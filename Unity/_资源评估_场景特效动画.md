## 0. 总览：三档判定

| 类别 | 判定 | 一句话结论 |
|---|---|---|
| **场景（15 个）** | **现成能用** | 数据完整度最高、成本最低。battlearena2 是性价比之王（24 个唯一网格 + 4 张贴图）。搭第 2 个战场约 1.5–3 小时，之后每个递减到 1–2 小时 |
| **特效（977 VFX 根）** | **需要加工（投入产出比很高）** | 粒子数据 100% 完整、原版就是 URP 不会变粉红；但 902/977 个特效的行为由一套 15 类的 `AnimFX` 框架驱动。**移植这套框架是一次性投入，不做就只能拿到静态粒子** |
| **动画** | **需要加工（但方向明确，成本可控）** | 全项目 **98 个唯一 AnimationClip**（解包整理内；原始 bundle 含主程序资源共 99 个）。**关键事实：原版的卡牌动效根本不是 AnimationClip，全部是 DOTween 代码 + 74 个 TweenSO 数据预设**。原始 C# 逻辑已反编译在手（`CardScript` 423 个方法） |

**三条最大的认知修正：**

1. **`AnimationClip 只有 88 个` 是口径错误。** 88 只是"战斗预制体"文件夹的**文件数**（对象只有 44 个），仅占全项目 45%。全项目实测 **98 个唯一 clip**（198 个 JSON，每个对象被 dump 两遍且 md5 相同；原始 bundle 全扫是 99 个）。明细见 §3.1。
2. **"clip 少"不等于"动画弱"**——原版**只在 DOTween 补不出来的地方用 clip**（着色器参数 `_DissolveAmount`、粒子开关 `m_IsActive`、后处理 `lutBlend`、材质属性）。卡牌的位移/缩放/旋转/淡入淡出/翻面/悬停 **100% 是代码**。这反而证明了"代码驱动"路线的可行性，而且**原版的手感数值（74 个 TweenSO 的 ease/duration/loops、CardHighlight 5 色态 RGB、AutoCardRotation 视差参数）全部可以搬运**。
3. **`"Spine 卡牌动画 2334 文件"` 是误标。** 这 2334 个文件 100% 是 `CardAnim` 的 `AnimInfo` JSON（动画时序配置），扩展名全是 `.json`，没有任何 `.atlas`/`.skel`。**三层穷举（1.6 GB bundle 二进制 grep、67,410 个 MonoBehaviour 的脚本反解、722 个 MonoScript 类名）证明发行版里没有任何 Spine 骨架或 Spine 组件实例**——只剩 DLL 和空的脚本注册表。**Spine 这条路建议直接划掉**（且商用授权按席位收费）。

现有流水线：`d:/2/Warpforge_tools/scripts/gen_unity_arena_manifest.py`（Python，场景 → 清单 JSON + 拷贝模型/贴图） + `d:/4/Unity/MyGame/Assets/WarpforgeArena1/Editor/BuildArena1.cs`（Unity Editor 脚本，清单 → 场景）

**必须修的流水线缺陷（做第 2 个场景时顺手修）：**
1. `BuildArena1.cs:385,432` 材质硬编码 `Shader.Find("Universal Render Pipeline/Unlit")`。粒子应该用 **`Universal Render Pipeline/Particles/Unlit`**，否则粒子顶点色、软粒子、相机淡出全部失效。
2. 39/39 材质全部 `_Surface=1`(Transparent) + `_ZWrite=0`，连地板都半透明 → 排序错乱 + overdraw。应改回"仅带 alpha 的才透明"。
3. `BuildArena1.cs` 目前把一切烘进**一个 .unity 场景**（0 个 `.prefab`）。做卡牌游戏需要 prefab 化，否则每加一个战场就复制一遍整个场景。

### 2.1 977 是什么（先纠正三个误读）

来源：`d:/2/解包整理/说明书/06_特效_预制体/战斗VFX预制体清单.md`、`08_预制体特效/`

### 2.4 单个特效的重建成本

**两个层面的成本，必须分开算：**

**A. 粒子参数转换（便宜，接近一次性）**
现有 Unity 管线 `gen_unity_arena_manifest.py` + `BuildArena1.cs` 已能覆盖：`InitialModule` / `EmissionModule`（含 burst）/ `SizeModule` / `ColorModule` / `UVModule`(翻页图集) / `ShapeModule` / render mode / 材质贴图 / GO transform。
battlearena1 的 34 个粒子**批量重建 + 调试 ≈ 1 小时**，且坑（材质透明判据、翻页图集、alpha 修复）已填平。
**坑填平后，重建 100 个和重建 1,000 个的差别只是脚本跑多久**——边际成本≈0。

**B. `AnimFX` 执行层（这是真正的大头）**
`977 个根里有 902 个（92.3%）含至少一个 AnimFX 系 MonoBehaviour，共 2,847 个实例。`

| `actionStart`/`cameraShakes`/`manualTriggerCameraShakes`（镜头震动） | 433 |
| `actionStart`/`collisionAndParticles`（碰撞触发） | 357 |
| `actionStart`/`doParentRelation`/`particleSystems`（粒子挂点） | 314 |
| `actionStart`/`playOnEnable`/`tweenAnims`（补间） | 138 |
| bloom 强度/阈值/LUT 混合（后处理） | 52 |
| `forceEnableEmittersOnEnable`/`notifyFinishWhenNoParticles`（生命周期） | 49 |

对应类名（`d:/2/解包整理/说明书/05_游戏数据/脚本定义.md`，1,444 个 MonoScript）：
`AnimFXController`、`AnimFXInstanceParticleAdjacent`、`AnimFXModule{Animation, Cardback, ChangeMaterial, Collisions, DestroyInTime, DoDestroyAnimation, Event, PostProcess, ScaleByTarget, ScreenShake, TransformModifier, Tween}`、`AnimFxModuleMoveParticlesToTarget` 等。

**不移植这套框架，重建出来只有静态粒子**——没有延时、没有补间、没有镜头震动、没有后处理、没有子特效串联。
**好消息：字段名和值全部序列化在 JSON 里**，所以是"移植约 15 个类"，不是"手搓 902 个特效"。**投入产出比极高。**

**C. Shader（原版就是 URP，但要重连）**
`d:/2/解包整理/11_着色器/shaders/` 有 45 个 shader 资产，读出真实名字：
- URP 官方 3 个：`Universal Render Pipeline/Lit`、`/Unlit`、`/Particles/Unlit`
- Everguild 自研 **34 个**：`Everguild/FX/*`、`Everguild/Cards/*`、`Everguild/UI/*`
- ShaderGraph 4 个、Hidden 回退 3 个、内置 1 个

**✅ 关键好消息：原版游戏本身就是 URP。** 材质属性键与 Unity 6.3 + URP 17.3 完全对得上（`_Surface`/`_Blend`/`_AlphaClip`/`_BaseMap`/`_BaseColor`/`_QueueOffset`…），**不会出现"全变粉红"**。

**❌ 但 34 个 `Everguild/*` 是编译后的 ShaderGraph，拿不到连线图源码**（34/34 的 fallback 都是 `Hidden/Shader Graph/FallbackError`）。粒子高频用到的 6–8 个（`Particle Premultiply Greyscale Coloring`、`Unlit UV scroll`、`Halo UV scroll`、`Vortex`、`Burning`、`Particle Distortion Affect Transparents`）**必须在 Shader Graph 里重连**。
不过 `m_ParsedForm.m_PropInfo` / `m_KeywordNames` 保留了完整属性表（197 个唯一 shader 全量可读），可以据此还原参数语义。

卡牌相关 shader 的属性表已完整拿到，例如：

- `Everguild/Cards/3D Card Dissolve`：`_DissolveTex` / **`_DissolveAmount`** / `_BorderColor` / `_BorderWidth` / `_AlphaClipThreshold` / `_SCREENSPACEUV`

### 3.4 【核心结论】卡牌动画是 DOTween 代码，不是 AnimationClip

**证据链（三条独立证据指向同一结论）：**

**证据 1 — 原始 C# 反编译（最硬）**
`d:/2/Warpforge_tools/data/decomp_il2cpp_0827/decomp_out/` 有 **2,024 个已反编译的 C 文件**，按 `<类名>__<方法名>.c` 组织，覆盖 34 个卡牌游戏类。

其中 `CardScript` 有 **423 个方法**，动画/运动相关的关键方法名直接说明了实现方式：
```
CardScript__DrawCard                     抽牌
CardScript__TurnCardAround               翻面
CardScript__FinishCardDrawRotation       抽牌旋转收尾
CardScript__CardToMinionAnim             卡牌变成场上单位
CardScript__CardToMinionAnimTeleport     同上（传送变体）
CardScript__MoveIntoFieldFromHand        手牌 → 战场
CardScript__MoveBackToHand               返回手牌
CardScript__MoveAndDisappearAnim         移动并消失
CardScript__MoveToDeck                   回牌库
CardScript__AttackMeleeAnim              近战攻击动画
CardScript__ApplyMovementDisappearAnimRotations  移动消失的旋转
CardScript__CardPosAndScaleToUI          位置/缩放到 UI
CardScript__CardWaitingToBePlayed        待打出态
CardScript__GetHandToBoardAnimEventTime  手牌→战场的动画时间点
CardScript__MinionPlayedIntoField        单位上场
CardScript__DoBodyAnimation              模型动画
CardScript__ActivateIconAnim / ActivateTraitAnim / ActivateTriggerTraitAnim   图标/特性动画
CardScript__HighlightBloodThirst / HighlightIcon                              高亮
```

**证据 2 — `DrawCard` 的代码内容直接写着 DOTween**
```c
uVar3 = UnityEngine_Component__get_transform(param_1,0);
uVar3 = DG_Tweening_ShortcutExtensions__DOScale(uVar3, &uStack_38, param_4, 0);
DG_Tweening_TweenSettingsExtensions__SetEase<object>(uVar3, 0xc, _DAT_1842d1520);
```
`DG_Tweening` = **Demigiant DOTween**。`DOScale(transform, scale, duration)` + `SetEase(0xc, ...)` = 缩放补间 + 缓动曲线，时长由 `param_4` 传入。
同一函数里还调用了 `CardScript__TurnCardAround` 和 `BattleCardUI__SetObjectVisibility`，并播 `SoundAssetCollection__DrawCardFromDeck` 音效。

**证据 3 — UI 交互全在代码里**
`BasicCardUI` 的方法名：`OnTouchDown` / `OnTouchUpAsButton` / `OnTouchExit` / `FadeCard` / `SetCardAlpha` / `SetLayer` / `SetImageOverDraw` / `ToggleCardBack` / `ToggleOpenCardDisplayOnTouch` / `ToggleUpgradeHighlight` / `RefreshCardVisualEffects` / `SetChangedAmountTextUp` / `SetGemsChange`。
**悬停/选中的三态反馈是代码写的，没有对应 clip。**（Godot 侧自查也确认了这点：`battle.gd mouse_entered/mouse_exited` = 0 处 = hover 反馈缺失。）

**结论**：
> 原版游戏**只把 AnimationClip 用在 DOTween 补不出来的地方**——着色器参数（`_DissolveAmount`、`_Shatter_Color`、`_DisplacementController`）、粒子/拖尾开关（`m_IsActive`）、后处理（`bloomIntensity`、`lutBlend`）、材质属性（`floatProperty1.value`）。
> **卡牌的位移/缩放/旋转/淡入淡出/翻面/悬停，100% 是代码。**

这完美解释了"为什么全项目只有 98 个 clip"——不是资源匮乏，是**架构选择**。

**旁证：曲线的属性分布**（跨全部 clip 统计）也印证了这一点——`m_IsActive` 出现 43 次、`lutBlend` 12 次、材质参数（`material._DissolveAmmount` / `_Shatter_*` / `_WarpColor.*` / `_EmissionColor.*`）若干次。**原版 clip 曲线里占比最大的是"驱动材质/后处理/开关"，而不是"驱动 Transform"**——Transform 的活儿全交给 DOTween 了。

**另一个旁证：只有 3 个 clip 带 AnimationEvent**（函数名 `CardHandToBoardAnimationFinished` / `AnimationResurrectionEnd` / `OnAnimationEndEvent`）。原版不靠事件驱动流程，靠代码 `await`。

### 3.8 骨骼 / 蒙皮动画：基本没有

- `SkinnedMeshRenderer` 22 文件 = **11 个唯一**，全部挂在 `Cone.001` ~ `Cone.007`（Hive Fleet 触须），每个 **17 根骨骼**、骨骼名是纯直线链 `Bone` → `Bone.001` → … → `Bone.016`，共 187 根骨骼。驱动它们的正是 `HiveFleetTendrils`(76 曲线) 和 `Scene`(134 曲线) —— **这是全项目唯一的真骨骼动画**。
- **战斗单位没有骨骼**。单位表现走：
  - **VAT（Vertex Animation Texture）**：`VATAnimation` 组件（例 `Card Remnant_Remnant Anim 3`：`Frames=15, PartsCount=75, Duration=3.0`，配 `PositionsTex` + `RotationsTex`），对应 clip `Vanguard Frame Animation`（1.792s）
  - Sprite 序列帧 + Shader 溶解（材质曲线 `material._DissolveAmmount` / `_Shatter_*`）

**判定：骨骼动画对卡牌战斗表现 = 基本没有。** 但 VAT 是值得考虑的技术——**用一张贴图烘 15 帧模型动画，对卡牌游戏这种"多单位同屏"的场景非常省性能**。

### 3.10 补动画的成本

**先纠正一个常见误解**：`d:/2/Warpforge_tools/scripts/convert_unity_anim.py` **输出的是 Godot `.tres`，Unity 不可复用**（硬编码 `[gd_resource type="Animation" format=3]`，且只处理 Float/Position/Scale 曲线，`m_RotationCurves`/`m_EulerCurves` 代码里根本没循环到）。
**但 Unity 目标根本不需要转换器**——原始 bundle 就是 Unity AssetBundle，直接 `AssetBundle.LoadFromFile` 即可。

**三条路：**

| 路线 | 内容 | 工时 |
|---|---|---|
| **A. 现成 clip + 照搬 74 个 TweenSO 数值 + DOTween 自写**（推荐） | 用 §3.2 的 `Card Hand To Board` / `InBattleDamageCounter` / `Minion Death Icon` + §3.3 的 13 个相机飞入 + §3.7 的 `BattleHudShow/Hide` / `Card Display Open`；发牌/悬停/选中/攻击位移照搬 `UnitTweenSO` 的 ease/duration/loops 数值 | **15–25 人天**（可玩版本） |
| **B. A + 数据驱动 Tween 框架** | 照抄 `UnitTweenSO` 的 6 种 tween 类型 + ScriptableObject 编辑器，把 74 个预设和 804 条 `AnimInfo` 转成 Unity 资产 | **25–35 人天**（框架化，之后所有卡复用，调手感不再改代码） |
| **C. 全量重建（含 99 clip / 400 VFX / 全部 shader 重连）** | 不推荐 | 40+ 人天 |
