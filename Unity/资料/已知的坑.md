| **🆕 原版材质上带着内置 Standard shader 的残留值** | 原版 shader 换过之后，旧材质里的 `_SrcBlend/_DstBlend/_ZWrite/_Surface/_Glossiness/_Metallic…` **不会被清掉**。如果新 shader 的属性表里**没有**这些名字，它们就是**死值**（Unity 忽略）；但我们自建的 shader 一旦用 `Blend [_SrcBlend][_DstBlend]` 这种间接寻址，就会把死值当活值用。实测：`Everguild/FX/Particle Distortion Affect Transparents` 属性表里混合相关的一个都没有（写死在 pass 状态：SrcAlpha/OneMinusSrcAlpha、ZWrite Off），而材质上是 `_SrcBlend=1/_DstBlend=0/_ZWrite=1` → 导出侧变**不透明覆盖 + 写深度**，把背后的东西整块抠掉。**判据：先读原版的 `m_PropInfo.m_Props`，属性表里没有的就一律硬编码，别做间接寻址**（`WFSpritesAdditive` 是同一个坑的另一例） |

## 🔴 两个 Unity 实例撞车时，症状**不像撞车**（2026-09-23 踩）

## 🔴 **不带引号的 heredoc 会把反引号当命令替换**（2026-09-23 踩，差点毁掉记忆索引）

- 要喂含**反引号 / `$` / `\`** 的内容，**一律写成 `<<"PYEOF"`（带引号）**，或**先把脚本 `cat > /tmp/x.py` 再 `python /tmp/x.py`**（本次修好用的就是后者）。

## 🔴 **同一个渲染队列的两层，「谁盖谁」是不可控的**（2026-09-23 踩两次，自动断言全绿）

**形状**：手搭 UI 时按「**一层一个大类**」给队列（背景 3006、轨道 3009…），
于是一棵树里的**父子两层用了同一个队列**（例：`Background` 的纯黑底 + 它的子件 `Warp` 大图）。

**为什么错**：`ImageQuad` 全是**透明队列**，同队列里 Unity 按**到相机的 3D 距离**排 ——
而这些件都在 `z≈0`、只差中心 ⇒ 屏幕中间那张更近、**谁盖谁由几何偶然决定**，
而且**每帧可能一样、改一个尺寸就翻**。

**这次的两处（都是「画面上什么都没有，而断言一条都没红」）**：
1. 锻造页 `Background` 的**纯黑底把旋涡大图整张盖掉** —— 画面上只剩几缕紫雾，
   而 `CheckAt`/`CheckRectPx`/`CheckArt` **全绿**（它们量的是矩形、贴图名，量不到「被盖住」）。
2. 格里的 `BarEnd`（条形末端标记）与 `LevelBg`（等级圆牌）同队列 ⇒ 末端标记时有时无。

**做法**：
- **一层一个队列，逐层 +1**，次序照**原版的子节点序**（父 → 子、兄 → 弟）。
  格内这种「一层里还有图标+文字」的，**连图标和文字都要各占一个**。
- **加断言**：关键的两层之间钉一条「**上层的队列 > 下层的队列**」
  （例：`Warp.RenderQueue > Black.RenderQueue`）—— 这条正是这次唯一能自动拦住它的判据。
- ⚠️ 和 `CLAUDE.md` §三 那条「**分层要用渲染队列、不能用 z**」是**同一条的两面**：
  那条讲「**该分**的要分」，这条讲「**分了就别合并**」。

## 🔴 **`AlignLeft/AlignRight` 必须在 `SetText` 之后调**（同一次，战役页 `Campaign Header`）

**形状**：对齐是**按当前文字的宽度**算的（`AlignLeftOn` 里先 `RefreshBounds()` 再拿 `WorldW` 定位）。
第一版把 `MenuDraw.AlignLeft(_title, r)` 写在 `Build()` 里 —— 那时 `TextBox` 刚建出来、**文字还是空串**，
