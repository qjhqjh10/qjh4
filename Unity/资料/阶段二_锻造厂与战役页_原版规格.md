**方法行为**：
- **`Awake`**（`__Awake.c:11-27`）= **只碰两个调试钮**：先 `SetActive(DebugUIEnabledUI)`、**紧接着再 `SetActive(false)`**
  ⇒ 净效果 **两个调试节点恒为隐藏**（与 prefab 里 INACT 一致）。`disasm_va.py 0x1806E4110` 直读指令流复核过。
- **`OnOpen`**：`GetHandler<CampaignHandler>()` 取选中阵营 → `SelectArmy` → `GetAllForgeEvents()` →
  `armySelector.Initialize(armies, selected, ArmySelectorType.Forge)` → 订阅 `OnArmySelected` / `OnLevelUpdated`。
  **不写任何文本/可见性。**
- **`SelectArmy(army)`**：查 `currentForgeEvent` → **`rewardSelector.Initialize(currentForgeEvent)`**
  → `selectedArmyInfo.Initialize(army, …)`。
- **`RefreshLevel`**：**只写一个节点** ——
  `selectedArmyInfo.levelText.text = string.Format("{0} {1}/{2}", 本地化("MainMenu/Level"), rewardsCollected, Rewards.Count)`
  ⇒ 得到 `Level 1/50`。**由 `rewardSelector.OnLevelUpdated` 回调触发，不是每帧。**
- **`Refresh`**：重取 forge 列表 + 重调 `armySelector.Initialize`。**私有且全代码无调用点** ⇒ 只能由 prefab 侧 UnityEvent 触发。
- **`GetForgeItem(index)`** = `rewardSelector.currentRewardItems.ElementAtOrDefault(index)`；
  唯一外部调用者是教程 `TutorialStageClaimForgeFirstLevel__DoMenuActions.c:144`。
- **`GiveForgePointsButtonOnClick`**（`Debug Add points` 的处理函数）**整段只有一行 `CustomDebug.Log`**
  —— 不读任何字段、不发任何请求 ⇒ **纯空壳**。

**🔴 `Ready for level up` 的判据**：`ForgeRewardSelector.hasToCollectReward`（对每格取或，`__CreateRewards.c:83-87`）。
`ForgeRewardItemContainer.Initialize` 返回 `state == ToCollect(2)`。
应用：`canLevelUpEffect.Toggle(...)`（**隐藏** `__Initialize.c:52` · **显示** `__FinishedSnapping.c:5`，时长 **0.3f** ·
领完再隐藏 `__RewardCollected.c:5`）。
⚠️ **prefab 里该节点是激活的**，代码第一次 `Toggle(false)` 才关 ⇒ **我们建完必须立刻关**（纪律④）。

**🔴 `Rewards Content` 里放什么**：每格 = `ForgeRewardSelector.rewardItemContainer`（= `ForgeMenuRewardButton` prefab）的实例，
父 = `Rewards Content`（`Object.Instantiate<T>(prefab, rewardsContentAnchor)`）。
数据源 = **服务端** `currentForgeEvent.Data.Rewards`（`List<RewardData>`）+ `SaveGame.currentPoints / rewardsCollected`。

**取不到的**：`currentPoints` · 每级所需 `Points` · `rewardsCollected` · 奖励物品 `RewardInfo` ·
「哪些阵营有 forge 事件」—— **全在服务端 Forge 存档里**（`Debug Set Forge` 走的是 PlayFab 云脚本 `"SetForgeLevel"`）。

## 八、页签机制的复核（推翻一条旧结论，并揪出一处我们自己的偏离）

**旧结论**（`日常_原版规格.md` §十·3）：「`TabButtons.Initialize` / `GameWindowWithTabs.CreateTabButton`

   配套 `firstTime(0x40) = true` —— 用来**吞掉「开窗时程序化置 `isOn`」触发的那一次事件**。
2. **`CreateTabButton` 只服务「运行期新增页签」**（`CreateTab<T>` → 活动页/商店页/聊天页），
   **与奖励窗左栏那 3 个键无关**。
3. **`GetStartingTab`** = `GameWindowWithTabsOptions.startingTabType` 指定的那个；没设就 `tabs.FirstOrDefault()`
   ⇒ 奖励窗取 `tabs[0]` = **Missions**（与我们一致）。
   `tabs` 顺序 = `[MissionsTab, ForgeWindowTab, CampaignWindowTab]`（序列化原文）。
4. 🔴 **第 4 键（`Menu Navigation Panel Button` / Booster Packs）原版运行期是隐藏的** ——
   它是 `tabButtonPrefab`（`EverguildToggle` pid `5159086895759431423`），`Initialize` 第一件事就把它关掉。
   它**没有 `OpenWindowButton`、没有 id 组件**，既不是页签也不是可点导航键。
   ⇒ **我们原来把它当常显的第 4 键画出来了**（偏离），**2026-09-23 已改成「照建但关着」**（`TabButtons.Initialize`）。
5. **`ChangeTabCO` 名字里的 "CO" 是遗留，函数体是普通同步方法**，没有 IEnumerator / yield / tween
   （`ForgeWindowTab.OnOpen` / `CampaignWindowTab.OnOpen` 里 DOTween 命中数都是 **0**）。
   `from == to` 时**不触发 `OnTabChange`**。

**已被推翻** 3（见上）· 5（676 个 61 字节占位是**诊断错** —— 那批是**真空覆写**，`RVA 0x4B33B0` 全库 1992 处）·

### 十四·二、`Open()` 的判定顺序（`CampaignRewardsWindow__Open.c`，逐支解）

1. `hasBase = Rewards.Any(r => r.rewardTier == 0)` · `hasPrem = Rewards.Any(r => r.rewardTier == 10)`

3. **只有一列有奖励时 `CenterHolder(那一列)`**：它把 holder **和它的父**一起改成
   `anchorMin(0.5,0) / anchorMax(0.5,1) / pivot(0.5,0.5) / anchoredPosition.x = 0` 再强制重排
   ⇒ **内容在视口里水平居中**（不是留在自己那一半）。两列都有 / 两列都空 ⇒ **不调**

5. `param_1 + 0xC8/0xD0 = (bVar9 ^ 1)`、`+0xD8/0xE0 = bVar9` ⇒ 见下「四个件是哪四个」
6. `SetBaseButton()` · `SetPremiumButton()`（原版这两个是**无参**的，成本从 `context.PointCost` 取）
7. 逐条 `ItemDrawer.Draw(这一档的容器, item, quantity)` 之后 **`SetAsFirstSibling()`** ⇒ 物品挤到列首
8. `LayoutGroupContentFixer.FixLayout()` —— 它是一个 `List<RectTransform>`，对每个元素
