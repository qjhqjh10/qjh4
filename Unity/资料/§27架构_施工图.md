## 二、做法（三步，每步都能单独验收）

### 第 1 步：把「逐场场景状态」抽成一个**共用函数**（不改行为）
新建 **运行时**类 `CardPresentation/Battle/ArenaSceneState.cs`：
```csharp
public struct ArenaSceneState {   // 字段 = 现在 ArenaBuilder 写进场景的那些
    public int fogMode; public float fogDensity, fogLinearStart, fogLinearEnd; public float[] fogColor;
    public int ambientMode; public float[] ambientSky; public float ambientIntensity;
    public string skybox;                       // 名字（运行时按名字取）
    public int lightType; public float[] lightColor; public float lightIntensity; public float[] lightRot;
    public bool hasSun; public float haloStrength, flareStrength;
    public float[] camSensorSize; public float camFocalLength; public int camGateFit;
}
public static void Apply(ArenaSceneState s, Transform lightRoot, Camera cam);
```
· `ArenaBuilder` 里那段（2436-2600）**改成调它**（判据只留一处）；
· 数据从哪来：**仍然是 `mf`（manifest）** —— 这一步只是把代码搬个地方，**行为一字不改**。
· **验收**：`BattleScene.Run` 1086+ 条不动、13 场表不动作废（跑一次 `arena_compare` 对比）。

### 第 2 步：新增「建战场 prefab」（**加法，不删旧路**）
`ArenaBuilder` 加 CLI **`BuildArenaPrefabs`**：逐场 → 建内容 + 挂一个 `ArenaPrefabData`
（= 第 1 步那个 `ArenaSceneState` + `arenaKey`）→ `PrefabUtility.SaveAsPrefabAsset`
到 **`Assets/Resources/ArenaPrefabs/<场>.prefab`**（`Resources` 才能按名字在运行时取）。
· ⚠️ `Resources/` 里放 13 个 prefab：**几何/材质仍是引用**（`arenas/<场>/Models|Materials`）⇒ 不重复占空间；
· **验收**：13 个 prefab 建得出来、`Resources.Load` 取得到（一条断言）。

### 第 3 步：切成单场景 + 运行时实例化
· `BattleScene.BuildScene`：把 `BuildArena3D`（烘内容）换成 —— 建一个空 `Arena3D` + 挂
  **`ArenaRuntimeLoader`**（运行时组件：`Resources.Load<GameObject>("ArenaPrefabs/" + key)` → `Instantiate`，
  再把 `ArenaPrefabData` 应用到 `RenderSettings` / 光源 / `BoardCamera`）；
· **`key` 从哪来**：玩家对局 = `ArenaByArmy.SceneFor(督军阵营)`；**批处理/预览** = 环境变量 `WF_ARENA`（判据转发
  `ArenaBuilder.ArenaFromEnv`，别在别处再写一套）；
· `BattleScene.ScenePath`：**不再按 `WF_ARENA` 分叉**（只存 `Battle.unity`）；13 份 `Battle_<场>.unity` 不再生成；
· 🔴 **预览/量图那条路**（`RenderPreviewFromCLI` 打开的是 `arenas/Scenes/<场>.unity`）**这一步先不动** ——
  它跟 §27 是两回事，等第 3 步验完再决定要不要并过来（并过来要改 `sweep_env_states.py` 与 `arena_compare.py` 的输入）。
· **验收**：见文末三条。

## 三、风险（写下来，别事后补）

1. **运行时实例化的加载时间与内存要实测**（现在是烘好的）—— 正本 `资料/战场场景线_交接.md` §五 的「已知风险②」。
2. `Resources/` 的 13 个 prefab 会**整包进构建**；`Resources.Load` 是按需加载 ✓，但构建体积会涨。
3. **同一时刻只能有一个 Arena3D 实例**（换场要先把旧的销毁）—— 一局只有一场，但自检里要断言「不叠加」。
4. 逐场 RenderSettings 是**场景级**的：单场景里换场必须**先把上一场的值还原**，否则会残留（`SaveOrReuse` 那类老坑的同族）。
5. 本件**不改变画面** ⇒ 任何一张表动了都是 bug（不是「改善」）。
