# 卡表核对 · 卡图逐张提取（原始产物）

> 2026-09-13 建立。**这里是「东西在哪」，结论与对账见 `资料/卡表逐张核对_与对账.md`。**

## 这批文件是什么

**1118 张卡图逐张看了一遍**，把卡面的 11 列抄下来 —— 为了和引擎在用的卡表对账。
29 个子代理各负责 ≤45 张，**全程禁止参考任何已有数据**（要的就是独立抄一遍）。

## 目录里有什么

| 文件 | 是什么 |
|---|---|
| `_合并总表.md` | **1118 张卡的合并总表**（11 列 + 来源批次）。**对账与修正都以它为准** |
| `_对账.md` | 新旧逐列差异（`Unity/工具/compare_cards.py` 生成，**只报差异不裁定**） |
| `_提取规格.md` | 发给子代理的**规格书**（版面、11 列含义、图标写法、纪律）。**再派同类任务时直接复用它** |
| `<阵营>__<批>.md` ×29 | 每批的原表，**每份末尾有 `## 存疑`** —— 那是子代理逐条写下的「拿不准的地方」，很值钱 |
| `_工作清单/` ×29 | 每批负责的 PNG 路径清单（`merge_cards_new.py` 会用到；也能用来复现「谁看了哪几张」） |

## 几条**下个会话必须先知道**的

1. **卡面版面不止一种印次**：有「白卡名 + 橙色阵营行」，也有「橙卡名、干脆没有阵营行」，
   同一个阵营内都会混。**「没有阵营行」不是漏抄**，别去补。
2. **效果文字下面那行橙色小字 = 这张卡的归类**：部队卡写兵种（`Infantry`/`Vehicle`/`Beast`/`Daemon`…），
   防御卡写 `Defence`，督军写 `Warlord`，有些计策写 `Dark Pact`/`Overlord Power`/`Combat Elixir`…
   **部队卡那一列才是引擎说的「字段（兵种）」**。
3. **效果里的图标全部只写了形状**（`【图标:眼睛】` / `【图标:盾牌】`…），**没有猜语义**。
   好处是不会带偏数据；代价是**同一枚图标在不同批次可能起了不同名字**。
   👉 **要对齐图标得用 `资料/关键词图标/关键词与图标_对照表.md`**（见那份文档的说明）。
4. **卡面印 `0` 的地方就是 0**，不是漏读（多处 `0` 曾被人当成缺项）。
