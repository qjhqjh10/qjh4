# 自研游戏 —— 特效接入 & 卡牌表现基座设计

> 建立：2026-09-11（第四轮）　|　面向：**下一个会话**
> 这份文档回答两件事：
> 1. 还原出来的特效**怎么在自研游戏里真正跑起来** —— 而不是只能挂在原版游戏里看
> 2. 卡牌表现基座（发牌 / 手牌 / 拖拽 / 落位 / 高亮 / 卡牌动效）**怎么设计** —— 原版只作参考蓝本，最终要自己出方案

---

## 一、特效接入：从「研究产物」变成「游戏资产」

### 1.1 现状盘点 —— 差的不是特效本身

| 项 | 现状 | 缺口 |
|---|---|---|
| 特效本体 | 958 个 prefab（`Assets/WarpforgeVFX/Prefabs/`） | 按红线发布前必须整个移出构建 |
| 材质重建 | `Runtime/WarpforgeEffectBinder` 运行时重建 | ✅ 可用 |
| shader 来源 | `StreamingAssets/WarpforgeVFX/*.bundle` | ⚠️ 里面是**原版编译字节码**，不能进发布版本 |
| **生命周期** | **无** | **特效播完不会自己消失** —— 缺 `AnimFXController` 的等价物 |
| **播放入口** | **无** | 只能手动 `Instantiate`，没有「播一个特效」的 API |
| **触发条件** | **不知道** | 很多效果是被技能/碰撞触发的，不是自播的 |

**所以「还原了 958 个效果」≠「有 958 个能用的特效」。** 差距在后三项。

### 1.2 目标形态：一个自包含的运行时包

建议做成**一个能整体拷进任何 Unity 工程的文件夹**，不依赖本工程的其它部分：

```
WarpforgeVFX_Runtime/            ← 整个文件夹拷走就能用
├── Scripts/
│   ├── WarpforgeShaderLoader.cs     从 StreamingAssets 加载 shader 包
│   ├── WarpforgeShaderMap.cs        原版 shader 名 → 本工程 shader 的映射
│   ├── WarpforgeEffectBinder.cs     运行时重建材质（已有）
│   ├── WarpforgeEffectPlayer.cs     ★新 播放入口 + 生命周期
│   └── WarpforgeEffectLibrary.cs    ★新 注册表：名字 → prefab
├── Shaders/                         5 个自建替代 shader
└── StreamingAssets/
    └── wf_shaders.bundle            发布版本必须换成**自建**的（见红线）
```

### 1.3 ★要新写的两个东西

**(a) `WarpforgeEffectPlayer` —— 播放入口 + 生命周期**

没有它，特效就是「不会死的对象」。至少要有：

```csharp
namespace WarpforgeVFX
{
    public class WarpforgeEffectPlayer : MonoBehaviour
    {
        // 播一个特效：按名字取 prefab、挂到父节点、按 scale 缩放、到期销毁
        public static WarpforgeEffectPlayer Play(
            string effectName,
            Transform parent = null,
            Vector3 localPosition = default,
            float scale = 1f,
            float autoDestroySeconds = -1f);   // <0 = 用 prefab 上的 binder 记录的时长

        public event Action OnFinished;

        public void Exit();      // 停止发射、进入收尾（对应原版 AnimFXController.Exit）
        public void Kill();      // 立即销毁
    }
}
```

生命周期规则（**这是从原版行为反推的，需要实拍验证**）：

| 参数 | 来源 | 默认行为 |
|---|---|---|
| `exitDestroyTime` | `AnimFXController.exitDestroyTime` | Exit 后多久销毁 |
| `destroyTime` / `preventDestroy` | `AnimFXController` | 无 Exit 时的兜底销毁时间 |
| 安全销毁兜底 | 原版常量 `SAFE_DESTROY_TIME = 3f` | 无论如何 3 秒后回收 |

> ⚠️ 这三个数值已经在 `数据/游戏数据/animfx_components.json` 里了（`AnimFXController` 990 个实例），
> 直接读，不要猜。

**(b) `WarpforgeEffectLibrary` —— 注册表**

现在是 958 个零散 prefab，没有索引。建议生成一份 `effect_index.json`：
效果名 → prefab 路径 + 建议缩放 + 建议挂点 + 是否自播 + 触发条件猜测。

生成脚本可以复用 `工具/dump_animfx.py` 的路子（读 prefab + binder 数据）。

### 1.4 落地顺序（从「能看」到「能用」）

| 步 | 做什么 | 为什么这个顺序 |
|---|---|---|
| 1 | **`WarpforgeEffectPlayer` + 兜底销毁** | 不先做这个，特效进场景就内存泄漏，别的都白搭 |
| 2 | **`WarpforgeEffectLibrary` + `effect_index.json`** | 没有索引就没法按名字播 |
| 3 | **在一张白板场景里实拍验证** —— 铺 20 个常用特效，确认「播→消失」闭环 | 项目准则 #5：每个改动都要能实拍验证 |
| 4 | AnimFX P0 两个模块（`AnimFXController` / `AnimFXModuleTween`） | 补上原版节奏；数据全在，见交接文档 P0-e |
| 5 | 发布版本前：77 个原版 shader 逐个自建替代 | 红线要求，不急 |

**第 1–3 步做完，特效就真的「能在自研游戏里用」了**（约 2–3 天）。第 4 步是「像原版」，第 5 步是「能发布」。

## 二、卡牌表现基座设计

> 原版只作**参考蓝本**：学它的结构、抄它的手感数值、照搬它的设计思路，
> 但最终的布局/交互/动效要自己设计。这一节给的是**建议方案**，不是原版复刻。

### 2.1 原版有哪些现成的、可以直接拿来当参考的

| 资产 | 在哪 | 能拿来干什么 |
|---|---|---|
| `Card Hand To Board` clip（0.92s） | 原版动画数据 | 「手牌落到战场」的**完整时序蓝图**，17 条曲线把时间点拍清了 |
| **74 个 `UnitTweenSO`** | `d:/2/新解包资源/.../bundle_tweenandshakes_assets_all/MonoBehaviour/` | ease / duration / delay / loops / punch 数值**整套可搬**，含具体类型名（`PunchTween` 等） |
| `DrawCard` / `TurnCardAround` | `d:/2/Warpforge_code/`（签名桩）+ Ghidra 反编译 | 原版是 DOTween 代码驱动，`DOScale` + `SetEase` 直接写在里面 |
| `CardHighlight` 5 色态 | 原版预制体 | 可打出/不可打出/选中/目标/悬停 的状态色 |
| `card_anim_map.json` / `atk_vfx_map.json` | `Unity/数据/游戏数据/` | 卡牌 → 特效映射（591 条定义 → 400 个预制品） |
| 34 个卡牌类 / 2024 个方法名 | `d:/2/Warpforge_tools/data/decomp_il2cpp_0827/` | 当**需求规格说明书**用 —— 它告诉你「原版考虑了哪些情况」 |

**取用原则**：数值照搬（手感是调出来的，重调浪费时间），结构和交互自己定（要避版权、也要贴合自己的玩法）。

### 2.2 建议的模块划分

```
Assets/CardPresentation/
├── Core/
│   ├── CardView.cs              一张卡的视觉载体（正反面、图、文字、费用、攻防）
│   ├── CardState.cs             状态枚举 + 状态机（在牌库/在手牌/在场上/进弃牌堆）
│   └── CardAnimator.cs          动效调度器（把下面几个拼起来）
├── Hand/
│   ├── HandLayout.cs            ★手牌扇形布局（角度/间距/弧高随张数变化）
│   ├── HandHover.cs             悬停抬起 + 邻牌让位
│   └── HandDrag.cs              ★拖拽（拿起/跟随/松手回弹/出牌判定）
├── Board/
│   ├── BoardLayout.cs           ★落位（7 格：督军居中 + 两侧各 3）
│   ├── DropTargeting.cs         落点高亮与合法性判定
│   └── DeploySequence.cs        部署动画（手牌 → 战场的一条曲线）
└── Highlight/
    └── CardHighlight.cs         ★5 色态高亮
```

（★ = 你点名要的四项）

### 2.3 四个核心模块的接口草案

```csharp
// ——— 手牌扇形布局 ———
public class HandLayout : MonoBehaviour
{
    [SerializeField] float fanAngleMax = 18f;      // 满手牌时的总张角
    [SerializeField] float arcHeight   = 60f;      // 中间那张比两边高多少
    [SerializeField] float spacingMin  = 70f;      // 手牌很少时的间距
    [SerializeField] float spacingMax  = 120f;     // 间距上限，超过就压缩

    public void Refresh(IReadOnlyList<CardView> cards, int hoveredIndex = -1);
    // 需不需要让位：hoveredIndex 那张抬起，相邻牌往外挪一点（原版的"邻牌让位"手感）
}

// ——— 拖拽 ———
public class HandDrag : MonoBehaviour
{
    public event Action<CardView, Vector3> OnDropped;   // 松手时抛给落位系统判合法性
    public bool IsDragging { get; }

    // 拿起：放大 + 置顶 + 取消扇形旋转；跟随：鼠标/触摸位置 + 轻微倾斜
    // 松手：合法 → 交给 DeploySequence；不合法 → 回弹到扇形原位
}

// ——— 落位 ———
public class BoardLayout : MonoBehaviour
{
    public const int SlotCount = 7;                 // 督军居中，两侧各 3
    public int WarlordSlot => 3;

    public bool TryResolveSlot(Vector3 worldPos, out int slot);
    public Vector3 SlotPosition(int slot);
    public void HighlightValidSlots(bool[] valid);  // 拖拽时只亮合法的格子
}

// ——— 5 色态高亮 ———
public enum CardHighlightState { Normal, Playable, Unplayable, Selected, ValidTarget, Hover }
//                           常规    可打出     不可打出     已选中    合法目标    悬停
public class CardHighlight : MonoBehaviour
{
    public void Set(CardHighlightState state, float blendTime = 0.12f);
}
```

### 2.4 数值从哪来

| 要调的 | 参考来源 |
|---|---|
| 发牌手感（缩放/位移/缓动） | `DrawCard` 的 `DOScale` + `SetEase`；74 个 `UnitTweenSO` 里的 `PunchTween`（`ease` 是 DOTween 的 Ease 枚举，`6` = InOutQuad 一类） |
| 手牌到战场（0.92s 的完整时序） | `Card Hand To Board` clip 的 17 条曲线 |
| 高亮过渡时长 | `CardHighlight` 的色态切换 |
| 落位吸附 | 原版没有独立数值，自己定（建议 0.15–0.2s，`Ease.OutBack`） |

> ⚠️ **不要照搬原版的整体布局坐标** —— 那是给 1920×1080 手机横屏调的。自己的游戏先定分辨率与安全区，
> 再按自己的比例重算扇形半径和间距，只把**缓动曲线和时长**搬过来。

### 2.5 和特效怎么接

`atk_vfx_map.json` / `card_anim_map.json` 是现成的「哪个动作播哪个特效」映射表。
建议在 `CardAnimator` 里加一层：

```csharp
// 卡牌动作 → 特效名，从映射表读，不要硬编码
WarpforgeEffectPlayer.Play(EffectMap.For(cardId, CardAction.Attack), parent: cardRoot);
```

这样特效和卡牌表现是**解耦**的 —— 换特效不用改卡牌代码，换卡牌布局不用碰特效。

### 2.6 建议的落地顺序

| 步 | 内容 | 依赖 |
|---|---|---|
| 1 | 定分辨率/安全区 + `BoardLayout` 的 7 格坐标 | 无 |
| 2 | `CardView` + `HandLayout` 扇形布局（先只做静态排布） | 1 |
| 3 | `HandHover` 悬停抬起 + 邻牌让位 | 2 |
| 4 | `HandDrag` 拖拽 + 回弹 | 3 |
| 5 | `BoardLayout` 落位判定 + `DeploySequence`（用 `Card Hand To Board` 的数值） | 4 |
| 6 | `CardHighlight` 5 色态 | 5 |
| 7 | 接特效（`WarpforgeEffectPlayer`） | 一、1–3 步 |

**前 6 步不依赖特效线**，两条线可以并行。

## 三、一句话总结

- **特效线**还差两件事才算「能用」：**播放入口 + 生命周期**（`WarpforgeEffectPlayer`）和**索引**（`WarpforgeEffectLibrary`）。约 2–3 天。
- **卡牌基座**是独立的一条线，前 6 步不依赖特效，可并行起步。
- 原版的价值是**数值和结构参考**，不是复制品 —— 布局坐标、交互细节、美术全部自己出。
