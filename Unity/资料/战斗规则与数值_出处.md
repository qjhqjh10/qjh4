## 三之二、怎么把 ScriptableObject 的**值**挖出来（下一步该做的）

### 先说一个**错误的搜法**（本轮踩了，别再踩）

「`grep 字段名` 全盘搜」**注定搜不到** —— release 构建把**类型树剥了**，
**字段名根本不会落到数据里**。搜不到不等于资产不在。
（唯一能搜到名字的是**场景里的 MonoBehaviour**：它们的字段名跟着场景序列化，比如 `skullsObjs` 能搜到。）

### 正确办法：**按 MonoScript 的 PathID 找实例**

每个 MonoBehaviour 实例都带 `m_Script: {m_FileID, m_PathID}`，PathID 指向它的 **MonoScript**。
而 MonoScript 就躺在 `d:/2/新解包资源/assets_full/bundle_Waprforge_monoscripts/MonoScript/`，
**文件名里就是 PathID**：

```
MonoScript_-5845469671781466849.json   ← 里面 "m_Name": "ScenarioVariables"
```

所以：

1. 在 MonoScript 目录里按 `"m_Name": "<类名>"` 找到文件 → 文件名后缀 = **PathID**
2. 把 PathID 转成 **8 字节小端**（`struct.pack('<Q', pid & 0xFFFFFFFFFFFFFFFF)`）
3. 拿这 8 个字节**当二进制模式**去 bundle 里搜（`grep -rlP "\x1f\x7d..."`）
4. 命中之后，用 UnityPy 把那个对象读出来（**这一步才是拿值**）

```python
import struct
pid = -5845469671781466849              # MonoScript 文件名里的数
print(struct.pack('<Q', pid & 0xFFFFFFFFFFFFFFFF).hex())   # → 1f7d25dc4db8e0ae
```

> ⚠️ **注意**：找到实例之后，**读到的是二进制块**。要解出字段值，得知道布局 ——
> 这时 §二 那张「字段顺序 + il2cpp 偏移」表就有用了（`+0x34` 是 `clockTimeLimit` 之类）。
> 或者用 UnityPy 带着 MonoScript 的 type tree 去读（数据被剥了 type tree 时它会退回按字段顺序给你）。

**另一条更稳的路**：跑起游戏（`CLAUDE.md` 铁律 4），在场景里用 mod 直接把那个
ScriptableObject `JsonUtility.ToJson()` 出来 —— 运行时它一定在内存里，字段名也一定在。

## 三、🔑 手法：反编译里的 `_DAT_xxxxxxxxx` 是能读的

**这是本轮新摸出来的，之前文档里没有。** 反编译出来的 `.c` 里常出现这种：

```c
iVar1 = BattleManager__get_matchType(lVar2,0);
if (iVar1 == 0x50) { uVar3 = _DAT_1834b31c4; }   // ← 这个值没解析
```

`_DAT_` 不是「拿不到」，是 **Ghidra 没跟到的只读数据字面量**。地址是**绝对虚拟地址**，
基址就是 PE 的 `ImageBase`（这份是 `0x180000000`）。所以：

```
RVA = 地址 − ImageBase          →  0x1834b31c4 − 0x180000000 = 0x34B31C4
再拿 PE 的节表把 RVA 映射成文件偏移，读 4 个字节（float 小端）
```

这一步用 Python 三十行就能做（见下面的脚本）。本轮靠它读出了 **240.0 / 600.0** 两个回合时限。

```python
# 用法：python read_literal.py <GameAssembly.dll> <十六进制绝对地址>
import struct, sys
d = open(sys.argv[1], 'rb')
head = d.read(0x400)
pe = struct.unpack_from('<I', head, 0x3C)[0]
nsec = struct.unpack_from('<H', head, pe + 6)[0]
optsz = struct.unpack_from('<H', head, pe + 20)[0]
base = struct.unpack_from('<Q', head, pe + 24 + 24)[0]
secs, off = [], pe + 24 + optsz
for _ in range(nsec):
    va, vsz, rsz, ptr = struct.unpack_from('<IIII', head, off + 8)
    secs.append((va, vsz, rsz, ptr)); off += 40
rva = int(sys.argv[2], 16) - base
for va, vsz, rsz, ptr in secs:
    if va <= rva < va + max(vsz, rsz):
        d.seek(ptr + (rva - va)); b = d.read(4)
        print('bytes', b.hex(), '| float', struct.unpack('<f', b)[0],
              '| int', struct.unpack('<i', b)[0]); break
```

> ⚠️ **自检办法**：读出来的 float 要是**整齐的值**（240.0 / 600.0 / 10.0 这种）。
> 如果得到 1e-38 之类的乱数，说明 RVA 映射错了，别当成答案。

## 四、查战斗规则的标准顺序（照这个走，别跳）

1. **要语义**（这东西怎么结算）→ **规则书** `:115-241`
2. **要「原版有哪些环节 / 节点叫什么」** → **`资料/说明书/01_战斗_对战/`**（13 份战场全树）+ `04_界面UI/`

5. **要行为与流程** → **`decomp_il2cpp_0827/`**；`.c` 里的 `_DAT_` 用 **§三** 读
6. **要到这一步还没有** → **跑起原版游戏**（`CLAUDE.md` 铁律 4），或者**问用户**

### ⚠️ 别踩的两个坑

- **`d:/warpforge/scripts/battle.gd` 是有 bug 的重实现** —— 规则语义可以信它，
