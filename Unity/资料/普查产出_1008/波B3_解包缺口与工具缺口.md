### (f) `scenes_scenes_mainmenuwarpforge` · GameObject 1（**这条是 A174 点名要查的那件**）

**结论：是【导出漏了】，不是「本来没有」** —— 这颗对象**真存在**，丢的原因是**两个坑叠在一起**：

1. 这个包是**双 CAB**（`c0abb8a090277ce1cc411d6d532.sharedAssets` + `CAB-32e46c0abb8a090277ce1cc411d6d532`），两份 CAB 里**各有一颗 pid = 247** 的 GameObject：
   - `.sharedAssets` 那份：**`Text`（大写 T）**，`m_IsActive=1` · `m_Layer=5` · `m_Component=[352,32,523,550,120]`
   - 主 CAB 那份：**`text`（小写 t）**，`m_Component=[1536,841,1780,2065,2175,1643]`
   （⇒ 与 A152 记的「主菜单包 128 个同类型 pid 撞号」是同一个坑，这是其中一件。）
2. **导出的文件名只差大小写**：`.sharedAssets` 先写 ⇒ `Text_247.json`；主 CAB 后写 ⇒ `os.path.exists('text.json')` 在 Windows **大小写不敏感**下命中已存在的 `Text.json` ⇒ 转到 `text_247.json` ⇒ **实际打开了 `Text_247.json` 并覆盖**。
3. **实测证据**：磁盘上 `Text_247.json` 内容 = `m_Name='text'`（小写那颗）· 主菜单包的 `_stats.json` 里 **`objects=3217 / json=3216 / fail=0`** —— **`fail=0` 把这次静默覆盖盖住了**；文件数 696 也是现在这样来的。

⇒ **补法**（已实测跑通，见 §1·5）：用 UnityPy 直接从真包取 `.sharedAssets` 的 pid 247（取回结果：`Text` / `m_IsActive=True` / `m_Layer=5` / `comps=[352,32,523,550,120]`）。

### 1·5 补法（**能补**，两条路）

**① 单件按需取回（只读，随时可用）** —— 已在主菜单那颗上跑通：

for _k, v in env.files.items():
    for cab, sf in v.files.items():            # ⚠️ 两份 CAB 都要看（主 CAB / .sharedAssets）

同法可把「19 件内容缺失」里任何一件取回（表在 §1·3，`pid` 都给了）。

**② 若要重导（⛔ 本次没做，脚本在只读档案库里）**：
- `fix_exports.py` 的 `base` 加 **`_{path_id}`** 后缀（或先 `os.path.exists` 探一次再 bump）——**必须**，否则同名必丢；

## 二、A145 —— 工具缺口：`localScale` 没被乘进读数

### 2·1 结论（一句话）

- ⚠️ **`menu_rect.py` 根本没有「md 表」**（记录里那句 `工具/{menu_dump,menu_rect}.py 的 md 表…` 不准确）—— 它只有**纯文本表** + `--cs`。真正的缺口是：**纯文本模式只有一个 `scl=` 系数（算不出画出来多大）**、**`menu_rect.py` 那张表一个字都不提**、**`--cs`（抄进 `.cs` 的那条路）完全不提缩放**。

### 3·1 🔴 `assets_full` 里有 **9 个 0 字节文件** —— 「文件在、内容是空的」比「文件不在」更坏

全树 246,680 个文件扫一遍（`d:/4/_tmp_view/a174_zero.py`，只读）：

```
resources/Font/LiberationSans.ttf                        0 B
resources/Font/NotoSerifCJK-Regular.ttf                  0 B
resources/Font/PerfectDOSVGA437.ttf                      0 B
resources/TextAsset/BillingMode.txt                      0 B

```

- **成因**：`fix_exports.py` 那两支**先 `open(..., 'wb')`（当场把文件截成 0）再算要写的 bytes**，表达式一抛异常（`Font: a bytes-like object is required, not 'list'` / `TextAsset: string argument without an encoding`），异常被外层 `except` 吃掉 ⇒ **留下 0 字节文件 + 在 `fail` 计数 + `os.path.exists` 从此恒真**。
- **为什么 A151 那套「文件数 vs 对象数」看不见它**：0 字节也**算一个文件** ⇒ 它那套比对**结构上抓不到这一类**。
- **能补**：`m_FontData` 是**整数 list**（实测 `NotoSerifCJK-Regular` 长 **24,810,096**，前 4 字节 `74 74 63 66` = `"ttcf"` = TTC 字体集合）⇒ `bytes(d.m_FontData)` 就能把 TTF 原样救回来。
- ⚠️ **没查**：这 9 个文件**有没有被我们哪条管线读过**（`resources/TextAsset` 那几个是 Unity 自带的 BillingMode/PerformanceTest 配置，大概率没用；`NotoSerifCJK-Regular.ttf` 要看 CJK 那条线是不是依赖它 —— `资料/` 里记的是「TMP Essentials 必须自己解包」，两份要核一下）。
