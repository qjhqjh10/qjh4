## 一、原版是什么（照抄的字段，别自己编）

### 1·1 `ScrollRect`：**102 个实例的实测分布**

出处：`d:/2/新解包资源/assets_full/bundle_menus_assets_all/MonoBehaviour/*.json`
（判定条件 = 同时有 `m_Horizontal` / `m_Vertical` / `m_MovementType` / `m_Content`）。

| 字段 | 实测值 | 说明 |
|---|---|---|
| `m_MovementType` | **1 = Clamped** 或 **2 = Elastic** | 两种都有，**逐处不同** |
| `m_Elasticity` | **0.1** | 全库一致 |
| `m_Inertia` | **1** | 全库一致 |
| `m_DecelerationRate` | **0.135** | 全库一致 |
| `m_ScrollSensitivity` | **1 / 10 / 50 / 100** | **逐处不同**，没有统一值 |
| `m_Horizontal` / `m_Vertical` | 逐处不同 | 锻造页两条都是**横向**（`1 / 0`） |

### 1·2 三处用到它的地方（本轮的接线点）

| 界面 | 结构 | 内容 | 视口 |
|---|---|---|---|
| `Forge Tab/Rewards Scroll View` | `ScrollRect(横, Elastic, sens 1)` + `Viewport`(带 `RectMask2D`) + `Rewards Content`（HLG + `ContentSizeFitter`） | 50 个奖励格，**左对齐**（内容从视口左边起）+ padLeft 122 + spacing −130 | 330.97..1919.73 |
| `Forge Army Selector` | `ScrollRect(横)` + `Viewport`(`RectMask2D` soft x=42) + `Army Content` | 阵营条目，**居中**（内容是「视口中心的一个零宽点」+ `ContentSizeFitter` ⇒ 对称展开），spacing −14 | 588.17..1662.53 |
| `Campaign Army Selector` | 同上（`Army Content` 锚 `(0.5,1)`、pos x ≈ 0） | 同上 | 745.92..1920.34 |

### 1·3 「聚焦到某一项」是原版有的行为

`ArmySelector.FocusOnArmy` → 协程 → `ScrollViewFocusFunctions.FocusOnItem(scrollRect, item)`
→ `CalculateFocusedScrollPosition(...)`（取 **item 矩形中心**变换到内容空间再算归一化位置，
即 **item 中心 = 视口中心**）→ `ScrollRect.normalizedPosition = …`。
⏰ **全代码零外部调用点**（`grep -rln FocusOnArmy d:/2/tools/decomp_full` = 只有定义与协程本体）
⇒ 只能由 prefab 侧 UnityEvent 触发。锻造轨道那边另有一路 `ForgeRewardSelector.FinishedSnapping`
（说明原版确实会「吸附到某一格」）。**我们照这个语义做开页定位**。

## 二、我们怎么实现（三件，都在 `Shell/`）

| 件 | 文件 | 干什么 |
|---|---|---|
| **滚动区** | `MenuScroll.cs` | 视口 + 内容两端 + 偏移；`Shift/Intersects/FocusOn/Wheel`。**全壳唯一一份滚动实现** |
| **裁切** | `MenuWindowBase.Clip`（`PxRect?`） | 画内容前设一次、画完清掉；`Rect()` 把越界部分**截掉并把 uv 一起截**（否则图会被压扁）。**= 原版 `RectMask2D` 的等效物** |
| **指针层** | `PointerLayer.cs` | 新输入系统轮询 + 自己算命中：**滚轮**派给滚动区、**左键**派给 `WindowButton`。**.NET 唯一一条「真鼠标 → 界面」的路** |

**范围怎么定**（`MenuScroll` 自己算，调用方不用管）：
- **左对齐内容**：`[0, 内容右端 − 视口右端]`（只能往左滚）。
- **居中内容**：**两侧都有** `[内容左端 − 视口左端, 内容右端 − 视口右端]`
  ⇒ 往右滚能看到被左柱盖住的那几个、往左滚能看到越出右边的那几个。

**滚轮手感**：照**卡组编辑那条已经验过的路**（`DeckRuntime.HandleScroll` 用 `dy * 0.4f`，
`Deck/DeckRuntime.cs:1106-1113`）⇒ 新输入系统一格 ±120 ⇒ 一格滚 48px。**别两处各写一套。**

**命中顺序**（`PointerLayer.HitButton`）：**渲染队列大的先**（画在上面的先吃），
同队列再比 `z`（越小越靠前 —— 照 `CardInteraction.HitTest`）。
扫描时机 = **真有滚轮/按下/抬起时**才 `FindObjectsByType<WindowButton>()`（**不做每帧扫描、也不建静态登记表**）。

## 三、🔴 实现到什么程度（**2026-10-03 更新**）

### 3·1 ✅ **已做**（2026-10-03 这一轮补上的）

> 🔴 **判据 = Unity 自带的 `ScrollRect` 源码本体** —— 原版游戏的滚动就是它跑的，
> 「照抄 UGUI 的算式」= 逐位复刻、**不是我们挑的**。本地就能读：
> `Unity/MyGame/Library/PackageCache/com.unity.ugui@27635d171b1a/Runtime/UGUI/UI/Core/ScrollRect.cs`
> （另 `EventSystem/EventSystem.cs:68` 的 `m_DragThreshold = 10`）。

| 件 | 算式 / 值（照 UGUI） | 落在哪 |
|---|---|---|
| **惯性** | `v *= Mathf.Pow(m_DecelerationRate, deltaTime)`；`\|v\| < 1` ⇒ 0；`pos += v * dt`（:863-866） | `MenuScroll.Tick` |
| **速度来源** | 拖动中每帧 `newV = (pos − prevPos)/dt`；`v = Lerp(v, newV, deltaTime * 10)`（:884-888） | 同上 |
| **回弹** | `Elastic` 且越界 ⇒ `SmoothDamp(pos, 边界, ref speed, smoothTime)`，`smoothTime = m_Elasticity`（滚轮那一帧 **×3**），`\|speed\| < 1` ⇒ 0（:849-858） | 同上 |
| **橡皮筋** | `(1 − 1/((\|over\|·0.55/viewSize) + 1)) · viewSize · sign(over)`（:1084-1087） | `MenuScroll.RubberDelta` |
| **拖拽** | `pos = 按下时的位 + (当前指针 − 按下指针)`；Clamped ⇒ 夹回；Elastic ⇒ 再减 `RubberDelta`（`OnDrag` :779-810） | `MenuScroll.BeginDrag/DragTo/EndDrag` |
| **拖拽阈值** | **10px**（`EventSystem.m_DragThreshold`）—— 越过 ⇒ 这一套「按下→抬起」判成拖、**抬起时不再点按钮** | `PointerLayer.DragThreshold` |
| **悬停** | 指针下那一颗进 `Highlighted` 态；离开还原 | `PointerLayer.HoverAt` + `WindowButton.Enter/Exit` |
| **按下态** | `Pressed`；按下与抬起不在同一件 ⇒ 不派发 `onClick`（UGUI 语义，本来就有） | `WindowButton.Press/Release` |
| **纵向裁剪** | `MenuDraw.Rect` 现在**横纵两轴都截 uv**（原来只截 x ⇒ 纵向滚动区裁不住）；`MenuWindowBase.Text/TextBox` 的「整块在框外就不建」也补了 y | `MenuDraw.Rect` / `MenuWindowBase` |
| **接上滚动的界面** | 锻造轨道 · 锻造阵营条 · 战役阵营条 · 收藏窗 · 商店栅格（🆕）· **战役轨道 `Campaign Track`（🆕）** | 各自的 `Build*` |

### 3·2 🟡 **原版有、我们仍没做**（**不是「不做」** —— 判据齐了就补，铁律 11）

1. **悬停换图**（原版 `SpriteSwap` 那 **630 个按钮**）：原版实测 `bundle_menus_assets_all` 里
   1276 个按钮组件 —— `m_Transition = 2(SpriteSwap)` **630** · `1(ColorTint)` **505** · `0(None)` **141**，
   而 **630 个 SpriteSwap 的 `m_SpriteState.m_HighlightedSprite` 全部非空** ⇒ 那一档**换的是图**。
   我们这版只做了**统一的色偏兜底**（`m_Colors.m_HighlightedColor = 0.9607843`，那是 505 个 ColorTint 的行为）。
   ⇒ **要做**：逐个按钮从 bundle 读 `m_SpriteState`，把高亮图接进 `WindowButton`。
2. **软边遮罩**：原版 `RectMask2D` 的 `m_Softness` 逐处不同（商店 `Viewport` 是 **y=25**、
   `Forge Army Selector` 是 **x=42**）—— 我们一律**硬边**。
3. **文字的部分越界**：`Text`/`TextBox` 只做「整块在框外就不建」，压在视口边缘的那几个字**仍画出去**
   （文字没法像图那样截 uv）。
4. **九宫格那条路（`MenuDraw.Nine` / `RectSliced`）完全不接 `Clip`** —— 目前**没有任何滚动区用到九宫格**
   （查过：用到它的都是页头/行/弹窗，不在滚动内容里）⇒ 现在**无可观测影响**，但记着。
5. **部分可见的条目，点击区仍按整条算**（只有**整条在视口外**才不建）。
6. **键盘导航**（原版 UGUI `StandaloneInputModule` 的方向键选 + 回车确认 + ESC 取消那一套）——
   我们只有「文本框打字 + 各窗口自己的 `closeOnESC`」。**要做**。
7. **右键**：🔴 **原版就没有** —— UGUI `Button.OnPointerClick` 首行
   `if (eventData.button != PointerEventData.InputButton.Left) return;` ⇒ 原版 UI 对右键什么都不做。
   **我们跟着不做**（铁律 11「原版本身就没有」那一档），别再当漏做。
8. **卡组编辑那套滚动仍是另一份实现**（`DeckRuntime._poolScroll/_deckScroll/_fltScroll`）
   —— **明账**，将来收口到 `MenuScroll`（`CLAUDE.md` §三：两处写同一条规则 = 迟早不一致）。

> ⚠️ **`m_MovementType` 逐处不同**（1 = Clamped / 2 = Elastic）—— 我们**每个区自己声明**
> （`MenuScroll.Elastic`，默认 false = Clamped）。已知的真值：
> 商店 `Packs Scroll View` = **Clamped** · 锻造轨道 `Rewards Scroll View` = **Elastic**（规格 §1·2）。

## 四、🔴 建的时候被自检抓出来的 4 个 bug（都是同一族：**回调重入 / 生命周期假设**）

| # | 症状（自检原文） | 根因 | 规矩 |
|---|---|---|---|
| 1 | 「`Army Content` 下建了 **18 条**（共 13 个阵营）」 | `FocusOn → OnChanged → BuildArmyItems` **重入**，而它**不先清旧的** ⇒ 越建越多 | **被回调重入的构建函数必须幂等**（先清后建） |
| 2 | 「开机对到该领那一格：偏移 **2124.82**，期望 708」 | `FocusOn` 调的是 `ScrollBy`（**相对**加）⇒ 连调两次位移翻倍 | 「定位」要**绝对设值**（`SetOffset`），不是相对加 |
| 3 | 「`PointerLayer` 不在场景里 / `WindowButton` 登记表 **0 个**」 | **自检跑在编辑模式**，而编辑模式下 `Awake/OnEnable` **只对 `[ExecuteAlways]` 的脚本**才跑（`WindowHolder` 正是因此才加它 + 显式 `RegisterNow()`） | 自检里**别依赖生命周期回调**：惰性取用 + **事件时扫描**（`FindObjectsByType`）。⚠️ 顺便：`FindObjectsByType` **默认不含未激活对象** |
| 4 | 「该领那一格的 `Claim` 钮**不在命中表里**」（诊断打出 `[ClaimHit 无quad]`） | `ImageQuad.Create(parent, …)` 建的是**子物体**，命中却用 `GetComponent<ImageQuad>()`（同物体）⇒ 恒 null | 按钮上的图/字一律 `GetComponentInChildren`（同 `RewardsScene.RectOf` 那条注释） |

📌 **这 4 条已进 `资料/已知的坑.md`**。它们同时也是「**断言要能验**」的正面例子：
**4 个 bug 全部由自检报出来**，而且报的是「我们值 vs 原版值」，不是「看着不对」。
