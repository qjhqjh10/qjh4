## 二、相机对账为什么「按值定位」

原版 dump 的 `GameObject/` 是**按名字**存的（`2DCard.json` / `2DCard_1075.json`），
**没有 `GameObject_<pid>.json`** ⇒ 「相机 JSON → `m_GameObject` → GameObject 名字」这条链**解不开**
（就是 §五 记过的那条 pid 解析坑）。

⇒ 改用**按值定位**：13 场**每场只有一台相机的 `fov` 命中我们的 46.397182**（13/13 无歧义），
再比 near / far / lensShift。结果 **0 差异**，`far` 逐场 300 / 2800 / 1650 / 461.1 全对。

⚠️ **这条「按值定位」是权宜**：**不是**通用判据（若两场相机参数相同就分不出来）。
要根治得走 `PPtr` 解析（memory：**解析引用一律先走 `PPtr.read()`**）。

## 三、🔴 雾（fog）—— 真缺陷，两半

**原版机制（反编译实证）**：

- `ScenarioEnvironmentConditionSO` 的字段**只有** `blendTime / ambientColor / ambientBlend / fogColor / fogDensity / scenarioObjects / defaultScenarioObjectsState / filterOptions / animationsToChange`
  —— **没有 `fogMode`、没有 `linearFogStart/End`**
  （出处：`d:/2/Warpforge_code/Scripts/Assembly-CSharp/ScenarioEnvironmentConditionSO.cs` 字段表）
- `ScenarioEnvironmentConditionSO__ToggleFog.c` 全文一行：
  `RenderSettings.set_fog(0.0 < *(float *)(param_1 + 0x40))` —— **只切开关**，不改形状参数。
  ⇒ **雾的「形状」（mode / 线性起止）只能来自场景的 `RenderSettings`** ⇒ **它是逐场的**。

**原版逐场真值**（`07_场景/<场>/RenderSettings/*.json`，13/13 直读）：

| 字段 | 原版 | 我们 |
|---|---|---|
| `m_FogMode` | **11 场 = 2 (Exponential)** · **2 场 = 1 (Linear)**：`aeldari` / `blacklegion` | **全部 3 (ExponentialSquared)** |
| `m_LinearFogStart/End` | **逐场**（5 种组合）：7.47/8.75（8 场）· 4.4/27.6（arena2）· 0/155.8（arena3）· 65.3/181.5（aeldari · leviathan）· 51.6/132.3（blacklegion） | **全部 0/300** |
| `m_FogColor` | **逐场**（4 种）：(1,1,1) ×8 · (0.660,0.370,0.115) arena2 · (0.415,0.355,0.233) arena3 · (0.509,0.267,0) aeldari/blacklegion | 场景里是 Unity 默认 **(0.5,0.5,0.5)** |
| `m_FogDensity` | **逐场**：`aeldari`/`blacklegion` = **0.012**，其余 **0.0** | 场景里是 Unity 默认 **0.01** |

**两半缺陷**：

- **① 生成器（`工具/scripts快照/gen_unity_arena_manifest.py:1110-1111`）只读 `m_FogColor` / `m_FogDensity`**
  —— **`fogMode` / `m_LinearFogStart` / `m_LinearFogEnd` 根本没进 manifest** ⇒ 下游无从设置。
- **② `ArenaBuilder` 连已进 manifest 的 `fogColor` / `fogDensity` 也没写进场景**
  （场景里读到的是 Unity 默认的 0.5 灰 / 0.01，而 manifest 里 arena1 是 (1,1,1)/0.0、aeldari 是 0.012）。

**为什么现在看不出来**：13 场 `m_Fog` 全是 false ⇒ **静态渲染完全不受影响**。
**什么时候会露**：**4 环境**那条链 —— 进攻卡生效时 `ToggleFog` 会把雾打开（`fogDensity > 0`），
届时 mode / 颜色 / 线性范围**全是我们这套错的默认值**。
⇒ **这条同时是 §28 的正确性缺陷与 §30 第 5 件「4 环境」的前置数据缺口**（铁律 11：要做）。

### 第三半的确切改法（已读代码，落点在这儿 —— 等 Unity 批处理跑完再动 `.cs`）

**现状**（`MyGame/Assets/WarpforgeArena1/Editor/ArenaBuilder.cs:2444-2452`）：

```csharp
float fd = mf.defaultEnv != null ? mf.defaultEnv.fogDensity : mf.ambient.fogDensity;
RenderSettings.fog = fd > 0f;
if (RenderSettings.fog)                                   // ← 13 场默认 env 的 fogDensity 都是 0 ⇒ 这块【从不执行】
{
    RenderSettings.fogColor   = ToColor(...fogColor);
    RenderSettings.fogDensity = fd;
    RenderSettings.fogMode    = FogMode.Exponential;      // ← 而且硬编码，原版是逐场（1 Linear / 2 Exponential）
}
```

⇒ **两个毛病**：① 关着雾时**什么都不写** ⇒ 场景里留 Unity 默认（mode 3 / 0.5 灰 / 0.01 / 0–300）；
② 真开雾时 mode 也是**写死的 Exponential**，对 `aeldari`/`blacklegion`（原版 Linear + 65.3/181.5、51.6/132.3）是错的。

**改法**（`AmbientData` 类加 `fogMode` / `linearFogStart` / `linearFogEnd` 三个字段，然后）：

```csharp
// 雾的【形状】无条件照原版场景写（SO 里没有这三项，见 §三 判据）
RenderSettings.fogMode        = (FogMode)mf.ambient.fogMode;
RenderSettings.fogColor       = ToColor(mf.ambient.fogColor);
RenderSettings.fogDensity     = mf.ambient.fogDensity;
RenderSettings.linearFogStart = mf.ambient.linearFogStart;
RenderSettings.linearFogEnd   = mf.ambient.linearFogEnd;
// 开关与「运行时覆盖」照旧（判据 = 原版 ApplyFog：0 < SO 的 fogDensity）
float fd = mf.defaultEnv != null ? mf.defaultEnv.fogDensity : mf.ambient.fogDensity;
RenderSettings.fog = fd > 0f;
if (RenderSettings.fog) { /* 照旧：颜色/密度取 defaultEnv */ }
```

⚠️ 改完要**重打 13 份 `Battle_<场>.unity`**（`工具/_build_battle_scenes.sh`，**串行**）
＋ 跟一次 `BattleScene.BuildAndSaveScene`（铁律：改完战场必须跟一次）。

**实际落地时踩到的两点**（都已进代码注释）：

1. 🔴 **Unity 的 API 名与场景 YAML 名不一样**：YAML 是 `m_LinearFogStart/End`，C# 侧叫
   **`RenderSettings.fogStartDistance` / `fogEndDistance`** —— 写 `linearFogStart` 会 `CS0117`
   （**秒级类型检查当场抓到**，见 `资料/命令速查.md` 的「秒级类型检查」）。
2. ⚠️ **`fogMode` 要防缺字段**：`mf.ambient.fogMode` 缺省是 **0**，而 `FogMode` 枚举
   **1 = Linear / 2 = Exponential / 3 = ExponentialSquared**（**没有 0**）⇒ 老清单会写进一个非法值。
   已加 `>= 1 ? (FogMode)… : FogMode.ExponentialSquared`（并出声）。

## 六、🔴 2026-09-30 抓到的真缺陷：`gen_arena_negscale.py` 的名字索引 bug（已修一半）

**怎么发现的**：独立数「原版里负缩放的**网格**对象」→ 与我们的 `<场>_negscale.json` 对 → **少了 9 个**。

**根因**（`工具/gen_arena_negscale.py:113`，原代码）：


| `Side Altar 2 L.json` | `'2 L'`（唯一 ⇒ 侥幸能用） |
