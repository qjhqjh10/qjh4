## 〇、一句话结论

`SetupEnviromentalEffectPhase` 是**换牌之后、开打之前**那一段「选环境效果卡」：**面板永远只给「本机这一侧」弹**，
但**列出的池子取自【后手那一方】的阵营**（本机先手 ⇒ 弹的是**对手阵营**的进攻卡池；本机后手 ⇒ 弹**本机阵营**的防御卡池）。
面板标题那两个 `DAT_` 就是 **`"offensive"` / `"defensive"`** 两个词条名。
**后手方「选防御卡」这一步是存在的**（就是同一个面板的 `defensive` 那一档，**没有第二个弹窗**）；
而 `AddGoesSecondCardToDeck` 是**另一件事**：它从**同一个防御池**里随机抽一张塞进后手方**手牌**，
且**只在 `matchType ∈ {50,80,110,120}`**、且**卡组没带防御卡**时才生效 —— 官方文案 `Random Defence card` 说的是它。

### 2.3 给谁弹 / `+0x247` 的极性（**这是本轮最要紧的一条**）

- `+0x247` = **`playerGoesFirst`**，且 **true = 本机这一侧先手**：
  - `GetStartingMana(bool isPlayer)`：`isPlayer == playerGoesFirst` ⇒ 返 **`startingMana`(+0x2c)**，否则 `startingManaSecond`(+0x30)（`:7-20`）；
  - `SetupInitialMana(bool isPlayer)`：`playerGoesFirst == 0` ⇒ **本机**拿 `startingManaSecond`(+0x30)（`:24,33-35`）；
  - `MulliganManager.ActivateMulligan(bool goFirst)`（`dump.cs` 形参名就是 `goFirst`）由 `SetupMulliganPhase` 传入 `+0x247`（`_SetupMulliganPhase_d__341__MoveNext.c:143`）；
  - `PlayerHand.AddCardsToMulligan(..., manager.playerGoesFirst, ...)` 给 `playerHand(+0xd0)`、`!(...)` 给 `enemyHand(+0xd8)`（同上 `:80,84`）。
  ⇒ **`+0x247 == 1` ⇒ 本机（`playerManager` 那一侧）先手。**
- 面板挂的是 **`manager.chooseCardManager`(+0x1f8)**，选完由 `ChooseCardMenu.ProcessChooseDone` →
  `BattleManager.ClickChosenCardDone(选中卡)`（`ChooseCardMenu__ProcessChooseDone.c` 尾部那段），
  而 `ClickChosenCardDone` 把 id 写进 **`matchData.playerEnviromentalEffect`(+0x90)**（见 §六）
  ⇒ **面板 = 本机这一侧的选卡口，卡进的是"player"槽**。
- ⚠️ 但列表的**阵营**不是本机的 —— 见 §三（`GetEnvEffectCards` 里 army 恒取**后手那一方**）。

### 2.4 `+0x49 == 0` 那一支对应谁（**不是"对手"**）

`GameplayVariablesData.showMulligan == false` ⇒ **本机这一侧的卡由系统自动挑**：
- 本机是**后手**（`playerGoesFirst == 0`）⇒ 列表是**防御池** ⇒ **`UnityEngine.Random` 均匀随机**取一张；
- 本机是**先手**（`!= 0`）⇒ 列表是**进攻池**、下标 0 = 空卡 ⇒ **取"不使用进攻卡"**（不换环境）。

**对手那一张不在这里挑**：它在 `ClickChosenCardDone.c:58-63`，
`AI.GetAiEnvEffectCard(aiManager, GetEnvEffectCards(!playerGoesFirst, /*justOwned=*/0, 0))`
→ `matchData.enemyEnviromentalEffect`(+0x98)。而 `AI__GetAiEnvEffectCard.c:27-33` 是
**`BattleManager.GetRandomInt` → `MatchData.GetRandomInt`（对局种子 RNG，可复现）** 的均匀随机，空表返空串占位。

> 所以「随机抽 vs 取第 0 张」和「谁」是两件事：
> · `MoveNext` 的两支 = **本机自动挑**（先手取空卡 / 后手随机取防御卡），条件是 `showMulligan == 0`；
> · 对手 = **`AI.GetAiEnvEffectCard` 均匀随机（种子 RNG）**，与本机是不是"自动"无关。

## 三、第 2 问：`GetEnvEffectCards(bool shouldUseOffensive, bool justOwnedCards)`

### 3.1 army 恒取【后手那一方】的阵营（`:38-48`）

```

else                      lVar8 = manager.enemyManager (+0xc8);
```

`playerGoesFirst ? enemyManager : playerManager` = **"谁后手就用谁的 `PlayerManager`"**（本机先手 ⇒ 对手后手 ⇒ 对手的 manager）。
**这一点由三处独立证据钉死**（不是我的推测）：

1. `AddGoesSecondCardToDeck.c:145` 传 `shouldUseOffensive = 0`（= **防御池**），而它的用途（函数名 + `:184` `AddNewCardToHand`）
   就是「发给**后手**那一方」⇒ 后手方才该拿到"防御池"，与上面的 army 取值一致。
2. `ApplyOffensiveAndDefensiveEffects` 里判"是不是空卡"用的是
   `SO.GetEmptyOffensiveCard(**GetHero(manager, playerGoesFirst == 0).army**)`（`_ApplyOffensiveAndDefensiveEffects_d__337__MoveNext.c:99-107`），
   而 `GetHero(true) = playerManager.heroCard`、`GetHero(false) = enemyManager.heroCard`（`BattleManager__GetHero.c:7-13`）
   ⇒ 传进去的也是**后手那一方**的阵营。
   🔴 这一条**有判别力**：13 个阵营的 `emptyOffensive` 是 **13 张不同的卡**（我们表 `offensive_cards.json` 里 PathID 13 个互不相同），
   所以"进攻卡 id"必须来自**后手方阵营**的池子，这条比较才有意义（否则"选了空卡"这一支永远判不出来）。
3. `AddGoesSecondCardToDeck.c:28-95` 里取"卡组里那张防御卡"时同样是
   `playerGoesFirst ? matchData.enemyRawBattleData(+0x50) : matchData.playerRawBattleData(+0x58)`（同一个"后手方"口径）。

`param_2`（= `shouldUseOffensive`）除此之外还决定**加不加空卡**（见下）；`param_3`（= `justOwnedCards`）**只**往下传（见 3.3）。

### 3.2 `shouldUseOffensive != 0` 时前置那张空卡（`:50-59`）

`list.Add(SO.GetEmptyOffensiveCard(army))`，**插在下标 0**（`List` 刚 new 出来、size=0 ⇒ 直接落到 `_items[0]`）。

⇒ **空卡只出现在"进攻"那一路，且恒在下标 0**；`justOwnedCards` **不影响**它（不看不筛）。
⇒ 面板上第一张 = `Normal Conditions`（各阵营自己那张，SW 叫 `Default Conditions`、Tau 拼成 `offence`）—— 与 `资料/加时与冲突模式_原版规格.md:306` 一致。

## 四、第 3 问：后手方有没有「选防御卡」这一步 —— **有**（选项 (a)+推论 (c)）

**答案：就是 (a)。后手方弹的**同一个** `ChooseCardMenu`，列表是该阵营的 `defensiveCards`（3 张、无空卡）。**

- 判据链：`MoveNext:63` 的 `shouldUseOffensive = playerGoesFirst` + 标题 `playerGoesFirst ? "offensive" : "defensive"`（`:99-105`）
  ⇒ **本机是后手 ⇒ 列表 = 后手方（= 本机）阵营的防御池、标题 "defensive"**；本机是先手 ⇒ 列表 = 后手方（= **对手**）阵营的**进攻池**、标题 "offensive"。
- **(b) 不成立**：`AddGoesSecondCardToDeck` **不是**唯一的防御卡来路，它是**战前发放**那条：从**同一个防御池**随机抽一张进**手牌**。
- **两处实参对比（是不是同一份列表）**：

| | 面板（`MoveNext:63`） | `AddGoesSecondCardToDeck.c:145` |
|---|---|---|
| 实参 | `(playerGoesFirst, /*justOwned=*/1, 0)` | `(0, /*justOwned=*/0, 0)` |
| 池子 | 先手时**进攻池** / 后手时**防御池** | **恒防御池** |
| 等级门槛 | **按 `forgeLevel` 筛**（只给已解锁） | 不筛 |
| 结果去向 | `matchData.playerEnviromentalEffect`（本机的环境卡） | **`AddNewCardToHand`（后手方手牌）** |

⇒ **不是同一份列表**（同源、同阵营、**不同筛选**、**不同去向**）。
- `AddGoesSecondCardToDeck` 的三个附加条件（逐行读，非按文件名）：
  1. `matchType ∈ {50 PracticeOffline, 80 EventAI, 110 ClosedDeck, 120 ClosedDeckBot}`（回放局看 `matchReplayType`）才做随机替换（`:104-142`，`MatchType` 枚举实读）；
  2. **本机是后手、且本机卡组 `DeckAndWarlordData.defensiveCard(+0x20)` 非空 ⇒ 随机那张被卡组那张覆盖**（`:154-166`）；
