# 卡牌制作 · 样板库（2026-10-18 立）

> **这份讲什么**：**每个「代表形状」挑 1 张真实卡，把「卡 SO → 效果 → 动画 GUID → CardAnim → VFX prefab → 我们侧事件 → 本地化 → 立绘」整条链写成可对照的样例。**
> 做新卡 / 接新特效时，先在这里找一张形状最像的，照它抄。
>
> **配套**：知识正本 = `资料/卡牌制作_正本.md`（字段/枚举/五层总图）；本文件只给**样例**，不重复讲规则。
>
> **判据层级**（与 `CLAUDE.md` 铁律 2 一致）：
> ① 原版卡 SO 实测字段 = `资料/普查产出_1018/allcards_1350/cards_raw.json`（1,351 张）
> ② 逐卡 VFX / 事件归类 = `数据/游戏数据/card_vfx_by_card.json`（`byCard`，1,127 张）
> ③ GUID → 资产名 = `资料/普查产出_1018/cardanim_guid_map/guid_map_bundles.tsv` + `数据/索引/anim_address_map.json`
> ④ 本地化 = `数据/游戏数据/官方本地化_en+zh-CN.json` 的 `terms`
> ⑤ 枚举 = `d:/2/Warpforge_code/Scripts/Assembly-CSharp/*.cs`（签名桩）
>
> **维护**：数值一律从 `cards_raw.json` 现抄，⛔ 不凭印象补。发现抄错按铁律 5 就地改。

## §〇 读之前先看：三档判定与记录格式

### 0·1 一条动画链的「三档」，别混成一句「有 GUID」

| 档 | 判据 | 本库怎么标 |
|---|---|---|
| **① GUID 可解** | 该 GUID 在 `guid_map_bundles.tsv` 或 `anim_address_map.json` 里能查到**资产名** | 列出 `GUID → CardAnim 名` |
| **② CardAnim 有 animInfo** | 该 CardAnim 的 dump 里 `animInfo.animAdressable.m_AssetGUID` 有值 | 列出 `CardAnim → (animAdressable GUID) → prefab` |
| **③ prefab 在本地且已进我们效果库** | `card_vfx_by_card.json` 里该条 `inLibrary=true`（prefab 落在 `WarpforgeVFX/Prefabs/` + `WarpforgeEffectLibrary.asset`） | 列出 `prefab` + 我们侧事件 |

⚠️ **「GUID 可解」≠「能播」**：本库 15 张卡的 **41 条**引用**三档全过**（`inLibrary` 全为 `true`）；
但全池还有 163 条引用（112 张卡）在 `card_vfx_by_card.json` 里没有对应条目 —— 见 §四·3。

### 0·2 记录格式（每张卡一张表）

| 行 | 写什么 |
|---|---|
| **身份** | `uniqueId` · `cardName`（内部名）· `Card_Name/<id>` 的 en / zh |
| **类型/数值** | `cardType` / `spellType` / `manaCost` / 近战·远程·生命·护甲 / `keyword`（兵种）/ `cardRarity` / `expansionPack` |
| **规则效果** | `cardAbilities[i].abilityLogic[j]` 的 `trigger`（值+枚举名）· `triggerValue` · `chosenAbility`（值+枚举名）· `targetsAffected`（值+枚举名）· `playersAffected` |
| **动画链** | `soField`（哪一格的 GUID）→ GUID → CardAnim → prefab → **我们侧事件** |
| **本地化** | `Card_Name/<id>` · `Card_Description/<id>`（含 en / zh 全文） |
| **立绘** | `cardImageReference` GUID → 资产名（束） |
| **语音 / 逐卡粒子** | `summonAudio` / `attackAudio` / `deathAudio` / `customRangedAttackParticles` / `customDeathParticles` / `remnantBodyPrefab` 的 GUID |
| **照它抄** | 这张卡代表什么形状 |

> **我们侧事件名** = `VfxMap` 的那一套：`play` / `deploy` / `attack_melee` / `attack_ranged` / `hit` / `heal` / `death` / `ability` / `trigger` / `return` …（正本 §4·4）。
> `card_vfx_by_card.json` 的 `abilityEvent` 已经把「原版 trigger → 我们事件」拍好了；表里直接抄，⛔ 不要自己另推一套。

## §四 判据缺口 / 已知坑（⛔ 别当定论）

1. **`Whispers`（`cardType=40`）当前 build 0 张**。
   判据：`cards_raw.json` 1,351 张现算 `cardType` 分布 = `{0:605, 10:66, 20:680}`，**没有 40**。
   ⇒ 要做 Whispers 卡，**本地没有原版样本可抄**；只能照 `CardTypeOptions.cs` 的枚举值 + 现有 Tactic 的形状自建。

2. **`anim_address_map.json` 对 EC（帝皇之子）缺 27 个 CardAnim**（77 条引用 / 61 张卡）。
   判据：这些 GUID 在 `guid_map_bundles.tsv` 里是 `source=old-map`、`containerKey` 是短 id（例 `bc`），而 `anim_address_map.guid_to_asset` 没有它们。
   **补法（已验证）**：读 `assets_full/bundle_chaosspacemarinesemperorschildrencardanims_assets_all/MonoBehaviour/<CardAnim 名>.json` 的 `animInfo.animAdressable.m_AssetGUID`，再查 `guid_to_asset` —— **27/27 全部可解**。
   ⚠️ `card_vfx_by_card.json` 里 **25/27 已有条目**（只有 `EC Target User Warlord` / `Buff EC Creating Card Warlord` 两条没进表）⇒ **运行时表基本没受影响，受影响的是「查表脚本」**。

3. **全池有 163 条 `cardAnimations` 引用（112 张卡）在 `card_vfx_by_card.json` 里没有对应条目**。
   抽样：这些 GUID 都能解出 CardAnim 名（如 `DA Teleport Summon Next` / `Buff_Tyranid Atk`），但 `cardanim_to_asset` 没有落到 prefab。
   ⇒ **「没进逐卡表」≠「本地没有 prefab」**；要接这几张卡得先补齐 `cardanim_to_asset`（本库 15 张卡**不在**这 112 张里，全部已覆盖）。

4. **SOR3 的 `Talent` / `Pray` 两条效果没有 `cardAnimations`**；AM36 的 `Regiment` 也没有。
   ⇒ 遇到 `cardAnimations` 为空的 ability，**不是漏抄**（原版如此），动画要靠关键词/通用动画（`byCard` 里 `inferred-keyword` 那类，⛔ 不是原版逐卡绑定）。

5. **`EC29` 的立绘在 `anim_address_map` 里查不到**，但 `card_vfx_by_card.json → _assetRefs[0]` 有（`CSM_EmperorsChildren_veh_Heldrake`）。
   ⇒ 查立绘**优先用 `card_vfx_by_card._assetRefs`**，它是从 SO 的 `cardImageReference` 直接解出来的。

6. **`GOF105` 的卡面名/描述里有 `$$卡id$$` 指代** → 解析要落到 `Card_Name/<id>`（`CardIcons.cs:621-639`），⛔ 不要当普通文本显示。

7. **本库不覆盖「光环 / WhileInPlay」类**：需要那类样本时去 `RuleEngine/Core/Aura.cs` 的相关卡（正本 §3·2 的 20/240 行）与 `cards_raw.json` 里 `trigger=20/240` 的卡，本库没有挑。

8. **「或者」句式（`or`）的最终语义没查清**：本库挑的 **SW43** 在 SO 里是**两条独立 `cardAbilities`**（一条 `buffOthers`、一条 `doHeal`，都 `ThisCardPlayed`）。这**不等于**「原版一定两条都跑」，也**不等于**「二选一」。正本 §7·1 / CLAUDE.md 铁律 7 讲的是英文 `or` 的两种含义（二选一 / 条件换数值），**判据在中文与 `choose` 关键字**；本条只记录「结构长什么样」，语义要另查（`BoardCriteria` + `targetIfMeetsCriteria` 的结算代码）。

## §五 一句话

**照着一张真卡抄，比照字段表拼快 10 倍**：先从 §一 找到形状 → 到 §二 抄它的 `trigger`/`chosenAbility`/GUID 链 → 用 §三 反查「要做什么」 → 最后回 §四 确认你不是踩在判据缺口上。
