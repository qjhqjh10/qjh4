## ② 三条断言的「牙」（改前 / 改后）

### 断言 1 `:17188` `Check(u.Attack, 6, "★ 近战翻倍（3 → 6）")`

- **改前**：**恒红**（不是「没牙」）—— 触发器一次都没响。`RuleCore.cs:3960` 是
  `if (hpBefore > ex && u.Health <= ex)`，而 `hpBefore = 4`、`ex = 5` ⇒ `4 > 5` 假 ⇒ 不触发 ⇒ 近战停在 3。
  即：**它期望一个在该前提下不可能出现的结果**（这正是 X1 报的 `期望 [6] 实得 [3]`）。
- **改后**：`hpBefore = 6`、`u.Health = 5` ⇒ `6 > 5 && 5 <= 5` ⇒ `FireTriggerOnBoard` ⇒ `DoDouble` 翻近战。
  会让它红的改坏法（任一条）：
  1. **触发器整个不响** —— `RuleCore.cs:3960` 的 `u.Health <= ex` 被写成严格 `<`（`5 < 5` 假）；或闸①
     `u.Has(KeywordTable.Ecstasy)`（`:3957`）坏掉 / 关键词认不出；或 `EcstasyX` 解不出 5。
  2. **`DoDouble` 不翻近战** —— `EffectResolver.cs:7043` 的 `dMelee` 假（载荷里没有 `melee`）
     ⇒ `:7058` 不执行 ⇒ 停在 3。
  3. **目标指不到自己** —— `ResolveTargets` 对 `this troop` 解析坏（`:7052-7057`）⇒ `n == 0` ⇒ 不翻。
- ⚠️ **反例（重要）**：把 `hpBefore > ex &&` 整个删掉，**本格照样绿** —— 因为 `5 <= 5` 本来就在跨越点上，
  删不删都一样。**「删掉 `hpBefore > ex` 会红」的是 ④ 那格（反例一 2 → 1 仍在阈下），不是本格。**
  简报 `硬要求 1` 里那句括注与本格不符，**以现读为准**（判据 = `RuleCore.cs:3960` + 本格夹具 6 → 5）。
