## 一 改动面逐条「改前 / 改后」

### 1·1 新增一件（本仓唯一的「两段式」口径）

**新文件** `Unity/MyGame/Assets/CardPresentation/Core/CardbackFace.cs`（+ `CardbackFace.cs.meta`，guid `3b7b3cffccae4d8c8c89eabdf12f926c`）

```csharp
// ① 定框：比的是 sprite 的 m_Rect（707×1020），⛔ 不是贴图自己的宽高
spriteRatio = rectW/rectH;  boxRatio = boxW/boxH
spriteRatio > boxRatio ? (fw = boxW, fh = boxW/spriteRatio) : (fh = boxH, fw = boxH*spriteRatio)
// ② 画心：框 × (textureRect / m_Rect)，再按 padding 挪
sw = (rectW − padL − padR)/rectW ; sh = (rectH − padB − padT)/rectH
w = fw*sw ; h = fh*sh ; k = fw/rectW
dx = (padL − padR)*0.5f*k ; dyUp = (padB − padT)*0.5f*k      // 出参 y **向上**为正（uGUI 的方向）
```

- 出处逐条写在文件头：`Image.cs:830-860 GetDrawingDimensions` · `:810-827 PreserveSpriteAspectRatio`（本机现读）。
- **兜底**：贴图**没登记**（非卡背 / `<名>_sdf`）⇒ 把「贴图自己」当成 `m_Rect`、`padding = 0` ⇒ 整段**逐字退化**成
  本仓原来的「按贴图自身比例内接、居中」（`dx = dyUp = 0`）。**⇒ 旧调用点零变化**（这是「不越界改别人」的机械保证）。
- **`_SDF` 故意不进表**（C1 裁定「这层本来就是对的、不用动」）：它 233/233 的 `m_Rect == textureRect`（差 0.5px 图集取整），
  两段式与本式只差 **0.34%（1.5px）**，而严格套公式会因那 0.5px 把它**横挪 1.7px**（量化噪声，不是原版语义）。
