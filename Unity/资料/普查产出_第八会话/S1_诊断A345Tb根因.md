### 3·3 生成侧：这一条是**旁挂算宽了**（根因所在）

`Unity/工具/gen_arena_groups.py`：

```
:415-420   # 灯 / 相机**不在** `meshes`/`particles` 里（`ArenaBuilder` 单独建它们…）
           lv = manifest.get('light') or {}          # ← 灯：确实由 BuildContent 里的
           if ...: add('light', lv['name'], lv.get('pos'))   #   ApplyLightAndAmbient 建进 root ✅
```

⇒ **`built_paths` 里那句「ArenaBuilder 单独建它们」对【灯】成立、对【相机】不成立**：

- 灯：`BuildContent` 末尾 `ArenaBuilder.cs:2639` `ApplyLightAndAmbient(root.transform, mf)` ⇒ **建在 `root` 里** ⇒ `FindBuilt` 找得到 ✅

**一个「同一份清单、两处口径」的典型**（`CLAUDE.md` §三「两处写同一条规则 = 迟早不一致」）：
`is_built(...)`（`:456`）对 `meshes`/`particles` 是**逐条对读 C# 的四道闸门**，
而对 `light`/`camera` 只是**一句注释里的假设** —— 相机这一格假设错了。

### 3·4 结论归类（按你给的三档）

> **「原版本来就没有」= 否**（原版有，实据见 3·1）。
> **「我们有东西没搬」= 也不是**（相机建了，在战斗场景 / 独立场景里；功能不缺）。
> ⇒ **第三类：判据（旁挂 `targets[]`）与实现（`BuildContent` 的产出）口径不一致** ——
> **旁挂多算了一条、C# 永远对不上**。所以「1 条」不是缺陷、也**不是**「预期的」——
> 它是**一笔【假待办】**：`A345-T-b` 的「没对上 0 条 ×13」**照今天这条链永远达不成**，
> 除非**动生成侧**（或让 C# 显式承认相机不在内容树里）。

## ④ 为什么是「1」这个固定值（假设 + 验没验）

**假设**：`manifest.camera` 是**每场唯一一个**相机，且它是 `built_paths` 里**唯一一个
`BuildContent` 从不建的对象** ⇒ 每场恰好 +1。

**验过了**：

1. 现读 13 份 `<场>_manifest.json`：`camera.name` **13/13 都是 `BoardCamera`**、`pos` 逐场相同
   —— 每场**一个**相机对象（不是零、不是多）。
2. 现读 13 份 `<场>_groups.json`：`targets[]` 里 `BoardCamera` 条目 **13/13 恰好 1 条**。
3. **`targets.Length = moved + 1` 在 13 场全部成立** ⇒ **除了相机，全场再无第二条没对上**
   （所以不是「某几场多、某几场少」）。
4. 反证「灯那一格是对的」：`Directional Light` 同属 manifest 顶层单例、同样被 `add()` 进 `built_paths`，
   但它**建在 `root` 里** ⇒ **0 条没对上**。两格一对比，**唯一差别就是 BuildContent 建不建它**。
5. 🔴 **不是**「某个全局唯一对象每场都漏」的**泛**现象 —— 是**相机这一格**：
   环境体 / UI 根 / 天空盒 / 后处理 Volume 都**不在** `targets[]` 里（它们不是 `built_paths` 的条目），
   所以谈不上漏。

**⇒ 「1」是这么来的：`每个 prefab = 1 个 manifest.camera = 1 条 `built_paths` 里永不成立的目标`。**
