## 四、顺手发现的（⛔ **我一条都没改**）

1. 🔴 **`t.Exhausted = true` 与「原版的推导值」之间可能还有一层差异（需调度台裁定，别当我已查清）**：
   原版 `ResetSummonSickness` 写的是**字段** `summonSickness = 1`；**真正决定能不能动的那一位**
   是 `canAct`（`+0x230`），它由 `CardScript__ActivateMinion.c:39-42` 算成
   **`!displaySummonSickness`**，而 `displaySummonSickness = +0x58 && !fast(0x28) && !flank(0x1cc)`
   ⇒ **若被抢的单位【本身】带 `fast`/`flank`，原版的 `canAct` 会是 true（能动）**，而我们写死
   `Exhausted = true` 会判它不能动。
   ⚠️ **今天不可观测**：全池只有一张 `takecontrol`、它自带 `and give it Fast`（尾句会把 `Exhausted` 清掉）
   ⇒ 两种读法在**真卡上完全等价**。我**按施工单字面做了**（「无条件」），把这条差异留痕在此。
   若调度台要严格按「推导值」，最小改法是这一句换成 `t.Exhausted = !RuleCore.HasDeployExemption(t);`
   （判据链与本工程已有的同形写法：`RuleCore.ApplyDeployTurnState` = `Exhausted = !HasDeployExemption(u)`）。
2. 🔴 **同一个语义「转移归属 ⇒ 重新入场」在本仓已有的写法是 `RuleCore.ApplyDeployTurnState(...)`**
   （`EffectResolver.cs:7482`，残骸翻回来的第三入口 `DoReanimate` 就是调它）。
   **我特意没用它**，原因是一条**静默坏卡**的风险：`ApplyDeployTurnState` **同时**写

   **「能动、但不能攻击」**，而卡面写着 `give it Fast` ⇒ **把已发布的卡打坏**（F7 那一类坑）。
   （`CannotAttackThisTurn` 只在构造时与 `ApplyDeployTurnState` 里写，`AddKeyword` **不重算它**
   —— 现读 `UnitState.cs` + 全仓 `Exhausted` 写入点清单确认。）
