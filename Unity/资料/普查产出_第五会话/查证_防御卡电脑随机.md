# 查证：后手那张卡 / 防御卡 —— 电脑（AI）那一方在代码里怎么定的（2026-10-08 · 第五会话 · 只读）

## 一、结论（5 行）

1. 原版发「后手那一方」那张卡的函数是 `BattleManager__AddGoesSecondCardToDeck`（下称 AGS），共 **3 条来路**（表见 §二）：
   ①后手方**卡组自带**的 `DeckAndWarlordData.defensiveCard(+0x20)`；②`matchType ∈ {50,80,110,120}` 时从**后手方阵营的防御卡池随机抽**；③**电脑后手且卡组那张为 null** 时读**该督军自己的 `goSecondCardInHand(+0x150)`**。
2. 🔴 **电脑那一方永远拿不到①**：`PrebuiltDeck` 根本没有防御卡字段，而 `CardDeck..ctor(PrebuiltDeck,List)` 把 `defensiveCard` **显式写成 0**（`DeckBasicSetup` 第 5 实参 = 0）⇒ `DeckAndWarlordData.defensiveCard` 恒 null。**⇒ 电脑只有②③两条来路。**
3. ②的池子 = `EnviromentalEffectCardsSO` 里**后手方阵营**的 `DefensiveCards`（每阵营 **3** 张，= 我们 `数据/游戏数据/defensive_cards_39.json` 的 13×3）；随机源 = `MatchData.GetRandomInt`，取的是**开局预抽好的 100 个数表**（`UnityEngine.Random.Range(0,1000)`，非 `System.Random`）。
4. 我方现在的实现（`RuleCore.cs:491`）**两边都从卡组列表取第一张 `Type=="defence"`**：玩家侧与原文等价（原版玩家侧 = 玩家在卡组里挑的那张）；**电脑侧是真偏离**（原版电脑侧恒不从卡组取，且我们给预组补的 `defensiveId` 是**确定性**挑的：本阵营 cost 最低 → id 最小，`资料/预组卡组_原版规格.md` §五之七）。
5. ⇒ `A1070` **判定「算真偏离，要做」**；改法与所需数据见 §五。

## 四、电脑那张 = null（反汇编实证，两条独立链）

1. `MatchData__SetBotOpponent.c:50-72`：`GetBotDeck` 拿 `PrebuiltDeck` ⇒ `new DeckAndWarlordData(prebuiltDeck, playerData)`（RVA `0x7280A0`）。
2. **VA `0x1807280A0`**：先 `new CardDeck` + `CardDeck..ctor(PrebuiltDeck, allCardCollection)`（`call 0x1809273d0` = RVA `0x9273D0`），再 `call 0x1807279b0` = `DeckAndWarlordData..ctor(CardDeck)`（RVA `0x7279B0`，= `dump.cs` 报的那个 `.ctor(CardDeck deck)`）。**该函数全程没有写 `+0x20`。**
3. **VA `0x1809273D0`**（`CardDeck..ctor(PrebuiltDeck,List)`）：写 `+0x20`(prebuiltDeckId) / `+0x28`(cardbackId) / `+0x30` / `+0x70`(gameMode) / `AddRange`→`+0x58`(cardLibrary)；在 `0x1809275A2` 调 **`CardDeck.DeckBasicSetup`（VA `0x1809251B0`）**，实参 `RCX=this, RDX=名字, R8=督军, R9=0, [rsp+0x20]=0, [rsp+0x28]=0`。**永不写 `+0x48`。**
4. **VA `0x1809251B0`**（`DeckBasicSetup`）：`0x18092526B  lea rcx,[rdi+0x48]` + `0x180925272  mov [rcx],rdx`，而 `rdx = [rsp+0x70]` = **调用点第 5 实参** = **0** ⇒ **`CardDeck.defensiveCard = null`**。
5. ⇒ `DeckAndWarlordData..ctor(CardDeck)` 的 `this+0x20 ← deck+0x48`（`DeckAndWarlordData__.ctor.c:68-70`）搬到的就是 null。**与 §二 `:65-89` / `:145-153` 两条兜底完全吻合。**
6. 对照玩家侧：`MatchData__SetPlayerDeck.c:50-58` 用 `.ctor(CardDeck)`（玩家自己的卡组）⇒ `defensiveCard` = **玩家挑的那张**；从存档读回时按 id 找回（`DeckAndWarlordData__SetupSerializedData.c:62-63` 的 `List.Find` + `<SetupSerializedData>b__0`：`card.+0x38(uniqueId) == SerializedPlayerDeckData.+0x20`）。面板写入口 = `CardDeck.AddDefensiveCard`(0x48) / `TryAddDefensive` / `CanAddDefensive`。

**池子 / 随机源**：`GetEnvEffectCards(0,0,0,0)` → `playerGoesFirst ? enemyManager : playerManager` 的 hero 的 `army`（**恒后手那一方**）
→ `EnviromentalEffectCardsSO.GetEnvCardList(army, shouldUseOffensive:false, …)` → 该 `EnviromentalEffectReferenceData.DefensiveCards`（`{defensiveCard, forgeLevel}`）。
⚠️ **池子挂在 Forge 事件上**：`LiveOpsManager.GetHandler<ForgeHandler>()` 找不到本阵营那条 Forge ⇒ **直接 return 空表**（一个都不给）——详见 `资料/普查产出_0930/进攻防御卡_面板语义.md` §3.3。
随机源 = `MatchData.GetRandomInt(min,max)`（RVA `0x735240`）：`randomNumbers(+0x20)` 是 `GenerateRandomNumbers` 用 `UnityEngine.Random.Range(0,1000)` 一次抽 **100** 个数，`randomNumbersIndex(+0x28)` 逐个取、按 `index % count` 绕回。
