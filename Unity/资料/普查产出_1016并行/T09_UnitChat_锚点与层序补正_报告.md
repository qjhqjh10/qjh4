### ④·三 为什么世界档那一乘是 `LayoutSpace.Scale`（而不是写死 `1/108`）

判据（**等价变换，逐值核过**）：`scaleFactor = min(W/1920, H/1080)`；`Scale = min(1, VW/DesignWidth)`，`VW = 10·(W/H)`、`DesignWidth = 10·(16/9)`

```
scaleFactor · 10/H  = min(W/(192·H), 1/108)
Scale/108           = min(1, VW/1920)/108 = min(1/108, W/(192·H))    ← 两式逐项相同 ⇒ 恒等
```
⇒ `ap_world = ap_canvaspx · Scale/108` 就是「画布 px → 屏 px → 世界单位」那条链的合成 ✓
（16:9 下 `Scale = 1` ⇒ `1/108` ⇒ 与旧式逐位相同；4:3 下 `0.75`、16:10 下 `0.9`、21:9 下 `1` ✓ 与 `scaleFactor` 一致）。
⚠️ **`Scale` 走 `Cam.aspect`、`scaleFactor` 走 `Screen` 像素** —— 批处理下**两者会不一致**
（`Screen = 640×480` 而 `cam.aspect` 被 `BattleScene` 钉在 `DesignAspect`）：选 `Scale` 是**有意的**，
因为世界帧本来就由 `Cam.aspect` 定义 ⇒ 「世界档在两台机器上按同一宽高比算同一份布局」✓，
而且**批处理下 `Scale = 1`** ⇒ 现存世界档断言（`BattleScene.cs:11951` 那条 0.001 容差、
`E2` 那 6 颗钮的点击、`A218` 的 `box()`）**一条都不受影响**（实测 Δ ≤ 3.6e-5 世界单位）。
