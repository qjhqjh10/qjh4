## 三、整体形状（这是「原版长什么样」的骨架）

```
BattleManager.<PlayAi>d__399 协程（延时在这一层：GetFirstActionDelay/GetActionDelay/GetEndTurnDelay + Random.Range + WaitForSeconds）
  └─ 循环调 AI.PlayTurn(manager, mode)   ← 一次调用**只做一步**，AI 类里没有任何协程/await
       PlayTurn:
         ① playedFirstComboCard = false
         ② GetAvailableActions(manager, isPlayer:false, allowAutoActions:false)   ← 动作表，见下
         ③ 逐条 GetActionScore(manager, list, i, calculateUnitedScore:true, mode)
         ④ TweakAvailableActions(...)     ← **唯一随机源 + 唯一难度旋钮**（随机丢掉最低分的几条）
         ⑤ SelectBestAction(...)          ← 严格 `>`，平手保留先出现的
         ⑥ 最佳是 endTurn → 收手；否则 ExecuteAction（入 AutoAction 队列 + 播随机语音）
```

**`GetAvailableActions`（`BattleManager__GetAvailableActions.c`）= 动作表**：

1. 手牌：`CanPlayCard` 过的每张 → 一条 `playCard`（要选目标的按每个合法目标各来一条）
2. 场上单位：`GetAvailableAttackActions` → **近战一条、远程一条**（× 每个合法目标）
3. 有主动技能（`+0x220`）且 `CanUseActiveAbility` → `activeAbility`（要目标就每目标一条）
4. 灵族残骸 + `CanUseWaystone` → `clickWaystone`（cost 1）
5. **最后追加一条 `endTurn`**（acting/target 为 null、cost 0）= 「什么都不做」的基准

**`SelectBestAction`**：先拿 endTurn 当基准（没有 endTurn 就取 `list[0]`）；然后线性扫，
**严格大于才换**（平手保留先出现的，**选择过程无随机**）；唯一的例外 ——
若当前最佳是 `endTurn` 而候选是近战/远程攻击，则攻击胜出，**除非**出手卡是
`berzerk` 反面那四类（`stealth` / `vanguard` / `HasSpecialAttackScoring` / `cardType==Hero`）；
带 `berzerk(360)` 则**一定**胜出。

**`TweakAvailableActions`（难度就在这里）**：
按分降序排 → 从表尾（最低分）往前扫、跳过 `endTurn` → 前 `minSkips` 条**无条件删**，
之后每条掷一次 `roll = GetRandomInt(0,100)`，`roll < skipChance` 就删、否则换下一条重掷，
最多删 `maxSkips` 条。⇒ **「难度」= 有多大比例、多少条地把「AI 本来想做的事」按最低分往下砍掉。**
⚠️ 原版**只在打机器人局**才跳动作（`ShouldDisableTweakAvailableActionsByMode`：matchType ∈
{RankedBot 20, ClosedDeckBot 120, FastModeBot 210} 或「PracticeOffline 50 且非新手期」以外一律不跳）。
⚠️ **我们不分模式**（单机就是打 bot）⇒ 四档全按上表生效。
（那个函数是「被内联」还是死代码**没证死**，见 §八·3 —— 别把它当已证事实。）

## 四、打分族（`GetActionScore` 的分派）

| 动作 | 走哪个函数 | 主公式（`[机器码]` = 从 DLL 反汇编还原） |
|---|---|---|
| `playCard` | `ScoreFromPlayingCard` | `(非法术 ? GetValueInPlay : 0) + ScoreFromPlayingNow` |
| `playCard` 的 criteria 层 | `ScoreFromPlayingNow` → `ScoreFromCriteria` | 遍历卡资产上配的两张 criteria 表（`RawCardScript 0x2E8/0x2F0`），逐条累加 |
| `attackMelee` / `attackRanged` | `ScoreFromAttack` | `ScoreFromBuffedAttack(...)` ＋（特殊攻击打分 / 献祭 / blast / markerlight 的补项）；**打的是英雄且 `CombinedAttackCanKillWarlord` ⇒ +10000** |
| `activeAbility` | 技能自己的 criteria | 逐条 `ScoreFromCriteria` 求和 |
| `clickWaystone` | 固定 | **50.0** |
| `endTurn` / 其它 | —— | **0**（⇒「分 ≤0 的动作就不做，宁可结束回合」） |

**子打分器**：

| 函数 | 公式 |
|---|---|
| `GetCardValueInPlay` | `(overrideInPlay ? manualValueInPlay : manaCost) × 2 + 1 + ValueOfEnchantments`；**受伤**再 `× (0.5 × 当前血/上限 + 0.5)`；**stun/pindown** 再 `× 0.8` |
| `GetCardReferenceValueInPlay` | `manaCost × 2 + 1`（基准值，「1 张卡 ≈ 几个点」的尺子） |
| `ScoreFromDamagingBuffedUnit`（伤害的核心） | 门禁：`ambush`→0 · `longrange`→0 · `dropPod`（不忽略时）→0 · `dodge`/`shield`→只给 `攻击/3 + 1`。然后 **小兵**：打死 → `价值 × (survivor ? 0.8 : 1.0)`；没打死 → `价值 × 0.6 × 伤害 / (血上限 + bastion)`。**英雄**：打死 → **1e6**；没打死 → `伤害 × (剩余血 > 15 ? 1.2 : 1.8)` |
| `ScoreFromBuffedAttack` | `我方伤害分 − 敌方反击分`（反击要走同一个伤害分函数）`+ 0.1`（被反击后还活着）`+ rawCard.extraScoreFromAttacking + target.extraScoreFromTargetingOnAttack`；带 `poisonous` 且没打死 → `+ 0.7 × ScoreFromPoisoning(目标)` |
| `CombinedAttackCanKillWarlord` | **乐观上界和，不是搜索**：把所有「打这个目标」的攻击动作**按出手单位去重**（每单位只留伤害最高那条）后求和，`≥ 目标当前血 + CurrentBastion` ⇒ true |
| `SuicideHeroAttack` | 双方都是英雄 且 **我方当前血 ≤ 对方当前血** ⇒ true（**这版构建 0 调用点，见 §六**） |
| `ScoreFromStun` | 英雄 → `当前近战攻 × 1`；小兵 → `× 0.5`；`cantAttack`/`unstunnable` → `价值 × 0.2` |
| `ScoreFromPoisoning` | 已有毒 / `resistant` / 督军类 → 0；否则 `价值 × f`，`f` = 未晕且能打时 `血<3 ? 0.2 : 0.5`，晕了 `0.8` |
| `ScoreFromReturnToHand` | `目标当前费用 − (2×费+1 − 目标价值) × 1.5 − (rally?2:0) − (codex?2:0)` |
| `ScoreFromJam` | `ValueOfEnchantments + ValueOfTraits + (没 jam 时 rawCard.extraScoreFromJamming)` |
| `ScoreFromGivingCharge` | `不可行动 && summonSickness` ⇒ `当前近战攻`，否则 0 |
| `ScoreFromDrawingCard` | `手牌上限 − 手牌数 − 1`；**牌库空**则直接 `= −2 − 手牌上限` |
| `ScoreFromManaBuff` | 「被加费之后才付得起的手牌数」× 1.0 |
| `ScoreFromHandBuff` | 手里因 `costChange` 才打得起的牌里 `ScoreFromPlayingCard` 的**最大值**，收尾 `− 3.0 × N`（N 语义未完全解出） |
| `ValueOfTraits` | `Σ CardTrait._aIScore`（**值在数据资产上**） |
| `ValueOfEnchantments` | `addStats` → `(近战+远程+血) × 0.5`；附魔类 → `+1.0`（`SecretOrder` 派系 → `−2.0`） |
| `ScoreFromBuff(trait)` | **trait → 分值表**，见 §五·三 |
| `ScoreFromCriteria` | `baseValue(Friend/Enemy 按目标阵营选) + Σ_目标 [ value(option) × multFactor × multiplyByFriend/Enemy ]`；19 个 `ScoringOption` 见 §五·二 |
| `ShouldPlayComboCard` | `criteria.comboCard` 在手里 && 两张费用付得起 &&（本回合已打过第一张 ‖ `comboCardFirst && score ≥ 2.0`）**——这版 0 调用点** |
| `GetAiEnvEffectCard` | 从候选里**均匀随机**抽一张（不打分）—— 唯一有调用点的随机选牌 |

## 七、我们怎么落地（`SimpleAI` 重写）

- **搬结构**：动作表（`AvailableAction` 那一套）→ 逐个打分 → `TweakAvailableActions`（难度）→ `SelectBestAction`。
- **动作种类**：`playCard`（含战术卡目标变体）· `attackMelee` / `attackRanged`（**两条都列、各打分**，
  取代「远程攻击力更高就用远程」）· `activeAbility` · **誓约能力** · **替代行动**（`duty/pray/ferocity/agenda`）
  · `endTurn` 基准。`clickWaystone` 先留位（引擎那半还没实现 = 待办第 8 行）。
- 🔴 **criteria 那层原版数据在服务端**（`ScoringCriteria` 的**类形状**来自 `dump.cs`，但**值**是挂在卡/效果资产上的、本地没有）
  ⇒ 我们**从自己卡表 + 已解析的 `EffectOp` 推**（`deal N` → 伤害分、`give +N attack` → buff 分、
  `draw` → 抽牌分…），并在代码注释与文档里写明「**结构照原版、权重是我们配的**」。
- **随机**一律走 `System.Random(seed)`（工程铁律：一局必须可复现）。
- **难度**：照 `TweakAvailableActions` 的 `minSkips/maxSkips/skipChance` 三旋钮，玩家入口做进**对局内设置面板**
  （`Battle/SettingsPanel.cs`，用现成的 `40K_button` + `Label`）。
  🔴 **四档的取值就在这一行（唯一出处，`SimpleAI.KnobsOf` 与代码逐位一致）**：
  `SuperEasy (0,3,90)` · `Easy (0,2,60)` · `Normal (0,1,30)` · `Hard (0,0,0)` —— 语义 = `(minSkips, maxSkips, skipChance)`。
  ⚠️ **`minSkips` 一律 0**（原版那个值是「无条件先砍掉几条」）：给正数时 AI 只剩一两条动作会被**全砍光**，
  表现成「对手发呆什么都不做」。
  🔴 **那个入口是我们加的**：原版**没有**玩家可见的难度开关（那三个数在 `AIBotsConfig` 里，
  按排位/连败/牌组自动挑），所以「设置面板里能调」这一条**不是原版行为**，如实标着；
  **四档的具体取值也是我们配的**（原版那三个数的值本地没有）。
- **死代码不照抄**：`SuicideHeroAttack` / `ScoreFromKeepingTheCard` / `ShouldPlayComboCard` /
  `GetDefensiveAttackValue` / `IsBetterAction` / `AIModes`（见 §六）—— 一条都不实现，
  只在文档里记着「原版源码里有、这版没跑」。

#### 10·7·b 🔴 **口径裁决（2026-09-25）—— 结论是「先别改」，理由如下**

**先更正一句话**：§10·7 里那个「真差异」写得**不够准** —— 我们的退化支「取池序前 N 个」
**恰好就是原版枚举里的 `firstAdded(7)`**（`case 7`：从表头往后取 `maxTargets` 个）。
⇒ 它不是「原版没有的规则」，而是「**八档里选了一档，但很可能不是原版给这些卡配的那一档**」。

**「补另外几档」这件事查过了：没有可补的。**
- **卡面文字根本不驱动那几档**：全池 1126 张的 `desc` 里，挑法短语只有
  **`highest` ×5 · `lowest` ×3**（`weakest` / `strongest` **0 命中**，2026-09-25 实扫）
  —— 有明确写法的，`PickMost("+/-stat")` **已经全覆盖**。
- 其余六档（`valueInPlay` 两档 / `firstAdded` / `lastAdded` / `cardTarget` / `random`）
  **全靠服务端给每张卡配的 `targetSelectMethod`**，本地一条证据都没有（§10·8 第 1 条）。

**为什么不干脆把默认改成 `random`（原版 switch 的 `default`）**：
`targetSelectMethod` 那道闸的前置是 **`maxTargets >= 1` 且 `候选数 > maxTargets`**（§10·1 的 `:1164/:1169`），
而 **`maxTargets` 同样在服务端**。若某张卡 `maxTargets < 1`，原版**根本不做裁剪**（`LAB_1808199c1`）——
那就是「**命中全体**」，和 random **完全是两回事**。
⇒ 在 `maxTargets` 未知的前提下，改 random 只是**换一个猜法**，而且会把现在确定性的行为改成随机的。

**裁决**：**保持现状（= `firstAdded`）**，把它如实记成「**我们挑的档位，不是证出来的**」，
并在 `EffectResolver.cs` 那一支写过注记（✅ 2026-09-25 已写）。
⚠️ **`SimpleAI` 那一处不用注** —— AI 侧**根本没有「挑一个」这件事**（§10·5：每个合法目标各发一条动作、靠打分选），
所以这个档位只影响**玩家打出的、不手选目标的效果**。**将来要动它的那一天，先拿到逐卡配置（线上数据 / 社区数据），别凭现在的三条证据硬改。**

  （`SimpleAI.cs:580`）⇒ 永远落**最小槽号**（0→1→2→3→5→6→7→8）= 先把左边 4 格**从外往里**填满、再填右边
  ⇒ **与原版正好相反**。

#### ② 战术卡目标：**系统性挑错，且没有兜底**
- `CanPlayTactic` 强制要一个具体 `targetSlot`，而 `ScoreOp(ctx, op, slot)` 的 `slot` **函数体一次都没读**
  ⇒ 同一张卡的所有格位**同分**、平手留先（`NextPlay` `:1007-1011` / `SelectBestAction` `:843-857` 都是严格 `>`）
  ⇒ **永远打「槽号最小的合法目标」**。
- 后果：**裸 `Deal N damage` 不会打最低血的那个** —— §10·7 那张表里「✅ `PickMost = "-health"`」那一行
  **只在玩家那条路上成立；AI 出牌这条路上没生效**（`ResolveTargets` 的「调用方已选定」支把 `PickMost("-health")`
  盖掉，`EffectResolver.cs:759-762`）。
- 🔴 **失败不重试**：`ExecuteAction` 失败 → `return false` → `PlayTurn` 里 `break`（`SimpleAI.cs:959` 附近），
  **不换目标重试、也不退次高分**；表现层只打一条 `Debug.LogWarning("[Battle] AI 的动作被引擎拒绝：…")`。
- ⏭ **改法**：打分要把 `slot` 算进去（至少让 `deal / damage` 那族偏好「**能被这一下打死 / 血最少**」），
  **并且**失败要能退次优。改完配断言（先手/后手、能杀/不能杀各一条）。
