## 〇、结论（先看这 10 行）

1. **商店页签完全由服务端数据长出来**：`ShopWindow.SetupTabs`（`ShopWindow.cs:596`）遍历 `Shops.GetAllStores(EventLocationType.Main, null)`；
   现在 `HandlerData.Shops.RawEvents = []` ⇒ **一个页签都没有**，屏幕上连「空商店」都不会出现（`GameWindowWithTabs.Open` 在 `tabs.Count==0` 时直接 return，`GameWindowWithTabs.cs:161-186`）。
2. **一个页签 = 一条 `IStore` 事件**。可用的数据类：`Everguild.LiveOps.FixedStoreData`（固定商店）· `Everguild.LiveOps.DailyStoreData`（每日商店）· `Everguild.LiveOps.GachaEventData`（抽奖/宝箱）。
   页签**内容 prefab** 取该事件 `drawData.EventComponents[key=11]`（`EventComponentReferenceType.Tab`）。
3. **页签里的每张商品 = 一条 `IShopOffer` 事件**（`ShopOfferData` / `ShopOfferDataV2`），商品卡 prefab 取该 offer 的 `EventComponents[key=0]`（`Container`）。
4. **offer 必须被某个 store 的 `items[]` 引用**（`item` = offer 的 `eventId` 字符串）。没被任何 store 引用的 offer 会被 `Shops.SetupEvents` **从事件表里删掉并打警告**
   （`[Shops] Offer X is not assigned to any store, removing it from the list.`，`Shops.cs:498-650`）。
5. **`Persistence` 不能为 null**：`RawEvents[*].Persistence = null` ⇒ 新建 TSave（`IsActive=false`）⇒ 事件进 `blockedEvents`，页签照样一片空白。
   这是第一百三十七会话在模式卡上踩过的同一个坑（交接 §二-4）；商店的存档类型 = `ShopStorePersistence` / `ShopItemPersistence`。
6. **价格**：`price.Currency = 30(realMoney)` 走 Steam 内购（离线不可用）；`40(free)` 会显示「Free」且 `HasEnoughCurrency()` 直接放行；其它币种**必须**在 `CurrencyConfig` 里有一条对应 `type` 的 `Currency`，
   否则 `ToCurrency()` 返回 null ⇒ `BuyWithGameCurrency` 里那条 `if (ToCurrency(...) != null)` 不成立 ⇒ **抛异常、什么都不发**（`PurchasesManager.cs:1962-2090`，Ghidra `PurchasesManager__BuyWithGameCurrency.c`）。
7. **购买链三步**：`PlayFab PurchaseItem` → `ExecuteCloudScript RegisterPurchase` → `ExecuteCloudScript UnlockCrateContainer`。
   现有 `responses/` 里**这三个模板一个都没有** ⇒ 现在点购买会落到兜底 `ExecuteCloudScript.json`（`Error` 非 null）⇒ `onError`。
8. **最少改动就能跑起来**：填 `Shops.RawEvents`（3 条 store + 1 条 offer，offer 可复用到三条 store）+ `TitleData.CurrencyConfig`（1 条 free 货币）+ 补 3 个模板（`PurchaseItem` / `ExecuteCloudScript.RegisterPurchase` / `ExecuteCloudScript.UnlockCrateContainer`）。
9. **资产 GUID 全部是真实 Addressables 键**，且 `menus_assets_all.bundle`、`boosterpacks_assets_all.bundle` 都在本地 `StreamingAssets/aa/StandaloneWindows64/`（87 个 bundle）里，能直接加载。
10. **没有做的事**：本报告没有跑游戏验证任何一条 JSON；`$type` 解析、`AssetLocator` 跨 provider 查找、`CurrencyConfig` 的内联 SO 反序列化这三处是**推理**，见 §八。

## 九、顺手发现（与本任务相邻，建议记账）

1. 🔴 **`ShopWindow.Open` 的取数在 `base.Open()` 之前**，而 `base.Open()` 里才调 `SetupTabs()` ⇒ 只要 `stores` 为空就**完全不报错地空白**。
   这解释了为什么「商店从来没打开过」在日志里可能一条异常都没有。
2. 🔴 **`Shops.SetupEvents` 会把没被 store 引用的 offer 直接删掉并打 `LogWarning`**（`Shops.cs:498-650`）。
   以后若发现「offer 造了但商店里没有」，第一件事是搜这条警告，而不是怀疑 `EventComponents[0]`。
3. ⚠️ **`GetAllStores(Main, null)` 只匹配 `location.type == 0`**。本地唯一一条真实 `FixedStoreData`（`Premium Campaign Store`）的 `location.type = 1 (None)`
   ⇒ **它不是主商店的店，是挂在战役父事件下的**。抄它当模板时要**删掉 `location` 或改成 `type: 0`**。
4. ⚠️ **`ShopElement.item` 在本地资产里是 `{genericObjectReference, targetId, reference}` 三段**，但**线上只能给字符串**（`WriteJson → JValue(targetId)`）。
   直接拷本地 Unity JSON 会被 `OnBeforeRead` 忽略（它不是 `JTokenType.String`），表现是「item 解析不出来」。
5. 📌 **`GetStoreItems` 仍然没有调用点**（本轮再次确认：`PlayfabWrapper.GetStoreItems` 只有定义；`responses/GetStoreItems.json` 从未命中）。
   B154 的结论保持：商店**不走**它。别为它写数据。
6. 📌 **`ShopWindow` 的 tab 按钮模板在窗口 prefab 内**（`TabbedWindowComponents.tabPrefab` → 场景内 `Shop Tab`，pathID `4778154276333570172`，非 Addressable），
   跟「页签内容 prefab」（事件里的 `[11]`）是**两样东西**，别混。
