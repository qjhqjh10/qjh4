## 六、顺手发现

1. **`temporaryWindowDictionary` 只有 19 个窗口，但全项目 `GameWindow` 体系类约 60 个** —— 说明「WindowsManager 能按类型开」的只是少数；其余靠代码里的 `ComponentReference`/`AssetReference`/LiveOps 事件组件。**做离线版不要只看那张字典**。
2. **四条模式卡的背景图是同一个 sprite**：`GameModes.RawEvents[*].drawData.EventAssets` 的 `key=10`（`MainMenuContainerBackground`）全部指向 `ad9725ac046204b7fbdee84edc37f65c`（「Space Wolves Container 1x2」），而且四条都没有 `GameModeIcon`(12) ⇒ 与用户报的「四张卡同一张图」完全对上。判据落在 `E:/warpforge/05_工具/server/responses/ExecuteCloudScript.InitializeLiveOps.json`。
3. **`GameModes.RawEvents` 已经从 3 条变 4 条**（新增 `PracticeEventData`，`eventId=PracticeEvent`，`MainWindow` = `Practice Mode Menu` `c2552d81…`）——`任务_离线原版.md` §一 里写的「3 条」是旧读数。
4. **`PlayerDecks` 只有 1 副种子卡组**（`offline-deck-saimhann`，15 张卡），`PlayerDecksFast` 是空数组；`UserData` 整个是 `{}`。⇒ 好友/成就/每日计数/战力/等级这些走 `UserData` 的界面现在全是空。
5. **库存 = 1,353 张卡 + 2 件默认外观**（默认头像 `d151b095…` + 默认头像框 `36ae26bb…`）⇒ 头像页只有 1 个、称号 0 个、卡背 0 个、异画 0 个。这与用户「卡池/锻造厂/卡牌/头像全解锁」的口径不一致，属于待办。
6. **`Resources Container` 在场景里是空的**（`MainMenu Warpforge.unity` 里 `Resources Bar/Resources Container` 无子节点）——货币条目是运行时 `ResourcesBarController.GetCounter` 造的，所以「顶栏没有数字」不是场景丢对象，纯粹是 `CurrencyConfig` 空。
7. **`Collection Menu Variant` 预制体里是「4 个页签 + 1 个 Shared」**：`Select Deck Tab`（内含 `Decks Tab` + `Select Game Mode Deck Tab`）、`CardsTab`、`Cardback Tab`、`Alternate Art Tab`、`Shared`；按钮是 4 个（Deck/Cards/CardBacks/Alternate Art）。「Select Game Mode Deck Tab」是**从排位/赛事打开收藏时**用的另一套卡组列表（`RankedDeckSelector.collectionWindow`）。
8. **`Social Submenu Variant` 只有 2 个页签**（Alliances/Friends），`Rewards Base Submenu Variant` 有 3 个（Missions/Forge/Campaign），`Main Menu Settings Window` 有 5 个（General/Media/Account/Graphics/Support），`Player Profile Window` 有 6 个（Profile/Avatar/Title/Battle Log/Trophies/Ranked）——这些数字是从 prefab 的 `m_Children` 直接数出来的，比任何文档都可靠。
9. **商店页签是「服务端长的」**：`ShopWindow.SetupTabs` 遍历 `stores`，每个 `IStore` 用 `EventComponentReferenceType.Tab` 取一个 `WindowTabBase` prefab。⇒ 没有 `Shops.RawEvents` 就没有页签，界面上连「空商店」都不会有。
10. **`ChatPreview` 是主菜单右上角的一个常驻组件**（`Intro.unity` 的 `#3 ChatPreview`，`initstat.tsv` 显示 `status=2 active=1`），它开 `ChatPanel`。离线无 Photon 时它的行为没验过。
11. **`Challenge button` 场景里 `active=1`、运行期 `active=0`**（`initstat.tsv` `#4 ChallengeButton (Challenge button) status=2 active=0`）——说明它由某个 feature/tag 在运行时关掉，不是场景里就关的。
12. **`BattleSettingsWindow` 的 prefab 名是「BattleSettingsPanel」**（不是「Battle Settings Window」），且它是**场景内组件**（在 `battlearena1` 场景包里），没有 Addressables GUID；同理 `CardDisplayWindow` 的 prefab 名是「Card Display Window」（战斗场景）和「Card Displayer Menu For Menu」（主菜单场景）。查资产时按类名搜不到时，按「类名 → 场景包 GameObject 名」找。
13. **`Profile content` / `Player Profile Container Base` 这类「他人资料」组件在菜单包里是独立 prefab**，但 `PlayerProfileMenu` 打开他人资料依赖 `GetRandomPlayerLeaderboardAroundPlayfabID` ⇒ **离线没有排行榜时，「点好友/排行榜行看资料」必然失败**（不只是空）。
14. **`WindowsManager.OpenWindow` 有 7 个重载**（`WindowsManager.cs:1246/1259/1280/1286/1355/1366/1514`），主菜单导航走的是 `OpenWindow(ComponentReference<GameWindow>, data, closeAll, options)`（`OpenWindowButton.cs:191`）；探针已挂到这条（`windows.tsv` 的 `open OpenWindow/4`），所以后续查「点开没开」以 `windows.tsv` 为准。
15. **`ConfigManager` 的 20 个 provider 在 `Intro.unity` 里是一个个 MonoBehaviour 子节点**（`PlayerDataManager Should be disabled by Default/Config Manager/...`），名字与 `TitleData` 的 20 个 key 一一对应；离线上「缺哪个 key」可以直接对照这棵树。
16. **`EventAssets` 的 `key` 是 `EventAssetReferenceType` 枚举，不是任意数字**：`Icon=0`、`MainMenuContainerBackground=10`、`MainMenuContainerForeground=11`、`GameModeIcon=12`。四条模式卡给的 `key=10` 是**卡背景**（所以四张卡长得一样），`GameModeIcon(12)` **一条都没有** ⇒ 要让四张卡有各自图标，得给每条事件加 `key=12` 的 sprite。
