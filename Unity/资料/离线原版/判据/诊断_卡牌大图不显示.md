## 〇、一句话结论

**这不是游戏 bug，是探针把被探的方法打死了。**
`CardWindowProbe` 给 `CardDisplayWindow.ShowCard` 打了 Harmony prefix，而这个方法的签名里有一个 **`Nullable<CardTier> tier`（按值传的结构体）**；

## 二、逐条回答派单里的 6 个问题

### Q1 `WindowsManager.OpenWindow(GameWindow, …)` 做了什么？会不会把窗口置 active？

**它自己【不】置 active**，只做三件事：**改兄弟序（有条件）→ 记账 → 调 `TryOpen`**。

`WindowsManager.cs:1259-1278`（`OpenWindow(GameWindow window, object data, bool closeAll, GameWindowOptions options)`）：

```
1263  Transform transform = window.transform;
1264  Transform parent = transform.parent;
1265  WindowHolder component = parent.GetComponent<WindowHolder>();
1266  if ((bool)component) { transform2.SetAsLastSibling(); }   // ← 只有父节点上挂了 WindowHolder 才提层
1272  OpenWindowCO(window, data, closeAll, options2);
```

`OpenWindowCO`（`WindowsManager.cs:1551-1614`）：
- `if (closeAll) CloseAllWindows();`
- `if (window.type == WindowType.Fullscreen) { if (openWindows.Count>0) HideAllWindows(); }`
  `else if (window.type == Popup && currentWindow) currentWindow.ToBackground();`
- `CurrentWindow = window;` 并把 window 追加进 `openWindows` 列表（**没有「必须先在某个字典里注册」的前置条件**；
  `automaticallyLoadedWindows` 那个字典只服务 **AssetReference 加载**的那条路，场景内组件不走它）。
- `window.TryOpen(data, options2);`

**真正 SetActive 的地方在 `GameWindow.TryOpen`，而且只在 `CurrentState == Closed` 那一支**：

`GameWindow.cs:153-199`（`TryOpen(object, GameWindowOptions)`）／`GameWindow.cs:201-239`（无参版，行为一致）：

```
166  if (CurrentState != WindowState.Closed) { flag = true; }      // ← 非 Closed：整段跳过
172-180  else { PlaySound; gameObject.SetActive(true); CurrentState = Open; Open(); OnOpen(); … }
188  bool flag3 = (CurrentState == WindowState.Open);
190  if (!flag3) flag4 = flag;            // 只有「跳过了 SetActive 且最终不是 Open」才走
194  if (flag4) { CurrentState = Open; ToFocus(); }
```

**⇒ 两个真实的静默失败点（跟这次的探针无关，但同一个症状）：**
1. **`CurrentState == Open` 但 GameObject 是 inactive** ⇒ `TryOpen` **什么都不做**（既不 SetActive、也不调 `Open()`、也不 `ToFocus()`）⇒ 窗口永远不出现。
   反编译同构：`decomp_full/GameWindow__TryOpen.c:16-28`（`param_1[0xd]` 是 state；`:21` 的 `(int)lVar2 != 1` 才走「置 Open + 虚调用」）。
2. **`CurrentState == Background`** ⇒ 跳过 `SetActive` 只置 Open + `ToFocus()`；若 GameObject 此时是 inactive，同样看不见。
3. `WindowsManager.cs:1263-1264` 的 `parent.GetComponent`：**父节点为 null 会 NPE**（`parent` 直接解引用）。本例父节点存在，不是这条。

## 四、顺手发现（不在派单范围，但会咬人）

1. **「没有 `SHOW-CARD` 日志」不能推「`ShowCard` 被内联」**。本次它就是没跑 —— 因为跳板先炸了。
   以后判「某个方法有没有被调用」，要么在**调用方**挂 prefix，要么去 `Latest.log` 搜 `[Il2CppInterop] During invoking native->managed trampoline`。
2. **`GameWindow.TryOpen` 的 `CurrentState == Open` 分支是空转**（`GameWindow.cs:188-198`）：state 说「开着」但 GameObject 是 inactive 时，
   再怎么 `OpenWindow` 都不会把它显示出来。任何「先 `SetActive(false)` 但忘了把 state 置回 `Closed`」的补丁都会踩这个坑。
3. **`CardDisplayWindow.Open()` 有「二实例自杀」逻辑**（`CardDisplayWindow.cs:330-334`）：以后若为了「窗口常驻」而额外 `Instantiate` 一份，
   会在 `Open()` 里被 `Destroy`，表现同样是「打开没反应」。
4. **`WindowsManager.OpenWindow(GameWindow, …)` 的 `options` 实参在反编译里被丢掉**（`WindowsManager.cs:1271-1272` 传 `default`，
   `OpenWindowCO:1603-1604` 也是 `default`）—— 大概率是 Cpp2IL 丢实参（同族的「ILSpy 把实参常量反编译成 default」），
   **本次不影响 CardDisplayWindow**（`options` 为 null），但以后查「窗口参数没生效」要记得这一格可能是反编译假象。
5. `cardwindow.tsv` 里 `[0]=(null)` 是 `BasicCardUI.rawCardData__BackingField` 为 null（探针 `DeckState()` 取的就是这个字段），
   **不代表 cardUI 本身是 null**（同一行 `/act=True` 已经说明 GameObject 是活的）—— 报表里别把它读成「卡槽是空的」。
