### 3·3 「全解锁」补库存（最小方案）

改法（在 `main()` 里加一个 `--cosmetics` 开关）：

```python
# 新增常量
COS = r"E:/warpforge/02_解包资源/assets_full/bundle_cosmeticsso_assets_all/MonoBehaviour"

# --cosmetics 时：
import glob
seen = {u for u, _ in cosmetics}
n = len(inv)
for p in sorted(glob.glob(os.path.join(COS, "*.json"))):
    d = json.load(io.open(p, encoding="utf-8"))
    if "inInventory" not in d or "uniqueId" not in d:
        continue                      # 81 个非 CosmeticItem，跳过
    uid = d["uniqueId"]
    if uid in seen:
        continue                      # 去重（默认头像/边框已有）
    seen.add(uid)
    inv.append({
        "ItemId": uid,
        "ItemInstanceId": "offline-cosmetic-%04d" % n,
        "DisplayName": d.get("m_Name") or uid,
        "RemainingUses": 1,
        "CatalogVersion": "",
    })
    n += 1
```

## 七、顺手发现（不在本轮范围，但下个会话该知道）

1. `SRV/tools/add_all_configs.py` 的 `MINIMAL` 里 `LeaderboardConfig` 是 `{}` —— 与本报告 §四第 4 步冲突，**改配置时要一起改脚本**，否则下次跑脚本回退。
2. `add_inventory.py` 的注释说「不给默认头像会让 `PlayerAvatarDataManager.DefaultAvatarItem` 抛」—— **这个因果说法不准**：`DefaultAvatarItem` 查的是**本地 cosmetics 定义集合**（`ILSPY/PlayerAvatarDataManager.cs:481-508`），不是玩家库存。往库存里塞默认 id 并不能阻止那个 `First` 抛。真正的时序兜底是 `ProfileFixProbe`。
3. `probe.log` 的 `[WFP][CFG] ... config=null` 是**探针反射失败**（`Il2CppReferenceArray` → `System.Array` 的 `InvalidCastException`），**不能**据此判「20 份配置全是 null」。要判配置是否真的解出来，得换一种读法（或直接看消费方行为）。
4. `SettingsMenu` 的 `AccountTab` **不调用** `GetAccountInfo`：它读登录响应里的 `AccountInfo.PrivateInfo.Email` 与 `PlayerProfile.DisplayName`。所以现有 `GetAccountInfo.json` 缺 `PrivateInfo` 不影响 Account 页。
5. 假服务端的 `state/player_state.json` 是**全局单档**、没有账号维度（`SRV/server.py:372-421`）⇒ 离线版「切换账号」本质上无法隔离不同档案，这是设计限制，不是缺陷。
