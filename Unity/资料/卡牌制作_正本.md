## §一 卡 id 怎么写

> **这一节回答**：`uniqueId` 长什么样、怎么保证唯一、新增一张卡时号从哪来。

### 1·1 字段本体

| 事实 | 出处 |
|---|---|
| `uniqueId` 是 **`PlayerItem` 的 public string 字段**，`RawCardScript : PlayerItem` 继承它；**字段偏移 `0x38`**（同块：`expansionPack 0x30` · `autoAssign 0x34`） | `d:/2/Warpforge_code/Scripts/Assembly-CSharp/PlayerItem.cs:14` · `dump.cs:18809-18813` · `RawCardScript.cs:7` |
| 卡 SO 的识别键是 **`m_Script.m_PathID == 8864902669260471755`**（旧包同类名的 `MonoScript.m_ClassName = RawCardScript`） | `资料/普查产出_1017/卡牌ID/R_SO与触发代码链_可行性.md:31` ＋ `资料/普查产出_1018/allcards_1350/报告.md:37` |
| 当前 build 的 allcards 包：`allcards_assets_all_ea8bca4f5c6909d3124fd4975dc96173.bundle`，内层 CAB `CAB-fb8f01449289635703d83d52c3f18245`，**1,351 张 `RawCardScript`** | `资料/普查产出_1018/allcards_1350/报告.md:9-11,20` |
| **`uniqueId` 1,351/1,351 非空、0 重复** | 同上 `:38`；本正本现算复核一致 |

⚠️ **`m_Name` 不是 id**：SO 资产名形如 `33 EmperorsChildren-Heldrake`（带序号），唯一键是 `uniqueId` 字段。
出处：`R_SO与触发代码链_可行性.md:70`；本线「已知的坑」第 4 条。

### 1·2 两种形态（当前 build 实测）

| 形态 | 判据 | 数量 | 例 |
|---|---|---|---|
| **阵营前缀 + 数字** | `^[A-Z]{2,4}\d+$` | **1,040**（本正本现算） | `EC29` · `SOR36` · `GOF105` |
| **32 位十六进制** | `^[0-9a-f]{32}$` | **311**（本正本现算） | `8a028d3771c60014aa35c7269d38159e` |

### 1·3 新增一张卡时 id 怎么取

**🔴 这一条是「我们定的做法」，不是原版写下来的规定** —— 原版只暴露了「前缀 + 数字」这个惯例，
没有一份「取号规则」的文档。做法如下（依据是 1·2 的实测惯例）：

1. **先选阵营** ⇒ 前缀由 1·2 那张表唯一决定（不许自创前缀）。
2. **在本阵营号段里取「下一个未被占用的号」** —— 用 `card_ids.json.mapping`（1,351 条）+ `cards_raw.json` 交叉查，
   ⛔ **不要**只看我们池子（池只有 1,127 张，包里有 1,351 张）。
3. **id 全局唯一**：写进任何表之前先查 `mapping`/卡池；`CardDatabase.Load()` 侧对撞车**不判**（`RuleEngine/Data/CardDatabase.cs:425` 注释：
   「id 撞车在生成器那一侧就炸了」）⇒ **撞车是上游生成器的责任**。
4. **不要用 32 位 hex 给新卡的「常规 id」**：hex 是原版历史/特例形态（311/1,351），
   新卡用前缀号更好读、也能被阵营规则识别。
5. **id 一旦发布不要改**：它同时是本地化键（`Card_Name/<id>`）、立绘文件名（`art_<id>.png`）、
   语音表键、VFX 表主键 —— 改 id = 这四张表一起改（2026-10-18 的 `K06` 迁移就是一次实例：
   29 个文件 247 处 + 62 条语音 + 228 个立绘文件）。

### 1·4 `card_ids.json` 怎么用（我们侧的真值映射）

| 键 | 现读 | 说明 | 出处 |
|---|---:|---|---|
| `mapping` | **1,351** 条 | `uniqueId → 显示卡名`（当前 build 全表） | `数据/游戏数据/card_ids.json` |
| `poolTrueIds` | **1,127** 条 | **历史迁移表**（旧池 id → 真 id） | 同上 |
| `poolIdsAreTrue` | `true` | **为 true 时按 id 直接查，⛔ 不要反转 `poolTrueIds`**（反转会把真 id 映射回旧 id，认成别的卡） | 同上 |

> ⚠️ `poolTrueIds` 现在的定位写在它自己的 `poolIdsAreTrue_note` 里；
> `K06` 已把池内 114 张旧 id 全改成真 id（报告 `资料/普查产出_1018/K06_池id迁移_报告.md`）。

### 1·5 `cardShortId` 是什么

`RawCardScript.cardShortId`（`RawCardScript.cs:9`）是**数字短号**：当前 build **861 个不同值**、**436 张为 0**（本正本现算）。
它的**运行时用途本正本没查到**（反编译里没有按它分发的证据）——
⇒ **写新卡时照抄同族卡的取值或填 0**，⛔ 不要赋予它语义。

> **这一节回答**：一张卡在数据层由哪些字段组成、每个字段写什么、我们引擎读不读。

### 2·2 字段总表

**读法**：「我们引擎读不读」只针对**当前** `cards_engine.json` 那条链（`card_stats.json → gen_cards_engine.py → CardDatabase`）。
**不读 ≠ 不重要** —— 做原版复刻/新卡设计时它们仍是 SO 的一部分。
**取值从哪来**：① 原版**同族样本卡**（`cards_raw.json` 里找同阵营/同 `cardType` 的卡照抄）；
② 各枚举桩（2·3）；③ **卡面内容**（效果文字/数值/兵种）以 PnP 成品卡图或官方本地化文本为准。
⛔ **不要**从截图/卡名猜字段值。

### 2·5 写 SO 的五个易错点

1. **枚举的主槽位按 10 递增留白，但同族细分子项会占邻位** ——
   例：`summonUnit` 系 `70/71/72/75/77`、`triggerMob` 系 `460/461`、`triggerAmbush/Uprising/Slay/Teleport` = `465/466/467/468`、
   `recallToDeck` = `300/301`。⇒ **照抄枚举桩里的数值，⛔ 别自己按 10 算**；把枚举当位掩码更是错的。
2. **`TargetCriteria` 的 include 位要照同族样本补** —— ⚠️ 本正本**没有逐条读** `FilterMethods.CheckIfMeetsCriteria`；
   但实读样本（`SOR36` 的 `allFiltered`）把 `enemyUnits=1/includeHero=1/includeMinions=1/includeRemnants=1` **全置 1**
   （`R_SO与触发代码链_可行性.md:86`）⇒ **写卡时把 include 位补齐**是安全做法；只写 `targetsAffected` 很可能筛不出目标。
3. **`randomAbilityChoice` 默认 false = 全部按顺序触发**，不是「随机一条」。
4. **规则层是内联结构体、表现层才是指针**：`cardAbilities` 直接写在 SO 里；
   `cardAnimations` 存的是 **GUID**（`AssetReferenceTyped`）。
5. **卡间引用用 PPtr**：`unitsToSummon[]`、`relatedCard*`、`startingCardInHand` 都是同包直接引用；
   旧快照 `unitsToSummon` 的 PPtr **395/397 可解析（99.5%）**（`R_SO与触发代码链_可行性.md:104-106`）。

### 4·6 给一张新卡接特效，最小步骤

1. 在原版数据里找到四个逐卡字段/`cardAnimations` 的 **GUID**（若这张卡来自原版）。
2. 用 `guid_map_bundles.tsv` 把 GUID 解成**资产名**（解不出 = 本地没有这件资产，如实记「缺」）。
3. 用 `anim_address_map.json` 的 `cardanim_to_asset` 把 CardAnim 名翻成**本地 prefab 名**。
4. 跑 `工具/gen_card_vfx_by_card.py` 重出运行时表（⛔ 别手改 `Resources/card_vfx_by_card.json`）。
5. 在 `VfxMap` 的 `ByCard` 里能查到 `(id, event)` 即接上；查不到会退回 `ByFaction`/`ByEvent`（`VfxMap.Resolve`）。
6. 若事件根本不被引擎发出（如 `ability`/部分 `attack_ranged`），那是**引擎侧缺事件**，不是特效表缺行
   （T14 §四·4 的 18 张就是这一类）。

## §八 一句话总结

**新卡 = 一个 id + 一块 SO 数据（`cardAbilities` 是内联的效果表）+ 一组本地化键 + 立绘/语音 GUID + 一张 GIF 式的动画引用表**；
**引擎侧只有「触发判定」和「一个 enum → 一个动作」两层**，我们侧对应 `WhenEvent`（22 种时机）与
`EffectDispatch`（44 个动词）。**照这张表填数据，不写代码就能做出一张原版语义的卡**；
只有当你要的行为不在 83 个 effect / 97 个 trigger / 44 个动词里时，才需要动代码。
