## 三、节点链：`HandArea` / `HandAnchor` **是纯 Transform，不是 RectTransform**

| 节点 | 组件 | 局部量 |
|---|---|---|
| `HandAnchor` GO 58 | **纯 `Transform_1257`** | localPos **(0, 0.46, 0)** · scale (1,1,1) |
| `HandArea` GO 318 | **纯 `Transform_1295`** | localPos (0,0,0) · **localScale (108,108,108)** |

### `EnemyBaselineY = 0.9102` 怎么来的（**这一段是推导，不是原版字段**）

原版敌方 `HandAnchor` 落在**屏幕顶边**（距顶 0.32 px，ny ≈ 0.9997）；
而敌方卡区只有**顶部 ~97 px 厚**（`EnemyCardAreaSizeHelperData` 的 `sizeDelta (100, 96.7)` 挂顶边；
我方对应件是 249.9 ≈ 整张卡高）⇒ 判为「**卡顶贴屏幕上沿**」：
卡高 194.3 px（宽 122.05 × 高宽比 1.5918），半高 97.15 px = 0.08995 ⇒ 中心 = 1 − 0.08995 = **0.9102**。

**实据**：`BattleScene.Run` 的截图（`_tmp_view/battle/26_换牌之后.png`）—— 那排卡背**完整可见**、
顶边正好贴着屏幕上沿，弧向下的形态也出来了。**对不上的话就调这一个数**。

### 顺带改的两处（都不是「敌方手牌」本身的事，但被它逼出来的）

1. 🔴 **`TurnLabel` 下移**（`0.965` → `0.810`）：它原来在距顶 38 px、水平正中 —— **正好在敌方手牌那一排里**，
   截图里三张卡背把它压掉一半。⚠️ `TurnLabel` **是我们自加的**（原版没有）⇒ **该让位的是它**。
2. 🔴 **`Object.FindObjectOfType<HandLayout>()` 的坑**：`BattleScene` 里有 **4 处**这么找手牌；
   场景里一变成两份 `HandLayout`，那个 API 返回哪一份就是**任意的** ⇒ **六条我方手牌断言一起红**
   （马脚：「4 张时用原版间距 1.45 不压缩（实测 **0.600**）」—— 0.6 是敌方的值）。已收敛成
   `BattleScene.PlayerHand()`。**教训：有引用就用引用**（同形状：`QuestIconPos` 的 `transform.Find`、
   震镜头那次 HUD 挂载点）。
