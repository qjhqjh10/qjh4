## 三、改动（只此一个文件、两处）

### 改动① `Editor/CollectionScene.cs:5919-5934` —— 摆位改成「以**卡自己的父节点**为参照」，并加一条结构前提

```csharp
var cellT774 = card774.parent != null ? card774.parent : vpNode774;
CheckTrue(card774.parent != null && cellT774.name.StartsWith("Content "),
          $"（A774 前提）第 1 张卡挂在**格容器** `Content <i>` 里（实测「{cellT774.name}」）"
        + " —— A14 起卡不再直挂 `Viewport`；父节点取错 ⇒ 卡会被摆到视口外、量到 0 个顶点（假红）");
var pos774 = MainMenuSubmenuWindow.Local(cellT774, r774.x1, r774.y1, r774.x2, r774.y2);
cv774.SetPose(pos774, 0f, sc774);
```

* **只换了 `Local(...)` 的第一个实参**（`vpNode774` → 卡的真实父节点）。`r774` / `sc774` / 三态流程 /
  期望值（`vp774.y1`）/ 改坏法注释**一个都没动**。
* **为什么这样就够**：`MenuDraw.Local(parent, r) = RectCenter(r) − PosInDesignSpace(parent)`
  ⇒ 无论容器自己摆在哪（**包括它是在上一趟、按旧滚动偏移建出来的**），
  卡的世界落点都回到 `RectCenter(r774)` ⇒ 与生产 `CollectionWindow.cs:1477-1478`
  （`Local(cellT, cardR…)`）**同一式**。
* **为什么加那条前提**：以后若有人把卡从容器里搬回 `Viewport`（或 A14 被回退），这一段会**先红在结构上**，
  而不是像这次一样红成「0 个顶点」让人误以为裁切坏了。
  ⚠️ 它也顺手挡住 `Local(null, …)` 的 NRE（取不到父节点时退回 `vpNode774`、由那条前提红出来）。

### 改动② `Editor/CollectionScene.cs:5957-5967` —— 态③ 不再「量不到就静默跳过」

## 四、为什么修完仍然能分出「跟节点」与「跟旧矩形」

断言链**一个字没改**，改的只是「卡摆在哪」：

| 态 | 摆法 | 期望 | 若边界退化成「宿主常量矩形」会怎样 |
| --- | --- | --- | --- |
| ① | `padding = 0`，节点框 = `330.2,155.9→1919.9,1079.9` | 最高顶点 `b1 ∈ [155.4, 158.4]` | 与 ① 相同（常量矩形 = 节点框、padding 0）⇒ ① 本来就分不出，**这是设计如此** |
| ② | **只改节点** `padding.Top = 60`（`vc774.padding`），再 `SetPose` 一次 | `b2 ≥ 215.4`（= `vp.y1 + 60`） | 停在 **155.9** ⇒ 红 |
| ②b | —— | `abs(b2 − b1) > 50` | 差 **0** ⇒ 红（就是本轮那条 `0px`） |
| ③ | 还原 `padding` | **回到** `155.9`（且**必须量得到**几何） | 停在 215.9 ⇒ 红 |

即：**判据仍是「同一个卡、只动节点 `padding`，渲染几何跟着动」**，两个状态源（节点 / 宿主常量）
在 ② 与 ②b 上分得开；①③ 是「读数随状态回来」的锚，②b 是「这不是碰巧」的锚。
改坏法（注释里原本那三条）**全部仍然成立**：

1. 调用点退回 `v.SetPose(…, CardsViewport)`（显式矩形赢）⇒ ② 停 155.9 ⇒ 红；
2. 删掉 `v.SetClipFromTree()` ⇒ 整卡不裁 ⇒ `b1 ≈ 94.2` ⇒ ① 红；
3. 删掉 `CardView.ApplyClip` 里 `_clipFromTree` 那一支 ⇒ ② 不重解析 ⇒ 红。

⚠️ **本代理没跑 Unity ⇒ 上面四条「应当转绿」是推理，不是实测。** 需要同步点跑一次 `CollectionScene.Run` 核。
断言合计会从 **2211 → 2212**（改动①新增 1 条结构前提；改动②不增条）。

## 五、顺手发现（⛔ 都没改，交调度台分流）

1. **`A774` 探针的 `sc774` 仍是 W11 之前的口径**：`CollectionScene.cs:5918`
   `CollectionWindow.CardsCellH / (CardView.Height * 108f)` = **1.0（整格 384）**，
   而生产自 `W11`（2026-10-18）起是 `(CardsCellH − CardsCounterH) / …` = **0.9609**
   （`CollectionWindow.cs:1421`）⇒ 探针摆出来的卡**比生产高 38.27 px**、底边压进张数条。
   本段只断「最高顶点 ≤ 视口上沿」，**不影响判据**（顶边由矩形定、不由缩放定），所以本批**没动**；
   但下一个人若照抄这段当「生产形状」，就会把旧口径当尺子。要统一的话，正确写法是
   `Local(cellT, CardsCardRect(r)) + (CardsCellH − CardsCounterH)/(…)`——
   ⚠️ 届时 `≈94.2` 那句提示（影子越出量）也要跟着重算（≈100.3）。
2. **同一族「量不到就静默跳过」我只收了 `RenderExtentPx` 那一处**（本段态③，已改）。
   本文件其余探针都已经是「前提一条 + 判据若干」或 `else CheckTrue(false, …)`（`:5745-5752`）。
   ⛔ 别的宿主（`DeckScene` / `ShopScene` …）没查（不在白名单，也没在本次根因链上）。
3. **`Content <i>` 容器是**裸节点**（没有 `Graphic`、没有 `CanvasGroup.blocksRaycasts` 语义）**：
   A18 已给容器补了 `CanvasGroup`（`CollectionWindow.cs:1435`），但命中区仍在容器**外面**
   （`CardHit_*` 在 `Viewport` 下）。本轮诊断顺带确认过：这**不影响**本段（`RenderExtentPx` 走的是渲染器，不是射线）。
4. **`RenderExtentPx` 会**漏掉**被裁到「整层关掉」的层** —— 这是它作为「量真几何」工具的**本意**
   （关掉的层确实不画），但反过来说：**「0 个顶点」有两种含义**（① 卡本来就没建 / ② 卡被整层裁掉了）。
   本轮就是靠 `CropLayer` ① 那条才把 ② 认出来的。以后看到「0 个顶点」，**先量卡的世界位置是否落在视口外**，
   别先怀疑没建。建议（未做）：在 `RenderExtentPx` 旁边加一个 `CountAllRenderers(t)` 之类的旁证口径，
   把「关掉了几层」写进失败消息。
