### 4·2 为什么简报那句「在我们 shader 里是死值」不成立

- **原版** shader：`m_ParsedForm.m_SubShaders[0].m_Passes[0].m_State.rtSeparateBlend = **False**`
  ⇒ 原版的 `Blend` 是**单条**（色与 alpha 共用因子）⇒ `_SrcBlendAlpha=1` 在**原版**里是**死值**，
  原版**实际**的 alpha 混合 = 彩色混合 = **5 / 10**。
- **我们的** shader：`WFAlphaMaskOneLayer.shader:87` 写的是
  `Blend [_SrcBlend] [_DstBlend], [_SrcBlendAlpha] [_DstBlendAlpha]`（**分开寻址**，是 2026-10-21 `T17` 按原版 pass 反编译**特意**改成的）
  ⇒ `_SrcBlendAlpha` 在**我们这里**是**活值**，直接进 Blend 状态。

⇒ 现值 `5` 让我们得到 **5 / 10**，**与原版实际混合一致**；
改成 `1` 会变成 **1 / 10**（One / OneMinusSrcAlpha），**反而偏离原版**。

### 4·3 会不会影响别的材质 —— **会，而且是系统性的**

扫 `WarpforgeVFX/Materials/*.mat`（746 个）与 `assets_full` 里同名原版（973 个名字）逐个比 `_SrcBlendAlpha`：

| | 数 |
|---|---|
| 原版有 `_SrcBlendAlpha` 且能对上我们某张材质的 | **379** |
| 其中 `_SrcBlendAlpha` **已经相同** | 138 |
| 其中**不同**（我们 = `_SrcBlend`，原版 = 1） | **241** |
| 这 241 条在原版 shader 里的 `rtSeparateBlend` | **全部 False** |
| **全库** 148 个原版 shader × 431 个 pass 里 `rtSeparateBlend = True` 的 | **0 个** |

⇒ ①「alpha 侧 = 彩色侧」这条**不是 Sand Storm 的失误**，是 `ArenaOriginalMaterial.SetBlend`（`:498-499`）**2026-09-27 有意的决定**，
而且在「原版从来没有 separate blend」这个事实下**它是对的** —— 它复现的是原版的**实际**混合。
② 真要「逐字对齐原版字段」就得一次改 **241 张**，而且改了**画面会变**（变差）。

### 4·4 结论与建议

- ⛔ **不改**（值正确、改了就错）。若将来有人坚持要「字段逐字一致」，正确的做法**不是**改材质值，
  而是让 `WFAlphaMaskOneLayer` 那族 shader 的 alpha 侧**不寻址** `_SrcBlendAlpha`（回到单条 Blend）——
  那是**改 shader**、影响面是**所有**用这族 shader 的材质，必须有 A/B sweep 才敢动 ⇒ 本件不做。
- 建议在 `ArenaOriginalMaterial.SetBlend` 那段注释里补一句「原版 431 个 pass 的 `rtSeparateBlend` **全为 False**，
  所以『alpha 侧 = 彩色侧』复现的是原版**实际**行为，不是近似」。**这句我没加**（`WarpforgeVFX/**` 虽在白名单，
  但它是共用件、A10 正在同一目录写 `WFModuleChangeMaterial.cs`，且改它要重跑战场线生成器 —— 留给调度台裁）。
