## 二、`R8` `normalAbilityBoardCriteria`（＋ `hasAlternativeAbility`）

### 2·1 带出了什么

`cards_engine.json` v21 的两个新键：

```json
"SW21": { "hasAlternativeAbility": 1,
          "normalAbilityBoardCriteria": { "playerTurn": 10, "countOptions": 0,
                                          "triggerIf": 1, "referenceValue": 0,
                                          "countSet": { "targetsAffected": 10,
                                                        "friendlyUnits": 1, "includeMinions": 1, … } } }
"SW9":  { "normalAbilityBoardCriteria": { … "referenceValue": 1, "countSet": { "targetsAffected": 90,
                                                        "enemyUnits": 1, "includeMinions": 1,
                                                        "traitsFilter": 1260 } } }
```

- **`countSet` 与 `unitConditions[].countSet` 逐字同形**（原版都是 `TargetCriteria` ＋ `BoardCriteria.playerTurn`）
  ⇒ 生成器直接复用 `count_set_of()`，C# 侧直接复用 `CountSetDto` / `CardDef.CountSetSpec`（⛔ 没有第二份字段表）。
- 🔴 **只落「非默认」的**：默认 criteria（`playerTurn/countOptions/referenceValue` 全 0 ＋ `countCriteria` 逐格 0）
  在 `BoardAnalysis__MeetsCriteria.c:101` 走 `targetsAffected == any ⇒ true` ⇒ **行为与「没有这一列」等价**
  ⇒ 不落。**缺席 = 恒真**，⛔ 不是「判不了」。
- ⚠️ **`SW9 Fenrisian Wolf` 也有非默认 criteria，但 `hasAlternativeAbility = 0`** ——
  原版**不会**对它调 `MeetsCriteria`（`RawCardScript__GetActiveAbility.c` 的第一道 if）。
  数据照实落（它确实是原版 SO 上的值），消费端按 `hasAlternativeAbility` 先判，**不会**误用。

### 2·2 消费（哪里真的用它）

1. **`CardDef.UsesAlternativeAbility(ctx, owner, actor)`** —— 原版那 17 行的等价物：
   `alt == 0 ⇒ false`（连 criteria 都不看）· `alt < 0 ⇒ null（未知）` ·
   否则 `!MeetsBoardCriteria(...)`。**`true` = 替代支，`false` = 普通支**（方向已按判据钉死）。
2. **`CountEval.MeetsBoardCriteria(ctx, owner, BoardGateSpec, actor, out gap)`** ——
   `BoardAnalysis__MeetsCriteria` 的等价物，**复用** `CountSet` / `SetGap` 那一套（`A12` 已经把
   `playerTurn` / `countOptions` / `triggerIf` 都实现过了）。
   逐档：`playerTurn` 整条闸 → `triggerIf == 8 RandomChance`（未实现 ⇒ null）→
   `targetsAffected == 0 ⇒ true` → 数个数 → `1/2/3` 比较；其余档照原版 **LogError + true**。
3. **`ConditionEval` 的 `case 280`** —— 这是**生产消费点**：原版 `DoesAbilityRequireLoading:24-31`
   本来就靠 `GetActiveAbility` 选主/备，我们照它选完再读对应的 `needsLoading`。

⚠️ **没有接进 `UseAbility`**：`CardDef.Ability` 是**卡面 `Ability:` 文本**解析出来的（池内 0 张有该语法），
而原版 `activeAbility` / `alternativeAbility` 是 SO 数据 —— 两者不是同一样东西。要真把「分支选择」
接到「按哪个技能结算」，得先把 `activeAbility` 的 `abilityLogic` 结构搬进引擎（那是另一条账）。
⇒ **今天这一层能接的、也是原版自己用的那一处，就是 280**。如实记在这里。

## 三、`EmitHit` 的 0 伤 / 被吸收早退闸

### 3·1 判据

```text
BattleManagerSupport__BroadcastUnitDamaged.c   广播调用点 :19,59,70,82 —— **无条件**
CardScript__ResolveDamageDealt.c（接收端）
  :31-33  if (damageInfo.damageAbsorbed(+0x24) != 0) return;
  :34-36  if (damageInfo.damageValue(+0x18) == 0)  return;
  :159    RawCardScript.OnTrigger(0x3c = 60 UnitDamaged, …)   ← 在早退之后
  :168    isPraying(+0x67) = 0                                ← 在早退之后
```

⇒ **「广播发出去」与「触发算数」是两件事**。我们改前把两件事绑在 `EmitHit` 一处、且 0 值也广播
⇒ 带「受到伤害时…」的卡在被盾/闪避/无敌/空投舱/堡垒整份挡下时会**多响一次**。

### 3·2 改法

`EmitHit(ctx, u, amount, absorbed = false)`：

```csharp
int owner = EmitUnit(ctx, EvtKind.Hit, u, amount);   // ⚠️ 表现层不受下面两条闸影响
if (u == null || u.Card == null) return;
if (absorbed || amount == 0) return;                 // ← 新增：原版接收端两条早退
PreCallBoardListener(…); BroadcastWhen(…);
```

- **只挡事件层**。`EvtKind.Hit`（盾碎 / 闪掉 / 打不动的画面反馈）**照旧无条件发** ——
  原版 `BattleCardUI.DamageReceived` 在 `_ReceiveDamage` 尾段、吸收时是否仍飘字**本轮没查**
  （`CardPresentation/**` 是黑名单，也不该在这里改）⇒ 按简报「先只挡事件层」，**表现层另判**。
- **今天所有挡下的调用点传的都是 `amount = 0`**（`RuleCore` 的 `7534/7543/7705/7749/7779` 那五处），
  所以 `amount == 0` 这条闸已经覆盖；`absorbed` 形参是给「**挡下了但数值非 0**」那种原版形态留的口子
  （原版 `GetAdjustedDamage.c:39-50` 置 `absorbed = 1` 时**不改** `damageValue`）。
- 🔴 **函数尾巴那一处（`EmitHit(ctx, u, actual)`）刻意【不】传 `absorbed`**：
  空投舱那一支会把局部 `absorbed` 置真，但它**池子被打空**时 `actual` 已经换成**易伤第二发**的量 ——
  原版第二发是**另一条** `DealMultiDamage`、有它自己的 `DamageInfo`（那时 `dropPod` 已摘 ⇒ `absorbed = 0`）
  ⇒ 这一发**本来就该广播**。⛔ 别为了「统一」写成 `EmitHit(ctx, u, actual, absorbed)`（那会漏掉第二发）。
  这条已写进代码注释。
