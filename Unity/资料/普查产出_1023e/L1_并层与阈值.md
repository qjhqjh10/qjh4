## 二、`MenuScroll` 去阈值（`拆账·MenuScroll 半格门槛` · 判据 `C1-B08`）

### 结论
**已去**。原来那道 `Mathf.Abs(dy) < 1f` 是**自造闸**，而且本机滚轮一格 = ±1 ⇒ 它**正好卡一整格**，
触控板/半格滚被静默丢掉。现在 `dy == 0` 才早退，幅度全交给 `NotchPx`/`NotchK`（= 原版 `m_ScrollSensitivity`）。

### 🔴 关键发现：这道闸有【两道】，只删下游等于没改
| 位置 | 原代码 | 现在 |
|---|---|---|
| `Shell/MenuScroll.cs` `Wheel()`（下游） | `if (Mathf.Abs(dy) < 1f) return;` | `if (dy == 0f) return;`（`10 / 1`） |
| **`Shell/PointerLayer.cs` `WheelAt(px,py,Vector2)`（上游，`Update` 真入口）** | `if (Mathf.Abs(f) < 1f) return false;` | `if (f == 0f) return false;`（`9 / 2`） |

上游那道**不在我拿到的白名单里**，但它是同一个 `C1-B08` 缺陷的输入侧、且删下游时上游会先把半格丢掉
（等于没改）⇒ 按 `铁律 14`「判据已查清（`C1-B08`）+ 改动就在这一批 + 改完秒级 typecheck 能过」三条全中，
**顺手做掉**。⚠️ 同一文件里我**只多改了一处**：把 `bool WheelAt(float,float,Vector2)` 加 `public`
—— 它原来是 `private`（只有 `Update` 调），不加就没法从 Editor 断言侧走真入口；**生产调用点仍然只有 `Update` 一处**。

### 证据
- 行为判据：uGUI `ScrollRect.OnScroll`（`Library/PackageCache/com.unity.ugui@…/Runtime/UGUI/UI/Core/ScrollRect.cs:665-676`）
  —— `position += delta × m_ScrollSensitivity`，**任何非零 delta 都位移**；零 delta 只经
  `data.IsScrolling()`（= `scrollDelta != Vector2.zero`）影响 `m_Scrolling`，**不产生位移**（所以 `dy == 0` 早退与 UGUI 语义**相同**，不是自造）。
- 菜单包 `m_ScrollSensitivity` 现读 **1.0**（多数）/ **100.0**（一份） ⇒ 幅度交给它，不是我们来卡。
- 判据全文 → `资料/普查产出_1023e/C1_战斗线判据_布置与层级.md` 的 `C1-B08`。
