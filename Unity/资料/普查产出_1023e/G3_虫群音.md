## 六、顺手发现（⛔ 没自己动手改别处）

1. 🔴 **`Swarm Card Merge VFX` 没有 `AnimFXController` ⇒ 现在的算法永远读不到它的音**
   （本件的直接后果）：`效果库报告.tsv:863` 那一行 **控制器数 = 0、模块列为空**，
   而 `animfx_modules.json` 的 612 个 effect 里也没有它（只有 `Psychic_Lightning_Swarmlord` /
   `Swarm_Trigger_OnTarget`）。
   ⇒ 要让合并真的响，得**三选一**（都在 G3 黑名单）：
   ① 在合并的调用点（`Battle/**`，A31 §五·3 那一段 `WarpforgeEffectPlayer.Play("Swarm Card Merge VFX", …)` 旁边）
   照 `CardView.PlaySwarmOnSound`（`Core/CardView.cs:6989-7003`）那个先例加两行、**只把 `is2d` 换成 false**
   （原版是 `SoundManager.Play3D`）：

   ```csharp
   WarpforgeVFX.WFSoundCue cue;
   if (WarpforgeVFX.WFSoundBank.TryGetCue("Trait Swarm Tyranid", out cue))
       WarpforgeVFX.WFSoundPlayer.Play(cue, view.transform.position, false);   // is2d = false ⇒ 原版 Play3D
   // 取不到 ⇒ 按工程口径 log 一次（⛔ 不许静默）
   ```

   ② 或在 `WarpforgeVFX/Runtime/WarpforgeEffectPlayer.cs` 给没有 `AnimFXController` 的件补一条
   「原版 `SwarmVFXController.sound` 等价」的 3D 音通道（要连带读 prefab 字段）；
   ③ 或建一个 `WFModuleDef` 侧的特例表。
   **推荐 ①**（最小、与 A31 §五·3 是同一处改动、不引入第四套「音从哪来」的口径；
   播放器 API 实测 = `WFSoundPlayer.Play(WFSoundCue cue, Vector3 worldPos, bool is2d)`，
   见 `WarpforgeVFX/Runtime/WFSoundPlayer.cs:97`）。
   ⚠️ 别把它当成「已经接好」——本报告只补了**数据**。

2. ⚠️ **`import_original_sfx.py` 只拷 wav、不写 `.meta`**（`import_battle_sfx.py` /
   `import_remnant_sfx.py` 同族，也都不写）。而工程里没有 AudioImporter preset ⇒ 手工补进来的 wav
   会被 Unity 用**内置默认**导入（`loadType 0`），与既有 509 条的 `loadType 1 + compressionFormat 2（**ADPCM**，⛔ 不是 Vorbis；见 G4 订正）+ preload 0`
   不一致。本件我按兄弟 meta 复制了一份补上（§三·4）；**要不要把这条下沉进脚本**（每次拷完顺手写 meta）
   由主对话定 —— 那会动到一个被三个脚本共用的地方，G3 不擅自改口径。

3. ⚠️ 反向查漏改前只剩 **1** 个候选、且正是本件补的这条 ⇒ **改完为 0**。
   也就是说「工程按名字播、表里却没有」的那一类 cue，**目前清空了**（口径与局限见脚本注释：
   它是启发式、宁少报不误报）。
