## 二、分类：**β1 —— 回放侧少做了一步**（不是 β2/β3/β4）

### 证据 1：两格的局面读数（`r2_battle.log:161682 / :161695`）

| | `Turn` | `Active` | P1 能量 | P1 手牌 | P1 牌库 | P2 手牌/牌库 |
|---|---|---|---|---|---|---|

| **回放现在**（第 3 条做完） | **T0** | 0 | **0** | **3** | **26** | 5 / 25 |

P2 两侧**逐位相同**；差的只有**行动方 P1 那一整套「回合开始」**：回合 +1、能量 0→2、手牌 +2、牌库 −1。

### 证据 2：录制侧那一格的 log 尾（`r2_battle.log:161669`）

```
[Replay] 录的 log 尾 Draw#p0s-1<-p-1s-1:Stormhawk Interception ／ 现在 log 尾 <空>
```

录制侧的最后一个引擎事件就是**回合开始那一抽**（`p0` = 行动方）；回放侧那时**一条引擎事件都没有**。

### 证据 3：`+2 手牌 / −1 牌库` 正好等于一次 `RuleCore.BeginTurn`

- `RuleCore.BeginTurnCore`：`nDraw = Vars.drawCardsPerTurn = 1` ⇒ 抽 1 张（牌库 −1）——`RuleCore.cs:1744 / :1793`；

  （这张不是从牌库来的 ⇒ 牌库只 −1）。
- 能量：先手第 1 回合 `startingMana(1) + TurnCount(1)×1 = 2` ——`RuleCore.cs:1548-1560`。

**三项读数逐项吻合** ⇒ 两格之间少的就是**这一次 `BeginTurn`**。

### 证据 4：代码路径（为什么恰好漏在第 3 条）

- `NetApply.Apply` 的 `MulliganDone` 支（`A29`）**只** `RuleCore.EndMulligan`，并把「回合还没开」
  记进弱表 `PendingSetupBegin`（`Net/NetApply.cs`）。
- **旧代码只在「第一条真动作之前」兑现**（`Apply` 中段 `IsRealActionKind` 闸之后那句
  `BeginTurnAfterSetup(ctx)`）；四条伪 `kind` 在此之前各自 `return`。
  ⇒ 第 3 条是**伪 `kind`（100）**，它 `return` 得比兑现点早 ⇒ 待办还在、`Turn` 还是 0。
- 录制侧为什么是 T1：`NetReplay` 那趟是 `_logReplaying = true`，`ApplyLoggedAction` 末尾那句补开被
  挡住（`BattleDriver.cs:373`），但**收尾那句**照样补了一次（`BattleDriver.cs:1033`）——
  它排在 `RecMsg(MulliganDone)`（→ `trace[2]`）**之后**、第 3 条 `RecMsg`(`trace[3]`) **之前**。
  所以 `trace[2]` 两端相等（`A29` 修的就是这一格，✓），`trace[3]` 只差这一次回合开始。

### 排除的另外三档

- **β2（RNG 错位）**：不成立。`BeginTurn` 会消耗 `ctx.Rng`（`SpawnTalents` 的 `Next`），但两侧
  **各只消耗一次**，只是**位置**不同（录制侧在 `NetReplay` 收尾、回放侧原在循环收尾）；
  第 3 条之后没有别的动作 ⇒ 随机流没有任何差异。终局 `StateHash` 两侧相等（`r2_battle.log:161734`
  「= 录制时的 ⇒ **同一局**」）也印证 RNG 没分叉。
- **β3（录制侧多记/少记）**：不成立。①②两条断言已证 `actions` / `trace` 一一对应 3→4 条，
  且第 3 条两侧都返回 OK 且 no-op；录制侧 `RecMsg` 落在 `trace` 位置上没有错。
- **β4（哈希取点差一拍）**：不是「取点」问题 —— 两侧都取在 `ApplyLoggedAction` 返回之后
  （`RecMsg` 是方法里最后一件事；回放的 `DeepHash` 在 `Apply` 返回后）。是**回放侧那一刻真的还没开回合**。

## 五、顺手发现（本代理在改动现场看见的）

1. **`RuleCore.BeginTurn` 是 RNG 消费者**（`SpawnTalents` 的 `ctx.Rng.Next`，`RuleCore.cs:11505`/`:11518`）。
   ⇒ 「在哪一格兑现 `BeginTurn`」这条规则**有随机流含义**。本轮安全：录制端与回放端**都只兑现一次**，
   而且第 3 条（伪动作，不耗 `Rng`）之后没有别的动作 ⇒ 位置差不动任何后续随机数。
   将来若出现「`MulliganDone` → 带 `marks` 的换牌残条 → 真动作」这种产品形状，
   因为**两侧都是「先兑现、后落地」**，仍然一致；但这条值得记着。
   另：`SpawnTalents` 每回合都给行动方**新造一张临时卡**进手，所以「回合开始」在这一局里是
   `手牌 +2 / 牌库 −1`（不是 +1 / −1）—— 以后对录像读数时别按 +1 去对。
2. **`RuleCore.Mulligan` 返回 -1（换牌阶段已关）时，`NetApply.Apply` 仍返回 `RuleCodes.OK`**
   ——「迟到 / 重复的换牌」两端都被当成功吞掉，唯一痕迹是日志里那句 `换了 -1 张`。
   这算不算「静默失败」要不要改成拒，是**产品口径**问题（在线的乱序守卫在 `NetBattle` 那一侧），
   不在本账范围，**仅记录**。
3. `PendingSetupBegin` 是 `ConditionalWeakTable`，`NetReplay` / `PlayReplay` 每局都换新 `ctx`
   ⇒ 不会跨局泄漏（本轮加的开头判据也只是查表，不改这条性质）。
