## 〇、一句话结论

**新账-98 与 新账-99 是同一个根**：`NetApply` 把 `MulliganDone` 展开成 **`EndMulligan` + `BeginTurn` 两件**，
而**原版**的次序是 `换牌完成 → 选环境卡 → 环境生效 → 洗牌/补牌 → StartBattlePhase(回合开始)`。
⇒ 回放侧**把回合开始提前到环境卡之前**了。这一条同时解释：
① 轨迹哈希在 `MulliganDone` 那一格假报分叉（新账-98）；② 回放的战场环境到底会不会被应用（新账-99）。

🔴 **新账-99 的原话「回放路径不调 `ApplyOffensiveEnvOnce`」与现读代码不符** —— 回放**会**经
`ApplyLoggedAction` → `IsOffensivePick` → `BeginOffensiveRevealOrApply`（`BattleDriver.cs:334`）走到它，
只是**多绕一层**（reveal 开着时会推迟到 `TickOffensiveReveal` 第 2 段）。详见 R-02。

## 二、逐条补注

### R-01 / R-03 的次序对照（一图）

```text
原版：  Mulligan(换牌)  →  FinishMulligan  →  选环境卡(FirstPhase)  →  环境生效+防御卡进手(FinalPhase:142)
                          →  ShuffleDeck(:159)  →  CompleteMulliganPhase(:165)  →  StartBattlePhase(:233 = 回合开始)

我们录制： Mulligan → EndMulligan → [RecRaw(MulliganDone) ★哈希在这] → 选环境卡 → 环境生效(BeginBattleAfterSetup) → BeginTurn
我们回放： Mulligan → (EndMulligan + BeginTurn) ★哈希在这 → 选环境卡 → 环境生效(可能被 reveal 推迟)
                                ↑ 回合开始被提前了两步
```

### R-01 为什么「只挪哈希」不如「改展开」

- 只挪哈希：`NetApply` 仍然在 `MulliganDone` 里开回合 ⇒ 回放的**动作边界**与原版相反，`OffensivePick` 落在
  回合开始之后（原版在之前）。今天看不到行为差，是因为 `ChooseOffensiveCard` 只写 4 个 `Ctx` 字段、
  不读回合状态；`ApplyOffensiveEnvOnce` 又只碰表现层。**但这是「靠运气」**——只要哪天有卡/规则在
  `BeginTurn` 里读 `Ctx.OffensiveEnvSO`（例如环境卡影响回合开始的抽牌/加成），这条次序就会变成真缺陷。
- 改展开：`MulliganDone` 只 `EndMulligan`；`BeginTurn` 挪到「环境那两条伪动作都落地之后」。
  ⚠️ 回放的动作流里**没有「setup 结束」这个显式标记** ⇒ 需要一个新的判定点（例如：遇到第一条
  **非** `Mulligan/MulliganDone/OffensivePick/DefensivePick` 的动作时，先补 `BeginTurn`），
  或者干脆**加一条只落盘的伪动作**（归 `RecKind*` 那一族，不进 `MsgAction` 的线上语义）。
  两条路都要动「回放契约」的措辞 ⇒ 建议由主对话定口径后再派执行代理。
