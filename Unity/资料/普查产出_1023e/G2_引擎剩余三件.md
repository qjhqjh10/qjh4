## 三 · `questTimes` 的消费点

### 3·1 结论（判据闭合，已接上）

`questTimes` **不是**「任务卡要做 N 次」，而是**这条任务附魔能力的蓄力次数**：
每次它要触发时 `questCounter += 1`；**还没到 `questTimes` ⇒ 那条 ability 不结算**；**到了之后每次照常结算**（计数器**不复位**）。

### 3·2 证据

| 项 | 现读 |
|---|---|
| 原版全文（15 行） | `d:/2/tools/decomp_full/EntityScript__ReachedQuestCounter.c`：`:5-7` 判 `cardType==0x28(Whispers) ∧ spellType==0x78(120 Quest) ∧ 1 < questTimes`；`:9` `param_3+0x270 += 1`；`:10-13` `< questTimes` ⇒ `UpdateFigures` + `return 0`；否则 `return 1` |
| 调用点 | `RawCardScript__TriggerAbilities.c:115` —— 在**每条附魔 ability** `CanTriggerAbility` 通过之后、真正派发之前 |
| 计数位 | `EntityScript__ReachedQuestCounter(entity, enchRaw, entity)` 第三次实参 = **载体** ⇒ 计数器在**牌**上，同一张牌两条任务附魔**共用** |
| 字段名 | `CardScript.get/set_questCounter` 读写 `+0x270`；`questTimes` = `RawCardScript +0x7C` |
| 卡类型码 | `dump.cs:45710-45717` `CardTypeOptions { Minion=0, Hero=10, Tactic=20, Whispers=40 }`（`Whispers = 40` 现核） |
| 我们的落点 | `RuleCore.cs:10700-10710` —— `ench = Enchantments.Matching(...)` 之后、`ops/spec/skipDraw` 那道闸之前 |

### 3·4 断言（怎么才会红）

`ruleprobe g2` ③（**人造夹具**：`spellType=120 · questTimes=3` 的任务附魔 + 走真触发口 `DeclareAttack` 的 `Strike`）：

| 断言 | 🧨 怎么红 |
|---|---|
| 5 次触发 ⇒ `QuestCounter == 5` | 把计数写成「到 `questTimes` 就停」⇒ 3 |
| 前 2 次**不放行**（只扣攻击 3+3） | 把这道闸删掉 ⇒ 第 1 次就多扣 2 |
| 第 3 次（= `questTimes`）**放行**（+2） | 把 `counter < times` 写成 `<=` ⇒ 第 3 次仍不放行 |
| 之后**每次**放行（计数器不复位） | 达到后清零 ⇒ 第 4/5 次不放行 |

### 3·5 没查清 / 已知边界（如实记）

1. 🔴 **现池完全不可达（数据事实，不是省略）**：`资料/普查产出_1018/allcards_1350/cards_raw.json` 1,351 张 ——
   `questTimes` **全 0** · `_quest` **全 0** · `spellType == 120` **0 张**。⇒ 这个消费点在现池里**一次都不会改变行为**
   （所以「全池结算零行为变化」是必然，而不是没验）。
2. **`FireTriggerAlways` 那一支没加这道闸**：它只用 `Enchantments.Matching(...).Count > 0` 判「有没有正文」，
   会把「只有一条未达成的任务附魔」算成「有正文」⇒ 走到 `FireTriggerAt` 后被本闸挡住 ⇒ **不发信号**（原版同样是 `return 0` 不放行）。
   差别只在「多走一跳、无副作用」；现池不可达，**没改**（改了要动另一条广播路径，收益 0、风险不为 0）。
3. **一处附魔一条计数**：原版是对**每条附魔的每条 ability** 调一次；我们的 `Matching` 是**一条附魔一份**（按关键词筛）。
   同一条附魔多条 ability 命中同一个 trigger 时，原版会 **+N**、我们 **+1**。现池 0 张可达（`abilityTriggers` 也没有 120 的卡），
   将来真出现要按 ability 粒度拆。
4. **`FilterByQuestCounter` 的名字不区分 `SpellType` 未知**：`SpellType == -1`（旧表）⇒ 不加闸、不猜 —— 与工程 `-1` 契约一致。

## 六 · 顺手发现（不是本批任务，按铁律 13·4⑧ 报上来）

1. 🔴 **`ruleprobe` 的 `LoadPool` 原来【没传 `animTimes`】**（引擎 `CardDatabase.Parse` → `MapAnimTimes` **是传的**）。
   后果：探针侧 `CardDef.AnimTimes` **恒空** ⇒ `HasAnimTrigger(...)` **恒假** ⇒ 任何「拿探针量动画归口 / `SelfCheckRoutedTriggers`」
   的读数都是**假阴性**（与 `A1911`/`A1959`/`A17` 那族「探针与引擎口径不同」同一个坑）。
   **已补**（`工具/ruleprobe/Program.cs` 的 `LoadPool`，+105/-4，含逐字段搬运与「缺列 = 空表」口径）。
   ⇒ 建议：以后 `CardDef` 加列时，**探针那一侧与引擎那一侧要成对加**（这一条已在两处注释里写明）。
2. 🔴 **`ActionScope` 的构造函数（`ActionPump.cs:87`）也会调一次 `PumpActionQueues`**（结掉上一轮残留）。
   ⇒ 任何「每个动作做一次」的副作用**都不能挂在 `PumpActionQueues` 尾部**（实测一次动作发 2 条）。
   这条已写进 D9 那段注释；建议主对话把它抄进 `Core/ActionPump.cs` 的头注释或「已知的坑」。
3. ⚠️ **`VfxMap.SelfCheckRoutedTriggers` 原来只在 `want` 侧跳过歧义行**，`got` 侧不跳 ⇒ 只要有卡的真歧义行
   在 `got` 里出现（`SW18` 就是这样），这条闸会**恒报「多播」**（= 整条闸报废）。
   已补 `got` 侧同跳（`ambig` 逐次消费）。⚠️ 这是**放宽**：只放宽「已被 `AmbiguousTriggerLabel` 判为分不出来的**那一行**」，
   `Buff_Blue_SW` 那一行仍然逐件验。
4. ℹ️ **`EntityScript__ReachedQuestCounter` 的语义容易被误读**：它不是「做 N 次任务」，而是「这条附魔能力蓄力 N 次才开，
   开了之后**一直开**」（计数器不复位）。已写进 `CardInstance.QuestCounter` 与 `Enchantments.FilterByQuestCounter` 的 doc。
5. ℹ️ **`NoEmitTriggerNames` 现在只剩 8 个名字**（`A21`+`A27`+`A30`+本批一共放行了 4 个：520·665·195·20）。
   现读 8 个：`Unstable` / `OnSecretCreated` / `OnCollectQuestPoints` / `TriggeredCodex` / `OnCollectSpiritStone` /
   `UnitLoseStealth` / `UnitStunned` / `OnSabotageCreated`。其中 **`OnCollectQuestPoints`(695) 的原始广播器已经找到**
   （`BattleManagerSupport__BroadcastCollectQuestPoints.c` / `CardScript__ReactToCollectQuestPoints.c` 的 `OnTrigger(0x2b7=695)`），
   与 `questTimes` 是**同一块任务机制**的另一半 —— 但我们的引擎**没有「收集任务点」这条事件源**（现池 0 张任务附魔），
   属「还要先补事件源」，本批没动。
6. ℹ️ `play check` 的基线过期（见 §五）—— 不是本批引起，但**下一个跑自检的人会看到红**，需要主对话裁定是否重钉。
