### 1·3 做法（为什么这样才有判别力）

```csharp
var ctx = make();                                   // 最小局面（空棋盘 / 空手牌为主）
int ran = 0;
RuleCore.EnqueueAbility(ctx, ActionPriority.Player, "W62·哨兵", () => ran++);   // ← ① 塞哨兵
call(ctx);                                          // ← ② 裸调入口（外面【不】包 BeginAction）
Check(ran, 1, …);                                   // ← ③ 哨兵被泵掉了
Check(ctx.ActionQueue.Count, 0, …);                 // ← ③ 队列空
Check(ctx.ActionQueue.Resolving, false, …);         // ← ③ 闸没泄漏
```

**为什么非要塞哨兵**：不塞的话，入口什么都不入队时 `Count == 0` 恒真 = 假绿。
哨兵之后判别式变成**两行同时**：

| 入口 | `ActionScope` ctor 的行为 | 实得 |
|---|---|---|
| **有**外壳 | `_outermost = true` ⇒ 先 `PumpActionQueues`（此刻 `Resolving == false`）⇒ 哨兵跑掉 | `ran == 1` · `Count == 0` ✅ |
| **漏了**外壳 | 没人泵（且没有外层作用域 ⇒ `ActionScope.Dispose` 那句 `LogError` 也**不会**发） | `ran == 0` · `Count == 1` ❌❌ |

⇒ **这就是「某入口漏泵一次 ⇒ 必红」的灭自证**，而且是**结构上不可能同时满足**的两半。

**为什么入口要「裸调」**：外面若自己开一层 `BeginAction`，入口那层就变成内层（`_outermost = false`）、
**永远不泵队** —— 测的就不是它了（`ActionPump.cs` 的设计口径 ②）。

**为什么夹具可以「最小」**：`using (BeginAction(ctx))` 是这 18 个入口的**第一句**，
早退（非法参数 / 无目标 / 不在场）也在作用域**里面** ⇒ 空棋盘就足以把外壳跑一遍。
业务语义各有各的用例（`A1983` / `W61T24` / `W61T25` / `T23`…），本组**不重复**。
