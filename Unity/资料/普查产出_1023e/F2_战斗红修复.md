### 证据链（全部现读，不靠猜）

1. 失败读数：`battle.log:161640`
   `[Replay] **开局次序反了**：第 2 条 MulliganDone 落地之后回合已经开始了（ctx.Turn = 1 …）`
   —— 第 2 条（0 起算）= `rpActs[2] = MulliganDone`（`BattleScene.cs:26967` 那三条字面动作），**不是**环境卡那一支。
2. 同一份日志里，这条流的前两条换牌**根本没落地**：
   `battle.log:161592` / `:161608` = `[Net] 换牌落地：座位 0/1 换了 -1 张`
   —— `-1` 是 `RuleCore.Mulligan` 的「**不在换牌阶段**」返回值（`RuleCore.cs:410-411`：`if (!ctx.MulliganOpen) return -1;`）。
3. 为什么 `MulliganOpen` 是 false：该夹具跑在 `RunCore` 的 driver 上，`mulliganEnabled` 是**字段初值 `false`**
   （`BattleDriver.cs:6390`；只有 `BuildAndSaveScene` 把它置真 —— `BattleScene.cs:184`）⇒ `Begin` 交给
   `RuleCore.NewBattle(openMulligan: mulliganEnabled …)`（`BattleDriver.cs:4402-4403`）⇒
   `mulliganOpenNow = false`（`RuleCore.cs:213`）⇒ `Ctx.MulliganOpen = false`（`RuleCore.cs:381`）⇒
   `Begin` 走**无换牌支**、**当场** `RuleCore.BeginTurn(Ctx)`（`BattleDriver.cs:4630`）⇒ **回合 1 在任何动作之前就有了**。
   ⇒ 于是 `MulliganDone` 落地那一刻 `Turn == 1`，`A29` 的结构断言**如实报红**。它报得对。
4. **产品不会录出这种流**（这是判「夹具前提」而不是「断言太严」的关键）：
   三条伪动作的唯一生产者是 `NetBattle.HostResolveMulligan`（`Net/NetBattle.cs:1272-1280`，`kind` = 100 / 100 / 101），
   而它的两个调用点都挂在**换牌提交**上 —— `NetBattle.cs:1028`（主机自己也交了）/ `:1222`（主机收到客机的换牌）。
   换牌面板不开 ⇒ 没有人能提交 ⇒ 这三条**一条都不会出现**。
   ⇒ **「`MulliganDone` 存在」蕴含「那一局真的进过换牌阶段」**，`A29` 那条断言的前提本来就该成立。

**结论**：`A29` / `A32` 的实现与断言**都正确、一个字没改**；错的是 `A1099` 那个夹具——它把
**只在换牌局才会出现**的三条伪动作，灌进了一局**从头就没开换牌**的对局。

## 四、顺手发现（⛔ 本代理没改，只记）

1. **`A32` 报告 §2·2 的动作 `kind` 写错了**：它写 `rpActs` 是「三条伪动作 **100/101/102**」，
   实际是 **100 / 100 / 101**（`NetActionKind.Mulligan = 100`，`MulliganDone = 101` —— `NetProtocol.cs:140-142`；
   102 是 `OffensivePick`，这一节没有）。不影响它的结论，但下一个会话照那句去查会对不上。
   ⇒ 建议主对话在 `A32` 报告里就地订正（铁律 5；`资料/**` 不在本代理白名单）。
2. **`NetApply.Apply` 的 `MulliganDone` 日志无条件打**（`NetApply.cs:68`）：
   即使 `wasOpen == false`（这条 `MulliganDone` 是空操作）也照打「换牌阶段结束（回合开始推迟…）」。
   本次红就是被这句话带着走了一段弯路（日志看起来像「换牌正常结束」）。属「不许静默失败」的反面（**误报**），
   建议改成按 `wasOpen` 分两句。⚠️ 在 `Net/**` ⇒ 本代理**不许动**，留给主对话裁。
3. **`mulliganEnabled` 不进录像头**：`ReplayRecord` / `MsgStart` 里没有这一格，回放要靠 driver 当时的字段值
   才能重建同一局 ⇒ 任何「换牌局」的回放（含自检夹具）都必须由调用方自己带对。
   今天产品那条路是安全的（场景里存着 `mulliganEnabled: 1`），但**夹具很容易再踩同一个坑**。
   要根治得让录像头记一格（会碰 `ReplayStore` / `MsgStart` = `Net/**`）—— 不在本笔范围，记在这里。
4. **`A29` 那两条结构断言目前只覆盖「回放」**（`PlayReplay` 的循环）。活局路径（`ApplyLoggedAction` 直调）
   没有同族读数 —— 本次诊断时正好靠 `换牌落地 -1` 这个日志才看清前提，说明「活局到底在什么状态下开回合」
   还缺一条正面判据。不是缺陷（`NetApply` 实现是对的），是**覆盖缺口**，留给战斗线排。
