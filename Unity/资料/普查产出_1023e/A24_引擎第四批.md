## 1. `T21④` —— 回合末两个 Broadcaster 的发射序

### 结论

`ResolveAtTurn` 原来**边遍历作业边发** `EvtKind.Trigger`（手牌 → 棋盘（进场序）→ 常驻），
且 40/41 按卡二选一**混在同一批**；而原版是**两趟广播**、41 整趟在前，每趟按
**`allCardsInPlay`（进场序）→ 当前玩家手牌 → 对手手牌**。已把**发射**整趟提出去、按原版序发，
**结算/入队次序一个字没动**（`T03·c` 口径）。

### 证据（本轮亲读 `d:/2/tools/decomp_full/`）

- `BattleManager__ResolveEndTurn.c:385` → `BattleManagerSupport__BroadcastTurnBeforeEnd(...)`；
  `:433` → `BattleManagerSupport__BroadcastTurnEnd(...)` —— **同一段直线代码、同帧**。
- `CardScript__OnTurnBeforeEnd.c` = `RawCardScript.OnTrigger(0x29 = 41)`；
  `CardScript__OnTurnEnd.c` = `OnTrigger(0x28 = 40)`（另有 `0x2b=43` / `0x2d=45` 两支，见 §4）。
- `BattleManagerSupport__BroadcastTurnEnd.c` 与 `__BroadcastTurnBeforeEnd.c` 的遍历序**逐行一致**：
  ① `manager+0x470`（`allCardsInPlay`，只对 `CardScript__IsInPlay` 的调 `OnTurnEnd/OnTurnBeforeEnd`）
  → ② `GetCardsInHandRef(BattleManager__IsPlayerTurn(...))`（**当前玩家手牌**）
  → ③ `GetCardsInHandRef(!IsPlayerTurn())`（**对手手牌**）。
- `BattleManagerSupport__BroadcastTurnStart.c` 是**同一序**（所以 `turn_start` 也按它发）。
- 全池现读：`TurnEnd` 动画行 **11 张** · `TurnBeforeEnd` **1 张**（`SAU20 Chronomancer`）；
  **没有一张卡两个名字都有**（所以「两遍各发一次」今天 = 每卡仍恰好一条）。

### 改动清单（`Core/EffectResolver.cs`）

- 新增 `EmitTurnTriggerNamed`（指名版发射口，闸仍 `HasTriggerSource`）· `EmitTurnTriggerRaw`（不过闸的发射体）
  · `EmitAtTurnTriggers`（`turn_end` 分两遍；`turn_start` 单趟）· `EmitAtTurnTriggerPass`（一趟 = 原版那三个循环）。
- `ResolveAtTurn`：`var unresolved = …` 之后**先整趟发射**（`EffectResolver.cs:6749` 附近），
  三个 `foreach` 里的 `EmitTurnTrigger(...)` 全部删除；**入队/结算代码逐字未动**。
- 棋盘那一趟直接复用 `unitJobs`（它已由唯一那处 `StableSortByPlayOrder` 排成进场序）；
  递归保护 `EffectChain` 对棋盘那一趟照旧生效。
- **对手手牌那一趟**：写成注释而不是空循环 —— `EffectText.SplitAtTurn` 只认 `you` 视角的手牌陷阱，
  ⇒ 对手手牌在行动方回合**恒不发**（池内两张都是 `At the end of your turn`）；将来出现 `each turn`
  型手牌陷阱要**发射层 + 结算层一起改**（见 §4·4）。

### 断言（`Editor/RuleEngineTest_Order.cs::TestT21TurnBeforeEndBeforeTurnEnd`，已挂 `Step`）

## 2. `新账-104` —— `EC58 Vengeful Surge` 部署解析不出

### 结论（根因）

`desc = "Deploy an Infractor and a Tormentor. If a friendly troop died this turn, give them Flank"`。
`TryDeploy` 只切「`and` + **动词**开头」的尾句（`SplitAndTail`），而 `and a Tormentor` 是**第二个卡名**，
不切 ⇒ 整个 `"infractor and a tormentor"` 当一个载荷 ⇒ `CreatePool.Resolve` 认不出
（「既不是原版卡名、也不是兵种词」）⇒ **两张都不上场**（改前实测就是这个读数）。

### 证据（第一权威 = 原版卡数据字段；本轮亲读）

`资料/普查产出_1018/allcards_1350/cards_raw.json` 的 `EC58`：

- `cardAbilities[0].abilityLogic[0]`：`chosenAbility = 70`（summonUnit）·
  `summonCriteria.unitsToSummon` = **两条 PPtr**（`-8203997727151427570` → **`EC8 Infractor`**、
  `4826896904129109588` → **`EC5 Tormentor`**）· `summonAllTargets = 1` ⇒ **两张都召**（不是二选一）。
- 后半句在数据里是 `cardAbilities[1]`：`abilityLogic[0].chosenAbility = 75`（summonBuffedUnit）+
  `buffEffect{buffType 3, trait 460}`，`summonCriteria.unitsToSummon` **还是这两条** ⇒ `them` = 这一批**两张**。
- 成品卡图亲读：`d:/2/Warpforge部队卡片/Emperor_s Children/4计策/Warpforge_57_Vengeful-Surge.png`
  —— 与 `desc` 逐字一致（`Deploy an Infractor and a / Tormentor. If a friendly troop died this turn, give / them ⚡Flank`）。
- 全池按同一形状扫：`\bdeploy\b[^.]*\band\s+(a|an)\s` **只命中 EC58 一张**（改动面 = 1 张）。

### 改动清单

- `Core/EffectText.cs`：新增 `EffectOp.Payload2`（doc 里带上面那三行判据）·
  `TryDeploy` 末尾新增「`X and a/an Y`」拆两载荷（**只在「两张具名卡、各 1 张、从全池、无 random/费用/upTo」这一档**填；
  别的形状今天全池 0 例，**不猜**）。
- `Core/EffectResolver.cs::DoDeployOnce`：新增双载荷分支（`EffectResolver.cs:2982` 附近）——
  两次 `CreatePool.Resolve` 各部署 1 张；**`LastTargets` = 两次部署的并集**（紧跟的 `give them` 指这两张）；
  一侧解析不出仍部署另一侧并**出声**。⚠️ 刻意**不拆成两条 op**：那样第二条会把 `LastTargets` 清成只剩自己
  （`DoDeployOnce` 的「刚部署的这批」口径）⇒ `them` **少给一张**，是那种「一半绿一半红」的静默半错。

### 断言（`Editor/RuleEngineTest_S23_Resolve.cs::TestA24EC58DeployPairAndFlank`，已挂 `Step`）

1. 先杀一个**友方部队**（`Deal 99 damage to a friendly unit`）⇒ 打 `EC58` ⇒
   `Infractor` 与 `Tormentor` **都上场**、且**都**有 `flank`；前提断言：`DeadUnits` 里有本回合的 `troop`。
2. **灭自证**：没有阵亡的同一局 ⇒ 两张**照上**、但**一张都没有** `flank`。

🧨 改坏法：退回「整段一个载荷」⇒ 两张都不上场 ⇒ 1 的两条红；拆成两条 op ⇒ 只有后一张拿到 Flank ⇒ 红；
忽略条件半句（永远给 Flank）⇒ 灭自证红。

### 没查清的部分

- `EC58` 的 `boardCriteria.countCriteria`：**ability[0]（部署那半句）也带** `conditionsFilter = 221`，
  且 `triggerIf = 1 / referenceValue = 0`；ability[1] 是 `triggerIf = 2 / referenceValue = 1`。
  `triggerIf` 这两档的**确切语义没解清**（是否表示「≥/≤ 某个计数」）。卡面（③）明确部署是**无条件**的，
  本实现与卡面一致；若要闭合要读 `FilterMethods__MeetsConditionCriteria` / `BattleManager` 那一段（§4·5）。
- `give them Flank` 的时长：`buffEffect` 里 `untilEndOfTurn=0 / permanentBuff=0`，两个字段同时为 0 时
  不代表「不永久」—— 卡面没写时长 ⇒ 按永久（工程既有口径）。**字段语义没进一步解**。

## 4. 顺手发现（不在两件账里，供调度台分流）

1. **`TurnStart(30)` / `TurnStartPlayer(31)` 不是两次广播，而是同一个回调里的两次 OnTrigger**
   （本轮读 `CardScript__OnTurnStart.c` 现核）：`OnTrigger(0x1e = 30)` **无条件**，
   随后 **`param_2 == 卡主` 时**再 `OnTrigger(0x1f = 31)`。
   而 `BattleManagerSupport__BroadcastTurnStarted`（`_NextTurn_d__395__MoveNext.c:385`，排在
   `BroadcastActivateMinions` 之后）发的是 **`0xa0 = 160`**（另一个 trigger），**不是 31**。
   ⇒ 我们 `TurnTriggerNameOf`「在 [TurnStart, TurnStartPlayer] 里二选一」在**今天池内 0 张两名字都有**的前提下
   无可观测差异；但真出现两名字都有的卡，原版是「**同一趟里先 30 再 31**（31 仅当 owner==行动方）」，
   不是「两条广播」。⚠️ 建议就地订正 A19/既有注释里「两个名字分两拍」的说法（未动别处文档）。
2. **`BroadcastTurnEnd` 的棋盘循环有一支我们没建模**：`IsInPlay == false` 的卡，若
   `EntityScript__HasCurrentTrait(...)` 且 **`cardState`(+0x228) == 5**，**也会**调 `OnTurnEnd`。
   🔴 **2026-10-24 A2 已闭合**：trait = **1050 `remnant`**（机器码 `0x9B5695` = `mov edx,0x41A` + `cmp [rax+0x228],5`）；原写 `cardType == 5` 是字段读错。我们已在 `EffectResolver.cs:7487-7492` 实现，只缺断言。
3. **`OnTurnEnd` 另有 `0x2b(43)` / `0x2d(45)` 两支**（`+0x230` 的 `ObscuredBool` / `param_2 == owner`），
   与 A19 §6「没查清」同一格，本轮仍未查它们的生命周期与闸门。
4. **对手手牌那一趟**（原版第三个循环）：我们 `SplitAtTurn` 只认 `you` 视角的手牌陷阱 ⇒ 今天**恒空**。
   已写成显式注释（`EmitAtTurnTriggerPass` ③）。将来若出现 `each turn` 型手牌陷阱，
   **发射层与结算层（只扫行动方手牌）必须一起改**，只改一层 = 「播了效果没人结算」。
5. **`EC58` 的 `boardCriteria` 语义未闭合**（见 §2「没查清」）—— `conditionsFilter=221` 同时挂在
   **无条件**的部署 ability 上，`triggerIf` 的 1/2 两档读法未解。今天按卡面实现，若要「按字段」复刻需再读一层。
6. **`gen_diag_runner.py` 产物在本代理开工前就已经过期**（A20 加了 3 条用例没重生成 ⇒
   `DiagDriftAlarm` 每次 Unity 起来都会 `LogError`）。本笔为了让自己那 2 条用例进诊断表**顺手重生成**
   （305 条 = 含 A20 那 3 条），现在 `--check` 逐字节相同。⚠️ 这不是本笔的账，但重生成后不再误报。
7. **`play check` 的 6 张主档差**（`AM43` / `BL64` / `DA28` / …）是 v21 卡表的遗留，与本笔无关 ——
   建议下一轮安排重钉 `PinnedPlayMd5` 时一并处理（本轮按简报**没碰**）。
