### ① 三件一起做（⚠️ 第一道门槛【内容】被证伪 —— 这是本报告最重要的一条）

**㉑①-a 原文**：「先 `ChatPreviewMessage.Instance != null && Instance.message.enabled` ⇒ 再 `closeOnESC` ⇒ 再关。」

🔴 **实测不是 `ChatPreviewMessage`。逐条证据（第一权威 = 反编译方法体 + 类元数据）：**

### ② `WindowState` 枚举对齐

- 原文：`public enum WindowState { Closed = 0, Opening, Open, Background }`
- 改后：`public enum WindowState { Closed = 0, Open = 1, Background = 2 };`（`Shell/WindowsManager.cs:59`）
- 判据：`d:/2/Warpforge_code/Scripts/Assembly-CSharp/WindowState.cs` 逐字 = `Closed = 0 / Open = 1 / Background = 2`；
  原版 `IsOpen()` 是**字面量** `0x68 == 1`（`GameWindow__IsOpen.c`）⇒ 错位就会判错。
- **`Opening` 全仓零引用**（`grep -rn "Opening" --include=*.cs` 只命中 `Booster Opening - Card …` 这类动画名）
  ⇒ 删除是零行为变化；全仓其它 `WindowState` 引用**都用枚举成员、没有一处 `(int)` 比较**（已逐处核）。
- 新断言：`Check((int)WindowState.Closed, 0, …)` / `Open, 1` / `Background, 2`（`ShellScene.cs:1347-1350`）。

### ④ 那条「理由写错」的断言

**原文**：`CheckTrue(!pl.KeyCancel(), "★ 一扇窗都没有时 ESC 什么都不做（原版 `WindowsManager.Update` 在 `currentWindow == null` 时直接 return）");`
**问题**：`currentWindow == null` 这一句对，但**原版那一刻的处境不是「一扇窗都没有」** —— 原版有**常驻 `baseMenu`**
（`WindowsManager` 字段 0x48；`CloseWindowCO` 首句就是拿它比），那一刻 `currentWindow` = baseMenu，
而 `MainMenuWindow.ESCPressed` 覆写成**开「退出游戏」弹窗** ⇒ **原版那一下会开弹窗**。
**改后（只改文字、兑现「不许拿文字替原版背书」）**：`ShellScene.cs:1192-1197` —— 明写「这一条钉的是**【我们的处境】**，
不是原版的处境」，并标 `📌 已记账`（见 §3 新账 1）。实现（`currentWindow == null ⇒ 直接 return`）**没动**。
