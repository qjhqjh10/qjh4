## 一、结论（做完了 · 一句为什么）

**做完了**：按代码静态数，本窗**全窗 35 个 `Label`**（3 页签 + 图像页 11 + 音频页 5 + 联机页 16；
自检第 ③ 条会打出**实测**个数，门槛 15）的字号现在都 = **原版字面量 × 0.9**（原来全是大 11% 的那个未缩放值）。

| 项 | 结果 |
|---|---|
| 页标题（`Tab Title`，原版 fs **55**） | 改前实画 **55.00** → 改后 **49.5**（屏幕真值） |
| 全窗（含 FPS 刻度/音频行/页签/输入框，静态数 **35** 个 `Label`） | 改前 5 组值 **55/42/40/35/34** → 改后 **49.5/37.8/36/31.5/30.6** |
| 其它窗 | **零变化**（共用件 `MenuDraw.cs` **一行没碰**，见 §二·3） |
| 新断言 | **+7 条**（`Editor/SettingsScene.cs` 新开一节，⛔ 一条旧断言都没动） |

### 修法（选的是「调用点传对值」，但把「调用点」收敛到本窗**唯一那个漏斗**）

在 **`SettingsWindow.Text(...)`**（本窗**唯一**的文字入口：15 处调用 + `PageTitle` 都走它）里，
把字号和矩形**同一个漏斗里一起缩**：

```csharp
var lb = MenuDraw.Text(p, r, s0, c, n, fs * RootScale, q);   // 🔴 A171：字跟着坐标一起缩
```

**为什么这样最不容易再分叉**：`Screen()` 已经在这句的上一行把**矩形**缩过一次（本窗把原版根上那层
`m_LocalScale = 0.9` **烘进坐标**）——「原版未缩放设计值 → 世界里实画」这条规矩**只写一处**，
字号跟着它走，两者不可能再各缩各的。本窗**第二个文字入口**（`MenuInputField`，它自建一棵小树、
历史上绕过了漏斗）在同文件里单独补了 `InputFontPx = 40f * SettingsWindow.RootScale`（= 36）。
再靠 §二·2 那条**扫全窗**的断言兜底：谁新加一段字忘了缩，那条当场红。

### 被否掉的两个方案（各一句理由）

1. **把 `0.9` 硬写进 `MenuDraw.Text`（共用件）** —— **错**：别的窗根上**没有**这层缩放。
   实扫 `bundle_menus_assets_all` + `generalgamewindows` + `mainmenuwarpforge` + 13 个战场包的**全部**
   `RectTransform`：`m_LocalScale` 恰为 `0.9` 的**只有 2 颗**，其中一颗是
   `GameObject/Main Menu Settings Window.json` 这个**窗体根**、另一颗是名为 `Image` 的节点
   ⇒ 写进共用件会把**别的 113 处调用**一起缩小。
2. **在 15 个调用点各写一遍 `FontLabel * RootScale`** —— **不用**：漏一处就又是一块大 11% 的字
   （这次的第二个入口 `MenuInputField` 就是这么漏的），而且「原版设计值 → 实画值」这条规矩会在
   两个地方各写一份（CLAUDE.md §三：两处写同一条规则 = 迟早不一致）。
   同理**也没给 `MenuDraw.Text` 加 `scale` 形参**：它只会由同一个漏斗传一个常数进来，
   却要在共用件上改签名（本轮 `MenuDraw.cs` 还有 A9+A140 / A12① / A78② 三位写手在飞）。
