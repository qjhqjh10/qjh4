## ① 结论

**练习窗开窗时的阵营筛选已从我们自加的 `ArmyIndex = -1`（不限）改成原版口径**：

| 状态 | 原版（`Open.c:172-180`） | 我们现在 |
|---|---|---|
| 有那副牌、且它的督军有阵营 | `ChangeSelectedArmy(牌.deckHero.cardArmy)` | `ArmyIndex = Factions().IndexOf(督军阵营)` |
| 没有可用的牌 / 督军为空 / 阵营不在那 13 格里 | `ChangeSelectedArmy(10)` | `ArmyIndex = Factions().IndexOf("Ultramarines")` |
| 数据残缺（连 `Ultramarines` 都不在 `Factions()` 里） | 不会发生 | `-1` 并**出声**（`Debug.LogWarning`） |

**`10` 是什么档 = `CardArmy.Ultramarines`**（枚举每档 +10，见 ②·2）。

**可见效果**：开窗左列从 **79 格（78 对 + 首格「你的卡组」）** ⇒ **7 格（该阵营 6 对 + 首格）**；
内容高 **6381 → 657**（159×4 + 21）；可滚范围 **5840.21 → 116.21**（7 格仍超出视口 540.79 一点点）。
`MainMenuScene` 里那批按 79 格写的数字**一个都没改** —— 改成在量它们之前**显式把筛选摆回 `-1`**，
并写明「这是**夹具基线**、原版没有这一档」（`ArmyIndex = -1` 现在只剩「自检摆位」与「数据残缺」两个来路）。

## ② 原版判据（`文件:行号`）

### 2.1 开窗时设哪一档 —— `d:/2/tools/decomp_full/PracticeModePopup__Open.c`

`Open` 的**末段**（`:172-181`），逐句：

| 行 | 原文（逐字） | 含义 |
|---|---|---|
| `:172` | `cVar1 = CardDeck__op_Inequality(lVar2,0,0);` | 判「活动那副牌」是不是 null |
| `:173-175` | `if (cVar1 == '\0') { uVar8 = 10; }` | **空 ⇒ `10`** |
| `:176-179` | `else { … if ((lVar2 == 0) \|\| (*(longlong *)(lVar2 + 0x40) == 0)) goto LAB_18080e960; uVar8 = *(undefined4 *)(*(longlong *)(lVar2 + 0x40) + 0x2c); }` | 非空 ⇒ 读 **`deck + 0x40 → +0x2c`** |
| `:180` | `PracticeModePopup__ChangeSelectedArmy(param_1,uVar8,0);` | 设筛选（**Open 就此 return**） |

- `+0x40` 是什么：`d:/2/tools/il2cpp_out/dump.cs` 的 `class CardDeck`（`TypeDefIndex: 380`）字段表
  = **`public RawCardScript deckHero; // 0x40`**（⚠️ **不是**同一张表里的 `public CardArmy deckArmy; // 0x50` —— 反编译读的是前者）。
- `RawCardScript + 0x2c` 是什么：`ObtainableItem` 那一层的 **`public CardArmy cardArmy; // 0x2C`**（`dump.cs` 现读）
  ⇒ **= 这张（督军）卡身上的阵营**。我们这一侧的同一条推导 = `PracticeModePopup.FactionOf(deck.WarlordId)` /
  `CollectionData.DeckAt(i).Faction`（`CollectionData.cs:115` 取的是同一个 `hero.Faction`）。
- **`ChangeSelectedArmy` 怎么用这个数**（`PracticeModePopup__ChangeSelectedArmy.c:30-33`、`:61`）：
  `if (param_2 == *(int*)(self+0xe8)) return;`（同阵营早返回）→ 写 `+0xe8` → 刷标题 →
  循环里 `SetActive(btn+0x28 /* Highlight */, btn.army(+0x48) == param_2)` → 末句 `SetArmyButtons(self, param_2)`。
- **`param_2` 的取值域 = 阵营枚举本身**（不是「第几格」）：`PracticeArmySelectionButton__Initialize.c:17`
  `*(undefined4 *)(param_1 + 0x48) = param_2;`，而 `ConfigureArmyFilterButtons.c` 是 `Enum.GetValues(<阵营枚举>)` 逐值建格
  （跳过 `0`），`PracticeArmySelectionButton__OnArmySelected.c:5-6` 又把 `+0x48` 原样传回 `ChangeSelectedArmy`
  ⇒ **`10` 与格子上那个 `+0x48` 是同一个域**。

### 2.2 `10` 是哪一档 —— `d:/2/tools/il2cpp_out/dump.cs` 的 `public enum CardArmy`

```
Neutral = 0 · Ultramarines = 10 · Goff = 20 · SaimHann = 30 · Sautekh = 40 · BlackLegion = 50 ·
Leviathan = 60 · TauEmpire = 70 · Sororitas = 80 · Genestealers = 90 · AstraMilitarum = 100 ·
DarkAngels = 110 · EmperorsChildren = 120 · SpaceWolves = 130
```

⇒ **`10` = `CardArmy.Ultramarines`**。
⚠️ `ConfigureArmyFilterButtons` 那份 `Enum.GetValues` 的枚举类型常量（`DAT_1842bf628`）在本文件里解不出名字；
但**表里另一个候选 `CardArmyOrdered`（`dump.cs`，`TypeDefIndex: 935`）的 `10` 也是 `Ultramarines`**
（两者只差 `SaimHann` 的序号 30 vs 55）⇒ **结论不依赖选哪个**。
旁证：本工程 `BattleLogData.ResolveArmy("Uriel Ventris") == 10 /* CardArmy.Ultramarines */`（`Editor/MainMenuScene.cs` 那条断言）。

### 2.3 我们这一侧的映射（为什么存阵营名、不存 `10`）

`ArmyIndex` 是 **`Factions()` 的下标**，不是 `CardArmy` 的值 —— 两者只是**今天**恰好同序
（`Deck/DeckEditorState.cs` 的 `ArmyOrder` = `Ultramarines, Goff, SaimHann, Sautekh, …` = 枚举 `10…130` 的序）。
⇒ 实现里存的是**阵营名** `"Ultramarines"`，运行时再换成下标（`DefaultArmyIndexOf`）。
⛔ 若把 `10` 直接当 `ArmyIndex` 会落到「第 10 格」= `DarkAngels`（代码注释里已写死这一条）。

**实现要点（为什么这么落）**：

- `DefaultArmyIndex()` 在 `Build()` **之前**算（`Open()` 里 `DeckIndex` 定下来之后）⇒ 首次绘制就是终态。
  原版的顺序是「先 `ConfigureArmyFilterButtons` 建格、后 `ChangeSelectedArmy` 设筛选并刷高亮」，
  ⇒ 原版中间那一帧没有高亮，我们连那一帧都没有。**最终可见状态逐项相同**，差别已写进代码注释。
- `DefaultArmyIndexOf` 做成**纯函数**（阵营名 + 阵营表 → 下标），是为了让「有阵营 → 用它」「空 → `Ultramarines`」
  **两条分支都能自检**：夹具里当前那套卡组**有**阵营，光靠开窗态测不到回落分支。
- `StartPracticeMatch` 那一处对齐**是必需的**：不对齐的话，`PickDeck(ownDeckIndex)` 之后
  「选中的这一副」可能**不在当前筛选的列表里**（面板 / `Battle!` 拿的还是它）= 静默不一致。
  ⚠️ 原版这条链**不经过本窗**（`DeckInfoPopup__StartPracticeMatch.c` 是 `ShowPopUp(等待窗)` + 直接 `StartMatch`），
  我们借本窗当开战宿主 ⇒ 这一步是**我们内部的自洽**，代码注释里已如实标注，⛔ 不假装是原版行为。

## ⑤ 没查清 / 明知没做（如实，⛔ 不猜）

1. **我们的阵营格来源与原版不同**：原版 = `Enum.GetValues(CardArmy)`（**永远 13 个**，与玩家有没有那阵营的卡无关）；
   我们 = `CollectionWindow.CardsState.Factions()`（**卡池里出现过的阵营**）。今天两边都是同样 13 个名字、同样顺序，
   **但若将来卡池缺某个阵营**，我们那列会少一格、`Ultramarines` 也可能不在表里（那时回落到 `-1` 并出声）。
   原版不存在这种状态。**如实记，未改**（改它 = 换整条数据源，属于另一件）。
2. **原版「牌在、督军为空」那一支**：`Open.c:177` 走 `goto LAB_18080e960`（反编译里落到 `FUN_1803f47a0`，
   即异常/提前返回），**不会**调 `ChangeSelectedArmy`。我们回落到 `10` 是**最接近的语义**、不是逐句等价 —— 代码注释与报告都标了。
3. **`ChangeSelectedArmy` 里那句标题本地化的键没查**：`System_String__Format(DAT_18426d0a0, armyId)` → `GetTermTranslation`，
   格式串常量解不出名字。我们这一侧沿用既有 `_facs[i].ToUpperInvariant()`（本轮不动，不在本件范围）。
4. **`SelectItem` / `DeckSelected` 的其它副作用**（`+0x318` 存档、`gameModeText`）不属本件，前一轮报告 §2.3 已论证「原版自己也看不到」。
