## ① 结论

**练习窗的「默认选中 = 玩家自己的卡组（左列第 0 格）」接上了**，两个入口都走同一条判据：

| 入口 | 我们的落点 | 原版对应 |
|---|---|---|
| 开窗 / **切 `Game mode`** | `ResetContent()` → `SelectDefaultDeck()` | `ResetContent` + 随后 `SetArmyButtons` 的 `DeckSelected(item0, …)` |
| **换阵营筛选** | `PickArmy()` → `SelectDefaultDeck()` | `ChangeSelectedArmy` 的**末句** `SetArmyButtons(param_1, param_2)` |

`SelectDefaultDeck()` 的规则（= 原版两条分支，逐句）：

1. **你的卡组那一格存在（阵营相符）⇒ 选它**（原版第 0 项）；
2. 否则 ⇒ **当前模式 + 当前阵营下第一对**（原版 `SelectItem(list[0])`，列表按 `decks` 数组序 = 我们的 `uiOrder`）；
3. 都没有 ⇒ 面板归零并**出声**（原有的空列分支，抽成 `ShowNoDeckSelected(why)`）。

🔴 **同时按原版删掉一条我们自己加的行为**：改前 `ResetContent` 会「保住 `PairIndex`、切模式之后落回**同一对**」。
原版没有这回事 —— `ResetContent` 把 `+0xf8`（`currentButtonSelected`）清空、旧格全 `Destroy`，
`SetArmyButtons` 一律重建并**选 item0**。⇒ 现在切模式后选中态回到「你的卡组」。

🔴 **顺带修掉一处真不一致（换阵营那条）**：改前 `PickArmy` 只 `RebuildDeckRows`、**不改选中态** ⇒
玩家先选了一对 A 阵营的牌、再点 B 阵营，列表里已经没有那一对了，**面板与 `Battle!` 却还拿着它**。
原版 `ChangeSelectedArmy` 末句就是 `SetArmyButtons`（重建 + 默认选中），所以原版不会出现这种态。

**开窗那条路不变**（也不需要改）：`Open()` 写 `DeckIndex = CollectionData.CurrentIndex()` +
`PickedPrebuilt = null` + `PairIndex = -1` 再 `Build()`，其状态与「`DeckSelected(item0)` 跑完之后」逐项相同
（首格亮、面板是你的那套、预组/对都空）⇒ 没有额外再调一次 `PickDeck` 去重复建树。

## ⑤ 没查清 / 明知没做（如实，⛔ 不猜）

1. **`PracticeModePopup__GameModeValueChange.c:16` 那个虚调用槽 `0x178` 是哪个方法 —— 查不到。**

2. **开窗时的阵营筛选默认值 —— 本件未做（独立一件）。**
   原版 `PracticeModePopup__Open.c:172-180`：拿到活动那副牌就 `ChangeSelectedArmy(deck.army)`，拿不到就 `ChangeSelectedArmy(10)`；
   我们 `Open()` 仍是 `ArmyIndex = -1`（本窗自加的「不限」档）。

   6381 / 5840.21 / 「`ArmyIndex = -1` 时一格都不亮」等一整批数字与三条断言，属于另一件；

   已按铁律 5·b / 11 记进本报告的 ⑤ 与台账（**要做，只是排在后面**）。
3. **`SelectItem` 的早返回没复刻**：原版「同格再点 ⇒ `DeckSelected` 首句 `return`」；
   我们的 `PickPair` / `PickDeck` 每次都全量重刷（可见结果相同、只是多一次重建）。如实记，不改。
4. **`Close()` 没有改成调 `ResetContent()`**：原版 `Close.c:7` 第三句是 `ResetContent()`；

5. **`ResetContent` 的 `_e8`（当前阵营）归零那半**：原版 `ResetContent.c:29` 把 `+0xe8 = 0`
