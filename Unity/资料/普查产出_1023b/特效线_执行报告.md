## 一、R1 —— `Hidden/LUTBlender`：自建 shader 的 VS 少一跳（**已修**）

### 1·1 差异（判据 = 反汇编，本件重跑 `工具/dump_lutblender.py`）

原版 `vs_4_0`（`wf_arena_2.bundle` · `Shader pathID = 42`）：

```
dcl_constantbuffer CB0[3], immediateIndexed
mad o0.xy, v1.xyxx, cb0[2].xyxx, cb0[2].zwzz      // ← uv * ST.xy + ST.zw
```

我们改前：`o.uv = v.uv;`（**少了这一跳**）。
文件头原来还写着「原版 vs 就是**直通**（`mad o0.xy, …` —— 无滚动/无缩放）」——
**把那条 `mad` 读成了直通**，是本仓「读指令读错」的又一例。

**为什么一直没被发现**：`BattlePostFx` 是 `Graphics.Blit(null, rt, mat)`，`_MainTex` 未绑定
⇒ 各张 `*_ST` 都是默认 `(1,1,0,0)` ⇒ 两侧逐像素相同。
**只要出现非单位 ST**（源是真实纹理 / 翻转投影通道 / 立体渲染），原版缩放+平移、我们不 → **256×16 的 LUT 被上下颠倒**（16 行 = 3D LUT 的纵轴）。

### 1·2 改了什么

`MyGame/Assets/WarpforgeVFX/Shaders/WFLUTBlender.shader`
1. `CBUFFER` 加 `float4 _LUT1_ST;`
2. `vert()`：`o.uv = v.uv * _LUT1_ST.xy + _LUT1_ST.zw;`（照那条 `mad`）
3. 文件头：订正「原版 vs 直通」那句话（带 2026-10-23 日期、判据、`wf_arena_2.bundle` 这条新路径）

### 1·3 没查清（**不许当结论**）

**`cb0[2]` 到底是哪一张 `_ST`（`_LUT1_ST` / `_LUT2_ST` / 别的），查不到**：
- 内置管线 shader **没有** `SerializedPass.m_CommonParameters`（本件实读 = `None`）；
- `Shader.m_ParsedForm` 也**不序列化** `m_ConstantBuffers`（本件实读属性表只有 8 个字段）。
- ⇒ 取 `_LUT1_ST`（主纹理、原版只读的那一张）。**今天**三张 ST 都是单位值 ⇒ **取哪一张渲染逐像素相同**；
  将来若要接非单位 ST，先用 §八 的 A7 条对一次原件再定。

### 1·4 「改走原件」这件事**仍然开着**

`WarpforgeShaderMap.cs:289-292` 那条理由（「bundle 里的 shader 在编辑器/批处理下渲品红」）
**从来没被核过**（`普查产出_1023/E4_R29分因与R1判据.md` §③-4），而且反证已出现：
`UseOriginal` 里 64 条（含 `Mobile/Particles/*`、`Hidden/Everguild/PlanarReflections*`）全在走 bundle 原件。
⇒ **A/B 之前不改**（没量过就改 = 可能让 `BattlePostFx` 整条后期失效）。已在 `WarpforgeShaderMap.cs` 就地写清。

## 二、R9 —— 屏震 `rawSignal`（Beautify/6D 自定义波形）：**判据全解，未落地**

### 2·1 它是什么（本件新解，判据级）

`CameraShakePresetSO.preset.rawSignal` 是个 **PPtr**（`m_FileID:0` = 同包）。
全 17 个 preset 里 **5 个非空**，但那 5 个只指向 **2 份信号 SO**（所以工作量是 2 不是 5）：

| preset | rawSignal 资产 |
|---|---|
| `Shake Forward Pull` · `Shake Land on ground` · `Shake Upwards Hand` | **`Warpforge 6D Shake One Axis`** |
| `Shake UI Earthquake` · `Shake UI Hit` | **`Warpforge 6D Shake No rotation`** |

来源：`assets_full/bundle_tweenandshakes_assets_all/MonoBehaviour/Shake *.json` 的 `preset.rawSignal.m_PathID`
（`5063336325074814410` / `-9200777822741555375`），资产本体同包（`MonoBehaviour` · `m_Script` 来自 Cinemachine.dll）。
**另有 2 份没被引用**（`Warpforge 6D Shake` = 位置+旋转全开 · `Warpforge 6D Shake One Axis No rotation`）⇒ 收数据时一并收，但**不会被播到**。

### 2·3 我们现在是什么 + 落地要动哪三处

| 处 | 现状 | 归属 |

而 `Request` 的**唯一消费端** `CardFeel.ShakeCamera` 不在白名单 ⇒ 只加字段 = **加一份没人读的死数据**。
