## 一、原版卡面上的图标（照成品卡图 + 解包资源核过）

**总则**：图标全部**嵌在正文句流里**，不是独立一行；**关键词类一律「图标 + 紧跟英文词」**
（`【翼】Flying.`）；只有 **数值 / 资源类**图标后面没有词（`+2`【拳】、`Give -2`【枪】）。
图标直径 ≈ 40 px（卡宽 900 的 4–5%）。

| 类 | 例 |
|---|---|
| **近战数值**（粉拳圆徽） | `… gains +1`【拳】` and …` |
| **远程数值**（紫枪圆徽） | `Give +1`【拳】`, +1`【枪】` and +1 Health…` |
| **行首付费/资源前缀** | `1`【绿圈1 = 灵魂石】`: Gain Shuriken 2 this turn`（灵族）· `8`【金太阳 = 信仰】`: Deploy an additional Battle Sister`（修女会）· `⑤`【灵魂石 5 档】 |
| **关键词前缀** | `【盾】Armour 1.` · `【闪电】Rally:` · `【骷髅】Backlash:` · `【卡】Talent:` · `【齿轮】Artifice:` · `【碎卡】Ephemeral` … |
| **触发前缀** | `⚡ Rally:`（= rally 图标）· `💀 Backlash:`（= backlash 图标） |
| **阵营资源** | 暗黑天使任务点（`gain`【带数字的徽章】）· 灵魂石 · 信仰 |

**⚠️ 四件容易想当然、实际不是的：**

1. **原版没有「关键词单独一行徽标」这回事**（卡面上）—— 关键词就是正文里的「图标 + 英文词」。
   **但棋盘上的单位卡有**：`BattleCardUI.boardTraitIcons`，左 3 + 右 4 共 **7 个 `TraitIconContainer`**
   （每个 = `TraitIcon` + `Trait Icon Background` 底板，组件 `BoardTraitIcon` 带
   `traitIcons[2]` / `traitNotActiveIcons[2]` / `counterText`）—— 这就是「buff/debuff 图标」。
2. **阵营行 / 兵种行是橙字纯文本，没有图标**。
3. **`+N Health` 永远是文字，没有生命图标**；护甲写裸词 `Armour N`（**可以有银盾图标前缀** ——
   2026-09-15 三张卡面实测：`Bladeguard Ancient` / `Hardwired Destruction` / `Unforgiven Redemptor` 都带盾）。
4. 🔴 **方括号 token 的名字是 OCR 猜的，换张卡就换意思** —— 见下面「坑」。

### 二之二·补、新增：卡面「关键词前缀」图标（2026-09-15）

卡面上**每个关键词都印成「图标 + 紧跟那个词」**（`【翼】Flying.`、`【闪电】Rally:`），
而 `desc` 是**卡图 OCR** 的 —— 这些图标**基本没被记下来**（只有极少数留下了 `⚡`/`💀` 字符）。
改之前计划表只覆盖 `[方括号]` 记号，**卡面上这一大批位置全画不出来**（`DA8` 只剩 1 枚图标、
`DA16 Librarian` 一枚都没有，就是这个问题）。

**做法**：`工具/gen_icon_plan.py` 里加了 `KEYWORD_PREFIX` 规则 —— 句首位置的「关键词 [+ 数字] + `:`/`.`」
按**名字**查图（图集文件名就是关键词名；中文走 `_规则书关键词表.md` 那 61 条中英对照）。

- 覆盖 **1043 处**（`desc` 526 + `descZh` 484 量级），涉及 **560 张卡**
- 例外：`Destroyer` → `frenzied`（图集里没有 `destroyer.png`）；`Penitence` → 如实报缺口（图上真没有）
- **逐张在真卡面上核过 19 个关键词**：`Codex` `Armour` `Regiment` `Duty` `Ephemeral` `Waystone`
  `Flank` `Rally` `Blast` `Destroyer` `Stealth` `Strike` `Flying` `Vanguard` `Shield` `Talent`
  `Agenda` `Remnant` + `Oath`
- ⚠️ **只认句首位置**。卡面**句中**的关键词**有时也带图标**（`Baneblade Tank` 的第二个 `Armour 1`、
  `Lead by Example` 的 `Duty ability`、`Attilan Rough Rider` 的 `Blood Thirst`、
  `Vitus Gryf` 的 `with 〔翼〕Flying have`）—— 但那要先判断「这个词是当关键词用、还是当普通名词/动词用」
  （`Stun an enemy` / `Choose a Sabotage card` / 写成词的 `Ranged Attack` **都不带**）。
  **判不了就不画**：宁可少画，不给错图标（工程红线）。

## 二之三、下一步：「画上去」要动哪几处（2026-09-15 量过）

素材、sprite asset、计划表、`CardIcons.Rewrite` 都就位了，**只差接进渲染**。改动点（已量）：

1. `BattleDriver.FaceText()`（`BattleDriver.cs:2474`）—— 现在直接返回 `DescZh`/`Desc`，
   要过一道 `CardIcons.Rewrite(c.Id, field, body)`（`field` 按用的是哪个字段传 `"descZh"`/`"desc"`）。
2. **TMP 那边要挂 sprite asset**：`CardView.Fill()`（`CardView.cs:610-624`，建 TMP 文字的唯一一处）
   里给 `t.spriteAsset` 赋 `CardIcons.SpriteAsset`，否则 `<sprite name=…>` 会当字面量印出来。
3. ⚠️ **无 TMP 字体的回退路径**（`CardView.cs:1457-1460`，自写 5×7 点阵字库）画不了 sprite ——
   那条路上带着 `<sprite>` 标签会很难看，**要一起处理**（回退前把标签剥掉，或那条路不 Rewrite）。
4. `CardDisplayWindow`（`CardDisplayWindow.cs:108` 用 `d.keywords`）跟着走同一条数据，验证时带上。
5. 改完按工程规矩复跑：`BattleScene.Run` / `DeckScene.Run` / **`CardBaseDemo.Run`（四档分辨率，改版面必跑）**
   + 人眼看 `CardFaceProbe` 的单卡渲染。


## 三、坑（都是踩过的，别重踩）

1. 🔴 **token 名不可信，必须逐卡定**（2026-09-15）。同一个 `[Attack]`：
   `DA44 Ancient Reliquary` 上是【拳】（近战），`EC8 Alluress` 上是【枪】（远程）；
   `EC17 Sonic Blaster Noise Marine` 里 `[armor]` 是【拳】、`[attack]` 是【枪】——
   **和「DA44/AM50 那一族」正好相反**。`[Health]` `[Might]` `[Power]` `[weapon]` `[Strength]`
   这些名字**实测画的全是拳或枪**。⇒ 判据是 `数据/游戏数据/card_icon_plan.json`（按卡），
   **不是**一张全局表。
2. 🔴 **`N [Spirit Stone]` 的数字烘在图里** —— `Atlas_SpiritStone_1..5` 就是「绿圈里写 1..5」。
   画的时候要把文本里那个 `N ` 一起吃掉，别再画一次数字。
   （这条也把一桩**悬案**结了：行首那个绿数字圆 = **灵魂石档位**，
   `资料/关键词图标/关键词与图标_对照表.md:66` 说的「本行能量费用」**是错的**。）
3. ⚠️ **`☀` 是信仰、不是能量**（修女会 7 张卡面核过）；`[Energy]` `[Icon]` `[icon]` `[Faith Icon]`
   四个名字在卡面上**画的是同一张金太阳**。
4. ⚠️ **五张 `markOf*` 切片逐字节相同**（混沌五神印记认不出是哪位），`relentless` 与 `resolution`
   只差 1 像素。**认不出就如实说**，别按名字猜。
5. ⚠️ **徽标/图标的大小要先标定**：原版 sprite asset 的 `m_FaceInfo` 是 0，TMP 会**退回按字体**
   算缩放（`TMP_Text.cs:4154-4166`），而我们的字体与原版不同 ⇒ 大小会跟原版不一样。
   法子写在对照文档第八节。
