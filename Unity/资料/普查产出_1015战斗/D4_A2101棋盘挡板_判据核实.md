# D4 · `A2101`「棋盘挡板」判据核实 —— **结论：账的机制描述与本 build 不符**（2026-10-15 · 只读）

> 触发 = 交接 §二 第 4 件：「`A2101` 棋盘挡板（原版拖到边界被物理挡住）—— ⚠️ **先核坐标系映射再动**」。
> 甲方 = `assets_full/bundle_scenes_scenes_battlearena{1,2}`（13 张战场逐包 grep）+ `d:/2/tools/decomp_full/` + `d:/2/unity_run_ref/GameAssembly.dll` 字节扫描。

## 结论（3 行以内）

1. 13 张战场场景里**一共只有 1 块带 collider 的「挡板」**：`CardLowBoardLimit`（BoxCollider · layer 11 = `BoardCardLimit`）+ 空父 `CardBoardLimits`；另有 `HandLimitArea`（layer 5 = UI，**只有 Transform、无 collider**）。**不存在**「上/下/左/右四条挡板」。
2. 🔴 **它不是「边界」，是整块板底下的一块超大底板**（footprint 远大于可玩区）；而且在本 build 里**没有任何代码读它** —— 唯一读它的两个函数（`BattleManager.GetBoardCardMousePos` / `GetBoardCardPosFrom2DPos`）**自己也是 0 调用点**（用 4 种方式扫了两份 `GameAssembly.dll`）⇒ 「拖牌被物理挡住」这条**不成立**。
3. ⇒ **不能照账里那样动手**（照抄那 4 个参数 = 加一块惰性 collider，对我们零行为）；「坐标系映射」**没核清**（差「运行时相机矩阵」+「哪条路径真的调它」两条判据）。账 `A2101` 的机制描述与本 build 不符，**建议先改账再动手**。

## 坐标系映射

**没核清** —— 给不出可信公式。已查实的是「为什么给不出」，逐条：

1. **原版那一侧的实现本身是死的**：`GetBoardCardPosFrom2DPos(world2DPos)` = `hudCamera(+0xa0).WorldToScreenPoint` → **`boardCamera(+0xa8)` `ScreenPointToRay`** → `Physics.Raycast(mask = LayerMask.GetMask("BoardCardLimit"))` → 返回命中点；`GetBoardCardMousePos(yOffset)` 同法。出处：`BattleManager__GetBoardCardPosFrom2DPos.c:76-85` · `BattleManager__GetBoardCardMousePos.c:90-99`；mask 字符串解出：`DAT_184294bb8` = `all_strings.txt` 首列 **69815224 (=0x4294bb8)** = **"BoardCardLimit"**（另一份 `GetBoardMousePos.c:83-92` 用的是 `DAT_184272698` = "Default"）。
2. 🔴 **这两个函数在本 build 里 0 调用点**：① 反编译全量 grep（`decomp_full` 25096 个 `.c`）除定义外 0 命中；② 字节扫描 `GameAssembly.dll`（`d:/2/10.13游戏/` 与 `d:/2/unity_run_ref/` 两份，76,765,184 字节同 build）：`E8 rel32` 直接调用 **0** · `E9` 尾调用 **0** · `FF15` 间接调用槽 **0** · 8 字节函数指针**只在 Il2Cpp 方法注册表各 1 处**。**对照组**：`GetMousePosInWorldSpaceCanvas`（已知 5 个调用点）同法扫出 **5/5 命中** ⇒ 扫描法有效。
3. ⚠️ 而且这条路**几何上也不闭合**：`Board/ArenaSlots.cs:139-147`（我们自己已查实）写「BoardCamera 朝向是**单位四元数（没有俯仰）**，射线是水平的、`ray.direction.y == 0`、**永远打不到地面**」⇒ 一块顶面在 `y=−0.1754` 的水平板，水平射线永远打不到 ⇒ 即使被调用也拿不到「板面点」。
4. **两侧唯一的桥是屏幕坐标**：我们拖拽 = `LayoutSpace.ScreenToWorld`（`Core/LayoutSpace.cs:121-136`，正交、可见高恒 10 世界单位、屏幕中心 = 原点、1 px = 1/108 世界单位）；原版 = **透视**（boardCamera `FOV 46.397` / `sensor (41.5,24)` / `lensShift (0,−0.205)`，B4 §1.1）⇒ 原版世界 z → 屏幕 y 是 **1/深度**的射影关系（**不是仿射**，没有恒定 px/单位）。
5. **已知锚点（任何实现都必须对得上，可当靶）**：原版实测 **我方行卡心 = 636 px（58.90% 距顶）** · **敌方行卡心 = 425 px（39.37%）**（`资料/3DBody_原版场上卡体规格.md:286-287`）。我们这边对应的 `y01 = 1−636/1080 = 0.4111` / `1−425/1080 = 0.6065`。
6. **差什么、去哪拿**：① 运行时读一次 boardCamera 的 `worldToCameraMatrix` / `projectionMatrix`，或直接把 box 的 8 个角 `WorldToScreenPoint`（一次 print 即可）—— ⚠️ 这需要**违反当前「只做不验」口径跑一次**，得用户批；② 确认**哪一版/哪条路径**真的调用那两个函数（拿法：对 `dump.cs` 里 `GetBoardCardPosFrom2DPos = RVA 0x965430` 做 xref，`d:/2/tools/ghidra_proj` 里已有导入工程）。在此之前**不许猜**。

## 能不能动手

**不能照账那样动手。** 三条理由，各自有出处：

- 账里「拖牌到边界会被物理挡住」**无判据**（上面 §坐标系映射 2、3）—— **原版这一版没有代码读它**，照抄 4 个参数得到的是惰性件。
- 我们**全线不用物理**：`CardPresentation/` 里 **0 处 `Physics.Raycast`** / **0 处 layer 11** / **0 个挡板 collider**（grep 只命中 prefab 的 `m_RenderingLayerMask`）⇒ 加 3D BoxCollider 对我们的 2D 正交拖拽**不产生任何互动**。
- 即便它真是「边界」，它的几何也**不是边界**（footprint 是可玩区的 5×12 倍）。

能做的两条（都要按**铁律 3** 明标「**这是我们挑的，不是原版的做法**」）：

- **(A) 只想要手感**：在 `Hand/CardInteraction.cs` 的 `var target = world + _grabOffset …`（现**无钳制**）与 `PointerWorldSafe` 的野值守卫之间加一道 **LayoutSpace 内的归一化矩形钳制**，边界取我们自己的棋盘几何（`BoardLayout.lineY` / `BattleScene.cs:121-122` 的 `PlayerLineY`/`EnemyLineY` + 半间距）。
- **(B) 真要资产对齐**：复刻 `CardLowBoardLimit`（4 个参数已抄全，见上表）—— 但先说清**它对行为零影响**，只是「资产表上补齐」。

**还差哪条判据 → 去哪拿**：① 一条「原版确实靠它挡」的调用点（DLL xref，或换更早 build 的 DLL 重扫）；② 运行时相机矩阵（跑一次采样）。**两条都拿不到 ⇒ 本件应当暂缓，只把「原版有这块件、我们完全没有」当记录留在账上。**

## 顺手发现（⛔ 未改，报给主对话）

1. ⚠️ **「我们的棋盘两行用的是旧校准」这一条【本工程已经立过账】** —— 代理报的「低 72 px / 41 px」与 `A2104` ① ② 记的**同一件事**：
   `A2104`② 写着「我们 2D 行心 372 px 与 3D 实测行位（**58.9% = 636 px**）差 **264 px**」，① 写着「`BoardLayout.lineY`(我方) = 0.3444 = 372 px，**差 72 px** —— ⛔ **别就此直接改 0.3444**：`lineY` 同时是 2D 棋盘行心 ⇒ **正解是把两个用途拆开**」。
   ⇒ **本轮新增的只有「敌方那一行差 41 px」这一个数**，**不是新账**（铁律 6：清单只留一处）—— 已并入 `A2104`。
   ⚠️ **实据复核**（主对话 2026-10-15 亲读）：`Editor/BattleScene.cs:121-122` 至今写死
   `EnemyLineY = 0.5685f（原版 466/1080）` / `PlayerLineY = 0.3444f（原版 708/1080）`；
   而 `ArenaSlots.cs:31-40` 与 `3DBody_原版场上卡体规格.md:286-294` **都写明** 708/466 是 `battle.gd` 旧校准、实测真值 **636/425 px**。**两侧并存属实**。
2. 原版挡板上的 `MeshRenderer` 是 **`m_Enabled: false` + 空材质**（arena1/arena2 都是）—— B4 §2.1 只记了「有 MeshRenderer/MeshFilter」，**没记它不显示**；⛔ 别推论「游戏里看得见那块板」。
3. 原版**相机上的 `PhysicsRaycaster`（B4 §1.2 记的 MB 4923）`m_EventMask = 1024`** = 只有 layer 10 `BoardElements` ⇒ 连物理 raycaster 也**不看**那块挡板（layer 11）。同一法：`BattleManager__GetTargetInPos.c:239-247` 的 3D 兜底是 `LayerMask.NameToLayer("BoardElements")` → `1 << 10`。
4. **`d:/2/Warpforge_code/Scripts/Assembly-CSharp/*.cs` 是【stub】**（方法体全 `return default`）—— 只有**签名/类结构**可用，**判据（值/逻辑）一律不能从这里取**。
5. 🔧 **工具发现（已落进 `资料/命令速查.md`）**：`d:/2/tools/all_strings.txt` 的**十进制首列 = 反编译里 `DAT_18xxxxxxx − 0x180000000`**。对照组两例：`DAT_184294bb8` → 69815224 → **"BoardCardLimit"**；`DAT_184272698` → 69674648 → **"Default"**。⇒ 凡 `LayerMask.GetMask(<DAT>)` / `System_String__Equals(<DAT>)` 都能**直接解码出字符串**，不用猜。
6. ⚠️ 反编译里 `GameStaticData.GetLayerId` 认的那批名字（`Settings/Hand/Background/Elements/OverHand/Blocking/HandMoving/OverElements/Default`）是 **Sorting Layer** 名、**不是物理层**名（与 `TagManager_3.json` 的 `m_SortingLayers` 逐字相同）—— 而 `"Default"` 这个**字符串字面量在两种用途间被 il2cpp 去重共用** ⇒ 读反编译时别把「Default」一律当物理层。
