## 六、顺手发现

1. 🔴 **`2D层_battlearena1全树.md` 的 `BattleSettingsPanel` 子树不完整**（`资料/说明书/01_战斗_对战/2D层_battlearena1全树.md:673-725`）：它**漏了整行 `Match Skulls`**（arena1 里 `Match Skulls.json`/`Match Skulls_929.json` 都在）、**也漏了 `Debug Buttons/Buttons container` 的第 4 颗 `Toggle Parrticles`**（arena2 现读：`Toggle Parrticles < Buttons container < Debug Buttons`，`m_IsActive=True`）。
   ⇒ 那份文件标题写着「**全树**」，实际**有节点被丢掉** ⇒ 下游任何以它为「全树」的核对都会漏件。**本文件一律以 arena2 的原始 JSON 为准**。
2. 🔴 **`Match Skulls` 是两层同名节点**：外层（RT_3029，`m_IsActive=False`，743.2×148.764）**装着**内层（RT_3160，`=True`，686.8×75.212）与 `Match Skulls Text`（`=True`）。
   ⇒ 只读「内层是 True」会误判「这行亮着」；只读 B2 那一行会不知道里面有第二层。**判显隐一律看外层**。
3. 🔴 **同族两处 `Dark Shade` 的尺寸不一样**：`BattleSettingsPanel/Dark Shade` = **3963.53×2692.97**（B2 §1.8）· `WaitText/Dark Shade` = **3963.5×3366**（`WaitBanner.cs:6` 的实况 dump）。两个都叫「铺满」，**高差了 673**。别互相抄。
4. 🔴 **`BattleDoors` 那一支的 scale 1.0665 会顺着父链压到整块结算面板**（含视频、骷髅、奖励）；我们这一族的**每一件**都要么乘进去、要么显式声明不复刻。今天只有 `BattleDoors.cs:153-160` 声明过（且只声明了「我这一层不渲染」）。
5. 🔴 **`Alliance Panel` 与 `Unit Chat/ChatPopup` 的 `BGFrame` 共用同一组四张 `40k_UnitChat_Background_Top/Bottom/Right/Left`**（B2 §六·3）—— 两处若各导入一份会重复；我们的 `Shell/AlliancePanelWindow.cs` 与 `Battle/ChatPopupPanel.cs` 是各写各的取图，**没收口到一处**。
6. ⚠️ **`EndPanel` 的注释与代码自相矛盾**（不是原版问题，改到自己头上了）：`EndPanel.cs:215` 写「标题/副标题/骷髅**统一挪到 y ≥ 730**」，而 `:216` 建标题在 `Content(960f, **260f**)`（= 贴屏幕**上方**）；副标题 730、骷髅 790 才是照那句注释。⇒ 二者必有一错。**可见影响小**（有视频时标题本来就 `SetTitleVisible(false)`），但**口径要裁一个**，否则下一个人会照注释去改另外两件。
7. ✅ **重名陷阱在本族**有一处实测（`Sound effects Slider` ×2）；而**我们没踩** —— 三根滑块是**按构造建**、不按名查。同类陷阱下次要是出现在「按名查」的代码里（`transform.Find` 只找直接子件、同名兄弟只回第一个），要按父节点取。
