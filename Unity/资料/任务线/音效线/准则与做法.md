# 音效线 · 准则与做法

> **入口** = 同目录 `任务总表.md`（只看【未完成】）。
> ⛔ 本文件不抄 `CLAUDE.md` 的铁律，只写本线特有的。

## 一、这条线是什么
壳侧 / UI 音效：**窗的开/关音** · **按钮/开关的点按音** · **弹窗/开包窗的事件音** · **音量组（FX / Jingles）**。
边界：**战斗音响 = 战斗线 T06**（已无余账、待真机验收）· **语音 = 战斗线 T18**（本线不收）。

## 二、判据从哪来（按权威顺序）
| 想知道什么 | 去哪 |
|---|---|
| 原版某个窗/按钮该不该响、响哪条 cue | prefab 的 `openSound` / `closeSound` / `useDefaultCloseSoundIfNull` / `m_onClickSound`（`d:/2/新解包资源/assets_full/bundle_*` 的 `MonoBehaviour/`），**字段值直接喂 PPtr** |
| PPtr → cue → clip 的名字 | `m_FileID` 是 **1-based**：`externals[m_FileID − 1]` 指向所在 CAB；**cue 是包装**（`SoundAssetCollection`），**不要**只在 `AudioClip/` 目录按 pid 找（那是 2026-10-17 之前「名字没解出」的错因） |
| 播放在哪个 mixer 组 | 反编译 `SoundManager.Play2D(..., MixerType)`：`FX` / `Jingles`（开包窗的稀有度声与拆包声是 **Jingles**） |
| 我们的播放口 | `Core/WarpforgeAudio.cs`（三根滑块 → mixer）· `WFSoundPlayer`（写死 FX）· `Shell/WindowSounds.cs`（壳侧唯一 cue 表） |
| 音频素材 | `d:/2/新解包资源/assets_full/bundle_soundcollection_assets_all/AudioClip/`（按 clip 名存裸音频）→ 由 `工具/import_original_sfx.py` 的 `EXTRA_CUES` 导进 `Resources/animfx_sounds.json` |

## 三、动手流程
1. 先在 prefab 里读**字段值**（别凭「应该会响」）。
2. 逐条把 PPtr 解到 **cue 名 → clip 名**，写进代码注释（带 MB pid / externals 下标）。
3. 接进现成播放口（⛔ 不新写第二套）；缺 cue ⇒ **只警告一次**，不静默。
4. 改 `.cs` 后立刻 `bash d:/4/Unity/工具/typecheck.sh`（0 错）。
5. **不跑自检、不起 player**（现行口径：复刻完成再统一验收）。

## 四、已知的坑
1. 🔴 **`m_FileID` 是 1-based，且它指的是 cue 包装、不是 clip** —— 只在 `AudioClip/` 里按 pid 找会得出「名字没解出」的假结论（2026-10-17 已订正 U1/U3）。
2. **`useDefaultCloseSoundIfNull = 0` 的窗要显式关**（`Collection Menu Variant` / `Shop Menu Variant` 就是）—— 否则会多一声。
3. **`WFSoundPlayer` 写死 FX 组** ⇒ Jingles 要走 `WarpforgeAudio.PlayJingle`（别复用）。
4. **压暗层/吸收层不是按钮**（原版 `BackgroundCloseButton` 是纯 MonoBehaviour）⇒ `WindowButton.Click` 的默认音要按 `MenuDraw.WasShadeHit` 之类显式跳过。
