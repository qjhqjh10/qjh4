### 2·1 `A1480` + `A1491` —— 「player 里点不动」的**两条根因**（**都不是界面缺陷**）
- **根因① = 没从壳启动**：`Shell.unity` **自带** `WindowsManager`（GUID 命中 1 次），`MainMenu.unity` **两样都没有**
  （`WindowsManager` 0 次 · `PointerLayer` 0 次）；而且非 Editor 侧的全部 `EnsureHost` 调用点里，
  `Shell/MainMenuRuntime.cs:909` 那一处在 `OpenBattleLogPopup()` **内**、**不在启动链上**
  ⇒ **单独 `-wfscene MainMenu` 时没有任何人建指针层**（判据 → `Shell/PointerLayer.cs:1-13` 文件头自陈
  「**全壳唯一一条『真鼠标 → 界面』的路径**」＋「**自检一直全绿，是因为它们走 `ClickForTest()` 直调 action**」）。
- **根因② = 两个缺陷叠加**（`A1491`，**都只在 Play 里发作**）：
  · **窗口层被自己的拆除循环拆了**：`WindowsManager` 是 `ShellRuntime` 的**子节点** ⇒ Play 里 `Awake` 先跑、`Instance = this`；
    随后 `Build()` 第一件事是拆除循环 `DestroySafe(root.GetChild(i))`，而 Play 里 `DestroySafe` 走 **`Destroy`（帧末才生效）**；
    同一函数**后面**才调 `WindowsManager.EnsureHost(root)`，而它判据是 `if (Instance != null) return Instance;`
    ⇒ **返回那台待死的、不建新的、也不打日志**；帧末销毁、`OnDestroy` 把 `Instance` 置 null ⇒ **之后没人再 `EnsureHost`**。
    **日志证据**：`FX_Shell.log` 里 **`[Win]` 一行都没有**（尤其没有那句「场景里没有 `WindowsManager` ⇒ 现建了一台」）。
  · **指针层是「无父的场景根件」**：`PointerLayer.Ensure` 里那句 `SetParent(root)` **是死代码**
    （`Instance` getter 自己先惰性现建了一台**无父**的，第一句 `return` 就把它带走了）⇒ 它落在**壳场景**里 ⇒
    切主菜单是**单场景加载**（`LoadMainMenu` 的 `SceneManager.LoadScene`）⇒ 壳场景卸载时它被销毁、`OnDisable` 清 `_inst`。
- ✅ **已修两处**（2026-10-10 · 各 2~3 行 · typecheck 0/0）：① `ShellRuntime.Build()` 的拆除循环**跳过窗口层**；
  ② 指针层那一支。
- ✅ **2026-10-17 现核（铁律 5）**：`A1491🅑` **已落地** —— `Shell/MainMenuRuntime.cs` 的 `OpenMode` 已改走
  统一读口 `WindowsManager.Get()`（注释原文：「原来直接读 `Instance` ⇒ 切场景后它是 null ⇒ 模式卡点不动」）。
  其余生产侧 `WindowsManager.Instance` 读点逐个人工核过：**全是存在性判断**（`if (Instance != null) ShowPopUp…`）
  或**编辑期特例**（`RegisterMainMenuWindow` 明写「⛔ 别在这儿用 `Get()`」，理由 = 会把三样物体建进场景）。
  ⇒ 本条**不再开着**；剩下的只有真机复核（现行口径不做）。
  原文（留痕）：「⏭ **仍开着**（`A1491🅑`）：**窗口开不出来** —— `onClick` 派发了但弹
  `[Warning] [Menu] 没有 WindowsManager，开不了模式窗：draft`（**33 次**），而 `[Win]` 日志 **0 行**。」
- `A1480` **另带四条观感**（用户说「界面混乱、不成正式的界面」）：① 右上角两行绿字 `Player Name: Message`（**占位文字 ×2**，

### 2·2 `A1494` —— 「点哪儿都命中中间那张卡」
- **根因① = 坐标换算退化**：`Cam` 是**场景根件**（**不在** `Shell` 的 `DontDestroyOnLoad` 层级里 —— `ShellRuntime.Awake` 只 DDOL 了 `Shell` 自己）
  ⇒ 切主菜单（单场景加载）时相机被销毁 ⇒ `Cam` 指向**已销毁**的相机 ⇒ 原代码 `if (cam == null) return Vector3.zero`
  ⇒ **每一次换算都退化成世界原点** ⇒ `PixelOfDesign(0,0)` 恒等于画布正中 **(960,540)** ⇒ **命中永远落在屏幕正中那一件上**。
  **实据**：同一次运行里 `00:20:28 场景 Shell 屏幕(1139,241)→画布(854.3,899.3)` **正确**，
  `00:20:29 场景 MainMenu 屏幕(1139,240)→画布(960.0,540.0)` **退化**。
  🔑 **而这条坑本仓早就记着**（`资料/已知的坑.md`：「`LayoutSpace.Cam` 是静态字段…场景里要有个 `Start()` 重新 `Apply(cam)`」）⇒ **踩过、记过、又踩了一次**。
  **修法**：`MainMenuRuntime.Build()` 补 `LayoutSpace.Apply(Camera.main)`；`LayoutSpace.ScreenToWorld` 的空相机兜底**回落 `Camera.main`** 并把 `Cam` 修回。
- **根因② = 读口不统一**（不是「建不出来」）—— 见 §2·1。
- **④ 顺带**：场景里**不该有** `placement=None` 的 Holder（**是我们自己 `MakeHolder` 的构造噪音，不是场景坏了**）；
  且 **`AudioListener` 随那台场景根相机一起被销毁** ⇒ 切主菜单后**全场没有 `AudioListener` ⇒ 音乐/UI 音效静音**
  （全仓只有 `Shell.unity` 有这一颗，主菜单那场景只建相机、不挂它）。
