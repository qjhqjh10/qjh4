## 三、干一件活的流程（**六步**）

```
① 读「本任务文件」（或总表那一行的「索引」）→ 判据与出处都在里面
② 判据不够 ⇒ 先补判据（派只读子代理去勘 / 用 menu_dump.py 现读），⛔ 别凭印象动手
③ 动手改（.cs）→ 立刻跑 `bash d:/4/Unity/工具/typecheck.sh`（**秒级，唯一挡「编不过」的**）
④ 落盘：把「查出的事实 / 坑 / 判据」写进该去的地方（见 §五）
⑤ 收工：按 `任务线/README.md` §五 那四步改总表
⑥ ⛔ 不跑自检、不起 player（见 §四）
```

**六条本线的硬规矩**：

1. 🔴 **别拿「一个值」当「全部情况」**（铁律 5·c；本线的头号病根）——
   同一个原版组件**有多套配置**：**卡池 6 列 vs 筛选战将 4 列**（`A1488⑥` 自己引的先例）·
   收藏窗 RSR 列数**三家不一致**（`A1509①`）· `Scroll View` 在两个窗里**参数不同**（`A1510` 那批）。
   ⇒ 读到「原版值」先问：**这是哪种情况下的值？一共几种？谁在运行时改它？**
2. 🔴 **框 ≠ `m_SizeDelta`**（`A1226`）—— 66 处里**只有 8 处 `sd` 就是框**；**28 处是伸锚偏移** ·
   **24 处被布局组/`ContentSizeFitter` 撑** · **6 处是模板位**。
   **正解 = 比「原版有效框」＝ 父宽 × 锚跨度 ＋ `sd`**。
3. 🔴 **分层靠渲染队列、⛔ 不靠 z**（本线踩过：侧栏底板把整个卡组列表盖住，z 明明是对的）——
   而「新加一层」还要单独问**「这一层什么时候关」**（筛选栏底板建了却没跟开关隐藏 ⇒ 一直盖着侧栏）。
4. 🔴 **命中区 = 可射线件的【并集】＋ 各自 `m_RaycastPadding`（负值 = 外扩）** ——
   ⛔ **不是** `m_TargetGraphic` 那一处（已有三个反例）。先例：`Editor/CollectionScene.cs` 的 `A180/A299`。
5. 🔴 **改 `.cs` 必须跑类型检查**（它是「攒批不跑自检」这条规矩下**唯一不能省**的一步）。
6. 🔴 **自检口 `UiClickPx` 覆盖不到卡池/卡组行/卡背**（`A1495` 查出的**结构性盲区**）——
   ⇒ **凡「点不动 / 炸异常」那一族的账，⛔ 别指望自检抓得到**；要验只能真机，或者**先补自检口**。

## 四、验收口径（**现行：只做不验**）

🔴 **用户 2026-10-15 第八次收口**：「**之后暂时别检查，先完全复刻，复刻好了再检查**」。
⛔ **不跑 `*.Run` 自检**（一条都不跑）· ⛔ **连「起 player 截图看界面」也停**。
✅ **只留两件**：**秒级类型检查**（`bash d:/4/Unity/工具/typecheck.sh`，几秒，不算检查）·
**「原版 vs 我们」的缺口普查**（那是复刻的**输入**，不是验收）。
🔑 **判别句**：**这件事是在「找出还没复刻的」，还是在「验证我刚改的对不对」？** 前者做，后者停。
🕐 **什么时候才验**：**复刻完成之后**统一验收（进游戏 → 截图 → 用 `工具/wf_click.py` 真点）。
⚠️ **真机三条附注**（真要验的时候用得上）：
· **截图必须等停稳**（面板开出来那一帧要跑 ≈15 秒，`A1750`）—— 早拍拍到的是冻住的那一帧；
· `wf_click.py` **必须关沙箱**，坐标 = 屏幕像素 1:1，**先 `shot` 再 `click`**、点前先 `win` 置前；
· **`wf_click.py` 没有滚轮口**（`A1712`）⇒ 「滚一格」那一步工具做不到。

## 五、形成文件说明（**任务文件怎么写**）

### 5·1 一件活一个文件，文件名 `T<两位序号>_<短名>.md`
**必须有的六节**（⛔ 别写成散文）：
```markdown
# T0N · <一句话说清这件活>
> 状态 / 起于哪一版 / 关联 A 编号

## 一、要做什么（**能一句话说清「做完之后画面/操作有什么不同」**）
## 二、判据（**逐条带出处**：资产路径 / `文件:行号` / 类名+方法名）
## 三、我们现状（现状**逐处**给 `文件:行号`）
## 四、怎么改（**改哪个文件、改什么**；分几步；先做哪步）
## 五、做完了怎么自检（**照当时的验收口径**：现在是「只跑类型检查」，将来是「进游戏点」）
## 六、还差什么 / 判不准的（⛔ **不许猜**，写「没查到 + 我搜过哪些词/哪些包」）
```

### 5·2 什么写进**任务文件**、什么**不**写
| 写进任务文件 | ⛔ 不写 |
|---|---|
| 判据（带出处） | `CLAUDE.md` 已有的铁律（**抄一遍就会过期**） |
| 我们现状 + 行号 | 别的任务已写过的东西（**给指针**） |
| 改动清单 | 大段反序列化 JSON / 反编译原文（**给资产路径 + `文件:行号`**） |
| 「还差什么」 | 已经做完的过程叙述 |

### 5·3 详情**超过 ~150 行**就再拆
判据原文太长 ⇒ 搬进 `资料/待办判据_*.md`（**编号同一套**），任务文件只留「一句话 + 指针」。
📌 **本版只给总表【前 5 件】写了详情文件**（T01–T05），其余 5 件在总表右列**只给判据出处**、标 `⏳ 待写`
（⚠️ **别硬凑** —— 判据还没收齐的件，等它真开工时再建详情文件）。

### 5·4 收工后的归档
按 `任务线/README.md` §五。**已完成的详情文件搬进 `资料/历史/已收口_界面线_<日期>.md`**（原文一字不改）。

## 六、本线已知的坑（**继续加，⛔ 别删**）

1. 🔴 **`任务_卡组卡牌战斗.md` §一 的表格【行里没有「状态」那一格】** ——
   表头是 4 列（编号 / 一句话 / 状态 / 判据·详情），而实读 **47–50 行有 4 格、51–189 行只有 2 格**
   ⇒ **GFM 渲染成 2 列**，**「状态」整列丢失**（同族的缺列在这一族里**累计约 354 行**）。
   ⇒ **抄状态时⛔ 别以为「没有状态列 = 没状态」**：要**回判据件（`资料/待办判据_*.md`）或按行内文字判**；
   **行内写 `✅ 已修` = 主件已改完、但这条账【还开着】**（`任务_卡组卡牌战斗.md:19` 自己的读法）。
2. 🔴 **`LayoutSpace.Cam` 是静态字段** —— 场景里要有人 `Start()` 重新 `Apply(cam)`；切场景（单场景加载）
   会把相机销毁 ⇒ **每一次坐标换算都退化成世界原点** ⇒ **「点哪儿都命中屏幕正中那一件」**。
   ⚠️ **这条本仓早就记着（`资料/已知的坑.md`）、踩过、记过、又踩了一次**（`A1494①`）。
3. 🔴 **`PointerLayer` 是「无父的场景根件」，切场景就随壳场景一起没了** ⇒ **真鼠标 → 界面**唯一那条路径断掉。
   ⚠️ 它连带解释了「**自检一直全绿**」：自检走 `ClickForTest()` **直调 action**，不过指针层（`A1480②`、`A1491②`）。
4. 🔴 **`WindowsManager.Instance` **读口不统一**（有的走 `Instance`、有的走 `EnsureHost()`）⇒
   「窗口开不出来」的**根因不是建不出来、是读口不统一**（`A1494②`，日志里 33 次「没有 WindowsManager」）。

   ⚠️ **原版没有「逐件渲染队列」这套机制**（它靠兄弟序 + 排序层）⇒ 那张梯子**是我们自己起的**。

   漏 `Build()` ⇒ **窗参六条全绿、树却是空的**）。
