### 2·1 本线的**快内环**（唯一能替代「等 Unity 编译」的东西）

```bash
bash d:/4/Unity/工具/ruleprobe.sh            # = check，全池 dump 与基线逐行比，≈2 秒
bash d:/4/Unity/工具/ruleprobe.sh play <卡id>  # 单卡【结算层】真打读数（≈0.3 秒）
bash d:/4/Unity/工具/ruleprobe.sh play all     # 全池逐卡真打（≈5 秒），可加 pf <out.txt> 写结算指纹
bash d:/4/Unity/工具/ruleprobe.sh seg "<卡面英文>"   # 手搓一句看解析成什么
```
**为什么能离线**：`RuleEngine/Core/` 有一条成文铁律 —— **只许碰 `UnityEngine.Debug` / `UnityEngine.Random`**
（写在 `TutorialScript.cs:344-352` 并在各文件头注重申）。**真实可编译面 = 1 个成员 / 18 个调用点 / 6 个文件** ⇒ `Stub.cs` 够用。
🔴 **定位 = 【快速内环 / 旁证】**：**正式验收仍然是 `RuleEngineTest.Run`**（断言的真宿主）——
**探针绿 ≠ 自检绿**（`资料/引擎离线对拍_探针.md` §五）。⛔ **也别给探针加 `<DefineConstants>UNITY_5_3_OR_NEWER</DefineConstants>`**
（`Core/` 里**不许**写回 `Resources`/`JsonUtility`/`TextAsset` 的双分支）。

## 三、干一件活的流程（**六步**）

```
① 读「本任务文件」→ 它里面有判据与出处
② 判据不够 ⇒ 先补判据（派【只读】子代理去勘），⛔ 别凭印象动手
③ 动手改（.cs）→ 立刻跑 `bash d:/4/Unity/工具/typecheck.sh`（**秒级，唯一挡「编不过」的**）
④ 同一批跑一次 `bash d:/4/Unity/工具/ruleprobe.sh check`（**≈2 秒**；🔴 判据见 §六·2）
⑤ 落盘：把「查出的事实 / 坑 / 判据」写进该去的地方（见 §五）
⑥ 收工：按 `任务线/README.md` §五 那四步改总表；⛔ **不跑自检、不起 player**（见 §四）
```

**六条本线的硬规矩**：

1. 🔴 **对局必须可复现**：引擎里**只用 `System.Random(seed)`**，⛔ **不用 `UnityEngine.Random`**
   （`Core/` 里 12 处 `UnityEngine.Random` **全是注释、在用 `ctx.Rng`**）。
   ⛔ **定死的规则（「取槽号最小的那个」那类）不要改成随机。**
2. 🔴 **新增「会改引擎状态」的动作路径，必须走两个记账口之一**：
   **玩家的动作走 `BattleDriver.LocalAct(...)`** · **AI 的动作走 `SimpleAI.ExecuteAction`**
   （后者在引擎边界发 `SimpleAI.Executed`）。**绕过它们直调 `RuleCore.*`（或手写 `ctx.Players[x].Board[y]`）**
   ⇒ **那一路的动作一条都没录，本地录像从那里开始演成另一局**。判据在 `Battle/ReplayStore.cs` 文件头；
   实测抓到过两处（`SimulatePlay` + 自检里三处局部直调）。
3. 🔴 **`d:/warpforge/scripts/rule_core.gd` 是我们自己的上一版 Godot 复刻 —— 只作旁证、⛔ 不是判据**
   （用户 2026-10-15：「我们直接使用解包资料，**不要被 Godot 时代的账这些干扰**」）。
   ⚠️ 它**实际致错过**：`规则引擎_进度与交接.md` 里两处「handler 顺序照抄 `rule_core.gd` 的 `_resolve_text`」已就地打上 2026-10-17 更正痕。
   同族：**粉丝实体规则书**（`资料/规则书/Warpforge_Offline_Rulebook_1_5-3_*.md`）**自己第 5 行写着 `Not official. Fan project.`** ⇒ **第二来源/旁证**，⛔ 不许当数字版的最终判据（判据全文 → `CLAUDE.md` 铁律 2 那条更正）。
4. 🔴 **「一个值 ≠ 全部情况」在本线尤其凶**：同一个字段**运行时按状态改**是常态
   （例：`isPraying` **置真一处、置假两处**；`attackDamageType` 按 `DamageType` 分 `{7,8}`；`justOwnedCards` 三个调用点传 `0/1/0`）。
   ⇒ **交结论时给「状态 → 参数」表**，只查得出一档时**明说「只覆盖 X 这一档」**。
5. 🔴 **一个对象有多个实例时，先按父链 / 用途字段判用途**，再谈值（先例：`CardsHorizontalLayout` 我方手牌 5271 / 敌方 4053）。
6. 🔴 **两处写同一条规则 = 迟早不一致**，判据只留一处。
   ⚠️ 本线**已抓到多例**：`HasAlternativeAction`（原 `AlternativeActionKeyword` / `CanUseAlternative` 各写一遍、口径还不一样）·
   `FaithProbe.cs:79/:407` 仍用 `IsPaidHead` 与自己注释脱节（`A1681`）· 「黑暗契约记号族」判据**三处各一份**（`A2054`）·
   `RuleEngineTest` 里一份 `WillRun` 判据的移植副本（`A1594`）。

## 四、验收口径（**现行：只做不验**）

🔴 **用户 2026-10-15 第八次收口**：「**之后暂时别检查，先完全复刻，复刻好了再检查**」。
⛔ **不跑 `*.Run` 自检**（一条都不跑）· ⛔ **连「起 player 截图看界面」也停**。
✅ **只留两件**：**秒级类型检查**（几秒，不算检查）· **「原版 vs 我们」的缺口普查**（那是复刻的**输入**，不是验收）。
✅ **本线额外允许**：`ruleprobe.sh check` / `play <id>` —— **它不跑 Unity、≈2 秒**，属「**修好自己那件活的读数**」，
⚠️ **但它是【旁证】、不是验收**（§二·1）。
🔑 **判别句**：**这件事是在「找出还没复刻的」，还是在「验证我刚改的对不对」？** 前者做，后者停。
🕐 **什么时候才验**：**复刻完成之后**统一验收（`RuleEngineTest.Run` **是收口的宿主**）。

## 五、形成文件说明（**任务文件怎么写**）

### 5·1 一件活一个文件，文件名 `T<两位序号>_<短名>.md`
**必须有的六节**（⛔ 别写成散文）：
```markdown
# T03 · <一句话说清这件活>
> 状态 / 起于哪一版 / 关联 A 编号

## 一、要做什么（**能一句话说清「做完之后，玩家/数字有什么不同」**）
## 二、判据（**逐条带出处**：`.c:行号` / `dump.cs` 偏移 / 卡面图路径 / 类名+方法名）
## 三、我们现状（现状**逐处**给 `文件:行号`）
## 四、怎么改（**改哪个文件、改什么**；分几步；先做哪步）
## 五、做完了怎么自检（**照当时的验收口径**：现在是「只跑类型检查 ＋ 探针读数」，将来是「`RuleEngineTest.Run`」）
## 六、还差什么 / 判不准的（⛔ **不许猜**，写「没查到 + 我搜过哪些词/哪些包」）
```

### 5·2 什么写进**任务文件**、什么**不**写
| 写进任务文件 | ⛔ 不写 |
|---|---|
| 判据（带出处） | `CLAUDE.md` 已有的铁律（**抄一遍就会过期**） |
| 我们现状 + 行号 | 别的任务已写过的东西（**给指针**） |
| 改动清单 | 大段反编译原文（**给 `文件:行号`**） |
| 「还差什么」 | 已经做完的过程叙述 |

### 5·3 详情**超过 ~150 行**就再拆
判据原文太长 ⇒ 搬进 `资料/待办判据_*.md`（**编号同一套**），任务文件只留「一句话 + 指针」。

### 5·4 收工后的归档
按 `任务线/README.md` §五。**已完成的详情文件搬进 `资料/历史/已收口_引擎线_<日期>.md`**（原文一字不改）。

## 六、本线已知的坑（**继续加，⛔ 别删**）

### 6·1 量具本身会骗你（**最贵的一族**）

1. 🔴 **`ruleprobe.sh` 构建失败会拿旧 dll 跑出假绿** —— `dotnet build` 的退出码原来被 `2>&1 | grep … || true` **吃掉**，
   而**构建会被别人半成品的源码打断**（实测一次 `CS1525`，来源 = 当时另一个写手正在写的 `工具/ruleprobe/WillRun.cs`）
   ⇒ 旧 dll 还在 `bin/` ⇒ 打出「**解析差异 0 行**」这种**看起来全绿**的读数。
   **成因与修法**：`工具/ruleprobe.sh:36-60`（`A1466`，**现已取 `dotnet build` 的退出码、非 0 出声并停**）。
   ⚠️ **本仓同族血案两条**：`_run_8_checks.sh:13-22`（`$?` 被 `$(date)` 吃掉 ⇒ 编译错误也报 0）· `typecheck.sh:68-70`。
2. 🔴 **`check` 的「解析差异 0 行」只是「与基线一致」、不等于「解析全通」** ——
   ① 它**还跑一组与基线无关的哨兵**（`=== 哨兵合计：失败 N 条 ===`，**那 N 条也计入 rc**）⇒ 「差异 0 行 + 哨兵 > 0」**仍然红**；
   ② ⑥ ⑦ 两个**输出指纹**既不读卡池、也不读基线文件 ⇒ **`scan` 重生成基线抹不掉它**
   （兜住「任何真回归 + 重生成基线 ⇒ 静默变绿」这条洞）。判据 → `工具/ruleprobe.sh:11-15` 与 `Program.PinnedParseMd5`。
   **⇒ 判绿红一律看【摘要行 + 哨兵行 + 指纹行】，⛔ 不看 `$?`**（本仓规矩：退出码会被别的命令吃掉）。
3. 🔴 **`scan`/`check` 的基线有一个【6 张卡的盲区】**：`工具/ruleprobe/Scan.cs:137` 有一句
   `if (string.IsNullOrEmpty(desc)) continue;` ⇒ **`desc` 为空的卡不进全池 dump**（现读正好 6 张：`ASH61` `BL2` `BL26` `GOF8` `TL61` `UM6`）
   ⇒ **这 6 张的效果永远不在基线里**，改 `EffectText` 动到它们时 `check` **不会出声**。
   这**就是「全池 1120」与「卡池 `count = 1126`」对不上的全部原因**。⚠️ **`GOF8` 那一张仍未查**（`A1941`）。
4. 🔴 **`ruleprobe.sh` 的相对路径是在 `cd` 之后解析的** ⇒ `scan 工具/ruleprobe/基线/out_baseline.txt`
   会写到**嵌套一层**的地方，**而且照样印「wrote …」、`rc=0`**。实测踩过一次：以为重生成过基线，其实盘上那份**一个字没动**。
   修法见 `工具/ruleprobe.sh:24-31`（**要重生成基线就传绝对路径**）。
5. ⚠️ **量具的噪声族要先过滤再派活**：`play` 的已知误报 —— ① 卡面就是 `Does nothing`；
   ② 夹具把 `GameplayVariables.MaxEnergy` 设成 30，而 **`MaxEnergy ≥ 10` 就进加时**（`RuleCore.cs:1009-1034`）⇒ 夹具局**从第 2 回合起多抽一张**；
   ③ 档 B（`Strike:`/`Duty:`/`When…`/`Teleport:`…）**本夹具产生不了那个事件**（`other = 0` 是预期的，**是量具盲区、不是证据**）；
   ④ **牌库顺序不比**（只按 id 多重集比）。判据 → `资料/普查产出_第十九会话/E8_ruleprobe逐卡真打.md` §2（`A1573`）。
6. ⚠️ **探针看不见哪一类改动，这件事还没收完**：`EffectOp.Source` 在三个 dump 入口**一个都不打**；
   `Tail` 与 `ChooseDeadScope` **`Dump` 打了、`Scan` 不打**；`EffectOp` 有 **50 个公开字段、dump 只盖 15 个**，
   而「**该打哪些**」这条判据**本身没有出处**（`A1561①` / `A1568`）。
