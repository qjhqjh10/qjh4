## 一、这条线是什么

**把原版那 900+ 件特效（prefab / 粒子 / 材质 / shader / 网格 / 贴图）搬进我们工程，并且「画得像」。**

🔴 **它与【战斗线】的交界**（`任务线/README.md` §四 那条规矩的唯一落地处）：
- **改 `CardPresentation/**`（表现层 / `VfxMap` / `BattleDriver` / `CardView`）⇒ 归【战斗线】** —— 本线**不收**；
- **改 shader / 粒子资产 / `WarpforgeVFX/**` / 特效导入链 ⇒ 归【本线】**。
- ⛔ **同一笔账不许两边都列**（铁律 6）。`任务_卡组卡牌战斗.md` §四 里的 **`A2080`–`A2111` 整段是战斗线的**，
  **本线一条都不收**（2026-10-15 定的口径）。
- ⚠️ **本线的账本来就没走 A 表** —— `任务_卡组卡牌战斗.md` **§四 里没有一条属于本线**（现核：那节全是 `CardPresentation/**`）；
  本线的待办在 `项目任务.md` §三 第 4 条 与正本 §十四 末节，**用 ①②③ 编号**。
  只有 `A1864`（抽卡特效 prefab 缺件）与 `A1883`（自写 VAT shader）两条**主件落在本线**，已收进 `任务总表.md`。

**这条线的两个「层」**（判每条差异属于哪一层，全靠它）：
① **正常态** —— `UseOriginal` 白名单里的名字**走原版 bundle 原件**（几乎总是对的）；
② **兜底路** —— 白名单失效 / 原件包不在场时，落到**我们自建的替代 shader**。
🔴 **判缺陷之前先问「这一条是正常态还是兜底路」** —— 兜底路的问题**正常态看不见**，反之亦然。

## 二、判据从哪来（**动手前必读，按权威顺序**）

| 想知道什么 | 去哪 | 备注 |
|---|---|---|
| **① 逐效果「像不像」（数字的唯一出处）** | **`资料/特效还原台账.tsv`** | 全量 sweep（原版 vs 导出）逐效果：分组 / 判定 / 亮度比中位 / `\|ln\|` / 置信度 / 技术构成。**看之前先读正本 §〇 那两段「尺子」判据** |
| **② 兜底路还差多少** | **`资料/比对基线/兜底路审计_1002j.tsv`** | `WFBIND_FORCE_BUILTIN=1` 跑的那趟。🔴 **`_1002j` 才是现行**（正本 §十四 :1639 明写「整轮对照表 = 它」）；`_1002.tsv` 是 §十三 收工态、`_1002f`/`_1002g` 是中间态 |
| **③ 语义 / 算式 / 谁在什么条件下改它** | `d:/2/tools/decomp_full/`（26,282 个方法） | 入口 → `资料/全量反编译_入口与用法.md` |
| **④ 原版 shader 的属性表 / pass 状态** | `工具/dump_shader.py "<shader 名>"` | **做自建 shader 前先跑它**；属性表里没有的**一律硬编码** |
| **⑤ 编译字节码（DXBC）** | `工具/dump_shader_blob.py` · `工具/disasm_dxbc.py` | HLSL 源码被剥了，**字节码在**；资源名是明文，「采样哪张纹理」查得到 |
| **⑥ 槽位名（`cbN[i]` / `tN` 叫什么）** | **Unity 自己的序列化反射**（`SerializedPass.m_CommonParameters`） | 见正本 §十四「通用钥匙」第 1 条；`cb0` = `$Globals` |
| **⑦ 我们做到哪了（快速内环）** | **`EffectCompare`（`Assets/WarpforgeArena1/Editor/EffectCompare.cs`）对拍** | **2 分钟**一轮（全量 sweep 要 8 分钟）。**口诀：形状不同 ⇒ 配对错；形状同只差亮暗 ⇒ 算式错；品红 ⇒ 编译错** |
| **⑧ 单件效果的原版侧读数** | 同进程 `WFSWEEP_SIDE=both` / `WFSWEEP_SIDE=orig` | ⚠️ **必须与基线同样的扫描位置**，否则与全量基线不可比 |

🔴 **三条最容易犯的**：
1. **⛔ 别把「效果库总条目数」写进任何文档** —— 现读口径 = **台账的数据行**；**库里 prefab 数 = 自检自己打印的那一行**（两套口径本来就不同）。
   旧的 **957 / 959 / 962** 那批数**全部作废**（正本 :20 已就地订正）。
2. **⛔ 别拿 `白名单比值` 那一列单独判缺陷** —— 它是 `导出 ÷ 原版`，而**原版侧读数与「同一进程里它前面跑过什么」有关**（进程级全局关键字泄漏）。
   **判缺陷/排序只看 `偏差 = |ln(自建 ÷ 白名单)|` 列**（两边都是导出侧，可跨跑比）。
3. **⛔ 别拿单效果 / 小批的读数去对全量基线**（正本 §十四「量测口径」列了三条实测反例）。

## 三、干一件活的流程（**六步**）

```
① 读「本任务文件」→ 它里面有判据与出处
② 判据不够 ⇒ 先补判据（读反编译 / 跑 dump_shader.py / 派只读子代理去勘），⛔ 别凭印象动手
③ 动手改（.shader / .cs）→ 立刻跑 `bash d:/4/Unity/工具/typecheck.sh`（**秒级，唯一挡「编不过」的**）
④ 落盘：把「查出的事实 / 坑 / 判据」写进该去的地方（见 §五）
⑤ 收工：按 `任务线/README.md` §五 那四步改总表
⑥ ⛔ 不跑自检、不起 player（见 §四）
```

**四条本线的硬规矩**：
1. 🔴 **一改就 A/B**：兜底路的改动**必须**用 `EffectCompare`（小批 + `WFCMP_ISO=all`）与**兜底路审计**两条口径各看一眼 ——
   ⛔ **别只看一条**：这两把尺子**测的不是同一件事**（正本 §十四 E② 就是这么栽的）。
2. 🔴 **改一个变量**：一次只改一处（`A1557` 那批当初就是**按「一次只改一个变量」拆开的**）——否则读数说不清是谁的账。
3. 🔴 **⚠️「观测不到」不等于「验过了」**：`WFUnlitAmbient` 那三条改完**在现有 958 个效果上观测不到**
   ⇒ **`EffectCompare` 对它不是有效验证**，要验得做**正控**（W12 §六）。
4. 🔴 **不许静默失败**：取不到 shader / 贴图 / 属性，**一律出声**（`Debug.LogWarning`），⛔ 别默默退回默认值。

## 四、验收口径（**现行：只做不验**）

🔴 **用户 2026-10-15 第八次收口**：「**之后暂时别检查，先完全复刻，复刻好了再检查**」。
⛔ **不跑 `*.Run` 自检**（一条都不跑）· ⛔ **连「起 player 截图看界面」也停**。
✅ **只留两件**：**秒级类型检查**（几秒，不算检查）· **「原版 vs 我们」的缺口普查**（那是复刻的**输入**，不是验收）。
🔑 **判别句**：**这件事是在「找出还没复刻的」，还是在「验证我刚改的对不对」？** 前者做，后者停。
🕐 **什么时候才验**：**复刻完成之后**统一验收。

⚠️ **本线的历史口径**（要知道它存在，但**现在不照它办**）：`EffectCompare` 对拍 / 兜底路审计 / 全量 sweep
—— 它们是**量差异**的工具（属复刻的输入），**不是**「验收我刚改的对不对」。

## 五、形成文件说明（**任务文件怎么写**）

### 5·1 一件活一个文件，文件名 `T<两位序号>_<短名>.md`
**必须有的六节**（⛔ 别写成散文）：
```markdown
# T0N · <一句话说清这件活>
> 状态 / 起于哪一版 / 关联 A 编号

## 一、要做什么（**能一句话说清「做完之后画面有什么不同」**）
## 二、判据（**逐条带出处**：资产路径 / `文件:行号` / shader 名 + 槽位）
## 三、我们现状（现状**逐处**给 `文件:行号` / shader 文件头）
## 四、怎么改（**改哪个文件、改什么**；分几步；先做哪步）
## 五、做完了怎么验（**照当时的验收口径**：现在是「只跑类型检查」；量差异走 §二的工具）
## 六、还差什么 / 判不准的（⛔ **不许猜**，写「没查到 + 我搜过哪些词/哪些包」）
```

### 5·2 什么写进**任务文件**、什么**不**写
| 写进任务文件 | ⛔ 不写 |
|---|---|
| 判据（带出处） | `CLAUDE.md` 已有的铁律（**抄一遍就会过期**） |
| 我们现状 + 行号 / shader 文件头 | 别的任务已写过的东西（**给指针**） |
| 改动清单 | 大段反编译原文 / DXBC 反汇编（**给 `文件:行号`**） |
| 「还差什么」 | 已经做完的过程叙述 |

### 5·3 详情**超过 ~150 行**就再拆
判据原文太长 ⇒ 搬进 `资料/待办判据_*.md`（**编号同一套**）或那份 `普查产出_*/` 报告，任务文件只留「一句话 + 指针」。

### 5·4 收工后的归档
按 `任务线/README.md` §五。**已完成的详情文件搬进 `资料/历史/已收口_特效线_<日期>.md`**（原文一字不改）。

## 六、本线已知的坑（**继续加，⛔ 别删**）

1. 🔴🔴 **原版材质上带着内置 Standard shader 的残留值** —— `_SrcBlend` / `_DstBlend` / `_ZWrite` / `_Surface` 这些名字
   **在原版 shader 的属性表里可能根本没有**（property 被删了、值还留在材质上）。原版 shader 不采它们时它们是**死值**；
   而**自建 shader 一旦用 `Blend [_SrcBlend][_DstBlend]` 间接寻址，就会把死值当活值用**
   （实测把**抓屏扭曲**变成**不透明覆盖 + 写深度**）。⇒ **属性表里没有的，一律硬编码。**
2. 🔴🔴 **接一个原版属性之前，先问三句**：① **它的默认值是什么**？② **原版在什么条件下才采它**？③ **原版是加法还是乘法**？
   —— **它多半不是乘法**。**已栽过两次**：`_EmissionColor`（默认黑 ⇒ 整个材质被乘成黑、13 个效果同时变暗）、
   以及 `WFParticlesExtraColor` 里一行**凭空来的加法**。全过程 → 正本 §〇·一。
3. 🔴 **`[Toggle(KEY)]` 的 KEY 别在 CBUFFER 里声明同名变量** —— Unity 开关键字时会 `#define` 它 ⇒ **重定义、整份 shader 编不过**（渲成品红）。
4. 🔴 **自建替代 shader 的关键字名必须与原版【逐字】相同** —— 原版 Everguild 系开的 `_SOFTPARTICLES` **没有 `_ON` 后缀**，
   照我们的拼法写 = **设了但不生效、还不报错**。（代价 = 两条效果查了整整一轮。）
5. ⚠️ **`cbN[i]` 认名字有路了** —— 走 Unity 序列化反射，不必再找 RDEF（正本 §十四「通用钥匙」1）。
   `ConstantBuffer.m_VectorParams[].m_Index` 是**字节偏移** ⇒ `slot = off / 16`；`m_TextureParams[].m_Index` 直接是槽号。
6. ⚠️ **`WFMatDef` 的并列数组按名字 ASCII 排序、且混着旧 shader 的残留名** ⇒ 「读到一个数」≠「读对了那个数」。
7. ⚠️ **`disasm_dxbc.py` 用 `| head` 截断会被 SIGPIPE 掉** ⇒ **文件不落盘且不报错**，要用 `| tail` / `| grep`。
8. ⚠️ **判定级噪声底** = E 计数 **±1**（±1 的变化说明不了任何事）；**`|ln| ≲ 0.6` 的 E 条目分不出真假**；
   根因 = 渲染侧 **±1 LSB**（仿真侧确定）。`analyze_sweep.py` 每次会打「尺子自检」表，**看计数变化前先跟它比**
   （边界挪 0.05 就能摆动 22–54 个）。不稳定名单 → `资料/比对基线/尺子不稳定名单.tsv`。
9. ⚠️ **跨进程仍会漂**（同进程内已修）—— 两跑差约 6% 的行；别拿「两跑不一致」当资产退化的证据。
10. ⚠️ **`资料/特效E组_根因初判.md` / `资料/特效E组_逐效果根因表.md` 是按【旧台账（242 条）】分的组**
    ⇒ **逐效果结论要按新账重核**，⛔ 别再照它们动手；E 组的当前正本 = `资料/普查产出_0918/E组_共享资产筛_与EMISSION线索.md`。
11. 🔴 **`任务_卡组卡牌战斗.md` 里 358 行的表格行只有 2 格**（表头却声明 4 列：`编号 / 一句话 / 状态 / 判据·详情`）
    ⇒ GFM 把它们渲成 2 列。**其中本线相关的是 §四 后 17 行（`A1485` 起）与 §七 全部 18 行。**
    **⇒ 抄状态时别以为「没有状态列 = 没状态」**：那些行的状态**只能用行内文字判**（开头那个 🔴/⚠️/🟡/✅ 就是它的状态），
    或者**回判据件**（`资料/待办判据_第三十三会话.md` 的 `## Axxxx` 节）读原文。
    （现读：`任务_卡组卡牌战斗.md` **358 行 2 格** / 66 行 4 格；`⊘` 这个记号**全文件 0 次**，⛔ 别去找它。）
