1. ✅ **`unitDamage` —— 已接（2026-10-16）。**
   判据（`T06b` 实核）：原版它在 `_ResolveMultiDamage…` / `…AndDestroySelf…` 里，**只在该批的最后一个目标那一下播**
   （`count-1 <= index`），而**普通攻击不走它**（`_ResolveAttack:865` → `ResolveAttackDamage`，攻击命中归 `BattleCardSounds` 那一族）。
   ⚠️ 顺带订正一条旧结论：那两个方法**不是「没有调用点」**，是**被内联**了 —— `BattleManager.ResolveAction`
   是一张 91 项跳转表（`ActionType − 1` 作索引），case 体把工厂逐指令内联进去（详见 `资料/已知的坑.md` 末尾那一条）。
   **我们这一侧**（等价物、不是原件）：`BattleDriver.UnitDamageCueIndex`（**纯函数**，便于断言）——
   「一批」= 一次 `DrainSignals`；「挨打」= `EvtKind.Hit` 且 `Amount > 0`（负数是治疗）；
   **跳过紧跟 `EvtKind.Attack` 的那一条**（= 攻击命中）；**只认最后一条**。挂在 `PlaySignals` 里（要整批视野，
   ⛔ 不挂逐事件的 switch）。配了 5 条断言（单目标 / 攻击命中不播 / 多目标只认最后 / 治疗不播 / 混合的判别式）。
   ⚠️ **仍未定**：引擎侧**没有**「同一批」的正规判据（`DrainSignals` 一次可能跨不止一条动作）——
   将来事件若补上「同源动作 id」，`UnitDamageCueIndex` 应改成按那个 id 分组。
2. ✅ **`sneakAttack` —— 判为「我们卡池里没有触发物」，照铁律 11 例外①【不做】。**
   `T06b` 查实：真身 = **攻击者当前带 `sneakAttack`（`DefinedTrait` 20）trait 的一次攻击**（原版状态机里
   那个 `else` 不是「远程」的 else，是 `HasCurrentTrait(attacker, 0x14)` 的 else）。
   而**原版 1195 张卡 SO（`远端缓存_旧profile_1013/导出/cards_1195_2022时代.json`）与我们 1127 张，两边都是 0 张**
   带这个 trait（词条在官方本地化表里有 `Card_Trait/sneak`、但**没有任何卡引用**；`Stealth` 是**另一个** trait=70）。
   ⇒ **触发点判据已齐**（将来加卡即可直接接），但**当前卡池上没有触发物**。

3. **`BattleCardSounds` 那 9 条（B 组）** —— 它们**逐卡序列化在卡 prefab 上**（不是全局一张表），
   取值链要另开一条（卡 prefab → `BattleCardSounds` 组件）。⚠️ 其中 `backToHand` / `landOnGround` / `createCardInHand`
   **全仓只找到 getter、调用点没查到** ⇒ 那三条的时机原版就没定。
4. **`ActivateSentinel` 的触发点** —— 全反编译 **0 命中**（且它本 build 就是悬挂 GUID，见 §三）。
5. **战斗 BGM「哪一场放哪首 / 什么时候切」** —— **零份**；已知**部分**：`BattleMusicManager` 有三档强度快照
   `battleLow/Medium/High`（阈值 `midHealthChange`/`highHealthChange`）＋ 结算时 `FinishMatch` 换快照。
6. **`matchType == 0x32`(=50) 是哪个模式** —— `_MulliganCountdown:23` 有一道 `if (matchType == 0x32) return;`

7. **`SoundCollection`（旧的 `AudioClip` 表）在 `decomp_full` 里 0 引用** ⇒ 战斗只用 `SoundAssetCollection` ⇒ ⛔ 别照 `SoundCollection` 接。

## 六、本轮的坑（⛔ 别删）

1. 🔴 **「表里已经有」不等于「这一族在表里」** —— 上一轮那句「432 条现役、只差接线」就是这么来的（见 §〇）。
   同类：**「同名」不等于「同族」**。
2. 🔴 **`assets_full` 的 `grep -a` 对 UnityFS bundle 是无效判据**（块是压缩的、会假阴性）——
   本轮一开始想用「裸搜 GUID」证明某条资产不存在，**那个结论不可用**；改用 **catalog 的 `key_index`**
   （正面判据）＋ **shipped bundle 亲读**（正面判据）才站得住。
3. ⚠️ **`_guid_resolve_probe.lookup()` 返回的是 `list`**（同一条 GUID 可能解出多条），⛔ 不是 dict。
