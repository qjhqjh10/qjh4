把原版**卡牌 ScriptableObject**（`RawCardScript : PlayerItem`）当成**真值源**：

- 同时把**触发代码 → 参数**整理成表，供将来新增卡直接复用。

## 四、已验证的结论（⛔ 别推翻）

1. **`uniqueId` + `cardName` 是 SO 自身字段** ⇒ 拿到 SO 就是**读**，不是「逆推」。**5/5 已知卡全链逐字段相等**。
2. **效果纯数据驱动**：`AbilityEffect` 83 值 / `AbilityTrigger` 97 值 / 49 个 `BattleManager.Add*` 操作；**没有一卡一个 C# 类**。
3. **本地直读覆盖率 = 0/118**；**拿到 `allcards` 包 = 118/118**。
4. **数值签名严重重复**（54% 共享）⇒ 认卡必须叠加立绘 GUID / 效果签名 / 稀有度 / 扩展包。
5. **id 前缀 → 阵营 1:1**（13 个前缀）；`uniqueId` 1194/1194 唯一；⛔ 别按卡名 join（46/1009 归一化后仍不同）。
6. **32 位 GUID 的 id 没有前缀**；`SW` 在旧 SO 里 0 行；SO 阵营内 `cardName` 有 84 组重名（只取短 id 时 0 重名）。

## 五、已知的坑

1. ⛔ **别在 `assets_full` 里找卡 SO** —— 它 24 万个 JSON 里**含 `cardAbilities` 的 = 0**；真身在旧 profile 缓存 / 原始 bundle。
2. ⛔ **别把「旧快照」当「当前 build」** —— 旧包是 Unity 2022.3.38f1 时代（无 SpaceWolves），原版后来做过大版本重建。
3. ⛔ **别把「B 档旁证」写成定论**（DT 稀有度 73/116 · draft 69/116 · 预组 61/116 都只是旁证）。
4. ⚠️ **`m_Name` 不等于 `uniqueId`**：`.asset` 文件名是卡名/变体名，唯一键是 `uniqueId` 字段。
5. ⚠️ **卡 SO 的 `cardType` + `spellType` 是完美类型分类器**（0/0=unit · 10/0=hero · 20/0=tactic · 20/210=defence）；`keyword` 枚举就是兵种。
