## 二、已查实的关键结论（**接手先读这一节**）

1. **卡 SO 的类 = `RawCardScript : PlayerItem`**（`m_Script` pathID `8864902669260471755`）：
   - `uniqueId`（`PlayerItem.cs:14`）· `cardName`（`RawCardScript.cs:21`）· `cardArmy` · 费用/近战/远程/生命/护甲五格 ·
     `cardAbilities`（规则层，**内联结构体不是指针**）· `activeAbility` · `cardImageReference`（立绘 GUID）· `CardTraits`。
   - **本机有 1,192 张完整卡 SO**，但**只在旧 profile 缓存**（`d:/2/远端缓存_旧profile_1013/Unity缓存_按哈希/54bdb7b1…/…/__data`，2025-07-30 快照）；
     `assets_full` 的 24 万个 JSON 里**含 `cardAbilities` 的 = 0 个**。
   - ⇒ **1009/1127 张池内卡早就是原版真值**；缺的是 **118 张**（SW 68 / UM 15 短号 + 23 无号 / DA 12），全部是快照之后的新内容。
2. **链路抽样**：5 张已知卡 **5/5 全链走通**，与 `cards_engine.json` **逐字段相等**（AM1/SOR36/GOF105/SAU23/DA61；单位召唤 PPtr 395/397 可解析）；
   **5 个未知 0/5 走到 SO**（SW20/DA78/UM87/GSC48/SOR76 —— 2 个只有引用级旁证，3 个本地一个文件都不出现）。
3. **效果是纯数据驱动**，一张卡没有专属 C# 类：`CardAbility{trigger, abilityLogic[]}` →
   `AbilityLogic.chosenAbility`（`AbilityEffect` 83 值，用到 53）由 `AbilityLogic__PlayAbility.c`（2,878 行）switch 到
   49 个 `BattleManager__Add*`；`AbilityTrigger` 97 值（用到 57）。
4. **数值不能单独认卡**：1,192 张只有 689 个数值签名，**54% 与别人共享签名**、87 组重名 ⇒ 必须叠加
   立绘 GUID / 效果签名 / 稀有度 / 扩展包。
5. **id 前缀 → 阵营 1:1**（`UM`=Ultramarines … `SW`=Space Wolves），**`uniqueId` 1194/1194 唯一**；
   ⚠️ 32 位 GUID 的 id 没有前缀（SO 259 / 池 113）；`SW` 在旧 SO 里 0 行。
6. **当前 build 卡 SO 包的唯一期望名**：`allcards_assets_all_ea8bca4f5c6909d3124fd4975dc96173.bundle`。
