## 二、已查实的关键结论（接手先读这一节）

1. **卡 SO 的类 = `RawCardScript : PlayerItem`**（`m_Script` pathID `8864902669260471755`）：
   `uniqueId`（`PlayerItem.cs:14`）· `cardName` · 五格数值 · `cardAbilities`（**内联结构不是指针**）·
   `activeAbility` · `cardImageReference`（立绘 GUID）· `CardTraits`。
   **当前 build 1,351 张全部可读**，`uniqueId` 1,351/1,351 非空、0 重复（`报告.md:37-39`）。
2. **id 有两种形态**：13 个「阵营前缀 + 数字」（1,040 张）+ 32 位 hex（311 张）。
   前缀 → 阵营 1:1（旧快照 933/933 零例外，`R_SO…:346`）；**卡名不能当主键**（108 个重名，`报告.md:99`）。
3. **效果是纯数据驱动**：一张卡没有专属 C# 类。`CardAbility{trigger, abilityLogic[]}` →
   `AbilityLogic.chosenAbility`（`AbilityEffect` 83 值）由 `AbilityLogic__PlayAbility.c`（2,878 行）switch 分发到
   **75 个 `BattleManager.Add*`**（旧记 49 是子集，`P1:341` 已订正）；`AbilityTrigger` 97 值。
   **当前 build 用到 60 个 trigger / 57 个 effect**（本线现算；旧快照是 57/53，卡池不同，不是打架）。
4. **关键词分三种形态**：纯数据（rally/ambush）· 硬编码标志位（jam/stealth/blast…）· 专用子类（Duty/Ferocity/Oath）。
   ⛔ 别一锅端（`P1:176-229`）。
5. **动画链 = 卡 SO 的 `AssetReference` GUID → `CardAnim` → `animInfo.animAdressable` → prefab**；
   GUID 反查资产名**走本地 bundle 的 `m_Container`**（新表 6,140 个 GUID），不依赖远端目录
   （`T14…报告.md:30-43`）。
6. **本地化按 id 建键**：`Card_Name/<id>` / `Card_Description/<id>` / `Warlord_Lore/<id>`；
   台词是 `Chat_Messages/<refId>-Chat<N>`。官方表（含 zh-CN）**已解开**，在 `数据/游戏数据/官方本地化_en+zh-CN.json`。
