## 一、怎么用（**新会话照这个顺序走**）

```
① 先看本文件 → 找到你这条线的文件夹
② 进 <线>/任务总表.md  → 只看【未完成】那一节（⚠️ 已完成的别看，那是留痕）
③ 每一条任务后面有【索引】，按它去读 <线>/任务/<那份文件>.md
④ 开工前再读一次 <线>/准则与做法.md（判据去哪找 / 怎么收工 / 怎么落盘）
```

🔴 **三条不许违反的**：
1. **⛔ 已完成的条目不要点进它的详情文件**（也不要去读 `资料/历史/`）—— 那是留痕，不是知识。
2. **⛔ 别在这套文件之外再开一份待办台账**（铁律 6：清单只留一处）。新账**只**往 `<线>/任务总表.md` 里加。
3. **⛔ 别把判据原文粘进任务总表** —— 总表只放「一句话 + 状态 + 索引」；判据写在**它自己那份详情文件**里（或者它指向的正本里）。

```
资料/任务线/
```

## 三、一条「任务」是怎么定义的

**一件「可验收的活」**，不是一条账。
· 它**可以包含好几个 A 编号**（账户是本项目的原子记账单位，**继续沿用**，⛔ 不要另起一套编号）。
· 它**应该能一句话说清「做完之后，玩家/画面有什么不同」**。说不清 ⇒ 说明它还没切好。
· **例**：`战斗线/T01`「按原版补 HUD 缺件」下面挂着 `A2109`（残余 4 条）＋ `A1547` ＋ `A1239`。

### 3·1 🔴 **状态标记只有这一套**（2026-10-15 统一，⛔ 别再引入第二套）

| 标记 | 意思 | ⚠️ 怎么判 |
|---|---|---|
| **`✗`** | **未做** | 默认档 |
| **`◐`** | **部分做**（主件已改、尾巴仍开） | 行内**同时**有 ✅ 与「仍开着」⇒ 一律记这个 |
| **`？`** | **判据未定 / 判不出** | ⛔ **不许猜**；要在「还差什么」里写清缺哪条判据、去哪拿 |
| **`✓`** | **已修、待验收** | 主件已改完，只差**真机验收** ⇒ ⚠️ 按现行「**只做不验**」口径，**这一档今天收不了口** |
| **`⏸`** | **暂缓** | 只两种：**判据是空的**（原版没有 / 代码被剥掉）或**用户拍板暂停**；⚠️ **必须在行里写清是哪一种** |
| **`📌`** | **常驻口径 / 记录**（**不是待办**） | 例：`A2108`「引 `BattleDriver.cs` 行号前先现核」· `A1885`「cards.json 里那张 `Ambush` 别当替身卡」 |

🔴 **两条读法**（本工程的坑，会静默骗人）：
1. **行内 `✅ 已修` ≠ 账已收口** —— 那通常指「主件改完了、账还开着」。**只有「它整条搬进 `资料/历史/`」才算闭**。
2. ⚠️ **旧台账里约 359 行的「状态」列根本不存在**（表格行只有 2 格 ⇒ GFM 里渲染成 2 列）⇒ **「看不到状态格」不等于「没有状态」**，要**回判据件或按行内文字判**。
   📌 **实测口径两条**（2026-10-15 两支独立普查）：**`资料/任务_卡组卡牌战斗.md` 里 9 张表【全部】是这个形状**（§一 `:45` · §二 `:195` · §三 `:291` · §四 `:359` · §五 `:407` · §六 `:442` · §七 `:471` · §八 `:494` · §附 `:503`）；**精确读法 = 358 行是 2 格 / 66 行是 4 格**，分段 §一 139 · §二 75 · §三 60 · §四 17 · §五 24 · §六 22 · §七 17 ⇒ ⛔ **别写死这个数**，判据 = 「表头 N 列 + 数据行 M 格，N ≠ M」。
   🔴 **纠正一处**：这条缺陷在**待办台账**里，⛔ **不在** `资料/规则引擎_进度与交接.md`（那份全文 0 处该形状）—— 早期简报里把它写成「那份正本里」是**指代不清**。

### 3·2 🔴 **别把「普查代理自制的图例」当成台账里的真标记**（2026-10-15 连犯两次）

**事实**：那一轮只读普查的报告里用了 `✗ ◐ ？ ✓ ⊘` 造了一张图例，**而 `资料/任务_卡组卡牌战斗.md` 与 `项目任务.md` 里这些符号一个都没有**
（写手实测：`⊘` 全仓 **0 次**、`◐` 在 `项目任务.md` **0 命中**；台账真实用的是行首 `🆕 / ✅ / 无标记`）。
**后果**：主对话把它当「台账里有这些标记」写进了 5 份派活简报 ⇒ **两个写手各自花时间去找一个不存在的记号**，其中一个还写了「你给的图例我 grep 不到」。

🔑 **规矩**：**派活简报里引任何「文件里的标记 / 编号 / 数」之前，先自己 `grep` 一次**。
⛔ **不要因为「那份报告是本会话自己派的代理写的」就采信它的元信息** —— 代理给的**结论**可以信（有出处），但**它自己造的记法/图例/表格样式**不是文件里的东西。

## 五、完成一件活之后做什么（**收工动作，四步**）

1. **改状态**：在 `<线>/任务总表.md` 里把它从【未完成】移到【已完成】（**一行**，带日期 + 一句「做了啥」）。
2. **详情文件**：**整份搬进 `资料/历史/已收口_<线>_<日期>.md`**（原文一字不改），总表那一行的「索引」改成指向归档件；或者——**只留一行记录**、详情文件直接删（⚠️ 搬之前先问：这条信息下个会话**还要不要动手**？不要 ⇒ 删）。
3. **坑与判据**：把这一轮新学到的**坑 / 判据 / 出处**写进它该去的地方（`资料/已知的坑.md`、线正本、或那份任务的归档件里）—— ⛔ **不要留在总表正文**。
4. **线正本**：如果这一件改变了「本线的架构认知」（不是「又修了一个 bug」），**更新线正本**，并在总表那一行留一行指针。

🔴 **`项目任务.md` 头部的四条写法纪律继续有效**（只放待完成的账 · 别处有正本就只留指针 · 坑/判据写去别处 · 超 5 行就搬走）。
