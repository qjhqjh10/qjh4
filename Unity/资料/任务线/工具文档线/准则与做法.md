## 一、这条线是什么

**工具 · 文档线** —— `工具/*.py` `.sh` · 生成器 · 反编译工具链 · `资料/*.md` 的维护 · 账目编号 · 构建发布。

🔴 **本线的头号口径（用户 2026-10-15 原话）**：
> 「**Godot 时代的账请你清点，我们直接使用解包资料，不要被 Godot 时代的账这些干扰，请你清理**」

**「Godot 时代」= 本项目早期用 Godot 做的那一版复刻**（`d:/warpforge/scripts/` **70 个 `.gd`**：
`rule_core.gd` / `battle.gd` / `sd_card.gd` …）**以及从它派生的一切文档、数值、坐标口径**。
⇒ **本线的世界只有两个权威**：
① **原版解包资源** `d:/2/新解包资源/assets_full/`（4.4 GB / 24.7 万文件）·
② **反编译** `d:/2/tools/decomp_full/`（26,282 个方法）。
⚠️ **`d:/warpforge/` 是我们自己的 Godot 复刻，⛔ 不是权威**（`CLAUDE.md` 2026-09-18 更正那条）。

⚠️ **但「清」不等于「删」** —— `工具/sync_from_d2.py:86-98` 的 `GDATA = 'd:/warpforge/data'`
**是「Godot 时代的数据进 Unity 树」的总闸**，而 `card_stats.json → gen_cards_engine.py:30 →
运行时 cards_engine.json` 这一条 **d:/4 内零替代生成器** ⇒
🔴 **正确顺序 = 补生成器 → 换一个核一个 → 再归档**（判据 → `普查产出_1015战斗/D5_…md` §A）。

## 三、干一件活的流程（**六步**）

```
① 先查 `资料/命令速查.md` / `资料/已知的坑.md` / `工作准则_操作经验.md` —— 有没有现成的做法与坑
② 判据不够 ⇒ 先补判据（派只读子代理去勘），⛔ 别凭印象动手
③ 动手改 → 改完立刻跑 `bash d:/4/Unity/工具/typecheck.sh`（改 .cs 时）
④ 落盘：把「查出的事实 / 坑 / 判据」写进该去的地方（见 §五）
⑤ 收工：按 `任务线/README.md` §五 那四步改总表
⑥ ⛔ 本线【纯工具 / 纯文档 ⇒ 一条自检都不用跑】（铁律 12）；⛔ 也不起 player
```

**五条本线的硬规矩**：
1. 🔴 **改已有的文档 / 脚本，一律用 Edit 工具；⛔ 别用 `sed -i`**（它会把整个文件的行尾翻成 LF）——
   本工程**已经踩过四次**。真要整篇写，照抄它原来的行尾，**改完立刻 `git diff --numstat`**。
2. 🔴 **改完立刻 `git diff --numstat`** —— **数字接近文件行数就是行尾被翻了**（一眼就能看出来）。
3. 🔴 **「判据 / 规则」只留一处** —— 本线最容易犯的就是「两处写同一条规则」
   （先例：`restore_card_icons.py` 的 `PREFIX_FALLBACK` 写了两遍、Python 字面量**后者静默赢**）。
4. 🔴 **生成器必须有 `--check` / `--dry-run`** —— `A1648` 就是「**不带参数就落盘**」踩的（本意是干跑、结果无条件重写）。
5. 🔴 **不许静默失败** —— 工具静默丢东西（`A1548` `menu_dump.py` ＋ `assets_full` **会静默丢掉整支子树**）
   比报错难查得多：**它给出的是一份「看着完整」的读数**。

## 四、验收口径（**现行：只做不验**）

🔴 **用户 2026-10-15 第八次收口**：「**之后暂时别检查，先完全复刻，复刻好了再检查**」。
⛔ **不跑 `*.Run` 自检**（一条都不跑）· ⛔ **连「起 player 截图看界面」也停**。
✅ **只留两件**：**秒级类型检查**（几秒，不算检查）· **「原版 vs 我们」的缺口普查**（复刻的**输入**，不是验收）。
🔑 **判别句**：**这件事是在「找出还没复刻的」，还是在「验证我刚改的对不对」？** 前者做，后者停。

⚠️ **本线的一条特别口径**（铁律 12 的例外，仍然成立）：
**纯工具（`工具/*.py`）/ 纯文档（`资料/*.md`）⇒ 一条自检都不用跑**（2026-10-05 实测：
那一整批工具活跑完**不影响任何一条自检**）—— 所以本线的「不跑」是**双重的**，⛔ 别因为「改得多」就去跑。

## 五、形成文件说明（**任务文件怎么写**）

### 5·1 一件活一个文件，文件名 `T<两位序号>_<短名>.md`
**必须有的六节**（⛔ 别写成散文）：
```markdown
# T03 · <一句话说清这件活>

> 状态 / 起于哪一版 / 关联 A 编号

## 一、要做什么（**能一句话说清「做完之后玩家/画面/工具行为有什么不同」**）
## 二、判据（**逐条带出处**：资产路径 / `文件:行号` / 命令 + 读数）
## 三、我们现状（现状**逐处**给 `文件:行号`）
## 四、怎么改（**改哪个文件、改什么**；分几步；先做哪步）
## 五、做完了怎么自检（**照当时的验收口径**：纯工具/纯文档 ⇒ 零条；改 .cs ⇒ 类型检查）
## 六、还差什么 / 判不准的（⛔ **不许猜**，写「没查到 + 我搜过哪些词/哪些包」）
```

### 5·2 什么写进**任务文件**、什么**不**写
| 写进任务文件 | ⛔ 不写 |
|---|---|
| 判据（带出处） | `CLAUDE.md` 已有的铁律（**抄一遍就会过期**） |
| 我们现状 + 行号 | 别的任务已写过的东西（**给指针**） |
| 改动清单 | 整段脚本原文（**给 `文件:行号`**） |
| 「还差什么」 | 已经做完的过程叙述 |

### 5·3 详情**超过 ~150 行**就再拆
判据原文太长 ⇒ 搬进 `资料/待办判据_*.md`（**编号同一套**），任务文件只留「一句话 + 指针」。

### 5·4 收工后的归档
按 `任务线/README.md` §五。**已完成的详情文件搬进 `资料/历史/已收口_工具文档线_<日期>.md`**（原文一字不改）。

## 六、本线已知的坑（**继续加，⛔ 别删**）

1. 🔴 **`工具/ruleprobe.sh` 只判「dll 在不在」**（`:20-24`）⇒ **构建失败时它照样用上一次的 dll 跑**，
   给出「**解析差异 0 行 · 哨兵 0 失败**」这种**看起来全绿**的读数。
   **实测**：另一个写手当时正写的 `WillRun.cs` 让构建报 `CS1525`，脚本没出声、直接拿旧 dll 跑完了。
   🔴 **为什么这条最要紧**：`ruleprobe` 是**引擎改动的验收工具** ⇒ **仪器静默报绿 ⇒ 读数全要打问号**。
   ✅ **做法**：**别只信脚本的汇总行** —— 拿 `dotnet build` 的**退出码**单独判一次；
   或自己 `cd` 到 `工具/ruleprobe` 手工 `dotnet build && dotnet run`。
   （出处 → `资料/已知的坑.md`「2026-10-10（第十四会话）· 🔴 探针脚本会【拿旧 dll 接着跑】」）
2. 🔴 **`check` 的「解析差异 0 行」只等于「与基线一致」** —— **不等于**「解析器对」。
   ⛔ **别只看前一行**：`解析差异 0 行` **而** `哨兵合计 > 0` = **仍然红**。
   判据表 → `工具/ruleprobe/README.md:64-73`；另注「`check` 的摘要行原来只打 diff」→ 同上 `:425`。
3. 🔴 **改已有的文档 / 脚本一律用 Edit 工具** —— **`sed -i` 会把整个文件的行尾翻成 LF**
   （`.cs` / `.meta` / `.tsv` 一律别用）；python 文本模式 `open(...,'w')` **会翻 CRLF**；
   `io.open(p,'wb').write(<表达式>)` 会**先把文件截断成 0 字节再求值**（表达式一抛异常，**文件就永久空掉**）。
   ⇒ **要写的内容先算进变量，确认没错再 `write`**。
4. 🔴 **改完立刻 `git diff --numstat`** —— 数字接近文件行数 = 行尾被翻。
   ⚠️ **判「混行尾」必须二进制读**（`io.open(p,'rb')`）—— 文本模式会把 `\r\n` 折成 `\n`，两个数**恒相等**。
5. 🔴 **`工具/sync_from_d2.py:86-98` 的 `GDATA` 指向 `d:/warpforge/data`（Godot 工程）** ⇒
   跑它会把**旧数据同步回来** ⇒ **要连同脚本条目一起改，⛔ 别只删文件**；
   而且 `Unity/数据/界面布局/ui_layout/` 与 `粒子/` **已被 git 跟踪**（1,118 + 3 个文件 / 19 MB）。
6. ⚠️ **`资料/说明书/` 整目录在 `.gitignore:15` 里**（`/Unity/资料/说明书/`）
   ⇒ **任何按 `git ls-files` 做的扫描都会漏掉它 44 份** ⇒ **清点必须走文件系统扫描，别用 git**。
7. ⚠️ **两份同名 `CLAUDE.md`**：`资料/索引与盘点/CLAUDE.md` 是**解包项目的准则**（不是本项目的），
   **同名 + 在 `资料/` 下 ⇒ 新会话极易误读**。
8. ⚠️ **「快照」这个名字有歧义**：`工具/scripts快照/README.md:21` 明写「战场清单就住在这一份，用它跑」
   ＋「已同步回 `d:/2`，两边逐字节相同」⇒ 它**不是只读快照、是活源** ⇒ ⛔ **别当死件清掉**。
9. ⚠️ **`Read` 工具在大文件上会返回【盘上没有的字符】**（`A1747`）
   ⇒ 拿它读大 `.md` / `.log` 时，**别把读回来的字面当成原文**。
10. ⚠️ **`.ps1` 一律写纯 ASCII**（PowerShell 5.1 按 ANSI/GBK 读无 BOM 的 UTF-8 `.ps1`，
    中文注释会把解析搞乱：**报错行号指向不存在的行**、变量莫名是 `$null`）。
