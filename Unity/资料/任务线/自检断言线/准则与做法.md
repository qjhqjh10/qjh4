## 一、这条线是什么

**自检断言线** —— **断言本身**：`Check*` / 夹具 / 探针 / 自检宿主（`*.Run`）。

🔴 **归属判据（`资料/任务_卡组卡牌战斗.md` §头部「类型体系」原句）**：
> **自检断言线** —— 断言本身（`Check*` / 夹具 / 探针 / 自检宿主 `*.Run`）；
> **给某条业务账配断言归那条业务线**。

⇒ 本线管的是**「这条断言有没有鉴别力 / 它到底在验什么」**，
⛔ **不管**「那个业务功能对不对」（那归业务线）。
⚠️ **交界处的例子**：`A2008`（`BattleScene.cs` 4 条断言把**中文**当判据）——
账在**本线**（断言写法的问题），而它**修在战斗线的宿主里**。

**本线的三个层次**（`资料/已知的坑.md` 那 34 节反复出现的形状）：
① **断言本身写错**（期望值抄错、量纲传错、断错对象）；
② **断言与实现「同口」** ⇒ **自证**（两边一起绿，也一起错）；
③ **夹具前提不成立**（有洞棋盘 / 静默换牌 / 跨节漏状态）⇒ **验的不是那条路径**。

## 三、干一件活的流程（**六步**）

```
① 判定：这条断言在验什么？期望值从哪来？（**是原版参数，还是我们自己的常量？**）
② 判据不够 ⇒ 先补判据（派只读子代理去勘），⛔ 别凭印象改期望值
③ 写断言原文 → 交回时**必须同时给出「怎么让它红」的判别式**
④ 落盘：把「查出的事实 / 坑 / 判据」写进该去的地方（见 §五）
⑤ 收工：按 `任务线/README.md` §五 那四步改总表
⑥ ⛔ 不跑自检、不起 player（见 §四）—— 断言原文先攒着，**到同步点由主对话统一跑**
```

**五条本线的硬规矩**：
1. 🔴 **断言要盯「原版参数」，不盯「我们自己的常量」** ——
   否则就是「**拿我们的实现证明我们的实现**」（自证）。判据入口 = 解包资源 / 反编译。
2. 🔴 **「灭自证」：只断「新写法对」不够** —— 若**被测实现和它的检测器用同一个口**，
   **把两边一起改回旧写法**依然全绿。⇒ 补一条**结构上不可能同时满足**的断言
   （例：`Vector2.Distance(DropTargetWorld(s), SlotPosition(s)) > 0.5f` · `punchMin >= -1e-3` 挡「穿零」·
   「次序判别式」挡改回旧次序）。
3. 🔴 **⛔ 别写恒真的断言** ——
   本仓三种现成形状：**参数取反**（「左边缘 = 右边界 − 0/2」恒真）· **对不存在的 key 恒答 `false`**（`A1532`）·
   **求值排在它要观察的那一步之前**（`A914` 那条 `NetBattleTest.cs:886` 就是「求值在 `Tick()` 之前」）。
4. 🔴 **新断言的期望值必须「有人真跑过一遍」** ——
   `A1926` 那一条方法论账：Battle 那 6 条红里 **3 条是「新断言首跑即红」**（抄错函数名 · 抄错分量 · 前提只在
   `count==2` 成立）。**写手给出的「断言原文」必须有人真跑过**，否则等于没写。
5. 🔴 **一条断言只能有一个判据口** —— 本仓反复出现的「**两处写同一条规则**」
   （`RectOf` 三份 · `RenderedRect`/`QuadPxRect`/`PxOf` 的甲式/乙式）就是这一条的实例。

## 四、验收口径（**现行：只做不验** —— 这一条**改变了本线的节奏**）

🔴 **用户 2026-10-15 第八次收口**：「**之后暂时别检查，先完全复刻，复刻好了再检查**」。
⛔ **不跑 `*.Run` 自检**（**一条都不跑** —— 连同「按覆盖面跑对应的那几条」**也不是例行公事**）·
⛔ **连「起 player 截图看界面」也停**。
✅ **只留两件**：**秒级类型检查**（`bash d:/4/Unity/工具/typecheck.sh`，几秒 —— **不算检查**）·
**「原版 vs 我们」的缺口普查**（那是复刻的**输入**，不是验收我刚改的对不对）。
🔑 **判别句**：**这件事是在「找出还没复刻的」，还是在「验证我刚改的对不对」？** 前者做，后者停。
🕐 **什么时候才跑自检**：**复刻完成之后**统一验收；或**跨面 / 动了共用件 / 准备提交 / 收口**时
（`bash 工具/_run_8_checks.sh`，12 条，**必须串行**）—— 但那要**在待办确实做完之后**。

⇒ 🔴 **本线的日常因此变成**：
- **能做**：静态审计（读断言原文、读夹具、读判据）· **补判据** · **写断言原文 + 判别式** ·
  **修「断言自己写错」的**（那不用跑也能看出来）。
- **不能做**：跑 `*.Run` 看红绿 · 起 player 看画面 · 用「跑一遍试试」来判成因。
- ⚠️ **配套一条**：**新写的断言在落盘时要把「它一定会红的那条判别式」一起写出来**，
  否则将来统一验收时**分不清「蓝了是因为实现对」还是「因为这条断言没鉴别力」**。

## 五、形成文件说明（**任务文件怎么写**）

### 5·1 一件活一个文件，文件名 `T<两位序号>_<短名>.md`
**必须有的六节**（⛔ 别写成散文）：
```markdown
# T01 · <一句话说清这件活>

> 状态 / 起于哪一版 / 关联 A 编号

## 一、要做什么（**能一句话说清「做完之后哪条断言会真红、哪条不会再空转」**）
## 二、判据（**逐条带出处**：`文件:行号` / 断言原文 / 原版参数在哪）
## 三、我们现状（现状**逐处**给 `文件:行号` + **这条断言现在的期望值从哪来**）
## 四、怎么改（**改哪个文件、改什么**；分几步；先做哪步；**并且给出判别式**）
## 五、做完了怎么自检（**照当时的验收口径**：现在是「只跑类型检查、断言原文攒着」）
## 六、还差什么 / 判不准的（⛔ **不许猜**，写「没查到 + 我搜过哪些词/哪些包」）
```

### 5·2 什么写进**任务文件**、什么**不**写
| 写进任务文件 | ⛔ 不写 |
|---|---|
| 判据（带出处） | `CLAUDE.md` 已有的铁律（**抄一遍就会过期**） |
| 断言原文 + **判别式** | 别的任务已写过的东西（**给指针**） |
| 我们现状 + 行号 | 大段自检日志原文（**给行号 / 给「哪一节」**） |
| 「还差什么」 | 已经做完的过程叙述 |

### 5·3 详情**超过 ~150 行**就再拆
判据原文太长 ⇒ 搬进 `资料/待办判据_*.md`（**编号同一套**），任务文件只留「一句话 + 指针」。

### 5·4 收工后的归档
按 `任务线/README.md` §五。**已完成的详情文件搬进 `资料/历史/已收口_自检断言线_<日期>.md`**（原文一字不改）。

## 六、本线已知的坑（**继续加，⛔ 别删**）

1. 🔴 **`AutoFitBox` 那条教训：断「渲染宽度 ≤ 框宽」，别只比字号** ——
   字号对而**溢出**，自检照样全绿（2026-09-22 踩过）。同族：**`SetAutoFitBox` 排在 `AlignLeft` 之前
   ⇒ 对齐被抹掉**（`SetAutoFitBox` 的末句就是 `RefreshBounds()`）· **它还是「棘轮」**（同一个 Label 多说几句、
   字号一档档往下缩）· **它会顺手打开折行**。
2. 🔴 **「灭自证」断言 —— 防「两边一起改回去」**（见 §三·2）：只断「新写法对」不够，
   要补一条**结构上不可能同时满足**的。
3. 🔴 **⛔ 别写恒真的断言**（见 §三·3）—— 尤其「对不存在的 key 恒答 `false`」这一族
   （`A1532`：`UiQuadActive(key)` **对不存在的 key 恒 `false`** ⇒ 全仓所有「**这件没显示**」的断言**天然空转**）。
   ⇒ 那类断言**必须配一条 `UiHasQuad(key)` 前提**。
4. 🔴 **「检测器走另一条路」也是假绿** —— `A1329`：`WfSlider.HandleHitPx` 是**静态纯算术口**（不过 `ppu`），
   而**生产路径是实例方法**（走 `ppu`）⇒ **两者不是同一条路 ⇒ 实现写反了它照样绿**。
   🔑 这是「灭自证」那一族的**反面**：那一族防「同口 ⇒ 一起绿」，这条是「不同口 ⇒ 一个红一个绿，而**绿的在骗人**」。
5. ⚠️ **探针会「量到 0 是必然结果」** —— `A1834`：`TimeOneTextRelayout` 排在 `RebuildCardsCells` **之后**
   （字形已烘、文本未变）⇒ 量到的 **0.0 ms 是必然结果**。**探针要挪到建卡之中/之前**才有鉴别力。
6. ⚠️ **「只比中心」的断言 ⇒ 命中框缩掉一半它照样绿**（`A1835`：`CheckAt` 只读 `t.localPosition`）
   ⇒ 要补「**边界两态** ＋ **灭自证**」。
7. ⚠️ **夹具会「静默换牌」** —— `A2059`：`DeckWithTactic` / `MakeDeck` 凑牌**既不筛「能不能进卡组」也不看 id 形状**，
   而 `ResolveDeck` 事后会**静默降级**（摘牌 → `TooFewCards` → 换成自动凑的一副）
   ⇒ **症状永远是「拿不到 / 数字对不上」而不是「牌被换了」**。
8. ⚠️ **夹具会「跨节漏状态」** —— `A1519`：`ProfileData.AvatarIndex` 是 `public static` **可变字段**
   ⇒ 任何自检都能改它且可能不还原，**漏到后面每一节**。
9. ⚠️ **夹具会成为「另一条路径」** —— `A1984`（在 `项目任务.md` §29·b）：用 `Place(s3)` + `Place(s1)`
   ⇒ 左侧下标 `{0,2}`、**1 号是洞** ⇒ `BoardSlots.IsContiguous` 假 ⇒ 下面那次 `PlayCard(..., 2)`
   走 **degraded 分支**（「请求哪格写哪格」）⇒ **这条断言验的不是我们以为的那条路径**。
10. ⚠️ **自检宿主会「把运行时对象烘进场景」**（`A1534`）——
    跑 `*.Run` 之后**要 `git diff --numstat` 对一眼**（那些宿主一律 `NewScene` 建场 → 收尾 `SaveScene()`）。
11. ⚠️ **报绿的汇总行不能只看一行**（`ruleprobe` 那族）：**判据是「解析差异 0 行」只等于「与基线一致」**，
    不等于「对」；且**构建失败时旧 dll 会照样跑出「看起来全绿」的读数**（见 `工具文档线/准则与做法.md` §六）。
