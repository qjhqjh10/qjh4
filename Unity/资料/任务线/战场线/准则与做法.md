## 三、干一件活的流程（**六步 + 铁律 15**）

```
① 读「本任务文件」→ 它里面有判据与出处
② 判据不够 ⇒ 先补判据（读反编译 / dump 原版场景 JSON / 派只读子代理去勘），⛔ 别凭印象动手
③ 改生成器 / ArenaBuilder / C# → 立刻跑 `bash d:/4/Unity/工具/typecheck.sh`（**秒级，唯一挡「编不过」的**）
④ 重跑 → 出图 → 量 → 与「原版实拍」比
⑤ 落盘：把「查出的事实 / 坑 / 判据」写进该去的地方（见 §五）
⑥ 收工：按 `任务线/README.md` §五 那四步改总表
```

🔴🔴 **铁律 15（用户 2026-10-15 点名）：一场一场做，⛔ 不许 `--all` 一把梭。**
```
gen_unity_arena_manifest.py --arena <场>          # ⚠️ 真身在 工具/scripts快照/，⛔ 不是 d:/2 那份
WF_ARENA=<场> … -executeMethod ArenaBuilder.BuildFromCLI      # 写【场景】
WF_ARENA=<场> … -executeMethod ArenaBuilder.BuildPrefabFromCLI # 写【prefab】
WF_ARENA=<场> … -executeMethod ArenaBuilder.RenderPreviewFromCLI  # 出图
bash 工具/arena_diff_phases.sh <场>                # 3 相位
python -I -X utf8 工具/arena_diff.py <场> [--top N] [--out DIR] [--ledger TSV]
```
🔴 **改生成器 ≠ 13 场都要重跑** —— 先判「**这场真的变了吗**」：**逐场比 `len(meshes)` / `len(particles)`**，
⛔ **别看 diff 行数**（一列改动就能刷出几百行）。
（先例：一次生成器修复，已跑的 10 场里**只有 1 场真的多了对象**，另外 9 场只是 `matQueue` 那一列变了 ⇒ 白跑。）

**六条本线的硬规矩**：
1. 🔴 **量表必须开 `WF_PSFIXSEED=1`** —— 不开时**同一份构建**两次能差 **6%**（arena3 实测 55.91 / 59.26），
   比要判的偏差还大 ⇒ **表里的数字每次都不一样、根本没法追踪变化**。开完**逐像素可复现**。
   ⚠️ 剩下的不确定只剩**原版那侧的单帧相位**（原版 PNG 是别人渲的，种子改不了）⇒ **别抠单点**。
2. 🔴 **「改完战场 → `BuildAll` → 渲 → 量」是这台机器上唯一的回归闸门**；
   **重跑任何一场之后必须跟一次 `BattleScene.BuildAndSaveScene`** —— ⚠️ §27 起**理由换了**（战场改成运行时实例化、
   `Battle.unity` 只有一份），**动作照旧要做**。13 场整体用 `bash 工具/_build_battle_scenes.sh`（**串行**）。
3. 🔴🔴 **跑任何「会存盘的自检宿主」之前，先留一份场景副本；跑完立刻 `git diff --numstat` 对一眼。**
   那些宿主一律 `NewScene(EmptyScene)` 建场 → 收尾 `SaveScene()` ⇒ **跑一次就把对应场景整个重建后覆盖存盘**。
4. 🔴 **`SaveOrReuse`（`ArenaBuilder.cs`）只对「本轮被重建的场」刷写、从不校验磁盘 vs 当前代码**
   ⇒ **13 场的 `.mat` 实际是不同代码版本的结果**（铁证：同一份原版材质 `Glow Additive Extra Color` 的 `_Color`
   在 3 个场给出 3 套值）。**判据 = 磁盘 mtime 就是这批产物的版本号。**
5. 🔴 **判据是「产物 mtime + `grep -c` 你改的字段」**，⛔ **别信构建日志**。
6. 🔴 **`wf_arena_*.bundle` 在 `.gitignore` 里**（整个 `StreamingAssets/WarpforgeVFX/`）⇒ **新克隆的仓库没有它们**：
   反射与一批战场 shader 会**出声**退回旧路径 ⇒ 先跑 `python 工具/extract_mirror_shaders.py`（**务必看到 `[6b]` 那行**）
   ＋ `python 工具/extract_missing_shaders.py --arenas`。

## 五、形成文件说明（**任务文件怎么写**）

### 5·1 一件活一个文件，文件名 `T<两位序号>_<短名>.md`
**必须有的六节**（⛔ 别写成散文）：
```markdown
# T0N · <一句话说清这件活>
> 状态 / 起于哪一版 / 关联 A 编号

## 一、要做什么（**能一句话说清「做完之后画面有什么不同」**）
## 二、判据（**逐条带出处**：资产路径 / `文件:行号` / 原版对象名 + 字段名）
## 三、我们现状（现状**逐处**给 `文件:行号` / 工具读数）
## 四、怎么改（**改哪个文件、改什么**；分几步；先做哪步）
## 五、做完了怎么验（**照当时的验收口径**：现在是「只跑类型检查」；找差异走 §二的工具）
## 六、还差什么 / 判不准的（⛔ **不许猜**，写「没查到 + 我搜过哪些词/哪些包」）
```

### 5·2 什么写进**任务文件**、什么**不**写
| 写进任务文件 | ⛔ 不写 |
|---|---|
| 判据（带出处） | `CLAUDE.md` 已有的铁律（**抄一遍就会过期**） |
| 我们现状 + 行号 / 工具读数 | 别的任务已写过的东西（**给指针**） |
| 改动清单 | 大段原版场景 JSON / 反编译原文（**给 `文件:行号`**） |
| 「还差什么」 | 已经做完的过程叙述 |

### 5·3 详情**超过 ~150 行**就再拆
判据原文太长 ⇒ 搬进 `资料/待办判据_*.md`（**编号同一套**）或那份 `普查产出_*/` 报告，任务文件只留「一句话 + 指针」。

### 5·4 收工后的归档
按 `任务线/README.md` §五。**已完成的详情文件搬进 `资料/历史/已收口_战场线_<日期>.md`**（原文一字不改）。

## 六、本线已知的坑（**继续加，⛔ 别删**）

> 全项目的坑在 `资料/已知的坑.md`；下面是**这条线自己的**（正本 `战场场景线_交接.md` §三 更全）。

1. 🔴 **`CAB` 同名互斥 ⇒ 同名 bundle 会整包被顶掉**（`wf_arena_shaders.bundle` 就是这么丢的，32 份材质拿不到原版 shader）。
   ⇒ **「随包 bundle 取不到」先怀疑包没加载成功，别先怀疑资产不在。**
2. 🔴🔴 **bundle 里的 shader 落不了工程资产** —— 材质要 `AssetDatabase.CreateAsset` 落盘，而 bundle 里的 shader
   **落不下**（症状：`Could not extract GUID …` ⇒ `m_Shader` 悬空 ⇒ arena2 亮度比 `1.022 → 1.084`，A/B 抓的）。
   ⇒ 现在**只接受「自建 / 工程自带」，其余退回兜底并出声**。
3. 🔴 **这台工程的 URP 实时阴影链整条没跑** —— `①-l` 把标志**逐对象接对了之后画面逐格不变**

4. 🔴 **「写完当场回读」抓不到「没落盘」** —— 资产要 `AssetDatabase.SaveAssets()` 才真写文件；
   **判据必须重开文件读一遍**。
5. 🔴 **生成资产别用 `AssetDatabase.GenerateUniqueAssetPath` +「每次先删光」成对使用** ——
   那等于每跑一次换一批 guid，而**早先存过盘的场景还指着旧 guid**。

7. ⚠️ **同一个对象有多份实例，先解父链 / 读用途字段**（铁律 4），再谈「谁权威」。
8. ⚠️ **实况优先于解包字段**（铁律 4）：同一处**跑得到就跑**；跑不到就**如实说「没跑到实况」**。
