## 二、② 拆开看（三小半，别混成一条）

**(a)「第四张被切在屏幕外」不是缺陷。**
参考图**右侧同样有一张被切**（带 `练习` 标签那张只露出一条）。
我们代码里早就按这个结论写了：`MainMenuRuntime.cs:1713` 自陈
「⇒ `514×830 ≈ 535×848.8 = 1×2` ✓，且第四张在右缘被切（**原版就是横滚、切是对的**）」。

**(b)「尺寸不齐」也不是缺陷 —— 我们用的就是原版那套档位。**
`MainMenuRuntime.cs:1705-1718`：
`CardW 535` · `CardH 414.4`（1×1）· `CardHTall 848.8`（1×2 = 2×414.4 + 20 缝）· 列起点 `205` · 列距 `555`
—— 与原版 prefab 的 `FlexibleGridLayout rows=2 columns=20 itemSize 535×414.4 spacing (20,20) pad L38` 逐值一致
（出处 `资料/主菜单_原版规格.md` §二·4 / §9·1）。
**原版本来就是两种尺寸并排**：`Base Game Mode Container 1x1` = 535×414、
`1x2` = 535×848.8（root 上挂 `FlexibleLayoutSizeOption(1,2)` 跨两行）
⇒ 参考图里「一列两张半高卡叠着」= 两张 1×1 落在同一列，**不是画错**。

**(c) 🔴 真差异 = 【顺序】（不是尺寸、不是基线）。**
- 参考图那一排：`[小冲突 1×2] [ … 1×2] [Draft/Aeldari 1×2] [最右一列：练习 / 教学 两张 1×1 叠着]`。
- 我们：`[最左一列：练习 / 教学 两张 1×1 叠着] [DRAFT MODE 1×2] [小冲突 1×2] [RA… 1×2 被切]`。
⇒ 两组**用的是同一套网格语义**，差别是**这张 1×1 的对子落在最左还是最右**（= 模式在清单里的次序）。
⚠️ **次序判据在 liveop 服务端**（`A1635`：本地拿不到）⇒ 参考图给的是**一条真实例**，
**不是能推出来的规则**；⛔ 别把它当成「原版次序就是这样」写死。
