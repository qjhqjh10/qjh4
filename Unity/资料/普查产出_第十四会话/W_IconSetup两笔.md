## 二、灭自证（**每笔各一条**，写清「改哪两处会一起变绿」）

### 1. `A1421` → `⑥b`（`:750-765`）

**改哪两处会一起变绿**（这条判据有**两个**天然恒绿的写法）：

| # | 写法 | 为什么会恒绿 |
|---|---|---|
| ① | 把 `DataPlanFileAbs` 抄成 `PlanFileAbs` 那个值（常量指同一个文件） | 那就是「自己跟自己比」，**永远相等** |
| ② | 两边都取不到 `"cards"` 键时，拿 `==` 直接比（断言写成 `bodyA == bodyB`） | **`null == null` 恒真** —— 生成器哪怕把键改成别的名字，这条也绿 |

**为什么挡得住**：`⑥b` **不另抄一份期望值**，而是拿**同一份真内容**（`bodyA`）造四个变体，
要求**同一个比较器** `SameCardsBody` 分别给出**正确**答案：

```
自身            ⇒ 必须「相同」（挡「恒不同」那种写法）
中间翻一位      ⇒ 必须「不同」（**长度不变** ⇒ 连「只比长度」的退化写法也一起挡了）
截掉 100 字符   ⇒ 必须「不同」（挡「只比前缀」的退化写法）
null 与 null    ⇒ 必须「不同」（⛔ 就是上表 ② 那个洞）
＋ 断言两条路径**确实不同**（⛔ 补上表 ① 那个洞）
```
⇒ **「恒绿」与「认得出四个变体」结构上不可能同时成立**。形状照 `A1409` 的 ④b（同一份真表造「改回去」的副本、过同一个谓词）。

### 2. `A1423` → `④c-b`（`:589-601`）

**改哪两处会一起变绿**：

| # | 写法 | 为什么会恒绿 |
|---|---|---|
| ① | 把 `Check` 写成恒真（`Check(true, …)`） | 主判据形同虚设 |
| ② | 把常量写成 **`KnownZhGaps.Length`**（自引用：`Check(KnownZhGaps.Length == KnownZhGaps.Length)`） | **永远真** —— 而且它**看起来很认真**（像「有判据」） |

**为什么挡得住**：守卫做成**纯函数** `GapTableOk(table, declared)`，`④c-b` 拿**同一张真表**造**三个变体**
要求它分别给出正确答案：

```
真表 +1 条（WithExtra）        ⇒ 必须【拒】（挡「往里加一条」）
真表 −1 条（WithoutLast）      ⇒ 必须【拒】（挡「删了表项没改常量」）
真表 + 声明值写错（15+1）      ⇒ 必须【拒】 ← 🔴 **这一格就是挡上表 ①② 的**
真表本身                       ⇒ 必须【过】（否则 ④c 本来就红）
```
第三个变体是关键：**任何忽略 `declared` 的写法**（恒真 / 自引用 / 只比表长）在「声明值写错」这一格上**必红**。
⇒ 「守卫恒绿」与「三个变体全被拒」**结构上不可能同时成立**。

🔴 **如实说清这条挡不住什么**：它**挡不住「表项 + 常量同时改」** ——
那把一条新缺口**合法化**了（表从 16 条、常量也写 16 ⇒ 三格全过）。
一个文件里的机械保证到此为止；它能保证的是「**只改一处必红**」＋「**守卫不能自引用/恒真**」，
双改则必然在 diff 里露出**两处**（这正是调度台要的「两处一起改、表才不会变成谎话」）。
