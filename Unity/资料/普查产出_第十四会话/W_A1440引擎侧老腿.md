### 1·1 「空表」为什么现在能被区分出来

老形状（`A1440` 之前）**只有一种问法**：

```csharp
var ops = EffectText.WillRunOps(c);
foreach (var op in ops)                       // ← ops 是空表时，这个循环一次都不进
    if (!EffectText.OpHasMechanism(op, c.Faction, pool, out why, out imprecise))
    { 卡点++; break; }
// ⇒ 空表 = 0 个卡点 = 这张卡算「全通」                      ← 【空转 ⇒ 全绿】
```

修法 = **两条【独立的腿】**对着账，**空表时把它们分开**（口径与 `工具/ruleprobe/WillRun.cs` 逐档相同）：

- **腿 A（执行层）** = `EffectText.WillRunOps(c)` —— 引擎的**注册结果**（**老口径那个 `foreach` 原样留着**，
  只用来并排对照，⛔ 不再当结论）；
- **腿 B（卡面）** = `desc` 分句 ∪ `keywords` **原文条目**里 `Head: body` 且 `body` 主解析器解得出 op 的段
  —— **只借归一函数**（`EffectText.Split` / `StripLeadingIcons`），**不借任何注册结果**。

⇒ 一张卡收 0 条 op 时，三种可能**分开报**：

| 档 | 判据（`MeasureWillRunRow:8931-8940`） | 是缺陷吗 |
|---|---|---|
| **① 本来没正文** | 卡面上没有任何「可执行正文段」 | ❌ 不是。**但必须报出来**，⛔ 不混进「全通」 |
| **② 收漏了** | 卡面**写着**可解析的正文、执行层**一条都没收到**（`Orphans.Count > 0`） | 🔴 **是**（`A1386` 那种） |
| **③ 未归因** | 收 0 条、卡面**没有** `Head:` 段，但 `EffectText.Parse(整条 desc)` 解得出 op | ⚠️ **不判**，如实标出 |

再加**段级三档**（`ClassifyWillRunFace:9069`）与**⑤ 无头档**（`AddWillRunHeadless:9008` /
`ClassifyWillRunHeadless:9036`）。⑤ 的三道闸（`CardDef.HandledByOtherLayer` / `EffectText.AtTurnClauses` /
`CardDef.CostWhens`）**全部转调引擎自己的公开面**，报表里**一行新文法都没写**。

### 1·2 与探针 `willrun` 的口径怎么对齐的

**逐档对齐**（读 `工具/ruleprobe/README.md` 的 `## willrun` 一节 + `WillRun.cs` 现读），
连**常量字面值**都取同一个（`本来没正文` / `收漏了` / `未归因` · `收漏` / `付费段` / `同头两写` ·
`无消费点` / `回合起止` / `降费触发器`），并且这几样**逐条同款**：
