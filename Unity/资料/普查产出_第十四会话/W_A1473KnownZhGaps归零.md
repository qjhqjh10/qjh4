## 二、第三处（守卫自己的边界 bug）

### 1. 表为空时**原先会怎么崩**（那一行 = `HEAD` 版 `WithoutLast` 的第 1 句）

```csharp
var r = new string[t.Length - 1];        // t.Length == 0  ⇒  new string[-1]  ⇒  抛异常
```

**执行证据（不是引用规范 —— 真跑了一遍）**：在 `/tmp/wf_neg/` 用一个 net8 控制台把**改前 / 改后两个 `WithoutLast` 逐字抄进去**跑（`dotnet run`）：

```
=== 旧写法（HEAD 版）在【空表】上 ===
  抛 System.OverflowException => 4c-b 那一格崩、整个 Verify() 挂掉
```

⇒ **成因**：`t.Length - 1` 在 `int` 上**不会下溢**，得到 `-1`；`new T[-1]` 由 BCL 抛 **`System.OverflowException`**
（不是 `IndexOutOfRangeException`、也不是返回空数组 —— 我第一版 python 复刻里 `['x'] * -1 == []` 是 **python 的语义**，
**别拿它当 C# 的结论**）。
⇒ **为什么这次才现形**：表 15 → 1 时 `WithoutLast` 拿到的是长度 1 的表（合法）；**1 → 0 时第一次拿到空表**。
⚠️ 而且它崩的是 `Verify()` **整个方法**（`④c-b` 那句在 `try` 外、异常没人接）⇒ 症状是「**一条断言都没跑完**」，
而不是「④c-b 红」—— 这正是它比一条红更坏的地方。

### 2. 我怎么守的

```csharp
if (t == null || t.Length == 0) return null;   // 「−1 条」无从构造 ⇒ 交给 `GapTableOk` 的 null 判据去拒
```

**为什么返回 `null`（而不是「钳到 0」= 返回空表）**：④c-b 的第二个变体要求**这个变体必须被拒**；
若返回**空表**，`GapTableOk(new string[0], 0)` 恰好 **= true** ⇒ ④c-b 变体二**红**。
`null` 是「**这一变体无从构造**」的如实表达，而 `GapTableOk` 的**第一句就是** `table != null && …`
（那个 null 判据本来就在，不是我加的）⇒ **`null` 恒被拒**。
- ✅ 非空表的行为**一字未变**（跑过回归：长度 1 的表 −1 ⇒ 长度 0，对常量 1 被拒 = true；长度 2 ⇒ 长度 1，对常量 2 被拒 = true）；
- ✅ `null` 入参也不 NRE（旧写法会 NRE —— 但今天没有 `null` 调用点，这是**顺带**加固）。
