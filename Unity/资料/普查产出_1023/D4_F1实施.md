## ③ 没查清（**这些都没猜着改**）

1. 🔴 **shader 能不能过编译，本机**验不了**（typecheck 只编 C#）。两个待验点：
   - **`UsePass` 能否解析**到 `Universal Render Pipeline/Unlit/DepthOnly` / `…/Unlit/DepthNormalsOnly` / `…/Simple Lit/ShadowCaster`（名字我逐个在 17.3.0 包里核过，但**没跑过 Unity**）。
   - **`CGPROGRAM`（主 pass）与 `HLSLPROGRAM`（UsePass 进来的 URP pass）混用** —— 我的理解是允许的（`CGPROGRAM` = `HLSLPROGRAM` + 自动 `#include UnityCG.cginc`），但**没验**。
   - 若第一跑出现**满屏品红 / shader 报错**，排查顺序：① 把三个 `UsePass` 逐条注掉、看是否恢复（定位是哪一条）；② 若 `ShadowCaster` 那条不行，改手写（判据：`ShadowCasterPass.hlsl` 的 `ApplyShadowBias` 写法）；③ 若 CG/HLSL 混用报错，把主 pass 改成 `HLSLPROGRAM` + 显式 `#include "UnityCG.cginc"`（逐字等价）。
2. ⚠️ **SRP Batcher 兼容性**：主 pass 的属性是「裸 uniform」，UsePass 进来的 URP pass 用 `UnityPerMaterial` CBUFFER ⇒ 这个 shader **大概率不能进 SRP Batcher**（Unity 会打一条兼容性提示，通常只是不批处理、不报错）。**没验**；若真报错，解法是把主 pass 的属性也收进 `CBUFFER_START(UnityPerMaterial)`（会动主 pass，风险另算）。
3. ⚠️ **`_Cull=2` 是否真的进了材质**：`_Cull` 是本批**新加**的属性，`new Material(sh)` 会取默认值 2 ✔（推断，按 Unity 的 Properties 默认值语义）；没跑起来读。
4. ⚠️ **`MotionVectors` 没加**：原版有，我们没有「开运动矢量/TAA」的需求。若将来开 TAA，卡体会缺运动矢量（会闪）。
5. ⚠️ **URP 深度贴图**：加了 `DepthOnly`/`DepthNormalsOnly` 之后，理论上卡体进 `_CameraDepthTexture`/`_CameraNormalsTexture`；**没在运行时验**（批处理跑不了）。
6. ⚠️ 上一轮遗留的 `_USE_BLEND` 语义**仍未查清**（与本批无关）。

## ⑤ 顺手发现（只报不改）

1. 🔴 **`SubtreeQueues()` 的语义被本批收窄了，`BattleScene` 里那条断言的含义跟着变**：
   `Editor/BattleScene.cs:16263-16278`（`A1672②`「场上每张卡的**每一层**都在它自己那一段里」）拿 `Min/Max(SubtreeQueues())` 判 —— 本批之后它**不再包含卡体**。
   ⇒ 断言仍然会绿（因为卡体不再是 2000 以外的号），但它**不再能证明「卡体被正确对待」**。
   建议（**归 A4/主对话**，那是他们的文件）：在该段补一条体专属判据 —— `body3D.sharedMaterial.renderQueue < 2500`，与本批 `CardBaseDemo` 的 ①④ 同一条判据。
2. 🟢 **顺带治掉一个老隐患**：以前 `SetQueue` 若在溶解进行中跑到卡体上，会把渲染器换成 `QueueMaterial` 的克隆、而 `SetDissolveAmount` 写的是 `_dissolveMat` 原件 ⇒ 溶解**静默卡住**。现在 `StampQueue` 直接跳过卡体，这条路径没了。
3. ⚠️ **`Blend One Zero` + `ZWrite On`** 让卡体真正进了不透明 pass：它与**别的卡体**的先后从此由**深度**决定（不再由队列段）。
   静态看是对的（与原版同模型：原版也是不透明 + 按距离/深度），但「两张卡在出牌飞行中重叠」那一瞬的表现**必须真机看一眼**（`CardBaseDemo` 的截图是静止档，看不出）。
4. ⚠️ **`ShadowCaster` 用的是 Simple Lit 那份**：它的 `_ALPHATEST_ON` 未开 ⇒ 卡体按**整块网格**投影（与原版一致：原版 base 材质 `_AlphaClip=0`）。
5. 本批之后，卡体的 `renderQueue` 恒为 **2000**（正常）/ **2450**（溶解），与「一张卡一段队列」（2962–3000）**完全解耦** —— 若日后有人看到「卡体的队列没跟着卡走」当 bug 修，请先读 `StampQueue` 里那条判据注释。
