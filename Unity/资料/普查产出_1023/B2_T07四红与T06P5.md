## 二、证据（逐条）

### ① `GOF38 Proper Killy` —— SO 多 `+2 melee`，其余一致

- **原版 SO**（`资料/普查产出_1018/allcards_1350/cards_raw.json`，`uniqueId GOF38`）a0.0：
  `chosenAbility=30 buffOthers` · `buffEffect{buffType=3 addTrait, trait=220, meleeAttackChange=2, untilEndOfTurn=1}` ·
  `tgt{targetsAffected=10 allFiltered, friendlyUnits=1, includeHero=1, includeMinions=0}`。
  枚举判据：`BuffType.addTrait = 3`（`d:/2/Warpforge_code/Scripts/Assembly-CSharp/BuffType.cs`）·
  `DefinedTrait.bloodThirst = 220`（`DefinedTrait.cs:21`）· `TargetsAffected.allFiltered = 10` /
  `friendlyHero = 120`（`TargetsAffected.cs`）。
- **官方本地化**（`d:/4/Unity/数据/游戏数据/官方本地化_en+zh-CN.json` 的 `Card_Description/GOF38`）：
  `((Your_warlord_gains_trait_x_this_turn,[[bloodThirst]]))` —— **没有** `+2 melee`。PnP 卡图同句。
- 🔴 **`melee+2` 不能当序列化残留糊过去**：全池 **26 条** `buffType=3` 同时带 stats，其中至少 3 条卡面**明写**
  那些 stats（`Pariah Vanguard`「Give +2 [Melee] and Vanguard」`bt3 trait=980 melee=2` · `Thunderous Charge` ·
  `Slaanesh's Spawn`）⇒ 引擎确实会把它算进去。
- 🔴 **同文孪生卡 `Proper Hunt`（同一句卡面）**：`stats = {}`、`targetsAffected = 120(friendlyHero)` ⇒
  Proper Killy 的 `melee+2` 与 `allFiltered` 是**只在这一张上多出来的**。
- **目标侧不冲突**：本游戏每方恰好 1 位英雄 ⇒ `allFiltered + includeHero + includeMinions=0` ≡ “your warlord”。
- **我们**：`gain/0|blood thirst` 目标 `own|warlord`（`工具/ruleprobe/基线/out_baseline.txt:637`）。
- ⇒ **判定不变（留红）**，定性 = 「原版冲突（按卡面）」。要改成按 SO 补 `+2` 属**行为改动**，须主对话拍板。

### ② `Bitter Blows`（`36892cd…`）a0.1 —— 模板残余

- **step0 已经 ✅ 且是对的**：`chosenAbility=110` = **`AbilityEffect.destroy`**（`AbilityEffect.cs:25`）+
  `targetSelectMethod=6` = `TargetSelectMethod.lowestHealth` + `tgt{allFiltered, enemyUnits=1, includeMinions=1, maxTargets=1}`
  ⇒ 「摧毁生命值最低的敌方部队」= 卡面 = 我们的 `destroy … PickMost=-health`。
  （同 step 上带着的 `damageCriteria 2-4` / `buffEffect{buffType=8 markOfChaos}` 是**共享结构体的残留** ——
  destroy 分支不读它们；这几项也正是 `Warmaster` step0 的同一组数。）
- **红的只是 step1**：`buffOthers` 对「友方英雄」打 2-4 + 治 2 + 生命+2。
  它**逐字节等于 `Warmaster`（`97e95944…`）的 step1**，且 **2022 时代快照与当前 build 完全相同**
  （`d:/2/远端缓存_旧profile_1013/导出/cards_1195_2022时代.json` 对照）⇒ 复制模板留下的残余。
- ⚠️ **没闭合的那半截（如实标着）**：`targetsAffected=90 (targetIfMeetsCriteria)` 在
  `d:/2/tools/decomp_full/AbilityLogic__GetTargets.c:747-760` 的 `0x5a` 支只把**传入的上一批目标**
  `AddRange` 进来；**后续是否再按 criteria 过滤没读到**。若不过滤，原版会把它作用在**上一步那个敌方部队**上
  （净 -0..2 血 +2 生命）—— 那也不是「我们缺一条友方 buff」。
- **缺什么 / 去哪拿**：`AbilityLogic__PlayAbility.c` 里 `local_170 = *(param_3 + 0x20)` 这个「上一步目标」
  在 90 那支之后有没有过 `BoardAnalysis__MeetsCriteria`；必要时在游戏里跑一张 Bitter Blows 看有没有治疗数字。

## 五、顺手发现（只报不改）

1. **`AbilityEffect.destroy = 110` 这个枚举值**解释了一批「原版 `我们缺`」的形状：`destroy` 步骤上常带着
   `damageCriteria` / `buffEffect`（共享结构体残留），判据只看 `chosenAbility` + `targetCriteria` 就够。
   建议对账工具将来对 `chosenAbility ∈ {110 destroy, 120 jam, 130 stun}` 忽略同块的伤害/buff 载荷。
2. **`proper Hunt` 与 `Proper Killy` 是同一句卡面的孪生卡**（一个 `ta=120`、一个 `ta=10` 且多 `melee+2`）——
   这类「同文异数据」是查 SO 污染的最好对照组，建议以后遇到冲突先找孪生卡。
3. `Warmaster`（Chaos 督军）的 abilityLogic **在 `Bitter Blows` 上被复用了一份** ⇒ 同一份模板可能还被别的卡引用，
   下次清残留时按「签名重复 ≥2 张」扫一遍比逐张读快得多。
