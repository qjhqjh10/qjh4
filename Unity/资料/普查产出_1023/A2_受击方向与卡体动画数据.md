## ② 证据

### 2.1 `GetPushBackFactor` 的档位（原版原值）

`d:/2/tools/decomp_full/SupportMethods__GetPushBackFactor.c`：

```
if (param_1 == 2) return DAT_1834b2bb8;   // 1.0
if (param_1 == 3) return DAT_1834b3090;   // 1.5
return DAT_1834b2bb4;                      // 0.5
```

三个常量从 `GameAssembly.dll` `.rdata` **4 字节 float 实读**（`工具/read_literal.py`）：

| 地址 | 值 | 档 |
|---|---|---|
| `0x1834b2bb4` | **0.5** | 尺寸 0（近战 ≤ 3） |
| `0x1834b2bb8` | **1.0** | 尺寸 2（4…7） |
| `0x1834b3090` | **1.5** | 尺寸 3（> 7） |

尺寸本身 = `SupportMethods__GetUnitSize.c:11-16`：`m = CurrentMeleeAttack; m <= 3 ? 0 : (m <= 7 ? 2 : 3)`
（**只有 0/2/3，永不返回 1**，判据是**近战**攻击）。
⇒ 我们的 `CardFeel.PushBackMagnitude` = **0.5 / 1.0 / 1.5**，与旧值**一致**（这一半本来就是对的，本件没动）。

### 2.2 方向（这次改的那一半）

`CardScript__ReceiveAttackAnim.c`（逐句）：
```
size   = SupportMethods.GetUnitSize(attacker);
factor = SupportMethods.GetPushBackFactor(size);
dx = self.position.x - attacker.position.x;
dz = self.position.z - attacker.position.z;
len = sqrt(dx*dx + dz*dz);
if (DAT_1834b2f44 (=1e-5) < len) dir = (dx/len, 0, dz/len);   // y 恒 0
else                            dir = <静态常量 Vector3>;      // 读不出名字
DOPunchPosition(self.transform, dir * factor, 0.4, 8, 0.3, snapping:false).SetDelay(...).OnComplete(...)
```
⇒ 我们落地为 `CardFeel.PushBackDir(victimPos, attackerPos)`：
`d = victim − attacker`，**`d.z = 0`**（**换轴**：原版棋盘在 XZ 地面、我们画在 XY 平面，z 是景深 —— 这是换算不是原样，已写进注释），
`len ≤ 1e-5` ⇒ 返回 `Vector3.up`（沿用 `Flat` 的既有退路；原版那个常量读不出名字）。
时长/vibrato/弹性 = `PushBackDuration/Vibrato/Elasticity` = **0.4 / 8 / 0.3**（既有，未动）。

## ③ 没查清 / 降级后玩家看到什么

1. **原版两点重合时那个「静态常量向量」读不出名字**（`DAT_1842da2a8 + 0xb8` 是某个类的第一个静态 `Vector3`）。
   我们沿用 `Flat` 的 `Vector3.up`；原版若是 `zero`，差别只是「要不要弹一下」（幅度 0 vs 0.5/1.0/1.5）。
   **没查清**，已写进 `PushBackDir` 的注释。
2. **轴换了**：原版方向在 XZ 地面、y=0；我们是 XY 平面、z=0。这是**换算**（我们的棋盘不在 XZ 地面上），
   不是原版原样。判据：`CardFeel.MeleeAttack` 早已是同一套换算（文件头「位移方向」那条）。
3. **`cardanim_clips.json` 载不到时玩家看到什么**（显式降级，`LogError` 一次 + 每条 `LogWarning`）：
   技能动画那一件**照播**，但 `sp = ep = pt = 0`（`PositionOption.self` = **施法者自己那一格**）且**不位移**
   ⇒ 本该飞向目标（`Healing_Projectile` 0→2）/ 落在敌方督军（`Trait_GainQuest` 4）/ 落在棋盘中心
   （`CreateCard GSC` 5）的那几件，会**贴在单位身上**播完。⛔ 不会静默（自检断 `CardAnimClips.Loaded`）。
4. **生成器跳过 32 个 CardAnim**（`cardanim_to_asset` 里没有 `sourceMono`/`targetName` 的那批，
   如 `BattleHonourAnim` / `BlastAnim`）—— 它们是**天赋动画**，不在卡池的两桶里，今天没有消费者。
   将来若有用到，`PlacementOf` 会出声并降级。
5. **反击那条 `Hit` 的 `hitOfCounter` 只认「紧挨着的上一条是 `Retaliation`」**。若某天引擎把反击拆成
   `Retaliation → Attack → Hit`，这条就不成立了（方向会退回去）。没查清引擎将来会不会拆。

## ⑤ 顺手发现（只报不改）

1. 🔴 **生成器第一版读错了字段**（`cardanim_to_asset[...]["dump"]` = **prefab 的 GameObject**，
   `animInfo` 在 `["sourceMono"]` 上）—— JSON 照样生成、形状照样对、**全部字段是 0**。
   **是「16 行逐值比对」这条断言抓出来的** ⇒ 这条断言值得留着（它证明的不只是「搬对了」，也证明「读的是对的那个文件」）。
2. 🔴 **同一 prefab 名被多张 `CardAnim` 共用、参数不同** —— 现读 **215 组**（例：
   `Trait_GainQuest` 之于 `Trait_GainQuest_self`(sp=0) 与 `…_enemywarlord`(sp=4)）。
   ⇒ **任何按 prefab 名查 `AnimInfo` 的写法都是错的**。今天仓里**只有** `VfxMap.SharedRangedVfxDuration`
   还是按 prefab 名（那张表只放「共享件」，那些没有逐卡歧义，暂时安全）。⛔ 别把这条经验用到别的表上。
3. `数据/游戏数据/animinfo_lookup.json`（418 条，8 月那位）**已经被这份新表覆盖并超越**（1,067 条）。
   建议标注它作废 / 只作历史（⛔ 别再有人拿它当判据 —— 本件的 16 行里有 9 行在它里面查不到）。
4. `CardFeel.HitReact` 现在**只剩三个调用点**：`BattleScene` 的自检探针两处 + `CardBaseDemo` 一处
   （都不传真实攻击方）。生产路径已全部改走 `HitReactFrom` ⇒ 若将来想让「不知道攻击方」那条彻底不出声，
   得先决定自检探针要不要也换口。
5. 原版 `BattleManager._ResolveUnitShake_d__472__MoveNext.c:139-147` 是**同形的第二处**后坐入口（W63 的注释提过）。
   本件只改了 `CardScript.ReceiveAttackAnim` 那一条 —— **`_ResolveUnitShake` 在我们这边有没有对应物、要不要也走 `PushBackDir`，没查**。
