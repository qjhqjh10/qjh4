## ① 结论

### 1·A 先说最容易误读的一件事

台账那一档的名字叫 **「导出整个丢了」**，`effect_index.json` 里也照抄成
`只有原版有内容 —— 导出整个丢了`。**这个措辞会把人带偏**：我逐件数过，
**没有一件是对象丢了**。那 4 件的 `ParticleSystem` 个数、发射开关、发射率、循环、
`playOnAwake`、`maxParticles` **两侧逐项相同**。

真正丢的是**画面**（sweep 的像素），不是**资产**。
⇒ 建议把这个判定名改成 **「原版有画面、我们没有」**（它衡量的是渲染结果，不是导出完整性）。

### 1·D R1 —— `Hidden/LUTBlender` A/B

**静态判据三方齐全，而且我这次是独立重解了一遍**（不是照抄旧结论）：

1. **属性表 3 条**（`wf_arena_2.bundle` 的 `Shader pathID = 42`，本件现读）：
   `_LUT1` Texture / `_LUT2` Texture / `_Blend` Range
2. **pass 状态**：单 pass、无名、无 tags；`srcBlend=1 (One)` / `destBlend=0 (Zero)` /
   `blendOp=0 (Add)` / `colMask=15 (RGBA)` / `zWrite=1` / `zTest=4 (LEqual)` / `culling=2 (Back)` /
   `zClip=1` / `rtSeparateBlend=False`；SubShader `RenderType=Opaque`。
   → 与自建 `WarpforgeVFX/Shaders/WFLUTBlender.shader` 的 `Blend One Zero / ZWrite On / ZTest LEqual / Cull Back / RenderType=Opaque` **逐项一致**。
3. **像素着色器（反汇编，本件现跑）**：
   ```
   sample r0.xyzw, v0.xyxx, t1.xyzw, s1     // t1 = _LUT2
   sample r1.xyzw, v0.xyxx, t0.xyzw, s0     // t0 = _LUT1
   add    r0.xyzw, r0.xyzw, -r1.xyzw        // _LUT2 − _LUT1
   mad    o0.xyzw, cb0[3].xxxx, r0.xyzw, r1.xyzw   // cb0[3].x = _Blend
   ```
   ⇒ `o = lerp(_LUT1, _LUT2, _Blend)`，与我们的 HLSL **一字不差**。

**🔴 但我发现一处真差异（新）——顶点着色器少了「UV 的 scale/bias」那一跳**：

```
原版 vs_4_0：
  mad o0.xy, v1.xyxx, cb0[2].xyxx, cb0[2].zwzz      // uv * ST.xy + ST.zw
我们的 WFLUTBlender.shader：
  o.uv = v.uv;                                      // 直通，没有 ST
```
- `Graphics.Blit(null, rt, mat)` 时 `_MainTex` 未绑定 ⇒ `ST = (1,1,0,0)` ⇒ **两侧等价**（这也是为什么至今没被发现）。
- 但只要出现 **非单位 ST**（源是真实纹理 / 走翻转投影的渲染通道 / 立体渲染），
  **原版会翻转+缩放，我们不会** ⇒ 256×16 的 LUT 会被**上下颠倒**（16 行是 3D LUT 的纵轴）。
- ⇒ 建议给自建 shader 的 VS 补一行 `o.uv = v.uv * _LUT1_ST.xy + _LUT1_ST.zw;`
  （或显式声明 `_MainTex_ST` 并按 Unity 的 blit 约定取）。**本批只报不改**（`WarpforgeVFX/**` 不在我的所有权里）。

**其它已核、判定为「不是问题」的**：
- `LOD 100`：原版没写 LOD（默认 300），批处理/`Graphics.Blit` 下不影响。
- pass 名：原版无名，我们叫 `LUTBlend` —— 只有 `UsePass`/`SetShaderPassName` 才吃它，无影响。
- **LUT 贴图 `enableMipMap: 1`**（14 张全一样）：全屏 blit 下 UV 导数 ≈ 1 纹素/像素 ⇒ 采 **mip 0**；
  64×4 被拉伸到 256×16 时导数反而更小 ⇒ 仍是 mip 0。**判定无害**（但我核过了，不是漏看）。
- **工程是 Linear 色彩空间**（`m_ActiveColorSpace = 1`），14 张 LUT 全部 `sRGBTexture: 0`（线性数据）
  ⇒ 着色器里 `lerp` 作用在**原始纹素值**上，与原版同语义。`BattlePostFx.NewRt` 的
  `new RenderTexture(w,h,0,ARGB32)` 与原版 `new RenderTexture(256,16){useMipMap=false}` 同默认值。

### ④-1 R1 的**专验法**（方案，供主对话跑）

**为什么不能复用 sweep**：见 2·4（sweep 从不进后处理栈）。
**为什么能复用 `DistortProbe` 的骨架**：它已经是「自建相机 + 离屏 RT + `ReadPixels` + 与参照比」
（`DistortProbe.cs:88-95, 435-458`），而 LUT 这条链**不需要** URP Volume ——
`Hidden/LUTBlender` 就是一个**全屏 blit shader**，可以脱离战场单独验。

**建议新增宿主 `LutBlendProbe.Run`**（`WarpforgeArena1/Editor/LutBlendProbe.cs`，本批**不写**，等你拍板）：

```
第 0 步  合成两张 256×16 LUT（GPU 侧 Texture2D，`linear: true`，**mip 关掉**）：
          A(x,y) = (x/255, y/15, 0, 1)
          B(x,y) = (1 - x/255, 1 - y/15, 0.5, 1)
         ⚠️ 这样「恒返回 A」「恒返回 B」「恒返回平均」都会在某一档露馅（灭自证）。
第 1 步  mat = new Material(sh); SetTexture(_LUT1, A); SetTexture(_LUT2, B);
         rt  = new RenderTexture(256,16,0,ARGB32, RenderTextureReadWrite.Linear);
第 2 步  对 _Blend ∈ {0, 0.25, 0.5, 1}：SetFloat("_Blend", v) → Graphics.Blit(null, rt, mat)
         → RenderTexture.active = rt → tex.ReadPixels → 逐像素比 CPU 端 lerp(A,B,v)
第 3 步  同参数再跑一遍 **原件** `Hidden/LUTBlender`（`AssetBundle.LoadFromFile("wf_arena_2.bundle")`）
第 4 步  输出 `LP <case> maxAbs=<n> badPix=<n> meanAbs=<x>` + 存 PNG
```

**断言（每条都要，缺一条就可能自证）**：

| # | 断言 | 挡的是什么 |
|---|---|---|
| A1 | `_Blend=0` ⇒ 输出与 LUT1 **逐字节相同**（`badPix = 0`） | 挡「UV 翻转 / 采样错通道」 |
| A2 | `_Blend=1` ⇒ 输出与 LUT2 **逐字节相同** | 挡「恒返回 LUT1」（**灭自证**：只断 A1 时，一个恒返回 LUT1 的 shader 也是绿的） |
| A3 | `_Blend=0.5` ⇒ 与 `(A+B)/2` 每个通道 `≤ 2/255` | 挡「端点对、中间错」（例如写成 `a*(1-t)+b` 少减一次） |
| A4 | `_Blend=0.25` ⇒ 与 `lerp(A,B,0.25)` `≤ 2/255` | 挡「把 `_Blend` 当 0/1 开关」（阶跃） |
| A5 | `_LUT1 = _LUT2 = X` ⇒ 输出 == X（任意 `_Blend`） | 挡「没采纹理、自己发光」 |
| A6 | 原版那一路：`maxAbs ≤ 2` 即 **A/B 通过**；若整片 `(255,0,255)` ⇒ **记「原版批处理下不可渲染」**（这是替换理由的**正向证据**，**不算失败**，但必须打出来，⛔ 不许静默跳过） | 第二判据；也顺便复核 `WarpforgeShaderMap:289-292` 那条理由 |
| A7 | **VS 的 ST 那一跳**：`mat.SetVector("_MainTex_ST", new Vector4(1,-1,0,1))` 再跑 A1 —— **原版应上下翻转、我们这份不翻** | 直接钉住 1·D 那条新发现的差异（补 VS 之后这条应变成「两侧都翻」） |

**色彩空间**：工程是 **Linear**（`m_ActiveColorSpace=1`），14 张 LUT 都是 `sRGBTexture: 0`。
探针里**必须**把合成的 LUT 与 RT 都设成 **linear**（`new Texture2D(..., linear: true)` /
`RenderTextureReadWrite.Linear`），否则 sRGB↔linear 转换会让我们拿一个**恒偏亮/偏暗**的假结论。
**这一条是最容易假阳/假阴的地方，写进探针文件头。**

**建议同时跑的第二臂（可选，一条命令）**：
`WFBIND_FORCE_BUILTIN=1` 对 `Hidden/LUTBlender` **没用** ——
`WarpforgeShaderMap` 的 `Replacements` 里 `Hidden/LUTBlender` **不在 `UseOriginal` 白名单里**
（它本来就走自建），所以这个开关翻不动它。要 A/B 只能像上面那样**显式 `AssetBundle.LoadFromFile` 取原件**。

## ⑤ 顺手发现（只报不改）

1. **`effect_index.json` 有 17 件 `verdict` 为空串**（`count = 977`，`对得上 702 + 两边全程空 254 + C/D/E 各 1 = 960`，
   差 17）。这 17 件既不在台账里、判定也没被填 —— 文档 `:115` 说的「空判定 8」是**旧口径**。
   建议重生成时给「台账里没有的件」填一个 `未进 sweep` 而不是空串（空串和「对得上」在消费端分不开）。
2. **台账那一档的名字会误导**（见 1·A）：`只有原版有内容 —— 导出整个丢了` 对 `Tidewall Gunrig` 而言
   **对象一个没丢**。建议改名 + 在列里加一栏「原版粒子数 / 导出粒子数」，让「丢画面」和「丢资产」一眼可分。
3. **`dump_shader_blob.py` / `disasm_dxbc.py` 的 `BUNDLES` 不含 `wf_arena_2.bundle`**，
   而 `Hidden/LUTBlender` 恰好在那里（`pathID=42`，带完整 DXBC）。所以命令行的 A/B 离线臂
   **必须**用我新加的 `工具/dump_lutblender.py`。建议把 `wf_arena_2.bundle` 也加进那两个工具的清单
   （否则下一个人会得到「找不到这个 shader」的假结论 —— 和铁律 2 那条「没找到 ≠ 不存在」同型）。
4. **`WFLUTBlender.shader` 的文件头写着「DXBC 在 `scenes_scenes_battlearena*` 那 13 份里，
   不在 `dump_shader_blob.BUNDLES` 那 3 个包里」** —— 后半句成立，但**没说它也在 `wf_arena_2.bundle` 里**。
   本件实测：`wf_arena_2.bundle` 的这份**带完整字节码**（解压后 3504 B，两段 DXBC）
   ⇒ 复核这条链**不必去翻 13 个场景包**。建议就地补一句（铁律 5）。
5. `EffectIso` 的文件头说「只加载特效包一个包时，原版 prefab 的 shader 解析不到 ⇒ 原版侧渲品红」
   —— 这条与 `WarpforgeShaderMap:289-292` 的「bundle 里的 shader 在编辑器/批处理下渲染出故障」
   **是两种不同的品红成因**（前者 = 缺依赖包，后者 = shader 对象本身在编辑器下不可用）。
   做 R1 的 A6 那一条时**要先区分是哪一种**，否则会把「包没加载全」误判成「原版 shader 不可用」。
