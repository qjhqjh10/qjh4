## ① 结论

**能安全改，但必须先补三件事；而且「翻 shader」单独做等于没做。**

三条硬结论（都有第一手判据）：

1. **原版卡体从来没有 alpha 混合**：
   - 正常材质 `Card 3d Lvl1` → shader `Everguild/Cards/3D Card`：子着色器 `QUEUE=Geometry`、`RenderType=Opaque`、pass 状态 `blend (1,0)=One/Zero`、`zWrite 1`、`zTest 4`、`cull 2`。
   - 溶解材质 `Card 3d WH40K Dissolve` → `Everguild/Cards/3D Card Dissolve`：`QUEUE=AlphaTest`、`RenderType=Opaque`、同样 `blend (1,0)`、`zWrite 1`。
   - 三份材质的 `m_CustomRenderQueue` 全是 **−1**（= 用 shader 标签）⇒ 实际队列 **2000 / 2450**，都在不透明档。

2. **原版的「淡出」不是卡体 alpha**，而是分两条完全不同的路：
   - **2D 卡面** → `CanvasGroup.alpha`（字段 `fadeGroup` `+0x68`；`BasicCardUI.FadeCard` = DOTween 对 `CanvasGroup.alpha` 做补间）。
   - **3D 卡体** → **换溶解材质 + `_DissolveAmount`**（由 `Card Hand To Board` 动画 clip 驱动）；或者**直接 `SetActive(false)`**（阵亡）。
   - 一手证据：clip `Card Hand To Board`（length **1.0**）里有两条曲线 —
     `Board Elements/3DBody/Card 3D → material._DissolveAmount`：**(0.1667, 1.0) → (0.7, 0.0)**；
     `2DCard → m_Alpha`：**(0, 1.0) / (0.3333, 1.0) / (0.6667, 0.0)**。
     全包扫过所有 AnimationClip：**没有任何一条曲线动 `Card 3D` 的 `material._Color`**（只有 `_DissolveAmount` 与残骸体的 `_Shatter_*` / `_VerticalFade`）。

3. **我们这边唯一真正依赖卡体 alpha 的，只有两条「兜底」分支**（见 §③）：
   `CardFeel.Dissolve`（阵亡**取不到爆散体**时的旧表现）与 `CardFeel.ReturnToHand` 的 `!canDissolve` 分支。
   正常路径（登场 / 回手 / 发牌 / 战术卡消散）要么已经走溶解、要么作用在没有 3D 体的手牌上。

**必须先补的三件事（缺一条就不安全）**：

- **P1 —— `SetQueue` 必须跳过 `_body3D`。** 否则你改了 shader 标签也白改：`CardView.SetQueue`（`Core/CardView.cs:1153`）会遍历**所有** `MeshRenderer`，把 `_body3D` 的材质**克隆一份并写 `renderQueue = 卡队列段`（2962–2979）**（`StampQueue` `:1259`）——`renderQueue` 是**优先级最高**的排序键，它会把 `QUEUE=Geometry` 盖掉，卡体仍然落在透明档。
- **P2 —— 两条 alpha 兜底改成溶解。** 否则那两条路上「卡体不淡、其它层淡」（不透明后 `_Color.a` 被忽略）。
- **P3 —— shader 补齐 pass。** 原版 `3D Card` 是 **5 个 pass**：`Universal Forward / DepthOnly / MotionVectors / DepthNormalsOnly / ShadowCaster`；我们的 `Shaders/Card3D.shader` 只有 **1 个 Forward pass + `Fallback Off`**。这直接决定了两件事：
  - **F3（已改的 `castShadows=On`）现在其实是空转** —— 没有 `ShadowCaster` pass、又没有 Fallback ⇒ 卡体**进不了阴影图**；
  - 卡体也不在 URP 的 `_CameraDepthTexture` / `DepthNormals` 里（**`推断`**：URP 用 `DepthOnly`/`DepthNormals` pass 画这两张图；我们没有 ⇒ 依赖它们的后处理/贴花看不到卡体）。

**切换点必须成对做**：「跳过盖章（P1）」与「shader 换 Geometry/Opaque」是**一个原子改动**。单独做 P1（body 落回 shader 标签 3000）会把卡体从「一张卡一段队列」里摘出来、暂时退回纯距离排序 —— 那正是 `A1665` 要治的病；单独做 shader 也会被 `SetQueue` 盖掉（等于没改）。

**「能不能用 `_USE_BLEND` 打开混合来做淡出？」** —— 两份 shader 的**属性表**里都有 `_USE_BLEND`，三份材质里都是 `0`。
**`推断`**：ShaderGraph 的**混合状态是编译期写死的**（我们实读到的 `blend (1,0)` 在 `SerializedPass.m_State` 上、不随材质变），`_USE_BLEND` 最多影响片元里的 alpha 计算，**改变不了队列/混合** ⇒ 它大概率不是「淡出开关」。**没查清**（见 §⑤）。

### 3.3 shader 本体

| 项 | 现状（`Assets/CardPresentation/Shaders/Card3D.shader`） | 原版 |
|---|---|---|
| 队列 / 渲染类型 | `Queue=Transparent` · `RenderType=Transparent` | `QUEUE=Geometry` · `RenderType=Opaque` |
| 混合 | `Blend SrcAlpha OneMinusSrcAlpha` | `Blend One Zero` |
| 深度 | `ZWrite On` · 默认 `ZTest LEqual` · `Cull Back` | `zWrite 1` · `zTest 4` · `cull 2`（一致） |
| 片元输出 | `fixed4(col * _Color.rgb, **_Color.a**)` ⇒ **alpha 只来自 `_Color.a`**（`:131` 附近） | 无 `_Color`；alpha 由 alpha-clip（溶解材质）处理 |
| `_Color` | **我们加的**（原版没有，材质里那个是死值） | 无 |
| pass | **1 个**（Forward） · `Fallback Off` | **5 个**：Forward / DepthOnly / MotionVectors / DepthNormalsOnly / **ShadowCaster** |
| 圆角 / 越界 | 靠 mesh 形状 + UV1 区间 mask（`0.18<uv1.x≤0.82 && uv1.y>0`）；alpha 不参与 | 同（base shader 属性表里既没有 `_AlphaClip` 也没有 `_AlphaClipThreshold` ⇒ 材质里那两个是死值） |

⇒ **`_Color.a == 1` 时，Opaque 与我们现在的 Transparent 输出逐像素相同**（`SrcAlpha=1 ⇒ src*1 + dst*0`）。
这就是为什么 F1 的**视觉风险几乎只落在两条兜底路径上**，而不是整个卡面。

## ④ 实施顺序 + 验收方案

### 4.1 顺序（每一步都可单独回滚）

**Step 1 · 先换兜底（零视觉变化，可独立提交）**
- `CardFeel.Dissolve()`（`Core/CardFeel.cs:2311`）：`if (card.BeginDissolve())` ⇒ `DOTween.To(0→1, SetDissolveAmount, dur)` + 保留上浮/缩放；否则保持现状（已有 warning 口径）。
- （可选）`ReturnToHand` 的 `!canDissolve` 分支：把「整卡淡出」改成「`SetBody3DVisible(false)`」。
- **此时卡体仍是不透明？不是** —— 此时 shader 还是 Transparent，溶解材质本身是 AlphaTest，所以溶解材质在用的那一刻**已经把卡体放进不透明档**（今天就是这样）。视觉不变。

**Step 2 · 成对切换（一个原子改动，A/B 就靠它）**
- 2a. `Shaders/Card3D.shader:41-45`：`Tags { "Queue"="Geometry" "RenderType"="Opaque" }` + `Blend One Zero`（`Cull/ZWrite` 不动）。
- 2b. `Core/CardView.cs:1153` `SetQueue`：`if (mr == _body3D) continue;`（连带 `QueueMaterial` 不再给体做克隆）。
- **回滚 = 同时 revert 2a + 2b**（两处、约 3 行）。
- ⚠️ **顺序不可拆**：只做 2a 会被 `StampQueue` 盖掉（白改）；只做 2b 会让卡体退回 3000 纯距离排序（`A1665` 那类层序问题）。

**Step 3 · 补 pass（独立风险，可另开一件）**
- 给 `Card3D.shader` 加 `DepthOnly` + `DepthNormals` + `ShadowCaster` 三个 pass（照 URP Unlit/ShaderGraph 的标准写法，fragment 与主 pass 同样乘 `_Color.rgb`、alpha 走 clip）。
- **没有 Step 3，F3（`castShadows=On`）就是空转**（`Fallback Off` + 无 ShadowCaster ⇒ 不进阴影图）。
- 风险：新增 pass 会改变 URP 深度贴图/阴影图内容 ⇒ **必须真机并排**。

### 4.2 验收

**批处理能验的（断言，建议挂在 `CardBaseDemo` / `CardFaceProbe` 这两个非战斗线宿主）**
1. **材质队列**：场上卡 `body3D` 的 `sharedMaterial.renderQueue == 2000`（原版 `Card 3d Lvl1` = shader tag Geometry）。
2. **渲染类型**：`sharedMaterial.GetTag("RenderType", false) == "Opaque"`（读 shader tag；`Queue` tag 用 `GetTag("Queue",false)` = `"Geometry"`）。
3. **不再被盖章**：`card.SetQueue(2970)` 之后，`body3D.sharedMaterial.renderQueue` **仍 < 2500**（灭自证：把 2b 删掉 ⇒ 必红）。
4. **溶解材质不被盖**：`BeginDissolve()` 之后 `OnDissolveMaterial == true`；再 `SetQueue(...)` 一次，**仍然 `OnDissolveMaterial == true`**（这条同时抓 §3.1-C1b 那个老隐患）。
5. **兜底路径改道**：`CardFace.Board` 卡上跑 `CardFeel.Dissolve()` ⇒ 结束时 `DissolveAmount == 1` 且 `OnDissolveMaterial == true`（若 `DissolveSupported==false` 则断「有且仅有一条 warning」）。
6. **回归**：`CardBaseDemo.Run`（四档分辨率截图 + 现有 500+ 条）· `CardFaceProbe.CheckLayers` · `BattleScene.Run` 的场卡层级断言（由主对话在同步点跑）。

**必须真机的（批处理看不到）**
1. **并排**：同一张场卡（带立绘/数值/徽标）与原版参照图并排 —— 看边缘、滚边、立绘未变暗/未变亮。
2. **重叠**：两张相邻卡（含出牌飞行/让位期）谁压谁 —— 不透明档下**卡体由深度决定**，与前卡队列段无关，必须看一眼有没有新穿插。
3. **粒子/底光**：`CanActParticles` 绿光、目标底光在卡体前/后各看一次。
4. **两段过渡**：手牌→场上（溶解出）、回手（溶解回去）各看一遍（这是 alpha-clip 与不透明混排最容易露馅的地方）。
5. **阵亡兜底**：临时把某张卡的爆散体置空（`PickDeathFx` 走 `Fx==null`）看「溶解版」阵亡是否完整。
6. **阴影（Step 3 之后）**：卡下的投影方向/浓淡与地面是否贴合。

### 4.3 最小可回滚

| 改动 | 回滚方式 | 风险 |
|---|---|---|
| Step 1（兜底改溶解） | revert `CardFeel.cs` 那一段 | 低（不改层级） |

## ⑤ 没查清

1. **`_USE_BLEND` 到底是什么** —— 两份 shader 属性表里都有、三份材质都是 0；ShaderGraph 的**混合状态在 pass 静态状态里**（我们实读到 `blend (1,0)`），所以它**改不了队列/混合**。
   缺：ShaderGraph 生成的 HLSL 源（`工具/dump_shader_blob.py` 能出 DXBC，读 `_USE_BLEND` 分支即可定案）。**本轮没做**。
2. **`m_Alpha` 曲线作用在哪个组件上** —— clip 里路径是 `2DCard`、属性 `m_Alpha`，与 `fadeGroup`（`CanvasGroup`）对得上，但我没在序列化里把 `2DCard` 的 CanvasGroup 与 `fadeGroup` PPtr 一一对上（`2DCard` 节点本身有 `CanvasGroup`）。

## 附 · 顺手发现（只报不改）

1. 🔴 **F3 现在是空转**：`Shaders/Card3D.shader` 只有 1 个 pass + `Fallback Off`，**没有 `ShadowCaster`** ⇒ 上一批把 `shadowCastingMode` 打开**不会产生任何阴影**。要让 F3 真正生效，得先做本报告 §4.1 的 **Step 3**（补 pass）。原版 `3D Card` 是 5 个 pass（含 `ShadowCaster`），所以原版是**真投影**的。
2. 🔴 **`SetQueue` / `StampQueue` 会盖掉 3D 体的材质身份**（§3.1-C1b）：溶解进行中被盖章的话，渲染器拿到的是**克隆**、而 `SetDissolveAmount` 写的是原件 ⇒ 溶解可能静默卡住。这条**今天就可能存在**，与 F1 无关，但 F1 会把它一起治掉。
3. 原版三份材质的 `_Color` 是**死值**（两个 shader 的属性表里都没有 `_Color`）—— 我们的 `_Color` 是**自己加的扩展**（shader 文件头已写明），不要拿原版那个 `(0.126,0.176,0.264)` 去「对齐」。
4. 我们的 `HandToBoard` 常量和原版 clip 逐位对得上：`Land 0.1667` / `FadeStart 0.3333` / `FadeEnd 0.6667` / `DissolveEnd 0.7`，材质复位事件 `0.55`（`HandToBoardDone`）—— 这一组**不是近似**，别动。
