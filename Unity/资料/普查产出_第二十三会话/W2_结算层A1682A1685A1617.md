### 2 · `A1685` —— 能力层也要消费 `EffectOp.Instead`

**判据**：`instead` 的语义 = 「**替换掉前一句**」（`EffectOp.Instead` 的 doc；解析层 `PeelInstead`
只负责贴旗标）。**出牌 / 战术卡那条重载一直这么做**，能力层那条**一个字都没有** ⇒ 同一张卡在两条路上
行为不一致 —— 这正是本仓红线「两处写同一条规则 = 迟早不一致」。

**改了什么**

| # | 文件:行号（现读） | 改前 → 改后 |
|---|---|---|
| ① | `Core/EffectResolver.cs:99-152` | **无** → 新增 `static bool[] InsteadSkips(ctx, owner, ops, chosen, pairConditional)`：把原来**内联在出牌重载里**的「配对 + 裁决谁跳谁」整段（含 `A1388` / `A1412` 的全部理由）搬进来，**两个重载共用这一份** |
| ② | `EffectResolver.cs:240` | 出牌重载里那 76 行内联 → **一行调用** `InsteadSkips(…, chosen, pairConditional: true)`（行为逐字不变 ⇒ A/B 实测 `b3`/`b2` 相同） |
| ③ | `EffectResolver.cs:5073` ＋ `:5076` | 能力层重载：**无** → 新增 `var skip = InsteadSkips(…, null, pairConditional: false);`（放在 `ChargePaidGroups` **之前** —— 同出牌那条路的位置约束），主循环加一句 `if (skip[i]) continue;` |
| ④ | `EffectResolver.cs:5060-5072` | 新增那段注释：为什么能力层**只配无条件那一档**（见下）＋ 那一档**仍然是真缺陷**的指向 |

🔴 **为什么能力层只配【无条件】的 `instead`**（这是**判据逼出来的**，不是偷懒）：
能力层**没有 `chosen`** ⇒ `ConditionHolds` 只能退回 `ctx.LastTargets` / `ctx.LastTarget`
（`alreadyhas` / `targethaskw` / `targethasarmour` 那几支一律 `chosen ?? ctx.LastTargets`，
`EffectResolver.cs:7358+` / `:7183` / `:7222`），而 `ResolveOps` **入口**刚把那个槽种成
**`prime` = 这条能力的施放者**（`:4888-4892`）。⇒ 结算前判「it has Flying」**判的是施放者自己**。
**实测后果**：`ASH31 Crimson Hunter`（自带 `Flying`）的 Rally 会**永远**判成立 ⇒ 打**非**飞行目标
也从 3 变 6 —— **那是把对的改错**。所以这一档**不配**（保持现状，**A/B 证明零回归**）。
