## 二、逐张详情

**`TAU42` —— 唯一不一致的一张（英文档多印 1 枚）**

- 卡面（亲读）：`〔盾〕Shield. 〔导弹〕Long Range. 〔卷轴〕Talent: Shield Generator` = **3 枚**图标。
  `Shield Generator`（**天赋名**）前面**没有**图标。
- 我们的英文档（`sim_rewrite` 现跑，`card_icon_plan.json` TAU42.desc 两条 token = `Talent:`→`talent` · `Shield`→`shield`）：
  - `KeywordSegment` 补出 `〔盾〕Shield. 〔导弹〕Long Range. `（`Shield` 在 `Talent: Shield Generator` 里**前一个字符是 `:`** ⇒ 按 `IsDeclarationAt` 只认 `. 。 ． ; ； , ， \n \r` ⇒ **不算声明** ⇒ 照印；`Long Range` 不在正文里 ⇒ 照印）—— 这 2 枚**与卡面一致**。
  - `CardIcons.Rewrite('TAU42','desc','Talent: Shield Generator')` = `〔卷轴〕Talent: 〔盾〕Shield Generator`
    ⇒ `Shield` 这条 token **命中了天赋名里的那颗 `Shield`**，多插一枚图。
  - 合成 = `〔盾〕Shield. 〔导弹〕Long Range. 〔卷轴〕Talent: 〔盾〕Shield Generator` = **4 枚 vs 卡面 3 枚**。
- 根因：`Shield` 那条来自 **`BARE_TOKEN_BY_RULE` 的「恒带」按词规则**（`gen_icon_plan.py:1172`，自报读数「33 卡 37 处 · 双写 34 处 ⇒ **缺 3 卡**」—— 卡面**不印**的那 3 处里就有这一处），它是**纯子串替换**、分不出「关键词用法 / 天赋名」。
- 中文档**不受影响**（3 枚，正确）：`descZh` 的段首 token 是 **`护盾。`（带句号）** ⇒ 与 `护盾发生器` 匹配不上；且裸词规则那条 `护盾` 被**守卫③**（`gen_icon_plan.py:2458`，`_t in _pre_tokens`）挡掉。英文档之所以漏过去，是因为英文的段首 token 是 `Talent:`、**不含 `Shield`** ⇒ 守卫③挡不住。
- 现形条件：`CardText.Zh`（`CardText.cs:38`）为假（**切到 English 语档**）时。

**其余 4 张（`TAU33` / `TAU20` / `TAU14` / `TAU16`）一致**，逐条核过的点：
- `TAU33`：`keywords` 解析成 `{stealth:1, companion:2}`（`KeywordTable.Parse` 按 `:` 切头 + 前缀匹配）⇒ `Stealth` 在**段首**、`Companion` 段首 ⇒ `seg = ""`；两枚图标全由 `desc` 的 `Stealth.` / `Companion 2:` token 画（带收尾符 ⇒ **不会**误配 `Stealth Drone`）⇒ 与卡面**同词同位置**。
- `TAU20`：`seg = 〔羽翼〕Flying. 〔导弹〕Long Range. `（`Long Range` 在 `Gains Long Range` 里前一个字符是 `s` ⇒ 非段首 ⇒ **印**；这正是 `A1345` 修掉的那一笔）＋ `desc` 两枚 ⇒ 与卡面逐处对上。
- `TAU14`：`seg = 〔羽翼〕Flying. 〔眼〕Stealth. `（`Stealth` 在 `give Stealth to` 里 ⇒ 非段首 ⇒ 印）＋ `desc` 句尾一枚 ⇒ 3 枚 = 卡面 3 枚。
- `TAU16`：三项都在 `desc` 段首 ⇒ `seg = ""`；4 枚全由 `desc` token 画（`Stealth.` / `Rally:` / `Talent:` + 逐卡 `Stealth to`，`gen_icon_plan.py` 的 `_A1613_GAP` `:859` 那行）⇒ 4 枚 = 卡面 4 枚。顺序 = 卡面顺序。
- 五张的**次序**都对（`seg` 按 `keywords` 数组序输出，`CardText.cs:297-317`）：`Flying,Stealth` / `Flying,Long Range` / `Shield,Long Range` 与卡面一致。

## 三、判不了的 + 还差什么

1. **没有 Unity 实跑**（红线）。渲染串是 `工具/icon/sim_rewrite.py` 的**静态逐分支复刻**（它自己声明「不模拟 `<link>` 那一层的运行时行为」）＋ 我对 `KeywordSegment` 的离线复算 —— **`seg` 那半边没有现成工具、是我照 `CardText.cs` 逐条手推的**。
   还差：真机点开 `TAU42` 英文档卡面确认那第 4 枚。5 张里只有它有差异，其余 4 张的 `seg` 结论若要知道「实渲是否一致」，同样只能真机。
2. **卡面图标形状（哪张图）没判** —— 只判了「词/位置/枚数」，图标 sprite 对不对属图标线（已收口），不在本账。
3. **`descZh` 无卡面判据**（原版无中文卡表，铁律 2）：中文那半的结论是「与英文逐处对应」推出来的。
