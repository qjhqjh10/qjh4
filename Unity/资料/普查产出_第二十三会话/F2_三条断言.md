## 二、逐条

### 红 2 —— `★ 载荷 it as well 认出来了`

**原文**（`RuleEngineTest.cs` 改前 `:8666-8685`，当前 `:8666-8711`）：

```csharp
var ops = EffectText.Parse(desc, out _, out _);      // desc = 整条卡面
foreach (var o in ops) if (!string.IsNullOrEmpty(o.Payload)) {
    var ps = GivePayload.Parse(o.Payload);
    if (ps != null) foreach (var p in ps) if (p.CopyEventPact) copy = true; }
CheckTrue(copy, "★ 载荷 `it as well` 认出来了（改之前五条判据一条都不命中 ⇒ 整条 op 空过）");
```

**为什么是「钉旧形状」**：`W1` 的 8c-ter（`EffectText.cs:2723`）让 `When <事件>, <正文>` 走成 `whenclause` 标记 op
⇒ **裸解析整条 desc** 只得到 `whenclause / payload=[this troop gains it as well] / target=[]`
（实测 `ruleprobe card "Accursed Helbrute"`）⇒ 拿**整条正文**当载荷喂 `GivePayload.Parse` 必然 null ⇒ `copy` 恒 `false`。
⚠️ 这个 `[it as well]`（改前的裸解析载荷）**本身就是切错了的产物** —— 用例 `:8741-8750` 那段注释早就写着
「⛔ 别拿 `EffectText.Parse(整条 desc)` 的结果去验」；只是**上一版把这句话写进了注释、没落到输入上**。

**改成什么**：取 op 的来源换成**事件层**（`CardDef` ctor 的 `CollectWhenTriggers` → `AddWhenTrigger` → `WhenTriggers`）：

```csharp
var card = new CardDef("FxHelbrute", "FxHelbrute", "unit", desc, "rare", "BlackLegion",
                       8, 9, 7, 9, null);
CheckTrue(card.WhenTriggers.Count > 0, "★ 那一句收进了**事件层**（`WhenTriggers` 非空）");
var eventOps = card.WhenTriggers.Count > 0 ? card.WhenTriggers[0].Ops : null;
bool copy = false;
foreach (var o in eventOps ?? new List<EffectOp>()) { … GivePayload.Parse(o.Payload) … }
// 原来的 `ops` / `seen` 保留、只喂末尾那条诊断（⛔ 不再拿它的 Payload 判 `copy`）
```

**为什么选事件层、不选「对正文单独 Parse」**（诊断给了两条路、读数逐字相同）：
① 事件层是**引擎真正跑的那条路**（`CardDef.AddWhenTrigger`），选它对「事件层切分坏掉」也有一份覆盖，
   而「对正文单独 Parse」得把 `"this troop gains it as well"` **硬编进断言** ⇒ 切分一改，这条就静默脱离真实路径；
② 本文件已有 **296 处** `new CardDef(…)` 的先例，本用例的 ③ 段本来就在建同一张卡（`BL74F`）。
**静态链复核**（我自己读的、不是转述）：`CardDef.cs:2440`
`ops = body.Length > 0 ? EffectText.Parse(body, out _, out _, evHasTarget) : null;` ⇒ 事件层那 `ops` **就是正文单独解析的结果**；
`ruleprobe seg "this troop gains it as well"` ⇒ `verb=gain payload=[it as well] target=[this troop] Subjectless=1` ✅。

**🧨 红法（改坏哪一行 ⇒ 这条必红）**：
- 删/放宽 `GivePayload.cs:495` `if (low == "it as well")`（全仓**唯一**设 `CopyEventPact` 的地方）⇒ `copy` 必红；
- 让 `CardDef.AddWhenTrigger` ① 不再登记（例如去掉 `CardDef.cs:631` 的 `CollectWhenTriggers(keywords)`，
  或 `CanListenForEvents`（`CardDef.cs:2626` = `IsUnit`）不再认 `unit`）⇒ `WhenTriggers` 非空 + `copy` **双红**；
- 把输入改回 `EffectText.Parse(desc, …)`（旧形状）⇒ `copy` 必红。
- **灭自证**：断的两个口是**两个组件**（`CardDef` 的事件层切分 vs `GivePayload` 的载荷词表），
  不是「被测实现和它的检测器用同一个口」；把任意一边改回旧形状都会有一格红。

### 红 3 —— `带条件从句的 X takes N damage 判不认识（不许把条件当主语）`

**原文**（`RuleEngineTest.cs` 改前 `:7803-7808`，当前 `:7803-7837`）：

```csharp
Check(EffectText.ParseSegment("When you play a Stratagem, your Warlord takes 1 damage").Kind,
      EffectText.SegKind.Unknown,
      "带条件从句的 `X takes N damage` **判不认识**（不许把条件当主语）");
```

**为什么是「钉旧形状」**：改前 HEAD 对这句产出 **0 条 op**（`unparsed = 整句`），8c-ter 之后产出一条
**标记 op**：`ruleprobe seg` ⇒ `partial=` 空 · `op: verb=whenclause payload=[your Warlord takes 1 damage] target=[]`
⇒ `Kind = Ok`。**旧理由已作废**：它防的是「`(.+?)` 把条件从句吃成**主语** ⇒ 任何时候都结算」，
而标记 op 走 `EffectResolver.cs:850` 的 `"whenclause" → DoWhenClauseStub`，**只打一行日志**。
⚠️ 而且**改前那条路才是坏的那条**：0 条 op ⇒ `RuleCore.PlayTactic` 拿到空表 = **扣了费什么都不发生**（本仓红线）。
⚠️ **这一句是真卡** `GSC_Jammed_Communications`（tactic · 破坏卡 · Genestealers）。

**改成什么**（钉 op 形状，原意用 `Target == null` 保住）：

```csharp
var r = EffectText.ParseSegment("When you play a Stratagem, your Warlord takes 1 damage");
Check(r.Kind, EffectText.SegKind.Ok, "…现在由 **`whenclause` 标记 op** 收下（改前 = Unknown、0 条 op …）");
CheckTrue(r.Ops != null && r.Ops.Count == 1, "……收下**恰一条** op（是标记 op，不是真效果）");
Check(mark == null ? "(无 op)" : (mark.Verb ?? "(空)"), "whenclause", "……它是【标记 op】、⛔ 不改结算");
CheckTrue(mark != null && mark.Target == null, "★ **原意保留**：条件从句**没有被当成主语**");
```

最后那半句（`Target == null`）**没有省** —— 它就是原意「不许把条件当主语」的可验证形式
（没有目标 ⇒ 不存在「解出一个目标 ⇒ 任何时候都结算」）。⛔ 也**没**写成「反正只打日志就放行」那种永真形状。

**「判据必须在知道卡类的地方」这条原则没被破坏**（三处继续承载，我逐个核过行号）：
`CardDef.IsHandTrap(CardDef)`（`CardDef.cs:4209`）· 本文件反例 ②（现读 `:12720-12723`，
搜 `反例：非单位卡的`，`HandledByOtherLayer` 对这张卡**返回 null**）·
`EffectText.Coverage` 的 `IsHandTrap` 短路（`EffectText.cs:1912`）。

**🧨 红法**：撤掉 8c-ter 那条支（或让它对被挡住的句子仍返回 null）⇒ `Kind` 回到 `Unknown` ⇒ 前两格红；
把 `TryWhenPrefixStub` 的 `Target` 填上（退回「事件从句当目标」那条老路）⇒ 最后一格 `Target == null` 必红。

### 红 5 —— `（如实记：同一句经 EffectText.Parse(整条 desc) 会被归进 partial（半懂）…）`

**原文**（`RuleEngineTest_S14.cs` 改前 `:1645-1649`，当前 `:1650-1671`）：

⭐ **断言文案自己就写着**「如实记 …… ⛔ **别拿它当判据**」⇒ 它本来就不是判据（是「如实记」）。

**改成什么**（**改写**，⛔ 没有删格）：

```csharp
CheckTrue(pa != null && pa.Count == 0,
          "（改形状）…**不再落进 `partial`** —— 改前它是 `partial`（8c-ter 落地后全池 `partial` 10 → 1）…");
CheckTrue(whole.Count > 0 && whole[0].Verb == "whenclause",
          "（同上）`Parse(整条 desc)` 那一路产出的**首条** op 动词是 `whenclause`（不是 `gain`）…");
```

**紧邻的下一格（`whole.Count == 0 || whole[0].Target == null`）原样保留** —— 诊断实测它仍然绿，我也没碰。
**「两条路形状不同」这个原意落点**：事件层 = `gain`/`fast`/`Subjectless`（本方法前几格）；
`Parse` 那一路 = `whenclause`/`Target == null`（本格 + 下一格）。

**🧨 红法**：撤掉 8c-ter 那条支 ⇒ `whole[0].Verb` 回到 `gain` ⇒ 新增那格必红；
