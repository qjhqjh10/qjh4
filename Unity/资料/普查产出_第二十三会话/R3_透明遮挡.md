# R3 · 卡组编辑「被透明的东西挡住 ⇒ 要滚动一下才能点/拖」

> 只读诊断（第二十四会话 `R3`）。⛔ 未跑 Unity / 未跑游戏。每条给 `文件:行号`，行号**现读**。

## 一、一句话结论：**(a)/(b)/(c) 三条【全部证伪】**；真机制是第四条

**卡池的命中不是「另算一份矩形」，而是当场用卡视图自己的 transform 反解出来的**（`Core/CardView.cs:4064-4068`
`Contains()` = `transform.InverseTransformPoint(world)` ≤ `Width/Height` 的一半）⇒
**「命中区」与「画出来的位置」永远同一个来源**：布局挪一寸、命中跟着挪一寸，**没有可"过期"的缓存**
⇒ **(a)「命中区只在滚动后才刷新」不成立**、**(c)「命中区趁视图没建好时算出来」也不成立**。
**(b) 在开局那一刻也不成立**：本窗唯一那颗整屏可射线件是 `imp_shade`，建完就被关掉、且只在 `_importOpen` 时放行（见 §二·4）。

🔴 **真正的机制 = 「能被滚轮驱动」与「能被点击驱动」是两条不同的路**：
`HandleScroll`（`Deck/DeckRuntime.cs:5711-5746`）**没有一道闸**，卡池那一支还是最后的 **`else` 兜底**
（不要求精确命中：任何不在左栏/侧栏的点都滚卡池）；
而 `HandlePointer`（`:3908-4043`）在碰到卡池之前有 **4 道闸 + 4 段早退**（见下）。
**其中任何一条为真 ⇒ 点击 + 拖动整条链静默失效，而滚轮照旧** —— 这正是用户描述的「能滚、点不动、拖不动」。

**最可能触发的是一条（本仓已知形状）**：入场景时**上一场景那扇窗还开着** ⇒ `OtherWindowUp()`（`:4017`）
让本窗指针**整条让位**。判据链：壳是 `DontDestroyOnLoad`（`Shell/ShellRuntime.cs:115`）⇒ 进本场景时
`WindowsManager` 还在（`DeckRuntime.cs:1120-1136` **自己写着这一点**）；进编辑器的**正常来路**
（`Shell/CollectionWindow.cs:3502-3517`）**只写意图 + `LoadScene`，不关窗、不动 WindowsManager**；
`IsOpen()` 读的是**状态字段**不是 `activeSelf`（`Shell/WindowsManager.cs:670` `CurrentState == WindowState.Open`）
⇒ **那扇窗在编辑器里仍是 Open** ⇒ 闸从第 1 帧就真。
⚠️ 而我们自己历次真机验收都用 `-wfscene DeckEditor` 直接起 player（**没有壳 ⇒ `WindowsManager.Instance == null`**）
⇒ **这条路径我们一次都没跑到过**。

## 二、证据链

1. **命中 = 视图自己的 transform**：`Core/CardView.cs:4064-4068`（`Contains`）· 摆位唯一写点 `SetPose`
   `:4170-4187`；卡池每格摆位 `Deck/DeckRuntime.cs:2282` `v.SetPose(Pos(cx,cy),0,P.CardScale)`。
2. **同一个函数是取卡的口**：`DeckRuntime.cs:4050`（x 区间闸，**没有 y 闸**）→ `:4060`（跳过 `null`/未激活/`_poolIndex<0`）
   → `:4061`（`v.Contains(wp)`）→ `:4062` `State.VisibleAt(_poolIndex[i])`（`Deck/DeckEditorState.cs:522-526`
   **每次都重算整张 `VisibleCards()`**；越界给 `null`）。⚠️ `:4063` `if (def == null) return true;` = **静默吞掉这一下**
   （且挡掉后面的 `HandleDeckRowClick`/`HandleButtons`）。
3. **指针链的 4 道闸**（都在 `HandlePoolClick` 之前，`HandlePointer` 内）：`:4012` `ModalPopupOpen` ·
   `:4017` `OtherWindowUp()` · `:4020` `_importOpen` · `:4025`/`:4031` `FltStripOn`/`CosmoFltStripOn`（左带 `x<333.9`）。
   **4 段早退**：`:3941` `_dragging` · `:3953` `_cosmDrag` · `:3960` `_cardDrag` · `:3973` `_cardArmDef`（等一次位移/松手）。
   ⇒ 前三段与闸都是**整函数 `return`**；滚轮那条路（`HandleScroll`）**一道都没有**。
4. **本窗唯一的整屏可射线件 = 导入弹窗压暗层**：建在 `DeckRuntime.cs:3173`（1920×1080，α 0.396，队列 `QModal-1`＝3099）、
   命中矩形 `:3296` `Btn_("imp_shade",0,0,ScreenW,ScreenH)`、**建完立刻关**(`:3305` `_modalOnly` 全 `SetActive(false)`)、
   开与不开由 `KeyLive` 那一支管（`:6940-6952`，只有 `_importOpen` 放行）⇒ **开局不挡、也不可见**（(b) 由此证伪）。
   ⚠️ **没有别的整屏件**：本窗的命中**不走 UGUI 射线**，所以「透明件压着」在本窗**只能**经上面那 4 道闸生效。
5. **「滚动」到底重算了什么**：`HandleScroll:5746` → `_poolScroll -= step` → `RefreshPool()`(`:2214-2303`) + `RefreshHeader()`(`:3713`)。
   `RefreshPool` 里会变的是：`_poolScroll` 的夹取(`:2302`)、每格 `SetPose`(`:2282`)、`_poolIndex[i]`(`:2252`)、
   卡换没换(`:2269` 比 `_poolViewIds`)、末段关掉超出行列的视图(`:2296-2297`)。**全是渲染/取卡，与命中区无关**
   ⇒ 滚动**不修**命中，它只是**把卡挪到别处**（或干脆是用户在那一下失败之后试的下一个动作）。
6. **左带那条已知路由不是本案**：`FltStripOn` 要求 `_filtersOpen && PageOn && Interactive`（`:2095`），而
   `_filtersOpen` 出厂 `false`（`:755`）、`_tab` 出厂 0（`:754`）、抽屉 `Slide/SlideTarget` 出厂 0 ⇒ `Interactive=false`
   （`:2056`）⇒ **开局左带没被筛选抽屉吃掉**。

## 四、修法候选（⛔ 我没改任何东西）

1. **让闸不认「上一场景留下的窗」**（改 1 处谓词）：`OtherWindowUp()`（`:4540-4547`）除了 `IsOpen()` 再要求
   「**这扇窗在本场景活着且在画面上**」（`w.gameObject.scene == SceneManager.GetActiveScene()` 或 `activeInHierarchy`）。
   **代价低（一处谓词）**；⚠️ 动的是 `DeckRuntime` 自己的谓词，**不动共用件**（`WindowsManager` 只读）。
2. **在入口关掉上一扇窗**（改 `CollectionWindow.GoEdit:3513` 前后）：进去之前 `WindowsManager.Get().CloseAllWindows()` 或
   `TopWindow?.Close()`。**代价低但要动 `Shell/CollectionWindow.cs`（共用件，需按覆盖面跑 `CollectionScene.Run` 等）**；
   ⚠️ 与既有「按来路回」（`A855`：回来时**重开**收藏窗的卡组页）**语义相容**（那边是回来时重开，这里是走时关）。
3. **两条路对齐闸门**（结构性）：把「这一刻指针能不能派发」收成**一个谓词**，`HandlePointer` 与 `HandleScroll` **共用**
   （现在滚轮**零闸**、点击**四闸** ⇒ 任何未来回归都会继续以「能滚、点不动」的形状出现，且**滚轮会把读者引向错的方向**）。
   ⚠️ 代价最高、会动冷热路径，**建议先做 1、2，再做 3**。
4. **出声（最便宜的诊断，建议与上面同批做）**：`OtherWindowUp()` 为真时**每帧一次**（或变化时一次）
   `Debug.Log("[Deck] 指针让位：<窗名> state=…")`，并把 `ModalPopupOpen/_importOpen/_dragging/_cardDrag/_cardArmDef`
   五个布尔一起打。**这一行就能把 §五 那三个候选一次分开**（现在**一个都不出声**，所以只能靠 §五 的探针）。

## 五、没查清的部分 + 还差什么（要跑游戏怎么复现那一下）

以 §一为真时**「滚动一下就恢复」这一半我解释不了**（`OtherWindowUp()` 每帧都问；滚轮**没有任何一步会去关那扇窗**）。
剩下两个与其并列的候选，**都没法静态分开**，需要真机探针：
- **候选 2 = 状态机被打死**：`:3941`/`:3953`/`:3960`/`:3973` 那四段只要状态留在「已按下/正在拖」就**每帧 `return`**，
  而它们只有在**看见一次松手**时才会清（`:3946`/`:3963`/`:3976`）。**若某次松手落在窗口外/切场景那一拍丢掉了**
  ⇒ 整条指针链**永久死**、滚轮照旧。**← 这条能解释「第一下之后一直点不动」，但仍解释不了「滚动」**。
- **候选 3 = 环境侧**：`Mouse.current.position` 陈旧/窗口未聚焦。这一条**唯独能解释「滚动」**：
  `HandleScroll` 的卡池支是 `else` 兜底（`:5746`），**拿陈旧坐标也照样滚卡池**；而点击要精确命中 ⇒ 全打空。
  🔴 **探针（3 分钟，二选一即可）**：
  ① 在 `OtherWindowUp()` 那一行加一次性出声（§四·4）⇒ 三个候选立刻分开；
  ② 真机对照：**只把光标悬停**（不动、不点、不滚）看页头 4 颗钮**亮不亮**（悬停走 `:3924` `UpdateButtonHover`，**在闸之前**）
  —— **亮、但点不动 ⇒ 闸/状态机（候选 1/2）；连悬停都不亮 ⇒ 候选 3（坐标/焦点）**。
  ③ 复现那一下：`-wfscene Shell` 起 player → **真鼠标点进「收藏」→ 再点「进编辑」**（⛔ 别用 `-wfscene DeckEditor`，
  那条路没有壳、也复现不出候选 1），然后**先只悬停、再点一下空白、再滚一格**，各记一次。

## 六、顺手发现（只报不改）

1. **卡池【没有裁切】** —— `SetClip`/`SetClipFromTree` 在 `Deck/DeckRuntime.cs` **0 命中**（只给筛选抽屉那族裁过，
   `:6013-6033` / `:6173`）⇒ 越出视口的卡**整张画出去 + 命中区也越界**，而**原版那棵树上挂着
   `Card Display > Scroll View > Viewport` 的 `RectMask2D`**（滚轮/指针规格 §3·2 第 5 条自己写着「部分可见的条目点击区仍按整条算」）
   ⇒ **要做**（铁律 11）。判据 = `Core/CardView` 既有的可选裁切口（`A181`，`Core/CardView.cs:4167`）。
2. **`HandlePoolClick` 里那句 `if (def == null) return true;`（`:4063`）= 静默吞点击**：它连
   `HandleDeckRowClick`/`HandleButtons` 一起挡掉，且没有任何日志 ⇒ 「点了没反应且查不出为什么」。
   ⇒ 至少改成**出声**（本仓红线：不许静默失败）。
3. 🔴 **自检口碰不到卡池**：`UiClickPx`（`:5333-5341`）**只路由到 `HandleButtons`/筛选抽屉**，
   **从不调 `HandlePoolClick`/`HandleDeckRowClick`/`HandleCosmeticClick`** ⇒ **本笔这一族缺陷（"点不动"）
   在自检里结构性地看不见**（跑多少断言都是绿的）。**先例**：`A1495` 那次「卡组编辑点空白处 NRE」
   正是**用户真机实测**报出来的（见 `:4054-4059` 那段注释）。⇒ 建议补一个**走真路径的合成口**
   （喂**屏幕坐标**而不是设计 px，即走 `LayoutSpace.ScreenToWorld` 那一步），否则这一类还会再来。
4. `ArmPxSlop = 16.2f`（`:2838`）= 设计 px；小幅抖动的「点击」算点击、超过就转拖拽 —— 而拖拽还要过
   `IsScrollDragThreshold`（`:3022`，与水平轴夹角落在 (60°,120°) 就**判成滚动、不起拖**，`:3079`/`:3109`）
   ⇒ 「**竖直方向拖卡**」在原版语义里本来就不起拖（这条是照原版的，不是缺陷）；
   ⚠️ 但 `:3994` 那声 `Debug.Log` 只在**真机**打得出来，自检打不到。
