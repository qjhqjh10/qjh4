# R1 · 「没选战将的卡组」为什么能进「选择卡组」

## 一、一句话结论（+ 我判到哪一步）

**它不是「退出时」被存下来的，而是在【点新建那一刻】就已写进磁盘** —— 我们的「新建卡组」=
`CollectionData.CreateDeck()` → `DeckLibrary.Create()` → **立刻 `Save()` 落盘**，**全程零校验**；
两条列表（收藏窗卡组页 / 选择卡组弹窗）**也都不按督军过滤** ⇒ 它一格不差地显示出来。
**原版不是这样**：原版「新建」只 `new` 一个空 `CardDeck` 并**直接开编辑器**、**从不入库**；只有 `Done/ESC` 过了
`ValidateDeck` 之后 `UploadDeck` 才把它写进库存 ⇒ 原版「新建 → 不选战将 → 退出」**什么都不剩**（§三）。
判到底了（反编译 + 四份源码逐行 + 落盘链）；**唯一没做的是真机复现**（§五·1）。

## 二、判据链：今天发生了什么（我们）

1. 入口两颗钮，转同一个口：① 收藏窗卡组页 `Create Deck` → `Shell/CollectionWindow.cs:2972` → `CreateDeck()` @ `:3525`；
   ② 事件窗 `Create deck` → `Shell/LiveOpsEventWindow.cs:1119`。二颗都 → `Shell/CollectionData.cs:300 CreateDeck()`。
2. `CollectionData.cs:331 Lib.Create(name, gameMode)` → `RuleEngine/Data/DeckLibrary.cs:162 Create()`：
   `:166 _decks.Add(d)`（`d = new PlayerDeck(名字, 督军=null, 防御=null, …, mode)`）→ `:167 _current = 最后一格`
   → `:168 SaveOrWarn("Create")` → `:243 Save()` → `DeckStore.cs:229 SaveAll(整份库)` ⇒ **建完当场进盘**。
   `Create` / `Save` / `SaveAll` **三处都不看卡组合不合法** —— 没有前置校验，这才是本症状的根。
3. **编辑器这一侧没问题**：`Deck/DeckRuntime.cs:6854 CommitDeck()` 只由 `SaveAndSay()` @ `:4302` 调，而它在 `:4304`
   先 `State.Validate()`、不合法就 `return`（A330 那道闸，照原版 `__TrySaveDeck.c:80`）⇒ 空卡组**不是编辑器存进去的**。
4. **退出不清盘**：`BackToMenu()` @ `:4114` 只切场景；`TryClose`（`:4408+`）干净直接走 / 脏弹丢弃窗；
   `RollBackEditingCopy()` @ `:4478` 注释明写「**不动盘、也不动库**」。全仓**没有自动删卡组**的路径
   （`DeleteDeck` 只有 `Shell/DeckInfoPopup.cs:1540` 那颗删除钮调）。
5. **两条列表都不筛**：收藏窗 `Shell/CollectionWindow.cs:3273 FilteredDeckIndices()` 只按「阵营 + 卡名」两个 UI 筛选；
   取不到督军立绘就**退回画卡背**（`Shell/MenuDraw.cs:3044`）⇒ 画面 = 一格「卡背 + 名字『新卡组』」。
   选择卡组弹窗 `Shell/DeckSelectionPopup.cs:324 Shown()`「我的卡组」页**只按 `ModeFilter` 筛模式**（`:332`）。
6. 督军闸全在下游：开战前 `PracticeModePopup.cs:1722` / `LiveOpsEventWindow.cs:971` 拒绝并弹窗；真打起来
   `Battle/BattleDriver.cs:6962` 再 `Validate`、不合法 ⇒ 退回自动凑（`:7009-7012`）
   ⇒ **后果不是「打坏」，是「列表多一格假货」+「`_current` 被指到它」**。

## 三、原版怎么做（判据 = `D:/2/tools/decomp_full/`，⛔ 不是从我们实现反推）

1. `SelectDecksTab__CreateDeck.c`：`:19 CardDeck__GetEmptyDeck(0)` → `:26` 打 gameMode + `syncedToServer=0`（脏）→
   `:28 WindowsManager__OpenWindow<DeckEditingWindow>(…)` —— **只开窗，没有任何入库/上传调用**。
   （`CardDeck__GetEmptyDeck.c` 逐字段：`+0x40=0` 督军 · `+0x48=0` 防御 · `+0x50=0` 模式 ⇒ 一份孤立空对象。）
2. **入库的唯一路径** = `DeckEditingWindow__TrySaveDeck.c`：`:80 ValidateDeck(deck, out err, 1, 0)`；`:81-98` 不合法 ⇒
   `ShowPopUp(ToRawLocalizationString(err))` 后 `return`（**绝不走到 `:100`**）；`:99-105` 合法 ⇒ `:100 UploadDeck`；
   而 `DeckEditingWindow__UploadDeck.c` = `CardDeck__CopyDeck(开窗时那副 ← 编辑中那副)` →
   `PlayerDataManager__UploadUnsyncedDeck(…)` ⇒ **这才是「进入玩家卡组库」那一刻**。
3. `DeckUtility__ValidateDeck.c`：`:44 *(deck+0x40)`（督军）→ `:49 op_Equality(督军,0)` 真 ⇒ `:52 err=2; return 0;`
   ⇒ **错误码 2 = 没督军 = 不合法**。
4. `DeckEditingWindow__UpdateDoneButton.c:22` 同一条 `ValidateDeck` ⇒ 只切 Done 的**高亮/音效**（`UIEffectTogglerController.Toggle`）、
   **不设 `interactable`** ⇒ 原版那颗 Done 点得下去、点下去出错误窗 ⇒ 「不选战将存不下来」靠的是「**压根没入库**」
   +「**保存前校验**」两道，**不是灰按钮**。
5. 原版**选择卡组列表也不按督军筛**（`DeckSelectionTabController__ShowOwnDecks.c:59-64`：`GetInventory<CardDeck>()` →
   `.Where(谓词)` → `.ToArray()`；谓词 `…__ShowOwnDecks_b__10_0` 比的是 `CustomGameModeEvent`）—— **因为库里本来
   就不存在非法卡组**。⇒ 修法方向应是「**别让它进库**」，**不是**「列表筛掉它」。

## 四、修法候选（⛔ 我一个都没改）

**A（=照原版，推荐）「新建不入库：只造副本 → 直接进编辑器 → Done 过了校验才入库」**
- 改：`CollectionData.CreateDeck` 拆成「造一份**未入库**的 `PlayerDeck`」与「入库」两件事；`DeckRuntime` 要能吃
  「不在库里 / 没有下标」的卡组（今天 `CommitDeck` 走 `Library.CommitCurrent` = 写回**当前选中**那一套，
  `RuleEngine/Data/DeckLibrary.cs:221`），Done 时**新增**而非覆写；退出/丢弃 ⇒ 丢掉副本。
- 代价 **高**：跨三层（`Shell/CollectionData.cs` + `Deck/DeckRuntime.cs` + **共用件** `RuleEngine/Data/DeckLibrary.cs`）
  ⇒ **动共用件、要翻 A566 的案**（`Deck/DeckRuntime.cs:6842-6852` 原文裁定「不加守卫、也不动 `DeckLibrary`」），理由要写足。
- 顺带修掉**第二处同源偏离**：我们收藏窗那颗 `Create` **建完不进编辑器**，原版是 `:28` 直接开窗。
- 验收：`DeckScene.Run` + `CollectionScene.Run` + `MainMenuScene.Run`。

**B（最小改动）「`Create` 先不落盘，等第一次 `CommitDeck` 再写」**
- 改：`DeckLibrary.Create` 那一次 `SaveOrWarn` 去掉/加开关。代价 **中**：共用件一行，但语义变成「内存可能比盘上多」
  —— 崩/断电即丢、重启后 `current` 漂移；且出现「盘上没有、内存里有」**两个真相**（正是 CLAUDE.md §三
  「两处写同一条规则」的形状）。对**事件窗那条路**够用，收藏窗那条路会留下未落盘的孤儿。

**C（最省事，但**偏离**）「两条列表把不合法卡组筛掉」**
- 改：`FilteredDeckIndices` / `DeckSelectionPopup.Shown` 各加一条 `DeckRules.Validate == None`。代价 **低**，但 **⛔ 是偏离**：
  ① 原版列表不筛（§三·5）；② 「编了一半的卡组」会**突然消失且点不进去继续编**，比现状更糟。
  只建议当**临时止血**，且注释里必须写「这是我们挑的，不是原版的做法」。

## 五、没查清 + 还差什么

1. **用户的精确来路没核**：两颗 `Create` 钮通同一个洞，但「建完进不进编辑器」**不一样**（收藏窗那颗**不进**、事件窗那
   颗**进**）。真机走一次（`工具/wf_click.py`）即可钉死：`_tmp_view/click_log.txt` 会出现 `[Collection] 新建卡组…` 或
   `[Event] 新建卡组…` 之一。
2. **`_current` 被顺带改掉那一半没验**：`DeckLibrary.cs:167` 把 `_current` 指到新空卡组**并落盘** ⇒
   `BattleDriver.PickSavedDeck`（`Battle/BattleDriver.cs:2660`，读 `lib.Current`）会拿回这副空的。今天所有开战入口
   都先过督军闸（§二·6）⇒ 我**以为**够不着，但**没跑真机**，判据不足。
3. 原版 `UploadUnsyncedDeck` 的**回调/失败支**没读（网络链）—— 单机用不上，但「保存失败时原版说什么」要复刻得读它。

## 六、顺手发现（只报不改）

- `Shell/CollectionWindow.cs:3525 CreateDeck()` **建完不进编辑器**，原版 `SelectDecksTab__CreateDeck.c:28` 是直接开窗
  ⇒ 收藏窗这条路的**入口行为**本身就与原版不同（= §四候选 A 里的第二处）。
- `Shell/CollectionData.cs:335` 那句警告说的是「**内存里有、没写进存档**」——与本症状（**落盘成功**的反面）是两个方向。
- `DeckLibrary.Create` 会**顺手改掉「当前选中」并落盘**（`:167-168`）—— 玩家什么都没选，选中项却变了。
