### 2. A475 —— 为什么「字距排在 `AlignLeft` 之后」是缺陷、为什么**不用**补 `ForceRelayout`

- **机理**：`MenuDraw.AlignLeft` → `Label.AlignLeftOn` = 「先 `RefreshBounds()` 量一次、再按**当时的 `WorldW`** 反推整块位置」
  （`Battle/Label.cs:790-794`；`localPosition.x = worldLeftX − 父x + WorldW×0.5`）。
  而 `SetCharSpacing`（`Battle/Label.cs:463-472`）**只重排 mesh、不重量** ⇒ 排在它**之后**加宽 = 那一行是**按旧宽**摆的
  ⇒ 字整体往**左**溢出 `Δ宽/2`（TMP 的 `NewText` 把所有 TMP 建成 `Center`，`Core/TmpFont.cs:158`
  ⇒ 加宽是**对称**的、不动的左缘就一定会移）。
- **同一条纪律的现成出处**：本文件 `:721-722` 自己写着「🔴 **顺序不能反**：`AlignLeftOn` 是按**当时的 `WorldW`** 定位的，
  而 `SetAutoFitBox` 会**改字号 ⇒ 改宽** ⇒ 先对齐再自适应，左边缘会被推走（实测偏 **40.75px**）」——
  `SetCharSpacing` 与 `SetAutoFitBox` **就是同一类**，所以这一处是**违反自己的注释**，不是新规矩。
- **⛔ 为什么本处不补 `ForceRelayout()`**（与 H31 在 `InboxWindow` 那处的区别 —— H31 那处**必须**补）：
  `AlignLeftOn` 自己**头一句就是 `RefreshBounds()`**，那一次读的是 `SetCharSpacing` 已经 `ForceMeshUpdate` 过的
  `textBounds` ⇒ `WorldW` 本来就是**含字距**的新值，`ForceRelayout` 只是把同一件事做第二遍。
  `InboxWindow` 那处没有「之后再来一次量宽」的口（那颗是 **Center**、根本不调 `Align*`）才必须显式补一刀。
- **原版侧的旁证**：`m_characterSpacing = 5` 是 **TMP 的序列化静态字段**（不是运行期事件）——
  原版**不存在**「先对齐、后加字距」这种次序，所以照原版只能「字距在前」。

### 3. A476 —— 为什么出声、为什么**每处一次**、为什么**另一条早退不出声**

- **为什么出声**：`_tmp == null` = **点阵后端**（`TmpFont.Available == false`，`Core/TmpFont.cs:52`；`Label.Create:72-73`
  在这条路上一整个 `Align*On` 等于不存在）⇒ 那时**整批左/右对齐静默退回居中**（画面错、日志空）。
  同族的 `SetCharSpacing` **早就出声**（`Battle/Label.cs:466-468`）⇒ 两个口口径不一致本身就是缺陷（红线：**不许静默失败**）。
- **为什么不逐次打**：两个口全仓约 **20 个生产调用点**（主入口 = `Shell/MenuDraw.cs:1585-1594`；
  `Deck/DeckRuntime.cs:3391` · `Shell/CollectionWindow.cs:1677` 还会**逐格**调），而且**每个窗每重建一次就跑一遍**
  ⇒ 逐次刷屏会把别的告警淹掉、信息量为零。**本仓先例**（同一件事故只出声一次）：
  `Shell/ItemDrawer.cs:727-737` 的 `Note` · `Core/CardIcons.cs:91` 的 `_warned` · `Core/Tooltip.cs:392` 的 `_warnedNoEntry`。
  ⇒ key 取 **「方法 + 节点全路径」**：既是「每处一次」，又能认出是哪一窗哪一颗（"Window Title" 这种重名不会互相吞）。
- **⛔ 为什么 `HasMeasuredWidth()` 那条早退不出声**（`Battle/Label.cs:791`/`:801`）：那是**有意的守卫**
  （空串 / 量不出宽时**不许动位置**，否则会把节点扔到 2.1e9 之外 —— 见 `HasMeasuredWidth` 的文件头实测），
  而且**空文案是正常状态**（零值态面板、等数据的格子），调用方灌进文案后会**再对齐一次**
  （例 `Shell/TrophyInfoPopup.cs:461`）。与「这个后端根本没有对齐功能」是两件事。
