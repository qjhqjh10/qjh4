## A315 —— 原版 `BlinkGraphic` 公共件该长什么样

### ① 结论
一个**普通 MonoBehaviour**，`Update()` 每帧算 `t = Clamp01(|Cos(blinkSpeed × currentTime)|)`、**只改 alpha 一位**：`a ← Lerp(a, a×colorVariation, t)`，**算完才** `currentTime += Time.deltaTime`（scaled）；**驱动 = Unity 帧循环（不是协程）**。**我们已有一份逐字实现**（`Shell/RewardWindow.cs`，A355 已把 sin 订正成 cos）——「抽公共件」= 把那一份抬出来，不是重新发明。

### ② 证据
**(a) 字段表**（`d:/2/Warpforge_code/.../BlinkGraphic.cs` + 反编译实读偏移）
| 偏移 | 字段 | 类型 | 出厂值 / 来源 |
|---|---|---|---|
| `+0x20` | `graphic` | `Graphic`（`[SerializeField]`） | `OnValidate()` 里为 null 则 `GetComponent<Graphic>()` |
| `+0x28` | `blinkSpeed` | float | `.ctor` 立即数 `0x3f800000` = **1.0** |
| `+0x2c` | `colorVariation` | float | `.ctor` 立即数 `0x3f000000` = **0.5** |
| `+0x30` | `currentTime` | float | `.ctor` 不初始化 ⇒ 0 |
| `+0x34..0x43` | `originalColor` | `Color` | `Start()` 从 `graphic.color` 拷（vtable 0x298 getter） |

**(b) 方法体**（`d:/2/tools/decomp_full/BlinkGraphic__{ctor,Start,Update,OnValidate}.c` 逐句）
- `Update()`：`uVar3 = FUN_180488130(blinkSpeed × currentTime)` ⇒ `f = clamp01( bits(uVar3) & 0x1834b2e60 )`
  —— `0x1834b2e60` **实读（4 字节）= int `2147483647` = `0x7FFFFFFF`** ⇒ 那是 **float 取绝对值**的掩码；上界 `0x1834b2bb8` **实读 = 1.0f**（`0x1834b2bb4 = 0.5f`，同 `DelayedParticlePlay` 那条）。
  ⇒ `newA = (a×colorVariation − a)×f + a`（= `Lerp(a, a×colorVariation, f)`），**只写 `Color` 的高 32 位（alpha），低 32 位原样 `CONCAT44` 带过去**；写色走 vtable 0x2a8。
  ⇒ **最后**：`currentTime += Time.deltaTime`（`UnityEngine_Time__get_deltaTime`，**scaled**，⛔ 不是 unscaled）。
  ⇒ `graphic == null` 那一支走 `FUN_1803f47a0()`（**抛 NRE**，反编译标「不返回」）⇒ **时钟一次都不走**。
- `Start()` = `originalColor = graphic.color`（不改色，当帧不写）。
- 🔴 **`FUN_180488130 = Mathf.Cos`（不是 Sin）**，三条独立判据：① `Easing__<Get>g__inOutSine_0_30.c` = `(1 − F130(t×π))×0.5`，而 `0x1834b2e90` **实读 = 3.14159**（任何 InOutSine 都必须 `g(0)=0` ⇒ `F130(0)` 只能是 1 ⇒ 只能 cos）；② `…g__outSine_0_29.c` = `F6e0(t×π/2)`、`…g__inSine_0_28.c` = `F6e0((t−1)×π/2)+1`（`0x1834b2ec4` **实读 = 1.5708**）⇒ **`F6e0` 才是 sin**；③ `UIFlippableAndRotableUVs__RotatePointAroundPivotUVs` 的标准旋转式（cos 配 x、sin 配 y）。
  ✅ 与**记忆文件** `warpforge-ui-preserve-aspect.md:54`（A320 的裁决）**一致**；`Shell/RewardWindow.cs:325-340` 已就地订正过同一句；`资料/主菜单_原版规格.md:270-271` 那句错解释**仍未改**（本件不动）。

**(c) 实例普查**（`assets_full/*/MonoBehaviour/*.json` **全树扫**，不按文件名猜）
**36 个实例 · 全部在 `bundle_menus_assets_all` · `(blinkSpeed, colorVariation)` 36/36 = (1.0, 0.5)**（一个都没被 prefab 覆盖，与 `.ctor` 立即数逐位相同）。宿主 GameObject 名分布：`background`×22 · `Tap To continue`×9 · `Tap To Continue`×2 · `Glow`×2 · `Tap to close`×1（⇒ 它是「**会呼吸的提示/底图**」那类件的通用件）。

**(d) 我们自己已有的那一份（抽件要抬的就是它）**
`Shell/RewardWindow.cs`：`BlinkT` `:431`（`Clamp01(|Cos(BlinkSpeed × _blinkT)|)`）· `BlinkAlpha` `:433` · `BlinkClock` `:435` · 常量 `BlinkSpeed/BlinkVariation` `:351` · 状态 `_tapLabel/_tapBase/_blinkT/_blinkNullWarned` `:367-375` · `BlinkTick(float dt)` `:664`（次序照原版）；**驱动** = `RewardWindow.Tick(float dt)` `:570`（帧循环 / 自检直调）。断言在 `Editor/RewardsScene.cs` §九(f)（`:5845-5910`、`:6153-6170`）。

## A384 —— 每日重置（`MissionResetSignal`）

### ① 结论
**这个信号在客户端【没有任何地方发】**（不是「我没找到」，是**泛型实例全表里的硬否定**）⇒ 发点在**后端**；客户端只有**登记方** `SkullsCount.OnReset()`。每「天」的那一拍由**服务器时间的日界**决定：`DailyLoginChallenge.GetNextUpdate()` = `lastUpdate.Date + 1 天`（进度未满时返回**当天 0 点**），`Missions` 用 `ActionScheduler.Schedule(那一刻, …)` 排一次 **PlayFab 云脚本（`0x401`）**再重排。⇒ 「什么时候触发」= **服务器换日**，不是本地跨天检测。

### ② 证据
- 类型与登记：`dump.cs:60974 public class MissionResetSignal : IBattleSignal, ISignal`（字段 `missionId`；`MissionResetSignal.cs:9`）。
  `decomp_full/SkullsCount__OnReset.c` 全文 = `Signal.Register<…>(<Action>, DAT_184272a28)`（**登记**，不是发）。
  调用链实读：`MissionChallenge__Initialize.c` 调 vtable `0x1c8`、`MissionChallenge__DisableChallenge.c` 调 `0x1b8`；`dump.cs` 给 `OnInitialize = Slot 9` / `OnReset = Slot 8` ⇒ **同序**（`0x1b8` = OnReset = **被 `DisableChallenge` 调**，**不是每天定时器**）；`Initialize()` 只在 `initialized == false` 时调一次。
- 🔴 **「谁发」的硬否定（可复用的一次证否法）**：`d:/2/tools/il2cpp_out/script.json` 的 `Addresses` 段（= 二进制里**全部泛型实例**）里 `Method$Scaffold.Core.Events.Signal.Raise<T>()` **共 37 个 T**：AddCardEffect / AddSabotageCard / AddTag / Attack / BattleEnd / CampaignNodeCollected / CampaignPointAmountUpdate / CardCollectionUpdated / CardPlayed / CollectFaith / CollectRewards / CollectSpiritStone / CollectorLevelChange / CollectorXPChange / CompleteCampaign / CreateSecret / Damage / DraftRunFinished / DrawCard / EnemyHealthChange / EnergySpent / EventExpired / HealUnit / InventoryUpdated / LiveOpsHandlerRefreshed / MissionComplete / OpenContainer / PlayerHealthChange / ScreenResolutionChange / SetAttribute / TriggerAbility / TroopKilled / UnitReanimated / UnitSwarm / UpgradeCard / UpgradeForge / WildcardUpdate。
  **`MissionResetSignal` 不在其中**；而 `…Signal.Register<MissionResetSignal>()` **在**（`script.json:2049611`，`Address 69672280`）。
  全库提到这个类型的地方**只有 3 处**：类声明（`dump.cs:60974`）· `MissionResetSignal$$.ctor` · 上面那条 `Register<MissionResetSignal>`。
  ⇒ **它是全客户端唯一「登记了却从不发」的信号**（37 个 Raise 类型里其余 6 个是「只发不登记」，见 §顺手发现 3）。

## A198② —— 「逐视口可入栈」的设计选项（**只查、只列选项，不定案**）

### ① 结论
原版的裁切**逐节点**：一个视口节点一个 `RectMask2D`，**挂在 `ScrollRect` 的 `Viewport` 那一级**（uGUI 标准位），**一扇窗里几个视口就有几个组件**（`Collection Menu Variant` 一扇窗实读 **6 个**），TMP 输入框的 `Text Area` 也各挂一个；**参数只有两个**（`m_Padding` / `m_Softness`），**两个都真在用**。

### ② 证据
- **计数复现**：UnityPy 直读 `menus_assets_all.bundle` ⇒ `RectMask2D`（判据 = 同时有 `m_Padding` 与 `m_Softness` 且无 `m_RaycastTarget`）= **150 个**，与既有记录「全库 222 个（菜单 **150** / 通用弹窗 5 / 战场 65 / 主菜单 2）」**逐数吻合**。
- **挂在哪一级**（逐实例沿 `m_Father` 走上去，节选原文）：
  · `Viewport ← Scroll View ← Content ← Reward Window`（pad 全 0 · **softness (200,0)**）
  · `Viewport ← Scroll View ← Content ← Campaign Reward Window`（softness (200,0)）
  · `Viewport ← Packs Scroll View ← Shop Tab ← Tabs ← Content Area ← Shop Menu Variant`（softness (0,25)）
  · `Viewport ← Scroll View ← {CardsTab | Alternate Art Tab | Cardback Display} ← Tabs ← Content Area ← Collection Menu Variant`（softness (0,0)）
  · `Text Area ← Input Field ← Name FIlter ← Filters ← Viewport ← … ← Collection Menu Variant`（pad **(−8,−5,−8,−5)** · softness (0,0)）
  ⇒ 形态固定为「**mask 挂 `Viewport`，`Scroll View` 是它的父**」，**没有一层 mask 罩住另一层 mask 的写法**（输入的 `Text Area` 是**并列**的另一处视口）。

## A217② —— 原版「同窗再开不重建」时，那 9 条入口靠什么刷新内容

### ① 结论
**基类里根本没有「刷新内容」这回事**：原版复用实例时**每次都重喂一遍 `data`/`options`（`SetupData` 只写两个字段）**，然后看 `CurrentState` —— **`Open` ⇒ 什么都不做直接返回**；`Background` ⇒ 提回前台；`Closed` ⇒ 才 `SetActive(true)` + `Open()` + 触发 `OnOpen` 委托。
⇒ 刷内容**只可能**来自：**各窗自己 override 的 `TryOpen(data, options)`（全库 7 个）或 `Open()`（57 个）**，或窗自己订阅的数据更新。**那 9 条入口对应的族（`GameWindowWithTabs` 系）里没有这一层 ⇒ 原版「再开一次」就是不刷。**

### ② 证据（两条 `OpenWindow` 重载本地没有 `.c` ⇒ 用 **VA 反汇编** + `dump.cs` 的 RVA）
- `WindowsManager.OpenWindow(ComponentReference<GameWindow>, object, bool, GameWindowOptions)` = **VA `0x180875990`**（`dump.cs` RVA 0x875990 / file off 0x874390；本件用 capstone 解，公式 `file off = RVA − 0x1600`）：
  `automaticallyLoadedWindows`（`+0x68`）**`TryGetValue(ref, out win)`**（call `0x1815caa30`）⇒ **命中跳 `0x180875bf8`**：`rcx=this, rdx=win, r8=data, r9d=closeAll, 第5实参=options` ⇒ **`call 0x180875650`**（= `OpenWindow(GameWindow, object, bool, GameWindowOptions)`）⇒ 返回 `win`。
  （`OpenWindow(AssetReference, …)` VA `0x1808758C0` 只是把 AssetReference 转成 ComponentReference 再 **tail-jmp 到 0x180875990**。）
- `WindowsManager__OpenWindowCO.c` 末段 = **`window.TryOpen(data, options)`**（`(**(code **)(*param_2 + 0x198))(param_2, param_3, param_5, …)`；`GameWindow` 上吃 `(object, GameWindowOptions)` 的虚方法只有 `TryOpen`，`d:/2/Warpforge_code/.../GameWindow.cs:58`）。同函数还实读：`type==0` 且 `openWindows.Count>0` ⇒ `HideAllWindows()`；`type==1` ⇒ 对 `currentWindow` 调一个 0 参虚方法；然后 `set_CurrentWindow(win)`（`currentWindow` 字段 `+0x58`）· 压 `openWindows`（`+0x50`，**末位已是同一扇就不重复压**）。
- 基类 `TryOpen(object data, GameWindowOptions options)` = **VA `0x180836120`**（本地**没有** `.c`）逐句：
  ① `call [rax+0x188]`（this, data, options）= **`SetupData`** —— `GameWindow__SetupData.c` 实读：**只写 `+0x48 windowOptions` / `+0x40 data`，一个 UI 字段都不碰**；
  ② `esi = CurrentState`（`+0x68`，`GameWindow.cs:29` 的字段）；
  ③ `state == 0`（Closed）⇒ 播 `openSound`(`+0x28`) → `SetActive(true)` → `state=1` → **`call [rax+0x178]`（= `Open()`）** → 触发 `OnOpen`（`+0x58` 委托）；
  ④ 收尾 `cmp esi,1 / cmovne edi,eax / test edi,edi` ⇒ **只有 `state==2`（Background）** 才 `state=1` + `call [rax+0x1a8]`（提回前台）；**`state==1` ⇒ 一个字段都不写就 return**。
  （旁证：`WindowsManager__ShowPreviousWindow.c` 末句就是 `set_CurrentWindow(prev)` + **无参 `GameWindow__TryOpen(win,0)`**；`GameWindow__TryOpen.c` 的**无参**版与上面 ①③④ 逐条同构。）
- **「谁在刷」**：`grep "override void TryOpen"`（签名桩）**只有 7 个**：`DeckEditingWindow:69` · `DeckSelectionPopup:33` · `PurchasePremiumWindow:77` · `RankedEventWindow:66` · `RankedEventWindowV2:74` · `SinglePlayerOnlyEnergyEventWindow:39` · `SkirmishEventWindow:66`；**形状一致 = 先调基类、再补自己的刷新**：
  `decomp_full/SkirmishEventWindow__TryOpen.c:14` = `GameWindow__TryOpen(this, data, options, 0)` → 后面 `SkirmishEventWindow__RefreshScore` / `TimerDisplay__Initialize`；
  `DeckSelectionPopup__TryOpen.c` 同样先走基类、再 `DeckSelectionPopup__Initialize(...)`。
  `override void Open()` 有 **57** 个（`CollectionScreen:16` · `ShopWindow:44` · `ChatPanel:71` · `Everguild/LiveOps/InboxWindow:32` …）—— 但 `Open()` **只在 Closed⇒Open 那一拍**被基类调。
- **关掉就是销毁**：`WindowsManager__CloseWindowCO.c` = 调 `Close` → 从 `openWindows` 移除 → 在 `automaticallyLoadedWindows` 里 `TryGet` 命中则 **`Object.Destroy(win.gameObject)` + `ComponentReference.Release(ref)` + 从字典移除**；`SceneUnloadOperations` 清空字典。⇒ 「不重建」只在**窗还开着**时成立。
- **我们这边**：`Shell/WindowsManager.cs:347-357` 的 `TryOpen` **恒调 `Open()`** ⇒ 差**只出现在「窗还开着时再点」**这一档（关掉时会重新加载，两边一样重建）。

### ③ 还差什么
- 原版**重新加载那一段**（Addressables 取 prefab → 加进字典）在缺失的 `.c` 里；本件只读到 `TryGetValue` 命中那一支与 `OpenWindowCO` 全部（VA 都在上面，可再挖）。
- 9 条入口**各自**在原版走哪个重载 / 带不带 `data` **没查**（`SettingsWindow` / `SocialWindow` / `LeaderboardWindow` / `PlayerProfileWindow` / `RewardsWindow` 这 5 个**类名在签名桩里根本不存在**，要按 prefab 名反查类再谈入口）。

### ④ 建议做法（选项）
- 若**照原版改**（`CurrentState != Closed` ⇒ 不调 `Open()`）：必须同时给那 8 条入口（`OpenInbox/OpenSettings/OpenSocial/OpenChat/OpenLeaderboard/OpenProfile/OpenRewards/OpenCollection/OpenShop` 里走 `OpenByRef` 的那些）**补一条显式刷新**，三种做法：
  (a) 把重建从 `Open()` 挪进显式 `Refresh()`，入口 `Open()` 命中复用后**显式调 `Refresh()`**（= 原版 `SkirmishEventWindow` 那个形状：基类 + 自己的刷新动作）；
  (b) 让**真有内容要重建**的窗 override `TryOpen(data, options)`（照原版那 7 个的样子）；
  (c) 保持现状（不动）——⛔ 与铁律 11 冲突，除非能证明那 8 扇窗都不需要刷。
- 🔴 无论选哪个：**`Shell/CardDetailPopup.ShowCard` 是必改点**（它今天就靠「每次重建」换卡，S4 已记）——要么显式 `Build()`，要么它自己 override `TryOpen`。
- ⚠️ 判据面：本件证明的是**基类行为**；「那 9 条入口在原版是不是每次都带 `data`」是**另一半**，没查清之前**别按「反正不刷也无所谓」定案**。
