## 二、🔴 为什么**只**接一处（H2 §5.1 的裁断 + 我复核出的第二条理由）

H2 报告 **§一 的表格**里写「调用点在 `ArenaRuntimeLoader.cs` / `EnvironmentApplier.cs`」（派单也这么转述的），
但 **§五·1 只有一处补丁**，而且**专门写了一节「为什么不放在 `EnvironmentApplier.EnsureSceneBlendables()`」**。
⇒ 按 §五·1 的「**一行**」接，**没有**接第二处。两条理由都**现读核过**：

1. **时机（H2 已写，我核过）**：`EnvironmentApplier.Apply` 在**全仓只有一个调用点** ——
   `BattleDriver.cs:3156`（**进攻卡**那一段，`_envApplier.Apply(envItem, instant: false)` 前面就是
   `if (!useCard) { …; return; }`）。而 `EnsureSceneBlendables()` 只从 `Apply()` 里被调到（`EnvironmentApplier.cs:205`）
   ⇒ **放那儿这 5 条在「打出一张进攻卡」之前根本不存在**，与原版（它们序列化在场景里、从战场出现那刻就在）不符。
   （现读法：`grep -n "envApplier\|EnvApplier" Battle/BattleDriver.cs` ⇒ 4 处 = `AddComponent` / `Apply` / 字段 / `Advance`。）
2. 🆕 **去重口径对不上 ⇒ 两个都接会【建两遍】**（**这一条 H2 原文没写**）：
   `BuildSceneAnimFx` 的去重判据是 **`ScenarioBlendables.cs:1972`** 的 `_sceneAnimFxRoot != null && _sceneAnimFxRoot == arenaRoot`
   —— 认的是**传进来的那个 Transform**。而：
   · 本件的调用点传的是 **`Current.transform` = `Warpforge_<场>`**（`ArenaRuntimeLoader.cs:108-110` 刚 `Instantiate` 出来的那件）；
   · `EnvironmentApplier.ArenaRoot()` 返回的是 **`Arena3D`**（`EnvironmentApplier.cs:500` 的 `GameObject.Find("Arena3D")`）。
   **两者不是同一个 Transform** ⇒ 去重**拦不住**；而 `nodes[]` 是**无条件** `new GameObject`（`ScenarioBlendables.cs:2005`）
   ⇒ 第二处会**多建出一整棵 `Scenario/…` 重复树**，且**不报错**（静默）。
   ⚠️ **只接一处**时没有这个问题（本件就是把两处合并成一处）。
3. **顺带核过挂载时机是对的**：`ArenaRuntimeLoader` 是挂在 **`Arena3D` 自己**身上的（`Editor/BattleScene.cs:10348`
   的 `root.AddComponent<CardPresentation.ArenaRuntimeLoader>()`）⇒ `Instantiate(prefab, transform)` 出来的是
   `Arena3D/Warpforge_<场>` ⇒ **`Current.transform` 就是战场内容那棵树的根**，与 `BuildSceneAnimFx` 的参数注释
   「`arenaRoot` = 战场实例的根（`Warpforge_<场>`）」一致。
   而 `res`（`SceneResolver`）是**从 `arenaRoot` 往下搜**的 ⇒ 我们要找的那批粒子都在它下面
   （`ArenaBuilder` 把粒子**平铺**在根节点下：`ArenaBuilder.cs:1774` 的注释 + `:2041` 的 `SetParent(root.transform, false)`）。
