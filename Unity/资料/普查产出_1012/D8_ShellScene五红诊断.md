## 一、红 1 / 红 2 / 红 3 —— 同一个根因：**逐位相等** 比 **反推值**

### 1.1 判据与算式（现读）

- `ViewportClip.ClipPx`（`Shell/ViewportClip.cs:169-191`）**不是存下来的**，是**从节点世界坐标反推**：
  中心 `LayoutSpace.ToPixel(MenuDraw.PosInDesignSpace(transform))`，半宽 `rt.rect.width × (1080/10) × 0.5`。
  节点那个 rect 本身则由 `MenuDraw.ApplyPxRect`（`MenuDraw.cs:170-174`）= `Local`（px 中心 → 设计世界）+ `SetPxSize`（px → `sizeDelta`）写进去的。
  ⇒ **「写进去」与「读回来」是两条路，中间隔着一次 px → 世界 → px 的往返。**
- 判定用的 `MenuDraw.SameRect`（`MenuDraw.cs:241-242`）是**四个字段逐位 `==`**；
  `ShellScene.cs:1637` 那一条更直接：`o4.x1 == 200f && o4.y1 == 100f && o4.x2 == 300f && o4.y2 == 400f`。

### 1.2 数值：这个往返在 float32 下**不是恒等**（逐句模拟这条代码路径）

| 写的框 | 反推回来（`ClipPx`） | 差 |
|---|---|---|
| `(100,100,500,500)`（`vpBox`，红 1） | `(99.999939, 100.0, 499.999939, 500.0)` | **x1 / x2 各 −6.1e-5 px**，y 逐位相等 |
| `(100,100,300,500)`（`vpBox2`，红 2） | `(99.999939, 100.0, 299.999939, 500.0)` | 同上 |
| ⇒ 交集（红 3） | `o4 = (200.0, 100.0, 299.999939, 400.0)` | **只有 `x2` 一个字段差**，而 `:F0` 把它印成 `300` |

🔴 **这就解释了「期望与实测打印一模一样却仍红」**：**判定用的是浮点全精度，打印的是 `:F0` 四舍五入**。

### 1.3 为什么可以排除「值真的偏了」（四条独立观察）

1. **往返没有系统性缩放项**：`Editor/ShellScene.cs:443` 把 `cam.aspect` 钉成 `LayoutSpace.DesignAspect`（16/9）且**全程不再改**
  （`:470` / `:666` 只取 `Camera.main`，`:474` 只换 `targetTexture`，不碰 `aspect`）
   ⇒ `VisibleWidth × 108 = 10 × (16/9) × 108 = 1080 × (16/9)`，float32 下**恰好等于 `1920.0`**（已核）。
   ⇒ 残余只可能来自中间几步的浮点舍入（~1e-4 px 量级），**不可能**是「比例不对」。
2. **同一块里凡是量这份框的断言全绿，而且打印精度到 F2（±0.005px）**：
   `:4500`「实测 x **100.00..500.00** ⊆ 100..500」· `:4513`「左沿 **100.00** ≈ 100 · 右沿 **500.00** ≈ 500」·
   `:4630`「右沿 **300.00** ≤ 300」· `:4643`「**300.00** ≈ 300」· `:4656`「**100.00** vs 100.00」
   ⇒ 实得值与字面量之差 **< 0.005 px**，比那批断言用的 `0.6` 容差小两个数量级。
3. **反例检验（H40 §七 两条判读法）都落空** ⇒ A484 那条链是好的：
   · 若 `clipArg` 没生效 ⇒ `:1588`/`:1596` 会印 **500.00**（它们印的是 300.00）；
   · 若守卫那条链另有处覆盖形参 ⇒ `:1617` 的 `NodeShadowedByParam` 会涨（实测 0 → 0）。
4. **同一文件另外 4 处 `SameRect` 全绿**（`:1115` / `:1131` / `:2445` / `:2480`）——
   它们比的都是**没进过世界往返**的量（字面量 / 纯算式 / 存下来的矩形）。
   ⇒ 对照组把「`SameRect` 本身坏了」排除掉，**剩下的唯一变量就是「有没有往返」**。

### 1.4 这一条**不是**「把节点挪了」或「没重裁」（也一并证伪）

`:1582` 那条之所以红，**不是**因为节点没挪：紧接着的 `:1588`「右沿 300.00」（该断言在 `lbNode.RefreshBounds()` **之后**）
证明**重裁用的是新框**；而 `:1599`「左沿 100.00 vs 100.00」证明是**按新框重算**而不是整块平移。
⇒ 红 2 只可能是**同一个逐位相等**问题。
