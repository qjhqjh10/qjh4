   「行号 → 原字面量 → 键名」，并裁定「**要做、只是先后**」；
   `资料/普查产出_第五会话/交件_波0b4建键.md:84` 也写着「**键名待与 `Battle/Cemetery/*` 那 19 条活键对表后再定**」。

**⇒ 处置（本笔的选择，理由写全）**：调用点**一律走 `LogTerm`**，并**带「过渡期兜底」两列**：
```csharp
static string LogTerm(string key, string en, string zh, params object[] args)
{
    if (Loc.HasEntry(key)) return string.Format(CardText.Term(key), args);   // 键在表里 ⇒ 一切照表
    Loc.T(key);                                                              // 缺键：出声 + 记账（⛔ 不静默）
    return string.Format(CardText.Zh ? zh : en, args);                       // 过渡期兜底
}
```
- ① **为什么不是「就写 `Loc.T`」**：`Loc.T` **缺键返回【键名本身】** ⇒ 日志会印 `Battle/Log/Death`（本仓踩过）。
- ② **为什么不是 `CardText.TermOr(key, 英文兜底)`**：那样在**中文档**会印英文（12 条全中），
  而这一节自检有 3 条断言盯中文子串（见 §五·3）⇒ **当场假红**、且中文玩家看到的日志会退化。
- ③ **为什么不是「把 12 条键加进 `Loc.cs`」**：`Core/Loc.cs` 在 `CardPresentation/Core/` —— 简报明写
  「另有一个写手在 `CardPresentation/Core/`＋`Editor/` ⇒ **别越界**」（对应铁律 13·3「一个文件一个写手」）⇒ **没动**。
- ④ 形状**与同文件的 `HandFullText()` 一致**（`BattleDriver.cs:4081`：先 `Loc.HasEntry`、缺了回自己那两列）。
- ⑤ **键一进表，这两列兜底就永不触发、可整段删**（删之前核一句：与表里那两列**逐字相同**）。
  📌 主对话已告知：**那 12 条键已另派专人加进表** ⇒ 这一步很快会发生（⛔ 本笔不去等、也没碰 `Loc.cs`）。
- ⑥ 缺键**会出声**（`Loc.T` → `Debug.LogWarning`，按键去重一次；`MissingCount` 每次 +1）⇒ **不静默**。
  ⚠️ 自检会因此看到 12 条 `[Loc] 语言表里**没有**这个词条：Battle/Log/…` 告警 —— **那是预期的**（键进表即消失）。
