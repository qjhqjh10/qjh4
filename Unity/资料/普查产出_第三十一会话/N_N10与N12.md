## 四、顺手发现（**没改** —— 都不在我这两个文件里）

1. **践踏溢出量会随本笔变**（`N12` 的**后果**，不是缺陷）：`excess = dealt − hpBefore`，
   `dealt` 取自 `ApplyDamage` 的返回值 ⇒ 甲 2 的 1 血残骸挨 5 点时溢出 **2 → 4**。判据见上面「可达性」那一行。
2. **`DeckEditorState.CostCurve()` 自带一份 `[0,20]` 夹取**（`:598` `int k = c.Cost < 0 ? 0 : (c.Cost > maxCost ? maxCost : c.Cost);`）——
   那是**卡组的费用曲线**（左列 `Card Cost` / `Cards in deck`），与卡池筛选**是两件事**。
   ⚠️ **原版那一处夹不夹、夹到几，我没查**（`DeckCostQuantityRowDrawer__Initialize.c` 没读）。
   **没有改它**（同一个文件里，但它不在本笔的判据里 ⇒ 不顺手改）。
3. **我们的费用筛选格在「还没选督军」时**没有隐藏 —— 原版 `CardCostFilter__SetFilterToDeck.c:13-22`
   是 `SetActive(deck + 0x40 /* deckHero */ != null)` ⇒ **没督军时那一族格子整个隐藏**。
   我们 `FilterPanelModel` 的费用族是**无条件**建的（`CostBuckets` 那一段没有可见性开关）。
   判据同 `资料/普查产出_第三十一会话/I_卡池筛选判据.md` 问题 2 那张表的 `CardCostFilter` 那一格。
   **落点在 `CardPresentation/Core/FilterPanelModel.cs` + `Deck/Runtime` ⇒ 本代理禁改名单里，没动。**
4. **进程坑（我自己踩的，已修回）**：用 `bytes.replace(旧,新)` 改源码时，
   **结算侧那一行与预览侧那一行**在文本上**逐字相同**（`if (u.Armor > 0 && actual > 0) …`）⇒
   一次 `replace` **把两处都改了**，而它**不报错**（`assert count==1` 只挡了「一处都没有」那种）。
   我是靠「副本 vs 工作树 `cmp`」才抓到的。⇒ **教训**：替换前后都要**打出计数**，
   而且 `IsRemnant` 那条判据现在**两处长得不一样**了（结算侧带守卫、预览侧不带）—— 这本身也提醒后来人别一把替换。
5. **`VulnerableDamagePart`（`:4816`）自身**照旧**不减残骸的甲（`Math.Max(1, v − u.Armor)`）** ——
   这**不算漏**：现读全仓**5 个**调用点，**结算侧那三个都已经在残骸上被挡掉了** ——
   `:4923`（`DamageAfterReduction` 的 `return actual + …`；它靠上面 `:4922` 那道 `N7` 早退挡住残骸）·
   `:5809`（空投舱支，`:5810` 的条件里带 `!u.IsRemnant`）·
   `:5887`（堡垒支，`:5888` 的条件里带 `!u.IsRemnant`）；**剩下两个是预览侧**（`:5042` `DamageAfterReductionOne` ·
   `:5222` `WouldKillByEntries`）—— 那正是原版预览自己不看残骸的那条口径，**故意不挡**。

## 五、怎么复现这两套离线判别式（不跑 Unity、不碰工作树）

```bash
# ① 把被测源码拷进一个临时树（**只读地拷**，⛔ 不动 d:/4 的工作树）
T=/tmp/wf_n1012p ; mkdir -p "$T/工具" "$T/MyGame/Assets"
cp -r "d:/4/Unity/工具/ruleprobe" "$T/工具/ruleprobe" ; rm -rf "$T/工具/ruleprobe/bin" "$T/工具/ruleprobe/obj"
cp -r "d:/4/Unity/MyGame/Assets/RuleEngine" "$T/MyGame/Assets/RuleEngine"
mkdir -p "$T/MyGame/Assets/CardPresentation/Deck"
cp "d:/4/Unity/MyGame/Assets/CardPresentation/Deck/DeckEditorState.cs" "$T/MyGame/Assets/CardPresentation/Deck/"
find "$T" -name '*.meta' -delete
```
- `ResolveOutDir` 是按**汇编位置往上找 `MyGame/Assets`** ⇒ 副本那边**自成一体**，读数与工作树一致（本次已 `cmp`/`diff` 核过）。
- 判别式的两个小宿主（各 ~100 行，`EnableDefaultCompileItems=false` + `Stub.cs`）：
  `N12` ⇒ `/tmp/n1012_harness`（`n1012.csproj` / `Main.cs`，编 `Core/*.cs`）；
  `N10` ⇒ `/tmp/n1012_harness10`（`n1010.csproj` / `Main10.cs` / `CardTextStub.cs`，编 `DeckEditorState.cs` + `Core/*.cs`
  ＋三个极小替身 `CardText` / `FilterPanelModel` / `Loc`，**只喂卡名搜索那几行，与费用档无交集**）。
  ⚠️ 它们**在临时目录里**（不是仓库产物）⇒ 想留就把那两个 `.csproj` + `Main*.cs` 搬进 `工具/`（本代理没搬：
  白名单只给了那两个文件）。
- 跑：`cd <harness> && dotnet build -v:q --nologo && dotnet run --no-build` ⇒ 按 `[OK]` / `[XX]` 与末尾那句
  `=== … 判别式：失败 N 条 ===` 读（⛔ 不只看退出码）。
