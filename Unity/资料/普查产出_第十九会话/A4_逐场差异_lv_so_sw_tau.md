## 〇、四个总判决（先回答简报里点名要查的）

1. **四场都没有「整个画面偏移」** —— 全图最优平移四场一致 = **dx 0 / dy +2**（1280×720），
   即 1920×1080 下的 **(0, −4)px**，与正本记的「干净的 (0,−4)px 平移」同源 ⇒ **取景平移，不是缺陷**。
   判法：`100..1180 × 100..620` 内搜 ±8px，四场都只在 `dy=+2` 变好
   （`leviathan` 12.51→**7.21** · `sororitas` 12.88→**5.88** · `spacewolves` 14.06→**6.11** · `tauviorla` 18.69→**8.43**）。
2. **整图亮度不是问题** —— 四场带形差全部 ≤ ±4（`arena_bands.py`）：`leviathan` 1.008 · `sororitas` 1.024 ·
   `spacewolves` 1.006 · `tauviorla` 0.999。**本条所有发现都是「按物体的局部差」**，别去追全局量。
3. 🔴 **正本点的「tauviorla 炮塔死黑」—— 我复核了，成立，而且是【两个独立的东西】**：
   ① 炮塔**箱体材质渲成近黑**（不是缺物体，轮廓在、同一物体的下半部却对得上）；
   ② **蓝色激光束 + 炮口闪光整条没有了**（亮像素 1678→39、最大 `B−R` 193→19）。
   ⚠️ **但正本那句「原版炮口有一团蓝色枪口闪光、我们那边没有」的【另一半推测】我推翻**：
   炮口那团**不是**「我们渲得暗一点」—— 我们那边**连蓝像素都没有**（见 T2 的两组数）。
4. 🔴 **正本点的「tauviorla 我们渲成一块死黑、边缘发硬」这句的【归因】我推翻**：
   箱体不是纯黑 —— 它是**有结构、但没有受光**（我们 std **40.7** 比原版 32.4 还大，
   RGB `(40.5,34.3,30.2)` vs 原版 `(80.3,68.7,60.9)`，**色相是同一族、只有明度差 2 倍**）
   ⇒ 是**材质/受光**问题，**不是**黑贴图、也不是缺物件（见 T1）。

T2 的**硬判据**（luma mean 差别不大，因为那块背景本身就亮；这条要数蓝像素）：

```bash
cd /d/4/Unity && PYTHONIOENCODING=utf-8 python -I -X utf8 -c "
from PIL import Image
import numpy as np
o=Image.open('D:/4/Unity/MyGame/Assets/WarpforgeArena1/arenas/battlearenatauviorla/preview_battlearenatauviorla.png').convert('RGB')
p=Image.open('D:/4/Unity/资料/原版实拍/arena_0920/shot_Battle_Arena_Tau_Viorla.png').convert('RGB').resize(o.size,Image.LANCZOS)
a=np.asarray(o,float); b=np.asarray(p,float)
for x0,y0,x1,y1 in [(860,0,1280,110)]:
    for lab,z in (('ours',a),('orig',b)):
        q=z[y0:y1,x0:x1]; L=q.mean(2)
        print(lab,'n(L>180)=',int((L>180).sum()),'maxB-R=',(q[:,:,2]-q[:,:,0]).max())
"
```

印出来：`ours n(L>180)= 39 maxB-R= 19.0` / `orig n(L>180)= 1678 maxB-R= 193.0`
（另一组：`x860-1000,y40-110` 内 `B−R>60` 的像素 —— 我们 **0** / 原版 **927**，原版那团 bbox = `x900-979, y66-97`）

- **T1 的判据链（为什么判「材质」不判「缺物体」）**：
  ① 轮廓在 —— 我们那边是一整块**有形状**的暗块，不是「透过去看见背景」；
  ② **同一物体的下半部是对的**：`800,140,880,180` 我们 **64.2** / 原版 **58.2**（1.104×）；
  ③ **同一物体左边邻居也是对的**：`700,60,780,120` 我们 **98.8** / 原版 **96.4**（1.025×）；
  ④ 我们那块 `std 40.7`（比原版 32.4 大）⇒ **有内部对比（亮棱 + 黑面）**，不是一张纯黑贴图。
  ⇒ 差的是**箱体那一层没被照亮**（自发光/受光），**不是**少了一个对象。
  ⚠️ **成因没定名**：可以是「我们多了一层阴影 / 少了一盏灯 / 材质光照模型不对」，**要消融才分得开**（见 §三）。
- **T3 为什么只给 🟡**：明度差只有 4.1，但**蓝通道差得大**：
  `B−R` 均值 我们 **6.8** / 原版 **15.5**；最大值 我们 **89** / 原版 **176**；饱和度（max−min）**17.4 / 26.0**。
  这根柱子是**会动的能量柱**（`Tau Viorla Energy Bar`，正本 §一 结论五点名过 4 个），**分不清是「材质少了自发光」
  还是「两边动画相位不同」** ⇒ 如实标存疑。
- **T2 与正本的对应**：正本 `:678-680` 写 `battlearenatauviorla` 有 **`Muzzle Flash view` ×3 / `Muzzle Flash glow` ×2**
  等 11 个**与开着的重名的原版关着的对象** ⇒ 「我们到底有没有这些对象」这件事**值得用 `WF_ONLY=Muzzle` 渲一张定死**（见 §三）。
  ⚠️ **不排除**「我们建了、但被原版关着的同名件顶掉了」这条路径。

- **S1+S2 / S3+S4 是「同一个火盆的上下两半符号相反」** ⇒ 形状上像「整团火下移了」。但**颜色判据说不是位移**：
  · 盆口 `40,280,80,320`：我们 RGB `(94.9,67.6,57.3)`（`R−B` **+38**）· 原版 `(137.0,107.6,76.0)`（`R−B` **+61**）
    ⇒ **原版更亮更橙**；
  · 盆腹 `40,320,80,360`：我们 RGB `(93.3,85.3,81.4)` = **近乎中性灰**（`R−B` 只有 **+12**）·
    原版 `(39.3,24.5,12.1)` = **暗暖铜**（`R−B` **+27**）
    ⇒ **我们那边是一团白的**，不是「被移下来的橙色火」。

  但**「那一块是中性灰白、不是暗铜」这件事不是相位能解释的**。
  ⇒ 要彻底定死，需要**同一构建渲一张「把火盆那族粒子全 `WF_HIDE` 掉」**（见 §三）。
- **S5 为什么只给 🟡**：**火焰那一行两边几乎相同**（`1080,500,1200,560`：我们 `(88.5,60.5,39.8)` `R−B +49` /
  原版 `(90.8,60.9,37.4)` `R−B +53`）⇒ **不是焰色问题**；偏亮的是**烛体/光晕那一段**（`R−B` 我们 +34 / 原版 +21）。
  正本 §一 结论五已把 sororitas 的 14 个烛焰（`CandleFlame_mid` / `CandleFlame_small`）多槽材质修过一轮
  （y480-600 **+8.4 → +6.6**）⇒ **剩下的这 +16 是修完之后仍在的**。
