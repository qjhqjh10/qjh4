## 八、首跑订正（主对话复跑报回的两条几何红 —— 已改，只动断言文件）

### 8.1 现象与根因

主对话复跑 `MainMenuScene.Run` 后，(B) 的两条几何读数都是 **`±2.3e11`**：

```text
[E10] FAIL (B) 胜场图标位置 = prefab（… 实得 -231928200000.00..231928200000.00 · …）
[E10] FAIL (B) 那颗字**左对齐到 prefab 那条线**（… 实得 -231928200000.00）
```

**根因（一条，两处都中）**：

1. **`MenuCheck.NodeRectPx` 的 `Label` 分支优先** —— 我原来对**图标节点**调它，而图标节点底下正好挂着
   `Victories`（**原版父子就是这样**：`Victories` 是 `Victory Counter Icon` 的子件）⇒ 它没去量那颗
   `ImageQuad`，而是去量了 **TMP**。
2. **那颗 TMP 那时是「未激活 / 未布局」** —— 批处理里没有一局进行中的存档 ⇒ `RefreshDraftModeCard` 把
   `State` 整条 `SetActive(false)`。TMP 在未激活 / 空串 / mesh 没生成时 `textBounds` 是**未定义哨兵**
   `k_LargePositive/NegativeVector2 = ±2.147e9`，乘 108 就是 **±2.319e11**（`Battle/Label.cs` 的
   `EnsureMeasured`/`PushLayoutInactive` 那段注释里逐字记着这个数）。

⇒ 两处 FAIL 是**量法问题**（不是产品问题）：产品那两颗件的 `localPosition` / `localScale` 本身是对的。

### 8.2 改法（`Editor/ProfileRankAssertE10.cs` 一个文件）

| 改前 | 改后 |
|---|---|
| `MenuCheck.NodeRectPx(icon, Node, …)` | **`MenuDraw.QuadRectPx(iq, …)`** —— 直接量那颗 `ImageQuad`（= `MainMenuScene.QuadPxRect` 的口径：`WorldW/WorldH × 108` + 设计帧节点位置），`iq = icon.GetComponentInChildren<ImageQuad>()` |
| `MenuCheck.NodeRectPx(vicLb.transform, LabelNode, …)` | **`SelfCheckTextMetrics.RenderedRectDesign(vicLb.transform, …)`** —— TMP 自己渲出来那块的设计帧矩形（`A490/A617` 那条口径） |
| 量的时候 `State` 可能是**藏**的 | **先喂一局进行中的存档 + `RefreshDraftModeCard(true)`**（= `SetActive(true)`）再量；量完再往下走显隐矩阵 |
| 没有哨兵防护 | 每条几何先过 **`Sane()`**（宽高 1..2000px）—— 哨兵**当场判红并打印原始四值**，⛔ 不比期望值 |
| 字的 `textBounds` 万一还是哨兵（自适应那一档 `GetTextInfo` 单遍可能 early-return） | 先量一次；**只有量到哨兵时**才调公共件 `Label.ForceRelayout()`（激活档 = 真 `ForceMeshUpdate`）**补推一次版面再量**，并打一行日志说明走的是兜底。⚠️ 它**只重排 mesh、不动节点位置** ⇒ 不会替被测实现把左缘挪到期望值上（不算自证） |
| (A) 徽记用 `NodeRectPx(q.transform, …)` | 同一口径改成 `MenuDraw.QuadRectPx(q, …)` + `Sane()`（(A) 首跑本身是绿的，这一改是为了**不踩同一个坑**：`DivisionImage` 底下也有一颗 `RankImage` 兄弟节点，将来若有人给它加 Label 就会走上同一条分支） |

**只改了断言文件**：`ProfileRankAssertE10.cs`（`git diff` 只此一个文件）。
⛔ 产品侧（`ProfileTab.cs` / `MainMenuRuntime.cs`）**一个字没动**（`MainMenuRuntime` 属只读、本轮没碰）。
✅ 主对话给的那处 α 修（`FindChild(card, "State/Victory Counter Icon")`）**保留并写进了注释** ——
另外主对话顺带把卡节点的取法换成了递归 `mm.Find(...)` + 父链钉 `Viewport/Content`，我也一并保留。

### 8.3 现在这套量法**为什么批处理下能拿到真值**（三句）

1. `ImageQuad.WorldW/WorldH` 是**建件那一刻**写死的字段（`Create` 给世界高、`SetAspect` 给比例），
   **不依赖 TMP、不依赖布局组、不依赖帧循环**；位置走 `MenuDraw.PosInDesignSpace`（只读父子链缩放，
   而 `MainMenuRuntime.New(...)` 只写尺寸不写位置 ⇒ 全树 `localPosition` 由 `Center(...)` 直接给绝对值）。
2. `Victories` 那颗字先被**显示出来**（`SetActive(true)`），之后 `Text → AlignLeft` 走
   `Label.EnsureMeasured` 的**激活**分支（`TmpFont.GenerateLayout` + `RefreshBounds`）
   ⇒ `textBounds` 是**测量值**、`RenderedRectDesign` 读到的是真矩形（不再是哨兵）。
3. 每条几何都过 `Sane()` ⇒ 万一哪天又量到哨兵，**红的是「量法失效」这一条**（带原始四值），
   不会拿垃圾数去和 `8.67 / 106.12 / 109.29` 相比而给出误导性的通过/失败。

### 8.4 改坏必红的判别式（这一族）

- 图标三格偏移改一位（`MainMenuRuntime.DraftVicL/T/W/H`）⇒ 「胜场图标位置 = prefab」红（带实得卡内偏移）；
- 字不 `AlignLeft`、或 `AlignLeft` 排在 `SetText` 之前 ⇒ 「左对齐到 prefab 那条线」红；
- 把 `Victories` 挂到 `State` 底下（改了原版父子）⇒ 同一条红（`AlignLeft` 的基准与卡内偏移一起变）；
- 把 `State` 条**恒关**（谁把 `RefreshDraftModeCard` 的 `SetActive` 删了）⇒ 先撞「【几何前提】显示」这条红；
- 量法退回「对含 `Label` 的父节点用 `NodeRectPx`」或「未激活就量」⇒ `Sane()` 那条红（实得 `±2.3e11`）。
