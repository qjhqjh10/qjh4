## 二、改了什么（改前 → 改后）

### B1 · `Editor/ProfileDataAssertE13.cs`（`finally`）

改前 `:65-69` → 改后 `:77-80`：

```csharp
// 改后（先清、后还原 —— 照 Editor/NetSelfTest.cs:925-929）
if (!string.IsNullOrEmpty(ReplayStore.OverrideDir)) ReplayStore.ResetForTest();
if (!string.IsNullOrEmpty(BattleLogData.OverrideDir)) BattleLogData.ResetForTest();
ReplayStore.OverrideDir = null;
BattleLogData.OverrideDir = null;
ProfileData.SavePathOverrideForTest = null;
```

- 为什么带 `if (!string.IsNullOrEmpty(...))`：若 A/B 节就抛异常、C 节从没设过临时目录，就没东西可清
  —— 此时不该去调 `ResetForTest`（新硬挡会报一句会误导人的「拒绝清空」）。
- `BattleLogData.ResetForTest()` 也挪到 `OverrideDir` 还原**之前**：它是「清内存 + **从盘重读**」
  （`Shell/BattleLogData.cs:311`），原来在 `OverrideDir = null` 之后调 ⇒ 读进来的是**玩家的真对战记录**
  （只读、不删，但同样违反「自检不碰玩家真档」）。
- 文件头（`:24-26`）与 C 节（`:237` 旁）各加了一条「删档类调用的顺序」注释，防下一个人再写反。

### B2 · `Battle/ReplayStore.cs`（`ResetForTest` 加硬挡 + 出声）

改后 `ReplayStore.cs:660-679`：

```csharp
public static void ResetForTest()
{
    if (string.IsNullOrEmpty(OverrideDir))
    {
        Debug.LogError("[Replay] 自检：**拒绝清空录像** —— 没设 `OverrideDir` 时删的就是玩家的真录像（`"
                     + Dir + "`）。先 `ReplayStore.OverrideDir = <临时目录>`，清完**再**还原它"
                     + "（⛔ 顺序反了 = 删掉玩家的真录像）。");
        return;
    }
    ...
    foreach (var f in Directory.GetFiles(Dir, "*" + Ext))
    {
        Debug.Log("[Replay] 自检清空：删掉 " + f);   // B3：删的是用户数据 ⇒ 出声
        File.Delete(f);
    }
}
```

- 口径逐字照 `BattleLogData.DeleteStoreForTest`（`LogError` + `return`，文案里说出「先设 OverrideDir」）。
- **B3 顺手做掉**（RE1 的 B3 =「删用户数据一声不响」）：每删一份打一行 `[Replay] 自检清空：<完整路径>`。

### 新增一格测试专用改写口 · `Battle/ReplayStore.cs:314`、`:329-341`

`public static string PlayerRootForTest;` —— 只在 `Dir` 的**玩家目录那一支**生效
（`OverrideDir` 为空时，用 `PlayerRootForTest ?? Application.persistentDataPath` 当根）。

🔴 **为什么要加它（这不是顺手扩权，是 B3 的前提）**：B3 要求「构造『未设 `OverrideDir` 时调 `ResetForTest`』
也必须**不删任何文件**」。这条断言必须**真的**在 `OverrideDir = null` 下走一次；而那时 `Dir` 天然指向玩家的真目录
—— 一旦哪天硬挡被人删掉，**这条断言自己就会重演 10-24 的事故**。
⇒ 把「根」指到临时目录，「删不到玩家真档」就**由目录结构保证**，而不是靠断言写得小心。
默认 `null` ⇒ 生产路径逐字节不变（`Dir` 仍是 `persistentDataPath/WarpforgeReplays`）。

### 新增 `Editor/ReplayStoreGuardAssertE11.cs`（+ `.meta`）

独立入口 `public static void Run()`，自带 `Pass/Fail`（与 `ProfileDataAssertE13` 同形）。
⚠️ **还没接进任何宿主** —— 白名单不含 `Editor/MainMenuScene.cs`，等主对话接线（两行）：

## 四、断言（`ReplayStoreGuardAssertE11` · 12 条）

目录布局（全在 `%TEMP%` 下，跑完全删）：
- `wf_e11_root_<guid>/WarpforgeReplays/` —— **假的「玩家目录」**，放两份 `.json` 哨兵（`s1`/`s2`）；
  用 `ReplayStore.PlayerRootForTest` 指过去 ⇒ 本断言**永远碰不到真的 `persistentDataPath`**。
- `wf_e11_tmp_<guid>/` —— 当 `OverrideDir` 用。
- `wf_e11_empty_<guid>/` —— 对照用的空目录。

| 名字 | 判别式 | 干什么 / 灭自证 |
|---|---|---|
| **G0** | `ReplayStore.Dir == playerDir` | 前提：`OverrideDir` 空时 `Dir` 落到「玩家目录」（否则后面几条测的不是那条路） |
| **G1 ★** | `File.Exists(s1) && File.Exists(s2)` | `OverrideDir = null` 下调 `ResetForTest()` ⇒ 两份哨兵**都在**。🧨 **把硬挡删掉 ⇒ 红**（且被删的是这两份假哨兵，不是真录像） |
| **G1-b** | 目录里 `*.json` 个数 == 2 | 同一判据的另一种量法（不是只看两个已知路径） |
| **G1-c ★** | 捕获到 `LogError` 且含「拒绝清空」 | 出声（铁律「不许静默失败」）。硬挡被删 ⇒ 没有这条日志 ⇒ 红 |
| **G1-d** | **没有**任何含「自检清空」的 `Log` | 证明它是**删之前**就 `return`，不是「删完才报错」—— 挡住「先删再判断」那种假修复 |
| **G2**（前提） | `Dir == tmpDir` | 设了 `OverrideDir` ⇒ `Dir` 就是它 |
| **G2 ★** | `tmpDir` 里 `*.json` == 0 | 正常路径仍然会删（硬挡没误伤） |
| **G2-b ★** | `s1`/`s2` 仍在 | 删除范围**只有 `Dir`**，不多删一处 |
| **G2-c ★** | 「自检清空」日志条数 == 2 | B3：**每删一份都出声**，一条不少（删 2 份就必须有 2 行） |
| **G2-d** | 没有「拒绝清空」 | 对照：G1-c 不是「反正每次都会报」的假象 |
| **G3 / G3-b** | 空临时目录 ⇒ 不报「拒绝」+ 哨兵仍在 | 对照：硬挡判据是「`OverrideDir` 空不空」，不是「目录里有没有东西」 |

**收尾顺序（本断言自己也守纪律）**：`finally` 里先 `OverrideDir = tmpDir` → `ResetForTest()` →
再还原 `OverrideDir` / `PlayerRootForTest`（`⛔ 顺序反了 = 删真录像`，同 `NetSelfTest.cs:925-929`），
最后递归删三个临时目录。

## 七、顺手发现（**都不是本批范围，没改**）

1. 🔴 `BattleLogData.ResetForTest()`（`Shell/BattleLogData.cs:311`）里的 `LoadFromDisk()` **绕过了 `StoreOn` 门**
   （那道门只管写，`LoadFromDisk` 是无条件读）⇒ **没设 `OverrideDir` 时它会读玩家的真对战记录**。
   E13 这条已经修好（现在「还在临时目录上」才读）；但 `Editor/MainMenuScene.cs` 那 6 处调用
   （`:7122` / `:7166` / `:7363` / `:14414` / `:14549` / `:14749`）有没有同样的问题，**我没核**（文件不在白名单）。
   建议：给 `ResetForTest` 加一句 `if (!string.IsNullOrEmpty(OverrideDir)) LoadFromDisk();` —— 但会动到
   MainMenuScene 的既有预期，**留给主对话判**。
2. ⚠️ `Editor/BattleScene.cs:462` 把 `ReplayStore.OverrideDir` 设成 `d:/4/_tmp_view/replays_selftest` 后
   **从不还原**。现在无害（BattleScene 是独立批处理进程），但若哪天在一个进程里串跑多个宿主就会「串味」
   —— 那时 `ResetForTest` 的硬挡反而会拦住（因为 `OverrideDir` 非空 ⇒ 会把临时目录当成合法目标）。
3. `ReplayStore.TrimToLast`（`ReplayStore.cs:618-634`）删真录像只有一行 `Debug.Log`、**没有回收站/备份**。
   那是产品行为（50 局上限），不是缺陷；但和 B1 同族 —— 目前全仓**删用户数据的地方一律不可恢复**。
4. `RE1` 的 B3 本来只是一条「加日志」，本批已并入 B2 一起做完（`ResetForTest` 每删一份打一行）。
