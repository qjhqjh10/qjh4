### 1·3 卡的缩放：**原版公式读的是高度，不是宽度**（这条是新的机器码判据）

- prefab：`CollectionCard` MB `40971030049256792` —— `initialCardScale = **150**` · `initialHeight = **512**`
  · `cardUI` = `Content/CardUI`（其子 `2DCard` = **2.0927 × 3.3313** 卡单位，出厂 `CardUI.localScale = 150`）。
- 反汇编 **`CollectionCard__OnRectTransformDimensionsChange` @ VA `0x1806D9980`**（`工具/disasm_va.py` 现跑）：
  ```
  1806D99C3  call   0x1830169c0          ; RectTransform.get_sizeDelta(this)  → Vector2 走 rax（x 低 4B / y 高 4B）
  1806D99C8  mov    rcx, [rbx+0x48]      ; cardUI
  1806D99CC  mov    [rsp+0x70], rax      ; ← x 落在 +0x70、y 落在 +0x74
  1806D99D1  movss  xmm6, [rsp+0x74]     ; 🔴 取的是 **y（高度）**
  1806D99D7  mulss  xmm6, [rbx+0x70]     ; × initialCardScale（150）
  1806D99DC  divss  xmm6, [rbx+0x74]     ; ÷ initialHeight（512）
  ```
  ⇒ `cardUI.localScale = **sizeDelta.y × 150 / 512**`（三轴同值）。
  **自洽性**：出厂格高 512 时 `localScale = 150` = prefab 里写死的那个 150 ⇒ 这条式子就是「按高度等比缩放」。
  ⚠️ **`A2` 写的 `sizeDelta.x × 150/512` 是错的**（用 x 时出厂 350 会算成 102.5 ≠ prefab 的 150）。
- **量纲换算**：`112.5 px / 卡单位`（= 384 × 150/512）→ 我们的 `SetPose(scale)` 用的是**世界缩放**、
  1 卡单位 = **108 px** ⇒ 等价世界缩放 = **112.5 ÷ 108 = 1.0417**。

## 三、为什么卡缩放**不**按原版公式直译（三条硬理由）

1. **会重新造出用户报过的缺陷**：`1.0417` ⇒ 卡块高 `3.3313 × 108 × 1.0417 = **374.83**`，
   而「格高 − 张数条」只有 `384 − 38.272 = **345.728**` ⇒ **卡底压住张数条 29.1 px**。
   这正是 **用户 2026-10-18 报的「张数与卡牌重叠」**（`W11` 修的就是它，见 `CollectionWindow.cs` `CardsCardRect` 的 doc）。
2. **与用户自己的原版实拍不符**：`C:/Users/qjh36/Desktop/warpforge参考图/收藏—张牌的界面参考图（打开过滤器按钮后）.png`
   （1578×888）逐像素量（背景 `lum<45` 掩膜 + 逐行/逐列连通段）：
   - 列距（pitch）**194.5 px**、卡可见宽 **158.6 px** ⇒ **81.4%**
   - 行距 **285 px**、卡可见高 **236 px** ⇒ **82.8%**
   - 行距/列距 = **1.465** ⇒ 反证格是 **384/262.5 = 1.4629**
     （`A2` 的 225×364.5 = **1.62**、250×405 = **1.62** ⇒ 实拍直接排掉）
   - 卡底**明显在**红色 `x2` 张数条**上面**（中间还有一段纯背景色）⇒ 实拍里**没有重叠**
3. **高度那 9% 的差不在格子上**：原版**看得见**的最外圈是 `CardFrame`（2.2452 × 3.2572，比例 **0.689**），
   而 `CardView` 铺的是**卡本体** 2.0927 × 3.3313（比例 **0.628**，更瘦高）。
   ⇒ 「按宽对齐」时我们的可见高度必然高约 9%（90% vs 82.8%）。这一层在 `CardView`（⛔ E6 白名单外）。

⚠️ **仍然开着的问题**（给主对话，别当已结）：原版 prefab + 反编译这条链**自洽**（出厂 512 → 150），
但**与实拍对不上**。最可能是**本地快照与关服前最后一版不是同一份 prefab**（或 `initialCardScale` 被改过）。
本轮**没有**任何本机能验证这一点的物证 ⇒ 按铁律 4「实况 > 静态字段」保留现式，**并如实记在这里**。

## 六、顺手发现（只报不改）

1. 🔴 **`A2` §Q6 的格判据要就地订正**（铁律 5）：225×364.5 / spacing 20 / 卡占格 61.3% **是卡组列表的格**；
   正确 = **262.5 × 384 / (0,0) / 卡宽 ≈ 81.7%**。建议改 `资料/普查产出_1024c/A2_引擎战斗判据总表.md` §6·1/§6·5，
   保留更正痕迹。**（E6 不改别人的产出文件，故只在这里报。）**
2. 🟡 **`_segments` 是死值**（`_useFixedCellSize = 1` 时被 `ConfigureColumnNumber` 现算覆盖）——
   全仓凡是「读 `_segments` 当列数」的地方都要核一遍（本轮只核了卡池）。
3. 🟡 **我们「异画 / Styles 页」用的 262.5×384 可能抄错了页**：原版 `Collection Cosmetic` 那份 RSR 是
   **250 × 405 · mobile 1.2**（`StyleCellW/H` 现写 262.5×384，`CollectionWindow.cs:1968`）。
   异画页归谁要看它对应原版哪一页 —— **不在 E6 账上，建议立账给界面线**。
4. 🟢 `CardView` 的 quad 用**卡本体** 2.0927×3.3313，而原版**看得见**的外圈是 `CardFrame` 2.2452×3.2572
   （比例 0.628 vs 0.689）⇒ 同一个缩放档下我们永远比原版「瘦高」约 9%。这条是 §三·3 的根，属卡面线。
