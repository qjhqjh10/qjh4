## 一 · Q1 根特效该由哪台相机画（最高优先）

### 1·1 结论

1. **原版战斗场景只有两台相机**，且**没有正交相机**：
   - **主 / 战场相机**：`m_CullingMask.m_Bits = 1137` = 层 **0(Default) · 4(Water) · 5(UI) · 6(AfterTransparents) · 10(BoardElements)**，`orthographic: false`、`depth −1`、`clearFlags 2(SolidColor)`、fov 46.397。
   - **UI 相机**：`m_CullingMask.m_Bits = 32` = **只有层 5(UI)**，`depth 0`、`clearFlags 4(DepthOnly)`。
   ⇒ **layer 0 的根特效在原版里由【战场透视相机】画，是竞技场世界坐标**。
2. ⇒ **`A367` 的两个候选里「归战场相机」是对的**。原来那条「layer 0 ⇒ HUD 正交相机」的推导错在**把本工程自造的 HUD 正交相机当成了原版某台相机**——原版根本没有它。
3. 真正把 root prefab 分到两台相机的是 **prefab 根节点的原版层**，而不是「根还是子」：
   - 根层 ∈ **{0,4,6,10}** ⇒ 原版由**战场相机**画（我们 3D 档应搬到 `ArenaLayer=8`）；
   - 根层 = **5** ⇒ 原版由 **UI 相机**画（我们保持 0，由 HUD 相机画）。
   - 本地 prefab 根层实测（我们导入的 978 件）：**0 → 903 · 5 → 46 · 6 → 24 · 10 → 4 · 1 → 1**（导入保留了原版层，可直接当判据用）。
4. 因此：
   - **`CardFeel.SpawnDeathBody`（`:2635/:2638`）的坐标是对的**（竞技场 world），**错的是层**：`parent=null` ⇒ 停在 prefab 自带层 0 ⇒ 被我们的 HUD 正交相机画 ⇒ 位置/尺度全错。**不是**「比 `:5719` 更大的位置 bug」。
   - `BattleDriver` 里那条「根特效 + `DropTargetWorld(slot)`（HUD 平面点）」对**竞技场空间的事件**才是错的那一半；对**HUD/UI 事件**（抽卡、资源三件）是对的。

### 1·4 顺带发现（同族、同一刀能一并修）

**🔴 直接 `WarpforgeEffectPlayer.Play(parent!=null)` 的四处绕过了层钩子**：

- `CardView.cs:2315`（残骸体）· `CardFeel.cs:2869`（`PlayDeathFallbackFx`，parent=卡）· `BattleDriver.cs:2580`（相邻单位）· `BattleDriver.cs:21005`（Swarm 合并）。
- 钩子只装在 `CardEffects.Play` 上（`WarpforgeEffectHook.cs:32`），**直接调 `WarpforgeEffectPlayer.Play` 的调用点一个都不走它**。
- 后果：这些实例保留 **prefab 自带层**（残骸体=10、Swarm 件=0、多数相邻件=0）⇒ 在 3D 档被 HUD 相机画。**下一次 `SyncBoard` 的 `SetLayer` 会把它整棵改回 8**，所以是「建出来到下一次棋盘刷新之间」错；`SyncBoard` 只在引擎事件上跑 ⇒ 这段窗口可能持续数秒。
- **证据（顺序）**：`BattleDriver.cs:22434` `if (!flyingNow && use3DBoard) v.SetLayer(ArenaSlots.ArenaLayer)` **在** `:22489` `v.SetRemnantBody(true, remPrefab)` **之前**（同在 `SyncBoard`，函数起点 `:22281`）。

**建议落点（判据只此一处）**：把「层 = 父节点层」这条规则从 `WarpforgeEffectHook` **下沉进 `WarpforgeEffectPlayer.Play`**（`parent != null` 时 `SetLayerRec(fx, parent.layer)`，`:249-256` 那一段）。这样 4 个直接调用点 + 以后的任何新调用点一次覆盖；`CardEffects.Play` 那边只留转发。

### 1·5 还差什么

- 🔴 **`真Play待验清单` 的 `D36` / `A367` 的「必须真机才能判」今天可以销掉**：判据不再依赖运行时 —— **原版只有一台画 layer 0 的相机**（13 场逐场读 mask），且 UI 层恒为 5，层与相机的对应是静态确定的。剩下那半（「原版 layer 5 的 UI 特效在我们正交 HUD 下尺寸对不对」）才需要并排图。
- **「原版 layer 5 的 UI 特效，在我们正交 HUD 下尺寸对不对」没有实拍判据**。原版 UI 相机是透视 fov40、按 canvas 距离成像；我们的 HUD 是正交 108px/单位。对屏幕空间 UI 效果，两者只差一个常数缩放；**要真机并排一次**才知道差多少（`EffectCompare` 那类）。
- `FireEventAll` 里**非 play/trigger** 的事件（`Deploy`/`Draw`/`Heal`/资源三件）仍走「根特效 + `DropTargetWorld`」：其中哪些原版是「卡上锚点件」**没有逐类核**（`play`/`trigger` 已被 `W1` 的 `PlayPlacedPieces` 接走）。**探针方案**：在原版跳一场打出 `Heal`/`Draw`，dump 特效实例的 `transform.parent` 与 `gameObject.layer`（SceneJumpShot 的 dump 能读到 layer）。
