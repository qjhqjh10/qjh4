## 一、结论（一句话）

**根因 = `_art`（底层整幅插图）被套上了原版 `_Clamp_Range` 硬矩形**（`H1` 当天早些落的那条）。
硬矩形在 **贴图 UV** 上只留中央 `u ∈ (0.18, 0.82]`（64%），而战术/防御立绘是**整张 1024²** ⇒
板 1.7436 被削到 **±0.5579**，可卡框的画窗是 **±0.839…±0.872** ⇒ 左右各留 **≈0.28 卡单位**的黑带、
顶边也被压成一条直线。**这正是用户报的「插图不覆盖战术卡框上面空着的地方 + 有漏掉的地方」。**

**修法（已落）**：`CardView.ArtClampKindFor` 恒返回 **0**（`_art` 不套硬矩形；`_artFront` 那条路不变）。
修后离线逐框验过 **75 张 `*_strat*` 卡框**：覆盖画窗所需半宽最大值 **0.8718 = 立绘板半宽本身**
⇒ 板**刚好铺满每一张画窗**，一张都不漏。

## 七、没查清（如实记）

1. **`_Clamp_Range` 到底被什么门控**：C# 层没有任何按卡型的分支（`SetImage`/`ChangeState`/`DoChange` 都对卡型一视同仁），
   但原版实况里战术卡显然没被它削。可能是 shader 里由 `frameMask` / 材质态 / 关键字门控 —— **没有 shader 反汇编证据**，
   只查到 shader 有 `_Clamp_Range` 与 `Toggle(UNITY_UI_ALPHACLIP)` 两个属性名。**这条留待以后有反汇编手段时闭合。**
2. **原版战术卡立绘中心的 y**：模型 `−0.044 + 0.5 = 0.456`（Front 局部）；从原版详情窗大卡量得
   **≈0.57 ± 0.06**（三个 patch 反解 + 以卡框高标定）⇒ 差 **≈0.085 卡单位（2.5% 卡高）**。
   两种可能：详情窗那个 prefab 的 `CardImage` apos 与 `CardUI` 参考模板不同 / `tacticsOffsetPosition` 的作用空间不同。
   **没有改**（改了会牵动 `FrameMesh` 的 uv2 与所有 y01 常量）。⇒ 记账，另开一盘。
3. **防御卡与战术卡共用 `cardType = 20`** 这一点沿用 E9/H6 的现读结论（`cards_truth.json` 只有 0/10/20），本次未重核数据侧。

## 八、顺手发现（重要，请主对话决定是否立账）

1. 🔴 **整张卡面（框 / 文字 / 立绘）在卡体矩形里比原版低 0.08 卡单位（2.4% 卡高）**
   —— 父链 `2DCard → Front(**apos.y = +0.0800**) → CardImage(−0.044) / CardFrame(−0.030) / 文字族`。
   我们的 `FRAME_UNIT_Y = −0.03`、`ArtUnitY = −0.044`、以及**全部文字 y01** 用的都是 **Front 局部**坐标，
   **谁都没加那个 +0.08**（逐条验算过：`ArmyTextUnit` 的 y01 0.6394 反解 = −0.464，而含 Front 应为 −0.3845）。
   ⇒ 内部自洽（层与层之间没问题），但**整张脸相对卡体矩形偏低 0.08**。修法是**一处**（给 2D 面根节点 +0.08），
   但它会移动每一层 ⇒ 需要单独一盘 + 全场景复核。**本次未动。**
2. `ArtClampKindFor` 现在有未用形参（`d` / `bigState`）—— 保留签名是为了「档位只有一个出口」，避免重烘路径再分叉。
3. `CardBaseDemo` 的 `AssertArtClampForSample` 里 ①/③b 现在**同源**（都是「画窗边」）—— ③b 那条精确等墙仍然挡
   「板边/窗口算法/档位」三类回归，① 那条挡「覆盖不足」，两者措辞与判据不同，**不算自证**；若后续要更强判别力，
   建议 ① 换成「**画窗四角都被立绘盖住**」（取 4 个角的采样点，而不是只比 x 极值）。
