## 一 (A) 立绘中心 y：原版**分两族**

### 1·1 判据（一手：全库普查 91 个 bundle）

口径：`assets_full/*/GameObject/*.json` 里 `m_Name == "CardImage"` 的 GO → `m_Component` → `RectTransform_*.json`
的 **`m_AnchoredPosition.y`**（RT 的 `m_LocalPosition` 序列化恒 `(0,0,0)`，Unity 由 anchoredPosition 反推 ⇒ 取它）。

| 族 | 节点路径（根 → 叶） | apos.y | 实例数 |
|---|---|---|---|
| **战斗卡 prefab** | `CardPrefab / 2DCard / Front / CardImage`（`bundle_battleprefabs_vfxandmisc_assets_all/RectTransform/RectTransform_2364194910465924032.json`） | **−0.06499999761581421** | **1** |
| **菜单 / HUD 卡 UI** | `… / CardUI( Reference) / 2DCard / Front / CardImage` | **−0.04399999976158142** | **151**（`bundle_menus_assets_all` 41 · 13 个 arena 场景各 8 = 104 · `mainmenuwarpforge` 5 · `staticgeneralassets` 2 …） |
| （无关） | `… / Mask / CardImage`（头像气泡，176×176 @ y −5） | −5.0 | 39 |

两族的**尺寸完全相同**（2.7484²）、父链前三层逐位相同（`Front` apos y = **+0.08**、`2DCard` 0）。
差额 **0.021 卡单位** = 0.63% 卡高（手牌 263 px 上 ≈ **1.7 px**；详情窗大卡 1076 px 上 ≈ **6.8 px**）。

⚠️ **13 个 arena 场景里那 8 个 `2DCard/Front/CardImage` 全是 −0.044**（= `CardUI` 族，挂在
`BattlePrefab/BattleHud/…/Card Display Window`、`CemeteryGroup`、`Card Picker`、`Generic Multi Card Display Combat` 下）
—— **它们不是手牌/场上卡**；战场卡是运行时从 `CardPrefab` 实例化的 ⇒ **这一族只能从 prefab 读**。

**事实**：−0.044 不是我们抄错，是**菜单/HUD 那 151 个实例的原版值**；我们（`CardView` 一个类画所有卡面）
把它用到了**所有**卡上 ⇒ **只有手牌/场上那一张（`CardFace.Hand` / `CardFace.Board`）少 0.021**。
⇒ 正确处理是**分族**，不是把常量翻成 −0.065（那会让放大窗 / 卡池 / 收藏 / 详情窗全部偏 0.021）。

## 三 (C) `RenderPixelsIsolated` 没关 UGUI `CanvasRenderer` —— 真缺陷

### 3·1 缺陷

旧实现：`Object.FindObjectsByType<Renderer>()` → `forceRenderingOff = true`。
`MeshRenderer` / `SpriteRenderer` / `ParticleSystemRenderer` **都**是 `Renderer`，但 UGUI 的
`Image` / `Text` / `TextMeshProUGUI` / `RawImage` 画出来的东西是 **`CanvasRenderer`**
（`UnityEngine.Component` 的子类，**不在 `Renderer` 的继承树上**）⇒ **一条都没关掉**。
落在探针相机前面的 `ScreenSpaceCamera` / `WorldSpace` Canvas 会混进像素 A/B 的差集，
而 `RenderPixelsIsolated` 存在的全部意义就是「只让被测卡进画面」。

### 3·2 修法（`Editor/CardFaceProbe.cs:1975` 起）

* 额外 `FindObjectsByType<CanvasRenderer>(FindObjectsInactive.Include, …)`；
* 子树在外的一律 `SetAlpha(0f)` ＋ `cull = true`（**两条一起上** —— 只做一条时不同 Canvas 模式下行为不一致）；
* `finally` 里 `cull = false` ＋ 把 `GetAlpha()` **先存后还原**；
* 本来就 `cull == true` 的不碰（还原时会误开）；
* 新增两个只读计数（`LastIsolatedCulledRenderers` / `LastIsolatedCulledCanvasRenderers`）与两个测试入口
  （`RenderPixelsIsolatedForTest` / `RenderPixelsForTest`）—— ⛔ 断言里不另写一台相机（两把尺子迟早不一致）。

### 3·3 断言（C 组）

| 编号 | 断什么 | 灭自证 |
|---|---|---|
| C1 | **不隔离**时挡在前面的红 quad 画得出来（前提） | 夹具前提 |
| C2 | **隔离**后中心像素 = `root` 的绿 | 退回旧实现 ⇒ 红 |
| C4 | `LastIsolatedCulledCanvasRenderers >= 1`（改之前**恒 0**） | 删掉 CanvasRenderer 那段 ⇒ 红 |
| C5 | 渲完 `cull` / `alpha` **原样还原** | 不还原 ⇒ 同一现场后续测的全错 |
| C6 | 像素证据：UGUI 那块蓝在隔离后**不在画面里** | 前提不成立时**大声说「判不了」**（⛔ 不静默当通过） |

## 四 没查清 / 顺手发现（供调度台分流）

1. 🔴 **`CardFace.Full` 里混着两种族**（本轮的已知边界）：`Full` 一档我们映射成「菜单/HUD 卡 UI（−0.044）」，
   但 **battle 侧有几处 `CardFace.Full` 建的卡其实可能属于战斗卡 prefab** ——
   `BattleDriver._revealCard`（`OffensiveReveal`）· 选牌/环境牌那两块 `_choosePanel` · `CenterCard_*`。
   原版那几处到底走 `CardPrefab` 还是 `CardUI` **没查**（判据得逐个去 prefab/scene 找对应节点）。
   差 0.021 卡单位、放大窗尺度 ≈ 6.8 px ⇒ 值得复核。**先记账。**
2. ⚠️ **战术那颗 `RaceText` 的框宽也不一样**：`MinionOrWarlord` 90×21 / `Tactic` **155×19**。我们 `_race`
   一律用 `nameW` 当框宽 ⇒ 与原版两颗都不等。因为这一行字短、居中、不折行，**当前看不出差别**；
   但它是原版字段，按铁律 11 **要补**（判据齐全，改 `Fill` 的 `maxWidth` 一处即可）。
3. ⚠️ **「印不印」那条我们与原版 `CardTextsController` 不同源**：原版 state 3（战术 + 有描述）**不印**兵种行，
   而我们对 9 个具名系列一律印（判据来自 PnP 成品卡图，`SubtypeLine` 的 doc 有 70 张逐张核的记录）。
   两条判据**可能**在「战术卡既有长描述、subtype 又落在 9 类里」的卡上打架。**没查**这类卡有多少张。先记账。
4. ⚠️ **同一颗 `CardImage` 在 `CardUI` 族的父链上多一层**（`CardUI Reference` 2.5437×3.3686 / `CardUI` 150 scale…）
   —— 本轮的 `accY` 普查里我按「累加到 `Front`（含）」对齐，两族在 `Front` 之上**逐位相同**；
   但 `CardUI Reference` 那层 2.5437×3.3686 与 `2DCard` 2.0927×3.3313 **不等**，锚点都是 0.5 ⇒ 不影响 y。
   记下来备查（`CardView.CardUnitW` 取的是 `2DCard` 那组，未被 `CardUI Reference` 影响）。
5. ⚠️ **两处覆盖率探针只按「单位卡口径」建模**：`FrameArtCoverage` / `FrameArtBevelCoverage` 里
   `ArtMeshInFrame(art, artScale, frameTex, true)` 用的是默认 `typeScale=1 / typeDy=0`，
   **既不认卡型偏移（E9）也不认族差（本轮）**。它们量的是**形状覆盖率**（平移不影响百分比），
   所以**当前读数不受影响**；但将来谁拿它量位置就会错。**先记账，不改。**
6. ✅ 顺手确认：`CardImageController__SetImage.c` 的 `localPosition` 是「**缓存的原位 + 卡型偏移**」
   （`this+0x80/0x88` 首次从 transform 读入，之后 `set_localPosition(base + tacticsOffset)`）⇒
   **prefab 的 −0.065 / −0.044 不会被运行时覆盖**，本轮拿 prefab 值当判据成立。
