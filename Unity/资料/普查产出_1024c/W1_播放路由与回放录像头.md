## 二 A1 · 回放录像头记的是「入口参数」不是「开局事实」

### 判据出处
- `RE1` §1.2 ①–⑩（逐跳，带 `BattleDriver.cs` 行号）。
- 原版：`BattleRecordData` **双方各存一份牌组**（`DUMP:77673` 段，`playerData +0x40` / `oppData +0x38`；映射 → `资料/普查产出_0927/回放_入口与数据链.md` §C·①）。

### 根因（读代码 + 用户那次 `Player.log` 实据）
`RecBegin(myDeck, foeDeck, myFaction, foeFaction, …)` 取的是 `Begin` 的**形参**；产品开局路
（`BeginFromDeckLibrary` → `Begin(seed:, myDeck:, foeDeck:)`，`BattleDriver.cs:3747`）**一个阵营都不传**
⇒ 形参恒 `null` ⇒ `JsonUtility` 写成 `""` ⇒ 回放 `Begin(myFaction:"", foeFaction:"")` 把 `_foeFaction` 覆盖成空串
（`"" != null` 那一支）⇒ 对手自动凑按**空阵营**筛卡池 ⇒ **0 张** ⇒ 第 0 条换牌就分叉。

### 改前 / 改后
| | |
|---|---|
| 改前 | `BattleDriver.cs:4559` `RecBegin(myDeck, foeDeck, **myFaction, foeFaction**, seed, …)` |
| 改后 | `BattleDriver.cs:4570` `RecBegin(myDeck, foeDeck, **_myFaction, _foeFaction**, seed, …)` ＋ 12 行判据注释 |

**为什么安全（写进代码注释了）**
- `Begin` 内 `:4147-4148` 先落形参、`:4440-4451` 再按督军 / 「去内战」解析 ⇒ 到 `RecBegin` 那一刻
  `_myFaction/_foeFaction` **就是座位 0 / 1 的最终阵营**。
- 客机的**视图侧交换**在 `Begin` **返回之后**才做（`BeginFromPendingCore` 里 `if (_me == 1) …`）⇒ 与 `MsgStart` 的绝对座位口径一致。
- 与 `Restart()`（`Begin(_myFaction, _foeFaction, …)`）**同一条写法** —— 不是新发明，是把两条路统一。

### 影响面
- 「对手牌由引擎自动凑」的**所有单机局**（排位 / 遭遇 / 练习默认档）。
- 旧录像（`hostFaction == ""`）**行为不变**（照样空）—— 它们本来就是坏档，如实保留。
- **附带修好**：`FactionOf(seat)` 给对手返回空阵营导致的卡背 / 描边 / 阵营色 / 默认环境卡取错（RE1 §1.1 那张表最后一行）。

## 六 R6 · 死亡触发的能力动画没有播放拍

### 判据出处
- `RawCardScript__OnMinionDeath.c:19/22/23` —— 死者自己那一支先 `0x50`（80）→ `0x51`（81）→ 再按死因发 `175/180/170`
  （我们引擎侧 `170/175/180` 三族已经在发：`EffectResolver.EmitDeathByAbilityTriggers` 等，2026-10-24 `G2`）。
- `TriggerAbilities` → `AbilityLogic.PlayAbility` → `PlayAnim`（`AbilityLogic__PlayAbility.c:273/1531/2465`）。

### 根因
生成器把 `ThisUnitDeath(80)` / `UnitDeathByAbility(180)` 的 `cardAnimations[]` 归到 **`death` 桶**
（`工具/gen_card_vfx_by_card.py` 的 `TRIGGER_EVENT`），而 `death` 桶的表现层只有两个消费者：
① `CardFeel.PickDeathFx` —— **D13 之后只认 `customDeathParticles`**（那一族解出来**没有** `CardAnim`）；
② `PlaySignal` —— `GenericVfxFor(Death)` 恒 `null` ⇒ 走 `evt == null` 那条 early-return。
⇒ 这一族**一条都不播**（7 行 / 6 卡：`AM34`(180) · `BL62` · `BL66` · `GOF3`×2 · `GOF83` · `SAU72`）。

### 改法（**与 AN1 建议的落点不同，如实记**）
AN1 R6 的修法是「引擎侧补 `EvtKind.Trigger` 发射口 + 表现层把它加进 `VfxMap` 白名单」——
**那两处（`RuleEngine/**`、`Core/VfxMap.cs`）都不在本批白名单**。⇒ 改用**表现层**落法：

- `BattleDriver.PlayDeathAbilityAnims(BattleEvent e)`：`EvtKind.Death` 那一拍，取该卡的 **`death` 桶**，
  用 **`ResolvedVfx.Anim` 是否为空**当判别式**只挑「能力动画」那一族**（= D13 用的同一条判据，⛔ 没另立第二条），
  再走 §五 的 `PlayPlacedPieces`（`perCardOnly: true`，避免掉进 `ByEvent` 的阵亡替代品兜底）。
- 调用点：`PlaySignal` 里 `PlayTraitParticles(e);` 之后、`evt == null` early-return **之前**
  （`GenericVfxFor(Death)` 恒 null，放后面就永远到不了 —— 与 `Retaliation` 那一段同一条纪律）。

**为什么这是「同一个拍」**：原版 `TriggerAbilities(80/180)` 是由「这个单位死了」这件事派发的；
我们的等价物 = `EvtKind.Death`（引擎在死亡那一刻发的表现层信号）。

### 与 D13 不冲突（并在断言里钉住）
- D13 管「哪一件**阵亡爆散体**」（`customDeathParticles` / 默认件）；
- R6 管「**能力动画**那一族」；
- 两者按 `ResolvedVfx.Anim` 是否为空**互斥**划分，同一行不会被两边各播一次。

### 断言
- `★ R6 前提`：`AM34` 的 `death` 桶里有能力动画行（且 `ResolveDeathParticle` 回 null）。
- `★★ R6：单位阵亡那一拍，它自己的 ThisUnitDeath(80) 能力动画真的播了`：喂一条 `EvtKind.Death` ⇒ `FiredCount("GuardSummon") > 0`。
  🧨 删掉 `if (e.Kind == EvtKind.Death) PlayDeathAbilityAnims(e);` ⇒ 红。
- `★ R6 与 D13 不冲突（判别式）`：`PickDeathFx` 对 `AM34` 仍取**默认件**（`Fx == DeathBodyFx`，≠ `GuardSummon`）。

   R6 的判别式复用了同一条口径（`ResolvedVfx.Anim` 是否为空），**没有**引入第二套。
4. `CardAnimClips.PlacementOf("RelentlessMarchSummon").n == "GreenSummonCircle"` ——
   **`animTimes[].a` 是 CardAnim 名、`n` 是 prefab 名**，断言里比 `FiredCount` 必须用 **prefab 名**。
   本批第一次写错过（写成 CardAnim 名），已就地改正 —— 后续写这类断言的人注意别踩。
