### 1·1 旧断言（原文，改前 `:852-855`）

```csharp
Check(x0 >= -hardHalfW - 1e-3f && x1 <= hardHalfW + 1e-3f,
```

### 1·2 为什么弱：它只挡「越出」，**完全不挡「收进来」**

它是一条**单边区间**（`x0 ≥ −a` 且 `x1 ≤ +a`）。只要网格比硬矩形**窄**，不管窄多少都绿。
下面这些改坏改前**全部绿**（x 极值都是我按 `CardView.ArtMeshInFrame` 的三条返回路径静态推的，
不是实测 —— 依据：`ArtWindowMesh` 的 `Mathf.Max/Min(..., bxL/bxR)`、矩形路的 `xL = Max(xL, win.xMin)`、
单 quad 路的 `xL = Max(xL, clampCard.x)`，三条都会先与 `clampCard` 取交集）：

| 改坏 | 生产档 x 极值 | 旧 ① | 新 ① |
|---|---|---|---|
| `ClampRangeSmall` 误用 BIG 的 `(0.75,0.89,0.25,0.1)` | **±0.4359** | 🟢 绿（⊆ 区间） | 🔴 红 |
| 硬矩形被收窄任意一档（例 u 取 0.20..0.80） | **±0.5231** | 🟢 绿 | 🔴 红 |
| 网格塌成零宽 / 只剩一根竖线 | **0** | 🟢 绿 | 🔴 红 |
| 只夹一侧、另一侧被开口/卡体截住 | 不越界 | 🟢 绿 | 🔴 红 |
| `_art` 的 `clampKind` 改回 0 | **±0.871792**（板边） | 🔴 红（旧断言唯一能抓的一类） | 🔴 红 |
| 板宽丢了 `cardScales 0.61`（E9 回退） | **±1.04635**（被卡体截住） | 🔴 红 | 🔴 红 |

⇒ **旧断言的判别力只覆盖最后一列的上半部分（往外走），往里走一律放过**，
而「收进来」恰恰是最常见的静默改坏（改错常量、少乘一个倍率、误用另一档窗口）。

### 1·3 新断言 + 期望值来源

改后（`CardBaseDemo.cs:896-904`）：

```csharp
Check(Mathf.Abs(x0 + hardHalfW) <= ArtClampEdgeTol
      && Mathf.Abs(x1 - hardHalfW) <= ArtClampEdgeTol, ...)
```

`ArtClampEdgeTol = 1e-3f`（新增常量，`:697`；≈ 0.3 px，见它的 doc）。

**期望值来源（⛔ 不是把实现再算一遍；本方法不读 `ClampRangeSmall` / `ArtBoard` / 生产网格的任何数）**：

1. 硬矩形 SMALL 的 x/z 分量 = 原版 `_Clamp_Range` 的 **0.82 / 0.18**（材质默认 `(0.82,1,0.18,0)`，
   判据见 `CardView.ClampRangeSmall` 的 doc）⇒ **半宽 0.32**（贴图 UV 口径）；
2. 立绘板宽 = 原版 `CardImage` 方框 **2.7484** × **我们的** `ArtCoverMargin` **1.04**
   × 原版 `CardScalesByCardType[20]` **0.61** = **1.743585** 卡单位（两张样卡的立绘都是 1024²，
   ⇒ u 线性映射到 x，`ArtClampUv01` 的 `spanU = 1`）；
3. ⇒ 硬矩形两端 x = **±0.32 × 2.7484 × 1.04 × 0.61 = ±0.557947**（= 形参 `hardHalfW`，由调用方 `:743` 传）。

⚠️ **1.04 是我们自己的边距**（`ArtCoverMargin`，不是原版字段），2.7484 与 0.61 是原版字面量 ——
这三个数在代码注释里逐条标了出处，将来谁改 1.04 必须同步改期望（注释已写「⛔ 别放宽容差」）。

**float 精度核对（离线，numpy float32，按实现的两条算路各算一遍）**：
`0.32×2.7484×1.04×0.61 = 0.55794716`；实现的 `clampCard` 两端 = `−0.55794716 / +0.5579472`
⇒ 差 **0.0 / 5.96e-8**，比 1e-3 小 4 个数量级 ⇒ 不在抖动带里。

**为什么「精确等边」这个期望成立（束缚必须是硬矩形，不能是别的东西）**：
两张样卡在 tier4 下的卡框开口 = astra `[−1.0463,+1.0463]` / sororitas `[−1.0403,+1.0463]`，
卡体收边 ±1.04635，立绘板边 ±0.871792 ⇒ **三条都宽于 ±0.557947** ⇒ 只有硬矩形截得住它。

### 1·4 灭自证：两条精确墙（内壁 + 外壁）

只断「新写法对」不够 —— 若实现与检测器走同一个口，把两边一起改回旧写法仍然会绿。所以：

- **内壁（①，新增精确值）**：生产网格 x 极值 = **±0.557947**（原版 SMALL 那一组常量）；
- **外壁（③b，`CardBaseDemo.cs:976-995` 新增）**：**关掉硬矩形**后 x 极值 = **±0.871792**
  （= `2.7484 × 1.04 × 0.61 ÷ 2` 的**字面量**，⛔ 不读 `ArtBoard`）。

两条墙的作用（逐条）：

1. **③b 让 ① 不是空验** —— 关档后能截住网格的只剩「立绘板 ∩ 卡体 ∩ 卡框开口」，板半宽 0.871792 < 卡体 1.04635
   ⇒ 极值**要么**是板边（开口够宽）、**要么**是开口边（开口比板窄，例：tier1 astra 开口右沿 **0.8395**）。
   实测极值 **== 板边** ⇒ **反证卡框开口比板宽** ⇒ ① 里「硬矩形是唯一束缚」的前提成立。
2. **两条都是精确值 ⇒ 「两边一起改」不可能同时满足**：任何让内壁/外壁同时移动的改动（板宽变、倍率变、
   档位互换）都会让其中至少一条离开边。举例：
   - 误用 BIG 档 ⇒ 内壁变 0.4359（①红），外壁不变（③b绿）⇒ 至少一条红；
   - 退回 E9 前（板 = 卡框 quad）⇒ 外壁变 1.04635（③b红），内壁 0.5579 也得跟着变才能绿，但期望是字面量 ⇒ ①红；
   - 只把 `DebugDisableArtClamp` 常开（硬矩形从来没接上）⇒ ①②③b 三条一起红。
3. **期望值全部是写死的原版字段组合**（0.32 / 0.82 / 0.18 / 2.7484 / 0.61）⇒
   「实现改错 + 期望跟着改」这条路要求改的人主动去改**带出处注释**的字面量，不会静默发生。

**改坏必红（可直接照做的验收动作）**：把 `CardView.ClampRangeSmall` 改成 `(0.75,1,0.25,0)` ⇒ ① 必红且 ③b 仍绿
（这就是旧断言骗过、新断言抓住的那个情形）；把 `DebugDisableArtClamp` 默认置 true ⇒ ① 与 ③b 同时红。
