## 一、结论（一句话）

那层「淡黑」= **左竖导航的投影 `Navigation Panel/Panel Shadow`**
（`Shell/MainMenuRuntime.cs:1000-1001`；贴图 `Smooth_background_lateral` × 纯黑 `m_Color (0,0,0,0.46667)`；
rect **(-762.5, 511.7) → (1166.2, 581.7)**，竖向 alpha 斜坡、底边最浓）。

**这个件、这个矩形、这个颜色、这张图 —— 原版逐位都有，我们抄得没错。**
错的是**层序**：它的渲染队列是 `QPanel = 2910`，而模式卡的**卡图**是 `QCardArt = 2905`
（`MainMenuRuntime.cs:240` / `:2662`）⇒ **影子画在了卡图之上**，在卡面上压出一条横贯的暗带。

⇒ 这是**我们的层序缺陷**，不是原版观感：用户自己的原版实拍 `主界面参考图.png` 同一位置**没有**这条影
（逐像素量过，见 §二·2）。修法只动队列，**不动** rect / 颜色 / 贴图（那些是原版值）。

**为什么正好是「冲突、经典两张」**：影子右沿 **x2 = 1166.2**
⇒ col0 小冲突（x 205..740）**全被盖**、col1 排位（x 760..1295）**被盖到 1166**（76%）、
col2 选秀（x 1315..1850）**一点不沾**（1315 > 1166.2）。
用户说的「经典」= col1 那张 —— 它的卡图就是 `Container_Image_Ranked`，**与「经典」模式卡是同一张图**
（`MainMenuRuntime.cs:2409-2410` vs `CollectionWindow.cs:4136`）。第三张（选秀）没被盖 ⇒ 只报两张。

## 三、根因

我们这套 UI **没有 uGUI 的 Canvas / 兄弟序**，分层完全靠 `ImageQuad.SetRenderQueue`
（`Shell/MainMenuRuntime.cs:235-239` 自己写明了这条口径）。主菜单的队列梯子是
`QBg 2900 → QCardArt 2905 → QPanel 2910 → QContent 2920 → QText 2921 → QOverlay 2930`。

`Panel Shadow` 挂在 `QPanel(2910)` 上是对的（它在导航那一组里要压住导航底板、要让分隔线压在它上面），
**但它有 1929 px 宽，横穿到 x=1166.2 —— 早就伸进模式卡区**；而模式卡的**卡图**偏偏排在它下面（2905）
⇒ 卡图被 45% 的黑按竖向斜坡压掉一截。

> 注：卡片其余三层（`TextDarkening` 暗带 2920 / 标题 2921 / 边框 2930）**本来就在影子之上**，
> 所以只有「图像」这一层脏 —— 这也解释了为什么暗带本身、边框、标题都看不出来被压。

## 四、修法（推荐 A，备选 B）

### A（推荐）把**模式卡图**抬到导航那一层之上

`Shell/MainMenuRuntime.cs:2662`：

```csharp
cardArtQ.SetRenderQueue(QCardArt);   // 2905 —— 低于 QPanel 2910 ⇒ 被 Panel Shadow 压
```

→ 新增一档并改用它：

```csharp
/// <summary>模式卡**卡图**的队列：必须 **高于 `QPanel`(2910)** —— 左栏 `Panel Shadow`
/// 是 1929×70、右沿到 1166.2，横穿卡区；低于它就等于给卡面蒙一层 45% 的黑。
/// ⚠️ 2911 已被 `QNavHighlight` 占用 ⇒ 取 2912（2912..2919 全空，最近的占用是 `QContent` 2920）。</summary>
const int QCardArtAboveNav = QPanel + 2;      // 2912
...
cardArtQ.SetRenderQueue(QCardArtAboveNav);
```

连带：
- `:240` 那行梯子注释补一句「`QCardArtAboveNav 2912`（> QPanel 2910）」，`QCardArt` 若无其它用处可删/留作历史（本文件只有 `:2662` 一处用它，`grep` 已核）。
- `:3067` 那条注释「夹在卡图（`QCardArt` 2905）与边框（2930）之间」同步订正为 2912。
- `:238-239` 的「每层各占一档」结论不变。

为什么不选「整卡抬到 2910 以上」：只有**卡图**低于 2910，暗带/标题/边框/印玺早就在上面，
动 5 处不如动 1 处；且 `QContent 2920` 必须留在卡图之上（暗带要压着卡图）—— 2912 正好在两者之间。

### B（备选）把影子降到「纯背景层」

`MainMenuRuntime.cs:1000` 的 `QPanel` → `QBg + 1`（2901）：
影子从此永远在任何内容之下（最保险），**代价**是它同时掉到导航底板 `Background`（也 2910）后面，
导航列内那 191 px 的那点阴影没了（原来那里因为**同队列**本来就是「谁盖谁不确定」，见 §六·1）。
**视觉差很小，但改动面更大（全屏那一条 1929 px 都会变）⇒ 所以推荐 A。**

### ⛔ 不要动的

rect / tint / 贴图 / 节点名 / `Panel Shadow` 自身的队列 —— **全是原版值**，
并且 `Editor/MainMenuScene.cs:801 / :14761` 两条断言钉着它们。

## 五、验收

### 断言（加在 `Editor/MainMenuScene.cs` 的 `CheckCard(...)`，`:18842` 起）

```csharp
// 卡图必须画在左栏投影之上（那条影 1929×70、右沿 1166.2，横穿卡区）
var shadowN = FindChild(menu.Find("Navigation Panel"), "Panel Shadow");
var shadowQ = shadowN != null ? shadowN.GetComponentInChildren<ImageQuad>() : null;
CheckTrue(shadowQ == null || q.RenderQueue > shadowQ.RenderQueue,
          $"{what} 卡图的渲染队列 ({q.RenderQueue}) **高于** 左栏 `Panel Shadow` ({shadowQ.RenderQueue})"
        + " —— 低了就是一条横贯卡面的淡黑带（判据 → D1_主界面模式卡淡黑层.md）");
```

- 结构上不可能「两边一起改绿」：它比的是**两个不同对象**的队列（不是拿我们自己的常量自证）。
- 顺手可以再断一条**影子自身不变**：`shadowQ.RenderQueue == MainMenuRuntime.QPanel`（这条钉住「别靠降影子来解决」）。
- 覆盖五张卡（`CheckCard` 被 5 处调用 ⇒ 一条断言管 5 张），其中 col0/col1/col2 正好是「全盖 / 半盖 / 不盖」三档。

## 六、没查清 / 还差什么

1. 🔴 **原版为什么没把这条影画到卡上 —— 未闭合。**
   静态数据里 `MainMenu` 的孩子序是 `MainMenu(含 Background / Safe area All→GameModes)` → `Safe area Only Horizontal`
   （RT 1114 的 `m_Children` 逐项实读），按 uGUI「后面的兄弟画在上面」本该**压住卡**，可原版实拍里没有影。
   排除过的：这条路径上**没有** `Canvas` / `SortingGroup` / `Mask` / `RectMask2D` / `CanvasGroup`
   （`Navigation Panel` = RT + `NavigationPanelController` 一个脚本；`Safe area Only Horizontal` = RT + `CanvasRenderer`；
   场景包 9 个 Canvas 全不在 `GameModes` 子树里；`menus` 包 63 个 Canvas 里也没有模式卡 prefab 那几棵）。
   剩下的候选：① 运行时某处 `SetSiblingIndex` 重新排过；② 帧里的导航面板状态与静态假设不同
   （`NavigationPanelController.Awake` 会把面板 `SetActive(false)` 并记 `hiddenPosition`，`Toggle(true)` 才滑回来）；
   ③ 我们读到的这份 build 与视频那一版不同。
   **不影响修法**：修法目标是「与原版实拍一致」，而实拍已被逐像素量过。
2. 原版这条影在**卡片以外**（导航与卡之间的背景、卡片右方 x 1166..1920）到底看不看得见 —— 那几处在实拍里要么太暗、要么被字幕压住，**没能隔离出来**。
   修法 A 不动影子的可见范围（只抬卡图），所以这一条不影响验收。
3. 用的实拍只有一帧（`主界面参考图.png`）。若后续拿到第二帧（不同滚动位置），可再核一次 §二·2 的结论。
