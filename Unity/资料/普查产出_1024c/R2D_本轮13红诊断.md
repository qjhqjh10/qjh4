## 四、CardBase · 卡面外壁（2 条）

### 12 · `[CardBase] ③b 战术卡 Armoured Squadron（AM52）`
### 13 · `[CardBase] ③b 防御卡 Sacred Altar（SOR59）`

两条**同一个根因**，合写。

- **分类**：**α**（③b 的前提「立绘板比卡框画窗窄 ⇒ 极值是板边」对这两张样卡**不成立**）· 次要：**δ**（选样）
- **实得 vs 期望**：
  | 条 | 实得 `[o0, o1]` | 期望 |
  |---|---|---|
  | AM52 | **[-0.8395, +0.8395]** | [-0.8717925, +0.8717925] |
  | SOR59 | **[-0.8461, +0.8494]** | [-0.8717925, +0.8717925] |
  容差 `ArtClampEdgeTol = 1e-3`（`CardBaseDemo.cs:697`）；板半宽字面量 `0.5*2.7484*1.04*0.61`（`:989`）。
- **根因（这条可以下死结论，不依赖反推）**：
  1. **SOR59 的两端不对称**（−0.8461 / +0.8494）。板边、卡体收边、硬矩形**全是左右对称**的常量
     ⇒ **能把两端夹成不对称的只可能是「卡框的画窗 / 开口」这类逐帧几何**。
     这就直接否掉了 ③b 的前提句「板比硬矩形宽 ⇒ 极值 = 板边」。
  2. `③` 那条（越出量 ≥ 0.02）**过了**，实测「最大越出 **0.2815**（AM52）/ **0.2914**（SOR59）」
     = `0.8395 − 0.557947` / `0.8494 − 0.557947` ⇒ 进一步坐实「关掉硬矩形后」的束缚是**开口**，不是板。
  3. 这两个数**正好等于 astra/sororitas 的 `_strat` 卡框开口边**：
     · `0.83948` 就是仓库里已有的常量 `Editor/CardFaceProbe.cs:1255` `const float WinHalfX = 0.83949f`，
       它的注释逐字写着「极值顶点落在**卡框画窗边**（贴图列 257/767 = WinHalfX）而不是硬矩形边」
       —— **同一个现象、同一类卡框，F4 那条早就把它写成「三明治判据（下界 = 画窗边）」了**；
     · 我离线按 `CardView.FramePxXEdge`（`Core/CardView.cs:9411-9416`，`FrameSpriteRectX/W = 171/682`、
       `FrameUnitW = 2.2452`）把 `Resources/Art/cards/` 那批 `_strat` 框的开口端点算了一遍，
       `frame_sororitas_strat_tier2` 的开口 = **[−0.8461, +0.8494]**（与实测**四位小数全等**），
       `frame_astramilitarum_strat_tier1` = [−0.8362, +0.8395]（右端与实测吻合，左端差 1 px）。
       ⇒ **实测值 = 卡框开口，不是立绘板**。
  4. ⚠️ **还有一个「档位没钉住」的疑点必须点出来**：`CardBaseDemo.cs:757` 明明写着
     `CardView.DebugFrameTier = TacticArtClampProbeTier`（= 4，`:690`），三条断言文案也都印「卡框钉 tier4」，
     而 H4 的离线表（`CardBaseDemo.cs:723-727` 的注释）对 **tier4** 的读数是 **astra `[−1.0463, +1.0463]`**
     （两侧都**越出板边** 0.8718）。**实测不是那个数** ⇒ 要么 `DebugFrameTier` 没进到 `CardView.Build`
     （`Core/CardView.cs:3857-3860` 是唯一的读点），要么 `CardArt.Frame(..., tier:4)` 退回到了 lower tier
     （`Core/CardArt.cs:78-86` 的逐级退回）。
     **这一条我在只读环境里定不了**（需要在 `AssertArtClampForSample` 里补一行探针，见下「还差什么」），
     **但它不影响 ③b 的结论**：无论 tier 几，实测值都落在**开口**上、不是板上。
- **修法**（分两步，第 1 步必做，第 2 步定因）：
  1. **③b 的期望值按「这张样本实际的画窗」写，或者把 ③b 改成两分支** —— 按本文件自己的规矩
     （`CardBaseDemo.cs:904` 与 `:876-879` 两次逐字写着「换到『开口比硬矩形窄』的样本时两端由开口决定 ⇒
     **改期望值**，⛔ 别放宽容差」），推荐**两分支 + 逐样本字面量**：
     ```csharp
     // ③b 外壁：板边 / 画窗边 取**更窄**的那一个（谁窄谁是束缚）
     //   AM52（AstraMilitarum · tactic · `frame_astramilitarum_strat_*`）画窗半宽 = 0.83949
     //        —— 同一常量已在 Editor/CardFaceProbe.cs:1255 记过（贴图列 257/767）
     //   SOR59（Sororitas · defence · `frame_sororitas_strat_*`）画窗 = [-0.8461, +0.8494]
     //        —— 离线按 FramePxXEdge 量得，与 `frame_sororitas_strat_tier2` 逐位吻合
     float boardHalfW = 0.5f * 2.7484f * 1.04f * 0.61f;      // 0.8717925
     float expL = Mathf.Min(-boardHalfW, expectWinL);
     float expR = Mathf.Max( boardHalfW, expectWinR);

     其中 `expectWinL/R` 按**样本**给字面量，并**写清出处**（哪个框、哪两列像素）。⛔ **不许**把
     本次实测 `[-0.8395, 0.8395]` / `[-0.8461, 0.8494]` 直接抄成期望值 —— 那是自证
     （实现改了、期望跟着改，两条一起绿）。

     **落地前请用 `资料/普查产出_1024c` 的离线脚本口径再核一次左侧**，或以「±1 px 内的单侧精确值」为容差下限。
  2. **补一条「卡框档位真的钉住了」的断言**（这才是本轮真正的牙齿）—— 在 `AssertArtClampForSample`
     里 `CardView.Create` 之后加：

     Ok(vOn.FrameTexture != null && vOn.FrameTexture.name == "frame_astramilitarum_strat_tier4",
        "★ 前提：本样本渲在**指定的卡框档**上（`FrameTexture.name`；⛔ 退回 tier1 就无声无息）");
     ```

  3. **样本选择**（若要保留「板边当外壁」的原设计）：换一张**开口比板宽**的样本回来 ——
     `CardFaceProbe` 的 `Howling Banshee Exarch`（单位卡、`clipWindow:false`）不适用；
