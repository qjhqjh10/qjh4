## ① D6：换牌阶段压暗层盖住了换牌卡

### 结论

**病灶属实**（像素证据成立），但**病灶的位置和工单里推断的不一样**：

| 项 | 工单推断 | 实际（本轮现核） |
|---|---|---|
| 层序问题 | 压暗层与换牌面板同一档 Z | ✅ 成立（细节见下：**排序层**输赢，不是同档 Z） |
| alpha 只吃到 0.63–0.69 | 「染色路径让 `Image.color` 的 alpha 没生效」 | ❌ **不成立**：alpha **0.88 完全生效**（实测线性透射 0.1206 ⇒ alpha 0.879）。错因 = 拿 **sRGB 比值**当透射，本工程是 **Linear** |
| 改法 | 把压暗层往下挪到「场上卡与手牌之间」 | ❌ **不可行**：**战场几何也是队列 3000** ⇒ 压暗层只要 ≤2999，整个战场就不再被压暗 |

### 1. alpha 那条：不是 bug（实测证据）

同一相机、同一战场的两帧（`_tmp_view/shots/2026-10-22_第六十二会话/`）：

* `21_battle_start.png`（换牌期，压暗层开着）
* `24_hand_settled.png`（换牌结束，压暗层关着）

取背景废墟区（设计 px **(600,200)–(760,340)**，36,516 个像素），**按线性光**逐像素拟合
`linear(有压暗) / linear(无压暗)`：

```
线性透射：mean 0.1378 · median 0.1206   ⇒ 反推 alpha = 0.862 / 0.879
```

写死的值是 **0.88**，与反推值一致（差在 8bit 量化内）⇒ **染色路径没问题**。
`ProjectSettings.asset:50` = `m_ActiveColorSpace: 1`（**Linear**）⇒ 18% 的线性光透射在 sRGB 屏上
看起来就是「只剩 0.29–0.33」（而且**随底色变**，不是一个常数）。工单里「背景 220→82 应只剩 12%」
是按 sRGB 直接相乘算的 —— 那个算法在 Linear 工程里不成立。

### 2. 真病灶：换牌卡与压暗层**同队列**，输在排序层

* 换牌卡 = 世界空间 `MeshRenderer`（`CardView`）：手牌段队列 **2989..3000**、排序层 **`Default`**
  （`Hand/HandLayout.cs:265-287`）。
* 压暗层 = 画布件：队列 **3000** + 排序层 **`OverHand`**（`MulliganPanel` 的 `OverHand` 子画布）。
* Unity 透明排序：`renderQueue` → `sortingLayer` → `sortingOrder` → 距离。
  ⇒ 碰巧在 3000 那一档的卡与压暗层**同队列**，于是**排序层**判胜负 ⇒ 压暗层压在卡上面。

### 3. 为什么不能「把压暗层往下挪」（这条直接推翻工单的改法，务必记）

战场几何**整批也在队列 3000**：

* `WarpforgeArena1/Editor/ArenaBuilder.cs:5068` —— 「原版这批是 3000（`m_CustomRenderQueue = −1` ⇒ 用 shader tag）」，
  运行时是 `mat.renderQueue = (int)RenderQueue.Transparent`。
* 13 场 manifest 逐场数（`Unity/MyGame/Assets/WarpforgeArena1/arenas/*/*_manifest.json`）：

  | 场 | 3000 以上的件数（含 3000） |
  |---|---|
  | battlearena1 | 37@3000 · 2@3002 · 1@3003 · 1@3005 |
  | battlearena2 | 1@2995 · 87@3000 · … · 3@3005 |
  | leviathan | 1@2995 · 67@3000 |
  | tauvorla | 185@3000 |
  | blacklegion | 68@3000 · … · **5@3011（全 13 场最高）** |

  其中含 `Background_sky` / `BG_Building_1..6` / `Prop_*` / `Toxic Pool Glow` / 44 个粒子（leviathan）。
* ⇒ 压暗层只要 ≤2999，**天空与背景楼整块不再被压暗**（比现状更糟）。
* 反过来，压暗层抬到 ≥3001 会**盖住提示行与换牌钮**（它们也是画布件、队列 3000）。

**三条约束（战场暗 / 卡亮 / 提示行亮）只有一条路能同时满足：抬「卡」。**

**为什么抬卡不会伤到别的**：
`QMulliganCard = 3001` > 画布那一档 3000 ⇒ 卡画在压暗层之后（在它上面）；
< `CardFan.QCardBase = 3009` ⇒ 「点卡放大」那扇窗的卡（3009..3011）**照样压在换牌卡之上**（原版行为）。
换牌结束 `ClearCardButtons` 还回原队列，下一轮 `SyncHand → HandLayout.Place` 还会再按手牌槽位重算一次（正主）。

### 5. 新增断言（`Editor/BattleScene.cs` 换牌节，`D6`）

| # | 断什么 | 改坏法 |

## ② 收藏窗左栏那条竖向浅白带

### 结论

白带 = **`Content Area/Tab Buttons/Shadow`**（**原版里有这一件**，⛔ 不该删）。

* 原版 prefab（`工具/menu_dump.py bundle_menus_assets_all "Collection Menu Variant" --depth 5`）：

  ```
  Shadow | 167.2 158.6 214.8 1080.0 | 47.64×921.36 | Image |
  40k_main_tab_shadow 51×4 否 | Simple (0,0,0,0.475)
  ```

* 图 `40k_main_tab_shadow` 本体是 **纯白 + alpha 渐变**
  （`Resources/Art/ui_deck/40k_main_tab_shadow.png`：51×4，alpha 左 255 → 右 3，RGB 全 255）
  ⇒ 原版那句 `m_Color = (0,0,0,0.475)` 才是「黑阴影」的来源。
* **我们建它时没给 tint（= 白）** ⇒ 屏上就是一条**白带**。
  实测（`02_collection.png`，设计 px）：可见白带 **x≈167..232 · y≈368..1079**
  （x=168 处 RGB **(253,253,253)** 几乎纯白，往右衰减到 x=210 的 (99,75,76)；
  上端 368 = 选中页签红底 `QHighlight`(3006) 的下沿 —— 红底把阴影盖住了，这与原版树序一致）。
* 原版实拍同位置（`收藏—卡组的参考图.png`）是**暗**的：y=700 处 x=168 → **(42,0,3)**、x=240 → (55,0,0)
  ⇒ 黑阴影把 `55 → 42`（线性比 0.60 ≈ 1−0.475，与 tint 对得上）。

### 改法

| 文件 | 改了什么 |
|---|---|
| `Shell/CollectionWindow.cs` | 新增 `RebuildTabBarShadow(bar)`（`Build()` 里 `BuildShell` 之后调用一次）：**销毁基类那件、按原版重建** —— `Rect(bar, ArtBarShadow, 167.17, 167.17+47.64, **158.64**, 1080, "Shadow", QPanel, Color(0,0,0,0.475))`；顶边用新增常量 `TabBarTop = 158.64` |
| `Editor/CollectionScene.cs` | 新增一节 `左栏 Shadow（W62）` 四条断言：节点在 / 贴图 = `40k_main_tab_shadow` / **色 = (0,0,0,0.475)** / 矩形 = 167.17,158.64→214.81,1080 |

**为什么是「删了重建」而不是「改个色」**：基类那件连**矩形**都不对 —— 它从 `ContentT`(**70.94**) 起算，
而原版本窗的 `Tab Buttons` 是 **158.64..1080**（本窗 `BarPadTop=117.7` 的同一个来历）。只改色会在页头
那 88 px 上多压一条黑影。

## 没查清 / 需要下一轮确认

1. **背景亮度的验收阈值用哪把尺**：本代理按**线性光**写断言（0.20）。屏上 sRGB 的中灰底量出来是 **≈0.33**
   （alpha 0.8 时）。工单里的「≤0.25」只在 sRGB 口径下成立，而那时 alpha 得 ≥0.92（与原版 0.8 冲突）——
   请主对话在复拍时按**线性光**判，别按 sRGB 比值判。
2. **原版 `Shadow` 与页签的树序**：原版 `Shadow` 是 `Tab Buttons` 的**第 5 个孩子**（在四个按钮之后）
   ⇒ uGUI 画序上它**压在页签图标与红底之上**（左沿 47.64 px 那一段）。我们这侧是
   `QHighlight`(3006) > `QPanel`(3005) ⇒ **红底压在阴影之上**（与我们的现状一致，也与实拍不矛盾：
   选中页签左沿的暗度被红底自己的九宫软边盖住了，量不出来）。**没查到能分辨的判据**，如实记；
   真机复拍时若发现「选中页签左沿应有暗带」再定。
3. **D6 的「卡亮」只验到层序**：批处理没有画面，`D6⑤` 的亮度比是从层序**推**出来的，
   真值必须靠复拍确认（换牌卡区域最亮 >200）。
4. **换牌卡队列 3001 与战场 3002/3005/3011 那几件**：卡抬到 3001 后，少数战场件（arena1/2/blacklegion
   各 1–6 件）会画在换牌卡**之前**（= 在卡下面）。它们本来就在卡后面（距离更远），实际无差异；如实记。
