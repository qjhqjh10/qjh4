## 1. 场上的卡是真 3D 网格

判据 = 原版 `CardPrefab.prefab`（AssetRipper 导出）+ 网格 `.obj` 实读。

```
CardPrefab
└ Board Elements (layer 10)
  └ 3DBody        SortingGroup + flying 控制器 + Animation(禁用)
    ├ Card 3D          MeshFilter+MeshRenderer · mesh `Card 3D WH40k` · 材质 `Card 3d Lvl1`
    │                   localScale 0.88586 · 绕 Y 180° · BoxCollider 1.827×3.01×0.5 @(0.0135,1.55,-0.016)
    │  └ Card blob shadow   SpriteRenderer（sprite `Card blob shadow`）· 绕 X −90° · scale 2.0567
    ├ MinionLight      SpriteRenderer（sprite `Card board frame SDF` 79×107@100ppu）
    │                   pos(−0.001,1.326,0) · scale(3.1555,3.0920,2.99) · sortingOrder −1
    ├ TraitIcons（8 个容器）· Base Attack Counters · Base Health Counters · Armour Container
    ├ DamageCounter(0,1.708,0) → DamageIcon(0.094,−0.104,−0.05) + DamageText · SwarmIcon · Minion Death Icon
    └ CanActParticles   ParticleSystem(Mesh 模式, 内置 Quad, `Circle_Hoop Additive`, 绿)
       └ RotatingRing   ParticleSystem(Mesh, `FxObject_cylinder_short`, `Sparks UI Additive Scroll`)
     EffectAnchor · ToBoardFX
```

- 网格 `Card 3D WH40k.obj`：**881 顶点 · x ±1.045 · y 0.012…2.973 · z ±0.942**（728/881 顶点在 z±0.15 平面附近，其余是底部卷边/计数器面板的实体几何）⇒ **是立体的卡**，不是 billboard。
- 主卡体 = MeshRenderer（matcap 假光照 Unlit，立绘吃 UV1）；光晕/软阴影/徽标 = SpriteRenderer；底盘光环 = ParticleSystem(Mesh)。
- 我们一致：`CardView.BuildBody3D`（`Core/CardView.cs:5024+`，`Body3DScale=0.88586`，yaw 180°），残骸体 `SetRemnantBody`。
- ⚠️ 偏离：原版 `Card 3d Lvl1` 材质**不透明**（`_Surface 0` · `m_CustomRenderQueue −1` ⇒ Geometry · `_ZWrite 1` · `_Cull 2`）；我们的 `Shaders/Card3D.shader:41-44` 是 **Transparent 队列** + ZWrite On + Cull Back。原版 `Card 3D` 的 `CastShadows/ReceiveShadows = 1/1`，我们 `CardView.cs:5059-5060` 是 **0/0**。

## 2. 底座绿光 = `CanActParticles` + `RotatingRing`

**原版逐值**：
- `CanActParticles`：`3DBody` 直接子件，localPos (0,0.03017,0.00605)、绕 X 90°（平躺）、scale **1.735563**；粒子 = 内置 `Quad` + `Circle_Hoop`；`startColor.maxColor=(0.30104,0.94510,0.09020, a0.22745)`（绿）、`startSize 1.9`、`maxParticles 2`、`simulationSpeed 0.5`、`looping=false` + `ringBufferMode=2(Loop) range(0.1,0.9)`。
- 子件 `RotatingRing`：localPos(0,0,−0.04743)、scale(0.59292,0.59292,0.05929)；网格 `FxObject_cylinder_short`（半径 0.6552、长 1.011、**360° 完整筒面**，36 面）；材质 `Sparks UI Additive Scroll`，shader **`Everguild/FX/Halo UV scroll`**，贴图 `Spark UI`。
- 「会转」靠 shader 的 UV 滚动：`Spark UI` 的 alpha 实测只有**一处彗星状亮块，占 U 约 0…0.2**（其余全透明）⇒ 看到的是一段亮弧在环上绕圈。

**根因（按可信度）**：
1. 🔴 **我们没设滚动速度** —— `CardView.BuildFxMaterial`（`:4814-4859`）没写 shader 的两个哈希名属性：
   - `Vector4_62056e41ff4042358d02be808b0352f9` =「UV Scale (XY) Speed (ZW)」，**原版材质实读 (1,1,0.63,0)**，shader 默认 (1,1,**0.2**,0) ⇒ 我们慢 **3.15 倍**。
   - `Vector3_65160a41016e4bb0ad3f5043d258b214` =「Border Fade(X) Clamp(YZ)」，原版 (1,0,1,0) = 默认值。
   - 同族正确写法可照抄：`Battle/TargetReticle.cs:403-405`。
2. 🔴 **贴图 wrap 是 Clamp，原版是 Repeat** —— 我们的 `Resources/Art/card3d/CanAct_SparkUI.png.meta:40-41` 是 `wrapU/V: 1`；原版 Texture2D `Spark UI`（pathID 2237300359485136697，128²）**`m_WrapU=0 / m_WrapV=0`（Repeat）**。UV 一滚出 0…1 就被夹住 ⇒ 亮弧**绕不过接缝，走到一头就没了**（「每次到一半就没」最直观的来源）。
   ⚠️ 未证前提：shader HLSL 被剥，不知道它是否自己对 UV 取 `frac`；若取 frac，第 2 条只是「与原版不符」，第 1 条无论如何要修。
3. **几何事实（原版也如此）**：环半径 ≈ 0.243 世界单位，卡体半宽 ≈ 0.333 ⇒ 整圈落在**不透明卡体后面**，只有**前半圈**露得出来；亮弧转到卡后就「没了」，下一圈再从另一边出来。
4. 若现象是**整圈彻底消失且不再回来**：查 `looping=false` + `ringBufferMode=Loop` 是否仍维持粒子；原版参数相同，**未验**（`真Play待验清单 D6`）。

## 4. 血痕位置错 = 我们自己的偏移量，与卡位无关

- 血痕真身 = `3DBody/DamageCounter/DamageIcon`（SpriteRenderer，sprite `Card Damage` 256²）；原版 `DamageCounter` localPos **(0,1.708,0)**，`DamageIcon` 再偏 (0.094,−0.104,−0.05)。伤害白字 `DamageText` 也在同一节点下。
- 换算：卡根在 3DBody 空间 y = `Height/2` = 1.66565 ⇒ 原版血痕在**卡根局部 y = +0.042**（≈ 卡中间）。
- 我们的基准点 `BoardLayout.DropTargetWorld` 投的是 `ArenaSlots.CardCenter`（= 3D 卡身中点，卡根局部 **−0.34335**）⇒ 正确偏移 = **0.3857 卡单位 = 0.234 我们世界单位**。
- 实际：`BattleDriver.cs:17632` `PopOffset = (0, CardFeel.ToOurs(0.35), −0.4)` = **0.590** ⇒ **比原版高 2.52 倍**，落在卡根局部 **+0.63**（卡身高度的 ~80% 处）。
- 血痕是飘字节点的子件（`PopNumber.cs:304`），所以跟着飘字一起被顶到卡上部。⇒ 用户看到的就是这一条。白色伤害数字也偏高同样的 0.59，一起修。
