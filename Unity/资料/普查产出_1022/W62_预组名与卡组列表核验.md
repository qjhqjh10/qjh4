## A 预组名空白

- **判定：判不了（截图不复现"空白"）＋ 背后有一处【真缺陷】（官方名 join 漏 8 副）；其中 2 副"空白"是【原版如此】。**

- **证据 1（截图）**：`_tmp_view/shots/2026-10-22_第六十二会话/17_practice.png` 第 2 行第 1 格
  实测**有名字**（"撕裂火焰"，放大裁图为证）；第 1 行 6 格、第 2 行 6 格**全部有名字**，
  只有**第 3 行被视口裁掉**（名条在视口外，滚动即见）。⇒ 被指的那一格不是空白。
- **证据 2（日志那行是真的）**：官方表**有**这条键 ——
  `Unity/数据/游戏数据/官方本地化_en+zh-CN.json` 的 `terms["PrebuiltDecks/SpaceWolvesDeck5"]`
  = `["Lupine Companions", "狼性伙伴"]`；`PrebuiltDecks/*` 共 **215 条**（`PrebuiltDecks/SpaceWolves*` 7 条）。
  而运行时取的是 `Resources/official_names.json`（`Shell/PrebuiltDecks.cs:99` `Loc.BulkOr`），
  该产物里 `PrebuiltDecks/*` 只有 **95 条**、**没有** `SpaceWolvesDeck5` ⇒ 于是打了
  `Core/Loc.cs:3175` 那条「数据面词条表里没有这条键」。
- **证据 3（漏的原因）**：`工具/_loc_official/gen_official_names.py:137-174` 的 `resolve_prebuilt_decks`
  是**按英文名** join（`:151` `byen[v[0]]`、`:163` `byen.get(d.get("name"))`）。
  我们的 `name` 列 = 原版 SO 的 `deckName`（`prebuilt_decks.json`；生成器 `gen_prebuilt_decks.py:564`
  直接抄 `decklists.json` 的 `name`），与官方**值**对不上就漏。
  **103 副里漏 8 副**（逐条已算）：
  `AeldariDeck4` · `DA_SK_4` · `DarkAngelsDeck7` · `Deck_UM_Titus` · `ORK_SK_6` · `SpaceWolvesDeck1` ·
  `SpaceWolvesDeck3` · `SpaceWolvesDeck5`。
  其中 **6 副的官方键就在"同形"位置**（`PrebuiltDecks/<deckId>` 直接命中，例
  `PrebuiltDecks/AeldariDeck4`=`死者之主`、`Deck_UM_Titus`=`副将提图斯`、`SpaceWolvesDeck5`=`狼性伙伴`）；
  **只有 `DA_SK_4` / `DarkAngelsDeck7` 官方表里彻底没有**（这两个 SO 的 `deckName` 都是
  "The Vengeful Brethren"，`isPracticeDeck=1`，见 `bundle_prebuiltdecks_assets_all/MonoBehaviour/DA_SK_4.json`）。
- **证据 4（显示永不空白）**：`Shell/PrebuiltDecks.cs:88-110` 的 `DisplayName` = 官方词条 → `nameZh`
  → `name`；产物里 **103/103 的 `name` 与 `nameZh` 都非空**（现读）。⇒ 我们这边**不会因缺键变空白**。
- **原版口径（第一权威 = 反编译 + 字面量）**：
  · `PrebuiltDeck.LocalizedName` 读的是 **`+0x48`**（`decomp_full/PrebuiltDeck__get_LocalizedName.c:15`
    `*(undefined8 *)(param_1 + 0x48)`），而 `dump.cs:22915-22916` 写明 `deckName`=`0x40`、**`deckId`=`0x48`**
    ⇒ 原版键 = **`"PrebuiltDecks/" + deckId`**（前缀字面量 = `il2cpp_out/stringliteral.json` 的
    `{"value":"PrebuiltDecks/","address":"0x4292C50"}`）。
  · 缺键时 I2 **不兜底**：`I2.Loc.LocalizationManager__GetTranslation` → `TryGetTranslation` 返回 0 且
    输出串保持 `null`（`TryGetTranslation.c:62-71`）⇒ 原版对 `DA_SK_4`/`DarkAngelsDeck7` 的
    `LocalizedName` = **null**，画出来就是**空名**。⇒ 这 2 副的"空白"**是原版如此**。
  · ⇒ 顺带订正一处文档错（未改，只记）：`资料/预组卡组_原版规格.md:56` 写「`LocalizedName` =
    `GetTranslation(前缀+deckName)`」——**应为 +deckId**（上面两条硬证据）。
- **结论**：①若用户看到的空格是 DA_SK_4 / DarkAngelsDeck7 ⇒ **假问题（原版也空）**；
  ②其余 6 副（含 SpaceWolvesDeck5）是**真缺陷**：官方名存在但我们在生成期漏 join ⇒ 界面显示我们自译名、
  日志噪声；③被指的那一格（第 2 行第 1 格）**截图里不是空白**，无法定位当时的真实格子 ⇒ **判不了**。

## B 卡组列表首开为空

- **判定：假问题（不是加载时序/缓存未刷新）—— 首开时确实一套卡组都没有；后来出现的那副是
  打开卡组编辑器时"空库自动补的演示卡组"，当场落盘。**

- **证据 1（文件是本次会话才生的）**：`C:/Users/qjh36/AppData/LocalLow/Everguild/Warpforge/WarpforgeDecks.json`
  **Birth = 2026-10-22 00:09:26**、Modify = 00:13:16。而 `02_collection.png` 拍于 **00:08**（空列表）⇒
  那一刻**盘上没有存档**，「没有卡组」**是对的**（`DeckStore.LoadAll` 走 `NoSaveFile`，
  `RuleEngine/Data/DeckStore.cs:128-133`，返回空表且**不算失败**）。
- **证据 2（这副牌是代码造的，不是玩家造的）**：存档里那副「复仇者之刃」的 30 个 id 与
  `Deck/DeckRuntime.cs:8509-8560` 的 `PlayerDeckForDemo()` 按**当前**池子算出来的结果**逐位相同**，
  防御位也正好是它挑的 `ASH56`（现算复现：ASH83×2 … ASH70）。
  成因 = `DeckRuntime.Build` 的 **`if (Library.Count == 0)`** 那段（`DeckRuntime.cs:1263-1272`）：
  `Library.Create(我的卡组)` → `Library.CommitCurrent(PlayerDeckForDemo(fresh))`；而
  `DeckLibrary.CommitCurrent` **连名字一起拷**（`RuleEngine/Data/DeckLibrary.cs:267` `dst.Name = deck.Name`）
  ⇒ 默认名被演示名「复仇者之刃」覆盖并**落盘**（`Save()`）。
  名字源 = `Core/Loc.cs:1868` `MenuDeck/DemoDeckName` = 「复仇者之刃」/「Avenger's Blade」。
- **证据 3（后来为什么出现）**：`14_after_discard.png`（00:11）是在**卡组编辑**里点了"放弃更改"、
  经 `DeckRuntime.LeaveByHostWindow` 回壳后拍的 —— 那一路会先
  `CollectionData.InvalidateLibrary()`（`Deck/DeckRuntime.cs:5062`）再重建收藏窗，
  ⇒ 进程级缓存 `CollectionData._lib`（`Shell/CollectionData.cs:58-61`）重读盘，才看到这副新落的演示卡组。
- **空态文案（问题 2）**：键 = **`MenuCollection/NoDecksFound`**（`Core/Loc.cs:763`），
  **只有一颗节点** `Empty Collection Warning`（`Shell/CollectionWindow.cs:3632-3646`），
  显隐判据 = `FilteredDeckIndices().Count <= 0`（`:3898-3912` / `:3948-3951`）
  ⇒ **"一套都没有"与"筛完为空"共用同一条文案**。
- **原版口径**：收藏线数据是**本地单例、同步内存表**（`Shell/CollectionData.cs:4-12` 的 A4 实证：
  Deck 页 = `DeckManager.DeckCollection`，全链无 `handler.`）；`CardCollectionDisplay__OnEnable`
  只 `Register` 一个 collection 更新信号（`decomp_full/CardCollectionDisplay__OnEnable.c:18-19`），
  `RefreshCollection` 里那个延迟是 `DOVirtual.DelayedCall` 的**动画**（`…RefreshCollection.c:26-30`），
  **不是读盘、也没有"加载中"态**；空态判据同样是"筛选后为空"（我们的注释照抄了
  `CollectionDisplay.RefreshCollection` 的 `filteredCollection.Count <= 0`）。
  ⇒ 原版不存在"首开空、几秒后自己冒出来"这种行为 —— 我们这次也不是，是**编辑器空库补牌**。
- **仍然是真的问题（副产物，建议记一条账）**：① 打开卡组编辑器会**静默把一副演示卡组写进玩家存档**，
  并**覆盖掉默认名**（`我的卡组` → `复仇者之刃`）；② 原版没有"打开编辑器就发一套牌"这条
  （原版新账号的起始卡组走 FTUE/`FTWESelectDeckWindow`，不是编辑器副作用）。这是**我们的选择**，
  但它会被玩家读成"卡组自己冒出来"。

1. **A（真）**：`gen_official_names.py:resolve_prebuilt_decks` 改成**先按 `PrebuiltDecks/<deckId>` 同形取**

   日志那行消失。`DA_SK_4`/`DarkAngelsDeck7` 官方没有键 ⇒ 保留 `nameZh` 兜底并在账里注明

   → 官方「狼性伙伴」）—— 这是**对的**（原版就是按 deckId 取）。

   三处「键 = SO 名 / LocalizedName 用 deckName」的旧说法（铁律 5）。
2. **B（假）**：不改加载链。若要收掉"卡组自己冒出来"的观感，方向是**把 `DeckRuntime.Build` 的
   空库补牌改成不落盘/或在收藏页显式提示**——但那属于**偏离原版的设计取舍**，需用户拍板，⛔ 别顺手改。
3. **B 的文案**（可选）：`MenuCollection/NoDecksFound` 两档共用**是原版做法**，不需要拆；真要区分，
   得先有原版判据（现在没有）。
