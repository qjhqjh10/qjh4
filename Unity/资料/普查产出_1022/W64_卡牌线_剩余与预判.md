- 可打出那圈绿/白光是 **SDF `_Outline`**，入口是 **`CardView.SetOutline`**（`CardView.cs:7137`），
  由 `BattleDriver.RefreshHandPlayable` 调。

⇒ 探针渲的所有 `_selected.png` 里，那圈白光**是 `_rim` 状态环，不是 `outlineGlow`**。

**`1−α` vs `(1−α)²` 能不能从图上看出差别？→ 不能，而且原理上不能。**

- 我们现在的实现 = **几何等价物**：立绘铺到斜面下、由卡框自己的 α 合成 ⇒ 结果**就是 `1−α`**。
- `(1−α)²` 要多乘一次立绘 alpha。
- 两者只在中 α 处有差别，**而我们的渲图本身固定是其中一支** ⇒ 拿自己的渲图去判「我们用的是哪一支」是自证。
- 唯一的外部尺子只有**原版游戏的实拍**。手上那几张（`C:/Users/qjh36/Desktop/warpforge参考图/战斗截图参考.png` 1576×747、`11_glow_defense.png` 520×620）
  里，手牌卡宽约 165 px ⇒ 斜面 **11 px @1024 贴图** 折算到屏上只有 **≈2.7 px**，还要叠 JPEG/缩放 ⇒ **判不了**。
- 静态侧也判不了：`d:/2/tools/decomp_full/UnityEngine.UI.Extensions.SoftMaskScript__get_MaskMaterial.c`
  **内容对不上**（文件里的函数体是 `ActiveSkillDisplay__get_parentCard`，反编译索引串了）；
  `__SetMask.c` 只看到 `SetTexture/SetFloat/SetInt`（`_MaskTex` / `_FlipAlphaMask` / `_MaskArea`），
  **真正的乘算在 shader 里，而 HLSL 源码被剥了** ⇒ 这条静态路是死的。

⇒ **判据缺口**：要么接受「结构上一次乘（`1−α`）」，要么补一张**原版把战术卡放大到 ≥400 px 宽、且斜面下压着亮色立绘**的实拍。

### 4·2 探针要给的两处能力（**当前做不到**）

view.SetOutline(CardHighlight.OutlineOf(def, canBePlayed: true));   // 语义 = 可打出
Shot(view, Path.Combine(OutDir, SafeName(name) + "_playable.png"));

⚠️ `OutlineOf` 的签名是 `(RuleEngine.CardDef card, bool canBePlayed, bool drawnThisTurn=false, bool oathAffordable=false)`

否则拍到的是「补间起点 = alpha 0」。**这是这条改动的真坑。**

## 6. `W62` 那两条代码尾巴：读了一下，判断

### 6·1 `TmpSetup.cs:258-267`（⑧ 读数口径）—— **是现在就能改的，而且确实错了**

现状（`TmpSetup.cs:258-267`）：
```csharp
float wg = CardPresentation.TmpFont.WorldGlyphPerFontSize;      // = 汉字墨高 ÷ fontSize（CJK 面）
float titleH = CardPresentation.CardView.TitleFontSize * wg;
float kwH    = CardPresentation.CardView.KeywordFontSize * wg;
```
两处对不上：

1. `CardView.TitleFontSize` / `KeywordFontSize` 自 **2026-10-22（`W62/T2`）** 起已经是
   **按面的 em 字号**（`CardView.cs:3798` = `TmpFont.FontSizeForEm(Face.LatinUi, Height*TitleEmOfCard)`；
   `:3826` = `FontSizeForEm(Face.LatinCardBody, Height*DescEmOfCard)`）。
2. `WorldGlyphPerFontSize` 是 **CJK 面**的汉字墨高比（`TmpFont.cs:333-340`），
   而且它的读数**随 `m_Scale` 变**（2026-10-21 `A1262` 起 CJK 那份对齐成 `m_Scale=0.9` ⇒ 0.0948 → **≈0.0853**，见 `TmpFont.cs:324-328`）。

⇒ **混了量纲**：拿拉丁面的字号去乘 CJK 的墨高比。数值上偏小 **0.0853/0.1 = 0.853**，
即打印出来的「卡高 %」比真值小 **14.7%** —— 正好就是 §一 里那个「小 14.7%」。

**改法候选**（只动一个只读探针的打印，不动任何画面）：
```csharp
float emUi   = CardPresentation.TmpFont.EmPerFontSize(CardPresentation.TmpFont.Face.LatinUi);      // = 0.1
float emBody = CardPresentation.TmpFont.EmPerFontSize(CardPresentation.TmpFont.Face.LatinCardBody); // = 0.1
float titleH = CardPresentation.CardView.TitleFontSize * emUi;
float kwH    = CardPresentation.CardView.KeywordFontSize * emBody;
// 汉字那一档保留给 HUD 用（它本来就走 CJK 面）
```
⚠️ `wgOk` 的通过域 `wg > 0.002f && wg < 0.2f`（`:261`）**不用动** —— 它量的是 CJK 那条链，仍然是 0.0853。
⚠️ 顺带把文案里「汉字『字形高度 ÷ 字号』」那句改成「**拉丁面 em ÷ 字号**」，否则下一轮又要混。

### 6·2 `IconSetup.cs:67` —— **是现在就能改的，但只改注释、别改 `CalibScale`**

原文：「卡面效果文字字号 **2.48**（`CardView.KeywordFontSize`）、拉丁大写墨迹高 **0.19** 卡单位」。

现读 **`CardView.KeywordFontSize` = 2.3552**
（= `Height 3.3313 × DescEmOfCard 0.0707 ÷ 0.1`，`CardView.cs:3826` + `:3830`）。
`2.48` 是**改前的口径**（= `0.23552 ÷ WorldGlyphPerFontSize 0.0948` = 2.4844）⇒ 注释过期，应改。

🔴 **但 `CalibScale = 0.776` 别顺手改**：它是「目标图标高 0.38 = 2.0 × 0.19」÷「实测图标 0.49」推出来的，
而 `0.19` 是**当量出来的大写墨迹高**、`0.49` 是 `IconSizeProbe` 扫出来的。
字号从 2.48 掉到 2.3552 ⇒ 大写墨迹高大约跟着掉到 **≈0.180**，那 `CalibScale` 就该是 ≈**0.735**。
**但这是推算、不是实测** ⇒ 按 `IconSetup.cs:73` 自己那句「改这条要重跑 `IconSizeProbe.Run` 复量」办，
**⛔ 不许照着推算改常数**（`IconSetup.cs` 的 `CalibScale` 注释里也写了：两个系数同源、改一个要想另一个）。

⇒ 建议拆两笔：**（a）改注释里的 `2.48` → `2.3552`（安全、纯文字）**；
**（b）`CalibScale` 要不要跟着动 = 先跑 `IconSizeProbe.Run` 复量再定**（这笔要 Unity）。
