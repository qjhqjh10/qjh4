### R4（β·1）手牌陷阱闭包捕获 `for` 变量

- **改动**：`EffectResolver.cs:7736-7746` —— `BroadcastHandTrapWhen` 里 `var _p = p; var _opsT = ops;`，闭包用 `_p`。
- **判据**：同族 `:7458` 的 `var _pe = pe;`（C# 5 起只有 `foreach` 逐帧捕获，`for` 不是）。
  原来那句注释「`p` 在入队这一刻定死」是**假的** —— 循环跑完 `p == 2` ⇒ 出队时 `ctx.Players[2]` ⇒
  `IndexOutOfRangeException @ ResolveTargets`（`spec.Kind=="warlord"` 支）。
- **断言**：无新增；`TestA4Batch4` 整段恢复跑完（它本来是**整段中断**）。

### R1（γ·13）入口没有 `ActionScope` ⇒ 入队的触发永远不结算

| 入口 | 改动 | 形状 |
|---|---|---|
| `Hurt` | `RuleCore.cs:7666-7684`：`using (BeginAction(ctx)) return HurtCore(...)` | 照 `ApplyDamage`（`:7179`）的壳+体 |
| `BroadcastWhen` | `EffectResolver.cs:7147-7166`：`using (BeginAction(ctx)) BroadcastWhenCore(…)` | 同上（公开口 = 自检直调它，`A1682` 那 5 条） |
| `GrantDarkPact` | `EffectResolver.cs:8748-8762`：`using (BeginAction(ctx)) GrantDarkPactCore(…)` | 同上（②③ 已改入队，④ 的 `ApplyOneGain` 也可能入队） |
| `TryCancelAttackByOwnAboutToAttack` | `RuleCore.cs:6780-6795`：壳 + `…Core` | 同上（自检走反射直调，外面没有作用域） |

- **判据**：`ActionPump.cs` 的设计口径 ③（顶层动作外壳 = `ActionScope`，退出时取空队列）＋
  `ActionScope.Dispose` 的「泵点漏了」只在**外层**作用域退出时才报 ⇒ 漏包的入口是**静默**。
  泵点没新造，全是同族 `using (BeginAction(ctx)) …Core(…)`。
- **`Auras.Recompose`（`:8585/:8619`）那两条**不需要单独改：它在 `MinionDeathBookkeepingDeferred`
  （队列体）里，`Hurt` 有了作用域之后会真的跑到。
- **断言**：无新增。诊断建议的「公开入口返回时 `ctx.ActionQueue.Count == 0`」那条自检**本轮没加** ——
  我这边跑不了 `RuleEngineTest`，加了无法确认不会引入新红；已列进 §五 欠账（**建议下一批补**）。

### R3（γ·2）指代槽比队列动作的生命期短

- **改动**：`RuleCore.Draw`（`RuleCore.cs:2572-2592`）把 `MoveDeckTopToHand` 提到作用域外，
  然后 `using (DrawReferentScope.Seed(ctx, inst)) using (BeginAction(ctx)) DrawCore(…)` ——
  C# `using` **倒序释放** ⇒ `BeginAction` 先退（**泵队**）、指代槽后还原。
  `DrawCore` 里那句 `using (DrawReferentScope.Seed(...))` 删除（`:2612` 附近，改成普通调用 + 注释）。
- **判据**：`BroadcastWhen(Draw, …)` 只入队；监听器正文在**出队时**才跑（`FireBoardListenerDeferred`），
  而 `DoLowerCost` 的「指代上一张」只有两个来源：`ctx.LastCreated` → 兜底 `ctx.DrawnThisResolve`。
  一个是变短就会失效，一个是 `ResolveOps` 入口会清 ⇒ 槽必须活到泵点之后。
- **断言**：`TestS10CompanyMasterLowerCost` ①②（既有，未改）。

## 三、没查清 / 风险（如实标着）

1. **`DeathBatch` 套在每条队列动作外面**是我按「原版 death action 排在当前动作之后」做的等价实现；
   `_ResolveBacklash_d__451` 与「反噬 ability 入队点」之间到底隔了几拍 `WaitForSeconds` **没逐机器码核**。
   ⇒ 观测等价靠既有断言（`TestW58*` 五条）兜，如果主对话跑出来有反例，优先回看这一处。
2. **`BroadcastUnitFerocity` 三跳都无自排除** 这句是照诊断的引用落的（不是我这轮独立核的）。
3. **R5 的「环会一路跑到有人被打死」**是对新机制的直接推断（原版没有深度上限）；本轮只把它写成
   「没摸到结构闸 + 队列停干净」，没有断言「一定有人死」。
4. **本轮改动里三处「可能翻绿为红」的风险最高的地方**（主对话跑 `RuleEngineTest.Run` 时请优先看）：
   ① 泵点的 `SimultaneousDamage`（死亡一律延后到该动作结束）；
   ② `PlayTactic` 正文整段入队（战术卡的效果落地时刻推后到泵点，仍在同一次调用内）；
   ③ `EvtKind.Death` 信号入队（表现层信号的相对次序变了，规则层不读它）。

## 五、顺手发现（只报不改）

1. **`RuleCore.cs:11124` 那句 `if (!ctx.DeathsDeferred) TryCreditKill(...)` 现在恒不成立**
   （队列体一律在 `SimultaneousDamage` 里）⇒ 它和 `EffectResolver.cs:2094/2505/3065` 同形的三处
   **都是死代码**；实际记账由 `FlushDeaths` 的 `PendingDeath.ActingCard` 那一支接住（行为对，路径换了）。
   建议下一批在这几处补一句注释或删掉，免得下一个会话以为它还在生效。
2. **诊断 R1 建议的「公开入口返回时 `ctx.ActionQueue.Count == 0`」自检本轮没加**（见 §二·R1）。
   这是防「以后又漏包一个入口」的唯一结构闸，值得补 —— 但要能在 Unity 里跑过再加。
3. `DoGive` 那一族**其余 10 个动词 handler** 仍是 `!t.IsAlive` 闸（`EffectResolver.cs` 里那 10 处），
   本轮只把 `DoGive` 与代词解析扩成 `IsInPlayOrDying`。原版那 10 个入口闸**没逐条核过**（既有注释也这么说）。
4. `RuleCore.cs` 里 `TryCancelAttackByOwnAboutToAttack` 的 80 行 doc 挂在**壳**上、`Core` 没有 doc ——
   和 `ApplyDamage` 同形，不影响行为；如果以后有人按 doc 找函数体，会先落到壳（可接受）。
