## 一、战场相机

**原版只有两条路，没有旋转、没有惯性、没有左键/中键平移**（`CombatCameraZoom` 挂在 `BoardCamera`）：

1. **滚轮缩放**：`ScrollDelta`（legacy `Input.mouseScrollDelta.y`，Windows 一格 ±1）× `zoomSensitivity 0.1` → `TargetZoomLevel += ±0.1`，clamp `[0,1]`；`invertMouseScrollWheel=true` ⇒ **上滚=放大**。
2. **右键拖拽平移**：`TouchPressedSecondary` 就是 `Input.GetMouseButton(1)`（`TouchInputManager__Update.c:134-138`）。**左键在原版是拖卡、不控相机**。

**每格滚轮走多少**：
- 原版：1 格 = ±1 legacy → **zoom ±0.1** → `sensorSize.x` 变 ±1.369（41.5 ↔ 27.807）⇒ **每格 ≈3.4% 视觉大小，10 格走满全程，总变焦 1.49×**。
- 平滑：`SmoothDamp(..., smoothTime = dt × zoomSpeed 12.5)` ⇒ 60fps 0.208 s / 30fps 0.417 s。
- 我们：`ScrollUnitsPerNotch = 120`，`raw ÷ 120` ⇒ 若设备每格真报 ±120，则逐值与原版相同。

**「按住鼠标不能左右移动」**：
- 原版**有**平移，但只认**右键**；左键按住不动相机（原版也一样）。
- **zoom=1（开局档）时横向被夹死**：视锥宽 20.1156 ≈ `worldBounds` 宽 20.115 ⇒ 任何 x 位移都被推回。这是**原版几何**。纵向视锥高 11.32 < 边界 15.75 ⇒ 纵向能动 ±2.2 世界单位。要横移必须先放大。
- 平移量：`像素位移 × 0.01 × (−1)` 直接当 lensShift 增量 ⇒ 1px 鼠标 ≈ 19px 画面。

**「为什么慢」**：数值链**逐值与原版一致**（场景 13/13 同值）。只剩两个可疑点：
- ① **唯一非原版的一环 = 滚轮量纲 `/120`**（Input System 没有 legacy `Input`）。`资料/普查产出_1012/H20_手动相机与指针入口.md:143` 自记「这一除是我们挑的等价物，一格到底该走多少只有真 Play 才量得准」，`:149` 记「真 Play 没跑」。若实机每格不是 120，步长按比例缩小 ⇒ 正是「很慢」。
- ② 帧率：`smoothTime = dt×12.5`；30fps 时平滑时长翻倍。
- 另注：开局 zoom 已经是 1（最远档），**再往下滚不动**；只有往上滚才放大。

## 二、大图后面的卡点不到

**原版有**这个操作：`CardDisplayWindow__AddCardsListeners.c` 给扇形列表里**每一张卡**（主卡 + 相关卡，最多 5）各挂监听；`CardUIClicked.c` / `b__38_0..3.c` / `RelatedCardUIClicked.c` 全部走 `ChangeCardPosition(被点那张)`。
`ChangeCardPosition.c:50-57` 三道早退：同一张卡 ⇒ return（点前排自己不关窗）；开窗动画 isPlaying ⇒ return；`swappingCards` 闸。

原版为什么点得到：每张卡身上有**自己的 uGUI 射线靶** `2DCard/UI Collider`（`battlearena1/GameObject/UI Collider_500.json`：RectTransform + Image `m_RaycastTarget=1`/padding=0 + `UIGenericEventCatcher`），排在 `Menu Dark Background` 之上 ⇒ 点击到不了背景关闭件。

**我们被谁挡住**：卡体仍是**世界空间 mesh**（不在 uGUI 射线里），画布上有一块**全屏透明 uGUI** `cdw_background_close`（`CardDisplayWindow.cs:570-583`）。同一次松手：
- `BattleDriver.HandleDisplayWindowClick`（`:9528-9535`）判到卡格 → `SwapToFront(i)` 起 0.25 s 补间；
- backdrop 同时 `_closePending=true` → `LateUpdate` → `ApplyPendingClose` → `Hide()`（`:1249-1267` 清子件、杀补间）。
⇒ **窗直接关掉**。点前排自己那张同样会关窗（原版是「什么都不做」）。
这是已挂账的 **P1-4**（`普查产出_1019/W57_战斗线_T09_审查修复.md:191`；`交接_第五十七会话.md:92` 要求真机验）—— 现在真机验出来了。

**最小改法**：
```csharp
// CardDisplayWindow.cs（约 :244 加字段；:1278 RequestCloseByUgui 加门）
public System.Func<Vector3> PointerWorld;          // BattleDriver 接 WorldPointer
void RequestCloseByUgui() {

    if (PointerWorld != null && HitSlot(PointerWorld()) >= 0) return;   // 卡自己的射线先吃
    _uguiCloseClicks++; _closePending = true;
}
```
```csharp
// BattleDriver.cs:20561 之后
_cardDisplay = CardDisplayWindow.Create(root);
_cardDisplay.PointerWorld = WorldPointer;
```
长期正解仍是卡体迁 uGUI（`T09` 第 5/6 步 / `T09-残 A4`），迁完删补丁。

## 四、建议改动清单

1. **A-量**（不改逻辑）：`TouchInputManager.ReadRaw`（`:361-373`）加临时日志，`scroll.ReadValue().y != 0` 时打 `raw / dt`；真机滚一格记数值。
2. **A-修**：若实测 ≠ ±120 ⇒ 只改 `ScrollUnitsPerNotch`（`:322`，全工程唯一口径）。若 = ±120 ⇒ **不要动常量**，查帧率 / 与用户确认是否接受原版手感（改 `zoomSensitivity` 属偏离原版，要用户拍板）。
3. **A-补**：给 `CombatCameraZoom.PointerOverUi` 接真判据（原版：指针在 UI 上时手动镜头整段不跑）。原版有、我们缺，与「慢」无关。
4. **B-修**：`CardDisplayWindow` 加 `PointerWorld` 钩子 + `RequestCloseByUgui` 早退；`BattleDriver.cs:20561` 接线。
5. **B-长期**：卡体迁 uGUI（`T09-残 A4`），迁完删补丁。

## 五、断言建议

- **A**：已有 A422 那 12 条（`Editor/BattleScene.cs:9884-10196`）。补两条配对：
  ① `ZoomChange(±1) ⇒ TargetZoomLevel 变化恰 0.1`（含 `ScrollUnitsPerNotch == 120` 换算）；
  ② **灭自证**：`zoom=1` 时横向夹回 ~0 / `zoom=0.5` 时拖得动（期望相反）。
- **B**：三条必须**成对**（否则「把 backdrop 关窗一刀切」会全绿）：
  ① `Show → 点 slot i(i>0) ⇒ Visible 仍真 + 前台换成第 i 张`；
  ② `Show → 点空白 ⇒ Visible 假`；
  ③ `Show → 点 slot 0 ⇒ Visible 真 且不换位`。
  ⚠️ 必须走真实入口（`RequestCloseByUgui` / `HandleDisplayWindowClick`），⛔ 不许直接调 `SwapToFront`。
