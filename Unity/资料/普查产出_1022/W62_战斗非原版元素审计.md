## A 换牌压暗

- **结论：不是原版如此 —— 我们把压暗层画在了卡上面。**（同时 alpha 也是我们自己挑的：0.88 vs 原版 0.8）
- 原版（判据逐条）：
  - 压暗件 = `Canvas/FrontCanvas/ShadePanel`，**`FrontCanvas` 的【第一个】子件**，而换牌内容在**后一个**子件
    `Safe area FrontCanvas/…/Mulligan` 下 ⇒ **兄弟序在卡与按钮之前 = 画在它们后面**。
    判据：`Unity/资料/说明书/01_战斗_对战/2D层_battlearena1全树.md:229-232`（`ShadePanel` 与 `Safe area FrontCanvas` 同级、`ShadePanel` 在前）、`:307`（`Mulligan` / `MulliganAnchor` 在 `Safe area FrontCanvas` 内）。
  - 原版起手牌是**搬进 `Mulligan/MulliganAnchor`**（同一块画布里的 uGUI）⇒ 卡在压暗层**前面** ⇒ **卡是亮的**（用户实拍 `战斗—替换手卡参考图（先手）.png` 与本条互证）。
  - 颜色/透明度：`MonoBehaviour_4399.json`（Shade 组件）`onAlphaLevel = 0.8`；`MonoBehaviour_4215.json`（被它驱动的 `Image`）`m_Color = 黑, a=0`（运行时淡到 0.8）、`m_RaycastTarget=0`；调用点 `BattleManager._SetupMulliganPhase_d__341__MoveNext.c:48` = `Shade.SwitchShade(shade,1,1,0)`。
- 我们：
  - 压暗 = `MulliganPanel._shade`，`CardArt.Solid()` 的 uGUI `Image`、**`Color(0,0,0,0.88)`**，建在 `Mulligan Canvas` 子画布（排序层 `OverHand`、order 0）里，`FillParent` 铺满 — `Battle/MulliganPanel.cs:690-703`。
  - **卡体仍是世界空间 `CardView`**（`MulliganPanel.cs:96-110` 文件头「有意不迁」那两条 + `:573`）⇒ 画布层**盖在世界之上** ⇒ 压暗压在卡上。
  - 像素实测（`_tmp_view/shots/2026-10-22_第六十二会话/21_battle_start.png`）：**卡面任意像素最亮 = 98/255**（整张卡被压到同一个天花板，正是「上面盖了一层"的证据）；同屏画布件（「替换」钮 / 「继续」钮 / 眼睛）最亮 **= 255**。98 = 线性 0.12 = 1−0.88 转 sRGB，与那层 0.88 黑**逐位吻合**。
  - ⚠️ 旁支：`CardHighlight.ColorOf(Unplayable)` = 灰 0.55（`Core/CardHighlight.cs:101`）—— 若换牌期还被判成「不可打出」会再压一层；本次**没有证据显示它被触发**（否则天花板不会正好等于 0.88），但修 A 时顺手确认一次。

## B 「由 … 创建」

- **原版显示条件**（`BattleCardUI__DisplayCreatedByText.c` 亲读，与 `BattleCardUI__SetObjectVisibility.c:100-133` 同判据）：
  ① 先把 `CreatedByText` 节点 **`SetActive(false)`**；
  ② `card.createdBy != null`（`CardScript.createdBy`，偏移 **+0x268**，`d:/2/tools/il2cpp_out/dump.cs:35476`）；
  ③ 状态判据（`CardStateOptions`：`inHandShowing=8` / `inHandPlaying=10`）：
  **`state==8` ⇒ 显示**；**`state==10` 且 `isPlayer(+0x40)==false` ⇒ 显示**；**其余一律不显示**。
  ⇒ 也就是：**只在自己手牌「正在展示/放大」那一刻**（和「对面的牌被打出」那一档）才亮，普通 `inHand=1`、场上 `inPlay=2`、牌堆、详情窗**都不亮**。调用点印证：`CardScript__ShowCardInHand.c:172`（亮）、`CardScript__SetStateInHand.c:39`（按当前状态重算 ⇒ inHand 时关）、`CardScript__StopShowingCardInHand.c`、`CardScript__StartMovingFromHand.c`。
- **文案**：`SupportMethods.GetCreatedByText(创建者卡名)` = `GetTranslation("Battle/HUD/CreatedBy").Replace("{0}", 名字)`；官方表有 `Battle/HUD/CreatedBy` = `Created by {0}` / `由 {0} 创建`（`数据/游戏数据/官方本地化_en+zh-CN.json`）。
- **卡面几何/字体是照原版的**（亲读资产，不是采信注释）：`bundle_menus_assets_all/RectTransform/RectTransform_4803967432083755832.json` = 锚/轴心 (0.5,0.5)、`m_SizeDelta (2.5, 0.38)`、`m_AnchoredPosition (0, 1.65)`；`MonoBehaviour_4833287377952691000.json` = `m_text "Created by someone fancy"`、`m_fontSize 2.45`、`enableAutoSizing=1`、`H=Center / V=Middle`、白色。⇒ 文字框比卡宽、并且**上缘超出卡顶 0.17 卡单位**，这是**原版本来就这样**，不是我们画歪。
- **我们今天**：
  - `BattleDriver.cs:18800` 每轮对**每一张手牌**都推一次 `SetCreatedBy(Ctx.CreatedByOf(h[i]))`；`Core/CardView.cs:2227-2236` 名字一变就重画、`SetFace(Board)` 时整层关（`CardView.cs:1627`、`:3426`）⇒ **场上是关的（对），手牌是常亮的（错）**。
  - 实拍：`24_hand_settled.png` 与 `30_hand_only_1080p.png` 里那行字出现在**没有抬起、没有悬停**的普通手牌上 ⇒ **显示面比原版宽**（原版要 state 8）。
  - **创建者取错（真缺陷，用户点的就是这条）**：引擎 `RuleEngine/Core/BattleContext.cs:635-636`
    `var creator = ActingUnit != null ? ActingUnit.Card : PlayingCard;`，而 **`PlayingCard` 从不清空**（同文件 `:1161-1167` 自己写着「从不清空」，写点只有 `ResolveOps` 入口与 `NotePlayed`），并且**不分玩家（全局一个）**
    ⇒ **任何在「不是效果结算中」新造的牌，都会拿到「上一张被打出的卡」——可能是对手的卡**。
    实拍证据：同一条手牌（`先知之道`，玩家战将的天赋卡）在两个时刻显示两个**不同**创建者：
    `24_hand_settled.png` = 「由 **舰队之主** 创建」（`9238c27730a0c424288d46ed0f4a742c`，Ultramarines 天赋/tactic，「Deal 1 damage…」，**造不出任何牌**）；
    `30_hand_only_1080p.png` = 「由 **他们越大...** 创建」（`64a657fc5ed5bbb4fa7b585cf29c1e95`，**Goff/兽人**战术卡）。玩家牌组是 Saim-Hann（手牌全是 Aeldari）⇒ 这两张只可能是**对手**打出的卡。
  - **为什么偏偏是天赋卡**：`天赋卡 = 每回合开始生成`（`RuleCore.cs:2006` 调 `SpawnTalents(ctx, ctx.Active)`），生成走 `ctx.NewInstance(...)`（`RuleCore.cs:10896 / 10935`）—— 那时 `ActingUnit==null`、`PlayingCard` 还停在**上一个人打出的最后一张** ⇒ 天赋卡被盖上别人的名字。**判据链齐**，不需要真机复现即可定位。
- **差异小结**：(1) 创建者来源错（`PlayingCard` 全局且不清空）；(2) 显示时机错（我们常亮，原版只在「展示/放大」那一档）；(3) 自己打出的那张在 `inHandPlaying` 时原版**不亮**（`isPlayer` 判据），我们会亮。原版天赋卡该不该有这行 —— **原版确实会给「进手牌时带 creator」的牌盖章**（`BattleManager__AddNewCardToHand.c:161-165`、`BattleManager._StartBattlePhase_d__334__MoveNext.c:230/255` 给 `startingCardInHand`/`goSecondCardInHand` 传 creator=督军），所以**这行字本身不是我们发明的**；错的是**名字**与**时机**。

## 建议（只给方向，不动手）

1. **A**：让换牌卡画在压暗层**之上**——最省的做法是压暗层降到卡体所在的那一侧（世界空间 quad 放卡后面 / 或把起手牌抬到压暗层之上的画布层）；顺便把 0.88 改成原版 **0.8**（`onAlphaLevel`）。顺手确认换牌期卡没被 `Unplayable` 灰化。
2. **B-1（真缺陷，优先）**：`BattleContext.NewInstance` 的 `creator` 不能退回**从不清空的全局 `PlayingCard`** —— 要么加一个「正在结算」作用域（`ResolveOps` 进入置真、退出置假，且**分玩家**），要么在 `BeginTurn/EndTurn` 把 `PlayingCard` 清空；否则每回合的天赋卡、以及一切非结算期新造的牌都会挂上「上一张打出的卡」（可能是对手的）。
3. **B-2**：给 `SetCreatedBy` 加「正在展示」闸（照原版 `state==inHandShowing`；自己的牌打出那一档不亮），别常亮。
4. **C**：上表「我们自造」的 10 条按用户口径「原版没有的设计不要」处理 —— 直接删（回合行、Settings 标题、AI Difficulty、两句「点一下关闭」、开局牌组播报），或至少先把 9 句硬编码中文接回 `Battle/Hint/*` 词条（现状英文档露中文）。日志的「后果」那几行要留就先定口径，别默认当原版。
