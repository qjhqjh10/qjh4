# W63 · 换牌倾斜 + 可打出绿光判据（只读代理，2026-10-22）

## 1. 换牌那排卡：原版是平整 0°

**有反编译第一权威，不是靠截图**：
- 布局实例 `MB_4881`（`MulliganAnchor` GO131 身上的 `CardsHorizontalLayout`）：
  `m_useRotation=0` · `m_invertRotation=0` · `m_rotationModifierBasedOnTotalCards` 全 0 ·
  `m_yAxisCurve` 平 0 · `m_verticalOffsetLookTo=0` · `m_inverted=0` ·
  `useExtraSpaceOnSelectedCard=0` · `useZOrder=0` · `m_maxLayoutSize=0.98` · `m_maxHeight=0.44` ·
  `m_betweenElementsSpacing=502.2` · `m_scale=183.41` · `m_numberOfCardsForMaxHeight=7`。
- `CardsHorizontalLayout__GetRotation.c:34-41`：`m_useRotation==0` ⇒ **直接返回 `Quaternion.identity`**。
  `GetPosition.c:235-236`：y = 锚点 y + `yAxisCurve(t)×maxHeight×hMod`，曲线平 0 ⇒ 所有卡同一 y。
- 原版换牌移动链：`PlayerHand._AddCardsToMulligan_d__41__MoveNext.c:119` → `MoveCardToMulliganPos` → `CardScript.DrawCard`；我方走 `TurnCardAround`（两段各 90°），完成时 `FinishCardDrawRotation.c:13-24` 收在 **`Vector3.zero`**；敌方 `DrawCard.c` 也 `DORotate(Vector3.zero)`。
- 行心：`Transform_1292`（MulliganAnchor）`localPosition (0,29,0)` ⇒ 设计 y=511（我们一致）。
- 间距/尺寸：序列化 502.2 / 183.41；换牌这一行**只有**用户实拍 414 / 292（1579×887 视频帧 ×0.821），T10 已记「待真机复测」。另：原版 `MoveCardToMulliganPos` 的卡尺度取自 `CardScript.GetCardInHandScale`，**不是**布局的 `m_scale` ⇒「换牌卡宽 = 383.8」的推断不成立。原版还有**逐张错开**（每张 `WaitForSeconds(timeToDraw×0.5)`），我们是一次性搬完。

### 我们为什么斜（根因链）

1. `BattleDriver.Begin`：`RefreshAll()`（`:4124`）→ `SyncHand`（`:18872`）→ `interaction.SetCards` → `CardInteraction.Relayout()` → `HandLayout.Place()`，场景 `animateRelayout=1` ⇒ 起一条 **0.2 s 的 `CardTween.ToPose` Sequence（含把 rotation 补到扇形角）**。
2. 同帧 `OpenMulligan()` → `MulliganPanel.Open()` → `BuildCardButtons()`：`SetPose(行位, **0f**, 尺度)`（`MulliganPanel.cs:969`）——**没有 DOKill**。（`ReapplyRowPoses` 有 DOKill，但它 `if(!Visible) return`，这一步走不到。）
3. `PlayDealAnimation()`（`:19098`）→ `CardFeel.DealInPose(…, rotZ:0f, sc)`：位移 0.3 s，而翻面旋转只占 `0.5×DealDuration=0.15 s`。

⇒ 0.15 s 后没人再写 rotation；手牌那条 0.2 s 的 `DORotate` 尾巴**最后落盘** ⇒ 卡停在扇形角；position/scale 被更长的 deal 补间覆盖成换牌区那一套 ⇒ **位置对、尺度对、角度错**（与真机照片一致）。

- `CommitDealtPoses()`（`:19020`）里 `v.transform.DOKill()`（`:19033`）**没拦住**：推断 `CardTween.ToPose` 是 `DOTween.Sequence`（target=null），叶子 tween 是 nested ⇒ `Transform.DOKill()` 杀不掉整条。**未反编译 DOTween.dll，未坐实**。
- 真机旁证：`_tmp_view/shots/2026-10-22_第六十二会话/21_battle_start.png`、`2026-10-21_第六十会话/71_mulligan_fixed.png` 均为扇形；用平卡标定后左端 ≈+3°、中间 ≈0、右端 ≈−5°，与 `HandLayout.RotationAt` 同量级同号。

### 最小改法

1. `MulliganPanel.BuildCardButtons` 在 `SetPose` 前加 `c.transform.DOKill();`（与 `ReapplyRowPoses` 同形）。
2. **根治**：换牌期不让手牌布局摆这几张 —— `SyncHand` 调 `interaction.SetCards(list, relayout: !Ctx.MulliganOpen)`；`CardInteraction.Relayout` 在 `relayout:false` 时 return。
3. **兜底**：`PlayDealAnimation` 的 `MulliganRowPose` 分支给 `DealInPose` 的返回 Tween 挂 `OnComplete(() => v.SetPose(rowLocal, 0f, RowCardScale))`。

## 2. 可打出卡绿色外圈光

**颜色/机制/时机/节点/材质/贴图都有原版判据；只有「圈的位置/宽度」（`OutlineGlowScale=1.35`）是我们自己加的。**

- 机制 = `Card Highlight And Shadow` 节点的 Image（材质 `Card Frame SDF`）上的 `_Outline`：`BattleCardUI.ChangeToHighlightColor`。
- 颜色 = 预制体字段（`MonoBehaviour_122102074273340352.json:218-253`）：`cardPlayableColor #1C7101 (28,113,1)` · `ephemeralCardPlayableColor #5B0F53` · `cardSabotageColor #FF2200` · `cardSelectedColor #003765` · `legendaryCardSelectedColor #FF6203(HDR)` · `cardSpecialActionColor #42E5FF`；打不出去 ⇒ `_Outline.a = 0`。
- 补间 0.2 s。节点 `RT_6990339727227853760` = **4.4281×4.4281 @ y −0.01265，localScale=1**。
- 材质 `Material_-3316280387615011577`（`Card Frame SDF`）：`_Inner_Edge .333 / _Outer_Edge .465 / _Inner_Fallof .224 / _Outer_Fallof 1.053 / _SpriteAlphaEdge_Outer .484 / _Inner .043 / _NoiseIntensity 1.15 / _NoiseColor (1,.6726,0,1) / _Noise=Noise Combined(128²) / _Noise_Speed_Scale_StepLow_StepHigh (.01,2,.06,.21)`，关键字 `_ALPHACHANNEL_R`+`_NOISE_CHANNEL_B`。**原版有噪声（颗粒/流动），但没有「脉冲」字段。**
- 我们自造：`OutlineGlowScale = 1.35`（`Core/CardView.cs:4046`）+ 专用 `outlineGlow` 层 + `OutlineZ = 0.055`。原版节点 **scale 就是 1**。

### 🔴 更深一层：原版是 Gamma、我们是 Linear

- 原版 PlayerSettings（`unity_run_ref/Warpforge_Data/globalgamemanagers` offset 272 = **0**，ColorSpace.Gamma）；我们 `ProjectSettings.asset:50 m_ActiveColorSpace: 1`（Linear），player 同槽位 = 1。两个 build 字段序列逐词对齐 ⇒ 同一字段。
- 同一张 SDF（原版 Texture2D `m_ColorSpace=1` sRGB）在 Gamma 下按**原始值**采、在 Linear 下被 sRGB→linear 解码（R 0.565→0.278）。按我们这张 SDF 的 R 剖面：
  - **Gamma**：带子 R∈[.333,.465] → |x|≈**0.84..0.99 卡半宽** ⇒ 贴着卡框外沿；
  - **Linear**：同阈值解码后 → |x|≈**0.69..0.83** ⇒ 落进画窗内沿（正是 W61 实测的 0.72..0.80）。
- ⇒ **`1.35` 实质是给色彩空间差做补偿**（0.75×1.35≈1.01），不是原版参数；它同时把带宽/噪声放大 35%。
- 结论：绿光的颜色/gating/0.2s/噪声都不是自造；**半径（1.35）是自造**，成因是 Linear/Gamma 差。

### 改法

1. `工具/import_original_card_sdf.py` + `card_sdf/*.png.meta`：`sRGBTexture: 0`（linear）。
2. `CardView.OutlineGlowScale` 回 **1.0**（或删掉专用层）。
3. 顺手：`SdfMaterial` 补 `_SpriteAlphaEdge = 0.397`（原版材质有）。
4. **必须渲图并排**（`C:/Users/qjh36/Desktop/warpforge参考图/战斗截图参考.png`）——这是唯一能定半径的办法。

## 4. 断言建议

- **A1（换牌角度）**：`CardTween.Advance` 过 0.5 s 后逐张断 `|DeltaAngle(0, localEulerAngles.z)| < 0.05°`。
- **A2（灭自证·扇形）**：同一夹具断 `|DeltaAngle(rot, hand.RotationAt(i,n))| > 0.5°`（n≥3）。
- **A3（灭自证·弧/排布）**：所有卡 `|y_i − y_0| < 0.5 px` 且中心距 = `RowSpacingPx` ±1.5 px。
- **A4（诊断 DOTween 语义）**：起一条 `CardTween.ToPose(..., 10°, 1, 0.2f)` → `tr.DOKill()` → `Advance(0.3f)` → 断 `|rotz| < 0.01°`。**今天可能红**——红了就坐实 `Transform.DOKill` 杀不掉 Sequence。
- **B1**：`TextureImporter(path).sRGBTexture == false` **且** `OutlineGlowScale == 1f`。
- **B2（灭自证·行为）**：`CardFaceProbe` 渲一张可打出卡，读回像素量绿带中线到卡心距离，断落在 **0.90..1.10 卡半宽**。只改 1.35 或只改纹理导入都会红。

## 5. 没查清

1. `Transform.DOKill()` 是否真杀不掉 `CardTween.ToPose` 的 Sequence（DOTween.dll 未反编译）——A4 可坐实。
2. 原版换牌行间距/卡宽真值（414/292 只来自视频帧；序列化 502.2/183.41 不同量纲链）。
3. `OutlineGlowScale` 归 1 后的最终半径：shader 的 R→半径映射未解出，只能渲图定。
4. 原版绿光是否「脉冲」（材质无该字段；只有噪声流动）。
5. 原版 Gamma / 我们 Linear 的影响面远不止绿光（SDF 阴影、材质色、UI 色都受影响）；要不要整体切 Gamma 是**工程级决定**，本轮只记录、没动。
