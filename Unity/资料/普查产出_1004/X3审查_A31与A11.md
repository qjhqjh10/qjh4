### 🔴 R1 · **错（高危）· `ApplyDrawerSlide` 把**像素**常量加进**世界单位**的 `localPosition` ⇒ 位移放大 108 倍**

- 证据（实现）：`Shell/CollectionWindow.cs:359-362`
  ```csharp
  var lp = p.BasePos;                       // BasePos = p.Node.localPosition（**世界单位**）
  lp.x += FltHiddenDx * (1f - p.Slide);     // FltHiddenDx = -550f —— 但它记的是**原版 px**
  p.Node.localPosition = lp;
  ```
  常量出处 `Shell/CollectionWindow.cs:189-190`（注释自己写着「原版 `hiddenPosition = (-550, 0)`」= px）。
- 证据（单位判据，三条互相独立）：
  1. `Core/LayoutSpace.cs:110-116`：**「可见高度固定 10 个世界单位 = 1080 px ⇒ 1 px = 1/108 世界单位」**（`Px(px) = px / 108`）；
  2. `Shell/MenuDraw.cs:25-26`：`Local(parent,…) = LayoutSpace.RectCenter(px 矩形) − parent.position` —— 减的是**世界坐标**，
     而 `Node()`（`:47-53`）把它的返回值**直接**赋给 `localPosition` ⇒ 这套树里 `localPosition` 就是世界单位；
  3. **同工程同形状的对照组**：`Battle/BattleLogPanel.cs:493-501`（另一处面板滑动，已验收过）显式换算
     `LayoutSpace.ToWorld(xPx / 1920f, 0.5f).x` 再写 `localPosition` —— 正是本处缺的那一步。
  另：`Editor/CollectionScene.cs:116`（`PxOf(worldX) = worldX * 108f + 960f`）说明自检也按「1 单位 = 108 px」折算。
- **后果**：收起位 = `BasePos − 550 世界单位` = **−59,400 px**（不是 −550 px）。Play 里抽屉在 0.3 秒的**前 ~0.6%**（≈2 ms）
  就飞出屏幕 ⇒ **「滑入动画」实际看不见，等于原来的硬切**；反过来打开时它在 0.3 秒的**最后 0.6%** 才进场。
  而**命中/滚轮那 0.3 秒照样是全失效的**（`Interactive` 要到 `Slide==1` 才 true）⇒ 玩家实际感受到的是
  「点了 Filters，抽屉瞬现，但这 0.3 秒里点它/滚它都没反应」。
- 该照哪个判据：铁律 3（照解包参数复刻）· 判据原文 `资料/待办判据_卡面卡池与双语.md:237`（`DOAnchorPosX(rect, x, 0.3)`
  改的是 **`anchoredPosition` = px**）。**修法**：`lp.x += LayoutSpace.Px(FltHiddenDx) * (1f - p.Slide);`
  （或照 `BattleLogPanel` 那条 `ToWorld` 换算），**别**让 px 值裸进 `localPosition`。
