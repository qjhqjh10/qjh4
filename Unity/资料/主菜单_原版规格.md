## 三、① 「3D 背景」那块 —— **结论与汇总 §1b 相反**

**实测（raw JSON）**：`Background Render Texture Holder`（RT1118, GO 42）**没有子节点**，组件只有 `CanvasRenderer` + `MB1976` + `MB1977`：
- `MB1977` = **RawImage**（有 `m_Texture / m_UVRect`），**`m_Texture = {fileID 0, pathID 0} ⇒ 出厂无贴图**，`m_Color` 白，`m_RaycastTarget=0`；节点 a(0,0)-(1,1) sz(0,0) = **整屏拉伸**。
- `MB1976`（script `5861345434818698247`，字段名 `cameraToBake / image / blitBlurMaterial`）：`cameraToBake = **602**`（**就是 UI Camera**）、
  `image = 1977`（同一 GO 上的 RawImage）、`blitBlurMaterial = {fileID 5, pathID 3}`（本包 `Material/Material_3.json` = **`UI Blur`**）。
  内层 MainMenu 的窗口控制器 `MB1927` 也把 `screenBaker = MB1976` 挂在自己身上。

**相机（`Cam/602` = UI Camera, GO 47）**：`m_Enabled=1` · `m_ClearFlags=2`(SolidColor) · `m_BackGroundColor=(0,0,0, 0.0196)` ·
**`orthographic=false`** · **`field of view=40`** · near **0.3** / far **1000** · `m_Depth=-1` ·
**`m_CullingMask.m_Bits=32`（只渲染 layer 5 = UI**；本包 674/696 个 GO 在 layer5，只有 5 个管理器在 layer0）·
**`m_TargetTexture = pathID 0 ⇒ 不渲到 RT`** · HDR/MSAA **全关** · viewport 全屏。
它是 `Canvas1077`（Game UI）的 ScreenSpaceCamera 相机。

**反证「3D→RT」**（四条）：
1. 全包**没有任何 RenderTexture 资源**（24 个类型目录里没有 `RenderTexture`），也没有 `m_TargetTexture != 0` 的相机；

#### 🔴 背景渐变的角度约定 —— **我们画反过（2026-09-27 查实并修）**

原版那个 `MB1931` 不是自研组件，是 **Asset Store 那个知名的 `UIGradient : BaseMeshEffect`**
（`dump.cs` 里带 `[AddComponentMenu("UI/Effects/Gradient")]`，字段 = `m_color1` / `m_color2` / `[Range(-180,180)] m_angle` / `m_ignoreRatio`）。

🔴 **它的【有效方向轴】是 `(sin θ, cos θ)`，不是 `(cos θ, sin θ)`**。
**我们工程里的 `CardArt.Gradient` 用的是 `(cos, sin)`** ⇒
**同一个 82 直接传进去，画出来的方向差 90°**。

> ⚠️ **2026-10-11 更正（A320 · 铁律 5）**：这里原来接着写「`decomp_full/UIGradientUtils__RotationDir.c` 返回 `CONCAT44(uVar2, uVar1)`（x = uVar1, y = uVar2）」**当作「返回 `(sin,cos)`」的判据 —— 那半句是错的**。
> **实读**：`RotationDir(θ)` **返回的是 `(cos θ, sin θ)`**（`FUN_180488130 = Mathf.Cos` · `FUN_1804886e0 = Mathf.Sin`；
> 判据 = `Easing__…inOutSine_0_30` / `…outSine_0_29` 两支 + `RotatePointAroundPivotUVs.c` 的标准旋转 + `UIGradient__ModifyMesh.c:77-78` 的内联处）。
> **但结论不变**：有效轴仍是 `(sin,cos)` —— 因为 `UIGradient__ModifyMesh.c:148-149` 的梯度参数是
> `pos.y·(dir.x/size.y) + pos.x·(dir.y/size.x)` ⇒ **`dir.x`(cos) 配 `y`、`dir.y`(sin) 配 `x`**（**转置着用**）。
> **错因**：拿「函数返回值」当「屏幕上的轴」，中间漏了 `ModifyMesh` 那一步。
> ⇒ **「差 90°」与「主菜单背景传 188°」两条都还成立、⛔ 别推翻**；下面那张实测场是**不依赖任何函数读法**的最终判据。
> 出处：`资料/普查产出_1011/审查_W1.md` §R1 · `资料/普查产出_1011/F1_W1修复.md` §五。

**实测场**（⚠️ **拿 `00_主菜单_无弹窗.png` 比，别拿 `01_主菜单.png`** —— 那一张里**开着一个社交窗**，

## 八、🔴 更正：那张原版实拍**不能当亮度/颜色的尺子**

`menu_roots/001_ActionScheduler.png` 是**原版初始化失败状态**（中间弹着「无法初始化服务 Game UI」）。

**不能判亮度、不能判颜色**。要判颜色，只能读 `m_Color` / 顶点色（§七）与 `m_fontColor`。

⚠️ 顺带记一条**我们自己犯的错**（已纠）：第一版给 `Resources Bar` **凭空加了一层背景图**
