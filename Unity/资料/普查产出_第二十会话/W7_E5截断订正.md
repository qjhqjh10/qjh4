## 一、截断是怎么发生的（判据 + 一条可复现命令）

### 1·1 两样东西：**工装**（`Esc5Driver.cs`）与**输入**（`texts.tsv`）

### 1·2 根因：**`desc` 里的真换行没被转义**

驱动那一侧的口径本来就是「用 `\n` 两个字面字符代表换行」——
`Esc5Driver.cs:30` 明写 `Desc = p[2].Replace("\\n", "\n")`，即**读进来才把字面 `\n` 换成真换行**。
而那份 TSV 的生成器**把真换行直接写了出去**（`SOR2` 的 `desc` 变成三个物理行）。

驱动那一侧的载入是 `Esc5Driver.cs:25-31`：

```csharp
foreach (var ln in File.ReadAllLines(tsv, Encoding.UTF8))
{
    if (ln.Length == 0) continue;
    var p = ln.Split('\t');
    if (p.Length < 3) continue;                       // ← 闸在【3】，不是 4
    list.Add(new Row { Id = p[0], Type = p[1],
        Desc = p[2].Replace("\\n", "\n"),
        Kw = p.Length > 3 ? p[3] : "" });             // ← 只有 >3 段才有关键词
}
```

**字段数直方图**（现读 `D:/tmp/wf_e5/texts.tsv`）：

| 字段数 | 行数 | 是什么 |
|---|---|---|
| 4 | **1102** | 正常的卡（desc 单行） |
| **3** | **24** | 🔴 **被截断那张卡的【首行】**——desc 只到第一个换行为止，`Kw` 落空 |
| **2** | **24** | 被截断那张卡的**最后一行**（这一行的尾巴上挂着 keywords 那一列） |
| 1 | **2** | 被截断那张卡**中间的**续行（`SOR2` / `SOR40` 各一行，纯 desc、后面没挂东西） |
| 合计 | **1152** | 池是 **1126** 张 ⇒ 多出 26 行 = 26 个换行 |

### 1·3 🔴 症状要订正：**不是「整行被丢」，是「desc 截到第一句 + 关键词整条掉」**

`A1592` 账文（`任务_卡组卡牌战斗.md:51`）与 `W1_信仰阈值落地.md:44-47` 都写成
「第二行起被 `Split('\t')` 判成「字段不足」**静默丢弃**」——**方向对、细节错**：

| 谁 | 判定 | 后果 |
|---|---|---|
| **续行**（1 段 / 2 段） | `p.Length < 3` ⇒ **真的被丢** | 那几句 `desc` 消失 |
| **首行**（3 段） | `3 >= 3` ⇒ **留下了** | desc 只剩第一句；`p.Length > 3` 不成立 ⇒ **`Kw = ""`（这张卡的 `keywords` 整条掉）** |

⇒ **没有一张卡「整张消失」**（驱动侧仍载入 **1126** 条、唯一 id **1126** 个），
错的是那 24 张的**内容**：**desc 被砍 + keywords 被清空**。
🔴 这条要就地订正（阈值是 **3**、症状是「截断 + 掉关键词」）；**结论不变**：24 张被截断。

### 1·4 反证：这份 TSV 的**内容源**其实是对的 —— 错只错在换行没转义

（这条很重要：**不需要怀疑 E5 用了另一份卡池**。）
