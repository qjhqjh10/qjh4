# 战斗 UI 位置核对（2026-09-13）

> 起因：用户发现**里程碑骷髅压住了名牌文字**，并要求「举一反三，全面检查战斗界面上这些按钮/图标的位置是否正确」。
> 根因不是骷髅 —— 是**名牌的位置本身抄错了实例**。于是把所有可见元素按**绝对矩形**重对了一遍。

## 图

`对齐核对_原版矩形vs我们.png` —— 在我们自己的对局截图上，**画出原版每个元素的绝对矩形**，
一眼就能看出对齐没对齐。框的颜色分组：红=名牌、绿=骷髅与分数、蓝=牌堆与张数底板、
黄=回合灯、橙=已出牌数三枚、紫=能量水晶、青=END TURN 与设置钮。

**怎么看这张图**：每个元素都落在对应框内 = 位置对。注意几个**原版刻意的溢出**，
别当成我们摆错了：名牌实绘左缘在 **−11.4**（贴屏幕左缘、出血 11 px）、
骷髅**翘在名牌上沿之外** 21.9 px、能量区大底板右侧出血 160 px。

> ⚠️ **为什么用「字段里的绝对矩形」当尺子而不是原版截图**：原版的真渲图里**没有 HUD**
> （HUD 要对局数据才出得来，原版已关服、手牌注入不了），所以这里没有并排截图可比 ——
> 尺子只能取原版 RT/MonoBehaviour 里的绝对矩形。出处全部列在
> `资料/战斗UI_原版对账表.md` §三点五 与那份表的每一行。

## 复现这张图

```python
# 1) 跑一次对战自检，拿截图： d:/4/_tmp_view/battle/01b_版面.png
# 2) 把原版绝对矩形画上去（y 从上）：
from PIL import Image, ImageDraw
im = Image.open('_tmp_view/battle/01b_版面.png').convert('RGB'); d = ImageDraw.Draw(im)
for (x0,y0,x1,y1), c in [((-11.4,951.4,370.9,1077.7),(255,80,80)),   # 名牌(我)
                         ((168.9,929.5,217.9,983.7),(80,255,120)),   # 骷髅
                         ((1615,850,1845,1080),(120,180,255)),       # 我牌堆
                         ((1801.5,967.4,1825.3,1003.0),(255,230,80)),# 回合灯
                         ((13.5,548.2,91.5,568.2),(255,150,40))]:    # 已出牌数三枚
    d.rectangle([x0,y0,x1,y1], outline=c, width=3)
im.save('对齐核对.png')
```

## 结论（两处位置错，都已修 + 加了断言）

| 元素 | 原来 | 原版 | 错因 |
|---|---|---|---|
| **督军名牌（我）** | 左缘 x=32.6、中心 y_top 977.4 | 左缘 **−11.4**、中心 **1014.55** | 抄了 `FrontCanvas/Alliance Panel` 底下**另一份 inactive 实例**的坐标 |
| **督军名牌（敌）** | 左缘 x=157.4、中心 y_top 108 | 左缘 **−11.2**、中心 **78.75** | 同上（**偏了 ~168 px**，一眼可见） |
| **名牌文字** | 左对齐 | **居中**（原版 H=2） | 同上 |
| **牌堆回合灯** | 相对牌堆中心 (75.6, −86) | **(83.46, −20.2)**（敌 (73.6,−9)） | 只按锚点矩形折算，**漏了 `anchoredPosition (7.9,65.8)`** |

**顺带治好了骷髅压字**：名牌下移 37 px 之后，骷髅正好落在文字上方 —— 原版也是「骷髅翘在名牌上沿之外」。
