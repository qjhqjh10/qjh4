## `特效_抓屏扭曲/` —— P1-a0 的证据（2026-09-12）

**要证明的事**：台账里那条「`Spore Explosion` 原版 4612 亮点 / 导出 0 ⇒ 抓屏扭曲的材质不等价」
**是不是真的资产差异**。结论是**不是** —— 原版在没内容可扭曲的空场景里画的是一块**恒定半透明灰方块**
（采到一张没绑定的默认灰贴图），跟背景、跟渲染队列都无关。

**重跑**：`-executeMethod DistortProbe.Run`（自带 26 条断言，输出到 `d:/4/_tmp_view/distort/`）

**怎么读这些图**（文件名格式 `Spore Explosion_<背景>_<组合>.png`）：

| 背景 | 说明 |
|---|---|
| `黑` / `中灰` / `白` | 纯色 clear。**关键看点：原版在三种背景下输出的是同一个恒定值**（黑底上和背景差 0.239、白底上差 0.922、中灰底上**正好等于背景**）—— 说明它采的不是背景 |
| `棋盘` | 背后放一块**不透明棋盘 quad**。原版把棋盘**透出来但冲淡了**（min 0.239 / max 0.922），不是扭曲位移 |
| `棋盘_透明队列_*` | 把材质**强制排进透明队列**（让 URP 的 `_CameraOpaqueTexture` 真的装上棋盘）再拍一遍。**原版的输出一个像素都没变** —— 这是「它根本不读那张纹理」的决定性证据 |

四种组合 = prefab（原版/导出）× 材质（原版/导出）。`导出prefab+原版材质` 与 `原版prefab+原版材质`
看起来一样 ⇒ 问题在**材质侧**，不在 prefab 侧。

> ⚠️ 这些图**不能**当「我们的扭曲做得对不对」的验收依据 —— 它们证明的是「那把尺子量不了这个」。
> 真正该做的验收是**在有内容可扭曲的场景里比**（见交接文档 P1-a0 的下一步）。

## `卡面组装_0912/` —— 卡面重做的证据（2026-09-12）

**背景**：用户指出「卡框没包住插图」。查下来是我们**把立绘裁进了一个矩形窗口**，而那个窗口
是**拱形**的（对卡框 alpha 做膨胀 + flood fill 量的），立绘的直角顶出拱形、窗口以外还不画立绘。
原版的正解是「**立绘铺满并溢出、卡框的 alpha 当遮罩切掉多余的**」
（`资料/战斗规格/战斗重建_0827/子代理读报_2dcard_0827.md:310`）。

| 文件 | 证明什么 |
|---|---|
| `side.png` | **改造前**：左=原版卡面，右=我们（立绘只占中间一条窄矩形、直角顶出拱形、卡下半截没画） |
| `final3.png` | **改造后**：同一处对比 —— 立绘铺满、卡框盖在上面，和原版同构 |
| `tier_map.png` | **稀有度 → 卡框档位的映射**是实测的：上排四张原版卡面（common/rare/epic/legendary），下排四张 tier 框，tier1 素框 / tier2 加尖塔 / tier3 加两侧骑士像 / tier4 金蓝华丽，一一对应 |
| `tiers.png` | 四档 troop 框长什么样（并排） |
| `gems.png` | **「卡框分档」和「底部稀有度宝石」是两件事**：上排原版卡面的宝石是**彩色**（浅蓝/绿/紫/金），下排我们四档框的同一位置**都是空的暗色凹槽** —— 颜色来自另外叠的那张宝石（`1_40k_cardframe_rarity_*` 5 张） |
| `gem_sprites.png` | 那 5 张宝石贴图（common 浅蓝 / rare 绿 / epic 紫 / legendary 金 / special 橙红） |

**重跑**：`-executeMethod BattleScene.Run`（197 条断言，图在 `d:/4/_tmp_view/battle/`）、
`-executeMethod DeckScene.Run`（61 条，图在 `_tmp_view/deck/`）。
证据图本身是**手工拼的**（PIL），没有脚本 —— 要复现就照上面每张的「证明什么」重新拼一次。

**为什么留**：#1 和 #2 是一对**改造前/后**的对照，是「这次改对了没有」的唯一直接证据；
#3/#5 是**从资源里推出来的结论**（资源里没有白纸黑字写「tier1=common」），
别人要质疑这个映射时，得能一眼看到它是怎么对上的。

> ⚠️ 卡面**尺寸**的权威来源不是这些图，是 `子代理读报_2dcard_0827.md` 的 A2 表（卡本体 2.0927×3.3313、
> 卡框 2.2452×3.2572@y−0.03、立绘矩形 2.7484²@y−0.044、稀有度宝石 0.4×0.4@(0,−1.458)）。

## `卡表核对_0912/` —— 卡面数值 / 宝石色的读数证据（2026-09-12）

**背景**：用户要求「直接看卡面图」来定卡表里对不上的字段。两张拼图是**当场读数的记录**，
用来支撑 `工具/gen_cards_engine.py` 里 `STAT_FIXES` / `RARITY_UNLISTED` 表里那几条修正。
完整对账过程见 `资料/卡牌数据源对账_0912.md`。

| 文件 | 证明什么 |
|---|---|
| `卡面四数值_读数核对.png` | **卡面四个圆各是什么**（横排四张卡的底部条）：左起红=近战、紫=**远程**、右绿=生命，右侧那枚**盾牌才是护甲**。这张图是「那份 0824 卡表的『甲』列 = 远程攻击」这个结论的现场证据（列头写错了），也证明 Baneblade 的紫圆是 **12** 而不是我们记的 2 |
| `破坏卡宝石色_浅蓝common.png` | `Genestealer Cult/6破坏卡` 那 4 张（手机翻拍）底部宝石全是**浅蓝 = common** —— 这 4 张不在三份 0824 卡表里，稀有度只能这么定 |

**重跑**：没有脚本，是 PIL 现拼的（做法：横排裁每张卡的底部条再拼）。
原图在 `D:/2/Warpforge部队卡片/`，**不在仓库里**（原版资产）。

**为什么留**：这两条结论**没法用断言表达**（「列头写错了」是文档层面的判断），
而它们各自改动了卡表里的真实数据（Baneblade 的 `ranged` 2 → 12、9 张卡的稀有度）。
以后有人质疑「凭什么是 12」，翻出这张图就能对上。
