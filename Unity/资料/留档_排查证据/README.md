## `特效_抓屏扭曲/` —— P1-a0 的证据（2026-09-12）

**要证明的事**：台账里那条「`Spore Explosion` 原版 4612 亮点 / 导出 0 ⇒ 抓屏扭曲的材质不等价」
**是不是真的资产差异**。结论是**不是** —— 原版在没内容可扭曲的空场景里画的是一块**恒定半透明灰方块**
（采到一张没绑定的默认灰贴图），跟背景、跟渲染队列都无关。

**重跑**：`-executeMethod DistortProbe.Run`（自带 26 条断言，输出到 `d:/4/_tmp_view/distort/`）

**怎么读这些图**（文件名格式 `Spore Explosion_<背景>_<组合>.png`）：

| 背景 | 说明 |
|---|---|
| `黑` / `中灰` / `白` | 纯色 clear。**关键看点：原版在三种背景下输出的是同一个恒定值**（黑底上和背景差 0.239、白底上差 0.922、中灰底上**正好等于背景**）—— 说明它采的不是背景 |
| `棋盘` | 背后放一块**不透明棋盘 quad**。原版把棋盘**透出来但冲淡了**（min 0.239 / max 0.922），不是扭曲位移 |
| `棋盘_透明队列_*` | 把材质**强制排进透明队列**（让 URP 的 `_CameraOpaqueTexture` 真的装上棋盘）再拍一遍。**原版的输出一个像素都没变** —— 这是「它根本不读那张纹理」的决定性证据 |

四种组合 = prefab（原版/导出）× 材质（原版/导出）。`导出prefab+原版材质` 与 `原版prefab+原版材质`
看起来一样 ⇒ 问题在**材质侧**，不在 prefab 侧。

> ⚠️ 这些图**不能**当「我们的扭曲做得对不对」的验收依据 —— 它们证明的是「那把尺子量不了这个」。
> 真正该做的验收是**在有内容可扭曲的场景里比**（见交接文档 P1-a0 的下一步）。
