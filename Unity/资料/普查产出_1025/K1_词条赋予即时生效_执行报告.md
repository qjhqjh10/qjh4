# K1 —「词条被赋予之后是否即时生效」执行报告（2026-10-25）

> 起因 = 用户真机报告：**给一个部队加上「侧翼」(Flank) 词条，该部队当回合仍然不能进攻**。
> 本文按「结论 → 判据 → 改动清单 → 断言 → 没查清 → 顺手发现」写。

## 一、结论（一句话）

**原版【会】即时生效** —— 加/摘 `fast`/`flank` 都会走
`AddEffect/RemoveTrait → UpdateSummonSicknessAnims → ActivateMinion` 重新算 `canAct`/`canAttack` 两位；
我们原来**只在「部署那一刻」算过一次**、之后再没人重算 ⇒ **用户报的是真缺陷**。
已按原版口径把重算收进**关键词变更的唯一入口**（`UnitState.AddKeyword` / `UnitState.RemoveAll`），
判据只写一处（`RuleCore.RecomputeActAndAttack`），并补了三条断言（含两条灭自证）。

## 六、没查清的部分（如实标着，已写进代码注释）

1. **光环给/收 `fast`·`flank` 要不要重算** —— 原版光环关键词走哪条路**没读到实据**
   （`AddTraitSilently` 明确**不重算**；`UpdateWhileInPlay` 那一支只读到名字、没读到方法体）。
   ⇒ 本次**故意没接** `AddAuraKeyword` / `ClearAuraGrants`（接了可能与原版相反）。
   **还差**：`CardScript__UpdateWhileInPlay*` / 光环收发的实据（谁调 `AddTraitSilently`、调用点在哪）。
   池内那 4 张 `give flank` 的光环卡（`AM73` · `DA30` · `EC8` · `TAU31`）今天仍靠
   **部署那一刻**的 `ApplyDeployTurnState` 兜住（落地即侧翼 ⇒ 本来就没问题）；
   只有「已上场的单位，中途因光环重算才拿到侧翼」这一格没覆盖。
2. **原版两道守卫无对象可复刻**：`isPlayer == isPlayerTurn`（`ActivateMinion.c:18/:50`）与
   `+0x228 == 2`（cardState = 在场）。`Core/` 没有「本机/对手」与 cardState 概念。
   已论证**无可观察差异**（对手回合本来就 `ErrNotTurn`；未上场窗口只有 `ApplyHandBuffs`→
   `ApplyDeployTurnState` 同一拍内），写进了 `RecomputeActAndAttack` 的 doc。
3. **`actedOut` 不写进 `CannotAttackThisTurn`** —— 刻意的收窄（我们 `CanAttackNow` 自己就有配额闸；
   写进去会把「清 `Exhausted` 换额外行动」那类效果连攻击一起禁掉）。doc 里标了原因，等调度台若要 1:1 可再议。

## 七、顺手发现（⛔ 未改，只报）

1. 🔴 **`UnitState.Has()` 判的是 `ContainsKey`**（`UnitState.cs:806`），不判值 ⇒ `AddKeyword(kw, 0)`
   会给「0 值关键词」**建键**，`Has` 立刻变真。`EffectResolver.ApplyOneGain` 的关键词支是 `if (val >= 0) AddKeyword(...)`
   ⇒ 一条「空给（`give 0 X`）」会**静默把 X 算成有**。既有缺陷、与本次无关，建议单开一条。
2. **简报/`CLAUDE.md` 说 `RuleCore.cs` / `RuleEngineTest.cs` 是 CRLF —— 实测不成立**：
   `git show HEAD:` 现读 `RuleCore.cs` = **13,226 行全 LF**、`UnitState.cs` = 1,470 行全 LF；
   而 `RuleEngineTest.cs` / `RuleEngineTest_Diag.cs` 确实是 **CRLF / LF**（各按原样保留，`git diff --numstat` 已核，
   没有整篇翻转）。建议调度台订正那句口径。
3. `Unity/MyGame/Assets/RuleEngine/Core/EffectResolver.cs` 里 **2026-10-25 有另一个代理（`X3`）在改 `ward` 那一半**
   （`AddSide` 的 `stealthGate`）。我**没有碰那个文件**；本报告里的 typecheck / ruleprobe 读数是在它那笔改动
   已经在盘上的状态下取的（0 错），但如果它随后又改，**读数需重取**。
4. `RuleCore.cs` 里 `ResetSummonSickness` 的旧注释把 `+0x48` 读作「已行动计数」；本次把它与
   `AttacksThisTurn` 对齐使用（两者语义一致：攻/技能/替代行动都 ++）。若将来发现原版 `+0x48`
   只计**攻击**、不计技能，那 `ActionQuota` 那一句要按新判据收窄（现在**没有**反证）。
