## 一、结论（三句，都可以复算）

1. **压暗层没有漏、也没被绕过。** 同一相机、同一局面取「关压暗 / 开压暗」成对帧，逐像素相除：
   **线性光透过率 = 0.199–0.200**（全画面各干净窗口的中位都是 0.199/0.200，见 §2.3）——
   `1 − 0.8` 一分不差。所以「背景比原版亮」**不是**「背景没被压到」。
2. **真因 = 色彩空间。** **原版工程是 Gamma（`ColorSpace.Gamma`），我们是 Linear** ⇒
   原版那 `onAlphaLevel = 0.8` 的语义是「**显示空间（已经 sRGB 编码过的画面）**上 ×0.2」；
   我们的世界 quad 在**线性光**里混 ⇒ 同一个 0.8 得到的是「**线性** ×0.2」，换算到显示空间约 **0.48**，
   于是背景比原版亮一倍多。§2.2 用原版实拍把两个模型并排算了一遍，γ 模型对上、线性模型差一倍。
3. **台账那个 56–74 vs 11–22 还叠了第二层误差：两边不是同一个战场。** 我们那局的测试战场是
   **Aeldari**（13 场里最亮的之一，原版实拍 p95 225），原版那两张换牌实拍是 **Genestealers / Astra Militarum**
   （p95 104 / 149）。同一 α 下，Aeldari 的换牌背景 p95 本来就该比 Genestealers 高 ≈2.5 倍。
   ⇒ **这条指标不能跨场比**；§2.4 给了逐场数字。

**落地的改法**：把原版的「**γ 空间**透过率 0.2」**换算成等效的线性透过率**写进压暗层
（`ShadeAlpha` = 1 − 0.055 = **0.945**，按工程的 `activeColorSpace` 分支，将来整体切 Gamma 会自动回 0.8）。
13 场逐场对原版实拍复核：换牌背景 p95 从「+80%…+141%」收到「**−3% … +27%**」（§四那张表）。
⚠️ 这是**色彩空间补偿**（与 `W63` 那个 `OutlineGlowScale = 1.35` 同族），**不是原版参数**；
理想解见 §七。

唯一不对的是**这个 0.2 落在哪个空间**。

⇒ **背景在显示空间只降到 0.45**，而原版是 **0.20** —— 这就是「背景比原版亮一倍多」的实拍指纹，
和 §2.2 的模型完全一致。改成 `ShadeTransmittanceLinear = 0.055` 后，同一套统计的期望是
**p10 ≈0.12 / 中位 ≈0.20 / p90 ≈0.24**（13 场逐场算过，全部落在 0.08–0.30 窗内）。

| Space Wolves | 107.2 | Astra Militarum | 53.1 |

台账那句「56–74 vs 11–22」里，**至少一半是跨场差**，另一半才是色彩空间。

### 4.2 为什么取 0.055（不是 `0.2^2.2 = 0.0289`）

理想映射是**逐像素** `L → lin(0.2 · srgb(L))`。**单靠一个常数 alpha 做不到**：
需要的系数在暗端（sRGB 的线性段）是 **0.2**、在亮端（幂律段）趋近 **0.2^2.2 = 0.029**。
按 **13 场原版实拍 × 4 个背景窗的 p95** 拟合（RMS 对数误差最小）得 **k = 0.055**（α = 0.945）。
逐场复核（换牌背景 p95，γ 模型 = 原版口径）：

| 场 | γ 目标 p95 | 改前 k=0.2（α0.8） | 改后 k=0.055（α0.945） | 改后/目标 |
|---|---|---|---|---|
| Battle_Arena_1 | 27.2 | 62.8 | 30.8 | +13% |
| Battle_Arena_2 | 24.1 | 54.7 | 26.1 | +8% |
| Battle_Arena_3 | 19.3 | 42.5 | 19.0 | −1% |
| Battle_Arena_Aeldari | 34.3 | 80.8 | 41.4 | +21% |
| Battle_Arena_Astra_Militarum | 23.5 | 53.1 | 25.2 | +7% |
| Battle_Arena_Black_Legion | 18.1 | 39.5 | 17.6 | −3% |
| Battle_Arena_Dark_Angels | 27.3 | 62.8 | 30.9 | +13% |
| Battle_Arena_Emperors_Children | 25.3 | 57.9 | 28.0 | +10% |
| Battle_Arena_Genestealers | 19.1 | 41.9 | 18.6 | −2% |
| Battle_Arena_Leviathan | 20.6 | 45.8 | 20.9 | +2% |
| Battle_Arena_Sororitas | 20.0 | 44.3 | 20.0 | +0% |
| Battle_Arena_Space_Wolves | 44.6 | 107.2 | 56.7 | +27% |
| Battle_Arena_Tau_Viorla | 34.8 | 82.1 | 42.1 | +21% |

（残差整体：**中位 +8%、范围 −3%…+27%**；对照改前 **+80%…+141%**。）

### 4.3 影响面

- **换牌卡**：在压暗层**之上**（队列 3007 > 3006）⇒ α 怎么变都碰不到它。
- **正常战斗**：压暗层关着 ⇒ 零影响（新加的负例断言盯着）。
- **画布 HUD**（提示行/按钮/眼睛/继续）：`OverHand` 排序层 ⇒ 压暗层压不到。
- **选牌面板（追加单）**：候选卡同样在压暗层之上（`QChoiceCard 3007 > QChoiceShade 3006`，AU2 已修）⇒
  α 变化只影响**背景**；面板收起时 `SetVisible(false)` 联动关压暗（`R7⑧` 盯着）。

### 6.3 p95 怎么算（判据必须同场、且按**显示值**比）

```python
# 背景窗（归一化坐标，和 §2.2 同一批）
WINS = [('botL',.02,.24,.75,.99), ('topR',.78,.98,.02,.26),
        ('topL',.02,.24,.02,.26), ('botR',.76,.98,.75,.99)]
import numpy as np
from PIL import Image
def lum(p):
    a = np.asarray(Image.open(p).convert('RGB'), dtype=np.float32)/255.0
    return a.mean(axis=2)                      # ⚠️ 直接比显示值（原版是 Gamma 工程，见 §2.1）
for name, p in [('ours', OURS_PNG), ('orig', ORIG_PNG)]:
    L = lum(p); H, W = L.shape
    print(name, [round(float(np.percentile(L[int(y0*H):int(y1*H), int(x0*W):int(x1*W)], 95)*255), 1)
                 for _, x0, x1, y0, y1 in WINS])
```
