## 结论（先看这 6 条）

1. 🔴 **数值颜色判据原来是错的（P0，本会话已改）**：原版 `CardTextCountersController` 的颜色比的是
   **「当前值 vs 基准值」**（`DoColorChange(currentValue, baseValue)`），是**持续态** ——
   受伤的生命**一直红**、被 buff 的攻击**一直绿**，回到基准才白。我们 2026-09-29 那版按 **「新 vs 旧」**
   闪一下就刷白，**判据不同**。判据 = 9 参 `SetText` 的指令流（VA `0x18060C180`，本会话用
   `工具/disasm_va.py` 现读）+ `CardTextCountersController__DoColorChange.c` 全文。
2. 🔴 **两套载体原来只做了一套（P1，本会话已改）**：每个数值 counter 的 `textsToSet` 有 **2 件**
   （2D 卡面 `m_fontSize 0.34` + 3D 卡体 `m_fontSize 7/8`，后者带 `highlightAttackType`；**费用只有 1 件**），
   原版对**每一件**都 `set_text` + 复位 `localScale` + `DOPunchScale`、`DoColorChange` 也遍历**每一件**。
   我们原来只对 `CardFace.Board` 那套网格层做 ⇒ **手牌 / 卡池的数值涨落完全无声**（无变色、无 bump）。
3. **简报里那份类名单一半不成立（覆盖面据此重定）**：原版**没有** `CardView` / `CardFrame` / `CardText` /
   `CardImage` / `TraitIcon` / `CardLocalization` 这 6 个类（`dump.cs` 全库 0 命中；`CardUI` 也只是 prefab 名）。
   真正承载卡面的是 **`BasicCardUI`(71) / `BattleCardUI`(81) / `Card2DController`(13) / `CardImageController`(12) /
   `CardTextsController`(10) / `CardTextCountersController`(11) / `CardTraitCollection`(25) / `CardTrait`(12) /
   `BoardTraitIcon`(10) / `HighlightAttackType`(3) / `CardFramesSO`(6) / `CardTierUIController`(3) /
   `CardRarityHolderController`(2) / 三个 `CardTrait*` 子类(2+2+2) / `CardImageScalebyCardTypeSO`(4)** 等 ——
   共 **17 个类 / 269 个方法**；把 `CardTraitData`(6) · `CardRarityColorsSO`(2) · `CardCounterDisplay`(4) ·
   `CardCounter`(1) · `CardDamageCounterController`(3) · `CardBoardElementsController`(3) 一并计入
   = **23 个类 / 288 个方法**（明细见 §①）。
4. **其余重点项逐条核过、结论是「已对上」**（判据在案，不重复抄）：9 个文字态选态、四数值显隐规则、
   关键词图标的**三道闸**（`hasIcon` + `isInPlayIcon` + `traitIcon != null`）、`<nobr>`+`<sprite>`+`<link>` 结构、
   官方正文的四支记号（`((…))`/`$$…$$`/`[[…]]`/`(N)`，**顺序不可换**）、大图 ×1.27 只给 `cardType ∈ {0,10}`、
   战术卡 `cardScales 0.61` + `tacticsOffsetPosition` 双独立轴、伤害飘字（`CardDamageCounterController`）已实现。
5. **新增 4 条账（其中 3 条本会话没动、1 条已修一半，判据都清了）**：费用数字我们**烘在 `_info` 里**
   （原版是第五件真 TMP `CostText`）· 效果文字少一个**尾随换行**（`GetLocalizedCardDescWithLineBreak` 的
   `AppendLine()`）· 卡框遮罩材质原版**也贴到 `textBackground`**（我们没有 SoftMask 体系）·
   🔴 **战术/防御卡底部那行「类型行」的原版键是 `Card_Race/<SpellType 枚举名>`（无空格），我们用的是
   带空格的展示名** ⇒ 键规则本会话已摆正，但**值那一半仍是手写表旧译**（57 张卡，见 §②·D9）。
6. **`CardData.statBasesKnown / base*` 这组字段已就位，但全工程还没有调用点** —— 填它的那一步在
   `BattleDriver.ToCardData`（`Battle/**`，不在本代理文件所有权内）⇒ **持续色今天仍是潜伏的**，
   出厂退回旧近似（见 §③ 的「欠接线」）。

## ② 差异清单

> 每条给：**原版判据** → **我们** → **差在哪** → **优先级**。
> P0 = 用户一眼能看到的静态差别；P1 = 一眼能看到的动态/状态差别；P2 = 细节或结构差异；P3 = 极小。

### D1 · 数值颜色：`current vs base`（持续态）↔ `new vs old`（瞬时）—— **P0 · 本会话已修机制**

- **原版判据**：`CardTextCountersController__DoColorChange.c`（全文）
  ```c
  if (param_2 == param_3) {  /* 刷回 originalColors[i]（= 白） */ }
  else if (statIncreaseIsPositiveToThePlayer == 0)   /* 费用 */
       { param_2 < param_3 ? statIncreaseColor /*(0,1,0)*/ : statDecrease /*(0.9725,0.306,0.353)*/ }
  else                                               /* 近战/远程/生命/护甲 */
       { param_2 > param_3 ? statIncreaseColor : statDecrease }
  ```
  **传进去的是哪两个数**（本会话新查，关键）：9 参 `SetText` 的指令流 VA `0x18060C180`：
  `mov ebx,r9d`(= `baseValue`) · `mov edi,r8d`(= `currentValue`) ·
  `call DoColorChange(this, edx=currentValue, r8d=baseValue)` ⇒ **当前 vs 基准**。
  调用侧印证：`CardScript__UpdateAttackText.c` 传 `(CurrentMeleeAttack, CurrentMeleeAttack, <RawCardScript 的基准近战>)`、
  `UpdateHealthText` 传 `(当前生命, 当前生命, 最大/基准生命)`；四个属性 counter 的
  `statIncreaseIsPositiveToThePlayer = 1`、**费用 counter = 0**（五份 `MonoBehaviour_*.json` 实测）。
- **我们（改前）**：`CaptureStatChanges` 比 `oldV vs newV`，变了就涂一下、下一次刷新刷白；
  只对 `CardFace.Board` 做；费用完全没算。
- **差在哪（用户可见）**：
  · **受伤的兵，生命数字原版一直是红的**（3/5 红、治满才白），我们是「闪一帧红就回白」；
  · **被 buff 的兵，攻击数字原版一直是绿的**，我们同样会回白；
  · **被减费的牌，费用数字原版是绿的**（费用越低越好），我们不做；
  · 建出来就已经受伤的卡（例如复活/复制出来的残血单位），原版第一次就是红的。
- **现行**：基准已知 ⇒ 原版口径；基准未知（**出厂：还没有人填**）⇒ 退回旧近似。见 §③ 与 §结论 6。

### D2 · 数值涨落只在场上那套载体上 —— **P1 · 本会话已修**

- **原版判据**：同一个 9 参 `SetText` 的指令流对 **`textsToSet` 的每一件**都
  `set_text` → `set_localScale(originalScales[i] 或 HighlightAttackType.TargetScale)` →
  `DOPunchScale(基准 × cardTextBumpSize, cardTextBumpTime, vibrato 10, elasticity 2)`；`DoColorChange` 同样遍历每一件。
  而 `textsToSet` 的实测（`bundle_battleprefabs_vfxandmisc_assets_all`，按 TMP 节点名反查）：
  | counter | `textsToSet` | 2D 卡面那件 | 3D 卡体那件 |
  |---|---|---|---|
  | 费用 `…_6320885271709195200` | **1** | `…_0.34`（`CostText`） | —（3D 不印费用） |
  | 远程 `…_-3358613892933444672` | **2** | `m_fontSize 0.34` | `Range Attack Text`，7.0，带高亮 |
  | 生命 `…_1339511855435914176` | **2** | 0.34 | `HealthText`，8.0，带高亮 |
  | 近战 `…_4301255605536791488` | **2** | 0.34 | 7.0，带高亮 |
  | 护甲 `…_576116891963464640` | **2** | 0.34 | `Armour Text`，7.0，带高亮 |
- **我们（改前）**：`FlashStat` 只动 `_stats[s]`（场上网格层）且**要求该层 active**；
  2D 那四件 TMP 只吃 `_tint`（状态色/淡出/灰化），**从不涂涨落色、从不 bump**。
- **现行**：`BumpStat` 按载体分叉（网格层优先、否则 2D TMP），颜色两套都涂（`FaceStatInk` 唯一口）。

### D3 · 费用数字是「烘图」，原版是第五件真 TMP —— **P2 · 记账（未改）**

- **原版判据**：`GameObject/CostText.json` + `MonoBehaviour_-2105138887792092224.json`（真身实读）：
  `TextMeshPro`、`m_fontSize 0.34`（autoSize 0.025–0.34）、`m_fontColor` 白、hAlign `2 (Center)` /
  vAlign `512 (Middle)`、`m_TextWrappingMode 0`（不折行）、材质 `<Patern> Thin Outline`、
  rect `0.456 × 0.42`（= `Cost Container` 的 0.38×0.35 × `CostScale 1.2`）、父链在 `Cost Container` 下。
  它也挂着一个 `CardTextCountersController`（第五个）⇒ **费用变化时同样涂色 + bump**。
- **我们**：费用数字画进 `_info` 贴图（`InfoTexture`），只有底板 `_costBg` 是独立层。
- **差在哪**：费用**变色 / 放大播不出来**（`CardData` 里已有 `baseCost` 与 `_statFlash[StatCost]`，但没载体）；
  字形来源也不同（我们是 `PragatiDigits` 烘的字形表，原版是 TMP `Pragati-Regular` SDF）。
  视觉上 0–9 单个数字差别很小 ⇒ P2，但要真复刻得单独一批（新增第五件 TMP + 两档容器的显隐 + 断言）。

### D4 · 效果文字少一个「尾随换行」 —— **P2 · 记账（未改）**

- **原版判据**：`RawCardScript__GetLocalizedCardDescWithLineBreak.c` = `new StringBuilder(desc)`，
  **`if (Length > 0) AppendLine()`** 然后 `ToString()` ⇒ 正文**多一个 `\n`**；它正是
  `SetCardTextsExcludingStats → CardTextsController.SetTexts → SetDescription` 喂进去的那份串。
- **我们**：直接喂 `d.keywords`（无尾随 `\n`）。
- **差在哪**：`DescTextUnit/Tactic` 是**固定矩形 + `m_VerticalAlignment = Middle`** ⇒ 多一个空行会让
  **整块字上移约半行**（并在 autoSize 下顺带压一点字号）。**这是会动所有卡面文字的量** ⇒
  ⛔ 不顺手改：要先并排比 + 重定 `CardBaseDemo`/`CardFaceProbe` 里所有「墨迹框」期望，单独一批。

### D5 · 卡框遮罩材质原版**也贴到文字底板** —— **P2 · 记账（未改，与 `K1` 同族）**

- **原版判据**：`CardImageController__ToggleMask.c`：`frameMask.enabled = on` 之后，
  `textBackground.material = on ? frameMask.<材料> : null`（字段 `+0x50` 就是 tooltip 写着
  “This is needed so the card image overflows also here” 的 `textBackground`）。
- **我们**：没有 SoftMask 体系（`_artFront` 是近似，`K1` 已把这族的语义记成「`AlphaMask == null` ⇒ 整层淡没」）。
- **顺带**：同一个 `SetImage` 里对 **`cardType == 0x14`（战术）** 还有两支：
  `frameMask.AlphaMask = null` + `frameMask.enabled = false` + `textBackground.material = null`
  ⇒ **战术卡的插图不被卡框遮罩**。这正是 2026-10-24 `M2`「战术插图铺满拱窗」的**机制依据**
  （当时只有 NCC/实拍的经验结论）—— 我们 `ArtClampKindFor` 恒 0 的效果与它同向，**不用改**。

### D6 · 详情窗的「拥有张数」(`CardCounterDisplay`) —— **P2 · 记账（不属本代理文件）**

- **原版判据**：`CardDisplayOptions`（`CardDisplayWindow.ShowCard` 里初始化）含 `counterDisplay`；
  `CardCounterDisplay.Initialize(card)` 用 `InventoryManager.GetOwnedCount` + `GetMaxCopiesInDeck`，

- **我们**：`Shell/CardDetailPopup.cs` 没有这件。⇒ **界面线账**（我的文件白名单里没有 `Shell/**`）。

### D7 · 关键词段「没有图」那支少 `<nobr>` —— **P3 · 本会话已修**

- **原版判据**：`GameStaticData__TraitNameToString.c` 两条分支（粗体 / 非粗体）**都**是
  `Concat("<nobr>…", …, "</nobr>")`，包的是「图标 + 词」整项（`0x184237e80` = `<nobr>`、
  `0x1842cf8e8` = `</nobr>`；粗体那支中间多一个 `<b>`）。
- **我们（改前）**：有图那支包了 `<nobr>`，**认不出图那支没包** ⇒ 同段里那些词可能被 TMP 拆到下一行、
  与其它词**不在同一行**。
- **现行**：两支都包（`CardText.cs:393`）。

### D9 · 战术/防御卡的「类型行」：键与中文值都不符原版 —— **P1 · 键规则已修（值那一半记账）**

- **原版判据（一手，两条一起读）**：
  · `GameStaticData__CardRaceToString.c` —— `cardType == 0x14`（战术/防御）那一支 =
    `name = Enum.ToString(spellType@0x90)` → `GetTranslation("Card_Race/" + name)`；
    `spellType == 0` ⇒ **返回空串**；
  · `CardTextsController__SetTexts.c` / `SetDescription.c` / `SetCardTextLayout.c` 三处同一条：
    战术卡的文字态 = `3 + (spellType != 0)` ⇒ **`spellType != 0` 才印那一行**；
  · `SpellType` 成员名见 `dump.cs` 的 `enum SpellType`：`PsychicPower 90` / `CombatElixir 260` /
    `Genomic 240` / `OverlordPower 180` / `MarkOfChaos 190` / `DefensiveCard 210` / …（**全部无空格**）。
- **我们（改前）**：`RaceTerm(subtype)` → 键 = `Card_Race/` + **卡表展示名（带空格）**。
