## 一、真机那条事故的复盘（任务 ③·b：找出真正吃这一下的节点与分支）

### 1·1 现场证据

`_tmp_view/player/shell_probe2.log:6831-6832`（同一帧两行，一一对应）：

```
[CardPresentation] Release：指针世界 (-1.12,-0.67) · 卡在 (-1.00,-1.07,-1.10) · 抓取偏移 (0.13,-0.39) · 拖动中=False
[CardPresentation] 落位：Hand_Light Cover → 战术卡打向 3
```

同一段日志里 `拖动中=False` 一共出现 **5 次**（`:6778 / 6831 / 6960 / 7002 / 7060`），而那 5 次**每一次都紧跟着一行 `落位：…`**（也就是每一次都真的把牌打出去了）。

### 1·2 真正吃下这一下的节点

| 环节 | 结论 | 证据 |
|---|---|---|
| 谁处理的 | **`CardInteraction.Release`**（`Hand/CardInteraction.cs:1304`）—— **手牌层** | 日志行就是它打的（`:1338`）；下一行 `落位：…` 也在它里面（`:1403`） |
| 当时在不在拖拽态 | **在**。`Release` 全仓只有两个调用点，**两个都带 `_dragging != null` 前置**：`TickInput`（`:684`）与 `SimulateRelease`（`:1697`）⇒ 能进到 `Release` 就**必然**在拖拽态 | `Hand/CardInteraction.cs:684 / 1703 / 1304` |
| 为什么日志写 False | **改前**那一行是 `… · 拖动中={_dragging != null}`，而**上一句刚把 `_dragging` 置 null**（老 `:1196`）⇒ **恒 False** | 老代码顺序：`_dragging = null;` → … → `Debug.Log(… _dragging != null)` |
| 是不是「场上按压被错认成手牌」 | **不是**。`card.name = "Hand_Light Cover"` 是**手牌视图**（`BattleDriver.SyncHand` 建的那批，名字带 `Hand_` 前缀）；棋盘单位视图在 `_myUnits` / `_foeUnits` 两张表里，**从不进 `_cards`**，而手牌命中只扫 `_cards` | `CardInteraction.HitTest`（`:1573`）→ `Frontmost(_cards, …)`（`:1532`） |
| 第二条独立佐证 | 那一行里 `卡在 (…, -1.10)`，**z = −1.10 = 手牌层**（棋盘单位的 z 在另一档） | 同上日志行 |

⇒ **那一下真的是「拖一张手牌战术卡，打向 3 号格」的正常出牌。** 测试者只是被 `拖动中=False` 骗了（《真机批量验收_第七十七会话》§二 编号 14 那一行据此写的「待诊断」）。
