### 2 `minionMovementInfo` 的三轴旋转 —— **轴 = 世界 X/Y/Z（right/up/forward）；连乘顺序 = `qX * qY * qZ * startRotation`**

- **判据结论**：

  **① 三个（四个）静态 `Vector3` 常量的初值 —— 已解，不用再跑原版探针**

  `d:/2/tools/il2cpp_out/il2cpp.h:5149-5160` 给出 `UnityEngine.Vector3_StaticFields` 的**声明顺序**
  （每个 `Vector3_o` = 12 字节，`il2cpp.h:5126`）：

  | 偏移 | 字段 | 值 |
  |---|---|---|
  | +0x00 | `zeroVector` | (0, 0, 0) |
  | +0x0C | `oneVector` | (1, 1, 1) |
  | **+0x18** | **`upVector`** | **(0, 1, 0)** |
  | +0x24 | `downVector` | (0, −1, 0) |
  | +0x30 | `leftVector` | (−1, 0, 0) |
  | **+0x3C** | **`rightVector`** | **(1, 0, 0)** |
  | **+0x48** | **`forwardVector`** | **(0, 0, 1)** |
  | +0x54 | `backVector` | (0, 0, −1) |

  四条**独立互证**（都不是「按名字猜」）：
  1. `CardScript__MoveToDeck.c:55-87`（弹出补间在 `:70-86`）：`param_2 == 0` 支用 `+0x00` 当「无位移」；`else` 支用 `+0x18 × 15.0` 加在**卡当前位置**上
     —— 15 单位、且是「先弹出去再翻牌」，只能是 **up**。
  2. `CardScript__MoveToDeck.c:150-151`（`DOScale` 在 `:167`）：`DOScale` 的目标 = `(+0x0C) × fVar14` —— 三轴同倍率 ⇒ **one**。
  3. `_d__358:293/311/341` 的三次 `ApplyMovementDisappearAnimRotations` 分别喂 `+0x3C` / `+0x18` / `+0x48`，
     而同三次的 `AnimationDefinition` 依次是 `minionMovementInfo + 0x40 / 0x48 / 0x50` =
     **`rotateXAxis` / `rotateYAxis` / `rotateZAxis`**（`dump.cs:25390-25395`）
     ⇒ 轴 = **right(X) / up(Y) / forward(Z)**，与字段名逐字吻合。
  4. `UnityEngine.Quaternion_StaticFields` 只有 `identityQuaternion` 一个字段（`il2cpp.h:8332-8334`）
     ⇒ 「该轴 `enable == 0` 时返回」的那个四元数块就是 **identity**（`CardScript__ApplyMovementDisappearAnimRotations.c:29-38`）。

  **② `end += v × Δy × attackPositionYOffset` 里的 `v`** = **`Vector3.up`**（同一格 `+0x18`，`_d__358:126-137`）
  ⇒ 等价算式 **`end.y += (target.CardUI.effectsAnchor.position.y − target.transform.position.y) × card.attackPositionYOffset`**
  （`TL` §5·1「`v` 是哪个基向量没解出」—— **本节闭合**）。

  **③ 三轴连乘的逐句顺序**（`_d__358:284-365`，把 IL2CPP 内联出来的 4 组卷积逐项还原成标准四元数积）：

  ```
  q1 = Apply(cur = startRot, axis = right  (+0x3C), def = rotateXAxis(+0x40), t01)
  q2 = Apply(cur = startRot, axis = up     (+0x18), def = rotateYAxis(+0x48), t01)
  q3 = Apply(cur = startRot, axis = forward(+0x48), def = rotateZAxis(+0x50), t01)
  transform.rotation = ((q1 * q2) * q3) * startRot
  ```
  - **每一次 Apply 的 `cur` 都是 `startRotation`**（不是上一次的结果）：三处调用前都重新读了
    `param_1 + 0x60 / 0x68`（`_d__358:295-296 · 305-306 · 330-331`）。
  - 还原办法（可复核）：把 `:323-364` 的四组 `fVarN * fVarM ± …` 与标准积
    `(a*b).x = aw·bx + ax·bw + ay·bz − az·by` 逐项对齐 —— 第一次积的 `a = (local_e8, uStack_e0)` = q1、
    `b = (fVar19,fVar16,fVar5,fVar6)` = q2；第二次积把结果 `(fVar18,fVar17,fVar23,fVar20)` 当 `a`、
    `(fVar16,fVar5,fVar6,fVar7)` = q3 当 `b`；最后再右乘 `startRotation (fVar19,fVar16,fVar5,fVar6)`。
  - **施加到物体上的实际次序**（Unity `a*b` ⇒ 先 b 后 a）：`startRot → qZ → qY → qX`。

  **④ 单个轴的四元数**（`CardScript__ApplyMovementDisappearAnimRotations.c`，70 行读全）：
  ```
  enable == 0                        ⇒ q = Quaternion.identity
  enable != 0 && curve != null       ⇒ q = Quaternion.SlerpUnclamped(          // 反编译是 LerpUnclamped
                                              startRot,
  ```

### 3 易伤目标那条 `Hit` —— **原版是两拍：主伤害 1.0 s，然后「易伤额外」1.4 s（= 0.4 高亮 + 1.0），串行**

- **判据结论**（`CardScript._ReceiveDamage_d__381__MoveNext.c` 373 行读全 + `BattleManager__DealMultiDamage.c` 读全）：

  **① 第二发是「另一条 `DamageInfo`、另一个动作」，不是同一拍里多算点数**
  主 `_ReceiveDamage` 在扣完主伤害之后（`:188-257`，第二发在 `:252-254`）：
  ```

      && !HasCurrentTrait(0xf0 dodge) && !HasCurrentTrait(0x50 shield) && !HasCurrentTrait(0x136 invulnerable)

      && !IsVulnerableDamage(本次 damageInfo.damageType(+0x1c))   // 防递归
      && damageInfo.damageValue(+0x18) > 0
      && target.currentHealth(+0x68) > 0        // 主伤害落完之后还活着
      && target.isRemnant(+0x65) == 0)
  {
      DamageInfo second = new DamageInfo(
          card   : damageInfo.actingCard(+0x10),        // 原攻方
          damage : EntityScript.get_CurrentVulnerable(target),   // = 易伤层数【原值，不减护甲】
          type   : (本次 damageType == 4 Attack) + 7);  // Attack ⇒ 8 VulnerableCombat；否则 7 Vulnerable

  ```
  🔴 `(iVar8 == 4) + 7` 里的 `iVar8` 在上一行刚被**重新赋值**成 `damageInfo.damageType`（不是易伤层数）——
  `DamageType.Attack = 4`（`dump.cs:45515`）⇒ **被「攻击」打出来的易伤额外是 8，其它来源是 7**。

  **② 两拍是【串行】的，不是并行**（这条是「2.4 而不是取 max」的关键）

  - 队列优先级：`priority 2 ⇒ BattleManager+0x368`、`priority 0 ⇒ +0x350`（`BattleManager__AddAutoActionToQueue.c:47/173`）；

  - `FinishResolvingAction` 只在四个队列**都没有阻塞动作**时才收尾（`BattleManager__FinishResolvingAction.c:34-37`）。
  - ⚠️ 如实留一句：`NextActionInQueue` 的**调用点**在反编译里没有产物

### 4 `targeted && fromEnemyHand` 的 0.5 s —— 是**准星飞过去**（`EnemyTargetingAnim`）的时间，**不是「居中展示」**

- **判据结论**：

  **① 值 = `VarsGlobal.targettingAnimTime` = 0.5 s**
  `BattleManager__GetTargettingTime.c` = `globalVars + 0x88`；`ReplaySkipAnims()` 为真时 `/ DAT_1834b2e8c`（本报告实读 = **3.0** ⇒ 0.1667）。

  **② 它是什么动画**：`BattleManager__EnemyTargetingAnim.c`（全文 61 行）= 把
  `TargetReticleController` 的准星**从起手位置补间到目标**，时长正是 `GetTargettingTime()`；

  ⇒ **AU1 把它叫「居中展示前置」是张冠李戴**：`ShowCardInCenter` / `PlayEnemyCard` 是另一件事（0.6 / 1.2 / 1.3 s，`J1` §2）。
  正确的名字 = **准星定位（`EnemyTargetingAnim`）0.5 s 前置**。

  **③ 加在什么前面（从手牌打出那一支）**
  `BattleManager._ResolvePlayCardFromHand_d__447__MoveNext.c` 的 `case 1/case 2`，**顺序**：
