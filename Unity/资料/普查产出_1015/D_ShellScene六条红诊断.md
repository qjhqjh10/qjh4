## 三、根因（一条链）

### 3.1 夹具怎么摆的（意图）

`Editor/ShellScene.cs` 的 ⑤·d-4 段内 B2b 块：

- `:1752` `const float Fx1 = 100f, Fx2 = 500f;` —— 注释写明「整段落在框的 x 里」；
- `:1755` `softBox = (100,300,500,500)` —— 软边节点自己的框，**上沿 = 300**，`softness = (0,25)`；
- `:1764-1765` 先从**对照字**（`:1758`，父链上没有节点）量出两个字体的实测量：**字形高 `gH`** 与**字形中心 − 矩形中心 `gOff`**；
- `:1794-1796` 用这两个实测量反推三条实验字各自的矩形 y 中心：`cIn`（字形中心落在框心 400）· `cE1`（下沿进带 **6px**）· `cE2`（下沿进带 **18px**）；
- 意图 = 三条字**同一个节点、同一段字、同一个 x 区间**，**唯一变量是字形离上沿有多深**。

### 3.2 实际落在哪 —— 实参序错了

`:1797-1799` 传的是：

```
vpWin.Text(vcSoft.transform, Short, Fx1, cIn - 60f, Fx2, cIn + 60f, 5, Color.white, "TInB2b", 60f);
                                   ↑x1  ↑x2???    ↑y1??? ↑y2
```

而签名是 **`Text(Transform parent, string text, float x1, float x2, float y1, float y2, int scale, Color color, string name, float fontPx)`**
（`Shell/MenuWindowBase.cs:284`）⇒ 实际四元组 = **`(x1 = Fx1 = 100, x2 = c−60, y1 = Fx2 = 500, y2 = c+60)`**：**第 2、3 个实参互换了**。

对照同文件里**三处传对**的调用（都是 `(x1, x2, y1, y2)`）：`:1705`（`Tx1, Tx2, Ty1, Ty2`）· `:1710`（同上）· `:1758`（`Fx1, Fx2, Fy1, Fy2`，对照组自己）—— **只有 B2b 这三条错**。

`PxRect` 的构造**不排序**（`Core/UguiRect.cs:30` 逐字赋值），`Label` 只吃矩形的**中心**（`MenuDraw.Local` → `LayoutSpace.RectCenter`，`Shell/MenuDraw.cs:30-31`）⇒ 三条字实际落在

| 字 | 夹具意图的中心 (x,y) | **实际**中心 = `((100+c−60)/2, (500+c+60)/2)` |
|---|---|---|
| `TInB2b` | (300, 400) | **(221.6, 481.6)** |
| `TE1B2b` | (300, 281.1) | **(162.1, 422.1)** |
| `TE2B2b` | (300, 293.1) | **(168.1, 428.1)** |

⇒ **y 被整体往下推 ~78~138px，x 被挤到左边**（三条字的字形都 200.2px 宽 ⇒ E1/E2 各有 ~38px 压出节点左沿 `100`；因为 `softness.x == 0`（硬边 ⇒ `SoftAlpha` 恒 1），**x 这一半在读数上不留痕** —— 这也是它没被更早发现的原因）。

### 3.3 数值对账（唯一的自由参数 = `gOff`）

`gOff`（字形中心 − 矩形中心）由夹具自己在 `:1765` 从对照字量出。本报告**从 E1 的实测反解**它，再拿另外两条**独立**校核：

- 由 `E1` 实测中心 `(394.03+443.86)/2 = 418.945`、`gH = 49.83`（`:1777` 打印）⇒ `gOff = 2×(418.945 − (433 − gH/4)) = **−3.195 px**`；跨度 `[394.03, 443.86]` —— **与日志逐位相同**。
- `TInB2b`（用同一个 `gOff`）：矩形中心 `481.598` ⇒ 字形中心 `478.402` ⇒ 跨度 `[453.49, 503.32]`；下沿在框外 ⇒ 夹到 `500` ⇒ 实测 `453.5..500.0` —— **与日志逐位相同**（且跨度高 `46.5 < gH 49.83`，**本身就是「下沿被啃掉一截」的独立证据**）。
- `TE2B2b`：字形中心 `424.945` ⇒ 跨度 `[400.03, 449.86]` ⇒ 两行离最近边 `100.0 / 50.1px`（都 > 25）⇒ 读数 `1.000..1.000` —— **与日志相同**。
- **独立旁证**：B2 那条**顺序正确**的调用（`:1710`，矩形 y 中心 `330`）实测网格 `y 302..352`（日志 `:4531`）⇒ 中心 `327` ⇒ `gOff ≈ −3.0 ~ −3.2` ✔ 与上式吻合（那条打印是 `F0`，只能定到 ±0.5）。

### 3.4 反证：「意图摆位」这一支被实测排除

| 假设 | E1 字形中心 / 跨度 | 与实测 `394.03..443.86` |
|---|---|---|
| 按夹具**意图**摆 | `281.085` / `[256.17, 306.00]` | **差 +137.9px** ✗ |
| 按**实参换序**摆 | `418.945` / `[394.03, 443.86]` | **逐位相同** ✓ |

更强的一条：按意图摆时，`TE2B2b` 的**上沿那行会落在框外**（跨度 `[268.2, 318]`，上沿行在 `300` 以上）⇒ 被夹到 `300` 且 `a = 0` ⇒ 读数应是 `0.000..` 而不是实测的 `1.000..1.000` ⇒ **意图摆位被直接排除**。

### 3.5 结论

**实现（`MenuDraw.ClipTmpMesh` / `ClipQuad` / `SoftAlpha`）这一侧没有错**：三处 alpha 读数（框外夹 0 · 夹到框沿 0 · 远离边保持 1）与 `Shell/MenuDraw.cs:1298-1302` 的几何 + 剖面**逐条相符**。
夹具那两条「（前提）」正是**照设计**把摆位错报了出来 —— 它们是这套牙口的守门员，**⛔ 别删**。

**⚠️ 一条顺带的反证观察（不是缺陷，是佐证）**：换序后的矩形是**倒置**的（`y1 = 500 > y2 = c+60`），而 `MenuDraw.Visible` 判的是 `r.y1 >= c.y2`（`Shell/MenuDraw.cs:290-295`）—— `r.y1` 恰好 `= 500`、正好压在节点下沿上，这一条**本该**在 `Shell/MenuWindowBase.cs:308` 就把三条字全部拒掉（那样日志里「（前提）三条实验字建出来了」会先红）。日志显示它**没**被拒 ⇒ 当时节点 `ClipPx` 的 `y2` 读回 **≥ 500**（差在那条 `~6e-5px` 的 float32 往返残差上，A497 记过）。⇒ **修好实参序之后矩形不再倒置，这个「靠浮点残差过关」的悬崖也就没有了**。
