## 一、结论

**`A1099` 已按候选 A 落地** —— **联机局的「对手那一半」现在真进录像了**：

1. **补的记账口只有一处**：`BattleDriver.ApplyLoggedAction` 的**末尾**（`return code;` 之前）调一次新方法 `RecMsg(m)`。
   ⇒ 它同时覆盖 `NetBattle` 那**三个**调用点（主机收客机动作 / 客机收主机广播 / `AppendLogAndApply` 的换牌定序三条伪动作），
   因为那三处**都**经 `_d.ApplyLoggedAction(m)`（判据：`NetBattle.cs:1013` / `:1052` / `:1142`）。
2. **为什么不破坏回放**：放录像那一趟 `RecordReplays = false`（`PlayReplay:633-634` + `finally:749`）⇒ `RecBegin`
   直接 `_rec = null`（`:485`）⇒ `PlayReplay` 里灌的每一条都走同一个 `RecMsg`，而它第一句就是 `if (_rec == null) return;`。
   ⇒ **回放那趟一条都不记**（与接线前逐字相同）。`NetReplay` 那趟**不关** ⇒ 记（见下一条）。
3. **为什么不破坏重连**：`NetReplay` 的重放循环顺序、返回值、引擎调用**一个字没动**；只多了一句 `Debug.Log`。
   `RecMsg` 只往 `_rec.actions` / `_rec.trace` 追加，**不碰 `Ctx`、不碰 `Log`、不调引擎**。
   `NetKind.Applied` 对**本机自己**的动作带 `preApplied = true`（`NetBattle.cs:1022` / `:1050`）⇒ 那一支 `return`、
   **不落地**⇒ 也走不到 `RecMsg` ⇒ **不会与本机 `LocalAct` 双记**（上一笔已核，本件复读确认）。
4. **`RecBegin` 的语义扩写 = 显式写明 + 出声**（不动 `version`）：
   · **写明**：`BattleDriver.cs:763-782`（`NetReplay` 的 doc，三段 `<para>`：语义从「开局」扩成「开局 / 重连重建」、
     为什么那是**正确结果**而不是副作用、与「放录像」那趟分别是刻意的）；
     `RecMsg` 自己的 doc 里也写明「权威流 = 对手那一半 + 换牌定序」这一分工（`:554-574`）。
   · **出声**：`BattleDriver.cs:793-800` 一句 `Debug.Log`，**两档都出声** —— 记的时候说「从头重录（权威流全量 N 条）」，
     `RecordReplays == false` 时说「**这一趟不记录像**」（⛔ 不静默）。
5. **代价照担**（候选 A 的已知代价）：重连那一局会多出一份**完整可用的**新录像（不是残档）——
   这是设计意图，不是副作用；见 `BattleDriver.cs:765-778`。
