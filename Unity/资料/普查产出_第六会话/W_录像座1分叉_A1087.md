## 三、证据

### 1. 那一格在引擎里「有后果」（这就是分叉的机理）

- `RuleEngine/Core/BattleContext.cs:756-783`：`BotSeat`（`-1` = 没有电脑 / `0`/`1` = 该座位是电脑）+ **唯一判据** `IsBotSeat(seat)`。
- `RuleEngine/Core/RuleCore.cs:658-687` `GoesSecondCard(ctx, seat, deckCard)`：
  **`if (!ctx.IsBotSeat(seat)) return deckCard;`** —— 真人 ⇒ **用卡组自带那张**（不掷随机）；
  电脑 ⇒ `RandomSecondSeatDefence(ctx, seat, t)`（`:702+`，从后手方阵营防御池里**随机**取，**随机源 = `ctx.Rng`**）。
  ⇒ 座位身份一变：**卡不同** + **`ctx.Rng` 多/少消耗一次** ⇒ 之后每一步都可能错位。
- `RuleCore.cs:208-209`（`NewBattle` 里 `openMulligan:false` 那一档）与 `:407-408`（`EndMulligan` 那一档）是它**唯二**的调用点。

### 2. 为什么「不传 = 老口径」是**逐字等价**（我做到这一点了）

- 改前那一句 = `botSeat: AiShouldDriveOpponent ? 1 : -1`；改后 = `botSeatOverride ?? (同名表达式)`。
- 五个入口都没传 `botSeatOverride`（只有 `PlayReplay` 传）⇒ **文本与语义都只多了一层 `??`**：
  · 真 Play / 自检（`BeginFromDeckLibrary` → `Begin`）· 教程（`BeginTutorial`）· 联机开局（`BeginFromPendingCore(attachNet:true)`）· 重连重建（`NetReplay`，`_net` 还挂着 ⇒ 老口径本来就给 `-1`，**正好是录的时候那个值**）。

### 3. 哨兵为什么必须取 `0`（不能存引擎值本身）

引擎值域 `{-1, 0, 1}` 里 **`0` 是合法值** ⇒ 直接存「`0` = 没记」会把「座位 0 是电脑」吃掉。而老录像缺键时读出来的是 **`int` 的默认值 `0`**（`JsonUtility` 跑不跑字段初始化器**本地没有判据**，同 `tutorialStage` 那条）⇒ 只能**整体 +2**：`0` 空出来当哨兵，`-1/0/1 → 1/2/3`。本产品永远只会写 `1` 或 `3`。

### 4. 「老录像」那一档**本机实测为空**（回退口径取哪个都可，我取「不改行为」那个）

- 真存档目录 `C:/Users/qjh36/AppData/LocalLow/Everguild/Warpforge/WarpforgeReplays` —— **不存在**（0 份）。
