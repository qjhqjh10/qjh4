## ① 结论

1. **根因成立，逐条复现**：在仓里规定的 `D:/2/Warpforge_tools/py312/python.exe`（**Python 3.12.10 + UnityPy 1.24.2**）下，
   原版自带 `Warpforge_Data/Resources/unity default resources` 里 **13 个 `Mesh`** 的
   `read_typetree()` **13/13 全抛** `ValueError: Expected to read 26068 bytes, but only read 26040 bytes`
   —— **每个刚好短 28 字节**。原来 `:678` 那句 `except Exception: continue` **把异常静默吞掉** ⇒
   字典空 ⇒ 打印「解出 0 个内置网格名」⇒ `builtinMesh` 全 `null`。
   附：简报说的另一条退路 **`o.read()` 实测也不通**（py312 下 **13/13 同样抛**同一句），⛔ 确认不能用。
2. **按简报给的回退修好了**：`read_typetree(check_read=False)`（**仅新增的那 1 处调用**）。
   py312 实测 **13/13 拿到名字**，且与 PATH 上裸 `python`（**3.14.4 + UnityPy 1.25.3**）的
   **六个 pid 逐名完全相同**（§三·3）。
3. **行为只加不减**：成功路（`names` 非空、打印文案、缓存语义）逐字未动；
   新增的只有「失败回退」与「失败出声 + 不落缓存」。
4. **单场验证通过**（`battlearena1` + `battlearenaemperorschildren`，用 py312，⛔ 未跑 Unity、⛔ 未跑 `--all`）：
   `Shadow Receiver` 的 `builtinMesh` = **`'Quad'`**（`pid 10210`），EC 场另外两件 `Tank distortion 1/(1)` 也一起出来了。
5. ⚠️ **清单文件本轮【没有重跑】**（按简报 · 那是主对话的活）：盘上 13 份**仍然全是 `builtinMesh: null`**
   （实测 13 份 `null` 合计 = 29+55+47+41+80+50+58+79+47+44+82+55+50，**非空 0 条**）。
   重跑 13 场后**必须跟一次 `工具/gen_arena_meshkeywords.py`**（旁挂是反向生成的）。
