## 六、顺手发现的（⛔ 我一个字都没改）

1. 🔴 **上一轮交件 §五·2 有一句不成立**：它写「`Cache Stealth` … **它本来就因为找不到 OBJ 而没进清单** —— 与本批不是同一件事」。

   只是 `objFile=null` ⇒ **构建侧跳过它**。差别很重要：**「进清单但不建」≠「没进清单」**
   —— 前者会让 `active=false` 出现在清单里（本趟就出现了），后者不会。
   我照 `/d/4/Unity/资料/普查产出_第五会话/交件_8b_2c_ShadowReceiver.md:226-227` 的原话核的（**没改那份文件**，它在白名单外）。
2. 🔴 **`is_transparent()` 缺「残留值闸门」，且会【反向】出错**（`unity_scene_to_godot.py:677`）：
   把闸门搬过去会翻 **13 份 `LUTBlender`：`true → false`**（它材质上写着 `_Blend > 0`，而 pass 是 `1/0`）。
   ⇒ 这说明**「材质值」与「pass 硬编码」谁说了算，在这个判据里与在 `unity_mat_fields` 里是两回事**，**不能照搬**（这也正是我没搬的理由）。
   **判据**：`probe_a1074b.py` 逐场输出（13 行，每场 2~3 条）。
3. 🔴 **`is_transparent()` 也还不认 `5/1`（预乘 Alpha）** —— 实测两份被它判成不透明：
   `battlearena3` 的 `default_001_add`、`emperorschildren` 的 `bubble_light`（都是 `5/1`、关键字空）。
   ⇒ **铁律 11 ⇒ 要做**（判据清楚：`5/1` = 预乘 Alpha），**先做哪个由调度台定**。
4. ⚠️ **`mi.zwrite` 对 `Transparent Shadow Receiver` 读回的是 `1.0`（写深度），而原版 pass 是 `ZWrite Off`**
   —— `shader_info` 那张表**只有 `name` / `has_src_blend` / `pass_src` / `pass_dst` 四个键，没有 pass 的 `zWrite`**。
   ⇒ 凡是「材质没写 `_ZWrite`、pass 里关掉」的件（这一份就是），**判据拿不到真值**。
   影响面**本趟没量**；**要做**的话落点是 `Assembler.shader_info`（`unity_scene_to_godot.py:583` 附近）+ `unity_mat_fields` + `MeshEntry`/`SubMatEntry` 的 schema（**跨三处，须单独排**）。
   ⚠️ 同一个口也解释了上一轮交件 §三 里那句「`subMats[0]` … ✅ `srcBlend=2 / dstBlend=0`」，那是**走了闸门**才对上的。
5. ⚠️ **`_meshkeywords` 旁挂「先有鸡还是蛋」这个结构性问题**（§5·4）：凡是**新进清单**的对象，
   第一轮**必然**没有关键字 ⇒ 任何「清单重生成」之后**都要跟一次 `gen_arena_meshkeywords.py`**。
   建议把它写进调度台那条收口清单（上一轮交件 §七·3 已经提过一次，本趟**第二次撞上**）。
6. ⚠️ **`emit_mat` 的「混合档位表」也只看【材质上】那一对**（`unity_scene_to_godot.py` 里
   `if mi.blend == 3 or (mi.dst_blend == 0 and mi.src_blend == 2): …BLEND_MODE_MUL`）——
   而 `Transparent Shadow Receiver` 的 `mi.src_blend`/`dst_blend` 是 **`None`**（材质上没写）
   ⇒ 就算 `is_transparent()` 现在回了 `True`（⇒ 会写 `TRANSPARENCY_ALPHA`），
   **`BLEND_MODE_MUL` 那一行仍然不会写** ⇒ 那一档在 Godot 侧会落成**普通 Alpha 混合**而不是**乘暗**。
   ⇒ **要做**（判据清楚：同一道「残留值闸门」），落点 = `emit_mat` 里那三行 `mi.src_blend/dst_blend`
   换成「经闸门后的那一对」；**本趟没动它**（`A1074` 只要求「不再判成不透明」，这一条是**下一档**）。
