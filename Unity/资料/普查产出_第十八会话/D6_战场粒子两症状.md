## 3. 症状 B（`Dust Floor` 深色块）逐条判

**(乙) 当时成立，已修。** 原版材质关键字含 **`_EMISSION`**、`_EmissionColor=(0.481132,…)`（清单 idx 29/30/31/33 的
`matProps` 逐条实读），而 URP `ShaderLibrary/Unlit.hlsl:22` 是 `finalColor = half4(albedo + emission, alpha)`
（见 `ParticlesUnlitForwardPass.hlsl:63-67`：`#if defined(_EMISSION)` → `emission = _EmissionMap * _EmissionColor`，否则 `emission = 0`）
⇒ 少了它就是 **0.228 的线性积 = 比背景暗**。这正是 `:239-266` 的诊断。

**修已落地且今天可复现**：关键字写不进 `.mat` ⇒ 走 `WarpforgeVFX/Runtime/ArenaParticleKeywords.cs` 运行时给材质实例设；
prefab 里那 11 组 `keywords: [_EMISSION,_FADING_ON,_FLIPBOOKBLENDING_ON,_SOFTPARTICLES_ON,_SURFACE_TYPE_TRANSPARENT]`、
`additive: 0`（粒子那档 = 整表替换）全在；**两条渲染路都显式刷**（`ArenaBuilder.cs:584` `PrepareSceneMeasure` 与
`:855` `RenderPreview`，注释已标"第二条路"）。实测复现 `:286` 的数：**(940,280) = 135.5 / 138.4**。

**(甲)(丙)(丁) 不成立**：深色块来自材质项缺失，不是没建、不是排序、不是没跑。
**⇒ 剩余的是 `(960,280)` −22 / `(920,280)` +18 的横向错位，量级小、方向自相消。**

## 4. 主对话新增两条

### ① 「原版亮柱 / 我们深灰块」→ 数值上不成立
`(940,280)` **我们比原版亮 2.9**。逐块复量裁图内 |差| 最大处在 `src(1040–1140,440)` = **+35~+45（我们更亮）**，
负向最大只有 `(960,280)` 的 −22 ⇒「深灰块」这个观感在今天的图里找不到对应的量级。
⚠️ **坐标映射错了一格**：裁图 `(940,280)±180` 只覆盖 **x 760–1120 / y 100–460**，而描述里的
「x≈1075, **y≈690**」**超出下边界 230px**；并排图左右各 720×720（2× 放大），易把**面板像素**当 1280 空间坐标
⇒ 后续报坐标先按 `src = 原点 + 面板px/2` 换算。

### ② 「右下那团火完全没有」→ **成立**，且**不在**「不建」那一档
定位（1280 空间）= 原版 **`(1020,450)-(1074,484)`**（并排图右下角最后几行）；原版 mean (109.1,**81.5**,**29.0**)
max **(245,221,105)**（明显黄橙），我们 mean (109.6,**86.0**,**50.6**) max (152,131,97)。
**不是 (甲)**：火那一支的发射器都在桶边（`Barrels Light FX` = `(103.5298, 1.490763, −6.471353)`）——
`TinyFlames`(idx 19, `TinyFlame.png`) · `Embers`(idx 24, `Glow.png`) · `SmokeEffect`(idx 21, `smokeysteam.png`) ·
`WildFire`(idx 25, `LargeFlame02.png`)，**四颗 `texFile` 全非空**、贴图都在 `arenas/battlearena1/Textures/`、prefab 里都在。
**「没贴图所以不建」那条对 arena1 不适用**：13 场 `particles[]` 共 **578** 颗，`texFile` 为空的是 **14** 颗
（`战场13场…:755-770` 已给 arena3 那 2 颗开 Mesh 豁免；darkangels 那 2 颗是 `renderMode=5`）—— **arena1 占 0 颗**。
⚠️ `普查产出_0920/场景光照与后处理_原版规格.md:545` 的「**18 个**」是 **2026-09-20 旧数**，现读 **14**（我未改，建议按铁律 5 订正）。
**两个候选，尚未判死**（只列判据，不发明做法）：(a) `TinyFlame` 材质关键字里**没有 `_EMISSION`**
（idx 19 `matKeywords` = `[_FADING_ON,_FLIPBOOKBLENDING_ON,_SOFTPARTICLES_ON,_SURFACE_TYPE_TRANSPARENT]`），
而它的 `_EmissionColor=(4,4,4,1)`、`_EmissionEnabled=1` ⇒ **那 4.0 的自发光今天不会被加进去**；
若原版 `m_ValidKeywords` 本来也没有它，则我们也对（照原版）—— **这一层我没核到原版原文**，见 §7。
(b) **`Barrels Light FX` 那块发光板**同位置我们 **+44** 亮，比火更近/同深，alpha 混合会**把火冲淡**
（正是 B 抬高、峰值压低的形状）⇒ 先跑实验 ①。

## 5. A/B 判别实验（≤3 个，由主对话跑）

**共用**：`WF_ARENA=battlearena1` + **`WF_PSFIXSEED=1`**（不开种子本机单帧相减不可用）+ `WF_WARMUP=4`。
⚠️ **`WF_HIDE` 与 `WF_HIDEIDX` 共用同一个文件名 `arenas/battlearena1/hide_battlearena1.png`**（`ArenaBuilder.cs:1293-1297`）
⇒ **一次只开一个开关，跑完立刻把 png 改名/拷走**，否则第 2 趟静默覆盖第 1 趟。
量块口径（`工具/arena_imgstats.py` 没有区域参数，`--pair` 只有整图 mean/dark%/hi%/gray%）：

```python
from PIL import Image; import numpy as np
a=np.asarray(Image.open(r'<png>').convert('RGB')).astype(np.float32)[y:y+20, x:x+20]
print(a.reshape(-1,3).mean(0).round(1), a.reshape(-1,3).max(0))
```

**实验 ① 火是「没画出来」还是「被 `Barrels Light FX` 冲淡」**
```
WF_ARENA=battlearena1 WF_PSFIXSEED=1 WF_WARMUP=4 WF_HIDE="=Barrels Light FX,=Generator 2 FX" \
"$UNITY" -batchmode -quit -projectPath "D:\4\Unity\MyGame" -logFile - -executeMethod ArenaBuilder.RenderPreviewFromCLI
```
看 `(1020,450)-(1074,484)` 的 mean/max。**max R 跳到 ≈245、B 掉到 ≈30** ⇒ 火一直在，是**发光板冲淡/盖住**
（(丙) 变体）⇒ 与 `(1080,440) +44` 并案查那块板；**仍 ~150、B 仍 ≈50** ⇒ 火自己出不了像素 ⇒ 进实验 ②。

**实验 ② 火：粒子有没有发射 / 材质路对不对**
```
WF_ARENA=battlearena1 WF_PSFIXSEED=1 WF_WARMUP=4 WF_PSSEC=2 WF_MAXPS=20 WF_PSDUMP=TinyFlames \
"$UNITY" … -executeMethod ArenaBuilder.RenderPreviewFromCLI      # → preview_battlearena1.png；再加 WF_ORIGPART=0 跑一遍作对照
```
看日志 `[Arena] 粒子数 TinyFlames = N / max 1000（…尺寸…） 跨度 … 平均已存活 …`、`PSDUMP` 的发射体世界位置与前 8 颗 `pos/vel/size`；图看 `(1020,450)-(1074,484)`。
**N=0** ⇒ 没发射 ⇒ **(丁)**（查 `prewarm` 等价物 / `simulationSpeed` / `startDelay` / `shapeType=10` 的 `arc`）。
**N≥1 但 `size` 远小于 0.5~0.75 或 `pos` 全挤在原点** ⇒ **(乙)**。
**N≥1 尺寸对、像素仍不出，且 `WF_ORIGPART=0` 反而亮** ⇒ ⑨「粒子走运行时原版材质重建」（`ArenaOriginalMaterial.Rebuild()` 的
`ParticleSystemRenderer` 支，`ArenaBuilder.cs:2464-2494`）把那族弄没了 ⇒ **(乙)**。
**两档都出不来** ⇒ **(丙)**（队列/深度：`matQueue` 全 −1 ⇒ 都落 3000，与发光板打平 ⇒ 排序不可控）。

**实验 ③ 汽：`Dust Floor (3)` 今天压不压 `Steam`（顺带结掉症状 A）**
```
A: WF_HIDEIDX=30        → hide_battlearena1.png（改名 hide_idx30.png）
B: WF_HIDEIDX=16,17,18  → hide_battlearena1.png（改名 hide_steam.png）
```
看 `(940,280)` 与 `(1035,370)` 两个块。**B 那趟 `(1035,370)` 掉 >3** ⇒ 三颗汽真在出像素 ⇒ 症状 A 结案
（`:290` 那句"贡献 0"只对 `(940,280)` 成立）；**B 那趟纹丝不动 <1** ⇒ 汽建了但不出像素 ⇒ 才回到 **(丁)/(乙)**，
用实验 ② 的 `WF_PSDUMP=Steam` 查；**A 那趟 `(940,280)` 变 >10** ⇒ 「`Dust Floor (3)` 压住汽」今天仍通 ⇒ 才需要动排序。
