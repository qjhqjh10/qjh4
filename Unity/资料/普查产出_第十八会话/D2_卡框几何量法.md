## 一、量法说明书（下一个代理照抄即可）

### 1.1 结论先行：**别用 `assets_full` 量这棵子树**

卡面这棵树（`Card Info` 以下）在解包目录 `d:/2/新解包资源/assets_full/bundle_scenes_scenes_battlearena1/` 里 **是残缺的**：
`Card Info` 的 RT（`RectTransform_1261.json`）与 `Cost Container` 的父 RT（`_1388.json`）**在该目录里不存在**
（实测 `ls RectTransform | grep -x RectTransform_1261.json` → 空）⇒ `工具/menu_dump.py` 走那棵树时会 **静默把 `Card Info` 整支丢掉**
（表尾只报「3 个纯 Transform 子件」，不报「少了 Card Info」）。
**判据**：解包目录里 `Front` 只有 3 个子件；**真包里 `Front` 有 5 个**（多 `Textbackgrounds` 与 `Card Info`）。

### 1.2 ✅ 正确量法：UnityPy 直接读**真包**

真包：`D:/2/unity_run_ref/Warpforge_Data/StreamingAssets/aa/StandaloneWindows64/*.bundle`（84 个，只读）。
UnityPy 1.25.3 已装（`python -c "import UnityPy"` 可验）。做法：

```python
import UnityPy, os
AA = r'D:/2/unity_run_ref/Warpforge_Data/StreamingAssets/aa/StandaloneWindows64'
path = next(os.path.join(AA,f) for f in os.listdir(AA) if 'battlearena1' in f)  # ⚠️ 子串会先撞 'menumusic'，写长一点
env = UnityPy.load(path); objs = list(env.objects)
# ① 根：o.type.name=='GameObject' 且 o.read().m_Name=='CardUI'
# ② 走树：go.m_Component[] 取 class 名 Transform/RectTransform 那颗；tr.m_Children[] 是【已读出的对象】，
#         用 c.m_GameObject.read() 拿子 GO（c 是 PPtr 时退到 c.read().m_GameObject.read()）
# ③ 字段：RectTransform → m_SizeDelta / m_AnchoredPosition / m_AnchorMin|Max / m_Pivot / m_LocalScale
#    Image（⚠️ 托管类，UnityPy 报成 MonoBehaviour）→ c.read_typetree() 有 'm_Sprite' 就按 Image 解
#    TMP（同样报 MonoBehaviour）→ typetree 里有 'm_fontSize'；类名一律 `type(obj).__name__`
```

本次两个脚本全文在 `/tmp/d2/dump2.py`（走树+逐字段）· `/tmp/d2/sil13.py`（帧图轮廓），
`python -I /tmp/d2/dump2.py battlearena1 CardUI`。⚠️ `/tmp` 会被清，**要复用得先挪到 `工具/`**（本轮我没这个权限）。

### 1.3 三个「不照做就会错」的点

| # | 坑 | 判据 |
|---|---|---|
| ① | **`Card Info` / `Textbackgrounds` / `MinionOrWarlord Container` / `Tactic Container` / `EffectAnchor` 是【纯 `Transform`】**（不是 RectTransform） | `type(cc).__name__ == 'Transform'`；无 `m_SizeDelta`。它们 `lp=(0,0) ls=(1,1)` ⇒ **纯转发**，子孙的锚点参照物是 **`Front`** |
| ② | **锚点基准 = `Front` 的原点，不是 2DCard 的中心** | 这些容器的锚点全 `(0.5,0.5)`、pivot `(0.5,0.5)`，而 `Front` 的 pivot 就在它自己矩形中心 ⇒ 锚点基准 = `Front` 原点 = 2DCard 空间 **(0, 0.08)**。**`apos` 直接就是相对 Front 原点的中心偏移** |
| ③ | **sprite 的 `m_Name` 会说谎** | 帧图的 sprite 名字印成 **`Orc Frame`**（32 个不同的帧图**同名**）。真名看它引用的 **Texture2D** 的 `m_Name`（`40k_Cardframe_troop_Ultramarines_tier1` 等） |

### 1.4 顺路发现（可复用）：**bundle 容器键 = 资产 GUID**

`AssetBundle.m_Container` 的键就是 `AssetGUID`（`o.read().m_Container` 是 **list of (guid, AssetInfo)**）。
⇒ **SO 里只存 GUID 的引用（`AssetReferenceTyped`）能这样解析**，`guid_map.tsv`（assetName 列全是 `None`）不必再当唯一路口。
本次靠它把 `CardFramesByArmy` 的 208 个 GUID 解成 sprite。
🔴 **但键不一定是【完整】GUID，也可能是 GUID 前缀** —— 实测 EC 包（`chaosspacemarinesemperorschildrencardassets_assets_all`）的帧图键是
`716`/`19`/`7d`/`bb7`（= `7163291b…`/`19e56d39…`/`7d41790c…`/`bb7e1025…` 的前 3 位），UM 包却用完整 GUID
⇒ **必须「先精确匹配、再前缀匹配」**，只做精确匹配会静默漏掉整整一个阵营。
（`catalog.bin` 与 `staticgeneralassets_assets_all.bundle` 里也含 GUID 文本 —— 那是 Addressables 目录与 SO 本身，不是资产本体。⚠️ 另：本机有**两份游戏副本**，本次只用 `D:/2/unity_run_ref/`。）
