# D4 · 只读诊断 · `MainMenuScene` 那条「阵营图标在左下」的 rect 断言为什么红

结论一句话：**（α）成立** —— `W5` 的**期望值算式量纲错**（把已在「显示 px」的 `CellW/2` 又乘了一次 `K`）。
**我们的实现逐位正确**（`−83.925, +102.645`，与原版 250×405 格 ×0.9 的等比缩放完全一致）。⛔ 不是回归、不是夹具。

## 一、四类逐条判

### (α) 断言自己错 —— ✅ **成立**（唯一根因）

**缺陷位置** = `Editor/MainMenuScene.cs:3504-3507`：

```csharp
float ex = cx0 + (MenuDraw.DcFacX + MenuDraw.DcFacW * 0.5f
                  - DeckSelectionPopup.CellW * 0.5f) * K;   // ← 减号右边多乘了一次 K
float ey = cy0 + (MenuDraw.DcFacY + MenuDraw.DcFacH * 0.5f
                  - DeckSelectionPopup.CellH * 0.5f) * K;
```

**量纲错在哪**：`DeckSelectionPopup.CellW/CellH = 225/364.5`（`DeckSelectionPopup.cs:162`）**已经是显示 px**
（= 原版作者系 `250×405 × DeckCellK(0.9)`），它的半值 `112.5/182.25` **不需要再乘 `K`**。
`DcFacX/DcFacY/DcFacW/DcFacH`（`MenuDraw.cs:2842`）那一族才是**作者系**、必须乘 `K`。
⇒ 同一个括号里混了两套坐标系（简报第 ③ 节猜的那件事**就是这个**，判据逐项如下）。

**实算**（`K = 0.9` · 作者系 `DcFacX/Y/W/H = −10.5/273.7/84.5/85.7`）：

| 量 | 值 |
|---|---|
| 实现（= 原版）相对**格中心**的偏移 | `(31.75×0.9 − 112.5, 316.55×0.9 − 182.25)` = **(−83.925, +102.645)** |
| 断言的期望偏移 | `((31.75 − 112.5)×0.9, (316.55 − 182.25)×0.9)` = **(−72.675, +120.870)** |
| **残差 = 期望 − 实得** | `(112.5×(1−0.9), 182.25×(1−0.9))` = **(+11.25, +18.225)** |

**自检里报的就是 `差 (11.25, 18.23)`** —— 与预测**逐位吻合**（x 到 0.005px、y 到 0.005px，y 的 `.225→.23` 正是 `F2` 的进位）。
且**方向**也对：报的 `实得 (280.6, 493.5) < 期望 (291.8, 511.8)`，与上表 `期望 > 实得` 同向。
⇒ 两条独立方程同时命中同一个单参数解释（`K`），**不是巧合**。

**这个算式还有第二个病（连带，见第四节）**：残差 `(CellW/2)(1−K)` 与 `DcFacX/DcFacY/DcFacW/DcFacH`
**完全无关** ⇒ 这条断言**现在恒红**，`W5` 在报告 `:44` 写的「改坏法 = 把 `DcFacX/DcFacY` 改回右上 ⇒ 本条红」
**说明不了任何事**（怎么改都是红 11.25/18.23）。

*(反证需要什么)*：若 (α) 不成立，则「实得」必须**不等于**「作者系等比 ×0.9」那个值。
实测实得 = **280.6** / 预测 (α) 的 280.55 —— 差 0.05px（`F1` 显示位）。反证需要拿出另一个解释同时说清 11.25 与 18.225。

## 二、根因（唯一）

`Editor/MainMenuScene.cs:3504-3507` 的**期望值算式把「显示 px 半宽」当成「作者系半宽」又乘了一次 `K`**。
**实现、常量、夹具、改名全部无辜。**

## 三、最小修法建议（⛔ 不要动手，交给主对话）

**推荐（连带治好「恒红」这个第二病）—— 期望值锚到【原版字面量】，不锚我们的常量**：

```csharp
// 原版字面量（说明书 :56 / content [0,0 250x405]）—— ⛔ 别改成 MenuDraw.DcFac*
const float OFacX = -10.5f, OFacY = 273.7f, OFacW = 84.5f, OFacH = 85.7f;
const float OCellW = 250f, OCellH = 405f;
float ex = cx0 + ((OFacX + OFacW * 0.5f) - OCellW * 0.5f) * K;
float ey = cy0 + ((OFacY + OFacH * 0.5f) - OCellH * 0.5f) * K;
```

**次选（改动最小，只挪一个括号）**：把 `− CellW * 0.5f` 挪到**乘 `K` 之外**：

```csharp
float ex = cx0 + (MenuDraw.DcFacX + MenuDraw.DcFacW * 0.5f) * K - DeckSelectionPopup.CellW * 0.5f;
float ey = cy0 + (MenuDraw.DcFacY + MenuDraw.DcFacH * 0.5f) * K - DeckSelectionPopup.CellH * 0.5f;
```

两者**数值恒等**（`125 × 0.9 == 112.5`，`202.5 × 0.9 == 182.25`）。
❗**但次选有个坑**：它把断言变成**代数恒等式** —— 实现侧与期望侧由**同一组常量**驱动，
`measured − cx0 ≡ (DcFac*+半)·K − CellW/2` **对任意 `DcFacX/DcFacY/DcFacW/DcFacH` 都成立** ⇒
`W5` 写的那条改坏法（`:3491`「改回右上 ⇒ 红」）**永远不会红**，这条断言退化成同义反复。
（现在的 `DcFac*` 全仓**只有 `MenuDraw.cs` 与这一条断言**两处使用者，`grep` 已核 —— 没有任何别处钉住它们。）
**首选**因为期望值来自原版印刷值，`DcFacX` 一旦被改回右上，实现侧动、期望侧不动 ⇒ **真的红**。

改完顺带核两件（都不必跑 Unity）：① 改后残差应为 **0.0 / 0.0**；② `grep` 确认没有第二处引用 `DcFac*` 的期望值算式。
