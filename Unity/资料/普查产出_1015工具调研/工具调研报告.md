## 二、逐类对照

### 2.1 场景（13 个战场 + 主菜单）

- **我们现在怎么做**：`工具/scripts快照/gen_unity_arena_manifest.py` **直接读 `bundle_scenes_*`** → `<场>_manifest.json`
  → `WarpforgeArena1/Editor/ArenaBuilder.cs` 照清单建场（`WF_ARENA=<场> -executeMethod ArenaBuilder.BuildFromCLI`）。
  产物实测在 `MyGame/Assets/WarpforgeArena1/arenas/<场>/<场>_manifest.json`（13 份，逐场一个目录）。
- **候选工具能不能更好**：**只有 AssetRipper 一条**（`SceneAssetExportCollection` / `SceneAssetExporter` / `PrefabExportCollection` 在开源仓里）。
  它一次能出**整棵 `.unity` 场景 + `.prefab` + `.mat` + mesh**，不用我们自己写建场器。
- **判据**：① 开源仓 `Source/AssetRipper.Export.UnityProjects/Project/` 目录实测同时有这四个 exporter（GitHub contents API）；
  ② 但它「还原被内联的 prefab」是**付费功能**（`Prefab Outlining`，文档明写默认 `false`）⇒ 免费版拿到的是**一大坨内联 GameObject**，
  跟我们现在的清单一样平；③ **静态合批**：原版 13 场里**只有 `battlearena2` 一场有静态合批**
  （实据 `资料/战场13场_逐场对账_0920.md:525`：「逐 bundle 实读 13 场的 `MeshRenderer.m_StaticBatchInfo`」），
  而这一条**我们 2026-09-25 已经修完了**（`firstSubMesh`，`资料/任务线/战场线/任务总表.md:61`：`1.086 → 1.022`）。
  ⇒ AssetRipper 的免费版**不拆合批**、付费版**拆的正是我们已经拆完的那一场**。

### 2.2 特效 / 2.3 粒子

- **我们现在怎么做**：`工具/gen_arena_particles*.py` 一族 + `gen_unity_arena_manifest.py` 的 `ParticleSystem` 解析段
  （字段清单见 `资料/资源使用手册.md` §3.2，2026-09-22 更正补了 `emissionRateCurve`/`noise`/`subEmitters`/`hasXxx` 五个布尔 等）；
  导出器在 `Assets/WarpforgeVFX/`（`ArtBaker` / `EffectExporter` …）。
- **候选工具能不能更好**：**没有专门工具**。AssetRipper 的开源导出模块目录（实测 GitHub contents API 列举）是
  `AnimatorControllers / Audio / AudioMixers / EngineAssets / Miscellaneous / PathIdMapping / Project / RawAssets / Scripts / Shaders / Terrains / Textures` —— **没有 particle / vfx 专项目录**；
  粒子走的是通用 native class 导出（`ParticleSystem` 是 Unity 原生类，理论上能出）。
- **判据**：**没查到**任何「专门为粒子做的 bundle→工程」工具；也**没查到** AssetRipper 对 `ParticleSystem` 导出完整度的公开文档（写在 §五）。
- ⚠️ **已知的同类坑不因换工具消失**：`资料/已知的坑.md:533` —— `SpriteRenderer`/`SpriteMask` 的 sprite 是 bundle 资产、
  引用落不下来、遮罩一空整块效果渲成空（实测 78 个 prefab 有被遮罩的粒子）。这是 **Unity 资源引用层**的问题，不是提取器的。

### 2.4 材质 / shader（**这一条最关键**）

- **我们现在怎么做**：① 材质：`gen_unity_arena_manifest.py` 的 `unity_mat_fields()` 从
  `_SrcBlend/_DstBlend/_AlphaClip/关键字/贴图透明像素占比` 判透明（**不用 `blend` 字段**，见 `资料/资源使用手册.md` 坑 2）；
  ② shader：**运行时从 bundle 取原件**（`WarpforgeShaderLoader` / `WarpforgeEffectBinder`，
  见 `资料/已知的坑.md:1599`、`:1660`），因为 **bundle 里的 Shader 落不了工程资产**（`d:/4/Unity/资料/已知的坑.md` 同名条目）。
- **AssetRipper 能做到什么程度**（逐条实测源码）：
  - 开源仓 `Source/AssetRipper.Export.UnityProjects/Shaders/` 目录里**只有这些**：
    `DummyShaderTextExporter.cs` · `SimpleShaderExporter.cs` · `ShaderExporterBase.cs` · `ShaderExportCollection.cs` ·
    `TemplateShader.cs` · `Templates/{Default,SingleColor,SingleTexture,TransparentDiffuse}.txt` · `YamlShaderExporter.cs` ——
    **没有反编译器**（GitHub contents API 实测目录列表）。
  - `SimpleShaderExporter.cs` 的判据是 `shader.Has_Script() && HasDecompiledShaderText(shader.Script.String)` ——
    **只处理「`m_Script` 里本来就有源码」的 shader**。我们的原版 `m_Script` 是 `null`（这正是我们那条坑），⇒ **它走不到这条路**。
  - 兜底是 `DummyShaderTextExporter.cs`，其 `FallbackDummyShader` 是一段**写死的** `#pragma surface surf Lambert` 的占位 shader。
  - `ShaderExportMode` 枚举（`Source/AssetRipper.Export/Configuration/ShaderExportMode.cs`）**确实有 `Decompile` 一项、
    注释写着 `Export as decompiled HLSL`** —— 但**实现不在开源仓里**（仓里另有 `AssetRipper.GUI.Licensing` 模块）。
  - 官方文档把 **Shader Decompilation 列在 Premium**，原文自陈：`This is an experimental shader decompiler …
    it's not yet polished, so expect it to throw errors while ripping some shaders and for there to be compilation errors in Unity Editor.`
- **判据 / 效力**：对我们这 527 个原版自定义 shader（`d:/2/解包整理/11_着色器/`）——
  **免费版 = 通用 Lambert 占位**（等于「手译」那一课从零开始，还丢掉了原版的 pass/blend/cull 状态）；
  **付费版 = 唯一可能替代手译的路**，但它自己承认会出错、且**需要能在编辑器里编译** —— 而我们的用法是**运行时用原件**，本来就不需要它编译。

### 2.5 光照

- **我们现在怎么做**：`SceneJumpShot` mod 的 `LogRenderEnvFacts()` 探针（`资料/资源使用手册.md` §3.3）读运行时
  `RenderSettings` 全量 + `ambientProbe` + 每盏灯；规格落在 `资料/普查产出_0920/场景光照与后处理_原版规格.md`。
  结论里已记：原版**烘焙无影** ⇒ 我们生成器里把 `shadow_enabled=false` 固化（`Unity参照管线_0825/README.md`「已验证结论」）。
- **候选工具能不能更好**：**没有**。AssetRipper 的开源导出模块列表里**没有 lighting / lightmap / RenderSettings 专项目录**
  （见 2.2 那份目录列表）。光照是 `Scene` 资产的一部分，理论上随场景一起出去，但**没查到任何专门能力**。
- **判据**：GitHub contents API 列举 `Source/AssetRipper.Export.UnityProjects/` 全部子项，无 lighting 相关项。

## 三、红队：看着能替代、实际不行

1. **「AssetRipper 直出 Unity 工程，所以不用自己写建场器了」** —— **不成立**。
   ① 它出的是**平铺的内联 GameObject**（还原 prefab 是付费的 `Prefab Outlining`，文档明写默认 `false`）；
   ② 我们真正花时间的不是「建 GameObject」，而是**逐场对账**（13 场 × 相机栈/雾/顶点色/`m_CustomRenderQueue`…，
   见 `资料/历史/交接_第三十六会话.md:82`：「最大来源 = 13 场里 12 场没开始」）—— 那部分**一件工具都替不了**；
   ③ 它的 shader 是占位、MonoBehaviour 是 missing（见下），出来的场**不是能跑的样子**。

2. **「AssetRipper 免费版能反编译 shader」** —— **不成立**。
   实据：开源仓 `Shaders/` 目录**没有反编译器**（只剩 dummy / template / pass-through 三支 + yaml 导出）；
   `SimpleShaderExporter` 的入口判据要求 `m_Script` 非空（**我们的就是 null**）。
   用户报告佐证：issue **#1827**（2025-07-02 关）标题原文 `Dummy shaders don't work, and all mono behavior scripts show as "missing"`；
   issue **#1229**（2024-03-01 关）报告 90% 普通 shader 也是错的（贴出的就是那段 DummyShader 文本）。

3. **「AssetRipper 出的 shader 至少能在编辑器里看」** —— **要打问号**。
   `YamlShaderExporter.cs` 自己的注释原文：`Shader.Find will not work in the Unity Editor with this exporter.`
   ⇒ **yaml 模式**导出的 shader **`Shader.Find` 找不到** —— 而我们的代码**大量**用 `Shader.Find`/按名解析
   （`资料/已知的坑.md:547`：`Shader.Find` 打包后找不到未被引用的 shader，自建 shader 必须注册进 Always Included Shaders）。

4. **「付费版反编译能替掉我们运行时从 bundle 取 shader 的做法」** —— **不划算且风险高**。
   我们现在的做法是**取原件、语义 100% 保真**（`WarpforgeShaderLoader` 从已加载的包里捡）；
   付费反编译产出的是**重新编译的 HLSL/ShaderLab**，官方自陈 `expect it to throw errors` / `compilation errors in Unity Editor`。
   用「可能编不过的重编译产物」换「本来就能跑的原件」，是**降级**。

5. **「UABEA 那条路」** —— **能走，但正是我们已经在走的路**。
   讨论 **#1802**（2026-10-15 现读仍 `state: open`）里的实况工作流原文：
   `1. Assestripper uses the Dummy Shader` → `2. Use the Unity engine's AssetBundles packaging tool`（重打我们自己的小包）
   → `3. Export raw to the original shader in UABE` → `4. Success uses the original shader`。
   **这就是「bundle 里取原件」那套**（我们记忆里 `warpforge-original-asset-loading` 的四步走）。
   ⇒ 它能确认思路对，**但不带来新能力**。

6. **「FBX / glTF / Alembic / USD / MeshSync 能替代 bundle 导入」** —— **不能**。
   这五条全是「工程 ↔ DCC / 中间格式」，**没有一条读 bundle**（表的第 4 列全是 ❌）；
   要先用 AssetRipper/UnityPy 出中间格式再用它们 ⇒ **多一道有损转换**。
   而我们已实测**导入器会静默改坏原版资产**（`资料/已知的坑.md:2858-2865` 的「完整名单」表：OBJ 手性/子网格 ·
   贴图 `m_MipCount` · `maxTextureSize` —— 已踩 5 次）。**加一道转换 = 多一类静默损坏**。
   ⚠️ 另：`MeshSync` 最新版 **0.17.3-preview（2023-06-12）**、`USD` **3.0.0-exp.5（2023-10-19）** —— 都**两年多没动**。

7. **「Pixyz 能优化原版场景」** —— **不适用**：`unity.com/products/pixyz` **308 跳转**到 `/products/unity-asset-transformer`，
   定位是 **CAD 数据**可视化/减面，不读 Unity bundle。

8. **「AssetStudio 是首选」** —— **过期**：`Perfare/AssetStudio` **`archived: true`**、最后推送 **2022-12-08**。

9. **⚠️ 一条对所有工具都成立的限制（换工具绕不开）**：MonoBehaviour 的自定义脚本**不在 bundle 里**。
   AssetRipper 官方 CommonIssues 原文：`Except in extremely rare and special cases, there are no mono scripts stored in asset bundles`；
   并且要读 MonoBehaviour 字段，**必须把手游的 `.dll` 一起拖进去**（IL2CPP 游戏要先跑 Cpp2IL）。
   ⇒ 我们的 MonoBehaviour 海（24.7 万文件里的大头）**任何免费工具都只能读成 `UnknownObject`**，跟我们 UnityPy 现状一样。
