## 一、结论（三条，改前 → 改后）

| # | 改前 | 改后 |
|---|---|---|
| **① D1 · `DeepHash` 跨进程** | 卡 id 走 `string.GetHashCode()`（.NET **按进程随机化**，本项目自己在 `EffectResolver` 写过这条红字）⇒ 换进程 / 换运行时放**同一份录像**，第 0 条就报分叉并 `break` 掉整条动作流。今天 Unity Mono 下字符串哈希恰好稳定 ⇒ **自检全绿、雷埋着** | 三处一律改走 `NetProtocol.Hash()`（31 进制滚动、**只由字符内容决定**）⇒ 同一个局面在任何进程/任何运行时算出同一个数 |
| **② D2 · `StateHash` 维度** | 只有「回合/行动/胜者 + 双方 张数 / 能量 / 督军四围 / 手牌≤12 / **牌库每 7 张取 1** / 棋盘每格四围」⇒ **演错了也可能判「同一局」** | 补 **13 维**（见 §二·2）+ 牌库/弃牌**全量** + 手牌 `CostDelta` + 棋盘**附魔** ⇒ 每一维都有「只改那一格 ⇒ 哈希必须变」的断言 |
| **③ E1 · AI 选牌 RNG** | 录制端 `PickOffensiveForAi` / `PickDefensiveForAi` 吃 **`ctx.Rng`**，回放端（`NetApply`）**不掷** ⇒ 开关打开时整条随机流错位。开关默认 `false`（生产不可达），自检也不覆盖 ⇒ **埋着的雷** | 走**方案 A**（录制端把抽取结果记进动作流、回放端直接用、不掷）＋ 录制端的骰子从 `ctx.Rng` 移到 **`ctx.AiRng`** ⇒ `ctx.Rng` 在录制/回放两边**序完全一致** |

**方案 A 而不是 B 的硬理由**（不是口味问题）：录制次序是
`Mulligan → EndMulligan → [这一格掷 Rng] → BeginTurn`，而回放次序是
`Mulligan → MulliganDone(= EndMulligan + BeginTurn) → [录到的结果]` ——
`BeginTurn` 自己就吃 `ctx.Rng`（`RuleCore.BeginTurn` 那条链）⇒ **即便回放端补掷一次，取到的也是另一段值**。
要走 B 就得让 `NetApply` 把环境卡那两条挪到 `BeginTurn` 之前（改结算次序），爆炸半径大得多。
⇒ A 才是与「动作流 = 起始条件 + 动作」这条契约同形的那一个；而且它**加强**了本线既有的
「AI 只吃 `ctx.AiRng`、不吃对局随机流」那条不变量（普查报告 §1·1 的第 3 行）。
同族先例：`SimpleAI.AiAction.CapturedPicks` 就是同一形状（**执行前抓答案、回放不再问**，见 `SimpleAI.cs:101-106`）。

## 六、顺手发现（只列，**没改**）

1. 🔴 **`MulliganDone` 那一格的轨迹在录制/回放两侧取的时机不一致 —— 带 trace 的录像会假报分叉。**
   - 录制：`OnMulliganDone` 里 `RecRaw(MulliganDone)` 取 `DeepHash` 时 **`BeginTurn` 还没跑**
     （`BeginBattleAfterSetup()` 在它后面，`BattleDriver.cs` 的 `OnMulliganDone`）。
   - 回放：`NetApply.Apply` 把 `MulliganDone` 落成 **`EndMulligan` + `BeginTurn` 两件**，
     `PlayReplay` 的 `DeepHash` 取在**两件之后**。
   - ⇒ 只要 `mulliganEnabled = true`（**出厂场景 `Battle.unity` 就是 `mulliganEnabled: 1`** ⇒
     **真实玩家的每一局都带换牌**），回放就会在 `MulliganDone` 那一条**假报分叉并 `break`**，
     接着终局 `StateHash` 也不等 ⇒ **`PlayReplay` 返回 false**。
   - 为什么今天没人发现：自检的驱动默认 `mulliganEnabled = false`（`BattleDriver.cs:6253`，自检钉子），
     §20 的录像那一段是在**关换牌**下录的 ⇒ **这条链一次都没被自检走过**。
   - **本笔没修**：它不是「随机流」问题（本笔的授权范围），而且正确修法要决定
     「录制次序 vs 回放次序」以谁为准（`MulliganDone` + 环境卡那两条都在 `BeginTurn` 前面）——
     那是**另一条账**，不该由本笔发明口径。⇒ 请主对话立账。
   - 本笔的 21·3③ 因此**显式清空 `trace`** 再放（见 §三的说明）。
2. **回放路径不调 `ApplyOffensiveEnvOnce`** —— 录制时换牌后 `BeginBattleAfterSetup` 会按选定的进攻卡
   切战场环境（雾/环境光/环境 prefab），回放只走 `NetApply`（`MulliganDone` → `EndMulligan` + `BeginTurn`），
   `BeginOffensiveRevealOrApply` 只在 `ApplyLoggedAction` 里对 `OffensivePick` 调一次 —— 单机回放
   **没有** `ApplyLoggedAction` 之外的触发点。⇒ 回放里战场环境**停在默认**（**表现差异**；
   `ApplyOffensiveEnvOnce` 只调 `EnvironmentApplier`，**不改引擎状态**）。判不准的那一半：联机重连那条路
   （`ApplyLoggedAction` 会调 `BeginOffensiveRevealOrApply`）是否有同样问题 —— **没查**（不在本笔范围）。
3. **`ReplayRecord.version` 3 → 4 ⇒ 玩家磁盘上的旧录像从今天起读不出来**（`Load` 出声 + 返回 null）。
   这是**有意**的（尺子换了），但主对话在汇报时值得点名一句。
4. **`typecheck.sh` 期间两次报 `RuleEngine/Core/` 的错**（`CounterAttack.cs(64) KeywordTable.Sniper` ·
   `RuleCore.cs(152) EffectResolver`），两次的内容还不一样 ⇒ 是**别的代理正在写那两个文件**。
