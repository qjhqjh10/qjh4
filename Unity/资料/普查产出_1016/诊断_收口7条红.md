## 1. ★★ A712 多行 `Top` 首行（期望 +10.26px，实测 116.58px）

- **① 归类**：β 实现缺陷（本轮 W25 新增算式写反）；**兼 γ** —— 相对 W25 之前读数**变差**：不带这一项时首行 = 53.06−2.49+12.94 = 63.5px（偏 ≈53px），带上之后 116.58px（偏 ≈106px）。
- **② 根因（现读）**：`VOffsetBlockWorld()` 返回的是「**块心相对本行行盒心**」（其推导是**向下为正**的距离），而它的 doc/报告自陈「本行行盒心相对块心（**向上为正**）」—— 两者差一个符号。`VOffsetWorldNow()` 末句 `- VOffsetBlockWorld()`（`:1573`）因此把「本该把整块**下移** L」变成了「**上移** L」。
  逐位核对（F=35 · 行盒高 L=53.06px · `(sum+Lk/2)−blockH/2` 对 `Top`(k=0,n=3) = `L/2−3L/2 = −L`）：`_vOffset = 12.94 − (−53.06) = 66.00px` = 日志 `VOffset(三行)=66.005px` ✓；首行墨心 = `L − 2.49`（块心摆位）+ 66.00 = **116.58** ✓；符号改正后 = `53.06 − 2.49 + (12.94 − 53.06)` = **10.26** = 目标 ✓。
- **③ 证据**：`Battle/Label.cs:1514`（`return (sum + lineBoxK * 0.5f) - blockH * 0.5f;`）· `:1452-1514` doc 自陈「向上为正」· `:1573`（`- VOffsetBlockWorld()`）· 断言 `Editor/BattleScene.cs:3404-3410` · 夹具 `:3385-3391` · 日志 `battle.log:6483` + `:6506`。
- **④ 最小修法（一行）**：`Label.cs:1514` → `return blockH * 0.5f - (sum + lineBoxK * 0.5f);`。（等价替代 = `:1573` 的 `-` 改 `+`，但那会让函数与自己的 doc/报告继续打架，不取。）
- **⑤ 风险**：只影响「`Top`/`Bottom` **且**多行」—— `n<2` 与 `Middle`/`Capline`/`Midline` 都在前面短路成 0 ⇒ §4.6d 那 4 条（含单行 `Bottom` + `SetAutoFitBox`）逐位不变。现场会跟着回到正确位置的是本轮**刚落档**的两处生产件：`Shell/ReferralPopupWindow.cs:445`（真 3 行 `Top`）与 `Core/CardWinBox.cs` 的 `EnchanterText`×5（`Bottom` + 折行）。⚠️ 没有任何断言量 `Label` **节点**位置（`_vOffset` 只加在 TMP 子节点上）⇒ `Editor/ShopScene.cs:4476`、`Editor/MainMenuScene.cs:7155` 的 `CheckAt` 不受影响。
