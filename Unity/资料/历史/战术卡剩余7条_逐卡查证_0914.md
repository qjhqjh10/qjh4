## 二、`Telephatic Domination`（偷控制权）—— ✅ **2026-09-16 已做**（原判「挂起」）

**语义**（能查到的部分）：把敌方一个部队的**控制者**在本回合内换成自己，并让它本回合能行动；回合结束归还。

**出处（逐层）**：
- 规则书中文版：**查不到「控制权变更」**（`:185` 迅捷 / `:98` 部署当回合不可行动，是仅有的相关两条）
- `rule_core.gd`：**全库 0 命中**（`take control` / `gain control` / `domination`）
- 反编译：`AbilityEffect.cs:36-37` `stealMinion=180` / `stealMinionSelf=185` ·
  `BattleActionType.cs:42` `stealMinion=39` ·
  `CardScript__ChangeOwner.c:2-4`（**有体，只有一行**：翻转 `param_1+0x40` 那个 owner 布尔）·
  `BattleManager__AddStealMinion.c:29`（有体，只看到建了个 type=39 的 `BattleAction`）
- 🔴 **`BattleManager__ResolveStealMinion.c` 只有闭包/状态机分配** —— 真逻辑在
  `_003CResolveStealMinion_003Ed__551.MoveNext`，**不在这次导出里**。

✅ **2026-09-16 已做** —— 原来判「**挂起**」，理由是「**本回合内、结束归还**」这个**时间维度三层全没有**，
**这条理由的前提已被推翻**：`ChangeOwner` 那一行**只翻一个 bool**（`param_1+0x40`）**正是答案** ——
原版的「归属」就是**一个可翻转的标志**，本来就不需要记时长、也不需要记原主。
我们的归属问的是**「这个单位待在谁的 `Board[]` 里」** ⇒ 落点 `EffectText.TryTakeControl` +
`EffectResolver.DoTakeControl`（**抢 = 换数组**），归还走 `RuleCore.EndTurn` 新增的那一段
（`BattleContext.TempControl` 记「原主 + 原格位」只是为了还回原位 —— ⚠️ 那条是**我们挑的**）。
反面证据（仍然有效，帮后面省时间）：`BattleActionType.cs` 全文 95 行里**没有** `returnControl` / `giveBack`
之类的名字；`CardScript.ChangeOwner` 全工程**只有一处定义、0 处调用**（调用点在没导出的 `MoveNext` 里）。

**我们这边的真空位**：`UnitState` **没有 Owner 字段**（靠棋盘反查 `EffectResolver.OwnerOf` / `FindSlot`）；
`BoardSpec` 是**固定格位**，没有原版那种「插入并外移」（`reorderMinionsInPlay=7`）。

**（原「若以后要做」的最小代价路线 —— 2026-09-16 **未采用**，留档。子代理给的，**未验证**）：**不搬格子** ——
给 `UnitState` 加 `int ControllerOverride = -1`，让 `OwnerOf` 先读它；
`CanPlayCard` / `IsValidTarget` / `DeclareAttack` 的目标侧判据全走 `OwnerOf`（迁移后自动跟对）。
代价：表现层要自己画「这格现在归谁」。
⚠️ 抢过来的单位**带不带 Fast 之外的关键词**（Vanguard / Stealth 那些按阵营判的）**三层都没写**，别自己发明。

## 三、`Spreading Corruption`（易伤 + 死亡传染）

**语义**：给一个敌方部队**易伤 4**；若它在**本回合**内死亡，把这**同一效果**再套到**另一个随机**敌方部队上。

🔴 **容易实现错的一点**：`Vulnerable 4` 是**永久关键词**（规则书 `:224` 没时限），
`this turn` 限定的是「**若它死了就传染**」这个**观察窗口**，**不是**易伤持续到回合末。
❌ 别照 `CardEffect.untilEndOfTurn` 那个字段名把易伤做成限时的。

**出处**：
- 规则书中文版 `:224` 脆弱 X「本单位每次受伤害 +X」· `:143`
- `rule_core.gd:4418-4419`（易伤加伤）· `:2411`（`GIVE_KW` 含 `vulnerable`）
- 🔴 **`rule_core.gd:3675-3676` 专为这句写过**：`if int(u["kws"]["vulnerable"])>0:
  _broadcast_when(ctx, ev_p, "vulnerable_died", …)`；`:3486` 有对应事件短语
  `["vulnerable_died","you",r"an enemy with vulnerable dies"]`
- ⚠️ **但 `another random enemy troop` 那一句在 gd 里 0 命中**；卡名也在反编译里 0 命中

**现状（2026-09-14 当时）**：前半句（`give vulnerable 4`）**已经通**（`GivePayload.GiveKw` 有 `vulnerable`，
伤害侧走 `RuleCore.DamageAfterReduction`）。—— ✅ 后半句 2026-09-16 也已做，见下。

✅ **2026-09-16 全通** —— 原来判「后半**挂起**」（**理由的前提已被推翻**，当年那四条理由留档在下面）：
🔴 **它不是条件** —— 走 `TryIf` 会在**施放当刻**求值（那一刻它还活着）⇒ 后半句**永远不发生且不报错**；
新路：`TryApplyOnDeath` / `TryFillDeathWatch`（跨句回填）→ `EffectOp.DeathWatchTarget` →
登记 `ctx.DeathWatches`（**新容器**）→ 死亡那一刻 `RuleCore.FlushDeathWatches` **复述一次**。
⚠️ 其中 ② 的裁定落成了「**只转一次、不递归**」（**我们挑的**）；断言 `TestBatch0916` ⑦。

**当年判「挂起」的四条理由（留档）：**
① **缺「非棋盘监听者」容器** —— `RuleCore.BroadcastWhen` 的监听者**只扫双方棋盘上的 `UnitState`**，
而这张是**已进弃牌堆的战术卡**；`WhenEventKind` 里也**没有 `vulnerable_died` 这个 kind**。
② **递归语义零依据**：`this effect` 字面包含这整句 ⇒ 第二个目标死了要不要继续传染？三层都查不到。
**必须显式定一条并标注「我们挑的」**。
③ **`another` = 排除集**：`EffectText.ParseTarget` 认 `a random enemy troop` 但**不认排除**。
④ 回合窗口我们**有**依据：`RuleCore` 的 `DeadUnits.Add(..., DeathTurn = ctx.Turn)`。

**一个更省的近似**（**未采用**，留档）：在 `CleanupDeaths` 死亡那一刻判
`u.Card.Id == 施放者记录的 id && u.DeathTurn == 记录回合`，命中就直接对随机另一个敌人再套一次。
⚠️ 只能撑**一次**传染，且「另一个」的排除集要显式做。

⚠️ 「另一个随机敌方部队」**空场的情况**（对面只剩它一个）卡面没写、三层也查不到
⇒ 按「**没有合法目标就什么都不做**」实现并标注。

## 四、`Bjorn's Shrine`（狂暴留场）—— ✅ **已落地**

**语义**：给一个友方单位 +2 生命（**连上限一起**，这条本来就对）；本回合它**下一次**用狂暴时
**不回牌库、留在场上**。

🔴 **出处（本轮唯一在反编译里有完整体的一条）**：
`CardScript__UsedActiveAbility.c:52-64` ——
`HasCurrentTrait(0x4f1)` = **1265 = ferocity** → `:55` **先** `BroadcastUnitFerocity` →
`:58` `HasCurrentTrait(0x4f6)` = **1270 = dontReturnFerocity**，**有它才跳过回牌库** →
`:59` `EnoughPendingDamageToDie`（要死也不回）→ `:64` 否则 `AddRecallToDeck(…, priority=3, …)`；
`:75-88` 用后 `SendRemoveEffect(..., 1)` **摘掉**（⇒ 一次性）。
`DefinedTrait.cs:130-131` `ferocity=1265` / `dontReturnFerocity=1270`。

⚠️ **「留在场上」和「本来就要死」是两个各自独立的短路**（反编译里就是两个条件），
别写成一个；我们这边后者对应原来那个 `u.IsAlive && Board[slot] == u`。

⚠️ **一次性 + 本回合两个修饰都要**：消费点在 `RuleCore.UseAlternative` 的狂暴那一段
（**用掉当场清**），兜底复位在 `UnitState.RefreshForNewTurn`。
只在后者清 = 「本回合每次狂暴都留场」。

⚠️ **别和 `SW42 Bjorn the Fell-Handed` 混**：那张写 `When a friendly unit uses Ferocity, it stays in play`
（**常驻、无 `next time`、无 `this turn`**）—— **另一张卡另一条语义**，归事件层。
`ReFerocityStay` 的判据卡住了整个句式；那条**今天仍判不认识**（断言钉着）。

**落点**：`UnitState.FerocityStay` · `EffectText.ReFerocityStay` / `TryFerocityStay` ·
`EffectResolver.DoFerocityStay` · `RuleCore.UseAlternative` 的狂暴段 · `UnitState.RefreshForNewTurn`。

## 五、`Raid Tactics`（常驻：友方狂暴 → 打敌方督军 2）—— ✅ **已落地**

**语义**：本场战斗**常驻** —— 只要一个**友方**部队使用狂暴，就对**敌方督军**造成 2 点伤害。

**出处**：
- `rule_core.gd:3493` 事件短语 `["ally_ferocity","you", r"a friendly (?:unit|troop) (?:triggers?|uses?) (?:a )?ferocity"]`，广播在 `:2382`
- 🔴 原版广播器 `BattleManagerSupport__BroadcastUnitFerocity.c`（**有完整体**）：
  发 `TriggerAbilitySignal(Ferocity=725)` → **场上在演的每张牌** → **当前回合方手牌** → **另一方手牌**，
  逐个调 `CardScript.TriggeredFerocity`(=726)
- ⚠️ `rule_core.gd` **卡名 0 命中**，`_resolve_tactic` 也**没有这族的注册器**
  （只有 `at the start|end of your turn` → `persistent_turn_start`）

🔴 **容器形状是本工程自定的**：原版也是「**牌**在听」，而这张卡的监听者是
**一张已经进弃牌堆的战术卡** —— 那一端在原版**同样找不到对应**
（`BroadcastTacticPlayed` 也带 `IsInPlay` 检查）。**如实标着，别当成查到了。**

**落点**：`EffectOp.When` / `PersistentEffect.Ev` ·
`EffectText` 里 `RePersistAny` 块的**第 ③ 支**（`when <事件>, <正文>`）·
`EffectResolver.DoPersist` 的 `Trigger == "when"` · **`EffectResolver.BroadcastPersistentWhen`**。

⚠️ **两个必须记住的点**：
① `BroadcastPersistentWhen` **必须排在 `BroadcastWhen` 那句「场上没人听就 return」之前**
   （和 `BroadcastCostWhen` 同一条教训 —— 否则自己场上一个兵都没有时**静默不生效**）。
② 事件短语**复用 `WhenEvents.Parse`**（`uses <关键词>` 那一族早在
   `WhenEvent.TryParseKeywordTrigger` 里，那条注释点名的就是这张卡）—— **别另写一份**。

⚠️ **先后次序无据**：我们的 `FireTriggerAt` 是**先结算触发者效果、再广播** `Triggers(keyword)`，
而且明写是「我们挑的」；原版 `UsedActiveAbility` 只证明「广播在**回牌库**之前」。

## 八、`Author of the Codex` —— ✅ **已落地**（2026-09-14 A4 批 4）

> **卡图复核**（铁律 7，`Ultramarines/2天赋/Warpforge_02_Author-of-the-Codex.png`）：
> `Ephemeral.` + `[典籍图标] Trigger the Codex ability of a friendly unit and choose a Codicil
> and put it in your hand`，费用 **2**。下面那些结论与卡面一致。

🔴 **做成了「通用动词」而不是只做这一句** —— 逐句探针跑全池**含 `trigger` 的 22 个分句**之后发现，
   这是一个**族**（8 张卡），只做这一句会让另外 7 句继续静默失效：
   · 带目标：`Author of the Codex`（UM）· `Duty's End`（GS，`💀 backlash:` 正文）·
     `Atalan Leader`（GS，`Strike:` 正文）· `Master Lazarus`（DA，`Agenda:` 正文，**一句话两个关键词**）
   · 尾句 `… and trigger their <X> abilities`：`Regimental Doctrine` · `Deathwing Assault` ·
     `Open Insurrection` · `Stomp Em` · `Codex Discipline`（5 句）
   ⚠️ **原来那 5 句的尾半句是被吞进目标短语里的**（探针实测：
   `heal 目标[own/unit 「all your units and trigger their regiment abilities」]`）——
   整句**判「认了」、卡面不打 `*`，而那半句永远不发生**。
   根因：`EffectText.SplitAndTail` 只看**第一个** ` and `，而载荷里自带 ` and `
   （`Give +2 Attack, +2 Armor **and** +2 Health …`）。⇒ 改成**往后扫到第一个「动词开头」的 ` and `**
   （全池只有 **4 句**受这个改动影响，4 句全是**修好**：见 `TestA4Batch4` ②）。

**语义**：① 选 1 个**友方单位**，把它的 `Codex:` 正文**现在结算一遍**（不等能量归零）；
② 从 3 张 `Codicil` 里选 1 张**进手牌**。

**出处**：规则书中文版 `:175` · `rule_core.gd:2397 _check_codex`（`_trigger_fx(ctx,p,u,"codex")`，
**只触发第一个**，`break`）· `:3407 _trigger_fx` ·
反编译 `BattleManager__AddTriggerCodex.c:27`（type `0x45=69=triggerCodex`）·
`CheckIfCodexTriggered.c:49`（`0x46=70=triggerPlayerCodex`）·
`CardScript__TriggerOtherCardCodex.c:22`（广播 `AbilityTrigger.TriggeredCodex=650`）·
`CardScript__CanPlayWithCodexNow.c:36`（`GetManaLeft == GetCurrentCost`）。

✅ **那条 🟡「要用户裁」的结论是「不判」**（**有证据，不再是拍板**）：
`CardScript__TriggerOtherCardCodex.c` 的**整个方法体只有一行** —— 发一个 `TriggeredCodex = 650`
的触发，**没有任何能量判据**。⇒ 「这条链路上不判能量」**有据**。
⚠️ 但**能力自身的条件读不到**（`AbilityLogic.CanPlayAbility` 方法体是空的）
⇒「原版强行触发时到底还判不判 `energy == 0`」**查不到**，绕过与否是**我们挑的**（代码注释里标着）。
实现：`BattleContext.ForcedTriggerDepth` + `ConditionHolds` 的 `"energyzero"` 分支。

**落点**（判据各只有一处）：
- `EffectText.TryTriggerAbility` + `ReTriggerAbilityOf` / `ReTriggerTheirAbility`
  （**关键词必须在 `CardDef.RoutableTriggers` 里**，否则判不认识 —— 宁可打 `*`，
  也不做一条「触发了但正文压根没收下来」的动词）。
- 🔴 **`codex` 必须进 `CardDef.RoutableTriggers`**（原来不在 ⇒ `TriggerOps("codex")` **恒为 null**）。
  ⚠️ **但不能只在那一处加** —— 见下。
- `RuleCore.TriggerKeywordOf` / `BeginForcedTrigger` / `EndForcedTrigger`
  （走 `FireTriggerAt`，**所有触发唯一的出口** —— 日志/事件/递归保护/「关键词被触发」广播都在那一处）。
- `EffectResolver.DoTriggerAbility` · `EffectDispatch["triggerability"]` ·
  `EffectText.NeedsTarget`（新动词默认 `true` ⇒ 尾句形态能**继承前半句的目标**）。

🔴 **踩到的坑（加 `RoutableTriggers` 会连累解析层）**：`ParseSegment` 会把「可路由触发前缀」
   （`Rally:` / `Strike:` …）**从整段开头剥掉**。`codex` 一进去，`Codex: <正文>` 的前缀就被剥了
   ⇒ `Dispatch` 里那个**挂 `EnergyZero` 条件的分支永远进不去** ⇒ 条件丢失 ⇒
   **Codex 不等能量归零就触发**（自检两条红：`能量不为 0 → Codex 不触发` 与
   `卡池里真的有 Codex: 的战术卡（0 条）`）。
   ⇒ 加了一份 `EffectText.PrefixKeepsMeaning`（**目前只有 `codex`**）：
   两个名单**用途不同、是子集关系**，不是同一张表。

⛔ **别把这一批的覆盖率算高 —— 同族里还剩一条没做**（写在新动词的注释里，也钉在自检里）：
- **嵌入的引号效果**：`Duty's End`（`Give "💀 Backlash: Trigger the Codex ability of all friendly
  units" to a friendly troop`）· 某单位的 `+2 Health and "Strike: Trigger this troop's Codex ability"`
  —— 这两句**外层解析得到**（引号那截当成 `give` 的载荷），而**里面的能力压根不会被授予**。
  它们**仍然挂在 ③ 栏**（`嵌入的效果文字解析不了`）—— `TestA4Batch4` 没有为它们加断言，
  交接文档里的「完全解析」数字也**不要**因为这一批而对它们乐观。
- ⚠️ 另：`Righteous Repugnance` 的 `Heal them 1`（**全池只此 1 处**）在 `SplitAndTail` 改动之后
  从「静默吞掉」变成**如实判半懂** ⇒ 那张卡现在**打不出去**（`ErrUnimplemented`）。
  **这是好事**（原来那半句永远不发生、卡面还不打 `*`），但**不为它硬塞一条正则**（单例）。
