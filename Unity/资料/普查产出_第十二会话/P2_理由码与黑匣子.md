    ⇒ 它的信号与它的读法**是同一份口径**，不存在「检测器看得见、人类读不出来」的盲区；

## 3. 断言（+ 为什么**不自证**）

**`A1297`**

- `L⑨-b` `:714`：收侧日志流里出现 `[BattleResult] Cancelled(5)`。**不自证**：读的是**日志流**（⛔ 不是实现顺手写的镜像变量），
  删掉那句 `Debug.Log` 就红；且它与 `L⑤-b`（**发侧** `Cancel()` 自己记的）是**两条不同的代码路径** ⇒ 谁删哪一支只有对应那条红。
- `L⑨-c` `:719`：把同一行喂给 `ReplayStore.TryParseResultLine`，要求解出 `Cancelled` + `seat == -1`。
  **不自证**：与 `L⑨-b` **不同源**（那条比字面、这条比「匹配层写的」与「录像层读的」是不是一套）。
- `L⑫-b` `:756` ★★ **灭自证**：**开局之后**迟到的 `match.cancel` ⇒ **零条 token 行**；`L⑫-c` `:760` 那一局也没被撤。
  与 `L⑨-b` **结构上互斥**：把记码从 `else` 支提到 `case` 支外面（两支都记）⇒ **这条红、`L⑨-b` 照样绿**。
- `M⑩-b` `:1115`（掉线）/ `M㉑-b` `:1241`（`bye`）：两次都出现 `[BattleResult] Disconnect(3)`。
  ⚠️ 两条回调走**同一个出口**（`RevokeMatchLocal`）⇒ 一条断言就能管住两条路，⛔ 没在 `HandleLobbyPeer*` 里各写一份。
- `M⑩-c` `:1120` / `M㉑-c` `:1250`：同一行被录像侧解析器读回来（`Disconnect` + `seat == -1`）。**不同源**于各自那条字面比较。
- `M⑭-c` `:1164` ★★ **灭自证**：`had == false`（本机没在匹配这一局）时掉线 ⇒ **零条 token 行**。
  与 `M⑩-b` 结构互斥（把记码提到 `if (had)` 之外 = 无条件记 ⇒ 这条红、`M⑩-b` 绿）。
  🔴 **并配了「不空转」的证明**：`M⑭-d` `:1171` 断的是**同一跳真跑了**（`LastHint` 换成了 `NotMatchingThisGame` 那个 tail、
  且**不含** `MatchRevoked` 那个 tail —— 两个中文串**互不为子串** ⇒ 有鉴别力）。没有 `M⑭-d`，`M⑭-c` 可能是空转。
- `M⑯-b` `:1206`：闸（`LobbyHandled == false`）挡住时也**零条 token 行** —— 堵住「把记码挪到闸之前」。
- ⚠️ 所有正例都同时钉了**码是哪一档**（`Cancelled(5)` vs `Disconnect(3)` 分别出现、不互相冒充）。

## 4. 顺手发现（只报，⛔ 没动手）

1. `HandleLobbyPeerClosed`（`Net/NetMatchmaking.cs:222`）**没有 `_peerGone` 那道闸**（`HandleLobbyPeerLost:191-196` 有）⇒
   若「掉线」之后同一条会话又发 `bye`，第二跳会**再弹一次窗**、并把提示行改口成「本机本来就没在匹配这一局」
   （第一跳已经撤过局）。本轮只保证它**不会记第二条码**（`had` 闸），**弹窗那半没动**。
2. `case NetKind.MatchCancel` 收到 **迟到的**取消时**不回包**（`:_started` 支只 `LogWarning` + 弹窗）⇒
   真机上会出现「对面已退回大厅、本机照旧进战场」。注释里这就是原设计（「如实说、不假装两边一致」），
   但「不回包」这一点之前没被写出来。
3. `_started` 是**一个**静态量，却同时承担「我发过开局包」与「我收到过开局包」两种意思（`GoToBattle:647` 两端都置）——
   `Cancel()` 与 `RevokeMatchLocal` 都拿它当判据。单进程自检里分不出两端，⚠️ 真机上是**两个进程各一份**，暂无碍。
4. §T 那两条结构断言（`T①`/`T②`）其实**不依赖 Unity 的任何运行期设施**（`new BattleContext(seed)` + 两个 `List`），
   ⇒ 将来若要「不跑 Unity 也能验」，它们是最好搬的一批（纯逻辑）。
