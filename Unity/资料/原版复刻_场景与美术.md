## 二、战场背景是怎么来的

原版战场 `battlearena1` 早就重建成了 Unity 场景（`Assets/WarpforgeArena1/Scenes/BattleArena1.unity`，
28 网格 + 34 粒子 + 原版机位的相机）。**直接用它当背景**有个好处：原版量出来的槽位坐标
（玩家行 y=708 px / 敌方行 y=466 px）就是**在这个机位下量的**，贴上去位置正好对上。

```bash
# 烘背景（会打开 BattleArena1 场景 → 渲 1920×1080 → 存 Resources/Art/arena1_bg.png）
unset ELECTRON_RUN_AS_NODE && Unity.exe -batchmode -quit -projectPath "D:\4\Unity\MyGame" \
  -executeMethod ArtBaker.BakeFromCLI -logFile -
grep "^ART " d:/4/_tmp_view/artbake.log
```

**两个必须知道的点**：

1. **批处理下粒子不会自己走** —— 渲之前要 `ps.Simulate(4f, ...)`，否则烟/火/蒸汽全是空的。
2. **粒子的烟一开始渲成了一坨白方块** —— 因为 `BuildArena1` 给粒子用了 `URP/Unlit`，
   而**它不乘粒子顶点色**，`startColor` 里的灰度和透明度全丢。改成
   `Universal Render Pipeline/Particles/Unlit` 之后才对（改在 `BuildArena1.GetOrCreateParticleMaterial`）。

背景是**静态图**（一次性烘的）。原版战场里那些飘的烟/火是动态的 —— 以后想要动态的话，
把 `BattleArena1` 场景改成**附加加载** + 它自己的相机渲到 RenderTexture 就行，
`BattleBackdrop` 留了 `Image`/`Ready` 两个口子。

> 显示策略是「**铺满**」（cover）：宽高比和图不一致时按大的那边铺、多出来的裁掉，**不拉伸**。
> 16:9 下正好 1:1 对上（图 17.78×10 == 可见区），超宽/4:3 才裁。

## 三、卡框：分层 + 自动量 UV

原版卡框 PNG 是 **1024×1024，卡本体只占中间一块**（各阵营/各档的包围盒都不一样，
例：Ultramarines 卡框实测 `x[201,808] y[56,991]`，见 `资料/战斗UI_原版对账表.md` §五），
四周是透明留白。直接铺满 quad 的话卡会缩成一小块还偏。

`CardView` 的做法（**换任何卡框 PNG 都自动成立**）：

1. 开 Read/Write（`ArtBaker.ApplyImportSettings` 里对 `cards/` 下的图设 `isReadable = true`）
2. 运行时 `GetPixels32()` 扫一遍 alpha，量出不透明包围盒 → 缓存成 UV 矩形
3. 卡框那一层用**自定义 UV 的 quad**（`FrameMesh`），把 UV 裁到卡本体

卡牌是**四层 + 一层独立的 rim 描边**，和原版一样（rim 是单独一份，不跟四层共用）：

```
info      数值/名字/关键词（我们画的，透明底）        z -0.02   ← 最前
artFront  立绘的**角色抠图**（越出卡框；只有清单里的卡有）z -0.008
frame     卡框（原版 PNG，UV 裁到卡本体）             z  0
art       立绘（原版插画；没有对应文件时退回程序生成的占位图）z +0.03
rim       状态描边（高亮/置灰）                      z +0.05   ← 最后（衬在整张卡后面）
```

⚠️ `artFront`（**前景立绘层**）是后加的第 4 层：有角色抠图的卡要画**两层立绘** ——
完整插图用 `CardPresentation/ArtOpaque` shader 垫在卡框**下面**（**只取 RGB、忽略贴图自带的 alpha**，
否则立绘的透明区会把卡框透出来），角色抠图盖在卡框**上面**，角色因此「越出卡框」。
**判据是清单、不是卡型**：`Resources/Art/cards/card_cutouts.json`（665 张，问 `CardArt.HasCutout`）——
没有立绘（回退占位图）的卡不在清单里，**绝不能给它加前景层**（那会把卡框整个盖住）。
出处：`Core/CardArt.cs:111`（`HasCutout`）· `Core/CardView.cs:466-469,760-768` · `Shaders/ArtOpaque.shader`。

立绘的取法是 `CardArt.Portrait(卡名)` → `Art/cards/art_<卡名小写下划线>.png`，
**没有文件就自动退回占位图** —— 换自己的画只要按同名放进去。

**数值位置是照原版卡框量的**（`CardView.cs:125-129` 的 `CostAt/MeleeAt/RangedAt/ArmourAt/HealthAt`）：
费用在**右上**（`(0.8766,0.3001)`，盖在阵营徽记上）、近战/远程在**左下**的红/紫宝石、生命在**右下**的绿六边形、
**护甲在右侧的盾牌**（`(0.9296,0.7975)` —— 这一格原来**根本没画**，是后补的）。

> ⚠️ 别把费用挪回左上 —— 原版手牌的层序是「左卡压右卡」，牌挨着的时候**露出来的是每张牌的右半边**，
> 费用和生命必须放右边。

**贴图尺寸**：`FaceW×FaceH = **256×407**`（比例 0.629，`CardView.cs:115`）跟着原版卡框的本体比例
（0.628）走，这样卡框铺满 quad 不会被拉变形。

> ⚠️ **2026-09-13 更正**：原来写 **256×371**（比例 0.690）。那是照**旧卡框**量的 ——
> 卡框换成分档那套之后卡本体比例变成 0.628，高度跟着从 371 改到 **407**。

## 四、原版 UI 图是**怎么从图集里切出来的**（可复用）

原版战斗 UI 的图都在一个 2048² 的图集里（`BattleAtlasUI`），**Unity 的 Sprite 数据里没有图集坐标**：

- `Sprite.m_Rect` / `m_RD.textureRect` 全是 `(0,0,w,h)` —— 那是 sprite 自己的尺寸，不是它在图集里的位置
- `uvTransform` 是枢轴偏移，也不是位置
- **真正的位置在 `SpriteAtlas.m_RenderDataMap` 里**（`textureRect` 字段），按 `m_PackedSprites` 的顺序一一对应

脚本：`d:/2/Warpforge_tools/slice_battle_atlas.py`（UnityPy 1.24.2，用
`d:/2/Warpforge_tools/py312/python.exe` 跑）。产物 60 张切片在
`Unity/素材/Warpforge原版/UI图集/图集/battleatlasui/sliced/`（那是**备查库**，
实际用的是拷进 `Resources/Art/ui/` 的 **54 张**）。

要切别的图集（主菜单/通用窗口/…），把脚本里的 `BUNDLE` 换掉即可，
bundle 在 `d:/2/Warhammer 40k Warpforge/Warpforge_Data/StreamingAssets/aa/StandaloneWindows64/`。

## 六、踩过的坑

| 坑 | 真相 |
|---|---|
| **NPOT 缩放会把背景图改尺寸** | Unity 默认把非 2 次幂的图缩到最近的 2 次幂 —— 背景图 1920×1080 会被拉成 **2048×1024**（宽高比 1.78 → 2.0），一「铺满」就整体放大 12.5%，和原版量出来的槽位对不上。`textureImporter.npotScale = None`（UI 切片同理，182×112 这种尺寸全会被改） |
| **共享材质上改 mainTexture** | 所有卡会共用同一张贴图。每层都要 `new Material(模板)` |
| **粒子用 `URP/Unlit` 会丢顶点色** | 烟/蒸汽渲成一坨白方块。要用 `Particles/Unlit` |
| **组件上的私有引用不进序列化** | `BattleBackdrop` 存了场景之后 `_mr/_tex` 是 null，运行时得从子节点重新找一遍（`Build()` 里做了） |
| **HUD 图和文字的 z 撞在一起** | 都在 z=0 时谁压谁看渲染顺序，实测按钮底图会把文字盖住。图统一放到 z=+0.3 |
| **`SpriteAtlas.m_RenderDataMap`** | 图集切片的图集坐标只在这儿，别在 `m_Rect` 上找 |
