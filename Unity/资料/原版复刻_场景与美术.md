## 一、美术放在哪 / 怎么换

```
Assets/CardPresentation/Resources/Art/
├── arena1_bg.png            1920×1080 战场背景（ArtBaker 从 battlearena1 场景烘的）
├── cards/
│   ├── frame_ember.png      阵营卡框（原版空框，1024²，中间是透明美术窗口）
│   ├── frame_tide.png
│   ├── back_ember.png       卡背（牌堆用）—— 黑色军团「荷鲁斯之眼」
│   ├── back_tide.png        卡背 —— 灵族 Asuryani Path
│   └── art_<卡名>.png       26 张立绘（原版卡的插画，按角色挑的，见下表）
└── ui/                      原版战斗 UI 图（从图集里切出来的）
    ├── UI_Button_End_Turn_Normal_wide.png   END TURN 按钮底图
    ├── 40k_battle_energy_full / _empty.png  能量宝石
    ├── UI_Player_Frame.png                  名牌
    ├── Attack_type_button_Melee / _Ranged.png   攻击方式按钮（红拳套 / 紫枪）
    ├── Attack_type_button_highlight.png         按钮选中黄圈
    ├── Attack_type_Generic_Foreground.png       主动技能按钮的**占位**底图（见下）
    ├── 40K_melee_glow / 40K_ranged_glow.png     单位身上的高亮光圈（红 / 紫，见下）
    └── ...（60 张切片里挑出来的 17 张）
```

**立绘怎么来的**：原版把「卡框」和「插画」拆成两份资产
（`d:/2/解包整理/01_卡牌/<阵营>/Texture2D/` 下 `*_Cardframe_*` 和 `*_inf_/ _veh_/ _war_/ _monster_`），
插画是干净的 662×1024 立绘、不带字。我们的 26 张卡按**角色**挑了对口的：
Ember→黑色军团、Tide→Saim-Hann 灵族。对应关系写在
`Resources/Art/cards/` 的文件名上（`art_scavenger.png` ← `inf_Chaos Legionary`）。

代码里所有的取图都走 `Core/CardArt.cs`：

| 要什么 | 怎么取 |
|---|---|
| 背景 | `CardArt.Backdrop` |
| 阵营卡框 | `CardArt.Frame("Ember")` → `cards/frame_ember.png`（**阵营名大小写不敏感**） |
| UI 图 | `CardArt.Ui("UI_Button_End_Turn_Normal_wide")` |
| 有没有装美术 | `CardArt.Available` |

> ⚠️ **`Attack_type_Generic_Foreground.png` 是我们挑的占位，不是原版的做法。**
> 原版 `Select Active Skill Button` 的 `m_Sprite` 是**空的** —— 它在运行时由
> `buttonIcon` 赋（多半是每张卡自己的技能图标）。那张 `Generic Foreground` 虽然名字像，
> 但全 `d:/2/解包整理` 里**只有图集自身引用它**，没有任何 GameObject/Prefab 用它。
> 换自己的美术时，给每张有技能的卡配一张图标才是正路。
>
> ⚠️ **`40K_melee_glow` / `40K_ranged_glow` 的真正用途是「单位身上的高亮」**，
> 不是按钮的外发光 —— 见 `08_预制体特效/战斗预制体/GameObject/Highlight_*.json`
> 和 `Highlight ranged_*.json`（挂在 `CardPrefab/…/Base Attack Counters/Melee|Range Attack Container` 下）。
> 这两张图**目前还没接进战斗**，规格和「锚点待确认」的说明在
> `资料/规则引擎_进度与交接.md` 第七节。

**换自己的美术**：把自己的图按同名放进去就行 —— 卡框会自动重新量「卡本体在哪」（见下），
不用改代码。**换阵营**：加 `cards/frame_<阵营小写>.png`，`CardData.faction` 填那个名字。

**删掉整个 `Resources/Art/`**：`CardArt.Available` 变 false →
卡走 `CardView` 的程序生成黑卡、背景不建、HUD 退回纯文字。自检里那几条美术断言会自动跳过。

> ⚠️ **版权**：`Resources/Art/` 和 `Assets/WarpforgeArena1/` 都是 Everguild / Games Workshop 的资产，
> **发布前必须整个移出构建**。用户做的是「模仿玩法 + 自出美术」，原版美术只能当复刻参考。

## 二、战场背景是怎么来的

原版战场 `battlearena1` 早就重建成了 Unity 场景（`Assets/WarpforgeArena1/Scenes/BattleArena1.unity`，
28 网格 + 34 粒子 + 原版机位的相机）。**直接用它当背景**有个好处：原版量出来的槽位坐标
（玩家行 y=708 px / 敌方行 y=466 px）就是**在这个机位下量的**，贴上去位置正好对上。

```bash
# 烘背景（会打开 BattleArena1 场景 → 渲 1920×1080 → 存 Resources/Art/arena1_bg.png）
unset ELECTRON_RUN_AS_NODE && Unity.exe -batchmode -quit -projectPath "D:\4\Unity\MyGame" \
  -executeMethod ArtBaker.BakeFromCLI -logFile -
grep "^ART " d:/4/_tmp_view/artbake.log
```

**两个必须知道的点**：

1. **批处理下粒子不会自己走** —— 渲之前要 `ps.Simulate(4f, ...)`，否则烟/火/蒸汽全是空的。
2. **粒子的烟一开始渲成了一坨白方块** —— 因为 `BuildArena1` 给粒子用了 `URP/Unlit`，
   而**它不乘粒子顶点色**，`startColor` 里的灰度和透明度全丢。改成
   `Universal Render Pipeline/Particles/Unlit` 之后才对（改在 `BuildArena1.GetOrCreateParticleMaterial`）。

背景是**静态图**（一次性烘的）。原版战场里那些飘的烟/火是动态的 —— 以后想要动态的话，
把 `BattleArena1` 场景改成**附加加载** + 它自己的相机渲到 RenderTexture 就行，
`BattleBackdrop` 留了 `Image`/`Ready` 两个口子。

> 显示策略是「**铺满**」（cover）：宽高比和图不一致时按大的那边铺、多出来的裁掉，**不拉伸**。
> 16:9 下正好 1:1 对上（图 17.78×10 == 可见区），超宽/4:3 才裁。

## 三、卡框：分层 + 自动量 UV

原版卡框 PNG 是 **1024×1024，卡本体只占中间一块**（实测 x 201..847, y 56..991，
占比 63%×91%），四周是透明留白。直接铺满 quad 的话卡会缩成一小块还偏。

`CardView` 的做法（**换任何卡框 PNG 都自动成立**）：

1. 开 Read/Write（`ArtBaker.ApplyImportSettings` 里对 `cards/` 下的图设 `isReadable = true`）
2. 运行时 `GetPixels32()` 扫一遍 alpha，量出不透明包围盒 → 缓存成 UV 矩形
3. 卡框那一层用**自定义 UV 的 quad**（`FrameMesh`），把 UV 裁到卡本体

卡牌是三层的，和原版一样：

```
info   数值/名字/关键词（我们画的，透明底）   z -0.02  ← 最前
frame  卡框（原版 PNG，UV 裁到卡本体）       z  0
art    立绘（原版插画；没有对应文件时退回程序生成的占位图）  z +0.03  ← 最后
rim    状态描边（高亮/置灰）                 z +0.05
```

立绘的取法是 `CardArt.Portrait(卡名)` → `Art/cards/art_<卡名小写下划线>.png`，
**没有文件就自动退回占位图** —— 换自己的画只要按同名放进去。

**数值位置是照原版卡框量的**（`CardView` 里的 `CostAt/NameAt/KwAt/MeleeAt/RangedAt/HealthAt`）：
费用在**右上**（盖在阵营徽记上）、近战/远程在**左下**的红/紫宝石、生命在**右下**的绿六边形。

> ⚠️ 别把费用挪回左上 —— 原版手牌的层序是「左卡压右卡」，牌挨着的时候**露出来的是每张牌的右半边**，
> 费用和生命必须放右边。

**贴图尺寸**：`FaceW×FaceH = 256×371`（比例 0.690）跟着原版卡框的本体比例（0.691）走，
这样卡框铺满 quad 不会被拉变形。

## 四、原版 UI 图是**怎么从图集里切出来的**（可复用）

原版战斗 UI 的图都在一个 2048² 的图集里（`BattleAtlasUI`），**Unity 的 Sprite 数据里没有图集坐标**：

- `Sprite.m_Rect` / `m_RD.textureRect` 全是 `(0,0,w,h)` —— 那是 sprite 自己的尺寸，不是它在图集里的位置
- `uvTransform` 是枢轴偏移，也不是位置
- **真正的位置在 `SpriteAtlas.m_RenderDataMap` 里**（`textureRect` 字段），按 `m_PackedSprites` 的顺序一一对应

脚本：`d:/2/Warpforge_tools/slice_battle_atlas.py`（UnityPy 1.24.2，用
`d:/2/Warpforge_tools/py312/python.exe` 跑）。产物 60 张切片在
`Assets/CardPresentation/Art/原版/ui/`（那是**备查库**，实际用的是拷进 `Resources/Art/ui/` 的那 13 张）。

要切别的图集（主菜单/通用窗口/…），把脚本里的 `BUNDLE` 换掉即可，
bundle 在 `d:/2/Warhammer 40k Warpforge/Warpforge_Data/StreamingAssets/aa/StandaloneWindows64/`。

## 六、踩过的坑

| 坑 | 真相 |
|---|---|
| **NPOT 缩放会把背景图改尺寸** | Unity 默认把非 2 次幂的图缩到最近的 2 次幂 —— 背景图 1920×1080 会被拉成 **2048×1024**（宽高比 1.78 → 2.0），一「铺满」就整体放大 12.5%，和原版量出来的槽位对不上。`textureImporter.npotScale = None`（UI 切片同理，182×112 这种尺寸全会被改） |
| **共享材质上改 mainTexture** | 所有卡会共用同一张贴图。每层都要 `new Material(模板)` |
| **粒子用 `URP/Unlit` 会丢顶点色** | 烟/蒸汽渲成一坨白方块。要用 `Particles/Unlit` |
| **组件上的私有引用不进序列化** | `BattleBackdrop` 存了场景之后 `_mr/_tex` 是 null，运行时得从子节点重新找一遍（`Build()` 里做了） |
| **HUD 图和文字的 z 撞在一起** | 都在 z=0 时谁压谁看渲染顺序，实测按钮底图会把文字盖住。图统一放到 z=+0.3 |
| **`SpriteAtlas.m_RenderDataMap`** | 图集切片的图集坐标只在这儿，别在 `m_Rect` 上找 |
