## 三、本会话查清的关键结论（**判据 + 更正痕**）

### 3·1 🔴 `LoadingMenu` 的方向原来是反的（**这条最要紧**）
`D1` §5 写「`down=0` = **补间到全黑**、结束后自己关掉」—— **照那个做出来是黑屏卡住**。实读纠正：
参数名是 **`show`**（`dump.cs:109207`），里面是「`SetActive(true)` → **立刻** α = `show?0:1` → `DOFade(show?1:0, 1.25s)` → 回调 `if (show) return; else SetActive(false)`」
⇒ **进战斗（`show=false`）= 立刻全黑 → 补间到【透明】 → 自己关掉**；时长 = **1.25 s**（实读常量 `0x1834B2EC0`，**不是**「寄存器里读不出」）；`DAT_1834b2bb8` = **1.0f**（读到的）。

### 3·2 🔴 两条方法论级的坑（已进 `资料/已知的坑.md`）
- **「反编译里 0 调用点」很可能是【被内联】**，不是「不可达」—— 实例：`BattleManager.ResolveMultiDamage` 等 63 个 `Resolve*` 全是 0 调用点，真因是 `ResolveAction` 那张 **91 项跳转表**把工厂逐指令内联了；**反证**：那 63 个里含 `ResolveDrawCard`/`ResolveHeal`，显然在跑。
- **`decomp_full/` 里有【文件名与内容不符】的条目** —— 实例：`VoiceLinesController__ToggleMute.c` 里装的是 `EntityScript__set_isPlayer` ⇒ **引方法体前先核内容**，拿不准就按 RVA 现反汇编。

### 3·3 战斗音响 / HUD / 教程 / 镜头（逐条带指针）
- **`unitDamage`**：原版**只在该批【最后一个目标】那一下播**，且**普通攻击不走它** ⇒ 我们做成纯函数 `BattleDriver.UnitDamageCueIndex`（跳过紧跟 `EvtKind.Attack` 的 hit、只认最后一条），5 条断言。见 `任务/T06`。
