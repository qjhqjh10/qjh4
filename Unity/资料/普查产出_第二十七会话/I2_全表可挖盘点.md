## 五、`Card_Name` / `Card_Description` 那两个数为什么对不上（硬要求）

**结论：主要不是「我们卡池缺」，是「键名不同源」—— 官方有一大批键用的是 32 位 GUID，而我们的 `card_ids.json`
没把它们解出来，于是我们自己造了 `ASH_Path_of_the_Seer` 这种 id。**

| 量 | `Card_Name` | `Card_Description` |
|---|---:|---:|
| 官方键数 | **1065** | **1101** |
| 我们卡池 | **1126** | 1126 |
| **按 id 直命中** | **837** | **835** |
| 官方有、我们池没有 | **228** | **266** |
| ↳ 其中 **32 位十六进制 GUID 键** | **124** | **147** |
| ↳ 其中 纯 id（`AM3`/`BL57`…） | **98** | 其余 |
| ↳ 其中 `OLD_*` / 带下划线 | 6 | 其余 |
| 我们池有、官方没有 | **289** | 291 |
| ↳ 其中 **我们自造的 id（带下划线）** | **187** | — |
| ↳ 其中 纯 id（`DA75..86`/`EC72..77`/`SW1..10`） | **102** | — |
| **改用「id → 英文名」两级查之后** | **974 / 1126** | **972 / 1126** |
| 剩下**真·快照没有** | **152** | **154** |

**证据（可复算）**：
- 那 124 个 GUID 键里 **105 个的英文名能在我方卡池找到同名卡** —— 例：官方 `Card_Name/09bcb1b3b8794c4429d82d4b2e68fa1f`
  = `Path of the Seer`/`先知之道`，我方是 `ASH_Path_of_the_Seer`（同英文名）⇒ **那串 GUID 才是这张卡的真 id 形态**。
- 98 个纯 id 里 **33 个**同样按英文名对上我方（例：官方 `Card_Name/BL57` = `Hellfire Torch`/`地狱火炬` ↔ 我方 `BL_Hellfire_Torch`）。
- 反向那 289 张里 **187 张是我方自造 id**（`cards_engine.json` 的 `_note` 自己写着「自造 id 形如 `AM_Some_Card`（带下划线）」）。
- 剩 152 张两族都拿不到，前缀 = `SW 68 · UM 37 · DA 13 · GOF 9 · EC 7 · TAU 7 · SAU 5 · AM 2 · SOR 2 · BL 1 · GSC 1`
  ⇒ **正是 2025-07-30 之后新增的阵营**，与「快照时代限制」自洽。
- 另：`Card_Description` 比 `Card_Name` 多 36 条，其中 **49 条描述键没有同名卡名键**（26 条是 GUID 形态）。

**对「能不能整批换」的结论**：**不能只按 id 整批换**（会漏掉 137 张 = 974−837 张名 / 137 张描述）。
要写成 **「先按 `id` 查、查不到再按英文名经 `Card_Name` 桥到同一个键」** 两级；这样 Card_Name 837→974、Card_Description 835→972。
