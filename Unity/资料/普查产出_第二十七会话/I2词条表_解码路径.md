# I2 词条表（`localization_temp_*_未解密.bin`）—— 解码路径

> 结论：**已解开**。9,412,193 字节 = **硬编码密码的重复密钥 XOR 流**（I2 Localization 自带的
> `LanguageSourceAsset` 加密源），XOR 回去就是 UTF-8 的 JSON。**脚本已跑通**：
> `python -I -X utf8 d:/4/Unity/工具/_i2_decode_probe.py`
> 产出 **9,447 条词条 × 15 列**（其中 **zh-CN 非空 9,440 条**）。

## 一、结论四问答

**(a) `LanguageRemoteAsset` 读没读那个 byte[]？** —— **没读，它一个方法都没有**。
那 9.4 MB 是 **`I2Languages` 这个 `LanguageSourceAsset` 的 `temp` 字段**；
`LanguageRemoteAsset` 只是个壳（唯一字段 `source` @ `0x18`），
真正的读取发生在 `LanguageSourceAsset.get_SourceData` → `DecryptData()`。

**(b) 那 9.4 MB 是什么？** —— **既不是压缩、也不是纯文本，是 XOR 混淆过的 UTF-8 文本**
（明文就是完整的 `LanguageSourceData` JSON）。实证：① 还原后 **首字节即 `{`**、末字节即 `}`
（**没有头部要剥**）；② `bytes.decode('utf-8')` 全程无异常，得 **7,880,532 个字符**；
③ `json.loads` 从头解析到尾成功，顶层键就是 `LanguageSourceData` 的字段名
（`mTerms` / `mLanguages` / `Spreadsheet_*` …）。

**(c) 加密算法 / 密钥从哪来？** —— 算法 = **逐字节重复密钥 XOR**（无 AES/DES、无 IV）：
`temp[i] = ((i 偶 ? 0x17 : 0xCD) * i) ^ temp[i] ^ (byte)password[i % password.Length]`。
密钥 = **硬编码的字符串字面量**：`LanguageSourceAsset` 的静态字段 `stringObfuscatorPassword`，
由 **cctor** 从字符串字面量 **VA `0x18427C678`**（= `stringliteral.json` 里的 `0x427C678`）`.ToCharArray()` 得到，
**138 个字符 / UTF-8 199 字节**（同一串也被 `I2.Loc.StringObfucator` 的 cctor 用）。
**密码原文在 `global-metadata.dat` 偏移 `0xf2ae8` 处可逐字节查**。

**(d) 不跑 Unity、不联网能不能解？** —— **能，已经跑通**。脚本 = `d:/4/Unity/工具/_i2_decode_probe.py`
（纯 `json/io/os` 标准库，`--in / --out / --grep / --limit`）。

## 三、试过什么、为什么排除

| 方法 | 结果 | 判据 |
|---|---|---|
| gzip / zlib / raw deflate / lzma / bz2（整份 + 前若干字节） | ❌ **均失败**（前任做过，本轮**未重复**） | 与本轮结论不冲突：明文本来就不是压缩流 |
| 盲猜 XOR 密钥 | ❌ 不需要了 | 走对了路：**从第一权威反编译方法体读算法**，密钥有确切出处 |
| 直接 `(byte)password[i]` 与 `(char)password[i]` 两种取法 | ✅ 取**低字节**才通 | `DecryptData.c:48` 是 `*(byte *)(lVar5 + 0x20 + uVar9*2)`（char 数组按 2 字节步长、只读低字节）；而 `StringObfucator.XoREncode.c` 那条是 `*(ushort *)` 取整 16 位 —— **两条不是一回事，别混用** |
| 需要剥掉文件头吗 | ❌ **不需要** | 首字节 XOR 后就是 `{` |
| 密码 138 字符 vs 69 字符（dumped 值里能看到 69 字符的重复段） | 两种长度**XOR 流完全相同**（138 = 69×2） | 且 `global-metadata.dat` 里 199 字节的 **138 字符原串**整段命中 ⇒ 138 是准数 |
| 轮外尝试：`_DAT_` 常量手读 / VA 反汇编 | 未用到 | 本轮**不需要** —— `.c` 里方法体和字面量表都是齐的 |

## 四、还没查清的 / 还差什么

1. **`LanguageRemoteAsset` 与 `I2Languages` 是不是同一只包里的两个对象** —— 本轮只按「`source` 指向
   `LanguageSourceAsset`」推的；**没验证** `LanguageRemoteAsset.source` 的 PPtr 是否就指向这只 `I2Languages`。
   （不影响解码结论：byte[] 确实在 `I2Languages` 上，且算法/密钥都已实证跑通。）
2. **这 9,447 条 ≠ 当前客户端在用的全量** —— 这是 **2022.3.38f1 / 2025-07-30** 的远端包快照；
   后来加的阵营（SpaceWolves / Ultramarines / DarkAngels 等）**这里没有**（`Card_Description` 只到 DA/UM/BL/TA/… 那批）。
   ⇒ 每个键族「还缺不缺、缺哪几条」**没盘**（本轮只统计了族内条数，没和我们的键表逐条对账）。
3. **密码是否与语言/平台相关** —— 只见到这一处字面量、两个 cctor 引同一个地址；**没查**有没有第二份 build
   用不同密码（本机只有这一份 `GameAssembly.dll`）。
4. **`ProcessBundleLanguage` / `AssetCompletedLoading` 里那些被标成
   `System_Collections_Generic_List<AnimatorClipInfo>__get_Item` 的调用是 ICF 折叠错名**
   （那段逻辑在操作 I2 的 source 列表，不可能是 `AnimatorClipInfo`）⇒ **名字不可信，语义按上下文**。
   本轮结论不依赖它们，但要读那两段时要小心。

## 五、顺手发现（请主对话分流）

1. 🔴 **原版确实有官方 zh-CN 全量表**（9,440/9,447 条非空），而且**不在客户端本地、在远端包里** ——
   这**补上了** `CLAUDE.md` 那条「原版客户端根本没有中文表（246,807 个文件扫中文串零命中）」的**原因**：
   不是没有，是**这份表由远端 Addressables 包下发**，离线包体里当然扫不到。
2. 🔴 **zh-CN 里 Warlord 一律译作「战将」**：全表 `战将` **129** 处 · `督军` **0** 处 · `术士` **1** 处
   （例：`Achievements/Ach_1` EN `Deal damage to the enemy Warlord` → ZH `对敌方战将造成伤害`；
   `Battle/Tips/AttackGiantKiller` EN `You must attack the Warlord or a Front Line unit` → ZH `你必须攻击战将或前线单位`）。
