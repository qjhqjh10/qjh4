## 顺手发现（⛔ 一个字都没改）

1. 🔴 **`BattleDriver.AbilityPickOwner` 的 doc 已过期**（`BattleDriver.cs:14100-14130`：说「引擎结算层只认敌方 `1-p`、`EffectTargets` 没有友方规格」）——E8-1 之后**两句都不成立**（`EffectTargets.FriendlyUnit`、`RuleCore.ChooseAbilityTargetOwner/UseAbilityCore` 的 `targetOwner`）。不改正则下一个人会按它去「先打开表现层」⇒ 重演 `E5-2` 的静默错打。
2. **`TargetCriteriaEval.cs:151-153` 的 `case 100` 口径错**：原版 `FilterMethods__CheckIfMeetsCriteria.c` **没有 ta=100 分支**（`grep 0x64` = 0 命中）⇒ 应 `break` 走常规格，不该 `gap=未实现`（现会「出声放行」= 少筛）。数据里有 **17 行** ta=100。
   🔴🔴 **2026-10-25 就地订正（执行代理 `X3` · 铁律 5）—— 这条的后半句是错的**：
   「原版没有 ta=100 分支」**不成立**。`CheckIfMeetsCriteria.c` **尾巴 `:407`** 明写
   `if (*(int *)(param_4 + 0x10) != 100) { return 1; }`，`:411-425` 再走
   `BattleManager__GetAdjacentUnits(manager, thisCard)` + `List.Find(predicate)`
   ⇒ **`ta=100` 还多一条「thisCard 的相邻里至少有一个满足同一份 criteria 的单位」**。
   之所以 `grep 0x64` = 0 命中，是因为**反编译器把常量印成了十进制 `100``（不是十六进制）**。
   ✅ **前半句仍然成立、且已落地**：早返 switch（`:56-160`）里确实没有 100 这一档
   ⇒ 常规 36 格要先判（`X3` 已把 `case 100` 改成 `break` 落进常规档）；
   ⚠️ **尾巴那一截本版仍未实现**，由函数尾的 `ta == 100 ⇒ gap + return null` 兜住
   （`null` = 判不了 ⇒ 保留候选 + 出声）。判据全文 → `资料/普查产出_1025/X3_引擎判据缺口_执行报告.md` §4。
3. `J5` §七·3 的「20 可判 / 3 判不了」少算 `DA33`（应 19/4）——见 §一。
4. 台账 `:175` 的「`terror` 的 `get_currentCombatAttack` 未读」与 `:117`（B3 已修）冲突：**:175 过期**，方法体已全读并实现（`Core/CounterAttack.cs`）。
