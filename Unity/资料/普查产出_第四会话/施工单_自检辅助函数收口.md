## ⑥ 回归怎么证（含「灭自证」）

**断言本体是检测器、也是被改的实现** ⇒ 自检自己的绿**证明不了**这次重构没改判据。三层，缺一不可：

1. **改前存档**：跑全套 12 条，把 **7 条相关 `*.Run`（`CollectionScene` / `DeckScene` / `MainMenuScene` / `RewardsScene` / `SettingsScene` / `ShellScene` / `ShopScene`）的完整 stdout 落盘**（含每一条 `✓`/`✗` 的行序与文案、以及末尾合计行）。
2. **改后逐字节比对**：**同一 seed、同一顺序**再跑一次，与存档 diff。判据只有一句话：
   **「通过数、失败数、失败清单文本、`✓` 行数 —— 四者逐字节相同」**。
   这条**结构上挡得住「实现和检测器一起改回去」**：把某条断言削弱 ⇒ `_pass` 计数掉一（或 `✓` 行消失）⇒ diff 立刻显形；把期望值改成我们的常量 ⇒ `_failures` 文本变 ⇒ 同样显形。**不需要新写断言**（新写断言 = 改判据，本就禁止）。
3. **计数器路由的专门断（这一条才是本活独有的「灭自证」）**：这是**唯一**无法靠 diff 覆盖的失效模式 ——「**失败被记进别人的合计里**」（`RewardWindowFixture.cs:12-14` 点名的那个）。做法：**临时**在某一宿主（如 `ShellScene`）里插一句必然失败的
   ```csharp
   CheckTrue(false, "PROBE 计数器路由探针");
   ```
   然后**只跑那一条**，要求：**只有一个宿主**的失败数 +1、且打印出来的是**那一个宿主的 `P` 前缀**（`[Shell]`），**其余 6 条的合计一位不变**。反向验完（把探针删掉）再跑一次确认回到基线。
   —— 这条**不可能被「两边一起改」满足**：若两个宿主共用了同一个计数器，探针一定会污染别人；若共用件写了全局 static 计数器，7 条会一起变。
4. （可选、廉价、不经 Unity）`grep` 结构闸：改后 `Editor/{7 个宿主}.cs` 里 **`static void CheckTrue(` / `static void CheckNear(` / `static void CheckHoverSwap(` / `static void CheckNoMissingSwapArt(` / `static void Section(` / `static void Shoot(` 必须各只剩 1 处**，且 `MenuCheck.cs` 是这些函数体的**唯一定义处**。
5. **不许碰的东西**：本次改动 **⛔ 一行期望值、一个容差、一条断言文案都不许改**（`CheckNear` 的 `F2/F3/F4`、`Shoot` 的 `> 3f` 与「不是空图」文案都算**行为**，不是格式）。
