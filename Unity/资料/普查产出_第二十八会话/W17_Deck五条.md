## 第 5 条：`ClipRowToBand` 怎么区分「状态关掉」与「被裁出去」

- 真缺陷：`DeckRuntime.cs:4123` `SetOn(_deckRowCost[i], on && !heroRow)` **确实关掉了**，但同一趟循环末
  `ClipRowToBand` 的 ① 见 `!activeSelf` 就 `SetActive(true)`（`PieceShared` 原来**恒被处理**，`:2013` 只挡
  `PieceHero/PieceCard`）⇒ 刚关掉的圆**又被点亮**（静默）。旁证：`deck.log` `row_c0` 红（圆亮）而
  `row_cnt0` 绿（数没亮）——「一开一关」正是「圆在 `_rowPieces` 里、数不在」的形状。
- **做法 = 多传一个「该不该显示」的实参**（不是靠读 `activeSelf` 反推）：
  `void ClipRowToBand(int slot, float y, bool hero, bool shared)`（`:2016`）+
  `if (it.Kind == PieceShared && !shared) continue;`（`:2032`）—— **没被选中 = 一个字都不动**，
  与另两档**同一条口径**；调用点 `:4193` 传 `on && !heroRow`，**与 `SetOn` 那一句逐字同值**。
- ⛔ 没弄坏 `PieceHero` 的显式跳过（`A1720` 那条「滚过一行后督军档关掉」仍靠它绿）。
- ⚠️ **约定已写进注释**（`PieceShared` 的 doc `:1002-1008` + `:2026-2030` + `:4101-4106`）：
  **注册进 `_rowPieces` 的每一颗，可见性就归 `ClipRowToBand` 管** ⇒ 调用点必须把那一行「该不该显示」
  一并传进来，否则将来加件会复现同一个坑（今天 `PieceShared` 只有费用圆一颗）。
- 防御卡那一档不受影响（`heroRow=false` ⇒ `shared=true`），`DeckScene.cs:3859` 那条绿保持。
