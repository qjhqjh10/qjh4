## 口径

- **单位** = `(卡 id, ability 序号, abilityLogic 序号)`，一行一条效果步骤。**原版面（判据）** =
  `d:/2/远端缓存_旧profile_1013/导出/cards_1195_2022时代.json` 的 `cardAbilities[].abilityLogic[]`
  ＋（简报没数到的）`activeAbility.activeAbilityLogic[]`；枚举名 →
  `资料/普查产出_第二十七会话/abilityLogic_枚举词典.tsv`（现读 53 个取值，都有名字）。
- **我们面（被测实现）** = `bash 工具/ruleprobe.sh scan d:/4/_tmp_view/our_scan.txt`，即
  `RuleEngine/Core/EffectText.Parse(desc)` 的产物，与本仓 `scan`/`check` 基线**同一个口**。
  **为什么走它**：原版卡的引擎侧唯一逐卡产物就是它（`CardDef` 四条正文通道 `TriggerOps`/`SpiritOps`/
  `FaithOps`/`OathOps` 喂同一台解析器）；`play` 是结算层、`card` 只打收集层，覆盖都不如它。
  🔴 **本口不含 `AuraSpecs`（`Core/Aura.cs`）与 `keywords` 驱动机制** ⇒ 光环那一族**结构上不可见**。
- **对齐** = 卡级多重集（⛔ 不按 ability 分组），家族等价表见脚本 `EQ`；按「触发头（`Source` 前缀）+ 数值
  对得上」打分取最优。原版一条步骤可带**多个 criteria 块**（如 `dmg1-1`+`buff{health+1}`），我们拆成多条 op
  ⇒ 先按**主家族**匹配，不成再按**次家族**匹配并判 `⚠️原版一条含多效果`。
- **三档判据**：`✅一致` = 家族对上**且**取值对得上（伤害/治疗比 `amount`；增益比属性增减集；`addTrait`
  比 trait 名；`changeCost` 比 cost；附魔类 BuffType 不做数值比较）。`⚠️表示不同·语义同` = 拆条差异 /
  原版重复N次 / 粒度不同（我们收在「信封」op）/ 原版一条含多效果 / 承载不同（选牌·改费编码在
  `targetCriteria`）/ 纯表现·纯 UI。`🔴真差异` 子类 = `我们缺`/`我们多`/`取值不同`/`条数不同`。`❓查不清` = 判据不足。

## 与 `A1822`（`SummonCriteria` 只接 summon 分支 ⇒ 静默漏 135 条）的对账结果
