## 抽卡 Draw

### 落点怎么选的（⛔ `slot<0` 那道闸怎么绕的）
- 🔴 选**「显式落到手牌区」**那一条（简报的第二选项），**没有**塞进 `IsResourceUiEvent` —— 那个判据的语义是「落点在**资源计数图标**上」，而抽卡的落点在**手牌区**，混进去 = 一个判据两件事。
- 做法：`IsResourceUiEvent` **原样不动**，新收一个**判据只此一处**的 `BattleDriver.IsHudAnchoredEvent(EvtKind)` = `IsResourceUiEvent(k) || k == EvtKind.Draw`；`PlaySignal` 里原来内联的 `if (IsResourceUiEvent(e.Kind))` 改成 `if (TryHudAnchor(e, out var hud01))`（`BattleDriver.cs:11004` 一带）⇒ 4 个 HUD 锚点事件共用同一条出口。
- 落点 = `HandRow01(mine)`：取**刚抽到那张牌**会在的位置（手牌是**追加到末尾**的 —— 判据 = `RuleCore.MoveDeckTopToHand` 的 `ps.Hand.Add(inst)`）= `HandLayout.SlotPosition(count-1, count)`；拿不到排布时退成**那一行的正中**（`HandLayout.DefaultBaselineY` / `EnemyBaselineY`）。两级都在手牌区。

### 接了什么
- `EvtKind.Draw` 进 **`PlaySignal` 的 switch**（`BattleDriver.cs:10978-10981`）+ 进 **`VfxMap.Events[]`**。
- 特效名 **`VfxMap.Draw = "draw"`**，走**按阵营**档：`Ultramarines → UM_CardDraw` · `Sautekh → SAU_CardDraw`（`ByFaction`）。⛔ **不进 `ByEvent`**：本地只有这 **2 件**，其余 11 个阵营**留白**（同 `SummonCircleOf` 的先例：宁可留白、不硬凑）。
- **音效那一层不用另接**：两件的 `AnimFXController.sounds[0].sound` = cue **`Draw`**（→ clip `MatchDraw`），`WarpforgeEffectPlayer.BuildSounds` 跟着播。
- **动画那一层本来就有**（`CardFeel.DealInPose` / `DealInQuad`，由 `SyncHand` 驱动）⇒ **不**在 `PlayFeel` 再加 Draw case（那会是第二条发牌补间）。
- `EventTiming`：`case EvtKind.Draw: return DrawDeal;` = **0.3 s**（`CardFeel.DealDuration` = `VarsGlobal.timeToDrawPlayerCard`；原版这一档**确实会等**：`PlayerHand._AddDrawnCardToHand_d__37:78-80` 的 `WaitForSeconds(TimeToDrawCard + …)`）。⚠️ **只覆盖我方档**（敌方 0.15 拿不到座位号 —— 如实标着）。

## 伏击翻面 AmbushExit

### 两条发出点各接了什么（`damage` / `window`）
- 🔴 **两条用同一件**：`VfxMap.AmbushExit = "ambush_exit"` → `ByEvent` = **`AmbushEffect`**（不分阵营）。本事件的语义 = 「这个单位不再面朝下」这个状态迁移，两条出口都是它；`Resolve` **没有**「同一事件按 `Effect` 分特效」那一层，本地也只有这一件（⛔ 不硬凑第二件）。已写进 `ByEvent` 与 `PlaySignal` 的注释。
- 走**格位那条路**（`Slot` = 那个单位还在场上那一格）⇒ `IsHudAnchoredEvent(AmbushExit) == false`。
- **三层一次到位**（这件 prefab 自己带的）：音效 = cue `Trait Ambush`（→ clip `Ambush`）· 动画 = `AnimFXModuleChangeMaterial` 把**卡**材质换成 `Card 3d Dissolve Blend Image Ambush` · 粒子 = 它内部那几个 ps。
- `EventTiming`：`case EvtKind.AmbushExit: return 0f;` —— 🔴 **查过之后故意取 0，不是「填死值」**：原版 `CardScript.SetAmbush(card,false)` 是**普通方法、不阻塞**（`CardScript__SetAmbush.c` 逐行读过），而 `RuleCore.ApplyDamage` 里它**紧跟着同一击的 `Hit`**（`:5651` → `:5655`）⇒ 排一段时长会把**同一下伤害的挨打反馈整段推后**（= 新偏离）。那件特效自己多长是它自己的事（材质补间 = `MaterialTweenFloat(_Blend)` **delay 0.35 + duration 1.0 = 1.35 s**，写进 `SourceOf` 备查、**不进时间线**）。

- ⛔ **有意不碰引擎状态**（直接往 `Ctx.Signals` 塞事件 = 「引擎说了什么 / 画面怎么翻译」的分界线）。**为什么不用 `RuleCore.ApplyDamage` 真打一遍**：那会写棋盘 + `ctx.Log`，而 `RecBegin` 从开局就开着 ⇒ 副作用落在**录制窗口**里、却不进动作流（不走 `LocalAct`/`SimpleAI.Executed`）⇒ 后面 §回放 那条「指纹与录制时相等」会红。引擎**真的会发**这一半由 `RuleEngineTest` 钉着（`:13755-13920`，「把 `Emit` 挪出 `if (u.FaceDown)` ⇒ 红」）。

- ⚠️ 连带把 `StepThrough` 的等待上限 6 s → **9 s**：抽卡现在也占时间（每回合开始都抽一张，`RuleCore.BeginTurn:1151`）⇒ 同一批事件总长 +0.3 s。该上限**只在推不完时**起作用（排空即退出），不改变任何断言语义。
