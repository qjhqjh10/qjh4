## A1873 `Talent: <具名卡>` 一族（79 条）

### 原版怎么做（方法体逐句）
`Talent: <名>` 在真值里是 `cardAbilities[]` 里 **`trigger == 46 /*AbilityTrigger.Talent*/`** 的那一条：
- **时机** `CardScript__OnTurnStart.c:163-166` —— 回合开始时，对**回合方自己**的、带 `DefinedTrait.talent = 845`
  （`HasCurrentTrait(param_1, 0x34d, 0)`）的卡发 `RawCardScript__OnTrigger(raw, 0x2e, …)`；`:152` 那条闸是教程 `TurnScriptedData.dontDrawTalent(+0x1A)`。
- **造哪一张** `CardScript__GetTalentCard.c` —— 取第一条 `trigger == 0x2e` 的 ability，再取
  `abilityLogic(+0x50)[0].summonCriteria(+0x58).unitsToSummon(+0x18)` = **候选表**；
  `AbilityLogic__GetCardToSummon.c` 对 `N > 1 且 !summonAllTargets` 走 `BattleManager__GetRandomInt` **随机挑一张**。
- **干什么** `chosenAbility = 100 /*createCardInHand*/` → `AbilityLogic__PlayAbility.c:1110/1141` → `AddNewCardToHand`（造到**手牌**）。

### 我们原来怎么做（为什么 op 表是空的）
两半都缺：① `EffectText.Parse(Desc)` **不认 `Talent:` 那一段**（扔进 `unparsed`）——
对账量的正是它；② 引擎侧是**另写的一条路**（`CardDef.TalentName` + `RuleCore.SpawnTalents`，
**按卡面名字**查池子）⇒ 实测**有一批静默不生成**（池子里那几张的名字带 ` (某督军的 Talent)` 后缀，
如 `Duelist's Hubris` vs `Duelist's Hubris (Lucius' Talent)`）。

### 改了什么
1. `Core/EffectText.cs` —— 新增 `TryTalent`（`ParseSegment` 的 **0)** 支）：`Talent: <名>` →
   `create` 一条（`Dest="hand"`、`Amount=1`、`Payload`=名字）。名字抽法**转调 `CardDef.ExtractTalent`**（不另切）。
2. `Core/CardDef.cs` —— `ExtractTalent` 由 `private` 改 **`internal`**（两个调用点必须同一份抽法）+ 补 doc。
3. 🆕 `工具/gen_talent_cards.py` → 🆕 `数据/游戏数据/talent_cards.json`（全量真值，含落不下的）
   + 🆕 `MyGame/Assets/RuleEngine/Resources/talent_cards.json`（**运行时件**，键 = 我们卡池 id）
   + 🆕 `Core/TalentCardData.cs` ＋ 🆕 `Data/TalentCardMap.cs`（`partial` 一对，照 `RelatedCardData` 先例）。
   真值 = `unitsToSummon[*]`（**候选表，不止第一条**）经 `related_cards.json` 的 PathID 翻译表落到我们 id。
4. `Core/RuleCore.cs::SpawnTalents` —— **先读真值表**（按 id 取，`N>1` 时用 `ctx.Rng` 随机挑一张），
   查不到才退回原来按名字那条路（⛔ 没有删掉任何老路）。

### 修掉了多少条（对账 TSV 现算）
`createCardInHand · 我们缺` **79 → 22（−57）**。剩下 22 条 = **17**（另一族，见下）+ **5**（真值缺：`SOR9 Preacher` ·

## A1875 `doDamage`（46 条）—— ⛔ **没做，理由与判据缺口写清**

  ⇒ 它**结构上进不了 `EffectText.Parse(desc)`** ⇒ 这一族是**口径缺口**而非实现缺口。
