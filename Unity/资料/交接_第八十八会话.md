## 七、本会话的硬知识（多数已进 `CLAUDE.md §三` / `工作准则_操作经验.md`）

| 坑 | 一句话 |
|---|---|
| **本 build 的代码在 `il2cpp` 节、不在 `.text`** | 只扫 `.text` 时调用目标 14,942，扫对了 212,994（**差 14 倍**）⇒ 只扫 `.text` 得到的「0 调用点」几乎全是假的 |
| **`dump.cs` 的 RVA 是十六进制、`script.json` 的 `Address` 是十进制** | 按十进制读会**全读成 0** 且不报错 |
| **相邻 bool 的清零被编译器合并成宽 store** | `bm+0x240` 一条 4 字节零写清 4 格；按单偏移 grep 必漏、ILSpy 里根本没这行 |
| **同一段逻辑在 `decomp_full` 可能有两份产物** | `.c` 体 + ILSpy 内联体 ⇒ 只看 `.c` 会漏**外层闸** |
| **`cards_truth.json` 顶层是对象** | 直接当 list 迭代会**静默扫到 0 张卡** |
| **`m_PathID` 粗搜会前缀撞车** | `"m_PathID":3327` 的 7 个命中全是 `m_GameObject` 长整数 ⇒ 必须用 `m_Script` 精确重扫 |
| **`id(临时元组)` 做去重键会静默丢数据** | CPython **复用 id** ⇒ 14 条只落 8 条**且不报错** |
| **给调用点很多的方法加参数：重载参数别给默认值** | `int p = 0` ⇒ 所有既有调用**二义**（`CS0121`×20）；更好的是把它插到**可选参数之前**（第 5 位必填），老调用直接不适配 |
| **`--all-A` 只校验 A 行** | 大批 C 升 A 后，这些行的**落点格式**才第一次被校验 ⇒ 一次冒出 102 条失败 |
| **自证式断言是本会话最大的隐患** | 揪出 4 处：`startingManaSecond==2` · `StageTitle` 同源 · 行距 `(vpH−节点高)/784` · `Beautiful Death` 假 4/真 4 数字相同 |
| **「补某个写点」之前先做调用点扫描** | 783 `HideWarlordActiveAbilityForTutorial` 原版**零调用点** ⇒ 差点造出原版没有的行为 |
| **`WaitFor`…`_DAT` 常量可读** | `RVA = 地址 − ImageBase(0x180000000)`，`工具/read_literal.py`（4B/8B 按形参类型选） |
| **探针会「盲绿」** | `ruleprobe` 的 `LoadPool` 走 `System.Text.Json` **手读卡表、绕过 `Data/CardDatabase.cs`** ⇒ **新增的卡表列它看不见**，dump 相同只证明「探针没走那条分支」 |
| **泛型方法体产物早就在** | `D:/2/tools/decomp_generic_trial/out/`（640 个 `.c`）⇒ 「泛型方法体从没导出过」**已过期**，⛔ 不用再动 `d:/2` |
| **「手牌数」有两种口径** | `Hand.Count` 含**附魔/武器/密语**；原版 `ta=50` 只数**单位 + 战术** ⇒ 混用会**多点伤害**（本会话 80 档就是这么错的） |
| **按名字搜不到 ≠ 没有（4 例）** | 判 SO/组件走 `m_Script` pathID → `m_ClassName`；判「功能有没有」**grep 行为词不是类名**（内联等价实现常年在别的类里活着） |
