## 件 1 —— `rect_of` 的 `scale` 是死参

- **我读懂的语义**：`scale` = **`lossyScale(父)`**（= 根→父，**含父自己那一级**的 `m_LocalScale` 连乘；判据 = `walk` 的递归，
  根收 `(1,1)`、每下一级 `× 本级 m_LocalScale`）。要乘的是**局部单位的那几项**：
  ① `sizeDelta ⊙ scale`；② `anchoredPosition ⊙ scale`。**不乘**的是 `anchorDiff ⊙ 父的屏幕框`
  （锚点比例本来就按父的**屏幕**尺寸取）。**不含本件自己的 `m_LocalScale`** —— 那正是 `_scl_cell` 那一列
  （修之前，当 `lossyScale(父)≠1` 时**连那一列也是错的**）。
  推导：`rect.size = sizeDelta + anchorDiff ⊙ parent.rect.size`（父的**局部**尺寸）→ 换算回屏幕 = `× lossyScale(父)`。
  与 uGUI `AspectRatioFitter.GetSizeDeltaToProduceSize`（`:196-199`）与 `SetSizeWithCurrentAnchors` **互为逆运算**，可反证。
- **改法**：| 位置 | 改前 → 改后 |
  |---|---|
  | `menu_rect.py:162 rect_of` | `pos`/`sizeDelta` **一次都没乘** `scale` → `pos⊙scale`、`sizeDelta⊙scale` |
  | `menu_rect.py:188 parent_rect_of` | 逐级 `rect_of(..., (1,1))`、返回 2 元组 → **跟着累积 scale**，返回 3 元组 `(rect, 名, lossyScale(父))` |
  | `menu_rect.py` 新增 | —— → `parent_local_size()` / `local_size()`（局部单位换算，**`scale≈0` 时返回 `None` 而不是抛**） |
  | `menu_dump.py` 调用点 | `walk(..., (1,1))` 写死 → 传 `parent_rect_of` 返回的 `lossyScale(父)` |
  | 新增开关 | —— → `--no-ancestor-scale`（**只为复现旧口径 / 读「未缩放帧」的设计值**，默认关） |
- **影响面**：**130/308 窗口、9536 条目（4768 个不同节点）**变了；**最大位移 25578.42px**、平均 245.79px。
  最大那条 = `Generic Multi Card Display` 的卡片链（祖先 `CardUI Reference` `scale=223.14`、
  子孙自己 `scale=0.01`）：`Text` 布局宽 `115.1455 → 25693.57`（= 115.1455×223.14，视觉框再 `×0.01` = 256.9px = 真渲染宽）。
  🔴 **本包里 390 个 RT 的 `m_LocalScale` 是 `(0,0)`、1476 个是 `(0.01,0.01)`**（动画/隐藏态存进了 prefab）⇒ 默认口径下
  那些子树被压成 0/极小 —— 这是**数据事实**，但原来被**静默**当成「缩放=1」的全尺寸。⇒ 新增三块出声：
  逐行 `⇲ls=×a,b`、末尾「父链上有缩放」清单（含 `scale≈0` 那些的**未缩放帧**尺寸）、`--no-ancestor-scale` 退路。
- **fixture / 自证**（`verify_layout` ⑤a–⑤e，期望值全手算）：⑤a/b 点锚点 `scale=1/2`；
  ⑤c 拉伸锚点+`sd=100`（**错写法给 500×400，正确 600×500**，专抓「忘了乘」）；
  ⑤d `local_size`/`parent_local_size`/`scale=0 ⇒ None`；
  ⑤e **回归锚**：卡片链 `Text` = 25693.57，`--no-ancestor-scale` 退到 **115.1455**（= 旧口径逐位）。

## 件 4 —— `_ignores_layout()` 的口径差

- **差在哪**：uGUI `LayoutGroup.cs:60-79` 是 `GetComponents(ILayoutIgnorer)` 后
  **只要有一颗 `ignoreLayout == false` 就 `break` 出去收进 `rectChildren`**；旧写法是**任意一颗为真就排除**。
  ⇒ **只在「同一节点挂 ≥2 颗 `ILayoutIgnorer` 且标志混合」时岔开**：全 True ⇒ 都排 ✔；全 False ⇒ 都收 ✔；
  **混合 ⇒ uGUI 收、旧写法排**（已按源码改成「全 True 才排」）。
- **落在岔开集合里的节点数 = 0**（`bundle_menus_assets_all`：挂 ≥2 颗 `LayoutElement` 的 GO **只有 1 个**
  = `Title_-8615221960607866717`，两颗都 `m_IgnoreLayout=0` ⇒ 两种写法同值）。
  ⚠️ 另查实：**原版 dump 里 `ILayoutIgnorer` 的实现者只有 `LayoutElement` 一个**（传递闭包，41 个 ILayoutElement 里唯一）
  ⇒ 「只看 LayoutElement」这条**本来是对的**，改的只是「任意 vs 全部」。
- **改不改**：**改**（3 行，规则照抄源码；真数据上同值所以零风险）—— 留着的错口径迟早在别的包/新 prefab 上咬人。
  ⚠️ 另一处**已知口径差、本次不动**：uGUI 收孩子判 `activeInHierarchy`（整条父链），
  `apply_layout_to_children` 判 `m_IsActive`（只看自己）。**本包实测这一类点 = 0**（无「自己 active、祖先 inactive」的可排子件），
  但它是**真差**，理由是 `walk` 本来就会走进 inactive 子树、要如实列出它们。**已记待办**。
- **fixture**：⑦ 六种标志组合打桩（含 `[True,False] ⇒ 收` —— **旧写法会红**）；⑥b 真数据锚（`Title` ⇒ `False`）。
