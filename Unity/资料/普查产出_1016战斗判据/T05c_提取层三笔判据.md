  ⇒ 这两个枚举**是原版把一条 cardAnim 绑到「哪一次技能」上的键**。
  ⚠️ 「引擎一次技能**只发一条** `EvtKind.Ability`」那一格（T05 §2·5）**没查**（那是另一个代理的活，本代理未碰）。

**③ 我们现状（= 缺陷的确切位置）**
- **全量件里【有】**：`gen_card_vfx_by_card.py:838-858` 的 `so_refs` 已经把
  `abilityTrigger / abilityTriggerName / chosenAbility / chosenAbilityName` **逐条写到 entry 上**（都在 `byCard[*]` 里，现读 1,265 条）。
- **运行时件里【被裁掉】**：`gen_card_vfx_by_card.py:1317-1340` 的投影循环把每条 entry **只留三个键**：

  实读运行时件 `Resources/card_vfx_by_card.json`：`es` 的键并集 = **`['a','c','n']`**；card 级 = `['audio','events','fa','id','nm']`。
- **C# 侧模型也没有**：`Core/VfxMap.cs:287` `RtEntry { public string n; public string c; public string a; }`；载入时（`:388-400`）按 `confPriority` 把同一 `(卡,事件)` 折成**一个** `string`。
- ⇒ **现在「`cardAnimations` 归到 `ability` 事件」确实是生成器拍的**（`_conventions.authoritativeEventMapping` 自陈），下游**看不到** `trigger`/`chosenAbility`。

  ⇒ 即便把两个枚举投影进运行时，**下游还得有一张「我们的 Keyword/Effect → (trigger, chosenAbility)」的翻译**才能用（那属于 A2084/A2085 的活）。

**④ 怎么改**
1. **生成器**（`gen_card_vfx_by_card.py` 的运行时投影几行，`:1338`）：`es` 里补
   `"at": abilityTrigger, "an": abilityTriggerName, "ct": chosenAbility, "cn": chosenAbilityName`（短键、与 `n/c/a` 同风格；缺值写 null 或省键，⛔ 别写空串充数）。

   要能按 `trigger`/`chosenAbility` 过滤，就得**别再折死**（改成保留候选数组、由查询口挑），或至少把首选的 `at/ct` 也带出来。
3. **消费**：只有在「引擎事件带得出这一次是哪条 ability」之后才有意义（T05 §2·5 那一格 + 翻译表）。⇒ **本笔可先只做 1、2（提取层），消费留到 A2084/A2085 一起**。
- ⚠️ **依赖**：`1` + `2` **能被本笔独立做**；`3` **必须等** §2·5 判据（「多条 = 同事件 N 拍 还是 N 个事件」）＋ 引擎带出「哪条 ability」。
