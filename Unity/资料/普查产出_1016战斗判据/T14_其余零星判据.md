1. 🔴 **②（运行时加载 117 个原版 shader）+ ⑩（首帧 shader 变体编译/贴图首传）** —— 这是**唯一一条「我们与原版架构性不同」**的段。原版把 shader 打进 build（`d:/2/tools/assetripper_out/ExportedProject/ProjectSettings/GraphicsSettings.asset` 与我们的 `GraphicsSettings.asset` 都 `m_PreloadedShaders: []`，两者**都不预编译**），但**我们从 StreamingAssets bundle 运行时 `LoadAllAssets<Shader>()` 现取** —— bundle 解压 + 建 117 个 shader 对象 + 首帧 `CreateGPUProgram` 全落在这一帧。
   同族**旁证**（足证这是本工程的**反复病**）：`A1813` 收藏窗打开 **17.3 s**（`普查产出_第二十七会话/新发现_待立账.md:135`，探针读数 `①b 页 3 Setup() = 17338.6 ms`，那份**同源怀疑 = 首次 Resources.LoadAll / shader 首次编译 / 贴图首传**）；同族还有 `A1780`。
2. ⚠️ **动态 CJK 字形首烘**（每出现一个新汉字就从 TTF 现烘）：`Core/TmpFont.cs:27-28` 记「全仓只有一个字体 `NotoSerifCJK-Regular SDF`、**Dynamic（`m_AtlasPopulationMode = 1`）、图集是 1×1 占位**」⇒ 首帧所有 HUD/卡面汉字一次性首次出场。**嫌疑**，未量（`T08_每帧开销判据.md:158-160` 也把它列为嫌疑、注明「我没量过」）。
3. ⚠️ **场景反序列化 5350 个对象** —— 但 `Unloading 38 unused Assets` 那步只 2.4 ms，**不像**大头。
4. ❌ **arena 载入**：**已排除**（56 ms）。

### 2·4 怎么改（**先测后改 —— 现在还没到「知道改哪」的地步**）

⛔ **本件现在不能直接改**：连「12.5 s 花在哪一段」都还没定 ⇒ **先加分段计时，再决定改哪**。
逐段计时**照本仓现成范式**（`Shell/CollectionWindow.cs:3796-3930` 的 `BuildWatch`：`Application.isPlaying` 闸 + `Time.realtimeSinceStartup` 分段 + `WaitForEndOfFrame` 那一格）—— **在 `PlayerBoot` 的 `LoadSceneMatching`（`Core/PlayerBoot.cs:317-332`）两侧各记一次 `Time.realtimeSinceStartup`**，并给 §2·2 每一段的首尾各插一对 `Mark`（§`Watch`），跑 `-wfscene Battle -wfwatch -wfwatchfile <f> -wfquit 75` 一次即得**逐段 ms**。
> 🔴 **⛔ 别用 `-wfstall N`** —— 它让进程**自杀并丢日志缓冲**（`工作准则_操作经验.md` §54 / `Watch.cs:112-118`）；要留日志就用 `-wfquit` 正常退。

**拿到分段数后的改法（按段）**：
- 若 **②** 大 ⇒ 把 shader 预热挪出「进战那一帧」（原版等价物 = 加载屏期间后台预热），或减到「本局真用得上的 shader」。
- 若 **⑩**（首帧渲染）大 ⇒ 做 **shader 变体预热**（`Shader.WarmupAllShaders` / `ShaderVariantCollection`）到加载屏期间；⚠️ 这一步会让原版与我们的差异**缩小**（原版至少也是首帧编译）。

- 若 **③/⑤**（材质/面板建）大 ⇒ 那是我们自造的建件开销，精简建件。

⛔ **别按「稳态帧率」查**（`T08` 只覆盖那一种；本件是一次性长停顿，见 `T08_每帧开销判据.md:31` 与 §五第 3 条）。
