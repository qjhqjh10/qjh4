## 二、怎么跑（照抄即可）

```bash
# ① Il2CppDumper：产出 script.json（符号表）+ stringliteral.json（字符串字面量）+ dump.cs + il2cpp.h
cd /d/2/tools
dotnet il2cppdumper/Il2CppDumper.dll \
  /d/2/unity_run_ref/GameAssembly.dll \
  /d/2/unity_run_ref/Warpforge_Data/il2cpp_data/Metadata/global-metadata.dat \
  /d/2/tools/il2cpp_out
#   ⚠️ 跑完会抛一个 "Cannot read keys ... console input has been redirected" —— 那只是它想等你按键，
#      **产物已经写完了**，别当成失败。

# ② Ghidra 全量分析（**首次数小时**；之后各次只需 -process 复用工程，几分钟）
export JAVA_HOME="D:\\2\\tools\\jdk-21.0.12.1+1"
mkdir -p /d/2/tools/ghidra_proj        # ⚠️ 这个目录**必须自己先建**，Ghidra 不会建（第一次就栽在这）
cmd //c "D:\\2\\tools\\ghidra_12.1.3_PUBLIC\\support\\analyzeHeadless.bat \
  D:\\2\\tools\\ghidra_proj Warpforge \
  -import D:\\2\\unity_run_ref\\GameAssembly.dll \
  -scriptPath D:\\2\\Warpforge_tools\\data\\decomp_il2cpp_0827\\ghidra_scripts \
  -postScript il2cpp_renamer.py D:\\2\\tools\\il2cpp_out\\script.json \
  -max-cpu 8"

# ③ 反编译想看的类（**不用重新分析**，走已有工程）
#    filter 文件：一行一个类名（脚本按 `<类名>$$` 前缀匹配方法名）
cmd //c "...analyzeHeadless.bat D:\\2\\tools\\ghidra_proj Warpforge \
  -process GameAssembly.dll \
  -scriptPath ...\\ghidra_scripts \
  -postScript il2cpp_decomp.py D:\\2\\tools\\il2cpp_out\\script.json D:\\2\\tools\\decomp_AI D:\\2\\tools\\classes_wanted.txt"
```

**自检办法**（别信印象）：
- Il2CppDumper：产物里 `script.json` ≈ **127 MB**、`ScriptString` 数组 **26507** 条（`python -c "import json;print(len(json.load(open('script.json'))['ScriptString']))"`）。
- Ghidra：`d:/2/tools/ghidra_proj/` 从 9 KB 涨到 **GB 级**才算分析在推进。

## 三、已经用它拿到了什么

1. **字符串字面量表**（`stringliteral.json` + `script.json` 的 `ScriptString`）——
   `StringLiteral_N` 就是 **`ScriptString` 数组第 N 个（从 1 数）**，脚本 `il2cpp_renamer.py:38-46` 定的规矩。
   ✅ **第一个收工**：换牌倒计时那个格式串 `StringLiteral_20746` = **`"0:0"`**
   ⇒ 原版最后十秒按钮上写 **`0:09`…`0:01`**，也解释了阈值为什么是 `< 10`。
2. **`dump.cs`（42 MB）**：**带字段偏移的完整签名**（比 `Warpforge_code/` 的签名桩多**偏移**），
   以后推 `0x??` 字段是谁就不用再靠猜。
3. （进行中）`AI` + `AnimFX*` 18 个类的**方法体** → `d:/2/tools/decomp_AI/`。

3. ✅ **2026-09-17 当天就补下来了：`AI` 整个类（41 个方法）+ `AnimFX*` 18 个类**，共 **127 个 `.c`**
   → `Warpforge_tools/data/decomp_il2cpp_0827/decomp_out_ai/`。
   读法与已解出的结论见 **`资料/AI_原版反编译_0917.md`**（**换牌规则那条已经解开了**）。

## 四、坑（都踩过）

- **`ghidra_proj` 目录要先建**，否则 `ERROR Abort ... Directory not found`。
- 🔴 **Ghidra 12 跑不了 `.py` 脚本**：`ERROR ... il2cpp_renamer.py : Ghidra was not started with PyGhidra.
  Python is not available` —— 上一轮留下的两个 Python 脚本**在这版上无法直接跑**。
  ⇒ 改用**同目录的 Java 版** `Renamer.java` / `Decomp.java`（它们吃「**十进制地址 ⇥ 名字**」的清单文件）。
  （要跑 `.py` 得走 `support/pyghidraRun` 建 venv，本次没走这条。）
- Il2CppDumper 结尾那句按键异常是**正常的**（产物已落盘）。
- Ghidra 首次跑会先解压类型库（`%LOCALAPPDATA%\ghidra\packed-db-cache`），那几分钟是正常热身。
- 分析工程 `ghidra_proj` 别删 —— 删了下次就得**再花几小时**重新分析。
