## 二、本会话完成（按主题）

### 2.1 特殊卡拦截（`src/deckrules.js` 重写）

- 旧实现只用 `inventoryOptions/showInCollectionOptions` 判，**从未触发过**；本轮改成**原版卡池口径**
  （`报告/OFF170_每阵营卡池清单_1111.md` §二·一，已用原版 16 张 `DT <Army> R1..R4` 逐张复现）：
  `cardRarity ∈ 1..4` + `cantBeRandomlyCreated == 0` + `showInCollectionOptions == 5` + `inventoryOptions == 0`。
- 两个放行分支照原版：`cardType==10`（战将 → `CanAddHero`）、`cardType==20 && spellType==210`（防御卡 → `CanAddDefensive`）。
- 字段用**裸指针读**（`android_il2cpp_1117/dump` 偏移：rarity 0x28 · cantRandom 0x44 · show 0x48 · inv 0x4C ·
  spell 0x90 · cardType 0x94 · shortId 0x40 · name 0x60），不依赖字段名解析。
- **端到端自测**（临时把 `Scout` 标成违规，验完已删）：拖进卡组 → `[DECKR] 拦下特殊卡：SELFTEST · id=213 …`，
  计数仍 0/30 ⇒ 拦截链路成立。正常卡池实测 115 张全合规（仅 3 张防御卡按原版放行）。

### 2.2 匹配队列「取消」真退队（`matchbot.js` + `mmqueue.js`）

- 之前取消只关窗口，**云端队列还在轮询**，可能把玩家配进房。
- 现在：`onUserCancel` / `doBot` 都调 `WFMMQueue.stop(false)` → `op=leave`，并打一行 `退出队列（op=leave）`。
- 真机：点「取消」前云端 `{"waiting":{"skirmish":1}}` → 点后 `{"waiting":{}}`。

### 2.3 `Can't find room!` 噪声（`photon.js`）

- 反编译 `NetworkCustomManager__LeaveRoom.c`：无房间时**只** `Debug.LogError("Can't find room!")`。
- 给 LeaveRoom 加守卫：`PhotonNetwork.room == null` 直接跳过（语义等价）。
- 真机自测（临时 25 s 主动调一次 LeaveRoom）：`[PHOTON] LeaveRoom 跳过（当前无房间 …）`，此后不再刷该错误。

### 2.4 小冲突积分条 NRE（`probe.js`）

- 反编译确认 `SkirmishEventWindow.RefreshScore` 自己就传 `icon=null / name=null`（`Initialize(...,0,0,0)`）——
  不是我们数据缺字段。
- 给 `RewardProgressBarPanel.Initialize` 包一层 revert→invoke→catch：异常**吞掉并记录**
  `[RPP] Initialize 异常已吞（原版数据/进度触发）`，不再刷 `LogException`，也不会再穿过钩子帧。

### 2.5 退出杀进程（`probe.js`）

- `UnityEngine.Application.Quit` 是 **internal call**，`implementation` 替换**不生效**（实测：Activity 关了、无 [EXIT] 日志、进程仍在）。
- 改挂托管入口 **`PlayerDataManager.QuitApplication()`**（反编译链：
  `SettingsMenu.<ExitGamePopup>b__8_0 → QuitApplication → LeaveRoom → 协程 → Application.Quit`）；
  原逻辑照跑（存档/离房），1.5 s 后强杀。
- ⚠️ 本 Frida 运行时**没有 `Process.kill` / `Process.terminate`** ⇒ 改用 libc **`_exit(0)`**。
  **钩子已实测触发**（`[EXIT] QuitApplication 被调`），但 `_exit` 这一版**还没复测**（见 §五）。

### 2.6 🆕 帧率显示（新模块 `src/fps.js`，用户新增需求）

- 需求：绿色；非战斗放在资源图标（红水晶）**前面**，战斗放**敌方玩家名片名字上方**；始终最上层、
  不影响点击/拖拽；设置「通用」→「禁用机器人」下面新增「帧率显示」开关。
- 实现（踩坑详见 `已知的坑.md` **484**）：
  - **自建 `ScreenSpaceOverlay` 画布**（sortingOrder 32767）——战斗 HUD 是**另一台相机**渲染的，
    挂游戏自己的画布 order 再高也会被盖（红块探针证实）。
  - 文字用 **`UnityEngine.UI.Text` + `Font.CreateDynamicFontFromOSFont("Roboto",32)`** +
    `UnityEngine.UI.Outline` 描边（TMP 自建 `verts=0`、克隆在战斗里属性全绿也不画 ⇒ 换 UI.Text）。
  - 绘制驱动 = **引擎帧钩子 `Interceptor.attach(Time.get_frameCount)`**（JS 计时器切场景后会静默死掉），
    另留 1 s 计时器 + 3 s 看门狗兜底。
  - 句柄校验按名字（`get_name()=="WfFpsText"` + 父 Canvas 名）重建 —— 场景切换后旧句柄会被内存复用。
- 位置：菜单 `anchor(1,1)/pivot(1,0.5)/anchored(-(W-1900), -55)`；战斗 `anchor(0,1)/pivot(0,1)/anchored(360,-18)`
  （名片框顶边≈屏顶 70 px，帧率占 18–58 px，**不重合**）。
- 设置行：克隆 `GeneralTab.disableBotsToggle` 那一行；**藏掉原标签 + 自建标签**（原 TMP 改不动，本地化覆盖）；
  **字号读原行 TMP 的 `get_fontSize()`（本 build = 50）照抄**；`Toggle.onValueChanged` 是**公开字段**（0x118，
  没有 `get_onValueChanged`）；状态落 `wf_state.json` 的 `fpsOn`。
- 真机判据：菜单「59–61 FPS」在红水晶前；战斗「60 FPS」在敌方名片名字上方；开关关→字消失、开→回来；
  `wf_state.json` `"fpsOn":true`；这一轮所有点击（设置/开关/卡组/战斗）都在帧率开着时点的 ⇒ 不吃输入。
