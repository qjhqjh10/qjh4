## 三、🔴 现象 3 的根因链（全部在反编译里核过）

```
DraftModeMenuOngoingState.PlayButtonOnClick
 → PlayEvent.StartMatch → MatchMakerManager.FindMatch
 → SearchOpponentManager.SearchOpponent
 → MatchMakerManager.CanMatchWithHumans
       只有 playMode == PlayModes.Classic 才看 GameModes.IsHuman；
       选秀是 ClosedDeck ⇒ 直接 return true ⇒ 永远走「找人」这条 PvP 路
 → BattleNetworkManager.MoveToBattleRoom（ClosedDeck=110 → searchingRandomOponent）
 → PrepareToConnectToBattleRoom → PhotonNetwork 未连接 → ConnectToPhoton()
 → ❌ PhotonRedirectProbe：AllowRedirect 只由 OnlineGameProbe 在「线上房间」流程置 true
      ⇒ SKIP 非线上房间模式 ⇒ 放行原实现 ⇒ 连 ns.exitgames.com（已关服）⇒ CONNECT-FAIL
 → MatchMakerManager.MatchMakingError("CustomErrors/InternetUnreachable")
 → 屏幕：「连接服务器出错。请检查您的互联网连接并重试。」
```

**实机判据**：
- `phase0/photonredirect.tsv`：19 次 `SKIP 非线上房间模式`、14 次 `CONNECT-FAIL`；
- `phase0/draftflow.tsv`：4 次 `ShowPopUp text=[CustomErrors/InternetUnreachable]`
  （`15:19:39` / `15:19:54` / `15:21:17` / `15:21:51`）。

**为什么我本地能打**：手工带了 `WF_OFFLINE_PHOTON_REDIRECT_ALL=1` + `WF_GAME_VERSION=1.1`
（自建 Photon 的 appVersion 仍是 1.1，客户端现行 1.2 = `LONG-02`），才重定向成功。
**默认启动（启动器 → 云端）没有这两个开关。**

## 六、`OFF-189` 要做什么（下个会话直接开工）

### 6.1 用户口径（2026-11-14 原话）

> 「给选秀模式在等待连接的时候，不是有弹窗吗。增加一个『人机』按钮，在取消按钮的左边，并列。
> 玩家无法通过服务器连接到真人的时候，点击人机按钮，直接进行人机对战。」

### 6.2 弹窗归属（先查清再改）

`MatchMakerManager` 的搜索等待窗 —— 序列化字段在 `MatchMakerManager.cs:107-116`：
`SearchingMatch` / `CancelButton` / `SubmitButton` / `MatchFound` / `searchingOpponentWindow`。
界面上是「**搜索中…**」+「**取消**」两个元素（截图 `s235_draft/06_after_play_local.png` / `12_search.png`）。

### 6.3 正确做法（⛔ 别自己拼战斗流程）

点「人机」→ 调原版 bot 入口：

```
MatchMakerManager.ChangeToBotBattle(matchData)          // MatchMakerManager.cs:438
  → MatchData.SetBotOpponent()                          // MatchData.cs:336
        把 matchType 从 ClosedDeck(110) 改成 ClosedDeckBot(120)
  → BattleNetworkManager.MoveToBattleRoom
        matchType == ClosedDeckBot → IL_04e7 → playingOfflinePvp
        ⇒ 不再碰 Photon（PrepareToConnectToBattleRoom 在 playingOffline 分支不会再要求连接）
```

需要拿到当前 `MatchData`：`PlayerDataManager.singletonManager.matchData`，
以及 `MatchMakerManager.Instance`。参考已有探针里对这两个的取法
（`Probes/PracticeProbe.cs` 有 `MatchMakerManager` / `SearchOpponentManager` 的类型解析；
`OnlineGameProbe.ConnectToPhotonNow` 有 `NetworkCustomManager.singletonManager` 的取法）。

### 6.4 🔶 自己设计（非原版）—— 要在代码里打标

- 按钮文案「**人机**」、位置在「**取消**」**左边并列**；
- **只在选秀（`PlayModes.ClosedDeck`）的匹配等待窗显示**（其它模式不动）；
- 点完的行为 = 走原版 bot 入口（§6.3），不自造。

### 6.5 ⚠️ 原版自带的兜底不可依赖

`SearchOpponentManager.WaitForHumanOpponent` 的 `IL_0574` 分支在「找不到真人」时确实会自己
`ChangeToBotBattle`；但它要先等 `FeatureConfig.GetMatchmakingWaitingTime`（实测可能大到 100000 秒）
⇒ **必须给玩家一个显式按钮**，别指望它。

### 6.6 验收标准

1. 选秀「搜索中…」弹窗里，「取消」左边出现并列的「人机」；
2. 点它 → **直接进人机对局**（不弹「连接服务器出错」）；
3. **默认启动（启动器 → 云端）** 下能连打多局；
4. 打完回选秀界面：颅骨计数正确、「战斗！」仍可点（顺带复核现象 1/2）。
