## 四、关键结论 / 判据（下会话直接用）

1. **启动门**：`stateOk = libil2cpp + global-metadata + (UnityMain|UnityGfxDeviceW)`；最短 **3 s**；metadata 后稳 2 s；兜底 14 s；上限 45 s；
   `--floor-ms` 是实验开关；`--delay-ms` 默认 **3000**。⛔ 不再按内存分档。
2. **PlayFab 方法名在路径里**（`/Client/<Method>`），`WfBridge.Conn` 的 `method` 是 HTTP 动词（坑 603）。
3. **`wf_state.json` 一个键同一时刻只能有一个写者**：`JAVA_OWNED`（现 = achievements / purchases / crateCounters / instanceSeq /
   decksClassic / decksFast）两侧必须逐字一致；JS 不加载不写回，`writeAll()` 以磁盘为底，`mirrorNow()` 镜像磁盘那份（坑 604）。
4. **墙钟余量**：固定 10 s 只剩 1.3 s；Unity 线程 1 s 就出现（不能当「初始化完成」），`nativeRender` 本机挂不上（坑 546/605）。
5. **`FindObjectOfType` 传 Type 参数在桥上必抛 `expected an integer`**；正解 = **泛型 inflate**
   （`oc.tryMethod("FindObjectOfType", 0).inflate(cls).invoke()`，`fps.js` 同款）。`FindObjectOfType<LoginManager>` 登录失败后取不到，
   但 `LoginScreenManager.manager`（`0x38`）就是它（坑 606）。
6. **从 JS 调 `LoginManager.RetryLogin()` 会卡主线程**（perform 的 promise 不落地 / Update 里 invoke 后不返回）⇒ **不要做自动重试**（坑 607）。
   迟到时交给玩家点原版「重试」。
7. **包内资产两个新断言**：`assets/wf_shop.json`（PC `data/shop_offers.json`）· `assets/wf_decks.json`（`src/starterdecks.js` 里的 JSON）；
   构建必须 PASS 这两条 + 原有 catalog/模板/dex 断言。
8. **商店的 inventory 提示**（`There's no item with instanceId … in the inventory`）是客户端按服务端库存查实例，**不阻塞**；
   要消掉需把购买项注入 `UserInventory`（归 F2 余项/库存）。
9. **卡组 UI 过滤**：缺 `hero`/`defenseCard` 的卡组不会显示在列表里（第一版测试卡组就因此看不到）。
