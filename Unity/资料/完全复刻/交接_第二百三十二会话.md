### 3. 云地址落地（用户问「真实云地址」）

- 之前 404 的**真因**：云上假 PlayFab 是**令牌模式**，路径必须带 `/t/<secret>/` 前缀（`server.py:2410`）。
- 令牌：`05_工具/server/deploy/public_token.txt`（⛔ 不外传；换令牌 = 所有客户端 base URL 一起换）。
- 正确形态 `https://106.14.41.15/t/<token>/Client/<Method>`，实测 **200 真模板**。已 `--cloud` 打进包。
- 设备实测：12 条走云成功，11 条被云 **401 NotAuthenticated**（云有自己的账号体系）⇒ 回落本地模板 ⇒ 仍进主菜单。
  ⚠️ 要让这些也由云作答 = 把本地存档搬上云（**B 档**），不是中继能解决的。

### 4. 冻结：新证据 + 两个真正有效的改动

- **信号假设否定**：冻结时 `gum-js-loop` 的 `SigPnd=0`（没有挂起信号）⇒「Java 补发信号救活」不成立。
- **抓到自家人压满 JS 线程**：等待期每 250 ms `enumerateModules()` + 读 1 MB `/proc/self/maps` 拼字符串
  ⇒ `stime≈7 s`。改 512 KB / 500 ms / 字节比对后 **stime → 0.15–0.44 s**（坑 581）。
- **gadget 17.23.3**：参考包里的 `libgadget.so` 解压后 **25,237,232 B**，与官方 `frida-gadget-17.23.3-android-arm64.so`
  **字节数完全一致**；换上去（旧 17.27.4 备份在 `downloads/libgadget_17.27.4.so.bak`）。
- **A/B 结果**：17.27.4 ≈ **69%**（22/32）；**17.23.3 + 降载 = 15/16 ≈ 94%**（两组各 8 次），
  其中 2 次 JS 真停，**游戏仍进主菜单**。

## 三、关键结论（给下会话的判断依据）

- **冻结的三种签名**（都有现场 dump）：
  ① `rt_sigsuspend` + `SigPnd=0`（定时器/事件循环不再被服务）—— 最常见；
  ② `unix_stream_read_generic`（读 unix socket 阻塞，fd≈0x149）—— **尚未定位来源**，是目前唯一没查的线索；
  ③ 早期还见过 `ptrace_stop`（GC Finalizer，单例，未定性）。
- **判据口径**：`/__health` **只能由本机 JS 答**（⛔ 不能走云中继，否则测不出 JS 死活）；
  冷启动判据 = **进主菜单 + 进去之后再 ping 仍 200**（坑 575）。
- **冻结已不阻断玩家**：服务端由 Java（云/模板）兜底，只是客户端补丁失效。

## 七、本会话新增坑（572–582）

572 本机 SDK 没 `android.jar` ⇒ Java 只能写纯 `java.*`，入口走 smali 注入 · d8 产物当 `classes3.dex`
573 Windows `File.renameTo` 不覆盖已存在目标（Linux 可以）
574 JS 文件队列起点要在「决定走文件模式那一刻」取
575 冻结签名：`gum-js-loop` 停在 `rt_sigsuspend`；判据要改成「进主菜单 + 之后再 ping」
576 apktool 回编会静默合并版本限定目录(364)/重编译 XML(127)/丢 `stamp-cert-sha256`
577 「重复构建 ≠ 干净」：base_src 缓存 + 外部 JS 覆盖
578 dev 包会读外部 `files/wfmain.js` —— 热更后不确认就等于在测旧代码
579 旧 backup.js 会把空态覆盖到 media 备份；新 store.js 双坏不覆盖
580 整段 JS 在 IIFE 里 ⇒ `globalThis[name]` 取不到模块（改闭包 `eval`，并强制打「模块缺席」日志）
581 启动等待期探针（`enumerateModules` + 1 MB maps）把 JS 线程压满：`stime≈7 s` → 0.2 s
582 健康检查/探针接口绝不能走云中继；启动早期也不要走
