## 一、本会话做了什么

### 1.1 事件「结束于」→ 日期（用户新口径）

- 判据：`TimerDisplay.UpdateTimer()` 每秒写一次「描述 + `SupportMethods.GetTimeString(target − 服务器时间)`」；
  `target` 是 private `Nullable<DateTime>`，**Il2CppInterop 反射读出来恒 `HasValue=false`**（坑 665）。
- 做法：在 `UpdateTimer` 跑完后，从它刚写好的倒计时文本解析时长，`target = CurrentServerDateTime() + 时长`，
  把 `timer.text` 覆盖成 `yyyy年M月d日`（保留「结束于：」的 description）；每秒覆盖一次，做等值短路（坑 666）。
- 两端：PC `Probes/EventDateProbe.cs`；安卓 **新模块** `src/eventdate.js`（已登记 `modules.json` + `main.js`；
  回退 `WFEVENTDATE={off:true}`）。
- 真机：`51_pc_dates.png` · `52_a_dates.png` · `53_a_classic_date.png`。

## 三、关键结论 / 判据（新会话直接用）

1. `TimerDisplay.target`（`Nullable<DateTime>`）**反射读不出值**；只能从倒计时文本反推（坑 665）。
2. `TimerDisplay` 文本每秒被原版重写 ⇒ 必须挂 `UpdateTimer` postfix 持续覆盖（坑 666）。
3. `RankingDisplay.Initialize`（含 `Nullable` 形参）**不能挂 Harmony postfix**，会让进程静默消失（坑 659）；
   经典窗改挂 `RankedEventWindowV2.SetDivision`，小冲突由 `SkirmishDivisionProbe` 主动调 `ApplyTo`。
4. 本 build 的 bundle 资产名 = **资产 GUID**，且 PC build 的 GUID ≠ `02_解包资源` 里的（坑 660）；
   `40k_UI_icon_ranked_classic = c648fb…`、`…_Skirmish = d0c37d…`。
5. 安卓 `FeatureConfig.Check("ZeroBasedRank")` 在不同窗口返回值不一致（坑 662）⇒ 评分数字直接按 `WFState` 写真值。
6. 安卓 TMP 类名是 **`TMPro.TextMeshProUGUI`**；`LeaderboardManager` 单例在小冲突首开时可能为 null（坑 663）。
7. 好友表以**服务端**为准（对称表）；本地只是缓存。赛季战绩四桶结构见 §1.2。
