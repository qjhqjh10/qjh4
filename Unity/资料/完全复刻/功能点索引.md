## §2 怎么读这张表（验收三法怎么挂）

| 列 | 用途 |
|---|---|
| 功能点 | 「玩家能做的一件事」。**验收按行跑**，不按类跑 |
| 主链/边角 | **主链** = 玩家一定会走到（开局·出牌·攻击·目标·结算·收藏/卡组主链·卡面数值）；边角 = 次要/低频/纯观感 |
| 挂哪些类.方法 | 回到 `账/<域>.tsv` 的原行（按 `原版类` + `方法` 搜），那里有 `判据出处` / `判据要点` / `我们的落点` |
| 状态分布 | **改成 A 之前先看这一列** —— 有 C 就说明这条功能点还有「该做没做」的洞 |

**三步走**：① **判据签收** = 该功能点下每一条 C/E 都要有 `判据出处`；② **oracle 对照** = 原版离线可跑，拿这条功能点的行为去比；③ **成品并排比** = 截图/录屏与 PvP 卡面/界面并排。

## §4 「主链/边角」两版对照（⛔ 这列原先没有一手判据，本轮补了一版**由账推导**的）

**两版的口径**：
- **我判版**：按方案 §4.2 的 P0/P1 定义人工判断（玩家主链上能看见/能触发 = 主链）。
- **账推版**：取该功能点下 **`状态 = C` 的那些行的 `等级` 列**（P0 ⇒ 主链 / P1·P2 ⇒ 边角）。没有 C 行的功能点记 `—`（账里没暴露差异）。

🔴 **先报一个总账级事实（现读，⛔ 别抄死）**：**9,603 行里 `等级 = P0` 的行有 105 条**，其中 **0 条是 C 行**（C 行合计：P0×0 · P1×1 · P2×2 · 未填×0）。⇒ 「P0 ⇒ 主链」这条口径**现在判得出主链**了。⚠️ 但**有 C 行没填等级**的那几条会静默落进 4.2，别把它当「已对齐」。

## §5 本轮没做到的

1. **不是「功能点全集」**：这张表是**从账里长出来的**，账没覆盖到的功能（例如账里根本没列的方法）不会凭空出现。
2. **粒度不均**：`战斗逻辑驱动` 那 1,380 行切成了 27 个功能点，而 `本地化` 只有 10 行却是 1 个功能点 —— 这是账的规模差异，不是重要性差异。
3. **「最高档 A」会骗人**：它只表示「至少一个方法已对齐」。判断这条功能点能不能验收，看**分布列**。
4. **活动线只标了「暂停」**，没有细化 —— 用户暂停期间不做归并。⚠️ 但「暂停」现在**逐条规则写死**（不是按域名切），活动线里**不**暂停的条目（`排位赛与遭遇战模式`）不会跟着被标暂停。
5. **⏭ 编译器生成类型那几行不参与验收**：只为「账没有丢行」留档（见 §1 备注与 `SKIP_NODES`）。
