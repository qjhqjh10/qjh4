### 2.2 🔴 覆盖账多算了 25 条 —— `parse.py` 的「`{}` 单行空类型」缺陷

**机理**：`D:/2/_tmp_view/wfcover/parse.py` 的 `re_decl` 能认出类型声明，但**把 body 收拢的结束条件写成了「列 0 的单独一行 `}`」**：

```python
if s == '}' and not line.startswith(' '):
    cur = None
```

而 dump.cs 里**空类型是写成 `{}` 一行的**：

```
public interface IClassicEvent : IOwnDeckPlayEvent, ... // TypeDefIndex: 3542
{}
```

⇒ 这一行既不触发新类型、也不触发结束 ⇒ **后面那个类型的全部方法被记到了这个空类型头上，而后面那个类型整个从 `types.json` 里消失**。

## 五 没查清 / 已知局限

1. **Cpp2IL 的 `dev_ilspy` 只导出了 `Assembly-CSharp.dll`，没导出 `Assembly-CSharp-firstpass.dll`** —— 因此 firstpass 的类（本名单里只有 `DOTweenExtensions` / `<Module>`，共 2 条 X）**无法用 Cpp2IL 复核体**，只有 `decomp_full` 里的 `DOTweenExtensions__DoSlideIn/__DoWidth` 两个文件。
2. **`RankedDivision` 是 `record`**，我最初的正则只认 `class/struct/interface/enum`，漏了 `record`；补上后能扫到 10 个成员。但那条链上 `op_Equality/op_Inequality/<Clone>$` 在 C# 里写成运算符/特殊名，**没有做逐条名字对齐** —— 这 9 条 X 的「真身有体」结论是**按同文件成员清单判的**，不是逐条精确匹配。
3. **A 档带 `Method not found` 空洞的，我只判了「有体」和「有洞」，没有逐条把洞补出来**。~~补齐需要顺着每个 `Method not found @VA` 反汇编~~ 🔴 **2026-10-25 G5 更正：这条路只对 42 条有效**；其余 276 条的体被 `Unmanaged memory load` 打成 `if ((nint)0 != 0)`，**洞后面没有业务逻辑可读**（精确数 = **318**，不是 322）。详见 `判据/半缺口_322条_第2轮.md`。
4. **「19 条 `0x4B33B0` = 空方法」这条结论，依据是「共享空桩 + `ret 0`」**。理论上还有一种可能：IL2CPP 给「泛型实例化后代码相同」的方法做了**折叠**（fold）—— 但折叠只会发生在**同代码**的方法之间，而一个 `ret 0` 的体只可能来自空方法体，所以结论不变。
5. **`dec` 的准确重算没做全**：我只对 159 个类做了「`<base>__` 前缀」近似匹配，没有对全库 1,488 个游戏类重算 `dec`。所以 §2.3 的「至少 10 个类其实有 `.c`」是**下限**。
6. **`types.json` 少了 29 个类**，我把其中 12 个带方法的列了出来，但**没有把整份覆盖账按正确解析重算一遍** —— 那是覆盖账自己的返工活，不在 G1 的范围。

## 七 顺手发现（不属本 724，但下个会话该知道）

1. 🔴 **`复刻覆盖账_首版_1025.md` §1.1 的「165 类 / 724 方法」应改为「159 类 / 699 方法」**，另 25 条是 `parse.py` 的 `{}` 缺陷串档（§2.2）。**建议在覆盖账里就地加更正注**（铁律 5），并把 `parse.py`/`count2.py` 的缺陷写进去（否则下次重跑还是 165/724）。
2. 🔴 **`parse.py` 还漏了 29 个类型 / 其中 12 个带方法**；**`count2.py` 的 `dec` 对泛型类恒为 0**。两个脚本都要修，否则覆盖账的「有方法体」列对所有泛型类都是假的 0。
3. 🔴 **`out_cpp2il_ilspy` / `out_il2csharp` / `out_cpp2il_dif/DiffableCs` 三份都是签名壳**（`throw null;` / `NotImplementedException` / `{ }`）。**只有 `out_cpp2il_dev_ilspy` 有真方法体**，而且它**不含 `Assembly-CSharp-firstpass.dll`**。→ 建议写进 `资料/全量反编译_入口与用法.md`，避免下一个人又拿 stub 版做交叉验证（我这次就差点被骗）。
4. 🆕 **Cpp2IL 会「静默丢体」**：`{ }` + 零 note，但机器码里有一条 `mov`（§3.1 两条）。⇒ **凡「Cpp2IL 说空」，一律要 RVA 复核**。这条和 CLAUDE.md 里那条「`.c` 读不出来要两份都打开看」是同一族，但方向相反（这次是 Cpp2IL 在骗人）。
5. 🆕 **IL2CPP 把所有空方法体折叠到一个共享桩 `0x4B33B0`（`ret 0`，全程序 1,992 处引用）**。这是一把**现成的判据**：「原文里这个方法是不是空方法」可以直接问二进制，不必推理。全库扫一遍还能顺带统计出「原版有多少空方法」。
6. **`out_cpp2il_dev_ilspy` 的文件里，一个文件可能有多个顶层类型**（`MissionEvent.cs` 同时有 `MissionEvent` 和 `MissionEvent<TS,TD>`）；**反编译器会把名字转义**（`_003C_ScheduleHandlerRefresh_003E_b__25_0`）—— 按名字找方法前必须先反转义。这两条都会让「找不到方法体」变成假结论。
