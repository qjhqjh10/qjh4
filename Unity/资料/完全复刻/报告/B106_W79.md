## 四、静态判定的推理与依据（结论：都不是 A、也不是 B）

**现场复述**（日志 + `D5` §三）：`:131964` 前提红（`got != infoWb`）；`:131980` 紧跟着**全日志唯一一次** `[Shop] 没有 WindowsManager ⇒ 开不了 Booster Info Popup`，栈 = `OpenBoosterInfo ← BuildCell b__0 ← WindowButton.Click ← PointerLayer.ClickAt ← ClickByQuad`；且 `:132014` 之前那条「…这一下点在它渲出来那块的中心上」是**绿的**（`ClickAt` 返回 true）。
⇒ 点到的**确实是一颗 `InfoHit`**，但**不是 `w2` 那颗**，且那颗所属页 `_win` 为假 null（或其 `Manager` 为 null）。

**逐条推**：

1. **「多一张命中表候选」需要该钮 `activeInHierarchy`** —— `AllButtons()` = `Object.FindObjectsByType<WindowButton>(FindObjectsSortMode.None)`（省略 `FindObjectsInactive` ⇒ **Exclude**）⇒ inactive 的窗/页根本不参与。
   ⇒ 候选 A 那种「只 Close 不销毁」留下的窗（`Hide()` 已 `SetActive(false)`）**造不出本红**。
2. **B 的路不存在** —— `BuildPages()` 唯一调用点在 `Open()` 里的 `Build()` **之后**，而 `BuildShell` 第一句 `DestroyChildren(window.transform)` 会把旧的 `Content Area/Tabs` 整棵（含全部页）销毁（`MenuDraw.ClearChildren` 在**编辑模式**走 `DestroyImmediate`，`Shell/MenuDraw.cs:145`）。
   ⇒ `tabs.Clear()` 不销毁旧页这件事**永远不会被触发成孤儿页**。
3. **一个页能活着的唯一形态 = 它的 GameObject 活着**。而页是**窗 GameObject 的后代**（`Node(tabHolder, …)`，`tabHolder` ⊂ `Content Area` ⊂ 窗根，`Shell/MainMenuSubwindowWindow.cs:553/578`）⇒ `DestroyImmediate(窗.gameObject)` 连页一起没（`B103F4_Assert` 自己的 `finally`、`ShopScene` 的 `wOff/wOn/wSm/w15Host` 都是这么做的）。
4. ⇒ 要得到「页激活 + `_win` 假 null」，只能是：**宿主组件被单独销毁**（页 GO 还活着），或 **`_win.Manager == null`**（宿主是活窗但 Manager 为空 —— 早退条件的两段之一，日志分不出来）。
   本仓对「窗自建出来的页」**没有找到**任何组件级 `DestroyImmediate(win)`；`_win` 也**只有** `SetHost` 一处写（`:63`），而 `SetHost` 的两个 `null` 调用点（`B97_SHOP2_Assert.cs:130` / `ShopFamilyAssertB94S1.cs:108-116`）建的是**裸 GameObject**（不建树、且 `finally` 里 `DestroyImmediate(go)`）。
   ⇒ **判不出来，不猜着改。**

**为什么我不做「把 `ReapClosedWindows` 的静默豁免收窄」这种顺手修**：① 判据不成立（它解释不了本条红）；② `Shell/WindowsManager.cs` 不在我的白名单内。

## 九、顺手发现（不改，只报）

1. 🔴 **`GameWindow.Hide()` 的首句守卫会制造「永久僵尸窗」**（`Shell/GameWindow.cs:699` 起）：
   `if (!gameObject.activeSelf) return;` ⇒ 对**已经 inactive** 的窗调 `Hide()`，`CurrentState` **不会被写成 `Closed`**。后续两处一起失效：
   - `ReapClosedWindows`（`WindowsManager.cs:1668`）的 `w.CurrentState == Closed` 不成立 ⇒ 它被**从待收表静默摘掉、不销毁**（就是 D5 说的那条静默豁免）；
   - 再调 `TryOpen()` 时走 `OpenByState` 的 `Open` 支 ⇒ **一个字段都不写就 return**（`Shell/GameWindow.cs:516` 起）⇒ 这扇窗**既回不来、也销毁不掉**。
   本条的**证据面**：本次红**不是**它造成的（它 inactive ⇒ 进不了命中表），但它和「陈旧页/陈旧窗」是同一族；且 `WindowsManager.cs` / `GameWindow.cs` **不在本代理白名单**，所以只报不改。
2. `OpenBoosterInfo` / `OpenBoosterPack` 的早退条件是**两段**（`_win == null || _win.Manager == null`），日志文案只有一条 ⇒ 单看日志**分不清**。本次诊断文案已把两半分开印（`HitIdentity`），不需要再改生产代码。
3. `AllButtons()` 用 `FindObjectsSortMode.None` 的重载（= Exclude inactive）—— 这条事实本身是「候选 A 单独不成立」的判据，值记一笔，免得下次有人拿 `[Win] 关过的那一具 ⇒ 销毁` 的日志条数去推「场上还有几具活窗」。
4. `shop.log` 里 `[Shop] Packs Scroll View … 已接`（= `ShopWindow.Build()` 跑到过）共 **16** 次，而本场景里 `ShopWindow.Create` 只有 **10** 处 ⇒ 有 **6 次是「Closed ⇒ Open」重开触发的 `Open()` 重建**。因为 `BuildShell` 首句就 `DestroyChildren`，这些重建**不留旧页**（= 上面 B 被排除的实据之一）。
