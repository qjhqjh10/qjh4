## 3 战斗域逐条补齐结果（四档，带证据）

见上表 + `判据` §三。三条最有价值的：

1. **`RawCardScript.do` → `GetChatSound`**：G3 的 `missing` 是「成员名被解析成裸 `do`」造成的假缺口；`decomp_full/RawCardScript__GetChatSound.c` 完整给出 `ChatMessage → AudioClip` 的 **11 支 switch（case 0–10 + default）**（字段偏移 `+400/+0x198/+0x1a8/+0x1b0/+0x1a0/+0x1b8/+0x1c0/+0x1d0/…`）+ 「音频引用为空 ⇒ `LogWarning` ⇒ 回落 `defaultChatSound`」。⇒ **战斗域真缺口 = 0**。
2. **`AI.ScoreFromCriteria`**：`AI__ScoreFromCriteria.c` 有 367 行、**但首行返 `void`、每处浮点累加都被 Ghidra 吞掉、函数尾只剩 `return;`**。**这不是新发现**（`G3` 的 R6 更正已记），本件确认它**是 66 条里唯一一条「体在、值全丢」**，且**已用 VA（`RVA 0x93A290`）逐 case 补出来**，落地在 `RuleEngine/Data/AiScoring.cs`（文件头逐段列了 11 段 RVA）。
3. **vtable 槽模型（本件现推，可复用）**：`槽号 N = (偏移 − 0x138) / 0x10`，两个独立锚点坐实 —— **`0x158` = 槽 2 = `Object.GetHashCode`**（`CardDeck` / `RoomInfo` 两个不同类的 `GetHashCode` 都调它）、**`0x168` = 槽 3 = `Object.ToString`**（三处 `StringBuilder` 返回点都调它）⇒ 槽序 `0 Finalize / 1 Equals / 2 GetHashCode / 3 ToString`。以后 `.c` 里见到 `(**(code **)(*p + 0xN))`，**先算槽号再对名**，比反汇编便宜一个数量级。

### 3·1 顺带发现的系统性质量闸（建议进 `工具/`）

本件用「**`.c` 首行返回类型 vs `dump.cs` 声明返回类型**」做了一次机器比对，**战斗域 66 条里命中 15 条降级**（22.7%）。
这是**最容易实现、最能止损**的一道闸 —— `.c` 看着有几百行、逻辑完整，**返回值全丢**（`AI.ScoreFromCriteria` 就是这么骗了一整轮）。**全库 25,096 份 `.c` 还没扫过**，见 §5·2。
