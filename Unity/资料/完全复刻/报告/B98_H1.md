### 一·二 🔴 **前提订正：「两条行跑同一组 op = 双份」在现代码里不可达**（铁证，请复核后再决定要不要更严格）

施工单写的是「`SW21` 两个对象、两行 `j` 都是 0 ⇒ 两条行跑同一组 op = 双份」。**现读代码，这个结论不成立**，理由两条：

1. **`plan` 的 `rows` 永远只来自【一个】能力对象**（`RuleCore.cs:15529-15554` `ResolveActiveAbilityRows`）：
   ```
   if (hasAct != hasAlt) return hasAct ? rowsAct : rowsAlt;      // 只有一组 ⇒ 就是它
   bool? alt = u.Card.UsesAlternativeAbility(ctx, p, u);
   return alt.Value ? rowsAlt : rowsAct;                         // 两组都有 ⇒ 运行期闸挑**一组**
   ```
   ⇒ 它**从不返回两组拼起来的表**。`SW21` 的两组各 1 行（`RuleEngineTest_G12.cs:466-471` 现成断言钉着），
   所以 `plan` 里**只有一条** `{10, ta, 0}`，`executed` 只加 1。
2. **同一组内部 `j` 本来就互不相同**（`j` 就是 `row.ChosenAbility` 的下标）⇒ 组内不存在键撞车；
   跨组的两条行**不可能同时进 `plan`**（第 1 条）。

⇒ 因此 `SW21` 今天**没有双份**：`ActiveRowOpsOf(u, 0)` 取到那 1 条 `ferocity` op，**执行一次**。
（若探针 `play` 的事件电池里真看到两段 3 点伤害，那是**别的原因**：现读基线 `E|SW21` 那行
`☠ 伤害累计 P0 10 → 13;☠ 伤害累计 P0 13 → 16` **不是** `SW21` 独有形状 ——
`out_play_baseline.txt` 里 `E|` 行带 ≥2 段伤害累计的共 **483 行**（电池本来就含 `selfChip` / 两发攻击 / 两个来回）。
🔴 请调度台在跑 `play check` 时**另行定位**这两段伤害的来源，别把它算在本笔头上。）

**那本笔到底做了什么**：把这条链上唯一的**隐含假设**（「op 的 `ActiveAbilityRow` 是哪个对象挂的」= 挂载对象）
显式化，并给出**唯一一处**判定点 `ActiveRowOpsOf(u, ab, row)`：

* 行属于**挂载对象** ⇒ 照旧按行号取（与 `ActiveRowOpsOf(u,row)` 逐字等价）；
* 行属于**另一个对象** ⇒ 只有 `ApplyActiveAbilityLogic` 闸③（`SameActiveRows`：两组逐格一致）**放行过**
  （= `CardDef.ActiveAbilityMap == "attached"`）才借用同一批 op —— 那本来就是**设计**（`SW21` 走的就是这条）；
  闸③ 没放行 ⇒ 那时**一条 op 都没挂**，本来也取不到。
* 📊 **可达性（如实标）**：第二支的「拒绝借用」那一句 = **0 张可达**（两对象 ∧ 闸③ 不过的卡一条 op 都没挂）
  ⇒ 本笔对现池**零行为变化**，它是**结构闸**（铁律 11：休眠也留着）。
* ⛔ **本方法不重判闸③** —— 只读它的**结论** `ActiveAbilityMap`；抄一份 `SameActiveRows` 会让两份判据迟早不一致。
