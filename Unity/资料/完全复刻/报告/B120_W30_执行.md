## 一、判据结论（先判，后改）

### 1. 这个机制到底在做什么

**不是「换整副牌」，是「这副牌的督军变身成另一位督军」。** 逐句判据：

- `d:/2/tools/decomp_full/BattleManager__CheckForHeroDeckTransform.c`（101 行全文）
- `d:/2/tools/decomp_full/BoardAnalysis__DeckMeetsCriteria.c`（101 行全文）
- `d:/2/tools/decomp_full/BattleManager.__c__DisplayClass282_0___CheckForHeroDeckTransform_b__0.c`（谓词）
- `d:/2/tools/cpp2il/out_il2csharp/Assembly-CSharp/BattleManager.cs:1097-1145`（同一方法的可读版，与 `.c` 逐句交叉）
- 调用点 `decomp_full/BattleManager__SetupBoardPhase.c:56/66`：`CheckForHeroDeckTransform(matchData.playerRawBattleData(+0x58), isPlayer:1)` / `(enemyRawBattleData(+0x50), isPlayer:0)`
- 字段表 `d:/2/tools/il2cpp_out/dump.cs:23244`（`RawCardScript.deckCriteria // 0x1F8`、`transformedWarlordId // 0x200`）
  · `:18804`（`PlayerItem.uniqueId // 0x38`）· `:77945`（`DeckAndWarlordData.deckWarlord // 0x18` / `shuffledCardLibrary // 0x28`）
  · `:78170`（`MatchData.originalPlayerWarlord // 0xD8` / `originalEnemyWarlord // 0xE0`）

跳序：

1. 取 **这一副牌自己的督军** `rawBattleData.deckWarlord(+0x18)`；
2. `BoardAnalysis.DeckMeetsCriteria(shuffledCardLibrary(+0x28), deckWarlord)` —— 拿**这副牌本身**按督军身上的
   `deckCriteria(+0x1f8)` 逐张筛、比张数（`countCriteria.targetsAffected == 0` ⇒ 原版**直接 return 1**「无条件即满足」；
   否则 `triggerIf(+0x18)` 1/2/3 = 相等/≥/≤ 与 `referenceValue(+0x1c)` 比）；
3. 满足 ⇒ 按 `deckWarlord.transformedWarlordId(+0x200)`（**另一位督军的 id**）到
   `PlayerDataManager.fullHeroCollection` 里 `Find(hero.uniqueId(+0x38) == 那个 id)`；
4. 找到 ⇒ `matchData.originalPlayerWarlord(+0xd8)` / `originalEnemyWarlord(+0xe0)` ← 原督军，
   再把 `rawBattleData.deckWarlord` **换成找到的那一位**（**只换督军这一格，牌库一张不动**）；
   玩家侧再 `VoiceLinesController.SetTransformedWarlordNewChats`。

**关于「名称叫 Transform、谓词比 id」的矛盾**：不矛盾。谓词比的是
`hero.uniqueId == deckWarlord.transformedWarlordId` —— **两个不同的 id**（目标是另一位督军）。
派活简报里那句「谓词比的是同一个 id」是简报自己的笔误（`+0x200` 是 `transformedWarlordId`，不是 `cardId`/`uniqueId`）。
旧实现（`B96_CB`）把它读成「同一个 id / 换牌库」，属于**按名字猜语义**。
