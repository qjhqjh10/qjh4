## 四、⚠️ 顺手查出的一处同族真缺口（⛔ 我没改，请调度台立账）

**`DeadCandidates`（`EffectResolver.cs:6440`）仍手扫 `ctx.DeadUnits`，绕开了墓地那四条闸。**

- 触发面：`ChooseCardCandidates` 的 `ChooseSrc == "dead"`（`EffectResolver.cs:4835`），来自卡面 `… that died this game / this battle / since your last turn`。
- 池内命中 **5 张**：`EC39` / `GSC44` / `SAU39` / `SOR42` / `UM61` —— 它们的 `abilityTargets[].ta` 现读**就是 `60`**
  （`cards_engine.json` 现扫：`EC39 [[60]]` · `GSC44 [[60]]` · `SAU39 [[60]]` · `SOR42 [[60]]` · `UM61 [[60,0]]`），
  即**原版这一支的候选同样来自 `GetCardsInCemetery`** ⇒ 残骸 / 放逐 / 「不在墓地」这三条闸都该生效；我们这一支一条都没判。
- 差别是**可观察的**：残骸被摧毁后那张卡**在 `Discard` 里**（`RuleCore.cs:9955` `AddToCemetery`）、也在 `DeadUnits` 里，
  所以它会**被当成「本局死过的部队」让玩家选**（原版选不到）。
- **为什么我没改**（三条，任一条都够）：
  ① `EffectResolver.cs` 此刻有 **3 路在飞写手**（`W9` / `W9b` / `W36`，见 `文件所有权_当前.md`）⇒ 撞车风险；
  ② 换源会把「手牌超上限弃掉的单位卡」也变成候选（`CemeteryDeadUnits` 的 `DeathTurn = -1` 档，`B98_K4` 已按「窗口档排除」落），
     **「`this game` 无窗口档要不要收它们」还没查清**（原版墓地列表的构成需要另查 `PlayerHand` 超上限那一跳）⇒ 判据不足；
  ③ 改的是**行为**不是注释，必须跑宿主自检，而本代理不跑 Unity。
- **可粘贴的落法（给调度台）**：
  - `EffectResolver.cs:4835`（**同一物理行**、行数零变化）：`source = DeadCandidates(ctx, owner, op.ChooseDeadScope);` → `source = DeadCandidatesFromCemetery(ctx, owner, op);`
  - 新方法**追加到 `EffectResolver.cs` 类尾**（该文件账落点密集，⛔ 别插中间）：用 `CemeteryDeadUnits(ctx, owner, null, op)` 取候选、`d.Owner != owner` 过滤、`d.DeathTurn >= 0 && d.DeathTurn < mark` 做 `since_last_turn` 窗口（`-1` 排除）、`Card` 投影成 `List<CardDef>`。
  - 断言：把 `B141_W65_Assert` A 组那份夹具换成「残骸在 `Discard` + `IsRemnant=true`」⇒ `ChooseCardCandidates` 的候选表里**不该有它**（现在是**有**）。
