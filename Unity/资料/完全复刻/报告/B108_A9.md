## 一 · 逐类型实现（读数口 + 口径出处）

### 1.1 `effect_render` → op `sweep_ratio`

- **读数口**：`资料/比对基线/sweep_orig.tsv`（962 效果 × 8 时刻）＋ `sweep_exp.tsv`（957）。
  `输入/命令` 写 `effect=<名1>|<名2>...`（可 `orig=`/`exp=` 覆盖路径），`期望` 写**验收阈值**（本批一律 `0.30`）。
- **算法**：**逐字照 `工具/analyze_sweep.py`**（不是另立一套）：
  - 一个时刻「有内容」= 该侧 `lit >= LIT_MIN`（`analyze_sweep.py:60`，60 个亮点，低于它算噪声）；
  - 亮度比 = `sum`（第 4 列，线性亮度和）的 `exp/orig`，取**中位**；验收量 = `|ln(中位比)|`；
  - 分支次序照 `analyze_sweep.py:137-160`：
    两侧全程空 → 跳过（W）；只有一侧有内容且另一侧峰值 `>= LIT_MIN*0.6` → 「次阈值小样本」按任意两正时刻的比值中位算；
    只有一侧有内容（另一侧峰值 <36）→ **C/D = 红**（原版独有 / 我们独有）；两侧有内容但**从不同时出现** → **T = 红（时序错位）**；
    两侧都有内容 → 用 `both` 集合的比值中位。
  - 一条都不在可比区间 → 行状态 `缺数据`（不是通过）。
- **阈值出处**：`|ln| <= 0.30` = `资料/特效还原_进度与交接.md:1640`「**现在全表没有任何一条 > 0.30**」＋同文件 `:1463 / :1562 / :1632` 三张表的 `>0.30` 列。⛔ 本批**没有改**这个数，也没有把它写进代码后就不看文档 —— 每行自己的 `期望` 列也写着 `0.30`。
- **比 S 文档更严的地方（必须写清）**：`analyze_sweep.py` 的「判定列」用的是 0.7–1.4 带宽（它自己声明**只用于分组、不是验收**）；本工具用 `|ln|<=0.30` 作验收。**两者在 0.706 这个点上分歧**（带宽判 Z、验收判红），见 §6 顺手发现 1。
