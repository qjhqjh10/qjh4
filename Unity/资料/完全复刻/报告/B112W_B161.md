## 为什么这不是「第二套基准量算法」

**先说为什么不能照简报字面用 `CardProgress.Owned(c.Id, c.Rarity)` 当期望值**（逐行推演，不是猜测）：

1. `Owned` 的实现（`Shell/CardDetailPopup.cs:237-250`）：
   ```csharp
   var info = Inventories.Cards.Get(id);
   if (info != null) return info.Amount;   // ① 在背包里 ⇒ 回背包值
   if (_owned.TryGetValue(id, out v)) return v;   // ② 否则先查 _owned 缓存
   v = DeckCap(rarity) + (NeedCopies[MaxLevel] - NeedCopies[1]);   // ③ 最后才是公式
   ```
2. 迁移第 ⑤ 步（现 `:215-223`）是**先摘条目、再播种** ⇒ 此刻 `Owned` 命中的是 **②**，也就是缓存里那个 5；
3. 于是播种给 5、复核 `5 >= Owned(=5)` **恒真** ⇒ 判据重新变成恒绿 —— **正是本条要堵的那个洞**。
   换句话说：在「条目已摘掉」的状态下，`Owned` 与「播种实际给的值」是**同一个函数同一个状态**，两者相减恒为 0。
4. 缓存也读不到、也摘不掉：`_owned` 是 `private static Dictionary`（`CardDetailPopup.cs:133`），本次白名单不含那个文件 ⇒ 没有公开口。

**所以只能绕开缓存，用 `Owned` 的 ③ 那一支。** 这是**同一式子的第二处副本**，不是第二套算法：

- 式子 `DeckCap(rarity) + (NeedCopies[MaxLevel] - NeedCopies[1])` 与 `CardDetailPopup.cs:247` **逐字相同**；
- 本文件头部 `:15` 早就把它写成「基准量」的定义，断言侧 `B113_G3_Assert.cs:273-274` 也用它算 `want` —— 全工程认的就是这个数；
- 本文件里**只有一处**（`ExpectedCardAmount`），没有散落；
- 刻意走**不带卡型**的 `DeckCap(rarity)`，与播种那句 `Owned(c.Id, c.Rarity)` 同档（那条也吃不到 `CardDef.Type`）
  —— 若改用带卡型那档，督军会算成 10 而播种实际给 11，反而把「修好了」误判成「没修好」。

⛔ 我没有新开 `Inventory.cs` / `CardDetailPopup.cs` 的 API（白名单外）。要彻底消掉这份副本，见下面 §还差什么。

## 边界：哪些情况仍会静默（若有）

1. **卡池查不到、且数量 > 1 的行**：算不出基准量 ⇒ 既不修也不报（只报 `<= 1` 的那档）。
   这些行**值不变**；如果同一次迁移里有别的卡被修好、Save 把它们原值写回去，那是**原样回写**，不是新写的坏值。
2. **基准量以上、但可能也是陈旧的行**（例：`_owned` 缓存 12，基准 11）：按 11 判「不算坏」。
   合法来源（`AddOwned(+1)` 的创建副本）产出的正是 >11，无法与「陈旧偏高」区分 ⇒ 宁可不动（不猜）。
3. **`WarpforgeCardLevels.json` 的 `owned` 数组本身不修**（本迁移只管 `cards.json` 背包）。⇒ 被毒化的那张卡：
   背包/盘上仍是原值（可能是 1），但 `_owned` 缓存还是 5 ⇒ **每个进程启动都会再报一次 `LogError`**。
   这是**有意出声**（不许静默），但确实会是重复噪声；根治要另一份档的裁定（见 §还差什么）。

   `B113_G3_Assert.cs:227-231` 的 O-3 那条断言会红 —— 那是它自己注释里写明的待改点。

## A · 迁移侧的第 4 处改动（为让 `B161-1h` 成立，且它本身也是同一个洞）

**问题**：`:repaired == 0` 那条分支（「一条都没修好 ⇒ 不写盘」）**只保证不写盘**，内存里已经是播种值（例：5）。
玩家接着干任何事（`AddOwned` 的创建副本、`SetLevel`…）都会调 `InventoryStore.Save` ⇒ 那个 5 **照样会被写进盘**。
和「第三个洞」是同一个根：`Save` 写的是整份 `SnapshotAmounts()`。

**改法**：把「恢复成迁移前」抽成 `static bool RestoreUnfixedAmounts(...)`（`InventoryPartial_B112G.cs` 类尾），
**两条分支都调**：`repaired == 0` 先还原再返回 `false`；有修复时还原完再落盘。
`repaired == 0 ⇒ 不写盘` 这条**保命闸一字未改**（还原不涉及 `Save`）。
