## §6 顺手发现（⛔ 我没改任何东西，交调度台分流）

1. **`CardScript.SetFutureRemnant` 的 VA 在 `dump.cs` 落到 `CacheControlHeaderValue.set_Private`（账行 896）**
   —— 不是普查错，是 **ICF 折叠**：`SetFutureRemnant(bool)` 的体就是 `base.isRemnant = v`（ILSpy `CardScript.cs:21192`），
   与 `EntityScript.set_isRemnant`、`CacheControlHeaderValue.set_Private` 是**同一段机器码**（地址 `0x1805FCB80`）。
   ⇒ 给「同 VA 多方法」清单**再加一例**；也说明「按 VA 反查方法名」在这类小 setter 上必错，要按**形参个数 + 体**区分。

2. **`decomp_full/CardScript__SetFutureRemnant.c` 的首行函数名不是自己**（是 `EntityScript__set_isRemnant`）
   —— 属于 CLAUDE.md 里已记的「文件名与内容不符」那一族，但这里成因是**折叠**、不是产物错位。
   判法仍照旧：**先读体**。

3. **`out_il2csharp` 比 ILSpy 多抓到一个关键入口（账行 456 `PlayAi`）**
   —— 建议把「字符串名 `StartCoroutine("X")` / `StopCoroutine("X")`」做成普查的**第五个计数列**（`sc=`），
   否则整族「用字符串名启动的协程」会永远被算成 0 调用。本批只命中 4 个串：
   `AddNextReplayAction`（3 次）/ `ReplayPlayAction`（3 次）/ `MulliganCountdown`（2 次）/ `WaitOpponentLastActions`（1 次，另 `PlayAi` 只在 il2csharp 里）。

4. **`MulliganFallbackCountdown` 与 `MulliganCountdown` 是两个不同方法**
   —— `StartCoroutine("MulliganCountdown")`（2 次）起的是**另一个**协程；`MulliganFallbackCountdown` 只有在 `ClickChosenCardDone` 里（内联后）被起。
   写我们换牌超时的时候**别把这两个合并**。

5. **`BattleActionType` 枚举 91 个非 0 项，`ResolveAction` 只有 82 个不同 case ⇒ 差 9 项**
   （现读，命令见下）：
   `2 createMinion` · `6 showEnemyCard` · `8 doDamage` · `12 playHeroPower` · `24 replaceHeroPower` ·
   `32 mulligan` · `33 returnToDeck` · `40 growthAnim` · `73 reanimate`

   ⇒ **枚举里有、分发里没有** = 这些 action 类型即使被生产者入队也无人处理（或由别处单独处理，如 mulligan 走专门流程）。
   ⚠️ 我**只做了枚举↔case 的差集**，没去核这 9 类各自的真实处理路径，**建议另立一条只读账**：
   「这 9 个 action 类型有没有生产者 / 生产者是谁 / 谁消费」。
   复算命令（可直接复跑）：
   ```bash
   python -I -X utf8 -c "import io,re;RA=io.open('d:/2/tools/decomp_full/BattleManager__ResolveAction.c','rb').read().decode('utf-8','replace');labs={int(m.group(1),16) if m.group(1).startswith('0x') else int(m.group(1)) for m in (re.match(r'\s*case (0x[0-9a-fA-F]+|\d+):',l) for l in RA.split(chr(10))) if m};d=io.open('d:/2/tools/il2cpp_out/dump.cs','rb').read().decode('utf-8','replace').split(chr(10));s=d.index('public enum BattleActionType // TypeDefIndex: 917');E={int(m.group(2)):m.group(1) for m in (re.match(r'\s*public const BattleActionType (\w+) = (\d+);',l) for l in d[s+1:s+140]) if m};print(sorted((v,E[v]) for v in E if v and v not in labs))"
   ```

6. **`GetUnitsInPlayRef`（账行 387）是纯字段 getter（`return this->[+0x470]`）**，
   而 `GetUnitsInPlayNewList` / `GetAllCardsInPlay` 都是**构造新 List**。
   ⇒ 原版这句 `return ref` 很可能就是**为了避开复制**；我们引擎里若把两者合并成一个，注意**别引入每帧分配**。

7. **`MinionManager.Awake` 与 `FillMinionPositions` 互含对方的 guard**
   ⇒ 两个方向都内联过一次。说明 `Awake` 里**直接展开了槽位表构建**，`FillMinionPositions` 作为独立函数只是给别处（可能 `OnDrawGizmosSelected` 附近）留的。
   我们实现时**只需一份槽位表构建**，别写成两处。
