## 三、`B142-DROPDOWN-LANGROWS` —— 重建前清空 `_langRows / _btnLangRows` ✅

**文件**：`CardPresentation/Battle/SettingsPanel.cs`（简报写 `Shell/` —— 见 §〇 ①），**行数 2999 → 2999**。

改前 `:1752`：
```csharp

```
改后（同一物理行追加）：
```csharp
float botFull = top - LstHPx; if (withRows) { _langRows.Clear(); _btnLangRows.Clear(); }
```

**为什么这是真缺陷（可达路径）**：`ShowLangList` 只在 `_langList == null` 时重建
（`:1866`），而 `_langList` 是 `Transform` —— **宿主子树被销毁后它是 Unity 假 null**
（`== null` 为真）⇒ 会再建一次；但 `_langRows` / `_btnLangRows` 是**普通 C# List**，
里面还是上一批**已销毁**的件 ⇒ 不清就**行数翻倍**，`LangRowCount` / `LangRowBg(i)` /
`RefreshLangRows()` / `HitLangRow()` 全部指到销毁件（静默）。
同一棵树被重建（`MenuDraw.ClearChildren` 那一路）就会走到这个状态。

**为什么加 `if (withRows)`**：同一个函数也被 `:1724` 用来建 **`Template` 原型**（`withRows = false`），
那一档**一行都不加**（`real == false`），清空会把别人正在用的表清掉（虽然当前是首次构建，但不能靠巧合）⇒ 明确挡住。

⚠️ 纯防御性：今天 `_langList` 从没被显式置 null，正常路径只建一次；这条防的是「子树被重建」那一档。
