## 0. 为什么不能直接写执行器

`AbilityLogic__PlayAbility.c:293-345`（`chosenAbility == 0xa5`）的**第一格**就读 `AbilityLogic.playersAffected`（`+0x20`）：
```
SupportMethods.IsPlayerAffected(thisCard.isPlayer, playersAffected)
SupportMethods.IsPlayerAffected(!thisCard.isPlayer, playersAffected)
```
它决定「弃哪一侧的手牌」。而我们的 `CardDef.TriggerAbilityIndexSpec.Pa`（`Core/CardDef.cs:9229` 那一行里）**今天恒 `-1`**：
- `Data/CardDatabase.cs:5032 MapTriggerAbilityIndices` 只填 `Ab / Lg / Trigger / TriggerValue / Ca`（`list.Add` 在 `:5054`）；
- `Pa / Ta / Fm / Mult` 的装载口是**附魔模板那条路**（`CardDatabase.FillEnchantmentIndexPayload`），卡表主路没有。

⇒ 现在写执行器，只会永远走「`playersAffected` 读不到 ⇒ 出声 + 不结算」那一支。**先补数据列。**

### 2.1 执行器本体

```csharp
static int RunDiscardWholeHandRowOfHandCard(BattleContext ctx, int owner, CardInstance inst,
                                            CardDef.TriggerAbilityIndexSpec row, string by)
{
    if (ctx == null || inst == null || inst.Card == null || row == null) return 0;
    string who = by ?? "手牌能力";
    int pa = row.Pa;                                   // v50 起卡表主路才填；< 50 / 缺键 = -1
    if (pa < 0)
    {
        ctx.Log($"{who}：「{inst.Card.Name}」的手牌 `ca 165`（discardWholeHand）—— `playersAffected` **读不到**"
              + "（`CardDef.TriggerAbilityIndexSpec.Pa` = -1：旧表 < v50 / 缺键）⇒ 判不出弃哪一侧，本行不结算");
        return 0;
    }
    var op = SyntheticRowOp(inst.Card, "discardwholehand", row.Lg);   // 形状同现函数（Verb/Source/A/I/L）
    var unresolved = new List<string>();
    bool ok = DoDiscardWholeHand(ctx, owner, inst.Card.Name ?? "?", op, chosen: null, unresolved);
    if (unresolved.Count > 0)
        ctx.Log($"「{inst.Card.Name}」的手牌 `chosenAbility 165`：{string.Join("；", unresolved)}");
    ctx.Log($"{who}：「{inst.Card.Name}」的手牌 `ca 165`（discardWholeHand）⇒ "
          + (ok ? "整手牌已按 `playersAffected` 处理" : "**没有弃成**（见上一条日志）")
          + "（原版 `AbilityLogic__PlayAbility.c:293-345`）");
    return ok ? 1 : 0;
}
```

### 2.2 `DoDiscardWholeHand` 传 `chosen: null` 的依据（现读）

`EffectResolverPartial_B88E2.cs:723`：
```csharp
static bool DoDiscardWholeHand(BattleContext ctx, int owner, string by, EffectOp op,
                               UnitState chosen, List<string> unresolved)
```
函数体（`:725-760`）**一次都没读 `chosen`**（现读逐行确认；同族 `DoDiscardFromHand` `:700` 也一样）。
它只读 `op`（`Verb` / `Source` / `LogicIndex`）+ `ctx.Players[*].Hand` + `PlayersAffectedOf(ctx, op, by)`。
⇒ 手牌上下文传 `null` 与棋盘上下文传 `chosen` **语义等价**。

⚠️ **但有一条现读缺口要一起记账**：`PlayersAffectedOf`（`:837`）读的是
`ctx.ActingUnit != null ? ctx.ActingUnit.Card : ctx.PlayingCard` 的
`ActiveAbilityLogicGroup(CardDef.ActiveAbilityObject)` —— 那是 **`activeAbility` 那一组**，
而 `ca 165` 落在 **`cardAbilities`** 行上。⇒ 棋盘侧现在这条 `RunDiscardWholeHandRow` 对 `cardAbilities` 行
同样会读成 `-1`。**本施工单的执行器绕开它、直接用 `row.Pa`**（所以两者不会打架）；
若将来要把 `PlayersAffectedOf` 也修好，那是另一条账（同一份 `pa` 数据列可以复用）。
