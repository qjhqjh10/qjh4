## §一 读数口设计与取舍

### 1·1 选 **(A) 纯 dotnet 路**，没选 (B) Unity 路

| 取舍 | 理由 |
|---|---|
| **A（`工具/ruleprobe/` 加子命令）** ✅ | ① `RuleEngine/Core/TutorialScript.cs` **本来就在** `ruleprobe.csproj` 的 `Core/*.cs` 编译集里 —— 一行都不用加编译项；② 关卡数据是离线文件，探针自己读 + `TutorialData.Install(...)`（产品同一个装载口）；③ 重编 ~1.5 秒、**不占 Unity 实例**（`_run_8_checks.sh` 那条全局串行锁对它无效）；④ 判据侧可以写成「反编译方法体的逐句转写」，期望值**不来自我们的实现**（灭自证）。 |
| **B（`RuleEngine/Editor/` 新建自检宿主）** ❌ | 那要调度台跑一次 Unity（1–9 分钟、且同工程只能一个实例）；**而且本轮一半的落点根本不在 Unity 侧**（`TutorialScript` / `TutorialRules` 全在 Core），用 B 是花钱买不需要的东西。 |

### 1·2 「两侧数值」是怎么保证不是自证的

- **原版侧** = 把反编译方法体**逐句转写**成 C#（每块都在输出里写了 `文件:行号`，如
  `decomp_full/AiScripted__HasActionData.c:11-16`、`cpp2il/out_cpp2il_dev_ilspy/AiScripted.cs:467-489`）；
- **我们侧** = **调用产品代码**：公开 API 直接调（`TutorialRules.ShouldShuffleDeck` ·
  `TutorialScript.Matches` · `PlayScriptedTurn` · `FinishedScriptedActionsInTurn`），
  **私有谓词走反射**（`TutorialScript.First`）—— ⛔ 没有为了读数而改产品源码，也没有把我们的实现抄一份当期望值；
- **样本** = 真实 6 关数据（79 回合 / **回合内 430 条动作**），外加**刻意构造的边界夹具**
  （`data=null` / `data=[]` / `data=[null]` / 计数器越界 / 域外 unitType…）。

### 1·3 用了哪个「局」

`RuleCore.NewBattle(a, b, tutorial: new TutorialScript(stage))` —— 教程分支的**唯一**落点
（不洗牌 / 先手照关卡 / 不换牌 / 起手与起始单位走 `TutorialRules`）；关卡牌从
`Resources/tutorial_decks.json` 按 id 精确查（认不出就出声丢掉，⛔ 不拿别的卡顶）。

🔴 **走带必须按回合调 `RuleCore.BeginTurn`**（它自带教程 `dontDrawCard` 闸）：
第一版是「纯脚本走带」，结果 `PlayCard` **全线 `Unresolved`** —— 因为手牌永远不补。
**那是量具的错，不是引擎的错**，已修，并把这条写进文档的「已知边界」。
