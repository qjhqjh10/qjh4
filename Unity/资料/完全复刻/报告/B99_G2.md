## 二、🔴 对施工判据 §2·3 **F 行**的一处有意偏离（请调度台核）

§2·3 F 行建议把 `BaseClaimed(i)` 改成 **`_base[i] || _prem[i]`**（注为「= 原版的 `State==20||30`」）。
**那个等式只在非可重复节点上成立。** 原版 `CampaignWindowTab__OnNodeClicked.c:30-60` 是：

```
BaseCollected    (ctx+0x28) = (State == 20 || State == 30)
PremiumCollected (ctx+0x29) = (State == 30)
```

而**可重复节点**领过之后 `State = 40`（§2·1 的 `LAB_1806b9a30`）⇒ 原版这时 **`BaseCollected = false`**，正是靠这一点，奖励窗才**重新**亮出「可领」的钮。
若照 `_base || _prem` 写，`UM47` 领过一次后 `BaseCollected = true` ⇒ `CampaignRewardWindow` 的 `claimedState`（`CampaignRewardWindow.cs:763`）翻真 ⇒
`clickable = !premiumLocked && !claimedState && …`（`:858`）**恒假** ⇒ **UI 上再也点不了**，`Claim` 里放开的「无限重复领」等于白做。

⇒ 本件按**机器码口径**落地（铁律：判据与 `.c` 冲突时以 `.c` 为准）：
```csharp
public static bool BaseClaimed(int i) { … int s = StateOf(i); return s == BaseCollected || s == AllCollected; }
public static bool PremiumClaimed(int i) { … return StateOf(i) == AllCollected; }
```
对**非可重复节点**它与 `_base || _prem` / `_prem` **逐格等价**（`State=20 ⇔ _base`、`State=30 ⇔ _base&&_prem`）；差别**只**出现在可重复节点上，而那正是本件的目标。断言 **B3/B4** 钉住「`BaseClaimed` 由 State 派生」。
