## §8 口径与覆盖边界

- **裁定单位 = 根对象**（一个 prefab 根一行），子件跟着根走；**不按 2,483 行逐条判**（R7 §7.3：根可以停在可复用的中间 prefab）。
- **`代码构造等价` 的判据** = 我们的代码里**真的建出**了同一件东西（`MenuDraw.Node/Rect/Text/Hit(..., "<原版节点名>")` 或同一套模板），⛔ 不是「类名像」。名字不同但结构同（如 `Campaign Profile Container Variant` ↔ `Campaign Profile Container`）**在证据列里注明**。
- **`真缺` 的判据** = 原版确实用 + 我们功能已建 + **资产没导或线没接**；三条都写清（原版哪个功能 / 我们的落点 / 缺资产还是缺接线）。
- 本表**只读产出**：没有改源码、没有导资产、没有改账主表、没有跑 Unity。

**覆盖边界（与方案 §2.4 一致）**：本表只回答「这些**资源**要不要、缺在哪」；**「读过」≠「复刻过」** —— 判 `代码构造等价` 不等于那扇窗的每一颗子件都对（例如抽屉内部、Timer 行、活动卡的领取态都已单列）。
