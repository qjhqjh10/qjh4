### 实得 vs 期望
`win.CurrentState` 期望 `Open`，实得 **不是 `Open`**（日志只印 `[False]`、不印实际状态 —— 见「还缺什么」）。

### 日志证据（shop.log 现读）
- 同一句共出现 10 次：`80041 / 81384 / 82439 / 82961`（绿）· **`86381`（红）** · `91268 / 92111 / 110189`（绿）· `133350`（失败重列）。
- `（编排）买完弹出的开包窗先关掉，把商店重新开起来` **只出现 3 次**：`79867 / 81210 / 82265`。
  ⇒ **从 `82961` 那一次起 `bp` 恒 null**。
- 为什么恒 null：`82961` 那次走的是「`win.CurrentState == Closed` ⇒ `win.Manager.OpenWindow(win)`」这半边，而那会 **`Open()` → `Build()` → `BuildPages()`**（`Shell/ShopWindow.cs:150-168` / `:249-261`）**重建出一批新的 `ShopTabPage`** ⇒ 页上的 `LastBoosterPack` 跟着归零。之后任何一次调用都关不掉开包窗。
- 失败那一刻的窗口栈：`:85811` 附近
  `[Win] Booster Pack Open Window：`TryOpen` 命中 **`Background`** 支 —— 只提回前台，不重建内容`
  —— 来自 `CheckAbsorbRule` 点面板外关掉 `popA` 后 `ShowPreviousWindow()` 把**开包窗**带回 `Open`（`WindowsManager.cs:664-700`）。⇒ **开包窗压在商店上面、商店停在 `Background`**。
- ⇒ 那一刻同时成立：`bp == null`（关不掉上面那扇）+ `win.CurrentState == Background`（≠ `Closed` ⇒ 不重开）⇒ 红。

### 定性
**α（自检编排写法不完整）+ δ（前提未覆盖 `Background` 档）**。
⚠️ **不是产品缺陷** —— `ShowPreviousWindow` 把列表尾那扇开回 `Open`、其余留在 `Background`，是照 `WindowsManager__ShowPreviousWindow.c` 逐句抄的（`WindowsManager.cs:664-700` 的注释有完整对位）。

### 修法（方案，未动手）
```csharp
static void ClosePackAndReopenShop(ShopWindow win)
{
    // ① 从管理器**现取**：⛔ 别读页上的 `LastBoosterPack` —— 页会被 `BuildPages()` 重建，那个字段跟着归零
    var mgr = win.Manager;
    if (mgr != null)
    {
        var pop = mgr.GetOpenWindow<BoosterInfoPopup>();      if (pop != null) pop.Close();
        var bp  = mgr.GetOpenWindow<BoosterPackOpenWindow>(); if (bp  != null) bp.Close();
    }
    // ② 三档都收：Background ⇒ 无参 `TryOpen()`（= 原版那一跳，只回前台不重建）；Closed ⇒ `OpenWindow`
    if (win.CurrentState == WindowState.Background) win.TryOpen();
    else if (win.CurrentState == WindowState.Closed && mgr != null) mgr.OpenWindow(win);
    CheckTrue(win.CurrentState == WindowState.Open, "（前提）商店重开之后真的开着 —— 下面几段都靠它");

```

### 还缺什么
`CheckTrue` 只印 `[False]`、**不印实得状态** ⇒ 没法从日志区分 `Background` / `Closed`。
建议文案改成 `$"…（实得 {win.CurrentState}）"`。
