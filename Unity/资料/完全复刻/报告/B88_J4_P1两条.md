## 二、`LiveOpsPopupPresenter.Open` 装配

### 原版触发链（8 步，逐条出处见判据文件 §3.1）
`服务器载荷 → Manager.BuildHandler → SetupEvents` →（`:170-171`）`ScheduleEventPopups`
→ 触发支（`ShowWindowOnTrigger(+0x28) && !WasSeen && !已排`）取 `TriggerPopupOptions(+0x30)` /
过期支（`EventState == Finished(3)`）取 `ExpirePopupOptions(+0x40)` → `QueueEventPopup`
→ `MenuActions.QueueActionWithCallback` → `CheckActiveMenus`/`Routine`/`TryTriggerAction` 四道闸
→ **`ShowTriggerEventPopup`（`…__ShowTriggerEventPopup__1019560.c:39-47`）**：
`GetComponentReference(ev, options.PopupLabel)` → `WindowsManager.OpenWindow(...)` → `MarkOnScreenClose` 挂 `MarkAsSeen` → **立刻** `onComplete`
（过期那支：`…__ExpireEvent__1017c80.c:65-70`，关窗时 `ev.Expire(null)`）。

### 入参
`ev` = handler 的事件实例；`options` = `drawData.TriggerPopupOptions / ExpirePopupOptions`，
13 份 SO 实测 **`PopupLabel = 20`（触发）/ `21`（过期）**，其余三格逐份相同。
`label` 是 **key 不是 prefab id** ⇒ 必须回到**事件自己的 `EventComponents`** 查。

### 🔴 旧结论被推翻：GUID → prefab 名本地**可解**
`bundle_menus_assets_all/AssetBundle/AssetBundle_1.json` 的 **`m_Container`** 直接给 GUID→`m_PathID`，
再反查 `GameObject/*.json` 得根名：
`e4c251… = Base Event Popup` · `44c1eb… = Full Screen Event Announcement Variant` ·
`be526b… = Base Expiration Popup` · `2d7ec1… = Event Help Popup Variant`。
⇒ 「只解到 GUID、没解到 prefab 名」那句话（4 处）应按铁律 5 就地改。
逐份实测：触发弹窗只服务 5 份 Parent（4 份用 FullScreen，`Dark Zealots` 那份 `enabled=0`）；
过期弹窗只服务 4 份 Scoring。

### 我们缺 **两处**（不是一处）
- **A `LiveOpsPopupPresenter.Open` 生产 0 赋值** ⇒ 两分支都「出声不出窗」（`LiveOpsHandler.cs:387-392 / 440-445`）。
- **B `LiveOpsLocalHandler.LoadFromCatalog`（`LiveOpsHandler.cs:897`）0 调用者** ⇒ `events` 空 ⇒
  `ScheduleEventPopups` 排 0 条 ⇒ 连 `ContainsKey` 都进不去。**只补 A 补不出窗。**
- 建议落点（都在 `Shell/LiveOpsHandler.cs` **类尾**，同形先例 `LiveOpsPump.Install:1044` / `SettingsWindow.cs:6413`）：
  `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]` 装 resolver + `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` 调 `LoadFromCatalog`。
  resolver 的完整伪代码在判据文件 §3.5（含 GUID 表、按 variant 取 0/1 或 10/11 tag、
  `WindowsManager.Get()` 而非 `Instance`、找不到 label 时照原版 `LogWarning + null`）。

### 还差（一条要裁定）
1. 🔴 **口径冲突**：`ScheduleEventPopups` 的触发支**不看日期**，而我们把 13 份（含过期）全装进 `events`
   ⇒ 接上 B 之后**首次启动会排 5 条触发弹窗**（含 `enabled=0` 的 Dark Zealots）。
   原版看不到这一幕是因为服务端只下发在期事件。**与用户边界「过期活动不做」冲突，J4 无权定，请调度台裁定。**
2. 过期弹窗今天验不出（4 份 Scoring 的 `expireDate` 都早于今天 ⇒ `EventState = Expired(4)`，只排 `Finished(3)`）⇒
   要验得把 `LiveOpsClock.NowProvider` 钉到 `endDate ~ expireDate` 之间。
3. 原版是 Addressables 异步加载 prefab，我们同步建窗 = **等价简化**（按铁律 18 打 `🔶 自己设计`）。
