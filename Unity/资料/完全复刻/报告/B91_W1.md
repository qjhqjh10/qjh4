### §五·① L722 做了什么（`W4` 已先提供 `UnitState.RemoveTempBuff`，本笔接第 ② 步）

- 新增 `public static int EnqueueEndOfTurnEffectRemovals(BattleContext ctx, int seat)`（类尾 `:16454`）：
  扫**两侧棋盘每张卡**的 `TempBuffs`，取 `!b.UntilMyNextTurn && !b.UntilOpponentNextTurn`
  （= `UnitState.cs:1700` 的 `due` 同式 = 「本回合结束撤」那一档），**每条各**入队一条
  `EnqueueAbility(ctx, ActionPriority.DelayedInstant, "removeEffect:"+b.Name, () => unit.RemoveTempBuff(buff))`
  —— lane `DelayedInstant`(3) = 原版 `SendRemoveEffect(card, effect, **3**)` 的 priority（`CardScript__SendRemoveEffect.c`
  里它就是 `AddAutoActionToQueue(action /*type 0x10*/, priority)`）。闭包逐条捕获局部量（⛔ 不让它捕获循环变量）。
- **接线**：`EndTurn` 里那条「回合末到期:限时增益」入队动作（`:2348-2355`）的**动作体**改成调它
  ⇒ 外层（每卡一跳的等价物）与内层（每条 effect）**两层都在 DelayedInstant**，与原版两层同形。
  ⛔ 动作体里**不再**调 `RevertBuffs(true, …)`。
- **有没有「撤两遍」的风险 —— 三条判据**：
  1. **生产路径已无第二条整批撤**：`grep "RevertBuffs(true" Assets/**/*.cs` 现读只剩
     `CardPresentation/Editor/BattleScene.cs:9852`（**自检探针断言**），`RuleCore`/`EffectResolver` 一处都没有；
  2. **`RemoveTempBuff` 自带幂等闸**：`_buffs.LastIndexOf(b) < 0 ⇒ return false` ⇒ 同一条 buff 被入队两次
     （或 `EndTurn` 被同一局连跑两次，如回放展开）也只会**真撤一次**；
  3. **枚举时机**：枚举放在那条入队动作**体内**（不是 `EndTurn` 体内）—— 与「原版动作 61 出队时才扫」同形，
     所以回合末 **Instant** 那一批触发（它们排在 DelayedInstant 之前）新挂的「本回合」增益**同样被扫到**。
- ⚠️ **可观察影响（如实记）**：
  - 撤除**次序**从「每张卡内**逆序**」变成「**正序**」= 原版 `activeEffects` 列表序（这是本笔的收益）；
  - 撤除**时刻**从「那一条 DelayedInstant 动作执行中」后移一个小节（那些逐条动作在同一轮泵里紧随其后）⇒
    只有「同批还排着别的 DelayedInstant 动作」这种边缘局面才可能不同；
  - 🔴 **一行日志文案变了**（只有真有「本回合」增益到期时才打）：
    `（N 条「本回合」增益到期）` → `（回合末：N 条「本回合」增益到期 ⇒ 入队 M 条逐条摘除动作 —— …）`。
    因为 `ctx.Log` 会进 `ctx.Events`（`BattleContext.cs:1855-1859`）⇒ **对局指纹会变**（行数不变、仍是 1 行）；
    `play all dump` 逐字节对比会出现这一处差异，**是预期的**。
