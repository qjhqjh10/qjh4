# B118-W16 · 卡牌总索引工具（`工具/gen_card_dossier.py`）

## 1 · 用法三条（命令 + 预期输出）

```
python -I -X utf8 d:/4/Unity/工具/gen_card_dossier.py --card ASH83     # 单卡全貌（9 区，人读）
python -I -X utf8 d:/4/Unity/工具/gen_card_dossier.py --all --dry      # 全池读数 + 三态分布，零写盘
python -I -X utf8 d:/4/Unity/工具/gen_card_dossier.py --all --check    # 与盘上 TSV 逐字节比（一致 rc=0 / 不一致 rc=1）
python -I -X utf8 d:/4/Unity/工具/gen_card_dossier.py --all --write    # 写 判据/卡牌总索引.tsv（唯一写盘档）
python -I -X utf8 d:/4/Unity/工具/gen_card_dossier.py --json --out X.json   # 机器可读导出（--json 单独用 = 打到 stdout）
```
- `--card` 也吃**英文卡名**（精确、忽略大小写），如 `--card "Aerial Dominion"` → `ASH46`。
- ⛔ **裸跑 = 打印用法 + `rc=2` + 零写盘**；不认识的参数同样 `rc=2`；卡 id 不存在 → `rc=1` 并说明现池张数。
- 实测耗时 **≈1.3 秒/次**（含 45 MB 判据目录扫一遍）；`--check` 当前 **rc=0（逐字节相同）**，可放心重跑。

## 2 · 列定义（每列 → 数据源 文件:字段）

| 列 | 数据源 |
|---|---|
| `id` `name` `faction` `subtype` `cardType` `rarity` `cost` `melee` `ranged` `armour` `health` `keywords` | `RuleEngine/Resources/cards_engine.json:cards[]` 的 `id/name/faction/subtype/type/rarity/cost/attack/ranged/armour/health/keywords`（`cardTraits` 并入 keywords） |
| `nameZh` | 同上 `nameZh`（空 → `查不到:` + 现池张数） |
| `traits` | `cards_truth.json:cards[].cardTraits[]` 的 `name` + `_trait`（**id 必须带**，mod 侧要看数字） |
| `desc` `descZh` | `cards_engine.json` 的 `desc/descZh`（`descZh` 空时退 `desc`；两者都空 → `无:` + 原因） |
| `abilities` | `cards_truth.json:cards[].abilities/activeAbility/alternativeAbility` → `trigger`(AbilityTrigger) / `chosenAbility`(AbilityEffect) / `targetCriteria.targetsAffected`(TargetsAffected) / `playersAffected` / `buff`(BuffType) / `damage` / `heal` / `summon` / `manaBuff` / `handBuff` / `furtherMultiplier` / `chanceOfHappening` |
| `vfx` | 声明 = `CardPresentation/Resources/card_vfx_by_card.json:cards[id].events[].ev/es[].n`；判定 = **原样复用** `判据/全池事件覆盖_静态.tsv`（维=特效，连 `(事件, 资源名)`）的 `在工程/在消费表/参数判定/参数出处` |
| `anim` | 声明 = `cards_engine.json:cards[].animTimes[]`（`a`=CardAnim `n`=prefab `tg/tn`=触发）；clip 存在性 = `cardanim_clips.json:rows[].a`；判定 = 覆盖表（维=动画，连 `(tn, n or a)`） |
| `voice` | `CardPresentation/Resources/voice_lines.json:cards[id].lines[]`（`ev/file/src/so`）+ 文件是否存在（`Resources/Art/audio/vo`）；空则退 `card_vfx_by_card.json:cards[id].audio[]`；判定 = 覆盖表（维=语音） |
| `code_entry` | **现读行号**（符号锚见脚本 `CODE_ENTRIES`）：`CardDef` · `CardDef.AddTriggerOp` · `EffectText` · `EffectText.Parse` · `EffectResolver.EffectDispatch` · `VfxMap.ByCard` · `CardAnimClips` · `UnitTweenTable` · `VoiceLines` |
| `code_special` | 扫 `RuleEngine/{Core,Data}` 的 116 个 `.cs`，按「引号字面量恰好等于该 id」匹配 → `文件:行号` + 该行原文 |
| `criteria_docs` | 扫 `判据/` 764 个 `.md/.tsv/.txt`，按 id 字面量精确匹配（唯一条目 = 该文件）；**全池表已单列**（见列头 `#` 行） |
| `verify` | `判据/全卡核验_判定.tsv` 的四列（引擎/特效/动画/语音判定） |
| `gaps` | 本行所有「查不到 / 无」的原因汇合（无问题写 `无`） |

- **三态写法（全表统一）**：`有(值+出处)` / `无(否定证据)` / `查不到:<搜过什么>`；实测**全表 0 个空单元格**。
- 原版枚举**不抄表**，每次从 `D:/2/Warpforge_code/Scripts/Assembly-CSharp/{AbilityTrigger,TargetsAffected,PlayersAffected,BuffType,AbilityEffect}.cs` 现读（本次 5/5 读到、0 缺失）；读不到会退化成裸数字并在行内标注。
- TSV 为 **UTF-8 无 BOM + LF**，`#` 开头的 9 行是元信息（生成方式 / 数据源版本 / 复跑命令 / 两张「批量表」名单），跳过 `#` 后第一行是列名行。

## 5 · mod 用法示例

```python
import io
def load(path="D:/4/Unity/资料/完全复刻/判据/卡牌总索引.tsv"):
    lines = [l for l in io.open(path, encoding="utf-8").read().split("\n") if l and not l.startswith("#")]
    hdr = lines[0].split("\t")
    return hdr, [dict(zip(hdr, l.split("\t"))) for l in lines[1:]]

hdr, cards = load()
by_id = {c["id"]: c for c in cards}
c = by_id["ASH83"]; print(c["abilities"], c["code_entry"])
# 按列筛：所有「有专项特判」的单位
sp = [c for c in cards if c["cardType"] == "unit" and not c["code_special"].startswith("无")]
# 三态判断：一律看前缀，⛔ 别判空串
no_vfx = [c for c in cards if c["vfx"].startswith("查不到")]
```
- JSON 档（`--json --out`）是 `{sources, columns, count, cards:[{…25 列同名键…}]}`，`cards` 可直接按 id 建索引。
- 想在工具链外复查：`code_entry` 里是 `符号=文件:行号`，行号**每次现读**，源码改动后重跑即复位。

## 6 · 没覆盖到的 / 顺手发现

1. **特效「查不到」29 张**：`card_vfx_by_card.json` 只覆盖 1,100/1,129。本工具**不补**（去补 = 另造一套口径），列里写明搜过哪张表、覆盖多少张。
2. **`Reconnaissance Mission`（`e8cf1eb5…`）** 三处特殊：无 `nameZh`、不在 `全卡核验_判定.tsv`（骨架 1,128 张的差那 1 张）、是 `LegacyCardIds` 之外的 enchantment。本工具按 1129 为准如实标 `查不到`，⛔ 没扩表。
3. **`full_raw` 双份技能树**：本工具完全不读 `cards_raw.json`（递归扫会翻倍），口径已写进脚本头与 TSV 头。
4. **顺手发现（未修，⛔ 不在本代理白名单）**：`cards_engine.json` 里有 **233 张卡**的 `descZh` 带着**未展开的 `((Key,arg))` 占位**（例 `ASH46` = `((Deal_x_damage_to_a_random_enemy,3))。每有一个友方载具…`；`ASH15` = `((Stun_an_enemy))`），英文 `desc` 一个都没有 ⇒ 中文卡面会把这串原样印出来。建议另派写手查（起点：`工具/gen_cards_engine.py` 的 `descZh` 来源 + 官方本地化表的占位符语法）。
5. **代码特判只扫 `RuleEngine/{Core,Data}`**（116 个 `.cs`）：`CardPresentation/**` 与 `Editor/**` 里的 id 引用（多半是自检夹具）**没进** `code_special`。要扩就改 `SRC_DIRS`，并同步报告。
6. **`LegacyCardIds.cs`（1,103 张 id 的历史别名表）被整表排除**（阈值 100 个不同 id = 批量表），名单写在 TSV 头部 `#` 行与单卡输出的「整表排除」行 —— 不是「没有」，是「不当特判」。
