## 三 🔴 `:1121` —— **不接线**，反证：引擎半 `BoardSlots.NextSlotPos` 的循环上界用错了对象

### 3·1 缺陷
`RuleEngine/Core/BoardSlots.cs:726 NextSlotPos`（`B95_RBW` 落地，今天 0 调用方）的扫描循环用
`if (Math.Max(r, l) <= i) break;`（`r/l` = **两侧人数**）。而原版 `.c:45-62` 的上界是
`max(len(leftSlotPosNormal|Weapon), len(rightSlotPos…))` = **每侧格位数**（= 4）。
把人数当格数 ⇒ **提前 break**，直接掉进「一个都找不到」那一支。

**可复现的错**（连续无洞棋盘，`BoardSpec.SlotsPerSide = 4`）：

| 局面 | `required` | 原版应回 | 现在回 |
|---|---:|---|---|
| 右 2 / 左 2 | 2 | 左第 3 格（signed `-3`） | **LogError + 右最外（`+4`）** |
| 右 0 / 左 0（空场） | 2 | 左内格（`-1`） | **LogError + `+4`** |
| 右 0 / 左 0（空场） | 3 | 右第 2 格（`+2`） | 只枚举 i=0 ⇒ 回 `-1`（错） |

⇒ 接线 = **换回错值 + 每次动画 LogError**（红线「不许静默失败」也挡不住错误值）。这不是「需要真机才能定」的问题，是**判据级错误**。

### 3·2 实据（三重，互相独立）
1. **字段偏移**：`d:/2/Warpforge_code/Scripts/Assembly-CSharp/MinionManager.cs` 的字段序 +
   两个已知落点反推基址 `B = 0x20`（`isWeaponSetup` → `+0x40` = `.c` 里那个 bool；`ExtraYOnBoard` → `+0x94` = `.c:243` 读的那个 float）⇒
   `+0x20/+0x28/+0x30/+0x38` = `leftSlotPosNormal / rightSlotPosNormal / leftSlotPosWeapon / rightSlotPosWeapon`。
2. **`GetRightSlotPos` 的形状**：`MinionManager__GetRightSlotPos.c:19-33` 对同一格 `+0x28` 取
   `*(int*)(x + 0x18)` 当**数组长度**、元素从 `x + 0x20 + i*8` 读（Vector2 步长 8）⇒ 它是 `Vector2[]`，**不是 `List<CardScript>`**。

### 3·3 给 `B97_W4` 的施工单（`BoardSlots.cs` 是它的文件）

2. 补 `.c:178-276` 的 `required == 1` **`pos.x == 0` 中性支**（我们动画时刻**没有点击点** ⇒ 只能走中性支）：
   右满 ⇒ `GetLeftSlotPos(leftCount)`；否则左满 ⇒ `GetRightSlotPos(rightCount)`；否则 ⇒ **人少那一侧**的第 N 格；
