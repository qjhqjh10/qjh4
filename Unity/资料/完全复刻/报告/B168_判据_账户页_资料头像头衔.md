## 二、必查项：页签按钮的点击绑定到底在哪，为什么没绑上

### 2.1 绑定写在 `TabButtons.Initialize`，逐条 `onValueChanged.AddListener`

`E:/warpforge/03_反编译/cpp2il/out_cpp2il_dev_ilspy/TabButtons.cs:83-267`

```csharp
public void Initialize(GameWindowWithTabs window)   // :83
{
    if (tabButtonPrefab != null) tabButtonPrefab.gameObject.SetActive(false);   // :117-121（prefab 里是 null）
    window.OnTabChanged += UpdateTab;                                           // :124-126
    foreach (TabButton option in options) {
        option.toggle.group = group;                                            // :187（group 序列化 = null）
        option.toggle.onValueChanged.RemoveListener(...);                       // :217
        option.toggle.onValueChanged.AddListener(state => Toggle(state, option.tab)); // :238-244
    }
}
```

`Toggle`（`:269-282`）是真正切页签的那一层：

```csharp
private void Toggle(bool state, WindowTabBase tab) {
    if (!firstTime) { if (state && tab) window.ChangeTab(tab); }
    else firstTime = false;     // 构造里 firstTime = true（:501），只吃掉第一次事件
}
```

`UpdateTab`（`:284-312`）把每个 toggle 的 `isOn` 收敛成「只有 == 当前页签的那颗为 true」。

### 2.2 `Initialize` 只有一个调用点：`GameWindowWithTabs.SetupTabs`

`GameWindowWithTabs.cs:85-159`，其中 `:116` 是唯一一处 `components.tabButtons.Initialize(this)`。
`SetupTabs` 只被 `Open()` 调用，且**有一次性闸**：

```csharp
public override void Open() {            // :161
    if (!initialized) { SetupTabs(); initialized = true; }   // :163-167
    base.Open();                                              // :168
    if (tabs.Count > 0) {
        if (CurrentTab == null) { CurrentTab = GetStartingTab(); ... }   // :174-183
        CurrentTab.TryOpenTab();                                         // :184
    }
}
```

`ChangeTab`（`:308`）→ `ChangeTabCO`（`:363-388`）= `from.CloseTab()` → `to.TryOpenTab()` → `OnTabChanged`（→ `UpdateTab`）。
`WindowTabBase.TryOpenTab`（`WindowTabBase.cs:74-84`）= `SetActive(true)` + `OnOpen()`；`CloseTab`（`:90-95`）= `SetActive(false)` + `OnClose()`。
`ForceCloseTabs`（`GameWindowWithTabs.cs:403-428`）把 `tabs` 里所有页签 `SetActive(false)` —— **这是 SetupTabs 的最后一步**，也是「Title Tab 不再压在别人身上」的唯一机制。

### 2.3 结论：三个环节任一断了都会表现成「点击只换高亮」

| 链节 | 断了会怎样 | 现读证据 |
|---|---|---|
| ① `SetupTabs()` 没跑 | 没有任何 `onValueChanged` 监听 ⇒ 点击只改 `Toggle.isOn`（= 视觉高亮），**不进 ChangeTab** | `PlayerProfileMenu.Open` 先 `new LocalPlayerInfo()` 再 `base.Open()`（`PlayerProfileMenu.cs:154-224`，`base.Open()` 在 `:214/:222`）；ctor 在 `LocalPlayerInfo.cs:58` 就 `.PlayerTitle.GetID()`，而 `PlayerDataManager.PlayerTitle` 在 `demoData == null` 时是 **throw NRE**（`PlayerDataManager.cs:7123-7185` 末尾 `return (CosmeticItemTitle)(object)new NullReferenceException();` = ILSpy 对 `throw` 的译法）⇒ **基类 Open 根本没被调过** |
| ② `initialized` 已被设 true 但 SetupTabs 当初失败过 | 之后每次 Open 都跳过 SetupTabs，**永不自愈** | `initialized = true` 紧跟在 `SetupTabs()` 之后（`:165-166`），所以只有「SetupTabs 抛异常」才可能留下这种半状态；**当前 profilefix 日志里没有 `SETUPTABS-EXC` 行** ⇒ 这一支未被观测到 |
| ③ `options[i].tab` 为 null | `Toggle(state, null)` 什么都不做 | prefab 里 6 条都填了 `tab`，**这一支可以排除** |

**⇒ 施工单（P0，可直接照做）**：让 `PlayerProfileMenu.Open` 能走完 `base.Open()`（或由 mod 在异常路径上**按原版顺序**补跑 `SetupTabs()` → `OpenTabs()`）。
这不是「新行为」：`SetupTabs` 里除了建监听，还有 `ForceCloseTabs()`（关掉 Title Tab）。**光把 Title Tab 手动 `SetActive(false)` 不等于修好** —— 监听还是没有，点击仍不切页。

### 2.4 关于「`profilefix.tsv` 里没有 `TAB-TOGGLE`」这条证据的强度（⛔ 别过度解读）

现读 `E:/warpforge/07_产物/phase0/profilefix.tsv`：**只有 17 行，时间 15:21:54–15:22:20**，内容是 6 次 `WIN-CENSUS` + 10 次 `TICK`。
其中 `WIN-CENSUS` 命中数一直 `hits=1`，命中的是 **`PlayerProfileUIController/Player Profile`（顶栏那块）**，不是档案窗。

⇒ **这份日志里根本没有「打开档案窗」的那一段**，所以「没有 `TAB-TOGGLE`」在这份文件上**不构成「点击没进 Toggle」的证据**。要收口，必须重跑一次并拿到：
`PROFILE-OPEN-IN` / `PROFILE-OPEN-OUT`（或 `PROFILE-OPEN-EXC`）· `TABS-AFTER-OPEN` · `TABBUTTONS-INIT` · 点击后的 `TAB-TOGGLE state=… tab=…` · `CHANGE-TAB to=…`。

补一条 mod 侧的坑（会影响下一次取证的可信度）：`ProbeUtil.FindMethod` 用的是
`Public | NonPublic | Instance | Static | **DeclaredOnly**`（`E:/warpforge/05_工具/mod/WfOfflineProbe/ProbeUtil.cs:92-101`）。
`TabButtons.Toggle` 是 **private**（`TabButtons.cs:269`）⇒ 能补到；
但 `GameWindowWithTabs.Open` 是 `override`、`SetupTabs` 是 `protected virtual`，二者都 `DeclaredOnly` 命中（都在本类里声明）——**目前看没问题**。
⚠️ 真正要留意的是：`PlayerProfileMenu.Open` 是 override，`FindMethod(ppmType,"Open",0,false)` 用 `DeclaredOnly` 也能命中（override 会在派生类重新声明）。这一条已复核。
