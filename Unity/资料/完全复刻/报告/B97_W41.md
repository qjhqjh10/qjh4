## 一 结论（三句）

1. **`SetAutoFitBox` 那个「量纲对不上」的障碍【不存在】** —— W8 记的「该口吃墨高 px、与 TMP 的 `fontSize` 不同量纲 ⇒ 接不上」
   是**误读**：该口内部就是按 `NominalPx()`（= `FontSizeToPxNow(TmpFontSize())`）把 px 折回 `fontSize` 单位的。
   真正的差只有**一个随字面走的系数**：uGUI 档「1 个 fontSize = 多少画布 px」= `EmPerFontSize(face) × 10`
   ⇒ **CJK 0.948 / 拉丁 1.0**（判据 → `Label.cs:1430-1445` 的 `NominalPx()` 与 `Label.cs:1293` 那段的 doc）。
   ⇒ 传原版 18/40/36 之前**乘这个系数**即可，落回去就是原版那三个 `fontSize`。
2. **`Quantity` 的三档已接上**：`AutoSizing == true` · `FontSizeMin/Max/Base == 18 / 40 / 36`（**= 原版字段原值**）。
3. **图标内版式有真值，⛔ 不再是 🔶 0.7**：原版 `Icon *Drawer*.prefab` **14 份逐份现读** —— 主图节点
   **锚 (0,0)-(1,1) · `sd (0,0)` · `m_PreserveAspect = 1`**，而抽屉根被 `Instantiate(prefab, parent, **false**)`
   实例化到 `DrawerHolder`（65×50）⇒ 根撑满 65×50、主图再拉满并内接 ⇒ **方形图 = 50×50**。
   已把 `RewardIconFill` 从 **0.7 → 1.0** 并补 `Image.preserveAspect = true`（`🔶 自己设计` 注释随之删掉）。

账状态**仍 B**（不是 A）：残差换成三条更细的（见 §六），其中最实的一条 = 原版 `SetReward` 对抽屉对象

**换算算式（写进 `FillRewardRow` 的注释里）**

```
pxPerFontSize = label.FontSizeToPxNow(1f, label.ActualFace)    // uGUI：EmPerFontSize(face) × 10
                                                              //   CJK 0.0948×10 = 0.948 · 拉丁 0.1×10 = 1.0
SetAutoFitBox(boxW=70, boxH=45, 18*pxPerFontSize, 40*pxPerFontSize, 36*pxPerFontSize)
```

为什么这样一定落回原值：`SetAutoFitBox` 里 `_tmp.fontSizeMax = cur × (maxPx / NominalPx())`，

（`cur` 在式子里**约掉了** ⇒ 与标签建时的 `scale`、`_glyphHeight` 无关，这一点也写进了断言。）
