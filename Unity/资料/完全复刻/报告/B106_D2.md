### 1.2 R1（A1–A5）：断言取错了「第 1 格」

**实测链条**（全部可从日志/源码复算，不需要跑）：

1. `fcontent.GetChild(0)` **不是** `ForgeCell_0` —— `BuildCell(i)`（`Shell/ForgeTab.cs:994`）里有 `if (_trackScroll != null && !_trackScroll.Intersects(r)) return;`（`:997`），**视口外的格根本不建**，所以子件序 = 「第一个建出来的格」。
2. 该页开页时 `ForgeTab` 会 `FocusClaimable()` 把轨道吸附到**可领那一格**（日志 `rewards.log:18115` 实测：`锻造轨道：偏移 1603.3px · 实建格 [1,2,3,4,5,]`）⇒ `GetChild(0) = ForgeCell_1`，而 `ForgeCell_0` **压根没建**。
3. `ForgeCell_1` 的左沿 = `TabL 330.69 + pad 1017 + 375.9 − 1603.3 = 120.29`，右沿 626.19；视口 `x1 = 330.97` ⇒ **这一格有一半在视口左外侧**（格本身与视口相交 ⇒ 建了）。
4. `Points` 子块的中心是格中心 − 196.1、宽 208.83 ⇒ 该子块横跨 **72.7 … 281.5**，**整块 < 330.97** ⇒ `MenuDraw.VisibleAbove` 判「整块在框外 ⇒ 不建」（`Shell/MenuDraw.cs` 的 `Visible` 语义）⇒ `Army` 与 `PointsLabel` **同时不存在**。
5. 而可领那一格 `ForgeCell_3` 在视口中心 ⇒ 子块都在框内 ⇒ 那条前提（`:3674`）绿。

⇒ **生产行为是对的**（原版 `RectMask2D` 语义：裁掉的部分不画、也点不到），错的是断言把「第一个建出来的格」当成了「第 1 格」。

**修法**（`Editor/RewardsScene.cs`，只动本节，⛔ 别动生产）：

  ```csharp

  int lvPts  = Mathf.Max(0, lvSel - 1);                            // 它左边那一格（同屏、也完整）
  ```

  然后把 `:3671-3687` 五条的 `fpt0/flb0` 换成 `cellPrevPts` 的直系子件、`fptC/flbC` 换成 `cellClaimPts` 的，期望值从 `PointsText(forgeArmy, 0)` 换成 `PointsText(forgeArmy, lvPts)`。

### 1.4 R3（B2）：切回战役页后背景永久透明

### 2.2 R5：`B106_W14` 的「已拥有」口径太宽

**一处根因，8 条全中**：

- `Shell/ShopTabPage.cs:1517` `IsOwnedCell(idx) => ShopData.OwnedOf(_page, idx) > 0`，被三处消费：
  `:721` `ownedShown`（决定**不建价格图标**、文本印 `Owned`）· `:1524` `PriceButtonBlocked`（决定**变灰**）· `:783` `Buy`（决定**拒绝购买**）。
- 出问题的两件（出厂值见 `Shell/ShopData.cs:174-181`）：
  - 第 1 页第 1 件 `Ultramarines Booster`：`Owned = 3`、限购 `1/5`、`Rarity` 缺省 ⇒ 明明是**还能再买一次**的卡包，却被判「已拥有」⇒ E1/E2/E4/E5/E6；
  - 第 1 页第 3 件 `Space Wolves Booster`：`Owned = 1`、`Rarity = 4`、无限购 ⇒ 正是**传奇重复购买**那一档（`ShopData.NeedsLegendaryConfirm` @ `Shell/ShopData.cs:431`），却被 `:783` 的已拥有闸先拦下 ⇒ D1/D2（确认框根本到不了）；E3 也是它（灰着）。
- **原版判据（已现读，见 `判据/B106_D2_三宿主失败诊断.md` §一）**：`CatalogItemContainer__Refresh` 里那个「已拥有」布尔**只在 `item is CosmeticItem` 时才会被算**，别的类型一律 `= false`（`out_cpp2il_dev_ilspy/CatalogItemContainer.cs:206-257`：`if (item is CosmeticItem) { … } else obj8 = 0; … if (… && obj8 == null) interactable = IsPurchasable(); else interactable = false;`）。
  ⇒ 「拥有数 > 0 就 `Owned` / 不卖」**只对外观件成立**；卡包/通货/票券这些消耗品**永远不在这条路上**。
  （`CatalogItemContainer__TryPurchase` 那支也印证：传奇确认只对 `RawCardScript` 生效。）

**修法（生产，`Shell/ShopTabPage.cs`）**：
```csharp
// :1517
public bool IsOwnedCell(int idx)
{
    var o = ShopData.Offers(_page);
    if (idx < 0 || idx >= o.Length) return false;
    return o[idx].Type == "Cosmetic" && ShopData.OwnedOf(_page, idx) > 0;   // 原版这个布尔只对 CosmeticItem 算
}
```
- 更稳一档：给 `ShopOffer` 加一个显式 `Ownable`（只有外观件 = true），⛔ 别靠 `Type` 字符串比较散落在多处。
- `NeedsLegendaryConfirm`（`Shell/ShopData.cs:431`）**不需要**再单独豁免 —— 一旦 `IsOwnedCell` 只认外观件，名册里没有任何 `Rarity 4` 的外观件，确认框那条路自然恢复（D1/D2 一起好）。
- ⚠️ 这条同时把「第 4 页 ⇒ `Open ({n})`」那一族留成原样（`IsOfferFamily` 不变）。

### 3.2 R6（F1）：单位换算写错

- `:65` `float dyDesign = Mathf.Abs(bots.localPosition.y - touch.localPosition.y) / SettingsWindow.RootScale;`
- `localPosition` 是**设计空间的世界单位**（`MenuDraw.Local` → `LayoutSpace.RectCenter`，**1080 px ↔ 10 单位 ⇒ 108 px/单位**，`Core/LayoutSpace.cs:36/208`）；`RootScale = 0.9` 只是**字号/内缩**的缩放系数（`Shell/SettingsWindow.cs:149`），**不参与坐标换算**。
- 复算：两行间距 80.641 设计 px ⇒ `ΔlocalPosition = 0.7467`；`/0.9 = 0.8296` ⇒ `Round = 1` —— 与日志的「实得 1」**逐位吻合**（生产其实是对的）。
- **修法**（`Editor/B106_W15_Assert.cs:65`）：
  ```csharp
  float dyDesign = Mathf.Abs(bots.localPosition.y - touch.localPosition.y) * 108f;   // 或 LayoutSpace.DesignPxH / LayoutSpace.DesignHeight
  ```
- 🔴 **2026-10-31 就地订正（铁律 5 · `B106_W75` 反证，本行原来是错的）**：本段原写「`RootScale` **不参与坐标换算**」⇒ **不成立**。本窗节点一律经 `Node`(`SettingsWindow.cs:6151`) → `Screen`(`:1581`)，而 `Screen` 里 `S(v,c)=c+(v−c)×RootScale`(`:1584`) 就是**把原版 px 先按 0.9 缩一遍**。逐位复算：屏 y `540+(446.11−540)×0.9=455.4990` / `540+(526.751−540)×0.9=528.0759` ⇒ `Δ=72.5769 px` ⇒ `ΔlocalPosition=0.672008`（不是 0.7467 —— 0.7467 是**没缩**的值）⇒ `/0.9 = 80.641 ⇒ Round 81` ✅。
  ⇒ **上面那条 `* 108f` 的修法修了仍会红**（`72.577 ⇒ Round 73 ≠ 81`）。**正确修法**见 `报告/B106_W75.md` §②：先 `LayoutSpace.PxY(...)` 换 px 再 `/ RootScale`；本仓已有唯一权威换算 `Editor/SettingsScene.cs:126 OrigPxY`。
  ⇒ 教训：日志读数 `Round 1` **区分不了两个假设**（两者都能得 1）⇒ 这类「量纲」问题只能靠**代码链**判，不能靠日志吻合度判。
- ⚠️ 顺带核一下同文件里别处有没有同样的 `/ RootScale` 用在坐标上（本文件其它断言没量坐标，只有这一处）。
