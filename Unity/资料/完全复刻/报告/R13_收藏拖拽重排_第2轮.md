## 一 结论

**12 条（= 1 件活）全部落地，`typecheck` 0/0（两次复跑都是 0/0）。**

一句话：Deck 页的卡组格现在**按住能拖、松手会换位、换位会落盘**；闸门照原版（**有名字/阵营筛选时不可拖**；模式筛不算筛选，照样能拖）。

另有两条本轮**自己查出来、自己纠掉**的坑（都会让功能"看着有、其实永远不触发"，属于必须记下来的）：

1. 🔴 **闸门的第一版写错**：拿 `CollectionData.DeckCount()`（全库）去比 `FilteredDeckIndices().Count`。
   而生产流程是「进 Deck 页 ⇒ **先出模式页** ⇒ 点一张模式卡（`ChooseDeckMode:4557` 设 `_deckModeFilter`）⇒ 才看得到列表」
   ⇒ 那样写等于**默认流程里拖拽永远关着**。判据：原版 `collection`(`+0x50`) 收的是 `DeckCollectionTab.GetCollection()`
   的结果，**已经按 liveops 事件（= 我们的模式）筛过**；`filteredCollection`(`+0x58`) 才是名字/阵营那一层。
   ⇒ 改成 `BaseDeckIndices()`（只过模式筛）当基准。
2. 🔴 **落点下标不能拿 `DeckCells` 的下标**：`RebuildDeckCells` 会**跳过视口外的格子**（`!DeckScroll.Intersects(r) ⇒ continue`）
   ⇒ 滚到第二屏时 `DeckCells[0]` 是第 12 个显示序号。加了一张 `_deckCellPos`（格子 → 显示序号）显式映射。

**⚠️ 给调度台的一条重要订正**（崩溃恢复消息里那条假设不成立）：
**`CollectionItem<T>` 那一半不在 `Shell/ItemDrawer.cs` 里。** `ItemDrawer.cs` 是原版 **`ItemDrawer<T>`**（奖励/商店「按物品类型选抽屉」）
的等价物，全文 `CollectionItem` **0 命中**（文件头第 1-20 行写的就是 `ItemDrawer.Draw(holder,item,qty,override)` 那条链）。
我们的 **`CollectionItem<T>` 等价物 = 收藏窗的**「格子装配 + 点击 + 悬停 + 拖拽」那一层，落在 **`CollectionWindow.cs`**
（卡格 `RebuildCardsCells` / 卡组格 `BuildDeckCell`）。⇒ 本轮 `ItemDrawer.cs` **一个字节没动**（原样 1631 行），**也不需要动**。

## 六 改动请求（跨文件 · ⛔ 我一个字没动）

### 请求 ① → `Shell/CollectionData.cs`（**owner 未知**；不在本批白名单）
现在 `MoveDeckInOrder` 只能走「`DeckLibrary.Load()` → `UpdateOrder` → `CollectionData.InvalidateLibrary()`」这条绕路，
因为 `CollectionData.Lib` 是 **`private static`**、且**没有重排口**。建议加一个薄口：

```csharp
/// <summary>卡组拖拽重排的落点（原版 `DeckInventory.UpdateOrder`）。
/// 失败原因见 <see cref="LastReorderError"/>。⚠️ 名字查不到的**保留原位**（不丢卡组）。</summary>
public static string LastReorderError { get; private set; } = "";
public static bool ReorderDecks(IList<string> namesInOrder)
{
    LastReorderError = "";
    if (!Lib.UpdateOrder(namesInOrder))
    {
        LastReorderError = string.IsNullOrEmpty(Lib.LastError) ? "重排没写进存档" : Lib.LastError;
        Debug.LogWarning("[CollectionData] 卡组重排失败：" + LastReorderError);
        return false;
    }
    return true;
}
```
拿到之后 `CollectionWindow.MoveDeckInOrder` 里那三行（`Load` / `UpdateOrder` / `InvalidateLibrary`）换成一次 `CollectionData.ReorderDecks(names)`，
并**顺手把 `InvalidateLibrary` 的 doc 改掉** —— 它现在写着「**唯一调用点** = `MainMenuRuntime.Build`」，
而本轮在 `CollectionWindow.MoveDeckInOrder` 里多了一个调用点（铁律 5：文档要等于当前认知）。

> 为什么这不算「做了不该做的」：不改的话，`CollectionWindow` 会**重读一次盘**（丢弃 `CollectionData` 那份进程级缓存），
> 只要将来有人在内存里改了卡组**没落盘**，重排就会把它丢掉。今天所有写口都会 `Save()` ⇒ **今天没有可观测差异**，但这是个隐患。
