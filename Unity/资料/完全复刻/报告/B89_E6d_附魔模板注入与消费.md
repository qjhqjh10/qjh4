🔴 **为什么不是 `ctx.EnchantmentTemplates = CardDatabase.LoadEnchantmentTemplates();` 这一行**（原计划写法）：
> `Core/` **不引用 `Data/`**（方向固定 Data → Core；`Enchantment.cs:703` 那条口径就是它）。若在 `Core` 里直接写
> `CardDatabase.LoadEnchantmentTemplates()`，`ruleprobe`（只编 `Core/*.cs` + 显式列的 `Data/CardDatabase.cs`）
> 与「Core 只依赖 Core」这条分层就同时被打破。⇒ **改成钩子**：`Core` 只声明委托，
> `Data/CardDatabase.cs` 用**静态构造**登记（`static CardDatabase() { BattleContext.EnchantmentTemplatesProvider = LoadEnchantmentTemplates; }`，见 `CardDatabase.cs:3577`）。
> **效果逐字等价于那两行**：任何一局（生产 / 自检 / ruleprobe 夹具）只要碰过 `CardDatabase`，钩子就是通的；物化是**懒**的（第一次 `FindEnchantmentTemplate` 才读表）。

🔴 **为什么写在文件末的 `partial` 块**：`BattleContext.cs` 有 48 处账落点按【行号】引用，
其中 `MatchTypes`（`:2151`-`:2397`）里就有 `:2119`…`:2314` 一整片（含 A 行）⇒ 类体里插成员会让它们整体漂移。
`BattleContext` **本来就声明成 `partial`**（`:317`）⇒ 追加在**全部落点之后** = 零漂移（`git diff` 只有一个末尾 hunk）。

## §3 顺手发现（⛔ 没自己改）

1. **`BattleContext.cs` 里 `BattleContext` 类体只到 `:2105`，后面的 `:2151-2397` 是 `MatchTypes`** ——
   我第一次把新成员追在 `IsReplayMatch` 后面，结果落进了 `MatchTypes`（3 条 `CS0708`），
   编译器报的是「`MatchTypes.EnchantmentTemplates` 不能在静态类里做实例成员」。
   ⚠️ 同族提醒：**「文件末尾的方法」不一定是「主类的成员」** —— 追加前先 `grep "^    public .*class "` 看类边界。
2. **`CardInstance` 的非对局实例要走 `CardInstance.Detached(card)`**（`Id < 0`），⛔ 别自己 `new CardInstance(card, 1)`——
   正数 id 是 `BattleContext.NewInstance` 的领地（会与真对局的实例号撞）。
3. **`Enchantments.Attach(ctx: null, …)` 是安全的**（`ActivateTraitsAfterEnchant` 在 `ctx == null` 时早退、
   所有日志都有 `ctx != null` 闸）⇒ 断言可以完全不搭棋盘就验「挂载记录」这一层，比造 `PlayerState` 稳。
4. **仍有未接的同类查找**：`EffectResolver`（`R1d` 的文件）里按**名字**从 `ctx.CardPool` 找卡的几处
   （`:5363` `CreatePool.FindByName(ctx.CardPool, pick.Card)` · `:3481` · `:4691` …）**不会**看到第二张表。
   今天它们找的是「可玩卡」不是附魔模板，所以**不是缺陷**；但如果将来有「按名字找附魔模板」的需求，判据是
   **改用 `ctx.FindEnchantmentTemplate(id)` 或给它加一个 name 版**，⛔ 别直接往 `CardPool` 里塞模板。
