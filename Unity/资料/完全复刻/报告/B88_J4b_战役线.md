## 一、要裁的那条：`GetNodePosition` 的 `−1.0` —— **结论 = 我们的 y 已经取反，判据把 x/y 写反了**

**结论**：`DAT_1834b2bc8 = −1.0f`（`read_literal.py "D:/2/unity_run_ref/GameAssembly.dll" 0x1834b2bc8` → 4B float **−1**）
乘在 **y** 上，**不是 x** ⇒ **不存在左右镜像**，我们 `_centerY − n.Y * Ratio` **已经做了这一步**；
`x` 侧没有任何取反 ⇒ `CampaignData` 的 X 数据**不需要预取反**，两边都**不用改**。要改的只是那条判据的描述（x→y）。

### 逐条证据（4 条，互相独立）

1. **函数体**（`decomp_full/CampaignTrack__GetNodePosition.c:12-14`）：
   ```
   return CONCAT44((node[+0x3c] - offset.y) * DAT_1834b2bc8 * ratio,   // ← 高 32 位
                   (node[+0x38] - offset.x) * ratio);                  // ← 低 32 位
   ```
2. **「低 32 位 = x」由同族的 `SetTrackSize` 反证**（`CampaignTrack__SetTrackSize.c:58`）：
   `sizeDelta = CONCAT44(_, Max(node.anchoredPosition.x) + width * 1.5)` —— 被写进 `sizeDelta` 的**宽度**在**低半**
   ⇒ `CONCAT44(hi, lo)` 的 **lo = x**。⇒ 第 1 条里带 `−1.0` 的是 **y**。
3. **`GetNodesOffset` 同构**（`CampaignTrack__GetNodesOffset.c:52-57`）：
   `CONCAT44(rootNode[+0x3c] − startingOffset.y, min([+0x38]) − startingOffset.x)`
   —— 低半是 `minX − 330`（x 侧，与 `startingOffset.x` 配对）⇒ `+0x38 = X`、`+0x3c = Y`，且 **x 无 −1**。
4. **数据不是预取反的**：`CampaignData.Nodes` 的 `x` 从 **−8** 递增到 **6712**（步长 320，见 `CampaignData.cs:75-80` 头注与表），
   与 SO 原值同向 ⇒ 我们喂的 X 就是原版 `+0x38`。

**⇒ 行动**：`CampaignTab.NodePos` 的 `_shiftX + n.X * Ratio` / `_centerY − n.Y * Ratio` **保持不动**（已经对）。
账 row 69 里那句「顺手发现：x 乘了 −1.0」**已推翻**，补丁里写明了。

> ⚠️ **仍未查清（与本条无关，但同属 x 方向）**：`CalculateRatio` 的分子是
> `trackHolder.height − nodePrefab.background.height` = **559.06**，而 ratio 同时用于 **x 与 y** 的缩放
> （原版 `GetNodePosition` 的 x 也乘 `ratio`）。若按此，x 方向跨度 = `(6712+8) × 0.1276 ≈ 857px`，
> 与「SetTrackSize 把内容宽设为 `Max(node.x) + …`（≈6712 量级）」**对不上** ⇒ x 侧很可能**另有一套换算**
> （或 `Max` 作用在缩放后的坐标上）。**这一格没查清，别照着猜**。
