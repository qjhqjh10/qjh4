## ② W11 自适应缩放 —— 按原版公式改（**先核了张数条**）

### ②·1 张数条 vs prefab（你要求的第一步）

`python -I -X utf8 工具/menu_dump.py bundle_menus_assets_all "Collection Card" --depth 4 --no-sprite` 现读（2026-10-25）：

| 节点（原型 **350×512**） | 矩形 | 组件 / 逐值 |
|---|---|---|
| `Content` | 0,0 → 350,512 | `NonDrawingGraphic` |
| **`Content/Counter`** | **100, 461 → 250, 511**（150 × 50.01） | `Image` **`Simple (1,1,1,1)` + `preserveAspect`** · `CollectionCardCounter` · `UIFlippable` · `UIImageGreyscaleController` |
| `Content/Counter/Text (TMP)` | 100, 477.7 → 250, 508 | `'x14'` fs **31.9** · auto[7~32] · Center/Midline |
| `Content/CardUI` | 点（0×0，视觉 ×150） | `BasicCardUI` + 5×`CardTextCountersController`(1 禁用) |
| **`CardUI/2DCard`** | **18, 6.2 → 332, 505.8**（313.91 × **499.70**） | `Card2DController` … ⇲ls=150 |

**逐条对账**：
- **位置/尺寸**：`Counter` 的矩形折成锚点 = `x 0.2857..0.7143` · `y 0.002..0.09967` ⇒ 与我们的 `CardsCntMinX/MaxX/MinY/MaxY` **逐位相同** ✔（我们没错）。
- **底色 alpha**：`Image.m_Color = (1,1,1,1)` ⇒ **不透明白**（条的可见形状来自贴图本身）✔ 我们 `Rect(..., null)` = 白。
- **类型/等比**：`Simple(0)` + `m_PreserveAspect = 1` ✔ 我们 `Rect(..., keepAspect: true)`。
- **层级/渲染队列**：prefab 兄弟序 = **`Counter`(0) → `CardUI`(1)** ⇒ 按 uGUI 规则条**在卡下面**；**但卡体是 2D sprite 渲染器**（`Card2DController` + `_SortingLayer/_SortingOrder` 那一族），uGUI 与 2D 渲染器的先后由 Canvas / sorting 决定 ⇒ **静态 prefab 判不出**。实拍里条**是看得见的** ⇒ 我们保留「条画在卡之上」（`QPageRow` 3032 > 卡 3000），**并把这个取舍写进断言文案**（标「判据不可及 + 实拍佐证」）。
- **渐变遮罩**：`Counter` 上**没有** `Mask`/`RectMask2D`/渐变组件 ⇒ 无遮罩 ✔

⇒ **结论：条与 prefab 一致** ⇒ 按你的分支走「重叠是原版行为」。

### ②·2 公式与重叠（prefab 反证）

- 卡体 `2DCard` = **499.70 / 512 = 97.6%**、宽 **313.91 / 350 = 89.7%**
  —— 与公式 `384 × 150 / 512 = 112.5` px/卡单位（世界缩放 1.0417）算出的 **97.6% / 89.7%** **逐位吻合** ⇒ **公式就是原版卡体的真实大小**。
- 卡体 y `6.2 → 505.8`、条 y `461 → 511`（同一 512 帧）⇒ **重叠 44.8px**（折成 384 格 = **33.6px**）。
- ⚠️ **实拍不能当尺子**（你已明确）：用户参考图的 81.7% / 82.8% 量的是**立绘/边框内沿**，不是 `CardUI` 外框（外框 = 89.7% / 97.6%）。

### ②·3 改了什么（`Shell/CollectionWindow.cs`）
1. `float scale = (CardsCellH − CardsCounterH) / (CardView.Height × 108f)`（0.9609）
   → **`float scale = CardsCellH * 150f / 512f / 108f`**（= **1.0417**），并就地订正了那一大段「为什么不用它」的注释（改成 prefab 实测判据 + 说明重叠是原版长相）。
2. `CardsCardRect(cell)` 由「格高 − 张数条」**改回整格**（卡体在整格里居中 —— `2DCard` 上下各 6.2 边距、居中，折 384 = 上下各 4.65）。
3. `CardsCounterRect` / `CardsCounterH` **没动**（已是 prefab 值）。

### ②·4 断言（`Editor/CollectionScene.cs` 新一节，标「待并排比」）
- ① **卡体缩放 = 公式值** `384×150/512÷108 = 1.0417`（`CardView.BaseScale`，容差 1e-3）—— 🧨 退回 0.9609 ⇒ 红。

## ⑥ 顺手

1. 🟢 **prefab 反证法好用**：这次「公式对不对」不是靠实拍、也不是靠反汇编推，而是**拿 prefab 里 `2DCard` 的实际矩形去反算**（499.70/512 = 97.6% ⇔ 公式的 97.6%）—— 一步就把「公式 / 实拍 / 我们」三方分歧定死了。以后遇到「某个缩放/尺寸公式对不对」，**先找 prefab 里那个件自己的矩形**。
