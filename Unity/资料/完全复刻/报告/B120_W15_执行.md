## 一、`D118-64` 满手抽牌：整段建模

### 判据（第一权威 · 现读全文）

`d:/2/tools/decomp_full/PlayerHand._AddDrawnCardToHand_d__37__MoveNext.c` 是一个三态协程：

| state | 逐句（`.c` 实读） | 对应的「拍」 |
|---|---|---|
| 0 | `BattleHud.GetCardDrawPosition(isPlayer)` → `CardScript.SetSortingLayer(<HandMoving>)` → `CardScript.DrawCard(card, pos = 抽牌锚, scale = Vector3.one × cardDrawnScale, t = TimeToDrawCard(isPlayer))` → `WaitForSeconds(TimeToDrawCard + DAT_1834b2dc4)`（4B 实读 **0.1**） | **飞牌**（+ 落位后 0.1 s 停顿） |
| 1 | `hand.Count(+0x50→+0x18) < BattleManager.MaxCardsInHand()` ⇒ `List.Add` + `SetupCardInHand` + `MoveCardsInHandToPosition`；**否则** `CustomDebug.Log` → `CardScript.SetCardStateInCemetery` → **仅 `PlayerHand + 0x28 (isPlayer)`** 为真时 `ShowHeadsUpMessage(GetTermTranslation(Battle/Tips/HandFull))` → `WaitForSeconds(DAT_1834b2bb4)`（4B 实读 **0.5**） | **抬头提示（仅本机侧）** + 等 0.5 s |
| 2 | `CardScript.SendToCemetery`（= `StopAnimsInPlay` + `DissolveWholeCard(timeToDissolveCard 0.2)` + `GoToCemetery`，见 `CardScript__SendToCemetery.c`） | **送墓地**（溶解） |

`CardScript__DrawCard.c` 只做 `DOScale(Vector3.one × cardDrawnScale)` + `DOMove(param_2)`；`param_2` 就是
`GetCardDrawPosition` 那个**抽牌锚**（我们的等价口 `BattleDriver.CardDrawPositionWorld`）。

### 改前

- 引擎：`RuleCore.AddCardToHandWithinLimit` 判到满手 ⇒ `AddToCemetery(ps, inst)`，**牌从不进 `Hand`**、
  也**不发任何信号**。
- 表现层：只有 `BattleDriver.WatchHandFull` 这一条**旁证**口径 —— 看「弃牌堆里多了一份从没进过手牌/棋盘的东西」，
  当场 `SetHint(HandFullText())`。它**不知道飞牌什么时候落位** ⇒ 提示比原版早约 0.4 s，而且**飞牌与送墓两拍整段没有**。

### 改后

1. **引擎**（`RuleEngine/Core/RuleCore.cs:3249`，同一物理行）：
   `MoveDeckTopToHand` 里抓 `AddCardToHandWithinLimit` 的返回值，为 `false` 时发
   `ctx.Emit(EvtKind.Draw, p, -1, inst.Card.Name, effect: "handFull", instanceId: inst.Id)`。
   - 载体**借 `EvtKind.Draw` + `Effect == "handFull"`**（与既有 `Effect == "display"` 同一套借用约定，
     ⛔ 不是新增 `bool` 字段、也不新增 `EvtKind` 成员 —— 后者要在 `DurationOf` / `SourceOf` /
     `TimedKinds` / `IsSourced` 四处同时登记，且会撞 `BattleScene.cs:2561` 的 `unsourced == 1` 断言）。
   - **发出点只此一处**：⛔ 别抬进 `AddCardToHandWithinLimit`（它同时服务**造牌**
     `_AddCardNotDrawnToHand`，原版那条路**没有**抬头提示）。
   - `Emit` 只写 `Signals` / `ActionLog`，**不进 `ctx.Events`** ⇒ 不动 `NetProtocol.Fingerprint`。
2. **表现**（`CardPresentation/Battle/BattleDriver.cs:41561` `PlayHandFullDrawFeel`）：
   - 第 1 拍：建一张临时卡（我方 `CardView` + `CardFeel.DealInPose`，卡背→翻面→正面；敌方用敌方手牌那套
     卡背 quad + `CardFeel.DealInQuad`），起点 → 终点 = `DrawStartWorld` → `CardDrawPositionWorld`。
   - 第 2 拍：`DealSeconds + 0.1` 之后，**仅 `mine`（本机那一侧）** `SetHint(HandFullText())`；
     敌方不弹（原版 `isPlayer == 0` 不进那一段）。
   - 第 3 拍：再过 `HandFullCemeteryHold`（**0.5 s**）后 `CardFeel.DissolveInHand`
     （⇐ 原版 state2 `SendToCemetery` 的 `DissolveWholeCard`），我方收尾 `Kill`、敌方 `FadeOutHandQuad`。
   - 两拍都走 `SchedulePresentationCallback`（**不动队尾**）：原版外层 `_ResolveDrawCard` 在
     `WaitForSeconds(timeToPositionCard + TimeToDrawCard)`（0.5 s）就 `FinishResolvingAction`，
     送墓那一下（0.9 s）本来就发生在**动作结束之后** ⇒ 不许拿它推下一条事件。
   - 路由：`PlaySignal` 里原来那条 `else if (… e.Effect == "display" …)` 追加一条 `else if (… "handFull" …)`
     （同一物理行，零行数变化）。
3. **去重**：`PlaySignals` 的 drain 循环把 `handFull` 事件的 `InstanceId` 收进 `_handFullDrawSeen`
   （同一物理行）；`WatchHandFull` 见到该实例就**让路**、不再补一次提示（否则一次满手抽牌弹两下、
   第一次还早 0.4 s）。集合在 `ResetHandFullWatch` 里随局清。
4. **别让同一件事响两遍 / 数两遍**：
   - `PlayBattleSfx` 的 `case EvtKind.Draw` 对 `Effect == "handFull"` 直接 `break`
     （同一张牌那条普通 `Draw` 事件已经响过 `DrawCardFromDeck` / `CreateCardInHand`）；
   - `PlaySignals` 里「本批抽卡第几张」的计数**不统计** `handFull`（它对应同一张牌的另一条事件）。

### 影响 / 没做的

- 影响面只在**满手**那一支（手牌未满时这条信号一次都不发）。规则侧零变化（牌仍然在抽的那一刻进弃牌堆）。
- 敌方那一侧同形实现（原版是**同一条协程**，只有 `isPlayer` 分支不同）—— 我方用 `CardView`、敌方用卡背 quad，
  这是**载体差**（我们敌方手牌只有卡背 quad，没有 `CardView`），如实记。

## 二、`D118-66` ①：一次抽 2+ 张的间隔

### 判据（现读）

`d:/2/tools/decomp_full/BattleManager._ResolveDrawCard_d__432__MoveNext.c:233-249`：
起完 `PlayerHand.AddDrawnCardToHand(card)` 之后

```c

fVar2  = *(float *)(globalVars + 0xa4);                  // ← dump.cs 字段表：+0xA4 = timeToPositionCard
WaitForSeconds(fVar2 + fVar11);
```

`dump.cs` 的 `VarsGlobal` 字段表（`public class VarsGlobal` 段）逐行核过：`+0xA0 minionReassembleTime` ·
**`+0xA4 timeToPositionCard`** · `+0xA8 timeToDrawPlayerCard` · `+0xAC timeToDrawEnemyCard`；
值 0.2 见 `资料/VarsGlobal_原版数值.md` §一。⇒ **一条抽卡动作占 0.5 s（我方）/ 0.35 s（敌方）**，
而原版每张牌各入队一条动作（`AddDrawCard(...)`），所以「一张与下一张之间」= 0.5 / 0.35 s。

⚠️ `B120-REC` 当时只差这一格没定名（「还差 `+0xa4` 是 `VarsGlobal` 哪一格」）—— 本次定名 = `timeToPositionCard`。

### 改前 / 改后

| `EventTiming.DrawDealOf(seat)`（时间轴上一条 `Draw` 占多久） | `CardFeel.DealSeconds` = 0.3 / 0.15 | `CardTween.RelayoutDuration(0.2) + DealSeconds` = **0.5 / 0.35** | `.c:243` |

## 四、`B120-Q04d`：`HitSlotHitCountForTest` 与 `HitSlot` 同源

### 判据 / 形状

- `B120_W13` 已把 `HitSlot` 的 **3D 档**换成原版射线链 `TryHitSlotByBoardRay`
  （`Physics.RaycastNonAlloc` → 缓冲里**第一条**解析得出 `CardView` 的；`BattleManager__GetTargetInPos.c:250-265`），
  **miss 即 −1、⛔ 不回落投影**。
- 而 `HitSlotHitCountForTest` 当时仍然**只**跑逐卡投影（`CardHit`）⇒ 两个读口的口径**已经分家**。

### 改后

1. `TryHitSlotByBoardRay` 增加第 2 个出参 **`out int cardHitCount`** = `views` 里被这条射线命中的
   **去重**张数。为了数全，循环不再在第一条卡处提前 `return`：
   ```
   slot = -1; cardHitCount = 0; bool found = false;
   for (...) {
       ...
       if (!found) { slot = SlotOfView(views, cv); found = true; }
       if (SlotOfView(views, cv) >= 0 && !RaySawEarlierHit(i, cv)) cardHitCount++;
   }
   return found;
   ```
   `RaySawEarlierHit(int upto, CardView cv)`（`:41540`）负责按**卡**去重（同一卡体可能挂多颗 collider）。
   槽号语义**逐位不变**（仍 = 第一条解析得出 `CardView` 的命中；原版 `hits[0]`）。
2. `HitSlotHitCountForTest`：3D 档**直接委托同一条射线链**；2D 烘图兜底档仍走逐卡 `CardHit`
   （那一档 `HitSlot` 用的也是同一谓词，只是多算一个 z 序 —— ⛔ 不是第二套判据）。

### 影响 / 没做的

- ⚠️ **`BattleScene.cs` 的 `B2b②`（「两张卡叠在同一点 ⇒ 取 z 最小那张」）已经过期**：`B120_W13` 之后
  生产口在 3D 档**不再按 z 排序**（原版就是 `hits[0]`、`RaycastNonAlloc` 不排序）⇒ 那条断言在本机缓冲序
  固定时**可能不再红/绿**地说明问题。**该文件不在本代理白名单**，未改，交调度台分流。
- ⚠️ 同样地，`B97_UI2_Assert` / `B97W37_Assert` 里把 `HitSlotHitCountForTest >= 1` 当「真 collider 命中」的**前提**：
  3D 档现在等于「射线命中」，语义仍然成立（还更贴原版），但那两句文案里的「`CardHit` / `HitByCollider`」
  说法过期了 —— 也在别的代理文件里。
- 计数语义：只数**本册**（同一侧 `views`）里的卡，与容器口径一致。
