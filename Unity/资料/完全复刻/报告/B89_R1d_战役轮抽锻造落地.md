### §1-1 为什么 `DeckSelectionPopup` 的改动是「零漂移」写法

`卡组编辑.tsv` 里 `DeckSelectionPopup.cs` 的 A 行落点有 `:183/:191/:198/:245/:253/:259/:372/:397/:432/:46` 等 ⇒ **插一行就全漂**。做法：
- `Create` 的形参**加在同一行**（`int? modeFilter = null, … filter = null`）；
- `win.Filter = filter;` **接在 `win.ModeFilter = modeFilter;` 那一行**后面；
- 两个消费点都是**在原有 `if` 里加一个 `&&` / `||`**；
- 新字段 + 它的 doc **整块追加在类尾**（类尾之后没有任何落点）。

⇒ 改前改后**既有行号逐行不变**，只有文件变长（尾部）。

### §1-2 判据（逐条，⛔ 不是猜的）

- 原版排位栏开「选卡组」窗时带的 `DeckSelectionContext` 里有**列表级谓词**：
  `decomp_full/RankedDeckSelector___OnSelectDeckButtonClick_b__32_1.c` = **`d.Army == currentArmy`**
  （账 `战役.tsv:121` 就是这条；`:117` 的 ② 缺的两个口 = 本条 + `allowEdit:false`）。
- 本工程阵营是**字符串**（`CollectionData.DeckInfo.Faction`，判据 = 那个 struct 的 `:47`），不是原版的 `CardArmy` 枚举
  ⇒ 调用方写 `d => d.Faction == currentArmy` 即可。
- ⚠️ **只作用于「我的卡组」那一页**：预组页**不筛**（照原版 —— 见 `ModeFilter` 的 doc：预组页就是两模式混排的 66 副）。

## §4 顺手发现

1. ✅ **战役 55 的「两套图」其实早就在本地**：`CardPresentation/Resources/Art/ui_menu/40K_genearl_icon_Campaign_points.png` 与 `…_big.png`（源 = `bundle_menusharedresources_assets_all/Texture2D/40K_genearl_icon_Campaign points[ _big].png`；原版名确实把 `general` 拼成 **`genearl`**，⛔ 换拼写去搜会 0 命中）。⇒ 我上一批 §5 的 **D-1 结案**。
2. 🔴 **`CampaignPoints` 在本工程不是「item」，是标量**：`CampaignData.Points`（本次读 = **9999**，注释写明「用户 2026-10-24 只改 `Wallet.StartAmount`，战役点未动」）。⇒ 原版那套「按阵营画战役点」在我们这里**没有入口**；把它当视觉缺陷去追会白做。
3. **`ItemTypeSet` 的后三列（`Horizontal`/`Shop`/`Popup`）写 `null` 是正确的**（= 原版 `customDrawerOverrides` 里**没写这一档**、回落主档），不是「判据空」—— 该 struct 的 doc `:367-371` 已经写死这条，⛔ 别把它当缺口。
4. **`DeckInfo.Faction` 是字符串**（从督军卡推，查不到=空串）⇒ 任何「按阵营筛」的谓词都要考虑**空串**这一档（我的 `Filter` 口交由调用方决定；⛔ 默认值别写「空串算不算」）。
