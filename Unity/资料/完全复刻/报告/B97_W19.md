### 2·1 新入口干了什么（逐句对照 `B97_R1`「第二轮·1」那五步）

```csharp
static bool TryCancelAttackByUnits(ctx, p, atkSlot, tgtP, ref tgtSlot, ref target)
{
    打的是敌方督军吗？            // ① ability 的 targetCriteria 筛被打者（`your Warlord`）
    攻方还在场、没将死？          // ③ AddRedirectedAttack.c:36-48
    cands = CheckUnitsCancellingAttack(ctx, attacker, target);       // ② 原版那一个查询口（0 调用点 → 现在有）
    using (BeginAction(ctx))
        逐候选（只收【被打督军那一方】）→ FireCancelAttackTrigger(...)  // ② ResolveCancelAttack → OnTrigger(0x118)
    return TryRedirectAttackToBodyguard(...);                        // ⑤ 74 的同步等价 = 就地改目标

```
- **① `ClearPendingDamage` ×2**：本仓**没有 pendingDamage 缓冲**（伤害逐段现结，账 `:253` 备注已记）⇒ **无对象**，不建假的。
- **① `RegisterPlayerActionCancelled`**：只动 `bm + 0x3bc` 那个**联机计数器**（`Net/*` 那条线）⇒ 本件不碰。

- **作用域**：`FireTriggerAt` / 补发信号都**只入队** ⇒ 新入口自带 `using (BeginAction(ctx))`（形状照

  出队发生在**外层**退出时（即主伤害之后）—— 今天池内**没有**任何卡有 `abouttoattack` 的可结算正文

## 三 🔴 与简报字面的一处偏离（**请调度台裁定**，理由与证据都在这）

简报第 2 条写「删掉 `:6089` 一带的 `gu.Card.Bodyguard` 判据（它属于旧捷径）」。
**照做了**：`TryRedirectAttackToBodyguard` 里那行 `if (gu.Card == null || !gu.Card.Bodyguard) continue;`
已经**不是**成员判据了（成员来自 `CheckUnitsCancellingAttack`）。

**但 `CardDef.Bodyguard` 我保留在 `HasCancelAttackAbility`（=「这张卡有没有那条 280 ability」）里**，
与 `AbilityTriggerPresence(280) == 1` 并列。三条理由（都是现读，不是偏好）：

1. **数据层那一行今天派发不了**：`SAU33` 的 280 ability 只有 `chosenAbility 236`（`cards_truth.json` 现读），
   而本引擎**没有 `chosenAbility` 的 trigger 派发口**（`EffectResolver.cs:18102` 自己写着
   「`chosenAbility` 驱动的那一类今天没有分派口」）⇒ 若只认「正文存在」，`Vargard Obyron` 会**不是候选**
   ⇒ 替身**整个失效**（今天唯一一张替身卡）。
2. **宿主里 6 条既有断言用 `Bodyguard` 夹具钉原版语义**（`RuleEngineTest.cs:8186-8400` 的 ②-a…②-f：
   沿用攻方打法 / 不复检 Stealth / jam 不截 / 只结算一次 / 只管打督军 / `forced` 不截）。
   那些夹具是 `new CardDef(..., "Any attack against your Warlord targets this troop instead.")`，
   **没有** `abilityTriggers` ⇒ 只认数据列会让 6 段 ≈20 条断言**全红**，而 `RuleEngineTest.cs`
   本批不在我的白名单（简报：宿主接线由调度台做）。
3. **语义上它不是捷径**：`CardDef.Bodyguard` 就是卡面那句原文的解析结果
   （`MatchStaticBattleRule` 的 `"替身"` 分支，`:4397`），与原版那条 ability 是**同一件事的文本层表达**；
   它现在只参与「有没有这条 ability」，**不再**决定「改不改目标」。
   📌 建议：等 `chosenAbility 236 → AddRedirectedAttack` 的 trigger 派发口建起来后，
   把 `Card.Bodyguard` 从这条谓词里摘掉（届时 `AbilityTriggerPresence(280)` 一项就够）。
