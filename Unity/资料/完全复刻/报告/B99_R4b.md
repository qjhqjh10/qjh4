## 四 `P06` 静态盐 2×2 → **改成 1×2**，并且旧 profile 就在本机

### 1 判据结论（算法已完全解出）
判据 = `out_cpp2il_dev_ilspy/CryptoString.cs`（**ILSpy 有可读全量体**）+ `decomp_full/CryptoString__GetPWD.c` / `__NewRijndaelManaged.c` + `dump.cs` 两个常量。

```
EncryptRijndael(text):  空串直接 return text；否则 pwd = GetPWD()（**dataVersion 用默认值 1**）
NewRijndaelManaged(salt):
   kdf = new Rfc2898DeriveBytes("560A18CD-6346-4CF0-A2E8-671F9B6B9EA9", ASCII(salt))
         // 密码 = Inputkey 常量；默认 1000 次 / HMAC-SHA1
   rm.Key = kdf.GetBytes(32); rm.IV = kdf.GetBytes(16)      // 同一实例继续取 ⇒ 共 48 字节
   ⇒ AES-256-CBC，结果 Convert.ToBase64String
GetPWD(dataVersion = 1):
   dataVersion != 0 且 DUID 非空 且 DUID != "n/a" 且 DUID 长度 >= 5  ⇒ 盐 = DUID
   否则                                                          ⇒ 盐 = "toQmbArBDRPNkMbm"
```

**⇒「2×2」不成立**：**密码恒 1 个常量**，盐只有 **2 个分支**（常量档 / DUID）。组合 = **1 × 2**。

**并就地订正一条**：简报说「先试 DUID 空/长度<5 那一支」—— 那一支**不是我们挑的**，它由旧机器当时的 `SystemInfo.deviceUniqueIdentifier` 决定；Windows Standalone 上它**总是可用**（不会 `n/a`）⇒ 旧档**几乎必然**是 DUID 档。真正能走常量档的只有一条：**存档里的 `dataVersion` 恰好 == 0**（`PlayerDataManager__LoadPlayerData.c:34-35 / :235-236` 把档里那一格传给 `DecryptRijndael`）。

### 2 🔴 新发现：旧 profile 真身在本机（B98 说「永久不可解」时没看到）
- **`d:/2/关服前存档/Warpforge/PlayerDecks39.dat`（1,211 B）** = `BinaryFormatter` 序列化的 **`LocalPlayerData`**（40 字段，字段名与顺序我逐条读出）。
- 同目录 `Player.log` 18.6 MB · `Player-prev.log` 6.2 MB · `RemoteConfigCache.json` · `eventcache` —— **P07 / P09 那几条远端账先来这儿翻**（铁律 2 对 `D:/2/关服前存档/` 的原话要求）。
- 另一份 `d:/2/远端缓存_旧profile_1013/Everguild/PlayerDecks39.dat` **10.4 MB**，同名但大 8,600 倍，**不是同一份东西**。
- 我从 1,211 B 那份读到：值区里一段 **64 字符 base64**、`lastBuildSaved = "1.35.0"`、**两个空串**（`BinaryObjectString{len 0}`）。`PlayerDataManager__SavePlayerData.c:42-49` **只加密 `loginPassword(+0x18)` 与 `deviceId(+0x20)` 两格**，`playFabId` 不加密。
  ⚠️ **字段 ↔ 值逐格对齐我【没闭合】**（BF 的 string 成员是记录式写入 `06/09/0A`，我第一版按裸长度前缀解 ⇒ 漂 1~3 字节）。**如实记，⛔ 不猜。**

### 3 判定实验设计（**纸面，本批未执行**）
- **E0（前置，≤30 分钟，一步判死 2/3）**：用 `BinaryFormatter` 真正反序列化成 `LocalPlayerData`（⛔ 别手写解析；`Shell/LegacySaveReader.cs` 可看有没有现成读法）。自校验 = 40 字段全有值 + `lastBuildSaved == "1.35.0"` + 字节消耗 == 1,211。
  - `loginPassword` 与 `deviceId` **都空** ⇒ 🟢 **P06 无阻塞**（原版 `EncryptRijndael("")` 直接返回 `""`，档里没有任何 DUID 派生密文）。
  - `dataVersion == 0` ⇒ 🟢 盐 = 常量，可解。
  - 有密文且 `dataVersion != 0` ⇒ 需要 DUID ⇒ E2。
- **E1（常量盐试解，也可用来排掉这一支）**：`pbkdf2_hmac("sha1", INPUTKEY, b"toQmbArBDRPNkMbm", 1000, dklen=48)` → key 32 / iv 16 → AES-CBC 解 base64。
  **判定式（自校验，无需已知明文）**：解出必须**全是可打印 ASCII**。错盐时每字节可打印概率 ≈ 96/256 ⇒ ≥16 字符的串命中概率 < 1e-7 ⇒ **一次就能判死/判活**，不存在「像对又不敢定」。
- **E2（真需要 DUID 时）**：① 先测本机 `SystemInfo.deviceUniqueIdentifier` 与 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid` 的关系（是否 `MD5(MachineGuid)`）——**这一步决定还有没有救**；② 找旧 MachineGuid：`C:\Windows.old`（**本机存在该目录，但 `Windows/System32/config` 已不在**，我实测过）· `*.reg`/`NTUSER*` 导出 · 还原点 · 归档 dump / log（我已 grep `[0-9a-f]{32}` 与 GUID 模式，**全 0 命中**）；③ 全无 ⇒ 128-bit 未知盐、无已知明文 ⇒ **那时**才写「不可解」。
