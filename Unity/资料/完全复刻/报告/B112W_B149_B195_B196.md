## 四、`B-196` 的换算修正（改前 / 改后算式）

**改前**（`CardDisplayEffects.Build`，挂在战斗窗 `Cards` 下）

```
unitToPx = CardsS / 2.0927 = 100 / 2.0927 = 47.785          // CardsS=100 是 **100×100 的定位框**，不是卡宽（CardWinBox.cs:22）
s        = unitToPx / 108 = 0.442457
```

而主卡 `CardView` 根的**实际**局部缩放（详情窗槽 0）：

```
h        = CardFan.Hpx(0) = 832.825 px                       // 前台那张的目标高
baseScale = h / (CardView.Height * 108) = 832.825 / (3.3313 × 108) = 2.314754
```

⇒ 光效层实际渲染尺寸 = `s × 1`（父件 scale=1 的世界壳）÷ 卡的实际 scale：

```
2.314754 / 0.442457 = 5.232 倍   ← 即「光效层比卡小 5.23 倍」
```

**改后**（`BuildUnder2DCard`，挂主卡 `2DCard` 下）

```
s = 1
```

理由（不是拍脑袋）：原版这些节点的坐标/尺寸/缩放**本来就是 `2DCard` 的局部单位**，而我们的

```
CardView.Width  = 2.0927  == 原版 2DCard.m_SizeDelta.x
CardView.Height = 3.3313  == 原版 2DCard.m_SizeDelta.y
```

逐值相同；`2DCard` 在 `CardView` 里 `localScale = 1`（`CardView.cs:4260`），父链的 2.3147 是**卡自己**的缩放 ⇒ `s=1` 时粒子/图件与卡面同一套单位，缩放由父链自然带上（`scalingMode = Hierarchy`）。

> ⚠️ 判据 §还差什么 #1 已声明：这是**算术推算，没在 Unity 里量过**。真机必须目测一次（见 §六）。

## 七、顺手发现

1. 🔴 **`CardView.Build` 不幂等（判据文档 §还差什么 #2 的猜测不成立）**：`AddLayer` 每次都 `new GameObject` + `new Material`，`Build` 开头**不清旧层**（`CardView.cs:6295`）。⇒ 判据里那个 `RefreshTier() { Build(Data); }` 的写法**会整卡层数翻倍**（静默，typecheck 也看不出来）。建议补一条反证断言「同一实例连续 `Build` 两次，子件数/`_layers.Count` 不变」，或干脆把 `Build` 改成先清层再用。本批选择了不用 `Build`（见 §三）。
2. **`2DCard/Glow Explosion` 与 `Lighting Rays` 两条 path 仍解析不到**（10 条曲线里 5 条 path，命中 3 条）。判据 JSON 的粒子 `parent` 字段（`Circling Particle` / `Glow Explosion` / `Lighting Rays`）**现在被 `BuildInto` 忽略**，所有粒子直接挂层根 —— 若按它建出父节点，这两条 path 就通了（`Lighting Rays` 是 `CardUI` 的直接子件，不在 `2DCard` 下，要单独挂）。**未做**：判据 §还差什么 #3 明确「要不要补留待有判据再定」。
3. **`Side Border Left/Right` 与 `Level Up Effect` 不是同一套单位**：前者 `933.9×2280.3 · pos(−1426,−19.4)`（像屏幕 px），后者 `2.80×3.81 · pos(−0.001,−0.023)`（卡单位）。旧代码用同一个 `s` 折两者 ⇒ Side Border 算出来是 **1009 世界单位（≈10.9 万 px）**；换父件后变成 2280 **卡单位**，同样离谱。**但这两件建出来就是 `SetActive(false)`、全仓没有任何地方把 `Borders` 打开** ⇒ 行为不变、画面不变。将来若要真开 Borders，必须单独给一套换算（⛔ 别把它并入 `s=1`）。
4. **光效层图件的渲染队列仍是默认 3000**（`ImageQuad.Create` 用 `Sprites/Default`），而卡面各层被 `CardFan.ApplyQueues` 钉在 `QCardStack = 3106` ⇒ `Level Up Effect` 那张图会画在**卡框后面**（原版它是 `2DCard` 的子件、按层级序在框上）。本批**没改队列口径**（属表现层，需真机确认），真 Play 时请重点看「1.45 s 边框辉光看不看得见」。
5. `CardDetailPopup` 每次 `Build()` 都会重建整层光效（10 粒子 + 4 图 + 材质克隆）；`DoUpgrade` 那一跳整窗重建 ⇒ 一次升级会建两次。可接受（原战斗窗也是每次开都建），但若以后详情窗变重，可把这一层做成懒建/缓存。
6. `CardDisplayEffects` 的 `_warnedParent` 现在会替 `Side Border*`（父件 `Borders`）出声一次——那是**预期**的（父件不在本层名单里），不是故障。
7. `Editor/B97_PROFILE_Assert.cs:82` 只在注释里提到 `CardDisplayEffects`（说它「恒 true」的那一段判据），本批没碰 `ApplyParticle`，零影响。
