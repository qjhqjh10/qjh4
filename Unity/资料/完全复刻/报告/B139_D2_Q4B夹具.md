## §1 根因（照诊断 #8/#9，已复核）

旧夹具的拖距是**用阈值表达式算出来的**：

```csharp
float needTravel = CardInteraction.TapThreshold * 2f;
if (Vector3.Distance(inHand, home) < needTravel) inHand += new Vector3(needTravel, 0f, 0f);
```

`inHand`（`ToWorld(0.5, 0.12)`）与卡的 `home` **横差 ≈0.1234 且方向与补足相反** ⇒ 实得拖距 = `2T − 0.1234`。
`TapThresholdPx` 10→5（`B130`）后 `2T` 由 **0.4167** 掉到 **0.2083** ⇒ 拖距 **0.0849 < 0.1042**：

1. `（前提）C2 这一拖超过轻点阈值` 直接红（等于 `0.0849 ≥ 0.1042` 为假）；
2. `Release` 里 `_travel >= TapThreshold` 不过 ⇒ `ApplyOutFromPlayingArea` 不被调 ⇒ `★C2`（`lights` 应 1）连带红。

⚠️ 这条同时是**铁律 5 的判据过期**：文件里写着「批处理 480p ⇒ 0.2083」，那是 10 px 时代的值，现为 **0.1042**。

## §2 改法（`Editor/B121_Q4B_Assert.cs`）

### C 组（`C_NotCommitted`，:349-377）：拖距改成**绝对常量**

- `const float DragDistWorld = 0.25f;`（:359）—— 480p 阈值 0.1042 / 1080p 0.0463 ⇒ 明确大于任何一档合理的轻点阈值；
- `Vector3 inHand = home + new Vector3(DragDistWorld, 0f, 0f);`（:360）—— **只横移、y 不变** ⇒ 仍在手牌带（线下）、`PlayCommitGate` 必不过；
- 前提拆成**三条硬断言**（原来只有一条，且与阈值同表达式）：
  - `C1`（:363）**拖距 = 显式常量**（|travel − 0.25| < 1e-4）⇒ 挡「有人又写回阈值表达式」；
  - `C2`（:366）**拖距 ≥ `TapThresholdWorldAt(Screen.height)`** ⇒ 阈值将来再变，这条会**自己报红**，不再静默相消；文案写死「这条红 = 调大 `DragDistWorld`，⛔ 别去改阈值（原版就是 5）」；
  - `C2b`（:370）**落点仍在手牌带**（`!CardInteraction.IsInPlayArea`）⇒ 挡「把落点拖到出牌区、测到另一条支」的假绿。
- 原文案「批处理 480p ⇒ 0.2083」就地订正为「阈值现为 **5** ⇒ 480p 下 **0.1042**」，并写明错因（`2T` 带符号补足被横差相消）。

### 新增 E 组（`E_ShortDragBelowThreshold`，:464-488）：**灭自证 ②**

同夹具、同路径，**只把拖距减到阈值 ×0.5**：

- `E1`（:474）前提：`travel < th`；
- `E1b`（:476）前提：落点仍在手牌带；
- `★E2`（:482）**`lights == 0` 且 `returns == 1`** —— 即 `CardInteraction.cs:1550` 那道 `_travel >= TapThreshold` 闸**真的挡住**。

**为什么这算灭自证**：C 组的前提与 E 组的前提是**同一个谓词**（拖距 vs 阈值），一个给 0.25、一个给 `0.5×阈值`，
结果一个是「亮灯」、一个是「不亮灯」⇒ 前提**不是恒真**。阈值被改小 / 那道闸被删 / 前提被写回阈值表达式
⇒ E2 的 `lights` 会变 1 ⇒ 红。

> ⚠️ 这条**不靠改阈值取绿**：阈值 5 一个字没动（`git diff` 里 `Hand/CardInteraction.cs` 为空）。
