| 项 | 结论 |

### 证据链

1. `RuleEngine/Core/RuleCore.cs:13083`（`FireTriggerAlways` 的早退条件）：
   `if (u.FxOps(keyword) == null && u.Effect(keyword) == null && !(Enchantments.HasAny(u) && Enchantments.Matching(u, keyword).Count > 0))`
   ⇒ **只有「一件匹配的附魔都没有」时才进这一支**；一支匹配的附魔都没有，`FilterByQuestCounter` 自然无事可做（它不是「漏接」，是**空集**）。
2. `RuleCore.cs:13093`：其余情况（含**有**匹配附魔）一律 `FireTriggerAt(ctx, u, keyword, owner, slot, null, subject);`。
3. `RuleCore.cs:12713-12742`（`FireTriggerAt` 体内）：`var ench = ... Enchantments.Matching(u, keyword)`，随后
   `if (ench != null && ench.Count > 0) ench = Enchantments.FilterByQuestCounter(ctx, u, ench, keyword);` —— **就是这一步**。
4. 另两条附魔派发路也都过同一口：`RuleEngine/Core/EffectResolver.cs:20015`（`RunActiveEnchantmentTriggerOf`）· `EffectResolverPartial_B109E6.cs:93`（`FireEnchantmentAbilitiesByNumber`）。
5. 原版那支**确实要走**：`d:/2/tools/decomp_full/RawCardScript__TriggerAbilities.c`（附魔循环体内）现读有
   `cVar1 = EntityScript__ReachedQuestCounter(param_4, *(lVar2 + 0x10), param_4, 0);`（`ReachedQuestCounter` 在 `CanTriggerAbility` 之后、真正派发之前）⇒ 与我们 `FilterByQuestCounter` 的位置、语义一致。
6. **0 可达成立**：`Resources/cards_engine.json`（现读 `count 1142`）里 `spellType == 120` = **0 张**；`FilterByQuestCounter` 的三道闸是 `cardType==40 ∧ spellType==120 ∧ questTimes>1`（`Core/Enchantment.cs:503` 段头注）⇒ 现池确实一次都跑不到。
