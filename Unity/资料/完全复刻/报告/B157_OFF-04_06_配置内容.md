#### 为什么必须带 `$type`（这是整份里最容易「静默失败」的一格）

- `TemplateConfig.Templates` 是 `Dictionary<string, IDataTemplate>`（**接口**，`TemplateConfig.cs:9`；
  ConfigKey = `Templates`，⚠️ **不是类名 `TemplateConfig`**）。
- 值的反序列化链：`TypedDictionarySerializer.ReadJson` 逐条把 value 交给
  `JsonWrapper.DeserializeObject(JToken, IDataTemplate)` → `JsonConvert.DeserializeObject(…, TypedSettings)`
  → `TypedSerializer.ReadJson` 读 JObject 的 `"$type"` → `ReflectionHelper.GetTypeFromString`（`Type.GetType`）。
  **没有 `$type` 时**：`type2 = objectType` = `IDataTemplate` → `IsAbstract` → 打
  `"Can't deserialize to an abstract type …"` 并**返回 null**（`TypedSerializer.cs:120-140`）——
  也就是**不报错、只剩一个 null 值**，必须靠 `$type`。
- `$type` 的写法沿用工程里**已经跑通**的样例：本文件 RawEvents 的
  `"$type": "Everguild.LiveOps.FixedStoreData, Assembly-CSharp"` / `"TutorialEventData, Assembly-CSharp"`
  （教程/经典模式能进 ⇒ 这条链是通的）。
- 类 `DLCMessageData : LocalInboxMessageData : GameMessageData : BaseMessageData : LiveOpsEventData`
  显式实现 `IDataTemplate, IIdentifiable`（`LocalInboxMessageData.cs:7`），**非抽象、public 无参 ctor** ⇒
  满足 `TypedSerializer` 的 `IsAbstract` / `IsAssignableFrom` 两道闸。
