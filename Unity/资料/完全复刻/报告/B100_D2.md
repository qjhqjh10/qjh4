## §一 结论

| 件 | 结论 | 受影响 | 施工点 |
|---|---|---|---:|
| **A · T21 手牌锚路** | 原版手牌卡**有锚点**（`GetEffectAnchor` 对 `inHand(1)` 取 `cardUI+0x30`）；我们的事件对、**错在 `PlaySignal:23300` 的 `if (slot<0) return;` 把整条事件吃掉**。 | **6 张卡**（必须手牌锚的 **3 张**） | **3 必做 + 1 建议 + 1 伴随另立** |
| **B · 多目标 `sp/ep/pt==2`** | 消费端**已完整**；**生产端只出 0/1 个目标** —— 缺的是「这一条 ability 的 `targetsAffected` 目标表」。原版它是 `AbilityLogic.GetTargets` 的**列表**、每 logic 一次、`PlayAnim` 逐目标各播一份。 | `sp/ep/pt==2`：**55 卡 / 67 拍**；真多目标 **8 卡 / 11 拍** | **3 处** |

**两处术语必须先纠正**：`sp/ep/pt` = `PositionOption`（`2 = abilityTarget`）；`targetsAffected`（`ta`）是另一把尺子，**枚举里没有 `2`**。「多目标 `sp/ep/pt==2`」的正确读法 = 「位置选项引用 `abilityTarget` 的那几拍」，张数由 `ta` 定。

## §二 A —— 关键证据（五跳）

1. **原版锚点**：`decomp_full/CardScript__GetEffectAnchor.c`（全文 18 行）—— 状态 `+0x228 ∈ {0,1,4,8,9,10,12,16}` ⇒ `cardUI+0x30`（2D 卡那一级）；否则 `cardUI+0x1a0`（场上卡）。
   `CardStateOptions.cs`：`inHand=1`（⇒ 手牌走 2D 卡那一级）· `inPlay=2`（⇒ 场上那一级）。
   `AbilityLogic__GetPos.c:183-187`（`case 0 self`）⇒ `thisCard(+0x10)` → `GetEffectAnchor()`。
2. **原版播放**：`AbilityLogic__PlayAnim.c:171-248` —— 每拍按 `GetPos` 解 sp/ep/pt，`BattleManager__AddCardAnim`（`decomp_full/BattleManager__AddCardAnim.c` 全文）每次压一条 `BattleAction(0xb)` 进动作队列。
3. **我们的等价件齐了**：`CardView.EffectAnchor(bool)`（`CardView.cs:2149-2155`，手牌档 = `FaceRoot` = `2DCard`）· `AnimAnchors.CardAnchor`（`AnimAnchors.cs:275-284`）按 `OnBoardOf` 二选一 · `BattleDriver.IsViewOnBoard`（`:3998-4004`）对手牌视图返 `false` ⇒ **只要把手牌视图当 `self` 传下去，锚点自动正确**。
4. **事件确实发了**（`EffectResolver.cs:18852-18861` `EmitHandAbilityTrigger` / `:8344-8365` `EmitCardTrigger` / `:8588-8607` `EmitTurnTriggerRaw`，三者都 `Slot = -1`）。
5. **死在表现层**：Trigger 支只接管 `UnitAttack`（`BattleDriver.cs:23203-23233`）→ `TryHudAnchor` 不认 Trigger（`:24697-24700`）→ `:23282` 的 Play 支不成立 → **`:23300 if (slot < 0) return;`**。
   注：`:23300` 之前的**音效/语音照播**（`:23083-23138`），缺的只是画面。

**受影响卡（现读，⛔ 不是 4 张）**：严格判据（`abilityContext == 10` **且** 有对应 `animTimes` 行）⇒ **6 张**：
`Improvised Barricade` · `Jammed Communications` · `Cult Propaganda` · `Poisoned Supplies` · `Vengeance for Cadia` · `Avenging Zeal`。
其中「必须手牌锚」的只有 **3 张**（前三张里的 `Jammed` / `Cult` / `Poisoned`，它们的 `Card_Buff_Sabotage_self` 是 `sp=0 self`）；另外 3 张的拍是 `sp=3/5`（督军/棋盘中心）或 `sp=2`（技能目标），**只需要放行事件**。

**修法（详见施工单 A·4）**：
① `PlaySignal` 在 `:23282` 与 `:23300` 之间加一条 `Trigger ∧ slot<0` 支（⛔ 别改 `IsHudAnchoredEvent`、⛔ 别删 `:23300`）；
② 新增 `HandCardViewOf(seat, cardId, instanceId)`（我方按 `_handViews[i].Inst.Id` / 手牌同下标；对手恒 `null`）；
③ `PlayPlacedOne` 的 `e.Slot<0` 降级加 `handAnchored` 前半句（对手侧退 18/19 手牌容器锚，**保留 140 那条给未指定目标的战术卡**）；
④（建议）手牌那一跳的事件带 `CardInstance.Id`（今天 `unit == null ⇒ InstanceId = 0`）。

## §三 B —— 关键证据（四跳）

1. **原版目标表按 logic 算一次**：`AbilityLogic__PlayAbility.c:262` `GetTargets(bm, abilityLogic.targetCriteria(+0x28), thisCard, 1, 0)` → 存 `abilityLogic+0x78` → `:273 PlayAnim(..., *puVar1, 0)`。
2. **`ta` 决定目标池**（`AbilityLogic__GetTargets.c` 逐档现读）：`0 any` `:889-905` = 场上**双方全部**单位；`10 allFiltered` `:975-996` = 按 `friendlyUnits/enemyUnits/include*` 筛的一组；`30 target`/`220` `:192-207` = 只读玩家点的那个；`maxTargets` 截断在 `:1171-1260`（默认 `random`，走**开局预烧的随机数组**）。
3. **`PlayAnim` 逐目标各播一份**：`AbilityLogic__PlayAnim.c:171-248` —— `sp/ep/pt 任一 == 2` ⇒ `目标表 == 0` 时 `LogError + 整段 return`；否则**逐目标** `AddCardAnim`（最后一个带 `waitAnimToApplyEffect`），并且**跳过躺在对手手里的目标**（`CardScript.IsInHand(item) && item.isPlayer == 0 ⇒ LogWarning + continue`）。
4. **我们这半边**：消费端已完整（`BattleDriver.cs:19740-19824`，`tgtList` 逐目标同刻入队、`beatTail`、`beatTgt*`）；生产端 `RuleCore.cs:15262-15276 AbilityTargetsFor` 只走**封闭文法 `EffectSpec.Target`** ⇒ **恒 ≤ 1**。数据列**已经在** `CardDef`（`CardDef.cs:2621 ActiveAbilityTargetCriteriaAt` → `CountSetSpec`），只是事件层不读它。三个发点：`RuleCore.cs:11695-11702` / `:12128-12138` / `:15507-15516`（最后一处的 `plan` 里**已经有 `ta`**：`:15468`，只是没往上递）。

**受影响（现读）**：`ability_anim_durations.json` 现读 **93 卡 / 160 拍**（旧口径「62 卡 / 99 拍」已过期，交接那句「62 张里 38 张」就是旧值）；其中 `sp/ep/pt==2` 的主动能力拍 = **55 卡 / 67 拍**；`ta` 能选 >1 的 = **12 拍 / 9 卡**；扣 `SW21`（`maxTargets=1`）⇒ **真多目标 = 11 拍 / 8 卡**（逐卡表 → 施工单 B·4）。

**修法（详见施工单 B·5）**：① 新增 `AbilityTargetListFromCriteria(ctx, owner, CountSetSpec, source, outList)`（`RuleCore.cs` **类尾**，只读、无副作用、random 走预烧数组）；② `AttachAbilityTargets` 加可选 `criteria` 形参（不给 = 今天那条单数路，零回归）；③ `ResolveActiveAbilityRows:15516` 把 `plan` 里那一行的 `ta` + `ActiveAbilityTargetCriteriaAt` 递进去。
⛔ **不要**照 `B99_R3a` 那条「`ResolveTarget` → `ResolveTargets`」：`B99_B1` 的三条反证（类型 / 副作用 / 映射不等价）本代理复核**全部成立**。

## §四 无判据项（⛔ 不许猜，必须调度台裁或另派）

| # | 缺口 | 为什么不能猜 |
|---|---|---|
| 1 | **多行 ability 的目标表怎么合并**成一条 `EvtKind.Ability` 的 `AbilityTargetList` | 原版是**每 logic 一次 `GetTargets` + 一次 `PlayAnim`**（`PlayAbility.c:262/273`，另有 `:1524-1531` 第二个调用点）；我们一条事件管整条 ability ⇒ 取第一行 / 并集 都没有判据 |
| 2 | **`ta=150 previousAbilityFiltered` 落在手牌**（`SW8`） | `BattleEventTarget` 只能表达「棋盘格」（`BattleEvent.cs:838` `Slot=-1` 那档消费端 `ViewAt` 拿不到） |
| 3 | **`PlayTraitPulse` / `PlayTraitParticles` 对手牌卡该不该演** | `BattleDriver.cs:24864/24972` 都按 `e.Slot` 早退；原版 `BattleCardUI.DisplayTriggerAnim` 在手牌卡上有没有对应 UI 面 —— **没查到** |
| 4 | **对手手牌的 2D 卡锚** | 原版是**那一张**手牌的 `cardUI+0x30`；我们只有卡背 `ImageQuad`（`_foeHandViews`），没有 `CardView` ⇒ 只能用容器锚近似（要打 `🔶 自己设计`） |

## §五 顺手发现（⛔ 本代理未改，交调度台分流）

1. 🔴 **旧报告的手牌陷阱名单有错**：`报告/B99_A1.md:44` 与 `交接_第九十九会话.md:86/162` 写的是
   `Jammed Communications / **Master Interromancer** / Cult Propaganda / Poisoned Supplies`。
   **现读 `cards_truth.json`：`Master Interromancer` 的 `abilities = [(0, None), (90, 50)]` ⇒ `abilityContext = 50`（墓地或在场），不是手牌** —— 它在场时 `Slot >= 0`，走格位那条路，**不属本族**。
   而严格扫出来的另外两张 **`Vengeance for Cadia`（90 / ctx 10）** 与 **`Avenging Zeal`（650 / ctx 10）** 反而**没被列进任何名单**。⇒ 账上那一条的卡名要订正（铁律 5）。
2. 🔴 **事件 `InstanceId` 在两处手牌跳恒 0**：`EffectResolver.cs:8362`（`EmitCardTrigger`）与 `:8606`（`EmitTurnTriggerRaw`）都写 `unit != null ? unit.InstanceId : 0`；而 `EmitHandAbilityTrigger`（`:18860`）会带 `inst.Id`。⇒ **同一个「手牌触发」概念，两条发射口的身份完整度不一样**。表现层要指名到「哪一张」时（同名两张）会取错。
3. ⚠️ **「62 张里 38 张」是过期口径**：现读 `ability_anim_durations.json` = **93 卡 / 160 拍**（`A2` 2026-10-30 更新）；对应「有 `sp/ep/pt==2`」= **55 卡**，不是 38。引用这一句的账/交接要不要刷新，请调度台判。
4. 🔴 **结算侧的 `ta=10 / ta=0` 也不完整**：`EffectResolver.cs:1680-1682` 的注释自认「`10 allFiltered` / `0 any` … 我们这一列**没落那些位** ⇒ 拿不准，宁可不改」。
   ⇒ **即使 B 的表现侧修好，结算侧仍可能是「己方全体」近似**。两者要一起核、同一笔账，⛔ 别只做表现层就宣布这条复刻完。
5. ⚠️ **`TurnEnd` 手牌陷阱只覆盖「行动方手牌」**（`EffectResolver.cs:8693` + `:8697-8704`）。今天两层口径一致（`SplitAtTurn` 只认 `you` 视角）⇒ **不是缺口**；但「`each turn` 的手牌陷阱」出现时，发射层与结算层要**一起**改（已有账，本代理仅复述）。
6. ℹ️ `EmitTrapDrawnInsteadOfCardDrawn`（`EffectResolver.cs:16787-16812`）那条 250 `ThisCardDrawnAsTrap` 也发 `EvtKind.Trigger` + `unit = null` ⇒ **`Slot = -1`、同样被 `:23300` 吃掉**。池内 `trigger 250` 的 ability = 0 条（同一段注释自认）⇒ 今天零可观测，但**修 A 的时候它自动一起修好**（同一个分支），如实记在设计里。
