## 0. 一句话

**是 (β) 实现缺陷，不是断言过期。** `B111_R1WB` 加的那句「**字段优先**」（`DeckRules.DeckArmy` 版首）把**原版不变量**盖住了：
原版 **有督军 ⇒ `deckArmy` 恒 == 督军阵营**（`CardDeck__DeckBasicSetup.c` 无条件写），而我们的**一批入口绕过写点直接写 `WarlordId`**
（`DeckLibrary.Create(...)` 之后逐格赋值、自检夹具、旧存档反序列化）⇒ 那些卡组的字段停在 `"Neutral"`（或旧值），字段优先一挡，
读口就返回 `null`/错值 ⇒ `Validate` / `RemoveInvalidCards` / `ArmyFaction` 全塌 ⇒ 25 条红（外加一整串下游）。

修法 = **在读口复原原版不变量**（不是新语义、不是放宽断言），并顺手修掉一个**必炸但本轮还没炸**的持久化缺陷（见 §3）。

## 1. 根因链（证据）

### 1.1 主因：字段优先压住了「有督军 ⇒ deckArmy == 督军阵营」

| 环节 | 证据 |

| 原版不变量 | `d:/2/tools/decomp_full/CardDeck__DeckBasicSetup.c:29-40` —— `uVar2 = hero == null ? 0 : *(int*)(hero + 0x2c);` 然后 **无条件** `*(int*)(deck + 0x50) = uVar2;`（0 = `CardArmy.Neutral`） |

### 1.2 副因（**本轮没直接炸，但必炸**）：`JsonUtility` 把 `null` 字符串写成 `""`

- 证据：`d:/4/_tmp_view/menu/_menu_test_decks.json` 里 `"WarcryId": ""`、`"DeckId": ""` —— 这两个字段在内存里**从未被赋过值**（`DeckLibrary.Create` 只传 5 个实参），只能是 `JsonUtility.ToJson` 把 `null` 写成了空串。
- 后果链：旧存档缺 `DeckArmy` 键 ⇒ `DeckStore.Parse` 给 `null` ⇒ 任何一次 `lib.Save()` 落盘后**变成 `""`** ⇒ 下次读档 `deck.DeckArmy != null` 为真、`IsNeutralFaction("")` 为假 ⇒ 读口返回 `""` ⇒ `Validate` 拿 `""` 去 `SameFaction` ⇒ **玩家整库卡组全判 `WrongFaction`**（静默、且重启才现形）。
- 这条本轮日志里没有直接对应条目（测试夹具用 `_tmp_view/menu/_menu_test_decks.json`、每次开头删文件），但它是确定性的 ⇒ 一并修掉。

### 1.3 为什么这是 (β) 不是 (α)

派单里点名的两条旧断言（`B105_W4` B2「有督军 ⇒ 督军阵营」、`B107_W14` N120③）我逐条回源核过：

- **`B105_W4` B2/B3 的期望值是对的**（原版 `AddHero` / `DeckBasicSetup` 都是 `deckArmy = hero.cardArmy`）⇒ 新实现让它变 null 就是实现缺陷。
- **`B105_W4` B4/B5** 期望「没督军但卡表非空 ⇒ 卡表第 0 张」—— 这也是原版可达态（`AddCard` 的 `CardCount(hero:1)==0` 那一支）；出错的只是**夹具的造法**（构造器已经把字段写成 Neutral）。
- **`B107_W14` N120①/②/③** 是「读口 = 当前内容派生」这条旧前提；字段化后 ① ② 仍能靠字段值蒙对，③（清空到 0 张）就露馅了 —— 那一格由**原版 `RemoveCard` 的不变量**（`count(hero:1)==0 ⇒ Neutral`）补回来，不是放宽。

⇒ 全部按**修实现**处理，没有放宽任何一条断言。
