逐项说明「有判据 / 无判据」：
- `id` = `Trophy_1..13`：**有判据**（本地化 key 就是这个名字，26 条词条实测）。
- `title.mTerm`：**有判据**（同上）。
- `description.mTerm`：🔴 **无独立词条** ⇒ 只能借用 `Default_Trophy` 的描述（或留空）。**写清：本地无判据**。
- `challenge.$type = GamesPlayed` + `army`：**有判据**（`GamesPlayed.cs` 有 `army` 字段且 `override Army`；`AllianceTrophy.IsHidden` 会读 `challenge.Army` 去问 `FeatureConfig.IsArmyHidden`，见 `AllianceTrophy__get_IsHidden.c`）。
- `challenge.id` = `Daily_XX_1`：**有词条判据**（13 条阵营词条），但**是不是原版用的 id 无字段判据**（服务端数据）。
- `challengeType = 2 (MilestonesBased)`：**有枚举判据**（`ChallengeType` 只有 `DifficultyBased=1 / MilestonesBased=2 / DailyLogin=4`，见 `dump.cs:59791-59798`；奖杯是里程碑制 ⇒ 2）。
- `reachMilestoneWhen = 10 (HigherOrEqual)`：**弱判据**（枚举只有 `EqualTo=0 / HigherOrEqual=10 / LowerOrEqual=20`；奖杯算法自己按 `targetValue <= 当前值` 数，不读这一格）。
- `rewards[].targetValue`（10/25/50 之类）：🔴 **无判据**（服务端数据，关服）⇒ 标 `🔶 自己设计`。
- `reward`（badge id）：**硬判据**（badge SO 的 `cardArmy`，见 6·3 表）。⚠️ 但**运行时能不能解析**未验：`AllianceBadgeAssetProvider__GetAssets.c` 是 `SingletonBehaviour.Instance` 的某个列表 `OfType<AllianceBadge>()`（很可能是**库存里已拥有**的徽章），不一定是全量 SO 表 ⇒ **建议第一版先给 `reward: null`（`Default_Trophy` 就是这样）、确认 13 条能列出来之后，再逐条把 badge 填上并实机验**。
- `cardArmy`（继承自 `ObtainableItem`）：**有判据**（同上表）。

⚠️ 两条红线：
1. **id ↔ 阵营的映射**只能按标题语义走，**必须在账里写「无字段级判据」**（`🔶` 或「软判据」）。建议顺序与参考阵营列表一致（UM / BL / GOFF / LEV / SAU / SH / SOR / TAU / GSC / AM / DA / EC / SW）。
