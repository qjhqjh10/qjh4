## ② 两件逐条

### 件 1 · `Shell/CardTierConfig.cs` 的 `GetTierInfo` 不出声

#### 原版判据（本轮现读，不是复述旧结论）

- `d:/2/tools/decomp_full/Everguild.LiveOps.Config.CardTierConfig__GetTierInfo.c:32-38`：
  两条 `System_Linq_Enumerable__FirstOrDefault`，**查不到 = 返回 `FirstOrDefault` 的 default（null）**——
  **这个方法自己不会抛异常**。
- `d:/2/tools/decomp_full/Everguild.LiveOps.Config.CardTierConfig__GetTotalPlayerXPFromInventory.c:82-86`：
  调用方拿到 null 后 `if (lVar8 == 0) { FUN_1803f47a0(); }`，函数注释为 `WARNING: Subroutine does not return`。
- 交叉确认「`FUN_1803f47a0` = 抛 NRE」：`d:/2/tools/cpp2il/out_cpp2il_dev_ilspy/Everguild.LiveOps.Config/CardTierConfig.cs:463-469`
  `if (tierInfo != null) { … } else { throw new NullReferenceException(); }`。
  ⇒ **「原版抛 NRE」这件事发生在【调用方】，不在 `GetTierInfo` 里** —— 文件头与 `GetTierInfo` 的 doc 原来把主语写混了，已就地订正。
- `GetNextTierInfo.c:6` = `GetTierInfo(this, currentTier + 1, rarity)` ⇒ **满级那一跳本身是正常路径**（拿 null、不崩）。

#### 改前

```csharp
public CardTierInfo GetTierInfo(int tier, string rarity)
{
    var group = FindGroup(rarity);
    if (group == null || group.TierInfo == null) return null;   // ← 静默
    for (...) { if (t != null && t.CardTier == tier) return t; }
    return null;                                                // ← 静默
}
```

doc（`:293-294`）却写着「…**我们出声** + null，调用方自己判」。**doc 与实现不符**，而「不许静默失败」是本项目铁律。

#### 改后（`Shell/CardTierConfig.cs:304-341`）

- `group == null` ⇒ `WarnOnce("no-group:<rarity>", …)` 再返回 null；
- `group.TierInfo == null / Count == 0` ⇒ `WarnOnce("no-tiers:<rarity>", …)` 再返回 null；
- 遍历时**顺便记 `maxTier`**；找不到时：
  - `tier > maxTier` ⇒ **静默返回 null**（= 满级没有下一档，`GetNextTierInfo(MaxLevel)` 天天走）；
  - 否则（`tier < 1` 或有效区间缺格）⇒ `WarnOnce("bad-tier:" / "no-tier:<rarity>:<tier>", …)` 再返回 null。

**为什么这样分两档**（而不是「查不到一律出声」）：
`GetNextTierInfo(MaxLevel, rarity)` 在升级面板里**对每张满级卡都会调**；若一律出声，会刷出「档位 5 缺失」这种**假警报**——
原版那里也是正常返回 null。真正需要报警的是**结构性缺失**（稀有度不在配置里、组为空、有效档位缺格、1 基下越下界），
这几类每次都去重成一行（`WarnOnce`，键 = 稀有度(+档位)）。

#### 连带改动

- `GetTotalPlayerXPFromInventory`（`:386-391`）原来在 `info == null` 时**自己再 `WarnOnce("missing-tier:…")` 一次** ⇒
  同一次缺格会与 `GetTierInfo` 内部那条**刷两行**，而且「两处写同一条规则 = 迟早不一致」。
  现在改成 `if (info == null) continue;` + 注释指向 `GetTierInfo`（跳过该格 = 该格 XP 按 0 算）。
- `WarnOnce` 加一个 `static int _warnEmitted` 计数器 + `static int WarnEmittedCount` 只读口（给 `SelfCheck` 断言用）。

#### 新增断言（`CardTierConfig.SelfCheck()` §④，`:508-534`）

1. **未知稀有度 ⇒ null**：用 `Guid` 造一个随机稀有度连查 **3 次**，三次都必须 null；
2. **出声只一次**：第 1 次 `WarnEmittedCount` **+1**，第 2、3 次 **+0**（`WarnOnce` 去重失效就红）；
3. **满级正常路径静默**：`GetTierInfo(MaxLevel+1, "epic")` 与 `GetNextTierInfo(MaxLevel, "epic")` 都返回 null，
   且 `WarnEmittedCount` **一点不变**（谁把「越上界」也做成出声 ⇒ 红）；
4. **`tier = 0`（1 基越下界）⇒ null**。

> 设计点：随机稀有度是**每次自检都是新键** ⇒ 断言不受上一次 `SelfCheck()` 的全局去重影响（否则第二遍会假红）。
> ⚠️ 这条断言会**故意打出 1 条 `LogWarning`**（未知稀有度那条）+ 1 条（`tier=0` 那条）—— 属预期，不是缺陷。
