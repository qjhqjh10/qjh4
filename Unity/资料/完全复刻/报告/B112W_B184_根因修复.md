## 二、encode 发生在哪一步（代码行 + 为什么）

**结论：在 `ReadableCopy` 的 GPU 回读里**（`EffectExporter.cs:4594-4616`），改前的原文是：

```csharp
        var rt = RenderTexture.GetTemporary(src.width, src.height, 0,
            RenderTextureFormat.ARGB32, RenderTextureReadWrite.sRGB);      // ← 4605-4606，写死 sRGB
        Graphics.Blit(src, rt);
        …
        var readable = new Texture2D(src.width, src.height, TextureFormat.RGBA32, false);  // ← 4610，sRGB 目标
        readable.ReadPixels(new Rect(0, 0, src.width, src.height), 0, 0);
```

**机制**：回读的 `RenderTexture` 被写死成 sRGB 色域，于是 `Blit` 这一次往返**对源贴图做了「采样时解码 +
写入时编码」**：

- 源是 **sRGB 颜色图** ⇒ 采样**解码**、写入**编码**，两次抵消 ⇒ **字节原样回来**（这正是 459 张判 `EXACT` 的原因；
  其中相当一部分差 ≤1/255，就是这一次往返的量化）。
- 源是**线性数据图**（原版序列化 `m_ColorSpace: 0`：法线 / 遮罩 / Noise）⇒ 采样**不解码**、写入**照编一次**
  ⇒ 落盘的是 `sRGB_encode(原版)` ❌ —— **这就是那 22 张**。

（Linear 工程下这一段真的会转换；Gamma 工程下整条链不转换 ⇒ 两边只会错在一边 —— 这批图是 **Linear 下导的**，
见下面的时间线。）

### 证据链（四条，可复算）

1. **22/22** 判 `ENCODE` 的图，其原版 AssetRipper 导出工程的 `.meta` **全部是 `sRGBTexture: 0`**
   （`RippleSubtle` / `Noise Combined` / `EarthCrackNormal` / `MuzzleFlash_*` / `SplatNormal` …）。
   复算脚本 → `_tmp_view/b184_交叉验证.txt` / `_tmp_view/b184_srgb0清单.txt`。
2. **交叉表（484 张 × 判定 × 原版 sRGB）**：

   | 判定 | 原版 `sRGBTexture: 0`（线性数据） | `: 1`（颜色图） | 找不到原版 meta |
   |---|---|---|---|
   | `ENCODE` | **22** | **0** | 0 |
   | `EXACT` | 15 | **398** | 46 |
   | `OTHER` | 1（`NoiseNRM`） | 2 | 0 |

   ⇒ **没有一张「原版是颜色图」的被编码**；被编码的 22 张**全是**线性数据图。
3. **反证（决定性）**：`NoiseNRM` 同样是 `sRGBTexture: 0`，**却没被编码**（普查判 `OTHER`，直接比 5.43、encode 比 35.86）。
   它之所以没中招 —— 它**可读**，走的是 `ReadableCopy:4603` 的「直接 return src」那条路。
   ⇒ 中招条件 = **「不可读（走 GPU 回读）」 ∧ 「源是线性数据贴图」**，正好把这个坑钉在 `:4605-4606` 那一行。
4. **时间线**：这 484 张的 mtime 是 **2026-10-31 03:26 ~ 09:24**；工程切 Gamma 是 **2026-11-01 09:48**
   （`ProjectSettings.asset:50` 现读 `m_ActiveColorSpace: 0`；判据 `报告/B167_色彩空间切Gamma.md` §一 记录执行前是 `1`）。
   ⇒ **这批 PNG 是在 Linear 工程里导出来的**，与机制自洽。

### 🔴 关于普查 §五 的修法 —— 必须先订正再施工

普查 §五 给的是「`p_new = linearize(p_old)` **＋** `.meta sRGBTexture: 1→0`」。**这套只在 Linear 工程下成立**：

| 工程色彩空间 | 原版 PNG 字节 `orig` + meta 0 | 普查 §五（linearize + meta 0） |
|---|---|---|
| Linear | 解码一次 ⇒ `orig` ✅ | 解码一次 ⇒ `orig` ✅ |
| **Gamma（现在）** | 不解码 ⇒ `orig` ✅ | 不解码 ⇒ **`linear(orig)` ⇒ 偏暗** ❌ |

也就是说：**如果照 §五 手工 linearize，这 22 张在现在的 Gamma 工程里会变成「偏暗」**（只是反过来错）。
正确的目标是「**让落盘字节 = 原版落盘字节**，`.meta` 照原版 `m_ColorSpace`」—— 这正是本单改生成链路做的事，
而且它对 Linear / Gamma **两态都成立**（见 §三 的推导）。⛔ **建议把 §五 那两行就地订正**（我按白名单没改判据文件）。

### ⑤ 新增判定方法 `SrcIsSrgb`（`:5294`，追加在 `Flatten` 之后、类尾 `}` 之前）

```csharp
    static bool SrcIsSrgb(Texture2D t)
    {
        if (t == null) return true;
        try { return t.isDataSRGB; } catch { }
        try
        {
            var gf = t.graphicsFormat;
            if (gf != UnityEngine.Experimental.Rendering.GraphicsFormat.None)
                return UnityEngine.Experimental.Rendering.GraphicsFormatUtility.IsSRGBFormat(gf);
        }
        catch { }
        return true;
    }
```

判据来源：`Texture.isDataSRGB`（Unity 本机 `UnityEngine.CoreModule.xml:57419`：「Returns true if the texture pixel
data is in sRGB color space」）—— 对 bundle 载入的 `Texture2D` 即原版序列化的 `m_ColorSpace`；
读不到时退回 `GraphicsFormat` 的 `_SRGB` 位（`GraphicsFormatUtility.IsSRGBFormat`，同 XML `:13025`）。
**判断不了一律返回 `true`** = 保持加这个判定之前的行为，⛔ 绝不静默改掉已经正确的 459 张。
完整论证写在 `:5268-5293` 的注释块里（就在方法上方）。

### 为什么「下次重跑导出器，这 22 张会自动变成正确字节」

对一张**不可读 + 线性数据**的源贴图逐跳推：

| 跳 | 改前 | 改后 |
|---|---|---|
| 采样 | 源非 sRGB ⇒ 不解码，得原值 `v` | 同（源本身没变） |
| 写入 RT | RT=sRGB ⇒ 存 `encode(v)` ❌ | RT=**Linear** ⇒ 存 `v` ✅ |
| `ReadPixels` → `readable` | 目标是 sRGB 纹理 | 目标是 **linear** 纹理（`linear: true`） |
| `EncodeToPNG` | 写 `encode(v)` | 写 `v` |

⇒ 落盘字节 = **原版 `Texture2D` 的落盘字节**。对 **sRGB 颜色图**则三处判定都返回 `true` ⇒ 走的是**改前逐字相同的代码**，
⇒ 459 张的字节**一个都不会变**。Gamma / Linear 两态下这条推导都成立（Gamma 下整链不转换，两态字节都等于 `v`）。

**自检口径（重跑后照这个判）**：

1. `grep -L "sRGBTexture: 0"` 在这 24 张上应**全部命中 0**（22 + `NoiseNRM` + `Large_Monolith_Mask_sprite`）；
   其余 460 张仍是 `: 1`（**若变成 484 张全 0，见 §六 的回滚指令**）。
2. 用普查同一套判据复算：这 22 行应从 `ENCODE` 变 `EXACT`（直接比 RGB MAE ≤1/255，**必须保留 alpha 掩码**）。
3. `.meta` 的 `guid` 不变 ⇒ prefab / 材质引用不断，不需要动 `.mat` / `.prefab`。
