## §二 缺的是哪一跳（改前的四个断点，按数据流从上游到下游）

1. **数据列缺**：`cards_engine.json` 没有 `enchantment` 列（per-ability：`trigger` / `buffType` / 模板 `uniqueId`），
   `CardDef` 也没有对应字段 ⇒ Core 侧**无从知道**「这张卡的哪条 ability 会挂哪张模板」。
   真值在 `cards_truth.json` 的 `abilities[].logic[].buff.enchantment.m_PathID`
   —— 本笔现读（去重后）：**130 行 / 114 张挂载者**，其中**可玩池内 63 张**；
   按 `buffType ∈ {12,15,16}`（附魔三档）筛 = **115 行 / 102 张**，可玩池内 **54 张**。
   ⚠️ 已有另一份**窄口径**判据：`判据/effectText链_判定.md` §二 列了 **38 行 / 31 张（全在池）**，
   那是「`effectText` 非空」的那一族（其中 **29/38** 带附魔 PPtr）——**与本条的 130 行不是同一个分母**，别混用。
2. **反向索引被丢掉**：`enchantment_templates.json` 每张模板**已经带** `owners[]`（`{id, buffType, trigger, inPool}`），
   但 `Data/CardDatabase.LoadEnchantmentTemplates()` 物化时只造 `List<CardDef>`，**把 `owners` 丢了**
   ⇒ Core 拿不到「谁挂我」。（`Data/CardDatabase.cs:3656-3705`）
3. **没有通用的「挂载端」入口**：`Enchantment.Attach` 是**低层**写表口，但「谁该在什么时候调它」只有
   `AttachPray` / `AttachDA42...` 两条**硬编码链**，没有「按来源卡 → 模板」的通用入口。
4. **没有接线点**：`EffectResolver.PlayTacticCore` 在 `BroadcastWhen(Play)` 之后**只有**
   `Enchantments.OnCarrierPlayed(...)`（DA42 专用），没有「这张牌自己的 buffType 12/15 附魔 → 挂到目标」。

**⇒ 修的方向**：1 + 2 是**数据侧**（生成器 + `CardDef` + `CardDatabase`），3 + 4 是**Core 侧**。
本笔只能动 3 + 4（`Enchantment.cs` / `EffectResolver.cs` / `RuleCore.cs` 的所有权）⇒ 用 **id 白名单**顶住 1+2 的缺口，
把 3+4 做成**通用形状**（见 §三），数据列一落地就只换「查表来源」、不动调用点。

### 3·4 为什么「模板取不到」是**静默**的（⛔ 不是偷懒）

`ruleprobe` 只编 `Core/*.cs` ⇒ `BattleContext.EnchantmentTemplatesProvider` 为 `null`；
而 `ctx.Log` 会进 `ctx.Events`、`ctx.Events` 进 `Fingerprint`（`Core/BattleContext.cs:1855-1858`）
⇒ 在「模板取不到」那条路上出声，会让 `play all dump` / `play check` 的**指纹整片变化**。
所以：**只在真挂上时出声**（`Attach` 体内那几条日志，`ruleprobe` 走不到），
「**没挂上**」这件事由**断言**钉（§四 的 G2 正例 + G3 灭自证）。这条取舍与本工程红线
（「不许静默失败」）的调和方式：**失败可观察 = 断言红**，不是「日志刷屏」。

✅ **推论（给同步点用）**：`ruleprobe` 里 `EnchantmentTemplates` 恒 `null` ⇒ 新加的这句**什么都不做、也不写日志**
⇒ `play all dump` / `play check` 的**指纹应当零变化**（本代理⛔ 不跑 ruleprobe，这一句是**推理**，请调度台在同步点复跑确认）。
