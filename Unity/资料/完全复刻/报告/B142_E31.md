### 1.3 🔴 为什么**不是** `ViewportClip`（施工单写的是它，但那条在这棵树上不成立）

施工单 / 派活单说「照 `SettingsWindow` 的既有先例补 `ViewportClip`」。**那条先例在另一个渲染档里**：

1. `Shell/SettingsWindow.cs` 是 **`MenuDraw` 世界档** —— 件由 `MenuDraw.Rect/Text/Hit/Nine` 建，而**裁切状态只在那几路里被解析**
   （`ViewportClip.Resolve` 的唯一入口，见 `Shell/ViewportClip.cs` 文件头第①节）。
2. `Battle/SettingsPanel.cs` 是 **uGUI 子画布档**（`HudCanvas.EnsureSubCanvas` + `HudCanvas.MakeSlicedPiece`，件是 `UnityEngine.UI.Image`）。
   **`Battle/` 整目录对 `ViewportClip` 的引用数 = 0**（现扫 `grep -rn "ViewportClip" Battle/`：只有 `MultiCardDisplay` / `UnitChatPanel` 的注释提到那个**概念**，没有一处调用）。
   ⇒ 在这里挂 `ViewportClip` = **挂了个不生效的组件**（比不挂更糟：下一个人会以为裁了）。
3. 本工程 **uGUI 档的裁切先例**是 `RectMask2D`（`Battle/UnitChatPanel.PartB118W3.cs:42`：`maskGo.AddComponent<RectMask2D>()  // padding 0 / softness 0 = 原版硬边`）。
4. 🔴 **还有个坑**：本文件的 `Node()` 建的节点 `sizeDelta` **恒为 (0,0)**（`:769-777`）。**光挂 `RectMask2D` 不量框 ⇒ 掩码把整棵子树裁没**
   （画面全黑、零报错）⇒ 必须**同批** `HudCanvas.SetPxSize`。这一条已写进断言 A3。
