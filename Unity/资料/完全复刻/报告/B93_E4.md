## 件 2（`read_il2cpp_string.py`）

新增 `d:/4/Unity/工具/read_il2cpp_string.py`（约 330 行，**纯只读**）；
说明文档 `d:/4/Unity/资料/工具/read_il2cpp_string.md`（**只此一处**，没往 `资料/命令速查.md` 写第二份）。

### 用法

```bash
python -I -X utf8 d:/4/Unity/工具/read_il2cpp_string.py DAT_1842baac0 0x184271c70   # 解令牌
python -I -X utf8 d:/4/Unity/工具/read_il2cpp_string.py --search 'line="{2}"'       # 反查（表→槽 VA）
python -I -X utf8 d:/4/Unity/工具/read_il2cpp_string.py --selftest                  # 5 条已知真值 + 2 条反例
```

`-h` ⇒ 用法、退出 0；**不带参数 ⇒ 只打用法、退出 2**（⛔ 不做任何动作）。退出码 `0/1/2` = 全解出 / 有解不出 / 用法错。

**原理三步**：`VA − 0x180000000` 按 PE 节表 → 读 8 字节槽值 → `type = v>>29`（5 = StringLiteral）、
`idx = v & 0x1FFFFFFF` → 🔴 **`entry = idx >> 1`** → `global-metadata.dat` 的 string literal 表
`{uint32 length; uint32 dataIndex}` → 字符串（不 NUL 结尾）。

### 解出的样例（B92_N4 §5 那 5 个「缺口」全部解出）

| 令牌 | 解出 | 你怎么核对它对 |
|---|---|---|
| `DAT_1842baac0` | `"\n"` | ILSpy `SceneInitializer.GetUnityFormatStacktrace` 体里就是 `stackTrace.Split("\n")` |
| `DAT_184271c70` | `"Assets\"` | 同上：`.Contains("Assets\\")` / `.IndexOf("Assets\\")` |
| `DAT_1842c7cf8` | `":"` | 同上：`text4.Split(":")`；且模板里 `{3}:{4}` 正好是这两段 |
| `DAT_184238728` | `" in "` | 同上：`.Split(" in ")`；模板 `{0} in …` 与它语义自洽 |
| `DAT_184268c80` | `'{0} in <a href="{1}" line="{2}">{3}:{4}</a>'` | 同上：`String.Format(template, object[5])`，5 个占位符 ↔ `.c` 里 `object[5]` 五次赋值 |

**三重旁证**（不是我“觉得像”）：

1. **同族方法**：5 条与 ILSpy 同一个方法体里的字面量**逐字相同**（上表）。
2. **全库对照实验**：把 `.c` 里所有 `DAT_1842xxxxx` 按两种解各解一遍，拿 ILSpy 方法体的字面量集合当判据 ——
   `entry = idx` 命中 **2 条 / 2 个方法**；`entry = idx >> 1` 命中 **3271 条 / 1500 个方法**（扫 6767 个方法）。
   不移位解出来的是**别的函数**的字符串（`'Fulah'` / `'Cheerful'` —— 表里真有这些词，所以「解出来是像样的英文」**不等于**解对了）。
3. **官方本地化表**：解出的字符串直接命中 `数据/游戏数据/官方本地化_en+zh-CN.json` 的键，且落在**同名方法**里，例如
   `AccountTab__InactivateAccount.c` 的 `MainMenu/Settings/ButtonLabel/DeleteAccount`（zh = 删除账户）、
   `AccountTab__Register.c` 的 `PlayfabErrors/InvalidPassword`（zh = 无效的密码）。
4. 顺手量到的规模：`.data` 里 **26,507 个 type=5 槽**，覆盖 **26,507 个不同字面量**（表共 26,514 条）⇒
   **「原版方法里有个字符串我不知道」这类问题，本地现在解得开**。

### 还解不出什么（如实写）

1. **`type != 5` 的槽本工具不碰**（TypeInfo 1 / Il2CppType 2 / MethodDef 3 / FieldInfo 4 / MethodRef 6）——
   要解名字得再解 `typeDefinitions` / `methodDefs` 那几张表，**索引是否也要移位未考证**。工具会如实打
   「⛔ 不是字符串字面量（type=3 MethodDef）」并计入退出码 1（实测 `DAT_1842a6bb0` / `DAT_184296af0` 就是 type=1）。
2. **`entry = idx >> 1` 的机制没考证**，只知道「本 build 实测如此 + 3271 条命中支撑」。
   ⛔ 别写成「il2cpp 就是这样」；**换 build 先跑 `--selftest`**，红了就重新做那张对照表。
