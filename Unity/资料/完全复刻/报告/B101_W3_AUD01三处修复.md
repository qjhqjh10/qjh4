## §五 没查清 / 顺手发现（**只报不改**）

1. 🔴 **`Highlight` 的布局框高度本来就是错的（prefab 实算 vs 我们的常量差 2.67 px）—— 本批按简报「布局不动」未修。**
   prefab 五元组实读（`Highlight`：锚 stretch · `m_SizeDelta = (3.3384, 1.8547)` · `m_AnchoredPosition = (1.6692, 2.6)` · `pivot (0.5,0.5)`；
   父 `Image Container` = 98.877 × 65.694）⇒ 布局框 **102.215 × 67.549**，即 `y[8.343, 75.891]`。
   我们的 `(av.x1, av.y1−3.53, av.x2+3.34, av.y2−36.37)` = **102.21 × 70.22**，即 `y[8.34, 78.56]` ⇒ **底边低 2.67 px**
   （×1.9 后拉开到 **5.07 px**）。
   ⚠️ **普查报告 §2·1 那张表写的 `y[8.34,79.24]`（70.90 高）与 prefab 实算也不符** —— 三种说法（67.55 / 70.22 / 70.90）里
   **只有 67.55 是能从序列化字段直接算出来的**。建议下一波把这一格按五元组重算后一次性改掉（同时改普查表）。
   `Border` / `Image` 两格**逐位吻合**（18.44..84.13 / 9.17..74.86 都对），所以这不是「整族口径不同」，是**这一格单独的旧错**。
2. ✅ **普查 §五「没查清 ②」已查清：成员行的 `Highlight` 是开着的。**
   3 个 `Alliance Member Entry` 实例的 `Highlight` 上那颗 **uGUI `Image` 组件 `m_Enabled = 1`**（`m_Sprite` 非空）；
   `Border` 的 `m_Enabled = 1`；`Image`（立绘）那颗 **`m_Enabled = 0` 且 `m_Sprite = m_PathID 0`**
   ⇒ 正是 `set_enabled(img, sprite != null)` 那条**运行期灌图**的口（`:660` 已有记）。
   ⇒ **「成员行的 Highlight 该建、该画」成立**，本批不需要降级。
   （⚠️ 与 `Alliance Panel` 那份不同 —— 那一份 `Highlight` 是 `m_Enabled = 0`，是**另一个实例**、不冲突。）
3. 🟡 **放大后的「相邻行重叠谁压谁」仍未评估**（`E18` 留的那条账，普查 §五 ③）：成员行现在立绘会**戳出 `Avatar Item Small`**
   （197.75 宽 vs 容器 98.87 ⇒ 每侧溢出 **49.4 px**），相邻两列成员格的内容会**真重叠**。原版靠 uGUI 兄弟序，
   我们靠「到相机的距离」⇒ 需要队列档的人接一次。本代理不动队列。
4. 🟡 **`Done Highlight` 的 `Image.m_Color = (1, 0.5672, 0.1098, 1)`（橙金）仍未落实**（普查 §2·5 第一行）：
   `:2477` 走 `FX_Square_UI_SDF`，最终 tint 由 `UIEffectTogglerImage` 的淡入淡出两段合起来决定，**静态读不出** ⇒ 本批没动。

   它是「要不要补取决于真机看页头亮不亮」的候选，本批不在范围内。
