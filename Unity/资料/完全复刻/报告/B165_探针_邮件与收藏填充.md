#### 1·2 「20 个 provider 的 `config` 全是 null」的**第二个根因**（本次新查出）

| 项 | 内容 |
| --- | --- |
| 旧读法 | `ProbeUtil.GetMember(v, "config")` → 先 `GetField` 再 `GetProperty`（两者都只在**调用方的类型**上找；基类的非公共成员拿不到） |
| 为什么恒 null | `ConfigProvider<T>.config` 是 **`protected` 字段**（`dump.cs:135132` 段，偏移 0x0），Il2CppInterop 把字段代理成**同名属性**（实测 `PropertyMap`：`Il2CppEverguild.LiveOps.Config.ConfigProvider`1` 有 `config` / `Key` / `Config` / `ConfigType`）。**非公共属性声明在泛型基类上** ⇒ 在具体的 provider 类型上调 `Type.GetProperty` **拿不到**（继承来的非公共成员不返回）。这正是「providers 还没修就已经 config=null」的原因。 |
| 新读法 | `ConfigOf(provider)`：① `ProbeUtil.GetMemberDeep(provider, "config")`（**新加的沿基类链查找**）→ ② 兜底 `GetMemberDeep(provider, "Config")`（公共属性，语义 = `get_Config => config`） |
| 输出增强 | `DumpChildProviders` 现在逐条打 `name<Type> key=… (config=Type/null)`，并给尾标 `configNonNull=N/总数`；`DumpStaticConfigs` 同样给 `configNonNull=N` |

> ⚠️ **对任务描述的一处订正（铁律 5）**：任务里把「`Configs` 全 `config=null`」归因于 providers 那个 `InvalidCastException`。
> **不成立** —— `DumpStaticConfigs()` 与 `DumpChildProviders()` 是两条互不调用的路径（各自 try/catch），
> 强转失败不会让静态表的 `config` 变 null。真因是上面这条**反射拿不到基类 protected 属性**。

## ④ 没查清 / 卡住

1. **三件都没有实机验证**（本轮明确禁止启动游戏）—— 全部只有「编译 0 错误 + 静态判据」。
   **唯一能在下轮开机时立刻证伪的两点**：
   - `hooks_installed.tsv` 里 `collectionfill:CardCollectionTab.ToFocus` / `inbox:*` 是不是 `OK`；
   - `inbox.tsv` 里 `MakeContainer.OUT` 那一行 `result=NULL` 是否出现在**第一条**消息上。
2. **`ContainerBuilder<MessageContainer>` 能不能 `MakeGenericType` + Harmony patch** —— ⛔ 未实测。
   已知风险两条：① Il2CppInterop 对**静态泛型类**的代理可能不允许 `MakeGenericType`；② 即便闭类型能建出来，Harmony 对**共享泛型代码**的 patch 也可能报 FAIL。
   **两种失败都只影响这一条 hook**，`MessageList.Initialize` 那条照样给证据。
3. **「`config` 修完就非 null」仍取决于 titleData 里真有那 20 个键** —— 这是数据侧的事，⛔ 本轮没跑，不能保证。
   本轮只保证**读取路径**不再必然 null（`configNonNull=N` 会直接告诉我们 N 是多少）。
4. **收藏 10 秒空白的根因没定位** —— 本探针只给「每次重试时 `GetItemCount()` / `cells.Count` 怎么变」。
   还没查的是：`RecyclableScrollRect.ReloadData` 那一跳到底卡在哪（是 `SetCell` 建卡慢、还是图集/异画懒加载、还是 `CardArt.Get` 的同步加载）。**要等 TSV 里 `itemCount` 从 `-1/0` 变正的时间点**才能继续切。
5. **`MessageList.Initialize` 的 NRE 到底是「第一条 `MakeContainer` 返回 null」还是别的** —— 任务描述是这么说的，但本轮没法证。
   探针会把 `MakeContainer.OUT result=NULL` 与 `MessageList.Initialize` 的消息条数并排打出来，**下一轮看两行就能定**。
6. **`closeButton.onClick` 的监听器数可能读不出** —— `m_Calls` 是 `UnityEventBase` 的**非公共**属性名，Il2CppInterop 是否真的把它代理成属性，只能在运行期确认；读不到时该字段打 `?`（⛔ 不抛、不影响其它两行）。
