## ② `B-177`：卡级 `cardTargetCriteria` 的 36 格（**数据 + 载体已落；点选路未碰**）

### 落法（键名 + 形状 + 样例）

**新列 = 卡表顶层 `cardTargetCriteriaSet`（每张卡**一个对象**，不是行数组）**

```json
"cardTargetCriteriaSet": {
  "playerTurn": -1,                 // 纯 TargetCriteria：BoardCriteria.playerTurn 结构上没有 ⇒ 恒 -1
  "targetsAffected": 10, "chosenArmy": 0, "armyFilter": 0, "keywordFilter": 10, …
  "friendlyUnits": 1, "enemyUnits": 0, "includeHero": 0, "includeMinions": 1, …
  "filterSpecificCards": [], "excludeEnchantments": []
}
```

- **36 格字段名 = 原版字段名逐字**，直接复用 `criteria_set_of()` / `COUNT_SET_*` 元组（⛔ 没有另写字段表）。
- **`conditionsFilter` / `excludeCondition` 不在本列** —— 它们仍然住在 `unitConditions` 的
  `role="cardtarget"`（`ab=-3, lg=-1`）那一行的 `cond` / `ex` 里（与 v25/v26/v27 的分工一致）。
  现读那 13 行**一字未动**（`unitConditions` 仍 **442 行**，`role=="cardtarget"` 仍 **13**）。
- **样例（真值核对过）**：`ASH55 Aspect Shrine` = `ta 10 / keywordFilter 10 / friendlyUnits 1 / includeMinions 1 / …`。

> **为什么【不】落成 `unitConditions` 的行**（施工单原话是「生成器落行」）：
> 那一列的行会被 `EffectText.AssignCardTargetFallback` 逐卡消费 —— 现读池内按 `ta != 0` 会多出 **363 行**：
> `targeted == 1` 的 **236 张**会因此给每条 op 贴上 `TargetCondition`；`targeted == 0` 的 **127 张**会
> 各打一条「带 `cardTargetCriteria` 但 `targeted=0` ⇒ 不接」的 notice（`CardTargetNotice`）。
> 那等于**改动一个既有消费面**，而 `EffectText.cs` 是 `W2` 的文件、不在本代理白名单。
> ⇒ 本笔改成「**卡级一列 + 载体**」：零行为变化，且覆盖 1129/1129（行式口径只能到 376/1129）。
> 若调度台更想要行式载体，那是**另一次结构改动**（要连 `AssignCardTargetFallback` 的闸一起改）。
