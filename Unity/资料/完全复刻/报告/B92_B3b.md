## 6 顺手发现

1. 🔴 **本仓没有叫 `EffectResolver` 的类** —— `RuleEngine/Core/EffectResolver.cs` 只是**文件名**，内容是 `public static partial class RuleCore`。`EffectResolver.cs:8348` 自己就写着「全仓**没有**叫 `EffectResolver` 的类」。我第一次按文件名写成 `EffectResolver.RunAbilityOfAnotherCard(...)` ⇒ `CS0103`（typecheck 一击命中）。**这类「文件名叫 X、类名不叫 X」的地方，引用时必须写真实类名**；`grep "class EffectResolver"` 会 0 命中，别当成「不存在」。
2. 🔴 **环境卡不在我们的卡池里，这是「这一跳跑不动」的唯一原因**：`Resources/cards_engine.json`（1,129 张 = **组牌池**）现读 `Dawn Attack` / `Planetary Invasion` / `Manufactorum Overdrive` / `Warp Storm` / `Helfire Outburst` / `Daemonic Feast` / `Normal Conditions` **7/7 未命中**；真值在 `数据/游戏数据/cards_truth.json`（`AM63 Dawn Attack` = `cardType 20` / `spellType 200`，`trigger 0` 那条 ability = `chosenAbility 30` + `buffType 12` + 一个 enchantment PPtr）。⇒ **P1 级数据缺口**：13 阵营 × 3 张进攻卡的 `ThisCardPlayed` 效果今天**全部不会结算**（原版会）。
3. ✅ **`Get2DPosOfCard` 的全部 7 个原版调用点都传 `useCenter = 1`** —— 这条是**新事实**（上一轮我只核到 `_ChooseUnitTarget` 那一处）。含义：我们任何一个调用点若传 `false` 都偏离；接线时**默认就该传 `true`**。
4. ⚠️ **`BattleManager.GetHeroPos(isPlayer)` 我们完全没建** —— 5 行小方法，`= Get2DPosOfCard(该侧 heroCard, true)`。它的两个消费者（`AiScripted.GetTipPosition` / `CardScript.MoveIntoFieldFromHand`）都不在战斗写手面里 ⇒ 记账，等那两条线的写手一起做（⛔ 别单独建一条零调用者的死方法）。
5. ⚠️ **`ApplyOffensiveEnvOnce` 里「空卡早退」早于督军触发** —— 与原版一致（原版 `d__337` 只在**非空卡**才进 `ApplyEnvEffect`），所以「不使用进攻卡」那一档**不会**触发督军能力。这一点本轮没动，但值得在账里留一句（下一轮别误以为漏了）。
