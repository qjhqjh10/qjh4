## 〇 一句话

原版「手牌也能收事件」的唯一机制是 `RawCardScript.OnTrigger` **不看区域**（区域只是
`CanTriggerAbility → IsRightContext` 的一道闸，`10 = Hand` 才放行）。
我们把它实现成了「必须 `UnitState`」的 `FireTriggerAt` ⇒ **手牌卡的 `abilityTriggers` 一条都发不出来**。
本笔补上**唯一一个手牌适配器**（复用已建但零调用点的 `TriggerCarrier`）＋ **四类广播的两跳辅助器**，
并把它接到**本文件能接的三个**位置；剩下**三行**在 `RuleCore.cs`（另一写手），见 §六 施工单。

## 七 顺手发现（供调度台分流）

1. 🔴 **`RuleCore.HasUnitPoisonedBody`（`BroadcastUnitPoisoned` 的棋盘筛子）在生产里恒 false**：
   它读 `u.FxOps("UnitPoisoned")` / `u.Effect("UnitPoisoned")`，而这两个口在**没有任何卡**上能命中
   （`TriggerOps` 的键只可能是卡面正文关键词；全池 `UnitPoisoned:` 出现 **0** 次）⇒ 棋盘那一跳
   **也只能被夹具（`GrantOps`）驱动**。与账行 658 的「棋盘那一趟已建」不矛盾（结构在），
   但**「有正文的单位才会响」这道筛子今天一条都过不了**。同族：`FireTriggerAlways("UnitPoisoned")`。
2. `RuleCore.BroadcastTurnStarted`（棋盘那一跳，:14804）用的是 `u.FxOps("TurnStarted")` 那一族判断 ⇒ 同上，
   池内 `TurnStarted:` 0 次 ⇒ 它走的是「没正文 ⇒ 只发 `EvtKind.Trigger`」那一支（= 只为表现），
   **不是**「真结算」。这与账行 644 的 B 档描述一致，但值得写清：**棋盘那一半也只是演出**。
3. `EffectResolver.cs` 的 `BroadcastWhen` 形参表已经很长（`boardAndPersistentOnly` / `attackType` /

   `actingCard` 也加进来（同样可「行内追加」，零行数变化）。
4. `ctx.Events` 是**日志字符串表**、表现层事件在 `ctx.Signals`（我第一版断言写错、typecheck 抓到）——
   凡是断「发了几条 `EvtKind.Trigger`」的自检，一律扫 `Signals`。
