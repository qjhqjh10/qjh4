## 六 顺手发现（域外 / 方法论 · 由调度台分流）

1. 🔴 **两个匿名类型的域归属是分类噪声**：`<>f__AnonymousType88<<Filter>…>` 与 `<>f__AnonymousType96<<GroupBadge>…>` 的唯一使用点是 **`AlliancesController.cs` / `AlliancesManager.cs` / `TrophyInfoPopup.cs`**（联盟 / 社交 / 奖杯），**不在收藏域**。档 = D（编译器生成），但建议把它们从「收藏」挪去「社交_聊天」账，否则以后每个域都会重复认领。
2. 🔴 **`BoosterPackBadge : InventoryBadge` 也**没有发射点（全库只自身一个文件）⇒ 我们 `BadgeNotifications.cs` 没有 `BoosterPackBadge` **不是缺口**；但 `InventoryBadge` 的 `IsAssignableFrom` 那条（`:199`）**已经对**，将来真要加也不会漏。
3. **`ItemDrawer.Refresh()` 的调用点全在别的域**：`CatalogItemContainer.cs:347`、`DailyRewardDrawerController.cs:334`、`DailyRewardItemContainer.cs:260/266/275/297`、`DailyStreakItemContainer.cs:354`（商品 / 日常）。我们**没有 `Refresh()`**，靠**重建** `ItemDrawerView` 达到同样效果。⇒ **日常 / 商店两线若要「买完原地变」，需要这个口**（收藏域本身不用）。
4. **`ItemDrawer.SetItemName` 全库 0 调用点** ⇒ 原版死代码（不是我们缺）。
5. 🔴 **方法论：`cpp2il` 会丢「字段赋值」而不报错**。`CollectionDisplay.UpdateCollection` 在 cpp2il 里只剩一句 `RefreshCollection()`，**RVA 一反汇编就露出前面的 `collection = 传入List`**。凡「只是转调」的结论，若原版方法签名带参数但体里没用它，**必须反汇编确认**（本轮 12 条里 3 条属这种情况）。
6. **`G4` 把两个 `PrintMembers.c` 标成「文件名与内容不符」**（文件内容 = `return 0;`，被 Ghidra 同形函数合并）。这条**恰好与 `PrintMembers` 返回 false 兼容** ⇒ 不算缺陷，但引用 `.c` 时必须用 cpp2il 交叉（本轮已做）。
7. **`CollectionDisplay.Select` 有一道我们没有的闸**：`listView+0x18a`（列表忙 / 正在滚）就直接 return。我们点格 lambda（`CollectionWindow.cs:1681`）没有这层 ⇒ **快速滚动中点到卡会直接开详情**。属小差（B 行里已记），要不要补由界面线定。
8. **`ItemDrawer.Draw` 的「名字为空 ⇒ 隐藏名字」这一支**，我们靠 `TextCentered` 不传空串达成，没显式闸；不影响收藏（不画 ItemDrawer），但奖励 / 商店格可能出现「空名字仍占位」。
