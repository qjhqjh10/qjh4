### 7·2 ⚠️ 以后用 Python 批量调 MSYS 的 `cmp` / `diff` 要警惕（`W-52` 实测）

**症状**：`subprocess.run(["cmp", "-s", a, b])`（`shell=False`）对 13 份 `VO_Tau_Empire_Aun'va_*.ogg` 返回 **rc=2（无法打开）**，其余 437 份返回 0；而对同一批文件 `shell=True` 返回 0、bash 里直接 `cmp` 返回 0、Python 全文读 + `sha256` 也完全相同。

**结论：不是文件不同，是 argv 引号重排的伪失败。** 反证：同目录 `Aun'Va`（大写 V）、`Aun'Shi` 走同一条 subprocess 路径**都返回 0**。窗口落在小写 `'va` 上（`Aun'va`），全 43/450 名单里**恰好只有这 13 份**呈现该形态。

**做法（三选一）**：
1. **别用 Python 去调 MSYS 的 `cmp`/`diff` 做批量判据** —— 直接用 Python `io.open(p,'rb').read()` 全文比较，或 `hashlib.sha256`；
2. 必须调时用 `shell=True`（或 `bash -c` 并自己做好引号），别用 `list` 形态；
3. 真要逐份 `cmp`，用 bash 的 `while IFS= read -r -d ''` + NUL 分隔名单（本会话就是这么跑出 **450/450 全 0** 的）。

> ⚠️ 同类坑的兄弟：本仓已有记录「Windows 下 `python -c "…"` 含中文/反引号会被 bash 吃字」，凡是**跨 shell 传目录名**的判据都要用**二进制/字节级**自证，⛔ 别用「命令退出码 = 0」当唯一依据。
