## 悬案 2：原版那四格 bool（`0x240/0x241/0x242/0x243`）到底会不会复位

### 结论

**会复位 —— 每次回合开始把它们【一起】清 0**，写法是**一条 4 字节零写**：

```c
// decomp_full/BattleManager._NextTurn_d__395__MoveNext.c:174（紧挨着 turnCounter++ 那一段）
*(undefined4 *)(lVar3 + 0x240) = 0;   // 一次清掉 0x240/0x241/0x242/0x243 四格
```

⇒ 账 195 的「随回合清零」**已证实**；A2（`B87_A2_B04`）写的「判据真空、可能从不复位」**是错的**，根因见下。

### 判据

**甲、四格的身份（🥇）**
`d:/2/tools/il2cpp_out/dump.cs:30808-30814`（`BattleManager` 的 `[CompilerGenerated]` backing fields）：

| 偏移 | 字段 |
|---|---|
| `0x240` | `<playerPlayerCardInTurn>` |
| `0x241` | `<enemyPlayerCardInTurn>` |
| `0x242` | `<playerPlayerTroopInTurn>` |
| `0x243` | `<enemyPlayerTroopInTurn>` |

**乙、清零点（🥇 本次的关键发现）**
`decomp_full/BattleManager._NextTurn_d__395__MoveNext.c:174`：`*(undefined4 *)(lVar3 + 0x240) = 0;`
上下文（同文件 `:150-176`）：`"<isPlayer> turn <turnCounter+1>"` 的日志 → `AvailableActionsPool.Reset(+0x4e8)` →
`turnCounter` 自增（ObscuredInt，写 `+0x3f8/0x3FC/0x400/0x404/0x408`）→ **本行清零** → 后面接
`*(undefined1 *)(lVar3 + 0x244)`（`allowPlayerActionsFlag`）与 `*(bool *)(lVar3 + 0x246)`（`allowEnemyActionsFlag`）。
⇒ 位置 = **每次回合推进的那一段**，四格**同一条 store** 全清。

**丙、写点（只有置 1）**
`decomp_full/BattleManager._ResolvePlayCardFromHand_d__447__MoveNext.c`：
`:1433`（`0x241` 敌方·卡）· `:1440`（`0x243` 敌方·兵）· `:1444`（`0x240` 我方·卡）· `:1451`（`0x242` 我方·兵），全是 `= 1`；
分叉闸 = `*(char *)(card + 0x40)`（敌/我）＋ `RawCardScript__IsUnit`（单位才置 troop 位）。与 `AlreadyPlayedTeamp…TroopThisTurn.c:5-8` 的读法一一对应。

**丁、为什么上一轮会判成「没有写回 0」（这条要记进坑表）**
🔴 **相邻 bool 的清零会被编译器【合并成更宽的 store】**，按单偏移 grep 一定漏：
- 本例：四格合一 → `undefined4 @ 0x240`（`:174`）⇒ `grep "0x242"` / `grep "0x243"` **命中 0 处写回 0**。
- 同族旁证（同一文件）：`*(undefined2 *)(lVar3 + 0x418) = 0;`（`:382`）一次清
  `waitingToResolveActiveAbilityFlag(0x418)` ＋ `waitingToResolveUseWaystoneFlag(0x419)` 两个相邻 bool。
- 加上 A2 只用 ILSpy 侧核：`out_cpp2il_dev_ilspy` 全树里这四格**只有 setter 内部的 `__BackingField = value`**（`BattleManager.cs:14506/14530` 等），
  **清零那一行在 ILSpy 版里根本不存在**（ILSpy 丢写点 / 该状态机在 ILSpy 产物里没有对应文件）。
⇒ **判法（建议写进准则）**：查「某格 bool 有没有被清」必须按**能覆盖它的最宽写**查
（`grep "+ 0x240) = "` / `+ 0x242) = "`，含 `undefined1/2/4/8` 三种宽度），并且**必须看 `.c`**。

**戊、附带事实（对本账有用）**
`AlreadyPlayedCardThisTurn` / `AlreadyPlayedTroopThisTurn` 在全量反编译（`.c` 26,282 个方法体 ＋ ILSpy dev 树）里**0 个调用者**，
`assets_full` 里也**没有**这两个方法名的字符串引用（prefab `m_MethodName` / SO AssetReference 都查了）。
⇒ 本 build 里这四格是「**写了没人读**」的格。⚠️ 但 `decomp_full` 只覆盖约 29% 的方法体，**不能据此断言永远不会有消费者**。
