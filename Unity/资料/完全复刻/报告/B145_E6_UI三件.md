## 四 卡住 / 与判据冲突

1. **A-15 的施工单修法不成立（已按判据改，见上表）** —— 「走 `SetScriptHeight(text, px, 1)`」在现读换算式下与现有 `SetGlyphHeight(px)` **逐位等价**（两条路经 `CapOverGlyph` 往返），照做**一个像素都不会动**。已改为「按大写高定档」（判据不变，仍是原版 `m_fontSize 55 × 0.72` = 39.6）。⚠️ 建议把施工单/审计里那句「应走 `SetScriptHeight`」就地订正（铁律 5），本写手**未改** `报告/B144_W3_B129参数.md`（不在白名单）。

3. **A-17 只能靠断言 + 真机点验**：命中框是 uGUI 射线件，批处理里没有 `EventSystem` 真射线；断言钉的是 rect 尺寸/中心/存不存在，**「点标题不关窗」要真机点**。
4. 未接线：`B145_E6_Assert.Run()` 的**宿主接线不在白名单**（`Editor/*Scene.cs` 与 `RuleEngineTest.cs` 都有别的写手）⇒ 待调度台接线后跑一次。
5. **断言覆盖的边界（如实记）**：A-2x 钉的是**换算 + `Label` 两条 API 的实际差别**；「`Build()` 里那一句真的调用了 `SetCapHeight(TitleCapPxFor(...))`」**没有运行时断言**（要一台真面板实例）。要防「有人把那句改回去」，靠接管宿主时补一条（建 `ChoosePanel` → 读 `_title.CapHeightWorld`），或 code review。
