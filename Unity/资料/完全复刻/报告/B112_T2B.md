**三条**减少噪声的设计（都是本次实测调出来的，写在这里免得下一个人重踩）：

2. **条件先按 `&&` / `||` 在深度 0 拆成子句**再逐句看 `==`。第一版只看第一个 `==`，

4. **`高置信` 从 7 → 18**：同样是第 2 条那个「先拆 `&&`」修好之后，嵌在复合条件里的自证才被抓到。

## ④ 建议的修法模式（按「怎么改才灭得掉自证」排序）

| 模式 | 怎么做 | 适用 |
|---|---|---|
| **① 字面量真值** | 期望值直接写成**原版材料上的字**（卡面原文 / prefab 字段 / JSON 值），并在注释里给 `文件:行` 或资产路径 | 最硬。`DeckScene.cs:7033` 就是范例（整句中文抄进去） |
| **② 外部数据表** | 期望值走**数据侧**（`Loc.T` 读官方词表 / `card_stats.json` / `assets_full` 的材质 JSON） | 文案、参数、贴图 |
| **③ 判别式 / 反例** | 主断言之外加一条**结构上不可能同时满足**的断言（「不许退回 id」「两档不许同一串」「不同种子必须不同」） | 前后不变量、跨语档、幂等 |
| **④ 见证（witness）** | 先断「两次的**输入真的不同**」，再断「输出相同」 | 复现性 / 缓存复用。范例 `BattleScene.cs:27991` |
| **⑤ 计数/副作用** | 改用**旁路计数**（`TraitPrefabsInstantiatedTotal`）或**盘上字节**（`disk0`）当尺子 | 幂等 / 只落一次盘 |
| ⛔ **不许做的** | 把期望值再抄一遍同一个函数（哪怕改成 `F(x)` 换个写法） | 一切 |

## ⑥ 顺手发现

1. 🟢 **本项目的「灭自证」文化已经写进代码注释了**：抽查到的自证/半自证现场，旁边几乎都有一句
   「🧨 改坏法：…… ⇒ 本条红」或「⛔ 别改回 X」。⇒ 这一族的**判据其实已经有人在守**，
   普查的价值在于**把散落的判断集中成一张可复跑的清单**，而不是「发现了没人管的事」。
