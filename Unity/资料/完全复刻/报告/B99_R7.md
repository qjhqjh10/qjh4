## 5. ⑤ 需人判的清单与原因（4,697 行）

| 原因 | 行数 | 说明 / 怎么办 |
|---|---:|---|
| **类定义（游戏类，多实例）** | 4,168 | `类型=MonoScript`。一个类挂多处 ⇒ 「一个名字对应多个对象」，账/重放取到的根会不同（实测 75 条链完整行两边不一致全是此类）。**这是代码覆盖问题，归 `账/` 主表，不进资源清单**；要判「这个类我们有没有」，应按类名查源码，不能按资源用度 |
| **类定义（第三方/引擎库）** | 525 | 可判 DOTween / PlayFab / TMP / SIMD(`Sse3/Ssse3/Avx/Popcnt`) / `DebugUI.*` / Firebase / 广告 SDK 等 ⇒ **判非复刻对象，销账** |
| **功能域不可判（未知）** | 4 | 名不带任何功能词且非类，需人看属主 |

> 其中 4,693 条在 `globalgamemanagers.assets`（原版主 Assembly 的类存根）。**建议：把 `类型=MonoScript` 整体从「资源缺口」移出**，否则「读过的资源里 X% 没用上」这个指标会被代码类永久污染。

## 6. 已知边界（别把数字当绝对）

1. **④ 是「候选」，不是「功能没做」**：本仓 UI 多为**代码构造**（`Shell/*.cs`），与原版 prefab 不同名。④ 里标了 `近似类=` 的（如 `Draft Mode Timed Mode Window`↔`DraftModeWindow`、`SkirmishModeEventWindow`↔`SkirmishEventWindow`、`Rewards Base Submenu Variant`↔`RewardsWindow`）很可能是「功能已建、具体变体未导」。**逐根确认**正是这张表派工的意义。
2. **未见「功能全无代码」的域** ⇒ ②=0 是证据性结论，不是漏判；但若某域只是薄桩（`SocialWindow` 281 行），其 ④ 行可视作 ②（转该线）。清单已按域分组，可直接转交。
3. **`名字` 判据本身**：账方已记 366 行扩展名漏判（`.cs/.webm/.cubemap` 案）；本层**没重做 U1、没改账**，只在其结果上分层。
4. **追根可能停在与最外层窗口之间的可复用中间预制体**（`Icon Container Drawer Variant` / `Avatar Item Small` / `Title Drawer`）：它们是 addressable 预制体根，停在那是「它本身就是根」，**不是追根断了**；但意味着同一批子件可能分散挂在多个根下。
5. **重放 BFS 未纳入场景 `m_Father==0` 根**（需 UnityPy）：对 battlearena 整包定域无影响；若要精确到场景子树，需补根集。
6. **4,698 个 MonoScript（27%）是类定义**，不该按资源缺口计。剔掉后，「资源类未用」实为 **12,673 行**，其中 ④ 真缺口候选 **2,821 行 / 250 根**。
7. `③ 父件已用` 与 `③ 根名↔类` 是**名字级判定**，不保证像素级一致；它们的价值是「解释为什么这行不用单独处理」，不构成「已完美复刻」的证据。
