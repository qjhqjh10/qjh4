### 1·2 🔴 两处**判据措辞订正**（铁律 5 —— 会影响别人家的断言，请调度台转派）

1. **「中间值 = 按满阈值显示」不精确** —— 原版印的是**加完的累计值**（`:66-71` 比的是 `>=`）。
   例：余 2 时 `+3` ⇒ 原版先印 **`5/3`**，1.0 s 后变 `2/3`。`判据/B142_R17_CHK05块5.md` §二·2·2 的
   「先把任务点按满阈值显示一秒」应改成「先按**加完的累计值**显示」。
2. **「那一跳不弹」是误读，方向反了** —— 见上表 ③④⑤：
   `silently:false`（`.c` 里那个 `0`）**是「不静默」= 会弹会播上升特效**；
   **静默的是 1 s 之后那一跳**（第 ⑨ 行，`.c:76` 传 `1`）。
   ⇒ **`BattleDriver.cs:37718` 那段 doc 与 `Editor/BattleScene.cs` 账 586 的断言 ②③ 都建立在这个误读上**：
   - 它们断言「值立刻到 + **此刻不弹** + 0.6 s 后弹一次」；
   - 原版是「值立刻到 + **此刻就弹（上升）** + 1 s 后**静默**降到余数」。
   ⚠️ 这两条**不是本笔的白名单**（`BattleDriver.cs` / `BattleScene.cs` 都不是我的），**我一个字节没改**，
   只把证据写在这里 —— 请调度台决定派给谁（HUD 那条活本来就该跟本笔的字段一起做）。
3. 附带发现（同族，供 HUD 那笔参考）：`ManaTypeHolder.TryDOVfx` 的 `currentValue(+0x70)`
   **只在 `!silently` 时更新** ⇒ **下降特效（`Quest UI Trigger`）不在扣阈值那一刻播**，
   而是在**下一次加任务点**（新值 ≤ 上次静默前的值）时才播。现有 `EvtKind.QuestSpent`
   （`EffectResolver.QuestPointThreshold` 里发出）**在时间上与之不符** —— 只作证据记录，本笔不改。

## 二、`B142-PLAYEVENT-DEFENSIVE` —— 防御卡分支

### 2·1 第二实参 = **不存在**

判据：
- 原版签名**只有一个形参**：`public static DeckUtility.DefensiveCardInventoryCheck HasDefensiveCards(CardDeck deck)`
  （`d:/2/tools/il2cpp_out/dump.cs:21883` · `out_il2csharp/Assembly-CSharp/DeckUtility.cs:239`）。
- 调用点 `PlayEvent_object__object_.StartMatch__1127df0.c:51` 印成 `HasDefensiveCards(deck, 0)` —— 那个 `0`
  是 **Ghidra 给每个方法调用多印的一个 `MethodInfo*` 尾巴**。同文件同形状的旁证（全是「真形参数 + 1」）：
  · `:106` `WindowsManager__ShowPopUp(…, uVar8, lVar7, 0)` = 7 形参印 **9** 个实参（`dump.cs:115547`）；
  · `PlayerManager__AddQuestPoints.c:80/97` `ManaManager__SetQuestPoints(qp, 阈值, 0, 0)` = 3 形参印 **5** 个；
  · `ManaManager__SetQuestPoints` 的真形参就是 `(int, int, bool)`。
- 返回值是**三态枚举**（不是 bool）：`DontHave=0` / `HaveItInInventory=1` / `HaveItAssigned=2`
  （`dump.cs:21826-21832`）；调用点 `:52` **只判 `== 1`**，`:112` 的 0 与 2 都直接 `StartMatchNoCheck`。

### 2·2 我们原来的读法（两处都歪）

`Shell/PlayEvent.cs` 改前：
```csharp
protected virtual bool HasDefensiveCardInInventory(string deckId) { return false; }   // 🔶 自己设计
```
- **命名歪**：布尔名 `…InInventory` 无法表达「**已经分配**」这一档 —— 一旦有人照着名字把它实现成
  「库存里有没有」，`HaveItAssigned` 会被当成 `true` ⇒ **已经分配好防御卡的卡组反而开不了战**（原版没这行为）。
- **语义歪**：恒 `false` 是 2026-10-27 的 `🔶 自己设计`（理由是「防御卡是我们补的」）。
  但这条**与服务器无关**（库存 / 卡组都在本地，判据现在也已补导）⇒ 按**铁律 18·0** 应复刻原版。
