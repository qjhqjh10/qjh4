**为什么用 `RuleCore.TriggerNameOfKeyword(keyword) ?? keyword`**：`Matching` 收到的是**引擎关键词**
（`rally` / `spiritstone` …），而 `AbilityTriggerNumberOfName` 是**原版枚举名**表（没有 `Rally`；
原版 rally = `ThisCardPlayed(0)`、spiritstone = `UseSpiritStone(600)`）。不换名 ⇒ 这两族的数据位项
**恒 `-1`**（静默失效）。`TriggerNameOfKeyword` 是本仓**唯一**那张反向表（正本 = 生成器
`ABILITY_TRIGGER_KEYWORD`），⛔ 本笔没有另抄一份。

**为什么 `Matching` 用「OR」、而 `FindCancelAttack` / `HasEnchantmentForTrigger` 用「数据位优先、
`-1` 才退正文」**：`Matching` 是**预筛**（`FireTriggerAt` 后面还有 ops / abilityContext / criteria
若干道闸），正文多认一件不会直接造成结算；而取消攻击那一族是**最终判据**，必须以数据位为准。
两者都已写进注释，⛔ 别互相「对齐」掉。

### 6.1 派发侧（引擎线 · `RuleCore.cs` / `EffectResolver.cs`）——「伤害那一刻，附魔那条 ability 也要被选中」

**判据**：§1.3 那条链。**我们今天的差**：`EffectResolver.FireBoardDamagedByNumber`（`:20527`）
调的 `FireTriggerByNumber` 只跑**载体自己**那张卡（`u.Card.TriggerOpsByNumber(60)`），
**整条不查 `ActiveEnchantments`**。

补丁 A（`EffectResolver.cs` 的 `FireTriggerByNumberWithSink`，`:20995` 起，`var ops = u.Card.TriggerOpsByNumber(triggerNumber);` 之后）：

```csharp
// 原版 RawCardScript__TriggerAbilities.c:59-108 的附魔趟：载体身上每一件附魔，按 trigger 数值各派一次
if (Enchantments.HasAny(u))
{
    var enchHits = Enchantments.Matching(u, tn);          // tn 已由 TryAbilityTriggerNameOfNumber 得到（原版枚举名）
    for (int i = 0; i < enchHits.Count; i++)
    {
        var e = enchHits[i];
        if (e == null || e.Card == null) continue;
        if (Enchantments.AllSpent(u.Instance, e.Card)) continue;        // 原版 .c:66
        var eops = e.Card.TriggerOpsByNumber(triggerNumber);
        RuleCore.FireTriggerAt(ctx, u, tn, owner, slot, chosen: targetCard, subject: actingCard,
                               only: e, opsOverride: eops);              // FireTriggerAt 已支持 only + opsOverride
    }
}
```
⚠️ **两个已知卡点**（照实写，别当成能直接贴）：
① `FireTriggerAt` 的早退闸 `ops == null && spec == null && skipDraw == null && (ench == null || ench.Count == 0)`
   —— `only != null` 时 `ench` 恒 null，而 `Pray Enchantment` 的 `TriggerOpsByNumber(60)` **也是 null**
   （它的 `abilityLogic` 是 `chosenAbility 340` 这种**数据**行，不是文本 op；`triggerAbilityIndices`
   只把**文本 op** 归位，见 `CardDatabasePartial_B98H7.cs` 头注 §二）⇒ 仍会早退。
   ⇒ 要么给 `FireTriggerAt` 加一个「数据位 ability：只发信号 + 入队、不跑正文」的分支
   （与 `FireCancelAttackTrigger` ② 那一段同形，`RuleCore.cs:17581-17586`），
   要么在这里就地 `ctx.Emit(EvtKind.Trigger, …, only.Card.Id, …)` 后返回。
② **要让表现层查得到「附魔卡自己」的逐卡行，事件的 `CardId` 必须是附魔卡的 id**，
   而 `FireTriggerAt` 的 `emitSignal` 现在固定传 `u.Name`（载体名）。原版 `PlayAnim` 用的是
   **附魔卡自己的** `cardAnimations`（`AbilityData.thisCard` = `only.Card`）⇒ 那一格应当改成
   `only != null ? only.Card.Id : u.Name`（**这会给已有附魔正文触发换事件卡 id**，要单独评估影响面）。
