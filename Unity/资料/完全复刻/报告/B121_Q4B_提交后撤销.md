## §五 还差什么（如实记）

1. 🔴 **残余差（未做，已登记）**：原版撤销后 `UIstate = movingHandCard`(2) ⇒ 卡**继续跟着指针**、可立即再拖上去重提；我们按施工单的形状把卡放回手牌槽位（票已清、`_dragging` 仍 null）⇒ 要**松手再按下**才能再拖。可见面（卡回手牌 / `QHandMoving` / 描边重刷）一致。要做成原版那一档，需要额外的「重入拖拽态 + 抑制下一次松手的二次 `ApplyOutFromPlayingArea`」状态位 —— 会扩大 `Release` 的状态面，建议单独立账。
2. **断言未接线、未跑 Unity**：`Editor/BattleScene.cs` 的聚合行由调度台接（`B121_WB_Assert.Run();` 之后）。29 条里 A/B/C/D 全部依赖「夹具能真的提交」这一个前提（A0/前提那几条会先报出来，⛔ 不会假绿）。
3. **真机手感未验**：撤销那一瞬间卡从半空飞回手里的观感、以及「拖回线下」的判定边界（`HandLimitY`）手感 —— 要真 Play。
4. **`PendingSignalQueue` 没有按键移除的口**：撤销后那条已排程的 `cueAction` 仍留在队里（到点跑一个空操作）。行为上无影响（闸在 `MaybeStartHandToBoardClip`），但严格说「撤掉已排程动作」只撤了效果、没撤条目。
5. **`CardFeel.HandToBoard` 的 `OnKill` 只复位两档 α**（`SetAlpha2D` / `SetCounterAlpha` / `SetCountersForcedVisible`），**不复位**溶解材质 / `body3D` / 立绘缩放 / 两级 y。本件在调用点补了这些复位；若将来别处也「中途打断登场 clip」，同一套复位要复用（现在是 `CardInteraction.CancelDeployFlight` 里内联的）。

## §六 顺手发现（交调度台分流）

1. `CardView.BoardElementsForTest` 只在 `Board3DBones()` **懒建之后**才非空；撤销复位用 `transform.Find("Board Elements")` 更稳（本件就是这么写的）。两级节点都是**恒等变换** ⇒ 复位 y 就是 0；`body3D` 的基准位是 `−CardView.Height/2`（`BuildBody3D` 的判据）。
2. `BattleDriver.OnPlayerDeployFlightStart(card, which, land, duration)` 的 `which` / `land` **两个实参全方法体都没用** —— 不是缺陷，但将来若有人按它算落点会误以为拿得到。
3. `_handToBoardCard` 与新增的 `_playerDeployFlightCard` 是**两个**「正在演的那张」口径（前者 = clip 正在跑、后者 = 飞行未撤），本件没合并：合并会让 clip 的 0.7 形态切换与撤销闸耦合。已在两处注释里互相点名。
4. `CardFeel.HandToBoard` 的 `OnKill` 复位面比 `BeginFrameDissolve` / `BeginDissolve` 打开的面小（见 §五·5）—— 这条值得在**特效动画线**立一条账（谁将来中途杀这条 clip 都会踩）。
5. 本件在 `Update` 第一行之后多一次函数调用（无票时第一句就 return）；`PointerWorldSafe()` 只在**有票**时才算 ⇒ 零帧率影响。
