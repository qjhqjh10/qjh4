## 四、⚠️ 与简报不一致的一处：`WritePlayerEvent` 的文件名

简报写的是 `responses/ExecuteCloudScript.WritePlayerEvent.json`。**那份永远不会被命中**：

- `server.py:281-300 resolve_template` 只在 `method == "ExecuteCloudScript"` 时才拼 `ExecuteCloudScript.<FunctionName>.json`；否则候选只有 `<Method>.json`。

> ✅ **2026-11-07 追加（S2 二轮）：本条已直接做进 `server.py`（`_inject_liveops`，运行时注入），⛔ 不需要调度台再改模板。** 下面的键路径与片段保留作判据 / 实现说明，实现与自检见 §八。

⛔ 本轮**没有改** `responses/ExecuteCloudScript.InitializeLiveOps.json`（归另一写手）。两条的读取端都在 `InitializeLiveOps` 响应里，键路径如下：

| 来源 state | 目标键路径（`FunctionResult.` 之后） | 值 | 客户端读点 |
|---|---|---|---|
| `eventPrefs[eventId].defaultDeckId` | `HandlerData.GameModes.RawEvents[eventId==<eventId>].Persistence.defaultDeckId` | string | `PlayEventSaveGame.defaultDeckId` · `PlayEvent.GetEventDeck()`（`PlayEvent.cs:1094`） |
| `selectedArmy` | `HandlerData.Campaign.SharedData.selectedArmy` | int（`CardArmy`） | `CampaignHandler.cs:432`（缺省 Ultramarines=10） |

当前模板的落点（现读）：
- `HandlerData.GameModes.RawEvents` 共 5 项，`OfflineClassic` 那项（下标 1）的 `Persistence = {"$type": "Everguild.LiveOps.RankedV2Save, Assembly-CSharp", "eventId": "OfflineClassic", "IsNew": true, "IsActive": true}` ⇒ 往里加 `defaultDeckId` 即可。
- `HandlerData.Campaign.SharedData` 现为 `{}` ⇒ 加 `"selectedArmy": <int>`。

推荐做法（**运行时注入**，不必每次手改模板，也不会与模板写手冲突）：在 `server.py` 的 `do_POST` 模板命中后、`_inject_decks` 旁边加一个 `_inject_liveops(payload)`，伪代码：

```python
if method == "ExecuteCloudScript" and branch == "InitializeLiveOps":
    self._inject_liveops(payload)

def _inject_liveops(self, payload):
    try:
        hd = (payload or {}).get("FunctionResult", {}).get("HandlerData") or {}
        if self.state.selected_army is not None:
            camp = hd.setdefault("Campaign", {})
            camp.setdefault("SharedData", {})["selectedArmy"] = self.state.selected_army
        events = (hd.get("GameModes") or {}).get("RawEvents") or []
        for ev in events:
            if not isinstance(ev, dict):
                continue
            pers = ev.get("Persistence")
            if not isinstance(pers, dict):
                continue
            pref = self.state.event_prefs.get(pers.get("eventId"))
            if isinstance(pref, dict) and pref.get("defaultDeckId"):
                pers["defaultDeckId"] = pref["defaultDeckId"]
    except Exception as e:
        self.state.log.note("注入事件态失败: %s" % e)
```

（`payload` 是 `strip_meta(doc)` 之后的 dict，`FunctionResult` 就在里面。`_inject_liveops` 只写内存副本，不落盘。）
若调度台选择**静态改模板**，就把上表两条键直接写进 `InitializeLiveOps.json` 的对应位置——但静态值只有一份，玩家换阵营/换默认卡组后会被模板覆盖，**推荐运行时注入**。

## 七、顺手发现

1. **`WritePlayerEvent` 的日志本身是「上游出过错」的回声**：`0018` 那条的 `Body.Action = "CloudscriptError"`、`CustomError` 里就是 `NotImplemented ... GenericCloudScriptHandlerAsync` 的堆栈 ⇒ 补完模板后，这条请求应当**大幅减少**（只有真错误才发）。它 22 次 / 5 个目录，正好和那几条缺模板的失败次数同源。
2. **`updatePlayerDecksArray` 会把 `gameMode=13` 的突围先锋卡组写进 `decks`**，随后 `_inject_decks` 会把它一起塞进登录响应的 `UserReadOnlyData.PlayerDecks`。这正是原版 `FixSkirmishDeck` 的语义（服务端保存、下次不再补），但**卡组列表是不是该显示这些 `gameMode=13` 的条目**属于客户端过滤口径，需要真机验收时看一眼（本轮不起游戏，未验）。
3. `state/player_state.json` 现在多了 `eventPrefs` / `selectedArmy` 两个键；`save_state` 会把不认识的键原样带回，所以**外部手工加的键不会被写没**（已用 `someHandEditedKey` 回归验过）。但**没有任何 `tools/*.py` 写这个文件**（`grep` 0 命中）⇒ 将来若加此类工具，要记得保留这两个键。
4. `updatePlayerDecksArray` 的 `Data.Decks` 是**字符串套 JSON**（不是对象），`json.loads` 失败时只出声、响应仍 200 —— 与原版「保存失败也不阻断登录」一致。
5. `SetGamemodeDefaultDeck` 在日志里只出现 2 次、`OnRankedV2MatchFound` / `SelectActiveCampaign` 各 1 次 ⇒ 它们从没在真实登录链上反复刷，补模板主要是消除 onError 分支（尤其 `OnRankedV2MatchFound` 的 onError 会**重调** `MatchFoundCallback`）。

### 9.3 是否要落盘 / 发放卡组

- **发放卡组 = 客户端行为，不需要服务端落盘**：`RewardService.Collect([deck] + extraRewards)` 在本地发（`PrebuiltDeck` 未重写 `HandleOnCollect`，收集不改服务端）；节点收集写的是 `Campaign` 的内存列表 + `CampaignNodeCollectedSignal`。
- 这条回调里真正的服务端调用只有两条，**都已经有模板 + 落盘**：`CampaignHandler.SaveSelectedArmy()` → `SelectActiveCampaign`（本报告 §二·5）、`IRankedEvent.SetDefaultDeck(...)` → `SetGamemodeDefaultDeck`（§二·3）。⇒ **本函数不需要 server.py 分支**。
- ⚠️ **唯一需要扩 server.py 的一步（留给调度台决定）**：模板是静态的，`deck.item` 写死 `UM_SK_Starter`。FTUE 允许选别的阵营（`ASH_SK_Starter` / `SAI_SK_Starter` / …），那时回调会拿到**错的阵营卡组**，`SetSelectedArmy(reference.cardArmy)` 会把战役阵营设成 Ultramarines。要做对，需要在 `server.py` 的 `do_POST` 里加一条运行时改写（与 `_inject_liveops` 同型，只改内存副本）：

```python
if method == "ExecuteCloudScript" and branch == "GrantStarterDeck":
    payload = copy.deepcopy(payload)
    self._inject_grant_starter_deck(payload, body)

def _inject_grant_starter_deck(self, payload, body):
    try:
        data = (body.get("FunctionParameter") or {}).get("Data") or {}
        deck_id = data.get("starterDeckId")
        fr = (payload or {}).get("FunctionResult")
        if not isinstance(deck_id, str) or not deck_id or not isinstance(fr, dict):
            return
        deck = fr.setdefault("deck", {})
        deck["item"] = deck_id
        deck["quantity"] = 1
        fr.setdefault("rewards", [])
        fr.setdefault("extraRewards", [])
        # army：参考 starterDeckId 前缀（UM/ASH/SAI/…）→ CardArmy 的映射；不读也不影响（回调取 deckHero.cardArmy）
        self.state.log.note("GrantStarterDeck: deck.item -> %s" % deck_id)
    except Exception as e:
        self.state.log.note("GrantStarterDeck 注入失败: %s" % e)
```

（`army` 字段在成功回调里**没有被读**，真正用的是解析出来的 `deck.deckHero.Reference.cardArmy`，所以只要 `deck.item` 对，阵营就对。）
