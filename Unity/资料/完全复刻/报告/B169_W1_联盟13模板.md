## 二、几处需要说明的判定

1. **"回调读不读返回值"是分档的唯一判据**：`GenericCloudScriptHandler<T>` 在 `FunctionResult` 为 null 时以 null 调 onComplete（不是 onError）—— 这条已在 `ExecuteCloudScript.CreateGroup.json` 的 `_sources` 第 3 条固化（`PlayfabWrapper__DeserializePlayfabResult_object_.c:23-28`）。所以只要回调形参是 `Action` / `Action<object>` 且不读，null 就安全；形参是 `List<Group>` 就必须给 `[]`。
2. **`UpdateGroupInfo` 是唯一"不抛但有副作用"的**：两条 lambda 都是 `SetCurrentGroupCached(updatedGroup)`。`SetCurrentGroupCached(null)` 只把缓存字段清零、不抛（`AlliancesController__SetCurrentGroupCached.c`；`B168_对账_A2 §4·3` 已核）——但联盟会从 UI 消失。因为**离线本来就没有联盟**，与现状一致；已在模板 `_todo` 里写死"一有真 Group 必须同时升级"。
3. **`FetchGroupsOrdered` 给 `[]` 而不是 `null`**：虽然全树查不到调用点，但公开签名是 `Action<List<Group>>`，空数组与已上线的 `FetchGroups`（也返回 `[]`）同口径，类型上不会错。
4. **`UpdateTrophy` 给 null 的代价**：客户端点"上报奖杯"后本地进度不会被服务端确认（回调跳过）。这是"⛔ 不伪造会写进存档的数值"的直接结果，已写进 `_todo`。
5. **没有任何一处伪造数据**：11 份全部是 `null` 或 `[]`，不含联盟成员、奖杯分值、名次。
