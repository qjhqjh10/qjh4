## 二 · 为什么这么改（灭自证）

- **Settings 组 A**：生产值本来就是对的（`m_fontSizeMax` 里确实写着 42）。错在**读取口**：静态 `Label.FontSizeToPx` 恒按 **CJK 汉字墨高**折算，而这六颗是拉丁面 ⇒ 恒差 `0.0853 / 0.1 = 0.853`。判据把六条比值逐条算出来是 0.85317/0.85291/0.85310/0.85314/0.85317/0.85310（同一常数）。改用实例口后：12.60 / 37.80 / 42.00 / 41.41 / 45.20，且 #2 的区间变成 `[15.79, 36.42]`（实得 35.64 ∈ 区间）。
  ⚠️ 判据给的**方案②**（「直接比 `m_fontSizeBase` 的原始字段值 14/42/41.4/45.2」）**不采纳**：那两个字段存的是 TMP 的 fontSize 单位（`SetAutoFitBox` 按 `maxPx/nomPx` 折过），实测不是 42 而是 3.5 这一档 —— 照它写会立刻红。这里只采用**方案①**。
- **Settings 组 B**：`NetConfig.OverridePath` 是 `static`，宿主设了不还；`B140_V4b_Assert` 是同宿主里被调的，只清 `SaveSandbox.*` 三件套 ⇒ 用**自己的**前值/`finally` 把 `NetConfig` 那一格也管起来。**产品代码一个字没动**。
- **Rewards #3**：`0.77254903` 是原版 prefab 的 `m_Color.a` 精确值；`0.773` 是取整，差 4.5e-4 已超 1e-4 容差。生产侧（`InboxWindow.cs:381` 的 `0.7725490f`）与 `0.77254903f` 是**同一个 float**，所以只需要改期望。
- **Rewards #2**：`Drawer.SetState` 现在两条都结构性：`Unlocked` 由 `colider` 吞、`Collected` 由真 `Shadow` 节点（`WindowButton.absorbOnly`）吞 ⇒ 「按灰」不再是命中闸的职责（`Interactable = state != Unlocked`，`Collected` 其实是 **true**）。所以断言改断节点，而不是改期望值凑绿。
- **Rewards #4**：`37` 不是拍出来的 —— 是 `48 − 11`：`MinOffset` 只把**内容**左端贴到视口左沿，第 1 格在内容里还有 `m_Padding.left = 48`；命中区再吃到 `Icon` 的 `m_RaycastPadding = −11` 外扩。**这同时解释了控制组为什么过**：pad = 40 > 37 ⇒ 被 pad 吃掉，读数停在 +40。判别力：pad 未复位 ⇒ 40（差 3 > 容差 1.5）红；`ArmyHitRect` 丢了 −11 ⇒ 48 红；`ArmyPadL` 归零 ⇒ 0 红。
- **Rewards #5 / #6**：**期望值一个字没动**，动的是**量法**。`MenuDraw.Hit` 建的命中区节点 `localPosition` **恒 0**（只写 `sizeDelta`），quad 才摆在矩形中心 ⇒ 拿节点量中心恒等于「条目中心」。用日志实测值反推可以逐位对上：`hitBot − itemTop = h/2 + OrigItemH/2 = 129.5/2 + 65 = 129.75`（日志：**+129.75**）、`hitTop = itemTop + 65 − 64.75 = itemTop + 0.25`（日志：74.69 = 74.44 + 0.25）。而 `bestHitH`（`:276` 那条）本来就绿 —— 高度是对的，只有中心错。
- **Collection #1**：几何那一半的前提（自然宽 > 框宽）随字体度量漂掉了（366 < 512）。换更长的探针串即可，判别式与容差**一个字没动**；契约那一半（`:10442` 的 `AutoSizing` 判别式）保持原样。
- **Collection #2**：纯次序问题。`B141_W53_Assert.Run(win)` 挪到 `RunCollectionCloseScrolls` 之前；`CheckB326Uv1(win)` 本来就在前面，未动。

## 四 · 与判据不一致的一处（请复核）

**Rewards #1**：`判据` §3·2 R-a 判它「字体面折算、按 `ActualFace` 重钉期望」。**本轮没按它改**，理由是：

1. 读口 `FontPxOf → lb.FontPxNow` **本来就是**按 `ActualFace` 的实例口（`RewardsScene.cs:13937-13941`），**不存在**「静态口」这一层可换；
2. 「重钉成 38.34」= 把一个**二分收敛值**写成字面量 —— 正是本文件自己写在 `CheckFontPx` 头上的禁令（`:13956`「只用在【没有自适应】的件上」）；
3. `38.34 / 34.5 = 1.1113` 与 `0.0948/0.0853 = 1.1114` 撞得太像，容易被当成「同一个 0.9 因子」；但那是**先验猜的比值**，而 `CheckFontWindow` 的路子是**原版四格**（30/35 × 1.15），不依赖任何字体常数。

⇒ 改成窗口断言（含「自适应确实开着」+「收敛值落在窗口内」两条守卫）。**若这一颗其实没开自适应，会红在 `AutoSizing` 那条守卫上** —— 那是明确信号，不是静默。**需一次 Unity 复跑确认**。
