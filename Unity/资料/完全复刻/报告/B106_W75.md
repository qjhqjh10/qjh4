## ② 逐条

### R6（α）`B106_W15_Assert.cs:65` —— 量纲用错，**但正确修法不是 `* 108f`**

**改前**（`:65`，单行，注意行号在本文件里已因 §R8 的改动下移）：

```csharp
float dyDesign = Mathf.Abs(bots.localPosition.y - touch.localPosition.y) / SettingsWindow.RootScale;
```

**改后**（`Editor/B106_W15_Assert.cs:72-73`）：

```csharp
float dyPx     = Mathf.Abs(LayoutSpace.PxY(bots.localPosition.y) - LayoutSpace.PxY(touch.localPosition.y));  // 画布 px（已含 0.9 缩放）
float dyDesign = dyPx / SettingsWindow.RootScale;                                                            // ⇒ 原版设计 px
```

🔴 **为什么不照施工单写 `* 108f`（举证）**：

1. 施工单说「`RootScale 0.9` 只是字号/内缩系数，**不参与坐标换算**」—— **不成立**。本窗所有节点都经
   `Node(...)` → `Screen(...)` 落位，而 `Screen` 就是**把原版 px 先按 0.9 缩一遍**：
   `Shell/SettingsWindow.cs:1584` → `float S(float v, float c) { return c + (v - c) * RootScale; }`
   （`Node` 在 `:6151`，`GenToggleRow` 里两行的 t = `GenChkT` = 446.11 / `GenChkT + ChkRowStep` = 526.751）。
2. 算一遍（逐位）：
   - 屏 y：`540 + (446.11 − 540)×0.9 = 455.4990` · `540 + (526.751 − 540)×0.9 = 528.0759`
   - `ΔlocalPosition.y = 72.5769 / 108 = 0.672008`（`localPosition` 是**矩形中心**，`MenuDraw.Local` → `LayoutSpace.RectCenter`）
   - 旧式：`0.672008 / 0.9 = 0.746675 ⇒ Mathf.Round = 1` —— **与日志「实得 1」逐位吻合**
   - 施工单写的 `× 108f`：`0.672008 × 108 = 72.577 ⇒ Round = 73` ≠ `Round(ChkRowStep 80.641) = 81` ⇒ **仍红**
   - 本次写法：`72.5769 / 0.9 = 80.641 ⇒ Round = 81` ✅
3. 同一条换算在本仓**已有唯一权威**：`Editor/SettingsScene.cs:126`
   `static float OrigPxY(float worldY) => 540f + ((540f - worldY * 108f) - 540f) / SettingsWindow.RootScale;`
   —— 即「世界 → 画布 px → **再 ÷ RootScale** 才是原版值」。本次就是照这一条写的（`LayoutSpace.PxY` 那一半是
   `540 − y×108`，与它逐位同源）。
   ⚠️ 施工单 §3.2 里那句「复算：80.641 ⇒ ΔlocalPosition = 0.7467」本身就是**漏了 0.9** 的算式
   （0.7467 = 80.641/108，那正是**没缩**的值；真实值是 0.672）。两条都能得到 `Round 1`，
   所以**「实得 1」不能用来区分两种假设** —— 这里只能靠代码链判。

**灭自证仍成立**：生成端改回 `GenChkT + 2f * ChkRowStep` ⇒ `dyDesign = 161.28 ⇒ Round 161` ≠ 81 ⇒ 红。

> 生产**没问题**（`Shell/SettingsWindow.cs:2331/2338` 两行的 t 值是对的），本条只改断言。
