## 一、β1 · `Shell/GameWindow.cs:804` —— `Close()` 跳过 `OnCloseWindow`

### 改前（原文，第 804 行）
```csharp
            gameObject.SetActive(false);                      // = 原版 `CloseWindowCO` 里那一跳 `Hide()` 的尾句（**排在摘表之前**）
```

### 改后（同一物理行，第 804 行）
```csharp
            Hide();   /* = 原版 `CloseWindowCO` 里那一跳 **Slot 9 `Hide()`**（`0x1c8`，与 `HideAllWindows.c:63` 互证）—— **排在摘表之前**。🔴 2026-10-30（`B101_W1` 同步点 β1）：本行原来是**内联它的尾句** `gameObject.SetActive(false)` ⇒ 只做了「物体置灰」，**跳过了** `SetBake(true)` / `CurrentState = Closed` / **`OnCloseWindow.Invoke()`**；原版那一跳是**整条 `Hide()`**、不是只有尾句（同函数 `:802` 的 baseMenu 支早就在调 `Hide()`，是同一处判据）。🟢 判别式：改回 `SetActive(false)` ⇒ 任何 `OnCloseWindow` 订阅方收不到通知（`Shop` 的 R10/R11/R12b 三条红），且 `Hide()` 那半句 `SetBake` 也不会跑。 */
```

### 判据
- 原版 `GameWindow.Close` 只做守卫 + 关窗音；实体动作全交给 `CloseWindowCO` 的虚表 **Slot 9 `Hide()`**（`0x1c8`）。
- 互证：`WindowsManager__CloseWindowCO.c` 那一跳 `(**(code **)(*param_2 + 0x1c8))(…)`；`HideAllWindows.c:63` 同一个 `0x1c8`。
- 本文件自己的旁证：同函数 `:802` 的 `baseMenu` 支**本来就是 `Hide(); return;`**；`:691-692` 的注释自己写着「`Close → CloseWindowCO → Slot 9 Hide()`」。
- `NotifyClosed`（`Shell/WindowsManager.cs` 的 `internal void NotifyClosed`）只做摘表 + `ShowPreviousWindow`，**不调 `Hide()`** ⇒ 换上 `Hide()` 之后**不会双调**。

### 净差到底有多大（**已逐句核过，别读成「改了很多」**）
走到第 804 行的**一定不是 `baseMenu`**（`:802` 那个支 `Hide(); return;` 在前）⇒ 对本行涉及的所有窗：
- `SetBake(true)` —— **空操作**：`SetBake` 首句是 `if (!IsBaseMenu) return;`（`GameWindow.cs:628`）；
- `CurrentState = Closed` —— **已写过**：`:758` 在 `Hide()` 之前就写了；
- `gameObject.SetActive(false)` —— 与原句**逐字相同**（`Hide()` 的尾句）；
- ⇒ **唯一的行为增量 = `OnCloseWindow.Invoke()`**（`GameWindow.Hide` 末两句）。这也正是原版那一跳的语义（`GameWindow__Hide.c` 末句）。
- 反过来说：**baseMenu 那条路一个字都没变**（它本来就调 `Hide()`），`T16` 注释里「常驻主菜单会经 `Hide()` 再烘一次、与原版同为两次」那句**仍然成立、也没被本次改动带偏**。

### 判别式（怎么改回去会让哪条断言红）
把第 804 行改回 `gameObject.SetActive(false);` ⇒
1. 任何 `OnCloseWindow` 订阅方**收不到关窗通知**（`CardInBoosterPack.CardDisplayWindowOnCloseWindow` 那条原版链；本仓今天**零订阅者**，但事件口本身是原版行为）；
2. `Shop` 的 **R10 / R11 / R12b** 三条红（它们就订阅这个口）。

### ⚠️ 顺手发现（只报不改）
`Shell/CardDetailPopup.cs:948` 的 `Close()` 先调 `ResetFanState("Close")`、再 `base.Close()`；换上 `Hide()` 之后基类那一跳会走**虚函数** `CardDetailPopup.Hide()` → 再 `ResetFanState("Hide")` **一次**。
- **功能上无害**（幂等：`_swapping=false`、`SettleLevelUpAnimation()`、`DOKill` 都是幂等；`TopBar.ToggleOverlay(false)` 也是幂等关），
- **只是多打一条日志**（`gameObject.activeSelf` 在第一次 `Hide` 之前还是 true ⇒ 第二次 `ResetFanState` 仍会 `wasUp=true` 并打印）。
- 是否要把 `CardDetailPopup.Close` 那句 `ResetFanState("Close")` 删掉，**不在本简报范围**，留调度台判。

## 二、β2 · `Shell/ErrorPopupWindowController.cs:82` —— 窄谓词冒充「能不能取到文案」

### 新增（唯一一份三档判据）：`CardPresentation/Core/Loc.cs` **类尾**（原第 3946 行前，现 3947–3965）

```csharp
    public static bool HasAnyTerm(string key)
    {
        if (string.IsNullOrEmpty(key)) return false;
        return HasEntry(key) || HasBulk(key) || !string.IsNullOrEmpty(Lang13Of(key, "en"));
    }
```
（带 18 行 doc，写明「`HasEntry` 只查手写 `Table`（754 条）」与三档顺序，以及「⛔ 别拿它替代 `HasEntry` 的既有调用点」。）

- **为什么放类尾**：`Loc.cs` 被账按行号引用（最高 = `:3942` = `Warcry`），插在中间会整片漂移。插在 `Warcry` 之后 ⇒ 只有文件末尾 2 行（类/命名空间闭合括号）往后挪，**没有账落在那儿**。
- 命名：现场风格是 `HasEntry` / `HasBulk`；本口是「任意一档有」⇒ `HasAnyTerm`（⛔ 不叫 `HasTerm`，免得和 `ErrorPopupWindowController.HasTerm(CustomError)` 混）。

### 调用点改前 → 改后（三处，均在白名单内同一物理行）

| 行 | 改前 | 改后 |
|---|---|---|
| `:82` | `return Loc.HasEntry(TermOf(customError));` | `return Loc.HasAnyTerm(TermOf(customError));`（doc 就地扩写，**同物理行**扩为一行 `<summary>`，行数不变） |
| `:95` | `if (Loc.HasEntry(term)) text = Loc.T(term);` | `if (Loc.HasAnyTerm(term)) text = Loc.T(term);` |
| `:100` | `text = Loc.HasEntry(TermFallback) ? … : "";` | `text = Loc.HasAnyTerm(TermFallback) ? … : "";` ← **简报只点名两处，这是第三处同族** |

### 为什么第三处也改（铁律 14 的「迅速」三条全中）
`CustomErrors/UnhandledError`（回落键）**同样不在手写 `Table`**、在官方 13 全表里 ⇒ 旧写法让「回落文案」变成**空串**（一块空白 = 静默失败）。判据已查清、改动就在本文件、改完当场 typecheck 过。

### 判据
- `CLAUDE.md` §三：「判『会不会把键名印到屏幕上』必须**三档一起算**」—— `Loc.T` 的取值是四段：`Table` → bulk（`official_names.json`）→ **官方 13 语言全表（`official_loc_13lang.json`，现读 10,862 键）** → 缺键档。
- 现读数据（`python -I` 直接查 `Resources/official_loc_13lang.json`）：
  - `CustomErrors/InternetUnreachable` → **True**（在官方全表；手写 `Table` 里 `grep` 0 命中）
  - `CustomErrors/UnhandledError` → **True**（同上）
  - `CustomErrors/ErrorCloudscript` → **True**
  - 总键数 **10,862**
- 旁证：`Loc.T` 自己的注释（`:3436` 一带）写明三档顺序；同族先例 = 各处 `Lang13Of(键, "en")` 判「官方表里有没有」。

### 判别式
把 `HasTerm` 改回 `Loc.HasEntry` ⇒ **`Shop` 的 S5**（`Editor/B97_REMOTE1_Assert.cs:143`：`Tr(ErrorPopupWindowController.HasTerm(CustomError.InternetUnreachable), "S5 词条 … 在本地化表里")`）立刻红。

### 判据（本批回归的根因）

也就是说：这是**探针没跟上实现**（γ），不是实现错。`CardView.Create` 的 `face` 形参本就在（`Core/CardView.cs:2186`，默认值 `CardFace.Full`），只需传进去。
