## 一 `:254` / `:255` ①：`GetChoiceOptions` 收进引擎

### 1·1 判据（现读，第一权威）

`decomp_full/BattleManager__GetChoiceOptions.c` **全文 61 行**：

- `:40-43` `iVar1 = min(fullPool.Count, *(criteria + 0x40))`（`+0x40` = `choicesDefinition.maxTargets`）
- `:46-70` 循环 `iVar1` 次：`iVar3 = GetRandomInt(0, fullPool.Count)`；越界（`>= Count`）⇒ 置 0；
  `item = fullPool[iVar3]` → `options.Add(item)` → **`fullPool.RemoveAll(同 uniqueId)`**
- `:75-100` 补齐：`options.Count < iVar1` ⇒ 先把 options 里每张按 `LastIndexOf` 从**副本**摘掉，再从副本**头**（`get_Item(0)` + `RemoveAt(0)`）补到 `iVar1`
- `:110-113` `if (options.Count <= iVar1 && param_4 == '\0') options.Sort(SortByCostAndName)`

两支调用方：`ChoiceOfCardPlayer.c:27` 传 `0`（**一定排**）· `ChoiceOfCardEnemy.c:31` 传 `bVar5`（= 非联网 ∧ 非 replay）⇒ **敌方档不排，取 `options[0]`**，再用 `IndexOf` 翻回全集下标。

### 1·2 改了什么

1. **`EffectResolver.BuildChoiceOptions(ctx, cands)`**（`:19644`，`public static`，类尾追加）——逐句照上面那段：
   `left = 池`（就地 `RemoveAll`）· `backup = 池.ToList()` · `n = min(池, maxTargets)` · 循环抽 → `RemoveAll(同 Id)` ·
   不够再从备份头补。产出同时写进 `ctx.ChoiceOptions`（`BattleContext.cs:2656`，**同一份**给面板）。
2. **`TakePickCard` 开头一行**（`:4523`）：`ctx.ChooseSites++; var __choiceOpts = BuildChoiceOptions(ctx, cands);`
   ⇒ **开面板之前**先按原版消耗 `N` 格随机（原版就是这样：两支都在弹面板前调 `GetChoiceOptions`）。
3. **`TakePickCard` 末行**（`:4556`）：面板没答案 ⇒ `__choiceOpts.Count > 0 ? __choiceOpts[0] : cands[GetRandomInt]`。
4. **`BattleContext`**：`ChoiceOptions`（只读表）· `ChoiceOptionsSource`（是哪张卡算的）· `internal SetChoiceOptions`。

### 1·3 🔴 指纹影响（必读）

`MatchData.GetRandomInt` 是「**预烧 100 整数 + 按下标取、每取一次游标前进一格**」（`BattleContextRandom.cs:62-70`）。
接上之后，**凡是走 `choosecard` 的那几次结算，整局随机流会多消耗 `N-1` 格** ⇒ 之后的每一次随机（随机目标 / `RandomizedOnResolution` / 洗牌以外的抽取）**全部位移**。

- **选中的那张不变**：`options[0]` 就是第 1 次抽到的 `pool[idx]` —— 与旧实现 `cands[GetRandomInt(0, count)]` 同一张（断言 A2 就是钉这个）。所以**玩家可见的选牌结果不变**，变的是「之后的随机序列」。
- ⇒ `play all dump` / `play check` **必须整批重钉基线**（调度台做，⛔ 代理不重钉）。
- 兜底：`maxTargets <= 0`（缺值 `-1` / 合法 0）**不抽**、返空表 ⇒ 调用方退回旧口径（`🔶 自己设计` 一格，理由见 `BuildChoiceOptions` 的 doc：原版在这两档返空表后 `ChoiceOfCardEnemy.c:34` 会对空表 `get_Item(0)`，我们不照抄那次越界）。
- ⚠️ **另外还有一条算进指纹的东西**：`ctx.Log` 是 `Events.Add(message)`（`BattleContext.cs:1855-1859`），而 `Events` **没有任何 drain、却被算进 `Fingerprint`** ⇒ 本批新增的**两条日志**（`BuildChoiceOptions` 的「抽出 N 张」/ 缺值那句）本身也会让指纹变。⇒ 重钉基线时**别把这两句日志当成噪声删掉**（它们是「不许静默失败」那一条的要求）。

### 1·4 残余（如实）

- ③ **面板仍自己抽**：`BattleDriver.ShowAsk`（`CardPresentation/Battle/BattleDriver.cs:11234`）用 `Ctx.ShowRng` 的 `DrawForDisplay`，引擎用 `ctx.GetRandomInt` ⇒ **两份不是同一份**。「同一处算」要改面板读 `ctx.ChoiceOptions`（面板 = 调度台文件，本代理白名单外）。

- ⑤ `ChoiceOfCardPlayer`（账 255）与本行**共用同一份实现**（`TakePickCard` 只有一个调用点：`DoChooseCard`）。
