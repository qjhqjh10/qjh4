### §1·a L242 的语义逐句对齐（`.c` 现读）

命中条件（`.c` 的 `do/while` + 两段 `if`）：

1. `queue[i].casterCard` **非空** 且 `== jammedUnit`
   （`.c` 的 `local_58` = 缓冲区 + **0xD8** = `BattleAction.casterCard`；偏移判据 = `Core/ActionPump.cs` 类尾「五、②」那张表 + `BattleAction.cs` 字段声明序，两处吻合）。
2. `actionType != 1`（attack 不撤）——`.c` 那个 `while` 条件的第二支。
3. `targetCard == null` **或** `queue[i].targetCard == targetCard`
   （`.c` 的 `local_120` = 缓冲区 + **0x10** = `BattleAction.targetCard`）。

命中之后**三个「结束整条泳道」的豁免**（`.c` 里三处 `return`，不是「跳过这一条」）：

- ⓐ `actionType == 0x2d`(45 destroyUnit) **且** `deathType == 0x28`(40 poison)
  （`local_40` = 缓冲区 + **0xF0** = `BattleAction.deathType`；偏移判据 = 字段声明序 + `bool keepEffects(+0xEC)` 之后的 4 字节对齐）。
- ⓑ `actionType == 0x1a`(26 recallToHand)
- ⓒ `shouldIgnoreDestroy` 为真 **且** `actionType == 0x2d`(45)

否则 `CustomDebug.LogWarning("Removing action from queue from card " + cardName + ", " + type)` 后
`CancelBattleActionFromQueue(queue, i)`。

**为什么今天两处缺口无可观测差异**：

- `ActionType` 今天**恒 0**（`QueuedAction.ActionType` 的 doc 自己写着「今天所有入队点都没写这一格」）⇒ 三个豁免与 `attack`/`createHandCard` 两个副作用**结构上走不到**。
- `Target` 今天几乎恒 `null`；而原版四个调用点里**三个**传 `targetCard = null`（`ResolveJamUnit` / `ResolveAction` jam 支 / 本批不涉及的其它），只有 `RemoveSelfBuffsFromQueues` / `ResolveTransformUnit` 传「自己那张」——那两条本批没接线。
- `Actor` 作为 `casterCard` 的等价物：`RuleCore.FireTriggerAt`（`RuleCore.cs:12706` 一带）传 `actor: u`，`u` 就是**这条触发归属于哪张卡**，与原版 `casterCard` 同语义（⛔ 不是 `actingCard(+0x08)`，那在原版是另一格）。
