## 二 · #2 `targetWillDieFromThis` 的判死口径（结构差 #30 的「守方那一半」）

### 改动（`RuleCore.cs:6813`，零行数变化）

```csharp
bool targetWillDieFromThis = targetDied || WouldKillByEntries(target, new[] { atk });
// 改前：targetDied || DamageAfterReduction(target, atk) >= target.Health
```

### 为什么用 `WouldKillByEntries` 而不是施工单字面的 `EnoughPendingDamageToDie(target)`

施工单原文：「从 `DamageAfterReduction` 改成 `EnoughPendingDamageToDie(target)`」。
**本工程里那个同名函数不行**：

- 我方的 `RuleCore.EnoughPendingDamageToDie(u)`（`RuleCore.cs:7730`）体内只有一句
  `return u.Health <= 0 && u.Survivor <= 0;` —— 它读的是**已经落账的血**，**不看待结算 entries**。
  （这是设计使然：我们逐段现结伤害，没有原版那张 `pendingDamage` 表。）
- 原版 `CardScript__EnoughPendingDamageToDie.c`（现读全文）走的是
  `pendingDamage[0] > 0 || CurrentSurvivor != 0` → `EnoughPendingDamageToDieWithDamageValues(card, dmgList, typeList)`，
  **是把待结算的逐条伤害喂进判死算式**。
- ⇒ 照字面替换会把「**这一下会不会打死它**」退化成「**它是不是已经死了**」——
  而前半句 `targetDied ||` 已经覆盖了那个语义，整格等于**被废掉**（恒定跟随 `targetDied`）。

**正确的等价物 = `WouldKillByEntries`**（`RuleCore.cs:7789`，doc 明写「原版
`EnoughPendingDamageToDieWithDamageValues` 的等价物」，含 护甲 / 盾 / 闪避 / 无敌 / 幸存者 / 堡垒 / 空投舱 七档）；
**Strike 那一半（`RuleCore.cs:6816`）用的就是它** —— 同一个函数里上下两句同族，口径一致。

⇒ 净差异 = **原来漏掉 幸存者 / 堡垒 / 空投舱 三档**（`DamageAfterReduction` 只做 盾/闪避/无敌/护甲/易伤）。
