## 6 顺手发现（⛔ 不只放在对话里）

1. 🔴 **`RawCardScript.stratagem` 这个公开属性是常量假**（`Warpforge_code/Scripts/Assembly-CSharp/RawCardScript.cs:235` → `public bool stratagem => false;`），而 `ShuffleCardList` 读的是**序列化字段 `_stratagem`**（`RawCardScript.cs:159`）。全池 1,351 张 SO 现扫 `_stratagem` **0 命中**。⇒ 「洗牌的钉位支」**永远走不到**，任何为它写的代码都是零可观察。**建议**：把这条写进洗牌那一族的 doc，避免下一个代理再花一轮「实现钉位」。

2. 🔴 **`CreatePlayerDeck` 在非教程局就传 `checkStratagem: true`**（`out_cpp2il_dev_ilspy/BattleManager.cs:15705`）—— 旧账「原版只在轮抽/战术起手用」是错的。虽然数据空使它净等价，但**口径要改**，否则将来有人「按旧账」把它当轮抽专属。

3. 🔴 **`BattleManager.AddCardToDeck` 与 `BattleCardManager.AddCardToDeck` 是两份**（后者少了 reparent 两句），**两份都 0 调用点**。⇒ 如果我们将来要建「按下标插牌」，**照 `BattleCardManager` 那份建**（更窄、且没有一坨 transform 操作），⛔ 别照 `BattleManager` 那份（它多出的 reparent 在引擎里没有对应层）。

4. 🟡 **`CardScript.RemoveCardFromCemetery` 的实体只有一句 `+0x24b = 0`** —— 这条几乎被所有旧账当成「墓地移除功能」，实际上它只是清一个重入闸。⇒ 所有「原版有『从墓地移除』功能」的推论都要重新过一遍（含 `CemeteryManager.RemoveFromCemeteryList` 那一族）。

5. 🟡 **原版 `PlayerHand.LightPlayableHand` 是「逐张调 `CanPlayCard(card, showTips:false, initiateAction:false)`」**，而我们的等价物 `BattleDriver.RefreshHandPlayable` 用的是**本地近似**（`card.Cost <= p.Energy && (IsUnit ? hasSlot : true)`）—— **不走 `CanPlayCard`**。后果：封阻队列 / 教程闸 / 法术目标存在性 / `Cost<0` / `IsEnchantment` 这几档在手牌高亮上**完全不生效**（例如「手里这张法术现在没有任何合法目标」我们照样亮）。
   ⚠️ 按 A 尺子这属 `HUD` 行的缺口，⛔ 不在我这 39 行里 —— 我把它记在这里，请调度台分流给战斗界面/HUD 那一批（落点 = `BattleDriver.RefreshHandPlayable`）。

6. 🟡 **`BroadcastQuestResolved` 这条广播的「另一半」被两处账各认了一半**：`EffectResolver.cs:18079` 自己写着「仍缺」、而 `战斗逻辑驱动` 里这一行又被记成 B 并指到 `QuestPointThreshold`。⇒ 这是「**一个功能被拆成两行、每行都以为另一半在做**」的典型（与 CLAUDE.md 里 `ResolveCardAutoSummoned` 那次同型）。已在本轮把它并成一行并改指落点。

7. 🟡 **`UpdateManaLeftAccumulation` 的 `turn > 1` 闸** 是一条**只有遭遇模式能观测**的差异（经典 `manaAccumulation = 0` ⇒ 恒早退）。如果哪天真机验遭遇模式发现「第 2 回合能量多 1 点」，根因就是这里 —— 已写成一行级施工项。

8. 🟡 **`cardState` 的缺失是 5 行的共同根因**（附录 C·①）。补它不是一个「小字段」：要同时补 `CancelAttack` 的状态闸、`ActivateMinion` 的 `==2` 闸、`ResolveMinionDeath` 的 `==5` 闸、`SetAsUnitDestroyed` 的写值，以及「谁在什么时候把状态从 2 改成 3/0x11/5」。**建议派一路专门做 `cardState` 状态机，别分散到 5 个写手**。
