三处判据：

- **起点 `useCenter:false`**：`.c:24` 取的是 `get_transform(cardOrigin).position`，**没有任何 `useCenter` 分支**；`useCenter` 只出现在 `.c:18`（`param_3` = target）。`Get2DPosOfCard(caster, false)` 自带**同一跳**投影（`BattleDriver.cs:37034-37036`，`boardCam.WorldToScreenPoint` → `cam.ScreenToWorldPoint(z = HudCanvas.PlaneDistance)`），基准是裸原点 ⇒ 与「原版在 `PrepareMovement` 内部投影 `transform.position`」逐句等价。
- **终点 `useCenter:true`**：`.c:18` 第 4 实参 = `1`；`useCenter` 真 ⇒ `GetEffectAnchor().position`（`Get2DPosOfCard.c:29-31`，我们的等价物 `CardView.EffectAnchor(true)`）。
- **去掉 `ResolveAim`**：我们的 `_cross` / 弧线吃的是 **HUD 画布平面**的点（`TargetReticle.Show/Aim/AnimTo` 把入参**原样**写成 `localPosition`，`TargetReticle.cs:570/593/617`），而 `TargetReticle.ResolveAim`（`:511-547`）返回的是**战场帧**的点（`boardCam` 射出的屏幕点 → **hudCam** 射线 ∩ `enemyMinionPlane`/`floorPlane`，`LastAim` 就是世界交点）。它本来是给**指针**用的（指针求交后还要抹 z），拿它去处理**已经算好的目标点** = 跨帧，而且 HUD 相机正交时射线平行于 floor ⇒ 那一支恒打空。原版终点走的是 `DoCrosshairMove`（`set_position`），**根本不经过 `UpdateTrail`**。
- **注释就地订正（铁律 5）**：`.c:22-24` 那个位置是**起点**，`.c:18` 才是终点；`B92_B3c` 原注释两处都写反了，已留更正痕迹。

### 3) 连带：`Editor/BattleScene.cs:10569-10570`

```csharp
// 改前

// 改后
Vector3 toW = driver.PointerAtWorldForTest(driver.MyUnits[vicSlot].transform.position);
```

为什么必须一起改：第 ③ 条断的是 `frac = |p1.x−p0.x| / |toW.x−p0.x|`。
