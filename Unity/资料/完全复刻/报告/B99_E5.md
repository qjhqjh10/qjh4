## 一、结论

1. **主活已落**：`BattleDriver.ShowSkillPanel` 里原来**各自现写**的两格改为走**唯一读点**
   `BattleDriver.SkillPanelLoadingFlags(u, out requiresLoading, out abilityLoaded)`（新成员，追加在类尾）：
   - `requiresLoading` ← **`UnitState.RequiresAbilityLoading`**（原来是**卡级** `CardDef.HasActiveAbility == 1 && …` 自己拼一份合取）；
   - `abilityLoaded` ← **`UnitState.ActiveAbilityLoaded`**（原来写死常量 `false`，注释理由是「我们没有装填机制」—— 该理由
     在 `B97_W22` / `B98_K2`（2026-10-29）建好装填机制之后**已过期**）。

   **`CardScript` 实例字段** `+0x220`；改前的卡级读点**看不见两个实例位** —— 教程关闸 `ActiveAbilityHidden`
   与 jam 压制 `ActiveAbilitySuppressed`（两者在原版都把 `+0x220` 写 0）。改后同层。
3. **方向没有反**（`.c` 为准，见 §二·3）：原版**先** `DoesAbilityRequireLoading()`、**再**读 `+0x224`，
   两格互相独立（`loaded` 变真不改 `requires`）—— 断言 `A2′` / `B1` 把这条方向钉住。
4. **今天行为零变化**（诚实标注）：全池 `needsLoading` 现读全 0 ⇒ `RequiresAbilityLoading` 恒假、
   `StepActiveAbilityLoading` 也不写位 ⇒ 面板描述链仍落第三档。**本条是「休眠但照建」（铁律 11）**，指纹预期零。
5. **引擎侧接口对得上**：`u.RequiresAbilityLoading`（`UnitState.cs:3974`）· `u.ActiveAbilityLoaded`（`:3741`，
   写点 = `:2674` 复位 + `:3994 StepActiveAbilityLoading`）· 唯一产品调用点 = `RuleCore.cs:11623`（`B98_K2` 建的，现读仍在）。
   **没有发现接口缺口。**
