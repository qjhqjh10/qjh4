## Warlord 技能的读取路径（`CardDef` 还是快照）—— 现读证据

**结论：读 `CardDef`（经 `CardInstance.Card`），`UnitState` 上【没有】能力快照。**
所以原版那一格「换」在我们的等价形状 = **换一个引用**（实例级覆盖位），不是重建 `UnitState`、也不是改 `CardDef`。

| 跳 | 现读证据 |
|---|---|
| 督军载体 | `PlayerState.Warlord` 是 `UnitState`（`Core/PlayerState.cs:71-72`，注释明说「和 `Board[BoardSpec.WarlordSlot]` 是**同一个对象**」） |
| 单位 → 卡 | `UnitState.Card { get { return Instance.Card; } }`（`Core/UnitState.cs:36-40`） |
| 卡实例 → 定义 | `CardInstance.Card` 是 **`public readonly CardDef Card`**（`Core/CardInstance.cs:57-58`，注释「不可变定义，全场同名卡共享同一个对象」） |
| 能力正文 | `UnitState.Ability { get { return Card != null ? Card.Ability : null; } }`（`Core/UnitState.cs:985`）—— **每次都现读卡面，无缓存** |
| 「有没有主动能力」 | `UnitState.ActiveAbilityAvailable`（`Core/UnitState.cs:3190`）= `Card.HasActiveAbility == 1 && !ActiveAbilityHidden && !ActiveAbilitySuppressed`（同样现读卡面） |
| 费用 | `CardDef.ActiveAbilityManaCost`（`Core/CardDefActiveAbility.cs:71`，唯一写点 `AttachActiveAbilityCost` `:100`，数据来自 `CardDatabase.cs:1744`）；闸在 `RuleCore.AbilityCostGate`（`RuleCore.cs:15310` 附近，读 `oathUnit.Card`） |
| 每回合 / 每局计数 | **在 `UnitState` 上、不在卡上**：`UsedActiveAbilityThisTurn`（`UnitState.cs:760`）、`ActiveAbilityUsed`、`ActiveAbilityLoaded` —— 原版也是实体级（`CardScript +0x4c / +0x50 / +0x224`），`ReplaceHeroPower` **不清**它们（我们照抄，不清） |

⇒ 因此 `HeroPowerOverride` 放在 `UnitState`（实体级）是**与原版同层**的；⛔ 不放进 `CardDef`（全场共享不可变，
写它会污染全池 —— 同 `ActiveAbilityHidden` 的既有裁定 `UnitState.cs:3473-3476`）。

## 顺手发现的东西（⛔ 均未动手改）

1. 🔴 **施工单 C09 的前提与二进制不符**（已在上面展开）：`ScriptedActionType` 无 24；`ReplaceHeroPower` 三源 0 调用。
   ⇒ 同批的「教程动作 24 静默进 `Unknown`」这句**不成立**：那条动作**造不出来**（`data[0].type` 只能是
   `ScriptedActionType` 的值）。**建议**：`判据/B109_R16_死码C45.md` 的 C09 行与「最该先做的 3 条」那句应订正（该文件是判据件，不在我白名单）。
2. **`BattleManager__ResolveAction.c` 的 switch 缺 8 个 case**（`2/6/8/0xc/0x18/0x20/0x21/0x28`）。
   其中 `2 createMinion` / `8 doDamage` 这种一定是有体的 ⇒ 凡「靠 `ResolveAction.c` 找 case」的判据
   **都可能踩空**。建议记进「已知的坑」：**这份文件的 `switch` 不能当「哪些 action 有分支」的穷举**。
3. **`BattleActionType` 枚举在 `TutorialScript.cs:96` 里**（不是单独文件，也没标「这是抄来的枚举」以外的说明）。
   它服务的是白名单闸门 `CheckIfMatchesActionData`，与 `ScriptedActionType` 同文件但**完全不同用途** ——
   施工单把它们混了，很可能就是「教程动作 24」这句误会的来源。
