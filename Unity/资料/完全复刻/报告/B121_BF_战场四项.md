### T06·残余·renderqueue 同名（`？ 判据未定` → 本批落地「不静默」那一半，真正的按资产区分**未做**并说明了原因）
- 现状：`工具/gen_renderqueue_truth.py` 对同名多值 `mat_table[k] = sorted(v)[0]`（取 min，只把冲突记进 `_conflicts`）。
- 现读只有 2 条冲突，逐条查实（`assets_full` 直读）：
  | 材质名 | 取值 | 来源包 | 生效队列 |
  |---|---|---|---|
  | `Campaign Points` | −1 / 3000 | `shaders_assets_all` / `menusharedresources_assets_all` | shader `Everguild/UI/Campaign Points` QUEUE = **3000** ⇒ **两者生效值都是 3000** |
  | `SandParticle` | 3000 / 3001 | `battleprefabs_vfxandmisc_assets_all` / `battlesharedresources_assets_all` | shader `URP/Particles/Unlit` **没有 QUEUE tag**（默认 2000）⇒ **真歧义** |
- 改法（已落）：① 先按**生效队列**判，一致就用那个值（`Campaign Points` −1 → **3000**，与原行为链等价）；
  ② 真歧义（`SandParticle`）**保持 min=3000**（= 消费方 `EffectExporter` 实际读到的那一份），
  ③ 但**不再静默**：每个冲突**逐条打印**（取值 + 生效值 + 包 + JSON 路径），并写进 `_conflicts` / `_conflict_sources` / `_conflict_policy`。
- 🔴 **为什么没选「冲突项不进 mat 表」**：实测会回归 —— `SandParticle` 的 shader 没有 QUEUE tag，
  丢表后 `WarpforgeEffectBinder` 走 `d.renderQueue = −1` ⇒ 不覆盖 ⇒ 落回 shader 默认 **2000（不透明）**，原版是 **3000**。
- 真正彻底的解 = 让消费方（`EffectExporter.TruthQueue`）带 **bundle 维度**（同名两份是两个不同资产），
  这要改 TSV/JSON 键与调用点 ⇒ **不在本批文件白名单内**，留给调度台裁定。
- 产物：`mat_renderqueue.tsv` diff **3/3**（`Campaign Points` −1→3000 ＋ 两条冲突项回到首次出现位置）；`shader_renderqueue.tsv` 0 变化。

### T09·Timeline 地堡门（`⏸ 等战场线恢复` → 离线部分**做完**，剩 Unity 重建 + 真机）
**判据（原版）**：`battlesharedresources` 的 `Bunker Door Parent` 上 `PlayableDirector 7845524703085758649`

Animation Track 的 `m_InfiniteClip` = `Recorded`（17.133 s）⇒ 原版进图门自动循环播。

**本批落地（三个文件）**
1. `工具/gen_arena_timeline.py`（新）—— **直读原版包**（UnityPy 读 `scenes_scenes_battlearenaleviathan.bundle`
   与 `battlesharedresources_assets_all.bundle` 的 typetree）抽出 director / track / clip / exposedName / 种子，
   产出 `数据/游戏数据/arena_timelines.json` ＋ `Resources/arena_timelines.json`（两份逐字节相同）。
   有 `--write / --check` 两个显式动作；不带参数 = 用法 + rc 2。
2. `WarpforgeVFX/Runtime/ArenaTimelinePlayer.cs`（新）—— 运行时按 JSON 重建 `TimelineAsset`
   （1 条 AnimationTrack + 4 条 ControlTrack / 7 个 `ControlPlayableAsset`），
   绑 `m_SceneBindings`（track→`Bunker_door`）与 `m_ExposedReferences`（7 个 exposedName→目标 GO，
   用 `PlayableDirector.SetReferenceValue`，与原版把引用存在 director 上同构），
   再按原版四个状态字段起播（Loop · 从 15.0 s · GameTime）。取件口 = `WarpforgeAnimatorBridge.TryGetClip("Recorded")`。
   读数口：`LastDirectors / LastTracks / LastClips / LastMissed / LastMissedWhat`（给将来的自检与真机日志）。
3. `WarpforgeArena1/Editor/ArenaBuilder.cs` —— 新增 `ApplyArenaTimelines`（类尾，`:6465`），

**与规范的偏差（有意的，已写进代码头注）**
