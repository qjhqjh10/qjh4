# B110_F2 · 「原版 `quantity` 传进物品窗」最后一跳（`ItemDrawerView.HandlePointerClick`）

## 一句话结论

**接上了。** 物品窗那一半（`ItemDisplayWindow.Context.Amount` / `ShowAmount` / `BuildAmount`）早就在，
缺的**抽屉那一路的生产者** `ItemDrawerView.HandlePointerClick()` 现在已经把抽屉实例上的
`Quantity`（原版 `+0x40`）与「这一族抽屉会不会画数量行」一并交给窗：

## 五、没查清的部分 / 边界（如实记）

1. **断言未接宿主**：9 个断言宿主不在本代理白名单。`Editor/B110_F2_Assert.cs` 现在是**零外部引用**
   （与 `C2_Assert.cs` 同一状态）。接法（调度台做，**同一物理行、第一个 `//` 之前**）：
   `B110_F2_Assert.Run(); pass += B110_F2_Assert.Pass; fail += B110_F2_Assert.Fail;`
   本件自足（自己 `WindowsManager.Get()` 建壳、跑完关窗拆对象），接哪个宿主都行。
2. **本件没跑过 Unity**（铁律：执行代理不跑批处理）⇒ 断言**只是编译过**，没有一次实跑读数。首次接线时请看它的合计行。
3. **`HasQuantitySlot` 按「族」判，不按「实例」判** —— 这是本仓 `ItemDrawer.Draw` 的选法（`PickDrawer` 只挑族）。
   两处提请注意：
   - **旁挂变体** prefab 常有另一套槽位组合：`AvatarDrawer` 在 `General Basic Offer Container Variant …` 里有 10 份是
     `quantity` 非 null、`Content/Label` 关；`ContainerDrawer` 只有 `Container Drawer` 本体是两道闸都过。
     若将来某条奖励**真从旁挂变体走**，这张表要改成「按实例」（今天不存在那条路）。
   - 🔴 **Icon 档与主档同类名、槽位不同**（本批已就地出声）：`ItemTypeSets` 里 `Currency` / `Container` / `CampaignPoints` /
     `ExpansionPassPoints` / `AllianceTrophyData` / `DropTableItem` 的 **Icon(10) 列写的仍是主档类名**，
     而它们的 Icon 变体 prefab（`Icon Currency Drawer Variant` / `Icon Container Drawer Variant` / …）的
     `quantity` / `label` **全是 `{fileID:0}`、`Content/Label` 也不在** ⇒ 原版那一档**不画**。
     `HasQuantitySlot` 现在对这 6 族**按主档给 true 并 `Note` 一次**（如实记：今天的生产者不传 `DrawerOverride`
     ⇒ 没有「按 override 判」的输入）。⛔ 这是**已知口径缺口**，不是判据不确定 —— 判据齐，缺的是调用方的 override。
4. **`Context.Amount` 的默认值仍是 0**（struct 表达不了原版 ctor 的默认实参 1）——
   本批把**唯一生产者**接上了，`ForCardback` 也一直显式给 1；但**新调用方**若开 `ShowAmount` 却忘给 `Amount`，仍会印 `"0"`。
   这条已由断言 C 段（`ForCardback`）与 B 段（3 / 7）共同钉住，但**没有**在 `Context` 上加运行时兜底
   （改了就等于替调用方猜，与原版「ctor 默认实参」不是同一件事）。

## 六、顺手发现（⛔ 未改，超出白名单）

1. 🔴 **`判据/B109_R21_G5判据缺口.md` 的 N30 有一条会做错的施工单**：
   它建议把 `ItemDrawerCosmetic.cs:122` 从 `hasName: false, hasQuantity: false` 改成 `hasName: true, hasQuantity: true`，
   依据是「`Cardback Drawer.prefab:466-469` 现读 `label` 与 `quantity` **都非空**、`CosmeticItemCardback` 的 `showName=1 ∧ stackable=1`」。
   **本批现读的结论相反**：那两个槽非空，但它们的宿主节点 `Content/Label`（`Label_-8075592410334473988`）`m_IsActive = 0`，
   而原版 `ItemDrawer<object>.Draw` **只会激活 `Name` 那颗 TMP 自己的 GameObject**（本来就 active），**从不激活 `Content/Label`**
   ⇒ 原版在卡背这一族里**名字与数量都不显示**。照那条施工单改 ⇒ **比原版多画两行**（可见偏离）。
   ⇒ 建议调度台按本批证据把 N30 的 ② 半条划掉（本代理未动那份判据文件，它在白名单外）。

   值得抄进 `资料` —— 之前几轮都在用 `+0x38 = quantity` 这个偏移，但**没人把整张偏移表落过盘**。
3. `ItemDrawer.cs:1689` 同一行上已有两处历史注记（`Art` 那格、`ArtName` 那格）；本批又append 了一段，
   **该行现在很长**。下一次要改这一行的人请注意：追加必须落在**行内第一个 `//` 之前**，否则代码会被注释吞掉（本仓踩过 6 次）。

   但 `Amount` 仍应照原版传 `quantity`（原版实参 `(item, quantity)`），doc 段也要按铁律 5 就地订正。**建议调度台另开一条小账**。
