## §6 顺手发现（⛔ 未改任何东西，交调度台分流）+ 工具用法

### 6-1 🔴 `lea=0` ≠「没被取址 / 没有委托」—— 本批最贵的纠错
`VIPCardShopTab.VipTimerOnOnRunOutOfTime` 普查 **`E8=0 lea=0 dec=0 il=0`（三源 0）**，
而它在 `out_cpp2il_dev_ilspy/VIPCardShopTab.cs:237` 明确写着 `Action value = VipTimerOnOnRunOutOfTime;`。
同类还有 `RankedTab.InitializeFactionScores`（`Action<LeaderboardResult> onComplete = InitializeFactionScores;`）。
⇒ **普查的 `lea` 不能当「地址没被取」**；判「有没有人引用」必须补 `out_il2csharp` / `out_cpp2il_dev_ilspy` 里的**同类方法组**（本批靠这条把 58 条从「D」翻成「要做」）。

### 6-2 🔴 `dec=1` 可能是「自我 ICF 别名」不是调用者
`RankedArmySelectorContainer.ToggleInteractable` 普查 `dec=1`，`decomp 调用者: ArmyItemContainer__ToggleInteractable.c`；
但那个文件的 line2 是 `void RankedArmySelectorContainer__ToggleInteractable(...)` —— **它就是本方法**（ICF 折叠 / 文件名≠内容），**不是调用者**。
同类：`BoostTimerPanel.SetDescription`（`LoginScreenManager__SetMessage.c` 实为自身）、`EventProgressBarController.ToggleRectMask`、`RewardProgressBarPanel.CollectButtonClick`。
⇒ 判 `dec` 时必须看「调用者文件第 2 行是不是自己」；**列 0 的定义行 = 不是调用**，**缩进的 `Class__Method(` = 真调用**（本批用这条把 16 个假 REAL 收敛到 1 个真 REAL，见 6-4）。

### 6-3 🔴 guard 追的是【静态字段】，不是方法 —— guard 内联是**候选**不是铁证
本批唯一一例假阳性：`PlayerDataManager.GetXPFromMatch` 的 guard `DAT_18453b119` 出现在 `PlayerDataManager__CreateTutorialResult.c`，
但对方体是 `if(lVar1!=0){*(lVar1+0x10)=0;return;}`，**与 GetXPFromMatch 的经验 if 链毫无关系** —— 两个方法**共用同一静态**才共享 guard。
⇒ **`guard INLINE` 必须配「调用符号重叠率 + 读体」再落**（本工具 `--verify` 会算 overlap；`overlap<0.4` 或 `None` 的一律人工读体）。

### 6-4 🔴 方法组/委托只在【同类文件】里可信；跨类要「接收者带链」
`new UnityAction(this.OnClick)` 在**别的类**的文件里出现是**别的类的 `OnClick`**（同名撞车），不能当本方法入口。
本批唯一真的跨类是 `ChallengeManager.AcceptPracticeChallenge` ← `ChallengeButton.cs:80` `new EverguildButton.SourceDelegate(x.challengeManager.AcceptPracticeChallenge)`（接收者 `x.challengeManager` 带链）。
`button.OnClick`（Unity 组件的属性 getter）**不是**某类 `OnClick` 方法的委托 —— 本批 43 处全是这类噪声，已排除。

### 6-5 传递性：被内联进一个「本身是 D」的方法
`GameStaticData.CheckIfNewCards` 内联进 `GameStaticData.FoundNewCard`，而 `FoundNewCard` 本身是 D（无调用者）。
⇒ 严格传递看 `CheckIfNewCards` 也是死的；但按调度台口径（被内联 ⇒ 休眠、⛔ 别判 D）**保持原档**。日后清账时这两条可以一起处理。
