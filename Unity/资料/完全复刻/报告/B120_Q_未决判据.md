## §一 Q1 · 多条 `setCost(95)` 同时生效取哪条

**回答问题：原版 getter 是「先写赢」还是「后写赢」—— 硬证据 = 先写赢（三源一致）。**

### 1. 原版 getter：遇到第一条 `setCost` 就用它，然后**重扫全表加 Σ changeCost，再 return**

- Ghidra `D:/2/tools/decomp_full/EntityScript__get_CurrentCost.c`
  - `:43-45` 正序枚举 `activeEffects(+0x108)`；`buffType(+0x38)==2` ⇒ `iVar2 += costChange(+0x68)`
  - `:50-53` `buffType(+0x38)==0x5f(95)` ⇒ `iVar2 = costChange`
  - `:55-79` **重新 `GetEnumerator`（从头）**，内层循环**只判 `==2`**（不再认 95），加完到表尾 ⇒ `:66-73` `clamp0` 后**直接 `return`** —— 这一支**不加** `rawCardData.manaCost`
  - `:84-91` 一趟没遇到 95 ⇒ `iVar2 += *(param_1+0x28 的 +0x78)`（base cost）、`clamp0`、返回
- 交叉 ①：`D:/2/tools/cpp2il/out_il2csharp/Assembly-CSharp/EntityScript.cs:414-441`
  `while(list14.MoveNext()) { if(==95) break; }` → 取该元素值 → **全新 `GetEnumerator()`** 再扫一遍只累加 `==2` → 返回
- 交叉 ②：`D:/2/tools/cpp2il/out_cpp2il_dev_ilspy/EntityScript.cs:500-545`
  同样的「外层找第一个 95 就 break → 内层全新枚举只累加 2 → `max(v,0)` 返回」
- ⇒ **先写赢（列表序靠前的那条 `setCost` 生效）**，且**所有 `changeCost` 都会被加上**（含 95 之前与之后）。

### 2. 但这条差异**不可观测**：原版 `AddEffect` 的 `case setCost` 会先删光旧记录

- `D:/2/tools/cpp2il/out_cpp2il_dev_ilspy/CardScript.cs:17756-17768`：
  `if (newEffect.buffType == BuffType.setCost) { RemoveActiveEffects(newEffect.buffType); activeEffects.Add(newEffect); UpdateCostText(); }`
- `D:/2/tools/decomp_full/CardScript__RemoveActiveEffects.c:31-48`：**倒序遍历、每命中一条就 `RemoveEffect` 并继续**（`joined_r0x0001805f630a` 回到循环）⇒ **删光所有匹配项**，不是删一条。
- ⇒ `activeEffects` 里 `95` **至多一条** ⇒ 「先写赢 / 后写赢」在原版**永远等价**。

### 3. 我们现状

- `D:/4/Unity/MyGame/Assets/RuleEngine/Core/RuleCore.cs:1048-1057`：`for (i...) { if (m.SetTo>=0) { setTo=m.SetTo; continue; } sum+=m.Delta; }` ⇒ **最后一条赢**。

**判定：✅ 行为一致（等价）。** 我们 last-wins 与 getter 字面不一样，但「同卡同 Key 只留一条」这条前提由 `:470-480` 保证了。
