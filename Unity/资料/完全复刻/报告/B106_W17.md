## ⑧ · `Run()` 补 catch（调度台追加件 · AUD11 类 4 · 判据 `报告/B103_D1.md` A3）

**改动**：`BattleScene.cs:459-488`（`Run()` 的 `try/finally` 那一段）。

- 形状（照 `B106_W16` 已落地的五宿主，`MainMenuScene.cs:682-683` / `DeckScene.cs:776-789` 等）：
  ```csharp
  bool runCompleted = false;
  try { WarmUpRenderPipeline(); RunCore(); runCompleted = true; }
  catch (System.Exception e) { Debug.LogError(P + "=== RunCore 抛异常（**其后的断言段没跑**）：" + e); }
  finally
  {
      WarpforgeVFX.WFSoundPlayer.Enabled = prevSoundEnabled;
      if (!runCompleted)
      {
          Debug.Log(P + "=== 合计：**RunCore 中途抛异常 —— 计数器在 RunCore 内、不可达 / 本条合计不完整** ===");
          Debug.LogError(P + "   ⚠️ **RunCore 中途抛异常 —— 其后的断言段没跑，本条合计不完整**");

  ```
- **与五宿主的一处必要差别（写清，不是偷懒）**：那五个宿主的计数口是类级 `_sink`，所以能 `_sink.Fail++` 并在 `finally` 印真数；
  **本宿主的 `pass`/`fail` 是 `RunCore` 的局部变量**（`RunCore` 开头的 `int pass = 0, fail = 0`）⇒ `catch`/`finally` **够不着**，
  不可能不假装地报数。**⛔ 没有为此引入静态计数口**（那要改 `RunCore` 内 500+ 处 `pass +=` / `fail +=`，风险远大于收益）。
  现在的做法 = 异常**出声**（LogError）+ `finally` 印一条明确的「不完整合计」+ `rc=1`。
- **退出写法沿用本宿主**：`if (Application.isBatchMode) EditorApplication.Exit(1);`（与 `RunCore` 末尾
  `EditorApplication.Exit(fail == 0 ? 0 : 1)` 同一口径）。
- **⛔ 断言一条没删、公开签名没动**；`finally` 里原有的「还原 `WFSoundPlayer.Enabled`」照旧。
- 正常完成时 `runCompleted = true` ⇒ `finally` 只还原开关、不印额外合计、不强制退出（行为与改前一致）。
