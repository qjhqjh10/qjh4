## 5. 覆盖边界 + 顺手发现

### 覆盖边界

  仍以 R1 报告那句「与 UnityPy 自带读法 878/879 一致」为准，**我没有复跑那次比对**。
- **没有独立验 R0 的 247,612 行**（只拿它的列做交叉）。

- 卡在 `assets_full` 之外的（远端包）一律没碰。

### 顺手发现
1. **R1 报告有两处小数字偏差**：①「905 个里 **897** 个是 MonoBehaviour」→ 实测 **898**；
   ②「`r1_decoded2/` 有 **886** 个对象的解码后 JSON」→ 实测 **885 个文件**（`I2Languages` `decoded=True` 但 `dumped=False`；
   `r1_decode2_status.json` 里 `decoded True = 886`，那是"解出数"，不是"落盘数"）。
2. **R1 的分组描述有两处口径混列**：§① 表把「286 解出」与「886 个对象走 ttread」并列，
   两个数字的**分母不同**（前者是分档数，后者是解码路数），容易被读成"886 个解出、286 个无关"。
3. **`DOTweenSettings` 的 R1 与 R0 互相矛盾**（R1 说无关 / R0 说已用（工程内））——
   这是本轮唯一一条**同一批产物内部打架**的记录，建议一并修。
4. **`R0_未使用清单.md` §3 并不独立复核 R1**：它只写「见 `R1_905对象归属.tsv`，本轮全部给了归属」，
   两处是同一批判据的自引用 ⇒ 别把"R0 也说 905 全部有归属"当成第二份证据。
5. **`Core/ArmyIcons.cs:16-17` 那句「那个 SO 不在 `assets_full` 的 JSON 导出里……`grep ArmyIconsSO` 在 `sharedassets0.assets` 里 0 命中」仍成立**
   （正是这 905 个 fail 所致），且它已经用原始字节解出来了 —— 现在有了 R1 的
   `r1_decoded2/sharedassets0.assets/MonoBehaviour_416.json` 可当**交叉旁证**，不必再手工切字节。
   （**仅记录，未改该文件** —— 我这条线不许改既有文件。）
6. **R0 的"用没用"是名字匹配**：`ItemDrawerConfig`（我们叫 `ItemTypeSets`）、`ArmyIconsSO`（我们叫 `Core/ArmyIcons.cs` 的表）
   都会被判成"读过（文档）"。⇒ 别用 R0 的 U3 反推"原版这个资产没用"。
