### 二·1 「与原图比对」是怎么算的（不是自证）

- **12 张卡包图（17 个落点）**：它们的 `m_Rect` = 整张 `Texture2D`（1024×1024），所以「修好的画布」应当**整张等于原版 `d:/2/新解包资源/assets_full/bundle_boosterpacks_assets_all/Texture2D/<名>.png`**。
  实测：**可见像素（原图 alpha>10）mean\|Δ\| = 0.0000**，旧贴法 6.227–28.825。这是一条**与贴法无关**的独立比对（拿原图当尺子，没用我们的 `m_Rect` 反推）。
- **`Roman VI`**：同理（`m_Rect` 128×128 = 原图 128×128）⇒ 可见像素 **0.000**。
- 其余 8 张的原图集对位**建不起来**，如实写进 §六·1（⛔ 没编数）。

### 二·2 复跑读数（`--check` 修前 / 修后）

```
修前： 🔴 按 m_Rect 补画布 25 张 → 盘上已是正确贴法 3 张 / 要重导 22 张
修后： 🔴 按 m_Rect 补画布 25 张 → 盘上已是正确贴法 25 张 / 要重导 0 张
```
（这 25 张**永远**会出现在「要补画布」那一栏 —— 那是它们的固有形状（源被紧裁过），不是缺陷；判「好没好」看的是 `要重导` 那一栏。）

### 二·3 为什么有 3 张「本来就对」（不是有人修过）

新贴法 top = `th − oy − h`，旧贴法 top = `oy`。两者**相等当且仅当 `h = th − 2·oy`**（上下留白对称）。
现读恰好命中：`40K_shop_offer_booster_Sautekh`（1024−110−914 = **0**，两个落点）+ `Roman VI`（128−16−112 = **0**）⇒ 位移 0、像素差 0、md5 前后相同。
🔴 所以那 3 张**不是**「被谁修过」，是**数学上的巧合** —— 别拿它们当「以前修过一半」的证据。

## 七、顺手发现（不在本任务范围）

1. 🔴 **`ui_menu/40K_shop_offer_bg_Sororitas_0.png` 的「名字与内容不符」**：文件名叫 Sororitas，逐像素其实等于 **SaimHann** 那张的 450×512 裁片（mean\|Δ\| 0.000）。这是**照原版走的**（原版 `40K_shop_offer_bg_Sororitas_0.asset` 的 `m_RD.texture` 就指向 SaimHann 贴图，14 个同名 Sprite 各指一张不同阵营），不是我们抄错；但**以后谁按名字推断内容会错**，已在 `MENU_TEXTURE_IMAGES` 注释里写死。
