# B169_J92 · 卡牌升级点不动 + 成就进度诊断（只读）

> 结论先行：**升级面板「看着能点、点了没反应」= `upgradeButton.interactable` 被 `CheckUpgradeRequirements` 置 false**（两个条件都不满足），
> 而 prefab 的「禁用态」没有换图 ⇒ 画面上看不出被禁用。**成就进度能涨**（链路完整、客户端驱动），但**不落盘 ⇒ 重启回落到模板值**。

## §一 卡牌升级

### 1·1 点击处理在哪
| 环节 | 类.方法 | 出处 |
|---|---|---|
| 面板组件 | `UpgradePanel`（挂在 GameObject `Upgrade Panel`） | `assets_full/bundle_scenes_scenes_mainmenuwarpforge/MonoBehaviour/MonoBehaviour_2117.json`（`upgradeButton→2247` / `costIcon→2212` 均已赋值） |
| **绑监听** | `UpgradePanel.OnEnable` → `((Button)upgradeButton).m_OnClick.AddListener(TryUpgrade)` | `cpp2il/out_cpp2il_dev_ilspy/UpgradePanel.cs:91-96`（`OnDisable` 摘除 :98-103） |
| **可点性计算** | `UpgradePanel.CheckUpgradeRequirements` | `cpp2il/.../UpgradePanel.cs:105-203`；权威 = `decomp_full/UpgradePanel__CheckUpgradeRequirements.c` |

**`m_OnClick` 在 prefab 里是空的（`m_Calls: []`），监听只由 `OnEnable` 加** ⇒ 「没绑监听」这一档**排除**（面板能显示数值 ⇒ Initialize→CheckUpgradeRequirements 跑过）。
同段还证明「点击目标没被挡」：按钮 `Image m_RaycastTarget=1`、`m_TargetGraphic=2215`，`m_Interactable` 初值 1。

### 1·2 前置条件（`set_interactable` 的唯一来源）
`decomp_full/UpgradePanel__CheckUpgradeRequirements.c`：
```
:60   nextTierInfo = CardTierConfig.GetNextTierInfo(cardTier, rarity)
:100  iVar6 = GameplayVariablesData.GetMaxCopiesInDeck(rarity, cardType)
:102  if (owned < 1 || owned < iVar6 + iVar1)  → uVar2 = false      // iVar1 = requiredCopies(+0x20)
:106  uVar2 = InventoryManager.HasEnough(cost.Currency, cost.Amount) // cost 在 +0x18
:121  Selectable.set_interactable(upgradeButton(+0x40), uVar2)
```
即 **interactable = 有下一档 && owned ≥ maxCopiesInDeck + requiredCopies && 货币够**。
`GetMaxCopiesInDeck`（`dump.cs:130194`）= `cardType==10(Hero) → 1` · `rarity==4 → numberOfCopiesLegendary(1)` · 其余 `numberOfCopiesOtherRarities(2)`（本服 GameModesConfig 现读 1 / 2）。

### 1·3 升级时调什么
`TryUpgrade` → `CardServices.UpgradeCard` → **ExecuteCloudScript `FunctionName="UpgradeCard"`，payload `{itemId: <卡 uniqueId>}`**（匿名类型 `<>f__AnonymousType0<itemId>`）。
成功回调里客户端自己做：`TierCollection[card]+1` → `InventoryManager.Remove(card, requiredCopies)` → 扣货币 → `Signal.Raise(UpgradeCardSignal)` → `RewardService.Collect(result.Rewards)`。
**等级持久化 = 库存条目的 `ItemInstance.CustomData["CardTier"]`**（`CardInventory.cs:141/154` `UpdateCardTier` 读它；`ItemInstance.CustomData` 在 `dump.cs:613165`），**不是 `PlayerItem.tier`**。

### 1·4 最可能原因（判据，非猜测）
打开的卡 = **乌列尔·文特里斯 `UM47`（Hero、rarity 2、卡面 tier 0）**；面板显示 `3 / 225 / +38` 正好等于 `CardTierConfig` 里 **Rarity 2 · cardTier 1** 那一行（`responses/ExecuteCloudScript.InitializeLiveOps.json` → `CardTierConfig`）：

| 条件 | 要求 | 实际 | 结果 |
|---|---|---|---|
| 有下一档 | nextTierInfo≠null | 面板有内容 ⇒ 成立 | ✅ |
| **持有份数** | `≥ maxCopiesInDeck(1) + requiredCopies(3) = 4` | 登录档案 `UserInventory[UM47].RemainingUses = 2`（`server/logs/live-20261107-201014/0001_LoginWithSteam.resp.json`；收藏格角标也显示 x2） | ❌ **先在这里短路** |
| **货币** | `HasEnough("gold", 225)` | `Inventory<Currency>` 里**没有 `gold` 条目**（见 1·5）⇒ 0 | ❌ 即使份数够了也还是 false |

⇒ `interactable = false` ⇒ Unity 直接跳过 `onClick` ⇒ **服务端一条 `UpgradeCard` 都没有**（`grep UpgradeCard server/logs/` = 0 命中，与用户看到的现象完全一致）。

**为什么「看起来能点」**：按钮 `m_Transition = 2 (SpriteSwap)`，而 `m_SpriteState.m_DisabledSprite` 是 `{fileID:0, pathID:0}`（空）（`MonoBehaviour_2247.json`）⇒ 禁用态**不换图、不变灰**，画面上零反馈。

### 1·5 我们离线侧缺什么
- **`CardTierConfig`：有**，但整张是 `🔶 自己设计`（`server/tools/add_all_configs.py:117-175` 自陈：4 档的 requiredCopies/cost/pointReward/xpReward 与稀有度倍率都是编的）——**能用来跑，但不是原版值**。
- **`ItemsConfig`：无关**（只有改名/原画解锁价格）；升级花费只由 `CardTierConfig` 决定。
- **白块 = `costIcon`（升级花费的货币图标）= `gold`**：`CheckUpgradeRequirements` 取 `cost.Currency.Reference.GetIcon(Small)`；而本地 Currency 资产只有 **`Crystals`(code C2) / `Blackstone`(C3) / `Gacha tickets`(C5) / CurrencyConfig 的 `C1`(free)**（`assets_full/bundle_cosmeticsso_assets_all/MonoBehaviour/` 全库 `"smallIcon"` 只命中 3 份）⇒ `Reference` 解不出 ⇒ `sprite = null` ⇒ 白块。
- 同一根因还让 `HasEnough` 失效：`InventoryManager.HasEnough(LoadableReference<T>,int)` **只比 `TargetId` 字符串**（`InventoryManager.cs:1481-1501`），`TargetId="gold"` 在 `Inventory<Currency>` 里查不到 ⇒ 0。顶栏金 2000 能被看到，是因为 mod 给**另一个方法** `CurrencyExtensions.GetOwnedCount` 打了桩（`Probes/Stubs.cs:333-420`），**救不到这里**。

## §二 成就进度

### 2·1 写入链（客户端驱动，不依赖服务端算分）

- `AchievementsManager.GetSave` 缺条目会自动建 0 进度条目（`:606-639`）⇒ 102 条都能涨，不限注入的 8 条。

### 2·2 我们的假服务端是静态还是动态
| 模板 | 行为 |
|---|---|
| `ExecuteCloudScript.UpdateAchievement.json` | 模板本身静态，但 **`server.py:1311-1313` → `_apply_achievement_update()`（:1760）动态回显**请求里的 `{Id,TotalPoints}`，回 `{id,highestValue,value,enabled:true}` ✅ |
| `ExecuteCloudScript.UpdatePooledAchievements.json` | **静态 `[]`**（数组形状正确、客户端回调循环 0 次、无副作用），但**不回写任何条目** |

### 2·3 结论：**能涨，但只活一次运行**
- ✅ 打完一局（非教程/非回放/非 Duel）→ `CombatFinished` → `FinishedProcessingMatchResult` → `UploadPooledProgress`，模板齐（`onPracticeMatchFinished` / `onRankedMatchFinished` 都在）⇒ **进度条本局内会涨**（胜利类如 `ACH37 Resilience` / `ACH38` 有 `BattleEndSignal` 直接挂钩；战斗类 `ACH1/ACH5` 走战斗内信号）。
- ❌ **不落盘**：`UpdateAchievement`/`UpdatePooledAchievements` 都只改响应、不写 `state/`；而登录时 `USER_DATA_READONLY_DEFAULTS["Achievements"]`（`server.py:241`）会在缺键时注入那 8 条固定值（登录片段里没有 `Achievements` 键）⇒ **重启后回到 12000/55/42/75/30/12/45/1200**。
- ⚠️ 顺带查到一个真缺陷：`AchievementsManager.Initialize` 末尾 `GrantSteamAchievements()` 抛 `InvalidOperationException: Steamworks is not initialized`（`phase0/stubs.tsv:45`，20:10 这轮），发生在 `UploadPooledProgress()` 与 `IsInitialized=true` **之后**，成就页不受影响，但异常会冒给调用方。

## §三 修法建议

1. **份数（数据侧，低风险）**：`python -I 05_工具/server/tools/add_inventory.py --copies 7 --write`（默认 2）。
   覆盖所有档位（tier1→2 需 `maxCopies+3`、→3 需 `+4`、→4 需 `+5`；max 为 1 或 2 ⇒ **7 是安全上界**）。⚠️ 会重写整份 `UserInventory`（脚本自带 cosmetics / 异画条目，但改前请先 `cp` 备份 `playfab_profile.json`）。
2. **货币判定（mod 侧，低风险 · 首选）**：照抄已有桩的口径，给 `InventoryManager.HasEnough<T>(LoadableReference<T>,int)` 加 prefix：Currency 且 id 不在库存时，回落到 `PlayerDataManager.userInfo.UserVirtualCurrency[code]`（映射表已有：`Stubs.CurrencyCodes`）。
   ⛔ 不建议改 `CardTierConfig.cost.Currency` 去蹭 `C1/C2` —— 那是把 225 金币记成别的货币，与原版语义不符。
3. **升级真正可用（服务端，中风险）**：新增 `responses/ExecuteCloudScript.UpgradeCard.json`（`CraftCardResult = {Result:bool, Rewards:RewardInfo[]}`）+ `server.py` 分支：扣 `UserVirtualCurrency.gold`、`RemainingUses -= requiredCopies`、`UserInventory[i].CustomData["CardTier"] += 1`，**并在登录注入时把 CustomData 带出去**。缺这一步时点击只会弹 `ErrorDataSync`（兜底模板 `ExecuteCloudScript.json` = NotImplemented）。
4. **白块（mod 侧，低风险）**：`costIcon` 的 sprite 为 null 时 `Image.enabled=false`（OFF-88/W7 同一套兜底，把它加进 `ImageFallbackProbe` 的覆盖名单）；要「显示金币图标」则用本地 `40k_general_icon_currency_gold` 显式赋给 `costIcon`，并在注释标 `🔶 自己设计`（原版走 Currency 资产，本地没有 `gold` 资产）。
5. **成就落盘（服务端，低风险）**：把 `_apply_achievement_update` 的结果写进 `state/`，`UpdatePooledAchievements` 同理；登录注入改为「有落盘值用落盘值，否则用默认 8 条」。
