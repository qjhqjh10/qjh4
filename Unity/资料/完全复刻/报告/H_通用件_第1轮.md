## §二 三个通用件：判据、行为、差异

### 2.1 一句话判据（先写判据、再建件）

| 件 | 「它在什么时候改什么」 | 判据（第一权威） |
|---|---|---|
| `UIImageMaterialColorChanger` | `DoColorChange(target, propId, time, instant)`：先把材质**实例化一份**；`instant=false` ⇒ 记住 `original=当前色`、`currentTime=0`、`enabled=true`，每帧 `t=currentTime/time`、`SetColor(Lerp(original,target,t))`；**先算 t、后累加 dt**；`instant=true` ⇒ 直接写 | `out_cpp2il_dev_ilspy/UIImageMaterialColorChanger.cs:21-116` |
| `UIGroupTint` | `SetColor(color,time)` 记 `tintColor`（`time=0` 直落，`>0` 补间）；`DoColorChange()` 把整棵子树（**含未激活**）每件刷成 `tintColor`；`Update` 只在 `\|last−tint\|² ≥ 9.9999994e-11` 时刷、**下一次自停** | `UIGroupTint.cs:32-176` |
| `UIScaleToFit` | `Fit()`：目标框尺寸按 `Flat`（**加** padding）或 `Multiplier`（**乘** padding）修正 → `s = min(目标宽/自身宽, 目标高/自身高)` → `localScale=(s,s,s)`；目标空 ⇒ 警告返回；NaN/∞/`\|s\| < ε·8` ⇒ 不写 | `UIScaleToFit.cs:108-182` + `decomp_full/UIScaleToFit__Fit.c:30-67` |

### 2.2 与我们的世界的结构性适配（如实标，⛔ 不写成原版行为）

- **材质色**：原版挂 `Image.material`；我们无 uGUI ⇒ 挂 `Renderer.sharedMaterial`（语义一一对应）。`_Color` 不是所有自建 shader 的属性 ⇒ **调用方显式传属性名**；缺属性时**出声一次**（不静默）。
- **组染色的乘/写**：原版 `CanvasRenderer.SetColor` 是**乘在顶点色上的独立通道**；我们的 `ImageQuad.SetTint` / `Label.SetColor` **写的就是唯一那一路颜色** ⇒ 本件在 `Refresh` 时**记基色**，之后写 `基色 × tint`。⚠️ 这带来一处**静默风险**：若别的代码在本件生效后又改基色，本件下一次覆盖会盖掉（原版两路互不覆盖）⇒ **接实例时本件必须是该子树最后一个写色的人**（已写进文件头）。
- **补间**：仓库无 DOTween ⇒ 逐帧插值 + `Step(dt)`（批处理无帧循环，自检手推；与 `UiBadgeNotification.Step` 同口径）。

### 2.3 🔴 `UIGroupTint`：**原版就是空转的 ⇒ 我们同样空转**（用户 2026-10-25 纠正 ①）

**证据**：`Refresh()` 在反编译的 Assembly-CSharp 里零调用点（`grep -l UIGroupTint__Refresh` 只有它自己的定义；唯一消费者 `BasicCardUI__TintCard.c` 只调 `SetColor`；`bundle_menus_assets_all` 里 306 个实例的 `m_PersistentCalls` **全空**）⇒ `canvasRenderers` 只在 ctor 建成空表、**从不填充** ⇒ 组件实际什么也不做。

**处置（铁律 11 例外①：「原版本身没有该行为」）**：
- **删掉** `RefreshIfEmpty()` 及其在 `SetColor` / `Toggle` / `OnEnable` 里的自动调用；
- 保留同名 `Refresh()`（原版 private 零调用点；改成 public **只为自检/显式调用**），**任何生命周期都不调它**；
- **306 处实例本轮不接**；账里 `UIGroupTint` 全族判 **D**，理由「原版空转；我们不接 = 行为一致」；
- 断言：先钉「没 Refresh ⇒ 列表空、`Toggle` 不自动收、`SetColor` 一件都不改」，再**显式** `Refresh()` 单独验算法（测试专用入口，原版从不会走到）。

⛔ 不再写成「有意偏离」——**自动 Refresh 才是自我设计**，用户口径是「一切按原版、不做多余的自我设计」。

### 2.4 🔴 冲突（按用户要求：先停下写报告，不发明折中）

**`UIScaleToFit` 的 `fitInParent` 在我们这里常常没有尺寸**：
原版 183 处全靠 uGUI 布局把父框撑出来；我们树里**大量父节点是 0×0 的锚点/容器**（`MenuDraw.Node` 只为定位建节点）。
照抄「fitInParent ⇒ 父节点」会算成 0/0 —— 原版两道保护会让它**静默不缩放**。
本件的处理：**不猜父框**；0/负尺寸时**出声一次**并返回，需要缩放时由调用方显式 `SetTarget(rt)`（或 `SetTargetSizeForTest`）。
👉 **下一轮接实例时必须逐处确认父框有尺寸**；没有就把调用点改成显式目标，⛔ 不许在件里自动往上找。

### 5.2 「建了但没接」怎么被挡住（每条都有一条「值随源变」）

- 材质件：`DoColorChange` 后**材质色 == 目标色**；中间步 == `Lerp(起始,目标,0.5)`；原材质**一个字节没动**；**同一 Renderer 上两颗组件共用同一份实例材质**（为接实例前置）。
- 组染色：先钉**空转**（没 `Refresh` ⇒ 列表 0、`Toggle` 不自动收、`SetColor` 一件都不改）；再显式 `Refresh` 后验 `quad.Tint == 基色 × tint`，且 `q.Tint.r (0.4) < tint.r (0.5)`（灭自证：不是直接写 tint）；**未激活那颗也变**。
- 缩放：父框 400×200 → 2；父框改 300×150 → **1.5**（只算一次/缓存 ⇒ 红）；Flat/Multiplier 两种 padding 各验一次。
- 页签：`ChangeTab` → 页 active + `OnOpen` 计数 + `CurrentTabView`/事件参数；同页再切**只重开**；换页 `OnClose` 计数；`ForceCloseTabs` 全关且**不清** CurrentTab；`Toggle(true, tab)` 走按键路径；`RemoveTabButton` 键**真被销毁**。
- 拖拽：`PressAt` → `MoveTo` 越阈值 → `onDrag` 次数/坐标；`ReleaseAt` → `onDrop` + **onClick 0**；阴性对照「不越阈值 ⇒ 点击 1 次、drop 0」。
- DeckCell：非排序列 hover = 1.05；排序列 0.8 **且 hover 不放大、离开仍 0.8、无高亮**（🧨 只改缩放不改闸 ⇒ 红）。
