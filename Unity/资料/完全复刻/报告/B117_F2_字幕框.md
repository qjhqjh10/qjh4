## 一、根因：**(γ) 对齐 / 轴心错**（不是 α 框太小、也不是 β 自动缩小没开）

### 1. 实测到的偏移量（像素级）

对 `23_pick.png` 逐行扫描近白像素，台词墨迹落在 **设计 px x ≈ −19 … 312**、`y 764.3 … 795`：

| 量 | 实测 | 该在的地方（判据） | 差 |
|---|---|---|---|
| 墨迹左沿 | **≈ −19.35** | **201.1**（= 气泡左沿 12.61 + `TextLeft` 188.5） | **−220.45** |
| 墨迹垂直中心 | 779.5 | 779.05（框 y[738.2, 819.9] 的中线） | **+0.45 ✓ 对** |
| 气泡底图 / 立绘 | 就位 ✓ | 12.61 / 44.9 | ✓ |

−220.45 **恰好 = `TextW / 2`（440.9 ÷ 2）** ⇒ 不是「框太小」，是**整块矩形以节点为中心摆**。
**垂直是对的、只有水平错**，这一条把范围直接钉死在「枢轴 x」上（pivot.y = anchor.y = 0.5）。

### 2. 判据链（三条，缺一条都会把修法做成「看着对、其实是巧合」）

1. **本文件这套坐标是「文本区左沿 + 中线」**：`TextLeft = 188.5`（左沿）/ `TextCy`（中线，`UnitChatPanel.cs:127`），
   而 `Move` 摆的是**枢轴点** —— `HudCanvas.SetAnchorPx` 的 doc 自己写着「**与 `pivot` 无关**：式子只管枢轴点摆在哪」。
2. **`Label.CreateCore` 的 uGUI 档把 `pivot` 硬写成 `(0.5, 0.5)`**（`Battle/Label.cs:204`）。
   `MakeBubble` 建件时传的那个 `(0, 0.5)`（`UnitChatPanel.cs:706/712`）是 **`Label.anchor`，不是 pivot** ——
   它只当「墨迹在节点内怎么摆」用（`Label.RefreshBounds` 末句 `-anchor.x * _tmpW - b.min.x`，`Label.cs:1677`）。
3. **那条纠正路在这条链上永远跑不成**：`RefreshBounds` 量的是 `TMP_Text.GetTextBounds()`，而它
   **只统计 `isVisible` 的字**（`Library/PackageCache/com.unity.ugui@…/Runtime/TMP/TMP_Text.cs:4864-4894`）；
   而 `Speak` **每一句开头都先 `HideBubble(b)`**（`UnitChatPanel.cs:1036`），它里头是
   `SetText("") + SetMaxVisibleCharacters(0)`（`:1237`）⇒ 后面 `SetText` / `SetGlyphHeight` / `SetAutoFitBox`
   里的每一次 `RefreshBounds` 都读到**空集哨兵 `±4.29e9`** ⇒ `Label.UsableBounds` 不过 ⇒ **一个字节都不挪**。

⇒ 于是「枢轴居中 + 440.9 宽的矩形」全程**以节点为中心**摆；节点是按**左沿**摆的 ⇒ 台词从框左沿外
`TextW/2 = 220.45 px` 开始（首两三字被屏幕左缘切掉）。
⚠️ **尺寸全对**，所以既有那五条「渲染宽 ≤ 440.9 / 高 ≤ 81.7 / 字号在 [10,33] / 折了行」**全绿也抓不到它**（位置 ≠ 尺寸）。

> **`24_endturn.png` 交叉验证**：敌方气泡那句（两行，自动缩到 ≈25.5 px）墨迹 `x 2.3 … 404`、`y 276.8 … 342`，
> 垂直中心 309.4 vs 原版框 `y[268.2,348.9]` 中线 308.5（**+0.9 ✓**）；水平同样左移 220.45 ⇒ **同一根因**。

## 二、改了什么

### 1. `CardPresentation/Battle/UnitChatPanel.cs:717`（**净增 0 行**）

把台词那颗 TMP 的**枢轴钉成「左中」**：

```csharp
Move(t, b.left + TextLeft, topPx + TextCy, ZText, at.ax, at.ay); if (t != null) { var _ct = t.GetComponentInChildren<TMP_Text>(true); if (_ct != null) _ct.rectTransform.pivot = new Vector2(0f, 0.5f); }   // 🔴 B117-R1：…（判据链整段写在这一行行尾的注释里）
```

**为什么这样就对**：枢轴一旦在左，`b.min.x` 也变成 ≈0、`RefreshBounds` 那条式子**退化成 0** ⇒
**跑与不跑结果相同**（两条路同源）。
**为什么不是「调用方自己 + `TextW/2`」**：`RefreshBounds` 真跑成的那些句会把这一半**再加一次**。
**为什么只动 x**：`anchor.y = 0.5` 本来就和 `pivot.y = 0.5` 一致（垂直实测只差 0.5 px）。

### 2. `CardPresentation/Battle/UnitChatPanel.cs:1096-1097`（**净增 0 行**）

`SetAlignLeft()` 从 `SetAutoFitBox` 前面**挪到 `SetText()` 之前**（原来那句改成一行指针注释，行数不变）。
理由：`SetText` 内部那次 `RefreshBounds` 按**当时的 alignment** 算偏移 —— 还停在 `Center` 时
`b.min.x = (框宽 − 墨宽)/2 ≈ +55` ⇒ 它会把 TMP 子节点整体**左推 ≈55 px**。现在两条路都落在同一位置。

### 3. `CardPresentation/Editor/BattleScene.cs:22145` + `:51213-51300`

- **接线**（行尾追加，**净增 0 行**）：`chat.HideAll(); B117F2_Assert.Run(chat);`（原行没有 `//`，不会被吞）
- **断言类** `B117F2_Assert` 追加在**文件最末**（其后没有任何账落点 ⇒ 零漂移）

## 五、顺手发现（⛔ 没改，交给调度台分流）

1. 🔴 **`Label` 这一族有一个会复发同类缺陷的隐患**（**共享件，不在我的白名单**）：
   `Label.CreateCore` 的 uGUI 档把 `pivot` 写死 `(0.5,0.5)`，而 41 处 `MakeText` 调用点里有相当一批传的
   `anchor.x = 0`（左对齐 + 左沿坐标，例：`Battle/SettingsPanel.cs:1168/2270`、`MulliganPanel` 多处）。
   只要那些标签的字**某一刻 `maxVisibleCharacters = 0` 或文本为空**（打字机 / 输入框占位 / `SetText("")`），
   `RefreshBounds` 就会早退、矩形停在**中心** ⇒ 同样的「左移半个框宽」。
   **根治**应是 `CreateCore` 里写 `rt.pivot = anchor`（一行），但那会动 40+ 个调用点的几何 ⇒ 该由调度台裁定 + 全量自检。
2. **`Label.ForceRelayout()` 会把「TMP 子节点位置错」这类现场抹平** —— 任何用 `HudBlockRel` 之类
   「相对节点」的恒等式做断言的检查，只要先 `ForceRelayout` 一次就恒绿（本报告 §三 那条自证注记）。
   建议在 `Label` 的 doc 里补一句：**验「摆到哪」时必须只 `ForceMeshUpdate`**。
3. **既有那五条「台词不许溢出」断言只量尺寸**（`BattleScene.cs` 那节）。本轮补的三条是**位置**那一半；
   两者要一起看才知道「在框里」。⛔ 别把那五条删掉换成新的。
4. 真机 `24_endturn.png` 那句的自动缩字号落在 **≈25.5 px**（框 440.9 宽装 2 行）—— 与「`auto[10,33]`」自洽，
   不是缺陷，记一笔备查。
