### ③ 🔴 一个必须记下的落差（**缺口已立账，未修**）

原版那颗根 Image 的悬停色偏**是生效的**（`EverguildButton.m_Transition = ColorTint` → `CanvasRenderer` 顶点色 → PS 乘顶点色）。
我们的 `ImageQuad.SetTint` 走的是 **`sharedMaterial.color`（= `_Color`）**，而**原版这支 shader 没有 `_Color`**
（属性表 = `_Brightness/_Contrast/_Hue_Offset/_MainTex/_Saturation`，判据 `OriginalShaderBlendTable.cs:422`）
⇒ 直接挂上去会让 `SetTint` 每帧打一条 `Material doesn't have a color property '_Color'` 并把那一层整个跳过。
所以：**这两条 toast 的悬停色偏目前不生效**，`HueTintableQuads` 把它们从染色名单里剔掉并**出声一次**（⛔ 不静默）。
补齐两条路（都**越出本件白名单**）：① 给 `ImageQuad` 加「按顶点色染色」的通道（原版就是这条路）；② 另写一支带 `_Color` 的等价 shader。
⚠️ 现有的 `W58-D6①/②` 断言用的是 **Achievement** 档（`Sprites/Default` 底图，**不受影响**），所以它们**不会**变红、也**测不到**这个缺口。

1. 🟠 **`UI Orange Button To Purple` 有两个消费者，本件只做了 toast 那两处。**

2. 🟢 **原版 `Campaign Node/Collectable Highlight` 还挂 `UIBorderGlow`**（`menu_dump` 组件列 = `Image,UIBorderGlow`），我们没挂。
   但 `playOnEnable = 0`（`B112W_B08` §2·0：85 个里只有 3 个是 1）⇒ 原版**也不播**；
   而这支 shader 的 PS 用 `SV_POSITION` 自己算屏幕坐标（`dcl_input_ps_siv … position` + `div r0.xy, r0.xyxx, cb0[3].xyxx`），

   ⇒ **缺它不影响画面**（真机验收时可以扫一眼，但不必为它另开一件活）。判据：`工具/disasm_dxbc.py`。
3. 🟢 **旧注释里那句「原版 `m_Sprite` 与我们不是同一张」是错的，已就地订正**：
   `menu_dump` 实读该节点 sprite = `Border Thick Circle FX`，工程里就是 `Resources/Art/ui_menu/Border_Thick_Circle_FX.png`
   （下划线 vs 空格只是命名口径）⇒ **同一张**。
4. 🟠 **`_Aut…`/`_Add`/`_Range`/`_RangeStartOffset`/`_NoiseStrength`/`_Length`/`_MaskScale`/`_ScaleFromCenter` 这一族「材质有值、shader 不声明」的死值**，
