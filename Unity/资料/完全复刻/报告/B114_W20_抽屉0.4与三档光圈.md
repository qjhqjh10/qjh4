- 若 `Content` 左沿真是 0，那它要么宽 **712.8**（`m_SizeDelta.x` 就不该是 712），要么**不居中**（锚/`anchoredPosition` 就不该是 `(0.5,0.5)`/`(0,0)`）。三条实测**同时**否掉这两个可能。

## 三、`m_RaycastTarget = 1` 在我们这套 `ImageQuad` 下意味着什么

### 1. 原版实测（同一份 prefab 全量扫 `!u!114` 的 `m_RaycastTarget`）

`Expansion Pass Points Drawer.prefab` 里 **17 颗图形，15 颗是 `1`**：

```
Content/Background = 1   Content/Image = 1   Content/Campaign Glow = 1   Content/Army = 1
Content/Label = 1        Content/Label/Name = 1   Content/Label/Quantity = 1
Content/Converted Drawer = 1（+ AlreadyOwned = 1）   Content/Ephemeral Drawer = 1
Content/Collected Badge/Image = 1（+ TMP = 1）
Premium Highlight/{Highlight, Blackout, Badge} = 1
（只有 Converted/Ephemeral 的 Price Display 的 icon/text 两颗 = 0）
```

⇒ **`m_RaycastTarget = 1` 是 uGUI 的默认值**，原版**没有为光圈单独开这一位**。它既不表示「光圈是按钮」，也不是「光圈比别件特殊」。

### 2. 我们这套模型的实际情况

- 本仓**没有 `Graphic.m_RaycastTarget` 这个位**：`ImageQuad` 是纯渲染件，壳里没有 `Canvas` / `EventSystem`。
- 命中 = **`WindowButton` 子树里所有 `ImageQuad` 的外接盒并集**（`PointerLayer.HitBoxPx` → `UnionOtherQuads`，`Shell/PointerLayer.cs:1199/1875`）。**不在任何 `WindowButton` 子树里的 `ImageQuad` 完全不参与命中。**
- 抽屉自己**不会**建命中区：`ItemDrawerView.AttachHit`（`ItemDrawer.cs:2013`）只在 `ShowInfoOnClick == true` 时建，而 `ShowInfoOnClickOf`（`:1945-1947`）对 `ExpansionPassPointDrawer` **不在全票为真那批里** ⇒ 默认 **false** ⇒ **这两档抽屉今天连自己的 `Hit` 节点都没有**，点击由宿主（如 `CampaignTab.cs:680` 的 `AddHit`）负责。

### 3. 差异到底在哪一条

原版的「可点区」= 该抽屉祖先（若有 handler）子树里**所有 `raycastTarget=1` 图形的并集**。我们 = 宿主那颗 `Hit` 的框 ∪ 它子树里的 quad。两边的差别**只有一处**：

- 原版并集 = **`Background` 那 712×1080**（⊂ 根框）∪ **光圈溢出带**；
- 我们 = 宿主给的 `_box`（⊇ 根框，因为 `FrameOf` 把根**内接**进 box）。

⇒ 我们**缺的只是光圈溢出根框的那条带**：基础档 `x ∈ [−114.26, 0.4)` ∪ `(712.4, 827.06]`（高 146.46…717.54），换成屏幕 px = **±114.2555 × k**（`k = min(box.H/1080, box.W/712.8)`）。Icon 档的光圈 ≈ 1079.76² 设计 px ⇒ 对**方框**是 0（对非方框才有一点点）。
