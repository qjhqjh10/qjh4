## 一 结论

🔴 **根因 = `CampaignEventData.Nodes[].Position` 量纲错了约 1000 倍，三个节点被算到 x ≈ 184,490 / 185,049 / 185,608 的画布坐标上 —— 离屏幕右边约 18 万个单位，所以一个都看不到。**

- 原版 `Position` = **XNode 图编辑器坐标**（实测 47 份 `Campaign Node Data*.asset`：x ∈ [-8, 6712] 步长 **320**；y ∈ {-392,-264,-136,-8,120,248,376} 步长 **128**），不是 0/1/2 这种归一化值。
- `CampaignTrack.CalculateRatio` 的分母是 **Position.y 的跨度**：`ratio = (trackHolder.rect.height − nodePrefab.rect.height) / (2 × max|Position.y − offset.y|)`；我们的 y 跨度只有 **0.5** ⇒ ratio ≈ **559.06**（原版实测 ≈ **0.546**，差 **1024 倍**）。
- 该 ratio 同时乘在 x 上 ⇒ `x = (Position.x − offset.x) × ratio = 330 × 559 ≈ 184,490`；顺带把 `Content`（ScrollRect 的 m_Content）`sizeDelta.x` 撑到 ≈185,758。
- **不是**被过滤、**不是** prefab 缺、**不是** Addressables 加载不到、**不是** 布局 0 尺寸 —— 四条已逐条排除（§二）。
- 附带缺陷①：`UnlockedBy` 三条全空（应为 c2←["c1"]、c3←["c2"]）⇒ `GetNodeState` 里三节点全是 `unlocked`（不是 locked）；「起点节点」判据 `UnlockedBy.Count == 0` 现在三节点都满足，只靠列表顺序取到 c1 才碰巧对。
- 附带缺陷②（修时必须一起避开）：**三个节点的 `Position.y` 若全相同** ⇒ 分母 0 ⇒ `ratio = +Inf` ⇒ 位置 Inf/NaN，同样不显示。原版 y 恒有 7 档就是这个缘故。

### 2·3 坐标公式（根因所在）

```
GetNodesOffset:  offset.x = min(Position.x) − startingOffset.x(330)
                 offset.y = firstNode.Position.y        // firstNode = 第一个 UnlockedBy 为空的
CalculateRatio:  ratio = (trackHolder.rect.height − nodePrefab.rect.height)
                         / (2 × max|Position.y − offset.y|)      ← 分母是 Y 跨度
GetNodePosition: x = (Position.x − offset.x) × ratio
                 y = (Position.y − offset.y) × (−1) × ratio        ← DAT_1834b2bc8 = −1.0f
```
出处：`CampaignTrack__GetNodesOffset.c:34,51-52` · `CampaignTrack__CalculateRatio.c:40,55,70-71` · `CampaignTrack__GetNodePosition.c`（`+0x38`=x、`+0x3c`=y）· `CampaignTrack.__c___CalculateRatio_b__12_0.c`（**selector 取 `+0x3c` = Position.y，不是 x**）· `CampaignTrack.__c___GetNodesOffset_b__11_1.c`（`+0x38` = Position.x）· 常量 `工具/read_literal.py` 现读 `GameAssembly.dll`：`0x1834b2bc8=-1.0f`、`0x1834b3090=1.5f`（+width×1.5）、`0x1834b3250=2.5f`、`0x1834b2e60=0x7FFFFFFF`（abs 掩码）。

`trackHolder`/`nodePrefab` 的 rect 全是 prefab 静态值，**不依赖运行时布局**：`Campaign Track` RT `sizeDelta.y=709.06`（`Rewards Base Submenu Variant.prefab:73452`）→ `Viewport` `+50` = **759.06**（`:73557`）→ `Content` `−100` = **659.06**（`:73630`）；`Campaign Node` 根 `sizeDelta = 100×100`。

### 2·5 原版真值（用来对量纲）

- `Assets/MonoBehaviour/Campaign Node Data*.asset`（47 份，同一张 `Graph` guid `d4495133…`）：`position: {x:5752,y:120}`（无后缀那份）、`{x:312,y:-136}`（`_0`），`NodeId: UM44 / UM1`；x 步长 320、y 七档步长 128。

- `Ultramarines Campaign.asset` 里**没有 `Nodes` 字段**（只有 `Graph`）：`CampaignEventData.OnBeforeSerialize` 是**编辑器侧**从 `Graph.nodes` 生成 `Nodes`（`out_il2csharp/.../CampaignEventData.cs`），转换走 `CampaignNodeInfo(CampaignNodeData)`：`Position = data.position`（`Everguild.LiveOps.CampaignNodeInfo__.ctor.c` 的 `+0x20/+0x24`）、`UnlockedBy = data.unlocks.Select(n=>n.NodeId)`、`Unlocks = data.nexts.Select(...)`。⇒ **运行时 JSON 必须自己写对 Position/UnlockedBy**，没有别处替我们算。

### 2·6 顺带核过、**不是**问题

- `NodeId` 必须含数字：`CampaignNode.Setup` 做 `Int32.Parse(new string(NodeId.Where(IsDigit).ToArray()))` 存 `Index` ⇒ `"c1".."c3"` 合法（原版是 `"UM44"` 这种）。若改成纯字母会抛 FormatException。
- Track 上的 `TransformScalerBySmallScreenUI`（menuScale 1.125）只把整棵轨道 ×1.125，且非小屏时 `enabled=false`（`TransformScalerBySmallScreenUI__LateUpdate.c`）⇒ 与本症状无关。
- `Rewards` 形状 `{"item":"campaignPoints","quantity":100}` 与 `Daily_Login` 同款，`LoadableReference<T>` 有 `ctor(string)` ⇒ 不是本次原因。
