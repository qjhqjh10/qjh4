### 1·3 为什么「净行为对现池 = 0」

  其中落 `abilityLevelCriteria` 行的只有 **AM56 / TAU57**（各 1 行，`trigger 90 · ta = 10`）。

  `OwnerIs = RelFriendly` + `Subjects.KindWord = "troop"`（`WhenEvent.Subjects.Parse` 里 `troop` 是
  **真筛选**，把督军排除）；TAU57 对称（`enemy`）。**这两道筛与 ability 级 criteria 的方向完全一致**
  （`fu=1` / `eu=1`、`includeMinions=1`）⇒ 闸不会新增任何一次拒绝。
- 两张的 `unitConditions` / `abilityConditions` 现读都是 **null** ⇒ 第三道闸（board）也不新增判定。

⇒ **预期 `play check` 指纹：不变。**
（若合并后 `play check` 真的把 AM56/TAU57 判成变了 ⇒ 说明 `subject` 传错了格，要先查再重钉。）

### 2·2 #21② 窄闸③：**只在 `EffectResolver.ApplyAbilityFamilyGate` 那侧改**（`:247`）

```csharp
if (uab >= 0) { ApplyAbilityFamilyGateUnique(ctx, owner, thisCard, card, triggerName, ops, chosen, skip, by); return; } if (!uamb) return;
```

- 唯一定位（`uab >= 0`）⇒ 新成员 `ApplyAbilityFamilyGateUnique`（`:20508`，**追加到类尾**）
  → `AbilityLevelCriteriaAllows` → `false` ⇒ **整段正文 `skip[i]=true`**（原版那条 ability 没触发 ⇒
  `PlayAbility` 不入队，⛔ 不是「只跳一条 op」）；`null` ⇒ 放行 + 出声。

🔴 **为什么 `RuleCore.AbilityFamilyGateOpsForTrigger`（判据点名的 `:12987`）保持「唯一定位 ⇒ 不启用」**：

`AbilityLevelCriteriaWarningsForTest` 会**各加一次**、日志出两遍 —— 这正是判据 §2·5·2 点名要避免的
「double」。⇒ 判据那句「两条路互斥」按**全局**落实：**唯一定位 ⇒ `EnqueueAbility`；
不唯一 ⇒ 族闸**。该函数只在注释里把这件事写死（`:12964`，行数不变）。

## 四 🔴 判据订正：`ASH70` 的 `excludeTrait` 在原版**永不求值**

判据 §2·2 写：「玩家点选的目标如果已经带 `Vanguard`，这条 ability 根本不触发
（`excludeTrait=1` + `traitsFilter=980` ⇒ `MeetsTraitCriteria` 返 0 ⇒ `CanTriggerAbility` 返 0）」。
**机器码不支持这句**：

1. 现读 `cards_engine.json`（v44 / count 1129）：`ASH70` 那份 criteria 的
   `targetsAffected = **30 (target)**`（不是 90）。
2. `decomp_full/CardAbility__CanTriggerAbility.c:130` 的实参是
   `CheckIfMeetsCriteria(param_4 /*thisCard*/, param_6 /*targetCard*/, param_6 /*targetCard*/, +0x30)`
   ⇒ **被筛对象与 targetCard 是同一个**。
3. `decomp_full/FilterMethods__CheckIfMeetsCriteria.c:73-91`（`iVar17 == 0x1e` 那一支）：
   `if (op_Inequality(evaluated, 0) == 0) return 0;` → `return op_Equality(evaluated, param_3);`
   —— **只做身份比较就 return**，后面的常规格（含 `traitsFilter` / `excludeTrait`）**一格都不判**。
   ILSpy 交叉（`cpp2il/out_cpp2il_dev_ilspy/FilterMethods.cs:102-175`）同形：
   `if (targetCriteria.targetsAffected != TargetsAffected.target || evaluatedCard == targetCard) { …常规格… }`
   —— ta=target 且身份相符时直接落到返回。
4. ⇒ `ASH70` 的 `excludeTrait=1 / traitsFilter=980` **是死格**（原版也不叠判定）。
   真正会让它「不触发」的只有「targetCard 为 null」（那一支原版 `return 0`，我们回 `null` = 判不了放行 ——
   这是既有三态契约，不是本批引入）。

**处置**：
- ⛔ **不写**「ASH70 已带 Vanguard ⇒ 不叠」那条断言（它按现实现会红，而且红得对）；
- ✅ 断言改成：`ASH70` 的**数据前提**（1 行 / `ThisCardPlayed` 唯一定位到第 0 条）+ 一条结构事实
  （`targetsAffected == 30` ⇒ 判据订正的那一格），行为则用**同形状的合成卡（ta=10）**验闸。
- ✅ 数据里那 8 行 ta=30 的卡因此**本批零可观测**（列表见 §五）。
