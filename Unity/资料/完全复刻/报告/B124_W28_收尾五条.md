## 1 `[B118W23] N2（前提）普通档` —— 批处理没有帧循环，`_blocking` 永不收尾

- **根因**（判据 `BattleDriver.cs:20884-20898`）：`TickBlockingWindow` 只在**帧驱动**里放行
  （`_timeline.Count == 0 && _clock >= _blockingQuietAt`）。批处理不跑帧 ⇒ 上一批演出留下的
  `_blocking` 一直挂到收工 ⇒ `ChatHotkeyUiState()` **正确**返回 3（`BattleDriver.cs:36262-36275` 第 11 支）。
  W27 补的 `!d.WaitingForBlockingAction` 只是把这条前提**改成诚实地永远为假**，不是修好。
- **改法**：进 N 段先 `if (d.WaitingForBlockingAction) d.SetBlockingForTest(false);`（该钩子的注释原文就是
  「批处理没有帧循环 ⇒ `TickBlockingWindow` 不会自己收尾」）——**只放行前置条件，映射函数一个字没碰**；
  同时把 `ChatHotkeyUiState()` 的**全部**前置支路补齐（`AwaitingPlayTarget` / `selector.Visible` /
  `interaction.IsDragging` / `skillPanel.Visible` / `SelectedSlot`），并把每个标志打进断言文案。
- **预期回收**：`N1`（st 1）+ `N2` 前提 + `N2` 主判据 **+3 通过**。

## 4 `[B117G1008] B4 已选那格「钮外 75 px」` —— 与账 `B-12` 的产品闸冲突（改判，⛔ 非放宽）

- **根因（先判后改）**：不是夹具点位算错，`KindAtPoint` 也**没算错** ——
  `AttackSelector.Selectable()`（`Battle/AttackSelector.cs:1581-1586`）第二句
  `if (opt.Kind == _selected) return false;`（判据 = 原版 `UnitOnBoardAttackTypeSelector__AttackButtonClick.c`
  第一句 `if (card.attackType == param_2) return;`，2026-11-02 `B120-W3` / 账 `B-12` 落地），
  而 `KindAtPoint` 与 `OnHoverEnter` **共用这一个口**。圈又**只在已选那格亮**（`IsPickedSlot`）
  ⇒ 「圈放大命中区」在原版语义下**结构上不可观测**（圈亮的那格恰好是打不出去的那格）。
  读数 `up75 = 0.69444` 与 `KindAtPoint == None` **都是对的**（世界档一档：`W(75)×Scale`）。
- **改法**：`B4` 改钉 `B-12` 这道闸：已选那格**圈亮着**（`B4a`）+ 钮外 75 px **不算受体**；
  判别式仍在（删掉 `opt.Kind == _selected` 那句 ⇒ 变 `Melee` ⇒ 红）。几何那半边由 `C2c`
  （圈 176.23×176.875 > 钮 118.372×118.806）钉住；文件头 B 段的旧描述已就地订正（铁律 5）。
- **⚠️ 交调度台裁定的一条判据冲突**：原版**射线层**上圈确实是靶（`m_RaycastTarget = 1` 且已选那格 `SetActive(true)`），

- **预期回收**：1 条。
