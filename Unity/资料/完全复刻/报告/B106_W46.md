## ③ 灭自证怎么写的

**同一道闸的两面**（`WildcardTutorial.TryStart` 的 `if (IsDone) return null`，`Shell/WildcardTutorial.cs:125-133`）：

| 把闸写成 | 哪一条红 |
| --- | --- |
| **恒真**（`TryStart` 永远返回 null） | 上一条 `built != null` 红 ⇒ 证明「没被闸挡住」 |
| **恒假**（把 `StartWildcardTutorialOnPoolBuilt` 里的 `TryStart` 换成 `ForceStart`） | 本条 `... == null` 红 ⇒ 证明「闸真的在趟」 |

两条**结构上不可能同时满足**（除非 `IsDone` 在两次调用之间**真的翻面** —— 而两次调用之间只夹了 `built.State` / `built.PointerVisible` 两条只读断言，没有写 `PrefDone` 的路径：
自检口只调 `TryStart`，`PrefDone` 只在 `WildcardTutorial.Update` 走到 `Owned(false)` 那一支才写，本次没有 `SendMessage("Update")`）。

**写法选择**：按 `B106_W40` §④ 注意 1，用 `CheckTrue(… == null, …)` 而**不是** `Check(…, (WildcardTutorial)null, …)`。
理由：`MenuCheck.Check<T>` 走 `EqualityComparer<T>.Default.Equals`（`Editor/MenuCheck.cs:88`），
对 `UnityEngine.Object` 虽然能用（`Object.Equals` 有 null 感知），但**与既有写法保持一致**更稳（`:10048` 那条已经这么写）。

**为什么先 `ResetProgressForTest()`**：上面 ③ 把状态机推到 `End` 时写了 `PrefDone`（`:10046-10047` 的断言就是断它），
不清的话自检口必定返回 null —— 那会红成「教程起不来」，而真因是夹具没复位（会误导下一个会话）。

**为什么不在末尾再 `ResetProgressForTest()`**（`B106_W40` 建议里有这一句）：本段之后紧跟的就是外层还原块
（`:10093-10098`：按进块时备份的 `hadDone` 写回 / 删键），它无条件覆盖 —— 再清一次是冗余，
而且会让「进块备份 → 出块还原」这条唯一的复位链**看起来有两处**（违反「同一件事只留一处」）。
