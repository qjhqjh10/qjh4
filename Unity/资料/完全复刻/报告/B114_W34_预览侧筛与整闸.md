## 一、两件逐条（判据 → 现状 → 改动）

### 活 1 · `B-270`：预览单位不看 `spec.Side`（真缺陷）

| | 内容 |
|---|---|
| **判据** | 池子的侧是**在建池时**定的：`PlayTargetPool` 只在 `spec.Side == "own" / "any"` 时把**出牌者那一侧的棋盘**加进池（`AddSide(ctx.Players[owner], …)`），`"enemy" / "any"` 时加对手那侧。预览单位（`asIfOnBoard` = 待落地那张自己）**落地必在出牌者那一侧** ⇒ 它是否属于这个池，与 `spec.Side` 是同一个判据。原版这一档同样是「落位后按 `spec.Side` 扫那一侧」（`_ResolvePlayCardFromHand_d__447__MoveNext.c:849-860` → `IsThereValidUnitTarget` → `RawCardScript__GetValidTargets.c:31-45`）。 |
| **现状（改前）** | 侧筛**只**在 `AddSide` 里做；预览是**绕过 `AddSide`** 直接进 `probe` 走 `ApplyTargetFilters`（那里没有侧的概念）⇒ **35 张「敌方目标」的单位卡**会把自己（友军）算进「要不要问」的判定。今天没炸，只是因为那 35 张恰好都 `includeSelf == 0`、被 `PreviewSelfExcludedByCardCriteria` 那条窄口**顺带**挡住 —— **巧合，不是判据**（两格是两个维度）。 |
| **改动** | `EffectResolver.cs:2175` 把 own 侧那个条件**提成一个变量** `ownSideInPool`，`AddSide` 与预览**共用同一处判据**（⛔ 不再是两份）；`EffectResolver.cs:2203` 的并池条件加 `&& ownSideInPool`。老判据 `!PreviewSelfExcludedByCardCriteria(card)` **原样保留**（验收要求，且它在 §一·活2 的 C 段仍有**不可替代**的作用）。 |

### 活 2 · `B-271`：预览应过**整道** criteria 闸（改前只接了 `includeSelf` 一格）

| | 内容 |
|---|---|
| **判据** | 同一份判据：原版是**落位之后**问（`IsThereValidUnitTarget` → `GetValidTargets` → 逐候选 `IsValidTarget`）⇒ 待落地那张自己**也在候选里**，也要过 `FilterMethods__CheckIfMeetsCriteria.c:203-408` 那 36 格。 |
| **现状（改前）** | 预览不在棋盘 ⇒ `TargetCriteriaEval.SideOf` 恒 `-1` ⇒ `Matches` 在**阵营闸**（`TargetCriteriaEval.cs:230-231`）就返 `null`（判不了）⇒ `ApplyCardTargetCriteriaFilter` 按「整条不筛」处置 ⇒ 预览只受了「不依赖棋盘」的那一格 `includeSelf`（`PreviewSelfExcludedByCardCriteria`）。 |
| **改动** | 按 `报告/B114_W30_criteria三处.md` §四 的三步补丁落地：<br>① `TargetCriteriaEval.cs:96` 加可选形参 `int? sideOverride = null`；`:230` 改成 `int side = sideOverride ?? > ⚠️ 仍然**单独跑 probe**（没有把预览塞回 `pool` 统一筛）：`ApplyCardTargetCriteriaFilter` 遇到「判不了」是**整条不筛**，混在一起会让棋盘那批的筛也一起废掉。
