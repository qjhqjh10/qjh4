## 二、判据与证据（含两条**必须让调度台知道**的裁定）

### 2·1 `DisplayBigChat` 的显示本体在原版里被剥了 —— 只能按侧面证据定

- `.c`：`decomp_full/BattleManager__DisplayBigChat.c:13-26` = 两次 `CustomDebug__Log*` + 两次 `return`，
  **没有第三个调用**；ILSpy（`out_cpp2il_dev_ilspy/BattleManager.cs:21664/21683`）在
  `sprite = rawCardData.fullHeroSprite` 之后**整条断掉**。
- ⇒ 版式与「用哪一颗框」**没有第一手判据**。用三条侧面证据定案（全部可复查）：
  1. **13 个战场场景里没有第四颗聊天框**：`Unit Chat` 下只有 `PlayerChatDisplay / EnemyChatDisplay / RadioChat`
     三颗，`sd` **逐字相同** `648.774 × 236.505`
     （`资料/说明书/01_战斗_对战/2D层_battlearena1全树.md:255-306`）⇒「大」= 谁在说，**不是框更大**。
  2. **Sprite 重载拿不到「哪一方」**（形参只有文案 + Sprite）⇒ 显示目标必须**与阵营无关**
     ⇒ 三颗里只有 `RadioChat`（`VoiceLinesOnSceneType.Radio = 2`，`UnitsVoiceLinesPanel__GetChatBox.c` 的 `2→+0x30`）。
  3. 同族 `DisplayWarlordChatMessage` 的那条 tip 走的正是 `ShowChatBox(panel, **2**, data)`
     （本仓 `BattleDriver` 已按它落成 `UnitChatPanel.Speak(2, …)`）。
- ⇒ 代码里已按铁律 18 打标：`BattleBigChat.Side` 那条 doc 明写 `🔶 自己设计（非原版）` + 三条证据 + 为什么拿不到。

### 2·2 🔴 `PlayIconAnim` / `ResolveAbilityIconAnim` 在原版**零调用点**（本 build 死路）

- `grep -rl PlayIconAnim`：`decomp_full/` 只命中 `BattleManager__PlayIconAnim.c` 自己；
  `out_cpp2il_dev_ilspy/` 只命中 `BattleManager.cs`（定义处）。`ResolveAbilityIconAnim` 同样。
- ⇒ **kind 21 从来没有被入过队**，图标动画这一路在原版**从不触发**（不是我们没做）。
- ⇒ 本次**只把形状与参数落地、不接任何触发源**。⛔ 特别**不许**挂到 `EvtKind.Trigger` 上 ——
  那条链已有 `BattleDriver.PlayTraitPulse`（= `ActivateTriggerTraitAnim` 那一支，同样两跳：
  `HighlightTraitIcon` + `DisplayTriggerAnim`），挂上去就是同一件事演两遍。
- 同理 `waitForAnim` 的**消费点没查到**（`FinishResolvingAction` 全文读过，不读这个字段；
  真正读它的应是 `ResolveAction` 那一支，未反编译）⇒ 只做读口，**不据此发明阻塞时长**。

### 2·3 时长参数是从二进制读出来的，不是猜的

`_ResolveAbilityIconAnim_d__475__MoveNext.c` 里两个 `yield return` 分别取 `manager+0x4B0` / `+0x4C8`
（构造里 `WaitForSeconds` 的字面量），用 `工具/read_literal.py` 对 `GameAssembly.dll` 实读：

```
0x1834b2bb0  4B float 0.2     ← +0x4C8（twoFractDelay）
0x1834b2bb4  4B float 0.5     ← +0x4B0（sec5FractionDelay）
```

⇒ `DurationOf(trigger) = trigger == 440(Landing) ? 0.7 : 0.2`。

### 2·4 `trigger → trait` 是**名字对名字**，不是数值表

ILSpy `CardTraitCollection.cs:266` 把 switch 还原清楚了：`Unstable → unstable` · `ThisUnitDeath → backlash` ·
`ThisCardPlayed → rally`，其余 `Enum.TryParse<DefinedTrait>(lowerFirst(trigger.ToString()))`。
我们这边没有 `DefinedTrait` 这个 C# 枚举 ⇒ 用「`TraitFrames` 绑定表里有没有这一位」当同一条判据的代理
（代码里写明这是代理判据 + 认不出时出声一次；原版对 `TurnStart` 这类也返回 `none`）。

**③ 音效 FIFO：两种节奏各一条断言（461/464）**

> 🔴 **2026-10-26 调度台裁定：默认 = 原版「每帧取一条」**（依据 = 他实读
> `BattleManager__Update.c:152` 里那句 `PlayNextSoundInQueue(param_1, 0);` 就在 `Update` 里）。
> 派活包原写「3 条串行、间隔 ≈ clip 时长」**是我们自己编的验收口、不是原版**，已在
> `判据/B9_剩余C_派活包.md` §2·P-12 就地订正。⇒ **两档都要断**（下面 `Gap` 显式设一次，
> 免得依赖默认值；默认值本身也单独断一条）。

```csharp
BattleSfx.ResetCounters(); BattleSfx.ResetQueueForTest();
Check(BattleSfx.Gap == BattleSfx.GapPolicy.OnePerFrame,
      "**默认 = 原版「每帧取一条」**（判据 BattleManager__Update.c:152）—— 不是串行档");

// ── ① 原版档：每帧一条 ⇒ 三条在同一次 DrainAll 里连着出队，间隔恒 0 ──
BattleSfx.Gap = BattleSfx.GapPolicy.OnePerFrame;
BattleSfx.Play(BattleSfx.UnitDamage);
BattleSfx.Play(BattleSfx.MinionHeal);
BattleSfx.Play(BattleSfx.DrawCardFromDeck);

for (int i = 1; i < BattleSfx.Log.Count; i++)
    Check(Mathf.Abs(BattleSfx.Log[i].at - BattleSfx.Log[i-1].at) < 1e-4f,
          $"原版档：第 {i} 条与第 {i-1} 条**同一拍**出队（间隔 0，≈1 帧/条）");

// ── ② 串行档（🔶 可选演示，非原版）：间隔 == 前一条 clip 的时长 ──
BattleSfx.ResetCounters(); BattleSfx.ResetQueueForTest();
BattleSfx.Gap = BattleSfx.GapPolicy.SerialByClipLength;
BattleSfx.Play(BattleSfx.UnitDamage);
BattleSfx.Play(BattleSfx.MinionHeal);
BattleSfx.Play(BattleSfx.DrawCardFromDeck);
BattleSfx.DrainAll();

for (int i = 1; i < BattleSfx.Log.Count; i++)
    Check(Mathf.Abs((BattleSfx.Log[i].at - BattleSfx.Log[i-1].at) - BattleSfx.Log[i-1].length) < 1e-3f,
          $"串行档：第 {i} 条的开始距第 {i-1} 条 = 上一条 clip 的长度");
BattleSfx.Gap = BattleSfx.GapPolicy.OnePerFrame;   // ⚠️ 断言完**必须还原默认**（别污染后面的用例）
```

## 四、差异与风险

1. ✅ **音效出队节奏（已裁定，2026-10-26）**
   - **原版实测** = `Update` 每帧取一条（`BattleManager__Update.c:152` + `PlayNextSoundInQueue.c:20-67`）
     ⇒ 3 条在连续 3 帧（≈16 ms）里放出去，`PlayOneShot` **仍然是叠着响的**。
   - 派活包原写的「3 条**串行**、间隔 ≈ clip 时长」**是我们编的验收口、不是原版**，
     调度台已就地订正（带更正痕迹）。
   - **现行**：`BattleSfx.Gap` **默认 = `OnePerFrame`（原版形状）**；
     `SerialByClipLength` 保留为 **🔶 可选演示档**（会拉长演出窗口），⛔ 别当默认、⛔ 也别把它标成原版。
     `🔶 自己设计` 标记**只挂串行档**（`OnePerFrame` 是照抄，不打标）。
2. **`DisplayBigChat` 还没接线**：`BattleDriver.SpeakTutorialChat` 里 `PlayerChatBig / AiChatBig` 仍走普通气泡
   （`BattleDriver.cs:16929-16945` 那段注释已写明「我们没做」）⇒ P-11 只需一行：
   `BattleBigChat.Display(_unitChat, text, who);`（`who` 是 `CardDef`）。⚠️ 数据侧 6 关教程里 `*ChatBig`
   实测 **0 条** ⇒ 今天零可见影响。
3. **立绘写入口是桥**（295）：`UnitChatPanel.Speak` 只收 `artKey`（→ 卡面插图），而大聊天要 `fullHeroSprite`
   ⇒ 显示后按节点名 `chat_card_RadioChat` 换纹理、比例**先量后拽**（不复制 `UnitChatPanel` 的常量）。
   节点/组件取不到 ⇒ **出声**并退回卡面插图。📌 将来 `UnitChatPanel.Speak` 加 texture 口 ⇒ 删掉这段。
4. **`isWarlord` / `traitValue` 只能由宿主传**：原版是 `DisplayTriggerAnim` **自己从卡上取**，我们没有那条内部链
   ⇒ 不传 = `false` / `NoTraitValue`，后果分别是「督军那道 `playIfWarlord` 门放行（可能多演一次）」与
   「不刷计数器」。已在 API doc 与账的差异列写死。
5. **音效载荷**：原版入队时已持有 `clip`，我们存 `(字段名, cue)`、由 `WFSoundPlayer` 出队那一刻随机挑
   ⇒ 「随机化包装」那一层仍生效（⛔ 没把它当单值）。
6. **结构兜底**：队列 > 256 条 ⇒ 出声一次 + 丢弃（原版没有上限；防「泵没接上还一直入队」跑飞）。
7. **风险（已避开）**：`LastField` 仍写在**入队**那一刻 —— 既有自检
   （`BattleScene.cs:39322-39331` / `:40203`）问的是「这一拍请求了哪条 cue」，改到出队会让它们
   在批处理里全部读空。`BattleSfx.ResetCounters` **语义未改**（新加 `ResetQueueForTest`），
   以免动到账里 `BattleSfx.cs:148 / :153` 那些落点行号。
