## 二、方法学订正（⛔ 下个会话别再照 ExportedProject 的 `.meta` 推这三项）

`d:/2/tools/assetripper_out/ExportedProject` 的 `.png.meta` **不是原版工程的导入设置**，是 AssetRipper 根据包内数据重建的。它**能**反映 `textureType` / `spriteMode` / `spriteBorder` / `spritePixelsToUnits` / `spritePivot`（这些由 `Sprite` 对象的存在与字段决定），**不能**反映四个纯导入期字段 —— 那四个在 3,121 份里是**整齐划一的默认值**：

| 字段 | ExportedProject 现读 | 结论 |
|---|---|---|
| `alphaIsTransparency` | **3,121/3,121 = 1** | 假的（AssetRipper 默认），⛔ 不能当原版判据 |
| `textureCompression` | **3,121/3,121 = 2** | 假的；原版真值只能读 bundle 的 `m_TextureFormat` |
| `maxTextureSize` | 3,088 张 2048 / 30 张 4096 / 3 张 8192 | 不可信；原版真实尺寸以 `m_Width/m_Height` 为准 |
| `nPOTScale` / `mipmapEnabled` | 无有效判别 | mip 真值 = `m_MipCount`（>1 才有 mip） |

> 🔴 与 `判据/B108_AUD09_纹理格式.md` §1·1 同一条口径，本报告复核后**再次确认**。`B108_AUD09_meta.md` §二「36 张被 2048 降采样」已在那份里推翻，本轮用 IHDR 复测：**0 张被降采样**（见 #21）。

## 六、最该先修的（按「原版值 vs 我们值」）

1. **法线图 `textureType`**（23 张）：原版 **NormalMap(1)**，我们 **Default(0)**。修法 = 对 `WarpforgeVFX/Textures/*` 与 `arenas/*/Textures/*` 里那 13 个法线名（`NoiseNRM` / `SplatNormal` / `RippleSubtle` / `Explosion Distort` / `EarthCrackNormal` / `GoopSprayNormal` / `GoopStreakNormal` / `RippleNormal` / `SandDecalNormal` / `SmokePuffNormal` / `Distortion Star` / `Card Booster Pack Normal` / `TinyStonesNormals`）设 `textureType: 1`，`sRGB` 保持 0。**别在 `ArtBaker.ApplyImportSettings` 里写无条件 Default**（它现在无条件写 `TextureImporterType.Default`，`ArtBaker.cs:460`）。

## 七、没查清（如实记，⛔ 不拿猜测填空）

1. **78 个「代码里带 border」的精灵没有逐条全量核** —— 只抽了 5 个逐字相等。全量核要按「名字 → `Nine(...)` 的实参」逐处读，`grep` 窗口法**不可用**（实测窗口会抓到旁支的 `new Vector4(-20,-20,-20,-20)` 之类的射线 padding，523 个候选里 314 个是噪声）。**下一波做这个时必须人工定位每个 `Nine(...)` 调用点。**
2. **`m_PixelsPerUnitMultiplier` 没有全量账** —— 原版 6,328 处 Image 里 `1` 占 6,328 的绝大多数，其余 13 种取值共 ~800 处。我们只核了已落地的 6 个常量。**要全量，得按 prefab 逐 Image 对到我们的绘制点**，成本高、判据齐（`ExportedProject/*.prefab` 直接读），但本轮没做。
3. **`CompressedHQ` 在 StandaloneWindows64 上是否 100% 落 BC7 未实读** —— 本轮是「`.meta` 声明 + Unity 语义」，没跑 `-executeMethod` 读导入后 `Texture2D.format`（红线：不跑 Unity）。
4. **图集 padding / 打包参数拿不到** —— 原版只留运行时 `SpriteAtlas` 对象，packing settings 不序列化（#36）。
5. **`alphaIsTransparency` 没有原版真值**（#23），只有「用途级」判据。

## 八、顺手发现（不属于本报告结论，但下个会话要知道）

1. **`ArtBaker.ApplyImportSettings` 无条件写 `textureType = Default` + `mipmapEnabled = false`**（`ArtBaker.cs:460/469`）—— 它是 #16（法线）与 #3（mip 21 张）的**同一个根因**。改它要按子树加例外，⛔ 别改成「全部 Sprite」。
2. **`ArtBaker.ApplyImportSettings` 只扫 `Resources/Art`** —— `Resources/Fonts/**`（TMP SDF 图集）与 `WarpforgeVFX/Runtime/Vat/**` 从来没被它管过，这正是 #15 / #13 长期存在的原因。
3. **`WarpforgeArena1/arenas/**` 的 mip / sRGB 已经修完**（231/231 一致）—— `B108_AUD09_纹理格式.md` §3·2 的「114 张缺 mip / 41 张 sRGB」**已过期**，引用前先按本报告复测。
4. **卡背「尺寸对不上」是预期**：466 张里 233 张 `_Main` 是 `textureRect` 紧裁件（624×933 等），不是 1024² —— 比对时**必须拿 `Sprite.m_RD.textureRect` 当尺子**，⛔ 别拿 `Texture2D.m_Width`（会得出「233 张全错」的假结论）。
5. **`WarpforgeVFX/Textures/*_sprite.png` 有 18/87 张是紧裁未补画布** —— 只有当 Sprite 用时才出错（目前都是粒子贴图，安全）；将来谁把它们挂 `SpriteRenderer` 要重新按 `m_Rect` 补边。
6. **图集包含列表覆盖 419/544**（125 名缺 PNG）—— 归**资源覆盖线**，不是导入设置。
7. 🔴 **`ArtBaker.ApplyArenaImportSettings` 会把已经修好的战场 mip 一次打回原形**：它在 `ArtBaker.cs:625` 对**全部** arena 贴图写 `ti.mipmapEnabled = false`，而本轮实测这 231 张的 mip 已经**逐张**与原版 `m_MipCount` 对齐（`ok 231 / missing 0 / extra 0`）⇒ **谁重跑这个方法，那些原本有 mip 的贴图会立刻变回无 mip**（`B108` 全量记的是 114 张，含 VFX；本轮实测 arena 侧 `mip` 已 231/231 与原版一致，**一次烘焙就静默回退，零报错**）。重跑前必须先把那一行改成「按原版 `m_MipCount>1` 决定」。
