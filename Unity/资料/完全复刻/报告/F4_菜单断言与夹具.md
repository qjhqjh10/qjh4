## (1) `Editor/BattleScene.cs` · sneakAttack 夹具 —— **夹具写错（δ）**

**落点**：`Editor/BattleScene.cs:9902-9907`（攻击预览·反击豁免闸那一节）

**原写法**
```csharp
pAtk.AddTempBuff(new UnitState.TempBuff
{
    IsKeyword = true, Name = RuleEngine.KeywordTable.SneakAttack, Value = 1,
    Owner = 0, UntilMyNextTurn = true, Src = "夹具", SourceCard = "夹具",
});
```

**新写法**
```csharp
pAtk.AddKeyword(RuleEngine.KeywordTable.SneakAttack, 1);
```

**为什么新写法能抓住坏法（灭自证在哪）**
- 原夹具**挂不上关键词**：`UnitState.AddTempBuff`（`RuleEngine/Core/UnitState.cs:1681-1686`）只做 `_buffs.Add(b)`；
  `IsKeyword` 仅在 `RevertBuffs` 里用于 `RemoveKeyword` **记账**，**不写 `_keywords`**。
  而 `Has(keyword)`（`UnitState.cs:968-972`）**只读 `_keywords`** ⇒ `pAtk.Has(SneakAttack)` 恒 false ⇒ 豁免闸根本不成立。
- 正规挂词口 = `AddKeyword`（`UnitState.cs:1120` 签名 / `:1139` 写 `_keywords[keyword]`）。
- 豁免闸本体（`RuleEngine/Core/CounterAttack.cs:49` `if (attacker.Has(KeywordTable.SneakAttack)) return true;`）**未动**。
  灭自证靠**同一节内的对照组**：攻方没豁免 ⇒ 上一格 `withCounter.WillDie` 仍为 ✓；加了 `AddKeyword` 后这一格
  `noCounter.WillDie` 必须为 false —— **两格在同一局、同一张守方、只差攻方身上那条 keyword，结论结构上不可能同时成立**。
- 行数：本处**净 0 行**（原 6 行块 → 新 6 行块，`var noCounter` 仍在 `:9907`）⇒ 下游 25 条账落点零漂移。

**判据出处**
- `RuleEngine/Core/UnitState.cs:1681-1686`（`AddTempBuff` 只 add）· `:968-972`（`Has` 只读 `_keywords`）· `:1120/1139`（`AddKeyword`）
- `RuleEngine/Core/CounterAttack.cs:43-49`（`NoCounter` 第① 通道 = sneakAttack）
- 旁证：同节对照组（攻方没豁免 ⇒ 预览判被打死）原本就是 ✓ ⇒ 闸没坏，是夹具没挂上

## (2) `Editor/DraftAssertD3.cs` · 面板 `sizeDelta` —— **断言的量纲错了（×108）**

**落点**：`Editor/DraftAssertD3.cs`（轮抽 Alliance Info 页 · `Alliance Event Score Panel`）

**原写法**
```csharp
Mathf.Abs(scoreRt.sizeDelta.x - 383.59f) < 0.5f
Mathf.Abs(scoreRt.sizeDelta.y - 511.52f) < 0.5f
```
（直接拿 `sizeDelta` 比**设计 px** —— 差 108 倍，必红）

**新写法**
```csharp
float swPx = scoreRt.sizeDelta.x * 108f;
float shPx = scoreRt.sizeDelta.y * 108f;
Ok(scoreRt != null
   && Mathf.Abs(swPx - 383.59f) < 0.5f
   && Mathf.Abs(shPx - 511.52f) < 0.5f,
   "⑦ 面板 `sizeDelta × 108` = 383.59×511.52 设计 px（实测 " + swPx.ToString("F2") + "×" + shPx.ToString("F2") + "…）");
```

**为什么新写法能抓住坏法（灭自证在哪）**
- `MenuDraw.SetPxSize`（`Shell/MenuDraw.cs:203-213`）写的是 `LayoutSpace.Px(w) = w / 108`
  （`Core/LayoutSpace.cs:208-211`：`DesignPxH 1080 / DesignHeight 10`）⇒ **`sizeDelta × 108` 才是设计 px**，
  本工程惯例见 `Editor/MainMenuScene.cs:2118` 的 `sizeDelta.x * 108f`。原来少了这一步 ⇒ 量纲差 108 倍。
- 期望值 383.59 / 511.52 是**原版 prefab 几何**（`判据/B90_C2b_远端prefab几何.md` §A），⛔ 不是从我们实现里读出来的。
- **把实测值打进断言消息**（`实测 {swPx}×{shPx}`）—— 下次一眼就能看出量纲对不对（若又写成裸 `sizeDelta`，消息里会出现 `3.55×4.74`）。
- 只读 `sizeDelta`、**不乘 `localScale`**：`localScale ≈ 0.95581` 是独立的一个量（上面 `:1368-1372` 那条单独断）——
  ⛔ 别把两个量乘到一起（那会自造一个 366.66 的新数）。
- ⛔ 没有把 `AllianceEventScorePanel` 的 `sizeDelta` 改成 383.59（那会让全链几何 ×108）。

**判据出处**
- `Shell/MenuDraw.cs:203-213`（`SetPxSize` = `LayoutSpace.Px`）· `Core/LayoutSpace.cs:208-211`（`Px = px / 108`）
- `Editor/MainMenuScene.cs:2118`（本工程 `sizeDelta * 108f = 设计 px` 的惯例先例）
- `判据/B90_C2b_远端prefab几何.md` §A（383.59×511.52）

## (3) `Editor/MainMenuScene.cs` · 队伍卡还原 —— **断言自相矛盾**

**落点**：`Editor/MainMenuScene.cs:20555-20557`（队伍卡三格还原）

**原写法**
```csharp
CheckTrue(nmLb != null && nmLb.Text == nm0 && capLb != null && capLb.Text == cap0
          && imgA.GetComponentInChildren<ImageQuad>(true) == null,
          "（还原·队伍卡三格）文本回到断言前那一版、图槽回到空态");
```

**新写法**
```csharp

CheckTrue(nmLb != null && nmLb.Text == nm0 && capLb != null && capLb.Text == cap0
          && (restoreQ == null || !restoreQ.gameObject.activeSelf),
          "（还原·队伍卡三格）文本回到断言前那一版、图槽回到空态"
        + "（= `SetTeamImage(side, null)` 的可观测结果：载体可留、但必须关 —— 与上面 `backQ` 同一谓词；⛔ 别要求销毁载体）");
```

**为什么新写法能抓住坏法（灭自证在哪）**
- 同一方法**前面** `:20536-20538` 对同一件事用的就是 `q == null || !q.gameObject.activeSelf`（**接受「关着」**）；
  `:20555` 却要求 `== null`（**载体必须消失**）⇒ 两条自相矛盾，且后者与实现不符。
- 实现 `Shell/ParentEventWindow.cs:1609-1626`：`SetTeamImage(side, null)` = `if (q != null) q.gameObject.SetActive(false);`
  （**不销毁载体**，注释写明「与 `sprite = null` 同一可观测结果」）⇒ 收尾这一条按「载体必须消失」写**必红**，
  且它逼人把实现改成 `Destroy`（会破坏「重建时不重建载体」的复用语义）。
- 新谓词 = 「载体不存在 **或** 关着」，仍能咬住「`SetTeamImage(null)` 后旧图**还亮着**」这个坏法（那时 `restoreQ` 在且 active ⇒ 红）。
- ⛔ 没有把 `SetTeamImage(null)` 改成 `Destroy`。

**判据出处**
- `Shell/ParentEventWindow.cs:1609-1626`（`SetTeamImage(side, null)` = `SetActive(false)`，不销毁）
- `Editor/MainMenuScene.cs:20536-20538`（同方法前面已用「关着」谓词）
