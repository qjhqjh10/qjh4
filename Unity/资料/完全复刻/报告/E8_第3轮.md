## 四、断言（宿主不在本批白名单 ⇒ 写成**纯函数式**的 `CardTierConfig.SelfCheck()`）

> 本批**未跑 Unity**（红线）⇒ 以下是**已编译进代码**的检查口，返回失败清单（空 = 全过）；
> 将来宿主只需 `foreach (var f in CardTierConfig.SelfCheck()) Check(false, f);` 就接上了。
> ⚠️ 数值层面本代理另用 float32 精度的等价实现**离线实算过一遍**，结论一致（见 §六·②的曲线表）。

```csharp
// CardPresentation/Shell/CardTierConfig.cs:433（原文照贴）
public static List<string> SelfCheck()
{
    var fail = new List<string>();
    var c = Instance;

    // ①-a 往返
    for (int n = 1; n <= 50; n++)
    {
        float acc = c.GetAccumulatedXPForLevel(n);
        int back = c.GetLevelForXP(acc);
        if (back != n)
            fail.Add("① " + n + " 级往返不等：`GetLevelForXP(GetAccumulatedXPForLevel(" + n + "))` = " + back
                   + "（累计 XP = " + acc + "）");
    }
    // ①-b 单调不减
    float prev = c.GetXPRequired(1f);
    for (int l = 2; l <= 50; l++)
    {
        float cur = c.GetXPRequired(l);
        if (cur < prev - 1e-3f)
            fail.Add("① `GetXPRequired` 在 level=" + l + " 下降：" + prev + " → " + cur
                   + "（自拟标量选错，判据 = 报告 §末「选参理由」）");
        prev = cur;
    }
    // ② 灭自证：三个不同值同时成立
    if (!(c.GetLevelForXP(0f) == 1
       && c.GetLevelForXP(c.GetAccumulatedXPForLevel(2)) == 2
       && c.GetLevelForXP(c.GetAccumulatedXPForLevel(5)) == 5))
        fail.Add("② 等级是常数（灭自证失败）：`lvl(0)` = " + c.GetLevelForXP(0f)
               + " · `lvl(acc(2))` = " + c.GetLevelForXP(c.GetAccumulatedXPForLevel(2))
               + " · `lvl(acc(5))` = " + c.GetLevelForXP(c.GetAccumulatedXPForLevel(5)));
    // ③ 取整语义
    if (c.RoundPrecision != 5f)
        fail.Add("③ `RoundPrecision` = " + c.RoundPrecision + "，原版构造函数写死 5f");
    for (int l = 1; l <= 60; l++)
    {
        float xp = c.GetXPRequired(l);
        float units = (xp - c.Offset) / c.RoundPrecision;
        if (Mathf.Abs(units - Mathf.Round(units)) > 1e-3f)
            fail.Add("③ level=" + l + " 的 `GetXPRequired` = " + xp
                   + " 不是 `RoundPrecision` 的整数倍 + Offset（取整没做上）");
    }
    return fail;
}
```

**每一条在挡什么（改坏了会怎样）**

| 断言 | 改坏法 → 它怎么红 |
|---|---|
| ①-a 往返（n=1..50） | 把 `sum > xp` 写成 `sum >= xp`、或 `num-1` / 下限 1 写错 ⇒ 某些 n 回来是 n±1 |
| ①-b 单调不减 | 把 `Base` 改成负数（判据文件那个**举例值** `-0.15`）⇒ 后半段逐级下降，立刻一条条爆 |
| ② 灭自证 | 把 `GetLevelForXP` 改成 `return 1;`（或整条曲线摊平成常数）⇒ 三个值里有两个对不上 |
| ③ 取整 | 把 `Math.Round` 拿掉（直接 `num12 = num10`）⇒ 返回值不再是 5 的整数倍 |

### ② 选参理由（为什么是 `Y_Max=100 · X_Inflection=20 · Offset=0 · Base=+0.15`）

1. **`Base` 必须取【正】**（判据文件 §五 那个例子写的是 `-0.15`，原文是「如」= 举例）：
   `num4 = Base·((level−XI)/(XI/5))`，`Base<0` 时 level 越大 `num4` 越负 ⇒ `Exp` 越小 ⇒
   `1/(Exp+1)` 越大 ⇒ `1−num6` 越小 ⇒ **每级所需 XP 越来越低**，上界退化成 `Offset` ——
   那与字段名 `Y_Max`（= **最高**每级需求）自相矛盾，而且 ①-b 单调断言必红。
   `Base>0` 时高等级趋近 `Y_Max`、低等级最小 ⇒ 单调不减、`Y_Max` 名副其实。
2. **量级用「每张卡最多给 4 次 XP」反推**（`CardTier` 只有 Tier1..Tier4）：实算（`RoundPrecision=5` 取整后）
   `lvl1 → 35 · lvl6 → 35 · lvl7 → 40 · lvl20 → 50 · lvl60 → 80 · 上界 100`；
   累计 `1→2 级 = 35 · 2→3 级 = 70 · 3→4 级 = 105`。
   ⇒ 前期每级 35–40、等级越高越贵、长期收敛到 100，是「千位数总量」的量级，
   不会一进游戏就冲过 `GetLevelForXP` 的 `num > 9999` 上限保护。
3. **`X_Inflection = 20`** 让「明显变贵」发生在 20 级之后（前期平缓 = 新号体感不憋）；
   **`Offset = 0`** 让 XP 从 0 起算（`GetLevelForXP(0) == 1` 才是「0 经验 = 1 级」）。
4. 这 4 个数**只出现在构造函数那 4 行**（`:133-136`）：远端真配置出现、或用户另定 ⇒ **只改这 4 行，算式不动**。
