## 五 · 结构性差异（如实记，⛔ 不假装已一样）

1. **`MainMenuMission` 那格镜像没落**（`.c:118-127`）：`progress.resetProgress == true` 时原版会写
   `MainMenuMission.HasFailed(+0x30) / FailedValue(+0x34)`。本仓**没有 `MainMenuMission` 子类**
   （`grep MainMenuMission` 只剩注释）。它只影响**主菜单的失败弹窗**，不改进度数值。
   ⇒ 我们**不静默吞**：`resetProgress` 为真时出声一次（`WarnProgressResetMirrorOnce`，`MissionEvent.cs:1169`）。
2. **云脚本 `0x38b` 上传没做**（`.c:128-190`）：原版在「进度真的变了」之后拼 `ToolTipData` 并调
   `PlayfabWrapper.GenericCloudScriptHandler(0x38b, …)`，回调 `b__0` 再把服务端回包写回存档。
   **关服 ⇒ 判据在远端**，按 `CLAUDE.md` 18·0（只有服务器相关才允许自己设计）判为**本地落地 + 不发出**，
   代码里挂 `🔶 自己设计（非原版）` 并写全三样（是什么 / 为什么 / 谁定的 + 日期）。
   玩家看得到的那部分（进度数值）与联网时**一致**；差的是「服务端备份」。
3. **`TroopKilledSignal` 载荷收窄**：原版两格都是 `CardScript`；我们只剩 `bool killerIsPlayer`。
   理由 = 唯一消费者 `.c` 全文**只读 `killer.isPlayer` 这一位**，而 `CardScript` 不在 `Shell` 层。
   「结构不同、语义相同」⇒ 按 18·0「⛔ 不许打标记」第②类，**未挂 🔶**。
   ⚠️ 副作用：「凶手是 null」这一档**表示不出来**（原版是抛异常 ⇒ 不计数）⇒ 已写进 doc：喂入方不知道凶手时**别发信号**。
4. **`EnergySpentSignal` 载荷收窄**：去掉 `Card`（同上，消费者一格没读）。
5. **`🔶` 桥 `TroopsKilledCount.RaiseKilledForPlayer(int)`**：原版**没有**这个方法（逐杀由 `ChallengeLogMgr` 发）。
   我们因为 `EvtKind.Death` 不带凶手只能按累计值补发 ⇒ 挂 `🔶 自己设计（非原版）`，三样写全。
6. **「逐杀实时」做不到**：`EvtKind.Death`（`RuleEngine/Core/BattleEvent.cs:510-543`）只有

## 六 · 顺手发现（⛔ 只报不改）

   否则这条挑战在两边都是死的。已在 `ApplyProgressPayload` 的 doc 里写死。

   只放行 `DailyLoginChallenge`（原版同）。⇒ 新建档玩家打完第一局，这两条挑战**一条都不会动**。
   B4 接线后若「真机上什么都没发生」，**先查这一条**，别急着怀疑信号没发。
4. ⚠️ **`Shell/RewardCollected.cs` 与新基类两套并存**（R7 §二·4 已记）：它自带 `Progress` + `ProgressSink`，
   **不走** `MissionChallenge`。本批**没动它**。它现在也能吃到 `ApplyProgressPayload` 的新能力**但用不上**
   （它不是 `MissionChallenge` 子类）⇒ 归属与处置由调度台定。
