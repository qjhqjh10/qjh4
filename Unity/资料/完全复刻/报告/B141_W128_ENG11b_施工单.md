### 判定条件（怎么识别「载体是 `ca 320`」）

```text
ListenerBodyYieldsToFollowUp(card, kind, selfOnly):
  tn = TriggerNameOfWhenKind(kind, selfOnly);            // 拿不到名字 ⇒ false
  n  = CardDef.AbilityTriggerNumber(tn);                 // <0（认不出）⇒ false
  rows = card.TriggerAbilityRowsOf(n);                   // null = 列未知（旧表 < v42）
  if (rows == null) return FollowUpSchedulerOf(card) == tn;   // 旧表退回硬编码表（= 改前行为的等价物）
  if (rows 里没有 Ca == 320 的行) return false;                // 不是载体 ⇒ 正文照旧
  return AllChosenAbilityRowsExecutable(card, 410);           // ⭐ 关键：410 那一边必须**全部**有执行器
AllChosenAbilityRowsExecutable(card, 410): rows=TriggerAbilityRowsOf(410)；每行 Ca ∈ {30,40,50}（本批补完之后的能力集），否则 false
```

⭐ 最后一条是**安全闸**：只让路、不保证「有人接」= 效果凭空消失（W48 §七·1 的「只做 (a) = 效果消失」）。现读两张卡都过：`ASH81` 的 410 = `ca 40 + ca 40`、`GSC14` 的 410 = `ca 30`。

## 四 数据缺口：`GSC14` 的 `targetCard`（本批**不必**补）

- 原版值 = 被打出那张战术的 `targetCard`（W48 §二）。我们两处 `BroadcastWhen(WhenEventKind.Play, …)` 都把它留成 `null`：
  - `EffectResolver.cs:2724`（战术出牌）`BroadcastWhen(ctx, WhenEventKind.Play, p, card, null);`
  - `RuleCore.cs:4204`（单位出牌）`BroadcastWhen(ctx, WhenEventKind.Play, p, card, unit);` —— 第 5 实参是 `subject`，`target` 仍是缺省 `null`。
- 要补得改两处调用点，把「这张牌打出时点定的那个目标」放进第 7 实参 `target`（战术路在 `PlayTacticCore` 里已有 `chosen`；单位路要从 `Deploy` 的目标传递链拿）。**风险**：`target` 会经 `EventSlotsScope.TargetAndCard` 种进 `ctx.EventTarget`，**所有** `When … plays …` 监听者的「the target of the attack」类指代会一起看到它 ⇒ 波及面远超本件。
- ⇒ **本批结论：不补**。判据上也不吃亏：`GSC14` 的 410 行 `ta = 10`（`abilityTargets` 现读），`ta 10` 不吃调用方给的目标（`AbilityLogic__GetTargets.c:192-207` 只有 `30/220` 读 `param_5`）；`ASH81` 的 `ta = 20` 同理。**记成一条独立待办**（需要先盘清 `Play` 事件 target 的语义边界）。
