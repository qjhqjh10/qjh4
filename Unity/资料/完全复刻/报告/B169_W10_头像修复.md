# B169/W10 · 头像只换框修复（mod 侧）

> 判据：`B169_J92_头像与回放诊断.md` §1·3 / §1·4。
> 结论：数据侧无需改；缺陷在 `ProfileFixProbe.FillTopBar` 取了**默认件**并只打一次。
> 已改成 `PlayerAvatarItem ?? DefaultAvatarItem` / `PlayerAvatarBorder ?? DefaultAvatarBorderItem`，
> 并按 id 变化重打；换头像后下一 tick 顶栏与资料页/头像页一起刷新。

## §一 改了什么（`Probes/ProfileFixProbe.cs`）

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| `FillTopBar` 取头像 | `DefaultAvatarItem`（默认件） | `PlayerAvatarItem` 优先，取不到才回落 `DefaultAvatarItem` |
| `FillTopBar` 取边框 | `DefaultAvatarBorderItem` | `PlayerAvatarBorder` 优先，回落 `DefaultAvatarBorderItem` |
| 一次性闸 | 函数第一句 `if (_done) return;` | **已删**；改为「头像 id / 边框 id 变了才重打」（`_lastAvatarId` / `_lastBorderId`） |
| 刷新触发 | 只靠启动时一次 | 每次换头像/边框 ⇒ `_tabsRefreshed = false` ⇒ 下一 tick 重跑页签 `Initialize` |
| 页签刷新名单 | `TitleTab` / `AvatarTab` | 追加 **`ProfileTab`**（资料页的 `PlayerInfoDisplay.Initialize` 也要重取头像） |
| 日志 | `FILLED` | 追加 `AVATAR used=<id> src=live 或 default border=<id> borderSrc=live 或 default` |

- 新增两个反射小工具：`IsNullRef`（IL2CPP 的 `Pointer == 0` 也算 null；只看 `== null` 会把空引用当有效值）、
  `SafeId`（`PlayerItem.GetID()`，退回 `uniqueId`）。
- `TICK` 探测行从「有 avatar 之后每秒打」改成「只打前 10 个 tick」（原来靠 `_done` 早退才不刷屏）。
- 判据出处：当前件 `PlayerAvatarItem` = PADM `:443`、`PlayerAvatarBorder` = `:510`（`B169_J92` 表）；
  两者为 null 时消费方**跳过、保留旧图** ⇒ 「只换框」就是喂了 null 头像。`SetProfileAvatar/SetProfileAvatarBorder` 走原版口。
- 落点（现读，`Probes/ProfileFixProbe.cs`）：字段 `:60` · 取值 `:139-140` · id 变化闸 `:171` ·
  应用 + `AVATAR` 日志 `:186-196` · `ProfileTab` 刷新名单 `:657` · 新工具 `IsNullRef :1063` / `SafeId :1076`。

## §二 行为

1. 启动：等 cosmetics 就绪 → 用**当前件**打顶栏（`src=live`）；当前件还没加载时才用默认件（`src=default`，并会在下一 tick 自动换成 live）。
2. 玩家在头像页换头像/边框：`PlayerAvatarItem`/`PlayerAvatarBorder` 变化 ⇒ 1 秒内顶栏更新，
   并把 `AvatarTab`/`ProfileTab`/`TitleTab` 重新 `Initialize` 一次（不伪造数据，实际值仍取自 PADM）。
3. 值不变时不重复 `SetProfileAvatar`（避免每秒覆盖/打断动画）。
4. 日志只在「应用成功」时打一行 `AVATAR`（首冲 + 每次变化）。

## §三 风险 / 未验

- `ProfileTab.Initialize` 是 private 无参方法（`dump.cs:83445-83495`），用现有 `InvokeNoArg` 反射调用；
  若它依赖页签处于激活态，`Initialize` 可能空跑 —— 会写 `TAB-REFRESH ... fail:`，不会影响其它页。
- **未起游戏**（按任务约束）。实机验收：换头像后看 `profilefix.tsv` 是否出现
  `AVATAR used=<新 id> src=live`，并确认顶栏与资料页头像同时变化。
- 未改数据侧（`avatarUrl` 两半已完整，`server.py:1634-1638` 已注入）—— 与判据 §1·4「数据侧不用改」一致。

## §七 OFF-101 头像边框「切不回默认」（已做 · `Probes/BorderFixProbe.cs` 新建）

**判据**：`报告/B169_J101_头像边框诊断.md` §一/§二 —— `AvatarTab.ToggleAvatarBorder` 是二值切换；
切成金色后 `IsDefaultBorderEquipped()` 为假 ⇒ 目标改取 `DefaultAvatarBorderItem`，运行时是 **null**
⇒ `SetCurrentItem(null)` 抛 NRE（`avatarprobe.tsv` 19 次 `SETCURRENTITEM-IN NULL`）。

**做法（最小改动，⛔ 不改二值切换语义）**：`AvatarTab.ToggleAvatarBorder` 挂 **prefix**，只接管「切回默认」那一路。

- `FindActiveAvatarBorder()` 为 null ⇒ 放行原方法（原方法自己 return）；
- `IsDefaultBorderEquipped()` 为真（Default → 活动边框）⇒ 放行原方法（正常方向一字不改）；
- 为假（活动 → Default）⇒ 改从 `InventoryManager.GetInventory<CosmeticItemAvatarBorder>().GetItems()`
  里按 id **`36ae26bb6bd304e79bd17fe02fbd3725`** 取默认边框（⛔ 不用 `DefaultAvatarBorderItem`），
  取到就 `SetCurrentItem(default, RefreshDisplays)` 并 `return false`；
  **取不到 ⇒ 保持当前状态 + `NULL-GUARD` 日志，`return false`**（⛔ 绝不把 null 传进 `SetCurrentItem`）。
- 回调委托用 `DelegateSupport` 两步查找把托管 `System.Action` 转成 IL2CPP 委托；转不出去就传 null 并立即 `RefreshDisplays()`。

**日志** `phase0/borderfix.tsv`：`TOGGLE used=<id> src=inventory` · `NULL-GUARD …` · `INV-EXC/EXC …`（上限 200 行）。
**风险**：默认边框是否真在 Inventory 里由诊断 §四-1 留下的两个候选之一（收藏集缺项 / getter 内联）——
本修法绕开 `DefaultAvatarBorderItem`，只要 Inventory 有这条（`playfab_profile.json` `UserInventory` 的 5 条边框在），就能切回来；
若 Inventory 也缺，日志会写 `INV 库存边框 N 条，未命中`，此时保持现状（不会再 NRE）。未起游戏，实机待验。

## §十 OFF-98 布局炸掉后的修正（2026-11-07 · 待再验）

**实机现象**：两个按钮都变成 `470.7×120.8`、横向重叠压住标题；克隆体保留了 `cards`/`cost`，多出一条价格条。

**根因**：`LayoutGroupContentFixer.FixLayout()` 会 `LayoutRebuilder.ForceRebuildLayoutImmediate`
（`decomp_full/LayoutGroupContentFixer__FixLayout.c`），把按钮重建回**内容首选尺寸**；上一版在两个按钮上
都调了它 ⇒ 200×60.3 被撑成 470.7×120.8。

**本轮改法**（`UpgradePanelTweaksProbe.cs`）：

- **不再调用 `FixLayout()`**；克隆体上的 `LayoutGroupContentFixer` 直接 `enabled=false`。
- 尺寸用 **`sizeDelta` + `SetSizeWithCurrentAnchors(Horizontal/Vertical)`** 双写；设完先 `Canvas.ForceUpdateCanvases()`
  把挂起的布局重建冲掉，**再钉一次**并回读（`RECT up=… down=…`）。
- 坐标：`Upgrade=(104,-0.3)`、`Downgrade=(-104,-0.3)`，各 `200×60.3` ⇒ 中间 **8px**，合计 408 < 450。
- **裁克隆体**：隐藏 `cards` / `cost` / `Button Text`；用 `cards/quantity`（真 TMP）克隆一条居中文案
  `DowngradeText`（`size=180×50`、`anchoredPosition=(0,0)`）写 `Downgrade`（避免中文无字形）；
  日志 `PRUNE hidden … / text cloned from cards/quantity / texts=0|1`。
- 这轮只保证「不重叠、各 200 宽、降级按钮只有文字」；**降级功能联调放下一步**。

**仍可能的风险**：① 若本帧末尾还有别的 canvas 布局重建，尺寸可能被改回一次（下次 `CheckUpgradeRequirements`
会再钉；`RECT` 行可验）；② 若 `cards/quantity` 克隆/TMP 写值失败（`texts=0`），按钮会是空底图；
③ `ForceUpdateCanvases` 需要从 `UnityEngine.UIModule` 反射（csproj 未引用），找不到时只是不冲刷，不影响主流程。

## §十四 降级按钮点不动（EVerguildButton 没找到）→ 已修（2026-11-07）

## §二十二 克隆体 TMP 拿不到 → 「先在原件写好再克隆」（2026-11-07）

**实机**：`LABEL src=titleText set=FAIL exc=comp=null(tmp=TextMeshProUGUI); scan=0`
⇒ 从原始 `titleText` 克隆出来的节点上，`FindTmpComponent` 三条路都拿不到 TMP（克隆出来的组件代理只给基类）。

**改法**（`BuildLabel` / 新增 `PrewriteAndClone`）：

1. 不再「克隆后写副本」；改为**先在原始 TMP 上写**：
   - 取原始 `titleText`（中文 TMP，FIELD 已证实类型）的 `text`/`alignment`；
   - `SetTmpText(原件, "降级")` + `alignment=Center` + `ForceMesh`；
   - `Instantiate(原件)` 到按钮根 —— **副本继承写好的文本与对齐**；
   - **立刻恢复原件**的 `text`/`alignment` 并重画（同一调用内完成，不会露出中间态）。
2. `titleText` 不可用时同样处理原始 `neededCards`；再退到克隆体自带的 `Button Text` / `cards.quantity`。
3. 日志新增：`LABEL-SRC from=<titleText(prewrite)|…> tmp=<True/False> set=<文本|FAIL>`
   （`tmp=False` 说明副本的代理拿不到组件，但文本已由预写继承，仍应显示）。
4. `Tick` 仍保持停用（不接回 `ModMain.OnUpdate`）。

**如果这条仍不行**：按协调人意见停手，文案改为英文 `Downgrade`（一行字符串）或接受空按钮，单独记待办。
