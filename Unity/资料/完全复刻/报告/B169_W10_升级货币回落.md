## §二 回落逻辑

1. **原方法先跑**，`__result == true` ⇒ 立即 return（正常路径零改动）。
2. `false` 且 id 命中 6 个虚拟货币名（`gold/crystals/blackStones/tickets/energy/campaignPoints`，
   大小写不敏感；`tickets` 归一成档案键 `gachaTickets`）⇒ 读
   `PlayerDataManager.singletonManager.userInfo.UserVirtualCurrency[key]`（与 `Stubs.Pre_GetOwnedCount` 同源）。
3. 够 ⇒ `__result = true`；不够 ⇒ 保持 `false`。
4. `energy` 不在 `UserVirtualCurrency`（原版走 `EnergyContext`）⇒ 走 `SharedEventDataManager.SharedContexts`
   的 `GetCurrentEnergy()`；读不到**不改结果**（不瞎给能量）。
5. **其它任何 itemId（卡 id / 通配符 id）一律交给原方法**，不做任何改动；⛔ 只改「够不够」，**不扣钱**。

## §四 风险

- **泛型共享**：IL2CPP 引用类型共用 `<object>` 代码 ⇒ patch 会截到「所有 T」的 `HasEnough`；
  已用「id 必须命中 6 个货币名」硬闸兜住，其余 id 原样返回。
- **`MakeGenericMethod(Currency)` 依赖运行时元数据**：同机制已被 `AvatarProbe.GetAllItems<PlayerAvatar>` 实证
  （`hooks OK` + `avatarprobe.tsv:24` 有真实调用）；若异常，日志写 `FAIL`，不改游戏行为。
- **只修门控、不修白块**（`costIcon` 仍 null，属 B169/W7）；**份数闸未动**（库存 2 份仍需 J92 §三-1）。
- 本文件与 `UpgradeFixProbe.cs` 均为 `🔶 自己设计（非原版）`：gold 的 Currency SO 本地不存在、服务器已关服。

## §六 OFF-95 追加：升级门控只读诊断（2026-11-07 第二段）

**现状**：实机 `upgradefix.tsv` 已出现 `ALLOW currency=gold need=225 have=2000 => true` ⇒ 货币闸已通；
库存 `add_inventory.py --copies 7` 后卡牌详情显示 `x1/6`，但点升级面板**仍然 0 条 `UpgradeCard` 请求**。

**门控判据**（`decomp_full/UpgradePanel__CheckUpgradeRequirements.c:60-110` 现读）：
`iVar5 = InventoryManager.GetOwnedCount<RawCardScript>(originalCard)`（**`T item` 重载**，非 string 重载）；
`iVar1 = nextTierInfo.requiredCopies`（`+0x20`）；`iVar6 = GameplayVariablesData.GetMaxCopiesInDeck(rarity, cardType)`；
失败条件 = `iVar5 < 1 || iVar5 < iVar6 + iVar1`。
`GetOwnedCount<T>(T item)` 的共享体尾部是 `Enumerable.Sum`（`decomp_full/InventoryManager__GetOwnedCount_object_.c` 末句）
⇒ 原版这里取的是 **RemainingUses 之和**，不是条目数。

**新增**：`UpgradePanel.CheckUpgradeRequirements` 的 **postfix**（只读）→ `phase0/upgradereq.tsv`（上限 200 行），格式
`ts \t CHECK \t card=<id> owned=<GetOwnedCount(T)> ownedStr=<GetOwnedCount(string)> maxCopies=<n| -1> required=<n| -1>
currencyOK=<true/false/?> result=<interactable> neededText=<...> costText=<...> entries=match=<n>/<total> uses=[...]`。
`-1 / ?` = 那一步拿不到（`maxCopies` 走 `LiveOpsManager.GetHandler<GameModes>` → `GetActiveEvent<IRankedEvent>` → `GameplayVariables`）。
`currencyOK` 用本探针已挂好的 `HasEnough<Currency>(LoadableReference<Currency>,int)` 复算（`_inDiag` 闸：不让主日志重复记）。
**⛔ 不改任何结果**：不写 `interactable`、不调 `TryUpgrade`、不改库存。

**怎么读**：`owned` 若 ≈7 且 `maxCopies+required ≤ 7` 而 `result=false` ⇒ 门控不是 owned 卡住，要查 `interactable` 的**写入时机**（面板开在数据刷新前/别的代码又置 false）；
`owned=1` ⇒ 7 份没进 `GetOwnedCount(T)`（看 `entries=` 的 `match/uses` 是否为空，再查 `ItemId` 与 `GetID()` 是否对得上）。
