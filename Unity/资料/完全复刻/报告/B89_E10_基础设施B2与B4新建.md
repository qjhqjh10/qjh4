### 逐条要点（只写「与原版一致 / 刻意不同」）

1. **`AddPracticeMatch`** —— 纯 `List.Add`：**不查重**（同一 `PlayerId` 约两次就是两条）、不判 null、不排序。条目类型用 `SocialData.ChatMessage`（我们唯一带 `PlayerId` 的聊天条目，= 原版 `ChatMessageData`）。
2. **`AreDecksEqual`** —— 🔴 **不对称**照抄：只判「cards 里每张都能在 ids 里销掉一张」，**不判两边张数相等** ⇒ `({A},{A,A})` = **true**、`({A,A},{A})` = **false**。`List.Remove` 每次只摘第一个命中（照抄）。刻意不同：`ids == null` 原版抛 `ArgumentNullException`、`cards == null` 抛 NRE、元素为 null 抛 NRE —— 我们**一律出声 + 不抛**（`cards` 为 null 返 `false`，元素为 null 当 `id=null` 参与销账）。
3. **`ExtractDeckInfo`** —— 原版 `.c` 是唯一权威：**`cardback = deck+0x28` / `warcry = deck+0x30`**，账上「被 IL 折叠成 null」**不成立**。ctor 形参序 `(deckId, deckName, heroID, cardID[], lastEditTime, cardback, warcry)` 而**字段序不同**（第 1 个形参落到第 2 个字段 `uniqueId`）—— 照抄，别「理顺」。刻意不同 ①：`deck == null` / 没战将 ⇒ 原版抛 NRE，我们返 `null` + 出声。刻意不同 ②（`🔶 自己设计`，代码里已标）：**我们的 `PlayerDeck` 没有 `deckId` / `lastEditTime` / `warcry` 三列** ⇒ 分别填 `null` / `default(DateTime)` / `null`，一进程出声一次。
4. **`GetEnviromentString`** —— 常量 `"LIVE"`（`stringliteral.json` 地址 `0x42A2A30`）。原文 **0 调用点**。
5. **`GetMD5Hash`** —— 空串/null ⇒ **空串不是 null**；**大写十六进制、无 `-`**；编码**照抄 `Encoding.Default`**。实现细节：原版 `MD5CryptoServiceProvider`，我们 `MD5.Create()`（同算法工厂，输出逐字节相同）。原文 **0 调用点**。
6. **`GetXPFromMatch`** —— 赢的判据是 **`matchWon == 1.0f` 精确相等**。`Campaign` 赢 ⇒ **130**（原版 bug，注释写死「⛔ 别修」）。`Practice(90)` 走 default（告警 + 0）。
7. **`IsBattleLogCreated`** —— 位掩码**原样照抄**（`0x4000000100400` / `0x1004000040100001` / `0x40100001` / `p == 0xd3`），白名单 **12 档**：`10, 20, 50, 90, 110, 120, 150, 170, 180, 200, 210, 211`。列表类型做成泛型 `IReadOnlyCollection<T>`（我们的战报条目不是 `BattleLogMatch`）。原版**不看每条记录的 `matchType`**，只数条数（照做）。
8. **`RemovePracticeMatch`** —— **只删第一条命中**（`return` 在循环里）。刻意不同：表里若有 `null` 条目，原版 `ldfld` 抛 NRE，我们跳过 + 出声。
9. **`ResetFactionPoints`** —— 一个 `int` 清零，不夹不校验不广播。⚠️ `faction0Points` **不是**我们那三种阵营资源（信仰/灵魂石/任务点）。
10. **`SetLocalStartTime`** —— `localStartTime = CurrentMillis()`，而 `CurrentMillis()` **就是 Unix 毫秒**（证明见 §3 第 4 条）。

## §3 顺手发现（⛔ 我一个字都没改，交调度台分流）

1. 🔴 **施工单 §2.3 的 `GetXPFromMatch` 分支表有一处错**：它把 `PracticeOffline(50)` 列进「直接 `return 0`」那一组。
   `.c:22-27` 那三个 `if` 是 `0x50`(**= 80**) / `100` / `0x6e`(**= 110**)，`50 = 0x32` 三个都不等 ⇒ **`goto default`**（告警 + 0）。
   ILSpy `:9812-9820` 同形（只显式列 `EventAI`/`Tutorial`/`ClosedDeck`）。**返回值一样是 0，差别只在「会不会打告警」** ⇒ 我按 `.c` 走 default。
2. 🔴 **施工单 §4.2 的 `IsBattleLogCreated` 白名单有两处错**：
   ① 它写「⚠️ **`110 ClosedDeck` 不在白名单**（容易看错）」—— **反了**：`0x40100001` 的**位 20** 就是它（`0x100000`、`90+20=110`），**在**。
   ② 真正**不在**的是 `EventAI(80)` / `Tutorial(100)` / `Campaign(130)` / `TutorialReplay(140)` / `Replay(160)` / `Scene(190)`。
   ③ 账行 421 的备注写「50/58/100/…/150/160/190/200 等」——那是**猜的**；逐位解出的是上面那 12 档。
3. **`ExtractDeckInfo` 的病根比账上写的更宽**：账上只说「`cardback` / `warcry` 被 IL 折叠成 null」，
   实际 ILSpy `:10495-10501` 把 **`cardID` / `lastEditTime` / `cardback` / `warcry` 四个实参全折叠成 `default`** ⇒ 照 ILSpy 实现会把**卡表写成空数组**（比丢两格更严重）。
4. 🆕 **`PlayerDataManager.CurrentMillis()` 就是 Unix 毫秒**（可直接给别的账用，别再猜「开机以来毫秒」）：
   `__CurrentMillis.c` = `(long)(DateTime.UtcNow − GetUtcOriginDate()).TotalMilliseconds`，
   而 `SupportMethods__GetUtcOriginDate.c` = `new DateTime(0x7b2=1970, 1, 1, 0, 0, 0, Utc)` = **1970-01-01Z**。
   ⇒ 另一条账 `get_currentServerTime`（`CurrentMillis() − localStartTime + 服务器时刻`）可以直接用我们那个 `LocalStartTime`。
5. **三条原文是 0 调用点**（两棵树都只有定义处）：`GetMD5Hash` · `GetEnviromentString` · `ExtractDeckInfo`。
   按铁律 11 照样复刻（不因「没人用」判 D），只是**今天没有任何玩家可见行为**。
6. **`practiceMatchesList` 与 `SocialData.ChatMessages` 不是同一张表**：前者是「和我约过战的人」（`+0x1c0`），后者是聊天流（Global/Alliance 两频道）。两者原版**都**用 `ChatMessageData` 类型 ⇒ 别把两个容器合并。
7. **`faction0Points` 不是我们那三种阵营资源**（信仰 / 灵魂石 / 任务点）。它是**活动阵营积分**，原版另两个写点在 `RecordFactionPoints` / `RecordBossFactionPoints` 的服务器回包闭包里（P3）⇒ 本地只有「读」+「清零」。

## §4 没查清（不是「查不到」，是这一轮没查到底）

1. **`PlayerDeck` 要不要补 `DeckId` / `LastEditTime` / `WarcryId` 三列** —— 那是**卡组数据模型**的决定，
   不在本波白名单里（`RuleEngine/**` 禁碰）。今天的后果 = `ExtractDeckInfo` 那三格恒 `null`/`default`。
   `Warcry` 在 `SerializedPlayerDeckData` 里已经有一格（服务器那半，P3），但 `PlayerDeck` 本身没有。
2. **`Encoding.Default` 在「我们的运行时」与「原版 IL2CPP」上是不是同一个码页** —— 只影响**非 ASCII** 输入的 MD5。
   原版自己用的就是 `Encoding.Default` 这个有歧义的 API ⇒ 「照抄」在语义上是最忠实的做法；
   要真钉死得跑一次 Unity 比 `GetMD5Hash("中文")`（本波禁跑 Unity，没做）。ASCII 输入两边同值（断言钉的就是 ASCII）。
3. **原版 `practiceMatchesList` 在哪一步被初始化成空表** —— `AddPracticeMatch.c` 里对 `+0x1c0` 有 null 判 + 抛，
   说明它可能一度是 null（反序列化前）。我没追初始化点；我们的实现**直接给空表**（不会抛）。影响 = 无（原版那条 null 路是未初始化态）。
