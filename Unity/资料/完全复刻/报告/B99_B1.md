## §四 ⛔ 多目标 Step1：为什么**零改动**（反证）

施工单写：「`RuleCore.cs:15223` `ResolveTarget(...)` → `EffectResolver.ResolveTargets(ctx, owner, spec, source, chosen)`（复数）」。

**反证三条**：

1. **类型对不上**（编译层面就不成立）。`AbilityTargetsFor` 的形参是
   `static List<BattleEventTarget> AbilityTargetsFor(BattleContext ctx, int owner, UnitState source, **EffectSpec** spec, UnitState chosen)`
   （现读 `RuleCore.cs:15261`，方法是**封闭文法** `EffectSpec`，只有 `Verb/Target/Amount/Source` 四个字段、
   `Target` 是 5 个字符串之一：`self / ownwarlord / enemywarlord / enemyunit / friendlyunit`）。
   而 `EffectResolver.ResolveTargets` 的第三个形参是 **`EffectTargetSpec`**（`EffectText.cs:938`，20+ 个字段的富结构）。
   ⇒ 施工单里那个 `spec` 指的**不是**这个 `spec`；照抄**编不过**（`typecheck` 会 `CS1503`）。

2. **`ResolveTargets` 有副作用，「零可观测」不成立**。
   · `ResolveTargetsCore` 末尾**无条件**写 `ctx.LastTargets` / `ctx.LastTarget`（`EffectResolver.cs:1944-1946`）；
   · `ResolveTargets` 收口还会调 `NoteTriggerTargetSink`（`:1409-1426`）—— 它会**写 `ctx.TriggerTargetSink` 的三个字段并置 `Done=1`**；
   · 还多两段过滤 `FilterSingleUseMutationTargets` / `ApplySelectFromChooseResolution`（`op == null` 时**确实**是空转，但那是**这一次**的巧合，不是结构保证）。
   `AbilityTargetsFor` 的调用点在 **事件刚 Emit、能力的正文还没结算**那一刻（`AttachAbilityTargets` 的 doc 明写
   「必须紧跟在自己的 `ctx.Emit(…Ability…)` 之后」）⇒ 在那里改 `LastTargets` 会改掉**这一条能力自己**后续 op 的
   `it` / `them` 指代；改 `TriggerTargetSink` 会污染 T21 那一笔刚接上的目标填充。**本代理不能跑 `play check`** ⇒
   我无法证明它零可观测，按纪律**不做**。

3. **5 个封闭文法目标映射过去【不等价】**（举一个可判的）：
   `EnemyUnit` 在 `ResolveTarget` 里是「**有 `chosen` 就用它（哪怕它是督军）**，否则取敌方槽号最小的活部队」；
   而 `ResolveTargets(Side="enemy", Kind="unit", Count=1)` 的池**先排除督军**，最后那句
   `if (chosen != null && … spec.Count == 1 && list.Count > 0 && !list.Contains(chosen)) list.Clear(); list.Add(chosen);`
   要求 **`list.Count > 0`** ⇒ 敌方**没有部队**、玩家点的又是督军时，`ResolveTargets` 返回**空表**，`ResolveTarget` 返回那个督军。
   ⇒ 「改成复数」会在这条真实路径上**丢目标**。

**Step 0（施工单要求「不许跳过」）的结论 —— 也是本条的真正归属**：

`targetsAffected == any = 0`（`TargetsAffected.cs:3`）。原版 `AbilityLogic__GetTargets.c` 的 ta 分派里
`0 (any)` **没有专属分支** ⇒ 落到末尾的通用建池 `GetUnitsInPlayList(…, both = friendly||enemy)`，
而 any 档 = `inclPlayer=1 ∧ inclEnemy=1` ⇒ **敌我两侧并集**（与 `施工单 §一 第 12 行 AUD8·Any 并集` 同一处判据）。
`PlayAnim.c:170-176` 的循环条件是 `*(lVar5+0x18) == 2 || *(lVar5+0x1c) == 2 || *(lVar5+0x20) == 2`
（= `sp/ep/pt` 任一为「目标位」，**与 `targetsAffected` 无关**）⇒ 只要目标表有 N 条，就逐条 `AddCardAnim`、只有最后一条带 wait。

⇒ **「多目标」不是文法扩档问题，是「卡数据 `activeAbilityTargets[].criteria.targetsAffected` 没有进入事件层」的问题**。
`card_anim_order.json` 现读 **62 张**卡、其中 **38 张**有 `sp/ep/pt == 2` 的拍（施工单已核），
我们的 `AbilityTargetsFor` 却只能给 0/1 条 ⇒ 那 38 张里凡是 `ta=any` 的，原版会逐目标播、我们只播一条。
**建议另立一笔**（生产端：把 `activeAbilityTargets[].criteria` 从卡数据带进 `EffectSpec` / 事件层），
**不要**按施工单那一行硬改。判据已在本节写全，照着做即可，不必重新查。
