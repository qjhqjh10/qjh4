## ② 判据（本轮读到的硬结论）

### 2.1 十二个泛型基类

| 类 | 核心判据（出处见账） |
|---|---|
| `CollectionItem<T>` | cell 只做「装配 + 事件转发」：`Config(item,display,animate,isSelected)` → 虚 `Config` → `AnimateIn` → 按 `useSelectedHighlight` 刷选中；拖拽三类回调转给 `EventRelay`；`OnPointerEnter` 只在**没在拖**（`eventData.pointerDrag == null`）时才悬停高亮 |
| `CollectionDisplay<T>` | 列表负责「筛选 → 空提示 → ReloadData」与**拖拽重排**：按 `GetSiblingIndex()` 反推新下标 → 从 `filteredCollection` 摘/插 → `ReloadData()` → **恢复 `normalizedPosition`** |
| `ItemDrawer<T>` | `Draw(...)` 是 sealed：**每次先复位** `SetConvertedItem(null)`/`SetEphemeralDisplay(null)`，末尾再 `ToggleClaimedWarning(false)`+`TogglePremiumHighlight(false)`；三跳（premium/ephemeral/converted）我们已逐句复刻（A） |
| `Inventory<T>` | 每个 T 一份背包（`InventoryManager.GetInventory<T>()`）：id→`ItemInfo`、数量变更事件、按 Type 注册子集；`GetItemInstances(useQuantity)` 会把数量>1 展开 |
| `DynamicList<T>` | 按**元素运行时类型分桶**的多类型列表（`Get<T1>()` / `GetIndexType(i)` / `Inser`——原版拼写就是 `Inser`） |
| `LoadableReference<T>` | 只序列化 id；`GetReference()` = 有对象用对象、否则运行期按 id 取；`==`/`!=`/`Equals` 都按 id |
| `BiDirectionalDictionary<TKey,TValue>` | 两个平行 `List` + 下标同步；双向查询（`TryGetKey(value)`）；找不到抛 `KeyNotFoundException("The key 'X' was not found in the dictionary.")` |
| `LiveOpsEvent<TSave,TData>` | 每个活动一份 data/save：`ValidateEventData` 反序列化失败→新建；`SelectEvent()` 取 MainWindow 引用→`WindowsManager.OpenWindow`；`GetEndDate` 取 `FinalDate`→`DateTime.MaxValue`→与「现在+小时数」取 **min** |
| `PlayEvent<TSave,TData>` | 开局校验两条错误 key（`MenuDeck/Error/InvalidDeck`、`MenuDeck/Error/HasNotAssignedDefensiveCard`）；`MatchFinished` 按 `BattleWinner` 分派，**平局记 2.0**；`GetEventDeck` 优先「该阵营/模式上次用的卡组」 |
| `MissionEvent<TS,TD>` | 三态进度；`UpdateChallengeProgress` 有**教程门**（`!FirstTwoTutorialCompleted()` 时不记 `DailyLoginChallenge`）；`RerollChallenge` 重随 |
| `DraftEventBase<TS,TD>` | 选包/选战将/场次推进；`GetRandomPack` = `FullPackCollection.Where(warlord).OrderBy(random).Take(n)`；付费/免费两条入场 |
| `LiveOpsHandler<TEvent>` | 事件总调度：`events`+`blockedEvents`+`shared`；`handlerActions: Dictionary<string,MenuActions.Action>` **按活动 id 去重弹窗**；`ScheduleHandlerRefresh` = Release 旧 `ScheduledAction` → 按**服务器时间**算间隔 → `ActionScheduler.Schedule`；`HandleBeforeRefresh` 先打 `[key] Before Refresh` |

### 2.2 启动链

| 类 | 判据 |
|---|---|
| `SceneInitializer`（16/16 C） | `FindObjectsOfType<MonoBehaviour>` ∪ 已登记 → 按 `InitializationPriority` 分组 → 每组「同步 Initialize → 异步 StartCoroutine → **等该组 IInitializationComplete 全完成**」→ 全完调 `OnComplete`；出错 `LogError("Failed to initialize behaviour: …")` + 首次弹 `CustomErrors/FailedToInitializeServices`（**不中断**）；运行期新增：Initializing 中→`needToRestart`，已 Initialized→`Restartinitialization`（日志「Restarting initialization due to new behaviours added」） |
| `LoginManager`（32 D / 3 B） | 32 条 D 全部写清「原版断在哪」：Steamworks 初始化 → PlayFab 登录 → 远端存档/AssetBundle/IAP → FCM → 云脚本错误通道 → 重复连接。**离线替代覆盖**：不联网、本地存档、资产已导入；**未覆盖**：`CheckPlayerDeck` 的「登录后修卡组」时机（B）、语言集合/回落点未逐条对（B×2）、Loading 下载文案（词条可用） |

## ④ 没查清

1. **两条 E**（见 ①）：行为读不出，**没有猜**。
2. **ILSpy 对泛型方法体丢类型信息**：约一半 C/B 行的「原版行为」是**签名 + 字段表 + 可读片段 + 具体派生类调用点**推出来的，不是逐句读全。已在 `判据/泛型与启动链.md` §六 逐类标注，并给了补读办法（RVA→`decomp_full`，或 oracle 加探针）。
3. **「我们的落点」精确到文件/方法，多数没有行号**：本轮只做只读普查，没逐处打开我们的实现核行号（除少数已引用的，如 `ShopData.cs:266`、`ItemDrawer.cs:839/899/932/960`、`CollectionWindow.cs:1139`、`ShellRuntime.cs:610`、`WindowsManager.cs:671`）。
4. **`LiveOpsLocalCatalog` 是否已覆盖「阻塞名单 / 共享数据」语义**：只读了它的公开 API（`TrySelectActive*`/`Find`/`IsExpired`/词条），没有逐条对 `blockedEvents` 与 `shared`。⇒ 判 D/C 时按「没有 blocked 概念」写的，这一条**可能在下一轮被推翻**。
5. **存档格式耦合**：我们的本地存档（`DraftModeWindow` 的 `DraftRunSave`、`DailyData`、`ShopData` 的 `_owned`）是否走同一套序列化，本轮没查 —— 这决定 #2/#4 能不能一次替换到位。
6. **没有跑运行时**：没有进原版 oracle、也没跑我们的自检（红线）。所有「我们是 X」都是静态 grep 结论。

## ⑤ 顺手发现（不在本账范围，但会影响别人）

1. **账本 `n_nt` 口径不稳**：`DynamicList<T>` 账本 12 / dump 非平凡 9（账本把 `get_Item` 之类访问器算了进去）；**接口类**账本记 0，但 dump 里有声明方法。⇒ 重跑 `gen_replica_ledger.py` 前把「访问器 / 事件 add-remove / 接口声明」的取舍写进脚本，否则 774 这个数每轮都会飘。本账按「接口声明 = D」补了 21 行。
2. **平局 = 2.0**：`PlayEvent.MatchFinished` 与 `FastModeBaseEvent.OnMatchDraw` 都是「平局按 2 格推进」。这条最容易写错。
3. **两条现成错误文案 key** 可直接接：`MenuDeck/Error/InvalidDeck` · `MenuDeck/Error/HasNotAssignedDefensiveCard`；初始化失败窗 `CustomErrors/FailedToInitializeServices`（`{0}` = 组件名）。
4. **`LoginManager.CheckDataLoaded` 会等 Steam**（0.3s 重试 + `Waiting for Steam to load`）—— 这解释了「普通启动必须先开 Steam」；离线不需要。
5. **弹窗去重表**：`LiveOpsHandler.handlerActions` 按活动 id 去重，缺了会「每次刷新重弹」。
6. **`SceneInitializer` 的静态钩子在场景没就绪时是「出声」**（LogWarning/LogError），不是静默 —— 别实现成静默 return。
7. **第三方 FancyScrollView 70 条**：原版所有列表都用它（**含 cell 回收池**）。我们的 `MenuScroll` 覆盖滚动/裁切/拖拽，**不覆盖 cell 回收** ⇒ 列表条目变多时是性能差异（不是画面差异）。
8. **`Draggable<T>`/`DraggableController<T>` 我们已 A**（`Core/DraggableController.cs`，逐 RVA 复刻）—— 这是本轮 20 条 A 里证据最硬的一组，可直接当其它拖拽件的模板。
