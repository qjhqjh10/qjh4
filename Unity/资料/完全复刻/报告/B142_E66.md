## 一、改了什么（文件 · 行）

### 1）`B142-ACHIEVE-HIGHEST` — `CardPresentation/Shell/ProfileData.cs`

原版 `AchievementPersistence` 有 `currentValue` + `highestValue` **两格**，我们只有一格。

| 落点 | 改动 |
|---|---|
| `SaveDto`（`:996`） | 新增 `public int[] achHighest`（与 `achIds` 同下标、与 `achValues` 等长）。**与 `achValues` 同一行** ⇒ 零行数变化 |
| 内存表（`:1020`） | 新增 `static Dictionary<string,int> _achHighest`（与 `_achProgress` **同一行**） |
| `EnsureSave`（`:1036`） / `ReloadSaveForTest`（`:1161`） | 同拍初始化 `_achHighest` |
| `LoadFromDisk`（`:1076`） | 读 `d.achHighest[i]`；**旧档没有这个键（或数组短了）⇒ 用 `achValues[i]` 初始化**（⛔ 不清零） |
| `SaveNow`（`:1102-1104`） | payload 同时写 `achHighest`（取 `max(历史最高, current)`，保证两格自洽） |
| `SetAchievementValue`（`:1180`） / `SetAchievementValueAtLeast`（`:570`） / `AddAchievementValue`（`:1197`） | 每写一次 current 就 `RaiseAchievementHighest(id, 新值)`（**只涨不落**） |
| **类尾**（`:1657+`） | `RaiseAchievementHighest`（私有）· `AchievementHighestValue(id)`（= 原版 `GetHighestValue`）· `AchievementPersistenceView` struct + `AchievementPersistenceOf(id)`（= 原版 `GetSave` 的等价物，两格一起返回） |

**判据（decomp 现读）**
- `d:/2/tools/decomp_full/AchievementsManager__GetHighestValue.c` = `Math.Max(<0x3c>, <0x38>, 0)`；
  `Everguild.LiveOps.AchievementPersistence__set_CurrentValue.c` 证实 `CurrentValue` 在 **0x3c** ⇒ **0x38 = `highestValue`**。
- `AchievementsManager__GetSave.c` = 查不到就 `new AchievementPersistence` 再塞回字典 ⇒ 我们的等价物「查不到 ⇒ 两格都是 0」。

**写点口径**：原版 `GetHighestValue` 自己做 `Math.Max(current, highest, 0)` ⇒ 即便 `highestValue` 那天没人写过，
读出来也不会低于 current。我们照抄这条：写点把 highest 抬到 `max(highest, current)`、读口再取一次 `Math.Max(h, cur, 0)`。
> ⚠️ 与判据 §2·2 的措辞有一处**有意不同**：那儿写的是「`SetAchievementValueAtLeast` 写 highest，`AddAchievementValue` 只写 current」。
> 照那个写法，`Add(100)` 之后再来一次 `Set(0)`（自检 / 修档会调）就会把历史最高丢成 0 —— 与「highestValue = 历史最高」直接冲突。
> ⇒ 本笔让**所有写 current 的写点**都抬 highest（`SetAchievementValue` / `AddAchievementValue` / `SetAchievementValueAtLeast`），
> 可观测结果与 `GetHighestValue` 的 `Math.Max` 逐值一致，且「只涨不落」在任何调用序列下都成立。
