`Battle/CardDisplayWindow.cs:646`（`_fx = CardDisplayEffects.Build(_cards, …)`，那扇「卡片展示窗」）。

| | |

## 二、判据（三源，2026-11-01 全部自己现读）

### ① 原版 clip 的宿主是谁 —— **是那张展示卡本身**

`MainMenu Warpforge.unity` 里挂着 `Level Up Card` 这支 clip 的 `Animation` 组件（`&622`）在
**GameObject `&88` = `Game UI/Main Canvas/MainMenu/Safe area Only Horizontal/3 - PopUp Holder/Card Displayer Menu For Menu/Card Display/Cards/CardUI`**。

⇒ clip 里 `path: 2DCard/Front` / `2DCard/Level Up Effect` 是**相对这张卡**解析的（不是相对 `Upgrade Panel`）。
这一条把「动画到底播在哪张卡上」钉死了：**播在展示卡上**。

### ② 「只给一张挂」是原版事实，不是我们的取舍

同一批 `Cards/` 下 **5 张 `CardUI`**：
- `CardUI`（无后缀）的 `2DCard/Front` → 有 `ParentConstraint`（target = 同卡 `2DCard/Level Up Effect`）
- `CardUI (1)…(4)` 的 `2DCard/Front` → **只有 RectTransform**

### ③ 我们这边：本窗只有一张卡

`CardDetailPopup` 的注释与 `pulseTarget = SlotView(0)` 都写明「本窗 `Card` 永远建在槽 0」
⇒ 绑 `SlotView(0)` **天然就是「只有一张」**，不需要额外过滤。

## 三、父子层级核实结论（施工单 §4 点名要核的那条）

| | 原版 | 我们 |
|---|---|---|
| `Front` 的父链 | `CardUI ▸ 2DCard ▸ Front` | `CardView(GameObject) ▸ 2DCard ▸ Front`（`CardView.cs:4277-4283` 建的） |
| `Level Up Effect` 的父链 | `CardUI ▸ 2DCard ▸ Level Up Effect`（**与 `Front` 同级**） | `<卡片展示窗>/Card Display ▸ Cards ▸ Card Display Effects ▸ Level Up Effect`（`CardDisplayEffects.Build` 自建的 `"Card Display Effects"` 层根，`SetParent(cardParent)`） |
| 结论 | **同级** | **不同父**，而且在**另一扇窗**里（本窗连节点都没有） |

**这意味着什么**（两层，各说各的）：
1. **今天**：`inheritTarget == null` ⇒ 这一跳**完全不发生**（组件出声一次）。所以「比原版更明显」的风险**今天不存在**。
2. **将来真接上之后**：因为不同父，`target.TransformPoint(offset)` 的坐标基不再是同一个 `2DCard`
   ⇒ 若那时把本窗的 `Front` 接到展示窗的 `Level Up Effect` 上，卡面会被拽到**另一棵树的位置**（大概率是肉眼可见的错位）。
   ⇒ **接线时 `inheritChild` 与 `inheritTarget` 必须来自同一棵子树**（`BindLevelUpInheritTargets` 现在取的都是**本窗**的：
   `SlotView(0)` + `FindNewest`——`FindNewest` 只扫本窗 `transform` 的子件 ⇒ **不会跨窗**，这一点是安全的）。

> 施工单要的「按原版还是按现状」的处置：**按现状（只指本窗，取不到就 null + 出声）**。
> 理由：跨树硬接 = 造出原版没有的行为；而「让 `Level Up Effect` 出现在升级弹窗里」是**建件**的活，属于 Shell/展示窗那条线。
