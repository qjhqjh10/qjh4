## 一、4 类静默点 —— 逐条回源（这一步的结论与本批的「预期」不同，如实报）

> **关键认识（本次回源推翻了施工单的一个隐含前提）**：原版「4 类不刷」说的是**这 4 个方法自己不去调 `UpdateTraitIcons`**，
> **不是**「它们造成的效果在画面上不刷新」—— 这 4 类的调用点里，**除 2 处以外，同方法或同链里都跟了一次刷新**

### 2·1 新的口

```csharp
// UnitState（类尾）
public int TraitRev { get; private set; }          // 只有【非静默】trait 写才 +1
public void MarkTraitIconsDirty() { TraitRev++; }  // 「要刷但没走 AddKeyword/RemoveAll」那几处用它

// CardView（类尾）
public int BadgeRebuilds { get; }                  // 自检的幂等短路观测口
public void MarkTraitIconsDirty() { _traitIconsDirty = true; }
public int SetBadgesDirtyAware(List<Badge> badges, int traitRev)
{
    if (traitRev <= 0) return SetBadges(badges);                                              // 未接线 ⇒ 老行为
    if (_badgesBuilt && !_traitIconsDirty && traitRev == _traitRevSeen
        && _traitIdSeen == Data.id) return _badgesDrawn;                                       // 幂等短路
    int n = SetBadges(badges);
    _traitRevSeen = traitRev;
    return n;
}
```

⚠️ **`_traitIdSeen == Data.id` 这一格不是多余的**：视图会被**复用到另一张卡**（槽位换人 / 手牌换牌）。
没有它，两张卡的 `TraitRev` 恰好相等时（例：都是 0→1 的新卡）短路会**带着上一张卡的徽标** ——
那是静默错、而且正是本账要消灭的那一类。换卡（`id` 变）⇒ 必须重建。

### 2·2 为什么「未接线 ⇒ 老行为」是必须的（不是偷懒）

`Data.traitRev` 的填充在 `BattleDriver.ToCardData`（**不在本代理白名单**，且 `BattleDriver.cs` 由 `B120-W15` 在飞）。
若把 `traitRev == 0` 也当成「已接线」，那么**接线落地之前**每张卡的图标就变成「只在 rev 第一次变化时建一次」
→ **整局不再更新**（静默、且是玩家一眼看得见的回归）。⇒ `<= 0` 显式退回老路径，接线是「纯增益、不改行为」。
