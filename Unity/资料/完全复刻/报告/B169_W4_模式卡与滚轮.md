### 6.3 `A4=FAIL`（`viewport=-1x-1`）

- **根因**：`ProbeUtil.GetMember(scrollRect,"viewport") as RectTransform` —— 属性返回的代理是基类 `Transform`，

- **改法**：`ViewportOf()` 改走 **子节点名 `Viewport` → `GetComponent<RectTransform>()`**，

  ⛔ 不再碰 `horizontalNormalizedPosition` 属性。

### 8.1 贴边自动滚动一次都没触发 ⇒ 加 `EDGE-DBG` 心跳

- `EdgeScroll` 里原来的**每一条静默 `return`** 现在都会带一个 `reason=` 出来，并且**每约 2 秒**（`_edgeDbgT >= 2f`，
  ⛔ 不是每帧）打一行：
  `EDGE-DBG mouse=(x,y) local=(x,y) s2l=ok/fail inRect=真/假 left=… right=… edgeU=80 hidden=… reason=… ticks=… path=…`
- `reason` 取值与含义（照着这一步就能定位）：
  - `no-mouse` = `UnityEngine.Input.mousePosition` 反射没拿到（同时会有 `NO-INPUT`）
  - `s2l-fail` = 屏幕点 → viewport 本地坐标换算失败（`RectTransformUtility` 与兜底都失败）
  - `not-in-rect` = 鼠标不在 viewport 矩形内 —— 先看 `local` 与 `left/right` 的量级对不对
  - `not-at-edge` = **在视口内但不在边缘带**（看 `left/right` 的实际数值；也要看下面那条换算提醒）
  - `hidden<=1` = 内容装得下 ⇒ 本来就没得滚；`dragging` = 正在拖拽（让路）；`clamped` = 已到最左/最右
  - `no-geometry` / `no-bounds` = viewport/content 没找到或 corners 读失败
  - `scrolled-left/right` = **正在自动滚**（这时才会有 `EDGE-ON`）

- 🔴 **换算提醒（很可能是这次没触发的原因）**：`edgeU` 是 **viewport 本地单位**，不是屏幕像素。
  1440p 下 canvas 缩放通常 1.333 ⇒ **80 单位 ≈ 107 屏幕像素**；而 viewport 横跨屏幕 x≈223→2560 px

### 9.2 根因（已回源核实，不是猜）

`d:/2/tools/assetripper_out/ExportedProject/Assets/Data/Scenes/MainMenu Warpforge.unity`：
主 UI 的 Canvas（`!u!223 &1077`，GameObject 419）是 **`m_RenderMode: 1` = Screen Space - Camera**，
而且**序列化里 `m_WorldCamera` 是空的**（`worldCamera=0`）；CanvasScaler 在同一个 GameObject 419 上
（`m_UiScaleMode:1` · 参考 **1920×1080** · `ScreenMatchMode:1`(Expand) · `MatchWidthOrHeight:0`）。

⇒ 我们原来「Overlay ⇒ 传 null 相机」的假设**不成立**：null 相机时 `ScreenPointToLocalPointInRectangle`
把屏幕像素当世界坐标，而这条 canvas 层级的世界缩放约 0.065，于是 `local = (像素−视口位置)/0.065 ≈ 24220`，
`RectTransformUtility` 还照样返回 `true` —— 这就是「`s2l=ok` 但值是垃圾」的来路。
`hidden=0.0` 是同源：`GetWorldCorners` 这条在那套代理上调出来的 content/viewport 世界跨度退化（相减为 0）。

### 9.3 改法（三处，仍只动本代理的两个探针文件）

1. **`ScreenToLocal` 改成「候选相机逐个试 + 量级校验」**：
   候选 = `canvas.worldCamera` → `null`（Overlay）→ `Camera.main` → **`Camera.allCameras` 里剩下的**（最多 8 个），
   每个候选同时试 `RectTransformUtility` 与 `InverseTransformPoint` 两条路；
   合格条件 `|x| ≤ max(4000, rect.width×4)`、`|y| ≤ max(3000, rect.height×4)`（24220 / 7395 会被**否掉**）。
   用中的是哪个相机写进 `EDGE-DBG` 的 **`s2lSrc=`**（`canvas` / `null` / `main` / `camN` / `rejected` / `fail`）。
   另：`CanvasCamera()` 不再先看 `renderMode`（那个属性在基类代理上未必读得到），改成**直接取 `worldCamera`**，有就用、没有就 null。
2. **`GetHBounds` 改成本地矩形空间优先**（`hiddenSrc=local`）：
   `cMin = content.anchoredPosition.x + content.rect.xMin`、`vMin/vMax = viewport.rect.xMin/xMax`
   ⇒ `hidden = content.rect.width − viewport.rect.width`（主菜单 **2254−1753 = 501**，与 content 实际宽度自洽）。
   只有 `content.parent != viewport`（`anchoredPosition` 不在 viewport 空间）时才退回 world corners，
   并在 `EDGE-DBG` 里标 `hiddenSrc=world`；世界跨度退化（≤1）直接判失败。
3. **加一道保险 `bounds-inconsistent`**：动手前先算当前 `rawNorm = (vMin−cMin)/hidden`，
   只有落在 `[-0.25, 1.25]` 才允许移动 —— bounds 一旦取错，宁可这一拍不动，**也不把 content 甩到极端位置**。

## 十、第五轮：贴边滚动的**方向符号写反了**（根因就在 `ticks=59` 那个数上）

现场：`s2lSrc=main inRect=True hidden=501.0 hiddenSrc=local` ✅（坐标已经对了），
但 `reason=bounds-inconsistent(-0.26)` ⇒ 每一拍都被闸挡回，只闪了一下 `EDGE-ON/EDGE-OFF`。

### 10.1 根因：`SetNormalizedPosition` 的符号抄反（不是 padding）

Unity 真实源码是：

```text
contentBoundsMinPosition = viewBounds.min − value * hiddenLength
newLocalPosition        = m_Content.localPosition + contentBoundsMinPosition − m_ContentBounds.min
```

我写成了 `ap.x + cMin − contentBoundsMinPosition`（**减反成加**）⇒ 每一拍把 content 朝**反方向**推。

**为什么排除「漏了 padding」这个猜想（判据都在现场那两行里）**：

1. 若是固定偏移，`rawNorm` 会**从一开始就是 −0.26**，闸 `[-0.25,1.25]` 会从第 0 拍就拦住 ⇒ `ticks` 应恒 **0**；
   但现场是 **`ticks=59`**（先成功移了 59 拍，漂出去之后才被闸挡）。⇒ 是**累积漂移**，不是常量偏移。
2. 量级也对得上：59 拍 × 每拍约 `EDGE_SPEED*dt*hidden ≈ 2.2 单位` ≈ **130 单位 = 0.26 × 501**。
3. padding 本身给不出 130：`m_Padding L38 R16` 合计 **54**，而且它**已经在** `content.rect.width = 2254`
   （= 布局算出的 2200 + 38 + 16）里面了，不会再额外产生偏移。

### 10.2 改法

1. **符号改正**：`delta = (viewMin − want*hidden) − cMin`（与 Unity 逐字一致），代码注释已写清推导。
2. **闸放宽**到 `[-0.5, 1.5]`（Elastic 回弹会越界一点点，0.25 太紧）；判不过时照旧只记 `bounds-inconsistent(rawNorm)` 不动手。
3. **`EDGE-DBG` 现在**不论在不在边缘带都打 **`rawNorm=`**（内容在最左端时应该 ≈ **0.000**），一眼确认这套 bounds 算对了。
4. `holdTicks=` 保留，但**只作观测、不当问题追** —— 用户已确认之前那几次光标位置变化是**他自己在移动鼠标**，
   ⛔ 不是游戏吸光标，所以不为此做任何改动。
