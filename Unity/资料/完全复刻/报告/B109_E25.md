**「它们做什么」**：这 6 个都是 **VFX Graph 的 Output 阶段 shader**（粒子渲染器本体）——
顶点侧从 `graphValuesBuffer/attributeBuffer/indirectBuffer/deadList`（`ByteAddressBuffer`）读粒子数据、按 `unity_MatrixVP` 变换；
片元侧输出 `SV_Target0`，采样由 VFX 图在材质/图上给。它们**没有 `Properties{}` 块**（原版就没有 ⇒ 材质 `m_SavedProperties` 全空是原版行为，不是我们漏了）。

**怎么证明「照原版做的」，不是「照着猜的」**（本批独立复核，区别于 A14 的行级 diff）：

| 复核项 | 方法 | 结果 |
|---|---|---|
| **骨架**（`Shader` 名 / SubShader Tags / Pass 数 / Blend / ZClip / ZWrite / Cull / LIGHTMODE） | 去掉 HLSL 块与注释后**逐行 diff**：我们 vs `d:/2/tools/ruri_out_1020_allshaders/ExportedProject/Assets/{a291e5dd…,1e59d172…[_0/_1/_2],Hidden_VFX_Gargoyle Swarm….shader}` | **6/6 骨架 32 行 / 32 行，diff = 0** |
| **可编译性** | 复用 `B108_A14` 的静态编译代理 `_tmp_view/r4_108_work/verify_real.py`（Unity 自带 `D3DCompiler_47.dll`，A 档 strict + B 档 compat） | **24/24 阶段编译通过，`TOTAL FAILING STAGE-COMPILES: 0`** |
| **可移植性归一没多改** | 只许 ①–⑦ 七条（见文件头）：本批逐文件核 `#pragma use_dxc`（非注释行）= 0、本地 `#include` = 0 | 6/6 通过（断言 B7/B8） |

⚠️ **`.meta` 的 guid 与 EP 那份导出的 shader guid 不同，这是故意的**：
EP 给导出 shader 重新发了 guid（例：Dust 是 `30f347b4…`），而 6 个 `.mat` 的 `m_Shader` 里写的仍是**原版 shader guid**（Dust = `f2642f61…`）。
⇒ 把**工程 shader 的 `.meta` guid 设成 `.mat` 里写的那个**（`f2642f61…` 等 6 个），`.mat` 一个字节都不用改、引用自动接上（该 guid 在 `Assets/**` + `Packages/**` 现读 0 冲突）。
