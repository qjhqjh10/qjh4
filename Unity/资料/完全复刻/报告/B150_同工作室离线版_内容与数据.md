### 3.1 「只在服务端才有的数据」他们从哪来？（本项目 P3 最相关的一节）

**结论分两半：**

1. **卡表 / 卡图 / 语音 / 本地化 —— 不是服务端 API，是远端资源包。**
   - `probe.js:865-880`：从 `assets.json` 里取 `id === 'scriptable_objects'` 的包当「定义包」，`LoadFromFile` 之后手工把 `AssetBundleData`（含 `version`）塞进 `AssetBundleManager`，紧接着调 `PlayerDataManager.UpdateCardCollection`。
   - `probe.py:134-137` 的注释写死了这句：「Card rules live in the definition bundle as well as the runtime scripts」，并且**把这个包的 sha256 计入联机指纹**。
   - 本地化同理：`languages` 包（21.5 MB）走同一条 `GetLoadedBundle` 拦截路径（`probe.js:194-215`：把客户端请求的 `PCWin/<name>` 去掉前缀，按 name 找，找不到再按 `id`（去掉尾部数字）找）。
   - ⇒ **他们不是「还原了服务端」，而是「把原本由服务端下发的资源包原封不动归档到本地」**。

2. **真正的服务端状态（账号/库存/新闻/特惠/任务/匹配/排行）—— 他们没有还原，而是摘掉。**
   - 登录：`probe.js:152` 把 `LoginManager.Start` 换成空函数、`get_IsLoggedIn` 恒真；`NetworkCustomManager.StartConnection` 换成空函数（`:268`）。
   - 玩家数据：`probe.js:842-900` 直接在内存里写字段（昵称 `Offline Player`、Elo 30、tips 阶段 3、开 4 个功能开关、全卡 owned）。
   - 刷新口：`UpdateTitleNews` / `RefreshUserData` / 战令任务更新置空（`:156-162`）。
   - 网络：`probe.js:2662-2668` 对 `ws2_32` 的 `connect/WSAConnect/sendto/WSASendTo` **一律返回 -1** —— 原版客户端一个包都发不出去。
   - ⇒ **活动、商店轮换、远征章节**：不存在「取回来」这回事。原版活动与商店**没做**；「远征章节」是他们在 `engine.js` 里自己写的 11 个章节（`:31-45`），商店/掉落/事件全是自定参数（`:11-12` `LOOT_RULES`）。

## 4. 存档与进度

**总原则：把原版客户端所有落盘重定向到 `OfflineLab/profile/`，再在外部用 JSON 重建进度。**

- 重定向手段（三处叠加）：
  - `probe.js:76-78` 替换 `Application.get_persistentDataPath` / `get_temporaryCachePath` 返回 `profile`；
  - `probe.js:2670-2683` 拦 `SHGetFolderPathW` / `SHGetKnownFolderPath`，把 `LocalAppDataLow`（FOLDERID GUID 首 4 字节 `165,39,181,161`）写到 `profile`；
  - 公司/产品名改成 `OfflineLB`/`LegiLab`（`app.info`），让 PlayerPrefs 的注册表命名空间也与真游戏分离。
- **`decks.json`（卡组 + 个人资料）**：`version: 1`。卡组字段 = `id / hero / cards / premiumCards / heroAlt / carapace / rightArm / leftArm / badge / avatar / warcry / cardback / name / prebuilt / tag / premiumHero / premiumPilot`；另有 `current` 与 `profile{displayName, badge, avatar, warcry, cardback}`（`probe.js:490-523`）。
  写入：`probe.py:108-118` 收到 `save_decks` 消息后调 `offline_save.save_state` —— **严格结构校验 → 原子替换（tmp + `os.replace` + `fsync`）→ 旧档转 `.bak` → 坏档另存 `.corrupt-<纳秒>`**；读取时主档坏就回退 `.bak`，并把坏档留档（`offline_save.py` 全文，约 110 行）。
- **`replays.json`（回放）**：`version: 1`，`nextId` + 最多 6 条；每条带 `rules` 指纹 `'legions-3.7.3-offline-card-rules-v16'`，读取时指纹不符即判「与当前游戏规则不兼容」（`probe.js:2266, 2451, 2596`）。另有 `replay-settings.json`（录制开关，version 1）。
- **`online-settings.json` / `online-accounts.json`**：各 `version: 1`；账号按服务器地址存 43 字 token + 账号摘要，最多 32 台服务器（`online_accounts_runtime.js:19-38`）。
- **`great-rebellion.json`（远征进度）**：`engine.js:10` `VERSION = 3`；读档时 `1→3`、`2→3` 迁移（`:1022-1060`），保存前 `snapshot()` 走 `validateState` 全字段校验（`:1017-1021`）。战将跨场持续状态另有软上限：**120,000 字节 / 每类 240 条**，超了先丢「待领任务奖励」再报错（`native_state.js:166-167, 186`）。
- **旧项目导入**：`great_rebellion/migration.py` —— 只读源文件、校验 `version in (1,2,3)` 与 `hero/deck` 结构、限 2 MB、临时文件 + `os.rename` 原子落位；目标已存在就跳过。
- **性质判定**：这是**自造存档，不是原版存档格式**。字段只是原版内存对象（`CardDeck`、`PlayerDataManager`）的投影；原版的卡组/收藏本来在 PlayFab 服务端，本地从来没有过。所以**不存在「存档兼容原版」这回事**，只有「本 mod 自己的版本兼容」（`version` 字段 + 迁移函数 + 指纹）。

## 5. 他们没做 / 不必做的部分（= 跑原版客户端带来的红利）

**不必做（原版二进制直接提供，且天然 100% 一致）：**

- 卡组编辑器、收藏页、战将详情 —— 原版界面（只替换了它们背后的存档读写）。

**必须自己补（服务端缺失导致的）：**

- 登录/账号/玩家数据构造（`probe.js:152, 842-900`）；
- 资源包重定向 + 按需加载 + 缺省降级（`probe.js:165-215, 240-266`）；
- 存档序列化/校验/原子写/版本迁移（`offline_save.py`、`probe.js:490-730`）；
- 联机全栈：LAN 发现与对战、自建 TLS 中继、合作中继（`lan_transport.py`、`online_transport.py`、`coop/`）；
- 一整个新模式「大叛乱」（规则引擎 `engine.js` 99 KB、UI 克隆 `native_*.js` 约 500 KB、自生成纹理）；
- 内容可见性过滤：本地没有素材的外观/隐藏卡就不显示（`probe.js:899-971, 1170`）。

**明确放弃的原版功能（全部是服务端驱动的）：** 战役、商店/内购、日常/战令、活动/Draft/排位、教程、原版社交与好友、遥测/分析、Steam。
