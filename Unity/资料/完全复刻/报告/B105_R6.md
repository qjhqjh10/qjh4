## 2. P0：唯一真正需要改的一行

**`Unity/MyGame/Assets/CardPresentation/Core/CardText.cs:133`** —— `KeywordDisplay`

```csharp
if (Loc.HasEntry(t)) return Term(t);     // ← 应改 Loc.HasAnyTerm(t)
Loc.T(t);
return null;
```

- **今天为什么错**：`Card_Trait/*` 有 **31 条不在手写 Table**（27 条 bulk+13、4 条只在 13lang）⇒ 这里返 `null` ⇒ 调用方 `CardDisplayWindow.TraitRowText:2460` / `RemoveTraitRowText:2473` 回落成 `e.Trait` ⇒ **卡面/效果行印裸 canonical 名**。
- **可达性证据**：卡池 `cards_engine.json` 里 `concussive` 出现在 **6 张卡**（`ASH75 / GSC32 / GSC28 / GOF68 / GOF63 / GOF26`）。
- **为什么换宽就够**：`Term()` 自己三档齐（`Lang13Current` → `Table` → `Loc.T` 兜 bulk/13）。
- **风险已核**：① 无断言钉「`KeywordDisplay` 必须返 null」；② 这 31 条的官方值是**纯文本**（`concussive` = `震荡的`/`Concussive`，`sneak`/`jam`/`rage` 同），**不带 `[[ ]]` / sprite 记号**；③ 三档皆无的键仍返 null（与今天一致）。
- **改法**：同行谓词替换，**不插行**（不会造成账漂移）。

1. **`Card_Trait/*` 31 条不在手写 Table**（Table 65 / bulk 27 / 13lang 83；4 条只在 13lang：`bloodThirst` / `cantAttack` / `huntMark` / `spiritStone`）。

3. **`_acMissingKeys` 的「应当空表」依赖「没人引用那 7 条 Account 键」**（见 §3）。
4. **`Cosmetic_Description/*` 三档 0 条不构成缺陷**：`ProfileData.GetLocalizedDescription` 零消费者，且原版 `GetTranslation` 兜底就是回键名 ⇒ 与原版一致（`ProfileData.cs:1614-1617` 已写明）。

## 7. 复现

- 扫描器逻辑 = 五态字符机（`//` · `/* */` · `"…"` · `@"…"` · `'…'`），**二进制读**（裸 CR 会偏行）。
- 数据面：`official_loc_13lang.json` 取 `keys`（列式 10,862）· `official_names.json` 取 `entries[].k`（3,263）· `Loc.cs` 正则 `\{\s*"…"\s*,\s*new Entry\(`（现读 755）。
- 对账：138 条「宽」行按文件分组 ↔ 现读 `HasAnyTerm` 处数；每条「宽」行查 ±12 行内是否仍有 `HasEntry`（只剩 `SettingsWindow:2379/2410`）。
