## 一、§五-① 那一跳**定掉了**：x **也乘 ratio**，`Max(...)` 作用在**缩放后的 `anchoredPosition.x`** 上

三条判据（`decomp_full/CampaignTrack__Initialize.c` 建节点那一段的完整链，`:200-215`）：

1. **x 乘 ratio**（与 `GetNodePosition.c:12-14` 同一个式子）：
   ```
   local_res10 = CONCAT44((node[+0x3c] − offset.y) × DAT_1834b2bc8(−1.0f) × ratio,   // 高 32 = y
   ```

   ⇒ 低半 = x ⇒ **x 被 `ratio` 缩放、没有取反**。上一批「x 方向少一跳」的**前提本来就不成立**。
2. **`SetTrackSize` 的 `Max` 读的是 `anchoredPosition.x`**（`__c___SetTrackSize_b__14_0.c:6` 现读：
   `UnityEngine_RectTransform__get_anchoredPosition(param_2 + 0x40)`）—— 即**已经乘过 ratio 的**值，
   不是 SO 里的原始 X ⇒ 「÷ ratio 前后对不上」那个矛盾**消失**：
   `maxA = (6712 + 338) × 0.7279 ≈ 5132`（设计 px），内容宽 = `5132 + 431.25 ≈ 5563`。
3. **`ratio` 本身的分母也修了**（见 §二·③）：`2 × max(|maxY − 根节点Y|, |minY − 根节点Y|) = 2 × 384 = 768`
