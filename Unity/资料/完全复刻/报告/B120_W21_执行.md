## 三、上游闸 —— **判据已定，闸已存在，不需要新增行为**

`B120-W18` §1.5 把「松手那一支到底有没有位置闸」记为 ❓（`FUN_180617800` 读不出）。本波**换了读法**：
不去猜那个函数，直接看 **`case 3` 的两条支**（`il2csharp/BattleManager.cs:25866-25999`）：

```
case 3 (playingCard):
  if (sub_180617800(...) == null)            // 鼠标已松开
  { ... GetClosestAvailableSlot(...) → 出牌 ... }        // :25877-25949
  else if (mouseCanvasPos.y > vector32.y)    // 还按着、指针在**棋盘线以上**
  { ... ReassembleMinionsWhilePlayingUnit(...) ... }      // :25951-25990（让位预览）
  else                                       // 还按着、指针在**线以下**
  { cardTracked.OutFromPlayingAreaAnim(); RemoveSwarm(0);  // :25991-25998
    UIstate = movingHandCard; ReassembleMinions(0); }
```

**结论（三条，逐句可核）**：

1. **松手那一支（进 `case 3` 之后）没有第二道位置闸** —— 它直接 `GetClosestAvailableSlot(指针)` 出牌。
   但在 `case 2`（还按着）里，**要进 `case 3` 必须先满足**两条：`line.y < mouse.y`（手牌限位线）
   **且** `pointerCursorStart.y + minMovementToPlayCard(0.3) < mouse.y`（`:249-253` 那一段）。
   ⇒ 原版的「位置闸」在**上游的晋级条件**里，不在松手那一刻。
2. **我们的 `PlayCommitGate`（`CardInteraction.cs:2349-2353`）逐字就是那两条**：
   ① `nowWorld.y − pressWorld.y ≥ PlayLiftWorld`（0.3 原版世界单位 = 4.45 px）；
   ② `ToNormalized(now).y ≥ BoardLayout.HandLimitY`（= 原版 `HandLimitArea` 的 `300/1080`）。
   ⇒ **闸已经在，且语义等价** ⇒ **本件没有新增任何闸**（⛔ 不造行为）。
3. 容差删掉之后，「没落在棋盘上」这件事**只由上面第②条决定** —— 正是 `B120-W18` §1.4-2 要的形状。

**唯一附带改动（同一份判据的下游）**：`UpdateDrag` 的落点底片/让位预览原来只靠 `ok`（= 落点解析成功）点亮。
容差删掉后 `ok` 几乎恒真 ⇒ **拖在手牌带里也会亮一个格**。按原版同一份判据补了一道闸
（`CardInteraction.cs:1096`）：`… && LayoutSpace.ToNormalized(world).y >= BoardLayout.HandLimitY`
（判据 = `ReassembleMinionsWhilePlayingUnit` 的唯一调用点在 `case 3` 的「线以上」支，`il2csharp:25963`）。

**如实记的残余**：原版 `else` 支的 `OutFromPlayingAreaAnim()`（把卡「推出播放区」的动画）我们**没有对应实现** ——
我们的取消路径就是 `OnReturned` → 手牌重排（`CardScript__MoveBackToHand` 那条，无 DOMove）。
本件**没有造**这个动画（不在 Q04c 范围、也没有判据说是哪一条 tween），已列进「没做的」。
