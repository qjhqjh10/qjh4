## 二、跳过 / 存疑（为什么）

1. **`gen_card_anim_order` 完全跳过**：静态名单把它列进来了，但现读 `main()` 已是
   「不带参 ⇒ `print(USAGE); return 2`」+ 五个显式动作（`--check/--write/--probe-base/--check-slim/--write-slim`）。
   waudit 裸跑 `WAUDIT_RC 2`、`WAUDIT_WRITE none` ⇒ **无需改动**。
2. **三个「改前裸跑本来就不写」的**（`gen_anim_clips` · `gen_draft_packs` · `gen_grabpass_effects`）：
   按简报本可跳过，但它们裸跑是 **rc=0**（或无 rc 的 `main()`），与纪律「非零退出」不符
   （E27 §顺手发现 6 已点名同一类）。本次只做**最小改动**：补「用法 + rc 2」，**不碰任何写盘路径**。
   ⚠️ 唯一的行为变化：`gen_anim_clips --only=<名>` **单给时现在 rc=2**（要先给 `--write/--check/--dry`）。
3. **`gen_animfx_modules` 没有 `--check`**：原状只有 `--dry`，本次**没加**（简报说「按各脚本原状补，不强求统一」）。
   它的产物不可跨分钟复现（时间戳），要做 `--check` 得先定义「忽略 `generated` 再比」的口径 —— 见 §四·2。

## 四、顺手发现（只报不改，全在白名单外）

1. 🟠 **`gen_anim_clips` 的 `Booster Window - Background Shake On Open.anim` 盘上已过期**
   —— `--write` 会把 `inWeight/outWeight` 从 `0.33333334` 写成 `0.3333333`（3,483 B → 3,446 B）。
   **HEAD 版产出的也是 `0.3333333`** ⇒ 是我们**盘上那份**旧，不是本次引入。
   按纪律**已还原、未留盘**；它在 `MyGame/Assets/**`（黑名单）⇒ 未修。建议排一条「重跑 + 核销」。
2. 🟠 **`gen_animfx_modules` / `gen_trait_effect_bindings` 的产物带生成时间戳**
   （`generated` 分钟级 / `generatedAt` 秒级）⇒ **跨时间点重跑必然字节不同**，`--write` 的「逐字节相同」
   **只在同一分钟/秒内成立**（本次 A/B 两次跑在同一窗口，逐行 0 diff；对盘上那份的差异**只有时间戳那一行**）。
   建议以后统一成 `--generated-at <固定值>`（`gen_trait_effect_bindings` 已经有这个参数了）。
3. 🟠 **`gen_grabpass_effects` 的产物 `资料/完全复刻/判据/B107_B14_失真效果挪层清单.md` 已过期且差得不小**：
   现读 `GrabScreen501.DefaultLayer` = **6**，产物里写的是 **9** ⇒ 「全部渲染器已在目标层」由 **0** 变 **195**，
   391 行里 **236 行**不同（整张表的「目标层」列全变）。`--check` 现在**当场 rc=1**（这正是它该有的行为）。
   建议排一条「重跑 `--write` + 核销」（产物在 `资料/完全复刻/判据/`，不在我的白名单）。
4. **代码注释里有 20+ 处写着「跑 `python 工具/gen_env_blendables.py` 重生成」**
   （`CardPresentation/Battle/ScenarioBlendables.cs` · `EnvironmentApplier.cs` 等）——
   **现在裸跑 rc=2 且不写**（这是我们要的），但这些提示语会误导下一个人「跑了却没变」。
   建议统一改成 `--write`（文件在 `CardPresentation/**`，黑名单，未动）。
5. **`gen_cardbacks` 在 `problems=True` 时返回 rc 0**（打印「🔴 有对不上的 —— 先把上面几行查清再决定要不要写」）。
   即「有输入对不上」被当成成功退出。**改前就这样**，本次未动（不属守卫范畴，但是个 rc 口径缺陷）。
6. **`gen_animator_controllers --write` 不是「从零可复现」**：它会把现有 `OUT` 里的 `clipsByGuid`
   原样带回去（`prev_clips`）。若那份文件被删/损坏，`--write` 会**静默写出 `clipsByGuid: []`**。
   本次 A/B 两侧都还原成同一份输入，所以比对不受影响；但**别在产物缺失时直接 `--write` 当重建**。
