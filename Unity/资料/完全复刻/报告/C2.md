## 三、🔴 改 `QualitySettings` 的**安全路径**（怎么写、为什么这么写）

**问题**：`QualitySettings.vSyncCount` 是**工程资产级**的开关 —— 在编辑器里写它会把 `ProjectSettings/QualitySettings.asset` 标脏并落盘（同 `Shell/SettingsWindow.cs:4721` 那句「`QualitySettings.vSyncCount` 也会写脏工程设置」，以及它存在的原因 = `VSyncSetterOverride` 这个注入口）。一次编辑器 Play / 一次批处理就写脏一次，而且**看不出来**。

**做法（`LocalPlayerDataStore.ApplyDisplaySettings`）**：

```csharp
if (SettingsWindow.VSyncSetterOverride != null) SettingsWindow.VSyncSetterOverride(vsync ? 1 : 0);
#if UNITY_EDITOR
else
    Debug.Log("[LocalPlayerData] 编辑器里**不写** `QualitySettings.vSyncCount`（原版此刻会写 N）—— …";
#else
else QualitySettings.vSyncCount = vsync ? 1 : 0;
#endif
Application.targetFrameRate = TargetFramerateFor(fpsLimit);
```

四条要点：

1. **真 Player 里照原版写**（`#else` 支）—— `-wfscene Shell` 起的 player 不受任何影响，玩家看到的就是原版行为。
2. **编辑器（含 `-batchmode` 自检）里不写工程资产**，改成**出声说明**（⛔ 不是静默跳过）：日志里写明「原版此刻会写几」以及为什么这里不写。
3. **复用全仓唯一那条拦截口** `SettingsWindow.VSyncSetterOverride`（`public static Action<int>`，`Shell/SettingsWindow.cs:4722`）—— 自检要观测这一跳就注入它，**不新开第二个注入口**（否则就是「两处写同一条规则」）。
4. **`Application.targetFrameRate` 不设闸**：它是**纯内存态**，不碰任何工程资产 ⇒ 编辑器里也照写（与 `SavePlayerData` 末段那句同一条口径）。

> 选 `#if UNITY_EDITOR` 而不是 `Application.isEditor` 的理由：前者在 player 构建里**编不进去**（连误用的可能都没有）；后者会把这段判断留在产物里。
