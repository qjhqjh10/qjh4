## ⑥ 顺手发现

1. 🔴 **`PlayerDataManager` 就是「活动线暂停」的根**：它一份 217 条，占本域 C 的 **84%**。恢复活动线时，第一步不是建事件窗，而是**决定要不要重建这一层**（G §三 的 #2/#3 都挂在它下面）。
2. 🔴 **我们有 7 份本地存档**（`WarpforgeDaily`/`Draft`/`Profile`/`CardLevels`/`BattleLog`/`Replays`/`Shop`）—— 每一份都自带 `StoreDto` + `version` + `StoreOn` 门。**这是「同一件事写了 7 遍」的典型**：下次再有新东西要存，⛔ 别再加第 8 份，先看能不能并进一个 `ProfileStore`（不需要等 `PlayerDataManager`，一个薄封装就够）。
3. **`GameBootController` 是个典型的「启动器被裁掉」**：它靠 `AssetReference playerDataManagerReference` 在启动时加载 `PlayerDataManager` —— 而后者我们也没有 ⇒ **这条链在原版里是「启动 → 加载中央存档」**，与我们 `Shell/ShellRuntime.Build` 做的事同构（只是我们没做成组件）。这条关系值得写进「启动链」那本账。
4. **`ReferenceCache`（ScriptableObject）是「id → SO」的缓存表** —— 我们的等价物是 `Core/CardArt` 里那几张静态字典；**它 0 引用 + 0 资产实例**，说明原版后期不用了。⛔ 别照着建。
