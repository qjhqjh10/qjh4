### 2. 公式（原文 vs 我们）

设框 `box`（宽 `bw`、高 `bh`），根设计尺寸 `rootW × rootH`（基础族 `712.8×1080`，Icon 方族 `1080×1080`）。

**原版（`m_AspectMode 2` / HeightControlsWidth）**

```
根高  = bh                       （锚 0..1 拉伸 ⇒ 高跟着父框）
根宽  = bh * (rootW / rootH)     （ARF：宽 = 高 × 比例，**不夹父宽** ⇒ 可能 > bw，那就是溢出）
K     = bh / rootH               （Content 的 UIScaleToFit = min(根宽/Content宽, 根高/Content高)；
                                  基础族 0.66/712 > 1/1080 ⇒ **高那一支恒更小** ⇒ K = bh/1080）
根左  = box.CX − 根宽/2          （左右居中 ⇒ 溢出时**两侧各溢一半**）
```

**原版（`m_AspectMode 3` = FitInParent，或**根上没有 ARF**、`Content` 走 `UIScaleToFit`）**

```
K    = min(bh / rootH, bw / rootW)     ← 等比内接（与我们现行口径**逐位相同**）
```

**我们（`FrameOf`，本轮之前 / 本轮默认）**

```
K = min(bh / rootH, bw / rootW)        ← 永远是内接
```

### 3. 差在哪、差多少

两者相等 ⟺ `bw / bh ≥ rootW / rootH`（基础族 0.66 · Icon 方族 1.0）。**只有「框比根更窄」才分叉**，此时：

| 量 | 原版 | 我们（现行） | 差 |
|---|---|---|---|
| `K` | `bh/rootH` | `bw/rootW` | 我们的**偏小**，比例 = `(bw/bh) / (rootW/rootH)` |
| `Content` 宽 | `712 × bh/1080`（可 ≥ `bw`） | `712 × bw/712.8`（恒 ≤ `bw`） | 我们的缩进去了 |
| 水平位置 | 根居中、**溢出两侧** | 整块内接居中 | 边缘逐点不同 |

**举个实数**（基础族，框 `600×1080`）：

- 原版：`K = 1`、根 `712.8×1080` ⇒ 左沿 `300 − 356.4 = −56.4`、右沿 `656.4`（**两侧各溢出 56.4**）。
- 我们：`K = 600/712.8 = 0.841750` ⇒ 整块缩进框内，边缘差 `56.4 + 0.4×(1−0.8418) ≈ 56.5` px。
- 再往下的每一层（`Image` / `Army` / `Label`）**同比例偏移**，一个字都不在原来的地方。

## 六、顺手发现（⛔ 都没改，交调度台分流）

1. 🔴 **`Title Drawer`（**基础档**）的 `Content/Background` 也不是共享那张**：真包现读 = **`40k_Rewards_icon_title card`**（329×499），
   而 `ItemDrawerLayout.DrBackgroundSprite` 是 `40k_Rewards_icon_base_card`（`ItemDrawerLayout.cs:90` 的常量 + `NodeBackground` 的 doc 还写着「sprite 恒 …」）。
   ⇒ `ItemDrawerTitle.Title()` 现在**画错底板**（它转调 `DrawerBackground`）。落点 = `Shell/ItemDrawerTitle.cs:57`（**不在我白名单**）。
   资源已在 `Resources/Art/ui_menu/40k_Rewards_icon_title_card.png` ⇒ 修起来只是换一个图名常量。
   ⚠️ 同族风险：`DrBackgroundSprite` 那句「逐份相同」需要**逐份复核**（本轮只证伪了 Title 两档）。
2. 🔴 **`Title Drawer` 的 `Army` 字号真包是 35.1，我们画 75**：`DrawerArmyName` 写死 `75f * K`（`ItemDrawerLayout.cs:204`），
   而 `Title Drawer` 那颗 TMP 的 `m_fontSize = 35.099998`（auto `[12,75]`）。对照：`Avatar Drawer` 的 `Army` 确实是 **75**（同法现读）
   ⇒ **75 是通则、Title 是例外**。落点 = `ItemDrawerTitle.cs`（不在我白名单）。横条档不受影响（它 `Army` 关着、我们也不建）。
3. 🔴 **`Alliance Badge Drawer Icon` 的根是「固定尺寸」**：无 ARF、锚 `(0.5,0.5)`、`sizeDelta 165.9539×155.7357`
   ⇒ 原版**根本不跟父框走**（永远是 166×156 设计 px、居中）。我们现在走 `FrameOf(box, 1080, 1080)`（**跟框缩放**）
   ⇒ 框大于 166×156 时我们画得比原版大、小于时比原版小。这一族的正确模型是「不缩放、按固定尺寸居中」。
   与 `B-260` 是**同一片空白的两端**（一个「宽了怎么办」、一个「压根不跟框」），建议合成一条独立账。
4. **`Icon Expansion Pass Points Drawer Variant` / `Icon Campaign Points Drawer Variant` 的 `m_AspectMode` 是 `3`（FitInParent）**
   —— 与其余 Icon 变体的 `2` 不同。既有文档多处把「Icon 变体」当一族写（例：`ItemDrawerLayout.cs` 文件头那三行），
   本波已在文件头 ① 里补了这一句**例外**（同 `B114_W20` §六·2 提的 `Icon Expansion Pass Premium` 例外）。
5. **`Title Drawer` 在真包里根 GO 是 `INACT`**（`menu_dump` 打 `INACT`，`Content` 打 `ANC✗`）——
   说明这份 prefab 的出厂态是关的、由实例/调用方开。不影响方法论，但**照 `m_IsActive` 判「画不画某层」时要先分清是「prefab 出厂关」还是「这一层自己关」**
   （我判 `Army`/`Label` 用的是**它们自己**的 `m_IsActive`，不是从根继承来的 `ANC✗`）。
