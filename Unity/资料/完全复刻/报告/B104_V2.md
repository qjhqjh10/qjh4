## 二、trace 记的是什么（口径）

列（= `AnimTrace.Columns`，TSV 第一行是表头）：

```
seq  cardId  evtKind  piece  startOffset  holdSeconds  seat  cueKind  firstOfEvent
```

- `cardId` = `BattleEvent.CardId`（⚠️ **英文卡名**，引擎就是这么装的）；
- `evtKind` = `EvtKind` 枚举名；非事件 cue 为空；
- `piece` = 这一拍播的那件：按表展开的拍 = `CardAnimBeat.vfx`，`cueVfx` = 那件名，**事件拍 = 空串**
  （事件拍的那几件由 `VfxMap` 在**播放那一刻**解，排期时没有名字 ⇒ ⛔ 不猜）；
- `startOffset` = `_clock` 口径的**绝对**起播时刻（秒）。对账器按「本组首拍」归一成相对偏移；
- `holdSeconds` = **阻塞时长**，按 cue 三族分取：
  - **事件拍** = `EventTiming.DurationOf(evt)`（= `PlaySignals` 推进 `t` 用的**同一个值**）；
  - **按表展开的拍** = `CardAnimBeat.Duration`（= `vfxDelayTime + timeAtStartPos + timeMoving + timeAtEndPos`）；
  - **`cueVfx` / `cueAction`** = **0**（排期函数把 `duration` 只用来推队尾、**没存进信号** ⇒ 排队这一刻拿不到；
    如实记 0，⛔ 不拿「下一条的 `at` 减这一条」反算 —— 那是**间隔**不是阻塞）；
- `seat` = 座位 0/1（非事件 cue = −1）；
- `cueKind` = `event` / `beat` / `cueVfx` / `cueAction`；
- `firstOfEvent` = 1 = 本组首拍（`beat` 按 `beatTail == false` 判；其余恒 1）—— 对账器靠它切组。

**落盘**：`Application.persistentDataPath/WarpforgeAnimTrace/<yyyyMMdd_HHmmss>.tsv`，边记边写（`AutoFlush`）。
⚠️ 与任务原文的「战斗结束落一个 TSV」有一处**偏离**：现在是**边记边写**、一个进程一份文件（多局追加、`seq` 连续）。
理由写在 `AnimTrace` 类头：崩在战斗结束前就全丢，而「崩溃/退出」恰恰是最需要它的时候；收尾口 `Flush()` / `Close()` 都留着。

## 三、怎么开、怎么跑

**开 trace**（默认关，**零默认行为改变**）：

```bash
# 真机 / 批处理起进程前设（Windows cmd）：set WF_ANIM_TRACE=1
# bash：export WF_ANIM_TRACE=1 然后起 player / 跑 Unity 宿主
```
自检里强开（等价口径，只给断言用）：`CardPresentation.AnimTrace.SetEnabledForTest(true, "<路径.tsv>")`，
用完 `ClearTestOverride()`。

**跑对账器**：

```bash
python -I -X utf8 d:/4/Unity/工具/compare_anim_trace.py                 # 只打印用法，退出 0
python -I -X utf8 d:/4/Unity/工具/compare_anim_trace.py --check         # 跑（自动取最新一份 trace）
python -I -X utf8 d:/4/Unity/工具/compare_anim_trace.py --check --trace <文件.tsv> --card SOR36 --tol 0.01
```
退出码：0 = 比到的卡全一致 · 1 = 有差异 · 2 = 用法/IO 错。
输出列 = `卡id | 原版值 | 我们值 | 差`；汇总给「比到 / 一致 / 差异 / 原版无数据 / 本局没跑到 / 原版**参数不全**的拍」。

## 四、验了什么 · 还没验什么

**验过（可复跑）：**

0. 🔴 **首轮 `BattleScene.Run` 的 V2 = 16 通过 / 3 失败（A1d/A1e/A1f），已定位并修好**：
   - **根因 = 断言侧（读法）+ 实现侧一个弱点**，两处都有份：
     · 自检在 **writer 还开着写句柄**的时候就 `File.ReadAllLines(path)`；`File.ReadAllLines` 自己按
       `FileShare.Read` 打开，而**已存在的写句柄**不允许别人以「拒绝写共享」的方式再打开
       ⇒ `IOException: The process cannot access the file … because it is being used by another process`
       ⇒ 而断言里那句 `catch { }` **把异常静默吞了**，于是报成「读回 0 行」（日志里**没有**任何 `[AnimTrace] 写 trace 失败`，
       与「写成功」自洽：`A1b Rows==1` / `A1c FilePath==path` 当时都是绿的）。
     · 实现侧弱点 = `new StreamWriter(path, false, enc)` 的共享模式是**运行库默认值**，别的进程/工具想在中途读
       只能靠对方开宽松共享 —— 不可控。
   - **本地 .NET 8 复现（临时目录，未入仓）**：同一段写法「开着读」⇒ `lines=-1, IOException … being used by another process`；
     「Close 之后读」⇒ `lines=2`；新写法（`FileStream(..., FileShare.ReadWrite)` + Close）⇒ `lines=2 / 表头逐字相同 / 9 列`。
   - **改了两处**：① `AnimTrace.EnsureWriter` 改成**显式 `FileStream` + `FileShare.ReadWrite`**（对端用宽松共享打开即可读，
     例如 Python `open()`；续写档 `FileMode.Append` 且不重写表头）；`Flush()` 追加 `FileStream.Flush(true)`（best-effort）。
     ② `B104_V2_Assert`：**读之前先 `AnimTrace.Close()`**（flush + 释放句柄），并把「文件存在 / 读回没抛异常」写成
     **硬前提断言（A1c2 / A1c3）**，⛔ 不再 `catch { }` 静默吞。
   - ⚠️ 生产语义没变：开关仍**默认关**；`Close()` 之后再 `Append` = **同路径续写、不截断**。

1. **秒级类型检查**：`TMPDIR=/tmp/wf_v2 bash 工具/typecheck.sh` ⇒ `运行时错误数: 0` / `编辑器错误数: 0`（修完复跑仍 0/0）。
