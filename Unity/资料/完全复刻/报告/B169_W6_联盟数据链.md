## 补二：`groupPlayer` —— 客户端「我在不在联盟里」的唯一入口（2026-11-07）

**实机症状**：加入已落盘（`state.currentGroupId = offline-alliance-vanguard`、成员 3→4），但重启后社交窗仍是「开放联盟」列表；本次启动只收到 `FetchGroups`，**从没收到 `FetchCurrentGroup`**。

**根因（回源查到链头）**：客户端**不会**自己发 `FetchCurrentGroup`。登录链是
`PlayerDataManager` 的 Task 屏障里跑 `EntityObjectsManager.Unpack()`（cpp2il/PlayerDataManager.cs:4498）
→ `AlliancesManager.Initialize` → `BuildCurrentMember()`
（cpp2il/AlliancesManager.cs:548-591）读 **实体对象** `EntityObjectsManager.GetObject<JObject>("groupPlayer")`：
拿得到 → 设 `controller.CurrentPlayerCache` → 才 `GetCurrentGroup(forceRefresh:true)` → **这一跳才发 FetchCurrentGroup**；
拿不到（我们的 `GetObjects` 一直回 `Objects:{}`）→ 整段跳过。`PLAYER_OBJECT_KEY = "groupPlayer"`（AlliancesManager.cs:314）
在客户端**只有读、没有写**（全树无 `SetObject(s)`），原本是服务端 CloudScript 写的 ⇒ 假服务端必须自己造。

**改法**：`server.py` 新增 `Handler._inject_group_player(payload)`，挂在 `method == "GetObjects"` 上 ——
`currentGroupId` 非空时往 `Objects.groupPlayer` 写一条
`{"DataObject": null, "EscapedDataObject": "<GroupMember 的 JSON>", "ObjectName": "groupPlayer"}`
（读法：`<Unpack>d__2` 取 `ObjectResult.EscapedDataObject` = 0x18 字段、请求带 `EscapeObject:true`，
`GetObject<T>` 再 `JsonWrapper.DeserializeObject<T>(字符串)`；形状 = GroupMember 的字段名，客户端随后会覆盖 id/titleId/avatarId/avatarBorderId）；
不在联盟里就删掉该键（`Objects` 保持 `{}`）。`FetchCurrentGroup` 的 state 分支本来就有，未改。
`responses/GetObjects.json` 的 `_todo` 已写明「模板本体保持空，动态注入在 server.py」。

**关于「列表里显示已在」**：`Group` **没有** `isMember` 字段 —— 客户端用 `Group.IsCurrentGroup`
（cpp2il/Group.cs:120-140，比较 `groupId == CurrentPlayerCache.groupId`）自己算。
所以 `groupPlayer` 一补上，列表/详情页的「当前联盟」语义自动成立，不需要给 `FetchGroups` 加字段。

**自检**（临时 8799 + 临时 state）：① 未加入 ⇒ `GetObjects.Objects == {}`、`FetchCurrentGroup == null`；
② `JoinGroup(vanguard)` 后 ⇒ `Objects.groupPlayer.EscapedDataObject` 可 `json.loads` 成

③ `ExitCurrentGroup` 后 ⇒ `Objects == {}` 且 `FetchCurrentGroup == null`；
④ `FetchGroups` 形状未变（2 个，键集合与上轮一致）。
