### 4·2 `LiveOpsManager.Initialize` 在等什么 → **`Unpack` 抛异常（Task = Faulted）**

`LiveOpsManager.Initialize()` 是一个**每帧自旋**的协程：

```csharp
IEnumerator Initialize() {
    while (waitingForHandlers) yield return null;   // ← 只要这个字段还是 true，就永远不结束
}
```

判据：ILSpy `LiveOpsManager.cs:1244-1270`（`_003CInitialize_003Ed__14.MoveNext`）+ Ghidra `LiveOpsManager._Initialize_d__14__MoveNext.c`。
`SceneInitializer.<AsyncInitialization>d__24` 的语义是「先置 `Status=1` → 跑完这个协程 → 置 `Status=2`」
（`SceneInitializer._AsyncInitialization_d__24__MoveNext.c` 的两个状态各调一次 `set_Status`）⇒ 协程不完 ⇒ 永远停在 1。

`waitingForHandlers` 的写点（ILSpy `LiveOpsManager.cs:1549 / 1589 / 2221`）只有一个地方会把它置 false ——
**`Unpack(...)` 的末尾**：

```csharp
waitingForHandlers = true;
config = ConfigManager.GetConfig<FeatureConfig>();
await BuildHandlers(data, config);
await InitializeHandlers(config);
waitingForHandlers = false;     // ← 只有走到这里才会清
```

2026-11-06 14:25 实测（`tasks.tsv`）：

```
14:25:23.943   LiveOps.Unpack   Faulted   True
```

⇒ **`Unpack` 抛异常**，`waitingForHandlers` 永远停在 true ⇒ `LiveOpsManager.Initialize` 永远自旋 ⇒ 转场永远不结束。
同一轮 `taskslog.tsv` **没有任何 `BuildHandler-enter`** ⇒ 异常发生在**第一个 handler 建之前**
（即 `ConfigManager.GetConfig<FeatureConfig>()` 或 `BuildHandlers` 的入口），不是某个 handler 卡住。

🔴 **这条同时解释了「登录卡 state 20」**：`PlayerDataManager` 的登录链 await 这条 Unpack，
而 `LoginManager.ProcessLoginResult` 对 Task「只拿不 await」（`StepProbe.cs` 头注释）⇒ 异常被静默吞掉，
症状就是「停在 state 20、没有弹窗、没有日志」。**两个症状是同一个根因。**

下一步：把 `Task.Exception` 的内容打出来（已加进 `AddressablesProbe.Tick` 的 Faulted 分支），按栈定位那一行。

### 4·4 第二层：Manager 组过了之后，**UI 组**又炸一次（2026-11-06 14:32）

加 ⑥ 之后再跑：`SceneInitializer.status` 从 `1/prio=1` 变成 **`-1/prio=2`**（= Manager 组已过，UI 组里有人抛异常被置 `Error`）。

⇒ 抛异常的是 **`UiBadgeNotificationManager`（GameObject 名 `EventHighlighterManager`）**，

处置：同 ⑥，加 ⑦ 桩（跳过 + 置 `Status=Initialized`，🔶 标记）。

### 4·5 处置（当前）

先加一条**非原版桩**把这条路解开（🔶 标记）：
`GameModes.InitializeHandler` → 直接返回 `Task.CompletedTask`。
目的：让 `Unpack` 走完 → `waitingForHandlers=false` → `LiveOpsManager.Status=2` → `SceneInitializer.Status=2`
→ `WaitSceneLoad` 退出 → **转场应当完成**。跑通之后再回来做「让 BuildHandler 真正跑起来」这件事。

### 4·6 其它结论

1. `AchievementsManager.Initialize` 以前**整段 skip 而不置 Status**，会让它停在 Pending(0)。已改成
   「skip 后置 `Status=Initialized(2)`」（`stubs.tsv` 实测 `skip+init AchievementsManager.Initialize prop(2)`）。
   ⚠️ 但**单这一条不足以解决**（`LiveOpsManager` 才是当前卡点）。
2. **登录卡 state 20 是另一条独立的链**（`ProcessData` 之后的续体不恢复 / 某个 await 不返回），
   与转场卡点**不是同一个**（`AddressablesManager.Init` 已证明会完成）。
3. **本地化包 CRC 不符是真缺陷**，但**不是**转场卡点的原因（菜单能加载、顶栏能渲染）。
