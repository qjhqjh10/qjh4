## 二 判据（我凭什么这么改）

### 1 · 落点：按【符号名】重定位，不按行号
- **判据**：`工具/check_ledger_points.py` 的 `find_decl_candidates(name)`（一个名字处于**声明语境**的行）。
- 规则：落点第一个 `文件:行` 的**括号名**（`head_name` 优先，其次 `paren_idents`）就是「我们那边的声明名」；
  在**现文件**里找它的声明候选：**唯一 ⇒ 写回那个行号**；多义 / 找不到 ⇒ 不动、报人工（最终 0 条）。
- **反例（为什么不用 `--fix`）**：`战斗逻辑驱动.tsv` 在本会话动手前**已经漂了 16 行**
  （账写 `CombinedAttackCanKillWarlord @ 1231`，动作前实际在 1247）⇒ `--fix` 只会把旧错固化。

### 2 · 落点形态：`verify_annot.dn_at` 同款正则（新增 NEED-HUMAN 闸）
- `fix_block_reason` 现在**第三道闸**：目标行必须能被 `dn_at_name()` 解析成「声明名 + `(` 或 `{`」；
  解析不出（注释行 / `{` / `}` / 空行 / **字段带初始化器**）⇒ 打 **`NEED-HUMAN`** 并**跳过**，不写。
- 自测负例：目标行是 `///` / `}` / 空行 / 字段 ⇒ 都必须报 NEED-HUMAN（4 条新断言）。

### 3 · `.cs` 一律【二进制读】（裸 CR 会让行号整体偏移）
- `read_src_lines()`：`rb` 读 → 只把 `\r\n` 归成 `\n`，**裸 `\r` 留在行内**（与编辑器 / git 口径一致）。
- 起因：`RuleEngine/Core/DeckRules.cs` 曾有 **7 个裸 `\r`**（`\r\r\n`）⇒ 该文件行号**整体偏 +7**，
  而我第一批 `--fix` 恰好跑在修 CR **之前** ⇒ **12 行被改到错行**（已按符号名全部改回，见 §三·1）。
- 自测负例：喂一个含 `\r\r\n` 的临时文件，`void Foo` 必须算在**第 4 行**（文本模式会算成第 5），共 6 条新断言。

### 4 · 状态口径
- `A` = 判据读了 + **双侧到方法级** + 行为一致；同一 `文件:行` 覆盖多个方法 ⇒ **只能 B**。
- `B` = 有实现未核（含「只找到同名字段/表级实现」）；`C` = 该做没做；`D` = 不复刻，**必须带书面判据**。
- `D` 的三种合法理由：**死代码（0 调用点 + 0 挂接）· 服务器/平台 SDK · 原版空方法体**。

### 5 · 用户裁定（2026-10-25，逐字落进 `差异` 列）
`s 档` 原文：**「原版服务器/账户/云后端不复刻」** —— 只覆盖 **a 档 84 类**；**b 档一行不动**；**其余 P3 候选仍须报用户**。
