## 二、🔴 关键发现：坐标帧已解，「等真机」不再成立

旧账（B96_WA / B97_DAILY / B98_H5）反复以「`Event Progression ap(0,122)` 从根底算会落到可见裁切外，无 live 验证判不了」把 #4–#7 卡在「等真机」。**本轮静态解出，结论相反**：

1. **`Event Progression` 是 prefab 根的直接子节点**，不是某个深层节点。
2. **prefab 根 `RectTransform` = 535×848.8**（1×2 高卡），挂 `RectMask2D` 裁到 `535×848.8`。
3. **旧账的「535×414.4 可见」是拿错了 1×1 变体**（`Base Game Mode Container 1x1.json` 根才 414）—— 这个错误正是「卡点」的来源。
4. `Event Progression` 底边距卡底 122、顶边 181.39 ⇒ **即便按 414.4 算也在卡内**（`181.39 < 414.4`）。**绝不落到裁切外，无歧义。**
5. 我们 `MainMenuRuntime` 早已支持 1×2 高卡（`CardHTall=848.8`，`:2402`；`Put` 按 `h>CardH+1` 选档 `:2540`；事件卡 `H=CardHTall` `:2584-2588`）⇒ **宿主接线无尺寸障碍**。

**⇒ 下一波可以把「建 `Event Progression` 子树」直接排期**（几何见 `判据/B99_R2_日常9条终局.md` §二），⛔ 不必等真机。
