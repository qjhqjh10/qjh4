## 二 两条硬约束怎么落的（施工单 §二·3 反坑 1/2）

### 约束①：`MsgStart.mode` 必须 = `"ClosedDeck"`

- **唯一真源** = `DraftModeWindow.NetModeName { get { return PlayModeNames.Name(GameMode.ClosedDeck); } }`（`:4516`）。
  `LaunchBattle` 里 `TryStart(…, NetModeName, …)` 用的就是它，**不存在第二处字面量**。
- **为什么错一个词就静默**：`MsgStart.mode → NetPendingBattle.Mode → PlayMode`，
  而 `BattleDriver.RecordBattleLog` 写的是 `PlayModeNames.Name(Ctx.PlayMode)` ⇒ 记录 `Mode = "Skirmish"`
  ⇒ `DraftOutcomes` / `CountDraftMatchesIn`（两者都按 `PlayModeNames.Name(GameMode.ClosedDeck)` 过滤）**一条都数不到**
  ⇒ 轮抽战绩永远不涨，**零报错**。
- 端到端断言直接量这件事：合成一条 `Mode = "ClosedDeck"` 的记录 ⇒ `DraftOutcomes` **数到 1**；`Mode = "Skirmish"` ⇒ **数到 0**（A6/A7）。

### 约束②：交过去的 `PlayerDeck.GameMode` 必须 = **13**

- **唯一真源** = `DraftModeWindow.NetDeckGameMode { get { return (int)GameMode.Skirmish; } }`（`:4525`），
  `pre.gameMode` 现在直接填它（原来写死 `(int)GameMode.Skirmish`）。
- **为什么不能填 7**：`NetPendingBattle.Vars`（`Net/NetBattle.cs:81`）**不看 `PlayMode`**，
  它读 `PlayerDeck.IsSkirmish`（`DeckRules.cs:742` = `GameMode == 13`）⇒ 填 7 ⇒ `IsSkirmish = false`
  ⇒ **12 张轮抽牌按经典 30 张那套打**（起手 3 / 手牌上限 10…），**不报错**。
- 断言把这条**实测**出来（B7/B8）：`gameMode = 7` ⇒ `IsSkirmish` 假 ⇒ `Vars.deckSize = **30**`（反例端到端）。

### 反坑 4（施工单没编号，我一并落了）：跨局泄漏

联机分支**只 `return`**，一个字节都不写 `PrebuiltDecks.SetPendingBattleDeck` / `BattleDriver.SetPendingPlayMode`
（那两个是「读一次就清」的静态通道，联机这条路上**没人读** ⇒ 写了会漏到下一局单机）。

5. **对面掉线/重连** ⇒ 主机等重连、客机重放（既有联机行为在轮抽模式下不被破坏）。
