### 3.1 为什么是「同一物理行追加」+「helper 放外层类尾」

- 内层类 `ParticleCollisionDefinition` 里**插任何一行**，都会让账行 `TapHitMaterialDefinition.cs:200/205/212`（`未分类_其他.tsv:624/629/626`）整体漂移；
  外层类尾之后没有账落点 ⇒ 只有这里能加行而不动账（铁律 · `§三` 那条「新成员追加到类尾」）。
- 第 120 行**没有**行尾 `//` 注释（那是 `:119` 那行才有）⇒ 追加的代码不会落进注释里（踩过的坑：`2026-10-30` 六次）。

### 3.2 具体代码（落点自证）

```csharp
// TapHitMaterialDefinition.cs:120（改后）
CacheParticles[particles] = ps; RelocateGrabLayer(ps.gameObject);   // WF_GRAB501 开时才搬层（关时一行不跑；定义在类尾）

// TapHitMaterialDefinition.cs:227（新增，外层类类尾）
static void RelocateGrabLayer(GameObject go)
{
    int layer = GrabScreen501.FinalLayer(go, -1);

}
```

- 传 `wantedLayer = -1`（**不是**父层）：`FinalLayer` 里 `source = wantedLayer >= 0 ? wantedLayer : go.layer` ⇒ 记的是**prefab 自带层 0**；
  且**不是失真效果的 Tap 件会原样返回 -1 ⇒ 一行不跑**（若传父层，非失真件会被改层 = 静默行为变化）。
