## ⑥ 顺手发现

1. **🥇 `out_cpp2il_dev_ilspy` 现在是【顶层 + 按命名空间分目录】混排**（2,404 个文件）：全局命名空间的类在**顶层**，带命名空间的在**子目录**（如 `Everguild.LiveOps/`）。找类**必须** `find <root> -iname "*类名*"`，⛔ 别只 `ls` 顶层（我第一遍就漏了一个 `Everguild.LiveOps/InventoryCondition.cs`，正好是账里新增的那一条）。
2. **K3 §⑤ 的「`OverlapsAny` 判据不在 `decomp_full`」是错的** —— `decomp_full/RectExtensions__OverlapsAny.c` 就在，且和 ilspy 那份逐句一致。**已就地订正**（写进了 `CollectionWindow.CheckFocusedArmy` 的 doc）。
3. **ilspy 的 `CardArmy.Neutral` 是占位符，不是真参数**：`CardCollectionTab.OnItemSelected` 与 `CardCollectionDisplay.CheckFocusedArmy` 两处的 `wildcards.Initialize(CardArmy.Neutral)` 在 ilspy 里长得一模一样，但**两处调用前各有一行 `Unmanaged memory load: [… +0x2C]`**（= 读一个 int 字段）⇒ 真参数是**那张卡的 `cardArmy`**（`RawCardScript` 的 `cardArmy` 在 `+0x2C`；旁证 = `WildcardDisplay.SetCountersText` 的谓词也在 `+0x2C` 上比 `currentArmy`）。**教训**：ilspy 里出现「枚举字面量当实参」时要先看它前一行的内存 load —— 那多半是解不出来的参数。
4. **`CardArmy` 里没有 `Neutral` 卡**：`cards_engine.json` 1,128 张全在 13 个阵营里（`faction` 分布 134/119/92/84/83/83/81/79/79/78/78/70/68，**Neutral 0 张**）⇒ 徽记那条链**不可能**遇上 `ArmyIcons.Id("Neutral") = -1`。这条同时说明：Cards 页排序（阵营升序）下**第一格永远是 Ultramarines**，所以「一开页徽记 = Ultramarines」这件事**同时**能用 Setup 的 `Initialize(10)` 和 CheckFocusedArmy 解释 ⇒ 断言必须靠**滚到底**那一条才有分辨力（已在 ④ 里那么写）。
5. **`CardNameFilter` 的搜索结果原版是【反序】的**：`decomp_full/CardNameFilter__CheckInputTextSearch.c` 里循环是 `iVar1 = *(int*)(param_2+0x18); … iVar1 += -1; … ` 从**末尾往前**取，`list.Add` 往后追加 ⇒ **结果表是输入序的反序**。我们保持输入序。这条我没改（**玩家可感知但极难判断「哪个才对」**，而且它明显像原版的意外行为）⇒ **记在这里由调度台定口径**；要照抄的话是 `VisibleCards()` 在 `needle != null` 时 `.Reverse()`。⚠️ 我倾向**不照抄**（这是原版的 bug 味道），但按铁律 11 应该照抄 —— **需要一条裁定**。
6. **`DeckCostQuantityRowDrawer` 的 `maxCostToDraw` 是 ctor 里写死的 8**（`DeckCostQuantityRowDrawer.cs:119`），不是序列化字段 ⇒ 请求 2 里那句 `i == 8` 有依据。
