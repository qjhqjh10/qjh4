## ② 判据（可直接照做的口径）

**总表在 `判据/战斗逻辑驱动_前置门与现算口径.md`**（四节，每节：原版行为 → 我们现状 → 差在哪 → 怎么改 → 置信度）。这里只放「E 组最需要的五条」：

1. **extrinsic 闸的形状**（`CardScript__AddEffect.c:93-157`）：
   `Contains == true` 时四出口 —— ① `buffType==removeExtrinsic(11)` 放行；② `!extrinsicVariable` ⇒ **return 0**（静默）；③ `extrinsicVariable` 且找到 `IsSameEffect` 完全一样的 ⇒ **return 0**；④ `extrinsicVariable` 且没有完全一样的 ⇒ **先 `RemoveExtrinsicEffectsFrom(施放者)`**（清该来源的全部 extrinsic）**再放行**。
2. **闸还有第二个位置**：`AbilityLogic__PlayAbility.c:2832-2847`（`TurnStart` 重演路径）—— `Contains` 为真 ⇒ **跳过该目标、根本不调 `AddEffect`**。⚠️ **极性：真 = 跳过**。
3. **`AddArmour` 只需三句**：`+= delta` · `if (<0) = 0` · `UpdateHealthText()`。**无上限、不查 Invulnerable、不重算。**
4. **`CurrentMeleeAttack` / `CurrentRangeAttack` 的覆盖档**：`setMeleeAttack(70)` / `setRangeAttack(85)` 一旦出现在 `activeEffects` 里，getter **立即 `return` 它的增量**（连 base 和已累加的都丢掉）。**`CurrentRangeAttack` 开头还有一条 `blind ⇒ return 0`。**
5. **`setCurrentHealth(100)` 与 `setHealth(9)` 不是一回事**：
   - `100`：`currentHealth = effect.healthChange`（**无条件、不夹上限、不查 Invulnerable**，`.c:229-247`）；
   - `9`：`currentHealth = currentMaxHealthProcessed`（`.c:794-820`），而该上限因刚 `List.Add` 了这条 `setHealth` 记录已把 `healthChange` **当覆盖值**算进去 ⇒ **不是单纯「回满血」**（见 §⑤·6）。
