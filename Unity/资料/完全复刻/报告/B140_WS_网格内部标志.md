## 一、这 101 份网格是怎么进来的

**结论：不是任何一个脚本写出来的 —— 是 Unity 造 `Mesh` 对象时的默认值。**
全仓（`工具/*.py` · `工具/scripts快照/*.py` · `WarpforgeArena1/Editor/*` · `WarpforgeVFX/Editor/*` · `ArtBaker`）
`grep m_MeshOptimizationFlags|m_MeshUsageFlags|m_KeepVertices|m_KeepIndices` = **0 命中** —— 这正对应 G6 记的「生成器 0 命中」。

实际生产链（两条，都落在 `EffectExporter.ImportMesh` 那一族）：

| 路径 | 生产点 | 落盘方式 | 为什么带 Unity 默认值 |
|---|---|---|---|
| `WarpforgeVFX/Meshes/**`（97 份）· `ArenaOriginalPrefabs/…/Mesh/**`（共 579 份与本活配对，其中 1 份命中本活名单） | `WarpforgeArena1/Editor/EffectExporter.cs:4755` `ImportMesh(Mesh m)` | `DeepCopyMesh`（简单网格）或 `Instantiate` → `AssetDatabase.CreateAsset` / `EditorUtility.CopySerialized` | 新建/深拷贝出来的 `Mesh` 带**新建对象的序列化默认值**（`OptimizationFlags 1` / `UsageFlags 0` / `Keep* 0`），原版那份是**他们的 asset pipeline 写死的**（-1 / 4 / 1 / 1） |
| `Resources/Art/card3d/**`（2 份）· `Resources/Art/vfx/**`（1 份） | 同一导入族（3D 卡体 / 能量环网格，读口 `Core/CardArt.cs:150` / `:296`） | 同上 | 同上 |

⇒ **不是「写错了」，是「从来没写」**。所以修复方式不是改某个常量，而是**加一个可重复的写口**。

## 三、写口设计（`B140_WS_MeshFlags.cs`）

- **入口**：`Run()` 写盘 · `DryRun()` 只报差异不写 · `Verify()` 只读校验；三个都有 `[MenuItem]`（`Tools/Warforge/B140_WS …`）。
- **三段式落盘**（项目铁律：`SetDirty` 后当场回读抓不到「没落盘」）：
  ① `SerializedObject(mesh)` 写四个 `intProperty` → `ApplyModifiedPropertiesWithoutUndo` + `SetDirty` + `SaveAssets` → **重开文件按字节读回**；
  ② 不一致（或属性不存在 / 加载不到）⇒ **文本级只替换那 4 行的数值** → `AssetDatabase.ImportAsset(ForceUpdate)` → **再读回**；
  ③ 仍不一致 ⇒ **点名报红**（⛔ 不静默）。
  文本级那条**保留行尾与 BOM**（现读：这批 `.asset` 全是 **LF、无 BOM**，实测 `CRLF 0 / LF 180`）；正则允许 `\r?` 以兼容将来被转成 CRLF。
- **逐份写「该份自己的原版值」**，不是统一常量 —— 因为原版本身就有 5 种组合（见 §二）。
- **顶点指纹护栏**：写之前/之后各算一次 `m_VertexCount / m_DataSize / _typelessdata 长度+前 64 字符`，
  变了就报红（这批网格的顶点字节是审计 A-04/A-10 验过**与原版逐字节相同**的，写口不许碰）。
- ⚠️ **故意不调 `MeshUtility.Optimize`**：它会把网格**真的重排几何**（index 重排 / 顶点去重），
  我们只要那个**序列化标志**的数值 —— 用了它等于拿「标志对了」换「几何被改」。

## 五、没做的 / 待做的

1. 🔴 **出包验证（唯一能证伪「`KeepVertices=0` 打包后返空」的那一验）** —— **编辑器断言 ≠ 出包验证**。
   `m_IsReadable` 与 `Keep*` 决定的是**打包时**顶点是否被裁掉；而现读 `m_IsReadable` 我们 **1**、原版 **0**（79 份不同），
   所以**编辑器里怎么读都读得出**（C-2 就是把这件事钉死的一条断言）。
   **必须列进 Unity/真机波次**：出一次 Player → 在 Player 里跑同一个 `Resources.Load<Mesh>().vertices` 读口 → 断非空。
   ⛔ 在那之前，「已修好」只到「盘上值对了」这一层。
2. **`m_IsReadable` 79 份不同（我们 1 / 原版 0）** —— 本轮**没动**。它直接管运行时能不能读顶点，
   与 `Keep*` 是两套机制；本活判据（top-5 #4）只点了四个字段。**要不要照原版改成 0，等出包验证有结论后再定**
   （若原版 0 也能读，说明原版靠 usage flag 4/8 保读；那就该一起照抄）。已记进报告，未进账。
3. **`EffectExporter.ImportMesh` 重跑会把这四个字段再冲回默认值** —— 写口是「事后修」，**不是「生成时写」**。
   根治要在 `ImportMesh` 落盘那一刻写这四个字段（与本活同域、但属另一处文件，未授权改）。
   ⇒ 重跑 `EffectExporter` 之后**必须再跑一次** `B140_WS_MeshFlags.Run`（`Verify()` 会立刻抓到）。
4. **`m_MeshMetrics[0]/[1]`（审计 A-17）与 `m_Channels` 法线维度（A-18）** 也在同一批网格上、也是同一个「新造对象默认值」的病，
   但属另外两条账，未纳入本写口。
