## §4 「语义不同」那批 —— **本批 0 条**

两条**一度**要判语义不同、最后判真等价的，差异**必须单独立账**（⛔ 别当成已解决）：

### 4·1 `CollectionDisplay<T>.ToggleFilters(bool state)` —— 置位 vs 翻转
- 原版：`filterController.Toggle(state)` ⇒ **按 state 置位（幂等）**。
- 本仓 `ToggleFiltersNow()`（`CollectionWindow.cs:2803`）：**无参、每次翻转** `_fltOpen`；包一层 `ToggleFilters()` 给点击用。
- 今天等价（唯一入口是点击）；**但一旦出现「程序化置位」（例如外部想让筛选栏一定打开），翻转会失配**。
- 建议：`ToggleFiltersNow` 改成吃 `bool state`，`ToggleFilters()` 传 `!_fltOpen`。

### 4·2 `CampaignNode.Setup` 的 `Index` 来源
- 原版：`Index = int.Parse(NodeId 里的数字)`。
- 本仓：**数组下标**（`CampaignData` 表 = 原版 SO 顺序，但**缺 `UM14`**）⇒ 第 15 项起 Index 与原版差 1。
- 建树/样式/首奖励/点击都对，所以本行仍判真等价；**但 Index 这一格要单独立账**（若任何地方按 Index 与外部数据对齐，会错位）。

## §6 顺手发现（调度台分流用）

### 6·1 🔴 `CardTraitFerocity.IsActive` 其实**判得了** —— 代码注释可以订正（铁律 5）
`BattleDriver.cs:28129-28131` 那段写着「`CardTraitFerocity__IsActive.c` 同一个撞击符号，所以 Ferocity 那一条**判不了**」。
**ILSpy 有真体**：`out_cpp2il_dev_ilspy/CardTraitFerocity.cs:5-8` = `public override bool IsActive(CardScript card) { return true; }`（**恒 true**）。
⇒ 把注释改成「已由 ILSpy 实读 = `return true`，走默认支」。我们的实现本来就是默认 `return true`，**行为不用改**。

### 6·2 `ArmyItemContainer.OnDestroy` 不是「文件名与内容不符」—— 是**清订阅**
`.c` 与 ILSpy（`ArmyItemContainer.cs:403-415`）一致 = `m_OnSelected = (_003C_003Ec._003C_003E9__22_0 ??= delegate(CardArmy){})`
—— 把 `OnSelected` 事件的**后备委托换成空委托**（释放订阅引用）。ctor 里是同一个写法（`b__23_0`）。
⇒ 第 2 批那条原来「疑文件名与内容不符」可以销案。

### 6·3 `ArmyItemContainer__ToggleInteractable.c` / `ChallengeButton__Toggle.c` 首行是**别的类名**（ICF 折叠，非错位）
- `ArmyItemContainer__ToggleInteractable.c` 首行 = `RankedArmySelectorContainer__ToggleInteractable`；
- `ChallengeButton__Toggle.c` 首行 = `Card2DController__Toggle`；
- `CardTraitFerocity__IsActive.c` 首行 = `BaseAddressableLibrary__ValidateLibraryLoad`，体 `return 1`。
三者的**体语义都与 ILSpy 版一致**（`Selectable.interactable=option` / `gameObject.SetActive(option)` / `return true`）
⇒ 属 CLAUDE.md 已记的**良性 ICF 折叠**，⛔ 不要当「内容错位」去推翻。

### 6·4 第 3 批工作单 col4「本仓同名方法在哪」的**口径与列名不符**（1-3 批一直如此）
抽样脚本填的是**落点方法名**的声明位置（例：`日常_奖励.tsv:27` 那行填的是 `Build` 的位置），
而 census 的「同名」指的是**与原版方法同名**的符号位置（那才是「优先核它是不是等价」的那一批）。
⇒ 两批消费方都拿 col4 当「落点位置」用了。**建议下一批换口径**（或在列名上写明），本次为兼容前两批**保持原样**；
真正有用的「同名符号在哪」我写进了各条 `依据` 里。

### 6·5 `ChallengeButton` 的四条账里有两条**降级为「无对应物」**（3、18）
`WireChallengeButton` 往**静态** `ChallengeEngine.VisibleChanged` 上 `-=` 再 `+=`、徽标总线 `Attach` 幂等 ——
**这套在「只有一个宿主」时完全正确**，但用户 2026-10-27 的注释写着宿主**有两个**（主菜单 / 卡组编辑）：
两个宿主的 `_challengeRoot` 会**互相顶掉最后一个**（静态字段只有一个）。目前看不见，但值得立账。
