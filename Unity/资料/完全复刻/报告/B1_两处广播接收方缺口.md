## ① `BroadcastUnitSpiritStone` —— 补「接收方自排除」

### 1. 原版逐句

| 位置 | 内容 |
|---|---|
| `decomp_full/CardScript__TriggerSpiritStone.c`（全文） | `CardScript.TriggerSpiritStone(this)`：先 `RawCardScript.OnTrigger(600, …, this, this)`，再 `if (HasAbilityType(600))` ⇒ **`BattleManager.BroadcastUnitSpiritStone(this)`** ⇒ 广播实参**就是发起那张卡** |
| `out_cpp2il_dev_ilspy/BattleManager.cs:27987-27989` | `BroadcastUnitSpiritStone(CardScript unitSpiritStone)` = 一句转调 `BattleManagerSupport.BroadcastUnitSpiritStone(this, unitSpiritStone)` |
| `out_cpp2il_dev_ilspy/BattleManagerSupport.cs:1050-1083` | 三跳：**棋盘**（`:1057` `if (cardScript.IsInPlay())`）→ **当前回合方手牌**（`:1064-1072`）→ **另一方手牌**（`:1073-1082`）。三跳**都没有**额外的 `op_Inequality` ⇒ **自排除不在广播器里** |
| `out_cpp2il_dev_ilspy/CardScript.cs:7619-7627` | **接收方** `TriggerOtherCardSpiritStone(CardScript spUnit)` 体内**第一句**就是 `if (spUnit != this)`，通过才 `OnTrigger(455 OtherCardSpiritStone, mgr, this, actingCard = default, targetCard = default)`。`.c` 里同一句渲染成 `UnityEngine_Object__op_Inequality(param_2, param_1)` |
| `out_cpp2il_dev_ilspy/CardScript.cs:12093-12101`（对照） | 同族的 `TrapResolved` / `QuestResolved` 也**没有**体内守卫 —— 它们的自排除写在调用方（`BattleManager` 的循环里） |

**结论**：`spUnit` 在原版**只用于自排除**，且 `actingCard` / `targetCard` 都是 `null`。

### 2. 我们改前差在哪

`EffectResolver.cs:964-965`（`ResolveOneCore` 的 `kind == "spirit"` 付费支）：

```csharp
BroadcastWhen(ctx, WhenEventKind.SpiritAbility, owner, null, null);
```

`subject` = `null` ⇒ `WhenEvents.Matches` 里那条自排除守卫（`WhenEvent.cs:1683`）走的是
「**拿不到事实时放行**」那一档 ⇒ **自己用灵魂石能力时，自己那张卡的 455 监听器也会被叫醒**（比卡面宽）。

⚠️ **不能靠 `WhenEvents.SelfExcludesOnKeywordTrigger` 修**：那个守卫的入口按
`WhenEventKind.TriggersPrefix`（`"triggers:"`）判，而 `SpiritAbility` 的 Kind 是 `"spiritability"`、
**不在那一族里**；反过来 `triggers:*` 那一族**原版也不自排除**（`Ferocity` / `Synapse` / `Duty`，
见 `WhenEvent.cs:1664-1687` 的机器码表）—— **⛔ 一刀切会把真卡改错**。

### 3. 改了什么

新增 `RuleEngine/Core/EffectResolver.cs` **类尾** `BroadcastUnitSpiritStone(BattleContext, int who, UnitState spUnit)`：

- 先 `SnapshotBoardListeners(ctx, null, null)`（**判据仍是那一份**，没有第二份过滤器），
  再 `RemoveAll(l => ReferenceEquals(l.Unit, spUnit))`，然后把快照交给
  `BroadcastWhen(…, boardListeners: snap)` —— 用的是 `BroadcastWhen` 原生的
  「调用方在**事件发生那一刻**拍快照」口（`W62 · R2` 建的口）。
- `card` / `subject` / `actor` **仍传 `null`**：原版 `actingCard`/`targetCard` 都是 `default`；
  传 `subject` 会多出一个「事件主体」（`ResolveOps` 的 `it` 种子 + `SelfOnly` / criteria），那是**更宽**。
- `spUnit == null`（现读 = **手牌战术卡付石**那一档，见 §5）：原版这时 `unitsp` 是手牌那张
  `CardScript`，而手牌卡与棋盘/手牌里的监听者**永不相等** ⇒ 排除退化为无操作，与本支路**等价**；
  我们这层没有手牌卡的 CardScript 身份 ⇒ 不猜、`ctx.Log` 出声。
- 调用点 `:964-965` 改成 `BroadcastUnitSpiritStone(ctx, owner, source)`（**行数不变**，避免给账的行号落点造成漂移）。

### 4. 为什么今天「零可观测」

全池唯一 455 监听者是 **ASH81 Bright Lance Vyper**（`"When you trigger a Spirit Stone ability,
gain Sniper and +1 [Ranged]"`），而它自己的 `abilityTriggers = [410, 455]` ⇒
**自身没有 `[Spirit Stone]` 能力** ⇒ 永远不会「自己叫醒自己」。
（12 张带 `[Spirit Stone]` 前缀的**战术卡**会走 `spUnit == null` 那一支。）

### 5. 战利（顺手查实）

`[Spirit Stone]` 前缀现读 **28 张**（16 部队 + 12 计策）。部队那 16 张 `source` 是 `UnitState`（真自排除）；
计策那 12 张 `source == null`（我们这层没有手牌卡的 CardScript 身份）。

## ② `BroadcastSacrificeResolved` —— 去掉多出来的 `IsInPlay` 闸

### 1. 原版逐句

| 位置 | 内容 |
|---|---|
| `out_cpp2il_dev_ilspy/BattleManager.cs:27937-27939` | `BroadcastSacrificeResolved(CardScript unitSacrifice)` = 一句转调 `BattleManagerSupport.BroadcastUnitUsedSacrifice` |
| `out_cpp2il_dev_ilspy/BattleManagerSupport.cs:1764-1805` | **三趟**：棋盘 `:1766-1777` / 当前回合方手牌 `:1778-1790` / 另一方手牌 `:1791-1804`。**三趟唯一的闸都是 `if (cardScript != unitSacrifice)`**（`:1771` / `:1784` / `:1798`）——**没有 `IsInPlay()`、也没有 null 判** |
| `out_cpp2il_dev_ilspy/CardScript.cs:7783-7788` | 接收方 `ReactToUnitUsedSacrifice` 体内**只有** `OnTrigger(225 OtherCardSacrifice, …, this, default, default)` ⇒ 自排除写在调用方，接收方不再排一次 |
| `.c` 对照 | `decomp_full/BattleManagerSupport__BroadcastUnitUsedSacrifice.c` 第 1/2 趟的 `op_Inequality(uVar3)` 看着只有 1 个实参 —— 那是 **Ghidra 把 `rdx` 掉了**（机器码有 `mov rdx, rsi`），与第 3 趟的 `op_Inequality(uVar3, param_2)` 同义。**⛔ 别据此判「前两趟不是自排除」** |

### 2. 我们改前差在哪

`triggers:sacrifice` 走 `FireTriggerAlways` → `BroadcastWhen(Triggers(Sacrifice))`。
`BroadcastWhenCore` 的棋盘快照（`SnapshotBoardListeners`）**无条件**
`if (ctx.IsPendingDeath(u)) continue;` ⇒ **待死单位收不到 225**，而原版三趟都不判 `IsInPlay`。

（对照：`BroadcastUnitSpiritStone` / `Summoned` / `Damaged` / `Attacked` 那几族棋盘那一趟**有** `IsInPlay` ⇒
那道闸对它们是对的，⛔ 不能整体拆掉。）

### 3. 改了什么

1. `SnapshotBoardListeners(ctx, preCalled, preCalled2, bool includePendingDeath = false)` —— 新增第 4 个**可选**参数
   （默认 `false` ⇒ 既有调用点行为逐字不变；`RuleCore.cs:12345` 那条两参调用照旧）。
2. `BroadcastWhenCore` 算一次 `bool boardIncludesPending = BoardJumpIncludesPendingDeath(kind);`，
   喂给快照**和**棋盘跳的 `FireBoardWhenListener(..., allowPendingDeath: boardIncludesPending)`（两处同刻，缺一处就漏）。
3. 新增 **类尾** `BoardJumpIncludesPendingDeath(string kind)` —— 这份名单的**唯一落点**
   （今天只有 `WhenEventKind.Triggers(KeywordTable.Sacrifice)` 一族）。判据全文写在该方法的 doc 里。

### 4. 已知残差（如实标，已写进账）

「用献祭那张卡**自己有正文**」时，广播走 `FireTriggerAt` 那条路，它的监听者快照是
**入队那一刻**由 `RuleCore.cs:12345` 拍的（`SnapshotBoardListeners(ctx, null, null)`，默认不含待死）
⇒ 那条路上待死监听者仍会少收一次。

**一行修法（给 `RuleCore.cs` 的写手）**：

```csharp
// RuleCore.cs:12345
SnapshotBoardListeners(ctx, null, null, includePendingDeath: keyword == KeywordTable.Sacrifice)
```

`RuleCore.cs` 不在本代理白名单（`A3` 在改那个文件）⇒ **没有动**。今天不可达（池内 0 张卡有
`sacrifice` 监听者），但口径上要收口。

同理「跳过 `u.Card == null` 的单位」**保持不动**：原版 `ReactToUnitUsedSacrifice` 要用
`rawCardData`，无卡单位在原版会直接崩；我们保留 null 判是「宁可不崩、不静默错」的一档，
已写进 `SnapshotBoardListeners` 的 doc。
