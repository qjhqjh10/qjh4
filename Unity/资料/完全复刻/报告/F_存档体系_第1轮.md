## ② 四问的答案（核心）

### a) 版本迁移 —— **有版本号，没有迁移**
- **有**：`PlayerDataKey.ProfileVersion` 存**游戏版本字符串**；`OnlineData.GetPlayerGameVersion`（`OnlineData.cs:70-95`）读它、`Split(" ")` 取首段、解析失败退 `new Version("0.0")`。
- **没有**：⛔ 任何 `Migrate*/Upgrade*` 方法（0 命中）；⛔ 每个 key 的 JSON 里**没有 schema 版本**；⛔ 本地档不迁移 —— `ClearLocalPlayerData()`（`PlayerDataManager.cs:10157-10172`）就是 `File.Delete`，换版本 ⇒ 新文件名 `PlayerDecks{ver}.dat` 读不到 ⇒ `LoadStarterData()`。
- **原版唯一的「兜底补丁」形态** = `CheckForTutoriaDoneAndDataFix()`（`:11229`）：读 `UserReadOnlyData["GameModes"]` → 探 `TutorialEvent` → 缺就补 → 不认识就忽略。**要照抄的是这个形态，不是「版本→迁移函数表」**。

### b) 写盘时机
| | 本地设置档 | 云端进度 |
|---|---|---|
| 方法 | `SavePlayerData()`（`:10174-10270`） | `UpdateOnlineUserData()`（`:11893-11930`）→ 协程队列 → `PlayFabClientAPI.UpdateUserData` |
| 时机 | **关键节点整文件覆盖**（7 个调用点：`AccountTab`×4 / `LoginManager`×3 / `BattleSettingsWindow:133` / `LoginWithEmailHelper:63` / `RankedEventBase:261`） | **每次改动一个请求**；失败重试一次（`:1036-1072`） |
| 原子性 | ⛔ `File.Open(FileMode.Create)` **直接截断**再写 —— **无 tmp、无备份、无 fsync** | 服务端事务 |
| 失败 | ⛔ 无 try/catch | **`!IsLoggedIn` ⇒ `LogWarning` + 丢弃**（`:11925`） |

**断电丢什么**：丢最后一次设置变更；**崩在写中间 ⇒ 本地档整份损坏**（不是丢一条）。云端进度不受影响（原版权威在云）。

### c) 多活动隔离
- **分表清单现成 = `PlayerDataKey` 53 个**（52 个有效，见方案文件 §四·1 全文）。**每 key 一份 JSON**。
- **读**（`OnlineData.cs:145-193`）：`UserReadOnlyData[key]` →（可选）`UserData[key]` → 都没有则 `Log` + `null` → 有则 `JsonWrapper.DeserializeObject<T>`，**⛔ 无 try/catch**（坏 JSON 冒泡）。
- **写**：`Dictionary<string,string> values` **按 key 整值覆盖**。**合并规则 = 无**（没有字段级 merge、没有版本比较、没有时间戳）。
- ⚠️ **对我们直接影响**：将来做多端/云同步，**必须自己加版本或时间戳** —— 原版**没有**可照抄的合并算法。

### d) 「没有赋值点」的字段
- **`tips` 已人工确认是「有读无写」**：`private List<Tips>`（`:5102`，**无 `[SerializeField]`**，上下文 `:5096-5106` 只有它是 private ⇒ prefab 序列化不了），全类只有 `:13575` `if (tips != null)` 一处读，**无属性包装**。
  ⇒ 我上一轮在 `TipPrebattle_调用点.md` 写的「**只能来自存档/远端**」应**降级为「来源未证」**（要么 ILSpy 丢了写方法体，要么反射）—— **已在方案文件 §五·2 更正**。
- **其余「零出现」的字段**：脚本扫出 38 个（24 个 `public` 序列化字段 + 14 个 private），**但同一个 ILSpy 丢 setter/方法体的问题同样适用**，**不能当结论**，只能当线索。
