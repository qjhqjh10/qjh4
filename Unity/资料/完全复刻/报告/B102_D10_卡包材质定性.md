## 一、结论（一句话）

**不是 A，不是 B，也不是 C —— 是第四种：东西都进包了、PPtr 也按格式规则重映射了，但 Unity 运行时不认「同一个 bundle 里的兄弟 CAB」的引用。**

⇒ 合并**在运行时一点作用都没有**（那 200 个槽照旧 null），而且**顺手把 8 个本来指外部包的 shader 改写成了兄弟 CAB，把能用的那一路也掐了**（172 个坏 shader 就是它）。

两个数字**逐槽对得上**，这是本结论最硬的证据：

| 运行时读数 | 精确来源 | 数量 |
|---|---|---|
| 空材质槽 **200** | 16 个材质，全在 4 个新兄弟 CAB（`dup 100 + bs 49 + menu 17 + font 34`） | **200** ✅ |
| shader 坏 **172** | 主 CAB 里 8 个材质，`m_Shader` 被改写成指向兄弟 `CAB-boosterfxshaders`（`Embers 50 + Glow Rays UI 68 + Glow Additive UI 17 + Ring_Warped UI 31 + SmallDots 2 + spark_light 2 + SandParticle 1 + Waterfall_Noise 1`） | **172** ✅ |
| 正常材质槽 **189** | 指向主 CAB 内部（`m_FileID = 0`）的引用 —— **同 CAB 引用是好的** | 389−200 = 189 ✅ |

### 2.5 附带查出：`B97_W32` §四 的「200→0 / 8→0」是**错的尺子**

## 三、修法（可执行）

### 3.1 首选 **A：把 6 个小组各自打成【独立 bundle 文件】，运行时一起加载**（= 照原版分包）

**为什么选它**：原版自己就是「17 棵 prefab 在 `boosterpacks`、16 个材质在另外 4 个包」—— 引用形状就是 `archive:/<CAB>/<CAB>` **指向另一个 bundle**。这是 Unity 唯一被原版证明可用的跨包路（游戏能渲染卡包粒子就是证据），而本工程 `wf_shaders / wf_shaders_extra / wf_builtin / wf_tmp_shaders` 也全是这条路。改动面最小：`repack_tree` **已经**在临时目录里打好了那 6 个小包（`merge_imports_into_bundle` 的 `[M2]` 段），只是最后被并进了同一个文件。

**改哪一段**（`工具/extract_missing_shaders.py`）：

1. `merge_imports_into_bundle()` `:1122-1131`：
   - **不要** `bf.files[k] = v` / `keep.append(k)`（把兄弟 CAB 塞进产物）；
   - 改成把 `out`（那一份完整的小包，`UnityPy` 打出来的 `UnityFS`）**原样写到**
     `StreamingAssets/WarpforgeVFX/wf_booster_<组>.bundle`（`CAB-boostermatsdup` → `wf_booster_matsdup.bundle` …，6 只）。
2. `:1143-1179` 的**引用改写整段保留**（这正是跨包引用要的：`archive:/CAB-boostermatsdup/CAB-boostermatsdup`）。
3. `:1181-1189` 收口照旧（`keep` 只留主 CAB 的 `.resS`）。
4. 顺手把 6 个新名字（**小写**）追加进主 CAB 的 `AssetBundle.m_AssetBundleDependencies`（原版就是小写 `cab-*`；不改也能跑，但写对了更稳）。
5. `run_booster_mats()` `:1193-1211` 的 `--check` 打印里补一行「另外产出 6 只依赖包」。

## 四、风险

1. **跨 bundle 引用在【我们这个运行时】没有直接读数**。引擎级机制与原版相同、原版游戏就是靠它渲染卡包的（强旁证），但本项目从未断言过「加载 A 之后 B 的 PPtr 解得出」。⇒ 所以 **3.1 先跑探针**，别直接改运行时。
2. **可执行文件数量增多**：`StreamingAssets/WarpforgeVFX/` 多 6 只包（该目录 gitignore，新克隆/新机器必须本地跑一次 `--booster-mats`，这条既有规矩不变）。
3. **重名拒收**：6 只新包的内层名 `CAB-boostermats*` / `CAB-boosterfx*` 是**故意改过的**（避免与 `wf_shaders`=`CAB-805d8e…`、`wf_builtin`=`CAB-5ffb81…`、`wf_tmp_shaders`=`CAB-daee69…`、`wf_arena_shaders`=`CAB-68cc81…` 撞）—— ⛔ 别改回源包名。
4. **只动这一个产物**：`--prefabs` 会顺带重写 `wf_prefabs_extra` / `wf_menus_extra` / `wf_battleshared_extra` / `wf_mainmenu_extra` ⇒ 仍然只跑 `--booster-mats`（这条 `B97_W32` §七·1·2 已经立过）。
5. **同样的病还在 4 个产物里**（`B97_W32` §7.2）：`wf_menus_extra` 29 / `wf_prefabs_extra` 31 / `wf_battleshared_extra` 13 / `wf_mainmenu_extra` 58 个包内悬空槽 —— 修法一样，**但那些数字现在也得按「跨 bundle 可能是好的」重新定级**，别照旧账直接开工。
6. **shader 那一路的退化要单独注意**：即使材质这条换成 B/A，**把 8 个材质的 `m_Shader` 从 `CAB-805d8e…/CAB-5ffb81…`（运行时有包）改指兄弟 CAB，本身就是退步**。走 3.1 时它们会变成「指向另 2 只加载着的包」，OK；走 3.2 时要一起搬进主 CAB，别只搬材质。

## 五、还差什么（⛔ 没查清的部分）

1. **「加载着的独立 bundle 能被 `archive:/<内层名>/…` 解到」这件事，本项目没有一条直接断言** —— 3.1 的探针就是补它。这是整份报告里唯一「判据靠引擎常识 + 原版旁证」的一格。
2. **`--single-cab` 让 Unity 原生崩溃的机制没查**（`:588-596` 只有现象）。若 3.1 探针红、必须走 3.2，这一格得先查清（否则搬 5000 个对象前没有安全网）。
3. `贴图槽 799 · 空 726` 未逐条核（`an7.py` 离线数主 CAB 24 个材质的 `m_TexEnvs` 只有 139 条、未赋值 67 条 ⇒ 726 大部分应该是「shader 声明了但材质没赋」，属**正常的未赋值属性**，不是缺口；但这条**没在 Unity 侧验**，修完材质后要复测一次再定级）。
4. `B97W32Assert` 在本次运行里是**首次被执行**（`B97W32_Assert.cs:191-194` 记着「此前全仓 0 宿主」）⇒ 它在 `ShellScene` 里接得对不对、`OkCount/BadCount` 有没有并进 `_sink`，本代理**没核**（不在本件范围，但 4 红里有 4 条是真的，说明至少主断言跑起来了）。
