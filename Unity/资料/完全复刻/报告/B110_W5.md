### 每个 shader 的 9 项断言（`CheckEntry`）

1. 前提：`AssetDatabase.LoadAssetAtPath<Shader>(file) != null` → 失败**单独一条红**，直接返回（⛔ 不让 NRE 逃掉）
2. 名字：`loaded.name == 清单里的名字`
3. 前提：`Shader.Find(name) != null`
4. **结论（合并）：`ShaderOk(name)` = `Shader.Find != null && isSupported`** ← 灭自证锚点
5. 结论：`isSupported == true`
6. 结论：`ShaderUtil.ShaderHasError(sh) == false`
7. 结论：`sh.passCount > 0`
8. 结论：`new Material(sh).SetPass(0) == true`（洋红直接判据）
9. 进包：`/Resources/` 路径 **或** `AlwaysIncluded` guid **或** 被 `Resources/` 下的材质 guid 引用
＋ ⑨ 材质 guid：每份 `.mat` 的 `m_Shader` guid == 该 `.shader.meta` 的 guid

## 四、顺手发现

### ① 🟡 `WFUIBorderHighlight.shader` 不在 `Resources/`、也不在 `AlwaysIncluded`

- 位置 `Assets/WarpforgeVFX/Shaders/WFUIBorderHighlight.shader`（guid `8d5ed6ff6f6883649b60650e625a9160`）。
- `grep` `ProjectSettings/GraphicsSettings.asset` = **0 命中**（`m_AlwaysIncludedShaders` 共 44 条，没有它）。
- 生产代码对它**只有注释**（`Shell/CardDisplayEffects.cs:320` / `:460`），**没有 `Shader.Find`**；
  实际走 `Resources/Art/vfx/Border Effect For Level up.mat` 的 guid 引用 → **今天没缺陷**。
- ⚠️ **风险**：谁将来照 `ParentEventWindow.cs` 那套写一条 `Shader.Find("WarpforgeVFX/UI/UI Border Highlight")` 退路，
  **在 player 包里会静默拿到 null**（编辑器里一切正常）。
- 建议：要么把它加进 `m_AlwaysIncludedShaders`，要么在调用点旁边写死「⛔ 不许用 `Shader.Find` 取它」。
  断言里已按 `MaterialRef` 口径覆盖（会盯住这条唯一进包路径）。

### ② 🟡 判据文档 `B110_R2` 写「5 个新 shader」，实际是 **6 个**

`判据/B110_R2_小账时效复核.md:37`（§五②）与 `:97`（顺手发现⑦）都写「5 份 + `WFUIFxShine`」。

### ③ 🟢 全工程**没有重名 shader**

`grep -rhoP '^\s*Shader\s+"\K[^"]+' --include=*.shader | sort | uniq -d` = **空**。
⇒ `Shader.Find` 不会因为「两个 shader 同名」而拿到别人。

### ④ 🟢 `WFUIFxShine` 的两个 `shader_feature_local` 关键字**不会被剥掉**

- `WFUIFxShine.shader:89-90` 用 `shader_feature_local _ _USESCREENSPACE` / `_ _USETILEMASK`

- 实测 `WFUI_FxShine.mat:14-16` `m_ValidKeywords: [_USESCREENSPACE, _USETILEMASK]` ⇒ 两条都开着，**不会裁掉**。
- `WFUIAdditive.shader:94` 的 `multi_compile_local _ UNITY_UI_ALPHACLIP` 是 `multi_compile` ⇒ 两档恒编，无风险。
- 📌 记这条是因为：**`shader_feature_local` + 材质没开关键字 = 打包后静默丢段**，和洋红一样不报错。
