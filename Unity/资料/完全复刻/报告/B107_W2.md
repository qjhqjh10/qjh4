## ② A 段 —— 原版**没有** 60 下限（结论 (a)，已去掉）

### 判据链

1. **根上根本没有下限件**：`d:/2/tools/assetripper_out/ExportedProject/Assets/ChatMessageRow.prefab:3-16`
   —— 根 GO `1709254077376921` 的组件只有 **RT + `VerticalLayoutGroup` + `ContentSizeFitter` + `ChatMessageUI`**，**没有 `LayoutElement`**。
   （全 prefab 的 4 颗 `LayoutElement` 都在子件上：`RowBackground` 那颗 `m_IgnoreLayout: 1`（`:418`）、头/字那三颗 `m_IgnoreLayout: 0`。）
2. **CSF 只撑不夹**：同一 prefab 的 `m_VerticalFit: 1`（= `MinSize`，`:315`）⇒ 根高 = VLG 的 preferred，
   VLG `m_Padding L25/R60/T10/B10`（`:288-292`）· `m_Spacing: 12`（`:294`）· `m_ChildControlHeight: 0`（`:298`）· `m_ChildForceExpandHeight: 0`（`:296`）。
   参与布局的活子件 = **一个头（`m_SizeDelta.y = 25`）+ `Message`**（`Message` 自带 `CSF m_VerticalFit: 2 = PreferredSize`，`:1616`）。
   ⇒ `h = 10 + 10 + 25 + 12 + 正文高 = 57 + 正文高`。
3. **空正文的正文高 = 0**：TMP 的 `CalculatePreferredValues` 对空串**早退**（`d:/4/Unity/MyGame/Library/PackageCache/com.unity.ugui@27635d171b1a/Runtime/TMP/TMP_Text.cs:3901-3905`
   —— `m_TextProcessingArray == null || Length == 0 || [0].unicode == 0 ⇒ return Vector2.zero`）⇒ 空正文行 = **57**。
4. **空正文行真的会出现**：`Shell/SocialData.cs:324` 的 `default: return "";`（= 原版 `ChatMessageData.GetMessage` 同形分支）
   —— `Practice` / `Rally` / `RewardShare` / `ReplayShare` 这类「没有模板」的类型正文就是空串。
   ⇒ 我们原来那层 `Mathf.Max(60, …)` 会把它们撑成 **60（比原版高 3px）**，是**玩家看得见的偏差**，不是死边角。
5. `_DefaultItemSize = 60` **不是**原版行高真值：它是 OSA 的占位估计，且 `_PrefabControlsDefaultItemSize: 1`
   （`assets_full/bundle_mainmenualwaysloaded_assets_all/MonoBehaviour/MonoBehaviour_-8786325734254409834.json`）运行期会被 prefab 覆盖。
6. 原版确实把量出来的行高回灌给列表：`decomp_full/ChatEntryView__MarkForRebuild.c`（`CSF.enabled = true`，twin pass 前重开）
   + `ChatContentView__UpdateViewsHolder.c` / `ChatContentView__OnItemHeightChangedPreTwinPass`（`B106_D4` §0 判据 4 已记）。
