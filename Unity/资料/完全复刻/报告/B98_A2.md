## 三 换算推导（为什么是 `× qk`，而不是原数）

```
qk   = label.FontSizeToPxNow(1f, label.ActualFace)
     = 1 × TmpFont.EmPerFontSize(face) × PxPerUnit × (_ugui ? 10 : 1)
     ⇒ uGUI：CJK 0.0948×10 = 0.948 · 拉丁 0.1×10 = 1.0          （Label.cs:1066-1085）

SetAutoFitBox(w, h, minPx, maxPx, basePx) 内部（Label.cs:1369-1376）：
    cur      = TmpFontSize()                                    // 标称字号，**不含**自适应结果
    nomPx    = NominalPx() = FontSizeToPxNow(cur, face) = cur × qk
    fontSizeMax = cur × (maxPx / nomPx) = maxPx / qk
    fontSizeMin = cur × (minPx / nomPx) = minPx / qk
    baseCur     = cur × (basePx / nomPx) = basePx / qk          // 经 fontSize setter 回写 m_fontSizeBase（早退回退到 EnsureFontSizeBase）

⇒ 要落成原版 18 / 40 / 36，实参必须是 18×qk / 40×qk / 36×qk（= 17.06 / 37.92 / 34.13 @CJK-uGUI）。
⇒ 直接传原数会整体 **偏 1/0.948 = 1.0549 倍**（min 落成 18.987）—— 正是 B 段 B4/B5 断的那件事。
⚠️ `cur` 在式子里**约掉** ⇒ 与 `HudCanvas.MakeText(..., scale: 2, ...)` 那个 `scale`、与标签建时的
   `_glyphHeight`/`CapWorld` **全都无关**（⛔ 别去「修」那个 `2`：它是点阵后端的档位，TMP 档用不到）。
```
