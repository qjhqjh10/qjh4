## §二 关键结论与证据

### 1. T21 —— 反证：施工单指的落点不在执行路径上（⛔ 没有照做）

施工单 §一 T21(B) 写：「`PlayPlacedOne:24099` 的 `e.Slot<0` 分支里……降级到 `createCardPos(140)`」。现读证据链（**五跳**）：

1. **手牌陷阱的 trigger 事件 `Slot` 恒 `-1`**：`RuleEngine/Core/EffectResolver.cs` 的 `EmitCardTrigger`（现读 `:8344`）——
   `int slot = -1, p = owner; if (unit != null && FindSlot(...)) {...}`；手牌卡**没有 `UnitState`** ⇒ `unit == null` ⇒
   `ctx.Emit(EvtKind.Trigger, p, **-1**, ...)`。
2. `BattleDriver.PlaySignal` 的 Trigger 支（现读 `:23228`）只处理 `UnitAttack` canonical；手牌陷阱走不到那里。
3. `TryHudAnchor`（`:24735`）只认 `IsHudAnchoredEvent` = **资源三件 + Draw**（`:24697`）⇒ Trigger 不是 HUD 锚事件。
4. 于是落到 `int slot = e.Slot`（`-1`）→ `if (slot < 0 && e.Kind == EvtKind.Play)`（`:23282`）不成立 → **`if (slot < 0) return;`（现读 `:23300`）**。
5. `PlayPlacedPieces` 只有 3 个调用点（`:23291`=Play/非单位、`:23397`=play\|trigger 且 `slot>=0`、`:24134`=阵亡）⇒
   **`PlayPlacedOne` 永远拿不到「Trigger + `Slot<0`」**。

⇒ 结论：**那 4 张手牌陷阱（`Jammed Communications` / `Master Interromancer` / `Cult Propaganda` / `Poisoned Supplies`）
的 `sp=0 self` 动画今天一次都不播**。只按施工单改 `PlayPlacedOne` = 改一段**永远不会执行**的代码（本仓红线：
「调用写在 `//` 之后 = 从来没执行」的同族错误），而且会让人误以为这一条已经复刻。

**真修法（供调度台另立一笔 / 另派）**：在 `PlaySignal` 里给「`EvtKind.Trigger` ∧ `Slot < 0` ∧ 卡在手里」开一条**新手牌锚**路
（锚 = 该卡的手牌 `CardView` ⇒ `EffectAnchor(false)` = `2DCard`；对手那侧 `_foeHandViews` 是**卡背 `ImageQuad`**、没有 `CardView`
⇒ 只能退手牌容器 `AnimAnchors.HandAnchorOf(seat)`）。它要动 `PlaySignal` 的早退判定 + `PlayAbilityBeat` 的锚点口，
**不是「方法内改、零行数变化」**，超出本件白名单口径 ⇒ 停手交回。
