## 一、工具用法

### 三种模式

| 模式 | 命令 | 干什么 |
| --- | --- | --- |
| `--list` | `--list [--grep HUD]` | 列出 `Assets/**.prefab` + `.unity`（根 = `d:/2/tools/assetripper_out/ExportedProject/Assets`） |
| `--list-src` | `--list-src <源> [--root 子树名]` | 读一份源、打印根节点；给了 `--root` 就把那棵子树的节点逐条列出来（**找准确名字用这个，⛔ 别按猜测 grep**） |
| 真 diff | `--orig <A> --ours <B> --out <tsv>` | 见下 |

### 真 diff 的完整参数

```
--orig   <yaml>           原版侧：.unity / .prefab / .asset
--root-orig <名字>        原版侧子树（不写 = 整份必须只有 1 个根）
--ours   <yaml|tsv>       我们侧：同上，或 SceneJumpShot 运行时 dump 的 .tsv
--root-ours <名字>        不写就沿用 --root-orig
--out    <tsv>            输出表（7 列）
--summary <md>            额外落一份摘要（可选）
--dry                     只打印摘要、不写盘
--only-diff               只写「不一致 / 仅原版有 / 仅我们有」（把「一致」和 `?` 滤掉）
--props all|default|a,b,c 默认 = `DEFAULT_PROPS` 里「两侧都能给值」的那些
--tol <浮点>              数值容差，默认 0.06（dump 的 ap/sd 只有 1 位小数 ⇒ 舍入误差 ≤0.05）
--ours-dead-cols <列>     我们侧这个源里**已知不可用**的列，默认 `fontSize,text`（记 `?`，⛔ 不记不一致）
--no-pair-dups            关掉同名兄弟的内容配对
```

### 安全（照本工程踩过的坑）

* **裸跑 = 打印用法 + `rc=2`，一个字节都不写**（先例：写盘脚本裸跑真写盘，冲掉 232 行手工修订）。
* `--help` = 打印用法 + `rc=0`。
* `--dry` 只预览。**真写盘必须同时给 `--orig / --ours / --out`**，缺一个就是 `rc=2`。
* 读文件一律 `io.open(p,'rb')` 二进制读（自处理 BOM / `\r\n` / 裸 CR）。写文件固定 `newline="\n"`。
* 只读输入，只写 `--out` / `--summary` 两个路径。

### 输出 TSV

`层路径 | 属性 | 原版值 | 我们值 | 判定(一致/不一致/仅原版有/仅我们有/?) | 原版出处 | 我们出处`

`?` 的定义是**「一侧或两侧查不到这个属性」**，⛔ 不是「不一致」，⛔ 也不是「一致」。

## 二、输入格式踩到的坑（每条都有实据）

### dump（`runtime_ui_dump_*.tsv`，SceneJumpShot v3.6）

1. **`path` 列装的是【父节点的全路径】，不是自己的全路径。**
   判据 = `d:/2/Warpforge_tools/scenejumpshot/SceneJumpShot.cs` 的 `DumpGo`：写出的是传入的 `path`，
   而递归给子节点传的是 `path + "/" + go.name`。
   ⇒ 自己的全路径 = `path 列 + "/" + name 列`；根行没有父（`path == name`），全路径 = `name`。
   判定法：**「这一行的 path 是不是某个已见节点的全路径」—— 是就有父，不是就是根**（DFS 序下确定）。
   第一版按「path 就是自己的路径」写 ⇒ 子树直接取错，`BattleHud` 选到了 `BattlePrefab/BattlePrefab`。
2. **表头错位且缺列**：写 11 列，真实 **15** 列。真实顺序（照 `DumpGo` 的拼接顺序）：
   `path / name / activeSelf / activeInHierarchy / rect(RT|TF) / anchoredPosition / sizeDelta / anchorMin / anchorMax / pivot / "TXT"标记 / text / fontSize / "IMG"标记 / sprite`。
   表头里那三列 `rect / pos / pivot` **不是**这三个东西。工具**不看表头**，按真实列序读，并在摘要里打印「表头 ⚠️ 错位」。
3. **TXT 那一组整组失效**：本文件 **324/324 个 TMP 节点的 `text` 全空、`fontSize` 全 `0.0`**（IMG 那组是好的，301 个 sprite）。
   根因**高置信推测**（未在运行时验证）：`DumpGo` 用 `st.GetField("m_text")` / `GetField("m_fontSize")`，
   而这两个字段声明在**基类 `TMP_Text`** 上，`GetField` 不爬基类 ⇒ 两个都返回 null ⇒ `text=""`、`fontSize` 落到 `0.0`。
   要修就在 dump 端用 `FlattenHierarchy` 或沿 `BaseType` 找（本次**不改 mod**，只把结论记在这里）。
4. dump **不写** `localPosition / localScale / localEuler / fontColor / imageColor / imageType / renderQueue / raycastTarget / sortingOrder`。
   工具的处理：**某属性在某一侧整列都查不到 ⇒ 两个源不具备可比性，默认不展开**，并在摘要里点名（⛔ 不静默丢）。

### Unity YAML（AssetRipper 导出）

5. **没有任何嵌套 prefab**：`grep -rl "^--- !u!1001"` 在 **1,389 个 prefab + 17 个场景里 0 命中**（已全部展开）⇒ 不需要处理 `PrefabInstance`。
6. **场景里 GameObject 与 Transform 一一对应**：`Battle Arena 1.unity` 有 1,224 个 `!u!1`、988 个 `!u!224` + 236 个 `!u!4` = 1,224。
   根 = `m_Father: {fileID: 0}` 的 Transform，共 **3** 个（`Scenario` / `PlayFabHttp` / `BattlePrefab`）。
7. **兄弟序只能按父的 `m_Children` 算**（Unity 2023+/6 已删 `m_RootOrder`，那字段现在恒 0）。
8. **uGUI 组件也是 class `!u!114` MonoBehaviour**（`Image` / `TMP` / `Button` 全是）。
   guid → 类名要扫 `.cs.meta`：`ExportedProject/Assets`（2,644 个）+ `_tmp_view/orig_ui_proj/Library/PackageCache`（3,729 个）= **5,631** 条。
   ⚠️ **TMP 不在单独的包里** —— 在 `com.unity.ugui@27635d171b1a/Runtime/TMP/`。
9. **还是有认不出的 guid**（例：`67dfb1fdfb2b407222eda8e23ac8b724` —— 一个带 `m_text` 的自定义类）。
   ⇒ 分类**按字段签名**，⛔ 不按 guid 猜：有 `m_text` ⇒ 文本组件；有 `m_Sprite` + `m_Color` ⇒ Image 组件；guid 只用来打**标签**。
10. **自写迷你 YAML 解析器踩了一脚**：`m_Component:` 后面紧跟**同缩进**的 `- component: {fileID: X}`。
    第一版把「空值键 + 同缩进的 `- `」当成空串 ⇒ **整份文件的 `m_Name` / `m_Father` 全丢**，1,224 个节点全是根、名字全空。
    判据：空值键的下一行**缩进更大** ⇒ 子映射；**缩进相同且以 `- ` 开头** ⇒ 序列；否则才是空串。

### 比对规则上的坑

11. **子图命名**：AssetRipper 导出的 atlas 子图叫 `X_0`，运行时 `sprite.name` 是 `X`。
    ⇒ 只允许**一侧**去掉 `_<数字>`。**两侧都归一**会把 dump 侧的真名字也剥掉，于是像
    `40K_shop_offer_bg_Sororitas_0_2`（静态）vs `40K_shop_offer_bg_Sororitas_0`（运行时）这种**同一张图**
    被误判成「不一致」（实测 1 条）。最终规则：`a == b` 或 `norm(a) == b` 或 `a == norm(b)`。
12. **内置 sprite**（guid `0000000000000000…`）名字表本地没有 ⇒ 记 `(内置:<fileID>)`，判定记 `?`，⛔ 不猜名字。
13. **同名兄弟不能按次序配对**（本工程已知坑：AssetRipper 会重排子节点）。
    本场景 `Glow Orange` 有 **4 个**，静态与运行时的次序**不同** ⇒ 按次序编 `#k` 会凭空刷出 4 条「不一致」+ 4 条「仅原版有」。
    工具做法：同名组**两侧个数相同**时按「字段差数最小」贪心配对（`_pair_cost` 只看两侧都有值的属性），再重编号；**个数不同就不配**并在摘要里出声。
14. **dump 侧的路径会撞**：同名兄弟在 dump 里 `path` 完全相同 ⇒ 第一版用 dict 索引时**静默丢了 17 个节点**（1100 → 1083）。
    修法：dump 侧也按父的 children 序加 `#k`，与 YAML 侧同一规则。
15. **「我们侧已知不可用列」必须显式声明**，否则 `fontSize` 会刷出 319 条假「不一致」。默认 `--ours-dead-cols fontSize,text`。

## 四、还差什么（如实写）

### ① 我们侧**没有**可机读的树 —— 这是最大的缺口

* 简报把 `runtime_ui_dump_*.tsv` 写成「我们的侧」，**实际它是原版游戏自己的 dump**（SceneJumpShot 是原版 mod）。
* 我们的战斗 HUD **不在任何场景文件里**：`CardPresentation/Scenes/Battle.unity` 只有 **31 个 GameObject**（2 个根：`Battle` / `Main Camera`；内容 = Slots / PlayerBoard / EnemyBoard / AttackSelector / SkillPanel / Arena3D / 相机），
  而 HUD 是**运行时由 `.cs` 建的**（`grep -rn BattleHud --include=*.cs` = **576 处**）。
* 我们的工程里也**没有** HUD 的 prefab / 树 dump 产物。
⇒ **真「原版 ↔ 我们」表还差一份我们侧的树**。两条补法（都很便宜）：
  1) **加一个 dump 宿主**（编辑器侧跑一遍 `BattleScene.BuildFor…` 之后 DFS 吐同样 15 列的 TSV）——工具已经能吃 `.tsv`，一条命令就出真 diff，**不需要改工具**；
  2) 或者把现有 dump 修好（`GetField` 用 `FlattenHierarchy`）再重跑一次原版，先补齐 `text` / `fontSize` 两列。

### ② 本次比不了、必须承认的边界

| 项 | 状态 |
| --- | --- |
| `text` / `fontSize` | dump 侧整列失效（见坑 3）⇒ 本次**一条文字都没比过** |
| `localPosition` / `localScale` / `localEuler` | dump 不写 ⇒ 本次未展开（`--props all` 可强制展开，但全是 `?`） |
| `fontColor` / `imageColor` / `imageType` / `renderQueue` / `raycastTarget` / `sortingOrder` | 同上；这些**只能靠 YAML ↔ YAML** 比（两侧都是我们/原版的场景文件时才有意义） |
| 运行时状态 | 静态 YAML 与运行时 dump 天然不同态 ⇒ 这张表**不能当缺陷表**用 |
| `localEuler` 的口径 | 用 `m_LocalEulerAnglesHint`（编辑器显示的那个）；本场景实测与四元数一致（例 `CardsInHandText` hint x = 0.09995°，四元数换算同值） |
| 多根场景 | 不写 `--root-*` 时要求整份只有 1 个根；`Battle Arena 1.unity` 有 3 个根、`Battle.unity` 有 2 个 ⇒ 必须给子树名 |
| 名字含 `/` 的节点 | 会把路径切错（本场景没出现）；工具未特殊处理 |

### ③ 工具本身还没做的（都不影响本次结论）

* 不支持嵌套 prefab（本导出 0 例，所以没做）。
* 不做像素级比对（只比字段，不比渲染图）。
