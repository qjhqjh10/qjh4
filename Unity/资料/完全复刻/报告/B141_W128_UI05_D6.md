## 二、新存档 JSON 形状（样例）

`<SaveRoot>/WarpforgeSave/PlayerDecks.json`（`SaveCenter` 的信封 `_v` 是最外层，payload 内**不再有 `current`**）：

```json
{"_v":3,"version":1,"decks":[
  {"Name":"甲","WarlordId":"UM1","DefensiveId":"DEF","CardIds":["C1","C2"],
   "GameMode":0,"CardbackId":"","WarcryId":null,"DeckArmy":null,"DeckId":"8f0c…（32 位 hex）"}

```

`<SaveRoot>/WarpforgeSave/CurrentDeck.json`（**卡组 id 字符串**；本地包一层对象，见 §五·方案）：

```json
{"_v":1,"id":"8f0c…（32 位 hex）"}
```

旧形状（**仍可读**）：`{"version":1,"current":1,"decks":[…]}` —— `DeckStore.Parse` 照旧返回 `current:int`；只有 `ReadCurrentDeckText` 接上之后才会被 `CurrentDeck` 覆盖。

## 三、旧档迁移路径

1. **运行期（首选）**：`DeckLibrary` 记住旧 `_current`；下一次 `Save()` 时 `EnsureCurrentDeckIdInMemory` 给当前那套补 `DeckId`（只改内存）→ `PlayerDecks`（无 current）与 `CurrentDeck`（id）同一次写盘。旧 payload 被新 payload 覆盖，`current` 自然消失。
2. **启动导入（`LegacySaveReader.ImportDecksFile`）**：旧 `WarpforgeDecks.json` →
   - `PlayerDecks` 写 `DeckStore.SerializeStore(decks)`（**新形状**，当前那套若没 id 现发一个）；
   - `CurrentDeck` 写 `DeckStore.SerializeCurrentDeck(curId)`（旧 `current` **下标 → id**）；
   - 两个 key 各自「已有就不覆盖」（红线：不覆盖玩家已有中央档）。
3. **回滚**：旧文件 `WarpforgeDecks.json` 一个字节没动；但它作为**镜像**以后不再含 `current`（见 §六·①）。

## 五、`CurrentDeck` 的承载方案（为什么不改 `SaveCenter`）

原版 `CurrentDeck` 的载荷是**裸字符串**；`SaveCenter.SetRaw` 只收 **JSON 对象**（`SaveCenter.cs:305-315`，`SaveThroughLegacy` 同 `:1104`）。
⇒ **选择「包对象 `{"id":"…"}`」**（不改 `SaveCenter`）：

- 本地承载不同，但 **key 名 / 语义 / 值（卡组 id 字符串）都照原版**；`ParseCurrentDeckId` 同时接受**原版裸 JSON 字符串** `"…"`，所以将来若有原版数据直接喂进来也能读。
- 代码里已按铁律 18 打 `🔶 自己设计（非原版）`（为什么必须自定 + 调度台 2026-11-04 裁定）。
- ⛔ 另一条路（给 `SaveCenter` 加标量口）会改信封形状（`{_v:N, value:…}`），影响所有 key，**不做**。
