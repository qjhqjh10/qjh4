## 一 · A：`normalAbilityBoardCriteria` 全池物化

### A1 结论：**是**，全池级

`CardDto.normalAbilityBoardCriteria` 是 `[System.Serializable]` 类字段（`CardDatabase.cs:607`，类型 `AbilityGateDto` = `:658`）。
`JsonUtility.FromJson` 对**缺键的可序列化类字段会物化出一份对象，不是 `null`**（本项目已实测两次：`B100_F10_Assert.cs:72-77` 的 A1/A2、
`B100_X3` #17 的「期望 True 实得 False」；记忆 `jsonutility-null-subtree`）。
⇒ `CardDatabase.MapBoardGate` 里 `if (d == null) return null;`（`CardDatabase.cs:2477-2478`）**这一支恒不成立**，1127 张全部落成非 null。

### A2 张数（两把尺子，互相对得上）

| 尺子 | 读数 |
|---|---|
| **数据层**（`cards_engine.json` 现读，`count`=1129） | 只有 **`SW9`（Fenrisian Wolf）/ `SW21`（Wulfen Pack Leader）** 有 `normalAbilityBoardCriteria` 键；**1127 张没有** |
| **运行时实测**（`_tmp_view/b100g_ruleengine.log` 里按 id join 回池） | 报 `normalAbilityBoardCriteria.countOptions 缺键` 的池内卡 = **1127 / 1129**；**唯二没报的正是 `SW9` / `SW21`**（另 19 张是合成夹具卡，见 `B97W5GateC` / `E9ProbeTa30` 等） |

取数办法：`grep "normalAbilityBoardCriteria.countOptions 键"` 的行按 `（id）` 抽出，与 `cards_engine.json` 的 1129 个 id 求交 —— 交 1127，`pool - ids` 恰为 `['SW21','SW9']`。

### A3 三个字段的实读值：**全 `Unknown(-1)`**

直接证据 = **`B97W5 闸探针C`**（就是 A5 那张合成卡）在同一次日志里的四条 `[RuleEngine] … 缺键/没有…`：

**机制链（为什么是 -1 而不是 0）**：`AbilityGateDto` 的三个 int 字段初值就是缺键哨兵 `MissingIndex = -99`（`CardDatabase.cs:662/664/666`）；

`countSet` 那个 `CountSetDto` 没被物化（实测 `MapCountSetDto` 收到 null ⇒ `CardDatabase.cs:2387-2393` 落 null + 出声）。

**旁证（这条很重要）**：同一文件的 A4（同一个 `AbilityGateDto`，只是缺 `conditionsFilter` 一个子键）在日志里是**绿**的 —— 说明「`JsonUtility` 为它构造出来的嵌套对象**跑了字段初始化器**」，所以 `-99` 哨兵链成立。

### A4 后果

1. **断言 `B97W5_Assert` A5 测的是一条不可能成立的设计** ⇒ 该条判 **α**（改断言，不改产品）。A5 日志 `:332527`（与 `:354664` 汇总重印）：「期望 [True]，实得 [False]」。

3. **契约失效**：`NormalAbilityBoardCriteria == null` 从此**恒假**。而 `CardDef.cs:258-260` 的 doc 与 `CardDatabase.cs:2477` 的注释都写着「`null` = 原版那个恒真的默认 criteria」⇒ 任何「这张卡有没有这条闸」的 `!= null` 判断都是**死判据**。

   ⇒ 所以**行为上无误**，错的是「数据形状 / 日志 / 判据契约」，不是结算。

### A5 修法方向（只给方向，不动手）

## 二 · B：#26 / #64 的真根因

### B1 一句话根因

- **#26（`B98G6` A10）**：夹具卡是裸 `new CardDef(...)`（`B98G6_Assert.cs:412` 的 `Unit()`），**从来没挂 `cardTraits`**；而 `TargetCriteriaEval.RawCardMeetsTraitCriteria` 在 `traitsFilter == 0` 短路**之前**先无条件查 `HasDefaultTrait(summonRift)`（`TargetCriteriaEval.cs:1035-1037`，该次序 = 原版 `FilterMethods__RawCardMeetsTraitCriteria.c:12-73` 的①②③次序，**故意照抄**）⇒ `_cardTraits == null` ⇒ `why = CardTraitsWhy` ⇒ gap。
- **#64（`RuleEngineTest_EngineB94F1.cs:101`）**：断言写于 2026-10-29 `cef436cd`，期望「手牌打出 `oath` 卡**再付一次**」；但同一天 `B96_OATH` 按原版把**两个手牌出牌**的 `PayCardPlayedCostOath` 调用点删掉了 —— 现在 `PlayCard` 只收卡费（`RuleCore.cs:3955` 的注释就写着「⛔ 别在这里加誓约费」）⇒ 3 − 1 = **2**。
