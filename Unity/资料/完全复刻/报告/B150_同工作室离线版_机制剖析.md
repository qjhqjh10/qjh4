> 调查方式：**纯静态阅读**。全程未执行包内任何 `.cmd` / `.exe` / `python.exe` / `start_offline.py`，未加载 Frida，未 attach 游戏，未修改 `E:/2hhl` 任何文件。

## 1. 一句话结论

这是**「原版客户端零改动 + 进程内运行时拦截」**方案：自带 Python 3.13 启动器用 **Frida 以挂起态 spawn 原版 `HorusHeresyLegions.exe`**，在 `il2cpp_init` 返回后用 **IL2CPP C API 按类名/方法名现场解析**出函数地址，逐个 `Interceptor.replace/attach`；同时**在 `ws2_32.dll` 层把出站 socket 全部打死**，于是原版的 PlayFab/Photon 链路根本发不出包。**联机、局域网、合作、账号这些「服务器功能」全部搬到进程外的 Python 里自建 JSON-over-TCP/TLS 协议**，再通过 Frida 的 `send`/`recv` 与游戏内 `BattleCommsManager` 的收发口对拷。客户端 44 个文件里**只有 `app.info` 与 `globalgamemanagers` 两个被改**（后者改了公司/产品名和 Unity `bundleVersion`），其余（含 `GameAssembly.dll`、`global-metadata.dat`、全部 `.assets`、`localbundle`）**与原版逐字节相同**。

### 2.2 注入点：等 `il2cpp_init` 返回

`probe.js` 末尾注册 **模块观察器**；当 `gameassembly.dll` 载入时，挂在导出函数 `il2cpp_init` 的 `onLeave` 上，**IL2CPP 运行时初始化完成的那一刻**才安装全部钩子：

- `OfflineLab/analysis_runtime/probe.js:2644-2690`（`Process.attachModuleObserver({onAdded(m){ … }})`）
- `probe.js:2688-2690`（`if (n === 'gameassembly.dll') Interceptor.attach(m.getExportByName('il2cpp_init'), {onLeave(){ installIL2CPP(m); }})`）

### 2.3 找函数的方式：不写死地址，走 IL2CPP 元数据

`installIL2CPP`（`probe.js:19-70`）先 `il2cpp_domain_assembly_open('Assembly-CSharp')`，再包一层 `klass(name)` / `method(class,name,paramCount)`：

- `probe.js:22` 全部 `il2cpp_*` 导出用 `NativeFunction(..., {abi:'mscdecl'})`
- `probe.js:56-57` `assembly_open('Assembly-CSharp')` + `class_from_name(ns='', name)`
- `probe.js:59-70` `method()` 按 **类 + 方法名 + 参数个数** 取 `MethodInfo`，再 `mi.readPointer()` 才是函数体地址

所以**绝大多数钩子的「目标」是（类名, 方法名, 参数个数）三元组，不是偏移**——这是它能在小版本间迁移的根本原因。**只有 3 处**用了裸 RVA，而且**每一处都自带指令字节自检**（见 §3.3）。

### 2.4 进程启动参数

- 正常单机：`-screen-fullscreen 0 -screen-width 1280 -screen-height 720 -logFile <output_dir>/unity_probe.log`（`probe.py:83,91`）

### 3.4 是「改字节」还是「替函数」

- **没有一处修改磁盘上的二进制**（§6 已用全量哈希证明）。
- **只有两处用 `CModule` 手写机器码桩**（走 `Interceptor.replaceFast`）：Steam 空桩（`probe.js:135`）与 Blast 过滤器（`probe.js:814-825`）。其余全是 Frida 的 `Interceptor.replace`（函数入口跳板，跳进 NativeCallback）或 `attach`（旁路读写参数/返回值）。
- **大量「写内存」发生在托管对象字段上**（例：`playerObject.add(0x304).writeS32(30)` 把 Elo 直接改成 30 绕过教程、`self.add(0x41).writeU8()` 切金卡、`match.add(0x10).writeS32(1)` 改对局类型），这是**运行时改状态**，不是改代码。

## 4. 网络伪造层

### 4.1 两条完全不同的路径

**(A) 原版自身的服务器功能：直接掐死，不伪造**

- 出站 socket 被 `ws2_32` 钩子打成 `-1`（`probe.js:2662-2668`）→ PlayFab / Photon / 资源下载**一个包都发不出去**。
- 上层再加语义级空桩：`LoginManager.Start`（`probe.js:152`）、`NetworkCustomManager.StartConnection`（`:268`）、`PlayerDataManager.IsLoggedIn` 恒真（`:265`）、公告/任务刷新置空（`:156-162`）、Steam 全关（`:140-144`、`:2686`）。
- **不是**「本地起一个假 PlayFab/HTTP 服务」，包内也没有任何 HTTP 反向代理或 hosts 改写（`局域网对战说明.md:14` 明确「无需修改 hosts 或系统代理」）。

**(B) 他们自己的联机：进程外自建，游戏内只做「动作结构体对拷」**

- 网络 I/O **全部在 Python 启动器进程里**（`lan_transport.py` / `online_transport.py` / `tls_pump.py`），游戏进程只通过 Frida 的 `script.post` / `recv('lan'|'gr_coop')` 与 JS 通信。
- 游戏侧把 `BattleCommsManager` 的 `Send*` 换成「发一条 JS 消息」，把收到的消息**回调进原版的 `ReceivePlayerAction` / `ReceiveEnemyMulligan` / `DisplayChatMessage` …**（`lan_runtime.js:342-359`），所以**规则、结算、动画全部是原版的**，只有「消息从哪来」被换掉。

### 4.3 消息类型（原文）

**对战中继（online_transport / lan_transport）**

- 客户端→服务器：`{'type':'online','protocol':1,'build':<构建指纹>,'op':'list|host|join|match'}`（online_transport.py:124-142）；`{'type':'game','message':{...}}`（lan_transport.py:82）
- 服务器→客户端：`rooms`（房间列表，最多 32）/ `waiting`（等待，房间号 16 位 hex）/ `start`（players + local + first + seed + room + latency）/ `game`（按 `seq` 严格递增）/ `ping` / `latency` / `leave` / `reject`（online_transport.py:145-206）
- 游戏动作消息体：`kind` ∈ {`mulligan`, `mulligan_ack`, `action`, `chat`, `seen`, `reorder`, `forfeit`, `finished`}；`action` 字段固定为 `typ/act/tget/tgtd/pos/num/ts`（lan_transport.py:106-124）

**账号（同一端口，`op='account'`）**

- `{'type':'online','protocol':1,'build':…,'op':'account','action':…}`，`action` ∈ {`apply`（申请）、`login`、`state`、`logout`、`password`、`friend_*`、`block_*`、`duel_*`}（online_transport.py:23-36；online_accounts_runtime.js:36,149-165,253-305）
- 账号状态：`pending / active / rejected / suspended / deleted`（online_accounts_runtime.js:9），令牌是 **43 字符 URL-safe base64**（`:22,65`）。

**合作（protocol v2）**

- `{'op':'hello'|'leave'|'plan'|'state'|'clock'|'action'|'proposal'|'commit'…, 'protocol':2, 'build':…}`；宿主权威（server.py:1-5），其余人只提交**合法动作参数**（`kind:'native'` + `args` + `targeted` + `slot`），**永远不在客机上跑原生代码**（protocol.py:90-113）。

### 4.4 「在线服务器已内置」到底是什么

- **地址内置**：默认端点硬编码为 `tls://play.erwinthhl.ink:26837`（lan_runtime.js:20），用户可在「在线账号 → 服务器地址」改；用 `profile/online-settings.json` 持久化（lan_runtime.js:28-45）。
- **服务器本体不在包里**：`在线联机说明.md:20` 原话「本包不含服务器或后台管理器。管理后台由管理员独立维护」。`使用说明.txt:9` 的「内置」= 不用填地址，不是打包了服务端。
- 包里**唯一**的服务端代码是 `great_rebellion/coop/server.py`，且它只在「局域网合作当房主」时**在启动器进程内**起一个 `127.0.0.1:26839` 的 `CoopServer`（client.py:99-107）。

### 4.5 版本互斥（V2.2 不能与 V2.3 互连）是怎么实现的

**不是比对显示版本号，而是比对「构建指纹」**——指纹覆盖源码本身，任何一行代码不同就不互认：

| 层 | 算法 | 证据 |
|---|---|---|

## 5. 数据与存档

### 5.1 卡表 / 活动 / 商店数据的来源：**(a) 从原版包里挖出来的原版 AssetBundle**

- `OfflineLab/assets/` 有 **102 个 `UnityFS` 包，共 977 MB**（实测；`package_manifest.json` 的 `resource_bundles` 也记 102，`assets.json` 数组长度同为 102）。
- 目录 `assets.json` 每条 = `{name, id, version, path, size}`，`id` / `version` 就是原版远端资源包的命名（例：`assets_betagarmon_ba` v2、`assets_betagarmon_events` v10、`scriptable_objects` **v3580**）。
- **卡牌定义**在 `scriptable_objects` v3580（6.1 MB）里，游戏内路径是 `assets/remoteassetbundles/...`（probe.js:882 直接 `LoadAsset("assets/remoteassetbundles/eventdecks/…/soh2_tybalt_deck3.asset")`），`art_index.json` 的 13,073 条也全是 `assets/remoteassetbundles/...` 内部路径。
- `package_manifest.json` 记为 `definitions_version = 3580`、`game_version = 3.7.3`、`offline_version = 2.3`。
- **不是**「他们重建的 JSON」，也**不是**「让客户端回退默认」——就是原版远端包本体，只在加载口被换成本地文件。
- 所以原版的**活动/商店/远征等“服务器数据”**要么本来就在这些包里（卡池、外观、预组），要么根本没有（在线商店目录、LiveOps），后者**直接不做**：`probe.js` 全文搜不到 `ClickShop` / `ClickForge` 的接管（`great_rebellion` 只在 `ClickEvents`/`ClickShop` 上挂了一个「顺带关闭远征页」的旁路，native_ui.js:443-444）。

### 5.2 资源装载链

1. 启动时先手动把 `scriptable_objects` 载入并塞进 `AssetBundleManager` 的缓存字典（`probe.js:863-876`）。
2. 之后所有 `GetLoadedBundle(key)` 未命中都被拦截，把 `PCWin/` 前缀剥掉后在 `assets.json` 里找，`AssetBundle.LoadFromFile` 本地包后**写回原版的 link 字典**（`probe.js:194-210`）。
3. 语音/立绘的**散件**（不在已加载 bundle 时）按 `art_index.json`「名字 → [bundle, 内部路径, 类型]」按需补（`probe.js:234-262`）。

### 5.3 存档

- **格式**：`OfflineLab/profile/decks.json`，JSON：
  `{version:1, decks:[{name,id,prebuilt,badge,cardback,warcry,avatar,hero,heroAlt,carapace,rightArm,leftArm,cards[],premiumCards[],tag,premiumHero,premiumPilot}], current:"", profile:{displayName,badge,avatar,warcry,cardback}}`（probe.js:507-527；校验器 offline_save.py:10-40）。
- **不是「仿制原版服务端存档」**，而是**把原版内存里的 `PlayerDataManager` 卡组列表序列化下来**：卡 id 是 32 位 hex 的 `RawCardScript` 主键（`serializeDeck` 读 `rawCard.add(12)` 的 string）。
- **原子写 + 双份**：先写 `.tmp` → `fsync` → `replace`；旧文件验证通过才提升为 `.json.bak`；坏了就另存 `decks.json.corrupt-<ns>` 再从备份恢复（offline_save.py:52-96）。
- 恢复时机：离线启动末尾 `restoreDecks()` 重建 `CardDeck` 对象并替换玩家卡组列表（probe.js:682-727,972）。
- **profile 目录重定向**三层同时做：IL2CPP 层替换 `Application.get_persistentDataPath`（probe.js:76-79）、Win32 层替换 `SHGetFolderPathW` / `SHGetKnownFolderPath`（:2670-2683）、以及 `os.chdir`。
- **其它档案文件**：`replays.json`（最多 6 场，原子替换用 `MoveFileExW`，probe.js:2264-2271,2308-2319）、`replay-settings.json`、`online-settings.json`、`online-accounts.json`（存 43 字符令牌，最多 32 台服务器）、`great-rebellion.json`（远征进度，另有迁移入口 great_rebellion/migration.py）。

### 5.4 「大叛乱」远征模式= 他们自己写的整块 JS，注入进游戏进程

- 源码：`OfflineLab/great_rebellion/mode/*.js`（25 个文件、604,020 字节；`engine.js` 99 KB 是规则引擎，`native_battle.js` 47 KB 是原生战斗桥）。
- 组合方式：`great_rebellion/runtime.py:37-52` 把纯 JS 模块拼到最前、原生桥插在 `// __LAN_RUNTIME__` 标记处，然后才交给 Frida 注入。
- **战斗仍走原版引擎**：宿主建原生 `matchData`（type 6 练习局），客机只提交动作参数（native_coop.js:1-3 注释原文「The host runs the native card rules; peers submit a legal action, never native code」）。
- 入口：主菜单「战役」按钮被改名「大叛乱」，点击走 `ClickCampaign`（native_ui.js:443-453）。
- 存档：`profile/great-rebellion.json`（README:5）。

## 6. 客户端是否被修改

**结论：文件级几乎没改，全部靠运行时。**

实测（全树 SHA-256 对比 `OfflineLab/client/` 与 `The Horus Heresy Legions原版/`，共 44 个文件）：

| 文件 | 结果 | 说明 |
|---|---|---|
| `HorusHeresyLegions_Data/app.info` | **不同** | `OfflineLB` / `LegiLab` ← 原版 `Everguild` / `Legions`（读文件原文） |
| `HorusHeresyLegions_Data/globalgamemanagers` | **不同**（3,951,880 vs 3,954,708 字节，−2,828） | ① 公司/产品名：`OfflineLB` / `LegiLab` ← `Everguild` / `Legions`（ASCII 串对照）；② **Unity `bundleVersion`：`2.3` ← `3.7.3`**；③ 一处 **2,888 字节**、几乎全零（20 种字节值，末尾一个 16 字节哈希 `fd53be08…b6f2`）的二进制段只存在于原版，离线版里整段缺失（搜过全文件，不是移动）；④ 该段之后整体偏移 −2,832，另有一处 4 字节字段差异；**除上述外，其余 2,600+ 个 ASCII 串两版完全一致** |
| `vcruntime140.dll` | **新增**（原版目录没有） | 补 VC 运行时 |
| 其余 41 个文件（`GameAssembly.dll`、`global-metadata.dat`、`HorusHeresyLegions.exe`、`UnityPlayer.dll`、`baselib.dll`、`resources.assets(.resS)`、`sharedassets0-2`、`level0-2`、`StreamingAssets/localbundle` …） | **逐字节相同** | `GameAssembly.dll` 的 SHA-256 = `a2184710…35c3`，与原版一致，也正是 `original_hashes.json` 里登记的值 |

- `original_hashes.json` 只登记 3 个文件（`GameAssembly.dll`、`globalgamemanagers`、`global-metadata.dat`），算法 **SHA-256**；校验代码里 **`globalgamemanagers` 被 `continue` 跳过**，注释写明「The clone has its own company/product identifier」（probe.py:44-45）。
- 改公司名/产品名的目的（推断，未见文档）：Unity 的 `PlayerPrefs` 在 Windows 走注册表 `HKCU\Software\<company>\<product>`，改名即与原版存档/单实例互不干扰；probe.py 的注释只说「The clone has its own company/product identifier」，没写原因。
- `bundleVersion` 从 `3.7.3` 改成 `2.3`，与发布版本号 `offline_version = 2.3` 一致；是否有代码依赖 `Application.version` 做判定，未查。
- **没有任何 DLL 注入文件**：Frida 是独立注入器（`_frida.pyd` 135 MB 内嵌 frida-core），注入的是脚本，不是新增的 Unity 插件。
