## 二、用法

### 1. 督军受伤（`B142-RULEPROBE-WOUND`）

```bash
bash /d/4/Unity/工具/ruleprobe.sh play BL8 preset herodmg=2
bash /d/4/Unity/工具/ruleprobe.sh play BL8 preset herodmg        # N 缺省 = 2
```

- 电池里（⓪ 出牌之后、②b `chip2` 之前）让 **P0 督军**挨 N 点，走引擎自己的 `RuleCore.ApplyDamage`
  （与 `selfChip` / 夹具扣血**同一个口** ⇒ 真发 `WhenEventKind.Damaged`，`RuleCore.cs:9558`）。
- **封顶到 `Health-1`**：督军被打死会牵出 `IsOver`，读数会变成「终局」而不是「受伤事件」。
- 电池局 / 空正文对照局**都跑这一步** ⇒ 夹具自身噪声（督军掉血本身）在净差里相减抵消。
- 可与别的 preset 组合：`preset herodmg=3,selfdies=1` 实测正常（`selfDies=skip(dead)` 如实打出来）。

### 2. 手牌态监听 × Deploy(190) / Kills(120)（`B142-RULEPROBE-HAND-EVENTS`）

```bash
bash /d/4/Unity/工具/ruleprobe.sh play TAU34 preset hand=self,event=deploy
bash /d/4/Unity/工具/ruleprobe.sh play SOR10 preset hand=self,event=kills
```

- `hand=` / `handn=` / `amount=` 与原来那 5 个事件**完全同一套**（`B8_AV` 夹具，卡**留在手牌**）。
- `event=deploy`：`BroadcastWhen(Deploy=190, who=0, subject=P0 第一张活部队, card=它的卡)`；
- `event=kills`：`BroadcastWhen(Kills=120, who=1, subject=P1 第一张活部队, actor=P0 第一张活部队)`
  —— 与产品发射口 `RuleCore.cs:6400` 同一组实参形状。
- ⚠️ 两档都是**直调广播**：⛔ 没有真部署 / 真击杀任何牌 ⇒ 棋盘不动，「变化逐条」剩下的只有监听器真的做了什么。
- ⚠️ `legacy=1` 对这两档**没有另一档语义**：它复现的是 2026-10-26 那 9 个发射点加 `boardAndPersistentOnly: true`
  之前的形状，而 Deploy / Kills 两个产品发射口本来就传默认值（`false` = 四跳）。

## 四、边界 / 别推翻

1. 🔴 **`herodmg` 是量具干预**（与 `selfdies=` / `killbymate=` 同一档）：不声称原版有这样一个受伤顺序，
   只回答「让 P0 督军挨这一下，挂在上面的那一族会不会响」。
2. ⛔ **别把 `heroDmg` 加成无条件的一步** —— 那会让全池 `steps` / 电池读数漂移、`PinnedPlayMd5` 必须重钉。

   这是「输出逐字节不变」的唯一保证（改法见 §一）。
4. ⚠️ `deploy` / `kills` 是**直调广播**，不是产品路径（真部署 / 真击杀各要造一张牌 / 走一整套攻击路）。
   读数里已明写「⛔ 没有真部署 / 真击杀任何牌」；⛔ 别拿它当「产品这一跳已验证」。
5. ⚠️ 两档的 subject / actor 取的是**夹具合成单位**（`FIX_A` / `FIX_E1`，卡面为空）⇒ 它们自己不会因这条广播多响。
