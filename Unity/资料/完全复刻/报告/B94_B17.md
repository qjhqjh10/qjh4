## 七、顺手发现（⛔ 都没动别人的文件）

1. 🔴 **B6 判据 §5 有一处误读**：`MilestoneScoreBar` 的 `progressBar` 被写成 `PPtr<ProgressBar>`，
   实际是 **`Slider`**（`dump.cs:111238` 明写 `private Slider progressBar; // 0x20`，
   而 `SetProgressBar` 读写的 `wholeNumbers/maxValue/normalizedValue` 全是 `Slider` 成员）。
   ⇒ 组件照 `Slider` 建；账补丁里那一行的「判据要点」已就地订正。⚠️ `判据/B94_B6_判据补全.md` 是 B6 的产出、**不在本代理白名单** ⇒ 只在这里记。
2. 🔴 **B6 §8 的「两套固定几何」不成立**：同一变体内**每个宿主各一套覆盖**（见 §五·1 的五种根框）。
   照「两套」写死会在另外两个宿主上偏 48–70 px。
3. **`MilestoneScoreBar.Initialize` 与 `SetScoringMilestones` 是同一段代码（内联 + 死码）** ——
   原版 `Initialize` 内联了那段 `while`，`SetScoringMilestones` 因此 0 调用。这条以前记成「两个方法」，
   实际是「一个活、一个死」。我们的 `InitializeLines` 只保留一份实现，`SetScoringMilestones` 转发过去。
4. **`GenericScoreBarLine` 的 `Locked` 与 `Unlocked` 只差 `readyToCollect` 的显隐**，箱子图**同一张**。
   这是最容易「照直觉写错」的一格（写成 Unlocked 换开箱图 ⇒ 视觉上少一档「已开」状态），断言 G2a 咬住了。
5. **`chestOpen` 是 Sprite 资产、不在 `bundle_menus_assets_all`**（15 个实例逐个读 `m_FileID != 0`）⇒
   它的图名要从 `AllianceEventScoreInfo` 那一族用的 `40k_Crate_TierN_*_open` 那一批拿（同族已知）。
   `Chest` / `Skull` 的 sprite 同样在外包，`Skull` = `40K_missions_icon_Daily skulls`（`AllianceEventScoreInfo` 里已有）。
