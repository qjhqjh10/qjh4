## §3 为什么「生产货币账 = `Wallet`」（这是本件唯一的结构决定，不是新判据）

- 原版 `GetOwnedCount` 末跳 = `InventoryManager` 里那份**由服务器解包灌进来的** `Inventory<ICurrency>`（`CurrencyExtensions__GetOwnedCount.c`）。
- 本工程**从未登记** `Inventory<ICurrency>`（`Inventories` 的静态构造只登记 `Cards / Shop / AltArts / Wildcards`）；原版已关服 ⇒ 那份背包**永远不会有来源**。
- 而「资源固定 2000」这条用户边界就落在 `Wallet.StartAmount`；`Shell/DailyData.cs:2306` 与 `Shell/Inventory.cs:1952` 两处自己写着「全工程唯一发奖口 = `Wallet.Grant`」，顶栏读数 `MainMenuRuntime.OwnedOf` 也读它。
- ⇒ 按简报「若结构上无法统一，停手写报告」——**能统一，且只有一条路**：把 `Wallet` 认作货币账。
  **再开一个 `Inventory<ICurrency>` = 第二个钱包**（CLAUDE.md §三「两处写同一条规则 = 迟早不一致」，还会绕开用户的 2000 边界）。
- 🔴 **键只取一处**：`MainMenuRuntime.CounterSpecs` 的 `WalletKey`；**读也只转调 `MainMenuRuntime.OwnedOf`** ——
  它本来就被标成「原版 `CurrencyExtensions.GetOwnedCount(c)` 在我们这边的等价物」（`Shell/MainMenuRuntime.cs:2169`）。
  ⇒ 顶栏与本读口**共用一张表、一个函数**，不是「两边各算一遍再对答案」。
- 🔶 这一段在代码里按铁律 18 打标（`Shell/CurrencyCatalogSeed_B142E65.cs` 文件头 ②：「🔶 自己设计（非原版）… 判据在远端 … 调度台 2026-11-04 裁定」）。

### 3·1 `C3` / `C5` 今天读 0，是**如实**、不是新缺口
`CounterSpecs` 只给 **`campaignPoints` / `crystals` / `gold`** 配了 `WalletKey`；`blackStones(C3)` / `gachaTickets(C5)` / `raidMedals` 是 `null`（我们从来没有那两路记账）。
⇒ 这两档 `GetOwnedCount` **与顶栏一致地给 0**（名册里查得到它们，只是没有账格）。⛔ 我没有在别处另抄一张「code → 键」表去硬造它们 —— 要真给它们记账，改的是 `CounterSpecs` 那一张表。
