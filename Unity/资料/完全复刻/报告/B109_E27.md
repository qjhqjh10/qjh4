## §5 顺手发现（**本件没改**，交调度台排）

1. 🔴 **`Fill` 的填充图在进度变化时根本不会长** —— 这是一条**比换图更实的缺陷**，单独记账：
   - `BuildRewardsFooter` 里 `Fill` 的框是 `FillR`（`x1 == x2` ⇒ **0 宽**），`MenuDraw.Nine(...)` 建九宫格时
     `ImageQuad.CreateNineSlice` 把 `scX = worldW / (wl + wr) = 0/0.185 = 0` ⇒ 三列全 `w <= 0` ⇒ **一个 `ImageQuad` 子块都不建**；
   - `SetRewardProgress`（`:1151`）只对 `_progressFill`（`Fill` 节点）调 `MenuDraw.ApplyPxRect`（改 `sizeDelta`），
     **不重建**那个九宫格 ⇒ 就算进度变成 3/6，**画面上仍然是空的**；
   - 原版是 uGUI `Slider`：`Fill` 的 `RectTransform` 走**拉伸锚点**，`Slider.value` 改 `anchorMax` ⇒ 底下的 `Image` 跟着重算矩形。
     我们这套没有 uGUI 运行时 ⇒ 必须自己在 `SetRewardProgress` 里重建（或改用一张 stretch 的 quad 再调 `SetPxSize`）。
   - **为什么本件没改**：① 超出本次派单（派单只要换常量 + 断言）；② 真修要照原版 `Fill` 的 `m_AnchorMin/m_AnchorMax`
     与 `Slider` 的驱动关系取判据（铁律 3 / 18·0：不许自己挑一个画法）。**建议**：单开一条，判据 = 原版 prefab 里
     `Fill Area/Fill` 的 anchor + `Slider` 的 `m_FillRect` 关系。
   - ⚠️ 影响面：今天生产路径**没有** `RewardsProvider`（`Snapshot()` 恒 null）⇒ `SetRewardProgress` 生产上从不被调用，
     所以这条**目前零可见差**；一旦接远端掉落表（`SpecialDropTable`）就会立刻显形。
2. ⚠️ 主表 `商店.tsv:120`（`GachaRewardsPanel.RefreshFooter()`）与本件**同源**：本件的账补丁是**整行替换**那一行

   **以主表为准重跑一次 `d:/4/_tmp_view/b109_e27_patch.py`**。
