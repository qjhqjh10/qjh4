## 二、T7-1 `ShopData._shopItems` 丢顺序（**假账**）

**原版顺序从哪来**（`cpp2il/out_cpp2il_dev_ilspy/Everguild.LiveOps/FixedStoreData.cs`）：

- `Items` getter（`:88-166`）= `Enumerable.Concat(items, SelectMany(offerLists, x => x.offers))`，再 `.Where(IsActive)`：
  ⇒ **items（追加序）在前 + offerLists（每条 `.offers`）按列表序展开在后**，再滤掉非活动项。
- `AddItem`（`:150-170`）= 追加进 `List<ShopElement> items`（`:85`）；`offerLists`（`:83`）= `List<LoadableReference<ShopOfferList>>`。
- 这个序由**服务端 store 数据**决定。本地唯一真 store = `Premium Campaign Store`（战役高级轨，13 条），**与我们三个页签无关**。

**我们丢了什么**：**没丢显示顺序**。

- 我们的 `ShopData` 是自建（文件头标 `🔶 自己设计`）：三页 = `Pages[]` + **有序数组** `_cards`/`_daily`/`_items`。
- 货架渲染 `ShopTabPage.BuildGrid` 取 `var offers = ShopData.Offers(_page)` 后**按 index 遍历**（`Shell/ShopTabPage.cs:399-401`）⇒ 画面顺序 = 数组下标序。
- `_shopItems` = `static readonly Dictionary<string, ShopItem>`，**只作身份缓存**：`ItemFor` 的 `TryGetValue`/赋值（`ShopData.cs:304,306`）、`ResetForTest` 的 `Clear`（`:480`）。**全仓仅此 4 处引用，从不被遍历渲染**。

**裁定**：`Dictionary` 确实无序，但它在本工程里**不承担顺序职责** ⇒ 「丢顺序 → 货架排列错」对画面**不成立**。原版有序合并（items+offerLists）是**数据模型**层面的东西，而我们的商品数据**全部是自设计**、原值在服务端拿不到。

**建议**：不改代码，在 `ShopData` 文件头补一句「顺序语义 = `Offers()` 数组下标序；`_shopItems` 仅身份缓存不作顺序用途」，防止下个会话再立这条假账。判 **D**（时间限定：拿到服务端目录数据再开）。

## 三、T7-2 `CampaignBadge` 缺 `army`（**真缺口**）

```

{
    public CardArmy army; // 0x18
    public void .ctor(CardArmy army = 0)   // 默认 Neutral=0，dump.cs:123697
```

- `PrintMembers` 打印 `army`（`decomp_full/CampaignBadge__PrintMembers.c:29-37`）；`Equals` 比 `+0x18`（`CampaignBadge__Equals.c:26-31`）。

  `Neutral=0 · Ultramarines=10 · Goff=20 · SaimHann=30 · Sautekh=40 · BlackLegion=50 · Leviathan=60 · TauEmpire=70 · Sororitas=80 · Genestealers=90 · AstraMilitarum=100 · DarkAngels=110 · EmperorsChildren=120 · SpaceWolves=130`。

3. 值域对齐枚举 `0/10..130`。

**怎么验**：造两个不同 `Selected` 阵营 ⇒ 两个 `CampaignBadge.army` 不等；`MainMenuScene` 现有红点断言仍绿（`CampaignBadge` 为 useFilter=0 无过滤，加字段不改计数）。
