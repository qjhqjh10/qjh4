## §3 顺手发现（⛔ 未越界改）

1. 🔴 **`Countdown` 整个类在本 build 不可达** —— 不止 208 这一行：B 行 **204/205/206/207**（`Activate` / `ChangeSpeed` / `GetSecondsLeft` / `Stop`）是**同一个类、同一批证据**（0 实例 + 0 引用点 + 运行时 dump 0 命中）。**建议一并判 D**（本代理只动 C 行，B 行留给调度台裁）。
   连带：账里 204–207 的落点写的是 `CardPresentation/Shell/TimerDisplay.cs` —— 那是**另一个原版类**（`TimerDisplay`）的等价件，**不是** `Countdown` 的等价件（两个类的功能不同：`Countdown` 有 speedFactor + `<5s` 提示音，`TimerDisplay` 只有「剩余 → 文案」）。这个「落点指错类」的偏差建议在判 D 时一并订正。
2. ⚠️ **`ActionScheduler` 的「过点不排」是一条真行为，落地后会影响 `LiveOpsEventWindow`**：`ScheduleExpiryRefresh` 用的是 `ev.EndUtc`，若事件**已过期**（`EndUtc` 在过去）⇒ 现在 `Schedule` 返 `null` ⇒ 不再排截止刷新。**这与原版一致**（原版 `Schedule` 同样 `return null`），且该调用点已能接住 `null`（`ReleaseExpiryRefresh` 有 null 判），**不会 NRE**。但它改变了一条既有行为，验收时留意。
3. ⚠️ **`UIResourceCounter` 那两条（706/708）的残差不是「没做」而是「一行 Layout 重算牵扯整条栏」**：`Shell/TopBar.cs:776` 的 `QtyWMin/QtyWMax` + `:821` 的 `Mathf.Clamp(nat, …)` 是「先量后建」的一次性布局；要做到原版 `layoutGroupContentFixer.FixLayout()`，得把 `BuildResourcesBar` 从 `MenuDraw.SetPxSize(container, totalW…)` 往后的**整段药丸/图标摆位**抽成可重跑的函数（≈80 行）。本代理判为**风险高于收益**（无 Unity 可视核验、改坏 = 顶栏整条位移，而 `Editor/MainMenuScene.cs` 顶栏有次序断言会红）⇒ **建议单独派一个执行代理，配一次 Unity 截图验收**。
4. ⚠️ **`RendererExtensions`（544/546）的消费者不存在**：`Shell/InboxWindow.cs` 里**没有任何音效调用**（全文只有两处注释提到 `ButtonClick Positive` 是 prefab 的 `m_OnClick` 音频）。原版「可见才播 slotting 音效」那一跳在我们这边**连音效本身都没接** ⇒ 单建 `CountCornersVisibleFrom` 会是零 caller 的空壳。**正确顺序 = 先接音效（音效线）再补可见性闸**。
5. 📌 **`CollectSpiritStone`（165–167）的可达性判断要再收一格**：账里写「本地加一支 `case "CollectSpiritStone"` 即可」，但**本批现读发现还差两跳**（见 §4）—— 它不是「一行 case」的量，别按账里那句话直接派活。
6. ⚠️ **`DateTime` 的 kind 一致性（本批改 `Schedule` 时专门核过，结论：安全）**：新 `Schedule(DateTime)` 会把入参 `ToUniversalTime()` 后存成 `DateTimeKind.Utc`，而 `DateTime` 比较**只看 ticks 不看 kind** ⇒ 若某处拿 Local-kind 的时刻去比就会差 8 小时。已逐个核过三个比对点：`LiveOpsClock.NowUtc`（`DateTime.UtcNow`）· `LiveOpsEventTimeData.FromMs`（`…UtcDateTime`）· `LiveOpsLocalCatalog.Event.EndUtc`（`FromMs`，同一条换算）—— **三点都是 Utc ticks** ⇒ 无偏移。将来往 `LiveOpsScheduler` 传时刻的人**也必须给 Utc**（本类只保证「存进去的是 Utc」）。
