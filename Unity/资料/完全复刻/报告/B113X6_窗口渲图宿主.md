## 2. WindowShots 怎么跑（逐行命令）

```bash
# ① 全量（32 扇窗 + 主菜单基线；两台宿主按顺序建场，一次跑完）
unset ELECTRON_RUN_AS_NODE && "D:/Unity/Hub/Editor/6000.3.23f1/Editor/Unity.exe" -batchmode -quit \
  -projectPath "D:\4\Unity\MyGame" -executeMethod WindowShots.RunFromCLI -logFile -

# ② 只跑一台宿主（MainMenuScene 那 32 行）
unset ELECTRON_RUN_AS_NODE && "D:/Unity/Hub/Editor/6000.3.23f1/Editor/Unity.exe" -batchmode -quit \
  -projectPath "D:\4\Unity\MyGame" -executeMethod WindowShots.RunFromCLI -logFile - -wfWinHost mainmenu

# ③ 只跑一扇窗（按 slug）
unset ELECTRON_RUN_AS_NODE && "D:/Unity/Hub/Editor/6000.3.23f1/Editor/Unity.exe" -batchmode -quit \
  -projectPath "D:\4\Unity\MyGame" -executeMethod WindowShots.RunFromCLI -logFile - -wfWinOnly shop
```

⚠️ **必须串行**（同一工程同一时刻只能一个 Unity 实例，CLAUDE.md §1·b）—— 跑它的时候**别同时跑别的自检**。
⚠️ 这三个入口**都不存盘**（`Build` 只 `NewScene` 建场，⛔ 不调 `SaveScene`）⇒ 不需要「跑前留场景副本」那道工序。

**产物**：

```
d:/4/_tmp_view/shots/win/<slug>.png     每扇窗一张（固定 1920×1080）
d:/4/_tmp_view/shots/win/_index.tsv     窗名 | 宿主 | 输出文件 | 分辨率 | rc | 说明
```

**`_index.tsv` 的 6 列**：前 5 列是单子上钉死的；**第 6 列 `说明` 是追加的** —— 理由：
`rc != 0` 的行**必须把原因落盘**（⛔ 不许只印在日志里，日志会被下一次跑覆盖）。

**rc 语义**（固定）：

| rc | 含义 | 退出码影响 |
|---|---|---|
| 0 | 拍成（平均亮度 > 3） | — |
| 1 | **疑似空图**（平均亮度 ≤ 3）—— 文件已写出，但**别当它拍到了** | 计失败 |
| 2 | 失败：开窗返回 null / 抛异常 / `Camera.main == null` / 渲染写盘异常 | 计失败 |
| 3 | 跳过：① 宿主没建起来 ② 规格表点名但内建表没有开法 ③ 本文件 §3 那 6 条「跑不了的窗」 | 不计失败 |

`fail > 0` ⇒ 批处理 `EditorApplication.Exit(1)`；否则 `Exit(0)`。**「跳过」不判红**（它们本来就是已知产不出的）。

**尺寸口径（单子上点名要写清的那条）**：
`W × H = 1920 × 1080` 是**我们的**渲染尺寸，与 `MenuCheck.Shoot` 和 7 个宿主自检**逐字相同**
（`LayoutSpace.DesignHeight = 1080`）。**原版参照图（用户实拍 25 张 / `资料/原版参照图/用户实拍_1017` 10 张 /
`资料/原版实拍/menu_topbar_0927` …）的尺寸是另一回事** —— 并排比时由 `工具/fp_sbs_check.py` 做归一。
⛔ 别把这 1920×1080 当「原版的尺寸」。

**渲染的是「整屏一帧」，不是「窗口矩形那一块」**（这是一个**有意的取舍**，理由写死）：
① 原版参照图全是**整屏**实拍（左栏 / 顶栏都在），只裁窗口那一块会**没法并排比**；
② 现成的渲图口（`MenuCheck.Shoot` 与 7 个宿主的 `Shoot`）**全是整屏**，照它们的形状写 = 零新机制；
③ 窗口在屏上的位置本身也是要验的东西（`placement = 5/10/15` 三档挂在不同锚点）。

## 3. 跑不了的窗 + 原因（逐条；它们也进 `_index.tsv`，rc=3）

| 窗 | 宿主 | 为什么今天产不出这一张 |

| 商店窗（单宿主版） | `ShopScene` | 同一扇窗**已被 `MainMenuScene` 宿主以生产开窗路覆盖**（`MainMenuRuntime.OpenShop`）；`ShopScene` 那份是**没有左栏/顶栏**的自检变体 ⇒ 两版并排会变成「同一扇窗两张不同底图」⇒ 不进本表 |
| 收藏窗（单宿主版） | `CollectionScene` | 同上（已被 `MainMenuRuntime.OpenCollection` 覆盖；`CollectionScene` 是无左栏的自检变体） |
| 奖励窗（单宿主版） | `RewardsScene` | 同上（已被 `MainMenuRuntime.OpenRewards` 覆盖） |
| 设置窗（单宿主版） | `SettingsScene` | 同上（已被 `MainMenuRuntime.OpenSettings` 覆盖） |
| 主菜单壳（完整壳） | `ShellScene` | `ShellRuntime` 要走「建壳 → 开场动画 → `LoadMainMenu`」那套时序；本表只拍**窗口**，壳层基线由 `main_menu` 那一行承担。看完整壳 ⇒ `-executeMethod ShellScene.Run` |

🔴 **这 6 条按单子上的白名单「必要时」判的**：白名单允许我在 8 个宿主里各加一行查询口，但**只加了 2 个**
（`MainMenuScene` / `DeckScene`）。理由 = 上面那 4 个单宿主版本的窗**全都能从 `MainMenuScene` 以生产路开出**，
再各加一份只会产出「同一扇窗、两张不同底图」，对并排比**是负资产**（人会分不清该跟哪张比）。
