## 四 · 顺手发现（照报，未改）

1. 🔴 **本仓是 Allman 花括号** —— 任何按「`if (…) {` 同行」写的正则在这仓**恒 0 命中**。已有工具/文档若假设同行，需复核。
2. 🔴 **「已覆盖」有 3 种写法**：`（前提` 字面量 / 同变量 `!= null` 断言 / `else CheckTrue(false,…)`。
   只看 `（前提` 会把 **93 条**（semantic 86 + else 7）误报成缺口。
3. 🔴 **大量块级 guard 的条件由夹具自己创建**（`var ds2 = pw.OpenDeckSelection(); if (ds2 != null) {…83 条…}`）。
   这类「恒真」guard 修不修都行，但按 AUD11 口径仍算「条件假 ⇒ 静默」。⚠️ 建议施工时**优先修「从场景/prefab 取」的**（真会 null），夹具自建的可降级。
4. ⚠️ **`else { 两条断言 }` 形态完全没被任何一轮 AUD11 覆盖**（原正则、本轮都不扫 `else` 块）。建议下一轮单独扫。
5. ⚠️ **文件在扫描期间被并发改**（1,019→1,021，`BattleScene/DeckScene/ShellScene` mtime 09:43–09:44）—— 本表是**近似快照**，施工前必须重新 `grep -n`。
6. 🔴 **影响面最大的两条块级 guard（一次 null 吞掉几十~两百条断言）**：
   - `CollectionScene.cs:8390` `if (hb0 != null)` —— 块**横跨 8390–9810（1,420 行）**，包了 **210 条 Check**（花括号平衡与缩进两条独立方法都确认 9810 闭合）。
   - `MainMenuScene.cs:5203` `if (ds2 != null)` —— 块 **5203–5923（720 行）**，包了 **83 条 Check**。
   ⇒ 这两处一旦取不到对象，**合计 293 条断言静默不跑、合计也不减**。建议**第一批就修**（加一条 `（前提·不静默）` 就解锁整段）。
