## 一 缺陷（判据 → `报告/B100_X3.md` #17）

`ReplayRecord.vars`（`ReplayVars`）原来靠 **`vars == null`** 判「这份录像没记规则参数」。
🔴 **那条分支恒不成立**：`JsonUtility.FromJson` 会把**缺键的可序列化类字段物化成一份全 0 对象**（本项目已知坑，记忆 `jsonutility-null-subtree`）。
实跑证据（#17 原文 / `B97W18_Assert` A7a「期望 True 实得 False」）：老档 `{"version":4}` 读出来 `vars != null` ⇒
生产 `BattleDriver.ReplayVarsForReplay` 会拿 `deckSize=0` / `startingMana=0` 去 `ToVars()` ⇒ **老录像放出来是全 0 参数开一局**。

## 二 哨兵设计（一句话）

**照同文件 `overtimeTurnSet` 的同族写法**：`ReplayVars` 加 `public bool varsRecorded`（`Capture` 置 `true`；老档没有这个键 ⇒ 读到 `false`），
**唯一读法** = `ReplayVars.IsRecorded(v) = v != null && v.varsRecorded`；生产消费点 `BattleDriver.ReplayVarsForReplay` 改判它。
哨兵取 `false`——`false` **既是 `bool` 的 CLR 默认值、也是初始化器值**（`JsonUtility` 跑不跑无参构造都给 `false`），与 `ReplayRecord.tutorialStage` / `botSeatPlus2` 同一条纪律（该纪律的论证在 `ReplayStore.cs:183-203`）。

## 七 覆盖边界（如实记）

- **没跑 Unity**：`A1`「老档读出来 `vars != null`」这条**事实**来自 `B100_X3` #17 的实跑（A7a 期望 True 实得 False），本代理**未重跑**；本代理只做了类型检查。
- **`varsRecorded` 依仗 `JsonUtility` 不序列化「属性 / `[NonSerialized]` 字段」**：那是 Unity 文档级事实，本件用 C3 把它变成可观测断言（真跑时才验）。
- **老档策略是「一律当没记」**（包括 2026-10-29~10-30 之间、**有 `vars` 但没有哨兵**的 v4 档）：它们会退回默认参数并**出声**，⛔ 不会静默、也不会假装「记了全 0」。这是 #17 规定的路（「没有该标记的档 ⇒ 走没记」），**不采用**「非零就当记过」那种启发式（会重新引入猜）。
- **`version` 不 +1**：纯新增字段，旧档行为=退回默认（`ReplayStore.cs` 版本纪律那条 `:61-90` 未被碰）。⚠️ 但**反过来说**：v4 档里既有「有 vars 无哨兵」也有「无 vars」两种，本改法**一律**按「没记」处理 ⇒ 那批档的规则参数**不会**再被装回（此前会装回）。这是**有意**的取舍：真装回的代价是「可能装回一份全 0」。
