## 二、几条必须留痕的判据

### #16 / #17 —— **⛔ 绝不许把 `Remove(keyword)` 改回 `Clear()`**
断言文案直接引用了 `decomp_full/CardScript__AddEffect.c:474` 的 `RemoveActiveEffects(param_1, 4);` —— **Ghidra 少印了第三个实参**。三份独立证据：
1. `cpp2il/out_cpp2il_dev_ilspy/CardScript.cs:17651` = `RemoveActiveEffects(BuffType.removeTrait, newEffect.trait);`
2. `cpp2il/out_il2csharp/Assembly-CSharp/CardScript.cs:10855` = 同上（**独立第二份 IL**）
3. 签名 `cpp2il CardScript.cs:18455` = `RemoveActiveEffects(BuffType buffType, DefinedTrait trait = none)`，体内 `if (trait != none) { … if (item.trait != trait) continue; }`；Ghidra 侧同样能读到 `param_3 != 0 ⇒ 按 +0x3c(trait) 过滤`（`decomp_full/CardScript__RemoveActiveEffects.c:34-40`）

⇒ **只清新增那条 trait 自己的「已移除」记录**。`UnitState.cs:1112-1121` 是对的。
🔴 **这是本项目同型事故的第二次**（上一次是「督军不算」那条断言把错口径钉死了一整轮）⇒ 改断言时**必须**保留一个「一真一假两个方向」的灭自证。

### #8~#11 —— 手牌效果去重
原版 `SetupCardInHand` 是先 `CardScript__AlreadyContainsEffect(card, handEffect.cardEffect)`、**为假才 `AddEffect`**；
`CardEffect__IsSameEffect` 比的是**字段值**（`buffType` / `enchantingCard` / 五个 `until*` / `+0x48..0x70` 的数值），**没有记录号、没有 `numberOfUses`**。
⇒ 两条字段完全相同的记录，**第二条被挡掉** ⇒ 新牌只吃 **1** 条、打出后 **3** 攻。
我们 `EffectResolver.cs:5536-5575` 的逐字段比**恰好就是原版那条闸** ⇒ 这 4 条**换哪种去重口径都红**，必须改断言。
⛔ `RuleCore.HandEffectRegistry` 的 `RecordId` 去重（`RuleCore.cs:10585-10603`）**不要动**。

### #14 —— 只改期望值会留下**永远绿的空断言**
夹 0 之后「结算一次(-2)」与「结算两次(-4)」都变 0 ⇒ 抓不到「Rally 结算两遍」。
⇒ **必须同时**把目标属性抬到 5/5（一次 3/3、两次 1/1）。

### #12 / #13 —— 两条 trait 结构上不能共存
加毒时身上有 resistant ⇒ 这次中毒作废；加 resistant 时身上有毒 ⇒ 摘掉毒。**先加哪个都不行**。
⇒ `RuleCore.cs:2529-2535` 那条回合末豁免支**在原版不变式下不可达**（保留代码，删掉对它的断言）。
