## 三、为什么这么改（判据摘要）

- **原版不是 `list[0]`**：`GetChosenCard`（`decomp_full/AiScripted__GetChosenCard.c:20-40`）比的是 `cardName`，
  `list[0]` 只在 `chosenMinion == null` 时才走；这 5 个 pid 的 PPtr **都非空** ⇒ 今天的「no-name → 第 0 只」
  **是我们缺数据造成的偏离**（铁律 18·0）。
- **Aggressor 必须显式 ourId**：现读 `RuleEngine/Core/TutorialScript.cs` 的 `ScriptedCardMatches`
  = `if (!string.IsNullOrEmpty(r.name) && c.Name == r.name) return true; return !string.IsNullOrEmpty(r.ourId) && c.Id == r.ourId;`
  —— **第一跳是逐字比**。原版 `cardName` 是 `Aggressor Sergeant (tutorial)`、池里那张叫 `Aggressor Sergeant`
  ⇒ 第一跳永远 false，只能靠第二跳比 id。故 `ourId = UM19` 是**必需**，不是可选。
- **卡名不改写**：产物 `name` 保留原版 `cardName`（含 `(tutorial)` 后缀），符合「产物保留 SO 原名」的既有口径。
- tutorial 变体的数值（`mana 8 / melee 4 / range 7 / health 6`）与池版本不必相同 —— 那是**池版本问题**，与匹配键无关，另立账。
