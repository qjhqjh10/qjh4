## §2 每条断言的判据与「牙」（怎么才会红）

### 2·1 三条同时成立才算「走横幅」

```csharp
Check(s, c1, c0 + 1,  …)                                   // ① ShowCount +1
Check(s, mt.LastRawText, "<该案例的键>",  …)                 // ② 原始入参 == 原版那条键
True (s, WindowsManager.Instance.popUpWindow == null, …)    // ③ 没有模态窗
```

* **为什么必须三条**：只查 ① 会被「横幅 + 模态一起弹」骗过（那种实现照样 +1）；③ 才是把
  「B89-E16b 判的那个错」钉死的那一颗牙。**灭自证**：把 `DuelPopupWindow.cs:319` 改回
  `ErrorPopupWindowController.ShowError(...)` ⇒ ① 不变、③ 红；反过来只删横幅保留模态 ⇒ ① 红。
* `LastRawText` 的语义已现读核对：`Battle/ErrorMessageBanner.cs:659` `LastRawText = text;`（**原始入参**，
  本地化发生在它之后）⇒ 断言比的是**键**、不是本地化后的句子（换语言不会红）。

### 2·2 ② 为什么**不会真删卡组**

`CollectionData.DeleteDeck(-1)` → `DeckLibrary.Delete(-1)` 第一句 `if (index < 0 || index >= _decks.Count) return false;`
（`RuleEngine/Data/DeckLibrary.cs:256-258` 现读）⇒ **立刻返回、不写盘、不 Remove**。
⚠️ 断言里**必须**先把 `DeckIndex` 置 −1（`DeckInfoPopup.DeleteDeckNowForTest` 的 doc 已写死这条）。

### 2·3 ③ 为什么「自适应当前数据状态」而不是写死 0

`PlayerIdForCopy()`（`Shell/ProfileTab.cs:1721`）今天恒 `null`（`PlayfabId` = 服务器账户域 P3）⇒
`copied == false && ΔShowCount == 0`；**将来接上账户域**后自动变成 `copied == true && Δ == 1` ——
两种状态**同一行断言**，不会因为 P3 数据补上而假红。

### 2·4 ④ 为什么只能读源码

`DeckInfoPopup` 那条闸是 `State == Import && !CanImportDeck(CurDeck)`，而 `CanImportDeck` **恒 true**
（2026-10-18 按原版实况改判，见该方法的注释），且 `state == Import` 在本 build **没有调用点** ⇒ 分支**不可达**。
⇒ 用源码扫描断（先例 = `Editor/CollectionScene.cs` 的 `A1051(4)`：读 `DeckInfoPopup.cs` 扫 `systemCopyBuffer` 赋值）。
扫描**跳过 `//` 开头的行**（旧写法就躺在注释里）。
