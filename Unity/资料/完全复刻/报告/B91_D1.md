## 二、根因（β）：闸判的是「我刚写进去的数」，不是「原来待卖的数」

**原版判据**（`d:/2/tools/cpp2il/out_cpp2il_dev_ilspy/PlayerDataManager.cs:13776-13799` 现读）：

```csharp
public void SellSpareCards(Dictionary<string, int> cardsToSell, bool fromInit = false)
{
    CustomDebug.Log("Sell All Spare");
    if (fromInit) { if (initialDuplicatesAlreadyProcessed) { LogWarning(...); return; } initialDuplicatesAlreadyProcessed = true; }
    Dictionary<string, int>.KeyCollection keys = pendingCardsToSell.Keys;   // ← 读的是【字段】
    int count = keys.Count;
    if (count == 0 && (isSellingCards ? 1 : 0) == count && (waitingSellCardCooldown ? 1 : 0) == count)
        StartCoroutine(SellSpareCardsRecursive());
}
```

两条铁事实（`.c` 同口径：`decomp_full/PlayerDataManager__SellSpareCards.c` 体里 `param_2`（形参字典）**一次都没被读**，
只出现 `*(longlong *)(param_1 + 0x450)` 那个字段）：

1. **闸看的是字段 `pendingCardsToSell.Keys.Count == 0`**（= 此刻「还没待卖」）；`count == 0` 时另两项也必须 == 0
   ⇒ 等价于 `!isSellingCards && !waitingSellCardCooldown`。
2. 本方法**从不给该字段赋值**。

**我们的实现（修前）**：

```csharp
int pending = cardsToSell != null ? cardsToSell.Count : 0;
PlayerInventoryOps.PendingCardsToSell = pending;                    // ← 先写
if (pending == 0 && !IsSellingCards && !WaitingSellCardCooldown)    // ← 再判「我刚写的那个数」
    SellSpareCardsRecursive(cardsToSell);
```

⇒ 传进来的待卖表只要**非空**（`Count >= 1`），闸就恒 false ⇒ **drain 永不起**。
唯一能过闸的是「空表 / null」那一档，而它又被下一行 `cardsToSell == null ⇒ 出声 return` 拦住
⇒ **`SellSpareCards` 这条链事实上是死的**（自检里 5 条红全由此而来；因为生产侧 0 调用点，线上没暴露）。
