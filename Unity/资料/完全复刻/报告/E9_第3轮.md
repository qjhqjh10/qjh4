## 三、代码缺陷 / 判据工具缺口（未改任何 `.cs`，只报告）

1. 🔴 **判据工具认不出「多行只读属性」声明** —— `check_ledger_points.py` 的 `looks_like_decl()` 要求那一行自带 `(` / `=>` / `{`，而 C# 里
   `public bool Foo` + 换行 `{ get { … } }` 这种**多行属性**的声明行三样都没有 ⇒ 永远判「既无 `(` 也无 `=>`/`{`」。
   本轮 3 条（`TutorialScript.cs:716 / :728 / :687`、`BattleDriver.cs:32450`）全撞在这上面。
   **建议**（下一轮改工具，不改账）：`find_decl_candidates` / `looks_like_decl` 增加一档 —— **下一行是单独的 `{` 且再下面是 `get`** 时，把本行当声明；或对「括号里是裸标识符 + 该名字在本文件有 `get {`/`{ get` 命中」时放行。
2. ⚠️ **`ClockManager.PauseForAnim/UnpauseForAnim` 的公开口今天 0 调用者**：`BattleDriver.cs:2891 / :2893`（`PauseClockForAnim` / `UnpauseClockForAnim`）没有任何调用点，真正生效的停表闸是 `TickClock :14030` 的 `WaitingForBlockingAction`。
   ⇒ **不是缺陷**（净效果等价、账里已写明），但**将来谁改钟表逻辑时别以为改 2891/2893 会生效** —— 那是死口。建议下一轮考虑删掉或接上。
3. ⚠️ **`CardScript.IsCurrentTurn()` 在我们这边没有单一实现点**：全仓十余处 `p != ctx.Active ⇒ ErrNotTurn` 各写一遍。
   ⇒ 目前落点只能指代表点。若将来要「一条规则只写一处」，应抽一个 `RuleCore.IsTurn(ctx, p)`（⛔ 本轮不动代码）。
4. ℹ️ `CleanupDeaths` 一段替原版三个方法（`CheckIfDead` / `TriggerOnMinionDeath` / `TriggerUnitDeathActions`）。
   代码注释里已如实记：**原版是「逐监听者」交错，我们是「逐死者」聚合再发** ⇒ 多监听者时**触发交错次序与原版不同**（无规则副作用，只影响结构化发射序）。这条不是本轮新增，只是提醒别把它当成「已逐句对齐」。
