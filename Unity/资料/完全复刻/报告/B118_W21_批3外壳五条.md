## #203 的方案与影响面（单独一节）

**原版那一层的三件**（判据全部现读）：
1. `TransitionUIAnchor : MonoBehaviour`（`dump.cs:118368`）：`EnableAnchor()` = `WindowsManager.anchorOverride = this.transform`

   `localPosition=.zero` / `localScale=.one`（`…__DisableAnchor.c` 全 118 行）。
2. `SimpleSceneTransition : SceneTransition`（`dump.cs:123196`）：`OutAnimation` =「`if (anchorOverride) EnableAnchor()` →
   `blackout.DOFade(1, fadeDuration)` → 等完成」；`InAnimation` =「`if (anchorOverride) DisableAnchor()` → `DOFade(0, …)`」
   （两个 `MoveNext.c` 全文）；场景实例 `MonoBehaviour_23.json`：`doOut=1 · doIn=1 · fadeDuration=1.0 · blackout→"Blackout" · anchorOverride→"Override"`。

**本仓已有 / 缺什么（别整层重造）**：
- `EndTransitionAnchor`（= `DisableAnchor`）与 `RegisterAnchorOverride`（= `EnableAnchor` 的实质）**早就有** ⇒ 缺的是
  「**谁**在切场景前把 override 指向**哪颗节点**、切完谁解掉」。
- **黑场已经有一个**：`Shell/LoadingMenu`（`ShellRuntime.Loading.LoadingFade(true/false, cb)`）就是 `blackout.DOFade`
  的等价物 ⇒ ⛔ **不另建第二块黑布**（两块会有「谁先淡回」的竞态，画面结果完全一样）。
- 过渡锚点节点：原版住在 `simpletransition` 场景；我们**没有**那个场景（`SceneTransitionList` SO 本地 0 实例 ⇒
  「按 from/to 选哪条过渡」那半判 D，`B88_J2` 普查）⇒ 锚点挂在**常驻**的 `WindowsManager` 自己下面。

**本波建的件**（`Shell/WindowsManager.cs`，尾插 partial 段 ⇒ 既有行号一个不动）：
- `:1908 EnsureTransitionAnchorRoot()` —— 惰性建 `Transition UI Anchor`，挂 `WindowsManager.Instance` 下（跨场景存活）；
