## ③ 假 null 的处理方式（自证「不会再抛」）

Unity 假 null 的两面（`判据/B106_D1` §四·3）：`x != null` 走 `UnityEngine.Object.op_Equality/Inequality` 重载（已销毁 ⇒ `!= null` 为 **false**）；而 `x.gameObject` 等**原生属性**直取**直接抛** `MissingReferenceException`。

本文件里现在所有对可能已销毁对象的原生访问都是这个形状：

| 处 | 写法 | 短路后不会碰原生侧 |
| --- | --- | --- |
| `:10220` | `if (built != null && built.Pointer != null && built.Pointer.gameObject != null)` | ✅ `built` 假 null ⇒ 整条假 |
| `:10222` | `if (built != null && built.gameObject != null)` | ✅ 同上 |
| `:10151/10153` | `if (tut != null && tut.Pointer != null && tut.Pointer.gameObject != null)` / `if (tut != null && tut.gameObject != null)` | ✅ 顺手补的守卫 |
| `:10162/10164/10165` | `ta != null` / `tb2 != null` / `ta == null` | ✅ 只有重载比较，不取原生成员 |
| `:10179/10181` 起的两块收尾 | 外层 `if (ta != null)` / `if (tb2 != null)`，内层再判 `Pointer`/`Pointer.gameObject` | ✅ 原本就安全（销毁 `Pointer` 的 GameObject 不会连带销毁教程组件） |

C# 的 `&&` 是短路求值 ⇒ 左侧为假时右侧**不求值** ⇒ 已销毁对象永远走不到 `get_gameObject`。
另：**主修法**（夹具先写 `PrefDone`）让第二次调用不再重启 ⇒ `built` 在正常路径**根本不会**被销毁 ⇒ 上面的守卫只是**防回归**的第二道。

**同类隐患普查（本文件）**：裸取 `if (\w+\.gameObject != null)` 的形状全文件只有 **2 处**（`:10153` 已补守卫、`:10185` 本来就在 `if (tb2 != null)` 里）⇒ 这一族在本文件**已清零**。
