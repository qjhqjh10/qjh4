## 〇、一句话

**回源结论：`chosenAbility` 不是触发侧的派发键。** 原版触发侧选 ability **只看 `CardAbility.trigger(+0x10)`**
（`CardAbility__CanTriggerAbility.c` 全 143 行**一次都没读 `chosenAbility`**）；`chosenAbility` 只在
`AbilityLogic.PlayAbility` 内部当**效果 switch** 用。⇒ **不能"按 `ca` 把这一行再跑一遍"（= 打两次）**。

所以本口做成：**只在「正文 op 为空」那一格**按 `ca` 兜底 ——
`320 followAfterResolution` 走**已有**执行器；其余真效果种类**出声**（今天静默空转）；
`ca == -1` 三支都不进＝**逐字改前行为**。

### ⇒ 和我们现有结构对不上的地方（这就是必须先说的那条）

## 六、顺手发现（请调度台分流）

1. 🔴 **`报告/B113X7` §五 那份"安全判据"草稿有个 bug**：它写「`ca <= 0` ⇒ 跳过」。
   而 `ca == 0` 是**合法真值**（`drawCard`，现池 **81 行**），未知只能是 `-1`（`B114_WB` §四已实证）。
   照那份草稿写会**静默丢掉 81 行 `drawCard`**。本件按 `ca < 0` 判，并在断言 A2 钉住。
2. 🔴 **`FireTriggerByNumber`（数值路）没有接 `randomAbilityChoice`**：`RandomAbilityChoiceOps` 只接在
   `FireTriggerAt`（关键词路，`RuleCore.cs:12933`）。而原版 `RawCardScript__TriggerAbility` 的
   `ability+0x48` 那一跳对**两条路都成立**。⇒ 一个独立缺口（`FireTriggerByNumberWithSink` 在我白名单内，
   但补它 = 改行为，本会话**跑不了 `play check`** 验，故只记账不动手）。
3. 🟡 **`EffectResolver.cs:20596-20597` 那段注释与 `B109_E6` 的 A3 断言互相印证**：
   `Pray Enchantment` 的 `TriggerOpsByNumber(60) == null` —— 与我在 §3·2 的现扫一致。
4. 🟡 **`TriggerAbilityRowsOf` 每次调用都 `new List` + `ToArray`**（`CardDef.cs:9254`）。
   本口只在 `ops` 为空时调它，量级可接受；若将来改成"每次都调"，先改成无分配版本。
5. 🟡 **`B113X7` 的核心反证仍然成立**：`320/360/380/480` 的 `ca` 行**全部在 `trigger 0`**，
   而 `FireTriggerByNumber` 够不到 `trigger 0` ⇒ **就算把这道口做到完美，也修不到 `AM54`/`GOF93`/`GOF104` 的 380**。
   那三张卡的缺口仍是「`380 → 320 → 410` 引用表链由正文 op 顶替」，**待调度台定性**（`B113X7` §八 那条仍然开着）。
