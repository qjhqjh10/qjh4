## 三 活 3 · 只读评估：`WildcardShine` / `WFUIAdditive` / `WFUIBorderHighlight` 该不该统一

### 3·1 结论（三层，别压缩成一句）

1. **不该「统一成同一份实现」。** 这三颗是**三颗不同的原版 shader**，pragma 形式、分支结构、裁切算式都不同：

   | 我们这颗 | 原版 shader | 原版的 clip/alphaclip 声明 | 原版的裁切算式 |
   |---|---|---|---|
   | `WarpforgeVFX/UI/UI Border Highlight` | `Everguild/UI/UI Border Highlight` | `m_KeywordNames[18]=UNITY_UI_CLIP_RECT` / `[19]=UNITY_UI_ALPHACLIP`，flag=1 | **软边 mask**（同族 `Pulse Alpha` b9 `:118-124`：`(rect.zw-rect.xy) - abs(INTERP.xy)` 再 `clamp`）；`_ClipRect` 在 `$Globals cb0[131]`（R5 `:38/:258`），`o3` = 裁剪矩形插值器（R5 `:65`） |
   | `WarpforgeVFX/UI/Additive` | `Everguild/UI/Additive` | `#pragma multi_compile_local _ UNITY_UI_ALPHACLIP`（`:44`）+ `_ UNITY_UI_CLIP_RECT`（`:45`） | **软边 mask**（b9 `:34-37`）；`_ClipRect` 在 `type_Globals c4` |
   | `CardPresentation/WildcardShine` | Coffee `Hidden/UI/Default (UIEffect)` | `#pragma multi_compile_local _ UNITY_UI_ALPHACLIP`（`:44`）+ `_ UNITY_UI_CLIP_RECT`（`:45`），**与 `TONE_GRAYSCALE`/`TRANSITION_DISSOLVE`/`TRANSITION_SHINY`/`EDGE_SHINY` 同列** | 未实现（整批变体都没做） |

   ⇒ 把 `WFUIBorderHighlight` 那段照抄到另两颗 = **与那两颗各自的原版不符**（顺序/分支/算式都不同）。

2. **但「判断口径」应当统一 —— 而现在这三处用的确实是两套口径：**
   - `B-262` 的口径 =「**原版 shader 声明了这两条关键字 + 编译产物有这两路 ⇒ 我们就要有**」（不看今天有没有消费者）。
   - `WildcardShine.shader:49-52` / `WFUIAdditive.shader:33-39` 的口径 =「材质 keywords 为空 / 今天没有消费者 ⇒ 不做」。
   - 按**铁律 11**（与原版不符的全部要做，只有先后之分）+ **18·0**（默认复刻原版，只有服务器相关才允许自设计），**`B-262` 的口径才是对的**；另两处应记成**真缺口/已登记缺口**，⛔「惰性」只能决定**先后**，不能当「不做」的理由。

3. **逐颗处置：**

   - **`WFUIBorderHighlight`** —— 已有（`B-262`），**保留**。今天**惰性**（全仓 `_ClipRect` 生产写入点 = 0；`ImageQuad` 是 `MeshFilter`+`MeshRenderer`，没有 `CanvasRenderer`/`Graphic`，`RectMask2D` 那套找不到它 —— 判据 = `报告/B114_W31_顶点色与CLIP关键字.md` §2·3）。⚠️ 但**算式存疑**，见 §3·3 顺手发现 (a)。
   - **`WFUIAdditive`** —— **真缺口**（与 B-262 同一类）：原版有 4 档变体 `b7/b8/b9/b10`，我们只复刻了 `b7` + `b8` 的 clip 那一句，**缺 `b9`/`b10`**。判据：`Everguild_UI_Additive.shader:44-45`（两条多编译）+ 四分支 `:48-56`/`:59-69` + 编译产物 `Sub0_Pass0_{Vertex_b3,b4,Fragment_b9,b10}.hlsl` **实存**。补的时候要照 **Additive 自己的**写法（四分支 + 软边 mask + `_TextureSampleAdd`），⛔ 别抄 BorderHighlight。优先级 P1（惰性、无消费者），但**该进账**。
   - **`WildcardShine`** —— **不是「只缺 clip」**：原版那两条与另外 9+ 个变体（`TONE_GRAYSCALE` / `TRANSITION_DISSOLVE` / `EDGE_SHINY` / Gradation / Target / Detail / Shadow / Color / Sampling）**同属一整批未实现变体**，我们只做了 `TRANSITION_SHINY + 无裁切` 这一档。**只补 clip** 会把「未实现清单」变成「部分实现」而不解决其余 ⇒ 要么整批补完、要么整批留作已登记缺口，**不应单摘 clip**。

### 3·2 反证（为什么"一刀切"会出错，逐条给证）

- **pragma 顺序不同**：`Everguild/UI/Additive` 是 **ALPHACLIP 先、CLIP_RECT 后**（`:44` → `:45`）；`WFUIBorderHighlight` 我们是 **CLIP_RECT 先**（`WFUIBorderHighlight.shader:136-137`）。统一 = 至少有一边顺序与原版不符（顺序影响 VS 分段，R5 `:68` 用"clip/alphaclip 组合的 VS 完全相同"反证过关键字顺序）。
- **`_ClipRect` 住处分不同**：BorderHighlight 在 `$Globals cb0[131]`（R5 `:38/:258`）；Additive 在 `type_Globals` 的 `c4`（b9 `:9`）。两者都**不在 `UnityPerMaterial`** —— 我们这边三颗都只能当**材质属性**喂（`ImageQuad` 无 `CanvasRenderer`），这是**共同的必要差异**，但默认值与坐标空间要**各自核**，不能假定一样。
- **算式不同**：原版 Everguild 两族都是**软边 mask**（`(rect.zw-rect.xy) - abs(INTERP.xy)` → `clamp` 相乘）；而本机 `UnityGet2DClipping` 是**硬边** `step`（`D:/Unity/Hub/Editor/6000.3.23f1/Editor/Data/Resources/CGIncludes/UnityUI.cginc:4-8` 现读）。⇒ 「统一实现」会把三颗都推向同一边的错。
- **`WildcardShine` 的变体矩阵更大**：它的原版把 clip 与 4 个效果家族并列（`:44-49`），我们只实现其中 1 档；这与 `Additive`（只差 2/4）不是同一个量级的问题。

### 3·3 顺手发现（只报告，未改任何 shader）

- **(a) `WFUIBorderHighlight` 的 clip 算式与原版同族不一致**：我们用 `UnityGet2DClipping(i.worldXY, _ClipRect)`（硬边）；原版 Everguild 这一族用**软边 mask**（`Pulse Alpha` b9 `:118-124`；`Additive` b9 `:34-37`），且 R5 `:65` 记着 base `UI Border Highlight` 的 `o3` 就是"裁剪矩形"插值器、`_ClipRect` 在 `$Globals cb0[131]` —— 与软边路径同形，与"世界 XY + 硬边"不同形。
  今天**惰性**（无数据源）⇒ **0 视觉影响**；但按"逐字复刻"这是一处偏离。**未复核 base shader 的 PS 原文**（本机只有 `Pulse Alpha` 的 hlsl 导出，base 的 DXBC 在 assets_full 的 shader JSON 里，R5 只分析了 VS/角度，没深挖 clip PS）⇒ 置信度：**高但非确证**，建议调度台派一条只读去 `Shader_-4463273156108355430.json` 的 clip 变体 PS 里对一眼。
- **(b) `WildcardShine.shader:51-52` 的措辞**：「该实例上全是 None ⇒ 这两个关键字变体里**也不会被编进去**」—— 对 `#pragma multi_compile` 的关键字**不成立**（`multi_compile` 一定编，只是运行时不被选中）。这是文字精度问题，**不是代码问题**；按只读任务红线未改。
- **(c) 两个断言类接线后各只有一个宿主**（`grep` 已复核），不会重复累加。
- **(d) 本报告未验证断言本身是否全绿** —— 跑宿主需要 Unity（红线），交调度台在同步点跑 `ShellScene.Run` / `BattleScene.Run`。
