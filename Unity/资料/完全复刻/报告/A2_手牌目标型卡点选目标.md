## 五 · 没做的 / 需要别人配合的

### ① 单位卡「撤单位 → 回手到原索引」（`:903-970`）— **没做，与 `AUD8` 同一条账**
为什么不做：我们的形状是「**点完目标才落位**」，没有「已落位再撤回」这一跳。
**引擎要给什么口（调度台点名要写清）**：一个「**撤销一次已生效的部署**」，语义 = 把那张刚上场的 `UnitState` 从 `Board` 摘掉 + 把 `CardInstance` 放回手牌原下标。⚠️ 必须先说清三件副作用，否则会静默改局面：
1. **不能走死亡路**：`KillUnit` 会发 `Death`/`OnUnitDied` 一族广播 ⇒ 触发「死亡时……」的能力（原版撤牌**不发**这些）；
2. **光环重算**：摘人后必须 `Auras.Recompose(ctx)`（否则光环停在旧棋盘上 —— 本仓已知静默坑）；而 `Recompose` 本身**有副作用**（夹血 / 费用重登记 / 誓约），撤牌这一跳是否该付这些代价要单独裁定；
3. **事件流**：原版这一支只 `RemoveMinion` + `TransformUnitInPlayToCard` + `AddCardNotDrawnToHandAtIndex`，**没有** `Play`/`Deploy` 的回滚广播 ⇒ 我们的 `ctx.Events` 不能因为撤牌多出/少掉条目（会动 `NetProtocol.Fingerprint`）。
⇒ 建议：引擎口名 `TryUndoDeploy(ctx, p, slot)`，只做「摘棋盘 + 回手 + 重算光环」，⛔ 不走死亡、⛔ 不发事件。

- 新增 `n == 0` 闸（`:7935`，**只对单位卡**）：池非空但棋盘上一个都点不到 ⇒ 不进等待态 + `Debug.LogWarning`。
