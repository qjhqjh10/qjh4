### 2) `FirstDeckInArmy`（`LiveOpsEventWindow.cs:370`）—— 排序落在**挑第一套**这一跳

**改前**：

```csharp
int start = (prefer >= 0 && prefer < n) ? prefer : 0;
for (int k = 0; k < n; k++)
{
    int i = (start + k) % n;
    if (InArmyDeckList(i, faction)) return i;

```

**改后**（合法的优先；全不合法才取表里第一套 —— 表本身仍然是「阵营 ∧ 模式」的**全表**）：

```csharp
int start = (prefer >= 0 && prefer < n) ? prefer : 0, first = -1;
for (int k = 0; k < n; k++)
{
    int i = (start + k) % n;
    if (!InArmyDeckList(i, faction)) continue;
    if (first < 0) first = i;                    // 稳定序里的第一套（全不合法时用它）
    if (DeckIsLegal(i)) return i;                // 合法优先 = `OrderByDescending` 之后的 `FirstOrDefault`
}
return first;
```

- `prefer` 那一套若**在表里且合法** ⇒ 返回它自己 = 原版 `ChangeArmy` 的「上次那副属于本阵营 ⇒ 保持」那一支。
- `prefer` 不在表里 ⇒ 从它起绕一圈；**全不合法**（夹具现状）⇒ 表里第一套，**与原版 `FirstOrDefault` 稳定序同解**。

## 二、为什么这是原版语义（判据逐句）

判据 = `d:/2/tools/cpp2il/out_il2csharp/Assembly-CSharp/RankedDeckSelector.cs` **（这一条只认 `out_il2csharp`）**

```

  currentArmyCardDeckList = Enumerable.ToList(enumerable);      // ★ 字段存的就是【排序后】的表
```

- `:492-496` 谓词体 = `return DeckUtility.ValidateDeck(d, ref err, true);`
  ⇒ **合法性是排序键**（`OrderByDescending` 是稳定排序），**不合法卡组没有离开表**。
- `:247-253` 四钮显隐 = `next/prev SetActive(Count > 1)` · `view/select SetActive(Count > 0)` —— 用的是**表长**。
- `:382-386` `deckQuantity.text = "{IndexOf(deck)+1}/{Count}"` —— 分母也是**表长**。

⇒ 把合法性做成 `Where`，会让 **表长变小**（甚至 0）⇒ 空态 / 四钮全关 / `0/0`，与原版相反。
我们的 `ArmyDeckCount()`（`:388`）与 `ShownDeckOrdinal()`（`:398`）都直接复用 `InArmyDeckList`，
所以**改这一处、三处一起回正**（全类唯一一份筛法）。

⚠️ **为什么 `decomp_full` 的 `.c` 会骗人**：`decomp_full/RankedDeckSelector.__c___ChangeArmy_b__29_1.c`
把谓词的返回值打成 `void`（返回值被吞）——只看那份 `.c` 会以为它是 `Where` 的谓词。**这条判据只认 `out_il2csharp`。**

⚠️ **第三形参不是 `isSkirmish`**：原版 `ValidateDeck(deck, ref err, bool validateOwnership = true)`
（`:97`）—— 那个 `true` 是「校验持有」，牌数规则由 `deck.GameMode` 在方法体里分档。
我们的 `DeckRules.Validate(deck, lookup, skirmish)` 第三形参才是模式档，传 `raw.IsSkirmish`（由该副自己的 `GameMode` 推）
⇒ **等价**，且与本仓既有用法一致（`DeckLibrary.cs:494,510` · `LegacyCardIds.cs:1331`）。
