### 1·5 B11 修复（`IsParentEventActive` 兜底）—— 本轮唯一的「改行为」

**实机证据**（run6 `phase0/avatarprobe.tsv`，调度台转述）：

```text
FIND-ACTIVE-BORDER!EXC  NullReferenceException ... CustomDebug/… (栈: AvatarTab.FindActiveAvatarBorder → CosmeticItemAvatarBorder.IsParentEventActive)
AWK-OUT  n=1  toggleAvatarBorderIcon{... activeSelf=False ...}     ← 按钮被隐藏
```

**因果链**：`FindActiveAvatarBorder` 遍历 `Inventory<CosmeticItemAvatarBorder>.GetItems()`，对每一项调 `IsParentEventActive()`；
`Avatar Border Default` 的 `parentEvent`（`LoadableReference<ExpansionPassData>` @0x60）两个引用全 0
（`genericObjectReference` / `reference` 的 `m_PathID` 都是 0、`targetId` 为空串）⇒ 原方法走到「引用解不出」那一支
`FUN_1803f47a0()`（throw）⇒ **遍历中断** ⇒ `FindActiveAvatarBorder` 整体抛 ⇒ `Awake` 里 `SetActive(...)` 没走到 ⇒ 按钮保持隐藏。

**修复**（`Probes/AvatarProbe.cs:285` 注册，`:873` 实装）：
`ProbeUtil.Harmony.Patch(IsParentEventActive, finalizer: Fin_IsParentEventActive)`

- `__exception == null` ⇒ 直接 `return null`（**正常路径零影响**）；
- 有异常 ⇒ 设 `__result = false`、落一行 `IS-PARENT-EVENT-ACTIVE!FIX`（`id` + `name` + 异常摘要，上限 40 行）、`return null`（**吞掉该异常**，遍历继续）。
- 口径：「没有父事件的边框」= **非活动**（它本来就不该算进「活动边框」）。
- 代码注释里标了 `🔶 自己设计（非原版）`：离线数据缺口的兜底；原版为什么不会走到这一支**尚未查明**；正常路径零影响。

**修复后的预期**：`FindActiveAvatarBorder` 不再抛，能返回 4 个活动边框里第一个 `IsParentEventActive()==true` 的那个；
`Awake` 末尾的 `SetActive(true)` 能走到 ⇒ 「切换边框」按钮重新出现 ⇒ 点击链才有机会走到 `UpdateAvatarUrl`。
⚠️ 若修复后 `FIND-ACTIVE-BORDER` 仍为 `NULL`（而不是 FIX 行），说明**4 个活动边框的父事件也没解析出来**（与 R2 的 `ScoringEvent.RawEvents` 装载有关），那是另一条。⛔ 不要把这条修复当成「按钮一定能工作」的保证。

### 2·2 三条保险（对应任务要求）

1. **prefix 只诊断、不拦**：`achievementsList`（`AssetReferenceTyped<AchievementsList>`）/`achievements`（`List<Achievement>`）/`achievementsSave`（字典）任一为 null，**仍然返回 true 放行**，让原方法自己抛/自己 return —— 错误会出现在 `stubs.tsv` + MelonLoader 日志里，**不静默跳过**。
2. **postfix 记最终态**：`DONE IsEnabled=... IsInitialized=... achievements=count=...` —— 直接回答「102 条到底加载出来没有」。
3. **finalizer 不吞异常**：记录 `EXC(RE-THROW)` 后 `return __exception` —— 行为和「没装这根探针」完全一致，便于区分「是我们桩出来的问题」还是「原版真抛」。
