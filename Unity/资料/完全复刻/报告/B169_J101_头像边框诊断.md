## 一、结论

| # | 问题 | 答案 |
|---|---|---|
| 1 | 「切换边框」是**列表**还是**直接切**？ | **直接切 —— 二值 Toggle，原版根本没有边框列表**。`AvatarTab.ToggleAvatarBorder()` 只在「Default 边框」和「`FindActiveAvatarBorder()` 那一个」之间来回；prefab 里 Avatar Tab 只有 `Select Avatar Button` + `Toggle borde`（`Player Profile Window.prefab`，无 ItemDrawer 给边框用） |
| 2 | 列表的数据源 | 不存在的「列表」。等价物 = `FindActiveAvatarBorder()`：`InventoryManager.GetInventory<CosmeticItemAvatarBorder>().GetItems()` 上 **`First(IsParentEventActive())` —— 只取第一个**；对侧固定是 `DefaultAvatarBorderItem`（按 id `36ae26bb…` 在 `GetAllItems<CosmeticItemAvatarBorder>()` 里找） |
| 3 | 5 个边框都拥有？4 个活动都 active？ | 是。`playfab_profile.json` 的 `UserInventory` 里 **5 条 ItemId 全在**（索引 1352、1360–1363：Default / EC Release / UM Guilliman / Expansion pass / SW Release）；4 个父事件都在 **`HandlerData.ScoringEvent.RawEvents`**、`IsActive:true`、无 filter ⇒ live（`GetEvent(id)!=null && IsActive()` 成立）。运行时实证 Default（非活动）+ EC Release（活动）都在库存遍历里；其余 3 条被 `First` 短路，**未逐条实证** |
| 4 | 为什么只看到 1 个金色的 | **三条叠加**：① 结构上只有 1 个非默认槽；② 4 个活动边框**共用同一张金图**；③ 切到金之后**切不回默认**（真缺陷） |
| 5 | 修法 | ③ 是中国式阻断，必须修；要 5 个可选**只能走 mod**（原版没有这个 UI） |

**① 结构（原版语义）**：`ToggleAvatarBorder` =「Default ↔ 第一个 active」的开关，`First()` 短路 ⇒ 另外 3 个活动边框**永远轮不到**。
**② 美术**：4 个活动边框 SO 的 `imageReference.m_AssetGUID` **全是 `d93f2c13…` = `Player Profile Border Gold`**（一张图），Default 是 `9d34f925…` = `Player Profile Border`（银）⇒ 本地**只有 2 张**不同边框图，选谁都只有金/银两种长相。
**③ 真缺陷（切不回去）**：切成金色后 `IsDefaultBorderEquipped()` 变 false ⇒ 目标改用 `DefaultAvatarBorderItem`，而它**返回 null** ⇒ `SetCurrentItem(null)` 抛 NRE。`avatarprobe.tsv` 实录：第 1 次点（20:52:53）`IS-DEFAULT-BORDER-EQUIPPED=true` → 成功写 `SAVE-AVATAR-BORDER(EC Release)`；**第 2 次起到第 19 次**（20:53:10 起）全是 `IS-DEFAULT-BORDER-EQUIPPED=false → SETCURRENTITEM-IN NULL → SETCURRENTITEM!EXC(NRE)` ⇒ 画面再也不变。

## 三、修法（最小改动）

**第一步（必做，纯修 bug）：让「切回默认」恢复。** 现在 `DefaultAvatarBorderItem` 为 null ⇒ `SetCurrentItem(null)` 必 NRE。
最小改法 = mod 侧（`Probes/AvatarProbe.cs` 已有同类 patch 骨架）：Harmony **prefix `AvatarTab.ToggleAvatarBorder`**，自己取目标——
`InventoryManager.Instance.GetInventory<CosmeticItemAvatarBorder>().GetItems()` 里按 id `36ae26bb…` 取默认项（**走 Inventory，不走 `GetAllItems`/收藏集**，后者正是拿不到它的那一边），非默认项仍用原 `FindActiveAvatarBorder()`；然后 `SetCurrentItem(target)` 并 `return false` 跳过原方法。约 25 行，只碰 1 个方法。
（数据侧也可试「把 Default 边框补进 `FullCosmeticCollection`」，但 5 个 SO 本来就在同一个 `cosmeticsso` 包里、`showInCollectionOptions=Show`，**为什么缺它还没查清**，见 §四。）

**第二步（要「5 个可选」才做，属自设计）：把二值 Toggle 换成循环选择。**
同一 prefix 里改为：候选 = `Default` + 所有 `IsParentEventActive()`（用 Inventory 列表）→ 取「当前已装备」的下一个（回绕）→ `SetCurrentItem(next)`。必须打 `🔶 自己设计（非原版）：原版同一活动期只有一个边框可选，离线把 4 个活动同时激活；活动排期原本由服务器下发`。
⚠️ **做完也只有 2 种长相**：4 个活动边框共用同一张 `Player Profile Border Gold`。要「5 个各不相同」得先有 4 张不同的图——**本地没有**（SO 里写死的就是同一 GUID，不是解包丢的）。

## 四、没查清的（❓）

1. **`DefaultAvatarBorderItem` 为什么是 null** —— 两个候选，未定：
   (a) `PlayerDataManager.fullCosmeticCollection`（1180 条，本地 cosmetic SO 1261 条、差 81）里没有 Default 边框；
   (b) getter 被内联进 `ToggleAvatarBorder` ⇒ Harmony postfix 不触发 —— 佐证是 `avatarprobe.tsv` **一条 `PADM.DefaultAvatarBorderItem` 都没有**（hook 本身 `hooks_installed.tsv` 是 OK）。但 (b) 只解释「没日志」，不解释「值为 null」。
   **判据办法**：加一条探针直接读 `fullCosmeticCollection` 里 `OfType<CosmeticItemAvatarBorder>()` 的 id 列表 + `GetItemWithId<CosmeticItemAvatarBorder>("36ae26bb…")` 是否非空。
2. **其余 3 个活动边框的 `IsParentEventActive()` 是否真为 true** —— `First()` 短路，现有日志只证明了 EC Release。推定 true（4 个事件同形同数据），**未逐条运行时实证**。
3. **用户说的「5 个」是 5 个 id 还是 5 种长相** —— 本地只有 2 种图；若期望 5 种不同外观，那批美术本地不存在（SO 引用的就是同一张）。
