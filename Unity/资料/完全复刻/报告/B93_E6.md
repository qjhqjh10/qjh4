### 2·1 扣甲前伤害

**判据链（全部现读，`.c` 优先）**
1. `decomp_full/BattleManager__ResolveAttackDamage.c:28-30` —— `GetCombatDamage` → `DamageInfo(value, type=4)` →
   `CardScript__GetAdjustedDamage` → **`BroadcastUnitDamaged` 无条件执行**（`:19-31` 一路没有 `if` 挡它）。
2. `decomp_full/CardScript__GetAdjustedDamage.c:10-19,44-52` —— 调整后的 `DamageInfo` 的 `damageValue(+0x18)` =
   **进来那个原值**（只在部分 damageType 上走 `GetRandomInt` 随机化）；`:36-50` 只改 `damageAbsorbed`（`+0x24`），
   **不动 `damageValue`**；`:52-60` 的堡垒那一档同理（只置 absorbed）。
3. `decomp_full/DamageDeltToEnemyUnit__OnDamageDelt.c:81-83` ——
   `MissionChallenge__UpdateProgress(param_1, *(undefined4 *)(*(longlong *)(param_2 + 0x10) + 0x18), 0, 0)`。
   ⚠️ 全文**没有**任何 `+0x24`（absorbed）闸 ⇒ **被盾/闪避/无敌/空投舱/堡垒挡下的那一下也计入**。
4. 护甲在哪里减：本仓既有判据（`CardScript._ReceiveDamage_d__381__MoveNext.c:62-98` 的 `Max(1, damage - 护甲)`）
   在广播**之后**、且在 `bastion < 1` 那一支里 ⇒ 「扣甲前」= 我们 `ApplyDamageCore` 的入参 `dmg`。

**我们改在哪**
- `RuleEngine/Core/RuleCore.cs:8475`（`int actual = DamageAfterReduction(...)` 那一行，**就地扩写、未加行**）：
  ```csharp
  int _rawDealer = OwnerOf(ctx, u);
  if (kind != DamageKind.Unknown && (_rawDealer == 0 || _rawDealer == 1))
      ctx.Tally.AddDamageRaw(1 - _rawDealer, kind, dmg);
  ```
  放在**所有早退之前** ⇒ 盾 / 闪避 / 无敌（`:8521/:8530` 一带）、空投舱、堡垒整份吃下那几支
  **天然「先记再退」**，正是原版「absorbed 也计入」的形状（不需要逐支改动那几个 `return 0`）。
- `RuleEngine/Core/RuleCore.cs:8967`（`AddDamage` 那一句，**就地扩写、未加行**）：同一 `if` 体里补
  `if (vulnSecondPart > 0) ctx.Tally.AddDamageRaw(1 - _own, kind, VulnerableRaw(u));`
  —— 量取 **`VulnerableRaw`（扣甲前）**，⛔ 不是 `vulnSecondPart`（那份已经减过甲）。

**为什么是「并存」而不是「替换 `AddDamage`」**
`AddDamage`（扣甲后 `actual`）的唯一读者是 `CardPresentation/Battle/BattleDriver.cs` 的 `AwardAchievements`，
**不在本路白名单**（B3/E5 的文件）⇒ 本路只把**原版口径那一格喂上**，消费侧切换留给 B3。
这正好也是账行 1004 之所以只能留 **B** 的原因（见 §4）。

**已知唯一缺口（今天不可达，已在容器 doc 里写死）**：空投舱血池把**易伤第二发**也吃掉那一支
（`after >= 1` 的那个 `EmitHit(ctx, u, 0); return 0;`）绕过函数尾 ⇒ 那一发原版会广播、我们没有记。
全池 **0 张卡**带 `dropPod`（现扫 `cards_engine.json`）⇒ 行为差异 = 0。

### 2·2 能量按 CostType 分档

**判据链（全部现读）**
1. 全树 `grep "EnergySpentSignal___ctor"` = **只有两个命中**：`BattleManager__PayCardCost.c` /
   `BattleManager__PayActiveAbilityCostOath.c`（+ 它自己的 ctor）。
2. `PayCardCost.c:26-37` —— 扣费后 `EnergySpentSignal___ctor(sig, card, card+0x40 /*isPlayer*/,
   EntityScript.get_CurrentCost(card), 1 /*Type = CardCost*/, 0)` → `Signal.Raise`。
   `EntityScript.get_CurrentCost` 这一句是**扣费之后重取**（同一函数里出现两次，第二次才是信号用的那个）。
3. `PayActiveAbilityCostOath.c:19-38` —— `GetCurrentTraitValue(card, 0x4fb)` → `UseMana` → 信号以 `Type = 2`。
   唯一调用点 = `CardScript__UsedActiveAbility.c:44`（**单位使用主动能力**）。
4. `EnergySpent__OnEnergySpent.c:14-40` —— 消费闸 = `IsPlayer` ∧ `costCondition.Compare(Cost)` ∧
   `ContainsFlag(costType(+0x60), Type(+0x24))` ⇒ `UpdateProgress(Cost)`。
5. **刻意不记的两处（原版根本不发这条信号）**：
   `PayCardPlayedCostOath.c:13-26`（`AbilityLogic__PlayAbility.c:2033` 调；**无** `EnergySpentSignal___ctor`）
   与 `RawCardScript__TriggerAbility.c:52`（`UseMana(…, ManaType 5)`，也不发）。
   ⇒ 我们卡面付费前缀（`Oath N:` / `N Energy:`，落在 `EffectResolver` 的 `CostPrefixPayable` 支）
   **传 `costType = 0`：只记总数、不记分档**（⛔ 没给它编一个类型）。

**我们改在哪**（4 处，全部同长替换）
- `RuleCore.cs:13087` —— `SpendNormalMana` 形参加 `int costType = 0`。
- `RuleCore.cs:13115` —— `RecordEnergySpent(ctx, p, paid, source, costType)`。
- `RuleCore.cs:14983 / :14997` —— `RecordEnergySpent` 形参加 `costType`，体内
  `if (costType == EnergyCostCard || costType == EnergyCostAbility) ctx.Tally.AddEnergySpent(seat, paid, costType);`。
- 三个调用点显式传值：`RuleCore.cs:3943`（出单位卡）→ Card、`EffectResolver.cs:2582`（出战术卡）→ Card、
  `RuleCore.cs:15438`（单位主动能力）→ Ability。维护费 `RuleCore.cs:1826` 仍是 `energySpentSignal: false`（不动）。

**⚠️ 未消的差异（已写进容器 doc + 账行 1373）**：原版那格记 `get_CurrentCost`（付费后重取），
我们记实付 `paid`（两格都取 `paid`，彼此一致）⇒ 「付完会改费用」的卡上会分叉。
