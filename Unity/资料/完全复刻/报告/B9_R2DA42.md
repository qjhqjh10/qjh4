# `B9_R2DA42` 报告（查判据代理 · 2026-10-27 · 只读）

## 结论

1. **`DA42` 的机制已从二进制读到端到端**：打出 DA42 → 从**对手手牌**按 criteria 挑一张（`selectFromChooseResolution` 按卡名收敛到选牌结果）
   → 给**那张手牌实例**挂 `buffType 15 singleUseEnchantment`（`AddEffect case 0xf → AddEnchantment`，**无区域闸**）
   → **那张牌被打出时**（`OnCardPlayedWithTarget.c:43` 的 `thisCard==cardPlayed` 支 → `TriggerAbilities(0)` → 共享尾块扫 `+0x110`）
   → 附魔的 `trigger 0` 结算 `buffMana{3, enemyPlayer:1, questPoints:1}` ⇒ **+3 任务点给 DA42 施放方** → `340` 排队摘附魔。
2. **「三个前提」要重排成 5 条（P0–P4）**，其中 **P0 是普查件漏掉的**：模板卡 `e8cf1eb5…` **不在卡池**、`cards_engine.json` **没有 `enchantment` 列**、
   `CardDef` 也没有对应字段 ⇒ 今天**连「要挂哪张附魔」都表达不出来**。P1（挂到手牌）**容器层已经就绪**（`Attach` 吃 `CardInstance`），**缺的只是调用点**。
   P2（承载卡打出时派发）缺；P3（附魔能力的执行体）**最大**——我们没有被动 `cardAbilities[].abilityLogic[]` 解释器，`Pray` 是硬编码；
   P4（极性）半有 —— 任务点本体在 `DoFactionResource`，但「相对载体属主取反」这一格没有。
3. **订正普查件**：DA42 今天**不是「看不到效果」**，而是 **`Choose` 只挑不做 + `When played` 那句被主解析器解成 `gainquest 3` ⇒ 打出当刻就 +3**（`EffectText.cs:8745-8753` 的立意就是让它继续这么解）。
   ⇒ 验收夹具要盯「打出当刻不该加、承载卡打出之后才加」，**两条今天都红**。
4. **`BroadcastHandWhen` 六族：F1/F2 已做（现核，别再排工）· F3 = 就是 DA42 这条链（不是广播的洞）· F4 复算仍是「0 个未接住的手牌态监听者」· F5/F6 数据为 0。**
   F4 的口径要写全：它是「trigger 值 + desc 形态」分类，**看不见附魔挂载那条新轴**（判定件 §二·补）。
