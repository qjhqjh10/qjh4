## ② 逐条

### 1. 主菜单 16:9 常量 —— 🔴 **反证：不该改**

**施工单主张**：`itemH = 414.4 × max(1, (16/9)/aspect)`，我们的 `CardH/CardHTall/CardRow0Top` 是常量 ⇒ 缺这一档
（`判据/AUD05_state_matrix_主菜单与侧栏.md` §3·1 S-G1 / §4 缺口①）。

**原版判据（成立）**：`decomp_full/AdaptFlexibleGridLayoutByAspectRatio__ModifyFlexibleLayout.c` 全 30 行 ——
`itemSize.y = originalY × max(1, 1.7777778f / ((float)Screen.width / (float)Screen.height))`，`itemSize.x` 不变。

**为什么在我们这儿是恒等**（判据两条，都在仓里）：

1. 原版那条乘法是**为 `CanvasScaler(1920×1080, Expand)` 服务的**：Expand 下窄屏时**画布变高**
   （16:10 ⇒ 画布 1920×1200 · 4:3 ⇒ 1920×1440），所以必须把 `itemSize.y` 也乘 s，**才能让卡占屏幕高的比例恒定**。
2. 我们的设计空间是**钉高**的：`Core/LayoutSpace.cs:13-14,36` ——「可见高度恒等于 `DesignHeight`（10 世界单位）…与分辨率无关」，
   可见宽 = `DesignHeight × aspect`。⇒ 设计 px → 物理 px 的斜率**两轴都是 `Screen.height/1080`**，与宽高比无关
   ⇒ `CardH = 414.4` 设计 px **已经**是「占屏高 0.3837」那一档，**再乘 s 就是多乘了一次**。

**算术复核（用用户那张非 16:9 实拍反着验）**：实拍 `1430×883`（aspect≈1.6195）——
原版：画布 1920×1185.6（scale 0.7448）· itemH 454.9 · `row0top` 201.7 画布 px ⇒ 屏幕 **150.2 px**；
我们：`CardRow0Top 182.8` 设计 px × 0.8176（=883/1080）⇒ 屏幕 **149.4 px**。**差 0.8 px**（= 两模型 Content 锚点算式的高阶小项）。
⇒ 我们那组常量**在任何 aspect 下都复现原版的屏幕相对几何**。

**已有裁定（不是我发明的）**：`Shell/MainMenuRuntime.cs:3884-3918` 的类尾注释（`B88-A3`，2026-10-28）逐条写了同一件事，
并点名「⛔ **别为了「照原版多个组件」再建一个每次都乘 s 的适配器** —— 那会在窄屏把卡放大 1/s 倍、
与 `Editor/MainMenuScene.cs` 的 5 条 `CheckCard`（`205 + 555c / 535 / 414.4 / 848.8 / 182.8`）冲突，**而画面反而更不像原版**」。

**⇒ 建议**：`AUD05_state_matrix_主菜单与侧栏.md` §4 缺口① / §5 施工建议 A **应当被划掉**（改成「等价实现已在，
判据 = 本文件 §1·1 的乘 s **针对 Expand 画布**，我们钉高 ⇒ 恒等」）。
⚠️ **真正残留的那一格不是这个组件**：窄屏时我们的**可见宽度**变窄（4:3 ⇒ 只看得到 1920 设计 px 里的 1440），
原版同一时刻画布宽仍是 1920 ⇒ 那是 `LayoutSpace.cs` 记着的**全局画布模型差**（`A2092/A2098`），与本条无关、也**不在本批**。

**状态 → 参数表**（原版语义 → 我们的落点）：

| 状态 | 原版（Expand 画布 px） | 原版屏幕占比 | 我们（钉高设计 px） | 屏幕占比 | 等价? |
|---|---|---|---|---|---|
| aspect = 16:9 | itemH 414.40 · row0top 182.79 | 0.3837 / 0.1693 | 414.4 / 182.8 | 0.3837 / 0.1693 | ✅ |
| aspect = 16:10 | itemH 460.44 · row0top 204.29 | 0.3837 / 0.1702 | 414.4 / 182.8 | 0.3837 / 0.1693 | ✅（差 ≤1.2 px @1080） |
| aspect = 4:3 | itemH 552.53 · row0top 247.30 | 0.3837 / 0.1717 | 414.4 / 182.8 | 0.3837 / 0.1693 | ✅（差 ≤2.6 px @1080） |

### 7. （调度台追件）`Loc.NotifyLanguageChanged` 逐家 try/catch —— ✅ 已做

```csharp
            int n = h.GetInvocationList().Length;
            try { h(); }
            catch (System.Exception e)
            {
                // 红线：不许静默失败。一个订户抛异常不能连带其它订户（原版 `BroadcastMessage` 也不连带）。

```

**改后形状**（同样 7 行，`Core/Loc.cs:3879-3885`）：

```csharp
            var inv = h.GetInvocationList(); int n = inv.Length;
            // 红线：不许静默失败。🔴 2026-10-31（B106_W12 · AUD03「仍缺」）：逐家 try/catch —— …（就地订正原注释）
            for (int i = 0; i < inv.Length; i++)
            {
                var one = inv[i] as System.Action; if (one == null) continue;
                try { one(); } catch (System.Exception e) { Debug.LogError("[Loc] 换语言广播里有一家订户抛了异常（其它订户照常收到）：" + e); }
```
