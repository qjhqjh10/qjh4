## 一、这一轮打通的（全部实测）

| # | 环节 | 证据 |
|---|---|---|
| 1 | **登录状态强制推进可行** | `LoginManager.currentState` 是**属性**（不是字段）时也能读；实测 `20 → 50` |
| 2 | **`LoginManager.TryCompleteLogin()` 能调通** | 它除了置 50 还会 Invoke `+0x68` 那个 UnityEvent ⇒ 这才是转场触发器，**手动改状态不够** |
| 3 | **转场链完整跑起来了** | `GameBootController.StartGame → EverguildSceneManager.ClearLoadedScenes → SceneChanger.DoChange → LoadScene`，随后活动场景从 **`Intro` 变成 `Simple Transition`**（`heartbeat.tsv` 的 `scene=` 列） |
| 4 | **Addressables 操作调度本身是好的** | 自己调 `Addressables.InitializeAsync(false)`：**2.0 秒 `Succeeded`** ⇒ 不是「操作永不完成」那类问题 |
| 5 | **拿到了主菜单场景的 address key** | 先用错 key 试出 `InvalidKeyException: No Location found for Key=…`；换成 **`MainMenu Warpforge`** 后错误变成 `GroupOperation failed because one of its dependencies failed` ⇒ **key 对了，是依赖（bundle）失败** |

### 位置：`TryCompleteLogin` 的真实调用栈（异常抓出来的）

```
LoginManager.TryCompleteLogin()
 └ UnityEngine.Events.UnityEvent.Invoke()
    └ GameBootController.StartGame()
       ├ PlayerDataManager.FirstTwoTutorialCompleted()
       │   └ PlayerDataManager.IsTutorialIndexCompleted(int)   ← 原本在这里 NRE
       └ EverguildSceneManager.ClearLoadedScenes() → SceneChanger.DoChange()
```

**NRE 根因**：`IsTutorialIndexCompleted` 读 LiveOps 的 GameModes 事件，而我们给的 `InitializeLiveOps` 是 `{}` ⇒ 拿不到事件 ⇒ 空引用。
**当前处置**：`Stubs` 里把 `IsTutorialIndexCompleted` 钉成 `true`（教程视为已完成，直接进菜单）。⚠️ 这是**桩**，不是复刻；真解是把 `InitializeLiveOps` 的 FunctionResult 按真实形状补出来（阶段 2 剩余工作）。

## 二、现在的卡点（精确）

```
Addressables.LoadSceneAsync("MainMenu Warpforge", LoadSceneParameters(Single), true, 100)
  → 2 秒后 Failed
  → OperationException: "GroupOperation failed because one of its dependencies failed"
```

- 场景**位置能解析到**（换了正确 key 之后不再是 InvalidKey）；
- 失败的是**它的依赖**（bundle）。而 `scenes_scenes_mainmenuwarpforge.bundle` **就在本地**
  `StreamingAssets/aa/StandaloneWindows64/`，catalog.bin 里 84 处 `StandaloneWindows64`、**0 个 http**；
- **`getloadedbundle.tsv` 始终为空**（游戏自己的 `AssetBundleManager.GetLoadedBundle` 一次没被调）⇒ 失败发生在 Addressables 内部那一层。

### 下一步要试的（按顺序）

1. **把依赖异常挖到底**：`OperationException` 只是最外层；下一条要读它的 `InnerException` 链 / `StackTrace`，看是哪一层 bundle provider 失败（`AssetBundleProvider` vs 游戏自定义 provider）。
2. **确认游戏是否替换了 Addressables 的 bundle provider**：`AssetBundleManager` 有自己的 bundle 清单（TitleData `AssetBundlesDataPCWin`，枚举 13；DTO `AssetBundleDataPlayfabAll` / `AssetBundleDataPlayfab` / `AssetBundleData`）。本轮已把 84 个本地 bundle 写进该 TitleData（`tools/add_assetbundles_titledata.py`），**但场景加载仍是同一个错** ⇒ 说明这条链没被用到，或形状不对。
3. **验 bundle 本身能不能加载**：绕开 Addressables，直接 `AssetBundle.LoadFromFile("…/scenes_scenes_mainmenuwarpforge.bundle")` 再 `SceneManager.LoadSceneAsync(sceneName)`（`SceneJumpShot` 就是这么干的）——成则证明资产没问题、问题在 Addressables 的依赖解析。
