## §二 每条为什么是**夹具问题**（一句话 + 证据）

1. **X2 B1/B2/B3/C4**：`Quaternion.Euler(-90,0,0)` 的 forward 不是精确的 `(0,1,0)`，而是 `(0, 0.99999996, ±2e-8)`（float 残差）；Unity `Plane.Raycast` 的平行闸是 **`vdot == 0`（精确零）**，于是敌兵平面 `vdot ≈ ±8e-8 ≠ 0` ⇒ `enter = 4/8e-8 ≈ 4.7e7 > 0` ⇒ **判命中**。
   **证据**：实得落点 `(0, 47171730, −4)` —— `47171730 = 4 ÷ 8.47e-8`，而 `z = −4` 正好就是 `enemyRowZ`（命中敌方那面平面的指纹）。被测实现 `TargetReticle.ResolveAim`（`Battle/TargetReticle.cs:511-547`）**是对的，一字未改**。
   **新夹具为什么「结构性」打空**：`dir = (0, .7071, .7071)` ⇒ 地面 `enter = −5/0.7071 < 0`、敌兵面 `enter = 4/(−0.7071) < 0` ⇒ 两条都靠**符号**判假，不靠浮点精度。
2. **X1 F1/F2/F3**（两条独立的夹具缺陷，叠在一起）：
   - ① **反射调 `Update()` 驱动不了**：编辑模式批处理没有帧循环，`Time.deltaTime` 不是可用的正帧长（DG2 §四·1 推定：只有 `deltaTime < 0` 才能让 `updateRate(0) <= accum` 为假 ⇒ 闸门永不开）。⚠️ **这一条本会话没有实测**（见 §五·1）。
   - ② **量角器本身是瞎的**（本会话新发现，可静态证死）：`Quaternion.Angle` 先过 `IsEqualUsingDot` —— 本机 `UnityEngine.CoreModule.dll` 的 IL 是 `ldc.r4 0x3F7FFFEF`（`1 − 1e-6`）+ `cgt` ⇒ **`dot > 1 − 1e-6` 直接 `return 0.0f`**，即夹角 **< `2·acos(1−1e-6)` = 0.16206° 时恒读精确 0**。这个夹具每拍只转 `|ySpeed| = 0.02°` ⇒ **转没转都读 0.000**。
     本工程同一坑已有先例与 IL 现读：`Editor/BattleScene.cs:48485-48504`（`AngleDegTiny` 的 doc 与实现），我当时直接**照抄那份算式**（`θ = 2·atan2(|xyz|, |w|)`，不设 dot 阈值）。
     ⇒ **所以「实测 0°」不能单独当成「`Time.deltaTime` 为负」的证据** —— 它也可能是「转了但量不出来」。两个前提都修掉才稳。
   - 被测语义未改：`Update` 现在只转发 `TickForTest(Time.deltaTime)`，方法体（累加 ⇒ `updateRate <= accum` ⇒ 归零 + `Rotate`）一字未动。
3. **B10 G2**：读口 `ProfileData.EquippedBorder`（`Shell/ProfileData.cs:1339-1349`，`:1344`）**每次读都跑一遍** `RefreshExpiredBorders(NowUtc)`；而本机今天只有下标 0（`Default`，无父活动）可用，下标 1..4 那 4 条限时边框的父活动都在 2025 / 2026-01 ⇒ 一设下标 1 就被**卸回 `Default`**（DG2 贴的日志：`限时边框 EC Release 已不可用 ⇒ 卸下、回到 Default`）⇒ `n1 == n0`。
   **证据链**：`ProfileData.cs:1453-1469`（卸下逻辑）· `:1429-1446`（`IsBorderUsable` 按 `GetState(utc) == Expired` 判）· `LiveOpsState.cs:43-56`（`finalMs = expirable ? expireMs : endMs`）· `Shell/LiveOpsLocalCatalog.cs:487-488`（`ECReleaseScoring`：`endMs = 1750410000000`、`expirable = false`）。
   **新夹具**：把下标 k 那条的父活动 `EndMs`（`Expirable` 时连 `ExpireMs`）临时写成「现在 + 1 天」⇒ `GetState` 落到 `Active` ⇒ `IsBorderUsable` 为真 ⇒ 装备得住。⛔ **没有跳过可用性检查**（那正是原版行为），只是让它的活动**真的在期**；`finally` 里把 `EndMs` / `ExpireMs` 与 `EquippedBorderIndex` **全部还原**。
   **为什么不按 DG2 建议加 `ProfileData.NowUtcForTest`**：`Shell/ProfileData.cs` **不在本代理白名单**（「其余实现文件」）⇒ 按铁律 13·3 的做法，**不改别人的文件**，改在白名单内用等价夹具达成同一个目的。
   若 ProfileData 的写手愿意加注入口，更干净的做法是：`public static DateTime? NowUtcForTest;` + 读口改成 `RefreshExpiredBorders(NowUtcForTest ?? LiveOpsLocalCatalog.NowUtc)`（零行为变化，产品路径不受影响）。
