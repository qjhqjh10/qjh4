## 五 没查清（如实记，⛔ 不当成「原版没有」）

1. **`UIResourceCounter.SetQuantity` animated 支开头那次 `transform.localScale = <静态 Vector3>`** —— 那个值在 `DAT_1842da2a8 → +0xb8 → +0xc/+0x14`（类静态字段，不是字面量），**本轮仍未解析出来** ⇒ 资源条数字滚动**没有那一下缩放**。做这件事要动 `Shell/TopBar.cs`（不在本代理白名单）。
2. **`WarlordMasteryContainer` 的 ③「战报里那条 ownHeroName」语义** —— 原版 `victoriesById` 的 key 与战斗日志 `ownHeroName` 是不是同一套字符串（`UM47` 形态）**没证死**；本仓两边都按「卡 asset 名」落地（`VictoryCountersStore` 文件头已记这条未判定），跑起来若对不上会表现为「永远走 `HighestCardId` 那一支」（不报错）。
3. **`ArmyProgressBar` 的三个实例**（`2Armies Progress Bar` / `Draft Mode Menu Demo` / `Draft Mode Deck Info Panel`）—— 只把前两个宿主接上了（`BuildAlliancePage` / `BuildTimedArmyBar`）；`DraftModeDeckInfoPanel` 那一处在本仓**没有对应窗**（未查它在原版哪一屏）。
4. **`RankedArmyBonusContainer` 两行仍阻塞**（C/B）：那个容器要的「阵营加成清单」是 liveop 服务端数据；`调度台日志:7983` 已定位 prefab 在 `Reward Event Container 1x1`，但**我们连这张卡都没建**（5 张模式卡里没有它）⇒ 建出来只能空卡，而原版 `evt==null ⇒ Destroy(this)` 正说明「没数据就不该有这张卡」。**要真做必须先定本地模拟的加成数据来源**（🔶 服务器相关，§18·0 允许自设计，但要调度台拍口径）。
