## ⑤ 顺手发现（⛔ 本代理没改，只报）

### 5.1 🔴 全仓还有 **1 处**同形缺陷（生产代码，`Shell/SceneInitializer.cs:311-312`）—— **已修**（§3.4）

```csharp
static bool IsSettled(IBaseInitializable i)
{
    if (i == null) return true;
    // ⚠️ 被 Unity 销毁的件（== null 的 UnityEngine.Object）也算 settled —— 否则永远等。
    var obj = i as UnityEngine.Object;
    if (obj != null && obj == null) return true;          // ← :312 恒假，与 TabButtons 那两处**同形**
    return i.Status == InitializationStatus.Initialized || i.Status == InitializationStatus.Error;
}
```

- **同形证据**：`var X = Y as UnityEngine.Object;` 紧跟 `if (X != null && X == null)` —— 与 `B103_D1` §2.2 一模一样。
- **后果**：`:310` 的注释写着「否则永远等」，而这句**永远不会命中** ⇒ 被销毁的件只能靠 `i.Status` 兜底；
  若它在销毁时仍停在 `Pending/Initializing`，`:280` 的 `while (!AllSettled(group)) yield return null;`（协程等待）
  **会永久空转**、**静默**（没有日志）。这正是注释想防的那一幕。
- **只读核过**：`IsSettled` 的生产调用点只有 `AllSettled`（`:302-306`）← `:280` 的协程等待。**不是死代码**。
- ✅ **已按调度台指示就地修**：`:312` 改成 `if (!ReferenceEquals(obj, null) && obj == null) return true;`
  （**没有**为了让这里复用而去改 `TabButtons.IsDeadHandler` 的可见性 —— 参数类型不同，两处语义相同、就地写、注释互指）。
  C 组 9 条断言钉住（活 `Pending` ⇒ false；已销毁 ⇒ true；`AllSettled` 同；灭自证）。
