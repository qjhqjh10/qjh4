## 二、判据（先确认再改，⛔ 不是照施工单硬做）

### S4 —— 原版确实「有在期活动就按它的 `endDate` 建」

`D:/2/tools/decomp_full/SkirmishEventWindow__TryOpen.c`（本节全部实读）：

- `param_1 + 0x70` = 活动实例（`IFastModeEvent`），`param_1 + 0xc0` = `timerDisplay`；
- `iVar1 = *(int *)(配置 + 0x24)`；`SetActive(timerDisplay.gameObject, iVar1 != 0)`，为 0 时 `RefreshScore` 后直接 `return`（= 活动不 active ⇒ 关掉它）；
- 非 0 ⇒ 取活动的虚方法 `puVar5(plVar2, 0, …)` 得到一个值，**原样喂** `TimerDisplay__Initialize(timerDisplay, <该值>, key, 0)`。

`TimerDisplay__Initialize.c`：该实参经 `MillisSinceEpochToDateTime` → `Nullable<DateTime>` → 写进 `+0x78`（**定死**），再 `UpdateTimer`。

⇒ **结论**：截止时刻 = **在期活动实例的 `GetEndDate()`**，且是**开窗时取一次**（不是每秒重取）。
本机 FastMode 表为空（服务端才下发）时取不到 ⇒ 仍走「整棵不建」，这不是「写死不给」。

**为什么是「开窗取一次」而不是每秒现取**（这条决定了实现形态）：若每秒按「当前有没有在期活动」现取，活动一过期目标就变 `null`
⇒ `TimerDisplay.UpdateTimer` 落到「目标未知」那一支（`return;`，`Shell/TimerDisplay.cs:380-390`）⇒ 屏上**冻住最后一格倒计时**；
而原版目标定死后到点走 `remain <= 0` 那一支（清字 + `SetActive(false)` + `OnRunOutOfTime`）。⇒ 取一次 = 与原版同解。

⚠️ **单位**：`LiveOpsLocalEvent.EndUtc` 是 `DateTimeKind.Utc`，`TimerDisplay` 拿本机 `DateTime.Now` 相减（**不认 `Kind`**）
⇒ 必须 `ToLocalTime()`，否则差一个时区（本机 UTC+8 = 少 8 小时）。

### M5 —— `keepAspect`

`Battle/ImageQuad.cs:190` 单参口 = `SetTexture(t, false)`，`:235` `if (!keepAspect && t != null && t.height > 0) _aspect = t.width/(float)t.height;`
⇒ 方形 256² 会把 `_aspect` 冲成 1.0。`Shell/MenuDraw.cs:1684` 在 `ImageQuad.Create` 之后紧跟 `quad.SetAspect((x2-x1)/(y2-y1))`（**裁切后**的框）
⇒ 行内 icon 的 `_aspect` 本是 `143.098/117.71 = 1.2157`；被冲成 1.0 后 `WorldW = WorldH × 1 = 117.71`
（实测 `x 1317.98..1435.69` = 117.71，期望 `1305.29..1448.39` = 143.10）。

`keepAspect: true` 只跳过那一句（`:235`），`_aspect` / `WorldW` / 网格全不动 ⇒ 宽回到 143.098。
它与 `Create()` 那条路（无裁切时 `_aspect` = 框比例）同解 —— 即 s99 之前 `MenuDraw.Rect` 直接画图时的几何，**两路都回到原状**。

## 顺手发现

1. **`Editor/MainMenuScene.cs:9449` 那条断言现在靠「活动表为空」才成立**。它钉的是 `ForceActiveEventForTest = true`（只有布尔，没有结束时刻），所以本窗建出来时 `TimerDeadline` 仍是 null。
   ⇒ 将来谁给那个夹具塞一条真活动（`FastModeEventsOverrideForTest`），这条会**立刻变红**——**红得对**（那时 Timer 应该建）。记在这里，⛔ 别到时候去改实现迁就它。
2. **`TimerDisplay.Attach` 的 delegate 档「目标由有变 null」时会冻住最后一格文本**（`Shell/TimerDisplay.cs:380-390`：`WarnUnknownOnce` + `_expired=false` + `return`，⛔ 不清字、不隐藏）。
   原版走不到这一支（`+0x78` 定死），所以**目前没有偏离**；但任何「目标会变 null」的新消费点都会出现「屏上冻住倒计时」。本件已用「开窗取一次」的形状避开，⛔ 未改 `TimerDisplay`（不在白名单）。
3. **`FactionScore.Initialize` 的 `keepAspect` 与 prefab 的 `m_PreserveAspect=1` 并不等价**（`m_PreserveAspect` 是 uGUI 的等比内接，我们是「铺满框」）。
   账 `未分类_其他.tsv`（`FactionScore` 行）已记「本件不内接、宿主按整框量它」= **既有口径**；本件**没有推翻也没有新增**，只是把 s99 引入的「方图内接」改回该口径。若将来要按 `m_PreserveAspect` 复刻，那是**另一条账**（涉及 `Small 212.63×128.5 / Big 164×145.8` 两格的图源真实尺寸）。
