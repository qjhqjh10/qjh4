## 四、判据证据（本批**新查**的部分）

### 4.1 `ContentSizeFitterMinMax.ClampSize` 逐句

`decomp_full/ContentSizeFitterMinMax__ClampSize.c` 的形状是两条**短路 `&&` 链 + 赋值副作用**：

```
if ((clampWidth != 0) && (v = widthMin,  v <= x) && (v = x, widthMax < x)) v = widthMax;
```

逐条对完 = `x < min ⇒ min` · `x >= min 且 x > max ⇒ max` · 否则原值 ⇒ **就是 `Mathf.Clamp`**。
`y` 轴用 `+0x44/+0x48/+0x4c`（另一组开关与上下限）—— **两轴各自独立，不是一套**。
`SetLayoutHorizontal/Vertical` 的 `.c` 各 3 句：**先调基类、再 `ClampSize()`**。

### 4.2 `UIPreferedSizeFixer`：`preferredWidth = rect.height`，**不是 0**

`decomp_full/UIPreferedSizeFixer__ApplyConfig.c` 末段：
`get_rect(&local_18, rectTransform)` 取四个 float，然后 `(**(code**)(*plVar1 + 0x378))(plVar1, uStack_c, …)` ——
`uStack_c` 是 rect 的**第 4 个 float（= height）**，`+0x378` = `set_preferredWidth`。
🔴 ILSpy 把这一句打成 `float num = default; layoutElement.preferredWidth = num;` —— **那是丢实参**，照它写会把首选宽设成 0。

### 4.3 `__CalculateLayoutInputHorizontal.c` 的内容 = `ApplyConfig`

该文件**首行就是** `void UIPreferedSizeFixer__ApplyConfig(longlong param_1)`。
ILSpy 里两个方法（`:142-152` 与 `:154-164`）也**逐行相同**。
⇒ 结论不是「本方法体在本机读不到」，而是**原版两个方法就是同一份体**。账里那句旧判词本批已就地订正。

### 4.4 `PlaySoundOnTime.Update`：一次调用只播一条

`decomp_full/PlaySoundOnTime__Update.c` 尾部：`*(int *)(param_1 + 0x2c) = … + 1; return;` ——
**没有循环**。我们原来的 `while`（一帧把欠的几条全播掉）在低帧率下会多播、而且几条同时响
⇒ 按 §18·0「默认复刻原版」改成 `if`。

### 4.5 `ShowCardBeingDrawn` 的三个字面量（本轮复读确认）

`工具/read_literal.py "D:/2/unity_run_ref/GameAssembly.dll" 0x1834b2bb0 0x1834b3158 0x1834b2e7c 0x1834b2e04`
⇒ 弃牌 **0.2** · 偷牌 **0.4** · 每段占比 **0.25** · 单段角度 **90**。
我们侧三个常量（`CardFeel.cs:3544/3549/3238/3241`）与 `TurnCardAround` 的 `delay` 形参全部对上。

### 4.6 `GetTargetInPos`：原版**恒返回 null**（本轮反证）

`decomp_full/BattleManager__GetTargetInPos.c:100` 的 `Physics2D.GetRayIntersectionNonAlloc(ray, results, DAT_1834b2bc8, 0)`
—— 距离实参 `DAT_1834b2bc8` = **−1f**（B91 已实读）⇒ **恒 0 命中** ⇒ `if (0 < iVar7)` 那一支永不进入 ⇒
本方法**恒返回 null**，`BattleManager.Update:136` 把它存进 `+0x440` 后判 `op_Equality(result, 0)` 恒真。
⇒ 账 `战斗逻辑驱动:381` 的落点（`TargetReticle.ResolveAim`）**疑似错配**：`ResolveAim` 的真判据是

**因此我们这边的正确改法不在 `CardFeel`**：`CardFeel.HandToBoard`（`Core/CardFeel.cs:2052`）的
`if (card.Face == CardFace.Board) return null;` 是**对的**（Board 形态下没有 2D 卡面可淡，clip 的 ①③④ 三段都失去对象）。
真正缺的是**入口**：`BattleDriver.StartAiDeployFlight` 用 `ImageQuad` 当飞行载体、落地时由 `SyncBoard` **新建一个 Board 形态的视图**
⇒ 那一路的 `HandToBoard` 天然 no-op。

**要补的三步，落点全在 `BattleDriver.cs`（F3 的所有权）**：
1. AI 飞行期间让这张视图**以 Hand 形态存在**（`card.SetFace(CardFace.Hand)`，`SetBody3DVisible(false)`）；
2. 交接点（`aiHandoff.Apply`）**不要新建 Board 视图**，改为调 `CardFeel.HandToBoard(card, onDone)`；
3. 3D 体在 0.1667 那一刻由 `HandToBoard` **自己**打开（`HandToBoard` 的 doc 与实现都在，`SetBody3DVisible(false)` 只在开头那一句）。
   ⚠️ 与 F3 报告里写的「clip 的 0.1667 那一刻 `SetBody3DVisible(true)`」**有一处偏差**：原版 `ToggleBody3D(1)` 是
   **Play 之后立刻**（`.c` 逐句），0.1667 是**动画曲线**里 `Board Elements.m_IsActive` 那个键 —— 两件事，别混。

`CardView.SetFace` / `SetBody3DVisible` / `CardFeel.HandToBoard` 三个口**都是 `public`** ⇒ F3 那侧一行就能接，**不需要本件改任何类**。
⛔ 本件**没有**自己排一个「先退回手牌再变 3D」的回退顺序（B90_B2 禁止），也**没有**为了绕过闸去动 `HandToBoard` 的那道 `Face == Board` 判断。
