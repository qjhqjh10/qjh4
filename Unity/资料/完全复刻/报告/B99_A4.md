## 二 证据（`.c` 原文，逐字）

**① `d:/2/tools/decomp_full/TimerDisplay__UpdateTimer.c:19-21`** —— 方法**第一条**就是：

```c
  if (*(char *)(param_1 + 0x78) == '\0') {
    return;
  }
```

- `+0x78` = `Nullable<DateTime> _target`（`TimerDisplay.cs` 类桩字段序；`Initialize` 里由 `Nullable<DateTime>___ctor` 写入）。
- `== '\0'` = `HasValue` 为假 ⇒ **`return;`**：此时**还没**走到任何 `SetActive`、也没写 `text`
  （方法体里第一处写 `text` 在 `LAB_18088d6a5` 之后，第一处 `SetActive` 也在那之后）⇒ **原版这一支什么都不做**。
- 另外：原版**没有**「`Initialize(null)`」这条路 —— `TimerDisplay__Initialize` 第一句就是
  `MillisSinceEpochToDateTime(param_2)` 再 `Nullable<DateTime>___ctor`（**永远带值**）
  ⇒ `+0x78 == 0` 只出现在「`Initialize` 从没被调过」。这就是本地（没有服务端事件数据）的全部情形。

**③ `d:/2/tools/decomp_full/RankingDisplay__Initialize.c` 尾部**


⇒ **没有结束时刻就根本不会 `Initialize`**；再叠加 ① 的 `return;` ⇒ 那一行建了也只有一个「不动的占位」。
