## 六 顺手发现（4 条）

1. 🔴 **`AttackKind` 是【命名空间级】enum，不是 `AttackSelector` 的嵌套类型** —— 全名前缀应是 `CardPresentation.AttackKind`。
   施工单/文档里如果写 `AttackSelector.AttackKind` 会 `CS0426: 类型"AttackSelector"中不存在类型名"AttackKind"`（我第一版就这么写，被 `typecheck` 当场抓到）。
   ⇒ `AttackTypes` 也一样（`CardPresentation.AttackTypes`，在 `CardView.cs:167`）。
2. 🔴 **`UnitState` 的四个攻击型常量缺 3**（见 §五·1）。这三处（`AttackTypes` / `AttackKind` / `UnitState.AttackType*`）是同一族值域的三份副本，**只有前两份含 3** ⇒ 将来若真要产 3，第三份也得补，否则 `.LastAttackType = 3` 只能用魔数。
3. ⚠️ **账补丁的三个硬约束（本次实测）**：① 第一行必须是那 11 列表头；② 行数必须 11（少一列直接拒绝）；③ `方法` 列必须是**单方法签名带 `(...)`**（`looks_like_one_method` 会拒绝全角括号 / 一格多方法）。
   `merge_ledger_parts.py --dry --only B99_A3` = **更新 1 · 新增 0 · 0 错误**（真合并由调度台做）。
4. 🔴 **我又踩了一次「bash 双引号里写含反引号的 python」**（CLAUDE.md §二 已记的那条坑，这次还叠加了中文）：一条命令把整个 `B99A3_Assert.cs` 写成了乱码（每个汉字变成 `的`）。
   **已整份重写恢复**（现 389 行 / 0 个 `U+FFFD` 替换字符 / `typecheck` 0 错）。
   ⇒ **教训（建议补进坑表）**：凡要写**含中文或反引号**的内容，**一律**走 `Write` 工具或「先写 .py 脚本文件再 `python -I -X utf8 脚本`」，⛔ 不要塞进 `bash -c` / `python -c` 的字符串里（中文字符同样会被嚼）。
