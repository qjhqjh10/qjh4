## 七、操作坑（2026-11-07 收尾补记 · 谁再动这份库存都要照做）

### 7·1 🔴 必须带 `--cosmetics` 跑，否则 1180 件外观会被冲掉

`add_inventory.py` 是**整表重建**：它每次从「卡 id 表 + 硬编码 9 条外观」重新拼一份 `UserInventory` 再覆盖写回
（`:44-89` 先建卡，`:98-120` 只有 `--cosmetics` 才会把 1180 件 `CosmeticItem` 补回去）。

- ✅ **唯一正确命令**：`python -I add_inventory.py --cosmetics --write`
- ⛔ **不带 `--cosmetics`** 就 `--write` ⇒ 外观从 **1187 → 9**，收藏「美容品」页整页空、卡背筛选全空
  （`RemainingUses=1` 的那 1187 条里 1178 条会消失，只有 2 默认头像/边框 + 7 异画留下）。
- 判据：写完必须核 **`RemainingUses == 1` 的条目数 = 1187**（本单 §四 第 3 项就是这么验的）。

### 7·2 🔴 不加 `-X utf8` 也能跑了（但别再往打印行塞非 ASCII 符号）

- **原病**：打印行里有一个 `⇒`（U+21D2）。本机控制台是 **GBK（cp936）**，`print` 到 GBK stdout 直接抛
  `UnicodeEncodeError: 'gbk' codec can't encode character '\u21d2'` —— 而它发生在**写盘之前**
  ⇒ `--write` 会「什么都没写就退出」，看着像没跑。
- **已修（2026-11-07）**：打印行的 `⇒` 换成 ASCII `=>`，并在那一行上方加了注释说明原因。
- **实测**：`cd E:/warpforge/05_工具/server/tools && python -I add_inventory.py --cosmetics`（**不带 `-X utf8`**）
  ⇒ **rc = 0**，正常打印 `… + 52 条通配符 => UserInventory 2590 条`；**不写盘**，
  `playfab_profile.json` 复跑前后 **size 625,317 B / sha1 `f46c92bf…` 不变**、`UserInventory` 仍 2590 / wildcard 仍 52、
  `state/player_state.json` mtime 仍 `1794027654.8163602`。✅ 数据零改动。
- ⚠️ **仍然成立的边界**：
  1. **中文注释/中文字符串在 GBK 下没问题**（GBK 能编中文），出事的只有 `⇒`/`→`/`✅` 这类**符号**；
     终端里中文会显示成乱码，但**不影响逻辑**。
  2. `print("样例:", json.dumps(inv[:3], ensure_ascii=False))` 打印的是卡名，当前全是 ASCII。
     **将来若卡名/外观名里出现非 GBK 字符，同一个坑会复发** ⇒ 要么保持 `-X utf8`，要么把 `ensure_ascii` 改回 `True`。
  3. `PYTHONIOENCODING=utf-8` 在**本机 Git Bash** 下实测**不生效**（stdout 仍是 gbk）；管用的是 `python -X utf8`。

> 两句话记住：**写库存 = `python -I add_inventory.py --cosmetics --write`**（不加 `-X utf8` 也行，但加了更保险）；
> **只验证不写 = 去掉 `--write`**。

### 8·4 你们问的三条，逐条回答

**① `InventoryManager.Add(ItemInstance)` 按什么分流？会不会「找不到 Inventory 就静默 return」？**

- **不按 `IItemInfo.GetItemType()`** —— 全仓**没有** `GetItemType` 这个方法（`grep -n "GetItemType" dump.cs` = 0 命中）。
  `IItemInfo` 只有 `Quantity / ItemId / InstanceID / Add / SetAmount`（`dump.cs:94060-94086`）。
- 真正的分流 = **`item.GetType()`**，也就是 `AssetLocator` 解析出来的那个**资产对象的运行时类型**：
  `Add<T>(T item, …)` 里 `Type type = item.GetType(); … GetInventory(type);`
  （`out_cpp2il_dev_ilspy/InventoryManager.cs:1372-1400`；C 版 `decomp_full/InventoryManager__Add_object_.c`：
  `uVar2 = System_Object__GetType(param_2, …); lVar3 = InventoryManager__GetInventory(param_1,uVar2,0);`）
- **两条「静默路」只有一条是静的**：
  - **找不到资产** = 真静默（只打一行 `error adding item to inventory, couldn't find item <DisplayName> (<ItemId>)` 然后 return）——
    `InventoryManager.cs:1349-1370`。**我们这次踩的就是这条。**
  - **找不到对应 `Inventory<T>`** = **抛异常**（`GetInventory(Type)` 是 `inventories.get_Item(type)` 索引器，缺键抛 `KeyNotFoundException`；
    C 版是 `if (lVar3 == 0) { … FUN_1803f47a0(); }` 不返回）—— `InventoryManager.cs:1294-1298` · `decomp_full/InventoryManager__GetInventory.c`。
    这次**没有** `DESC-EXC`（`inventory.tsv` 里没有这个 kind）⇒ 说明 **`Wildcard` 这把钥匙在 `inventories` 里是有的**（61 个键之一），
    所以问题不在「没有 `Inventory<Wildcard>`」。
- ⇒ 也就是说：**「没有 `Inventory<Wildcard>`」这条已经被日志否掉；「找不到 wildcard 资产」这条与我们观察到的 0 完全自洽**（且它的报错在本机看不到，见 8·2）。

**② `WildcardAssetProvider.GetAssets()` 那 52 个资产的 `GetID()` 是否等于我们写的 ItemId？注册时序如何？**

- **不等于** —— 见 8·3，`GetID()` = 阵营名 + **数字**，我们写的是阵营名 + 枚举名。
- **时序没问题**：
  - `WildcardAssetProvider` 是 MonoBehaviour，挂在 **`Intro.unity`**（guid `410769a45aada64db9ff56bad6526e6b` 在该场景命中 1 处），
    `AssetProvider<T>.Awake()` 里注册（`out_cpp2il_dev_ilspy/AssetProvider.cs`）；
  - 登录时 `DeserializeInventory` 发生在 **13:55:55.165**，`Intro` 场景在 **13:55:43** 就加载完了，`ConfigManager` 20 个配置在 **13:55:55.004** 已经 `configNonNull=20/20`
    （`Latest.log:426` / `inventory.tsv`）⇒ **provider 和 config 都先于库存解析就绪**。
  - 顺带：`WildcardAssetProvider.GetAssets()` 直接返回 `ConfigManager.GetConfig<WildCardConfig>().wildcards`（`WildcardAssetProvider.cs:7-14`），
    所以「配了 52 条」这件事本身也成立（`TitleData.WildcardConfig` 现读 52 条，`Latest.log:425` 也打出来了）。

**③ `WildcardDisplay` 读的到底是什么？**

- 读的是 **`InventoryManager.GetInventory<Wildcard>()` → `GetItems()` → `IItemInfo.Quantity`**，
  **不是** `CollectionManager` 的拥有表，也**没有**二次过滤（只有 `wc.Army == currentArmy` 一条过滤 + 按 `Rarity` 分组）。
  出处：`out_cpp2il_dev_ilspy/WildcardDisplay.cs` `SetCountersText()`；C 版 `decomp_full/WildcardDisplay__SetCountersText.c`
  （`GetInventory<object>` → `*plVar5 + 0x278` 取 Items → `Where` → `ToDictionary(rarity)` → 每档 `Int32.ToString()`）。
- **而且这次它确实跑了**：`Deck Editing Menu.prefab` 里四个 counter 的 TMP 默认文本是 **`999`**（`commonCount/rareCount/epicCount/legendaryCount` 四块 `m_text: 999`）；
  截图 `1107_s142/07_editor.png` 右上显示的是 **`0 0 0 0`**，不是 999 ⇒ `SetCountersText()` 执行到底了、
  只是四档 `GetValueOrDefault` 全落空 ⇒ **`GetItems()` 里没有当前阵营的 wildcard**。这一条把「显示层没接线」彻底排除。
