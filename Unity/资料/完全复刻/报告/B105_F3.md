## 一 · 必须先修的那一条：`RuleEngineTest.cs:14164` 恒假守卫

### 1·1 原状（`git show HEAD` 也是这个）

```csharp
Check(ops2.Count, 3, "★ `Battle Sister` 切成 **3** 条 …第 3 条 = `A1873` 补的 `Talent:`（`createCardInHand`）那份");

```

守卫 `Count == 2` 与**紧邻上一行**的期望 `3` **逻辑上不可同时成立** ⇒ 这条「第 2 条 = heal」**自 2026-10-14 起一次没执行过**。

### 1·2 修法

```csharp
Check(ops2.Count, 3, "…第 3 条 = `Pray:` 的 `triggerability`（账 `A1874`）");
CheckTrue(ops2.Count >= 2, "（前提·不静默）`Battle Sister` 至少切出 2 条 op（上面那条已断 3）");
if (ops2.Count >= 2) Check(ops2[1].Verb, "heal", "第 2 条 = heal");
```

- 守卫改成 **`>= 2`**（= 取 `ops2[1]` 的**安全前提**），不是 `== 3`：若以后条数再变，`== 3` 会把这条断言**再一次静默**跳掉 —— 正是本次要修的那个病。
- 前提**单独一条**（假 ⇒ 红，⛔ 不静默）+ 守卫保留（下标安全）。

### 1·3 「确实能跑到」的三重证据

1. **逻辑**：修前 `Count==2` ∧ 上行 `Check(Count,3)` ⇒ 恒假（`3==2` 为 false）；修后 `3>=2` 为 true ⇒ 执行。
2. **数据（`ruleprobe seg`，同一份 `Core` 源码、同一 `Parse` 重载默认值）**：

```
bash 工具/ruleprobe.sh seg 'Pray: Gain +1 Attack and +1 Ranged Attack and heal 1'
  op: verb=gain   payload=[+1 attack and +1 ranged attack] tail=[heal 1]
  op: verb=heal   amount=1
  op: verb=triggerability payload=[pray]
```

   ⇒ `ops2.Count == 3`、`ops2[1].Verb == "heal"`。`RuleEngineTest` 用的是三参 `Parse(desc, out un, out partial)`（默认 `eventHasTarget=false / whenBody=false / card=null`），与探针 `Parse(line, out …, false, card: null)` **完全同一条路**。
3. **兜底**：即便今后条数再变，`CheckTrue(ops2.Count >= 2, …)` 会先红 —— 不会再出现「条件假 ⇒ 什么都不发生」。
