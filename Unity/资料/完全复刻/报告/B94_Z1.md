## 4 活 4：`CanCollectLogin()` 回源结论（**不改**）

**原版谓词**（一手）
- `cpp2il/out_cpp2il_dev_ilspy/Missions.cs:787`（= `CheckNotification` 里的 `_003C_003Eb__18_1`）逐句：
  `if (!x.canCollect) return false; bool flag4 = x.IsComplete(); return !flag4;`
  ⇒ **`canCollect` 是字段直读**（⛔ 不是 `MissionChallengeProgress.CanCollect()` 那个虚拟方法 —— 那一个还会再查 `RewardsToCollect().All(r.CanCollect())`）。
- `Missions.cs:2139` `CheckNotification()` 第一句 = `new MissionsBadge()`（T1 已核）。

**`canCollect` 由谁写**（`MissionChallengeProgress.canCollect`，字段偏移 **0x48**，判据 `out_cpp2il_dif/.../MissionChallengeProgress.cs:95`）
- 全仓 `grep -rn "canCollect"` 只命中 **2 处写点**，都在 `DailyRewardTrackPanel.cs:81 / :93`（`HandlePurchase` → 买 Premium 通行证成功后的回调）。
- `MissionChallengeProgress` 的 setter **只有三个**（`__set_CurrentValue` / `__set_FailedValue` / `__set_HasFailed`，见 `decomp_full/` 文件表）—— **没有 `set_canCollect`** ⇒ 客户端**没有**「进度到顶 ⇒ 置可领」这条路。
- 它的来源是**服务端**：`decomp_full/Missions__UpdateMissionProgress.c` 里任务进度的更新最终走
  `PlayfabWrapper__GenericCloudScriptHandler(0x38c, …)`（云脚本 handler `0x38c`）⇒ 进度对象连同 `canCollect` 一起由服务端下发。
  ⚠️ 方法层面用 ILSpy 全树搜 `canCollect =` 属**弱否定证据**（clas 名/字段名可能被反编译吃掉），所以我又做了两条交叉：
  ① `out_il2csharp/Assembly-CSharp/MissionChallengeProgress.cs` 里它只有 `public bool canCollect; // 0x48` 一个裸字段、**没有 setter 方法**；
  ② `MissionChallengeProgress` 的全部 `decomp_full` 产物里没有写 0x48 的 setter。

**为什么这会让「Missions / 导航 Rewards 两颗红点常亮」变成「不是缺陷」**
1. 原版 `canCollect` 什么时候为真 = **服务端判据**，关服后本机**永远拿不到** ⇒ 按铁律 18·0 / 红线「⛔ 别自己发明一条原版没有的闸」，**不能**自造一条「今日登录挑战已完成」的闸。
2. 我们的登录卡是**单奖励模型**（`DailyData` 的 `MissionProgressView(max = 1)`）：`_loginState` 只有 `InProgress / Claimed`，
   `CanCollectLogin()` = `_loginState != Claimed` ⇒ 在单奖励模型下**恰好等于** `canCollect && !IsComplete()` 的合取：
   · `canCollect` 这一半在原版里「只要你今天登录过、还有一份没领的登录奖励」就是真 —— 而**你在玩 = 你今天登录过** ⇒ 恒真；
   · `!IsComplete()` 这一半 = `_loginState != Claimed`。
3. ⇒ 出厂态 `CollectableMissionCount() >= 1`、两颗红点每天都亮到领掉为止 = **原版行为**（每天登录给一份），**不是 bug**。
   断言 ⑤ 把这条事实锁住（并写明：若将来按原版 7 天登录轨重做，这条要跟着改）。

**还差什么（如实记）**：原版 `DailyLoginChallenge` 是 **7 天循环轨**（`MissionChallenge.loopable` + `sequentialDays`，`decomp_full/DailyLoginChallenge__Execute.c` / `_Execute_b__3_0`），
我们只有「今天一份」这一格 —— 这是**奖励轨模型**的缺口（另案，不属本件），但它解释了为什么原版那颗红点「亮一天就灭一次」而我们也是。
