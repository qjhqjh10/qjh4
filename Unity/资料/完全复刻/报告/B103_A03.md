## ⑤ 顺手发现（⛔ 不在本批范围，交调度台分流）

1. **连登窗（`DailyStreakPopup`）大部分文案是英文常量，根本没接本地化**：
   `DailyData.StreakCurrentLabel()` = `"Current streak:"`（自注「我们挑的」）· `MoreRewardsInText()` = `"More Rewards In"` · `StreakBrokenText()` = `"STREAK BROKEN"` · `StreakLostText()` = `"Streak lost: " + N` · `ResetStreakText()` = `"Reset Streak"`。
   而 `DailyData` 自己的注释说 `MoreRewardsInText` 是**原版 prefab 的占位串**（运行期由 I2 词条覆盖）⇒ **本窗换语言时这些字不会变**，与原版不符。判据缺口：五条词条的原版 `mTerm` 还没逐条核出来（只有 `StreakClaimText` / `StreakInfoText` 两条核过）。
2. **`Loc.NotifyLanguageChanged` 的 `try/catch` 其实不「逐家兜底」**：注释写「一个订户抛异常不能连带其它订户」，实现是 `try { h(); }`（整条组播调一次）⇒ 第一家抛异常，**后面的订户一个都收不到**。本次没有改它（不在白名单语义里、也怕动到主菜单那条链），但我的登记表走的是**自己的逐家 `try/catch`**；建议后续把 `h()` 改成 `foreach (var d in h.GetInvocationList()) try { d(); } catch …`。
3. **`TimerDisplay` 的订法是 `Awake`/`OnDestroy` 自订自摘**（`:287-288`）—— 与 §② 里「批量模式不派 `OnDestroy`」那条已知坑同族。生产（真 Play）没问题，**编辑器批处理**下会留已销毁订户；`NotifyLanguageChanged` 的现有 `try/catch` 包住整次调用 ⇒ 一颗炸掉会让**它后面所有订户**（含主菜单重摆）都不跑。建议与顺手发现 2 一起改。
4. **`CardDisplayWindow.SolidTexFor` 原本是 `internal`**，而断言宿主在**编辑器程序集**（本仓无 `InternalsVisibleTo`）⇒ 本条若要断就必须开 `public`。已开，并在该行写了理由；其它 `internal` 自检口若以后要给断言用，同样得开。
5. **`Shell/RewardWindow.cs` 与 `Shell/RewardsWindow.cs` 里**没有一句 `Loc.T` —— 它们的文案都经 `RewardsData` / 页签类二次转手，**做 #94 剩下的绑定时要先认准「哪个口才带词条」**，别在窗文件里硬塞字面量（铁律：两处写同一条规则 = 迟早不一致）。
