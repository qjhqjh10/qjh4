## ⑥ 顺手发现（可能影响别人）

1. 🔴 **`AudioSetup.CreateSnapshots` 必须停用**（已就地改成只打 LogError）—— 它会在**主 mixer** 上新建同名快照，跑一次就把「快照落在子 mixer」这个结构拉回旧样子，而且留下**空值**快照。
2. 🟠 **`AudioSetup.SnapshotValuesTable` 原来是「单 mixer 投影」**，不是原版值本身。子 mixer 一建回来它就会指错组 —— 已换成 27 格逐格表。**任何按旧表语义写的文档/账都要跟着改**。
3. 🟠 **`工具/setup_audio_mixer.py` 会从 `工具/_audio_mixer_base.yaml` 重生成** ⇒ 若不同步补步骤 ④，重跑一次就会把 `-50` / `VolumeMaster` / 快照值全抹掉。**已修**（并实测重跑产出与现有文件只差两处无害项）。
4. 🟡 `Editor/B107_W15_Assert.cs:280-288` 断言 `WarpforgeAudio.MusicGroup` / `WFSoundPlayer.FxGroup` 非空。**若 4-1 红（子 mixer 认不出来），这两条会跟着红** —— 那是**正确信号**，别当成新 bug 去改断言。
5. 🟡 `WarpforgeAudio.ParamsOk` 我**故意没扩成 8 条**（`AudioSnapshotCheck` / `PlayerBoot` 依赖它的 4 条语义 + 文案）⇒ 8 条另开 `AllParamsOk`。以后谁要改 `ParamsOk`，记得这两个消费方。
6. 🔵 `Editor/B109_E19_Texture3DBuild.cs:141` 曾有一条 `CS0136`（`byte[] b` 与外层同名）、`Shell/RewardWindow.cs:1462` 曾有 `CS0103 NewCardBadgeOn` —— **都不是我的文件**，只是 typecheck 时被一起编进来；两者各自修好后全仓已回 **0/0**。
7. 🔵 `Main Mixer.mixer` 里那条 `Snapshot` 我按原版连 **pitch 的 5 格**一起写了（原版 `m_FloatValues` 就是 5 音量 + 5 pitch）。旧文件只有音量两格。
8. 🔴 **首跑 `AudioSetup.Verify` 报 14/16，两条第 7 条的「期望」是空串 —— 是【检查自己的 bug】，不是资产 bug。**
   根因：`MixerYaml.GroupFileId` 写成了 `Dictionary<string,int>` + `int.TryParse`，而 Unity 的 local fileID 是 **Int64**
   （本工程实测 `1621529463892821992` / `-7176780287274492476` / `1611842700211643575` / `2510090633941230439` 四个都**溢出 Int32**，
   只有 `Master = 24300002` 装得下）⇒ 表里只剩 `Master`，`Music`/`FX` 取不到 ⇒ `wantM`/`wantF` 为 null ⇒ 期望值渲染成空串。
   已改成 `Dictionary<string,long>` + `long.TryParse`；改后离线复核 `wantM = {fileID: 1621529463892821992, guid: b4f23f9c…, type: 2}`
   与 `Music.mixer` 的 `m_OutputGroup` **逐字相同**，`wantF` 同理。**资产本身一直是对的**（第 2 条「子 mixer 输出组 == 主 mixer 同名组对象」本来就过了）。
   ⚠️ **教训**：Python 镜像用的是任意精度 `int`，**验不出 C# 的整数宽度问题** —— 这类「解析出来的数字」必须按目标语言的最小宽度再审一遍。
