## 二 uv 方案（这是任务单第 ③ 条，也是「会不会改坏观感」的答案）

### 2·1 结论：**每一块拿 sprite 自己的那一段 uv，和 uGUI 一模一样**

判据 = uGUI `Image.GenerateSlicedSprite`（`Image.cs:1160-1178`）：

```csharp
s_UVScratch[0] = new Vector2(outer.x, outer.y);   // (0, 0)
s_UVScratch[1] = new Vector2(inner.x, inner.y);   // (0.40625, 0.40625)
s_UVScratch[2] = new Vector2(inner.z, inner.w);   // (0.59375, 0.59375)
s_UVScratch[3] = new Vector2(outer.z, outer.w);   // (1, 1)
```
`inner = GetInnerUV(sprite)` = `m_Border / m_Rect` 归一化 = **52/128 = 0.40625**（四边同值），
`outer` = `textureRect` 归一化 = **(0,0)–(1,1)**（贴图就是 128²、sprite 占满）。

⇒ 九块的 uv 分段（两轴相同）：`[0, 0.40625] · [0.40625, 0.59375] · [0.59375, 1]`。

### 2·2 「观感会跟着变」的真相：**变的是原来的错，不是引入新的差异**

这颗 shader（`WFUIBorderHighlight.shader:199-203` 现读）只把 **网格 uv `i.uv.xy`** 喂进
`uv2 = puls*(uv − 0.5) + 0.5 + nz`，再拿 `uv2` 采 `_MainTex`（边框形状来自它的 `.a`）。
- **过去（整张拉伸）**：uv 跨 0→1 铺满整个 quad ⇒ 八边形被按 2.80 : 3.81 **整体拉开**，而且 `puls` 会在整张图上收缩。
- **原版（九宫格）**：9 块各带自己的 uv 子矩形进**同一颗 shader** ⇒ `puls` 在每个分段内部收缩、块与块在边界处 uv 连续
  （块 0 右边界 = 块 1 左边界 = 0.40625）⇒ 环是连续的、角块不拉伸。

⇒ **我们现在的做法就是原版的做法**；任务单担心的「uv 一变观感就变」这件事，**在照抄 uGUI 之后是自动对齐的**，
⛔ 不是「我们挑了一个近似」。反证：如果给每一块都塞完整 0–1 的 uv（= 每块画一整张八边形），
屏幕上会出现 **9 个八边形** —— 那显然不是原版。

### 2·3 另外两条 uv 通道**不受影响**（必须写清，否则会被误判成回归）

| 通道 | 来自哪 | 九宫格后会不会变 |
|---|---|---|
| 片元里的 `sp`（屏幕 UV，喂 `_Noise_R` 与 `p` 的极坐标） | VS 的 `ComputeScreenPos`，与原版 `SV_POSITION / _ScaledScreenParams` 等价 | **不变**（跟几何位置走，不跟 uv 走） |
| `uv0.zw`（极坐标原点） | `UIViewportUvWriter` 写 `camera.WorldToViewportPoint(transform.position)` | **不变** —— 这正是必须做「一个网格」的原因，见 §三·2 |
| `i.uv.xy`（采 `_MainTex`） | 网格 uv | **变了，而且应该变**（= 原版的九宫格 uv） |

### 3·2 为什么必须是「一个网格里 9 块」，而不是复用现成的 `CreateNineSlice`（9 个子 quad）

三条**判据级**理由，任何一条不成立这条活都是错的：

1. **`uv0.zw`（极坐标原点）**：原版 `UIBorderGlow.ModifyMesh` 给**整张 Image 的每个顶点写同一个值**
   （`d:/2/tools/decomp_full/UIBorderGlow__ModifyMesh.c:59-110`，循环外算一次），我们由 `UIViewportUvWriter` 写。
   9 个子 quad ⇒ 每个子件各写自己的 `transform.position` ⇒ **9 个不同的圆心** ⇒ 径向揭开会碎成 9 块。
2. **`AnimateUIMaterialProperty` / `UIBorderGlow` 都按单个 `MeshRenderer` 挂**
   （`CardDisplayEffects.cs:365` 的 `quad.gameObject.AddComponent<UIBorderGlow>()`、`:402` 的 `Attach(quad.GetComponent<MeshRenderer>(), …)`）
   ⇒ 9 个子件只挂得上其中一块，其余 8 块不亮。
3. **uGUI 自己也是一个 `Image` 生成一张含 9×4 顶点的网格**（`Image.cs:1180-1200` 的 `toFill` 单次 `Clear()` + 9 次 `AddQuad`）
   ⇒ 单网格 = 原版形状。
