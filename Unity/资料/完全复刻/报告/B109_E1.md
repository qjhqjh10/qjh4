## 三、断言覆盖（`Editor/B109_E1_SettingsPersist_Assert.cs`）

入口：`Run()`（A，自包含）· `RunInitialValue(win)`（B）· `Run(win)`（A+B，输出两段合计）。
数据：`SaveCenter.OverrideRoot` 注入**临时目录**（跑完删除）、`LocalPlayerDataStore.PersistOverride = true`（不动 mixer / PlayerPrefs / `targetFrameRate`）。

### A 段（`Run()`）——「改 → 存 → 重读 → 仍是新值」

1. **前提**：`SaveCenter.StoreOn = true`（临时根已注入）· 临时目录里**还没有**总档（`ReadDataFromFile() == null`）。
2. 写第一组「都与出厂值不同」的值：`vsync = false`（出厂 true）· `FPSLimit = 0`（出厂 2）→ `SavePlayerData()` 回 true → `ResetForTest()` 清进程内缓存 → `ReadDataFromFile()` ⇒ **`d.vsync == false` · `d.fpsLimit == 0`**（判据：`PlayerDataManager.cs:10241-10242`）。
3. **灭自证**：换一组**相反**的值（`true` / `1`）再走一遍 ⇒ 读回必须是第二组（挡「恒返回某个固定值 / 读出的是出厂值」）。
4. **「重开游戏」**：把 `GameStaticData` 先摆成与档**不同**的值，再 `LoadPlayerData()` ⇒ **`GameStaticData.vsync == true` · `GameStaticData.FPSLimit == 1`**（判据：`PlayerDataManager.cs:10397-10398`）。

### B 段（`RunInitialValue(win)`）——「初值取自已存值」+「关窗真的会存」

1. **前提**：`win != null` · `win.Manager != null`（重开窗要经它）。
2. **前提·分辨力**：`Application.targetFrameRate = 144`（反查档 **2**）与 `GameStaticData.FPSLimit = 1`（档 **1**）**必须不同** —— 否则这条断言证明不了任何事。
3. `win.Close()`（= 原版 `SettingsMenu.Close` 那一条链）⇒ 从临时档根读回：**`fpsLimit == 1`**（🧨 删掉 `Close()` 开头那句 ⇒ 读不到档 / 读回旧值 ⇒ 红）。
4. `manager.OpenWindow(win)` 重开 ⇒ `Build()` → `BuildGraphicsPage()` 重跑 ⇒ **`win.FpsIndex == 1`**（🧨 改回 `FpsIndexOfTarget(Application.targetFrameRate)` ⇒ 会摆成档 2 ⇒ 红）。
5. 全程拦下副作用：`VSyncSetterOverride = c => { }`（不写脏工程 `QualitySettings`）· `ApplyGraphicsChangesOnClose = false`（关窗别把哨兵 144 覆盖掉）· `PersistOverride`（不写 PlayerPrefs）· 跑完全量还原 + 删临时目录。

**接入（本代理不动宿主）**：`Editor/SettingsScene.cs` 里
`B109_E1_SettingsPersist_Assert.Run(win); _sink.Pass += …Pass; _sink.Fail += …Fail;`

## 五、顺手发现（该立账 / 该派活，本代理**没做**）

1. 🔴 **启动读档后没有把 `vsync` / `FPSLimit` 应用出去**（**玩家可见**）：
   - 我们的 `LocalPlayerDataStore.Apply()`（`Shell/LocalPlayerData.cs:265-273`）只把值灌进 `GameStaticData` 的**栅格**，**不写** `QualitySettings.vSyncCount` / `Application.targetFrameRate`。

   - ⇒ **后果**：本批修好之后，「档里的值」与「设置窗显示的值」都会保留（B 段断言覆盖），但**重开游戏后实际帧率/垂直同步仍是平台默认，直到玩家开一次设置窗再关掉**。
   - ⇒ 建议：调度台立一条账，落点 `Shell/LocalPlayerData.cs` 的 `Apply()` 尾部（`if (!PersistOverride) { QualitySettings.vSyncCount = GameStaticData.vsync ? 1 : 0; Application.targetFrameRate = TargetFramerateFor(GameStaticData.FPSLimit); }`）。
   - ⚠️ **我没顺手做**的理由（铁律 14 判据 ①②③ 里第 ② 条不完全成立）：`QualitySettings.vSyncCount` 的写入会**写脏工程的 `QualitySettings.asset`**（`Shell/SettingsWindow.cs:4721` 那条注释就是为此写的，`VSyncSetterOverride` 这个自检注入口也是为它建的）——进来一次 Play 就写脏一次，属于「需要先定一条编辑器安全路径」的改动，不是一笔能静默带过的。
2. 🟡 **`SettingsWindow.ApplySettingsOptions()`（static，`Shell/SettingsWindow.cs:6913`）今天是零调用者**，且它内部用 `FpsIndexOfTarget(Application.targetFrameRate)` **反推**档位再写回 —— 与 B 段同一族「读已应用值」的旧写法。原版这个方法的调用方在读档/登录链（P3）。⇒ 将来若要把它接进启动链，**先把它改成读 `GameStaticData.FPSLimit`**，别再留第二份「反推」口径。
