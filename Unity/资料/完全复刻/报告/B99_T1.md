## 2. 判法说明

### 2.1 怎么取 `.c` 首行
Ghidra 输出的函数签名**会折行**（第一行常常是空的、或只有返回类型，函数名/参数在下一行），且文件是 **CRLF**。取法：
1. **二进制**读（`open(...,'rb')`）→ utf-8 解码 → 按 `\n` 切、去行尾 `\r`（避免文本模式把 `\r\r\n` 折成两行、行号/内容错位）。
2. 从**第一个非空、非注释行**起，**连续拼到出现 `(` 为止**（最多 8 行），得到一个完整签名串。
3. 签名里 `(` 之前的 token 序列：**最后一个 token = 函数名**，**其余 = 返回类型**。
   - 兼容 `undefined8`（合法 8 字节返回）、`undefined8 *` / `char *`（`*` 是独立 token，被并进返回类型）这类多 token 返回类型。
   - 例：`undefined8` + `AI__SelectBestAttackAction(...)` 两行 → 函数名 `AI__SelectBestAttackAction`、返回 `undefined8`。

### 2.2 怎么处理「文件名 ≠ 内容」
**一律用【内容第一行里的函数名】去 dump.cs 查声明，绝不用文件名。** 本库文件名与内容不符很普遍，实测证据：
- `AI.__c__DisplayClass15_0__.ctor.c` 里装的是 `<>f__AnonymousType31___ctor`；
- `CollectionManager.__c__DisplayClass12_0___GetRawCardFromId_b__0.c` 里装的是 `BattleManager_<>c__DisplayClass337_0__<ApplyOffensiveAndDefensiveEffects>b__1`。

（这类多来自 ICF 折叠/共享体。工具按内容名判，因此「这条 `.c` 的内容到底是不是它文件名那个函数」由**内容名**回答——复刻时也应以内容名为准。）

### 2.3 dump.cs 侧：名字怎么对得上（Ghidra C 名还原）
dump.cs 把**命名空间写在类型声明上面一行注释**（`// Namespace: X`），类声明本身**不含**命名空间；**嵌套类型**才用点写进类名（`AI.<>c__DisplayClass15_0`）。据此构造 C 名：

```
C名 = (命名空间 + '.' + 类声明名，嵌套类沿用它最外层顶层类的命名空间)
       把所有 '.' 换成 '_'，再拼 '__'，再拼方法名（方法名以 '.' 开头时把首字符换成 '_'）
```

实测吻合的式子：
- `BattleManager.DrawCardFromDeck` → `BattleManager__DrawCardFromDeck`
- `AI.<>c__DisplayClass15_0.<X>b__0` → `AI_<>c__DisplayClass15_0__<X>b__0`
- `AI.<>c..cctor` → `AI_<>c___cctor`（`.cctor` 的首 `.` → `_`）
- `Azure.StorageServices.Auth.CreateAuthorizedStorageRequest` → `Azure_StorageServices_Auth__CreateAuthorizedStorageRequest`
- `DG.Tweening.DOTweenModulePhysics.<>c__DisplayClass0_0.<DOMove>b__0` → `DG_Tweening_DOTweenModulePhysics_<>c__DisplayClass0_0__<DOMove>b__0`

按此规则，**匹配率 91.3%**（22,911 / 25,096）。

### 2.4 什么算「降级」、什么算「未匹配」（不算降级）
| 归类 | 含义 | 计入降级？ |
|---|---|---|
| `降级_void` | `.c` 首行返回 **void**，dump 声明**非 void** | ✅ 严格丢值 |
| `降级_裸undefined` | `.c` 返回裸 `undefined`，声明非 void | ✅（本次 0 例） |
| `降级_未定指针` | `.c` 返回 `undefined*`，声明非 void，且声明类型**不是**已知结构体 | ✅ 需人工（本次 7 例） |
| `疑似_结构体按值` | `.c` 返回 `undefined*`，声明是**值类型/结构体**（Vector3/Color/ObscuredXxx/ValueTuple…） | ❌ Ghidra 用 `undefined8*` 表示结构体按值返回，**不是**丢值 |
| `异常_c非void声明void` | `.c` 返回非 void，声明 **void**（Ghidra 把寄存器尾值当返回值，噪声） | ❌ |
| `一致_都void` / `一致_都非void` | 两边一致 | ❌ |
| `未匹配` | 内容函数名在 dump.cs 里**找不到**声明（多为泛型实例 / `FUN_` / thunk） | ❌ 不计降级 |

> 另有一列 `体标志 = 疑似丢值(体)`：声明非 void、且函数体里**只有 `return;`（无带值 return）**。它只在 `降级_void` 上出现（1,770 里 781 条命中），是对「确实丢值」的二次确认。

## 6. 已知边界（会误报 / 漏报的地方）

**可能误报（报成降级但不是真丢值）**：
- **`降级_未定指针`（7 条）** 和 **`疑似_结构体按值`（341 条）** 都源于 Ghidra 用 `undefined8*` 表示「结构体按值返回」。已用值类型白名单把 341 条归到「非降级」；但白名单外的**少数类也可能其实是 struct**（如 `BattleAction`/`PlayerBattleData`/`CustomDeckData`/`MonoScriptData` 是否 class 未逐一确认）⇒ 这 7 条保留为「需人工判」。`undefined8*` 若对应真实引用类型返回，才是真降级。
- `一致_都非void` 里若声明返回是引用类型而 `.c` 是 `undefined8`（非 `*`），本工具**不视为降级**（Ghidra 对引用类型常用裸 `undefined8`），可能漏报「引用被当标量」。

**会漏报（真丢值但没被抓到）**：
- **未匹配 2,185 条**：其中 **1,768 条是泛型实例**（Ghidra 用具体类型实参，如 `FastCall<object>`，而 dump 声明是 `FastCall<T>`，名字对不上）；**299 条是 `FUN_`/`thunk_`**；其余 118 条其他。这些里若有非 void 被吞成 void，本工具看不到 ⇒ 泛型类的返回值降级是**盲区**（可用 CLAUDE.md 记的 `decomp_generic_trial`/VA 反汇编补）。
- **解析失败 0**：本库全部 `.c` 首行都能解析出 `返回类型 + 函数名`。但若将来 Ghidra 版本变化（比如首行变成 C++ 符号、或返回类型跨多行带结构体名），可能解析失败（已按「拼到 `(` 为止、最多 8 行」兜底）。

**判法本身的边界**：
- C 名还原规则是**实测归纳**（命名空间→`_`、类型→方法→`__`、`.ctor/.cctor` 首点→`_`）。个别命名（显式接口实现 `IFoo.Bar`、泛型方法 `Foo<T>`、以及 IL2CPP 转义名 `_003C_`/`_003E_`）可能对不上 → 落到「未匹配」，**不会误判成降级**（安全侧）。
- **文件名≠内容**：工具按内容名判，正确；但这也意味着「该文件名对应的函数」可能根本没被导出（内容是别人的共享体），这类文件**对复刻无用**，别按文件名去用。
- `异常_c非void声明void`（11 条）是 Ghidra 把寄存器尾值当返回值的噪声（多为 `Update`/`ShuffleDeck` 这类 void 方法），**以 dump 声明 void 为准**，不算降级。

**只读承诺**：本工具只 `glob` + 二进制读 `d:/2/tools/decomp_full/*.c` 与 `d:/2/tools/il2cpp_out/dump.cs`，**不写/不删 `d:/2` 任何字节**；输出只写到 `--out` 指定的路径（不给 `--out` 就打到 stdout，绝不默认覆盖文件）。默认不带 `--scan` 时**只打印用法并退出**。
