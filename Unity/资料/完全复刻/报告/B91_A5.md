### 取时点 = `EvtKind.StatusApplied` 且关键词 = `bloodthirst`

为什么不用「Slay 触发」那一条 `EvtKind.Trigger`：

- `FireTriggerAt` 的 `emitSignal` 在**入队那一刻**就发（`RuleCore.cs:12562` 附近）⇒ 正文还没跑，
  此时 `u.KwValue(bloodthirst)` 还是 **0**，会把状态框的计数器印错。
- 改挂 `StatusApplied`：`gain … this turn` 走 `give`/`gain` op（`EffectResolver.cs:1122` → `DoGive` → `ApplyOneGain`），
  授予那一跳**必发** `EmitStatusApplied`（`EffectResolver.cs:12038`，条件 `added && val > 0`；
  发射口 `:7961` 把**关键词塞 `CardId`**、`Player/Slot` = 载体）⇒ 正好是「Slay 正文（含治疗）结算**之后**」，
  与原版 logic 序 `heal(20) → buff(40) → highlight(480)` 一致，且此时值已是 1。

## 四 ⚠️ 与施工单的偏离：没有新增 `EvtKind.BloodThirstHighlight`

施工单 §三·1 要求「`BattleEvent.cs` 加 `EvtKind.BloodThirstHighlight`」，但：

   `EvtKind` 的实际家是 **`RuleEngine/Core/BattleEvent.cs`**（属于「⛔ `RuleEngine/**` 一律不动」）。
2. **加一档的连带面在白名单外**（现读核过）：
   - `CardPresentation/Battle/EventTiming.cs` —— 未登记的档 ⇒ `BattleScene.Run` 的「`unsourced == 2`」
     （`CardPresentation/Editor/BattleScene.cs:2500`）与 `EngineClosedDeckAssert` §B1（`RuleEngine/Editor/EngineClosedDeckAssert.cs:175`）**双红**；
   - `RuleEngine/Editor/RuleEngineTest.cs:16271` —— `Check(kinds.Count, 21, …)` 是**硬编码的成员计数**，加一档必红；
   - 本文件还要一个 `case` 消费分支。
   ⇒ 三处里**两处**在白名单外，且都是「不加就红」的护栏。
3. 本条本质是**纯表现信号**，改用既有 `StatusApplied` 取时点后：**零 `EvtKind` 改动、零断言改动、零指纹改动**，
   且**不产生死枚举成员**（`BattleEvent.cs` 尾注明确「加成员必须同时有发射口与消费口，否则是死代码」）。
4. ⚠️ 因此生产点落在**表现层**（按事件流近似），而不是施工单 §8·4 写的「`RuleCore` 里 SW34 的 Slay 正文结算之后」——
   后者要求的 `RuleCore`(A2) / `EffectResolver`(A1) 都在白名单外。这一档与账
   `战斗界面_HUD:766` 早已记下的「**事件模型等价（走事件而非排队）**」是同一条口径。

**若调度台要补 `EvtKind.BloodThirstHighlight` 那一档**，需要动的是上面 §四·2 的两处护栏 + 本文件一个 `case`；
本笔**没有**动它们（越白名单）。
