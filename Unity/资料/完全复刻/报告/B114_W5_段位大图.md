## 七、🔴 `RankArtName` 的**反证**：它和 `DivisionArtName` **不同构**，只能夹下越界

派工说明里写「它的 doc 自己写着 `GetRankData` 与 `GetDivisionData` **同构** ⇒ 越界也该按原版夹取」。
回源核了机器码，**这条前提只对一半**，所以我没有照「两边都夹」做：

| 函数 | 机器码 | 越界行为 |
|---|---|---|
| `RankedDivisions__GetDivisionData.c:26-33` | `Math.Max(n,1)` → `FirstOrDefault` → **`if (null) Last()`** | **下越界夹到 1、上越界落到最后一条**（永远有图） |

## §六（写手 `W-55` · 2026-11-01）：`A4c` 快照化 —— **断言写错、实现无缺陷**

### 6.1 红的是什么

`MainMenuScene.Run` 唯一红：`[B114W5] ✗ A4c🧨 段位 1 与 7 画的是**两张不同的贴图`。
`B114_R11` 已判：**实现没问题，是断言自己跨了一次整窗重建**（静态链闭合，见 `判据/B114_R11_W5_A4c诊断.md`）。

### 6.2 为什么原来的写法必红（改前）

```csharp
win.DivisionNumber = 1; win.Show();
var q1 = win.DivisionNode.GetComponent<ImageQuad>();   // 第 1 次 Show 后的 quad
win.DivisionNumber = 7; win.Show();                   // ← 这里整窗重建
var q7 = win.DivisionNode.GetComponent<ImageQuad>();
Ok(q1 != null && q7 != null && q1.Texture != null && q7.Texture != null && q1.Texture != q7.Texture, "A4c …");
```

链：`Show()` → `Build()` → 首句 `MenuDraw.ClearChildren(transform)`（`RankedSeasonEndedWindow.cs:167`），
**非 playing** 下走 `DestroyImmediate`（`MenuDraw.cs:145`）⇒ 第 2 次 `Show()` 之后 `q1` 是**已销毁的 Unity 对象**；
Unity 对 `UnityEngine.Object` 重载了 `==`/`!=`，**已销毁对象 `!= null` 恒为 `false`** ⇒ `Ok(false, …)` ⇒ 必红。
**与实现对不对无关**：即便实现改成「复用同一颗 quad 只换贴图」，`q1.Texture` 也会在重建时被换成 `07-Legend` ⇒ 同样必红。

### 6.3 改法（改后）：**跨重建的东西一律快照成值，不持活对象**

```csharp
win.DivisionNumber = 1; win.Show();
var q1 = win.DivisionNode != null ? win.DivisionNode.GetComponent<ImageQuad>() : null;
var t1 = q1 != null ? q1.Texture : null;              // 快照 Texture 引用
string n1 = t1 != null ? t1.name : null;              // 快照名字（值）
…
win.DivisionNumber = 7; win.Show();
var q7 = …
var t7 = q7 != null ? q7.Texture : null;
string n7 = t7 != null ? t7.name : null;
Ok(t1 != null && t7 != null && t1 != t7 && n1 != n7,
   "A4c🧨 …（现读 1 = `" + n1 + "` · 7 = `" + n7 + "`）｜🧨 实现里把图名写死成一张 ⇒ 1 与 7 相同 ⇒ 红");
```

**为什么快照化才对**（而「改成 `q7 != null && q1 == null` 之类」不对）：
① `ImageQuad` 的**生命周期只到下一次 `Build()`**，它承载的信息（`Texture`）**不随它一起死** —— 断言要判的是「两次画的图不同」这件事，判的是**值**；
② **快照 `Texture` 引用是安全的**：`CardArt.Release` 明确**不销毁贴图**，且 `ReleaseArtUnder` 只放
`CardArt.IsPerItemArt` 命中的路径（`cards/art_` · `cardbacks/` · `avatars/` · `altarts/` · `ui/flavourbg_` · `ui_menu/Cursor_`），
`ui_menu/01-Rook` / `ui_menu/07-Legend` **都不命中** ⇒ 重建后 `t1` 仍指向同两张真图；
③ 于是 `t1 != t7`（**不同对象**）+ `n1 != n7`（**不同名字**）**两条一起判** —— 只判名字会被「同一张图换名」蒙过，只判引用会被「同一贴图两个加载实例」蒙过；
④ 顺带把 **A4/A4b 也换成读快照**（`n1`/`n7`），三处判的是**同一份快照值**，不会出现「A4 读活对象、A4c 读快照」两个口径。

**顺带修掉的第二个缺陷（原文案的）**：`A4c` 原来**不打印任何现读值** —— 红的时候从日志里看不出「两张各是什么」，
只能回去读实现。现在文案里带 `现读 1 = … · 7 = …`。
