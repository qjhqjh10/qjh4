## 三、做法与三条坑

1. 原版侧：UnityPy 开 bundle → 按 `PathID` 取 Mesh typetree → `m_StreamData.(path, offset, size)` 从 `.resS` 读字节 → 按 `m_Channels` 解 ch0。
2. 工程侧：OBJ 读 `v ` 行；`.asset` 读 `m_VertexData` 的 `m_Channels` + `_typelessdata`（十六进制串）。
3. 匹配 = **按顶点数分桶 + 逐点比**（⛔ 不按名字）：先按顶点序逐点比；不一致再按**点集**比（格哈希查 27 邻格，判据 `|Δ| <= 1e-04`）。点集连一半都配不上的候选判 `different`（同顶点数的巧合，直接丢掉，⛔ 不能当"我们的件坏了"）。
4. 判定：按序 0 超点 = `exact`；点集完全相同但按序有位置对不上 = `permuted`（几何一致、只是导出时重排了顶点）；点集也缺 = `partial`（真缺陷）。坐标约定：OBJ 侧先把 X 取反回来再比，`.asset` 侧原样比。

三条必守（`资料/已知的坑.md`「流式网格」）：

1. `ChannelInfo.dimension` **只有低 4 位是维度**（法线通道存 `0x34`；按原值算步长得 116、真值 48）。
2. bundle 内层 `read()` **是消耗式**的（第二次返回 0 字节）⇒ 必须 `Position = offset; read_bytes(size)`。
3. `m_StreamData.offset` **相对 `.resS` 起点**（reader 的 `Position` 已含 `BaseOffset`，别再加）。

## 四、边界（本报告没覆盖什么）

- 只比 **ch0 位置**；法线 / UV / 顶点色 / 索引 **没比**。
- 只覆盖**流式 169**（`流式 = 1`）；非流式 665 与压缩网格 4 不在本表（它们的顶点是内嵌的，另一条路）。
- 「一致」= 顶点坐标一致，⛔ 不等于「工程里那份被用上了」——「有没有被 prefab/manifest 引用」是 R2-04/06 的活。
- 本脚本不跑 Unity、不改任何资产；`d:/2` 只读。
