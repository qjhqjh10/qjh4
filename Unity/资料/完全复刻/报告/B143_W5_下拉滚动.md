## ⑦ 第三轮：与 `B143-W7` 的 `BindScrollbar` 口径冲突（复核抓到 · 已修）

**复核报告** → `判据/B143_Scrollbar复核.md`。W7 在 `AllianceMemberTab.BuildScrollbar` 末尾加了
`_scroll.BindScrollbar(...)`，而 `BindScrollbar → SyncScrollbar` 会按 **`MenuScroll.MaxOffset > 0`** 决定要不要显示滚动条
—— 于是「要不要显示」有了两个口径：

| 口径 | 算式 | n = 15 时 |
|---|---|---|
| 生产（②轮加的） | `needBar = n × ItemH + ItemGap > viewH + 0.01f`（**原版真实内容高 = 全部 n 行**） | **true** |
| `MenuScroll`（W7） | `MaxOffset > 0`，而 `MenuScroll` 只知道**实际建出来的 `Content` 高** = `rows(14) × ItemH + ItemGap` | **false** |

执行顺序是先 `SetActive(needBar)`（`:2807`）再 `BindScrollbar → SyncScrollbar`（`:2811-2816`）⇒ **后者把前者覆盖**：
**n > 14 时滚动条永不显示**，`B142_E18_Assert` 的 `C3` 当场红。

**修法（只改 `AllianceMemberTab`，`MenuScroll` 一行没动）**：

```csharp
// BuildList 的调用点：多传一个 contentH（= n × ItemH + ItemGap，早就在作用域里）
BuildScrollbar(listR, vpR, contentR, vc, needBar, contentH);

// BuildScrollbar 里：
_scroll = MenuScroll.TopAligned(vpR, needBar ? contentH : contentR.H, ScrollSensitivity);
```

- 🔴 **为什么不给 `MenuScroll.TopAligned` 加形参**：它**本来就有** `(PxRect viewport, float contentH, float notchPx)` 这个第二形参
  ⇒ 只需要「传的值」换掉，共用件**一个字节都不用改**（调度台给的「加一个可选形参」那一半**不需要做**）。
- 🔴 **不滚动时仍传 `contentR.H`（不是 `contentH`）**：两者在多数站点逐位相同、但 `Field3` 上差 **1 ULP**
  （`contentR.H = 123.4639892578125` vs `contentH = 123.46399688720703`）⇒ 用 `needBar ? … : …` 把「n ≤ 14 零变化」变成**结构保证**，不靠数值巧合。
