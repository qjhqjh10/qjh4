## 五、没查清 / 已知差异（如实记）

1. **`[[RewardName]]` 的物品真名**：原版 = `ObtainableItem.LocalizedName`（一个 I2 词条）。本地无 `ObtainableItem` SO 名表 ⇒
   只按 art 键小表兜底（货币 code / 战役点），**其余奖励类型原样回 art 键**（不是原版 LocalizedName）。🔶 已标 + 出声说明。
   缺口 = 「任意其它奖励类型 → 显示名」的映射表（本机没有那份 SO）。
2. **ConfigProvider 缓存宿主（R-M G4 未解）**：用本地静态表 `ConfigCache` 顶（🔶 自己设计）。原版 `FUN_180002340(slot 1/2)` 宿主类名未解。
3. **ConfigProvider 反序列化**：`JsonWrapper.DeserializeObjectWithType<T>`（Newtonsoft 多态）⇒ 本地用 `JsonUtility.FromJson<T>`（T 须 `[Serializable]`）。
4. **`GameNewsEvent.SelectEvent` 的 `Data.+0x90` 分支**：`LocalInboxMessageData.+0x90` 本地未建模 ⇒ 该早退支判不了
   （云脚本又整段无落点，故两支本地等价）。
5. **`ScoringEvent.IsMilestoneCollected` 的「两支」**：真体按「奖励是 `CosmeticItem`（→ `HasItem`）还是 `RawCardScript`（→ `GetOwnedCount >= limit`）」分两支；
   我们只有 id 字符串 ⇒ 合一支（`GetOwnedCount >= limit`，limit==0 恒 false）。R-M §1·2 判 **需改实现 0**、属「判据可补」，故**本轮未改代码**，仅在册说明。
6. **`ConfigProvider` 未接线到具体配置类**：本批只建泛型骨架；`CardTierConfig` / `RankedData` 等仍各读本地 JSON（未改）。属后续接线。
