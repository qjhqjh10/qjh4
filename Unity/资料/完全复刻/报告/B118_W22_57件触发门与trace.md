### 门 1 · 空位门（`startPosOption / endPosOption ∈ {14,15,16,17}`）—— **真的，且是「跳过这一拍」**

- **原版语义（回源逐句）**：门在 **`AbilityLogic.PlayAnim`** 里 —— `decomp_full/AbilityLogic__PlayAnim.c:104-169`：按 `startPosOption`(AnimInfo+0x18) / `endPosOption`(+0x1C) 逐档查 `MinionManager.IsAvailableSlot(mm, N)`，不成立就 `goto LAB_180821700`，而那个 label 就是**方法尾**（`:282`）= **这一拍整个不排**（不是换锚点）。
  · 档位 → 侧/N：`14` 行动方·1（start+end 都查）· `15` **对面**·1（⚠️ 源码只写了 `+0x18 == 0xf` **两次**，`endPosOption==15` 那一支**根本没有** ⇒ 只查 start）· `16` 行动方·2 · `17` 行动方·3（都 start+end）。
  · `IsAvailableSlot`（`MinionManager__IsAvailableSlot.c:19-29`）= **(左容量−左人数)+(右容量−右人数) ≥ N**，即**该方两侧合计**还放得下 N 个。
  · 侧怎么定：`PlayAnim.c` 用 `thisCard.isPlayer(+0x40)` 取 `BattleManager +0xe0/+0xe8`（`+0xe0` = 本地玩家那一侧，由 `AbilityLogic__CreateTempAbilityTransform.c:33-42` 的四分支反推）⇒ **14/16/17 = 行动卡那一侧、15 = 对面**。
- **「换锚点」那一半在哪**：在**取锚点**那一层 —— `CreateTempAbilityTransform → MinionManager.GetNextSlotPos`（`MinionManager__GetNextSlotPos.c:194-207`）：`required==1` 且**两侧都满** ⇒ 回**督军 `GetEffectAnchor().position`**（不抛、不跳）。门（技能路径）保证了这一支在技能路径上基本走不到。
- **我们现读**：`BattleDriver.cs:19874 BeatSlotGate(int sp,int ep,int actorSeat)` / `:19881 BeatSlotOk(...)`（1/1/2/3 · 行动方侧 · 15 只查 start）· `:19911 FreeMinionSlots(seat)` = 全盘空格数（督军格排除）= 原版和式的等价物 · 取锚点侧 `BattleDriver.cs:3948 EnsureMinionSpotAnchor` 的 `signed == int.MinValue` 分支**已经**回督军 `EffectAnchor(true)`。⇒ **语义 ✅ 一致**。

### 门 2 · 位移门 —— **口径错了一半：真正的门是 `shouldMoveVFX`，不是 `timeMoving>0`**

- **原版语义**：`CardAnimController__Initialize.c:30-62`：`if (!info.shouldMoveVFX(+0x38)) controller.enabled = false; else if (start != end) enabled = true + 记起点`；`CardAnimController__Update.c:29-32` 只在 `[timeAtStartPos, timeAtStartPos+timeMoving)` 里插值，`t01 = (t−ts)/tm`。
  ⇒ **位移成立 = `shouldMoveVFX==1` 且 `start≠end` 且 `timeMoving>0`**；`timeMoving>0` 单独**不构成**位移（`tm=0` 只是区间为空、站点不动）。
- **全池实测（`数据/游戏数据/card_anim_map.json`，506 条真条目）**：`timeMoving>0` **379** 条，但 `shouldMoveVFX=1` 只有 **82** 条；**`mv=0` 而 `tm>0` = 301 条**；`mv=1` 且 `sp==ep` = **57** 条（`Initialize` 会把控制器关掉）；`mv=1` 但 `tm<=0` = 4 条。
- **57 件里**：`mv=0` **42** 件（⇒ J11 标的「位移 X s」对它们**不成立**）· `mv=1` **3** 件 —— `SOR36`(sp0→ep2, tm0.1 **真会飞**) · `SAU51`(sp4==ep4) · `UM38`(sp5==ep5) ⇒ **后两件 `start==end`、原版 `enabled=0`、也不飞**。**⇒ 57 件里真正会位移的只有 1 件**。· 12 件无 `CardAnim` 参数（查不到，⛔ 未猜）。
- **我们现读**：`BattleDriver.cs:23721 bool move = moveOn && tm > 0f && (end-pos).sqrMagnitude > 1e-8f;`（技能拍）· `:22892 ArmAttackVfxMove(Transform carrier, string cardAnim, Vector3 start, Vector3 end)` / `FireAtAttackAnchor` 的 doc 与实现（攻击弹道）⇒ **两道口都按原版的三重条件判** ⇒ **✅ 一致，零改动**。
