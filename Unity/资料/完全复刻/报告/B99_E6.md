### G4 · 同批死两个（`B99E6G4TwoDeathsInOneBatch`）

**夹具**
```
Battle( P0: Unit("B99E6G4Hero",0,9,9) , P1: Unit("B99E6G4Foe",0,0,1) )
ToP1Turn(ctx, 2)
Place P1 槽 5 → x（1 血）· P1 槽 6 → y（1 血）        ← 右侧 indices 0/1 ⇒ 连续无洞
using (RuleCore.SimultaneousDamage(ctx)) { hurt x 5 killer:0 ; hurt y 5 killer:0 }
RuleCore.PumpActionQueues(ctx)
```
**为什么挑右侧**：出队序 = 入队序，而右侧「贴督军那格 5」在前 ⇒ 先摘 5 号格，6 号格那个**补到 5 号格** ——
正好踩中「按记下的格号定位会指空、第二个静默留在场上」那条真 bug（2026-10-01 治过）。

**断言意图（6 条前提 + 8 条结论）**
| 断言 | 意图 | 🧨 怎么才红 |
|---|---|---|
| 右侧 2 个 / 连续 / 计数 0 / 都活着 | **前提** | —— |
| 5 号格空 + 6 号格空 | 两个都真的离场 | 按格号定位的旧写法 ⇒ 第二个留着 |
| `CountOnSide==0` + `IsContiguous` | 摘除走的是 `BoardSlots.RemoveAt`（补位），不是 `Board[slot]=null` | 改成裸置 null ⇒ 空洞 ⇒ 红 |
| `dX < dY`（`ctx.Signals` 的 `EvtKind.Death`） | 死讯顺序 = **入队序**（= 伤害落下的先后） | 在 `FlushDeaths` 里 `Sort(按方/格号)` ⇒ 当入队序≠格号序时红 |
| `TroopsKilled[0] == 2` / `[1] == 0` | 原版 `:112` **每个死者无条件一次**，记给凶手座位 | 挪回 `TryCreditKillCore`（6 道闸）⇒ 少计 |
| `DeadUnits.Count == 2` 且 x 的下标 < y 的 | 与死讯**同序**的第二观测口（结构上独立于 signals） | 嵌套/乱序入账 ⇒ 红 |

### G5 · 死亡里再死一个（`B99E6G5NestedDeath`）

**夹具**（骨架照既定夹具 `TestW58NestedDeathInterleave` ①，⚠️ 不重复它的 90/Slay 日志断言）
```
P0：atk（1 攻 / 10 血，槽 3）· C（0 攻 / 2 血，槽 5）
P1：A（0 攻 / 1 血，槽 3，`Backlash: Deal 4 damage to all enemies`）
DeclareAttack(ctx, 0, 3, 1, 3)
```
A 死后 Backlash 4 点溅到 P0：攻击者 10→6（**故意不死**，否则观测被搅乱）、C 2→−2（**嵌套死亡**）。

**断言意图**
- 前提：`a.Has(KeywordTable.Backlash)`（**必须先断**：正文没解析出来时 C 不会死，后面的次序断言会退化成「两个 −1 比大小」）、
  A 1 血 / C 2 血 / 攻击者血 > 4、A 与 C 都死、攻击者活着。
- 结论：`Death(A) < Death(C)`（原版队列 **FIFO**：新死者追加**队尾**）
  🧨 在 `FlushDeaths` 里递归 flush（或把新死者**头插**）⇒ 变成 A→C→B / C 抢到前面 ⇒ 红。
- 补充：`DeadUnits` 下标也 A < C（第二个观测口）。

> ⚠️ **口径说明**：`EvtKind.Death` 是**表现层信号**，`A962③` 让它故意排在反噬**之前**
> ⇒ 拿它验「90 观察者的次序」会假绿（`TestW58NestedDeathInterleave` 就是为此改用日志）。
> 本件用它验的是**死亡本身的先后**（不同的事），并**另配** `DeadUnits` 一口交叉印证。

### G7 · 残骸那一档（`B99E6G7RemnantTier`）

**夹具**
```

② hurt rem 1 killer:0 → 残骸被摧毁
```

**断言意图**
| 步 | 断言 | 🧨 |
|---|---|---|
| 前提 | `r.Has(remnant)` ∧ `!r.IsRemnant` ∧ 右侧 2 个 ∧ `DeadUnits==0` ∧ `TroopsKilled[0]==0` | —— |

| ① | 右侧仍 2 个（残骸**占着**格位） | —— |
| ① | `DeadUnits` **不增** / `TroopsKilled` **不增**（`leftPlay` 仍 false） | 把记账挪到分支之前 ⇒ 红 |
| ① | `DiedThisTurn` **+1**（原版两支都写 `+0x250`） | 只有「真离场」那支 `++` ⇒ 少 1（`A858` 那笔） |
| ② | **外侧内移**：5 号格是 `bg`、6 号格空、`CountOnSide==1`、连续无洞 | 改成 `Board[slot]=null` ⇒ bg 留在 6 ⇒ 红 |
| ② | 补位上来的是**同一份对象**（`ReferenceEquals`） | 「名字相同就算」的写法测不出这个 |
| ② | `DeadUnits` +1 且 **`IsRemnant == true`** | 写 false ⇒ 墓地查询多出这张（原版 `GetCardsInCemetery.c:60` 无条件排除） |

## 七 · 顺手发现（值钱的几条，全部来自本件的现场）

1. 🔴 **`B97_R8` §1 的 G4/G7 判据照抄会写出「恒绿」断言**：它写的 `ctx.Tally.TroopsKilled[凶手座位] == 2`
   配的是 `RuleCore.HurtForTest(ctx, u, 5, "夹具")`（**4 参**），而那个重载的 `killer` 缺省 `-1`、
   `actingCard` 缺省 `null` ⇒ 落点 `AddTroopKilled(killer >= 0 ? killer : SeatOf(ctx, actingCard))`
   = `AddTroopKilled(-1)` ⇒ `SeatOk(-1)` 假 ⇒ **一次都不计** ⇒ 断言永远看到 0，而「期望 2」会红得莫名其妙，
   或者更糟：有人把它改成「期望 0」就变**恒绿**。
   ✅ 正解 = `RuleCore.HurtWithSourceForTest(ctx, u, 5, "夹具", killer: 0)`（8 参版，本件就用它）。
2. 🔴 **直接调伤害入口的夹具必须先 `RuleCore.PumpActionQueues(ctx)`**：`EvtKind.Death` 自 2026-10-22（`W62·R2`）
   起是**入队**发的（`CleanupDeaths` 里 `EnqueueAbility(… "death-signal:" …)`）⇒ 不泵队时 `ctx.Signals` 里
   **一条死讯都没有**，读出来像「信号没发」（假红）。判据里没写这一条，本件在每一处都补了。
3. 📌 **「账 N」的编号口径有两套并存**：`B98_J0` §三 写「522 `ResolveMinionDeath`」= **数据行序号**（表头不算），
   `B97_R8` 写「战斗逻辑驱动:523」= **文件行号**。**同一行**。建议以后统一写 `战斗逻辑驱动.tsv:<文件行号>`。
4. 📌 `EvtKind.Death` 的判别力边界（已在 §四 G5 里写死）：它是**表现层信号**，`A962③` 故意排在反噬之前
   ⇒ 它**不是**「死亡触发的结算次序」的观测口；那条只能用日志（90 监听器 / Slay）看。
