## ③ 出厂快照怎么抓的 / 会不会被污染

**不会。** 快照 = `static readonly Dictionary<string,int> _factoryAvailable = CaptureFactoryAvailable();`，
**在类型静态构造里取一次**。依据：

1. C# 静态字段初始化按**源码声明序**执行（编译器把它们排进同一个 `.cctor`）。
   `_cards`(163) / `_daily`(201) / `_items`(221) / `_vip`(577) / `Pages`(114) 都声明在
   `_factoryAvailable`(779) 之前 ⇒ 快照读到的必然是**字面量出厂值**。
2. 三个可能污染 `Available` 的入口**都发生在类型初始化之后**，不可能抢在快照之前：
   - `EnsureSeeded()`（读盘 `extras` 覆盖 `Available`，`ShopData.cs:344-355`）；
   - `Buy()`（`Available--`，`:487-488`）；
   - 自检临时代码直接改表（如 `B106_W63` §②-2 的 `offI544[0].Owned = 0`，那改的是 `Owned`，本来就不受影响）。
3. 因此**第一次 `ResetForTest()` 之前发生过什么状态都不影响快照**（快照与调用时机无关，只与类型初始化绑定）。

⚠️ 一个已知边界（写进报告、不改）：若将来有人在**运行时**用 `SetPageArray` 把某页换成
「快照里没有的新商品名」，那件新商品的 `Available` 不会被还原（会保留当时值）。今天的生产路径里
`RemoveFinishedOffer` 只**摘**不**增**，且 `isActive == null` 时一个都不摘 ⇒ 今天走不到；真走到时
`ResetForTest` 也不是这条路径的正确复原口（它不还原数组本身，只还原 `Available`）。

## ⑤ 顺手发现（只报不改）

1. **`ShopTabPage.ResetOwnedAffordForTest()` 全仓 0 调用点，但语义与 `ResetForTest()` 不重复**：
   它清的是 `OwnedRefusals` / `AffordRefusals` / `OwnedOpens` + 三个 `Last*` 下标记（`Shell/ShopTabPage.cs:1624-1630`），
   属于 `ShopTabPage` 的读口；`ShopData.ResetForTest()` 管的是数据层（背包 / 限购 / 存档文件）。
   两者**互补、不同域**。让 `ShopData` 去调它会造成「数据层依赖 UI 层」，不建议；正确做法是：
   谁写「绝对值 == N」的断言，谁在自检入口调它。⛔ 未删（可能有外部消费者），只在此说明。
2. 现读确认：`OwnedRefusals` / `AffordRefusals` 的**所有消费点都已经是「前后差」写法**
   （`Editor/ShopScene.cs:2063-2068 · 2217-2236 · 2514-2526 · 2641-2654`），暂无跨节污染风险；
   风险只在「将来有人写绝对值」—— 已写进 `ResetForTest` 的 doc。
3. `ResetForTest()` **不重置** `_vipForTest`（VIP override 位）与 `RequiredItemId`：
   `Editor/ShopScene.cs:2119` 的注释已经点过这一格（「别指望它兜底」），本次未扩大范围。
4. `ReloadForTest()`（`:394-399`）走的是「清背包 → 重新播种 → **读盘**」，盘上 `extras` 里若有被扣过的
   `Available` 会照样盖回来 —— 这是它「重读盘」的**设计语义**，不是缺陷；但意味着
   **「想回出厂」只能调 `ResetForTest()`**（它先删盘）。已在本报告留痕，未改代码。
5. `ResetForTest()` 会删默认目录存档这一点，`B106_W63` §⑤·3 已单独立账（`W55` §⑤·5 也提过）；
   本次只把「行为面」写进 doc，**没有改「删不删」这件事本身**（⛔ 不由本代理裁定）。
