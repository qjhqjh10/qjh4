## 五、两条重要的口径纠正（铁律 5）

### 5.1 🔴 L1376：上一批「删 `EndAuraRecompute` 那一句」的改法**不能照做**（已推翻）

`B93_F4` 写的建议是「原版摘 trait 不重算 ⇒ 删掉 `UnitState.EndAuraRecompute` 里的 `RecomputeActAndAttack`」。**前半对、建议错**：

- 原版**确实**不在 `RemoveTraitSilently` 里重算（`.c` 全文 0 命中）；
- 但原版**每结束一个动作**都对**行动方**重算：`BattleManager__FinishResolvingAction.c:105`（敌方）/ `:115`（我方）
  → `MinionManager__ActivateMinions(...)` → `CardScript__ActivateMinion` 按 `displaySummonSickness` 重写 `canAct`/`canAttack`；
  另有 `OnTurnStart` / `ResetActions` / `ResetSummonSickness` 三个入口。
- **我们没有**那个「每动作结束 ActivateMinions」的钩子：`RuleCore.BroadcastActivateMinions`（`RuleCore.cs:16445`）只在 `BeginTurnCore`（`RuleCore.cs:2262`）调**一次**。

⇒ 删掉那句 = 从「比原版严（当场重算）」变成「比原版松、且到回合开始前补不回来」。
**本批保留**，并把真缺口改写成「**缺 `FinishResolvingAction` 的每动作 `ActivateMinions` 钩子**」（落点 `RuleCore`/`EffectResolver`，不在本代理白名单）。
**零代码改动**；T1 用三条断言把现状钉住（其中「真丢当场重算」那条的文案里写明「如实标：我们比原版严」）。

### 5.2 L1379：`ShowWarlordActiveAbilityForTutorial` 是「**恢复**」不是「**置 1**」

- `CardScript__ShowWarlordActiveAbilityForTutorial.c`（12 行全文）= `*(byte*)(this+0x220) = *(byte*)(rawCardData+0x2a9)`。
- 账里原来把它跟 `SetBaseCardTraits.c:37` / `RemoveEffect.c:271` 一起归进「三处从 `+0x2a9` 复位」——**这是对的**；
  但若有人照「Show = 置 1」去实现，会把 **45 张「有 `activeAbilityLogic` 却 `hasActiveAbility=0`」** 的卡**好心点亮**。
  T2 用「卡面 0 的卡 Show 之后仍不可用」把这条钉死。

  ① **谁调 Show** = `decomp_full/AiScripted__ShowPlayerActionAnim.c:606`（教程播玩家动作时对己方督军那张 `CardScript` 调）；

## 七、顺手发现（⛔ 都不是我白名单里的文件，只报不改）

1. 🔴 **我们没有「每个动作结束对行动方 `ActivateMinions`」这一跳**（§五·1）。影响面**不止光环**：
   任何**回合中途**改 `fast`/`flank`/召唤病、或改 `AttacksThisTurn` 的场景，原版都会在**动作边界**重算 `canAct`/`canAttack`，
   我们只在「关键词变更那一跳」和「回合开始」重算。**建议在 `RuleCore`/`EffectResolver` 立账**（对应原版 `FinishResolvingAction`）。
2. 🔴 **`UnitState.ActiveAbilitySuppressed` 改前是死位**（本批已修）。同类风险：任何「写了没人读」的实例位都值得一次 `grep` 体检。
3. `ResetToValuesInHand` 的原版全方法体在 `if (RawCardScript.IsUnit())` 里 ⇒ **非单位卡（战术 / 附魔）只清两表 + `questCounter`**，不重置数值；
   我们是**无条件**跑全部 ⇒ 若将来对非单位卡调用会多重置。**今天休眠**（所有调用点都是单位卡）。
4. `CardScript__CardSetup.c:117` 有一句 `RemoveTraitSilently(0x82)`（= **130 = jam**）—— 原版**建卡时**会摘 jam；
   我们靠「新实例天然没有 jam」等价，**没有对应动作**（若将来复用 `UnitState` 对象重部署，这里会漏）。
5. `AbilityTrigger` 名表本批用脚本对拍：**97/97 全等**（0 缺 / 0 多 / 0 值错）—— 这条以后不必再重查。
6. `RemoveTraitSilently` 的**「默认 trait 表」`+0x130`** 那一半我们**没有对应结构**（我们只有一张合并字典）。
   本批维持「净等价」的结论（唯一调用点 `TransformIntoRemnant` 倒序摘光），但**「同一张卡同名 trait 出现两份」**一旦有别的调用点就会露，已在账 L863 里写明。
