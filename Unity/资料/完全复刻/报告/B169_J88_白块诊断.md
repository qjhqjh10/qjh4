# B169_J88 — 个人资料页 / 头衔页「纯白方块」诊断（只读）

> 对象 = **离线版客户端**（`E:/warpforge/`），⛔ 不是复刻工程 `d:/4/Unity/MyGame`。
> 只读诊断：未跑游戏、未改任何文件（本报告除外）。日期 2026-11-07。

## §一 结论

**两处白块机制相同，根因不同。**
机制 = Unity UI `Image` 在 `m_Sprite = null`、`m_Color = 白(1,1,1,1)`、`m_Type = Simple` 时**不采样任何贴图，直接画一个纯白矩形**。
所以「白块」= 代码把 `sprite` 赋成了 null，而 `enabled` 仍为 true。

**A. 个人资料页（右上 440×440 大白块 + 2 个 123×104 小白块）**
白块 = 三张信息卡的 `Badge` 节点（战将精通 / 锻造厂 / 当前战役）。它们的 prefab `m_Sprite` **本来就是 0**，
运行期由 `ProfileContainerComponents.armyIcon` / `WarlordMasteryContainer.armyIcon` 填。
**真正根因：`WarlordMasteryContainer.OnInitialize` 在「设完标题、还没设图标」时抛 NullReferenceException**
（`.c` 里 `goto LAB_180754d80` = `FUN_1803f47a0()` = throw），于是
`ProfileEventSection.Initialize` 就地中断 ⇒ **锻造厂 / 当前战役两个容器一次都没初始化** ⇒ 三块 Badge 全停在 null。
抛的原因 = **假服务端下发的 `VictoryCounters` 是空字典 `{}`**：
`context.GetVictoryCounters()` 空 ⇒ 对 `Logs` 的 `FirstOrDefault` 谓词恒 false ⇒ 取到 default KVP ⇒
`highestGroup.Value == null` ⇒ throw（对「0 胜场的新号」是必抛，不是偶发）。
⇒ 顺带解释同一页的英文 `Current campaign` / `Level: 0`：那是 **prefab 默认文案**，不是本地化失败。

**B. 头衔页（221×221 白块）**
`ProfileItemDisplay.Initialize` 执行 `image.sprite = ArmyUtilities.GetArmyIcon(item.cardArmy)`，
随后 `image.enabled = (item != null)`（= true）——**sprite 为 null 时它不隐藏**（与同族 `TitleDrawer.Draw`「null 就 SetActive(false)」相反）。
当前装备头衔 = `Title_All_Generic_8`（"领导者"，uniqueId `0834f36ddcb51844bae1e3a11bf0afc1`），**`cardArmy = 0 (Neutral)`**；
而 `IconsByArmySO`（`ArmyUtilities.armyIcons`）只有 **13 条（10…130），没有 0** ⇒ `GetArmyIcon(0)` 返回 null ⇒ 白块。
同一原因让头衔网格 9 个按钮的**阵营圆徽全部不显示**（`TitleDrawer` 判 null 后主动 SetActive(false)）。

**相关资产本地全都有**（不是缺资源）：
`armyicons_assets_all` 17 Sprite / `IconsByArmySO.asset` 13 条 / `uiwarlords_assets_all` 65 张 2048² RGBA 都在客户端里；
实机排名页 13 个阵营圆徽、战斗记录页每行的阵营圆徽**全部正常**，反证 `ArmyIconsSO` 链路是好的。

## §三 修法（按推荐顺序）

**① 数据侧修 A（首选，改一行）** — `server.py:149`
把 `"VictoryCounters": "{}"` 改成 `json.dumps({"UM46": 1})`（key 必须是客户端能按 id 解到的卡，`UM46`/`BL34`/`AM1` 都在 `BattleLogData.ownHeroName` 里且战斗记录页已证明能解）。
- 效果：战将精通容器不再抛 ⇒ 三块 Badge 都拿到真图（大块 = 该卡 `fullHeroSprite`，两块小 = `GetArmyIcon(阵营)`），英文默认标题也一并被本地化标题替换。
- 风险：低。副作用是「胜场：1」这个数字是我们编的（🔶 自己设计，按铁律 18 记账）。改后需重启假服务端 + 重启客户端（数据只在登录时下发）。

**② mod 侧兜底（建议与 ① 一起做）** — 在 `WfOfflineProbe` 里给 `ProfileItemDisplay.Initialize` 加 postfix（或 hook `ProfileContainerComponents.ArmyIcon` 的赋值），**`sprite == null ⇒ image.enabled = false`**。
- 理由：这**正是原版自己的策略**（`TitleDrawer.Draw` 就是这么干的），不算自设计；能一次性盖掉「任何取不到图的 Badge 画白块」。
- 风险：低。副作用：取不到图时那块变成「空」而不是白，符合用户要求。

**③ 头衔页单独修（二选一）**
- 数据侧：把 `player_state.json` 的 `DemoData.playerTitle` 换回 `370bd66e…`（Recruit，UM）或任一有阵营的称号 ⇒ 立刻有图标；代价 = 改掉用户当前选的「领导者」。
- 或直接靠 ② 兜底：Neutral 称号就不显示图（与网格里按钮的现有表现一致）。
- ⚠️ **不要**往 `IconsByArmySO` 里硬塞一张 Neutral 图：那 SO 是原版资产，塞的是我们自己挑的图（🔶），且 `m_Sprite` 是裸 Sprite 引用，运行期改要先异步加载。

**④ 资源侧（不需要）**：`armyicons` / `uiwarlords` / `allcards` 三个 bundle 本地都有（`game/Warpforge_Data/StreamingAssets/aa/StandaloneWindows64/`，87 个），无需从 XAPK 取远端包。
