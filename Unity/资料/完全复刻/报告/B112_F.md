### 一·2 根因（现读，可复算）

**触发链**：`EffectExporter.ClearGenerated()`（`EffectExporter.cs:751-765`）在 `Run()`（`Resume=false`）里**无条件**删掉
`WarpforgeVFX/{Materials,Textures,Meshes,Prefabs}` 四个目录下的**全部**资产，再按「效果根」重导一遍。
而上面这 4 件**只有 `BoosterPackExporter.Run()` 会生成**（它走 `EffectExporter.ImportMaterial/ImportMesh/ImportTexture`），
`EffectExporter` 那套效果根的依赖树里**根本不含它们** ⇒ 一次全量特效重导就把它们**永久删掉**，而 `BoosterPackExporter` 之后没再跑。

**盘上证据**（`ls -la --time-style` 现读）：
- `WarpforgeVFX/Prefabs/*.prefab` **最早 = 2026-10-31 03:26**，没有任何更早的文件 ⇒ `PrefabDir` 确实被清过一次，那次全量重导在 **03:26–03:33**（另有一段 **09:24**）。
- 四个 `CardPresentation/Effects/Boosterpack Open Card Rarity *.prefab` = **2026-10-31 01:08** ⇒ 停在**全量重导之前**，此后没重导。
- 现存能解析的那几份材质（`Spark Additive Extra Color` / `Glow Rays Additive Extra Color`）**是效果根也会用的** ⇒ 03:26 那次被重新生成过；只有「booster 独有」的四件回不来。

**⇒ 正确修法 = 按 `BoosterPackExporter.cs` 头部与 `.gitignore:210-219` 写死的顺序重跑**：
`extract_missing_shaders.py --prefabs` → `BoosterPackExporter.Run` → `EffectLibraryBuilder.Run`。
**⛔ 反过来（先 Booster 后 Effect）就会再把它们删一次。**

### 一·4 两个**材质**为什么不硬造（判据，不是「做不了」）

`WarpforgeEffectBinder.cs:155` `void Awake() { Apply(); }`，`Apply()` 会在运行期**按 prefab 自带的 `materials[]`（`WFMatDef`）重建材质**并把
`r.sharedMaterials` 整条换掉（`WarpforgeEffectBinder.cs:195-233`）。四份 prefab 的 binder def 现读：

- Rarity 1/2：`[0]=Glow Rays Additive Extra Color · [1]=Spark Additive Extra Color · [2]=CardFlip Effect`；
  `rendererSlots = [0,1,1,2]` ⇒ **`CardFlip` 渲染器分到 def 2**。
- Rarity 3/4：`[0]=Glow Additive Extra Color · [1]=Spark · [2]=Glow Rays Additive EC · [3]=CardFlip Effect · [4]=Glow Rays`；
  `rendererSlots = [0,1,2,1,3,4,2,2]` ⇒ **根 PSR 分到 def 0、`CardFlip` 分到 def 3**。

⇒ **那两个悬空材质在运行期会被 binder 覆盖掉，玩家看不见差异**（静态悬空只是编辑器/`res_audit` 噪声）。
而硬造 `.mat` 要猜「原版 shader → 我们哪个 shader」的映射（`CardFlip Effect` 的 shader 在包里 `m_Name` 是**空串**，`ImportMaterial` 只能走兜底），
猜错的后果是**渲成品红**——比现在（null）更糟。⇒ **判「不硬造，等 `BoosterPackExporter.Run` 重导」**。
（`Glow Additive Extra Color` 那条甚至不需要等：工程里已有同名变体 `WarpforgeVFX/Materials/Glow Additive Extra Color__75594af2.mat` / `__80c1155a.mat`。）

## 五 · 顺手发现（⛔ 都没自己改）

1. 🔴 **`ExtractMissingShaders` 重打出来的 `wf_menus_extra.bundle` 里，一部分外部引用指向的是我们**自己的**重打小包，但 pid 对不上**：
   那份 CAB 的 externals 表把原版的 `CAB-0dc9fe43…` 等改成了 `CAB-boostermatsfont` / `CAB-boostermatsdup` / `CAB-boosterfxshaders` / `CAB-boostermatsmenu`，
   而 `Glow Additive Extra Color`（pid `-7266583462553607439`）实际住在 **`duplicateassetisolation_assets_all.bundle`** —— 不在那 4 个重打包里。
   ⇒ 只要 Unity 不顺手把原包也加载进来，这条引用就解析不到。（这也解释了为什么同一族的两份材质，一份能导、一份不能。）
   判据：`UnityPy` 读 `wf_menus_extra.bundle` 的 `CAB-wfmenusextra.externals[30..33]` + 全 84 个原包里扫 pid。
2. 🟠 **`CardPresentation/Effects/Boosterpack Open Card Rarity *.prefab` 与 `CardPresentation/Resources/Art/` 都在 `.gitignore` 里**
   （`.gitignore:217` 与 `:99`）⇒ 本代理新加的两个件**不会进仓库**。它们和 prefab 属于**同一类「本机可重建产物」**，
   换机重建时仍要走 §一·2 那条顺序链。⛔ 别以为「加了就永久好了」。
3. 🟡 **`CardFlip` 根用 `m_RenderMode: 4`（Mesh）+ 内置风格的 `Cylinder`**：原版这颗 50 顶点的 `Cylinder` **不是 Unity 内置 Cylinder**（内置是 88 顶点）；
   工程里已有的三个 `Cylinder__*` 变体是 **88 / 64 / 68** —— 都不是它。所以「拿现成的顶上」这条路**不存在**，必须从包里导。
4. 🟡 `Assets/Settings/DefaultVolumeProfile.asset` 里还留着一个 `m_Script: {fileID: 0}` 的
   `VolumeComponentSupportedOnAnySRP`（`Unity.RenderPipelines.Core.Editor.Tests` 命名空间）—— 是 URP 测试夹具残留，与本次 4 处悬空**不同**（它本来就是 fileID 0），
   Unity 重存时会被一起丢掉。
