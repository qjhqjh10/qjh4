### 与任务描述的一处口径差异（请调度台核）

任务正文说「写进 `responses/fragments/playfab_profile.json` 的相关字段」，但红线给的**可改文件白名单只有** `server.py` 与 `responses/ExecuteCloudScript.ChangePlayerName.json`。本实现按白名单执行：**登录片段文件保持静态默认**，新名字由 `state/player_state.json` 的 `displayName` 在**运行时注入**登录响应（与 `_inject_liveops` 同一条路子）。理由：
① 白名单优先；② 状态只留一处（`state`），片段文件继续当「出厂默认」；③ 运行时改写模板文件会和 `TemplateStore` 的热重载/mtime 缓存打架（改一次就整库清缓存），还会让「默认名」随最后一次运行漂移。
若调度台仍要求落进片段文件，这是一处 3 行的追加写（`json.load` → 改两格 → `json.dump`），可随时补。

1. 起离线版 → 主菜单/资料页点**名字旁的铅笔** → 改名窗输入一个新名字（客户端自己校验：长度 >2 且 ≤25、和当前名不同，见 `ChangeNameWindow.cs:198-215`）→ 点确认。
   **该看到**：等待弹窗消失、改名窗关闭；资料页名字**立刻**变成新名字（走 `OnPlayerNameChanged`）。
2. 关掉客户端再启动 → 资料页/主菜单的名字**仍是新名字**（登录响应注入生效）。
3. 再进改名窗点一次改名 → 仍能改（价格按钮不出现、不改名按钮可点）。这一条验的是我们保 `changes: []`（`TimesNameChange` 恒 0）这个决定。

## 六、顺手发现

1. **`changes` 不能追加**：`TimesNameChange = changes.Count`（`decomp_full/PlayerDataManager__get_TimesNameChange.c`），而 `ChangeNameWindow.Open`（`decomp_full/ChangeNameWindow__Open.c:30-40`）在 `>=1` 时改走「`ItemsConfig.TryGetItemOrActionPrice(ChangeName)`」那一支 —— 本地配置里没有那格价格时会 `CustomDebug.LogError` 且 `canChangeNameBecauseOfCost=false` ⇒ **第二次改名按钮直接不可点**。所以 `_apply_name_change` 永远给 `[]`。将来要让改名收费，得同时改：`ItemsConfig` 的 ChangeName 价格、`changes` 追加、响应 `price` 非 null 三处。
2. `PlayerDataManager.playerNameSocial`（+0x218）在 ILSpy 全树**只有 getter、没有写点**（`PlayerDataManager.cs:5168, 5893-5897`）—— 改名不会更新它；若某个社交 UI 用它，会出现「两个名字」。目前没找到消费点，仅记录。
3. `_inject_decks`（`server.py:1011`）是 `LoginWithSteam` 路径上**直接在共享缓存对象里写**的（`strip_meta` 只浅拷贝顶层）；因为每次注入的值相同，暂时看不出问题。本轮新增的两处注入都先在 `strip_meta` 之后 `copy.deepcopy` 再改。建议以后把 `_inject_decks` 也改成 deepcopy（本轮不动，避免扩大 diff）。
4. 服务端**不复核**名字长度/字符（原版云函数判据在远端、关服拿不到）；正常 UI 路径已被 `ChangeNameWindow.ValidateInput` 卡在 3–25 字符，直接构造请求可以绕过 —— 离线版单机，按「能玩通」处理，未加限制。
5. 自测产物都在 `E:/warpforge/_tmp_view/b168_r1/`（config、脚本、临时 state、`bak/` 三份改动前副本），可随时删。
