```csharp
static bool HandListenerContextAllows(CardDef card, string kind)
{
    if (card == null) return false;
    string tn = TriggerNameOfWhenKind(kind);
    if (card.AbilityTriggerPresence(tn) == 0) return false;   // ← 第二刀；⛔ 不是 `!= 1`
    int actx = AbilityContextOfAbilityV14(card, tn);
    return actx == CardDef.AbilityContextUnknown || actx == CardDef.AbilityContextHand;
}
```

> ⚠️ **为什么必须是 `== 0` 而不是 `!= 1`**：`-1` = 未知（旧卡表 / 缺 `abilityTriggers` 列 / 认不出 trigger 名）
> —— 把未知并进「明确没有」= **把旧卡表的监听静默砍光**（工程红线「不许静默失败」）。

### 2·2 为什么「必须两处一起改」

- 预扫只决定「要不要进循环」；真正挡卡的是 `:11092` 的逐张闸。
- **预扫比逐张宽** ⇒ 只是白建一次快照（正确性不变，E36 之后一直是这样）；
- **预扫比逐张严** ⇒ 会吞掉本该响的手牌监听 = **真漏判**（而且没有任何报错）。
  ⇒ 所以本笔把预扫**收紧到与逐张同口径**（两处都调同一个判定函数），并给这条不变量配了结构断言（D3a/D3b）与行为断言（D4a/D4b）。

### 2·3 ⚠️ 一处**故意**不套这道闸

预扫的**后半截** `(drawMode && h[i].ArmedTrap != 0)` **不能**给它套 `HandListenerContextAllows`：
被抽的**武装陷阱**在逐张循环里排在闸**之前**，由 `EmitTrapDrawnInsteadOfCardDrawn` 处理（账 250 第三批）——

## 六、顺手发现

1. **`play check` 对「手牌态监听」的盲区比 E36 报告写的更彻底**：E36 收尾后能过第一刀的只剩 `presence == 0` 那一类，
   而现有夹具**从不把被测卡留在手里等事件**（电池是「先打出、再跑事件」）⇒ 这一整族在 `play check` 里**结构性不可观测**。
   ✅ 建议：给 `ruleprobe` 加 `Deploy(190)` / `Kills(120)` 的 `preset hand=self,event=…` 两档（白名单外，没动）。
2. **`SOR10` 的 over-fire 在真局里其实**不可达**（卡面是 `this unit kills`，自指 `ActorSelf`，而躺手里的卡杀不了人）；
   **`UM81` 才是真可达的那一档**（手里攥着它 + 部署另一张 Eliminator）。⇒ 若将来要给这两张写「回归样本」，
   优先用 UM81，别用 SOR10（SOR10 只能靠夹具造）。
3. **闸 B 的正例只有 1 张卡**（`Jammed Communications`），且它 `abilityTriggers = [0,10]`、两条 context 都是 10 ——
   本笔的第二刀对它**零影响**；这张卡是「闸 B 没被一起关死」的唯一活证据，⛔ 别把它的数据当成可随手改的。
