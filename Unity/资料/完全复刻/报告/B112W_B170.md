## 二、改法（贴 diff）

**思路 = 「全部落点先预计算、逐个判」**：把 `check_extra_refs` 的**调用点从函数尾部挪到函数开头**
（只依赖 `land` / `roots`，与主落点判成什么无关）。`check_extra_refs` 本体**一个字没改** —— 没有放宽任何判据。

现文件 `工具/check_ledger_points.py:828-853`：

```python

        _r0 = REF.search(land)
        ex_fails, ex_warns = check_extra_refs(
            land, roots,
            skip_key=((_r0.group(1).replace("\\", "/"), int(_r0.group(2))) if _r0 else None))
        for _rel, _ln2, _why in ex_fails:
            fail("（次要落点）" + _why)
```

## 五、还差什么

1. **`--fix` 路径未实跑**：本次账里 0 漂移 / 0 改写，`--fix` 会写盘 ⇒ 按红线**没跑**。
   静态核对结论：`check_extra_refs` 从来不产生 `rewrites`（改前也不），`rewrites` 只由主落点漂移那条路追加，
   所以 `--fix` 的行为**结构上没变**。⚠️ 真要用 `--fix`，仍按老规矩：**没有 `.cs` 写手 + 补丁已合并完** 时才跑。
2. **`通过=` 的口径**：现在按「有问题的行数」算，`失败/漂移/告警` 三列仍是「问题条数」。
   现账 0 问题 ⇒ 数字与改前一致；有问题的账上，行数会**小于**条数（这是预期的，见 §六②）。
3. **这条闸仍然只能证明「落点形态」**，证明不了「这一行实现了那个原版方法」—— 与改前一样（文件头第 5-7 行）。
4. 夹具只覆盖了 6 种短路形态（#1/#2/#3/#4/#5/#7 各一），**#6 歧义 / #8 散文名不符 / #3 读不了文件** 没有单独造夹具；
   但它们与已覆盖的几处是**同一个 `continue` 机制**，且真账 `diff` 为 0 已证明无回归。

## 六、顺手发现

1. 🔴 **短路点不止 3 处，是 11 处。** 任务书按判据代理的读数记了 `:927-929` / `:939-941` / `:951-953` 三处；
   实际 `check_file` 从 `land` 取到、到 `check_extra_refs` 之间共有 **11 个 `continue`**（见 §一表格），
   其中**名字核对那一段就占了 5 个**（`:879/:884/:896/:908/:918`）。
   只修那 3 处会留下「名字对不上 / 漂移 / 歧义」时的同一类顺序效应 —— 本次**一次修全**（挪调用点，不是补 `continue`）。
2. 🟡 **`通过=` 会把负数印出来（改法上线前实测 `A=8 … 失败=12 通过=-5`）。**
   根因：原来是 `total - len(fails) - len(drifts)`，那时「一个落点行最多报一条问题」（主落点一失败就 `continue`）
   ⇒「问题数 == 行数」。现在一行可以同时报主 + 次两条 ⇒ 再按条数减就减穿。已改成按
   `(类.方法, 落点)` 去重数**有问题的行数**（该键在现账 9,687 行里**零重复**，2026-11-01 实测）。
   ⚠️ 这是**显示口径**修正，⛔ 没有放宽任何判据；真账输出因 0 问题而**逐字节不变**。
3. 🟡 **`--help` 没被解析**：不带显式动作参数时它会**直接跑一次真检查**（只读，不写盘，但会耗几秒扫全账）。
   这与 CLAUDE.md「写盘类脚本不带显式动作参数时必须什么都不做」**不冲突**（默认只读），但**用法不友好**。
   本次按任务书要求**没有改**（超出本任务范围）。建议后续给它加一个「`--help` ⇒ 打用法并退出」的短路。
4. 🟢 **`check_extra_refs` 的 docstring 里「只取 `:行` 之后、下一处 `:行` 之前」那段措辞与实现一致**（`ms[i+1].start()`），
   本次改调用点**没有**影响它；文件头 `:74-91` 已补一条 B112W_B170 的说明，避免下一个人再按「尾部位」去找调用点。
