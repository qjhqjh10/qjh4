## 5. 顺手发现（都不在本批 4 条的范围内）

1. **`gen_cards_engine.py` 的 `ENCHANT_TEMPLATES_REPORT` 是模块级累加器**（`:5264` 初始化、`:5652` 等 `+=`），`build()` 入口**不重置** ⇒ 同一进程里第二次 `main()` 会打印「有挂载者 140 张」这类翻倍读数（我的三态 harness 里就看到了 70 → 140 → 210）。
   - CLI 单次运行无影响；⚠️ 但**任何「同进程跑两遍生成器」的测试/工具**都会拿到翻倍数字。建议后续在 `build_enchantment_templates` 入口把该 dict 重置（⛔ 本批没动，避免超出「只加闸」的口径）。
2. **`gen_renderqueue_truth.py --check` 现在是 rc=1**（json 过期 + 第 3 张 TSV 不存在）—— 这是**预期**，要让导出器真正用上 bundle 维度，需要调度台在「没有 `.cs` 写手 + 没有账写手」时跑一次 `--write`，再重跑一次 `EffectExporter` / `BoosterPackExporter`。
3. **文档/任务表里 `gen_renderqueue_truth.py:95-97` / `:105-107` / `:107` 这些行号已漂**（本批文件重写后行号全变）；
   另外 `战场线/任务总表.md:57` 那条「改法二选一（冲突不进表 / 逐条出声）**未裁**」—— 本批已经走了**第三条路（bundle 维度）**并保留名字键回落，**建议调度台据此核销/改写那条**（⛔ 我没改正本）。
4. **导出器的 bundle 线索是「prefab 自己的包」**，材质可能跨包引用（判据 §3.3 也这么写）。命中不到时 `TruthQueue` 走名字键回落并**出声一次**；模块材质有精确出处包，不受影响。真正验证要跑 Unity（本批没跑）。
5. **`vfx_param_audit.queue_check`** 现在优先用 `mat_by_bundle`（bundle 从 `--bundle` 目录名推），缺表/没命中回落 `mat`（旧行为）。没有单独跑该工具（它需要额外参数/较慢），只做了静态改动 + 语法自检（`typecheck` 不覆盖 `.py`；改动只在 `queue_check` 内、无新导入）。
