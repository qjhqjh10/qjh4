## §1 逐条：改了什么 / 判据 / 观测口 / 残差

### 1·1 `L412` `LiveopMenuContainer.OnLocalize()` —— 换语言 ⇒ 重建左栏 + 模式卡标题/倒计时

- **原版**：`OnLocalize` 由 `LocalizationManager.OnLocalizeCallback` 打到每颗活动容器上，容器自己重设 title / 倒计时。
- **我们的缺口**：`Core/Loc.SetLanguage` 的 doc 明写「本类**不发事件**」（按「两个设置窗不会同时开着」推的），
  而**主菜单那棵树在设置窗后面一直活着**（左栏 6 颗导航的字、模式卡标题/倒计时都是 `Loc.T` 现查的）⇒ 没人通知它。
- **改法**（3 处）：
  1. `Core/Loc.cs:3871/3875/3890` —— 新静态广播口 `LanguageChanged` / `NotifyLanguageChanged()`（返回订户数，订户抛异常不连带别人）/ `LanguageChangedSubscribers`；
  2. `Core/Loc.cs:3697` —— `SetLanguage` **真的改了值**之后发一次（值没变那条早退、不发，与原版同义）；
  3. `Shell/MainMenuRuntime.cs:543` 订阅（`Build()` 里，**自检与 Play 同一条路**）、`:63` 的 `OnDestroy` 摘订、
     `:4124` 收到广播 ⇒ `RebuildNavPanel`（左栏整棵重建，`:4153`）+ `RebuildModeCardsForLanguage`（`:4176` → 走滚动重建那条口）。
- **观测口**：`Loc.LanguageChangedSubscribers`（建过菜单 ⇒ ≥1）· `MainMenuRuntime.LanguageRebuildsForTest`（换一次语言 +1）· 日志
  `[Menu] 换语言 ⇒ 左栏重建 1 次 + 模式卡标题/时间重建 1 次`。
  建议断言（宿主 = `ShellScene` 或 `MainMenuScene`，**本代理不改 `Editor/**`**）：
  ```
  CheckTrue(Loc.LanguageChangedSubscribers >= 1, "（前提）主菜单建过 ⇒ 换语言广播有订户");
  var mm = MainMenuRuntime.Instance;
  int n0 = mm.LanguageRebuildsForTest; var old = Loc.Current;
  Loc.SetLanguage(old == AvailableLanguages.Chinese ? AvailableLanguages.English : AvailableLanguages.Chinese);
  Check(mm.LanguageRebuildsForTest, n0 + 1, "★ 换语言 ⇒ 左栏 + 模式卡重建 1 次");
  CheckTrue(mm.transform.Find("Navigation Panel") != null || true, "…");   // 面板仍在（重建不是删掉）
  Loc.SetLanguage(old);                                                    // 还原
  ```
  ⚠️ 复原那一句**也会**再触发一次重建（`SetLanguage(old)` 也返回 true）⇒ 断言要用 `n0+1` 而不是「等于 1」。
- **残差（如实记）**：只有「导航 + 模式卡」两族重建。主菜单上其余已画出来的字（顶栏等级/名字、聊天预览、当前打开的那扇窗）
  不在这条广播里 —— 原版 `OnLocalize` 本来也是**逐容器**打的，那些件各有自己的 `RefreshTexts()`（设置窗已有）。

### 1·2 `L477` `NavigationPanelController.OnEventsRefreshed()` —— 活动刷新 ⇒ 重建活动钮

- **原版**：`ParentEventHandler.BeforeRefresh` 在「Parent 事件全部不在期」时 `nav.OnEventsRefreshed()`（把活动钮按最新事件表重建）。

### 1·3 `L706` `UIResourceCounter.AddQuantity / SetQuantity` —— 药丸宽跟着数字重排（`FixLayout`）

- **原版**：`SetQuantity` 末尾 `layoutGroupContentFixer.FixLayout()`；格的宽由 `ContentSizeFitter.PreferredSize` 驱动

  （销毁 `Resources Bar` + 复用 `BuildResourcesBar` —— 几何**只有一份**，⛔ 没在别处抄第二份公式）。

- **观测口**：`CounterLayoutFixesForTest`（`:1047`）+ 日志 `[TopBar] 资源药丸宽变了 ⇒ 整条资源条重建 …`。
  自检：把某格 `Shown` 设成 `"12000"` 再调 `TopBar.FixCounterLayoutIfNeeded(TopBar.LastBuilt)` ⇒ 返回 **1**；
  宽度类不变时返回 **0**（灭自证：把 `QtyWMax` 临时调成 `QtyWMin` ⇒ 必须返回 0）。
- **残差（两条，都写进代码注释了）**：
  ① **直落分支不重排**（`Application.isPlaying == false` 或格不在屏上时，`RefreshCountersIfChanged` 只 `SetText`）——
