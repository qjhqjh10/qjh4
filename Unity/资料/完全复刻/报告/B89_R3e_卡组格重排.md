## §1 逐条

### ① `DeckEditorState` 加 `TryMove`（判据 = 原版 `DragAndDropItem` 的落点语义）

| 符号 | 行 | 是什么 |
|---|---|---|
| `RowOrderOf(cardIds, warlordId, defensiveId)` | **1103** | 卡组的「行序」= `CardIds` **去重**后的卡 id（剔除督军/防御卡那两条）。⚠️ 与 `DeckRuntime.DeckEntries()` 的 `seen` **逐字同口径**（那个方法按 id 去重 ⇒ 行号 ≠ `CardIds` 下标） |
| `TryMoveInList(...)` → `List<string>` | **1126** | **纯函数**（不碰存档）⇒ 自检可以只给一个 `List<string>`。失败返回 `null` + `why` |
| `TryMove(fromRow, toRow, out why)` | **1169** | 把上面那步应用到本卡组（改 `Deck.CardIds`）；**不落盘**（落盘仍走 `MarkDeckDirty()` + 存档链） |
| `CardIdAtRow(row)` | **1179** | 行口径读口（自检用） |

**移动语义（逐句对过）**：`RemoveAt(from)` 之后 `Insert(to)` ⇒
- 往下拖（row2→row4，`[A,B,C,D]`）⇒ `[B,C,A,D]`（落在目标那一格**之后**）
- 往上拖（row4→row2）⇒ `[C,A,B,D]`（落在目标那一格**之前**）
- 两个方向都等于「**挪到那一格**」，与原版拖放直觉一致。

**边界（全部显式返回 false + 人话 `why`）**：
| 情形 | 结果 |
|---|---|
| `fromRow`/`toRow` < 2（督军 / 防御卡那两行） | 拒做 —— 那两个是**固定槽**（原版也不动它们：`TryAdd`/`TryRemove` 对 hero/defence 单独路由） |
| 行号越界（那一行没有卡） | 拒做 |
| `fromRow == toRow`（拖回原位） | 拒做（`why = "拖回原位"`） |
| 同一张卡有多份 | 允许；重建时**份数原样保留、且聚在一起** |
| `CardIds` 里混进督军/防御卡 id（历史脏数据） | **原样补回末尾**（⛔ 不静默丢） |

### ② `DeckRuntime` 接上松手那一跳

| 符号 | 行 | 是什么 |
|---|---|---|
| `EndDragAt(float screenX, float screenY)` | **9187** | 松手：落点在**列表矩形内**、落在**另一行**、且两行都是卡（≥2）⇒ `State.TryMove(_dragRow, target, out why)` → 成功则 `MarkDeckDirty()` + `Say("已调整位置")` + 记 `LastReorderForTest`；**其余一律交给原来的 `EndDrag`**（拖出右缘 = 删除 · 没动 = 开卡窗） |
| 松手调用点 | 拖拽块那一行 | `EndDrag(px.x)` → **`EndDragAt(px.x, px.y)`**（1 行替 1 行） |
| `LastReorderForTest` | **9210** | 自检读口：最近一次重排落到的那一行（`-1` = 没重排过） |

**落槽口径（你问的「会不会落错槽」→ 结论：不会，只可能视觉错位）**：
- `_dragRow` 是**数据行号**（`DeckRows()` 的下标），拖拽期间**不随滚动变化**；
- 落点行号 = `floor((y − ListY + _deckScroll) / RowPitch)` —— 与 `RefreshDeckList` 摆行那条式子
  （`y = ListY + i×RowPitch − off`，`off = _deckScroll − firstRow×RowPitch`）**互逆**；
- ⇒ 滚过一整屏之后指针落在哪一行仍算得对。**视觉上**「贴指针的那一行可能已经换了名字」是上一轮 §4·3 那条，
  **但落点用的是行号、不是视觉** ⇒ 不会写错数据。**真机第 2 步顺手核一下即可**。

## §4 没查清

1. **落位那一下的动画/回位补间**：原版 `OnEndDrag` 把被拖件送回目标槽时有没有 Tween（`DOTween` 那条），判据**没读到** ⇒ 本轮**不做**，记待接（⛔ 不编一个动画）。
2. **重排要不要触发「卡组合法性重算」**：原版拖放后会 `ValidateDeck` 吗？本轮只 `MarkDeckDirty()`（不重算合法性）。合法性本身与顺序无关（规则不看顺序），所以**今天无差异**；但若将来有「按顺序计数」的卡（没有判据）就要回头。
3. **`CardIds` 里 `#HB_` 异画条目的顺序语义**：`RowOrderOf` 按 plain id 去重（与 `DeckEntries` 同口径），但异画条目与普通 id 并存时谁先谁后**没有判据**（原版 `Collection Deck` 的排序规则未读）。
