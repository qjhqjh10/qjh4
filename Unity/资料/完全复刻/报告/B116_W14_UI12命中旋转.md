## 二、算式：改前 / 改后

**改前**（`CollectHits`，两行，只比轴对齐盒）：
```csharp
if (Mathf.Abs(px - c.x) > half.x) continue;
if (Mathf.Abs(py - c.y) > half.y) continue;
```
`QuadBoxPx` 只读 `lossyScale`，**一次没读 `transform.rotation`**。

**改后**（两行 → 两行，**行数零变化**，下游账落点不漂）：
```csharp
if (!QuadContainsPx(q, c, half, px, py)) continue;
```
新增（**类尾**，`Shell/PointerLayer.cs:1922-1978`）：
- `θ == 0`（旋转基 `ax == (1,0,0)`、`ay == (0,1,0)`，1e-6 容差）⇒ **走原来那两句直路，逐位不变**。
- 否则：设计 px → 世界（`ToDesignPixel` 的逆：`dx=(px-cx)/PxPerWorldX`、`dy=(cy-py)/k`）→ 投到 quad 自己的两根轴 → `|lx| ≤ half.x/kx`、`|ly| ≤ half.y/ky`。
- 🔑 **为什么不在设计 px 里直接转**：非 16:9 下 x 斜率 = `PxPerWorldX`、y 斜率恒 = 108，两者**不等** ⇒ 把世界角直接套在设计 px 偏移上会把矩形判歪；16:9 下两种做法等价。
- ⚠️ 与「并集 / 登记表」的边界：那两条路产出的是**未旋转帧**的外接盒；今天「主件带旋转 × 并集/登记表」**零交集**（两件旋转卡背都是单 quad 子树，登记表只服务顶栏 4 颗）⇒ 不另立语义，已写进注释。
