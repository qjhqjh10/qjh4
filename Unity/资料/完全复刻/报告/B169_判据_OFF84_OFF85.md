## 一、OFF-84 —— 练习 / 教程两张竖向小卡之间的间距

### 1.1 `FlexibleGridLayout` 全部字段（`dump.cs:104785-104843`）

| 字段 | 偏移 | 类型 | 序列化 | 主菜单实例值（`MonoBehaviour_1961.json`） |
|---|---|---|---|---|
| `rows` | 0x60 | int | ✅ | **2** |
| `columns` | 0x64 | int | ✅ | **20** |
| `itemSize` | 0x68 | **Vector2** | ✅ | **535 × 414.4** |
| `spacing` | 0x70 | **Vector2（x=0x70 / y=0x74）** | ✅ | **20 × 20** |
| `grid` | 0x78 | bool[,] | ❌（运行时分配） | — |
| `m_Padding`（基类 LayoutGroup） | 0x20 | RectOffset | ✅ | L38 R16 T0 B0 |
| `m_ChildAlignment`（基类） | 0x28 | TextAnchor | ✅ | 3 = MiddleLeft |

**⇒ 回答用户的问题：有，而且是原版参数。** `spacing` 是**一个 `Vector2`，横纵各自独立**（`x` 管横向、`y` 管纵向），主菜单这份的**纵向间距 = `spacing.y = 20`**。
**没有** `alignment/itemOffset` 之类的第二套间距；影响「两张小卡之间距离」的**只有 `spacing`**。
（`AutoLayoutSpacingByItemSize`（`dump.cs:104753`）是另一个「按宽高比改 HorizontalLayoutGroup 间距」的组件，主菜单**没挂**，实例只在 `bundle_menus_assets_all/MonoBehaviour_5343527243449095809.json`＝`spacingAt16_9:-40 / spacingAt4_3:84.76`。）

⚠️ **多实例对比（铁律 5·c，不是一份）**：`bundle_menus_assets_all` 里 3 份 = `rows2/cols200/item 372.9×427.9/spacing 28×32`；`battlearenaleviathan` 1 份 = `rows2/cols10/item 100×100/spacing 0×0`；主菜单 `spacing 20×20`。**别把 20 当全局值。**

### 1.2 `spacing` 到底怎么用（`FlexibleGridLayout__CalculateLayoutInputHorizontal.c`）

**真正摆位置的不是 `GenerateGrid`，是 `CalculateLayoutInputHorizontal`**（`SetLayoutHorizontal/Vertical` 是 `RVA 0x4B33B0` 空桩）。逐句反编译：

- 横向：`posX = x*spacing(0x70) + padding.left − padding.right + x*itemSize.x`；`width = (sizeX−1)*spacing + sizeX*itemSize.x`
- 纵向：`posY = y*spacing(0x74) + 居中偏移 + padding.top − padding.bottom + y*itemSize.y`；`height = (sizeY−1)*spacing + sizeY*itemSize.y`
- `sizeX/sizeY` 来自子件上的 **`FlexibleLayoutSizeOption`**（`dump.cs:104846`，`sizeX 0x20 / sizeY 0x24`，有公开 `set_SizeX/set_SizeY`）。
- `m_ChildAlignment` 只允许 3（纵向居中，留白×0.5）与 6（纵向置底）；其余分支 `Debug.LogWarning`。

**`GenerateGrid`（RVA 0x8087B0）里没有间距**：它只做 `grid = new bool[columns, rows]`（读 `+0x64` / `+0x60`）＋ 把布尔网格清零。**间距完全不在这个函数里**。

### 1.3 由此推出的原版真实排版（和参考图逐项吻合）

- **大卡 = `sizeY 2`**：高 `(2−1)*20 + 2*414.4 = 848.8` ⇒ 就是用户说的「535×850」。
- **小卡 = `sizeY 1`**：高 `414.4`。
- **两张小卡纵向相距 = `spacing.y = 20`**（`y=0` 与 `y=1` 的 `posY` 差 `= 414.4 + 20`）。
- 填充顺序是**先竖后横**（`FindSpaceOnGrid` 外层扫 x、内层扫 y）⇒ 5 张卡 = 3 列大卡 + **1 列两张小卡**，正是参考图的样子。
- **原版有 1x2 容器 prefab**：`bundle_menus_assets_all/GameObject/Base Game Mode Container 1x2.json`（另有 `1x2 No Timer` / `1x2 Raid or Army Release` / `Draft Game Mode Container 1x2`）。本地 build 只实例化了 `Base Game Mode Container 1x1`（`menulayout.tsv:4` 五个子件名全是 `1x1(Clone)`）⇒ **本地 build 的「2 行小卡」是数据差，不是布局类差**。

### 1.5 方案建议：**先做 C（原版机制），A/B 都是退路**

| 方案 | 做法 | 影响面 | 风险 |
|---|---|---|---|
| **C（推荐，= 原版）** | 保留**一个** Grid（`rows=2/cols=20/item 535×414.4/spacing 20×20`），只让前三张卡用 **1x2 容器**（或运行时把它们的 `FlexibleLayoutSizeOption.sizeY` 设 2，走原版公开 setter），然后照旧调 `GenerateGrid()` 重建 | 只动**喂给 Grid 的容器数据**（`LiveopsMainMenuData.ContainerRef`，`MainMenuWindow.InstantiateLiveOp` 用它选 prefab）；`MenuLayoutProbe` 里「写 rows=1 / itemSize.y=内容高」那段**要删掉** | 低。**唯一未知**：`1x2` prefab 的卡内排版在 535×848 下是否正常（本地没跑过）——但这是原版资产，按铁律 11 本来就该这样 |
| A 两个容器 | 大卡横向 ScrollRect + 小卡纵向容器各一套 | 要改 UI 树结构（`Content`/`GameModes` 下新建节点）＋ 两套滚动 | 高：**破坏原版滚动模型**（原版是一个 Grid 一屏横向滚），且 `AdaptFlexibleGridLayoutByAspectRatio` 只认单个 `flexibleGridLayout`（`dump.cs:104731`），两套要各挂一份 |
| B 运行时手动摆位 | 绕开 Grid，直接写每个卡 `anchoredPosition`/`sizeDelta` | 只动探针 | 中高：**跟 LayoutGroup 打架**（Grid 每帧/每次 rebuild 都会把子件摆回去，`MarkLayoutForRebuild` 到处都在调）；`Content` 的宽度也没人算了（现在由 Grid 的 `CalculateLayoutInputHorizontal` 写 `sizeDelta`）⇒ 要自己复刻这段，等于重写半个布局类 |

**推荐理由**：C 不需要新写任何布局逻辑，而且「大卡 = 1x2 容器」在原版资产里**直接存在**（`Base Game Mode Container 1x2`），是最省事也最不偏离原版的一条。
**A/B 什么时候才用**：只有当 `1x2` prefab 在本地缺失或卡内排版崩掉、且短期修不好时。

### 2.2 主菜单 ScrollRect 运行时 `enabled=False` —— 谁关的

- 场景序列化是 `m_Enabled: 1`（`MonoBehaviour_1982.json`）。
- 全 `decomp_full` 里**唯一**写这个 ScrollRect `enabled` 的代码：**`MainMenuWindow.ToggleScroll(bool)`**
  （`MainMenuWindow__ToggleScroll.c`：`UnityEngine_Behaviour__set_enabled(*(this+0xA0), option)`；`scrollList` 字段偏移 `0xA0`，`dump.cs:105528`）。
- 它的**全部调用者**只有两条，都在排位教学模式里：
  - `TutorialStagePlayRanked__ShowCursor.c` → `ToggleScroll(this, **0**)`（关）
  - `TutorialStagePlayRanked__CheckForCompletion.c` → `ToggleScroll(this, **1**)`（开）
- 我又查了「所有调用 `Behaviour.set_enabled` 的类」全表 + `TutorialManager/FTUESelectDeckWindow/ScrollConflictManager/UI_InfiniteScroll`，**没有第二条路**会关它；也没有任何 UnityEvent 指向 `ToggleScroll`（`assets_full` 与 ExportedProject 全库搜 `ToggleScroll` 只命中两个 `.cs`）。
- **⇒ 原版里「内容装得下就把它关掉」这种逻辑不存在**（`MenuLayoutProbe.cs` 注释里那句是推测，不是判据）。
- ⇒ 我们离线版里它是关的 ⇒ **要么教程链走过了 `ShowCursor`、要么别处有写入**。❓ **还没查清是哪一条**，建议实机时用 Harmony 钩 `UnityEngine.Behaviour.set_enabled` 打调用栈（一次就能定位），⛔ 别再猜。

### 2.3 原版有没有「鼠标贴边自动滚动」

**❓查不到 = 原版没有这种组件/行为。** 依据（不是「没搜」）：
- 反编译全量 `grep` 关键词 `autoScroll / scrollSpeed / edgeScroll` → 0 命中（`d:/2/tools/all_strings.txt` 里的相关标识只有 `mouseWheelScrollSize`，而它属于 UIToolkit 的 `Scrolling`，`dump.cs:383844`，与本项目 UI 无关）。
- Unity UI Extensions 里**有**能做「自动滚动/吸附」的组件（`ScrollRectTweener` / `ScrollPositionController` / `ScrollSnap` / `UIScrollToSelection(XY)` / `UIVerticalScroller` / `Snapper8` / `ScrollRectLinker`），我把它们的 guid 全查出来，在**全部 1389 个 prefab + 全部 `.unity` 场景**里逐个搜过 —— **一个都没被挂上**（唯一命中的是 `UI_InfiniteScroll`，在 `Main Menu Offer Container Carousel 1x1.prefab` 和 `Reward Event Container 1x1.prefab` 上，那是无限循环轮播，不是贴边滚动）。
- `ScrollViewFocusFunctions`（`FocusOnItem` / `LerpToScrollPositionCoroutine`）**存在**，但那是「把某个 item 滚到可见位置」的协程，**不是鼠标贴边触发**，而且没有任何 `IPointerEnter` 侧的实现。

⇒ **结论**：贴边自动滚动**要自己做** ⇒ 按铁律 18 打 `🔶 自己设计（非原版）`；同时它是**用户 2026-11-07 明确要求**的行为改变，不是「凭空加功能」。

### 2.4 「到不了最右」的障碍归因（逐界面）

| 界面 | 障碍 | 判据 |
