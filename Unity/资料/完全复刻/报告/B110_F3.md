### Bug 1 · `effective_max_size()` 把 `overridden: 0` 的平台块当成生效

- **位置**：`Unity/工具/res_audit.py: effective_max_size()`（修前 `:251-264`，修后 `:257-274`）
- **错在哪**：旧实现是「有 `Standalone` 块就按它的 `maxTextureSize` 算」，**完全不看 `overridden`**。
  而同一个文件里 `parse_platform_settings()` 的 docstring（修前 `:213`）写着「`overridden: 0` 的平台块**不生效**，Unity 回落到 `DefaultTexturePlatform`」—— **实现与自家 docstring 自相矛盾**。

  ```python
  blk = ps.get("Standalone")
  if blk and blk.get("overridden") == 1 and blk.get("maxTextureSize"):
      return blk["maxTextureSize"], "Standalone"
  ```

### Bug 2 · P2 逐像素比对把 `alpha=0` 区域的 RGB 差算成「内容不同」，且没做 gamma 复检

- **位置**：`pixel_diff()`（修前 `:372-388`，修后 `:412-458`）+ `run()` 里 P2 的判定分支（修前 `:984-1003`，修后 `:1054-1087`）
- **错在哪**：
  ① 旧版对整幅图（含 alpha=0 的像素）算 RGB 差。我们的导出把透明区 RGB 写成 0、原版保留白色/原色 ⇒ 差全落在**不可见像素**上，却被算成内容差（`B110_R1 §4-a`：18 条）。
  ② 旧版只比原始编码。我们存 sRGB、原版存 linear ⇒ `srgb2lin(我们的) ≈ 原版`，导入 `sRGBTexture: 1` 后 GPU 取值一致（21 条）。
- **修法**：
  ① `pixel_diff()` 改成返回 dict：`all / rgb / rgb_mask / gamma / mask_frac`；`mask = (alpha_ours > 0) | (alpha_orig > 0)`（**至少一侧可见**才算），只在掩码上算 RGB 均值。整图全透明时退回全像素（防除零）。
  ② 新增 `_srgb_to_linear()` 复检：`g1 = |srgb2lin(ours) − orig|`、`g2 = |ours − srgb2lin(orig)|`，取最小值（**正反两向都不押方向**）。
  ③ 判定顺序：`all ≤ 3` → `rgb_mask ≤ 3 且 < rgb`（仅透明区不同）→ `gamma ≤ 3` → `rgb ≤ 1`（仅 alpha 不同）→ 才算 `内容不同`。
  ④ 法线图那条旧注释「压缩通道重排会放大差异」当**改掉**（R1 明确：排除理由不是压缩通道重排，是 gamma 编码）；现在落进 `内容不同` 的行会写明「本行是连 gamma 复检也不等价」。
- **修前读数 → 修后读数**：`内容不同（需核）57 → 18`；③ 逐像素 `不同 56 → 17`、`近似 312 → 351`。
  - 回收 **39 条**，与 R1 的拆分**逐条对上**：**18 条 alpha=0 区**（`EC Whip Basic` 0.30 · `EC Whip Lucius 2` 0.26 · `Chain_Rugged_Trail` 0.43 · `Glow_Noise_Stylized` 0.27 · `Lightning_001` 0.08 · `Maulerfiend_Tentacle` 0.29 · `Shimmers01` 0.67 · `Tiretrack_motorcycle_1` 0.90 · `Trail Narrow Noise` 0.25 · `Trail_fading` 0.56 · `Trail_Plasma_Stylized_2` 0.20 · `Tyranid_Tentacle` 0.40 · `water` 0.43 · `Gauss Rays` 1.77 · `Lighting Trail` 2.65 · `EmojiOne` 1.31 · `40K_shop_offer_booster_Sautekh` ×2 = 1.06）

### Bug 3 · 「关键字未声明」的 `our_kws` 只从 `#pragma` 收（而且 valid/invalid 从来没分开）

- **位置**：`RE_PRAGMA` / `RE_TOGGLE_KW`（修前 `:329`，修后 `:361-369`）· `parse_shader()`（修后 `:387-397`）· `parse_mat_props()` + 新增 `_mat_keyword_section()`（修后 `:277-360`）· `run()` 的 `unk`（修后 `:1179-1189`）
- **错在哪**（两处，第二处是修第一处时才现形的）：
  ① `our_kws` 只从 `#pragma multi_compile(_fragment|_vertex)?` 与 `#pragma shader_feature(_local|_local_fragment)?` 收 ⇒ **不认 `#pragma multi_compile_local` / `shader_feature_local_fragment` 等全组合**，也不认 `Properties` 里的 **`[Toggle(KEY)]`**。
  ② **旧 `parse_mat_props` 根本没有「valid / invalid」之分**：它从 `m_ValidKeywords:` 那一行的行尾往后把整份 `.mat` 里所有 `  - xxx` 行都收进来 ⇒ 连 `m_InvalidKeywords:` 一节也当成我们的关键字。于是「Unity 说 shader 不认的死值」被当缺陷报。
- **修法**：
  ① 关键字声明**三处全收**：`#pragma multi_compile*` / `#pragma shader_feature*`（正则放宽到 `multi_compile\w*` / `shader_feature\w*`）＋ `[Toggle(_KEY)]` / `[ToggleOff(_KEY)]` / `[ToggleUI(_KEY)]`；`multi_compile _ _FOO` 里的空位 `_` 跳过；pragma 扫描对象从 `.shader` 正文改成 `blob`（含 `#include`，与属性那一路一致）。
  ② 新增 `_mat_keyword_section()`，按节截断到下一个二级键，返回 `(kws_valid, kws_invalid)`。
  ③ 缺陷只算 **`m_ValidKeywords` 里 shader 没声明的**；`m_InvalidKeywords` 里 shader 不认的**不再当缺陷**（R1 §7 ①：Unity 自己判的死值，运行时开着也不起作用），但要**出声**：计入新信息项 `关键字死值(在 m_InvalidKeywords、目标 shader 不认)`。
- **修前读数 → 修后读数**：`材质未消费（关键字未声明）119 → 71`
  - **非战场 17 份材质 → 0**：`Barge_1` · `Battle Arena Leviathan Dynamic Objects Alt Ambient{ Variant,}` · `Dark Angels Background Sky Orbiting` · `Default-Particle` · `Explosion_Color` · `Fighter Jets` · `FireBlack` · `FireRed` · `Flames Loop Green` · `Flames Loop Red` · `LightningTrail_environment Soft__3e59bd19` · `Space Wolves Battle Arena Baked Full Moon` · `Space Wolves Props 1 Extra-Ambient` · `Stealth_Icon` · `Trail Distort__1ade9d4f` · `Waterfall_ExtraColor` —— 逐份实测：**这 17 份的 `m_ValidKeywords` 每一条现在都能在自家 shader 里找到**（`u2 = valid − declared` 全为空）。
  - **剩下的 71 条全部在 🛑 `WarpforgeVFX/ArenaOriginalPrefabs/**`（战场线，用户 2026-10-29「暂停，以后再说」）**，逐条看是 `_SURFACE_TYPE_TRANSPARENT` 一类的合法关键字 + 我们的重打包 shader 确实没声明（比如 `WFUnlitAmbient.shader` 没有这个 pragma）。**与 R1 的「104 条战场线」不是同一个数**：旧 104 里混了 valid/invalid 两节被一起算，现在分开后是 71（工具口径下的「valid 且未声明」）。
  - 新信息项 `关键字死值 = 266`（`m_InvalidKeywords` 里 shader 不认的那些；以前全混在 119 条缺陷里）。
- **⚠️ 关于「唯一该留的是 `_SOFTPARTICLES`」—— 实测这条在工具口径下不成立，如实写清**：
  `LightningTrail_environment Soft__3e59bd19.mat` 的 `m_ValidKeywords` 是 **`_SOFTPARTICLES`**（invalid 是 `_SURFACE_TYPE_TRANSPARENT`）。它这句话在 shader 侧**被两处声明**：`WarpforgeVFX/Shaders/WFParticlesExtraColorEC.shader:50` 的 `[Toggle(_SOFTPARTICLES)]` 与 `:103` 的 `#pragma shader_feature_local_fragment _SOFTPARTICLES` ⇒ 收全三处后**它不再是「未声明」**，不会留在缺陷里。
  这与 R1 §7 末段自己是自洽的（R1 原话：「**这不是"未声明"，是"声明了但这个开关在该材质上是 ON，行为对不对要核"**」）。⇒ 「保真」这一点**没丢**：该材质上 `_SOFTPARTICLES` 确实是 **ON**，R1 §7 / §8 那条**行为待核项（软粒子分支 + `_SoftParticleFadeParams` 三段 fade）仍然成立**，只是它不该出现在「关键字未声明」这个缺陷类里。
- **正样例仍能抓到**：`材质未消费（属性未声明）1`（`TextMeshPro/.../LiberationSans SDF - Drop Shadow.mat`）照常报；战场线 71 条照常报（**一条都没被「宽松掉」**）；死关键字 266 条改成信息项照常出声。

## 顺手发现

1. 🟠 **`pixel_diff` 原来还有个隐性口径问题**：它按 `max_px=4,000,000` 决定要不要缩到 256²，而 **2048×2048 = 4,194,304 > 4M ⇒ 会被缩**。也就是说 2048 的贴图是在 256² 上比的。本轮没改（超出三处 bug 范围），但它意味着「2048 图的像素差」是缩略图口径。若以后要精确到原分辨率，得改这个阈值或改成分块。
2. 🟠 **`CardPresentation/Editor/B110_F2_Assert.cs` 缺 `.meta`**（另一个并发写手正在建的文件，不是我的）。它会让日志出现 `缺 meta 1`，但**没有进缺陷类**（`B110_F2_Assert.cs` 不在 `ASSET_EXTS` 里）。别当缺陷修别人的在飞文件。
3. 🟠 **`parse_mat_props` 的 valid/invalid 混淆**是独立于「pragma 收不全」的第二个 bug（见 Bug 3 ②）。即使不修三处声明，它也会让这一类统计失真；已在本次一并修掉。
4. 🟡 **旧实现里 `RE_PRAGMA` 扫的是 `.shader` 正文（`b`）而不是含 include 的 `blob`** —— 与同一函数里收集属性那一路不一致。已改成 `blob`。
5. 🟡 **66 条新增尺寸项里有 1 条在 `boosterpack/`**（`40K_shop_offer_booster_UM_Expansion_1.png`），与其余 65 条 `ui_menu/` 不是同一批导入来源，但机制相同（Default 块 1024）。R1 顺手发现 #6 只预告了 `Art/ui_menu` 那批，这条是同类未被点名的。
6. 🟢 **`res_audit.py` 不会误写盘**：`main()` 是 `add_help=False` + 手判 `--help/--scan/--dry`，不带参和 `--help` 都只打印用法并 `return 0`，没碰到本项目那次 `merge_ledger_parts.py --help` 的坑。
