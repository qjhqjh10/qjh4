## ⑤ 顺手发现

### ⑤-1 `HitOf` 的口径结论（本任务点名要核的那件事）

**结论：`HitOf` 拿的【不是】「可射线件的并集 + `m_RaycastPadding`」口径。**
它是「在钮节点下找名为 `Hit` 的**直接子件**，取它身上的 `WindowButton`」——即
**① 单件（不是并集）· ② 不读任何 `m_RaycastPadding` · ③ 完全没碰命中矩形**（只判「组件在 && `onClick` 非空」）。

- 本工程的**实际**命中模型也不做并集：`Shell/PointerLayer.cs` 的 `HitQuad(b)` = `b.GetComponentInChildren<ImageQuad>()`
  ⇒ **一颗钮只有一个命中 quad**；`m_RaycastPadding` 那一档走**登记表** `HitRectOverride`（`ApplyHitRectOverride`，
  doc 里写着「出厂态只有顶栏那 4 颗钮登记」）。
- 而**原版**的判据确实是并集 + padding：`Shell/MenuDraw.cs` 的 `Union(...)` doc 写得很清楚
  （「每一颗 `m_RaycastTarget==1` 的 Graphic 各按自己的 `m_RaycastPadding` 修正后取并集」，出处
  `资料/普查产出_第四会话/普查_全仓命中区与关闭键族.md` §〇-1）。
  ⇒ **这是「我们的等价实现 vs 原版判据」的一条已知差**，但**不是本批该修的**（改它会动 `PointerLayer` / `MenuDraw`，不在白名单）。
- 对 `B103W2` 的 A2 而言：A2 是**前提**断言（命中区在不在），`HitOf` 这个口径够用，
  但它**不验证**「命中区盖住了画出来的那块」——⛔ 别把它当成命中区几何的验收。

### ⑤-2 `[A388(b)]` 那条 `Debug.LogWarning` 的文案本身是自相矛盾的

它写「钩子仍挂着 {n} 条」，而 `n = 0` 时读起来是「仍挂着 0 条」。这条警告已随两档合并被删（内容搬进注释）；
若将来还要在别处重建同类警告，**文案要按状态分支写**，别把数字直接塞进「仍挂着」这个断言式句子里。
