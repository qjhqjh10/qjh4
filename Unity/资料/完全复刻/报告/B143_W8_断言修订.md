## §3 两条断言各自的「怎么才能红」（灭自证）

### ① `Check(matNull == 0, "…都拿得到材质（null n / 总数 颗）…")`

- **怎么红**：让任意一颗 `ParticleSystemRenderer` 的 `sharedMaterial` 拿不到 ⇒ `matNull ≥ 1`。
  本机可复现的两条路（不跑 Unity 也能推）：
  a) `Core/BoosterPackAssets.TryEnsureLoaded()` 不再加载 `LiftPackParticles` 依赖的 6 只依赖包（`B118_W24` 离线复核：按旧加载法 338 个材质槽有 **200 个解析失败**）；或
  b) 给任一颗粒子清空材质槽（prefab 侧 `m_Materials[0] = {fileID: 0}`）。
- **不是自证**：期望值 `0` 要求的是 **Unity 真实资产槽**的读数，不来自我们任何常量；标签把 `实际 null 数 / 总数` 印出来。
- **方向性自检**：把判定反过来（`matNull != 0`）⇒ 现网 17 颗全可读（`B118_W24` 现读 338/338 可解）⇒ **立刻红**，说明不是恒真空断言。

### ② `Check(lowQ == 0 && readable > 0, "…renderQueue 全部 ≥ QCard(3123)（偏低 n 颗 · 可判 r / 总数 颗 · 最低 …）")`

- **怎么红（四条互不相同的路）**：
  a) 任一**可读**材质的 `renderQueue < QCard`(3123) ⇒ `lowQ ≥ 1`（例：删掉 `Shell/BoosterPackOpenWindow.cs:1630` 的 `m.renderQueue = QCard;`，粒子回 prefab 默认 3000）；
  b) 把粒子提到 `QShade`(3122) 而不是 `QCard` —— **裁定 ② 收紧后这一档现在会红**（旧阈值下会漏）；
  c) `readable == 0`（一颗都读不出材质）⇒ `readable > 0` 为假 ⇒ **红**，标签明写「未验，按红计」（裁定 ①）；
  d) 把 `QCard` 常量本身抬高到实现设置值之上。
- **不是自证**：阈值的**两端在不同文件** —— `lowQ` 来自资产侧的材质队列，`QCard` 是这扇窗「卡层最低档」的公共常量（`BoosterPackOpenWindow.cs:150`，与 `:1630` 的写入值同一处定义）⇒ 断言的是「粒子必须在卡层之上」这条**渲染事实**，不是「某常量 == 某常量」。
- **方向性自检**：把 `<` 改成 `>` ⇒ 现网全部 `== QCard`(3123) ⇒ **立刻红**。
- **灭「两边一起改回去」**：若有人把耦合重新接回（null 也去 `lowQ++`），日志会自露 —— ① 打 `null 1 / 17`、② 打 `偏低 ≥1 颗 · 可判 16 / 17`，而 `readable + matNull == 总数`、`lowQ ≤ readable` 这两条不变式把「同一颗被数了两遍」显出来。
- **灭「零覆盖报绿」**：`readable > 0` 就是这条的闸；把 `readable > 0` 删掉，全 null 场景下 ② 会重新变成 `✓ 偏低 0 颗 · 可判 0 / 17`（= 静默失败）。

### 3.1 已知取舍

- 外层仍保留 `if (prs.Length > 0) { … }`：**不是静默跳过** —— 前提 `:126` 自己是一条会红的 `Check`；`prs.Length == 0` 时日志里是 `✗（前提）卡包实物子树里有粒子`，两条被测断言不执行。这与 `B141_BattleHud_Assert.cs:198-199` 的既有写法同族（`Check(m != null, …); if (m == null) return;`）。
