**批处理怎么驱动**（本轮唯一一个「非现成套路」的地方，已查证）

- `TweenOutline`（`CollectionWindow.cs:5243`）建补间时**没有** `SetUpdate(CardTween.Mode)`（不像 `CardTween.Use`），
  而 `DOTweenSettings.asset` 的 `defaultUpdateType: 0` = `Normal`，`DOTween.ManualUpdate` 只推 **Manual** 档
  （反编译实证：`DOTween.ManualUpdate` → `if (TweenManager.hasActiveManualTweens)`；
  `TweenManager.Update` 内 `tween.updateType == updateType` 过滤）。
- 本文件又**不能改** `CollectionWindow.cs` ⇒ 断言里对**这一条补间实例**调
  `DG.Tweening.TweenSettingsExtensions.SetUpdate(tw, UpdateType.Manual)` 再 `CardTween.Advance(0.2 + 0.05)`。
  依据（反编译 `DOTween.dll`）：`SetUpdate` 只挡 `t == null || !t.active`（补间建出来就 `active=true`，
  `Tweener.Setup` 里 `isPlaying = defaultAutoPlay == All` ⇒ 我们是 `All`），且 `SetUpdateType` 会把
  `hasActiveManualTweens` 置真。口径与 `Editor/DOTweenSmokeTest.cs` 一致。

### ②·2 `Shell/WildcardTutorial.cs:143`（`Destroy` → 按播放态分叉）

**判据** = `报告/B106_W46.md` §⑤·2：`ForceStart` 里
`if (_instance != null) Destroy(_instance.gameObject);` —— **编辑模式（自检批处理）下 `Destroy`
报「Destroy may not be called from edit mode!」且不生效** ⇒ 旧教程留在全屏根上；`_instance` 只靠 `OnDestroy` 清。

**改了什么**（现读 `:143`）

```csharp
if (_instance != null) { var old = _instance; _instance = null; if (Application.isPlaying) Destroy(old.gameObject); else DestroyImmediate(old.gameObject); }   // 🔴 2026-10-31（`B106_W52` · 判据 `报告/B106_W46.md` §⑤·2）…
```

- **同物理行替换**（行数不变 ⇒ 账落点 `:136`（ForceStart）、`:206`、`:125`、`:166`、`:69`、`:217` 一个没挪）。
- 额外加了 `_instance = null`：**编辑模式下 `OnDestroy` 未必被派**（`CLAUDE.md` §三那条「`DestroyImmediate(组件)` 不派 `OnDestroy`」同族）
  ⇒ 不靠 `OnDestroy` 兜底，避免 `_instance` 留一个已销毁的引用。
- 注释写清了理由（编辑模式不生效 / 不靠 `OnDestroy`）。

**顺手同修**（同一类，同一文件，同物理行）：`:251` `OnDestroy` 里的 `Destroy(_pointer.gameObject)`
→ `Application.isPlaying ? Destroy : DestroyImmediate`。理由：**指针是全屏根的孩子、不是教程 GO 的孩子**，
编辑模式下 `Destroy` 不生效 ⇒ 每跑一次自检就在收藏窗上多一套指针。

## ④ 顺手发现（⛔ 本代理未改，除 §②·2 那处同族修）

1. **`TweenOutline` 的补间没接 `CardTween.Mode`**（`Shell/CollectionWindow.cs:5238-5252`）——
   全仓其它补间走 `CardTween.Use` 会自动 `SetUpdate(Mode)`，这条没有 ⇒ 批处理/编辑模式下**永远不推进**
   （真机 `Normal` 档没问题）。建议**由 `CollectionWindow.cs` 的写手**补一句 `SetUpdate(CardTween.Mode)`
   （我的断言已经自己在测试里切档，**不阻塞**；但补上之后断言可以去掉那两行 hack）。
2. **`ForceStart` 的早退分支会把刚建的实例留在树上**：`Shell/WildcardTutorial.cs:151-155`
   `if (!w._logic.Start()) { …; return null; }` —— 此时 `w`（与 `w._pointer`）已经建好、`_instance` 还没赋值
   ⇒ 返回 null 但节点在。生产路径不会走到（`TryStart` 已挡 `End`），只有直接调 `ForceStart` 才会。
   **未改**（判据不足：原版 `StartWildcardTutorial` 的 `state == End` 支是「只收指针」，没有这个第三种状态）。
3. **`Editor/DOTweenSmokeTest.cs` 是这轮能安全用 `SetUpdate(Manual)` 的唯一实证**，建议复跑时顺手放进
   `_run_8_checks.sh` 之外的**一次性手工**检查（它不是宿主，不在 12 条里）。
