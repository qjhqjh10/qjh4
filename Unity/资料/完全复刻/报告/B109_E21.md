### 3·1 `Label.SetFontMaterial`

```csharp
public void SetFontMaterial(Material m)
{
    if (m == null) return;                                    // 原版 Normal 态「不动材质」
    if (_tmp == null) { Debug.LogWarning(...); return; }       // 点阵后端：出声，⛔ 不静默
    _tmp.fontMaterial = new Material(m);                       // 🔴 必须克隆
    if (_queue >= 0) ApplyQueue();                             // 队列粘住（换材质会冲回默认 3000）
}
```

- **必须克隆的理由**：`ApplyQueue`（`Label.cs:274-302`）的注释里记着 2026-09-27 的实测先例 —— 直接把共享材质写进
  `fontMaterial` 会把 `renderQueue` **写回工程资产**。这里再往前一步：赋进去的**必须**是 `new Material(m)`。
- 两个读口：`FontMaterialName`（**活读** `_tmp.fontMaterial`，去掉 Unity 自己加的 ` (Instance)` 尾巴）与
  `FontMaterialNow`（给断言读 `_FaceColor` 这类参数）。
- ⚠️ **会被换面冲掉**：`SetFace` / `SyncFace` / 文本里冒汉字都会把 `m_sharedMaterial` 换回字体资产那份
  ⇒ 用法必须是「**先定面、后换材质**」（聊天行就是这样：`MenuDraw.TextBox` 建件时定面，之后才换材质）。

### 3·2 `ChatMessageRow.BodyText` / `ApplyTranslationFont`

```csharp
public static string BodyText(SocialData.ChatMessage m)
{
    string t = SocialData.Text(m) ?? "";
    if (m == null || m.TranslationStatus != TransTranslating) return t;
    return t.TrimEnd('\n') + " (" + Loc.T(TranslatingTipTerm) + ")";   // ⛔ 不是 TrimEnd()
}
```

**顺序说明（一处刻意的等价改写）**：原版是「先 `text = GetMessage()`，再在 Translating 支里改写 text」。

⇒ 把「最终正文」**在建件之前**算好（`BodyText` 一次给全），建件之后**只换材质**。
净观测量与原版相同（文字内容、材质都在），只是省掉一次无谓重排。

### 3·3 `Label.CjkFallbackFace`（**续办** · `B109_D1` §3 判定 β ⇒ 方案 A，忠实原版）

汉字是走 TMP fallback 的（fallback 用它**自己的**材质）⇒ **中文玩家在原版里看得到这行的颜色差**。
D1 判定：**β（实现与原版不符）**，不是夹具问题。

**改法（三处，全部零行号漂移）**
