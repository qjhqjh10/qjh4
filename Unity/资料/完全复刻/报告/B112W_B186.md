## 为什么不会丢掉合法 `shield`

合法写法只有两种形状，两条都实测过、都**没变**：

1. **裸 `shield`** —— 段首剥离要求 `wl.Length > icon.Length + 1`（至少再多 1 个字符），
   `"shield"` 长度正好相等 ⇒ **不进剥离分支**，落到 `GiveKw` 命中 `shield`（实测输出 `KW(shield 1)`）。
2. **`shield <值>`**（`shield 2` 这种）—— 剥离会先试 `rest = "2"`，
   `ParseInto("2")` 解不出任何载荷 ⇒ **不剥**，原样交给 `GiveKw`（`shield` + `ReNumber` → 值 2）。

3. **`[Shield] Shield`**（`SW61` / `TAU41` 两张真卡）—— 上游把 `[Shield]` 换成关键词名后
   payload 是 `shield shield`，`:381-382` 的 `ReDupWord` 先折成 `shield`，再走第 1 条。
   实测端到端 `payload="shield shield"` → `KW(shield 1)` ✔。

4. **`shield and vanguard` / `+1 attack, blast 1 and shield`** —— `shield` 不是段首，
   剥图标那一段根本不看它（实测 `SOR40` / `e01f4d54…` 两行改前改后逐字节相同）。

**别的图标词行为一个字没变**：`IconWordsThatArePayloads` 只包含 `shield`，
`wings` / `skull` / `icon` / `eye icon` / `codex icon` / `faith icon` 仍走**无条件剥离**
（它们都不在 `GiveKw` 里，剥错也不会吃掉一次真授予）。

## 顺手发现

1. **`shield` 是 `IconNames` 里第一个「同时是合法载荷词」的图标名** —— 这条不对称以后还会遇到：
   如果将来有人把别的关键词加进 `IconNames`（比如 `[Rally]` / `[Stun]`），
   **必须同时加进 `IconWordsThatArePayloads`**，否则一次真授予会被静默删掉。
   建议在 `IconNames` 的 doc 里留一句（我已在新字段的 doc 里写了，但 `IconNames` 本身的注释还没提这一点）。
2. **`TrimPrefixTail`（`:703`）也读 `IconNames`** —— 它会把「嵌入关键词之前那截」尾部的图标词丢掉。
   `shield` 进表后，理论上 `Give Shield and 'Slay: …'` 这种写法会把 `Shield` 当图标残渣丢掉。
   **池内实测 0 条**（全池 `desc` 里同时含 `shield` 与 `:` 的 19 张，没有一张是 `give … and <关键词>: …` 形状），
   所以本次**没有踩到**；但以后出现这种卡面就会是个静默坑 ⇒ 记一笔。
3. `Parse` 对 `"give shield to a friendly troop"` 返回 `null` **不是缺陷** —— 载荷层本来就不吃整句；
   简报里那条验收要求应在**端到端**（`EffectText.Parse`）口径下核，本次已按此核过。
