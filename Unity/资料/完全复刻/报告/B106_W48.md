3. 匹配 = **按顶点数分桶 + 逐点/点集比**（⛔ 不按名字 —— 同名覆盖的 `Floor`×3 / `Spirt Stone`×2 名字一样、几何不同）：
   - 先按顶点序逐点比；不一致再按**点集**比（格哈希查 27 邻格，`|Δ| ≤ 1e-4`）；

4. **坐标约定（本代理实测钉死）**：OBJ 件 = **原版 X 取反**（取反后 4.7e-8~1e-11，原样 23.1）；`.asset` 件 = **原版原样**（0.0）。比对时 OBJ 侧先把 X 取反回来。
5. 判定分四档：`exact`（按序 0 超点）· `permuted`（点集相同、序不同）· `partial`（点集也缺 = 真缺陷）· `different`（不是同一个网格）。

## ④ 顺手发现（施工单 / 判据里没写，下个会话该知道）

1. 🔴 **施工单 R2-01 那条「工程 `.asset` 是 YAML 文本，可直接解析」的前提只对 3/169 成立。**
   `MyGame/Assets/WarpforgeVFX/Meshes/` 确实是 **169 个 `.asset`**，但和这 169 个流式网格**只有 3 个同名**（`Spirt Stone` · `Card_Remnant_HO Optimization 2` · `Card 3D Subdivided`）。那 169 个是判据 §1.5 说的**「路 A · 特效/卡面网格」**；流式网格真正出货的件在 `WarpforgeVFX/ArenaOriginalPrefabs/**/*.asset`（168/169 覆盖）与 `WarpforgeArena1/arenas/*/Models/*.obj`（165/169 覆盖）。
   ⇒ **以后别把「`WarpforgeVFX/Meshes` 的 169 个 `.asset`」当成「169 个流式网格」**（两个 169 是巧合）。
2. **两侧坐标空间不同**（本代理实测）：**OBJ 件 = 原版 X 取反**；**`.asset` 件 = 原版原样**。写任何"比网格"的工具都要按各自约定折算（与 `工具/gen_arena_vertexcolors.py` 头注释那条一致）。
3. 🔴 **顶点序不保证一致**：`Bunker`（pid `8230726432342916604`，6856 顶点）的**末 9 个顶点**在 OBJ / `.asset` 两侧都被重排（点集完全相同）。⇒ **只按顶点序比会误报 9 点"不一致"**；判据要"先按序、不一致再按点集比"。
4. 🔴 **同顶点数的巧合会伪造"我们的件坏了"**：`BoosterPack`(330) 撞上 `ArenaOriginalPrefabs/battlearenaemperorschildren/Mesh/Gun 21_0.asset`(330)，逐点差 2.29（全 330 点）。⇒ 候选必须再做"点集确认"，否则会把"我们没有那个 `.asset`"报成"`.asset` 坏了"。
5. **抽样哈希不能当判据**：OBJ 只有 ~7 位有效数字，两侧差 5e-8 时就可能因 1e-6 量化的**半值边界**翻掉（实测 `Fences` 逐点一致、哈希不同）。与 `已知的坑.md`「`1e-4` 量化在半值边界会破向两边」同族。底表里只保留原版那一侧的抽样哈希当指纹。
6. **工程缺件情况（都不是缺陷）**：`Rubble1` 在 `Models/` 里没有 OBJ、只有 `ArenaOriginalPrefabs/battlearena2/Mesh/Rubble1.asset`（与判据 §1.6「只当 MeshCollider、走兜底 + LogWarning」一致）；`BoosterPack` 只有 `CardPresentation/Resources/Art/boosterpack/BoosterPack.obj`。
7. **`WarpforgeVFX/Meshes/` 亲数 = 169 个 `.asset`**（`EffectExporter.cs:4610` 注释里写的「`Meshes/` 全部 `.asset` = 250」**已过期**，别照抄）。
8. 清单 3 条 `CandleFlame_big/mid/small` **不在本批**（它们顶点内嵌、`流式 = 0`，且原版 0 个三角形）。

## ⑤ 没查清的部分

- **只比 ch0 位置**；法线 / UV / 顶点色 / 索引 **没比**（法线是 Float16，要另写一档）。施工单 R2-01 只要求顶点坐标。
- **「工程件被用上了吗」没验** —— 有没有被 prefab / manifest 引用，是 R2-04 / R2-06 的活。

- 「`.asset` 偏差 0.0」说明工程那份与 bundle 原件**逐 float32 相同**；但本代理**没有**去核 `EffectExporter.DeepCopyMesh` 的索引/子网格重建（那是 R2-03 的 `simple` 判定，需 Unity 批处理）。
