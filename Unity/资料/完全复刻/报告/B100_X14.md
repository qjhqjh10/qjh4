  `Texture3D_-5601361985474094491.json` → `vectorfield, 64×64×64, readable`。
- AssetRipper 导出的 PNG 是**展平**的：`SDF_Test.png` = **31×1984**（=31×(31×64)）、`vectorfield.png` = **64×4096**（=64×(64×64)）。
- 它给的 `.meta` 是 `textureShape: 8`、`textureType: 0`、`textureCompression: 2` —— **`textureShape: 8` 不是 3D**
  （Unity 的 `TextureImporterShape`：`2D=1 / Cube=2 / 3D=4 / 2DArray=6 / CubeArray=8`）。
  ⇒ 直接拷进去只会得到一张 **31×1984 的 2D 贴图**，尺寸和维度都错。

**两条可行补法（都不在本次施工范围内，列出来供切块）**
1. **编辑器侧重建 Texture3D 资产**：读展平 PNG → 按 `height/depth` 切 64 层 → `new Texture3D(31,31,64,…)` →
   `AssetDatabase.CreateAsset` 成 `.asset`（原版 `m_IsReadable=True` ⇒ 数据可读，没问题）。
   ⚠️ **切片方向（z 递增是自上而下还是自下而上）静态判不出来，必须摆一次图看 SDF 有没有翻**。
2. **运行时从原包取**：工程已有这条路的先例 —— `WarpforgeVFX/Runtime/WarpforgeShaderLoader.cs` 从
   `StreamingAssets/WarpforgeVFX/*.bundle` 运行时取原件（文件头写着「Unity 拒绝把 bundle 里的资产序列化成工程资产」）。
   Texture3D 是同样性质的资产，**可以照这条路抽一张小包**。
