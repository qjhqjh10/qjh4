但原版那条抖动**不 await**：`_UnitDeath_d__446__MoveNext.c:114` 的 `DOShakePosition` 后面紧接着就是
`:122` 的 `WaitForSeconds(gVars + 0x34)`（= 0.5）⇒ 抖动与那 0.5 s **同帧起算**、总寿命与档位无关。

**判据链（`.c` 逐句）**：
- `:100-109` 抖动时长分档（督军 `gVars+0x34` = 0.5 · 小兵 `+0x38` = 0.2），`:114` 调用、**不 yield**；
- `:117-122` `WaitForSeconds(gVars + 0x34)` = **0.5**（**不分档**）；
- `:374-379` 再 `WaitForSeconds(gVars + 0x8c)` = **0.2**；
- ⇒ 总寿命 = **0.5 + 0.2 = 0.7 s**，两档相同。

**同文件内的三处互证**（改前只有这一句与它们矛盾）：
- `DeathBeatsOf`（`:2414-2421`）：`ShakeEnd = DeathDissolve(isWarlord)`、`BodyAt = DeathHoldBeforeFx (0.5)`、`CemeteryAt = 0.5 + 0.2`；

- `EventTiming.cs:653-669`：`EvtKind.Death` 的占时 `return CardFeel.DeathTotal(false)`，注释写明「参数（督军与否）现在**不影响总寿命**（两档都是 0.7，只影响抖动长度）」。
