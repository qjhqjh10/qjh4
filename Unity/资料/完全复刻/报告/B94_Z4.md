### 2. 为什么载荷要**多一格** `practiceCountAtStart`
本仓的清位发生在**回灌**里（`IngestPracticeResults` → `ApplyPracticeOutcome` → `OnPracticeMatchFinished`），
而回灌游标 `_consumedPracticeMatches` **不落盘** ⇒ **每次重启都会把 `BattleLogData` 里全部练习场次重放一遍**。
只存布尔的话：重启 → 读回 true → 紧接着回灌第一场 → 清位 + 写盘 false ⇒ **续局提示永远判不到**（本功能等于没做）。
⇒ 同存「**开局那一拍对局记录里已有几场练习**」，读回时：
- 现在**更多** ⇒ 那场**已经打完**（= 原版服务器回包里清位）⇒ 按 `false` 起；
- **相等** ⇒ 一场新的都没记过 ⇒ 那场**还在打** ⇒ 按 `true` 起（交给 `InitializePracticeForMenuStart` 判负 + 提示）。

同理，`_practiceMatchStartedFromDiskOngoing` 挡住「回灌里那些**更旧**的场次」把刚读回的 true 清掉
（那些场次必然早于这个未收尾的局 —— 否则上面的判别已经把它判成「已打完」了）。

### 3. 为什么不落胜/负/平计数器
那三个数是**从 `BattleLogData` 回灌**出来的（`ApplyPracticeOutcome`），而游标不落盘 ⇒ 落计数器 = **重启后重数一遍**。

### 4. 账 583 仍判 B 的理由
- ①（`matchStarted` 不落盘）**本轮闭合**。
- ② 批处理里 `WindowsManager.Instance == null` ⇒ 提示只记日志 —— **批处理现象**，真机不影响。
