## 五、顺手发现

### 5·1 🔴 **`SwarmVFXController.ToggleBody3D(false)` 的等价物落在了「错误的那张卡」上**（真缺陷；`BattleDriver.cs` 属 W10）

**证据链（三源 + 调用链，全部现读）**
1. `decomp_full/CardScript__ExecuteSwarm.c:39-80`：`Instantiate(trait 0x28a 的 CustomObject, **this.transform.position/rotation**)` → 复制 `this.localScale` → `GetComponent<SwarmVFXController>()`（`DAT_1842cce30`）→ 虚槽 `0x178`（= `Initialize`）传 **`param_1`（= `this`）** 与闭包。
2. `decomp_full/CardScript.__c__DisplayClass401_0___ExecuteSwarm_b__0.c:23-55`（闭包，三格捕获 `+0x10/+0x18/+0x20`）：
   `+0x10` 提供 `CurrentMeleeAttack / CurrentRangeAttack`（被读的那张）、并 `BattleManager__DestroyUnitSilent(+0x10)`；
   `+0x18` 收 `CardScript__AddEffect(...)`（合并后的数值）+ `ActivateTraitParticlesFromCode(0x28a)`（虫群图标）+ `BroadcastUnitSwarm(…, +0x18)`。
   ⇒ **`+0x10` = 被并掉那张 · `+0x18` = 存活那张**；而 `Initialize` 的 `card` = `this` = **被并掉那张**。
3. ⇒ 原版 `card.CardUI.ToggleBody3D(false)` 藏的是**被并掉那张**的 3D 体（它随后被 `DestroyUnitSilent`，所以**永远不需要复原**）。
4. 我们这边：`BattleDriver.cs:24812 v.SetBody3DVisible(false)`，而 `v = ViewAt(e.Player, e.Slot)`，`e` 来自 `RuleCore.cs:4702` `FireTriggerAlways(ctx, host, …, p, hostSlot, …)` ⇒ **`v` = 存活那张**。
   （同一处注释里已自记「偏离 ① —— 原版挂在被并掉那张」，**3D 体这一跳继承了同一个偏离却没意识到**。）

**后果**：3D 棋盘档下，**合并后存活的小兵会永久丢掉 3D 卡体**（只剩 2D 卡面），直到下一次 `CardView.SetFace(Board)` 重刷（`CardView.cs:2761 Show(_body3D, _faceMode == CardFace.Board)`）—— 若没有下一次形态变更就一直不带体。
**自检为什么没抓到**：`Editor/BattleScene.cs:43334` 断完 `!vSwarm.Body3DVisible` 之后立刻 `vSwarm.SetBody3DVisible(bodyWasSwarm)` **还原**，产品态从不复读。
**建议**（W10 判）：① 首选**删掉**那一句（被并掉那张的体由阵亡/移除链自己关）；② 或退一步：藏 **被并掉那张**的视图（需表现层能拿到它）。⛔ 别「藏完再复原」——那与原版语义不同（原版那张卡已经没了）。

### 5·2 🔴 **原版「合并结果」是在虫群 VFX 播完之后才落账的，我们提前了 ≈1.2 s**（账 404 的 `onFinish` 为什么「没有对应物」）
