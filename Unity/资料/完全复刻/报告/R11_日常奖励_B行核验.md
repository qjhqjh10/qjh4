## ④ 顺手发现（只报不改）

1. **账的「还差」列有多条已过期**（现读均已实现）：`ChallengeLogMgr.LogTriggerAbility` 的 20/240/630 排除（`BattleLogData.cs:521-527` 已在）、`LiveOpsHandler.QueueEventPopup` 的「去重 + 队列」（`:338` / `:346` 已在）、`ScheduleEventPopups` 的「主菜单排期」（`:289-313` 已在）、`LiveOpsEventData.IsActive` 的「缺 includePlanned/OnPreview」（`LiveOpsEvent.cs:269-278` 逐句已在）。**建议下次核账先看这一批**，否则会反复「查同一件事」。
2. **`LocalLiveOpsHandler.SelectInTable` 自认的差异没有对应账行**：挑「当前活动」用的是 `IsInPeriod`（`start ≤ now < end`），**原版是 `GetState` 六档 + `EventFilter`** ⇒ **`Finished`/`Expired` 的边界不同**（原版 `LiveOpsEventData.IsActive` 连 `Finished` 都算 true）。本批把 `LiveOpsEventData.IsActive` 判成 A（方法本身照抄），但**选择口走的不是它** ⇒ 建议单独立一条账。
3. **挑战/任务内容确实只能自建**：`assets_full` 90 个 bundle 全量搜，**0 个 `ChallengeList` / `MissionChallenge` / `ChallengeMilestone` / `MissionsConfig` 资产**（只有 MonoScript 类定义）。建议把这条写成常识，免得下个会话再去搜一遍。

6. **`ChallengeList.GetID` / `GetAssets` 判 A 是「可见行为等价」**，不是「结构等价」：原版有 `ChallengeList` SO + `LoadableReference<MissionChallenge>` 两层，我们只有一张硬编码任务表（`DailyData.cs:65/117`）。若以后要做「按挑战清单分流」，这层要重建。
