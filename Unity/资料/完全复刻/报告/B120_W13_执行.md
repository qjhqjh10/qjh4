## 2 · 调用链结论（消费方要的是「格」，不是「卡」）

```
Update / TickBoardHover / 等目标（3 个生产调用点）
        └─ HitSlot(Dictionary<int,CardView> views, Vector3 world)      :33318   ← 返回**格号**（−1 = 没命中）
             └─ [3D 档] TryHitSlotByBoardRay(views, world, out slot)    :41132   ← 原版真生效支的实体
                  ├─ cam.WorldToScreenPoint(world)                      （原版直接吃 TouchPosition）
                  ├─ boardCam.ScreenPointToRay(screen)                  ✔ 同原版
                  ├─ Physics.RaycastNonAlloc(ray, _boardRayHits,
                  │        200f, 1 << ArenaLayer, UseGlobal)            ✔ 距离/触发档同原版；层见 §3
                  ├─ 扫缓冲：**第一条解析得出 CardView 的** → SlotOfView  ✔ 原版 `hits[0]` 的等价物
                  └─ 一条卡都没有 ⇒ return false ⇒ HitSlot 直接答 −1      ✔ 原版 `iVar7 < 1 ⇒ return 0`
             └─ [2D 烘图兜底档 only] 逐卡 CardHit 投影 + 取 z 最小        :33349   （见 §4）
```

**判语义的结论**：消费方（`MyUnits` / `FoeUnits` 那一册）要的是**格号**，原版要的是 `CardScript`。
⇒ **保留外层签名 `HitSlot(views, world)` 返回格号**，只把**内层命中判定**换成原版射线链（卡 → `SlotOfView` → 格）。
⛔ 没有把 API 换成「返回 `CardView`」—— 那会让 10 处调用点全部改签名（Q04 明确禁止）。

## 3 · 层号结论（🔶 **无法一比一**，此处唯一的设计差）

| | 原版 | 本仓 |
|---|---|---|
| 层名 | `BoardElements` | **不存在**（`LayerMask.NameToLayer("BoardElements")` 运行时 = **−1**） |
| 层整数 | **10** | 落到既有的 `ArenaSlots.ArenaLayer` = **8** |
| 该层上有什么 | **只有卡**（`CardPrefab/Board Elements/3DBody/Card 3D` 那颗 `BoxCollider`） | 卡 **+ arena prefab 的地面/背景点击碰撞体**（`battlearena1.prefab` 现读 **20 颗**：14 `BoxCollider` + 6 `MeshCollider`，全是 `TapParticleController` 的 tap 宿主；prefab 里 120/121 个 GameObject 都是 8 层） |

- `ProjectSettings/TagManager.asset` 现读：`0 Default · 1 TransparentFX · 2 Ignore Raycast · 4 Water · 5 UI · 30 WarpforgeIso`，
  **3～29 全空** ⇒ 没有 `BoardElements`。
- **为什么不能字面 `hits[0]`**：原版层 10 上只有卡，所以第 0 条必然是卡；我们的 8 层上混着地面/背景件
  ⇒ 字面取第 0 条会在「地面挡在卡前面」时**静默点不中**（不是「照抄原版」，是照抄了一个我们层结构里不成立的推论）。
  ⇒ 取「缓冲里**第一条解析得出 `CardView` 的**」= 原版 `hits[0]` 在「层上只有卡」这个前提下的等价物。
  ⛔ **不是「取最近」** —— 原版 `RaycastNonAlloc` 不排序，我们不引入 `distance` 比较。
- **要一比一得多大代价**（本轮没做，建议另开账）：新建 `BoardElements` 层 + 把卡的 `3DBody` 迁过去 + 核
  两台相机的 `cullingMask` + 165 个 tap 宿主的掩码（`TapParticleController.CollisionMask` 现在就是靠 bit8 工作的）。
  ⚠️ 这会连带 D 域层掩码那条结构性根因，**不该在一条 Q04 里顺手做**。
- 落点：`BattleDriver.cs:41422` `const int BoardTargetRayLayerMask = 1 << ArenaSlots.ArenaLayer;`（含完整 🔶 说明）。

## 5 · 行为变化（会被人看见的部分）

1. **点场上卡**：仍能选中（射线打 `3DBody` 的 `BoxCollider`）。
2. **点空白（地面）**：3D 档**一律 −1**。以前若投影判据把某张卡的外接矩形算到该点，会误选中；现在不会。
   ⇒ 这是**原版行为**（`.c:250-252`）。
3. **重叠的两张卡**：从「最近的那张」变成「物理缓冲里的第一张」。⚠️ `RaycastNonAlloc` 的序**不是**距离序
   ⇒ 理论上可能选到稍远那张。这是**照抄原版**（原版也这么选）。
4. **`use3DBoard == false`（退回烘图那一档）**：`HitSlot` 仍走老的投影判据 —— 原版那条路（2D 支）是**死支**
   （`Physics2D` 距离 −1 ⇒ 恒 0 命中），本仓这一档是**我们自己的兜底渲染模式**、原版没有对应活支 ⇒ 保留并标 🔶。

**下游 null 容忍（任务第 3 项要求确认）**：`HitSlot` 返回 `int`，`-1` = 没命中。逐处现读调用点，**全部按 `>= 0` / `< 0` / `!= -1` 判**，
没有一个把返回值当引用用：

| 调用点 | 判法 |
|---|---|
| `:8271-8272`（按下选单位） | `int mine = HitSlot(...)` 后比 `>= 0` |
| `:8655-8656` / `:18605-18606`（点板是否命中） | `if (HitSlot(...) >= 0) return true;` |
| `:13629` / `:13673` / `:13700`（自检口 `HitUnitSlotForTest` / `HitSlotForTest` / `HitSlotHitCountForTest`） | 原样透传，断言侧比 `>= 0` |
| `:15111` / `:15115` / `:15598` / `:15631` | `pick` / `t` 后比 `>= 0` |
| `:34416-34418`（等目标） | `if (hs < 0) { ... }` |

⇒ **拖到空白处不会 NRE**（值类型 + 逐处负值判）。
