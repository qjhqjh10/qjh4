## 二 · #40–#43：报告的建议改法不够，改的是别的根因（反证 + 新判据）

报告给的动作是「夹具显式给 `RectTransform.sizeDelta` 宽高 + `ForceMeshUpdate()` 之后再量」。
**现读代码 + 21:05 日志证据表明那修不好 D-0b**，理由如下（三段都可复核）：

1. **D-0b 的实得 300.0001 只有一种解释**：`Label.AlignLeftOn` 里 `HasMeasuredWidth()` 返回了 true
   ⇒ `_measured == true` 且 `0 < _tmpW <= 量纲上限` ⇒ 它走了 `PlaceLeftNow(300)`，
   落点 = `300 + WorldW * 0.5`，而 `WorldW` 恰是 `RefreshBounds` 写的下限 `1e-4` ⇒ **300.00005**（打印 300.0001）。
2. **为什么未激活也会「量到」**：`Label.SetTextTmp`（`Battle/Label.cs:1606-1607`）在**建标签时**就调了
   `RefreshBounds()`；而编辑模式下 `AddComponent` 不跑 `Awake`（CLAUDE.md 已知坑）⇒ TMP 的 `m_textInfo` 是 **null**
   ⇒ `TMP_Text.textBounds`（`Library/PackageCache/com.unity.ugui@…/Runtime/TMP/TMP_Text.cs:1354-1363`）返回 **`new Bounds()`**
   （**不是哨兵**）⇒ `Label.UsableBounds` 接受 (0,0) ⇒ `_measured = true`、`_tmpW = 1e-4`。
   ⇒ 「没量到」被当成了「量到 0」，`_pendAlignX` 那条待办**根本不产生**。
3. **所以夹具要造的是「TMP 已 awake、但还没排版」那一档**：`GetTextBounds`（`TMP_Text.cs:4864-4889`）在
   `characterCount == 0` 时给 `min = k_LargePositive`、`max = k_LargeNegative` ⇒ 尺寸是天文数字 ⇒ `UsableBounds` 拒绝
   ⇒ 才是真机上「未激活 TMP」的那个状态。⇒ 夹具补 `SendMessage("Awake")`，不是补 `sizeDelta`。

另外两条补丁同样是「批处理 ≠ 播放模式」的已知差异：

- `root.SetActive(true)` **不会**派 `OnEnable`（同 `Editor/B140_WC_Assert.cs:239-241` 的现成做法）⇒ 必须 `SendMessage("OnEnable")`，否则「激活时兑现」这条路一次都跑不到；
- 第二颗**活**标签：编辑模式没有帧循环，TMP 自己的 `OnPreRenderObject` 不跑 ⇒ 显式 `TmpFont.GenerateLayout(tmp)` 排一版再对齐。

⚠️ **D-1 原来那条「✓」是退化绿**（`WorldW = 0` ⇒ `left = x − 0 = 300` 恒等），改完之后 D-1 才真的在测东西 ——
所以这四条**必须**在下一次 `BattleScene.Run` 里重新看（⛔ 别拿本文件当「已修好」）。

## 六 · 顺手发现（⛔ 我没改，交调度台分流）

1. 🔴 **`Battle/Label.cs` 有一个生产侧空洞（建议立账）**：`RefreshBounds` 的守卫只挡哨兵/NaN/超量纲，
   **不挡 (0,0)**；而 `TMP_Text.textBounds` 在 `m_textInfo == null`（= 编辑模式下 `AddComponent` 没跑 `Awake`，
   或任何「TMP 还没 awake」的构建路径）时返回 **`new Bounds()`** ⇒ `Label` 把「没量到」记成「量到 1e-4」，
   `_measured = true`、`_pendAlignX` 那条待办**永远不产生**。
   判据 = `TMP_Text.cs:1354-1363` + `Battle/Label.cs:1634-1641 / 1665-1667 / 1762 / 1980-1994`。
   建议修法（**不在我的白名单**，需派给 `Battle/Label.cs` 的写手）：`UsableBounds` 增加
   「`Mathf.Abs(size.x) < 1e-3f && Mathf.Abs(size.y) < 1e-3f` ⇒ false」，或在 `RefreshBounds` 里对
   `w <= 1e-3f && h <= 1e-3f` 直接早退（空文本那一档 `HasMeasuredWidth` 本来就已经挡掉了）。
   ⚠️ 这条只影响「未 awake 的 TMP」，真机播放模式一般碰不到；但批处理自检与任何「先量后显示」的路会碰到。

2. `Editor/B141_W70_Assert.cs` 的 A9b（`DraftModeWindow` 无 `40k_UI_bt_play`）**本来就是绿的** ——
   该文件里连注释都没有这个串（现核 0 命中）；A10 才是真的踩了注释。

3. `Editor/B148_W3_Assert.cs` 的 D-1 在改前是**退化绿**（`WorldW = 0` ⇒ `x − 0 = 300`）。
   改后它才依赖真测量 ⇒ 下一次 `BattleScene.Run` 要**单独看这四条**（D-0b / D-0c / D-1 / D-2 / D-3）。
