## 三、口径偏离（**4 条，都是刻意做的，请调度台核**）

**a) C1 ③「逐行发带 `abilityIndex` 的 `EvtKind.Trigger`」—— ⛔ 没做。**
   理由：`BattleContext.Emit` 里 `if (e.Kind == EvtKind.Trigger) CountTriggerForAchievements(...)`（`BattleContext.cs:1868-1890`）
   ⇒ 多派一条 = **成就触发器重复计数**（`Ach_5/8/9/…`）。要做必须先给成就计数开一个「不计数」的口，那是另一件活。

**b) C1 ④「把 `FireTriggerRowsByChosenAbility` 改成转调」—— ⛔ 没做。**
   理由：那条路（`EffectResolver.cs:21385`）只在「正文 op 为空」时跑，而它的 `ca 320` 覆盖 **9 张单位卡**
   （`GSC14/AM8/AM21/ASH81/SAU11/GOF59/GSC17/TL3/UM64` 的非 0 trigger：10/300/301/455/560/580/120/145）。
   新派发器按 B5 **不认**这些（它们不是 `ThisCardPlayed`）⇒ 转调会让这 9 张**停止派 320**（真回归）。
   ⇒ 改成「分类判据共用」：`DispatchCardAbilityRows` 对 `BodyOp / Unknown` 直接复用 `TriggerRowKindOf` 的四档，不另写第二套语义。

**c) B8 三态：`null` ⇒ **放行 + 出声**（不是 R9 结论的「跳过」）。**
   实测理由：`GOF104` 的 380 行（= 本件最小验证格）其 ability 级 `actingCardCriteria` 是 `ta=20 self`，
   战术卡没有 `UnitState`；若按「`null` ⇒ 跳过」，**GOF104 的 380 永远不派** ⇒ D2 结构上不可能绿。
   而原版这一格的真值 = **真**（`actingCard == thisCard`）⇒ 跳过比放行更不忠实。
   代码先例：`CostWhenAbilityCriteriaAllows` / `AbilityFamilyTargetAllows` 都是「判不了 ⇒ 放行 + 出声」。
   ⇒ 落地为 `false ⇒ 跳过 + 出声` / `null ⇒ 放行 + 出声`（三态都在 H 段用合成卡钉住）。
   ⚠️ 终态仍是「改成卡级三件套、删 `UnitState` 依赖」（R9 §① 那条待办照旧成立）。

**d) 320 的执行体 = 只发 `FollowUpResolution` 表现拍，⛔ 不接 `410` 正文那一半。**
   理由：改前 `EffectResolver.cs:2917` 那一段**也只发表现事件**；把 `410` 正文一起接进来会改结算结果
   （`play check` 指纹会变）。那是另一件活（判据已在 `RunFollowAfterResolutionRow`）。

另两条小口径：`ta` 取自 `abilityTargets` 列（`triggerAbilityIndices[].ta` 生成器未写）；`380` 的 `ta=140/150`
目标集用的是 `new EffectOp { SubjectTargetsAffected = ta }`（与 `RunSetReferenceCardRow` **逐字同一构造**，
`AbilityIndex = -1` ⇒ 不做行级 criteria 过滤 = R6 §4 的已知近似）。
