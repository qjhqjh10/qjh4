## 一、C 组（6 条：#21–26）—— ✅ 已修

### 改了什么

`RuleEngine/Core/RuleCore.cs` · `FireTriggerAt` 入队那一跳（原 `:12787-12792`，**同一物理行内改**）

- 改前：`… abilityTrigger: _kwTriggerName, abilityTarget: chosen, abilityHostCard: _carrierCard);`

### 为什么这样改（判据）

- **原版**：`RawCardScript__TriggerAbilities.c:207` 那条循环是**逐 ability** 调 `CardAbility.CanTriggerAbility`（内含 `actingCardCriteria(+0x28)` → `targetCriteria(+0x30)` → `boardCriteria(+0x38)` 一条 `&&` 链）⇒ 闸是**按 ability 行**判的。
- **我们这侧的两道闸原本是按能力种类族名（那条是近似）**：`AbilityFamilyGateOpsForTrigger`（`X6` 口径乙）只在「这张卡的这条 trigger **定位不唯一**」时启用（`UniqueAbilityIndexForTrigger == -1 ∧ ambiguous`），它**逐 op** 剔正文。
- `EnqueueAbility` 那道 ability 级 `targetCriteria` 闸对「定位不唯一」的处置是 **整条不触发**（⛔ 不猜第几条，判据见 `ActionPump.cs:443` 那段）。
- ⇒ **两道一起判 = 整份正文被掐死**。日志实证（`b100e_ruleengine.log` §`X6b`）：`[ActionQueue] **不触发**「Vex Machinator·rally」… **ability 定位不唯一**：这张卡有 2 条 `trigger = 0`（ThisCardPlayed）的 ability` —— 而同一时刻族闸的 `skip` 计数**是对的**（= X5 报告 #21 那句「族闸计数却对」的成因）。
- `B99_E9` 的注释本来就写着「**唯一定位得到的卡**走 `EnqueueAbility` 那条闸 ⇒ 这里故意不启用」—— 但那一笔把 `abilityTrigger` **无条件**传了下去 ⇒ 变成对所有卡都判。本笔就是把那一句补成**二选一**。

### 灭自证

- `B100F17T1FamilyGateExclusive`：
  · 正例 —— 池内 `BL33`/`DA38`/`ASH30`/`DA33`/`SOR31` 的 `ThisCardPlayed` 全部 `定位不唯一` ⇒ 谓词为真（🧨 谓词改回恒假 ⇒ 红）；

- `B97_ER` ③ 与 `EngineE2` ③ 直接调 `EnqueueAbility`（不经 `FireTriggerAt`）⇒ 与本笔无关。

## 四、D 组（5 条：#31–35）—— ⛔ **产品侧不改**：夹具用错了伤害入口（α/δ）

### 查实过程（回源，不是猜）

1. 断言（`CardPresentation/Editor/B97W28_Assert.cs:203-208` 与 `:257-264`）用的是
   `RuleCore.ApplyDamage(ctx, f, 5, "自检")`。
2. `RuleCore.ApplyDamage`（`RuleCore.cs:8508`）**只做伤害**，doc 第一句就是：
   「⚠️ 会**造成伤害**的地方请用 `Hurt`，别直接调这个 —— **它少了「受伤触发」和「离场结算」两步，漏掉就会出现「血是负的但人还在场上」**」（`RuleCore.cs:8499-8500`）。
   实测核对：`ApplyDamageCore`（`:8519-9012`）整段**没有** `CleanupDeaths` / `RemoveIfDead` / `AddPendingDeath` 调用（逐行扫过）；真正的伤害入口是 `Hurt`（`:9118` `ApplyDamage` → `:9247` `RemoveIfDead` → `CleanupDeaths`）。
3. ⇒ 夹具把血打到 −4 之后**单位仍留在棋盘上**，`CleanupDeaths` 根本不会跑 ⇒
   `EvtKind.Death` 不发（D1/D3）、观察者 90 那一族不广播（C1）—— 与实测读数（`0` / `atk+0`）完全吻合，而 `C2`（期望「不响」）**空转绿**。
4. 断言里那句前提「炮灰真的死了」用的是 `!f.IsAlive` —— 它只是 `Health <= 0`，**不是**「已离场」（这正是本工程记过的坑：前提写成弱判据 ⇒ 后面全空转）。

### 正确的修法（**不在本代理白名单内**）

`B97W28_Assert.cs` 的两处 `RuleCore.ApplyDamage(ctx, f, 5, "自检")` / `(ctx2, f2, 5, "自检")`
⇒ 换成 `RuleCore.HurtWithSourceForTest(ctx, f, 5, "自检")`（`RuleCore.cs:9230` 的公开自检门，`= Hurt` = 完整伤害管线）。
（`更稳`：前提那两条 `CheckTrue(!f.IsAlive, …)` 可加一句「棋盘上找不到它」—— 但**不是必须**，`Hurt` 之后 `IsAlive` 与离场同步。）

### 为什么我不改产品

把 `ApplyDamage` 改成会处理死亡 = 改掉一个**被文档明确定义为「不含离场结算」**的原语，并且会连带改 `:9807`（猎杀标记那一发）的时序与 `Hurt` 的形态 —— 那是**造一个原版没有的第二条伤害管线**，且 `play check` 指纹大概率会变。**这属于「不该做的修复」**，故停下报。
