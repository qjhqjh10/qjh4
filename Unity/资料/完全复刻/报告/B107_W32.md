## 一、两件结论

### 1. `A5[0..4]s 相对倍率` 5 条红 → **α 断言错，已改期望式**

- 原式 `cScl / ss.keys[0].v[0]` 的分母是**本槽曲线的首键（t=0）缩放 = 210**；
  实现 `CardFan.Wpx(i)/FrontWpx ≡ _scl[i]/_scl[0]`，分母是**槽 0 的末键（t=length）缩放 = 250**。
  两者恒差 `250/210 = 1.190476` ⇒ 五条同倍数偏大。
- 改法：A5 循环前从**原版数据**取槽 0 `m_LocalScale` 的**末键**：`s0End = 末键(槽 0) = 250`；
  `:171` 期望式改成 `cScl / s0End`，文案改成「末端缩放(i) / 末端缩放(槽 0)」。
- **断言强度没降**：期望值仍**只来自原版 `misc_clips.json` 的末键**，⛔ 不回读 `CardFan`。
- 独立复算（`python -I` 直接读 `Resources/misc_clips.json`，不经过任何我们的常量）：

  | 槽 | 首键 t0 | 末键 t=0.31666666 | 末键/250（= 新期望） |
  |---|---|---|---|
  | 0 | 210 | 250.0 | 1.000 |
  | 1 | 210 | 232.95370 | 0.931815 |
  | 2 | 210 | 221.59259 | 0.886370 |
  | 3 | 210 | 204.54630 | 0.818185 |
  | 4 | 210 | 181.81482 | 0.727259 |

  与 D7 记的日志实得（1.000 / 0.932 / 0.886 / 0.818 / 0.727）逐位吻合 ⇒ 分母选错是唯一差异。

### 2. `wf_prefabs_extra.bundle 能被 LoadFromFile 加载` 1 条红 + 4 条被静默跳过 → **δ 夹具前提，已改「认领已加载包」**

- 真因（D7 已取证）：本会话新接线的 `B107R3d` 在宿主里先经 `WarpforgeAnimatorBridge` 加载
  `wf_prefabs_extra.bundle` 并**全程持有**句柄；之后 `B103W7b` 对同一文件再 `LoadFromFile` ⇒ Unity 返回 null。
- 改法（照 D7 可粘贴代码）：
  1. `Pack` 加 `Probe` 字段（四只包的**容器键**）：
     prefabs=`Vanguard Frame Animated VAT` · menus=`Booster Pack Open Window` ·
     battleshared=`TurnTimerTickPulse` · mainmenu=`Wildcard_Use_Button 1 Common`。
  2. `LoadFromFile` 返回 null ⇒ `FindLoadedWith(probe)` 从 `AssetBundle.GetAllLoadedAssetBundles()` **认领**那只包，
     并 `Debug.Log` 出声（包名一起打出来）；认领到的句柄 `owned = false`。
  3. 循环末尾 `if (owned) b.Unload(false);` —— **借来的句柄不卸**（否则会把 bridge 正在用的包抽走）。
  4. 类尾新增 `FindLoadedWith`：判据照抄生产侧 `WarpforgeAnimatorBridge.HasAsset`
     （① `Contains(裸名)` ② `GetAllAssetNames()` 按小写比，也认 `…/<小写名>` 与 `…/<小写名>.prefab` 尾段）。
- **认领失败仍然红 + 出声，而且不静默**：原写法 `if (b == null) continue;` 会把下游 4 条检查**悄悄跳过**（日志里只剩 1 条红）。
  现在 null 分支里**逐条记 4 条失败**（渲染器数 / 材质槽数 / 空材质槽 / shader 坏，标签带「包不可用 ⇒ 未执行」）
  并打一行 🔴 说明认领不到哪个容器键 ⇒ 失败时日志里能看出「一共 5 条不该绿的」。
- ⛔ 没用两种偷懒修法：null 判绿、只挪执行顺序（D7 已论证会复发/掩盖真坏）。
