## 二、任务 1 详述（判据是这一轮**新查**的，W13 只查到「社交窗那块恒 Global」）

### 2.1 原版到底传什么频道

`ChatPreview.OpenChat()`（`out_cpp2il_dev_ilspy/ChatPreview.cs:99-131`，`:314-338` 是同一段在 `OnComplete` 回调里的副本）：

```csharp
ChatPanel.ChatPanelContext chatPanelContext = new ChatPanel.ChatPanelContext(ChatRoom.Global);
chatPanelContext.startingChannel = channelType;          // ← :124
GameWindow gameWindow = instance.OpenWindow(chatWindow, chatPanelContext, closeAll: false, options);
```

`channelType` 是 `ChatPreview` 的**序列化字段**（`:25` `private ChatRoom channelType;`），
所以「开哪个频道」由**那一个 ChatPreview 实例**决定，不是全局常量。

### 2.2 两个实例的值（prefab / 场景 YAML 实读，⛔ 不是按名字猜）

```bash
grep -rn "channelType:" d:/2/tools/assetripper_out/ExportedProject/Assets/
# Assets/Social Submenu Variant.prefab:39623:  channelType: 1     ← 社交窗那一块
# Assets/ChatPreview.prefab:172:             channelType: 0     ← 预制体默认（主菜单用的那份）
# Assets/Data/Scenes/MainMenu Warpforge.unity:74539: channelType: 0
```

社交窗那一块的父链（本代理按 `m_Children`/`m_Father` 现解，不是按名字）：

```
ChatPreview / AllianceMemberVariant / Alliances Tab / Tabs / Content Area / Social Submenu Variant
```

另外核过它确实是**同一颗控件**：`sizeDelta = 400×60` · `anchoredPosition = (−40.70, −68.93)`（锚右上）
= 我们 `AllianceMemberTab.BuildChatPreview` 那条 `1479.80,109.80→1879.80,169.80`（1920 屏右上角 −40.2）。
⇒ **社交窗 = `ChatRoom.Alliance`（1）**，主菜单 = `Global`（0）。

### 2.3 落地（`Shell/SocialWindow.cs` 的 `OpenChat()`）

```csharp
string channel = ChatPanel.Channels.Length > 1 ? ChatPanel.Channels[1] : null;   // = "Alliance"
var chat = WindowsManager.OpenByRef(WindowsManager.PrefabRefChat, m =>
{
    var c = ChatPanel.Create(m);
    c.StartingChannel = channel;
    return c;
});
```

🔴 **为什么设在工厂里、而不是「拿到实例之后再设」**（这是这一条唯一的坑）：

- `WindowsManager.OpenByRef` 只在**新建**那一支调工厂（缓存命中且还开着 ⇒ 不调）；
- `ChatPanel.Open()` 只在 `CurrentState == Closed` 那一支跑（`GameWindow.OpenByState`）——
  **两条条件正好对齐**；
- 若写成「先 `OpenByRef`、再 `chat.StartingChannel = …`」，复用**已开着**的那一扇时 `Open()` 不会跑
  ⇒ 那个值会**留到下一次开窗**（`StartingChannel` 是一次性的）⇒ 下次从主菜单开也落到 Alliance（静默错）。
- 反过来也**与原版一致**：原版 `OpenWindow` 命中已开着的窗时，`TryOpen` 那一支**一个字段都不写就 return**
  （`GameWindow.cs:544-550` 注释里的判据），同样**不切页**。

频道名不在这里写第二遍：取 `ChatPanel.Channels[1]`（`ChatPanel.cs:115` 是频道名的唯一真值，
注释里写死「下标 = `ChatRoom` 值」）。

## 三、任务 2 详述（sanitize 钩子）

`Shell/TextInputField.cs`：

- 新增字段 `Func<string, string> _sanitize;`（类内、`_maxLen` 旁边），🔶 已按铁律 18 打标记
  （原版机制是 uGUI 的 `m_OnValueChanged` 事件，本仓没有 ⇒ 用回调形参等价）。
- `Create(…)` 与 `Bind(…)` **各追加一个末位可选形参** `Func<string,string> sanitize = null` ⇒
  现有 6 个调用点（`PromptPopup:458` · `AllianceSearchTab:443/997` · `AllianceMemberTab:1509` ·
  `FriendsTab:593` · `ChatPanel:280`）**一个字节都不用改**。
- `Tick()` 在「收完这一批字符、`Refresh()` 之前」过一遍：

```csharp
if (_sanitize != null)
{
    string sv = _sanitize(_value ?? "");
    if (!string.Equals(sv, _value, StringComparison.Ordinal)) _value = sv ?? "";
}
```

**为什么只挂在 `Tick()`**：原版那一条挂的是「值变了」事件；本类里**只有 `Tick()` 那一段是「用户打字改变值」**
（`SetValue` / `Clear` 是程序化口，`EndEdit(false)` 是丢弃）。`FeedText` 喂的是 `_typed`，最终也走 `Tick()` ⇒ 一并覆盖。

**与 `ChatPanel.Update()` 轮询的关系**：两者**不冲突、可共存**；W13 那条轮询（编辑态每帧比对后 `SetValue` 回去）
**建议保留**（删它会动 `ChatPanel.cs` 行数，且它现在是 `🔶 等价实现`、双保险）。接线后钩子先剥一遍、
