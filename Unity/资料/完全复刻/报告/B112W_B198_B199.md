### 2.2 新增（**追加在类尾 `:6019-6086`**，避免账的行号漂移）

```csharp
const string ArenaTexImportTsv = @"d:/4/Unity/数据/游戏数据/arena_texture_import.tsv";
struct ArenaTexImportRow { public int MipCount; public int ColorSpace; }
static Dictionary<string, ArenaTexImportRow> _arenaTexImport;      // 只缓存「加载成功」那次
static Dictionary<string, ArenaTexImportRow> LoadArenaTexImport();  // 缺表 ⇒ LogError + 返回 null（每次重试）

static void ApplyOriginalImport(TextureImporter ti, string path)
{
    var table = LoadArenaTexImport();
    var name = Path.GetFileNameWithoutExtension(path);
    ArenaTexImportRow row;
    if (table != null && table.TryGetValue(name, out row))
    {
        ti.mipmapEnabled = row.MipCount > 1;   // 原版 m_MipCount（已核 = 满链，Unity 只能开/关）
        ti.sRGBTexture = row.ColorSpace == 1;  // 原版 m_ColorSpace：0 = 线性
        return;
    }
    ti.mipmapEnabled = false;                  // 表外：退回旧口径
    Debug.LogWarning($"[Arena] 旁挂表里没有这张贴图：`{name}`（{path}）⇒ mipmap 退回旧口径 false、sRGB 未动。补表：跑 `工具/gen_arena_texture_import.py`");
}
```

**为什么 `mipmapEnabled = (mipCount > 1)` 就够**：脚本对全库 2,984 张核过，`m_MipCount` 只有两种取值 —— `1` 或
**满链** `floor(log2(max(w,h))) + 1`（`w>0,h>0` 的 2,984 张里「既不是 1 也不是满链」= **0 张**）。
Unity 的 `TextureImporter` 只能表达「开/关 mip」，开 = 自动满链 ⇒ **能精确复现**，不存在「层数对不上」。
（生成器仍会把例外印到 stderr，一旦将来出现中间值会立刻看见。）

**为什么用「文件名主干」当键**：`AssetDatabase.FindAssets` 给回来的是路径，原版贴图名就是文件名主干；
生成器按同一个口径（`os.path.splitext(basename)`）产出，且逐名字核过**同名多包真值一致**（见 §三·3）。

## 七、顺手发现（⛔ 未改，本单不越界）

1. 🔴 ~~**`arenas/<场>/Sprites/` 与 `Textures/LUT/` 完全没人管导入设置**~~ → **2026-11-01 就地订正（`B112W_B201`）**：
   **`Textures/LUT/` 那 7 张一直有人管** —— `EnsureLutImportSettings`（`ArenaBuilder.cs:3550`）是它们**唯一写手**（sRGB / 压缩 / 尺寸 / mip / filter）。
   **真正没人管的是 `arenas/<场>/Sprites/`（18 份）** —— 它不在 `TexDir` 范围内。
   ⚠️ 也正因如此，`B-201` 把 LUT 走「**只核对 + 出声一次 + 不写**」分支：塞进通用循环会与 `EnsureLutImportSettings` 的 `ok` 判据**互相翻写**，还会动到不该动的 `alphaIsTransparency` / `maxTextureSize`。`B-119`（LUT 的 wrapMode）结论**一个字没改**，而且现在有**三方一致**读数（`vfx_texture_mips.tsv` 0/0 · 新表 0/0 · AssetRipper LUT `.meta` wrapU/V: 0）。
   ⇒ **新账候选**：这 25 份是否与原版 `m_ColorSpace / m_MipCount` 一致，没查过。
2. 🔴 **wrap / filter / aniso 也有偏差（本次现读，226 份逐格比 `数据/游戏数据/vfx_texture_mips.tsv`）**：
   `wrapU/wrapV` **36 份**不一致（例 `Battle Arena 1 Floor` 原版 Mirror(2)，我们 Repeat(0)；
   `Battle Arena 1 Background` 原版 Clamp(1)）、`aniso` **5 份**不一致（例 `Battle Arena 1 Floor` 原版 16、我们 1）。
   `filterMode` **0 份**不一致。同一张表里就有真值（列 5..8），`EffectExporter.FixTextureImportSettings` 已经在用了
   —— **`ApplyTextureImportSettings` 没接**。⇒ 新账候选（照原版补 wrapU/wrapV/filterMode/aniso，与 B-198/199 同源同修法）。
3. **普查 §六·3 的天空盒 6 面**（原版 Cubemap `m_ColorSpace: 0`、我们 6 面 `sRGBTexture: 1`）**本单没动**：
   面 PNG 原版没导出成文件，且它们不在 `arenas/*/Textures` 下 ⇒ 属另一条。
4. `ApplyOriginalImport` 的兜底**故意退回旧口径**（`mipmapEnabled = false`）而不是「什么都不设」：
   新贴图 Unity 默认是 `enableMipMap: 1`，什么都不设会让「表外新增的贴图」**静默多出一整套 mip**，
   比退回旧口径更难发现。现读覆盖 226/226，这一支只在「有人新加贴图但没重跑生成器」时才走到，且会出声。
5. `arena_texture_import.tsv` 只覆盖**工程里实际存在的** 116 个名字（不是全库 2,984）。
   新增战场贴图时必须重跑生成器，否则 `--check` 不会报警（它只比已有名字），
   但 **Unity 侧会打 `旁挂表里没有这张贴图`** —— 所以重导后请看一眼日志。
