## 三、原版是不是也这样？（`.c`）

**不是。原版那两件事都是「队列里的动作」，跑在 Slay 记账【之后】。**

1. `D:/2/tools/decomp_full/CardScript__CheckIfDead.c` 残骸支（`SupportMethods__HasToTransformIntoRemnant` 为真、`+0x65 == 0`）：
   `CardScript__TriggerUnitBacklashActions(...)` → **然后** `BattleManager__AddTransformIntoRemnant(...)`。
2. `D:/2/tools/decomp_full/BattleManager__AddTransformIntoRemnant.c:99` → **`BattleManager__AddAutoActionToQueue(...)`** ⇒ 翻面是**排队**的，不是当场做。
3. `D:/2/tools/decomp_full/BattleManager._ResolveTransformIntoRemnant_d__554__MoveNext.c:43 / :45` → `CardScript__ResetToValuesInHand(card, 0)` **然后** `CardScript__TransformIntoRemnant(card, 0)`（后者才置 `+0x65 isRemnant = 1`）—— **这两跳都在那条排队 action 的体内**。
4. Slay 记账的位置：`D:/2/tools/decomp_full/BattleManager._ResolveBacklash_d__451__MoveNext.c:88`（`CardScript__ResolveDeadCard`）/ `:94`（`TriggerUnitDeathActions`，死者的 80/81 从这里发）**在** `:144`（`BattleManagerSupport__BroadcastDeadUnit`）之前；而 Slay 的闸在 `D:/2/tools/decomp_full/CardScript__ResolveDeadCard.c:~232-259`：
   `(*(char*)(local_308 + 0x65 /* isRemnant */) == 0 || cardState == 2) && *(char*)(local_308 + 0x222 /* alreadyTriggeredBacklash */) == 0`，里面那一道「算击杀」还额外要求 `+0x65 == 0`。
   ⇒ 记账那一刻，排队 action **还没跑**，`isRemnant` 仍是 0、血仍是死时的值 ⇒ **原版把「打死一个会变残骸的真单位」算作击杀**（`Slay` 会响），与 `TestStrikeAndSlay` 第 1 支的期望一致。
5. 同理 `TriggerOnMinionDeath` 读猎杀标记（`CardScript__TriggerOnMinionDeath.c:77`）也在同一条 death action 里 ⇒ **早于**重置/翻面 ⇒ 原版 `Amount` 是 2，不是 0。

⇒ **结论：我们两处都是「把原版排队的一步提前成同步」，属于实现偏差，不是照抄原版。**
