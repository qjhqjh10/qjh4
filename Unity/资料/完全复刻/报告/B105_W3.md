## 6. 没查清 + 顺手发现（**本件不改**）

### 没查清

1. **原版别的入口**（收藏窗「加进卡组」、轮抽/战役那类自动组卡）会不会清卡 —— 本件只逐类核了 `DeckEditingWindow` / `DeckEditingPanel` / `CardDeck` / `DeckUtility`。
2. **「0 调用点」的边界** —— 按**符号名**三源 grep + 资源 `m_MethodName` 全 0；**反射 / 字符串拼接的事件表**没穷举 ⇒ 严格说是「找不到调用点」，不是「证明不可能被调」。
3. **原版那条 `LogError` 分支我们没有对应实现** —— `RemoveNoValidArmyCards` 在 `deckHero == null` 或 `cardLibrary == null` 时打 `"Can't check invalid army cards. Missing warlord or library"`（`.c:21-29`）；我们这条走不到（`SetWarlord` 拿不到 hero 就 `return 0`，`CardIds` 恒非 null）⇒ 如实记，**没补**。
4. **中立卡** —— 原版跳过 `IsNeutralArmy`；现读卡池 **13 个阵营、0 张 `Neutral`**（`cards_engine.json` 现数）⇒ 今天无差异。但 `DeckRules.SameFaction("Neutral", x)` = false ⇒ **将来若加入中立卡，`SetWarlord`（自检那条路）会错误清掉它们**。改法 = 补一条中立豁免 + 断言，属另一件。

### 顺手发现

1. 🔴 **`CanAddCore` 的阵营闸门按「督军」比，原版按 `deck.deckArmy` 比** ——
   原版 `CardDeck__CanAddCard.c:86-93`：`!IsNeutralArmy(card.cardArmy) && deck.deckArmy(+0x50) != card.cardArmy && CardCount(countHero:true) > 0` ⇒ 拦。
   **`deckArmy` 在没有督军时并不为空**（`CardDeck.AddCard` 在第一张卡进来时就设成那阵营；`RemoveCard` 只在卡组**空掉**时才归 `Neutral`）⇒ **原版「没有督军、卡组非空」时照样挡异阵营卡**；我们（`DeckEditorState.cs:447-452`）在没有督军时**完全放行**。
   今天玩家 UI **不可达**（无督军时 `WarlordGatedPool` 只列督军，`DeckRuntime.cs:1431-1433`），但是逻辑缺口；要照原版修，得先给 `PlayerDeck` 一个 `deckArmy` 等价物（我们没有这个字段）⇒ 建议单开一件。
2. **我们 `SetWarlord` 顺手清防御卡（`DeckEditorState.cs:505`）= 我方旧有偏离** —— 原版 `RemoveNoValidArmyCards` **只清 `cardLibrary`**（`.c:30-61`），防御卡位 `+0x48` 一个字都不碰；`ValidateDeckCards` 也只遍历 `cardLibrary` ⇒ **原版不校验防御卡阵营**。`Editor/DeckScene.cs:2226` 有一条断言钉着「防御卡也被清」⇒ 本件**不动**（要按原版改，得连那条断言一起改，且它在断言宿主白名单外）。
3. **原版换将时列表会「先摘一行再加一行」，我们是直接替换槽位** —— `DeckEditingPanel.cs:305-357` 在 hero 支先 `RemoveCard(oldHero)` 再 `TryAddCard(newHero)`；我们 `SetWarlord`/`TryAdd` 直接写 `WarlordId`。**语义等价**（异阵营在 `CanAddCard` 阶段就挡了），但**侧栏列表动画不等价**（原版走一次增删）。要逐帧对齐得补这一步。
