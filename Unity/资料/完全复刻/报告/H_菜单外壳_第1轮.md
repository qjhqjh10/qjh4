## ⑥ 顺手发现

1. 🔴 **G 的判据 §五 `SceneInitializer` 有三处与反编译不符**（本轮以反编译为准，判据文件请调度台订正）：
   ① `InitializationPriority` 真名 = **Data / Manager / UI / AfterUI**（G 写 First/Core/UI/Deferred）；
   ② `IInitializableAsync` 的方法是 **`Initialize()` 返回 `IEnumerator`**（G 写 `InitializeAsync()`）；
   ③ `IInitializationComplete` 是 **`void OnInitializationComplete()` 方法**（G 写 `bool IsInitializationComplete` 属性）；另外 `IBaseInitializable` 还带 `InitializationStatus Status {get;set;}`。
2. **G 判据里「组内等 `IInitializationComplete` 完成」的语义要更精确**：反编译里「等」的条件是**组内每件 `IBaseInitializable.Status == Initialized`**；`IInitializationComplete` 只是**事后回调名单**。我们在实现里把 `Error` 也算「已定」（否则一件抛异常就**永远等下去** —— 原版两条语义自相矛盾），已在文件头如实标注为**有意差异**。
3. **「红点靠 alpha 不靠 SetActive」在数据层面也成立**：`UiBadgeNotification.UpdateCount` 对计数文本做 `SetActive(showCounter && count > 0)`，但**红点本身**始终 active、只动 `CanvasGroup.alpha` ⇒ 我们照此（红点 quad 不关、只改 tint α）。
4. **活动线的 `notificationDefinitions` 在场景里是空数组**（`MonoBehaviour_2341/2431`）—— 说明 Home/齿轮两颗红点是**纯占位**；我们原先写死 `BadgeAlpha(false)` 的观感**恰好就是原版**（这次只是把它换成同一套机制，**零可见变化**）。
5. **`ItemDrawer` 的 8 条 C 里有一条原版是空方法**（`ToggleShowInfoOnClick`）—— 落地时**不要**给它补逻辑（补了就是自造）。
6. **`Warning` 一处**：`ShellRuntime.Build` 的拆除循环会把新建的 `SceneInitializer` 子节点在**下一次 Build** 时连根拆掉（它不在 skip 名单里）—— 我们每次重建都会**新建一台**，语义正确（旧台 `OnDestroy` 会把静态钩子置空，但我们的判据是 `if (s_onQueued == 当前实例的委托)` 才置空 ⇒ **不会误伤新台**）。如要更省，可把它加进 skip 名单（未改，避免动清场逻辑）。
