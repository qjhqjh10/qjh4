## §1 `165 PremiumDrawer.GetItemName(PremiumItem)` —— **裁定：`item.LocalizedName`（词条 `MenuShop/PremiumCampaign`）**

### 1·1 结论

```
protected override string GetItemName(PremiumItem item)  =>  return item.LocalizedName;
```
`PremiumItem.LocalizedName` = `LocalizationManager.GetTermTranslation(localizationKey, FixForRTL: true, 0, ignoreRTLnumbers: true, …)`，
而 **13 份 `PremiumItem` SO 的 `localizationKey` 全是 `MenuShop/PremiumCampaign`** ⇒ 原版这一格印的是
**词条 `MenuShop/PremiumCampaign`（EN `Premium Campaign` · ZH「高级战役」）**，**不是** SO 名（`Premium Campaign UM` 那种）。

### 1·2 判据（VA 级 · 不按地址归因）

**甲、入口地址**：`d:/2/tools/il2cpp_out/dump.cs:93118` —— `PremiumDrawer.GetItemName(PremiumItem)` `RVA 0x6E6E80` / `VA 0x1806E6E80` / `Slot 20`
（`PremiumDrawer : ItemDrawer<PremiumItem>`，`dump.cs:93105`）。

**乙、指令流**（`D:/2/Warpforge_tools/py312/python.exe d:/4/Unity/工具/disasm_va.py D:/2/unity_run_ref/GameAssembly.dll 0x1806E6E80 40`；
`ret`/`int3` 为界，本函数 = `0x1806E6E80`–`0x1806E6EAC`）：

```asm
1806E6E80  48 83 ec 28              sub  rsp, 0x28
1806E6E84  4c 8b c2                 mov  r8, rdx              ; r8 = item（IL2CPP：rdi=MethodInfo · rsi=this · rdx=arg1）
1806E6E87  48 85 d2                 test rdx, rdx
1806E6E8A  74 1b                    je   0x1806e6ea7         ; item == null ⇒ 转 FUN_1803F47A0（空引用抛出）
1806E6E8C  48 8b 12                 mov  rdx, [rdx]           ; rdx = item→klass
1806E6E8F  49 8b c8                 mov  rcx, r8              ; rcx = item（被调方的 this）
1806E6E92  48 8b 82 a8 01 00 00     mov  rax, [rdx + 0x1a8]   ; ← 虚表 **slot 7** 的方法指针
1806E6E99  48 8b 92 b0 01 00 00     mov  rdx, [rdx + 0x1b0]   ; ← slot 7 条目的第二字（虚表 16 字节/档）
1806E6EA0  48 83 c4 28              add  rsp, 0x28
1806E6EA4  48 ff e0                 jmp  rax                  ; 尾调 ⇒ **一次虚调用，参数就是 item 自己**
1806E6EA7  e8 f4 d8 d0 ff           call 0x1803f47a0          ; 空引用抛出（原版不 return null）
```

⇒ 体语义 = **`return item.<虚表 slot 7>;`**，既不是直调 getter、也没有任何字符串拼装。

**丙、槽号换算（这才是「是哪一个」的判据）**：虚表基址 `0x138`、每档 **16** 字节 ⇒
`(0x1a8 − 0x138) / 16 = 7`。同一套换算在本仓已被三条独立事实钉过
（`Shell/ItemDrawer.cs` 里 `0x1b8/0x1e8/0x1d8` ↔ `dump.cs:93330/93339/93336` 的 `Slot 8/11/10`）。

**丁、slot 7 是谁**：

| 方法 | dump.cs | Slot | 说明 |
|---|---|---|---|
| `ObtainableItem.get_LocalizedName()` | `:18787-18788` | **7** | **abstract**（`RVA: -1`）⇒ 派生类必须实现 |
| `PremiumItem.get_LocalizedName()` | `:19240-19241` | **7** | `RVA 0x826700`，`override` |
| `PremiumItem.get_DisplayName()` | `:19237-19238` | **17** | `RVA 0x8266C0`，`=> name`（= **SO 名**） |

**戊、反证（排掉 `DisplayName`）**：`DisplayName` 是 **Slot 17** ⇒ 槽地址 `0x138 + 17×16 = 0x248`，
与指令里的 `0x1a8` **对不上** ⇒ 不可能是它。**这一条把「SO 名 vs 词条」彻底分开**。

**己、体语义落地**：`PremiumItem.LocalizedName`（ILSpy `out_cpp2il_dev_ilspy/PremiumItem.cs:21-35`）
= `LocalizationManager.GetTermTranslation(localizationKey, FixForRTL: true, 0, ignoreRTLnumbers: true, …)`
⇒ 词条；`localizationKey` 逐份实读（`assets_full/bundle_menus_assets_all/MonoBehaviour/Premium Campaign *.json`）
**13 份全是 `MenuShop/PremiumCampaign`**（例 `Premium Campaign AM` / `id premium_campaign_am` / `army 100`）。
词条真值 `Resources/official_loc_13lang.json`：EN `Premium Campaign` · ZH「高级战役」。

### 1·3 关于「同址 ≠ 同一方法」（这一条我按你的要求专门排过）

`decomp_full/PremiumDrawer__GetItemName.c` 的**首行**是 `MissionsTab_<>c__<RefreshRefillCount>b__9_0`，
而它所在的地址正好也是 `0x1806E6E80`（`.c` 里的 `Could not recover jumptable at 0x0001806e6ea4` 落在本函数体内）。

- 本裁定**没有**按地址归因：归属是 **`dump.cs` 的 Slot 20 + 体里读的槽 7** 两点共同锁定的。
- 「首行名是别人」在这里是 **ICF 折叠**（链接器把机器码相同的两个方法折成同一地址）⇒
  **那段机器码同时就是 `PremiumDrawer.GetItemName` 的语义**，所以结论不受影响。
- ⚠️ 判法记一笔：**先看 RVA 是否就是 dump.cs 给的那个**（这里正好是），再读体；两者不一致才是「内容错位」。

### 1·4 对我们代码的影响：**不改代码**（并说明为什么不改）

- 我们**没有** `PremiumDrawer`；`PremiumItem` 那 13 件在我们这边走**有图的通用 `Icon` 抽屉**，
  而 `Icon` 抽屉**不画名字**（`ItemDrawer.cs` 的 `Icon()` 只有主图 + 数量）。
- 原版这一格的名字要**显示出来**还多一道闸：`ItemDrawerReference.options.showName`
  （`ItemDrawer.cs` 的口径注释：`stackable`/`showName`/`typeString` 三字段在映射表 §② 里已解出、**我们还没接**）。
- ⇒ 现在**没有**任何界面把 SO 名当显示名印出来（`SoName` 只出现在 `MainMenuScene.cs:17155` 的诊断断言与一个夹具里，`grep SoName` 全仓 4 处）⇒ **不是可见缺陷**，但**判据要写对**：
  哪天要画这一格的名字，**必须** `Loc.T("MenuShop/PremiumCampaign")`，⛔ **不是** `SoName`。
- 因此账 165 **维持 B**：差的那一跳 = 「画名字」这一层（且它自己还差 `showName` 判据）。

## §2 `58 CurrencyDrawer.GetItemName` 的**图标那一半** —— 配对做实（走 guid 链，**不是**名字约定）

### 2·1 先回答「`guid_map.tsv` 为什么 0 命中」：**那张表只收卡**

`资料/普查产出_第二十七会话/guid_map.tsv` **4,998 行**，表头 = `uniqueId / cardName / field / assetGuid / bundle /
containerKey / type / className / name / internalId / exact` —— 每一行都是**某张卡的某个字段**引用的资产
（`cardImageReference` 一类）。⇒ 币种 GUID 0 命中**不是漏解，是索引口径**（⛔ 别把这句当成「本地没有」）。
