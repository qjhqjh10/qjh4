## 一、① `ShellScene` · `B103W7b` 渲染器数 30≠55 / 材质槽 32≠57

**裁定 = α（断言错：量法太窄）。不是 γ 回归、也不是「期望值过期」。**

### 证据（全只读）

1. **包是好的**（`_tmp_view/b103d4/probe_renderers.py` · UnityPy 静态逐对象数，不看容器登记）：
   ```
   wf_prefabs_extra.bundle  Renderer 类对象 = 55（ParticleSystemRenderer 53 + MeshRenderer 2）
                            材质槽 = 57 · 空槽 = 0
   ```
   ⇒ 期望值 **55 / 57 本身是对的**（与断言里钉的一致），包里**一个对象都没丢**。
2. 按**根 GameObject** 分组（`probe_roots.py`）：
   ```
   VanguardIdleEffect                   26
   Remnant Aeldari Collect particles    11
   Remnant Aeldari Destroy particles     6
   Card 3D Death Explosion               6
   Remnant Necrons Destroy particles     6
   合计 55（5 棵根）
   ```
3. **容器键指向的不是树的根**（`probe_cont.py` + `probe_tree.py`）：
   `m_Container` 里 `Vanguard Frame Animated VAT` → GameObject `pid=-7405287611820500883`，
   而它在层级里是**根 `VanguardIdleEffect` 下面的一个子物件**（只有一个 `MeshRenderer`）。
   其余 4 棵根都登记了 ⇒ 容器键那条路只能数到 **6+11+6+6+1 = 30 个渲染器 / 32 个槽**，
   与运行日志 `实得 30 个（期望 55）· 材质槽 32` **逐字吻合**。
4. 运行时**三条取法都没真正用上第一条**：`LoadAllAssets<Renderer>()` 对**四只产物全部返回 0**
   （日志里四只包的 `取渲染器的口` 全是 `容器键 + GetComponentsInChildren（去重）`）
   ⇒ 组件不是 Unity 意义上的「主资产」，那条口本来就走不通。
5. 顺带核：`wf_menus_extra` / `wf_battleshared_extra` / `wf_mainmenu_extra` 的三组绿数
   （36/36 · 13/13 · 66/68）与静态总数**逐一相等** —— 也就是说只有 `wf_prefabs_extra`
   因为「有一棵根没登记进容器」而被量少了。

### 修法（`Editor/B103W7b_Assert.cs`）

在「`LoadAllAssets<Renderer>`」与「容器键」之间**插一条** `LoadAllAssets<GameObject>()` +
逐根 `GetComponentsInChildren<Renderer>(true)` + **按实例去重**（GameObject 是主资产，包里 56 个全在）。
三条路的顺序与理由写进注释；容器键那条**保留为最后兜底**（前两条取不到东西时才有用）。

- 期望值 **55 / 57 不动**（静态复核已证）。
- **灭自证新增一条**（写进文件头）：删掉这条新路 ⇒ `wf_prefabs_extra` 回到 30/32 ⇒ 两条前提断红。
- 对另外三只产物**读数不变**（静态总数 = 现在那三个绿数，见证据 5）。

## 三、③ `DeckScene` · 那「2 条失败」其实是 **1 个根因**（外加 1 条**故意的**探针输出）

### ③-a `B3 ★ #94 英文档下，重取的口给出英文`（期望 `Claim`，实得 `init`）

**裁定 = α（断言断的是实现没承诺的事）。**

- 证据：`Battle/Label.cs` 的 `BindText` doc 明写「**只登记、不立刻取**」（理由：调用方通常刚把同一句
  传给 `MenuDraw.Text`，再取一次是白量一遍版面；想立刻对齐就自己调 `Relocalize()`）。
  `BindText` 体只写 `_textProvider` + `Loc.BindLocalized`，**不写文本**（`Label.cs:2617-2623`）。
  ⇒ 绑完之后 `lb.Text` 仍是 `Label.Create(..., "init", ...)` 那句 —— 实得 `init` **是设计行为**。
- 佐证：现读**有绑定面**的调用点全部是「先写值、再 `BindText(provider)`」的形状
  （`DailyStreakPopup.cs:496/616/828` 三处 · `InboxWindow.cs:506` 一处）。
  ⚠️ 另四个窗（`RewardWindow` / `RewardsWindow` / `DailyRewardPopup` 等）**还没绑 provider**
  （账见 `判据/B103_本会话待办与裁定.md:108`），它们走 `RelocalizeUnder(transform) == 0 ⇒ Open()` 那条退路，
  与本节无关。
- 修法（`Editor/B103A03_Assert.cs`）：绑完之后**显式调一次 `lb.Relocalize()`**（= `Loc` 换语言广播里
  对每颗标签做的同一跳），再断 `lb.Text == en`。断的仍是「provider 真能落到 `Loc.T` 的 en 列」，
  且走的是 provider → `SetText` → TMP 文本 的**整条链**（不是自证：期望值来自官方 13 语言表）。
  注释里写清为什么不能直接断「绑完就是英文」。

### ③-b `>>> A1007 探针 ✗ 截图 no_camera.png：没拍成 —— Camera.main == null`

**裁定 = 不是红，δ（夹具前提是【故意造出来的】）；**处置 = **什么都不改**。

- 这条 ✗ 是 `DeckScene.cs:1161-1207` 那条**判别式探针**的**预期输出**：它先把 `MainCamera` 标签摘掉 +
  关相机，**造出无相机上下文**再调 `MenuCheck.Shoot`，用来证明「没拍成时 `Shoot` 会出声」而不是静默 return。
- 它自己那 4 条断言**全绿**（`恰好 1 条 ✗` / `Pass == 0` / `图没落盘` / `相机还回去`），
  日志里那行前缀是 **`>>> A1007 探针 `**（`probeSink`，独立实例），**不进**本宿主 `_sink`。
- 结论：批处理里的「没有 main camera」是**探针手动造的**，不是环境事实、也**不该给它建相机**
  （`MenuCheck.cs:410-415` 那一支就是「无相机必须出声」的实现，改回裸 `return` 会让探针当场红）。
  ⛔ 不要改成 skip、也不要删。

### ③-c 顺带：`DeckScene` 的「2 条失败」= 同一根因记了两遍

`DeckScene.cs:825` 对子断言是这么并账的：
`_sink.Pass += B103A03_Assert.Pass; _sink.Fail += B103A03_Assert.Fail;` **然后**又
`Check(B103A03_Assert.Fail, 0, "★ AUD03 …")` ⇒ 子断言每失败 1 条，宿主合计**+2**。
日志佐证：`B103A03 合计 39 通过 / 1 失败` → 宿主 `2011/2013，2 条失败`，
且末尾失败清单**只列 1 条**（`Failures` 里只有 1 条）。
⚠️ **本次未改**（这是各宿主通用的并账口径，动了会改所有子断言的合计，超出本件范围）——
登记为读数口径问题，供调度台决定是否统一改成「只加 Pass、失败由那个 `Check` 承担」。
