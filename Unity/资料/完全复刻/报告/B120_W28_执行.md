## 四、⚠️ 与施工单有出入 / 如实记的边界（铁律 2 · 5·b）

1. **`OutFromPlayingAreaAnim` 的真实调用点不是「松手」**。`case 3/4/5` 的「还按着、指针又掉回线下」才是它
   （`Update.c:618/823/951`）；**松手**那一支原版只调 `MoveBackToHand`（`BattleManager.cs:25845`）。
   ⇒ 本件按派活把「两条方法在**松手这一刻**的并集」做进 `Release` —— **每一句都有出处，但「并在一起」是按派活拼的**，
   已在代码注释里标成「如实记」。真正的 `OutFromPlayingAreaAnim` 那一支（**已提交之后撤销**）我们**结构上没有**
   （越过高度即提交、不可撤销），**不在本件范围**。
2. **`cardState` 我们视图侧不存**（同 `CardFeel.ShowCardBeingDrawn` 的口径）⇒ 用 `Queue == QHandMoving` 当等价物。
   断言断的是这个等价物，**不是**真的 cardState 字段。
3. **`MoveBackToHand` 是「超集」**：它比 `DissolveMinionCard` / `UnDissolveWholeCard` 多了 `SetSortingLayer` 与
   `StopAnimsInPlay`（`CardFeel` 里唯一的公开等价物；`CardFeel.cs` 不在本件白名单，⛔ 没为它加新口）。
   多出来的两样都是回手该做的，且**必须排在 `Relayout` 之前**（`StopInPlayAnims` = `DOKill` 整张卡）。
4. **`Q04c5` 判据更正（重要）**：
   - 施工单/活状态表写「原版是 `NotEnoughRoom`（cantdo 那档）」—— **成立，但要限定在「松手」这一刻**：
     只有松手支传 `showTips = 1`（`BattleManager.cs:25816/25837`）；**其余 4 个调用点全传 `false`** ⇒ 静默。
   - 因此我**只在**「候选集为空 ∧ 指针在**出牌区里** ∧ 单位卡」三条同时成立时才判 `EngineRefused`。
     「指针留在手牌带里」那一档原版**根本不问** `CanPlayCard`（`BattleManager.cs:25806` 那层没进）⇒ 仍是 `MissedSlot`、
     仍然**一次都不问引擎**（断言 B5/B6 钉住）。
5. **`Relayout` 会覆盖队列**：`ApplyOutFromPlayingArea` 之后 `Release` 末尾的 `Relayout(true)` 会让 `HandLayout` 逐卡重设
   `SetQueue`（`HandLayout.cs:832`）⇒ 生产路径上 `QHandMoving` **只在那一拍成立**。断言 A2/A7 因此**直接调**
   `ApplyOutFromPlayingArea`（产品同一个入口）而不是走 `SimulateRelease`。
6. **`BattleDriver.cs` 有 20 行加在类尾（`:41639-41658` 一带）** ⇒ `:41660` 之后的 `ChoicePanelPool` 与命名空间整体 +20 行。
   账落点最深只到 `:41363`（该类尾注释自己写的），**产品代码行号未漂**；但若有人按 `ChoicePanelPool` 的行号引用过，需重核。
7. **未跑 Unity / typecheck**（派活红线）⇒ 已做的是逐行人工核 + 复用 W24 夹具打法；首次宿主运行请先看有没有编译错。
8. **多了一道 `_travel >= TapThreshold` 闸**（派活没写）：`Release` 同样服务**轻点 / 长按**（`OnTapped` 就在它里面发），
   而原版那一刻走的是 `OnTouchUpAsButton`（开关卡面展示窗），**从不进 `movingHandCard`** ⇒ 不可能是
   `OutFromPlayingAreaAnim` 那一支。不加这道闸的话，「点一下手牌」会被溶一次、`targeted` 法术还会弹一下缩放。
   断言 C2 因此额外硬断「这一拖超过轻点阈值」，避免它在「轻点」这条别的原因上通过。
