## 一、确认键（`B146-CONFIRM-ADAPTIVE-FONTSIZE`）

**改了什么**（`CardChoicePanel.cs:509`，单行原地替换、**行数零变化**）：
`if (_confirm != null) _confirm.SetGlyphHeight(33.7f);` → `ApplyAutoFit(_confirm, ConfirmBoxW, ConfirmBoxH, ConfirmFsMin, ConfirmFsMax, ConfirmFsBase);`

新增常量（类尾）：`ConfirmBoxH = 43.622f` · `ConfirmFsMin/Max/Base = 18 / 45 / 36`。

**⚠️ 与施工单的一处偏离（必须先看）**：施工单写的是「直接 `SetAutoFitBox(372.857, 43.622, 18, 45, 36)`」。
**不能直接这么填** —— `SetAutoFitBox` 的 min/max 是 `Label` 的 px 口径
（`NominalPx = FontSizeToPxNow(TmpFontSize(), ActualFace)`），而那个口径**按字体面分两支**：
拉丁面 = **em**（`EmPerFontSize 0.1 × UguiFontScale 10` ⇒ 1:1）；`Face.Cjk` = **汉字墨高**
（`EmPerFontSize = WorldGlyphPerFontSize`，现读 ⇒ **0.853 × em**，旁证 = 活状态表同一行的「修后中文读 28.75」= 33.7 × 0.853）。
中式文本会翻到 CJK 面（`Label.ActualFace`，`:1110`）⇒ 原样填 45 会让 `fontSizeMax` 变成 `45/0.853 = 52.7 em`。
⇒ 实现 = `ApplyAutoFit(lb, boxW, boxH, minEm, maxEm, baseEm)`（类尾）：先 `FontSizeToPxNow(minEm, lb.ActualFace)` 再喂，
两支都精确落到 `[18,45] em`（= 原版 TMP 字段原值）。**顺带**：`FontSizeMin/Max` 读回来就是 18/45，比「round-trip 的 px」更好断。

**期望值**（全部来自现读，不是估）：
· 原版字段 `m_fontSize 45 / base 36 / auto 1 / [18,45] / margin 0 / Right+Middle` →
`d:/2/tools/assetripper_out/ExportedProject/Assets/Data/Scenes/Battle Scenarios/Battle Arena 1.unity:225320-225380`（`m_text: Continue`）。
· 运行时 dump：`继续` = **fontSize 33.7**（`资料/原版参照图/Unity参照管线_0825/data/panel_0914b/choose_tree_forced.tsv:9`，矩形 372.86×43.62）。
· 为什么是 33.7：**垂直闸**卡出来的 —— 框高 43.622 ÷ 中文行盒 1.2933 = **33.73**；英文不触闸 ⇒ 顶到 max **45**。

   `fontSizeMax` 会大 `1/0.853 = 1.17` 倍。最近的一处是 `Battle/MulliganPanel.cs:946`（`DoneFsMin/Max/Base = 18/45/36`、框 `368.929×62.242`）——
  按同一条推导，中文「继续」会收敛到 **48.1**（垂直闸）而不是原版的 **45**（max），**大约 +6.9%**。`MulliganPanel.cs` 在我的黑名单里，**没动**，建议另派一条去核原版 `DoneText` 的 TMP 字段。

   我们直接建在 Label 上，没有这层。只影响折行宽，不影响 55 px 的字面。
