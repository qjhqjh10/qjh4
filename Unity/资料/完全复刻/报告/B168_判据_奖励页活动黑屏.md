## 一 渲染链（「活动」页由什么组成、读什么数据）

- **三个页签按钮和三个页签内容都是【prefab 里烘死的】**，不是由事件数据建出来的：

## 二 黑屏主因：`filter.army` 缺省 = Neutral(0) ≠ SelectedArmy(10)

### 2·1 数据事实

`E:/warpforge/05_工具/server/responses/ExecuteCloudScript.InitializeLiveOps.json` →
`FunctionResult.HandlerData.Campaign.RawEvents[0].Data`：

```json
{ "$type": "CampaignEventData, Assembly-CSharp", "eventId": "OfflineCampaign",
  "drawData": {...}, "PointsPerLevel": 10, "Nodes": [...3 条...],
  "Premium": null, "Background": { "m_AssetGUID": "" } }
```

**没有 `filter` 字段。**

### 2·2 `filter` 在反编译里是有默认值的（所以不是 NRE，而是「错值」）

- `LiveOpsEventData.Army => filter.army`（`Everguild.LiveOps/LiveOpsEventData.cs:42-52`）
- `LiveOpsEventData` **构造函数**里就 `filter = new EventFilter { eventDuration = 24, eventCooldown = 168 }`
  （同文件 `:172-212`，`new EventFilter` 在 `:207`）
  ⇒ JSON 缺 `filter` 时 Newtonsoft 走默认构造 ⇒ `filter != null`、**`filter.army == 0`**。
- `CardArmy`：`Neutral = 0 · Ultramarines = 10`（`d:/2/tools/il2cpp_out/dump.cs:45634-45652`）
- 参考活动资产 `Assets/MonoBehaviour/Ultramarines Campaign.asset` 写的是 `filter: { army: 10, ... }` —— **这才是原版形状**。

### 2·3 于是 `ChangeArmy` 一定落空

- `CampaignHandler.SelectedArmy__BackingField = CardArmy.Ultramarines`（`Everguild.LiveOps/CampaignHandler.cs:309`，无 `SharedData.selectedArmy` 时保持默认）
- `CampaignWindowTab.ChangeArmy` **没有兜底分支**：
  ```csharp
  object obj = Enumerable.FirstOrDefault(campaigns, c => c.Army == army);
  if (obj != null) SetActiveCampaign((Campaign)obj);   // ← 不命中就【什么都不做】
  ```
  （`CampaignWindowTab.cs:600-632`）
- 本数据：`c.Army == 0`，`army == 10` ⇒ `FirstOrDefault` = null ⇒ **`SetActiveCampaign` 从未执行**
  ⇒ `track/display/background/premiumPoints` **四个 Initialize 一次都没跑**。

### 2·4 四条独立反证（证明「初始化没跑」，而不是「跑了但画不出来」）

| 画面现象 | 若 Initialize 跑过应该是什么 | 实际（prefab 序列化值） | 判据 |
|---|---|---|---|
| 标题 `ULTRAMARINES` | `ArmyUtilities.GetLocalizedArmyName(10)` = **极限战士**（`Armies/Ultramarines` 的中文） | `ULTRAMARINES`（全大写英文） | `Campaign Tab.prefab:2115` |
| `Points: 69` | `string.Format("积分：{0}", TotalPoints-UsedPoints)` = **积分：0** | `Points: 69` | `Campaign Tab.prefab:2810`；`Rewards Menu/Points` 中文=`积分：{0}` |
| 底部同时出现 **`200` + `Continue` + `Siguiente: 5d…`** | `ChangeState` 三选一：非高级 ⇒ 显按钮+点数、**隐藏计时器**；已领 ⇒ 隐藏按钮+点数、显计时器 | 三组**同时可见**（prefab 默认全 active） | `Campaign Tab.prefab` 各 `m_IsActive: 1`；`CampaignPremiumPointsPanel.cs:ChangeState` |
| 整块黑 | `background.Initialize` → `LoadImage` 会把 `Background Image` `SetActive(true)` 并填 sprite | `Background Image` 仍 `m_IsActive: 0`；只剩父级那颗黑 Image | `Campaign Tab.prefab:54`(inactive) `:1159`(黑) |

⚠️ 一个**容易误判成正证**的点：底部标题「高级战役每日奖励」是**中文**，看起来像运行时本地化的。
实际它来自 prefab 上的 I2 `Localize` 组件：`mTerm: Missions/PremiumDailyCampaignPoints`、`LocalizeOnAwake: 1`
（`Campaign Tab.prefab:3885`，该 GameObject 组件表 `:519-538` 里第 5 颗）。**它 `Awake` 就会本地化，不依赖任何 Initialize。**

✅ 反向确认（排除同样的可能）：`Campaign Header` 的 `Title` / `Points` 两个 TMP **没有任何 I2 `Localize` 组件**
（逐组件现读：`Title` = RectTransform + CanvasRenderer + TMP；`Points` = RectTransform + CanvasRenderer + TMP + Image），
所以它们上面印的英文**只可能**是 prefab 烘死的值 —— 这条反证成立。

### 2·5 为什么同一个窗口的「锻造厂」页正常

`ForgeWindowTab.GetForgeEventByArmy` **有兜底**：

```csharp
Forge forge1 = Enumerable.FirstOrDefault(forgeEvents, x => x.Army == typeFilter);
Forge forge2 = forge1;
if (forge1 == null) forge2 = Enumerable.First(forgeEvents);   // ← 找不到就取第一条
```
（`d:/2/tools/cpp2il/out_il2csharp/Assembly-CSharp/ForgeWindowTab.cs`，`GetForgeEventByArmy`）

我们 `OfflineForge` 的 `filter` 同样缺省（army 0），但被这个 `First()` 兜住了 ⇒ 页面照常出数据
（截图 `65_forge_run3.png`：100 / 200 两档、`0/10` 进度、标题「极限战士」——注意标题用的是
`SelectArmy(selectedArmy)` 传进来的 10，不是 `currentForgeEvent.GetArmy()`，所以看着对）。
**`CampaignWindowTab.ChangeArmy` 没有这一句兜底 ⇒ 活动页什么都不做。**

> 📌 结论：**主因 = `HandlerData.Campaign.RawEvents[0].Data.filter` 缺失（army 默认 0）。**
> 不是节点缺、不是预制体缺、不是布局为 0、不是 `Premium: null`（`InventoryManager.HasItem(null)` 返回 false，安全，见 `InventoryManager.cs:862-876`）。

## 三 白块（`200 [白块]`）来源

- 那个格子是 `Premium Panel` 里的 `Icon Campaign Points Drawer Variant`（`Campaign Tab.prefab:606`），
  即 `CampaignPointDrawer : ItemDrawer<CampaignPoints>`；`image: {fileID: 114632457200066912}`（`Icon Campaign Points Drawer Variant.prefab:303`）。
- 被指的那颗 `Image`（GameObject `Image`，`1618682377417806`）：
  **`m_Color {1,1,1,1}`、`m_Sprite {fileID: 0}`、`m_Enabled: 1`**（`Icon Campaign Points Drawer Variant.prefab:494`）
  ⇒ Unity UI 对「无 sprite + 不透明色」直接画一个**白方块**。
- 正常流程里它由 `CampaignPointDrawer.DrawForArmy(army)` 赋 `ArmyUtilities.Instance.GetArmyIcon(army)`，赋不到就 `image.enabled=false`：
  ```csharp
  image.sprite = ArmyUtilities.Instance.GetArmyIcon(army);
  image.enabled = image.m_Sprite != null;
  ```
  （`CampaignPointDrawer.cs:DrawForArmy`）
- 因为 `Initialize` 没跑 ⇒ `DrawForArmy` 没跑 ⇒ sprite 一直是 null ⇒ 白块。
  **不是 guid 缺失、不是 `CampaignPoints.GetIcon` 的问题**（那条链根本不在这条 UI 上：这里画的是**军队图标**，不是战役点数图标）。

（⚠️ 必须同时改生成器 `E:/warpforge/05_工具/server/tools/add_all_configs.py` 的 `CAMPAIGN_EVENT`，否则下次 `--write` 会把它冲掉）

### 5·3 必做③：节点 / 每日奖励（数据已够，但要复核两个数）

- **节点**：`Nodes` 3 条已有 `NodeId/NodeCost/Rewards/UnlockedBy/Unlocks/Position/IsRepeatable`，
  且 `CampaignNodeInfo` 的所有属性都带 `[JsonProperty]`（`dump.cs:125243-125275`）⇒ Newtonsoft 能写私有 setter，**不用改**。
  `CampaignTrack.GetNodesOffset` 的「起点节点」判据是 `UnlockedBy.Count == 0`（c1 满足）。
  节点 prefab guid `72c49059124c6ae4f8124b6c131a10d0` = `Campaign Node`，在 **`bundle_menus_assets_all`**（`GameObject/Campaign Node.json`）⇒ 与 `Campaign Tab` 同包，离线可解析。
- **每日奖励点数**：`CampaignPremiumPointsPanel` 显示的是
  `Missions.GetPointsPerArmyOnDailyLogin(army)` = 在 `MissionsConfig.dailyLoginRef`（`Daily_Login`）的奖励里找
  **`Item is CampaignPoints && Item.cardArmy == army`** 的那一条（`Missions.cs:2067` + `:713-750`）。
  我们现在的 `Daily_Login` 奖励是 `{"item":"campaignPoints","quantity":50}`，而
  - `PointsConfig.points` 里**没有任何 `CampaignPoints` 条目**（现读只有 `ForgePoints` / `ScoringPoint`），
  - `CurrencyConfig` 里 `campaignPoints` 是 `Currency`（`cardArmy: 0`）。
  ⇒ **预判 `GetPointsPerArmyOnDailyLogin(10)` 会返回 0**（面板显示 `0` 而不是 50）。
  **修法（需实测确认）**：`PointsConfig.points` 增加
  `{"$type":"CampaignPoints, Assembly-CSharp","cardArmy":10,"cardRarity":0,"smallIcon":{...},"bigIcon":{...}}`，
  并让 `Daily_Login` 的奖励 item 指向它。⚠️ 这一条**不影响页面是否显示**，只影响那个数字对不对，可作为第二批。

### 5·4 不用改的（避免误修）

- **不要**给活动加 `drawData.EventComponents/EventAssets` —— 参考资产 `Ultramarines Campaign.asset` 也是空的，tab 是 prefab 烘死的。
- **不要**为了匹配而把 `SharedData.selectedArmy` 改成 0（那样军队选择器/标题会变成 Neutral）。
- **`Premium: null` 保留**：`IsPremium` → `InventoryManager.HasItem(null)` 返回 false（`InventoryManager.cs:862-876`），不会 NRE；
  走 `State.PremiumNotPurchased`，显示「成为高级」按钮、隐藏计时器 —— 这是非高级玩家的原版行为。

## 八 顺手发现（记账用）

1. 🔴 **所有 liveops 事件都没有 `filter`**（`ParentEvents/Shops/GameModes/Inbox/Missions/Forge/Campaign/ScoringEvent` 逐条现读 = null）。
   目前只有 Campaign 因为「`FirstOrDefault` 无兜底」而炸成空白；
   Forge 靠 `First()` 兜底、Missions 按 missionType 分组，所以症状被掩盖。
   ⇒ 这条缺口**不是 Campaign 独有**，凡是按 `army` 分流的地方（军队选择器、`GetCampaign(army)`、`PointsConfig.GetPointItem(army)`）
   都会拿到 `Neutral(0)`。**建议按 S1 的生成器一次性给所有需要 army 的事件补 `filter.army`**，并逐页复核。
2. ⚠️ **白块不是这一页独有**：`65_forge_run3.png` 顶上正中、以及左下 `0/10` 前面的图标**也是白块**，
   同族原因（`Image` 的 `m_Sprite` 为 null 而 `enabled=1`）。凡「运行时才赋 sprite 的 drawer/icon」在初始化缺失时都会这样。
3. 📌 **`CampaignBackground`（黑底板）与 `CampaignUIBackground`（背景图）是两层**：
   黑底板在 prefab 里就常开，所以**任何一次 `Initialize` 失败都不会让页面「白」或「透明」，而是「纯黑」** ——
   以后见到活动页纯黑，先想「背景图没加载 / 初始化没跑」，别想「面板没建」。
4. `Campaign Tab.prefab` 里还有 `Premium pruchased`（`purchased` 拼错，`:305`）与 `Change Deck`（`:1859`）等编辑器残留，属于原版资产原样，**不是我们写错的**。
