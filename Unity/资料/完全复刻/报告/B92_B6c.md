## 6 顺手发现

1. 🔴 **`RuleCore.IsUnitInPlay` 在「待死窗口」与原版 `IsInPlay()` 分叉（潜在真缺陷）**：
   它只按「在不在某一方棋盘上」判（`RuleCore.cs:10782`），而 `DeferDeaths` 窗口内**死者仍占着槽**
   ⇒ 它返回 `true`，原版对 `cardState == 5` 返回 `false`。
   唯一调用点 = `RuleCore.cs:10761` 的 `RemoveCardEffectIfInvalid`（extrinsic 施放者）
   ⇒ 可观测 = 「施放者刚判死、其 extrinsic 手牌效果这一拍本该被摘，我们没摘」。
   修法 = 改用 `u.IsInPlayState(ctx)`。**已写进 `CardScript.IsInPlay()` 那条账的差异列**，等 B1 接。
2. 🟡 **`RuleCore.IsUnitInPlayOrDying` 是宽口径**（含「已回手但仍活着」），而原版那个谓词**只按 `cardState`**
   ⇒ 两者在「已回手」那一档不同。它作为「加效果/指代目标」的闸是对的，但**不能**叫原版那个谓词；已在账里写清。
3. 🟡 **`drawing(7)` 是休眠档**：40 个写入点里**没有一处**置它 ⇒ 原版出货 0 写点。照抄保留，⛔ 别当缺口。
4. 🟡 **ILSpy 里 `object obj = cardState - 17; return obj == null;` 就是 `== 17`** —— 这类「装箱减法」在 ILSpy 里出现多次
   （`IsInPlay` / `IsInPlayOrDying` / `IsInHand` / `IsInDeck` 全有）。**判「这是哪个值」时要把它还原成相等比较**，
   ⛔ 别当成算术运算。这条以后还要用（`decomp_full` 那边同样的招式是 `(uint)(x - 5) < 2` 之类）。
5. 🟡 **B1 需要的两条现在都能拼**：① 载体 `u.IsInPlayState(ctx)`；③ 目标 `CardStateOf ∈ {3,17}`。已在 `AllowResolveAttack` 那条账里写清。
