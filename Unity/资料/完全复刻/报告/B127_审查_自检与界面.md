### `界面-P-25` —— 为什么判「判据本身错」而不是「没做」

1. **原版确实用 JP 字形**（这是待办行自己也在问的那一点）：原版 font 是 TTC，`name` 表 face0 = `Noto Serif CJK JP`（`nid 1/4 = Noto Serif CJK JP` · `nid 6 = NotoSerifCJKjp-Regular`）；原版 TMP 资产的 `m_FaceIndex = 0` ⇒ 取的正是这个 face。
2. **我们装的也是 JP**：`Assets/CardPresentation/Fonts/NotoSerifCJK-Regular.ttf`（mtime 2026-10-25 07:22）md5 = `395466fcc2c3e40ae60e9d061c21569b`，与 `_tmp_view/wfC/NotoSerifCJK-Regular-JP.ttf` **逐字节相同**；其 `name` 表同样是 `Noto Serif CJK JP`。⇒ 「没有 `-JP` 那份」只说明**文件名沿用了旧名（guid 不变）**，不是没装。
3. **不需要重烘**：该 SDF 资产 `m_AtlasPopulationMode: 1`（Dynamic）、`m_GlyphTable: []` / `m_CharacterTable: []`，与**原版那份完全相同**（原版 `NotoSerifCJK-Regular SDF.json` 也是 Dynamic + 空 glyph 表）。动态字体在运行时按需光栅化，**没有「烘焙」这一步**；`TmpFont.cs:27` 也写着「只有 `NotoSerifCJK-Regular SDF` 那份是 Dynamic、图集是 1×1 占位」。
4. **原版 vs 我们逐字段**：`m_FamilyName` JP = JP · `m_FaceIndex` 0 = 0 · `m_PointSize` 50 = 50 · `m_Scale` 0.9 = 0.9 · `m_AtlasPopulationMode` 1 = 1 · `m_AtlasWidth/Height` 2048/2048 = 2048/2048。
