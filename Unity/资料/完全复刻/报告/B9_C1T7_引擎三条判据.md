## 一、三条的结论（一句话版）

### ① 残骸上的光环关键词 —— 修法选 **①「残骸整条不施加」**，候选 ② 是错的

- **原版两层闸都指向「不施加」**：
  1. **目标池**：光环 logic 的 `targetCriteria.includeRemnants` 现扫 **52/53 行为 0**
     （唯一 1 = `SAU36 Nemesor Zahndrekh`，而它投 `buffType 90` + `trait 1190 notDestroyRemnant`，
     正是我们 `AuraSpec.RemnantStay` 那支）。判据 `FilterMethods__CheckIfMeetsCriteria.c:273-278`。
  2. **投递**：光环是**触发能力 20/240** ⇒ `AbilityData.whileInPlay/whileInPlayVariable` ⇒
     `CardEffect.extrinsic = true`（`AbilityLogic__PlayAbility.c:1193-1197` / `:1350-1354`），
     而残骸门 `CardScript__AddEffect.c:159-170` **只放行 `addStats`+`healthChange≠0` 与 `addTraitRemnant(90)`**
     ⇒ `addTrait(3)`（光环授关键词）在残骸上**直接被拒**。
- **候选 ② （`AddAuraKeyword` 也写 `_remnantTraits`）会与 `HasCurrentTrait` 相反**：
  原版残骸支只扫 `activeEffects` 里 `buffType==0x5a`（`EntityScript__HasCurrentTrait.c:54-70`）
  ⇒ `Has` 必须是 false。
- **「今天零可观察」只对 `regeneration` 成立**：唯一读 `KwValue("regeneration")` 的行为点是回合末再生段
  （`RuleCore.cs:2527-2541`），它前面先 `!u.Has("regeneration") ⇒ continue` ⇒ 残骸走不到。
  🔴 **但 `Armour N` 这一族走的是【关键词】那条**（`GivePayload.cs:144` 的 `GiveKw` 有 `armour`）⇒
  `AddAuraKeyword("armour",1)` → `SyncKeywordState` → `Armor` 字段 +1，而
  `DamageAfterArmourOne`（`RuleCore.cs:7600-7605`，**击杀预览**）/ `CounterAttack.cs:146` /
  `ConditionEval.cs:390-393` 都不看 `IsRemnant`（实伤那条 `RuleCore.cs:7477` 才有 `!IsRemnant` 守卫）
  ⇒ 残骸会被算成「更耐打」。活例 `UM14 Honour Guard` / `AM38 Baneblade Tank` / `AM28 Chimera`。
  **所以这条账比交接里写的严重一级：不是纯潜伏。**
- **施工 = `Core/Aura.cs` 的 `ApplyAura` 通用载荷委托首行加一句 `if (t.IsRemnant) return;`**
  （⛔ 别碰 `a.RemnantStay` 那支；⛔ 别加 `ctx.Log` 免得动 `play all dump` 指纹）。

### ② `chosenAbility 160 (discardFromHand)` —— 我们 0 个派发，且那张卡不在池里

- 唯一使用点 = SO **`f3df0cfc…`**（`T1 BlackLegion-Abaddons Chosen_startinghand`，名字也叫
  Abaddon's Chosen，`cardType 20`，`manaCost 1`）的两条 `TurnStart(30)` logic：
  **① `160 discardFromHand`（targetsAffected = self，即弃**它自己**）** · ② `100 createCardInHand → BL37`。
- 原版结算链（逐跳已读）：`AbilityLogic__PlayAbility.c:588-603` → `BattleManager__AddDiscardFromHand.c:23/76`
  （`BattleAction type 0x1c=28`、`casterCard=null`、纯入队）→
  `…_ResolveDiscardFromHand_d__544__MoveNext.c:29`（**不在手牌 ⇒ 只 LogWarning、不弃**）/ `:95/:108/:112/:135/:150/:155/:156`
  （展示 → DestroyCard → RemoveCostEffects → 移出手牌 → Finish）。**本路不发任何广播。**
- 我们这边：`grep discardFromHand` = 0；`EffectText`/`EffectResolver` 没有 `discard` 动词；
  这张卡**不在 `cards_engine.json`**（1,128 张），只在 `cards_truth.json`（1,351 SO）里，
  且 `card_inventory_options.json` 把它列进 `unmatchedTruthRows`（不可获取）。
- **还差一层结构**：我们的回合起止只在「棋盘单位 / `IsHandTrap` 手牌陷阱 / 常驻」三处发火
  （`EffectResolver.cs:8571-8614` + `8501-8548`）⇒ **「手牌里一张卡的结构化 TurnStart 能力」没有路**，
  光把卡加进池它也不会响。

### ③ `ResolveTargets` 不挡 stealth / camouflage / ward —— **正确，⛔ 不许改**

- 原版这三族只在**合法性层**挡，`AbilityLogic.GetTargets`（= 我们 `ResolveTargets` 的对应物）
  **一个都不看**（`AbilityLogic__GetTargets.c` 里 `HasCurrentTrait` 调用数 = **0**；
  ⚠️ 该文件 `:845/:849` 出现的 `0x46/0x8c` 是 `targetsAffected` 枚举值 70/140，不是 trait）⇒
  随机/全体/AoE 照样命中潜行单位。
- 三道闸的覆盖矩阵（都是「**只在异侧**」）：
  - `IsValidSpellTarget.c:47-57` = **stealth + ward + camouflage**（战术卡点选，且 `caster.targeted`）
  - `IsValidActiveAbilityTarget.c:47-53` = **stealth + ward**（**无 camouflage**）+ `0x2da summonRift`
  - `IsValidAttackTarget.c:134 → :320-330` = **只有 stealth**
  - `RawCardScript__IsValidTarget.c:24/30/37` = ward · camouflage（**仅 `caster.cardType==0x14`**）· stealth
- 我们**三条路都已对齐**：`AddSide(stealthGate)`（`EffectResolver.cs:2897-2911`，被 `IsLegalPick:2019-2022` /
  `PlayTargetPool:2081-2084` 使用）· `RuleCore.CanUseAbilityTarget:11309-11349` ·
  `RuleCore.IsValidTarget:5382-5386`。**没有发现缺口。**
- 已有断言：`RuleEngineTest.cs:35474`（单选挡）· `:35556`（全体不挡）。

## 二、顺手发现（按铁律 5 / 5·b —— 建议记账，均未改）

0. 🔴🔴 **①那条账的严重度要上调：`Armour` 类光环在残骸上是【今天就可观察】的，不是「零可观察」。**
   `Armour` 载荷在我们这边走**关键词**那条（`Core/GivePayload.cs:144` `GiveKw` 里有 `armour`/`armor`），
   所以 `Aura.ApplyAura` → `AddAuraKeyword("armour",1)` → `UnitState.SyncKeywordState` → `Armor += 1`
   （`UnitState.cs:1247`）。而 `Armor` 的这几个读点**不看 `Has`、也不看 `IsRemnant`**：
   `RuleCore.DamageAfterArmourOne`（`:7600-7605`，`WouldKill*` / 击杀预览那一族）·
   `CounterAttack.cs:146` · `ConditionEval.cs:390-393`（`u.Armor > 0` 条件格）。
   ⚠️ **实伤**那条有守卫 `if (!u.IsRemnant && u.Armor > 0 …)`（`RuleCore.cs:7477`，判据是原版
   `ReceiveDamage` 有 `+0x65` 闸、预览函数没有）⇒ 偏差形状是「残骸被**算成**更耐打，真打却不减甲」。
   活例：`UM14 Honour Guard` / `AM38 Baneblade Tank`（`Adjacent units have Armour 1`）·
   `AM28 Chimera`（`Friendly Infantry troops have Armour 1`）。
   ⇒ 交接里那句「今天零可观察差异（`EndTurnCore:2531` 挡掉）」**只对 `regeneration` 成立**。
1. 🔴 **`EffectResolver.cs:2896` 的「camouflage 池内 0 张可达 ⇒ 今天零行为变化」不成立。**
   现读 `cards_engine.json`：**印 `Camouflage` 关键词的卡 21 张**
   （`ASH69` / `AM59` / `AM68` / `AM16` / `DA31` / `DA8` / `GSC68` / `SOR21` / `SOR29` / `SW8` / `SW7` …），
   keywords/desc 提到共 33 张 ⇒ 这条闸**今天就是活的**，谁按那句注释去改它就会踩真回归。
   （同段 `:2881` 的「池内 0 张」若指 `ward/wardWb` 则**对**：keywords 现扫 0 张。）
2. 🔴 **`CardScript.AddEffect` 的闸②③④「只在 `if (extrinsic)` 块内」**（`.c:91-197`；
   ILSpy `CardScript.cs:17465-17470` 的 `if (!extrinsic) goto IL_0694`，而 `IL_0694` 在 `:17601`，
   残骸门在 `:17597-17600`）。仓库里 `EffectResolver.cs:11311-11326` 的四闸表**没有写这个前提**
   ⇒ 下一个人会以为「非 extrinsic 的效果也过残骸门」。本轮之所以能定 ①的结论，靠的就是这一跳。
   **建议**：在那段注释补一句前提；**⛔ 但别顺手把我们的闸③ 改成「只在 extrinsic 时生效」** ——
   我们的 `extrinsic` 判定今天只有手牌那一层有载体（`EffectResolver.cs:11336-11341` 已如实写明），
   改了会放开一片。
3. ⚠️ **`UnitState.cs:1157`（`AddKeyword` 在残骸上写 `_remnantTraits`）依赖「闸③ 挡住所有非 90 的关键词授予」。**
   本轮只核了 `EffectResolver.DoGive` 一路；其它直接调 `AddKeyword` 的入口（附魔层 / `RuleCore` 内部授予 /
   `AddTraitSilently` 等价物）**没有逐点核** ⇒ 可能存在「原版 `Has=false` 而我们 `Has=true`」的反向偏差。
   建议单开一条只读普查。
4. ⚠️ **`AuraSpec` 没有 `IncludeRemnants` 这一位**，而卡数据里现成有
   （`cards_engine.json` 的 `abilityTargetCriteria[].criteria.includeRemnants`）。
   今天靠「通用分支统一跳过残骸 + RemnantStay 分支单独放行」等价覆盖 52/53；
   **出现第一种「授权给残骸的普通光环」时会错**。建议趁生成器还热的时候接进 `AuraSpec`。
5. ⚠️ **「手牌里一张卡的结构化 TurnStart 能力」这条通道整体缺失**（不只是 ② 那一条）：
   `ResolveAtTurn` 的手牌那一趟只收 `EffectText.IsHandTrap(card)`。原版
   `BroadcastTurnStart` 的 ②③ 两跳扫的是**双方手牌的全部卡**（`GetCardsInHandRef`）。
   池内 `TurnStart 3 / TurnStartPlayer 3` 六张卡今天靠棋盘那一趟兜住了，所以不可观测；
   但 ② 那张池外卡正是靠这条路 ⇒ 修 ② 之前必须先决定走窄口还是宽口。
6. ℹ️ **id 链对上了**：`RuleCore.cs:9762` 注释里的「`SAU68 Damaged Plasmacyte`」是**旧 id**，
   现池是 **`SAU67`**（`Data/LegacyCardIds.cs:730`：`SAU68 → SAU67`）。不是错，别当缺陷改。
7. ℹ️ **「池内 1 张」这个说法要修正**：`chosenAbility 160` 实际是 **全 SO 1 张 / 池内 0 张**。
   账里若写「池内 1 张」，下次会有人去 `cards_engine.json` 里找它而找不到。
8. ℹ️ `BL37`（池内那张）投的是 `buffType 16 choiceEnchantment`，`choicesSpecificCardIds` =
   四张 `Mark of {Khorne,Nurgle,Slaanesh,Tzeentch}_enchantment` ⇒ 它**不是**「Dark Pact 附魔」那条链，
   与 ② 无关；`判据/B9_全池对拍_差异.tsv:733` 那行「BL37 挂 16 类加成 = 对」仍然成立。
