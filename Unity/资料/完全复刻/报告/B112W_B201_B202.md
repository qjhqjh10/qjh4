def _wrap(d, field):
    """读 `Texture2D.m_TextureSettings.<field>`；读不到返回 -1（未知，调用方不许拿它覆盖）。"""
    try:
        st = getattr(d, "m_TextureSettings", None)

**⑤ 类尾新增（全部追加在文件末尾，⛔ 不动中间任何一行）**

```csharp
struct ArenaTexImportRow
{
    public int MipCount; public int ColorSpace;
    public int WrapU; public int WrapV; public int FilterMode; public int Aniso;   // 🆕 -1 = 未知/老表无列 ⇒ 不动
}

static string[] ArenaTextureRoots(string scene) => new[]
{
    TexDir(scene),
    ArenaDir(scene) + "/Sprites",
    RootDir + "/Textures/LUT",
};

static bool IsSpriteTexture(string path) => path.Replace('\\', '/').Contains("/Sprites/");
static bool IsLutTexture(string path)    => path.Replace('\\', '/').Contains("/Textures/LUT/");

static void ApplyTextureType(TextureImporter ti, string path)
{
    if (IsLutTexture(path)) return;
    ti.textureType = IsSpriteTexture(path) ? TextureImporterType.Sprite : TextureImporterType.Default;
}

static bool ApplyOriginalImport(TextureImporter ti, string path)
{
    var table = LoadArenaTexImport();
    var name  = Path.GetFileNameWithoutExtension(path);
    ArenaTexImportRow row = default(ArenaTexImportRow);
    bool has = table != null && table.TryGetValue(name, out row);

    if (IsLutTexture(path)) { /* 只核对 wrap、出声一次、⛔ 不写；见 §四 */ return false; }

    if (!has) { ti.mipmapEnabled = false; /* 出声 */ return true; }

    ti.mipmapEnabled = row.MipCount   > 1;   // 原版 m_MipCount
    ti.sRGBTexture   = row.ColorSpace == 1;  // 原版 m_ColorSpace
    if (row.WrapU      >= 0 && row.WrapU      <= 3) ti.wrapModeU  = (TextureWrapMode)row.WrapU;
    if (row.WrapV      >= 0 && row.WrapV      <= 3) ti.wrapModeV  = (TextureWrapMode)row.WrapV;
    if (row.FilterMode >= 0 && row.FilterMode <= 2) ti.filterMode = (FilterMode)row.FilterMode;
    if (row.Aniso      >  0)                        ti.anisoLevel = row.Aniso;
    return true;
}
```

## 四、LUT 与 `B-119` 的关系

### 4·1 结论先行

**本单没有动 LUT 的 wrap，`B-119` 的结论一个字没改。** 代码里那 7 张走的是「**只核对、不写** + 出声一次」的分支。

### 4·2 为什么这么设计（不是偷懒）

`EnsureLutImportSettings`（`ArenaBuilder.cs:3550`）**一直在管**这 7 张 LUT：
`sRGBTexture = false`（LUT 是**数据不是颜色纹理**）· `mipmapEnabled = true` · `FilterMode.Bilinear` ·
`textureType = Default` · `npotScale = None` · `compression = Uncompressed` · `maxTextureSize = 256`。
`ApplyPostFx` 每次建场都会调它（`:3599` 那段，**故意放在加 ColorLookup 之前**，见那里的注释）。

⇒ **`B112W_B198_B199.md` §七·1 那句「`Textures/LUT/` 完全没人管导入设置」不准确**：
没人管的是 `Sprites/`；LUT **有唯一写手**，只是它的 `.meta` 里 `wrapU/wrapV: 1`（Clamp）与原版 `0`（Repeat）不一致。
（我⛔ 没有权限改那份报告，请调度台就地订正 —— 铁律 5。）

若把 LUT 塞进通用循环，会出现三个后果，所以本单**不做**：

1. `ApplyOriginalImport` 会写 `wrapModeU/V = Repeat`，而 `EnsureLutImportSettings` 的 `ok` 判据要求 `Clamp`
   ⇒ **每次建场都把 wrap 翻一遍**（写 → 判 false → 再写回），`.meta` 抖动、日志刷屏；
2. 通用循环会设 `alphaIsTransparency = true` 与 `maxTextureSize = 512`，**都不是 LUT 该改的格**（现读 0 / 256）；
3. `B-119` 的施工单（`活状态表.md:204`）写死了落点：**`EnsureLutImportSettings` 的判据式与写入两处一起
   `Clamp → Repeat`，改完重导那 7 张、重跑受影响战场**。那是**战场线的执行窗口**，不是本单。

### 4·3 本单给 `B-119` 留下的东西

- 旁挂表里现在**有 LUT 的 7 行**，`wrapU = wrapV = 0`（Repeat）、`filterMode = 1`、`aniso = 1`；
- 构建时会打一条（**每个 LUT 名字只一次**）：
  `[Arena] LUT `LUT Battle Arena X` 的 wrapU 与原版不一致（我们 1 / 原版 0） ⇒ 账 `B-119`，本方法不改`；
- **三方读数一致，`B-119` 的「原版 = Repeat」成立**：
  `vfx_texture_mips.tsv` = `0/0` · 新 `arena_texture_import.tsv` = `0/0` ·
  `D:/2/tools/assetripper_out/ExportedProject/Assets/Texture2D/LUT Battle Arena Aeldari.png.meta` = `wrapU: 0 / wrapV: 0`。

⚠️ **`B-119` 落地时要注意**：`EnsureLutImportSettings` 的 `ok` 里那条 `ti.wrapMode == TextureWrapMode.Clamp`
也要一起改（它是**单一 `wrapMode`**，不是 U/V 分开）。改完这 7 张的 `.meta` 会变，本单的「LUT 0 份变化」随之失效 ——
**但那是 `B-119` 的账，不是本单的回归。**

## 七、顺手发现（⛔ 都没改，本单不越界）

1. 🔴 **`报告/B112W_B198_B199.md` §七·1 那句「`Textures/LUT/` 完全没人管导入设置」不准确** ——
   `EnsureLutImportSettings`（`ArenaBuilder.cs:3550`）一直在管那 7 张的 sRGB / mip / filter / 压缩 / 尺寸 / wrap。
   只有 `Sprites/`（18 份）是真的没人管。请调度台就地订正（铁律 5）。
2. 🔴 **`Atack_Icon BW` 的 `.meta` 是 `textureType: 0`（Default）· `spriteMode` 缺失 · `enableMipMap: 1` ·
   `alphaIsTransparency: 0`**，而它是原版 `BattleAtlasUI` 图集里的一个 Sprite。
   成因：13 个用它的 `Crosshair` 在 `*_sprites.json` 里**全部 `active: false`** ⇒ `LoadSpriteAsset` 从没跑过 ⇒
   **没有 Sprite 子资产**。本单把 `textureType` 提到 `Sprite`（采样设置照原版图集），
   `spritePixelsToUnits` 现读已是 **100**、`spritePivot` 已是 **(0.5,0.5)**，与原版 `m_PixelsToUnits/ m_Pivot` 一致。
   ⚠️ 但**它仍然不会被任何人加载** —— 「不活跃的 Crosshair 到底要不要建」是另一条，本单不碰。
3. **5 张已导入的精灵 `spriteMode: 1`（Multiple）带 1 条 `spriteSheet` 条目，而 `LoadSpriteAsset` 要 `Single`** ——
   本单**没动**（换 `spriteMode` 会重排 sprite 子资产 fileID ⇒ 唯一写手应是 `LoadSpriteAsset`）。
   现读：`Glow` / `Glow Scattered` / `Card Text smooth background` / `Eclipse Sun` 都是 `spriteMode: 1`。
   ⇒ 这可能就是「精灵建了但 `LoadAssetAtPath<Sprite>` 该返回什么」那条隐忧的来源，**建议另立账核**。
4. **表里 `Atack_Icon BW` 的 `width/height` 记的是图集尺寸 2048×2048**，不是这张精灵自己的 **180×182**。
   消费侧不读这两列（`maxTextureSize` 用的是磁盘 PNG 的实际尺寸），所以**不影响行为**；但看表的人要知道，
   否则会以为工程里有一张 2048² 的 `Atack_Icon BW`。
5. **218 / 251 份 `.meta` 仍是 Unity 默认值**（`maxTextureSize: 2048` 到处都是）⇒ 说明
   `ApplyTextureImportSettings` **自 B-198/199 落地以来一次都没跑过**（战场线暂停）。
   本单的 §三 是「跑一次会怎样」的预测，不是「已经怎样」。
6. **`filterMode` 现读 127 个名字全一致** —— 与 `B112W_B198_B199.md` §七·2 的「0 份」吻合，
   这条**不用再做**（除了 LUT 那 7 张，现读也是 1 = Bilinear，与原版一致）。
