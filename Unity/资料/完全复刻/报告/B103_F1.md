## 一、结论（三处各怎么修的、为什么这样修而不是别的）

### 0. 先说根因（一处，不是三处）

`Inventories.Wildcards.Updated` 是**静态**事件（`Shell/Inventory.cs:1529`，= 原版 `Signal.Raise(WildcardUpdateSignal)`）。
订阅口 `DeckRuntime.HookWildcardUpdate` / 退订口 `UnhookWildcardUpdate`，而**唯一的退订时机是 `OnDestroy`**（`Deck/DeckRuntime.cs:1196`）。

🔴 **批处理（`Application.isPlaying == false`，也就是全部 Unity 自检）里 `DestroyImmediate` 不派发 `OnDestroy`**
⇒ 每一具被销毁的 `DeckRuntime` 都**还挂在静态事件上**。
判据（本项目已实测过两次，不是推测）：

- `资料/普查产出_1012/D9_Battle六红诊断.md:14` —— 「`BattleDriver` … `DestroyImmediate(组件)` **不会派发 `OnDestroy`** ⇒ `DetachStaticHooks()` 根本没被调过」；
- `资料/普查产出_1017/D4_联机诊断.md:123` —— 「本宿主（批处理）里不派」；
- `CLAUDE.md` 记录的「编辑模式下 `AddComponent` 不触发 `Awake/OnEnable/Start/Update`」是同一族的另一半。
  ⚠️ 如实标注：`OnDestroy` 单独这一条**本仓的成文实证只有上面那两处诊断结论**，我另外做了**一致性反推**（见 §二·3）。

`B103_R1` 的 AUD03 #8 + F3 把 `OnWildcardsUpdated` 从「只播扫光」改成「播扫光 + `RefreshHeader()`」（= 原版 `UpdateCounters` 的
`UIEffectTweener.Play` + `SetCountersText` 两句，`d:/2/tools/decomp_full/WildcardDisplay__UpdateCounters.c`）——
**这一改把上面那条一直静默的泄漏变成了抛异常**：一具尸体上 `Root == null`、`_deckNameHint` 已销毁，
`RefreshHeader` 第一句取 `_deckNameHint.gameObject` ⇒ `MissingReferenceException: The object of type 'CardPresentation.Label'`。

⇒ ①（`DeckScene` 崩）与 ③（`CollectionScene` 1 红）是**同一个根因、同一个修法**：
不是「F3 那半做错了」，而是**信号回调必须先问一句「我还活着吗」**。

### ① `DeckScene.Run` 整条宿主崩 —— 修在 `DeckRuntime`（自愈 + 出声）

选 **(b)+(a) 的组合**，理由：

- 只在 `OnWildcardsUpdated` 加闸（= 选项 b）能挡住这一条路；
- 但 `RefreshHeader` 是**多路调用**（`SetTab` / `RefreshAll` / 改名 …），任何一条在尸体上跑都是同一个崩
  ⇒ 再加一道**入口硬闸**（= 选项 a）。
- ⛔ 都没有把 F3 那半删掉（活的实例照旧刷四格，新断言 ② 钉着它）；
- ⛔ 都不是「静默跳过」：两个闸都 `Debug.LogWarning`（每条只响一次 —— **闸里当场退订**，之后信号再也不会打到这具尸体上）。
- ⛔ 没有改「谁在什么时候销毁」这一层（那属于别的代理的文件，且原版关窗本来就是销毁）。

落点（**都改在既有行上，行数零变化**）：

| 位置 | 改法 |
|---|---|
| `Deck/DeckRuntime.cs:4748`（`RefreshHeader` 第一句） | 新增 `if (Root == null \|\| _deckNameText == null \|\| _deckNameHint == null) { 出声 + UnhookWildcardUpdate() + return; }`，原注释**整句保留**在后面 |
| `Deck/DeckRuntime.cs:9138`（`OnWildcardsUpdated` 第一句） | 新增 `if (Root == null) { 出声 + UnhookWildcardUpdate() + return; }`，原 `CardDisplayPage` 那句**逐字保留**在后面 |

为什么判据是 `Root == null`：`Root` 是 `Transform`（`DeckRuntime.cs:990`）⇒ C# 的 `==` 落到 `UnityEngine.Object.operator==`
⇒ 实例被销毁时**必然**为真；这比逐个判 `_deckNameText == null` 更能表达「整棵树没了」。
`RefreshHeader` 那道还多判两颗标签：因为**部分销毁**（树在、某件被摘）也只能从标签看出来。

### ② `RewardsScene.Run` 整条宿主崩 —— 照 `B102_D9` 样板重造一具

链路（现读，全部闭合）：

1. `Editor/RewardsScene.cs:8191` `var dr = DailyRewardPopup.Create(wm2);` + `:8192 wm2.OpenWindow(dr)`；
2. `:8533 wm2.CloseAllWindows();` —— **把 `dr` 也关了**（它同时在 `openWindows` 里）；
3. `:8537 wm2.OpenWindow(ds)` —— `OpenWindow` 的 `ReapClosedWindows` 把**已关闭**的 `dr` 收割（销毁）
   （「关窗 = 延后到下一次开窗时销毁」，与 `B103_D1` 在 `cw` 上诊断出来的是同一条机制，见本文件 `:7079-7090` 的既有注释）；
4. `:8610` `dr.entries[...]` 读的是**托管字段**，尸体上照样读得出来（**看不出来**）；
5. `:8651/8653` `dr.transform` 才第一次碰原生对象 ⇒ 崩，**整条宿主零输出、连合计行都不印**。

修法 = 与 `:7085` 那具 `CampaignRewardWindow` **同形**：`if (dr == null) { LogWarning; 重造 }`，插在 `:8592`（R0 那一节的第一句）**同一物理行**
（⇒ 行数不变，`:9637` 那条账落点不漂）。

⚠️ 一处**与样板不同**、必须写明的选择：重造后走 **`dr.Open()` 而不是 `wm2.OpenWindow(dr)`**。
理由：`DailyRewardPopup.type = Fullscreen`，而 `WindowsManager.OpenWindow` 的全屏支第一句就是
`if (openWindows.Count > 0) HideAllWindows();`（`Shell/WindowsManager.cs:315-319`）——
那会把**紧接着 R0/R1 两块要量的 `ds`（连登窗，`:8537` 刚开）一起藏掉**。
`GameWindow.OpenByState` 的 `Closed` 支做的事是「播开窗音 → `SetActive(true)` → `state = Open` → `Open()`」，
`Create` 出来的 GO 本来就是 active（`AttachToAnchor` 只改父级，不 `SetActive`）⇒ 这里只需要「`Open()` = `Build()`」这一步。
R0/R1 那两块只读 `dr.transform` / `dr.entries` / `Label.Face|Text|ActualFace`（全是建树时就有的东西），不读 `CurrentState`。

### ③ `CollectionScene` 1 红（`B99_W2` 断言自身抛异常）—— **由 ① 的同一处修复覆盖**

- 现象：`_tmp_view/collection.log:116263` `MissingReferenceException · CardPresentation.Label`，
  发生在 `B99W2Assert` 的 `win.RaiseWildcardSignalForTest()`（`Editor/B99W2_Assert.cs:120`，= 原版同一句 `Signal.Raise`）之后。

### 2. 为什么是「已销毁的 `B99W1` 那具」而不是宿主那具 / `B99W5` 那具

- 崩溃发生在 `B99W5_Assert.cs:144`，此时**已死**的只有 `B99W1` 那具（它在 `B99W1_Assert.cs:196` 的 `finally` 里被 `DestroyImmediate`）。

  （它建树时必然建出 `hdr_wcbg`）。
- 修正前后**行为差**：修前第一具死实例在 `WildcardShineAfterTab` 就打了那条误导性的 `hdr_wcbg` 警告，然后 `RefreshHeader` 抛异常
  —— 多播委托**遇到异常就中断**，后面的 `B99W5` 那具**根本没轮到**。修后：死的那具出声 + 退订 + 返回，活的两具照常播 → 断言恢复正常语义。

### 3. 「批处理里 `DestroyImmediate` 不派 `OnDestroy`」的一致性反推（我自己做的，供复核）

若 `OnDestroy` **会**派发，`UnhookWildcardUpdate()` 就会执行，静态事件上只剩两具活实例
（宿主 + `B99W5`），**根本没有尸体可抛** ⇒ 日志里那条 `Label 已销毁` 就无从解释。反过来，只有「不退订」这一种情形能同时解释
「`hdr_wcbg` 找不到 + 标签已销毁 + 崩在 `RefreshHeader`」。加上 §〇 那两份诊断，结论成立。
