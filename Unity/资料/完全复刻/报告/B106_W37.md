## ④ 断言的「灭自证」是怎么写的

`SectionRewardsDerived()` 里每一条正向都配一条 **结构上不可能同时成立** 的反向：

| 编号 | 断言 | 改坏法 ⇒ 哪条红 |
|---|---|---|
| ⑥a / ⑥b | `typeof(RewardsBadge).IsAssignableFrom(typeof(CampaignBadge / ForgeBadge))` | 基类改回 `: BadgeNotification` ⇒ 红 |
| ⑥c / ⑥d | `new CampaignBadge().parentId == ""` / `new ForgeBadge().parentId == ""` | 删掉 ctor 或写错值 ⇒ 红 |
| ⑥e | 不同类型（Campaign vs Forge）同 `parentId` ⇒ 算中 | 第一支写成恒 false ⇒ 红 |
| ⑥f 🧨 | 不同类型、**不同 `parentId`** ⇒ 不算中 | 第一支不比 `parentId` ⇒ 红 |
| ⑥g | **同类型**、不同 `parentId` ⇒ 不算中 | 把同类型支写成「同类型即匹配」⇒ 红 |
| ⑥h | 同类型 ∧ 同 `parentId` ∧ 同 `army` ⇒ 算中 | —— |
| ⑥i 🧨 | 同类型 ∧ 同 `parentId` ∧ **`army` 不同** ⇒ 不算中 | 删掉 `army` 比较 ⇒ 红（这是 13 颗阵营格的红点赖以成立的那一条） |
| ⑥j 🧨 | `ForgeBadge` 的 `army` 同理 | 同上 |
| ⑥k 🧨 | `CampaignBadge.Validate(new InboxBadge())` = false | 把默认支写成「任意通知都过」⇒ 红 |
| ⑥t 🧨 | `RewardsBadge{parentId="CampaignMission"}` 过滤 ⇒ 战役 0 条算中 | 证明 ⑥s 的正数来自 `parentId` 比较，不是「类型对上就算」 |

**关键的一对是 ⑥i + ⑥s**：⑥i 挡「把 `army` 删掉」，⑥s 挡「把基类改回兄弟类」——
两处一起改回去不可能同时绿（⑥i 只依赖同类内部的比较，⑥s 只依赖外闸 `IsRelated`）。

⚠️ 旧 ④f 的写法（`new CampaignBadge{army="Goff"}`）在本轮改动后**其实仍然通过**（`Selected` = `Ultramarines`），
所以它不是「改完必红」，而是「**语义已经不对**」：它只证明了「同类型那一支比 army」，
证不了「不同类型比 parentId」那一支。已按上表拆成两条，两支各打一枪。
