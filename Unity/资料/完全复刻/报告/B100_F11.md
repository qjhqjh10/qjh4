## 五、顺手发现

1. 🔴 **X3 报告 #12 的判据键写错了一个词，简报跟着写成了「按 `cardType` 排除 20」**：
   `cardType == 20` 是「非单位牌」的大类（**487 张**：tactic 446 + defence 39 + enchantment 2），**不是附魔的判据**；
   照它过滤会把 **446 张战术卡**的受击件一起删掉（而且产物看起来「干净了」，是静默大范围错）。
   真正的键 = **`type == "enchantment"`**（2 张），与 `BattleScene.cs:13425` / `VfxMap.cs:3521` 逐字同义。**本件按 C# 尺子做，已实测只挡下 1 条（`Pray Enchantment / Pray_Exit`）**。
   📌 建议调度台把 X3 #12 那一格的措辞订正成「`cardType 20`（= 这张附魔卡的 `cardType` 值）」免得下一批再照抄。
2. ⚠️ `CardPresentation/Core/VfxMap.cs:1261` 那句汇总日志把 `notPlayed` 一律称「⛔ 无权威依据**不播** N 条」——
   我们新加的那一条**有权威依据**（`conf = authoritative`），只是「那个时机不属于它」。现在它会被叫成「无权威依据」，措辞误导。
   `VfxMap.cs` 不在本代理白名单 ⇒ **未改**；建议后续把那句改成「不播 N 条（`notPlayed[].outcome` = `duplicate` / `unbacked` / `enchantment-not-unit`）」。
3. 📌 `CardPresentation/Editor/BattleScene.cs:2523` 的注释写「现读 **19 档**全部登记」—— `DiscardReveal`/`StealReveal` 进来后是 **21 档**。只是注释（断言本身是 `Enum.GetValues` 现数，不写死），不在白名单 ⇒ **未改**。
4. 🔍 **`Pray_Exit` 现在完全没播**：原版那一下是「附魔被摘掉」的演出（`chosenAbility = removeThisEnchantment`(340)）。
   要在 `EvtKind.EnchantmentRemoved` 那一拍播它，得先查原版 `ResolveRemoveEffect`（内联进 `ResolveAction` `case 0x10`）那条链有没有「该播哪件」的判据 ——
   今天 `EventTiming.cs` 那条注释明写「`BattleDriver` 侧**没有任何消费者**（纯表现信号）」⇒ **没有判据，所以没搬**（已写进 `notPlayed` 的 `why` 里，⛔ 不拿猜测顶替判据）。这是一条**新活**，建议进账（铁律 11：有判据就做、只有先后）。
5. ✅ 生产路径有一处**顺带被验证**：`BattleDriver.PlayCardBeingDrawn`（`:37854`）本来就用 `CardFeel` 那一对常量，
   只是**时间线那一侧**缺登记（`DurationOf` 回 0 ⇒ 下一拍会在揭示动画中途就开场）。现在两侧同源。
