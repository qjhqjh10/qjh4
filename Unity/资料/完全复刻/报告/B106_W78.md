## ③ 三档为什么这样收口

| 档 | 动作 | 为什么 |
|---|---|---|
| `Open` | **什么都不做** | 商店已经在 `Open`。这里若再 `OpenWindow(win)` 会走 `Open()`→`Build()`→`BuildPages()` **重建内容**（页对象换一批、`LastBoosterPack` 归零、货架/抽屉计数重算）—— 后面实拍与断言的现场被无声换掉。原版 `OpenWindowCO` 对已开的窗也没有这一跳。 |
| `Background` | `win.TryOpen()`（无参重载） | 判据 = `Shell/GameWindow.cs:507`（`public bool TryOpen()`）：三支本体 `Closed ⇒ Open()` / `Background ⇒ state=1 + 回前台虚方法(+0x1a8)` / `Open ⇒ ret`。这与原版 `WindowsManager__ShowPreviousWindow` ⑥ 那一跳（`mov rcx,[rdi+0x58]; xor edx,edx; call 0x180835fd0`，**一个实参都不喂**）逐句对位 ⇒ **只回前台、不重建内容**。这正是本红的现场（开包窗压在商店上、商店停在 `Background`）。 |
| `Closed` | `mgr.OpenWindow(win)` | 与原写法一致（唯一保留的一档）。判据 `Shell/WindowsManager.cs:383` 的 `GetOpenWindow<T>` 同一套窗口表；`OpenWindow` 走 `Open()`→`Build()`，重建是这一档的**语义本意**（窗本来是关的）。 |

`mgr` 为空时两扇弹窗都没法关（`GetOpenWindow` 挂在管理器上），`Closed` 档也没法重开 —— 那时只做断言、让它如实红（⛔ 不静默吞掉）。

## ④ `bp` 改取的依据

改成 `mgr.GetOpenWindow<BoosterPackOpenWindow>()`：
- **`LastBoosterPack` 会被重建抹零**：`Shell/ShopWindow.cs:150-168`（`Open()`）→ `:249-261`（`BuildPages()`）重建一批新的 `ShopTabPage`；日志侧铁证 = 「（编排）买完弹出的开包窗先关掉…」只出现 3 次（`79867/81210/82265`），此后 `:82961` 起再没出现 ⇒ 页上引用已换新、指不回旧开包窗。
- **`GetOpenWindow<T>` 读的是管理器的活窗口表** `openWindows`（`Shell/WindowsManager.cs:383`，判据 = `WindowsManager__GetOpenWindow_object_.c` 的 `FirstOrDefault(x => x is T)`），与页对象是否重建无关；窗口活着就一定能取到。
- 同一个口顺手把 `BoosterInfoPopup` 也关掉（`Editor/B103F4_Assert.cs:322/335` 已有同样取法先例）。先关 popup 再关开包窗：popup 是压在开包窗上的详情窗，先摘上层、再关下层，避免关下层时又把上层 `ShowPreviousWindow` 提回来。
