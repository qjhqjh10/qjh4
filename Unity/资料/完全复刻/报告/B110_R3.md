## 六、顺手发现（⛔ 一个都没顺手改）

1. 🔴 **原版 AI 对 oath 是「随机二选一」，我们是「付得起就付」**（真行为差异）。
   判据：`ChoiceOfCardEnemy` 在「非联网 + 敌方卡 + 非 replay」时 `num1 = fullPool.IndexOf(options[0])`
   （`out_il2csharp/Assembly-CSharp/BattleManager.cs:8951-8965`），而 `GetChoiceOptions(..., isBotAndNotReplay: true)`
   **跳过排序**（`:9061`）⇒ `options[0]` = 随机抽出来的第一张 ⇒ 平/誓等概率（并消耗预烧随机）。
   我们 `DecideOathChoice` 是确定性的「付得起就付」（`EffectResolver.cs:18020-18032`）。
   **调度台已另立账 `B-69`，本批没动。** ⚠️ 将来做它时**正好用得上本批的两格**（AI 挑出来的值也要录进/发出去）。
2. 🟠 **`MsgAction.handId` 是死字段**（类 doc 自己写着全仓 0 读取点）。本批差点被当成「能塞答案的地方」——
   建议收口时记一条「要么删、要么写明为什么留」（同族：`MsgStart.myDeckSeat` 零消费方、`MsgDeck.draftPropsVer` 是正例）。
3. 🟠 **账的落点机检有一个新形状的坑**：`looks_like_decl` 的候选正则要求「名字后面紧跟 `( < { ; = :` 或行尾」——
   给类型声明行**加行尾注释**会让「`SimpleAI.cs:76（AiAction）`」这类 A 行**直接变失败**（不是漂移）。
   ⇒ 结论：**改 `class X` / `struct X` 这类声明行时，注释要挪到 `{` 那一行**。本批踩过一次、已修（失败 22 → 21）。
4. 🟢 `NetSelfTest.TestSeatAndWire` 原来**没有任何「字段级」往返断言**（加 `picks` 时也没加）——I⑩~I⑫ 是这一族的第一批；后续再加 `MsgAction` 字段照这个形状补一条。
