## 1. `BattleScene.Run` — `TargetParameterCountException`

- **现象**：`battle.log:207936`；死点前最后一条绿 = `C5 D12（表现层）`（`:207858`），D12「引擎那一半」一进入就炸；异常前 **0 条红**。

- **定位（现读）**：`Editor/BattleScene.cs:41877-41879`（第二次在 `:41890-41892`）反射调 `RuleCore.EmitListenerTrigger`，**给 6 个实参**；而 `RuleEngine/Core/EffectResolver.cs:8019-8020` 的形参已是 **7 个**（`…, bool selfOnly = false, int instanceId = 0`）。
- **`git blame` 判据**：`EffectResolver.cs:8020` = **未提交 · 2026-10-31 · `B106_W57`**（行尾注释自述）；`BattleScene.cs:41877-41879` = 提交 `45dd42d4`（**2026-10-24**）未动。
- **定性：γ 本批回归 —— `B106_W57`**（同批「同物理行改签名 ⇒ 行号零漂移」只保住了账；`Invoke` 的 `object[]` 编译期查不出 ⇒ typecheck 0/0 也放行）。
- **修法**：两处实参表各补一个 `0`（= `instanceId` 缺省 = 改前行为）：`…, false, 0 });`；并建议加硬前提 `Check(miEmit.GetParameters().Length == 7, …)`。
- **影响**：死点后到 `RunCore` 结束（`:46869`）整段没跑，源码 `Check/CheckTrue` **416 处**（D13/D14/A5/A1/A3/A4/A1905/A/E/F/E7…）。
- **还缺**：跑一次 `BattleScene.Run` 验（补 `0` 后 D12 两条是否真绿 + 后续有没有别的红）。

## 2. `CollectionScene.Run` — `MissingReferenceException`（`WildcardTutorial` 已销毁）

- **现象**：`collection.log:88806`；异常前一条红在 `:88791`（`★★ 已看过 ⇒ 再走一次不重启` 期望 True 实得 False，栈 `CollectionScene.cs:10211`），并紧跟着第二次 `[WildcardTutorial] 起：state = Filter` 的日志。
- **栈关键帧**：`CollectionScene.RunCore [0x1d8b3] @ CollectionScene.cs:10217` → `UnityEngine.Component.get_gameObject` → `TryThrowEditorNullExceptionObject`。
- **定位（现读）**：`Editor/CollectionScene.cs:10197-10224`（`B106_W46` 新增的 ⑤ 段）。链条：
  1. `:10197` `ResetProgressForTest()` 清 `PrefDone`，`:10198` 还断言「没看过」；
  2. `:10199` 第一次 `RunPoolBuiltHookForTest` 起教程（`CollectionWindow.cs:6784-6799` → `TryStart:125-133` → `ForceStart`）；
  3. **起完不写 `PrefDone`**（只有状态机走到 `OnOwnedToggled` 才写，`WildcardTutorial.cs:200`）⇒ `IsDone` 仍 false；
  4. `:10211` 第二次调用 ⇒ `TryStart` 判「没看过」⇒ **真的重启** ⇒ `ForceStart:143` 的 `DestroyImmediate(old.gameObject)`（批处理 `isPlaying=false`）**把 `built` 真删掉** ⇒ 返回非 null ⇒ `:10211` 红；
  5. `:10217` 取已销毁的 `built.gameObject` ⇒ 抛（Unity 假 null 只在 `== !=` 重载成立，原生属性直取会抛）；`:10220-10224` 的 `PrefDone` 还原与「（收尾）」断言因此没跑。
- **定性**：**主因 α 断言写错（`B106_W46`）** —— 断言前提「已看过」与夹具 `:10197/:10198`「没看过」自相矛盾；`B106_W46` 交回把「两次调用之间没有写 `PrefDone` 的路径」推反了（正因为没有，第二次才会重启）。**异常本身 γ** —— `B106_W52` 的修复（`WildcardTutorial.cs:143` 编辑模式改 `DestroyImmediate`）是对的，但它把这条错断言从「红一条」升级成「宿主中途炸」；W52 前 `Destroy` 在编辑模式不生效、`built` 还活着 ⇒ 不会抛。**不是 β**（`TryStart/ForceStart` 行为与原版 `state != End` 一致），**不是 δ**（夹具前提都成立）。
- **修法**：`:10210` 前插入 `PlayerPrefs.SetInt(WildcardTutorial.PrefDone, 1); PlayerPrefs.Save();` + 一条 `CheckTrue(WildcardTutorial.IsDone, "（夹具）…")`，再调第二次（应返回 null ⇒ 不重启 ⇒ `built` 不被删）；`:10215/:10217` 收尾改为 `if (built != null && …)`（用 `==` 重载挡假 null）。
- **影响**：死点后 17 个 `Section`、源码 `Check/CheckTrue` **330 处**没跑；**副作用**：`PrefDone` 停在「删掉」（`hadDone` 备份了没写回）⇒ 真 Play 时万能牌教程会再弹一次，修好后自然消失。
- **还缺**：跑一次 `CollectionScene.Run` 验；另立一条「`TryStart` 闸该不该是进程内一次性」——判据 = 原版 `WildcardTutorialManager` 的宿主是否常驻（**未查清，没下结论**）。

## 3. 同一节的另一条红（非异常）：`ForceStart` 连起两次「都拿得到实例」

- **现象**：`collection.log:88587`，栈 `CollectionScene.cs:10164`。
- **定位**：`CollectionScene.cs:10162-10167` —— `ta` 在 `:10163` 第二次 `ForceStart` 时被 `DestroyImmediate` 真删，`ta != null`（Unity 假 null）= false ⇒ `:10164` 红；而紧邻 `:10165` 要求 `ta == null`。**两条在同一时刻结构上互斥，必红一条。**
- **定性：α（W52 自己写下的一对互相矛盾的断言）+ γ（同一笔的 `DestroyImmediate` 让 `ta` 真变假 null 才触发）**。W52 只跑了 typecheck，没跑宿主 ⇒ 没发现。
- **修法**：把 `CheckTrue(ta != null, …)` 移到**第二次调用之前**（或改成先存 `bool taAlive = ta != null;`），`:10164` 简化为 `CheckTrue(tb2 != null, …)`；`:10165` 的 `ta == null` 保留。
- **还缺**：跑宿主确认。

## 4. 顺手发现（规则级，建议进账）

- **反射 `Invoke` 不补可选参数**（`OptionalParamBinding` 也不行）⇒「方法存在」这条前提挡不住「形参个数变了」。`Editor/` 下 `.Invoke(null, new object[])` 形态 **37 处**（另有 `.Invoke(target, …)` 形态未逐个核），本批只此一处不匹配（`EmitCardTrigger` 无反射调用点）。建议纪律：**取到方法后先断 `GetParameters().Length`**。
- **Unity 假 null 两个面**：`x != null` 对已销毁对象恒 false（复合条件会被静默吃掉）；`x.gameObject` 直接抛 `MissingReferenceException`。⇒ 清理一律写 `if (x != null && x.gameObject != null)`。
- **「让销毁真的生效」的修复会唤醒下游依赖「没生效」的断言** —— 本次第 2、3 条都是这个形状；改销毁口时要 grep 该组件的 `!= null` 邻域。
