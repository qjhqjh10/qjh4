#### A·2 换算函数（收口一处）

Unity 的 `localScale` 绕**节点自己的 `m_Pivot`** 缩，⛔ 不是绕父左上角。所以：

```
visual = P + s · (layout − P)        P = 枢轴在父(Entry)坐标系里的位置
     P_normal  = (DrawerOx + DrawerW/2,              DrawerOy + DrawerH/2)          = (157.51, 206.06)
     P_premium = (DrawerOx + DrawerW/2,              DrawerOy + dy + DrawerH/2)     = (157.51, 600.54)   (dy = 394.49)
```

我们原来写的是 `visual_old = s · layout`（= `ScaleAbout(..., 0, 0, ...)`，实为绕 Entry 左上角）
⇒ **偏差 = `0.2 × P`**：

| 抽屉 | Δx | Δy |
|---|---|---|
| `NormalReward` | **+31.50** | **+41.21** |
| `Premium Reward` | **+31.50** | **+120.11** ← 派单里那句「8 个子件系统性偏 (+31.5,+41.2)」只覆盖了普通抽屉 |

**落地**：`ScaleAbout(PxRect r, float ox, float oy, float s, PxRect parent)` 本身不用改（它本来就是「绕 `parent+(ox,oy)` 缩」），
只把**调用点的 `ox/oy`** 从 `(0,0)` 换成枢轴；两个枢轴收成类尾两个属性 `DrawerPivotX` / `DrawerPivotY`（⛔ 不在每个子件上手改魔数）。

#### B·3 为什么**没有**改成数据驱动（判据 + 风险）

1. **原版那两个数不是常量、也不是本地可算的**：它们来自 `MissionChallengeProgress` 这个**服务端进度对象**（关服后本地没有等价物）。
2. 我们本地**唯一**近似是 A815 的 `_streakDays`（登录计数，**从 1 起**），而弹窗这套夹具是 `Current=5 / Collected=5` —— 两者**口径不同**（`DailyData.cs:995-1004` 那段已经写明「合并会把弹窗那一族断言一起改口径」）。
3. **硬接会越界崩**：`_streakName/_streakIcon/_streakAmount` 只有 **7 条**，而 `SI(i) = Mathf.Clamp(i, 0, StreakDays-1)`。一旦 `StreakDays > 7`（`Current` 一变大就会），`SI` 能返回 7 ⇒ **`IndexOutOfRangeException`**。
   ⇒ 真要做，得先扩奖励表 + 建 `MissionChallengeProgress` 的本地等价物，属**另立一件**，不是「迅速可解决」。
4. 按铁律 18·0（**只有和服务器有关的才允许自己设计**）—— 这一格正是那一类 ⇒ **保留夹具 + 打 `🔶` 标记 + 在注释里写出处**，⛔ 不猜数。
