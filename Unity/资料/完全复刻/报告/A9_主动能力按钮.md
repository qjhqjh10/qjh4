### 1·1 最关键的一条设计取舍：**四处接线读同一个谓词**

```csharp
static bool IsActiveAbilityEntry(UnitState u)     // BattleDriver.cs:36148
    → u.Card.HasActiveAbility == 1 && !u.HasAbility
      && RuleCore.AlternativeActionKeyword(u) == null && u.Card.OathOps.Count == 0
```

* **为什么按「前三条等价入口在【数据上】都不存在」判、而不是按「前三条的闸没过」**：结算那条路（`DoResolve`）**只按有无分档**（`alt != null` → 替代行动 …），它拿不到「哪一档的闸过了」。若按钮按「闸」出现、结算按「有无」分档，就会出现**「钮亮了、点下去走的是另一条正文」**——静默错配（本项目最怕的一类）。
* ⇒ 按钮给不给（`OpenCommand`）/ 目标在哪一侧（`CommandTargetSideFor`）/ 目标合不合法（`LegalTargetCode`）/ 真的结算（`DoResolve`）**四处读同一个谓词**，⛔ 别在任何一处另写一份。
* **对另外 86 张 `hasActiveAbility == 1` 的卡：`IsActiveAbilityEntry` 恒 `false`** ⇒ 本笔对它们**逐位无影响**（判据 = `判据/SOR66主动能力_判定.md` §3·2：那 86 张至少带 `duty`/`pray`/`agenda`/`ferocity`/`oath` 之一）。
* 「要不要玩家点目标」**没另写一份**：用 `RuleCore.CanUseActiveAbility(…, targetSlot: -1)` —— 只有「要选目标」那一支会回 `ErrTarget`，其余码都不是这条意思。

### 1·2 `SOR66` 的完整链路（静态逐句走了一遍）

`拖拽/轻点棋盘卡` → `OpenCommand`（`skill = true`）→ 悬停选中 → `CommitCommand(Ability)` → `CommandTargetSide()` = **`_me`**（己方，`ActiveAbilitySideOr`）→ `HighlightTargets` 把**我方合法单位**画上 `ValidTarget` 描边（`LegalTargetCode` → `CanUseActiveAbility` → `CanUseAbilityTarget(targetOwner = p)` → `ActiveAbilityPickGate` 的 36 格）→ 玩家点中的那一格 → `Resolve(Ability, t)`（asks 为空 ⇒ 直落）→ `DoResolve` → `LocalAct(AiAction{Kind=ActiveAbility, TargetP=_me, TargetSlot=t})` → **`RuleCore.UseActiveAbility(ctx, _me, slot, t)`**（A3 新口：`buffOthers` 给**你点的那一个** +2 远程 / `triggerPray` 自己进祈祷）。
