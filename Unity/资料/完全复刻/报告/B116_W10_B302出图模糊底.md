# B116_W10 · `B-302` 出图宿主的模糊底比原版糊 3 倍

核销时点 2026-11-02（未跑 Unity · 未动账/活状态表/git）

## 结论：**改了**（`UIBakeScreen` 行数零变化 · 新成员全在类尾）

## 根因
- 批处理 `-executeMethod` 跑在**编辑器非播放态**，没有真实 GameView ⇒ `Screen` 恒 **640×480**
  （本仓多处实测：`资料/交接_第五十八会话.md:111` · `任务线/战斗线/任务/T09_整层换uGUI.md:687` · `交接_第四十一会话.md:94`）。
- 而 `WindowShots` 这一趟的场景是按**硬编码 1920×1080** 渲的（`Editor/WindowShots.cs:72` `const int W = 1920, H = 1080`）
  ⇒ `UIBakeScreen.CreateRT()` 读到 640×480 × 0.25 = **160×120**，线性分辨率只有原版 1920×1080 → **480×270** 的 **1/3**。
- 不是我们没设：全仓 `Screen.SetResolution` **0 命中**，启动命令也没有 `-screen-width/-screen-height`。
- **顺带查出的第二个缺陷**：4:3 的 RT 让 `ImageQuad.WorldW = WorldH(10) × 1.333 = 13.33`，而 16:9 的可见宽是 **17.78**
  （`Core/LayoutSpace.cs:13-14,106-116`）⇒ 现在的模糊底**左右各少盖约 12.5%**。改成 16:9 后 17.78 正好铺满。

## 改法
1. `CardPresentation/Shell/UIBakeScreen.cs`
   - 新增 `[System.NonSerialized] public Vector2Int ScreenSizeOverride;` + 两个私有算口 `EffScreenW/EffScreenH`
     （**全在类尾**，`:304-320`；默认 `(0,0)` ⇒ 回落到 `Screen.width/height`，与改前逐位相同）。
   - `CreateRT()` 的 `w/h`、`Build()` 的 `_rtW/_rtH`、`Update()` 的分辨率比对、异常告警文案：改读 `EffScreenW/H`
     —— **全部就地改写，行数零变化** ⇒ 账引用的 `:108 Build / :156 CreateRT / :201 Toggle / :278 ResolutionChanged / :284 OnDestroy`
     现读**逐一在原位**（已用脚本按行号打印核过）。
2. `CardPresentation/Editor/WindowShots.cs`
   - `EnsureBake()`：`bake.ScreenSizeOverride = new Vector2Int(W, H);`（排在 `Build()` **之前**，让 `_rtW/_rtH` 也按有效值播种）
     ⇒ RT = `ceil(1920×0.25) × ceil(1080×0.25)` = **480×270**（= 原版同形）。
   - `_index.tsv` 的读数串 / 退化告警 / `MinBakeRtW` 判据注释 / 文件头：同步改成「帧尺寸」口径（该文件**无账落点**）。

## 是否 `🔶 自己设计`：**是**，已按铁律 18 打标（`UIBakeScreen.cs:304-313`）
- 是什么：一档「用显式帧尺寸替代 `Screen`」的读数口。
- 为什么必须自定：原版判据（`CreateRT`）只认 `Screen`，而批处理下 `Screen` 拿不到真实帧尺寸、也不可设
  （`-executeMethod` 是编辑器非播放态；`Screen.SetResolution` 在编辑器里不生效 —— **Unity 文档口径，本机未实测**；
  `-screen-width/-screen-height` 只作用于独立 player）。判据本身在这一格是空的。
- 谁定的：调度台 2026-11-02（`B-302`）。
- **⛔ 真机零影响**：override 只有 `WindowShots.EnsureBake()` 赋值；`ShellRuntime` 建的那件、`ShellScene` 自检用的那件都不赋值
  ⇒ 仍读 `Screen`，`Editor/ShellScene.cs:9144/9146` 的 `RT == ceil(Screen×0.25)` 断言按静态读码不受影响（未实跑）。
