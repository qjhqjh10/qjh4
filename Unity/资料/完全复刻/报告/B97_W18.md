## 四 回放选牌面板 —— 行为口径（含**两处刻意边界**）

1. **候选从录像来，⛔ 不回放时重算**：`choosecard` 的候选是 `BattleManager.GetChoiceOptions` 那套「随机抽 `maxTargets` 张」（我们的 `ShowAsk → DrawForDisplay`，吃 `ctx.Rng`）⇒ 回放时重算会**消耗随机流、把后面每一条动作全冲掉**。⇒ 录制端在 `ShowAsk` **真摆出候选那一刻**快照 `_askCands` 的 id（其它 ask 族快照面板上的文字）。
2. **`action` 下标怎么对齐**：ask 发生在动作**落地之前**（`BeginPlay`/`Resolve` → `BeginAsk` → `ShowAsk`），而三个记账口（`RecAct`/`RecRaw`/`RecMsg`）都是 `append` ⇒ 那一刻的 `_rec.actions.Count` **正好等于**这条动作将要拿到的下标。
3. **两处刻意边界（如实记，⛔ 不假装）**：
   - **(a) 批处理不摆面板**（`Application.isBatchMode`）：自检没有帧循环、也没有画面；摆了只会让既有那批回放断言依赖一条**纯表现**的时序。**真机那条路照做**（原版看得见的正是那一半）。
   - **(b) 只记本机玩家的 ask**：联机局里对手的动作走 `NetApply.Apply`、**从不经过面板** ⇒ 对手那一半的 ask 不记。原版是两端各自重跑引擎、两边都会弹；这一点我们与它不同（如实记）。
4. **`ProcessChooseDone()` 的「不选卡」照抄**：我们的收口只 `Close()` 面板 + 清视图，**不写 `ctx.ChoosePicks`** —— 因为回放的答案早在 `NetApply.Apply` 里排好了（见下条「顺手发现」）。
5. 🔶 自己设计（非原版）：2 秒到点后**不把答案写回引擎** · 原版那条是引擎同步等面板返回，我们这里面板是**纯表现** · 调度台 2026-10-29 裁定（判据 ①~④ 已逐条对上，差异只在「答案从哪来」这一步的内部管线）。

## 五 存档格式与向后兼容

### 5.1 新字段

```csharp
// ReplayRecord（partial，追加在类尾）
public ReplayVars vars;                          // null = 没记（老档）
public List<ReplayAsk> asks = new List<ReplayAsk>();
```

- 🔴 **用的是类型化嵌套对象，不是 R1 建议的 `string varsJson`**：`GameplayVariables` 带 `int?` 字段、`JsonUtility` 会**静默丢掉**可空字段 ⇒ 必须先换成**全非可空**的 `ReplayVars` 再序列化。用嵌套 `[Serializable]`（`JsonUtility` 原生支持）比「把 JSON 塞进一个字符串字段再转义一遍」少一层、也少一处出错的地方。
- `ReplayVars` 的 22 格 = 原版 `GameplayVariablesData` 的 **18** 格（`maxLegendaries` / `numberOfCopiesOtherRarities` / `numberOfCopiesLegendary` / `slotsPerSide` / `warlordLifeChange` / `deckSize` / `overtimeTurn` / `startingMana` / `startingManaSecond` / `addedManaSecond` / `manaPerTurn` / `drawCardsPerTurn` / `manaAccumulation` / `handLimit` / `shouldReshuffle` / `showMulligan` / `assignDefensiveCardsInEditMode` / `alternativeTraitLogic`）+ 我们独有的 **4** 格（`startingHand` / `secondExtraCards` / `manaBonusSeat0` / `manaBonusSeat1`）。

### 5.2 🔴 **`version` 不 +1（4 保持 4）—— 理由**

R1 写「若加这格并参与重建，`version` 要 4 → 5」。本代理**没升**，理由按本文件头部那条规矩（「改结构**或改结算语义**就 +1，防的是『旧档被硬解成另一局』」）逐条对：

- **旧档（v4）在新代码下的行为没变**：`vars == null` ⇒ `ReplayVarsForReplay` **出声**后返回 `null` ⇒ `Begin` 拿 `pb.Vars`（= 与加这一格之前**逐字相同**）。它不是「同一格换语义」，而是**新增一格**（同 `tutorialStage` / `botSeatPlus2` / `mulliganPlus1` / `hostCardIds` 的先例）。
- **升到 5 的代价是「所有旧档一律拒播」**（`ReplayStore.Load` 对版本不等直接 `return null`）—— 为一条「旧档行为不变」的改动付这个代价是**反向伤害**。
- ⚠️ 若调度台口径是「宁可全拒也不许静默近似」，把 `ReplayRecord.version` 改成 5 即可（一处常量），**其余代码不用动**。

## 七 顺手发现（⛔ 不是本件范围，交调度台分流）

1. 🔴 **R1 的 `:1081` 施工口径会晚一步（已按更严的做）**：R1 写「在 `NetPendingBattle.FromStart(...)` 之后、第一条动作之前把 `varsJson` 装回 `Ctx.Vars`」。**不成立**：`deckSize` / `startingHand` / `warlordLifeChange` / `shouldReshuffle` / `maxLegendaries` 这些格子在 `RuleCore.NewBattle` 那一趟就被读掉（`Begin` 的 `var vars = pb.Vars` → `NewBattle(vars:)`）⇒ 开局之后再写 `Ctx.Vars` **装不回来**。⇒ 本件改走 `BeginFromPendingCore` 的 `varsOverride` 形参（在 `NewBattle` **之前**落 `_vars`）。建议把 R1 那一条就地订正。
2. 🔴 **ILSpy 丢常量族新增一例**（与「ILSpy 把实参常量反编译成 `default`」同族）：`ChooseCardMenu.Setup` 的 `SelectCard(_chooseCardUis[target])` 在 ILSpy 里是 `int index = default; … get_Item(index)` —— **不是「选 0 号」，是常量丢了**。`out_il2csharp` 才有 `[target]`。（本件若照 ILSpy 做 ⇒ 每一处回放永远预选第 0 张，且**看着像对的**。）
3. 🔴 **`isReplayPlayActive` 这个名字会骗人**：它不是「回放正在播放」，而是「**自动播放已暂停**」（`ClickPauseReplay ⇒ true` / `ClickPlayReplay ⇒ false`，开局 `= matchType==160`）。派单与判据里那句「`!isReplayPlayActive` ⇒ 起协程」**本身是对的**，但读名字很容易反。建议把这条写进 `判据/B97_R5…` 那一行。
4. 🟢 **「答案从来没丢过」**：`NetApply.Apply` 早就把 `m.picks` / `m.pickIds` 排回 `ctx.ChoosePicks` / `ChooseCardIds`（`NetApply.cs:131-132`）⇒ 回放**引擎侧一直是对的**，缺的只是**看得见的那块面板**。这也解释了为什么现有回放断言全绿而玩家在回放里看不到面板。
5. ⚠️ **`RecordAskForReplay` 的一个已知窄缝（如实记，未修）**：若某次出牌**被引擎拒了**（`code != OK` ⇒ 不 `RecAct`），那一处 ask 记的 `action` 下标就会**指到下一条真动作**上 ⇒ 回放时那一处面板会在错误的动作前弹。代价 = 表现层错一拍、不影响动作落地（答案本来就在 `picks` 里）。修法 = 被拒时把最后一条 ask 摘掉（要动 `LocalAct` 的拒绝支，本代理未动）。
6. ⚠️ **进攻卡/防御卡那两扇面板不走 `ShowAsk`**：我们 `_choosePanel.Open(_envPickViews, "选择进攻卡"/"选择防御卡", …)`（`:9318` / `:9359`）是**独立的一支**（原版同样走 `ChooseCardMenu.Setup`）。防御卡那扇默认 `defensiveCardPanelEnabled = false`（原版 `ShouldUseEnviromentalEffects` 恒 false ⇒ 一致）；进攻卡在回放里本来也不开（走 `OffensivePick` 伪动作）。⇒ **这一族没有受益于本件**，要照原版补需要单独一条（归 `战斗界面_HUD` 另立）。
