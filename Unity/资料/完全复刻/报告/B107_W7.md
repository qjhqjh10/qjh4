## 五、没查清 / 没覆盖的部分

1. **运行期未验证**（红线：本代理不跑 Unity）。`Resources.Load<TextAsset>("vfx_shared_durations")` 的端到端、以及自检宿主里 `SharedDurationTableRows == 7` 都**没有实跑过**；下次 Unity 批处理/自检时才第一次真正走这条链。
2. 新 json **没有 `.meta`**（白名单只有这个 json，不许我建 meta）⇒ 下次开 Unity 时由编辑器导入生成 guid。若导入失败，`EnsureSharedDurationsLoaded` 会 `LogWarning` 并退回手写表（= 出声，不静默），但**「导入成功」这件事今天没证据**。
3. `animinfo_lookup.json` **没有 `vd`（`vfxDelayTime`）字段** ⇒ 生成器**结构上无法**包含它；「该表 418 条 `vfxDelay` 全 0」是 `VfxMap:1865` 的既有结论，本代理**没有逐条复核**（要复核得回 `animinfo_0824.json` / bundle 的 `AnimInfo` 原件）。
4. **只收 7 个共享件**（与手写表同一集合），**没有**把 418 条全量烘进运行期表 —— 因为消费者 `AnimDurationOfPrefab` 的契约就是「共享件」，全量会让 `ChainDuration` 的第三档对更多件返回非 0，属于本批白名单外的时序行为变化（无法在本批验证）。若将来要全量，改 `SHARED` 清单/加参数即可，生成器本身与格式不用动。
5. 「哪些 prefab 算共享件」这份**清单**在生成器里（`SHARED`），不在数据里 —— 现读 `Resources/card_vfx_by_card.json` **没有** `generic.attackRangedByArmy` / `byEvent` 段（该段在施工单里被引作出处，实际盘上产物只有 `cards[]`），所以没有可用的数据侧来源去自动派生这 7 个名字。清单里每条都写了「对应哪张 CardAnim」，指错会**报错停写**。
6. 顺手观察（**不是我改出来的**）：`VfxMap.cs:4163` 那份类尾注释沿用旧说法「A 档落点含 `:1757`×2」，但现读 `资料/完全复刻/账/*.tsv` 里对 `VfxMap.cs` 的行号引用最大是 `:3450`、**没有 1757**（`特效动画.tsv` 机检也是漂移 0）⇒ 那句话可能已过期；本代理只在类尾新增、**未改**它。
