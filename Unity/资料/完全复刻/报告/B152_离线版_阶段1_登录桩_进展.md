## 三、现在卡在哪（精确到方法）

`login_states.tsv` 的逐跳（`LoginScreenManager.SetProgress` 探针）：

```
10 downloadingPlayerData → 65 processingLogin → 14 loadingAnalytics
→ 15 checkingVersion → 17 deserializingData → 20 processingPlayerData  ← 停在这里
```

`steps.tsv` 的调用轨迹（prefix enter / postfix exit / 状态机 finalizer）：

```
ProcessLoginResult  enter ... exit            ← 它只 kickoff、不 await（已知）
_ProceedSuccessfulLogin  MoveNext #1
  PlayerDataManager.FinishLogin         enter → exit   ✅
  （然后 Start<CheckNewVersion> 并 await 它的 Task）
  _CheckNewVersion → _CheckNewVersionSucceed → _UnpackPlayerData → _ProcessData
    _ProcessNewLogin  MoveNext #1 → #2（拿到 onUserConnected 响应）
      PlayerDataManager.ProcessNewLoginResult  enter → exit  ✅
    ← 之后【再无任何 MoveNext】，_ProcessData 的第 2 跳从未发生
```

**⇒ 卡点 = `PlayerDataManager.ProcessNewLogin` 返回的 Task 不再完成**（`_ProcessData` 在 `LoginManager._ProcessData_d__36__MoveNext.c:109` 的 `GetResult()` 就再没被唤醒）。

- **没有异常**：11 个状态机的 `MoveNext` 都挂了 finalizer，**一条 EXC 都没有**（`LoginManager__ProcessLoginResult.c:147-149` 那条「只拿 Task 不 await、异常被吞」的路子本轮没有触发）。
- **`AsyncInitialization` 从未被调用** ⇒ 所以 `InitializeLiveOps` / `GetObjects` 在最近几轮都没出现，`GetLoadedBundle` 也始终 0 条、`DownloadingStoreData(30)` 从未出现。
- **`UnityServicesManager.InitializeUnityServices` 打桩（`WF_OFFLINE_STUBS=1`）无效** —— 因为这条链根本没走到它。

### 下一步要验的三件事（按性价比排序）

1. **`ProcessNewLoginResult` 到底是不是真的「正常返回」** —— 给它加 `postfix` 记 `__result`/耗时；若它正常返回，就在 `_ProcessNewLogin.MoveNext` 的 postfix 里打 `state` 字段（`-2` = Task 已完成）。**这一步能一刀切开「卡在 ProcessNewLoginResult 内部」还是「卡在 continuation 调度」**。
2. 若 continuation 不跑：怀疑 **`TaskAwaiters.ForceAsync`（原版自己包的一层 awaiter）** 与 Harmony 改过的原生入口冲突 —— 可以对 `System.Threading.Tasks.TaskAwaiters.ForceAsync` 打点，看它给出的 awaiter 是否 `IsCompleted`。
3. 若 `ProcessNewLoginResult` 内部卡住：它末尾在 `grantedItems.Count > 0` 时会 `MenuActions.QueueAction`（我们给的是空数组，不该走），其余是纯字段拷贝；重点查 `PlayerDataManager__CurrentMillis` 与 `FUN_180c5bab0` 那一跳。
