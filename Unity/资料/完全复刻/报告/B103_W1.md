## ④ 没查清 / 未做的部分

1. **联机客机的 `LocalSeat` 没人设**（真缺口，判据已明）：`CardPlayedSignals.LocalSeat` 缺省 0 = 单机正确；
   联机客机（`BattleDriver.SetMySeat(1)`）需要一行 `CardPlayedSignals.LocalSeat = seat;` —— **`BattleDriver.cs` 不在本代理白名单**，没动。
   后果：客机侧 `IsPlayer` 恒 false ⇒ 那张挑战不推进（仅影响联机局；单机 0 影响）。
   📌 **2026-10-30 调度台已把这一行转给 `BattleDriver.cs` 的写手**（该文件本波归它）⇒ 本代理不再需要动那一处。
2. **`CardPlayedCount.Army` 没搬**：原版是个**计算属性**（`CardPlayedCount__get_Army.c`：`onlyCountCompanions ⇒ CardArmy 0x46`、
   `!anySpellType && spellType == 260 ⇒ 0x78`、`withTrait` 含 610 ⇒ `0x82`、否则 0）。本仓 `MissionChallenge` **基类没有 `Army` 这一位**
   ⇒ 无处 override。它**不参与** `OnCardPlayed` 那六道闸 ⇒ 不影响本条账的 A 判，但「挑战属于哪个阵营」那一格在我们这边**不存在**。
3. **`withTrait` 的类型收窄**：原版 `DefinedTrait[]`（枚举数字）→ 本仓 `string[]`（trait 名）。理由 = 我们的 `CardDef` 只有
   `HasDefaultTrait(string)`，数字→名字的映射只在**生成器**里、运行期没有那张表。⚠️ 数据在远端 `MissionsConfig` ⇒ 本机 0 实例，
   这条收窄**今天无法用真实配置验证**。
4. **`CardPlayedSignal` 的 `CurrentCard` 只搬了 `isCompanion` 一位**：原版那一格是 `CardScript`，六道闸里**只有** `onlyCountCompanions`
   读它（`+0x100`/`+0x64` = `isCompanion`）⇒ 其余五格一个都没读第二次。若将来有别的消费者，需要把它补回来。
5. **没跑 Unity**（红线）：`B103W1_Assert` 一条都没执行过。所有「闸对不对」的证据都是**静态逐句对 `.c`**，不是运行结果。
6. **`CardPlayedCount` 的数据在远端**（`MissionsConfig` / PlayFab Title Data `Challenges`）⇒ 建出来是**空表**，与原版同构但本机不会有实例。
