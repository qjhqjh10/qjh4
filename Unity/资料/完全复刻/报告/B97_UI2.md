### 为什么 #5 才是 `GetTargetInPos` 的对应物（判据链）

原版 `.c` 全文 271 行现读（`decomp_full/BattleManager__GetTargetInPos.c`）：

- `:104` **2D 支** = `Physics2D.GetRayIntersectionNonAlloc(ray, buf, **-1f**)`（`-1f` 由 `read_literal` 实读）⇒ **负距离恒 0 命中 = 死支**；它里面的**三档**（`:151` / `:173` / `:184` 的 `GetComponent` → `ActiveSkillDisplay` / `ActiveWarlordAbility` / 裸 `CardScript`）与 `:160/:163` 的 `+0x290 == 10 / 0xd ⇒ return null` **状态闸**全部**结构性不可达**。
- `:204-265` **真生效支** = `boardCamera.ScreenPointToRay(TouchInputManager.TouchPosition)` → `Physics.RaycastNonAlloc(方向×200f, hits, 1<<LayerMask.NameToLayer("BoardElements"))` → 取 `hits[0]`（`RaycastNonAlloc` **不排序**）→ `GetComponentInParent<CardScript>()` ⇒ 返回**棋盘**元素，打空 = `null`。
- **调用点只有一处**（三源现扫）：`BattleManager__Update.c:136` 每帧一次，结果存 `+0x440` ⇒ 它服务的就是「**这一帧指针压着棋盘上哪个元素**」。

我们这边三条消费者**全部走 `HitSlot`**（同一个口，没有第二份判据）：
`Update` ⑤ 记按下（`BattleDriver.cs:15067`）· `TickBoardHover`（`:34295`，每帧「指针压着哪张棋盘卡」→ 成对派发 `OnTouchEnter/Exit`）· `TryResolvePlayTarget`（`:8246`，等目标那一下点的是场上哪张）。

**结构差（如实标，不假装等价）**：本仓棋盘**没有 3D collider**（`BattleDriver.cs:16913` 已记「战场也没有 collider 射线」）⇒ 我们用「逐卡 `BoxCollider2D` 投影」（`CardHit`）代替物理射线；「不排序取首条」↔「取 `z` 最小」的逐位等价由战斗线 `新账-64`（`普查产出_1021/W61_战斗线_战将点击诊断.md`）钉着。**2D 支**是死支 ⇒ 三档与状态闸**按「死支照抄不实现」处理**，⛔ 不补一个原版到不了的行为。
