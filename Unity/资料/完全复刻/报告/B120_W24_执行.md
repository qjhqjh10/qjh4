## 一、`B120-A15`：原版提交不要求指针压在某一格

### 1.1 判据（亲读，⛔ 不照抄二手）

| 事实 | 出处 |
|---|---|
| 提交那一帧**只问两件事**：① 指针越过 `HandLimitArea` 那条线 ② 比 `pointerCursorStart` 抬够 `minMovementToPlayCard(+0x7C = 0.3)`；随后 `CanPlayCard(...)` 一过就 `MoveIntoFieldFromHand()`，**全段没有任何「指针压在某格」的比较** | `decomp_full/BattleManager__Update.c:249-288`（`MoveIntoFieldFromHand` 在 `:260`）；逐行可读版 `cpp2il/out_il2csharp/Assembly-CSharp/BattleManager.cs:25720-25864`（`:25733`） |
| `CanPlayCard` 对**单位**只查「还有没有空位」（`MinionManager.IsAvailableSlot` 为假 ⇒ `NotEnoughRoom`），**格号不参与判定** | `decomp_full/BattleManager__CanPlayCard.c:104-120` |
| 落格是**另一跳**：候选集 = 每侧「最内空格 + 内圈已占格」（满侧整条剔除、不含督军位）· **2D 欧氏屏幕距离** · **无任何容差** ⇒ 只要该侧有空格，指针在**任何位置**都返回一个格 | `cpp2il/out_il2csharp/Assembly-CSharp/MinionManager.cs:321-390` · `decomp_full/MinionManager__GetClosestAvailableSlot.c:35-145`（`B120-W21` 已逐句核过） |

### 1.2 改前（我们的形状）

- 3D 产品路径（`ArenaSlots.TryResolveSlot`）在 `B120-W21` 之后**本来就是最近格、无容差** ⇒ 那一半没问题。
- **2D 兜底档**（`BoardLayout.TryResolveSlot` 没有 3D 相机时那一支）仍带着两道**我们自己挑的**容差
  （`snapToleranceY = 0.09` / `snapTolerance = 0.036`，标着 `🔶 自己设计`）⇒ 指针抬到棋盘上方空白处
  （真机很常见：往中间一甩）**解不出格** ⇒ `DropReject` 判 `MissedSlot` ⇒ **既不提交、也不亮落点指示**。
- 另有一处**结构性**限制：`TryCommitWhileHolding` 的 `dropOk` 恒来自 `ResolveDrop`，而它没有「最近格」这一档。

### 1.3 改后（做法）

只加**一档 opt-in**，默认档一个字不动：

1. `BoardLayout.TryResolveSlot(worldPos, out slot, occupiedLeft, occupiedRight, **bool allowNearest = false**)`
   - `allowNearest == true` 时（2D 档）：**跳过 `snapToleranceY` 的 y 带**、按 `ArenaSlots.IsCandidate(occupiedLeft, occupiedRight)`
     收窄候选（**复用 W21 那一份**，不另写）、**不做 `best <= snapTolerance` 截断**；
   - 2D 九格同在 `lineY` 一行 ⇒ 只比 `|dx|` **就是** 2D 欧氏最近（`dy` 是常数）；
   - **候选集为空（两侧都满）⇒ 返回 false**（⛔ 不当成可出牌）；
   - `allowNearest == false`（默认）⇒ 逐位等同改前。
2. `CardInteraction.DropReject(..., bool allowNearest = false)` / `ResolveDrop(..., bool allowNearest = false)`
   —— 只把这一档**直通**给 `board.TryResolveSlot(...)`（单位卡那一支；战术卡那一支**不接**）。
3. **只有提交路径传 `true`**：`UpdateDrag`（`ResolveDrop`）与 `Release`（`DropReject`）。
   `ExplainDrop` / `DropRejectKindForTest` / `CardBaseDemo` 这些走**默认档** ⇒ 判据不受影响。

### 1.4 影响面 / 副作用（如实写）

- **`PlayCommitGate` 的两道门一条没放宽**：`allowNearest` 只影响「能不能解出一个格」，
  「抬高 0.3 原版世界单位」与「越过手牌限位线」仍在 `TryCommitWhileHolding` / `Release` 里逐字判。
- **取消路径不受影响**：指针留在手牌带里时 `PlayCommitGate` 不成立 ⇒ 仍走「牌回手 + `OnReturned`」（断言 D 段）。
- **引擎仍然说了算**：解出最近格之后照旧走 `CanDropAtSlot` → `RuleCore.CanPlayCard`（费用 / 回合 / 两侧满 / 教程…）。
- **可观测的行为变化（只这一档）**：2D 夹具（`CardBaseDemo` 那类真拖拽）里，把单位牌拖到棋盘上方
  **空白处**再松手 —— 以前回弹，现在会打到最近候选格。这正是原版行为。
- **3D 产品路径零变化**（它本来就走 `ArenaSlots.TryResolveSlot`，不受 `allowNearest` 影响）。
- **落点底片**：越过手牌限位线之后会按最近候选格亮起（原版 `ReassembleMinionsWhilePlayingUnit` 就是每帧指一格）。

### 1.5 没做的（如实）

- **`LandingSlot` 那一跳没变**：解出来的「最近候选格」是**请求格**，引擎 `BoardSlots.Resolve` 还会按连续棋盘
  插入 / 换侧挪一次；消费方走 `LandingSlot`，两处口径没合并（属于 `B120-W21` 已有结论的范围）。
- **3D 相机下的候选集 `occupiedLeft/Right`**：产品里由 `SideCount` 现数（`RuleEngine.BoardSlots.CountOnSide`），
  本件**没改**它；夹具没有驱动 ⇒ 恒 −1（两侧按皆空），所以「两侧都满 ⇒ 不出牌」那一档只能在 API 层断言（见 B 段）。
