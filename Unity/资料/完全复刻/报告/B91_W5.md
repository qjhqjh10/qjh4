### §1·1 步骤 6 里"做了什么"的逐句对位（判据 = 反汇编）

原版 `BoosterShopTab.OnOpen`（`decomp_full/BoosterShopTab__OnOpen.c` 全文）=
`base.OnOpen()` ＋ `ShopTab.RefreshOffers()` ＋ `if (Context is OpenData) TryOpenContainerArmy(Context)`。

我们这一侧：
- `RefreshOffers()` = `Setup()`（既有口径）⇒ 在 `OnOpen` 里对 crates 页也调 `Setup()`（`ShopTabPage.cs:1009`）。
- `TryOpenContainerArmy` 的四步**逐句照 `.c`**：① `army == Neutral` ⇒ return；② 逐件比阵营；③ 命中的开**那件报价的窗口**；④ **把 `context.army` 消费成 0**（所以再切回本页不会重复弹）。
- ⚠️ **为什么它挂在 `Setup()` 末尾、还带 `_win.CurrentTab == ShopCrates` 那道闸**：`ShopWindow.BuildPages()` 会给**所有**页各跑一次 `Setup()`；不带闸的话，窗口一打开就会弹一个没人要的卡包窗。原版没有这个问题（它的 `OnOpen` 只在切到该页时跑）。

### §1·2 三处"我们挑的替代"（如实标）

1. **"开容器" = `OpenBoosterInfo(idx)`，不是 `OpenBoosterPack(idx)`。**
   判据：`ShopOfferContainer__OpenContainer.c` 全文 = `GetComponentReference(…, 0xc)` → `WindowsManager.OpenWindow(…)`（**开窗**），只有那条 `CanXxx` 为假才落 `base.OnClick()` 的购买路；而 `Shell/BoosterInfoPopup.cs` 文件头早已认定**它就是 `ShopOfferContainer.OpenContainer` 那一跳的等价物**。
   ⛔ `OpenBoosterPack` 是"买完拆包"，原版在**服务端回执之后**。
2. **"每件的阵营" = 主图名反查 `BoosterPackOpenWindow.ArmyOfArt`**（全工程唯一那张 商品主图 → 阵营 的表）。
   原版比的是 `ObtainableItem.cardArmy`（服务端 SO 给），本机没有那批 SO ⇒ ⛔ 没另写第二张表（两处写同一条规则 = 迟早不一致）。
3. **"落哪一页" = `OpenData.army != Neutral`。**
   原版这根信号走 `GameWindowWithTabsOptions.startTab = TypeReference(typeof(BoosterShopTab))`（`RankedDeckSelector.OnGoToStoreButtonClick`，ILSpy 源码级现读）；本地**没有 options 资产** ⇒ 用 army 提示顶它。已在 `OpenData` 的 doc 里标成"我们的换算"。

### §1·3 `forcedOpened`

原版这个字段在**全量产物里只有声明 + 默认值**（`ShopWindow.cs:17` 是唯一命中；`grep forcedOpened` 全 `decomp_full`/`out_cpp2il_*` **0 个读写点**，唯一构造点 `RankedDeckSelector` 只赋 `army`）。

## §五 · 顺手发现

1. 🔴 **`WindowsManager.OpenByRef` 会把它喂进去的 `data` 清掉**（`Shell/WindowsManager.cs:940` ＝ `wm.OpenWindow(win, **null**, closeAll)` → `TryOpen(null)` → `SetupData(null)` ⇒ 基类 `Data = null`）。
   ⇒ 任何"建窗时塞一份上下文、开窗时读它"的窗，**都不能只靠 `GameWindow.Data`**（本仓开商店的三条路全是 `OpenByRef`：`ShellScene` 窗口表 / `LiveOpsEventWindow.OnGoToStoreButtonClick` / `MainMenuRuntime`）。
   本批的处理 = `Create(mgr, data)` 里**另存一份 `_openData`**（`ShopWindow.cs:325`），`Context` 取 `_openData ?? (Data as OpenData)`（`:322`）。⚠️ **这条对将来任何"给窗户带上下文"的活都成立**，建议进交接的"坑"。
2. 🔴 **`Booster Shop Tab` 这个 prefab 本地根本不存在**（`assets_full` 按名 `find` + 内容 `grep` **双向 0 命中**）。
   真正的机制（现读）：

   - `工具/menu_dump.py bundle_menus_assets_all "Shop Menu Variant" --depth 5 --no-sprite` 现读：`Tabs` 下唯一序列化的就是 **`Shop Tab`**（脚本 `ShopTab`），而且**它的 `daily shop header` = `167.2,70.9 → 1920.0,155.9`（1752.83×85）—— 与我们的 `ShopTabPage.Header`（167.17,70.94 → 1920.00,155.94）逐字相同**；`Line` = 167.2,150.9→1920,160.9 也与我们那个 INACT 位一致；

   ⇒ **E7 §三 第 7 步可以关闭**：不是"缺几何判据"，而是"本页没有独立 prefab，几何 = 共用 `Shop Tab`"，而且是**我们已经在用的那一套常量**（不需要动任何坐标）。

## §七 · 🔴 新坑：`WindowsManager.OpenByRef` 会清空 `GameWindow.Data`（建议进 CLAUDE.md 坑表）

**事实（现读，不是推断）**
`Shell/WindowsManager.cs:940` 是 `OpenByRef` 的最后一句：
```csharp
wm.OpenWindow(win, null, closeAll);      // 注意：data 位**恒传 null**
```
而 `OpenWindow(win, data)` → `win.TryOpen(data)` → `GameWindow.SetupData(data)`（`Shell/GameWindow.cs:483/585`）会执行 `Data = data`。
⇒ **任何"建窗时把上下文塞进去、开窗时再读 `GameWindow.Data`"的写法，在 `OpenByRef` 这条路上一律读到 `null`** —— 而且**没有任何报错**（`SetupData` 是纯字段写入）。

**为什么是本仓的普遍形状，而不是商店特例**
开窗的三条生产路全是 `OpenByRef`（`Shell/WindowsManager.cs:734` 那份 `_openByRef` 缓存）：
1. `Editor/ShellScene.cs:7580` 的窗口表（`("ShopWindow", m => ShopWindow.Create(m))` 等）
2. `Shell/LiveOpsEventWindow.cs:2112`（`OnGoToStoreButtonClick`）
3. `Shell/MainMenuRuntime.cs` 的 8 条入口（含 `RefShop`）

**本批的处置（`Shell/ShopWindow.cs:322/325/332`）**
```csharp
public OpenData Context { get { return _openData ?? (Data as OpenData); } }
OpenData _openData;                                   // Create(mgr, data) 里写
public static ShopWindow Create(WindowsManager mgr, OpenData data)
{ var w = Create(mgr); w.SetupData(data); w._openData = data; /* … */ return w; }
```
- `SetupData(data)` 照原版那条路写 `Data`（对走 `OpenWindow(win, data)` 的调用方仍然有效）；
- `_openData` 是**抗清空的那一份**，`Context` 两个口取一个。
- ⚠️ 副作用与边界：`_openData` 只在这个实例上有效。因为本仓**关窗后 `OpenByRef` 会新建一扇**（`StillOpen` 判假 ⇒ `_openByRef.Remove` + `create(wm)`），所以不存在"上一次的上下文漏到下一次"；而"还开着就直接复用"那一支不会重跑 `Open()`（`TryOpen` 的 `Open` 支早退）⇒ 也不会重读它。

**给将来写"带上下文开窗"的一句话口径**
> 窗要读开窗上下文时，**别只读 `GameWindow.Data`** —— `OpenByRef` 会把它清成 null。要么自己留一份（本批做法），要么调用方改走 `WindowsManager.OpenWindow(win, data)`（那就不是"按引用复用"那条路了）。
