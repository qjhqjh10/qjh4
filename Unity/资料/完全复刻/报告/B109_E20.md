## 4 没覆盖 / 没查清

### 4·1 🔴 真数据上触发不到（**本批最重要的发现**）

`RewardWindow.BuildItem` 的守卫是 `res.Drawer ∈ {CardDrawer, CardAlternateArtDrawer}`，而今天这条**在真数据上恒不成立**：

1. `ItemDrawer.PickDrawer` 只在 `item.Type` 有值时走真表（`ItemTypeSets`）；`ItemTypeOf` 的另一半 `TypeOfKind` **只认 `Wildcard`**。
2. `ItemDrawer.Spec(targetId, art, label)` 的 `Type` **只从 `IdTypes` 取**，而 `IdTypes` 现读**只有 4 条**（`Booster Pack Ultramarines` / `Booster Pack Legendary Ultramarines` / `DT Ultramarines All` / `DT Ultramarines All R2+`）—— **不含任何卡 id**。
3. 战役奖励里**有 15 个 id 是真卡 id**（现比 `cards_engine.json` 的 1,129 个 id）：
   `UM2 · UM3 · UM8 · UM13 · UM17 · UM18 · UM22 · UM24 · UM27 · UM28 · UM34 · UM37 · UM39 · UM44 · UM55`
   （`Shell/CampaignData.cs:426-…` 那 89 条奖励里）。这些 id 既不在 `CampaignData.ItemIcon`、也不是 `Resources/Art/ui_menu|ui_deck|ui/` 下的图名
   ⇒ `ArtOf(id) == null` ⇒ `Kind = Unknown` ⇒ **`PickDrawer` 给 `DrawerPlaceholder`** ⇒ 领奖窗里这 15 格画的是**占位板**。

⇒ 两条结论：
- **J1 这一跳要真跑，必须先让卡奖励的 `ItemSpec.Type = "RawCardScript"`（+ `CardId`）** —— 落点在 `Shell/ItemDrawer*.cs`（`Spec()` 或 `PickDrawer` 的判据层），**不在本代理白名单**（那一族归 `B109_E11`）。
  建议补丁（供调度台派活，⛔ 本代理未改）：
  ```csharp
  // Shell/ItemDrawer.cs 的 Spec(...) 末尾（或 BuildItem 在建完 item 之后）
  var cardDef = CollectionData.Card(s.Id);            // 卡池认得出 ⇒ 原版类型就是 RawCardScript
  if (cardDef != null) { s.Type = "RawCardScript"; s.CardId = cardDef.Id; }
  ```
  ⚠️ 这条补丁会把那 15 格从**占位板**换成**真卡面**（严格更接近原版），但**是可见变化**：现有断言里凡按 `IconPlaceholder` / 占位板取件的地方（如 `Editor/RewardsScene.cs:6444 / 7532-7543 / 10276` 那几处三级兜底）要复跑确认；本代理**不跑 Unity**，不下结论。
- 在这一条补上之前，本批 J1 的价值 = **把形状先接对**（等 `Type` 一填就自动生效），**而不是**「玩家今天能看到角标」。
