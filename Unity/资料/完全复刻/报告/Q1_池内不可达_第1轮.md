## ② 判据（怎么证的，四层证据链）

1. **枚举先行**：全库只有 `CardEffect` 一个类声明了 `BuffType` 字段（`grep -rn "public BuffType"` ⇒ 1 处 = `CardEffect.cs:28`）。
   ⇒ 产出 `buffType` 只有两条路：**SO 数据里一条 `CardEffect`** / **代码 `new CardEffect` 后写 `buffType`**。两条都穷举了。
2. **L1 SO 全字段**：`cards_raw.json` 154 个叶子键逐键交叉统计（不只看 `buffType`）：`newRace` / `daemonHostType` /
   `handBuff.cardEffect.buffType` / 四个 `*ValueOptions` / `enchantment` 指针 / `trigger` × `chosenAbility` / `hasAlternativeAbility`。
3. **L2 代码构造点全枚举**：`.c` 里靠 `CardEffect` 类的类型指针 `DAT_1842d44f8` 定位，**14 个分配点**，
   逐个看写不写 `buffType` ⇒ 能产出的只有 **{1, 3, 8, 11, 12, 25}**（+ 拷贝）。另用「全库 4 字节写 `+0x38`」交叉校验，排除漏网。
4. **L3 读取点**：10 个文件里 `BuffType.<名字>` 逐处行号；**读取点 = 0 的档**（5 / 26 / 30）连「有人塞数据就有行为」都不成立。
5. **L4 其它资产**：`assets_full`（90 bundle / ~24.7 万文件）全树 grep `"buffType"` ⇒ **0 文件**（sanity 用 `"m_Name"` 验过 grep 没失效）。

**怎么判「②可达但走别的字段」**：本轮只命中一例 —— **11**。它的数据入口不是 `buffType` 列，而是
`cardAbilities[].trigger == 240` **且** `abilityLogic[].chosenAbility == 30`（32 条），代码在
`AbilityLogic__PlayAbility.c:1236-1254` 里**现造**一条 `buffType = 0xb` 的 effect 去清「同源 extrinsic」。

## ④ 没查清（如实，逐条给"还差什么"）

1. **`newRace` 到底有没有读者** —— 证据只是「ilspy 里除声明行 0 命中」。若那段方法体没反编译出来，读者可能藏在里面。
   **要一锤定音** = 对 `CardEffect+newRace` 的偏移做 VA 反汇编扫读（本轮只读、没做）。
   影响：6 / 30 的「消费端也缺」从「高」降到「高但非绝对」；**不影响「无数据入口」这一层**。
2. **`assets_full` 的 905 个导出失败对象**没逐个看（只知分布：`resources.assets` 616 / `sharedassets0` 182 / `level0` 73）。
   若其中有带 `CardEffect` 的 SO，会推翻「L4 = 0」。风险低（战场与 menus `fail=0`）。
3. **远端 CCD 的卡数据**本地没有 ⇒ 13 档都可能**在历史/未来版本**被用过。本轮结论的时限 = 「当前 build 的本地快照」。
4. **`11` 的实际触发效果没跑运行时**（只读代理不跑 Unity）：32 条入口里哪些**目标身上真会有同源 extrinsic**、清掉之后数值变不变，
   要一条 `ruleprobe` 差分实验才能钉住观测量。
5. **`changeAbilityCost` 的读取端 `33 C0 C3`** 是引我们既有记录（`EffectResolver.cs:906-908`），本轮**没有重新反汇编复核**那个 RVA。
