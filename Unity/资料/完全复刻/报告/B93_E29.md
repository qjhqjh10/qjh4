### 2·2 已落地的接法（全部在 `ShowEventArmiesPanel`，`MenuScroll.cs` 零改动）

```csharp
_scroll = new MenuScroll(new PxRect(ScrollL, ScrollT, ScrollR, ScrollB), ScrollL, ScrollL)
{
    Vertical = false,          // 原版 m_Horizontal = 1 / m_Vertical = 0（prefab 现读）
    Elastic    = true,         // 原版 m_MovementType = 1 (Elastic)
    Owner      = _root.gameObject,   // ⚠️ 必须非空（PruneScrolls 把 Owner==null 当死条目）
    ClipNode   = _viewport,          // ⚠️ 必须宿主显式给（沿 Owner 往上找恒找不到）
};
_scroll.OnChanged = () => { if (!_rebuilding) RebuildItems(); };
if (Application.isPlaying) PointerLayer.RegisterScroll(_scroll);
```
- 可滚范围 = `[ScrollL, ScrollL + n × 136.5]`（13 个 ⇒ `37.77..1812.27`）；视口 `37.77..642.99` ⇒ `MaxOffset = 1169.28`。
- 内容坐标 → 屏幕坐标走 `MenuScroll.Shift`；滚出视口的格子由 `ViewportClip`（原版 `RectMask2D`）裁掉。
- **⛔ 没有为了让 13 颗摆得下去缩格/改几何**（那是伪造布局）。
- 只在 Play 里 `RegisterScroll`：`PointerLayer.Instance` 的惰性现建在批处理里会**留下一个游离 GameObject**，而 `ShellScene.Run` 一族会 `SaveScene()` ⇒ 那个游离物会被写进场景。批处理没有指针输入，登记无意义；自检直调 `Scroll.ScrollBy(...)` 不受影响。
