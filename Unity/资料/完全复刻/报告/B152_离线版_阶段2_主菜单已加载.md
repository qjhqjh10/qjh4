## 一、破掉卡点的三件事（按贡献排序）

### 1. 找出**真因**：3 个 bundle 本来就登记在**已关服的远端 CCD** 上

用 `OperationException` 的 `InnerException` 链挖到底：

```
ChainOperation failed
 └ GroupOperation failed because one of its dependencies failed
    └ RemoteProviderException: Unable to load asset bundle from
       https://d03469d2-…client-api.unity3dusercontent.com/…?path=/allcards_assets_all.bundle
       → HTTP 400
```

本地 `StandaloneWindows64/` 里根本没有 `allcards_assets_all.bundle`。远端组共 **3 个**：
`allcards_assets_all` · `alternateartstyles_assets_all` · `localization_assets_all`
（判据 → [`B152_HHL_自建机制_对卡点的启示.md`](B152_HHL_自建机制_对卡点的启示.md) §4）。

### 2. 三个包从「关服前存档」的 Unity 缓存里补齐

| 包 | 来源（`D:/2/关服前存档/新建文件夹/Everguild_Warpforge/<hash>/<hash>/__data`） | 大小 |
|---|---|---|
| `allcards_assets_all.bundle` | `54bdb7b1…/ea8bca4f…` | 531,962 B |
| `alternateartstyles_assets_all.bundle` | `7416b641…/8657f84d…` | 69,582 B |
| `localization_assets_all.bundle` | `c9187397…/dca1724a…` | 10,764,942 B |

三个文件都是标准 `UnityFS` 包（Unity 6000.2.6f2），直接拷进
`E:/warpforge/game/Warpforge_Data/StreamingAssets/aa/StandaloneWindows64/` 即可。

### 3. `Addressables.InternalIdTransformFunc` 把远端 URL 重写到本地文件

catalog 把这三个包登记成 CCD 地址，光放本地文件没用 ⇒ 用 Addressables 官方钩子改地址：

```
https://d03469d2-…/entry_by_path/content/?path=/allcards_assets_all.bundle
  → E:/warpforge/game/Warpforge_Data/StreamingAssets/aa/StandaloneWindows64/allcards_assets_all.bundle
```

⚠️ **两个坑**（都实测踩过）：
- 属性类型是 **Il2Cpp 的 `Func<IResourceLocation,string>`**，不是 .NET 委托 ⇒ 不能直接写 lambda；
  `DelegateSupport.ConvertDelegate` 还要求形参**原生类型指针完全一致**（报 `IResourceLocation != Il2CppObjectBase`）。
  **正解 = 运行期用表达式树造委托**：形参类型取 `属性类型.GetGenericArguments()[0]`，
  body 读 `InternalId` 再调我们的 `RewriteId(string)`（见 `ModMain.InstallIdTransform`）。
- **⛔ 不要**在 csproj 里写 `Unity.Addressables` / `Unity.ResourceManager` 的编译期引用 —— 实测会让启动序列停住，
  连 `PlayerDataManager` 都不创建。全走反射。
- 钩子要**推迟到 t≥8s** 再装（`WF_OFFLINE_XFORM=1` 控制）。

## 三、现在的**唯一阻塞**：主菜单弹「无法初始化服务 Game UI」

- 文案键 = **`CustomErrors/FailedToInitializeServices`**（`官方本地化_en+zh-CN.json` 的 `terms`，`{0}` 被填成 `Game UI`）
- 场景本身是好的：`scene=MainMenu Warpforge` 稳定，顶栏（Player Name / 邮件 / 设置齿轮）都在渲染
- 我们的 `ErrorPopupWindowController.ShowErrorMessage` 钩子**没命中**（`errs.tsv` 空）⇒ 该弹窗走的是别的入口，下轮要换钩法
- 最可能的来源：`InitializeLiveOps` 我们返回的是**空对象 `{}`**，而它本该返回 Handlers/Configs 那一大坨真实配置
  （请求体里点名 10 个 Handler + 22 个 Config）。「Game UI」很可能就是其中某个 handler/service 的显示名。

### 下一轮三条（按性价比）

1. **换钩法抓到调用栈**：挂 `ErrorPopupWindowController` 的其他重载 / `CustomDebug.LogError` / `ShowErrorMessage(int,…)`，
   把「谁在报 Game UI」的栈打出来（不要再靠猜）。
2. **把 `InitializeLiveOps` 的 `FunctionResult` 按真实形状补出来**：Handlers 10 个 + Configs 22 个，
   形状判据见 `判据/B152_判据_PlayFab_DTO形状.md` 与 `decomp_full/PlayerDataManager._InitializeLiveOpsAndConfig_d__527__MoveNext.c`。
3. 若 ② 太大，先把「Game UI」这个 service 的初始化打了桩（返回成功），确认菜单其余部分（对战/收藏/商店入口）能不能用。

## 六、「无法初始化服务 Game UI」已定位到**具体方法**（2026-11-06 13:20）

### 6·1 文案是怎么拼出来的

`SceneInitializer.OnInitializableError(IBaseInitializable initializable, Exception e)`
—— 它取 `initializable.name`（**GameObject 名**）去填 `CustomErrors/FailedToInitializeServices` 的 `{0}`。
所以「Game UI」是主菜单场景里那个 GameObject 的名字，不是服务枚举。

**钩住它就能直接拿到异常本体**（`ModMain.PostInitError`，`errs.tsv` 的 `INIT-ERR` 行）。

### 6·2 三层因果链（逐条实测）

```
① 登录 payload 里没有 FeatureConfig
   └ ConfigManager.Unpack(字典) 的唯一调用方 = PlayerDataManager._UnpackUserInfo_d__522__MoveNext
② LiveOpsManager.BuildHandler 用 FeatureConfig.CheckFeature(key) 决定建不建 handler
   └ 没有 FeatureConfig ⇒ handler 不建 ⇒ LiveOpsManager.GetHandler<T>() 返回 null
③ 菜单初始化时 GeneralMenuController.Initialize() / AchievementsManager.Initialize()
   都在 GetHandler 之后解引用 ⇒ NullReferenceException ⇒ SceneInitializer 弹「无法初始化服务 Game UI」
```

### 6·3 已经验证有效的修复

把 `FeatureConfig` 放进**登录片段的 `InfoResultPayload.TitleData`**（值是 JSON **文本**）：

```json
{"features":[{"key":"ParentEvents","strategy":0,"enabled":true}, …]}
```
（10 个 key = 客户端请求里 Handlers 数组的原名：ParentEvents / Shops / GameModes / Inbox / Missions /
Forge / Campaign / Rewards / ScoringEvent / RankedScoreBoost）

**效果**：`GetHandler` 从 `NULL` 变成 **`ok`**（实测 `ParentEventHandler ok` · `RewardEventHandler ok` · `CampaignHandler ok`）。
脚本：`server/tools/add_feature_config.py`。

### 6·4 现在剩下的两条 NRE（下一轮就从这儿接）

| 报错 | 判断 |
|---|---|
| `ResourcesBarController.GetCounter(GameCurrency)` | 顶栏货币条的取数；**补 `UserVirtualCurrency` 已试过、无效** ⇒ 不是货币字典缺失，要在 `GetCounter` 方法体里查那个空引用（很可能是某个 UI 子节点/计数器对象没建出来） |
| `AchievementsManager.Initialize()` | 成就系统初始化；`onUserConnected` 我们给的是 `Achievements: {}`，可能它需要非空条目或另一份成就定义 |

> ⚠️ 这两条**不再是「服务不存在」**，而是**具体组件自己的初始化**。它们仍然会触发同一个弹窗（同一句文案），
> 所以「Game UI」看起来没变，但底层已经从「handler 全空」推进到「两个组件各自缺数据」。

## 七、「Game UI」**已解决**（2026-11-06 13:42 实测）

### 结果

- `errs.tsv` 里 **`INIT-ERR` = 0 条**（此前每次都有 2 条 NRE）
- 画面：**错误弹窗消失**，主菜单顶栏正常渲染 —— 头像框 · `Player Name` · 邮件按钮 · 货币条 · 设置齿轮
- 截图：`d:/4/_tmp_view/shots/1106_offline/MENU_OK.png`

### 三处修法（缺一不可）

| # | 修什么 | 怎么修 | 判据 |
|---|---|---|---|
| 1 | `LiveOpsManager.GetHandler<T>()` 返回 null | 把 **`FeatureConfig` 放进登录片段的 `InfoResultPayload.TitleData`**（值 = JSON 文本，`features[].key` 用客户端请求里 Handlers 的原名） | `ConfigManager.Unpack` 唯一调用方 = `_UnpackUserInfo`；`BuildHandler` 用 `CheckFeature(key)` 决定建不建 |
| 2 | `ResourcesBarController.GetCounter` NRE | 打桩 `CurrencyExtensions.GetOwnedCount(InventoryManager, GameCurrency)` → gold=2000 / crystals=500 / 其余 0（返回类型是 **Int32**，用 `ref int __result`） | `GetCounter` 内部 `InventoryManager.Instance` 为 null 时 `GetOwnedCount` 直接 throw |
| 3 | `AchievementsManager.Initialize` NRE | 打桩整段跳过（它要读 `AssetReferenceTyped<AchievementsList>` + 玩家成就存档） | 成就不是进菜单的必要项，离线版先跳过 |

脚本/开关：`server/tools/add_feature_config.py` · `Stubs`（`WF_OFFLINE_STUBS=1` 时自动装）。

### 还剩什么

- **菜单主体还是空的**（只有顶栏）：模式卡/按钮要 `GameModesConfig` 等 LiveOps 配置，
  我们目前只给了 `FeatureConfig` ⇒ 下一步按 `InitializeLiveOps` 请求里点名的 **22 个 Config** 逐个补
  （`GameModesConfig` 最关键，它决定主菜单那几张大模式卡）。
- **游戏自己的转场仍不稳**：`TryCompleteLogin → Simple Transition` 之后，游戏自己的主菜单加载**有时不完成**
  （手动 `Addressables.LoadSceneAsync("MainMenu Warpforge")` 100% 成功；
  两者同时跑会**把主线程卡死**（窗口标题变 `(未响应)`）⇒ 调试时**别同时用 `WF_OFFLINE_LOADMENU`**）。
