## §1 …… #2（β）：同档早退不该跳过「应用所选打法」

### 原版判据（亲读，不是推断）

1. **原版确实有这条早退** —— `decomp_full/UnitOnBoardAttackTypeSelector__AttackButtonClick.c:28-30`：

   ```c
   if (*(int *)(lVar2 + 0x120) == param_2) { return; }
   ```
   （`+0x120` = `card.attackType` = 我们的 `UnitState.CurrentAttackType`）
   ⇒ 早退之后 `ChangeAttackType` / `HighlightSelectedAttackTypeButtons` / `SetAttackType` / `ShowPotentialTargets` **全都不跑**。
   ⇒ **这条早退是复刻，不能删**（删了会把「同档再点一下」变成「重亮一遍目标 + 再响一次选中音」）。

2. **早退跳过 `ChangeAttackType` 本来就是空操作** —— `decomp_full/CardScript__ChangeAttackType.c:14` 自带同一条守卫：
   `if (*(int *)(param_1 + 0x120) != iVar5) { … }`（同值直接 return）。

3. 🔑 **原版的「这张卡自己的打法底光」是状态派生的，不是「点过才亮」**：
   - `decomp_full/CardScript__CardSetup.c:263-267`：**部署那一刻**就写 `+0x120 = (CurrentMelee < CurrentRange) + 1`，**紧接着**调 `BasicCardUI__AttackTypeChanged(+0x290, iVar9)`；
   - `decomp_full/BasicCardUI__AttackTypeChanged.c:22` → 逐颗 `HighlightAttackType__HighlightIfNeeded`（`HighlightAttackType__HighlightIfNeeded.c:47-61`：`param_2 == 自己那格 ⇒ SetActive(true) + DOScale(×倍数)`）。
   ⇒ 同档点一下时，底光**本来就已经亮着**；早退什么都不做是**对的**。

4. **我们错在哪**：展示层 `OwnAttackTypeOf` 读的是 `u.LastAttackType`（我们自己的镜像字段，部署初值 0），而镜像**只在早退之后**那一行（`:15691`）写 ⇒ 同档时镜像永远是 0 ⇒ **底光永远不亮**。

`BattleDriver.cs:15646` 由


## §4 …… #4（α）：3 位数样本已失效

- **根因（一个）**：`_upEdge` 是「用掉就没了」的一次性沿（`BattleDriver.cs:33051-33056`）。

- **修法**：进本段时**显式再 poll 一次**（`BattleScene.cs:34594` 同物理行追加 `wb4.PollInputEdgesForTest();`）。
  `PollInputEdges` 里 `_upEdge = !held && _held && …` 是**赋值**不是或等 ⇒ held 一直 false ⇒ 当场清成 false；且不走 `LogClickBeat`（不会给 `ClickLog` 多记一笔）。
- **补一条硬前提（诊断 §4②）**：`sel4.TickForTest(0.11f, …)` 那一行同物理行加了 `Check(sel4.Visible, …)` ——
  否则「安全窗走完 ⇒ 可以发」这条在 `Visible == false` 时**恒真**（空转绿），本轮就是用它 `safeLeft=0.000s` 蒙过去的。
- **不改产品**：诊断 §4③ 提的「产品侧 `_command` 起手非 None 后，松手即结算/取消是否该在『没有真按下』时触发」**没动** —— 原版 `Update.c` 的 `case 6` 就是「抬起 ⇒ 非法目标 ⇒ `CancelAttack`」，我们这条与它同形；问题在**夹具伪造了一条没发生过的松手**。
