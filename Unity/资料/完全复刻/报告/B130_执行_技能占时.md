# B130 执行 · 技能事件占时只算「占队列」的拍（节奏级差异，`B129` 审计 #11 ★）

> 一句话：**原版只有 `waitAnimToApplyEffect = 1` 的拍才占动作队列**（`w = 0` 的拍协程一开头就
> `FinishResolvingAction`，动画转后台继续播）⇒ 我们把 93 张卡里的 **13 张**从「Σ全部拍」改成
> 「Σ仅 `w=1` 的拍」，其余 80 张逐值不变。

## 一、判据（第一权威 = 反编译方法体，逐行读过）

`d:/2/tools/decomp_full/BattleManager._ResolveAnim_d__466__MoveNext.c`

| 行 | 内容 | 语义 |
|---|---|---|
| `:63-66` | `if (*(char *)(param_1 + 0xc0) == '\0') { CustomDebug__Log(…); FinishResolvingAction(lVar1, *(param_1+0x28), 0, 0); }` | **`waitForAnim == 0` ⇒ 协程一开头就把动作队列放行**；之后才 `WaitForSeconds(startDelay)` → `DelayedVFXPlay` → `WaitForSeconds(GetAnimDuration)`，但那时**已经在后台跑**，不挡下一条 |
| `:200-211` | `WaitForSeconds(AnimInfo.GetAnimDuration(animInfo))` → state 5；`:191-194` 回 `if (*(char *)(param_1 + 0xc0) != '\0') FinishResolvingAction(…)` | **只有 `waitForAnim == 1` 的拍**才等满 `GetAnimDuration()`，等完才放行 |
| `:67-74` | `WaitForSeconds(*(AnimInfo + 0x28))` | 那是 `startDelay`（**两档都等**，但 `w=0` 那档队列早已放行 ⇒ 不占队列）。现读 160 拍 **`startDelay` 全 0** ⇒ 不影响求和 |

`+0xC0` 的来历（**已双向核实**，不是按字段顺序猜的）：
`BattleManager__ResolveAnim.c` 把整个 `BattleAction` 从 `stateMachine + 0x28` 起整块拷进去 ⇒
`0xC0 − 0x28 = 0x98`；`d:/2/tools/il2cpp_out/dump.cs`（`BattleAction`，`:118981`）标 **`public bool waitForAnim; // 0x98`**。
同一算式给出 `0xC8 − 0x28 = 0xA0` = `BattleAction.animInfo`，而状态机确实把 `+0xC8` 当 `AnimInfo` 用
（`+0x60` screenShake / `+0x80` tweenAnim / `+0x28` startDelay）⇒ **两处锚点互相印证**。

`waitAnimToApplyEffect` 怎么传到 `waitForAnim`：`AbilityLogic__PlayAnim.c` 单目标那一支直接传
`*(undefined1 *)(lVar5 + 0x58)`（`AnimInfo + 0x58`）；多目标那一支是
`iVar11 == targets.Count-1 ? (AnimInfo+0x58) : false`（**每拍**各自判，不是「最后一拍」）⇒
我们一拍只播一次 ⇒ 退化成 `= waitAnimToApplyEffect`（`CardAnimOrder.Waits` 早就是这个口径）。

## 二、「先查后做」三问的答案

1. **原版是哪一格 / 默认值 / `0` 与 `1` 的语义**：`AnimInfo.waitAnimToApplyEffect`（`dump` 偏移 `0x58`，
   C# 字段名来自 `[FormerlySerializedAs("pauseDuringAnim")]`）。语义**不是「时长」**，而是
   **「这一拍要不要把动作队列按住」**：`1` = 等满本拍时长再放行下一拍；`0` = 立刻放行、本拍动画转后台。
   ⇒ 任务描述里「`0` 是『不等待』」**就是原版语义**，已用 `:63-66` 反证（不是推断）。
2. **我们现在怎么算**：`EventTiming.AbilityHoldOf`（`EventTiming.cs:359`）→
   `AbilityAnimDurations.TryGet`（`AbilityAnimDurations.cs:202`）读运行期表的 `s`；
   生成器 `gen_ability_anim_durations.py` 里 `total = round(sum(r["seconds"] for r in act), 4)`
   —— **旧版把 `act` 全部拍加进去，不看 `waitAnimToApplyEffect`**。
3. **我们采到这一列没有**：**采到了，只是没参与计算** —— 每拍的
   `waitAnimToApplyEffect` 一直写在 `cards[*].activeAnims[*]` 里（生成器 `row["waitAnimToApplyEffect"]`），
   全量件 160 拍逐拍现读 **129 拍 = 1 / 31 拍 = 0**。⇒ **不需要补采集**，只需要改聚合口径。

## 五、断言（含灭自证）

`Editor/B120_W4_Assert.cs` 的 `CheckAbilityHoldWaitOnly()`，7 条：

1. **（前提）** `CardAnimOrder.TryGetBeats("DA23")` = 2 拍；Σ全部 = 2.0、Σ仅 `Waits` = 0.2；
2. **（前提）** 两者差 > 1.0（差不开就验不出鉴别力）；
3. **★ 正题**：`AbilityAnimDurations.TryGet("DA23")` == **0.2**（原版值）；
4. **★ 灭自证**：`s` ≠ Σ(全部拍) 2.0 —— **把 `waitAnimToApplyEffect` 全当 1 处理（= 改前形状）⇒ 第 3、4 条同时红**；
5. **★**：`EventTiming.AbilityHoldOf(DA23)` == 逐拍表算出的 0.2 且 ≠ 2.0（事件级占时与 `CardAnimOrder.Waits` 同口径）；
6. **★**：`Incursor`(UM89) == 1.4（中间那拍是 `w=1` 的卡）、`Lord Solar Leontus`(AM1) == 0（全 `w=0`）；
7. **★ 灭自证（面）**：UM89 与 AM1 必须差 > 0.5 —— 「一律按全部拍」或「一律按 0」都会让两者同时失真。

**期望值的来源**：`0.2 / 1.4 / 0` 是**原版判据手算**（逐拍 `AnimInfo` × `waitAnimToApplyEffect`），
而灭自证那半个期望值 `Σ全部拍` 是从 **`CardAnimOrder`（另一件产物、另一条生成链）** 现算的 ⇒
**不是从被测的 `ability_anim_durations.json` 抄**，不是自证。
接线：该文件 `Run()` 早已挂在 `BattleScene.cs` 的方法尾聚合行（`:47035`），**本轮没动宿主**。
