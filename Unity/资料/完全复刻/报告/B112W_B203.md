## 一、原版语义（`infantry troops` 到底筛什么）

**答案 = 两层「并且」：兵种 = Infantry **且** 只限 troop（= 场上部队，含督军那一格要排除）。**
不是「只限兵种」。

判据（第一权威 = 原版卡数据字段，`MyGame/Assets/RuleEngine/Resources/cards_engine.json` 的
`abilityTargetCriteria[].criteria`，逐张现读）：

| 卡 | 卡面 | 原版 criteria 行 | `includeHero` | `includeMinions` | `keywordFilter` |
|---|---|---|---|---|---|
| `UM13 Primaris Chaplain` | `… to your Infantry troops` | lg=0 | 0 | 1 | **5** |
| `TAU73 Hidden Hunters` | 同上 | lg=0 / lg=1 | 0 | 1 | **5** |
| `AM41 Move! Move! Move!` | 同上 | lg=0 | 0 | 1 | **5** |
| `b3735ef3… Grisly Feast` | `… your Warlord and Infantry troops` | lg=0 / lg=2（督军） | **1** | **0** | 0 |
| 同上 | 同上 | lg=1 / lg=3（步兵部队） | **0** | **1** | **5** |

⇒ 同一句里，「督军」那一档是 `includeHero=1 / includeMinions=0`，「步兵部队」那一档是
`includeHero=0 / includeMinions=1 / keywordFilter=5` —— **两个维度各自一层**。

**`keywordFilter` 就是兵种枚举，不是「关键词」**：

- 取值域：全池 `keywordFilter` 非零值只有 `{5:25 处, 10:55, 25:4, 30:7, 35:16, 40:10}` ——
  **全部**落在 `Keyword` 枚举里（`CardDef.cs:6350-6351` 的注释：
  `none 0 / Infantry 5 / Vehicle 10 / Monster 15 / Building 20 / Battlesuit 25 / Drone 30 / Beast 35 / Daemon 40`）。
- 反编译佐证（`d:/2/tools/cpp2il/out_cpp2il_dev_ilspy/`）：
  · `FilterMethods.cs:692-693`：`bool flag5 = evaluatedCard.IsKeyword(targetCriteria.keywordFilter);`
    `if (targetCriteria.keywordFilter != Keyword.none) …` ⇒ 目标筛选**就是**按这个枚举比一次。
  · `RawCardScript.cs:3967-3972`：`public bool IsKeyword(Keyword checkValue) => keyword == checkValue;`
    ⇒ 拿 `card.keyword`（单位卡上就是兵种枚举）与筛选值**全等**比。
- 我们这边 `CardDef.Subtype` 是同一件事的**字符串形态**（现读全池单位卡 **585/589** 一致，
  4 张已知不一致 → §八·2）。

⇒ 我们的 `Kind = "troop"`（`EffectResolver.AddSide(..., troopOnly: true)` 排督军）
＋ `SubtypeFilter = "Infantry"`（`ApplyTargetFilters` 按 `CardDef.Subtype` 精确筛）**正好是这两层**。

### 我们的消费侧是否已经正确（问题 2）

是。两层是**互相独立**的筛，**并且**关系：

- `EffectResolver.cs:1743`：`bool troopOnly = spec.Kind == "troop";` → `AddSide` 里 `:3037`
  `if (troopOnly && u.IsWarlord) continue;`
- `EffectResolver.cs:2268-2286`（`ApplyTargetFilters`）：`SubtypeFilter` 单独 `RemoveAll`，
  支持 `|` 并集，`Subtype` 为空的卡保留。

⇒ **消费侧一行都不用改**，缺的只是解析侧没往 `SubtypeFilter` 里填值。
（督军卡的 `Subtype` 现读 **56/56 = `Warlord`** ⇒ 兵种筛也不会误吞督军。）


## 二、根因（代码行）

改前 `EffectText.cs:10241-10258`（现 `10241-10257`）：

```csharp
if (spec.Kind != "warlord")
{
    if (t.Contains("warlord")) spec.Kind = "warlord";

    else if (t.Contains("unit")) spec.Kind = "unit";
    else if (t.Contains("enem"))  spec.Kind = "any";
    else if (t.Contains("target")) spec.Kind = "prev";

    {

```

`your infantry troops` 命中第二条 ⇒ `Kind="troop"`，**后面的兵种词分支进不去** ⇒
`SubtypeFilter` 留空 = 不筛兵种。「`troops` 这个词把 `infantry` 吃掉」。
（`B-189` 修的是同一句的 `Side`，`Kind/SubtypeFilter` 这一层当时明确留给本笔。）


## 三、改法

**只有 `EffectText.cs` 两个位置，消费侧/数据侧一个字节没动。**

1. **就地改写两行（行数不变，账不漂）** —— `EffectText.cs:10244-10245`：

```csharp
else if (t.Contains("troop")) { spec.Kind = "troop"; ApplyKindNounSubtype(spec, t); }
else if (t.Contains("unit"))  { spec.Kind = "unit";  ApplyKindNounSubtype(spec, t); }
```

2. **类尾追加两个私有 helper**（`EffectText.cs:10839` / `:10879`，在既有最大账落点 `:10701` 之后）：

- `SubtypeFilterOfKindNoun(string t, out bool sawKindWord)`
  - 只在**紧贴通称名词**的那一段里找兵种词：先定位第一个 `troop(s)/unit(s)` 词元，
    再从它往回走 —— **只放行兵种词与 `and`/`or`，遇到任何别的词就停**。
  - 命中多个 ⇒ 按原句顺序拼成 `"Infantry|Battlesuit"`（与既有 `|` 并集形状一致，消费侧已支持）。
  - 映射不到但确实写了兵种词（如 `terminator troops`）⇒ `sawKindWord = true`。
  - ⚠️ 刻意**不用整句 `FirstKindWord`**：那会把别的分句里的兵种词也算进来
    （`GOF72 Dead Choppy`：`Give Blood Thirst to a friendly Vehicle or +2 [attack] to another
    friendly troop` —— 那个 `vehicle` 属于前一截，不在 `another friendly troop` 里）。
- `ApplyKindNounSubtype(spec, t)`：填 `SubtypeFilter`；`sawKindWord` 但映射不了 ⇒
  如实记 `KindUnfilterable = true`（⛔ 不静默当成「不筛」）。

判据与选型理由都写在代码注释里（含 `cards_engine.json` 的 `keywordFilter` 逐卡读数）。

## 六、`TAU29` 叠加形状（`Infantry and Battlesuit troops`）

**结论：`TAU29` 不经过 `ParseTarget`，它走的是【光环】层，而光环层早就处理对了，本笔不需要动它。**

- `ruleprobe scan` 里 `TAU29` 的 `unparsed` = 整句、ops 为空 —— 这不是「丢兵种」，是
  `Your other Infantry and Battlesuit troops have +2 [Ranged]` 这族 **`X have Y` 本来就不产生 op**
  （`CardDef.HandledByOtherLayer` → 「光环（AuraSpecs）」），由 `Core/Aura.cs` 的 `Auras.TryParse` 收。
- 光环层的并集处理（`Aura.cs:466-524` `SubjectFilters`，现读）：
  · `:479` `Regex.Split(subject, @"\s+and\s+")` = **按 `and` 切段**；
  · `:499-503` 「同一段里有具体兵种时，泛称 `troops` 只是名词头」⇒ `Infantry troops` 只留 `Infantry`，
    `troops` 那半**只贡献「排督军」**；
  · 多段落 `KindWord = "infantry"` + `KindAnyOf = ["battlesuit"]`（`:513-522`）。
- 侧别：`head = "your other"`（`Aura.cs:154` Heads 里 `your other` 排在 `your` 前面）⇒
  `ExcludeSelf = true`（`:360`），正好对上卡面的「**other**」。
- 文档侧的既有记录：`资料/单位卡desc与光环_批次划分.md:212` 把 `Cadre Fireblade` 列在「排除自己」那一格；
  同一份 `:169` 记这族「A7 收工」。
- **反证（我做过，不是猜）**：把同一句硬丢进 `ParseTarget`（`ruleprobe seg "…"`），
  它会被并列切句器切成两条 op ——`your other infantry`（`Kind=infantry｜SubtypeFilter=Infantry`）＋

## 八、顺手发现（不在本笔白名单内，交调度台分流）

1. 🔴 **`CardCriteria.FromTarget` 不拷 `SubtypeFilter`** —— `Core/CardCriteria.cs:164-182` 只带
   `KindWord / WarlordOnly / Keyword / Name`。凡是走 `spec.Deployed`（`… you deploy`）与
   `spec.AttackedBySelf`（`… attacked`）这两种目标，兵种筛会**再丢一次**。
   现池**0 例**（`… you deploy` 那 10 张全是裸兵种词 ⇒ `Kind` 本身就是兵种词，`KindWord` 那格接管了），
   所以今天没有活缺陷；但只要出现 `<兵种词> troops you deploy`，就会静默宽打。
   ⇒ 与 `B-203` 同源，**建议单独立账**（`Kind == "troop"` 时 `FromTarget` 必须把 `SubtypeFilter` 也带上）。
2. **`card.keyword`（枚举）与卡面 `subtype`（字符串）有 4 张不一致**：
   `BL1 Chaos Spawn`（卡面 `Infantry` / 数据 `40 Daemon`）· `EC55/EC56/EC57`（卡面 `Warlord` / 数据 `5 Infantry`）。
   已在 `CardDef.cs:6353-6358` 记过（现读 585 一致 / 4 不一致）。我们的兵种筛读的是 `Subtype` 字符串，
   原版读 `keyword` ⇒ 「筛 `Daemon`」这类会**漏 BL1**（已知、非本笔引入）。
3. `TAU29` 那句在 `scan` 里显示为「整句 unparsed」容易被误读成「解析失败」—— 实际是光环层接管
   （`HandledByOtherLayer`）。若下次有人按 `unparsed` 列做覆盖率统计，这一族会**假性计入缺口**。
4. `ruleprobe check` 的哨兵 ⑦ 与「基线指纹」两条同时红/不判，读数很像；本次记录两者的区别
   （⑦ 只读源码、可跨卡池；基线指纹读卡池 md5）已写在 §七，免得下一个人当成两条新问题。
