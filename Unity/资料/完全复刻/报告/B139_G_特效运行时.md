## 三、逐条做了什么（判据 + 落地）

### 12-01 · 特效世界旋转不吃父/卡旋转
- **判据**：`decomp_full/BattleManager__CreateAnim.c:56-72` ——
  `Instantiate(prefab, anchor.position, **prefab.localRotation 当世界旋转**, anchor)` ⇒ 世界旋转 = prefab 自身。
- **落地**：`WarpforgeEffectPlayer.Play(...)` 两个重载末尾新增 `bool worldRotationStays = false`；
  true 时实例化后 `t.rotation = entry.prefab.transform.rotation`（并计 `WorldRotationStaysApplied`）。
- **⛔ 默认保持 false**：原版还有另一条实例化路 `CardScript.PlayTriggerAnim`（`decomp_full/CardScript__PlayTriggerAnim.c:29-33`）
  用的是**两参** `Instantiate(prefab, cardUI.effectsAnchor)` ⇒ 那条**要**继承锚点旋转（状态框那一族）。两条路在原版就不同。

### 12-02 · `doParentRelation` = `ParentConstraint`（不是父子）
- **判据**：`decomp_full/AnimFXModuleScaleByTarget__Initialize.c:96-118`（`AddComponent<ParentConstraint>()` +
  `Init(targetCard.GetEffectAnchor())` + `ToggleParentingOptions(1,1,0)`）+ `ParentConstraint__Sync.c`。
- **落地**（`WFModuleScaleByTarget.cs`）：`ConstraintPair{target, source, localOffset, localRot}`，
  `Initialize` 时**只记相对位姿不搬位置**（= `ParentConstraint.Init` 的 offset 语义），`ModuleTick` 每帧
  `target.position = source.position + source.rotation * localOffset`（**不乘** source 的缩放）、`target.rotation = source.rotation * localRot`；
  `source` 被销毁 ⇒ 跳过（特效留在世界）。删掉 `SetParent(targetCard, true)`（193/314 实例）。
- **锚点**：复用 `WFModuleTransformModifier.ResolveEffectAnchor`（判据只此一处；本条把它从 `private` 改成 `public static`），
  取不到（targetCard 不是 `CardView`）⇒ 退回卡根 + 出声计数 `ConstraintAnchorFallbacks`。

### 12-03 · `unParentAtStart` 之后仍被「持有者离场」收掉
- **判据**：`decomp_full/AnimFXModuleTransformModifier__Initialize.c:123-140`（`transform.parent = null`，此后与卡无关系）
  + `AnimFXController__OnEnable.c`（`preventDestroy = 1` ⇒ 不排销毁）⇒ 原版那两件**永久驻留**（原版泄漏，照抄）。
- **落地**：`WarpforgeEffectPlayer.ClearOwner()`（新）+ `WFModuleTransformModifier.Initialize` 在 `SetParent(null)` 之后调它
  （**仅当被脱父的就是特效根** —— 否则摘掉 `_ownerWatch` 会让整件泄漏）。现读那两件的 `__node` 都是特效根。
- **🔴 顺带修掉一个会让本条「等于没修」的顺序缺陷**：`Play` 原来在 `p.Init(...)` **之后**才设 `_ownerWatch`
  ⇒ 模块 `Initialize` 里刚摘掉的监视又被设了回去。现在**提前到 `Init` 之前**（`WarpforgeEffectPlayer.cs` 里带注释）。

### 12-05 · 到寿命那一帧的音效被吞
- **判据**：`decomp_full/AnimFXController__Update.c`（先 `currentTime += dt` 再逐条 `sounds[i].Update`）
  + `__OnEnable.c`（`Object.Destroy(go, destroyTime)` **帧末**生效）。
- **落地**：`Tick` 里 `TickSounds()` 移到 `_destroyAfterAt` / `_lifetime` 两条判定**之前**。现读命中面 0/937。

### 13-01 · `DestroyByTime` 只收自己那个节点
- **判据**：`decomp_full/DestroyByTime__Start.c:23-38`（`Object.Destroy(get_gameObject(this), lifeTime)`；`lifeTime == 0` ⇒ warning + 2.0）。
- **落地**（`WFExtraDestroyByTime.cs`）：不再 `owner.DestroyAfter(t)`（那会收整件）。
  · 运行期：`Destroy(gameObject, t)`（原版逐字）。
  · 批处理（无帧循环）：**子节点**走 `IWFEffectExtraTick` 自己数秒 → `DestroyImmediate(自己)`；
    **节点就是特效根**（= 收整件，与原版等价）交回播放器 `DestroyAfter` —— 否则会在 `Init` 中途把正在构造自己的对象删掉、`Play` 返回已销毁对象。
- **效果**：`Blast_Big_Ork_Missiles` 整件寿命 1.5 s → **4.0 s**（根 `destroyTime`）。

### 13-02 的运行时 / 数据半边（本条不在我的 9 条里，但 13-01/13-04 的判据依赖它）
- `工具/gen_effect_extras.py` 现在抽原版 `m_Enabled`，写成 `disabled: 1`；`WFEffectExtras.Attach` 见 `disabled > 0` ⇒ **不挂**并计 `DisabledSkipped`。
- 现读原版 164 个挂载里有 **4 个**是 `m_Enabled = 0` 且有行为：3 个 `DestroyByTime`（`Blast_Big_Ork_Missiles` 1.5 s · `Necrons Earthquake` ×2 3.0 s）+ 1 个 `SubEmitterManualTrigger`（`Sau_ParticleWhip`）。
- 用 `disabled`（默认 0）而不是 `enabled`（默认 1）：**旧表不会因为缺键把 9 个组件全停掉**。

### 13-03 · `SyncParticleSeeds` 只同步原版点名的那几颗
- **判据**：`decomp_full/SyncParticleSeeds__Awake.c:20-45` —— 循环 `particlesSystems`；**元素为 null 时 `break`（不是 continue）**。
- **数据**：`effect_extras.json` 新增 `ps`（每个 PS 所在**节点路径**，与 `WFEffectModule.ResolvePath` 同一套 `#N` 约定），
  由生成器按「PS 组件 PPtr → `m_GameObject` → 路径」烘出。现读 **40 挂载 / 88 槽 / 79 颗真粒子 / 9 个空槽**（原版 `fileID: 0`）。
- **落地**（`WFExtraSyncParticleSeeds.Apply(Transform root, string[] nodes)`）：只同步名单里的；
  空串 = 原版空槽 ⇒ **从此停**（照 `break`）；`nodes == null`（旧表）⇒ 退回整棵子树并**出声** + `LegacySuperset++`。
- **更正一条审计读数**：审计写「原版 90 颗」，我按 `m_PathID` 逐条数到 **88 个槽位 / 79 颗真粒子**（差的 11 = 空槽 + 跨文件引用）。
  断言用「表里数出来的」当期望，不写死 90。

### 13-04 · `SubEmitterManualTrigger` 只按 `subEmitterIndexes`
- **判据**：`decomp_full/SubEmitterManualTrigger__Update.c:20-42`（循环数组逐项触发；空数组 = 一次都不触发）。
- **数据**：新增 `se`（`int[]`）。原版那份 int[] 在 AssetRipper 的 YAML 里是**十六进制字节串**（`01000000` = `[1]`），
  生成器按小端 int32 解；现读 **12 挂载：11 个空数组 + 1 个 `[1]`**（后者 `m_Enabled = 0`）。
- **落地**：`Apply(int[] indexes)`；`null`（旧表）⇒ 退回「全下标」并出声 + `LegacyAllIndexes++`。

### 13-05 · `prewarm` 不再被 `Clear`
- **判据**：`decomp_full/AnimFXController__OnEnable.c` —— 只按 `destroyTime` 排销毁，**一处都不碰粒子** ⇒ 起播交给 `playOnAwake` + `prewarm`。
- **落地**：`Init` 里 `main.prewarm` 的系统**只 `Play`、不 `Clear`**（计 `PrewarmKept`），其余仍 `Clear + Play`（计 `InitCleared`，作对照）。

### 13-07 · `ParticleEmitOnEnable` 不再同节点挂两份
- **判据**：`decomp_full/ParticleEmitOnEnable__OnEnable.c`（一份组件、`if (!ps.isPlaying) ps.Play()`）。
- **落地**：`WFEffectExtras.Attach` 挂之前先按**类型名**查同节点是否已有 `ParticleEmitOnEnable`（CardPresentation 那份）
  或 `WFExtraParticleEmitOnEnable`（本仓这份）⇒ 有就不挂（`DuplicateSkipped++`）。
  ⛔ 用类型名而不是 `using CardPresentation`（依赖方向不变；`CardEffects` 那套回调就是这么解耦的）。
