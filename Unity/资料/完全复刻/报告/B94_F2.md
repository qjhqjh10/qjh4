## 六、顺手发现（交调度台分流，⛔ 本代理没改）

1. **`RunAbilityOfAnotherCard` 的正文键陷阱（已踩、已绕开）**：本仓 `CardDef.TriggerOps` 的键是**卡面触发词**（`rally`），不是原版 trigger 名。传 `"ThisCardPlayed"` ⇒ `TriggerOps` 恒 `null` ⇒ **静默空转**（账 1278/947 的施工单若照原版名字写会全落空）。`ThisCardPlayed(0)` 的等价正文键 = `KeywordTable.Rally`（判据 `ActionPump` 的 `AbilityTriggerNameOfKeyword` + 池内 105/105）。
2. **账 947 的落点原来指错**：`:237/334` 是 ability 级 `targetCriteria` 闸，与 `TriggerOtherCardAbility` 无关（已在账里订正，落点改为新口）。
3. **`GetChoiceOptions` 的随机流**：原版每次选牌从预烧表抽 `min(choicesDefinition+0x40,N)` 次，我们只抽 1 次 ⇒ 文档里那句「不是同一序列」现在有确切数量（**N-1 次错位**）。
4. **`AddCardNotDrawnToHand` 满手支有一条 `ShowHeadsUpMessage`（本地化「手牌满」）**，`RuleCore.AddCardToHandWithinLimit` 只有日志 ⇒ 少一条 UI 提示。
5. **`BroadcastUnitJammed` / `BroadcastQuestResolved` 扫的是 `unitsInPlay` 追加序**，我们按「双方棋盘格号」扫 ⇒ 多监听者时**顺序不同**（jam 现池 0 生产者，暂不可观测）。
6. **`Enchantment.Attach` 已记 `UsedEnchantment`**，但 `AddEffect` case 16 的 `TriggerEnchantment` / 任务清场（spellType 0x78 摘其他任务附魔 + `questCounter=0`）未接 ⇒ 附魔那半整族缺。
7. **`Out_il2csharp` 又一次证明比 ILSpy 干净**：947 的真值 `(ThisCardPlayed, mgr, this, this, 0)` 只在那边；ILSpy 的 `.c` 把 `this`/`target` 两格丢了。与已记的「ILSpy 丢常量」同族。
