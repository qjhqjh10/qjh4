### 3·1 货币为什么落 `Wallet`（这一格是本件唯一的**结构桥**，不是新判据）

- 原版 `CollectCurrencyReward` ⇒ `InventoryManager.Add<Currency>` ⇒ 进 `Inventory<Currency>`。
- **本工程没登记 `Inventory<ICurrency>`**（全仓只有 `RuleEngine/Editor/RuleEngineTest_W6.cs:242` 在自检里 new 一份；
  `Shell/Inventory.cs` 的 `Inventories` 静态构造只注册 `Cards / Shop / AltArts / Wildcards` 四个）。
- 而**生产货币正本 = `Shell/DailyData.cs` 的 `Wallet`**（`Shell/Inventory.cs:1952` 与 `DailyData.cs:2306` 两处自己写着
  「全工程唯一发奖口 = `Wallet.Grant`，按菜单图名记账」），**顶栏读数 `MainMenuRuntime.OwnedOf` 也读它**。
- ⇒ 再开一个 `Inventory<ICurrency>` = 「两处写同一条规则 = 迟早不一致」（CLAUDE.md §三），而且会绕开用户
  2026-09-17/10-24 定的「**资源固定 2000**」（那条落在 `Wallet.StartAmount`）。
- **落地**：`Wallet.Grant(CounterSpec.WalletKey, qty)`；`WalletKey` **取自 `MainMenuRuntime.CounterSpecs`**
  （⛔ 本件不另开一张 "code → Wallet 键" 的表）。货币 code → `GameCurrency` 三对取自
  `Shell/CurrencyNames.cs` 文件头 ① 的**三份 SO `code` 字段实读**（`Crystals`=`C2` · `Blackstone`=`C3` · `Gacha tickets`=`C5`）。
- ⚠️ `C3` / `C5` 在 `CounterSpecs` 里 `WalletKey` 是 `null`（我们只给金/水晶/活动点记了账）⇒ 这两档**出声、不发**。
  战役奖励表**只用 `C2`**（8 条），所以今天不影响任何一条真数据。
