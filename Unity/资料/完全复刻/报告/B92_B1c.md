## 6 顺手发现

1. 🔴 **`}))` 这种「双闭括号」是这批 lambda 调用的通用形状，改实参时最容易少一个括号** —— 我这一轮就踩了（`}), actionType: 1)` 少一个 `)`）。判据（不用编译也能查）：**数括号** —— `EnqueueAbility(` 后面的实参表要闭合一次、外层 `if (`/`return` 各自闭合一次。下次改这类行，先看**原行有几个右括号**再动手。
2. 🟡 **`CardScript__SendRemoveEffect.c:27` 与 `CardScript__TriggerUnitDeathActions.c:41` 是同一写法**（`local_208[0] = N;` 直接写 actionType 槽），而不是走 `BattleAction___ctor`。⇒ **判「某方法的动作类型」不能只 grep `BattleAction___ctor`** —— 这一族是**绕开构造器直接写第 0 个 dword**的，只 grep ctor 会漏掉（我第一轮就漏了 `minionDeath(4)` 与 `removeEffect(16)`，靠扩大搜索面（`grep "\[0\] = 4;"`）才捞到）。
3. 🟡 **`AddRecallToDeck` 的调用点显式传道号 3（DelayedInstant）**，而我们的 `recall-to-deck` 也是 `DelayedInstant` —— 这条**巧合**值得记：原版「狂暴洗回牌库」的**正文先入队（Instant）→ 洗回后入队（DelayedInstant）** 的次序，是 `UsedActiveAbility.c:58-66` 逐行定的，不是我们挑的（我们 `RuleCore` 那段 doc 已引）。
4. 🟡 **`ActionQueue.Has` 的扫描序（道 0→1→2→3、道内升序）与消费序（`DequeueOrder = {2,1,3,0}`）不同** —— `WaitingForBlockingAction` 要的是**前者**（存在性查询），⛔ 别借 `TryDequeue`。这条 `ActionQueue.Has` 的 doc 里已写死，我这次调用直接复用它、没另写一份扫法。
