## 二、这个清空为什么安全（不是「盲抄判据」）

`B100_X2` 的清单我逐条回源核了**两个前提**，两个都成立：

1. **这 20 张表（19 张 + `_cosmOnly`）都在每次 `Build()` 里被无条件重建。** `Build()` 体（`:1276-1426`，**无任何 early return**）按序调：
   `BuildAreaBackground / BuildTopBar / BuildHeader / BuildSidebar / BuildDeckList / BuildCurve / BuildTypeCounter / BuildFooter / BuildFilters / BuildPool / BuildCosmeticsPage / BuildCosmeticDrag / BuildCardDrag`
   然后才是 `_tab = 0; RefreshAll(); WildcardDisplayEnable();`。
   - 卡列表 7 张 + `_rowPieces` ← `BuildDeckList`（`_deckRowName.Add` `:2100` · `RegisterRowPiece` `:2233-2234`）
   - 页签 4 张 ← `BuildSidebar`（`_tabLabel.Add` `:1892` 等，`:1866-1892` 在 `BuildSidebar` 体内）
   - `_cardsInfoOnly` ← `BuildHeader`（`:1697-1770`，下一方法是 `:1775 BuildSidebar`）
   - 曲线 4 张 ← `BuildCurve`（`:2405-2407`）· `_infoOnly` ← `BuildCurve` + `BuildTypeCounter`
   - `_fltTitles` ← `BuildFilters` → `BuildFilterFixedParts()`（调用点 `:2535`，`:2912` Add）
2. **这 20 张表登记的对象全在被 `:1283` 销毁的那棵子树里。**
   过滤抽屉那批挂 `FltParent`，而 `FltParent = _fltSlide.Node`（`:2677`），`_fltSlide = NewDrawer("flt_drawer")`，`NewDrawer` 第一句就是 `go.transform.SetParent(Root, false)`（`:2669`）⇒ 抽屉容器是 `Root` 的直接子件 ⇒ 一起被 `DestroyImmediate`。
   其余全部直接挂 `Root`。

⇒ **清空不会丢任何「还活着」的引用**；不清则是必然的僵尸引用。
