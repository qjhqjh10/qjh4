## 1. 方法（可复现）

1. **数据源** = `D:/2/新解包资源/assets_full/bundle_menus_assets_all/`（组件目录 `ls` 现读，实际是
   `Animation · AnimationClip · AssetBundle · BoxCollider2D · Canvas · CanvasGroup · CanvasRenderer · GameObject · Material · Mesh ·
   MeshRenderer · MonoBehaviour · ParticleSystem · ParticleSystemRenderer · RectTransform · Shader · SortingGroup · Sprite ·
   Texture2D · Transform · VideoClip · VideoPlayer` —— **没有 `Image/`、没有 `Text/`、没有 `AudioSource/`**）。
   - `Image` / `TextMeshProUGUI` / 三个 LayoutGroup / `Button`·`Toggle` / `Mask`·`RectMask2D` 都在 **`MonoBehaviour/`** 下（它们是 MonoBehaviour 子类）；
   - `Canvas` / `CanvasGroup` 是**原生类型**，有独立目录。
2. **类名解析** = 组件的 `m_Script.m_PathID` → `bundle_Waprforge_monoscripts/MonoScript/*.json` 的 **`m_ClassName`**（722 个类，⛔ 没按名字搜字节）。
3. **树解析** = `GameObject.m_Component` → 各组件；`RectTransform.m_Children` 装的是 **`Transform` 的 pid、不是 `GameObject` 的 pid**
   （⚠️ 这是第一个坑：直接拿子 pid 去 `GameObject` 索引取会一个都取不到、**静默得到 0 行**）。
   文件名带 `_-<pid>.json` 后缀的直接按 pid 索引；**1,667 个 GameObject 文件名没有 pid 后缀**（如 `Deck Editing Menu.json`）
   ⇒ 用「它第一个组件的 `m_GameObject.m_PathID`」反推自己的 pid。
   ✅ pid 无重名（`GameObject` 15,101 个带后缀文件，**重复 pid = 0**；`MonoBehaviour` 34,904 个，重复 0）。
4. **默认值口径**（`非默认` 是相对下面这张表判的；**表里每一条都是 Unity/TMP 的出厂默认，不是本工程的约定**）：

| 字段 | 我用的默认 | 依据 |

| `Image.m_PixelsPerUnitMultiplier` | 1 | uGUI |
| `Image.m_FillMethod` | **`Radial360(4)`**（⚠️ 不是 Horizontal） | uGUI `Image.m_FillMethod` 出厂 |

5. **去重**：同名多实例**逐个走**，但 TSV 按 `(prefab, 节点路径, 组件, 字段, 值)` **归一去重**
