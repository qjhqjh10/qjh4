## 三、新的窗口化 bat 怎么用

**双击 `E:\warpforge\start_offline_windowed.bat`** 即可。它做的事与修正后的旧 bat 相同，只多一条：把游戏启动成 **1600×900 窗口**。

启动那一行（与原版 `Launcher.cs` 不同的唯一一处）：

```
start "" "E:\warpforge\game\Warpforge.exe" -screen-fullscreen 0 -screen-width 1600 -screen-height 900
```

**为什么用命令行而不是设置窗**：设置窗盘点结论（`B168_判据_设置窗功能.md`）—— 游戏**没有分辨率列表**，只有「全屏/窗口化」开关且**不持久化**；对离线测试最可靠的就是 Unity 自带的 `-screen-fullscreen / -screen-width / -screen-height`。

**非 ASCII 路径怎么处理的**（这是本文件最关键的一处设计）：
服务端目录叫 `05_工具`，文件名里带中文就会让这个「纯 ASCII」的 bat 破功。所以**不在文件里写它的名字**，改在运行时用通配符解析：

```bat
set "SERVERDIR="
for /d %%D in ("%~dp005_*") do set "SERVERDIR=%%~fD\server"
```

- `%~dp0` = 这个 bat 所在目录（**跟着 bat 走**，不写死盘符），后面直接接 `05_*`；
- 起服务端用 `start` 自带的 `/d` 指定工作目录，**避开 `cmd /c "cd /d "…" && …"` 那种嵌套引号**：
  `start "wf-fake-server" /min /d "%SERVERDIR%" cmd /c "python -I server.py --strict"`。

**两条防御性检查**（旧 bat 没有，新 bat 加了；都 `pause` 后 `exit /b 1`，不会静默失败）：

1. 找不到 `05_*` 目录（比如 bat 被单独拷到别处）⇒ `[launcher] ERROR: could not find the server folder next to this bat.`
2. 目录在但 `server.py` 不在 ⇒ `[launcher] ERROR: server.py not found in "…"`

> ⚠️ **8.3 短名这条路实测不可用**，别再试：`for /d %%D in ("E:\warpforge\05_*") do echo %%~sD` 对 `E:\warpforge` 返回了短名 `WARPFO~1`，但对 `05_工具` **返回的还是长名**（该目录没有 8.3 别名）⇒ `%%~sD` 拿不到短路径。

## 五、坑 / 注意

1. **`timeout.exe` 在 stdin 被重定向时会报「不支持输入重新定向」并立刻退出** —— 这是我在 `subprocess` 里捕获输出造成的，**双击运行不会**（有真控制台）。旧 bat 里也是同一行，口径一致，没改。
2. **新 bat 的游戏启动行是写死 `E:\warpforge\game\Warpforge.exe` 的**（照任务给的原样）。若整个工作区搬家，这一行要跟着改；服务端那一半已经跟着 bat 走了（`%~dp0`）。
3. **窗口化参数只能管住第一次启动时的窗口尺寸**。游戏内如果再点「全屏」开关，它的状态**不持久化**（设置窗判据），下次启动仍会被命令行参数覆盖回 1600×900 窗口。
4. **`start "" "…Warpforge.exe"` 不设工作目录**（沿用旧 bat 的写法）。实测游戏能找到自己的 `Warpforge_Data`（Unity 按 exe 路径找），所以保持不动。
5. 沙箱与临时脚本全在 `D:\tmp\t1s\`，**没有往 `E:\warpforge` 里留任何临时文件**；原文件备份在 `D:\tmp\t1s\bak\`。
