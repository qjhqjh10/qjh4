## 三、断言要点（`Editor/B110_W2_Assert.cs`，新建）

**三层，全部独立于实现：**

1. **① 机理（运行期真建一颗临时 quad）**
   - （前提）`ImageQuad.Create` 建得出来 · `Sprites/Default` 取得到 · **`SetTint` 后 `Tint` 读回 = 传入值**（先断前提，再断结论 —— ⛔ 不是 `if (x != null) Check(...)` 那种静默跳过）
   - 正确顺序「存 → 换材质 → 写回」之后 `Tint` **仍是**探针色
   - 🔴 **灭自证**：同一颗 quad 把顺序改回旧写法（`SetTint(Probe)` → `SetMaterial(new Material)`）⇒ `Tint` **一定不再**等于探针色。**这条绿 = 上面那条确实咬得住顺序**；两条结构上不可能同时满足
2. **② `UnitChatPanel.cs`（文本先后序，不是 `Contains`）**
   - `var keep = b.wave.Tint;`（@iKeep）**<** `b.wave.SetMaterial(b.waveMat);`（@iMat）**<** `b.wave.SetTint(keep);`（@iRestore）—— **把顺序改回去这句就翻号 ⇒ 红**
   - 写回那句**不在行末注释里**（`BeforeLineComment`，挡 2026-10-30 那个「代码落进 `//`」的坑）
   - `b.wave.SetTint(WaveTint);` 仍在（材质建失败 / 旧材质退回时颜色也对）
   - 全文件 `b.wave.SetTint(` **恰好 2 处**（⛔ 没有人给 uGUI / 世界两档各写一份）
3. **③ `MissionsTab.cs`**
   - `q.SetMaterial(m);` 的索引 **<** `q.SetTint(MilestoneDisabledTint);` 的索引（改回旧序 ⇒ 红）
   - `q.SetTint(MilestoneDisabledTint);` **不在行末注释里**
   - ⛔ **反向保险**：全文件 `var keep = q.Tint;` **必须不存在**（写了 = 把灰写回白）
   - 灰常量仍是原版 `m_DisabledColor` 的 `0.7843137`（⛔ 没被顺手换成别的灰）

**接线**：本文件**没有**自己往宿主里接（宿主是白名单外）。宿主加两行即可：
```csharp

pass += B110_W2_Assert.Pass; fail += B110_W2_Assert.Fail;
```
⚠️ 它只读源码文本 + 在内存里建一颗**临时** quad（`finally` 里 `DestroyImmediate(root/材质/贴图)`，与 `Editor/B102AUD05_Assert.cs:105-158` 同一个写法），不建窗、不动场景。

## 五、顺手发现（没改，交调度台分流）

1. 🟡 **`Editor/B110_S1_Assert.cs:320-322` 里 `TitleTab` 那条断言只看 `Contains`、不看先后序**：
   `Check("换材质前后存/恢复了 tint", tab.Contains("var keep = _bigArt.Tint;") && tab.Contains("_bigArt.SetTint(keep);"))`
   —— 把两句**顺序对调**照样绿。建议并入 `TitleTab` 那条时补一句索引比较（本批没动别人的断言文件）。
2. 🟡 **`HudPiece` 两档的 `SetTint` 语义不同却同名**：uGUI 档写 `Image.color`（顶点色）；quad 档写 `sharedMaterial.color`（材质色）。⇒ 「换材质会丢 tint」**只在 quad 档成立**，而这一层差异**没有任何注释**（`Battle/HudPiece.cs:158-175`）。将来谁再在 `HudPiece` 上写「先 tint 后换材质」，仍会踩同一个坑。已在本轮两处落注释，但**共用层没写**（`HudPiece.cs` 不在白名单）。
3. 🟡 **`ImageQuad.SetTint` 与 `SetMaterial` 的组合没有任何闸**：产品基类里 `SetTint` 写 `sharedMaterial.color`，而 `SetMaterial` 换整份材质 —— 两者一个 296 行、一个 398 行，**隔了 100 行、没有互引注释**。建议在 `SetMaterial` 的 doc 里补一句「**换完请自己恢复 tint / renderQueue（后者已由本方法代劳）**」。（`Core/ImageQuad.cs` 是白名单外）
4. 🟡 **`MissionsTab.cs:2173` 的 `m.color = MilestoneDisabledTint` 与 `:2177` 的 `SetTint(MilestoneDisabledTint)` 现在是同一件事写两遍** —— 保留无害（前者给缓存材质定值、后者保证每次施加），但**两处若将来改了其中一个就会打架**。建议把后者留作唯一写口、前者改注释说明「只是建缓存时的初始值」。
