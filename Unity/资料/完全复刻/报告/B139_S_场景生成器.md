### 为什么不是「把 BuildScene 里那台 HUD 相机直接改成透视」

`BuildScene()` 建完之后那台 HUD 相机**必须是正交的**：

- 整套 2D 世界件（卡 / 棋盘 / 手牌 / HUD quad）按「可见高恒 10 世界单位 ⇒ **108 px/单位**」布局
  （`LayoutSpace.VisibleHeight` / `Px()` / `ScreenToWorld`，以及 `HudCanvas.PlaneDistance = 20.3` 那套 z 推导）；
- 原版是另一套换算：uGUI 画布 `planeDistance 100` + fov 40 ⇒ **1 世界单位 ≈ 14.83 px**；
- ⇒ 相机一改透视，2D 件会整体缩成 `10 / (2×20×tan20°) = 0.687` 倍（连自检截图一起变）。

所以本包的边界是：**运行期仍由 `LayoutSpace.Apply` 强制正交**（`BattleDriver.Start()` 每次都调），
只在 `BuildAndSaveScene()` 存盘前往场景里写**原版序列化值** ⇒ 之后再重生成**不会**把包 Y 的成果覆盖掉。
🔴 要「运行期也用透视」得先把整套 2D 世界件搬进画布（`T09` / 账 `A2098`），**不在本包**。

## §三 未做 / 存疑（逐条写为什么）

1. **运行期仍是正交相机（`LayoutSpace.Apply` 未动）。**
   理由见 §一末：2D 世界件按 108 px/单位布局，改透视会整体缩成 0.687 倍。
   根治 = `T09`（整套 2D 件搬进 uGUI 画布）+ 账 `A2098`，**不在本包**。
   ⇒ 所以本包里「HUD 相机透视」只在**序列化值**层面成立 —— 与包 Y 对场景的改动同口径。
2. **HUD 相机的 `cullingMask` 仍是我们那个值（原版 32）。**
   我们整套 HUD 件（含 `HudCanvas` 根）都在**层 0**，写 32 = 相机不画层 0 = 整个战斗 HUD 消失。
   要先做「HUD 件整体迁到层 5」，那属 HUD 架构包。账里同一条 `C`（与包 Y 同一行）。
3. **`HudCanvas.PlaneDistance = 20.3` 未改成原版 100。**
   它不是「抄错的常数」，是我们这套分层 z 轴的承重件：`HudCanvas.cs` 文件头写着「相机在 z=−20 ⇒
   `planeDistance = 目标 z + 20`」，20.3 让画布正好落在 `HudImageZ`(0.3) 那一层、与世界空间 quad 共用同一条 z 排序轴。
   改成 100 ⇒ 画布落到 z=80，会**压在所有 HUD quad 前面**（它们全在 z ≤ 0.3）。
   ⇒ 保留现值；原版 100 只在「整套 HUD 已经是画布件」时才成立（同 §三·1 的 T09）。
4. **UACD `m_RendererIndex`（原版 UI 1 / 我们 −1）未动。**
   `Assets/Settings/` 只有 `PC_Renderer` / `Mobile_Renderer` 两份，`PC_RPAsset` 的 `m_RendererDataList` 只 1 项
   ⇒ 指向 1 会越界回退。新建资产不属本包（与包 Y 同判，账里同一条）。
5. **BoardCamera 的 GO 名仍是 `BoardCamera 透视（原版值）`（原版 `BoardCamera`）。**
   全仓无按名查找（`grep '"Main Camera"'` / `GameObject.Find` 已核）；改名只增加账漂移风险，未改。
6. **`m_CullingMask` 的 Board 侧（我们 1280 / 原版 1137）未动** —— 属 `B132` 物理层架构，另包。
