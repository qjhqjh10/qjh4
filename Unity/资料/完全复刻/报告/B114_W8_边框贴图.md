## 〇 一句话

**5 份原版材质，一份都没有 `_MainTex`。** 这颗 shader 的 `_MainTex` 是 **uGUI 的 per-renderer 纹理**
（`Graphic.mainTexture = Image.m_Sprite.texture`）⇒ 「是哪个资产」只能**按用它的那个 Image 反查**。
我们用到的那一份 `Border Effect For Level up` 在主菜单里只挂在两件上：
`Level Up Effect` = **`OctagonUI Filled SDF`**、`Level Up Effect Down` = **`OctagonUI Border SDF`**（都是 128²）。
两张图**本机早就有**（`Resources/Art/ui_menu/OctagonUI_{Border,Filled}_SDF.png`，2026-10-31 那批导进来的，逐像素与原版相同）
⇒ 本波把它们接进 `_MainTex`（并修掉「换材质把贴图和染色一起丢掉」那两跳）。

3. **`BuildImage`（`:397-411`）**：`AnimateUIMaterialProperty.Attach(...)` **之后**补一句

4. **新增 `BorderSprite(string)`（类尾 `:564-598`）**：`Level Up Effect` → `OctagonUI_Filled_SDF`；
   `Level Up Effect Down` → `OctagonUI_Border_SDF`；其余返回 `null`。
5. **就地订正（铁律 5）`：343`**：那句「缺的是**这块图用的材质**（仍是 `Sprites/Default`）」**已经不成立**
   —— 材质早在 `B9_W39MAT` 就挂上 `Border Effect For Level up` 了。改成带日期的新口径。

### 3·2 为什么第 3 条非加不可（这是 W-7 交接里那条「会更难看」的根因）

```
ImageQuad.Create(..., spr, ...)          → 材质 = new Material(Sprites/Default)，mainTexture = spr   ✅
AnimateUIMaterialProperty.Attach(...)
    → OnEnable → CreateInstanceMaterial  → new Material(Sprites/Default 克隆)
    → RebuildOwnInstanceMaterial         → new Material(Border Effect For Level up.mat)   ← 材质换了
                                          那份材质**没有 `_MainTex`** ⇒ mainTexture 退回 shader 默认的 1×1 白 ❌
```
⇒ 不补第 3 条，`c.a` 恒 1，新 shader 照原版算出来就是**一整块矩形**（比改之前还难看）。
`SetTexture(spr, keepAspect: true)` 只写 `_tex` + `sharedMaterial.mainTexture`，**⛔ 不碰 `_aspect`**
（几何已按判据定好，见 `ImageQuad.cs:214-243`）。

## 四 没查清的部分（如实写，⛔ 没猜测）

1. **九宫格（`m_Type: 1` = Sliced）没复刻。** 两个 Image 的原始字段：
   `Level Up Effect` → `m_PixelsPerUnitMultiplier 0.5`；`Level Up Effect Down` → `1.11`；
   sprite 的 `m_Border = (52,52,52,52)`（128² 里每边 40.6%）。
   **我们这条链是「整张拉伸的 quad」**（`ImageQuad.Create` + `SetAspect(w/h)`），不是九宫格
   ⇒ 软边在小矩形里会被**按轴拉伸**。
   ⛔ 本波**没有**把它改成九宫格：① 任务单只要求「把图喂进 `_MainTex`」；② `ImageQuad` 已有
   `CreateNineSlice`，但那会**改几何**，而 shader 的 Pulsating Scale / 噪声都是按 `uv` 算的
   （九宫格下 uv 是切片子矩形）⇒ 观感会跟着变，⛔ 不该由写手单方面拍。**要做得先拍板。**
   也**没有**算准九宫的世界尺寸（uGUI `Image.pixelsPerUnit = referencePixelsPerUnit / sprite.pixelsPerUnit * ppuMul`
   这一跳没核）。
2. **画面没验。** 本波红线不跑 Unity（也不跑 `-executeMethod`）⇒「接上之后边框是不是真成了八边形环」
   **只有代码层证据，没有像素证据**。建议调度台开窗口时顺手看一眼 `CardDetailPopup` 的升级演出。
3. **`wrap` 依赖没实跑。** shader 的 `uv2 += nz * _Noise_Strength.x` 会把 uv 推出 `[0,1]`；
   原版 `.meta` 是 `wrap 1`（Clamp），盘上那份 meta 也是 `wrapU/V/W = 1` ⇒ **设置一致**，但没跑起来验。
4. **另外 4 份材质我们没接**（本工程只用 1 个）。**唯一要说明的一处**：`Shell/CampaignTab.cs:664`
   （`Border Highlight Rotating Campaign` 那条）**已经是对的** —— 它 `_win.Rect(node, "Border_Thick_Circle_FX", …)`
   喂的正是原版那张 `Border Thick Circle FX`，与 §1·2 表 #5 吻合（顺带旁证本波的对照表没读错）。
   其余三份（`Border Highlight Appear Yellow` / `Border Gacha Button Glow` / 模板材质）本工程**没有使用点**。
5. **色彩空间只读了配置，没实拍。** 原版工程 `assetripper…/ProjectSettings.asset` 的
   `m_ActiveColorSpace: 0`(Gamma)，我们 `Unity/MyGame/ProjectSettings/ProjectSettings.asset:50` 也是 **0**
   ⇒ 两边都在 Gamma 下、`sRGBTexture: 1` 都**不做** sRGB→linear 解码 ⇒ 采样值与
   `_Color_offsets (0.8, 1.0)` 的标定对得上。这是**读配置推的**。
6. **`Level Up Effect` 那份 sprite 是 `Filled` 这件事有点反直觉**（一般会以为「Effect」是环、「Down」是实心）。
   本波是**按 PPtr 逐条读出来的**（Image 2545 → GameObject 338 `Level Up Effect` → `517922d5…` = `OctagonUI Filled SDF`），
   不是按名字猜的。⛔ 如果以后有人「按常识」把它换过来，请先回 `MainMenu Warpforge.unity` 重读那两个 Image 组件。
