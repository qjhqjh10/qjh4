执行代理：`B100_F9` · 2026-10-30 · 白名单：`RuleEngine/Data/CardDatabase.cs` · 新建 `CardPresentation/Editor/B100F9_Assert.cs` · 本报告。

## 一、根因判定 = **(a) 数据侧没问题，读取侧读错了键**

判据逐条：

1. **数据**：`RuleEngine/Resources/cards_engine.json` 的 `abilityEffectTexts` 现读 **38 行**，
   **38/38 的键集都是 `(ab, at, lg, src)`** —— **一条 `isHand` 键都没有**
   （`python -I` 逐行 `keys()` 统计）。
2. **生成器契约**：`工具/gen_cards_engine.py:7242` 写死了形状
   `[{"ab": i, "lg": j, "at": "buffEffect"|"handBuff", "src": "<effectText>"}, …]`，
   落行点是 `:7287` `out.append({"ab": ab, "lg": lg, "at": at, "src": src})` —— **没有 `isHand`**。
   这是**生成器自己的口径**，不是漏写。
3. **读取侧**：`CardDatabase.MapAbilityEffectTexts` 原来读 `r.isHand`（`CardDatabase.cs:4872` 原文
   `Ab = r.ab, Lg = r.lg, IsHand = r.isHand,`），而 C# `bool` **缺键默认 `false`**
   ⇒ 5 行 `handBuff` 全被当成 `buffEffect` ⇒ `(ab,lg,isHand)` 三元组撞键
   ⇒ **`buffEffect` 那条先入（排序在前）、`handBuff` 那条被丢**（日志 `b100_battle.log:103443/103459`）。
4. **同文件里的兄弟映射早就用 `at`**：`MapAbilityMutations`（`CardDatabase.cs:4542-4550`）判的是
   `if (r.at == "buffEffect") hand = false; else if (r.at == "handBuff") hand = true;`
   ⇒ **`abilityEffectTexts` 这一份是唯一的例外**（写它的时候按「JSON 会有 `isHand` 键」假设写了 DTO）。
5. **提交历史**：`cards_engine.json` 与 `CardDatabase.cs` 最后一次改都是第九十九会话同一个提交
   （`31f69eef`）⇒ 不存在「表是旧的、代码是新的」这种时序错位；这是**当天一起引入的契约不一致**。

⇒ 结论：**只改读取侧**（改生成器属调度台独占，且**不需要** —— 见 §五 顺手发现 ②）。
