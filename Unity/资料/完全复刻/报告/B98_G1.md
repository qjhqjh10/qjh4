### 5·1 🔴 `SetNextCardAsDeckDrawing` 的**扫描方向**与本仓牌库镜像约定相反（本批最重要的一条）

* **现象**：`RuleCorePartial_B97W34.SetNextCardAsDeckDrawing` 从 `ps.Deck[0]` 起扫第一张未标记的，
  而**本仓 `Deck` 的「顶」是列表末尾** —— `RuleCore.MoveDeckTopToHand` 取的是
  `int last = ps.Deck.Count - 1; var inst = ps.Deck[last];`（`RuleCore.cs:3133-3135`），
  同一方法的长注释（`RuleCore.cs:3127-3129`）写死了这条镜像约定：
  「原版：**下标 0 = 顶**。我们的 `Deck` 是同一份列表但**把末尾当顶**（等价的镜像约定）」。
  ⇒ **它标的是「牌库底」那张**，不是「下一张要被抽的那张」。
* **为什么本批照接了**：调度台的施工（`B98_R4` §573）只给了「先标再抽 / 离库即清」这两处，
  方向问题在 `RuleCorePartial_B97W34.cs`，**不在本批白名单**（我的白名单只有
  `RuleCore.cs` + 新建 `RuleCorePartial_B98G1.cs`）。⇒ 按 13·3③ 交回可粘贴补丁。
* **可粘贴补丁**（`RuleEngine/Core/RuleCorePartial_B97W34.cs:130`，**一行**、零行数变化）：

  ```csharp
  // 改前
  for (int i = 0; i < ps.Deck.Count; i++)
  // 改后（本仓 Deck 末尾才是顶 —— 见 RuleCore.cs:3127 的镜像约定；原版下标 0 = 顶 ⇒ 取 Count-1 起倒序扫）
  for (int i = ps.Deck.Count - 1; i >= 0; i--)
  ```
* **同时要改的两处**：
  ① 该方法头注释「原版从下标 0 起扫」→ 补一句「本仓镜像 ⇒ 从**末尾**起扫」；
  ② `CardPresentation/Editor/B97W34_Assert.cs:202-211` 的 C1/C2 断言把 `deck[0]`/`deck[1]` 当「牌库顶/第二张」
     ⇒ 方向修完必须同步改成 `deck[deck.Count-1]` / `deck[deck.Count-2]`，否则**修对了反而变红**。
* **修完之后的额外断言**（本批**故意没写**，因为现在写就是红的）：
  `RuleCore.Draw` 之后 `ctx.DeckDrawingInstanceIds.Count == 0`（现在的 F4 只敢写 `<= 1`）。
* **今天零可观测**：`IsDeckDrawing` 的唯一消费者是自检 / 将来的牌库顶动效，`DeckDrawingInstanceIds`
  不进 `Fingerprint` ⇒ **不改变任何对局行为**，但它是「状态说假话」，且会在动效接上那天现形。
