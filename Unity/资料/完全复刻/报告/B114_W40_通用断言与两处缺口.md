### 活 3 · `B-279`：`spec.Side == "self"` ⇒ 空池（**判定：不是缺陷（不可达）· 不改代码**）

| | 内容 |
|---|---|
| **判据** | `PlayTargetPool` 的 `spec` **只有一个生产者**：它自己上一句 `spec = EffectText.PickTarget(ops)`。`PickTarget` 的出口闸是 `if (t.Side == "enemy" \|\| t.Side == "own") return t;`（`EffectText.cs:1369`）⇒ `Side ∈ {"self","any","prev","eventtarget",""}` 一律返回 **`null`** ⇒ `PlayTargetPool` 在 `if (spec == null) return empty;` 就返回空池，**根本到不了 `AddSide`**。 |
| **现状** | 「`self` ⇒ 空池」这个形状**存在于代码里**（`AddSide` 两条都不命中），但**结构上不可达**。原版也没有这个文本侧：`EffectTargetSpec.Side` 的文档里写 `self`，是把「`self` 当 `own` 的别名」那一套（`EffectText.ResolvedSide`：`Side == "own" \|\| Side == "self"` ⇒ `"own"`），**不是**一个会被解析器产出的值。⇒ **结论：不是缺陷**（与改前、与原版都无行为差异），**不照原版改**（原版没有可改的东西）。 |
| **做** | 断言**钉住那道出口闸**（`C` 段）：对 `self / any / prev / eventtarget / ""` 五个值，`PickTarget` 必须返 `null`；并排对照 `own` / `enemy` **必须非 null**。⇒ 哪天有人为了支持新的文本短语把闸放宽到放行 `self`，`C1` **先红**，逼他同时决定「`self` 的侧」（`AddSide` / `ownSideInPool` 都没写这一档）。 |

> ⚠️ 我**没有**去「修」那个空池形状：在 `spec` 唯一生产者不放行 `self` 的前提下，任何改动都是**触不到的死代码**（铁律 18·0「默认复刻原版」，而原版没有这条文本侧）。若将来真要支持，`ownSideInPool` 与 `ResolvedSide` 需要**一次性对齐**，见 §五·2。

## 五、顺手发现（⛔ 一条都没动手改）

1. 🔴 **`CardDisplayEffects` 的 `SetVertexTint` 发生在材质还是 `Sprites/Default`（**有** `_Color`）的那一刻**：真正换成 `Border Effect For Level up`（无 `_Color`）是**之后** `AnimateUIMaterialProperty` 干的
   （`Shell/CardDisplayEffects.cs` 的 `BuildImage`：`quad.SetVertexTint(tint)` 在前、`AnimateUIMaterialProperty` 挂在后）。
   ⇒ 「材质无 `_Color` ⇒ `UsesVertexTint`」这条不变量在**调用那一刻**是**空真**，只在换材质之后才有意义。
   **我的夹具照生产次序建模**（先推色 → 再换材质），所以断言测的是**最终态**。⚠️ 若将来有人把「换材质」挪到 `SetVertexTint` 之前，断言仍成立（通道已开），**但那时就没人验「推色时材质还没有 `_Color`」这一档了** —— 记在这里，供以后判断。
2. ⚠️ **`EffectTargetSpec.Side` 的口径三处不完全一致**（都不影响今天的行为）：
   · 文档：`self / own / enemy / any`；
   · `EffectText.PickTarget`：只放行 `own / enemy`；
   · `EffectText.ResolvedSide`：`self` 当 `own` 的**别名**。
   ⇒ `B-279` 判「不可达」正是靠第二条。**建议调度台立一条**（`B-27x`）：若哪天真要支持 `self` 文本侧，`PickTarget` / `ownSideInPool` / `AddSide` / `ResolvedSide` 必须**一次性对齐**（⛔ 不许只放开出口闸）。
3. ⚠️ **`EffectResolverPartial_B114W30.cs` 的 `CardCriteriaExcludeNotSelfEmptiesPool` doc 有一句要订正**（不在我白名单）：它写「这条对**单位卡的棋盘那批**也对 ⇒ 棋盘那批同样**全淘汰**」。`B-278` 之后棋盘那批走**逐候选**（因为 `thisCard` 不再是 `null`），**结论等价**、机制变了 ⇒ 建议改成「棋盘那批也走逐候选（候选都不是它 ⇒ 全淘汰）」。
4. ⚠️ **`B114_W31_Assert` 与我的 A/B 段有重叠**（它 A5–A8 也测 `UIBorderGlow` 路）。我**没有**去改它（`W-37` 正在改）；重叠是有意的：我的断言用的是**通用不变量 + 双路**，它测的是**更细的顶点色/网格行为**。若调度台想合并，⛔ 别把 `B-269` 那条通用判据删掉（那正是本波要补的那一格）。
