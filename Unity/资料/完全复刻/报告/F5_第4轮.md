## 二、① P0 —— `AiScripted` TapCard 软锁（**根因 + 修法**）

### 2·1 现象与数据（现读，不是转述）

`RuleEngine/Resources/tutorial_stages.json` 现读：6 关 / 79 回合 / 462 条动作 / **152 条 `playerAction=true`**。
其中 `TapCard(120)` 恰好 **5 条**，全在第 5 关（`Warpforge_TutorialStage5`，Aeldari vs Sautekh）：

| 位置 | acting |
|---|---|
| stage4 · turn6 · act2 | `PlayerMinion` `ASH11 Striking Scorpion` |
| stage4 · turn6 · act7 | `PlayerMinion` `ASH5 Storm Guardian` |
| stage4 · turn10 · act0 | `PlayerMinion` `ASH12 Swooping Hawk (tutorial)` |
| stage4 · turn12 · act4 | `PlayerMinion` `ASH4 Guardian Defender` |
| stage4 · turn12 · act5 | `PlayerMinion` `ASH5 Storm Guardian` |

四张卡现读**全带 `Waystone`**（`cards_engine.json`：ASH4 `[Waystone, Shuriken 2]` · ASH5 `[Waystone, Shuriken 1]` ·
ASH11 `[Waystone, Stealth, Shuriken 2]` · ASH12 `[Waystone, Flying]`），
而 **turn6 act1 的 SmallTip 原文就是**「Click on the Spirit Stone to collect it.」
⇒ **这 5 条要玩家做的是「点那颗灵魂石去收集」**（不是点开看牌）。

### 2·2 原版怎么推进（**判据：两份反编译互证**）

1. **推进口在 `CardScript.OnTouchUpAsButton`**（🥈 `d:/2/tools/cpp2il/out_cpp2il_dev_ilspy/CardScript.cs:10114-10183`）。
   场上卡那一档（`cardState ∈ {inPlay(2), inPlayAttacking(3), inPlayAminingAttack(17)}`）**分两条支**：
   ```
   bool remnant = SupportMethods.IsAeldariRemnant(this);
   if (!remnant) { displayingCardFlag = true; DisplayCard(this, displayY:true, mulliganException:…); }
   else          { BattleMgr.TryUsingWaystone(this); }
   ```
2. `SupportMethods.IsAeldariRemnant`（🥇 `decomp_full/SupportMethods__IsAeldariRemnant.c` 全文）=
   **`rawCardData.cardArmy(+0x2c) == CardArmy.SaimHann(30)` 且 `isRemnant(+0x65)`**
   （字段偏移 `dump.cs` 的 `ObtainableItem.cardArmy // 0x2C`；枚举 `CardArmy.SaimHann = 30`）。
3. `BattleManager.TryUsingWaystone`（🥇 `decomp_full/BattleManager__TryUsingWaystone.c`）→
   `BattleManager.CanUseWaystone(bm, card, isPlayerAsking:1, …)` 五道闸 → 入队 `useWaystone` 动作。
4. 收集是**一个动作**⇒ 结算完走 `BattleManager.FinishResolvingAction`：
   `CheckIfWaitingForPlayerAction` 为真 ⇒ `AiScripted.PlayerChoiceAction()`（**`actionCounter += 1`**）⇒ 重启脚本协程。

**⇒ 结论：「推进」根本不经过 `CheckIfWaitingToClickCard`。** 那个谓词
（`decomp_full/AiScripted__CheckIfWaitingToClickCard.c` 全文 + 🥈 `AiScripted.cs:611-801`）是
「这次点击算不算脚本要的那一下」的**查询**（解析不出被点名那张 / 就是被点那张 ⇒ true），
它的**唯一调用方在 `CardScript.OnTouchDown` 的缺失体里**（两份反编译都缺）。
⇒ E4 那条「零调用 ≠ 死代码」的判断是对的，但它**不是**推进链。

### 2·3 我们的断点（真因）

`BattleDriver.BoardPress` 的「松手且没拖够」那一支**只有** `ToggleUnitCard(side, s)`（开/关大卡窗）——
**没有 `IsAeldariRemnant → TryUsingWaystone` 那一半**。而收集只挂在**拖出选择器**那条路
（`OpenCommand` 的 waystone 支）上。

⇒ 玩家按提示**点**那颗灵魂石：开出的是大卡窗（6 关 `hideLargeCardDisplay` 现读**全 false** ⇒ 窗真会开），
`ContinueTutorialScript()` 一次都不被调 ⇒ 脚本永远停在 `TutorialStep.WaitingForActor`。
而 `TutorialScript.PermitsPlayerAction` 的 ⑤ 只认 `useWaystone`
（`RuleEngine/Core/TutorialScript.cs:1255-1258`：`if (T != TapCard) return false; if (a.Action == useWaystone) return true;`）
⇒ **玩家的其它动作全被闸门挡** = 硬卡死。**与 E4 的描述一致，但根因是「缺一支轻点」，不是「闸门太严」**
（闸门口径与原版**一致**，⛔ 不需要也不允许放宽）。

### 2·4 修法（已落码）

新增 `BattleDriver.TapBoardCard(int side, int slot)`（类尾，`:32541`），并把 `BoardPress` 的
`if (!dragged) ToggleUnitCard(side, s);` 换成 `if (!dragged) TapBoardCard(side, s);`（**单行替换、行数不变**）。

```
TapBoardCard:
  若 (u != null && u.IsRemnant && u.Card.Faction == SpiritStoneFaction)   // = 原版 IsAeldariRemnant
     敌方那侧 ⇒ return（原版 CanUseWaystone ① 挡掉，**连卡窗都不开**）
     回放局   ⇒ return（我们自己的只读闸，原版无此概念）
     CanCollectWaystone == OK ⇒ OpenCommand(slot)   // 收集那一段仍只有一处（⛔ 不另抄判据）
     否则只记一句日志（原版 TryUsingWaystone 失败也是只 CustomDebug.Log、不改局面）
  否则 ToggleUnitCard(side, slot)                                         // 原版 DisplayCard 那一支
```

**为什么这样就够（灭自证思路）**：`OpenCommand` 的 waystone 支已经在收尾调
`ContinueTutorialScript()` ⇒ 指针 +1 ⇒ 下一帧 `DriveTutorialScript` 接着推。
**这条路不依赖任何新状态**；把 `TapBoardCard` 换回 `ToggleUnitCard` ⇒ 那 5 条立刻又卡死（可断言，见 §六·② A4）。

⚠️ **顺带的等价性收益**：原版对**敌方**灵族残骸也是 `TryUsingWaystone` 然后被 `isPlayer` 闸挡掉、**不开窗** ——
我们现在也这样（改前会开窗，是一处静默偏离）。

### 3·1 关于第 1 件（`SetSavedMana`）—— 做了什么 / 没做什么（⛔ 别混）

**做了**（逐句照 `.c`）：
- `manaAccumulationVFX{ON,OFF}` **两颗都建**（`40k_battle_energy_full` / `…_empty`，rect 与 ON 那颗**逐位相同**）；
- `SetSavedMana(saved, unused, total, useNumberChange)` 的 ①②③；
- `ToggleManaAccumulation(on, cb)` 的 ④⑤⑥：`Kill` → **`Mathf.Approximately(当前α, 目标α)` 整段 return** →
  **先把颜色写成反档**（`on ? 0 : 1` —— 反编译那句是 `param_2 ^ 1`，⛔ 别写成「写目标档再淡入」，那是零位移）→
  `DOFade(target, 1.0 s)` + `SetDelay(0.5 s)` → `DOVirtual.DelayedCall(1.0 s, cb)`（**onComplete 比补间早 0.5 s**）→
  音效按**静态 `Time.frameCount`** 去重；
- 自检口：`SetSavedManaForTest(...)` / `EnergyAccumOnVisibleForTest` / `EnergyAccumOffVisibleForTest` / `ManaAccumSoundCount`。

**没做（两条硬缺口，都有理由）**：
1. **引擎没有 `savedMana` 这一格**（`PlayerState.ManaCarry` 在 `BeginTurn` 立刻兑现并清零）⇒ **生产路径无人调用**。
   所以组内状态默认是「**未知**」⇒ 保持原来那一档（ON 亮 / OFF 灭）⇒ **今天的画面一个像素都没变**。
   接线点写在报告 §六·②（给 E1–E4）。
2. **音效 cue 查不到**：`manaAccumulated` / `manaAccumulatedUsed` 在本机**全仓 0 命中**
   （`MyGame/Assets` 全量 + `素材/` + 音效元数据都搜过）⇒ **只记日志、不放音**，⛔ 没编一个假 cue 名。
3. 附带一条如实记：我们 `UpdateHud` **每帧**按引擎值重写那颗数（原版是事件驱动）⇒ 真接上 `savedMana` 之后
   那一处要写 `Energy − savedMana`，否则「银行里那 1 点不计数」的显示会被下一帧盖掉（也写进改动请求）。

### 3·2 关于第 3 件（`OnApplicationPause`）—— 把 E5 的两条「没确认」钉死

机器码逐句（VA `0x1806221B0`）：

| 拍 | 指令证据 | 语义 |
|---|---|---|
| pause 支 `0x18062236A` | `mov [rdi+0xC8], rax`（`DateTime.get_UtcNow`）· `movss [rdi+0xD0], xmm0`（`Time.get_realtimeSinceStartup`） | 存两个时间戳 |
| resume 支 `0x180622281` | `DateTime.operator-` → `TimeSpan.get_TotalSeconds` → `cvtsd2ss` = `secs`；`xmm7 = realtimeSinceStartup − [rdi+0xD0]` | 两个「离开多久」 |
| 闸 ① `0x180622301` | `comiss xmm1(=0), xmm6(=secs) ; ja 结束` | `secs < 0` ⇒ 不补 |
| 闸 ② `0x180622338` | `comiss xmm0(=1.0f), xmm1(=abs(secs − realDelta)) ; ja 结束` | **`|secs − realDelta| < 1.0` ⇒ 不补** |
| 生效 `0x18062234B` | `cmp byte [rdi+0x87], 0` + `addss xmm0, [rdi+0x7C] ; movss [rdi+0x7C], xmm0` | 只在**倒计时阶段**（`clockCountdownFlag`）把 `secs` 加进 `timeInBackground` |
| 消费 `/` `ClockManager__Update.c:41-43` | `elapsed = (realtime − startTime − timePausedOrDiscounted) + timeInBackground − timeInAnimation` | **补进「已用时长」** |

⇒ 订正 E5 §五·2：**① 补进已用（不是把剩余加回去）；② 「≥1 s」的门槛不是秒数本身，而是两个时钟的「差」**
（`realtimeSinceStartup` 在后台照走 ⇒ 差 ≈ 0 ⇒ **不补**；只有它冻住时才补）。
⇒ 我们的等价物 = `_clockLeft -= secs`（`_clockLeft` 是递减的剩余量），闸逐条照抄；另加我们自己的两条（`_replaySession` 外的
`Ctx.Active != _me` / `Ctx.IsOver`，与原版 `ClockManager.Update` 头两句同口径）。

## 四、③ 卡牌线两处收尾核对（`spellType` / `spellTypeKnown`）

**核过，无遗漏。** 现读 `BattleDriver.cs` 里 `new CardData` 只有 **4 个站点**：

| 站点 | 是不是真卡 | 要不要 `spellType` |
