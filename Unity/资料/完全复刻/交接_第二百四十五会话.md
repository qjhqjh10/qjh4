## 一、本会话做了什么

### 1.1 PC 排位结算（OFF-209 子项）

- 根因：PC 便携版走**进程内假服务端**（`EmbeddedServerProbe` → `Server/InjectionPipeline.cs`），
  结算只插战斗记录，`EndMatchData` 全是模板里的 0 ⇒ PC 段位永远铁 I。
- 新增 `Server/Ranked.cs`（第三份实现，与 `server.py` / 安卓 `ranked.js` 同口径）：Honours + 3 连胜 +2 +
  段位保护 + Legendary Elo（K=32）+ 赛季护盾 + 阵营分。
- 接线：登录 `PlayerStatistics` 播种 · `GetLeaderboard`（含名册 6 人）· `InitializeLiveOps` 的
  `Persistence.currentRating/seasonNumber` · 1089/1105/1111 结算写 `EndMatchData` + 战斗记录真分。
- **坑**：`GetLeaderboard` 是 `ExecuteCloudScript` 的一个分支（CloudHandle 1056），不是 PlayFab 接口（坑 654）。

### 1.2 小冲突「未排名/排名」开关真正生效

- 以前：`server.py` 的 1111 分支与安卓 `ranked.js` 都硬编码 `isRanked=true`。
- 判据：原版 1111 载荷里**没有** `isRanked`（`FastModeBaseEvent.RecordMatchFinished`）；开关状态只能读
  `GameStaticData.unrankedFastMode`（= `RankedFastMode.IsRanked` 镜像，`RankedEventBase.ToggleRankedMode` 同时写）。
- PC：新增 `Probes/RankedModeProbe.cs` 每秒读静态字段；安卓：`ranked.js` 主线程定时器刷**缓存**（⛔ 结算线程不碰 IL2CPP）。
- **坑**：安卓克隆体 `Initialize(IRankedEvent)` 没把事件写进字段 ⇒ `Clicked()` 一直翻**经典**事件（坑 655）；
  改成直接对小冲突事件调 `ToggleRankedMode(bool)` + `SetState` 刷旋钮。

### 1.3 传奇段显示 `−2380` → `120`

- 判据：`RankingDisplay.cs:148-152` `if (FeatureConfig.Check("ZeroBasedRank")) value = points − 2500;`
  （原版 Legendary Elo 从 2500 起；我们标尺 0…120）。
- PC：Harmony postfix `FeatureConfig.Check` 把 `ZeroBasedRank` 强制 false。
- 安卓：`Check` 被 IL2CPP **内联**、钩不到 ⇒ 改钩 `RankingDisplay.Initialize`，`points ∈ [120,2000)` 时
  `args[1] = points + 2500`（内部再减 2500 还原）。坑 656。

## 三、关键结论 / 判据（新会话直接用）

1. PC 便携版 = **进程内假服务端**（`AutoServerProbe` → `EmbeddedServerProbe`），`server.py` 的排位/统计逻辑**不生效**；
   两份 C# 实现 = `Server/Ranked.cs`（排位）、`Server/BattleStats.cs`（统计）。
2. 小冲突开关的判据 = **`GameStaticData.unrankedFastMode`**（1111 载荷里没有 `isRanked`）；经典用载荷自带的 `isRanked`。
3. 传奇显示减 2500 = `ZeroBasedRank`；安卓 `FeatureConfig.Check` 被内联，只能钩 `RankingDisplay.Initialize`。
4. `GetLeaderboard` 走 `ExecuteCloudScript` 分支（1056），⛔ 不是 `/Client/GetLeaderboard`。
5. 安卓 frida：命名空间类要写**全名**（`Everguild.LiveOps.Config.ConfigManager`）；根命名空间用简名（坑 657）。
6. 假服务端的 `onUserConnected.ServerTime` **写死 2026-01-01** ⇒ 客户端所有倒计时都冻着（「结束于 423 天」就是这么来的），
   **用户 2026-11-26 定：不修**（坑 658）。
