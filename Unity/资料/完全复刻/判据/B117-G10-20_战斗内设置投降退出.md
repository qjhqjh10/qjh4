## 二 · 本批改了什么（逐条）

1. **`SettingsPanel.cs` `OnShadeClicked`（现 `:1357`）** —— 列表没开时 `Hide()`（= 原版 `Dark Shade` 的 `CloseBackgroundButton → CloseWindow`）。
   同时**就地改掉**了原来那句错的判据注释（原文「`MB_4927` 的 `BackgroundCloseButton` 两个字段都空 ⇒ 原版点它什么也不做（不关设置窗）。⛔ 别在这儿 `Hide()`」，在 `:966-976`）——
   错因：**只读了序列化 `m_PersistentCalls`**，而监听是 `Awake` 里 `AddListener` 加的（铁律 5 就地改，并留更正痕迹）。
2. **`SettingsPanel.EscPressed`（现 `:1992`）** —— 列表没开时 `Hide()`（= 原版 `WindowsManager.Update → BattleSettingsWindow.ESCPressed → base → Close()`，`closeOnESC=1`）。
   文档同步改写（原来写「⛔ 窗不关 / 本件不是 `GameWindow`」）。配套：`PointerFrame`（`:2365`）在关窗后当场返回；
   `EscPressed()` 头部补了 `if (!EscDown()) return false;`（它是「处理一次 ESC 按下」的口，
   **直接调它而这一帧没按键 ⇒ 什么都不做** —— 这一条同时让 `Editor/BattleScene.cs:20224-20228` 那条老断言**不会变红**）。
3. **`SettingsPanel.SyncFromOpen`（新方法，`:2898`，由 `Show()` 的 `:2555` 调）** —— 每次打开回填三根音量滑块
   （`WfSlider.SetValue(v, fire: false)`，⛔ 不回写音量）+ `RefreshTexts()`（等价原版 `Open()` 里的
   `languageSelector.Initialize()` 那颗「当前语言名」）。**追加在类尾**（⛔ 别往中间插）。

## 三 · 与 `Editor/BattleScene.cs:20224-20228` 那条老断言的关系（本批白名单外，**不会变红**）

那条 ★ A921 判别式写的是「列表**没开**时 ESC **本件不吃**（返回 false、窗照旧开着）」，它**直接调**
`sp.EscPressed()`（不经过 `PointerFrame`、也没有按键）。

本批为此在 `EscPressed()` 头部加了 `if (!EscDown()) return false;` —— 「处理一次 ESC 按下」的口在
**这一帧根本没按键**时什么都不做 ⇒ **那条老断言照旧是绿的**（它没按键）。

⚠️ 但它的**文案已经与语义不符**（真正的行为是：**ESC 真按下时**列表没开 ⇒ 关窗）。
建议调度台把那一组换成「按一下真 ESC」的写法（判据 = `WindowsManager.Update` 的派发链 +
`GameWindow.ESCPressed` + `closeOnESC = 1`）：

```csharp
sp.Show();
Check(sp.Visible, "（前提）窗又开出来了");
SettingsPanel.EscapePressedForTest = true;
sp.PointerFrame(f5, false);                       // 生产那条每帧入口
SettingsPanel.EscapePressedForTest = null;
Check(!sp.Visible,
      "★ B117-G10-20：列表**没开**时按 ESC ⇒ **关设置窗**（原版 `WindowsManager.Update → "
    + "BattleSettingsWindow.ESCPressed → base.ESCPressed → GameWindow.Close`；`closeOnESC = 1`）"
    + " —— 把 `EscPressed()` 改回「列表没开就不吃」这条就红");
```

（本批的独立断言文件 `Editor/B117_G10_20_Assert.cs` 的 B1/B2 两条**就是**上面这个写法，可并行存在。）
