## 〇、先读这 10 行

1. **服务端现在只被 4 个 PlayFab 方法命中过**（445 条请求）：`LoginWithSteam` 121 · `ExecuteCloudScript` 218（其中 `onUserConnected` 112 / `InitializeLiveOps` 105 / 兜底 1）· `GetObjects` 105 · 以及**一次**旧路由造成的 `404`。**其余 11 份模板一次都没被请求过**（统计见 §二）。
2. **服务端是完全无状态的**：除日志外不写盘（`server.py` 里没有任何 profile 写口；`UpdateUserData.json` 的 `_todo` 自己写着「本响应不落盘」）。⇒ 任何「保存」类云函数即使补了模板，也不会持久化。
3. **没实现的 CloudHandle 不会出现在 `missing` 里**：`ExecuteCloudScript` 有兜底模板 `responses/ExecuteCloudScript.json`（`FunctionResult=null` + `Error` 非 null），客户端走 `onError`。⇒ 补 CloudHandle 时**不能靠 `__health.missing` 驱动**，只能靠 `_index.tsv` 的 `template=ExecuteCloudScript.json` 那一行（现在只有 1 条）。
4. 🔴 **20 个 Config 的真实来源 = `ExecuteCloudScript.InitializeLiveOps` 响应的 `FunctionResult.TitleData`**，不是登录 payload。
   - 判据：`PlayerDataManager.cs:4570` `playerDataManager.configs.Unpack(result.TitleData)`；真体 `PlayerDataManager._UnpackUserInfo_d__522__MoveNext.c:55-70`（`InitializeLiveOpsAndConfig` 的 Task.Result 的 `+0x18` = TitleData → `ConfigManager.Unpack`，`+0x20` = SharedEventData，`+0x10` = HandlerData）。
   - ⇒ **`判据/B153_C_20配置DTO.md` §0·2 第 48 行「InitializeLiveopsResult.TitleData 没被 Unpack 用到」是错的**（同一份文件 §〇 的链路图也画反了）。登录 payload 的 TitleData 只被 `OnlineData.GetTitleData` 读 `ServerVersion` / `AddressablesConfig` / `ConnectionSettings` / `OverrideConfig` / `CloudscriptRestrictedVersionConfig`（`PlayerDataManager.cs:4331 / 11171 / 11191 / 11202`）。
   - 现在 `FeatureConfig` 在**两处都有**（登录片段 + InitializeLiveOps），所以「它生效」无法区分是哪一份；**要补的 19 个必须写进 InitializeLiveOps 的 TitleData**。
5. 🔴 **登录「自然完成」仍未验证/很可能仍未修好**：**全部成功轮都开着 `WF_OFFLINE_FINISH=1`**（`probe.log` 的 `[FINISH] 已把 currentState 从 20 推到 50`），即登录仍停在 `state 20 processingPlayerData`，由 mod 强推。上一次 `FINISH=0` 的结论是「停在 20」（`cycle_finish0.log`，但那是在 ⑥⑦ 两条桩之前）。

8. **卡组数据只能放 `UserReadOnlyData`（首选）**：`"PlayerDecks"` 这个键走字符串重载、`checkPublicData=false` ⇒ **只读 `UserReadOnlyData`**（`PlayerDataManager.cs:11454`；`OnlineData.cs:145-190` 的查找顺序：先只读段，`checkPublicData` 才回落 `UserData`）。兜底才是 `PlayerDataKey.Decks`（`UserData`，`11459`）与 `CurrentDeck`（`11472`）。
