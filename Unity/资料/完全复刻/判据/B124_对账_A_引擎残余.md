### §3 `B123-DEFK` —— 双发，不是过滤器

**日志证据**（`d:/4/_tmp_view/ruleengine_b123c.log:825690`，⚠️ 该文件在两处重复出现，`:1046628` 同一行）：

‖ 附魔层：把「Deffkopta」挂到「Deffkopta」身上（#id 0，buffType 15，spellType 0，来源 Deffkopta）
‖ Deffkopta 触发 RALLY：「Other friendly Deffkopta deal 2 damage to a random enemy」
‖ 潮涌 2：Deffkopta 造出 1 张复制（进了手牌；它自己带着 1，打它才会再带一张）

‖ Deffkopta·Deffkopta·trigger#0：`chosenAbility 10`（doDamage）⇒ 对 1/1 张各 2 点伤害

**三层判读**

1. `OtherThanSelf` **没有失效**：`DoEachUnitDeal`（`EffectResolver.cs:3617-…`）里 `:3656` `if (op.OtherThanSelf && u == ctx.ActingUnit)` 正常生效 —— 日志写「**1 个单位**各 2 点开火…**3 个不满足主语筛选**」。若 `ActingUnit == null`，这里会是「2 个单位各 2 点」。⇒ 台账里「`u == ctx.ActingUnit` 在附魔触发路径上可能为空」的假设**不成立**。
2. 第二条 2 点来自**附魔层**：`by` 串 = `carrier·card·trigger#N`（`EnchantmentExecutor_B115.cs:98/105/113/119/125/132/139/145`），日志正是 `Deffkopta·Deffkopta·trigger#0`；它跑的是附魔模板自己的能力。
3. 附魔模板是**真的**（不是我们造的）：`enchantment_templates.json` id `c40a06616a2968240b1f765d0f919b69`，`mName = 28 Goff-Deffkopta_enchantment`，`owners = [{id: GOF56, buffType: 15, trigger: 0, inPool: true}]`；它唯一那条 ability = `trigger 0 / ca 10 / ta 10`，criteria = `enemyUnits 1 + includeHero/Minions/Remnants`，`damage {min 2, max 2}`。⇒ **「打 2 点随机敌人」这条载荷只存在于附魔模板里**。

**所以正确的口径**：卡面 `Other friendly Deffkopta deal 2 damage` 的原版实现 = 「本卡打出去时，给每只**别的** Deffkopta 挂一件 `buffType 15` 单次附魔，附魔自身结算 2 点」。我们的正文路（`EffectText` 解析出的 `eachunitdeal`，`Amount = 2`）把同一件事**又做了一遍**。

**修的方向（两种，选一，⛔ 别两边都留）**
- (a) 正文路让路：这类「正文 + 结构化附魔」同时存在的卡，在 `ops` 非空时**不再**跑正文那条 `eachunitdeal`（但要先确认它不是别的原因产生的）；或
- (b) 附魔路让路：若证明原版靠正文结算，则 `buffType 15` 的 self-enchantment 在 trigger 0 上**不该在同一次触发里立刻跑**。

判据倾向 (a)：卡自己的 `abilityDamage ab1/lg0` 是 `{min 1, max 3, opt 90}`（= 逐目标掷 1–3），与卡面「2 点」**对不上**，而附魔模板是**精确的 2/2** ⇒ 真载荷在附魔那张上。这条差异本身也值得记账（见 §九·4）。
