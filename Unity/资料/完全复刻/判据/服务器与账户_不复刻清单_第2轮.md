### 〇·二 判 D 的三条硬门槛（本次调查的执行口径）

1. **必须能说出「这条逻辑在客户端里根本不执行」或「只有服务器返回值在用它」。**
   说不清 ⇒ 标 **需人判**，不许判 D。
2. **不许拿「名字像网络」当判据。** 本清单查实 **两个反例**：
   - `PlayerManager` —— 名字像「玩家数据服务器」，实际是**战斗侧本地状态**（`AddFaithMana` / `GetCurrentSpiritStone` / `DestroyManaSlot`）⇒ 档 c；
   - `UnityContext` —— 名字像「遥测」，实际是**主线程派发工具**（`WorkHandle`）⇒ 只因「唯一消费者是 PlayFab 回调」才成立。
3. **不许拿「反编译里搜不到赋值点」当判据**（`CLAUDE.md` §三 那条：ILSpy 把私有 setter 反编译成 `obj = this + 偏移`，字段名会丢，扫出来的是**假数字**）。
   本清单一律用「**方法体里出现了哪个 SDK 符号**」判，做法见 §九「本次怎么量的」。

## 二、怎么用这张表（调度台操作四步）

1. **「建议 = D」的行** ⇒ 把账里那个类的对应行判 `D`，并把**「判据」列**抄进 `差异` 列（那是可复核的凭据）。
2. **「建议 = 保留 UI ／ 断后端」的行** ⇒ **只判「发请求 / 写回服务器」的那几个方法**为 D；
   同一个类里的**建视图 / 缓存 / 组装 / 排版 / 命中**方法**保持 C 或 A**，⛔ 别整类判 D。
3. **「建议 = 必须做」的行** ⇒ **不许判 D**；若账里当前是 D（例如 `PlayerManager` 的 37 行），**要改回来**。
4. **档 b 里已经判了 D 的那 320 行，默认不动** —— 它们的形态是「**UI 已 A、动作断**」（例：`AllianceMemberOptionsPopup.OnKickPlayerClicked` 的 A 是「钮建好了」，D 是「踢人这个动作要服务器」）。
   只有 §五 点名的那几类要改。
