## 3 · 连锁位移（调度台问的「整体后移多少」）

### 3·1 结论：**这 5 处合起来不是常数**

`GetRandomInt` **只在 `maxExcl > minIncl + 1` 时前进一格**，而 5 处的求值次数全是**数据相关**：

| 处 | 每次调用吃几格 | 一局里求值几次 |
|---|---|---|
| 1·1 `RandomValue(8)` | 1 | **0**（池内无此 option） |
| 1·2 `TrimRandom` | 1／次，`list.Count<=1` 时 0 | 每次「随机取 N」= `min(keep, count)` 次；只 7 条判据会走 |
| 1·3 `SkipChance` | 1／次 | **`Σ_轮 (扫到删掉为止的条数)`**，前 `MinSkips` 轮 0 ⇒ **不可预测** |
| 1·4 / 1·5 环境卡 | 1（`count>=2`）／0（`count==1`） | 每相位最多 1 次（AI 有环境卡时） |

⇒ 「整体后移 N 格」这个说法**只对硬币那一条成立**（见 3·2）。对这 5 处，**位移量随对局内容变化**，
而且 `GetRandomInt` 取的是 `数组[游标 % 100]`、再 `v % (max-min)` ⇒ **位移后不是「数值平移」，是整条序列换掉**。

### 3·2 硬币那一条（`B141-COIN-FLIP`）才是**常数位移 = +1**

`DrawFirstSeatRandomInt()` = `GetRandomInt(0, 2)` ⇒ 开局**无条件吃第 0 格**，之后所有取格点整体 **+1 下标**。
⚠️ 但 §1 已核：**它今天没接线** ⇒ 现在实际位移 = 0。**接线那一刻起全场 +1**，这是唯一能写死数字的一条
（也正是施工单 §2·4「连锁位移清单」只写了它一处的原因）。

### 3·3 对本批回放工作的直接含义

旧录像在 5 处改完之后**必然演成另一局**（不是因为数值后移，而是整条序列换了）⇒ 回放游标记账是**前置条件**：
- `ReplayStore` 的两列（`randomCursorBefore` / `randomCursorAfter`）**已落**（`ReplayStore.cs:1064/1073` + 体检口 `:1086`）；
- 录制端 5 个记账口 + 回放端恢复/断言仍在 `BattleDriver.cs`（施工单 §3·2 / §3·3），**等它空出**。
