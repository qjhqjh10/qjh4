## §1 账本身的结构（先把口径说清，否则数字对不上）

`R0_资源覆盖账.tsv` 13 列：`文件 PathID 类型 名字 我们有没有用 用/读判据 状态 深度 原版引用链 地址able路径 字节数 CAB 处置`。

- **`状态`（第 7 列）= 原版可达性**（原版可达 246,678 / 原版不可达 934）。⚠️ 任务简报里写的「账里 `状态` = 原版不可达」指的是这一列。
- **`我们有没有用`（第 5 列）= 我们的使用度**（U1/U1b/U2/U2b/U3/从没看过/无独立名字）。这 17,371 行就是这一列取 `读过（索引）+ 读过（文档）+ 从没看过`。
- **`深度` = 0 ⇒ 根对象**；**`深度` = -1 ⇔ `状态` = 「原版不可达」**（实测 101 行，一一对应）。
- **`原版引用链` = BFS 父链**（生成脚本 `d:/4/_tmp_view/wfres/r0_report.py` 的 `parent[]` 树）。
  格式 `本对象 <- 直接引用者 <- 再上一级 <- …`；`hops<5` 就补 `…`（**截断**）。
  「引用者」= 在引用图里**第一个 BFS 达该对象的源**，对 Transform/GameObject 即父链 / 组件宿主。

## §2 U1(账) 的已知盲点（= 为什么还要做这一层归因）

账里「没用上」是**按名字字符串**判的（U1 精确同名 / U2、U3 整串匹配）。它结构上**看不见**三类东西：

1. **预制体子件**：一个 prefab 我们整体用了、但它内部几百个 GameObject/组件**没有单独同名文件** ⇒ 全部落「从没看过」。这不是缺口，是名字判据的副产品。
2. **代码构造的窗口**：我们的窗口是**运行时用代码搭的**（`Shell/*.cs`），不是导入的 `.prefab` ⇒ 原版同名 prefab 在账里照样「没用上」。
3. **第三方 / 引擎类**：`globalgamemanagers.assets` 里 4,144 个 **MonoScript** 是**类定义**（含 DOTween / PlayFab / TMP / SIMD 之类），根本不是要复刻的「资源」。

本层归因 = 把每行**追到功能级根**，再判它落到哪个桶。

## §3 追根算法（每行一个根）

| 情形 | 根怎么取 | 命中行数 |
|---|---|---|
| `深度 == 0` | 根 = 自身名字 | 5,060 |
| `深度 > 0` 且链**完整**（末元素是名字，不是 `Type#pid`） | 根 = 链的**最末命名祖先**（跳过 `Transform#/#MonoBehaviour#` 之类结构件）= 账里的真根 | 7,494 |
| `深度 > 0` 且链**截断**（末元素是 `…`）但可见段里有命名祖先 | 根 = 可见段里**最深的命名祖先** | （并入上格） |
| `深度 > 0` 且链截断、可见段**全是 `Type#pid`** | **重放 BFS** 求根（见下） | 2,629 |
| 仍追不到（场景深层裸结构件） | 根 = 空；用 **bundle** 定域 | 2,087 |

**重放 BFS 的判据**（`_tmp_view/b99r7/replay.py`）：
- 用 `r0_objects.tsv`（file,cab,pid,type,name,container）+ `r0_edges.tsv`（938,803 条引用边）重建同一张父树。
- 根集 = 有 Addressable 容器路径者 + 7 个内置文件全部对象（**未加场景 bundle 的 `m_Father==0` 根**，因为那需要 UnityPy；对本次要解析的 menus / battleprefabs 无需）。
- 校验：对账里**链完整**的 2,284 行比对「账的根名 vs 重放根名」→ **1,835 一致 / 75 不一致 / 374 重放不可达**。
  75 条不一致**全是 `bundle_Waprforge_monoscripts` 的 MonoScript**（同一个类挂多处，账取一处、重放取另一处，两边都对）。✓ 重放可信。
- 用它把 `bundle_menus_assets_all` 里 2,419 条**截断到只剩 `Type#pid`** 的行解到具体预制体（例：`Rewards Base Submenu Variant` / `Missions Tab` / `Sunset Popup` …）。menus 包 297 个预制体根都带 addressable 容器 ⇒ 重放能追到它们。

## §4 功能域判定（token 匹配，非裸子串）

把根名（缺根时用自身名）按 `[a-z0-9]+` 切词，**短词（<5）只认整词、长词才认前缀**（否则 `unit` 会误中 `unity`、`card` 会误中 `cardframe`）。
先做 bundle 硬规则（音响/卡牌包/活动图/图集），再逐域跑关键词表（顺序：音频→特效→战场→社交→联机→教程→排名→轮抽→日常→活动→锻造→战役→商店→卡组→收藏→卡牌→战斗→菜单外壳），最后 bundle 兜底。
域清单 = 任务给的 19 个 + `引擎内置`（Unity 内置）+ `—`（不可达/非资产）。

## §5 分桶规则（每条只落一桶）

| 桶 | 判据（按优先级） |
|---|---|
| **① 原版不可达** | 账 `状态`=原版不可达（101 行，其中 82 个是 AssetBundle 清单文件） |
| **⑤ 需人判** | ① `类型=MonoScript`（类定义、多实例、非资源资产，4,693 行）；② 追不到根且无命名祖先（场景深层裸结构件）；③ 功能域不可判（未知，4 行） |
| **③ 动态/间接可解释** | ① 引擎内置文件（globalgamemanagers/resources/level1/sharedassets0）；② level0 Bootstrap 引导/服务对象；③ battlearena/mainmenu/simpletransition 场景对象（ArenaBuilder/外壳重建）；④ AssetBundle 清单；⑤ **父件已被我们使用**（根的账使用度≥已用/搬运/数据表）⇒ 随父件加载；⑥ **根名对应我们已实现的类/近似同名** |
| **④ 真缺口（候选）** | 已建功能域内、根对象既**没有同名实现**、也不在「已用父件」下、无静态加载口 |

**「根名对应已实现的类」怎么判**（`class_match`）：把根名归一化（去非字母数字、小写），与我们 `MyGame/Assets/**/*.cs` 里抽出的 2,102 个类名 + 929 个文件名（并集 2,315）比：同名 / 长度≥10 的互相包含 / 公共前缀≥10 ⇒ 命中。
实测这层把 2,528 行（155 个根）从 ④ 救回 ③，例：`Deck Editing Menu`↔`DeckEditingWindow`、`Main Menu Settings Window`↔`SettingsWindow`、`Collection Menu Variant`↔`CollectionWindow`、`Practice Mode Menu`↔`PracticeModePopup`。
**未命中的近名**（④ 理由列里标了 `近似类=`）如 `Draft Mode Timed Mode Window` ↔ `DraftModeWindow`（公共前缀仅 `draftmode`=9 <10）**留在 ④ 但标注**，请按根确认。

## §6 ③ 的「动态加载」判据怎么找到的

### 6.1 `Resources.Load` 全量调用点（49 处，34 条不同路径）
扫描 `MyGame/Assets/**/*.cs` 的 `Resources.Load/All/Async(...)`。完整文件:行 见 `报告/B99_R7.md` §4。
- **主分类：这些路径全是我们自己的结构**（`Art/cards/...`、`ArenaPrefabs/<key>`、`WarpforgeVFX/...`、`Art/videos/...`），**没有一条直接点名某个原版对象名** ⇒ **按字面路径的动态加载对「未用」17,371 行的覆盖 ≈ 0**（我核过：把 Resources 目录 16,074 个文件 stem 与名字比，只 24 行名义命中，且全是 `Music`/`Cards` 这类泛词的假阳性）。
- **真正把一大片解释掉的是「按 key / 按表」间接加载**：
  - `ArenaRuntimeLoader.cs:100` → `Resources.Load<GameObject>("ArenaPrefabs/" + arenaKey)`：13 个战场**按场名**装配 ⇒ battlearena 场景对象归 ③（随 ArenaBuilder 重建的 prefab）。
  - `CardArt.cs:687/1050`、`Cards` 表：卡画/异画**按卡 id/路径**取 ⇒ 卡画类通常已被 U2 判「已用（数据表）」（不在本 17,371 里）。
  - `BattleScene.cs:21443/21467` → `voice_lines` / `card_vfx_by_card`：VO 与卡特效**按卡**取。
- **结论**：③ 的主要解释力来自「(a) 父件已被使用」、「(b) 场景由 ArenaBuilder/外壳重建」、「(c) 根名↔已实现类」三路，而**不是** `Resources.Load` 字面路径。见 `报告/B99_R7.md` §4 的三路计数。

## §7 边界（这些先知道，别把数字当绝对）

1. **`名字` 判据本身漏了 366 行**已由账方记过（`.cs/.webm/.cubemap` 扩展名案，见 `R0_未使用清单.md` §0.4）；本层没重做 U1，也不改账。
2. **④ 是「候选真缺口」，不是「功能没做」**：我们的 UI 多数是**代码构造**，与原版 prefab 不同名不同名结构。所以 ④ 里凡标了 `近似类=…` 的，很可能「功能已建、只是具体 prefab 变体没导入」。要逐根确认（这正是一张可派工的表的意义）。
3. **根可能停在「可复用的中间预制体」**（如 `Icon Container Drawer Variant`、`Avatar Item Small`）而未到最外层窗口——那是它本身就是 addressable 预制体根，属正常，不是「追根断了」。
4. **`未知` 域 3,734 行**里 3,665 是 `MonoScript`（类名不带功能词，如 `ServerRemoteInspector`），**属代码账**，不该按资源缺口处理。
5. **4,698 个 MonoScript 是代码类**，其中 525 个可判为第三方/引擎库（DOTween/PlayFab/TMP/SIMD…）。它们**不该进入资源复刻清单**；代码覆盖请以 `账/` 主表为准。
6. 重放 BFS **未纳入场景 `m_Father==0` 根**：对 battlearena 对象无所谓（整包按 bundle 定域），但若将来要精确到「场景里的某棵子树根」，需补 UnityPy 根集。
