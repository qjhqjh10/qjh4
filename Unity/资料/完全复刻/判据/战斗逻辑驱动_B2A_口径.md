# 战斗逻辑驱动 · `B → A` 升档口径（可执行检查表）

> **产出**：F 判据代理（第 2 轮），2026-10-25。供下一批 **5 个执行代理**直接照做。
> **适用范围**：**只**适用于 `Add*` / `Resolve*` 这一族（`CardScript.AddEffect` · `AddTrait` · `AddEnchantment` · `AddArmour` · `AddPoison` · `BattleManager.Resolve*` · `RuleCore.Apply*`）。
> 其它方法名**不套这张表** —— 它们走方案 §4.1 的通用口径。
> **配套**：拆块结果见 `判据/战斗逻辑驱动_AddEffect分派器.md`（K0–K11）。

## 一、三条门槛（**原文，一条不满足就保持 B**）

| # | 门槛 | 落地写法 |
|---|---|---|
| **①** | **判据要点写明机制差异** | 账的「判据要点」列**不许**写「（判据见 X 方法体）」这种占位。必须写：**原版做什么 → 差异在哪 → 我们等价在哪**。至少一句能让人复核的**机制差异**（不是「语义一致」） |
| **②** | **至少一个【可观察量】钉住等价** | 必须点名**一个**在离线探针里能读到的量，并给出**原版侧期望值**与**我们侧实测值**。见 §三清单。**「看着一样」「断言绿了」不算** |
| **③** | **没核的不许归进这一族** | 只要这一行的方法体里**还有一段没读**（或读了但没对上我们的落点），**保持 B**，并在备注写「没核的是哪一段」。⛔ 不许用「本类其它方法都对齐了」代替（方案 §4.1 的「类级命中 ⇒ 只能记 B」） |

> 另加两条来自方案 §4.1 的硬约束（与本表重叠但更严）：
> · **双侧都要方法级**：判据侧要给 `类.cs:行号`（`.c` 或 ILSpy，**标明哪一份**）；我们侧要给**行号范围**，⛔ 不许「文件级」「字段表实读」「整个类的入口」。
> · **共享落点可以用**，但必须 ① 给行号范围 ② 「判据要点」里说清这段代码**如何分别满足**各方法。

## 二、执行检查表（G0 → G8，逐格打勾，任一 ✗ 就停）

### G0 判据侧：方法体在位、行号可复算
- [ ] 出处写成 `文件:行号`，**并标明是哪一份反编译**（`decomp_full/*.c` = 🥇 / `out_cpp2il_dev_ilspy` = 🥈 / `out_il2csharp` = 只骨架）。
- [ ] 若用 `out_il2csharp` 取骨架：**case 号 ≠ buffType** 这件事已处理（`switch (buffType - 1)` ⇒ 差 1）。⚠️ 2026-10-25 已踩：`AddEffect` 的 case 编号在两份反编译里差一格。
- [ ] 分支里的**裸常量**都已解出真值（`.c` 里是 `0x3cf` 这种；映射表见 `判据/战斗逻辑驱动_AddEffect分派器.md` §〇·一）。
- [ ] 若引了 `_DAT_xxxxxxxx`：用 `工具/read_literal.py` 读过，**4B / 8B 两档都看过**，并写清「按什么类型选的这一档」。
- [ ] 若方法体**没反编译出来**（`NoteDecompilerIssue` / `throw null` / 空壳）：**明写「读不到」**，⛔ 不许拿序列化默认值顶替。

### G1 我们侧：落点是**行号范围**，且真的执行那段行为
- [ ] 落点写成 `文件:起-止`（例：`EffectResolver.cs:13729-13771`）。
- [ ] **打开那段代码逐句读**，确认它做的**就是**判据那段（不是「名字像」）。
- [ ] 如果落点里已有 `// 原版 AddEffect.c:NNN` 这类注释：**那条注释本身是转述、不是判据**（方案 §三·6 明令）⇒ 必须回反编译核一遍原文，⛔ 不许把我们的注释当证据。
- [ ] 如果落点走的是**整体重算**（例：`Aura.Recompose` 等价 `RemoveExtrinsicEffectsFrom`）：必须写清「重算的**净效果**与逐个摘除相同」的**理由**，并在 G2 里给出「哪一类情况下不等价」。

### G2 机制差异：一句话，说得出「哪里不同」
- [ ] 写出**至少一条**机制层面的差异或等价证明。合格的形状：
  - 「原版按**五个时长旗标**分桶累加；我们是**单值 `HandEffect.Expire`** ⇒ 同一 buff 挂两次不同到期时会合并成一条（差异：到期时刻取后者）」。
  - 「原版 `setHealth(9)` = **回满血**；我们 `DoSetHealth` = **只降到 N 且比当前小才改** ⇒ 同一条卡两种语义」。
- [ ] 不合格（**直接退稿**）：「语义一致」「基本对齐」「行为相同」「参照原版实现」。
- [ ] **⛔ 不许**把「我没找到差异」写成「无差异」—— 要写成「在 X 范围内逐句对过（共 N 句），未发现差异」。

### G3 可观察量：选一个、给两侧数值、可复现
- [ ] 从 §三 清单里**选一个**量，写明怎么读。
- [ ] 给出**原版侧期望值**（从判据推出，或从卡面/规则推出 —— **必须写推导链**）。
- [ ] 给出**我们侧实测值**（探针输出，**贴那一行原始输出**）。
- [ ] 两侧**不等**时：要么改实现、要么把差异写进「差异」列并**降级/保持 B**。⛔ 不许调期望值去凑。

### G4 差分实验：同一张卡、两次读数
- [ ] 用 `bash d:/4/Unity/工具/ruleprobe.sh play <卡ID>` 打一次，**保存前后局面**。
- [ ] 至少有**两读数**：① 打之前 ② 打之后（或「第一次挂」vs「第二次挂」）。
- [ ] 若是「重复挂载/去重」类（K0 / K2）：**必须打两次同一效果**，看数值是不是只动一次。**单次打卡验不出重复叠加**。

### G5 边界与反例（至少跑 2 条）

## 四、四个已踩的坑（写进简报，别让代理重踩）

1. **case 号差一格**：`.c` 的 `case` = buffType 原值；`out_il2csharp` 是 `switch (buffType - 1)`。抄骨架时不换算 ⇒ 整块错位（本轮已实测）。
2. **「原版 abilityLogic 里我们没实现」很可能是口径缺口**：`ruleprobe` 的 README 明写 —— `A1759` 把 `WhileInPlay(7)` / `WhileInPlayVariable(17)` 那族 24 条判成「我们缺」，**很可能是口径缺口不是实现缺口**（`bt=3 addTrait` 那一群同理）。⇒ 判「缺」之前先跑 `ruleprobe layers`，确认那条能力**进不进我们那条执行层**。
3. **池内可达性 ≠ 做不做**：`cards_raw.json` 的 `buffType` 统计（见 `判据/战斗逻辑驱动_AddEffect分派器.md` §〇·三）只用于**排先后**。铁律 11：只有「原版本身没有」或「用户拍板不做」才可以不做。
4. **「原版自己 LogWarning」才可以判 D**，而且要引那一行（`.c:767` / `.c:969`）。`skipCardDraw(7)` / `tideCopy(26)` / `replaceAbility(40)` 三个**不许**因 `AddEffect` 不管就判 D —— 它们的真实实现可能在别的方法里（我们 `skipCardDraw` / `tideCopy` 都已建）。

## 六、附：本口径**不覆盖**什么（免得被扩大解释）

- **不覆盖**「纯表现层」方法（`UpdateFigures` / `UpdateHealthText` / `CleanStatusAnims`）—— 那些归 `战斗界面_HUD` 域，判据看 prefab + 实拍。
- **不覆盖**「动作队列」那一层（`BattleManager.AddEffect(CardScript, CardEffect, …)` 入队 / `ResolveAddEffect`）—— 那是**另一条账行**（`战斗逻辑驱动.tsv:144` 与 `:541`），口径是「入队 vs 同步」的净结果等价，观测量用**终局局面哈希**。
- **不覆盖** SO 数据本身（`CardTrait` 的 `_stackable` 真值等）—— 那归资源侧（`判据/CardTrait词条权威表.md`）。
