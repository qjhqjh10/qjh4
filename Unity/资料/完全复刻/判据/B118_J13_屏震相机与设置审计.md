## 5 · 没查清

1. **`attackDirection` 的端点与符号**：已证它 = `Vector3.Normalize(某两点差)`（`_AttackMeleeAnim_d__357:189-192`），但**没逐行确认是「攻击方−受击方」还是反过来**，
   也没确认它在我们 3D 棋盘系里的映射（我们的卡位是 2D 屏幕面 + z）。⇒ 上面 #1 施工前必须先读透那 6 行。
2. **`LegacySignalSource.GetSignal` 的 `m_RepeatMode=0 (Stretch)` 时间拉伸**没有本轮重新反汇编 —— 沿用了 `R9_rawSignal_算式.md` 的结论（`T = t×frequencyGain + phase`）。
   ⛔ 若那条结论有偏，A 的整条幅度换算要重推。
3. `WFModuleScreenShake.Resolve` 对 `overwriteAmplitude/overwriteFrequency` 的应用**没有与 `GetModifiedPreset.c:76-129` 逐格对**（只抽读了 0x34 那一段）。
4. `ShakeAndSoundObject`（原版 `OnEnable` 逐条 `preset.Play()`）在我们工程里**判据参数解析完整但没接线**（`Effects/ShakeAndSoundObject.cs:195-218`）；
   我只扫了 `CardPresentation/**/*.prefab` 没找到实例 —— **没扫全仓 prefab**，不能据此判「全是死件」。
5. 原版 `CameraShake`（legacy `DoScreenShake` / `AttackShake`）的实例数：`assets_full` 全库 grep `baseShakeTime` **0 命中** ⇒ 倾向「无实例、休眠」，
   但没有按 script pathID 精扫（该 pathID 未取到），所以只写到「倾向」。
6. 我们的 SSAO / Forward+ / 阴影参数是 URP 模板默认还是有意为之，**没有任何文档或注释说明** —— 这一条要调度台裁是不是「有意偏离」。
7. `m_OpaqueLayerMask` 这类 **rendering-layer** 掩码的实际影响：只确认了「原版包含 bit0、我们全开」，**没量过**有没有物件带非 0 的 `m_RenderingLayerMask` 会因此多画/少画。
