## 五、误判边界（哪些会假阳/假阴）

**假阳（会误报 🟠）—— 已处理的三种：**
1. **`??` 兜底链**：`Ui("x") ?? MenuUi("x") ?? DeckUi("x")` 里前两条单看必然 miss、
   整条表达式却是好的。工具按「同一行 + 同一名字」合并：只要有一条 ✅，其余改判 ✅
   （现读触发 2 处：`Battle/SettingsPanel.cs:2170-2171` 的 `40K_toggle_off/on`）。
2. **注释里的调用**：先做 C# 词法切分（`//`、`/* */`、字符串、字符字面量、原始串），
   **注释与字符串内容都从「代码面」抹掉**，所以文档注释里贴的 `CardArt.MenuUi("…")` 不算引用。
3. **负例夹具**：见 §三，内置 2 个名字的忽略表。

**仍然可能假阳（已知、未自动处理）：**
- **大小写**：按大小写不敏感匹配 —— 在 Windows 上这与 `Resources.Load` 行为一致；
  但若将来出 Linux 包，`Resources.Load` 会区分大小写，**这里会漏报**。
- **同名多份/异画**：只看「文件主名存在」，不管这张图在**哪个批次**、是否被 Unload 掉。

**假阴（会漏报 🟠）—— 这道闸看不见的：**
1. **名字来自变量/数据表/帮助函数**（314 处 ❓）：`IconName(k)` / `b.sprite` / `CardbackTable` /
   `ArtKey(cardDef)` / 拼接出的 `<名>_hover`。⛔ 工具**不猜**，宁可标 ❓。
2. **只认上表 13 个口**：`Frame`/`Sdf`/`CardBack`/`DeckCardback`/`FlavorBg`/`PortraitByName` 等
   名字由阵营枚举或数据表决定，本闸没扫（它们丢图时通常有各自的上游断言/出声）。
3. **`Resources.Load` 之外的加载路**：本闸只覆盖 `Resources/Art/`；`WarpforgeVFX/`、
   `ArenaPrefabs/`、Addressables / bundle 直取的资产不在此列。
4. **`.png` 之外**：`Art/` 下还有 `.mat` / `.json` / `.ogg` / `.wav` 等；本闸只查 sprite（png）。
5. **真机/运行时动态名字**：存档里的自定义名字、服务端下发名（关服后本地无判据）不在此列。

## 六、怎么接成断言（宿主建议，未接）

**推荐（成本最低、与现有账闸同型）**：进**同步点脚本**，不新开 Unity 宿主 ——

```bash
python -I -X utf8 d:/4/Unity/工具/check_sprite_refs.py --fail-on-missing
# 🟠 = 0 ⇒ 退出码 0；> 0 ⇒ 退出码 1，并逐条打印「名字 | 文件:行 | 期望路径」
```

理由：这道闸是**静态源码扫描**，不需要 Unity；项目已有 `check_ledger_points.py` / `check_md_tables.py`
这类 Python 闸，放同一层最自然。耗时约 12 秒，可以在每个同步点跑。

**可选（运行时那一半已经存在）**：`Editor/B111_S1_Assert.cs` 的 **B7** 已经在运行时用反射读
`WindowButton.PressedNames` 并逐条 `CardArt.MenuUi(...)` 判非空 —— 那是本闸字典部分的**运行时对拍**，
⛔ 不要重复造；本闸补的是「**非字典的代码字面量**」这一大片。

**若一定要 Unity 宿主**：新建 `Editor/B146_S7_Assert.cs`，只做一件事 ——
`Process.Start("python", "… check_sprite_refs.py --write …")` 后读 TSV 断 `🟠 == 0`。
⚠️ 这条路要处理 python 路径与 `-I -X utf8`，且会把「静态闸」绑进串行的 Unity 批处理，
**不建议**（与铁律 12「串行且昂贵」相反）。

**接线时记得**：
- 默认忽略表（2 个负例夹具）要保留，否则永远 2 条红；
- 新增「故意缺图」的夹具时用 `--ignore 名字`，⛔ 别关掉整道闸；
- 工具是**只读**的，`--write` 只写 `判据/B146_S7_资源引用闸.tsv` 这一份快照。
