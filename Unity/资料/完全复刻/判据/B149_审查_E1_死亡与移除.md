   ⚠️ **未坐实的部分**：两条动作的道号/优先级我**没有**逐一验（`backlash` 用 `globalVars.<0xc0>`、翻面用常量 `1`；`AddAutoActionToQueue.c:47/284/175/231` 的道号映射只核了 `0/1/2/3` 四档存在）⇒ **不能断言「原版一定先反噬后翻面」**，只能说「入队顺序如此、我们是在同一拍里先翻面」。可达性 = 28 张 `remnant` + 27 张 `waystone`。

## 4. 四个必答

### ① 消费者链

### ③ 灭自证（给一条「两边一起改回去就变红」的断言反例）

**目标**：防「实现和它的检测器用同一个口，一起改回旧写法仍然全绿」。

```
// 三档必须同时成立，且互为反例 —— 任何一个常量被改回旧值都会红：
Check(RuleCore.DeathTypeOfSource(TacticSourceCtx(), 3) == UnitDeathType.Tactic);        // 30
Check(RuleCore.DeathTypeOfSource(UnitSourceCtx(),   3) == UnitDeathType.Ability);       // 20
Check(RuleCore.DeathTypeOfSource(NoSourceCtx(),     8) == UnitDeathType.Unknown);       // 0
// 反自证：再断一条【结构上不可能同时满足】的 —— 三档必须两两不等
Check(DeathTypeOfSource(TacticSourceCtx(),3) != DeathTypeOfSource(UnitSourceCtx(),3));
```
若有人把实现与期望值一起退回「一律 ability(20)」，第一/第三条会同时红；只改其中一处则第二条红。
**残骸那一族同理**：`Check(bit.IsRemnant) ∧ Check(!ReferenceEquals(slotObj, original)) ∧ Check(slotObj.Health == 1) ∧ Check(original 不在 Board 里)` —— 单一常量/单一标志改不回来。

## 5. 顺手发现（越界也报，⛔ 未改）

1. 🔴 **残骸属性块缺判据**：`CardScript__TransformIntoRemnant.c:39-52` 把一个**全局配置的 5 个 int**（`*(DAT_18427be00 + 0xb8) + 0x298` → 同时写 `card+0xa4..0xb4` 与 `card+0x68..0x78`）当残骸的 攻/远/血/甲/第五格。我们 `RuleCore.cs:10070-10074` 硬编码 `AttackBase=0 / RangedAttackBase=0 / Health=1 / MaxHealthBase=1`，**没有出处也没打 `🔶 自己设计`**（铁律 18·0）。⇒ 要么把那 5 个值从资产里挖出来，要么补标记。
2. 🟠 `GetCardsInCemetery` 的 `inclWeapons` 是死参 —— 我们已在代码里写明（`RuleCore.cs:15975`），但**账里没写**，容易被后人当漏实现。
3. 🟠 **账落点漂移 8 处**（见 §3·②·#5）：其中 `EffectResolver.cs:1142` 现在指到 `lowercost` 动词行、`BattleDriver.cs:36467` 指到 `ResetReplaySpeed`、`RuleCore.cs:17107` 是一段注释 —— 按行号找会**静默找错**。
4. 🟠 `RuleCore.cs:16002` 的排除表达式 `remnantIds != null && remnantIds.Contains(inst.Id) || IsExiledFromCemetery(...)` 依赖 `&&` 高于 `||`，语义正确但**没有括号**；同族的静态检查工具若按「先或后与」读会误判（低风险，供参考）。
5. 🟡 `EffectResolver.cs:4358` 的 `DoDestroy` 传 `DeathTypeOfSource(ctx)` —— 原版 `DestroyUnit` 是**把 deathType 作为形参塞进动作**（`DestroyUnit.c:1022` 第 5 个实参写进 `+0xF0`）。所以「摧毁」类效果的死因档在原版是**调用方决定的**，我们统一按来源卡推。可达性：`chosenAbility` 里 destroy 那条的生产者本次未统计（`EffectText` 侧），建议下一波补。
6. 🟡 `SupportMethods__HasToTransformIntoRemnant` = `remnant(0x41a)` ∨ `waystone(0x474)`（`HasToTransformIntoRemnant.c:12-17`）—— 我们 `RuleCore.cs:10058` 的判据是 `u.Has(KeywordTable.Remnant) || u.Has(KeywordTable.Waystone)`，**关键词名与 trait 号对应正确**（`DefinedTrait.cs:103/112`），这一格可以放心。
