## 3 · `[B109E21] C7` Translating 行材质 = Light Green（实得 NotoSerifCJK…）

**现象**：`host_shellscene.log:165384`；同刻实现自己打了告警 `:165251`
`[Chat] 翻译态「Translating」没换材质：正文含汉字 ⇒ 这个标签实际用 CJK 面`。
**判定**：**β（实现与原版不符）**。⛔ 不是 δ —— **夹具没写错**：它用的是**生产上真会出现的**中文本地化词条。

**证据**：夹具 `Editor/B109_E21_ChatTrans_Assert.cs:234`（`原文 + " (" + Loc.T("MainMenu/Messages/Translating") + ")"`，该词条中文值 =
`正在转换`，同文件 A0/A0b 断言）· 实现 `Shell/ChatPanel.cs:1317-1323`（`if (lb.ActualFace != LatinCardBody) { 出声; return; }` = **整段不换材质**）·
翻面机制 `Battle/Label.cs:1108-1111`（指派了拉丁面、文本里有汉字 ⇒ **整颗回 CJK**）·
原版 `ChatMessageUI.SetMessageText()` 三态**无条件**赋 `fontMaterial`（判据 → `B109_E21_ChatTrans_Assert.cs:6-11` ＋ `报告/B109_E21.md` §一）
⇒ 中文玩家在原版里**看得到**这行的颜色差。`B109_E21.md` §七·4 已如实记过「没查清」。

**修法**（推荐 A；两处都**零行号漂移**）
- **A · 忠实原版（推荐）**：让聊天正文那颗 Label 走「拉丁面 + CJK fallback」，而不是整颗翻面 ——
  这正是原版的渲染模型（三份拉丁资产只有拉丁字形 ⇒ 汉字必然走 TMP fallback，fallback 用**它自己的**材质）。
  ① `Battle/Label.cs:1110` **就地改一行**（不增行数）：
  `get { return (_face != TmpFont.Face.Cjk && !_cjkFallbackFace && Loc.HasCjk(_text)) ? TmpFont.Face.Cjk : _face; }`
  ② `Battle/Label.cs` **类尾**追加 `bool _cjkFallbackFace;` + `public bool CjkFallbackFace { get => _cjkFallbackFace; set { _cjkFallbackFace = value; SyncFace(); } }`
  ③ `Shell/ChatPanel.cs:851`（`ApplyTranslationFont(msgLb, m)` 之前）加一句 `msgLb.CjkFallbackFace = true;`
  ④ fallback 链已在：`Core/TmpFont.cs:207 / :228-246`（`EnsureCjkFallback`，`SetFace(LatinCardBody)` 时自动挂）。
- **B · ⛔ 不推荐**：给 CJK 面克隆同色材质 —— 那是**自设计**（原版没有 CJK 版本地化材质），与铁律 18·0 冲突。

**风险**：中 ① 改的是**全局** `ActualFace` 判据（虽由新开关门控、默认关，CJK 那条路**逐位不变**）；
② TMP 对 fallback 子网格用的是 fallback 资产自己的材质 ⇒ **必须真渲一次确认**（批处理看不出，`C8` 只读主材质天然会绿，
⛔ 别拿它当「渲染对了」的证据）；③ 该支只有 `TranslationStatus != 0` 才可达，生产局里恒 0（`B109_E21.md` §七·3）⇒
**影响面小、但按铁律 11 仍要做**。
