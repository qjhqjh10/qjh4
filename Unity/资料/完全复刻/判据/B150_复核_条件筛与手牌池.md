## 4. `+0x38` 的定性

**结论：不是一个字段，是两个不同类里的同名偏移。作者两条陈述都对，但他由「倍率块不读 `+0x38`」推出「倍率路径不过 `conditionsFilter`」这一步是错的。**

三条证据：

1. **字段表**：`dump.cs:23850` `public UnitConditions conditionsFilter; // 0x38`（类 `TargetCriteria`）；`dump.cs:19464` `public int furtherMultiplier; // 0x38`（类 `AbilityLogic`）。两者分属不同 `TypeDefIndex`（463 / 360）。
2. **乘法那一句读的是 `AbilityLogic` 自己**：`AbilityLogic__PlayAbility.c:235-236`
   `if (0 < *(int *)(param_1 + 0x38)) { local_178 = local_178 * *(int *)(param_1 + 0x38); }`
   而 `param_1` 是 `AbilityLogic` 实例（同函数 `:181` `uVar12 = *(undefined8 *)(param_1 + 0x30)` = `multiplier`，`:260` `*(param_1 + 0x28)` = `targetCriteria`）。⇒ 这一句是 `furtherMultiplier`，**不是** `conditionsFilter`。
3. **`conditionsFilter` 的真身在下一跳**：`FilterMethods__CheckIfMeetsCriteria.c:298-300`
   `MeetsConditionCriteria(lVar14, *(undefined4 *)(param_4 + 0x38), *(undefined1 *)(param_4 + 0x3d), param_1, 0)`
   而 `param_4` 是 `TargetCriteria`（同函数 `:57` `iVar17 = *(int *)(param_4 + 0x10)` 就是 `targetsAffected`）。⇒ `TargetCriteria+0x38` = `conditionsFilter`，**每候选**跑一次。

**为什么「倍率路径不读 `conditionsFilter`」站不住**：`AbilityLogic__PlayAbility.c:181-236` 的乘数块本身确实只读 `multiplier.targetsAffected(+0x30→+0x10)` 与 `multiplier.traitsFilter(+0x30→+0x34)`，但它是在 **`:185` `AbilityLogic__GetTargets(manager, multiplier, abilityData, 1, 0)` 已经返回之后**才数 `local_178 = List.Count`。⇒ 乘数个数本身就是「**已经过 `CheckIfMeetsCriteria` 过滤后**」的列表长度。作者漏掉了这一跳。

补充：`AbilityLogic__PlayAbility.c:483`（`GetTargets(param_2,lVar11,local_res8,local_168,local_170,1,0)`，六参重载）与 `:1524` 也都是走 `GetTargets`，同一条尾巴。
