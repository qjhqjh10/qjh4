## 五 · 顺手发现（⛔ 不属于本件，交调度台分流）

1. 🔴 **`判据/B117_G5_战斗HUD层差异.tsv` 的「我们值」列** **不是我们的值** —— 它取的是
   `资料/原版参照图/Unity参照管线_0825/data/runtime_ui_dump_Battle_Arena_1.tsv`，而那份是**原版自己跑的运行时 dump**
   （判据：里面 **0 命中** 我们独有的节点名 `HandLabel` / `MyPileLabel` / `FoePileLabel` / `EndTurnButton`，
   而有 `CardsPlayedInTurn1` / `Player Deck Size Tex`）。⇒ 那张表实际是「**原版序列化 vs 原版运行时**」
   （7889 行里 7359 一致就是这个原因），**不能当「我们 vs 原版」的基线用**。
   它仍然有用：它证明了 `Player Deck Size Container.sizeDelta` 那两条「不一致」只是 `AspectRatioFitter`
   在运行时把高撑成 59.1/52.05（序列化写 0），**不是偏差**。
2. ⚠️ **`Resources/OffensiveCards.json` 各阵营的 `envSO` 大小写/空格不统一**：
   `DarkAngels`/`EmperorsChildren` 用 `"Environmental Condition …"`（有空格，与 `offensive_card_abilities.json` 的键一致），
   而 `AstraMilitarum` 用 `"EnvironmentalCondition …"`（无空格）。两者若某处按同一张表互相查，会**静默查不到**。
   本件的闸只认 DA/EC 两条（有空格那两条），**不受影响**；但建议另立账核一遍 `EnvSOFor` 的一致性。
3. 📌 `0827 子代理读报_back右区` 把 `TurnText` 的 `m_VerticalAlignment = 4096` 标成 **`Capline`** ——
   按 TMP `VerticalAlignmentOptions`，**8192 才是 Capline，4096 = Geometry**。我们代码里叫 `Midline`（`Label.VAlign` 的 0x1000 档），
   **数值一致**，只有那份外部文档的标签错。
