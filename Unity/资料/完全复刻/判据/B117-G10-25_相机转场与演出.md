## 二 · 改了什么（逐条）

### 2·1 `Battle/CombatAutoZoom.cs` — `CurrentSizeMultiplier` 取原版公式

- **判据**：`PlayerHand__get_CurrentSizeMultiplier.c` = `smallScreenUI ? *(PlayerHand+0x3c) : 1.0f`；
  `+0x3c` = `smallScreenSizeMultiplier`；13/13 场（玩家那件 `PlayerHand`）序列化 = **1.365**，
  `CameraVerticalFramer.playerHand`（`framer+0x60`）在 13/13 场都指向**玩家那件**（`isPlayer = 1`）；
  `PlayerHand.Initialize` 只读该字段，全反编译**写点 = 0**（`.ctor` 出厂 1.0、场景覆盖成 1.365）⇒ 运行期恒 1.365。
- **改法**：`return SmallScreenUI.Enabled ? PlayerHandSmallScreenSizeMultiplier : 1f;`，
  常量 `public const float PlayerHandSmallScreenSizeMultiplier = 1.365f;` **追加在类尾**（行号不漂）。
- **影响面**：只有 `MeasureCardAreaGapWorld()` 那一行乘 `CurrentSizeMultiplier`（`:791`）⇒
  `boundsVerticalSizeInViewport` → `cameraSizeXTable` → `sensorSize.x`。**只在 `smallScreenUI` 开时生效**。
- ⚠️ **仍然如实记**：我们自己的战斗 HUD **没有**「手牌区放大 1.365 倍」那一档
  （`Shell/TransformScalerBySmallScreenUI.cs` 的 `AddComponent` 生产调用点只在菜单窗口那两处）⇒
  开着 Small Screen UI 时「取景按原版的大手牌算、画面按我们的小手牌画」。
  **这是另一条待办（HUD 侧）**，见 §四。

### 2·2 `Battle/CombatAutoZoom.cs` — `ApplyFraming()` 补「只在无帧循环时生效」的闸

- **判据**：`CombatAutoZoom__SetZoomLevel.c` 全文**没有一处**写相机；相机收敛的唯一入口是
  `CombatCameraZoom__LateUpdate.c` → `ApplyZoom`（`SmoothDamp(current, target, ref v, dt·zoomSpeed, +∞, dt)`，
  `zoomSpeed = 12.5` ⇒ 时间常数 ≈ 0.08 s）。
- **改法**：`ApplyFraming()` 里加一句 `if (Application.isPlaying) return;`（真机有帧循环 ⇒ 交给 `LateUpdate`）。
  **编辑期/批处理照旧 settle** —— `BattleScene.Run` 的 A175 那几条（`FramingApplyCount`、
  `boardCam.lensShift.y == −0.210542 / −0.250836`）**一条都不受影响**（它们在编辑期跑）。
- **怎么才能红**：把 settle 整个删掉 ⇒ 编辑期 `FramingApplyCount` 不涨 ⇒ A175 那条红。

### 2·3 `Battle/CombatCameraZoom.cs` — 三处「待接线」→「已接线」

`PointerOverUi` 的生产接线 2026-10-28（`B90_B2`）就做了（`BattleDriver.cs:3722` → `PointerOverAnyUi`），
但 `CombatCameraZoom` 的三处注释还写着「待接线」⇒ 按铁律 5 就地订正（`:87` / `:241` / `:628`，**行数守恒**）。
