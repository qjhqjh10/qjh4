## 二、判定口径（为什么只有这么点）

判断一处是否"受洗牌影响"，要**三条同时成立**，缺一条就归 C：

1. **建局是真洗牌** —— `RuleCore.NewBattle(..., shuffle: true)`（**缺省就是 true**）或 `driver.Begin(...)`（`shuffle` 缺省 true）。
   - **`shuffle: false` 一律免疫**：牌序 = 传入序，`B143` 那格随机数根本不参与。
   - **`new BattleContext(seed)` 不是建局**，不洗牌。
   - **只有 `BattleDriver.Begin` 那条生产链会吃掉那格随机数**（`drawFirstSeat: true` 是 `Begin` 硬传的）；`NewBattle` 缺省 `drawFirstSeat = false` ⇒ 直调 `NewBattle` 的夹具**一格都不多吃**。
2. **按下标取手牌**（`Hand[i]` / `HandViewAt(0)` / `hand[0]` / `FirstUnit(...)` / `hand.Count-1`）。
3. **依赖那张卡的「身份 / 阵营 / 费用 / 可打出性 / 卡面内容」**。

⇒ 本项目里 **绝大多数夹具是 `shuffle: false` 或「自己注入一张、再按 `ReferenceEquals` 找回来」**，所以真正受影响的只有两个来源：**宿主 `BattleScene.Run` 那条洗牌对局**，和**少数几个吃宿主 `ctx` / `driver` 的 `*_Assert`**。

## 五、统一修法建议（按类，不逐条）

### 类 1｜**先按内容找卡，再退回第 0 张**

```csharp
var hand = ctx.Players[seat].Hand;
int i = hand.FindIndex(h => h?.Card != null && <所需属性>);
if (i < 0) { Check(false, "（前提）手牌里没有满足 X 的卡 —— 夹具需补一张"); return; }
```
适用：`:14725`（语音）· `:19068`（按名找）· `B112_R3C:117` · `B98G6:195`。

### 类 2｜**找不到就注入一张夹具卡**（本项目已有范式）

`BattleScene.cs:16307` / `:16385` / `:41385` / `:41494` 就是模板：先按条件找，找不到就 `Hand.Add(ctx.NewInstance(自造 CardDef))` + `RefreshAll()`，然后**按刚才那一份实例反查下标**。
适用：`:6420`（付得起的牌）· `:7267`（付不起的牌）· `B112_R3C:117`。

### 类 3｜**把「卡的属性」换成「座位的属性」**

`:31310` 那一处：期望「我方阵营」必须来自 **`FactionOf(seat)` / `driver.FoeFaction`**（`:31372` 的写法），⛔ 不是 `FirstUnit(...).Faction`。原版语义：阵营是**座位**的属性，卡上那个 `cardArmy` 是**卡自己**的（RALLY 变身会保留原阵营）。

### 类 4｜**先断前提、再断结论，⛔ 不许 `if (前提) Check(结论)`**

`:7267` 那种「找不到就 `Debug.Log("跳过")`」等于**这条断言从未执行**。改成 `Check(前提)` + `Check(结论)` 两行（本项目红线，见 CLAUDE.md §三「自检里的 `if (x != null) Check(...)` = 静默跳过」）。

### 类 5｜**通用防回归：把「第 N 张」的期望从「现算」而不是「写死」**

若某条断言确实需要「第 N 张就是某张卡」，**用同一局的 `ctx` 现读**（`Check(Hand[0].Card.Id, ctx.Players[0].Hand[0].Card.Id)` 那种自证要避免）——正确写法是**从夹具的输入**推期望（谁被塞进去、谁被抽到），而不是从实现读回来。
