### 1 · `createAtPos` —— **先做，但语义要照原版**

**原版判据（🥇 `decomp_full/AbilityLogic__PlayAbility.c:759-793`，逐句）**

`param_1` = `AbilityLogic`（`summonCriteria` 在 `+0x58`）；`iVar21 = *(int*)(summonCriteria + 0x20)`：

```
uVar10 = MinionManager__GetNextSlotWithoutDisplacing(area);      // ← 先取默认落点
iVar21 = *(int*)(summonCriteria + 0x20);                          // createAtPos
if (iVar21 == 0)      slot = GetNextSlotToCard(area, abilityData.thisCard);     // 贴「施放者那张卡」
else if (iVar21 == 1) slot = GetNextSlotToCard(area, abilityData.cardTarget);   // 贴「卡目标」
else if (iVar21 == 3) slot = GetNextSlotToCard(area, GetHero(thisCard.owner));  // 贴「自己督军」
else { AddMinionOccupation(area, 0); CustomDebug__LogWarning(<字面量未解>); }   // ← 14/140/6/18 全在这
```

`GetNextSlotToCard`（`decomp_full/MinionManager__GetNextSlotToCard.c`）：
`cardType == 10 (Hero)` ⇒ **直接返回默认落点**；右表含该卡且该侧还有位 ⇒ `IndexOf(右表)+2`；左表含该卡且左侧有位 ⇒ `-2-IndexOf(左表)`；都不中 ⇒ **`LogWarning` + 默认落点**。

**⇒ 三层结论（这三条是本列的全部价值）**

1. **`14 nextFriendlyMinionSpot` 不是「贴卡」** —— 它落进 `else` 支：出声 + **默认落点**。池内 47 行属这一档。
2. **`3 friendlyHero` 也等于默认落点** —— 锚点是自己督军，`GetNextSlotToCard` 见 `cardType==10` 第一句就返回默认。池内 1 行（`Rites of Possession`）。
3. **唯一会与今天不同的一档 = `createAtPos` 缺键（= 0 self）且施放者是场上单位**：

| 卡 | 触发 | 后果 |
| --- | --- | --- |
| Rukkatrukk Squigbuggy (580) · Painboss (0) · Canoptek Scarab (560) · Canoptek Spyder (560) · Ghost Ark (560) · Monolith (560) · Kroot Hound (0) · Sporocyst (560) · Harpy (50) · Biovore (40) · Primaris Impulsor (145) | 各自 | 召唤物应落在**施放者旁边（更外侧一格）**，而不是「人少那侧最外一格」 |

**要写的代码（三处，顺序不能反）**

1. **生成器**：新增 `ability_summon_of(cid, name, trow, report)`，形状仿 `ability_damage_of`（`:1754`）：

   🔴 **缺键必须落 `-1` 而不是 `0`** —— `0 = self` 是**有语义的取值**（见上面第 3 点），`-1` 才是「这张卡没写这一格 ⇒ 按原版默认值 0 处理」；
