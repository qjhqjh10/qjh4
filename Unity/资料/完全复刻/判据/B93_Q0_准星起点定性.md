# B93_Q0 —— `BattleScene.Run` 唯一那条红（AI 准星起点）定性

日期：2026-10-28 · 只读诊断代理 `B93_Q0` · 未跑 Unity、未动 git、未改任何源码/账/正本

## 判定

**档 = α（主判：断言把两个坐标系当成了一个）+ β（并列：`B92_B3` 那次改动的 `useCenter` 用在了错误的一端）**

一句话：准星是 **HUD 正交帧**的件（`CrosshairWorldSize = px/108`、`Z = -1.50`、HUD 相机 `orthographicSize = 5`），
而这条断言拿 **战场透视帧**的 `transform.position` 当期望值 —— 两个帧之间差着一个 ≈0.80 的投影缩放；
同时原版 `EnemyTargetingAnim` 的**起点**是 `cardOrigin.transform.position`（裸原点，`PrepareMovement` 内部才投影），
`useCenter:1` 只用在**终点**（`Get2DPosOfCard(target, useCenter:1)`）——
`B92_B3` 把 `useCenter` 加在了起点、把终点留成裸原点，**两头恰好对调**。
⇒ 单改实现或单改断言都仍然红，两边都要改。

## 该改什么

### ① 实现（`BattleDriver.cs:18962-18965`）—— 起点去掉 `useCenter`，终点改用 `useCenter`

```csharp
// 原版 `EnemyTargetingAnim(cardOrigin, target, attackType)`（dump.cs:32779）：
//   起点 = :24 `cardOrigin.transform.position` → `PrepareMovement`(:24) 里 `Get2DWorldPosFromBoardPos` 投影；
//   终点 = :18 `Get2DPosOfCard(target, useCenter: 1)`。
_aiAnimFrom = Get2DPosOfCard(caster, false);   // ← useCenter:false（= 原版裸原点 + 投影）
_aiAnimFrom.z = TargetReticle.Z;
_aiAnimTo = Get2DPosOfCard(target, true);      // ← useCenter:true（= 原版目标 effectsAnchor + 投影）
_aiAnimTo.z = TargetReticle.Z;
```

⛔ **别在 `_aiAnimTo` 外面再套 `reticle.ResolveAim`** —— 本工程 HUD 相机是**正交**（`LayoutSpace.cs:78`），
`ResolveAim` 的射线沿 +z 穿过 `enemyMinionPlane` 时返回的就是**同一个投影点**（floorPlane 还恒打空：射线与它平行）。
再套一次 = 双投。
⛔ **别把 `TooltipUpOffset(−3.0)` 加进来** —— 那条属于 `_ChooseUnitTarget` / tooltip（`BattleDriver.cs:35977`），不在本方法里。
⛔ 18962 那句注释「`.c:18`：起点走 `Get2DPosOfCard(cardOrigin, useCenter:1)`」是**错的**，按铁律 5 就地改写（`.c:18` 是终点）。

### ② 断言（`BattleScene.cs:10559-10564`）—— 期望值换到 HUD 帧

```csharp
Vector3 fromW = driver.FoeUnits[foeAtkSlot].transform.position;   // 战场帧（原料）
```

- 等价的另一份判据 = `driver.enemyBoard.DropTargetWorld(foeAtkSlot)`（`BoardLayout.cs:523`，「卡心投影」那个唯一口）；
  两者只在 z 上差（`PlaneDistance` vs `z=0`），x/y 逐位相同 —— 断言本来也只比 x/y。
- **2D 兜底档不受影响**：`PointerAtWorldForTest` 在 `use3DBoard == false` 时**逐位恒等**（`:13604`）。
- 这条断言最好同时把那句 `"起点 = 施法者"` 的文案改成「起点 = 施法者的**HUD 投影点**」，否则下个会话还会按「同一个点」去理解。

## 反证（为什么不是另外那几档）

- **不是 δ（夹具前提不成立）**：
  同一节前面已经 `Check(driver.SimulateStartEnemyTargetingAnim(actA), "目标在真人那一侧 ⇒ 起演出")`、
  `Check(driver.ReticleVisible, …)`，**都过了**；`StartAiTargetingAnim` 里 `ViewAt` 取不到视图会**直接 return false**（`BattleDriver.cs:18949-18955`），
  第一条就会红。后面「准星红 / OutQuad 43.75% / 演完执行」也都没报红 ⇒ 攻方视图、受方单位、准星都在。
- **不是纯 γ（本批回归到正确状态）**：
  B3 之前那版（`_aiAnimFrom = caster.transform.position`）**之所以绿，是因为断言和实现错在同一个帧**——
  正是 `CLAUDE.md §二` 记的那条「断言靶对齐到错的那一半 / 同义反复」的同型（同文件 `:9995-9996` 已经修过一例）。
  ⇒ 它不是「正确的旧行为被改坏」，而是「两个错对齐」被 B3 拆开了。**只回退实现会重新变绿，但那是用战场帧的点去摆 HUD 帧的准星**（弧线锚点偏 ≈18% x）。
  （B3 那一次改动确实**引入了**这一条红 → 时间归因上算本批，但定性上不是退回到对的状态。）
- **不是纯 β（只改实现就够）**：
  把 `useCenter` 改回 `false` 之后，起点 = `project(cardOrigin.transform.position)` ≈ `(1.33, ~1.27)`；
  期望值仍是**裸** `(1.66, 1.15)`，两轴都远超 0.05 ⇒ **仍然红**。断言不换帧就永远不可能绿（除非把实现写成错的那一版）。
- **判 α 的正面理由**：断言比的是 `p0`（HUD 正交帧）与 `transform.position`（战场透视帧），
  两帧之间是 `0.80` 的投影比例（上面已用 x 斜率验到）；同文件 `:10099`、`:9995` 两处已为同一族错误立过规矩。

## 顺手发现（改动现场看见、不在本任务范围）

1. **同族第二处（pre-existing，与本批无关）**：玩家选目标那条
   `BattleDriver.cs:16020-16021` / `:16160` 把 `me.transform.position`（**战场帧**）直接当准星**弧线锚点**喂进 `reticle.Show/Aim`，
