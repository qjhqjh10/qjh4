### 8-5 顺手发现（本波捎带查出，未改代码）

🔴 **`_tmp_view/wfres/r1_decoded2/` 里 885 份 JSON 中 858 份的 `m_Script` 是垃圾值。**
根因：**TypeTreeGeneratorAPI 从 IL2CPP 元数据生成的 MonoBehaviour 类型树，`m_Enabled` 节点没有
`kAlignBytes(0x4000)` 标记** ⇒ 紧跟其后的 `m_Script` PPtr **早读 3 字节**（Unity 在 `m_Enabled` 后真有 3 字节填充）。
实测 `#1430` 读出 `{m_FileID: 16777216, m_PathID: 76420218880}`（真值 `{1, 4555}`）、
`#544` 读出 `{33554432, 201343369216}`（真值 `{2, 12001}`）。

- **影响面**：`m_Script` 后面紧跟的 `m_Name` 是 string（4 对齐）⇒ 读口自愈 ⇒ **其余字段不受影响**；
  R1 TSV 的 `类名` 列也不受影响（那一列由 `parse_monobehaviour_head()` 直接读字节得到）。
- **修法**（已写进 `工具/r1_residual_decode.py` 的 `_align_fix()`）：给 `m_Enabled` 节点置
  `m_MetaFlag |= 0x4000` 后 `m_Script` 与头部字节手动解析完全一致。
- **没做**：没有重跑那 886 条把 858 份 JSON 刷掉（那属于 `r1_decode2.py` 的重跑，不在本波清单）。
