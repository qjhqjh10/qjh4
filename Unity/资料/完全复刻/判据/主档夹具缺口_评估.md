## 一 · 根因分级

### 1. 强制攻击那 12 张（`chosenAbility ∈ {231,235,236,237,238}`；`230`/`233` **池内 0 张**）

| 类 | 张数 | 卡 | 判据 / 证据 |
|---|---|---|---|
| **① 打出去那一拍就强制攻击、跑通** | **2** | `EC46`(237) · `GOF93`(235, Rally) | 主档 `rc=OK`；`EC46 dmg=2`、`GOF93 dmg=15`（`play all dump` 现读） |
| **② 打出去那一拍就该攻击、但打不出去** | **1** | `BL64`(231) | `rc=ErrNoTargetAvailable`；根因见下（**不是**缺受伤友方） |
| **③ 主档那一拍本来就不该攻击**（触发式） | **9** | `DA25`(Teleport 690) · `EC12`(Slay 120 / Ecstasy 715) · `SAU70`(560) · `SAU33`(280) · `GOF86`(30 回合开始) · `SW9`(Rally 410) · `SW5`(无 trigger) · `SW29`(play-time 只给猎杀标记，攻击在 Ferocity) · `EC22`(Cruelty 710 / Stimulation 720) | `cards_engine.json` 的 `abilityTriggers` 逐张现读 |

**② BL64 的根因（查到数据行级）**：它的 `unitConditions` 有两行 ——

```
{"ab": -3, "lg": -1, "role": "cardtarget", "cond": 40,  "name": "damaged",     "ex": 0}   ← ab=-3 ⇒ 没挂到任何 ability ⇒ 不生效
{"ab":  0, "lg":  0, "role": "target",     "cond": 341, "name": "canUseDuty",  "ex": 1}   ← 挂上了 ⇒ 生效
```

`EffectResolver.ApplyStructuredConditionFilter`（`EffectResolver.cs:2348-2375`）只接 `role` 属于「一个目标」的行 ⇒ 第二行生效；
`ConditionEval.cs:548-550` 的 `case 341: return !u.DutyUsed;` 对**任何还没用过 Duty 的单位恒为真**，而数据写的是 `ex: 1`（取反）
⇒ **把目标池里所有正常单位全排除** ⇒ `IsLegalPick` 为假 ⇒ `ErrNoTargetAvailable`。

**排除法（证明不是别的）**：
- 不是「缺受伤友方」：见开头那条更正。
- 不是 damaged 筛坏：另外两张带 `DamagedOnly=1` 的卡 `UM2` / `UM116` 主档 **`rc=OK`**。
- 不是解析错：`基线/out_baseline.txt` 的 `BL64` 行明写 `Side=own|Kind=unit|Count=1|SubtypeFilter=-|DamagedOnly=1`。
- 不是合成卡的问题：`preset sub=BL1`（把 `FIX_A` 换成池内真卡 `BL1 Chaos Spawn`）**照样** `ErrNoTargetAvailable`。

⇒ **🔴 2026-10-27 第五批更正（铁律 5）：这一条【不是引擎判据问题】** —— 反编译核定 ⇒
`ex` 是「取反」（`FilterMethods.cs:776` 的 `MeetsConditionCriteria(…, excludeTrait, …)`：尾部 `(excludeTrait^1) & flag2`，且 `excludeTrait && !flag2 ⇒ return true`），
`canUseDuty(341)` = `!usedActiveAbility`（`FilterMethods__MeetsConditionCriteria.c:170-174` 读 `+0x4C`；`+0x4C` = EntityScript 的 `usedActiveAbility`，写点 `CardScript.cs:14768` 只在 `hasActiveAbility` 为真时置 true）
⇒ **我们 `ConditionEval.cs:550` 的 `!u.DutyUsed` 与 `ApplyStructuredConditionFilter` 的取反都【与原版逐字同形】，⛔ 不要改代码。**
⇒ 于是折算出来的是：**原版语义下 `BL64` 的目标池 = 「有主动能力且本回合已用过」的友方单位**（数据 `excludeCondition=1`），而夹具的 `FIX_A/B/C` **都没有主动能力** ⇒ 池空。
⇒ **所以它仍算「夹具缺口」，但缺的不是「受伤的友方」，而是「一个有主动能力、且本回合已经用掉它的友方单位」**（收益 1 张）。
对照实验（机器正常）：`play BL50 preset chipenemy=1`（`cond=40 damaged, ex=0`）⇒ **能打出去** ⇒ 结构化条件与取反这一整套是好的。
⚠️ 上游疑点（**没查清**）：`BL64` 这条数据「只能选已用过 Duty 的单位」读起来反直觉 —— 要么原版如此（那我们**是对的**），要么 `cards_truth.json` 抽取时 `excludeCondition` 取错（归 `工具/gen_cards_engine.py` + SO 解包链）⇒ 下一轮从 `d:/2` 的 SO 核一次再定。

### 3. 为什么 `atkCount` 主档 1128 张全空 —— **真因是量具，不是夹具**（本条最重要）

就算强制攻击**真的发生了**，主档读数里也看不见它，因为：

> **探针里 `ForcedAttackRefund` 表恒 `Unknown` ⇒ 下游一律「退还」⇒ 计数必然回 0。**
> `ForcedAttackRefundMap.cs` 在 `Data/`，**不在 `ruleprobe` 的编译集**（`ruleprobe` 只编 `Core/*.cs`），
> `LoadFromUnity` 是 `partial` 的空声明 ⇒ 表恒 `null` ⇒ `Of()` 一律 `Unknown`（`ForcedAttackRefund.cs` 文件头自述）。

**实证**：`play GOF93`（`chosenAbility = 235` = 原版**不退还**族）的事件日志出现
`Hunta Rig 重置行动：本回合攻击次数 1 → 0（原版 CardScript.ResetActions；强制攻击不消耗它的行动）`
⇒ **探针把它当退还族处理了**（真值里 235 不退）。所以主档里 `atkCount` 空 ≠ 没发生攻击。
（`EC46`/`GOF93` 的强制攻击**都发生了**，而且都被 `dmg` / `changesFull` 记到了 —— 见 §一·1。）

⇒ **`atkCount` 这两列的正确用途**：**「退款有没有丢」的哨兵**（谁把退还弄丢，终局就会留下 `1`），
不是「攻击发生没发生」的读数。后者已经由 `dmg` / `changesFull` 覆盖。

| 位 | 能救的卡 | 结论 |

## 四 · 替代方案（不动全池夹具）

### 方案 A（推荐 · 零夹具改动）：让探针**装载 `ForcedAttackRefund` 表**
- 做法：把 `Data/ForcedAttackRefundMap.cs` 的装载（`Resources.Load` + `JsonUtility`）搬进 `工具/ruleprobe`（它是独立 csproj，自带 `Stub.cs`），或给它一个「读 `cards_engine.json` 的 `chosenAbility` 列」的旁路。
- **影响面 = 强制攻击那 12 张里成功的那 2 张**（`EC46` 237 不变；`GOF93` 235 **变**：终局 `P0[2]=1` 会出现在 `atkCount` 里）。
- 收益：`atkCount` 对**不退还族**开始有真读数；探针不再「一律退还」这种**系统性失真**。
- 代价：基线重建 **1 次**、`PinnedPlayMd5` 变 **1 轮**。

### 方案 B（按需 · 单卡专用）：扩 `play <id> preset` 两个旋钮
`PresetSpec`（`PlayProbe.cs:370-395`）已经有 `dead=` / `hand=` / `chipenemy=` / `sub=` / `legal=` / `pick=` / `tpick=` 七个旋钮，
再加两个即可（**都是单卡专用，不进 `play check` 基线** ⇒ 零全池影响、零基线重建）：

| 旋钮 | 语义 | 落点 |
|---|---|---|
| `chipfriend=N` | 把我方非督军单位扣 N 血（缺省用 `FixtureChip`）—— 与已有 `chipenemy=` **对称**，改法照抄 `PlayProbe.cs:607-613` | `PresetSpec` + 解析（`:500-530`）+ `BuildFixture`（`:712` 之后） |
| `actedfriend=1` | 把 `FIX_A` 置 `AttacksThisTurn=1` + `Exhausted=true`（**并让它留在第一个可选格**） | 同上 |

⚠️ **但按 §一 的证据，这两个旋钮今天救不了任何一张**（`BL64` 卡在选目标、其余 11 张跟它们无关）⇒ **暂缓**，
等方案 A ＋ `cond=341` 修好之后再评估。

### 方案 C（不推荐）：改全池夹具 —— 见 §二 / §三。
