## 三、最小可行实现方案

### A1（推荐先做，**行为级复刻**，风险最小）

> 判据依据：原版 `Icon Currency Drawer Variant` 的 `ItemDrawerComponents` 里 **`background/label/quantity/premiumHighlight/premiumBadge/claimedWarning` 全是 null**，只有 `image` 一件（prefab 实读，见 §1.4 ③ 那一行）⇒ **原版这一格画出来的就是「一张铺满、PA=1 的图」**——**与我们今天画的那一颗 `ImageQuad` 逐项相同**（同矩形 `D_Holder`、同 `preserveAspect = true`）。
> ⇒ 「先接这一跳」不必先把图标换成 `ItemDrawer`；**换成 `ItemDrawer` 反而会变小**（见 A2）。

**A1-1 数据面：把「抽屉的奖励列表」显式化**（`Shell/DailyData.cs`，追加到类尾，⛔ 别插进中间）

```csharp
/// 原版 `DailyRewardDrawerController.Initialize` 收到的 `IReadOnlyList<RewardInfo> rewards`。
/// 我们本地一格只有一条（表来源 = `_rewardFreeName/_rewardIcon/_rewardCount`），长度今天恒 1。
public static CampaignData.RewardSpec[] RewardSpecsOf(int day, bool premium);      // 空名 ⇒ Array.Empty
public static int RewardCountOf(int day, bool premium)
    => RewardCountOverrideForTest >= 0 ? RewardCountOverrideForTest : RewardSpecsOf(day, premium).Length;
/// 自检口（同族先例 `ForceRewardClaimedForTest`）：摆「这一格是几条」，运行时别调。
public static CampaignData.RewardSpec[] RewardSpecsOverrideForTest = null;
```

- **保持 `RewardCountOverrideForTest` 语义不变**（W11 那条断言照样能跑）。
- ⛔ **不要**用 `RewardCountOf` 去伪造 N 条奖励（红线：不编奖励）。

**A1-2 可点闸：按原版类型查表**（`Shell/DailyData.cs`）


- 表内 `true` 的类型 = §1.5 里写「1 ⇒ 可点」的那几行；`false` = 其余。
- **为什么必须出声**：我们的 mock 奖励类型今天**查不到**（`40k_topmarquee_currency_gold` 只有 Sprite、没有 SO；`CurrencyNames` 只认 `C2/C3/C5`）⇒ 按铁律 2 写「查不到」，不许拿「图名里有 currency」当类型判据。

- 在 `:511` 那颗图标**之后**（⛔ 不能之前，见 §四-3）加一颗**隐形命中件**：
