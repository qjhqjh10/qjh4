## §1 `✗ ①h ★★ 填充左缘钉在 Fill Area 左缘 1060.4（实得 1224.19）`

- **现象**：差 **+163.79 px**；同段 ①e/①g（宽 257.0）全绿 ⇒ 只有**位置**偏，尺寸对。
- **判定**：**α**（断言把「页内相对坐标」当成「整窗坐标」）。**实现是对的**。
- **证据**：
  - `Shell/GachaEventWindow.cs:144-149`：`PageDx = 163.7875f, PageDy = 0.1795f`，且 `R(...)` 对**每个**几何常量都 `+PageDx/+PageDy` ⇒ `FillAreaR` 实际 = `(1224.1875, 921.3795)-(1738.1875, 950.3795)`。
  - 实测 `1224.19 = 1060.4 + 163.7875`、`921.38 = 921.2 + 0.1795` —— **逐位吻合**。
  - 该偏移是**原版 prefab 值**（现读 `assets_full/bundle_menus_assets_all/RectTransform/RectTransform_8763003151348586113.json`：`m_AnchorMin/Max=(0,0)/(1,1)` · `m_AnchoredPosition=(82,0)` · `m_SizeDelta=(-163.575,-0.359)` · `m_Pivot=(0.5,0.5)`，父 1920×1080 ⇒ `x1 = 960+82-1756.425/2 = 163.7875` · `y1 = 540-539.8205 = 0.1795`）。

- **修法**（`Editor/C5_Assert.cs:62`，整段替换，可粘贴）：

## §6 `✗ ★ bg 压 Collectable Highlight（实得 ring=3263 < bg=3210）`

- **现象**：第一格描边的队列 = **3263**，而它的 bg = 3210（设计值应为 ring=3209 < bg=3210）。
- **判定**：**γ 回归**，与 §5 **同一条根因**（共用材质 ⇒ 队列也是共用，后写覆盖前写）。
- **证据**：
  - 3263 = `QCellBase 3210 + 9×QCellStride 6 + LC_Ring(-1)`（`AllianceMemberTab.cs:94-115`）⇒ 那是**第 10 格（下标 9）**描边的号；日志 `fin_MainMenuScene.log:133195` 记「实得 10」格 ⇒ 最后建的那一格。
  - `ImageQuad.cs:423-426 SetRenderQueue` 写 `sharedMaterial.renderQueue`；`ImageQuad.cs:300-303 SetMaterial` 又把**每颗自己的旧队列**写到那份**共享**材质上 ⇒ 10 颗描边全部读到**最后一次写入**的 3263。
  - 其它七件的队列正常（日志 `:133030`：`bg=3210 槽底=3211 end=3213 描边=3214 title=3215 counter=3215`）—— 只有走 `MenuFxMaterials` 的那一颗（`Collectable Highlight`）被污染。**这就是判据**。
- **修法**（`Shell/MenuFxMaterials.cs:51-66` 整段替换，可粘贴）：
```csharp
        /// <summary>挂到一张 quad 上。🔴 **每颗 quad 一份实例**：`SetTint`/`SetRenderQueue` 都写在
        /// `sharedMaterial` 上（`Battle/ImageQuad.cs:400`/`:425`）⇒ 共用 `Resources.Load` 回来那一份时，
        /// 同一张图的 N 颗 quad 会**共用染色与队列**（后写覆盖前写）。
        /// 实测：10 颗奖杯描边全被刷成第 10 格的队列 3263（`MainMenuScene` ④b 四条红）。</summary>
        public static void Apply(ImageQuad q, string resPath)
        {
            if (q == null) return;
            var m = Load(resPath);
            if (m == null) return;
            var inst = new Material(m);
            inst.color = q.Tint;          // 把本块**原有**的染色带过去（旧材质上的那一个）
            q.SetMaterial(inst);          // 内部：`mainTexture = 本块的图` · `renderQueue = 本块旧队列`
        }

        /// <summary>挂到一整个九宫格/子树（逐颗转调 <see cref="Apply"/> ⇒ 染色/队列各归各的）。</summary>
        public static void ApplyAll(GameObject go, string resPath)
        {
            if (go == null) return;
            foreach (var q in go.GetComponentsInChildren<ImageQuad>(true)) Apply(q, resPath);
        }
```
- **风险**：低。① 每颗 quad **本来**就是 `new Material(Sprites/Default)` 一份（`ImageQuad.cs:135`）⇒ 克隆后材质数与现状同量级；② 现读全仓 `MenuFxMaterials.Load` **只被本文件两个 `Apply` 用**，没有任何代码在别处改那份共享材质的属性（`grep` 过 `WFUI_`/`Load(`），所以「共享」没有被依赖。
- **替代（不推荐）**：只在 `AllianceMemberTab.cs:718` 就地克隆 —— 只治好这一处；同一病在 `ExpansionPassEventWindow.cs:1013/1267`（`Clock`，队列 `QHeaderIcon`）、`MainMenuRuntime.cs:3112`（`QText`）、`OfferContainer.cs:1545`（`qBase+QoText`）三处**还潜伏着**（见 §9 顺手发现）。
