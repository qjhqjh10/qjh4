### 全部徽章是怎么被取出来的（机制判据）

`AllianceBadgeAssetProvider__GetAssets.c`：
```
lVar1 = SingletonBehaviour<object>__get_Instance(...);
System_Linq_Enumerable__OfType<object>(*(undefined8 *)(lVar1 + 0x40), ...);
```
即「从单例的某个集合里筛出全部 `AllianceBadge`」。而这 16 份 SO 没有任何「列表 SO」指向它们 ——
真正的机制在 **Addressables 标签**里：`catalog.bin` 的地址/标签表中有一个地址就叫 **`AllianceBadge`**（见 §四-3）。
⇒ **复刻口径：应该做成「一次性载入全部徽章、按 `uniqueId` 索引」，而不是「按 id 逐个哈希取」。**

### 徽章绘制链（`AllianceBadgeDrawer__Draw.c` / `__SetTierFrame.c`）

1. `Draw(badge)`：取 `badge.Reference`（+0x10 的 `LoadableReference`）→ 一张 Sprite；
   **取不到就退回 `AlliancesTrophyController.DefaultTrophy`**；连控制器实例都没有则**抛异常**（不是静默）。
2. 设完图后 `SetTierFrame(badge.Tier /*+0x18*/)`：`index = Math.Max(0, tier - 1)`，
   从 `AlliancesTrophyController.tierFrames[]`（`AssetReferenceTyped<Sprite>[]`，dump.cs 里 `// 0x28`）取边框图，赋给另一个 `Image`。
   ⇒ **`tier = 0` 会得到 index 0 = `TIER1`**（0 不会画「无边框」）。
3. 名字走 `AllianceBadge.LocalizedName` = `"<前缀>" + GetID()` → `LocalizationManager.GetTranslation(...)`
   （前缀常量是 `DAT_184252eb0`，**是个 metadata 指针，没能读出字面量**，见 §六）。

### 4-6 方法论（给下个代理，可省一整轮）

- ❌ **别拿类名/字段名去扫包内字节**：Unity 序列化数据**不含字段名**，也不含 SO 的类名（只有 `m_Script` 的 pathID）。
  `AllianceBadge` 在 84 个包里字节级 0 命中，而它确实是那 16 份 SO 的类 —— 扫 0 **证明不了任何事**。
- ✅ **判「某类 SO 本地有没有」的正确顺序**：
  ① `grep` **它的独有字段名**（如 `badgeImage` / `keepPointsOnLeave`）在 `assets_full/**/MonoBehaviour/*.json`；
  ② 若 0 命中，再用 **`catalog.bin` 的地址表**看这个名字在不在；
  ③ 最后才谈包字节。
- ✅ **类名 ↔ SO 的铁证**：`Waprforge_monoscripts.bundle` 里 `m_ClassName` ↔ pathID，再对 SO 的 `m_Script.m_PathID`。
