## §1 `param_11` = `dontResolveEnchantments`（Oath / 360 支）

### 结论
- 权威签名（`out_cpp2il_dev_ilspy/RawCardScript.cs:1266`）：`TriggerAbilities(trigger, manager, thisCard, cardPlayed,
  targetCard, damageInfo, isEnchantment=false, resolveOnlyEnchantments=false, ignoreRandomTrigger=false,
  **dontResolveEnchantments=false**)` ⇒ `param_8/9/10/11` 依次是后四个 bool。
- 闸本体 `RawCardScript__TriggerAbilities.c:50-51`：`if (activeEnchantments(+0x110) 空 || Count<1 || param_11 != 0) return;`
  ⇒ **只挡附魔趟，不挡载体自己那趟**（两趟并列，见 `B109_R2` §1.2）。
- **什么时候为真**：传 1 的地方**只有 3 处** —— `AbilityLogic__PlayAbility.c:2038 / :2051 / :2063`
  的 `RawCardScript__OnTriggerAlt(…, 0, 0, 1)`；三处同属 `:1994` `iVar8 != 0x168` 的
  `chosenAbility == 360 = playChosenCardAbility` 支（`dump.cs:20710`），`:2015` 读 `bm.cardChosenInSelection(+0x2E8)`。
  交叉印证 `out_il2csharp/AbilityLogic.cs:2653 / 2675 / 2689` 三处末两实参恒 `(0, 1)`。
  `OnTriggerAlt` 是**纯 thunk**（`RawCardScript__OnTriggerAlt.c:1-20` → `TriggerAbilities(…, isEnchantment=0, p7, p8, p9)`），
  重放的是 **`ThisCardPlayed`(0)**，不是别的触发。
- **语义（一句话）**：360 让「选中的那张卡」按 `ThisCardPlayed` 再跑一次，但**不许重复派发载体
  （`abilityData.thisCard` = 那个 360 卡）身上的附魔趟** —— 那张卡被正常打出时附魔已派过一轮。
  带 `oath`（`:2038`）与不带（`:2063`）**两条子支都传 1** ⇒ **不是「oath 专属」，是「360 重放」专属的防重复派发闸**。

## §2 410 去重怪癖：`+0x20` = `CardAbility.triggerValue`

### 结论
- 字段确认（`dump.cs:20340` 起）：`CardAbility { trigger @0x10; abilityContext @0x14; priority @0x18; playIcon @0x1C;
  **triggerValue @0x20**; actingCardCriteria @0x28; … }` ⇒ `.c:148` 的 `*(int*)(lVar2+0x10) == 0x19a` = `trigger == 410`
  （`FollowUpResolution`，`dump.cs`），`.c:158` 的 `*(int*)(lVar2+0x20) == 1` = **`triggerValue == 1`**。
- 去重语义（`.c:136-137` + `:148-164`，与 `out_il2csharp/RawCardScript.cs:1134-1136`、
  `out_cpp2il_dev_ilspy/RawCardScript.cs:1513` 三方一致）：
  ```
  obj = null;                                              // 一趟 TriggerAbilities 一个
  逐件附魔 → 逐条 ability：
      if (附魔卡 != null && obj == 附魔卡) 跳过这条 ability;              // .c:136-137
      if (ability.trigger == 410 && ability.triggerValue == 1) obj = 附魔卡;   // .c:148/158/163
      TriggerAbility(ability, …, 附魔卡, enchantmentCardID);                    // .c:184-186
  ```
  ⇒ **同一件附魔**在本趟派过一条 `410 + triggerValue==1` 之后，它**后面的 ability 全被跳过**。
  `CanTriggerAbility.c:71` 已要求 `ability.trigger == 广播 trigger` ⇒ 这段**只在广播 trigger == 410 时才可能生效**。
- 可达性（现读 `cards_truth.json` × `enchantment_templates.json`，85 张模板）：带 410 ability 的模板**只有 1 张** =
  `Hallowed Martyrs`（`752141bbf0543314987e3b9afed938af`），abilities 顺序 = `[130, 410(value=1)]`
  ⇒ 410 是**最后一条**，后面没有可跳过的 ⇒ **结构性存在、当前数据零可观测**。
  全库含 `triggerValue` 的 ability 59 条，其中 410 的**只有这一条**。

### 我们现状
- `EffectResolverPartial_B109E6.cs:106-150` `FireEnchantmentAbilitiesByNumber`：**一件附魔只发一次信号**，
  没有「逐条 ability」那一层循环 ⇒ 这条怪癖在我们模型里**无处可落**。
- 数据半也缺：`CardDef.TriggerAbilityIndexSpec`（`Core/CardDef.cs:9225-9236`）只有 `Ab/Lg/Trigger`，**没有 `TriggerValue`**；

## §3 `AbilityData +0x4c` = `enchantmentCardId`（**不是能力下标**）

### 结论
- `dump.cs:19556` 起：`AbilityData { thisCard @0x10; actingCard @0x18; targetCard @0x20; baseEnchantmentCard @0x28;
  isPlayerTurn @0x30; damageInfo @0x38; whileInPlay @0x40; whileInPlayVariable @0x41; priority @0x44;
  blockPlayerActions @0x48; **enchantmentCardId @0x4C** }`。
- `TriggerAbility` 权威签名（`dump.cs:23484`，与 `RawCardScript__TriggerAbility.c:2-5` 的 9 个形参逐一对应）：
  `TriggerAbility(CardAbility ability, BattleManager manager, CardScript thisCard, CardScript cardPlayed,
  CardScript targetCard, DamageInfo damageInfo, RawCardScript enchantment, **int enchantmentCardId = -1**)`
  ⇒ `param_9` = `enchantmentCardId`；`.c:72` `*(AbilityData + 0x4c) = param_9;`。
- **`.c:184-186` 那个实参读的是 `ActiveEnchantment` 元素、不是 ability**：`TriggerAbility(…, 附魔卡 = entry+0x10,
  **entry+0x18**, 0)`；`ActiveEnchantment { enchantmentCard @0x10; **enchantmentCardID @0x18** }`（`dump.cs:118926`）。
  交叉印证 `out_il2csharp/RawCardScript.cs:1136`：`TriggerAbility(..., list13[num1].enchantmentCard, list13[num1].enchantmentCardID)`。
  ⇒ ✅ **`B109_R2` §5·5 的「`param_9` 传的是 `ability + 0x18`（同 `+0x44`）」是错的**：`+0x44` 收
  `CardAbility.priority(+0x18)`，`+0x4c` 收 `ActiveEnchantment.enchantmentCardID(+0x18)` —— 两处都写「`+0x18`」，
  但**读的是两个不同对象**。载体自己那趟传 `0xffffffff` = `-1`（`.c:231/257`）。
- 它是什么：`CardScript.AddEnchantment` 里 `id = bm.__field_enchatmentsUsed; bm.UsedEnchantment();`
  （`out_il2csharp/CardScript.cs:11810-11812`，同 `:11359-11360`）⇒ **本局第几件被挂上去的附魔**（流水号），**不是卡 id**。
- 下游唯一消费：`AbilityLogic__PlayAbility.c:1207/1253/1356` `*(CardEffect + 0xa4) = *(AbilityData + 0x4c);`
  ⇒ `CardEffect.enchantmentCardId`（`dump.cs:119112`），被 **`CardEffect.IsSameEffect`**（`CardEffect.cs:190`）与
  **`CardScript.AddEffect` 合并循环**（`CardScript.cs:10753-10754`：不相等就不合并）当**合并/去重键**。
  语义 = 「同一张附魔卡的**不同次挂载**不算同一条效果」。

### 我们现状
- ✅ **字段早就有、来源相同**：`Core/Enchantment.cs:136` `ActiveEnchantment.EnchantmentCardId`，写点 `:257-258`

- ❌ `ActiveCardEffect`（`Enchantment.cs:71` 起）**没有这一格**，全仓也没有任何消费点。
- 🔑 **为什么传 `-1` 今天等价**：这格唯一用途是**合并键**，而我们的模型**从不合并**
  （`Core/UnitState.cs:1814-1834`：等价于 `doNotStack = true`，求和逐字节相同，差异只在「按记录摘」的粒度）；

  ⇒ **数值零差异**，只是**结构不忠实**。
