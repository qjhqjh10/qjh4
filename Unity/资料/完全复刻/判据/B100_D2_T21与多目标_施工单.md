## A. T21 手牌锚路

### A·1 原版怎么做（判据链，逐跳）

**① 手牌里的卡确实会被触发，且事件落点就是那张手牌**

- `CardAbility__IsRightContext.c:1-90`（`abilityContext == 10 (Hand)` ⇒ **`CardScript.IsInHand(card)`**）
  ⇒ 手牌卡自己的 ability 只能**在手牌里**触发。
- 广播那几跳（`BattleManagerSupport__BroadcastTurnEnd.c` / `__BroadcastTurnStart.c` / `__BroadcastUnitDamaged.c` …）都带「当前回合方手牌 → 另一方手牌」两跳，接收端 `CardScript.OnTrigger(...)` 逐张调。
- 我们引擎里的等价物有三条发射口（都发 `EvtKind.Trigger` + `Slot = -1`）：
  - `EffectResolver.cs:18852-18861` `EmitHandAbilityTrigger` —— `ctx.Emit(EvtKind.Trigger, owner, **-1**, card.Name, keyword: triggerName, instanceId: inst.Id)`（**`InstanceId` 有值**）；
  - `EffectResolver.cs:8344-8365` `EmitCardTrigger` —— `unit == null` 时 `slot = -1`，且 **`instanceId: unit != null ? unit.InstanceId : 0` ⇒ 手牌这一跳 `InstanceId = 0`**；
  - `EffectResolver.cs:8588-8607` `EmitTurnTriggerRaw` —— 同上，手牌那一趟（`:8693` `EmitOne(j.Card, j.Owner, null)`）也是 **`InstanceId = 0`**。

**② 原版锚点 = 那张手牌自己的 2D 卡，不是屏幕中心**

`CardScript__GetEffectAnchor.c`（**全文 18 行，逐句**）：

```
iVar1 = *(int*)(param_1 + 0x228);               // CardStateOptions
if (iVar1 ∈ {4, 9, 0xc(12), 10, 8, 1, 0, 0x10(16)})
    → cardUI(+0x290) + 0x30                     // 「2D 卡」那一级
else
    → cardUI + 0x1a0                            // 场上卡那一级
```

`CardStateOptions`（`D:/2/Warpforge_code/Scripts/Assembly-CSharp/CardStateOptions.cs`，现读）：
`inDeck=0 · inHand=1 · inPlay=2 · inPlayAttacking=3 · waitingToBePlayed=4 · waitingToDie=5 · inCemetery=6 · drawing=7 · inHandShowing=8 · inHandMoving=9 · inHandPlaying=10 · removedFromGame=11 · inHandJustCreated=12 · inMulliganSelected=13 · inMulliganDiscarded=14 · inPlayTransforming=15 · inDeckDrawing=16 · inPlayAminingAttack=17`

⇒ **手牌（`inHand=1`）走 [+0x30] = 2D 卡那一级**；只有 `inPlay=2 / 3 / 17` 等才走 `+0x1a0`。

**③ 锚点怎么被用**：`AbilityLogic__PlayAnim.c` 对每一条 `cardAnimations[]` 调
`AbilityLogic.GetPos(bm, thisCard, targetCard, sp/ep/pt)`；其中

- `case 0 self`（`AbilityLogic__GetPos.c:183-187`）：`thisCard(+0x10)` → **`GetEffectAnchor()`**
- `case 1 cardTarget`（`:186-190`）：`targetCard(+0x20)` → `GetEffectAnchor()`
- `case 2 abilityTarget`（`:191-219`）：目标列表里的那张 → `GetEffectAnchor()`；目标为空 ⇒ 退 `+0x20`，再退 `+0x10`

⇒ **「自己」这一档 = 发出这条能力的**那张卡**的 2D 卡锚**。手牌陷阱 = 那张手牌本身。

**④ 我们已有的等价件（不用新建）**

- `CardView.cs:2149-2155` `EffectAnchor(bool onBoard)` ⇒ `onBoard ? EffectAnchorBoard : EffectAnchorHand`，而 `EffectAnchorHand = FaceRoot`（`CardView.cs:2128`，= `2DCard`）。
- `AnimAnchors.CardAnchor`（`AnimAnchors.cs:275-284`）用 `OnBoardOf(card)` 判哪一支。
- `BattleDriver.cs:3998-4004` `IsViewOnBoard` —— 手牌视图**不在** `_myUnits/_foeUnits` ⇒ 返回 `false` ⇒ 自动取「手牌档」。
  ⇒ **只要把手牌那张 `CardView` 当 `self` 传下去，锚点就自动是对的**，无需新写锚点解析。

### A·4 精确改法（施工点 3 处 + 1 处可选）

#### 施工点 ①（必做，核心）：`BattleDriver.cs` `PlaySignal` 加「手牌锚支」

**位置**：`:23282-23300` 之间 —— 在 `if (slot < 0 && e.Kind == EvtKind.Play) { … return; }` **之后**、`if (slot < 0) return;`（`:23300`）**之前**插一段 `if (slot < 0 && e.Kind == EvtKind.Trigger) { … return; }`。此时 `evt` / `perCardOnly` / `triggerKeyword` / `faction` 都已算好（`:23095-23128`），**不需要重算**。

**伪代码（照现有 `EvtKind.Play` 那一支的形状写，⛔ 不要另立一套播放器）**：

```csharp
if (slot < 0 && e.Kind == EvtKind.Trigger)
{
    // 原版：手牌里的卡锚 = GetEffectAnchor → 状态 inHand(1) ⇒ cardUI+0x30（2D 卡那一级）
    // 判据 `CardScript__GetEffectAnchor.c`（全文 18 行）+ `CardStateOptions.cs`
    string hFaction = VfxFactionOf(e.Player, e.CardId, e.InstanceId, e.Slot);
    CardView hv = HandCardViewOf(e.Player, e.CardId, e.InstanceId);   // 见施工点 ②
    Vector3 pos;
    if (hv != null) { var a = hv.EffectAnchor(false); pos = a != null ? a.position : hv.transform.position; }
    else
    {
        // 对手手牌：我们只有卡背（`_foeHandViews` 是 ImageQuad、没有 CardView）
        //   ⇒ 退手牌容器锚（`AnimAnchors.HandAnchorOf(seat)`，`BattleDriver.cs:3727-3731`）
        var t = HandOf(e.Player) != null ? HandOf(e.Player).transform : null;
        pos = t != null ? t.position : LayoutSpace.ToWorld(0.5f, 0.5f);
        // 🔶 自己设计（非原版）：对手手牌没有 2D 卡视图，用「手牌容器锚 + 容器内该卡格位」
        //   近似原版「那一张手牌的 2D 卡锚」。判据：原版是具体到**那一张**；我们只有卡背。
    }
    int nPlaced = PlayPlacedPieces(e, evt, hFaction, perCardOnly, triggerKeyword,
                                   hv, null, pos, handAnchored: true);
    if (nPlaced == 0)
        Debug.LogWarning($"[Battle] `{e.CardId}`（手牌触发 · `Slot = -1`）在 `trigger` 桶里"
                       + "**没有任何候选件** ⇒ 这条事件什么都不会播（如实报，⛔ 不静默）");
    return;
}
```

**四条硬约束（⛔ 别省）**：
1. **不要改 `IsHudAnchoredEvent`**（`BattleDriver.cs:24697-24700`）：那条判据的语义是「**落点在 HUD 固定锚上**」（资源图标 / 抽牌终点）。手牌陷阱的落点是**一张会动的卡**，塞进那一族会让 `HudAnchor01` 去算错的点，而且会把自检那条断言的意思弄坏。**另开一支**。
2. **不要删 `if (slot < 0) return;`**（`:23300`）：它还要拦「从牌库直接进弃牌堆」那一类（`:23300` 原注释）。新分支只放行 `Trigger`。
3. **必须保留 `PlayPlacedPieces` 那条路**（⛔ 别直接 `CardEffects.Fire`）：这些卡的 `AnimInfo` 有 `mv` / `pt` / `ts`/`tm` 参数（`cardanim_clips.json`），走 `PlayPlacedOne → PlayAbilityBeat` 才逐字段照抄原版 `AddCardAnim`。
4. **对手侧必须出声**（⛔ 不静默降级）：没有 `CardView` 是**我们的模型缺口**，要在同一个 `BeatSoundOff` 口径下打一次。

#### 施工点 ②（必做）：新增「按身份找手牌视图」帮手

`BattleDriver` 今天**没有**这个口（`_handViews` 只按索引取：`HandViewAt(int)` `:33414`；`HandIndex(CardView)` `:33421`）。

```
CardView HandCardViewOf(int seat, string cardId, int instanceId)
```
- `seat == _me`：先按 `_handViews[i].Inst != null && Inst.Id == instanceId`（`instanceId != 0` 时）；
  否则按 `Ctx.Players[_me].Hand[i]` 与 `_handViews[i]` **同下标**（`BattleDriver.cs:27504` 那条 `i < _handViews.Count && i < h.Count` 就是这条同下标约定的证据）逐张比 `Card.name`。
- 同名 **≥2 张** 且 `instanceId == 0` ⇒ **`BeatSoundOff` 出声一次**并取第一张（见施工点 ④）。
- `seat != _me`：恒 `null`（对手手牌没有 `CardView`）。

#### 施工点 ③（必做，波及 `PlayPlacedOne` / `PlayPlacedPieces`）：`handAnchored` 参数

**为什么**：`PlayPlacedOne`（`BattleDriver.cs:24071-24088`）今天有一条降级：
`self == null && sp ∈ {self,cardTarget,abilityTarget} && e.Slot < 0` ⇒ `sp = createCardPos(140)`（**屏幕中央**，`:24074-24079`）。
对手手牌那一侧 `self` 恒 `null` ⇒ 会落进这条降级 ⇒ **播在屏幕中央**（原版播在对手那张手牌上）。

**改法（方法内、零行数变化，照 `B99_R3a` 的口径「只收紧、别删整条 140 降级」）**：

- `PlayPlacedPieces` 增可选形参 `bool handAnchored = false`（追加在形参表尾，⛔ 别插在中间）；
- 透传给 `PlayPlacedOne`；
- 在 `PlayPlacedOne` 的 `e.Slot < 0` 那一格加前半句：
  `if (e.Slot < 0) { sp = handAnchored ? (e.Player == _me ? (int)PositionOption.friendlyHand : (int)PositionOption.enemyHand) : (int)PositionOption.createCardPos; }`
  （18/19 两档由 `AnimAnchors.HandAnchorOf` 解，`BattleDriver.cs:3727-3731` ⇒ 手牌容器锚）。
- **`positional 140` 那条降级原样保留**给 `EvtKind.Play` 的未指定目标战术卡（`:23289` / `:23564`）。

#### 施工点 ④（建议同批做，小）：让手牌那一跳的事件能**指名到实例**

现状：`EmitCardTrigger`（`EffectResolver.cs:8362`）与 `EmitTurnTriggerRaw`（`:8606`）在 `unit == null` 时写 **`InstanceId = 0`** ⇒ 表现层只能按**卡名**猜是哪一张手牌（同名两张时无法分辨）。
- **最小改**：给这两处加可选形参 `int instanceId = 0`，**手牌那三跳**（`EmitAtTurnTriggerPass` 的手牌趟 `:8693`、`BroadcastHandTrapWhen` 的 `EmitListenerTrigger` `:10779`、`BroadcastHandWhen`）把**那一份 `CardInstance.Id`** 带进去。
- **判据**：原版这一跳的 `thisCard` 就是**那一张 `CardScript` 实例**（`CardScript.OnTrigger` 的 `this`），不是「同名的某一张」。
- ⚠️ 这会不会动 `play check` 指纹：**不会**（`BattleEvent` 不进录像/联机、`ctx.Events` 里有 `InstanceId` 但 `Fingerprint` 只看局面量；**开工前请调度台按既有口径再核一眼**）。
- 若本批不做 ⇒ 施工点 ② 必须**出声**（不许静默取错）。

### A·5 还差什么（判据缺口 / 伴随项，⛔ 别当成「顺手做完」）

#### ⛔ 为什么不建议照 `B99_R3a` 施工单那条「`ResolveTarget` → `ResolveTargets`」

`B99_B1` 已给三条反证，本代理**复核成立**：
1. **类型对不上**：`AbilityTargetsFor` 的 `spec` 是 `EffectSpec`，`ResolveTargets`（`EffectResolver.cs:1440`）要 `EffectTargetSpec`。
2. **`ResolveTargets` 有副作用**：无条件写 `ctx.LastTargets/LastTarget` + `NoteTriggerTargetSink`（`:1446-1447`）⇒ 会改掉这条能力后续 op 的 `it`/`them` 指代。
3. **映射不等价**：`ResolveTargets(enemy, unit, 1)` 先排督军、敌方没部队时返回**空表**，而 `ResolveTarget("EnemyUnit")` 有 `chosen` 就用它。

⇒ 只能新写一个**只读、只产出列表**的函数（施工点 ①）。

### B·6 还差什么（判据缺口，⛔ 不许猜）

1. **多行 ability 怎么合并成一条事件的 `AbilityTargetList`** —— 原版是「每 logic 一次 `GetTargets` + 一次 `PlayAnim`」，我们一条 `EvtKind.Ability` 管一整条 ability（`RuleCore.cs:15507`）。**取第一行？并集？** 判据**没查清**（原版 `ResolveActiveAbility.c:58-67` 是逐行 `PlayAbility`，但我们的表现层已经把「一条 ability 的所有拍」放在同一条事件上）。
   ⇒ **必须调度台裁**，或另派代理把 `PlayAnim` 的调用粒度查透（提示：`AbilityLogic__PlayAbility.c:1524-1531` 是**第二条** `GetTargets + PlayAnim` 的调用点，说明一条 logic 可能触发两次 PlayAnim）。
2. **`ta=150 previousAbilityFiltered` 落到手牌**（`SW8`）：`BattleEventTarget` 只能表达「棋盘格」。要支持「手牌里的那张」，`BattleEventTarget` 得加一档（或复用 `Slot = -1` + `InstanceId`，但消费端 `ViewAt` 拿不到）。
3. **`ta=0 any` 的「双方全部单位」**：本族**现读 0 拍**（`AM1` 那张的 `sp/ep/pt==2` 拍走的是 `ta=30`），⇒ **休眠机制**（铁律 11：要做，但今天零可观测）。`ResolveTargetsCore` 里 `ta=10` / `ta=0` 的**结算侧**也被标成「我们这一列没落那些位 ⇒ 拿不准」（`EffectResolver.cs:1680-1682` 的注释）⇒ **表现侧与结算侧要一起做**，⛔ 别只做一半（账要并到同一笔）。
4. **`targetSelectMethod = random` 的随机源**：必须照 `CLAUDE.md §三` 那条（预烧 100 个 + 下标），⛔ 别在结算里直接 `ctx.Rng.Next`。**这会影响 `play check` 指纹** ⇒ 与本单同批要重钉基线（属调度台）。
5. **原版「对手手牌里的目标不播」那条闸**（`PlayAnim` 的 `CardScript.IsInHand(item) && item.isPlayer == 0 ⇒ LogWarning + continue`）我们**没有**（因为我们连目标表都没有）。施工点 ① 落地时**必须一起照抄**，否则会播原版不播的那一份。
