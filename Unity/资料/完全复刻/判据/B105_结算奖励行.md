## 0. 一句话结论

**原版这一排奖励 = 服务器 PlayFab CloudScript 返回体里的 `OnlineMatchResult.EndMatchData.Rewards`；客户端没有任何本地战斗奖励表或生成器。**
原版在「拿不到服务器结果」时**连 `ShowRewards` 都不调用** ⇒ 整个奖励块（含骷髅行 / 评分）保持隐藏。
⇒ **我们现行「不喂 + 整行藏」= 原版的离线等价。判定 `D（服务器）`，不接本地模拟。**

## 2. 判定

### 2.1 `D（服务器）`

奖励数组的唯一生产者是 **PlayFab CloudScript 的返回体**。关服后本地永远拿不到「原版一局给什么奖励」的那份判据。

### 2.2 同一件事的另一面：`空着更接近原版`

原版**没有任何一条离线/本地分支会造出非空 `Rewards`**。逐 matchType（判据 = `PlayerDataManager.ProcessMatchEndResult`，
ILSpy `out_cpp2il_dev_ilspy/PlayerDataManager.cs:8475`，方法体逐支；`.c` 版 = `PlayerDataManager__ProcessMatchEndResult.c:100-117`）：

| MatchType | 本地分支做什么 | 奖励 |
|---|---|---|
| `Ranked(10)` · `RankedBot(20)` | **什么都不调**（不触发回调，直接 `inventoryOpsThisSession = 0; return`） | — |
| `Tutorial(100)` | `RecordTutorialFinished(...)` + `CreateTutorialResult(winner)` → 回调**非 null** | **空数组** |
| `Replay(160)` | `LogWarning("Not recording yet match results for playMode")` + `CreateTutorialResult` → 回调**非 null** | **空数组** |
| `TutorialReplay(140)` · `Scene(190)` | 直接以 **null** 回调 `callbackOnSuccess` | — |
| `PracticeOffline(50)` · `Practice(90)` · `EventAI(80)` · `Undefined(0)` · `Unranked(170/180)` · `FastMode(200/210/211)` | `CustomDebug.LogError("Not recording yet match results for playMode X")` 后以 **null** 回调 | — |

⇒ 回调拿到 `null` ⇒ `RankedMatchResult.onlineMatchResult(+0x38) == null` ⇒ `MatchResultData.grantedResult(+0x20) == null`
⇒ `EndBattleDoors__SetupDoor.c:104 if (param_5 != 0)` **不成立** ⇒ `ShowRewards` **一次都不执行** ⇒ 第 7 跳那串 `SetActive(false)` 就是最终状态（**整块全藏**）。

**所以「空着」不是我们的妥协，它就是原版的离线形状。**

### 2.3 时间限定与判据边界

- 判据来自**当前 build**（`GameAssembly.dll`）的三份反编译产物：`decomp_full`（`.c`）· `out_cpp2il_dev_ilspy`（`.cs`）· `out_il2csharp`（第三方交叉）。三源在「数据来自云脚本」这一点上一致。
- **服务器关服后无法验证**：真实下发的那份 `EndMatchResult` 里 `Rewards` 到底有哪些 item id / 数量 / `RewardTier`。**这一格查不到**（见 §5）。

## 3. 若判定要「接」（**结论是不接**；此节只留将来若改判的最小接法）

⛔ 现在**不要**做这一步 —— 按 §18·0，只有「确实需要和服务器有关的设计」才允许自造；而 §2.2 已证明**原版的离线等价就是空**，自造只会比原版更假。

若将来用户明确要「本地模拟奖励」：

1. **数据源必须自造**（本地没有，见 §5），且必须打
   `// 🔶 自己设计（非原版）：… · 为什么必须自己定：原版奖励来自 PlayFab CloudScript，服务器已关服 · 谁定的 + 日期`。
2. **类型口**：`Shell/PlayEvent.cs:288` 的 `OnlineMatchResult`（字段 `EndMatchData` 在 `:297`）/ `:306` 的 `EndMatchData` 现在是 `🔶 自己设计` 的**子集**，**故意没搬 `Rewards`**（该文件注释明写）。要接就得在那两处加 `public List<RewardInfo> Rewards;`。
3. **填值口**：`Shell/FastModeBaseEvent.cs:472-496 RecordMatchFinished` 那条「本地等价」（`callbackOnSuccess(new OnlineMatchResult{success=true, …})`），以及 `Shell/GameModesHandler.cs:163 CombatFinished` 的分派路径。
4. **显示口**：`CardPresentation/Battle/BattleDriver.cs:32548 _endPanel.Show(...)` 之后加一句
   `_endPanel.SetRewards(list);`（`EndPanel.cs:913`）。
   - 放 `Show` 之后是因为原版次序是「`SetupDoor` 先全藏 → `ShowRewards` 再点亮」；
     我们的 `EndPanel.SetVisible` 末尾也会跑一次 `ApplyRewardVisibility()`（`EndPanel.cs:778`），所以**前后都安全**，但放后面更贴原版。
   - **⛔ 不要**改成「`Show()` 直接吃一个 rewards 参数」把两件事耦合起来 —— `SetRewards` 的 doc 已经把「这一屏要显示什么」与「怎么发放」分开了。
5. **失败出声**：原版的离线/未知模式是 `CustomDebug.LogError("Not recording yet match results for playMode X")`，**画面无提示**。
   我们对应 = **一条 `Debug.Log`**（不是弹窗、不是空奖池占位）—— 这正是「空着并出声」的正确粒度。

## 4. 判 `D` 的覆盖说明

### 4.1 「原版调用链断在这儿」

`d:/2/tools/decomp_full/EndBattleDoors__SetupDoor.c:104`
```c
if (param_5 != 0) {
  EndBattleDoors__ShowRewards(param_1,param_2,param_5,param_6,param_7,0);
}
```
`param_5` 只由 `MatchResultData.grantedResult`（`+0x20`）喂进来（`BattleManager._CloseBattleDoors_d__393__MoveNext.c:36`）；
而它唯一的赋值点是 `BattleManager._ShowFinishScreen_d__362__MoveNext.c:50`，来源是 `OnlineMatchResult.EndMatchData`；
`OnlineMatchResult` 只能由 **CloudScript 返回体**反序列化得到（§1 第 2/3 跳）。**断点就在第 2 跳。**

### 4.2 我们的替代物（现在 = 空行 + 注释）

| 面 | 我们 | 判据/位置 |
|---|---|---|
| 行容器 | 照原版建，**建完即 `SetActive(false)`** | `EndPanel.cs:961-962`（`BuildRewardsRow()`，宿主调用点 `:518`） |
| 数据 | **恒空**（零生产调用点） | `EndPanel.cs:913 SetRewards` · `:842 _rewardItems` |
| 显隐 | 0 条 ⇒ 整行连底板藏 | `EndPanel.cs:1095 ApplyRewardVisibility` |
| 断言把这一态钉住 | C2（`Create()` 后行是藏的）· C3（清单 0 条）· C4（喂 1 条就亮，互为灭自证） | `Editor/B98A2_Assert.cs:225-236` |

**覆盖范围**：奖励行的**几何 / 填充 / 字号 / 显隐**全部照原版复刻（`B97_W8` · `B97_W41` · `B98_A2`）；
**只有「数据」这一格**按 `D` 处理 —— 这与原版「没有服务器就没有奖励」是**同一个行为**，不是缺口。

### 4.3 一处如实差异（记录，不判缺陷）

原版在 `grantedResult == null` 时 **`ShowRewards` 整个不执行**，因此**骷髅行 / 评分也都不显示**（只剩 `SetupDoor` 里那一串 `SetActive(false)`）。
我们的 `EndPanel.Show` 仍然会点亮骷髅行（`EndPanel.cs:667-670`，判据 = `EndBattleDoors__ShowRewards.c:55`）。

- 这**不是**漏复刻：原版的骷髅数 `BattleScoreManager.GetSkullCount()` 本来就是**本地**算的；
  而我们**没有服务器**，不可能走到「`grantedResult == null`」这一格（我们的 `_matchResultProcessed` 是离线等价恒真，见 `BattleDriver.cs:32476`）。
- 我们最接近的原版档 = **教程/回放档**（`CreateTutorialResult` ⇒ `grantedResult` 非 null ⇒ `ShowRewards` 执行 ⇒ 骷髅照常显示、奖励行空）。
  在这一档下我们的行为**完全一致**。
- ⇒ 结论：**保持现状**。若将来要严格区分「有/无服务器回执」两档的骷髅显示，那是**另一条独立的裁定**，不在本账范围。
