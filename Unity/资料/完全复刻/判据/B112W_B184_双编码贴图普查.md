## 五、修复口径（给写手照做，**两步缺一即错**）

> 🔴🔴 **2026-11-01 就地订正（`B112W_B184` 根因修复代理现核）：本节「linearize + `.meta` 改 0」是【Linear 工程】下的口径，我们在 2026-11-01 当天已经切成 Gamma ⇒ 照它手工 linearize 会把这 22 张改成【偏暗】（反向错）。**
> **正确口径 = 「落盘字节 = 原版原始字节 + `.meta` = 原版 `m_ColorSpace`」**，由 `EffectExporter.cs` 生成链路保证（根因在 `ReadableCopy` 的 `RenderTextureReadWrite.sRGB` 写死 + `ImportTexture` 的 `sRGBTexture = true` 写死，已修）。
> 本节其余内容**作为「为什么会出现 encode(原版)」的诊断记录保留**，⛔ **不要再照它手工改图**。详见 `报告/B112W_B184_根因修复.md`。

### 为什么必须两步

- **现状**：PNG 里存的是 `encode(原版)`，`.meta` 写 `sRGBTexture: 1`。
  - **Linear 工程**：采样时 Unity 按 `sRGBTexture` 做**一次 sRGB→linear 解码**，正好抵消导出时那次编码 ⇒ 看到的是原版 ✅
  - **Gamma 工程**：`sRGBTexture` **完全不生效**（Gamma 下采样不做任何 sRGB 转换）⇒ 直接拿到 `encode(原版)` ⇒ **偏亮** ❌
- **目标**：让两种色彩空间都得到原版值。

### 第一步：把 PNG 反算回线性（`p_new = linearize(p_old)`）

对 **R/G/B 三个通道**逐个像素（**alpha 原样保留，不做任何变换**）：

```
l   = c / 255                      # c = 当前像素值
lin = l <= 0.04045 ? l / 12.92 : ((l + 0.055) / 1.055) ** 2.4
out = round(lin * 255)
```

### 第二步：`.meta` 改 `sRGBTexture: 1 → 0`

22 张的 `.meta` 里 **`sRGBTexture` 只出现 1 次**（第 10 行，`TextureImporter` 块内，`enableMipMap: 1` 的下一行）。
用**定点替换那一行**即可；⛔ **别用全文件正则**（平台覆盖块里还有别的 `maxTextureSize` 一类字段）。

### ⚠️ 只做一步会怎样

| 只改 | Gamma 工程 | Linear 工程 |
|---|---|---|
| 只改 `.meta` | 不变（仍然偏亮）❌ | **变坏**：不再解码 ⇒ 拿到 `encode(orig)` ❌ |
| 只改 PNG | ✅ 正常 | **变坏**：会被再解码一次 ⇒ 变成 `linear(orig)` ❌ |
| **两步都做** | ✅ = 原版 | ✅ = 原版（`sRGBTexture:0` ⇒ 不解码，直接用线性值） |

### 建议的执行方式

1. 只处理 **§二 那 22 个文件**，路径前缀 `D:/4/Unity/MyGame/Assets/WarpforgeVFX/Textures/`。
   ⛔ **不要遍历整个目录**（459 张 EXACT 动一张就坏一张）。
   ⛔ **不要碰 `ArenaOriginalPrefabs/`**（那里的同名文件是法线打包变体）。
2. 写 PNG 时保持 **8-bit RGBA**、尺寸不变、**alpha 通道逐字节不变**；别引入调色板/灰度/16-bit。
3. 改完 `.meta` 后让 Unity 重新导入（或在批处理里 `AssetDatabase.ImportAsset(path, ForceUpdate)`）。
   guid 不变 ⇒ **不会断引用**，不需要动 `.mat` / `.prefab`。
4. **自检口径**（改完必须复算，⛔ 别只看"改过了"）：
   - 改后 PNG 与 §二 备注里的原版原件：**alpha 掩码下直接比 RGB MAE 应 ≈ 0**（预期 ≤ 1.0/255）；
   - `.meta` 里 `sRGBTexture: 0`；

## 附：复算方法（可复现）

- 原版：`Image.open(...).convert("RGBA")` → float/255。
- sRGB 编码：`c<=0.0031308 ? 12.92c : 1.055c^(1/2.4)-0.055`，逐通道。
- 比较：`mask = (ours.A>0.02) & (orig.A>0.02)`；RGB 只在 mask 上算，alpha 全图算。
- 尺寸不同时：先试「alpha 包围盒 ±k 像素」的滑窗（中心 ±10，失败则**全位置穷举**），
  取 `min(直接比, encode比) + alpha比` 最小的窗口；仍不行才 `LANCZOS` 缩放到我们的尺寸（本次**一张都没用到**）。
