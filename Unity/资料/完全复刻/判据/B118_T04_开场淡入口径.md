## 2 · 那 6 个停用组件的真相（**判据文件那条担心不成立**）

1. **13 场加载时一律是启用的**：逐场现读 `bundle_scenes_scenes_battlearena*/MonoBehaviour/MonoBehaviour_*.json`（13/13）——`m_Enabled: 1` · `priority: 2`；`useMultipleTracks` 6 个为 0（darkangels/emperorschildren/genestealers/sororitas/spacewolves/tau）、7 个为 1。
2. 停用只发生在 `Initialize()`：`BattleMusicManager__Initialize.c:3` = `Behaviour.set_enabled(this, *(this+0x28))`（`+0x28` = `useMultipleTracks`）。
3. 它由 `SceneInitializer` 拉：`SceneInitializer.cs:540 Awake()` → `:555 FetchAllInitializables()` → `:606 StartCoroutine(InitializeBehaviours)`；该协程 **`_InitializeBehaviours_d__19__MoveNext.c` state 0 先 yield**（`:211 state=1; return 1`，state 1 再 yield，state 2 才 `:119 InitializeDefaultBehaviours`），且**按优先级枚举一组一帧**（`dump.cs:101215-101222`：`Data0/Manager1/UI2/AfterUI3`）。
4. Unity 帧序：`Awake`（场景载入时）→ `Start`（第一帧）→ `Update` → 协程续跑；`BattleMusicManager` 是 `priority 2` ⇒ **到第 3 组才 Initialize**。⇒ **`Start()` 永远早于 `Initialize()`**。另：`enabled = false` **不会**停掉已经起来的协程。
5. ⇒ **13 场全部跑满两拍**；`useMultipleTracks == 0` 的真实语义只是「关掉 `Update()` ⇒ 不再每 5 s 查血线切档」，与开场无关。
6. 旁证（派生 `Start` 会覆盖基类 private `Start`）：同族 `ClockManager.cs:94`、`PlayerHand.cs:1662` 都自己声明 `Start()`，方法体是按钮监听/本地化接线，**显然在跑**。
