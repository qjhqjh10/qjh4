## 五、顺带发现（⚠️ 导入 clip 后**可能仍然看不到画面**，建议同批核）

> 本代理只读、未改任何代码；下面三条是**在 `GachaEventWindow.cs` 现场读到的**，请调度台判是否同批修。

1. 🔴 **我们的 `VideoPlayer` 没有设 `renderMode`，原版是 `1 = CameraNearPlane`。**
   - 原版 prefab 实例（`bundle_menus_assets_all/VideoPlayer/VideoPlayer_-1726031322328607103.json`）：
     `m_RenderMode = 1`（= `VideoRenderMode.CameraNearPlane`）· `m_TargetCamera = null`（由 `Awake` 设成 `Camera.main`）·
     `m_AspectRatio = 0` · `m_Looping = false` · `m_PlayOnAwake = false` · `m_WaitForFirstFrame = true` ·
     `m_VideoClip = PPtr{PathID 2379737555482514068}`（该 PPtr 同时出现在同一份 json 里，可复核）。
   - 我们的 `BuildCrateVideo`（`GachaEventWindow.cs:1354-1360`）只设了 `enabled=false` / `targetCamera` / `started`，
     **没有设 `renderMode`**（`grep renderMode` 在该文件 0 命中）⇒ 用 Unity 默认值 `RenderTexture`，而 `targetTexture` 也没设
     ⇒ **即便 clip 导进来了，画面大概率仍然不显示**。
   - 对照：我们工程里另外两处视频（`Battle/BattleDoors.cs:328` 与 `Shell/ShellRuntime.cs:1054`）都是**显式设 `RenderTexture` + 自建 RT + RawImage** 的写法，
     与原版那里不一致；本支原版走的是 **CameraNearPlane 全屏**，没有 RawImage。
   - ⚠️ **本代理没有跑 Unity，未实测**；按铁律 2/3 标为「待实机确认」，而不是「确定错」。

2. ⚠️ **`GachaEventWindow.cs:1337-1338` 与 `:1366` 的注释写着「转成 `.webm`」—— 与真实容器不符**（内容是 MP4）。
   照那条注释做会得到一个「扩展名 webm / 内容 mp4」的文件，解码器选型会出错。建议就地订正为 `.mp4`（铁律 5）。

3. ✅ `:1456` 用 `_videoPlayer.clip.length * 0.85f` 算等待时长 —— clip 导进来后这条会从 0 变成 `4.4 × 0.85 = 3.74 s`，
   行为会随之变化（原版那一档是否也是 0.85 倍，本代理未核，属另一个判据）。
