## ① A2「收在关之前」—— 它靠什么判顺序

**靠【源码文本的字符顺序】，不是靠读口。**

```csharp
int iCollect  = src.IndexOf("DailyRewardAutoCollect();", src.IndexOf("public override void Close()", …), …);
int iBaseClose= src.IndexOf("base.Close();",           src.IndexOf("public override void Close()", …), …);
Check(iCollect >= 0 && iBaseClose >= 0 && iCollect < iBaseClose, …);
```

**现读实测**（`grep -n` 逐串定位，行号是 `DailyRewardPopup.cs`）：

| 锚点 | 首次出现处 | 偏移关系 |
|---|---|---|
| `public override void Close()` | `:1424` | 起点 |
| `DailyRewardAutoCollect();`（`start` 之后首个） | `:1429` | ✅ 命中 `Close()` 体内那一句（`:280` 那句在 `start` **之前**，不会被误命中） |
| `base.Close();`（`start` 之后首个） | `:1432` | ✅ |

⇒ `1429 < 1432` ⇒ **A2 绿，判法正确**；把两句对调 ⇒ 文本顺序翻转 ⇒ **红**（灭自证成立）。

🔴 **风险（换行 / 重排）**：
- 它**只认第一次出现的子串**。若有人在 `Close()` 里 `base.Close()` **之后**再补一句 `DailyRewardAutoCollect();`，`iCollect` 仍取第一次 ⇒ **照样绿**（但运行时是「先收、再关、又收一次」）。
- 若把 `Close()` 签名改成 `protected override void Close()` 或加 `sealed` ⇒ `IndexOf(…, -1)` **抛 `ArgumentOutOfRangeException`**（`startIndex` 不能为负）⇒ **不是红，是整个宿主崩**。
- 纯格式化（拆行 / 合并行）**不会**影响它（比的是子串偏移，不是行号）—— 这一点是**安全的**。

## ④ 🔴 A1 现在是【红】的（必须改）

```csharp
int iFlag    = src.IndexOf("_escCollectOnClose = true;");   // → :302（全文唯一）
int iBaseEsc = src.IndexOf("base.ESCPressed()");            // → **:287（`///` 注释里那句！）**

```

`grep -n "base.ESCPressed()"` 现读 **3 处**：`:287`（注释）· `:290`（注释）· `:303`（代码）。
`IndexOf` 不带起点 ⇒ 取 **`:287` 的注释** ⇒ `iFlag(302) < iBaseEsc(287)` **不成立** ⇒ **A1 必然失败**。

**改法（三选一，都不需要动生产代码）**：
1. 从 `public override bool ESCPressed()` 的位置起搜（`IndexOf(…, startOfMethod)`）——与 A2/A4 同法；
2. 跳过 `///` 行/`//` 行再匹配（写个小循环，按行扫，只认非注释行）；
3. 换成**行为断**（见 ⑤ 的建议）。
