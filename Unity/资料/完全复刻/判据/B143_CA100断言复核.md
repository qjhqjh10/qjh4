## 一 · A3 只断枚举，不断行为

**现读**（`B143_R3_Assert.cs:142-147`）：
```csharp
var kind = RuleCore.HandAbilityRowKindOf(card, row, out why);
Ok(kind == RuleCore.HandRowKind.CoveredByText,
   "A3 ★ ... ｜why=" + (why ?? "?"));
```
期望值 = 字面枚举；实际值 = 被测函数返回值。**它只证明「分类器吐出的那个词是 CoveredByText」**，
不证明两个消费者（`HandAbilityTriggerHasRows` / `DispatchHandAbilityRows`）真的走了新分支。

**场景推演（逐个按实现现读）**：

| 改动 | A3 | A4（`:149` 断 `HasRows == false`） | A5（`:160` 断 `fired == 0` + 手牌不变） |
|---|---|---|---|
| 把 `HandAbilityRowKindOf` 的 `ca 100` 支删掉（回落 `Unsupported`，两处 `continue` 保留） | **红** | **绿**（`Unsupported` 在 `:441` note 后 `continue` ⇒ 同样 `false`） | **绿**（`Unsupported` 在 `:471` note 后不派发 ⇒ `fired` 仍 0、手牌不动） |
| 分类保持 `CoveredByText`，**只删 `DispatchHandAbilityRows` 的 `:466` 那处 `continue`** | 绿 | 绿（`HasRows` 的 `:439` 还在） | **绿**（见 §五：ca100 没有执行器，`fired` 仍 0） |

⇒ 第一行 = **12 条里只有 1 红**；第二行 = **0 红**。
**能被 A3 抓到的只有「分类器改了」，抓不到「派发器改了」**——而这次改动要防的正是**派发器双造**
（`B143_R3_Assert.cs:9-10` 的自述）。

**根因**：`CoveredByText` 与 `Unsupported` 在**可观测行为上完全同形**（都 `continue`、都 `fired = 0`、
手牌都不动），唯一差别是 **`Unsupported` 会走 `NoteHandAbilityRowUnsupported`（`:471`/`:511`）打一条
warning 并把 key 记进 `_handRowKindNoted`（`:508`）**，而 `CoveredByText` **不出声**。
这个「静默 vs 出声」就是本笔的全部行为差异 —— **它现在没有任何断言覆盖**（`_handRowKindNoted` 是私有
`HashSet`，没有计数器、没有 `ForTest` 读口）。

## 二 · A5 的恒真性

**现读**（`:153-164`）：
```csharp
var ctx = NewCtx();
RuleCore.PumpActionQueues(ctx);
var inst = ctx.NewInstance(card);
ctx.Players[me].Hand.Add(inst);
int handBefore = ctx.Players[me].Hand.Count;     // ← 加完之后才取 ⇒ 至少 1
...
int fired = RuleCore.DispatchHandAbilityRowsForTest(ctx, me, inst, "TurnEnd");
Eq(fired, 0, "A5 ...");
Eq(ctx.Players[me].Hand.Count, handBefore, "A5b ...");
Eq(ctx.Players[1 - me].Hand.Count, oppBefore, "A5c ...");
```

1. **不是「本来就没手牌」那种恒真**：脚本先把 `inst` 加进手牌，`handBefore ≥ 1`（`NewCtx` 只给督军，
   加前是 0）。但**没有显式前提** `Check(handBefore == 1)` / `Check(Hand.Count > 0)` —— 属于「靠构造隐式成立」，
   复核口径建议补一条硬前提。
2. **真正的恒真在被测性质上**：`DispatchHandAbilityRows` 对 `Unsupported` **也**返回 0、也**不动**手牌
   （`:471` note 后 `continue`）。⇒ `fired == 0` + 两张手牌不变 **在「分类器完全没改」的世界里同样成立**。
3. **本文件没有任何正控**：没有任何一条断言证明「这个派发口真的会动东西」——C1 只测**分类**
   （`Kind == Owned`），不调 Dispatch；全文件没有一次 `fired > 0` / 手牌减少的读数。
   ⇒ 即使 `DispatchHandAbilityRows` 被改成恒 `return 0`，A5 依旧绿（12 条里 0 红）。
4. A5c 的对手手牌开局就是 0（`NewCtx` 的 `d1` 只有督军）⇒「不变」天然成立，判别力更弱。

**结论**：A5 **对被测性质零判别力**；它的文案（`B143_R3_Assert.cs:14`）「把 CoveredByText 并进 Owned
⇒ A5 会去派发 ⇒ 红」**与实现不符**（并把 Owned 后 `:470` 只认 `ca 160`，`ca 100` 落到 `:471` 的
「没有执行器」note，`fired` 仍是 0）⇒ **必须订正（铁律 5）**。

## 三 · B 组三条负例：三张不同的卡，判别力不互相掩盖

| 条目 | 合成卡 id | desc | trigger | 期望 | 隔离的变量 |
|---|---|---|---|---|---|
| B1（`:175-178`） | `B143R3B_noDesc` | **空** | 40 | `Unsupported` | 「没有正文」 |
| B2（`:180-184`） | `B143R3B_t30` | at-turn（同 B4） | **30** | `Unsupported` | **相位 ≠ 本行 trigger** |
| B3（`:186-189`） | `B143R3B_dmg` | `Deal 1 damage …`（非 at-turn） | 40 | `Unsupported` | 「有正文但不是 at-turn」 |
| B4（`:191-194`） | `B143R3B_ok` | at-turn（同 B2） | 40 | `CoveredByText` | **正例**（与 B2 成对，只差 trigger） |

- **不是同一张卡**；B2 vs B4 = 只差 `trigger`，B1/B3 各自只差「正文形态」⇒ **三个失败模式互不掩盖**。
- 唯一共同点：都走 `RowCard`（`ab0/lg0/ca100`）这一种行形状，**没有多行 / 多 ability 的负例**
  （例如「同卡另一行 ca 100、本行 ca 160」这种串行场景）。
- 另：三张负例都靠 `HandTurnTextCoversRow`（`CardAbilityDispatch_B116.cs:548-565`）的**不同早退支**
  （空 desc / `SplitAtTurn == null` / 相位不符）⇒ 确实各打一条路，设计是好的。

## 四 · 恒真 / 自证

**没有拿被测代码算期望**：所有 `Ok(... == HandRowKind.X)` 的期望都是**字面枚举**；
A5 的 `0` / A4 的 `false` 也是字面量。实际值来自被测函数 —— 这是正常的方向。

**三条弱同源（不是自证，但不判别）**：
1. **A4 的 `false` 在 `Unsupported` 档也成立**（`HandAbilityTriggerHasRows` 对两档都 `continue`）⇒ 它只能证明
   「没有 `Owned` 行」，不能证明「被归成 `CoveredByText`」。文案里的「也不出声」**没有断言支撑**
   （`_handRowKindNoted` 无读口）。
2. **A5 的 `0` 在 `Unsupported` 档也成立**（§二）。
3. **A3/B4 的正例与实现共用 `HandTurnTextCoversRow`**：若它把「任意 at-turn 正文」都当覆盖（不看 op 与
   `ca 100` 是否匹配），B1/B3 都抓不到 —— 目前**没有**「at-turn 正文但造的不是卡 / ca 不是 100」这一负例。
   这是「判据与实现同源」的典型风险，建议补一条。
4. `RowOf(card, 40)` 用生产 API 取行，但 A2 用 `row.Ca == 100` 做了一次独立核验 ⇒ 这一处**不**是自证。

## 五 · 🔴 额外发现（最严重）：只删 Dispatch 侧 `continue` ⇒ 12 条全绿

实现现读（`CardAbilityDispatch_B116.cs`）：
- `HandAbilityRowKindOf` 的 `ca 100` 支在 `:405-412` 返回 `CoveredByText`；
- `HandAbilityTriggerHasRows` 的对应 `continue` 在 **`:439`**；
- `DispatchHandAbilityRows` 的对应 `continue` 在 **`:466`**；
- `Dispatch` 里真正会 `fired++` 的只有 `:470` 的 `ca 160` 支；其余都落到 `:471` 的
  `NoteHandAbilityRowUnsupported(... "ca N 在手牌上下文没有执行器")` 然后不进 `fired`。

**推演**：只删 `:466` 那一行（分类器、`HasRows` 都不动）——
1. A3：分类仍是 `CoveredByText` ⇒ 绿；
2. A4：`HasRows` 的 `:439` 仍在 ⇒ `false` ⇒ 绿；
3. A5：Dispatch 走到 `:466` 被删后的下一个判断 —— `CardAbilityRowCoveredByTextLayer` 对 `Cult Propaganda`
   **恒 false**（该闸只看 `card.TriggerOpsByNumber(trigger)`，而 at-turn 文本**不是关键词前缀**，实现自己的
   doc `:538-541` 已写明「B7 抓不到这一张」）；`kind == Unsupported` 为假；`ca == 160` 为假；
   于是打一条 note、`fired` 仍 **0**、手牌不动 ⇒ **A5 绿**。
⇒ **`ca 100` 的「本层不派发、不出双造」这一条真正的防线，当前 0 条断言覆盖。**
（只有把**两处** `continue` 一起删，A4 才会红：`CoveredByText` 会落到 `:446` 的 `return true`。）
