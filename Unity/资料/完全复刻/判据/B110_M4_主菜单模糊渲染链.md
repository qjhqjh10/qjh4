### 1·4 模糊 shader 与材质

  Ruri 已反编译出可读 HLSL：`d:/2/tools/ruri_out_1020_allshaders/ExportedProject/Assets/Shader/Everguild_FX_Two passes blur/`。
- **属性表只有 3 个**：`_MainTex` / **`_Sigma = 2.25`** / **`_steps = 10`**
  （材质 `Material_3.json` 的 `m_Floats` 里另有 `_BlurRadius 0.05` / `_GridSize 3.45` / `_Iterations 6` / `_Offset 0.1` /
  `_Spread 1.09` / `_xBlur 0.0099` / `_yBlur 0.011` / `_QueueControl 0` / `_QueueOffset 0` —— **旧 shader 残留死值**，⛔ 不抄）。
- 两个 pass 只有**采样轴**不同（pass0 用 `_MainTex_TexelSize.x`、pass1 用 `.y`），算式逐字相同：

```
_34  = (uint)_steps
_40  = |(int)_steps| >> 1                       // 半宽
σ²   = _Sigma * _Sigma
_59  = 1 / (σ² * 2π)                            // 归一常数
w(k) = _59 * exp2( (-k*k / (2σ²)) * log2(e) )   // = exp(-k²/(2σ²)) / (2πσ²)
sum  = Σ w(k)·_MainTex.Sample(uv 沿本 pass 的轴 ± k·texel)
wsum = Σ w(k)
out.rgba = sum / wsum                           // 四个通道都归一（alpha 不强制 1）
```
（`Sub0_Pass0_Fragment_b5.hlsl:50-110`；三份变体 b5/b6/b7 除文件头 `Keywords` 外**逐字节相同** ⇒ 关键字不影响算式。）

## 六 还差什么

1. 🔴 **模糊核的循环边界读不出（本报告唯一没钉死的技术项）**
   Ruri 的 HLSL 是把 DXIL/DXBC 经 SPIRV-Cross 反编译来的，**`for` 循环被优化坏了**：
   `_76`（k）从 `_47`（= `|steps|>>1`）起、`_76 = _77 = _76 + 1`，而退出条件写成
   `(!_50 && _40 < _76) || (_50 && _42 < _76)` —— `_50` 两个分支下**都只跑一次**（k=5、以及 k=6）。
   那个形状显然不是原版（原版那两趟必须真的模糊）。
   ⇒ **能确定的**：`w(k) = exp(-k²/(2σ²))` 归一化，**与我们的算式逐项相同**；半宽由 `abs(_steps)>>1` 给出。
   ⇒ **不能确定的**：k 的实际区间（`[-half, half]`？`[-half, half)`？步长 1 还是 2）。
   **钉死办法**（二选一，都要调度台）：
   · ① 反汇编 `Shader_339.compressedBlob`（3556 B，DXIL）数循环；
   · ② 在我们这边把 `_steps` 当 ±steps / ±steps/2 各出一张同参数图，与**原版实拍**比高频能量。

   ⚠️ **影响评估（如实写）**：σ = 2.25 时，`k = 6..10` 的归一权重合计约 **2.7%**（`Σw` 由 5.565 变 5.642）。
   ⇒ **视觉上几乎不可分辨**，但**确实是偏离**（铁律 11 ⇒ 要记、要有先后，⛔ 不是「不做」）。

2. 🔴 **真机验收没做过**（本波纪律：不跑 Unity、不跑 player）
   判法：主菜单 → 开一扇 `Popup` 窗（如练习窗）⇒ 主菜单被压背景 ⇒ 截图应看到**主菜单的模糊快照**；
   关窗 ⇒ 快照消失。既有断言只断「RT 建了 / 尺寸对 / Showing 翻了」，**没断画面**。

   **恢复条件**：找到它的注册点（可能在某个**方法体未导出**的 `Start`/`Initialize` 里）。

4. ⚠️ **「烘之前先藏自己」是我们有意加的**（原版 `Toggle` 里没有这一句）
