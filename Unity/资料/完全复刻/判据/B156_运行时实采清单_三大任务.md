## §〇 · 一页结论

**可行，但只能采「是什么」（运行时事实），采不到「为什么」（代码语义）与「服务端内容」。**

| 判定 | 内容 |
|---|---|
| ✅ **直接可用** | 运行时最终参数（相机 / 材质 / UI rect / 字号 / 动画状态 / 粒子模块）· 资产实例到原版路径的映射 · 压缩网格顶点 · 真实调用次数与入参出参 |
| 🟡 **需二次处理** | 动画曲线采样（精度受采样率限制）· 「序列化意图」已丢失的值（如 `renderQueue = -1`）· 只在特定状态才出现的参数（要按「状态 → 参数」多套记录） |
| ⛔ **采不到** | 服务端数据（关服）· shader 算式（只有 DXBC/Ruri 反编译体）· 序列化 importer 标志 · 静态引用关系 · 未被实例化因此从未加载的资产 · 真实 PvP / 购买 / 匹配路径 |

**三条硬前提：**

1. **桩状态必须随数据一起记录** —— 离线版有大量桩（Steam / Profile / Tutorial / `AllTutorialsCompleted` 等）。
   桩会改行为 ⇒ 每个输出文件头必须写「本次开了哪些桩」（`session.json` + `stubs.tsv` 快照），
   ⛔ 不许把桩的行为当原版。
2. **采集探针一律只读** —— 默认 postfix，⛔ 不用 prefix 改方法体（`OFF-01` 的教训：prefix 把 `CardDisplayWindow.ShowCard` 打死）；
   收集中禁止写内存（`WF_READONLY=1` 硬闸）。
3. **运行时是 oracle，不是判据源** —— 方法语义仍以 `.c` 为准（铁律 10）；实采用来**验证与取值**，不替代读代码。

## §一 · 采集手段与通用探针（执行时第一步）

### 1·1 五类探针

| 探针 | 干什么 | 关键实现 | 产物 |
|---|---|---|---|
| `TraceProbe` | 批量挂方法入口/出口，记录**入参、返回值、耗时、异常**，以及**调用计数** | `ProbeUtil.FindType/FindMethod` 解析 + Harmony postfix/finalizer；`__args` / `__result` / `Stopwatch` | `trace.tsv` |
| `WatchProbe` | 按秒/按帧读**任意字段**，含按 `dump.cs` 偏移读内存 | 定位器三选一：静态单例 / `FindObjectOfType` / 从 hook 抓 `__instance`；支持指针链 `+0x50,+0x18` | `watch.tsv` |
| `DumpProbe` | 打印**对象树**：路径 / activeSelf / `rect.rect` / 锚点 / pivot / localScale / lossyScale / 组件 / sprite / TMP 文本与字号 / Button.interactable | 复用现有 `WindowProbe` / `MenuLayoutProbe` / `CardWindowProbe` 的写法 | `tree_<场景>.tsv` |
| `AssetMapProbe` | hook 资产加载，记录 **bundle 名 + asset 路径 + 类型 + 实例**，并记「这个实例被谁引用」 | hook `AssetBundle.LoadAsset` 系列 / Addressables 加载入口 | `assetmap.tsv` |
| `MeshDumpProbe` | 运行时导出网格：顶点 / 索引 / 子网格 / bounds / channels | `Mesh.GetVertexBuffer` / `GetVertices` / `GetTriangles` | `mesh_<name>.json` |

> 主动调用原版方法（按 RVA）**不算独立探针**：需要时用现有 `MenuLayoutProbe` 的 RVA 调用法，
> 且必须「先读基线校验、再调用、再回读」。

### 1·2 配置驱动（先做这个，⛔ 不要一项写一个探针）

**问题**：每加一个采集点都要改 `.cs` + `build.sh` + 重启游戏（约 1.5 分钟），逐项写探针不现实。

**做法**：通用探针 + 两份配置表，启动时读取；`WatchProbe` 支持 `WF_WATCH_RELOAD=1` 运行时重读（只读，安全）。

`targets.tsv`（给 `TraceProbe`）：

```
# id	class	method	paramCount	mode	every	note
E1-SETTLE	BattleManager	ResolveAction	2	in,out	1	结算入口
E3-POOL	AbilityLogic	GetTargets	3	out	1	目标池
```

- `mode`：`in` / `out` / `ret` / `count`（只计数）
- `every=N`：热方法每 N 次采一次（防刷屏、防拖慢）

`watch.tsv`（给 `WatchProbe`）：

```
# id	locator	type	path	field/freq	note
X1-CAM-1	find	UnityEngine.Camera	0	fov, near, far, rect, depth	主相机
X1-HUD-SCALE	path	HudFrame	0	lossyScale	期 2a
MT-RQ	find	UnityEngine.Material	0	renderQueue, shader.renderQueue	材质队列
```

- `locator`：`find`（`FindObjectOfType`）/ `path`（按层级路径）/ `static`（单例）
- `field`：优先字段名（走 Il2Cpp 反射）；代理类型缺失时改用**偏移**（`dump.cs` 的 `0xNN`）

### 1·3 安全纪律

1. ⛔ 不给每帧调用的热方法挂无节流 postfix（`every=N` 必填）。
2. ⛔ 采集模式下不写内存、不调会改状态的 RVA。
3. 探针自身异常一律落 `errs.tsv` 并**继续抛**（不吞，避免掩盖原版异常）。
4. 每次会话先写 `session.json`：时间 / 环境变量 / 桩清单 / 探针版本。
5. 探针装不上时**必须出声**（`hooks_installed.tsv` 逐条 OK/FAIL），⛔ 不许静默少采。

### 1·4 成本

- 一次「改探针 + 重编 + 重启到主菜单」≈ **1.5 分钟**；一次战斗局 ≈ **3–8 分钟**。
- 结论：**按批次采**（见 §六），一批 10–30 个目标，⛔ 不逐条开关游戏。

## §五 · ⛔ 不可采清单（⛔ 以后别再试）

| # | 采不到的东西 | 为什么 | 那怎么解决 |
|---:|---|---|---|
| 1 | 服务端数据（商店 / 排名 / 活动 / 玩家资产 / 远端本地化缺键） | 已关服，永远不加载 | 本地模拟 + `🔶 自己设计（非原版）`（仅服务器类允许） |
| 2 | shader 算式 | 运行时只有编译后的行为 | `d:/2/tools/ruri_out_1020_rootshaders/` 反编译体 |
| 3 | 序列化 importer 标志（`m_MeshOptimizationFlags` / `m_MeshUsageFlags` / `m_KeepVertices` 等） | Unity 运行时 API 不暴露 | `assetripper_out/ExportedProject` 的 YAML |
| 4 | 静态引用关系（谁引用谁） | 只有被实例化的资产才进内存 | 静态扫描（`check_prefab_refs.py` / grep） |
| 5 | 未被实例化的 prefab / SO | 不进内存 | 解包资源 / ExportedProject |
| 6 | 真实 PvP / 匹配 / 购买路径 | 离线不可达 | 判据为空 ⇒ 按「原版没有」或自设计处理 |
| 7 | 序列化意图（`renderQueue = -1` 表示用默认） | 运行时读到的是代入后的值 | ExportedProject 的原始字段 |
| 8 | 编辑器侧行为（AssetDatabase / 导入设置） | 不进运行时 | 读 `.meta` / 导入器代码 |

## §七 · 落地格式与标注规则

1. **每条实采值必须带四样**：① 对象路径或类型 ② 字段 / 方法 ③ 会话时间 + 桩状态（`session.json`）④ 是否重复两次一致。
2. **落盘位置**：`E:/warpforge/07_产物/phase0/<批次>/`（TSV / JSON），截图按既有约定放 `d:/4/_tmp_view/shots/<日期_会话>/`。
3. **写进我们代码时**：
   - 照原版实采值实现 ⇒ `// ✅ 已复刻（<日期> · <批次> · 出处=实采 <tsv>:行）`（铁律 20）；
   - 原版判据为空、只能自己定 ⇒ `// 🔶 自己设计（非原版）：…`（铁律 18 / 18·0）。
4. **冲突处理**：运行时值与序列化值不一致时，**两者都记**，并按铁律 5·c 判「状态 → 参数」有几套；
   ⛔ 不许只留一个数就下结论。
5. **探针自检**：同一会话跑两次，浮点按 `1e-5` 比对；不一致必须解释（随机 / 时间 / 插值 / 桩）。
