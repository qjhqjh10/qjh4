## 〇 · 结论（一句话）

**`(α) 断言写错`** —— `A4c` 把**段位 1 那颗 `ImageQuad` 的引用 `q1` 一直攥到下一次 `Show()` 之后**，
而下一次 `Show()` 会 `MenuDraw.ClearChildren` → **`Object.DestroyImmediate` 掉整棵子树** ⇒ `q1` 变成「已销毁的 Unity 对象」，
`q1 != null` 用 Unity 重载运算符判为 **false** ⇒ A4c **结构上永远不可能绿**。
**实现是对的**（A4 / A4b 两条各自现读到了 `01-Rook` / `07-Legend`）。**不是回归**（这是它第一次跑）。

### `q1` 为什么是「已销毁」

| 链 | 出处 |
|---|---|
| `win.Show()` → `Build()` | `Shell/RankedSeasonEndedWindow.cs:157-161` |
| `Build()` 第一段就清空整棵树 | `:167` `MenuDraw.ClearChildren(transform);`（`_division` 随即在 `:189` 重新赋值） |
| `ClearChildren` 在**非 playing** 下走 `DestroyImmediate` | `Shell/MenuDraw.cs:138-149`，关键在 `:145` `if (!Application.isPlaying) { Object.DestroyImmediate(go); continue; }` |
| 本宿主**就是非 playing** | 批处理 `-executeMethod`；同文件自己也断过 `CheckTrue(!Application.isPlaying, …)`（`Editor/MainMenuScene.cs:20978`），另 `:1132` 注明「批处理 `Application.isPlaying == false`」 |

`Division Image` 那颗 quad 是 `MenuDraw.Rect(transform, ...)` 建的（父 = 窗根）⇒ 是 `transform` 的子物件 ⇒ **必然被这一次清空销毁**。
`q1` 是那个被销毁 GameObject 上的 `MonoBehaviour` ⇒ 之后 `q1 != null`（Unity 的 `Object.op_Inequality` 重载）**恒为 false** ⇒ A4c 直接短路为 false。

> ⚠️ 另一种可能形态（即便不是因为销毁）：若将来实现改成**复用同一颗 quad 只换贴图**，`q1` 与 `q7` 会是**同一实例**，
> 第二次 `Show()` 后 `q1.Texture` 也变成 `07-Legend` ⇒ A4c 同样必红。
> **两种形态都指向同一件事：A4c 不该跨重建持有引用**（修法相同，见 §五）。

## 五 · 该怎么修 —— **改断言，不改实现**

### 判据：为什么改断言而不是改实现

- `A4` 已证明 `1 → 01-Rook`、`A4b` 已证明 `7 → 07-Legend`（各自紧跟自己的 `Show()` 现读，引用都活着）。
  两个**不同的字面量名** ⇒ 逻辑上已经蕴含「两张不是同一张」。
- 实现（`RankedSeasonEndedWindow.cs`）的「`Show()` 整窗重建」是**本批之前就有**的行为
  （`git show 9a823699^:…/RankedSeasonEndedWindow.cs` 里 `:157 Show` / `:164 Build` / `:167 ClearChildren` 全在），
  不是 `W-5` 引入的；且 `BuildDivisionImage()`（`:382-388`）本身对两张图都取对了。

### 最小修法（只在 `Editor/B114_W5_Assert.cs` 内，`:113-127` 那一段）

**在每次 `Show()` 之后立刻把要跨重建用的东西「快照成值」，不要留下组件引用**：

```csharp
// ---- A4🧨 换段位号 ⇒ 贴图必须跟着换（钉住「号→图」是查表直读，不是写死一张）----
win.DivisionNumber = 1; win.Show();
var q1 = win.DivisionNode != null ? win.DivisionNode.GetComponent<ImageQuad>() : null;
string n1 = (q1 != null && q1.Texture != null) ? q1.Texture.name : null;   // ★ 快照成值
Texture t1 = (q1 != null) ? q1.Texture : null;                            // ★ 引用也一起快照（见下「为什么安全」）
Ok(n1 == Art1, "A4🧨 段位号 **1** ⇒ 贴图 **`" + Art1 + "`**（现读 `" + (n1 ?? "<null>") + "`）");

win.DivisionNumber = 7; win.Show();
var q7 = win.DivisionNode != null ? win.DivisionNode.GetComponent<ImageQuad>() : null;
string n7 = (q7 != null && q7.Texture != null) ? q7.Texture.name : null;
Texture t7 = (q7 != null) ? q7.Texture : null;
Ok(n7 == Art7, "A4b🧨 段位号 **7** ⇒ 贴图 **`" + Art7 + "`**（现读 `" + (n7 ?? "<null>") + "`）");
Ok(t1 != null && t7 != null && t1 != t7 && n1 != n7,
   "A4c🧨 段位 1 与 7 画的是**两张不同的贴图**（现读 `" + (n1 ?? "<null>") + "` vs `" + (n7 ?? "<null>") + "`）"
 + "｜🧨 实现里把图名写死成一张 ⇒ 1 与 7 相同 ⇒ 红");
```

**为什么 `t1` 快照后仍然有效（不会被连带销毁）**：
`ClearChildren` 里的 `ReleaseArtUnder`（`MenuDraw.cs:3614-3639`）只对 `CardArt.IsPerItemArt(path)` 命中的路径做 `Release`，
前缀表 = `cards/art_` · `cardbacks/` · `avatars/` · `altarts/` · `ui/flavourbg_` · `ui_menu/Cursor_`（`Core/CardArt.cs:1138-1146`），
段位图是 `Art/ui_menu/01-Rook`、`07-Legend` ⇒ **不命中**；何况 `CardArt.Release` 本身「**⛔ 不销毁贴图**」（`CardArt.cs:1150`）。
⇒ 贴图资产对象在重建后依然活着，`t1 != t7` 可安全比较。
（`n1 != n7` 那一半是**冗余保险**：即便将来有人把贴图改成会被销毁的对象，比名字也不会误绿。）

**另外建议**（可选，非必需）：A4c 现在**不打印任何现读值**（这也是本轮无法从日志直接看出「两张各是什么」的原因），
上面那版已顺手补上 `n1` / `n7`。
