## ① `Aura.AddAuraKeyword` 不写 `_remnantTraits` —— 结论：**残骸整条不施加**（候选 ① 正确，候选 ② 错误）

### ① 原版做法（逐句 + 出处）

**1) 「光环」在原版 = 触发能力 20 / 240，不是另一套机制。**

- `CardScript__UpdateWhileInPlay.c:19-20` →
  `RawCardScript__UpdateWhileInPlay.c:14`（`TriggerAbilities(0x14 = 20 WhileInPlay, …)`）与
  `:17`（`TriggerAbilities(0xf0 = 240 WhileInPlayVariable, …)`）。
- `out_cpp2il_dev_ilspy/RawCardScript.cs:1772-1778`：`TriggerAbility` 里
  `if (trigger == WhileInPlay) abilityData.whileInPlay = true;`
  `if (trigger == WhileInPlayVariable) abilityData.whileInPlayVariable = true;`
  （枚举值 `AbilityTrigger.cs:6` / `:39`：`WhileInPlay = 20` / `WhileInPlayVariable = 240`）
- `AbilityLogic__PlayAbility.c:1193-1197` 与 `:1350-1354`（同一段逻辑的两个入口）：
  ```
  cVar4 = 1; if (abilityData.whileInPlay(+0x40) == 0) cVar4 = abilityData.whileInPlayVariable(+0x41);
  *(bool *)(newEffect + 0x30) = cVar4 != 0;      // CardEffect.extrinsic
  ```
  ⇒ **光环投出去的每一条 `CardEffect`，`extrinsic == true`。**
  （`AbilityData` 字段表 `dump.cs`：`whileInPlay // 0x40` · `whileInPlayVariable // 0x41`；
   `CardEffect` 字段表 `dump.cs:119060` 起：`extrinsic // 0x30` · `buffType // 0x38` ·
   `healthChange // 0x60` · `enchantment // 0x88`）

**2) `CardScript.AddEffect` 的四道闸里，②③④ **只对 `extrinsic` 生效**。**

- Ghidra：`CardScript__AddEffect.c:91` 是 `if (*(char *)(param_2 + 0x30) != '\0') {`（= `if (effect.extrinsic)`），
  这个块一直开到 **`:197`**；闸②（jam `:85-98`）、**闸③（残骸门 `:159-170`）**、
  闸④（施放者不在场 `:171-195`）**全在块内**。
- ILSpy 同形（可读版）：`out_cpp2il_dev_ilspy/CardScript.cs:17465-17470`
  `bool flag = !newEffect.extrinsic; if (flag) goto IL_0694;` —— **`IL_0694` 在 `:17601`**，
  而残骸门在 `:17597-17600`（`IL_1c2f`）⇒ **非 extrinsic 直接跳过残骸门**。

**3) 闸③ 原文（`CardScript__AddEffect.c:159-170`，ILSpy `:17577-17600`）**

```
if (this.isRemnant(+0x65)) {
    if (effect.buffType(+0x38) == 1 /*addStats*/) { if (effect.healthChange(+0x60) == 0) reject; }
    else if (effect.buffType != 0x5a /*90 addTraitRemnant*/) reject;
}
reject ⇒ Log("Trying to AddEffect to … which is remnant and the effect is not health buff") + return false
```
⇒ 光环授**关键词/属性**投的是 `buffType 3 addTrait` / `1 addStats`；
`addTrait` 在残骸上**被整条拒绝**，`addStats` 只有 `healthChange != 0` 那一格放行。

**4) 独立第二层：光环的目标池本来就不含残骸。**

- `FilterMethods__CheckIfMeetsCriteria.c:273-278`：
  `if (criteria.includeRemnants(+0x1b) == 0) { if (candidate.isRemnant(+0x65) != 0) return 0; }`
- 全池现扫（`cards_truth.json`，`trigger ∈ {20, 240}` 的 `abilityLogic[].targetCriteria`）：
  **49 张光环卡 / 53 条 logic 行**，`includeRemnants` 分布 = **0 × 52 · 1 × 1**；
  唯一那个 1 = **`SAU36 Nemesor Zahndrekh`**，而它投的是 `buffType 90 addTraitRemnant` +
  `trait 1190 = notDestroyRemnant`（正是我们 `AuraSpec.RemnantStay` 那一支）。
  `SAU67 Damaged Plasmacyte`（三代 id 链：旧 `SAU68` → 现 `SAU67`）= `trigger 240` ·
  `buffType 3` · `trait 1030 regeneration` · `traitValue 2` · `targetsAffected 100`（相邻）·
  `friendlyUnits 1` · `includeHero 1` · `includeMinions 1` · **`includeRemnants 0`**。

**5) 残骸上 `Has` 与 `KwValue` 在原版里本来就不同源（这是原版的形状，不是我们的 bug）**

- `EntityScript__HasCurrentTrait.c:17-70`：残骸（`!isLeavingRemnant`）只扫 `activeEffects(+0x108)` 里
  `buffType == 0x5a` 的；非残骸扫 `CurrentTraits(+0x128)` **或** `buffType == 3`。
- `EntityScript__GetCurrentTraitValueWithModifiers.c:24-70`：**没有** `isRemnant` 判断 ——
  累加 `activeEffects` 里 `buffType==3 && trait==X` 的 `traitValue(+0x40)`，再加
  `CurrentTraits` 里那条的基值（`+0x1c`），最后 `max(0, 基值+加成)`。
- `CardScript__TransformIntoRemnant.c:64-84`：翻面时把 `CurrentTraits` 里每一条 `RemoveTraitSilently`。
  ⇒ **如果**一条 `addTrait(3)` 真落到残骸身上，原版就是「`Has` 说没有、`KwValue` 说有」——
  与我们现在看到的现象一模一样。**但上面第 3/4 两层保证光环这一族落不上去。**

（`UnitState.cs:1247`），而 `Armor` 有几个读点**不看 `Has` / 也不看 `IsRemnant`**：

- `RuleCore.DamageAfterArmourOne`（`:7600-7605`，击杀**预览**/`WouldKill*` 那一族）；
- `CounterAttack.cs:146`；`ConditionEval.cs:390-393`（`u.Armor > 0` 那一格条件）。

  ⇒ 所以这一族的偏差表现是「**残骸被算成更耐打**（预览/AI/条件），真打下去却不减甲」，
  不是「少掉血」。**是否可观察要实测**，但机制上已经不是干净的。

**改一处：`Core/Aura.cs` 的 `ApplyAura` 通用载荷分支（`:881` 那个 `ForEachTarget` 委托）首行加残骸跳过。**

```csharp
    //     `FilterMethods__CheckIfMeetsCriteria.c:273-278`）
    //   · 投递层：光环 effect 是 extrinsic（`AbilityLogic__PlayAbility.c:1193-1197`），
    //     残骸门只放行 addStats+healthChange≠0 / addTraitRemnant(90)（`CardScript__AddEffect.c:159-170`）
    if (t.IsRemnant) return;        // ← 新增，仅这一行
    if (!a.Filter.Matches(t)) return;
    …

```

**⛔ 三条禁令：**

1. ⛔ **别碰 `a.RemnantStay` 那支（`Aura.cs:856-870`）** —— `SAU36` 的 `includeRemnants == 1` +
   `buffType 90`，那支本来就 `if (!t.IsRemnant) return;`（要求是残骸），改错就废掉「相邻残骸不消失」。
2. ⛔ **别在 `AddAuraKeyword` 里补 `_remnantTraits`**（= 候选 ②，见上）。
3. ⛔ **别加 `ctx.Log` 记「跳过了几个残骸」** —— `ctx.Log` 会进 `ctx.Events`（`Fingerprint`），

**已知等价性（可以放心用「整条跳过」而不是「逐 op 过闸③」）**：全池 53 条光环 logic 的 `buff`
现扫**没有任何一条带 `healthChange`**（授的是 `melee/range/armour`、`costChange`、`addTrait`、
`90/70/15` 那几档）⇒ 对今天的池子，「跳过目标」与「逐 op 过闸③」结果完全一样。
⚠️ 若将来出现一条 `Adjacent units have +N Health` 的光环，两者会分叉（闸③ 放行生命、目标池仍排除）——
那时要按 `includeRemnants` 那一格判（`AuraSpec` 目前**没有**这一位，见「还差什么」）。

**顺手该订正的两处注释（铁律 5，零行为）：**

- `Core/EffectResolver.cs:11313-11317` 的「闸③ 残骸门 `.c:159-170`」应注明
  **只在 `if (extrinsic)` 块内**（`.c:91-197`；ILSpy `CardScript.cs:17465-17470` 的
  `if (!extrinsic) goto IL_0694` 就是那一跳）。否则下一个人会像本轮一样先怀疑闸的位置。
- `Core/UnitState.cs:1153-1157` 那句「闸③ 对残骸只放行 90 档与生命增减 ⇒ 按『此刻是残骸』记账
  与逐条判 90 等价」——结论对我们这条 `give/gain` 路成立，但**依据要写全**：等价的前提是
  **这条效果是 extrinsic**（光环是；别的非 extrinsic 授予原版**不拦**）。

1. **`chosenAbility 160` 的结算原语**（新 op / 新动词，建议 `discardSelf`）。

## ③ `ResolveTargets` 不挡 stealth / camouflage / ward —— 结论：**这是对的，不许改**

### ① 原版做法（逐句 + 出处）

**三道闸都在「合法性层」，`AbilityLogic.GetTargets`（= 我们 `ResolveTargets` 的对应物）一个都不看。**

| 入口 | 出处 | 挡哪几族 | 条件 |
|---|---|---|---|
| `BattleManager.IsValidSpellTarget`（**战术卡点选**） | `:47-57` | **stealth + ward + camouflage** | `caster.isPlayer != target.isPlayer`；且 `caster.targeted(+0x268) != 0`（`:45`） |
| `BattleManager.IsValidActiveAbilityTarget`（**主动能力点选**） | `:47-53` | **stealth + ward**（**没有 camouflage**）；另有 `0x2da summonRift`（`:55`，**不分侧**） | 同上「异侧」 |
| `BattleManager.IsValidAttackTarget`（**攻击**） | `:134` → 拒绝支 `:320-330` | **只有 stealth** | 目标带 `0x46` |
| `RawCardScript.IsValidTarget`（`cardTargetCriteria` 通路） | `:24 / :30 / :37` | ward（异侧）· **camouflage（且 `caster.cardType == 0x14` = 20 Tactic）** · stealth（异侧） | 先 `IsInPlay` |

- `EntityScript__get_isCurrentlyWarded.c` = `HasCurrentTrait(140 ward) || HasCurrentTrait(145 wardWb)`；
  `EntityScript__get_isCurrentlyCamouflaged.c` = `HasCurrentTrait(985 camouflage)`。
  两者都走 `HasCurrentTrait` ⇒ **残骸身上恒 false**（残骸只认 `buffType 90`）。
- 官方词条佐证（`官方本地化_en+zh-CN.json`）：
  `CardTraitDescription/camouflage` = **"This unit cannot be targeted by enemy **Stratagems** until it attacks"**
  （⇒「只挡战术卡」这条与 `cardType == 0x14` 一致）；`CardTraitDescription/stealth` =
  "This unit cannot be targeted for one turn or until it attacks"。（`ward` 在本 build 的本地化表里**没有词条**。）
- **`AbilityLogic__GetTargets.c` 全文 `HasCurrentTrait` 调用数 = 0**（`grep -c HasCurrentTrait` = 0）
  ⇒ 它**不看任何 trait**，随机 / 全体 / AoE 效果**照样打得中**潜行/伪装/守护单位。
  ⚠️ 那个文件里确实出现 `0x46` / `0x8c` 各一次（`:845` / `:849`），但那是
  **`targetsAffected` 的枚举值**（`70 abilityOwner` / `140 previousAbilityTargets`，走 `iVar6`），
  **不是 trait 常量** —— 别按数字搜到就当证据（`0x3d9` 在该文件 0 次）。

### ② 我们的落点 + 差异

| 入口 | 落点 | 覆盖 |
|---|---|---|
| 战术卡点选 | `EffectResolver.IsLegalPick`（`:2005-2029`）→ `PlayTargetPool`（`:2064-2085`）→ `AddSide(stealthGate: true, tacticCaster: …)`（`:2897-2911`） | stealth + camouflage（仅 `!IsUnit` = cardType 20）+ ward，**只在异侧** ✔ 与 `IsValidSpellTarget` + `RawCardScript.IsValidTarget` 逐条同口径 |
| 主动能力点选 | `RuleCore.CanUseAbilityTarget`（`:11309-11349`） | stealth(异侧) + ward(异侧) + summonRift(不分侧) + tainted ✔ 与 `IsValidActiveAbilityTarget` 对齐；**不挡 camouflage** ✔ |
| 攻击 | `RuleCore.IsValidTarget`（`:5366` 起，stealth 那一句在 `:5382-5386`，码 `ErrAttackBlockStealth`） | 只有 stealth ✔ |
| 结算（`ResolveTargets`，`:1391 / :1404`） | **不挡** | ✔ **原版 `GetTargets` 也不挡** —— 这是正确行为 |

**已有的断言证据**：`Editor/RuleEngineTest.cs:35474 TestA1468SingleTargetStealthGate`（单选挡 +
正对照）· `:35556 TestA1468BatchAllEnemiesHitsStealth`（`Deal 1 damage to all enemies` 命中隐身=**对**）。

**⚠️ 两处注释与事实不符（铁律 5，建议订正）：**

1. `Core/EffectResolver.cs:2896` 写「**池内 0 张可达**（camouflage 只能由 addTrait 效果授予）⇒ 今天零行为变化」
   —— **不成立**。现读 `cards_engine.json`：**印 `Camouflage` 关键词的卡 21 张**
   （`ASH69 Howling Banshee Exarch` · `AM59 Astropath` · `AM68 Tempestus Scion` · `DA8` · `SOR21` …
   ），keywords/desc 提到它的共 33 张 ⇒ **这条闸今天就是活的**，动它会有真回归。
2. `Core/EffectResolver.cs:2881` 那句「池内 0 张（keywords/desc/descZh 与 cardTraits 各 0 命中）」——
   若指的是 **`ward`/`wardWb`** 则**成立**（现读 `keywords` 里 0 张，只能靠 `addTrait` 授予）；
   若被读成「整段三族都 0 张」就错了（stealth 30 张）。

### ③ 施工建议

  且 `TestA1468BatchAllEnemiesHitsStealth` 会立刻变红。
