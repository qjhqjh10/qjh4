## 五、`不再推进`三档（结构差 30 · 休眠 14 · 判据空 3）

### 5.1 结构差（30 条）—— 为什么不推

- **一句话**：这 30 条**不是没做**，是「原版的机制形状」我们选了另一套等价物；要「推成 A」等于重写机制，而净行为**今天不可观测或已等价**。三类根因：

  1. **异步队列 / 状态机 → 同步结算**（12 条）：原版「先入队、协程逐拍结算」（待结算伤害缓冲、`ResolveXxx` 状态机、`SendRemoveEffect` 逐条入队），我们同一动作外壳当场结算、回合边界整批做。已经调度台按 E4 族2/族3 正式裁过：`AddAttackAction` / `RecordAttackPendingDamage` / `DisappearFromHand` / `SetCardState` / `ReadyToUseActiveAbility` / `SendRemoveEffect` / `ResolveAction`(91 型 switch) / `ResolveMinionDeath` / `OnTurnSetup` / `BroadcastTurnSetup` / `ResolveCardAutoSummoned` 的入队半 / `CancelEffects*` 的队列半。

  2. **分层边界**（8 条）：原版把「查表 / 命中 / 动画 / 可见性」做在 `CardScript`/`DeckManager`/`MinionManager` 身上，我们拆成 `RuleEngine`（纯状态）+ `CardPresentation`（表现）。⇒ `GetDeckManager` / `GetAllCardsInPlay` / `GetUnitsInPlay*` / `GetEnemy|PlayerMinionsAndRemnantInPlay` / `GetTargetInPos` / `RemoveFromGameCard` 的三条表现层 / `PrepareAttack` 的 sorting layer / `PreloadAssets`（本仓 0 处 Addressables）。

  3. **口径层**（10 条）：行为等价，但落点只能是「字段 / switch case / 常量表」，过不了 A 档「声明行」的闸 —— `HasDiedThisTurn` / `HasDiedSinceLastTurn`（ConditionEval 的 case 221/222）、`CanTriggerAbility`（六道闸拆两段求值）、`MeetsCriteria`、`CardTraitCollection.Init`（编译期常量 vs 运行期资产填充）、`GetNextSlotToCard`（我们无 `AddMinionOccupation`）、`MoveCardToMulliganPos`（实拍值 vs `GetPosition` 算法）、`GetValidTargets`（格号升序 vs 进场追加序）、`EnemyReturnsAttack`(ⓐ 无待结算队列)、`ResolveFollowAfterResolution` 的泵收尾、`ResolveRevealOrders`。
