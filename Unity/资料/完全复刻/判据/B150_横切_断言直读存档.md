## 一、一句话结论

**共扫出 32 处**「断言／夹具直接读写存档文件」的可疑点：
**A「一定已坏」= 0 处**（唯一那处 `B142_E66` 已于 2026-11-05 修掉，现读已是 `ReadThroughLegacy`）·
**B「换环境才坏」= 12 处**（**在 `-batchmode` 下现在全绿；一旦在 GUI／Play 里跑自检、或某个断言把 `SaveCenter.OverrideRoot` 设了没还原，就成批变红或静默降级**）·
**C「安全」= 20 个文件**（归成 §三 的 6 组：夹具自己的临时档 / 走产品 API / 显式关掉中央档 / 摘掉钩子 / 非存档文件 / 判据源码与截图）。

⚠️ **B 级里有 3 处属于「静默降级」而不是「会红」**（`CollectionScene.cs:9151` · `B116W38_Assert.cs:103` · `DeckScene.cs:2961`）——
它们现在**恒绿**，但**已经不再验它声称要验的那件事**（产品写进了 `SaveSandbox` 的沙箱，而断言读的仍是手拼的真根／旧档）。这比红更危险：红会被看见，恒绿不会。
（`B140_V4b` D 组**不属**这一类 —— 它读真根是对的，只记一笔「两处子目录名是字面量」，见 §五·2。）

⚠️ **先说清判 A 还是判 B 的那条开关**（下面整张表都靠它）：

```text
SaveCenter.StoreOn  ==  !string.IsNullOrEmpty(SaveCenter.OverrideRoot)  ||  (Application.isPlaying && !Application.isBatchMode)
SaveCenter.SaveThroughLegacy(...)：
    StoreOn == true  → 写**中央档**（+ 只有 LegacyMirrorOn 才双写旧档；现在默认 false ⇒ 旧档**一个字节都不写**）
    StoreOn == false → **只写旧档**（与切换前逐字节同）
```

⇒ **批处理自检（`-executeMode` 默认 `-batchmode`）里 `StoreOn` 恒 false ⇒ 旧档照写 ⇒ 那些「按路径读旧档」的断言全绿。**
⇒ **在编辑器里用 GUI／Play 跑同一份自检时 `StoreOn` 恒 true ⇒ 旧档不写 ⇒ 同一批断言成批变红。**
这正是「换环境才坏」的全部机理 —— 不是代码坏了，是**断言读的那份文件与产品写的那份文件已经不是同一个**。

## 四、统一改法建议（⛔ 不要逐条改，按这五条收口）

1. **读存档只有一个口**：`SaveCenter.ReadThroughLegacy(key, legacyFullPath)`（`Shell/SaveCenter.cs:1165`）。
   它内部已经是「先中央、再旧档」，并且 `StoreOn` 关着时**只看旧档**（与切换前逐字节同）。
   - 「有没有」→ `SaveCenter.Exists(key)`（`:252`）；「原文」→ `SaveCenter.GetRaw(key)`（`:182`）；「文件在哪」→ `SaveCenter.PathOf(key)`（`:98`）。
   - ⛔ 断言里**不要**再出现 `File.ReadAllText(<某个 StorePath>)`。
2. **判「产品真的落盘了」用产品自报 + 回读**：`Xxx.LastStorePath != null` 且 `Xxx.LastStoreError == null`，再 `ReadThroughLegacy` 回读一次内容。
   ⛔ `File.Exists(StorePath)` 在沙箱/中央档任一形态下都不再等价于「落盘成功」。
3. **「没污染玩家真档」只能对【真根】断言**：`SaveRoot.Path`（`Shell/SaveRoot.cs:54`）或 `SaveSandbox.DisableForTest=false` 那一档；
   而被测产品写在哪，要问 `SaveSandbox.Dir(sub)`（`Core/SaveSandbox.cs:65`）——**断言侧不许再手拼 `SaveRoot.Path/<子目录>/<文件名>`**。
   `B140_V4b` D 组是现成的正确样板（基准被追认后可直接抄）。
4. **夹具要造「老档 / 坏档」时，造在【读口真正会读的那一侧】**：
   最省事 = 注入 `SaveCenter.OverrideRoot` 指向临时目录 + `SaveCenter.SetRaw(真实 key, payload)`；
   要造「文件不存在」= 把 `OverrideRoot` 指到**空目录**（中央档缺失 ⇒ `ReadThroughLegacy` 才回落到旧档）。
   ⛔ 只写旧档 = 一旦 `StoreOn` 为真就**完全无效**（`RewardsScene:3572` 与 `DeckScene:8550/8560/8581` 就是这个形状）。
5. **三个「自检注入口」一律存档-还原，⛔ 别写死 `= null`**：
   `SaveCenter.OverrideRoot`（`SaveCenter.cs:63`）· `SaveSandbox.OverridePath`（`Core/SaveSandbox.cs:40`）· `NetConfig.OverridePath`（`Net/NetConfig.cs:37`）。
   2026-11-05 已有一个真事故（`SettingsScene` 设了 `NetConfig.OverridePath`，`B140_V4b` 读到错根，只能自己再存-还一次 —— `B140_V4b_Assert.cs:327-346`）。

**附：判定 A/B 的运行时前提**（写清单时别判错）

- 批处理（`-batchmode`）⇒ `StoreOn=false` ⇒ 旧档照写 ⇒ 表里 B 级**全绿**。
- GUI／Play（含 `Application.isPlaying` 真、`isBatchMode` 假）⇒ `StoreOn=true` ⇒ 旧档不写 ⇒ 表里 B 级**全红**，且**会把临时夹具写进玩家真中央档**（比红更糟）。
⇒ 结论：**B 级 12 处在功能上等价于「只能在批处理里跑」**，要么改读口，要么在段首加一条硬闸 `Tr(!SaveCenter.StoreOn, …)`（`B112_G` / `B113_G3` 已经这么做了，可抄）。
