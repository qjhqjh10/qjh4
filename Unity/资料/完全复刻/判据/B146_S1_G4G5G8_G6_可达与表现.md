## 一、G-4 `Has()` vs `0 < 值`

### 原版判据
- 星镖 `_ResolveAttack_d__438__MoveNext.c:616-619`：`iVar14 = EntityScript__get_CurrentShuriken(攻方)` → `if (0 < iVar14)`。
- 哨戒 `:719-722`：`get_CurrentSentry(守方)` → `if (0 < iVar14)`。
- 爆裂 `:1017` + `BattleManager__ShouldTriggerAdjacentDamage.c:6-8`：`return 0 < EntityScript__get_CurrentBlast(攻方)`。
⇒ 三处闸都是**值 > 0**，不是「键存在」。

### 我们
- `RuleCore.cs:6900` `if (attacker.Has("shuriken"))`、`:6922` `if (target.Has("sentry"))`、`:7253` `if (attacker.Has("blast") && …)`。
- `UnitState.Has`（`UnitState.cs:968-973`）= `_keywords.ContainsKey`（残骸档读 `_remnantTraits`）；
  `UnitState.KwValue`（`:1104-1109`）= 字典值钳 `>= 0`（与原版 `GetCurrentTraitValueWithModifiers` 末句一致）。
- 🔴 `AddKeyword(kw, 0)` 会**建出值为 0 的键**（`UnitState.cs:1139` `_keywords[keyword] = RawKw + add`，无值闸；光环那条同形
  `UnitState.cs:1538` `AddAuraKeyword`）；`RemoveKeyword` 在 ≤0 时**整条摘掉**（`:1251-1268`）；数据面**没有**负值 addTrait。

### 数据普查（单份口径）
| 关键词 | 卡的印刷值分布（truth `cardTraits._traitValue`） | 出现 0 值？ |
| --- | --- | --- |
| `blast`(350) | 2×18 · 3×11 · 4×6 · 5×4 · 1×3（共 42 张） | 否 |
| `shuriken`(1120) | 2×4 · 3×3 · 1×2 · 4×1 · 8×1（共 11 张） | 否 |
| `sentry`(1280) | 4×1 · 2×1 · 1×1（共 3 张） | 否 |

- 池内 `cards_engine.json` 的 `keywords` 字符串同样是 `Blast 1..6` / `Shuriken 1..8` / `Sentry 1..4`，**无裸词**。
- `abilityBuffs`/`permanentBuffs` 里 `buffType∈{3,90}` 授予这三条 trait 的行：**全部显式值 ≥1（共 41 行，0 行缺值/0 行 ≤0）**；
  全库 `buffType=3` 的**负值 traitValue = 0 行**；没有 `removeTrait`(4) 指向这三条。
- 文本面：`lose … Shuriken/Sentry/Blast` 0 条（唯一命中是 `ASH79` 的 "loses Stealth"）。
- 反例（易误判）：`ASH26 War Walker` 英文 `desc` 写成 "Armour. Blast"（**英文缺数字**），
  但 `keywords`/`cardTraits` 是 `Blast 2` ⇒ 不是 0 值。

### 结论
**不可达（今天无任何路径能造出「有键、值 0」的 shuriken/sentry/blast）**。但**仍要照原版改**（铁律 11）：
三处调用点的闸改成 `KwValue(kw) > 0`（或 `int sh = KwValue(...); if (sh > 0)`），**⛔ 不要改 `Has()` 本身**
（`UnitState.cs` 那段 B128 已证：`HasCurrentTrait` 只比 id、`addTrait` 对 `traitValue==0` 照样挂）。
若可达，当前实现的症状是 **`Hurt(…, 0)` 会多一条 `Hit` 飘字「0」**（见 G-8 的 `ShowHitDamagePop` 口径）。

## 二、G-5 践踏多一道 `targetDied`

### 原版 / 我们
- 原版 `BattleManager__ShouldTriggerStompDamage.c:20-36`：`HasCurrentTrait(攻方,0x4d8)` ∧ **目标 `+0x68 < 0`** ∧ `adjCount > 0`。
  伤害量 = `:1078-1092` 取目标 `+0x68` 后 **`(v ^ (v>>31)) - (v>>31)` = `abs(health)`**（超杀量），与 `dealt>hpBefore` 同义。
- 我们 `RuleCore.cs:7290`：`targetDied && attacker.Has("stomp") && dealt > hpBefore && adjUnits.Count > 0`，
  `targetDied` 来自 `:7215` `if (dealt > 0 && !target.IsAlive) targetDied = true;`（另 `:6914` 星镖杀也会置）。

### 关键事实
- `UnitState.IsAlive`（`:1707`）**就是 `Health > 0`** ⇒ **「health < 0 但 IsAlive 为真」在定义上不存在**。
- `Health` 在伤害路径上**不夹到 0**（`RuleCore.cs:9150` `u.Health -= actual`，无 clamp）⇒ 负血是**批内瞬态**（死亡延后到批末）。
- 幸存者 `UseSurvivor.c:18-33`：`health = min(CurrentSurvivor, currentMaxHealthProcessed)`，存活者 ≥1 ⇒ 恢复后必 >0，
  **不会留下负血**。且池内 `survivor`(430) **0 张卡**（truth `cardTraits` + buff 全扫）⇒ 不可达。

### 真正的差异（须记录）
`targetDied` 被 `dealt > hpBefore`（⇔ `Health<0`）**完全蕴含** ⇒ 那道 `!IsAlive` 本身**等价、不产生差异**。
🔴 但**星镖杀**这一档不同：`:7196` 主伤害整段跳过 ⇒ `dealt = 0` ⇒ `0 > hpBefore` 恒假 ⇒ **我们不践踏**；
而原版只读 `+0x68`（此时被星镖打成负数）⇒ **原版照样践踏，量 = `abs(health)`**。
可达性：需要「带 stomp 的单位同时带 shuriken」——现读 **0 张**（stomp 8 张全 army 20=Ork；shuriken 仅 Aeldari），
单阵营卡组进不去 ⇒ **今天不可达**。
**结论**：G-5 判 **不可达**；`!IsAlive` 是死闸。建议按原版把闸/取值改成
`attacker.Has("stomp") && target.Health < 0 && adj > 0`、量 = `-target.Health`（去掉 `dealt>hpBefore`），
这样星镖杀那档自然同形（铁律 11，即使今天 0 张）。

## 三、G-8 dropPod / bastion 吸收时弹值

### 原版判据（`CardScript._ReceiveDamage_d__381__MoveNext.c` 逐行）
- `:54` 函数首句 **`+0x35 = 1`**（`hasDoneDamage` 默认真）。
- `:60-190` 的 if/else：外层闸 = `!dodge(0xf0) ∧ !invulnerable(0x136) ∧ !shield(0x50)`；
  - 里层 `dropPod(0xe6)`（`:69-186`）与 `bastion ≥1 且 deathType != 10`（`:126-174`）两支**整份吸收**，**都不清 `+0x35`**；
  - **只有外层 else（`:185-187`）才 `+0x35 = 0`**。
- `:313-317` `if (+0x35 != 0) BattleCardUI__DamageReceived(UI, *(int*)(DamageInfo + 0x18), 0)` ⇒ 弹的是
  **`DamageInfo.damageValue`（原值）**，不是「实际掉血」。⇒ dropPod/bastion 整份吸收时**要弹原值**。

### 我们
- `RuleCore.cs:8905`（dropPod 吃掉易伤第二发）/ `:8953`（dropPod 吸收完、无易伤第二发）/ `:8983`（bastion 整份吃掉）
  都是 `EmitHit(ctx, u, 0)`；`EmitHit`（`:9554`）→ `EmitUnit` 写 `BattleEvent.Amount`。
- 表现层 `BattleDriver.cs:25542` `ShowHitDamagePop(e.Amount, e.DamageFullyBlocked)`；
  `ShowHitDamagePop`（`:42560`）= `amount >= 0 && !fullyBlocked` ⇒ **`Amount=0` 弹「0」，原版弹原值**。
- `absorbed`（`RuleCore.cs:8806-8810`）只被 dropPod 置真；`damaged` 广播在 `EmitHit` 里由 `absorbed || amount==0` 挡掉
  （`RuleCore.cs` 那条 `if (absorbed || amount == 0) return;`）——**这一半两边已同形**（原版 `damageAbsorbed` 同样早退）。
- ⚠️ `Amount` **同时**是「血量显示差分」的输入：`BattleDriver.cs:20990-20996` `NotePendingHp` 用 `Hit.Amount` 反推
  「扣血前血量」⇒ **不能直接把 `Amount` 改成原值**（血没掉却按掉那么多显示）。

### 可达性（现读）
- `dropPod`(230)/`bastion`(850)：`cards_engine.json` 1142 张 **0 张**；`cards_truth.json` 1351 张 **0 张**；
  `buffType∈{3,90}` 授予这两条 **0 行**；关键词字符串 0 命中（`SW23 Fenrisian Drop Pod` 是卡名，trait 只有
  `ferocity`+`flying`）。⇒ **今天不可达**。

### 结论
**不可达，但按铁律 11 要照原版改**，且**必须**用一条新字段（建议 `BattleEvent.PopupAmount`，缺省 = `Amount`）：
- `:8905` 改发两条：`Hit(dmg)` + `Hit(podVulnRaw, vulnerableSecond:true, absorbed:true)`（原版是两条独立 `ReceiveDamage`，弹两次）；
- `:8953` 改 `Hit(dmg, absorbed:true)`；`:8983` 改 `Hit(hit, absorbed:true)`（**同时补 `absorbed: true`**，
  否则原版 `damageAbsorbed` 那档的 `damaged` 早退会丢失）；
- 表现层 `ShowHitDamagePop` 读 `PopupAmount`，`NotePendingHp` / 成就 / 统计继续读 `Amount`（保持 0）。

  在 **`EvtKind.Attack`** 上**无条件**按「攻方有没有这个词」播 ⇒ **不满足分支条件也播**（未远程、未击杀、被更早分支抢先都不判），

- terror 没有任何信号；sneakAttack 没有任何信号（`ResolveRangedAttack` 那支远程动画没建模）。

### 可达性（现读自己核过）
- `sniper`(990) **11 张**（ASH6/ASH10/ASH68/GSC25/GSC34/SAU15/SW29/UM8/UM20/UM81/UM94）。
- `longrange`(1160) **13 张**（AM23/AM33/TAU5/15/18/27/30/31/35/36/38/UM90/UM92）。
- `terror`(520) **0 张**（S1 给的「1」是 `TL74 "Terror of Vardenghast"` 这个**卡名**，不是关键词）。
- `sneakAttack`(20) **0 张**。
- 另有 `buffType=3` 授予 sniper 3 行 / longrange 4 行 ⇒ 运行时也能获得。

### 最小实现方案（⛔ 不写代码，只给落点）
1. `CounterAttack`：新增 `enum CounterExempt { None, SneakAttack, Terror, Sniper, LongRange }` 与
   `Classify(ctx, …)`（**按原版顺序** sneak → terror → sniper → longrange），`NoCounter` 改成 `Classify(...) != None`（判据只此一处）。
2. 引擎：`RuleCore.cs:6989` 已经有 `noCounterEarly`（预测口径 `WouldKillByEntries`，**正是原版「先算伤害再判」的形状**）
   ⇒ 在那里取分类，随 `EvtKind.Attack` 一起带出去（**建议给 `BattleEvent` 加 `CounterExempt` 字段**；
   `EvtKind.Attack` 已在 `:7129` 发、零时长，无需新 `EvtKind`、无需改 `EventTiming`）。
3. 表现层 `BattleDriver`：
   - `PlayAttackFeel`：`CounterExempt != None` ⇒ **不播**普通攻击动画/VfxMap 那一下（保留原版的前置 `SetupAttack` 抬手）。
   - `Sniper` → `TraitParticles.Play("sniper", 攻方 view)`；`LongRange` → `TraitParticles.Play("longrange", …)`。
   - `Terror` → 只播音效《activateTerror》（`SoundAssetCollection` GUID `a35d6ec183aa3544382fb9e84d04e1e7`），**不演状态框**（原版视觉为空）。
   - `SneakAttack` → 强制按「远程攻击动画」演（对应 `ResolveAttackRangedAnim`），今天 0 张也照做。
   - 把 `"sniper"` / `longrange`（以及 `"stomp"`）**从 `AttackTraitParticles` 移除** —— 它们各自有触发时机（本信号 / 践踏块 / 标记光块）。

## 六、没查清的
1. `ResolveAttackRangedAnim` 的第三个实参语义（`ResolveRangedAttack` 传 1、普通远程路也传 1，shuriken 那一支传 0）——
   取值一致但**参数含义未从 `.c` 判出**（需要 `CardScript__ResolveAttackRangedAnim.c` 逐句读）；只影响 sneak 支的动画细节。
2. `_ResolveAttack…` 里 `+0x139`（守方被星镖杀）与 `+0x13a`（攻击者被哨戒杀）在爆裂/践踏块里的**精确组合闸**：
   已确认 `:1013-1014` 只挡 Blast（我们同形），但 `+0x139` 是否也会挡践踏**未单独逐句核**（现读代码里未见）。
3. 「星镖杀 + 践踏」是否真能同体：现读 0 张，但**跨阵营卡组/临时授予链**（战将天赋、附魔、跨阵营模式）
   我没有逐条穷举；若存在跨阵营授予路径，这一档就**变为可达**。
4. `damageAbsorbed` 对 bastion 的取值：注释与 `GetAdjustedDamage.c:52-60` 一致（`damage <= CurrentBastion ⇒ absorbed=1`），
   但 `CurrentBastion` 读的是**扣减前**还是**扣减后**，`.c` 未逐行核（只影响「打平 `remaining==0`」那一格的广播）。
