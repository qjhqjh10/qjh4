## 三、最小 JSON 形状（可直接粘）

### 3·1 `InfoResultPayload.UserReadOnlyData.PlayerDecks`（**注意：ReadOnlyData，不是 UserData**）

`Value` 必须是**一段 JSON 文本**（`OnlineData.GetPlayerOnlineData` 会对 `UserDataRecord.Value` 再 `DeserializeObject<T>` 一次）：

```json
"PlayerDecks": {
  "LastUpdated": "2026-01-01T00:00:00.000Z",
  "Permission": "Public",
  "Value": "[{\"id\":\"offline-deck-0001\",\"name\":\"Offline Deck\",\"hero\":\"DA1\",\"cards\":{\"DA2\":2,\"DA3\":2},\"cardback\":\"\",\"warcry\":\"\",\"deckTag\":0,\"characterId\":\"\",\"prebuiltDeckId\":\"\",\"defenseCard\":\"\",\"lastEditTime\":1767225600000,\"gameMode\":null}]"
}
```

- 值 = `AzureDeckInfo[]`（`Everguild.W40k.AzureObjects/AzureDeckInfo.cs` 字段全表：`cardback` / `cards`(Dictionary<string,int>) / `characterId` / `prebuiltDeckId` / `deckTag` / `hero` / `defenseCard` / `id` / `lastEditTime`(long, ticks) / `name` / `warcry` / `gameMode`(PlayModes?, 可 null)）。
- `hero` **必须**能在 `cards` 标签的卡 SO 里按 `uniqueId` 命中，否则这条卡组被静默过滤。
- `cards` **必须存在**（哪怕是 `{}`），null 会 NRE。

### 3·2 `InfoResultPayload.UserReadOnlyData.PlayerDecksFast`

同形状；没有快模式卡组时给 `"Value": "[]"` 或干脆不填（两边都 null 时 `DeckInventory` 直接 return）。

### 3·3 `InfoResultPayload.UserInventory` 里的一条卡（`PlayFab.ClientModels.ItemInstance`）

```json
{
  "ItemId": "DA1",
  "ItemInstanceId": "offline-card-DA1",
  "DisplayName": "DA1",
  "RemainingUses": 1,
  "CatalogVersion": "",
  "ItemClass": "",
  "CustomData": {},
  "Annotation": "",
  "BundleContents": [],
  "BundleParent": null,
  "UnitCurrency": "",
  "UnitPrice": 0,
  "UsesIncrementedBy": null,
  "PurchaseDate": "2026-01-01T00:00:00.000Z",
  "Expiration": null
}
```

- **只有 `ItemId` 与 `RemainingUses` 是功能必需的**；`ItemInstanceId` 建议给（用于 `Remove(instanceId)` 与去重），其余可省。
- 一张卡一条，`RemainingUses` = 拥有张数（1~3）。同 `ItemId` 写多条会被 `Inventory<T>` 按 id 合并（`Inventory<T>.Add` 以 `item.GetID()` 为键），不如一条写对数量。

卡背（要开卡背页时）：

```json

```

（`ItemId` 取自 `bundle_cosmeticsso_assets_all/MonoBehaviour/Cardback_*.json` 的 `uniqueId`。）

## 六、顺手发现（不在本次范围，但值得记账）

1. **新卡组会触发两次 `updatePlayerDecks`**：`UploadDeck` 成功后 `InventoryManager.Add(deck, 1)` → `DeckInventory.OnItemCountModify(deck, 1)`（amount > 0 分支）→ 又把 `syncedToServer` 置 false 并再 `UploadUnsyncedDeck` 一次（`DeckInventory.cs:OnItemCountModify`）。假服务端必须幂等。
2. **`RemoveInvalidCards` 会按库存数量改卡组**，而且**不提示**。离线版如果先给「卡组」不给「卡」，用户点开编辑器就会看到卡组被清空 —— 很容易被误判成"读取失败"。
3. **卡组 id 不稳定会被当成新卡组**：`CardDeck(CardDeck deckToCopy)`（复制编辑）把 `deckId` 传 null ⇒ `DeckBasicSetup` 现场 `Guid.NewGuid()`；`AzureDeckInfo.id` 为空时同理。所以假服务端给的每条卡组**必须带 id**，否则每次登录都"多出一份"。
4. **`CollectionManager.GetRawCardFromId` 找不到时返回 null 而不是抛**（ILSpy 把 `?? throw` 渲染成 `new NullReferenceException()`，实际是 null），所以「hero 解析失败」的表现是**卡组静默消失**，不是报错。
5. **收藏窗没有「头像」页签** —— 4 个页签是 Select Deck / Cards / CardBacks / Alternate Art。若之前按"卡牌/卡组/头像/卡背"记过，应就地订正。
6. `ShowInCollectionOptions` 的取值是 **Hide=0 / Show=5 / OnlyIfOwned=10**（不是 0/1/2）；卡背 SO 常见 `10`，即"拥有才显示"。
