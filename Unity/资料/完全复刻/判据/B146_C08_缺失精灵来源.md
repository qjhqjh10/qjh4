**别一次性全导**（119 个无消费方，导进去只增加包体与「看着做了」的假象）。建议按消费方分批：

1. **第一批（真缺口，2 张）**
   `UI_Button_Organe_Square_Pressed` → `Resources/Art/ui_menu/`
   `40K_general_icon_lock` → `Resources/Art/ui_menu/`
   源 = TSV 的「来源路径」列，**直接拷 PNG 即可**（已切好、RGBA8、无 padding 处理）。
2. **第二批（卡组选择页要做的 78 张）** → `Resources/Art/ui_deck/`，与 `40k_DeckSelection_icon_Faction*` 同目录。
3. **第三批（社交/聊天/日常 18 + 3 + 1）** → `Resources/Art/ui_menu/`。
4. **第四批（调试/战利品 12）** → `Resources/Art/ui/`；`Battle Debug Atlas` 那 7 张可**先不导**（原版调试件）。

**导入时必须同时做的三件事**（照 `ArtBaker.cs` 的既有纪律，否则下次 `BakeAll` 会把 `.meta` 打回）：

- **`.meta` 压缩档**：这些是**图集切片**，原版图集本身是 BC7/DXT5；**必须把新名字补进 `ArtBaker.CompTruths`**，
  否则 `ApplyImportSettings` 会无条件写 `CompressedHQ`（见 `ArtBaker.cs:960-1010` 那段注释的同一坑）。
- **`spriteMode / pixelsPerUnit / pivot / border`**：本 TSV **没有逐张出**（值是有的 —— `Sprite/*.json` 的
  `m_Border` / `m_Pivot` / `m_PixelsToUnits`，图集那份 json 也在 `assets_full`）。真要导的时候按名逐张取。
- **落点目录决定 `CardArt` 的兜底顺序**（`ui_menu → ui_deck → ui`），别把同一张图放两层。

**如果将来真要「从图集现切」**（比如换一批图集），切法已验证可用（⚠️ 见 §五-1 的坑）：
```
rect = SpriteAtlas.m_RenderDataMap[匹配 m_RenderDataKey 的那条].textureRect     # 不是 Sprite 自己的 m_RD.textureRect
PIL box = (rect.x, H - (rect.y + rect.h), rect.x + rect.w, H - rect.y)          # H = 图集贴图高度，y 要翻
```

## 五、没查清的

1. 🔴 **方法学坑（已查实，值得记进 CLAUDE.md）**：`Sprite/*.json` 里的 `m_RD.textureRect` **不是图集里的位置**，

   **图集位置只在 `SpriteAtlas.m_RenderDataMap[m_RenderDataKey].textureRect` 里**。
   照 `Sprite/*.json` 切会**静默切错**（我第一版就切到了图集左下角的一把刀）。

   需要一个消费方或原版 prefab 引用才能定；本轮没查 prefab 引用图。
