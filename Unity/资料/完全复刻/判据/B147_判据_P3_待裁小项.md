### 三、离线还能定的两件（这两条就是我给的结论）

1. **`B146` §五 的「首选修法」方向对，但落点会连带改一处比例**：
   `TmpFont.EmPerFontSize(Face.Cjk)` 改成 `0.1` 后，`CapOverGlyph`（`Label.cs:525-533` = `CapPerFontSize / EmPerFontSize`）
   会从 **0.8217 → 0.7011**，而它同时喂 `GlyphHeightWorld`（`:537-545`）与 `SetScriptHeight` 的**拉丁路**（`:592`）。
   ⇒ 只说「改一行」会漏掉这一跳；正确表述是「改一行 + 复核 `CapOverGlyph` 的两个消费者」。
2. **auto-fit 站点要看「谁先卡住」**（这点 `B146` 没写，我推导并核过代码）：
   `SetAutoFitBox` 写进 TMP 的 `fontSizeMax/Min = cur × (maxPx / nomPx)`（`Label.cs:1369-1376`），
   而 `NominalPx()`（`:1442-1447`）与 `cur` 用**同一个** `EmPerFontSize`、且 uGUI 档 `PxPerUnit = 1`（`:2040`）
   ⇒ 比值把该因子约掉，只剩 `fontSizeMax = maxPx / (10 × e)`：
   **CJK 面 e = 0.0853 ⇒ 上限 = 1.172 × maxPx（原版 = maxPx）**；拉丁面 e = 0.1 ⇒ 正好 = maxPx。
   · **框先卡住**（中文长句 / 高框窄字）：收敛字号 = `框高 ÷ 行盒 = 43.622 ÷ (1.437×0.9) = 33.73`，
     只要 33.73 ∈ `[min, max]`（现读 `21.1 / 52.74`，两端同样被放大 1.172）⇒ **收敛值与原版逐位相同**；
   · **上限先卡住**（短中文 / 框很松）：我们最大能到 **1.172 × 原版上限** ⇒ **仍然 +17.2%**。
   ⇒ 结论要写成两半：`B146-W22` 已落的确认键属于「框先卡住」⇒ **现在是对的**；
   **但 auto-fit 不是全免疫**，短文本档仍带 +17.2%。真正**只**受固定字号影响的是 `SetGlyphHeight` 78 处 / `SetScriptHeight` 21 处的 CJK 半。

### 四、裁定

- **离线可定的部分现在就定**：
  ① 跨面差 = **+17.2%**（不是 5.5%），算式与三个常量如上，**不需要任何运行**；
  ② 修法 = 让 `EmPerFontSize(Cjk)` 与拉丁面同口径（`0.1`），**并同批复核 `CapOverGlyph` 的两个消费者**；
  ③ **受影响面分层**：固定字号 `SetGlyphHeight` 78 处 + `SetScriptHeight` 21 处的 CJK 半 = **全量 +17.2%**；
     auto-fit 156 处 = **「框先卡住」无偏差、「上限先卡住」仍 +17.2%**（要抽审短文本/松框那批）；
     其中**注释写明「原版 `m_fontSize = X`」的那批**（如 `BattleScene.cs:8449` `30.6/108`、`:8657`、`:8704`）改后即与原版逐位一致；
     **注释写「X px 高的字」（= 意图是墨高）的那批**（如 `DeckScene.cs:8266` `20f/108`「20px 高的字」）改后会小 14.7% ⇒ **要逐个改实参**（× 0.853），⛔ 不能一刀切。
- **必须真机并排才能定的（就给这三条）**：
  1. **我们的 `_tmp.fontSize` 是否真等于换算值**——有没有别处二次改写（`ReplayFitForFace` `:1393-`、`SetWrapWidth`、各面板的 `Fit`）。
     量法：`Label.DumpSizes()` 已含 `fontSize / min / max / base / tmpW / tmpH`（`Label.cs:1525-1534`），跑宿主时打出来对照。
  2. **改后是否溢出/被裁**（行盒从 `1.516F` 回到 `1.2933F`，折行与框高都会变）。
     量法：改后跑 `BattleScene.Run` / `DeckScene.Run` / `ShellScene.Run` 里那几条 `FontPxNow` 断言 + 抽 3 屏截图。
  3. **墨高的最终并排**（公式管「字号」，实拍管「眼睛」）。
     量法：同一句中文（如「继续」「选择一张牌」），原版实拍 vs 我们预览，量**墨迹上下沿**像素高；期望比 = 1.000。
     ⚠️ ⛔ 别用 `GlyphHeightWorld` / `CapHeightWorld` 当量具（它们是**回读传入值**的伪测量，`已知的坑.md`），用 `FontPxNow` + 截图。

### 还差什么

- `A1262` 建议的「`0.1 × faceInfo.scale = 0.09`」**只修 5.5%、还留 11.1%**，`活状态表` 已判它错，本次复核**确认那个判定是对的**（0.09 是「em per fontSize」，而原版 `m_fontSize` 是 fontSize 单位，两回事）。
- 本条的**真机并排**我没做（红线：不跑 Unity）。上面三条量法即施工单。

## ⑤ `B146-C11-OBLIQUE` —— 维持 P3，但**回退理由降级为「未证实」**

### 原版判据（斜切=真在用，且配方可逐句复刻）

`kTools.Mirrors.Mirror__RenderReflection.c`：
```
:92-123  反射相机.worldToCameraMatrix = 源相机.worldToCameraMatrix × mirrorMatrix
:125-131 plane = GetMirrorPlane(mirror, **reflectionCamera**)   → Camera.CalculateObliqueMatrix(**源相机**, plane)
:150     反射相机.projectionMatrix = 上面那个结果
```
`__GetMirrorPlane.c:50-134`：镜面点 = Mirror 组件 `transform.position + forward × m_Offset`（`:50` 取 forward，偏移沿 **forward**，不是沿我们代码里写死的法线）→
用**反射相机**的 `worldToCameraMatrix`（`:62` / `:80`）变到视图空间（`:76` `MultiplyPoint`）→ 法线 `MultiplyVector`（`:93`）后归一 → `w = -dot(camPos, n)`（`:134`，末位再取反）。

**我们已经有同款配方**：`ArenaMirror.cs:283-294 CameraSpacePlane(Camera c, pos, normal, sideSign)`，
只是**没接**（`:306-309` 注释说试过、已回退；`:310` 直接 `= cam.projectionMatrix`）。

### 我们现读的「回退理由」站不站得住

原文（`ArenaMirror.cs:306-309`）：
> 斜切会把投影歪掉 ⇒ 反射与屏幕对不齐，实测三场反而变差（sororitas 1.058 → 1.084、tauviorla 1.033 → 1.044、arena3 1.050 → 1.052）

三条都成立的地方：**它确实试过**（`CameraSpacePlane` 留着就是证据）、**确实回了退**、**那三场的整场亮度比确实变差了**。
**不**成立的地方：**「变差」用的度量是整场平均亮度比**，那是**色调/能量**指标，**不是对齐指标**；
三个 Δ 分别只有 **+0.026 / +0.011 / +0.002**，落在同一量级的噪声里。
⇒ 「斜切导致对不齐」**是一个假设，不是被证明的结论**（铁律 5：这行要就地改成「未证实」）。

**另一条反向证据（也是假设级）**：原版是**按屏幕 UV 采 `_ReflectionMap`** 的（`ArenaMirror.cs:5-8` 记的是
`CommandBuffer.SetGlobalTexture` 灌全局贴图），而**原版自己就带斜切** —— 如果「屏幕 UV + 斜切」根本对不齐，
原版那 8 场的地板反射就该是歪的。所以「我们的地板 shader 采样方式导致不兼容」这个因果**至少不自洽**。

### 裁定

**维持 P3（本轮不落），但理由改为「未证实」，并给一次性判别实验。** 理由：
- 它**是**真偏离（原版用、我们没用）⇒ 按铁律 11 **要做**，只排先后；
- 但它**必须 Unity 出图才判得了**（本代理红线不跑 Unity），且改动只有 3~5 行 ⇒ 放在「有 Unity 窗口的那一批」里，**成本极低**。

### 落点（给写手，勿自己拍板改）

```csharp
// ArenaMirror.cs:310 之前插入（零行数：就地替换 :306-310 那 5 行注释 + 1 行赋值）
var plane = CameraSpacePlane(_refl, p0 + n * 0.01f, n, 1f);   // 原版 `__GetMirrorPlane.c:56-83`（Mirror.forward + m_Offset）
_refl.projectionMatrix = cam.CalculateObliqueMatrix(plane);     // 原版 `__RenderReflection.c:131`（在【源相机】上调）+ `:150`（赋给反射相机）
```
⚠️ 两处**别抄错**：① `CalculateObliqueMatrix` 调在**源相机** `cam` 上（用它的 `projectionMatrix` 做底），不是 `_refl`；
② 偏移沿**镜面法线**（= 原版 `transform.forward`），不是我们的 `planePos` 直给。
⚠️ `nonJitteredProjectionMatrix`（`:311`）**保持原样**（原版只写 `projectionMatrix`）。

### 判别实验（一次，~3 场）

1. 选 **sororitas / tauviorla / arena3**（就是当年「变差」的那三场）各渲一次斜切 on/off；
2. **只看地板反射区**（画面下半）：`arena_diff.py <场>` 的候选 + `_z0N.png` 放大图并排看
   —— 判据是「反射里的物体**位置**对不对」，⛔ 不看整场平均亮度比；
3. 若三场的地板区没有可见错位、且反射里的几何/卡牌倒影与地面法线一致 ⇒ **采纳斜切、核销 C-11**；
   若出现可见错位 ⇒ 把**错位的放大图**当反证留下，理由才从「未证实」升级成「已证实不可用」。
成本：单场渲 ~30 s（13 场全量实测 28 s 是 `arena_diff`，渲染另计）+ 3 场 ≈ 一个短批处理。

### 还差什么

  `d:/2/tools/assetripper_out/ExportedProject/Assets/Shader/` 里是 **DummyShaderTextExporter 的空壳**，只有 Properties，无 HLSL 体）
