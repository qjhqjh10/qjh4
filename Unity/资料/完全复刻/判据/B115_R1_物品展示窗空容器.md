# B115_R1 · 物品展示窗「空容器」（`B-303`）判据

> 只读诊断代理 `B115_R1` · 2026-11-01 · 唯一问题：**是「窗没建对」还是「宿主调错入口（没给数据 / 给错 Context）」？**
> 结论一句话：**宿主调错入口** —— `WindowShots` 用**无参** `OpenItemDisplay()` 开窗（`ctx = null`），
> 而这扇窗的 `Build()` 与原版 `ItemDisplayWindow.Open` **同一条闸**：没有内容 ⇒ `LogError("No item available") + return`，**一个节点都不建**。
> 另附一条**独立**的保真缺口（原版那一刻 prefab 的静态骨架仍在，我们是零节点），但它不是 B-303 的主因。

---

## 判决

**宿主调错入口（没给 Context）** —— 依据三条，缺一不可：

1. **宿主那一行就是无参调用**：`Editor/WindowShots.cs:200-201`
   `c => T(WindowsManager.OpenItemDisplay())` —— 没有实参 ⇒ `ctx == null`。
2. **这扇窗把 `ctx == null` 判成「原版 `context.item == null`」那一支**：
   `Shell/ItemDisplayWindow.cs:247-263`（`Create`）里 `win._ctx = FillDef(ctx); win._ctxProvided = ctx.HasValue;`（`:259`），
   `Shell/WindowsManager.cs:1052` 的 `win.Show(ctx)` 同理（`_ctxProvided = ctx.HasValue`，`Shell/ItemDisplayWindow.cs:282`）；`Build()` 首句 `if (IsEmptyContext()) { Debug.LogError(...); return; }`（`:296-300`），
   而 `IsEmptyContext()` 第一句就是 `if (!_ctxProvided) return true;`（`:534`）⇒ **`ctx == null` 直接空**。
   ⚠️ 注意 `DefContext()`（`:164-172`，`"Title" / "New Text" / "Type"`）**只在 `_ctx` 里**，`Build()` 早退时**根本没读到它** ——
   所以「出厂文本」不会出现在画面上（这正是实测「渲染件 0 / 文本 0」）。
3. **三个生产调用点全都给了 `Context`**（所以生产路不进这一支）：
   `Shell/CollectionWindow.cs:2003`（`ItemDisplayWindow.ForCardback(cbName)`）· `Shell/DailyRewardPopup.cs:1317`（`ItemInfoContext(day, premium)`）·
   `Shell/DailyStreakPopup.cs:1087`（`ItemInfoContext(day)`）。

**不是 `OpenByRef` 用 `null` 清 `Data` 那一跳**（简报里的候选根因）：
`WindowsManager.OpenByRef` 第 963 行确实 `wm.OpenWindow(win, null, closeAll)` ⇒ 走 `GameWindow.SetupData(null)`（`Shell/GameWindow.cs:585`）清 `Data`（`:416`），
但这扇窗**从不读 `Data`** —— `grep -n "\bData\b" Shell/ItemDisplayWindow.cs` = **0 命中**，内容只经 `_ctx / _ctxProvided`。
⇒ 清 `Data` 对本窗**零影响**，排除。

**附：一条独立保真缺口（不是 B-303 主因，但同在「空」这一支）**：
原版那一刻 **prefab 的静态子树仍在**（`GameWindow.TryOpen` 先 `SetActive(true)` 再调 `Open()`；`Open()` 早退**不会销毁 prefab 子件**）
⇒ 原版画面 = 暗底 + 空面板 + 三颗出厂 TMP（`Title` / `New Text` / `Type`）。
我们的 `Build()` 是**程序化重建**，早退 ⇒ **零节点**（连暗底都没有，所以 `item_display.png` 里连 `(0,0,0,0.773)` 那层遮罩都看不见）。
⚠️ 这与 `Shell/ItemDisplayWindow.cs:290-295` 那条注释「一个节点都不建」**不完全成立** —— 那句话只描述 `Open()` 的方法体，
不等于「窗口看上去是空的」。详见 §修法二（建议单独记账，别混进 B-303）。

## 修法

### 修法一（解 B-303 · 必做 · 只动 `Editor/WindowShots.cs`）

把**那一行**从「无参」改成「带生产 Context」——**`ForCardback` 就是收藏窗卡背页那条生产建法**（`Shell/CollectionWindow.cs:2003`），
`CardbackTable.DefaultFor("Ultramarines")` 现读 = **`Cardback_UM_Campaign_Free`**（`Resources/Cardbacks.json` 的 13 条 `defaults` 之一；
`Resources/Art/cardbacks/Cardback_UM_Campaign_Free.png` **存在**）。

```csharp
// Editor/WindowShots.cs:200-201 —— 把原来那一行换成这三行
new Spec("物品展示窗", "item_display", HostKind.MainMenu,
         c => T(WindowsManager.OpenItemDisplay(ItemDisplayWindow.ForCardback(SampleCardback()))),
         "`WindowsManager.OpenItemDisplay(ItemDisplayWindow.ForCardback(<样张卡背>))`（= 收藏窗卡背页的生产那一跳）"),
```

并在 `T(...)` 旁边（`WindowShots.cs:142` 之后、类内任意位置）加一个**取不到就出声**的样张选择器：

```csharp
/// <summary>物品展示窗的样张：`Resources/Cardbacks.json` 的默认卡背（现读 `Cardback_UM_Campaign_Free`）。
/// 🔴 本窗**没有「出厂内容」**：原版 `ItemDisplayWindow.Open` 在 `context.item == null` 时
/// `LogError("No item available") + return`（`decomp_full/ItemDisplayWindow__Open.c:23-34`），
/// 我们的 `Build()` 同一条闸（`Shell/ItemDisplayWindow.cs:296-300`）⇒ 不给 ctx 就是空容器（B-303）。
/// 取不到不静默：返回 null 时这一行会照旧 rc=1（那才是真红）。</summary>
static string SampleCardback()
{
    var n = CardbackTable.DefaultFor("Ultramarines");
    if (!string.IsNullOrEmpty(n)) return n;
    var names = CardArt.CosmeticNames();
    if (names != null && names.Length > 0) return names[0];   // 现读首个 = `Cardback_AM_Cold Blood`
    Debug.LogError(P + "物品展示窗的样张卡背取不到（`Resources/Cardbacks.json` / `Resources/Art/cardbacks/` 都空）⇒ 这一行会是空容器");
    return null;
}
```

⚠️ 三点（写补丁的人必须知道）：
- `using CardPresentation;` **已有**（`WindowShots.cs:55`），`CardbackTable` / `CardArt` / `ItemDisplayWindow` 都直接可用；`WindowShots` 在**全局命名空间**。
- **⛔ 别用 `ItemDisplayWindow.DefContext()` 顶上**：它是哨兵（`:162-163` 明写「⛔ 别再拿它铺文本」），拿它开出来的会是 `Title` / `New Text` 这种占位字。
- ⛔ **别改 `OpenItemDisplay` / `ItemDisplayWindow` 让「无参 = 默认给张卡背」**：原版 `null` 走的就是错误支（`ItemDisplayWindow__Open.c:29-32`），
  那样做等于自造一个原版没有的行为（`CLAUDE.md` 铁律 18·0）。

### 修法二（保真 · **独立一条账，别混进 B-303** · 需调度台拍先后）

若要让「无 item」那一刻**和原版看上去一样**：`Build()` 在 `IsEmptyContext()` 为真时**不要 `return`**，
而是**照 prefab 静态骨架建一遍**（暗底 + `Options/Panel` + 三颗 `DefContext()` 字 + 空的 `Card Display` / `Item Holder`），
**再** `Debug.LogError("[ItemDisplay] No item available")`（顺序照原版：节点本来就在，报错只影响「铺内容」）。

- 影响面：只有「有人拿 `null` 开这扇窗」这一条路；三个生产调用方**都走不到**（它们都给了 Context）。
- 必须同时**就地订正** `Shell/ItemDisplayWindow.cs:290-300` 的那条注释（铁律 5）：它现在写「原版一个节点都不建」，
  而原版 `.c` 只说明 **`Open()` 不铺内容**，prefab 的静态子件仍在（证据 §证据 4）。
  ⇒ 建议写成「原版 `Open()` 不铺内容；但 prefab 静态子树仍在 ⇒ 画面 = 空骨架。我们是程序化建树，需显式补这一层」。
- ⚠️ **先说清代价**：修法二做完后，B-303 那一行会自己变绿（有骨架了），但**拍的是一张占位图**
  ⇒ **修法一和修法二都要做**：一保证「拍的是真窗」，二保证「无数据时与原版同形」。

### 与 `B-302` 的关系（简报要求核）

**无同源关系。** `B-302` 是批处理下 `Screen = 640×480` ⇒ `UIBakeScreen` 的 RT 只有 160×120 ⇒ **只影响出图宿主的模糊底**；
它改变不了「窗自己建了几个节点」。反过来，这扇窗的 `FlavourRect` 用的 `SmallScreenUI.Enabled`
是 **`PlayerPrefs` 持久化值、与屏宽无关**（`Shell/TransformScalerBySmallScreenUI.cs:67-75` 明写「与窗口宽/屏宽无关」）
⇒ **不会因为 640×480 就把风味条多放大 1.12 倍**。两条账各修各的。
