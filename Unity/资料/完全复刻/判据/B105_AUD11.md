### 2.4 类 3B · `if (<其它条件>) Check(...)` —— **195 条 / 28 个文件**

**现在会不会执行**：条件为假就不跑。与 3A 的差别是**条件不是 null 判空**，而是
「对象找到没」「字段 == 某值」「`File.Exists`」「`Count == 1`」这类 —— 有的是**合法分支筛选**
（例如「本池只有一个阵营的督军 ⇒ 换阵营那条不适用」），有的是**纯失明**（前提挂了也没人知道）。

**后果**：比 3A 轻，但**数量大、且常常盖住真缺陷** —— 条件本身就是断言想要的东西时，
条件为假恰恰是**最该红**的时刻，而现在静默通过。

**建议改法**：**逐条分诊**，按三种去处：
1. 条件 = 被测前提 ⇒ 改成 `Check(<前提>, "（前提）…");` + 无条件断结论（同 3A）。
2. 条件 = 合法业务分支（确实不该断） ⇒ 保留，但在注释里写明「**这不是断言，是分支**」，并在交接里登记为未覆盖。
3. 条件恒真/恒假（推断式） ⇒ 直接改成无条件，或删掉。


### 2.5 类 3D · `CheckTrue(true, …)` —— **9 条**

**现在会不会执行**：执行，但**永远通过**（断言本身不含判据）⇒ **通过数虚高**。
其中 5 条的文案自己就写着「跳过 / 收尾 / 诊断」，属于**明知假断言**；
其余 4 条是「读数打印当成断言」（`RuleEngineTest` 的诊断行）。

**后果**：不会造成假红，会造成**假绿** —— 「合计多 9 条通过」不代表多验了 9 件事。

**建议改法**：改成 `Debug.Log(P + "…")`（纯打印，不进合计）；确实要留「跳过」语义的，
写成 `Debug.LogWarning(P + "⚠️ 跳过：…")` 并在交接的未覆盖清单里登记。

### 2.6 类 4（🔴 **本轮新发现，不在原三类里**）· 整个 `Run()` 被一个 `try/catch` 包住 ⇒ **一次抛异常截断后面所有段**

**机制**：宿主 `Run()` 里写

```csharp
try { RunA(); RunB(); RunC(); RunD(); RunE(); RunF(); RunG(); }
catch (Exception e) { Fail++; Debug.LogError(P + "★ 未捕获异常：" + e); }
```

`RunD()` 一抛异常 ⇒ **E / F / G 根本不会被调用**，日志里只多「失败 1」这一条。
读日志的人只会以为「有一条断言没过」，**不会知道后面三段一条都没跑**。

**已证实的实例（`GameModesCheck`，2026-10-30 23:43 那次全套）**：

- `d:/4/_tmp_view/gamemodes.log` 末：`[GameModes] === 断言合计：52 通过 / 1 失败 ===`
- 段头只有 **A / B / C / D** 四行（`grep -c "\[GameModes\] --- "` = 4），而 `GameModesCheck.cs:44-50` 一共调了 **7 段**（`RunRegisteredHandler` / `RunDraftGate` / `RunBootWiring` **从未执行**）
- 触发点：`D8` 断言期望 `GetActiveEvent(…)` 返回 `null`，而实现（`Shell/GameModesHandler.cs:290`）已按「原版这一支是 NRE —— 照抄」**抛异常**
  ⇒ **断言与实现口径相反**，每次跑必红，并且**顺带吃掉后面三段**。

**机扫候选（16 个文件）**：判定 = `try` 与 `catch (Exception` 同缩进、且 try 体内直接调用了 ≥3 个 `Xxx();` / 打了 ≥3 个段头。

**建议改法（二选一）**：
1. **逐段 try/catch**：每段自己 catch + `Fail++`，一段炸不影响别段；**并且**在 catch 里把段名打出来

2. **catch 之后必须打出「本节已中止，共 N 段只跑了 M 段」** —— 只要不印这一行，读日志的人永远分不清
   「1 条红」和「3 段没跑」。

### 4·3 类 3A / 3B —— **灭自证**：证明改完会「红」

`if (x != null) Check(…)` 改成 `Check(x != null, "（前提）…")` 之后，**必须故意把夹具弄坏一次**：

```bash

```

**这一步不能省** —— `B102_W1` 的教训就是「看起来接上了、绿着、其实一行没跑」。

### 4·3b 类 4 —— 证明「后面那几段到底跑了没有」


两者不等 ⇒ **有段被截断**。同理适用于上表 16 个候选文件。

### 4·4 治本建议（可选，成本中等，收益最大）

给 `Check` 族加一个**可选 `id` 形参**，日志里逐条印 `✓ <id>`，然后：
- 每次宿主跑完导出 `$(id)` 列表 ⇒ 与源码里的 `id` 全集做差集 ⇒ **哪条没跑过，机器直接给**。
- 这条做完之后，AUD11 从「静态推断」变成「**实测**」，而且**永久可复跑**（不再靠人读代码）。

## 五 · 盲区（扫不到的形状，⛔ 别把「0 命中」当「不存在」）

| # | 盲区 | 影响 | 本轮怎么补的 |
|---|---|---|---|
