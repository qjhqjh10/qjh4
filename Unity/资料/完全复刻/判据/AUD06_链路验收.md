## 〇、判定口径（⛔ 不是「行级全 A」）

| 档 | 含义 | 判据 |
|---|---|---|
| **✅ 已验收** | 至少一条断言**真的驱动了 A**（点/悬停/推进/调入口），并**在同一段里断 B** | 证据给出「驱动那一句 + 结果那一句」所在行 |
| **🟡 只有件、没有链** | 控件/参数/数值都在，但没有任何断言把「A 触发 → B 出现」串起来；或断的是并列参数矩阵 | 证据给「件在哪」，**缺的那一跳**写清缺什么 |
| **❌ 断的** | 链路上**某一跳根本不存在**（生产代码没接 / 入口是我们自定的 / 一个调用点都没有） | 缺的那一跳 + 判据 |
| **D 档不适用** | 原版不可达 / 服务器类 / 编译器生成物，**没有玩家可见链路** | 记「不适用」并写出原因（铁律 11 例外①） |

两条硬规则（本工程踩过）：
1. **行级全 A ≠ 链路通** —— 账里 5,761 条 A 说的是「这一行读懂了」，不是「这条链被验过」。本轮 60 个 FP 里大部分 FP 的等级是 A/B/C，但下面仍有 2 条 ❌ 与 8 条 🟡。
2. `if (x != null) Check(...)` 这种**前提不成立就静默跳过**的写法**不算验收**（附录 §A 给了本轮扫到的实证清单）。

## 三、结论（一句话 + 证据）

1. **P0 四域（卡组编辑 / 收藏 / 卡牌面 / HUD）的链路基本是通的**：60 条里 40 条 ✅，而且**不是**靠「件在就算」——
   典型如 `CollectionScene.cs:5307`（真点页签 → `CurrentTab` + `activeSelf` + 高亮三个一起断）、
   `CollectionScene.cs:6547`（筛 legendary → 可见数变 → 清空回原数）、
   `BattleScene.cs:12588`（`AbilityClicked → SkillPanelConfirmRelease → TryUsingActiveAbility`）、
   `RuleEngineTest.cs:28486`（预览合计必须**等于**真打一局的掉血）。
2. **断口集中在「窗口入口是我们自己定的」和「服务端档」这两类**：
   - `FP-HUD-004` ❌：`TipPrebattle.Create` **全工程 0 个生产调用点**（只有 `GameStaticDataCheck.cs:128-137` 在测它的 `GetRandomTip`），「加载 → 战前提示 → 开场」这条链**不存在**。
   - `FP-SHOP-009` ❌：轮播区**只有数学**（`ShopScene.cs:1989-2006`），源码注释自己写着「UI 与输入还没接」（`ShopScene.cs:1987`）。
   - `FP-SHOP-003` 🟡：报价弹窗开出来了，但**入口是我们定的**（`ShopTabPage.OpenBoosterInfo`，原版 `ShopOfferContainer.OnClick→OpenContainer` 那一族没有）⇒ 「点商品 ⇒ 弹窗」这一跳没有断言。
3. **「参数矩阵 ≠ 链路」是本轮最常见的半缺口**（8 条 🟡 里有 5 条是这一类）：抽屉槽位/价格物件/活动页签都是逐件并列断言，没有一条「**换一条数据 ⇒ 画面跟着换**」。
4. **一个系统性问题要记（附录 §A）**：`if (x != null) Check(...)` 在本工程仍有 ~15 处**真·静默跳过**（已排除 `if (x==null) Check(false,…)` 这种响亮的写法）——它们落在链路断言里就会让「链路通」变成假绿。
