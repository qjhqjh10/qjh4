## 顺手发现（不在本任务范围，但下个会话需要知道）

1. 🔴 **`工具/res_audit.py` 有一个判据 bug（E24 的 9 条 `尺寸格式错` 全部来自它）**：
   `effective_max_size()`（`:251-264`）的 docstring 一边写「`overridden: 0` 的平台块**不生效**，Unity 回落到 `DefaultTexturePlatform`」（`:213`），实现一边又写「`overridden` 字段**不能**当门」（`:254`）并按平台块取值。**两个说法不能并存**，且**实现那一版被构建产物证伪**。修法（三行）：
   ```python
   blk = ps.get("Standalone")
   if blk and blk.get("overridden", 0) == 1 and blk.get("maxTextureSize"):
       return blk["maxTextureSize"], "Standalone"
   ```
   ⚠️ 改完要重跑 `--scan`（否则 TSV 里那 9 行还挂着）。
2. 🔴 **`工具/res_audit.py` 的 P2 逐像素判据会把"alpha=0 区域的 RGB 差"算进 `内容不同`** —— 56 条里 **18 条**是这么来的（原值差 0.08~2.9 却报 `内容不同`）。**修法**：比较前先按 `alpha > 0`（或 `> 10`）掩码，或把 RGB 差改成"alpha 加权"。同样，**建议加一条 gamma 复检**（`srgb2lin` 后再比，能再回收 21 条）。⚠️ E24 §六 说「用同名且同尺寸才比像素」避开了"同名不同图"风险 —— 这条对；但**没避开编码差**。
3. 🔴 **`工具/res_audit.py` 的"关键字未声明"有一半是假阳性（`our_kws` 漏两种声明形态）**：
   `our_kws` 只从 `#pragma` 收（`:353-358`），但我们的 shader 大量用 **`[Toggle(KEY)]`** 声明关键字（`WFDistortion.shader:67-72` / `WFEclipseTau.shader:53`），而 `RE_PRAGMA`（`:329`）也只认 `multi_compile(_fragment|_vertex)?` —— **不认 `#pragma multi_compile_local`**。
   **自证**：Unity 的 `.mat` 里已经把同一个关键字判成 `m_ValidKeywords`（= shader 认识它）⇒ 工具与 Unity 打架，**Unity 那一侧是对的**。
   **修法**：解析 shader 时额外收 `\[Toggle\(\s*(_\w+)\s*\)\]` 与 `_local`/`_vertex`/`_fragment` 全组合；`unk` 再与 `.mat` 的 `m_InvalidKeywords` 取交集才报。
4. 🟠 **本机文件名大小写不敏感埋着一颗雷**：代码写 `40K_generic_bt_info`（`Shell/CampaignExpansion…` 多处，`CardArt.MenuUi`），磁盘上是 **`40k_generic_bt_info.png`**（小写 k）。Windows 编辑器里能取到，**其它平台/区分大小写的构建环境下会取不到**。同类还有 `40k_UI_bt_back_pressed`（代码小写、文件小写 → 这个是一致的）。**判法**：`grep -o '“[0-9A-Za-z_]*”'` 的图名与 `Resources/Art/ui_menu/` 做一次**逐字（区分大小写）**对账。
5. 🟠 **`Assets/WarpforgeVFX/*`、`Assets/CardPresentation/Effects/*.prefab`、`Assets/WarpforgeBooster/*` 都是生成物**（`.gitignore:26` 只留 `Runtime/ Shaders/ Editor/`）⇒ **今天这张表里凡是"改工程资产"的修法，都要先问一句"它是不是生成器写的"**；是 ⇒ 改生成器 + 重跑，**⛔ 手改必丢**。
6. 🟡 **`WarpforgeVFX/Textures` 里 475 张的 `Standalone` 块全是 `2048 / overridden: 0` 的样板值**，只有 9 张的 `DefaultTexturePlatform` 被抬到 4096/8192 ⇒ **"读平台块"这件事在 `res_audit` 里要连同 `overridden` 一起读**，否则下次还会误报。同族的 `Art/ui_menu` 那批（`B100_X11` 记的 66 张 2048 边）也值得按这条重扫一次。
7. 🟡 **`BoosterPackAssets.cs` 与 `BoosterPackExporter.cs` 各存了一份 17/2 个 prefab 名表**（`BoosterPackAssets.cs:74-95` 的注释自己就点出来了）—— 违反「表只此一份」，两份将来必不一致。已在 `B97_W23` §四 提过跨文件请求，**仍未做**。
8. 🟡 **`CardFlip` 那颗 `ParticleSystemRenderer` 用的是 `m_RenderMode: 4`（Mesh）**，而 `BoosterPackExporter` 的导出报告里只写了「材质定义 N 个 · 渲染器槽 N 个」**没提网格** ⇒ 网格这一支很可能**从来没被导出器覆盖**（工程 `Assets/WarpforgeVFX/Meshes/` 下没有原版那个唯一的 `BoosterPack` 网格）。修 §1-B 时**先查这一支**。
9. 🟡 **`内容不同` 的 `ui_menu/` 4 张重复件与 `boosterpack/` 同源重复**（`generic` / `leviathan` / `Sautekh` / `UM` 各两份，名字一模一样、内容一模一样）—— `import_original_art.py:461-466` 的注释明确写了"`ui_menu/` 那 5 张**不动**"。⇒ **将来任何重导必须两份一起改**，否则同一张图两个版本（这正是本项目踩过的"两份说法打架"）。
