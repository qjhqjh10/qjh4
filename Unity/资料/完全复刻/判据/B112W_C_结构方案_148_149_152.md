## B-148 · 「谁在展示窗里播 `Level Up Card`」

### 原版（谁播、哪一刻、什么树）—— 证据

**结论先说：原版只有一扇 `CardDisplayWindow`，升级只在【菜单版那一份】里发生；我们把它拆成了 `Battle/CardDisplayWindow`（战斗版）与 `Shell/CardDetailPopup`（菜单版），`Level Up` 属于后者，⛔ 不属于前者。**

1. **谁播 = `UpgradePanel.TryUpgrade`**（菜单版 `Card Options Panel ▸ Panel ▸ Upgrade Panel` 上的组件）。
   - `decomp_full/UpgradePanel__TryUpgrade.c`：`CardDisplayOptions__ResetDisplayOrder` → **`CardDisplayLevelUpAnimationController__DoAnim(*(param_1+0xa8))`** → 读 `CardTier` 算新档 → 调云函数 `0x385`（升级）。
     ⇒ 动画在**云函数返回之前**就起播。
   - `decomp_full/UpgradePanel__PlayAnim.c`：另一条同名入口也是 `DoAnim()`（ILSpy 里 `.PlayAnim()` **0 个外部调用点** ⇒ 应挂在 prefab 的 UnityEvent 上，本代理未再追）。

## B-149 · 升级动画跑在「窗根」，clip 路径对不上

### 原版（`Animation` 挂哪、路径怎么解析）—— 证据

1. `Animation` 挂在 **`CardUI`（主卡根）**：`MainMenu Warpforge.unity` 的 `!u!111 &622` `m_GameObject: {fileID: 88}`；`!u!1 &88` 的 `m_Name: CardUI`。
2. clip 的 curve path 相对**那个 GO** 解析 ⇒ 第一条就是 `2DCard/Level Up Effect`（`Assets/AnimationClip/Level Up Card.anim` 的 `m_ScaleCurves[1].path`），因为 `2DCard` 是 `CardUI` 的直接子件（`!u!224 &1323` `m_Father: {fileID: 1516}`）。
3. `m_ScaleCurves[0]` 的 `path:` 是**空串**（= 打 `CardUI` 自己），值 `250 → 288.977`（t=1.45），而 `CardUI` 的 `m_LocalScale = 250` —— 即「脉冲 = ×1.156」。
4. `CardDisplayLevelUpAnimationController` 与 `Animation` **不在同一个 GO 上**（前者在 `Upgrade Panel`，后者在 `CardUI`）⇒ 原版**不需要**任何 `SetCurve` 重绑，靠的是「组件引用跨节点」。
5. `UpgradePanel.ChangeFrameOnLevelUp` 只做 `BasicCardUI.RefreshCardVisualEffects(cardUI, tier)`，而 `BasicCardUI.RefreshCardVisualEffects` 全文只有一句 `cardTierUI.SetTier(rawCardData, tier)`（`out_cpp2il_dev_ilspy/BasicCardUI.cs:490-493`）⇒ **1.45 s 换框是"就地换框"，不重建卡、更不重建窗**。

### 现状（我们的树）—— 证据

1. 组件与 `Animation` 都在**窗根**：`CardDetailPopup.cs:2965`（`LevelUpEffect = gameObject.AddComponent<CardDisplayLevelUp>()` 那一段，`PlayUpgradeAnimation` 内）· `CardDetailPopup.cs:3390`（`anim = gameObject.AddComponent<Animation>()`，`EnsureUpgradeAnimation` 内）。
2. 播放：`Effects/CardDisplayLevelUp.cs:278` `myAnimation.Play()`（`DoAnim` 第 ② 跳）。全仓**没有**对这支 clip 做任何 `SetCurve`。
3. clip 的 path 实读（`Resources/Animations/Level Up Card.anim`，**10 条 path**）：
   `2DCard/Level Up Effect` · `2DCard/Level Up Effect/Level Up Effect Down` · `2DCard/Front` · `2DCard/Glow Explosion` · `Lighting Rays`。
   窗根下**一个都没有** ⇒ 今天真实生效的曲线 = **0 条**（事件两条照发，因为事件不看 path）。
   ⚠️ 好消息：我们的 `.anim` **已经去掉了 `path: ''` 那条根缩放曲线**（原版那条 t=1.45 → 288.977）。若它还在，挂到窗根会**把整扇窗的 localScale 写成 250**（我们的窗根 scale 是 1）——那是灾难性的。这条不搬回去，改用代码里的 `pulseTarget`/`BeginPulse`（`CardDetailPopup.cs:3018` 已接 `pulseTarget = SlotView(0)`）。
4. **局部单位其实是对得上的**（这条决定了方案 A 是否几乎零换算）：
   - 原版 `2DCard` `m_SizeDelta = 2.0927 × 3.3313`，其子件坐标就是这套单位。
   - 我们 `CardView.Width/Height = 2.0927 / 3.3313`（`Core/CardView.cs:302-303`），`2DCard` 是 `CardView` 的直接子件、`localScale = 1`（`CardView.cs:4260`），`Front` 的 `localPosition.y = +0.08`（`CardView.cs:4279` + `FrontAposY`）——**与原版 `Front` 的同名偏移逐值相同**。
   ⇒ 把光效层挂到我们的 `2DCard` 下时，换算系数应当是 **`s = 1`**（原版单位 = 我们的 `2DCard` 局部单位），⛔ 不再是现在那套 `unitToPx = CardsS/2.0927`。
   - 现读那套换算：`CardsS = 100f`（`Core/CardWinBox.cs:22`，是个 100×100 的定位框，**不是卡的宽度**）⇒ 今天 `s = (100/2.0927)/108 = 0.4424`；而主卡 `CardView` 根的实际 `localScale = Hpx(0)/(Height*108) = 832.825/(3.3313*108) = 2.3147`（`CardDetailPopup.cs:1213` 的 `v.SetPose(..., h/(CardView.Height*108f))`）⇒ **现有光效层比卡小 5.23 倍**。这是**既有缺陷**，换父件时随手一起修掉。
     ⚠️ 以上是**算术推算**，本代理**没跑 Unity 量过**，施工后必须在真 Play 里目测一次。
5. **1.45 s 换框会销毁 `Animation`（方案 A 的硬前提）**：`CardDetailPopup.cs:3000 OnLevelUpChangeFrame()` → `RebuildKeepingState()` → `Build()`，而 `Build()` 首句就是 `for (i = root.childCount-1; i>=0; i--) CollectionWindow.DestroySafe(root.GetChild(i))`（`CardDetailPopup.cs:1062`）⇒ **整窗子件销毁重建**。`Animation` 若挂在卡上就会被一起销毁 ⇒ 后半段 clip 与 `AnimationFinished`(3.48 s) **永远不响** ⇒ 输入锁解不开（`InputBlocked` 恒 true）。

### 方案（只比较「怎么让 clip 找得到节点」）

| # | 做法 | 取舍 |
|---|---|---|
| **A（推荐）** | **把 `Animation` 挂到主卡 `CardView` 根**（原版就是 `CardUI`），`Level Up Effect` 挂到该卡 `2DCard` 下，`s = 1`。 | ✅ 与判据逐条一致、clip **一个字不用改**、事件仍走 `SendMessage`；⚠️ 必须同时解决「1.45 s 换框不许销毁卡」（见下面 5 步里的第 3 步）。 |
| **B** | 保留窗根宿主，**`SetCurve` 重绑**到克隆 clip（把 `2DCard/...` 改成 `<主卡节点名>/2DCard/...`）。 | ❌ 三个坑：① `Resources.Load` 返回的是**共享资产**，必须 `Instantiate` 克隆后再改，否则污染全局；② 克隆后**两条动画事件会丢**，而 `AnimationClip.events` 的运行时 setter 在本工程**未验证**（`AnimationUtility.SetAnimationEvents` 是 Editor-only）——事件丢了就是「换框 + 解锁都不发生」，比现在更糟；③ 路径里嵌了运行时层级名，卡一改名就静默失效。 |
| **C** | 窗根下造一棵**代理子树**（空 `2DCard` + 假 `Front` + `Level Up Effect`），只为了让 path 解析成功。 | ❌ 造出原版没有的节点（违铁律 18），且 `2DCard/Front` 会钉在一个**假节点**上，钉住效果落在空气里。 |
| **D** | 现状（窗根 + 0 条曲线生效）。 | ❌ 等于「动画根本没播」，只有手写的 `pulseTarget`/窗抖/换框那几跳在动。 |

### 推荐 + 落点（方案 A，5 步）

1. **`Animation` 换宿主**：`CardDetailPopup.cs:3384 EnsureUpgradeAnimation()` 里把 `GetComponent<Animation>()` / `gameObject.AddComponent<Animation>()` 改成**取主卡**：`var cv = SlotView(0); if (cv == null) return; var host = cv.gameObject;`（主卡 = `SlotViews[0]`，取数口 `CardDetailPopup.cs:813 SlotView(int)`；「`Card` 永远建在槽 0」那条口径见 `:776 Card` 与 `RewireLevelUpTargets`（`:3009`）的 doc）。同理 `PlayUpgradeAnimation`（`:2958`）里的 `LevelUpEffect = GetComponent<CardDisplayLevelUp>()` 也要跟着挪 —— **见第 2 步**。
2. **`CardDisplayLevelUp` 必须与 `Animation` 同 GO**（动画事件是 `SendMessage` 到 `Animation` 所在 GO）：把 `LevelUpEffect = gameObject.AddComponent<CardDisplayLevelUp>()`（`:2965` 附近）改成挂到**主卡 `CardView` 根**。字段全是引用（`shakeTarget` / `upgradePanel` / `onChangeFrame` / 三格 `FadeImage`），挪宿主不改语义。
   - ⚠️ 主卡会被重建 ⇒ 每次重建后必须**重新 AddComponent + 重新接线**，落点 = `RewireLevelUpTargets()`（`CardDetailPopup.cs:3009`，它已经在「`DoAnim` 之前」与「重建之后」两条路上都走到）。
3. **换框不许销毁卡**：把 `OnLevelUpChangeFrame()`（`CardDetailPopup.cs:3000`）里的 `RebuildKeepingState()` 换成**只刷这张卡**。
   - 忠实做法 = 原版 `BasicCardUI.RefreshCardVisualEffects`（就地换框）：给 `CardView` 加一个公开入口（追加到**类尾**，铁律 18·b）`public void RefreshTier() { Build(Data); }` —— `Build` 已被注明确认重入幂等（`CardView.cs:4278` 的注释「`Build` 重入时也要保证它在（幂等）」）。
   - 面板计数/按钮态（`LogRebuildPanels` 那套）改到 `AnimationFinished` 或 `DoUpgrade` 里那一次 `RebuildKeepingState()`（`CardDetailPopup.cs:2688` 已经有，且**在 t=0 就把新档换好了**）⇒ 1.45 s 这一次本来就只是「同档位再重建一次、画面无跳变」（文件自己的注释），删掉它不损失任何东西。
   - 然后 `RewireLevelUpTargets()` 在 1.45 s 仍要跑（重指 `pulseTarget` / 两格可淡图），但**不再需要重指 `inheritChild`**（卡没被销毁）。
4. **光效层换父件**：`CardDisplayEffects.Build` 的父件改成主卡 `2DCard`（`cv.FaceRoot`，`internal`，`CardView.cs:2068`），并把换算改成 `s = 1`：
   - 建议**换一个重载**而不是改现有签名：`Build(Transform cardParent, float cardWidthPx)` 保留给旧调用方（若还有），新增 `BuildUnder2DCard(Transform twoDCard)` 内部直接 `s = 1`。
