结论（要害）：**`BroadcastRemoveFromGame` 的语义 = 「让其它所有卡撤掉『这条被移出游戏的东西』给它们的外来效果」**（ReactToUnitJammed 那一半），**它本身不设 `removedFromGame` 状态**；那个 `11` 状态是 `RemoveFromGameCard(self)` 的副作用，而**全库找不到以 self 方式调 `RemoveFromGameCard` 的点** ⇒ **state 11 这一支是死状态**。

## ② 我们现状（落点 + 差什么）

- **没有「移出游戏」状态**：`UnitState` 无状态位；`PlayerState` 只有 `Deck/Hand/Discard`（`RuleEngine/Core/PlayerState.cs:19-21`），无 removed 区。`CardInstance.cs:1` 头注释虽写「移出游戏」应存 `CardInstance`，但**无实现**。
- **残骸翻面路径存在但缺这一步**：`RuleCore` 的残骸分支（`RuleCore.cs` 里 `rem = new UnitState(...)` + `rem.ClearAllKeywords()` + `SweepHandEffectsOnRemoval` + `ps.Board[slot] = rem`，约 `:9820-9850`）**没有**「其它卡撤掉该单位给的外来效果」这一跳。原版对应的是 `_ResolveTransformIntoRemnant:32` 的 `BroadcastRemoveFromGame`（残骸翻面**可达**）。
- 与账 533 `BroadcastRemoveEffectsFrom` 的区别（⛔ 别混）：533 是「**按来源摘全部** extrinsic」（`ResolveRemoveEffectsFrom`，动作类型 0x2f=47）；637 是「**一个东西被移出游戏** → 其它卡撤它给的 extrinsic」，两者时机/入口不同。
- 「按来源撤 extrinsic」我们只有一半：`UnitState.RemoveExtrinsicEffectsFrom`（`UnitState.cs:2264`）只到「限时增益 + 记了来源的数值修饰」（F3 已在方法 doc 标）。

## ④ 怎么验 + 还差什么

- **验**：人造夹具 —— 一个带「给友军 +N」光环/附魔的单位 A + 一张被 A 加成的友军 B；让 A 走残骸翻面；断言 **B 身上来自 A 的 extrinsic 被撤、A 的残骸还在原位**。

# §4 · `721 CheckStun()`

## ① 原版做法（逐句 + 出处）

- **方法体**：`decomp_full/CardScript__CheckStun.c:1-23`；带字段名版 `cpp2il/out_cpp2il_dev_ilspy/CardScript.cs:16220-16228`：
  ```

      RemoveTrait(DefinedTrait.stun);
      CardUI.RemoveStatusAnim(DefinedTrait.stun);        // 撤状态框演出
      RemoveActiveEffect(DefinedTrait.stun);             // 撤「授予 stun 的那条 addTrait 效果记录」
  }
  ```
- **`RemoveActiveEffect(100)`**（`cpp2il CardScript.cs:16230+`）：倒序扫 `activeEffects(+0x108)`，摘掉 `trait == 100`（buffType `addTrait`）的记录 —— 即把「当初挂 stun 的那条 buff」一并撤。
- **调用点**：`BattleManager__ResolveTransformUnit.c:1629` 与 `BattleManager.__c__DisplayClass555_0___ResolveTransformFromRemnant_b__0.c:20` —— **都是「变回单位」那一刻**（含残骸翻回）。
- 语义 = 「**已经带 stun 的单位后来获得 unstunnable ⇒ 立刻摘掉 stun**」（stun 先到、unstunnable 后到的顺序）。

## ② 我们现状（落点 + 差什么）

- 有 `RuleCore.Unstunnable` 常量（`RuleCore.cs:5045-5074`）+ 共用判定 `StunBlockedByTraits`（`RuleCore.cs:5110+`），但只用于**施加前拦截**（`EffectResolver.DoStun` / 震荡）—— 即「**先有 unstunnable、再来 stun**」那一档。
- 回合末到期摘 stun：`RuleCore.cs:2679-2700`（`StunnedAtStartOfTurn && Has(Stun) ⇒ RemoveAll(Stun)`）。
- **缺**：`CheckStun` 这一支（**先有 stun、后获 unstunnable** ⇒ 立刻摘）。**没有**「变回单位时统一跑一次 CheckStun」。
- **现池可达性 = 沉睡**：现读 truth 全表 `trait 250 unstunnable` **命中 0**（无任何卡面/cardTraits/buff 授予它），`trait 100 stun` 3 处 ⇒ 今天不可观测（与账 721 的「池内 unstunnable 0 张」一致）。

## ③ 施工建议

| 改哪 | 加什么 |
|---|---|
| `RuleEngine/Core/RuleCore.cs`（新增 `static void CheckStun(UnitState u)`） | `if (u.Has(Stun) && u.Has(Unstunnable)) { u.RemoveAll(Stun, silent:true); u.MarkedStunRemoved…; 撤「授予 stun 的那条记录」; }`。`RemoveActiveEffect(100)` 的对应物 = 在 `ActiveEffects`（附魔层）里摘 `Trait == "stun"` 的记录（若 stun 来自附魔/记录）。表现层 `RemoveStatusAnim` = `TraitFrames.Remove("stun")`。 |

| 消费点（表现） | 若 `CheckStun` 真摘了 stun ⇒ 发既有 `EvtKind.TraitRemoved`（`CardId="stun"`，机制已在 `EffectResolver.EmitTraitRemoved`）—— 表现层已有 `TraitRemoved` 的框销毁路径；`RemoveStatusAnim` 也可由 `TraitFrames.Remove` 承担。 |

## ④ 怎么验 + 还差什么

- **验**：人造夹具（不依赖卡池，因为 unstunnable 全池 0）：单位 `AddKeyword(stun,1)` → 再 `AddKeyword(unstunnable,1)` → 调 `CheckStun` → 断言 `Has(stun)==false`、`TraitFrames` 里 stun 框被 `Remove`、`TraitRemoved` 事件发出。

  - `RemoveActiveEffect(100)` 的精确范围（原版扫 `activeEffects` 里 `buffType addTrait ∧ trait 100` 的记录）要逐条对齐我们的 `ActiveEffects`/`ActiveEnchantments` 记账 —— 未逐条核。

## ② 归不归 532？—— **不归**（判据）

| 维度 | 532 `ResolveRemoveEffect` | 483 `RemoveSelfBuffsFromQueues` |
|---|---|---|
| 触发 | 动作 `removeEffect(0x10)` 出队 | **残骸翻面**（`_ResolveTransformIntoRemnant:39`） |
| 做什么 | 摘**一条 effect**（`CardEffect`） + 撤**anim** cue（只 `playAnim=11`） + 帧特效 | **撤队列里的动作**（**所有 actionType**，除 45/26） |
| 队列过滤 | `CancelAnimFromUnitFromQueue`：只认 `actionType==0xB(11)` | `CancelEffectsFromDisappearingUnitFromQueue`：认所有类型，只排除 45/26 |
| 参数 | — | `shouldIgnoreDestroy:1`（= 排除 `0x2d` 一类，别当「被销毁」） |
| 族 | removeEffect 族 | **消失单位清队列族**（`CancelEffectsFromDisappearingUnit`，另有 `ResolveJamUnit`/`ResolveAction`/`ResolveTransformUnit` 也调） |

⇒ **483 是 238（`CancelAnimFromUnitFromQueue`）的兄弟，但更宽**（全 actionType vs 只 playAnim），且触发是「残骸翻面」而不是「摘效果」。**它不属于 532 四段里的任何一段**（532 的 ② 是 `CancelAnimFromUnitFromQueue`，不是这个）。⛔ 别把两条混成一条。

## ④ 怎么验 + 还差什么

- **验**：夹具 —— 排队里放「目标=card 的 playAnim 动作 + 目标=card 的其它动作 + 目标=别的卡的动作」，调 483 等价物 ⇒ 断言前两类被撤、第三类留；再验 `shouldIgnoreDestroy:1` 时 `actionType==0x2d` 那一类**不撤**。
- **还差什么（如实）**：
  - `actionType 0x2d(45)` / `0x1a(26)` **具体是哪两种动作**未核（要查 `BattleActionType` 枚举）；这决定排除组的准确边界。
  - 我们的「动作道」是 1 条 `_timeline`（表现）+ ActionPump 的道，原版是 4 条；撤「所有 actionType」在这两套模型上的等价性**未证**。
  - 483 与 532 是**两条独立账**：532 的阻塞仍是「②撤 anim cue + ③帧特效」两条（见 532 行 / `判据/T4_532与PremiumCampaign_判据.md`），483 的阻塞是「全类型撤 + shouldIgnoreDestroy」。⛔ 判 532 完成时别把 483 算进去。
