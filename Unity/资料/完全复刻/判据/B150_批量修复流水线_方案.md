## 〇 · 一页速查（照这个顺序做，别跳步）

```text
① 分诊    B149_审查_<片>.md  →  B150_待修_<片>.tsv      （每条判 机器可批 / 需人工实现 / 需拍板）
② 聚合    按【参数类别 × 文件】切  →  B150_施工单/<类别>_<批>.tsv   （7 列，apply_param_spec 的输入）
③ 闸门    --check-owners 查文件所有权  +  每份施工单先跑 --dry
④ 改值    --write --rollback-out  →  bash 工具/typecheck.sh（0/0）
⑤ 攒批闸  ruleprobe check · ruleprobe play check · 账闸（见 §五）
⑥ 灭自证  按 §六 补断言，期望值抄判据列
⑦ 人工类  按 §四 切块派写手（一个代理 3–5 件、按文件不按问题类）
```

**一句话边界**：这条流水线**只做「行内把一个值换成另一个值」**。
凡是需要**增删行、加分支、跨文件接线、调时序**的，一律走 §五 的人工通道 —— ⛔ 别硬塞进施工单。

## 一 · 分诊：审查产出 → 结构化清单

### 1·1 输入长什么样（B149 §五 已定）

`判据/B149_审查_<片>.md` 的逐条表：

| 原版类.方法 | 原版判据(文件:行) | 我们落点(文件:行) | 三态 | 差异或缺什么 | 可达性 | 建议 |
|---|---|---|---|---|---|---|

**只有 `缺` 与 `已实现未核` 两态进流水线**；`已对齐`（不需要改）与 `不适用`（原版本身没有）不进。

### 1·2 输出：`判据/B150_待修_<片>.tsv`（12 列，制表符分隔，裸 `split("\t")`）

| # | 列 | 定义 | 硬约束 |
|---:|---|---|---|
| 1 | `ID` | `<片>-<三位序号>`，例 `E1-007` | **全项目唯一**；下游施工单直接沿用这个 ID |
| 2 | `片` | `E1` `E2` … `A1` | 必须是 B149 §四 的 19 片之一 |
| 3 | `原版类.方法` | 例 `BattleManager.DrawCardFromDeck` | 必须能在 `B149_审查工单.tsv` 里对上 |
| 4 | `修复形态` | `机器可批` / `需人工实现` / `需拍板` | **封闭词表**，三种以外 = 分诊失败，退回重判 |
| 5 | `参数类别` | 见 §二 的八类 + `其他` | 封闭词表；聚合的分组键 |
| 6 | `文件` | 我们的落点文件 | 相对 `d:/4/Unity/MyGame/` 或绝对路径 |
| 7 | `锚点` | **能唯一定位到那一行**的连续字符串 | 单行内可见；`--dry` 实测必须恰好 1 次 |
| 8 | `期望旧值` | 该行现在含有的旧值 | 非空；新值里不许含换行 |
| 9 | `新值` | 要换成什么 | 必须**直接抄自判据**，不许自己算 |
| 10 | `判据出处` | `文件:行` 或 资产路径+字段 | **机器可批必须非空**（空 = 自证，工具直接拒） |
| 11 | `断言落点` | 哪个断言宿主/类覆盖这个参数，例 `Editor/BattleScene.cs:12345`；没有就写 `无（参数级无断言）` | 无断言的必须在备注写「补断言计划」 |
| 12 | `备注` | 自由文本 | 不许含制表符 |

> 🔑 **不设「行号」列**：行号会随别人改动漂移，锚点不会。行号只作提示，写进备注即可（`L187 附近`）。

### 1·3 分诊规则（机械可判，别用「感觉」）

先跑五条**机械测试**，全过才判 `机器可批`：

| 测 | 内容 | 不过怎么办 |
|---|---|---|
| T1 | **一行内可替换**：锚点 + 旧值都在同一行，替换后行数不变 | 需人工实现 |
| T2 | **单值确定**：判据里这个参数只有**一个确定值** | 判据写「按状态分档 / 视情况」⇒ 需人工实现（铁律 5·c） |
| T3 | **判据非空**：能看到 `文件:行` 或资产路径+字段 | 判据为空 / 两说并存 ⇒ `需拍板` |
| T4 | **锚点唯一**：`apply_param_spec.py --dry` 报 `OK` | 报「锚点 N 次」⇒ 加长锚点再试；仍不行 ⇒ 需人工实现 |
| T5 | **不涉架构**：不改变承载方式/层级/生命周期 | 属于 B150 §一 C 档 ⇒ `需拍板`（架构决定） |

`需拍板` 的三个固定触发（其余一律不许判拍板）：
① 判据为空或两说并存；② 与服务器/远端有关（§18·0）；③ 架构级 C 档（`B150_架构决策与任务清单.md` §一）。

### 1·4 分诊批处理

- **一片一个代理**（与审查代理同片，避免二次读上下文），只读 `B149_审查_<片>.md` + 回源核锚点。
- 产出**只写自己那一份** `B150_待修_<片>.tsv`，⛔ 不改审查文件、不改账。
- 每片分诊完**当场跑一次** `--dry`（§三），把 `OK / CONFLICT` 的数字填进该片的 `B150_待修_<片>.md` 头部
  —— CONFLICT 就是「这条其实不能机器批」的证据，按 §一·3 回退。

## 二 · 聚合：按「参数类别 × 文件」切施工单

### 2·1 八类参数（沿用铁律 21，⛔ 别再新造类名）

| 类别 | 典型内容 | 判据通常在哪 | 断了会怎样 |
|---|---|---|---|
| `版面尺寸` | 宽高、间距、锚点、字号框 | prefab YAML / `menu_rect` / `runtime_ui_dump` | 版面错位 |
| `色彩` | `_Color`、alpha、渐变角度 | prefab `m_Color` / 材质 / shader 属性 | 观感错、压暗层错 |
| `字体排版` | 字号、行盒、对齐、AutoFit | prefab TMP 组件 / 原版行盒 | 字溢出/看不清 |
| `动画时长与缓动` | 时长、曲线、延迟、顺序 | Animator / clip / 反编译常量 | 手感错 |
| `音频参数` | 音量、pitch、cue、冷却 | mixer / `AudioCue` 表 | 声音不对 |
| `输入阈值` | 拖拽阈值、点击判定、长按时长 | 反编译 `m_DragThreshold` 等 | 点不动/误触 |
| `排序与容量` | 排序键、Take/Skip、容量上限 | 反编译 LINQ 链 | 结果集不对 |
| `渲染队列与材质` | `renderQueue`、blend、stencil | shader / 材质 / `ImageQuad` | 遮挡关系错 |

### 2·2 聚合键与切分规则

- **一级键 = 参数类别**，**二级键 = 文件**。
- **一份施工单 = 一个类别 + 一个批次号**（例 `B150_施工单/输入阈值_01.tsv`）。
- 🔴 **同一文件**出现在两份施工单里 ⇒ **必须合并成一份，或改成串行** —— 这就是「文件所有权冲突」，
  用工具查（`--check-owners`），⛔ 别靠 `git status` 判（铁律：`git status` 是与 HEAD 的累积差异）。
- 跨类别但同文件：**能合就合**（一份施工单里放两类的行没问题，类别只是分组用的）；
  合不了就**串行跑**，先跑的那份 `--write` 完再跑第二份（第二份的 `期望旧值` 必须按第一份改完后的样子写）。

### 2·3 所有权冲突检测（已实现）

```bash
python -I -X utf8 d:/4/Unity/工具/apply_param_spec.py \
    --check-owners 施工单A.tsv 施工单B.tsv 施工单C.tsv
# rc=0 无冲突；rc=2 有文件落在多份施工单里（逐条列出）
```

出施工单**之后、派活之前**跑一次，5 秒。同时人工对一眼
`资料/完全复刻/文件所有权_当前.md` —— **工具只能看见施工单之间的冲突，看不见「已在飞的写手」**。

### 2·4 施工单的命名与存放（建议）

```text
资料/完全复刻/判据/B150_施工单/<参数类别>_<批号>.tsv
资料/完全复刻/判据/B150_施工单/<参数类别>_<批号>.rollback.tsv   ← --rollback-out 产物
资料/完全复刻/判据/B150_施工单/<参数类别>_<批号>.log.txt         ← 执行输出存档
```

### 2·5 施工单封面（每份必带三样：条数 / 文件清单 / 验收方式）

工具**跳过以 `#` 开头的行**（不是注释语法糖，是刻意留的封面口子）。所以施工单头部就这么写：

```text
# ── 施工单：输入阈值_01 ──
# 条数：23（机器可批 23 · 其中 2 条锚点待加长）
# 文件：Battle/CardInteraction.cs（9） · Deck/DeckRuntime.cs（7） · Shell/MenuScroll.cs（7）
# 判据：反编译 m_DragThreshold / m_ClickMaxMove / 原版 hover 阈值
# 验收：bash 工具/typecheck.sh 0/0 → ruleprobe check 差异 0 行 → 行为断言「6px 不触发 / 7px 触发」
# 回滚：<类别>_<批号>.rollback.tsv
# 表头（⇥ = 制表符）：
ID⇥文件⇥锚点⇥期望旧值⇥新值⇥判据出处⇥备注
...
```

三样缺一不可：**条数**（对账用）、**文件清单**（所有权用）、**验收方式**（闸用）。

## 三 · 批量改值：工具契约

### 3·1 命令

```bash
# 只算不写（每次都先跑这个）
python -I -X utf8 d:/4/Unity/工具/apply_param_spec.py <spec.tsv> --dry

# 真写盘（必须显式；默认行为是「打印用法 + rc=2」）
python -I -X utf8 d:/4/Unity/工具/apply_param_spec.py <spec.tsv> --write \
       --rollback-out <spec.rollback.tsv> --quiet

# 严格档：有任何 CONFLICT 就一个字节都不写（首次跑新类别时建议开）
python -I -X utf8 d:/4/Unity/工具/apply_param_spec.py <spec.tsv> --write --strict
```

`--root DIR` 指定相对路径的根（默认 `d:/4/Unity/MyGame`）。

### 3·2 五项硬校验（与输出三态一一对应）

| # | 校验 | 不过时 |
|---:|---|---|
| 1 | 锚点全文件**恰好 1 次** | `CONFLICT`（0 次 / N 次都拒，⛔ 绝不猜） |
| 2 | 锚点所在行**仍含期望旧值** | `CONFLICT`（文件已被人改过 ⇒ 不覆盖别人的改动） |
| 3 | **行数守恒**（只做行内替换；新值含换行直接拒） | `CONFLICT` |
| 4 | **行尾保持**（`\r\n` / `\n` / 裸 `\r` 三个计数逐一不变） | 整份文件拒改 |
| 5 | **可回滚性自检**：写盘前在内存里跑一遍反向施工单，必须逐字节回到改前 | 整份文件拒改 |

额外硬闸：**`判据出处` 为空直接 `CONFLICT`** —— 期望值必须来自原版判据，否则就是自证。

### 3·3 输出三态（逐条打印，⛔ 不汇总成一句「完成」）

| 态 | 含义 | 退出码影响 |
|---|---|---|
| `OK` | 五项全过，会改 / 已改 | — |
| `SKIP` | 良性跳过：新值 == 旧值 / 同单内完全重复 | 不影响 |
| `CONFLICT` | 无法定位或危险，只跳过这一条 | 有则 `rc=1` |

### 3·4 退出码

| rc | 含义 |
|---:|---|
| 0 | 全部 OK / SKIP，无 CONFLICT |
| 1 | 跑完了，但有 CONFLICT（`--write` 下 OK 的那些行已写） |
| 2 | 拒绝执行：用法错 / 施工单格式错 / `--strict` 下有 CONFLICT / 文件级拒改 |

### 3·5 回滚

`--write` 会打印每个文件的**改前/改后 sha16**，并把**反向施工单**写到 `--rollback-out`：

```bash
python -I -X utf8 d:/4/Unity/工具/apply_param_spec.py <spec.rollback.tsv> --write
```

三条要点：
- **反向施工单会连锚点一起换**（锚点常含旧值，例 `HudImageZ = 0.3f` → `HudImageZ = 0.5f`）
  —— 不换锚点回滚会整批 0 命中（自测第一版就撞上了，见 §九·四）。
- 回滚**行号守恒** ⇒ **不会冲掉同文件里别人的未提交改动**。
  ⛔ 别用 `git checkout -- <文件>` 回滚（会一并冲掉别人的活）。
- 回滚跑完自己也会产一份反向单（`回滚 X` 的前缀会叠），**用一次就丢**，别二次回滚。

### 3·6 执行纪律

1. 🔴 **同一时刻只有一个写手**：`--write` 只能由**调度台**在**没有 `.cs` 写手**时跑（铁律 13·3）。
2. 🔴 **先 `--dry`，后 `--write`**；`--dry` 的 OK 条数 = `--write` 的改动条数，对不上就停。
3. 🔴 **写完立刻 `bash d:/4/Unity/工具/typecheck.sh`**（0/0 才算过）。红了 ⇒ 用回滚单撤，别改代码去迁就施工单。
4. ⛔ **不许把 `--write` 并发跑**（同一文件两个进程 = 后写的静默盖掉先写的）。

## 四 · 人工实现类：切块派写手

### 4·1 什么进这一档

需要**增删行**的（加分支、加类、接线、调时序）、`锚点` 无法唯一定位的、以及 T2 不成立（一个参数有 N 个状态值）的。

### 4·2 切块规则（照铁律 13·3 / 16·7）

| 规则 | 做法 |
|---|---|
| **按文件切，不按问题类切** | 一个代理 = 一组文件的**唯一所有者**；原版类与我们的文件是多对多，按问题切必然撞车 |
| **一个代理 3–5 件** | 一轮做完接着下一件；⛔ 不「一件活一个代理」 |
| **白名单写到文件级** | 简报里列「✅ 可改 / ⛔ 绝对别碰」，黑名单含别的代理在改的文件 + 两张正本 |
| **热点文件独占** | `BattleDriver.cs`（4.2 万行、非 `partial`）、`RuleEngineTest.cs`（3.9 万行）一个代理独占 |
| **`Shell/ItemDrawer.cs` 只能往回加** | 新成员一律加在 `:2340` 之后（两个类都是 `partial`） |
| **撞车就交补丁** | 发现文件被占 ⇒ 把改动写成「可粘贴代码 + 应插哪一节 + 调用链自证」交回调度台，⛔ 别硬改 |

### 4·3 每个代理必须交的四样

`改动清单（文件:行）` + `判据出处（原版文件:行）` + `typecheck 结果（自己的 TMPDIR）` +
`账补丁 账/_parts/B<批>_<代号>.tsv`（11 列、首行表头、`方法` 列是完整签名带 `(...)`）

> 代理跑 typecheck 用**独立 TMPDIR**：`TMPDIR=/tmp/wf_x1 bash d:/4/Unity/工具/typecheck.sh`
> （固定路径会互相覆盖；而且别人的半成品文件会被一起编进来 ⇒ 报错集中在**不是你负责的文件**上就不是你的问题）。

### 4·4 一条硬口径

> **执行代理不是「照施工单交差」的机器**：判据与 `.c` 冲突、或判据本身自相矛盾时，
> 正确动作是**零代码改动 + 写清反证**交回来（B9_W69ENG4 的样板），⛔ 不是硬做。

## 五 · 回归闸：跑什么、什么时候跑

### 5·1 三档节奏（⛔ 别每改一条就跑全套）

| 时机 | 跑什么 | 判绿 |
|---|---|---|
| **每次 `--write` 之后**（秒级） | `bash 工具/typecheck.sh` | 两行「错误数: 0」 |
| **每批施工单跑完**（一个类别 / 5–10 份） | `bash 工具/ruleprobe.sh` | `解析差异 0 行` **且** `哨兵合计：失败 0 条`（⚠️ 两个都要看，`rc` 由两者相加） |
| **同一批** | `bash 工具/ruleprobe.sh play check` | 逐卡差异 0 + 哨兵 0（结算层指纹） |
| **同一批** | `python -I -X utf8 工具/check_ledger_points.py --all-A` | 漂移 0 / 失败 0（我们行数守恒 ⇒ 本来就该 0；红了先怀疑**别人**动了行） |
| **同步点**（主场域一批收口） | 受影响的 `-executeMethod` 宿主，按覆盖面挑；跨面才 `bash 工具/_run_8_checks.sh` | 按各宿主的「断言合计」行判，⛔ 不看退出码 |

### 5·2 为什么「行数守恒」让账闸自然绿

账按 `文件:行号` 引用落点。本工具**只做行内替换**（校验 3 硬保证）⇒ 一个 A 行落点都不该漂。
**账闸红了 = 有别人动了行**，先查 `git status` 里同文件的其他改动，⛔ 别跑 `--fix` 把别人的漂移记到自己账上。

### 5·3 指纹基线的用法

改值前后各跑一次全池真打，比**变化卡数**：

```bash
bash 工具/ruleprobe.sh play all dump _tmp_view/b150_before.tsv
# …改值…
bash 工具/ruleprobe.sh play all dump _tmp_view/b150_after.tsv
```

期望：**变化行数 == 施工单里预期受影响的卡数**（施工单 `可达性` 列给的数字）。
多了 ⇒ 有副作用（典型：光环重算、费用重登记）；少了 ⇒ 改的地方根本没被消费（**消费者链断了**）。

### 5·4 ⛔ 什么时候一条都不跑

纯文档（`.md`）/ 纯工具（`工具/*.py`）改动 —— 一条都不用跑。

## 六 · 灭自证：批量改值后必须补的断言

### 6·1 三条铁规

1. **期望值只能抄 `判据出处`**（原版 `文件:行` / 资产路径+字段），⛔ 不许从我们代码里回读常量
   —— 那等于「拿我们的实现证明我们的实现」。
2. **一条值断言不够**：值改了、消费链断了，值断言照样绿。
   必须再补一条**消费者可见**的断言（派生量 / 交互结果 / 渲染输出）。
3. **反向验证**：手工把值改回旧值，断言必须**变红**（改回去还绿 = 断言没接上或恒真）。

### 6·2 三种断言形态（按参数类别挑）

| 形态 | 适用 | 写法要点 |
|---|---|---|
| **值相等** | 常量、队列号、尺寸 | `Check(Math.Abs(X - 0.3f) < 1e-4f, "…")`，注释写死判据 `文件:行` |

| **行为** | 阈值、拖拽、点击 | 用合成事件断「6px 不触发 / 7px 触发」这类**边界两侧**，⛔ 只断一侧 |

## 十 · 验收判据（这批流水线算不算「做成了」）

1. 一份真实施工单（≥20 条）跑 `--dry`：`CONFLICT` 条数 ≤ 10%，且每条 CONFLICT 都能说出为什么。
2. `--write` 后：`typecheck` 0/0 · 账闸漂移 0 · 每份文件行数与行尾计数不变。
3. 回滚单能把这批**逐字节**还原（sha 全部回到改前）。
4. 至少一条断言做到「手工改回旧值 ⇒ 变红」（反向验证留证据在报告里）。
5. 改动条数 == `--dry` 的 OK 条数（不多不少）。

## 十一 · 不做（防范围膨胀）

- ⛔ 不做跨行 / 正则 / 结构化（AST）替换 —— 一旦引入 AST，就得处理格式、注释、语义等价，收益远小于风险。
- ⛔ 不自动改账、不自动改断言、不自动跑 Unity。
- ⛔ 不把「需人工实现 / 需拍板」强行降级成机器可批（那是把人工判断变成静默错误）。
- ⛔ 不追求「一次把所有 5,846 个方法都批量改完」—— 审查还没走完，流水线先小批跑通再放大。
