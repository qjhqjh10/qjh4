## 二、三层推进

> 🔴🔴 **2026-11-03 加一条前提警告（`G8` 实测）：原版 prefab **不等于** shipped 实拍。**
> 卡名 `fontSize` 口径：原版 prefab = `font/卡宽 9.08%`，而**发行版实拍 = 6.86%（小 24%）**；我们是 **9.09%（与 prefab 逐像素一致、与实拍差 +32.5%）**。
> ⇒ **prefab 只能当结构尺子（层/锚点/父链/显隐），当字号尺子会错 24%。** 涉及「看起来多大多小」的量，一律**以实拍为准**（铁律 4 实况优先）；两者打架时**不许调和**，照实拍改并在判据里注明。
> 另一条：`B117_G5_战斗HUD层差异.tsv` 的两侧都是**原版**（静态 YAML ↔ 运行时 dump），「仅我们有」应读作「**运行时新建**」，⛔ 不是我们实现的独有节点。

### 第 1 层 · 建尺子（工具化，先做）
`工具/prefab_layer_diff.py`：
- **原版侧**：`d:/2/tools/assetripper_out/ExportedProject` 的 `*.prefab` / `*.unity` YAML。
  ⚠️ 判根 = `m_Father: {fileID: 0}`；兄弟序按**父的 `m_Children`**（Unity 2023+/6 已删 `m_RootOrder`）；⛔ 不按 pathID / 树次序配对（AssetRipper 会重排子节点）；`assets_full` 同名多份是常态。
- ~~**我们侧**：运行时 dump（`资料/原版参照图/Unity参照管线_0825/data/runtime_ui_dump_*.tsv`）~~
  🔴🔴 **2026-11-03 就地订正（`G5` 现核）：那份 dump 是【原版游戏自己】的**（`SceneJumpShot` mod · 2026-08-25 · 根节点 `BattlePrefab`，与 `Battle Arena 1.unity` 同一棵树），**不是我们的实现**。拿它当「我们侧」写进简报是错的。
  而**我们的战斗 HUD 没有任何可机读的树**：`CardPresentation/Scenes/Battle.unity` 只有 **31 个 GameObject**（Slots / PlayerBoard / AttackSelector / SkillPanel / Arena3D / 相机），HUD 全是运行时 `.cs` 建的（`grep BattleHud --include=*.cs` = **576 处**），工程里也没有 HUD prefab 或树 dump。
  ⇒ **「原版 ↔ 我们」的真差异表还差一份【我们侧的树】**。补法很便宜：加一个编辑器 dump 宿主，吐同样的 15 列 TSV，工具不用改、一条命令就出真 diff。
  ⚠️ 那张原版 dump 的表头列名**错位**，真实 15 列依次为 `anchoredPosition / sizeDelta / anchorMin / anchorMax / pivot / …`（判据 `d:/2/Warpforge_tools/scenejumpshot/SceneJumpShot.cs:41-49`）；且 `text` / `fontSize` 两列**整组失效**（324/324 全空 / 全 0），本次**一条文字都没比过**。
- **输出**：`层路径 | 属性 | 原版值 | 我们值 | 判定 | 两边出处`，按**节点路径**对齐；对不上就标「仅原版有 / 仅我们有」，⛔ 不硬配。

## 四、每域固定六步（本项目成功过七次的做法）

1. **原版层表** —— 该窗口在原版 prefab 的全部节点（按脚本反查 `m_Script.m_PathID` → `m_ClassName`，⛔ 别按名字搜）
2. **我们的层表** —— 对应节点（运行时 dump / 代码常量）
3. **逐格比** —— rect / 锚点 / 轴心 / 字号 / 颜色 / 渲染队列 / 显隐条件 / 父链，**每格带出处**，没出处写「？」
4. **按差异改** —— 一次一个域，改完跑 `typecheck` + 账闸
5. **一条断言一条差异** —— 先 `Check(前提)` 再 `Check(结论)`；灭自证（改回旧写法必须红）
6. **真机复核** —— 截图放 `_tmp_view/shots/<日期_会话>/`
