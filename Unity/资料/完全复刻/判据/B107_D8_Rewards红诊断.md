  - 同一段上面 **`rewards.log:58057` 那条是绿的**：`✓ ★ 顶点 2：x' = x + y·skewX（skewX = 0.5）（2.31 ≈ 2.31±0.00）`

  - 量纲来源：`Core/LayoutSpace.cs:211` `Px(px) = px / (1080/10)` = **px ÷ 108**；
    `Battle/ImageQuad.cs:113-114` `WorldH/WorldW`、`:474` `RebuildMesh` 的 `x0 = -anchor.x*w`；
    夹具 `B107_W15_Assert.cs:213` 的 `PxRect(100,100,500,300)` = 400×200 px

  「实现空转 ⇒ 差恰好 0 ⇒ 仍红；真 shear ⇒ 0.463 ⇒ 绿」，灭自证语义不变。
  也可写相对式：`> Mathf.Abs(va[topRight].y * 0.5f) * 0.5f`（推荐前者，更简单）。
- **还差什么**：无。判据链完整（公式断言已逐位钉死；这条只是「非零」的冗余保险）。

## 排除 β（接线/实现缺陷）的依据

1. **`MenuDraw.Rect` 确实把 skew 传下去了**：`Shell/MenuDraw.cs:1627` 形参 `skewX/skewY`；
   `:1693` `if (skewX != 0f || skewY != 0f) quad.SetShear(skewX, skewY);` —— 且它排在
   `Create`（`:1677`）/ `SetAspect`（`:1680`）/ `SetRenderQueue`（`:1681`）/ `SetUvRect`（`:1683`）/ `SetTint`（`:1684`）
   **之后**，是最后一步，**没有任何后续调用把它覆盖回去**。
2. **`SetShear` 是 CPU 侧顶点变换，不是 shader 参数**：
   `Battle/ImageQuad.cs:457-462` 存字段后调 `RebuildMesh()`；`:472-503` 里 `:486` 先建 4 个顶点，
   `:488-494` 逐顶点做 `x' = x + (y + _skewOffY)·_skewX` / `y' = y + (x + _skewOffX)·_skewY`
   —— 与 `SkewedImage__OnPopulateMesh.c` 的原版公式一致（偏移项是九宫子块的超集，已标 `🔶 自己设计`）。
   `_skewX/_skewY` 是持久字段 ⇒ 之后任何一次 `RebuildMesh()` 都会重新施加，不会被抹掉。
3. **日志本身是最强反证**：同段 8 条公式断言（`rewards.log:57989-58108`）全部 `±0.00` 通过；
   若接线断了或顶点没动，这 8 条会先红。
4. **量纲一致性**：原版在 uGUI 局部空间（1 单位 = 1 px）做 shear；我们顶点在世界单位（1 单位 = 108 px），
   而 `x' = x + y·k` 是齐次线性式，**统一缩放不变** ⇒ 0.463 世界单位 = 50 px（顶部 100 px 位移的一半高度）正是原版值。
