# B143 · 回放 + 共享随机流契约（施工单）

> 只读查判据代理 `B143-R1` · 2026-11-05 · 消费者 = 调度台 / 同步点写手
> ⛔ 本文件不改源码、不跑 Unity、不动账。

## 〇 · 一页结论

- **现状**：录像存的是「起始条件（`MsgStart` + 几张表头字段）+ 动作流（`MsgAction[]`）+ 两种逐动作指纹」，**完全没有随机游标 / 消耗次数**。唯一的随机信息是 `MsgStart.seed`（能重烧同一张表，但**不知道谁消耗了几格**）。
- **为什么必须有补丁**：AI 若改吃共享表（`B134-AI 随机流`），录制时 AI 评分/选目标/挑环境卡都会推进 `RandomNumbersIndex`；而**回放不重跑 AI** ⇒ 录制时被 AI 吃掉的格在回放里没人补 ⇒ 从第一个 AI 动作之后的第一次引擎抽卡起分叉。
- **最小补丁**：`ReplayRecord` 加**两条逐动作 `int[]`**（执行前 / 执行后的 `ctx.RandomNumbersIndex`）；录制端在「把动作交给引擎之前」抓一格、在现有 `trace.Add` 那个程序点抓一格；回放端在 `ApplyReplayActionAt` 里**落地前按 `before[i]` 恢复**、**落地后按 `after[i]` 断言**。
- **旧录像**：缺键 ⇒ `null` ⇒ **不恢复、不判**，行为逐字不变（会出声「本层没做」，⛔ 不是静默通过）。**但**若同批改了随机流语义（掷硬币 / AI 走共享表），旧录像本来就会演成另一局 ⇒ 那时必须 `version 5→6` 并**拒绝**旧档（既有纪律）。
- **联机**：`NetProtocol.StateHash` **不含** `RandomNumbersIndex`（现读确认，见 §5）⇒ 加游标**不影响协议/指纹**；反过来说，游标分叉也**抓不到**在指纹里 —— 所以必须单独立断言（§4）。

## 3 · 补丁设计（最小改法）

### 3·1 数据形状（只改 `ReplayRecord`，⛔ 不动 `MsgAction`）

`ReplayStore.cs` 的 `ReplayRecord` 里追加**两条纯新增 `int[]`**（放在 `traceFull` 后面，`version` **不动** —— 理由见 3·5）：

```csharp
/// <summary>逐动作【执行前】的预烧表游标：randomCursorBefore[i] = 第 i 条动作交给引擎之前那一刻的
/// `ctx.RandomNumbersIndex`。`null` = 老录像没记（本层不做，出声）。</summary>
public int[] randomCursorBefore;
/// <summary>逐动作【执行后】的游标，采集点与 `trace` / `traceFull` **同一处**（动作落地之后）。
/// 回放用它做「消耗格数逐条相等」的断言（`randomCursorBefore` 恢复之后不能拿它自证）。</summary>
public int[] randomCursorAfter;
```

- **不进 `MsgAction`**：那个结构同时是**网络协议**（`NetKind.Action/Applied` 发整个 `MsgAction`）⇒ 加字段 = 把游标送上网络（与 `oathRecorded` 的先例相反，那条是因为原版就随动作走）。
- 体积：每条动作 2 个 int ⇒ 200 条约 **+1.6 KB**（现读一局 ≈9 KB）⇒ 可接受。若要更省，可只在 `randomCursorAfter` 存**增量**，⛔ 不建议（值域小但多一层换算，容易错）。

### 3·2 录制端（`BattleDriver`）

1. 字段（加在 `_rec` 附近，`:587` 那一带）：
   ```csharp
   int _preActionCursor;                                  // 本条动作交给引擎之前的游标
   readonly System.Collections.Generic.List<int> _recCursorBefore = new System.Collections.Generic.List<int>();
   readonly System.Collections.Generic.List<int> _recCursorAfter  = new System.Collections.Generic.List<int>();
   ```
2. `RecBegin`（`:753`）里清表：`_recCursorBefore.Clear(); _recCursorAfter.Clear();`
3. **抓「执行前」**（在把动作交给引擎之前那一刻）——五类：
   | 动作类 | 抓在哪 |
   |---|---|
   | 玩家 | `LocalAct` **第一句**（`:284` 之后、`apply()` 之前）：`_preActionCursor = Ctx != null ? Ctx.RandomNumbersIndex : 0;` |
   | AI | 在 `SimpleAI.ExecuteAction` **入口**（`SimpleAI.cs:1659` 的 `ExecuteActionCore` 调用**之前**）加一个 **pre 钩子**：<br>`public static System.Action<BattleContext, AiAction> BeforeExecute;`（`:1653` 那族同款）<br>`var pre = BeforeExecute; if (pre != null) pre(ctx, a);`<br>驱动在 `Begin` 里与 `Executed` 同批挂：`SimpleAI.BeforeExecute = (c,_) => { if (c == Ctx) _preActionCursor = c.RandomNumbersIndex; };`（挂点 `BattleDriver.cs:5581` 那一行；摘点在 `DetachStaticHooks`，同 `Executed` 的 `:4264`） |

   | 权威流 | `ApplyLoggedAction` **入口**（`:355` 第一句，`NetApply.Apply` 之前）：`_preActionCursor = Ctx.RandomNumbersIndex;` |
   | 伪动作（换牌/环境卡/投降/延迟抽牌…） | 在每个「引擎调用」前抓：`:9051 RuleCore.Mulligan` 前 · `:9124 RuleCore.Mulligan`（玩家）前 · `:9128 RuleCore.EndMulligan` 前（→ `:9129 RecRaw(MulliganDone)`）· `:9696 RuleCore.ChooseOffensiveCard` / `:9725 RuleCore.ChooseDefensiveCard` 前（→ `:9631 RecRaw`，经 `LogAndSendEnvPick`）· `:496/:537/:12682 RuleCore.Forfeit` 前 · `:14693 RuleCore.ResolvePendingTurnDraw` 前 · `:18305 RuleCore.CheckWinner` 前（不抽随机，记当前值无害）。**聊天** `:6947/:7288`：直接 `_preActionCursor = Ctx.RandomNumbersIndex;`（不消耗） |
4. **落盘**：在 `RecAct`（`:824`）、`RecRaw`（`:846`）、`RecMsg`（`:885`）里，与 `_rec.actions.Add(...)` **同一处**各加两行：
   ```csharp

   _recCursorAfter.Add(Ctx != null ? Ctx.RandomNumbersIndex : 0);
   ```
   ⚠️ 必须在 `RecordFullTrace()` **之后/同点**（那个点才是「动作已落地」）。
5. **收尾**：`RecFinish`（`:913`，`_rec.finalHash = …` 之后）：

## 4 · 验收断言

1. **既有**：`finalHash`（`NetProtocol.StateHash`）相等 —— 已有，不动。
2. **新（推荐，非自证）**：**逐动作游标相等**
   ```csharp
   Check(driver.ReplayCursorDivergenceForTest < 0,
         "★ 回放逐动作游标一致（第 " + driver.ReplayCursorDivergenceForTest + " 条起分叉）"
       + "｜🧨 把任意一条的 randomCursorAfter 改成 +1 / 让某条动作多掷一次 ⇒ 红");
   ```
   - 放在 `Editor/BattleScene.cs` ⑨ 节现有回放断言（`ReplayDivergenceForTest < 0`）**旁边**。
   - **灭自证**：测试里手工把录像的 `randomCursorAfter[k] += 1`（再存盘）⇒ 必须红；把 `randomCursorBefore[k] += 1` ⇒ 必须**红**（因为恢复错了位置，`after` 也就对不上）—— 两条方向都要红。
3. **补一条「老档不静默」**：`randomCursorBefore == null` 时，`PlayReplay` 必须打 warning；断言读 `ReplayCursorLayerSkippedForTest`（新加只读口）= true。

## 5 · 风险

| 风险 | 结论 / 处置 |
|---|---|
| **旧录像** | 本补丁单独 = 兼容（null ⇒ 不判）；**与随机流改动同批 = 必须 `version 5→6` + 拒绝**（§3·4） |
| **联机两端一致** | `NetProtocol.StateHash` **不含** `RandomNumbersIndex`：全仓搜 `RandomNumbersIndex` 只命中 `BattleContextRandom.cs` / `EffectResolver`（面板推演），`NetProtocol.cs` 0 命中 ⇒ 加游标**不改协议、不改指纹**。反过来说：**游标不一致 StateHash 也看不出来** ⇒ 只能靠 §4 的专用断言（回放侧）；联机侧不新增断言（两端本来就不同步这张表的读数，公开它反而会误报） |
| **AI 在联机局** | `_net != null` ⇒ AI 不驱动（`AiShouldDriveOpponent`）⇒ §1 的 AI 改造**不影响联机**；联机只受掷硬币那一格影响（两端同 seed、同 `drawFirstSeat` ⇒ 同步） |
| **录像体积** | +2×4 字节/动作（约 +1.6 KB/200 条）⇒ 可忽略 |
| **`_preActionCursor` 漏抓** | 漏一处 ⇒ 那类动作恢复错位 ⇒ **`after` 断言当场红**（不会静默）；但**若漏抓与多掷恰好抵消**则测不出 —— 灭自证第 2 条覆盖单点改错，覆盖不了「两处同时错」，如实记 |
| **`RecMsg` 双记** | 本机动作的 `NetKind.Applied` 带 `preApplied = true` ⇒ 不落地、不 `RecMsg`（`ReplayStore.cs:879-882` 已核）⇒ 不会双记游标 |
