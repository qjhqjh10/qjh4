## 2. 原版算式（逐句）

### 2.1 触发：`UpdateWhileInPlay` 重跑 240

`CardScript__UpdateWhileInPlay.c:12-17` → `RawCardScript__UpdateWhileInPlay.c:14/:17`：
```
TriggerAbilities(0x14 = 20)
TriggerAbilities(0xf0 = 240)
```
两行**只有这两句**，**没有任何「先清除上次效果」的动作**。
呼叫链：`BattleManagerSupport.BroadcastWhileInPlay`（`cpp2il/…/BattleManagerSupport.cs:870-940`）遍历
① `unitsInPlay` → ② 当前行动方手牌 → ③ 对手手牌，逐张 `HasWhileInPlayAbility()` 为真就 `UpdateWhileInPlay(...)`。
⇒ **手牌里的这 4 张每遇到一次广播都会重跑 240**（与 W1 报告 §3b 的读法一致）。

### 2.2 应用：`PlayAbility` 的 `ca 30/40` 支把 `changeCost` 挂到卡上

`AbilityLogic__PlayAbility.c:180-236` 定重复次数 `local_178`：
- `multiplier.targetsAffected == 0 (any)` ⇒ **1**；
- `== 0xd2 (210)` ⇒ 遍历目标、**累加** `GetCurrentTraitValueWithModifiers(unit, multiplier.traitsFilter)`（`:207-232`）；
- 其它 ⇒ 目标表长度（`ta=50` 即「筛出来的手牌张数」）；
- 末尾 `if (0 < furtherMultiplier) local_178 *= furtherMultiplier`（`:235`）。
随后每轮对 `ta=20 self` 目标逐张 `AddEffect` 一条 `buffType=2 / costChange=-1`。

### 2.3 读取：`get_CurrentCost`

`decomp_full/EntityScript__get_CurrentCost.c:43-91`：
- 遍历 `activeEffects(+0x108)`，`buffType(+0x38) == 2` ⇒ `Σ costChange(+0x68)`（`:49-51`）；
- `buffType == 0x5f (95 setCost)` ⇒ `iVar2 = setCost.costChange`，然后**重扫整表把所有 `buffType==2` 再加一遍**，`clamp0` 直接 `return`（**不加 base**，`:52-82`）；
- 没有 setCost ⇒ `clamp0(manaCost + Σ)`（`:85-91`）。

⇒ 净算式：
```
无 setCost： cost = clamp0( manaCost + Σ changeCost )
有 setCost： cost = clamp0( setCost.costChange + Σ【全部】changeCost )
```

## 3. 我们的算式（`RuleCore.CostOf`）

`Core/RuleCore.cs:1011-1057`：

  + Σ CostPerKeywords     (Delta × Σ KwValue(kw) over 本方/敌方棋盘)

🟠 **只在某些局面等价**。反例链条：
1. `GSC39 Lying in Wait`（`GSC39`，Genestealer Cults，tactic，2 费）卡面 = `Return a friendly troop to your hand and reduce its cost to 1`；
2. `GSC37 Patriarch` 的 `cardType = 0 (minion)`、`subtype = Infantry` ⇒ 是「friendly troop」⇒ **可以被它回手**（同阵营，牌组合法）；
3. 回手后原版会给这张卡挂 `setCost(95, costChange=1)`；`get_CurrentCost` 的 setCost 支**仍会把 240 那条 `changeCost(−敌方手牌数)` 加进去**（§2.3 第二行）；
4. 我们的 `CostOf` setCost 支（`RuleCore.cs:1056`）只算 `setTo + Σ CostMods`，**把 `v` 里那三项静态降费整项丢掉** ⇒ 恒为 1。

> 📌 反向可达性核查：`GSC39` 是 **GSC 阵营**（与 GSC37 同阵营，牌组可放）；另一张 `TAU68 Trail Shaper`（`Rally: Return a friendly Infantry to your hand. Lower its cost to 1`）也能选 GSC37，但 TAU 与 GSC 不同阵营 ⇒ **实战不可达**；第三张 `TL69 Neurotyrant` 的 setCost 指向自造的 Ephemeral 复制，不落在 GSC37 上。⇒ **唯一可达路径 = GSC39 + GSC37**。
> ✅ **前提已核（2026-11-05 复读 `decomp_full/CardScript__ResetToValuesInHand.c:26-33`）**：回手会**清空 `activeEffects(+0x108)`**（列表长度置 0 + 数组 Clear）⇒ 240 那条 `changeCost` 被抹掉，之后在**下一次** `BroadcastWhileInPlay`（任何单位进场都会触发）里重挂。
> `BattleManager._ResolveRecallToHand_d__542__MoveNext.c` 只调 `ResetToValuesInHand`（`:188` / `:255`）与 `BroadcastCardReturnedHand`（`:74` / `:77`，后者只转发 `OnCardReturnedHand`），**自己不调 `BroadcastWhileInPlay`** ⇒ 回手那一瞬两者都 = 1；差 1 出现在**后续广播之后**（原版 0 vs 我们 1）。
> ⚠️ 顺带如实标：我们 `CostOf` 是**每次现算**、不等广播 ⇒ 会在「回手后、下一次广播前」这一小段**比原版早生效**。这是既有口径差（补丁前就存在），不是本次改动引入。

## 5. 更深的一条：原版 240 的重复应用是**累加**的（未验证）

`CardScript__AddEffect.c:316-395` 的 `switch(iVar16)`，`case 1: case 2: case 10:` 走同一支
（`1 = addStats` · `2 = changeCost` · `10 = changeAbilityCost`）：

```
遍历 activeEffects，找到「enchantingCard / buffType / 0x78 / 0x7c / 0x80 / 时序」全同、且 newEffect+0x75==0 的那一条
  ⇒ bVar2 = true
     existing.meleeAttackChange(0x48) += new.meleeAttackChange
     existing.rangeAttackChange(0x50) += …
     existing.healthChange    (0x60) += …
     existing.costChange      (0x68) += …      ← 我们关心的这一格
if (!bVar2) activeEffects.Add(newEffect)
```

⇒ 同一条 `changeCost(-1)` **不会取代**旧值，而是**把旧值再减 1**。配合 §2.1「每次广播都重跑 240」，原版在多次 `BroadcastWhileInPlay` 之后应当**越打越便宜**（直到 clamp 0），与卡面「1 less per X」的稳定语义不符。
这看起来是**原版自身的缺陷/实现细节**，但本笔**没有实况验证**（原版已关服；离线客户端要跑起来才能验，属另一批工作）。
📌 **它不改变「不接 240」的裁定**：不接时我们给的是稳定值；接上 240（哪怕原样复刻）也还需要复刻这一层累加语义才叫「照抄」，那是**另一条账**（见 §6）。

## 6. 裁定与施工面（⛔ 本笔不改代码）

| 问题 | 结论 |
|---|---|
| **要不要接 240？** | **不接**（W1 裁定成立）。接了 = `CostOf` 已给的 −N 之上再加 −N ⇒ **双计**，且只影响这 4 张（静默）。 |
| **接了会不会双计？** | **会**。`CostOf` 现在每次现算的三项就是这 4 张 240 行的等价物（逐值见 §4）；再让手牌 240 真跑一遍 `ca 30/40 buffSelf` 就是第二笔。 |
| 有没有需要修的既有偏差？ | 有 1 条，**2026-11-05 已修**（`B143-R3`）：`Core/RuleCore.cs:1056` 的 **setCost 分支** 由 `(setTo >= 0 ? setTo : v)` 改为 `(setTo >= 0 ? setTo + (v - c.Cost) : v)`（`v - c.Cost` = 三项静态降费之和）。`play check` rc=0、指纹 `2f640db5…` 与基线一致（电池不构造该局面 ⇒ 逐卡差异 0 属预期）。⚠️ 只在「`setCost` 命中这 4 张」时可见（现读唯一可达 = GSC39→GSC37）。 |
| 原版 240 的累加行为要不要复刻？ | **需要独立裁定**，不是「接 240」一行能解决：我们的引擎没有 `CardScript.activeEffects` 这一层，手牌效果挂在 `CardInstance`（`HandBuff*`）。要做只能另立一条账「手牌 `changeCost` 的挂载/清除/累加模型」，并按铁律 11 先查清「原版到底是不是真累加」（实况或更深的 `AddEffect` 复读）。 |
