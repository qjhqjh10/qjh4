## 五、风险清单（逐条给反证/验证办法）

1. **`Camera.main` tag**：原版板相机 = MainCamera、UI = UICamera；**我们已对调好**（`Scenes/Battle.unity:941 m_TagString: UICamera`；板相机 `MainCamera`）。阶段 2 改相机位置时 **⛔ 别顺手改 tag**。验：`B139_S_CameraSerialized_Assert`。
2. **射线帧**：`TargetReticle.ResolveAim` 双平面求交（`hudCam`+`boardCam`）· `BoardLayout.DropTargetWorld → ScreenToWorld`。帧根一加，反投影结果变成**帧局部**。验：`BattleScene` 落点断言 + 真机拖一手；反向验证 = `HitSlotByBoardRay`（走板相机）**不该变**。
3. **`ImageQuad` 世界空间 vs Canvas（结合 `B146-C10` bit5）**：板相机掩码 1137 含 bit5。`ImageQuad` 全文 **0 处 `.layer` 赋值**（`Battle/ImageQuad.cs:134` 只 `AddComponent<MeshRenderer>`）。**阶段 1 期间 HUD 仍在 z≈0（离板相机 13.7 单位）** ⇒ 若此时把 quad 迁到层 5，会被**两台相机各画一遍**（尺寸/透视完全不同）。**阶段 2a 之后** HUD 落在 z=+81（板相机看 −Z、根本不覆盖）⇒ 风险自动消失。验：Frame Debugger 数 draw call。顺序按 `B146-C10`：**先 UI 迁 5、再场地迁 0**。
4. **URP 深度/后处理**：UI 相机是 **Overlay**（`UniversalAdditionalCameraData.m_CameraType: 1`）、板相机是 Base。HUD 落到 z=+81 后远离板相机；若 Overlay 保留深度测试，HUD 可能被场地遮挡。验：截「HUD 在最前」的图 + Frame Debugger 看 ZTest。兜底：Overlay 上开深度纹理 / URP 里 ClearDepth。
5. **`DeckRuntime.cs:1280` 的另一个 `Apply`**：卡组编辑器不属 C-09，⛔ 别把 `ApplyPerspectiveHud` 挂过去（会把卡组窗整体缩 0.687）。
6. **21:9**：`ScreenAspectRatioController` 只在 `>2.4444` 或 `<1.3333` 时加黑边 ⇒ 21:9（2.333）**在区间内**，画布 2560×1080、`VisibleWidth 23.704`。`HudCanvas.MakeImage` 的锚点 = `cx/1920`（**中心锚**）⇒ 宽屏下件会随宽度散开（= Expand 行为）。验：21:9 截一张，看两侧面板是否贴边。
7. **批处理分辨率**：`Core/LayoutSpace.cs:175` 记「实测 `Screen.width/height = 640×480`」⇒ 自检跑的是 **4:3**，阶段 1 的「16:9 恒等」**在自检里验不到**。⚠️ 那条是 2026-10-14 读数，**先现测**；必要时给宿主显式设分辨率。
8. **手牌量纲桥（`0.13736 → 1`）**：同时影响 `DragTargetOffset`(0.2 单位) · `HandSnapNearD2/FarD2` · `lookToDistance`(74.5) · `AutoCardRotation.OriginalUnitsPerOurUnit` ⇒ **必须同批**。
9. **`PickUpScaleFactorFor` 双乘**：透视下若忘了翻分支，会「又乘 0.9215 又吃透视」⇒ 拖起的卡小 8%。验：`B120_W1_Assert` G2 + 真机拖起。
10. **z 排序退化**：z 压到 0.03 后同队列透明件几乎等距 ⇒ 排序退化。先确认层序已由 `renderQueue` 承担（`MarkerQ 3100` · 日志 4000 · 窗 3600+）再压。验：16:9 截屏 + 逐个面板开关一次。
11. **遮罩/裁切**：`Shell/ViewportClip.ClipPx` 与 `MenuDraw.QuadRectPx` 走 `ToDesignPixel`（`PxPerWorldX` 用实测 `VisibleWidth`）⇒ 换帧后**仍自洽**（同一斜率），但 `RectMask2D` 框是设计 px ⇒ 与 uGUI 件一致。验：4:3 下开一次卡牌展示窗（它有视口裁切）。
12. **震屏（🔴 最容易被忽略的一条）**：`CardFeel.ShakeCamera(cam, hudRoot, …)` **同时推 HUD 相机与 `hudRoot`**（`Core/CardFeel.cs:1395` 起，含「绕相机位置做刚体反补」）。**ScreenSpaceCamera 画布每帧被摆回相机前方** ⇒ **推相机对画布件完全无效**（内容不会晃）。⇒ 迁到画布后：**板相机震屏照旧**、**HUD 只能靠 `hudRoot` 自己动**。⛔ 别把 `hudRoot` 留在画布**外面**（那样它一动，画布不动）；`HudFrame` 必须挂在**画布内**、由 `hudRoot` 的等价节点驱动。验：真机挨一次打，看 HUD 有没有晃（与原版并排比）；自检读 `cam.transform.position` 与 `HudFrame.anchoredPosition` 两处都要动。
