## 0. 一句话

清单生成器的 `world_chain()` 只把**旋转 + 平移**沿父链累乘、**不乘父级缩放**；
Unity 的 `Transform.position` 是**父世界矩阵 × 局部 TRS** 的平移列（父级缩放**会**乘进子的 `localPosition`）。
⇒ 只要某颗对象的**祖先带非单位缩放**且**它自己的 `localPosition` 不是 0**，清单里的 `pos` 就**不是真世界坐标**。
本轮实测：13 场共 **194 条清单条目**（18 meshes / 159 particles / 9 tapHits / 8 anchor 记录）差 > 0.05，
**最大 47.65**；其中**当前真的被摆错、能在 prefab 里量到**的有 **102 条 / 98 颗对象**。
修法 = 把 `pos` 改成真世界坐标（rot / scale / 其它字段一个字不动），**代码侧不用改**（它比的本来就是 `Transform.position`），
但**清单 + 5 类旁挂必须一起重生成**。

## 1. 两种口径（定义 + 出处 + 为什么 b 才是 Unity 真值）

记父链 `p0(根) → p1 → … → pn(自己)`，每级局部 TRS = `(t, q, s)`。

### 1.1 口径 a（现行 = **错**）—— `world_chain()`

```
pos = 0; rot = identity
for 每级 lt（根 → 自己）:
    pos += rot * lt.t          # ← 只转 localPosition，**没有 lt.s**
    rot  = rot * lt.q
```

**出处**（实测行号，2026-10-26）：
`d:/4/Unity/工具/scripts快照/gen_unity_arena_manifest.py:857-870`（`world_chain`）
· 副本口径：`d:/4/Unity/工具/gen_arena_groups.py:189-208`（`Scene._world_of`）。

### 1.2 口径 b（Unity 真语义 = **对**）—— 父世界矩阵的平移列

```
M = I4
for 每级 lt:
    M = M · TRS(lt)            # TRS 的左上 3×3 = R·diag(s)
pos = (M[0][3], M[1][3], M[2][3])     # ← Unity 的 Transform.position
```

等价写法（**只在「父级无旋转」时成立**，⛔ 别照它写代码）：
`pos_world = pos_parent + R_parent · (lossyScale_parent ⊙ localPosition)`。
父级同时有**非均匀缩放 + 旋转**时，真正的变换会带剪切（shear），只有 4×4 矩阵是精确解 —— 本轮实现一律走矩阵。

### 1.3 「b 才是真值」的直接证据（不靠推）

`ApplyGroupNodes` 建出来的分组节点写的是**原版 local TRS**（`ArenaBuilder.cs:3118-3122`），
它们是 Unity 自己算的世界坐标。实测这些节点**落在 b 上、不落在 a 上**（逐条见 §4），
⇒ Unity 的语义就是 b；a 只是清单生成器自己发明的另一套。（这条比任何公式都硬。）

## 2. 判据怎么验（本轮的方法，可复现）

`d:/4/_tmp_view/q3_t09/recheck.py`（11 秒跑完 13 场，**纯离线**）：

1. 读**清单生成器同一份源**：`d:/2/解包整理/07_场景/<场>/Transform|GameObject/*.json`
   （`gen_unity_arena_manifest.Assembler.__init__` 就是 `load_pid_dir(07_场景/<场>/Transform)`）。
2. 对每条清单条目找出**原版那颗 Transform**：
   - `tapHits` / `anchor` 有 `path` ⇒ 按整条路径取候选（⚠️ **同路径可能有多颗同名兄弟**，实测 arena2
     `…/Battle Arena 2/Collision` 有 **8 颗**）⇒ 再按「a 位置与清单 `pos` 最近」消歧；
   - `meshes` / `particles` 没有 path ⇒ 按 **GO 名精确相等 + a 位置与清单 `pos` 最近**，且要求 **< 2e-4**。
3. 同一颗 Transform 分别按 a / b 算两个世界坐标。

**匹配结果（口径自证）**：734 meshes / 578 particles / 166 tapHits / 13 anchor 记录**全部配上**（unmatched = 0）；

⇒ 清单的 `pos` 确实就是 `world_chain` 的输出，**不是别的口径**。

> ⚠️ Q2 当年用「名字 + 最近清单 pos，差 < 0.05 就算配上」—— 那个容差**比本轮的 2e-4 松 250 倍**，
> 同名重复时有配错风险。本轮**方法更严**，结论**逐条相同**（§5 完全复现 Q2 的 18/159/9/8）。

```python
def world_chain(a, tpid):
    """沿 m_Father 上溯累乘 → (world_pos, world_quat)。
    🔴 2026-10-26（T09）：pos 改按 Unity 真语义算（父级缩放乘进子 localPosition）；
       rot **不变**（四元数连乘，与缩放无关）。判据 → 判据/T09_清单坐标口径_第4轮.md §1。
    """
    chain = []
    cur = tpid
    while cur is not None and cur in a.TF:
        chain.append(a.local_trans(cur))
        cur = a.TF[cur].get('m_Father', {}).get('m_PathID')
    M = [[1.0 if i == j else 0.0 for j in range(4)] for i in range(4)]
    q = [0.0, 0.0, 0.0, 1.0]
    for lt in reversed(chain):
        M = _mat_mul(M, _local_matrix(lt))     # 定义在本函数下方，调用时已存在
        q = list(q_mul(tuple(q), lt[3]))
    return [M[0][3], M[1][3], M[2][3]], q
```
