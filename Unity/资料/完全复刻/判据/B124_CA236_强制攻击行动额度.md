## 3. 「+0x48」就是「本回合行动额度」

`CardScript__ActivateMinion.c:18-30`：`canAct` 成立必须 `cardState == 2` ∧ `+0x48 == 0`
（例外：血渴 `0xdc` 且 `+0x48 == 1`）⇒ 打掉一次就动不了 = 消耗额度。
`CardScript__ResetActions.c:29-31`：`if (+0x48 > 0) +0x48--` —— 这才是「退还」。

## 4. 有没有第二处补偿（答案：`ca 236` 这条链上**没有**）

- `RemoveAttackThisTurn` 全树**只有两个调用者**：`AddForceAttack.c:41-42` 与 `AddScriptedForceAttack.c:44-47`
  （il2csharp `BattleManager.cs:18877` / `:18916`），两者都挂在 `dontCountAttack` 形参下。
- **`AddRedirectedAttack` 没有这个形参**（签名到 `blockPlayerActions` 就完）、不调 `RemoveAttackThisTurn`、不排 `ResetActions`
  （`BattleManager__AddRedirectedAttack.c` 全文）。
- `BattleManager__AllowResolveAttack.c:134` 对 `0x4a` **直接 `return 1`**（`0x34` 在 `:92` 同样早退）——
  它跳过的是 **`hasAvailableActions` / 目标合法性那套「能不能打」的闸**，**不是**「不扣额度」；
  恰恰相反：**原版允许一个「已经没行动」的单位被脚本再打一刀，而且这一刀照常记账**。

⇒ 「`AddRedirectedAttack` 里 `RemoveAttackThisTurn` 0 命中」只能推出**「不预扣、不退还」**，
**推不出「不消耗」** —— 消耗写在结算期的动画协程里。这就是现有注释的推理漏洞（见 §7）。

## 5. 顺带：`ca 238` **不是同一条链**，但净效果确实是 0

- `ca 238`（`case 0xee`，`PlayAbility.c:2767-2780`）→ `AddScriptedForceAttack(…, dontCountAttack = 1)` →
  `0x43 forceScriptedAttack` → **`ResolveScriptedTargetCardAttack`（`_d__505`）**（`ResolveAction.c:5915` 的 `case 0x43`）。
- 预扣：`AddScriptedForceAttack.c:44-47` `wasFree = (+0x48 == 0)` → `RemoveAttackThisTurn`。
- 退还：`_d__505__MoveNext.c:51` `if (wasFree) AddResetActions(…)` → `ResetActions` 把 `+0x48` 再 `-1`。
- 两档都净 0：`0 → +1 → reset −1`；`n>0 → n−1 → +1`（`wasFree` 假、不 reset）。
- 我们的 `DeclareAttackRefundingForced` + `RefundForcedAttackAction`（`RuleCore.cs:14670-14740`）净效果相同，
  **F3 那条「净不变」的断言是对的**。
