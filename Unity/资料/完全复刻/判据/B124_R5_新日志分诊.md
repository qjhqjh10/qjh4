## 〇、头号发现（一次解释 46 条红 + 1 条假绿）

**批处理里 `Tween.Kill(...)` 是【静默空操作】** —— DOTween 在编辑器/批处理下**从未初始化**。

判据全部来自工程自己的 `Unity/MyGame/Assets/Plugins/Demigiant/DOTween/DOTween.dll`（用 `d:/2/tools/ilspycmd/ilspycmd.exe` 解到 stdout，未落盘）：

| 事实 | 出处（反编译） |
|---|---|
| `Kill` 第一句就早退 | `TweenExtensions.Kill(Tween t, bool complete=false)`：`if (!DOTween.initialized \|\| t == null \|\| !t.active) return;` |
| `Complete` 同族（同样要吃 `initialized`） | `TweenExtensions` 的 `Complete` 系列 |
| 初始化**只在 Play 模式**做 | `DOTween.Init(bool?,bool?,LogBehaviour?)`：`if (!Application.isPlaying \|\| isQuitting) return null;` |
| `InitCheck()` 也只在 Play 模式 AutoInit | `private static void InitCheck() { if (!initialized && Application.isPlaying && !isQuitting) AutoInit(); }` |
| **但推进不看 `initialized`** | `DOTween.ManualUpdate(dt,udt)`：`InitCheck(); if (TweenManager.hasActiveManualTweens) TweenManager.Update(UpdateType.Manual, …);` |
| 「真的杀」= `TweenManager.Despawn`（它会派 `onKill`） | `Despawn`: `if (t.onKill != null) Tween.OnTweenCallback(t.onKill, t);` |

⇒ 批处理（`Application.isPlaying == false`）里：**补间照常被 `CardTween.Advance` 推**，但**谁都杀不掉它**。
`DeploySequence.Play` / `CardFeel.HandToBoard` 等**把收口写在 `OnKill` 上**的代码，在自检里**一次都不会执行**；
`OnComplete` 侧正常（`N` 组全绿可作反证）。

**这一条解释的红：**
- `cardface_e5.log` · `B123C3` **39 条**（K5 的 14 条 `AssertClean` · K6 的 13 条 · D4 的 10 条 · D5/D5' 2 条）
- `battle.log` · `B121_Q4B` **D2**（`tw.Kill(false)` 没杀掉落位序列 ⇒ `OnDeployed` 照跑，实得 1）
- `battle.log` · `B118W14` **C6 / C6c**（倒放补间没被杀 ⇒ α 停在 0.5999、2D 层没收起）
- 并且让 `B121_Q4B` 的 **A6 是假绿**（A 组杀完不推进 ⇒ `deployed` 当然是 0；判据「灭自证」失效）

**要不要改产品：不要。** Play 模式下 `initialized = true`，`Kill` 正常。这是**夹具/宿主**的可测性问题。
**修法（建议）**：在自检侧加一个 batch 专用的杀补间口，例如反射调 `DG.Tweening.Core.TweenManager.Despawn(Tween)`（`internal static`，它会派 `onKill`；判据见上表最后一行），全部 `X.Kill(false)` 换它。⛔ 别改产品代码去绕过 DOTween。
