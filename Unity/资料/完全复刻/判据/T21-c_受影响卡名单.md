## 一、口径（先说清「受影响」和「手牌锚」各指什么）

### 1·1 「受影响」= 三个条件同时成立

1. `cards_truth.json` 的 `abilities[].abilityContext == 10 (Hand)` —— 这条 ability **只能在这张卡位于手牌时触发**（判据见 §一·3）；
2. `cards_engine.json` 的 `animTimes[]` 里有 `tg` 命中那条 trigger 的行 —— 即这条手牌触发**绑定了 CardAnim**；
3. 这条触发走的是 `EvtKind.Trigger` + `Slot = -1` —— 而被 `BattleDriver.PlaySignal` 的 `if (slot < 0) return;`（现读 `BattleDriver.cs:23391`）整条吞掉 ⇒ **动画一次都不播**。

### 1·2 「必须手牌锚」= 该拍的起锚点由 `PositionOption.self(0)` 决定

`sp == 0 (self)` ⇒ 原版取「**发出这条 ability 的那张卡**」的 `GetEffectAnchor()`；
那张卡在手牌里 ⇒ 锚 = 它的 **2D 卡**（`cardUI + 0x30`），即**手牌那张卡本身**，不是屏幕中心（`createCardPos=140`）。
不满足这一条的另 3 张，锚点是 `friendlyHero(3)` / `boardCenter(5)` / `abilityTarget(2)`，**不需要**「手牌→2D 卡」这条锚。

## 三、必须手牌锚的 3 张：逐张理由

三张共用同一条链（§一·3 ③④）：`sp=0 self` ⇒ 锚 = 发出能力的这张卡 ⇒ 它此刻在手牌里 ⇒ **锚 = 那张手牌卡的 2D 卡**。

| 卡 | 为什么必须手牌锚 | 判据 |
|---|---|---|
| **Jammed Communications** | 手牌触发 `OtherCardPlayed(10)` 的第一拍 `Card_Buff_Sabotage_self` 是 **`sp=0 self`**。这张卡在触发时**在手牌里**（`abilityContext=10` ⇒ `IsInHand` 才许可），没有场上视图 ⇒ 原版锚 = 它自己的 2D 手牌卡。我们今天 `Slot=-1` 直接早退，或用 `createCardPos(140)`（屏幕中央）= 错。 | truth `cards[109].abilities[0]`（trigger 10 / ctx 10）；engine `cards[444].animTimes[0]`（tg 10）；clips `Card_Buff_Sabotage_self` sp/ep/pt=0/0/0；`PlayAnim.c:250-277` + `GetPos.c:183-187/210-218` + `GetEffectAnchor.c:9-19` + `IsInHand.c:7-9` |
| **Cult Propaganda** | 手牌触发 `TurnEnd(40)` 的第一拍 `Card_Buff_Sabotage_self` 是 **`sp=0 self`**，同理（回合结束时这张卡仍躺在手牌里）。同一 trigger 的第二拍 `CreateCard_GSC` 是 `sp=5 boardCenter`（棋盘中心），不受这条影响。 | truth `cards[149].abilities[0]`（trigger 40 / ctx 10）；engine `cards[432].animTimes[0]`（tg 40）；clips `Card_Buff_Sabotage_self` 0/0/0；同上四份判据 |
| **Poisoned Supplies** | 手牌触发 `TurnEnd(40)` 的第一拍 `Card_Buff_Sabotage_self` 是 **`sp=0 self`**，同理。同 trigger 的第二拍 `Toxic Vapors Damage quick` 是 `sp=2 abilityTarget`（走 T21-b 的目标侧通道，不是本条）。 | truth `cards[1233].abilities[0]`（trigger 40 / ctx 10）；engine `cards[452].animTimes[0]`（tg 40）；clips `Card_Buff_Sabotage_self` 0/0/0；同上四份判据 |

### 3·1 另外 3 张为什么**不**进「必须手牌锚」

- **Improvised Barricade**：唯一手牌触发拍 `GSC_Warlord Sabotage` 是 **`sp=3 friendlyHero`** ⇒ 锚 = **己方督军**（`GetPos.c` `case 3/9` → `GetHero` → `GetEffectAnchor`）。只需放行事件，**不需要**手牌锚。
- **Vengeance for Cadia / Avenging Zeal**：两拍都是 **`sp=2 abilityTarget`** ⇒ 锚 = **这条 ability 的目标**（`PlayAnim.c:170-249` 的 `sp==2` 支，逐目标 `GetPos`）。目标从 `abilityTargets` 的表来，属于 **T21-b「目标侧+格号」通道**，不是「这张卡自己的手牌锚」。
  - ⚠️ 数据补注（不改变 3 的计数，但 T21-b 要一起验）：这两条 trigger 的 `abilityTargets[].ta` 都是 **20 = `self`**（`TargetsAffected.cs`：`self=20`）⇒ 原版 `GetTargets` 的 self 支（`AbilityLogic__GetTargets.c:184-190`）把**发出能力的这张卡**加进目标表；`PlayAnim.c:185` 再对目标做 `IsInHand` ⇒ 目标就是手牌里的这张卡 ⇒ 原版锚**最终仍落在这张手牌卡上**（只是经「目标侧」而非「self」）。
  - ⇒ 实装口径：T21-a 的手牌锚支已在 `PlayAbilityBeat` 里对「`handAnchored` ∧ 目标锚为空」补了一条「退回这张手牌卡自己的锚」（`BattleDriver.cs:23651-23660`，**🔶 自己设计**，调度台 2026-10-31 裁定），所以这两张在实现上也会落在手牌卡上；**但判据上的归属是 T21-b，⛔ 别把它们算进「3 张必须手牌锚」。**

## 六、边界与未查清（⛔ 别把这里当结论）

1. **池内 `abilityContext == 10` 的卡 = 13 张**（`cards_engine.json` 现扫），不是 `B100_D2` 写的 14 张。
