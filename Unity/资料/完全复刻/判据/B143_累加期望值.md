## 3. 决定性问题：Aun'Shi/Piranha 的 changeCost 是不是 `extrinsic`？

### 3·1 结论：**是**（运行时），所以**不累加**

### 3·2 证据链（两源交叉）

| 跳 | 实读 | 出处 |
|---|---|---|
| ① trigger 20 把 `AbilityData.whileInPlay` 置 1 | `if (ability.trigger == AbilityTrigger.WhileInPlay) pooledAbilityData.whileInPlay = true;` | `out_il2csharp/Assembly-CSharp/RawCardScript.cs:1270-1277`（`whileInPlayVariable` 同段） |
| ② `PlayAbility` 把 `extrinsic` 覆盖成 `whileInPlay \|\| whileInPlayVariable` | `bool flag = true; if (!abilityData.whileInPlay) flag = abilityData.whileInPlayVariable; cardEffect.extrinsic = flag; cardEffect.extrinsicVariable = abilityData.whileInPlayVariable;` | `out_il2csharp/Assembly-CSharp/AbilityLogic.cs:677-682`（buffOthers 目标循环；同形在 `:829-834`）· C 版 `decomp_full/AbilityLogic__PlayAbility.c:1193-1198` |
| ③ 非 extrinsic 才直接入队；extrinsic 先查 `AlreadyContainsEffect` | `if (!cardEffect.extrinsic) AddEffect(...); else if (thisCard.AlreadyContainsEffect(cardEffect,false)) { /* skip */ } else AddEffect(...)` | `AbilityLogic.cs:688-700` / `:843-855` |
| ④ `AddEffect` 的 extrinsic 支：已有同源同 buffType ⇒ **直接 return false**（`extrinsicVariable == false` 时） | `else if (!ContainsExtrinsicEffectFrom(...)) { …既有效果的 switch… } else { if (buffType == removeExtrinsic) …; if (!newEffect.extrinsicVariable) flag15 = false; … }` | `out_il2csharp/Assembly-CSharp/CardScript.cs:10689`（`if (!newEffect.extrinsic)`）· `:11598`（`else if (!ContainsExtrinsicEffectFrom(...))`）· `:11669-11671`（`flag15 = false`）· C 版 `decomp_full/CardScript__AddEffect.c:91-110` |
| ⑤ `ContainsExtrinsicEffectFrom` = 「同来源卡 + 同 buffType + 同 baseEnchantmentCard 且 `effect.extrinsic`」 | 逐句：`if (effect.extrinsic)` → `enchantingCard == param_2` → `buffType == param_3` → `baseEnchantmentCard == param_4` ⇒ return 1 | `decomp_full/CardScript__ContainsExtrinsicEffectFrom.c`（全文） |
| ⑥ `AlreadyContainsEffect` = 任一现有 `IsSameEffect` 为真 | `for (...) if (IsSameEffect) return true;` | `out_il2csharp/Assembly-CSharp/CardScript.cs:12717` · `CardEffect.cs:172+`（`IsSameEffect` 比 `buffType/enchantingCard/enchantmentCardId/extrinsic/extrinsicVariable/until*/数值`） |

⇒ **Aun'Shi / Piranha / Grukk / Land Raider 的 while-in-play 效果在运行时 `extrinsic = true`、`extrinsicVariable = false`**（trigger 20；240 才会把 `whileInPlayVariable` 置真）。第 2/3 趟：目标卡身上已有同源同 buffType 的 extrinsic 效果 ⇒ `ContainsExtrinsicEffectFrom` 为真 ⇒ `!extrinsicVariable` ⇒ **return false，不再叠加**。
（buffOthers 支的第一道 `AlreadyContainsEffect` 查的就是**目标卡**（`possibleTargets[i]`，`AbilityLogic.cs:854`）；即使它返回 false，第二道 `CardScript.AddEffect` 的 `ContainsExtrinsicEffectFrom` 仍会挡掉。）

### 3·3 为什么 W7 §6 会得到「会累加」

W7 §六 证的是「**没有任何摘除点**」——**这一点成立**，但**摘除不是唯一的去重口**：
- 去重发生在 `CardScript.AddEffect` 的 **extrinsic 支**（本项目 `判据/B143_AddEffect累加取证.md` §2·1 自己引了 `if (!newEffect.extrinsic)`，但 §3·1 的「是否 extrinsic」表用的是 **SO 的 `extrinsic` 字段（0）**，没有跟进 `PlayAbility` 的运行时覆盖）；
- 因此「无摘除」+「每次重新触发」≠「会累加」——**每次触发确实会走到 AddEffect，但 AddEffect 对 extrinsic 同源同 buffType 直接 return**。
