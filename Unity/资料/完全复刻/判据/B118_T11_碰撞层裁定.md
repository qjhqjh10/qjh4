## 1 · 两处说法各自的真实含义

- **`CardView.cs:9544-9552 EnsureHitCollider`（`:9548` 只加 `BoxCollider2D`）**：建的是挂在内层 `2DCard`（`_tiltRoot`）上的 **2D** 碰撞体，
  服务对象只有两条**指针命中判据** `Contains`（`:9641 HitRect`）/ `HitByCollider`（`:9680`）。与 `Physics`（3D）**完全无关**。
- **`CardView.cs:9661`**：上下文是「2D `BoxCollider2D` 跟不了 X/Y ±10° 倾摆、最大差 ~2.6% 卡高」那一段的**收尾句**。它约束的是
  「**别拿 3D collider 顶替这条命中判据**」（会引入 z 排序、`HitByCollider` 与 `Contains` 就此分家）—— 这半句**成立**；
  后半句「**原版没有**」是**事实错误**：原版有，但它**不是**命中判据。该行**不该**被读成「整张卡不许有任何 3D 碰撞体」。

## 3 · 裁定

**B117-T11 成立；`CardView.cs:9661` 的「原版没有 3D collider」是错的，须就地订正。原版有，但它是「挡地面点击射线的板」，
不是「命中判定用的 collider」—— 两者用途不同，互不冲突，照原版补上即可。**

① 判据是 prefab 序列化字段，**逐值可核**（层 10 + `!u!65` BoxCollider 1.827034×3.01×0.5）；
② 原版**同时**存在「2D 卡面层 5 + 2 颗 `BoxCollider2D`」与「3D 卡体层 10 + 1 颗 3D `BoxCollider`」⇒ 本来就是两套，不是二选一；
③ 行为链自洽：上棋盘隐 2D 卡 ⇒ 闸⑥失效 ⇒ 只剩 3D 挡板能挡；缺了它原版自己也会多播一次地面反馈。

```csharp
/// <summary>原版 `CardPrefab/Board Elements/3DBody/Card 3D` 上那颗 3D `BoxCollider`（挡 `TapParticleController` 的地面点击射线）。
/// 判据：`CardPrefab.prefab` `--- !u!65 &65948132087033897` = size (1.827034, 3.01, 0.5) · center (0.013507843, 1.55, -0.016031265)
/// · m_IsTrigger 0；节点 `Card 3D` m_Layer 10。⛔ 这颗**不是**命中判据（`Contains`/`HitByCollider` 仍走那颗 2D）。</summary>
void EnsureTapBlockCollider(GameObject body)
{
    if (body.GetComponent<BoxCollider>() != null) return;      // 幂等：`Build` 可能重入
    var c = body.AddComponent<BoxCollider>();
    c.size = new Vector3(1.827034f, 3.01f, 0.5f);
    c.center = new Vector3(0.013507843f, 1.55f, -0.016031265f);
    c.isTrigger = false; c.enabled = true;
    body.layer = gameObject.layer;      // 场上 = 8（掩码内）；换层由 `SetLayer` 递归跟进
    _bodyCollider3D = c;
}
BoxCollider _bodyCollider3D;                                   // 同类尾
/// <summary>自检读口（`B118-T11`）：挡地面点击射线那颗 3D collider。</summary>
public BoxCollider TapBlockColliderForTest { get { return _bodyCollider3D; } }
```
