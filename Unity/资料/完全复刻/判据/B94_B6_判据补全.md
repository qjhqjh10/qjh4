## §1 · 账 204 `Countdown.Activate/Update` —— 那条「乘倍速」公式**结案**（原来标「未拿到逐字节判据」）

### 结论（逐字节）

```
speedAdjustedTimeElapsed = TimeSpan.FromTicks( (long)speedFactor * (now − lastStop).Ticks ) + timeElapsedBeforeStop
```

**先截断、再相乘**（⛔ 不是「乘完再截断」）。

### 证据 = VA 反汇编 `Countdown$$Update`（VA `0x180623EA0`，RVA `0x623EA0`）

```
180623F3E  f3 0f 10 77 44        movss  xmm6, dword ptr [rdi + 0x44]      ; speedFactor(+0x44)
180623F51  f3 48 0f 2c ce        cvttss2si rcx, xmm6                      ; ★ 先把 float 截断成 int64
180623F56  33 d2                 xor    edx, edx
180623F58  48 0f af cb           imul   rcx, rbx                        ; ★ × (now − lastStop).Ticks（rbx）
180623F5C  e8 2f 5f 46 00        call   0x180A89E90                     ; = TimeSpan.FromTicks(long)
```

`0x180A89E90` 全文只有 `mov rax, rcx; ret` ⇒ 就是 `TimeSpan.FromTicks(long)`（= `new TimeSpan(ticks)`）。

其余三跳（同一函数）：`TimeSpan.Add(result, timeElapsedBeforeStop(+0x30))` → 写回 `+0x38`；
`timeAvailable(+0x48) − (+0x38)`；`+ TimeSpan.FromSeconds(**1.0**)`；文本 = `Format("{0:0}:{1:00}", ts.Minutes, ts.Seconds)`；
`if (!soundPlayedFlag && (float)left.Seconds < **5.0**) { GetComponent<AudioSource>().Play(); soundPlayedFlag = 1; }`。

两个常量现读（`工具/read_literal.py`）：`0x1834B2DF4` = **4 字节 float 5.0**；`0x1834B2F60` = **8 字节 double 1.0**
（同一地址 4 字节读 = 0.0 —— 那是**错档**：`TimeSpan.FromSeconds(double)` 取 8 字节，ILSpy 也写明 `FromSeconds(1.0)`）。

### 我们原来错在哪

`Shell/TimerDisplay.cs` 的 `Scale` 原来是 `FromTicks((long)(ticks * (double)factor))` = **乘完再截断**。
⇒ `speedFactor = 1.5` 时我们走 1.5 倍、原版走 **1 倍**；`speedFactor = 0.5` 时我们走半速、原版**冻住**（`(long)0.5 = 0`）。

### 已改

`Shell/TimerDisplay.cs` 的 `Countdown.Scale` → `TimeSpan.FromTicks(unchecked((long)factor * ts.Ticks))`（行数 +0，
且**全部在 `:455` 之后** ⇒ 该文件在账里的两处落点（`:455`）零漂移）。断言 → `Editor/B94B6_Assert.cs` **M1–M5**。

### 仍差（如实标）

- **实例面仍未证**，但这次查清了**为什么本地证不了**（⛔ 不是「没查」）：
  ① `Countdown` 的 MonoScript **不在** 722 个 addressable 类里（`_tmp_view/apk135/monoscripts.json` 0 命中），
    只在 `assets_full/globalgamemanagers/MonoScript/MonoScript_2618.json`（`m_ClassName = "Countdown"`）；
 ② 那份目录的**文件名是文件序号、不是 pathID**（见 `CLAUDE.md` 2026-10-28 那条）⇒ 拿不到 pathID 就没法按
    `m_Script` 反查实例；`ScriptMapper_5.json` 只映射 shader（`m_Shaders` 一个键）。
  ⇒ 结论：**本地能判的都判完了**；要证实例数得有 pathID（需要解 `_tmp_view/apk135/globalgamemanagers` 那份原始文件）。

## §4 · 账 396/398/399 `ListExtensions` —— 三条等价物**写错了**（铁律 5 就地订正）

### 396 `SpliceWhere<T>(IList<T> list, Func<T,bool> predicate, int count = 0)`

体（`decomp_full/ListExtensions__SpliceWhere_object_.c` ＋ ILSpy `ListExtensions.cs:2362`）**逐句**：

```
sel = Where(list, predicate)
if (count > 0) sel = Take(sel, count)      ← ★ count <= 0 = **不限量**（不是「取 0 个」）
out = ToList(sel)
foreach (x in out) list.Remove(x)          ← ★ 逐条按**值**从原表移除**一次**
return out
```

🔴 **`List.RemoveAll(pred)` 不是等价物**：它 ①无视 `count`、②一次把**所有**匹配项删掉。
只有「`count <= 0` 且每个匹配值在原表里只出现一次」时两者才撞在一起。
⇒ 账里那句「等价 = `List.RemoveAll`」**必须加条件**，否则会照着写错。

### 398/399 `GetMax` / `GetMin`

- 两个方法在 `decomp_full` 里**产物同址同体**（`ListExtensions__GetMax_object__int_.c` 与
  `ListExtensions__GetMin_object__long_.c` 内容逐字相同，首行都是 `FUN_180d10f70`）= **ICF 折叠** ⇒
  **体本身分不出 max/min**（`B93_U1` 那条结论成立，本轮复核）。
- 方向改由 ILSpy 的 lambda 定（`ListExtensions.cs:459` `_003CGetMin_003Eb__0`）：
  `int c = f(i1).CompareTo(f(i2)); return c >= 0 ? i2 : i1;` ⇒ **`GetMin` 同分取 `i2`（后者）**；
  `GetMax`（`:408`）那一份被 ILSpy 降级（两个分支都写成 `return this`），**按镜像推**同分也取后者（未逐字节证）。
- 体形状 = `Append(…) + Aggregate(比较委托)` ⇒ 返回**元素**。

🔴 **账里「等价 = `Select(...).Max()`」是错的**：`Max()` 返回的是**投影值**、不是元素，而且同分取**第一个**。
正确等价物 = `data.Aggregate((a,b) => f(b).CompareTo(f(a)) > 0 ? b : a)`（或 `OrderByDescending(f)` 后**取最后一个**）。
⇒ 三个调用点（`CarforgeHandler.cs:321` · `MissionChallengeProgress.cs:576` · `ArmySelectorRanked.cs:604`）的
