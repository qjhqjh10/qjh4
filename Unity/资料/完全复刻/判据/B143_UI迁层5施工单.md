## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 我们 UI 在哪些层？ | **全在层 0**（场景里 31 个 GO 全 `m_Layer: 0`；运行时新建的 `GameObject` 默认层 0，创建路径**一处 `.layer =` 都没有**） |
| 原版是不是**所有** UI 都在层 5？ | **不是**。主流是层 5（菜单场景 552/569、战斗场景 1062/1224、UI prefab 绝大多数），但**确有层 0 的 UI 可渲染节点**（`Social Submenu Variant.prefab` 12 个、`MainMenu Warpforge.unity` 17 个：`Price Display` / `icon` / `Buy Original Card Button` / `UI Camera` 自己）。⛔ 别按「全部层 5」写断言 |
| 会不会推翻「必须迁层」？ | **不会**，但**有两处要限定**（见 §6）：① 我们的 UI 是真 `MeshRenderer`/`CanvasRenderer`，**参与相机层剔除**；② **今天没有任何东西要求层 5**（两台相机与 renderer mask 都含 bit5）⇒ 迁层的**唯一驱动**就是「原版那个 mask=32 的 UI renderer」 |
| 迁移会不会让画面少东西？ | **不会**（我们两台相机的 cullingMask / PC·Mobile renderer 的 mask **都含 bit 0 与 bit 5**）。真正的风险只在「**新 UI renderer 的 mask 收成 32 之后**」——那时**任何漏迁的件会当场消失** |

## 4. 施工路线（两条 + 推荐）

### 路线①（推荐）：**在共用创建口设一次**
把 `layer = 5` 设在「所有 UI 节点都要过」的那几个口上：

| 口 | 出处 | 覆盖面 |
|---|---|---|
| `MenuDraw.Node` | `Shell/MenuDraw.cs:169` | 壳里几乎所有容器/窗内容（含 `Battle/CardDisplayWindow.cs` / `EndPanel.cs` / `Core/CostCurveDrawer.cs` / `Deck/DeckRuntime.cs` 这些**战斗 UI** 也在用） |
| `MenuDraw.Hit` | `Shell/MenuDraw.cs:2247` | 所有命中区节点 |
| `ImageQuad.Create` / `CreateNineSlice` | `Battle/ImageQuad.cs` | 所有 quad 图元 —— ⚠️ **要先核它有没有被非 UI（3D/卡面/VFX）用**（见 §7） |
| `Label.Create` / `CreateUgui` | `Battle/Label.cs` | 所有文字 |
| `HudCanvas` 的建件口 | `Battle/HudCanvas.cs` | 战斗 uGUI 那一档 |
| 窗根 | `Shell/WindowsManager` 建窗处 | 兜底 |

**优点**：1298 处 `new GameObject` 不用逐个改；新建的东西**天然**在层 5。
**缺点**：每个口要**先核用途**（尤其 `ImageQuad` —— 若 3D 战场/卡面也用同一口，会把它们一起拉到 5，那会**改坏** 3D 相机的 mask=8/10 划分）。

### 路线②（兜底）：**建完整树后扫一遍**
已有现成实现：`BattleDriver.SetLayerDeep(Transform, int)`（`Battle/BattleDriver.cs:24491`，逐层递归）。
- 用在**明确是纯 UI 的根**上：`HudCanvas.Root`、壳根（`ShellRuntime` 根）。
- ⛔ **不能**对整个 `CardPresentation` 根扫 —— 会把层 8（战场）/ 层 10（卡）一起拉到 5，**直接改坏两台相机的分流**（`Editor/BattleScene.cs:47763/47844` 那两条断言会红）。

### 推荐：**① 为主 + ② 只当兜底/自检**
① 覆盖新建件；② 在「建完一屏」后**只读地扫一遍**（不改，只统计「UI 根下带 Renderer 且层 ≠ 5」的件数）当断言。

### 顺序（重要）
1. 先按 ①/② 迁层（此时 UI renderer mask 还是 `4294966015` ⇒ **画面零变化**，可以先合）；
2. 再把 `UI_Renderer` 的 3 个 mask 从 `4294966015` 收成 **32**；
3. 逐屏截图验收（这一步才会暴露漏迁的件）。

## 5. 验收办法

**断言（建议新增）**
- `HudCanvas.RootLayer == 5`（读口已有，`Battle/HudCanvas.cs:64`）；
- 建完一屏后：**UI 根子树里「带 `Renderer` 的节点」层号 != 5 的数量 == 0**（把清单打出来，不静默）；
- 两台相机 mask 仍含 bit5（`Editor/B117_G10_24_Assert.cs:183-202` 已有同族断言，可扩展）；
- 3D 相机 mask **不含** bit5 与 bit0（`Editor/BattleScene.cs:47169` 那条 `bcam.cullingMask == (1<<8)|(1<<10)` 已经钉着）。

**截图（逐屏，只比「有没有少件」，不比逐像素）**
主菜单 · 战斗 HUD · 卡组编辑 · 收藏 · 商店 · 社交（含下拉展开）· 设置（两页）· 奖励窗。
每张与迁移前那张并排看：**同一批控件都在、位置不变**；少一件就是漏迁。

**判别力（🧨 什么坏法会让哪条红）**
- 某一件留层 0 ⇒ 上面第 2 条断言红 + 该件在 mask=32 后从截图上消失；
- 误把 3D 战场/卡也扫进层 5 ⇒ `BattleScene.cs:47169`（3D 相机 mask 相等）与 `:20945-20948` 那组会红，且战场画面缺失；
- 把 UI 从层 5 又改回 0 ⇒ 第 1 条 `RootLayer` 红。

## 6. 会不会推翻「必须迁层」

**不会推翻，但有两条限定必须写进账：**

1. **层号对我们 UI 是真起作用的** —— `ImageQuad` 是 `MeshRenderer`、`Label` 是 `CanvasRenderer`，**都参与相机层剔除**（不存在「透明队列不参与 culling」那类前提）。⇐ 我按这条**特意查了**：`ImageQuad` 用自定义 `Material` + `MeshRenderer`，剔除走渲染器层，与材质/队列无关。
2. **但今天没有任何东西要求层 5**：两台相机 cullingMask 含 bit5、PC/Mobile renderer 含 bit5、UI renderer 还没建。
   ⇒ 迁层的**唯一驱动**是「原版那个 mask=32 的 UI renderer」。**如果将来决定不做 UI renderer（或它的 mask 保持 `4294966015`），这条活就是零收益**（但那是推翻已裁定方案，得调度台/用户点头）。

**反例留档（⛔ 别再写「原版所有 UI 都在层 5」）**：`Intro.unity` 相机 mask 全开、层 0 有 116 件；`MainMenu` 场景有 17 件层 0；`Social Submenu Variant` 有 12 件层 0。

## 7. 没查清（⛔ 不许拿猜测填空）

1. **原版那 12 + 17 个层 0 的 UI 渲染件到底画不画**：按 cullingMask=32 应被剔；但没有真机/编辑器 Inspector 确认，也扫不到 Overlay 画布。**这条决定「我们同族件要不要也留层 0」——在查清前一律迁 5（照多数派的形状）。**
2. **`ImageQuad.Create` / `CreateNineSlice` 有没有被 3D/卡面/VFX 复用**（若复用，路线①会在那几个口上误伤）——要逐个调用点核用途，本单没做。
3. **`MenuDraw.Node` 是否 100% 只用于 UI**（现读调用点在 `Battle/CardDisplayWindow` / `EndPanel` / `Core/CostCurveDrawer` / `Core/LayoutSpace` / `Deck/DeckRuntime`，看名字都是 UI，但没逐处核）。
4. **迁层后 base 相机会不会和 UI 相机「双画」**：原版 base mask `1137` **也含 bit5** ⇒ 原版同样双画；是否有可见差异（半透叠加）需真机看。
5. **`Intro` 那段**（相机全开、层 0 116 件）：本单不主张动它 —— 它不靠层分流，迁了也不会变，但会让「全仓 UI 层号统一」更好看；建议**先不动**。
