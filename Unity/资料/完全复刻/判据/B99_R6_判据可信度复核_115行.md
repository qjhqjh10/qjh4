## 一、判法（怎么判「体里算出返回值」）

T1 的判据只有一条：**`.c` 首行返回类型被写成 `void`，而 `dump.cs` 声明非 void**。逐份读下来发现，这条**不等于「值丢了」**——

### 1·1 Ghidra 把「返回值」渲染成两种等价形态（都不算丢）

| 形态 | `.c` 的样子 | 值在哪 |
|---|---|---|
| **A 尾调用转发**（最常见，占 95%+） | 函数体最后一条语句是 `Foo(a,b,0);` 然后 `return;` | **值就在 `Foo` 的 RAX 里**，尾调用原样带回。Ghidra 因为推断返回类型是 `void`，不写 `return Foo(...)`，只写 `Foo(...); return;` |
| **B 出参 / 写内存** | `*(int *)(param_1 + 0x38) = ...` 或 `*(undefined4 *)(lVar3 + 0x20) = 0xf0` | 值写进结构体字段 / 局部数组，调用方按约定读 |

实证（`AI__GetAiMulliganCards.c`，账 `战斗逻辑驱动:9` 声称「`manaCost(+0x78) > 4` ⇒ 换掉」）：

```c
if (*(int *)(lVar2 + 0x260) == 0x1e) { local_res10[0] = false; }        /* +0x260 == 30 ⇒ 保留 */
else { local_res10[0] = 4 < *(int *)(*(longlong *)(lVar2 + 0x28) + 0x78); }  /* 比较与常量 4 都在 */
```

⇒ 这条账的判据**完全可复核**，不需要 ILSpy。

### 1·2 什么才叫「真丢」（`需换源` 的判据）

Ghidra 在把返回类型判成 `void` 之后，会做一次**死代码消除**：只服务于那个返回值的**纯算术 / 浮点常量**被整段删掉，**带副作用的调用和分支控制流留下**。
⇒ **判别式（本轮的硬标准）**：

> `.c` 里**还剩下调用与控制流**，但**剩下不了一点「算出来的数」**（`*` / `+` / 浮点字面量），而 ILSpy 的 `return` 是一个**累加/乘出来的局部变量** ⇒ **需换源**。

三条对照（同一个类里紧挨着的三个方法，最能说明问题）：

| 方法 | `.c` 里有没有算式 | ILSpy `return` | 结论 |
|---|---|---|---|
| `AI.ScoreFromBuffedAttack` | **有**（`.c` 首行 `undefined4`，闸没降级） | `return num7;` | （不在本批） |
| `AI.ScoreFromAttack` | **无**：只剩 `ScoreFromBuffedAttack(...)` / `ScoreFromCriteria(...)` / `get_CurrentBlast` / `get_CurrentMarkerlight` 四条调用，`+=2f` / `+= blast×count` / `+= markerlight` 全没了 | `return num2;` | **真丢** |
| `AI.ScoreFromBuff` | **无**：只剩 `buffType`/`trait` 的 if 链，**零浮点常量**（`2.0/1.5/-1.0/-4.0/3.0` 一个都不在） | 16 个 `return <常量>` | **真丢** |

### 1·3 一条有用的副产物：**常量作为「实参」时不会丢**

浮点字面量只要**当实参传出去**，就会以 `DAT_xxxxxxxx` 数据引用留在 `.c` 里，可以 `工具/read_literal.py` 按 4B float 读回。
实证 `PrebuiltPackUI__CloseAnim.c`（账 `卡组编辑:293` 声称 `DOFade(alpha,0,0.4)` + `DOScale(content,0.6,0.4)`）：

```c
DG_Tweening_DOTweenModuleUI__DOFade(*(undefined8 *)(param_1 + 0x58),0,DAT_1834b3158,0);   /* 0.4 */
DG_Tweening_ShortcutExtensions__DOScale(*(undefined8 *)(param_1 + 0x50),DAT_1834b3180,DAT_1834b3158,0); /* 0.6 , 0.4 */
```

⇒ **只看「首行是 void」会误判一大批**；真正的判据是「这个返回值是不是靠纯算术凑出来的」。

### 1·4 交叉核对了什么

每一行都做了三件事：① 逐份读 `.c` 体；② 在 **ILSpy**（`out_cpp2il_dev_ilspy/`，**含子目录** —— `Everguild.LiveOps/*` 等 6 个文件一开始被我漏掉，已补）按**方法名 + 形参个数**定位同名方法体；③ 比对「`.c` 里剩下的那条语句」与「ILSpy 的 `return` 表达式」是不是同一个东西。
