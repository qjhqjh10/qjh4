# B155 · 配置登记链（`ConfigManager.Unpack`）根因与修法

> 2026-11-06 · 离线版 `OFFLINE-01` · 结论已实机验证（两轮 `run_cycle.sh` 对比）

## 一、现象

主菜单能进（顶栏 + 左侧导航渲染），**点「收藏」页签只变红、窗口不弹**。探针抓到异常：

```
OpenWindowButton.OpenWindow()
 → AssetLocator.TryGetAssetAbstract
 → DLCMessageAssetProvider.GetAssets()
 → NullReferenceException
```

`DLCMessageAssetProvider.GetAssets()`（`cpp2il/out_cpp2il_dev_ilspy/DLCMessageAssetProvider.cs`）：

```csharp
TemplateConfig config = ConfigManager.GetConfig<TemplateConfig>();
if (config != null && config.Templates != null) return OfType<DLCMessageData>(config.Templates.Values);
throw new NullReferenceException();        // ILSpy 把 throw 译成 return (IEnumerable<T>)new NullReferenceException()
```

探针读数（`E:/warpforge/07_产物/phase0/initstat.tsv`）：`tplCfg=config=null` ⇒ **`GetConfig<TemplateConfig>()` 返回 null**。

## 二、根因（两层，均已实测）

### 2.1 `Unpack` 用**索引器**取值 ⇒ 缺一个键就整条中断

- `ConfigManager.Unpack(titleData)`（Ghidra `decomp_full/Everguild.LiveOps.Config.ConfigManager__Unpack.c`）：
  `GetComponentsInChildren<IConfigProvider>()` → 逐个 `provider.Initialize(titleData)` → `Configs[provider.ConfigType] = provider`。
- `ConfigProvider<T>.UnpackInternal` 是 **`titleData[Key]`（索引器，不是 `TryGetValue`）**；
  `DailyStoresConfigProvider.UnpackInternal` 覆盖版同样用索引器。
- ⇒ **任何一个 provider 的键缺失 / 值形状不对，都会抛异常，`Unpack` 当场中断，后面的 provider 一个都登记不上。**

实测链（`probe` 的 `UNPACK-IN` / `UNPACK-EXC` / `UNPACK-OUT` 三行）：

| 轮次 | TitleData 键数 | 结果 |
|---|---:|---|
| 修前（只喂 `FeatureConfig` + `Templates`） | 2 | 第 5 个 provider `DailyStoresConfig` 抛 `KeyNotFoundException: The given key 'DailyStoresConfig' was not present in the dictionary` ⇒ 静态 `Configs` **只登记 4 个**，`TemplateConfig`（第 12 个）永远到不了 |
| 修后（喂全 20 个键） | 20 | `UNPACK-OUT Configs={count=20 …}`，**无异常** |

### 2.2 provider 的**场景顺序**决定谁先炸

`Intro.unity` 里 `Config Manager` 的子节点序（判据：`assetripper_out/…/Data/Scenes/Intro.unity` 中 Transform `193` 的 `m_Children`，逐个 fileID 追到 GameObject 再追 `m_Script` guid → `.cs.meta`）：

```
0 ShopConfig            1 WildcardConfig        2 CardTierConfig      3 PointsConfig
4 DailyStoresConfig ←   5 PremiumConfig         6 MissionsConfig      7 FeatureConfig
8 CloudscriptRestrictedVersionConfig            9 EventGroups         10 LeaderboardConfig
11 TemplateConfig ←    12 AlliancesConfig       13 ReferralConfig     14 GameModesConfig
15 CardsSpecialConfig  16 ItemsConfig           17 AIBotsConfig       18 EnergyConfig      19 CurrencyConfig
```

⇒ 只有前面的 11 个全部成功，`Templates` 才登记得上。

### 2.3 附带确认：静态 `Configs` **不会**在场景切换时被清空

Intro 卸载后探针读数仍是 `Configs={count=20 …}`（`config.tsv` TICK 行）⇒ `ConfigProvider<T>.OnDestroy` 不清静态表，
所以「登录场景配好、进主菜单丢了」这条假设**不成立**；真正原因就是 2.1 的中断。

## 三、修法（已落地）

新增 `E:/warpforge/05_工具/server/tools/add_all_configs.py`：把 **20 个键**一次性写进
`responses/ExecuteCloudScript.InitializeLiveOps.json` 的 `FunctionResult.TitleData`（登录片段同步一份）。

- 键名 = 各 Config 类的 `ConfigKey` 属性真值（`cpp2il/out_cpp2il_dev_ilspy/*.cs` 的 `return "…"`）：
  `ShopConfig · WildcardConfig · CardTierConfig · PointsConfig · DailyStoresConfig · PremiumConfig · MissionsConfig ·
   FeatureConfig · CloudscriptRestrictedVersionConfig · EventGroups · LeaderboardConfig · Templates ·
   AlliancesConfig · ReferralConfig · GameModesConfig · CardsSpecialConfig · ItemsConfig · AIBotsConfig ·
   EnergyConfig · CurrencyConfig`
- 值一律最小合法 JSON：绝大多数是 `{}`（配置类都是「对象 + 列表字段」）。
- **唯一例外 `DailyStoresConfig`：值是字符串数组 `[]`，不是对象**。
  判据 `DailyStoresConfigProvider.UnpackInternal`：`DeserializeObject<List<string>>(titleData["DailyStoresConfig"])`，
  再对每个元素 `titleData[x]` 反序列化成 `DailyStoreState` 建 `Stores`。
  ⚠️ 给 `{"dailyStores":[]}` 会抛 `JsonSerializationException: Cannot deserialize the current JSON object … into List<string> … Path 'dailyStores'`（本轮实测）。
- 脚本默认空跑，`--write` 才写，首次写先备份 `.bak_before_allcfg`。

## 五、同夜第二个根因：登录拆包链断在 `UnpackUserProfile`（库存/卡组根本没解包）

收藏窗在配上 20 份配置后**仍会卡在下一个 provider**：`DeckAssetProvider.GetAssets()` 抛
`KeyNotFoundException: 'CardDeck'`（`windows.tsv` 19:25:08）。原因不在 provider 本身 ——
**`InventoryManager.inventories` 是空的**（探针 `inventory.tsv`：`inventories=count=0`），
即 `PlayerDataManager.UnpackInventory()` 一次都没跑。

判据链：
- `PlayerDataManager` 的登录状态机（`ProcessingPlayerData`，`PlayerDataManager.cs:4570-4600`）顺序是：
  `configs.Unpack(TitleData)` → `await liveOps.Unpack(HandlerData)` → `UnpackUserProfile()` → **`UnpackInventory()`** → `AlliancesManager.Initialize` → `PreloadLeaderboards()`。

  我们假服务端的 `AccountInfo` 只有 `PlayFabId / TitleInfo / SteamInfo`，**没有 `PrivateInfo`** ⇒ NRE ⇒
  整个 async 方法当场抛，后面 `UnpackInventory()` 永远到不了。`WF_OFFLINE_FINISH` 的强制收尾把状态推到 50，
  **把这条异常完全掩盖了**（`login_states.tsv` 表现为 state 20 卡 16 秒后被强推）。
- 探针实证（`inventory.tsv`，2026-11-06 19:30 一轮）：
  - 修前：`PDM-IN` 一条都没有，`inventories=count=0`；
  - 修后（补 `"PrivateInfo":{"Email":""}`）：`PDM-IN UnpackUserProfile` → `PDM-OUT` →
    `PDM-IN UnpackInventory` → `DESC-IN DeserializeInventory` → `DESC-OUT inventories=count=61`。

修法：`server/responses/fragments/playfab_profile.json` 的 `InfoResultPayload.AccountInfo` 加
`"PrivateInfo": {"Email": ""}`（已落盘，备份 `.bak_before_privateinfo`）。

## 七、模式卡：`Persistence` 必须带 `IsActive:true`（2026-11-06 实测通过）

修好上面两条后主菜单中间仍是空的。根因（`判据/B155_D_模式卡为空的根因.md`）：
`GameModes.RawEvents[*].Persistence` 原本是 `null` ⇒ `LiveOpsEvent.ValidateEventData` 新建存档，
而 `LiveOpsEventPersistence` 默认 `IsActive=false` ⇒ `BuildHandler` 的活性闸把事件全丢进 `blockedEvents` ⇒ 主菜单 0 张卡（静默）。

修法：`server/tools/add_event_persistence.py` 给三条事件补
`{"$type": "<事件的 TSave>, Assembly-CSharp", "eventId": …, "IsNew": true, "IsActive": true}`。
`$type` 必须与事件声明的存档类型一致，否则 `save is TSave` 不成立、新建存档会**丢掉 IsActive**：

| eventId | Data `$type` | Persistence `$type` |
|---|---|---|
| OfflineClassic | `RankedV2Data, Assembly-CSharp` | `Everguild.LiveOps.RankedV2Save, Assembly-CSharp` |
| OfflineSkirmish | `RankedFastModeData, Assembly-CSharp` | `FastModeSave, Assembly-CSharp`（全局命名空间） |
| OfflineDraft | `Everguild.LiveOps.DraftEventData, Assembly-CSharp` | `Everguild.LiveOps.DraftEventSaveGame, Assembly-CSharp` |

实测：主菜单出现经典 / 小冲突 / 轮抽三张模式卡（截图 `07_产物/phase0/shot_before_collection.png`）。

## 十、练习局 `StartMatch` 的 NRE：事件按 priority 抢「当前事件」（2026-11-06 探针实测）

探针读数（`phase0/practice.tsv` 19:44:56）：
