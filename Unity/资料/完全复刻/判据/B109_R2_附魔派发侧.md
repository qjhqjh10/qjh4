## §0 一句话结论

1. **原版这条路是真的**：`RawCardScript__TriggerAbilities` 体内**内联**了附魔趟。给定 trigger 数值，它遍历载体
   `activeEnchantments(+0x110)`，对**每件附魔卡的每条 `cardAbilities[]`** 过 `CanTriggerAbility`
   （判据 = `ability.trigger(+0x10) == 传入值`），过了就 `TriggerAbility → PlayAbility`。
2. 🔴 **行号订正**：附魔趟**不是** `:47-108`，而是 **`:49-197`**（`LAB_18094b822` 起），派发调用在 **`:184-186`**；
   `:47-48` 只是「跑不跑载体自己那一趟」的闸。
3. 🔴 **「数据位 ability：只发信号 + 入队、不跑正文」这条分支，原版【没有】**。过闸就 `TriggerAbility`，
   由 `ability+0x50` 的逻辑行走 `PlayAbility` —— **没有「只发信号」的档**。那一档是我们因为「数据行没有执行器」
   而造的**逼近物**，⛔ 别写成原版行为。
4. **`emitSignal` 的 CardId**：原版这一刻发**两条**表现信号、用**两张不同的卡**：载体侧
   `PlayTriggerTraitAnim(bm, 载体, 1, trigger, …)`（`TriggerAbility.c:58-63`）；能力侧
   `PlayAnim(附魔卡那条 ability 的 AbilityLogic, …, thisCard=载体)`（`:73-106`）——**动画资产取自附魔卡**。
   ⇒ 「CardId 改成附魔卡」**只对第二条成立**；我们只有一条 `EvtKind.Trigger`，取舍见 §3·3。
5. **施工单落点**：`RuleEngine/Core/EffectResolver.cs` 的 `FireTriggerByNumberWithSink`（`:20995`），
   插入点在 **`:21007` 之后**；新增私有方法**追加到类尾**（`:21046` 前），零账漂移。
6. **影响面极小且可枚举**：现池能当附魔挂上、且带**非 0 trigger** 的模板**只有 `Pray Enchantment`**
   （`Reconnaissance Mission` 只有 trigger 0；4 张 `Mark of *` `owners = 0` 不可达；其余 79 个模板不在池）
   ⇒ 本改动**今天只让一个 (卡, trigger) 组合变**：`Pray Enchantment @ 60 UnitDamaged`。

```csharp

        /// `RawCardScript__TriggerAbilities.c:49-197`（`LAB_18094b822` 起的共享尾块）的等价物。
        /// 逐条落法：`:50-53` 空表/`param_11` → `:59-65` 逐件 → `:66` `IsSpentEnchantment`

        /// （`:184`；`TriggerAbility.c:73-106`），我们只能跑**文本 op**；数据行（`chosenAbility 340` 等）的

        /// ability（`:74-192` 全跑），我们按「一件附魔一发」（文本 op 表本来就按 trigger 合并）。
        /// 🧨 灭自证：删 `EmitCardTrigger` 那行 ⇒ A2 红；删 `AllSpent` 那行 ⇒ A4 红。</summary>
        static int FireEnchantmentAbilitiesByNumber(BattleContext ctx, UnitState u, int triggerNumber, string tn,
                                                    int owner, int slot, UnitState actingCard, UnitState targetCard)
        {
            if (u == null || u.Instance == null || !Enchantments.HasAny(u)) return 0;   // 原版 `:50-53`
            // 原版 `:71` 判的是**附魔卡自己**的 `cardAbilities[].trigger`；`MatchingForInstance` 的 ① 支
            // 就是「数据位 OR 正文」（`Enchantment.cs:1149`，与 `Matching` 同一口径）。
            var hits = Enchantments.MatchingForInstance(u.Instance, tn);
            if (hits == null || hits.Count == 0) return 0;
            hits = Enchantments.FilterByQuestCounter(ctx, u, hits, tn);                 // 原版 `:115-116`
            int fired = 0;
            for (int i = 0; i < hits.Count; i++)
            {
                var e = hits[i];
                if (e == null || e.Card == null) continue;
                if (Enchantments.AllSpent(u.Instance, e.Card)) continue;                // 原版 `:66`
                // ① 表现那一拍（原版 `TriggerAbility.c:58-63` 的载体脉冲 + `:73-106` 的能力动画）：
                //    `EmitCardTrigger` 的 CardId = **附魔卡名**、`Player/Slot` = 载体（= 原版 `AbilityData+0x10`）；
                //    `HasTriggerSource` 自动过掉「这张卡有没有这条 ability」（= `CanTriggerAbility.c:71`）。
                EmitCardTrigger(ctx, e.Card, owner, u, tn, tn.ToUpperInvariant());
                fired++;
                // ② 正文那一半：今天只有**文本 op** 能跑（见 doc ①）
                var eops = e.Card.TriggerOpsByNumber(triggerNumber);
                if (eops != null && eops.Count > 0)
                {
                    EnqueueAbility(ctx, TriggerLaneOfCard(e.Card, tn), u.Name + "·" + e.Card.Name + "·trigger#" + triggerNumber,
                        () => ResolveWithTriggerTargetSink(ctx, null, () =>
                        {
                            using (EventSlotsScope.TargetCardAndActing(ctx, targetCard, e.Card, actingCard))
                            { ctx.EffectChain++; try { ResolveOps(ctx, owner, u, eops, tn.ToUpperInvariant(), chosen: targetCard); } finally { ctx.EffectChain--; } }
                        }),
                        actor: u,
                        requireActorInPlay: ActorMustBeInPlayForTrigger(e.Card, tn, null),
                        // 原版 `CanTriggerAbility.c:126` 的 `IsRightContext` 看**载体**、读**附魔卡的行**
                        abilityContext: AbilityContextOfAbilityV14(e.Card, tn, null),
                        abilityTrigger: tn, abilityTarget: targetCard, abilityHostCard: e.Card);
                }
                ctx.Log($"{u.Name} 身上的附魔「{e.Card.Name}」触发 {tn.ToUpperInvariant()}"
                      + "（原版 `RawCardScript__TriggerAbilities.c:108/184` 的附魔趟）");
            }
            return fired;
        }
```

### 3·3 「`emitSignal` 的 CardId」那一问（独立、可选的一笔）
现 `RuleCore.cs:12774-12776`（`FireTriggerAt` 内）固定 `u.Name`。按 §1.7：**能力动画**用附魔卡、**载体脉冲**用载体 ——
一条事件只能二选一。建议 `only != null ? only.Card.Name : u.Name`。
* 用 **`.Name` 不是 `.Id`**：`BattleEvent.CardId` 的既有约定是**卡名**；`VfxMap.FindCardRow` 两者都认，
  但 `VfxFactionOf` 的格位守卫与 `HandCardViewOf` 都按名字比 ⇒ `.Id` 会多绕一圈。
* ⚠️ **今天零可观测**：关键词路能挂上的附魔同样只有 `Pray`/`Recon`，而 60/31/0 在 `FireTriggerAt` 的词表里
  没有对应关键词 ⇒ 那趟递归今天一次都不进。**改动是结构性的**。

### 3·4 顺带（判据已定，另立账、⛔ 不并进本笔）
`RuleCore.cs:12891-12894`：`FireTriggerAt` 在 `only != null` 时把 `_abilityCtx` 写死 `Unknown`（**跳过** `IsRightContext`），
