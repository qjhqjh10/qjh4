## 三 · 未修但判据已定（落点在 `BattleDriver.cs`，本代理无写权 —— `WBD` 独占）

### 补丁 ①（可立刻做，**行数守恒**，安全）
```csharp
// BattleDriver.cs:15693  现在：
if (selector != null) { selector.SetSelected(kind); selector.Hide(); }
// 改成：
if (selector != null) selector.SetSelected(kind);   // ⛔ 不在这里 Hide —— 原版选择器活到 StopTracking
```
**为什么安全**：两条收尾都会把选择器关掉 —— 结算路 `DoResolve` 末句 `ClearSelection()`（`:16435`），
取消路 `CancelTargetChoosingByInvalidClick` → `ClearSelection()`（`:14905`/`:15006`），
而 `ClearSelection` 里本来就有 `if (selector != null) selector.Hide();`（`:16634`）。
⇒ 效果 = 原版 `StopTracking`（**同时**关准星与选择器）。

### 补丁 ②（需要回归面评估 + 跑 `BattleScene.Run`）
`OpenCommand` 起手（`:15226` 之后、`_selectedSlot = slot` 那一带）补一句「把上一次的打法当作当前指令」：
```csharp
_command = KindOf(u.LastAttackType);   // 0 ⇒ None（原版那一档 attackType 也是 0，照样能结算）
```
理由：原版 `StartAttackFrom.c` 起手就把 `card.attackType` 交给准星与 `case 6` 的结算；
我们不这么做 ⇒ 快速拖过三颗钮就**整条链静默无反应**（见 §〇 ②）。
⚠️ 副作用面：`IsTargeting` / `IsScreenPointOverCommandTarget`（技能面板捕获区）/ `SetReticleTarget` 的
`_command != None` 闸 / `DamageEntriesFor` 都会跟着变成「起手就算在选目标」——
**这正是原版的样子**，但会动到 `T09` 那几条既有断言 ⇒ 必须整跑一次 `BattleScene.Run`。

### 补丁 ③（依赖 ①+②，否则会把「用近战再打一次」锁死）
`AttackSelector.Selectable`（`:1581`）补原版第一句闸：
```csharp
if (opt.Kind == _selected) return false;   // 原版 `AttackButtonClick.c` 第一句 `attackType == param_2 ⇒ return`
```
⛔ **单独上这一条 = 回归**：我们的 `_command` 只有悬停才会设，锁掉「已选那一档」等于
「上一手用近战 ⇒ 这一手再也选不了近战」。**必须先做完 ①②**。

## 六 · 顺手发现（未改，供调度台分流）

1. **`BattleDriver.cs` 的 `HighlightTargetsCore` 不把「上一档合法、这一档不合法」的卡刷回 `Normal`**
   —— 它只给合法的那几张 `SetHighlight(ValidTarget)`，其余一概不碰（只有 `ClearTargetHighlights` 会清）。
   今天不出事是因为「换打法 ⇒ 必然先 `ClearSelection`」；一旦有人加「不离开选目标态就换打法」那条路，
   会留下**过期绿环**。判据 = 原版 `ShowPotentialTargets` 前总会先 `StopShowingPotentialTargets`。
2. **`TargetReticle.Build()` 里 `Hide(true)` 会把 `Cursor.visible` 拨成 `true`** —— 如果将来在瞄准中途
   重建准星（`Rebuild` 类路径），系统光标会闪回来一下。
3. `AttackSelector` 的 `_badgeSized` 是**新加的实例字段**（类尾）；它与 `ClearPieces` 的清零绑在一起
   —— 以后若有人再加「重建标签」的路，别忘了同步清它（⛔ 否则新标签会沿用旧标签的「已定过字号」标记）。
