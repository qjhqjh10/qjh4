## 4 · 顺手发现

1. **`EventTiming.TriggerHold`（0.3）已是死常量**：全仓只有声明（`EventTiming.cs:958`）+ 注释提到它，
   `DelayBetween` 的 `case EvtKind.Trigger` 已改成 `return 0f`（`EventTiming.cs:424`）。
   ⚠️ 留着不是零成本：名字很诱人，将来有人「按名接线」就会把 2026-11-03 刚修掉的 0.3N s 白等接回来，且**没有任何断言会红**（§2-12）。
2. 🔴 **2026-11-02 就地订正（铁律 5）：原文写「`MultiCardDisplay` 我们**硬夹**（Clamped），真缺陷未修」—— **已过期**。**
   `B118-W3` 当天就按原版改成了 **Elastic**：`MultiCardDisplay.cs:963` 拖动不再夹 · `:973-981` 越界走
   `Mathf.SmoothDamp(_scrollPx, bound, ref _scrollVelPx, ScrollElasticity=0.1)` 回弹（≤0.01 px 吸附）· `:1278` `ScrollElasticity = 0.1f`；
   `Editor/BattleScene.cs` 那条「夹回 0」的旧断言也已同批改成「按住越界 + 松手 60 帧回弹 < 0.05」。
   ⇒ 本行从「真缺陷」改判 **✅已修**（判据 → `判据/B117-G10-14_选牌与多卡展示.md:25`）。
3. 🔴 **2026-11-02 就地订正（铁律 5）：原文写「战斗 HUD **没有**『手牌区放大 1.365』那一档」—— **已过期**。**
   `B118-W1` 同一天落进 `BattleDriver.ApplySmallScreenHandScale()`（调用点 `:4980` · 实现类尾 `:41045-41070`）：
   把 `HandLayout` 的**卡尺度 / 基线高度 / 悬停抬起量 / 小屏档横向跨度上限**四格一起 ×1.365，基值只抓一次（幂等）、
   只在 `SmallScreenUI.Enabled` 时生效。`CombatAutoZoom.cs:736-739` 那段自陈也已同步订正。
4. **注释里的 `.c` 短名会让 grep 落空**：`EventTiming.cs:423` 写 `_ResolveTriggerTraitAnim_d__476.c:11-14`，
   真文件名是 `BattleManager._ResolveTriggerTraitAnim_d__476__MoveNext.c`（`decomp_full/` 里按短名搜 = 0 命中）。
   本台账已按真名记录；建议全仓扫一遍这类短名（同族坑：铁律「文件名与内容不符」那一族）。
5. **`BattleScene.cs:229` 的 `HandScale = HandLayout.DefaultCardScale` 是自证型夹具**：
   它把实现常量拿来做夹具，§2-2 那条因此永远抓不到回归。
6. **本台账**只覆盖任务书点名的五类；**卡面字号 band 的实际生效值**（`NameUnitBandMax` 1.595 / `DescUnitBandMax` 1.560）
   都带「shipped 实拍校正系数」，那是**按截图反推**的修正——铁律 3 说截图只能验收不能定参数，
   这两格属于**已知的例外**（原版 TMP autosize 上限拿不到，只能实拍标定），建议在账里保留该性质说明。
