### 3 · 摇骰 —— ✅ 三条都成立

**① 独立 RNG（不污染战斗随机流）✅**
* `BoosterTables.RollPackIds`（`BoosterTables.cs:281`）**自己** `new System.Random(seed)`；
* `BoosterOpenOwned.TryOpenDropTable`（`:96`）要求调用方**传入**一个 `System.Random`；
* 五个 booster 文件**全仓 0 命中** `ctx.Rng` / `Ctx.Rng` / `RandomNumbersIndex`（`grep` 过），也**没有 `UnityEngine.Random`**（唯一一处在注释里）⇒ 与战斗引擎的预烧表**完全隔离** ✅

**② 同 seed 可复现 ✅** —— `System.Random(seed)` + 固定遍历序（卡位 0→4、表内按行序）⇒ 同 seed 同表必然同结果。
⚠️ 但 `TryOpen` 的 `<param name="seed">` 注释写「调用方一般传 `Time.frameCount` 之类」（`BoosterOpenOwned.cs:56`）—— 那个**每次不同、不可复现**。开包**本来也不需要**复现，但别把那句话当「可复现」的判据；真想要可复现就得传会话 seed。

**③ 权重 0 / 负权重不会被选中 ✅**
* `WeightTotal`（`:203-209`）**只累加 `weight > 0`**；
* `PickWeighted`（`:213-230`）主循环 `if (e == null || e.weight <= 0) continue;` ⇒ 0 与负数都不会被返回 ✅
* ⚠️ **一处不可达的兜底**：主循环理论上到不了，但它万一走到时的兜底（`:226-229`）只挑「最后一个非空 id」，**不看权重** ⇒ 会返回 0 权重项。构造上不可达（`r < Σ正权重`），记一笔即可。

### 4 · 回滚 —— ✅ 是真的回滚（不是只打日志）

**⚠️ 两处小隐患（不阻塞）**

1. **第二支回滚的落盘结果被丢掉**：`:85 BoosterInventoryStore.SaveContainers();` 没看返回值。若这次「退回 +1」也没落盘成功 ⇒ **内存 +1 / 盘上 −1**，下次启动少一包。这是**唯一一条**能留下不一致的路径（罕见：要先落盘成功扣 1、再摇空、再落盘失败）。建议：失败时 `Note(...)` 出声（一行）。
