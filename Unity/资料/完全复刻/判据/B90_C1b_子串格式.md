## §1 `GetWarlordDataString(bool isPlayer)`

**格式**：`idg:<uniqueInGameID>,id:<uniqueId>,h:<CurrentIntrinsicHealth>,am:<CurrentIntrinsicMeleeAttack>,ar:<CurrentIntrinsicRangeAttack>,ca:<CanAttackNow>`
12 个字符串元素直接 `string.Concat`（`.c:21` 建 `new string[12]`；`:118` `Concat`）——**无序号前缀、无记录分隔、无尾随 `/`**。

| 段 | 字面量地址 | 值来源 |
|---|---|---|
| `idg:` | `0x18423C7D8` | — |
| `{idg}` | — | `heroCard.uniqueInGameID`（`+0x22C`，`.c:33`） |
| `,id:` | `0x184281FF8` | `heroCard.rawCardData(+0x28).uniqueId(+0x38)`（`.c:45-50`） |
| `,h:` | `0x184281EF8` | `heroCard.CurrentIntrinsicHealth`（`.c:62`） |
| `,am:` | `0x184281C08` | `heroCard.CurrentIntrinsicMeleeAttack`（`.c:77`） |
| `,ar:` | `0x184281D00` | `heroCard.CurrentIntrinsicRangeAttack`（`.c:93`） |
| `,ca:` | `0x184281E00` | `heroCard.CanAttackNow()` → `bool.ToString()`（`.c:110`） |

hero 取侧：`isPlayer==0 ⇒ enemyManager(+0xC8)`，否则 `playerManager(+0xC0)`；再 `.heroCard(+0x28)`（`.c:25-31`）。**无空值 fallback**（hero 为空即 NRE，原版假设督军恒在）。

**🔴 `CurrentIntrinsic*` 不是字段直读**（`EntityScript__get_CurrentIntrinsic*.c`）：

**`CanAttackNow()`（`.c:110`，是方法不是字段）**：`CurrentMeleeAttack<1 && CurrentRangeAttack<1 ⇒ false`；`isRemnant(+0x65) ⇒ false`；`HasCurrentTrait(150 cantAttack)` 或 `(880 nonCombatant) ⇒ false`；本方动作锁位（manager `+0x246`/`+0x244`）为锁 ⇒ false；`cardState(+0x228) ∈ {2 inPlay, 3 inPlayAttacking, 17 inPlayAminingAttack}` 才继续（player 时还要 `UIstate ∈ {1,6}`）；最后 `canAct(+0x230) && canAttack(+0x23C)`。（`CardScript__CanAttackNow.c:17-80`；trait 名 `dump.cs:45738` / `45807`）

## §2 `GetCardsPlayPlayer(bool isPlayer)` —— ⚠️ 语义与名字不符

**🔴 最重要的一条**：它**不是**「本局打出过的牌」，而是「**当前场上（含待死）的本方部队**」。数据源 = `BattleManager.unitsInPlay(+0x470)`（`List<CardScript>`，入场 `Add`、`DestroyUnitSilent` 里 `Remove`），按列表顺序遍历并按四条筛（`.c:62-95`）：
1. `card.isPlayer(+0x40) == isPlayer`；
2. `cardType` **不能是** `Hero(10)` / `Tactic(20)` / `Whispers(40)` ⇒ 只剩 `Minion(0)`（`dump.cs:45710-45718`）；
3. `IsInPlay()` **或** `cardState(+0x228) == waitingToDie(5)`（`dump.cs:45474`）；
4. 通过者先进 `tempUnitsInPlayList(+0x538)` 再 `AddRange`（`.c:102`）。

数据源写入点（顺序 = 入场顺序）：`_ResolvePlayCardFromHand_d__447:710` · `_ResolveSummonUnit_d__510:181` · `_ResolveCardAutoSummoned_d__511:284`；移除 = `BattleManager__DestroyUnitSilent.c:22-26`。

**格式**：`index:<idx>,idg:<uniqueInGameID>,id:<uniqueId>,h:<CurrentIntrinsicHealth>,am:<...>,ar:<...>,ca:<...>/`
每条末尾都有 `/`（含最后一条），多条首尾相接、**记录之间没有别的分隔符**（`.c:114` 建 `new string[16]`，`[0]` 是累加器；`:202` `Concat`）。

**🔴 `index:` 是「左/右 + 侧内下标」的有符号编码，不是格号**：
```
idx = MinionManager.GetIndexOfCard(本方 MinionManager, card)     // .c:126-134
  leftMinions(+0x60)  第 i 位（0-based）⇒ ~i（= −i−1，负数）
  rightMinions(+0x68) 第 j 位（0-based）⇒ j+1（正数）
  两表都没有 ⇒ 0
```
⇒ 左侧第 1 格 `-1`、第 2 格 `-2`…；右侧第 1 格 `1`、第 2 格 `2`…；督军/不在表 `0`。
⚠️ 与我们 `BoardSlots` **完全同构**（`BoardSlots.cs` 头注已记同一套 `~slot` / `slot-1`）：`ownSlot = 4 + 原版有符号下标`。
VA 复核：`0x1806297D0`（`80 629 89E: not ebx`）。

**空表**：`""`（`DAT_1842b80e0`；`:105` 列表空直接 return）。

**格式**：`index:<PositionInHand>,idg:<uniqueInGameID>,id:<uniqueId>/`（每条末尾 `/`；**无 h/am/ar/ca**）

## §6 与现有实现的差（B1 要改什么）

4. **Hand** → 现在是 `卡id#实例号` 逗号拼 ⇒ 换成 `index:<下标>,idg:<Instance.Id>,id:<Card.Id>/`。

## §7 顺手发现

1. **`GetCardsPlayPlayer` 名字骗人**：它枚举 `unitsInPlay`（当前场上单位），不是「本局打过的牌」。账上/我们代码把它当「出过的牌」理解，**语义就错了**。
2. **`index:` 是有符号编码不是格号**：左 = `~i`（负）、右 = `j+1`（正）、不在表 = `0`。写成 `slot` 或 `slot+1` 就错。好消息：`BoardSlots` 已记同一套编码，直接复用。
3. **`GetCardsDeckPlayer` 的 `inclWeapons` 是死形参** —— 抄签名时别为它编语义。
4. **ILSpy 与 Ghidra 在 Hand 构造器的读取顺序上直接冲突**，已按 `.c:51` 定案。
5. **空串 fallback 是 `""`，不是 `"-"`** —— 与我们现有实现不同。
6. **四个 builder 的「累加器」写法**：`arr[0]` 是「上一条累计串」，**不是字段**，别把它建模成一个真实前缀。
7. **`ca:` 是方法不是字段**：`CardScript.CanAttackNow()` 一长串，不能拿 `u.CanAttack` 一个 bool 顶替。

## §8 还差什么（调度台已裁见下）

1. **`GetCardsPlayPlayer` 的记录顺序**：原版 = `unitsInPlay(+0x470)` 入场序。**我们没有这条列表**。
   🔴 **调度台 2026-10-28 裁定**：本轮用「座位 0 左→右，再座位 1 左→右」的确定性顺序，差异列**必须**写：`顺序：原版 = 入场序（unitsInPlay +0x470）；我们 = 座位+槽位序。🔶 自己设计（无 unitsInPlay 对应物）· 调度台 2026-10-28 裁定`；并立一条待办「补入场序列表（仅当 `GetGameState` 被接上消费方时才影响输出）」。
   ⚠️ 现状：`GetGameState` 今天 **0 调用方**、无联机反解 ⇒ 不影响任何现有行为。
2. **`ca:` 的 bool 映射**：我们 `RuleCore.CanAttackNow(ctx,p,slot,ranged)` 返回**错误码**且分近战/远程两次；原版是**一个 bool**。
   🔴 **调度台裁定**：在 `RuleCore` 里加**一个** `CanAttackNowBool` 收口（⛔ 别在两个 builder 里各写一份），= `近战OK || 远程OK`，并在注释里写明「原版是一个 bool；我们按近战/远程两次取或，逐条对拍未做（原版的动作锁 + UIstate 那一半在我们回合制模型里无对应物）」。
3. **`CurrentIntrinsic*` 的 `Extrinsic` 覆盖度**：`UnitState.StatMod.Extrinsic` 注释自承「240 WhileInPlayVariable 那一档没有单独标」⇒ 若单位身上有 240 档 extrinsic addStats，`Intrinsic()` 会**少减**。属已知实现缺口（`UnitState.cs:1890` 附近），不是判据缺口。
4. **未复核**：`CanAttackNow` 里 manager `+0x244` / `+0x246` 两个「动作锁」字段的**字段名**（只取了偏移，语义从分支形状推的）。不影响格式串，只影响 `ca:` 值。
