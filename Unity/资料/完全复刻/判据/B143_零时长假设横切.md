## 3 · 🟠 可能偏（3 条，都给了「怎么看出来」）

### 3·1 先记两条**历史**（同类病，已修）—— 说明这个病真的会复发

| 档 | 曾经当 0 | 修它的判据 | 症状（当时） |
|---|---|---|---|
| `Return` | 是 | 原版 `yield` 两段（0.55 + 0.2 = 0.75）⇒ 搬进 `TimedKinds`（`ReturnHoldOf`） | 回手/洗回时下一件事在位移中途就开场 |
| `SabotageCreated` | 是 | 原版 `_ResolveCreateHandCard…:100-107` `yield return StartCoroutine(DisplayEnemyCardInCenter)` ⇒ **1.078 s** | 牌在中央展示**中途**就进手、玩家能在展示期间出牌 |

⇒ 本轮审计**没有再找到**第三例「原版真阻塞、我们当 0」。这两条列在这里，是给「以后加新 `EvtKind`」当模板。

### 3·2 🟠 `EvtKind.Play` = 0 对**战术卡**没有兜底

- **今天的判据只覆盖单位卡**：`ZeroDurationKinds` 里 `Play` 那行写的是「登场位移由**紧随的** `Deploy` 负责」。
- **但战术/防御卡只发 `Play`、不发 `Deploy`**：发出点两个 —— `RuleCore.cs:4092`（`PlayCard`，单位卡）与
  **`EffectResolver.cs:2712`**（战术那条）。后者之后紧跟的是战术正文的 `EvtKind.Ability` / `EvtKind.Trigger`。
- **今天为什么没出事**：战术卡打出当刻**没有任何占时的起手演出**（我们的表现层只在正文的 `Ability`/`Trigger` 拍上演）。
- **什么时候会出事**：给战术卡加任何「打出当刻」的起手（翻牌 / 抬手 / 卡面滑动）而**没有**同步给它一个时间载体 ⇒
  下一件事立刻开场。**看不出来的原因**：不报错、断言也不会红（`Play` 是「合法的 0」）。
- **建议（不是现在做）**：给 `Play` 加时间载体时，走 **`DurationOf(BattleEvent)` 里按卡分档**（
  `e.CardId` 是战术卡 ⇒ 取该卡的 `ThisCardPlayed` 首拍时长），⛔ 别把 `Play` 登记进 `TimedKinds` 一刀切（那会把单位卡的出牌也推后）。

### 3·3 🟠 `Trigger` 的 0.2 是**通用节拍**，不是逐卡真值

- 现读：`EventTiming.cs:680` 的注释自己写着「见 `TriggerLen`（有出处，但那两个常量是引擎的**通用节拍**，不是 Trigger 专用）」。
- 也就是说：**所有**触发事件都占 0.2 s，而原版每条触发的 `AbilityLogic.cardAnimations` 是**各播各的**（时长各不相同）
  ⇒ 长得像「用通用节拍近似逐卡真值」。今天无害（触发动画本来就没接，见 `判据/B143_AnimTrigger接线补丁.md`），
  **一旦接上就必须 `Mathf.Max(DurationOf(e), 拍时长和)`** —— 补丁里已经这么写了。
- **怎么看**：接上后打一张触发动画 > 0.2 s 的卡，若下一件事在动画中途开场 ⇒ 就是这条。

### 3·4 🟠 `skillAnimAt` 回填会贴到**将来展开出来的拍**上

`BattleDriver.cs:19752-19762` 那段 for 的条件是 `ps.evt.Kind == EvtKind.Trigger`；而 ANIM-TRIGGER 补丁展开出来的
每一拍 `PendingSignal` 的 `evt` **正是那条 `Trigger` 事件** ⇒ 会被贴上 `skillAnimAt`（`:19760`）。
`skillAnimAt` 的消费者在 `:23309` `float t0 = skillAnimAt >= 0f ? skillAnimAt - _clock : 0f;`（攻击技能动画那一支）。
- **风险**：若那一支对 `beat=true` 的信号也跑，就会**每一拍都重播一次攻击技能动画**（N 拍 = N 次）。
- **落地时要做的**：现读确认 `PlaySignal` 的 `beat` 分支是否早退；没有就在那段 for 里加 `if (ps.beat) continue;`。
  ⚠️ 今天**没有**这句（`beat` 信号在本轮之前不会出现在 `Kind == Trigger` 的集合里）—— 这是补丁落地前必须补的一刀。

## 5 · 顺手发现（⛔ 都没改）

1. `EventTiming.cs:1207` 的注释说 `Trigger` 那 0.2 是「`BattleManager.twoFractDelay(+0x4C8)` = 0.2 —— `_ResolveTriggerTraitAnim` 那条链的等待」，
   而 `:680` 又说「不是 Trigger 专用」—— 两句都对，但**读起来像矛盾**；建议后者补一句「它同时是 `Trigger` 的工作值」。
2. `DurationOf(BattleEvent)` 对 `Heal` / `Death` / `Trigger` / `DiscardReveal` / `StealReveal` / `SabotageCreated` 直接落 `DurationOf(e.Kind)`；
   其中 `Heal` 的 `CardView.HealTextHoldSeconds` 是**表现层常量**（不是逐卡）—— 若将来原版治疗演出分档，这里会是同一类「通用节拍当逐卡真值」的坑。
3. 全仓 27 个 `EvtKind` 里 `SecretOrder` **0 发出点**、`WarlordTransform` 是 🔶 自设计 ⇒ 这两档的「零时长」永远不会被真实数据检验，
   别把它们的「绿」当成判据被验证过。
