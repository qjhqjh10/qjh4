## 2. `B142-ARENACARDSCALE-DUP` —— `ArenaCardScale` 与 `PoseFor` 的三支重复

### 2·1 原版判据

| 项 | 判据 |
|---|---|
| 三支缩放 | `d:/2/tools/decomp_full/BattleManager__GetUnitSizeInPlay.c`（`B117_G10_07` 现读）：`cardType == Hero(10)` ⇒ `heroScale` · `cardType == Minion(0)` ⇒ `desiredScale` · 其余 ⇒ `minionInPlayScale(0.75) × (enemy ? enemyUnitsScaleRatio 0.86 : 1)` |
| 我们落点 | `CardPresentation/Board/ArenaSlots.cs:90 CardScale` / `:92 HeroScale` / `:252 InPlayScale`（0.36/0.69 · 0.4/0.77 · 0.75/0.645） |
| 槽位合法性 | `RuleEngine/Core/BoardSpec.cs:41 IsValid(slot) { return slot >= 0 && slot < Size; }` ⇒ **只查边界，4 号督军格是合法值**（`IsDeployable` 才排 4，是另一个函数 `:36-39`） |

### 2·2 我们现在（两处各算一次）

| 位置 | 实现 | 独有的档 |
|---|---|---|
| `BattleDriver.cs:22162 ArenaCardScale(owner, slot)` | `warlord = slot == ArenaSlots.WarlordSlot` → 再 `u != null && u.IsWarlord`；`u != null && !u.Card.IsUnit` → `InPlayScale`；否则 `CardScale` | ① `slot == WarlordSlot`（即使 `u == null` 也给 `HeroScale`）② `u == null → CardScale`；⚠️ `u.Card` 为 null 时**会 NRE**（没有 `u.Card != null` 守卫） |
| `BattleDriver.cs:25788 PoseFor(mine, slot, u, …)` | `sc = PoseScale3D(u, foe)`（`:25796`）→ `PoseScale3DBranch(u != null && u.IsWarlord, u != null && u.Card != null && u.Card.IsUnit, foe)`（`:42463-42475`） | ③ `u == null → InPlayScale(0.75/0.645)`（= 非部队卡那一档）④ `u.Card == null` 有守卫 |

### 2·3 结论：那条判据**不是恒假**

- `ArenaCardScale` 的两个调用点：
  - `:22198`（`TryArenaIdealCardWorld`）—— 前置 `BoardSpec.IsValid(slot)`（`:22160`），**含 4**；
  - `:22254`（`FireHostFallbackVfx`）—— 只在 `useArena == true` 时走到，而 `useArena` 来自 `TryArenaGroundWorld` / `TryArenaCardWorld` / `TryArenaIdealCardWorld`，三者同样只要求 `IsValid`（含 4）。
  ⇒ **`slot == ArenaSlots.WarlordSlot` 可以命中**（例如给督军位播落地扬尘 / 攻击件退路）。
- 两条在**引擎可达状态**上大多数情况等价，因为 4 号格恒是督军（`PlayerState.Warlord` 与 `Board[4]` 同一对象、构造 `isWarlord:true`，`RuleCore.cs:640`；变身 `TransformUnit_B94B12.cs:251` 保留 `wasWarlord`）⇒ `PoseFor` 的 `u.IsWarlord` 也为真。
- 但两处**各有一档对方没有**，所以「合并成一处」若只是删掉 slot 判据，会改变行为：
  1. **`ArenaCardScale` 的 slot 档在 `u == null` 时仍给 `HeroScale`**；`PoseScale3D(null)` 给 `InPlayScale`。
  2. **`PoseFor` 的 `u == null` 档现在是 `InPlayScale(0.75)`，这是一条回归**：`BattleDriver.cs:13884 BuildDeployHandoff` 明确传 `u = null` 并注释「非督军走 `CardScale`」—— 但 E26 加第三支后 `PoseScale3D(null)` 变成 `InPlayScale` ⇒ **手牌出兵的落点预览缩放从 0.36 变成 0.75**（`OnDeployHandoff` 用它 `card.SetPose(aboveLocal, 0f, arenaScale)`，真落位会被 `SyncBoard` 再改回 0.36 ⇒ 可见的「落下时大一圈再缩回」）。`PoseFor(null)` 的另一处 `:39133` 也会受影响（空格位）。
  3. `ArenaCardScale` 的 `!u.Card.IsUnit` 没判 `u.Card == null`，而 `PoseScale3D` 判了 ⇒ 合并时要用后者那种空安全。

### 4·1 原版判据（逐句）

**由此推出的真实时间点**：`currentValue` 永远停在**上一次加点的累计值**（扣阈值那一跳静默）。下一次加点时 `TryDOVfx(新累计值)`：

- `新累计值 > 旧累计值` ⇒ 升向（`Quest UI Gain`）；
- `新累计值 < 旧累计值` ⇒ **降向（`Quest UI Trigger`）**；
- 相等 ⇒ 什么都不播。

> `currentValue` **不是 `[SerializeField]`**（`d:/2/Warpforge_code/Scripts/Assembly-CSharp/ManaTypeHolder.cs:43-44` 是裸 `private int`）⇒ 出厂 = 0，首跳必是升向（与我们的 `LastShownQuest = 0` 同口径）。

**降向是可达到的，而且很常见**：阈值 3，先 +3（累计 3、currentValue=3、余 0），再 +1 ⇒ 新累计 1 < 3 ⇒ 播 down。⚠️ **`BattleDriver.cs:33940-33955` 的 doc 写「`vfxOnValueDown` 那条路上永不触发」是错的**（反证见上；它把「扣阈值那一跳静默」误读成「永远没有更小的值」）。
