## 三、**判据未定 / 记下没做**（两条真差异，需要下一轮定口径）

### 3·1 🔴 战斗开场那两拍 **`SoundManager.ToggleSFX(false, instant:true)` → 下一帧 `ToggleSFX(true)`**（普查当时我们没有；判据见下，落点见 §3·1 末）

- **原版**：`T06d` §二 第 4/5 拍，出处 `BattleMusicManager._Start_d__13__MoveNext.c:34,37,50,55,60,65,69,85`：
  ```
  第 0 帧：noBattleMusic.TransitionTo(0f) ; SoundManager.ToggleSFX(false, /*instant*/ true) ; yield 一帧
  第 1 帧：SoundManager.ToggleSFX(true)   ; battleLow.TransitionTo(3.0f)
  ```
  `ToggleSFX(option, instant=false)` 的过渡 = `((instant?1:0)^1)*2f` ⇒ **重新开声是 2 s 的淡入**。
  ⇒ 原版战斗开头的 ≈2 s 里**整条 FX 总线是被压下去的**（不是零拍，是 2 s 的 duck）。
- **我们（普查当时）**：`BattleMusic.BeginBattle`（`BattleMusic.cs:149`）只做「瞬时静音 + 3 s 淡入 Low」，
  `WarpforgeAudio.ToggleSFX` 全工程**零调用点**（只在 `AudioSetup.Verify` 里被间接试）。
  🔴 **2026-11-02 已接（`B118_W10`）**：`BattleMusic.cs:154`（第 0 拍）/ `:160`（第 1 拍）/ `:265`（`OnDestroy` 兜底）
  ⇒ 生产调用点 **0 → 3**；断言 = `Editor/B118W10_Assert.cs`（待接线）。
- 🔴 **2026-11-02 就地订正（铁律 5 · `B118-J3` 回源现核）**：原来这里写「`useMultipleTracks == 0` 的 6 场组件是停用的、
  Unity 不会给停用的 MonoBehaviour 调 `Start()` ⇒ 那 6 场判不出来」—— **这个推理不成立**：
  · 13 场序列化**一律 `m_Enabled: 1` · `priority: 2`**（逐场现读 `bundle_scenes_scenes_battlearena*/MonoBehaviour/*.json`，13/13）
    ⇒ **加载时没有一个是停用的**；
  · 停用只发生在 `Initialize()`（`BattleMusicManager__Initialize.c:3` = `Behaviour.set_enabled(this, *(this+0x28))`），
    而它由 `SceneInitializer` 的 `InitializeBehaviours` 协程拉（`SceneInitializer.cs:540 Awake → :555 FetchAllInitializables →
    :606 StartCoroutine`），该协程 **先 yield、再按优先级枚举一组一帧**（`Data0/Manager1/UI2/AfterUI3`，`dump.cs:101215-101222`）
    ⇒ 到第 3 组才 Initialize；
  · Unity 帧序 `Awake → Start → Update → 协程续跑`，且 `enabled = false` **不停已起的协程**
    ⇒ **`Start()` 永远早于 `Initialize()`** ⇒ **13 场全部跑满两拍**，与 `useMultipleTracks` 无关
    （那个标志只关掉 `Update()` 里的 5 s 查档）。
  · 原句「`Initialize` 由 `BattleManager.OnInitializationComplete` 那条协程拉」**也是错的** —— 拉它的是 `SceneInitializer`。
- **"下一帧"是哪一帧**：`yield return new WaitForEndOfFrame()`（`_Start_d__13__MoveNext.c:88`，ILSpy `:160`）
  ⇒ **当前帧渲染完之后**（⛔ 不是 `yield return null`）⇒ 实听 = 「瞬间压到 −80 dB → 同帧末尾起 **2 s 淡回** 0 dB」。
- **改法**：`BeginBattle` 起手 `ToggleSFX(false, true)` + **下一次 `Tick` 最前面**（`_row == null` 早退**之前**）
  `ToggleSFX(true)` 与 `StartFade(Low, 3)` 同拍；⚠️ 解 duck 必须在早退之前，否则「BGM 表缺失」会把 FX 永久压住。
  另在 `OnDestroy` 加兜底（第 1 拍没解就销毁 ⇒ ⛔ 绝不把 FX 总线留在 −80 dB）。

### 3·2 🟠 `PlayNextSoundInQueue` 的**双重衰减**（原版把 FX 音量乘了两遍）

- **原版**：`BattleManager__PlayNextSoundInQueue.c`：
  `fVar5 = GameStaticData.get_SoundFxVolume()`（闸 `0 < fVar5`）→ `PlayOneShot(src, clip, SoundFxVolume * soundAsset.volume)`。
  而同一个 `SoundFxVolume`（`+0xd4`）**又是** `VolumeFX` 那根 mixer 参数的源
  （`PlayerDataManager__SetMusicAndFxVolumes.c` 第 4 句 `SetMixerVolume(mixer, 0, +0xd4)`）
  ⇒ 滑块拉到 0.5 时，原版战斗 cue 的实际响度 = **0.5（mixer）× 0.5（volumeScale）= 0.25**。
- **我们**：全局音量只在 mixer 上（`WFSoundPlayer.FxGroup`），`PlayOneShot(clip, cue 的随机 volume)`
  ⇒ 滑块 0.5 时 = **0.5**（比原版响一倍）。
- **为什么没动手**：还差一格 —— `BattleManager +0x90` 那颗 `AudioSource` **挂不挂 FX 组**没查
  （不挂 FX 组就只有 `volumeScale` 一次衰减，那我们就**已经对**）。查法 = 读 `BattleManager` 的 prefab / 场景实例
  那颗源的 `outputAudioMixerGroup`（或 `AudioSourceMixerGroupFixer` 挂没挂它）。
- **顺手一并订正**：`账/战斗逻辑驱动.tsv:465` 那句「我们用 `AudioListener.volume`」也是错的（见 §2·2 末）。
