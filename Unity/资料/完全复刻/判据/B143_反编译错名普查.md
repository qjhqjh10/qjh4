## 3. 方法：怎么判 ICF、怎么判错位

1. **预期名**：文件名去 `.c` → `<Class>__<Method>[__<args>]`；把 `.` / `<` / `>` / 空格 / `:` 统一成 `_`，再去掉导出器加的尾部地址后缀 `__<hex6+>`。
2. **实际名**：读文件前 20 行里第一个 `(` 之前的最后一个 token（兼容签名跨行：把非注释行拼起来再取）。
3. **✅ 一致**：两名字规范化后相等 / 仅大小写差 / 一方是另一方前缀（重载参数后缀）。
4. **⚠️ ICF / 桩**（满足任一）：
   - **同 class**（`Class` 前缀相同）—— 同类的不同方法共享体；
   - **同方法名**（`__` 后最后一段相同，大小写不敏感）—— 跨类的同名方法共享体（**这是简报里 `UIImageMaterialColorChanger__Awake` ↔ `UIImageGreyscaleController__Awake` 那一类**）；
   - **平凡体**：体 ≤4 句且无 `if/for/while/switch/goto/LAB_`（getter/setter/转发/空实现）；
   - **编译器生成符号**：`<>f__AnonymousType*` / `<>c*` / `System_Action<>` / `System_Func<>` / `SWIG` / `System_Collections_` 且体 ≤18 句；
   - 期望文件是迭代器/lambda/DisplayClass（`_d__` / `__c__` / `DisplayClass`）且体 ≤6 句。
5. **🔴 内容错位**：不同 class **且**不同方法名 **且** 不属于上面任何「平凡/编译器生成」档。
   - **A**：体与「实际第一行那个名字」自己的 `.c` **逐字节相同**（先去注释/空白）⇒ 可判定是 ICF 共享体，但**类/方法都不同**，按文件名读会读错类（简报第 7 例同型）。
   - **B**：体不同（或 canonical 文件不存在）⇒ 连 ICF 都不成立。
   - **A2/B2**：class 名互为包含（`Gradient2` ⊂ `Gradient`）、同泛型基名、或方法基名相同 ⇒ 疑似同族，**建议降 ⚠️**。
6. **❓ `FUN_`**：首行是 `FUN_<addr>`；按已知口径（2026-10-25 G7）多为「请求名含 `", "` 的泛型类方法」——本批 299 条里 **162** 条文件名含该净化形态，**137** 条不含（见 §4，需另查，⛔ 别一律归因）。
7. **为什么不能只看「名字不同」**：25,096 个文件里 **6,977 条**是名字不同但可验证的同族/平凡体；一律算错会把 28% 的产物误报。
