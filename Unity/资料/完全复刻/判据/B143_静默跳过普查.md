## 一 三类模式与判定口径

| 模式 | 形状 | 判定 |
|---|---|---|
| A · 块包断言 | `if (cond) { … Check/Eq/Near … }` | 前提不成立 ⇒ **整块断言不跑**；若外部无 `Check(cond)` ⇒ 🔴/🟠 |
| B · 单句包断言 | `if (cond)` ⏎ `Check(...)` | 同上（这就是 `B143_R1` E1/E2 的原形） |
| C · 早退 | `if (!cond) return;` 后面紧跟断言 | 早退本身没断言 ⇒ 后续关键断言不跑；**有 `SkipLine(...)`/`Check(false,...)` 的算 ✅** |

**「前提已断言」的判据**（把 🔴 降为 ✅ 的依据）：同一文件、候选之前 **≤200 行**、缩进不深于候选、且**含条件里的标识符**的断言行；或该断言消息里含「前提」。**另人工承认两种间接前提**：① 断言的是**派生变量**（`wbRow` 由 `hRow` 派生、`c3btn` 由 `c3hit` 派生 ⇒ 前提红时守卫也必不成立）；② `if/else` **两个分支都有断言**（含 `else CheckTrue(false,…)`）。

## 四 ✅ 可接受的典型（为什么机器/人工判它 OK）

1. **直接前提**：`Check(rp != null, "读得到 …（前提）")` 后 `if (rp != null) {20 条}`（`B120_W6_Assert.cs:180→201`）。
2. **间接前提（派生变量）**：`var hRow = FindChild(row,"Hit"); var wbRow = hRow!=null ? … : null; CheckTrue(wbRow != null, "行有点击区"); if (hRow != null) {5 条}` —— `hRow==null ⇒ wbRow==null ⇒ 前提红`（`MainMenuScene.cs:10943-10961`；`c3hit/c3btn` 同形，`:6283-6305`）。
3. **两分支都断言**：`if (GrabScreen501.Enabled) {6 条} else {7 条}`，且默认档还**打警告说开档那半没跑**（`B110_R17_Assert.cs:124`）。
4. **否定断言**：`if (q == null) CheckTrue(false, "…拿不到 ⇒ 下面四条没法量") else {4 条}`（`CollectionScene.cs:2928/3397/3419` · `ShopScene.cs:2822/3959`）。
5. **显式 SkipLine + else**：`if (rt.ActiveTab != 0) SkipLine("…跳过") else {…}`（`B141_W29_Assert.cs:200`）。
6. **语义分支不是前提**：`if (isUnit)`（单位卡才有数值格）/ `if (cost < 0)`（无费用才不建费用圈，`else` 分支有断言）/ `if (flex)`（页面类型）—— 这些条件的另一侧**本来就不该有那些断言**。

## 六 脚本与复跑 / 边界

**算法**（`/tmp/wf_w3_scan9.py`，不进仓库）：
1. 遍历 `Assets/**/Editor/*.cs`（823 个）；
2. 逐行找 `if (...)`：① 同行 `if (cond) Check(...)`；② `if (cond)` 后接 `{…}` 块或**单条语句**（`stmt_end` 找深度 0 的 `;`）；条件跨行（括号不配平）跳过；
3. 块内匹配断言助手：`Check*` · `Assert*` · `Eq` · `Near*` · `Ok` · `Tr` · 以及 `.True/.False/.Eq/.Near/.Check/.Ok` 限定调用；块长 ≤30 行才收；
4. 早退型：`if (cond) return/continue/break;` 且**后 3 行内**有断言；
5. 前提判定：候选前 200 行内、缩进不深于候选、且与条件共享标识符（或消息含「前提」）的断言行 ⇒ `OK`，否则 `SUSPECT`。

**已知边界（⛔ 别把「没进清单」当成「没问题」）**：
- **不解析语义**：`if/else` 双分支、派生变量前提、`SkipLine` 都看不见 ⇒ **假阳性约 3/4**（高风险样本实测）；
- 🔴 **`else` 分支完全不读**（块提取只到 `if` 的 `}`）：`else Check(false, …)` / `else MarkUnverified(…)` 会被判成「没前提」——**本次 5 条假阳性全部是这一个原因**（`CollectionScene:7896` · `B142_E74:142` · `BattleScene:24086` · `B117_G10_18:228` · `BattleScene:31432`）；下一版扫描器必须把 `else` 一并提取；
- 断言助手表是**闭集**：本仓还有 `C(...)` / `MenuCheck.True` 之外的私有助手，可能漏匹配（漏了 = 少报，不是误报）；
- 只收**块 ≤30 行**的 `if`：包住整段测试的超大 `if` 不在清单里（那种更像「分段开关」，但同样会静默）；
- **早退型**只收「后 3 行内有断言」：隔得远的关键断言不算（会少报）；
- 多行 `if` 条件（括号跨行）整条跳过（会少报）。
