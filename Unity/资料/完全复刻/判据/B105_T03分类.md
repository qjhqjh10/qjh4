## 结论（一句话）

**两条都是「尺子假象」，不是「真缺」。**
具体类型 = **`LIT_MIN = 60` 的稀疏阈值假阳性**：两侧原始数据逐时刻几乎逐位相同（亮度和比值中位 **1.000 / 1.045**），
只是「亮点数」在 60 这条**硬闸**上下差 **1～3 个像素**，被判据分到了 C / D 组。
**⛔ 不要动任何资产 / shader / 导出器。** 要动的是台账的**分类判据**（`工具/analyze_sweep.py`）。

### Tidewall Gunrig

- **定性：尺子假象**（阈值假阳性）。**不是**「抓屏扭曲在对比管线里必然为 0」—— 导出侧在 6 个采样时刻都**有**内容。

- **证据**

  1. **原始数据两侧逐时刻几乎相同**（`资料/比对基线/sweep_orig.tsv` / `sweep_exp.tsv`，列 = `lit`/`sum`）：

     | t | orig `lit`/`sum` | exp `lit`/`sum` |
     |---|---|---|
     | 0.15 | 49 / 16 | 49 / 16 |
     | 0.30 | **62** / 22 | **59** / 22 |
     | 0.50 | **60** / 18 | **59** / 18 |
     | 0.75 | 41 / 11 | 41 / 11 |
     | 1.00 | 41 / 13 | 41 / 13 |
     | 1.50 | 39 / 12 | 38 / 11 |
     | 2.00 / 3.00 | 0 / 0 | 0 / 0 |

     两侧同时有内容的时刻 = `0.15/0.30/0.50/0.75/1.00/1.50`（**6 个**）；逐时刻 `sum` 比 =
     `1.000 / 1.000 / 1.000 / 1.000 / 1.000 / 0.917` ⇒ **中位 1.000、最大 |ln| 0.087**。
     判据口径：`工具/analyze_sweep.py:19-32` 明确写着「验收指标用 |ln(亮度比)|」，而本条 |ln| ≤ 0.087，
     **落在该文件自己公布的噪声底内**（同代码同资产连跑两遍：|Δ|ln|| 99 分位 **0.09**、最大 0.412 · `资料/比对基线/README.md:181-183`）。

  2. **台账那两列是「硬闸」造出来的**：`工具/analyze_sweep.py:62` `LIT_MIN = 60` → `:163`
     `exp_on = [s for s in samples if s[2][0] >= LIT_MIN]` → 导出侧峰值 **59 < 60** ⇒ `exp_on` 空 ⇒ `:174-175`
     `elif not exp_on: grp="C"` ⇒ 台账写 `导出有内容时段 = —`。**只差 1 个亮点**（256×256 画面里的一个像素）。

  3. **这个判定本身在两趟跑之间会翻面（不是「稳定的错」，是「不稳定的错」）**：同一批原始数据换一对文件重算
     （只读脚本，未落盘）——
     `sweep_orig_1021 + sweep_exp_normal_1021`（2026-10-21）⇒ 导出侧 0.30 是 **63** ⇒ 判 **Z**；
     `sweep_orig_baseline_1031 + sweep_exp_preforig_1031`、`…+ sweep_exp_builtin_1021`、以及**当前这一对** ⇒ 导出 0.30 是 **59** ⇒ 判 **C**。
     同一效果、同一尺子、只差 4 个亮点，**组别 C↔Z 翻转**。

  4. **历史结论早就定过这一条**（本次独立复核一致）：
     `资料/交接_第六十一会话.md:56`「C/D 四条：`Tidewall Gunrig` / `BulletTrail_Single` = `LIT_MIN=60` **假阳性**（判 Z、不重导）」·
     同文件 `:99`「C/D 还有 `LIT_MIN=60` 的稀疏阈值假阳性（Tidewall 59/60、BulletTrail 原版峰值 59）」·
     `资料/任务线/特效线/任务总表.md:166`（2026-10-21 受控重扫：台账 `C0`，原 C 组 8 条全部落到 Z/W）·
     `资料/普查产出_1021/W60_真机与Unity_结果.md:46`。

  5. **「抓屏扭曲在尺子上必然量不出」这条假设已被 2026-10-02 修掉，本条的成因不再是它**：
     `EffectSweepBatch.cs:111-136`（底图从纯色换成棋盘 plate）＋ `:611-626`（每时刻**渲两帧读第二帧**，
     让 `GrabPassTransparentFeature` 抓到当前帧而不是上一帧）。**实测旁证**：把 `per_effect_tech.json` 里
     `fam` 含「抓屏扭曲」的 **233 条**整体对拍，`|Δln(exp/orig)|` **中位 0.000**（1,081 个可比样本）
     ⇒ 这一族在现在的尺子上**两侧一样**，不是「必然为 0」。
     （`资料/特效还原_进度与交接.md:628-630` 那条「半透明灰方块 4612 亮点」是**旧空场景**口径，与本条读数 62 差两个数量级，不适用。）

  6. **导出侧根本没丢东西**：我们 `Assets/WarpforgeVFX/Prefabs/Tidewall Gunrig.prefab` 的组件数与原版
     `d:/2/tools/assetripper_out/ExportedProject/Assets/Tidewall Gunrig.prefab` **逐类相同**
     （`ParticleSystem` 198 ×**19**、`ParticleSystemRenderer` 199 ×**19**、`SpriteRenderer` 212 ×**1**）；
     22 个材质槽 / 18 个不同 `.mat` **全部解析得到**（缺失 0）；`m_Mesh` 15 处引用 2 个网格（`Quad` / `Sphere__cfcc67b4`）**全部存在**；
     抓屏那一支用的 `RippleNormal Distort.mat` → shader guid `7692e407…` = 我们自建的 `WarpforgeVFX/Shaders/WFDistortion.shader`（照原版 pass 状态硬编码混合，见该文件头）。

  `EffectSweepBatch.cs:638` 逐像素闸 `thr = 6/255*3` → `:675-679` 数出 `lit`（导出侧峰值 **59**）

### BulletTrail_Single

- **定性：尺子假象**（同一类阈值假阳性，但方向相反 —— 这次是**原版**侧峰值差 1 个像素）。

- **证据**

  1. 原始数据（`sweep_orig.tsv` / `sweep_exp.tsv`）：

     | t | orig `lit`/`sum` | exp `lit`/`sum` |
     |---|---|---|
     | 0.15 | 0 / 0 | 0 / 0 |
     | 0.30 | 12 / 9 | 13 / 10 |
     | 0.50 | 56 / 29 | 59 / 30 |
     | 0.75 | **59** / 18 | 62 / 19 |
     | 1.00 | 4 / 2 | 4 / 2 |
     | 1.50+ | 0 / 0 | 0 / 0 |

     逐时刻 `sum` 比 = `1.111 / 1.034 / 1.056 / 1.000` ⇒ **中位 1.045、最大 |ln| 0.105**（噪声底 99 分位 0.09，同一量级）。
  2. `工具/analyze_sweep.py:62` `LIT_MIN=60` → `:162` `orig_on` 空（原版峰值 **59 < 60**）→ `:172-173` `elif not orig_on: grp="D"`。
     **差 1 个亮点。**
  3. **跨 5 对跑法全部复现「D」，且数值几乎逐位不变**（`1021_normal` / `1021_builtin` / `1031_baseline` /
     `1031_preforig` / 当前）：原版 0.75 = **59**，导出 = **62** ⇒ 这是**稳定的**阈值假阳性（不是抖动），
     但结论同样错：原版明明有内容（0.50 起 56 个亮点）。
  4. **导出侧组件数与原版一致**：`BulletTrail_Single.prefab` `ParticleSystem` ×**9**、`ParticleSystemRenderer` ×**9**
     ＝ 原版 `d:/2/tools/assetripper_out/ExportedProject/Assets/BulletTrail_Single.prefab` **9 / 9**；
     9 个材质槽 **全部解析得到**（缺失 0）；`m_Mesh` 3 处引用 2 个网格（`Quad` / `Bullet_Body`）**全部存在**
     （即**没有**踩「`ShapeModule.m_Mesh` 没导」那个已知坑）。
  5. 「单帧旧判定 = 两边都空」**不是矛盾**：那是 `EffectCompare` 在 **1.2s** 采的单帧（`EffectCompare.cs:26-27`，
     `WFCMP_SIMT` 默认 1.2），而本效果**在 1.0s 就播完了**（台账 `导出有内容时段 0.75–0.75s`、原始数据 1.50 起两侧都是 0）
     ⇒ 1.2s 两边当然都是空。**两列是两种采样口径**，单帧那一列本身还给了 `cover_orig=0 / cover_exp=0 / l1=0.0`
     （`资料/比对基线/per_effect_metrics.json`，该文件自述「已废弃，只作旧判定对照列」→ `README.md:19`）。

- **对比管线在哪一步把它变成「只有导出有内容」**：
  `EffectSweepBatch.cs:638/675-679`（原版峰值 59）→ `analyze_sweep.py:62` `LIT_MIN` → `:162` `orig_on` 空
  → `:172-173` 组别 **D** → 台账「原版有内容时段 = —」。

- **下一步（命令级）**
  1. 同 Tidewall 第 1 条：改 `工具/analyze_sweep.py` 的 C/D 判据（加「另一侧峰值 `< LIT_MIN*0.6`」硬条件），
     改后 `D` 应为 0。**⛔ 不需要动这个 prefab。**
  2. 若还要逐槽隔离：**先解决 `EffectIso` 没有时间参数**这个问题 —— `EffectIso.cs:115` `const float SimTime = 1.2f;`
     写死且**没有** `WFISO_SIMT`（`EffectCompare.cs:26-27` 有 `WFCMP_SIMT`，这边没有）⇒ 对 1.0s 就结束的效果，
     隔离出来的每一槽都会是空图。**建议给 `EffectIso` 补一行 env 覆盖**（照抄 `EffectCompare.cs:26-27` 的写法），
     然后 `WFISO_SIMT=0.75 WFISO_FX="BulletTrail_Single" bash d:/4/Unity/工具/run_iso.sh both`。
     ⚠️ 这是 `.cs` 改动（不在本代理白名单），交调度台派写手。

- **还差什么判据**：无（定性已闭合）。
