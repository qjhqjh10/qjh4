## 〇、一句话结论

**练习局 = LiveOps 的 `PracticeEvent` 卡 → `Practice Mode Menu` 窗（`PracticeModePopup`）→ `MatchMakerManager.StartMatch(PlayModes.OfflinePractice, …)` → `BattleNetworkManager.MoveToBattleRoom`（置 `playingOffline`，**不建 Photon 房间**）→ `SearchOpponentManager.StartBattle()` → `EverguildSceneManager.LoadScene("Battle Arena …")`。**
它**不是** `DemoGameMode.Practice`；`DemoGameMode` 是另一套（`MainMenuDemoVersion` 系）已经不再挂在任何 prefab 上的死代码。

离线版要补的关键三块（缺一条都走不到战斗）：

1. **`GameModes` handler 里要真有一条 `PracticeEventData` / `eventId = "PracticeEvent"`**（卡片 + `GameModes.CurrentPlayingEvent` 结算用）。
2. **`playerDeck.gameMode` 指向的那个事件（经典 = `RankedV3Event`）必须带非空 `gameplayVariables`** —— `StartMatch` 从这里取 `MatchData.GameplayData`，**为空直接 NRE**（`MatchMakerManager.StartMatch` 里 `GetBaseData().gameplayVariables.alternativeTraitLogic` 那句）。
3. **`TitleData.AIBotsConfig` 必须存在且 `BotListFastMode` 非空**（练习局的 AI 牌组走的是 `GetFastModeBotConfig()` 这条支路），现在 TitleData 里**只有 `FeatureConfig`**，所以 `GetBotDeck(50)` 必然抛 NRE。

## 六、顺手发现

1. 🔴 **`MatchData.GameplayData` 的来源与直觉相反**：练习局的战斗参数**不是**来自 `PracticeEventData.gameplayVariables`，而是来自 **`playerDeck.CustomGameModeEvent`**（经典牌 = `RankedV3Event`）。⇒ 只给 PracticeEvent 加 `gameplayVariables` **没用**，必须加在 `OfflineClassic` 上。
2. 🔴 **练习局的 AI 牌组走 `GetFastModeBotConfig()`（`BotListFastMode`）**，不是 `BotList`（Ghidra `MatchData__GetBotDeck.c:34-78`）。填 `AIBotsConfig` 时两个 list 都填最稳。
3. `BattleNetworkManager.MoveToBattleRoom` 对 `playingOffline` 仍然会调 `PrepareToConnectToBattleRoom()`（C# 左侧先求值）⇒ 离线练习会**尝试一次 Photon 连接**。`MatchMakerManager.Initialize`（`MatchMakerManager.cs:245-249`）在启动时也已经 `StartConnection` 过一次。
4. `decomp_full` 里 `PracticeEventData.EnemyDeckAddressableIds` **0 个读点**（全库按字段名搜）⇒ 它是死字段，不用填。
5. `SceneTransitionList.asset` 的 `transitions` 是**空表**、`defaultTransitionScene = Simple Transition` ⇒ 所有场景切换都走同一个黑场；`scenesInBuild` 只有 `Reset Scene` / `Intro`，其余全 Addressables。
6. `BattleManager.IsNetworkedGame()` 对 `PracticeOffline` 恒 false，`IsAgainstAI()` 恒 true ⇒ 战场里那些 `IsNetworkedGame()` 分支（共 20+ 处）都可以放心跳过；`BattleCommsManager` 的 RPC 一次都不会发。
7. `PracticeModePopup.Open()` 里 `currentPlayMode` 初值 = **Skirmish**（`PracticeModePopup.cs:78`），而 `_defaultDeck` 的第一副是经典牌（`Demo DeckInfo UM 1`），两档的 `classicDeck/skirmishDeck` 都可能为 0（如教程牌 `skirmishDeck: {fileID: 0}`）⇒ 某些军队在冲突档下列表为空。
8. `Practice Mode Menu.prefab` 的 `decks` 数组约 78 项、`_defaultDeck` 是第 1 项 —— 也就是说**「选卡组」的候选与顺序完全由 prefab 决定**，服务端给不了（也不该给）。这解释了为什么原版练习窗在离线态也有牌可选。
