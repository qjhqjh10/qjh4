## 六、怎么用这张表开 501

1. **不需要逐件手改**：`GrabScreen501.UsesDistortion` 是**数据驱动**的（binder `materials[].shader` + 运行期 `shader.name`），开 `WF_GRAB501=1` 时 `FinalLayer` 会把上表每一件搬到目标层，`SetLayerRec` 递归整棵子树。
2. 表的作用 = **核对覆盖面**：若某件该挪却没被识别（例如 binder 材质丢了 shader 名），它不会被搬 ⇒ 会在默认透明 pass 和 501 各画一遍（扭曲叠两遍）。逐件核对「材质列是否等于预期」。
3. A/B 两跑（主对话 · Unity 全局串行）：同屏两个扭曲件叠加的场景，分别用 `WF_GRAB501=0/1` 各渲一次逐像素比。⛔ 别在批处理（sweep/自检）里开它 —— 没有帧循环时 `EnsureCameraSeesRelocated` 不跑， 效果会整块空掉（见 `GrabPassTransparentFeature.cs` 文件尾 ⑤）。
4. 层号不是原版值：原版 `UniversalRendererData` 资产本地没解出来 ⇒ 目标层是我们挑的（`DefaultLayer`）， `WF_GRAB501_LAYER` 可覆盖。

## 七、覆盖边界 / 没查清

- 「当前层」= prefab 自带层，**不是运行期真实层**（不跑 Unity 量不到；运行期由 `Play` / `FinalLayer` 决定）。
- 只认 `Assets/WarpforgeVFX/Materials/` 里能解析到 shader 的 `.mat`；运行期从 bundle 现取的材质若**没有**同名 `.mat` 资产，本工具看不到（本轮现读：233/233 效果都能解析到至少一个失真渲染器）。
- `m_CustomRenderQueue` 的原始值取自 `数据/游戏数据/mat_renderqueue.tsv`（全是 `-1`）；表里「当前队列」用的是 prefab binder 的 `renderQueue`（运行期材质重建时按它覆盖）。
- 引用卡只按 `card_vfx_by_card.json`（运行期那份）；不含立绘/语音/卡背引用。
- 场景静态引用只认 guid（`*.unity` / `*.prefab`，>64 MB 跳过）；`.asset` / Addressables 容器未扫。
- 🔴 **发现的文档不一致（只读记录，未改任何 .cs）**：`GrabPassTransparentFeature.cs` 文件尾「2026-10-25 起有自动档」那段写着「层默认 **31**」，而同一个文件的常量 `GrabScreen501.DefaultLayer = 9`（`ParseLayer` 都读它）⇒ **以常量为准，文件尾那句是过期的**。本表目标层按常量 9。
