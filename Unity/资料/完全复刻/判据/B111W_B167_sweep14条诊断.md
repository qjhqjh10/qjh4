## 〇、结论先行（一句话 + 三条硬事实）

**根因 = 我们对「原版 `m_ColorSpace=0`（线性/数据类）贴图」的导出版 PNG 存的是【sRGB 编码后】的像素，`.meta` 又写 `sRGBTexture: 1`。这个组合只在 Linear 工程里成立；切到 Gamma 后 sRGB 旗标失效 ⇒ 采样值 = `encode(原版原始值)` ⇒ 我们这边整片偏亮 1.2–3.3×。**

三条硬事实（都可复跑）：

1. **尺子没有整体漂。** 694 个可比效果（两侧都有 ≥60 亮点的时刻）的 **Δln 中位 = 0.0008**、均值 0.0263、**p90 = 0.031**、**p99 = 0.823**、max 1.433；**只有 23 个 >0.15**，而这 23 个里的前 **14** 名**正好就是本次的 14 条 E**。⇒ 切 Gamma 本身没有把整把尺子挪掉，**只有特定效果动了**。
2. **动的效果集中在「带非白 HDR 颜色属性」的那一小撮上。** 按材质色值分桶：`maxNonWhiteColor ≤ 1.2` 的 41 个效果 **0 个动**（median 0.0000）；`10–40` 264 个里 13 个动；`>40` 110 个里 5 个动。**14 条 E 的 Δln 全部排在全体前 14 名**。
3. **像素级坐实了贴图双编码。** 逐像素比「我们的 PNG」与「原版解码 PNG」：
   `ours == sRGB_encode(原始)` 的**平均绝对误差 0.19–0.29 /255**（`Noise Combined` 0.24、`burst_puff` 0.27、`RippleSubtle` 0.19、`Explosion Distort` 0.26、`SplatNormal` 0.25、`drops_cloud` 0.29），
   而 `ours vs 原始`直接比是 **8.6–64.8 /255**（`drops_cloud` 8.6 · `drops_dripping` 23.6 · `burst_puff` 30.4 · `Explosion Distort` 33.4 · `SplatNormal` 37.3 · `RippleSubtle` 39.9 · `Noise Combined` 64.8）。⇒ **不是元数据差异，是像素本身被 gamma 编码过。**

## 二、逐条根因

### 1. `Environmental Condition Dark Angels Asteroid Zone`（|ln| 1.175 · 偏亮 3.24×）

- **现读**
  - prefab：`MyGame/Assets/WarpforgeVFX/Prefabs/Environmental Condition Dark Angels Asteroid Zone.prefab`
  - 主导渲染器（`资料/比对基线/iso_stats_exp.tsv` slot 39）：`Background space noise`，`lit=44459`、`contrib=15314.4`，**占全效果 15,380.8 的 99.6%**；原版侧同槽 15,450.2（`iso_stats_orig.tsv`）⇒ **切 Gamma 前两侧几乎逐位相同**。
  - 材质：`WarpforgeVFX/Materials/Glow Space Dark Angels Asteroid Zone.mat` → shader `WFAlphaMasksTwoLayer.shader`（对应原版 `Everguild/FX/Alpha Masks Two Layer`）
  - 该材质贴图：`Noise Combined.png`（`_NoiseTex1` / `_NoiseTex2` 各一份）
- **推理**：`Noise Combined.png` 是 **ENC 类**（我们存的像素 = `encode(原版)`，`Noise Combined` 平均 0.599 vs 原版 0.345，逐像素 vs `encode(orig)` 误差 0.24/255）。原版这张是 `m_ColorSpace = 0`（linear，`iso.orig.log` 里 `Noise Combined{128x128,RGBA32,m1,s0,...}` 的 `s0`）。
  Linear 工程里我们的 `.meta` `sRGBTexture: 1` 会在采样时把它线性化 ⇒ 恰好抵消，所以切前对得上；切 Gamma 后旗标失效 ⇒ 采样值直接是 `encode(原版)`。
- **证据**：`sweep_orig_bak_before_fix.tsv` / `sweep_exp_bak_before_fix.tsv` 该效果 8 个时刻全部 0.878–0.891；`sweep_orig.tsv` / `sweep_exp.tsv` 同 8 个时刻全部 **3.19–3.28**（orig 亮度 9767→11100、exp 9788→11100 一路拉平，是**两侧同时漂、方向相反**的典型形状）。
- **判定**：**真缺陷**。建议按 §三 的修法处理 `Noise Combined.png`（**先核对它在这条里到底走 `_Blend_Color_Opacity=0` 的哪一支** —— `iso_orig.log` 显示该材质 `_Blend_Color_Opacity=0.0000`，即噪声那一路权重为 0；若确认为 0，则本条要改判「查不到」，见 §四·5）。

### 3·1 修法（资源侧，**一条命令级别的口径**）

**根因**：`WarpforgeVFX/Textures/*.png` 里有一批「原版 `m_ColorSpace = 0`」的贴图，被存成了 `sRGB_encode(原版)`，同时 `.meta` 写 `sRGBTexture: 1`。这个组合只在 Linear 下成立。

**正确修法 = 两步一起做，缺一即错**：

1. **把像素改回原版原始字节**：`p_new = linearize(p_old)`（等于把那次编码解掉），
2. **`.meta` 的 `sRGBTexture: 1 → 0`**（原版就是 `m_ColorSpace = 0`；`判据/B108_AUD09_纹理格式.md:55` 也是这个口径）。

⚠️ **只做第 2 步会坏**：那样 Gamma 下采样到的仍然是 `encode(原版)`，而 Linear 下也会变亮 —— **两头都不对**。
⚠️ 这条**推翻/补全** `B108_AUD09_纹理格式.md §3·2` 的写法：那里只写了「原版 `cs=0`、我们 `sRGB=1` ⇒ 应改 0」，**没有发现我们的 PNG 像素本身也不是原版字节**（B108 是用文件名 join meta 的，没比像素）。

## 四、顺手发现

1. 🔴 **`判据/B108_AUD09_纹理格式.md §3·2` 的处方不完整**（已在上文 §3·1 写清）：它只说「改 `.meta` 的 `sRGBTexture`」，而**我们那批 PNG 的像素本身是 `encode(原版)`**，只改旗标会把 Linear 也弄坏。建议在那份判据里就地补一条（本文件不动它，交调度台）。
2. 🔴 **切 Gamma 前，同一批贴图在 Linear 下是「靠 sRGB 旗标把编码抵消掉」才对上的** —— 也就是说**这批贴图从来就没有「按原版字节存放」过**，而是一直靠管线的隐式转换兜着。任何一次「重导贴图 / 换色彩空间 / 关掉 sRGB 旗标」都会把它掀开。这次是第三次踩同一类（前两次：`_EmissionColor` 乘黑、材质死值 `_SrcBlend`）。
3. **`Trail_fading.png`（ours/orig = 0.85，逐像素差 40/255）、`Shimmers01.png`（0.93）、`Smoke Tile Texture.png`（0.99）、`NoiseNRM.png`（0.83）** 是**另一类**差异 —— 不是 `encode(orig)`（对 `encode(orig)` 的误差 44–63/255）。这四张需要单独查来源（可能是同名不同 bundle 的变体，或导出时选错了源）。**它们出现在 Spore Launch / Void Combat / Daemonic Feast 三条 E 里**，可能是那几条的次要贡献项。
4. **`White Square_sprite.png` / `Glow_sprite.png` 在 `assets_full` 里找不到对应原件** —— 无法比对，本次无法判定它们的像素是否有问题。`AcidSpraySweepAttack`（最大的一条）就用了 `White Square_sprite`。
5. ⚠️ **`Glow Space *` 两个材质的 `_Blend_Color_Opacity = 0`**（实读：`WarpforgeVFX/Materials/Glow Space Dark Angels {Asteroid Zone,Void Combat}.mat:46` 都是 `- _Blend_Color_Opacity: 0`；`iso_orig.log` 的 Void Combat 那行也是 `_Blend_Color_Opacity=0.0000`）。
   按 `WFAlphaMasksTwoLayer.shader:206-213`：`rgb = C + _Blend_Color_Opacity * (ov - C)` ⇒ **权重 0 时最终色就是 `C = LinearToSRGB(_Blend_Color)`，与主图/噪声无关**；而 `_Blend_Color` 是 **HDR**（Void Combat `(0, 1.0554, 3.2205)`、Asteroid Zone `(0.7059, 0.1844, 0.0157)`）。
   **但噪声仍然起作用**：同文件 `:216-219` 的 alpha 是 `a = K · min(pow(n·K·_Alpha_Multiplier_2, _AlphaMultiplier), 1)`，`n = t1·t2` 就是 `Noise Combined` 的两个通道乘积；而混合是 `_SrcBlend=5(SrcAlpha) / _DstBlend=1(One)`（加色、按 alpha 缩放）⇒ **噪声偏亮 ⇒ alpha 偏大 ⇒ 整个色云更亮**。
   ⇒ Dark Angels 两条**同时**受两个机制影响：① `_Blend_Color` 走 `LinearToSRGB` 后的编码次数；② `Noise Combined.png` 双编码抬高 alpha。
   **本次没能分离这两个的权重**（要跑 Unity 或做单通道 A/B）。**修贴图后若这两条只回落一半，剩下的就是 ①**，届时按 `_Blend_Color` 那一支单独查。 —— 这是本报告唯一一处「归因需要分两步验」的地方。
6. **14 条里有 4 条在 `尺子不稳定名单.tsv`**（Raging Storm 0.412 · EC 2 Fumes 0.196 · Basic_army_Guard 0.172 · Asteroid Zone 0.056）。其中 3 条恰好就是「查不到 / 本来就偏」的那 3 条 —— **统计上自洽**：有资源级解释的都远远超过自身抖动（0.47–1.43 vs ≤0.06），没有解释的都贴着抖动。
7. **`BulletImpact_Spore Launch` 与 `BulletImpact_Spore Launch 1` 的内容几乎完全相同**（8 个时刻的 lit/sum 只差 1–3），做 A/B 或修完复测时**只跑一条即可**，另一条必然跟着变。
8. **本次没有跑 Unity**，所以「修完贴图会好吗」需要起一次 `EffectSweepBatch` 两趟（~25 分钟）来验。**预期的正确结果**：14 条里的 11 条回到 0.7–1.4 带内；若 Dark Angels 两条不动，按 §四·5 改判。
