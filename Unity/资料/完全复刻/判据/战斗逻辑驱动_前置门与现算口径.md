## 一、`CardScript.ContainsExtrinsicEffectFrom` —— extrinsic 去重闸

### 1·1 原版行为

**签名**（`.c` 4 参 / ILSpy 3 参 + 1 默认值）：

```

                                        BuffType buffType = BuffType.none,
```

**⇒ 去重键 = `(施放者 CardScript 实例, buffType, baseEnchantmentCard)` 三元组**，且**只对 `extrinsic == true` 的效果生效**。

- **不是按效果 id、不是按时间戳、不按 `effectName` / `effectText`、不按 `enchantmentCardId`**。
- ⚠️ `baseEnchantmentCard`（`+0x98`，`[NonSerialized]`）**必须是同一个引用**（含「两边都是 null」这一种）；从 `BattleManager.RemoveExtrinsicEffectsFrom` 与 `AbilityLogic.PlayAbility` 调用时都**传 null** ⇒ 那两处等价于「**只匹配 `baseEnchantmentCard == null` 的效果**」。

  · `effect+0x18 = abilityData.thisCard(+0x10)` ⇒ **`enchantingCard` = 这条能力所属的那张牌**（不是 `actingCard(+0x18)`）；
  · `effect+0x30 = (abilityData.whileInPlay(+0x40) \|\| abilityData.whileInPlayVariable(+0x41))` ⇒ **`extrinsic`**；
  · `effect+0x31 = abilityData.whileInPlayVariable(+0x41)` ⇒ **`extrinsicVariable`**；
  · `effect+0x98 = abilityData.baseEnchantmentCard(+0x28)` ⇒ **`baseEnchantmentCard`**；
  · `effect+0xa0 = thisCard.isPlayer` ⇒ `originalIsPlayer`；`effect+0xa4 = abilityData.enchantmentCardId(+0x4c)`。
  ⇒ **「extrinsic = 这条是【在场上才成立】（`WhileInPlay` / `WhileInPlayVariable）能力给的」**，这也解释了闸的语义：「在场上才成立」的效果会因为施放者还在场而被**重演**，所以要去重。
- ⚠️ 它**不比** `enchantmentCardId`、`doNotStack`、五个时长旗标 —— 那是 `CardEffect.IsSameEffect`（§一·3）的粒度。两把尺子**粒度不同**，别混用。

### 1·4 什么时候「清」（= 去重表什么时候空）

去重没有独立容器 —— **`activeEffects(+0x108)` 这条 list 本身就是去重表**。所以「清」= 那些条目离开 list 的任何一条路：

1. `CardScript.RemoveEffect(card, effect, …)` —— `CardScript__RemoveEffect.c:40-47`：`permanentBuff(+0x74)` 为真则**拒绝**（`:40-44`）；否则**第一件事**就是 `List.Remove`（`:47`），之后才按 buffType 反算数值。
2. 回合边界：`CardScript.ClearEndOfTurnEffects`（`CardScript__ClearEndOfTurnEffects.c:15-35`）—— 拾 `untilEndOfTurn(+0x32)` 的，走 `SendRemoveEffect(card, effect, 3)`。**其它四个时长旗标不在这一处清**（各由自己的触发点清）。
3. `CardScript.RemoveExtrinsicEffectsFrom`（§1·3）。
4. `CardScript.RemoveActiveEffects(buffType[, trait])` —— `AddEffect` 在 `70/85/95/9/4/3` 等档进门会先按 buffType 清（`case 3` 是 `RemoveActiveEffects(4)` **不带 trait 过滤**，`UnitState.AddKeyword` 里已照抄）。
5. 施放者离场/死亡/被 jam ⇒ `BattleManager` / `BattleManagerSupport` / `RawCardScript.TriggerAbilities` 那几条 `BroadcastRemoveEffectsFrom` 路径（`BattleManager.cs:23944` · `BattleManagerSupport.cs:46/56/66` · `RawCardScript.cs:1338` · `CardScript.cs:15905/20116`）。

### 1·6 差在哪（逐条，可复核）

1. 🔴 **结构性缺口：没有「效果记录」载体**。「去重」在原版是「在 `activeEffects` 里查有没有同键的一条」，我们的 `addStats` 一族**连一条记录都不留**（`ApplyOneGain` 直接把值写进 `u.Attack` / `u.Health` / `u.MaxHealth`，`EffectResolver.cs:11332-11390`）⇒ **不是加一个 if 能补的**，要先有表。
2. **即使有了表，键也不一样**：原版按 **实例引用**（`enchantingCard` = 那张 `CardScript`）；我们的 `RecordGrant` / `TempBuff` 按 **卡名字符串**。⇒ 同一个卡名出现在场上两张（`Wulfen` 三张那种）时，原版「两个来源各算一条」，我们会**并成一条**（over-dedupe）。
3. **`extrinsic` 我们只有「半条道」**：`HandEffect.Extrinsic`（`CardInstance.cs:211`）**存在且语义写对了**（原版 = `whileInPlay || whileInPlayVariable`），但
   · 只挂在 `HandEffects` 那一条 list 上（= 原版 `+0x108` 的**手牌加成那一族**）；
   · `whileInPlay` 这个**输入本地没有**（`EffectResolver.cs:5334-5346` 的注释现读：「只出现在签名桩，任何数据文件里都没有」）⇒ **今天没有任何调用点传 `true`**（那条通道**没有生产者**）；
   · `extrinsicVariable` 这一维**根本没建**（`EffectResolver.cs:5458`）。
   ⇒ 结论仍成立（**闸没有**），但原因**不是「完全没有这个概念」**，而是「概念只在一条窄通道上、且没有生产者」。
4. **`baseEnchantmentCard`** 没有对应物。
5. 三道相关闸里，另外**四道**也都没有（卡状态 / jam / 残骸 / 施放者不在场 —— 见 `报告/F_判据_第2轮.md` §⑤·5）。**E4 要一次补全五道，别只补 extrinsic 这一道。**

1. 🔴 **方向相反**。原版：`activeEffects`（表）→ `Current*`（投影）；我们：字段（真相）+ 一张只在「限时」时才有的旁账。

### 7·4 🔴 「`Health` 到期是**减**」vs 原版「**夹到新上限**」—— 最小可复现局面（验收用例）

### 7·5 `CardView.statBasesKnown` —— 填了之后会怎么变，以及和「换投影」的关系

**填了之后（`CardView.cs:3422-3435`）**：
- **基准未知（今天）**：只在「值变了」时 `FlashStat` 闪一下（2026-09-29 那套近似）。
- **基准已知**：走 `StatColorVsBase(StatCost/StatMelee/StatRanged/StatArmour/StatHealth, 当前值, 基准值)` ⇒ **持续态着色**（`CardView.cs:12953`）：受伤的生命**一直红**、被 buff 的攻击**一直绿**、回到基准才变白；同时「值变了」仍 `BumpStat`。
- 🔴 **多出来的一条原版行为**：**一张建出来就已经受伤 / 已被 buff 的卡，第一次就该是红 / 绿**（原版 `UpdateHealthText(doColorChange = 1)` 每次调用都传 1；这里 `sameCard == false` 也照算）。基准未知时这一条做不到。

**`base*` 该从哪来**：**卡面印刷值** = `u.Card.Attack / RangedAttack / Health / KwValue(Armour) / Cost`（`CardDef` 模板；`CardView.cs:45-52` 自己写着）。
⛔ **绝不能填 `u.Attack`** —— 那样 `current == base` 恒成立 ⇒ **永远是白的**（等于把这条机制废掉）。

**和「换投影」是不是必须同批？—— 不必，但建议同批。**
- 判据：`CardData.melee/ranged/health` 是**当前值**（由 `BattleDriver.ToCardData` 填，`BattleDriver.cs:26767-26770`），`base*` 是**印刷值**（模板）⇒ 两者来源不同，**互不依赖**。
- 分两批的中间态 =「投影算出来的当前值 + 旧近似着色」—— **不会错**，只是少一条原版行为。
- 同批的好处：只改一次 `ToCardData`（要把 current 与 base **两套都填**），且 Stage 2c 之后卡面数值本身会变（blind / setMeleeAttack），**正好一起截图核**。
- 唯一读口：`CardView.StatBaseValue(d, s)`（`CardView.cs:12922-12932`）—— 新加读点请走它，⛔ 别在别处再读一次 `base*`。

### 7·6 🔴 `setCost` 公式订正 + 「设为值」四档的覆盖语义（2026-10-25）

> **触发**：N7 在做 Stage 1 时证伪了 §3·3·5 / §6·5 的 `setCost` 推导。本代理已**独立复核**（`.c` 原文 + `cards_truth.json`），下面是要点。

**① 两条出口（`get_CurrentCost.c` 原文，逐句）**

| 情形 | 行号 | 算式 |
|---|---|---|
| **有 `setCost`** | `:66-73`：`iVar2 = setCost.costChange` → **整表重扫**加回全部 `buffType==2` → `iVar3 = clamp0(iVar2)` → **`return iVar3`** | `clamp0( setCost.costChange + Σ(全部 changeCost) )` —— 🔴 **不含 base** |
| **无 `setCost`** | `:84-91`：`iVar2 = rawCardData.manaCost(+0x28 → +0x78) + iVar2` → `clamp0` → `return` | `clamp0( rawManaCost + Σ changeCost )` |

**② `costChange` 的语义 = 目标绝对值 N（数据实证）**

`cards_truth.json`（1,351 张 SO，现读）里 `buffType==95` 共 **3 条**，`costChange` **全是 1**：

| 卡 | `manaCost` | `costChange` | 卡面 |
|---|---|---|---|
| `GSC39 Lying in Wait` | 2 | **1** | `Return a friendly troop to your hand and reduce its cost to 1` |
| `TAU68 Trail Shaper` | 3 | **1** | `Rally: … Lower its cost to 1` |
| `TL69 Neurotyrant` | 6 | **1** | 造一张 **费用 1** 的 Ephemeral 复制品 |

⇒ 只有「**绝对值 1**」能同时对上三张卡；`N − manaCost` 会得到 −1 / −2 / −5，全错。且这三张卡上**没有其它 `buffType==2`** ⇒ 实算 `clamp0(1 + 0) = 1`，与卡面一致。

**③ 同族四档：是不是也「命中即 return、不含 base」（N7 那句的复核）**

| 档 | 判据 | 含 base？ | 含别的修饰？ | N7 那句 |
|---|---|---|---|---|
| `setMeleeAttack(70)` | `get_CurrentMeleeAttack.c:41-42` 命中即 `return effect.meleeAttackChange`；base 在 **`:49`** 才读 | ❌ | ❌ **连已累加的 `addStats.meleeAttackChange` 也不含** | ✅ **成立** |
| `setRangeAttack(85)` | `get_CurrentRangeAttack.c:46-47` 命中即 `return effect.rangeAttackChange`；base 在 **`:54`** 才读 | ❌ | ❌ 同上 | ✅ **同形，成立** |
| `setCost(95)` | `get_CurrentCost.c:66-73` | ❌ | ✅ **含全部 `changeCost`**（重扫） | ⚠️ **不同族**：70/85 把「其它修饰」也丢掉，95 却全量加回 |
| `setHealth(9)` | `get_currentMaxHealthProcessed.c:94 / :104` 把 `iVar3` **覆盖**成 `healthChange`；`:65 return iVar3 + iVar5` | ❌ | ✅ **保留 extrinsic 的加血**（`iVar5`）；❌ 丢掉非 extrinsic 加血 | ✅ **成立（不含 base）**，但**它盖的是上限、不是当前生命** |

⚠️ `setHealth(9)` 的形式和上面三档**不一样**：70/85/95 是**读时覆盖**（getter 命中即返回），9 是**写时物化** —— `AddEffect.c:794-820` 直接把 `currentHealth` 写成 `currentMaxHealthProcessed`（此时那条 `setHealth` 记录已经进表，所以上限已被覆盖），之后该记录继续通过 `currentMaxHealthProcessed` 影响上限（直到被 `RemoveActiveEffects(9)` 摘掉）。

**④ Stage 3 的落地口径（按订正后的公式改写，⛔ 别按旧版）**

1. **`setCost(95)`**：记录里存 **`TargetCost`（目标绝对值）**，⛔ **不是 delta**。
   `CurrentCostOf` 分两支：**有 `Kind=Set` 记录 ⇒ `clamp0(TargetCost + Σ(全部 changeCost))`；无 ⇒ `clamp0(rawManaCost + Σ changeCost)`**。
   ⚠️ 我们现有 `RuleCore.CostOf` 的形状是 `base + ΣCostMods` ⇒ **「有 set 记录」时要把 base 这一项整个换掉**（不是把两者相加）。
   ⚠️ 现有 `lowercost` + `EffectOp.CostSetTo` 的快照 delta 语义要改：现在是 `d = N − 当时 CostOf`，应改成「记录 N 本身」。
2. **`setMeleeAttack(70)`**：记录存**绝对值**；投影里**命中即返回**（不含 base，也不含 `addStats` 的累加）。
3. **`setRangeAttack(85)`**：同形。
4. **`setHealth(9)`**：记录进「setHealth 槽」；`CurrentMaxHealthProcessed = setHealthValue + Σ(extrinsic addStats.health)`（**把 base 与非 extrinsic 加血一起覆盖**）；应用那一刻 `currentHealth = 该值`。
5. **`setCurrentHealth(100)`**：不入投影 —— 直接 `currentHealth = 绝对值`（`AddEffect.c:229-247`，无 clamp、不查 Invulnerable）。
