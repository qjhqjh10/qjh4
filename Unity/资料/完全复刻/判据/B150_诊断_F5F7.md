## 3 · 为什么判「不是引擎缺一格」

1. **两层都在**（第五轮回退后）：棋盘支 `InPlayPoolIncludes` + `BoardCandidatePasses`（`CountEval.cs:507-508`）；卡片支 `CardPoolIncludes` + `CardPoolCandidatePasses`（`:1186-1187`）。
2. **trait 闸本身与原版逐句同构**：`TraitPasses`（`TargetCriteriaEval.cs:710-721`）与 `MeetsTraitCriteria.c:44-55` 的 ①summonRift 门 / ②不筛 / ③`exclude ? !has : has` 一一对应；F5 的「0」正是这个同构的**正确结果**。
3. **去重那一跳也是对的**：离线探针单独调 `FilterSingleUseMutationTargets` 得 2 张（u1/u2 之外剔掉 u2），与 `HasSingleUseMutation` 判据一致。
4. **没有第三条可指认的缺失**：把 F5 / F7 的每一跳和 `.c` 的 `GetTargets`（建池 → `:1095` 尾巴 → select / maxTargets / 去重 → 返回表 `Count`）对齐，缺的那一层在**两轮前就已经补回来了**；剩下能指认的差异只有顺序（§5 第 1 条，休眠）。
