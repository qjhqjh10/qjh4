### 4·1 先把算法**完整解出来**（不再有未知量）

判据：`d:/2/tools/cpp2il/out_cpp2il_dev_ilspy/CryptoString.cs`（ILSpy 有**可读全量体**）+ `decomp_full/CryptoString__GetPWD.c` / `__NewRijndaelManaged.c`（Ghidra，用于确认调用次序）+ `dump.cs`（两个常量）。

  if (string.IsNullOrEmpty(text)) return text;          // ← 空串直接返回，不加密
  pwd = GetPWD()                                        // 注意：dataVersion 用默认值 1

  saltBytes = Encoding.ASCII.GetBytes(saltString)
  kdf = new Rfc2898DeriveBytes("560A18CD-6346-4CF0-A2E8-671F9B6B9EA9", saltBytes)
        // ↑ 密码 = Inputkey 常量；salt = ASCII(GetPWD())；默认 1000 次迭代 / HMAC-SHA1
  rm = new RijndaelManaged()                            // 默认 KeySize 256 / BlockSize 128

GetPWD(int dataVersion = 1):

      d = SystemInfo.deviceUniqueIdentifier
      if (!IsNullOrEmpty(d)) {

### 4·2 `S₁` 那一支什么时候会发生（**比想象的宽**）

`GetPWD` 只有**三种情况**会回落到常量档：① `dataVersion == 0`；② `deviceUniqueIdentifier` 空/null；③ DUID 等于 `"n/a"` 或长度 < 5。

### 4·4 可直接跑的判定实验（**纸面设计，本批未执行**）

> ⛔ 本批**没有跑**任何解密（按简报红线）。下面每一步都可离线、只读、无联网。

**E0 · 先把字段对齐闭合（10 分钟，前置）**
用 `System.Runtime.Serialization.Formatters.Binary.BinaryFormatter`（或现成的 `Shell/LegacySaveReader.cs` 若已有 BF 读法）反序列化成 `LocalPlayerData` 对象；**不要**手写解析。

**E0 的产出直接回答**：`loginPassword` / `deviceId` 是不是空串？`dataVersion` 是不是 0？`playFabId` 是不是那串 64 字符？

| E0 结果 | 后续 | 结论 |
|---|---|---|
| `loginPassword` 与 `deviceId` **都为空** | 停 | 🟢 **P06 无阻塞**：原版这两格是 `EncryptRijndael("")` ⇒ 直接返回 `""` ⇒ **这份档里没有任何 DUID 派生出来的密文**。要的 `deviceId` 明文本来就是空 |
| `dataVersion == 0` | E1 | 🟢 盐 = 常量 `"toQmbArBDRPNkMbm"` ⇒ **可解** |
| 有密文且 `dataVersion != 0` | E2 | 需要 DUID |

**E1 · 常量盐试解（若 E0 说 `dataVersion == 0`，或想先排掉这一支）**
```python
# 只读；不联网
import base64, hashlib, io
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes   # 或 pycryptodome
PWD_CONST = b"toQmbArBDRPNkMbm"
INPUTKEY  = b"560A18CD-6346-4CF0-A2E8-671F9B6B9EA9"
def derive(salt: bytes):
    k = hashlib.pbkdf2_hmac("sha1", INPUTKEY, salt, 1000, dklen=48)   # .NET Rfc2898DeriveBytes 默认 = HMAC-SHA1 / 1000 次
    return k[:32], k[32:48]
key, iv = derive(PWD_CONST)
ct = base64.b64decode(CIPHERTEXT)
pt = Cipher(algorithms.AES(key), modes.CBC(iv)).decryptor().update(ct)   # 去 PKCS7 填充
```
**判定式（自校验，不需要已知明文）**：解出来必须**全部是可打印 ASCII** 且长度 > 0。错盐 ⇒ 每字节可打印概率 ≈ 96/256 ⇒ 一个 ≥16 字符的串命中概率 ≈ 1e-7 以下。⇒ **一次就能判死/判活，不存在「试了像对又不敢定」。**

**E2 · 若真需要 DUID**
1. **先确认 `SystemInfo.deviceUniqueIdentifier` 与 Windows `MachineGuid` 的关系**（本机可测：读 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`，用一个小 Unity/Editor 脚本打印当前 DUID，比对是否为 `MD5(MachineGuid)` 的 32 位小写十六进制）。这一步**决定了「还有没有救」**。
2. 若关系是「DUID = f(MachineGuid)」，去找**旧 MachineGuid**：`C:\Windows.old`（**本机存在这个目录，但 `Windows/System32/config` 已不在**，我实测过 ⇒ 里面没有注册表 hive）、注册表导出备份（`*.reg` / `NTUSER*`）、系统还原点、`D:/2` 归档里的崩溃 dump / `Player.log`（我已 grep `[0-9a-f]{32}` 与 GUID 模式，**全 0 命中**，只有 50 个全零串）。
3. 全都拿不到 ⇒ 盐 = 一个 32 位十六进制的 128-bit 未知量，**PBKDF2 无已知明文时暴力不可行** ⇒ 那时才写「不可解」。

**⇒ 我的裁定（按 §18·0 的「先证明原版那条分支」）**：
- **现在不能写「永久不可解」** —— 有三条未排除的活路（E0 说两格为空 / E0 说 `dataVersion==0` / 旧 MachineGuid 可回收）。
- **也还不能说「可解」** —— 字段对齐没闭合，上面三条都还没验证。
- 正确措辞：**「P06 的阻塞面比 B98 记的小得多：档案在本机、算法已完全解出、候选盐只有 2 个，且 E0 一步就能判死 2/3 的可能。下一波派一个人跑 E0（≤30 分钟）再定。」**
