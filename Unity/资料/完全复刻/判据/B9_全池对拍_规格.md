### 2·3 三档判定（`pool_effect_check.py` 的 `judge()`）

| 判定 | 条件（**全部**满足才算） |
|---|---|
| **对** | 该族要求的签名在读数里出现；或（召唤/造牌/进牌库）**卡 id 对上**（含「同名双 id」）。 |
| **错** | ① `trigger == 0`（打出即结算，主档一定走到）② `playRc == 0`（卡真打出去了）③ 不是督军 ④ 没有任何「夹具看不到 / 条件不成立」的闸 ⑤ **整张卡一条实得都没有**；或 **基础那一份被 `for each` 吞掉**（见 §2·4 ⑤）。 |
| **未验到** | 其余全部，**必须在 `备注` 里写明是哪一档闸挡住的**（⛔ 不许只写「未验到」）。 |

**「实得」怎么算**（`effective_changes`）：把「出牌本身 / 付费」那几条机械行剔掉，
但**同 id 的 `✚ 落场` 第一行要留着**——`Rally: Gain +3 Attack` 这类**自身加成是落地之前算好的**，
只在 `✚` 行里以「落地时它自己身上与印的数不同」露出来（实测 `TAU71` 6→9、`SOR33` 多出 `invulnerable1`）。
`50 buffHand` / `60 buffMana` 两族**不拿 `💰 手牌总价` / `⚙ 能量` 行本身当证据**
（出牌付费也会产生那一行）—— 只认探针自己加的标记：`⇒ **照卡面应付 N · 除付费外净 ±M**` /
`⇒ **除出牌本身外净 ±M**`（`energy_extra` / `handcost_extra`）。

### 2·4 六道防假缺陷闸（**不加这些，第一版会报 ~45 条假缺陷**）

① 🔴 **`unitsToSummon` 25% 是惰性遗留值** —— 原版只在 `chosenAbility ∈ {70,71,72,75,77,90,100,101,270}`
时读它（判据 `B8_BE_全池召唤对拍.md` §2·1）。别的族上挂的值**不是判据**。
② 🔴 **同一张卡两个 id**（`cards_truth.json` 70 组：短 id 池内 / GUID 池外）——
按 id 连接会**静默漏卡**（实测 `Armoured Lightning` 的 `unitsToSummon` 是 GUID `66486b3f…`，
实际落场的是池内 `AM68`，**同一张 Tempestus Scion**）⇒ 比对一律「**id 或同名**」。
③ **结构与条件闸**：`criteria.conditionsFilter / keywordFilter / traitsFilter / armyFilter / rarityFilter /
filterSpecificCards / multiCountCriteria / chooseCardInPlay / selectFromChooseResolution` 任一在场 ·
`TargetsAffected` 落在读数看不见的那几档（`50/51/52` 手牌 · `55/60` 墓地 · `65` 牌库 · `140/150` 前一段目标 ·
`180` 选择结果 · `190` 上一张打出 · `200/201` 引用卡 · `210/220` 计数 · `245` 秘密）· `multiplier` 在场 ·
`buffType ∈ {12,15,16}`（**附魔注册**，效果在后续事件才发生）· `buffType == 4`（剥关键词）· 负向加成（夹具目标该项常为 0）。
④ **卡面文字闸**：`if you control no other …`（条件型 Rally）· `if you control a/an …` · `for each …` ·
`died this game / that died`（要坟场）· `Choose …` · ` or `（二选一/条件换值）·
`your/the next … costs` · **`your <某一类牌> costs`**（夹具手牌只有 1 张垫牌，且每 5 张才 1 张战术卡）·
`Shuriken`（夹具单位没有）· `All enemies lose …` · `up to …`。
⑤ **`for each` 的例外**：它只修饰**附加份数**，基础那一份仍应生效 ⇒
`buffOthers/buffOthersNotResetPool/buffSelf` 三族若**零实得**，判 **错**（本批唯一一条「错」就是这么来的）。
⑥ **夹具结构上不适用**：探针 `fixtureFit` 列非空（`ephemeral` / `defence` 两族是**补进手牌**才测到的，
原版不会自然上手）⇒ **只在「没观察到效果」时**当闸，观察到了（签名命中）照样判对。
判据 = `PlayProbe.NotApplicable`，⛔ 别自己另立一套。

### 2·5 已知的口径边界（读表时必须一起看）

- **电池的「对」比主档弱一档**：电池净差是「这张卡 vs 空正文替身」的四遍并集，
  **不区分是哪一拍**（打出 / 事件 / 三个变体）⇒ 签名对得上就记「对」，但**归因不唯一**。
- **督军（56 张）走对照局**，不是「打出去」⇒ 它们的 trigger-0 行只能算「对照局净差命中」。
- **`play all dump` 结构上看不见 AI**（列里没有 AI 决策列）⇒ ⛔ 别拿它当 AI 改动生效与否的证据。

## 五 · 没查清的（如实写，⛔ 不拿猜测填空）

1. **`46 Talent` 到底算不算被电池覆盖** —— 隔离实验显示「Talent 独占」的卡 15/15 有净差，
   但**净差里到底是不是 Talent 那一条**没有逐字节归因（电池是四遍并集）。
   本批按「覆盖」处理；若是假覆盖，`createCardInHand` 那 105 行的判定要重算。
2. **`715 Ecstasy` / `720 Cruelty` 是半覆盖**（2/7、2/7）—— 为什么那 5 张抬不起来没查。
3. **`buffType=8`（随机标记）** 在读数里到底会以什么形状出现 —— 本批只把它记成软闸，没有逐张核。
4. **单位卡 `targetsAffected=30` 的原版语义** —— 我们只知道**我们的夹具**把它解析成自己；
   原版是不是也这样（那 63 张治疗卡在原版里是否真的只能治疗自己）**没有取证**。
5. **`for each` 的基础份数** —— 本批只对 `buff` 三族判了「基础没生效 = 错」；
   `damage`/`heal` 族的同类形状（`Deal N, plus 1 for each …`）**没有判**（怕治疗不可见造成假缺陷）。
