## 〇、结论（先看这三条）

### ① 有没有会让「同一局」不可复现的来源？—— **引擎结算层：没有**

* **`RuleEngine/` 的结算路径里 0 处**：`Time.*` / `DateTime.*` / `Environment.*` / `Stopwatch` / `Guid`（战斗）/ `UnityEngine.Random` / 无种子 `System.Random` **一处都没有**（全文件只剩注释提到它们；见 §三 A-1～A-4）。
* 三条随机流全部**由开局种子派生**：`ctx.Rng = new Random(seed)` · `ShowRng = seed ^ 0x5EED5EED` · `AiRng = seed ^ 0x0A1A1A1A`（`BattleContext.cs:676/679/681`），并**按原版形状预烧 100 个整数**再按下标取。
* 开局种子的来源是**真时间**（`BattleDriver.cs:4582` `DateTime.Now.Ticks`），但这是**每局现抽**的设计（原版硬币同理），且**三条路都记下了种子**：日志（`[Battle] 本局种子 N`）· 录像头 `start.seed`（`RecBegin` 收的就是同一个局部量）· 联机开局包 `pb.Seed`（主机抽、下发）。
  ⇒ **「种子 → 同一局」成立**；「同一局 → 种子」靠日志/录像取证。**且已有端到端兜底**：回放末尾比 `NetProtocol.StateHash`，种子不同会立刻分叉报红（`PlayReplay`）。
* **唯一的例外**：`CardChoicePanel` 倒计时到点**替玩家随机选一张**（`UnityEngine.Random`，`CardChoicePanel.cs:723`）—— **它会改棋盘**，但它①原版就是这么写的 ②结果被记进录像 `asks`（候选 + 选中下标）并作为动作入流 ⇒ **回放/联机仍可复现**。风险档记「中」，⛔ **不是改成 `System.Random` 的理由**（见 §四 B-11 的建议）。

### ② 有没有「玩家可见结果随真实时间变化」的来源？—— **有，且全部可归类**

* **设计需要（不是漏 seed）**：每日刷新（`DailyData`）· 商店刷新 / 活动倒计时（`TimerDisplay`/`ShopTabPage`/`BoostTimerPanel`）· LiveOps 期次（`LiveOpsHandler`/`LiveOpsLocalCatalog`/`LiveOpsState`/`GachaEventWindow`/`ParentEventWindow`/`RankedNewSeasonWindow`/`MainMenuRuntime`）· 社交/聊天时间戳（`SocialData`/`ChatPanel`/`ChatCache`/`ChatTab`/`InboxData`/`CardDetailPopup`）· 掉落道具过期（`Inventory`）—— **原版这格的时间来自服务器**，本地没有服务器 ⇒ 用本机 UTC/Now 顶替（各文件头都已写明）。
* **表现层可见差**：VFX 随机（爆散偏移、粒子 seed、抖动 desync、材质 `_Random`、残骸 VAT 随机池）· 音效音高/音量 · AI 出牌延迟 · 开局 tips 抽签。这些**同一局重跑两次屏幕/声音可以不同**，属 B107 已定义的「可见差」，⛔ 不得当成「必须改成 seed」。
* **漏 seed 的：0 处**（本普查没有发现「引擎里该用种子却用了时间/全局随机」的地方）。

### ③ 哪些在 `RuleEngine/`（最高优先）？—— **只有 2 处，且都不进对局**

| 位置 | 内容 | 是否战斗结算 | 结论 |

| `RuleEngine/Data/DeckBuilder.cs:40` · `:389` | `new Random(0)` 兜底 | 否（构筑兜底） | **定值**，可复现；唯一问题是「调用方没给 rng 时**静默**用 0」 |

## 八、G 档 —— `Dictionary` / `HashSet` 迭代序（单独一节，别硬套「随机源」）

> **口径**：同一进程内，`Dictionary` 迭代序对**同一插入序列**是稳定的 ⇒ 不是「每次调用都变」的随机源。真正的风险有两类：
> ① **跨运行时**（编辑器 Mono ↔ player IL2CPP）哈希函数可能不同 ⇒ 迭代序可能不同；
> ② **先到先得**的写法（`if (!d.ContainsKey(k)) d[k] = v;`、`return 第一个匹配`）把「序」变成了「语义」。
> 本仓自己已记过这条（`RuleEngine/Core/ReplayFingerprintTrace.cs:27`：「.NET 的字符串哈希按进程随机化 ⇒ 跨进程必然全红」）⇒ 不能假设跨进程稳定。

| 位置 | 写法 | 序会不会影响结果 | 说明 |
| --- | --- | --- | --- |
| `RuleEngine/Core/CardDefPartial_B96CA.cs:63` | `foreach (var kv in AbilityTriggerNumberOfName) if (kv.Value == number) return kv.Key;` | **会** | **6 组同义词共用一个数值**（文件自己写着）⇒ 反查命中哪个名字取决于迭代序。下游若按名字取正文，可读到不同名字（同值同义，通常等价，但**没有断言证明等价**） |
| `RuleEngine/Core/CardDefPartial_B94B16.cs:93` | `if (!d.ContainsKey(kv.Value)) d[kv.Value] = kv.Key;` | **会** | `DefinedTraitName(int)` 的同义词先到先得 |
| `RuleEngine/Core/CardDefPartial_B94B16.cs:117` | 同上 | **会** | `AbilityTriggerNameOf(int)` 同上 |
| `RuleEngine/Data/SimpleAI.cs:1022` | `foreach (var kv in card.Keywords) sum += TraitScore(...)` | 微 | **浮点求和顺序**会带来末位差；只有「刚好卡在阈值上」的评分才可能翻 |
| `RuleEngine/Core/CardDef.cs:3311` | `foreach (var kv in _triggerOps)` 数「恰好 1 个键有 op」 | 否 | `cnt != 1` 就 bail ⇒ 与序无关 |
