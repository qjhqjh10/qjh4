# 商店三页顺序 · 判据（R2 后续 · 2026-10-27 · B1UI · 只读取证）

> 三问：① 那三页 store SO 的**类名 / 资产类型**是什么？② 本地**有没有**？③ 有 ⇒ 解出顺序与 `ShopData.cs` 的
> `_cards` / `_daily` / `_items` 逐条对。本文件逐条答，**查不到就写查不到 + 搜过哪里**。

## ① 类名 / 资产类型（已查实）

- **`Everguild.LiveOps.FixedStoreData`**（`Assembly-CSharp`）。
  判据 = `bundle_menus_assets_all/MonoBehaviour/Premium Campaign Store.json` 的 `m_Script.m_PathID = 4669455528150324631`
  → `bundle_Waprforge_monoscripts/MonoScript/MonoScript_4669455528150324631.json` 的 `m_ClassName = FixedStoreData` / `m_Namespace = Everguild.LiveOps`。
- 这个类的资产形态（同一份 JSON 逐字段）：`eventId` · `dates` · `filter` · `drawData` · `priority` · `location{type,parent,reference}` ·
  **`offerLists[]`** · **`items[]{item{genericObjectReference,targetId}, price{Currency,Amount}, availability, sku}`**。
- 同名族的**类清单**（扫全部 5,175 个 MonoScript，按名模糊）：只有这 4 个——
  `Everguild.LiveOps.FixedStoreData` · `ShopOfferContainer` · `ShopOfferDataV2` · `ShopTab`。
  后三个是**界面件**（容器/Tab/老版本数据），**没有** `items + offerLists` 那种 store 结构
  ⇒ 「store SO」在本仓只有 `FixedStoreData` 一种。

## ② 本地有没有 —— **没有**（三页那三份不在离线包体里）

### 三跳（按项目口径走，没拿 AssetRipper 的 guid 去对）
| 跳 | 做的事 | 结果 |
|---|---|---|
| ① 「有哪些 FixedStoreData 实例」 | 全 `assets_full`（84 个 bundle / 24.7 万文件）**按字段名**扫 `"offerLists"` 与 `"transactionLocation"` | **各命中 1 个文件**：`bundle_menus_assets_all/MonoBehaviour/Premium Campaign Store.json` |
| ② 那份是谁 | 读它：`eventId = "PremiumCampaignStore"` · `items` = 一条 `premium_campaign_um` · **`offerLists = []`** | = **Premium 战役**的 store，**不是**商店三页（Cards / Daily / Items） |
| ③ 有没有漏导出的 | ① AA 目录里 `.bundle` 文件 **84 个** vs `assets_full` 的 `bundle_*` 目录 **84 个**，**差集为空**（脚本比对过） ⇒ 导出**覆盖了整个本地包**，没跳包；② 另一个内置文件 `level0`（无 type tree）的**原始字节**里按 `*Store*` 扫字符串 ⇒ 只有一处 `Stores`（像词条/类名碎片），**没有任何 store 的 `eventId`** | 没找到第二份 |

### 结论
- **商店三页的 store 定义不在本地**：离线包里 `FixedStoreData` **只有 1 份**，而且是 Premium 战役那条。
  ⇒ 与「liveops 内容由**服务端**下发」自洽（用户的 P3 边界那一条）。
- ⚠️ **唯一没完全覆盖的角落（如实记）**：`level0` 里的 **147 个 MonoBehaviour 无法按类名判**（该文件**没有 type tree**，
  `UnityPy.read()` 拿不到 `m_Script`）。⇒ 只能说「**原始字节里没有 store 的 eventId**」，不能说「已按类名穷举过 level0」。
  要闭合：借同类型样板 typetree 逐实例读 `m_Script`（本仓已有现成做法 —— `工具/read_tmp_level0.py` 就是这么读 level0 里的 TMP 的）。

## ③ 顺序能不能对 —— **不能对**（判据缺失，不是「对过了」）

- 我们那三页的商品表是 `Shell/ShopData.cs` 里**手写的定长数组** `_cards` / `_daily` / `_items`；
  原版顺序 = `FixedStoreData.get_Items`（`items` 在前 + `offerLists` 按列表序展开 + `Where(IsActive)`，
  判据 = `d:/2/tools/decomp_full/Everguild.LiveOps.FixedStoreData__get_Items.c` / `__AddItem.c` 里的 `List.AddWithResize`）。
- **差异表：没法产** —— 那三份 SO 不在本地（见 ②）。⇒ **「我们的数组序 = 原版序」这件事今天无判据**。
- ⛔ 别把这句读成「顺序错了」：**没有判据 ≠ 有差异**。同理也别读成「顺序对了」。

## ④ `level0` 闭合（2026-10-27 补 · 同一批）

**做法**（复用 `工具/read_tmp_level0.py` 的同一套口径，**没改那个工具**）：
- 原始文件 = `D:/2/unity_run_ref/Warpforge_Data/level0`；`m_Script` 走 **MB 头固定偏移** `script_of(raw)` = `('<i',16)` + `('<q',20)`

- `m_FileID = 1` ⇒ 按 externals 指到 `globalgamemanagers.assets`，那里按 `pathID` 查 `MonoScript` 的 `m_ClassName/m_Namespace`
  （**先走 PPtr 解，⛔ 没拿 PathID 全库扫小号**）；
- 全部 **147/147 个 MonoBehaviour 都解出了类名**（0 条「读不出头」、0 条「脚本查不到」）。

**自检（证明字段没串位）**：`pid 297 / 298`（= `Loading text` / `Progress text` 的两条 TMP）解出来是 **`TextMeshProUGUI`**，
`pid 295 / 296` 解出来是 `EverguildTextController` —— 与 `工具/read_tmp_level0.py` 当初的结论**逐条吻合** ⇒ 偏移与类名表都成立。

**结论**：**按类名穷举过 `level0`，里面没有 `FixedStoreData`。**
新增的事实（比「字节里没有」更硬的一层）——那 147 条里**只有 3 条与 store 有关，而且都是"空组件"**：
