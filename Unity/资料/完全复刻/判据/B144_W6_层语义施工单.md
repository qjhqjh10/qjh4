## 三 · 后果（为什么 `#33/#34` 改了会「全消失」）

层号不是「参数」，是**对象归属**与**相机可见性**的联立：

1. 3D 战场相机（我们）掩码 = `1<<8 | 1<<10` = **1280**；原版独立场景相机 = **1137** = 位 `{0,4,5,6,10}`（`Battle Arena 1.unity` 的 `Camera &1461`）。
2. 若**只**把相机掩码改成 1137 而不动对象：我们的 3D 内容在 **8**（1137 不含第 8 位）⇒ **一张都不画**；
   HUD 相机又「除 8/10 全层」⇒ 也画不出 3D ⇒ **棋盘/战场整块静默消失**（不报错，`B144-A` §五-3 已实测过同型：预览场景换掩码 ⇒ 预览图全黑）。
3. 反过来只把对象挪到 0 而不改掩码：3D 相机（1280）不含第 0 位 ⇒ 同样全消失。
4. **物理**同源：`ArenaSlots` 的层 8 还兼着「地面 tap 射线」等掩码（`TapParticleController.cs` `0x40000D01` vs 原版 `0x40000C01`，`B144-A` #90），
   对象一挪、掩码不跟 ⇒ 点地面无反应（静默）。
5. **UI 在层 0** 还牵连 `#34`（HUD 相机「除 8/10 全层」）、`#65/#80`（卡 2D 命中 `Physics2D.DefaultRaycastLayers` = 除 IgnoreRaycast 全层 vs 原版 `EventMask = 32` = 只层 5）。
