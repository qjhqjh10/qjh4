## 三 · `B-26` —— `OvertimeStart.wav` 削顶（**判得了，结论要改**）

### 3.1 找到了一条**绝对幅度可信**的 FSB5→PCM 解码链

- 工具：**`vgmstream-cli r2168 (Oct 25 2026)`**（win64 构建，含 `libvorbis.dll` / `avcodec-vgmstream-63.dll`）。
  下载落点 `d:/4/_tmp_view/b112_r1/tools/vgm/`（按铁律 8 自行下载；未改动系统 PATH、未碰 `d:/2`）。
- 关键开关：**`-w`**（`allow .wav in original sample format`）⇒ 输出 **32-bit float WAV**。
  ⚠️ **不加 `-w` 默认输出 PCM16，会在写盘时把 >1 的样点削掉** —— 这正是以前几次误判「原版就削顶」的陷阱。
- 命令：
  ```
  vgmstream-cli.exe -w -o <out.wav> <fsb5.bin>
  ```
- FSB5 的切法：`AudioClip.m_Resource.m_Source` 里的 `CAB-xxxx.resource` → 按 `m_Offset/m_Size` 切。
  （⚠️ UnityPy 的 `EndianBinaryReader.read()` **会把流读到底**，第二次读返回 0 字节；
  要么每次 `Position = 0`，要么把整段 `resource` 缓存下来。）

### 3.2 链路验证（三类样本，全 `corr = 1.000000` / `maxdiff = 0.000000`）

| 样本类 | 条数 | 对照物 | 结果 |
|---|---|---|---|
| ADPCM（`comp=2`）sfx | 5（`Add card to deck` · `Ambush` · `ArmourEffect` · `Hit Metal Light 2` · `Duty Reload`） | 工程里的 `.wav`（PCM16） | **逐样点相同**（长度、峰值、波形全等） |
| ADPCM（`comp=2`）vo | 3（`VO_DA_Assault Terminator…` 等） | 工程里的 `.wav` | **逐样点相同** |
| Vorbis（`comp=1`）单声道 vo | 7（48k / 44.1k / 32k / 24k 四档都覆盖） | 工程里的 `.ogg`（**修正末页 granule 后**，见 §4.2） | **逐样点相同** |

⇒ `vgmstream` 的 FSB5 解码**在本机是可信的**：它复刻的是 FMOD 内建的 FSB5-Vorbis setup header，
而 AssetRipper 的 `.ogg` 是**按「声道 + 采样率 + 猜测的 quality」拼出来的 setup header**（§4.1 有反证）。

### 3.3 `OvertimeStart` 真值读数 vs 我们那份

| 量 | **原版真值**（FSB5 → vgmstream `-w`） | **我们的** `Resources/Art/audio/sfx/OvertimeStart.wav` |
|---|---|---|
| 长度 | **260,212 样点** @ 48,000 Hz / 2ch = **5.421083 s**（与 `m_Length` 逐位吻合） | 260,212 样点 @ 48k/2ch（长度对） |
| 峰值 | **1.277220**（= 高于 0 dBFS 约 **+2.1 dB**） | **1.000**（PCM16 上限） |
| `abs(x) ≥ 0.999` 占比 | **0.48%** | **7.90%** |
| 与真值的相关 | —— | **0.00247**（在 ±60,000 样点内搜遍，最好也只有 **0.0087**） |
| 频谱（1.0 s 处 32k 窗） | 质心 3,091 Hz · 平坦度 **0.196**（有调性） | 质心 8,809 Hz · 平坦度 **0.630**（噪声样） |

**⇒ 我们那份不是「原版解码后被削顶」，而是【一次错误重建】（波形根本不是同一段）。**
`B110_V4 §E` 当年得到的「削顶后 corr = 1.000」是拿**我们自己那条 q=0.33 重建**当参照物的**自证**，
两个都是同一条错链的产物。

### 3.4 判据结论 / 要改哪个文件哪一行 / 还差什么

- **判据结论**：`OvertimeStart` **判得了**。原版音频**只是轻微过载**（峰值 1.277、0.48% 样点超 0 dBFS —— 正常商业音效的响度），

  重做方式：`vgmstream-cli -w` 出 float WAV → 直接作为源（Unity 支持 32-bit float WAV），
  或转 PCM16（**会重新引入 0.48% 的削顶 —— 那与原版 FMOD 播出来的听感一致，不算错**）。
  ⛔ **不许对源做限幅/归一化**（`铁律 18·0`：不是服务器相关）。

## 四 · 🔴 顺手发现（新账，必须记 —— 与本轮三条都相关）

### 4.1 结论

工程里 **1,813 个 `.ogg`** 全部来自 AssetRipper 的导出（`import_original_audio.py:1124` / `import_original_sfx.py:678` 只是 `shutil.copy2`，**不重编码**）。它们的**音频包（vorbis packet）字节是对的，但容器有两类病**：

| 类别 | 条数 | 症状 | 证据 |
|---|---|---|---|
| **A. 单声道 `.ogg`（内容对、时长被截断）** | **1,779** = 1,778 个 `vo/*.ogg` + `sfx/StartMatch.ogg`<br>（`vo/` 另有 115 个 `.wav`，是 ADPCM，**内容正确**，见 §3.2） | 末页 **granule 是错的**（远小于真值）⇒ 按 Ogg 规范算长度的解码器（libsndfile / vgmstream / **很可能 Unity**）只解出 **6%–20%** 的音频。**内容本身逐样点正确**（把 granule 改成真值 + 重算 CRC 后与 `vgmstream` 解码 `corr = 1.000000`） | §3.2 的 7 条抽查；全表统计：**1,811 条有真值的 `.ogg`，granule/真值 中位数 = 0.16，0 条 ≥ 0.99** |
| **B. 立体声 `.ogg`（内容是错的）** | **34** = **25 `bgm/` + 2 `music/` + 7 `sfx/`**（`MatchVictory` · `MatchDefeat` · `MatchDraw` · `Vault Crate Open Full` · `Progress Jingle` · `Draft Mode GainSkull` · `Draft Mode Loss Jingle`） | 它们的 setup header 是 **3,832 字节**（= AssetRipper 猜的「44.1k 立体声 q=0.33」），与 FMOD 内建的对不上 ⇒ 解码出来是**噪声/静音**（峰值 26 / 58 / 113 / 760…）。`main_theme.ogg` 未修 granule 时解出 **2,688 样点、峰值 0.00（静音）** | 抽查 6 条（3 bgm + 2 music + `MatchVictory`）**全部对不上**；`menu_idle_theme` 只有前 6,144 样点对得上 |

**旁证（为什么不是我们判错）**：
- 音频包层面 **1:1 相同**：`Warpforge Aeldari Combat High` 的 `.ogg` 除去 3 个头部包后，
  **9,915 / 9,915 个 packet 与 FSB5 里逐字节相同**（`ogg_packets[3:] == fsb_packets`）⇒ 内容没丢、**病在 header/granule**。
- 波形层面 **单声道全对、立体声全错**，而单声道的 setup header 是 **3,006 字节**、立体声是 **3,832 字节**
  ⇒ 两类 setup header 的可信度不同，与「AssetRipper 按声道数猜 setup」的机制自洽。
- 峰值合理性：单声道解出来峰值 **0.64–0.99**（正常），立体声解出来 **26–760**（不可能）。

### 4.2 影响（为什么必须立账）

- **A 类**：如果 Unity 也按 granule 取长度（`libvorbis` 的 `ov_pcm_total` 就是这么做的），
  那么**全部语音只有前 0.1–0.6 秒会播**，其余被截掉 —— 这是**玩家能直接听出来**的缺陷。
  ⚠️ **这一条还没在 Unity 侧验证**（本代理不能跑 Unity）：`差什么` = 一次 Unity 导入后读 `AudioClip.length`，
  与真值（`_sfx_audio_truth.json` / `m_Length`）比。
- **B 类**：**主菜单音乐（`main_theme`）现在是静音 / 噪声**，25 条战场 BGM + 7 条结算/开包音效同理。

### 4.3 修法（都已验证过可行）

- **A 类**：把末页 `granule_position` 改成 **`round(m_Length × m_Frequency)`**（真值表里有）并**重算该页 CRC**。
  已验证：改完 libsndfile 解出的长度 = 真值，且与 `vgmstream` 解码 **`corr = 1.000000`**。
  纯字节级修复，**不重编码、不改内容**（1,779 个文件）。
- **B 类**：**没有「只改 header」的解**（setup header 内容不对）⇒ 只能**从 FSB5 重新出音频**：
  `vgmstream-cli -w` 解成 float WAV（或 PCM16）后替换。代价 = 变成 WAV（丢压缩率），但内容正确；
  也可以再编码成 Ogg（二次有损，听感差异极小）。
  34 个文件，体积会涨（bgm 是 2 分钟级）。
