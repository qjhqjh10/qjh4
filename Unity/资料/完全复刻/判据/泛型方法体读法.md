## 二 怎么判「这份产物到底有没有真体」——六个体征

| # | 体征 | 判读 | 实例（本仓实测） |
|---|---|---|---|
| 1 | 首行函数名**不是**你请求的那个 | **不一定是坏事**：先读体。ICF/链接器把相同机器码折叠成同一地址时会这样 | `DraftEventBase…get_DraftState__4d5be0.c` 首行是 `PhotonView__get_OwnerActorNr`，但体 `return *(undefined4 *)(param_1 + 0x28);` **正是**读 `DraftState(+0x28)` ⇒ 体是对的 |
| 2 | 体是 `{ return; }` / `{ return 0; }` 且首行是别人 | **空桩/常量桩**。查 RVA：`0x4B33B0` = 全局空桩、`0x4BD440` = 全局 `return 0` | `…OnMatchProcessSuccess__4b33b0.c` = `NetworkingPeer__OnMessage(void){ return; }` ⇒ 原版基类这个方法**本来就是空的**（与账里「基类空方法体」一致）；`…GetArmyState__4bd440.c` = `return 0` ⇒ 原版基类恒 `None`，真语义在子类覆盖里 |
| 3 | 满屏 `Cpp2ILHelpers.NoteDecompilerIssue("Unmanaged memory load: …")` / `"Method not found @1xxxxxxxx"` | **ILSpy 降级体**：对象类型和实参常量都丢了 | `out_cpp2il_dev_ilspy/MissionEvent.cs` 的 `Initialize` / `InitializeChallenge` / `Collect` ×2 / `UpdateChallengeProgress` / `TryCollect` 六条 |
| 4 | 一整排实参都是 `0` / `default` / `null` | 同 3，常量被吞 ⇒ **回 `.c` 复核** | `BroadcastCardCreated` 那族的 `GetCardsInHandList(六个开关)` 在 ILSpy 里全成 `default`，`.c` 里是六个 `1` |
| 5 | `throw new NotImplementedException("Method body was not recovered.")` | `out_il2csharp` 的**无产物**档 | `out_il2csharp/Assembly-CSharp/MissionEvent_2.cs` 整类 |
| 6 | `throw null;` | `out_cpp2il_ilspy` 的签名壳 | 该目录整体 |

🔴 **硬规则（写进判档口径）**：一份 ILSpy 体里只要同时出现
`Unmanaged memory load` / `Method not found @VA` / 实参全是 `0`&nbsp;`default`&nbsp;`null` 中的**任一条**且控制流里出现 `(nint)0` 比较，
就 **⛔ 不得判「方法体逐句对过 ⇒ A」** —— 那不是体，是骨架。

## 三 泛型体的调用约定（读 `.c` 的第一件事）

```
longlong FUN_1818xxxxx(longlong param_1, longlong param_2, longlong param_3)
                        └─ this ──┘   └─ 形参1 ─┘   └─ MethodInfo ┘
```

- **`param_1` = `this`**（实例方法恒如此）。
- **最后一个参数 = `MethodInfo*`（rgctx）**，不是业务形参。判据：`MissionEvent` / `DraftEventBase` /
  `RankedEventBase` 的 `.c` 里，最后一个参数只被用来取 `+0x20 → +0xC0` 那张表（见下），从不当值用。
- **泛型字段的读写要过「字段表」**：

```
*(longlong *)(*(longlong *)(*(longlong *)(param_3 + 0x20) + 0xC0) + 0x88)
                 └ MethodInfo ┘  └ 声明类型 ┘  └ 字段表 ┘          └ 条目偏移 ┘
```

- `+0xC0` 那张表里的 `+0xNN` 是**条目偏移，不是对象字段偏移**；条目 8 字节一格
  （`DraftEventBase.GetRandomWarlords` 里连着出现 `+0x140/0x148/0x150/0x158/0x160/0x168/0x170/0x178/0x180/0x188`）。
- 这类 `FieldInfo` 会**作为最后一个实参传给 helper**：`Validate` 就是这么调 `SaveCards` 的 ——
  `FUN_181813870(this, save, cards, save+0x10(eventId), 0, 0, <字段表+0x88>)`。
- ⚠️ **哪个 `FieldInfo` 对应哪个字段，本仓还没做映射**：要么按 `dump.cs` 里该泛型实例的字段声明顺序核对，
  要么从**调用语义**反推（例：`+0x68` 传给 `GetCardsFromPacks` ⇒ 可能是包表；`+0x88` 传给 `SaveCards` ⇒ 可能是 `selectedCards`）。
  ⛔ 别凭偏移猜字段名。

## 四 对象布局速查（`LiveOpsEvent` 这一族）

**三家实测同一套**：


## 五 虚表槽怎么认（别按猜测）

**槽 N 的方法信息指针在 N+8**，所以形态恒为：

```c
(**(code **)(*obj + 0xNNN))(obj, *(undefined8 *)(*obj + 0xNNN + 8))
```

认槽的**唯一可靠办法 = 看返回值怎么被用**。已实测对照（可直接引用）：

| 槽 | 是哪个方法 | 证据 |
|---|---|---|
| `+0x5D8` | `BaseInboxEvent.GetMessageContent()` | `GetMessage__15892b0.c`：取回后读 `+0x18` = `message`；`GetTitle` 里读 `+0x20` = `title` |
| `+0x5F8` | `BaseInboxEvent.GetRewards()` | `GetTitle` / `GetMessage` 里取回后 `FirstOrDefault` → `get_Item(+0x208)` → `get_Name(+0x1A8)` |
| `+0x7E8` | `RankedEventBase.set_IsRanked(bool)` | `ToggleRankedMode__1185570.c` 第一跳；被调体写 `this+0x28` |
| `+0x448` | `LiveOpsEvent.GetID()` | `RewardEvent__HandleRewardDisplay.c` 把它当 `controllerID` 传给 Toast 上下文 |
| `+0x208` | 物品的 `get_Item`（列表元素→`ObtainableItem`） | `GetTitle` 链 |
| `+0x1A8` | 物品的 `get_Name`（→ 显示名） | `GetTitle` 链 |
| `+0x218` | 奖励的 `get_Quantity` | `RewardEvent__HandleRewardDisplay.c`（`String.Format` 前取值） |

## 六 `_003C_` 家族转义还原

IL2CPP 把 `<` `>` 等换成 `_XXXX_`，**按名找方法/字段前必须先还原**：

| 转义 | 字符 | 常见形态 |
|---|---|---|
| `_003C_` | `<` | `_003COnInitialize_003Eb__6_0` → `<OnInitialize>b__6_0` |
| `_003E_` | `>` | 同上 |
| `_007C_` | `\|` | `_007C_` 在匿名类型名里 |
| `_002E_` | `.` | `_002Ector` → `.ctor` |
| `_0060_` | `` ` `` | 泛型元数 `` Type`2 `` |
| `_002D_` / `_002B_` / `_0024_` / `_0040_` | `-` `+` `$` `@` | 运算符重载 / 闭包字段 |

⚠️ 一个文件里**可能有多个顶层类型**（`MissionEvent.cs` 同时有 `MissionEvent` 和 `MissionEvent<TS,TD>`）
⇒ 按名找方法前**先反转义 + 把该文件所有顶层类型一起扫**，否则「找不到方法体」是假结论。

## 七 四个一定会再遇到的坑

1. **RVA 相同 ≠ 同一个方法**（ICF 折叠）。`0x4B33B0`（空桩）/ `0x4BD440`（`return 0`）被几千处共享。
   判法：**先读体**，体与语义自洽就采信，别因为首行名不是自己就判「解错了」。
2. **文件名与内容不符**：`decomp_full` 里少数 `.c` 的内容是**另一个方法**。拿它当调用证据前，**先看首行函数名**。
   （与 ICF 折叠要分清：折叠的体是对的，错位的体是另一个方法的完整逻辑。）
3. **`dump.cs` 对泛型类写 `// RVA: -1`** ⇒ 按「RVA 非负」筛名单会**整类丢掉**；真地址在 `GenericInstMethod` 子块。
4. **`out_il2csharp` 不是「整份全是签名壳」**：逐方法看，有的比 ILSpy 干净（没有 `(CardScript)0` 那种丢实参）。
   反过来 `out_cpp2il_dev_ilspy` 也不是「整份都有体」—— `MissionEvent` 那六条就是降级体。
