## 2 · 切形态入口清单（逐个：设了哪几个量 / 缺哪几个）

1. **`Build`（出生）** —— CardView.cs:4251 起。建 `2DCard`→`Front`→各层；`board` 时再 `BuildBody3D`（:4421），并**同时建**一份 `_art` 关闭备用（:4430-4437）。✅ 设：层/父/缩放/队列（`AddLayer` 内 `StampQueue` :6325）。✅ collider。⚠️ 缺：无（`SetFace` 那条路要补的它都有）。
2. **`SetFace`（唯一正规换形态）** —— CardView.cs:2342-2511。✅ 设：形态、`_tilt` 开关+复位、`_body3D` 懒建+显隐、`_art` 二选一（:2382-2387）、`_frame/_artFront/_textBg/_costBg/_gem/_title/_keywords/_army/_race/_createdBy`、`PlaceRim`、`PlaceArmourIcon`、`PlaceInfoLayer`、`BuildStatLayers`、`BuildFaceStatTexts`、`ApplyBoardSortingOrders`（经 `SetQueue` 才走到）。⚠️ **缺**：① 不重置 `_artAlpha/_alpha2D`（见 §4-⑤）；② 首句 `if (_faceMode == f) return;` ⇒ 同形态重复调用**不会**修好被别处改坏的显隐（`SetArtAlpha` 能在场上把 `_art` 打开而无人再关）。
3. **`CardFeel.HandToBoard`（登场 clip）** —— CardFeel.cs:2065-2195。开场先 `SetFace(Board)`→`SetFace(prev)`→`SetBody3DVisible(false)` 借建体（:2073-2076），0.7 再 `SetFace(Board)`（:2183）。✅ 收口有 `OnKill` 复位两档 α（:2194）。⚠️ 缺：被打断时**不会**复位 `_artAlpha`（它没动它，暂时无害）。
4. **`CardFeel.ReturnToHand`（回手倒放）** —— CardFeel.cs:1887-1949。✅ 只有：溶解量曲线、`SetArtAlpha(0→1)`、复位材质。⚠️ **缺**：`SetFace(Hand)` 不在这里（调用方演完才调 / 或直接 Kill）；`_frame/_title/_keywords/_info` 全程保持关闭；**没有 `OnKill` 复位 `ArtAlpha`**（:1941-1948 只复位溶解材质）。
5. **`CardFeel.MoveBackToHand`（轻量回手）** —— CardFeel.cs:3718-3750。✅ `SetQueue(handQueue)`、`SetBody3DVisible(false)`、`ArtAlpha→1`、撤残骸。✅ 调用方紧接着 `SetFace(Hand)`（BattleDriver.cs:8386）。
6. **`UnDissolve` / `UnDissolveWholeCard`** —— CardFeel.cs:3596/3670。✅ `UnDissolve` 会把 `_art` 淡到 α1 ——**在场上形态下**（见 §4-⑦）。`UnDissolveWholeCard` 只动 `_alpha2D`（正确）。
7. **`SetRemnantBody` / `HideRemnantBodyNow`** —— CardView.cs:2597/2816。✅ 关体+关面；撤时**分两条路**恢复（有 3D 体就开体，没体才开 `_art`，:2821-2822）。`ShowOriginalRemnantCard` 是第三条覆盖路（HUD:153）。
8. **`SetData`** —— CardView.cs:3339-3460。✅ 末尾重放 `ApplyFace`/`ApplyArtTransform`/`ApplyClip`/`ApplyAmbush`（:3456-3458）。⚠️ 会**重建**晚建层（徽标/数值/`_art`），依赖各自 `StampQueue`。
9. **`SetLayer`** —— CardView.cs:2321-2331。**递归整棵子树**，包括挂在卡下的特效实例与 `EffectAnchor` 子树（见 §5-③）。
10. **`BattleDriver` 飞行三处** `SetLayer(0)` / 落地 `SetLayer(ArenaSlots.ArenaLayer)` —— BattleDriver.cs:25927/26008/26492/26766/37906。⚠️ 与 `SetFace` **不同入口**，两者都只在自己的路上显式设。

## 4 · 错位候选（状态 → 谁和谁不一致 → 预期症状）

- **① 场上卡体尺寸** —— `body3D` 世界尺寸 1.852×2.622（0.88586 × 网格 2.0901×2.9604），而同一张卡的 2D 层 / 教程锚 / 命中框都按 `CardView.Width/Height` 2.0927×3.3313 算 ⇒ 体高只有 2D 的 **78.7%**。活状态表 `UI-21` 记的是「`CardView.cs:309` 卡体缩放 1.0417（97.6%H）vs 原版实拍 82.8%H，待用户看画面」⇒ **同一格里两套读数打架，尚未定**（活状态表:492）。
- **② 教程标注尺寸** —— `BattleDriver.TutorialAnchor` 用 `CardView.Width/Height × lossyScale`（BattleDriver.cs:17186-17190）算高亮框，但场上看到的是 3D 体（78.7%H）⇒ 高亮/指针比真卡大一圈。
- **③ 回手倒放只亮立绘** —— `SetArtAlpha` 只开关 `_art`（CardView.cs:6732-6737），`_frame/_title/_keywords` 仍被 `SetFace(Board)` 关着（:2396-2435）。倒放 0.25–0.5833 s 之间观众看到的是**无框、无字的一张立绘矩形**；原版 `2DCard` 是一个 CanvasGroup，整组一起淡回来（判据写在 CardFeel.cs:1912-1919）。
- **④ 回手被打断留半透明** —— `ReturnToHand` 只给溶解材质挂 `OnKill`（CardFeel.cs:1948），`_artAlpha` 留在 0..1 之间；同一张视图回到手牌后**立绘永久偏淡**，没有任何口复位它（对照 `HandToBoard` 的 :2194 有双档复位）。
- **⑤ 回手段里「3D 体 + 无框立绘」同框、且立绘画到卡体外** —— `SetArtAlpha(a>0)` 会 `Show(_art, true)`（CardView.cs:6735），**不看形态**；`_art` 用 **`ArtOpaque`（忽略贴图 alpha）**、网格是 **2.7484² 方图**（CardView.cs:4423/4429-4437、957），比卡体 1.85×2.62 一圈都大。而 `SetFace(Board)` 已经把**卡框**关掉了 ⇒ 回手倒放那 0.6 s 里，方图没有任何东西裁它 ⇒ 卡体四周露出**矩形画框**。原版有卡框（`2DCard` 是整组 CanvasGroup）自然裁掉。另：`UnDissolve` 是同一族的潜伏口（CardFeel.cs:3614-3619，现核**全仓 0 调用点**）。
- **⑥ 场上数值/徽标 vs 卡体** —— 数值挂 `Board Elements/3DBody`（恒等，CardView.cs:13329），坐标已在 `Badges.BodyY` 里减过 `CardHalfH`（Badges.cs:139-147），与卡体 `y=−H/2` 是两套换算；任一处改成「按卡体节点算」都会整体偏移 0.08 或 1.6657。**今天两处一致**（已核），但这是最容易在后续改动里静默分家的格子。
- **⑦ 残骸体锚点** —— 用 `RemnantBodyAnchorLocal = (0,−H/2,0)`（卡底边），缩放复制 `_body3D.localScale`（CardView.cs:2688-2690）；若先撤了 `_body3D` 再建残骸体，会退回 `Body3DScale` 常量而不是「当前卡体缩放」——两者今天同值，将来若按卡体调缩放就会分家。

## 5 · 特效失真候选（父节点 / 缩放 / GrabPass 三面）

- **① 父节点**：卡上特效的正确挂点是 `EffectAnchor(onBoard)`（场上 = `Board Elements/EffectAnchor`，`(0,1.34,−0.128)` → 卡根 `From3DBody`，CardView.cs:2133/2157-2190）。`CardEffects.Fire` 走这条；`TraitFrames.Attach` 的 `_anchor` 局部位置仍是 **0**（G10-07 §四·1 已开的补丁，未落）。**关键词粒子已改走 `TraitParticles.SpawnAnchor`**（TraitParticles.cs:210-215/313-317，G10-07 已做）。
- **② 队列（本仓最可能的「特效错位」）**：`CardEffects.Fire` 会把新建实例挂进这张卡的排序段（CardEffects.cs:50-56 → `CardView.StampEffectRoot`）。但 **`TraitParticles.PlayCore` 直接调 `WarpforgeEffectPlayer.Play`**（TraitParticles.cs:215），**绕过了 `CardEffects.Fire`** ⇒ 从不登记 `_effectRoots` ⇒ 停在默认 **3000**。而场上卡整段是 **2962–2979**（BoardLayout.cs:155-158）⇒ 本仓自己的口径「停在 3000 的透明件**恒画在所有场上卡之上**」（CardView.cs:1980-1999）⇒ 关键词粒子会**穿过**前排卡。❗原版这一族的排序层/order 本地未查清（`EffectAnchor` 带 `SortingGroup order=1`，见报告 `D` §④·3b）⇒ 这条是「我们的机制漏一环」，不是「照原版」。
- **③ GrabPass 挪层**：`WarpforgeEffectPlayer.Play` 里统一做 `GrabScreen501.FinalLayer`（WarpforgeEffectPlayer.cs:332-338），但 **`GrabScreen501.Enabled` 默认 false**（`WF_GRAB501` 不设 = 关，GrabPassTransparentFeature.cs:448/461-467），且 `redrawAt501=false`（活状态表 `FX-01` :493）。`CardView.SetLayer` **递归整棵子树**（CardView.cs:2321-2331）⇒ 卡飞行/落地换层时会把挂在它下面的特效实例一起搬到 0/8；**批 E 判据已定：原版没有「搬卡时改 layer」这条活路径**（活状态表:493），所以这条**不要照原版改**，只在真机 A/B 确认 501 开着会掉层时按「自己设计」修（跳过特效锚子树）。
- **④ 缩放**：`WarpforgeEffectPlayer.Play` 默认把调用方 `scale` 当**乘数**乘在 prefab 作者缩放上（:305-309），只有 `assignScale:true` 才是赋值。`CardEffects.Fire` 的签名里没有 `assignScale`（CardEffects.cs:21-43）⇒ 想「赋值」的调用点（落地扬尘那族）只能另走 `Play` 重载。

## 6 · 建议的探针（不跑 Unity 也能写 / 真机要复现什么）

**静态（写进 `Editor/*Assert.cs`，可先不跑宿主）**

1. 对 `CardView` 每个「会 `Show(_art, …)` / `SetBody3DVisible` / `SetArtAlpha`」的入口做对照表断言：**场上形态下 `ArtVisible == false` 且 `Body3DVisible == true`**（现在 `SetArtAlpha` 是唯一的破口，见 §4-⑤）。
2. 断言 `TraitParticles` 建出来的实例**要么**登记在 `EffectRootCount` 里、**要么**队列 ≠ 3000（用它把 §5-② 钉住；改坏法 = 删掉登记）。
3. 断言 `ReturnToHand` 的 `OnKill` 之后 `ArtAlpha == 1f`（今天必红 ⇒ 正是 §4-④）。
4. 断言 `Card3D` 材质三张贴图**都非 null**（`_BaseMap/_MatCap/_CardImage`），缺失时读口报出来而不是画白（§3）。
5. 断言 `_body3D.lossyScale` 与 `ArenaSlots` 给的那一档、以及 `CardView.Height` 的比例关系是**同一个常量**（把 §4-① 那条读数钉死一处）。

**真机（一次打开、按用户口径批量看）**

- 打一张带关键词的单位上场 → 看关键词粒子是否盖到**前排其它卡**（§5-②），截图 `_tmp_view/shots/<日期>_j6/`。
- 让单位被回手（`RecallToHand`）→ 逐帧看 0.25–0.58 s 是否「只有立绘没有卡框」（§4-③）。
- 拖一张手牌出场 → 交接 0.95 s 前后看 3D 体与 2D 卡面是否**同时**可见（§4-⑤，若有，`UnDissolve`/`SetFace` 回放路径要先查）。
- 场上卡与教程高亮并排量：高亮框是否比卡体大一圈（§4-②）。
