### 0·1 客户端自己点名的名单（原文，顺序有意义）

`0003_ExecuteCloudScript.req.json` → `FunctionParameter.Data.Configs`：

```
ShopConfig, WildcardConfig, CardTierConfig, PointsConfig, DailyStoresConfig,
PremiumConfig, MissionsConfig, FeatureConfig, CloudscriptRestrictedVersionConfig,

```

这个顺序 **= `Intro.unity` 里 `Config Manager` 的 20 个子物体的兄弟序**（逐个核过，见 §一末表）。
⇒ `ConfigManager.Unpack` 里的 `GetComponentsInChildren<IConfigProvider>()` 也是这个序（Unity 是 DFS + 兄弟序）。

### 0·2 配置怎么进来（链路，已确认）

```
登录响应 InfoResultPayload.TitleData（Dictionary<string,string>，值是 JSON 文本）
  └ PlayerDataManager._UnpackUserInfo_d__522__MoveNext  →  ConfigManager.Unpack(titleData)
       └ foreach (GetComponentsInChildren<IConfigProvider>())
            └ provider.Initialize(titleData)  →  config = UnpackInternal(titleData)
                 └ 基类：titleData.TryGetValue(config.ConfigKey) → JsonWrapper.DeserializeObjectWithType<T>(json)
                 └ 缺键：Debug.Log("Couldn't find Config of type " + 类型名) + config = null（**不抛**）
```

⚠️ `InitializeLiveopsResult.TitleData` 这个字段**在本 build 里没被 `Unpack` 用到**（`_UnpackUserInfo` 取的是登录 payload 的 `+0x18` = `GetPlayerCombinedInfoResultPayload.TitleData`）。所以**要补的键写在 `responses/fragments/playfab_profile.json` 的 `InfoResultPayload.TitleData`**，不是 `ExecuteCloudScript.InitializeLiveOps.json`。

### 0·3 ⚠️ JSON 字段名 = **C# 字段名原样**（含 `private [SerializeField]`）—— 已证

- 反编译判据：`SerializationHelper.IsMemberValid`（`/e/.../out_cpp2il_dev_ilspy/SerializationHelper.cs:50`）——
  一个成员会被（反）序列化，当且仅当：是字段/属性 + 无 `[JsonIgnore]` + 类型不是「Unity 但非 ScriptableObject」（`IsUnityOnlyValue`，`:216`），
  **且** 满足 `public` 或带 `[JsonProperty]` / `[SerializeField]` / `[SerializeReference]` 之一。
- 实跑反证：`AddressablesConfig` 的 `preprod` / `live` / `preprodBadges` / `remoteLabels` **全是 `private [SerializeField]`**（`AddressablesConfig.cs:44-70`），
  而我们塞的 JSON 用了这些**小写字段名**，运行期 `probe.log` 打出：
  `[WFP][ADDR] AddressablesManager.Init: preprod=Il2Cpp.AddressablesConfig+Environment; live=…; remoteLabels=…`（**全部非 null**）⇒ **契约 = 字段名原样**。
- 推论（对写 JSON 的人）：`ConfigKey` 是只读属性、无 `[JsonProperty]` ⇒ 不会被反序列化，不用给；
  `LoadableReference<T>` 只序列化 `targetId`（`[SerializeField] protected string targetId`，`reference`/`genericObjectReference` 都 `[JsonIgnore]`）。

### 4·2 🔴 顶栏 NRE 的根因很可能不是 `InventoryManager.Instance`（`B152` 的判定偏了一层）

`B152_离线版_阶段2_主菜单已加载.md` §七 第 2 条把 `ResourcesBarController.GetCounter` 的 NRE 判成「`InventoryManager.Instance` 为 null」。

```

 └ CurrencyExtensions.GetOwnedCount(manager, currency)      // CurrencyExtensions.cs:189
      └ ICurrency item = ToCurrency(currencyType);          // CurrencyExtensions.cs:42-80
```
