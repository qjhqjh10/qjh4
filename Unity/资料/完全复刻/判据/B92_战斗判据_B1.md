## 附录 D · 两条方法论坑（本轮现踩，⛔ 下次别再踩）

**D-① 改「多行 lambda 当实参」的调用时，先数原行有几个右括号。**
`EnqueueAbility(…, () => { … }))` 结尾的 `}))` = `}`(lambda 体) + `)`(实参表) + `)`(外层 `if (`/`return` 那一层)。
要加尾随命名实参，正确形状 = **`}, actionType: N))`**；
写成 `}), actionType: N)` 就**少了外层那一个 `)`** ⇒ `CS1525 / CS1002 / CS1513`（而且报的行号指着 lambda 体的最后一行，很迷惑）。
✅ 另一个坑：命名实参 **不能排在位置实参之前** —— `EnqueueAbility(…, actionType: 1, () => …)` 是 `CS8323`；`body:` 不必起名，**把命名实参放到最后**即可。

**D-② 判「原版某个动作的 actionType」⛔ 不能只 grep `BattleAction___ctor`。**
原版有**两族**写法：
· 走构造器：`BattleAction___ctor(&local_208, **0x4b**, …)`（例：`AddResetDuty.c:34` 的 `0x57`、`AddRecallToDeck.c:38` 的 `0x33`）；
· **绕过构造器直接写第 0 个 dword**：`local_208[0] = **0x10**;`（`CardScript__SendRemoveEffect.c:27`）/ `local_208[0] = **4**;`（`CardScript__TriggerUnitDeathActions.c:41`）。
⇒ 只 grep ctor 会**静默漏掉后一族**（我第一次判 `minionDeath(4)` / `removeEffect(16)` 就是这么漏的）。
✅ 正确搜法：`grep -rn "BattleAction___ctor" ` **＋** `grep -rn "\[0\] = [0-9]\+;"`（两族一起搜）。
