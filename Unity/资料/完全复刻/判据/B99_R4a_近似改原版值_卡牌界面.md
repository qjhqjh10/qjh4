## 1. 卡-2 `FitToBox`：把「8 次二分 / 无量化」换成 TMP 真正的 autosize

### 1·1 原版到底怎么算（逐句，判据全是第一手方法体 + 源码）

`TMP` 的 autosize 不是一个「在 `[5%*nominal, nominal]` 上二分的搜索」，而是**在 `[m_fontSizeMin, m_fontSizeMax]` 上做的括号式二分**，并且：

1. **起始字号不是作者填的 `m_fontSize`，是 `clamp(m_fontSizeBase, min, max)`** ——
   `TextMeshPro.cs:2147-2152`（UGUI 那份同义：`TextMeshProUGUI.cs:2499-2504`）：
   ```csharp
   if (m_enableAutoSizing)
       m_fontSize = Mathf.Clamp(m_fontSizeBase, m_fontSizeMin, m_fontSizeMax);   // :2149
   m_maxFontSize = m_fontSizeMax;   m_minFontSize = m_fontSizeMin;              // :2151-2152
   ```
   **而原版卡面每一层的 `m_fontSizeBase` 都是 0.145 ~ 0.16**（下表逐层实读）⇒ `clamp` 到 **`m_fontSizeMin`**。
   ⇒ **运行时那趟搜索是从 `min` 起、一路往上涨的**；作者填的 `m_fontSize`（23.55 / 19 / 21.5…）**在运行时不起作用**。
2. **缩**（纵向溢出时）：`TMP_Text.cs:4537-4546`
   ```csharp
   if (fontSize > m_fontSizeMin && m_AutoSizeIterationCount < m_AutoSizeMaxIterationCount) {
       m_maxFontSize = fontSize;                                   // :4539
       float sizeDelta = Mathf.Max((fontSize - m_minFontSize) / 2, 0.05f);   // :4541
       fontSize -= sizeDelta;                                      // :4542
       fontSize = Mathf.Max((int)(fontSize * 20 + 0.5f) / 20f, m_fontSizeMin); // :4543 ★量化到 0.05、再夹到 min
   }
   ```
3. **涨**（这一趟没溢出、且括号还没收够时）：`TMP_Text.cs:4811-4828`
   ```csharp
   fontSizeDelta = m_maxFontSize - m_minFontSize;                  // :4813
   if (isTextAutoSizingEnabled && fontSizeDelta > 0.051f && fontSize < m_fontSizeMax && …)
   {
       m_minFontSize = fontSize;                                   // :4820
       float sizeDelta = Mathf.Max((m_maxFontSize - fontSize) / 2, 0.05f);   // :4822
       fontSize += sizeDelta;                                      // :4823
       fontSize = Mathf.Min((int)(fontSize * 20 + 0.5f) / 20f, m_fontSizeMax); // :4824 ★量化、夹到 max
   }
   ```
4. **迭代上限 = 100**：`TMP_Text.cs:524`（`m_AutoSizeMaxIterationCount = 100`）；撞上限只打一条日志（`TextMeshProUGUI.cs:4509`）。
5. **两条更早的支是死的**（原版数据里它们的开关都是 0）：
   · 行距支 `m_lineSpacingDelta > m_lineSpacingMax` —— `m_lineSpacingMax = 0.0`、`delta` 初值 0 ⇒ `0 > 0` 假（`TMP_Text.cs:3406`）；
   · 字宽支 `m_charWidthAdjDelta < m_charWidthMaxAdj/100` —— `m_charWidthMaxAdj = 0.0` ⇒ `0 < 0` 假（`TMP_Text.cs:4518`）。
6. **只看纵向溢出**（`TextProUGUI.cs:3393` `textHeight > marginHeight + 0.0001f`；3D 版同构 `TextMeshPro.cs:3295`）⇒
   **不折行的层（卡名/阵营/兵种）原版永远不会横向缩**：它们只会「一路涨到 `m_fontSizeMax`」（见 §1·4 的推论）。

**⇒ 等价的可执行形态**（`Q(x) = (int)(x*200+0.5f)/200f`，即 0.005 网格 = 原版 0.05 pt）：
```
lo = min;  hi = max;  cur = Q(clamp(0.015 /*=base÷10*/, min, max)) = min
重复（≤100 次）：
  若 cur 这一趟装得下：
      若 hi - lo <= 0.0051  或  cur >= max  ⇒ 收工，结果 = cur
      lo = cur;  cur = Q(min(cur + max((hi - cur)/2, 0.005), max))      // 涨
  否则（装不下）：
      若 cur <= min ⇒ 收工，结果 = cur
      hi = cur;  cur = Q(max(cur - max((cur - lo)/2, 0.005), min))      // 缩
```
⇒ **结果必落 0.005 网格上**，且 = 「能装下的最大网格字号」（或 `max` 若 `max` 也装得下）。

### 1·3 差多少（可离线精算，⛔ 不需真机）

- **缩的那一侧**：我们最终落在「二分 8 次后的 `lo`」，区间宽 = `nominal × 0.95 / 256`。
  desc（nominal 2.355）⇒ **0.00874（我们单位）= 0.0874 pt**；tactic desc / 卡名（1.9）⇒ 0.00705 = 0.0705 pt。
  **原版**落在 0.05 pt 网格上 ⇒ 两者的最终值最多差 **一个区间宽**（≈0.087 pt）且**我们永远偏小**、原版永远是网格值。
- **涨的那一侧（比缩那边大得多，而且现在的写法完全没有）**：
  `DescTextUnit` 名义 23.55 → 原版 **24.0**（+1.9%）· `NameTextTactic` 21.5 → **24.0**（+11.6%）· `DescTextTactic Big` 25.2 → 26.0（+3.2%）· 放大窗 `NameTextUnit` 16 → **19.0**（+18.75%）。
  ⇒ **凡是「装得下」的文字，原版一律被拉到该层的 `m_fontSizeMax`，我们现在停在名义值。**

**真卡复算（`Roboute Guilliman`，账里那个「缩到名义 60%」的例子）**：
- 我们现读结果 **fontSize = 1.411**（名义 2.355）；判据 `资料/普查产出_1025/X17_卡牌线五件_执行报告.md:148`、`资料/任务线/卡牌线/任务总表.md:93`。
- 二分 8 次后 `lo` 的误差上限 = 0.00874 ⇒ **真实边界 ∈ [1.411, 1.4197]**。
- 原版 = 该边界向下取到 0.005 网格 ⇒ 只能是 **1.410 或 1.415**。
- ⇒ **改完这条，Guilliman 的字号变化 ≤ 0.005（= 0.05 pt = 0.35%）。**
  🔴 **结论（重要，别误判）**：卡-2 那条「正文缩过头」**不是这个近似造成的**，主因是**量尺**（见 §1·5），本件改完**页面观感不会变**。要「缩过头」真的改善，必须动 §1·5 那个预算。

### 1·4 顺手发现（同一条判据链，⛔ 别漏报）

1. **`NameTextTactic` 原版是 24 pt（em 0.24），我们给它的是 19 pt（em 0.19）** ——
   `BuildTextLayers` 里卡名**不分单位/战术**，都喂 `NameFontSize`（`CardView.cs:5818-5866` 的 `TitleEmOfCard = 0.0570` ⇒ 19 pt）；原版 `NameTextTactic` 的 `m_fontSize = 21.5`、`m_fontSizeMax = 24` ⇒ 运行时 = **24**。
   即：**战术卡卡名我们小了 21%**（0.19 ÷ 0.24）。这一条与 §1·2 的「涨」是同一处修复（给了 `max = 2.40` 就会自己涨到 2.40）。
2. **`FitToWidth`（不折行的层）在原版里根本没有对应物**：原版 autosize **只判纵向**（§1·1 第 6 条），`NameTextUnit` 又是 `m_TextWrappingMode = 0` + `m_overflowMode = 0(Overflow)` ⇒ 原版**长卡名就是溢出、不缩**。
   我们现在按行盒/字墨**缩到框宽**（`CardView.cs:6051-6094`）。⚠️ 这是 X17 修「真机卡名被右边框切掉」时加的，**如实记为一处「与原版不同」**，要不要改回「允许溢出」需调度台/用户裁（不影响本件的参数表）。
3. **`_fitCache` 的键里带的是 `nominal`**（`CardView.cs:5574-5585`）。改成「按层的 min/max」以后，**键必须跟着换成 min/max**（否则同一段文字、同一个框、不同层会串味）。
4. **`ClampToInk`（`:5723-5749`）是原版没有的一步**（原版只按行盒 `textHeight` 判）。它现在会在网格结果上再往下缩 ⇒ 建议保留（它修的是真机越框），但 **`ClampToInk` 之后要把结果重新向下取到 0.005 网格**，否则「结果必落网格」这条不成立。

### 1·5 🔴 比参数更大的偏差：我们量的**不是原版那个矩形**

- 原版：`DescTextUnit` 的 rect = **152.74 × 76.16 px**（`m_LocalScale` 0.01 ⇒ 1.5274 × **0.7616** 卡单位），autosize 拿**这个矩形的高**当溢出线（`marginHeight = rect.height − margins`，margins 全 0）。
- 我们：`descH = descBudget01 × Height`，**对称预算**（`CardView.cs:699-708` 的 `FaceDescBand01`；调用点 `:4977`）。
  账里实测：单位卡 + 有兵种行 ⇒ **0.1098 y01 = 0.3658 卡单位**，**只有原版矩形的 48%**（0.3658 ÷ 0.7616）。
- ⇒ 同一个字号，原版装得下、我们装不下。**Guilliman 的字号差主要来自这里，不是 §1·3 那 0.087 pt。**
