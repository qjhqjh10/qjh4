## 四、口径冲突 / 需调度台裁定

> 以下 11 条**都不是**「要多做功能」，而是**账的描述 / 落点错**或**代码注释过期**。按铁律 5 应就地改账 / 改注释。

**① `AddArmour` 账「差异」写反了。**
账写「原版加护甲 = 往 trait 表加 armour 并同步 Armor 数值」；`.c:45-56` 实读是**直接写 `currentArmourValue(+0xb8)` 字段**（`ObscuredInt` 五个字）+ 结果 < 0 时写 0 + `:59 UpdateHealthText`，**完全不碰 trait 表**。
等价性结论不变（我们的 `Armor` 字段就是那一格），但描述要改。另：我们**加侧不夹 0**（数据无负值 ⇒ 今天不可观测）。

**② `ClearPendingDamage` / `RecordPendingDamage` 的账落点指到了「谓词」。**
账分别写 `RuleCore.cs:7920 EnoughPendingDamageToDie` 与 `RuleCore.cs:7755 WouldKill` —— 这两个都是**纯预测谓词**，不是记账/清表口。
我们**没有 pending 台账**（架构性等价：伤害立即结算），所以正确落点应写「无对应物（结构性等价）」，而不是指一个谓词。

**③ `RemoveActiveEffect` / `RemoveActiveEffects` / `RemoveBuffedTrait` 三个共用一个粗粒度落点。**
原版三者的共同点：**只动 `activeEffects(+0x108)` 记录表**（按 `buffType ∈ {3, 90}` / `buffType == 参数` / `hideTrait` 过滤），**不动 trait 表**。
我们 6 个「Extrinsic / Trait 相关」都指 `Aura.cs:619 Recompose` / `UnitState.cs:1282 RemoveAll` —— 按 §3·2，**共用落点只能算「未核」**。这 6 条不是新缺口，是**模型差**（我们没有「效果记录」这一层）。

**④ 🔴 最重要的一条：`RemoveTrait` 我们**会多摘**。**
- 原版 `RemoveTrait` = 只摘 `+0x128` trait 表（`RemoveTraitAndEffects` 之所以另立，就是因为它**不**摘效果）。
- 我们 `RemoveAll` = 关键词 **+ 它授予的属性/正文** 一起撤。
- ⇒ 原版**单独用** `RemoveTrait` 的 4 处（`CardScript__CheckStun.c:11` · `OnTurnEnd.c:126/133/138` · `RemoveDropPod.c:8` · `UseSurvivor.c:42/70`）在原版里**属性留着**，在我们这里**会被一起摘掉**。
- 影响面：`stun` / `blind` / `survivor` / `droppod` / `duplicitous` 这几条 trait 本身不带属性增量 ⇒ **今天很可能不可观测**；但只要将来有「带 addStats 的 trait 被单独 `RemoveTrait`」，就会多摘。
- **需裁定**：照原版把「trait 层 / 效果层」分开（大改），还是承认「我们无分层」并把这条差异写死在账里（推荐前者，铁律 11 要求照做；但它是引擎层结构改动，不是本片能定的）。

**⑤ `RemoveBuffHandCostEffects` 少一道闸。**
原版：`permanentBuff == 0` **∧** `buffType == 2` **∧ `enchantingCard(+0x18) == 双方英雄之一`**。
我们：只判 `Permanent`（且是**卡级** `permanentBuffs` 列，不是效果级 `+0x74`）⇒ **没有「施放者是英雄」这一道**。
若手牌费用修正来自非英雄来源，原版**不摘**、我们**会摘**。

**⑥ `RemoveCardFromCemetery` 账判 D 可以升 A，但「生产端目标层缺墓地表」要单列。**
等价物 `RuleCore.cs:17113 ExileFromCemetery` + 读点 `:16002` 都在；但生产行 `chosenAbility 350`（`EffectResolver.cs:19625`）**解不出目标集**（`ta = 60` 墓地表在我们的 `ResolveTargets` 里没有对应档），会出声空转。池内 `chosenAbility == 350` = **0 / 1351** ⇒ 休眠。

**⑦ `SetAsActiveTrap` 账判 D **过期**，应升 A。**
等价实现 = `CardInstance.ArmedTrap`（2026-10-27 `E7ENG`，构造时一次算定，三态含「判不了」出声）。
顺带：`ConditionEval.cs:188-189` 的注释「我们**没有**『已布置的陷阱』这一层（`armedTrap` / `cardState` 都不在模型里）」**已过期**（`ArmedTrap` 已建、`cardState` 由 `UnitStateCardState` 承载）—— 但 `cond 0` 在数据里从不出现 ⇒ 仍是恒真，**行为不变**。

**⑧ `RemoveExtrinsicEffectsFrom` 的口径差要在账里标（代码里已标）。**
动作 47 的结算体在原版调的是**无参**重载（摘该卡身上**全部** extrinsic）；我们**按来源**摘 ⇒ 少摘「别的施放者挂的」。我们自己的日志（`EffectResolver.cs:19759`）已经如实写了，账里「差异」列没写。

**⑨ `GetTargetsAvailable` 的落点不是同一个东西。**
原版是「主动能力专用」的薄转发 + `rawCardData.activeAbility(+0x298)` 非空闸 + 空 ⇒ **返回空表**。账落点 `ResolveTargets` 是通用解析。要核「主动能力没目标时是否返回空表」。

**⑩ `SetAmbush` 的落点跨了层。**
原版是**表现层**（伏击面 = 卡背 sprite + 藏数值 + 藏法力灯）；账落点 `DeclareAttackCore` 的伏击支是**结算层**的「翻开」。我们的「伏击面绘制」本片没找到指名实现 ⇒ 要么补落点，要么在账里标「表现侧未复刻」。

**⑪ 代码注释过期一处（顺带发现）。**
`Aura.cs:1068` 写着「本方法（`RemoveExtrinsicBySource`）现读**全仓 0 个调用点**」—— 实际 `EffectResolver.cs:19759 BroadcastRemoveEffectsFrom` 在调它。按铁律 5 应就地订正（否则下个会话会按「没人用」判它可删）。
