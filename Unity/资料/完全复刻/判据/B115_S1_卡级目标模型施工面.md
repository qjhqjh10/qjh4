## 2. 类型设计：`CardRef`

### 2·1 形状（推荐）

新文件 **`Unity/MyGame/Assets/RuleEngine/Core/CardRef.cs`**（⚠️ 类名必须 == 文件名，见 `CLAUDE.md` 那段 `!u!115` 根因）：

```csharp
namespace RuleEngine
{
    /// <summary>原版「目标」的等价物 = 一个 CardScript（手牌 / 牌库 / 墓地 / 场上同型）。
    /// 我们的等价物 = CardInstance（唯一身份）+ 可选的 UnitState（棋盘载体）。</summary>
    public readonly struct CardRef : System.IEquatable<CardRef>
    {
        public readonly CardInstance Inst;    // 唯一身份（UnitState 也有一个，见 UnitState.cs:32）
        public readonly UnitState    Unit;    // 棋盘载体；不在场 = null
        public readonly CardDef      Template;// 只有「没有实例的模板」才非 null（原版不会有 ⇒ 正常不走）

        public static CardRef Of(UnitState u);      // Inst = u.Instance, Unit = u
        public static CardRef Of(CardInstance i);   // Inst = i, Unit = null
        public static CardRef Of(CardDef d);        // Template = d（构造夹具/降级用，出声）

        public CardDef Card { get; }                // Inst?.Card ?? Template
        public bool IsOnBoard { get { return Unit != null; } }
        public UnitState ResolveUnit(BattleContext ctx);  // 按 Inst.Id 现扫棋盘（换位/补位后仍对）
        public bool Equals(CardRef o);              // 判据 = ReferenceEquals(Inst)（Inst==null 时比 Template）
        public override int GetHashCode();
    }
}
```

三条设计理由（都要写进代码注释）：

1. **身份只能取 `CardInstance`**：`UnitState.Instance`（`UnitState.cs:32`）已经存在，且 `UnitState(CardDef,…)` 那条夹具构造器（`UnitState.cs:940`）也会造一个 `CardInstance.Detached`（负 id）⇒ **没有「没有实例」的棋盘单位**。
2. **`Unit` 必须一起带**：`ResolveTargets` 的 60+ 调用点全部要 `UnitState`，每项现扫棋盘是 O(n·board) 且会丢「已离场/待死」的对象（原版 200 那一档**明确保留已离场的**）。⇒ 产出的地方知道就填上。
3. **`Template` 只为降级**：`AM54` 那种「战术卡自己打出去」在 380 写表时**要的是那张手牌实例**（`CardInstance`），不是模板。模板态只留给「数据里只有 CardDef」的夹具；一旦走到，**必须出声**（⛔ 不许静默当场上单位）。

### 2·2 落点选择：**挂 `CardInstance`，不另起一张并行表**

原版载体是 `CardScript.referencedCards`（J3）—— 手牌与场上**同一个字段**。我们的对应物：

| 原版 | 我们现在 | 目标 |
|---|---|---|
| `CardScript.referencedCards`（`+0x278`） | `UnitState.ReferencedCards`（`UnitState.cs:833`，`List<UnitState>`） | **搬家到 `CardInstance`**：`CardInstance.ReferencedCards`（新字段，追加到 `CardInstance.cs` 类尾）；`UnitState.ReferencedCards` **改成一个转发属性** `=> Instance.ReferencedCards`（旧调用点零改动、且战术卡也能写） |
| `AbilityLogic.abilityTargetsToSave`（`+0x80`） | `BattleContext.AbilityTargetsSaved`（`:1155`） | 换类型 `List<CardRef>` |
| 静态 `pooledPossibleTargets` / `CardScript.previousAbilityTargets` | `BattleContext.PreviousAbilityTargets`（`:1134`） | 换类型 `List<CardRef>` |

⚠️ `UnitState.ReferencedCards` 现在是 `readonly List<UnitState>` 字段，改成属性对**读**是兼容的（`.Count` / `[i]` / `Clear()` / `Add()` 照用）；对 `new List<UnitState>(u.ReferencedCards)` 这类**构造拷贝**会失配，需逐个核（现读只有断言文件用，见 §3 清单）。
