## 一、本会话做了什么

### 1.1 JS 冻结（A 机卡 65%）—— 根因 + 修复 + 真机验证

**根因（源码级）**：`Process.enumerateThreads()` 返回的 `ThreadDetails` 带 CPU context ⇒ 每个线程走
frida-gum `gum/backend-linux/gumprocess-linux.c` 的 `gum_process_modify_thread`：
① `socketpair(AF_UNIX, SOCK_STREAM)` · ② `gum_libc_clone(CLONE_VM|CLONE_SETTLS)` 单线程子进程 ·
③ 子进程 `PTRACE_ATTACH` 目标线程 · ④ 调用方 `read()` 等 ACK。
子进程一卡（ptrace 冲突 / 线程重建），**调用线程永久阻塞在 socket read**。
现场完全吻合：`gum-js-loop · state=S · wchan=unix_stream_read_generic`、冻结 fd 与另一 socket **inode 相邻**
（311=14032342 / 322=14032343）、`TracerPid=0`、`pidof` 两个 pid（多出的是 clone 子进程，坑 566/568）。

**踩中的调用点**：`src/main.js` 的 `[ALIVE] … threads=`（dev 每 3 s，**跑在 JS 事件循环线程**，主犯）·
`watchThreads()` · `src/crash.js dumpThreads()` · `src/perftrace.js findJsThread()`。
以前「关掉每秒 enumerateThreads 冻结率没变」是因为关的是 `thrScan`，`[ALIVE]` 这一直在调。

**修复**：四处全部改读 `/proc/self/task`（`WFStore.io.listDir` / libc `opendir`）；
**纪律：任何运行路径禁止 `Process.enumerateThreads()`**；需要别的线程栈时用外部 attach。
另修了两个**从未定义**的静默 ReferenceError：`dumpJsThread` / `installForkTrace`。
兜底实验（默认关）：`files/wfq/wake_on` 存在时向「两端未命名、inode 相邻」的 socketpair 各写 1 字节唤醒。

**真机验证（A 机，修复后 dev JS）**：冷启动 **20/20 PASS**（`freeze_probe.py` 10+10 轮 × 50 s）·
伪重启/换号 **6/6 PASS**（`restart_exp.py`）；`files/wfq/js_dead_*.txt` 停在 **01:58**（修复前），之后不新增；
`pidof` 只剩 **1 个 pid**。

## 三、关键结论 / 判据（新会话直接用）

1. **禁止 `Process.enumerateThreads()`**：任何运行路径都读 `/proc/self/task`；别的线程栈用外部 attach（listen gadget）。
   违反这条会重新引入 `gum_process_modify_thread` 的 socketpair/ptrace 冻结。
2. **登录白名单**：`LoginWithEmailAddress` 必须同时出现在 `DecksApi`（Java）· `inv.js` · `friends.js` · `decks.js`；
   否则换号后初始卡组/档位/好友不注入。
3. **模板里不要放测试卡组**：`responses/fragments/playfab_profile.json` 的 `UserReadOnlyData.PlayerDecks.Value` 已清空；
   ⚠️ 改模板后 **PC 出包要重打 `wf_server.exe`**（`LONG-01`）。
4. **卡组保存语义照原版**：不完整/非法卡组不能保存（`IncompleteDeck`）；「点了没反应」先查 `ValidateDeck` 与
   `doneButton` 文字（非法时是「丢弃」）。已同步且未改的卡组只关窗不上传（原版早退分支）。
5. **账户页已登录判据 = `PlayerDataManager.playFabEmail`(0x348)**；伪重启/下次登录会重置它 ⇒
   菜单后延迟补写并 `AccountTab.Refresh`。
6. **云端保存需要 `files/wfq/cloud.txt`**（或包内 `assets/wf_cloud.txt`）；Java `CLOUD_URL` 首次读取后缓存，
   运行期补写文件要**重启进程**才生效（本会话就是这样恢复 rev=130 的）。
7. **Honor 装包用 `pm install`**（push 到 `/data/local/tmp`），不要依赖 `adb install` 的确认框。
8. **`BattleErrorUIManager` 在 `Everguild` 命名空间**；`cls` 要试全名。
