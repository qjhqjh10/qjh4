   - `[SRV] 看门狗 listener=… started=… re=… hits=…` —— **有没有打出来**：

## 六、本会话新增坑（556–561）

- **556** 外部设备「最后一次出日志的位置」会随版本漂移 ⇒ 别拿「最后一行是哪个模块」当凶手；稳定判据只有「等待期全活」+「开工后 X 秒内停日志」；
  并记录：j 构建曾在同机**把 47 个模块全装完**后照样停。
- **557** 安卓「帧心跳」钩导出符号没用（Vulkan 的 present 走 dispatch 表，`eglSwapBuffers`/`vkQueuePresentKHR` 都不触发）；
  而且 **Unity 主循环不在进程主线程**（要量 `comm == "UnityMain"` 的 CPU）。
- **558** Android 16 上先怀疑 **Frida × ART 的 GC 栈走查**（`frida-java-bridge#387/#394`：`CodeInfo::DecodeGcMasksOnly` 空指针，fault 0x0）；
  缓解：换 Frida 版本 / `cmd package compile -m verify` / 减少钩子与分配。
- **559** 开场视频那两个探针钩子（`VideoPlayer.Prepare/Play/Pause/Stop` + 把 `GameBootController.Update` 换成 JS）
  在外部一加机上疑似致命；**能跑的 c 里这两个字符串出现 0 次** ⇒ `src/probe.js` 默认关（`DIAG_BOOT_VIDEO=false`）。
- **560** **Android 17（SDK 37）上光挂 Frida gadget 就会在启动几秒内死**（realme 上有一次连 10 s 等待都没撑过）
  ⇒ 先换框架版本，别改模块；Frida 官方对 Android 17 目前**无任何说明**。
- **561** **「卡在 65% + 假服务端监听口消失 + 进程还活着」**的判据与抓法：
  `cat /proc/net/tcp /proc/net/tcp6 | grep -c 2245` = 0 · `pidof` 有 pid · 截图看百分比；
  这是「闪退」的另一种形态（人看着卡住就关掉）。缓解：`server.js` 自愈 + 看门狗。
