## 三、原版棋盘机制（判据：反编译 + 场景 prefab）

| 事实 | 判据 |
|---|---|
| 棋盘 = **战将左右两翼**（不是两个玩家） | `MinionManager.leftMinions` / `rightMinions`；`GetLeftSlotPos/GetRightSlotPos` |
| 每翼 **4 格**（`slotsPerSide = 4`） | `Battle Arena 1.unity`；`FillMinionPositions()` 按该值重建数组 |
| 槽位坐标 `Awake` 时由 `MinionSeparation` / `origPosReduction` 重算（序列化 ±3/±6/±9 只是占位） | `MinionManager__FillMinionPositions.c` |
| 放牌 = **插入**：`InsertMinion` → `AdjustedSlot` 钳制/翻翼 → 按索引 `Insert` → `RefreshOccupationSlots` ⇒ 列表天然连续 | `MinionManager__InsertMinion.c` / `__AdjustedSlot.c` |
| 越界槽位**钳到最后一格** ⇒ 一翼超过 4 个会叠在同一格 | `GetLeftSlotPos` / `GetRightSlotPos` 开头 |
| 战将**不占**槽位 | `AddMinionOccupation`：`cardType == 10`（Hero）直接 return |
| 两块棋盘**不做左右镜像** | 场景 `EnemyBoardArea` / `PlayerBoardArea` 的 `m_LocalRotation` 都是 identity |

**左右问题的答案**：棋盘数据不镜像，左右翻转来自**双方摄像机隔着战场相对** ⇒ 你右边 = 对手屏幕上的左边；
同队两人（P1/P3）共用同一块棋盘与摄像机 ⇒ **队友之间不会互相左右翻**。

## 四、本会话修的两条（等你实机复验）

### 4.1 翼列表重复 ⇒ 位置乱 / 左右横跳（坑 243）

修前实机：

```
units: P:UM66#-87230@100.9                      ← unitsInPlay 只有 1 个
WING P slots=4 R=2[UM66@100.9  UM66@100.9]      ← 翼列表里有 2 份
```

修法：每拍 `DedupeUnits` 里新增 `DedupeMinionWings` —— 两侧 `playerMinionManager` / `enemyMinionManager`
的 `leftMinions/rightMinions` 按 GameObject 实例 id 去重，然后调原版
`RefreshOccupationSlots()` + `ReassembleMinions(null)` 收口。日志 `b4:units dedupeWings`。

修后实测：`WING E L=1[UM1@98.3] R=1[UM2@102.3]`（对称、各一格）；
把一张部队丢到离战将很远的位置，它落在战将旁边（右翼第一格）。

### 4.2 AI 回合空转（坑 244）

实机：座位 1 连续 **14 次**执行同一动作（`Forward Deployment → Incursor`，每 15 秒一次、单回合 `plays=18`），
回合卡 3 分钟；另有 `attackMelee card=UM46 target=UM46`（AI 把自己当目标）。
`GetAvailableActions` 每轮把它当最优返回，`ExecuteAction` 不抛异常也不生效。

修法：同一动作签名连续 2 次 + 「手牌数/能量/单位数」无变化 ⇒ `break` 走结束回合（日志 `b4:ai2 sameActionBreak`）。
修后实测 AI 回合 10 秒内推进。

### 4.3 附带加固

`GoId` 取不到实例 id 时返回 **-1** ⇒ 去重前 `id < 0` 一律放过，避免把真单位当重复删掉。

## 六、下一会话要做的两条（用户指定）

### 6.1 卡牌动画在切到队友回合时重演

**已知可疑点**（按嫌疑排序）：
1. `SwapSeat` 里对旧/新战将 `SetActive(false/true)`（会重播战将入场动画）；
2. 换手牌时 `ActivateList(...)` + `PositionHandCards(...)`（可能重播抽牌/入手动画）；
3. 每拍 `ReassembleMinions` 重摆所有单位的位移动画。

**做法建议**：先在 `Battle4Probe` 里给这三处加时序日志（谁在换座时 SetActive/Activate/Reassemble），
再用 `wf_record.py` 录一段「本机回合 → 队友回合」的窗口视频，按时间轴对上日志，确认是哪一段；
**先查清再改**，⛔ 不要先猜着关动画。

### 6.2 队友回合 UI 仍可交互

实机现象：本机在座位 3、队友（座位 1）行动时，屏幕仍显示本机能量与「结束回合」；
拖牌被 `b4:gate CanPlayCard.deny acting=1 my=3 initiate=true` 拦下 ⇒ 玩家看到的是「点了没反应」。

**做法建议**：非本机回合时把出牌区压暗 / 拖拽禁用（🔶 自己设计，需在代码里打標），
**⛔ 不要改成交给队友操作**（用户口径：手卡只看自己的）。
