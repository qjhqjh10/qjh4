## 八、🔴 本会话新发现的知识（**都是坑，别重踩**）

1. **`play check` 不跑 `play all` 的两条自检**（⑦ 付费前缀 / ⑧ 事件电池）⇒ 「`play check` rc=0」**证明不了**它们绿。⑧ 那条红从第九十三会话起就藏着。
2. **探针读不到的列 ⇒ 「play 输出没变」是伪证**：`ruleprobe` 的 `LoadPool` **不读 `abilitySummon` 列** ⇒ `Card.AbilitySummons` 恒 null（本会话 `B94_B20` 实证：改前/改后/还原三态指纹一模一样）。同族 = `A1911`。
3. **`cards_engine.json` 的 `chosenAbility` / `abilityTriggers` 是嵌套列表** —— 按顶层标量扫会得到**总数 0**，拿「0 命中」当「池内 0 张」是**空集上的假否定**。
4. **`cards_truth.json` 是稀疏导出**（`0/0.0/""/false/[]/null` 一律省略）⇒ 按「有没有这个键」数 0 值**必然数出 0 处**（本会话因此差点误判「12 张单位卡零差异」，实际是 `createAtPos=0` 的 12 行）。
5. **`Quaternion.Angle` 在本机有 0.16206° 盲区**（`IsEqualUsingDot` 的 `1−1e-6`）⇒ 小于该角**恒返回精确 0**。用 `Editor/BattleScene.cs:48485-48504` 的 `AngleDegTiny`。
6. **`RVA 0x4B33B0` = 空桩 `ret 0`；`0x6FB110` = 全局 `return false` 桩**（`xor al,al; ret`）；而 **`0x4B3630` 不是空桩**（`mov rax,[rcx+0x18]; ret` = 真字段取值器）。Ghidra 会把不同小方法折成同名同址 ⇒ 名字与分支都不可信。
7. **`out_cpp2il_dev_ilspy` 只导了 `Assembly-CSharp.dll` 一个程序集** ⇒ firstpass / TMPro / UnityEngine.UI / NaughtyAttributes 的泛型类**必然「三源全无」**，不是解不出。
8. **`.c` 首行名 ≠ 文件名**：可能是**内容错位**（已抓 10+ 例），也可能是 **ICF 折叠**（体逐字相同）⇒ **读体再判，别看名字**。
9. **`grep` 不到 ≠ 不存在**：本会话 `B94_B19` 只搜 `RuleEngine/` 就断言「`PermitsPlayerAction` 全仓 0 调用点」，实际调用方在 `CardPresentation/`（**10 处**）。**一律全仓 `Assets/` 搜**。
10. **`BattleAction` 在 Ghidra 里被当 `0x100` 字节整份拷贝，实际 ≥ `0x200`** ⇒ 落在 `base+0x100..0x200` 的局部量会「没有赋值点」（不是丢句）。
11. **同一个 `keepEffects` 位控制三件事**（重置/只摘自身 · 撤不撤队列 · 吃不吃召唤病）—— 接生产端时 ⛔ 别拆成三个形参。
12. **断言「从未执行过」会暴露一批老问题**：本会话把 14 个断言族接上宿主后，第一次跑就冒出 47 条红，其中绝大多数是**断言自己写错**（`MainMenuRuntime.Instance` 在编辑模式恒 null · 断言写死改动前的行为 · 夹具跨过循环回绕点）。
13. **`CardsCells`/`ItemDrawer` 一类「同名两处」**：`Shell/OfferContainer.cs` 与 `CardPresentation/Shell/OfferContainer.cs` **是同一个文件**（`Assets/` 下没有顶层 `Shell/`）—— 所有权表按短名写会分给两个代理。
14. **一次 `LocalPlayerData` 的 key 写错（缺 `_ours_` 前缀）⇒ 整条存档链从来没通**，而断言只报「写不进/读不回」，看起来像测试问题。**字段型缺陷要用「生产路径跑一次」才看得见。**
