## 一、一句话

**原版「预组卡组」= 出厂就烧在客户端包里的官方卡组资产**（`PrebuiltDeck : PlayerItem`，`ScriptableObject`），
**不是服务端下发、也不是玩家卡组**。一副 = 一个督军 + 一张卡背 + 一份写死的卡 id 列表（**30 张经典 / 12 张遭遇**），
再用 `Type` 与 `isPracticeDeck` 分流成「教程 / 机器人 / 练习 / 新账号初始」四种用途。

🔴 **别和 `PrebuiltPack` 混** —— `PrebuiltPack : IdentifiableSO`（`packName/packId/packArmy/packTier/cardIds`）
是**售卖的卡包**，不是卡组。（`PrebuiltPack.cs:3-17`；UI 说明书 `菜单全树.md:6552-6560`）

> 📌 **和「卡牌数值在服务端」不同**：卡牌**数值**确实在服务端，但**整份预组卡表在本地**（236 个资产）。

## 四、分流：一副资产进哪张表

**唯一入口**：Addressables 把 236 个资产加载完后，逐个塞进 `PlayerDataManager.PrebuiltDeckCollection`
（`AddressableDeckLibrary__AssetCompletedLoading.c:36-38`；全仓 grep `PrebuiltDeckCollection__AddDeck` **只此一处调用**）。

`AddDeck`（`PrebuiltDeckCollection__AddDeck.c:21-35`）：

1. **资产名含 `"Tutorial"` → 直接丢**（那 12 副教程牌不进任何表）
2. 否则进 `decks`
3. `Type == 0 (Bot)` → **同时**进 `botDecks`
4. `isPracticeDeck` → **同时**进 `practiceDecks`

⇒ **decks 224 · botDecks 196 · practiceDecks 103**（三张表的偏移 `PrebuiltDeckCollection__.ctor.c:14,18,22`；
103 与我们已知的练习池数一致，**交叉印证**）
