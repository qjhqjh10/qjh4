用户 2026-09-22 裁决 #2 明确 **不做**，见 `资料/阶段二外壳_待裁决清单_0922.md`。）

### 九·一 从那个 store 身上读到的**真实数据形状**（这就是「还差什么」的答案）

`Premium Campaign Store.json` 的字段：
`eventId` · `activationType` · `dates` · `filter` · **`drawData`** · `priority` · `location` · `showInMainMenu` ·
`transactionLocation` · `extraNotificationsToWatch` · `offerLists` · **`items`** · `references`。

- **`items`（13 条）每条长这样** —— 这就是商品数据的真形状：
  ```json
  { "item": { "targetId": "premium_campaign_um" },
    "price": { "Currency": 30, "Amount": 1999 },
    "availability": -1,
    "sku": "premium_campaign" }
  ```
  ⇒ **`{物品 id, 价格(币种枚举 + 数额), 可购次数, sku}`**。
  我们 `ShopData.ShopOffer` 的 `Name/Type/Art/Price/Owned/Available/AvailableMax` **形状对不上** —— 见 §六 第 2 条。
- **`drawData.EventLabels[]` 就是页签的文案**：`{key, value:{mTerm}}` ——
  `ShopWindow.CreateStoreTab` 里 `LiveOpsAssetUtility.**GetLabel(store, 0)**` 取 **`key = 0`** 那个；
  `LoadAsset(store, 0)` 取**页签图标**。
  本 store 的两个：**`key 1` = `Store 1`** · **`key 0` = `Premium Store`**。
  ⚠️ `drawData.EventAssets` / `EventComponents` **都是空数组**（= 这个 store 没有自带图标件）。
- ⚠️ `xsollaBundleData.names` 里确实有**八语言的真名字**（`<en>Premium Expansion Pass</en>` …），
  但那些属于**活动报价**、不是商店页签。

### 九·二 结论（三条，别推翻）

1. **页签表**：本地**判不出**（原版由服务端 store 列表驱动，prefab 只序列化一个母版键）⇒ **我们挑的**（§一·二）。
2. **页签文案**：机制是 **`store.drawData.EventLabels[key=0].mTerm`**；
   `Premium Campaign Store` 那一个是 `Premium Store` —— **但那不是我们三个页的任何一个**。
3. **商品数据**：本地**只有 1 个 store 的 13 条**（而且属于 `PremiumCampaignStore`，与我们的三个页无关），
   其余全是**过期活动** ⇒ **我们三个页的商品只能自己编**。**形状也对不上**（真形状见 §九·一）。
