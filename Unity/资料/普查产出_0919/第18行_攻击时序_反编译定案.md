## 六、🆕 2026-09-29：段1「位移到攻击位」的**目标点公式**（解出来了，可直接照写）

> **为什么补这一节**：用户看演示时指出「**攻击的动画和原版不一致**」，查实根因是**我们把 `timeToChargeAttack`
> 当成了攻击前摇**（见 §七）—— 而要对齐就得知道**原版到底位移到哪**。这一节把它解出来了。

```csharp
// 段1：0.1s（attackStepTime）· Linear（SetEase(...,1,...)）
Vector3 origin = transform.TransformPoint(originalLocalPosInPlay);   // 攻方的「出手点」（世界）：+0x2C4
Vector3 pos    = 受击方.transform.position;                          // 不是棋盘格位（函数名叫 GetBoardPosOfCard，实为 transform.position）
Vector3 dir    = Vector3.Normalize(pos - origin);                    // 长度 ≤1e-5 ⇒ Vector3.zero（FUN_180534610 已证 = Vector3.Normalize）
float  margin  = IsPlayer ? playerAttackMargin(1.7) : enemyAttackMargin(1.0);   // 攻方自己的 isPlayer（+0x40）；只用来选 margin
float  dy      = (受击方.CardUI.effectsAnchor.position.y - 受击方.transform.position.y) * attackPositionYOffset(0.5);
Vector3 endPos = pos - dir * margin + Vector3.up * dy;               // ⚠️ `Vector3.up` 是**静态** upVector（只改 y）
```

- **`margin` 是沿归一化方向的绝对世界距离**（不是百分比、也不是纯轴向）。
- **段4 归位 = `DOLocalMove(originalLocalPosInPlay, 2 × attackStepTime = 0.2, OutQuart)`**
  （⚠️ 段1 用 `DOMove`（世界）、段4 用 `DOLocalMove`（局部）—— **别混**）。
- **段2 / 段5 的转向**：`DORotateQuaternion` —— 先绕 `Vector3.up` 转 **90°**、再乘 `attackRotationAngle = 25°`；
  归位那半回到单位四元数。⚠️ **这两段代码里没调 `SetEase`** ⇒ 吃 DOTween 全局默认（默认 OutQuad，**但那是配置不是本代码规定**）。
- **远程不共用**：`_ResolveAttackRangedAnim` 只有 `DOLocalMove(originalLocalPosInPlay, attackStepTime)` 回正，**没有任何目标点公式**。
- **每帧还有一条** `CardUI.scaleByPosition.GetScale(isPlayer, 卡的当前 localPosition, defaultScale)` 在改 scale（只影响缩放）。
- 出处：`CardScript._AttackMeleeAnim_d__357__MoveNext.c:132-137`(origin) · `:139-153`(pos/margin) · `:158-197`(表达式拼装) ·
  `:198-201`(DOMove+Ease) · `:202-207`(OnComplete=命中帧) · `:208-257`(段2 转向) · `:258-259`(段3 0.1s) ·
  `:260-268`(段4 归位) · `:269-280`(段5 归位转向)；字段名 → `dump.cs:35406/35408/35410/35412/35414/35416/35492/35486`；
  `Vector3.Normalize` 的身份由 `工具/disasm_va.py` 反汇编 `0x180534610` 证实。

## 七、⚠️ 我们现在的实现与它的差别（**这是用户看到的「不一样」**）
