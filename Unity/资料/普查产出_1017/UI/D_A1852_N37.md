## 一、`A1852` `MenuDeck/CantImportDeck` 的 `{0}` 是什么 —— **已查实**

**判据 = 反编译方法体**（`d:/2/tools/decomp_full/DeckInfoPopup__EditDeck.c`）：
```
cVar2 = DeckInfoPopup__CanImportDeck(...);      // bool
if (cVar2 == 0) {
    uVar3 = LocalizationManager.GetTranslation("MenuDeck/CantImportDeck");
    uVar1 = *(int*)(deck + 0x50);               // deck.warlord 的 army
    uVar4 = GameStaticData__CardArmyToString(uVar1);
    uVar3 = System_String__Format(uVar3, uVar4);
    UIMessageController__ShowError(uVar3);
}
```
⇒ **`{0}` = 这副卡组督军的【阵营名】**（`GameStaticData.CardArmyToString`，即本地化的 `Armies/*`）。
**不是数量、不是卡名、不是理由。**

**官方文案**（`Resources/official_loc_13lang.json`，2026-10-17 现读）：
- EN：`Can't import deck. You don't have enough {0} cards.`
- ZH：`无法导入卡组。你没有足够的{0}张牌。`

**我们现状**：`Core/Loc.cs:2008` 的自拟两列（"这副卡组导不进来。" / "This deck can't be imported."），
`Shell/DeckInfoPopup.cs:1616` 又在后面拼 `"（" + wl.Name + "）"` —— **两处都不对**。

**改法**：
1. `Core/Loc.cs` 那一行改成官方两列（带 `{0}`）。
2. `DeckInfoPopup` 那一处改成 `string.Format(Loc.T(key), CardText.Faction(wl.Faction))`，
   删掉拼 warlord 名字的尾巴。
3. 断言：断「拼出来的串里含阵营名」+「不含卡组名」。
⚠️ 落点 `Core/Loc.cs` 与另一个写手冲突 ⇒ **下一批再做**（已记账）。

## 二、`N37①` `Demo/AvatarMenu/SelectAvatarButton` —— 原版 prefab **没有 `Localize`**

**现核**：`bundle_menus_assets_all` 里三处 `m_text = "Selecionar"`（葡语占位）的节点：
- `Player Profile Window > … > Avatar Tab > Selected Item Panel`
- `Profile Cosmetic Tab > Selected Item Panel > Select Avatar Button > Button Text`
- `Player Profile Window > … > Title Tab > Selected Item Panel`

这三个 GameObject 上挂的组件 = **TMP + `EverguildTextMeshPro`（max/minFontSize）+ `EverguildButtonMaterialModifier`（无字段）**
⇒ **没有任何一个组件带 `mTerm`/词条字段** ⇒ **原版 prefab 里这颗钮的文字没有本地化接线**（占位就是 `Selecionar`）。

**结论**：官方表里确实有 `Demo/AvatarMenu/SelectAvatarButton`（值 `Select` / `选择`），
但**「原版用的是这条键」是推断、不是 prefab 证据**。按「有疑问就查解包」的口径：
- ✅ **接**：显示名用官方键（比葡语占位更接近玩家看到的成品）；
- ⚠️ **如实标**：「原版 prefab 无 `mTerm`，按官方键接线属推断」。
- ⛔ 别再写「原版就是这条键」。
