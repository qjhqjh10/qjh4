## ② `decklists.json` 的 S1 玩家副 `faction` 标错 → **已按判据订正**

**事实**：`deckId=UMTutorial`、`heroId=ec0d25faeb266ea4eaec41ae72b8d8ad` 那一条（S1 玩家侧）写着 `faction=EmperorsChildren` /
`factionId=120` / `armyId=120` / `heroPortrait=…Lucius.png` ⇒ 督军解析去 EC 表里找 ⇒ **对不上**。
**该按哪个为准：三处对照一致指向 Ultramarines** —— ① 教程 SO 的 `m_Name` = `Ultramarines_Deck0_Tutorial1_Uriel`
（`bundle_prebuiltdecks_assets_all/MonoBehaviour/`，它的 `cardLibraryIds` 与本行 `cardIds` 逐项相同 ⇒ 确实是同一条）；
② 同 SO 的 `deckHero.targetId` = 那个 GUID，`warlord_ids.json` 里该 GUID = `UM_Warlord_Uriel Ventris`；③ 卡池里 = `UM3 Uriel Ventris`（Ultramarines）。
原版 SO 里**没有** faction 字段（`cardArmy=0`）⇒ `faction` 那一列是我们导出端的产物 ⇒ **数据订正，直接改**。
**根因（顺手查到，已写进 `gen_prebuilt_decks.py` 的 docstring）**：旧 Godot 工程 `d:/warpforge/tools/export_game_data.py:73`
`faction_of_deck()` 拿 `heroId` 的**头两个字母**当阵营前缀（`PREF2['EC']`），而这条 `heroId` 是 **32 位十六进制 GUID** `ec0d25fa…`
⇒ `EC` 命中 EmperorsChildren。**原版 id 是「字母+纯数字」（`EC56`）**；它自己的 deckId 兜底（`UMTutorial` → alias `ultramarine`）本来会给对，只是没轮到。
🔴 **实测 236 副里只有这一条踩到**（其余 GUID heroId 的阵营都对得上）。

**改了什么**：那一条的 **4 个字段**（`armyId` 120→10 · `faction`→`Ultramarines` · `factionId` 120→10 · `heroPortrait`→`…UI_Deck_Warlord_Titus.png`）。
`heroPortrait` 是导出器**按阵营**推的（`faction_defaults`；实测 236 副里每个阵营的 `heroPortrait` **只有 1 种取值**），所以它跟着 faction 走。
