## 二、`trigger == 15` 判据怎么落的

1. **枚举**：`AbilityTrigger.cs`（原版签名桩）`PlayedThirdCardInTurn = 15`；`AbilityEffect.cs` `doDamage = 10` / `drawCard = 0`。
2. **谁带这个能力**：`RawCardScript__HasPlayedThirdCardInTurn.c:29-31` 逐元素读 `RawCardScript+0x290 cardAbilities[].trigger == 0xf` ⇒ **逐卡、不是「进攻卡这一类通配」**。移植到 `OffensiveCardData.ThirdCardAbilities()`（判据只此一处）。
3. **触发时机**：`RawCardScript__OnCardPlayedWithTarget.c:105-112`：
   `if (thisCard != cardPlayed && BattleManager.CardsPlayedInTurn(bm) == 3) TriggerAbilities(this, 0xf, …)`。
   ⇒ **只认 `== 3`**（第 4、5 张不再触发）；`this` = **进攻卡那条 RawCardScript**；
   `thisCard != cardPlayed` 这一闸在我们这里**恒成立**（进攻卡不在手牌里，永远不会是「刚打出的那张」）。
   ⚠️ 顺带订正 S11 第二节 §4 第②句「在**刚打出的那张牌**上触发」—— 与它自己第 54-56 行引的方法体相反（方法体是 `TriggerAbilities(this, …)` + `thisCard != cardPlayed`）。
4. **计数**：`BattleManager__CardsPlayedInTurn.c:16-25` 读 `+0x3D0`；写点 = `_ResolvePlayCardFromHand_d__447__MoveNext.c:1390-1406` 的 `op_Increment`；清点 = `_NextTurn_d__395__MoveNext.c:231` 写 0。
   我们落成 `ctx.CardsPlayedInTurn`：`BeginTurn` 清 0；`PlayCard`（单位支）/ `PlayTactic`（战术支）各 `++` 一次（两条路互斥，**不会重记**；打不出去的牌一张都不记）。
5. **位置**：`OnCardPlayedWithTarget` 里 0xf 排在 600（灵魂石）/605（信仰）/690（传送）之后、20（WhileInPlay）之前 ⇒ 我们放在两宿主函数末尾（单位支 = 虫群合并后；战术支 = 巧技后），都在 `CheckCodex` / `CheckWinner` **之前**（伤害可能打死督军）。
