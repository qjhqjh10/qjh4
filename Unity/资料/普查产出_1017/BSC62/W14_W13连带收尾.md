## 二、那三条断言「改完还测不测得动」（会不会变成同义反复）

- **不是同义反复**：期望值是**硬写字面量** `0.985f` / `1.51f` / `0f`，不是从 `CardView` 读回去的；
  谁把 `CardView` 的 `1.97f` / `3.02f` / `0f` 改掉（含退回批① 那套），这三条就会红。
- **第三条偏弱**：`HitCenterDy` 是 `const float = 0f`，`Mathf.Abs(CardView.HitCenterDy) < 1e-5f`
  在编译期就被折成恒真；它能挡「const 被改回 `−0.02`」（重编译后变红），
  **挡不住**「`HitRect()` 里另加一个偏置而不改 const」。这一条是**编译期常量锚**，不是行为断言。
- **覆盖面**：三条只断**常态档**三个常量，**不断 in-hand 档**（`HitHalfHInHand = 1.5251` /
  `HitCenterDyInHand = −0.0151`）⇒ W13 新加的 in-hand 档目前**没有数锚**（详见 §六·1）。
- 档位切换 / `Contains` 行为由别处断言覆盖（A964/E2 的 `0.45` + `0.35` 半高点、展示窗的
  「命中区跟卡转」判别式），这三条不承担那件事。
