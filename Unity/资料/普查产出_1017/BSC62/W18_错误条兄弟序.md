## 一、改了什么（搜串定位，行号 = 改后现读）

### 1) 模板 —— `BuildTemplateChildren`（现 `:517-529`）
· 搜串：`MakeSlicedPiece(t.root, tex, "Background"`
· 改前：`MakeSlicedPiece(...)` → `if (piece != null) { t.barRoot = …; t.barParts = …; }`（**从不登记 z**）
· 改后：`if (piece != null) {` 里第一句补
  `HudCanvas.Add(piece.Rect, ZBar);`
· 为什么 `ZBar`：`ZBar = 0f`、`ZText = -0.01f`（`:329`），而 `HudCanvas.Group.Add` 是
  **z 降序插兄弟序**（`HudCanvas.cs:394-403`：`while (_zs[i] >= z) i++` → `SetSiblingIndex(i)`）⇒
  z 大的排在前面 = **先绘 = 压在底下**。`0 > −0.01` ⇒ 底条在下、文字在上，即「Background 先、Text 后」。

### 2) 每条真消息 —— `BuildBar` 的 uGUI 支（现 `:706-721`）
· 搜串：`MakeSlicedPiece(it.root, tex, "Background", wPx, hPx`
· 改前：建完直接 `it.barRoot = piece.gameObject;`（**从不登记 z**）
· 改后：
  ```
  HudCanvas.Add(piece.Rect, ZBar);
  piece.Rect.SetSiblingIndex(0);
  ```
· 为什么第 2 句（**如实交代：这一句是处方之外我加的，理由如下，可回退**）：
  `Group` 的 z 账**只 Insert、从不 Remove**（`HudCanvas.cs:389-403`，没有清理口），
  而底条**每次 `ShowItem` 都重建**（`BuildBar` 开头 `Destroy`/`DestroyImmediate`，`:683-688`），
  play 档 `Destroy` 又是**帧末才生效**。逐次推演：第 1 次 Show 下标 0（对）、第 2 次 1（仍在文字前）、
  **第 3 次起下标被陈旧的 `z=0` 记录顶到末尾**（`SetSiblingIndex` 越界夹到 last）⇒ 新底条落到文字**之上**。
  `it.root` 只有 `Background` / `ErrorMesage Text` 两颗子件（`:561-575` 建节点 + 本函数/`BuildTemplateChildren`），
  钉 0 后子件恒为 `[Background, Text]`，与判据一致。批次档走 `DestroyImmediate`、夹到 0 本来也对，
  **所以自检永远绿而真机会坏** —— 这正是要钉它的原因。
