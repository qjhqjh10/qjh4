**我们**：四颗**都画出来了但一个 `WindowButton` 都没有**（`TopBar.cs` 里那句「本批不接点击」= 静默失败）。

**改成什么**：接线**收进 `TopBar.Build`**（主菜单与卡组编辑**同一份**）—— 齿轮 `OpenSettings` / 信箱 `OpenInbox` / 头像 `OpenProfile`（三个入口都是**转调** `MainMenuRuntime` 那三个方法，⛔ 不在本件重写「哪颗钮开哪扇窗」）；**挑战那颗**挂 `onClick = ChallengeClicked`，只打一条 `Debug.Log`（把上面那条原版链讲清 + 「本地没有挑战源」）⇒ **出声，不是静默**。

**「指针层能不能在 DeckEditor 场景里用」——先核了，结论：能用**（三处实证）：
· `ShellRuntime.Awake` 有 `DontDestroyOnLoad`、`Build()` 里 `WindowsManager.EnsureHost(transform)`（`Shell/ShellRuntime.cs:101,216`）⇒ **指针层与窗口管理器建在壳下、跨场景活着**；进 `DeckEditor` 走的是 `CollectionWindow.GoEdit` → `LoadScene("DeckEditor")`（单场景，壳留下）⇒ **真机上本来就有一台**。
· `LayoutSpace.Cam` 在本场景有值（`DeckRuntime.Build` 里 `LayoutSpace.Apply(_cam)`，`:651`）⇒ `PointerLayer.Update` 的换算不会空转。
· 自检那条路：`PointerLayer.Instance` 惰性现建；断言段里已显式 `WindowsManager.EnsureHost()`（照 `MainMenuScene.cs:1337` 先例）。
· ⛔ 单独 Play `DeckEditor.unity`（**没有壳**）时指针层不存在 ⇒ 那四颗**点不动** ⇒ `BuildTopBar` 里补了**一条出声**的日志（`WindowsManager.Instance == null` 时打一次）。**没有再动 `WindowsManager` / 别的场景**。

**顺手补的一道闸（B25① 自己引入的问题，一并治了）**：那几扇窗开出来之后，本类**自己那套区域派发**会（a）**点击穿透**（一次右键能从窗缝里往卡组加牌）、（b）**ESC 被两家同时吃**（`PointerLayer.KeyCancel` 关窗 —— 这一跳对；同一帧本类还会 `SaveAndSay()` = **存盘离场**，而原版那一刻 ESC 只打给最上面那扇窗）。⇒ 新增 `DeckRuntime.OtherWindowUp()` + 两道闸（`HandlePointer` / `HandleEscape`），并记 `_winShieldPrev`（`PointerLayer` 的 `Update` 排在**本类之前**，按 ESC 那一帧窗已经被关掉了）。⛔ **闸只加在生产输入路**：`UiClickPx` / `EscPressed()` 两个**自检直调口**一个字没改（同 `UiPressDone` 那条「故意不做模态拦截」的先例）—— 既有那一片断言语义零变化。

## ② `A868①` · 主菜单收口到 `TopBar`

**原版 / 我们**：顶栏只有一条（原版卡组编辑是**盖在主菜单上的窗**，顶栏属于下面那层）；我们**两份实现**（`MainMenuRuntime` 四个 `private` 方法 + `TopBar` 一份逐参复刻）。

**收口时查出并修掉的**两处**真实偏离**（都在 `TopBar` 那一份里，D13/D14 抄漏的）：
1. 🔴 **资源计数器次序整个反了**（**可见**）：旧 `TopBar` 按 `DefaultCurrencies`（`{gold, crystals, blackStones}`）建 ⇒ 画成 **gold·crystals·blackStones**；原版是**建表序** ⇒ **crystals·blackStones·gold**。判据两条独立：`CounterSpecs` 的 `List.Add` 序（`GeneralMenuController__Initialize.c:51-146`）＋ **用户实拍** `资料/原版参照图/用户实拍_1017/卡组编辑界面参考.png` 右上角（左→右 = 水晶 41360 · 黑石 356 · 金币 1500）。这一条**肉眼可见**（并排一比就是反的）。
2. **信箱红点**：旧 `TopBar` 写死 `BadgeAlpha(false)`（恒 alpha 0）；主菜单那份是 `BadgeAlpha(DailyData.InboxHasBadge)`。⇒ 已统一。⚠️ **如实说**：`DailyData.InboxCount` 现在**恒 0**（`DailyData.cs:802`），所以这一处**今天画面零差异**，是「把两份合成一份」；等哪天有消息源，旧写法才会现形。
   （另：旧 `TopBar` 还漏了 `EnergyInResourcesBar` 那条条件支与「原版图标没查到」那句出声 —— 一并补齐，否则 `MainMenuScene` 的 energy 夹具会红。）

**改法**：`MainMenuRuntime.Build()` 里一句 `_topBar = TopBar.Build(_root, NoteMissingArt);`，删掉四个 `private` 方法 + 那一片几何常量 + `LoadAvatar`/`BuildTopAvatar`/`_topAvatar`；**保留两个 public 口**（`RefreshTopAvatarIfChanged()` / `TopAvatar`，签名语义不变，转调 `TopBar`）。**数据仍住主菜单**（判据与自检拨盘在那边）：`CounterSpecs` / `EnergySpec` / `CurrencyNames` 改 `public`（只给 `TopBar` 读，⛔ 没有第二张表）。
**一处必要的 API 改动**：`OpenInbox` / `OpenSettings` / `OpenProfile` 改 **`static`**（顶栏接线要能被「没有主菜单实例」的卡组编辑场景调到；三个体内只有一句 `OpenByRef` ⇒ **零行为变化**）⇒ `Editor/MainMenuScene.cs` 里 7 处 `menu.OpenXxx()` 改成 `MainMenuRuntime.OpenXxx()`（C# 不允许用实例访问静态成员）。⛔ 左竖导航那三条仍是实例方法（它们要 `SelectNav`）。
