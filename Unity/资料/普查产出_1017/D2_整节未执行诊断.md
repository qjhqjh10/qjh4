# D2 · 为什么整节断言没执行 + RE 没跑完

## 一、结论

**「run2 有一整节没执行」这个前提不成立 —— `battle2.log` 不是今天的第二次运行，是 2026-10-15 的旧日志。**
`battle2.log` 头 `Date: 2026-10-15T01:23:58Z`（mtime `2026-10-15 09:42:34`），栈帧写 `Check` 在 `BattleScene.cs:400`、
`Run` 在 `:1743/1752/1776`；而今天源码 `Check` 在 `:415`、该节在 `:1941`、`Run` 从 `:337` 起 —— 位置整体漂移 15~200 行。
那一节（21 颗字族 + 块 6 三根滑杆）是 **2026-10-16 / 2026-10-17** 才加的（源码注释自带日期），旧 build 里根本没有。
`RuleEngineTest` 也不是崩了 —— **它此刻仍在跑**（日志持续增长，见 §五）。

⚠️ 今天 `_tmp_view` 里**只有一次** `BattleScene.Run`：`battle.log`（`Date: 2026-10-17T02:38:39Z`，10:38–10:58，`3124 通过 / 12 失败`），
它把两族断言都跑了（`（第 N 颗）` 42 条 · `块 6：第` 21 条）。

## 二、`Check` 的实现与计数口径

- 源码：`Editor/BattleScene.cs:415-419`（`Run()` 内的**局部函数**）：
  ```csharp
  void Check(bool ok, string msg)
  { if (ok) { pass++; Debug.Log(...); } else { fail++; Debug.LogError(...); } }
  ```
  - **不会 throw**（无 fail-fast）；**没有「section 开关」概念**，不存在「不活跃就静默丢弃」。
  - 计数 = 闭包里的两个 `int`（`:413` `int pass = 0, fail = 0;`），收尾在 `:24218`（`=== 结束：{pass} 通过 / {fail} 失败 ===`）与 `:24224`（`=== 合计：… ===`）。
- ⚠️ **真正会「静默少跑」的形状不在 `Check` 里，在它的调用点**：`CheckHudBox`（`:509` 附近）
  在前提红之后 `if (lb == null || tmp == null) return;` ⇒ 每颗后面 9 条不跑（**但前提那条已红**，不是全绿）；
  AspectFiller 段也是 `if (topQ != null && botQ != null)` 同形（`:15282` 附近）。
  这正是源码注释里「EW8 迁画布后 16 个调用点全部前提红、144 条不跑」记的那个坑 —— 今天已修成前提红 + 条件块。

## 三、`try/catch` 与跳转路径（谁把这节「跳过去」了）

- `Run()` 跨 `:337` → `:24230` 左右，**整个方法体没有外层 `try/catch`**。
  全文件的 `catch` 只有 5 处：`:4782` `:4806`（局部小实验）· `:10308` `:10638`（删临时文件的 `try{}catch{}`）· `:22672`（产物写盘），**都不裹住 `:1941`**。
- `:337`–`:1941` 之间**没有** `goto`，`return;` 只在注释里出现（`:487/:507` 是 `CheckHudBox` 内部的提前返回）。
- 该节所在结构：`:1884` 起 `{ var drv = FindObjectOfType<BattleDriver>();` → `:1891` `if (drv == null) Check(false, …); else { … }`。
  `:1941` 就在这个 `else` 的**直线路径**上，外面没有别的 `if`。
- 结论：若真跑到这里，**要么每条都打日志、要么抛异常整段中断**；run1 日志里 `Exception` 出现 **0 次**，
  旧日志里也没有 —— 旧日志是**没有这段代码**，不是跳过了它。

## 四、`HudCanvasReady` 现读

- 定义：`Battle/BattleDriver.cs:16639` —— `public bool HudCanvasReady { get { return HudCanvas.RootRect != null; } }`（**只读属性，无赋值点**）。
- 来源：`Battle/HudCanvas.cs:60` `public static RectTransform RootRect { get; private set; }`；
  **全文件只有一处写入** = `Ensure(Camera)` 的 `:118`；**没有任何 `RootRect = null` 复位**（`grep` 已核）。
  ⇒ 进程内一旦建过就恒真；只有「一次都没调过 `Ensure()`」时才 false。
- run1 实测为 true（`:1941` 那条 `✓`，`battle.log:12702`）。
- ⚠️ 假如它是 false，`Check(false, …)` 会打一条 `✗`；旧日志**一条都没有**（而这节任何一条都 0 条）⇒ 再次证明**那一行在旧 build 里不存在**。
