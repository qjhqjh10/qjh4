## 〇、四句话结论（先看这个）

1. **效果是纯数据驱动的**：卡 SO（`RawCardScript`）里内联着 `List<CardAbility>`，每条 = `{trigger, 条件, List<AbilityLogic>}`；每条 `AbilityLogic` = `{chosenAbility(枚举), 参数块}`。**没有任何一张卡有自己的 C# 类**。
2. **执行是「一个 switch 分发 + 一个队列 + 一个 switch 执行」**：`AbilityLogic.PlayAbility`（2,878 行）把 `AbilityEffect` 翻译成 75 个 `BattleManager.Add*` 之一；`Add*` 只往 `List<BattleAction>` 里塞一条；`BattleManager.Update` 每帧从队首取一条，交给 `BattleManager.ResolveAction`（**9,300 行**、83 个 `Resolve*`）真正改状态。
3. **触发是一条反向的链**：`BattleManagerSupport.Broadcast*`（43 个）把「发生了什么」扇出给场上每张卡 → `CardScript.ReactTo*/Trigger*`（15 + 27 个）→ `RawCardScript.OnTrigger(trigger, …)` → `TriggerAbilities` → `CardAbility.CanTriggerAbility`（条件三连：trigger 相等 → 上下文/资源 → 三条 criteria）→ `TriggerAbility` → `AbilityLogic.PlayAbility`。
4. **阵营不分家**：整套 1,894 个类里**没有一个按阵营分的规则类**（只有 `RemnantAeldari` / `RemnantNecrons` / `TauCannonAnimationStopper` 这类纯表现件）。阵营只是 `CardArmy` 枚举字段，落在**数据**（卡 SO 的 `cardArmy`、`TargetCriteria.chosenArmy+armyFilter`）和**几处按阵营索引的资产表**（环境效果卡、主动技能图标、TraitEffect 动画、开场独白）上。

## 三、关键词表（`DefinedTrait`，134 个值）

> **关键词在代码里分三种形态**，别一锅端：
> **(A) 纯数据** —— 卡 SO 的 `CardTraits` 只提供图标/数值，行为由**同卡的 `cardAbilities`** 表达；
> **(B) 硬编码标志位** —— `EntityScript.HasCurrentTrait(n)` / `GetCurrentTraitValue(n)` 在规则代码里被点名查询；
> **(C) 专用子类** —— `CardTrait` 的 ScriptableObject 子类重写 `IsActive`。

## 四、阵营维度：**共用一套，不分家**

### 4·1 判据

1. **`Assembly-CSharp` 的 1,891 个桩文件（含嵌套类，实际约 2,294 个类）里，按阵营命名的类只有 3 个**，且全是表现件：
   `RemnantAeldari` · `RemnantNecrons` · `TauCannonAnimationStopper`。
   （`grep -i "Ultramarine|Goff|Saim|Sautekh|Leviathan|Sororit|Genesteal|Astra|DarkAngel|EmperorsChild|SpaceWol"` 在类名上 **0 命中**）
2. **`CardArmy` 只出现在 25 个 `.c` 里**，其中规则侧的只有一处：`FilterMethods.MeetsArmyCriteria(cardArmy, filterArmy, ArmyFilterOptions)`——就是**目标筛选**，语义是 `OnlyChosenArmy / ExcludeChosenArmy / OnlyChosenArmyOrNeutral`（`FilterMethods__MeetsArmyCriteria.c:20-40`）。其余全是抽卡/商店/战役/头像/筛选 UI。
3. **所有效果代码（`AbilityLogic.PlayAbility` / `BattleManager.ResolveAction` / `CardScript.*`）里，没有任何一处读 `cardArmy` 决定「怎么结算」**。

### 4·2 阵营的差异**只**落在下面这几层

| 层 | 差异载体 | 出处 |
|---|---|---|
| **数据（最主要）** | 卡 SO 的 `cardArmy` 字段 + 该卡自己的 `cardAbilities` / `CardTraits` / `activeAbility` | `PlayerItem.Army`（桩 `PlayerItem.cs:35`） |
| **筛选（规则）** | `TargetCriteria{chosenArmy, armyFilter}` + `FilterMethods.MeetsArmyCriteria` | `TargetCriteria.cs` · `FilterMethods.cs` |
| **条件（规则）** | `UnitConditions.bloodAngelsOrUltramarines(290)` / `isWarlordOrVehicle(275)` / `isBattlesuitOrVehicle(276)` / `isInfrantryOrBeast(277)` —— **按「种族/兵种组合」写死的少数条件**，不是按阵营分支 | `UnitConditions.cs` |
| **环境效果卡（规则+资产）** | `EnviromentalEffectCardsSO`：每个 `CardArmy` 一组 `{emptyOffensive, offensiveCards[], defensiveCards[], defaultVFX}`，按 `forgeLevel` 取 | `EnviromentalEffectCardsSO.cs:6-95` · `BattleManager.ApplyEnvEffect` |

| **动画** | `TraitEffect.overrideByArmies[]`（同一 trait 不同阵营换动画） | `TraitEffect.cs:9-20` |

## 五、命名与注释线索

### 5·1 反编译件的命名规律（已实测）

| 现象 | 实际 | 例 |
|---|---|---|
| `类__方法.c` | 正常方法 | `AbilityLogic__PlayAbility.c` |
| `类._状态机_d__NNN__MoveNext.c` | **协程体**（这才是真正的方法体） | `BattleManager._ResolveAttack_d__438__MoveNext.c` |
| `类___方法_b__23_0.c` | 闭包 / lambda | `AI.__c___SelectBestAction_b__8_0.c` |
| 首行函数名与内容不一致 | **ICF 同体折叠**（多个一行方法共享同一地址），**不是导出事故** | `CardTrait__IsActive.c` 首行是 `BaseAddressableLibrary__ValidateLibraryLoad` |
| 首行与内容都错位 | **符号错配**（无法查地址） | 见 `资料/全量反编译_入口与用法.md` §四·4 |
| `List<T>__get_Item` | 所有 `List<T>.get_Item` 都被 IL2CPP 折成同一个泛型实例名 | 见 §一·2 的警告 |

### 5·2 哪些名字**能直接读出语义**（不用读方法体）

| 前缀 | 含义 | 所在类 |
|---|---|---|
| `Add*` | 往 action 队列里塞一条 | `BattleManager`（75 个） |
| `Resolve*` | 出队执行（或启动执行协程） | `BattleManager`（83 个） |
| `Broadcast*` | 事件扇出给全场 | `BattleManagerSupport`（43 个） |
| `ReactTo*` | 某张卡对某事件的反入口 | `CardScript`（15 个） |
| `Trigger*`（`CardScript` 上的） | 主动把某个 trigger 灌给自己/别人 | `CardScript`（27 个） |
| `Get*Targets*` / `IsValid*Target` | 选目标 | `AbilityLogic` / `BattleManager` / `FilterMethods` |

### 5·3 哪些**必须读方法体**

| 问题 | 只能读方法体 |
|---|---|
| 某个 `AbilityEffect` 到底改什么 | `AbilityLogic.PlayAbility` 的对应分支 |

### 5·4 注释

反编译件里**几乎没有 C# 注释**，但**有两类可读文本**：
1. `[Tooltip("…")]` 的字符串被**保留在签名桩**里（`AbilityLogic.cs` 的 `[Tooltip("DoDamage")]` 等）—— **这是最可靠的字段语义来源**；
2. `[Header("If true, only one ability triggered, chosen randomly…")]` 这类 Header 也在桩里；
3. 方法体里的 `CustomDebug.Log("…")` 字面量在反编译里是 `DAT_0x184XXXXXX`，要用 `stringliteral.json` 换算（`资料/全量反编译_入口与用法.md` §二·⑤）。
