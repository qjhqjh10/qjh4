## 3. 关键词 / 词条：数据驱动还是硬编码？

### 3.1 三层结构（关键结论）

| 层 | 在哪 | 驱动方式 |
|---|---|---|
| **认得出**（字符串 → 规范名 + 数值） | `KeywordTable.Prefixes` `CardDef.cs:4196`，`Normalize` `:4431`，`Parse` `:4490`，`HasNumber` `:4568` | **数据驱动**：卡表 `keywords` 列是文本，靠前缀表规范化 |
| **效果正文**（`Rally:` 后面的字） | `EffectText.Parse` `EffectText.cs:1144`；收集点 `CardDef.CollectTriggerOps :761` | **数据驱动**：卡面英文经解析器变成 `EffectOp` |
| **机制本身**（这个关键词“做什么”） | 散在 `RuleCore` / `EffectResolver` 的**固定调用点**（`FireTriggerAt`、`ApplyDamage`、`IsValidTarget`…） | **硬编码**：每个关键词一条代码路径，没有通用“关键词执行器” |

`KeywordTable.Implemented`（`CardDef.cs:3880` 起，现 70 词）是“**机制真的有代码在读它**”的白名单，**不是**“认得出”的名单；不在里面的词会被 `UnimplementedKeywords`（`RuleCore.cs:8966`）报出来、卡面打 `*`。

## 4. 阵营维度

### 4.1 数据上有什么

- `CardDef.Faction`（`CardDef.cs:88`）：**英文枚举名字符串**，与卡背表 `CardbackTable.army` 逐字同名。
- 现读 13 个值（1127 张）：`Ultramarines 134 / Goff 119 / SaimHann 92 / BlackLegion 84 / DarkAngels 83 / Genestealers 83 / TauEmpire 81 / Sautekh 79 / Leviathan 79 / AstraMilitarum 78 / Sororitas 77 / EmperorsChildren 70 / SpaceWolves 68`。
- 其它阵营相关字段：`Subtype`（兵种）、`Rarity`、`Initiative`、`InventoryOptions`、`GoesSecondId`、`Keywords`。

### 4.2 代码里有没有“按阵营分支”

**几乎没有。** 全盘 grep `Faction ==` / `Faction !=`（含 `CardPresentation`）：

- 规则引擎**唯一**的语义性使用 = **造牌候选池筛选**：`CreatePool.Resolve(pool, payload, faction)`（`CreatePool.cs:90`；`EffectText.OpHasMechanism` 把卡自己的 `Faction` 传进去，`EffectText.cs:1807`）。它筛的是“这个阵营有哪些兵种卡”，不是“这个阵营有什么专属规则”。
- `CardDatabase` 的 `Faction ==` 只用于**按阵营取卡池**（`CardDatabase.cs:360`）；`DeckBuilder.cs:48` 只用于“卡组必须同阵营”；其余命中全在自检 / 编辑器（挑测试卡）。
- `BattleDriver` 的阵营分支只在**表现**（卡背、颜色、HUD 资源图标）：`FactionColor :98`、`ShowsQuestPoints :162`（`cmp 0x6e` = DarkAngels）等。
- **没有** `switch (faction)` 式的“阵营专属效果代码”。

### 4.3 那“阵营专属机制”在哪

它们都落在**共用机制 + 数据**上：

| 阵营资源 | 代码落点（共用） | 触发方式 |
|---|---|---|
| 信仰（Sororitas 等） | `PlayerState.Faith`（PlayerState.cs:90）；`EffectResolver.DoFactionResource :7274`；`UseFaithAbility :7799` | 卡面 `Gain N Faith` / `N [Faith]:` 阈值；**阈值不扣**（`ResolveOneCore :721-725`） |
| 灵魂石（Aeldari） | `PlayerState.SpiritStones :91`；`DoFactionResource`；`CostKindOf` 认 `spirit` | 卡面 / 残骸收集 `CollectWaystone :8140` |
| 任务点（DarkAngels） | `PlayerState.QuestPoints :106`；`QuestPointThreshold`（`EffectResolver.cs:7342`，步长 `QuestPointStep = 3` :7333） | 卡面 `Gain N Quest Points`；HUD 只在 DarkAngels 显示（`ShowsQuestPoints :162`） |
| 誓约（BlackLegion） | `CardDef.OathOps :1553` + `UseOathAbility :7701` | 卡面 `Oath N:` 付费前缀 |
| Dark Pact | `GivePayload` 的 `Variant` / `DarkPactFx`（`EffectResolver.cs:7100`） | 卡面载荷 |

⇒ **结论：阵营是“数据维度”，不是“代码分支维度”**。要做某阵营专属行为，优先走“关键词/正文数据 + 共用机制”；只有 `ShowsQuestPoints` 这类**表现判据**是硬编码了 DarkAngels 的机器码值。

## 5. 风险点：同一个规则写两处 / 静默失败 / 断言覆盖不到

> 下面每条都引用代码里**自己写下的**判据或坑；标「待核」的是本次没能完全证实的。

1. **两套效果文法并存（真实且刻意）**
   `EffectSpec`（自定 26 张，`EffectSpec.cs:86`）与 `EffectText`（原版卡面，`EffectText.cs:1144`）是两条路；`CardDef` 构造函数只对 `!FromOriginalPool` 用 `EffectSpec`（`CardDef.cs:364-382`），运行期 `_effects` 基本无人读（A1618 注释 `CardDef.cs:331-363` 明确说“只有自检与自定卡卡面读它”）。
   ⇒ **风险**：看到 `_effects` 为空不等于卡没效果；判“会不会跑”必须走 `EffectText.WillRunOps :1872` + `OpHasMechanism :1781`。
   另：`RuleCore.cs:22` 文件头仍写着“效果文字走 `EffectSpec` 那个封闭文法，**不解析原版 desc**”——**这是过期表述**（今天的 `PlayTactic` 明确 `EffectText.Parse(card.Desc)`，`EffectResolver.cs:1551`），下个会话容易读错层。

2. **`TriggerOps` vs `TriggerText` 可能对不上（文件自己点名的）**
   `CardDef.cs:743-748`：op 是“真的会结算”，text 是“卡面/日志要显示的字”；正文收下来但 op 解析失败时一边有一边没有。**别拿 `TriggerText` 判“会不会生效”**。

3. **`UnparsedEffects` vs `WillRunOps`：两张报表问不同问题**
   `CardDef.cs:32-46` 与 `RuleCore.cs:8988`：`UnparsedEffects` 只对自定 26 张有意义，对原版卡恒空。拿它统计“原版卡正文跑不了”会得到 **0 假绿**。

4. **`instead` 条件族在能力层仍是已知未做缺陷**
   `EffectResolver.cs:82-97` 明写：能力层只配**无条件** `instead`；条件成立时“那两条**都**结算”（同一张卡实测吃 `3 + 6`）。这是**真实差异、还没修**，不是文档噪声。

5. **付费前缀“一组只收一次”依赖解析层标记**
   `EffectText.StampPaidCost :1629` → `EffectOp.CostShared` → `ChargePaidGroups :517` / `Prepaid :476`。`EffectResolver.cs:635-680` 有长注释记录“逐 op 收 ⇒ 扣两倍”的历史。**新增付费形态时必须按批次结构，不能按执行次序推**。
