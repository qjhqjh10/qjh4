## 结论（是什么）

**`A1644` 那块暗色渐变的身份 = `Shell/MainMenuRuntime.cs` 建的【外壳左竖导航面板】的子件
`Navigation Panel/Panel Shadow`（图 `Smooth_background_lateral`）。它不是收藏窗的件。**

- 它是一条 **1929 × 70** 的半透明黑条：rect **`(-762.5, 511.7) → (1166.2, 581.7)`**，
  tint = `(0, 0, 0, 0.46667)`，渲染队列 = `MainMenuRuntime.QPanel` = **2910**。
- 贴图 `Smooth_background_lateral`（32×32）**本身就是一条竖向 alpha 斜坡**（alpha 0 → 255，
  逐行实测 `0/1/8/27/60/105/159/214/255`）⇒ 画出来就是「自上而下渐暗、底边是硬边」的样子。
- **原版里它被收藏窗挡在下面**：原版 `Safe area Only Horizontal`(RT1540) 的 `m_Children` 里
  `Navigation Panel`(1103) 排在 `2 - Canvas Holder Above upper bar`(1109) / `3 - PopUp Holder`(1121)
  **之前**（`Shell/ShellRuntime.cs:224-228` 逐项实读）⇒ 窗在兄弟序上更靠后 ⇒ 画在导航面板之上
  ⇒ 用户实拍同一位置看不到这条影。
- **我们把它顶上来了**：`Shell/CollectionWindow.cs:3044` 为了躲开 `CardView` 的默认队列 3000，
  把 `Content Area/Background` 一刀压到 **2000** —— 而 2000 **低于**外壳导航面板的 2910
  ⇒ 于是这条影画在了收藏窗底图**之上**，在卡组区那片空白里露出来。

一句话：**不是「多画了一个件」，是「窗底图被压到了外壳梯子之下」的层序缺陷。**

## 修法（改哪一处）

**唯一改动点：`Shell/CollectionWindow.cs:3044`**

```csharp
foreach (var q in bgNode.GetComponentsInChildren<ImageQuad>(true)) q.SetRenderQueue(2000);
```
→ 换成一个落在 **`(2930, 3000)`** 的值（建议 **2940**）：

- 必须 **> 2910**（`MainMenuRuntime.QPanel`，导航面板 + `Panel Shadow`）——这是 A1644 的根因；
- 建议 **> 2930**（`MainMenuRuntime.QOverlay`，主菜单那条梯子的顶）——否则主菜单其它件也可能透出来；
- 必须 **< 3000**（`CardView` 各层，压到 3000 以上会把卡池盖住 —— 也就是 2000 当初存在的理由）。

同时改 `:3035-3044` 那段注释：把「压到 2000」的理由补上一句
「**下限 = 外壳梯子顶（`MainMenuRuntime.QOverlay` 2930）**，2000 会低于导航面板的 `Panel Shadow`(2910)」。

**断言（回归判据，二选一）**

- 在 `CollectionWindow` 里给底图队列起一个常量（如 `public const int QWindowBg = 2940;`），
  `Editor/CollectionScene.cs:5711` 那条 `< 3000` 之外再补一条 **`bq.RenderQueue > 2910`**
  （⛔ 不要直接从 `MainMenuRuntime` 读 —— 那是 `private const`；可把它改成 `public`，或这条用字面量 + 出处注释）。
- ⚠️ `CollectionScene` **不建外壳**（`Editor/CollectionScene.cs:782-833` 只有 `WindowsManager.EnsureHost()`
  + `CollectionWindow.Create`）⇒ 这条只能写成「常量对常量」；要端到端验，得在 `ShellScene` 里断言。

⛔ **不要动** `Panel Shadow` 本身（它在主菜单里是原版的、逐位正确）；
⛔ **不要动其它三扇子菜单窗**（它们的底图仍是 3005，本来就对）。

## 顺手发现

1. 🔴 **`Editor/CollectionScene.cs:1257-1278` 那颗 `[A1644]` 探针看不到本件，跑了也白跑**（两条独立的理由）：
   - 它只遍历 `win.PageRoot(0)`；而本件的主人是**外壳的 `Navigation Panel`**，`CollectionScene.Build()`
     根本不建外壳（`Editor/CollectionScene.cs:782-833`）⇒ 那棵子树里没有它。
   - 即使能遍历到，筛条件 `x1∈[330,333] ∧ x2∈[1164,1167] ∧ y2∈[581,583]` 也会把它排除
     —— 它的真 `x1 = −762.5`（屏外），只有 `x2/y2` 命中。
   ⇒ 建议：**删掉这颗探针**（结论已定），或搬进 `ShellScene`、按 `Find("Navigation Panel/Panel Shadow")` 直取。
2. **这是「把底图压到 2000」留下的直接副作用，且只有收藏窗有病**：全仓 `SetRenderQueue(2000)` 只此一处
   （`grep` 复核），其它子菜单窗底图是 3005 ⇒ 都在 2910 之上。建议在 `MainMenuSubmenuWindow.QPanel`
   附近补一句常量契约：「**窗底图 ∈ (2930, 3000)**」——否则下一个把底图往下压的人会再踩一次。
3. `_tmp_view/w_01.png` 是 **N5 修格子原点之前**的渲染（第一格左沿 342.75，不是修后的 400.45），
   引用它的坐标时注意别和现行版本混着比。
