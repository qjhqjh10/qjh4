## 一、共同机理（11 条 menu 红里有 10 条是这两支）

**机理 A —— `CheckAt` 比的是 `localPosition`，用在【孙件】上必然差「父件的设计位置」。**
`CheckAt`（`Editor/MainMenuScene.cs:150-159`）拿 `t.localPosition` 比 `MainMenuRuntime.Center(矩形)`；而建窗写进去的是 `Local(parent,…) = RectCenter − PosInDesignSpace(parent)`（`Shell/MenuDraw.cs:30-31`）。
⇒ 孙件的差**恰好等于 `|PosInDesignSpace(父)|`**。设计空间口径 = **108 px / 世界单位、原点在屏幕中心 (960,540)**（`Core/LayoutSpace.cs` 的 `FromPixel/ToPixel`）。
两条红的数就是它，**逐位吻合**：`|Center(0,550,40.87,150.42)| = 7.5602`（红②③）· `|Center(60,649.68,244.89,902.69)| = 5.6121`（红④）⇒ **这两颗节点其实在正确位置**。
🟢 **同一节自己写着这条规矩**：`:2972` 注释「`CheckAt` 比的是 `localPosition`，只对**直接子件**成立」—— 作者只把它用在下面四条字栏，**上面三颗标题栏子件漏了**。同族遭遇战窗用的是 `CheckAtWorld`（`:4531`）✓。
⚠️ 为什么没早发现：`:2962` 的 `Warlord Darkening`（也是孙件、也用 `CheckAt`）**是绿的** —— 它的父件 `Warlod Image` 矩形中心**正好是 (960,540)**（`PosInDesignSpace = (0,0)`）⇒ **巧合**。

**机理 B —— `MenuDraw.AlignLeft` 会【挪节点】，所以不能拿它比「框心」。**
`Label.AlignLeftOn`（`Battle/Label.cs:1096-1105`）＝ `localPosition.x = 框左沿 − 父件x + WorldW*0.5` ⇒ 节点中心 = 框左沿 + **字宽**/2；断言比的是框心 = 框左沿 + **框宽**/2 ⇒ 差 **(框宽 − 字宽)/2**，**恒不为 0**（原版那四条 TMP 的 `对齐=Left`（`menu_dump` 实读），我们是靠挪节点仿出来的）。
🔴 **工程里已经写着这条**：`Editor/SettingsScene.cs:214-216` 的 `CheckLeftS` doc ——「`AlignLeft` 会把 Label 的节点挪走 ⇒ **不能**拿它的位置去比矩形中心，要比**左边缘**」；菜单侧同类做法见 `:4519`（`Window Title` 用 `TmpRenderedRect` 量**真渲染左缘**，容差 1.5px）。
🟢 自检：`TutorialSubTitle` = `The Basics` @fs54.30 ⇒ 字宽 ≈ 294px、框 504.10 ⇒ (504.10−294.26)/2 = **104.92** ✓ 与实测同值（差值是**水平**的、量级也对）。

**机理 C —— 名单格与右列【同名】，`FindChild` 深搜取第一个 + 兄弟序会变。**
`Tutorial Army Select Button` 格里的三行字**就叫** `TutorialTitle` / `TutorialSubTitle` / `TutorialComplete`（原版 prefab 实读 —— **同名是原版的**，不是我们起的）；`FindChild` = `GetComponentsInChildren<Transform>(true)` 取**第一个**（`Editor/MainMenuScene.cs:9604-9610`）。
建窗次序 `BuildInfo` 在前、`BuildArmySelector` 在后（`Shell/TutorialModePopup.cs:305-310`，与 prefab 子件序一致）⇒ 刚开门第一个命中是**右列**的；`SelectStage` 拆掉 `TutorialInfo` 重建 ⇒ 新节点**追加到窗根末尾** ⇒ 之后第一个命中变成**第 1 格**的。

**机理 D —— 通道被**别的节**先写脏了。**
`PracticeModePopup.StartBotBattle`（`Shell/PracticeModePopup.cs:1717` `SetPendingPlayMode`）在**同一个宿主**里跑过（日志 `menu.log:9590`「[Practice] 开战」）⇒ `_pendingPlayMode` 被填；批处理下**没人消费**（只由真开局那条链 `TakePendingPlayMode` 消费）⇒ 教程节进来时通道不空。
