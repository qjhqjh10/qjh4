### ① Sentinel / `skipCardDraw` 禁抽 —— 已落地

**原版证据**
- `BattleManager__TurnStartCardDraw.c:14-56`：① 教程 `dontDrawCard` ⇒ return；
  ② `PlayerHand__IsThereSentinel(hand)` 非假 ⇒ `PlaySentinelAnims` + return；
  ③ `PlayerHand__CanDrawTurnStartCard(hand, 1)` 非假才抽 `drawCardsPerTurn` 张、加时再 +1。
- `PlayerHand__IsThereSentinel.c:33-50`：扫**那一方场上单位**的 `HasCurrentTrait(0x29e)`；
  `0x29e = 670 = DefinedTrait.sentinel`（`dump.cs:45790`）。
- `PlayerHand__CanDrawTurnStartCard.c:58-99`：先再判一次 sentinel，再扫手牌效果
  `cardEffect.buffType(+0x38) == 7`（`BuffType.skipCardDraw = 7`，`dump.cs:45441`），
  取**最后一条**；命中 ⇒ **返回 0（不抽）**；`limitedUses(+0x28)` 为真时
  `numberOfUses(+0x2c)--`，扣到 <1 ⇒ `RemoveHandEffectAt`（`HandEffect` 字段表 `dump.cs:119795-119802`）。
- **次序**：②③ 都在抽牌之前；①② 命中时 ③ 的计数**不消耗**（原版那两条路先 return）。

**改法（`RuleCore.cs`）**
- 新增常量 `RuleCore.Sentinel = "sentinel"` / `RuleCore.SkipCardDrawVerb = "skipcarddraw"`
  （常量为什么在本文件：同 `Noncombatant` / `Unstunnable` 先例，`KeywordTable` 在 `CardDef.cs`）。
- `HasSentinelInPlay(ctx, seat)`：扫当前行动方 9 格 `u.Has(Sentinel)`。
- `ConsumeSkipCardDrawHandEffect(ctx, seat)`：扫 `PlayerState.HandEffectRecords` **与**
  每份手牌 `CardInstance.HandEffects`（真对局里两者是同一对象），取最后一条
  `Op.Verb == SkipCardDrawVerb`；有次数则扣 1，<1 时从记录表 + 所有牌身摘掉。
- `BeginTurn` 抽牌段改为三闸：
  `dontDraw（教程）→ sentinel → handSkip（仅前两闸都没命中时才查/消耗）`，
  命中任一 ⇒ 不抽 + 日志写明是哪一道闸。

**测试**：`TestBeginTurn` 内 ①（哨兵在场不抽）＋ 对照（同一位置换成无哨兵的单位 ⇒ 抽 1 张）；
②（`skipCardDraw` 拦抽 + 次数 2→1 + 对手照常抽 + 第二次 1→0 且整条摘 + 摘后恢复抽牌）。

### ② 狂暴（berzerk）强制攻击 —— 引擎侧已落地（入口接线留账）

**原版证据**
- `BattleManager__GetPendingBerzerkUnit.c:33-118`：候选 = 场上、`IsUnit`（cardType `0/10`）、
  `isRemnant(+0x65)==0`、`IsInPlay`；结果 = `HasCurrentTrait(0x168)` ∧ `CanAttackCard`。
  `0x168 = 360 = DefinedTrait.berzerk`（`dump.cs:45755`）。
- `BattleManager__CanAttackCard.c:34-56`：**只判「这个单位现在能不能攻击」**（不含目标合法性）。
- `BattleManager__EndTurnClick.c:78-125`：`IsPlayerTurn()` ∧ 待攻击列表非空 ∧
  **列表第一个单位**有 `GetAvailableAttackTargets` 非空 ⇒ 提示 + **拒绝结束回合**；
  `param_2 == 1`（时钟强制）绕过。
- `BattleManager__ResolveEndTurn.c:33-137`：回合真要结束时，对每个待攻击单位
  `AI.SelectBestAttackAction` → `AddBerzerkAttack` 排队，再重排 EndTurn —— **不管怎么结束都必须打**。
- `BattleManager__AddBerzerkAttack.c:25-40`：出手打法读卡上的 `+0x120`（当前攻击型）。
- `BattleManager__GetAvailableAttackTargets.c:44` 传 `attType = 0`，由
  `BattleManager__IsValidAttackTarget.c:54-57` 换成 `*(attacker+0x120)` ⇒ **只按当前攻击型枚举目标**。

**改法（`RuleCore.cs`）**
- `RuleCore.Berzerk = "berzerk"`。
- `PendingBerzerkUnits(ctx, seat)`：`Card.IsUnit` + 非残骸 + `IsAlive` + `Has(Berzerk)` +
  `CanActNow`（近战/远程任一可打）。
- `HasPendingBerzerkAttack(ctx)`：照 EndTurnClick —— 只看**待攻击列表第一个**在**当前攻击型**下
  有没有合法目标（`HasAnyValidAttackTarget`，判据用 `IsValidTarget`）。
- `ResolveBerzerkAttacks(ctx)`：在 `EndTurn` **最前面**（限时增益到期之前）执行；
  每个单位按**当前攻击型**选目标并 `DeclareAttackByCurrentType`（= `AddBerzerkAttack` 读 `+0x120`）；
  没有目标 ⇒ 出声跳过。**AI 座位跳过**：原版那一段在 `if (IsPlayerTurn(bm))` 里，
  `ctx.IsBotSeat(me)` 是「这一方是不是电脑」的唯一判据。
- ⚠️ **目标选择的偏差（如实标着）**：原版走 `AI.SelectBestAttackAction`（`Data/SimpleAI.cs`），
  而 **`Core/` 不许依赖 `Data/`** —— `工具/ruleprobe/ruleprobe.csproj` 只编 `Core/*.cs`
  （显式列了 `Data/CardDatabase.cs`，**没有** `SimpleAI.cs`）。实测在 Core 里写
  `SimpleAI.ScoreAction` 会让**整条 ruleprobe 构建失败**（CS0103 `SimpleAI` / `AiAction`）。
  ⇒ 用同族判据的最小版：**实际伤害 → 能斩杀 +10000 → 同伤害时督军 +0.5**。
  这是「选哪个目标」的差异，**不是「打不打」的差异**（后者才是本机制的闸门）。

**测试**：`TestBeginTurn` 内 ⑥：
- 正例：狂暴单位（5 攻）在 `EndTurn` 时**被强制出手**，目标 4 血（<5 攻，触发斩杀优先）⇒ 血量下降；
- 灭自证 A：同样配置但**没有** `berzerk` ⇒ 谓词假、`EndTurn` 后目标血量不变；
- 灭自证 B：狂暴单位已 `Exhausted` ⇒ 不算待攻击（原版 `CanAttackCard` 为假），不再强制。

**测试**：维护费 2（能量 2→0）、上限仍 2；对照 A（维护费挂在对手场上 ⇒ 不扣我方）；

### ⑤ 待死单位跳过回合开始触发 —— 已落地（等价落点）

**原版证据**：`CardScript__OnTurnStart.c:130-137`：
`RawCardScript.IsUnit(card) && CardScript.EnoughPendingDamageToDie(card)` ⇒
`LogWarning` + **整卡 return**（`OnTrigger(0x1e TurnStart)` / `0x1f` / 天赋 / Psyker 那几段一条都不跑）。
位置在该卡 OnTurnStart 的「清召唤病 → ActivateMinion → 开舱/Stealth → 晕瞎闸门」**之后**。

**改法**：`FlushPendingDeathsBeforeTurnStart(ctx)` 在逐卡循环与「正在祈祷清零」之后、
`ResolveAtTurn("turn_start")` **之前**执行：双方棋盘上 `EnoughPendingDamageToDie`（≡ 原版同一口：
`Health≤0 && Survivor≤0`）且**非督军**的单位，按**身份现查格号**走 `CleanupDeaths`。
- 为什么落成「先清掉」：我们**没有 `pendingDamage` 队列**（伤害逐段现结），正常路径到不了这个状态；
  而触发扫描在 `EffectResolver.ResolveAtTurn`（**不在白名单**）里只按 `!u.IsAlive` 过滤 ——
  若将来有新路径把待死单位留在场上，「Health>0 但累计待结算伤害已致死」那一档原版会整卡跳过、
  现有的 `!IsAlive` 挡不住。本笔把「它们不参与回合开始触发」这条不变量**显式**做在触发段之前。
- 督军不清：`EnoughPendingDamageToDie(督军)` 为真时对局已结束（`BeginTurn` 开头就 return）。

**测试**：真卡 `TAU13 DS8 Support Turret`（unit，desc = `At the start of your turn, deal 2 damage to all enemies`）
摆在 P1 场上、`Health = 0` ⇒ `BeginTurn` 后它已离场、敌方**一点伤害都没吃**；
对照（同一张牌满血在场）⇒ 触发照常结算 2 点（证明扫描面没坏，不是「怎么都不打」）。

     没有生产者 ⇒ 休眠。接线时挂一条 `Op.Verb = RuleCore.SkipCardDrawVerb` 的 `HandEffect` 即可。
