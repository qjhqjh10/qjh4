## 一、结论

**S6 已按「先凭据、后替换」的方式修掉，不是「谁连上来就顶替谁」。**

- 主机已有活连接时，新连接**不再在 `AcceptLoop` 被直接关掉**；它被收作**待替换候选**
  （独立 socket / 独立读线程 / 独立收件箱）。
- 候选必须依次出示：**`Proof` = HMAC(房间密码, 主机新发的 nonce)**，然后在**对局中 / 等重连**
  还必须出示 **`Reconnect{sessionToken}`**（这一局的钥匙）。
- 两者都对 ⇒ `PromotePendingReplacement()`：候选成为当前连接，**旧连接走有界优雅收尾**
  （`Shutdown(Send)` + ≤200 ms 排空 + `Close`）。
- 任何一步不对 / 超时（6 s） ⇒ `RejectPendingReplacement()`：关候选，**旧连接原样保留**。
- 替换/拒绝两条路径全部有 `NET/BYE-S6/*` 判别日志，**没有静默分支**。

⚠️ **安全边界的一条补强（本轮顺手堵上的真漏洞）**：`Ack` 原来无条件回传 `sessionToken`。
在「候选替换」这条新路上，那等于**任何**知道密码（或房间没设密码）的新连接都能白拿这局的钥匙、
再拿它去替换 —— 替换门槛等于零。现在：
- **对局中 / 等重连**时主机发的 `Ack` **不带钥匙**（`sessionToken = null`）；
- 候选路径的 `Ack` **永远**不带钥匙；
- 客机在**重连**这一趟**不覆盖**自己已有的 `SessionToken`（它本来就持有那把钥匙）。
⇒ 空密码房间里，第三方也**拿不到钥匙、替换不掉当前对手**。

## 二、S6 触发条件与现状（修复前）

### 2·1 触发条件

`TcpTransport.AcceptLoop`（修复前 `NetTransport.cs:308-334`，现 `:409`）：

```csharp
int stateNow = Volatile.Read(ref _state);
if ((stateNow & ConnBit) != 0)
{
    … _noteWarn.Enqueue("[Net] NET/BYE-S6/rejected …");
    try { c.Close(); } catch { }
    continue;
}
Setup(c);
```

- 条件：**新连接 accept 成功的那一刻，`_state` 的连接位仍立着**。
- 而这个连接位**只在读到失败 / EOF 时才清**（`Fail`）；TCP 半开、对面重启、拔网线这类
  **不会立刻产生 FIN/RST** 的情况，要靠**心跳 / 10 秒静默超时**才发现。
- ⇒ 「客机已经发现掉线并重连，主机还没判出旧连接死了」正是**最常见**的 S6 时序。

### 2·2 拒收之后两边的状态（修复前）

| 对象 | 状态 |
|---|---|
| **旧连接** | **完全没动**：`IsConnected` 仍真、`AcceptedCount` 不变、读线程仍在跑。若它其实已死，要等 `SilentTimeoutMs`（10 s）或一次真实写失败才被判掉线。 |
| **新连接** | 客机 `Connect()` **成功返回**（TCP 握手完成），随后**立刻收到 FIN**；主机**一个字节都没读**（新连接上若有 `bye` / 握手包，全部丢弃）。 |
| **客机会话** | 它的读线程读到 EOF ⇒ `PeerLost` ⇒ `WaitingReconnect` ⇒ 每 2 s 重试；**在主机判出旧连接死亡之前，每次重试都重复上面这一套**。 |
| **玩家可见** | 重连被拖到最长约 10 s；日志只有一行 `NET/BYE-S6/rejected`（W58-NETPROBE 已加）。 |

## 三、替换策略与身份凭据

### 3·1 判据

- 正本 `资料/联机P2P_设计与交接.md` §5·2 / §5·6：
  握手 = `helloChallenge{nonce}` → `hello{passProof=HMAC(密码,nonce)}` → `helloAck`；
  重连 = `reconnect{sessionToken}` → `resume{seed,decks,mode,arena,actions[]}`，
  **「认不出 token = 不是这局的人 ⇒ 拒绝」**。
- 实际场景：客机重连时**旧连接多半已经死了**，只是主机还没判出来。
- ⇒ 替换必须是「**先完成新连接握手，再替换旧连接**」；**不能**「先踢旧的再验新的」。

### 3·2 策略（分支判定）

| 主机状态 | 新连接 |
|---|---|
| **`InBattle`** 或 **`WaitingReconnect && _wasInBattle`**（`ReplacementArmed = true`） | 收作候选，走凭据；`Proof` + `Reconnect{sessionToken}` 都对才提升 |
| 其他（Lobby / Handshaking / Connecting / Off…） | **照旧拒收**（日志 `NET/BYE-S6/reject-not-in-battle`）。大厅/握手阶段没有「客机重连」这回事，不让陌生连接占候选位 |

### 3·3 凭据（为什么第三方踢不掉人）

1. **`Proof`**：`HMAC-SHA256(房间密码, 主机本次新发的 nonce)`；主机用**开台那一刻定格**的密码比对
   （与现有 `case Proof` **同一份规则** `CheckProofKey`）。
2. **`Reconnect{sessionToken}`**：对局中的替换必须出示这一局的钥匙，和对局内正常重连**同一道判据**。
3. **钥匙不再下发给候选**：见 §一的安全补强。
4. 候选位**只有一条** + **6 s 有界**：候选迟迟不交凭据 ⇒ 关掉，客机下一次退避重试再连
   （最坏多等约 6 s，但**旧连接一直不受影响**）。

| 符号 | 作用 |
|---|---|
| `IPendingReplacementHost`（新能力接口，`:79-125`） | 与 `IPendingFrameDropper` 同族：**能力接口 + 类型探测**。⛔ 没加进 `INetTransport`（夹具 `RecordingTransport` / `ScriptedTransport` 不实现也编得过、行为逐字不变）。成员：`ReplacementArmed` · `HasPendingReplacement` · `PendingReplacementGeneration/AgeMs/Peer` · `SendToPendingReplacement` · `PumpPendingReplacement` · `PromotePendingReplacement` · `RejectPendingReplacement` + 两个 `ForTest` 计数。 |
| `TcpTransport.AcceptLoop`（`:409-423`） | `ConnBit` 立着时：`_replacementArmed && !_pendActive` ⇒ `SetupPending(c)`；否则**保留**原拒收日志（并注明是「不允许替换」还是「候选位已占」）。 |
| `int _genSeq`（`:152`） | **代次分配器**。`Setup` 与 `SetupPending` 都从它领号，但 **`SetupPending` 不写 `_gen`** —— 写了旧连接读线程就会立刻退出（候选存在的全部前提就是旧连接可能还活着）。只有「成为当前连接」才写 `_gen`。 |
| `SetupPending`（`:602`） | 候选：独立 `GetStream` + 独立读线程；**不碰**连接位 / 计数 / `_peerLost` / `_lastError`；清掉上一条候选的残留帧。 |
| `PendingReadLoop`（`:650`） | 候选读线程（分帧与 `ReadLoop` 同源）。候选阶段帧进 `_pendInbox`；**提升之后自动转成当前读线程**（`_gen == gen` ⇒ 进 `_inbox`），不换线程。旧代闸 / `_closed` 闸 / 灌包上限（256 帧）齐全。 |
| `PendingEnded`（`:717`） | 候选自己断了：只作废候选；**提升之后**才走正常 `Fail(gen, why)`。 |
| `PromotePendingReplacement`（`:775`） | 先让旧代过期（`_gen = 候选代次`）→ 换 `_client/_stream/_readThread` → 清 `_peerLost/_closing/_closed/_lastError`、`Publish(connected:true, bumpCount:false)`（**不 +1 计数**：否则上层会把提升当成「又进来一条新连接」再发一次 Challenge）→ 丢弃旧代残留帧 → 把候选已读出的帧并入主收件箱 → 旧连接 `CloseSocketGracefullyBounded`。 |
| `RejectPendingReplacement`（`:813`） | 关候选、清候选收件箱、**旧连接不动**；按原因打 `reject-no-proof` / `reject-no-token` / `replacement-timeout` / `reject-not-in-battle` / `candidate-bye` / `reject-superseded`。 |
| `DrainPendingInbox`（`:592`） | 候选队列按「每条候选/作废时清空」处理 —— 否则上一条候选的迟到 `Reconnect` 会被下一条候选当成自己的凭据。 |
| `Close()` / `Setup()` | 收工/换当前连接时作废候选；`Close` 另清候选收件箱。`ClosePeer` **不碰候选**（它可能正是重连的新连接）。 |

## 五、测试与灭自证

新增 `Editor/NetSelfTest.cs::TestReplacementWhileLiveS6(int port)`（`:2500`），并在 `Run()` 里注册。
真 socket 回环（两个 `NetSession` + 裸 `TcpTransport` 当重连方），三条路径：

| # | 场景 | 断言 |
|---|---|---|
| ① | 旧连接仍在 ⇒ 新连接带**正确 proof + 正确 sessionToken** | `S6⑤` 候选收到 `Challenge` → `S6⑧` proof 通过收到 `ack ok` → `S6⑨` 光有 proof **还没提升** → `S6⑩` 钥匙对 ⇒ 收到 `resume` → `S6⑪` 提升计数 = 1 → `S6⑫/⑬` 主机 `InBattle`、连接活着 → `S6⑭` **旧连接被关掉（旧客机读到 FIN）** → `S6⑮` 有 `NET/BYE-S6/replaced` 日志 |
| ② | 旧连接仍在 ⇒ 新连接**密码错** | `S6⑱` 拒候选（计数 +1）→ `S6⑲` **当前连接原样保留** → `S6⑳` 会话状态没被打断 → `S6㉑` 有 `NET/BYE-S6/reject-no-proof` 日志 |
| ③ | 旧连接仍在 ⇒ proof 对、**`sessionToken` 错** | `S6㉔` 拒候选 → `S6㉕` 当前连接 / 状态都没动 → `S6㉖` 有 `NET/BYE-S6/reject-no-token` 日志 |

🧨 **灭自证（改回旧行为必红）**：
把 `AcceptLoop` 改回「`ConnBit` 立着就 `c.Close()`」⇒ 候选**永远收不到 `Challenge`** ⇒
**S6⑤ 红**。⚠️ 后面那些「拒收」断言在旧行为下**照样绿**（旧行为本来就是拒收）——
所以鉴别力必须落在 **S6⑤/⑩** 这条「能收候选、能提升」上，判据已按此写死。

⚠️ 测试里**故意不 `Pump` 那台旧客机**（只等它的读线程把 `PeerLost` 置上）：
一 `Pump` 它就会在同一帧「发现掉线 → 立刻退避重连」，自己又变成一条候选、占住候选位，
把 ②/③ 挤成假红。注释已写进测试。

⚠️ **本轮不许跑 `*.Run`**（任务红线）⇒ 这三条测试**只做了类型检查，没有执行**。
⚠️ 「旧连接走的是优雅收尾」在测试里断的是**旧客机读到 FIN**；200 ms 排空本身在测试里不可观测
（`CloseSocketGracefullyBounded` 内部，未加 `ForTest` 计数）。

## 六、没查清的部分 / 已知限制

1. **新测试未真跑**（红线：不跑 `*.Run`、不真连）。逻辑与编译已过；**时序断言需要下一次允许跑自检时验证**。
2. **「候选」这条路的真机时延没有实测**：`ReplacementHandshakeTimeoutMs = 6000` 是自拟边界；
   真机上从「客机重连」到「主机提升 + 发 resume」的耗时**没量过**。
3. **中途插入的陌生连接会占候选位最长 6 s**：期间真正重连的那条会走旧拒收路径（有 `NET/BYE-S6/rejected`
   日志）。这是「候选位只有一条」的取舍；没有实现多候选排队（v1 1v1，暂不需要）。
4. **对局中一个「知道密码但不是重连者」的新客户端**会先收到 `ack ok`（因为协议要求先 ack 才能出
   `reconnect`），它自己会短暂以为进了 Lobby；主机**不会**提升它，6 s 后作废候选，**旧对手不受影响**。
   要让它在协议层就知道「这不是给你留的位」，需要新增消息/字段 ⇒ 属于协议变更，没做。
5. **空密码房间**：`Proof` 等于空串（局域网自用口径，既有行为）。替换的门槛因此**只剩 `sessionToken`**；
   本轮已保证候选在对局中**拿不到**钥匙（`Ack` 不下发）⇒ 第三方仍替换不掉。但这是「凭据变弱」而不是
   「凭据不存在」，如实记下。
6. **没跑静态场景扫描器/没有真机日志**：`AcceptLoop` 的新分支与 `PendingReadLoop` 的线程交错
   没有经过运行时验证（本轮白名单允许的只有类型检查）。
