## 结论

1. **D8 已修**：`RuleCore.EmitHit` 现在**先给被打者跑一次它自己的监听**（与棋盘那一跳**同一个函数** `FireBoardWhenListener`），**再**广播其余监听者；`EffectResolver.BroadcastWhen` 的快照用 `ReferenceEquals(u, preCalled)` **排除被打者**。两步缺一不可（只预调 = 双响；只排除 = 被打者漏掉）。
2. **额外补了一道闸（验证时发现，必须留）**：预调**绕过了** `BroadcastWhen` 入口的 `EffectChain` 上限检查 ⇒ 不补闸的话「监听器再造成伤害」这条环在到达上限后仍会经预调无限递归（离线探针**实测爆栈**）。`EmitHit` 里现在同判一次 `ctx.EffectChain < BattleContext.MaxEffectChain`。
3. **A1567 注释错误引用已就地订正**（3 处）：`TriggerAbilities` **从不调用** `GetAbilitiesForTrigger`；判据改为 `RawCardScript.TriggerAbilities` @ `0x18094B420` 的**共享尾块 `0x18094B822`**，核心证据 = **循环出口 `0x18094B573 jge 0x18094B822`**。
4. 顺手注释订正两项（**只改文字**）：`CardDef` 的 Unstable/Backlash 次序、`RuleEngineTest` 的 3 处「负数 Hit = 治疗」。
5. 新增断言 `TestW58DamagedBroadcastOrderD8`（已注册进 `Step(...)`），既有 `TestW58DeathOrderD4/D5`、`TestW58SlayInterleave` **期望值一字未改**。

### 2. `Core/RuleCore.cs` · `EmitHit`（`:7036-7067`）

```csharp
int owner = EmitUnit(ctx, EvtKind.Hit, u, amount);
if (u == null || u.Card == null) return;

// ① 预调：被打者自己的监听先跑一次（与棋盘那一跳同一个函数）
if (!ctx.IsOver && ctx.EffectChain < BattleContext.MaxEffectChain)
{
    using (EventSlotsScope.TargetAndCard(ctx, null, u.Card))
        FireBoardWhenListener(ctx, u, WhenEventKind.Damaged, owner, u.Card, u, null, null, -1);
}

// ② 广播其余监听者（快照里 ReferenceEquals 排除被打者）
BroadcastWhen(ctx, WhenEventKind.Damaged, owner, u.Card, u, preCalled: u);
```

- 事件槽与棋盘那一跳同形（`target = null`、`card = u.Card`）。
- `owner` 来自 `EmitUnit`（`FindUnit`）——**督军也在棋盘上**（`PlayerState` 注释：`Board[BoardSpec.WarlordSlot]` 上永远是督军），所以督军的 `damaged` 监听同样走预调。
- **`EffectChain` 闸**：与 `BroadcastWhen` 入口判法一字不差。⚠️ 这是本批验证中发现的**必要项**，见下文「测试与灭自证」的 flip D。
