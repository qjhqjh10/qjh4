## 〇、结论

1. **缺陷坐实并已修**：`TraitFrames.DisplayTrigger` 原来把**所有**触发类框都写进 `_trigger` 去重表
   ⇒ 纯 `Trigger(3)` 的框（`oath`、`slay` …）也变成「这个关键词一辈子只演第一次」。
   原版回调**只对 `TriggerType == 6 (TriggerOnPlay)` 写表** ⇒ 已按此改。
2. **去重语义按 trait 粒度照原版**（表的键是 **trait id**，不是某条 effect）：
   · 纯 `Trigger(3)`（`oath` / `slay`）⇒ **每次触发都演、不写表**；
   · 含 `TriggerOnPlay(6)` 的 trait（`bloodthirst`）⇒ 第 1 次演完写表，之后不再演。
3. `oath` / `bloodthirst` 两条既有 `TriggerCount` 断言已按判据改写（**不是**为了让测试变绿）：
   `oath` 改判「演 3 次 / 表里 0 张」，`bloodthirst` 改判「第 1 次演+写表 1 张，第 2 次不再演」。
4. 新增断言用 `TriggerPlayCount`（真正播出去的触发框累计次数）观测「演了几次」——`TriggerCount` 只数
   「进了去重表的」，纯 `Trigger(3)` 永远是 0，观测不到。
5. 顺带发现两笔**未改**（如实记账，见 §六）：`bloodthirst` 的绑定来路不是 trait effect GUID 链；
   原版 `playIfWarlord` 门我们还没实现。

## 二、改法（符号）

**文件：`Unity/MyGame/Assets/CardPresentation/Core/TraitFrames.cs`**

1. 新增判据表 + 查询口（**判据只此一处**）：

```csharp
static readonly HashSet<string> TriggerOnPlayTraits = new HashSet<string> { KeywordTable.BloodThirst };

public static bool DedupesTrigger(string trait)
{
    var t = Norm(trait);
    return t.Length != 0 && TriggerOnPlayTraits.Contains(t);
}
```

   - 入表条件 = 该 trait 的 `_traitEffects` 里**存在 `TriggerType == 6`**（数据见 §1.3）。
   - 注释写清了「表的键是 trait id、写表只发生在 6 的回调、之后连 3 那条也被守卫挡住」，
     并要求**以后新增 `TriggerFrames` 行时必须同时判有没有 6**。

2. `DisplayTrigger` 改为：

```csharp
bool dedupes = DedupesTrigger(key);
if (dedupes && _trigger.ContainsKey(key)) return false;   // 原版守卫（只有写表类才可能命中）
…
if (dedupes) _trigger[key] = p;      // 🔴 只有 TriggerType==6 才写表
_triggerPlays++;
return true;
```

   - 非 6：每次 `Play` 都执行、**不写表**（框由 `WarpforgeEffectPlayer` 自己的寿命销毁，
     与原版「不在字典、靠 `AnimFXController.destroyTime` 自毁」一致）。
   - 6：第一次写表，之后 `ContainsKey` 挡住（返回 false）。

3. 断言观测口：`public int TriggerPlayCount`（累计真正播出的触发框数；`TriggerCount` 语义不变）。

4. 文件头 / 绑定表的**就地订正**（铁律 5）：
   - 文件头补 `2026-10-20` 订正：原实现没照「只有 6 写表」的判据做，附反编译逐行出处；
   - `TraitParticles` / `TraitFrames` 绑定表里 `bloodthirst` 那行的「判据 = `BloodThirstTraitTrigger`」
     **降级为「按名字硬绑」**：`BloodThirst.asset` 的三条 effect **没有任何一条引用它**（见 §六·1）；
   - `DisplayTrigger` 的 doc 补记原版还有 `playIfWarlord` 门、我们未实现（见 §六·2）。

**文件：`Unity/MyGame/Assets/CardPresentation/Editor/BattleScene.cs`**（只改「状态框」那一节的 ④⑤⑥）

- ④ `oath`：先把 `Trigger(3)` 分类钉住，再**连续触发 3 次**，每次断言 `TriggerPlayCount == oathPlays0 + n`；
  最后断言 `TriggerCount == 0`（演了 3 次但一次都没进表）。
- ⑤ `flying`（无绑定）：断言 `TriggerCount == 0` **且 `TriggerPlayCount` 不变**（不挂、也不演）。
- ⑥ `bloodthirst`：先钉 `DedupesTrigger(...) == true`；第 1 次触发断言
  `TriggerCount == 1 && TriggerPlayCount == btPlays0 + 1`；第 2 次触发断言两者都**不变**（不再演）。

## 四、灭自证

| 把闸改成 | 哪条红 | 为什么结构上不可能同时满足 |
|---|---|---|
| **所有类型都写去重表**（改回旧实现） | ④ 第 2 次起：`TriggerPlayCount` 只 +1 不 +n；且 `TriggerCount == 0` 红 | 「oath 演 3 次」与「oath 进表」互斥 |

## 六、没查清的部分 / 顺手发现（未改）

1. 🔴 **`bloodthirst` 的绑定来路不成立（真差异，未改）**：
   `BloodThirst.asset` 的 `_traitEffects` 只有 3/6/1 三条，分别指向
   `BloodThirstGainAnim → BloodThirstEffect_Gain` / `BloodThirstIdleAnim → BloodThirstEffect_Idle` /
   `BloodThirstLoseAnim → BloodThirstEffect_Lose`；**没有任何一条引用 `BloodThirstTraitTrigger`**
   （它是 `bundle_cardanimsgeneral_assets_all` 里的 CardAnim 资产，但在这个 trait 的引用链之外；
   `Bloodthirst_Flare_Warlord` 也不在 `_traitEffects` 里）。
   ⇒ 我们绑的 `BloodThirstEffect` 实际是**按名字硬绑**。要不要改成 `BloodThirstEffect_Gain`
   （= Trigger(3) 那条的真实目标）需要裁 —— 会影响真机画面，本笔**没动**。
   ⚠️ 另：若改绑，按原版 trait 粒度去重的结论**不变**（bloodthirst 仍含 6）。
2. 🔴 **`playIfWarlord` 门未实现（真差异，未改）**：`DisplayTriggerAnim.c:62-68` ——
   卡是督军且该 `TraitEffect.playIfWarlord == 0` 时**整条不播**；`Oath.asset` 那条正好是 0。
   我们的 `DisplayTrigger` 没有这道门（需要「这张卡是不是督军」的输入，属跨面改动）。
   本笔的断言用的是 `Tide Minion`（非督军）⇒ 不受影响。
3. **写表时机**：原版在**动画播完的回调**里写；我们仍是**同步**写（改动前也是同步）。
   差异 = 第一次动画还没播完时又来一次触发，原版会再播、我们会挡住。未改（既有简化）。
4. **一条 trait 多个 3/6 effect**：原版逐条播（各播各的），我们每个 trait 只绑一个 prefab。
   既有抽象限制，本笔未扩。
5. **`overrideByArmies`**：`TraitEffect` 可按阵营覆盖动画，我们的绑定表不含这一层（既有）。
6. **未跑 `*.Run`**（铁律 12）：上述断言只做了编译级验证，**没有执行**。
