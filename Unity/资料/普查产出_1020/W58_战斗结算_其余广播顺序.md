## 结论

1. **`Attack` / `Deploy` / `GetsHuntMark` 三族已按原版改成「先预调主体、再广播且排除主体」**；
   `Attack` 是**两个**主体（被打者 → 攻击者），`BroadcastWhen` 为此加了 `preCalled2`。
2. **`Deploy` 的预调只跑 `SelfOnly` 那一半**（原版预调 = `ThisUnitSummoned(195)`，不是
   `OtherUnitSummoned(190)`）—— 这是本批唯一不能直接套 D8 的地方：
   D8 的「主体预调」= 整份监听器；Deploy 的预调**必须**收窄，否则主体自己那句
   「When you deploy a troop, …」会被原版**排除**的 190 唤醒（静默多触发）。
3. **`triggers:mob / regiment / swarm` 不用改**：原版这三族**没有预调**，自排除在**接收方体内**
   （`CardScript__TriggerOtherCardMob.c` 的 `op_Inequality(param_2, param_1)`），
   我们的等价物 = `WhenEvents.SelfExcludesOnKeywordTrigger`（既有 `TestA1562` 已钉住）。
4. 把 D8 那三句「预调 = 判空 + `EffectChain` 闸 + 事件槽」抽成 **`PreCallBoardListener`**，
   本批 4 个预调点与 D8 的 `EmitHit` **共用同一份**（判据只一处）。`EmitHit` 只是改调它，**行为不变**。
5. 新增 3 条自检（`TestW58AttackBroadcastOrder` / `TestW58DeployBroadcastOrder` /
   `TestW58HuntMarkBroadcastOrder`），既有 D4/D5/D8/Slay 期望值**一字未改**。
6. `ruleprobe check` 绿（解析差异 0 / 哨兵 0）；`play check` 因工作树其它在飞改动仍红，
   **本批归因 = 恰好 3 张真卡**（`ASH66` / `BL30` / `TAU34`，见 §「ruleprobe 读数」）。

## 逐广播改法（预调谁 / 排除谁 + 判据）

### 1. `Attack` —— 两个预调主体

| 项 | 改前 | 改后 |
|---|---|---|
| 次序 | 棋盘格号序（P0 小格 → P0 大格 → P1 …）→ 手牌 | **被打者 → 攻击者 → 其余棋盘（格号序）→ 手牌** |
| 预调 | 无 | `PreCallBoardListener(target)` → `PreCallBoardListener(attacker)` |
| 排除 | 无 | `preCalled: attacker` + `preCalled2: target` |

**判据** = `BattleManagerSupport__BroadcastUnitAttacked.c`（接收者 = `param_1` 那张牌）：
- `:22` `CardScript.ResolveUnitAttacked(param_3, param_2, param_3, param_4)` —— 接收者 = **被打者**（`param_3`），
  实参攻击者 = `param_2`；
- `:29` `ResolveUnitAttacked(param_2, param_2, param_3, param_4)` —— 接收者 = **攻击者**；
- 棋盘循环 `:38` / `:44` 两条 `op_Inequality` 把**这两个都排除**（`:44` 机器码里比的是 `target`；
  `.c` 把第二实参丢了）。
- 调用点 `BattleManager._ResolveAttack_d__438__MoveNext.c:988-990`：`param_2 = *(param_1+0x28)`（攻击方），
  `param_3 = *(param_1+0x130)`（在 `:110` 由 `+0x30` 写入 = 目标）⇒ 上表「谁是谁」已核。

代码：`RuleCore.cs:4869-4879`（`DeclareAttack`，替换原来那一句 `BroadcastWhen(Attack, …)`）。
- 两个预调用**同一个** `EventSlotsScope.TargetAndCard(ctx, target, attacker.Card)` 与同一次广播同形；
- `target == attacker` 时只预调一次（结构上不会发生，纯防御）；
- `target == null` 时 `PreCallBoardListener` 自己空转（`IsValidTarget` 已挡过，属防御）。

### 2. `Deploy` —— 预调**只跑 `SelfOnly`**

| 项 | 改前 | 改后 |
|---|---|---|
| 次序 | 主体（若自己的监听器匹配）混在棋盘序里 | **主体 `SelfOnly` 预调 → 其余棋盘（格号序）→ 手牌** |
| 预调 | 无 | `PreCallBoardListener(unit, selfOnlyOnly: true)` |
| 排除 | 无 | `preCalled: unit`（两条部署入口都加） |

**判据** = `BattleManagerSupport__BroadcastUnitSummoned.c`：
- `:21` `CardScript.ResolveUnitSummoned(param_2, param_2, param_3)` —— 接收者 = 被召唤者；
- 棋盘循环 `:34` `op_Inequality`（第二实参被 Ghidra 丢掉）跳过它。

而 `CardScript__ResolveUnitSummoned.c` 内部**两支互斥**：
- `op_Inequality(param_2, param_1)`（`:21` 附近）⇒ 发 `OnTrigger(0xbe = 190 = OtherUnitSummoned)`——
  **只有「别人被召唤」才发**；
- `op_Equality(param_2, param_1)`（`:33` 附近）⇒ 发 `OnTrigger(0xc3 = 195 = ThisUnitSummoned)` 与
  `OnTrigger(0x25d = 605 = UseFaith)`——**只有「自己被召唤」才发**。

⇒ D8 那种「整份监听器预调」在 Deploy 上是**错的**：它会把主体自己的 190 也唤醒。
我们的 `When deployed, …`（省主语）记成 `Deploy + SelfOnly`（`WhenEvent.cs:847-850`），正是 195 那一支；
`When you deploy a troop, …` 是 190。实现 = `FireBoardWhenListener(..., selfOnlyOnly: true)`：
只按 `SelfOnly` 那几条取 op（`EffectResolver.cs:7020-7051`）。

⚠️ **Rally / 信仰（195 / 605）不在这里重复发**：它们在两条入口上**已经**按各自判据发过
（`RuleCore.cs:2910` 的 Rally；`ResolveFaithAbility` 两处）。本批只补「`When deployed` 自指监听」，
**不新增 195/605 的第二条路**（原有相对次序未动，属另一笔账）。

代码：`RuleCore.cs:2851-2853`（`PlayCard` 入口）· `:3514-3516`（`DeployFree` 入口）。

### 3. `GetsHuntMark`

| 项 | 改前 | 改后 |
|---|---|---|
| 次序 | 棋盘格号序（被标记者也在其中） | **被标记者 → 其余棋盘（格号序）→ 手牌** |
| 预调 | 无 | `PreCallBoardListener(markedUnit)`（整份监听器，与循环同一个函数） |
| 排除 | 无 | `preCalled: u` |

**判据** = `BattleManagerSupport__BroadcastUnitObtainedHuntMark.c`：
- `:21` `CardScript.ReactToUnitHuntMarked(param_2, param_2, 0)` —— 接收者 = 被标记者；
- 棋盘循环 `:29` `op_Inequality`（第二实参被丢）＋ **最后一跳手牌 `:64 op_Inequality(uVar3, param_2, 0)`**
  （**显式**，第二实参就是被标记者）。
- `CardScript__ReactToUnitHuntMarked.c:7` ⇒ `OnTrigger(0x208 = 520 = UnitReceivesHuntMark)`，
  预调与循环是**同一个入口**（所以这里用整份监听器，不收窄）。

代码：`EffectResolver.cs:7531-7549`（`BroadcastKeywordEvent`，只对 `kind == GetsHuntMark` 生效）。

### 4. `triggers:mob / regiment / swarm` —— **不改**

逐行读了三份 `.c`：**没有预调**（见下表），自排除发生在**接收方体内**：

| 广播器 | 棋盘跳 | 接收方体内 |
|---|---|---|
| `BroadcastUnitMob.c:29` | `op_Inequality(uVar4)`（1 条） | `TriggerOtherCardMob.c:18` = `op_Inequality(param_2, param_1)` ⇒ **接收者 == 触发源就跳过** |
| `BroadcastUnitRegiment.c` | 同形 | `TriggerOtherCardRegiment.c:18` 同形 |
| `BroadcastUnitSwarm.c` | `TriggeredSwarm(lVar4, param_2, param_3)` + `op_Inequality` | 接收方体内同形（`A1399` 机器码计数：棋盘跳 1 + 接收方 1） |

我们的等价物 = `WhenEvents.SelfExcludesOnKeywordTrigger`（`WhenEvent.cs:1460-1464` / `:1663-1670`），
`KeywordTriggerIncludesSelf` 只有 `ferocity / duty / synapse` ⇒ **mob / regiment / swarm 自排除**。
既有 `TestA1562` 的 ②-bis（触发者自己 0 次、同族旁观者 1 次）与 ④（`SelfOnly` 那一条自己要响）
已经钉住这一格。**若在广播层再加一次排除，只会让两处判据重复**（不改变可观测行为）。

⚠️ `Ferocity / Duty / Synapse` **不**自排除（原版三跳都没有 `op_Inequality`），维持现状 —— 未被本批波及。

3. **`GetsStun`**：`BroadcastUnitStunned.c` 是「对目标调用」的形状（没有棋盘循环），
   我们是否需要排除**没有判据** ⇒ 未改。

   我们的 `ResolveFaithAbility` 仍排在 `BroadcastWhen(Deploy)` **之后**（既有次序，本批未动）。
   这是**已经在的**次序差，不属于「预调 + 排除」这一笔，如实记着。
