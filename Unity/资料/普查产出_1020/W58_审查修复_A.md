## P2-4 改法（`Battle/ReplayStore.cs`）

两处：

1. **文件头新增「版本」一节**（放在「留多少局」之后、`using` 之前），内容：
   - 为什么不兼容：录像只存「起始条件 + 动作流」⇒ 同一串动作在新引擎里会算出另一种局面；
     旧闸只在**终局 `StateHash`** 不一致时出声，那时整局已经演完了。
   - **版本 3 的改动清单（6 条）**：① 加时触发点（能量 → 全局回合号）；② 死亡/触发次序（D4 `Backlash → Unstable → Die`、
     D5、`FlushDeaths` 逐死者交错）；③ 手牌上限时机（先判上限、再 Add，满了送**刚进手牌的那张**）；④ `Gain N Energy`
     （只结算一次、改 `MaxEnergy`、不随目标数翻倍）；⑤ 受伤/攻击/部署/猎杀标记广播的「预调主体 + 排除」；
     ⑥ 伏击揭示（删掉「回合开始自动揭示」，只在原版 7 个 `SetAmbush(false)` 调用点翻面）。
   - **旧版怎么处理（现有逻辑，一字未改，如实写进文件）**：`Load` 比 `new ReplayRecord().version`，
     不等 ⇒ `Debug.LogWarning("[Replay] 版本 N 不认识（本代码只认 M）⇒ 不播：<完整路径>")` + `return null`；
     `BattleDriver.PlayReplay(fileName)` 拿到 null ⇒ `return false`；列表那几处 `continue`。
     ⇒ **不硬解、不会演成另一局**；警告带完整路径与两头版本号（不是静默失败）。
   - 补一句：`JsonUtility` 读不到 `version` 键时给 `0` ⇒ 同样走拒绝路。
2. **字段**：`public int version = 3;`；字段 doc 从「将来**改结构**就 +1」改成「改结构**或改结算语义**就 +1」，
   并把 2 → 3 的语义原因指向文件头那一节（⛔ 不抄第二份）。

**位置（现读）**：`EffectResolver.cs:7865-7884`（能量在目标循环**之前**单独结算并打「最大能量 +N」）→

而不是「空过」。**本条需改 `EffectResolver.cs`（不在白名单）⇒ 未改。**
