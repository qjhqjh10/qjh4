## 结论（3 句内）

1. 原版在**战斗初始化完成**时（`BattleManager.OnInitializationComplete` → `StartBattleSequence` 第 0 步）先 `LoadingMenu.LoadingFade(false, null)`（**进战斗黑场 1.25 s 淡出**），再对 `BattleManager.cameraAnim`（`+0x190`，13 场各一个挂在 **`Cinemachine Vcam`** 上的 `Animation`）调**无参 `Animation.Play()`** —— **没有字符串参数**，播的是 `Animation.clip`（= 该组件唯一那条 `<场名> Camera Intro` 传统 clip，**2.5 s 从偏移位姿飞回相机本位**，`WrapMode.Once`）。
2. 13 个 clip **全部是 legacy 曲线格式**（`m_Legacy=true` · `m_MuscleClipSize=0` · 无 streamed 数据）⇒ **不属于**「muscle/streamed 拷进工程 = 空壳」那一类；位置/欧拉（或四元数）/光晕**逐场的数据本地全有**，可直接重建，不存在「拿不到」。
3. 落地路线（本报告建议）：**不导入 `.anim`、不从 bundle 取原件**，新增 `工具/gen_camera_intro_clips.py` 出一张曲线表 → 新增 `CardPresentation.CameraIntro` 在运行时用 `AnimationClip.SetCurve` + `SampleAnimation` 复现（逐帧可推 ⇒ 批处理可断言）；接线点 = `BattleDriver.Begin` 的战场加载处 + `BattleDriver.AdvanceTimeline`。

### 1·4 光晕那条 float 曲线（`flareIntensityMultiplier`）

- 组件 `CameraLensFlareIntenistyAnimation`（`dump.cs:50068-50086`）：`flareIntensityMultiplier`（`[SerializeField][Range(0,1)]`，`+0x20`）·
  `lensFlare`（`LensFlareComponentSRP`，`+0x28`）。

- `CameraLensFlareIntenistyAnimation__LateUpdate.c` 逐句：
  ```
  lensFlare.intensity = flareIntensityMultiplier * lensFlare.intensity;   // ← 每帧【相乘】
  if (lensFlare.intensity != 0) lensFlare.enabled = true; else lensFlare.enabled = false;
  ```

  ⇒ **不是 lerp**：2.5 s 前乘数 = 1（不变），2.5 s→曲线终点乘数 1→0 ⇒ 强度**乘法式衰减到 0**，然后把 flare **永久 disable**（整局）。

- **6 个场真的挂了 flare**：arena1(`4018`) · arena2(`4213`) · aeldari(`3980`) · astra(`4181`) · leviathan(`4181`) · tauviorla(`4611`)
  —— 与我们 `Assets/Resources/ArenaPrefabs/*.prefab` 里 `LensFlareComponentSRP` 的分布**逐场一致**（同 6 场各 1 个，其余 7 场 0 个）。

## 三、落地步骤（文件 + 符号 + 做法）

> 口径：**按符号定位，别照抄行号**（`普查产出_1019/W57_战斗线_T09迁移计划.md` §1·3）。
> 分类判定：13 条 clip 是 **legacy 曲线格式**，因此「muscle/streamed = 空壳」那条坑**不适用**；
> 但本工程更顺的路不是落 `.anim`，而是**把曲线表当数据、运行时重建 clip** —— 理由见下。

### 3·1 为什么走「运行时重建」而不是导入 `.anim` / 从 bundle 取

| 路线 | 可行性 | 取舍 |
|---|---|---|
| **从原版 scene bundle 运行时取 `LoadAsset<AnimationClip>`** | 可行但**要额外重打一个小包**（scene bundle 太大，不可能整包进 `StreamingAssets`） | ✗ 多一段打包链，收益只有「原件」名义 |
| **把 13 条落成 `.anim` 工程资产** | **可行**（legacy 不是 muscle，曲线数据在 JSON 里齐全） | △ 要写 YAML + `.meta` + 处理 `m_FloatCurves` 的 `script` GUID；资产导入是编辑器侧一次性动作 |
| ✅ **生成曲线表 JSON + 运行时 `AnimationClip.SetCurve`** | 可行（`SetCurve`/`SampleAnimation`/`legacy` 都是运行时 API，`dump.cs:1074461,1074485,1074511`） | ✅ 符合本仓「数据表 + 运行时」惯例（`card_anim_order` / `battle_bgm` / `shake_presets`）· **批处理可手动推帧、可逐帧断言** · 无 GUID / 脚本绑定问题 |

### 3·2 第 1 步：生成曲线表

**新增** `d:/4/Unity/工具/gen_camera_intro_clips.py`（只读 `d:/2/新解包资源/assets_full/`）：

1. 逐包（13 个 `bundle_scenes_scenes_battlearena*`）找 `Animation/*.json` 里 **`m_PlayAutomatically == false` 且 `m_Animation` 指向 legacy clip** 的那一份（跳过 darkangels 的空 `Animation_1661`）。
2. 读对应 `AnimationClip/AnimationClip_<m_Animation.PID>.json`，抽出：
   - `position`：`m_PositionCurves[0].curve.m_Curve` 的 `(time, value)`；
   - 旋转：有 `m_EulerCurves` 用 euler，否则用 `m_RotationCurves`（四元数）；
   - `flare`：`m_FloatCurves` 里 `attribute == "flareIntensityMultiplier"` 的 `(time, value)`（没有就不写）；
   - `length` = 全部曲线最晚的 `time`；`sampleRate`、`wrapMode`、`legacy`、`m_Name`。
3. 产出 **`d:/4/Unity/数据/游戏数据/camera_intro_clips.json`**，并**复制**到
   **`d:/4/Unity/MyGame/Assets/CardPresentation/Resources/camera_intro_clips.json`**（与 `card_anim_order.json` 同一套落法）。

建议 schema（键 = 场键，与 `ArenaByArmy.Rows[].Scene` 同源）：
```json

    "battlearena1": {
      "name": "Battle Arena 1 Camera Intro",
      "legacy": true, "sampleRate": 60, "wrapMode": "Once", "length": 3.5,
```

> 与 `new Keyframe(t, v)` 的 Unity 默认值**逐位一致** ⇒ 生成器只存 `(t, v)`。
> 多键曲线（leviathan 位置 4 键、aeldari euler 3 键）同样成立。

### 3·3 第 2 步：运行时播放器

**新增** `d:/4/Unity/MyGame/Assets/CardPresentation/Battle/CameraIntro.cs`（命名空间 `CardPresentation`）。

符号与做法（**不要照抄行号**）：

| 符号 | 做法 |
|---|---|
| `CameraIntro.ResourcePath` | `const string = "camera_intro_clips"`（`Resources.Load<TextAsset>`，与 `CardAnimOrder.ResourcePath` 同惯例） |
| `CameraIntro.Play(string arenaKey, Camera cam, GameObject flareHost)` | ① `cam==null` ⇒ 出声一次并返回 false（⛔ 不静默）② 记下 `homePos/homeRot = cam.transform.localPosition/localRotation` ③ 按表建 clip（见下）④ 挂/取 `CameraLensFlareIntensity`（若该场有 flare）⑤ `_t=0; _len=d.length; Sample(0); _playing=true` |
| `CameraIntro.Tick(float dt)` | `_t += dt` → `Sample(Mathf.Min(_t, _len))` → `_t >= _len` 时 `_playing=false`（**终帧仍是本位**，不需要回弹） |
| `CameraIntro.Sample(float t)` | `clip.SampleAnimation(cam.gameObject, t); _flare?.Apply();` |
| `CameraIntro.Stop(bool resetHome)` | `_playing=false`；`resetHome` 时写回 `homePos/homeRot`（`Begin()` 会被调多次 ⇒ 新一局先复位） |
| 测试口 | `StartForTest(key,cam,flareHost)` · `TickForTest(dt)` · `IsPlaying` · `Elapsed` · `ClipLength` · `PoseAtForTest(t) → (pos, rot)` |

**建 clip（逐条照做）：**
```csharp
var clip = new AnimationClip {
    name = d.name, legacy = true, frameRate = 60f, wrapMode = WrapMode.Once
};
// 位置：1~4 键
clip.SetCurve("", typeof(Transform), "localPosition.x", Curve(d.position, 0));
clip.SetCurve("", typeof(Transform), "localPosition.y", Curve(d.position, 1));
clip.SetCurve("", typeof(Transform), "localPosition.z", Curve(d.position, 2));
// 旋转（推荐【euler → 60 fps 四元数】，见下）：
//   · d.euler    → 用三条 AnimationCurve 在 t = i/60 上取欧拉 → Quaternion.Euler → 写 "localRotation.x/y/z/w"
//   · d.rotation → 直接写 "localRotation.x/y/z/w"
// 光晕：clippath="" + 我们自己那个组件
clip.SetCurve("", typeof(CameraLensFlareIntensity), "flareIntensityMultiplier", Curve(d.flare, -1));
```
**为什么 euler 要先采样成四元数**：原版这 13 条里已有 4 条（EC/genestealers/sororitas/spacewolves）本来就是
**151 键 @60 fps 的四元数曲线**；把剩 9 条的 euler 按同样方式采样，**表示形式与原版一致**，且绕开
「`localEulerAnglesRaw.*` 能不能被运行时 `SetCurve` 绑上」这个不确定点。采样公式不需要手写 Hermite：
原 JSON 的 `inSlope/outSlope` **全 0**、`inWeight/outWeight` **全 1/3** ⇒ 每段就是 Unity 的默认 Hermite
（等价 `smoothstep`），**直接用 `new AnimationCurve(keys).Evaluate(t)` 就是 Unity 自己的求值器**。
> 备选（更"原件"但不推荐先做）：`localEulerAnglesRaw.x/y/z` 直接绑 euler 曲线 —— 需先用 probe 证实本版本能绑上。

**`CameraLensFlareIntensity`（同文件，等价件）**：
```csharp
public float flareIntensityMultiplier = 1f;      // clip 写它
public LensFlareComponentSRP lensFlare;          // 从 arena 实例上取
public void Apply() {                            // 逐句照 LateUpdate.c
    if (lensFlare == null) return;               // 原版 Awake：null ⇒ 组件自 disable（等价于什么都不做）
    lensFlare.intensity *= flareIntensityMultiplier;
    lensFlare.enabled = lensFlare.intensity != 0f;

```
> `SampleAnimation` 能写「同 GameObject 上的自定义 MonoBehaviour 字段」（legacy 曲线按 `Type + propertyName` 绑定）；
> 若 probe 发现 `SampleAnimation` 不写它，就把 `flare` 曲线留在 JSON 里、由 `Tick` 直接算乘数（不进 clip）—— 两条路都只差 5 行。

## 五、风险

1. 🟡 **euler → 四元数的转换误差**：本方案主路是「euler 按 60 fps 采样 → `Quaternion.Euler` → 四元数曲线」，
   与原版那 4 条已采样场同构；理论误差 < 0.01°。断言用 t=0 / t=2.5 两个端点钉住（端点处两种写法完全一致）。
   若想逐帧 1:1 保留 euler 曲线本身，可改用 `localEulerAnglesRaw.x/y/z`，但**必须先 probe 证实**本版本能绑上。
2. 🔴 **相机 transform 的写权**：`CardFeel.ShakeCamera`（`CardPresentation/Core/CardFeel.cs`）也平移 `boardCam`。
   运镜只在开场、此时不会有战斗事件；但保险做法是**运镜播放期间每帧 `Sample` 覆盖**（本方案天然如此）+ 运镜期不主动起震屏。
3. 🔴 **坐标基准**：clip 的位置值是「相对原版 vcam 父节点（x=+100）」的局部值；我们能逐字用，**前提是**
   `boardCam` 的父节点在原点、本位 = `(0, 2.222075, −13.57198)`。谁要是动了 `BoardCamera` 的父级/本位，运镜会**整体偏移 100**。
   断言 §3·5⑦ 盯这个前提。
4. **光晕是乘法不是插值**：照 `LateUpdate` 做；曲线归零后 flare **整局关闭**（原版行为）—— 别「顺手」改成 lerp 或加个恢复。
5. **`SampleAnimation` 对自定义组件字段**：legacy 曲线理论上支持；若本版本不写，按 §3·3 的兜底把 flare 从 clip 移到 `Tick`。
6. **重入/多局**：`Begin()` 会被调多次（重开、录像）⇒ 必须 `Stop(resetHome:true)`；否则第二局从上一局终帧（本位）开始也不报错，但状态机的 `_playing/_t` 会残留。
7. **回放/教程**：`OnInitializationComplete` 没有按 `matchType` 分支（对比 `StartBattlePhase` 里有 `0xa0` 回放分支）⇒ **推断回放/教程也播运镜**。⛔ 未实况验证（见 §六）。
8. **黑场缓动**（顺带发现，不属 T12）：原版 `LoadingFade` 用 DOTween（未 `SetEase` ⇒ 默认 `OutQuad`），
   我们的 `BattleDriver.TickLoadingFade` 是**线性**（`p = t/1.25`）。这是 `T01` 既有的等价偏离，**不是本条引入的**，但会让「运镜 + 黑场」的叠加手感略有差异。
