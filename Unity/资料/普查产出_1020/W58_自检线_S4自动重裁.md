## 根因证据（源码）

1. **事件只由 TMP 自己发**：`ON_TEXT_CHANGED` 的发出点只有三处，全在
   `Library/PackageCache/com.unity.ugui@27635d171b1a/Runtime/TMP/TextMeshPro.cs`
   —— `:2210`（空串早退支）· `:4169`（`m_characterCount==0` 支）· `:5063`（Phase III 把网格写进 `m_mesh` 之后）。
2. **它唯一入口是 `OnPreRenderObject()`**（`:2114`），而**第一句就是静默早退**：
   ```csharp
   if (!m_isAwake || (this.IsActive() == false && m_ignoreActiveState == false)) return;   // :2119
   ```
   `ForceMeshUpdate()`（`:347-352`）只做 `m_havePropertiesChanged = true; m_ignoreActiveState = ignoreActiveState; OnPreRenderObject();`
   ⇒ **发不发完全取决于 TMP 自己的 awake / active 前提**，没有任何一条路径由我们决定。
   `GenerateTextMesh` 内部**所有**出口都会发（`:2210` / `:4169` / `:5063`），唯一的静默支就是 `:2193` 的「没字体」——
   那条会打 `Can't Generate Mesh!`，`rerun_ShellScene.log` 里 grep 为 **0 条** ⇒ 不是它。
3. **仓里自己的口径早就写着「批处理没有重排事件」**：
   `Shell/ClippedTextGuard.cs:40`「⚠️ 批处理里没有帧循环 ⇒ **没有重排事件**：自检别拿它自证（要验就在 `Play` 里点一次，
   或直调 `MenuDraw.ClipTextNow`）」；`Shell/MenuDraw.cs:1363-1364`（`ArmTextGuard`）同一句。
   ⇒ **10-18 那条绿不是范式**（TMP 当时恰好满足前提）；10-20 两趟（`shell.log` / `rerun_ShellScene.log`）都红。
4. **不是「生产少了发事件」**：这条事件从来不由我们发，补发会变成「TMP 发一次 + 我们再发一次」
   （幂等无害但会掩盖 TMP 的真实状态），且改动落在共用件上，**判据不支持**。
   **也不是「测试调错重排路径」**：`ForceMeshUpdate()` 正是 TMP 会发事件的那一条（`SetText` / `SetAutoFitBox` /
   `ForceRelayout` 内部调的都是它）——**没有任何一条我们自己的 API 能保证 TMP 发**。
   ⇒ 红的是「**拿 TMP 的内部前提当我们自己的契约**」。

## 遗留疑点（建议主对话另行开账，本件未动）

1. **`ClippedTextGuard` 在 TMP 的 `FastAction.Call` 回调里 `Remove` 自己**（`ClippedTextGuard.cs:108` →
   `:99-104`）。`FastAction<A>.Call` 是 `node.Value(a); node = node.Next;`
   （`FastAction.cs:72-80`），而 `LinkedList.Remove(node)` 会把**被摘节点自己的 `Next` 置 null**
   ⇒ 只要有**一颗**残留守卫（`_lb` 已销毁却仍在订阅）在这一趟里自摘，**排在它后面的所有订阅者这一趟都收不到**，
   而且**完全静默**。今天 `staleOn=0` ⇒ **不是本次红的成因**，但它是个真隐患（尤以「未激活父链下 `Arm`、
   之后随对象一起销毁」那一族为甚 —— 未激活时 `OnDisable` 是否一定被调用，本轮**没有判据**）。
2. `GUI`：`GetComponentInChildren<T>()`（不带 `includeInactive`）到底会不会返回**未激活子件的组件**，
   本轮没有跑起来验；它是「`IsActive()==false` 到底怎么来的」这条链的唯一缺口。
