## 结论

1. **选型：新增 `EvtKind.Heal`（追加在枚举末尾），不用「`Hit` + 标志」。**
   判据 = 原版**唯一显示口**是 `CardScript.Heal` 协程（`CardScript._Heal_d__468__MoveNext.c:107-225`），
   它与 `Hit` 是**两条完全不同的表现路径**（不同的 TMP、不同的时间轴、治疗不后仰不震镜头）。
   新枚举让「命中 / 治疗 / 幸存者广播」三者在类型层面就分开，消费端不会靠正负号猜。
2. **引擎：所有「原版会进 `CardScript.Heal`」的路径已收口到一个函数 `RuleCore.HealUnit`**（`:6987`）：
   `heal` op（`EffectResolver.DoHeal`）· `heal` 能力/触发（`RuleCore.ResolveEffect`）· 回合末再生 ·
   猎杀标记回血。它按原版四道闸走：`amount > 0` · `corrupt` 不治 · `min(请求, 缺失)` · **实际量 > 0 才发事件**。
3. **表现层：卡上 `HealText` 已接上**（`BattleDriver.PlayHealFeel`，`:16562`）：`"+" + 实际量`、
   `scale 0.05 → 1.0`（0.7 s OutQuad · Yoyo ×2）→ **1.5 s 自动隐藏**；治疗**不再**走
   `HitReact` / `ShakeCameraForHit` / `PopNumber.PopHeal`。
4. **Survivor 只保留负数 `Hit` 作为「已广播」标记，表现层对负数 `Hit` 一律不显示**
   （不飘字 / 不后仰 / 不震镜头 / 不出治疗圈），符合原版 `UseSurvivor` 不进 `CardScript.Heal`。
5. **Syphon**：`BattleEvent.HealSyphon` + `GenericVfxFor` 分流已就位（Syphon ⇒ 无 `Healing_Circles`，
   但**仍有飘字/音效**）。⚠️ 我们引擎**没有 syphon 词条/机制**（卡池现读 0 张、`KeywordTable` 无此键）
   ⇒ 今天**没有生产发出点**会置这一位，只有断言覆盖（见 §5·D）。
6. **`InBattleId`：按判据不做显示层**（原版 prefab 默认关、`SetRawCardData` 再关一次、全量反编译
   **零 `SetActive(true)`** ⇒ 正式对局永远不显示；等价语义已由 `UnitState.InstanceId` 覆盖）。

### 1.2 唯一治疗口 `RuleCore.HealUnit`（`RuleCore.cs:6987`）

```csharp
static int HealUnit(BattleContext ctx, UnitState u, int amount, bool syphon)
```

逐条照原版 `CardScript._Heal…`：
- `amount <= 0` ⇒ 不治、只打日志（`:105`）；
- `u.Has("corrupt")` ⇒ 不治、只打日志（`:107-108`）；
- 实际量 = `min(MaxHealth, Health + amount) − Health`；
- **`healed > 0` 才 `ctx.Emit(Kind = EvtKind.Heal, Amount = healed, InstanceId = u.InstanceId, HealSyphon = syphon)`**；
- 目标不在场 / 已死 ⇒ `0`。

> ⚠️ `corrupt` 用的是**字面量** `"corrupt"`：`KeywordTable` 里**没有**这个键（`CardDef.cs` 不在本笔白名单），
> 卡池现读 0 张带它、引擎也没有授予点 ⇒ **今天不可达**，但闸照原版留着（见 §6·2）。
