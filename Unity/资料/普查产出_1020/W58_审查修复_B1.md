## P1-1 · 猎杀标记要求「有击杀者座位」—— 已删闸

**原版证据**（`d:/2/tools/decomp_full/CardScript__TriggerOnMinionDeath.c:33-95`，逐行读过）：
唯一的闸 = `op_Equality(观察者, 死者)` ∧ `0 < CurrentHuntMark(死者)`；**没有** killer / deathType /
actingCard 任何判断。伤害 = `BattleManager.GetHero(card.isPlayer)` = **死者主人的督军**；
治疗 = `GetHero(card.isPlayer == 0)` = **死者主人的对面**。

**改前**（`RuleCore.cs` 原 `:7906`）：

```csharp
if (u.Has("huntmark") && killer >= 0 && killer != p)
{
    int marks = u.KwValue("huntmark");
    var enemyW = ctx.Players[p].Warlord;
    var killerW = ctx.Players[killer].Warlord;   // ← 击杀者的督军
    ...
}
```

`killer` 全仓只有主伤害 / Blast / Stomp 三处传 ⇒ 战术卡 / 星镖 / 标记光 / 自伤致死一律静默不结算。

**改后**：

```csharp
int huntMarks = u.KwValue("huntmark");             // 原版闸：0 < CurrentHuntMark(死者)
if (huntMarks > 0)
{
    int marks = huntMarks;
    var ownerW = ctx.Players[p].Warlord;            // 死者主人 → 挨打
    int foe = 1 - p;                                // 死者主人的对面 → 回血
    var foeW = (foe >= 0 && foe < ctx.Players.Length) ? ctx.Players[foe].Warlord : null;
    if (ownerW != null) { ApplyDamage(ctx, ownerW, marks, "Hunt Mark"); ... }
    if (foeW != null)   { HealUnit(ctx, foeW, marks, false); ... }
    CheckWinner(ctx);
}
```

**座位极性（报告 §没查清①，本笔已核）**：原版 `isPlayer(+0x40)` 是「该卡属于哪位玩家」的 0/1 标记，
`GetHero(card.isPlayer == 0)` = **不是死者主人**的那一方。我们的座位在 P2P 下是**绝对编号**
（`CardPresentation/Net/NetBattle.cs:10`「主机 = 0 · 客机 = 1，两端跑同一套编号」）⇒ `1 - p` 双端同解、
无需翻译。已写进代码注释。

`killer` 形参保留但**只作 `PendingDeath.Killer` 诊断留痕**（`Hurt` / `CleanupDeaths` 的 doc 已订正）。

## P2-1 · 嵌套死亡抢在外层之前 —— 已按 FIFO 排队

**原版判据**：`CardScript__TriggerUnitBacklashActions.c:181` 在判死那一刻把「死者 + actingCard」
包成一条 action `BattleManager.AddAutoActionToQueue`（FIFO）；反噬 / 死亡监听器里新死的人
在**当前 action 执行中**入队 ⇒ 它的 80/81/90 一律排在外层 `_ResolveBacklash_d__451:144
BroadcastDeadUnit`（外层 Die 广播 + 外层 Slay）之后。

**改前**：`CleanupDeaths` 跑 Backlash/Unstable/Die 广播时 `_deferDeaths` 已是 0（`FlushDeaths`
开头就 release）⇒ 被反噬打死的人立刻递归走完自己的整套 `CleanupDeaths`，再回外层。

**改后**（`RuleCore.CleanupDeaths`）：

1. 死亡触发段（Backlash → Unstable → `BroadcastWhen(Die)` → `FlushDeathWatches`）整段包进
   `ctx.DeferDeaths(); try { … } finally { ctx.ReleaseDeferDeaths(); }`。
2. 新增形参 `holdNestedDeaths`：`FlushDeaths` 的逐死者循环传 `true` —— 它把新入队的
   `TakePendingDeaths()` **追加到本地 `pending` 末尾**（FIFO：[A,B] 里 A 打死 C ⇒ [A,B,C]）。
3. 直接路（`Hurt` / `DoDestroy` / `ResolveEffect` 的伤害支）且 `actingCard != null` ⇒
   `CleanupDeaths` **不抢先 flush**；调用点紧接着的 `TryCreditKill` 在记账之后 flush
   （`TryCreditKill` 新增 `flushNestedDeaths` 形参，`FlushDeaths` 传 `false`）。
4. `actingCard == null` 的直接路（反噬 / 反击 / 不稳定 / 残骸…）没有任何人会记账 ⇒
   `CleanupDeaths` 末尾当场 flush（否则再也没人处理，静默）。

`TryCreditKill` 本体也包了一层 `DeferDeaths` —— Slay / `Kills` 监听器打死的同样进队列。
无双重记账（每个 `PendingDeath` 只调一次 `TryCreditKill`）。

## 没查清的部分

1. **`TryCreditKill` 的直接路依赖「调用点紧接着调它」这一契约**：`CleanupDeaths` 在
   `actingCard != null` 的直接路上会**把嵌套死亡留给 `TryCreditKill` 的 flush**。本笔已把
   全仓 `actingCard:` 的 `Hurt` 调用点逐个数过（`EffectResolver.DoDeal/DoDamageEach/DoDestroy`、
   `RuleCore.ResolveEffect` 的伤害支都紧跟记账；攻击那几路在 `SimultaneousDamage` 批内），
   **将来新增「带 actingCard 的批外伤害」时必须同时记账**，否则嵌套死亡会滞留在
   `_pendingDeaths`（下一次批结束时才被带走，或被静默拖住）。注释已写明契约。
2. **`P2-1` 的「观察者 90 的接收者顺序」**：我们量的是「同一名观察者被叫醒的日志次序」，
   没有逐张牌复刻原版 `BroadcastDeadUnit` 的棋盘遍历顺序（本项目既有口径就是按棋盘序广播）；
   本次只修「A vs C 两条 death action 的先后」，未复核 90 内部接收者次序。
3. **`TriggerAbilities` 是同步还是入队执行**（审查报告 §没查清②）：本笔的结论不依赖它 ——
   两种读法下嵌套 action 都排在外层 `:144` 之后；实现上以「外层 Die 广播 + 记账 → 再 flush」
   复现该次序，没有逐行读 `TriggerAbilities:199-266`。
4. **哨戒 Slay 的可达面**：`TryCreditKill` 第 ⑥ 条要求凶手属于当前回合方（原版
   `ResolveDeadCard.c:256` 同口径）⇒ 常规「攻击方回合里防守方哨戒打死攻击者」**不会**记 Slay
   （原版同样不会）。测试因此把哨戒主人设成当前回合方、敌方用 `forced: true` 发起脚本攻击。
   这不是本笔造的口径，是照原版那道闸。
5. **「将死」单位的光环窗口（P2-1 的副作用，既有模型的一部分）**：P2-1 之后，嵌套死者在外层
   action 跑完之前仍留在 `_pendingDeaths` 里、也还挂在 `Board[]` 上（= 原版 `waitingToDie(5)`
   的对应态）。而 `Auras.Recompose` 只判 `u == null`（`Core/Aura.cs:617-620`），**不筛将死单位**
   ⇒ 这段窗口里它的光环仍可能被算进邻格加成。既有「批内死亡」本来就有这个窗口（主目标 0 血
   直到批末仍挂在棋盘上），本笔只是把它扩展到「死亡触发段」。**原版光环重算是否按 `IsInPlay()`
   过滤（state 5 不在四档里）本笔没核**，`Aura.cs` 也不在白名单 —— 记下来，未改。
6. **`PendingDeath.Killer` / `Hurt(killer)` 现在只是诊断留痕**：P1-1 之后全仓没有行为读它，
   保留是为了 `PendingDeath` 的可读性与将来诊断；`AddPendingDeath` 的签名未动。
