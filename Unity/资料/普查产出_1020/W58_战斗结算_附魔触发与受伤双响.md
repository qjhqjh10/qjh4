## 〇、结论（两条各一句）

1. **附魔能力不是"兜底分支"** —— 原版 `RawCardScript.TriggerAbilities` 是
   **「（满足闸时）先跑载体自己的 `cardAbilities` → 再【无条件】跑 `activeEnchantments` 里每张附魔的 `cardAbilities`」**，
   两条路**汇聚到同一个尾块**。所以 **Helspear / Ferocious Rage 给督军挂 `Slay:` 能响**，与"督军自己有 abilities"不矛盾。
   ⇒ **我们现在的「无条件追加附魔」是对的（`RuleCore.FireTriggerAt` 的 `ench` 那一跳）；⛔ 不要按 `W58_战斗结算_多词条顺序判据.md` §七·2 / D12 去改掉它。**
   报告 §A3·2「附魔 = 兜底」与 D12「原版只跑自己那份」**是误读**，根因见 §一·C。
2. **受伤广播不会双响** —— `BattleManagerSupport.BroadcastUnitDamaged` 的棋盘循环里**有自排除**：
   `UnityEngine.Object.op_Inequality(item, damagedUnit)` @ **`0x1809B78C2`**（反编译 `.c` 里那句 `op_Inequality(uVar4)` 丢掉的第二个实参，
   机器码上是 `mov rdx, r14` = `damagedUnit`）。被打者只在**函数开头被单独预调一次**（`0x1809B7835`），循环**跳过它**。
   唯一会把被打者再调一次的分支见 §二·B（`damageType == Attack(4) && damageInfo.actingCard == 该卡`）。

**置信度：两条都是「实读」**（机器码逐条看过，地址可复跑）。

### B. 条件表（结论）

> ⚠️ `isEnchantment` 这个参数名**误导**：**非 jam 的卡会把实参覆盖成 `true`**（`0x18094B531-0x18094B536` 的 `cmove`）。
> 所以它实际语义接近「**忽略 jam 闸**」，不是「这一趟是附魔」。

| 自身 `cardAbilities` | jam(130/0x82) | 传入 `isEnchantment` | `resolveOnlyEnchantments` | `dontResolveEnchantments` | 有未花附魔 | **实际跑谁（按次序）** |
|---|---|---|---|---|---|---|
| 有 | **否** | 任意（**被强制 true**） | false | false | 有 | **自己 → 附魔** |
| 有 | 否 | 任意 | **true** | false | 有 | **只有附魔** |
| 有 | **是** | false（普通 `OnTrigger` 各重载） | false | false | 有 | **只有附魔**（自己的被 jam 压掉） |
| 有 | 是 | true（`TriggerEnchantment` / `OnTriggerEffectInCard` / `AiScripted`） | false | false | 有 | **自己 → 附魔** |
| **空 / null** | 任意 | 任意 | 任意 | false | 有 | **只有附魔** |
| 任意 | 任意 | 任意 | 任意 | **true** | 有 | **只有自己**（附魔被压掉） |
| 任意 | 任意 | 任意 | 任意 | 任意 | 无 / 全花掉 | **只有自己** |

补充：
- 附魔那一趟是**逐件判定 `EntityScript.IsSpentEnchantment(thisCard, enchantmentCard)`**，花掉的那件 `continue`（`.c:66-67`）。
- 附魔那趟对**每张附魔卡的每一条 `cardAbilities`** 逐条 `CardAbility.CanTriggerAbility(...)`（不是只看第一条 —— 这与 `GetAbilitiesForTrigger` 不同，见 §一·D）。
- `dontResolveEnchantments` **只在附魔那一趟的入口被读一次**（`0x18094B83C`），对"自己那一趟"无影响。

🔴 **`0x18094B573` 这条 `jge 0x18094B822` 是判据的核心**：`0x18094B822` 既被"跳过自己"的分支跳进来，也被"自己跑完"的循环出口跳进来
⇒ 它是**共享尾块**，不是"else 分支"。`.c` 里把它渲染成 `if {...附魔...} else {...自己...}`（`RawCardScript__TriggerAbilities.c:47-199`），
**布局反了**：Ghidra 把共享尾块放进了 `if` 体内，把"自己"那段放进了 `else`。

等价 C#：

```csharp
bool fired = false;
if (thisCard != null) {
    if (!thisCard.HasCurrentTrait(DefinedTrait.jam)) isEnchantment = true;     // 覆盖
    if (isEnchantment && cardAbilities != null && cardAbilities.Count > 0
        && !resolveOnlyEnchantments) {
        for (int i = 0; i < cardAbilities.Count; i++) { /* CanTriggerAbility → TriggerAbility */ }
    }
    // 共享尾块：两条路都到
    if (activeEnchantments != null && activeEnchantments.Count > 0 && !dontResolveEnchantments) {
        for (int i = 0; i < activeEnchantments.Count; i++) {
            var e = activeEnchantments[i];
            if (IsSpentEnchantment(thisCard, e.enchantmentCard)) continue;
            for (int j = 0; j < e.enchantmentCard.cardAbilities.Count; j++) { /* CanTriggerAbility → TriggerAbility */ }
        }
    }
}
return fired;
```

### E. `GetAbilitiesForTrigger` 与 `TriggerAbilities` 的一处真实差异（别混用）

- `TriggerAbilities` 附魔趟：**每张附魔的每一条 ability** 都判 `CanTriggerAbility`。
- `GetAbilitiesForTrigger` 附魔趟：**只看每张附魔的 `cardAbilities[0]`**，且只收 `trigger` 相等的第一条。
⇒ **不能拿 `GetAbilitiesForTrigger` 当 `TriggerAbilities` 的"同形判据"**（原报告 §七·2 就是这么写的；两处判据都读成了"兜底"）。

### B. 唯一例外（不会在普通战斗里命中）

特殊分支（`0x1809B78CB`）的条件 = **`damageInfo.damageType == Attack(4)` 且 `damageInfo.actingCard == 该卡`**，
它同时覆盖「`!IsInPlay(card)`」和「`card == damagedUnit`」两种到达方式。
- 普通战斗里 `actingCard` = **攻击者**、`damagedUnit` = **被打者**（`BattleManager__ResolveAttackDamage.c:26-30`：
  `DamageInfo(actingCard=param_2(attacker), …, type=4)` → `BroadcastUnitDamaged(manager, param_3(defender), …)`）⇒ **两者不同**，被打者不会被特殊分支再调一次。
- 只有当**某条 `DamageType.Attack` 的 `DamageInfo` 的 `actingCard` 就是被打者自己**（自伤攻击）时，才会出现"预调 + 特殊分支"两次。
  本语料里构造 `type=4` 的只有 `ResolveAttackDamage` 一处；**没找到硬闸禁止 attacker==defender** ⇒ 记为**强推断（实际不可达）**，见 §四。

### C. 手牌两跳（对"双响"无影响，但形状要记住）

棋盘循环之后：`IsPlayerTurn` → `GetCardsInHandRef(当前回合方)` → 逐张 `ResolveDamageDealt`；再 `GetCardsInHandRef(!当前回合方)` → 逐张（`0x1809B7979-0x1809B7A32`）。
**这两跳没有 `!= damagedUnit` 过滤** —— 但被打者通常在场、不在手牌，所以不构成双响。

### D. 我们 vs 原版的真实差异（受伤这一块只有这一条）

| 维度 | 原版 | 我们 |
|---|---|---|
| 被打者自己的监听 | **函数开头预调一次**（`0x1809B7835`），随后棋盘循环**跳过它** | `EmitHit`（`RuleCore.cs:7036-7045`）→ `BroadcastWhen(WhenEventKind.Damaged,…)`，棋盘快照（`EffectResolver.cs:6864-6879`）**包含被打者**，它按**格号序**在循环里触发 |
| ⇒ 结论 | **被打者先于所有其它监听者** | 被打者按 `p 升序 / 格号升序` 排队 |

⇒ 这是 **D8 的"序"差异，不是"双响"差异**。⚠️ **改的时候如果只加预调、不把被打者从快照里排除，就会真的变成双响** —— 这正是原报告担心的那个后果，别踩。

## 三、建议改法（只给方案，未改代码）

1. **D12：不改实现，撤回"差异"结论。**
   - `RuleCore.cs` 的 A1567 注释（`FireTriggerAt`，约 `:9059-9072`）**判据引错了符号**：
     写着「`GetAbilitiesForTrigger(thisCard, trigger, true)`」，实际 `TriggerAbilities` **从不调用它**（它把附魔那一趟内联在函数里；
