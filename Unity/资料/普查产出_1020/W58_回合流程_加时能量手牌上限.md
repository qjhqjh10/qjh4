## 结论（3 句）

1. **加时**：判据从「后手 `MaxEnergy >= 10`」改成原版形状「**全局回合号 `ctx.Turn >= overtimeTurn`**」。`overtimeTurn` 的**唯一本地配置**是 `GameplayVariables.ClassicOvertimeTurn = 10`（遭遇也用它），**值仍是推断**（服务器真值本地没有）。
2. **`Gain N Energy`**：原版是 `ManaBuff.createMana` → `PlayerManager.AddNewMana`，**永久 `totalMana++`、当前能量不动**（对 DA61：`refillMana=0`）。我们原来有**两条**错路：`DoEnergy`（`Energy = Min(Max, Energy+n)`）和 `DoGive` 的 `Attr=="energy"` 支（**逐目标** `Energy += n`，DA61 在 `ruleprobe` 里实测**4 个目标各加一次**）。两条都改成「上限 +N、当前不动、只结算一次」，并记进 `ctx.Vars.ManaBonus` 让 `BeginTurn` 的公式把它加回来。
3. **手牌上限**：改成原版「**抽牌那一刻先判 `Count < handLimit`，满了就把刚抽的这张送墓地**」；`MoveDeckTopToHand` 不再「先 Add 再丢表尾」。潮涌 / 伴生这两条造牌路也一起改成同一个 helper。

## ③ `Gain N Energy`

### 原版证据（逐句 + 反汇编）
- `BattleManager__ProcessManaBuff.c:38-62`：
  · `createMana(+0x16)` ⇒ `PlayerManager__AddNewMana`
  · `refillMana(+0x17)` ⇒ `PlayerManager__RefillOneMana`（只补当前，不动上限）
- `PlayerManager__AddNewMana.c`：
  · `totalMana(+0x38)` **无条件 `++`**
  · `unusedMana(+0x4C)` **只在第 2 个实参 `filledMana` 为真时 +1**（且仅当它 < 新 total）
  · `untilEndOfTurnMana(+0x60)` 只跟第 3 个实参
- **`filledMana` 实参是什么**：反汇编 `ProcessManaBuff` 的 `createMana` 支（RVA `0x971e11`）：
  ```
  movzx r8d, byte ptr [rbx+0x18]     ; untilEndOfTurn
  xor   r9d, r9d
  movzx edx, byte ptr [rbx+0x17]     ; <- filledMana = ManaBuff.refillMana
  mov   rcx, rdi
  call  AddNewMana
  ```
  ⇒ **只带 `createMana` 的卡：上限 +N、当前能量一点不动**。
- **DA61 的真值**（`Unity/数据/游戏数据/cards_truth.json`，`Plasma Generator`）：
  `manaBuff { "manaAmount": 1, "friendlyPlayer": 1, "createMana": 1 }` —— **没有 `refillMana`**。
- 全池分布（`cards_truth.json` 扫 `manaBuff`）：`createMana` only **49** · `refillMana` only **40** · 两者都有 **3**。
  「Gain」与「Refill」的卡面文字正好对应这两支（`Refill 1 Energy` = `GSC63 Alien Idol`，别混）。

### 改前 / 改后
| 路径 | 改前 | 改后 |
|---|---|---|
| `EffectResolver.DoEnergy`（`gainenergy`，裸 `Gain 1`） | `Energy = Min(MaxEnergy, Energy+n)`（补当前） | `MaxEnergy += n` + `Vars.AddManaBonus(owner,n)`；**当前不动** |
| `EffectResolver.DoGive` 的 `Attr=="energy"`（DA61 走这条！） | 逐目标 `Players[owner].Energy += val` —— `ruleprobe play DA61` 实测**4 个目标各加一次当前能量** | 在**目标循环之前**单独结算一次：`MaxEnergy += val` + `ManaBonus`；循环里 `Attr=="energy"` 直接 `continue` |
| `ApplyOneGain` 的 `case "energy"`（兜底） | `Energy += val` | `MaxEnergy += val` + `ManaBonus`（正常路径到不了，防其它调用点） |

### 跨回合保留（这是关键的一半）
我们的 `MaxEnergy` 每回合由公式**重算**（`RuleCore.BeginTurn`），原版 `totalMana` 是跨回合保留的。
⇒ 在 `GameplayVariables` 新增两个**每局副本**字段 `manaBonusSeat0/1` + `ManaBonus(seat)` / `AddManaBonus(seat,n)`，
`RuleCore.BeginTurn` 的公式加 `+ ctx.Vars.ManaBonus(ctx.Active)`（`RuleCore.cs:1132`）。
⚠️ 为什么放 `GameplayVariables` 不放 `PlayerState`：`PlayerState.cs` / `BattleContext.cs` **不在本次白名单**；
`ctx.Vars` 是每局一份的 `Clone()`（`BattleContext.cs:719`），出不了这一局。这是**可变的对局状态**，将来若搬回 `PlayerState` 请一起搬走。

### 改前 / 改后
| | 改前 | 改后 |
|---|---|---|
| 抽牌 | `Hand.Add` → `EnforceHandLimit` 丢**表尾** | `AddCardToHandWithinLimit`：`Count < limit` 才 Add + `SetupCardInHand`；否则**刚抽的**进弃牌堆 |
