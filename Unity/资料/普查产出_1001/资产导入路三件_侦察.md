### 3·5·a ✅ **`Hidden/LUTBlender` 的混合公式 = 逐纹素 `lerp`（反汇编实证，2026-10-01）**

工具：`工具/disasm_dxbc.py` 的 `_d3d_disassemble` + `split_dxbc`（Windows 自带 `d3dcompiler_47.dll`）。
⚠️ **这个 shader 不在 `dump_shader_blob.BUNDLES` 的那 3 个包里** —— 它在**每个战场场景包**
（`scenes_scenes_battlearena*`，13 份）里 ⇒ 要自己指定源包（拿 `UnityPy.load` + 复用那两个函数）。

`Shader.compressedBlob` 解出来 **3504 字节**，里面两段 DXBC（偏移 446 / 1278）：

```
--- vs_4_0（684 字节）---  只做 v1.xy → o0.xy 的直通 + 常规 MVP 变换（**没有 3D LUT 坐标运算**）
--- ps_4_0（452 字节）---
  dcl_resource_texture2d (float,float,float,float) t0
  dcl_resource_texture2d (float,float,float,float) t1
  sample r0.xyzw, v0.xyxx, t1.xyzw, s1     // t1 = _LUT2
  sample r1.xyzw, v0.xyxx, t0.xyzw, s0     // t0 = _LUT1
  add    r0.xyzw, r0.xyzw, -r1.xyzw        // _LUT2 − _LUT1
  mad    o0.xyzw, cb0[3].xxxx, r0.xyzw, r1.xyzw
  ret
```

⇒ 🔴 **`out = lerp(_LUT1, _LUT2, _Blend)`**（`cb0[3].x` = `_Blend`），
而且是 **`texture2d` + 同一个 UV**（**不是** `texture3D`）—— 也就是**在 256×16 的展开空间里逐纹素插值**。
这正是「混两张 color-grading LUT」应有的语义（在 3D 空间插值反而是错的）。
与 pass 状态 `One→Zero`（不透明、无混合）自洽：它是**往 RT 里写结果**，不是往屏幕上叠。

⇒ **这一步的「还差什么」已经没有了**：公式在手，shader 照这 5 行自己写一份等价的即可
（源码被剥，但算式是实测读出来的、不是猜的）。

### 🔴 探针实测：**本 build 的 `AssetBundle.LoadAsset<Material>(名字)` 是坏的**

第一轮改完（只试 `LoadAsset<Material>(名字)`）跑 `RunListed`，**3 张全部报「没取到」**。
写探针 `EffectExporter.ProbeModuleMaterials` 量了一遍（日志 `_tmp_view/matprobe.log`，筛 `^PM `），
结论**逐条实测**、不是推断：

| 取法 | `Card 3d Stealth` | `Card 3d Dissolve Blend Image Ambush` | `Vanguard_Frame VAT Dissolve` |
|---|---|---|---|
| 在 `GetAllAssetNames()` 里？ | **没有** | **没有** | **没有** |
| `LoadAsset<Material>(**名字**)` | **null** | **null** | **null** |
| `LoadAsset<Material>(**容器 GUID**)` | ✅ **成功** | ✅ **成功** | （本来就没有容器键） |
| `LoadAllAssets<Material>()` | ✅ 在（`battlesharedresources` 里共 **59** 个） | ✅ 在 | ❌ `battleprefabs` 里是 **0** 个 |

**两条硬结论：**

1. 🔴 **`GetAllAssetNames()` 吐的是【容器键】，不是资产名** —— 所以 `LoadAsset<T>(名字)` 对这个 build
   **恒为 null**。这不是「这个包没有」，是**取法不对**。⇒ 有容器键的走 `LoadAsset<Material>(键)`。
2. 🔴 **非 addressable 的材质只在【我们重打的小包】里才是可加载根** —— `Vanguard_Frame VAT Dissolve`
   在原包（battleprefabs）里 `LoadAllAssets<Material>()` 返回 **0**（它只是依赖、不是根），
   但**它已经在我们重打的 `wf_prefabs_extra.bundle` 里**（`Vanguard Frame Animated VAT` 的依赖；
   该包 8 个 Material 里有它）⇒ 去那个包按名字捞。
   （这与 2026-10-01 那两个 prefab 的坑**同源**，见 `资料/已知的坑.md` 同名那条。）

### 修法（落地）

新增 `工具/gen_module_material_sources.py` → **`数据/游戏数据/module_material_sources.tsv`**
（`材质名 \t 源包文件 \t 容器GUID(可空)`）。**挑法两条**：有容器键的优先（按键取）；
都没键就**优先重打的小包**（那种材质只有在它里面才是可加载根）。

实跑产物（3 条，逐条对）：

```
Card 3d Dissolve Blend Image Ambush	battlesharedresources_assets_all.bundle	e025562dc019d43ca80948e26410a9ed
Card 3d Stealth	battlesharedresources_assets_all.bundle	bdbaf2a0fef8b4d0c875d8d1e65dbc8e
Vanguard_Frame VAT Dissolve	wf_prefabs_extra.bundle	          ← 无容器键 ⇒ 去重打的小包按名字捞
```

⚠️ **写这个脚本时踩过一个坑**（第一版）：「找到就移出待查集」那套写法让
`Vanguard_Frame VAT Dissolve` **在源包里先被找到、重打小包那一份被跳过**，输出指向了原包 ——
而原包里它根本**加载不出来**。同一张材质会出现在**多个包**里，而「该去哪个」正是要判的东西。

`EffectExporter` 侧配套：`LoadedPacks` 从 `List` 改成**按文件名做键的字典**；`FindMaterialInPacks`
按上面那张表走三条路（有键按键 / 无键在该包 `LoadAllAssets` 捞 / 无表项退回遍历）；
`Run()` 原来**不加载** `StreamingAssets/WarpforgeVFX/` 的小包（只有 `RunListed` 加载）
⇒ 已补上 —— 否则「全量重导」反而会漏掉那几件。

### 🔴 第三张还是取不到 ⇒ 它得**重打进我们自己的包**

按上面那张表走之后，2 张卡材质进来了，**`Vanguard_Frame VAT Dissolve` 仍然报「在
`wf_prefabs_extra.bundle` 里 `LoadAllAssets<Material>()` 也捞不到」**。查清了：

- UnityPy 直读该包：**Material 对象确实在**（8 个，含它，PathID `8641366270028613505`）——
  但它的 **`m_Container` 只有 4 条**（两件 prefab × 裸名/小写路径）⇒ 它**不在容器里**
  ⇒ `LoadAllAssets` 也不吐它（还是那条「不在容器里 ⇒ 三条路都拿不到」）。
- 再查「有没有 Unity 对象引用它」：包里两个 `MeshRenderer` 引用的是 **`Vanguard_Frame VAT`**
  与 `Card 3d WH40K Explosion` —— **没有任何对象引用它**。
  引用它的只有 AnimFX 的**模块字段**，那活在 **JSON** 里、不在包里。
  ⇒ **从任何 GameObject 出发的依赖树都走不到它**，三条 Unity 取法也就一条都没有。

**做法（照这条线既有的模式）**：把它当**根**一起打进 `wf_prefabs_extra.bundle` + **登记容器项**。
`工具/extract_missing_shaders.py` 加了两处（都是小改）：
- `MATERIAL_TARGETS = ["Vanguard_Frame VAT Dissolve"]`；
- `repack_tree(..., extra_materials=())` —— 按 `m_Name` 找 Material，**并进 `found`**
  ⇒ 一起走依赖树、一起登记容器项；容器别名的后缀**按类型给**（原来一律 `.prefab`，
  现在 Material 给 `.mat`）。

**实跑**：干跑 `--prefabs --check` 报 `找到 1/1 个材质根：Vanguard_Frame VAT Dissolve(PathID 8641366270028613505)`；
真跑后 `_verify_prefab_bundle.py` **四项全过**，容器 **4 → 6 条**、预加载 **2 → 3 条**：

```
['Card 3D Death Explosion', 'assets/card 3d death explosion.prefab',
 'Vanguard Frame Animated VAT', 'assets/vanguard frame animated vat.prefab',
 'Vanguard_Frame VAT Dissolve', 'assets/vanguard_frame vat dissolve.mat']
```

⚠️ **自检脚本的期望值随之改了**（`WANT` 从 2 件到 3 件、「应为 2」改成按 `len(WANT)` 算）——
它原来把「2」写死，重打之后会报一处假红。**这类写死的期望值要跟着改，别让它变成噪声。**
