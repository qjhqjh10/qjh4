## 二、设计：三层，各自的判据只有一处

```
卡面文字
  │  CardDef.AddWhenTrigger  —— 切法：`When ` 开头、按**第一个逗号**切
  ↓
WhenEvent { Kind · OwnerIs · Criteria · Raw }
  │  WhenEvents.Parse        —— 事件短语 → 上面那个结构（认不出返回 null，**绝不降级**）
  │  WhenEvents.Matches      —— **极性判据的唯一一处**（friendly / enemy 在这里换算成 0/1）
  ↓
CardDef.WhenTrigger { Ev · Ops · Body }      ← 挂**场上那张牌**上
CardDef.CostWhen    { Ev · Delta · Body }    ← 挂**玩家身上**（牌在手里时就监听，离手还留着）
```

### 为什么不是一个 `if`

第三十一轮给触发式正文（`Rally:`/`Strike:`/`Slay:`/`Backlash:`/`Penitence:`）开的
`CardDef.TriggerOps` 只解决了一半问题 —— 那一族的**时机在代码里**（`FireTriggerAt` 这个固定调用点），
卡的正文只是给那个时机配的话。

**这一族反过来：时机本身就是数据。** 卡面写 `When a friendly troop dies`，
引擎就得先认得出「友方单位死亡」这件事、再在**那件事真的发生时**回头找谁在听。
所以必须先有一张「事件短语 → 事件种类」的表 —— 这就是 `WhenEvent.cs` 存在的理由。

### 三条硬规矩（都写在 `WhenEvent.cs` 文件头）

1. 🔴 **认不出的事件不许注册。** 正文能解析率很高（77/83），所以**风险全在事件名那一侧** ——
   认错了事件，正文照样是合法的 op，**打起来看不出哪里不对**。
   ⇒ `Parse` 认不出就返回 `null`，**绝不降级成「任意事件」**。
2. 🔴 **极性必须显式。** `When an enemy dies` 与 `When a friendly troop dies`
   的**事件种类完全一样**，差别只在 `OwnerIs`。写反 = 整档效果反着触发，**不报错**。
   原版对应的是 `TargetCriteria` + `HandEffect.playersAffected`
   （`PlayerHand__UpdateCardEffects.c:267` 判自己 / `:303` 判敌方）—— 那边也是显式写两遍。
3. 🔴 **相对词不在解析期换算成阵营。** `friendly`/`enemy` 是**相对监听者**说的；
   解析发生在卡表加载时（一局棋之前），那时没有监听者。
   ⇒ 解析期只记方向哨兵（`RelFriendly = -2` 等），换算留给 `Matches` 拿到 `listener` 之后做。
   **同一张卡在任何一局里解析结果一致。**

|---|---|---|

⚠️ **其中「造隐秘」实测是「点亮但打不出来」**：卡池里**共 18 张**提到 secret/sabotage 的卡，
造的全是 **sabotage**（Genestealers 一族 10 张在用 `Create a random Sabotage in the enemy hand`）；
提到 secret 的那几张走的是「**选择**一张隐秘加入牌库」和「**打出**过几张」。
⇒ `Ravenwing Champion`（`When you create a Secret`）**一次都不会响** ——
广播留着是对的（真有效果造隐秘时就该响），但**别把它算进「已铺完」**。

**🔴 `When you reanimate a Remnant` 与 `When Reanimated` 只差一个字母、语义相反，别合并**：
前者是「**你这一方**做了再造」（监听者自己**没有**被再造 —— 实测那张是督军 `Diviner`）⇒ **不能带自指**；
后者是「**它自己**被再造」⇒ **必须带自指**。两条各有正反断言钉着。

⏭️ **剩下这些怎么做** —— 只有**三条**主线，不是「要等很多机制」：

1. **关键词「被触发」时机**（`swarm` 合并 / `synapse` 复读 / `mob` 近战攻击后 / `ferocity` 替代行动 /
   `duty` 一次性）—— 剩下的 **10 种短语全在等它**，是大头。
   **接口照 `Prays` 的现样板**（`RuleCore` 里那处 `BroadcastWhen`）；语义判据由子代理查证过，见候选 E。
2. **荣誉 `honour` 资源**（1 张）—— 照信仰 / 灵石 / 任务点三件套复制即可；
   **顺带修掉 `oath` 静默按能量扣**（那是条独立的红线）。
3. **灵魂石主动能力 `useWaystone`**（1 张）—— 与「翻面 → 收集」两段式是**同一件事**。

**C / 单案四条里有一条已经可以提上来**：`this unit attacks an enemy with hunt mark` ——
它缺的三样里，**自指**与**运行时关键词筛选**本轮都补好了，只剩「动词在中间的切法」。
另三条（`played` / `this unit kills an enemy` / `you create or play a secret`）的说明见上面。

⚠️ **判定「该不该现在做」的标准仍然是那一条**：那个事件在引擎里**有没有发出点**。
`trigger ferocity` 听着像「加个词表就行」，但 `Ferocity` 机制本身没做（不在 `Implemented` 里）
⇒ 它属于「等机制」那一类。**长得像不等于做得了。**

## 三·五、第三十四轮：三件收尾 + 两处静默失效 + 两条「尺子会骗人」的教训

### ① 事件触发式降费 ✅

**落点**：`EffectResolver.BroadcastCostWhen`（新），调用点在 `BroadcastWhen` **开头**。

🔴 **必须排在「场上没人听就 `return`」之前** —— 这一族挂在**玩家身上**，与自家场上有没有单位无关
（`Lower cost by 1 when an enemy dies` 在自己一个兵都没有时照样该降）。放后面会被那条早退**静默跳过**。

**实测 3 张卡**：`AM60 Mechanised Infantry`（部署载具）· `AM61 Vengeance for Cadia`（友方部队死）·
`TAU66 Burgeoning Empire`（敌人死）。

**原版依据**：牌在手上就是一等监听者 —— 广播器**四支**（自己 → 场上每张牌 → **当前回合方手牌** →
另一方手牌），`BattleManagerSupport__BroadcastUnitSummoned.c:23,41,53,65`；牌入手牌就挂，
`PlayerHand__SetupCardInHand.c:60-73`；「对哪张牌降费」＝挂到那张手牌自己身上，
`PlayerHand__AddHandEffect.c:127-136`。

**⚠️ 四处「我们挑的 / 近似」**（代码注释里也写了）：① 按卡 id 匹配 ⇒ 同名副本一起降（卡实例身份仍缺）；
② 每命中一次叠一次、**无上限**（原版 `HandEffect.limitedUses` 有上限）；
③ **登记后不过期**（`ExpireTurn = -1`；原版每次刷新会回收，`PlayerHand__UpdateCardEffects.c:334`）；
④ **顺序**排在场上前，原版排在场上前**之后**（`:41` → `:53`）。

⚠️ **一处「查不到」，别当成原版结论**：那 3 张卡**各自的 trigger 枚举值**（结构上推是
`OtherUnitSummoned=190` / `OtherUnitDeath=90`）**无法从原始资产证实** ——
`d:/2/解包整理/01_卡牌/<阵营>/` 下只有 `AssetBundle / AudioClip / Sprite / Texture2D / 动画`，
**没有卡牌定义（`RawCardScript` / `CardAbility`）的 MonoBehaviour**（带 MonoBehaviour 的只有
`卡牌动画` 与 `卡组信息`，都不是效果定义）。⇒ 上面那些**行号级**依据（`BroadcastUnitSummoned.c` 四支、
`SetupCardInHand.c`、`AddHandEffect.c`）都来自**有方法体的真反编译**、可用；**枚举取值那一层是推断**。

### ② `damaged` 广播 ✅

**落点**：`RuleCore.EmitHit`（新）—— 把「发 `EvtKind.Hit` ＋ 广播 `damaged`」收成**一处**，
`ApplyDamage` 的三条出口（Shield 全挡 / Invulnerable 免疫 / 正常扣血）都走它。
三条出口各写一遍 = 迟早只剩一处是对的。

**实测 2 张卡**：`BL38 Child of Torment`（任意单位受伤 → 本回合 +1 远程）·
`BL19 Noise Marine`（**督军**受伤 → 一个黑暗契约）。

**原版依据**：`BattleManager__BroadcastUnitDamaged.c:15` →
`BattleManagerSupport__BroadcastUnitDamaged.c:21,61,72,84`；触发枚举 `UnitDamaged=60`
（`CardScript__ResolveDamageDealt.c:162-164`）。**每个受害者各广播一次**
（溅射逐目标，`ResolveTraitAdjacentDamage.c:19-28`）。

⚠️ **一处比原版宽、一处偏**，都如实标着：原版 `damageValue == 0` 时整体早退
（`ResolveDamageDealt.c:36-38`），我们 `amount == 0` **照样广播**（照 `EvtKind.Hit` 的口径）；
我们**扣血之后**才广播，原版在**扣血前**。

**递归已验**：`RuleEngineTest.TestEventLayerTail` ⑤ 是两个**互相触发**的监听器（各 50 血，
靠 `MaxEffectChain = 8` 截断），断言「真的会停」＋「**链归零**」。

### ③ 自指 ✅（`deployed` / `reanimated`）

**机制**：`WhenEvent.SelfOnly` ＋ `WhenEvents.Matches` 里的 `ReferenceEquals(listenerUnit, subject)`。
两头缺任一 ⇒ **不触发**（「收不到」比「乱触发」安全）。

**原版依据**：靠**枚举值本身**分「本卡 / 他卡」—— `ThisUnitSummoned=195` vs `OtherUnitSummoned=190`、
`ThisCardPlayed=0` vs `OtherCardPlayed=10`（`AbilityTrigger.cs`），同一条广播里用 `param_2 == param_1` 分流
（`CardScript__ResolveUnitSummoned.c:23-35` vs `:41-51`）。
⚠️ **不要把原版说成「牌自己监听自己」** —— 原版是**同一条广播里把 `thisCard` 和 `actingCard` 都传进去**。

**收到的**：`When deployed`（`SW17 Grey Hunter`，全池 1 张）· `When Reanimated`（Sautekh 4 张）。

🔴 **`reanimated` 原来是个真 bug**：只设了 `Kind`、**没设 `SelfOnly`** ⇒ 按「**任何单位**被再造」收。
任意一张 SAU 在场时，**别人（含敌方）被再造**都会让它的监听器响，而 `subject` 指向**被再造的那个**
⇒ `SAU72 Immortals Phalanx` 的 `deploy a copy of this troop` 会去复制**别人**。
原有用例只量了「自己翻自己」，所以一直没露头。

**`When played` 仍未收**（`DA47 Reconnaissance Mission`，全池 1 张）：它是**战术卡**，
而监听器只从**场上单位**收集 ⇒ 收下来就是「注册一条没人消费的监听器」（红线）。
它真正的形状是「打出这张牌时顺带做 X」，该在 `CanPlayTactic` 那条路上补，**不是事件层的事**。

### 🔴 顺带查出并修掉的两处静默失效（都**已经点亮了，却一次都不响**）

| 失效 | 症状 | 修法 |
|---|---|---|
| **判据只收 `CardDef`** | `When an enemy with Hunt Mark dies`（`Stormwolf` / `Wolf Priest`）—— 猎杀标记是效果在**运行时** `AddKeyword` 加的、**卡面没印** ⇒ `CardDef.Has()` 永远 false | 新增 `CardCriteria.Matches(UnitState)`；`WhenEvents.Matches` / `ResolveDeploy` 有 `UnitState` 就传它 |
| **关键词没归一化** | 判据那侧存**卡面原话** `"hunt mark"`（带空格），卡表那侧存规范键 `"huntmark"` ⇒ 换成 `UnitState` 也还是永不相等 | `CardCriteria.NormKeyword()` **一处**归一化，两个 `Matches` 共用 |

### 🔬 两条**当尺子用会骗人**的教训（本轮真踩了，各踩两次）

1. **`gain` 这类「无目标的正文」会落到己方全体**（`EffectResolver.cs:1945`，照 `rule_core.gd:3137`，
   原版自己标为近似）。⇒ 拿「**数值变了多少**」判「**谁的监听器响了**」是量错的：
   自指的 `When deployed` 与 `When Reanimated` 两格都因此先红了一次。
   **改用 `RuleEngineTest.WhenFired(ctx, 卡名)`** —— 数日志里「这张卡的监听器响了」几行，与目标语义无关。
2. **fixture 的正文解析不出来时监听器根本没注册** ⇒ 反例断言会**假通过**。
   ⇒ 每条反例**前面先钉一条 `WhenTriggers.Count == 1`**。

## 四、顺手修掉的静默失败：`talent` / `ferocity` / `quest`

**怎么发现的**：派子代理做「关键词三列对账」（产出 `资料/关键词三列对账.md`）时查出来的。

**症状**：这三个词**根本不在 `CardDef.Prefixes` 里** ⇒ `Normalize` 返回 null ⇒
`KeywordTable.Parse`（`CardDef.cs:447`）与构造函数（`:92`）**双双丢弃**。
后果是它们**既不出现在 `UnimplementedKeywords()` 名单上，卡面也不打 `*`** ——
**两张诊断单都看不见**，正好踩本工程「静默失败」红线。

**实测命中**：`Talent` **91 张**（SaimHann 一族，`Avatar of Khaine` 的 `Talent: Wrath of Khaine`、
`Wave Serpent` 的 `Talent: Skyborne Deployment` …）· `Ferocity` **13 张**（SpaceWolves 的替代行动族）。
`Quest` 本卡池 0 张，但规则书`:199` 收了、`DefinedTrait.quest :74` 有 —— 一起补。

**修法**：`CardDef.Prefixes` 加三条。**只补「认得出」这一层**，三者仍然**没有机制**
（不在 `Implemented` 里）—— 现在的行为是「如实报成未实现 + 卡面打 `*`」，**这才是对的**。

**验收**：自检打印的「全卡池未实现关键词」**24 → 26 个**（`ferocity` 出现；`talent` 本来就在
被丢弃之外的地方算得到，`quest` 池里 0 张）；**1262/1262 全过**。

|---|---|---|
| **监听范围不判回合方** | 只要「事件发生在自己这方」就触发，不看现在是谁的回合 | 原版广播器 `BattleManagerSupport__BroadcastUnitSummoned.c` 分四支（自己 `:23` → 场上每张牌 `:41` → **当前回合方手牌 `:53`** → 另一方手牌 `:65`）。我们只做「场上每张牌」那一支，**不判回合方** —— 规则书 `:238`「被攻击方优先结算」讲的正是**非**主动方要触发 |
| **降费语义** | 「每满足一次事件就 `-N`」，可叠加 | 卡面字面（`Lower cost by 1 when …`）。`rule_core.gd` **没有实现这四张卡**（它整库只有 2 处 `when` 的硬编码特判），**没有权威依据** |
| **`When deployed` 这一类自指事件** | ✅ **2026-09-13 第三十四轮收了** —— `WhenEvent.SelfOnly`，要求「发生事件的那个单位**就是**监听者」（`ReferenceEquals`） | 原版靠枚举值分「本卡 / 他卡」（`ThisUnitSummoned=195` vs `OtherUnitSummoned=190`）。`When played` 那张是**战术卡**，挂载点不在场上，仍未收（见 §三·五·③） |
| **`a friendly unit` 里的 `unit` 不筛** | `unit`/`troop`/`minion` 都当「单位」大类，不筛兵种 | `CardCriteria` 的三个维度都没有「是不是单位」这一维；卡表里 `unit` 也不是 `subtype` |

## 六·五、🔴 **实战检查：机制是对的，但「几乎看不见」**（第三十二轮实测）

按本工程那道「跑得完 ≠ 跑得对」的关（`TestFactionBattle` 的思路）做了一次，
**用卡池真凑的牌组打了 12 局**（Ultramarines vs Goff，各 30 张）：

| | 结果 |
|---|---|
| 带监听器的卡 | 31 张（全卡池 1130 张里） |
| 牌堆里**发到**带监听器的卡 | **11 张次**（12 局累计） |
| 广播**真的发了** | **2 次**，只在 **1/12 局**里 |
| 响过的**不同卡** | **1 张**（`Beastboss Morgrim`，`deploy beast`） |

**看着像坏了 —— 但不是。** 按第三十轮的规矩补了**受控检查**（「牌组里把靶子塞满」）：
10 张监听器 + 10 张 1 血炮灰凑一副牌打 3 局（共 22 回合）⇒ **广播发了 20 次 ✅**。
⇒ **机制本身转得起来；实战里不响，是因为「监听器卡被 1130 张的卡池稀释了」。**

**为什么会这么稀**（两个数，都能复核）：

1. **那两个主力阵营本来就没几张**：全卡池有 `When <事件>` 的卡 **82 张**，
   但**分属 12 个阵营** —— `Ultramarines` 只有 **4 张**、`Goff` 只有 **5 张**。
   自动凑的 30 张牌组里平均摊到 1 张，还要抽到手、还要满足条件。
2. **82 张里只有 31 张注册成功**：另外 51 张的事件名我们还认不出（见 §三·④）。

⇒ **这不是 bug，是「内容还没铺开」。** 结论有两面：
- ✅ **引擎那一侧是好的**，不用回头改；
- ⚠️ **要看见这个机制，得先把 `When` 事件名那一侧铺宽，或者去做那 13 个还有 9 个没做的阵营。**
  只做 Ultramarines/Goff 的话，加了 5 张卡在 30 张牌组里，**玩家基本碰不到**。

**做法留档（下次要复现，照这个来）**：临时探针跑「12 局自动凑牌组 + 3 局靶子塞满」两层，
判据是数 `ctx.Events` 里 `—— 事件「` 开头的行（`BroadcastWhen` 每次触发写一条）。
