### A1548 —— ✅ 已修（工具侧）：纯 `Transform` 转发节点底下丢掉整支 UI 子树，现在**出声 + 计数**

**定位（先按判据查，两个工具同形同错）**
- 缺陷不在「`assets_full` 导出缺件」这一层，而在**走树函数**：
  `Unity/工具/menu_dump.py` 的 `walk()`（原 `rt is None` 分支）与
  `Unity/工具/menu_rect.py` 的 `walk()`（同形同错，A620 时代分开写的两份）。
- 根因：子件 pid 在 `RectTransform/` 里查不到、但在 `Transform/` 里有 `Transform_<pid>.json` 时，
  旧代码把它当「3D 件（本来就不该进 UI 表）」**直接 return** ——
  而它可能是**纯 `Transform` 转发节点**（`Card Info` / `Textbackgrounds`），
  **底下挂着有 RectTransform 的 UI 子件**。旧表尾只说「N 个纯 Transform 子件」，
  **不报“那底下还有东西”**，读表的人以为没事。

**复现（一条命令，现读可复现）**
```bash
python -I -X utf8 d:/4/Unity/工具/menu_dump.py \
  "d:/2/新解包资源/assets_full/bundle_scenes_scenes_battlearena1" --rt 3393 --depth 3 --no-sprite
```
- `3393` = `Front`（`bundle_scenes_scenes_battlearena1`）。
- **旧行为**：表尾只有「另有 3 个纯 `Transform` 子件（3D，例：卡片的 3D 体）本来就不属于这张 UI 表」。
- **实际数据**（现读该包）：
  - `Front` 直接子件 5 个，其中 2 个是纯 `Transform` 转发：
    `Textbackgrounds`（`Transform_1393`，底下 **2** 个 RT）、
    `Card Info`（`Transform_1261`，底下 **9 个直接 RT + 更深 = 19 个 RT 后代**）。
  - 旧工具把 **21 个**会被画出来的 UI 件**整支丢掉且不报**。
  - 与 T04 记录的「解包目录 `Front` 只有 3 个子件、真包有 5 个」自洽：
    `3` = 直接 RT 子件；`5` = 把两个转发节点各算一格后的**直接 UI 子件**数。

**修复（只加出声，⛔ 不改坐标算法、⛔ 不下钻）**
1. `menu_rect.Bundle` 补只读索引：
   - `_transform_pids()` / `has_transform()` / `tr_obj()`：按需读 `Transform_<pid>.json`（带缓存）；
   - `go_name_of_transform()`：纯 Transform 组件 → GO 名（`_scan_go` 顺手记 `tr_name`，只存字符串）。
2. 新增 `menu_rect.count_under_transform(b, tpid)`：数纯 Transform 节点底下**所有有 RectTransform 的后代**
   （穿透多层纯 Transform；`_guard` 防环；只数、不改任何 dict）。
3. `menu_rect.walk` / `menu_dump.walk` 的 `rt is None` 分支记账：
   `t_dropped`（被丢后代总数）· `t_drop_nodes`（真丢后代的转发节点数）· `t_skip`（逐条点名）·
   `miss_pids`（真缺件 pid，两样分开）。
4. 表尾出声（判据文案**只此一份** = `menu_rect.dropped_subtree_lines`）：
   - `menu_dump.py` 文本模式与 `--md` 模式都打；
   - `menu_rect.py` 表模式走 stdout、`--cs` 模式走 stderr（沿用既有约定）；
   - 形如：`🔴 纯 Transform 转发节点底下被整支丢掉：有 2 个…还挂着 **21** 个 RectTransform 后代` +
     逐条 `Textbackgrounds（丢 2 个）` / `Card Info（丢 19 个）`；
   - 真缺件也从「只报数」升级为「报数 + 点名 pid」。
5. 自检/断言：`menu_dump.py --verify-layout` 新增 **㉑**（在 ⑳ 之后）：
   - 合成夹具（临时目录，不碰真实解包目录）：`100(RT根) → 200(纯Transform) → 201(RT) → 202(RT)`，
     外加 `300`（真缺件）⇒ 断言 **两条 walk** 都得到 `t_kids=1 / t_dropped=2 / t_drop_nodes=1 /
     miss_pids=['300']`，且出声行点到 `Forwarder` 与「丢 2 个」，`MR.stats_warning` 含 `A1548`；
   - 真数据复核：`bundle_scenes_scenes_battlearena1` 的 `Card Info`（`Transform_1261`）底下
     RT 后代数 **> 0**（实测 19）。
   - 实跑：`python -I -X utf8 工具/menu_dump.py --verify-layout` ⇒ **exit 0 · 0 个 ❌ · ㉑ 绿**。
