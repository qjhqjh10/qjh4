### A. P0-2（必修）`HandleReplayBar` 破坏释放沿

**改前**

```csharp
bool HandleReplayBar()
{
    if (_replayBar == null || !ReleasedThisFrame()) return false;
    return ReplayClickAt(WorldPointer());
}
```

- `_replayBar` 在 `BuildHud` 里**必建**（`ReplayBar.Create(root)` + `Setup(false)`），普通对局只是把
  `Holder` 关掉（`Setup` 只做 `_holder.gameObject.SetActive(isReplayMatch)`）⇒ **恒非空**。
- `ReleasedThisFrame()` 是**破坏性**的（`_upEdge = false` + `LogClickBeat()`）。
- ⇒ `Update` 里排在它后面的每一条 release 分支在真机上**一条都收不到沿**；自检从不调 `Update`，全绿。

**改后**（`BattleDriver.cs:4932`）

```csharp
bool HandleReplayBar()
{
    if (_replayBar == null || !_replayBar.HolderVisible) return false;   // 🔴 不可见 ⇒ 提前返回、**不碰沿**
    if (!ReleasedThisFrame()) return false;
    return ReplayClickAt(WorldPointer());
}
```

**判据**：原版这 4 颗只在回放局里存在 —— `objHolder.SetActive(BattleManager.matchType == 0xA0)`，
判据 → `ReplayBar.cs` 文件头（`Setup` 的 doc 逐字写着这一句）⇒ 普通对局里它们连 `GameObject` 都是关的、
`EventSystem` 根本不会把点击派发给它们 ⇒ **不吃沿**。

**行为等价性**：`HolderVisible == true` 时，新代码与旧代码**逐位等价**
（旧：`null` 检查 → 消费沿 → `ReplayClickAt` 里再查 `null` / `HolderVisible` → `Hit`；
新：`null` / `HolderVisible` 检查 → 消费沿 → `ReplayClickAt`（内部两道检查仍在、结果相同）→ `Hit`）。
唯一差异就是「不可见时**不再消费**」，这正是要修的。

**断言**：`BattleScene.cs` 新增 `T09-FIX5/P0-2` 组（`:8175` 起）——
① 前提：普通对局 `Holder` 关着；② 造一次按下→松手 ⇒ `TickReplayBarForTest()` 返回 false **且
`ReleasedThisFrameForTest()` 仍为 true**（沿没被吃掉）；③ 前提：喂的世界点不在任何一颗钮上（`Btn.None`）；
④ 对照：`Setup(true)` 后再来一次 ⇒ 返回 false **但沿被吃掉了**（可见时行为逐位不变）。
**灭自证**：改回「先消费沿、再看可见性」⇒ ②红；改成「可见也不吃」⇒ ④红。

### B. P0-1 配对面（`LeavePointerToWorld` 放行面 = 任何棋盘卡）

**改前**（`T09-FIX3`）：`IsScreenPointOverCommandTarget` 只认**目标侧**那一格：

```csharp
if (!IsTargeting) return false;
if (cam == null || !LayoutSpace.IsInsideScreen(screenPoint)) return false;
return HitCommandTargetSlot(LayoutSpace.ScreenToWorld(screenPoint, cam)) >= 0;
```

⇒ 点**自己人 / 非目标**时捕获区照旧「按下即关」，而那与原版证据矛盾。

**改后**（`BattleDriver.cs:10216` + 新私有判据 `HitAnyBoardCard` `:10226`）

```csharp
public bool IsScreenPointOverCommandTarget(Vector2 screenPoint)
{
    if (!IsTargeting) return false;
    if (cam == null || !LayoutSpace.IsInsideScreen(screenPoint)) return false;
    return HitAnyBoardCard(LayoutSpace.ScreenToWorld(screenPoint, cam));
}

bool HitAnyBoardCard(Vector3 world)
{
    return HitSlot(_myUnits, world) >= 0 || HitSlot(_foeUnits, world) >= 0;
}
```

**判据**（原版，第一权威 = 全量反编译）：

- 棋盘卡自带 `CardCollider`（`IPointerDownHandler` / `IPointerClickHandler`，
  `CardCollider__…OnPointerClick.c` → `CardScript.OnTouchUpAsButton`），13/13 战场相机上挂
  `EverguildPhysics2DRaycaster` ⇒ **点任何一张棋盘卡，这一下都先被那张卡吃掉**，`HideAbilityButton`
  那块远大于屏幕的捕获区**收不到 PointerDown**。
- 原版点亮目标时**只改高亮、不关非目标卡的 collider** —— 现读
  `d:/2/tools/decomp_full/BattleManager__ShowPotentialTargets.c`（循环里只有 `CardHighlight__ChangeState()`）与
  `BattleManager__StartChoosingAbilityTargetByClick.c`（`:26-31` 同样只有 `CardHighlight__ChangeState()`，
  其余是准星 `ToggleCrosshair` / `PrepareMovement`）⇒ 点自己人 / 非目标**同样不会关面板**。
- 与 `DrivePlayerTurn` ④ 的关系：**不再共用判据**。④ 仍走 `HitCommandTargetSlot`（目标侧，释放技能），
  本口只管「捕获区让不让路」。两者职责分开后，「点自己人」= 面板不关、这一下交给世界侧
  （世界侧随后怎么处理见 §四·1 的残余）。

**`SkillPanel` 侧**：`LeavePointerToWorld` 的 doc 与 `OnHidePointerDown` 的 doc 同步改成「任何棋盘卡」；
行为代码一行没动（`OnHidePointerDown` 仍是 `LeavePointerToWorld(ped.position) ⇒ _closePassCount++ + return`）。

**断言**（`BattleScene.cs`，P0-1 组 `:8005` 起）：

1. 目标卡 ⇒ `IsScreenPointOverCommandTarget == true` + 捕获区按下**不关面板** / 放行计数 +1（原有，保留）。
2. **新增配对面：自己人那张卡 ⇒ `true`**（`★ T09-FIX5/P0-1（配对面）`，`:8060`）+ 真喂一次
   `SimulateHidePointerDownForTest(自己人的屏幕点)` ⇒ **不关面板 / 放行 +1 / 选中槽与打法不变**。
   **灭自证**：判据缩回「只认目标侧」⇒ 红。
3. **新增配对面：空棋盘格 ⇒ `false`**（`★ T09-FIX5/P0-1（配对）`，`:8102`）。
   空点 = 挑一个**空的可部署格**（引擎两侧都空 + 视图两侧都空 + 卡心用 `HitUnitSlotForTest` 两侧都不命中），

`Interactable` 闸 ⇒ ②红（淡出里又关一次）。
