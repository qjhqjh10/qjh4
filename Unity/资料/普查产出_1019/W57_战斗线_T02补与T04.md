## 二、`T04` 的四个研究问题（逐条给答案，全部有判据）

### 1. 敌人手牌 / 面朝下的牌在**中央放大窗**里原版显示卡背还是正面？

**正面。** 而且更准确地说：**放大窗根本不参与「翻面」这件事**。

- `CardDisplayWindow` 整个类**从不**碰卡面可见性：`CardDisplayWindow__InitializeCardForDisplay.c` 全篇零 `SetCardVisibility`；
  同族的 `ShowCard` / `InitializeCards` / `InitializeRelatedCards` / `ChangeCardPosition` / `CardSwapFinished` /
  `ToFocus` / `ToBackground` / `ResetOrder` / `DisableAllCards` 全部 `grep` 过，**零命中** `SetCardVisibility` / `ToggleCardBack`。
- 卡背 ↔ 正面的那套东西属于**战斗里的卡本体**（`BattleCardUI` 的 `Card2DController`），发生在
  「**打出的卡被搬到屏幕中央**」那条演出里 —— 不是放大窗。

### 2. 翻面动画的时长 / 参数（DLL 实读，`工具/read_literal.py`）

| 常量 | 地址 | 值 | 用在哪 |
|---|---|---|---|
| DOMove 时长 | `0x1834b3178` | **0.15 s** | `DisplayEnemyCardInCenter` state 0 |
| 摆正 `DORotate(Vector3.zero)` 时长 / 随后等待 | `0x1834b2dc4` | **0.1 s**（同一个常量两用） | state 0 |
| 翻面单段占比 | `0x1834b2e7c` | **0.25** | `TurnCardAround`（每段 = `t × 0.25`） |
| 翻面单段角度 | `0x1834b2e04` | **90°** | 同上（两段方向相反：90° → 0°） |
| `PlayEnemyCard` 的 `DAT_1834b3180` | `0x1834b3180` | **0.6** | `scaleTime = 0.12 × 0.6 = 0.072` |
| 停留系数 | `0x1834b3184` | **0.66** | `WaitForSeconds(hold × 0.66)` |
| 再等系数 | `0x1834b3190` | **2.6** | `WaitForSeconds(hold × 2.6)` |
| `timeToPlayEnemyCard` | — | **0.12 s**（`0.6 / 5`，见 `PlayAutoPlayCenterDisplay` 上面那段旧判据） | `PlayEnemyCard` 的两个实参 |

**翻面到底怎么发生的（这是本笔最关键的发现）**：
`TurnCardAround` 第一段 `DORotate(90°, t×0.25)` 的 **OnComplete** 是
`CardScript__FinishCardDrawRotation.c`，它第一句就是
`BattleCardUI.SetObjectVisibility(card, card.cardState)`；而 `PlayEnemyCard` 在校程开头把
`cardState` 置成 **10**（`inHandPlaying`），把 `BattleCardUI__SetObjectVisibility.c` 对 **state 10**
逐分支重放 = `SetCardVisibility(Front)`。
⇒ **卡背 → 正面发生在「侧立 90°」那一刻**（画面上看不见），前半拍（0.15 s 飞行 + 0.1 s 摆正 + 0.1 s 等 + 第一段 90°）
**一直是卡背**。

> 顺手把状态表的几档也重放了（只到「能定案本笔」为止）：`state 1` ⇒ 敌我分档
> （`isPlayer == 0` → **Back**、`isPlayer == 1` → **Front**）；`state 8/10` ⇒ **Front**；
> `state 0/16` ⇒ `Toggle(hide)` 那支。其余档未读（见 §四）。

### 3. 谁触发

- `CardScript._PlayEnemyCard_d__258__MoveNext.c:36` / `_PlayPlayerCard_d__259__MoveNext.c:36` ——
  只在 **`cardType != 0`（非单位卡）** 时走 `DisplayEnemyCardInCenter(card, t×0.6, t, showFront = **0**)`；
  单位卡（`cardType == 0`）走的是 `ShowCardInCenter`（我们已有：`PlayAutoPlayCenterDisplay`）。
- `BattleManager._ResolveDisplayFromHand_d__548__MoveNext.c:195` —— `(0.3, 0.3, 0)`。
- `BattleManager._ResolveCreateHandCard_d__512__MoveNext.c:100` —— **唯一 `showFront = 1`**（造牌入手：
  `(0.3, 0.3, 1)`，开场 `SetCardVisibility(Front)`、**不翻面**、收尾 `SetCardVisibility(Back)`）。
- `CardScript._DisplayOffensiveCardInCenter_d__264`（进攻卡）：开场**无条件** `SetCardVisibility(Front)`，收尾**不还原**。

### 4. 我们当前 `SwapToFront`（`CardDisplayWindow.cs:1237`）的行为

它是**扇形换位**（原版 `CardDisplayWindow.ChangeCardPosition`）：只做**位置 / 转角 / 缩放 / 着色**补间
（2026-10-19 上一笔已改成 `CardView.TweenPose`，`_baseScale` 一起带过去），**不碰卡背/正面**。
原版 `ChangeCardPosition.c` 也零 `SetCardVisibility` ⇒ **它和卡背翻面无关，本笔不需要改它。**

## 四、没查清 / 没做的（⛔ 不猜）

1. **卡背贴图与阵营**：`DisplayEnemyCardInCenter` 里非我方那一侧取 `CardArt.CardBack(_foeFaction)`。
   若该阵营的默认卡背图缺失，`CardView.SetBackVisible` 会出声且**不画** ⇒ 翻面演出退化成「一直正面」（如实失败）。
   自检那条 `carrier.BackVisible` 会红 —— 这是**真缺陷信号**，不是断言噪声。
2. **`_DAT_1834b3184 = 0.66` / `_DAT_1834b3190 = 2.6`** 的宽度按 **4 字节 float** 取（8 字节档是垃圾）。
   依据：它们参与的是 `fVar1 * _DAT_…` 再进 `WaitForSeconds`（float 上下文）；**未在反汇编指令流里逐条确认**
   （Ghidra 这两个是没跟到底的只读字面量）。
3. **state 2 的 `DisplayCreatedByText`**：`EvtKind.Play` **不带创建者** ⇒ 不画
   （原版 `card.createdBy == null` 时同样不画）。`ToggleHighlight(false)` 同拍 —— 我们的临时卡本来就是 Normal。
4. **只接了对手那半**（我方那半**没做**，如实记）：原版 `PlayPlayerCard` 也调同一方法，但我们的**起点**是
   「那一侧手牌末位」—— 对手手牌全是**同一张卡背**（从哪格飞出看不出），我方手牌**每张不同**，
   从末位飞出会与真实位置不符（原版搬的是卡本体、不复制）。要开我方那半，得先把**真实手牌视图本体**交给这段演出。
5. **临时卡与手牌里那张视图会重叠**（原版搬本体、不复制）；手牌同步在同一个事件帧里会把原来那张收掉 —— **未真机核**。
6. **不阻塞事件时间线**：原版外层 `PlayEnemyCard` 会 await 这条协程；我们的表现层是「事件到点各播各的」
   （`_timelineTailAt` 只管批与批之间）⇒ 本演出与后续事件**并行**。观感需真机核。
7. `BattleCardUI.SetObjectVisibility` 的**完整状态表**只解了 0/1/8/10/16 这几档（够本笔用）；其余档
   （2/3/5/6/11/12/17…）没读 —— 将来要做「手牌/场上的翻面」得整表重放，建议先补一条账。
