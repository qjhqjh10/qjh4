### 1. 删掉假话 —— ✅ 已照原版改成「结算段对手掉线 = 静默」

**原版判据（逐句亲读）**

| 出处 | 内容 |
|---|---|
| `BattleManager__DisconnectedDuringBattle.c:35-51` | `battleStage == 0x3C(PostBattle=60)`：`if (param_2 == 0) return;` —— **对手**掉线**直接返回**（不弹窗 / 不停表 / 不改结果） |
| `Everguild.BattleErrorUIManager__ConnectionStatusChanged.c:31-54` | `if (*(int*)(lVar1 + 0x294) != 0x3c) { switch… }` ⇒ stage == 60 时**只 `CustomDebug.LogWarning` 然后 return**（任何连接状态变化都不进弹窗分支） |
| `BattleNetworkManager__SetOpponentDisconnected.c:24` | 调 `DisconnectedDuringBattle(bm, 0)` ⇒ `param_2 == 0` = **对手**这一档（本机那一档是 `EventDisconnected.c:71` 的 `(…,1)`） |

**我们改前**：`NetBattle.HandlePeerLost` 无条件 `SayPeerGone(ReconnectHint(30)…)` ⇒ 结算后给玩家一句
「对手掉线了 —— 正在等他回来（**30 秒后判他弃权**）」；而 `StartReconnectCountdown` 遇 `Ctx.IsOver`
**根本不起倒计时**（`_countdownOn = false` 后 return）⇒ **那句「30 秒」是假的**。

**改后**：`HandlePeerLost` 开头：`_d != null && _d.Ctx != null && _d.Ctx.IsOver` ⇒ 打一条日志（含传输层原因）
**然后 return** —— 不设 `_peerGone`、不停表、不起倒计时、不报信、不弹窗、不判负。
另外把 `StartReconnectCountdown` 的两道闸（`Ctx == null` / `Ctx.IsOver`）挪到
「算秒数 + `_enemyDisconnects++`」**之前**（原版那个自增在 `_ForfeitDisconnectedEnemy_d__322__MoveNext.c:63`，
协程没起就不该自增 ⇒ 原来结算段的掉线会**静默污染**掉线次数）。

**⚠️ 边界（有意没改）**：`HandlePeerClosed`（收到我们自拟的 `bye`）在结算段**仍然出声** ——
那是**我们自己的协议分档**（原版没有 `bye`），且现有自检 `NetBattleTest` §12③
（`:1255-1279`）把「已经打完的局收到 `bye` **仍然要出声**（`不判弃权 ≠ 不说话`）」钉死了
（`n13.Length == 1`）。本批不动它，避免与既有断言打架。

### 2. 本机掉线 —— 🟡 **对局中那条分支已经存在（A914）；结算段那一档如实留缺、⛔ 不猜**

**原版**：
- 对局中本机掉线：`DisconnectedDuringBattle(…,1)` → `ShowDisconnectionPopup(true)` → `AttemptReconnect`
  （`_AttemptReconnect_d__320__MoveNext.c`，`Math.Max(10, …)` 退避）→ 失败
  `FailedToReconnectAfterDisconnect.c:26-27`：`AddResignAction(1)` + `DeadHero(我, 3)`。
- **结算段本机掉线**：`DisconnectedDuringBattle.c:52-64`：若 `RankedMatchResult.resultSaved(+0x1C)` 为假 ⇒
  `ShowDisconnectionPopup(true)` + **`shouldLoseIfDisconnectEnd(+0x2D8) = true`**；失败后同一跳 `DeadHero(我,3)`，
  由 `DeadHero.c:109-121` 的战后闸**放行** ⇒ `:123-139` `SetBattleResult(reason, Enemy=0x14)` + 重跑
  `BasicBattleEndSequence` = **重判本机负**。

**我们的现状**
- **对局中**：`ReconnectCountdownExpired` 已按两端分（A914）：`iAmDisconnectedEnd = _s.Role == NetRole.Client`
  ⇒ 客机走 `NetSelfResign(Disconnect)`（判本机负）+ `StopReconnecting()`；主机走 `NetRemoteResign`（判对面）。
  **这一条本批只补注释/日志，行为一字未动**；断言在 §14③ + 既有 §10③-7/③-8。
- **结算段**：本批**按对手那一档静默**（见上一条）——**不判任何人负**。
  缺的两件（都超本批所有权，如实记）：
  1. **「谁掉线」判据**：P2P 里「本机断网」与「对面断网」在本地 socket 上同形。
     `A1267` 的「传输层掉线：原因 = …」**判不了**（见下）。
  2. **战后重判入口**：`RuleCore.Forfeit` 现在 `Winner != 0` 一律挡（`RuleCore.cs:9478-9489` 的战后重入闸，
     它自己写着「结算段本机掉线⇒重判为负」的放行门我们**没有对应触发源**）；
     原版靠 `shouldLoseIfDisconnectEnd` 放行。`NetSelfResign` 即使调了也会被这道闸挡掉。

**`A1267` 能判多少（结论 = 判不了，所以不拿它判）**

| 原因串（`_s.LastError`） | 能否判「谁掉」 |
|---|---|
| `Settings/Online/St/PeerClosed`（「对面关掉了连接」） | ❌ **不能当可靠判据**：本机 `ClosePeer()` 拆连接时，本机读线程也会以同族原因失败并写进 `_lastError` / `_peerLost`（`NetTransport.Fail` 里 `_closing` **只压日志、不压**那两个字段）⇒「本机主动拆」与「对面关掉」在这一格同值 |
| `St/SilentTimeout`（「N 秒没收到对面的任何消息」） | ❌ 两边通用 |
| `St/ReadAbort` / `St/SendFailed` | ❌ 两边通用（本机网断 / 对面 RST 都可能） |

⇒ **只有一个方向的信息**（「本机这条 socket 怎么坏的」），没有「对面那条活没活」的信息。
**缺什么**（要真做原版那一档，需按序补）：① 一条应用层存活握手（重连成功后互换 last-heard 时间戳，
由连续存活那侧判）；或 ② 服务端/第三方仲裁；③ 再在 `RuleCore.Forfeit` 加一个**与原版同名的**
`shouldLoseIfDisconnectEnd` 放行门 + `BattleDriver` 的入口。**这两件都不在本批白名单，⛔ 没有造后门。**
另：`_peerLossWhy` 只是把**掉线那一刻**的传输层原因留了一份给日志（30 秒里客机重连退避会
`Connect` 清空 `_lastError`）——**不参与判负**。

## 三、没查清

1. **结算段「本机掉线 ⇒ 重判本机负」**：原版那一半（`shouldLoseIfDisconnectEnd` 放行 `DeadHero` 战后重入、
   `RankedMatchResult.resultSaved` 状态机）**未实现**。缺三件，按序：
   ① 分「谁掉」的判据（应用层存活握手 / 仲裁者）· ② `RuleCore.Forfeit` 的战后放行门 ·
   ③ `BattleDriver` 侧入口（`NetSelfResign` 已存在但会被 ② 挡）。① 在 P2P 里没有可靠来源（A1267 判不了，
   见 §一·2 那张表）—— **⛔ 没有猜一个**。
2. **`PeerClosed` 的可靠性没有实测**：本机 `ClosePeer()` / `Close()` 之后读线程到底把 `_lastError` 写成
   `PeerClosed` 还是 `ReadAbort`，取决于 socket 关闭时阻塞读是返回 0 还是抛异常 —— **本地只读代码，没真跑**。
   ⇒ 本批结论按「不可靠」处理（最保守那档），若将来有人想拿它当判据，必须先跑一次实测。
3. **主机的「本机掉线」那一档**：我们这套只有客机有主动重连退避（`NetSession.Pump`），主机自己网断时
   没有 `AttemptReconnect` 的对应物 ⇒ 倒计时到点会按「对面掉线」判**对面**弃权（A914 已如实记着）。
   要补同样卡在「① 分谁掉」。
4. **§14 的运行时断言没跑过**：夹具照 §10/§12 的形状写（`SetupA912` + `PumpOne` + `StopReconnecting` 止血），

## 四、顺手发现

1. **`NetSession.StopReconnecting()` 的 doc 已过期**（`NetSession.cs:695-696`）：
   写着「这一端**还欠**「判本机负」（原版 `DeadHero(我,3)`）—— 那要给 `INetBattleHost` 加一个口」，
   但 2026-10-18（A914）已经加了 `NetSelfResign` 且 `ReconnectCountdownExpired` 在用。
   ⛔ 本批**没改**：该文件此刻有另一个写手的在飞改动（`A1264` graceful close），且不在本批「结算段掉线」范围内
   ⇒ 建议主对话就地订正（铁律 5）。
2. **`NetTransport.Fail` 的 `_closing` 只压日志、不压状态**：本机主动拆连接时，`_lastError` / `_peerLost`
   照旧被写（只有那行 warning 不出现）⇒ **「本机主动拆」与「对面关掉」在 `_lastError` 上同值**。
   这正是 A1267 的原因串不能用来判「谁掉」的根因。若将来要做「分谁掉」，先给 `Fail` 加一个
   「这一代连接是我自己拆的」的标记（别只压日志）。
3. **T07 报告提的两处文档订正仍欠**：`资料/普查产出_1016战斗判据/T07_结算与胜负门判据.md:59,66` 与
   `回收_本会话判据_立账与订正.md:54` 还写着「原版 stage==60 会弹 `MatchAlreadyFinished`」（已被 T07 反证）。
   不在本批白名单，**转交主对话**。
4. **结算段的 `bye` 与「掉线」是两档**：`HandlePeerClosed`（`bye`，我们自己设计的协议）在结算段**有意保留出声**
   （§12③ 钉着）；`HandlePeerLost`（心跳超时/连接断）在结算段**静默**。两者判据不同、别合并
   —— 合并会让 §12③ 那条红（也会把「对面明确退出」这条真实信息吞掉）。
5. **`ReconnectCountdownExpired` 里「主机 = 对面掉线那一端」是按角色推的**（注释已标明是自拟）：
   主机自己网断时会把对面判负。已在本批注释里点明，**修不了的原因**与 §三·3 同一条。
