## §二 证据

### 2·1 260 / 320 到底是什么（本轮读到的最硬一条）

- `AbilityLogic@cardAbilities.abilityLogic.chosenAbility 260 = triggerEffectInCard`（`abilityLogic_枚举词典.tsv:47`）·
  `320 = followAfterResolution`（`:51`）。
- **260 的真身**（`d:/2/tools/decomp_full/AbilityLogic__PlayAbility.c:2534`，`0x104` 支）：新建一张表 →
  **逐个目标收进表**（`FUN_180002430` = `List.Add`）→ 走共同出口；消费点是 `param_1 + 0x80`。
  ⇒ 它是「**把目标逐个挂上后面那条效果/附魔**」的**包装**，不是一条独立效果。
  所以同一族里 **有的卡我们本来就覆盖**（ASH46 / GOF41 的 `repeat`、GOF56 的 `eachunitdeal`、
  SAU11 的 `reanimate`），**只有 TL49/TL50 的「候选池」是真缺口**。
- **TL49/TL50 的池子 = 6 张同族 `_enchantment` 卡**（`资料/普查产出_1018/allcards_1350/cards_raw.json`）：
  `m_Name` 直接是 `T6 Leviathan-Hyper-adaptation_enchantment1..6` /
  `T12 Leviathan-Infinite Biomorphologies_enchantment1..6`，逐张 buff：
  `armour 1` / `stealth + armour 1` / `melee +2` / `ranged +2` / `health +2` / `vanguard`。
  我们原来只有 3 项（用户 2026-09-13 给的），漏 `+2 Health` / `Stealth and +1 Armour` / `Vanguard`。

  （`+2 Melee, +2 Ranged or Armour 1`）—— 那是**另一张卡**的印刷解释，**不是 Spanner 的数据**。

### 2·4 Unstable 的 `conditionsFilter=220`（**E9 的读法是错的，就地订正**）

- `UnitConditions.dealtKillDmg = 220`（`dump.cs:20748`）——**枚举名骗人**。
- 真身：`FilterMethods__MeetsConditionCriteria.c:253-257`
  `if (param_2 == 0xdc) { bVar3 = CardScript__EnoughPendingDamageToDie(param_1); }`
- `CardScript__EnoughPendingDamageToDie.c`：`cardState == 5`（将死）⇒ 1；否则「血 ≤ 0 且 `CurrentSurvivor == 0`」⇒ 1；
  有待处理伤害时按 `EnoughPendingDamageToDieWithDamageValues` 判 ⇒ **= 「这条命已经救不回来」**。
- `excludeCondition = 1` ⇒ 随机目标池**排除已经注定要死的单位**。
- 我们的等价判据 = `RuleCore.EnoughPendingDamageToDie(u)`（`u.Health <= 0 && u.Survivor <= 0`，全仓唯一判死闸）。
  ⇒ **不需要给 `UnitState` 新建「本回合造成过击杀」的账**（E9 那条新账的前提本身就是错的）。
  唯一差异档 = 「血 ≤ 0 但带幸存者」：原版**算活着、可被选中**，原来的 `t.IsAlive` 把它排掉 —— 本轮改成
  `!EnoughPendingDamageToDie(t)` 之后两边一致。
