## 一、结论

### 1.1 `Rewards` / `Shop` 重开保留当前页 —— **做了**（与 `Collection` 同一条判据）

- 判据（原版反编译）：`GameWindowWithTabs__Open.c:9-21` —— **当前页签**（字段 `0x12`）非空就只重开那一页；
  只有它是**空**（= 新建实例）才走 `GetStartingTab()`（虚表 `0x218`，回落 = `tabs` 的 `FirstOrDefault` = 第一页）。
  `WindowTabBase__CloseTab.c` 只 `SetActive(false)`、`GameWindowWithTabs__Close` 也不写 `0x12`
  ⇒ **隐藏 → 被 `ShowPreviousWindow` 带回来**这一路原版**保留当前页**。
- 落地：两窗各加 `StartVisualIndex()`（`CurrentTab != None` ⇒ 点回同一页签；新实例才落第 0 页），
  `Open()` 里 `tabButtons.Click(0)` → `tabButtons.Click(StartVisualIndex())`。
  用 `Click(visualIndex)` 而不是 `ChangeTab`：左栏高亮读的是 `TabButtons.CurrentVisualIndex`。
- ⚠️ **为什么没有收口到 `GameWindowWithTabs`**：该文件不在本件白名单（N117 刚改完的那一批之外，
  按铁律 13·3 的文件所有权切块）⇒ 两份逐值复制的 `StartVisualIndex`，注释里互相点名「改一处必须同步另一处」。

### 1.2 `PromptPopup` / `DailyRewardPopup` 的压暗层 —— **补了命中区，但它是「吸收」不是「关窗」**

🔴 **这一条与派单的字面要求不同**（派单写「点击→关窗」），因为原版判据把那一半否掉了。逐条证据：

| 窗 | 原版 prefab 压暗层上的组件 | 原版点这一下 |
|---|---|---|
| `GenericPromptWindow`（= `PromptPopup`） | `RectTransform + CanvasRenderer + Image + **BackgroundCloseButton** + BackgroundOverDrawController`（`MonoBehaviour_627461394584887679.json`） | **什么都不发生**（见下 ①②） |
| `Daily Reward Popup`（= `DailyRewardPopup`） | `RectTransform + CanvasRenderer + Image`（`MonoBehaviour_6390879965494403023` = `Image`）—— **没有 `BackgroundCloseButton`** | **什么都不发生** |
| 对照组 `Daily Streak Popup` | 同上 + **`BackgroundCloseButton`**（`MonoBehaviour_1145929419749663403.json`） | 关窗（所以连登窗那颗 `ShadeHit` 本来就是对的） |

- ① `GenericPromptWindow` 那颗 `BackgroundCloseButton` 的 `window = {0,0}`、`onClick.m_Calls = []`
  （原始 JSON 实读）—— 光凭这一条**不足以判**（本仓已知不可靠，见 `资料/已知的坑.md` 第 15 条），所以补了第 ②条。
- ② **`PromptPopup` 类里没有任何 `backgroundCloseButton` 字段**（`dump.cs:87347-87368`），
  方法只有 `Open / InstantiateInput / InstantiateDropdown / SetError / SetMessage / OnSubmit / OnCancel / .ctor`
  —— **没有 `Start` / `OnEnable`**；`PromptPopup__Open.c` 逐句实读：只给 `okButton`(+0x78) / `cancelButton`(+0x80) 挂监听。
  `GameWindow` 基类也没有这类字段或接线（`dump.cs:108796-108900`）⇒ **没有任何一处在运行时给它接线**。
- ③ `DailyRewardPopup` 同理：类里没有该字段，`DailyRewardPopup__Start.c` 只给 `closeButton`（`0x90`，圆形 X 钮）挂监听。
- ④ 同族**既有先例**就是这么判的：`Shell/PopUpGameWindow.cs:26-32`（`MessagePopupWindow` 的两颗
  `BackgroundCloseButton` 同为 `window` 空 + `onClick` 空）⇒ 用 `MenuDraw.Absorb`，**明文写着「⛔ 不是 `ShadeHit`」**。

⇒ 两窗都接 **`MenuDraw.Absorb`**（吃射线、什么都不做；档由公共件算 = `qContentMin − 1`）：
- `PromptPopup`：`QShade 3140 < 3142（吸收层） < QContent 3143`；
- `DailyRewardPopup`：`QShade 3002 < 3009（吸收层） < QContent 3010`。

> ⚠️ **若要按派单的字面口径改成「点暗处关窗」**：把 `MenuDraw.Absorb(root, "AbsorbHit", …)` 换成
> `MenuDraw.ShadeHit(root, …, () => Close(), "BackgroundHit")` 即可（一行），但那**不符合上面这条原版判据**，
> 且会与 `Shell/PopUpGameWindow.cs` 的先例不一致。**本件没有这么做。**
