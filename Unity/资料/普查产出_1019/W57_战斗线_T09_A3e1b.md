### B. `CardChoicePanel` 卡钮实绘尺寸 254.6×77 → 原版 **199.24×77.47**

**判据链（逐文件现读，不是转抄任务书）**

1. `bundle_battlesharedresources_assets_all`：
   `GameObject/CardChooseCardButtonFrame.json` 的 `MonoBehaviour_7927933141705382700.selectButton`
   → **-5173003275250738388**（`EverguildButton`），同 GO 的
   `RectTransform_-9013717219094471892.json`：`m_SizeDelta = **1.086300015449524 × 0.42239999771118164**`
   （**卡本地单位**）、`m_LocalScale = (1,1,1)`、中心锚 + `m_Pivot = (.5,.5)`；
   同 GO 的 `MonoBehaviour_4178237357239393068.json`（`Image`）：**`m_PreserveAspect = 0`**、`m_RaycastTarget=1`、pad 0。
2. 换算尺 = `CardsHorizontalLayout.Scale = 183.41`：`CardsHorizontalLayout__get_Scale.c` 读 `+0x78`；
   `CardsHorizontalLayout__GetPosition.c` 的 `spacing = lossyScale.x × 字段 +0x80` —— 我们那张实测表
   `SpacingPx(n≤3) = 502.2` ⇒ `+0x80 = 2.74`、`2.74 × 183.41 = 502.5` ⇒ **这把尺就是 px / 卡本地单位**。
3. ⇒ 宽 `1.0863 × 183.41 = **199.2383**`、高 `0.4224 × 183.41 = **77.4724**`（px）。

**254.6 的来源（回答任务里的那一问）：是 `sprite` 尺寸，不是节点 rect。**
改前那句 `ImgByHeight(_panel, CardArt.Ui("UI_Button_Mulligan"), …, 77f, …)` 的语义是「**高 77、宽按贴图比例**」，
而 `UI_Button_Mulligan` 是 **410×124** ⇒ 宽 = `77 × 410/124 = **254.5968**` —— 那是**贴图的原始比例**。
原版那颗 `Image` 的 `m_PreserveAspect = 0`（拉伸铺满 rect），所以正确做法是**显式给宽高**。

| 量 | 改前 | 改后 | 差 |
|---|---|---|---|
| 宽（设计 px） | **254.5968** | **199.24**（原版 199.2383） | 改前宽了 **27.79%** |
| 高（设计 px） | **77** | **77.47**（原版 77.4724） | 改前矮了 **0.61%** |
| `Image.preserveAspect` | 0（`MakeImageInParent` 出厂值） | 0（原版同值） | 不变 |
| 纵向位置 | `CardRowCy + 323` | 同左 | 原版 `−1.759 × 183.41 = −322.618` ⇒ 我们多 0.38 px，**既有值未动** |

改法 = `ImgByHeight(..., 77f)` → `MakeImg(..., CardBtnW, CardBtnH, ...)`（`CardBtnW/CardBtnH` 两个常量带完整判据 doc）。
⚠️ 实绘与命中是**同一块**（`_cardBtns[i]` 既是画出来的件、又是 `ButtonIndexAt` 量 `Contains` 的那一件）⇒ 两边一起变，不分叉。

**卡钮的 sprite 名（未能逐字节证实，如实记）**：那颗 `Image` 的 `m_Sprite` = file 4 / pid **3819842738995756391**，
落在外层 bundle、**没解出 pathID→名 的索引**。间接证据：全库 **410×124 的按钮图只有 `UI_Button_Mulligan`
家族那三张**（`bundle_duplicateassetisolation_assets_all` + `sharedassets0`）⇒ 高度可能就是它。
⚠️ 但**尺寸结论不依赖这一条**：`PA=0` ⇒ 画出来就是节点 rect，与贴图是谁无关。

### C. 选中后 `interactable = false`（单向），不再是真 toggle

**判据（逐方法现读 `d:/2/tools/decomp_full/`）**

- `SelectCardButtonFrame__SelectButtonOnClick.c`：`ChooseCardMenu.SelectCard(card)` →
  `Card2DController.ToggleHighlight(1)` → **`UnityEngine.UI.Selectable.set_interactable(这颗钮, 0)`**
  ⇒ 选中之后**那颗钮自己**收不到第二次点击 ⇒ **再点同一张 = 什么都不发生**。
- `ChooseCardUI__ToggleSelected.c` / `SelectCardButtonFrame__ToggleSelected.c`：
  `ToggleHighlight(selected)`；`set_interactable(!selected)` ⇒ 换选另一张时把上一颗重新启用。
- `ChooseCardMenu__SelectCard.c`：存 id → `chooseButton`（父 `Continue Button`）`set_interactable(true)` →
  播放声音 → `foreach (card in allCards) if (card != selected) ChooseCardUI.ToggleSelected(false)`。

**改法**

| 件 | 改前 | 改后 |
|---|---|---|
| `TogglePick(i)`（`PickMode.Single`，唯一派生子类 `ChoosePanel` 用的档） | 真 toggle：再点已选那张 = **取消选中** | **单向**：`_picked.Contains(i)` ⇒ **直接 return**（什么都不做） |
| `TogglePick(i)`（`PickMode.Multi`） | toggle | **不动**（换牌那一族本来就能再点取消，而且 `MulliganPanel` 自己实现、不走本类） |
| 选中那颗钮的反馈 | 只是换图成 `UI_Button_Mulligan_Pressed`，悬停仍换 hover 图 | 再叠 `BattleButtonFx.SetDisabled(true)`（`Swap` 档显示 `_nt` ⇒ **画面仍是 Pressed 那张**，但**悬停/按下不再变化**）= 原版 `interactable = false` 的等价物；取消选中时 `SetDisabled(false)` |
| 换选另一张 | 旧的那张自动取消（`Single` 下 `RemoveAt(0)`） | **不变**（等价于原版 `foreach … ToggleSelected(false)`） |

**`TogglePick` 调用点（grep 现核，全仓）**

| 调用点 | 说明 | 受本次影响 |
|---|---|---|
| `Battle/CardChoicePanel.cs:925` `HandleClick` → `if (hit >= 0) TogglePick(hit)` | 手搓路：点中卡下那颗钮 | ✅ 单选变单向 |
| `Battle/CardChoicePanel.cs:929` `HandleClick` → 点卡本身（**我们加的**那条路） | 自检 `SimulateChoosePick` 走的就是这条（它喂的是**卡心**，`ButtonIndexAt` 永远不中） | ✅ 单选变单向（与钮那条同义） |
| 仓内其它 `.cs` | **0 处**（`grep -rn "TogglePick(" --include=*.cs` 只命中本文件两处 + doc） | —— |
| uGUI 事件 `CardButtonClicked` | 目前**没有订阅者**（合并配方在 A3e1 §三）；将来驱动订阅后调的就是本方法 ⇒ 同一套单向语义 | ✅ |

⚠️ 已核**没有自检依赖「再点一次取消」**：`Editor/BattleScene.cs` 里对面板的断言只有
`IsPicked(0)==true`（`:19405/:19464`）与 `SimulateChoosePick → SimulateChooseDone` 的流程，**没有**点两次取消的用例。
