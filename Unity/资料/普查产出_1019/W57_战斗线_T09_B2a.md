## 三、与 `Contains` 的语义差异（逐条）

| # | 差异 | 影响 / 处置 |
|---|---|---|
| 1 | **X/Y ±10° 倾摆不跟**（`BoxCollider2D` 只认 Z 旋转） | **原版同构**（`2DCard` 上那两颗 collider 同样限制）；实测差最大 ~2.6% 卡高。`AutoCardRotation` 只在**位移时**倾摆、停下 2 秒内回正 ⇒ 静止/批处理下两判据一致 |
| 2 | 卡根 `SetActive(false)` 后 `Physics2D` 不收它（`Contains` 仍 true） | 藏起来的卡本来就不该可点；现读**没有任何** CardView 根被 `SetActive(false)` 后仍要求命中的路径（`MulliganPanel` 只关钮/字/压暗层，不关卡） |
| 3 | collider 没建（`Build` 没跑过）⇒ `HitByCollider` **退回 `Contains` 并出声一次** | ⛔ 不静默；全仓 `CardView` 只有 `Create → Build` 一条出生路（`AddComponent<CardView>` 全仓 1 处，就在 `Create` 里）⇒ 正常路径永远走真 collider |
| 4 | `Physics2D.OverlapPoint` **无视 z**，会同时命中前后叠着的卡 | `Frontmost` 自己按 `z` 取最前（保留旧语义）；这是原版「射线返回第 0 项」的对应物 |
| 5 | 每卡一次 `OverlapPoint`（N 张手牌 = 每帧 N 次查询 + N 次 `SyncTransforms`，后者幂等） | 与旧实现「每卡一次 `Contains`」同阶；手牌 ≤ ~15 张。**若将来profiling 发现贵**，优化口 = 一次 `OverlapPoint` + `GetComponentInParent<CardView>()` 映射 —— 但那要改 `CardView`（B1 的白名单）或在这里自带 filter/buffer，本波按要求只用 `HitByCollider` |
