## §二 证据

### 2·1 `DeployFrom` —— 接口形状与三个发射点

**需求来源**：`B3_报告.md` §三·2（战斗线 → 引擎线的跨线接口）。原版那两条协程的行为**完全不同**，而引擎发出的 `Deploy` 事件今天**逐字相同** ⇒ 表现层分不出「要不要演手牌飞行」。

**原版判据（B3 已逐行读过，本笔复核了调用点数量）**：
- `BattleManager._ResolveCardAutoSummoned_d__511__MoveNext.c:104,122,187` —— **有**手牌飞行 + `moveCardIntoBattle` / `playMinionFromHand` 两条起飞 cue（= 我们的 `DeployFree(fromHand:true)`，卡面 `from your deck`，池里 2 张 `BL55` / `SW57`）；
- `BattleManager._ResolveSummonUnit_d__510__MoveNext.c` —— `MinionManager.SummonMinion` **直接插格位**，两个声音调用点 **0 个**（= `DeployFree` 默认档）。

**设计（与 B3 建议的两点差异，都是刻意的）**：
1. **`Unknown = 0` 是哨兵**，`HandPlayed = 1` 起排 —— B3 建议 `0 = PlayCard`。理由 = 本工程对新增字段默认值的既定纪律（先例：`ReplayStore.tutorialStage` / `botSeatPlus2`）：**CLR 默认值必须表示「没写」**，否则一个忘赋值的 `Deploy` 事件会**静默冒充「手牌打出」**。消费端读 `Unknown` ⇒ 按改前老行为处理。⚠️ **消费端以本枚举为准**（不是 B3 报告里的 0..3 数字）。
2. **`DoReanimate` 的残骸那一条支原来【一条 `Deploy` 都不发】**（`DoReanimate` 的 doc 说「走 `DeployFree`」只对**墓地退路**成立）⇒ 本笔**新加**了那条事件。理由：`EvtKind.Deploy` 的语义本来就是「单位落到格位上」，再造正是这件事；而 B3 的消费约定「再造 ⇒ 只响落地两条」没有事件就演不了。
   ⚠️ **只发事件、不发 `When deployed` 广播**（`BroadcastWhen(Deploy)` / `ResolveDeploy` 那两跳照旧不跑）—— 加广播会多触发一批卡面效果，是另一条账。

**三个发射点（本笔落点）**：
| 入口 | 写什么 | 文件:行 |
|---|---|---|
| `RuleCore.PlayCard`（手牌打出） | `HandPlayed` | `RuleCore.cs:2577` |
| `RuleCore.DeployFree`（默认档） | `fromHand ? AutoPlayFromHand : Summon` | `RuleCore.cs:3253-3255` |
| `EffectResolver.DoReanimate` 残骸支 | `Reanimate`（**新加事件**） | `EffectResolver.cs:8882` |
| `EffectResolver.DoReanimate` 墓地退路 | `DeployFree(..., deploySource: Reanimate)` | `EffectResolver.cs:8918` |

**兼容性**：
- 回放：`ReplayStore.ReplayRecord` 只存 **`actions`（`List<MsgAction>`）**，`BattleEvent` **不进 `.json`**（`ReplayStore.cs:73-205`）⇒ 加这一位**不需要 `version +1`**，旧录像照读。
- 其它事件种类：默认 `Unknown`，不受影响。
- 自检里手工合成的 `Deploy` 事件（`BattleScene.cs` 5 处）⇒ 读到 `Unknown` = 老行为。

### 2·2 `PlayAbility` 的 `100`（`createCardInHand`）—— E10 的「缺段」不成立

**① 枚举真值**（`d:/2/tools/il2cpp_out/dump.cs:20669`）：
```
public const AbilityEffect createCardInHand = 100;
public const AbilityEffect createCardInHandAndKeepEffects = 101;
```

**② 反编译方法体在**（`d:/2/tools/decomp_full/AbilityLogic__PlayAbility.c`）：E10 搜的是 `0x64`，而**反编译器把这一支打印成十进制 `100`**：
```
:986    if (iVar8 != 100) { return; }
:987-1050  ← 分支体（下面逐句解）
```
（`iVar8 = *(int *)(param_1 + 0x10)` = `AbilityLogic.chosenAbility`，`dump.cs:19456`。）

**③ DLL 字节扫描独立印证**（⛔ 不是只靠那一个 `.c`）：
- `dump.cs` 里 `AbilityLogic.PlayAbility` 的签名行 = **RVA `0x8163A0`**？⛔ **不是** —— 逐行核过：那一条是**上一个方法**（`DeepCopy` 一带）；`public void PlayAbility(…)` 前面那一行写的是 **`RVA 0x81C000 / Offset 0x81AA00`**。
- `d:/2/unity_run_ref/GameAssembly.dll` 从**文件偏移 `0x81AA00`** 起扫 0x6000 字节，`cmp eax, 100` 的各编码里**唯一命中**：
  **文件偏移 `0x81ACBA` = `83 F8 64`**（入口后 0x2BA 字节，正是 switch 派发区）
  ⇒ **发布版二进制里确实有这一支**（⛔ 不是「反编译产物幻觉」）。

**④ 分支语义（逐句）**：
1. `local_178` = 要造的**张数**：默认 `1`；来自 `multiplier`（`AbilityLogic+0x30`，TargetCriteria）的命中数 × `furtherMultiplier`（`+0x38`，`>0` 才乘）。特殊档 `0xd2(210)/0xdc(220)` 走「逐个目标累加 trait 值」。
2. 外层 `do { … } while (iVar8 < local_178)` ⇒ **重复 N 次**：`GetCardToSummon(summonCriteria=+0x58, abilityData, manager, possibleTargets=+0x78, 0)`。
3. 内层对返回的每个 `RawCardScript`：
   `BattleManager.AddNewCardToHand(manager, rawCard, abilityData.thisCard, isEnemySide, posX, posY, priority, 0, blockPlayerActions, 0)`
   → 把**新建的 `CardScript`** 加进 `AbilityLogic.abilityTargetsToSave`（`+0x80`）。
4. 收尾 `AbilityLogic.SetPreviousAbilityTargets(abilityTargetsToSave, 0)`（`LAB_18081cc87`）—— 供后续 ability 用 `previousAbilityTargets(140)` / `previousAbilityFiltered(150)` 取。

**⑤ 卡从哪来（`AbilityLogic__GetCardToSummon.c`）**：
- `AbilityLogic+0x28` = `targetCriteria`（不是 `summonCriteria`！）。
- `if (targetCriteria.selectFromChooseResolution == 0)`（`+0x80`）：
  - `summonCriteria.unitsToSummon`（`+0x18`，`RawCardScript[]`）非空 ⇒ 逐个加进去；
  - `unitsToSummon` **空** ⇒ 按 `summonCriteria.chooseCardInPlay`（`+0x29`）再分两支：`false` ⇒ **扫 `PlayerDataManager.fullCardCollection`**（按 criteria 筛）；`true` ⇒ `GetTargets(targetCriteria)` 取目标的 raw card。
- `else`（**`selectFromChooseResolution == 1`** —— Mekaniak 就是这一档）：
  - 取 `manager.cardChosenInSelection`（`BattleManager+0x2E8`，`dump.cs:30844`，**选择面板里玩家点中的那张**）→ 加进结果并**清空该字段**；
  - 没有选中卡 ⇒ 退 `poolChoosenCard[0].rawCard`（`+0x28`）。

**⑥ `targetsAffected = 180 = choiceResolution`**（`dump.cs:20777-20812`）：
- `AbilityLogic__GetTargets.c:89-160`：`targetsAffected == 0xb4(180)` ⇒ 扫 `PlayerDataManager.fullCardCollection`、用 `FilterMethods.CheckIfRawCardMeetsCriteria` 按 criteria 筛，把命中的 **raw card 灌进 `BattleManager.cardsTargetedInChosenResolution`（`+0x308`）**（= **选择面板的候选表**），然后返回**空**静态池。
- 玩家点选 → `BattleManager.ClickChosenCardDone` 写 `cardChosenInSelection`（`BattleManager__ClickChosenCardDone.c:22`；AI/联机那档 = `BattleManager__ChoiceOfCardEnemy.c:47`）。
- `selectFromChooseResolution == 1` 的另一处读点在 `GetTargets.c:1101`：标准候选池一个都没命中时，退回「只留与 `cardChosenInSelection` 同名的那一张」。

⇒ **合起来（对「Choose a <筛选> and put it in your hand」那一族是完整的）**：选择面板列出「你的收藏里符合 criteria 的卡」→ 玩家选一张 → 100 号分支把**那一张**（`cardChosenInSelection`）造进手牌。池内同族卡（`Lead From the Front` / `Throne of the Heretic` / `Webway Entrance` / `High Rune Priest` / `Legendary Commandant` / `Brood Prophet` / `Dimensional Corridor`）的**卡面文字与这条链逐张吻合**。

### 2·4 `A2143` 的新判据（`autoPlayFromHand`）

`chosenAbility = 250 (0xFA) = autoPlayFromHand` 的分支**也在同一份文件里**（E10/E9 没读到）：
`AbilityLogic__PlayAbility.c:2797-2818`（`default:` 支，`if (iVar8 != 0xfa) return;`）——
对 `possibleTargets`（`+0x78`）里的每个目标调
`BattleManager.AddAutoPlayFromHand(manager, target, priority, 0, abilityData.actingCard, blockPlayerActions)`。

`BattleManager__AddAutoPlayFromHand.c` 的**完整语义**：
- **闸**：`card.IsInHand()` 为假 **且** `card+0x228 (cardState) != 0x10(16)` ⇒ 只打一行 `LogWarning`（**不做**）；
- 否则 `new BattleAction(type = 0x2E(46), …, actingCard, blockPlayerActions)` → `AddAutoActionToQueue(priority)`。
⇒ 「从手牌自动打出」是一条**排队动作**（类型 `0x2E`），而 `DeployFrom` 的 `AutoPlayFromHand` 正对应它落地后那一条 `Deploy`。
⇒ `AM58`（抽 2 辆载具再打出）/ `GOF93`（敌方手牌挑一张部署再攻击）要落地，仍缺：**① choose 管线**（选哪张/从敌方手牌取）② `DeployFrom` 的 `enemyhand` 来源档。**本轮没做。**
