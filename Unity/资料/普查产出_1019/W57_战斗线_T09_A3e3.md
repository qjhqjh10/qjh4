## 三、没查清的部分 / 还欠什么（⛔ 不猜，给「还差什么」和接线配方）

### 3·1 没查清 / 没实跑

1. **uGUI 派发本身没实跑**（本波口径 = 只做不验）。`EventTrigger` 的五个 eventID 在
   `InputSystemUIInputModule` 下的实际派发（尤其 `Drag` 的阈值）**没有跑过**；留给验收波。
   ⚠️ 批处理没有输入设备，断言要像 A2 那样**手工构造 `BaseEventData` / 直接调处理器**或 `ExecuteEvents`。
2. **捕获区与别的 `OverHand` 子画布的压盖关系没实跑**：`SkillPanel` 子画布 order 0，
   当它与 `CardDisplayWindow` / `ChatPopupPanel` / `AlliancePanelWindow` 等**同时可见**时谁先收射线，
   取决于 `HudCanvas.SubCanvasRank` 的兄弟序。本波只保证**扇内**顺序（捕获区在 `_bg` 底下）。
3. **`AbilityBoxClick` cue 本地不存在**（`grep -rn AbilityBox` 全仓 0 命中；`SoundAssetCollection` 的
   `get_AbilityBoxClick` 资产也不在本地 91 个包里）⇒ **没接、也没猜近似音**。
4. **`TargetsAvailableText` 吞点击的净效果**：形状照原版（`rt=1`），但我们的世界侧那条路**不经过 EventSystem**
   ⇒ 松手仍会 `ClearSelection()`。原版点那一小条是「什么都不做」。**这是既有行为**（本波没改世界侧），如实记。
5. **`ChoosePanel` 的探针依赖基类 A3-e 那批口**（`UguiInputReadyForTest` / `DoneParentHitForTest` / …）。
   基类此刻**正被另一个代理改**（`git status` 里 `CardChoicePanel.cs` 有未提交改动）；若那批最终被回滚，
   本文件的 `#if UNITY_EDITOR` 段会编译不过 —— 需要与基类那一批**同发**。
6. **`ContinueText` 那颗 TMP（`rt=1`）我们没有对应件**：基类只建了 `BG`/圆钮/眼睛/透明父件 + 卡钮，
   底条上的「继续」文字是 `Label`（`raycastTarget=false`）。原版那一块是确认区的一部分（冒泡到父 `Button`），
   但我们这条文字的矩形**整块落在 `BG` 上**（`BG` 577.5×63.84 覆盖文字 372.86×43.62）⇒ 点它时射线落到 `BG`，
   **结果等价**。这是**推断**（几何包含关系算出来的），未实跑；断言时可拿 `EventSystem.RaycastAll` 在文字中心打一发验证。
