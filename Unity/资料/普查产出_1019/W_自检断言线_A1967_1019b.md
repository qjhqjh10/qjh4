## 一、结论

✅ **做完了（静态）**。简报里的两件事都落了：

1. **降噪（产品侧）**：
   - `Core/CardView.cs` 的 `StampQueue` **不再调用 `Renderer.material`**，改走 **`(源材质, 渲染队列)` 的静态共享缓存** `QueueMaterial`（赋给 `sharedMaterial`）。同一源材质 + 同一队列号只克隆一次；布局反复换号也**不会克隆出一条链**（用「每视图第一次盖章时的源材质」当键）。

### 2·1 `CardPresentation/Core/CardView.cs`

- `:1103-1111` `<para>` 重写：`SetQueue` 不再走 `.material`，改走 `(源材质, 队列)` 共享缓存；保留「**绝不写字体资产原件**」那条判据（2026-09-27 踩过）。
- `:1143-1181` `StampQueue(Renderer)` 重写 + doc：
  - 保留原守卫 `sharedMaterial.renderQueue == _queue ⇒ return`（值对了就一个字节都不写；默认 3000 时零克隆）。
  - 源材质 = **本视图内该渲染器第一次盖章时那份**（`_stampState`）；`cur != st.Assigned` 判「外部换了材质」（`SetFace` / `SetData` 换卡面/卡背）并重新取源。
  - 源材质本身就在目标队列（常见：悬停抬号后又落回 3000）⇒ **直接用回原件**（少一份克隆、TMP 文字层恢复合批）；否则 `mr.sharedMaterial = QueueMaterial(origin, _queue)` —— **不调用 `.material`**。
- `:1181-1229` 新增缓存：
  - `struct QueueMatKey { SrcId, Queue }`（`IEquatable`）· `sealed class QueueMatEntry { Origin, Clone }` · `static Dictionary<QueueMatKey, QueueMatEntry> _queueMats`。
  - `QueueMaterial(Material src, int q)`：键 = `(src.GetInstanceID(), q)`；命中时再校验 `hit.Origin == src`（防实例 ID 在旧对象销毁后被复用、静默拿到别人的贴图）；未命中 `new Material(src)` + `renderQueue = q`。
  - `QueueMatCap = 4096`：超过整表清空（下一张卡按需重建；行为与修复前逐次克隆等价，只是那一小段恢复不了合批）。
- **影响面（已写进 `StampQueue` 的 doc）**：**「每张卡一份材质」这个既有假设仍然成立** —— 卡面各层（`AddLayer` / 徽标 / 数值层 / 卡背 / 3D 体 / rim / shadow）的源材质都是 `new Material(...)` 的**私有副本** ⇒ 缓存出来的克隆**逐层唯一** ⇒ 下列逐卡写 `sharedMaterial` 的路径**一个都没改、也不会串卡**：
  `ApplyTint` · `ApplyShadowColor` · `SetBadgeGrey` · `SetBadgePlateInk` · `SetBadgeIconTexture` · `SyncStatLayers` · `UpdateBack` · `SetBodyArt` · `SetOutline`。
  真正被共享的只有 **TMP 文字层**（字体资产材质）—— 它们本来就不吃 `sharedMaterial` 的着色（TMP 走顶点色）。⚠️ 将来若新增「多张卡共用同一份源材质、又要被整卡着色」的层，那一路必须改走 `MaterialPropertyBlock`（注释里点明了）。
