**为什么前两轮写「值不在本地」**

`assets_full` 的导出对**根资产文件**不完整（这是本轮实测的导出缺口，不是搜索词问题）：

| 根文件 | 原始 MonoBehaviour 数 | `assets_full/<文件>/MonoBehaviour/*.json` |
|---|---|---|
| `resources.assets` | 616 | **0** |
| `sharedassets0.assets` | 188 | **6** |
| `level0` | 147 | 77 |
| `globalgamemanagers.assets` | 29 | 0 |

这些导出的 JSON 还是**无字段**的（只有 `m_GameObject/m_Enabled/m_Script/m_Name`）——因为原版 bundle/根资产**没有 type tree**。
所以「`rg _traitEffects assets_full` = 0 命中」「`rg m_PathID 1795` = 0 命中」都**不能证明资产不存在**。
上一轮的第二轮报告 §三把「搜过的根」写成 `assets_full`（24.7 万文件）——覆盖的是**包内**，根文件那 616/188 个 MonoBehaviour 实际上没被搜到。

**静态解析方法（可复现）**

MonoBehaviour 原始字节布局（无 type tree，Unity 6000 系列）：

```
m_GameObject:  int32 fileID + int64 pathID      (12 B)
m_Enabled:     byte                             (1 B)
align4
m_Script:      int32 fileID + int64 pathID      (12 B)
m_Name:        int32 len + bytes + align4
--- 之后按字段声明顺序 ---
```

`CardTrait` 序列化顺序（与 `CardTrait.cs` 声明一致）：
`_traitIcon` PPtr(12) → `_hasInPlayAnim`(4) → `_hasIcon`(4) → `_isInPlayIcon`(4) → `_stackable` int(4) → `_aIScore` float(4) → `customObject` AssetReference(3 个 string) → `_traitEffects` List。
`TraitEffect`：`name` string → `effectAnim` AssetReference → `overrideByArmies`（int 数 + 每项 `{army int, effectAnim}`）→ `TriggerType` int → `playIfWarlord` int。

自校验：73/73 个资产解析后 `offset == len(raw)`；`TraitsCollection` 2416/2416；`TraitsCombinationsList` 120/120。
`_traitIcon` 解析结果与本地 sprite 名逐一对上（例：Agenda→`Atlas_trait_icon_agenda`、Armour→`Atlas_trait_icon_armour`），可反证布局正确。
