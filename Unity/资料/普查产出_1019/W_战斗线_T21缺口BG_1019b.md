## 一、结论

### B. `TriggerEnchantment`（4 张 `Dark Pact of *`）—— **4 / 4 接上**

- **引擎**：`RuleCore.GrantDarkPact` 在记下契约（`_keywordsPact[u] = k`）之后**发一条按附魔卡的
  `EvtKind.Trigger`**：`CardId` = 四张 `Dark Pact of *` 之一的**卡名**、`Keyword` =
  `KeywordTable.TriggerEnchantment`（= 原版 `AbilityTrigger.TriggerEnchantment = 500`）、
  `Player/Slot` = **载体那一格**、`InstanceId` = 载体实例。
  判据（逐句）：`CardScript__AddEffect.c:776-792`（case 8）→ `Enchantments.GetMarkOfChaos(...)`
  → `RawCardScript__TriggerEnchantment.c:7-13`：`TriggerAbilities(附魔卡, 0)` + `TriggerAbilities(附魔卡, 500)`。
  ⚠️ 触发的是**附魔卡自己的 `cardAnimations[]`**（`Buff_MarkOf*`），不是载体单位那条 ⇒ `CardId` 必须写附魔卡名。
- **表现**：`VfxMap.ResolveAllTimed` 的 `Trigger` 档新增「按原版 trigger 名归口」（见 G 的同一段实现）——
  四张契约的动画行在 `ability` 桶里（`tg = 500 / tn = TriggerEnchantment`），现在能解析出来。
- **现读数据模拟**（`Resources/card_vfx_by_card.json` + `RulesEngine/Resources/cards_engine.json`，2026-10-19 18:57 版）：
  4/4 都能解析到自己的 `Buff_MarkOf*`（Tzeentch / Khorne / Slaanesh / Nurgle）。

### G. `Ambush`（16 行 / 11 卡）—— 消费侧 **10 / 11 卡**接上；另 1 卡 + 4 卡各有一个**上游依赖**

| 口径 | 数字 |
|---|---|
| 运行时表里带 `tn = Ambush` 动画的卡 | **11 张** |
| 本次**能解析到 `trigger` 档**的卡 | **10 张**（`GSC32` `GSC9` `GSC5` `GSC28` `GSC37` `GSC69` `GSC15` `GSC11` `GSC7` `GSC25`；`ability` 桶 **10 行 / 14 候选**） |
| 无关键词时**拒绝推断**的卡 | **1 张**（`GSC16 Acolyte Heavy`：同一张卡混着 `Ambush` + `Strike` 两种 trigger 动画）→ 需要 `e.Keyword`，见 §三·1 |
| 引擎侧**结构上不会面朝下**的卡 | **4 张**（`GSC15` `GSC11` `GSC7` `GSC25`：原版 SO 有 `ambush` trait + trigger 670，但**卡面正文没有 `Ambush:` 段** ⇒ 我们 `PlaysFaceDown` 不放行、`EvtKind.Trigger` 不会发）→ 见 §三·2 |
| **今天运行时真的能播出来的** | **6 张**（`GSC32` `GSC9` `GSC5` `GSC28` `GSC37` `GSC69`，10 个候选） |

- 归口的判据 = `CardDef.CardAnimTime.TriggerName`（E12 落的逐候选 `tn`，来自 `cardAnimations[]` 外层
  `CardAbility.trigger`）—— 只有它能分清「这一行是 Ambush 还是 Strike」。
- 顺带修掉一处**既有乱播**：`GSC28` / `GSC32` / `GSC37` 的 `trigger` 桶里有 3 条 `inferred-keyword` 行
  （`ConcussiveTraitTrigger` / `ArmourTraitStart` / `TalentTraitTrigger`，这几个关键词在我们引擎里
  **根本不触发**，报告 §3·2）—— 归口生效后它们**不再在伏击那一拍乱播**。
- ⛔ **没有放开别的 trigger**：`VfxMap.IsRoutedTriggerName` 只放行 `Ambush` / `TriggerEnchantment` 两条；
  `Strike` / `Slay` / `Mob` / `Regiment` … 全部照旧（`trigger` 桶怎么播就怎么播）。

## 三、没查清 / 没做（含**接口需求**）

1. 🔴 **接口需求（`BattleDriver.cs` —— T11 在改，本批没碰）**：把 `e.Keyword` 交进表现层，才能接上
   `GSC16`（以及以后任何「同一张卡混多种 trigger 动画」的卡）。
   - `FireEventAll` 两个重载各加一个可选参数 `string keyword = null`，转发给
     `VfxMap.ResolveAllTimed(..., keyword)`；
   - `PlaySignal` 里三处 `FireEventAll(...)`（HUD 锚点那条 / 单点那条 / 多点那条）传 `keyword: e.Keyword`。
   - 预期效果：`GSC16` 伏击时只播 `Buff_GSC` + `Buff_Red`、Strike 时只播 `CreateCard Sabotage`；
     其余 trigger 名仍不动（`IsRoutedTriggerName` 只放行 Ambush / TriggerEnchantment）。
   - ⚠️ 接的时候**别顺手把 allowlist 扩成全量**：报告 §五·6 的「多播」就是那么来的。
2. **4 张「无 `Ambush:` 正文」的卡**（`GSC15` `GSC11` `GSC7` `GSC25`）：原版 SO 现读
   （`资料/普查产出_1018/allcards_1350/cards_raw.json`）**有 `ambush` trait、也有
   `cardAbilities[].trigger = 670`（`abilityLogic` 1 条）**；是我们 `RuleCore.PlaysFaceDown`
   要求「`ambush` 关键词 **且** `TriggerOps(Ambush) != null`」⇒ 这 4 张**不会面朝下打出** ⇒
   翻开那一拍根本不存在 ⇒ 动画结构上播不出来。
   - **没做**：`PlaysFaceDown` 是**全工程唯一判别式**、三个消费者，改它 = 改 4 张卡的**玩法**
     （是否面朝下/能否被打），超出「附魔/Ambush 事件发射」这一格 ⇒ 留给引擎线拍板。
   - 要做的话是**两处一起**：① `PlaysFaceDown` 改回「只看 ambush trait」；② `RevealAmbush` 对
     `TriggerOps(Ambush) == null` 的卡也补发一条 `EvtKind.Trigger`（否则 `FireTriggerAt` 的
     「没正文 = 不触发」早退会把事件吃掉，动画仍然没有事件可挂）。
3. **敌方载体那一路（1 张卡）**：`Litany of Despair` 的 Backlash —— `Give a Dark Pact to a random enemy troop`
   ⇒ 载体阵营 ≠ BlackLegion，而表现层 `AnimTimesOf(cardId, faction)` 按**载体阵营**查卡 ⇒ 拿不到
   `Dark Pact of *` 的 `AnimTimes` ⇒ 归口推断落空（那一拍不播）。根因在 `BattleDriver.AnimTimesOf`
   的 faction 过滤（不在本批白名单）。建议修法：`Trigger` 事件的 `times` 按**卡名不分阵营**查，
   或让事件带「卡自己的阵营」。**没进游戏核，仅静态推演。**
4. **静态 vs 实况**：本批全部是「静态可解析性 + 数据模拟」，**没有进游戏、没有跑一局**。
   `GrantDarkPact` 的四个种类在真机上是否稳定走「选中那张」那条路，沿用 `A1960` 的结论（未重核）。
5. **`GSC16` 的既有乱播**：keyword 接口接上之前，它伏击那一拍仍会播 `trigger` 桶的
   `CreateCard Sabotage`（`Strike` 那张动画）—— 这是**改前就存在**的行为，本批没有加宽也没有消除。

## 四、顺手发现

1. 🔴 **W 报告 §一「引擎真的会发 Trigger 的 17 张」口径偏乐观**：光有 `ambush` 关键词/trait **不等于**会发事件
   —— `RuleCore.PlaysFaceDown` 还要求 `TriggerOps(Ambush) != null`。11 张 Ambush 卡里
   **4 张今天结构上不会面朝下**（见 §三·2）。以后统计「引擎会发的」要按这个判别式算，别只按关键词。
2. 🔴 **按 prefab 名做 trigger 归口会张冠李戴**（本批踩到的坑，已写进 `TriggerNameOf` 的注释）：
   `GSC32` 的 `ArmourEffect` **在两个桶里同名** —— `trigger` 桶那条是 `inferred`（`A = ArmourTraitStart`），
   `ability` 桶那条才是权威（`A = GainArmourEffect`）。如果分类器在 `A` 查不到时退回 `N`，
   就会把推断行错标成 Ambush 候选、**同一件播两遍**。
   ⇒ 规则：**`A` 非空就只认 `A`**；`A` 为空（顶层字段/推断档）才按 `N`。
3. **数据侧若将来要彻底归口**：`工具/gen_card_vfx_by_card.py` 的 `TRIGGER_EVENT` 只有「事件」维度，
   没有「trigger 名」维度（同一卡的同一个粗桶里混着多个 trigger）。彻底做法 = 生成器按
   `(卡, trigger 名)` 分组写行（或给 `es[]` 加 `tg` 列）；本批**没有动生成器**（不在文件所有权内），
   消费端靠 `CardAnimTime.TriggerName` 完成归口。
