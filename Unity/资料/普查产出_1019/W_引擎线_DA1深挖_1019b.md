## 一、结论

**判定：隐藏能力（真实机制），不是数据残留。**

1. **原版真的会用。** 触发链的每一环都有方法体实现，且挂在**普通对局**的通用路径上（不是战役/教程专用）：
   拿任务点（任意卡牌的 `ManaBuff.questPoints`）→ 累计满阈值 → 对**玩家督军卡**发 `QuestTriggered`(=490) →
   该督军的 `createCardInDeck`(=270) → 从**固定 5 张黑暗天使隐秘**里随机 1 张塞进牌库。
2. **玩家看得到规则，只是不在督军卡面上。** 督军卡面/官方 `Card_Description/DA1` 只写 Agenda + Talent；
   但任务进度 HUD 的 tooltip（官方本地化 `Tips/Hud/PlayerQPCount`）明写
   「Your Quest Progress, **add a Secret to your deck for each 3 Quest Progress earned**」，
   特质词条 `CardTraitDescription/questPoints` 也是同一句。所以这是**黑暗天使阵营的公开机制**，
   只是实现上挂在督军的一张隐藏能力卡数据里。
3. **同一条能力在 4 张黑暗天使督军上重复出现**（DA1/DA2/DA3/DA75），内容逐字段相同；
   这正是「阵营机制」而不是「某张卡的残留」的形态特征。
4. **主对话简报里「本地没有任何落地实现」需要就地订正（铁律 5）**：
   - 代码里确实**没有** `QuestTriggered` / `createCardInDeck` 这两个符号（全 `Assets/` grep 0 命中）；
   - 但**规则结果层已经实现**：`EffectResolver.QuestPointThreshold` 每满 3 点任务就往牌库加 1 张隐秘
     （`RuleEngine/Core/EffectResolver.cs:7793-7822`），原型是 2026-09-13 第三十三轮照规则书做的。
   - 因此不是「从零实现」，而是「已有通用规则实现 + 4 处与原版不一致的细节」（见 §四）。
5. **判不出的那一小块**：`GameplayVariablesData.alternativeTraitLogic`（决定阈值取 3 还是 4）的**实例值在服务器**，
   本地 `assets_full` / `解包整理` / `d:/4` 全盘 0 命中（旧记录也写明「值在服务器」）。
   本地能拿到的是 `ScenarioVariables` 的两档值：`questPointsForTrigger = 3`、`questPointsForTriggerAlt = 4`。
   ⇒ 经典对局到底走 3 还是 4，**本地判不出**；但两档都指向同一个机制。

### 2.3 原版调用链（逐跳，全部有方法体）

1. **拿任务点**：`BattleManager.ProcessManaBuff` 在 `ManaBuff.questPoints(+0x1D)` 为真时调

     `PlayerManager__AddQuestPoints.c:33 / :40`；字段偏移见 `d:/2/tools/il2cpp_out/dump.cs:119944-119945` 与 `:130190`。

6. **从 5 张里随机 1 张**：`AbilityLogic.GetCardToSummon` 在 `summonAllTargets == 0` 时

7. **真正入牌库 + 隐秘广播**：`BattleManager._ResolveCreateDeckCard`
   → `BattleManager.AddCardInPlayToDeck`（`BattleManager._ResolveCreateDeckCard_d__513__MoveNext.c:111`）；
   随后读 `spellType`，等于 `0x96(150)` 就 `BroadcastSecretCreated`（同文件 `:113-119`）。
8. **入牌库的位置**：`BattleManager.AddCardInPlayToDeck` 用
   `GetRandomInt(0, deck.Count + 1)` 作为插入下标，再 `List.Insert` ——
   `BattleManager__AddCardInPlayToDeck.c:37` 与 `:64`。
   **原版不是「追加后洗整副牌」，而是「随机位置插入」**（规则书那句「并洗牌」是粉丝实体版的改写）。

## 四、最小实现方案（若要做）

> 前置判断：按铁律 11，这条「原版真的用」⇒ **要做**；但**不需要从零写**。
> 现有 `EffectResolver.QuestPointThreshold` 已经覆盖主结果，下面只补与原版不一致的 4 处 + 1 处健壮性。

### 4.1 必须补的差异（按影响排序）

1. **任务点 HUD/计数器语义（可见差异）**
   - 原版：达到阈值时**先减掉一个阈值**（`PlayerManager__AddQuestPoints.c:101-104`），
     延迟更新时读的是**减完后的值**（`PlayerManager._SetQuestPointsWithDelay_d__43__MoveNext.c:65,76`）
     ⇒ HUD 显示的是**余数**（0..2）/3。
   - 我们：`QuestPoints` 只增不减（`EffectResolver.cs:7740`），HUD 直接显示累计值（`BattleDriver.cs:20180-20181`）
     ⇒ 会显示 `3/3`、`4/3`、`5/3`。
   - 最小改法：在 `QuestPointThreshold` 触发时 `ps.QuestPoints -= QuestPointStep * times`（与 `QuestMilestone` 同步重算），
     HUD 不用改公式。或只改 HUD 为 `QuestPoints % 3` —— 但前者更贴原版（内部值也一致）。
2. **造出隐秘时没有广播 `CreatesSecret`（行为差异）**
   - 原版：`_ResolveCreateDeckCard` 读 `spellType == 0x96(150)` 后 `BroadcastSecretCreated`（同文件 `:113-119`）。
   - 我们：只有 `DoCreate` 的手牌分支在造隐秘/破坏时广播（`EffectResolver.cs:2866`）；
     `QuestPointThreshold` 走 `ps.Deck.Add` 直插（`:7816`），**没有广播**。
   - 影响卡（池内现读）：`DA15 Ravenwing Champion`「When you create a Secret, deal 3 damage to a random enemy」、
     `DA66 Ballistus Dreadnought`「When you create or play a Secret, deal 2-4 damage to all enemies」。
   - 最小改法：在 `ps.Deck.Add(...)` 之后照抄 `:2866` 的写法
     `BroadcastWhen(ctx, WhenEventKind.CreatesSecret, owner, card, null);`
     （`BroadcastWhen` 签名见 `EffectResolver.cs:6289`；归属传 `owner` 施放者，不是收牌方）。
3. **入牌库方式（分布差异，低影响）**
   - 原版：随机下标 `Insert`（`BattleManager__AddCardInPlayToDeck.c:37,64`），**不重排已有牌序**。
   - 我们：`Deck.Add` + 整副 `Shuffle`（`EffectResolver.cs:7816,7819`）。
   - 最小改法：`ps.Deck.Insert(ctx.Rng.Next(ps.Deck.Count + 1), ctx.NewInstance(card));`，删掉那次 `Shuffle`。
   - 注：规则书（粉丝实体版）写「并洗牌」，与反编译不一致 —— **按铁律 2/11 取反编译**。
4. **阈值来源（低影响，当前值一致）**
   - 原版：`ScenarioVariables.questPointsForTrigger`（默认 3）/ `...Alt`（4），由 `GameplayVariablesData.alternativeTraitLogic` 选。
   - 我们：常量 3（`EffectResolver.cs:7784`）。
   - 最小改法：若我们后续有 ScenarioVariables 等价物（目前引擎没有），把常量换成变量；否则保留常量并在注释里写清
     「只覆盖 alternativeTraitLogic = false 的 3 点档」。**别为了这条先造一套 ScenarioVariables。**

### 4.2 健壮性（可选，但建议）

5. **触发条件应收在「督军是否带这条能力」上**
   - 原版只在**督军的 RawCardScript** 上发 `QuestTriggered`；非黑暗天使督军没有这条能力 ⇒ 拿任务点也什么都不发生。
   - 我们是「加任务点就尝试造隐秘」。当前池里只有 DarkAngels 会拿任务点，所以**实际等价**；
     但若将来把 SW3 那条 activeAbility 文本化，我们会给 SpaceWolves 报一条造不出的错。
   - 最小改法：`QuestPointThreshold` 入口加一句 `if (faction != "DarkAngels") return;`
     （或更好：在 `CardDef` 的督军能力上记一个 `HasQuestTrigger`，但那要动卡数据管线，成本高）。
6. **一次加多点的多次触发**
   - 原版每次 `AddQuestPoints` **最多触发一次**；我们 `times = gained - milestone` 会连发。
   - 当前卡最多一次给 3 点、余数 < 3 ⇒ 实际最多跨 1 次，等价。若将来出现「一次给 6 点」的卡，再按原版改成一次。

### 4.3 要动的文件（最小集）

| 文件 | 改什么 |
|---|---|
| `Unity/MyGame/Assets/RuleEngine/Core/EffectResolver.cs` | `QuestPointThreshold`：减阈值、广播 `CreatesSecret`、随机 Insert（替换 Add+Shuffle）、可选阵营门 |
| `Unity/MyGame/Assets/RuleEngine/Core/PlayerState.cs` | 只改注释（`QuestPoints` 语义从「累计」改成「余数」） |
| `Unity/MyGame/Assets/CardPresentation/Battle/BattleDriver.cs` | 若走「减阈值」方案，HUD 公式不用动；走「只改显示」方案则改 `:20180-20181` |

不需要动 Unity 批处理；改完跑秒级类型检查即可（铁律 12）。

### 4.4 「不做」的判据（写清楚，供主对话裁决用）

本条的**唯一**可写「不做」的理由只能是「原版本身就没有」——但本轮已证明原版**有**（方法体 + SO + 官方 tooltip 三方一致）。
所以**不能**按「影响小/成本高」不做（铁律 11）。
如果主对话决定**暂缓**，应写成「排队，先做哪些」，而不是「不做」。
