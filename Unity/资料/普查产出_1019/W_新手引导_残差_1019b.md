### 2. `EnterLevelUpCard` —— ⛔ **等数据：活动卡是服务端数据，保持空态 + 出声**

**结论**：原版 `EnterLevelUpCard`（`MainTutorialManager__EnterLevelUpCard.c`）取
`LiveOpsManager.GetHandler<GameModes>() → GetActiveEvent<...>() → (CardTier>0 的那张)` →

### 3. `LevelUpButton` —— ✅ **条件已核、修了一处；另发现：原版这个 GameObject 名在本 build 也不存在**

**(a) 原版条件（实读）**：`AddPointer(10)` **只在** `EnterLevelUpCard` 里、紧跟在
`CardDisplayWindow.ShowCard(...)` 之后 ⇒ **只在卡窗刚被打开时可指**。
`EnterLevelUpCard` 的调用点只有 `ChangedWindowState` 的两支：
`CampaignRewardsWindow && state==4`、`MainMenuWindow && state==4`。

**(b) 我们的条件（改前 → 改后）**：
- 改前：`top as CardDetailPopup` 非空就返回 `UpgradeHit`。
- 改后：`cd != null && cd.IsOpen()`（`CurrentState == Open`）。
- **为什么必须加**：`GameWindow.Hide()` / `ToBackground()` 只改 `CurrentState` 与激活态，
  `CardDetailPopup.UpgradeHit` 的取法是 `GetComponentsInChildren<Transform>(true)`（**含未激活子件**）
  ⇒ 只判 `top as` 时，一扇「被藏起来但仍是 `currentWindow`」的详情窗也会被指到（静默画到空气/别处）。
  现在 `CurrentState` 不是 `Open` 就不可指。
- **保留的差异（如实标注）**：原版 `GameObject.Find` 是**全场景**搜索（被别的窗盖住也找得到）；
  我们额外要求它是**顶窗**。这是**有意更严**（被盖住时不该把手指画到别人身上），
  且原版这一指只在「刚打开卡窗」那一刻入队 ⇒ 正常路径下两者不会分叉。

**(c) 实读补充**：本 build 全量解包 `"m_Name": "LevelUpButton"` **0 命中** —— 原版卡窗里那颗升级钮的实名是
`Card Displayer Menu For Menu ▸ Card Options Panel ▸ Panel ▸ Upgrade Panel ▸ Content ▸ Upgrade`
（该 GameObject 树逐级实读；`Card Displayer Menu For Menu` = `CardDisplayWindow`，主菜单场景 MB `2033`）。
⇒ 原版这一指在本 build 里**也是死目标**（`GameObject.Find("LevelUpButton")` 找不到 → `LogError`）；
我们的 `CardDetailPopup.UpgradeHit` 是**按语义**对应的等价物（不是按名字）。

### 4. `returnedToPlay` —— ✅ **原版死字段；我们同样只写不读**

**原版判据**：全量反编译里对 `param_1 + 0x75` 的引用**只有 1 处**：
`MainTutorialManager__ChangedWindowState.c:111` = `*(undefined1 *)(param_1 + 0x75) = 1;`
（`MainMenuWindow` 且 `GetState()==CollectedCampaignFirstNode(4)` 那一支）。
`GetState` 读的是 **+0x74**（`selectedArmy`），不是 +0x75 ⇒ **0 个读点**。
⇒ **原版死字段**（写进去没人消费）。

**我们**：`_returnedToPlay` 同样只有 3 个非注释出现 = 声明 / 复位 / 写 1，**没有读点**。
已补一条**源码级断言**（读 `MenuTutorialManager.cs`，去注释后数出现次数 = 3）——
以后任何人加一个 `if (_returnedToPlay)` 都会让它变 4+ ⇒ 自检红。
