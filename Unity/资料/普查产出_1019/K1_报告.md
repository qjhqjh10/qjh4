## 二、`A2140` —— 两张卡少一枚信仰图标（**已修，显示层**）

### 2·1 做了什么

在 `CardIcons.Rewrite` 的**自造记号那一层之前**加了一条**句法规则**（官方记号仍先分流，互不干扰）：

```
英文： /[0-9]\s*Energy(?=\s*:)/      →  数字 + 空格 + 〔faith〕
中文： /[0-9]\s*能量(?=\s*[：:])/     →  数字 + 空格 + 〔faith〕
```

- 只把**词**换成图标，**数字与空白逐字保留**（`MatchEvaluator`，不走 `$` 替换串）。
- 输出形状与计划表里 `☀ → faith` 那一支完全一致：`<link=faith><sprite name="faith"></link>`。
- **幂等**：替换后词没了 ⇒ 第二遍 `IsMatch` 为 false（断言②钉住）。
- **`desc` / `descZh` 一个字节没动**（只改渲染出来的串）。

## 四、`A2138` —— 画框基准：alpha 块 vs sprite rect（**静态准备完成，未改几何**）

### 4·1 结论（一句话）

**原版画的是 sprite rect，不是 alpha 块；判据不只「倾向」，现在是三条硬证。**
改法 = `FrameUv` 对卡框返回 **(171,11,682,998)/1024 的 rect**（透明留白参与），
所有由它换算的落点（三围/宝石/费用/命中/烘图）自动跟着回位；**费用横向那一条公式要重写**。

### 4·2 三条硬证（比上一轮的「sprite rect vs alpha」更硬）

1. **原版 prefab 的 Image 字段**：`2DCard/CardFrame` 的 uGUI `Image`
   `m_Type = 0`（Simple）· `m_PreserveAspect = 0` · **`m_UseSpriteMesh = 1`**。
   ⇒ 走的是 `Image.GenerateSprite`（不是 quad）——本地 UGUI 源码
   `Library/PackageCache/com.unity.ugui@27635d171b1a/Runtime/UGUI/UI/Core/Image.cs:1090-1123`：
   ```
   spriteSize      = activeSprite.rect.size          // 682 × 998
   drawingSize     = RectTransform 的像素矩形        // 2.2452 × 3.2572（prefab 实读）
   vh.AddVert(vertices[i] / spriteBounds × drawingSize …)
   ```
   ⇒ **tight mesh（只覆盖内容像素）× `RT / rect`**；透明留白**不画**，内容按 **rect** 缩放。
2. **卡框 sprite 的 `m_Rect` 全是 (171,11,682,998)**：
   `frames_resolved.json` 的 52 行里 **96 个已解析槽位**（12 军 × 4 档 × troop/stratagem；
   另一个 `army=120` 的 8 个槽位是 `UNRESOLVED`）**全为 (171,11,682,998)**；
   全盘扫到的 **88 份** `Orc Frame*.json`（`bundle_*cardassets_assets_all/Sprite/`）**`m_Rect` 变体 = 0 个**；
   `m_RD.textureRect` 逐帧不同（≈我们的 alpha 块，614.9×929.85 … 680.9×931.9）。
   ⇒ 上一轮把 `m_Rect` 和 `textureRect` 混为一谈的说法**要订正一半**：
   **缩放基准是 `m_Rect`（682×998）没错，但内容只占 `textureRect` 那一块** ——
   两者合起来的等价做法就是「把 rect 拉满、留白照常透明」。
3. **交叉验证（新，最强）**：把凹槽像素按 **rect 映射**换算到卡面，
   与 prefab 里**独立存在**的容器常量对比（`CardView.cs:243-247`）：
   | 凹槽（贴图像素） | rect 映射（0..1） | prefab 容器常量 | Δ |
   |---|---|---|---|
   | 近战 (257.5, 862.5) | (0.0996, 0.8553) | (0.1005, 0.8572) | (−0.0009, −0.0019) |
   | 远程 (335.0, 929.5) | (0.2216, 0.9210) | (0.2157, 0.9203) | (+0.0059, +0.0007) |
   | 生命 (734.0, 916.0) | (0.8492, 0.9077) | (0.8536, 0.9083) | (−0.0044, −0.0006) |
   | 宝石 (511.0, 950.0) | (0.4984, 0.9411) | (0.5000, 0.9393) | (−0.0016, +0.0017) |

   **而且 rect 映射对 104 个卡框给出的是同一组坐标**（rect 恒定）——
   这正是原版敢用「固定容器常量」的原因。
   反过来，**我们现在的 alpha 映射**让同一个凹槽落到
   近战 x **0.022…0.133**（跨 **11% 卡宽**）、宝石 x **0.465…0.521** ——
   所以 `FaceStatAt01` 才必须逐帧反算（那是**在补偿错误的画框映射**）。

### 5·1 `A1492` —— 宝石尺寸判据**已定**（本轮不改数值）

⇒ **目标值 = prefab 绝对值 `RarityGemW/H = 0.25796 × 0.23345`**，**与画框映射无关**
