## 一、结论

### 1·1 `A2138` —— 卡框画的是 **sprite rect `m_Rect`（171,11,682,998）**，不是 alpha bbox

**原版机制（一手）**：`2DCard/CardFrame` 的 uGUI `Image` 是
`m_Type=0`(Simple) · `m_PreserveAspect=0` · **`m_UseSpriteMesh=1`** ⇒ 走 `Image.GenerateSprite`
（`Library/PackageCache/com.unity.ugui@27635d171b1a/Runtime/UGUI/UI/Core/Image.cs:1087-1122`）：

```
spriteSize      = activeSprite.rect.size          // 682 × 998
drawingSize     = RectTransform 的像素矩形        // 2.2452 × 3.2572
spriteBoundSize = activeSprite.bounds.size
vh.AddVert(vertices[i] / spriteBoundSize × drawingSize − drawOffset)
```

⇒ **整块 sprite rect（含四周透明留白）被拉进固定矩形**；不透明内容（`textureRect`，逐帧 614.9×929.85 … 680.9×931.9）
只是 rect 里面按 `textureRectOffset` **偏置**的一块。我们原来把 **alpha bbox** 拉满矩形 ⇒ 可见内容平均大
**7.7% 宽 / 6.1% 高**（逐帧表 `K1_A2138_逐帧映射差.tsv`）。

**这条不只靠读源码 —— 用用户实拍反证过**（`C:\Users\qjh36\Desktop\warpforge参考图\战斗—替换手卡参考图（后手）.png`，
4 张泰伦卡逐像素量，卡宽 277 px）：

| 判据 | m_Rect 模型预测 | alpha-bbox 模型预测 | **实拍实测** |
|---|---|---|---|
| 近战数字中心 − 凹槽圆心 dx | **0.0 px** | +11.3 px | **−1.5 px** |
| 远程数字中心 − 凹槽圆心 dx | **−1.7 px** | +8.0 px | **−1.0 px** |
| 生命数字中心 − 凹槽圆心 dx | **+0.9 px** | +2.7 px | **+0.5 px** |

（原版三个数值框是 **prefab 固定容器**、与阵营/档位无关；凹槽是**画在卡框贴图里**、像素位置逐帧恒定
⇒ 只有「按 m_Rect 映射」才能让两者在**所有**卡框上同时对齐。alpha 模型会把数字推出圆 ~8–11 px。）
旁证：4 张卡的可见外接 **aspect 0.690**（0.694/0.693/0.688/0.685）vs `CardFrame` 矩形 2.2452/3.2572 = **0.6893**；
alpha 模型没有固定预测、rect 模型对 `frame_leviathan_tier1` 预测 0.684（差 0.9%，在紫色描边辉光造成的量测偏大内）。

**y 的原点 = 贴图底边**（Unity `Sprite.rect` 约定）⇒ `vMin = 11/1024`、`vMax = 1009/1024`。
反证：`textureRectOffset.y = 18.08 = textureRect.y(29.08) − 11`（同一坐标系）；若把 11 当顶边，
alpha 内容会溢出 `textureRect` 36 px —— 不成立。⚠️ K1 报告里 `1-(11+998-0.5)/H` 是按顶边写的，**整体偏 4.5 px**，本轮没照抄。

**落地后的数值**（`FrameUv` 对 `frame_*` 1024² 返回 `Rect(171/1024, 11/1024, 682/1024, 998/1024)` = `(0.166992, 0.010742, 0.666016, 0.974609)`）：

- `FaceStatAt01`（跟着凹槽走）自动回到 prefab 常量附近（卡单位）：
  **melee −0.8362**（prefab −0.836）· **ranged −0.5811**（−0.595）· **health 0.7325**（0.740）；
- `FaceGemAt01`：宝石凹槽落到 **(−0.0016, −1.4547)**（K1 的复算值逐位复现）。
- 🔴 **费用（主对话 2026-10-19 裁定 → §五）：回到 prefab 固定容器 `(0.788, 0.666)`**，**与卡框贴图无关**。
  W27 的「逐帧贴 alpha 右缘 / 徽记下缘」连同它的 `gapUnit 0.0620` 那套**作废**
  （作废前它算出的 `cx` 域 = 0.7477…0.9057 —— 逐帧差 0.16 卡单位 = 7% 卡宽）。

### 1·2 `A1492` —— 稀有度宝石尺寸 = **0.25796 × 0.23345**

原版 `Card Rarity Sprite`（uGUI `Image`，`m_UseSpriteMesh=0` · `m_PreserveAspect=0`）的
`m_SizeDelta = 0.25796 × 0.23345`，整张 84×76 被拉进它自己的 RT ⇒ **与画框映射无关**。
改后可见菱形（alpha>128 的 75×73 px）= **0.2303 × 0.2242** 卡单位，对凹槽（67/682×2.2452 = 0.2206 宽、
63/998×3.2572 = 0.2056 高）= **1.044× / 1.090×**，与 PnP 实测「宝石外沿 ≈ 凹槽 1.0–1.12×」一致。
旧值 0.24620 × 0.22159 是 **2026-10-11 按错的 alpha 画框映射量出来的**（可见菱形只有凹槽 0.893× = 用户看到的「宝石小了」）。

👉 **两件必须同批**（本轮已同批）：只改尺寸不改画框 ⇒ 菱形 0.2303 比旧凹槽 0.2462 窄 6.5%，看起来仍然「小」。
