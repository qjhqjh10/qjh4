| 布局组 | `HorizontalLayoutGroup`：`m_Padding 0` · `m_ChildAlignment 3`(MiddleLeft) · `m_Spacing 0` · `m_ChildForceExpandWidth 0` · `m_ChildForceExpandHeight 1` · **`m_ChildControlWidth 1`** · **`m_ChildControlHeight 1`** · `m_ChildScaleWidth/Height 0` · `m_ReverseArrangement 0` | **逐字段照抄**（画布档才挂；世界档没有 uGUI 布局重建，挂了是死件）。断言把 9 个字段逐条读回 |
| `Main Icon` | Image · `m_Sprite` 跨包 → `40k_UI_icon_ranked_Skirmish` · `m_PreserveAspect 1` · `LayoutElement{min 60, pref 60, flex 0}` | 同名节点 · 同图 · `preserveAspect = true` · `LayoutElement{min 48, pref 48, flex 0}`（**60 × 0.8**，见下） |
| `Individual rating value` | TMP `Pragati-Regular SDF` · `m_fontSize 45` · `m_fontSizeBase 31.3799991607666` · `auto[18, 45]` · `Left/Midline` · **折行=1** · `LayoutElement{preferredWidth 5000}` · 文本 = `'-------'`(7) / `'------'`(6) | 同字体面（`TmpFont.Face.LatinCardBody`）· 字号 **36 / 14.4 / 25.104**（= 原值 × 0.8）· `Midline` · **`wrap = true`** · `LayoutElement{preferredWidth 5000}`（不乘 0.8，见下）· 同字面量 |
| `Secondary Icon` | `m_Children[0]`，**`m_IsActive = false`**（act F） | **不建**（出厂态不显示、也不进布局组 `rectChildren`；同 `AllianceMemberTab` 那颗的处理） |

**为什么 60 变 48、而 5000 不变**：
- 两个容器都有 `m_LocalScale = 0.8`。本文件的既定做法是**按实绘 px 建**（同 `NameLabelPx` 那一族：字号/框都乘 0.8），
  所以我们**不设** `localScale` ⇒ 容器宽高、图标首选宽全部按 **×0.8 后的实绘值**写；
- 而 `preferredWidth 5000` 只起「大过容器 ⇒ 吃掉剩余宽」的作用：uGUI `SetChildrenAlongAxis` 的
  `minMaxLerp = Clamp01((size − totalMin)/(totalPreferred − totalMin))`、`childSize = Lerp(min, preferred, minMaxLerp)`
  ⇒ 值那一格的**结果 = `size − 图标宽`，与 5000 这个数无关** ⇒ 照原值写。

### 1.3 空值态（⛔ 不编数值）

- `Player Rating Display` ⇒ **`'-------'`（7 个连字符）**；`Alliance Rating Display` ⇒ **`'------'`（6 个）**。
  **两格不同长**，各取各的（同族先例：`RankedTab.ScoreEmpty` = 6、`AllianceMemberTab.RateEmpty` = 7，但**不是同一份判据**）。
- 数值来源 = 服务端 profile（`DeckAndWarlordData.eloRating@0x38` / `allianceRating@0x7C`）；
  图标覆盖 = LiveOps 活动资产 key=6。两者本地都没有 ⇒ `Build` 末尾 **`Debug.LogWarning` 一次**
  （`WarnRatingOnce()`，实例字段 `_ratingWarned`；自检读 `RatingEmptyWarned`）。

## 5 · 现核补记（顺手发现 / 复查记录）

1. 🔴 **派工口径「图标本地没有」不成立** —— 见 §0。原版 `Main Icon` 的 `m_Sprite` 是跨包 PPtr，
   UnityPy 现解 = `40k_UI_icon_ranked_Skirmish`；且 `Initialize` 是「非空才覆盖」。
   ⇒ 我们**显示这张 prefab 自带的图**是原版离线态的逐句等价物，**不是自造**。
2. **`AllianceRatingDisplay__Initialize.c` 的两条调用**（`BattleAlliancePanel__Open.c`）：
   - 玩家评级：`(this, param_4 /*eloRating*/, uVar8 /*LiveOps icon 或 0*/, 0, 1, 1, 0)` —— 图标**可能**被覆盖；
   - 联盟评级：`(this, param_8 /*allianceRating*/, **0**, 0, 0, 1, 0)` —— 图标**恒为 null**
     ⇒ 那一格的 `Main Icon` **永远**是 prefab 自带那张（原版就是如此）。
3. **活动资产 key=6**：现扫 `bundle_cosmeticsso_assets_all/MonoBehaviour` 里带 `drawData.EventAssets` 的 **13** 个活动 SO
   —— keys 实测为 `{0,1,2,5,7,8,9,10}` 的子集，**没有 6**。与审计 R01 的结论一致。
4. **行尾**：两个被改文件都是 **LF**（改前 `b'\r\n'` = 0），全程用 Edit 改、没整篇重写；
   `git diff --numstat`（**相对 HEAD**，含本件里先前批次已有的改动）= `AlliancePanelWindow.cs 208/10` ·
   `MainMenuScene.cs 281/4` —— 数量级正常（**不是整篇翻**；本批 R01 自己新增约 280 行）。
