## 四、顺手发现

1. **`BattleManager.ShowDisconnectionPopup` 不是 UI 方法** —— 它只改状态 + 停表 + 起协程；
   真正的弹窗在 `BattleErrorUIManager.ConnectionStatusChanged`，而那一支在 `stage == 60` **主动压掉**。
   这是「结算段会弹 MatchAlreadyFinished」这个误判的根因（建议把这一句写进 `资料/已知的坑.md` 的
   「名字骗人」那一族）。
2. **`BattleErrorUIManager` 有 9 个 `LocalizedString`，其中 1 个（`MatchEndedWhileReconnecting`）是死字段**；
   其余 8 个都有读点（见 §一·2 的逐方法清单）。以后按 `mTerm` 扫词条时别把「序列化里存在」当成「会显示」。
3. **`CancelMatchWithVictory` 的触发点比 T07 文档记的多**：除了 `_InBattleFallbackCountdown`，
   `_ResolveAttack` / `_ResolvePlayActiveAbility` / `_ResolvePlayCardFromHand` / `_ResolveUseWaystone` /
   `_MulliganFallbackCountdown` 里也各有一次（都是「等不到对面对这一动作的确认」的 desync 兜底）。
   将来若接 desync 仲裁，这张表就是落点全集。
4. **`RuleCore.Forfeit` 的「只判一次」原来是一条静默早退**，而它在 `BattleDriver.Forfeit()` 里也被
   重复挡了一次（两层）。本批只把**引擎那一层**改成出声；驱动那一层也补了一句（互不重复，因为驱动
   在 `IsOver` 时根本到不了引擎）。
5. **类型检查出现「别人文件里的 807 条错」时不要改别人的文件**（铁律 13·3）：本批第一次跑的时候
   `DeckScene` / `ShopScene` / `CardFaceProbe` / `T09Probe` / `EffectExporter` / `CardBaseDemo` 全在报错，
   重跑就没了 —— 那是别的写手正在写盘。最终我的三个文件 0 错。
