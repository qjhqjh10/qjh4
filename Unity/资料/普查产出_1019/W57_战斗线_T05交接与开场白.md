## 一、逐项结论

### A. `T05(c)(d)` 中段交接 + `timeToScaleIntoMoving = 0.1` —— ✅ 做完（含 AI 两条载体）

**原版完整时序**（`CardScript._MinionPlayedIntoField_d__314__MoveNext.c` 逐句，判据 → `W_战斗线_T05演出接线_1019b.md` §三·1）：

| 时刻 | 原版做什么 | 我们改前 | 我们改后 |
|---|---|---|---|
| 0 → 0.3 | 飞到「槽位 + up × `minionConversionHeight`」（HUD 空间） | 同（0.3） | 同（0.3） |
| 0.3 → **0.4** | 🔴 `WaitForSeconds(timeToScaleIntoMoving = 0.1)`（**纯等待**） | ❌ **没有**（0.3 直接进 0.05 悬停） | ✅ `AppendInterval(0.1)` |
| **0.4** | 🔴 `SetUnitInPlayLayer()`（手牌卡面 → **场上 3D 体**）+ `DefaultScale = GetUnitSizeInPlay(...)` + `HideCardShadow` | ❌ 交接挂在序列末尾 0.55 s，且落下那 0.2 s 用的是**2D 手牌卡面**、全程 HUD 正交相机 | ✅ `InsertCallback(0.4, handoff)` ⇒ `BattleDriver.OnDeployHandoff`（`SetFace(Board)` + `SetParent(boardRoot)` + `SetLayer(ArenaLayer)` + `SetPose(aboveLocal, 0, in-play scale)`） |
| 0.4 → 0.45 | `WaitForSeconds(timeBeforeLand = 0.05)` | 有（但位置口径不同） | 同（0.05） |
| 0.45 → **0.65** | `UpdateMinionInPlayPosition(格位, 0.2)` —— 一句 `DOLocalMove`，**竞技场空间** | `DOMove`（HUD 平面） | ✅ `FallTarget.DOLocalMove(landLocal, 0.2)` |
| **0.65** | `LandOnGround`（扬尘 + 震镜头 + 落地音） | 0.55 | ✅ 0.65（`onDone` → `DoPlay`，引擎结算仍在这里，**没提前**） |

- **总长**：0.55 → **0.65**（`DeploySequence.TotalTime = HandoffTime + HoldTime + LandTime`）。
- **落点为什么能接上**（改后画面衔接的判据）：原版 `DropTargetWorld` 投的是 **卡心（`ArenaSlots.CardCenter` = 身体中点）**，
  而 `PoseFor` 摆的是**卡根**（`RootPosition`，比身体中点高 `0.34335 × scale`）；两者在屏幕上**同一点**
  ⇒ 交接后 `SetPose(RootPosition + up × conversionHeight)` 的投影，正好等于飞行段终点
  `DropTargetWorldAtHeight` 的投影 ⇒ **0.4 s 那一跳屏幕上看不见**；落下终点 = `PoseFor` 的位姿 ⇒ **0.65 s 也没有跳**。
- **AI 两条载体同样拆开**（原版 AI 走同一个 `_MinionPlayedIntoField`）：
  - 手牌卡背那条：0.4 s 卡背**隐藏**（⛔ 不能销毁 —— 整条序列 `SetLink` 在它身上）、**场上视图接管落体**
    （恢复渲染器 + `SetLayer(ArenaLayer)` + `SetPose(aboveLocal)`），落地拍才 `Kill` 卡背；
  - 退路 / 我方 autoPlay 那条：落体就是场上视图自己。
- **判据只留一处**：换体那半抽成 `BattleDriver.EnterBoardBody`（`SetFace(Board)` + `SetParent`），
  0.4 s 交接与 `DoPlay`（**程序化出牌**：`SimulatePlayViaPanel` / `-wfdrive` / 自检那些不经过飞行的入口）都走它；
  `DeploySequence` 只负责「在 0.4 s 调 `Handoff.Apply`、再让 `Handoff.FallTarget` 在竞技场空间落 0.2 s」。

ChatManager.IsPlayerFirstIntro()         // 只看【玩家自己的精确档】：
  GetCustomIntro(player, foe, 0) 命中 ⇒ entry.talksFirst(+0x20)；未命中 ⇒ 1（玩家先说）

  其中 4 条（`DA1/DA2/DA3` 对 `BL1/BL2/BL3`）**不可达**（对手取的是战将，而 BL1/2/3 是 unit），

## 三、没查清 / 没做（⛔ 不猜）

   本次只是照那份结论实现。
3. **`customSound` 的 GUID → 音频没接**（数据报告 §4·4 同款）：本笔只接文本键；`soundGuid` 只在全量件里备查。
4. **同督军对局里「玩家那一侧走 ② 按阵营档」没有实况证据** —— 反编译是这么写的（`param_2 != 0` 时进定制链），
   但原版已关服、无法实况复核；本笔按代码路径实现。
5. **教程 / 战役里有没有别的 `GetChatMessage(Intro)` 调用点** —— 只接了 `SpeakIntro`（开局独白）；其它场景没查全。
6. **`BattleScene` 里其它时序敏感用例只做了静态推演**（本波「只做不验」）—— 特别是：
   - A337 检测器换靶后 **第一次真跑** 才能确认 0.02 的阈值在 0.45→0.65 那段够不够（末帧进度 ≈ 99.9% ⇒ 距离 ≈ 0.001，理论余量 20×）；
   - B5·autoPlay 的等待循环最多 180 帧（3 s），比 `0.34 + 0.65 = 0.99 s` 富余。
7. **AI 卡背那条交接的观感**（卡背隐藏→场上视图在「槽位正上方」出现）—— 屏幕落点应当连续（同玩家那条的判据），
   但**没有真机截图**。
8. **AI 那条落体的生命周期边界**：手牌卡背那一版整条序列 `SetLink` 绑在**卡背**上，而落体（0.45→0.65）的目标是
   **场上视图** ⇒ 若那张视图在这 0.2 s 里被销毁（`SyncBoard` 的「这一格空了」分支 `Kill`），
   补间会指向一个已销毁的 transform（DOTween 安全模式只报错、不崩）。`Apply` 里已加 `v == null` 守卫；
   **落体那一句本身没有二次保护** —— 这是已知的边角，本波没有为此再造一套取消机制（⛔ 不猜、如实记）。
