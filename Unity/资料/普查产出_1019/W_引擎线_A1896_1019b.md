## 一、结论（行为差异）

### 1.1 判据（`d:/2/tools/decomp_full/`，逐句现读）

- **原版唯一调用点**：全库 grep `DeckUtility__RemoveInvalidCards`，除定义自身外**只被
  `DeckEditingWindow__TryOpen.c:47` 调用**。`TryOpen` 的顺序是：
  - `:41-45` `new CardDeck(deckToCopy)` + 拷贝构造 ⇒ 窗上 `EditingDeck`（`+0x118`）是**副本**；
  - **`:47` `cVar3 = DeckUtility__RemoveInvalidCards(*plVar1, 0);`**（对副本跑）；
  - `:141` `*(bool*)(*plVar1 + 0x60) = cVar3 == '\0';` —— **摘过就标脏**。
    `+0x60` 是「干净/已同步」标志，三处反证：`TryClose.c:9`（`== 0` 才走 `ConfirmDiscard`）·
    `TrySaveDeck.c:31`（`!= 0` ⇒ 不保存直接关）· `UploadDeck.c:65`（拷回库后置 `0` = 待上传）。
- **`DeckUtility__RemoveInvalidCards.c`**：顺序固定 `TryRemoveCardsNotOwned` → `TryRemoveInvalidHero`
  → `TryRemoveInvalidCards`；返回值 = `0 < removed.Count`。
  `TryRemoveInvalidCards.c:29-50` 从尾到头遍历卡表，任一条件成立就摘：卡型 ∉ {Minion, Tactic} ·
  `inventoryOptions != 0` · `showInCollectionOptions != 5` · `cardArmy != deck.deckArmy` ·
  （自定义模式同名上限）· 物品隐藏谓词。
- **原版开局链没有校验/摘除**：`BattleManager__CreatePlayerDeck.c` 拿到匹配数据里那份卡表后，
  直接走 `BattleCardManager__CreateDeck.c`（`while` 里逐张 `CreateCard` + `SetAsDeck` + `SetActive`，
  **没有任何条件过滤**）；`DeckUtility__ValidateDeck` 的调用者清单里**没有** BattleManager
  （只有 ChallengeManager / RankedV2Event / DeckEditingWindow / DeckInfoControls / DeckInventory /
  ImportDeckPopup / RankedDeckSelector）。

### 1.2 改前 / 改后

| 场景 | 改前 | 改后（照原版） |
| --- | --- | --- |
| 旧存档带 1 张「按原版不能进卡组」的牌 → **开局** | `ResolveDeck` 先摘 1 张 → 29 张 ⇒ `TooFewCards` ⇒ **整副退回按卡池自动凑**（玩家编的 30 张全被换掉），提示行印「N 张不合法的牌已按原版摘掉」 | **不摘、不判废**：那张牌照原版**带进对局**；只有「卡池里查不到的 id / 效果解析不了的战术」由 `DeckBuilder.FromDeck` 逐张丢并 `LogWarning`（那是**展开层**，不是构筑准入）。`Validate` 只用来打一条日志，**不改变**这一局用哪副牌 |
| 超张数（31 张）旧卡组 → 开局 | 整副判废 → 自动凑 30 张 | 31 张**照用**（原版开局不校验）；提示行「本局用你编的…」 |
| 旧存档带不合法牌 → **打开卡组编辑器** | 我们原来**不摘**（比原版少这一处） | 打开时对**副本**逐张摘（原版 `TryOpen.c:47`）；**源卡组/库那份一个字节不动**；`LastLoadRemoved` 摊开摘了什么 |
| 编辑器里按 Done/ESC | 不变 | 摘过的副本会被 `CommitDeck` 写回库 —— 与原版 `UploadDeck` 的 `CardDeck.CopyDeck(库 ← 编辑副本)` 同构 |
| 编辑器打开后按 ESC（摘过牌时） | 不弹确认 | 原版会弹（`+0x60` 被置脏）。**我们这半没接**，见 §三.1 |

> 一句话：**「整副判废」这条路没了**；「摘牌」只在打开编辑器时发生，且只动副本。
