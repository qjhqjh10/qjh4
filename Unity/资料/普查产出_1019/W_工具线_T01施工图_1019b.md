### 一·⑤ 详解（唯一还要动代码的一处）

**现读 = `0.1204f`，它不是一个「独立拍」的数：**

- `1 − 950/1080 = 0.120370…` → 写成 `0.1204f`，与 `d:/warpforge/scripts/battle.gd:407` 的 `const HAND_Y := 950.0` **逐位一致**（同文件 `:694-695` 的 `SLOT_Y_P=708 / SLOT_Y_E=466` 正是 ① 那对旧值，同一批货）。

**原版判据（三层证据，全部现读）：**

1. **节点位置**：`Transform_1455.json`（`HandAnchor`，GO 1192）= `localPosition (0.125, 1.100000023841858, 0)`；父 `Transform_1401.json`（`HandArea`，GO 898）= `localScale 108`；再上 `PlayerArea(1296, 0)` → `BottomAnchor(2618: anchorMin/Max=(0.5,0)、pivot=(0.5,0)、anchoredPosition=(0,0))` → `Safe area BackCanvas(3498: 全屏 stretch)` → `Canvas(2759)`。运行时 dump 里 `Canvas` 的 `rect = 1920×1080`（`原版参照图/Unity参照管线_0825/data/panel_0914/runtime_ui_dump_drive.tsv`），`CanvasScaler` 参考分辨率 `1920×1080`、`match=0`（`bundle_scenes_scenes_battlearena1/MonoBehaviour/MonoBehaviour_4731.json`）⇒ **16:9 下 1 canvas 单位 = 1 px**。

   - 中间（t≈0.5）：**961.2 px 距顶**
   - 两端（t=0/1）：**992.8 px 距顶**（低 31.6 px）

**我们的现值差多少：**

- 我们的 `SlotPosition` = `baselineY + ArcHeightFull×Arc01(t)`（`HandLayout.cs:488-496`），`ArcHeightFull = 3.0425×0.70×14.835/1080 = 0.029255`（= 31.6 px）。
- 现在 `baseline = 0.1204` ⇒ 两端卡心 **950.0 px 距顶**、中间 **918.6 px 距顶**。
- ⇒ **每一张都比原版高 ≈ 42.6 px**（原版两端 992.8 / 中间 961.2）。`B6` 表二 #8 的「≈11 px」只比了「我们的两端 vs 原版的中间」，**#7 的 31.35 px 弧高差没加进去**；两笔相加 = 42.6 px。

**改法（精确，推荐）—— 不是只换一个常量，而是把「弧高代数」换回原版口径：**

1. **`HandLayout.SlotPosition`（`HandLayout.cs:488-496`）**：把
   `float arc = ArcHeightFull * Arc01(t) * heightModifierByCount.Evaluate(...); arc *= LayoutSpace.Scale;`
   换成**已经存在的原版口径** `ArcOffsetFromBase`（`:531-541`，它 = `yAxisCurve × m_maxHeight × hMod × (14.835/108) × Scale`，返回**我们的世界单位**）：

   ```csharp
   float t = n == 1 ? 0.5f : index / (float)(n - 1);
   float arc = ArcOffsetFromBase(t, n) / Mathf.Max(1e-6f, LayoutSpace.VisibleHeight);  // 世界单位 → 归一化
   return LayoutSpace.ToWorld(NxOfSlot(index, n), baselineY + arc);
   ```
