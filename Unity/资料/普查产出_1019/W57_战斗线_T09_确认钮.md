## 三、没查清 / 遗留（建议主对话分流）

1. 🔴 **视觉上的「灰掉」没做（行为已做，观感待做）**。
   原版 `Continue Button` 子树**四颗件**（父 / `BG` / `ContinueText` / `ContinueButton`）各挂一颗
   `EverguildButtonStateFollower`（`m_Script -9096086197743689236`），`Disabled` 时：
   `EverguildButtonStateFollower__Disabled.c` → `DoStateTransition(4)` + 换
   `EverguildButtonHelper.get_DisabledMaterial()` 造出来的**灰度材质**
   （`EverguildButtonHelper__get_DisabledMaterial.c` 自己 `Shader.Find` 再 `new Material`；
   `DoMaterialRefresh` 逐图形改材质）。
   ⇒ 原版「没选牌时整颗继续钮是灰的」。我们**没有那支 shader/材质**（不在白名单，也不是现成资产）
   ⇒ 本波**只做行为**，⛔ 没有拿「乘一个 0.784」冒充它。**要做需另开一件**（先找/还原那支灰度 shader）。
2. 🔴 **两条现有 Editor 断言会受影响**（`Editor/**` 不在本波白名单，未改）：
   - `Editor/BattleScene.cs:18742`：`if (drv.Choose != null && drv.Choose.Visible) drv.SimulateChooseDone();`
     —— **没选卡就点继续**（防御卡备份路径）。改后该点击是 no-op ⇒ 面板**不关**、`OnDefensiveDone`
     不跑（`defInHand3 == 1` 那条可能仍绿，但会把**未关的面板 / 残留卡视图**带进下一块）。
   - `Editor/BattleScene.cs:18795`：`drv.SimulateChooseDone();          // ⚠️ 在还压着等级时走完（选下标 0 …）`
     —— 注释说的是「选下标 0」，代码却**没调 `SimulateChoosePick(0)`**。改后会红
     （`defAfter3` 还是 `Begin` 随机发的那张 ≠ `ownedAt3[0]`）。
     ⇒ 修法 = 这一句**前面**补 `drv.SimulateChoosePick(0);`（与它自己的注释一致，也与原版语义一致）。
   - 其余 11 处 `SimulateChooseDone` 现核都有前置的 pick（`CheckPick` / `SimulateChoosePick`），不受影响。
   - ⚠️ 另记：`BattleDriver.SimulateChooseDone()` 的返回值**只等于「面板开着」**（`A1972` 已记），
     别拿它当「点生效了」—— 断言要断「面板关了 / `Picked` 变了」。
3. ⚠️ **生产路径少了一条「空选跳过」**：`BattleDriver.OnChooseDone` 收到空列表时仍会
   `_askCands = null; Close(); NextAsk();`（跳过这一问），但**玩家点不到了**（原版也没有这条路）。
   原版靠**倒计时到点随机选一张**（`CountdownTrigger`）兜底 —— **我们这扇面板没有倒计时**，
   ⇒ 玩家现在**必须选一张**才能继续。若某处 ask 的候选会是空的，`Open` 里那道
   `_cards.Count == 0 ⇒ 保持可交互` 的保底会让它还能跳过（防死锁）。
   「要不要给选牌面板补原版倒计时」**另立账**（不在本波白名单）。
4. ⚠️ **本波未做实拍/真机核**（口径 = 只做不验）：判据是逐句反编译 + prefab 字段，
   画面验收（尤其「禁用时该不该灰、灰成什么样」）要等统一验收。
5. ⚠️ `+0x30` 的指认是**字段序推导 + 三处用法自洽**（§1·1），**没有**运行时反射打印字段名
