#### 为什么 `T=0` 正确（不是「没解出来」）

1. `customRangedAttackParticles` / `customDeathParticles` / `summonAnimDelayed` 是卡 SO 的**顶层字段**，
   **不在任何 `abilityLogic.cardAnimations[]` 里** ⇒ 原版没有「组内起点」这个概念：远程攻击粒子在**攻击那一刻**播、
   阵亡粒子在**死亡那一刻**播。`T=0` = 这两个时刻本身。
2. 推断档（`inferred-*`）是我们自己的构词法推断，**原版 SO 没有任何绑定** ⇒ 原版本来就没有时间。
3. **顺手补的一层核**（本报告新增，B6/W 没做）：608 里的 303 条 `customRanged` 中，
   **191 条（118 个唯一 GUID）**不在两张本地表里 —— 逐个从
   `d:/2/新解包资源/assets_full/bundle_*cardanims*/MonoBehaviour/*.json` 读 `animInfo`；
   另 **112 条**在 `数据/游戏数据/card_anim_order.json` 的 `cardAnims` / `card_anim_map.json` 里也核过：
   **两组合计 `vfxDelayTime > 0` = 0 条 · `startDelay > 0` = 0 条**。
   ⇒ 不只是「没有组起点」，连**逐条自身的延迟**也没有 ⇒ 不传 `vfxDelayTime` 不会漏拍。
4. 38 条 `customDeathParticles` 是 **GameObject prefab**（不是 CardAnim），本身没有 CardAnim 时间字段。

> ⚠️ 口径：**608 / 395 是「相对 `animTimes` 的覆盖」读数，不是缺陷数**。⛔ 别把它们当「缺数据」去补
