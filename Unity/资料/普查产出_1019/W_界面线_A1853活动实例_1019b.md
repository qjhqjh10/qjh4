## 四、顺手发现

1. **`BattlePass/SW/EventTitle` 在官方 10,854 键表里确有值**（`Space Wolves Release Event` / `太空野狼发布活动`）——
   与 `W_远端挂起_可解性审计_1019b.md:180` 一致；本批用它做了「官方表兜底」的断言，不再写「整条缺」。
2. **同目录里 4 份 `…Points` / 4 份 `…Premium Item`（非 Offer）不含 `Event_Description`** —— 之前若有账把「13 个活动 SO」
   理解成「Parent/Scoring/Premium 全算」，请按本报告口径：**带 `Event_Description` 的恰好 13 份**
   （4 Parent + 4 Scoring + 4 Premium Item Offer + 1 DarkZealots）。
3. **UM1 与 EC 的 `IntroEventDescription` 的 `{0}` 都指 `Expansion/ORKExp1/EventTitle`**（不是各自活动的标题）——
   原 SO 的复制痕迹，属原版数据，**照抄**并在代码注释里标了「⛔ 别修正」。
4. **`ExpansionOrks1_Premium_Item_Offer` 的窗口是 `start == end`（单点）** ⇒ 按右开区间它**任何时刻都不在期**；
   即使把 `enabled` 改回 1 也一样。这是原 SO 的值，不是我们的选择。
5. **`GachaEventWindow` / `RaidEventWindow` / `ExpansionPassEventWindow`（本批红线，未动）** 文件头列的
   `Event_Description/Gacha/*`、`Raid/*`、`ExpansionPass/BuyPremiumToClaim` 等键**不属于这 16 条**（不在 13 份 SO 里，
   来自 prefab `Localize` / 其它数据面）⇒ **它们不该接这个目录**；要接得另找 gacha/raid 的事件实例（本地没有）。
6. 13 份 SO 的 `EventAssets` 里 `m_SubObjectName` 大多为空（只有 `Icon` 与 DarkZealots 的 `ForegroundImage` 有名字）——
   「图名」不能从 SO 直接得到，需要 GUID→资产名那一层（见 §三·1）；本批**没有拿空名冒充图名**。
