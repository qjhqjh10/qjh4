### 1·1 「抓屏族该用什么度量」—— **答案已经在代码里，且已被 30 条抓屏效果验证过**

### 2·2 完整公式（可直接照写 shader）

```hlsl
// 顶点输入：POSITION（绑定姿势）、COLOR（rgb=本部件枢轴、a=部件号）
// 材质标量：_State（0..1，归一化时间；原版由 legacy clip 的 0.07→1.0 曲线写）、_PartsCount
// 材质向量：_BoundsCenter/_BoundsExtents（整段动画）、_StartBoundsCenter/_StartBoundsExtents（绑定姿势）
float part  = COLOR.a;                                   // 已量化 = k/(PartsCount-1)
float2 uv   = float2((part * (_PartsCount - 1) + 0.5) / _PartsCount,
                     _State + POSITION.x * 1e-4);        // 1e-4 是亚 texel 抖动，可忽略

float4 q    = tex2D(_RotationsTex, uv) * 2 - 1;          // 单位四元数 (x,y,z,w)
float3 p    = tex2D(_PositionsTex, uv).rgb * 2 - 1;      // 每部件每帧的位置
float3 partPos = _BoundsCenter      + _BoundsExtents      * p;
float3 pivot   = _StartBoundsCenter + _StartBoundsExtents * (COLOR.rgb * 2 - 1);

float3 v = POSITION - pivot;
// v' = q * v（四元数旋转，标准 (w^2-|xyz|^2)v + 2(xyz·v)xyz + 2w(xyz×v) 形式）
float3 outPos = partPos + rotateByQuaternion(q, v);
```

- **`U` = 部件轴**（`_RotationsTex` 14 列正好落在 texel 中心；`_PositionsTex` 28 列是**每部件两列同值**的填充，bilinear 取平均仍得原值 ⇒ 不会串部件）。
- **`V` = 帧轴（= `_State`）**，**连续量、不 floor** ⇒ 帧间是**线性插值**（`m_FilterMode:1 / m_WrapMode:1 / m_MipCount:1`）。
- `_State` 的曲线是 **0.07 → 1.0 / 1.7916666 s**（`AnimationClip_8189764618720115800.json` 的 `m_FloatCurves`），即从第 ≈2.9 行采样到末行。
- 高精度档（`_PositionsTexB` / `HighPrecisionMode`）**在这件 shader 里没有槽位**（全文只有 `t0/t1`），且本地 6 件 VAT 的 `HighPrecisionPositionMode` **全 0** ⇒ 对我们是 no-op。

### 2·3 🔴 对现有 `WarpforgeVatDriver.cs` 头注释的**订正**（该文件在 `CardPresentation/**`，本代理无权改）

### 2·4 本批修掉的两处「一动不动」—— **真缺陷，不是判据**

**① 材质缓存被 binder 换掉（`WarpforgeEffectBinder.cs`，✅ 已改）**

- 原版这件事本来就是**事件**做的：`Vanguard Frame Animation VAT` 上的 `AnimFXModuleChangeMaterial.eventsToFire` 有一条
  `VATGPUPlayer.UpdateMaterials(bool=true)`（`m_BoolArgument: 1`）⇒ 我们的 binder 在 `Apply()` 末尾补同样一条语义。
- 改动：`WarpforgeEffectBinder.Apply()` 渲染器循环之后 **+15 行**（取 `WarpforgeVatDriver` → `UpdateMaterials(false)`），**其它逻辑一行未动**。
