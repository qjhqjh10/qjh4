### B. 优先级 3：`SwapToFront` 的换位 tween 同步 `_baseScale` —— ✅ **已修**

- **缺陷**：`SwapToFront` 原来走 `CardTween.ToPose`（`DOMove/DORotate/DOScale`）⇒ 直接写 `transform.localScale`，
  而 `CardView` 的缩放是「**基础缩放 × 高亮系数**」（`_baseScale * _hlMul`，`ApplyScale`）⇒ 换位结束
  `_baseScale` 还停在**换位前那个槽位**的值上；之后任何一次 `SetPose` / `SetHighlightScale`（→ `ApplyScale`）
  都会把卡**弹回旧缩放**（静默，图上只表现为「换位后大小不对」）。
- **原版判据**：`CardDisplayWindow.ChangeCardPosition.c:203-221` 那两条 tween 作用在**同一个 transform** 上；
  原版缩放没有我们这层「基础 × 高亮」⇒ 等价物必须把基础缩放一起带过去。
- **我们的实现**：
  - `Core/CardView.cs` 新增 `TweenPose(pos, rotZ, scale, duration, ease)`（`:5774`）—— **每帧经 `SetPose` 写**，
    于是 `_baseScale` / `_hlMul` / `ApplyScale` 全部同步；`duration <= 0` 直接落终态。
  - 新增只读口 `BaseScale`（`:6239`）。
  - `Battle/CardDisplayWindow.cs:1255-1290`：位置/转角改取 **`localPosition` / `localEulerAngles`**、
    缩放取 **`BaseScale`**（⛔ 不再取已乘高亮系数的 `localScale.x`），两条 tween 改走 `TweenPose`。
  - ⚠️ 两张卡同挂 `_cards`（父链无缩放/无旋转）⇒ 局部坐标与旧的 world 坐标逐位同值；`SetPose` 的口径本来就是局部坐标。
- **新增断言**（两条换位入口各一处）：
  - `Editor/BattleScene.cs:9050-9065`（直接 `SwapToFront(1)` 那一段）：换位收尾后
    `SlotView(0).BaseScale == CardFan.Hpx(0)/(Height×108)`、`SlotView(1).BaseScale == Hpx(1)/…`、
    且无高亮时 `localScale == BaseScale`。
  - `Editor/BattleScene.cs:9232-9245`（点击链 `HandleDisplayWindowClick` 那一段）：同上两条槽位的 `_baseScale`。
  - 🧨 旧实现下这两组都红（两个 base 是**反的**）。
