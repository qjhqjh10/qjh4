## 一、结论（四处逐条）

### (a) 任务点只增不减 → 改成「减阈值、HUD 读余数」 ✅

- **原版**：`PlayerManager__AddQuestPoints.c:71-126` —— `value >= threshold` 时先
  `ManaManager.SetQuestPoints(满值, 阈值)`（`:97`），**再减掉一个阈值**（`:101-104`），
  然后 `RawCardScript.OnQuestResolved`（`:118-119`）。**一次 `AddQuestPoints` 只减一次、只触发一次**（不循环）。
  延迟协程 `PlayerManager._SetQuestPointsWithDelay…:65-76` 读的是**减完后的字段** ⇒ HUD 显示的是**余数**。
- **我们**：`EffectResolver.cs:7901` 的 `QuestPointThreshold` 重写为：
  `QuestPoints >= step` ⇒ `QuestPoints -= step` + `QuestMilestone++` ⇒ 造 1 张隐秘。
  原来 `times = gained - milestone` 的「一次加满连发多次」一并去掉（与原版一致；当前池单次最多 +3，实际等价）。
- 结论：HUD 分子**不用改** —— `BattleDriver` 读到的 `QuestPoints` 现在是余数（0..2）。
- ⚠️ 行为变化（有意）：一次 `Gain 6` 只造 1 张、余 3（原版就是这样，下次再拿点才再触发）。

### (b) 造出隐秘没广播 `CreatesSecret` → 补上 ✅

- **原版**：`BattleManager._ResolveCreateDeckCard…:113-119` —— 读 `spellType == 0x96(150)` 后
  `BattleManager.BroadcastSecretCreated(hero)`。
- **我们**：`EffectResolver.cs:7969-7970`，在随机 Insert 之后
  `if (CreatePool.MatchesKind(card, "secret")) BroadcastWhen(ctx, WhenEventKind.CreatesSecret, owner, card, null);`
  （写法照 `DoCreate` 手牌分支的 `:2867`；归属 = **造牌的施放者 `owner`**）。
- 受影响卡（池内现读）：`DA15 Ravenwing Champion`、`DA66 Ballistus Dreadnought` —— 之前注册的是**永远不响**的监听器。

### (c) 入牌库方式 → 随机下标 `Insert`（去掉 `Add` + 整副洗牌）✅

- **原版**：`BattleManager__AddCardInPlayToDeck.c:36-37` `GetRandomInt(0, deck.Count + 1)`
  （`MatchData__GetRandomInt.c` 上界**开**区间 ⇒ 下标 ∈ `[0, Count]`），`:63-64` `List.Insert`；
  本链调用点 `_ResolveCreateDeckCard…:111` 传 `param_3 = 0` ⇒ 走随机下标（不是插顶）。
- **我们**：`EffectResolver.cs:7963-7964`
  `origIndex = InsertRng.Next(Count + 1)`；`Deck.Insert(Count - origIndex, inst)`。
  ⚠️ 镜像理由：原版 **index 0 = 牌库顶**，我们的约定相反（列表**末尾** = 顶，见 `DoCreate` 的 `decktop` 注释）
  ⇒ `ourIndex = Count - originalIndex`（两边都均匀，但镜像后「相对牌顶/牌底」一致）。
  **删掉了那次 `Shuffle(ps.Deck, ctx.Rng)`**。
- **随机源**：每局一条独立 `System.Random`（`ConditionalWeakTable<BattleContext, QuestAux>`，
  模式同 `RuleCore.PendingDefence`），**不消耗 `ctx.Rng`** —— 往共享流里加消费者会让所有按种子写死期望值的自检整体漂移
  （`ShowRng` / `AiRng` 的注释记着同一个教训）。
- **种子（已知近似，见 §四.2）**：`BattleContext` **没有把开局 seed 存成字段**（只拿去构造 Rng/ShowRng/AiRng），
  且本批文件所有权不含 `BattleContext.cs` ⇒ 用**首次触发那一刻的确定性快照**做 FNV-1a 派生：
  `FirstSeat + 双方督军 Card.Id + 双方牌库/手牌每一份实例的 Id`。
  这些全是「种子 + 动作序列」的函数 ⇒ **同一局面重放，插入位逐位相同**（红线：可复现）。
- 规则书那句「并洗牌」是**粉丝实体版**的改写，与反编译不一致 ⇒ 按反编译（已在注释里写明）。

### (d) 阈值硬编码 3 → 读 `ScenarioVariables` 两档 ✅

- **原版**：`PlayerManager__AddQuestPoints.c:28-41` —— `GameplayVariablesData.alternativeTraitLogic`（`+0x4B`）
  为 0 ⇒ 取 `ScenarioVariables +0x2C`（`questPointsForTrigger`），否则取 `+0x30`（`...Alt`）。
  `DefaultScenario.json` / `EditorScenario` / `TutorialScenario` 实读 **3 / 4**。
- **我们**：`EffectResolver.cs:7819` `public static int QuestPointStepFor(BattleContext ctx)`
  = `ctx.Vars.alternativeTraitLogic != 0 ? 4 : 3`；常量 `QuestPointStepDefault/Alt` 在 `:7805/:7815`。
- **Alt 实例值本地 0 命中**（`alternativeTraitLogic` 的真值在服务器，深挖 §五.1）⇒ 默认走 3，
  **首次触发时 `ctx.Log` 出声**（说明「本地 0 命中 ⇒ 按经典档 3」），不猜。

### (e) 健壮性：非黑暗天使的任务点（SW3 那类不可达数据）✅

- 原版 `QuestTriggered` 发在**督军卡的 RawCardScript** 上 ⇒ 只有带这条能力的督军才造隐秘。
  当前卡池 **4 张黑暗天使督军**（DA1/DA2/DA3/DA75，`cards_engine.json` 现读 = 该阵营全部 hero）全有，
  其他阵营 **0 张** ⇒ 用「督军阵营 == DarkAngels」当代理判据。
- 我们：`faction != "DarkAngels"` ⇒ **照原版仍累计/减阈值**（原版在查能力**之前**就减了），但**不造隐秘**，
  并在**首次**碰到时 `ctx.Log` 出声（不静默）。
