### 1·D 两处**必须说清**的实现口径

1. **`talksFirst` 是逐对手的，不是每卡一个标量**：57 张精确档卡里 **31 张逐条 `talksFirst` 不同**
   （例：`SAU37` = 0/1/1/1、`GOF28` = 0/1/0/1/1/1、`BL35` = 1/1/0/0/0）。
   ⇒ 本表：顶层 `talksFirst` 只在「全部精确档条目一致」时给 0/1，否则 **`null`**；
   **逐对手真值在 `introByOpponent[<对手 chatId>].talksFirst`**（任务书要求的「每条一个 talksFirst」
   会静默丢掉这一半信息，故按真值落盘）。
2. **`introByOpponent` / `introByArmy` 的值是对象**（`{key, talksFirst?, hasText, soundGuid?}`），
   不是裸字符串 —— 同上理由；`hasText` 直接来自官方表对账，消费方据此决定「没有原文时怎么演」
   （我们自己的 `Loc.T` 对缺键**回显键名 + 警告**，见 `Core/Loc.cs:3309` 附近）。

### 1·F 消费方接线（给后续 `UnitChatPanel` / `BattleDriver` 的查表步骤）

```text
me  = 我方战将卡 id（cards_engine.json 的 id）
foe = 敌方战将卡 id
foeChatId = chatIdOverrides.get(foe, foe)          // 现读恒 = foe

entry = card[me].introByOpponent[foeChatId]        // ① 精确档
if entry:                                           //    → entry.key / entry.talksFirst
    key = entry.key; playerFirst = entry.talksFirst
else:
    byArmy = card[me].introByArmy[foeCard.faction]  // ② 按阵营档（faction 名 == CardArmy 枚举名，现读 1,127/1,127）
    if byArmy: key = byArmy.key; playerFirst = 1     //    ⚠️ IsPlayerFirstIntro 不查这一档 ⇒ 默认 1
    else:      key = "Chat_Messages/" + card[me].chatId + "-Chat0"; playerFirst = 1   // ③ 兜底
if !hasText: 照原版「缺键」处理（策略见 §3·C / §4·1，需拍板）
```

`cards_engine.json` 的 `faction` 13 个取值与 `CardArmy` 枚举名 **逐一相同**（现读 1,127 张全命中），
所以消费方**不需要自带枚举表**。

> 口径：**「一致」= SO 精确档对手集合 ∪ SO 按阵营档阵营集合 == 官方表 `<chatId>-Chat0-*` 的第三段集合**

> **裁决的总判据（反编译，非偏好）**：两档的**闸门都是 SO 列表** —— `GetCustomIntro` 只有
