## 一、结论

### T07 —— `Buff_DA_Forest_Self` 2.8× 根因：**找到 = `Shine trail` 的 V 方向 wrap**

**结论一句话**：原版 `Shine trail` 是 **U=Repeat / V=Clamp**；我们导进工程的是 **U=Repeat / V=Repeat**。
而 `Everguild/FX/Spiral Trail FX` 的 PS 把拖尾 UV 的 **V 放大 2.11 倍**（`_MainTextScale.y = 2.11`），
V 因此跑出 `[0,1]`（`[-0.555, 1.555]`）。Clamp 时只有拖尾中段约 28% 能采到贴图里的亮带；
Repeat 时亮带被**卷到两端**、可见长度约 61% ⇒ 原版是「一小段稀疏拖尾」，我们是**绕一整圈的闭环**。

**证据（全部可复核）**
1. **原版贴图实读**（UnityPy 直读 `D:\2\Warhammer 40k Warpforge\...\battlesharedresources_assets_all.bundle`）：
   `Shine trail | 128×128 | mip 1 | wrapU 0 wrapV 1 | filter 1 aniso 1 | DXT5 | sRGB 1`。
   ⇒ **V=1（Clamp）**。同表 `数据/游戏数据/vfx_texture_mips.tsv:2428` 也是 `0 / 1`。
2. **我们的 meta**（改前）：`MyGame/Assets/WarpforgeVFX/Textures/Shine trail.png.meta:40-41` = `wrapU: 0 / wrapV: 0`。
3. **shader 算式**（`d:/4/_tmp_view/wvfx_spiraltrail.asm`，PS 段 line 90–161，逐条）：
   ```
   r0 = frac(t × _Scale_XY_Speed_ZW.zw)                 ; 滚动
   sample noise(t1, v1.xy × _Scale_XY_Speed_ZW.xy + r0)
   r0.x = noise.r − 0.5
   uv   = v1.xy + _NoiseStrenght × r0.x
   uv   = (uv − 0.5) × _MainTextScale.xy + 0.5          ← 这一跳把 V 放大 2.11
   sample main(t0, uv)
   ```
   材质 `Spiral Trail FX Smoke` 的 `_MainTextScale = (1, 2.11, 0, 0)`、`_NoiseStrenght = 0.14`
   （原版材质 JSON 与导出记录 3 逐字相同）；拖尾 `textureMode: 0`（Stretch）、`textureScale (1,1)`
   ⇒ 拖尾自身 V ∈ [0,1]。
4. **量化**（对 `Shine trail.png` 的 alpha 逐行采样 + 上面那条 UV 映射模拟）：
   - Clamp 可见比例（alpha>0.05）= **0.257**；Repeat = **0.567** ⇒ 覆盖比 **2.20×**；
   - 平均 alpha 比 = **2.33×**；
   - 实测 `iso_stats_{orig,exp}.tsv:24-29` 的拖尾槽 #3：`contrib 538.133 → 1524.784` = **2.83×**、
     `lit 1187 → 3278` = 2.76×；整效果总和 1559.1 → 3485.6 = 2.24×（sweep 中位 2.13）。
   - 预测 2.2–2.3 vs 实测 2.8：剩余缺口符合「加法混合下重叠 + 噪声位移」的预期量级；
     **形状判据完全吻合**：`_tmp_view/buff_smoketrail_cmp.png` 左（原版）一小段稀疏拖尾、
     右（导出）一整圈闭环 —— 正是「亮带在 V 两端各出现一次」的样子。
5. **为什么以前查不到**：`EffectIso.TexStr()` 的贴图指纹是「尺寸/格式/mip/sRGB/像素校验和」
   （`WarpforgeArena1/Editor/EffectIso.cs:606` 起），**不含 wrap** ⇒ 「所有数据都对、画面就是不一样」
   那串排除清单里，wrap 是**唯一没被覆盖的输入**。2026-10-02 的 mip 修复（同一症状）确实改到了
   Shine trail（现读 `enableMipMap: 0`，正确），但 mip 与 wrap 是两条独立的轴，修好前者不会动后者。
6. **2026-10-19 的 T07 wrap 修复也没修好它**：`EffectExporter` 写的是单一 `ti.wrapMode = (TextureWrapMode)wu`
   （`WarpforgeArena1/Editor/EffectExporter.cs:2817`），U=0 ⇒ Repeat；代码**自己会打一条
   「wrapU≠wrapV，按 U 写，要人工看一眼」的 Warning**，但没有改 V。⇒ 这条要**用 `wrapModeU`/`wrapModeV` 分开写**
   （本机 Unity 6000.3.23f1 的 `UnityEditor.CoreModule.dll` 里三个成员都在，已用字符串实读确认）。
7. **`1.79` 的出处**：`sweep_orig/exp.tsv` 的逐时刻比值 = `3.00 / 2.18 / 2.05 / 2.12 / 2.26 / 2.02 / 2.15 / 1.78`
   ⇒ **`1.79` ≈ t=3.00s 那一帧的比值（1.782）**，是**点采样**；`2.12` 是台账的**中位**。
   两个数不打架，只是统计量不同。⚠️ 现读基线算出的中位是 2.134 / `|ln|` 0.758，台账写 2.12 / 0.750 ——
   属 sweep 版本差（~1%），结论不变。
8. **同族新发现（未改，需 A/B）**：`Noise Combined` 原版是 **sRGB=0（线性数据贴图）**，
   而 `EffectExporter.ImportTexture` 硬编码 `ti.sRGBTexture = true` ⇒ 我们采到的噪声**偏暗约 2×**
   （0.5 → 0.214）。它同时影响 `Alpha Masks Two Layer` 的辉光与 `Spiral Trail FX` 的噪声位移。
   **只记录**（改它会同时动两族亮度，必须单独 A/B）。

**本轮已落盘（盘上，未渲染验收）**
- `Shine trail.png.meta`：`wrapV 0 → 1`（`Gauss Rays` / `Gauss Rays Noise` 同族同错，一并改）。
- ⚠️ 这三处**不入 git**（整个 `MyGame/Assets/WarpforgeVFX/` 在 `.gitignore`），且**下次 `EffectExporter.Run`
  会按旧逻辑写回 Repeat** —— 持久修复必须同时改 C#（不在本写手白名单，见 §二 的待办）。

**B. 静态根因分析（兜底路 = 正常态与 `WFBIND_FORCE_BUILTIN=1` 的差）**

差别只可能来自「两种模式下 shader 解析到不同对象」的材质。逐条枚举（导出 prefab 的 binder 记录）：

| 效果 | 材质 | 原版 shader | 正常态 | 兜底路 | 静态复核 |
|---|---|---|---|---|---|
| 两条 | `Glow Space …` | `Everguild/FX/Alpha Masks Two Layer` | 原件 | `WFAAlphaMasksTwoLayer` | **算式逐条一致**（见下） |
| Asteroid | `RockDebris_asteroid` | `Matcap Full Options` | 原件 | `WFMatcap` | 基础变体一致；材质只带 `_NOISECHANNEL_R`，不触发未复刻分支 |
| Asteroid | `Ring2` | `Mobile/Particles/Additive` | 原件 | `Extra Color`（tex×vcol） | 原版就是 tex×vcol；材质 `_Color=1` ⇒ 等价 |

  `_Alpha_Multiplier_2` / 两张噪声图都一致），`_MainTex` 两侧都是 null→white。⇒ **静态看不出锅**。
- `WFMatcap` 基础变体 = `LinearToSRGB(_Color)·tex·matcap·_Intensity`，与原版一致；`_APPLYAMBIENTCOLOR` 无关键字 ⇒ 不分支。
- ⇒ **剩余差异最可能来自 `UnlitAmbient`（Void）**（2026-10-02 时我们还没有顶点色分流；`Ship 1..6` 确有颜色通道），

- ⚠️ **别拿现成的 `_tmp_view/iso/` 图当答案**：那一批是 **正常态 orig vs 正常态 exp**（不是兜底路），
  Asteroid 有 40 槽（39 张成对）、**Void 一张都没有**；按「相对棋盘底」粗算，Asteroid 39 槽里只有
  `Background space noise` 一处有差（exp 偏亮 ~17%），其余逐位同 —— 那是**正常态台账**的账，不是 T02 的账。
  （该粗算的绝对量级与 `iso_stats_*.tsv` **不可比** —— 门槛/底图口径不同；只用于「哪些槽有差」的排序。）
