## §一 三族逐项结论

### A · `FollowUpResolution(410)` ← `followAfterResolution`（effect 320/325）· 34 行 / 24 卡

**做了什么**

1. **结算语义（引擎效果层）** —— 原版那一拍是「**排队**」而不是立刻结算：
   `AbilityLogic__PlayAbility.c:2474`（`chosenAbility == 0x140 = 320`）把
   `BattleActionType.followAfterResolution = 58` 压进动作队列 →
   `BattleManager__ResolveFollowAfterResolution.c:380` → `CardScript__FollowUpResolutionPlayed.c:7`
   → `OnTrigger(0x19a = 410)`。我们补的是**这一拍的时机**：
   * `PlayTactic` 尾部（`EffectResolver.cs:1819-1833`）—— 战术/防御卡的 320 挂在它的
     trigger-0 能力里，所以**这张牌彻底结算完之后**发；
   * `FireTriggerAt` 尾部（`RuleCore.cs:8970-8985`）—— 单位的 320 挂在**某个关键词能力**里
     （Regiment / Strike / Artifice / Mob），那条能力结算完之后发；
   * `BroadcastWhen` 棋盘循环（`EffectResolver.cs:6630-6640`）—— 320 挂在**监听能力**里的两张
     （`GSC14` 10 · `ASH81` 455），那条监听结算完之后发。
2. **`CardId` = 该卡自己、`Keyword = "FollowUpResolution"`、`InstanceId` = 载体实例**
   （`EffectResolver.EmitFollowUpResolution`，`:5649-5661`）。落点：
   * 战术有棋盘目标 ⇒ **目标那一侧**的格号（`Player` 也写目标侧 —— 敌方目标不能拿施放方的棋盘去摆）；
   * 单位 ⇒ 它自己那一格（`FireTriggerAt` 显式传的格号）；
   * 无棋盘目标（抽牌 / 手牌降费那一族）⇒ `Slot = -1`（**仍不可达**，见 §三）。
3. **「哪张卡的 320 挂在哪条能力里」= 一张 19 条的转写表**
   （`EffectResolver.FollowUpSchedulerOf`，`:5613-5634`）。判据 = 当前 build SO 的
   `cardAbilities[].abilityLogic[].chosenAbility == 320/325`
   （`资料/普查产出_1018/allcards_1350/cards_raw.json`，逐卡按 `cardShortId`/`uniqueId` 配对
   `cards_engine.json` 的 `id`）。**24 张「有 410 动画行」的卡里 19 张在表里**：
   * 12 张战术/防御 → `ThisCardPlayed`（`ASH73`/`AM54`/`AM58`/`EC47`/`EC49`/`SAU61`/`GOF104`/
     `GOF102`/`Greatest Warboss`/`SW56`/`TAU40`/`UM39`）；
   * 7 张单位 → 各自那条：`AM8`/`AM21` Regiment(301) · `GSC17` Strike(580) · `SAU11` Artifice(560) ·
     `GOF59` Mob(300) · `GSC14` OtherCardPlayed(10) · `ASH81` OtherCardSpiritStone(455)。
   ⚠️ **为什么是硬编码**：引擎加载的 `cards_engine.json` 只有 `animTimes`（`tg`/`tn`），
   没有 `abilityLogic[].chosenAbility`；`cards_truth.json` 有，但由 `RuleEngine/Data` 装载
   （不在本批白名单）⇒ 本表是**当前 build 的转写**，卡池迁 id / 改能力后**必须重生成**。
4. **5 张 410 卡在原版数据里就找不到调度者**（`DA29` Darkshroud · `DA14` Ravenwing Speeder ·
   `SW9` Fenrisian Wolf · `UM118` Indomitus Crusade · `UM116` No Mercy）——
   它们的 410 能力在当前 build 的 `abilityLogic` 里**没有任何 320/325** ⇒ 原版也不会被这一拍触发，
   本表**不收**（8 行）。⚠️ `UM118`/`UM116` 的形状像是「`playChosenCardAbility(360)` 间接调度」，
   **未查清**（见 §四）。

**证据（本批落点）**：`EffectResolver.cs:1819-1833`（PlayTactic 尾）· `:5613-5661`（表 + 发射口）·
`:6630-6640`（监听者那一跳）· `RuleCore.cs:8970-8985`（关键词触发那一跳）。

### E · 监听者 / 自发反应路径发「按反应者」的事件

**做了什么**：**监听者真的结算时**（`ops` 非空、马上 `ResolveOps`）给它发一条按**它自己卡名**的
`EvtKind.Trigger`，`Keyword` = 那条监听能力的**原版 `AbilityTrigger` 名**。四条跳全覆盖
（`EffectResolver.EmitListenerTrigger`，`:5663-5681`）：

| 跳 | 落点（本批行号） | `unit` 传什么 | 落点格号 |
|---|---|---|---|
| 棋盘监听器（主路） | `EffectResolver.cs:6624` | 监听者单位 | 它自己那一格 |
| 常驻效果监听器 | `:6745` | `null` | `-1`（弃牌堆/无实体） |
| 事件触发式降费监听器 | `:6805` | `null` | `-1`（在手里） |
| 手牌陷阱监听器 | `:6884` | `null` | `-1` |
| 手牌单位卡监听器 | `:6996` | `null` | `-1` |
| `GrantDarkPact` 自发段 + 同伴段 | `:7818` / `:7832` | 单位 | 它自己那一格 |

**事件种类 → 原版 trigger 名**（`EffectResolver.TriggerNameOfWhenKind`，`:5566-5611`）：
`play→OtherCardPlayed(10)` · `deploy→OtherUnitSummoned(190)` · `die→OtherUnitDeath(90)` ·
`attack→UnitAttack(50)` · `damaged→UnitDamaged(60)` · `draw→OtherCardDrawn(260)` ·
`reanimated→Reanimated(570)` · `darkpact→UnitReceivesMarkOfChaos(510)` · `prays→TriggeredPray(660)` ·
`spiritability→OtherCardSpiritStone(455)` · `triggers:ferocity→TriggeredFerocity(726)` ·
`triggers:pray→TriggeredPray` · `triggers:duty→TriggeredDuty(661)` · `triggers:swarm→TriggeredSwarm(620)`。
认不出的事件种类 ⇒ **不发**（⛔ 不猜名字）。

**原版判据**：`RawCardScript__OnCardPlayedWithTarget.c:96`（`TriggerAbilities(10)`）·
`CardScript__TriggeredFerocity.c:7`（`0x2d6 = 726`）·
`CardScript__ReactToUnitMarked.c:7`（`0x1fe = 510`）；其余 = `AbilityTrigger` 枚举名
（`dump.cs:20235-20335`）与本工程 `WhenEventKind` 的字面对应。

**防重复 / 自激**：`ctx.Emit` 只往 `Signals` + `ActionLog` 追加，**不触发任何广播/监听**
（`BattleContext.cs:1456-1461`）⇒ 新事件不会叫醒监听器，**结构上不可能自激**。
一个监听者一次结算只发一条（发在它自己那一趟 `ResolveOps` 之前）。
`GrantDarkPact` 的两条旧路（`Effect("after receiving a dark pact")` / 同伴 `Effect(...)`）
**只对 `EffectSpec` 那批（非原版卡）成立**；原版卡走 `WhenTriggers` 事件层 —— 两条互斥，**不双发**
（见 `CardDef.BodyResolves` 的口径）。

### F · `TurnStart` / `TurnStartPlayer` / `TurnEnd` / `TurnBeforeEnd`

**做了什么**：`ResolveAtTurn` 三趟作业（手牌 → 棋盘 → 常驻）**每一份在结算之前**发一条
`EvtKind.Trigger`（`EffectResolver.EmitTurnTrigger`，`:5703-5713`；调用点 `:5825` / `:5836` / `:5845`）。

* **trigger 名怎么定**：读**这张卡自己**的 `AnimTimes` 里那一个 `Turn*` 名
  （`TurnTriggerNameOf`，`:5683-5701`）。现读全池 18 张卡**每张只有一种**
  （`TurnStart` 3 · `TurnStartPlayer` 3 · `TurnEnd` 11 · `TurnBeforeEnd` 1）⇒ 无歧义。
  ⛔ 不用「`each turn` → TurnStart / `your turn` → TurnStartPlayer」这种推断 ——
  数据上两张名字都用于 `your turn`，映射不存在。
* **手牌陷阱**那一趟原来只存 `EffectOp`、丢了卡身份 ⇒ 新增 `AtTurnHandJob`（带 `Card`）；
  常驻效果那一趟同理新增 `AtTurnPersistJob`（`Card = pe.Source`）。

**原版判据**：`CardScript__OnTurnStart.c:137+` 的 `RawCardScript.OnTrigger(0x1e = 30)`；
`TurnStartPlayer=31` / `TurnEnd=40` / `TurnBeforeEnd=41` 见 `AbilityTrigger` 枚举
（`dump.cs:20243-20246`）。⚠️ 原版 `TurnBeforeEnd`（41）在 `TurnEnd`（40）**之前**，我们的
`ResolveAtTurn("turn_end")` 是**同一批**跑（顺序 = 手牌→棋盘槽位序）—— 这一条**时序差异保留**（见 §四）。

## §四 没查清 / 仍不可达

1. **无棋盘落点的那一族（A 10 行 · E 7 行 · F 2 行）**：原版这些动画的落点由
   `AnimInfo.startPosOption` 决定（`AbilityLogic__PlayAnim.c` → `AbilityLogic__GetPos`；
   `PositionOption` 150/155 = 手牌世界锚、0 = 自身）。我们的 `EvtKind.Trigger` 只带
   `Player + Slot`，**没有手牌/弃牌堆锚**这条落点 ⇒ 发得出事件、播不出特效。
   数据侧**是齐的**（`数据/游戏数据/animinfo_lookup.json` 有逐 prefab 的 `sp`/`ep`；
   `BattleDriver.AnimAnchors.HandAnchorOf` / `HandWorldAnchorOf` 也已挂好）——
   **接口需求给表现层**：`EvtKind.Trigger` 需要一个「不在棋盘上的落点」通道（报告 §五·5 同一条）。
2. **`UM118 Indomitus Crusade` / `UM116 No Mercy`**：410 能力存在、但当前 build 的
   `abilityLogic` 里**没有 320/325**（另有 `playChosenCardAbility(360)`）。
   「360 会不会间接调度 410」**没查到判据**（`AbilityLogic__PlayAbility.c` 的 0x168 支没读透）
   ⇒ 按「查不到 = 不猜」先**不发**。`DA29`/`DA14`/`SW9` 同档（410 能力孤立）。
3. **`ASH73` 用的是 effect 325（`followResolutionIfPreviousMeetsCriteria`）不是 320** ——
   它的 410 能力（"If the target dies, deal 2 damage to adjacent units"）**带前置条件**，
   而我们的发射**无条件**（条件在我们这边是文本层的 `Condition=targetdies`，只作用于游戏效果）。
   ⇒ **这一张的动画可能比原版多播**（目标没死也播）。判据不足，如实记着。
4. **`TurnBeforeEnd`(41) 的时序**：原版它在 `TurnEnd`(40) **之前**；我们的
   `ResolveAtTurn("turn_end")` 是同一批（手牌→棋盘槽位序）。`SAU20 Chronomancer` 的动画会播，
   但**相对其它 `TurnEnd` 特效的先后可能与原版不同**。这是既有引擎口径，本批没改。
5. **`AbilityEffect.followAfterResolution` 的「游戏语义」**：19 张卡的**第二半效果**本来就由
   卡面文本解析覆盖（`Reanimate … and give it +1 Health` / `Destroy an enemy troop` 等），
   本批补的是**时机与事件**，没有把 `abilityLogic` 的 `chosenAbility` 数据层搬进引擎。
   「文本解析 vs 结构化 ability 是否逐卡等价」**没有逐卡对账**（24 张里只抽了 4 张读文本）。
6. **VfxMap 的 keyword 归口只放行「引擎带名字发出来」的 18 个**；`Strike` / `Slay` / `Mob` /
   `Regiment` / `Rally` 等旧路**行为不变** —— 它们的动画仍走原口径（可能多播，报告 §五·6 的旧账）。
   要全部收口需要给它们各自一个「发射口事件」，不在本批。

## §五 顺手发现（只报不改）

1. **`GrantDarkPact` 的两条旧结算支是死代码**（`EffectResolver.cs:7803-7808` 自发段与
   `:7819-7828` 同伴段）：`CardDef.Effect(key)` 读的是**关键词表**（`_effects`），
   而 `after receiving a dark pact` / `when a friendly troop receives a dark pact`
   **不是关键词** ⇒ 对当前 1127 张恒为 `null`。真正的路径是事件层 `WhenTriggers`
   （`CardDef.cs:2627-2642`）+ `BroadcastWhen(GetsDarkPact)`。
   ⛔ 别因为「注释里写着 ②③ 两件事」就以为它们还在跑。
2. **`PlayTactic` 的 `EvtKind.Play` 对「敌方目标战术卡」把 `Slot` 写成了目标格**
   （`EffectResolver.cs:1705-1714`：`Slot = targetSlot`，而 `BattleEvent.Slot` 的语义是
   「**己方的**第几格」）。`PlaySignal` 取 `owner = e.Player`（施放方）⇒ 表现出的是
   **施放方棋盘上同一格号**的位置（镜像位）。本批的 A 族特意用 `TargetPlayer/TargetSlot` 的
   思路绕开了（`EmitFollowUpResolution` 把 `Player` 写成目标侧），但这张旧事件**没动**。
   判据：`BattleEvent.Slot` 的 doc（`BattleEvent.cs:267`）。
3. **`VfxMap.ResolveAllTimed` 的 doc 说「生产路径传不进 keyword」——已过期**，
   本批就地订正（`VfxMap.cs` 两处）。
4. **`CardDef.HasAnimTrigger` 是逐卡动画行的唯一现成索引**；以后再有「这张卡这一拍有没有动画」
   的问题，别再遍历 `card_vfx_by_card.json` 另写一份。
