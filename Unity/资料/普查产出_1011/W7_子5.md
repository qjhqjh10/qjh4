### A223 —— ESC = 保存（三级顺序，每级有实读判据）

- **判据①**：`d:/2/tools/decomp_full/DeckEditingWindow__ESCPressed.c:5` =
  `DeckEditingWindow__TrySaveDeck(param_1, 0)` ⇒ **ESC = 保存**（⛔ 不是关窗；关窗走 `__TryClose.c`，
  只由关闭钮走）。我们的 `TrySaveDeck` 等价物 = `SaveAndSay()`（**Done 钮同一个函数**，
  `Deck/DeckRuntime.cs` 的 `HandleButtons` 里 `case "foot_done"`）。
- **判据②（新查到、原判据里没有）**：导入弹窗那扇窗在**原版是一扇独立的窗** ——
  `d:/2/Warpforge_code/Scripts/Assembly-CSharp/ImportDeckPopup.cs:6` = `public class ImportDeckPopup : GameWindow`；
  它的 prefab 实例 **实读 `closeOnESC = 1`**
  （`bundle_menus_assets_all/MonoBehaviour/MonoBehaviour_8307242524170911890.json`）
  ⇒ **ESC 归「压在最上面那扇窗」** = 关掉导入弹窗、**不保存**。
  （对照：`DeckEditingWindow` 的实例 `MonoBehaviour_5918047927837519652.json` 也是 `closeOnESC = 1`，
  但它**覆写**了 `ESCPressed` ⇒ 这一步能反证「字段=1 不等于会关窗」。）
- **判据③**：输入框优先 —— 本类**既有**的 `HandleTyping()`（`Deck/DeckRuntime.cs`）在 `_nameEdit != null`
  时把 ESC 当「取消编辑」⇒ `EscPressed()` 第一句 `return`，同一帧 ESC 只被用掉一次。
- **落点**：`Deck/DeckRuntime.cs` 的 `Update()` → `HandleEscape()`（**这是本件最要紧的一条**）——
  卡组编辑窗**不是** `WindowsManager` 的窗（`DeckRuntime : MonoBehaviour`、自己一个场景
  `DeckEditor.unity`）⇒ 外壳 `GameWindow.ESCPressed` / `PointerLayer.KeyCancel` 那条链**够不着它**
  （这正是 A223 原文记的「前置不成立」）。批处理没有键 ⇒ 自检直接调 `EscPressed()`（**同一个函数**）。
