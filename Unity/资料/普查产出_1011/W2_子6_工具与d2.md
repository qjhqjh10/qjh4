## 六、顺手发现（⛔ 一个都别改，只报）

1. 🔴 **`Warpforge_code/Scripts/Assembly-CSharp/QualitySettingsManager.cs:31-35` 那三个「签名桩」会骗人**：它写着 `AllowSuperSampling => false` / `ForceUINativeResolution => false` / `Quality => default(...)`，**实际不是**——反编译实读 `get_AllowSuperSampling` = `*(bool*)(this+0x2d)`、`get_ForceUINativeResolution` = **`*(int*)(this+0x24) < 1`**（= `clampInMenuResolution < 1`，**是个数据驱动的判断**）。⇒ 那个目录是「方法体为空」的桩，**布尔 getter 的 `=> false` 不是真值**（谁拿它当判据就会静默错）。
2. **`GetRenderScaleBasedOnClampedResolution` 在全量反编译里零调用者** —— `grep -rln` 只命中它自己的 `.c`。它在 `ChangeResolution` 里是**内联**形式存在的，而且**独立那份 `.c` 的 return 全被 decompiler 丢了**（`void` 返回、`Screen.get_width()` 的返回值当语句丢掉）⇒ **读这个函数只能读内联那一份**（`ChangeResolution.c:31-52`），照独立的 `.c` 读会得到「它什么都不返回」。
3. **「同名不同物」是这批丢件的结构性成因，不是偶发**：`Floor`×3（`Floor` / `Floor` / `Floor (1)` 三个 GO 各一份）· `Cone.001–004` 各×2 · `LDR_LLL1_0` 是 **`BlueNoise16/L/` 与 `BlueNoise64/L/` 两个不同目录的同名文件**被压平到一层目录 ⇒ 只要有「按 `m_Name` 落盘」的管线，**这一族一定会撞**（同族还有 `LDR_LLL1_1..31`、`BlueNoise256/`）。
4. **`UnityPy` 的 `SerializedFile.files` 是 property（等价 `.objects`）这个坑又咬了一次**：本件第一版反查脚本把独立 `.assets` 的 `f.files` 当成「CAB→SerializedFile 映射」⇒ 直接 `AttributeError`/找不到对象。庚1 §⑤·4 已记过，**这次是第二个独立复现**；顺带确认**判法只能是 `isinstance(f, BundleFile)`**（`工具/a236_scan_dual_cab_pid_collision.py:86-104` 的 `iter_sfs` 就是正确写法，照抄它即可）。
5. **导出的 `.obj` 是 CRLF**（`fix_exports.py:142` 用文本模式写），而 `--verify` 那一侧比的是**行尾归一后**的 md5 —— 两边都归一所以判得住，但**谁要按字节复现 `.obj` 就必须走 `open(...,'w')`**（本件 `a236_restore_lost_exports.py` 的 `write_and_verify` 就是为此分了 bin/text 两路）。
6. **`Avatar_UM_Chaplain Cassius` 的两份是两张不同的画**（512×512 各自、逐像素不同），而 `素材/Warpforge原版/装饰品/头像/Texture2D/` 里存的是**盘上那一份**。⇒ 如果将来有卡面/头像要按「原版那一份」对账，**这个坑会静默选错**（同名两份、都在盘上、只有一份在 `素材` 树里）。
