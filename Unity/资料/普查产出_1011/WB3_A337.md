## 二、判据（3D 投影点的口在哪 + 出处；2D 档为什么逐位不变）

1. **现成的口 = `BoardLayout.DropTargetWorld(int slot)`**（`Board/BoardLayout.cs:407-417`）：3D 时 =
   `boardCam.WorldToScreenPoint(ArenaSlots.CardCenter(slot, mirror, CardScale(mirror)))` → `LayoutSpace.ScreenToWorld`（HUD 相机反投影）→ `transform.InverseTransformPoint`。
   它把「3D 点」换算成**同一个屏幕位置**上的「HUD 平面点」—— 补间活在 HUD 平面里，所以这正是该喂给 `DOMove` 的东西。
2. **它投的那个点是什么**：`ArenaSlots.CardCenter` = `RootPosition + Vector3.up*(BodyMidOffset*sc)`（`ArenaSlots.cs:129-137`），
   即**「看得见的那张 3D 卡体」的中心** —— 场上整张 `2DCard` 是不画的（`CardView.cs:1409-1423`：`CardFace.Board` 下 2D 面全关、只画 `3DBody`/`Card 3D`）⇒ 交接那一刻眼睛看的中心就是它。
3. **简报那个 657px 的出处**（本件实读到原文）：`d:/4/_tmp_view/BattleScene.log:24836` = `[投影诊断] 我方行卡心 → 60.86% 距顶（= 657 px @1080）`；
   产生它的代码 = `Editor/BattleScene.cs:6769-6773`（`root + up*(bodyMid*sc)`，与 `ArenaSlots.CardCenter` 同一个式子）。同 run 的相机 = `:24894`（`aspect=1.7778 pixel=640x480 fov=46.3972 lens=(0.00,-0.21) pos=(0.00,2.22,-13.57)`）。
4. **落位后卡的真实位姿** = `BattleDriver.PoseFor:6105` 的 `ArenaSlots.RootPosition(slot, foe, sc)`（`SyncBoard:6224` → `:6232` `v.SetPose(...)` + `:6225` 换 `ArenaLayer`）；
   `RootPosition` 是**我们卡根（= 卡中心）**，与 `CardCenter` 差 `BodyMidOffset×sc = 0.34335×0.36 = 0.1236` 世界单位（我方行 ≈22px）—— 两个都读得到，**该拿哪个当靶见 §五·2**（本件倾向 `CardCenter`，理由：那是可见卡体的中心，交接时不会上下跳）。
5. **非 3D 逐位不变**：`DropTargetWorld` 的兜底 = `return SlotPosition(slot);`（`BoardLayout.cs:416`）—— 与今天 `CardInteraction.cs:442` 传的 `which.SlotPosition(land)` **同一个纯函数、同一个实例、同一实参**
   （`SlotPosition` 只读 `spacing/lineY/mirror`、无副作用，`BoardLayout.cs:359-368`）⇒ 返回的 `Vector3` **逐位相同**（不是「近似相同」）。
6. **为什么今天会「下坠再跳回来」**：补间飞向 `SlotPosition`（= 2D 行线上的点，屏上 708px），
   落地后 `SyncBoard` 把视图摆到 3D 位姿（屏上 631~657px，逐格不同）⇒ 交接那一帧**整张卡上跳/下跳一次**。改 `DropTargetWorld` 后补间终点就是那个投影点，交接不动。
