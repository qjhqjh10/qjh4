## 二、判据（逐处带 文件:行号 / 出处）

1. **口 = `BoardLayout.DropTargetWorld(int slot)`**（`Board/BoardLayout.cs:407-417`）：3D 时
   `boardCam.WorldToScreenPoint(ArenaSlots.CardCenter(slot, mirror, CardScale(mirror)))`
   → `LayoutSpace.ScreenToWorld`（HUD 相机）→ `transform.InverseTransformPoint`。
   **非 3D 时逐位等于 `SlotPosition`**（`:416` 的兜底就是 `return SlotPosition(slot);`）。
2. **它投的是「看得见的那张 3D 卡体」的中心**：`ArenaSlots.CardCenter = RootPosition + up*(BodyMidOffset*sc)`
   （`Board/ArenaSlots.cs:129-137`），而场上的 `2DCard` 面全关、只画 `3DBody`
   （`Core/CardView.cs:1412,1439`；`SetFace` 那一路同口径在 `:642,651`）。
3. **两个候选靶在 3D 下真的分得开**（实测，WB3 §二·3）：`DropTargetWorld(0) = (−5.84, −0.89)` vs
   `SlotPosition(0) = (−5.53, −1.56)` ⇒ **差 0.73 世界单位**（≈79 px）；督军位 51 px / 最外格 72 px
   （**不是同一个数**：透视下投影点的 y **逐格不同**）—— 所以本件的阈值**不用任何固定 px**。
4. **A359 的同族出处**：`BattleDriver.PlayAttackFeel:5875-5881` **2026-09-29 已修过同一类错**
   （自写「那个 `dir` 是**两个坐标系相减**出来的」）⇒ `PlayHitFeel` 是**漏掉的那一处**；
   原版那枚飘字挂在**卡自己**的 `damageCounterParent` 上（`Core/CardFeel.cs:1010-1014`）。
5. **改动只碰「基准点」**：`DropTargetWorld` 与 `SlotPosition` 都返回**世界坐标**（本场景棋盘根 = 恒等变换：
   `BattleScene.cs:9732` 的 `sceneRoot` 是裸 `GameObject`、两块棋盘 `SetParent(…, false)`（`:9797`/`:9807`），
   所以 `InverseTransformPoint` ≡ 世界），z 也都是 0 ⇒ 只可能改 x/y（A337 的检测器**照旧只比 x/y**，
   理由见 `BattleScene.cs:2209-2210`：补间中段那一下 `lift` 会把 z 拉到 −0.8）。

## 五、没查清 / 判不了的（⛔ 不猜）

1. **督军位那一格的投影可能不准**（WB3 §五·3 已报，本件**没动**）：`DropTargetWorld` 只按 `CardScale`（0.36/0.69）算，
   **没有 `IsWarlord` 分支**，而真落位走 `PoseFor` 的 `HeroScale`（0.4/0.77，`BattleDriver.cs:6126`）⇒ 尺寸不同 ⇒ 卡心不同。
   ⚠️ 本件把 `DropTargetWorld` 拿去当**飘字基准**之后，这条的影响面**变大了一点**（飘字可能落在督军位也偏）——
   但**实跑没跑**，仍是疑点不是结论。**实际出牌不落督军位**，影响面待判。
2. **敌行 / 战术卡那一档仍无实跑证据**（WB3 §五·4）：`Sep3D`/`dLinePop` 这两条的**幅值**我用的是**玩家行**的实测
   （51~72 px / 0.73 世界单位），**敌行没量到**（`monitor` 一次都没跑）。阈值我特意取到 **0.02 / 0.05**（≈2~5 px）
   ⇒ 只要敌行那两个点差 >5 px 就不会误红；**万一真跑红了，先量那个差，别急着改断言**。
3. **A359 的 0.05 容差用的是「父节点在原点 + `Label.Create` 把 `pos` 当 localPosition」这个前提**
   （`Battle/Label.cs:60-65` 亲读，`drv.transform` = `sceneRoot`，恒等）—— **没实跑复核**。若真跑红了，
   先量 `LastPop.transform.position` 与 `popAt` 的差是「常数偏移」还是「0.47 那种大差」，两种结论不同。
4. **`CheckAbsorbRule` 那条老坑**（早退会静默吞掉后面 N 条断言）**本件没查**是否波及上面这 6 条。
