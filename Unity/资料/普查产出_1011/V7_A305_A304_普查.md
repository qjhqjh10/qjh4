## 一、结论（两张表各一句）

**A305** —— 🔴 **「原版是 12」这个说法只对【一个站】成立，不是通则。** 全库 8,680 个「开了自适应」的原版 TMP 里，
`m_fontSizeBase` **`36.0` 出现 3,045 次**、**`12.0` 只有 559 次**，其余散在 **200+ 种取值**上；
而 **`36` 正是 TMP 的序列化默认值**（`TMP_Text.cs:473` `protected float m_fontSizeBase = 36;`）
⇒ 原版大多数站**根本没显式设过 base**（作者开着 autoSizing 改字号时 setter 不回写，见 `TMP_Text.cs:467`）。
**真正要照抄的不是「12」，是「逐站现读」** —— 本件交出 **19 个站**的实读值 + **46 个调用点**清单（§二、§三）。
⇒ 动手前必须知道：**这条改的是一个共用件、而共用件上站着至少 8 个「原版 base 各不相同」的站**（A207 那条判据的教科书例子）。
🔴 **另有一条同族、更值钱的**：**46 个调用点里有 42 个把 【原版 `m_fontSize`】 当成了上限传**（原版的自适应上限是
`m_fontSizeMax`）⇒ **短文案永远画小一档**。证据 = 我们传的 (min,max) 里有 **3 个档位在原版全库一个对象都没有**
（`(25,31.75)` · `(18,34.8)` · `(7,31.9)`）。详见 §三·1 / §三·2。
**A304** —— ✅ **今天没有一条「随时会红」的**（CollectionScene 那两条已经在本轮 F6 改成 `CheckAtPx` 了）。
但查出一条**更隐蔽的**：`Editor/BattleScene.cs:1784` 那条 3D 距离**不是红，是【静默量错】**
—— 3D 场上卡视图 z ≈ `−6.655`、而 `DropTargetWorld` 强制 z=0 ⇒ 检测器**一次都没触发过**

### 3·1 🔴 一个**系统性**的第二层问题（与 A305 同族，必须在同一件里一起定口径）

**我们的 `maxPx` 几乎一律 = 调用方标称字号（= 原版 `m_fontSize`），而原版的自适应上限是 `m_fontSizeMax`。**
证据链（三处互相印证）：

1. 代码：`MenuDraw.Text` / `TextBox`（`Shell/MenuDraw.cs:1450-1483`）把 `maxPx` 写死成 `fontPx`；
   `OfferContainer.LabelFit`（`:1323`）也是 `maxPx > 0f ? maxPx : fontPx`；
   `MatchLogRow.Text`（`:145`）= `(autoMinPx, px)`。
2. 原版实读：`CacheTab:Title` = `m_fontSize 31.75` / `max 35`；`Points` = `34.8` / `max 40`；
   `Match Log/Result` = `65.35` / `max 75`；`Score` = `46.25` / `max 50`；`skullCounter` = `30.2` / `max 45`。
3. **交叉验算**：拿「我们传的 (min, max)」去全库查**原版 TMP 的 (m_fontSizeMin, m_fontSizeMax)**，
   有 **5 个档在原版全库一个对象都没有**：`(25,31.75)` · `(18,34.8)` · `(7,31.9)` · `(14,24)` · `(16,26)`
   —— 前三个正是「把 `m_fontSize` 当成了上限」的直接指纹（后两个是我们自加件，本就无对应）。

⇒ **`Label.SetAutoFitBox` 的 A50① 修的是「px↔fontSize 的量纲」，没修「maxPx 该取哪个字段」。**
⇐ 本件的判定：**A305 若只把 `_tmp.fontSize = cur` 改成「照抄原版 base」，
天花板那条（短文案永远画小一档）一条都不会好** —— 两件事在同一族里，建议**一次定清**。
