### ① A310① 逐件 punch —— 四个字面量全是读出来的

**归一化距离那两个操作数（本件订正了上一轮的一处读错）**：

```c
// RewardWindow__DoRewardAnimation.c:123-132
lVar11 = *(longlong *)(*(longlong *)(param_1 + 0xd0) + 0x40);   // ← scrollRect + 0x40
fVar17 = get_localPosition(local_b8, lVar11).x;
... lVar11 = drawers[i].transform ...
fVar17 = (|drawer.localPosition.x| - 0) / (fVar17 - 0);          // 夹到 [0,1]
```

- 🔴 **`scrollRect + 0x40` 是 `m_Viewport`，不是 `m_Content`** —— 判据 = `d:/2/tools/il2cpp_out/dump.cs` 的
  `ScrollRect` 字段表（`m_Content` = **0x20** · `m_Viewport` = **0x40**）。
  ⇒ `资料/普查产出_1010/戊2_RewardWindow_A302.md` §五·3 写的「`scrollRect.content`」**作废**（铁律 5）。
- ⚠️ **它换算成「我们能写的量」= 视口半宽 960**：`Scroll View` 的 pivot 在**左沿**（0,0.5）、`Viewport` 的在
  **中心**（0.5,0.5）（两条都从 prefab 的 RT 实读）⇒ 在 `Scroll View` 的局部坐标里 `Viewport.localPosition.x = 960`。
  **我们**这边两件的 `localPosition` 都是 0（`MenuDraw.Node` 一律「矩形中心对矩形中心」）⇒ 直接抄字段会**恒得 0、静默丢掉整条错峰**
  ⇒ 取等价量 `ScrollView.W × 0.5`（`RewardWindow.PunchRefPx`）。
- ⚠️ **基准向量 `(1,1,1)` 是「结构推断」不是字面量**：`UnityEngine.Vector3` 的静态字段序
  （`0x0 = zeroVector` / `0xC = oneVector`，各 12 字节），旁证 = 同一个地址在另两处也都当 scale 用
  （`AbilityLogic__CreateTempAbilityTransform.c:79-80` 兜底 `localScale` · `AnimFXModuleTransformModifier__Update.c:34` 兜底缩放）。
  写进「没查清」了（§四·⑥）。
- 归一化距离的**分母**在原始状态下的值：`Viewport` 的 prefab RT 读数是 `m_LocalPosition (0,0)` / `ap (0,0)` /
  `pivot (0.5,0.5)`（`bundle_menus_assets_all`，按 PathID 走树实读）—— 那个 `m_LocalPosition` 对于**拉伸锚**
  的 RT 是**不可信的序列化值**（同文件里 `Content` 那条也写着 `(0,0)` 而它的 `ap.y = −25`），真正生效的是
  「pivot 相对父矩形原点的偏移」= 960。**这一条我按「等价量」处理并出声**，不去猜运行时读数。

### ⑥ 顺手修的真缺陷（白名单内）

- `DailyData.RewardStateOf` 原来**只判 `i < RewardsCollected`（常量 2）**、**完全没读 `_rewardClaimed[]`**
  —— 而 `_rewardClaimed[]` 全工程**只写不读**（`grep` 过：`Shell/DailyData.cs:473` 声明 · `:528` 写）。

  ② `CollectReward` 的守卫问的就是这个状态 ⇒ **同一格能无限重领**（每点一下再发一份奖励）。
- 修法 = 把「已领」判成 `i < RewardsCollected || _rewardClaimed[i]`（原版那一侧 `collectedRewards` 是服务端下发的
  「已领到第几天」⇒ 我们这边就是这两项之和）。**这不改任何既有自检的期望值**（那一刻 `_rewardClaimed` 全 false）。
