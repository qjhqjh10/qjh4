## 四、断言（位置 / 内容 / 改坏法）

**位置**：`Editor/MainMenuScene.cs:694`（主菜单那节）· `Editor/MainMenuScene.cs:1691`（练习窗那节）。
**形状**：与 A218 完全同款 `System.Action<Transform,string,float,float,string>` 探针 ——
每条先断两条**前提**（节点在 + `RectTransform` 在 + `lossyScale.x == 1`），再**分别**断 `rect.width` 与 `rect.height`
== `LayoutSpace.Px(原版 px)`（tol 0.01 世界单位 ≈ 1.08px）。

**内容（期望值独立来源，⛔ 不读被测实现）**：一律**字面量 + 出处字符串**，**一个字都没引用**
`MainMenuRuntime` 的常量、也没引用 `PracticeModePopup` 的 `InfoL/DlL/ArmL/DecksL/ArmVpL/DecksVpL/DecksCL`
（引用了就是「拿我们的实现证明我们的实现」）。

**🔴 两态（三态）可分辨 —— 两处各有一对「同一个工厂、两对入参」**：
- **练习窗最硬**：`Army Selector/Viewport` 与 `Decks Scroll view/Viewport` —— **同名、同一段代码、两对入参**，
  **177.12×764.21** vs **373.60×540.79**；再加 `Content` 的**高 = 0** ⇒ 三态互斥，
  把任一对写死进工厂（或只断一条）都会在另一条上红。
  （另：`Army Selector` 本身 697.99 与它的 `Viewport` 764.21 也成一对 —— 差 66.22，防「整窗统一取一对」那类糊弄。）
- **主菜单**：`Upper bar` **1920×100** vs `Player Level` **53.12²**（差三个数量级）；
  `Avatar Item Small` 138.42×139.568 vs `ChatPreview` 400×60（宽高比互为倒数）⇒ 弱断言过不了。

**改坏法**（逐条写进了两节的头注释）：
1. 删掉 `MenuDraw.SetPxSize` 那一跳（或把工厂改回「只建节点」）⇒ **两节每一条**的 `rect.width/height` 都变 0 ⇒ 全红。

4. `PracticeModePopup.New` 那一转调改成 `ApplyPxRect` + 自己算位置 ⇒ **位置不会变**（`Local3` 与 `MenuDraw.Local` 同式）
   ⇒ **这两节不测位置**（位置由本窗既有的 `CheckAt`/`CheckAtWorld` 那几十条守着，如实记 —— 别指望这一节兜住）。
