## 三、A304：`Editor/BattleScene.cs` 落位检测器的改法与「改坏法」

**现状（`atSlotStep` 那一行）**：原写法 `Vector3.Distance(view.transform.position, **slotPos**) < 0.02f`，
其中 `slotPos = pBoard.DropTargetWorld(freeSlot)`（`:1700`，**拖拽用的那个点**）。**两处独立地错**：

1. **靶取错了** —— 落位补间飞向的是 **`which.SlotPosition(land)`**（`Hand/CardInteraction.cs:442`：
   `DeploySequence.Play(card, which.SlotPosition(land), …)`），**不是** `DropTargetWorld`。
   3D 下两者相差 **0.73 世界单位（≈79px）**，判据 = **实测日志原文**（2026-10-01 `BattleScene.log:4250`）：
   `Release：指针世界 (-5.84,-0.89)`（= `DropTargetWorld(0)`）vs `SlotPosition(0) = (-5.532,-1.556)`。
2. **跨 z 层次** —— `DropTargetWorld` 走 `LayoutSpace.ScreenToWorld`，那个函数**末尾强制 `w.z = 0f`**
   （`Core/LayoutSpace.cs:86`），而 3D 下卡摆在 `ArenaSlots.RootPosition(…)`（`z = PlayerZ = -6.655`，`Board/ArenaSlots.cs:58`）。

⇒ 距离恒 ≫ 0.02 ⇒ **检测器从 3D 落地那天起一次都没触发过**，而它**不报错、只打一个负数**：
四份日志全打 `-0.03s`（= 哨兵 −1 ÷ 30）；2D 时代（`BattleScene_0919*.log`）打的是 **0.27s**，那是真的。

**改法**（`Editor/BattleScene.cs` 拖拽上场那一段）：
```csharp
var arrivePos = pBoard.SlotPosition(freeSlot);          // 同一个空间的点（世界坐标 · 与补间终点逐值相同）
for (int i = 0; i < 180 && ctx.Players[0].Board[freeSlot] == null; i++)
{
    Step(1f / 60f);                                     // 🔴 采样从 30Hz 收到 60Hz（理由见下）
    landSteps++;
    var pNow = view.transform.position;
    if (atSlotStep < 0 && new Vector2(pNow.x - arrivePos.x, pNow.y - arrivePos.y).magnitude < 0.02f)
        atSlotStep = landSteps;
}
float landSec = landSteps / 60f;                        // `landSec` 语义不变（= 引擎填格那一刻 ≈ 0.30s）
```

**为什么把采样也收了**（这一条与简报给的最小改法**不同**，理由写死在这里）：
落位补间末段是 `OutCubic`（`DeploySequence.cs:62`）—— 它**在到达前一帧才收敛到 0.02 以内**，
而 30Hz 采样下「收敛那一刻」**紧贴补间完成帧**；补间一完成，`OnCardDeployed` 就在**同一个 Step 里**
把卡摆到 `ArenaSlots.RootPosition`（3D 位姿，与 `SlotPosition` 差 2.16 世界单位）⇒ 那一刻**观测不到**。
**定量**：3D 下补间末段长 `|S − lift| = 1.329`（由日志里的真实坐标算出），OutCubic 在 30Hz 的倒数第二帧
剩余比例 ≈ 0.0183 ⇒ 距离 ≈ **0.0243 > 0.02（差 22%）**；收到 60Hz 后倒数第二帧剩余 ≈ 0.0006 ⇒ 距离 ≈ 0.0009，
**20 倍余量**。⚠️ 旧写法在 2D 时代能量到 0.27s，是因为那时 `slotPos` **就是**补间终点（`DropTargetWorld` 在非 3D 下
`return SlotPosition(slot)`）—— 本改在非 3D 路径上与原写法**逐位等价**。

**验收用的新断言（3 条，逐条带改坏法）**：

| # | 断言 | 位置 | 🧨 改坏法 |
|---|---|---|---|
| 1 | `★ 卡到格位那一刻真的被检测到（atSlotStep ≠ −1）` | `BattleScene.cs` 拖拽上场段 | 把 `arrivePos` 换回 `slotPos` ⇒ 靶差 0.73 ⇒ 恒 −1 ⇒ 红；把 `new Vector2(…).magnitude` 换回 `Vector3.Distance` ⇒ z 差 6.655 ⇒ 红；步长退回 `1f/30f`（而 `landSec` 仍除 60）⇒ 采样跨过收敛窗口 ⇒ 也可能红 |
| 2 | `★ SetAutoFitBox(…, basePx: 45.2) 把 m_fontSizeBase 写成 45.2px` | `BattleScene.cs` §4.6c | `Battle/Label.cs` 里 `float baseCur = basePx > 0f ? … : cur;` 改回 `= cur`（或删掉 `_tmp.fontSize = baseCur;`）⇒ 量出来是 40 ⇒ 红 |
| 3 | `★ 不传第 5 个实参时 base 仍是调用方那一档 30.6px` | 同上 | 把 `basePx > 0f` 写成 `basePx >= 0f`（0 也当真值）⇒ base 被写成 0 ⇒ 红（0 是**合法值**，这正是「缺省 0」必须与「真的 0」分开的原因） |

期望值取自**原版资产字段**（45.2 是 `Booster Info Popup/Text/Title` 的实读值），⛔ 不是我们自己的常量。
