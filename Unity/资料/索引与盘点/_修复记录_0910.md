## A4. 还原 4 个 0 字节 TTF ✅

**做了什么**
`10_字体/` 下 4 个 `.ttf` 原本全是 0 字节，数据完整躺在同名 `Font_*.json` 的 `m_FontData` 里。新脚本
`d:/2/Warpforge_tools/scripts/restore_fonts.py` 从 JSON 无损还原，并处理了 TTC 问题：

| 落盘文件 | 来源 JSON | 字节数 | 说明 |
|---|---|---|---|
| `10_字体/fonts/NotoSerifCJK-Regular.ttf` | `fonts/Font_363839005159822707.json` | 23,613,200 | TTC 拆出的 **Noto Serif CJK SC** 子字体 |
| `10_字体/resources/NotoSerifCJK-Regular.ttf` | `resources/Font_52.json` | 23,613,200 | 同上（两份 JSON 的 `m_FontData` MD5 完全相同：`776e130c…`） |
| `10_字体/resources/LiberationSans.ttf` | `resources/Font_54.json` | 350,200 | 原样还原（magic `\x00\x01\x00\x00`） |
| `10_字体/resources/PerfectDOSVGA437.ttf` | `resources/Font_53.json` | 81,192 | 原样还原 |

- `NotoSerifCJK-Regular` 的原始数据是 **TTC 集合**（`ttcf`，内含 JP / KR / SC / TC 四个字体，原始 24,810,096 B）。
  **Unity 不认 TTC**，所以脚本用 fontTools 拆出**简体中文 SC**（游戏是中文界面）写成 `.ttf`。
  需要其它语言：`restore_fonts.py --apply --all-subfonts`（或 `--lang KR`）。
- 安全策略：目标已存在且非 0 字节且内容不同 → 改写 `<name>__restored.<ext>` 并告警，**绝不覆盖**。
  本次 4 个目标都是 0 字节占位，属于正常的「覆盖占位」。

**验证方式与结果**
1. `restore_fonts.py --verify` → **181 个源，0 个问题**（TTC 用「重新拆一次 + 语义指纹」比对，
   指纹 `4e68b63ed5` 一致；逐字节比对会有 6 B 噪声，是 fontTools 重算 `head.modified`/`checkSumAdjustment` 所致，非内容差异）。
2. fontTools 逐个打开：`Noto Serif CJK SC`（65,535 glyph，中文全覆盖 ✅）、`Liberation Sans`（2,587 glyph）、
   `Perfect DOS VGA 437`（256 glyph）。
3. 幂等性：再次 `--apply` 会全部识别为「已一致(语义指纹)」跳过，不会产生 `__restored` 垃圾文件（已实测）。

**遗留**
- 拆出的 SC 是 **CFF/OpenType 轮廓**（magic `OTTO`）而文件名叫 `.ttf`。Unity/FreeType 能正常导入；
  若导入器挑扩展名，把副本改名 `.otf` 即可。JP/KR/TC 三个子字体**没有落盘**（需要时用 `--all-subfonts`）。
- 顺带更新了 `说明书/10_资源清单/字体.md`（原写「4 ttf 在用」，实际是 4 个空文件）。
