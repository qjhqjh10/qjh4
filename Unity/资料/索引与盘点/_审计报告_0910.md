## 2. 🔴 A 类：会影响复刻正确性

### A1. `06_模型/` 的所有 OBJ 是 X 镜像几何（最高优先级）

> ## ⚠️⚠️ 2026-09-10 事后更正：本条结论**对 Unity 是反的**，请勿按原方案执行 ⚠️⚠️
>
> **数据比对没错**（obj 顶点确实 `== -x × bundle 顶点`，UV 也确实没被镜像，已复验：`原样diff=4.35e-09`）。
> **但「进 Unity 会左右反」这个推论是错的** —— UnityPy 导出做的是 Unity(左手系) → OBJ(右手系) 的转换，
> 而 **Unity 的 OBJ 导入器会再做一次反向转换，两次恰好抵消**。
> 若在导入前先"还原"一次，Unity 再转一次 → 每个网格**内部被镜像**（多翻了一次）。
>
> **实拍 A/B 验证**（battlearena1，只换回 3 个代表网格）：
>
> | OBJ 处理 | 渲染结果 |
> |---|---|
> | **原样拷贝**（推荐） | 哥特教堂在**左上**，与原版参照图 `Unity参照管线_0825/shots_battle/unity_battlearena1_RT2_0825.png` **一致** ✅ |
> | 先还原手性 | 教堂跑到**右上**，28 个网格全部内部镜像 ❌ |
>
> 教堂是最不对称的物体，所以最容易看出；其余物体只是"看着有点怪"，不会报错。
>
> **正确做法：原样 `shutil.copy2`，不要做任何手性还原。**
> `gen_unity_arena_manifest.py` 的 `copy_assets()` 已按此改回，并留了注释说明原因。
> `restore_obj()` 函数保留但**不再被调用**（供 Godot 侧或其他场景参考）。
>
> 教训：**顶点级的数值比对不足以下结论，必须实拍比对**。顶点数据"对不上"不等于渲染会错 —— 导入器本身可能带反向转换。


**问题描述**
`06_模型/` 下 1,030 个 `.obj`（按来源包分成 16 个子目录）**不是 Unity 原始顶点数据**。UnityPy 的 `MeshExporter.export_mesh()` 在导出时做了「顶点 x 取负 + 面绕序反转」的左手→右手转换（该转换不完整：UV 的 u 没有一起镜像）。用户拿这些 OBJ 在 Unity 里摆场景，**每一个网格都是左右反的**，而且因为绕序也反了，背面剔除/法线方向同时是错的。

**证据**
用 UnityPy 从原始 bundle 解出 `m_VertexData`（手动按 channel 偏移解析 float32 顶点），与磁盘上的 OBJ 顶点逐一比对：

```
=== battlearena1 bundle meshes: 28  objs: 28
    'Back background': stride=32 bundle顶点=294 obj顶点=294 原样diff=142.55  镜像diff=4.96e-08 -> X镜像
    'Background Building 1':        bundle顶点=4   obj顶点=4   原样diff=20.631  镜像diff=4.27e-08 -> X镜像
    'Background':                   bundle顶点=4   obj顶点=4   原样diff=306.67  镜像diff=3.94e-07 -> X镜像
=== battlearena2
    'Pump support1':  stride=32 bundle顶点=4  obj顶点=4  原样diff=0.025088  镜像diff=4.85e-11 -> X镜像
    'Tower_Silk_11':  stride=48 bundle顶点=41 obj顶点=41 原样diff=0.0098777 镜像diff=4.98e-12 -> X镜像
    'Steam pipes 11': stride=32 bundle顶点=11 obj顶点=11 原样diff=0.029958  镜像diff=4.95e-11 -> X镜像
    'Rope1':          stride=32 bundle顶点=9  obj顶点=9  原样diff=0.0080926 镜像diff=4.08e-11 -> X镜像
```
即 `obj_vertex == (-x, y, z) * bundle_vertex`（误差 1e-7 量级 = float32 精度），**无例外**。
工具链自己早就知道这件事 —— `Warpforge_tools/scripts/unity_scene_to_godot.py:2818` 的 `fix_obj_xmirror()` 注释写着：
> "UnityPy MeshExporter 导出 OBJ: 顶点 x 取负 + 面绕序反转，但 UV 不镜像 … 每个网格绕枢轴水平镜像"

但那个修复只在 **Godot 管线**里对副本做（且会在原文件上打 `.xfixed` 标记 —— 幸好 `解包整理/` 下 `.xfixed` 文件数为 **0**，原始 OBJ 未被就地改过），**Unity 侧的 `gen_unity_arena_manifest.py` 直接 `shutil.copy` 这些 OBJ 进 Unity 工程**，没有任何还原。

**影响**
用户在 Unity 里复刻的 battlearena1 场景，**28 个网格全部左右镜像**。这不会报错，只会"看起来不太对"——和贴图朝向类的坑一样难查。

**修复方案** `[可自动修复]`
不要去动 `06_模型/` 的原始文件（Godot 管线在消费它们）。正确做法是在 Unity 侧导入前还原，二选一：

- **方案 A（推荐）：在 Unity 侧还原。** 给 `gen_unity_arena_manifest.py` 的 `copy_assets()` 加一道 `restore_unity_handedness()`：写 OBJ 时把 `v`/`vn` 的 x 取负、`f` 的索引倒序（与 `fix_obj_xmirror()` 完全一致，只是写到目标目录而不是就地改）。
- **方案 B：生成一套并行目录** `06_模型_unity/<来源包>/`，保留 `06_模型/` 原样。

> ⚠️ 注意：`f` 行的还原是 **索引倒序** `' '.join(p[3:0:-1])`，不是换两个索引。另外 OBJ 里 `vt`（UV）**不要动**（UnityPy 没镜像 UV），否则会从"几何镜像"变成"图案镜像"。

**脚本** `d:/2/Warpforge_tools/scripts/restore_obj_x.py`（新建）：
```python
# -*- coding: utf-8 -*-
"""restore_obj_x.py — 把 UnityPy 导出的 X 镜像 OBJ 还原成 Unity 原始手性。
用法: py312/python.exe restore_obj_x.py <src_dir> <dst_dir>
      # 例: ... restore_obj_x.py d:/2/解包整理/06_模型 d:/2/解包整理_unity/06_模型
只读取 src，全部写到 dst，绝不修改源文件。"""
import os, sys

def restore(src, dst):
    os.makedirs(os.path.dirname(dst), exist_ok=True)
    out = []
    with open(src, encoding="utf-8", errors="replace") as f:
        for l in f:
            p = l.split()
            if not p:
                out.append(l); continue
            if p[0] in ("v", "vn") and len(p) >= 4:
                out.append("%s %.9G %.9G %.9G\n" % (p[0], -float(p[1]), float(p[2]), float(p[3])))
            elif p[0] == "f" and len(p) >= 4:
                # UnityPy 写出顺序 = f c b a（绕序已反）→ 倒序即为 Unity 原绕序
                out.append("f " + " ".join(p[3:0:-1]) + "\n")
            else:
                out.append(l)          # vt / o / g / usemtl / mtllib 原样保留
    with open(dst, "w", encoding="utf-8") as f:
        f.writelines(out)

def main():
    src, dst = sys.argv[1], sys.argv[2]
    n = 0
    for dp, dn, fn in os.walk(src):
        for f in fn:
            if not f.lower().endswith(".obj"):
                continue
            rel = os.path.relpath(os.path.join(dp, f), src)
            restore(os.path.join(dp, f), os.path.join(dst, rel))
            n += 1
    print("还原 %d 个 OBJ -> %s" % (n, dst))

main()
```
验收：还原后重新比对，应满足 `obj_vertex == bundle_vertex`（`原样diff < 1e-5`）。
> 已核对：`06_模型` 全树 **565,537 行 `f` 全部是 3 顶点三角形**（token 数一律为 4，如 `f 3/3/3 2/2/2 1/1/1`），所以上面的 `p[3:0:-1]` 倒序不会漏顶点。

### A2. 材质 `blend` 字段不可靠 —— 判据应换成 `_SrcBlend`/`_DstBlend` + `_AlphaClip`

**问题描述**
清单/说明书里那个 `blend` 列取自材质 JSON 的 `_Blend` 浮点。Warpforge 用的是自定义 Shader（关键字是 `_APPLYAMBIENTCOLOR` / `_ALPHATEST_ON` 这类，**没有** URP 的 `_SURFACE_TYPE_TRANSPARENT`），`_Blend` 在这个 Shader 里基本恒为 0，**与真实混合态无关**。

**证据 1 —— 字段自相矛盾**（`07_场景/battlearena1/Material/`，`Platform Flag*` 用的 `BattleArena1 Texture Bake results-wind`）：
```
_Blend = 0.0     ← 清单/说明书据此写"不透明"
_SrcBlend = 5.0  (_SrcAlpha)
_DstBlend = 10.0 (_OneMinusSrcAlpha)   ← 这是教科书式的 Alpha 混合
```
**证据 2 —— 全量统计**（`mat_blend.py`，扫描全部 Material JSON 的 `m_Floats`）：

| 范围 | 材质总数 | `_Blend=0` 但 `_SrcBlend=5/_DstBlend=10`（真 Alpha 混合） | 真不透明 (`1/0`) |
|---|---|---|---|
| `07_场景/**` | 350 | **126 (36%)** | 40 |
| `08_预制体特效/战斗预制体/**` | 1,142 | **522 (46%)** | 164 |

**证据 3 —— 同一个 `blend` 值覆盖了 4 种完全不同的渲染状态**（`07_场景` 分布）：
```
_Blend  _SrcBlend _DstBlend  RenderType           数量
2.0     5.0       1.0        Transparent          114   (预乘 Alpha)
0.0     5.0       10.0       Transparent          110   ← 被误判为不透明
0.0     None      None                            40
1.0     None      None                            26
0.0     1.0       0.0        Opaque                22
0.0     5.0       10.0       (无标签)              16   ← 同样被误判
0.0     1.0       0.0        TransparentCutout     10
```
**证据 4 —— "贴图有 alpha 就当作要混合"也不够。** 用户举的例子 `Battle Arena 1 Background` 实际**确实是不透明材质**（`RenderType=Opaque`, `_ZWrite=1`, `_AlphaClip=0`），但它的贴图 **72.1% 不透明 / 25.9% 全透明**，且透明区 RGB **不是黑色**（是有内容的白/灰）——所以照"不透明"渲染会糊成大白板，用户的症状描述是对的，**但根因是"贴图需要 alpha 裁切/混合，而材质标了 Opaque"**，不是单纯的字段读错。

逐图像素统计（`battlearena1/Texture2D/`，`tex_pixels.py`）：
```
Battle Arena 1 Back  Background.png   2048x2048  不透明 12.5%  全透明 86.8%  半透明 0.6%   透明区纯黑 0
Battle Arena 1 Background.png         2048x2048  不透明 72.1%  全透明 25.9%  半透明 2.1%   透明区纯黑 0
Battle Arena 1 Floor.png              4096x4096  不透明 64.5%  全透明 35.2%  半透明 0.3%   透明区纯黑 0
BattleArena1 Texture Baked.png        2048x4096  不透明 23.8%  全透明 71.6%  半透明 4.6%   透明区纯黑 1
spacemarine droppod.png               64x64      不透明 25.1%  全透明 41.5%  半透明 33.4%  通用
```
注意 `Background Building 1/2` 用的是**另一份材质** `Battle Arena 1 Background Alpha`（`_ALPHATEST_ON`, queue 2450, `_AlphaClip=1`），**同一张贴图**。即原版作者就是靠材质变体区分"不透明 / Alpha 裁切"的 —— 材质本身是权威，但判据不是 `_Blend`。

**影响**
按清单 `blend` 列在 Unity 里建材质 → 126+522 个材质丢失透明度；同时反向错：`blend=2.0` 的 114 个（预乘 SrcBlend=5/DstBlend=1）会被当成普通 AlphaBlend，边缘发黑。

**修复方案** `[可自动修复]`
改 `Warpforge_tools/scripts/gen_unity_arena_manifest.py` 的物料字段产出与 `unity_scene_to_godot.py` 的 `MatInfo.is_transparent()`：
1. `_Blend` 只作为**辅助**，不再单独决定渲染模式；
2. 新增权威字段 `srcBlend` / `dstBlend` / `alphaClip` / `renderType` / `renderQueue`（这些 JSON 里全都有，`parse_mat()` 也已读出，只是没被 emit）；
3. `is_transparent()` 改为：
```python
def is_transparent(self):
    if self.src_blend == 5.0 and self.dst_blend in (10.0, 1.0):
        return True                      # SrcAlpha / OneMinusSrcAlpha 或预乘
    if '_SURFACE_TYPE_TRANSPARENT' in self.keywords or '_ALPHABLEND_ON' in self.keywords:
        return True
    return False
```
4. 对 `src_blend=1, dst_blend=0`（真不透明）但贴图透明像素 > 15% 的材质，输出一条告警让人工决定用 Cutout 还是 Blend；给 `_AlphaClip=1` 的加 `_ALPHATEST_ON` → Unity 里用 `Alpha Clipping`。

**建议同时补的"贴图 alpha 判定"脚本** `d:/2/Warpforge_tools/scripts/tex_alpha_report.py`（新建）：
```python
# -*- coding: utf-8 -*-
"""对每张战场贴图输出 alpha 健康度，供人工/AI 判断 Cutout / Blend / Opaque。"""
import os, sys, json, collections
sys.stdout.reconfigure(encoding="utf-8")
from PIL import Image
ROOT = r"d:/2/解包整理"
out = {}
for dp, dn, fn in os.walk(ROOT):
    if "Texture2D" not in dp:
        continue
    for f in fn:
        if not f.lower().endswith(".png"):
            continue
        p = os.path.join(dp, f)
        try:
            im = Image.open(p).convert("RGBA")
        except Exception:
            continue
        px = im.getdata()
        n = len(px)
        op = sum(1 for *_, a in px if a > 250)
        cl = sum(1 for *_, a in px if a < 5)
        out[f[:-4]] = {"w": im.width, "h": im.height,
                       "opaque%": round(100*op/n, 1), "clear%": round(100*cl/n, 1),
                       "path": os.path.relpath(p, ROOT).replace("\\", "/")}
json.dump(out, open(r"d:/2/Warpforge_tools/data/tex_alpha.json", "w", encoding="utf-8"),
          ensure_ascii=False, indent=1)
print("已写 tex_alpha.json:", len(out), "张")
```

```python

"""quarantine_second_pass.py — 隔离「第二遍解包」产生的重复文件。
只处理文件名满足 `X` / `X_<pathID>` 前缀关系的重复组（189,656 组 / 215,382 文件）；
「不同对象内容恰好相同」的 409 组一律保留。
默认 dry-run；--apply 才真正移动（移动到 d:/2/解包整理_第二遍冗余/，保留相对路径，可整体搬回）。
用法:
  py312/python.exe quarantine_second_pass.py                 # dry-run, 只出清单
  py312/python.exe quarantine_second_pass.py --apply         # 真正搬走
  py312/python.exe quarantine_second_pass.py --delete        # 直接删除 (危险, 需再确认)
"""
import os, re, sys, json, hashlib, shutil, collections

sys.stdout.reconfigure(encoding="utf-8")
ROOT = r"d:/2/解包整理"
QUAR = r"d:/2/解包整理_第二遍冗余"
LIST = r"d:/2/Warpforge_tools/data/second_pass_files.txt"
SUF = re.compile(r"^(.+?)_(-?\d{5,})(?:_\2)?$")

def md5(p, bs=1 << 20):
    h = hashlib.md5()
    with open(p, "rb") as f:
        while True:
            b = f.read(bs)
            if not b: break
            h.update(b)
    return h.hexdigest()

def main():
    apply_ = "--apply" in sys.argv
    delete_ = "--delete" in sys.argv
    by_size = collections.defaultdict(list)
    for dp, dn, fn in os.walk(ROOT):
        for f in fn:
            p = os.path.join(dp, f)
            try: by_size[os.path.getsize(p)].append(p)
            except OSError: pass

    groups = collections.defaultdict(list)
    for sz, ps in by_size.items():
        if sz == 0 or len(ps) < 2: continue
        for p in ps:
            try: groups[md5(p)].append(p)
            except OSError: pass

    to_move, skipped = [], 0
    for h, ps in groups.items():
        if len(ps) < 2: continue
        stems = [os.path.splitext(os.path.basename(p))[0] for p in ps]
        m = SUF.match(stems[0])
        # 必须是「同对象重复」形态: 组内存在一个 stem 是另一个 stem 的 <name>_<pid> 形式
        redump = False
        for i, s in enumerate(stems):
            for j, t in enumerate(stems):
                if i == j: continue
                mm = SUF.match(t)
                if mm and mm.group(1) == s:
                    redump = True; break
            if redump: break
        if not redump:
            skipped += len(ps); continue
        canon = min(ps, key=lambda p: (len(os.path.basename(p)), p))
        to_move += [p for p in ps if p != canon]

    print("将隔离:", len(to_move), "个文件;  保留(内容相同的不同对象):", skipped)
    os.makedirs(os.path.dirname(LIST), exist_ok=True)
    with open(LIST, "w", encoding="utf-8") as f:
        for p in to_move:
            f.write(os.path.relpath(p, ROOT).replace("\\", "/") + "\n")
    print("清单:", LIST)
    if not (apply_ or delete_):
        print("dry-run 结束。加 --apply 搬走 / 加 --delete 删除。")
        return
    for p in to_move:
        rel = os.path.relpath(p, ROOT)
        if delete_:
            os.remove(p)
        else:
            dst = os.path.join(QUAR, rel)
            os.makedirs(os.path.dirname(dst), exist_ok=True)
            shutil.move(p, dst)
```
