（`PlayerActions.cs`：`playCard=0 … clickWaystone=6`）。原版把这一族挂在**攻击类型选择器**上，
**一个阵营一个**，配一枚专属按钮图：

| 中文 | 英文 | 阵营（`CardArmy`） | 谁能做 | 代价 / 限制 | 我们卡表命中（按 `desc`） |

## 三、逐个机制（【读】出处逐条给）

### 3·1 祈祷 `Pray`（修女会）

- 链：卡效果 `AbilityEffect.triggerPray = 462` → 入队 `BattleActionType.triggerPray = 82` → `BattleManager.ResolveTriggerPray`
  → `CardScript.SetPray(true)`（体就是 `EntityScript.set_isPraying`，写 **`+0x67`**）→ `BattleManagerSupport.BroadcastUnitPray`。
- **状态位【读】**：`EntityScript` 字段表 `private bool <isPraying>k__BackingField; // 0x67`（`dump.cs`，TypeDefIndex 429）。
- 广播顺序【读】`BattleManagerSupport__BroadcastUnitPray.c`：**场上所有在演的牌 → 当前回合方手牌 → 另一方手牌**，逐个
  `CardScript.TriggeredPray`（= `AbilityTrigger.TriggeredPray = 660`）。
- **清除点两处【读】**：`CardScript__OnTurnStart.c`（`+0x67 = 0`，即持续到控制者下个回合开始）·
  `CardScript__ResolveDamageDealt.c`（**挨打立即中断**）。
- 目标筛选用 `UnitConditions.isPraying = 243`（「选一个正在祈祷的单位」那类卡）。
- ⚠️ **「Slow」没查到定义**：规则书只写「缓慢的非战斗行动」，**全书没有 Slow 的定义段**，
  反编译里也**没有** slow 这个 trait ⇒ 「部署当回合不能用」这一条**别当成原版语义**（见 §五）。

### 3·2 职责 `Duty`（星界军）

- 【读】`CardScript__UsedActiveAbility.c`：`HasCurrentTrait(0x4c4) → BattleManager.BroadcastUnitDuty(bm, card)`。
- **本局一次【读】**：标志位 = `EntityScript.usedActiveAbility`（**`+0x4c`**，bool —— 由 `EntityScript__get_usedActiveAbility.c` /
  `__set_usedActiveAbility.c` 两个文件坐实偏移；⚠️ Ghidra 把这两个函数的符号名错写成 `RoomInfo__get_serverSideMasterClient`，
  **以文件名和偏移为准**）。重置**只有** `AbilityEffect.resetDuty = 475` → `BattleActionType.resetDuty = 87` → `ResolveResetDuty`；
  **没有任何 turn-start / turn-end 会复位它**。
- 规则书另有一句：「震荡突击兵（Shock Trooper）的职责**即使不能攻击也能激活**」。

### 3·3 狂暴 `Ferocity`（太空野狼）

- 【读】`CardScript__UsedActiveAbility.c` 尾部：`HasCurrentTrait(0x4f1) → BroadcastUnitFerocity`；
  然后**除非** `HasCurrentTrait(0x4f6 = 1270 = dontReturnFerocity)` **或** `CardScript.EnoughPendingDamageToDie`，
  否则 `BattleManager.AddRecallToDeck(bm, card, isPlayer, 0, 3, …)` = **洗回牌库**（不是弃牌堆）；
  最后遍历 `card+0x108` 那张 effect 表，逐条 `SendRemoveEffect(…, 1)` 清掉本卡身上的 effect。
- 规则书把 `Ferocity` 与 `Fast` / `Flank` 并列豁免「部署当回合不能行动」。

### 3·4 议程 `Agenda`（暗黑天使）

- 【读】`CardScript__UsedActiveAbility.c`：`HasCurrentTrait(0x4d3) → TriggerAbilitySignal(0x2c1 = 705 = AbilityTrigger.Agenda)` + `Signal.Raise`。
- 🔴 **它没有 `BroadcastUnitAgenda`** —— 其余四个都有 `BattleManagerSupport.BroadcastUnitXxx`，只有议程走裸 `Raise`。
  **是设计如此还是反编译缺函数：没查到。**
- 结算内容（「+1 任务点」等）挂在卡的 `activeAbilityLogic` 上 = **服务端数据**，本地只有外壳（§五）。

### 3·5 誓言 X `Oath X`（极限战士）—— **机制与前四个完全不同**

- 【读】`CardScript__UsedActiveAbility.c`：`HasCurrentTrait(0x4fb) → BattleManager.PayActiveAbilityCostOath(bm, card)`
  → `TriggerAbilitySignal(0x2da = 730)` + `Raise`。
- **付 X 点能量**（不是免费）：`BattleManager__PayActiveAbilityCostOath.c` 取 `GetCurrentTraitValue(card, 0x4fb)` 当 X，
  再 `PlayerManager.UseMana(owner, X)`；付完立刻 `CheckIfCodexTriggered`（`Codex` = 能量归 0 时触发）并抛 `EnergySpentSignal`。
- **不占单位行动**（`ResolveActiveAbilityPlayed.c` 里 Duty/Ferocity/Oath 共用「主动技能已用」那条路，但 Oath 另有独立分支）。
- **使用次数**：`CardScript__CanUseOathAbility.c` —— 默认**只限部署当回合**（`IsTheSameTurnPlayed` 为真才放行），
  `oathInAllTurns = 1276` 可跨回合；默认**每回合 1 次**，`oathTripleActivation = 1278` 抬到 3 次/回合。
- `BattleManager__IsThereDoubleOathEffect.c` + `AbilityLogic__PlayAbility.c`：场上带 `oathDouble = 1277` 的卡
  会让 `RawCardScript.OnTriggerAlt` **多结算一遍**。
- ⚠️ 原版 `CanUseOathAbility` 在「两个 trait 同时在场」时因为 `&&` 混算，上限会退化成 1（**全池无这种卡**）——
  这条怪癖我们**故意不复现**（`RuleCore.cs` 已注明）。
