# 棋盘「连续无洞」模型 —— 实现与判据（2026-10-01 立）

> **这一条解决的是**：原版棋盘**每侧就是一条连续列表**，插入会把后面的单位整体推出去一格、
> 离场会把外侧的人整体拉回来一格 —— 也就是玩家在拖牌时看到的**「让位」**。
> 我们原来是**固定 9 格数组、允许留洞**（死亡只把那一格置 `null`），
> ⇒ 能摆出原版做不出来的局面，而且**没有让位**。
>
> **正本代码** = `Assets/RuleEngine/Core/BoardSlots.cs`（文件头写全了逐条出处）。
> 本节记「改了什么 / 怎么验 / 还欠什么」。

## 二、我们的格号 ↔ 原版的下标

```
我们：   0    1    2    3   [4=督军]   5    6    7    8
原版：  −4   −3   −2   −1      0      +1   +2   +3   +4
                             （有符号下标：负 = 左侧、正 = 右侧、0 = 督军格）
```
**只差一个 `+4`**：`ourSlot = 4 + origSlot`。侧 = 符号，`该侧第几格` = `|origSlot| − 1`（0 = 贴督军）。
判据 = `MinionManager__AdjustedSlot.c:77-89` 的 `~slot` / `slot-1` 编码 + `GetClosestAvailableSlot` 的回传值。

## 三、我们改了什么

### 3.1 新文件 `RuleEngine/Core/BoardSlots.cs`（模型的唯一判据）

| 函数 | 语义 | 原版对应 |
|---|---|---|
| `SideOf` / `IndexOf` / `SlotOf` | 格号 ↔ 侧 + 下标 | 上面那张表 |
| `Resolve(ps, 请求格, out side, out index)` | 请求格 → **插到哪一侧的第几个下标**（夹到 `[0, 该侧人数]`） | `AdjustedSlot` |
| `Insert(ps, 单位, 请求格)` → 落点 | **插入 + 外移** | `List.Insert` |
| `RemoveAt(ps, 格号)` → 被摘掉的单位 | **摘掉 + 内侧补位** | `List.Remove` |
| `NextWithoutDisplacing(ps)` | 人少的一侧的最外一格（平手走右） | `GetNextSlotWithoutDisplacing` |
| `IsContiguous(ps, out why)` | **不变量**：每侧从贴督军那格起连续无洞 | （原版天然成立） |

### 3.2 引擎里改走这两个函数的写入点（全仓 `Board[] =` 就这几处）

| 位置 | 原来 | 现在 |
|---|---|---|
| `RuleCore.PlayCard` 落格 | `ps.Board[slot] = unit` | `slot = BoardSlots.Insert(...)` —— **`Deploy` 事件/日志用回填后的格号** |
| `RuleCore.CanPlayCard` 的格位闸 | 「不可部署 ‖ 该格非空 ⇒ 拒」 | 「越界 ‖ **那一侧满 4 个** ⇒ 拒」（督军格照原版挑人少的一侧） |
| `RuleCore.DeployFree` 落点 | 「从 0 号格起第一个空格」 | `NextWithoutDisplacing` |
| `RuleCore.CleanupDeaths`（普通阵亡） | `Board[slot] = null` | `RemoveAt` |
| `RuleCore.CleanupDeaths`（**翻面成残骸**） | `Board[slot] = rem` | **不变**（残骸还占着那一格，原版也一样） |
| `RuleCore.TrySwarmMerge` | `Board[slot] = null` | `RemoveAt`（并进去的那张离场 ⇒ 外侧补位） |
| `RuleCore.UseAlternative`（狂暴洗回牌库） | `Board[slot] = null` | `RemoveAt` |
| `RuleCore.EndTurn` 归还抢来的单位 | 「原格空着就还原位 / 否则第一个空格」 | 摘走走 `RemoveAt`、落点走 `NextWithoutDisplacing` |
| `EffectResolver` 回手/回牌库 | `Board[slot] = null` | `RemoveAt` |
| `EffectResolver` 抢单位（`takecontrol`） | 「第一个空格」 | 落点 `NextWithoutDisplacing`；摘走 `RemoveAt` |
| `EffectResolver` **再造残骸（reanimate）** | `Board[slot] = back` | **不变**（原位换人） |

### 3.3 顺带修掉的两个真缺陷（都是这次改模型**逼出来**的）

1. **延后死亡记的是格号 ⇒ 同一批里死两个会漏掉第二个。**
   `BattleContext._pendingDeaths` 原来存 `(方, 格号, 击杀者)`；补位之后先记的格号已经指错人
   （右侧最坏：先摘 5 号格那个 ⇒ 6 号格那个补到 5 号格上 ⇒ 按 6 去处理是**空的** ⇒ **它永远留在场上**）。
   ⇒ 改成**记 `UnitState` 本身**（格号只用于出队排序），处理时按身份现查它在哪一格。
   断言 = `RuleEngineTest.TestBoardContiguousModel` 的 ⑤。
2. **`SimpleAI.FirstFreeSlot` 是「从 0 号格起第一个空格」（我们自己造的）**，在新模型下
   「请求格 ≠ 落点」⇒ 自检/演示拿它当落点会错位。改成原版那条 `NextWithoutDisplacing`
   （请求值 = 落点值）。调用点只有自检与演示（`BattleScene` 7 处 + `RuleEngineTest` 2 处）。
3. **「翻面成残骸」的守卫用的是「那一格还有没有人」** ⇒ 内侧阵亡**永远不播消散**。
   `BattleDriver.PlayDeathFeel` 原来写的是「这一格还站着人 ⇒ 是残骸 ⇒ 别溶解」——
   连续棋盘下**普通阵亡当场就会有人补位进来**（`BoardSlots.RemoveAt`），于是所有内侧阵亡都被
   判成「残骸」而不播消散（画面上人「啪」地消失；自检里那些洞状夹具不会有这个现象
   ⇒ **只有真人玩才看得出来**）。⇒ 改成按**身份**判：只有「那一格站着的确实是**同一张卡**的残骸」
   （`occ.IsRemnant && occ.Card.Name == e.CardId`）才不溶解。
   ⚠️ 连带一条：自检里那两条「残骸 ⇒ 不播消散」的夹具**原来没填 `CardId`**（引擎那边是填的
   —— `CleanupDeaths` 发的是 `u.Name`）⇒ 已被新判据照出来、夹具补上了名字。
   **这正说明判据该按身份**：按「那格有没有人」的话，补位上来的**活人**会被当成残骸。
   断言 = `BattleScene`「连续棋盘上的阵亡」那一组。
4. **表现层要单独存一档「键被补位的人顶掉、但演出还没播」的视图**（`BattleDriver._myFading / _foeFading`）——
   阵亡/回手的演出在事件时间线上**晚一拍**（阵亡 `DeathHold`），而那一格的键马上要给新主人用；
   不存的话演出那一刻 `views[slot]` 已经是**活人**了 ⇒ **溶掉一张活卡**（静默、且只在真人玩时出现）。

### 3.4 表现层

| 件 | 做法 | 出处 |
|---|---|---|
| **单位换了格号要认得出是同一张** | `BattleDriver` 加身份表 `_myUnitViewByUnit / _foeUnitViewByUnit`（单位 → 视图）；`SyncBoard` 发现某单位换了格就**把视图搬过去**（原来会「这格空了 ⇒ 销毁 + 在别处重建」） | 原版也是「摆回去」不是「重建」（`ReassembleMinions`） |
| **换格那一下的补间** | `CardFeel.Reassemble(card, 新局部坐标)` = `DOLocalMove(…, 0.1 s)`（**只动位移**） | `CardScript__UpdateMinionInPlayPosition.c:89` + 上面算出的 0.1 s |
| **拖动中的「让位」预览** | `CardInteraction.OnDropPreview` → `BattleDriver.TickShufflePreview`：每帧把该侧**下标 ≥ 插入点**的单位推向「插进去之后」的位置；松手/取消自己回到真格位 | `ReassembleMinionsWhilePlayingUnit`（逐帧那条） |
| **落点指示点在哪一格** | `CardInteraction.DropLandingSlot`（驱动层接 `BoardSlots.Resolve`）⇒ 指示与落位动画都用**真落点** | 两边同一个判据 |
| **出牌后视图落在哪** | `BattleDriver.DoPlay` 按**实例身份**回填落点（`SlotOfInstance`）—— 拖到哪 ≠ 落在哪 | —— |

⚠️ **两条如实标注的推断**（不是原版值）：
· 补间的**缓动**：原版那句 `DOLocalMove` **没有 `SetEase`** ⇒ 走 DOTween 全局默认（我们取 `Ease.OutQuad`）；
· 「让位预览」是**我们自己的实现**（每帧指数趋近），原版是每帧调一次 `DOLocalMove(0.1 s)` 的补间 ——
  观感接近但**不是同一条实现**，要坐实只能真 Play 并排看。

### 3.5 存档 / 联机的版本闸门

| 件 | 改动 | 为什么 |
|---|---|---|
| `ReplayStore.ReplayRecord.version` | **1 → 2**（读档处改成比 `new ReplayRecord().version`，不再写死字面量） | 旧录像的动作流在新引擎里会落到**别的格号** ⇒ 放出来是另一局，必须**出声跳过** |
| `NetProtocol.Version` | **1 → 2** | 不是消息格式变了，是**引擎语义变了** ⇒ 新旧版互通必然 desync |

## 五、还欠什么（**都记着，别当成做完了**）

1. ✅ **自检夹具里那批「有洞的棋盘」—— 2026-10-01 晚清完**（实测从 **67 处告警 → 0 处**，
   `RuleEngineTest` **3179/3179 全过**）。做法与踩到的坑：
   - **一次算清、一次套用**：`RuleEngine` 那侧的槽位引用**不止一种写法** —— 除了 `Place(ctx,p,S,…)` 与
     `Board(ctx,p,S)`，还有 `Players[P].Board[S]`、引擎调用里的槽位实参（`PlayCard/CanPlayCard/PlayTactic/
     CanPlayTactic/DeclareAttack/UseAlternative/UseOathAbility/CanUseAbility/UseAbility/IsValidTarget/
     CanCollectWaystone/CollectWaystone/AvailableAlternative/CanStartAbility`）—— **少一类就会写出一半新一半旧**，
     症状是 NRE 或「格位非法」（**分批补、反复套用同一个映射** ⇒ 会把已经改过的又改一遍）。
   - **映射 = 把该侧占用的下标压缩成 `{0..n-1}`**（保留相对顺序）⇒ 侧内相邻关系不变，
     变的只有「离督军多远」，所以原来的「相邻」断言照样成立。
   - 🔴 **三处踩过的坑**（脚本 `工具/fix_holey_fixtures.py` 里都写了注释）：
     ① **`ctx2/ctx3/ctx4` 也是上下文** —— 只认 `ctx` 会漏掉 44 处夹具；
     ② **`$"…{x}…"` 里的花括号**会被当成作用域 ⇒ 作用域编号全错、映射套到别的块上
        （判据：`TestAuraSettle` 里 `Board[1] == f2` 被错改成 `Board[2]`）；
     ③ `ctx = …` 才是**上下文重建**（`f1 = Place(...)` 这种不是）；
     ④ **`Board[x] = null`（清格）不该参与「初始布局」的记账** —— 它在断言之后发生，会把映射带偏。
   - ⚠️ **辅助函数摆的盘，脚本看不见**（`Duel(aSlot:3)` / `ToP2TurnWith` 在别的函数里 `Place`）⇒
     这些用例（`TestEffectChainGuard` / `TestAiKillLine` / `TestAiUsesAbility` / AI 那几个）
     **要人工核**：典型症状是**摆到同一个格上把前一个覆盖掉**。人工那半在 `工具/patch_manual.py`。
   - 🔴 **两条语义后果**（不是 bug，是连续模型的必然）：**打死了内侧那个 ⇒ 外侧的会补位**，
     所以「原来 X 号格那张」这类断言要按**补位后**的格号写；`TestStealthUntargetable` / Bjorn's Shrine
     那两处就是这么改的（后者改成量**牌库张数 +1**，那才是「洗回牌库」的直接判据）。
