## 一 · `MeleeEndPos` 传第四参（不改这行，`dy` 就不生效）

### 结论
生产那一行现在传 `tv`（受击方的 `CardView`），走 `CardFeel.MeleeEndPos(Vector3, Vector3, bool, CardView)` 那条重载 ⇒
`dy = EffectsAnchorHeight(tv)` = **锚点到卡底边**的高度，端点按原版那句 `+ up × attackPositionYOffset × dy` 抬高。

### 改动（现读那一版）
`Assets/CardPresentation/Battle/BattleDriver.cs:21961-21971`（`PlayAttackFeel` 的近战支）：
```csharp
Vector3 meleeEnd = CardFeel.MeleeEndPos(v.transform.position, tv.transform.position,
                                        e.Player == _me, tv);   // ⬅ 第四参 = tv
LastMeleeEndPosForTest = meleeEnd;      // 自检口：生产实际传给 MeleeAttack 的端点（只有自检读）
CardFeel.MeleeAttack(v.transform, meleeEnd, home, isPlayer: e.Player == _me);
```
* 上游同作用域本来就有 `var tv = ViewAt(e.TargetPlayer, e.TargetSlot);`（`BattleDriver.cs:21931`），变量名与简报一致（**已 grep 确认，未按行号**）。
* `LastMeleeEndPosForTest` 是**生产也在写**的记账格（先例 = `_attackAnchorPlans`），不是替身 —— 断言读到的就是这一行真用的值。

### 判据出处
* W11 §五 #1 · C6 §2·1；反编译 `d:/2/tools/decomp_full/CardScript._AttackMeleeAnim_d__357__MoveNext.c`：`fVar15 = anchor.position.y − targetCard.position.y`，随后 `× attackPositionYOffset`。
* 三参重载 `CardFeel.MeleeEndPos(…, float dy = 0f)`（`CardFeel.cs:922`）⇒ 不传第四参时 `dy ≡ 0`，正是「整段不生效」的原因。

### 断言（`CardRootAssert.RunMeleeEndPoint`，`CardRootAssert.cs:162`）
走 **生产入口** `driver.PlayAttackFeelForTest(e)`（它调的就是 `PlayAttackFeel`，`BattleDriver.cs:17658`），读 `LastMeleeEndPosForTest`：
1. ★ 端点 == `CardFeel.MeleeEndPos(origin, targetPos, isPlayer, tgt)`（偏差 < 1e-3）；
2. ★ 端点抬高 == `up × AttackPositionYOffset(0.5) × dy`（偏差 < 1e-3）；
3. ★ `dy` 只抬 Y（x/z 逐位不变）；
4. 🧨 **灭自证**：端点与**三参那条**相距 > `0.9 × 抬高量` —— 「改回三参重载」⇒ 这一条红（抬高涨到 0）。
   ⚠️ 门槛用 `wantUp*0.9` 而不是写死 0.02：受击方是 0.36/0.69 档，`dy` 量纲跟着卡走。
* 夹具 = **自己摆两张探针单位**（我方 3 / 敌方 5，贴督军那格）后 `RefreshAll()`，用完恢复（`SaveAndPlaceProbeUnits` / `RestoreBoards`，`CardRootAssert.cs:383 / :418`）。
  理由：这一节跑在整轮末尾，盘面是这一局剩下的 —— ⛔ 不指望「刚好有人」。手法照抄 `BattleScene` 自己的 A849 / E7 两节。

### 改回旧写法会不会红
会。生产那一行不写 `LastMeleeEndPosForTest`（或写的是三参结果）⇒ ① 与 ② 都红、④ 也红。

## 三 · 残骸体挂点（高半张卡）

### 结论
`CardView.SetRemnantBody` 现在把残骸体实例化到**卡底边**（我们的卡根在卡心 ⇒ 局部 `(0, −Height/2, 0)` = `From3DBody(0,0,0)`）。

### 反编译真值（**独立核过**，不是照 W11 推断）
`d:/2/tools/decomp_full/BattleCardUI__CreateRemnantBody.c:54-75`（逐句现读）：
```
this.transform.position  → position
<某静态 Quaternion 字段>  → rotation
Instantiate(prefab, position, rotation, this.transform)   // 第 4 参 = this.transform（父）
```
* `Instantiate(obj, pos, rot, parent)` 的 pos/rot 是**世界**量，而 pos 就取父自己的位置 ⇒ **局部位置 = (0,0,0)**，以**原版卡根**为原点；
* 原版 `CardPrefab` 根 = **卡底边**（C6 §2·1）⇒ 我们的等价局部位置 = 卡底边 = `From3DBody(0,0,0)` = `(0, −Height/2, 0)`。
* 改前传的是 `Vector3.zero`（卡心）⇒ 残骸体（连带 `CardFeel.SpawnRemnantDestroy` 取的落点）**比原版高半张卡**
  （= `Height × 0.5 × 卡的 lossyScale.y`；我方兵 0.36 档 ≈ **0.6 世界单位**）。
* ⛔ **没动 `CardFeel.SpawnRemnantDestroy`**（W11 特意没在那里减，否则会重复扣）。

### 改动（现读那一版）
* `Assets/CardPresentation/Core/CardView.cs:2333`：
  `WarpforgeEffectPlayer.Play(entry, transform, From3DBody(0f, 0f, 0f), 1f, float.PositiveInfinity)`
  （`Play` 第 3 参是**局部**位置 —— 注释里写清了「⛔ 别传 `TransformPoint` 的世界点」）。
* 同文件 `:2222-2226`：类头那条「必须把 localPosition 归零」已就地订正（铁律 5：不留打架的第二份说法）。

### 断言（`CardRootAssert.RunRemnantMount`，`CardRootAssert.cs:73`）

## 六 · 顺手发现（⛔ 一个都没改，只报）

1. **🟠 落定扬尘的【主路】可能也高半张卡（判据已核，没改 —— 不在本批三件之内）**
   * 反编译 `CardScript__LandOnGround.c:52-61` 现读：位置 = **`this.transform.position` + offset**，
     而原版卡根 = **卡底边**（C6 §2·1）⇒ 原版扬尘在地面附近。
   * 我们的主路（`BattleDriver.PlayDeployLandDust` 的 `dustHost != null` 支）是把特效**挂到卡视图**
     （我们的卡根 = **卡心**）上、局部偏移 `up × (LandDustOffsetY / hostScale)` ⇒ 世界位置 = **卡心 + 0.015**，
     **比原版高 `Height × 0.5 × lossyScale`（0.36 档 ≈ 0.6 世界单位）**。
   * ⚠️ `C6 §1·3` 那张表把这一格判成「✅ 对」（只核了「挂卡 + assignScale」两样）；
     本报告只报疑点，**未改**（怕与用户已验收的观感冲突，也超出本批三件）。
   * 修法方向：局部偏移改成 `up × ((LandDustOffsetY − CardUnitH × 0.5 × lossyScale.y) / hostScale)`，
     或干脆不挂卡、按「地面 + offset + `one × desiredScale`」根实例化。**要真机并排一次再定**。
2. **原版 `CreateRemnantBody` 的 rotation 是「世界 identity」这一档**：反编译把第 2 参写成 `Instantiate` 的
   **世界 rotation**（取自该类一个静态 Quaternion 字段），我们 `Play` 保留 prefab 作者的局部旋转。
   ✅ **本次实测**：两具残骸体 prefab（`WarpforgeVFX/Prefabs/RemnantBody3D {Necrons,Aeldari}.prefab`）
   根 `m_LocalRotation` **都是 (0,0,0,1)** ⇒ 今天**没有差异**，所以没改（把这条记下来，免得以后再查一遍）。
   （顺带实测：根 `m_LocalPosition` = Necrons `(101.2, 0, −6.757)` / Aeldari `(100, 0, −3.06)` —— 即注释里那个「后台 x≈100」，`Play` 会归位。）
3. **`CardFeel.SpawnRemnantDestroy` 自动跟着修好了**：它取 `card.RemnantBodyRoot.transform.position`
   （`CardFeel.cs:2836`/`:2850`）⇒ 挂点下移半张卡之后，那颗粒子的落点**一起下移**，无需再动它。
4. **`FireRootInArenaSpace` 与新的 `FireHostFallbackVfx` 不是重复实现**：前者是「载体 + `CardEffects` 钩子」
   （层靠父节点继承、没有缩放口），后者要**显式 `layer` / `desiredScale` / 自检记账**。已在
   `FireRootInArenaSpace` 的 doc 里加了分工说明（`BattleDriver.cs:19420-19433`），免得下个会话当成两份实现合并。
5. **`W11 §六·2`（`SetLayerRec` 两份实现）与 `§六·4`（`AnimFXCheck.cs` 并发写手）不在本批白名单**，没碰。
