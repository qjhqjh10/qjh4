### 2·1 旧断言的判别力缺口（为什么必须改）

| `ClampRangeBig` 的 `v=0.89` → 0.85 | 🟢 绿（只有 `by1` 动、小图档上沿不动） | 🔴 红（BIG 上沿落到 1.0664） |

### 2·2 新断言原文（`CardBaseDemo.cs:1001-1024`）

```csharp

const float ExpBoardCy = -0.044f + 0.5f;                                      // 0.456
```

期望值来源（**全部原版字面量，⛔ 不读 `ClampRangeBig` / `TacticArtScale` / `ArtBoard` / `ArtCoverMargin` / 生产网格**）：

* `2.7484` = 原版 `CardImage` 方框（RT `m_SizeDelta`）
* `0.61` = 原版 `CardScalesByCardType[20]`（战术/防御卡；判据在 `CardBaseDemo.cs:1071-1076` 那段）
* `0.89` = 原版 `_Clamp_Range` BIG 的 v 上沿（`CardView.ClampRangeBig` 的 y 分量）

相对墙保留（`CardBaseDemo.cs:1026-1034`，标签改 `④b`）——它现在的作用是**前提闸**：证明这一档的 BIG 上沿确实被硬矩形压住（画窗上沿更高），且小图档没被收窄到 BIG 那条线上。

### 2·3 「改回旧写法会不会红」判别式

* 删掉 ④a、只留 ④b ⇒ **不会红**（删断言永远不会红）—— 所以判别要看**实现**：
