## 一、结论先行

1. **整体是像的**：左列卡组面板 / 中间督军立绘 + 右侧信息面板 / 底部三件（返回 · 游戏模式开关 · 战斗！）**结构、几何、配色、图标资源全部对得上**。抽查的 8 组矩形与 prefab **逐位相同**（例：`Back button` prefab `pivot(1,0) @(-680,-416.10358)` 64.24×63.24 ⇒ 215.76,892.86→280,956.10 = 我们 `BackL/T/R/B` 一字不差；`Deck Selector` → 我们 `DsL..DsB = 77.10,165.33,610.90,858.19`）。9 行费用曲线、卡背封面、右上圆钮、更换卡组、模式开关的**图名**（`UI_Deck_Selection_Back` / `UI_Deck_Information_Back` / `40k_bt_underbutton` / `40k_gamemode_icon_skirmish|classic` / `40_main_bt_toggle_off` / `40k_UI_bt_deck` / `40k_UI_bt_play`）也**全部与原版一致**。
2. **七格 = 你的卡组(1) + 当前阵营的 6 对预组**，**与原版口径完全一致**（原版 `SetArmyButtons` 把「你的卡组」插在**第 0 格**，预组从 index 1 起；每阵营恰好 6 对 = 78 对 ÷ 13 阵营，`demo_deck_pairs.json` 现读）。**它是「并列插入」不是「替换」**，且**只在「你那副的阵营 == 当前阵营筛选」时才有**。
3. **最严重的三处不一致**（都是**可见**的）：

4. 次一级：**预组卡组的 `Warlord Name` 原版走本地化卡名、我们读英文 `CardDef.Name`**（参考图显示英文是因为当时选中的是**你的卡组**那支 —— 原版那一支恰好用**裸名**）。

## 三、「你的卡组」那一格的条件（用户第 3 问）

### 1. 判定链（全在 `PracticeModePopup__SetArmyButtons.c`，唯一出处）

```
清空列表 → 逐一 SetActive(false)
if (playerDeckInfoWrapper != null) {                    // +0x100，运行期 ScriptableObject
  CardDeck d = wrapper.cardDeck;                        // +0x58
  if (d != null && d.deckHero != null && d.deckHero.army == 当前阵营) {   // +0x40→+0x2c
       Instantiate 一格 → InitializeWithPracticeDeck(item0, this, wrapper, false, mode)
       SetActive(item0, true); SetActive(item0.Highlight, true)          // 默认选中它
       DeckSelected(wrapper, item0)                     // 面板右侧跟着它
       uVar9 = 1; bVar4 = true;                          // ⇒ 预组从 [1] 起
  }
}
foreach (DemoDeckInfoSO so in decks) if (so.GetDeck(mode).deckHero.army == 当前阵营) → 追加一格
if (第一格存在但没被选) SelectItem(第 0 格)
```

- **恒有？不是。** 两个条件同时满足才有：**① wrapper 里那副牌非空；② 它督军的阵营 == 当前阵营筛选**。切到别的阵营 ⇒ 那一格消失，只剩 6 格。
- **并列还是替换？并列（插入）。** 6 对预组**照旧全在**，它只是被插到**第 0 格**（`uVar9 = 1` 把预组整体后移一格）。参考图 7 格 = 印证。
- **格内长相**：名字 = 固定词条 `MenuDeck/Practice/YourDeck`（你的卡组）；图 = `ArmyUtilities.GetArmyIcon(army)`（**阵营徽**，不是这幅牌的插图）；名字条色 = `yourDeckColor`；`Button border` **enabled**；`IsPlayerDeck`（火漆印）**开**。预组格这后两件**都关**。
- **数量**：每阵营 **6 对**（`demo_deck_pairs.json` 现读：13 阵营 × 6 = 78，`kind=="practice"`）⇒ 最大 7 格；格数不在 1~7 之间浮动（要么 7，要么 6，除非该阵营某副缺 `deckId` 才 5）。

### 2. 那副「自己的牌」从哪来（关键，决定「什么情况下可以」）

| 时机 | 赋值点 | 判据 |
|---|---|---|
| 开窗 | `Open()`：`LiveOpsManager.GetHandler()` → `GameModes.GetActiveEvent(currentPlayMode)`；**非空时**才 `ScriptableObject.CreateInstance<PlayerDeckDemoDeckInfoWrapper>()`，把**该事件的 `IPlayEvent.GetEventDeck()`** 写进 `wrapper.cardDeck`，并把 `tutorialIndex = −1`；随后 `ChangeSelectedArmy(deck?.army ?? 10)`（10 = Ultramarines 兜底） | `PracticeModePopup__Open.c` 尾段 |
| 点「更换卡组」 | `DeckGeneralInfoDemo.ChangePlayerDeckButton` → `DeckSelectionPopup` → `DeckChanged` → `PracticeModePopup.PlayerDeckChanged`（**`if (wrapper != null)` 守卫**）→ 写 `wrapper.cardDeck`、归零 selectedArmy、再 `ChangeSelectedArmy(新牌.army)` | `DeckGeneralInfoDemo__ChangePlayerDeckButton.c` / `__DeckChanged.c` / `PracticeModePopup__PlayerDeckChanged.c` |
| 同上附带 | `DeckChanged` 还会 `IPlayEvent.SetDefaultDeck(newDeck, upload:true)`（接口方法表 slot 8 = `SetDefaultDeck(CardDeck,bool)`） | `DeckGeneralInfoDemo__DeckChanged.c:…` |

⇒ **原版这一格是「练功事件登记的那副牌」**：`PracticeModePopup` 是挂在一个 **live-ops 练习事件**上的入口，事件没开（`GetActiveEvent` 返回 null）时 **wrapper 根本建不出来**，`PlayerDeckChanged` 又被 `if (wrapper != null)` 挡住 ⇒ **连「更换卡组」都换不出这一格**，那时只可能用 6 副预组。

### 3. 我们这边

- 离线等价物 = **卡组库里当前那一套**（`YourDeckIndex` = `DeckIndex>=0 ? DeckIndex : CollectionData.CurrentIndex()`，`:1980-1987`），**只按阵营筛、不按模式筛**（`:1897-1902` 注释如实登记；`ShowYourDeckCell() :1993-2004`）。
- 默认选中它也接了（`:1557`，W66），与原版「建完第 0 格就 `DeckSelected`」一致。
- ⚠️ **我们永远有这一格**（本工程没有 liveops 事件层）⇒ 原版「无活动事件 ⇒ 只有 6 格」这一态**在我们这儿造不出来**。这是**有意的离线等价物**，不是漏项；但要在台账里记明，别拿它当「原版恒有」。

### 4. 模式开关与「6 副」的关系（顺带核定）

- `GameModeValueChange(bool option)`：`currentPlayMode = option ? 0(Classic) : 13(Skirmish)`；切换 = `ResetContent()` + 重开。
- 参考图滑块在**左** ⇒ Skirmish；参考图 6 个名字确实是 **skirmish 侧**的 `PrebuiltDecks/GSC_SK_*`（忠诚的群众 / 爪出鞘 / 无边的地平线 / 秘密行动 / 看不见的危险 / 隐藏的威胁）⇒ 与我们的默认（Skirmish）+ `PairDeck(pair, Skirmish)` **逐条吻合**。
- `DemoDeckInfoSO.GetDeck(mode)`：`0 → classicDeck(+0x18)`、否则 `→ skirmishDeck(+0x20)`（`DemoDeckInfoSO__GetDeck.c`）—— 我们 `PairDeck` 同口径。

## 五、没查清的部分（+ 差什么）

1. **`Selected Army Title` 的词条格式串**没逐字节读出：`ChangeSelectedArmy` 里是 `System_String.Format(DAT_18426d0a0, <boxed CardArmy>)` + `GetTermTranslation`，`DAT_18426d0a0` 是**托管字符串字面量**（`工具/read_literal.py` 只读数值常量，读不了）。**差**：一次 IL 字符串字面量 dump（或直接按「13 条 `Armies/<成员名>` 与 `CardArmy` 同名」的强吻合落地）。结论（原版=本地化中文）**由参考图直接坐实**，格式串只影响键名。
2. **`currentPlayMode` 的初值**：字段是私有非序列化（默认 0 = Classic），反编译里没有「按 `gameModeSelector.isOn` 初始化」的赋值点；而 `EverguildToggle` 是否在 Enable 时回调 `OnValueChanged` 本地读不到（`m_Script` 是 Unity 程序集，AssetRipper 只给占位 fileID）。参考图显示 Skirmish ⇒ 运行时**至少有某处在开窗时把它对上了**。**差**：`EverguildToggle` 的实机探针（`SceneJumpShot` 能 dump）。
3. **原版「无活动练习事件」时的真实画面**拿不到（服务器已关；`PracticeEvent` 由 PlayFab 下发）。我们只能从代码判「wrapper 建不出 ⇒ 无首格」，**没有实拍**。
4. **`Button border` 开在预组格上的视觉差别有多大**没实拍对比（它的中心不透明纯黑 237²，理论上会被 `Main image` 盖住）；只有节点态判据（`set_enabled`）。
5. 参考图是**比 16:9 更宽的窗口**（≈2200×1160 画布单位反推），不是 1920×1080 —— 与 prefab 的矩形换算一致（pivot 已逐件核对），但**逐像素叠图**没做。

## 六、顺手发现（只记不改）

1. `PracticeModePopup__LoadSavedDeck.c` / `__IsSavedDeck.c` **在全量反编译里确实无调用者**（grep 只命中自身）；但 **`PlayerDeckChanged` 不是死代码** —— 它经 `DeckSelected` 里 `new Action<CardDeck>(...)` 传给 `DeckGeneralInfoDemo.SetContent`（`PracticeModePopup__DeckSelected.c` 的 `System_Action<object>___ctor`）。代码注释（`:1271` 附近）若把三个方法并列说成「0 调用点」，建议补一句「`PlayerDeckChanged` 走委托、活的」。
2. `Loc` 里 `PrebuiltDecks/<deckId>` 的官方命中 **101/103**（`DA_SK_4` / `DarkAngelsDeck7` 缺）⇒ 这两副在 UI 上会回落我们自译/英文名（`PrebuiltDecks.cs:118-126`）。不影响本窗（Dark Angels 那 6 格里有 1 格会露英文名）。
3. `prebuilt_decks.json` 的 `nameZh` 有相当一批是 **None**（例：`GSC_SK_1_2`、`GSC_SK_2_2`、`GSC_SK_3_2`、`GenestealersDeck1/3/6`）＋已填的是**我们自译**（虔诚之众 ≠ 官方 忠诚的群众）。**本窗不受影响**（`DisplayName` 已优先官方键），但任何**直接读 `nameZh`** 的地方会露出自译或英文 —— 建议全库改成只走 `DisplayName`（另一条线的活，本代理未改）。
4. prefab 里 `Deck Name` 与 `Deck Selector Menu Item ▸ Deck Name` **同名不同字体**（前者 Asar、后者 Pragati）；我们注释已逐站判过（`:627`），此处只是再确认一次，⛔ 别按名字统一。
5. `Selected Army Title` 用的是 **`Asar-Regular Cream.mat`**（不是纯白）—— 参考图里那行偏米白/暖色就是它；若我们 `TmpFont.Face.LatinUi` 的材质不是 Cream，颜色会偏冷（**本代理没验我们面材质，列为疑点**）。
