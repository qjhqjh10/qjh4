> 补充口径（用户 2026-10-24）：「加不进的卡 = 显示 + 变灰 …… **这个是这个卡不能再加了，所以这个卡灰色，不是所有卡都是灰色**」。
> 判据来源：`d:/2/tools/decomp_full/`（反编译方法体）+ `d:/2/tools/assetripper_out/ExportedProject/`（prefab 原件）。
> ⚠️ 原版客户端已关服，**没有原版卡组编辑界面的实拍** ⇒ 本文判据全部是「代码 + prefab 字段」，不是截图。

## 1. 结论先行

**① 满编 30/30 时原版到底灰什么？—— 卡面「一张都不灰」；灰的是每张卡底部那条「张数」条的底板。**

- `ToggleGreyScale` 在 `CollectionCard` 上有**两个不同实例**，读的**不是同一层**：
  | 控制器 | 挂在 | `imageMaterialPairs` 覆盖的 Image | 由谁驱动 |
  |---|---|---|---|
  | `CollectionCard.counter.greyscale` | GO `Counter` | **只有 `Counter` 那一张图**（`40K_main_deck_card counter` 药丸底） | **`!canAdd`**（逐卡 `CanAddCard`） |
  | `CollectionCard.cardUI.greyscaleController` | GO `2DCard` | `CardImage`＋`CardFrame`＋`Cost Background`（= 卡面本体） | **`!isOwned` 或 `isBanned`** |
- 判据（逐句）：
  - `CollectionCard__UpdateCardVisuals.c:19-20` → `ToggleGreyScale(counterGreyscale, canAdd ^ 1, 0.25f)` ← **只到 Counter**
  - `CollectionCard__UpdateCardVisuals.c:44-47` → `cVar3 = isOwned ? isBanned : 1;` → `ToggleGreyScale(cardUI.greyscale, cVar3, 0)` ← **才是卡面**
  - prefab 实证：`Collection Card.prefab` `cardUI:`(114292246286975720)、`counter:`(114743393880019028)；counter 的 `greyscale`(114026196548002408) 只 pair 一个 Image（GO = `Counter`）；cardUI 的 `greyscaleController`(114699617135816954) pair 3 个（GO = `CardImage` / `CardFrame` / `Cost Background`）。
- ⇒ **原版满编 30/30：卡面 0 张灰，张数条全灰**（因为 `CanAddCard` 在满编时对每张卡都返回 false）。
- ⇒ **我们「整池卡面全灰」与原版不一致**，用户的抱怨成立。
- ⚠️ 但要如实说清一层：**用户的「逐张」口径本身在 30/30 下也会得到全灰** —— 因为原版的「逐卡」判据里**内含「整副一个空位都没有」这一条**（见 §2·D）。这层冲突见 §4「口径冲突」与 §5 两条改法。

**② 灰到什么程度？—— 两边一致：整卡真去色（降饱和），不是压暗、不动 alpha。**

- 原版：材质 `UI Greyscale` / `Card Image Simple Greyscale` 都是 `_GreyScale = 1`（`_GreyScale` 是 Range 0..1，默认 1）。
  算式（既有 DXBC 反汇编记录，见 `资料/待办判据_审查发现_1005.md:127`、`资料/普查产出_1007/波8_A77_15_19_8a.md:154`）：
  `grey = dot(col,(0.30,0.59,0.11)); out.rgb = lerp(col, grey, _GreyScale)`，**不乘暗暗色、alpha 不变**。
- 我们：`Resources/Shaders/CardSprite.shader:64-66` 同一算式（Rec.601 `0.299/0.587/0.114`）⇒ **程度等价**。
- ⚠️ **差别不在「多灰」，在「灰了哪些层」**：我们 `CardView.SetGrey` 遍历**全部** `MeshRenderer`（`Core/CardView.cs:6850-6856`）**外加 TMP 文字顶点色**（`:6872-6879` Greys）；原版只换那几个指名 Image 的材质，**文字一律不灰**。

**③ 我们漏接/多接的变灰条件**：见 §4 表。核心两条：
- **多接**：`TooManyCards`（满编）导致**卡面**变灰 —— 原版这条只影响**张数条**。
- **漏接**：`!isOwned` / `isBanned` 这两条原版会灰**卡面本体**（本工程「全解锁 + 无禁卡表」下恒不触发，属 N/A 而非缺陷）。

## 2. 原版判据（逐条）

**A. 卡组编辑卡池的调用链**（唯一一条，别再找别的入口）
`DeckEditorCollectionDisplay__DrawCell.c:65` `canAdd = CardDeck.CanAddCard(editingDeck, card)` → `:78` `CollectionCard.UpdateCardVisuals(card, canAdd, isOwned, counterText)`
（`SetCell` / `RefreshCells` 两个入口**都只调到 DrawCell**：`DeckEditorCollectionDisplay__SetCell.c:44`、`__RefreshCells.c:92` ⇒ 没有第二条灰化路径）。
`Deck Editing Menu.prefab:22449` `PrototypeCell → Collection Card.prefab` ⇒ 卡池格子就是这个 prefab。

**B. `canAdd` 只驱动「张数条」**
`CollectionCardCounter.Set(string counterText, bool setGreyscale)` → `CollectionCardCounter__Set.c:11-13` `ToggleGreyScale(greyscale, setGreyscale, 0.25f)`；
`CollectionCard__UpdateCardVisuals.c:19-20` 传的就是 `canAdd ^ 1`。
张数条的图 = `Collection Card/Counter` 的 Image，sprite = `40K_main_deck_card counter`；旁边的数字是**子节点** `Text (TMP)`（GO `1618682377417806`），**不在 pairs 里 ⇒ 数字不灰**。补间 **0.25 s**。

**C. 卡面本体只由 `!isOwned || isBanned` 驱动**
`CollectionCard__UpdateCardVisuals.c:44-47`：`cVar3 = isOwned ? isBanned : 1` → `ToggleGreyScale(cardUI.greyscale, cVar3, 0)`（**time 0，瞬切**）。
`isOwned` 来自 `DeckEditorCollectionDisplay__DrawCell.c:33` `InventoryManager.GetOwnedCount(card) > 0`；
`isBanned` 来自 `:68` `PlayEventData.IsCardBanned(currentEventData, card)`（**只有绑了活动/自定义模式才非 null** ⇒ 经典模式恒 false）。

**D. `CanAddCard` 内部：是【逐卡】调，但「整副满」也写在里面**
`CardDeck__CanAddCard.c` 分支（每张卡各算一次）：
| 行 | 条件 | 失败文案 |
|---|---|---|
| `:32` | `cardType == 10`（督军）⇒ `CanAddHero` | 见 CanAddHero |
| `:36` | `cardType == 0x14 && spellType == 0xd2`（防御卡）⇒ `CanAddDefensive` | 见 CanAddDefensive |
| `:40` | `*(int*)(card+0x4c) != 0 && *(int*)(card+0x48) != 5` | 一条无参词条（同族「这张不能进卡组」）—— ⚠️ 两个字段名**没解出来**，见 §6 |
| `:52-70` | 同名张数 ≥ `GetMaxCopiesInDeck(短id)` | 「已达同名上限 N」 |
| `:76-86` | `持有数 <= 已在卡组里的张数` | 「你没有更多张《…》」 |
| `:90-97` | 非中立阵营 + 与卡组督军阵营不同 + 卡组已有牌 | 阵营不符 |
| `:100-150` | 传说稀有度 + 自定义模式 `maxLegendaries` 上限 | 传说张数上限 |
| `:156` | 活动禁卡表命中 | 禁卡 |
| `:166-170` | `EmptySlotsCount <= 0` | **「卡组已满」** |

⇒ **「整副满」是逐卡判据里的一条**（`:166`），不是另一个「整副级」的开关；30/30 时它对**每张卡**都返回 false。

**E. 同一套 `CollectionCard` 在收藏卡牌页的接法（对照，用来证明「哪一层」的划分是稳定的）**
`CardCollectionDisplay__UpdateCardVisuals.c:38-39` 张数条 ← `ownedCount < 1`；`:84` 卡面 ← `!owned || banned`。
⇒ 「张数条 = 这个动作做不了 / 卡面 = 你没这张卡」这条分工在别处也一样。

## 4. 差异表

| 现象 | 原版 | 我们 | 修法落点 |
|---|---|---|---|
| 满编 30/30 | 卡面**全彩**；张数条（底板）变灰 | 卡面**全灰**；张数条不变 | `DeckRuntime.cs:3099-3107`：去掉卡面的 `SetGrey`/`Unplayable`（或改由下面两条驱动），把 `!canAdd` 接到张数条 |
| 「加不进」灰在哪 | **张数条**（`Counter` 的 Image），0.25s 补间 | 卡面 | `SetPoolCounter`（`:3259`）/`ShowPoolCounter`（`:3301`）加灰度；`ImageQuad` 目前**没有 `_GreyScale` 通道**（`Battle/ImageQuad.cs:135` 用的是 `Sprites/Default`）⇒ 要么换成 `CardPresentation/CardSprite` 材质，要么给 `ImageQuad` 补一个（**⛔ 别用 `SetTint` 灰** —— 那是乘法，会变暗不是去色） |
| 未拥有 / 禁卡 | **卡面本体**变灰（`!isOwned || isBanned`，瞬切） | 没有这条（全解锁 + 无禁卡表 ⇒ 恒不触发） | 不是缺陷（铁律 11 例外①）；若将来接活动禁卡表，落在 `DeckRuntime` 同一处，条件用 `!owned || banned` |
| 灰的层 | 只 3 个 Image（art/frame/cost-bg），**文字不灰** | 全部层 + TMP 文字 | 若保留任何卡面灰，需按层收窄（`ApplyGreyTo` 白名单） |
| 灰的程度 | `_GreyScale=1`，纯亮度去色 | 同（Rec.601 lerp） | 不动 |
| 逐卡条件集 | 见 §2·D 九条 | hero/defence/特效卡/满编/阵营/同名 —— **缺** 未拥有、禁卡、传说上限、`0x4c/0x48` 那条 | 缺的 4 条见 §6 |

**🔴 口径冲突（必须由主对话裁）**：用户说「这个是这个卡不能再加了，所以这个卡灰色」。但原版 `CanAddCard` 把**整副满**也算进「这张不能再加」 ⇒ 若照用户口径把 `canAdd` 接到**卡面**，30/30 时**仍然是全池灰**（= 现在的现象，用户不接受）。两条出路：
- **主案（照原版，铁律 11）**：卡面不灰，「加不进」只灰**张数条** ⇒ 满编时卡面全彩，问题消失。**推荐**。
- **次案（若坚持卡面灰）**：把 `TooManyCards` **从卡面灰里摘掉**（满编不算「这张不能加」），只灰卡自身原因（同名满 / 阵营不符 / 未拥有 / 禁卡）⇒ 满编时只有 2/2 那几张灰。**⚠️ 这与原版不同，须写进注释并留出处**。

## 5. 断言建议（不论选哪条改法都要动 `Editor/DeckScene.cs`）

现有三条会**把旧口径钉死**，必须一起改：
- `Editor/DeckScene.cs:3392` `Check(cv.State, Unplayable, "加不进的卡…显示且灰")` ⇒ 改成断**张数条**的灰度（新增 `PoolCounterGrey(slot)` 读数）。
- `Editor/DeckScene.cs:3400-3403` `LayerGrey("art") > 0.99 && LayerGrey("frame") > 0.99` ⇒ **反向**：断 `art/frame == 0`。
- `Editor/DeckScene.cs:3413-3429` 反向控制（没督军 ⇒ 一格不灰）保留，但读数改成张数条。

新增（含灭自证）：
1. **满编那一条**（本缺陷的靶心）：把卡组填到 `MaxDeckCount` → `RefreshAll` → 逐格断「`LayerGrey("art")==0` **且** `PoolCounterGrey==1`」；`grep` 一个「整池灰」实现必红。
2. **逐卡区分**：造「1 张已达同名上限 + 其余可加」的卡组 ⇒ 断**只有那一格**的张数条灰，邻格不灰（挡「恒全灰 / 恒不灰」）。
3. **灭自证**：把 `SetPoolCounter` 的灰度写死 0 ⇒ 第 1 条红；写死 1 ⇒ 第 2 条红。

## 6. 没查清的部分

1. `CardDeck__CanAddCard.c:40` 那条 `*(int*)(card+0x4c) != 0 && *(int*)(card+0x48) != 5` 的**字段名没解出来**（`RawCardScript.cs` 桩里字段多、无偏移表）。**没查清**，不敢猜。
2. `Card Image Simple Greyscale`（shader `Everguild/UI/Card ImageUI Simple GreyScale`）的**逐像素算式没有独立复核** —— 上面的 `lerp(col, dot(col,(0.30,0.59,0.11)), _GreyScale)` 是从**另一支** `Everguild/UI/Greyscale` 的 DXBC 记录推的。它额自带 `_AlphaCutout = 0.21`（`Card Image Simple Greyscale.mat`），**灰度时会不会裁 alpha 未查清**。
3. `UIImageGreyscaleController` 里 `ToggleGreyScale(bool, time)` 的 `time` 常量（`DAT_1834b2e7c`）**没有读二进制核实**，只能靠签名桩默认值 `0.25f` 推断；取消灰那条路径里 `time × DAT_1834b2bc8` 的符号**没解**（若为负数才是「反向补间」，否则 Update 只朝 1 走）。
4. 原版**卡组编辑界面没有实拍**（客户端关服）⇒ 「张数条变灰」在真机上到底多显眼，**看不到**。这是唯一一处「判据是代码、观感未验」。

## 7. 顺手发现（只记不改）

1. `Core/CardView.cs:6916-6928` `SetHighlight(Unplayable)` 会**顺带** `SetGrey(1f)` —— 这是个**隐式耦合**：「状态」和「灰化」被绑死。`BattleDriver.cs:23763`（手牌）、`MulliganPanel.cs:1338`、`CardChoicePanel.cs:895` 三处都要靠「再显式 `SetGrey(0)`」来抵消。建议单独立账：让 `Unplayable` 只管描边/状态，灰度独立。
2. `Collection Card` 的卡面灰**不覆盖文字**（原版），而我们 `Greyed()` 会把 TMP 一起灰 —— 若将来接「未拥有」的卡面灰，会**比原版更灰**。
3. 原版卡池**张数条数字是白色**（`Text (TMP)` `m_fontColor = (1,1,1,1)`，`m_fontSize 31.9` / auto `7..32`）；真机截图里我们那排数字偏红，**没核**是不是我们传的 `Color.white` 被底板色衬出来的错觉 —— 属于观感，未记账。
