## 6–9. 回放**静默漏演最后一条动作** —— β（真缺陷，一个根因四条红）

- **根因**：`TickReplayPump` **先 `_replayCursor++` 再调** `ApplyReplayActionAt`；
  而后者在 `AdvanceTimeline(0f)` 里被**递归调回来**时由 `_replayPumping` 挡成 no-op 并返回 `true`
  ⇒ **内层把游标偷走一格、那一条却没落地** ⇒ 外层 while 看到游标到底 ⇒ 静默收工。
- **改动**：`Battle/BattleDriver.cs:1288-1298` —— 把「重入就返回」挪到**游标推进之前**：
  ```csharp
  if (_replayPumping) return;          // ← 新增（在 `int i = _replayCursor++;` 之前）
  if (_replayCursor >= _replayRec.actions.Count) { … }
  ```
  `ApplyReplayActionAt` 开头那道 `if (_replayPumping) return true;` **保留**（防御别的入口），
  但它那段注释里「闸放在这里而不是 `TickReplayPump`」「调用方的游标推进照常」**两句已就地订正**
  （`:1091-1096`，铁律 5）。`TickReplayPump` 的 doc 也补了这道闸（`:1271-1279`）。
- **判别式（修前 / 修后）**：
  - **修前**：第 i 条落地途中 `AdvanceTimeline(0f)` 重入 ⇒ 游标 `i+1 → i+2`、第 `i+1` 条被 no-op ⇒
    `while` 收工 ⇒ 录像 2 条、回放只筛到 1 个样本（轨迹摘要 `29*31+t0` 对得上录制的前一格）；
    局面速写 `UM47@25 / UM46@30` vs 录的 `UM47@23 / UM46@28!`（丢的正是 AI 那条 `Attack`）。
  - **修后**：游标只在**真正落地**的那一次推进 ⇒ 每条动作被推且只被推一次 ⇒
    采样条数 == 录制条数 ⇒ `[Replay] 演完了 … 终局指纹 … = 录制时的 … ｜ 回放全量指纹：逐条一致`。
  - **灭自证**：把 `if (_replayPumping) return;` 挪回 `int i = _replayCursor++;` **之后** ⇒ 立刻复现漏演
    （并且现在会**出声**：`ObservedCount` 见 §12·1）。
- **预期转绿**：`回放完的终局局面哈希 == 录制时的` · `判别式：终局局面速写逐字相同` ·
  `W9 反例①的前提（终局指纹照旧相等）` · `W9 反例②的前提（老档照样演得完）`（4 条）。
