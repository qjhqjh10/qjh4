# W6 — 卡组编辑「变灰」按原版拆层（执行报告，2026-10-24）

> 目标（判据已闭合，`G1_卡组编辑变灰判据.md`）：原版把「变灰」拆成**两个独立控制器** ——
> `canAdd` 只灰**张数条**，卡面只由 `!isOwned || isBanned` 驱动。
> 我们原来把 `canAdd` 接到**卡面** ⇒ 满编 30/30 时整池卡面全灰、张数条一直彩着（正好对调）。
> **本批已按原版改回来。**

## 2. 改动逐件（文件:行号 · 判据 · 做法）

### 2·1 `Battle/ImageQuad.cs:306-396` —— 给世界空间图补一个 `_GreyScale` 通道

- **判据**：`G1` §2·B —— 原版张数条的灰是 `UIImageGreyscaleController.ToggleGreyScale(counter, canAdd ^ 1, 0.25f)`，
  落点是**材质属性 `_GreyScale`**（0 = 原色 / 1 = 全灰）；`G1` §1·② 的算式
  `lerp(rgb, dot(rgb,(0.299,0.587,0.114)), g)` 与我们 `Resources/Shaders/CardSprite.shader:64-66` 逐项一致。
- **做法**：
  - 新增 `SetGrey(float)` / `Grey`（自检读数）。写 **`MaterialPropertyBlock`**，不落到共享材质上
    （同 `CardView.SetGrey` 那条理由）。
  - **惰性换材质** `EnsureGreyCapable()`：只有**真被要求灰**的 quad 才从 `Sprites/Default`
    换到 `CardPresentation/CardSprite`（后者 = 前者 + `_GreyScale`，默认 0 = 逐像素一致）。
    ⇒ **`Create` 那句没动**，全工程其它几百个 `ImageQuad` 一个字节都不变。
  - 换材质时把 **`mainTexture` / `_Color` / 显式 `renderQueue`** 带过去 —— 队列那条是踩过的坑
    （`SetMaterial` 的 doc：掉队 = 那块图沉到自己底图之下，**静默**）。
  - 找不到 shader 时 `Debug.LogWarning`（⛔ 不静默）；`Grey` 在材质没这个属性时回 **`-1`**
    （与「0 = 不灰」区分开，防自检假绿）。
  - 软边子块跟着刷灰（同 `SetTint` 那条既有规矩）。
- ⛔ **没有用 `SetTint` 表达灰** —— 材质色是乘法（会「变暗」不是「去色」），正是简报红线。

### 2·2 `Deck/DeckRuntime.cs:3088-3132` —— 卡面与张数条**分家**

```csharp
bool owned = CardProgress.Owned(def.Id, def.Rarity) > 0;   // 原版 isOwned
bool banned = false;                                        // 原版 isBanned（数据源缺，见下）
v.SetHighlight(owned && !banned ? CardHighlightState.Playable : CardHighlightState.Unplayable);
bool canAdd = State.CanAdd(def) == DeckError.None;
ShowPoolCounter(vi, true);
SetPoolCounter(vi, def, cx - P.CellW * 0.5f, cellTop, !canAdd);
```

- **删掉**：`v.SetHighlight(canAdd ? Playable : Unplayable)` + `v.SetGrey(canAdd ? 0 : 1)`（旧口径，接在卡面上）。
- **判据**：`CollectionCard__UpdateCardVisuals.c:19-20`（`canAdd` → counter）·
  `:44-47`（`cVar3 = isOwned ? isBanned : 1` → `cardUI.greyscaleController`，`time 0` 瞬切）。
- **`CardView.cs` 没动**：`Unplayable` 那一档（它自己会 `SetGrey(1)`）现在**只**给「未拥有 / 被禁」用 ——
  这正是原版要的卡面灰，所以**不需要**在调用侧补 `SetGrey(0)` 去抵消（`BattleDriver.cs:23763` 那条先例是反着用的）。

### 2·3 `Deck/DeckRuntime.cs:3288` / `:3327` —— 张数条落灰

- `SetPoolCounter(..., bool greyed)`；底板 `bar.SetGrey(greyed ? 1 : 0)`。
- **只灰底板**：旁边的数字（`poolcnt_*`）是独立 `Label`，**一次都没碰** ——
  原版那个数字是 GO `Text (TMP)`，**不在** `counter.greyscale` 的 `imageMaterialPairs` 里、
  `m_fontColor` 恒 `(1,1,1,1)`（`G1` §2·B）。
- ⚠️ **补间**：原版传 `0.25f`，但那个常量**没有读二进制核实**（`G1` §6.3，连反向补间的符号都没解）
  ⇒ 这里**瞬切**，⛔ 不猜一个数（见 §4·1）。

### 2·4 `Deck/DeckRuntime.cs:6124-6134` —— 自检读数 `UiPoolCounterGrey(int)`

读**渲染器上真正生效**的 `_GreyScale`（MPB 优先）；`-1` = 那格没底板 / 材质没这个属性。
断言里对「不灰」一律先断 `>= 0`，把「通道没接上」和「不灰」分开。

### 2·5 `Editor/DeckScene.cs:3357-3550` —— 三条旧断言改向 + 三条新断言

| 位置 | 改前 | 改后 |
|---|---|---|
| `:3390-3397`（原 `:3392`） | `cv.State == Unplayable` | **张数条** `UiPoolCounterGrey > 0.99` |
| `:3402-3410`（原 `:3399-3402`） | `LayerGrey("art") > 0.99 && frame > 0.99` | **反向**：`art/frame < 0.01`（并先断 `>= 0` 防假绿） |
| `:3421-3441`（原 `:3413-3429`） | 逐格断 `State`/`Grey`/`art`/`frame` 全不灰 | 读数换成**张数条** + 卡面 `art/frame` |
| `:3446-3493` | —— | 🆕 **满编靶心**：填到 `MaxDeckCount` ⇒ 逐格「`CanAdd != None` ⇔ 张数条灰」+ 卡面全彩 |

## 3·1 「未拥有 / 被禁」：**判据在、数据源缺 ⇒ 本档今天不可达**（如实标注）

- `isOwned`：本工程「全卡已解锁」，`CardProgress.Owned` 恒 `> 0`
  （按「给足」口径回 `DeckCap + 升满所需`，`Shell/CardDetailPopup.cs:211-227`）。
- `isBanned`：原版走 `PlayEventData.IsCardBanned(currentEventData, card)`（只在绑了活动/自定义模式时非 null）；
  **我们还没有禁卡表** —— `DeckError.InvalidDeckBannedCards` / `CardsNotOwned` 一直是
  「永远不回」的那两个（`Deck/DeckRuntime.cs:5773`、`:5812`）。
- ⇒ 判定式 `owned && !banned` **代码路径照留**（与原版逐字同义），数据源一到位把 `banned` 换成真读即可。

## 3·2 夹具副作用（已防）

`TryAdd` 对**防御卡**写的是 `Deck.DefensiveId`、**不进 `CardIds`** ⇒ 满编那节只恢复 `CardIds` 会把
「填满时顺手加上的防御卡」留在卡组里（静默改掉后面各节的前提）。已一并快照/恢复 `DefensiveId`。

## 4. 没做到 / 做不到

1. **0.25 s 补间没做**。原版 `ToggleGreyScale(counter, …, 0.25f)` 的那个常量**没有读二进制核实**
   （`G1` §6.3 明写未查清，连「取消灰」那条路的符号都没解）⇒ 本批**瞬切**，⛔ 不猜数。
   要补的话先解 `DAT_1834b2e7c` / `DAT_1834b2bc8`。
2. **卡面灰的「层收窄」没做**：原版卡面只灰 `CardImage` / `CardFrame` / `Cost Background` 三个 Image、
   **文字一律不灰**；我们 `CardView.ApplyGrey` 会遍历**全部** `MeshRenderer` **外加 TMP 文字**（`Core/CardView.cs:6850-6879`）。
   - **为什么这轮不动**：① 它**只在「未拥有 / 被禁」那一档才现形**，而那一档今天不可达（§3·1）；
     ② 收窄必须改 `CardView`（调用侧做不到），而 `SetGrey` 同时服务**战斗侧**（`SetHighlight(Unplayable)`
     的手牌/换牌/选牌三处）—— 那是本批白名单外的一整片，风险远大于收益。
   - **需要立账**（铁律 5·b）：等「未拥有 / 被禁」真的可接入时，**同一批**把 `ApplyGreyTo` 收成白名单
     （`art` / `frame` / `cost`）并停掉 TMP 顶点去饱和，否则会比原版**更灰**。
3. **没跑 Unity / 没跑 `DeckScene.Run`**（简报红线：不跑批处理）⇒ 上文断言**只是写好了，没执行过**。
   同步点请按覆盖面跑 `DeckScene.Run`（只动了 `DeckRuntime` + `DeckScene` 这个宿主 + `ImageQuad`）。
4. **真机观感没验**：原版卡组编辑**没有实拍**（客户端关服），「张数条变灰」到底多显眼看不到
   （`G1` §6.4 同一条）—— 我们这边改完可以进游戏看，但本批没做。

## 5. 顺手发现（只报不改）

1. `CardView.SetHighlight(Unplayable)` **自己会 `SetGrey(1)`** —— 状态与灰化被隐性绑死
   （`Core/CardView.cs:6916-6928`）。现在有 **3 处**调用者靠「再显式 `SetGrey(0)`」抵消：
   `Battle/BattleDriver.cs:24164`、`MulliganPanel.cs:1338`、`CardChoicePanel.cs:895`。
   建议单独立账：让 `Unplayable` 只管描边/状态，灰度独立。（`G1` §7.1 已记，仍未做）
2. **`ImageQuad` 换材质后旧材质不销毁**（`EnsureGreyCapable`）—— 故意的（旧材质可能是调用方经
   `SetMaterial` 传进来的共享材质）。代价 = 每个「被灰过」的 quad 多留一份 `Material`，
   今天只有卡池张数条（≤ 24 条）走这条路，有界。
3. `CardProgress.Owned` **吃不到卡型** ⇒ 对 28 张**非传说督军**比「按督军档」多 1
   （`Shell/CardDetailPopup.cs:211-218` 已记）。本批只用它判 `> 0`，不受影响。
4. `G1` §7.3 那条「我们张数条的数字偏红，没核」—— 本批**也没核**（没跑 Unity）。
   代码上数字是 `Color.white`（`DeckRuntime` 的 `TxtPx(..., Color.white, ...)`），
   怀疑是底板色衬出来的错觉；**仍未验**。
5. `DeckRuntime` 的卡池视图**每次刷新都 `SetData` + `SetFace`**（`DeckRuntime.cs:3086-3087`），
   即使卡没换。本批新加的 4 段刷新会各付一次这个成本（视图**不重建**，走的是 `_poolSlotOfIdx` 复用
   ⇒ 不触发 `CardView.Create`）—— 对 `DeckScene.Run` 的总时长影响应当很小，**但没有实测**。
