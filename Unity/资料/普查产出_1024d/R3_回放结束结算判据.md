## 一、结论先行

1. **走同一套结算流程**，**没有任何 replay 分支跳过演出**：回放的动作由 `NextReplayAction → ExecuteNextAction`（与真打**同一个执行器**）推进 ⇒ 督军死 → `DeadHero` → `SaveMatchWinner` / `BattleFinished` → `ProcessMatchResult` → `FinishedProcessingMatchResult`（**0xA0 是唯一分叉**）→ `ShowFinishScreen` → `CloseBattleDoors` → `EndBattleDoors.SetupDoor`。
2. **有「结算视频」，而且是真视频**：`Victory Video` / `Defeat Video` / `Draw Video` 三条 `VideoClip`（`AssetReferenceTyped<VideoClip>`，**1920×1080 · split-alpha（源 3840×1080）· 无音轨**）。按 `BattleWinner` 三选一。
3. **结算屏上没有「胜利/失败」大字** —— `EndBattlePanel` 子树只有 `Background` / `Video Image` / `AllRewardsHolder`（骷髅行 + 奖励行 + 评级）。**结果字样就在那段视频里**（我们 `EndPanel` 早已 `SetTitleVisible(!video)`，与之一致）。
4. **胜负 = 录像里那一局的结果**：`DeadHero(playerIsLoser, BattleResult)` 在重放时同样被调 ⇒ `BattleWinner {Player=10, Enemy=20, Draw=30}` 由重放的动作推出来，不是固定显示某一方。
5. **回放只跳过三处上传**（Missions / Achievements / Alliance + `SaveMatchResultAnalytics`）；**奖励数据是「全零结果」**（`CreateTutorialResult`）⇒ 结算屏上**奖励/评级一律不显示**，只剩视频（骷髅行按实际档数显示）。
6. **之后去哪**：视频播完 + **2.0 s** 才置 `matchFinishedAndWaitingToLeave`；之后 **任意左键 / ESC ⇒ `LeaveBattle` ⇒ 主菜单场景**（`"MainMenu Warpforge"`）。与正常对局**同一条出口**。

## 六、我们该怎么实现（逐条，落点已核到行）

现状：`BattleDriver.cs:28372-28377` 的 `if (_replaySession) { 只打一句 Log }` —— **整块（含面板+视频）都跳过了**。判据表明**演出要留、账要跳过**。

1. 🔴 **把这个分支拆两半**（落点 `BattleDriver.cs:28372`）：
   - **留下的（账）**：日常推进 / 对局记录 / 录像收尾 / `StartPostBattleScript` / `_settleCount++` —— 回放照旧**不做**。
   - **移到 `else` 外面的（演出）**：`if (_music != null) _music.FinishMatch();` → `_endPanel.Show(Ctx.Winner, _me, _foeSkullCount, Ctx.Turn, Ctx.ForfeitedBy, …)` → `if (_music != null) _music.FadeOut();` → `TouchInputManager.Current?.Toggle(false)`。
   - 现成实现就在同文件 **≈28415**（`_endPanel.Show(...)` 那一段），**照抄那四句、不要另写一份**（铁律 6）。
2. **参数直接用引擎给的那几个**：`Ctx.Winner`（1/2/3，`EndPanel.Show` 已按 `winner==myIndex+1` / `winner==3` 映射 Victory/Defeat/Draw）、`_foeSkullCount`、`Ctx.Turn`、`Ctx.ForfeitedBy`（回放恒 -1）。⇒ **胜负自动 = 录像里那一局**，不需要另存结果。
3. **`_endPanel.Show` 会自动播视频**（`EndPanel.cs:646` → `_doors.SetupDoor(result)` → `BattleDoors.cs:347`），片源 = `Resources/Art/videos/{victory,defeat,draw}.webm`（**三条已在工程里，字节数与原版一致**）。⇒ 用户那句「放一个胜利或者失败的结算视频就行」**现成就有**，不用新做资产。
   - **不用另接「推时间」的泵**：`AdvanceTimeline` 里已经有 `_endPanel.Advance(dt)`（`BattleDriver.cs:17912`），而回放那条泵（`BattleDriver.cs:12653`）**排在 `HandleReplayBar()` 之前** ⇒ 每帧都会推（只有 `_replayPaused` 时停，与原版「暂停」一致）。
   - ⚠️ **我们挑的一处**（原版判据没查到，如实标）：若玩家在回放里按过「暂停」，结算视频会跟着停（同一个 `_replayPaused`）。原版回放结束时 `ReplayHud` 收不收，**本批没查到** ⇒ 落点建议**演完/进结算时把回放条收掉**（不做也不会错，只是多一条可见的条压在视频上）。
4. **奖励/评级不用补**：回放本来就该是「没有奖励那一档」，我们 `EndPanel` 只建了骷髅行 ⇒ 与 `ShowRewards` 在「空结果」下的表现**一致**（⛔ 别为回放去造假的奖励）。
5. **出口改成「视频播完才认点击」**（对齐 `+0x510`）：
   - 现在 `HandleReplaySessionExit`（`BattleDriver.cs:7200` 一带）**任何时刻**点空处/按 ESC 都走。
   - 建议：**点击那一路加 `_endPanel == null || _endPanel.ExitReady`**（= `Visible && _doors.Finished`，`EndPanel.cs:184`）——结算演出期间点空处**不退出**（原版如此）；**ESC 保留随时可走**（我们已如实记「ESC 一步走」是简化）。
6. **防重复结算**：已有两道，够用 —— `_settled`（`BattleDriver.cs:28370`）+ `_replayFinished`（`FinishReplay` 的闩）；原版同形闸 = `matchData+0x1c`（`ProcessMatchResult.c:133`）。⛔ 别再加第三道。
7. **自检**（照铁律 12 只跑受影响宿主）：`BattleScene.Run` 里回放那几条断言要补两条（与现有断言同源，⛔ 别新写一套判定）：
   - `PlayReplay` 演完后 `End.Visible == true` 且 `End.Doors.ClipName == victory/defeat`（**按录像结果**）——判据 = `BattleWinner` 三选一；
   - 回放演完**仍然**没有写对局记录 / 没推日常 / 没加骷髅（即原 `A381` 那三条断言**保持绿**）。
8. ⚠️ **不要顺手做**：`ShowFinishScreen` 前面那 **1.5 s + 0.5 s** 的等待我们**没有**（正常对局也没有）——这是既有偏离，**要么三处一起改、要么一起留着**，⛔ 别只给回放加（会出现「回放比真打慢 1.5 s」的诡异差异）。
