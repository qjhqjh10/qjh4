## 二、S3「场上插图白边 + 一直闪」—— UV 再内缩一层，已改

### 2·1 结论

`Shaders/Card3D.shader` 的 `artUv` 原来把 mesh 的 UV1 **铺满整张**裁好的立绘 PNG；
现在**再映射进 crop 的内子矩形** `[0.014412, 0.989541] × [0.001700, 0.997800]`
（= 原版在 1024² 图集里真正采样的那一块，换算到 671×1024 的 crop 坐标）。

### 2·2 改动

| 文件:行号 | 改了什么 |
|---|---|
| `Shaders/Card3D.shader:155-157` | 新增 `ArtCropUvMin` / `ArtCropUvMax` 两个常量 + `artUv = lerp(ArtCropUvMin, ArtCropUvMax, artT)`（`artT` = 原来的 0..1 归一） |
| `Shaders/Card3D.shader:131-154` | 根因 + **算式**（`textureRect` 与 UV1 角点逐个列出，换卡框/换裁法能重算）+ 三句约束（别改导入器 / 上下白边未处理 / 与原版 mask 的关系） |
| `Shaders/Card3D.shader:8-16` | 文件头 ① 改准：「原版根本没有 UV 重映射」+ 注明**我们这两层是必须补的**，⛔ 别「还原成原版那样直采 UV1」 |

**算式（逐字，与 shader 注释同源）**

```
u ∈ [(0.1818×1024 − 176.5)/670.5 , (0.8203×1024 − 176.5)/670.5]
  = [(186.1632 − 176.5)/670.5 , (840.0 − 176.5)/670.5]
  = [9.6632/670.5 , 663.5/670.5] = [0.014412 , 0.989541]
v ∈ [0.0017×1024/1024 , 0.9978×1024/1024] = [0.001700 , 0.997800]
```

`textureRect` 出处 = `工具/import_original_art.py:28` 与 `:1022`（`x176.5 y0 w670.5 h1024`，图集 1024²）。
**等价性已验**：这个 `lerp` 与「直接按像素算 `(uv1*1024 − (176.5,0)) / (670.5,1024)`」
在四个 UV1 角点上差 **0.0e+00**（脚本核过）。保留 `lerp` 只是让那两个数一眼能核。

### 2·3 判据出处

- 原版 `_CardImage` = `rawCard.cardSprite.texture` = **1024² 图集整图**，UV1 ∈ [0.1818, 0.8203]
  ⇒ 采样图集 x **186.16 … 840.0**（宽 653.8 px）—— S1 §2·8，DXBC 反汇编 + 规格文档
  `资料/3DBody_原版场上卡体规格.md` §一（「UV1 = 立绘 UV，正面四角 0.1818/0.8203/0.0017/0.9978」）。
- 我们的 crop 是 671×1024，两端各多采**左 9.663 px / 右 7.013 px**，那里是立绘 PNG 的**纯白卡框内沿**
  （S1 实测：左 5–6 px、右 5–6 px 纯白，**664/1168 张左右都有**）。
- **改 shader 前按规矩跑了 `工具/dump_shader.py "3D Card" "Card 3d"`**：
  `Everguild/Cards/3D Card` = **14 个属性**，全是 `_BaseMap` / `_CardImage` / `_CountersIntensity` /
  `_USE_BLEND` / `_MatCap*` / 两张 ShaderGraph `_var3DCardColor_*` / `_QueueOffset` / `_QueueControl` /
  三条 `unity_Lightmaps*` —— **没有任何 UV 偏移/缩放向量**（即原版确实不做重映射，直接吃 UV1）。
  另外：原版材质 `_CountersIntensity` 默认 2.0，我们声明 1.12 —— 但原版**材质值**就是 1.12 且
  `CardView.BuildBody3D` 每次都显式写 1.12 ⇒ 声明值不同**不影响画面**（见 §四·3，只是记账）。
  ⇒ 本批**没有新增任何 shader 属性**，也没有 `[_SrcBlend]` 那种间接寻址。

### 2·4 ⛔ 为什么没动导入器

同一批 `Resources/Art/cards/art_*.png` 也喂 2D 卡面（手牌 / 卡池 / 详情 / 卡组格），2D 那边被卡框 alpha 盖着、
**看不出白边**；改导入器等于给「看不出来的地方」引入风险。⇒ 只改 shader（S1 §2·11 同结论）。

### 2·6 没做到

1. **上下白边没一起处理**（按简报要求）。残余：实测 **151 张有上边白条 / 7 张有下边**；
