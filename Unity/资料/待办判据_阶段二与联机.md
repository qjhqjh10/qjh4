#### 10·2 「功能散落在别的文件里」怎么读 —— 用户点名的方法

**界面 = prefab；功能逻辑挂在 MonoBehaviour 上**，而且**跨 prefab 复用**（同一个 Controller 被好几个界面引用）。
⇒ **查一个界面时按这条链走**：
```
prefab 的 m_Component  →  MonoScript 的 m_ClassName  →  decomp_full/<ClassName>__*.c（调用链）
                                                     →  dump.cs（字段偏移）
                                                     →  反向查「谁开它」（grep 谁构造/实例化这个 prefab）
```
⚠️ **别只看那个界面自己的文件就动手** —— 这是用户特别提醒的（「其他地方的文件」）。
**每个界面交一份「打开它的入口 + 它调用的东西 + 谁在监听它」三张清单**再开工。

#### 10·3 🔴🔴 **复刻完成后怎么审 —— 「找茬式」审核办法**（用户点名要的）

**前提**：这批界面**没有可并排的原版实况**（关服 + 实例化即黑）⇒ **不能靠"看着像"**。审核只能靠**参数级对账**。

**第 0 层 · 先立尺子（复刻【之前】做，不是之后）**
- 每个界面先产出一张 **「层 × 参数」表**：逐节点 = 路径 / 名字 / sprite 名 / rect / 锚点 / pivot / 字号 / 颜色 /
  **activeSelf 的出现条件**。**每条必须带出处**（bundle 的 `GameObject`/`RectTransform`/`MonoBehaviour` JSON 路径 + 行号）。
- **没出处的格子写「？」，不许空着、不许写「大概」** —— 照铁律 3。
- 这张表**就是**后面审查的尺子 ⇒ **没表不许动手**（铁律 10 第 2 条）。

**第 1 层 · 机械对账（能自动就别靠眼睛）**
- 我们的界面是**代码画的**（`DeckRuntime.cs` 那种常量表）⇒ 写脚本把**我们运行时的控件真值 dump 出来**，
  与第 0 层那张表**逐字段比**，出**差异表**（我们值 / 原版值 / 出处 / 判定）。
- 🔴 **必须量「渲染真值」，不是抄「源码常量」** —— 源码常量对了画面仍可能错
  （已有坑：**量版面必须量渲染图**，`textBounds` 与字形差 0.039 卡高；今晚的 `WcIconX` 就是「常量对、没断言、画面错」）。

**第 2 层 · 对抗式复核（**这是"找茬"的核心**）**
- 每做完一个界面，**派一个独立子代理专门去证伪它** —— **不是让它确认，是让它证明这里有问题**
  （做法照 2026-09-22 那次「证伪 0919 结论」：**找不到反证才算通过**）。
- 给它三件武器：① 第 0 层的权威表 ② 我们的渲染真值 dump ③ 允许它 Read 原版实拍图（**只判"有没有/大概"，不量数值**）。
- **要求它交「问题清单」，不是「确认通过」**；真找不出问题，必须写清「我查了哪几类、为什么这类不可能有问题」。

**第 3 层 · 断言要盯「原版参数」，不是盯「我们自己的常量」**
- 每个界面在自检里加断言，**断言的值要带出处注释**（否则就是自证：拿我们写的常量断言我们写的常量）。
- ⚠️ 今晚的教训：`DeckRuntime` 的通配符计数条那段**一条断言都没有** ⇒ 断言全绿、画面全错。

**「找茬点」清单（从 2026-09-22 一夜的错里提炼，逐条必查）**：
1. 🔴 **一个值 ≠ 全部情况**（铁律 5·c）：这个界面在**不同筛选 / 状态 / 画质 / 小屏 UI** 下是不是**两套参数**？
   查全了再写。**实例**：卡池 6 列 vs 小屏 4 列。
2. 🔴 **多实例**：同一个组件在 bundle 里有几份？**先按用途字段认实例再取值**（例：认 `m_Viewport`/`m_Content`）。
   **实例**：`RecyclableScrollRect` 有 8 份、`CardTextsController` 有 153 份。
3. 🔴 **贴图用错**：每张图核 **sprite 名 + D 原版这层是否可见 + 是不是九宫格**。
   **实例**：我们把原版 `alpha=0` 的按钮根图当成了可见行底；描边该九宫格却拉满。
4. 🔴 **分层顺序**：不能只看位置，要核**渲染顺序 / 兄弟序**。
   **实例**：行底盖住了稀有度色条（原版相反）。
5. 🔴 **反编译缺产物 ≠ 那段代码不存在**（铁律 5·c）：用 `工具/disasm_va.py` 直读指令流。
   **实例**：`Initialize()` 与 4 参 `SetTexts` 都是**重载撞名丢了产物**，害人得出「零读取点」「零调用者」两个错结论。
6. 🔴 **是不是我们自加的**：动手前查 `资料/战斗UI_原版对账表.md` **§六「我们加的」**，别把自加当复刻。
   **实例**：棋盘正中那行 `HintLabel`。
7. 🔴 **别拿一个来源当全部**：本地 bundle / 原版实拍 / PnP 三者**可能不是同一个版本**。
   **实例**：阵营行 —— 本地 bundle 不印、实拍印。**冲突时报冲突，别自己选一个。**
