# 待修：作用域含手牌（`Avenging Zeal` 一族）

> 2026-09-16 · **只读调查**，未改任何代码。证据 = ① 全池探针 `d:/4/_tmp_view/probe_after.txt`（12:23，晚于 `HandBuff` 落地）② **独立复算**：把 `Assets/RuleEngine/Core/*.cs` 编进一个 .NET 控制台程序直接跑 `EffectText.Parse`（`Core/` 不依赖 `UnityEngine`）—— 与 ① **逐字相同** ③ `GivePayload.Parse` 实测 ④ 亲读 PnP 卡图。
> ⚠️ **行号会漂**（`EffectText.cs` 正被主对话编辑）⇒ 一律以 **函数名** 为准。

## 〇、先说一条：这张卡的**属性 token 名是错的**（数据侧，与作用域是两件事）

**卡面亲读**（铁律 7，`d:/2/Warpforge部队卡片/Ultramarines/4计策/zeal.png`）：`Give +2 ⟨粉拳 = 近战⟩ and +2 ⟨紫枪 = 远程⟩ to all your units in play and in hand.`
- 项目自己的 NCC 模板匹配表同结论：`工具/gen_icon_plan.py:90-91`「`[health icon]` → **Melee**（**写着 health、画的是拳**）· `[attack icon]` → **Ranged**」，落表在 `资料/卡面图标_对照与缺口.md:1386-1387`；卡图提取表 `_还原效果文字.md:1128` 也写 `+2 Melee and +2 Ranged`。
- 而 `cards_engine.json` 的 `desc` 是 `[health icon]`/`[attack icon]` —— 实测 `GivePayload.Parse("+2 health icon and +2 attack icon")` → **`+2 health` + `+2 attack`**；`descZh` 同样是「+2 生命和 +2 攻击」。`数据/游戏数据/cardface_fixes.json` 里**没有** `Avenging Zeal` 这条（`grep -c` = 0）⇒ **数据侧还没裁定**。

⇒ **修作用域之前/同时必须把属性也裁定掉**，否则修完是一张「+2 生命/+2 攻击」的错卡。按卡图应是 `+2 Melee and +2 Ranged`。**这属于数据侧**（`cardface_fixes.json` 的 `_manual_*` 通道），**解析层不许猜**。

## 一、根因（三层同时堵死 ⇒ 静默）

1. **解析层：目标短语的整体兜底只「抽」它认识的维度，不认识的词不报错。** `EffectText.ParseTarget` 只剩 `Side / Kind / Count / 筛选` 几个分支，`in play` 与 `in hand` **一个都不命中** ⇒ 当噪声丢掉。实测：`all your units in play and in hand` → `目标[own/unit 「all your units in play and in hand」]`，**Count=0 = 全部**。
2. **本来有一道补救，被自己挡住了。** `EffectText.SplitTargetList` 会在顶层 ` and ` 处切成两条（A=`all your units in play`、B=`in hand`），但第 ④ 道门要求 **B 解得成目标** —— `ParseTarget("in hand")` 返回 `null` ⇒ **不切**。（该函数注释里举的就是这个例子。）
3. **结算层根本没有「手牌」这个目标池。** `EffectResolver.ResolveTargets` 的 own/enemy 分支只走 `AddSide(..., ps.Board)`（只遍历棋盘格位）。全工程唯一的「手牌」通道是 `ctx.HandBuffs`（`BattleContext` 的 `class HandBuff`），而它**只被 `chooseeffect` 那条路写入**。

⇒ `in hand` 那半**彻底消失**，但 `IsFullyParsed` 仍为真（实测 `不认识 0 · 半懂 0`）⇒ **卡面不打 `*`、日志不报**。正是红线里的「静默少打」。

## 二、`HandBuff` 通道现状（谁写 / 谁读 / 何时兑现 / 能不能多属性）

| 环节 | 落点（以**函数名**为准） | 说明 |
|---|---|---|
| **数据** | `BattleContext.HandBuff` + `ctx.HandBuffs` | `{ CardDef Card; int Count; List<EffectOp> Ops; string Source }`。**按「卡 + 份数」记账**（本版无卡实例身份），同名两张 = 一条 `Count=2` |
| **写** | `EffectResolver.GrantHandBuff` —— **唯一写入点** | 只被 `EffectResolver.DoChooseEffect` 的 `handScope` 分支调（判据 `ChooseEffectIsHand`：`op.Payload == "hand"`）。它**硬编码 `c.Type != "unit"`** 跳过战术/防御卡 |
| **读 / 兑现** | `RuleCore.ApplyHandBuffs` —— **只此一处调用**：`RuleCore.PlayCard` 里（排在 `Auras.Recompose` **之前**） | 时机 = **那张手牌真的被部署上场的那一刻**。⚠️ **`PlayTactic` 里没有这一步** |
| **多属性** | ✅ **支持，不用改** | 兑现走 `ResolveOps(..., seed: unit)` → `DoGive` → `GivePayload.Parse`；实测已把 `"+2 health icon and +2 attack icon"` 拆成 **2 项**；`Ops` 本身也是 `List` |
| **兑现目标** | `GrantHandBuff` 造的 op 带 `EffectTargetSpec{ Subjectless=true, Auto=true, Side=own, Kind=unit }` | 「刚上场的那个单位」拿加成（与「`Give <内容>` 没写目标」同一条判据） |

## 三、最小修法 + 落点（改 2 处，**兑现点不动**）

**改 ① 解析层 —— `EffectText.cs`**
- `EffectTargetSpec` 加一个布尔，与 `Deployed` / `Subjectless` 同族：`public bool AlsoHand;`
- `EffectText.ParseTarget` 里，紧挨着 `DamagedOnly` / `PrayedOnly` 那两行加：
  ```csharp
  // ⚠️ 两个都要写：`in your hand` **不含**子串 `in hand`（同一条坑 `DestPhrases` 的注释已记过一次）
  if (t.Contains("in hand") || t.Contains("in your hand")) spec.AlsoHand = true;
  ```

**改 ② 结算层 —— `EffectResolver.DoGive`**
- 位置：`var targets = ResolveTargets(...)` 之后，**不要 `return`** —— 场上那半必须照常结算。
- 形状：抽 `GrantHandBuffForTargets(ctx, owner, by, op, spec, unresolved)`，与 `GrantHandBuff` **并排放**；再把 `GrantHandBuff` 的 body 改成「造一个 `own/unit/全部` 的 spec 再调它」—— **避免出现两份「往 `ctx.HandBuffs` 写」的实现**（工程红线）。
- 它干的事（与现有那条**完全同形**）：① 守卫 `spec.AlsoHand && spec.Side == "own" && sign > 0`（`lose` 的符号在兑现时会被翻正，别接）；② 筛手牌用 `CardCriteria.FromTarget(spec)`（**与场上同一份判据**）—— 实测 `CreatePool.MatchesKind(card, "unit"|"troop"|"beast")` 都可用，`Kind=unit/troop` 时等价于现有的 `Type=="unit"`；③ `spec.Count == 1 || spec.Random` ⇒ 用 **`ctx.Rng`** 抽一张（可复现红线）；④ 逐张登记 `Count++`，`Ops = [ give(payload = op.Payload, Target = Subjectless 自己) ]`；⑤ 一张都没筛到 → **如实报** `unresolved`，别静默。
- **`RuleCore.ApplyHandBuffs` / `PlayCard` / `HandBuff` 数据结构一个字都不用改。**

**两个「看着更省事但别做」**：① 在 `DoGive` 里读 `op.Target.Raw.Contains("in hand")` —— 只改一个文件，但 `Raw` 是「排查用原短语」，当语义判据迟早被别的句子撞上；② 让 `SplitTargetList` 认识 `in hand` 切成两条 op —— 第二条**在结算层没有目标池可落**，等于把「静默丢」换成「静默空过」。

## 五、与 `Infinite Biomorphologies` 的关系

**同一个 `ctx.HandBuffs` 表、同一个兑现点，但写入路径不同**：

```
Infinite Biomorphologies : 「Choose an effect and give it to all troops in your hand」
   → TryChooseEffect 判 hand = t.Contains("in your hand") → op { Verb="chooseeffect", Payload="hand" }
   → DoChooseEffect ② handScope = ChooseEffectIsHand(op) → GrantHandBuff(载荷 = 玩家选中那一项)
Avenging Zeal（拟）        : 「Give +2 … to all your units in play and in hand」
   → ParseTarget 置 AlsoHand → op { Verb="give", Payload="+2 … and +2 …" }
   → DoGive 场上照常 + 新增 GrantHandBuffForTargets() → 同一个 ctx.HandBuffs / 同一个 ApplyHandBuffs
```

**能不能照抄？** 能抄的半条 = `HandBuff` 数据结构 + 「打出时兑现」（`ApplyHandBuffs`）—— **一个字都不用改**。不能抄的两点 = ① **谁筛手牌**（`GrantHandBuff` 硬编码 `Type=="unit"`，表达不了 `a random troop` / `all Beasts`）；② **载荷从哪来**（那条是玩家选，这条是写死在卡面）。

## 六、风险与推荐度

| # | 风险 | 处置 |
|---|---|---|
| 1 | **属性 token 是错的**（§〇） | 修作用域**同时**裁属性，否则修完还是错卡；数据侧走 `cardface_fixes.json` |
| 2 | **`in your hand` 不含 `in hand`** | 判据必须写两个 `Contains`（同一条坑 `DestPhrases` 已记过一次） |
| 3 | **`GrantHandBuff` 的「合并」是潜在地雷** | 它按 `ReferenceEquals(h.Card, c)` 找条目，**只 `Count++` 不更新 `Ops`** ⇒ 同一张手牌先后吃两条不同来源的额度时**后一条载荷被静默丢掉**。以前只有一条写入路径、撞不上，**加了第二条就会撞**。建议改成「`Ops` 不同就另起一条」并加断言 |
| 4 | 老缺口（本期沿用，不新增） | ① 打出一张后**新抽到的同名卡**也会吃到额度（`BattleContext.HandBuff` 注释里如实记着）；② 手牌里那张卡的**卡面数字不会变**（没有任何 UI 读 `ctx.HandBuffs`），与 `Infinite Biomorphologies` 同一缺口 |
| 5 | **`Beast Snagga Nob` 接不到** | 它的 `give` 藏在 `atturn 载荷「…」` 里 ⇒ 本期改法**不覆盖**。**别说「A 族全修好了」** |
| 6 | 改 `EffectText.cs` 要和主对话协调 | 该文件正被编辑；改动只有 1 个字段 + 2 行，但**要先确认对方那轮落了盘** |
| 7 | 断言 | 加在 `RuleEngineTest` 的手牌加成两节（登记节 + `TestBatch0916` ⑧ 的兑现节）：① 打出后 `HandBuffs` 有条目且 `Count` = 手牌匹配张数；② 场上单位**同时**加成；③ 那张手牌打出时**带上加成**；④ 反向：只写 `in hand` 的**不给场上**加 |

**推荐度：高。** 2 处落点、兑现点零改动、不新增机制；按 spec 筛手牌即可顺带解锁另外 3 张（`Drag it Down` / `Cyber‑augmentation` / `Snakebite Nob`）。**本期不建议**：表现层手牌数字 · `Beast Snagga Nob` 的嵌套路径 · `Raw` 字符串判据 · **绕过数据通道去改属性**。

## 七、复核办法（可重跑，**不碰 Unity**）

`Core/` 不依赖 `UnityEngine` ⇒ 可把 `Assets/RuleEngine/Core/*.cs` 直接编进一个 .NET 控制台程序跑解析器（本报告的复算就是这么跑的：等价 JSON 读法 + `CreatePool.BuildNameIndex`）；脚手架在 `%TEMP%/handparse/`（**临时目录，不在工程里**）。⚠️ 它只量**解析层**；结算层仍只能靠 `RuleEngineTest`（Unity 批处理，同一时刻只能一个实例）。
