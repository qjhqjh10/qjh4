### 2·1 三条硬要求的落实

1. **每帧按深度重算**：`HookDepthScale` 给那条补间挂 `OnUpdate` → `ApplyDepthScale`（原版 `Sequence.OnUpdate` 的等价物）。
   **不是** `DOScale` —— 原版不是补间、是每帧按**当前位置**现算（写进去的是一条**位置→缩放**的映射，不是一条插值）。
2. **必须经 `CardView` 的口**：只写 `_baseScale` + `ApplyScale()`，⛔ 全仓没有新增任何一处 `transform.localScale =`（grep 可验）。
   不这么做的话，下一次 `SetPose` / `SetHighlightScale` 会把卡**弹回旧尺寸**（`T04` 那条潜伏缺陷的同一族）。
3. **共用静态口**：`CardFeel.DepthScaleFactor(worldZ, isPlayer)` 是**唯一**的曲线判据；`MeleeAttack` / `Reassemble` 共用 `ApplyDepthScale`。

### 2·2 两个新决定（都写进注释了，值得复核）

- **`z` 用【世界】z**：原版的 `localPosition` 是**相对自己那一行 `MinionManager`** 的局部 z；
  我们卡父节点是 `Battle`（`boardRoot` = `sceneRoot`，原点、缩放 1）⇒ 用 `worldZ − ArenaSlots.{Player,Enemy}Z` 现算。
- **门 = `gameObject.layer == ArenaSlots.ArenaLayer`**（`IsArenaCard`）：**2D 兜底布局**的卡都躺在 z = 0 的 HUD 正交平面上，
  套这条曲线会恒得 1.75×（纯错）。这一层的判据与 `BattleDriver.SyncBoard` 里 `if (use3DBoard) v.SetLayer(ArenaLayer)` **同一个开关**
  （同族那条 `★ A849` 钉着它）。反向也有断言（§三 ⑤）。
- **`isPlayer` 怎么来**：我们 `CardView` **不带阵营字段**（阵营只存在于 `BattleDriver` 的 `_myUnits` / `_foeUnits` 两个字典里），
  而 `BattleDriver.cs` 不在本笔白名单 ⇒ `MeleeAttack` 加了一个**可选** `bool? isPlayer = null`，不传时按
  「静止位离哪一行近」判（`IsPlayerRow`：两行 z 差 7.698，督军另有 0.42/0.75 的偏移也只占 6%，结构上不会误判）。
  **建议**：主对话下一批让 `PlayAttackFeel` 显式传 `e.Player == _me`（一行改动，`BattleDriver.cs:19053`），把推断换成真值。
- **收尾显式复位**：原版序列跑完就停在最后一帧（不再写）；我们在 `OnKill` 里把 `baseScale` 写回。
  两者在「自家那一行」上**同值**（系数恒 1），差别只出现在**敌方督军**（`x = 7.7 − 0.75 = 6.95` ⇒ 0.949×），
  而 `SyncBoard` 的 `SetPose` 每次刷新都会把缩放按格位重设一遍 ⇒ 那一档最多在两次刷新之间短暂差 5%。如实记在 §六。
