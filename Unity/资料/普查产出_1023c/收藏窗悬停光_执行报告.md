## 〇、先说三条「判据本身要订正」的（铁律 5：就地改，不只在对话里说）

### ⓪·1 🔴 悬停光**不在**战斗那圈状态环上 —— 原版写的是 `Card Highlight And Shadow` 那层，而**我们早就有了它**

核查报告 §三·2 / §五 的落点写的是「我们的等价物 = 状态环那一层（`_rim`）」，P0 四条也因此被描述成

- 原版那条链（`Card2DController__ToggleHighlight.c`）写 `_Outline` 的那颗材质 = `MENUS` 里
  `Collection Card ▸ Content ▸ CardUI ▸ 2DCard ▸ Front ▸ Card Highlight And Shadow` 那个 Image 的 `m_Material`
  = pid `−3316280387615011577` = **`Card Frame SDF`**。
- 我们这棵树里那个节点**已经建好了**：`CardView.SdfMaterial()`（`Core/CardView.cs:4555`，属性值**逐项**照抄
  `Card Frame SDF`：`_Inner_Edge 0.333` / `_Inner_Fallof 0.224` / `_SpriteAlphaEdge_Inner 0.043`）＋
  `ShadowMesh()`（`ShadowSize = 4.4281f`，`Core/CardView.cs:4527` @ y `−0.0126`）＋ 每卡自己的
  `CardArt.Sdf(faction, rarity, tactics, tier)` 贴图 —— 就是原版那个 Image。
- 而 `_rim`（`3DBody/MinionLight`）是**战斗**那一层（`CardHighlight` 6 态状态环，材质 `Card board Frame SDF`），
  菜单卡上根本没有那颗 3D 体。
⇒ **P0 四条的正确做法不是「给 `_rim` 加档位开关」，而是「换一层」**：悬停写 `OutlineMat`
（懒建的 `outlineGlow` 优先、没有就退回 `_shadowLayer`）。这样：
- 颜色 / alpha / 尺寸 / 材质**四条自动全部成立**（那一层本来就是 `#0080FF` 该写的地方 + 4.4281² + `Card Frame SDF`）；
- 「战斗档一格都不许变」**不是靠断言保住的，是结构上做到的**（物理两层，菜单这条代码路径根本不碰 `_rim`）。

落点：`Core/CardView.cs` 的 `SetHoverHighlight`（`:6608`）现在只有一句
`SetOutline(new Color(MenuHoverColor.r, MenuHoverColor.g, MenuHoverColor.b, on ? 1f : 0f));`
（原来写的是 `_rim` + `ApplyRimColor(白)`）。`CardHighlight.RimAlphaScale 0.447` **一个字没动**。

### ⓪·2 核查报告 §四 #3 的 `elasticity = 0.3` 是**错的** —— 本条调用传的是 **1.0**

`CollectionCard__SelectedHighlight.c` 的调用是
`DOPunchScale(uVar2, &punch, DAT_1834b2dc4, 10, DAT_1834b2bb8, 0)`。
`工具/read_literal.py` 实读：`0x1834b2dc4 = 0.1`（时长）· **`0x1834b2bb8 = 1.0`**（elasticity）·
`0x1834b2f94 = 0.05`（幅度系数）· `0x1834b2c80 = −0.0`（符号位掩码 `^ 0x80000000`）。
报告里那个 `0x1834b2dc8 = 0.3` 属于 `CardScript.DoPushBack` 那一处（也就是 `read_literal.py` 文件头第 18 行
自己举的那个例子），**不是这条**。

### ⓪·3 报告里「卡框宽的 1.97 / 高的 1.36」**不能直接当 `localScale` 用**

`4.4281 ÷ FrameUnitW 2.2452 = 1.972`、`÷ FrameUnitH 3.2572 = 1.359` —— 那是相对**卡框**说的。
我们的光晕 quad 是 `Quad()`（= 卡本体 `2.0927 × 3.3313`），照 1.97/1.36 直接乘会小 **1/1.064**。
本条最终**不需要**这个数（用的是现成的 `ShadowMesh`，绝对尺寸就是 4.4281），记在这里防下一个人照抄。

### §四 · punch 的判据是**怎么解出来的**（报告原写「源向量没解到」）

`CollectionCard__SelectedHighlight.c`：
```
uVar1 = *(undefined8 *)(*(longlong *)(DAT_1842da2a8 + 0xb8) + 0xc);      // x,y
local_20 = (float)(*(uint *)(*(longlong *)(DAT_1842da2a8 + 0xb8) + 0x14) ^ DAT_1834b2c80) * DAT_1834b2f94;  // z
… DOPunchScale(transform, &punch, 0x1834b2dc4, 10, 0x1834b2bb8, 0)
```
- `DAT_1842da2a8` = **`UnityEngine.Vector3` 的类**；`+0xb8` = 它的**静态字段块**指针；
  块内 `+0x00 / +0x0c / +0x18 / +0x3c / +0x48` = `zero / one / up / right / forward`。
  **三条独立旁证**（都在 `d:/2/tools/decomp_full/`）：
  ① `PhotonTransformViewPositionControl__.ctor.c` 拿 `+0x00` 当零向量初始化字段；
  ② `LookAtConstrainWIP__Update.c:120` 把 `+0x18` 当 `Quaternion.AngleAxis` 的**轴**（= `up`）；
  ③ `MoveByKeys__FixedUpdate.c:45-46,133-134` 在 `+0x3c` / `+0x48` 上做水平 / 前向位移（= `right` / `forward`）。
  ⇒ **`+0xc` = `Vector3.one`**。
- 于是 punch = `-(1,1,1) × 0.05` = **(−0.05, −0.05, −0.05)**；时长 **0.1**；vibrato **10**；elasticity **1.0**。
- 落地：`CardPunchCell` 用 `DOPunchScale(t, Vector3.one * -0.05f, 0.1f, 10, 1f)`，
  `OnComplete` / `OnKill` **都把缩放复位**（否则会在被点那一格留一个非 1 的缩放，静默）。

⚠️ **只做了「卡体」这一级**：原版打的是 `param_1 + 0x60`（`CollectionCard.content`）。
我们这棵树上「卡体」= `CardView` 自己的根（张数条是它的**兄弟**，不跟着弹）。
原版 `Content` 里到底含不含 `Counter`（张数条）**没查到**（见 §六）。
