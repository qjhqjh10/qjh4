## 一、① ESC 关全屏匹配窗后搜索没被取消（真缺陷）

### 结论

**病灶属实，而且比工单里给的那条判据更硬**：原版**这一扇窗自己的 `Close()` 覆写**就取消搜索。

### 证据（第一权威 = 全量反编译）

| 文件 | 内容 |
|---|---|
| `d:/2/tools/decomp_full/SearchingOpponentWindow__Close.c` | **本类自己的 `Close` 覆写**，全文两句：① `GameWindow__Close(this)`；② `if (MatchMakerManager 单例 != null) Everguild_MatchMakerManager__CancelSearch(manager, 0)`。⇒ **原版这扇窗一关就取消搜索** |
| `SearchingOpponentWindow__CancelButtonClick.c` | 尾调虚表 `0x1b8` = `Close()` ⇒ **`Cancel` 钮也走 `Close` 取消** |
| `SearchingOpponentWindow__OnDisable.c` | **不取消**（只 `RemoveListener`） |
| `SearchingMatchWindowDemo__ESCPressed.c:24` | 旁证（**弹窗那一支**，不是本类）：`Close()` 之后**无条件** `CancelSearch()` |
| `Everguild.MatchMakerManager__CancelSearch.c` | 那句本身是**有闸的轻动作**：`if (SearchOpponentManager 字段 != null) { CancelBattleSearch(停协程); 事件 }` ⇒ 原版无条件调没有副作用 |

🔴 **工单里写的 `SearchingMatchWindowDemo__ESCPressed.c` 是「弹窗」那一类**（`SearchingMatchWindowDemo`），
不是本窗（`SearchingOpponentWindow`）；本次补读了本窗自己的 `Close` 覆写，判据更强、结论一致。

### 实现（`Shell/SearchingOpponentWindow.cs`）

- 新增 `ESCPressed()` 覆写（`:335`）：置 `_escClose` 瞬时位 → `base.ESCPressed()`（**两道门槛仍由基类判**：`PointerLayer.InputEnabled` / `closeOnEsc`）。
- `Close()`（`:342`）在 `_escClose` 为真时先 `CancelSearchOnce()`，再 `ReleaseHold()` + `base.Close()`。
- `CancelSearchOnce()`（`:315`）+ `_cancelSent`（`:312`）：**幂等闸**。`OnCancel` 在生产上是
  `RankedEventWindow.CancelSearch`，而那条链**自己会再 `_searchWin.Close()` 一次** ⇒ 不幂等会绕成无限递归。
- `Cancel()`（`:477`）改走同一个 `CancelSearchOnce()` ⇒ `Cancel` 钮与 ESC 都**只取消一次**。
- `Build()`（`:402`）复位 `_cancelSent`（重开 = 新的一局）。

### ⚠️ 为什么**不是**照原版「`Close()` 无条件取消」（这是**我们故意不同的一处**，⛔ 别按原版改回去）

我们的 `OnCancel` 比原版那个 `MatchMakerManager.CancelSearch` **重得多**：
`RankedEventWindow.CancelSearch` = `_search.AbortSearch()`（清状态 + 注销常驻 ticker）
**＋ 联机 `NetMatchmaking.Cancel(...)`（会往对面发 `match.cancel`）＋ 自己关窗**。
而本类有**两条原版没有的程序关窗路**，无条件取消会把它们打成回归：

1. `RankedEventWindow.OnSearchFinished()` → `_searchWin.Close()`（**配到人了 / 等满 12 秒要开战**）——
   会在开战前把这一局撤掉；
2. 本文件 `Tick()` 的 `A1322` 那一支（**这一局已经被撤**）—— `NetMatchmaking.Cancel` 此刻没有活着的账
   ⇒ 返回 `false` ⇒ 弹一句 `Settings/Online/MatchCancelFailed`（屏幕上多一条「取消失败」）。

⇒ 加一道 `_escClose` 闸后，取消的**恰好就是原版那两个调用点**（ESC / `Cancel` 钮），两条程序关窗不受影响。
`Editor/ShellScene.cs` 里专门有一条**灭自证**断言钉住这件事（见断言 ②）。

### 影响面 / 谁调 `Close()`

| 调用点 | 该不该取消 | 本次行为 |
|---|---|---|
| `PointerLayer.KeyCancel` → `ESCPressed()` → `Close()` | ✅ 该（原版） | ✅ 取消一次 |
| `SearchingOpponentWindow.Cancel()`（`Cancel Match` 钮） | ✅ 该（原版） | ✅ 取消一次 |
| `RankedEventWindow.OnSearchFinished()`（配到人 / 等满 12 秒） | ❌ 不该 | ✅ 不取消 |
| `Tick()` 的 `A1322`（这一局被撤） | ❌ 不该 | ✅ 不取消 |
| `RankedEventWindow.CancelSearch()` → `_searchWin.Close()` | ❌ 不该（外层已经在取消） | ✅ 因幂等闸不重复 |
