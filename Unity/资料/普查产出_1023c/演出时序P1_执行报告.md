## 一 逐条

### ④ 远程伤害时刻 = 逐件 `AnimInfo.GetAnimDuration()`（P1-1）

**判据（第一权威）**：`d:/2/tools/decomp_full/AnimInfo__GetAnimDuration.c` —— 四字段
`vfxDelayTime + timeAtStartPos + timeMoving + timeAtEndPos` **无条件直加**；调用点
`BattleManager._ResolveAnimInfoRangeAttack_d__468__MoveNext.c:111-124` 用 `WaitForSeconds(...)` 等它，
**等完才** `ReceiveDamage` ⇒ 这一件演多久 = 伤害晚多久。

**根因**：`VfxMap.ChainDuration` 只覆盖两档（逐卡 `CardDef.AnimTimes` / 共享件表 7 个 prefab 名）。
逐卡远程件大多挂在卡 SO 的**顶层** `customRangedAttackParticles` 上、**不进 `AnimTimes`** ⇒ 两档都答不出来。

**改法**：新增 `CardAnimClips.RangedChainDuration(evt, faction, cardIdOrName, times)`
（`Battle/CardAnimClips.cs:193`）—— 第三档按 `ResolvedVfx.Anim`（**CardAnim 名**）查
`Resources/cardanim_clips.json`（1,067 行），取 `max(T + vd+ts+tm+te)`。
⛔ 按 prefab 名查会踩 **215 组同名不同参**（文件头判据）。
返回值契约与 `VfxMap.ChainDuration` **不同**：**≥ 0 = 真值（0 也算真值）**、**-1 = 判据为空**。

4 个生产调用点改道（原 `VfxMap.ChainDuration`）：

| 调用点 | 用途 |
|---|---|
| `BattleDriver.cs:17819`（`RangedVfxDurationBefore`） | **伤害时刻**（`DelayBetween(Hit)` 的第三参）—— ④ 的正题 |
| `BattleDriver.cs:17511`（攻击 VFX 队尾） | 队尾（与 ③ 同一行） |
| `BattleDriver.cs:17545`（`atkEnd` → `UnitAttack(50)` 起播） | 攻方技能动画起点 |
| `EventTiming.cs:108`（`RetaliationHoldOf`） | 反击那一拍的长度 |

**数值前后（现读，脚本逐条重算，见 §四）**：

- 441 个（卡,件）组合走兜底；其中 **265 个真值 ≠ 0.75**（186 早 / 79 晚）。
- 极端：`Exorcist` → `Atk_BulletImpact_Sororitas_MissileVolley_MoveAnim` = `0 + 2.5 + 0.1 + 1.0` = **3.6 s**
  ⇒ 伤害时刻 `Attack+0.2+3.6 = 3.80 s`（旧 **0.95 s**，早 **2.85 s**）。
- `Manticore` 3.0 · `Heldrake` 2.75 · `Wraithknight`/`Night Spinner`/`Fire Prism`/`Fire Dragon`/`Autarch` 2.5。
- **176 个恰好 = 0.75** ⇒ 它们本来就没差（所以「实际错 265/441」，与审查报告的 266 差 1 条 —— 见 §五·1）。
- **4 张 Tau 无人机**（`Stealth/Guardian/Gun/Marker Drone` 共用 `Atk_BulletImpact_Tau_Pulse Drone Dual`）
  四字段**全是 0**：原版那一下就是 `WaitForSeconds(0)` ⇒ 新实现的返回值**必须允许 0 是真值**
  （⛔ 别写 `d > 0 ? d : -1`，那会把它们白推 0.75 s）。
- 覆盖率：441 个组合的 CardAnim **全部在表里**（缺 0 条）⇒ 不会静默退回兜底。

### ② 阵亡在时间线上占 0.7 s（P1-3）

**判据（第一权威）**：`BattleManager._ResolveMinionDeath_d__454__MoveNext.c:113-121` —— 对 `UnitDeath`
是 **`StartCoroutine` + `yield return`**（`+0x10 = 1` 之后返回 1）⇒ 动作队列**真等整条阵亡协程跑完**；
那条协程总寿命 = `CardFeel.DeathTotal` = **0.7 s**（抖 `DOShakePosition` **不等它** → 同帧起算
`WaitForSeconds(gVars+0x34)` 0.5 → 0.2 后 `GoToCemetery`；判据 → `CardFeel.DeathBeats` 的 doc）。

**改法**：`EventTiming.DurationOf(EvtKind.Death)`：`CardFeel.DeathDissolveMinion`（0.2）→
**`CardFeel.DeathTotal(false)`（0.7）**（`EventTiming.cs:256`）。判据只此一处（⛔ 没在 EventTiming 里另写 0.7）。
`DelayBetween(Death)` 的 `DeathHold` 0.1 **不动**（那是「Hit 收尾 → 阵亡开场」的间隔，另一件事）。

**数值前后**：一条阵亡占 **0.2 → 0.7**；两条阵亡的间隔 = `DurationOf + DeathHold`
**0.3 → 0.8 s** ⇒ 两条 0.7 s 的演出**不再重叠**（旧口径重叠 0.4 s）；整批（闸 = `BeginBlockingWindow`）
**不再早 0.5 s 放行**。

**连带订正（铁律 5，都在我白名单内的文件里）**：

- `EventTiming.SourceOf(EvtKind.Death)`：原文写「0.2（督军那档 0.5 见 `DeathDissolve`）」→ 改成「整条协程 0.7」
  （`EventTiming.cs:614` 附近）。`IsSourced(Death)` 的说明同步（仍回 **false** —— 没出处的是 `DeathHold` 0.1，
  `BattleScene` 那条 `unsourced == 2` 的断言**不受影响**）。
- `BattleDriver.cs` 死亡那一段的 doc 原文写「这个视图要活 `DeathTotal`（小兵 0.9 s / 督军 1.2 s）」→ 改成 **0.7 s 不分档**
  （那是「抖动串在 0.5 前面」的旧值，`W61` 第 1 批已改并行）。审查报告 §4·2 的订正项，就地做掉。

### ③ 攻击 VFX 队尾漏 `_clock +`（P1-4）

**判据**：同文件另三处同形写法都带时钟项（`ScheduleAction` 的 `_clock + delay` · `ScheduleVfxCue` ·
`PlayUnitSkillAnim` 的 `_clock + at + …`），只有攻击 VFX 队尾那一处没有 ⇒ 中后期 `_clock > 3` 时
算出来的数**恒小于已排的队尾**，`ExtendTimelineTail` 变成空操作 = **静默没排队尾**
（`_timelineTailAt` / `_blockingQuietAt` 都不动 ⇒ 下一批事件能插到这一件还没演完时开场），而且**不报错**。

**改法**：

- 新增纯函数 `EventTiming.AttackVfxTailAt(clock, vfxAt, chainDuration)`（`EventTiming.cs:399` 起）——
  `max(0,clock) + max(0,vfxAt) + max(0,chain)`，把「时钟项」收成**一个口**（⛔ 别再在调用点手写）。
- `BattleDriver.cs:17511` 改成 `ExtendTimelineTail(EventTiming.AttackVfxTailAt(_clock, vfxAt, RangedChainDuration(...)))`。

**数值前后**：攻击 VFX 之后的队尾 `0.2 + 件时长`（**绝对值**，例如 0.95）→ `_clock + 0.2 + 件时长`
（例如 `_clock = 10` 时 **11.15**）。近战那一档同样受益（同一行，`chain = -1 → 0`）。

## 六 顺手发现（只报，没改）

2. **`atkEnd` 这一处原来是三处口径里最不准的**：`EventTiming.RangedDamageLag(ChainDuration=0)`

   比「伤害时刻」早 0.75 s，两个消费点对同一个数用了两套契约。本批改走 `-1` 契约后两者一致（`0.2 + 0.75`）。

   `BattleScene.Run` 的日志会多 32 行 warning，不是新缺陷。
4. **`_timelineTailAt` 只有 `BattleDriver` 内部一处清零（`BeginBattle`）**：本批把攻击 VFX 的队尾
   真正接上之后，**长链远程件（3.6 s 那种）会让「下一批事件」更晚开场** —— 真机验收时
   如果看到「连续远程攻击之间变慢了」，那是**这一条修对了**（原来是被静默跳过），不是回归。
