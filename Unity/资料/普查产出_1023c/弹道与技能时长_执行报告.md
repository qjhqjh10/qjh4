### ① 远程/近战攻击件的**弹道位移**（`新账-77④` · 审查 §2·2 #6）

**判据（第一权威，逐句读）**

- `CardAnimController__Initialize.c`：`if (!shouldMoveVFX) { enabled = 0; }` —— 不飞时**整条控制器关掉**
  ⇒ 等价于我们「当场 `ReleaseAbilityCarrier`」（改前行为）；飞的时候还有一道
  `if (start == end) enabled = 0`（同一个位置也不飞）。
- `CardAnimController__Update.c:36-97`：`t01 = (elapsed − ts) / tm`，**只在 `[0,1)` 里**写位置
  `lerp(startPos, endPos, easeCurve(t01))`；`t01 ≥ 1` 之后不写（停在终点）。
- `easeCurve` 就是 `AnimInfo+0x40`（`Update` 里 `lVar2 = *(param_1+0x28)` = AnimInfo，
  `+0x2c` = `ts`、`+0x30` = `tm`、`+0x40` = 曲线）—— 与我们的 `AbilityVfxMove{ts,tm,ease}` 逐字段同名。

**根因**：`ScheduleAttackPresentation` → `FireAttackVfxWithCtx` → `FireAtAttackAnchor` 播完**立刻**
`ReleaseAbilityCarrier`（：原文件 `17757`）⇒ 榴弹 / 导弹 / 炮击全在炮口原地炸。
而技能拍那条路（`PlayAbilityBeat` + `TickAbilityVfxMoves`）**早就有**完整实现。

**改法（3 个函数 + 1 个新函数）**

| 位置 | 改动 |
|---|---|
| `FireAttackVfxWithCtx` | 多一个 `string cardAnim` 形参（= `ResolvedVfx.Anim`），往下传 |
| `FireAtAttackAnchor` | 末句 `ReleaseAbilityCarrier(carrier);` → `if (!ArmAttackVfxMove(carrier, cardAnim, anchor.position, targetPos)) ReleaseAbilityCarrier(carrier);` |
| **`ArmAttackVfxMove`**（新） | 查 `CardAnimClips.PlacementOf(cardAnim)`；`!Move ｜ Tm<=0 ｜ start==end` ⇒ `false`（不飞）；否则往 `_abilityVfxMoves` 排一条 → **同一个** `TickAbilityVfxMoves` 泵 |
| 3 个调用点 | 攻方攻击（`items[i].Anim`）· 命中帧那件 `Hit`（**`null`**，通用粒子没有 CardAnim）· **反击**（`items[i].Anim`，与攻方同一个协程） |

⚠️ `for` 的循环变量**不是每轮一份**（`foreach` 才是）⇒ lambda 里用的 `an` 必须先拷成局部（已做）。

### ② 技能动画单候选拍的**时长**（`新账-75①` · 审查 §2·3 #3）

**判据**：`AnimInfo.GetAnimDuration()` = `vd + ts + tm + te`（四字段**无条件直加**）；
原版动作队列**等完它**才弹下一条（`BattleManager__ResolveActionFromQueue.c:44-76`、`_ResolveAnim_d__466…:200-210`）。

**根因**：`VfxMap.ResolveAllTimed` 对**单候选**故意把 `Duration` 压成 **0**（回归口径，`VfxMap.cs:1302,1350`），
而逐卡技能动画**几乎都是单候选** ⇒ 下游 `Mathf.Max(0.05f, 0)` = **0.05 s**：
① 喂 `CardAnimPlayback.Duration`（动画提前结束）；② 喂 `ExtendTimelineTail`（队列提前放行）。

**改法（⛔ `Core/VfxMap.cs` 一个字没动）**

- 新增 `public static float SkillBeatDuration(CardAnimClip clip)`：
  `clip.Duration > 0` ⇒ 原样返回；否则 `CardAnimClips.DurationOf(clip.Anim)`（**≥0 = 真值、0 也是真值、−1 = 判据为空**）。
- 两处消费点改道：`ExtendTimelineTail(_clock + at + Mathf.Max(0.05f, dur))` 与
  `CardAnimPlayback.Duration = Mathf.Max(0.05f, dur)`；`dur` 在 `PlayUnitSkillAnim` 里**算一次**、
  当参数传给 `PlayOneUnitAnim`（⛔ 不在两处各算一遍）。

   `start`/`end` 各一次），而 `AnimInfo` 允许逐件给 `sp/ep`。现读 `attack_ranged` 里有 **9 个（卡,件）**
   不是 `(0,2)` —— **全部 `mv=0`**（所以本件不碰它们的位移），但它们的**落点**今天仍按 `abilityTarget` 播：
   | 卡 | 件 | `sp/ep` |
   |---|---|---|
   | `Avatar of Khaine` | `Atk_BulletImpact_Eldar_Khaine` | `2/2` |
   | `Watcher in the Dark` | `Buff_DA_Forest_Target` | `2/2` |
   | `Heldrake` | `EC Heldrake Attack` | **`0/1`** |
   | `Unleashed Tramplasquig` / `Hunta Rig` | `Atk_Trampla_Charge` | `0/0` |
   | `Wulfen` / `Wulfen Pack Leader` / `Frost Claw Wulfen` | `Atk_Cut Wulfen` | `2/2` |
   | `Spore Mine` | `ToxicMiasma_Venomthrope` | `0/0` |
   ⇒ 这是一个**独立的账**（「逐件 `startPosOption`/`endPosOption` 没进攻击路径」）。本件**没做**：
   它要动 `ScheduleAttackPresentation` 的锚点解析与载体父节点（`start` 还兼着命中帧那件的挂载点），
   改错会静默把特效打在别人身上，而我**不能跑 Unity 验收**。
2. **`applyMovementOffsets` / `easeCurve` / `orientToVelocity` 三列没进运行期数据**（见 §一·① 的 ⚠️）。
   要补：`工具/gen_cardanim_clips.py` 多烘三列 → `CardAnimClips.RtRow` 多三个字段 → `ArmAttackVfxMove` 填上。
   **生成器与 `Resources/*.json` 都不在本件白名单。**
3. **`新账-75④`（`vfxDelayTime` 双计）仍开着**：`T` 里已含 `times[].Delay`（= `vd`），而
   `GetAnimDuration()` 也含 `vd` ⇒ 理论上是「等两次」。现读 `cardanim_clips.json` 里 `vd > 0` 只有
   **2 行**（max 1.4）⇒ 今天影响面极小，但它是**同一族**的账，P1 也记过。本件**没动**（要改得连
   `VfxMap` 一起改，不在白名单）。
4. **`AbilityVfxMove` 的载体在 `ts` 段会跟着锚点走**：载体是 `SetParent(anchor)` 的，`ts` 期间我们
   不写 `position` ⇒ 若那张卡在这 0.5–2.5 s 里还在动（回正补间 / 抬手），特效会跟着漂。
   **原版也是这样**（它 `Instantiate` 时父节点就是锚点），所以这不是偏离 —— 但**真机验收时值得看一眼**
   `Exorcist`（`ts = 2.5 s`，那 2.5 s 里攻方卡正好在跑回正补间）。
5. **驱动级那条 ② 断言（第 17 条）的判别力依赖「排期前队尾 < clock+2.2」**。我**没**把这一条写成硬前提
   （写成 `&&` 就有假红风险）；判据的硬核是那 16 条静态断言。若以后有人把这一段前面的流程改得让
   队尾更远，第 17 条会变成**恒真**（弱化，但不误报）—— 消息里已经把 `排期前 {tailBefore:F2}s` 打出来了。
6. **没跑 Unity**（红线）：20 条断言的**期望值**都是我按数据算的，**一条都没在 `BattleScene.Run` 里实跑**。
   风险最高的是第 8–12 条（驱动级，用的是 `FireAttackVfxForTest` 直连生产口 + 一个裸 `GameObject` 锚点）——
   我逐行核过 `EnsureAnchorSpace`（裸节点会 early-return）、`CardAnimOrder.EaseAt(null,…)`（线性恒等）、
   `CardEffects.Fire`（批处理里 `Play` 是假钩子 ⇒ 不建子节点，但**载体照样建**，所以位移泵的断言不依赖特效实例）。
