## 一、判 1：`HandLayout.Place` → `CardView.TweenPose`

### 1.1 判据（原版一手，逐句亲读）

`d:/2/tools/decomp_full/CardScript__UpdateMinionInHandPosition.c`：

```
cardState == 1（手牌常态）:
  Kill(+0x340) → DOLocalRotate(transform, euler, param_4, 0, 0)   // 局部角
  Kill(+0x348) → DOScale(transform, GetCardInHandScale(), param_4, 0)
  Kill(+0x2d0) → DOMove(transform, pos, param_4, 0, 0)            // 世界位
```
- 时长 `param_4` = `VarsGlobal.timeToPositionCard` = **0.2 s**（`PlayerHand._MoveCardsInHandToPosition_d__76__MoveNext.c:76-80` 读 `globalVars+0xA4`）；
- **全文一个 `SetEase` 都没有** ⇒ 三条各自吃 `DOTween.defaultEaseType`（原版资源实测 = 6 `OutQuad`，J3/A26 已核）。

### 1.2 这次改了什么

`Hand/HandLayout.cs:838` 的 `Place`：

```csharp
// 旧（J3 之后）：HandPoseTween.ToPose(c.transform, pos, angle, scale, CardTween.RelayoutDuration, Ease.Linear);
// 新：
if (!animateRelayout) { c.KillPoseTween(); c.SetPose(pos, angle, scale); return; }
...
var parent = c.transform.parent;
Vector3 local = parent != null ? parent.InverseTransformPoint(pos) : pos;
c.TweenPose(local, angle, scale, CardTween.RelayoutDuration, Ease.OutQuad);
```

三处**语义**变化，逐条都有判据：

| 变化 | 为什么 | 怎么才会红 |
| --- | --- | --- |
| **位姿整条改走 `CardView.TweenPose`** | `CardTween.ToPose` 的 `DOScale` **直写 `localScale`** ⇒ `_baseScale` 在补间期间停在起点（`Core/CardView.cs` 的 `T04` doc：补间一结束，任何 `SetPose`/`SetHighlightScale` 都会把卡**弹回旧缩放**，静默） | `BaseScale` ≠ 手牌档 / `localScale` ≠ `BaseScale × HighlightMul`（`CardBaseDemo` 新增那两条） |
| **ease 由 `Linear` → `OutQuad`** | 入口换了：`TweenPose` 是**单条**补间（`DOTween.To` + 每帧 `SetPose`），不是 Sequence ⇒ 传 `Linear` 会变匀速（原版是 OutQuad）。⚠️ **两个入口的 ease 约定是反的**，代码注释与报告都写死了这一条 | 半程位移比例：OutQuad = **0.75** / Linear = 0.5 / 二次弯曲 = 0.9375（片段见 §六·1） |
| **世界位 → 局部位** | `TweenPose`/`SetPose` 吃**局部**位（`transform.localPosition`），而 `SlotPosition` 给的是世界位。父链一旦带旋转/缩放（实机上 `BattleDriver` 根今天是 identity，所以今天是等价）两者就分家 | 父件带 30°+2× 的探针里，世界位必须仍落在 `SlotPosition`（`CardBaseDemo` 新增那条） |

另外补了两处**同族**（都在白名单文件里、都是同一族的「补间没人杀」）：

- `CardView.TweenPose` 开头 `KillPoseTween()` —— 同一条位姿链不许叠两条；
- `CardView.TweenPose` 给 tween 挂 **`SetTarget(transform)`** —— `DOTween.To` 建出来的补间默认**没有 target**，`transform.DOKill()` 按 target 比 ⇒ **杀不到**。而 `HandLayout.Place`（防叠）与 `Battle/MulliganPanel.cs:681/977`（掐重排补间，注释明写「掐掉手牌布局刚开的重排补间」）一直靠 `transform.DOKill()`。**不挂这一句，那些 `DOKill` 会静默失效**。
- `Place` 的 `!animateRelayout` 分支改成 `KillPoseTween(); SetPose(...)` —— 否则在飞的那条补间会把刚 snap 好的位姿改回去（静默）。**只掐位姿补间**（不动这个 Transform 上别的补间，比如 `DeploySequence` / `CardFeel` 那几条）。

### 5.2 🔴 但「格子 384 ⇒ 112.5」这条**站不住**（如实记，没拿它改代码）

**两处独立证据都与它矛盾**：

1. **绘制顺序**：`Content` 的子件是 `[Counter, CardUI]` ⇒ 卡画在张数条**上面**。
   若 `sizeDelta.y = 384` ⇒ `scale = 112.5` ⇒ 卡高 374.8 / 格高 384（居中 ⇒ 上下各留 4.6），
   而张数条占底部 `0.002…0.0997 × 384` = **0.8…38.3 px** ⇒ **卡会整条盖住 "x14"**，字根本看不见。
2. **用户原版实拍**（`C:/Users/qjh36/Desktop/warpforge参考图/收藏—卡牌的界面参考图（打开过滤器按钮后）.png`，逐像素量）：
   - 行距 **285 image px** = **384 设计 px**（图 1578×888 = 1920×1080 的下采样，且 UI 参考高按 1200 ⇒ 换算 ×1.352）；
   - 卡高 **≈ 238 image px = ≈322 设计 px** ⇒ **卡高 / 行距 = 83.5%**（不是 97.6%）；
   - 卡底边到下排卡顶边 **≈ 63 设计 px**，**"x2" 橙字就画在卡下沿之外**（`384…393 image` 那一带）；
   - 列向同理：格距 195 image（= 262.5 设计 ✓ 与 `CardsCellW` 一致）、卡宽 ≈ 162 image（≈ 219 设计 = 83.5%）。

⇒ 自洽的解释只有一个：**原版的「格子」比「行距」小（网格有 ~50–60 px 间距），而 `sizeDelta.y` 读到的不是行距**
（卡根是 **stretch 锚点 + sizeDelta (−350,−512)**，`sizeDelta` 是**相对锚框的偏移**、不是 rect 高度 ⇒
`OnRectTransformDimensionsChange` 里那一跳到底喂的是哪个 rect，必须在实况里量一次）。

**⇒ 结论：这条不能按 A18 的「384 ⇒ 112.5」去改我们的公式**（会改错方向）。**没查清的那一步** =
在原版游戏里跑一次、把 `CollectionCard` 的 `transform.sizeDelta` / `rect` / `Content.rect` / `CardUI.localScale` / `Counter.rect` 五个量**同时打出来**
（`d:/2/Warpforge_tools/scenejumpshot/SceneJumpShot.cs` 可自己加探针；收藏窗是能用 `-wfscene` 跳进去的菜单，不是战斗）。

### 5.3 我们的口径与它**不可比**的地方（就算上面查清也要一起判）

| 项 | 原版 | 我们 |
| --- | --- | --- |
| 卡的尺寸与格子的关系 | **比例式**（`scale ∝ sizeDelta.y`），卡/格 = 0.976 | **尺寸式**（`(格高 − 张数条)/(Height×108)`），卡/格 = 0.900 |

```csharp
        it.Relayout();                                   // 走 HandLayout.Place → CardView.TweenPose
        CardTween.Advance(0.01f);                        // 让补间真正起步（首帧不一定推进）
        from = tw0.transform.position;
        CardTween.Advance(CardTween.RelayoutDuration * 0.5f - 0.01f);
        Vector3 mid = tw0.transform.position;
        CardTween.Advance(CardTween.RelayoutDuration);   // 推到终点
        Vector3 end = tw0.transform.position;
        float p = Vector3.Distance(from, mid) / Mathf.Max(1e-6f, Vector3.Distance(from, end));
        Check(Mathf.Abs(p - 0.75f) < 0.05f,
              $"★ 手牌重排半程走了 {p:F3} 的位移（OutQuad 半程 = 0.75）"
            + "｜判据 `CardScript__UpdateMinionInHandPosition.c` 三条单补间不写 SetEase"
            + "｜🧨 传 Linear ⇒ 0.5；把 `CardView.TweenPose` 退回 `CardTween.ToPose(…, OutQuad)` ⇒ 0.9375");
    }
    finally { CardTween.Mode = oldMode; it.hand.animateRelayout = oldAnim; it.Relayout(); }
}
```

**灭自证**：`from / mid / end` 全部取自**渲染位姿**（`transform.position`），不是我们自己的常量；
`end-from` 当分母 ⇒ 与手牌档、卡宽、分辨率全部无关；只有**曲线形状**能决定 0.75 / 0.5 / 0.9375 三档。
⚠️ 若 `from≈end`（这张卡本来就在槽 0 且没动），`p` 无意义 ⇒ 先断言 `Vector3.Distance(from,end) > 0.05f` 再比。
