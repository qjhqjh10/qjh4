## 一、逐条结论

### P1-5 · `UnitChatPanel` 把「本来没声」与「真缺口」合成同一个 `false` —— **已修**

**改前**（`Speak:964`）：`b.expectsVoice = expectVoice && clip != null;`
⇒ `expectVoice:true + clip:null`（真实资源缺口）与 `expectVoice:false`（这一档本来就没声，例 `MuteEnemyChat`
的 SmallTip）在气泡上长得一模一样。而 `TickBubble` 那条「气泡在显示但没有音频在播」（`新账-63` 的诊断口、
全仓唯一的缺口信号）只在 `b.expectsVoice` 为真时才响 ⇒ **真缺口永远静默**。

**改后**（三态拆开，行为不变）：

| 状态 | `voiceRequested` | `voiceMissing` | `expectsVoice` | 现象 |
| --- | --- | --- | --- | --- |
| 该有声 + 取到 clip | true | false | **true** | 照旧播；Play 失败仍走原来的「没在播」告警 |
| 该有声 + 取不到 clip（**真缺口**） | true | **true** | false | 气泡照原版显示；**新告警单独响一次**（`WarnVoiceMissing`） |
| 这一档本来就没声（`expectVoice:false`） | false | false | false | 照旧静默（⛔ 不误报） |

- `expectsVoice` **保留原义**（= 该有声且取到 clip）；`TickBubble:1294` 那条「Play 失败」告警一个字没改。
- `voiceRequested` = 调用方 `expectVoice` 原值（只记语义，当前无读者 —— 见「没做/没查清」）。
- 告警去重口径 = **`卡id|事件`**（同一张卡同一句只喊一次；不每帧刷、也不每句重复喊），
  与 `VoiceLines.Clip` 的 `_missingLogged` 同形；`Bubble.warnedVoiceMissing` 另按颗兜一层。
- 新增自检读口：`VoiceMissingWarnCountForTest`（累计出声条数）· `ResetVoiceMissingWarningsForTest()`
  （清去重表+计数，**只给自检**；生产路径不清 —— 「缺了哪几行」是一笔跨局的账）。

**证据（改后）**：`UnitChatPanel.cs:202/209/212/215`（三态+闩）· `:986-1002`（赋值+出声点）·
`:1105-1121`（`WarnVoiceMissing`）· `:1290-1294`（「没在播」那一支的注释订正）· `:1341-1356`（计数/清口）。

**⚠️ 一个必须知道的事实**：`BattleDriver.SpeakFor`（`:6120` / `:6130`）在 `clip == null` 时**早退、根本不调
`Speak`** ⇒ deploy/attack/death 的单位语音缺口**不经过**本告警；那一路由 `VoiceLines.Clip` 的
`_missingLogged`（`VoiceLines.cs:696-700`）出声一次。**不是静默**，只是信号在另一处。
本告警覆盖的是「**调用方以为该有声、把 `clip:null` 交给了气泡**」这一类（开场白定制音解不出、
