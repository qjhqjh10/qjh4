## 二、判据（逐条，全部 `d:/2/tools/decomp_full/` 亲读）

### 2·1 缩放：`GetEnemyCardPlayedDisplayScale` = `Vector3.one × 1.4`（**绝对 localScale**）

| 出处 | 原文要点 |
|---|---|
| `CardScript__GetEnemyCardPlayedDisplayScale.c:26-31`（非移动档） | 基准 = `*(Vector3*)(static_fields(DAT_1842da2a8) + 0xc)`（x,y 在 `+0xc`、z 在 `+0x14`），再 `× *(float*)(globalVars + 0x48)` |
| 同文件 `:48-61`（`+0x11c` 打开那一档） | 同一个基准 × `[0x48]` × `[0x4c]` |
| **基准是什么** | `DAT_1842da2a8` **就是 `UnityEngine.Vector3` 的 Il2CppClass**、`static_fields + 0xc` = **`oneVector`**。静态字段表（`dump.cs` 的 `UnityEngine.Vector3` 块）：`zero 0x0 / **one 0xC** / up 0x18 / down 0x24 / left 0x30 / right 0x3C`；类身份三条独立反证 → `资料/普查产出_1011/审查_W1.md:113`。⇒ **基准 = `(1,1,1)`** |
| `CardScript._DisplayOffensiveCardInCenter_d__264__MoveNext.c:58-61` | `DOScale(GetEnemyCardPlayedDisplayScale(), param_2)` + `SetEase(3)`（= `OutSine`） |
| `CardScript__DisplayOffensiveCardInCenter.c` + `BattleManager._ApplyOffensiveAndDefensiveEffects_d__337` | 两个实参都是 `DAT_1834b2dc8` = **0.3** |

**同一条链的起手那一半（最强的量纲反证）**——`BattleManager__DisplayRevealedCard.c:47-53`：
建完卡立刻 `set_localScale(同一个基准 × DAT_1834b2dbc)`，而 `DAT_1834b2dbc` = **0.01**
⇒ **起手 = `Vector3.one × 0.01`（绝对 0.01）**，终点 = `Vector3.one × 1.4`（绝对 1.4）。
一始一终同量纲；我们那格 `RevealStartScale = 0.01` 本来就对得上（旧注释写的「场上值 × 0.01」是错的，已订正）。

### 2·2 `250` 属于**另一条链**（这也是旧算式的病根）

- `Card Display/Cards/CardUI` 的 `m_LocalScale = **250**` 是 **`CardDisplayWindow`（战斗放大窗）** 那个 uGUI 槽
  （⇒ 大卡画出来 `2.0927 × 250 ≈ 523` px 宽）。出处：`资料/战斗UI_原版对账表.md:48` · `资料/阶段二_卡片详情窗_原版规格.md:567`。
- 进攻卡 reveal 用的是 **`BattleCardManager.CreateCard` 建的世界空间卡**（父级 = `transform(BattleManager+0xd8)`），
  原版对它**从不读那个 250**。两个数被当成一个，是旧值大 2.3 倍的直接原因。

### 2·3 `CardView.Width` 是设计基准，「108」是像素换算

- `Core/CardView.cs:226` `public const float Width = 2.0927f;`（`CardUnitW` 同值，`:600`）——
  **单位 = 世界单位**；网格按 `Width / CardUnitW`（今天 = **1**）铺 ⇒ `localScale = 1` 时世界宽就是 **2.0927**。
- `LayoutSpace.DesignPxH / DesignHeight = 1080 / 10 = 108` ⇒ **1 世界单位 = 108 设计 px** ⇒ 卡自然宽 = **226 px**。
- 结论：**`CardView.Width` 是设计基准（卡本体几何），108 是它到像素的换算系数** —— 旧注释把「1 世界单位」当成了卡宽，
  于是把 `250 px` 的目标宽除以 `108`（而不是 `226`），又多乘了一个 1.4 ⇒ 3.24。

### 4·1 reveal 终点宽（**核心**，含灭自证）

**插在现有 reveal 块** `drv.AdvanceOffensiveRevealForTest(1.9f);`（现读 `:4801`）**之后**：
此刻 `_revealT = 1.9` ⇒ 缩放补间（`0.198 + 0.30 = 0.498`）早已结束、卡**还没被收走**。
⛔ 别放到 `+0.2` 之后 —— 那已进第 1 段（飞向 HUD 钮）。

```csharp
// ═══════════════════════════════════════════════════════════════════════════
// 🆕 2026-10-24（执行代理 `D6`）：reveal 的**终点缩放/世界宽**
//   ⛔ 期望值**不读** `BattleDriver.RevealEndScale`（那是被测常量 ⇒ 读它就是自证）。
//   算式只用两样独立量：① 原版字面量 **1.4**（`globalVars+0x48`；
//   `CardScript__GetEnemyCardPlayedDisplayScale.c:26-31` 的基准是 `Vector3.one`）
//   ② 卡自己的几何 `Core/CardView.cs:226` 的 `CardView.Width`（2.0927 世界单位）。
//   `LayoutSpace.Scale` 在 16:9 = 1（本场 `cam.aspect` 已由 `:883` 那条钉死）。
// ═══════════════════════════════════════════════════════════════════════════
{
    var rv = drv.RevealCardForTest;
    Check(rv != null, "（前提）reveal 第 0 段末那张揭示卡还在");
    if (rv != null)
    {
        float wantW = CardView.Width * 1.4f;                       // ≈ 2.9298 世界单位（≈ 316.4 设计 px）
        float gotW  = CardView.Width * rv.transform.lossyScale.x;
        Check(Mathf.Abs(gotW - wantW) <= wantW * 0.02f,
              $"★ reveal 终点：世界宽 {gotW:F4} = 目标 {wantW:F4} ±2%"
            + $"（= `CardView.Width` {CardView.Width:F4} × 原版 **1.4** `globalVars+0x48`）"
            + "｜🧨 退回旧算式 `1.4 × 250 / 108 ≈ 3.24` ⇒ 宽变 "
            + $"{CardView.Width * (1.4f * 250f / 108f):F4} ⇒ 红");
        // 灭自证：旧算式那个值是同一个量的另一个候选 ⇒ 结构上不可能同时满足这两条。
        Check(Mathf.Abs(gotW - CardView.Width * (1.4f * 250f / 108f)) > wantW * 0.5f,
              "★ reveal 终点**不是**旧推导值 `1.4×250/108`"
            + "（那是把 `CardView` 自然宽当成 1 世界单位算的；实际 2.0927 世界单位）"
            + "｜🧨 把 `RevealEndScale` 改回旧算式 ⇒ 本条红");
        // 同一条原版函数的两个消费点不许分叉（两处写同一条规则 = 迟早不一致）
        float twin = BattleDriver.PlayedCardCenterAbsoluteScaleForTest * LayoutSpace.Scale;
        Check(Mathf.Abs(rv.transform.lossyScale.x - twin) < 1e-3f,
              $"★ reveal 的终点缩放与「打出的卡居中展示」**同一个原版函数** ⇒ 同值"
            + $"（实得 {rv.transform.lossyScale.x:F4} vs {twin:F4}）");
    }
}
```
