## 四、没查清 / 没做（逐条写为什么）

### ① `AM18`（以及同族的 `GOF4` / `GOF90` / `TL68` / `SOR71` / `AM34` / `BL31`）—— **触发层不读 `for each` 计数**

* **实测**：`ruleprobe play GOF4`（`Rally: Gain +1 Attack for each other friendly Slugga Boy`）夹具里
  **0 个其他 Slugga Boy**，原版按 `multiplier` 应乘 **0**，我们给了 **+1**。
* **根因**：`ResolveOps` 的 **触发重载**（`IReadOnlyList<EffectOp>`）**没有 `repeats` 循环** ——
  那一段只写在**出牌 / 战术卡**那条重载里（`EffectResolver.cs` 的 `CountRef + CountScope ⇒ repeats`）。
  ⇒ 所有**触发**的 `for each`（`AM18` 回合末 / `GOF4` 集结 / `AM34` Duty / …）今天都按 **1 遍**结算。
* **为什么没顺手改**（⛔ 不是「成本高所以不做」）：两条原版机制**不是一回事**，机械照搬会引入新的静默错：
  * `multiCountCriteria` ⇒ **整条 ability 触发 N 遍**（`TriggerAbilities.c:230-250`）；
  * `multiplier` ⇒ **把数值乘 N**（`PlayAbility.c:708` `local_178 * damage`；`AdjustCardEffect(…, local_178)`）
    —— 与「重复 N 次」在**随机选靶 / 护甲 / 阈值**上结果不同（`Deal 1 damage for each X`：
    原版是「一个目标吃 N 点」，我们出牌路是「N 次各 1 点、可换目标」）。
  ⇒ 需要先把「哪一格驱动」按卡分开（`multiSet` vs `multiplierSet`），**再**决定触发层接哪一套。
  **建议单独立账**（本批只记，未改行为）。判据与证据已写进 `A1MultiCountEightCards` 的注释。

### ② `ASH52 Hosts of the Dead` —— 判不准，未改

🔴 **2026-10-24 订正（铁律 5 · C6 现核）：本条「判不准」已过期** —— 发射点**找到了两个**：① `RawCardScript__OnCardPlayedWithTarget.c:66`（全库**唯一** `TriggerAbilities(...,600,...)`，打在被打出的那张卡自己身上）；② 动作 77 链 `AbilityLogic__PlayAbility.c:1767`（case 440）→ `AddTriggerSpiritStone` → `ResolveAction:6917` → `CardScript__TriggerSpiritStone.c:16-18`（**这条不付费**）。`PlayerManager__UseSpiritStoneEnergy` 是**死函数**（全量反编译 0 调用者）。**`ta 161 = currentSpiritStone`，`GetTargets`（`GetTargets.c:321-345`）在循环之前只调一次** ⇒ N = 触发那一刻的石头数，之后每条扣 1 不再改 N ⇒ **ASH52 = 1 + K 只、花光 K 颗**；K=0 时 600 连触发都不触发。**我们已等价**（`spendspirit` + `spiritspent`，`EffectResolver.cs:11082/9654`，600 事件 `:7063`）⇒ **没有要接的东西**。判据 → `资料/普查产出_1024/C6_最后三条判据.md` §2。以下为当时的分析（留痕）——

* 原版 ab0（`ta 0`）部署 1；ab1（`trigger 600 UseSpiritStone`，`ta 161 currentSpiritStone`）再部署 N。
* **缺的两块**：
  1. **`UseSpiritStone(600)` 的发射点没定位** —— `PlayerManager__UseSpiritStoneEnergy.c` 只**扣数**、**不发触发**
     （全量反编译里没找到发 600 的那一跳）；
  2. `ta 161` 是「取**哪一刻**的剩余石头数」（每颗一次触发时递减？还是整次花完读 0？）**没有判据**。
* ⇒ 三种候选（1 + N / 1 + Σ递减 / 1）**读数差很大**，⛔ 不猜。我们今天的正文口径是
  `deploy 1 + spendspirit + deploy × LastSpentSpirit`（= 1 + 已花颗数）。**留待单独立账。**

### ③ `GSC75 Roaming Outriders` 的同一族计数仍然错（本批**没修**）

`Repeat for each Vehicle in your hand …` 的量词从句带着尾巴（`… and lower their cost by 1`），
`ClassifyCount` 的 `hand` 正则（`^… in the … hand\b`）**没命中** ⇒ 仍归成 `board`（数**场上**载具）。
判据与 `GSC56` 同一族（原版 `multiplier` 现读 `ta 50 inHandFiltered / friendlyUnits / keywordFilter`），
修法 = 放宽那条正则的**前缀**（现在它要求从句以量词开头）。⚠️ 它的原版重复形式是 `multiplier`（乘数值）
而不是 `multiCountCriteria`（§四·①），所以**不能**直接改成 `hand` 就完 —— 两件事要一起判。
