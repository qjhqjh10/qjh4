## 三、`JsonUtility` 初始化器（`ReplayStore.cs` 注释 + `BattleScene.cs` 封印断言）

### 3·1 结论

**`JsonUtility.FromJson` 会跑目标类型的无参构造（因而跑字段初始化器）⇒ 缺键字段留着初始化器写的值，⛔ 不是 `default(T)`。**
`ReplayRecord` 没有显式构造 ⇒ 走**隐式无参构造** ⇒ 属于「会跑」那一档。

### 3·2 判据（⚠️ 是**引擎行为**，不是本工程的数据判据）

1. **`Unity 6000.3.4f1` 实跑**：`kan-kikuchi.hatenablog.com/entry/JsonUtility_Ctor`（2026-03-05）——
   作者实测无参构造在反序列化时被调用，并引官方新文档「Field initializers and any logic in the default
   constructor are executed during deserialization」。**与本工程同一个 6000.3 小版本线**。
2. **官方 ScriptReference 改写过**：`Unity 6000.6 / 7000` 的 `JsonUtility.FromJson` 现在是
   「有无参构造就调它、字段初始化器一起跑；**没有**则字段落 `default`」；
   而 `2018.1 ~ 2023.1`（含 `6000.0` 旧页）写的是反的（「构造函数不执行」）⇒ 旧文档被更正。
3. ⚠️ **本会话没跑 Unity（红线）** ⇒ 上面两条是**外部证据**。本工程自己的**封印** = 下面 3·3 的探针断言
   （第一次实跑就在下一个同步点）。

### 3·3 加的 3 条 Check（`BattleScene.Run` · ⑩ 之后、⑪ 之前）

| # | 钉什么 | 灭自证 / 🧨 改坏法 |
| --- | --- | --- |
| 1 | 缺键 JSON ⇒ `intWithInit == 4242` 且 `strWithInit == "INIT"`（探针的初始化器**故意 ≠ 默认值**） | Unity 换版本后若不跑初始化器 ⇒ 读到 `0` / `null` ⇒ 红 |
| 2 | **判别式**：同一段 JSON 里**给了键**的 `plainInt` 照常被覆盖成 7 | 证明 #1 不是「整个对象压根没解析」的假绿 |
| 3 | **真对象**：`ReplayRecord` 缺键 ⇒ `tutorialStage / botSeatPlus2 / mulliganPlus1` 全 = `0` | 任一哨兵改成 `-1`/别的非 0 值 ⇒ 红（真机上 = 每份老录像被当成某一档） |

那一份已在用 `JsonUtility.FromJson<SrcVfxRt>` ⇒ 嵌套类型可用）。⛔ 生产代码一个字节都不碰它。

### 3·4 注释订正（`ReplayStore.cs`，4 处 · 结论统一）
