## 二、改法（`match_owner`，判据写在函数 docstring + 文件头）

**旧**（`for tbl in tables:` ⇒ full 先返回）：

```python
for tbl in tables:                     # full → short
    hit = None
    for key, cards in tbl.items():
        if " " + key + " " not in header: continue
        if hit is not None and hit is not cards[0]: return None
        hit = cards[0]
    if hit is not None: return hit     # ← full 层一命中就返回
```

**新**（两张表一起比，按「命中键含几个词」定具体度）：

```python
best_words = -1          # 命中键的**词数**（越多 = 覆盖得越具体）
best, ambiguous = None, False
for tbl in tables:                       # ⛔ 不再「full 命中就返回」
    for key, cards in tbl.items():
        if " " + key + " " not in header: continue
        card, words = cards[0], len(key.split())
        if words > best_words:
            best_words, best, ambiguous = words, card, False
        elif words == best_words and card is not best:
            ambiguous = True             # 同词数、不同卡 ⇒ 多义
return None if ambiguous else best       # 宁可认不出
```

**为什么具体度用「词数」而不用「字符数」**（这是我做的一个判断，请调度台复核）：
字符数会在**阵营词**上翻车 —— `VO_Tyranid_Leviathan_Biovore` 的 header 同时命中
`full["biovore"]`（`TL6`，7 字符）与 `short["leviathan"]`（`TL52 "Leviathan's Tendrils"` **的首段**，9 字符），
按字符数「更长者优先」会把**虫族**的登场语音挂到 `TL52` 头上（`leviathan` 只是**文件名里的阵营段**）。
词数在两边都是 1 ⇒ 判多义 ⇒ 不认。**实测两种口径对今天这张表产出完全相同**（都是 0 行变化），
差别只在这个反例的未来隐患上。

**同名多义（词数相同、不同卡）现读 = 22 组**（这就是「full/short 撞车」的全部面）：

## 六、顺手发现（只报不改）

1. 🔴 **`match_owner` 的 header 只按 `" - "` 截断，`_` 分隔的文件会把「台词正文」并进 header。**
   实证（新规则会在 ③ 猜错的一条）：`VO_GSC_Neophyte Initiate_The day of ascension approaches.ogg`
   —— 没有 `" - "` ⇒ header = 整串 ⇒ 命中 `full["day of ascension"]`（`GSC59 "Day of Ascension"`，3 词）
   **压过** `full["neophyte initiate"]`（`GSC6`，2 词）⇒ 新规则会猜 `GSC59`（真主 `GSC6`，`summonAudio` 直指）。
   ⚠️ 今天无害（这条由 ① 收走），但**同族文件名（`VO_GSC_*_<台词>` 这类）都有这个形状**。
   要根治得给 header 定「卡名段在哪结束」的判据（**没找到**：文件名规约里没有可靠分隔）。
2. **新规则仍会猜错的 3 条**（全部今天由 ① 收走，真主已核）：
   | 文件 | 新规则会猜 | 真主（SO） |

   | `VO_DA_Redemptor Dreadnought - My quest for vengeance is eternal.ogg` | `UM28 Redemptor Dreadnought` | **`DA34 Unforgiven Redemptor`** |
   | `VO_UM_Valtus, Redemptor Dreadnought- Lead me to the slaughter!.ogg` | `UM28` | **`UM83 Valtus`** |
   | `VO_GSC_Neophyte Initiate_The day of ascension approaches.ogg` | `GSC59 Day of Ascension` | **`GSC6 Neophyte Initiate`** |
   ⇒ 两条的共性：**真主的卡名是命中键的子串**（`Unforgiven Redemptor` ⊂ header 里的 `Redemptor Dreadnought`？
   不是 —— 是**文件名写的是另一张卡的名字**：原版把 `DA34` 的音频文件命名成了 `Redemptor Dreadnought`）。
   **这类只能靠「文件名与实际卡名不一致」这个已知事实**（D5 §四·2 那一条），`match_owner` 猜不出来。
   **建议**：③ 这一级**永远只当兜底**（现状即是），别让它去补 ①② 的空。
