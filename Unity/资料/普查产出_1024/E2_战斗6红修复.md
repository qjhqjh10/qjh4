## 二、为什么没有降级判别力

原断言要证：**精确档不是「后缀兜底」的复制品**。新夹具用**结构上不可能同时满足**的一对守住同一件事：

| 断言 | 它挡的是什么 |
|---|---|
| (a) 兜底在同一合成 id 上给不出 | 挡「命中其实来自兜底」——不是精确分支的功劳 |
| (b) 注入后 `TryPickExact` **拿得到注入值** | 🧨 精确档改回「照抄兜底」/ 改成不查表 ⇒ 合成 id 在 `voice_lines.json` 里**根本不存在** ⇒ 取不到 ⇒ **红** |
| (c) **还原后**取不到 | 🧨 把精确档写死成「对任何 id 都回一条 / 不查表」⇒ (b)(c) **必有一条红**（同一个口、相反期望） |
| (b0) `WasInjected` + (0) `Ready` | 挡「精确表/兜底表没载入 ⇒ 前提不成立」时**默默变绿**（那是假绿，不是通过） |

⇒ 比原来那条**更强**：原断言依赖数据巧合（某条数据刚好兜底给不出），一改数据就塌；
新夹具不依赖任何数据，而且多了一条「还原」的自证。

## 五、顺手发现（不属这 6 条）

1. **`SourceOf` / `DurationOf(EvtKind)` 的 `default:` 同样「只查零时长表」，但这两处是对的** ——
   `TimedKinds` 9 档在 `SourceOf` 里**各有 `case`**（到不了 `default`），所以不是同一个缺陷。
   ⚠️ 但**注释没写清这一点**，很容易被下一个人照着 `IsSourced` 的形状误判成「三处同一坑」。
   本次只在 `IsSourced` 的 doc 里补了说明（未越出白名单去改另两处注释）。
2. **`VoiceLines.ExactEntries` 不随 `SetExactForTest` 变化**（它记的是「载入时读了多少条」，不是表长），
   而 `ExactCards`（= `_exactById.Count`）**会**含合成卡 ⇒ 若将来有人在**注入作用域内**
   断言这两个计数，`ExactCards` 会偏大。已在 `SetExactForTest` 的 doc 里写明；本次自检的注入块内**没有**这么用。
3. **`VoiceLines.TryPick` 的 `EnsureLoaded()` 在合成 id 上会走完整条兜底链**（本次被当成前提 `(a)` 用）——
   `EvtMatches` 对 `"deploy"` 是精确相等，不会误匹配到别的 ev，前提可靠。
4. `BattleScene.cs` 那一大段「灭自证②」的历史注释（`exOnly` 那批）现在还留着两处**历史读数**
   （`621 条命中 · 5 条与兜底不同 · 0 条兜底给不出`）。它们标着日期、读得出是历史，本次**只在明显断言性语句上**加订正，
   没有逐条重写 —— 若主对话要彻底清理，那是文档整理活，不在本次白名单范围内。
