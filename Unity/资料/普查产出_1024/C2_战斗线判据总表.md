### 1·4 🔴 **方案不能直接照做的根因** —— 播放通道不对（这是本条的**新发现**）

A21 §2·4「写法 A」说：并桶之后自然走 `ResolveAllTimed(Trigger, …, perCardOnly:true, keyword)`。**它确实能解析出正确的 prefab 名**，但播放通道是：

```
BattleDriver.PlaySignal（EvtKind.Trigger）
  → FireEventAll(evt=Trigger, …, perCardOnly:true, keyword)        BattleDriver.cs:18696-18702
      → VfxMap.ResolveAllTimed(...)                                 VfxMap.cs:1239
      → CardEffects.Fire(name, pos, parent) / ScheduleVfxCue        BattleDriver.cs:17714-17734
```

`pos` = 这张卡在**屏幕上的格位点**（`layout.DropTargetWorld(slot)`，`BattleDriver.cs:18786-18787`），**没有**：
- `CardAnimTime` 的 `startPosOption` / `endPosOption` 锚点解析（`PlayAbilityBeat` 那一层）；
- 卡体动画层（`Card3DAnimationController.DoAnim`）；
- 每拍时长 `SkillBeatDuration`（`vd+ts+tm+te`）。

而 `unit_attack_anim` 这一桶**正确**的播法是 `PlayUnitSkillAnim`：
```
PlayUnitSkillAnim(e, VfxMap.UnitAttack, t0)        BattleDriver.cs:19449-19478（CardAnimClips.Resolve 在 :19455）
  → CardAnimClips.Resolve(UnitAttack, …)            CardAnimClips.cs:290-314
  → PlayOneUnitAnim(e, clip, dur)                   BattleDriver.cs:19513-19586
      → PlayAbilityBeat(sp/ep/pt 锚点) + CardAnimController.DoAnim
```
⇒ 照 A21 原样做，**prefab 名对了、位置/朝向/体动画/时长全错**（而且 `CardEffects.Fire` 用 HUD 点，与 `startPos/endPos` 语义无关）。
（可自证：`CardAnimClips.Resolve` 就是拿 `ResolveAllTimed(UnitAttack)` 取名的 ⇒ 名字那条链**已经通**，断的是「谁来播」。）

### 6·2 🔴 数据侧的关键细节（A7 那段需要补一句）

`Resources/trait_effect_bindings.json`（75 行 / 62 trait）现读：
- `stun(100)` **只有 `TriggerType=2 OnPlay → StunEffect`**，**没有 Start(0) 行**；

⇒ **精确结论**：
- 「再晕一次」在原版 **也不会重播** `StunEffect`（OnPlay 已在字典里）；`DisplayStatusAnim(100)` 那一下的价值是**重新激活被 Clean 掉的框** + 可能的位置归位。
- **真正丢的是「有 Start(0) 行的 trait 再施加」**（典型 `huntMark` 的 `HuntMark_StackEffect` 层数 +1、`armour` 再加一层、`rally` 再触发一次）—— 原版每次都播 Start，我们**一次都不播**（第二次以后）。

### 6·3 我们现状

- 唯一入口 = `TraitFrames.SyncKeywords(IEnumerable<string> current)`（`Core/TraitFrames.cs:745-760`）：**集合对差** —— `if (_prev.Contains(k)) continue;` ⇒ 只有**新出现**的关键词才 `DisplayStatus(k)`。

- 调用点：`BattleDriver.cs:21312`（`SyncBoard` 里 `tf.SyncKeywords(u.Keywords.Keys)`）。

### 6·4 补的入口应在哪、什么形状

**形状 A（推荐，语义最正）**：**引擎发一条「状态施加」事件，表现层收到就调 `DisplayStatus`**。

| 步 | 文件:行 | 改动 |
|---|---|---|
| 1 | `RuleEngine/Core/BattleEvent.cs`（`EvtKind` **末尾追加**） | 新增 `StatusApplied`：`CardId = 关键词`（如 `"stun"` / `"huntmark"`）、`Player/Slot` = 被施加的那张卡。判据 = 原版 `DisplayStatusAnim` 的 5 个调用点全部是「**某条 effect/trait 被加到这张卡上**」那一刻 |
