## 根因

`RuleCore.PlayCard(ctx, p, handIdx, slot)` 的 `slot` 是**【请求格】，不是落点**（`Core/RuleCore.cs:3392-3400` 的 doc，账 `A1597`）。
落点由 `BoardSlots.Insert` 算（连续无洞模型 = 插入推人）：
**空盘上请求 `0/1/2` 一律落 `3`**（`AdjustedSlot` 的夹取，见同处 doc）。

而夹具这一段是：
- `int slot = G6FreeSlot(ctx, 0);` → 开局我方盘上只有督军（槽 4）⇒ 返回 **0**；
- `PlayCard(..., slot)` 返回 `OK`，但单位实际落在 **3**；
- `var u = Board(ctx, 0, slot);` → 取的是槽 **0**（空）⇒ `u == null`。

⇒ 两条 `✗ ★ (前提) … 上场了 —— 期望 [True]，实得 [False]`（日志 `_tmp_view/20261024_sync2/RuleEngineTest_final.log:223563-223611`）**是夹具取错格，不是引擎缺陷**。第二段（盘上先 `Place` 了一张 GOF4）同一个原因。

## 改动

`RuleEngineTest_G6.cs`：

1. **①（单独一张）** 打出前 `G6Snapshot(ctx, 0)` 存引用快照；`PlayCard` 之后用
   `G6JustPlayed(ctx, 0, "GOF4", before)` 取那张刚上场的单位，再对它断 `Attack`。
2. **②（另一张 GOF4 先 `Place` 在场）** 同法。盘上会有两张 `GOF4` ⇒ 靠「打之前不在快照里」的**引用差集**区分，
   再叠一道 `PlayOrder` **最大**做兜底（`Place` 先取号、`PlayCard` 后取号 ⇒ 刚打出的那张号更大）。
3. **新增两个夹具助手**（放在 `G6FreeSlot` 之后）：
   - `static UnitState[] G6Snapshot(BattleContext ctx, int p)` —— 棋盘**按引用**拷一份；
   - `static UnitState G6JustPlayed(BattleContext ctx, int p, string cardId, UnitState[] before)` ——
     判据三条：① 不在 `before` 里（`System.Array.IndexOf` = 引用比较，`UnitState` 没有重写 `Equals`）；
     ② `u.Card.Id == cardId`（⛔ 不用 `Name` —— 卡名会重）；③ 多张命中取 `PlayOrder` 最大。找不到返回 `null`。
4. **就地订正 `G6FreeSlot` 的 doc**（铁律 5）：原文写「夹具摆场 / **`PlayCard` 的落点**」——
   它只是**请求格**，不是落点；已改写并指向 `G6JustPlayed`。
