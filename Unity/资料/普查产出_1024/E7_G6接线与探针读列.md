## 五 · 顺手发现（⛔ 只报不改，由调度台分流）

### 1 🔴 `G6` 的数据让 5 张战术卡的「按抽到的部队数」**从 2 变成 0**（疑似真缺陷，不是探针的问题）

**现象**（`bash 工具/ruleprobe.sh play BL51`，引擎自己的日志）：

```
战术卡：「Draw 2 cards」抽了 2 张
战术卡：「For each troop drawn, create a copy of Abaddon's Chosen in your hand」按 any 计 2 遍
战术卡：「…」正文计数「any」= 2，而原版 `multiplier` 结构化数据 = **0** ⇒ 按数据 0 遍
  （`AbilityLogic__PlayAbi…`）
```

**受影响的 5 张**（都是 `Draw N cards. For each troop drawn, …`）：`BL51` / `DA49` / `EC45` / `SAU75` / `SOR49`。
它们的 `mult` 行 = `(ab=0, lg=1, role=mult, cond=0)`，`multiplierSet` 现读
`targetsAffected = 150 (previousAbilityFiltered)` · `friendlyUnits 1` · `includeMinions 1`。

**为什么是 0**：`Core/CountEval.cs:412-434` 的 `ta == 150` 分支只数 `ctx.PreviousAbilityTargets`
（写点 = `ResolveOps` 出口，**只建模场上单位**；该分支自己的注释 `:410-411` 就写着「碰上手牌候选 ⇒ null + 出声」）。
「上一跳抽到的牌」不在里面 ⇒ 表是空的 ⇒ 循环一次不跑 ⇒ **返回 0，而且不报 gap**（`gap` 只在「候选不在场上」时置）。

**为什么改前不是 0**：这 5 条 `mult` 行是 `G6` 才落进数据/`CardDef` 的（改前 `cond == 0` 一律被丢）
⇒ 改前走正文计数（2，正确的那个）；现在 `EffectResolver.cs:498-518`（出牌路）/ `:11745-11764`（触发路）
的「**结构化乘数优先，不一致时按数据并出声**」规则把 0 顶上去。

**证据链**：夹具的 2 张抽牌是 `filler27` / `filler28`（`PlayProbe.cs:270-276`，`i % 5 != 4` ⇒ `Fix(...)` = **unit**）
⇒ 卡面语义「for each troop drawn」应为 **2**。

**建议处置**（三选一，判据都在原版）：① `CountEval` 的 ta=150 分支在「上一跳是抽牌 / 候选应为手牌牌库卡」时
**返回 `null` + `gap`**（照它自己那条注释），让 `TryStructuredMultiplier` 退回正文；② 在 `PreviousAbilityTargets`
里补「本跳抽到的牌」（原版 `SetPreviousAbilityTargets.c:19-28` 写的是整表，含非场上卡）；
③ 若确认这样 `mult` 行对消费端无意义，在生成器侧不落（但那要与 G6 §三·2① 的 `any` 口径一起定）。
⚠️ **在哪都别在探针里补** —— 探针现在这样是**对的**（它如实反映引擎行为）。
