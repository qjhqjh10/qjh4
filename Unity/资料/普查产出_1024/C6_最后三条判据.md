## 一 · `multiCountCriteria` ⇒ 整条 ability 触发 N 遍（`AM18` 及同族）

## 1·1 结论（一句话）

**判据完整解出、可以照做。原版规则 = 「`multiCountCriteria != null` 且 `targetsAffected != 0` ⇒ 先用 `AbilityLogic.GetTargets(manager, multiCountCriteria, thisCard, thisCard, targetCard, checkMaxTargets:true)` 求一个候选列表，再 `for (i < 列表.Count) TriggerAbility(...)`」——列表为空 ⇒ 一次都不触发。`targetsAffected == 0 (any)` ⇒ 只触发一次。**

`AM18` 因此**应当按「友方载具数」触发 N 遍**（N 可以是 0）。我们今天是 **1 遍**，且计数还把「友方载具」数成了「友方全体单位」（见 1·4 与 §四·2）—— **两处都错**。

## 1·4 「补 repeats 会不会和 `GOF4` 的实测冲突」—— **不会，两者是不同的机制**

**`GOF4`（Slugga Boy）根本不是 `multiCountCriteria`**：

| 字段 | `GOF4` 的值 |
|---|---|
| `uniqueId` / `cardName` / `path_id` | `GOF4` / `Slugga Boy` / `-4629209585521307817` |

⇒ `GOF4` 走的是 **`AbilityLogic.multiplier` = 把数值乘 N**，与 `multiCountCriteria`（触发 N 遍）**不是一回事**（A1 §四·① 自己已经写了这句，只是把它归进了同一个「触发层没有 repeats」的标题下）。

**`GOF4` 该不该乘 0：该乘 0，A1 的实测结论是对的。判据：**

1. `AbilityLogic__PlayAbility.c:181-236`：`local_178 = GetTargets(manager, multiplier, thisCard, checkMaxTargets:true).Count`（`ta == 0(any)` ⇒ 1；`ta == 210/220` ⇒ 累加 `traitsFilter` 值）；`if (furtherMultiplier(+0x38) > 0) local_178 *= furtherMultiplier`。**没有 clamp 到 1**。
2. **自己不算进去**：`FilterMethods__CheckIfMeetsCriteria.c:233` / `:241`——
   `cVar2 = op_Equality(param_1 /*thisCard*/, candidate); if (cVar2 && *(char*)(criteria + 0x1d /*includeSelf*/) == 0) return 0;`
   `GOF4` 的 `includeSelf = 0` ⇒ **自己排除** ⇒ 场上只有它自己时 **N = 0**。
3. `buffSelf` 分支确实乘 `local_178`：`AbilityLogic__PlayAbility.c:1310`（`iVar8 == 0x28`）→ `:1359-1360 AbilityLogic__AdjustCardEffect(..., local_178 * *(int*)(*puVar1 + 0x18), ...)` ⇒ **+1 × 0 = +0**。
4. ⚠️ 顺手确认：伤害那一支是 `:671` 的 `for (; iVar20 < count && 0 < local_178; local_178--)` + `:708 local_178 * damage` ⇒ `N=0` 时**一次都不打**（不是打 0 点）。

⇒ **补 `multiCountCriteria` 的 repeats 与 `GOF4` 完全无关**（它的 `multiCountCriteria` 是 any(0)，永远走「只触发一次」那条）。`GOF4` 要修的是 **`multiplier` 那条路**，而它今天的病根和 `AM18` 是**同一个 early-return**：`GOF4` 的 `multiplier.conditionsFilter = 0` ⇒ `mult` 行没落 ⇒ `TryStructuredMultiplier`（`EffectResolver.cs:11524`）取不到结构化乘数 ⇒ 退回正文计数，而正文计数**没排除自己**（`CountFor` 盘面分支，`:9780-9800`）⇒ 数到 1 ⇒ +1。**实测读数与 A1 一致，成因与 A1 写的不一样。**

## 二 · `ASH52` 的 `UseSpiritStone(600)` 发射点

## 2·1 结论（一句话）

**发射点找到了，而且不止一处 —— 但 `PlayerManager__UseSpiritStoneEnergy` 不是其中之一（它是 0 调用者的死函数）。真正的发射链是两条：**
1. **打出牌时，在「被打出的那张卡自己」身上发 600**：`RawCardScript__OnCardPlayedWithTarget.c:66`（全库唯一的 `TriggerAbilities(..., 600, ...)` 调用点）；
2. **动作 77（`triggerSpiritStone`）那条**：`AbilityLogic` 的 `chosenAbility == triggerSpiritStone(440)` → `BattleManager.AddTriggerSpiritStone` → `ResolveAction` case `0x4d` → `BattleManager.ResolveTriggerSpiritStone` → `CardScript.TriggerSpiritStone` → `OnTrigger(600)`（**这一条不付费**）。

**`ta 161` 的取值时刻也解了：`GetTargets` 在重复循环【之前】只调一次（`TriggerAbilities.c:250` vs 循环 `:253`）⇒ N = 触发那一刻的石头数，之后循环里逐次扣 1 颗，N 不会再变。**
