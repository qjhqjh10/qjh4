### 1·1 先从 `.c` 说起（这是**误读的来源**）

```c
  if (lVar4 != 0) {
```

### 1·4 「case 支里那个非空判断」**不是**「取不到就返回空」

`.c` 里每个 case 都有一句 `if (lVar4 != 0)`，看起来像「字段为空 ⇒ 返回空」。实际那是
**il2cpp 给 `callvirt` 补的空检查**（失败就走 `0x1803f47a0` 的抛异常桩）。

而这类字段**在序列化里根本不是 null** —— `资料/普查产出_1018/allcards_1350/cards_raw.json` 实测
（`Eliac Zephyrblade`，它任意一张卡的形状都一样）：

```json
"summonAudio":      {"m_AssetGUID": "", "m_SubObjectName": "", "m_SubObjectType": ""}
"attackAudio":      {"m_AssetGUID": "d5463ef3ec811481597ec31b6f6b4762", ...}
"defaultChatSound": {"m_AssetGUID": "d5463ef3ec811481597ec31b6f6b4762", ...}   ← 与 attackAudio 同一个
"introChatSound":   {"m_AssetGUID": "268a79e5c768d44ce907d6fcf19a21ba", ...}
```

⇒ **对象在、GUID 为空** ⇒ 指针非空 ⇒ 那个抛异常的分支**不触发** ⇒ `Load()` 拿不到 clip 返回空
⇒ **落到 `+0x188`**。

**旁证（同一形态的兄弟方法）**：`RawCardScript__GetDeathSound` / `__GetSummonSound` / `__GetAttackSound`
的机器码完全同形（字段 → `test/je` 抛桩 → `Load`），而它们的调用点拿到返回值后**立刻判空**：
`CardScript._UnitDeath_d__446__MoveNext.c:82-88`（`uVar6 = GetDeathSound(...)` 之后
`cVar3 = UnityEngine_Object__op_Inequality(uVar6,0,0)`）、`VoiceLinesController__DisplaySummonMessage.c:31-34`
（`GetSummonSound` 之后 `op_Equality(uVar3,0)`）。若「字段为空即抛」，1,283 张没有 `deathAudio` 的卡每次阵亡都会崩。

### 1·5 修正后的原版模型

```
GetChatSound(msg):
  if (chatAudioReferenceCard != null) return chatAudioReferenceCard.GetChatSound(msg)   // +0x180 链
  ref  = switch(msg) { 0..10 → 对应字段(空 GUID 也是非空对象);  _ → LogWarning; ref = null }
  clip = ref.Load()                                  // 空 GUID ⇒ null（不抛）
  if (clip != null) return clip
  return defaultChatSound.Load()                     // ← +0x188 【兜底】
```

进 `+0x188` 有两条路：
1. **枚举越界**（`default:` 支）—— 实际**调不到**：`ChatMessage` 只有 11 个值（`ChatMessage.cs:1-14`），
   调用点 `VoiceLinesPopupSelector.SetupChatOptions` 是 `5 + 按钮下标(0..5)` = 5..10，也在范围内；
2. 🔑 **真正会发生的**：某个 `*ChatSound` 字段存在但**没有音源** ⇒ `Load()` 为空 ⇒ 兜底到 `defaultChatSound`。
   各 case 支走这条路的指令是 `0x180946D48 e9 9b 00 00 00 jmp 0x180946de8` —— **和 `default:` 支汇到同一处**。

### 1·6 所以件 1 怎么处置

- **`ForIntro` / `ForMirror` / `ForCantDo` / `ForHurry` / `ForConcede` / `ForVersus` / `ForVoiceOver`
  里的 `"default"` 第二跳全部保持不动**；`voice_lines.json` 的 56 条 `ev="default"` 行**保留**。
- 结论写进了 `VoiceLines.cs` 文件头（**日期 + 谁说的 + 为什么错 + 复跑命令**，留更正痕迹）；

### 2·1 `TryPick` 的改法（件 2）

```csharp
int hits = 0, soHits = 0;
for (...) { if (!EvMatches(l.ev, want)) continue; hits++; if (IsSoAttributed(l)) soHits++; }
if (hits == 0) continue;

bool soOnly = soHits > 0;

int pool = soOnly ? soHits : hits;

for (...) { if (soOnly && !IsSoAttributed(l)) continue; if (seen++ != pick) continue; ... }
```
