## 一、件 1 —— `SwapToFront` → `CardView.TweenPose`

### 1·1 判据

- 病灶 = **`CardTween.ToPose` 直写 `transform.localScale`**，而本类的缩放是「**基础 `_baseScale` × 高亮 `_hlMul`**」
  ⇒ 补间期间 `_baseScale` 停在**起点槽位**的值上，补间结束后任何一次 `SetPose` / `SetHighlightScale`
  都把卡**弹回旧缩放**（静默）。判据原文 = `Core/CardView.TweenPose` 的 doc（`T04`，
  `Core/CardView.cs` 的 `TweenPose` 段）＋ `资料/普查产出_1024/A3_手牌卡面五件.md` §六。
- 原版形状：`CardDisplayWindow__ChangeCardPosition.c` 全文一个 `DOTween.Sequence()` + 六条 `Join`、
  **没有** `SetEase` ⇒ 每条子补间各吃 `DOTween.defaultEaseType`（= 6 OutQuad）。
  `CardView.TweenPose` 是**单条** `DOTween.To` ⇒ **传 `OutQuad`**；`CardTween.ToPose` 是 Sequence ⇒ 只能传 `Linear`。
  **两个入口的 ease 约定是反的**，⛔ 别对调（这一条已写进代码注释与 `CardTween` 的留档注释）。

### 1·2 改了什么（`Shell/CardDetailPopup.cs` 的 `SwapToFront`）

| 项 | 旧 | 新 | 为什么 |
| --- | --- | --- | --- |
| 入口 | `CardTween.ToPose(b.transform, pa, ra, sa, …)` | `b.TweenPose(pbInB, ra, b\`前台档\`, …)` | 带 `_baseScale` 一起过去（`TweenPose` 每帧经 `SetPose` 写） |
| 位置 | 世界位 `pa`/`pb` 直接传 | `b.transform.parent.InverseTransformPoint(pa)`（`a` 同理） | `TweenPose`/`SetPose` 吃**局部**位；今天父件是纯平移所以在数值上等价，父链一变就分家 |
| 角 | `eulerAngles.z`（世界） | `localEulerAngles.z`（局部） | `TweenPose` 写的是局部角（与 `SetPose` / `CardFan.Rot` 同一量纲） |
| 缩放 | `localScale.x`（含高亮系数） | **`BaseScale`**（`a.BaseScale` / `b.BaseScale`，跟着**槽位**走） | `TweenPose` 的 `scale` 形参写的就是 `_baseScale` |
| ease | `Ease.Linear` | **`Ease.OutQuad`** | 单条 tween 直接挂 ease；Sequence 才是「传 Linear 才等于各子补间 OutQuad」 |
| 收尾 | `ToPose(...).OnComplete(λ)` | `var tw = b.TweenPose(...); tw != null ? tw.OnComplete(FinishSwap) : FinishSwap();` | 兜底 `TweenPose` 在 `duration<=0` 时返回 **null**（`SwapTime` 恒 0.25，今天走不到） |

`FinishSwap` 的内容 = 原来那段 `OnComplete` 体（sibling 两两互换 · 槽记账 · `CardFan.ApplyQueues` 重排 · 开闸 · lore/语音/钮重设），**一行语义没改**。

### 1·3 `CardTween.ToPose` **已删除**

- 改前全仓**代码**调用方只有两个，都在这个 `SwapToFront` 里（现读 `grep -rn "ToPose(" --include=*.cs`）。
  两处都换成 `CardView.TweenPose` 之后 ⇒ **零调用方 ⇒ 删除**（在本代理白名单 `Core/CardTween.cs` 里）。
- 删掉之后原位置**留了一段 `//` 注释（不是 XML doc，避免 CS1587 悬空文档）**：为什么不能照原样加回来 +
  两个入口的 ease 约定（这条知识仍然成立，别丢）。
- 全仓剩余 `CardTween.ToPose` 的命中**全是注释/断言文案**（`Battle/CardDisplayWindow.cs` ·
  `Battle/MulliganPanel.cs` · `Hand/HandLayout.cs` · `Hand/CardInteraction.cs` · `Editor/BattleScene.cs` ·
  `Editor/CollectionScene.cs` · `Core/CardView.cs`）。其中 **`Core/CardView.cs:7898` 那句「菜单版详情窗仍是
  `CardTween.ToPose`」现在已经过期** —— ⚠️ 那个文件不在本代理白名单（A7 在改），见 §六·2。

## 三、件 3 —— `ShowMessagePopUp`：销毁旧的 + 按按钮数重建

### 3·1 判据（第一权威 = 反编译方法体，亲读）

`d:/2/tools/decomp_full/WindowsManager._LoadPopup_d__55__MoveNext.c:20-45`：

```c
if (op_Inequality(popUpWindow, 0)) {                 // *(this+0x60)
    WindowsManager__CloseWindow(this, popUpWindow, false);      // ① 先关
    Object__Destroy(Component__get_gameObject(popUpWindow));    // ② 再销毁
}
prefab = (*(param_1 + 0x28) == 0) ? this.<1 按钮版> : this.<2 按钮版>;   // ③ = `_LoadPopup` 的第 2 参
```

### 3·2 改了什么
