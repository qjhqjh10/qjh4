## 一、样品 / 档位的离线依据

### 1·1 根因不是「样品卡选错」，是「档位还原早了」

`AssertTacticArtClamp` 原来（H1 写的那版）是：

```csharp
CardView.DebugFrameTier = 2;
var vOn  = CardView.Create(goOn.transform, data, "h1_tactic_on");
CardView.DebugFrameTier = prevTier;      // ← ① 渲完就还原了
…
CardView.DebugDisableArtClamp = true;
var vOff = CardView.Create(goOff.transform, data, "h1_tactic_off");   // ← 这一版落回 tier1
```

⇒ **① 用的是 `tier2`、③ 用的是缺省档 `tier1`**，两条断言的**不是同一个情况**。而
`frame_astramilitarum_strat_tier1` 的开口整个落在硬矩形里 ⇒ ③ 结构性红（335/1 的那一条）。

**这不是推断，是逐位对上的**：离线复刻算出 tier1 = **x ∈ [−0.8362, +0.8395]**，
与 H1 报的 ③ 运行时实测 **`x ∈ [-0.8362, 0.8395]`** 四位小数完全相同。

### 1·2 离线量法（与 C# 逐字同一套）

脚本：`D:/4/_tmp_view/h4_measure.py`（`_tmp_view/` 在 `.gitignore` 里，临时件；只读、不改任何资产）。
逐字复刻 `Core/CardView.cs` 的：

- `FrameMaskData`：sprite rect 像素 `(171, 11, 682, 998)`（`FrameSpriteRectX/Y/W/H`）·
  `alpha ≤ 8` = 可通行 · 从 rect 四边泛洪得 `outside` · `hole = free & !outside` ·
  `ring` = `9 ≤ α < 248` 且与 `hole` 4 连通（`FrameBevelOpaquePx = 248`）；
- `BuildFrameRows`：`hole ∪ ring` 逐行片段 + `AddBevelRun` 左右各外扩 ≤ **3 px**（不越过 `outside`）；
- `ArtWindowMesh`：`x = FramePxXEdge(col) = (((col/1024 − 171/1024)/(682/1024)) − 0.5) × FrameUnitW(2.2452)`，
  再夹到**卡体收边 ±Width/2 = ±1.04635**（整段落在卡体外的 quad 直接丢弃，与 C# 的 `if (xR <= xL) continue` 同义）；
- 硬矩形半宽 = `0.32 × 2.7484 × 1.04` = **±0.914668** 卡单位（常数取自 `_Clamp_Range` SMALL 与 `ArtCoverMargin`，
  ⛔ 不是把实现再算一遍）。

### 1·3 实测（**`clampKind = 0`，即「关掉硬矩形」那一版的 x 极值**）

样本卡 **`Armoured Squadron`（AM52 · AstraMilitarum 战术卡 · `art_am52.png` 1024²）** 的卡框：

| 档位 | 文件 | 开口 `hole` x | `hole∪ring` x | **mesh（硬矩形关）x** | 越出 ±0.9147 |
|---|---|---|---|---|---|
| tier1 | `frame_astramilitarum_strat_tier1` | [−0.7703, +1.0765] | [−0.8263, +1.0864] | **[−0.8362, +0.8395]** | **−0.0752（两侧都不越）** |
| tier2 | `…_tier2` | [−1.0271, +1.0765] | [−1.0403, +1.0864] | [−1.0403, +0.9942] | +0.1256（左） |
| tier3 | `…_tier3` | [−1.0304, +0.7736] | [−1.0370, +0.8296] | [−1.0370, +0.8395] | +0.1223（左） |
| **tier4** | `…_tier4` | [−1.0502, +1.0568] | [−1.0502, +1.0601] | **[−1.0463, +1.0463]** | **+0.1317（两侧各越 0.1317）** |

口径说明：`hole` / `hole∪ring` 是**原始像素极值**；`mesh` 那列才是 `ArtWindowMesh` 真正交给渲染器的
x 极值（含 3 px 外扩、并经卡体收边裁剪）——**③ 断的是后者**。
（例：tier2 的 `hole` 右到 +1.0765，但那几颗孤立透明点**整段落在卡体之外**，C# 与复刻都会丢弃 ⇒ mesh 右只到 +0.9942。）

**另一阵营交叉验（H3 用的 `Armoured Offensive` / Ultramarines）**：

| 档位 | mesh（硬矩形关）x | 越出 |
|---|---|---|
| tier1 | [−0.8592, +0.8494] | −0.0554（不越） |
| tier2 | [−0.8592, +0.8494] | −0.0554（不越） |
| tier3 | [−1.0463, +0.8395] | +0.1317（左） |
| tier4 | [−0.8263, +1.0436] | +0.1289（右） |

`hole∪ring` 与 H3 §一 的表差 **≈0.0016 卡单位（半像素）**（H3 按像素中心、这里按像素边界），
tier1/2「整个在硬矩形里」、tier4「右侧越界」两条结论**一致** ⇒ 复刻与 H3 互为旁证。

### 1·4 选型结论

- **样品卡保持不变**：`Armoured Squadron`（AM52）——它在 tier4 下**两侧都越出 0.1317**，
  比 Ultramarines tier4（只右侧越 0.1289）覆盖更全；而且**它的 tier1 读数与 H1 的运行时实测逐位相同**，
  这份复刻对它本身的可信度最高。
- **档位钉 4**，并且 **①/③ 两次渲染都钉住**（这才是真正的修复点）。
