## 一、逐项改动（改前 → 改后）

### 1（β · 真缺陷）`KillPoseTween` 静默空转 —— `Core/CardView.cs`

**改前**
```csharp
public void KillPoseTween()
{
    if (_poseTween != null && _poseTween.IsActive()) _poseTween.Kill();
    _poseTween = null;
}
```
闸不成立时**什么都不做**，下一句又把引用丢掉 ⇒ 补间继续跑、再也没人杀得掉（`CBD ③1` 实测：割在 40% 处，推完一整段后到了终点）。

```csharp

_poseTween = null;
```

- 补了一段「⛔ 别再加回 `IsActive()` 闸」的注释（带实测症状），链接到 `CardBaseDemo.AssertHandPoseTween` ③。
- **自证**：见第 2 项（`③1/③2` 各补一条 `!tw.IsActive()`）。

### 3（α 一行）`A7 ④b` 容差方向反了 —— `Editor/CardFaceProbe.cs`（`CheckClampSmallPixelsUnchanged`）

### 4（δ · 量具）`RenderPixels` 没有渲染隔离 —— `Editor/CardFaceProbe.cs`

**改前**：`RenderCardPixels()` 直接调 `RenderPixels()`（**整场渲、无 `cullingMask`**），
而 `CheckLayers()` 是从 `CardBaseDemo.Run:322` 的**活现场**（12 手牌 + 3 场上卡 + 背景 + 板位标记 + 粒子）里调起的
⇒ `A7 ④a` 的 3 万点差**不可能**来自被测卡。

**改后**：新增 `RenderPixelsIsolated(GameObject root)`：
```csharp
var all = Object.FindObjectsByType<Renderer>(FindObjectsInactive.Include, FindObjectsSortMode.None);
foreach (…) { if (在 root 子树里) continue; if (r.forceRenderingOff) continue;
              r.forceRenderingOff = true; touched.Add(r); }
try { return RenderPixels(); } finally { 逐件 forceRenderingOff = false; }
```
`RenderCardPixels` 改成 `return RenderPixelsIsolated(root);`。

**为什么选这条而不是另外两条**（都写在方法 doc 里）：
- 比「专用 layer + `cam.cullingMask`」少一处全局配置（不动 TagManager、不担心 layer 号撞车）；
- 比「临时空场景」少一堆建/拆副作用（不触发 `OnEnable`）；
- **只影响这一帧的可见集合**，不碰材质/网格/队列。
- **只改了 A7 这一条路** ⇒ `Shot()` / 新账-66 ② 的 `RenderPixels()` **行为一字不变**（那两个断言本来比的也是
  「同一状态两次渲染的差」，别的对象在两张里都出现、天然抵消，见「六·顺手发现 1」）。
