## 一、结论

**做完了。** 原版「**传奇 且 `owned == 1` ⇒ 先弹确认窗、确认前不合成不播特效**」这一支已照原样接上：

- 闸的位置 = `CardDetailPopup.OnCraftClicked`（= 原版 `CraftingPanel.TryCrafting` 那一层）；
  `CraftingPanel.TryCraftingInternal` 那一层 = 新的私有 `CraftNow()`（闸之后，/ 确认窗 OK 直调）。
- 确认窗 = **原版同一扇** `PopUpGameWindow`（`MessagePopupWindow2Buttons`，2 按钮版），
  **左 = `Cancel`（不合成）· 右 = `OK`（合成 + 播那两件特效）**。
- 三句文案的术语键**全部解出来了**（A5 说「没解出」的那两个 `DAT_`，其实一共三个）：

### 2·2 关窗靠什么（决定我们回调里怎么写）

`PopUpGameWindow__ConfigurePopUp.c`：逐颗 `LiveButtons` 循环里 ——
① `if (button.OnPress != null)` 才挂「调 OnPress」那个监听；
② **无条件**再挂一个 `PopUpGameWindow.PopUpWindowButtonPressed`（`script.json` 的
`Method$PopUpGameWindow.PopUpWindowButtonPressed()` @7962432；签名桩里它读 `OnWindowSubmitted`）。
⇒ **原版 Cancel 那颗虽然 `OnPress = null`，点下去照样关窗**（第二个监听干的）。
我们的 `WindowButton.onClick` 只有一条路 ⇒ **两颗钮的回调里都要显式关窗**（净效果同原版）。

## 六、顺手发现（只报不改）

1. 🔴 **`WindowsManager.ShowMessagePopUp` 的「复用同一扇」与原版相反**：
   `WindowsManager._LoadPopup_d__55__MoveNext.c:20-45` 逐句 = **每次先 `CloseWindow(popUpWindow)` +
   `Destroy(gameObject)`，再按 `twoButtons` 现挑 prefab `Instantiate`**（`_LoadPopUpAndShow_d__59__MoveNext.c`
   的 `bVar4 = 1 < buttons.Count` 就是那个挑法）。⇒ `ConfigurePopUp` 里「超出按钮数的 `SetActive(false)`」
   在**原版**其实是防御性死路。我们（A416/A454）做成了「复用 + `RefreshLiveContent`」——
   **结果多半等价，但有一档会丢钮**：场上开着一扇 **1 按钮版**实例、又要求两颗钮时，那颗 OK 画不出来
   （本件在调用点做了局部兜底：先把它关掉再开，并出声）。建议记账让外壳线复核
   （改它会牵动 `Editor/ShellScene.cs` 的 A416/A454 那组断言）。出处：本报告 §五·4 之外的
   `WindowsManager._LoadPopup_d__55__MoveNext.c` 与 `WindowsManager._LoadPopUpAndShow_d__59__MoveNext.c`。
2. 🔴 **商店买传奇的确认框左右钮反了**：`Shell/ShopTabPage.cs` 那句
   `ShowPopUp(文案, Loc.T("MainMenu/General/OK"), DoBuy, Loc.T("MainMenu/General/Cancel"))`
   ⇒ `ShowPopUp` 把 `okText` 当 **primary（左）**。但原版
   `CatalogItemContainer__TryPurchase.c` 与 `CraftingPanel__TryCrafting.c` **同形**：
   `buttons[0] = Cancel`（左）· `buttons[1] = OK`（右），而 `ConfigurePopUp` 的 `LiveButtons[0]` = `ButtonLeft`。
   ⇒ 商店那扇**左 OK / 右 Cancel**，与我们新做的锻造确认窗（左 Cancel / 右 OK）**互相不一致**。
   建议记账、按原版对调（⚠️ `Shell/ShopTabPage.cs` 不在本件题面）。
3. **`Core/Loc.cs:1817-1824` 那条注释过期**：它说 `MenuShop/ExtraLegendaryWarning` 的 **EN/ZH 都自拟
   （0 命中）** —— 但**官方本地化表两列都在**（`官方本地化_en+zh-CN.json`），且与该 Entry **逐字相同**
   ⇒ 应改成「官方表实读」。⚠️ `Core/` 不在本代理白名单。
4. **那道闸在单机默认库存下几乎永不触发**：`CardProgress.Owned` 的缺省「给足」=
   `DeckCap + (NeedCopies[4]-NeedCopies[1])`（legendary 通常 = 10）⇒ 只有玩家真把某张传奇扣到 1 张
   （或合成到 1→2 的交界）才会看到确认窗。这是**数据侧的既有偏离**（不是本件引入），如实记。
5. `CraftingPanel` 的 `+0x78` 从签名桩字段序读出来是 `willCraftAlternateArt`（与 `TryCraftingInternal`
   用它选 `CraftCard`/`CraftAlternateArt` 互证）—— 这条**反过来证明**了闸只作用于「普通合成」那一档。
