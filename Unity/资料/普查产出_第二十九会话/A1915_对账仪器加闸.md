## 二、闸加在第几行 · 加之前是什么 · 加之后是什么

**落点**：`a1759_final.py` 第 311–325 行（改后行号），即 `abilities` 那个列表**唯一**产生 `ACT` 行的 `append`。
(`grep abilities.append` 现读：代码里只有 1 处，`:325`；另一处命中是我写的注释。)

```python
# 加之前（原文，3 行）
    aa = c.get('activeAbility') or {}
    if aa.get('activeAbilityLogic'):
        abilities.append(('ACT', 46, aa['activeAbilityLogic']))

# 加之后（只改了那一行的【条件】；上面加了 17 行注释，无代码行为）
    aa = c.get('activeAbility') or {}
    if aa.get('activeAbilityLogic') and c.get('hasActiveAbility'):
        abilities.append(('ACT', 46, aa['activeAbilityLogic']))
```

**为什么落在这里（三条，逐条写清）：**

1. **这是 `abilities` 里 `ACT` 的唯一来源** ⇒ 加在它的条件上 = 「不给这些卡加 `ACT` 行」，与账的原话一字不差。
2. **它同时收窄了第二处口径（有意）**：`:446` 那圈算「我们多」时用的是同一份 `abilities`
   （`ofams |= EQ.get(OFAM.get(...))`）⇒ 闸一落，这些卡的 `activeAbility` 也**不再**参与「我们多」的判定。
   两处口径一起收窄，语义才自洽（否则 `ACT` 行没了、`ofams` 还留着那条族）。
   🔑 **实测这个副效应为 0**：`我们多 37 → 37`、`承载不同 60 → 60`、`条数不同 7 → 7` —— 见 §三。
3. **判据（原版侧，现核）**：`d:/2/tools/decomp_full/CardScript__ResolveActiveAbilityPlayed.c:23`
   `if (*(char *)(param_1 + 0x220) == '\0') { … CustomDebug__LogWarning(…); return; }`
   （`:26` 是那行警告）——`+0x220` = `CardScript.<hasActiveAbility>k__BackingField`（`d:/2/tools/il2cpp_out/dump.cs:35444`）
   ⇒ **该标志为 0 时这份 `activeAbility` 在棋局里根本不可被发动**，不该拿它当对账的另一边。
   ⚠️ **`W15` 报告与 `A1875` 账把这一行写成 `:20`** —— 现读是 **`:23`**（`:20` 是一条 `DAT_` 初始化）。
   我照现核的写，未去改那两份文件（历史报告禁碰）。

**⚠️ 本闸的信用前提（必须留痕，别当已验）：** 真值 JSON 是 **资产侧** `RawCardScript` 的 SO dump
（实测：`RawCardScript` 195 个字段名里 **105 个**命中 JSON；运行期 `CardScript` 的 84 个字段名命中 **0**），
所以本闸读的是 `RawCardScript.hasActiveAbility // 0x2A9`（`dump.cs:23343`），
而原版那道闸读的是**运行期**的 `CardScript+0x220`。
**「资产侧 0x2A9 → 运行期 0x220 是否忠实同步」这一跳，本闸没验** —— 那正是账 `A1875` 的问题（简报已划清）。

**闸影响的边界（现核，真值 1195 张）：**

- `hasActiveAbility` 分布 = `{0: 1134, 1: 58, None: 3}`；`activeAbilityLogic` 非空 = **109 张**
  = **58 张 `hAA==1`（可发动）＋ 51 张 `hAA==0`（模板残留）**。
- 那 3 张 `None` **都没有** `activeAbilityLogic` ⇒ 按真值处理成 0 **零影响**。
