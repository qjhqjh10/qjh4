## 一、原版有没有「常驻效果」这一类

**结论分两半，必须分开说（分开说正是本笔要立的口径）：**

| 问 | 答 | 判据 |
|---|---|---|
| 原版有没有**叫 `PersistentEffect` 的类型**？ | ❌ **没有** | 全量 `dump.cs` `grep -c PersistentEffect` = **0**；全库 **13** 个带 `persistent` 的类型全是 I2 / Addressables / dots / Unity 的（`I2BasePersistentStorage` · `DebugUIHandlerPersistentCanvas` · `PersistentCall` · `MotionVectorsPersistentData` · `ScreenSpaceAmbientOcclusionPersistentResources` …），**与卡牌无关** ⇒ **我们那个 `PersistentEffect` 是自设计的** |
| 原版有没有**「本场战斗有效」这个概念**？ | ✅ **有，但不叫这个名字、也不是「弃置后由那张牌继续生效」** | 见下 §二·1–3 |

**原版拿什么名字实现**（**不是**某个类型，是**四样合起来**的一套结构）：

1. **时长靠「没有旗标」表达**：`CardEffect` 只有**回合级**的五个旗标
   `untilEndOfTurn(0x32)` · `untilPlayerTurnStart(0x33)` · `untilEnemyTurnStart(0x34)` ·
   `untilFollowingPlayerTurnStart(0x35)` · `untilNextAttack(0x36)`，加一个 `permanentBuff(0x74)`。
   ⇒ **一个旗标都不带的 `CardEffect` 就是「本场」的**（没有人来清它）。
   回合边界只清 `untilEndOfTurn` 那一档：`CardScript__ClearEndOfTurnEffects.c:23,27`。
2. **载体 = 一张还活着的牌**（真正的机制，两套并存的写法）：
   - **附魔型**：`CardEffect{buffType = enchantment(12) / singleUseEnchantment(15) / choiceEnchantment(16),
     enchantment = <附魔卡 RawCardScript>}` → `CardScript__AddEffect.c:826-828`（`case 0xc/0xf`）
     → `CardScript__AddEnchantment.c:25,37,43`（挂进 `card.activeEnchantments`，`+0x110`）
     → `CardScript__AddEffect.c:830-835`（`case 0x10`）是 `choiceEnchantment` 那一支。
   - **「给某张牌一个能力」型**：`BuffType.replaceAbility(40)` →
     `CardScript__AddEffect.c:242-251`：`card.activeAbilityRef(+0x118) = effect.enchantment` +
     `hasActiveAbility = 1`（`*(undefined2*)(card+0x220) = 0x101`）。
   - 之后**派发触发时把附魔一起算**：`RawCardScript__TriggerAbilities.c:50-88` 遍历
     `card.activeEnchantments(+0x110)`、取每个附魔的 `cardAbilities(+0x290)` 比对当前 trigger
     （对外 API = `RawCardScript.GetAbilitiesForTrigger(thisCard, trigger, includeEnchantments)`）。
     ⇒ **能力跟着载体牌走：载体在场一天有效一天，载体不在场就没了。**
3. **触发只送到「场上 + 双方手牌」**（见 §二·2）—— 弃牌堆不在任何广播的遍历范围内。

**数据侧的旁证（第二权威）**：原版官方词条表里，这一族是**逐卡一条具名能力文本**，
键就挂在 `Card_Abilities/` 下、名字直接写着 `Effect…`：
`Card_Abilities/EffectCadiaStands` · `…/EffectIdolatrous` · `…/EffectImmortalPride` ·
`…/EffectUndyingLegions` · `…/EffectUndergroudndNetwork`（原表拼写如此）·
`…/EffectWagesRetribution` · `…/EffectHiveFleet` · `…/SaviorProtocolsEffect` ·
`…/ExperimentalDronesEffect` · `…/EffectArmouredSupport`。
⇒ ① 原版**确实把这 10 张做成独立能力**（不是随卡面文字一次性结算）；
② 但**文本里没有一句讲「弃置后仍然生效」** —— 全表 9,441 条里
`remains in effect` / `stay in effect` / `after the card is` / `separate pile` **全 0 命中**。

## 二、弃置 / 离场时原版怎么处理（条件 → 行为 → 出处）

### 2·1 打出的那张战术卡：进弃牌堆，**不再参与任何触发**

| 条件 | 行为 | 出处 |
|---|---|---|
| 战术卡打出（有目标 / 无目标两条路都一样） | `cardState = inCemetery(6)` → `BattleManager.AddToCemetery` | `CardScript__TargetedSpellPlayed.c:13,75` · `CardScript__NonTargetSpellPlayed.c:8,23` → `CardScript__GoToCemetery.c:8,17` |
| 进弃牌堆 | 入 `CemeteryManager.cemeteryCardList(+0x60)` + `SetAsCemetery` + `SetActive(false)` | `CemeteryManager__AddCardToCemetery.c:17,48,52` |
| 「被弃置」的判定 | `CardScript.IsInPlay` 对 `inCemetery(6)` **返回 false**（只认 2/3/15/17） | `CardScript__IsInPlay.c:5-15` |

### 2·2 触发派发的**范围**（这是「弃置后还能不能自己触发」的判据）

| 广播 | 走哪些容器 | 出处 |
|---|---|---|
| 回合开始 | `BattleManager.unitsInPlay(+0x470)`（且 `CardScript.IsInPlay`）**→ 当前回合方手牌 → 另一方手牌** | `BattleManagerSupport__BroadcastTurnStart.c:18,25,33,42` |
| 回合开始（另一支） | 同上（调 `OnTurnStarted`） | `BattleManagerSupport__BroadcastTurnStarted.c:18,25,33,42` |
| 回合结束 | 同上（另允许 `HasCurrentTrait` 且 `cardState == 5(waitingToDie)` 的） | `BattleManagerSupport__BroadcastTurnEnd.c:18,26,34,45,54` |
| 某单位被部署 | 同上四跳（自己 → 场上 → 本方手牌 → 对方手牌） | `BattleManagerSupport__BroadcastUnitSummoned.c:20,28,44,54` |

⇒ **弃牌堆不在其中** ⇒ **原版不可能让一张已弃置的牌自己继续触发**。
⇒ 粉丝规则书那句「**单独放一摞**在弃牌堆旁边备查」是**实体台面**的备忘办法
（物理上你得把那张牌留在桌上才记得住），**数字版没有对应物**。

### 2·3 来源离场时：**分两种**，判据 = `CardEffect.extrinsic(0x30)` + `enchantingCard(0x18)`

`extrinsic` 的工具提示原文 = `Effect is tied to acting card, not target card`
（`dump.cs` `CardEffect` 字段表，`0x30`）。

| 条件 | 行为 | 出处 |
|---|---|---|
| **① 有绑定**（`extrinsic != 0` 且 `enchantingCard == 离场那张`）⇒ 这张牌挂到**别人身上**的效果 | **主动撤回**：手牌那一份从 `PlayerHand.activeEffects` 里摘掉 | `PlayerHand__RemoveFromGameCard.c:28,33,39` |
| 同上（场上 + 双方手牌那一份） | 走一遍 `unitsInPlay` + 双方手牌，对「含来自这张牌的 extrinsic 效果」的牌排队撤除 | `BattleManager__RemoveExtrinsicEffectsFrom.c:36,45,80` |
| 调用点 | 单位阵亡时 | `CardScript__ResolveDeadCard.c:244` |
| 调用点（第二条） | 加效果时撞上同源 extrinsic（`BuffType.removeExtrinsic = 11`） | `CardScript__AddEffect.c:823` |
| 单张牌自己身上的效果（`card.activeEffects`) | 随这张牌一起消失（列表就在它身上；单位还会先 `ResetToValuesInHand`） | `CardScript__GoToCemetery.c:12` |
| **② 没绑定**（在玩家手上 / 在某张活着的载体上） | **继续有效** —— 它本来就不在离场那张牌身上 | 由 ① 反推 + §一·2 的载体模型 |

### 2·4 「只在自己回合触发」也有原版判据（顺带核到，见 §六·1）

`CardScript__OnTurnStart.c:138` 先发 `TurnStart(0x1e = 30)`（**任何牌都收**，含双方手牌），
`:140` 判 `param_2 != card.isPlayer` 就 `return`，`:145` 才发 `TurnStartPlayer(0x1f = 31)`
⇒ **「自己的回合才触发」= 31 号那条**。

## 三、我们现在的实现 vs 原版

| 面 | 原版 | 我们 | 同 / 不同 |
|---|---|---|---|
| 结构 | **没有** `PersistentEffect` 类型；效果搬到「活载体」（附魔 / 挂到某张牌的能力） | `ctx.PersistentEffects`（`List<PersistentEffect>`），字段 = 谁 + 来源卡 + 时机 + 正文 | **不同**（**我们自设计的结构**） |
| 「本场」怎么表达 | **靠「没有时长旗标」+ 载体活着** | 登记后**永不清理**（`PersistentEffects` 全仓只在 `DoPersist` 加、没有 `Remove`/`Clear`） | **结果一致**（都不被回合边界清） |
| 来源卡弃置后 | 效果**不在那张牌上**（所以「还在」只是因为载体还在） | 效果在 `ctx.PersistentEffects` 里，**与来源卡在不在无关** | **结果一致**（本族 10 张的来源都是「打出即弃」的战术卡，两种情况殊途同归） |
| 来源卡离场时**要不要撤回** | **分两种**：`extrinsic` 有绑定 ⇒ 撤；没绑定 ⇒ 不撤 | **一律不撤** | ⚠️ **只看本族 = 一致**；⚠️ **若将来把「给别的牌加效果」也塞进这摞，会与原版①不符** ⇒ 届时按 `extrinsic` 那一支分家 |
| 触发范围 | 场上 + 双方手牌（**弃牌堆不收**） | 回合起止段走：双方手牌 → 棋盘单位 → 已登记常驻（`RuleCore.ResolveAtTurn`，`EffectResolver.cs` 的 `handJobs/unitJobs/persistJobs`） | **不同**（我们多了一摞「已登记常驻」，这正是替代原版载体机制的那一摞） |
| 「只在自己回合」 | `TurnStartPlayer(31)`，判 `isPlayer == 当回合方` | `pe.Owner != active` 就跳过 | **一致** |
| 粉丝规则书当判据 | —— | 本段原来是**唯一**判据 | ✅ **本笔换掉** |

**判不出的**：① 那 10 张卡**具体挂在哪个载体上**（督军？还是别的牌）—— 要看卡的字段级数据，
而**卡数据在远端 CCD，本地没有**；② `Card_Abilities/Effect*` 这些键**由哪一个字段引用**
（`RawCardScript` 有 `activeAbilityTextReferenceId(0x248)` 与 `cardDescriptionTextReferenceId(0x250)` 两个候选，
`effectText` 在 `CardEffect(0x28)` 上还有一个，**靠键名分不出来**）。
