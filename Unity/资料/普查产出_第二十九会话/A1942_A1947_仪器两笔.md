## 三、`A1947`：结论 —— **加读取，但只读出+出声，⛔ 不替原版挑**

### 为什么**不是**「把 `alternativeAbility` 也塞进 `abilities`」（那样做会造假账）

原版对 `hAA==1` 的卡**只跑两边中的一边**。若把替代那一支也 append 进 `abilities`：

- 对账机会拿**我们一侧的 op** 去比一条**原版可能根本没跑**的列表；
- 结果是凭空产出「**原版有、我们缺**」（或「我们多」）的**假账**——
  而这正是 **`A1915` 那道 `hasActiveAbility` 闸要治的同一类病**（拿一个原版不可达的分支去产出对账行）。
- 本仪器**没有局面**：它是**纯静态对账**（读真值 JSON ＋ 读 `our_scan.txt`，**不跑引擎**），
  而 `BoardCriteria` 的判据是**运行期棋盘** ⇒ 这一格**离线不可判**。

⇒ 采用的形状：**读出 + 出声单列**（两族，`hasAlternativeAbility` 为真 / `alternativeAbility` 有非零内容），
计数为 0 时**明写「今天不可达、仪器口径完整」**，非 0 时**逐条点名**并说清「没替它挑」。
按 `A1945`/本仓红线「**不许静默失败**」——盲区**从静默变成出声**，且⛔**零伪造**。
