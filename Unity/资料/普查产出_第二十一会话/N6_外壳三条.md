   - **幂等补齐**：`idx == SelectedNav` 早退**之前**先确认**那一颗的高亮节点真的在**，不在就补画。
     （`SelectedNav` 只是个数、高亮是树里一颗**节点** —— 两者会脱钩，原来只比数就会**永远不补画**。）

## A1639：原版 `ChatPreview` 的显隐语义 · 结论（改 / 不改 + 为什么）

### ① 语义 = **「有消息才画，读了就收」**（五条独立判据，全部逐句读出来的反编译）

| # | 出处 | 读到了什么 |
|---|---|---|
| ① | `ChatPreview__OnBeforeInitialization.c` | `icon.localScale = (0,0,0)` · `messageContainer.fillAmount = 0` · 每条 `ChatPreviewMessage` 的正文 `enabled = false` ⇒ **出厂视觉上就不可见**（⚠️ 那颗 GO 在场景里 **`m_IsActive = true`** —— `GameObject/ChatPreview.json` 实读 ⇒ 原版**不是**靠 `SetActive(false)` 按掉它，靠的是「缩放 0 + 填充 0」） |
| ② | `ChatPreview__Show.c` | `SetActive(true)` + `DOScale(icon, 1).From()` + `DOFillAmount(container, 1).From()` + `DOFade(container, 1).From()` ⇒ `Show()` 的语义 = **从看不见淡进来** |
| ③ | `ChatPreview__Show` 的**调用点**（全库） | 只有两个：`__OnInitializationComplete.c`（**仅当 `receivedMessages` 已为真**）、`__WaitAndAnimate.c`（**仅当该频道来了 ≥1 条消息**）。而 `__UpdatePreviews.c` 里 `receivedMessages`（字段 `0x40`）**只在 `messages.Count >= 1` 且频道匹配时**才置 1 ⇒ **没有消息 ⇒ 永远走不到 `Show()`** |
| ④ | `ChatPreviewMessage__Start.c` | 每条预览行**在 `Start()` 里自己 `set_enabled(false)`**（同①） |
| ⑤ | `ChatPreview__OpenChat.c` + 它的 `OnComplete` 回调 `ChatPreview__<OpenChat>b__10_0.c` | 先把预览**动画收回去**（`DOScale(icon, 0)` / `DOFillAmount(container, 0)` / `DOFade(container, 0)`），回调里 **第一句 `gameObject.SetActive(false)`**，然后才 `WindowsManager.OpenWindow(chatWindow)` ⇒ **读了就收** |

### ② 🔴 顺手否掉两个**很自然但错**的猜测

- **不是「只在主菜单画」**：`ChatPreview` 是 `Safe area Only Horizontal`(RT 1540) 的**最后一个孩子** ——
  兄弟序实读（同一份场景 JSON 逐条解 `m_Father`）：
  ```
  Loading Controller · Upper bar · 1 - Below Upper Bar Holder · Toast Notification Controller ·
  LoadingMenu · Navigation Panel · 2 - Canvas Holder Above upper bar · Borders · 3 - PopUp Holder ·
  ► ChatPreview ◄ · UI Error Message Controller · TooltipManager
  ```
  ⇒ 它在**三个 Window Holder 之后** ⇒ **结构上压在所有窗之上**。
- **不是「开别的窗就被盖住」**：`bundle_menus_assets_all` 里 **8 个 `m_OverrideSorting = 1` 的 Canvas**
  逐个解出宿主 GO = `Menu Dark Background`×2 · `ChooseNameWindow` · `Template`×2 · `Division Image` ·
  `LoadingMenu` · `Cards` —— **一个都不属于收藏窗** ⇒ 窗也盖不住它。

⇒ **原版没有「开窗就藏它」这条逻辑**（⛔ 别照那个去实现，那是我们发明的口径）。

### ③ 用户那两张实拍（**只差一分钟**）为什么不一致 —— 已解释

`主界面参考图.png`（23:30）**有**那块预览（`ShizaStrong: At last we have hope. They…` 那行绿字 + 气泡钮，
位置正好在设计 `1475..1875 × 85..145`）；`收藏—卡组的参考图.png`（23:31）**没有**。
⇒ 那 1 分钟里他**点了一下**那块预览（去读那条消息）⇒ 预览自己 `SetActive(false)` 了（判据 ⑤），
**和「收藏窗盖住它」无关**。

### ④ 我们的现状 → 改法

- **现状**：`Shell/MainMenuRuntime.BuildChatPreview` **无条件**把整棵建出来并**恒亮**（两条占位串
  `<color=#00FF20>Player Name:</color> Message`），所以在任何窗上面都露着（用户看到的那一幕；
  那两条串还压住收藏窗顶部「导入卡组 / 创建卡组」之间那道缝 = 旧账 `A1553`）。
- **改法（照原版）**：结构**照旧全建**（原版 GO 就是 active 的），但**出厂不可见** —— 我们**没有聊天数据源**
  （用户 2026-09-26 口径「网络聊天功能暂时不做」· `Shell/ChatPanel.cs` 文件头 ⑤：没有服务器、
  也没有 `ChatGlobalManager` 的对等物）⇒ 「没有消息」是**恒真**的 ⇒ 它**永远不该出现**。
  - **唯一显隐口** `public void SetChatPreviewVisible(bool)`（+ 只读 `ChatPreviewVisible`），
    ⛔ 别在别处再写第二句 `SetActive`；
  - 点击那条链改成 **`ChatPreviewClicked()`** = 「**先收起、再开聊天窗**」（= 原版 `OnComplete` 的两句，顺序照原版；
    我们没有 DOTween 那条 tween ⇒ 只保留终态）。
  - **唯一差别如实标（铁律 3）**：原版用 `scale/fill` 那套 tween 做「不可见」，本仓用 `activeSelf` ——
    理由两条：本仓没有 DOTween 那套淡入；`ImageQuad` 也没有 `enabled` 那一档。

### ⑤ 一条能红的断言

- `Editor/MainMenuScene.cs` 新增：「出厂 `ChatPreviewVisible == false`」+「结构仍然在（`ChatPreview` / `ChatHit` 都找得到）」

  （⛔ 只断「点完是关的」是弱断言：出厂本来就关着，那样写**两种实现都会绿**）。
