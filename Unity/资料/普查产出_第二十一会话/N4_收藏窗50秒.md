## 改法（照 `RebuildCosmoCells` 的哪个做法 · 逐处）

简报给的三个方向里，**「按视口裁剪」已经在做**（见上），所以本轮取的是另外两个：
**「复用同一份数据」+「不重做已经做过的事」**，并**把探针下钻**到下一层。

**逐处改动（全在 `Shell/CollectionWindow.cs`）**

1. **`:978-983`（卡池）· 去掉重复的 `ToCardData`**
   原来 `CardView.Create(parent, BattleDriver.ToCardData(list[i], list[i].Faction), …)` 算一次、
   下面 `SetData(BattleDriver.ToCardData(list[i], list[i].Faction))` **又算一次**（实参逐字相同 ⇒ 结果逐字段相同）。
   现在提成一个 `var data = …` 只算一次。它那条路要拼卡面文案（`FaceTextFull`：中/英二选一 + `CardIcons.Rewrite` + 关键词段）。

2. **`:1010-1018`（卡池）· 删掉 `v.SetData(data)`**
   它与**同一句** `Create(parent, data, …)` 做的是同一件事，逐条核过 `Core/CardView.cs`：
   - `Create` = `AddComponent` + `Build(d)`；`Build` 头一句就是 `Data = d`（`:1584`），尾三句 =
     `BuildTextLayers(d)`（`:1791`）· `SetBadges(d.badges)`（`:1794`）· `BuildStatLayers(); SyncStatLayers();`（`:1801-1802`）。
   - `SetData(d)` 里**别的每一段**在这条路上都是空转或同值：
     `CaptureStatChanges` 非 `Board` 直接 `return`（`:1195`）· `_face != null` 那支只在**没有卡框**的兜底路上才非空（真卡走 `_frame`，
     而本页 `data` 恒有框）· `_info`/`_art` 重赋的是**同一缓存键算出的同一张贴图** ·
     `SetCardImageTo3DBase()` 在 `_body3D == null` 时 `return`（`:2781`）· 末尾 `if (Clipping) ApplyClip()` 与上一句
     `SetClipFromTree()` 的产物同值 ⇒ **幂等**。
   - **净差别只剩一件**：`BuildTextLayers` 把 4 段 TMP **整个重排第二遍**（其中效果文字走 `FitToBox` 的 8 步二分，
     每步一次 `ForceMeshUpdate` ⇒ 每段最多 **9** 次；`FitToWidth` 那三段各 **2** 次）。**这一句是本件最大的一笔。**
   - ⛔ **不是「少建东西」**：卡面每一个件都还在，只是不再建第二遍（铁律：不许静默失败）。
   - ⚠️ **要退回**：把 `v.SetData(data);` 加回 `:1010` 那一行即可（`data` 就在上面）。

3. **`:1742-1747`（异画页）· 同一处删除（`v.SetData(d)`）** —— 理由逐条同 (2)，**不再抄第二份**（铁律：两处写同一条规则 = 迟早不一致）；
   这一页**多一条**：`d.artOverride` 是**在 `Create` 之前**设好的（`:1709-1711`）⇒ `Build` 那次就已经按异画建过立绘。

4. **🆕 探针下钻（`BuildWatch`，`:3511` 起；新增段 `:3541-3658`）** —— 上一批那 8 格只把「哪一页」分开了，本批补 **逐格相位累计器**
   （`CellsBegin` / `CellBegin` / `CellPhase` / `CellEnd` / `CellsReport`，`:3554-3586`），把**一格**拆成 5 段：
   `① CardView.Create` / `② SetPose` / `③ SetClipFromTree（第一刀真裁）` / `④ SetFace+SetHighlight` / `⑤ 张数条+命中区`。
   18 格 × 5 段压成 5 行。
   🔴 **⛔ 没有拆掉任何现有格子**：新 API 用**自己的** `_phT`，**不碰 `Mark` 的 `_t0`** ——
   否则「①b 页 N」那 8 格的读数会被内层埋点改掉（那正是「别拆现有的」要防的）。
   同闸：`Application.isPlaying` ⇒ **批处理自检的日志一字不变**。

5. **🆕 单次文字重排的绝对耗时（`TimeOneTextRelayout`，`:3607`）** —— 本账最要紧的一个数。
   理由：整张卡的 2.2 秒如果真是「每段文字重排 × 次数」，只有这一个数能把它**对上或当场推翻**。
   量第 1 张卡的第 1 段 TMP 连续两次 `ForceMeshUpdate`（两次差得大 ⇒ 第 1 次含**字形现生成**；两次都小 ⇒ 那条假设**不成立**）。
   ⚠️ **量完必须把裁切补回去**（`ForceMeshUpdate` 会把写进顶点的那一刀冲掉 —— 正是 `CardView.RestoreClip` 靠它还原原件的性质）
   ⇒ 补一句 `cv.SetClipFromTree()`，**画面与「不量这一下」逐位相同**（`:919` 调用点 + `:3607-3636` 的 doc）。

6. **🆕 字体资产读数（`FontReadout`，`:3638`）** —— `TmpFont.Font` 的图集尺寸 / 模式 / 已烘字形数，
   打进 `CellsReport` 的输出里。**它只是读数、不是结论**（读不出就写「读不到」，⛔ 不猜）。

## 顺手发现

1. 🔴 **滚动走的是同一条重建路，代价是同一笔（本账之外、但同源，建议单独开账）。**
   `CardsScroll.OnChanged = () => RebuildCardsCells(holder);`（`:909`）而 `OnChanged` 由 `SetOffset` / `Wheel` / `Tick` 触发
   （`Shell/MenuScroll.cs:220-228` / `:234-239` / `:359-361`）⇒ **每滚一格重画 18 张卡**，拖动时**每次鼠标移动**一次。
   按本账的 2.2 s/格算，那是**40 秒/次**。⇒ 开窗那次只付一遍，这个**每次都付**。
   真解 = **复用 `CardView`**（简报里第三个方向「复用」）：`Dictionary<int, CardView>`，滚出视口的销毁 / 滚进来的建 /
   留在视口里的只 `SetPose + SetClipFromTree`。⚠️ **但它要跟「命中区 + 张数条一起设计」**（那两个也挂在
   `holder/Viewport` 下、也被一起销毁重建，`:1033-1037`），而且**必须跑 `CollectionScene.Run` 里的滚动那几条**
   （`:3883` / `:3937` 那一族）—— 本件**没有动手**：那是独立一件、风险面大、且我**没法跑自检**，⛔ 不硬做。
2. **四页是「开窗全建」**（`:2793-2794`）—— 页 1 + 页 3 = **54.5 秒**都压在打开那一帧，而默认显示的是页 0。
   若只做「按页懒建」，`Build()` 会掉到 2.4 秒 ⇒ **看起来像修好了，实际只是把 41.5 秒挪到点 Cards 页签那一下**。
   ⛔ **不是解**，别把它记成修复（铁律 11：不许按「反正看不见」分档）。列在这里只为把判据钉住。
3. **`CardView.FrameUv` 对每张新卡框贴图做一次 `GetPixels32()`**（`Core/CardView.cs:4246-4285`：
   1024² ⇒ **104 万像素的 C# 循环** + 一次 GPU→CPU 回读），只按纹理缓存（`_uvCache`）。
   18 张卡最多 18 个不同卡框 ⇒ **保守 1 秒量级**（同族第二张免费）。**本件没量它**（要真机）。
4. **`Core/TmpFont.cs:27-28`：全仓唯一字体是 Dynamic + 图集 1×1 占位** ⇒ 每个字形都得从 TTF 现烘。
   这是「**整仓每一段文字都可能慢**」的第一号嫌疑（若成立，战场/卡组窗/所有弹窗一起受益）——
   `:3607` 那一格就是为它埋的。⚠️ 这条**不改**（不在白名单，且换字体「牵动全仓版面」，见 `TmpFont.cs:40-43`）。
5. **本账与 N3 §③「贴图全以未压缩 RGBA32 打进包」很可能是同一个病的两面**：
   一个说「每建一段文字贵」，一个说「每张新贴图贵」—— 两者都在**首次触碰**时付账。
   🔴 **判别实验只有一个**：**第二次开收藏窗是不是明显快**（顺手就能做）。⇒ 建议调度台把它写成下一趟的必做项。
6. `CollectionWindow` 里 `CardView.Create` 这一路**没有**传递任何 `CardFace` 之外的档位差异 ⇒
   卡池页与异画页用的是**同一份**建卡代价（这也是我把两页当同一件事处理、只改一次的理由）。
