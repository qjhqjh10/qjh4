### 1·3 🔴 `fontPx > autoMinPx` 那条共用闸怎么处理的（逐句）

真判据 = `Shell/MenuDraw.cs` 的 `TextCore`：**`wrapPx > 0f` ∧ `autoMinPx > 0f` ∧ `fontPx > autoMinPx` 三条全真**才执行 `SetAutoFitBox`。逐条：

1. **`wrapPx > 0`** —— 由上面那句 `fitW` **无条件满足**（只要调用点给了 `autoMinPx > 0`）：
   折行开的那一档直接用调用点给的折行宽；折行 = 0 的那一档补**本格框宽**。⛔ 于是「折行开的站」传的是
   原版 `m_SizeDelta.x`（= 本窗逐档核过与 `x2-x1` 相等），「折行 0 的站」传的是我们这一格的框宽
   （**那一格有一批原版是 HLG/VLG 排出来的、prefab 里是 `0×0` 模板位，没有字段值可抄** —— 已逐站标在代码注释里）。
2. **`autoMinPx > 0`** —— 由调用点给（原版 `m_fontSizeMin`）；不给就**整段不进** = 旧行为逐位不变。
3. **`fontPx > autoMinPx`** —— 🔴 **本笔【没有】改它**（`MenuDraw.cs` 是共用件、不在白名单）。后果**只有一站**：
   `LanguagesDropdown > Label` 原版是 `m_fontSizeMin == m_fontSize == 18` ⇒ **三条闸过不去 ⇒ 传了也不生效**。
   处理 = **四格照原版接上**（闸一放宽它就活）**+ 代码注释 + 断言里如实登记**，
   ⛔ **没有为了让这一颗活而把 `autoMinPx` 往下改**（那是发明一个原版没有的值）。
   → 与 `R2_A1126原版autosize真值.md` §3 注⑤（`PurchasePremiumWindow`）**同一族**，仍**由调度台裁**。
4. **折行档的副作用**：`MenuDraw.Text` 只要 `wrapPx > 0` 就把 TMP 开成 `Normal`
   （`Core/TmpFont.cs` 的 `SetWrapWidthRect` **无条件写**）⇒ 折行 = 0 的那些站由本漏斗

   位置**必须在 `ClipText` 之前**（`SetWrapping` 内部 `ForceRelayout` 会重排 mesh、把上一刀抹掉）。
