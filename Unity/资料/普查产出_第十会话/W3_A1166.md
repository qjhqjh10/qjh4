### 2.5 为什么在我们这边**等价**
18 档里**只有那 4 档代表「在棋盘上」**，其余 14 档全是牌库/手牌/坟场/离场状态。两个旁证：
- `removedFromGame(11)` 唯一置位点 = `CardScript__RemoveFromGameCard.c:19`，调用者全在
  **`PlayerHand__*` / `_ResolveStealMinion` / `_ResolveExchangeMinion`** —— 是**手牌**概念，不落棋盘；
- `waitingToBePlayed(4)` 由 `CardScript__CardWaitingToBePlayed.c:5` 置 = 「打出去了、还没落地」。

我们这边**眩晕的三个发生点，目标只可能来自棋盘**：
| 发生点 | 目标来源 | 已有的守卫 |
|---|---|---|
| `EffectResolver.DoStun`（`EffectResolver.cs:2113-2127`） | `ResolveTargets` → `AddSide`（**只遍历 `ps.Board[s]`**，`EffectResolver.cs:1296-1304`） | `t == null \|\| !t.IsAlive` |
| `RuleCore` 震荡（`RuleCore.cs:3612` 起） | `Board[slot]` 上那一个 | `!targetDied && target.IsAlive` |
| `SimpleAI.ScoreStun`（`SimpleAI.cs:628-630`） | AI 只看棋盘 | `target == null \|\| !target.IsAlive` |

两边摆齐：**原版 = `IsUnit && IsInPlay`；我们 = `棋盘上的 UnitState && IsAlive`**。
`在棋盘上` ⟹ 原版对应的一定是那 4 档之一；`IsAlive`（= `Health > 0`，`UnitState.cs:1047`）只会**收得更紧**。
⇒ **我们从不眩晕原版不会眩晕的牌**；反向只可能是 `waitingToDie`（血 ≤ 0、还没进坟场），那种单位
**这一批里必死**、眩晕不可观测。⇒ **等价。⛔ 不另加判据**（再加一份「在场上」= 同一件事第二次求值，
照「两处写同一条规则 = 迟早不一致」反而有害）。

⚠️ **今天连夹具都造不出差异**：全池 0 张卡带 `unstunnable`，而**这道 `IsInPlay` 闸在我们这边恒真**。
