## 一、结论：形参怎么加的 · 内部接到哪一步

**形参表（`Shell/MenuWindowBase.cs`，改后原文）**

```csharp
public Label Text(Transform parent, string text, float x1, float x2, float y1, float y2, int scale,
                  Color color, string name, float fontPx = 0f,
                  float wrapPx = 0f, float autoMinPx = 0f, float autoMaxPx = 0f, float autoBasePx = 0f)
```

四个新形参**全默认 `0`** ⇒ 旧调用点（R1 记的 24 个「没接」）**一字不改、行为逐位不变**。

**内部接线（插在 `if (fontPx > 0f) lb.SetGlyphHeight(...)` 之后、`MenuDraw.ClipText` 之前）**

```csharp
if (wrapPx > 0f)
{
    lb.SetWrapWidth(LayoutSpace.Px(wrapPx));
    if (autoMinPx > 0f && fontPx > autoMinPx)
        lb.SetAutoFitBox(LayoutSpace.Px(wrapPx), LayoutSpace.Px(y2 - y1), autoMinPx,
                         autoMaxPx > 0f ? autoMaxPx : fontPx, autoBasePx);
}
```

- **逐字照 `MenuDraw.TextCore`**（`Shell/MenuDraw.cs:1843-1860`，真判据那一处；`wrapPx > 0` ∧ `autoMinPx > 0`
  ∧ `fontPx > autoMinPx` 三条全真才调 `SetAutoFitBox`，`autoMaxPx <= 0` 退回 `fontPx`）。
- ⛔ **没改 `MenuDraw.cs`** —— 走的是它已公开的 `Label.SetWrapWidth` / `Label.SetAutoFitBox`。
- **为什么用 `wrapPx` 而不是 `x2-x1`**：`wrapPx` 是 `MenuDraw.Text` 的既有语义（可窄于节点矩形）；
  默认 0 是「不换行、不开 autosize」= 旧行为。
- 🔴 **没走 `MenuDraw.Text`**：那条内部把 `Label.Create` 的 `scale` **写死成 5**，而本方法的调用点传
  `5` **和** `6`（`CollectionWindow` 风格名那处是 6）⇒ 换过去会改点阵兜底那一档。所以保留 `Label.Create`，
  只把 autosize 两步按 `TextCore` 接上。
- ⚠️ **裁切次序**：`SetWrapWidth` / `SetAutoFitBox` 会重排 mesh ⇒ 必须排在 `ClipText` **之前**。
  收口前那 11 处是「`Text` 里裁一刀 → 调用点再 `SetAutoFitBox` **把它抹掉**」⇒
  **现在这些标签的裁切第一次真生效**（画面差 = 只有「本当被视口裁掉」的那些字）。
