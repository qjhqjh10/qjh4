## 1. 结论一句话

**战将的视图与 collider 都在、点击也确实进了 ⑤ 段，但 `HitSlot` 拿「UI 正交平面」的指针世界点去问 `Physics2D`，而卡的 collider 被 `PoseFor` 摆到了「3D 战场世界坐标」——我方那一行两个平面纵向差 ≈1.49–1.56 世界单位（≈160–168 px @1080）**（`PlayerLineY=0.4110` 对应指针平面 y≈−0.89，卡根在 `ArenaSlots.RootPosition` 的 y≈+0.60/+0.67），远超 collider 的半高（0.54/0.60），所以点在我方战将**画出来的位置**上永远 `HitByCollider=false` ⇒ `_pressSlot` 不赋值 ⇒ 松手不进 `BoardPress` ⇒ 看起来「没反应」。

**这不是战将独有：我方整排（含战将）都点不到；敌方那一排因为两个平面恰好只差 ≈0.09 世界单位（≈9 px）、collider 半高 1.04，所以照常能点。** 真机证据：点**敌方战将**的位置反而弹出了**我方督军** `UM65 = Chaplain Letharius` 的大卡窗（`_myUnits` 先查、4 号格赢）。

⚠️ 顺带纠两条任务里给的口径：
- `BoardSpec.IsValid(4)` **不是**把 4 排除——`IsValid` 是 `0..8`（`RuleEngine/Core/BoardSpec.cs:41`，**含 4**）；排除 4 的是 `IsDeployable`（`:36-39`）。点击链上**没有任何** `slot==4` 守卫。
- 「战将不在普通 minion 语义里」不影响本链：`RuleCore.NewBattle` 明确 `p.Board[BoardSpec.WarlordSlot] = p.Warlord`（`RuleEngine/Core/RuleCore.cs:549`）。

## 3. 逐条回答 5 个问题

**Q1：`_myUnits[4]` 非空吗？** ✅ 是。`SyncBoard` 无战将特判（`:17856`），`Board[4]=Warlord`（`RuleCore.cs:549`），`views[4]=v`（`:17977`）。真机旁证 = `#7/#8` 真的打开了 `UM65` 窗。

**Q2：collider 建了吗？3D 体会不会挡？** ✅ 建了且工作正常（`CardView.cs:2847 → 5918-5926`，`BoxCollider2D` 在 `_tiltRoot`）。`HitByCollider` = `Physics2D.OverlapPoint` + 缓冲逐颗比对（`:6048/6055-6056`）。`BuildBody3D` 只是 `body3D` 子节点的 `MeshRenderer`，**不碰** collider。真正问题是**跨空间比较**。

**Q3：`ToggleUnitCard(4)` / `OpenCommand(4)` 能处理战将吗？** ✅ 都能，无 `slot==WarlordSlot` 守卫。`ToggleUnitCard`（`:9230-9255`）取 `Board[4]` → `_cardDisplay.Toggle`；`OpenCommand`（`:10526-10531`）同样；`SimulateOpenCommand(WarlordSlot)` 在自检里通过（`BattleScene.cs:25354`）。

**Q4：指针被 HUD/面板捕获吗？** 普通回合、无面板/无大卡窗时，没有一条挡在屏幕中央的战将上——`PointerOverHudButton` 的 7 块矩形全在屏幕边缘。点击确实走到 ⑤，是 `HitSlot` 返回 −1。真机唯一常见的另一条吞点击 = **大卡窗已开着**（`click_log` `#9` 有该歧义）。
- 右上「战将卡」= 敌方牌堆卡背 `_foePile`/`_foeDeckPlate`（uGUI，无点击处理）；右下 = 我方牌堆 `_myPile`（有 `HitMyDeckPile`）；左上头像 = `_hudAvatarMe/Foe`；右上电台气泡 = `UnitChatPanel._radio`（uGUI `Image`、无处理器）。⇒ 都不是棋盘战将。

**Q5：原版督军也开大卡窗吗？** ✅ 同样开、无特判。`CardScript__OnTouchUpAsButton.c` 场上段直接 `DisplayCard`；`BattleManager__DisplayCard.c` 正常档 → `CardDisplayWindow__ShowBattleCard`。原版 `GetMousePerspectivePos` 与我们的 `ScreenToWorld` 同一公式；差别在**原版 collider 与卡画在同一空间**（`CardCollider2D__SetColliderNotInHand.c` state 2/3 → `Toggle(1)`；另有 `CardCollider3D`），不存在我们的跨空间比较。

## 4. 最小修法

**原则：把命中判据搬回「和用户看到的一致」的屏幕投影空间，且判据只留一处。** 不动渲染、不动 UI 坐标、不动 `Contains`。

### 4·1 `CardView.cs`（新增只读方法，紧挨 `HitByCollider`）

```csharp
/// <summary>真 3D 战场：按 collider 在【正交指针平面】上的投影矩形判命中。
/// 前提：场上卡根与 _tiltRoot 均为 identity 旋转（ArenaSlots.cs:19-21 / CardView.cs:2840）。</summary>
public bool HitByProjectedCollider(Camera boardCam, Vector3 orthoWorld)
{
    if (boardCam == null) return false;
    Vector2 half = new Vector2(HitHalfW, HitHalfH), off = Vector2.zero;
    if (_hitCollider != null) { half = _hitCollider.size * 0.5f; off = _hitCollider.offset; }
    var f = HitFrame();
    Vector3 a = f.TransformPoint(new Vector3(off.x - half.x, off.y - half.y, 0f));
    Vector3 b = f.TransformPoint(new Vector3(off.x + half.x, off.y + half.y, 0f));
    Vector3 sa = boardCam.WorldToScreenPoint(a), sb = boardCam.WorldToScreenPoint(b);
    if (sa.z <= 0f || sb.z <= 0f) return false;
    Vector3 oa = LayoutSpace.ScreenToWorld(new Vector2(sa.x, sa.y));
    Vector3 ob = LayoutSpace.ScreenToWorld(new Vector2(sb.x, sb.y));
    return orthoWorld.x >= Mathf.Min(oa.x, ob.x) && orthoWorld.x <= Mathf.Max(oa.x, ob.x)
        && orthoWorld.y >= Mathf.Min(oa.y, ob.y) && orthoWorld.y <= Mathf.Max(oa.y, ob.y);
}
```
