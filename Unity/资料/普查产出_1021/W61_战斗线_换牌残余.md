### ② 换牌区缩放：真源必须是 `CardView._baseScale`

- `Core/CardView.cs:6763-6767`：`ApplyScale()` = `transform.localScale = Vector3.one * (_baseScale * _hlMul)` ——
  **卡的实际缩放由 `_baseScale` 决定**，`transform.localScale` 只是它的产物。
- 改之前 `Battle/MulliganPanel.cs` 的 `BuildCardButtons` 直接写 `transform.localScale = (cardScale, cardScale, 1)`
  和 `transform.position = …` ⇒ **`_baseScale` 仍停在上一个档（手牌 0.7301 = 165 px）**。
- 唯一会写 `_baseScale` 的是 `SetPose`；换牌期另一条 `ReapplyRowPoses`（`MulliganPanel.cs:614-624`）走的就是它，
  但只在 `CommitDealtPoses`（`BattleDriver.cs:18338`）里、且 `Visible` 时才跑 ⇒ **建面板那一帧不覆盖**。
- 后果（静默）：任何一次 `ApplyScale()`（`SetHighlightScale` 那一族）都会把那张卡按 **`_baseScale` 旧值**重画
  —— 也就是「某一张卡突然回到手牌尺度」这个**形状**。批处理里这些补间不跑 ⇒ 结构上测不出来。
- `ClearCardButtons` 的归还同样是直接写 `transform.position/localScale`（`_baseScale` 留在换牌区那一档 1.292），
  而 `HandLayout.Place` 在实机走 `animateRelayout` 补间（`Hand/HandLayout.cs:798-801` 用 `CardTween.ToPose`，
  **只写 transform、不写 `_baseScale`**）⇒ 换牌结束后同样有「按旧尺度重画」的潜伏档。

### ③ 原版换牌期**不关** `AutoCardRotation`

- 关掉倾摆的唯一入口是 `Card2DController.Toggle(false)`（把挂 `AutoCardRotation` 的 `2DCard` 节点 `SetActive(false)`）。
- 换牌期的卡状态是 `0xD / 0xE`（`CardScript__OnTouchUpAsButton.c:52-58` 那段就按这两个值分流）；
  `BattleCardUI__SetObjectVisibility.c:48-67` 对这两个状态走 **else 支**：
  `Card2DController__SetCardVisibility(controller, 0)` + `BattleCardUI__ToggleBody3D(false)`。
- `Card2DController__SetCardVisibility.c`：`CardVisibility.Front = 0`（签名桩 `d:/2/Warpforge_code/Scripts/Assembly-CSharp/Card2DController.cs`）
  ⇒ 这一档是「**显示卡正面**（`cardFront.SetActive(true)`）+ 关 3D 体」，**不是**关节点。
  只有 `cVar2 == '\0'` 那一支才 `Card2DController.Toggle(false)`（整节点失活），换牌期走不到。
- `AutoCardRotation__Update.c` 里**没有任何** mulligan / 状态闸。
- 数学：倾摆上限 ±10°（153/153 实例 = 10/10/10）⇒ 投影高度 ≈ cos10° = **0.985（−1.5%）**，解释不了 −16%。
⇒ **原版换牌期保持倾摆**，我们若关掉就是偏离判据。**不改**。
