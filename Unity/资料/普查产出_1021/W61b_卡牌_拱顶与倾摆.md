## 4. 拱顶判据的闭环（为什么可以说「没有缺口」）

1. **算法层**：条带每行取「该行开口像素的 min..max」，拱顶逐行收窄 ⇒ 逐行 quad 各自贴合，**结构上不可能漏**；
   上下再各外扩 3 行、左右各 3 px（抗锯齿边钻进框的金属底下）。实测 75/75 张 `strip_miss = 0.000%`。
2. **网格层**（不是再算一遍算法）：新加的 `CardView.FrameArtCoverage` 把 `ArtMeshInFrame` **真交给渲染器的那块网格**
   的三角形逐行投影回来，与开口比 ⇒ 1024² 立绘下最差一张 0.33%，且那 0.33% 全部是
   **立绘板够不到的装饰小洞**（框最上沿那圈小孔在 `byT` 之外，原版也不该有图）。
3. **立绘板**：战术卡立绘现读 **1024×1024**（`art_UM75` 等；446 张 tactic 里 483 张立绘是 1024²，其余 671×1024）
   ⇒ `ArtBoard` = 2.858²，包围盒 x ±1.429 / y −1.473..1.385，**远大于**开口（x ±0.81 / y −0.28..1.25）、
   也大于卡体 ⇒ 不会因为板小而出缝（671×1024 那档 x 半宽也有 0.936 > 0.81）。

## 5. 🔴 新查出的真差异：开口一圈的**半透明内斜面**没画立绘（⛔ 本轮没改）

### 5·1 现象（量化）

沿开口一圈有一条约 **14 px 宽、alpha 从 20 缓升到 100+** 的斜面（框的内倒角）。
原版靠 `FlipAlphaMask` 会让立绘从开口**淡出**进斜面；我们的条带在 `alpha ≤ 8` 处**硬切**（只多钻 3 px）。

| 档 | 没被条带覆盖的半透明面积（卡体内） | ÷ 开口面积 |
|---|---|---|
| tier1 | 中位 32,172 px | 15.2%–22.9% |
| tier2 | 中位 36,209 px | 14.9%–23.5% |
| tier3 | 中位 28,782 px | 11.3%–21.7% |
| tier4 | 中位 31,055 px | 13.4%–20.7% |

（逐环采样：距开口 1 px 处 mean α = **20.5**，每往外 1 px 升 ~7，14 px 处 **103** ——
`_tmp_view/w61b/frame_ultramarines_strat_tier4_semi.png` 里那圈**洋红**就是它。）

### 5·2 两种修法（都**没做**，等渲图拍板）

| 方案 | 做法 | 风险 |
|---|---|---|
| **A（便宜）** | `BuildFrameRows` 每行从开口往两侧继续走，**直到碰到 alpha ≥ 248** 才停（再叠 3 px），并且**限制每侧最多 ~40 px** | 实测「面积」只涨 11–22%，但**个别行会一路走 400+ px**（框某处的半透明区连通到很远） ⇒ 必须加上限，否则可能把立绘画到框外面；改完只能靠渲图看 |
| **B（原版口径）** | 立绘铺满卡体 + 真做一层 `SoftMask`（`_MaskTex` + `_FlipAlphaMask=1`） | 要能解析原版那只 mask shader（`SoftMaskScript.Initialize` 从 `ShaderLibrary` 取），且**必须在 Unity 里试**；本轮做不到 |

⛔ 没改的理由：这**不是拱顶缺口**，改了会动观感，而铁律 12 不让跑 Unity/渲图 —— 我没法验证改完是变好还是漏到框外。
⇒ 建议：主对话渲一张 tier4 图 + 并排原版实拍后再决定；要改的话 A 是一处（`BuildFrameRows` 每行的左右生长）而 B 是大改。

### 6·2 静态等值线读数（和实拍对不上，如实留档）

对 per-frame SDF（`card_sdf/saimhann_strat_tier4.png`，128²）中线取 R 通道：
`R = 0.333` 在 x = 31.5 / 95.5 px，`R = 0.465` 在 35.5 / 92.5 px。
若按「UV 线性铺满 4.4281² quad」换算：**0.333 → |x| ≈ 1.09、0.465 → ≈ 0.99**
（卡半宽 **1.046**、卡框不透明外沿 x −1.02..1.12）⇒ 线性读法下**带子本来就在卡沿**、不用放大。
**但**我们实测（scale = 1.0）带子在 **x = 0.72..0.80**（对应纹理 R ≈ 0.60–0.67）
⇒ **shader 的 R → 半径不是线性的**（`_Inner_Fallof` / `_Outer_Fallof` / `_SpriteAlphaEdge_*` 参与），
静态解不出「1.35 对不对」这件事。

⇒ **1.35 保持不动**（派单要求）。要收敛只能是**渲图实验**：同一张 tier4 卡在 `OutlineGlowScale = 1.0 / 1.35`

## 7. `新账-67`：`SetFace(Board)` 复位倾摆

### 7·1 「真的能在倾摆没复位时出牌」—— 能，两条路都是

| 事 | 判据 |
|---|---|
| 倾摆写在哪 | `AutoCardRotation.Step` 写 `cacheTransform.localRotation`（`Core/AutoCardRotation.cs:129`），而 `cacheTransform` = 它自己那个节点 = **`_tiltRoot`（`2DCard`）**（`Core/CardView.cs:2837-2842`） |
| 原来只关不复位 | `SetFace` 只 `_tilt.enabled = !board`（改前 `:1567`）—— 全文件**没有第二处**写 `_tiltRoot.localRotation` ⇒ 停用后那一帧的值**永久留着** |
| 出牌一定会撞上 | ① 程序化出牌 `BattleDriver.EnterBoardBody` → `card.SetFace(CardFace.Board)`（`Battle/BattleDriver.cs:9873`）；② 带飞行的 `CardFeel.HandToBoard` 在 clip 0.7 调 `SetFace(Board)`（`Core/CardFeel.cs:1353`）。两条都发生在**卡刚刚/正在动**的时候 ⇒ `AutoCardRotation` 此刻非 0（上限 ±10°） |
| 后果 | 场上 2D 层全关 ⇒ 画面上看不出；但 `HitFrame()` / `BoxCollider2D` 的标架**就是 `_tiltRoot`**（`CardView.HitFrame`）⇒ 命中框跟着歪（投影包围盒约 +2%）；将来任何挂在这一级的东西都会跟着歪（静默） |

### 7·2 改法（一处，`Core/CardView.cs:1577`）

```csharp
if (_tilt != null) _tilt.enabled = !board;
if (board && _tiltRoot != null) _tiltRoot.localRotation = Quaternion.identity;
```

出生入口（`Build` 新建的那个节点）`localRotation` 天然是 identity ⇒ 那边不用写（铁律 10 第 5 条：两个入口都覆盖到）。

**已知副作用（可接受，但要知道）**：`CardFeel.HandToBoard` 为了借 `Board` 形态建 3D 体，
会 `SetFace(Board)` → 立刻 `SetFace(prevFace)`（`Core/CardFeel.cs:1298-1299`）。
有了这次复位，**clip 起播那一刻倾摆会瞬间回正**（≤10°，一帧）。
那一帧卡正好开始淡出，判断影响可忽略；若用户说「登场时会顿一下」，先回来看这里。

## 12. 顺手发现（⛔ 只报没改）

1. `Editor/CardFaceProbe.cs` 原来渲的 `Armoured Offensive` 走的是 `CardProgress.Level(artId)` 的**缺省 1**
   ⇒ **探针永远是 tier1 矩形窗**，这正是「拱顶一直没实拍」的根因（已用 `DebugFrameTier` 补上 3/4 两档）。

   没去核 md5，只记一句。

   卡面软光影那层用的是 **per-frame SDF**（`CardArt.Sdf`）—— 两者别混（本轮读代码时差点搞反）。
