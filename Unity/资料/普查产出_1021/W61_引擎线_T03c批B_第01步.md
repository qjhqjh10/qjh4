## 4. `Core/ActionQueue.cs` —— API 清单

```csharp
namespace RuleEngine
{
    public enum ActionPriority { Player = 0, Instant = 1, Interrupt = 2, DelayedInstant = 3 }  // 字面量

    public sealed class QueuedAction            // 名字故意不叫 Action（避免与 System.Action 歧义）
    {
        public ActionPriority Priority;         // Enqueue 时回填
        public int Seq;                         // 全局入队序号（1 起、递增；排查/断言用）
        public string Label;                    // 人话标签
        public object Payload;                  // 最小载体 —— 后续批接 ResolveOps 的入参
    }

    public sealed class ActionQueue
    {
        public const int LaneCount = 4;
        static readonly int[] DequeueOrder = { 2, 1, 3, 0 };   // ⛔ 不从枚举算出来
        public bool Resolving { get; set; }     // 原版 resolvingActionFlag(+0x280)；**本类不自己置位**
        public int Count { get; }               // 四道之和
        public int Dropped { get; }             // 被丢弃的入队次数（非法 priority / null）
        public int CountOf(ActionPriority lane);
        public bool Enqueue(QueuedAction action, ActionPriority priority);  // 非法 ⇒ LogError + 丢弃 + false
        public bool TryDequeue(out ActionPriority lane, out QueuedAction action);  // 2→1→3→0；同道 FIFO；**不看 Resolving**
        public void Clear();                    // 清四道（不重置 Resolving/Dropped）
    }
}
```

**三条设计口径（都有判据，别推翻）**：
1. **消费序写死 `{2,1,3,0}`**（原版 `Update.c:1284-1299` / `NextActionInQueue.c:11-28`）—— ⛔ 不是按枚举数值排。
2. **`TryDequeue` 不看 `Resolving`**：原版那道闸在 `Update`（泵点），不在 `NextActionInQueue` 里。
3. **非法 priority LogError 后丢弃**（不 clamp、不默认）—— 与原版 `AddAutoActionToQueue` 同口径。
