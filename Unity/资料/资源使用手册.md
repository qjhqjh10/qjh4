### 为什么这么分（三条判据）

1. **按「读 / 喂 / 拉」分，不按「来源」分。**
   - `资料/` = 给人**读**的（md/pdf/图），所以全部是纯文档，没有二进制素材混进来。
   - `数据/` = 给**引擎喂**的（JSON/CSV），所以全部是结构化数据，可以整目录丢进 `StreamingAssets/` 或转 ScriptableObject。
   - `素材/` = 给人**拉**进 Unity 的（png/mp4/ttf/obj），所以全部是原始二进制。
   一条边界：**同一份东西不要在两个目录各放一份**（比如卡框只在 `素材/`，卡框规格只在 `资料/`）。

2. **Warpforge 原版素材与第三方素材包分开**（`素材/Warpforge原版/` vs `素材/<第三方包>/`）。
   理由：来源、授权、命名体系、管线（原版是 Built-in→URP 需转换，第三方多数已 URP-ready）都不同；
   混在一起以后无法回答"这张图是原版的还是买的"。`素材清单.md` 已经只为第三方包写了说明，本手册只讲 `Warpforge原版/`。

3. **`工具/` 独立在顶层，而不是塞进 `资料/`。**
   工具是要**执行**的东西，不是要读的东西。但**工具的家仍在 `d:/2/Warpforge_tools/scripts/`** —— 脚本里硬编码了 `d:/2/解包整理/...` 的绝对路径，还依赖同级 `../data/`（如 `cab_bundle_map.json`），
   搬到 `d:/4` 会因为找不到 `../data` 而行为改变。所以这里只放**快照**（供阅读/检索/改前对照），**运行请回 `d:/2`**。

### ⚠️ 坑 1（最重要）：OBJ **原样导入**，不要做任何手性还原 —— 审计报告的 A1 已被推翻

`_审计报告_0910.md` §A1 说「`06_模型/` 的所有 OBJ 是 X 镜像，进 Unity 会左右反，要先还原」。
**那条结论对 Unity 是反的，2026-09-10 已由实拍 A/B 推翻，报告里也留了更正块。**

- 数据层没错：`obj 顶点 == (-x, y, z) × bundle 顶点`（误差 1e-7）。
- 但**推论错了**：UnityPy 导出做的是「Unity 左手系 → OBJ 右手系」转换，**Unity 的 OBJ 导入器会再做一次反向转换，两次恰好抵消**。
- 实拍验证（battlearena1，只换回 3 个代表网格）：

  | OBJ 处理 | 结果 |
  |---|---|
  | **原样 copy2（正确）** | 哥特教堂在**左上**，与原版参照图一致 ✅ |
  | 先还原手性 | 教堂跑到**右上**，28 个网格全部内部镜像 ❌ |

- **正确做法**：`shutil.copy2` 原样搬。`gen_unity_arena_manifest.py` 的 `copy_assets()` 里 `restore_obj()` 保留但**不再被调用**。
- 教训：**顶点级数值比对不足以下结论，必须实拍比对。**

### ⚠️ 坑 2（未修，务必遵守）：不要用材质 JSON 的 `blend` 字段判断透明

Warpforge 用自定义 shader，**`_Blend` 恒为 0**。照它判 → 场景 **126/350**、特效 **522/1142** 个真 Alpha 混合材质会被误判成不透明，**半透明物体渲染成实心白板**。

**权威判据**（`gen_unity_arena_manifest.py` 的 `unity_mat_fields()` 已实现，直接读它的输出字段）：

```
transparent  ← (_SrcBlend=5 且 _DstBlend=10)   或 (_SrcBlend=5 且 _DstBlend=1，预乘 Alpha)
             ← 或关键字含 _SURFACE_TYPE_TRANSPARENT / _ALPHABLEND_ON
alphaClip    ← _AlphaClip > 0.5 或 关键字 _ALPHATEST_ON
forceBlend   ← 不透明且不 alphaClip，但贴图"全透明像素占比 > 15%"（背景板就是这种）
```
