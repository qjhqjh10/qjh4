## `A1334` — 判：**(γ) 前提不成立**（台账担心的「静默失灵」**不存在**）

**结论**：`SAU9` 那条 `gain Fast` **执行了、而且行为正确**（= 它自己拿到 Fast）。
台账里看到的 `Target == null` 只出现在「**把整条 desc 当一句解析**」那条路上，
而**那不是单位卡会执行的层** —— 单位卡的 `When <事件>, <正文>` 由**事件层只解析正文**（`CardDef.cs:1674`）。
另：`UM_Angels_of_Death` 的 `Target == null` 是 **`ruleprobe` 探针没建卡名索引**造成的假象，引擎里它有目标。

### ① `SAU9` 的 gain 执行了、落在它自己身上（判据链逐跳）

1. 卡面 → 注册监听器：`CardDef.cs:1488` `foreach (seg in EffectText.Split(Desc)) AddWhenTrigger(seg)`；
   `CardDef.cs:1511-1544` ① 支 `TryParseWhenSentence`。
2. **正文与事件短语分开解析**：`CardDef.cs:1615` `TryParseWhenSentence`（逗号切两半）→
   `CardDef.cs:1674` **`ops = EffectText.Parse(body, …)`**（`body` = `"gain Fast"`，**不含 `When Reanimated,` 前缀**）。
3. 无主语 ⇒ `Subjectless`：`EffectText.cs:6895-6900` 写 `Side=own Kind=unit Count=0 Auto=true **Subjectless=true**`
   —— **与 `Hornet`/`Warbiker` 逐字同一条路**。
   ⇒ 台账说的「两条路口径不一致」**其实是「探针问的层 ≠ 引擎执行的层」**，不是运行时口径打架。
4. 结算时目标 = 监听者自己：`EffectResolver.cs:5319-5321` `ResolveOps(ctx, owner, **u**, ops, "事件触发", subject)`
   → `ResolveTargets` 的 `Subjectless` 支 `EffectResolver.cs:652-666`
   （`source != null && source.IsAlive ⇒ list.Add(source)`）。
5. `Reanimated` 事件确实广播、且是**自指**：`WhenEvent.cs:803`（`Kind=Reanimated` + `SelfOnly=true`）、
   广播点 `EffectResolver.cs:7715 / 7749`。
6. ✅ **已有断言就是照它写的**：`RuleEngine/Editor/RuleEngineTest.cs:2379-2425` ⑤ —— 造了一张
   `desc = "When Reanimated, gain Fast"` 的卡，断 `got.Has("fast")`「**触发了**（拿到 Fast）」＋ 旁观那张 `WhenFired == 0`。

### ② `Target == null` 在结算层走到哪一步 —— **它根本走不到结算层**

- 结算层**不会空转**：`EffectResolver.cs:6016-6020` `DoGive` 有兜底
  `op.Target ?? new EffectTargetSpec{ Raw="(未写目标：己方全体)", Side="own", Kind="unit", Count=0, Auto=true }`
  ⇒ `Count==0` ⇒ `:774-777 list.AddRange(pool)` ⇒ `AddSide`（`:1294-1305`，`troopOnly=false` ⇒ **含督军**）
  = **己方全体**。⇒ 真执行的话是「**打宽了**」，**不是空过**。
- 但那个 op **没有任何消费者**：单位卡出牌**不解析整条 desc**（`RuleCore.cs` 全文 `.Desc` 命中数 = **0**）；
  `EffectText.Parse(card.Desc)` 的四处（`EffectResolver.cs:894/:896` 与 `:1056`）都是 **tactic/defence** 那条路，
  `:2889` 是 `PlayerChooseOps`（只看带 ask 的 op），`:2983` 的 pick 全是 tactic 卡。
- 判据也**明文说过这是「问错了层」**：`CardPresentation/Battle/BattleDriver.cs:11744-11759` ——
  单位卡/督军卡**不判** `IsFullyParsed(Desc)`；`RuleEngine/Data/DeckBuilder.cs:305-315, 353-375` 只对 `tactic`/`defence` 用它。
- **整类形状全池只有 10 张**（现读 `工具/ruleprobe/基线/out_baseline.txt` 的 `partial` 列 ＋ `cards_engine.json` 卡类 join）：
  `ASH_Farseer` · `ASH_Warp_Spider_Exarch` · `ASH_Bright_Lance_Vyper` · `BL25` · `BL15` · `DA15` · `DA38` ·
  `SAU9` · `SAU10` · `SOR40` —— **10/10 都是 unit、10/10 报出的 op 都以 `gain` 开头**
  （触发从句被吞成 `ReGain` 的**主语**：`EffectText.cs:6802` `TryGain` → `ReGain` 的 `(.+?)` 吃掉 `"when reanimated,"`
  → `IsSuspendedSubject` 只认 `the next/the first`（`:7446`）⇒ 落到 `ParseTarget`）。
- 那个 `null` 的落点：`EffectText.cs:7228`（`if (kw == null && nameHit == null) return null;`）
  ⇒ `:2436` `Finish` 判 `NeedsTarget(op) && op.Target == null ⇒ SegKind.Partial`（**正是 baseline 里那一列**）。
- 顺带：`DA15`/`DA38`/`SOR40` 的载荷被从句污染（例：`gain/pool///0/quest point, heal 2`）——
  同样**只在探针/覆盖率侧可见**，执行层解析的是正文。

### ③ 原版对应的是什么

- 原版允许「无目标」的 `gain`：目标**不是从文本层来的**，而是**结构化字段**（`CardScript` / `TargetsAffected` 一族）。
  这正是我们上一版复刻 `rule_core.gd:3137/3167` 里「无目标 → 友方全体」的来源（旁证、**非权威**）。
  ⇒ **「无目标 ⇒ 己方全体」这句话的原版判据我们手里没有**，只有旁证 ⇒
  ⛔ **别把它当权威去定 `null` 的语义**（这也是 `Subjectless` 那段注释的来龙去脉，`EffectText.cs:6864-6900`）。
- ⚠️ **反编译文件没有逐条落到具体 `.c`** —— 本次结论**不依赖**它（执行层的行为由我们自己的代码链闭合）。
  ⇒ 这是**没查**的一项，**不是「查了没有」**。

### ④ 建议：`Target == null` 该解析成什么

**都不该 —— 应该「按触发前缀分派」**，即在解析层把 `When <事件>,` / `After receiving a Dark Pact,` 从句剥掉、
只把正文送进动词 handler。

- 判据（**复用现成的一份，别写第二份**）：`CardDef.TryParseWhenSentence`（`CardDef.cs:1615`）——
  事件短语 `WhenEvents.ParseAll(…)` 非空 **且** 正文 `EffectText.Parse(…)` 可解析，两边都成立才算。
  （`RePersistAny` 那段 `EffectText.cs:3479` 已经是这个形状的先例。）
- ⛔ **不要**把 `DoGive` 的 `op.Target ??` 兜底改掉；⛔ **也不要**让 `ParseTarget` 对「从句当主语」返 `Subjectless`
  —— 那会把**整队**送出去（正是 `EffectText.cs:6864-6892` 注释里记的 `Farseer`/`Penitent` 那个坑），
  而且它会「看着有依据」（有字段、有分支）。
- 与 `A1311` 的**口径一致性**：`ResolvedSide`（`EffectText.cs:832-838`）读的是 `Side`，
  两侧都只该在「**真有目标规格**」时才有值；`Target == null` 那一档应当**逐步收敛到 0 张真卡**。

## 顺手发现（⛔ 一个文件都没改）

1. **注释过期（会误导下一个人）**：`RuleEngine/Editor/RuleEngineTest.cs:2418-2423` 写着
   「`gain Fast` 是**无目标**的正文，在 `DoGive` 里会落到**己方全体**，于是旁观那张照样会拿到 Fast」——
   与**同文件** ⑥ 的结论（`RuleEngineTest.cs:2448-2456`「⛔ 不再洒给己方全体」）**相反**，也与本报告 ① 相反。
   它当时是「选尺子」的理由，现在已不成立。
2. 🔴 **`ruleprobe` 与引擎不同口径**（台账/报告引用的证据就是从这里来的）：
   `工具/ruleprobe/Scan.cs:23-50` 的 `ScanMain` **从不建卡名索引**；`Program.cs:76-89` 的 `LoadPool` 也不建。
   而 `RuleEngine/Core/CreatePool.cs:613` 明写「**没建索引时 `MatchCardName` 一律返回 null** ⇒ 解析行为与从前完全一致」。
   ⇒ 凡「目标靠**卡名**指」的句子，探针一律报 `target=[]` ＋ 落 `partial` 列
   （`UM_Angels_of_Death` 的 baseline `:1024` 就是这么来的；引擎里 `EffectText.cs:7419` 的
   `TailCardName("your primaris intercessor")` 会命中卡 `UM14 Primaris Intercessor`
   ⇒ `Target = {Side=own, Kind=unit, Count=1, NameFilter="Primaris Intercessor"}`）。
   **推论**：台账 `A1311` 那条「`UM_Angels_of_Death` 是 3 参重载唯一的真卡用户」**很可能也是同一处假象**
   （引擎里它 `Side=own`、走 4 参，值与旧口径同 ⇒ `A1311` 的改法结论不变，只是「唯一真用户」这句该订正）。
   ⇒ **已立 `A1339`**。
3. **潜伏账（今天 0 张受影响）**：`RuleEngine/Data/CardDatabase.cs:113` 的 `CreatePool.BuildNameIndex(list)`
   排在**所有 `CardDef` 构造之后**，而 `CardDef` 构造期就会解析并**缓存**
   `_whenTriggers` / `_triggerOps` / `_spiritOps` / `_oathOps`（`CardDef.cs:421/511/940/979/1290 附近`）
   ⇒ 这些缓存里的「卡名目标」**永远是 null**，且**会在运行时真的执行**。
   现读全池：卡名目标只有 2 张、**都是 tactic**（且都不带 `[Spirit Stone]`/`Oath`/正文关键词）⇒ **今天无实际受害卡**。
   ⇒ 应记成**待办**。⇒ **已立 `A1340`**。
4. ⚠️ `SAU72 Immortals Phalanx`（`When reanimated, deploy a copy of this troop`）在 baseline 里
   **ops 列为空**（`SAU72|…|||`）—— 与本账同族但**另一种形状**（整句都没解出 op）。
   运行时是否靠别的层生效，**没查** ⇒ **已并入 `A1340`**。
