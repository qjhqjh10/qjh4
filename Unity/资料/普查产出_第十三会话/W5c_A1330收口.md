## 一 · 共用论证（10 处共用这一套，逐处只写「本处的差」）

### 1·1 两个式子的准确关系

| | 中心项（位置） | 尺寸项 |
|---|---|---|
| **甲式**（10 处原写法） | `PxX(q.position.x)` / `PxY(q.position.y)`（或 `LayoutSpace.ToPixel(q.position)`）—— 斜率 **`108`**（字面量 `108f` / `DesignPxH÷DesignHeight`） | `q.WorldW * 108f` |
| **乙式**（`MenuDraw.QuadRectPx` / `UnionQuadRectPx`） | `PixelOfDesign(PosInDesignSpace(q.transform))` —— 位置先**除回父级缩放**，再 x 走 **`PxPerWorldX = DesignPxW ÷ VisibleWidth`**、y 走 **`PxY`** | `q.WorldW * K`，`K = DesignPxH ÷ DesignHeight` = **`108f`** |

- **尺寸项**：`q.WorldW * 108f * 0.5f` 与 `q.WorldW * K * 0.5f`（`K` 是 const 折叠成 `108f`）**逐位相同** ✓。
- **y 中心项**：两式都调 `LayoutSpace.PxY`，**同一句代码** ⇒ `PosInDesignSpace` 不生效时**逐位相同** ✓。
- **x 中心项**：两式只在 **16:9** 重合，且 **`PxPerWorldX` 实得 `107.99999 ≠ 108`**
  （`Core/LayoutSpace.cs` 的 `PxPerWorldX` / `ToDesignPixel` 两条 doc 自己写着）⇒
  **差 ≤2.5e-4 px**（量级 = float 舍入；本件涉及的 |设计 x| ≤ 8.889 世界单位 ⇒ 我算出来 ≈7e-6 px，比 doc 那条更紧）。
- **缩放项**：`PosInDesignSpace(t)` 除的是 **`t.parent.lossyScale`**（`Shell/MenuDraw.cs` 的 `DivByScale`）。
  设被测 quad 的父级 `lossyScale` 为 `k`：
  - `k == 1` ⇒ `DivByScale(v, 1f)` 就是 `v` ⇒ **逐位相同**；
  - `k ≠ 1` ⇒ 甲式读的是**已缩放的视觉世界坐标**、乙式读的是**设计坐标** ⇒ 差 `(1 − 1/k)·|pos|`。
    **乙式才是对的** —— 它除的正是建件那条路（`MenuDraw.Local` / `ImageQuad.CreateNineSlice` 的
    `root.localPosition = Local(parent,…)`）除过的**同一级** ⇒ 反推回来恰是建件时给的矩形中心
    （这条恒等式写在 `QuadRectPx` 的 doc 里，可自证）。

> 🔑 **九宫格子块的特别之处（本件 10 处全部是九宫格）**：子块的 `parent` 是
> `ImageQuad.CreateNineSlice` / `MenuDraw.Nine` 建的**裸 `new GameObject`**（它 `localScale` 恒为 1、
> **从不被写**）⇒ **`k ≡ 1`，与它上面几级有没有缩放无关**。本件另核过：
> `Shell/MatchLogRow.cs:196` · `Shell/LeaderboardRow.cs:154`（`Background`/`BackgroundHighlight`）·
> `Shell/TrophyInfoPopup.cs:531`（`Fill`）· `Shell/PracticeModePopup.cs`（`Army Selector/Background`）
> 四处**全走 `MenuDraw.Nine`**，且这四个文件里**一条 `localScale =` 赋值都没有**（grep 过）。

### 1·2 逐位不变 / 改对的准确措辞（⛔ 别写成「逐位不变」就完事）

- **y 分量：逐位相同**（同一句 `PxY` + `k==1`）。
- **x 分量：差 ≤2.5e-4 px**（量级 = float 舍入）—— 所以**严格说不是逐位**；
  但**它远小于这 10 处任何一条涉及 x 的容差**（本件最小的两条是 `#7` 的 **1.0px** 与 `#10` 的 **1.5px**，
  其余是 0.5px 的视口边）⇒ **判绿/判红的结果不变**。
- **父链真带缩放时**：乙式**才对**（见上面那条恒等式）；甲式会给出被放大过的 px。
  这一档本宿主**今天到不了**（见 §一·1·3），但收口之后**到得了也不会错** —— 这是收口的另一半收益。

## 三 · `MenuDraw` 的改动（唯一一处动共用件）

### 3·1 动了什么

新增 **2 个重载**（带**逐块过滤谓词** `System.Func<ImageQuad, bool> filter`），并把**原有 2 个重载**
改成**一行转调**（`filter: null`）：

```
UnionQuadRectPx(t, gate, searchInactive,                    out x1,y1,x2,y2)                // 旧，签名不动
UnionQuadRectPx(t, gate, searchInactive,                    out x1,y1,x2,y2, out quads)     // 旧，签名不动
UnionQuadRectPx(t, gate, searchInactive, filter,            out x1,y1,x2,y2)                // 🆕
UnionQuadRectPx(t, gate, searchInactive, filter,            out x1,y1,x2,y2, out quads)     // 🆕（唯一实现）
```

**唯一的行为增量 = 循环里多一行**：

```csharp
if (filter != null && !filter(q)) continue;   // 位置：激活闸之后、量矩形之前
```

⇒ `filter == null` 时**逐字等价于改前**（那一句是 `if (false && …)` 的等价物）。

### 3·2 「新形参是否带默认值」——**没有默认值，改成新重载**

- 简报允许的写法是「带默认值的可选形参」。我**没这么做**，理由**两条**（都写进代码注释了）：
  1. **可选形参在 C# 里必须排在全部必填形参之后**，而本函数的后面四个是 `out` ——
     `out` 不能有默认值 ⇒ 那个可选形参只能摆到 **`out` 们后面**，调用点写成
     `UnionQuadRectPx(t, gate, true, out a, out b, out c, out d, q => …)` —— **可读性反而不如新重载**
     （位置在 `out` 之后，容易被误读成「第 8 个出参」）。
  2. **新重载对既有调用点是【编译期事实】层面的零影响**（旧签名**原封不动地还在**），
     而「改旧签名 + 加可选形参」是**源码兼容但签名变了**。本件的验收标准是「⛔ 不改那既有 7 个调用点」
     ⇒ 新重载让这一条**可以逐字复核**（`git diff` 里旧签名一行都没变）。
- ⚠️ **没有把 `filter` 做成「排除某棵子树」那种更窄的形参**（本来也可以）：
  `A1330` 的普查口径就是「**与 `UnionQuadRectPx` 同判别式的内联循环**」，过滤谓词是**入参**；
  做成「排除子树」等于把**调用点的一条业务判据**焊进共用件。谓词更保守，也与简报的措辞一致。

### 3·3 既有 7 个调用点为什么**不受影响**（逐条）

| 调用点 | 绑到哪个重载 | 为什么不动 |
|---|---|---|
| `Editor/DeckScene.cs:281` | 旧（4 out） | 实参 6 个（t, gate, bool, out×4）⇒ 只有旧重载能接 |
| `Editor/DeckScene.cs:295` | 旧（4 out） | 同上 |
| `Editor/MainMenuScene.cs:11940` | 旧（4 out） | 同上 |
| `Editor/RewardsScene.cs:669` | 旧（4 out） | 同上 |
| `Editor/SettingsScene.cs:162` | 旧（4 out） | 同上 |
| `Editor/ShopScene.cs:690` | 旧（5 out，带 `quads`） | 实参 7 个 ⇒ 只有旧的带 `quads` 那个能接 |
| `Editor/ShopScene.cs:1020` | 旧（4 out） | 同前三行 |

- **重载解析**：旧 4-out 形参个数 7 / 旧 5-out 8 / 新 4-out 8 / 新 5-out 9 ——
  **没有一组实参能同时匹配两个**（新重载必须多传一个 `System.Func`，而 `bool` 与 `Func` 之间没有隐式转换，
  lambda 也不会自动补进「实参列表里没有的位置」）⇒ **旧调用点不可能被重新绑定**。
- 旧重载的**函数体**从「一段循环」变成「一行转调 + 唯一实现里那一句 `filter != null`」；
  `filter` 传 `null` ⇒ 行为**逐字不变**（含空集归零、`quads` 计数、`t == null` 那一支）。
