**⑧ 卡面「白边/黑边」与立体感（3DLit）** —— 这两条是一条因果链，连着看：
- **立绘贴图的 alpha 通道就是角色抠图轮廓**（单位卡 91–97% 全透明、亮的形状正是角色；**战术卡 0% 透明** ⇒ 战术卡没有越界效果）。
  做法：**同一张立绘用两次** —— 底层忽略 alpha（`Shaders/ArtOpaque.shader` 只取 RGB）、前景层用真 alpha 盖在**卡框上面**；
  清单 `Resources/Art/cards/card_cutouts.json`（665 张）由导入脚本生成。卡框的**拱窗自己也是全透明的**（alpha=0）⇒ 拱窗里的背景必须由底层补。
  ⚠️ **游戏内的结构不是这样**（`Front` 只有一层立绘 + 一层卡框，卡框在上）；「立绘压卡框」是**官方 PnP 印刷卡**的顺序 —— **用户要的就是 PnP 那个观感**，照它做。
- 🔴 **纠正两条被推翻的结论**（第二十一、二十四轮查实）：早期把立绘 alpha **二值化（>127→255）**、并在导入脚本里把 alpha **写成 255**（当成「解码残渣」）——
  **两条都错**，alpha 是真数据。二值化的后果是**把带背景残渣色的半透明像素变成不透明**，角色轮廓外多出一圈**亮边**
  （实测边界 RGB (98,101,112) vs 内部 (52,52,67)；而**原始 bundle 贴图**的边界是 (45,48,64) ≈ 内部 ⇒ **源图没有亮边，是我们处理出来的**）。
  **正确做法**（`工具/import_original_art.py` 的 `bleed_edge_rgb`）：**软 alpha 原样保留** + 把**角色外一圈 8 px 的颜色渗成角色自己的颜色**
  （残渣色被替换 → 马赛克和白边一起消失）。渗只渗 8 px：再往外是完整插图，底层 `ArtOpaque` 要拿它补拱窗里的背景。
- ⚠️ **Unity 的坑**：`alphaIsTransparency` **开着**时 Unity 会把透明区的 RGB 用「最近邻填充」补上，划分边界正好是**多边形格子**，
  卡面直接变成**彩色马赛克**（软 alpha 才触发、二值时不触发，所以以前没发现）⇒ **卡图的 `.meta` 必须把 `alphaIsTransparency` 关掉**
  （`fix_art_meta()` 已写进导入脚本；`.meta` 是 Unity 生成的，第一次导入后要**再跑一遍脚本**）。
  全量验证：1129 张有内容的插图里「贴边一圈 vs 往内 3 px」色差 > 30 的 = **0 张**。
- ⚠️ **没做**：`AutoCardRotation` 整卡刚性倾摆（±10°，跟位移不跟指针）/ SDF 光影层 / 战场真 3D 网格 + MatCap。
  ⚠️ **没调通**：`Shaders/FrameCutout.shader`（卡框按遮罩挖洞、立绘只画一次，没有重影）—— 遮罩采样错、插图碎成马赛克；
  `CardView.UseFrontLayer = false` 可切过去接着调。证据 `资料/留档_排查证据/卡面立体感_0913/`（4 张图 + README，含复现脚本）。

## 三、架构：三层，各管各的

```
RuleEngine/          纯 C#，零 UnityEngine 依赖
   Core/             棋盘 9 格 / 回合 / 出牌 / 攻击 / 伤害 / 胜负 · BattleEvent（**结构化事件流**）· EffectSpec（效果文法）
   Data/             CardDatabase · DeckBuilder · StarterCards · SimpleAI
        ▲  只在这一层交界 ▼
CardPresentation/
   Battle/BattleDriver.cs  ★ **唯一连接点**：引擎状态 ←→ 卡牌视图 / 引擎事件 → 特效
   Core/VfxMap.cs          事件名 → 特效名（引擎不认识特效）· Battle/Label.cs 世界空间文字（HUD）
   Core/CardView.cs        一张卡的视觉 · Board/BoardLayout.cs 9 格几何（**只有位置，没有规则**）
   Hand/  HandLayout.cs · CardInteraction.cs
```

**三条边界**：① **`RuleEngine` 不知道画面** —— 纯逻辑，随机走 `System.Random(seed)`（同一局永远可复现），只说「谁在第几格做了什么」（`ctx.Signals`）、**不说是哪个特效**（翻成特效名是表现层 `VfxMap` 的事）；
② **`CardPresentation` 不知道规则** —— 落点合法性是**注入**的（`CanDropAtSlot` 委托），它自己不做规则判断；
③ **只有 `BattleDriver` 两边都认识** —— 加 AI / 换 UI / 做回放都只动这一层。`BoardLayout` 只剩几何（槽位坐标、落点吸附），谁能不能放在哪一格由引擎说了算。

### 事件流

`ctx.Emit(EvtKind.Ability, p, slot, 名)` → 表现层 `DrainSignals()` **搬走并清空** → `PlaySignal(每条)` → `VfxMap` 翻成特效名 → `CardEffects.FireEvent(名字, 格位坐标, 阵营, 卡名)`。
**为什么用「搬走」而不是游标**：搬完就没有「读到哪了」的账要记，也不会因为裁掉旧事件而让游标错位；代价是**忘了 drain 就会堆着** —— 批处理里那段「一口气跑 200 回合」的循环就显式调了 `driver.DropSignals()`。

| **🆕 运行时生成的东西别烘进场景** | 选择器的按钮/底板/文字和卡牌一样是运行时建的。存进场景的话，`ImageQuad` 的私有 `_tex` 和运行时 `new Material(...)` 都不进序列化，重新打开就是一排没材质的空壳。所以 `BuildScene` 里**只建空节点**，`Awake()`（Play）/显式 `Build()`（批处理）去建内容 |

| **🆕 效果链天生是个环，别指望「保证不会发生」** | 「受伤 → 打回去 → 那边也受伤 → 再打回来」（两个带**忏悔**的单位）转起来是停不下来的。规则书 :237「同时触发」讲的就是它。用 `BattleContext.MaxEffectChain`（8 层）截断，自检里造了两个乒乓单位验 |

### 对局用「卡组编辑器编的那套牌」

开局读 `DeckLibrary` 里**当前选中的那套**（`BattleDriver.BeginFromDeckLibrary()`，`Start()` 调的就是它）；
我方阵营**跟着督军走**（`BattleDriver.WarlordFaction`）；不合法 / 展不开 / 存档坏了 → 退回自动凑
**并在屏上说明白**（`BattleDriver.ResolveDeck` 的 `notice`）；「按 R 再来一局」**不丢卡组**。
⚠️ **玩家自己选 Goff 时对手让开**（免得开局先打内战）—— **这是我们挑的**：原版由匹配系统配对手，单机没有匹配。

**🔴 这条的真重点是「必须让玩家看见」**：引擎只收**能解析的**卡（见上一节），所以**一副合法的 30 张卡组，
实际能上场的是其中一部分**（卡池构成见 `资料/阵营推进_清单与交接.md` §一 现状表）。以前这件事只写在 `Debug.LogWarning` 里
（玩家在画面上看不见），现在开局会写在**提示行**上：

> 本局用你编的「极限战士」· N 张（**效果本版解析不了的战术卡**）没上场

⚠️ 战术卡 2026-09-12 打通、防御卡 2026-09-13 打通 ⇒ **现在只会丢「效果本版解析不了的战术卡」**，提示行那句话里**没有「防御卡」三个字**。

- 提示行（`_hintLabel`，两行棋盘中间那条缝）的**休息态文字**就是这句：游戏过程中的临时提示
  （选目标 / 不能行动…）盖在它上面，用完自动落回来（`BattleDriver.SetHint`）。
- ⚠️ **原版没有这一行**（原版全卡种都能上场，没什么要交代的）—— **这是我们加的**。
  唯一要真清空的地方是结算，不然会从结算面板底下透出来。
- 卡组名**截断到 14 字**：`Label` 是 NoWrap 的，名字长了会横着铺出屏幕（自检里有一条量宽度的
  断言：最坏情况 11.50 / 可见 17.78 世界单位）。

**自检**：`BattleScene.Run` 第 9 节（截图 `12_玩家编的卡组`），存档**隔离**在临时文件里
（`DeckStore.OverridePath`，**不碰玩家真存档**）。验到：空库走自动凑 / 合法卡组真的用上 / 重开不丢卡组 /
不合法明说再退回 / 全是战术卡只剩督军 / Goff 不打内战 / 读的是「当前选中」那套 / 存档坏掉要说人话。

### 卡面组装的层级规格（原版怎么套）

**查出来的原版规格**（出处 `资料/战斗规格/战斗重建_0827/子代理读报_2dcard_0827.md:310`
+ 预制体 JSON 的组件字段）：

| 层 | 原版 | 出处 |
|---|---|---|
| `CardImage`（立绘） | **2.7484 × 2.7484** @(0,−0.044/战斗预制体 −0.065)，Image `m_PreserveAspect=0` —— **比卡还大，故意要外溢** | `RectTransform_2364194910465924032` |
| `CardFrame`（卡框） | rect 2.2452 × 3.2572 @y−0.03，挂 `SoftMaskScript`：`MaskArea`=**立绘的 RT**、**`FlipAlphaMask=1`** | `RectTransform_-3192049446263720900` + `MonoBehaviour_1868992003668548544` |
| 层序 | CardImage < CardFrame < 数值格 < 特效 | `子代理读报…:308` |

→ 原版是「**立绘铺满并溢出，卡框的 alpha 当遮罩把多余的切掉**」。

⚠️ **踩过的**：拿「对卡框 alpha 做膨胀 + flood fill 量出来的透空窗口」当**矩形**裁剪框用 —— 那个区是**拱形**、立绘是**矩形**，
于是直角顶出拱形、窗口以外根本不画立绘。现在的做法（`CardView.ArtMesh` / `FrameMesh`）：

1. **立绘铺满卡框那块矩形**，卡框画在上面 —— 卡框自己就是遮罩，等价、少一层 mask（不用新增 shader）。
2. **13 个阵营的卡框全导进来**，占位那条路也补上立绘（卡面把插图位**抠成透明**，立绘从那儿露出来）。
3. **卡框按 sprite 自身比例 fit，不拉满 rect**：金属 bbox 608×936（0.6496）vs rect 0.689，拉满会横向撑宽 6%；
   fit 出来 **2.1159×3.2572**，宽度正好落在卡本体（2.0927）那条线上 —— 和原版卡面实测的「金属基本顶到卡边（0～98% 卡宽）」一致。
4. **插图换源**：`工具/import_original_art.py` 从 **`d:/2/新解包资源/`** 取、**按 `Sprite/*.json` 的 `textureRect` 裁**
   （旧解包给的是 660×1024，裁过、位置也不对）。
5. **卡框按稀有度分四档**（原版就是）：`CardArt.Frame(阵营, 稀有度)`。**稀有度→tier 的映射是对照原版卡面实测的**

   对照图 `资料/留档_排查证据/卡面组装_0912/tier_map.png`）。⚠️ `special`（39 张）没实测，先按 tier4。

`FrameUv` 退回「整张 1024²」→ 卡框的透明留白一起铺上去，UV 裁切全失效。

### 战术卡效果（`desc` → 结算）

**管线与文件 map**：

| 层 | 文件 |
|---|---|
| 文本解析：原版 `desc` → `EffectOp`（handler 顺序照抄 `rule_core.gd` 的 `_resolve_text`） | `RuleEngine/Core/EffectText.cs` |
| 载荷层：`give/gain/lose` 的载荷 → 属性增减益 / 关键词（`GIVE_KW` 54 条逐条照抄） | `RuleEngine/Core/GivePayload.cs` |
| 结算层：`EffectOp` 落到 `BattleContext`（伤害/治疗/抽牌/摧毁/眩晕/给予/回能…） | `RuleEngine/Core/EffectResolver.cs` |
| 引擎放开：`CanPlayCard`/`PlayCard` 统一分发到 `CanPlayTactic`/`PlayTactic`；`FromDeck` 收能解析的战术卡 | `RuleCore.cs` / `DeckBuilder.cs` |
| 表现层：战术卡能拖到**敌方半场**的目标上；`OnCardDeployed` 有战术分支 | `CardInteraction.cs`（`foeBoard`）/ `BattleDriver.cs` |

- **`Choose one:`（三选一）** —— 按原版「单机自动选 1」用 `ctx.Rng` 掷（`EffectText.TryChooseOne` + `EffectResolver.DoChooseOne`）。
- **`instead` 的替换语义** —— ⚠️ **原版这里做坏了**（条件白判 + 原效果照样打），我们按语义成对处理（`EffectOp.Instead` + `ResolveOps` 的成对处理）。
- **嵌入的效果文字**（`Give "💀 Backlash: …" to a friendly troop`）：机制就位（`UnitState.GrantEffect` + `GrantEmbeddedAbility`），**文字仍受 `EffectSpec` 文法限制**。
- **四类条件**：`the target survives` / `it has armour` / `you don't control any` / `no enemy is affected`（`EffectCondition.Normalize` + `RuleCore.ConditionHolds`）。
