## 二、卡牌：自己设计的一套

**不用原版那 1131 张** —— 一是版权（见项目任务.md 红线），二是简单版不需要：
原版卡的效果全写在 `desc` 文本里，而 v1 **不解析 desc**。

所以设计了两套**纯数值 + 已实现关键词**的阵营，打起来行为明确、可控。
在 `Assets/RuleEngine/Data/StarterCards.cs`。

**效果怎么写**（`关键词: 动词 数值 目标`，文法见 `Core/EffectSpec.cs`）：

```
Rally:     Damage 2 EnemyUnit      登场就砸对面场上一个单位
Strike:    Damage 1 EnemyWarlord   攻击之后（打没打死都算）补一刀
Slay:      Damage 2 EnemyWarlord   砍死单位之后
Backlash:  Damage 2 EnemyWarlord   自己阵亡时
Penitence: Damage 1 EnemyWarlord   挨打但没死时
Ability:   Heal 3 OwnWarlord       主动技能：花掉这个单位一次行动
```

`Damage` / `Heal` / `Draw` 三个动词，目标 `Self / OwnWarlord / EnemyWarlord / EnemyUnit`。
**解析不出来的效果文字一律不结算，并且卡面上那个关键词会打 `*`** —— 不许装作能跑。

## 三、架构：三层，各管各的

```
RuleEngine/          纯 C#，零 UnityEngine 依赖
   Core/             棋盘 9 格 / 回合 / 出牌 / 攻击 / 伤害 / 胜负
                     BattleEvent（**结构化事件流**）· EffectSpec（效果文法）
   Data/             CardDatabase · DeckBuilder · StarterCards · SimpleAI
        ▲
        │  只在这一层交界
        ▼
CardPresentation/
   Battle/BattleDriver.cs   ★ **唯一连接点**：引擎状态 ←→ 卡牌视图 / 引擎事件 → 特效
   Core/VfxMap.cs           **事件名 → 特效名** 的对照表（引擎不认识特效）
   Battle/Label.cs          世界空间文字（HUD）
   Core/CardView.cs         一张卡的视觉（**黑卡白字**）
   Board/ BoardLayout.cs    9 格几何（**只有位置，没有规则**）
   Hand/  HandLayout.cs · CardInteraction.cs
```

**三条边界的规矩：**

1. **`RuleEngine` 不知道画面** —— 它是纯逻辑，随机走 `System.Random(seed)`，同一局永远可复现。
   它只说「谁在第几格做了什么」（`ctx.Signals`），**不说是哪个特效**
   （`VfxMap` 在表现层，把 `ability` 翻成 `Buff_Blue_SW` 是那边的事）。
2. **`CardPresentation` 不知道规则** —— `CardInteraction` 的落点合法性是**注入**的
   （`CanDropAtSlot` 委托），它自己不做任何规则判断。
3. **`BattleDriver` 两边都认识，但只有它认识两边** —— 加 AI、换 UI、做回放都只动这一层。

`BoardLayout` 现在**只剩几何**（槽位坐标、落点吸附）。谁能不能放在哪一格，是引擎说了算。

### 事件流（这一轮的关键改动）

```
引擎侧                                   表现层侧
ctx.Emit(EvtKind.Ability, p, slot, 名)  →  BattleDriver.PlaySignals()
                                              ↓ DrainSignals()（搬走并清空）
                                           PlaySignal(每条)
                                              ↓
                                           VfxMap：事件名 → 特效名
                                              ↓
                                           CardEffects.FireEvent(名字, 格位坐标, 阵营, 卡名)
```

**为什么用「搬走」而不是游标**：搬完就没有「读到哪了」的账要记，
也不会因为裁掉旧事件而让游标错位。代价是**忘了 drain 就会堆着** ——
批处理里那段「一口气跑 200 回合」的循环就显式调了 `driver.DropSignals()`（见第五节）。

## 五、踩过的坑

| 坑 | 真相 |
|---|---|
| **🆕 新加的组件不进存档场景 —— 差点漏掉** | `AttackSelector` 是 `BuildScene` 里新建的，而 `Battle.unity` 是**上一次** `BuildAndSaveScene` 存的。不重建场景，按 Play 点自己的单位**毫无反应**，而自检全绿（自检那部分是**当场建的新场景**，验不到存档）。`CheckSavedScene` 里补了两条断言守着。**以后加了新的场景节点，一定要重建一次场景** |
| **🆕 运行时生成的东西别烘进场景** | 选择器的按钮/底板/文字和卡牌一样是运行时建的。存进场景的话，`ImageQuad` 的私有 `_tex` 和运行时 `new Material(...)` 都不进序列化，重新打开就是一排没材质的空壳。所以 `BuildScene` 里**只建空节点**，`Awake()`（Play）/显式 `Build()`（批处理）去建内容 |
| **🆕 「能不能开始放技能」和「这个目标行不行」是两件事** | `CanUseAbility(ctx,p,slot)` 一开始把「要选目标的技能没给目标」也判成 `ErrTarget`，于是表现层永远进不了「选目标」状态 —— 而**进状态那一步还没选目标呢**。拆成 `CanStartAbility`（只看这个单位）+ `CanUseAbility`（再看目标） |
| **🆕 效果链天生是个环，别指望「保证不会发生」** | 「受伤 → 打回去 → 那边也受伤 → 再打回来」（两个带**忏悔**的单位）转起来是停不下来的。规则书 :237「同时触发」讲的就是它。用 `BattleContext.MaxEffectChain`（8 层）截断，自检里造了两个乒乓单位验 |
| **🆕 触发效果的「本单位存活时」要连「还在不在场上」一起看** | 督军血 ≤ 0 时**仍占着槽 4**，但它已经不算活着。只判 `IsAlive` 会让倒下的督军继续触发斩杀/猛击 |
| **🆕 `Backlash` 触发时单位已经不在棋盘上了** | 离场结算把格子清空之后才轮到反噬 —— 找格位会失败。所以 `FireTriggerAt` 把 **owner/slot 显式传进去**：它既决定特效播在哪，也是「这张卡死在哪」的唯一记录 |
| **🆕 批处理下特效不会自己消失（自检环境的账，不是游戏的）** | `WarpforgeEffectPlayer` 靠 `Update` 自毁，批处理没有帧循环 → 实测播到第 24 个还全活着。阵亡特效 `Explosion_Possession` 甩出的满屏橙红火线会把后面每张截图盖住。`BattleScene.ClearEffects()` 在小节之间清一次。⚠️ 而且 `Destroy` 要等帧边界，**当帧的截图还是拍得到** |
| **🆕 「挨打」和「掉血」不是一回事了** | 旧实现对比血量，**护盾挡下**（血没变）和**疲劳**（不走 `ApplyDamage`）都发不出事件。现在 `ApplyDamage` 和疲劳那条路都显式 `Emit(Hit)`，护盾挡下发的是 `Amount=0` |
| **🆕 0 攻单位会把 AI 的攻击循环卡断** | `SimpleAI.NextAttack` 原来不判「这一刀打不打得出」，`Reef Guard`（0 攻）能凭「打督军加分」被选成最优刀 → `DeclareAttack` 返回 `ErrNoAttack` → **循环直接 break**。现在按**实际会用的那套数值**取攻击力，≤ 0 就跳过 |
| **🆕 AI 只看近战，远程单位永远不出手** | `NextAttack` 原来一律按近战算，`Ballista`（近战 0 / 远程 4）算出来是 0 攻。现在近战远程按 `SimpleAI.UseRanged` 选（这条现在**只给 AI 用**了，玩家是手选） |
| **编辑器模式下 `Object.Destroy` 不生效** | 它要等下一帧，而编辑/批处理里**没有帧循环**。批处理自检里旧的手牌视图全留在画面上，看起来像「手牌莫名其妙多出好几张」。换成 `Application.isPlaying ? Destroy : DestroyImmediate` |
| **换边之后必须再 `BeginTurn`** | `EndTurn` 只换 `Active`，**发能量/抽牌/解疲劳都在 `BeginTurn` 里**。只调 EndTurn 的话对手整个回合 0 能量、一张牌出不来（表现：AI 场上永远只有督军） |
| **格位底片要用「落位后」的尺寸** | 战斗场景格位间距比手牌紧得多，用整卡尺寸画底片，9 个底片会**糊成一整条灰带**。要用 `placedScale * LayoutSpace.Scale` |
| **落位动画推进到「落定」为止，别写死时长** | 引擎调用在 `DeploySequence` 的完成回调里。批处理自检写死 `Step(0.8f)` 不够，断言全挂而画面其实是对的。改成「推进到引擎里真有这个单位」的循环 |
| **`LayoutSpace.Cam` 是静态字段，不进 Play 模式** | 编辑器里建场景时设过，运行时是 `null` → 归一化坐标退回默认宽高比，超宽屏/4:3 全错位。`BattleDriver.Start()` 里要重新 `Apply(cam)` |

| **🆕 TMP 的 `textBounds` 在空串时是 `4.29e9`（不是 0）** | 那是 `uint.MaxValue`，TMP 内部当「无穷大」的哨兵。技能卡面板按「装不下就回缩字号」写，结果空标签把字号缩掉了 **1e-10 倍** —— 表现是「面板上一个字都看不见」，而断言全绿（断言查的是 `Visible`/文案，不是尺寸）。**任何「按文本框自适应」的逻辑都必须先跳过空串**，再加一道「缩得比 5% 还狠就不缩」的保险 |
| **🆕 在未激活的 GameObject 上调 `SetText`，TMP 生成不出网格** | 面板一开始用 `SetActive(false)` 收起、`Show()` 里先 `SetText` 后激活 —— `ForceMeshUpdate()` 在未激活对象上不出网格，`textBounds` 全 0，字全是零尺寸。**要么先激活再灌字，要么干脆别用 `SetActive` 显隐**（面板最后改成只靠 alpha，几个全透明 quad 不值当为它冒险） |

| ~~汉字渲染没走通（未解）~~ | **2026-09-12 已打通**，见第六节 |
| **能量按「每方自己的回合数」算** | 不是全局回合数。`rule_core.gd` 有修正记录，自检里有专门一条守着 |

### 落地（2026-09-12 做完的）

1. **导 TMP Essentials** —— ⚠️ **`AssetDatabase.ImportPackage()` 在批处理下不管用**：
   它只是把导入**排进队列**，`-quit` 的进程在队列被处理之前就退出了，
   **一个文件都不落地、日志里连报错都没有**。改成**自己解 `.unitypackage`**
   （它就是 **gzip + tar**，每条记录一个 GUID 目录，里面有 `pathname` / `asset` / `asset.meta`）。
   实现：`CardPresentation/Editor/TmpSetup.cs` 的 `ExtractUnityPackage` / `ReadTar`。
   ⚠️ 归档里条目名带 **`./` 前缀**（`./<GUID>/asset`），不剥掉 guid 会被切成 `"."`。
   包在 `Packages/com.unity.ugui/Package Resources/TMP Essential Resources.unitypackage`
   （Unity 6 把 TMP 并进 UGUI 了），**包里没有 .cs**，所以导入不触发脚本重编译。
   跑 `-executeMethod TmpSetup.ImportEssentials`，落地 **37 个文件**。
2. **建字体资产** —— `-executeMethod TmpSetup.BuildCjkFontAsset`，参数**照抄原版**那份 JSON：
   pointSize **50** / padding **5** / 图集 **2048²** / `m_AtlasRenderMode` **4165 = SDFAA** / **Dynamic** + 多图集。
   产物 `Assets/CardPresentation/Resources/Fonts/NotoSerifCJK-Regular SDF.asset`；
   源 TTF 放在 `Assets/CardPresentation/Fonts/`（**不在 Resources 下，不进构建**）。
3. **卡面接上** —— `CardView` 的卡名/关键词改挂 TMP 的**世界空间**组件 `TextMeshPro`
   （**不是** UGUI 那版 `TextMeshProUGUI`）；数值/费用仍走点阵字库。
   中文文案表在 `Core/CardText.cs`。
   ⚠️ 那张表是**我们自己起的名字**，**没有**用原版那两份中文库（`zh_CN.csv` / `zh_cards_0827`）—— 版权红线。
   ⚠️ 规则/存档/测试/美术文件名**一律仍用英文 `CardDef.Id` / `Name`**，只换显示名
   （和原版「卡上只存 `refNameId`、显示名走本地化表」一个路子）。
4. **卡名字号按原版实测定**（`CardView.TitleFontSize`）——
   原版 `NameTextUnit` 的 `m_fontSize = 19` × `m_LocalScale 0.01` = 0.19 世界单位，
   卡面高 `2DCard.m_SizeDelta.y = 3.3313`（父级 scale 全 1）→ **字号 = 卡高的 5.70%**。
   出处：`08_预制体特效/战斗预制体/` 的 `NameTextUnit` / `2DCard`，场景 `battlearena1` 那份值一致。
   ⚠️ 比的是**字号（em）**对卡高，不是文字框对卡高（文字框 29.7308×0.01 = 0.2973 → 8.92%，
   那是留给卡名的**版面空间**，不是字实际多大）。
   ⚠️ 原版开着 `m_enableAutoSizing`（max = 19），名字长会自动缩 → 5.70% 是**上限**。
   ⚠️ **关键词的字号没有原版出处**：对应的是 `DescTextUnit`（`m_fontSize = 23.55` / max 24 / 同样自动缩放），
   那个 23.55 是**请求值不是渲染值**，从解包资源里读不出实际多大 —— 所以关键词沿用原来点阵字的大小
   （卡高的 3.75%），**这是「我们挑的」，不是原版的做法**。

### 踩过的坑

- ⚠️ **`TMP_Text.textBounds` 给的是「行盒」，不是「字形框」。** 按它定字号字会小 ~30%
  （Noto Serif CJK 行高 **1.437 em**，汉字只占 1 em）。实测比值：行盒 `0.1437` / 字形 `0.0948`（÷fontSize）。
  量字形要用 `textInfo.characterInfo[0].topLeft.y - bottomLeft.y`。见 `Core/TmpFont.cs`。
- ⚠️ **Dynamic 模式下盘上的 `m_GlyphTable` / `m_CharacterTable` 就该是 0 条** ——
  原版那份同样是 0 条（对照它自己的三份拉丁字体 `Asar` / `Pragati` / `RobotoCondensed`，
  那三份是 **Static**、各存 250 / 250 / 304 条）。**别去「修」那张空字形表。**
- ⚠️ `AssetDatabase.CreateAsset` **不会替你建目录**（报 "Parent directory must exist"）。
- ⚠️ `ComputeMarginSize()` **只在 `OnEnable` / `GetTextInfo` / `OnValidate` 里跑**，
  `AddComponent` 之后才改 `sizeDelta` 的话得显式走一趟 `GetTextInfo`，否则不折行（`TmpFont.SetWrapWidth`）。
- ⚠️ **TMP 的字不吃材质的 `_Color`**（它用顶点色）。卡置灰时要单独给 TMP 的 `color` 再乘一遍
  （`CardView.SetTint`），不然卡灰了、字还是亮的，状态读不出来。
- ⚠️ 自检里**别写死英文关键词**。`BattleScene` 原来断言 `keywords.Contains("ABILITY")`，
  文案一改中文就断 3 条 —— 期望值现在从 `CardText.Keyword(...)` 取，跟着语言走。

> **答案：在卡体那颗攻击数值格上，与数字同点同心**。四条互相独立的证据：
> 1. **变换类型**：`Highlight` 是普通 `Transform` + `SpriteRenderer`；卡面 UI 那支是
>    `RectTransform` + `CanvasRenderer`（两条链**并列且同名**，这是上一轮混淆的根源）。
> 2. **脚本字段**：3D 容器 `HighlightAttackType.highlightObject` 明确指向这两个 Highlight；

> 3. **几何**：与同格数字几乎同点（Δ≈0.006/0.005）、约为数字框 2 倍，
>    `SortingOrder 0 < 数字的 1` → 是套在数字**下面**的一圈光晕。
> 4. **不是地板**：同 prefab 里真正贴地的东西必须翻 -90°X（`Card blob shadow` euler(-90,0,-180)）；
>    `Highlight` 旋转是 identity、等比缩放。场景里真正的地面位置高亮是另一个东西
>    （`Minion Position Highlight`，用的是压扁的非等比 scale）。
>
> 尺寸：sprite 128 px ÷ PPU 100 = 1.28（卡体空间）× `m_LocalScale` 0.655 = **0.84**，
> 点亮瞬间再 × `scaleModifierOnHighLight` **1.35** = 1.13；卡体宽 `Card 3D` 2.09
> → **1.13 / 2.09 = 54% 卡宽**。
