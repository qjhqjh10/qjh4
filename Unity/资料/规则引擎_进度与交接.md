**⑧ 卡面「白边/黑边」与立体感（3DLit）** —— 这两条是一条因果链，连着看：
- **立绘贴图的 alpha 通道就是角色抠图轮廓**（单位卡 91–97% 全透明、亮的形状正是角色；**战术卡 0% 透明** ⇒ 战术卡没有越界效果）。
  做法：**同一张立绘用两次** —— 底层忽略 alpha（`Shaders/ArtOpaque.shader` 只取 RGB）、前景层用真 alpha 盖在**卡框上面**；
  清单 `Resources/Art/cards/card_cutouts.json`（**张数看该文件的 `count`** —— ⚠️ **2026-10-06 更正：原写 665 张，实际 668 张**）由导入脚本生成。卡框的**拱窗自己也是全透明的**（alpha=0）⇒ 拱窗里的背景必须由底层补。
  ⚠️ **游戏内的结构不是这样**（`Front` 只有一层立绘 + 一层卡框，卡框在上）；「立绘压卡框」是**官方 PnP 印刷卡**的顺序 —— **用户要的就是 PnP 那个观感**，照它做。
- 🔴 **纠正两条被推翻的结论**（第二十一、二十四轮查实）：早期把立绘 alpha **二值化（>127→255）**、并在导入脚本里把 alpha **写成 255**（当成「解码残渣」）——
  **两条都错**，alpha 是真数据。二值化的后果是**把带背景残渣色的半透明像素变成不透明**，角色轮廓外多出一圈**亮边**
  （实测边界 RGB (98,101,112) vs 内部 (52,52,67)；而**原始 bundle 贴图**的边界是 (45,48,64) ≈ 内部 ⇒ **源图没有亮边，是我们处理出来的**）。

  （残渣色被替换 → 马赛克和白边一起消失）。渗只渗 8 px：再往外是完整插图，底层 `ArtOpaque` 要拿它补拱窗里的背景。

  （`fix_art_meta()` 已写进导入脚本；`.meta` 是 Unity 生成的，第一次导入后要**再跑一遍脚本**）。

## 三、架构：三层，各管各的

```
RuleEngine/          纯 C#，零 UnityEngine 依赖
   Core/             棋盘 9 格 / 回合 / 出牌 / 攻击 / 伤害 / 胜负 · BattleEvent（**结构化事件流**）· EffectSpec（效果文法）
   Data/             CardDatabase · DeckBuilder · StarterCards · SimpleAI
        ▲  只在这一层交界 ▼
CardPresentation/
   Battle/BattleDriver.cs  ★ **唯一连接点**：引擎状态 ←→ 卡牌视图 / 引擎事件 → 特效
   Core/VfxMap.cs          事件名 → 特效名（引擎不认识特效）· Battle/Label.cs 世界空间文字（HUD）
   Core/CardView.cs        一张卡的视觉 · Board/BoardLayout.cs 9 格几何（**只有位置，没有规则**）
   Hand/  HandLayout.cs · CardInteraction.cs
```

**三条边界**：① **`RuleEngine` 不知道画面** —— 纯逻辑，随机走 `System.Random(seed)`（同一局永远可复现），只说「谁在第几格做了什么」（`ctx.Signals`）、**不说是哪个特效**（翻成特效名是表现层 `VfxMap` 的事）；
② **`CardPresentation` 不知道规则** —— 落点合法性是**注入**的（`CanDropAtSlot` 委托），它自己不做规则判断；
③ **只有 `BattleDriver` 两边都认识** —— 加 AI / 换 UI / 做回放都只动这一层。`BoardLayout` 只剩几何（槽位坐标、落点吸附），谁能不能放在哪一格由引擎说了算。

### 事件流

`ctx.Emit(EvtKind.Ability, p, slot, 名)` → 表现层 `DrainSignals()` **搬走并清空** → `PlaySignal(每条)` → `VfxMap` 翻成特效名 → `CardEffects.FireEvent(名字, 格位坐标, 阵营, 卡名)`。
**为什么用「搬走」而不是游标**：搬完就没有「读到哪了」的账要记，也不会因为裁掉旧事件而让游标错位；代价是**忘了 drain 就会堆着** —— 批处理里那段「一口气跑 200 回合」的循环就显式调了 `driver.DropSignals()`。

## 五、踩过的坑

| 坑 | 真相 |
|---|---|
| **🆕 新加的组件不进存档场景 —— 差点漏掉** | `AttackSelector` 是 `BuildScene` 里新建的，而 `Battle.unity` 是**上一次** `BuildAndSaveScene` 存的。不重建场景，按 Play 点自己的单位**毫无反应**，而自检全绿（自检那部分是**当场建的新场景**，验不到存档）。`CheckSavedScene` 里补了两条断言守着。**以后加了新的场景节点，一定要重建一次场景** |
| **🆕 运行时生成的东西别烘进场景** | 选择器的按钮/底板/文字和卡牌一样是运行时建的。存进场景的话，`ImageQuad` 的私有 `_tex` 和运行时 `new Material(...)` 都不进序列化，重新打开就是一排没材质的空壳。所以 `BuildScene` 里**只建空节点**，`Awake()`（Play）/显式 `Build()`（批处理）去建内容 |
| **🆕 「能不能开始放技能」和「这个目标行不行」是两件事** | `CanUseAbility(ctx,p,slot)` 一开始把「要选目标的技能没给目标」也判成 `ErrTarget`，于是表现层永远进不了「选目标」状态 —— 而**进状态那一步还没选目标呢**。拆成 `CanStartAbility`（只看这个单位）+ `CanUseAbility`（再看目标） |
| **🆕 效果链天生是个环，别指望「保证不会发生」** | 「受伤 → 打回去 → 那边也受伤 → 再打回来」（两个带**忏悔**的单位）转起来是停不下来的。规则书 :237「同时触发」讲的就是它。用 `BattleContext.MaxEffectChain`（8 层）截断，自检里造了两个乒乓单位验 |
| **🆕 触发效果的「本单位存活时」要连「还在不在场上」一起看** | 督军血 ≤ 0 时**仍占着槽 4**，但它已经不算活着。只判 `IsAlive` 会让倒下的督军继续触发斩杀/猛击 |
| **🆕 `Backlash` 触发时单位已经不在棋盘上了** | 离场结算把格子清空之后才轮到反噬 —— 找格位会失败。所以 `FireTriggerAt` 把 **owner/slot 显式传进去**：它既决定特效播在哪，也是「这张卡死在哪」的唯一记录 |
| **🆕 批处理下特效不会自己消失（自检环境的账，不是游戏的）** | `WarpforgeEffectPlayer` 靠 `Update` 自毁，批处理没有帧循环 → 实测播到第 24 个还全活着。阵亡那件爆散特效甩出的满屏橙红火线会把后面每张截图盖住。`BattleScene.ClearEffects()` 在小节之间清一次。⚠️ 而且 `Destroy` 要等帧边界，**当帧的截图还是拍得到**。⚠️ **同一条链还留了个疑点**（2026-09-30）：`BattleScene.Run` **跑完退出时段错误**（断言全过），怀疑与「挂在卡下面的常驻 `WarpforgeEffectPlayer` + 那个静态 `Active` 表」有关 —— **未坐实**，证据 → `资料/已知的坑.md` |
| **🆕 「挨打」和「掉血」不是一回事了** | 旧实现对比血量，**护盾挡下**（血没变）和**疲劳**（不走 `ApplyDamage`）都发不出事件。现在 `ApplyDamage` 和疲劳那条路都显式 `Emit(Hit)`，护盾挡下发的是 `Amount=0` |
| **🆕 0 攻单位会把 AI 的攻击循环卡断** | `SimpleAI.NextAttack` 原来不判「这一刀打不打得出」，`Reef Guard`（0 攻）能凭「打督军加分」被选成最优刀 → `DeclareAttack` 返回 `ErrNoAttack` → **循环直接 break**。现在按**实际会用的那套数值**取攻击力，≤ 0 就跳过 |
| **🆕 AI 只看近战，远程单位永远不出手** | `NextAttack` 原来一律按近战算，`Ballista`（近战 0 / 远程 4）算出来是 0 攻。现在近战远程按 `SimpleAI.UseRanged` 选（这条现在**只给 AI 用**了，玩家是手选） |
| **🆕 能斩杀时 AI 会先去清部队（直接送掉胜局）** | 评分里「打死一个部队」= **1000** 分、「打督军脸」= **400** 分 ⇒ 对面督军剩 5 血、我三个 3/3 一刀就能砍死他的时候，AI 会去清那个**打不死的诱饵**。2026-09-17 加 `SimpleAI.CanLethal` / `DamageToFoeWarlord`（这一回合能对督军打出的总伤害：**督军自己也算一个攻击者**、一个单位只算**一刀**（近战/远程取高的那路）、过 `DamageAfterReduction`），`NextAttack` 在斩杀时给打脸压倒性的分。断言在 `RuleEngineTest.TestAiKillLine`（11 条） |
| **🆕 判据写得比实际窄 = 静默失效** | 老 `NextAbility` **无条件**要求目标，而选目标的函数**只在敌方部队里挑** ⇒ 「打督军脸」的技能在对面空场时**永远放不出来**；`NextAttack` 那边同理（0 攻单位被选成最优刀 ⇒ 攻击循环断掉）。**2026-09-17 起 `NextAbility`/`NextAttack` 都改成从**动作表**里挑（判据全问引擎）**，这类「自以为窄」的坑换了个形态：现在要盯的是**比较范围**（比同目标、别比全场最高） |
| **🆕 写 AI 断言时漏了「督军也是攻击者」** | 第一版把「3 个 3/3 能对督军打出多少」写成 **9**，实得 **11** —— 督军就在槽 4、`NextAttack` 一直把它算在内。**被自己的断言当场打回来**（4 条红）。修完期望值后 11 条全过。⇒ 量「某一张卡贡献多少」时，**先把督军疲劳掉**再量 |
| **🆕 AI 的动作顺序不再是写死的** | 老实现是「先把牌出完 → 再技能 → 最后攻击」。原版**没有这个顺序** —— 出牌 / 攻击 / 技能在**同一张动作表**里按分挑（`AI.PlayTurn` 一次只做一步，循环在 `BattleManager` 的协程里）。「够斩杀就直接打脸」「该先解场而不是先把牌出完」都是打分排序自然出来的结果。改在 `BattleDriver.DriveAiTurn` + `SimpleAI.NextAction` |
| **🆕 判「技能划不划算」的比较范围写错 = 技能全被压掉** | `NextAbility` 要判「技能值不值得放」，比较**必须限定在同一单位、同一目标**上（老口径是「技能伤害 ≥ 本单位攻击力」）。第一版拿「全场最高的一刀」比 —— 打督军那一刀天生比打小兵分高 ⇒ `TestAiUsesAbility` 的「2 攻打 2 伤技能」当场红（3 条） |

| **🆕 懒加载的 `Ready` 必须先 `EnsureLoaded()`** | `VoiceLines.Ready` 原来直接读 `_byId`，而加载是懒的 ⇒ **同一个断言里 `Ready` 说「没读进来」、紧接着的 `CardCount` 又打印 595**（后者触发了加载）。这类「两个数互相打架」的根因都是**求值顺序**，不是数据错。修法：属性里自己 `EnsureLoaded()` |
| **🆕 共用一个位置的两枚图，命中判定要按「矩形」判，不能按「哪一枚亮着」判** | 回放条的 `Play`/`Pause` 同座标互斥（原版如此）。第一版 `Hit()` 只判「亮着的那一枚」⇒ **停着的时候点它永远返回 None，就再也播不起来了**。改成「用同一个矩形判命中、报哪一枚看当前亮着谁」才有解 |

### 踩过的坑

- ⚠️ **`TMP_Text.textBounds` 给的是「行盒」，不是「字形框」。** 按它定字号字会小 ~30%

  量字形要用 `textInfo.characterInfo[0].topLeft.y - bottomLeft.y`。见 `Core/TmpFont.cs`。
- ⚠️ **Dynamic 模式下盘上的 `m_GlyphTable` / `m_CharacterTable` 就该是 0 条** ——
  原版那份同样是 0 条（对照它自己的三份拉丁字体 `Asar` / `Pragati` / `RobotoCondensed`，
  那三份是 **Static**、各存 250 / 250 / 304 条）。**别去「修」那张空字形表。**
- ⚠️ `AssetDatabase.CreateAsset` **不会替你建目录**（报 "Parent directory must exist"）。
- ⚠️ `ComputeMarginSize()` **只在 `OnEnable` / `GetTextInfo` / `OnValidate` 里跑**，
  `AddComponent` 之后才改 `sizeDelta` 的话得显式走一趟 `GetTextInfo`，否则不折行（`TmpFont.SetWrapWidth`）。
- ⚠️ **TMP 的字不吃材质的 `_Color`**（它用顶点色）。卡置灰时要单独给 TMP 的 `color` 再乘一遍
  （`CardView.SetTint`），不然卡灰了、字还是亮的，状态读不出来。
