## ② 判据（逐条可复查）

### P0-1 三格标题
- 原版行为：`ProfileRankingSection.Initialize:103-111` 非传奇支只关 `Legendary Display Profile`，`Highest Rank` 整棵保留。
  Three 格标题各走官方词条（参考图 `账户-个人资料参考图.png` 三格 = 战将精通 / 最高锻造厂等级 / 当前战役）：
  `PlayerProfile/HighestWarlordMastery`(Warlord Mastery/战将精通) · `/HighestForgeLevel`(Highest Forge Level/最高锻造厂等级) ·
  `/CurrentCampaign`(Current Campaign/当前战役)。
- 预制体字面值是 `'Highest Warlod Mastery'`（原版拼写）与两格 `'Current campaign'` —— **作者态占位**，运行期被服务端事件文案覆盖。
- 🔴 **顺带修掉两笔同源错**（同一个 flag 既管版式又管标题的连带）：
  1. `Forge Profile Container` 原来传 `warlord:true` ⇒ 它的**版式**也错成战将那套（`Title` 宽 280.40 而不是 483.05、
     `Badge` 440 而不是 123.07×104.28、`ArmyName/Level` 的 x 也错）。判据 = `普查产出_0927/档案窗_Profile页.md` §A 149-154 行。
  2. `ArmyName` 的框宽（289.46 / 240.45 / 240.45）与 auto 下限（14 / 13 / 23）**逐格不同**，原来三格共用一组值。
- 断言：三格标题各 = `Loc.OfficialCurrent(键)`，**且两两不同**。

### P1-8 改名校验
- 反编译 `ChangeNameWindow__ValidateInput.c` 逐句：
  `RemoveRichTextTags(text)` → `Replace(x, y)` → `if (0x18 < len) text = Substring(0, 0x19)` → 钮 `interactable = (len >= 3) && flag && (text != 当前名)`。
  ⇒ **3~25**、去富文本、同名禁改。`MaxNameLen` 由 24 改成 **25**（原来那 24 是我们早先猜的，判据其实一直在反编译里）。
- 富文本那层：原版是拿一张**静态标签表**逐条 `StringBuilder.Replace(tag, "")`（`TextMessageValidationTools__RemoveRichTextTags.c`），
  那张表的成员是**运行期静态数组、本地没解出** ⇒ 我们按**形状**删（`<…>` 且里面无空白；无闭合的不删）—— **超集**，如实标着。
- 原版 `ValidateInput` 里那次 `Replace(DAT_1842c15b8, DAT_1842c11b8)`：两个字面量**没解出** ⇒ **那一跳没做**（如实记）。
- 顶栏刷新：`TopBar.Parts` 新增 `PlayerName` / `NameShown`，`RefreshPlayerNameIfChanged` 挂进
  `RefreshTopAvatarIfChanged` 的**最前面**（原来第一句 `if (parts.TopAvatar == null) return;` 会把「没取到头像图」时整块跳过）。
  两个宿主（`MainMenuRuntime.Update` / `DeckRuntime.Update`）本来就**每帧**调那个口 ⇒ 不必改宿主。
