## ① 直答：非活动期小冲突长什么样（原版证据）

1. **原版没有「非活动期 = 经典左列」的第三套小冲突窗。** 整包（`assets_full` 全量 grep）只有 **1 扇** Skirmish 窗 prefab = `bundle_menus_assets_all/GameObject/SkirmishModeEventWindow.json`（脚本 `MonoBehaviour_-1807133450305712782.json`，`m_Script` 只命中 `SkirmishEventWindow`）。它的左列出厂就是 `Reward Display`（Progression / 说明 / 胜利数 / 5 档记分条 / Collect），子节点全 `m_IsActive=true`，**运行时没有任何一句 `SetActive` 开关它**（`SkirmishEventWindow__Open/RefreshScore/CollectClicked` 里 `+0xB8` 只喂 `RewardProgressBarPanel.Initialize`）。
2. **它是一扇 LiveOps 活动窗**：`SkirmishEventWindow : LiveOpsEventWindow<IFastModeEvent>`（`dump.cs:63944`），`LiveOp` 就是活动实例；实例为空时 `TryOpen/RefreshScore` 走 `FUN_1803f47a0()`（抛异常）⇒ **没有活动就没有这扇窗**。
3. **经典式左列只在 `RankedEventWindowV2`**：`Ranked Division Info`（`RankingDisplay`，638×812 @0,146.9）= Rank Title + DivisionText + DivisionImage(RankImage) + 结束于 + LeaderboardButton + Ranked/Unranked 开关。**关键直读**：`RankedEventWindowV2__LeaderboardButtonClick` 按 `PlayerDataManager` 的当前 playMode 二选一（`==0(Classic) → rankingPrefabClassic`，否则 → `rankingPrefab`=遭遇榜）⇒ **V2 确实也服务小冲突玩法**。
4. 结论：**用户方向大体成立** —— Reward Display 是「活动（FastMode 活动）期」那一扇；常驻/排名版小冲突走的是 V2 的经典式左列。⚠️ 但「哪场活动绑哪扇窗」在远端数据的 `EventComponents[MainWindow]` 里，本地读不到 ⇒ 这一步是**推断（中高）**，不是直读。

## ② 切换判据（活动/非活动）

- **在期**：`LiveOpsEventData.enabled` + `activationType/dates` → `IsActive(now)`/`GetState`（`dump.cs:126504-126545`）
- **主菜单出哪张卡**：`LiveOpsManager.GetEventsForDisplayingInMenu()`（Where 过滤 active / ShowInMainMenu）→ `MainMenuWindow.RefreshLiveOpContainers` 注入 `liveopContainersAnchor`；场景里该节点 = `Content`，**出厂零子件**
- **开哪扇窗**：该活动 `drawData.EventComponents` 里 `EventComponentReferenceType.MainWindow(=10)` 指的 prefab。直读反例：4 个 Parent 活动共用 GUID `9a266973…`；4 个 Scoring 活动**没有 key 10**，只有 Tab(11)/ExpirePopup(21)/HelpPopup(30)
- **窗内没有活动/非活动分支**：Reward Display 常驻；只有 Timer（`TryOpen` 按某 `int@0x24` 开/关）、`Banned card in deck`（`OnDeckSelected`）、Shield/Trophy 图标（`SelectArmy`）会开关。5 档是 prefab 固定 `Score Bar Line Level 1..5`，`MilestoneScoreBar.Initialize` 只逐行填数、不隐藏多余行

`d:/2/关服前存档/Warpforge/Player.log`（关服前原版实跑，2026-10）主菜单同时加载 **5 张活动容器**：`RevivalSkirmish` / `RevivalClassic` / `RevivalDraft` / `RevivalLongGame` / `PracticeEvent`（每个 3–6 次 "No asset referente found for MainMenuContainerForeground in …"）⇒ **小冲突在原版也是一场活动**，模式卡由活动生成，不是静态五格。`Revival*` 的 SO **本地没有**（本地 13 份是 2025 的 Expansion/Release）。
