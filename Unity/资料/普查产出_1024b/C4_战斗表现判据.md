## 1 · `B-23` 技能面板「运行时压暗」——**查不到压暗层，但机制读全了**

### 1·3 自相矛盾之处（🔴 如实记，别硬圆）

底色白 + 四颗字白 + 字体材质 `_FaceColor` 白（`bundle_fonts_assets_all/Material/Material_1185407168034066855.json`，`m_Name="Asar-Regular Atlas Material"`，`_FaceColor=(1,1,1,1)`、`_OutlineWidth=0`）⇒ **静态数据推出来是白底白字**。三种可能，静态判据分不出：

1. **场景序列化 ≠ 运行时真值**（prefab instance 的 `m_Modification` / 运行时再赋值；本机解包是扁平后的场景对象）；
2. 该面板在当前 build **根本不显示**（见 1·4）；
3. 原版确有一处**不在这个子树里**的全局机制（把面板整体调色/调透明），本机反编译里没有对应类。

⇒ 这一条**只能真机开一次技能面板采 RGBA 才能定**；⛔ 别把「多半靠运行时别的机制压暗」再写成结论（那是 2026-10 初的猜测，本件把它降级为「三选一，未定」）。

### 1·4 顺手发现：`FadeIn` **零引用**

- `grep -rln "FadeIn" dt/*.c` = 5 个文件（`ActiveSkillDisplay__FadeIn.c` 自己 + `AudioSourcesController__Blend/FadeIn` + `MaterialFader__FadeIn` + `MusicManager__PlayMusic`），**没有一处调 `ActiveSkillDisplay__FadeIn`**。
- 全 84 个 bundle 的 JSON 里 `"m_MethodName": "(FadeIn|SetAlpha|FadePower)"` **零命中** ⇒ 不是 UnityEvent 挂的。
- 全 `all_strings.txt` 里 `FadeIn` **0 命中** ⇒ 不是 `SendMessage`。
- `BattleManager.activeSkillDesc(+0x168)` 的其它用途都只做 `ShowActingLight / FadeOut / DisableUsableLight / InitialSetup / Get gameObject SetActive(false)`（`dt/BattleManager__SetupInitialState.c:75-81` · `__ClosePopupsAfterBattleEnd.c:19-22` · `__StopBattleAfterBattleEnd.c:44-47` …）。
⇒ **本 build 里把这个面板「显示出来」的静态路径没找到**（可能方法体缺失，也可能这版不显示）。这条要真机确认；⛔ 不要据此改我们的实现（我们照常有面板）。

### 1·5 「怎么在批处理里验」（可直接写断言）

对**我们**这一侧（`Battle/SkillPanel.cs`）能批处理验的、且**判据来自原版**的六条：

1. **淡入目标 1.0 / 时长 0.2**（`FadeTime = 0.2f` 已是原值）。
2. **淡出时长 = 0.1 s**（原版 `fadeTime × 0.5`）—— 我们现在**两个方向都用 0.2**（`SkillPanel.FadeTo` 只有一个 `FadeTime`）⇒ 这条会红，是真差异。
3. **参与淡出的件恰为 6 件**：`cardFrame(=底板) · bgLight · manaIcon · Name · Desc · Cost`；**`TargetsAvailableText` 不参与**（原版 `SetAlpha/FadePower` 不含 `+0x78`）。我们现在 `ApplyColors()` 里把 `_targets` 也乘了 `Alpha`（`SkillPanel.cs:1551`）⇒ 真差异。
4. **三层灯的确切颜色/α**：`(1,1,1,.392) / (0.9254,1,0,.392) / (0.006,0,1,.392)`（现注释已对，加断言钉住）。
5. **`HideAbilityButton` 的判定域与 α=0**（吃射线不显示）——我们已有等价「点面板外收起」行为，断言「该捕获区不参与任何淡入淡出」即可。
6. **面板子树里没有任何深色底板**（原版侧）—— 这条只能在**解包静态检查**里跑（读 13 个 arena 的 `ActiveSkillDisplay` 引用闭包，断言不存在 `m_Color.rgb` 明显偏暗且 α>0 的 Image）；它**不能**验「像不像」。

## 3 · 打字机节拍

**原值 = `0.01 s/字`**，证据链完整：

| 环节 | 证据 |
|---|---|
| 字段 | `dump.cs:119528` `public static readonly float timeBetweenCharsTypewriter; // 0x1B8`（`GameStaticData`） |
| 值 | `dt/GameStaticData__.cctor.c:246-247` `*(…+0x1b8) = 0x3c23d70a` ⇒ **0.01f**（`struct.unpack('<f')` 现算 = 0.0099999998） |
| 用法 | `dt/VoiceLineBox._AnimateText_d__22__MoveNext.c:23`（先 `maxVisibleCharacters=0`）→ `:27,29` 等 **0.01** → `:43` 读 `textInfo.characterCount` → 循环 `:59`（每字 +1）`:63,65` 再等 **0.01** |
| 类身份 | `DAT_18427be00` = `GameStaticData`（同一个 TypeInfo 的 `+0x11c` = `smallScreenUI`，`dump.cs:119482`；旁证另见 `资料/普查产出_1006/A154_A155_窗口档位与缩放.md:177`） |

- 结构细节：**先等一拍**才显示第 1 个字；之后每显示 1 个字等一拍 ⇒ 总打字时长 ≈ `字符数 × 0.01`（比我们现在的 0.03 **快 3 倍**）。

- 建议：`UnitChatPanel.TypewriterCharSeconds 0.03f → 0.01f`，注释改成上面三条出处。

## 4 · 监听者族的目标

### 4·1 原版结构：触发回调**一直带三张卡**

```
RawCardScript.OnTrigger(trigger, thisCard, actingCard, targetCard, …)         // dt/RawCardScript__OnTrigger.c:15
  → RawCardScript.TriggerAbilities(…)                                          // dt/RawCardScript__TriggerAbilities.c
  → RawCardScript.TriggerAbility(…)                                            // :31 SetNewData
      AbilityData.SetNewData(thisCard, actingCard, targetCard, isPlayerTurn, priority, block)
  → AbilityLogic.PlayAbility(logic, manager, abilityData, triggerValue)        // dt/RawCardScript__TriggerAbility.c:89,103
```

- `AbilityData` 字段：`thisCard@0x10`（**能力所属卡** = 监听者自己）· `actingCard@0x18`（**做出动作的那张卡**）· `targetCard@0x20`（**被作用那张卡**）——`dump.cs:19556-19566`；赋值 `dt/AbilityData__SetNewData.c:2-12`。
- `PlayAbility` / `GetTargets` 就是读 `abilityData +0x10/+0x18`（`dt/AbilityLogic__PlayAbility.c:147-158,277-278`）⇒ **「被触发的目标是谁」= 广播方传进来的 `targetCard`（以及 `actingCard`），不是靠猜**。

### 4·2 那 7 张卡走的是同一条 `UnitAttack = 50`

- 数据：`cards_engine.json` 里 `DA22 / UM70 / UM83 / SW16 / GSC12 / SAU31 / TL24` 的 `abilityTriggers` **全部 = `[50]`**。
- 广播链：`BattleManagerSupport.BroadcastUnitAttacked(manager, attacker, attacked, kind)` → 逐个「在场单位 / 双方手牌」调 `CardScript.ResolveUnitAttacked(L, attacker, attacked, kind)` → `OnTrigger(50, thisCard=**L**, actingCard=**attacker**, targetCard=**attacked**)`。
  出处：`dt/BattleManagerSupport__BroadcastUnitAttacked.c:13-78`（21/29/53/66/78 五个调用点）；`dt/CardScript__ResolveUnitAttacked.c:27-30`。
- 同一条攻击结算协程里还有别族触发，形状**一样是三张卡**：例 `dt/BattleManager._ResolveAttack_d__438__MoveNext.c:379` `OnTrigger(0x1b8 = 440 Landing, thisCard=卡, actingCard=卡, targetCard=0)`、`:1444` `OnTrigger(0x82 = **130 Rage**, thisCard=被打方, actingCard=雷击来源, targetCard=…)`。⚠️ **`UnitDamaged = 60` 的广播点本轮没找到**（`grep "OnTrigger" | grep ",0x3c,"` 零命中）—— 要查它得单独追，⛔ 别拿 `0x82` 当 60。

### 4·3 逐卡该取哪一张（判据 = 卡面正文，中英都核过）

| 卡 | 卡面（英） | `actingCard` | `targetCard` |
|---|---|---|---|
| `SAU31 Doomstalker` | When an enemy attacks, deal 2-3 damage to **it** | ✅ 那个攻击者 | — |
| `UM70 Invictor Warsuit` | When an enemy attacks, deal 2 damage to **it** | ✅ 攻击者 | — |
| `TL24 Harpy` | When an enemy attacks, deploy a Spore Mine | 只用来判「是敌方攻击」 | — |
| `DA22 Techmarine` | When a friendly Vehicle attacks, gain 1 Quest Point. **If it survives, heal 3 to it** | ✅ 攻击者（既是判据也是治疗对象） | — |
| `UM83 Valtus` | When a friendly unit attacks, deal 3 damage **to the target of the attack** | 判据（是友方单位） | ✅ **被攻击者** |
| `SW16 Long Fang` | When **this** unit attacks an enemy with Hunt Mark… | 自己（thisCard） | 被攻击者（用于判 Hunt Mark） |
| `GSC12 Neophyte Iconbearer` | When a friendly unit attacks, create a Neophyte Initiate | 判据 | — |

⇒ 引擎侧需要的**不是一个 `Target`，而是两个**：`Actor`（actingCard，供「it / 本卡攻击」）与 `Victim`（targetCard，供「the target of the attack」）。VfxMap 的 `abilityTarget` 再按卡（`targetCriteria` 或卡面文本）选其中一个；选不出的仍退回 `self` 并出声。

### 4·4 建议

1. 事件层：给 `EvtKind.Trigger` 那条 `BattleEvent` 加 `ActorPlayer/ActorSlot`、`VictimPlayer/VictimSlot`（**只加字段，不改现有语义**），发射点 = 我们现有的 UnitAttack 广播处（攻方→Actor，被攻方→Victim；监听者自己仍是 `Player/Slot`）。
2. 消费层：`WhenTriggers`/VfxMap 里凡是「监听者族」的 `abilityTarget`，先试 `Actor`、再试 `Victim`，两者都不成立才 `self` 并出声。
3. 断言：`DA22`（敌人攻击我方载具）⇒ `EvtKind.Trigger` 的 `Actor*` = 攻方、`Victim*` 无；`UM83` ⇒ `Victim*` = 被攻方；`SAU31` ⇒ `Actor*` = 攻方。**别用「被打者」顶 `Actor`**（那是 `attacked` 族的语义，`B1 §七·1` 已经点过）。
