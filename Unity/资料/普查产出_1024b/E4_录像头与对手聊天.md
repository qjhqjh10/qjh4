## 六、顺手发现（⛔ 只报不改）

1. 🔴 **`SpeakFor` 的阵亡兜底查找比的是 `CardDef.Name`，不是 `Id`** —— `CardDatabase.Find(pool, name, faction)`（`:2285-2296`）
   按**名字**找，而 `CardEvent.Id` 形如 `ASH32`。现读**安全**（`RuleCore.cs:8748/8764` 发 `EvtKind.Death` 时带的是 `u.Name`），
   但这是一处**静默陷阱**：谁哪天把 `BattleEvent.CardId` 换成 `Id` ⇒ 阵亡语音与「纯音频」那一路**静默不出声**。
   建议立账（要么改成 `FindById` + 兼容名字，要么在 `BattleEvent.CardId` 的 doc 上钉死「只放 Name」）。
2. ⚠️ **`attack`/`death` 不再经过 `UnitChatPanel`** ⇒ `新账-63` 那条「气泡在显示但没有音频在播」的诊断口
   **不再覆盖这两档**（它本来就只管气泡）。若将来要查「攻击语音资源缺口」，得看 `VoiceLines.Clip` 的告警（那条仍在）。
3. ⚠️ **`CardDatabase.Find(pool, name, faction)` 在阵营不匹配时返回 null 且不报** —— 我这条 C4 断言差点因为它
   「因为错的原因变绿」（样本跨阵营）。已在断言里按阵营过滤，但**产品侧**同样的形状没有出声，建议立账。
4. ℹ️ `VoiceLines.SetExactForTest` 的注入口（`E2` 今天加的）**很好用**：本轮 C 节完全靠它造「精确绑定」，
   不需要依赖真卡数据里有没有 `attackAudio` ⇒ 建议后续同族断言都走它，⛔ 别再拿「数据巧合」当见证者。
