## ③ 逻辑：`CardPresentation/Shell/DraftPacks.cs`

| API | 说明 |
|---|---|
| `SupportedVersion` / `ResourcePath = "draft_packs"` | 版本守卫 + 资源名 |
| `CardsPerPack = 3` | **原版真值**（882/882 实测） |
| `RoundsPerDraft = 4` | 🔴 **我们挑的，不是原版真值**（`DraftEventData.draftRounds` 服务端下发、本地 0 命中） |
| `PacksPerRoundOffered = 3` | 🔴 **同上：我们按用户描述挑的**（本地唯一旁证只是选包 UI 的列表容量 3） |
| `ExpectedDeckSize = 12` | = `RoundsPerDraft × CardsPerPack`（⛔ 别在别处硬写 12） |
| `All` / `Count` / `Available` | 882 条（只读视图） |
| `PacksForArmy(armyId, enabledOnly=true)` | **粒度是阵营、不是战将**（原版 `GetRandomPack` 比 `packArmy`） |
| `Resolve(idOrKey)` | 先比 `key`（唯一），再退回裸 `packId`（那 27 组命中 enabled 优先的第一条） |
| `RollRound(seed, round, armyId, count, excludePackIds=null)` | 逐轮逐位确定；候选**按 `packId` 去重**（导出重复不翻倍权重）；同轮不重复；**候选不够就如实少给** |
| `BuildClosedDeck(warlordId, pickedPackIds)` / `TryBuildClosedDeck(...)` | 摊平成 `ClosedDeck { warlordId, cardIds[], packKeys[], packIds[] }`，**允许同卡两次**（包内自重） |

- **确定性口径**：第 (round, i) 位只由 `(seed, round, i)` 决定 ⇒ 同 seed 同轮次逐位相同。
  🔴 **不用 `UnityEngine.Random`，用 `System.Random(seed)`**（工程铁律）。
  ⚠️ **与原版的具体抽中结果不同**（原版是 `UnityEngine.Random`）—— 复刻的是形状与可复现性，不是同一串包。
- 🔴 **种子的形状照原版、但没照抄那个加法**：原版 `Random.InitState(seed + currentDraftRound + index)`
  会让 (0,1) 与 (1,0) 拿到**同一个种子** ⇒「换轮次结果不同」变成掷骰子（实测 1/129 概率整轮撞上）。
  改成散列混合 `(seed*73856093) ^ (round*19349663) ^ (i*83492791)`，**依赖关系一字不变**、碰撞可忽略。
- **载入**：`Resources.Load<TextAsset>("draft_packs")`；读不到 **`Debug.LogError` 出声**（不静默）。
  版本 < 1 / > 1、`count` 与 `packs.Length` 不符、某包 `cardIds` 不是 3 条 ⇒ 逐条**出声**（⛔ 不补齐不截断）。
- **测试口**：`SetPacksForTest(IList<PackDto>)` / `InvalidateCache()`（照 `ProfileData` 那几个 `*ForTest` 的形状）。

## ⑥ 顺手发现（不在本批范围，请调度台分流）

1. 🔴 **`TAU_EMyamoto` 在原始数据里撞键，而且两份内容不同**：
   `Darkstrider.json`（enabled=1 · `[TAU6,TAU12,TAU58]`）vs `E’Myamoto.json`（enabled=**0** · `[TAU12,TAU21,TAU58]`）。
   `decomp_full/CollectionManager__AddPack.c` 只是 `List.Add`、**没有去重** ⇒ 原版的包池里很可能**真有两个同 `packId` 的对象**，
   那 `GetClosedDeckByPackIds(warlordId, packIds)` 在原版就**存在歧义**。我们的处理：数据两条都留，
   `RollRound` 只让 enabled 的那条进候选（禁用的那条只在 `enabledOnly=false` 时出现）⇒ 正常轮抽无损失。
   **还没查清**：原版这一组到底哪条在 Addressables 里真被标了 label（要读 `catalog` 的 label 表）。
2. **882 个文件只有 855 个不同 `packId`**：27 组各两份（26 组逐字相同 = 导出重复；1 组见上）。
   任何「按 `packId` 建索引」的下游代码都会静默丢 27 条 —— 用 `key`。
3. **⚠️ 运行期还没接上**：`DraftPacks.Load()` 读 `Resources/draft_packs.json`，**本批按白名单没写那份**。
   接法：`python 工具/gen_draft_packs.py --write --emit-resources`（一条命令，两份产物同源）。
   不接的话 UI 那批一调 `DraftPacks` 就会报「读不到 `Resources/draft_packs.json`」。
4. **`packId` 前缀 ≠ 阵营**：Goff（army 20）的池里有 `ORK_ThickSkulled` / `ORK_Eadbanger` / `ORK_IrascibleLoons`
   这类 `ORK_` 前缀的包（抽包实测抽到过）。⛔ 别按前缀筛阵营，只能按 `packArmy`。
5. **`nameRefId` 882/882 全空** ⇒ 原版这个字段在这批数据里没被用过；生成器把它当**闸**（哪天非空就 red 提示重新核语义），不进产物。
6. **`draftpacks_assets_all.bundle` 只有 94,945 B**（S2 报告 §顺手发现），882 个 SO 全在里面 ——
   说明包数据是**纯文本级别的小对象**，以后要加别的轮抽数据也都在这一包里。
