## 四、没查清 / 没做（逐条写清「卡在哪、回来的条件」）

1. ⚠️ **`MuteEnemyChat` 那条 tip 的「4.0 s」没落地**：原版 `SmallTipData.tipDuration = 0x40800000 = 4.0f`，
   但真正决定气泡停留的是 `GenerateVoiceLineData(audio: null)` → `GetCurrentClipLength(null) = 2.0 s`。
   **我们按 2.0 s 走**（`UnitChatPanel.Duration`；与 `B1` 的记录一致），**4.0 那一格不进**聊天气泡 —— 判据见
   `BattleDriver.ShowMuteEnemyChatTip` 的 doc。⇒ 这一条**不是缺**，是把两个数分开用；如需 4 s 得先有「tip 专属时长」的判据。
2. 🔴 **联机局的聊天转发没有**（原版 `BattleCommsManager.SendChatMessage` + `PUNReceiveChatMessage → DisplayWarlordChatMessage(isLocal:0)`）：
   `CardPresentation/Net/**` 里 `Chat` **0 命中** ⇒ ①我方发言不会发给对面；②对面发来的话不会显示。
   **卡在哪**：`Net/**` 不在本轮白名单（联机线 2026-10-23 起暂停）。**回来的条件** = 联机线解冻 + 协议加一条 chat 消息。
3. ⚠️ **概率四个值仍是本地默认**（`AIBotsConfig` 是 RemoteConfig，`assets_full` 逐字搜 `emote_chance_after_action` 0 命中）。
   ⇒ 断的是**结构与量级**，不是原版数（与既有口径一致，别写成「原版值」）。
4. ⚠️ **`EmotesConfig` 之外还有一道远端开关**：`AIResponse.c` 开头 `GetConfig<?>(…)+0x70` 为真则**跳过概率闸**（必回）。
   **那是什么配置没查清**（`+0x70` 不在 `AIBotsConfig` 的字段表里，最后一个字段是 `disableFTUE @0x60`）⇒ 没建模。
5. ⚠️ **本轮断言未实跑**（红线：不跑 Unity）⇒ §六 的 🧨 只是「改坏就红」的**设计**，需主对话在同步点跑 `BattleScene.Run` 才算数。
