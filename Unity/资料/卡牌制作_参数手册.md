## 〇、先读这五条

1. **一条 `AbilityLogic` = 一个 `chosenAbility` + 8 个参数块 + 4 个标量**（`AbilityLogic.cs:7-46`，共 14 个公有字段）。
   代码**只读这个 effect 自己用到的那几个块**；其余块即使填了值，也**一律忽略**。
   ⇒ 数据里的「非默认值」不等于「生效」（见 §六·1 的实测脏数据）。
2. **所有字段的默认值 = C# 序列化缺省**：`int/bool → 0/false`、`enum → 0`、`List/数组 → 空`。
   SO 里没填的字段，`cards_raw.json` 里就是 0 / `[]`。
3. **枚举数值照抄，⛔ 别自己按 10 递增推算** —— 同族细分子项会占邻位（`summonUnit 70/71/72/75/77`、`buffMana` 的超类值等）。
   出处：`AbilityEffect.cs` / `AbilityTrigger.cs`；`P1_原版效果触发代码地图.md:172`。
4. **`chanceOfHappening` 只在 `0 < x < 100` 时才掷骰**（`PlayAbility:131-177`）：`0` 和 `100` 都 = **必中**。
5. **`TargetCriteria` 的 `targetsAffected` 是「选谁」的主开关**，其余 **37 个**字段是**筛选器**。
   `any(0)` 会**忽略所有其它筛选**（字段 Tooltip 原文：`'Any' disregards all other filters`，`TargetCriteria.cs:7`）。

## 五、做卡时照填（速查表）

> 步骤：**① 选 effect → ② 只填它读的块 → ③ 其余块留默认 → ④ 跑一次 `chanceOfHappening` 检查（0 = 必中）**。

| 你想要的效果 | effect | 必填块 · 最小写法 | 常见坑 |
|---|---|---|---|
| 造成伤害 | `10` | `damageCriteria{minDamage,maxDamage,damageType}` + `targetCriteria{targetsAffected:10, enemyUnits:1, includeHero:1, includeMinions:1, includeRemnants:1}` | `targetCriteria` 的 include 位不补齐 → **一个目标都选不到** |
| 随机伤害 | `12` | 同上 + `damageCriteria{valueOptions:90, damageType:5}` + `furtherMultiplier:N` | `min/max` 仍要写（随机范围） |

| 造卡入牌库 | `270` | 同上 | — |
| 加属性 | `30/40` | `buffEffect{buffType:1, meleeAttackChange/rangeAttackChange/armourChange/healthChange}` + `targetCriteria` | **`buffType` 不写 = 0（none）⇒ 加了也不生效** |
| 加词条 | `30/40` | `buffEffect{buffType:3, trait:<DefinedTrait>, traitValue:N}` | `trait` 是 **DefinedTrait**，不是 `Keyword`（兵种） |
| 降费 | `30` + `buffType:2` | `buffEffect{buffType:2, costChange:-N}`（+ `untilEndOfTurn`） | 手牌降费要用 `buffHand(50)` + `handBuff.cardEffect` |
| 加费 | `60` | `manaBuff{manaAmount:N, friendlyPlayer:1, createMana:1/refillMana:1}` | `createMana` vs `refillMana` 是两种语义 |
| 消灭 | `110` | `targetCriteria` | 原版走 `DestroyUnit`，**不是** `Add*` |
| 眩晕 | `130` | `targetCriteria` | `jam(120)` **不是** stun |
| 回手 | `140/150` | `targetCriteria` | — |
| 回牌库 | `300/301` | `targetCriteria` | 301 = 置顶 |

**三条硬规则**

1. **`targetsAffected` 必须写**（除非你确实要 `any`）。默认 `0 = any` 会**忽略所有筛选**。
2. **`include*` 位要补齐**。照同族样本抄（`SOR36` 的 `allFiltered` 把 `enemyUnits/includeHero/includeMinions/includeRemnants` 全置 1）。
3. **`buffEffect.buffType` 必须写**。0 = `none`，属性列填了也不会应用。

## 六、没查清 / 坑（如实列）

### 6·1 数据里的「非默认块」不一定是本 effect 读的

实测：`doOnlyVfx(3)` 的 10 条逻辑里有 1 条带 `summonCriteria`、2 条带 `damageCriteria`、4 条带 `buffEffect` ——
而代码 `:1456-1458` **只打一条日志就 return**。
⇒ **别按「数据里有什么」反推语义**；判据是 `PlayAbility` 读哪个偏移。

### 6·2 枚举外的值（**重要**）

| 字段 | 枚举外值 | 出现次数 | 已知线索 | 结论 |
|---|---|---:|---|---|
| `damageCriteria.valueOptions` | **8** | 38 | 全部带 `minDamage 3 / maxDamage 5 / damageType 5(Random)`；卡面语义 = 「造成 3–5 点随机伤害」 | 疑似旧版「随机」选项；**语义未坐实**，⛔ 别当 `ChooseValueOptions` 的成员用 |
| `buffEffect.healthValueOptions` | **17** | 8 | 全部出现在 GOF（兽人）卡上，`buffType` = 1/3 | 语义**未查清** |

### 6·3 其他未核

1. **`costChange = -999`**（1 处）—— 疑似「设为 0 费」的哨兵值，**未查清**。
2. **`manaAmount = 100`**（3 处）—— 疑似「本回合法力上限」，**未查清**。
