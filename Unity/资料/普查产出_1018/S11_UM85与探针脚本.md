### 4. 改了什么（改前 → 改后）· 修复前后各跑一次的读数

**文件**：`d:/4/Unity/工具/ruleprobe.sh`（纯 LF）

**改前**（第 21-25 行）：
```bash
if [ "$MODE" = "check" ]; then
  dotnet bin/Debug/net8.0/wfprobe.dll check "基线/out_baseline.txt"
else
  dotnet bin/Debug/net8.0/wfprobe.dll "$MODE"
fi
```

**改后**（`"$MODE"` → `"$@"`，并加 2 行注释写明原因）：
```bash
if [ "$MODE" = "check" ]; then
  dotnet bin/Debug/net8.0/wfprobe.dll check "基线/out_baseline.txt"
else
  # 🔴 2026-10-18 修：原来只传 `"$MODE"`（= `$1`）⇒ 后面的参数**全被吞掉**，
  #    于是 README/本头的用法 `… seg "<文本>"` 必崩（`Program.cs:47` 取 `args[i+1]` ⇒ IndexOutOfRange）。
  #    转发**全部**参数（`"$@"`），模式仍是 `$1`。
  dotnet bin/Debug/net8.0/wfprobe.dll "$@"
fi
```

`dotnet ... dll` 那一行已核对：**路径、dll 名都没动**（`bin/Debug/net8.0/wfprobe.dll`），只换了参数部分。

**与直调 dll（`cd 工具/ruleprobe && dotnet bin/Debug/net8.0/wfprobe.dll seg "…"`）的输出逐字相同** —— 这就是「转发对了」的判据。

**别的模式也一并核过**（它们走的是**同一个** else 分支，原来一起坏）：

| 模式 | 改前（只传 `$1` ⇒ 复现旧行为） | 改后（走 `"$@"`） |
|---|---|---|
| `seg <text>` | `IndexOutOfRange ... Program.cs:line 47` | ✅ 正常（上表） |

| `check`（默认、无参） | 本来就红不了（走的是 hardcode 那一支） | ✅ 未受影响，读数同 §3 |

⇒ **结论：`seg` / `card` / `filter` 三个模式在改前【全都用不了】**（README 与脚本头写的用法必崩），不是只有 `seg`。
