## 一、头像图「一张没画」—— **根因是画序，不是缺图**

### 结论

**图全在、也全取得到；是 `Border` 把 `Image` 盖死了。**

| 事实 | 证据 |
|---|---|
| 清单 469 条，**图名对不上 PNG 的 = 0** | `Resources/profile_cosmetics.json` × `Resources/Art/avatars/`（472 张 png = 469 头像 + 2 占位 + 1 别族；脚本逐条比过） |
| 头像 PNG 本体正常 | 469 张全是 **512×512 RGBA**，`alpha` 有 77% 透明边（不透明包围盒 252×302 = 49%×59%）——**贴图本身就是这样，不是导出坏了** |
| **边框贴图中心是【不透明黑】** | `Resources/Art/ui/Player_Profile_Border.png`（256×286）：中心像素 **RGBA (0,0,0,255)**；全图透明仅 **15.5%**、不透明 **75.6%** ⇒ 它是一整块黑盾 + 一圈金属边 |
| 原版兄弟序 = **`Highlight → Border → Image`** | `资料/普查产出_0927/档案窗_Avatar与Title页.md` §A1 第 **41–43** 行（大图）/ 第 **57–59** 行（格子）；同一份表第 42/58 行写明 `Player Profile Border` |
| 我们改前的队列 | 大图 `Highlight 4 → Image 4 → Border 5`；格子 `Highlight 1 → Image 2 → Border 3` ⇒ **Border 永远在 Image 之上** ⇒ 每格只剩黑盾 |

`AvatarTab.cs` 的两处（大图 `Build()`、格子 `BuildRows()`）就是上述画序。

### 修法

- 大图：`Highlight 4 < Border 5 < Image 6`
- 格子：`Highlight 1 < Border 2 < Image 3`（`Avatar Name` 2→4、`Hit` 4→5 顺延，互不重叠）
- 这**不是新发明的口径**：同一条病 2026-09-27 已在 `ProfileTab.L_ArtOverFrame` / `RankedTab.L_ArtOverFrame` 修过，
  顶栏有 `TopBar.QBarAvatarFrame(2991) < QBarAvatar(2992)`；三处注释都写着「盾的中心是不透明黑，反了就是一块黑」。

### 补的「出声」

`AvatarTab.WarnIfAvatarMissing(art)`（每个图名只报一次）：
取不到 `CardArt.Cosmetics(art)` 时 `Debug.LogWarning` **带图名 + 去哪里补**
（`Resources/Art/avatars/<名>` / 生成器 `gen_profile_cosmetics.py` / 导入器 `import_original_art.py` 的 `COSMETIC_AVATAR_SRC`）。
以前整页全黑时**运行期一行日志都没有**，只能靠截图发现。

### 顺带确认（不是猜）

- 加载路没问题：顶栏那块头像走的是同一个 `CardArt.Cosmetics`，同一张 `Avatar_UM_Aggresor Sergeant`，
  截图里**画得出来**（`13_avatar2.png` 左上角红盔）⇒ 排除「Resources 取不到」。
- 原版 prefab 里 `Image` 的 RectTransform **与容器同框**（`180×142.63` / `267.08×213.58`，`sizeDelta=0`、锚点铺满），
  `m_PreserveAspect=1` ⇒ 立绘按 512² 内接 = **约 60% 孔径**，**不铺满盾牌**。
  原版战斗截图（`桌面/warpforge参考图/战斗截图参考.png` 左下头像）量出来也是「人像四周留一圈黑」≈60–70%，
  所以**没有**去改这个比例（照 prefab 字段办）。

## 三、头像名中英混排 → 键拼错了

- 名字来自 `Resources/profile_cosmetics.json` 的 `avatars[].n`，`ProfileData.Fill` 再走
  `Loc.BulkOr("Avatars/" + <n>, n)`。
- **错因**：原版的键是 `Avatars/<nameTextReference 原文>`；`n` 是**剥掉 `Avatar_<阵营>_` 前缀**后的显示名。
  老一批 SO 的原文不带前缀（`Aggressor Sergeant`）、新一批**带**（`Avatar_UM_Attack Bike`）
  ⇒ 只拿 `n` 当键时**只命中 234/469**，另外 235 条（就是截图里的 Attack Bike / Bladeguard Ancient / Chairon…）全部落空。
- **改法**（数据 + 取值两处，都不猜）：
  1. `gen_profile_cosmetics.py` 把 `nameTextReference` **原文**存成 `r` 字段并重生成 json
     （重生成前后逐条比对：`avatars/titles/achievements/_note` **除新增 `r` 外逐字节相同**）。
  2. `ProfileData.Fill` 对头像按 **`r`（原文）→ `n`（显示名）→ `art`（图名）** 三级取键，
     每级先 `Loc.HasBulk` 探一下（⛔ 不用「先 BulkOr 再看返回值」，那会给 235 条各打一条 warning）。
- **现读：468/469 有官方中文名**；**无中文名的 = 1 条**：
  `Terminator Sergeant`（搜过 `Avatars/Avatar_UM_Terminator Sergeant` / `Avatars/Terminator Sergeant` /
  `Avatars/Avatar_UM_2nd Company Terminator`，并按 `en` 列反查整张 `Avatars/*` 表 —— 官方表里**确实没有**这条）
  ⇒ **保持英文原文**（⛔ 我们不自译）。
- `EnsureLoad` 末尾补一条**汇总** warning：缺几条 + 前 10 个名字 + 搜过的三种键形态（不逐条刷屏）。

## 四、左侧页签命中区

### 实测（`_tmp_view/click_log.txt` 第五轮，比我自己的推断硬）

| 点（截图坐标，上原点） | 画布坐标 | 命中 | 结果 |
|---|---|---|---|
| (268, 400) | (201, **300.8**) | `Hit / Tab Buttons / Avatar Button` | 正常切页 |
| (268, 1024) | (201, **768.8**) | `BackgroundHit / Player Profile Window` | **窗被关掉** |
| (252, 300) 附近 | (189, **297.0**) | `BackgroundHit` | **窗被关掉**（键 0/1 之间） |

⇒ 落在 `768.8` / `297.0` 这两点**不是文字没接**，而是**两键之间那 10px 空隙**：
`Tab Buttons` 是 `VerticalLayoutGroup spacing=10`（`KeyStep 119.252 − KeyH 109.252 = 10`），
原来每键的 `Hit` 只盖自己的键框 ⇒ 空隙落到窗根 `BackgroundHit`（= 关窗）。

### 修法

每键命中区**上下各吃半个间隙**（首键上沿 = 条顶 `BarT`、末键下沿 = 条底 → 正好铺满整条，相邻键**相接不重叠**），
键框本身（165×109.252）一个数没动。水平仍是 `KeyL..KeyR`（图标 `120.28..261.68`、文字 `113.48..268.48` 都在里面）。

### 原版这边如实记

原版 prefab 的六个键是 `EverguildToggle`，**没有**独立的 `Raycast Target` 子件
（`menu_dump bundle_menus_assets_all --rt 1299990831746480690 --depth 4`）⇒ 原版的射线区就是键框本身，
10px 空隙在原版里同样不属于任何键。**本处是照用户 2026-10-18 的指示「扩到整条页签」改的**，
属于我们主动放宽命中，不是「原版如此」。
