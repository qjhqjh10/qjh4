## 二、等级存档

- **位置**：`{Application.persistentDataPath}/WarpforgeCardLevels.json`（`CardProgress.SaveFileName`，`CardDetailPopup.cs:150`）。
- **格式**（`JsonUtility`；不用字典，因为它不支持 `Dictionary`）：
  ```json
  { "version": 1,
    "levels":    [ { "id": "UM82", "v": 2 } ],
    "owned":     [ { "id": "UM82", "v": 12 } ],
    "wildcards": [ { "id": "epic", "v": 98 } ] }
  ```
  `levels` 就是任务里要求的形状；`owned` / `wildcards` 是并列的另外两个数组（同一文件）。
- **读写**：懒加载（`EnsureLoaded`，`CardDetailPopup.cs:157`）· 写点 = `SetLevel` / `AddOwned` / `TrySpendWildcard`（`Save()`，`:182`）。
  读失败 / 写失败都 **`LogWarning` 出声、不抛**（红线：不许静默）。
- **缺省值 = 1**（`Level`，`:240`）：读不到存档 / 没有这条 ⇒ 1；越界夹到 `[1, MaxLevel]`。
- 🔴 **为什么从 4 改成 1**：缺省若仍是 `MaxLevel`，**每张卡一上来就满级** ⇒ `CanUpgrade` 恒假 ⇒
  升级钮永远灰、卡框永远只有 tier4 ⇒ **「升级换框」这条链根本走不到**（正是本任务的正文）。
  按原版口径：新卡一律 Tier1（`CardTier{Tier1=0..Tier4=3}`，显示等级 = 内部值 + 1；
  `CheckUpgradeRequirements.c` 的 `CardTier + 2` = 「升到第 N 级」）。
  2026-10-12「默认最高级」那条裁定的**前提**（当时不做升级机制、不想让面板印「升到 2 级」而卡框却恒最高档）
  **已消失** —— 现在两处是**同一个数**。
- ⚠️ **自检保护**：`ResetForTest()`（`:301`）现在清三张表 + `_persist=false`（**不写盘**）+ `_loaded=true`（**不读盘**）。
  否则跑一次自检就会改写开发机上的玩家存档、并让下一次自检被上一次的值污染（不可复现）。
- ⚠️ **连带行为变化**（都已在代码注释里标注）：`CardProgress.CanUpgrade` 在「给足」口径下（`Spares`=9）
  **恒真** ⇒ `BoosterPackOpenWindow.ReadyForLevelUp`（开包那枚「可升级」角标）**由恒假变回可真**。

## 三、创建副本：扣减口径

- 库存：**按稀有度 4 档**，初始 `WildcardsPerRarity = 99`（`CardDetailPopup.cs:264`），可扣减、落盘。
- 扣减：`DoCraft()`（`:1715`）→ `TrySpendWildcard(rarity)`（`:276`，扣 1、写盘）→ `AddOwned(+1)` → `RebuildKeepingState()`。
- 钮：`craftWb.Interactable = CardProgress.Wildcards(rarity) > 0`（`:1065`；排在 `Hit` 之后）；
  扣到 0 ⇒ 灰 + `WindowButton.Click()` 自己出声挡住（原版 `CraftingPanel__CheckButtons.c` 同支）。
- 计数条：详情窗那 4 格改读**真库存** `CardProgress.Wildcards(WildcardRarities[i])`（`:1617`），不再用写死的 `DeckRuntime.WcCountText`（`"99"`）。
- 🔴 **如实标注的两处偏离**（原版语义比我们细）：
  1. 原版通配符按 **army + rarity** 查；我们**只按稀有度**（4 档）—— 因为计数条本身就只有 4 格、单机没有发放源。**少一个维度**。
  2. 原版「**传奇且 `owned==1` 先弹确认窗**」（`CraftingPanel__TryCrafting.c`）**没做**（我们没有那扇确认窗）。
  3. 初始 99 是**我们挑的**（原版是服务端发放）；扣减本身是真扣。
