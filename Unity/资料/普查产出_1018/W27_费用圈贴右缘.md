## 一、新公式与取数来源

**横向（与卡框无关，是个常量）**：`FrameMesh` 恒把贴图**不透明块** uv.xMin..xMax 铺满 `FrameUnitW`、以 0 为心
⇒ alpha 右缘在卡单位里恒 `+FrameUnitW/2`。可见右边折回**网格中心**（`CostBgW` 是整张 sprite 的宽，
`Card_Frame_Cost_Icon`(248×244) 的 alpha>8 bbox = x3..238 / y3..238 ⇒ 右留 9、上留 3）：
`cx = 0.5·FrameUnitW − (239/248 − 0.5)·CostBgW = 0.8958 卡单位`（x01 = 0.92806）

**纵向（逐帧）**：`cy = badgeBottom(贴图 px → 卡单位 y) − (0.5 − 3/244)·CostBgH`。
`badgeBottom = frame_uv.json 的 bb`，由 `工具/gen_frame_uv.py` 离线量：alpha>200 的距离变换取右上窗口最厚处
= 徽记圆心 + 内切半径；沿圆心列下打，遇 alpha≤200 连续 4 行 = 下缘；若下缘 > 2.4×r（徽记与织带/挂饰连成一片）
改用「核心区最连贯的竖向色差边」。**预烘而不是运行时算**：运行时 `GetPixels32()+扫描` ≈55 ms/张（T09 已因此改过一版），
预烘 0 成本且有 150/150 覆盖。

**兜底**：表里没有 / UV 退化 ⇒ 旧固定点 `FrameCostPx/Py (751.7, 305.2)` + `Debug.LogWarning`（每张贴图只喊一次）。
**同源不变**：底板 `CardView.cs:2450` · 命中区 `:5058/:5115` · 数字/烘焙 `:6539` 全走同一个 `FaceCostAt01`。
