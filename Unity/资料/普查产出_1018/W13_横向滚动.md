# W13 · 横向列表能不能用鼠标滚轮左右滚（2026-10-18）

> 用户问题：「竖着框里可以鼠标滚动、上下滚动；那么横着的框里是否可以鼠标滚动、左右滚动？」
> 任务线条目 → `资料/任务线/界面线/任务总表.md` **N106**。
> 结论口径：**原版支持；我们也支持（机制上早就通了）**。用户感觉「横着滚不动」的**真实原因是步长**，不是轴向没接。

---

## 一、一句话结论

| | 能不能用滚轮横向滚 | 判据 |
|---|---|---|
| **原版** | **能**。uGUI `ScrollRect.OnScroll` 对 `horizontal && !vertical` **明确把滚轮 y 搬到 x 上** | 本地真 uGUI 源码 `MyGame/Library/PackageCache/com.unity.ugui@27635d171b1a/Runtime/UGUI/UI/Core/ScrollRect.cs:656-676` |
| **我们** | **能，而且早就通了** —— `MenuScroll.Wheel` **与轴向无关**，横向/纵向共用同一条路 | `Shell/PointerLayer.cs:391-396` → `:1170-1178`（`WheelAt`）→ `:1443-1456`（`HitScroll`）→ `Shell/MenuScroll.cs:270-275`（`Wheel`）→ `:404-409`（`Shift`，`Vertical ? 走 y : 走 x`） |

🔴 **所以不是「没实现」** —— 用户看到的现象是**步长**：
除 **主菜单模式卡（120 px/格，我们挑的，N66）** 和 **排位奖励活动窗（原版 100 px/格）** 外，
其余横向列表都照原版 `m_ScrollSensitivity = 1.0` ⇒ **一格滚轮只走 1 px**
（锻造奖励轨内容宽按本仓常量现算 = **19047 px**（`122 + 50×505.9 + 49×(−130)`，`ForgeTab.cs:126/128` + `ForgeData.MaxLevel = 50`），
视口是千 px 级 ⇒ 一格 1 px 要滚**上万格**；横向在手感上**等于不动**）。
纵向列表**大多数**能滚，是因为它们那几处原版灵敏度是 **50 / 100**（50~100 px/格）；
⚠️ 但**不是全部** —— 也有几处**纵向**照原版传了 1.0（`AchievementsMenu.cs:189` 成就页 · `InboxWindow.cs:487` 收件箱），
那几处一样会觉得「滚不动」。⇒ **同一个步长问题，横向纵向都有，只是横向几乎全是 1.0**。

## 二、原版判据（`文件:行号`）

### 2·1 uGUI `ScrollRect.OnScroll` —— 横向-only 会把 y 搬到 x

`d:/4/Unity/MyGame/Library/PackageCache/com.unity.ugui@27635d171b1a/Runtime/UGUI/UI/Core/ScrollRect.cs:648-682`

```csharp
public virtual void OnScroll(PointerEventData data)
{
    ...
    Vector2 delta = data.scrollDelta;
    delta.y *= -1;                                        // :658
    if (vertical && !horizontal)                          // :659-664
    {
        if (Mathf.Abs(delta.x) > Mathf.Abs(delta.y)) delta.y = delta.x;
        delta.x = 0;
    }
    if (horizontal && !vertical)                          // :665-670  ★ 横向-only
    {
        if (Mathf.Abs(delta.y) > Mathf.Abs(delta.x)) delta.x = delta.y;
        delta.y = 0;
    }
    if (data.IsScrolling()) m_Scrolling = true;           // :672-673
    Vector2 position = m_Content.anchoredPosition;
    position += delta * m_ScrollSensitivity;              // :675-676
    if (m_MovementType == MovementType.Clamped)
        position += CalculateOffset(position - m_Content.anchoredPosition);
    SetContentAnchoredPosition(position);
    UpdateBounds();
}
```

配套：`SetContentAnchoredPosition`（`:816-822`）**只放行允许的那根轴**（`if (!m_Horizontal) position.x = …; if (!m_Vertical) position.y = …;`）
⇒ 这条也是「横向列表的滚轮不会被纵向吃掉、纵向列表也不会被横向吃掉」的原版保证。

> ⚠️ 派单里那条假设「`vertical=false` 时滚轮**不**驱动水平」**不成立** —— uGUI 恰恰是在 `horizontal && !vertical` 这一支里做 y→x 的。

## 四、改动清单

**无（0 处代码改动）。**

理由：派单要求的「内容横向溢出时，滚轮 y 转 x」**已经在**（`MenuScroll.Wheel` 不判轴向，`Shift` 按 `Vertical` 把同一个 `Offset` 落到对应轴）——
再加一层「横向时把 dy 搬到 dx」会变成**同一套逻辑的第二份**，与 CLAUDE.md §三「两处写同一条规则 = 迟早不一致」相冲。

要真正解决用户的手感问题，**改的应该是步长**（不是轴向），而步长在**各宿主的构造参数**里
（`1f → 120f`，照 N66 那一处的口径）——**不在本代理白名单**（只能改 `Shell/MenuScroll.cs` / `Shell/PointerLayer.cs`）。
见 §五·1 的待办。

## 五、没查清 / 待拍板（都能直接照做，判据已给）

1. **🔴 横向列表的步长要不要统一提到 120 px/格（= N66 同口径，「我们挑的」，⛔ 不是原版值）。**
   要改的就是 §三表里第 3~9 那 7 处（`ForgeTab.cs:399/441` · `CampaignTab.cs:208/372` · `DailyRewardPopup.cs:257` ·
   `RewardWindow.cs:1121-1122` · `LeaderboardWindow.cs:461` 的最后一个实参 `1f → 120f`）。
   ⚠️ 这是**偏离原版**（原版 1.0）；N66 已经在主菜单开了这个口子，理由是「照 1.0 传 = 实际滚不动」。
   ⛔ 若决定「照原版 1.0 不动」，那就**保持现状**，但用户会继续觉得「横着滚不动」——这条要主对话拍板。
2. **我们横向滚轮的【方向】与 uGUI 原版相反**（今天只有 #1/#2 两处可感知，其余 1 px/格看不出）。
   推导（两根轴的 `Offset` ↔ `anchoredPosition` 符号相反）：
   · 纵轴 `Offset = +anchoredPosition.y` ⇒ 与原版同号 ⇒ 现有写法 `Offset −= dy·NotchK` ✔；
   · 横轴 `Offset = −anchoredPosition.x` ⇒ 必须**反号** ⇒ 原版语义是 `Offset += dy·NotchK`。
   ⇒ 原版：**下滚滚轮 = 内容左移 = 往右看**；我们现在：**下滚 = 内容右移 = 往左看**。
   ⚠️ **没有改**：原版横向列表的 1.0 灵敏度让这条在**原版里不可观测**，而改它会翻掉主菜单模式卡（N66）的现有手感 ⇒ 等主对话/用户拍板。
   改法一处：`MenuScroll.cs:274` 的 `Offset - dy * NotchK` → `Offset + (Vertical ? -dy : dy) * NotchK`。
3. **触控板/倾斜滚轮的横向分量（`mouse.scroll.x`）没接**：uGUI 在横向-only 那支里还有
   `if (|delta.y| > |delta.x|) delta.x = delta.y;`（即 **|dx| 更大时直接用原始 dx**）。
   我们 `PointerLayer.cs:394` 只读 `.y` ⇒ 触控板横向滑动滚不动。补法 = `WheelAt` 加一个四参重载把 `Vector2` 传进去。
   ⚠️ 普通滚轮 `x` 恒 0，**不影响今天的鼠标**。
4. **`DailyStreakPopup._trackScroll` 没登记**（`:475` 建了、全仓无 `RegisterScroll`）。
   但原版那条 `Rewards Scroll View` 是 **`m_Horizontal=0 / m_Vertical=0`** ⇒ `SetContentAnchoredPosition`
   把两根轴都冻结 ⇒ **原版也既不能滚轮也不能拖** ⇒ 我们**现状反而与原版一致**（只有 `FocusOn` 的自动定位在动）。
   ⛔ 别「顺手补一条 `RegisterScroll`」—— 那会让我们比原版**多**一种交互。
5. **原版还有一批横向 `ScrollRect` 我们还没建对应窗口**（一旦建起来，照 `MenuScroll` 走就自动有滚轮，无需再改滚动件）：
   `Gacha Tab > Rewards Panel > Rewards` · `Expansion Pass Tab > Rewards Scroll View` · `Raid Progress Tab > Rewards Scroll View` ·
   `Generic Multi Card Display`（3 份）· `Draft Mode Menu Demo/Timed Mode Window` 里那 4 份 · `Choose Army Deck FTUE Window > Armies`（**100**）·
   `Generic Shop Tab / Gold Tab / Packs Tab > Packs Scroll View`（这三份是 horizontal-only；我们已实现的
   `Card Shop Tab / Item Shop Tab / Daily Shop Tab` 三份**原版是纵向** `H=0 V=1`，我们 `TopAligned` ✔ 与判据一致）。
