## 一 · A：点「升级」后两颗按钮底图消失、只剩文字

### 1. 根因（`文件:行号` + 为什么只丢底图）

**`Shell/CardDetailPopup.cs` 的 `PanelBox(...)`**（现 `:1941`）：

```csharp
// 改前
else MenuDraw.Rect(p, tex, new PxRect(PanL, y1, PanR, y2), "Background", QCdRow);
```

面板**底板**原来画在 **`QCdRow = 3116`**，而面板里**所有内容**也都在 `QCdRow`：
两颗钮的底图（`Downgrade Bg` / `Upgrade Bg`，`:1145` / `:1160`）、面板里的图标、计数条底 …
本工程**没有 uGUI**，每个 quad 都躺在**同一个设计平面（z 全 0）**上；透明队列**同队列 + 同平面时
「谁盖谁」不可控**（`CLAUDE.md` §三「分层要用渲染队列，不能用 z」· `资料/已知的坑.md` 那条
「同一条渲染队列里【故意重叠】的两件 = 谁盖谁不定 —— 必须各给一档」）。

**为什么「只剩字」**：按钮上的「降级 / 升级」是 TMP `Label`，画在 **`QCdText = 3117`** ——
**严格高于**底板那条 3116 ⇒ 底板翻上来时只有**底图**被盖掉、**文字照样在**。与用户描述的现场逐条吻合。

**为什么「点升级之后才出现」**：`DoUpgrade` → `RebuildKeepingState()` → `Build()` **整窗重建**，
渲染件全部重新注册 ⇒ 同队列那两件的先后**翻了**（改前是先注册底板、后注册钮，画面上钮在上；
重建后反过来）。**同一份机制在同一个文件里今天就有现行实例**：写手 `W12` 查实
「详情窗那排万能卡**图标**被**底板**盖掉、而数字（`QCdText`）活着」—— 一模一样的形状（见 §四）。

### 2. 改法

* 面板底板 **`QCdRow`(3116) → `QCd`(3115)**（`:1941`）。`QCd` 这个常量在本文件里
  **没有任何别的用途**，而它自己的注释写的就是「3115 本窗的**钮 / 字 / 面板**」⇒ 面板底板本来就该在
  这一档，面板里的**任何**内容（按钮底图 / 图标 / 计数条 / 文字）都在它之上 ⇒ **与重建次数、注册顺序无关**。
  ⛔ 别改回 `QCdRow`；也⛔ 别去逐颗抬内容（要抬的地方太多，以后新加一件又会踩）。
* ⚠️ 顺带覆盖：这条同时把「面板里其它 `QCdRow` 件被底板盖掉」那一族（图标、计数条底）一起根治。

### 3. 防回归日志（用户要求的格式）

`RebuildKeepingState()` 里 `Build()` 之后加了一句 `LogRebuildPanels()`（`:1874` / `:1886`）：

```
[CardDetail] 面板重建：Crafting=有 · Downgrade=有 · Upgrade=有
[CardDetail] 面板重建·按钮底图：Downgrade Bg=有（q3116 · tex=UI_Button_Mulligan） · Upgrade Bg=有（...）
```

* 第一行 = 用户指定的三件在/缺（拿节点引用判 null）。
* 第二行是本笔补的**可操作读数**：底图节点的**渲染队列 + 贴图名** —— 队列掉到 ≤ 3115（被面板底板压住）
  或贴图变空，日志里当场看得见，⛔ 不必再等用户看截图。
* ⚠️ 找节点用的是新加的 `FindNewest`（从**最后一个子件**往前找）：运行时 `Build()` 走 `Object.Destroy`
  （**帧末才真销毁**）⇒ 重建后的同一帧里**新旧两棵树并存且同名**，直接用 `GetComponentsInChildren`
  会先撞上**旧的那颗**。`Build()` 是先销毁旧子件再按序新建 ⇒ 新树一定排在后面。

### 4. 把握度（如实）

根因是**机制层判定**（同队列 + 同平面 + 文字在更高一档），且有**同文件同日的现行实例**（`W12` 的图标被底板盖掉）
作证；修复后按钮底图（3116）**严格高于**底板（3115），**与注册顺序无关**。
⚠️ **本笔没跑 Unity、没真机复验** —— 画面请以真机为准（日志第二行可直接确认队列是 3116）。

## 三 · C：三块面板的间距（用户：「两个方框要保持距离；有三个方框时距离也要保持好」）

### 1. 最终 rect（设计 px）与两两间距

| `Upgrade Panel`（升级） | 411.12 → 672.74 | **451.12 → 712.74**（+40） | 261.62 |

  ⇒ 两块时也是 40.68、不重叠。

### 3. 🔴 为什么最终取 **40** 而不是 106（如实标注，⛔ 不冒充原版值）

用户同一条要求里还有「**三块面板的高度/顺序不变**」⇒ 三个高度之和 = **754.94**。
再塞两条 106 ⇒ 第三块底部 = `146.71 + 754.94 + 212` = **1113.65 > 1080**（出血到屏幕外）。

⇒ 取 **`PanelGap = 40f`**（`Shell/CardDetailPopup.cs:380`，注释里把这两路读数与这个折中都写死了）：
第三块底 983.01，离屏底 97 px，上下留白（146.71 / 97）接近。
⚠️ **这一档不是参考图那个数** —— 要做到参考图那档得先允许压面板高度（那是另一条用户口径，本笔不擅自改）。

### 4. 做法（为什么能只挪父节点）

新增 `ShiftPanelDown(p, y1, y2, dy)`（`:1954`）：`BuildCrafting/BuildUpgrade/BuildAltArt` 在**子件全部建完之后**
把面板根节点整体下移。本壳的件是**绝对设计坐标**建的（`MenuDraw.Local` 在建的那一刻就把
「绝对矩形 − 父节点位置」写进 `localPosition`）⇒ 子件相对位置已定死，**挪父节点 = 整块刚性平移**
（⛔ 不用逐个改 rect —— 那样要改十几处绝对 y，漏一处就是错位）。
尺寸 `y2−y1` 一个字节没动，只改中心。
