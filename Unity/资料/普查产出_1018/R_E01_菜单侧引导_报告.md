## 一、结论（三句）

1. **阶段链**：7 个 `FlowTutorialStage` 子类的**语义**全部从反编译方法体读死；**序列化顺序本地解不出**
   （`TutorialManager.stages` 与 `stageID/isFUTE` 全库 0 命中、`level0` 的 `MainTutorialManager` MB 没有 type tree），
   现按 4 条判据**推断**为
   `SelectArmy → GetMission → GetCampaignNode → PlayRanked → LevelUpCard → ClaimForgeFirstLevel → TutorialFinished`
   （已逐条标注「推断」）。
2. **指针映射**：`TutorialPointerMenu` = **菜单链全部 7 个阶段**（`TutorialManager.tutorialPointerMenu` 是
   `AddPointerAction` 唯一加载的 prefab）；`Wildcards` = `WildcardTutorialManager`；`Combat` = 战斗内；
   `Base` **未确证**（全库无序列化字段指向它）。
3. **状态机**：新建 `MenuTutorialFlow`（运行时挂载，`DontDestroyOnLoad` 以保住「排位观测」），实现原版
   `Initialize / DelayedPLayTutorial / Complete / TryForceComplete / WindowsChange` 的等价链；
   进度存 `PlayerPrefs`（原版是远端 profile，已 `Debug.Log` 出声标注）；可推进、可单阶段跳过、可整链跳过、可重置。

   且本轮不许新增 `.shader` ⇒ 用运行时生成的**反相径向遮罩** + `SetUvRect` 复刻同一份
   `_ViewportPoint/_UVScale` 数学；轮廓半径 (0.26,0.47) 是**目测近似**（原 PNG `isReadable:0`，读不出像素）。

   根因均是原判据在服务器或本仓对应状态恒真/恒假 —— 逐条写在阶段表与代码注释里。
5. `TutorialStageGetCampaignNode` 的方法名（`HasTwoNodesCompleted`）与官方文案（「first reward node」）
   /`MainTutorialState.CollectedCampaignFirstNode` **口径打架**；本实现按官方产品文案取「第一格」，
   `1<count` 的解释标**推断**。
