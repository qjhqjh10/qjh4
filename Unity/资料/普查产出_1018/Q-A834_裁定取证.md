## 2. `MenuDraw.Local` 读的是什么（算式逐句 · 父件被挪时怎么变）

### 2.1 逐句算式

`Shell/MenuDraw.cs:30-31`
```csharp
public static Vector3 Local(Transform parent, float x1, float y1, float x2, float y2)
    => LayoutSpace.RectCenter(x1, y1, x2, y2) - PosInDesignSpace(parent);
```

`Shell/MenuDraw.cs:71-79`（`PosInDesignSpace`，文件头自己写「全壳唯一一份」）
```csharp
if (t == null) return Vector3.zero;          // 无父 ⇒ 设计坐标就是世界坐标
var above = t.parent;
if (above == null) return t.position;        // 它就是根：链上没有任何缩放可除
var k = above.lossyScale;                    // 🔴 除的是【父件的父】那一级，不是节点自己的
return new Vector3(DivByScale(p.x,k.x), DivByScale(p.y,k.y), DivByScale(p.z,k.z));
```

两端的量纲（`Core/LayoutSpace.cs`）：
- `RectCenter(x1,y1,x2,y2)` = `FromPixel((x1+x2)/2,(y1+y2)/2)` = **世界坐标**（屏幕中心为原点；`FromPixel` `:157-158`）。
- `Px(px) = px / (1080/10) = px/108`（`:153-154`）· `ToPixel(world) = world×108 + (960,540)`（`:168-172`）。

⇒ 一句话：**`Local` = 「传进来的绝对矩形中心（设计 px → 世界）」 − 「父件【当下】的世界位置 ÷ 父件的父那一级的 `lossyScale`」**。

### 2.2 父件被挪动时这一项怎么变（本病的全部机理）

设抽屉行程 `Δ`（收起 = 左移 385px，`Shell/CollectionWindow.cs:314` `FltHiddenDx = -385f`）：

1. 父件（视口节点）被 `ApplyDrawerSlide` 挪到 `P₀ − Δ` 后（`Shell/CollectionWindow.cs:551-553`：只改 `localPosition.x`）。
2. `PosInDesignSpace(parent)` 随之少 `Δ` ⇒ `Local(...)` 算出的 `localPosition.x` **多 `Δ/108` 世界单位**。
3. 但**出生那一刻**子件的世界位 = `父件当下位置 + localPosition` = `RectCenter(r)`（`Δ` 被抵消） ⇒ **这一层建出来的每一件，落点只由「传进去那个 `PxRect`」决定、与任何节点实时 transform 无关**（这条正是 `Shell/ViewportClip.cs:37-48` 文件头那段「为什么基准位才是对的那一帧」的论证）。
4. 于是：**父件回到基准位之后**，这一版就**整批偏 `+Δ`** —— 这就是 ④（`Shell/CollectionWindow.cs:609-611`）要补的那一帧。

## 7. 候选裁法 3 个（⛔ 只报不选：形状 / 文件 / 改动面 / 风险 / 能不能被断言钉住）

### 候选甲 —— **建之前把抽屉摆回基准位**（复用 §6.2(a)/(b)/(c) 那条现成解法）

① **形状**：`RebuildFilterRowsNow` 在建之前把 `_flt.Node.localPosition` 临时摆回 `BasePos`（`HasBasePos == false` 时**什么都不用做** —— 那种情况节点本来就在基准位），建完照旧由它收尾那次 `ApplyDrawerSlide(_flt, _flt.Slide, true)`（`:1861`）按进度摆回去。等价于把 `DeckRuntime.DrawerHome` + `PrepareDrawerForBuild` 那两句搬过来（`Deck/DeckRuntime.cs:1602-1615`）。
② **要改哪些文件**：`Shell/CollectionWindow.cs` 一处（`RebuildFilterRowsNow` 头/尾）；若顺带把它与 `DeckRuntime` 的同名助手收成一份共用件，则多一个 `Shell/*` 或 `Deck/*` 的文件（⚠️ 收口 = 动共用件，见③）。
③ **改动面**：**只碰一个自检宿主类** ⇒ 按铁律 12 只跑 `CollectionScene.Run`（若顺手收口到共用件 ⇒ 先 `grep` 谁在用，再决定要不要加 `DeckScene.Run`）。
④ **风险 / 会不会静默**：**低**、不静默。
  · 好：`ApplyDrawerSlide` 与建树都在同一帧内同步跑完 ⇒ 临时摆位**不外泄**（Play 下也没有一帧渲染到它）；`MenuDraw.*` 的**不建/裁切**判据读的是**冻结的 `BaseRect`**（`ViewportClip.ClipPx` ①支）⇒ 临时挪节点**不会**改变「哪几件会被建出来」；`Label.AlignLeftOn` 那条读口**也一起被治好**（这正是 (a) 的原始理由）。

⑤ **能不能被断言钉住**：**能，而且能钉今天完全没被盯的那一类 —— 「过渡帧」**：
