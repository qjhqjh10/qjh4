## 二、第 8 条（方向）：**判定后停手，一个字没改**

### 2·1 结论

`Shell/MenuScroll.cs:274` 仍是 `Apply(Offset - dy * NotchK, !Elastic);`。

**理由**：把它改成 `+=` 不只是「对齐 uGUI」，它会**同时翻掉 N66（主菜单模式卡）的既有手感**，而 N66 正是派单给这 7 处定的「同手感」基准。派单里写好的停手条件（*「若你判断会翻掉 N66 的既有手感，先停手」*）成立 ⇒ 停手，把推导交主对话定。

### 2·2 事实前提（三条，都已现核）

**① 我们收到的 `dy` 是原始 `WHEEL_DELTA`：正 = 向上滚、负 = 向下滚。**

- `工具/wf_click.py:112`：`WHEEL_DELTA = 120  # Windows 一格滚轮 = 120（正数 = 向远离用户方向 = 向上滚）`；`:21` 的用法行也写着「正=向上滚、负=向下」。
- `Editor/MainMenuScene.cs:8941-8943`（纵向列表）：`WheelAt(…, -120f)` 的断言文案是「**往下滚一格** ⇒ 偏移往正走」，且紧跟一条「内容往上走的像素数 == 滚动偏移」⇒ 在项目自己的口径里 **−120 = 往下**。
- `Shell/MenuScroll.cs:266-267` 的注释同此（「往下滚（`dy<0`）」）。

**② 我们横向的 `Offset` 是「正 = 内容左移 = 看靠后的项」**：`MenuScroll.cs:404-409` 的 `Shift`（横向 `x1 − Offset`），`:150-151` 的字段注释；而 `:274` 收 `dy` 原始值。

**③ uGUI 原版（`Library/PackageCache/com.unity.ugui@27635d171b1a/Runtime/UGUI/UI/Core/ScrollRect.cs`）：**

```csharp
Vector2 delta = data.scrollDelta;
delta.y *= -1;                          // :656-658
if (horizontal && !vertical)            // :665-670
    if (Mathf.Abs(delta.y) > Mathf.Abs(delta.x)) delta.x = delta.y;
Vector2 position = m_Content.anchoredPosition;
position += delta * m_ScrollSensitivity; // :675-676
```

### 2·3 推导（两条路，结论相反）

**标定点 = uGUI 纵向的通用观感**（人人可验）：横向-only / 纵向-only 的分支都是「把 y 搬到 x（或反过来）」，所以只要纵向的方向定死，横向的符号就跟着定死。

- **纵向**：往下滚 ⇒ `scrollDelta.y = −1`（前提①：`scrollDelta` 与 `Input.mouseScrollDelta` 同号，`PointerInputModule.cs:293` 就是 `leftData.scrollDelta = input.mouseScrollDelta`）⇒ 过 `:658` 变 `+1` ⇒ `anchoredPosition.y += 1` ⇒ 顶对齐内容**往上走** ⇒ 露出下面的内容 ✔（= 所有人对 uGUI 的认知）。
  ⇒ **反推坐实：`scrollDelta` 是「上正」**（若按 `:657` 那句注释「Down is positive」算，往下滚会变成「内容往下走 = 露出上面的内容」，与人人可验的观感相反 ⇒ 那句注释不能当符号判据）。
- **横向**：往下滚 ⇒ 同上 `delta.x = +1` ⇒ `anchoredPosition.x += 1` ⇒ **内容右移 ⇒ 露出左边（靠前）的项**。
- **我们**：`Offset = −anchoredPosition.x` ⇒ uGUI 的 `position += delta` 折到我们这套字段上就是 `Offset += dy`（不是 `−=`）⇒ **W13 §5·2 给的公式是对的**。
  ⇒ 但落地后的观感是：往下滚 ⇒ 内容右移 ⇒ **露出靠前的项**（与 uGUI 一致，与我们现在的观感相反）。

### 2·4 两条路各自的代价

| | 现在（`Offset -= dy`） | 改成 `Offset += dy` |
|---|---|---|
| 往下滚一格 | 内容**左**移 ⇒ 看**靠后**的项 | 内容**右**移 ⇒ 看**靠前**的项 |
| 与 uGUI 一致 | ❌（是它的镜像） | ✅ |
| N66 主菜单模式卡 | 保持用户已经用过的手感 | **翻向** |
| 派单里写的验收方向（「滚轮向下应让内容向右露出 = 看到靠后的项」） | ✅ 满足 | ❌ 不满足 |
| 与纵向列表的直觉一致性 | ✅（往下 = 往后翻） | ❌（横向往下 = 往前翻） |

**N66 为什么一定被翻**：`Shell/MainMenuRuntime.cs:2200-2203` —— `_modeScroll = new MenuScroll(ModeViewport, CardCol0, ModeContentX2, 120f); … PointerLayer.RegisterScroll(_modeScroll);`，它和这 7 处走的是**同一个** `MenuScroll.Wheel`（`PointerLayer.Update ③` → `WheelAt` → `s.Wheel(dy)`），没有第二条路。

⚠️ 另外订正 W13 一处：§5·2 那段括号里写「**原版：下滚滚轮 = 内容左移 = 往右看 / 我们现在：下滚 = 内容右移 = 往左看**」—— 这两句与它自己给的公式（`Offset += dy`）**互相矛盾**，按 §2·3 的推导，**原版是「下滚 = 内容右移 = 往左看」，我们现在才是「下滚 = 内容左移 = 往右看」**。公式对、括号里的描述反了。

### 2·5 主对话决定后要改的只有两处（一处 1 行 + 一处 1 个符号）

若要**改成与 uGUI 逐位一致**：

1. `Shell/MenuScroll.cs:274`：
   `Apply(Offset - dy * NotchK, !Elastic);` → `Apply(Offset + (Vertical ? -dy : dy) * NotchK, !Elastic);`（纵向保持原样）
2. `Shell/PointerLayer.cs` 新增那条私有重载里的 `f = -sc.x;` → `f = +sc.x;`（见 §三，两处是同一个口径，必须同步）

若要**保持现状（= 与验收方向、N66 一致）**：两处都不动（= 本件的现状）。

## 三、第 9 条（触控板横向分量）：**已改，且只对横向滚动区生效**

### 3·1 改法

1. `Shell/PointerLayer.cs:390-401`（`Update` 的 ③ 滚轮分支，`Vector2 sc` 在 `:397`）：原来只读 `.y`，现在取整个 `Vector2`：

```csharp
Vector2 sc = mouse.scroll.ReadValue();
if (Mathf.Abs(sc.y) >= 1f || Mathf.Abs(sc.x) >= 1f)
    if (WheelAt(px.x, px.y, sc)) scrollMoved = true;
```

2. `Shell/PointerLayer.cs:1186-1205`：新增一条**私有**重载 `bool WheelAt(float px, float py, Vector2 sc)`（声明在 `:1198`；公开的三参 `WheelAt(px,py,dy)` 一个字没动 ⇒ `Editor/*Scene.cs` 那些自检调用点零影响）：

```csharp
float f = sc.y;
if (!s.Vertical && Mathf.Abs(sc.x) >= Mathf.Abs(sc.y)) f = -sc.x;
if (Mathf.Abs(f) < 1f) return false;
s.Wheel(f);
```

- 判据 = uGUI 横向-only 那支（`ScrollRect.cs:665-670`）「`|dx|` 不小于 `|dy|` 时用原始 `dx`」（uGUI 原话是反过来的写法：只有 `|delta.y| > |delta.x|` 时才把 y 搬到 x）。
- **符号 `-sc.x`**：按 §2·4 的「现状 = uGUI 的镜像」推出来的 —— uGUI 横向给 `ΔOffset = −delta.x = −sc.x`，镜像后我们给 `+sc.x`，而 `Wheel` 是 `Offset − f` ⇒ `f = −sc.x`。
- ⚠️ **它和 §2·5 第 2 条是同一个符号**：若主对话决定把 `Wheel` 改成 uGUI 原式，这里必须同步改成 `+sc.x`。代码注释里已写死这一句。

### 3·2 为什么这样写不算「牵动纵向」

- `!s.Vertical` 门挡住了纵向区：纵向列表仍然**只**用 `sc.y`，行为与改前**逐位相同**。
- 普通鼠标滚轮 `sc.x` 恒 0 ⇒ 全部 12 条现有自检（都喂单个标量给公开三参重载）**零影响**。
