## 〇 一句话结论

**换档本来是好的**：真机那两张「升级前 / 升级后」截图里，大卡卡框**确实从 tier1 换成了 tier2**
（tier2 独有的青绿宝石出现在卡框左右栏上）。
真正坏的是**两条误导性证据**：

1. `[CardView.Build] …（无卡框，走占位路径）` 这句把「图加载**计时** = 0 ms」当成了「**没有卡框**」；
2. 被当成「升级后」的 `04_after_upgrade.png` 与升级前的 `03_carddetail.png` **逐字节相同**（md5 一样）
   —— 那是一张**没拍到变化的废片**；真变化在 `05_after_upgrade.png` 里。

⇒ 本轮**不需要改卡框逻辑**（它是对的），只把那条错日志**改准**，并把 `frameTex.name / tier / 阵营 / 稀有度 / 兵种`
一起印出来（这就是「升级换框」那条链的唯一真值）。

## 三 那条误导日志：根因与修法

### 3·1 根因

老代码（`Core/CardView.cs`，改前 `:2322-2331`）：

```csharp
if (bt) {
    long end = _buildWatch.ElapsedMilliseconds;
    if (m0 > 0)  Debug.Log("… 图加载 {m0} · FrameMesh …");
    else         Debug.Log("…（无卡框，走占位路径）");   // ← 判据错：m0 是【计时】，不是「有没有框」
}
```

`m0` 只在 `if (frameTex != null)` 那一支里赋 `_buildWatch.ElapsedMilliseconds`（`:2090`）
⇒ **贴图全命中缓存时它就是 0 ms**。真机实证（`Player.log`）：

- `:343`（收藏页首建，第一次真加载）→ `ASH83 总 40 ms · 图加载 4 · FrameMesh 11 …`（有框）；
- `:371`（开详情窗，全部缓存命中）→ `ASH83 总 0 ms（无卡框，走占位路径）` ← **假的**；
- `:380`（升级后重建）→ `ASH83 总 2 ms（无卡框，走占位路径）` ← **假的**。

同一份日志里还有 10 张**同阵营同类型**的卡（`ASH63/62/22/4/69/79/6/17/11/70`）也打「无卡框」，而同批另外 8 张打正常格式 ——
它们全部 `faction = SaimHann / type = unit`（逐张查过 `cards_engine.json`）⇒ **区别只在计时是否恰好跨过 1 ms**，
不是框的有无。这条错日志正是「框丢了」那条错判的源头。

### 3·2 改法（已落地）

`Core/CardView.cs:2321-2342`：

```csharp
if (bt) {
    long end = _buildWatch.ElapsedMilliseconds;
    string frame = frameTex == null
        ? "无卡框，走占位路径"
        : $"卡框 {frameTex.name} · tier{frameTier}"
          + $"（{d.faction}/{d.rarity}/{(d.isUnit ? "unit" : "tactic")}）";
    Debug.Log($"[CardView.Build] {id} 总 {end} ms · {frame} · 图加载 {m0} · FrameMesh {m1 - m0} · "
            + $"其他建层 {m2 - m1} · rim {m3 - m2} · 文字 {m4 - m3} · 收尾 {end - m4}");
}
```

- 判据换成 **`frameTex != null`**（真正的「有没有框」）；
- `m0 == 0`（快）不再被当成「没框」；
- 顺带印 **`frameTex.name` / `frameTier` / 阵营 / 稀有度 / unit|tactic** —— 下一轮真机一眼就能看出
  「tier2 要的是 `frame_saimhann_tier2`，实际拿到的是不是它（**回落**时这里会显示 `…_tier1`）」；
- ⚠️ **`m0` / `m1..m4` 的计时语义一个字没动**（仍是 `_buildWatch.ElapsedMilliseconds` 的原点）。

改后预期日志（同一处）：

```
[CardView.Build] ASH83 总 2 ms · 卡框 frame_saimhann_tier2 · tier2（SaimHann/common/unit） · 图加载 0 · FrameMesh 0 · …
```

## 五 没查清 / 留给人看的两条

1. **真机复验（改完日志之后）没做** —— 红线不让跑 Unity/`*.Run`，player 由主对话起。
   下一轮只要看 `[CardView.Build] ASH83 … 卡框 frame_saimhann_tier2 · tier2 …` 这一行就能一次确认
   （若那里出现 `frame_saimhann_tier1` 而 tier 是 2，才是「回落」真缺陷）。
2. **`SetData` 不刷新卡框层**（`Core/CardView.cs:1375` 起：它只换 `_face/_art/_artFront/_info` 的贴图，**不碰 `_frame`**）。
   今天**踩不到**：详情窗换档走的是 `RebuildKeepingState()` → 整窗 `Build()`，卡是新建的。
   但这是**结构性隐患**：以后若有人「只 `SetData` 不重建」地改等级，卡框会静默停在旧档。
   ⇒ 这次**没动它**（不在本次故障链上、且会牵动每次棋盘刷新），只记在这里。
3. **收藏窗卡格**是否跟着换档没查：`CollectionWindow.OpenCardDetail` 之后**没有**「关窗回刷卡格」的钩子
   （`Shell/CollectionWindow.cs:3886-3906` 只负责开窗）。所以升级后关掉详情窗，**后面那一格格子大概率还是旧档**，
   要切页/重开收藏才刷新。属于「卡片详情窗之外」，本轮未改。
