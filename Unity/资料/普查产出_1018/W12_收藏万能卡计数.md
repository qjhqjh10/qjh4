## 一 · 图标为什么消失（根因 + 证据）

### 1.1 收藏窗那一排是**好的**（先排除）

`d:/4/_tmp_view/shots/2026-10-18_卡组选择弹窗_第四轮/02_cards_tab.png`（2560×1440）右上角放大 4×：
4 个图标（蓝/绿/紫/橙）各自在 `99` 前面，**一张不少**。像素量出来的底板范围 = 设计坐标 **1550.3 → 1869.0**，

实拍裁片：`d:/4/_tmp_view/_wc_crop.png`。

### 1.2 详情窗那一排：图标被自己的底板盖住

`Shell/CardDetailPopup.cs:1569-1580`（`BuildWildcards`）：

```

1572                    new PxRect(WcBgL, WcBgT, WcBgR, WcBgB), "Wildcard Bg", QCdRow);   // ← 底板 3116
```

`QCdRow = 3116`、`QCdText = 3117`（`Shell/CardDetailPopup.cs:331-332`）。

- 本仓**没有 uGUI**，每个 quad 都躺在**同一个设计平面 z=0**，而**同队列 = 按到相机的 3D 距离排、顺序不可靠**
  —— 这条在**同一个文件**里已经有先例与结论：`Shell/CardDetailPopup.cs:1288-1295`
  （`Art Style Logo` 就是因为「整块落在 `QCdRow` 的底板之内」而**显式抬到 `QCdText(3117)`**）。
- 数字（`Wildcard Count i`）走 `QCdText(3117)` ⇒ **数字活着**；图标走 `QCdRow(3116)` ⇒ **被同层的底板吃掉**。
  实拍完全符合这个推论：`05_after_upgrade.png` 里 4 个 `99` 在、4 个图标不在，底板在。
- `ImageQuad` 是**每个 quad 一份材质**（`Battle/ImageQuad.cs:135`），所以队列是**逐件**生效的，
  「同队列互相盖」不是共用材质造成的假象。
- **节点也建出来了**：自检场景存盘 `_tmp_view/scene_bak/CollectionCheck.unity` 里 `m_Name: Wildcard Icon 0`
  出现 **3 次**（收藏页 / 详情窗 / 另一处同款）⇒ **不是「没建」，是「建了被盖住」**。
- **不是图丢了**：`Resources/Art/ui_deck/40k_general_wildcard_{common,rare,epic,legendary}_small.png` 四张都在
  （42×51 / 41×51），`Player.log` 里 **没有任何**「图取不到 / wildcard」告警
  （`C:/Users/qjh36/AppData/LocalLow/Unity Technologies/com.unity.template.urp-blank/Player.log` 只有两行 `[Collection]` 开窗日志）。
  所以**不是路径/图名/后缀问题，是分层问题**。

### 1.3 为什么「点开一张牌」才没有

收藏窗自己那排走 `QPagePanel(3030) < QPageRow(3032) < QPageText(3033)`
（`Shell/CollectionWindow.cs:135-136`）⇒ **底板 < 图标 < 数字，梯队是对的**。
卡片详情窗是**另建一份同款条**（`Shell/CardDetailPopup.cs`），它整条压在收藏窗之上（3116 > 3033），
而它自己的图标和底板又在同一层 ⇒ 一点牌，用户看到的就是**详情窗这份坏的**。

### 2.2 回答用户第 2 问：图标 = **稀有度**，不是阵营

- 4 个 `Icon` 的 `m_Sprite` 是 **common / rare / epic / legendary 四档万能卡**（上表实读），
  **与阵营无关**、**与点开哪张卡无关** —— 它永远是这四张。
- **阵营 = 左边那颗 `Army Icon`**（80×85，出厂 `40k_DeckSelection_icon_FactionBlackLegion`）。
  运行期它会被换：`WildcardDisplay.Initialize(army)` → `ArmyUtilities.GetArmyIcon(army)`
  （收藏页：`CardCollectionDisplay.CheckFocusedArmy` 拿**指针压到的那张卡**的 `cardArmy`；
  卡组编辑窗：`DeckEditingWindow.FilterToDeck` 拿**这副卡组的 `deckArmy`**）。
- 跟着阵营变的**还有那 4 个数字**（`WildcardDisplay` 是**该阵营的**万能卡库存直出），
  **不是**跟着卡换图标。
- 我们的落地：详情窗 `Army Icon` 已经跟着 `Card.Faction` 换（`05` 里是 Dark Angels 徽记 ✔）；
  收藏页**恒为出厂 BlackLegion**（没有 hover，已如实记在 `Shell/CollectionWindow.cs:931-944` 的注释里）。
  4 个数字：详情窗 **2026-10-18 已改读真库存**（`CardProgress.Wildcards`），收藏窗/卡组编辑仍是恒定 `99`（用户 2026-09-28 拍板）—— 两处口径现在**不一致**，见 §五。

### 2.3 回答用户第 3 问：数字外面**没有**单独方框

- `Counter` 节点上**只有 `TextMeshProUGUI`**（prefab 现读，无 Image / 无描边）⇒
  **原版数字外面没有独立方框/药丸/描边**，唯一的「方框」是那**一条共用的 `Background`**
  （320×44、九宫 15、灰 0.462 的半透明圆角条）。
- 尺寸：底板 **320×44**（不是整条 400×85）· 4 组各 65×44 · 图标 30×44 框（实绘 30×36.4）· 数字框 41×44。
- 参考图验收（`C:/Users/qjh36/Desktop/warpforge参考图/点击卡片查看详情的参考.png` 右上角放大）：
  一条圆角灰条，4 张倾斜小卡 + 数字 `6 5 10 3`，**确实没有单格方框** —— 与 prefab 一致。
- 我们的收藏窗：**与 prefab 逐项相同**（并排图 `d:/4/_tmp_view/_wc_cmp_ref_vs_ours.png`，上=原版参考、下=我们）。
  我们的详情窗：底板被 `Rect`（Simple）拉成**一条亮白弧**（两端被拉长成一撇），这就是用户说的「不是方框」。
