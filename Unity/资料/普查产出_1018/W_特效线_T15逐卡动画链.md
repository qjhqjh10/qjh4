1. **① 27/27 补齐，且不是「补 27 条」那么简单**：根因是 `anim_address_map` 的生成器**只枚举束的
   `m_Container`**，而 EC（帝皇之子）的 cardassets / cardanims 两个束的容器键是**短 internalId**
   （`bc` / `0d7` / `eac` …），不是 GUID ⇒ 这些资产在正向表里**没有 GUID 身份**。
   补上 Addressables catalog 的「GUID → (束, internalId)」这一跳后，**27/27 全链可验**

3. **③ 生成物只增不减**：`anim_address_map` **+183 个 GUID、0 删**；`card_vfx_by_card` 两档

### 1·3 实现（`工具/gen_anim_address_map.py`）

| 位置 | 做什么 |
|---|---|
| `:78` `CATALOG_JSON_CANDIDATES` | Addressables `catalog_main.json` 的两个候选路径（用户 LocalLow 优先，`d:/2` 兜底） |
| `:162` `decode_catalog_json` | 解 catalog 的 `m_KeyDataString` / `m_EntryDataString` / `m_BucketDataString`（格式同 `_guid_resolve_probe.py:56-79`） |
| `:200` `load_catalog_internal_ids` | **只取依赖桶里的第一束**（= 资产主束）建 `{(束, internalId): (GUID, 类名)}`；同键两 GUID ⇒ 记歧义不升级 |
| `:291` `load_old_guid_map` | 读旧表（只用于**校验**，不参与 join） |
| `:320` `type_compatible` | catalog 类名 ↔ 束里对象类型的相容判断（`Sprite`/`Texture2D` 互认；具体 MB 子类 = `MonoBehaviour`） |
| `:795` 主流程升级块 | 三条闸门（旧表 `exact=True` + 名字逐字 / 非旧表条目按类型 / 歧义跳过）后追加合成容器项 |

**安全闸为什么必须有**（这是本轮挖出来的第二个坑，差点静默写错 23 条）：
catalog 里有一族 GUID 的 `internalId` 是**被截断的键**（旧表 `exact=False`，31 行）。
直接拿 catalog 的 `internalId` 去束里取，**31/31 全取到别的对象**（例：`db92a11e…` 是
`CSM_EmperorsChildren_inf_Dual Screamer Kakophonist`（Texture2D），catalog 的 iid 是 `d`，
束里 `d` 指向 `VO_CSM_EC_Lucius_vsAstraMilitarum`（AudioClip））。
⇒ 升级条件写死为：**旧表有 ⇒ 必须 `exact=True` 且资产名逐字相同；旧表没有 ⇒ 类型必须相容**。
实测：**117 条旧表 `exact=True` 全部名字逐字相同、31 条 `exact=False` 全部被挡**；
另 6 条非旧表条目因类型不符被挡；最终**升级 245 条**。
