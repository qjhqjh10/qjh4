## 3. 根因分析

### R1：批处理里没有帧循环 ⇒ `waitForTip` 的提示永远不消 ⇒ 脚本从第 0 条起就停住

**① 它怎么让这一串一起红**

S1 第 1 回合的数据（`RuleEngine/Resources/tutorial_stages.json` 的 `stages[0].turns[0]`，逐条 dump 过）：

| index | type | `playerAction` | `waitForTip` | `tipDuration` | data[0] |
|---|---|---|---|---|---|
| 0 | **SmallTip** | false | **true** | **50.0** | SmallTip(80) |
| 1 | AttackFreeMode | true | false | 0 | AttackFreeMode: PlayerWarlord→AiWarlord |
| 2 | **SmallTip** | false | **true** | **50.0** | SmallTip(80) |
| 3 | **SmallTip** | false | **true** | **50.0** | SmallTip(80) |
| 4 | EndTurn | true | false | 6.0 | EndTurn(100) |

执行链：`StepTutorialScript → TutorialScript.PlayScriptedTurn → ExecuteAction → Executed 事件 → OnTutorialScriptExecuted → ApplyTutorialActionView`（`BattleDriver.cs:8280+`）—— 遇到 `SmallTip` 且 `tp.waitForTip` 为真就 `_tutTipUp = true`（`BattleDriver.cs:8307-8316`）。
**紧接着下一次** `DriveTutorialScript()` 在 `BattleDriver.cs:8649` 早退成 `Advanced`，**指针一动不动**。

而 `_tutTipUp` 只能由 `DismissTutorialTip`（`BattleDriver.cs:8124`）清；它的两个调用口：
- `TickTutorialView(dt)` 的到点自动消（`:8422-8427`）—— **只由 `Update` 喂 dt**（`:6580`），**批处理下 `Update` 不跑**；
- `HandleTutorialTipDismiss()`（输入链、`:6372`）—— 批处理里没有真鼠标。

⇒ 在批处理里 `_tutTipUp` **一旦为真就再也不会变假**。这就是「成串」的机制：**一个位（`_tutTipUp`）决定红绿**（正是 `资料/已知的坑.md` #14 那个形状）。

三处出事的夹具段都**直接推真实 S1 数据**，且**一次都没消提示**（全仓只有 `⑯-③` 那个**合成**关卡段用过 `DismissTutorialTipForTest`：`BattleScene.cs:14955/14963/14978`；另外 `14666/14668` 那两次 `TickTutorialViewForTest` 喂的是 0.1s/1.0s，离 `tipDuration=50s` 差得远）：

- **⑧** `14246 driver.BeginTutorial(0)` → `14257` 驱动（执行 `[0] SmallTip`，提示挂起）→ **此后整段停摆**。
- **⑬** `14547 BeginTutorial(0)` → `14551` 同上。
- **⑭⑥⑦** `14661 BeginTutorial(0)` → `14676` 驱动（提示挂起）→ `14691` 起全停。
