## 二、K10：`Unity/工具/check_new_card.py`

### 2·1 用法

```bash
python -I -X utf8 d:/4/Unity/工具/check_new_card.py --card <卡片.json>
python -I -X utf8 d:/4/Unity/工具/check_new_card.py --card <卡片.jsonl|{cards:[…]}> --out <报告.json>
python -I -X utf8 d:/4/Unity/工具/check_new_card.py --list-checks
```

- **吃三种形态**（按字段别名识别，可混合）：原版 SO（`uniqueId/cardArmy/manaCost/…`）·
  我们卡池（`id/faction/type/cost/attack/…`）· `card_stats`（`ranged_attack/armor/…`）。
- 输出**分「错误 / 警告 / 通过」三档，每条带 `出处:`**；**「跳过」也出声**（归在警告档、前缀 `[跳过]`，
  并写明为什么跳过——没提供字段，还是判据索引没覆盖）。
- 退出码：`0` 无错误（允许警告）/ `1` 至少一条错误 / `2` 工具跑不起来。
- `--out` **只在没有错误时写**；有错误时明确打印「不写产物」。

   实测 `564af14f…`（`EC Heldrake Attack`，`customRangedAttackParticles` 用的那条）**不在**该索引里

## 五、顺手发现（⛔ 没改，交给调度台分流）

1. **同一个字段的 GUID 解出来的资产类型不唯一**：`cardImageReference` 在 `EC29` 解成 **Texture2D**、
   在 `BL27` 解成 **Sprite**（`guid_map_bundles.tsv` 的 `type` 列）。K10 两种都接受。
   若下游导入工具（`import_original_art.py`）假定只有一种，需要它自己确认——本轮没动它。
2. **原版 allcards 里 2 张卡一个非空 GUID 都没有**：`202fb454856a2b04d904c4ff7bc2410f`、
   `7552fe029df141946b0f813e28bfac98`。新卡校验器对空引用只报警告，不是错误（合法但少见）。
3. **`card_stats.json` 有 1,213 行，其中不少 `id: null` / `armor: null`**（第一行 `Autarch` 就是 `id: null`）。
   这类行喂给 K10 会红（缺 id / 缺护甲）——如果它们将来要变成正式卡，**先补 id 与数值**。
4. **`m_Script` pathID 直方图**（对以后读同类包有用）：
   `8864902669260471755` × 1351（RawCardScript）· `-3368977909917641325` × 7（AlternateArtCard）·
   `-5832762458676164525` × 1（AddressablesBuildNumber）。
5. **`guid_map_bundles.tsv` 共 6,173 行 / 6,140 个不同 GUID / 31 行 `exact=False`**。
   K10 对 `exact=False` 只给警告（按「解得出但容器键不完全匹配」处理）。
6. **旧脚本的产物路径**：`_tmp_view/_allcards_extract.py` 直接把 `cards_raw.json` / `cards.tsv`
   写进 `资料/普查产出_1018/allcards_1350/`。新工具**默认写 `_tmp_view/allcards_export/`**，
   就是为了避免「导出把对账基准覆盖掉」——这一点建议保留，⛔ 别把默认 `--out` 改回 `资料/`。
7. **环境事实**：UnityPy **1.25.3 + Python 3.14** 能直接读这个包（`read_typetree()` 0 异常）；
   与 `报告.md` 里的 1.24.2 / Python 3.12 结果一致。两个解释器都能跑，
   工具本身不写死解释器路径。
