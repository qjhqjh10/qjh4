## 〇、结论

原版 prefab 里 **inactive（不画）** 的是 `Background Mask` → 子 `Planer Name Background` 那一支
（出厂 `m_IsActive = False`；子节点自己写 True、但**父关** ⇒ 整支**一个像素都不画**）。

而**实拍里真正画出来的那块板，是【另一个节点】** —— `Background`（sprite `40k_main_player frame`
的**上沿横带**）；板上的**文字**是**再一个节点** `Player Name`（活的）。

⇒ 三者是**三个不同的节点**，「实拍里有块板」与「prefab 里那一支是关的」**并不矛盾** ——
当年把它读成矛盾，是因为**按名字认了节点**（都带 `Background` 字样），没去解父链、没看 `activeInHierarchy`。

| 节点 | `m_IsActive` / `activeInHierarchy` | 画不画 | sprite |
|---|---|---|---|
| `… /Player Profile` → `Background` | **True / True** | ✅ **画** —— 实拍里那块暖褐板就是它 | `40k_main_player frame`（388×124） |
| `… /Player Profile` → `Background Mask` | **False / False** | ⛔ 不画（自己就是关的） | —（无 `m_Sprite`） |
| `└ …/Background Mask` → `Planer Name Background` | True / **False** | ⛔ 不画（自活、**父关**） | `40k_topmarquee_currency_display BW`（44×39） |
| `… /Player Profile` → `Player Name` | **True / True** | ✅ 画 —— 名字文字层 | TXT |
| `… /Player Profile` → `Profile border` | **False / False** | ⛔ 不画 | `Player Profile Border` |

## 二、反证（为什么**不是** `Planer Name Background` 画的）

`Planer Name Background` 的 sprite 是 `40k_topmarquee_currency_display BW`。
我本轮实测它是 **44×39、均值 (126,126,126)、`max−min = 0`** —— **完全中性灰**（名字里的 `BW` 就是黑白）。
中性灰 **× 紫 tint** ⇒ 画面应是 **紫**（原始普查记的期望值 = **(47,23,37)**），
而实拍那块板是**暖褐 (37,28,22)** ⇒ **颜色族都对不上**。

再叠一条：那一支的**父链是关的**（① 的 `True / False`），**根本轮不到它上屏**。
⇒ 两条独立理由同时否掉它。
