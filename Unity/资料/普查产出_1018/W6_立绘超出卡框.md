## 1. 选了 A 还是 B、为什么

**选 A**：大图档启用**已有的** `_artFront` 层（同一张立绘、**真 alpha**、z = −0.008，盖在卡框之上），
不进 B（给卡框做 alpha 挖洞）。

理由（都写进了 `Core/CardView.cs:5890-5913` 那一段）：

| | A：`_artFront` 前景抠图层 | B：卡框 alpha 挖洞（等价原版 `FlipAlphaMask`） |
|---|---|---|
| 现状 | **层、材质、z、队列、着色都已接好**，只是被 `UseFrontLayer=false` 关着 | 2026-10-10 那条 `FrameCutout` 支路**从没人渲图看过就删了**，且 shader 与 SoftMask 的翻转语义**都没在实况里验过** |
| 立绘前提 | 立绘是抠图（84.4% 像素 alpha=0）⇒ 真 alpha 只会把**角色轮廓**压到框上 | 要自己写 shader 采 `uv2` 对齐立绘 alpha，多一层自造件 |
| 偏差 | 半透明像素处是「立绘半透明地压在框上」（不是「框被部分抠掉」）—— 逐像素差在边框，肉眼同一件事（**如实标注**） | 理论上更贴原版，但**没实况验过**（原版已关服，这一处进不去） |

### 三组最终数值（卡单位；卡本体 = `2.0927 × 3.3313`，`s = 1`）

| 层 | 原版 rect | 我们的板（放大前） | 大图档（×1.27） | 收边后画出来的网格 / UV |
|---|---|---|---|---|
| **立绘** | `2.7484² @ y=−0.044` | `1.8730 × 2.8583 @ −0.044`（= 2.7484² 里按 sprite 比例 fit，再 ×`ArtCoverMargin`1.04） | `2.3787 × 3.6301 @ −0.044` | **`2.0927 × 3.3313`（整块卡体）**、`u[0.0601, 0.9399]`、`v[0.0533, 0.9710]`、cy = **0** |
| **卡框** | `2.2452 × 3.2572 @ y=−0.030` | 同上（**没动**） | 同上（**框不动**） | 按 sprite 实宽 fit：`2.1159 × 3.2572 @ −0.030`（2026-09-12 量出来的值，保持原样） |
| **收边** | 卡体矩形 | `2.0927 × 3.3313` | 同一块 | 立绘先被卡体矩形裁、再压框 |

> ⚠️ 卡框**没有**改成照字面 `2.2452` 拉满：那张 PNG 左右各约 18% 是透明留白，直接拉满会把
> 金属横向撑宽 6%（`CardView.cs:5970-5977` 有实测判据）；`2.2452 × 3.2572 @ −0.030` 是它的 **rect**，
> 我们用它当「外框」、按 sprite 实宽 fit ——这是 2026-09-12 就定下的值，本轮**不动**。

### 收边那段为什么要重写（`:5560-5595`）

旧写法横竖各一套，竖的那套在「上下都要裁」时用**改过之后的** `cy` 去算 `v1` ⇒ UV 错 ~0.016（画面整体下移）。
小卡永远触发不到（立绘板最高 2.858 < 卡高 3.3313），**×1.27 之后 h=3.63 > 3.33 就会触发**。
现在统一成「先把板夹进卡体矩形、再由两条边的**原始**位置反算 UV」；对没放大的卡**结果与旧写法逐位一致**
（只裁宽那一路算出来同一个数：`u0 = 0.1338`）。

## 3. 1.27× 怎么落的

- **只乘立绘**（`_art` 与 `_artFront` 共用同一块网格），**卡框不动** —— 判据 = 原版 `CardImageController.ChangeState`
  状态 1 的 `bigSizeMultiplier`（`R_卡片详情大图三问.md` §二）。
- 乘在 `ArtCoverMargin` **之后**、**收边之前**（`ArtBoard` 里），等价于「把 `CardImage` 那个 RectTransform
  绕中心放大 1.27」；**中心 y = −0.044 不动**。
- **与卡体收边的冲突**：放大后 `2.3787 × 3.6301` 比卡体 `2.0927 × 3.3313` 大 ⇒ **裁掉**（左右各 0.143、
  下 0.193 / 上 0.105）。取舍 = **以「不穿帮」为先，绝不画到卡体外面**（原版也是「卡体矩形收边」）；
  代价 = 立绘四边各被裁掉一点（`u 6% / v 5.3%` 与 `v 2.9%`）。
- 开关 `BigCardOverdraw = false` 会**同时**关掉放大与前景层（一键回到 2026-10-18 之前）。

## 4. 怎么保证小卡档零影响

`_bigImage` 只在 `Create` 里判一次（`:880`），两支成立其一（`:888-904`）：

1. `use == CardUse.ZoomWindow` —— **全仓只有战斗详情窗**（`Battle/CardDisplayWindow.cs:1092`）传它；
2. 卡名是原版扇形槽名 `CardUI` / `CardUI (n)`（判据 = `Core/CardFan.SlotName`）**且父链上有一级叫
   `Card Display`** —— 菜单详情窗（`Shell/CardDetailPopup.cs:766`）走这条（它不传 `use`）。

**为什么要有第 2 条的两级条件**：抽卡包那扇窗也把自己的卡格命名成 `CardUI`
（`Shell/BoosterPackOpenWindow.cs:607`），但它挂在 `Booster Animation Parent/Cards` 下、**没有 `Card Display`
祖先** ⇒ 不会被误判。开包那张卡 scale ≈ 1.24（445 px 高），本来就不该吃详情窗的效果。

**小卡一栏**（全是 `Standard` 档、名字也不匹配 ⇒ 判据直接 return false）：
手牌 `Hand_*` · 场上 `MyUnit_/FoeUnit_` · 卡池 `pool_*` · 收藏 `CollectionCard_*` / `CollectionAltArt_*` ·
多卡窗 `mcd_card*` · 日志悬停 `LogHoverCard` · 选牌/换牌/进攻卡那些 `*_*` 名字。
⇒ 它们的 `artScale = 1f`（网格与改动前**逐位相同**）、`_artFront` **不建**（`UseFrontLayer` 仍是 `false`）。

另外：`UseFrontLayer` 保持 `false`（`Editor/CardBaseDemo.cs:500` 那条「出厂 false」断言**照旧绿**），
新效果走**另一个**开关，两条互不影响。

## 5. 没查清 / 已知偏离 / typecheck

### 没查清（原版关服，这一档进不去实况）

1. **原版状态 1 除了 ×1.27 还会不会动位置**：`ChangeState` 里同时有 re-parent
   （`CardImageController__ChangeState.c` 的 `DoChange` 一路）—— **re-parent 到哪个父、有没有额外偏移读不出来**
   ⇒ 我们只做了「绕中心放大」，位置沿用原来的 `y = −0.044`。要证伪得等远端数据或实拍。
2. **半透明像素处的合成差异**（A 与 SoftMask 不等价，见 §1）—— 未做像素级比对（要求并排渲图，本轮不跑 Unity）。
3. **非抠图卡（战术卡那种满幅方图）**：原版在状态 1 也开 `frameMask`，我们的近似（在框上重画）会把整块框盖死
   ⇒ 这种卡**不建前景层**（只吃 ×1.27 放大）。`cut` 清单 = `card_cutouts.json`（判据在 `CardArt.HasCutout`）。
4. **原版立绘 rect 是 `m_PreserveAspect = 0`（拉成 2.7484² 方形）**，我们仍按 sprite 比例 fit 进方形
   （2026-09-12 的既有决定，避免 1.53× 横向变形）⇒ 大图档我们横向**裁得比原版少**（原版裁 30%/边、我们 12%/边）。
   本轮**没有**动这条。

### 已知偏离（明写，不隐瞒）

- 原版 `useOverDraw` / `CardDisplayWindow.CardOverdrawHandle` 是**逐卡** opt-in 且**只对前台 index 0** 生效；
  我们的大图档是**整叠扇形（槽 0–8）一起开**。理由：`SlotViews` 的换位逻辑在
  `Shell/CardDetailPopup.cs`（本轮不许改）与 `Core/CardFan.cs`（不在白名单），没有「前台变了」的钩子可挂。
  影响：背景相关卡也带出血（它们本来就压暗 0.65 且被前台卡挡住）。
