## 四、附带发现（都会影响后续工作）

1. **本包比池多 224 张卡**（未映射到任何池内卡）：计策 195 · 单位 19 · 英雄 10。其中大量是**同名多对象**（见下条）与战场环境/教程变体（`Normal Conditions (...)`、`(tutorial)`、`(enchantment)`）。
2. **SO 重名严重**：108 个卡名有 ≥2 个对象（共 251 个对象）。最多的是 `Infinite Biomorphologies` ×7、`Hyper-adaptation` ×7、`The Fang` ×5、`The Rock`/`Ancient Reliquary`/`Craftworld Convergence`/`Indomitus Crusade` ×4。**⇒ 卡名不能当主键**，必须 id / 本地化 / 数值签名一起用。
3. **SO `cardName` ≠ 玩家显示名**：本地化里有 38 条 en 与 SO `cardName` 不同。前者是显示名（如 `AM66` SO=`Tempestor Prime` / 显示=`Hektor Thenmann`；`GSC66` SO=`Shanus Daskovian` / 显示=`Lhaska Szenari`；`DA1` SO=`Azrael, Grand Master` / 显示=`Azrael`；`UM101` SO=`Terminator Sergeant` / 显示=`1st Company Terminator`）。完整表 → `name_diff_SO_vs_LOC.tsv`。**我们池里的名字大多取的正是显示名**，所以“同 id 不同名”多数不是错，是口径不同。
4. **英雄血量在 2026 build 被统一下调**（35→25 / 40→30）：池里 **58 张卡**的数值与新包不同，绝大多数是这一条。**这不是我们抄错，是版本变化**。
5. `AddressablesBuildNumber.VersionNumber = 0`（当前包）。

## 六、没读出的 / 失败原因

- **无**。三个 bundle 都是完整 type tree，UnityPy 1.24.2 全部对象读取成功，0 个解析异常。
- 类名判定：本包不含 `MonoScript` 对象（旧包有），因此 `RawCardScript` 是按 **`m_Script.m_PathID == 8864902669260471755`** + **116 个字段指纹**（`uniqueId`/`cardAbilities`/`cardImageReference`/`manaCost`…）确认的，与旧包 `m_ClassName=RawCardScript` 一致。
- 不确定项（如实标注）：`AM66` / `GSC66` 两张英雄的 SO 内部名与显示名差异很大，我按**显示名 = 同一张卡**处理（依据：`relatedCard1` 指向的天赋卡与池内描述完全对应：AM66→`Efficiency and Excellence`，GSC66→`Master Outrider`）；若原版是“换角色”而不是“改名”，这两条的**卡名**应对照卡图再核一次 —— **id 本身不受影响**。
