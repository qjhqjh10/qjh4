## 七、跨窗 / 系统性问题（修一条影响多扇窗）

### S1. **压暗层用 1920×1080 而不是原版的「超画幅」矩形** — 影响 **Deck info / Import Deck**（视觉）+ **4 扇窗的点击区**

| 窗 | 原版矩形 | 我们矩形 | 出处 |
|---|---|---|---|
| DeckSelection | -1327.3,-746.2 → 3247.3,1826.2 ✅ | 同值 ✅（点击区 1920 ✗） | `:441-450` |
| DeckInfo | **-1327.3,-746.2 → 3247.3,1826.2** | **1920×1080** ✗（视觉 + 点击区） | `DeckInfoPopup.cs:970,981` |

| MissionReroll | -1327.3,-746.2 → 3247.3,1826.2 ✅ | 同值 ✅（点击区也对） | `:141,313` |
| CardDetail | -1327.3,-746.18 → 3247.3,1826.18 ✅ | 同值 ✅（点击区 1920 ✗） | `:495-502` |

`LayoutSpace` 的可见宽 = `10 × 宽高比`（16:9 = 17.78 · 21:9 = 23.33）⇒ **21:9 下可见宽 = 2520 设计 px，两侧各 300px 无压暗、也点不到**。
原版那 2.38× 的超画幅正是为这个准备的（`Import Deck` 的 3161×1777 是 1.65×，同样够用）。

### S2. **九宫格被画成单块拉伸** — 影响 **Deck Selection 页签 + 分隔线**（同族还有 `AllianceMemberTab` / `AllianceSearchTab` 的页签，未在本轮范围）

- 页签 `40K_tab_button` / `..._overwindow`：原版 `m_Type = Sliced` · 九宫 `40K_tab_button` = **(183,0,128,29)** · `..._overwindow` = **(188,0,99,30)** · ppuMul 1.5
  ⇒ 端帽 = `183/1.5 = 122px` / `128/1.5 = 85.3px`。我们 `MenuDraw.Rect`（`DeckSelectionPopup.cs:652`）
  按 260/489 ≈ 0.53 横向压扁整张图 ⇒ **圆角变形**。
- 分隔线 `40k_main_line`：同一份 sprite，**`DeckRuntime.cs:1460` 用了 `NineSlice`，`DeckSelectionPopup.cs:468` 没用**
  —— 同一个 sprite 在工程里有两种画法，这本身就是「两处写同一条规则」。

### S3. **TMP 竖直档默认 `Middle`，原版逐件不同**

原版大量件用 `Midline(4096)`（按钮/页签）、`Capline(8192)`（主菜单钮）、`Bottom(1024)`（`Deck Name`）。
我们 `MenuDraw.Text` / 各窗 `Txt` 的默认档是 `Label.VAlign.Middle`。
- 已逐件补对：`ImportDeck` 的 Confirm（`Midline`）、`DeckInfo` 三颗主钮（`Capline`）、`ImportDeck` 输入框（`Top`，靠 `SetVAlign`）。
- **未补、且判据明确的两处**：`DeckInfo/Deck Name`（应 `Bottom`）· `DeckSelection` 页签与 `Random` 钮（应 `Midline`）。
