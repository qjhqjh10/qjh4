## 七、本会话的硬知识与坑

| 坑 | 一句话 |
|---|---|
| 🔴 **「0 调用点」可能是内联假象** | `ResolveJamUnit` / `ResolveTriggerSacrifice` 符号层 0 外部调用，但**整个体被内联进 `ResolveAction` 的 case 0x16/0x3f** ⇒ 它们是「休眠」不是「不可达」。**判 0 调用点时要看那张 91 路 switch 有没有把体内联进去** |
| 🔴 **`decomp_full` 的 C 伪码会吞返回值** | `RankedDeckSelector.__c___ChangeArmy_b__29_1.c` 把谓词打成 `void`，看起来像 `Where` 其实是 `OrderByDescending` ⇒ **这条只认 `out_il2csharp`** |
| 🔴 **`globalgamemanagers/MonoScript/MonoScript_<n>.json` 的 n 是文件序号、不是 pathID** | MainMenuWindow 那边是 1342，真实 pathID 是 `6585963289051879589` ⇒ ⛔ 别拿小序号当 pathID 搜 prefab |
| 🔴 **`decomp_generic_trial/out/` 的 640 个 `.c` 只覆盖 39 个类型** | 10 个 LiveOps 配置基类（`DraftEventBase`/`PlayEvent`/`BaseInboxEvent`/`GameNewsEvent`/`RankedEventBase`/`ScoringEvent`/`ConfigProvider`/`ReferenceList`/`ShopStore`/`MultiKeyLiveOpsHandler`）**双侧都是 0**。补法已定位（加名单跑 14.4 秒） |
| 🔴 **拉伸锚点的节点不能量 `sizeDelta`** | 拉伸锚点下 `sizeDelta` 是「相对父框的内缩量」，不是设计尺寸 ⇒ 要量 `rect.rect.width * 108`（本会话最后 1 条红就是它） |
| 🔴 **在 `Editor/*.cs` 类尾追加方法** | 无 `namespace` ⇒ 插在**最后一个 `}` 之前**；**有 `namespace` ⇒ 插在倒数第二个 `}` 之前**（`grep -c "^namespace"` 先判）。⛔ 别用 `rfind('    }\n}')`（会变成 local function，运行时程序集照样 0 错、只有调用点报 `CS0103`） |
| 🔴 **`AddTempBuff(IsKeyword=true)` 挂不上关键词** | 它只 `_buffs.Add`，不写 `_keywords`；`Has()` 只读 `_keywords` ⇒ 要用 `AddKeyword` |
| 🔴 **bash 双引号里的反引号会被执行** | 本会话又踩一次（`B90_SYNC1` 被当命令、文字被静默吞掉）。往 `.md` 里写含反引号的内容：先 `Write` 到临时文件再 python 读，或用 `chr(96)` |
