### 1. 原版到底哪块在吃射线（我自己复核过，不只抄相 1）

`bundle_scenes_scenes_mainmenuwarpforge` 的 `Card Displayer Menu For Menu`（场景对象，出厂 act=F），

（锚定依据：卡中心必须落在 (960,480) —— 这与本工程已有的断言「前台卡中心 y = **480**」**互相印证**）：

```
Card Display      584.000,106.000 → 1336.000, 974.000
  Cards           910.000,490.000 → 1010.000, 590.000
    CardUI (4)    scl=250 → 视觉 642.038, 58.925 → 1277.962, 901.075
      2DCard      698.412, 63.587 → 1221.588, 896.413   ← 卡本体 523.175×832.825（= 我们的 `CardFan.FrontWpx/Hpx`）

        Front / CardFrame / CardImage / Card Highlight And Shadow / Cardback … → **ray = 0**
```

**卡片那一整棵子树里，`m_RaycastTarget = 1` 的只有 `UI Collider`**（`NonDrawingGraphic` + `UIGenericEventCatcher`）；
卡框/立绘/高光/卡背/文字**全是 `ray = 0`**（组件的 `m_RaycastTarget` 逐颗实读）。
⇒ 原版的吸收矩形 = **723.412,123.587 → 1196.588,846.413**（与 A94 相 1 §四·2 记的 `723.4,123.6→1196.6,846.4` 逐位吻合）。

### 2. 我们**已经**吃掉了它 —— `CardHit 0`

`Shell/CardDetailPopup.cs` 的 `BuildCardStack`（现 `:365-376`）**每一格都建了命中区**，前台那格也在：

```csharp
var hx = new PxRect(cx - w*0.5f*HitRatio, cy - h*0.5f*HitRatio,
                    cx + w*0.5f*HitRatio, cy + h*0.5f*HitRatio);
var hit = Hit(node, "CardHit " + i, hx, () => SwapToFront(idx));   // q 缺省 = `QCdHit`(3118)
```

代入前台那格的实数（`CardFan.Cx(0)=960` · `Cy(0)=480` · `Wpx/Hpx = 523.175/832.825` · `HitRatio = 0.9043`）：

```
our  CardHit 0 =  723.446, 103.438 → 1196.554, 856.562   (473.107 × 753.124)  档 3118
orig UI Collider= 723.412, 123.587 → 1196.588, 846.413   (473.176 × 722.826)
x：ours ⊇ orig（左右各只差 0.034px = 取整残差）
y：ours ⊇ orig（上多 20.149 / 下多 10.149）
⇒ **ours ⊇ orig（含 x、y 两轴）**
```

行为上：`SwapToFront(0)` 第一句 `if (idx <= 0 || idx >= Slots) return;`（原版闸②）⇒ 这一下**什么都不做**、
而 `PointerLayer.HitButton` 只挑**唯一赢家**（队列大者优先、同队列 z 小者优先）
⇒ 压暗层 `BackgroundHit`（`QShade` 3105）**根本拿不到这一下** ⇒ **窗不会关**。
（同文件 `:369-371` 的注释本来就是这么写的：「前台那格也要 —— 它的回调在闸②直接 return，
**作用是「吃掉这一下」**，否则会落到 `BackgroundHit` 上把窗关掉」；`Editor/CollectionScene.cs` 也已有
「点前台那张 ⇒ 窗不关、也不换位」那条断言。）

### 3. 那条修法为什么**不能**照接（两颗雷）

① **罩死**：`MenuDraw.Absorb` 的档由公共件算 = `qContentMin − 1` = `QCdHit(3118) − 1` = **3117**，
   而 `CardHit 0` 是 **3118** ⇒ 在两者重叠处（= 整块吸收矩形）**永远是 `CardHit 0` 赢** ⇒ 吸收层**一次也吃不到**。
② **断言必红**：`CheckAbsorbRule` 的「原版面板矩形以内找得到一个点、它的命中是吸收层」**找不到**这样的点
   （候选 + 40px 兜底全落在 `CardHit 0` 里）⇒ 自己把自己断红。
⇒ **要把这一块按原版分开，只能动 `CardHit 0` 的矩形/档**（例如前台那格改用原版那格 `UI Collider` 的矩形：
x 一样、y 收成 123.587..846.413）—— 那是**改命中模型**，且判据在 `Core/CardFan.cs`（**不在本件白名单**）
⇒ 按铁律 13·4 ⑧「顺手发现也要报、⛔ 不许自己顺手改」**留给调度台**。

### 4. 反向那一处（**这才是 A133 真正查出来的偏离**）

我们那格命中区是「**一个比例 `0.9043` 双轴同用 + 居中**」，而原版是
`m_SizeDelta = (-0.2, -0.44)` 的拉伸锚 ⇒ x 比 **0.90443**、y 比 **0.86792**（**两个比例不同**，且**不居中**：
上缩 60 / 下缩 50）。后果：**我们多吃了 20.1px（上）/ 10.1px（下）**——那两条窄带在原版是**会关窗**的。
（`CardFan.HitRatio` 的注释只写了「比例 = 473.18/523.25」，**那正是 x 那一个比例** —— 用它去乘 y 就是这处差的根因。）
