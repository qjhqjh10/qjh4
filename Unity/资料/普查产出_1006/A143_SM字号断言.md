**为什么带自适应的那四条量「窗口」而不是 `FontPxNow`**：`_tmp.fontSize` 是 TMP **二分出来的收敛值**，
文字装不下就比上界小 ⇒ 拿它比字面量会**时红时绿**（A132 那一族的弱断言陷阱）。
窗口是**定死的**（`SetAutoFitBox` 里 `fontSizeMax = cur×(maxPx/nomPx)` ⇒ 折回来恒 = `maxPx`），
且正好覆盖 `FS()` 的**另一半**（`autoMinPx` 也要一起乘）。⇒ 本节的规则：**有自适应 ⇒ 断窗口；没自适应 ⇒ 断 px**。

**区分力自检**：`FS()` 被去掉时的实得值离期望 **4.0 ~ 7.9px**，容差 **0.5** ⇒ 每条都能把两种状态分开。

## 九、🔴 复跑抓到的**真 bug**：`FitWindow` 量纲错（**已修**，2026-10-06）

**症状**：`RewardsScene.Run` = **912 通过 / 4 失败**，4 条**全是本波新加的窗口断言**（老的没红一条）：
④ 骷髅卡 `Collect` 窗口 的 [下界, 上界] 两条 + ⑦ 骷髅卡时钟行窗口 的 [下界, 上界] 两条。
实测打印值 **`0.13 / 0.47 / 0.16 / 0.40`**。

**判定：`实现没接上` 一侧的量纲 bug（不是断言写法错、更不是期望值错）。**

| 证据 | 内容 |
|---|---|
| 判据原文 | `Battle/Label.cs:345-347`：**「`minPx`/`maxPx` 是「像素」，不是 TMP 的 `fontSize`」**；`MenuDraw.Text` 也是把 `autoMinPx, fontPx` **原样**传进 `SetAutoFitBox`；**只有 `worldW/worldH` 过 `LayoutSpace.Px()`** |
| 我错在哪 | `MissionsTab.FitWindow` 里给 `minPx/maxPx` **也套了** `LayoutSpace.Px()` ⇒ **多除了一个 108** |
| 算式反证（四个数逐一吻合到打印精度） | `13.8/108 = 0.12778` → 实测 **0.13** ✓ · `50.6/108 = 0.46852` → **0.47** ✓ · `17.25/108 = 0.15972` → **0.16** ✓ · `43.7/108 = 0.40463` → **0.40** ✓ |
| 为什么 ⑤⑥ 没红 | 它们 `autoMaxPx = 0` ⇒ **根本不调 `FitWindow`**，走 `MenuDraw.TextBox` 的 `SetAutoFitBox(Px(r.W), Px(r.H), autoMinPx, fontPx)`（量纲本来就对）⇒ 正是调度台看到的「两条路径不同」 |
| 影响面（**不止断言**） | 窗口被设成 `[0.128, 0.469]` px ⇒ TMP 会把骷髅卡那颗 `Collect` 与时钟行文字压到**亚像素、整条看不见** —— 正是 `Label.cs:347` 记的那个老坑（「第一版把 `33/108` 直接填进 `fontSizeMax` ⇒ 被压到 0.3px」）。**这 4 条红是自检替我们挡下的一次可见缺陷** |

**修法**（`Shell/MissionsTab.cs` 的 `FitWindow`，**一行**）：
`lb.SetAutoFitBox(Px(f.W), Px(f.H), LayoutSpace.Px(FS(minPx)), LayoutSpace.Px(FS(maxPx)))`
→ `lb.SetAutoFitBox(Px(f.W), Px(f.H), **FS(minPx), FS(maxPx)**)`；
并把**量纲**连同这次的算式写进那个函数的 doc comment（让下一个人不用再踩）。

**修完「改坏就红」仍然成立**（四条路各红一次）：

* 去掉 `Txt` 的 `autoMaxPx` 那一跳（或去掉 `BuildButton` / `BuildClockRow` 的实参）⇒ 窗口回落成 `TextBox` 那套（`FS(12)/FS(34.05)` = 13.8 / 39.16）⇒ **上界**那条红；
* 去掉 `FS()` 那一乘 ⇒ 实得 **12.00 / 44.00**（或 15.00 / 38.00）⇒ 两条都红；
* **把 `LayoutSpace.Px()` 加回去（= 这次的 bug）⇒ 实得 0.13 / 0.47 ⇒ 红** ← 这一档现在被钉住了。

**顺带订正一条我自己写错的注释**：`FitWindow` 原注释写「本函数**不碰折行**」—— **错**：
`SetAutoFitBox` 内部会连锁调 `SetWrapWidth(worldW)`（`Label.cs:339`）⇒ 折行模式变 `Normal`、`sizeDelta.x` 被改写。
现在两个调用点都走 `Txt`→`TextBox`（**本来就已折行**）⇒ **无差别**；
但 ⚠️ **item 5（`counter text`）若要用 `FitWindow` 补自适应，会顺手把原版的 `m_TextWrappingMode = 0` 改掉** —— 记在这里，别踩。
