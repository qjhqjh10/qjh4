## 一、结论（逐宿主 / 逐窗：加了哪几条）

### 1. 公共断言组：**每个宿主各加一份 `CheckAbsorbRule`**（5 份，逐字同源）

```csharp
static void CheckAbsorbRule(string what, Transform winRoot, string nodeName,
                            float x1, float y1, float x2, float y2,
                            int qShade, int qContentMin, System.Func<WindowState> state)
```

**每调用一次 = 17 条**（20 次 = **340 条**），分四组：

| # | 断什么 | 期望值来自 |
|---|---|---|
| ① | 节点在（取法：**先按窗根的直接子件** `winRoot.Find(name)`，取不到再递归 —— 只有 `RankedEventWindow` 那个嵌在 `General Red Background` 底下，那处传的是**路径**） | —— |
| ② | `MenuDraw.WasAbsorb(node)` 为真（**证明走的是公共件**，各窗自己再写一份就红） | —— |
| ③ | 渲染矩形的**左/上/右/下沿** = 传进来的四个数（容差 1.5px） | **原版 prefab 那颗面板 `Image` 的 rect 字面量**（写在调用点） |
| ④ | 档 = `qContentMin − 1`；且 `qShade < 档 < qContentMin`；`MenuDraw.AbsorbTierWarns == 0` | **该窗自己的原版档常量**（与已有 `CheckShadeRule` 同一个来源） |
| ⑤ | **点面板 ⇒ 不关**：`pl.ClickAt(面板里的吸收层点)` 返回 true，而**窗的状态**仍是 `Open` | 状态期望值 = `WindowState.Open` |
| ⑥ | **点面板外 (5,5) ⇒ 关**：`pl.ClickAt(5,5)` 返回 true，且**窗的状态**变 `Closed` | 状态期望值 = `WindowState.Closed` |

🔴 **③④ 的期望值一个都不从被测实现里读**：
- **矩形写的是 prefab 字面量**（例：`BattleLogPopup` 写 `135f, 55f, 1785f, 1055f`），
  ⛔ **不写** `Shell/*.cs` 里那个同名常量（`BattleLogPopup.ContentR`）—— 那正是被测实现**传进去的实参**
  （自证最浅那一档：期望值与被测实参同一个表达式）。
- **档写的是该窗自己的原版档常量**（`BattleLogPopup.QPanel` / `QHit`），与本文件已有的
  `CheckShadeRule` 同一种写法；⚠️ 计算式 `qContentMin − 1` 是 **A94 裁定 §3·1 规定的算法**，
  实现若改成 `−2` / `+0`，这条立刻红（**它是分辨器，不是同义反复**）。

🔴 **⑤⑥ 两条互为对照**（裁定 §3·4 的要求），这是本组唯一能真分辨两条路的地方：
- 只断「点面板 ⇒ 不关」：一个**根本关不掉的窗**（或干脆把窗藏起来）也能绿；
- 只断「点面板外 ⇒ 关」：把窗建小到「点哪儿都关」也能绿；
- **两条一起**：改坏任意一条路都会红（逐条见 §五）。

**「点面板」点的是哪儿**（⚠️ 相 1 建议的「矩形中心」在本批**不能照抄**）：
先试**原版矩形中心** → 中心外一圈（±80）→ **贴四条边内缩那一圈**（6/20/40px）→
最后按 **40px 固定步长**做一次确定性兜底扫描。所有候选都要求
**① 落在原版矩形里 ② 在屏幕内（2..1918 / 2..1078）③ 那一刻命中的那一颗是 `absorbOnly`**。
⛔ 「命中是谁」**不是期望值**（它只是**选点条件**），真正断的是**窗的状态**；
⛔ 候选是**固定**的（不是随机、不是按实现反推）⇒ 点了哪儿可复现。
> 🔴 **为什么必须加「贴边 + 兜底扫描」**：相 1 报告说「点 `AbsorbHit` 矩形中心」，
> 但 **`PracticeModePopup` 选卡组那一列的中心被卡组格盖死** —— 每格都有自己的
> `Hit`（`Shell/PracticeModePopup.cs` 的 `BuildDeckRows` 里 `HitOn(cell…, "Hit", rr, () => PickDeck(idx), QPrHit)`，
> `QPrHit = 3103 > 吸收层 3102`）⇒ 照抄「点中心」会点到**卡组格**上（点下去 = 选中那副牌），
> 那一刻窗**也不会关**，于是「点面板 ⇒ 不关」会**假绿**（分不出「面板吸收了」还是「点到了格子」）。
> 那一列真正的空白只有**左边距 ~25px**（也见 §五 那条改坏法）。
