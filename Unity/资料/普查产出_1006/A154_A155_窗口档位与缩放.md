## 结论（两问各一句话）

**① 不是「原版大多数都是 5 (Canvas)」——恰恰相反：原版 141 个带 `windowsPlacement` 的实例里 `15 (Popup)` 有 96 个（68%）、`0 (None)` 32 个、`5 (Canvas)` 只有 10 个、`10 (World)` 3 个**（`bundle_menus_assets_all` 单独看更极端：95 个里 78 个是 15）。**我们也不是「系统性用了 15」——我们能对上的 26 扇窗里 25 扇与原版一致，唯一的真偏离是设置窗（原版 `5 Canvas`、我们 `15 Popup`）**；

## ② 原版 `extraScaleSmallScreen` 那个缩放器

### ②-1 `GameWindow.Open()` 的判定（**逐句读出，附字面量**）

判据 = `d:/2/tools/decomp_full/GameWindow__Open.c` + `GameAssembly.dll` 的 `.rdata` 字面量（读法 §三）。

```
if (GameStaticData.smallScreenUI) {                                   // ← 静态 bool，与窗口宽/屏宽【无关】
    if (!Mathf.Approximately(extraScaleSmallScreen, 1f)) {            // ← 只是「这个值不等于 1」
        var c = GetComponent<TransformScalerBySmallScreenUI>()
                ?? gameObject.AddComponent<TransformScalerBySmallScreenUI>();
        c.SetScale(extraScaleSmallScreen);
    }
}
```

三条硬证据：

| 结论 | 证据 |
|---|---|
| 第一层判据 = `GameStaticData.smallScreenUI`（**静态 bool**） | 反编译：`*(char *)(*(longlong *)(DAT_18427be00 + 0xb8) + 0x11c) != 0`（`+0xb8` = 类静态字段区）。**类与字段名钉死**：`il2cpp.h` 的 `GameStaticData_StaticFields` 第 0x11c 字节正是 **`bool smallScreenUI`**，紧邻 `bool touchInput`(0x11d) / `bool smallUIChosenManually`(**0x12e**) / `bool autoCombatChosenManually`(0x12F)；逐字段对偏移全对上（`timeToDisconnectAfterPause`@0xF0 = 8.0f、`graphicsQuality`@0x120 = 3、`vsync`@0x127 = 1、`FPSLimit`@0x128 = 2、`graphicsQualityChosenManually`@0x12C = 0 —— 与 `GameStaticData__.cctor.c` 写的常量**逐个吻合**） |
| 「窗口宽 < 阈值」**不存在** | `GameWindow__Open.c` 里**没有任何宽度/屏幕尺寸读取**；`0x1834b2394f8` 解出来是 **`UnityEngine.Mathf_TypeInfo`**（`script.json` 的 `ScriptMetadata`），配 `0x1834b2db8 = 1e-06f`、`0x1834b2e00 = 8.0f` ⇒ 那就是 **`Mathf.Approximately`** 的内联式（Unity 源码：`Abs(b-a) < Max(1E-06f * Max(Abs(a),Abs(b)), Epsilon*8f)`），反编译写的 `max(...) <= Abs(1-extra)` 正是它的**取反**。**没有阈值、没有量屏** |
| 那个 bool 从哪来（**也不是按屏宽算的**） | 全反编译里写 `+0x11c` 的只有 5 处：`GameStaticData__.cctor`（=0，出厂关）· `PlayerDataManager.Load{PlayerData,StarterData,SharedDefaultValues}`（从存档/默认值读）· **`GraphicsTab.SmallScreenToggleClick`**（设置 → 图形页那颗开关，同时写 `smallUIChosenManually`(0x12e)=1）。**没有任何一处拿 `Screen.width/dpi` 去算它** |

### ②-2 缩放器本体：`TransformScalerBySmallScreenUI`（乘在哪一级）

判据 = `decomp_full/TransformScalerBySmallScreenUI__{SetScale,Initialize,LateUpdate,OnEnable,ctor}.c` + 桩 `Assembly-CSharp/TransformScalerBySmallScreenUI.cs`。

| 环节 | 做法 |
|---|---|
| 挂在哪 | `GameWindow.Open()` 里 `GetComponent ?? AddComponent`，加在 **`Component.get_gameObject()` = 窗口根 GO 自己身上** |
| `SetScale(x)` | `menuScale = x` → `Initialize()` |
| `Initialize()` | `enabled = (menuScale != 1f) && GameStaticData.smallScreenUI`（两条都成立才启用） |
| `LateUpdate()` | 若 `localScale` 与「上次自己设过的值」差 > `sqrt(0.0001)=0.01`（字面量 `0x1834b2f48 = 0.0001`，逐分量平方和）⇒ **`localScale = 当前 localScale × menuScale`**，并记下这一次的值 |
| **乘在哪一级** | **组件挂在哪个 GO 上就乘谁** —— 对窗口就是**窗口根 Transform 的 `localScale`**（整扇窗一起放大，不是某个内层容器） |

**两个必须一起看的事实**（否则会把行为记错）：

1. `Open()` **只在 `extraScaleSmallScreen ≠ 1` 时才调用 `SetScale`** ⇒ 当 `extraScaleSmallScreen = 1.0` 时，
   **它不动 prefab 里已经烤好的 `menuScale`**。
2. **`menuScale` 是序列化字段，全库有 168 颗实例**（`MonoBehaviour/<任意 pid>.json` 的 `m_Script.m_PathID == 3361136396530371980`）：

   - **绝大多数不在窗口根上**（战场 HUD：`LowerSection` 1.12 · `PlayerInfo`/`EnemyInfo`/`RadioChat` 1.25 · `ChatPopup` 1.3 ·
     `CemeteryLogPanel`/`Alliance Panel` 1.3 · `TutorialTip` 1.2 · `ChatPreview` 1.33；菜单里：`Purchase buttons` **1.1×21** ·
     `Scale menu` 1.15×2 · `Campaign Track` 1.125×2 · `Scaled Content` 1.05×2 · `FlavourTextBG` 1.12）。
3. 🔴 **窗口根上带成品的只有 3 个，而且它们的 `menuScale` 与 `extraScaleSmallScreen` 不相等**：

## ④ 顺手发现（**只报，没改**）

1. 🔴 **`资料/阶段二_Shell_原版规格.md:88-89` 那条是错的**：「若**窗口宽度 < 阈值**，用 `TransformScalerBySmallScreenUI.SetScale(extraScaleSmallScreen)` 放大」
