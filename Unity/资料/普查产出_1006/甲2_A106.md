## 四、没查清的部分 + 顺手发现的东西

### 1. 3~4 张卡那一档**没算**（按调度台口径：另开一件）
`Special Missions` 的 `ContainerHolder.maxAmount = 4` ⇒ 实机可能挂 3~4 张。**实机挂几张卡本地判不了**
（服务端任务数据）；算式是同一条（`SM 的首选 = Σ minW + (n−1)×11.01`，再走父组那条 flexible 分配），
要算的话把 `n` 代进去即可 —— 但**本轮不扩范围**。

### 2. 🔴 顺手发现①（**未修**，不属 A106）：`Daily Missions` 的 `localScale = 1.15` **我们从来没用过**
- `DM_Scale = 1.15f`（`Shell/MissionsTab.cs:134`）**全仓只有这一处声明、一次都没被引用**（grep `DM_Scale` 全工程：1 处）。
  而 `Special Missions` 那份**做了**（`_s` / `ScaleAbout`，2026-09-23 D7 修的）。
- 后果：**每日任务那一整块（卡头 + 三行 + 行内文字/字号）渲染出来比原版小 15%** ——
  行宽 609.50 vs 原版画出来的 `609.50 × 1.15 = 700.93`；行高 150 vs 172.5；里程碑格、`fs` 同理。
- 判据：`Daily Missions` 的 RT `scl=(1.15,1.15)`（`资料/日常_原版规格.md:194`）+ 父级 `localScale` 作用于整棵子树
  （与我们自己 D7 那条同一条语义）。**修法 = 给 DM 子树过一次 `ScaleAbout`（像 SM 那样）**，
  但它会动到该区**所有**矩形的断言 ⇒ 独立一件，请排期。

### 3. 顺手发现②（**未修**）：两张特殊卡的**宽度**也还是作者 `sizeDelta`
原版运行期这两张卡由 SM 的 HLG 管（`ctrlW = 1`）⇒ 各自会被排成 **347.64 宽**（各自的 `minW`）、
第二张的 x = `347.64 + 11.01 = 358.65`；我们现在画的是**作者值**：登录卡 **334** 宽 @0 · 骷髅卡 **336** 宽 @347.01。
差 3~4%，属同一族（「作者位 vs 布局位」），**不属 A106，未动**。

### 4. 顺手发现③：`MissionsTab.cs:885` 那条 `menu_rect.py … --root-size 539.188x150` **没动**
那是 `BuildRewardCell` 里**格内**相对几何的推导记录（格 126.334 宽由它自己的 `sizeDelta` 定，与行宽无关）
⇒ 数值仍然成立；只是「行宽 539.188」这个当时的前提已变，本轮不动它。
