## 一、问题（一句话）

点「窗内面板的空白处」时，**原版什么都不会发生**，而我们 **21 处**会把窗关掉。

## 二、两侧机制（已实读，2026-10-06）

### 原版
- 窗内面板本体那颗 `Image` 的 **`m_RaycastTarget = 1`**（7 个窗逐个实读）⇒ 射线**打到面板自己**
- `BackgroundCloseButton : MonoBehaviour, IPointerClickHandler`（`d:/2/tools/il2cpp_out/dump.cs:104878`）挂在**压暗层**那颗 `Menu Dark Background` 上，
  全库 **88 个 `BackgroundCloseButton`、88/88 的宿主都不是窗内面板**（82 `bundle_menus_assets_all` + 1 `mainmenualwaysloaded` + 5 `generalgamewindows`）
- 原版派发 = `ExecuteEvents.GetEventHandler<IPointerClickHandler>(命中的 Graphic)` **沿父链向上找**
  ⇒ 从面板出发的父链上**没有**处理器 ⇒ **无事发生**
- ⚠️ **一条反例**：`CardDetailPopup` 那类**没有面板底图**的窗，原版点了**确实会关**（射线直接落到压暗层）

### 我们
- 命中候选**只收 `WindowButton`** —— `Shell/PointerLayer.cs:856 CollectHits` → `AllButtons()` → `HitBoxPx(...)`
- ⇒ **一颗没有 `WindowButton` 的 quad 对命中【完全透明】**，射线会**穿过面板**落到压暗命中区 ⇒ 关窗
- 赢家判据 = **`RenderQueue` 大的先**，同队列再比 `z`（`Shell/PointerLayer.cs:840-852 HitButton`）
- ➡️ **这就是 A94 的根因**，也是「原版吸收、我们不吸收」的机制级解释

## 三、🔴 裁定：收口形状 = 「**吸收层**」

**一句话：给窗内面板加一颗【语义 = 吸收点击、什么都不做】的命中区** —— 它就是原版「面板那颗 `Image` 吃掉这一下」的等价物。

### 3·1 公共件一份实现

在 **`Shell/MenuDraw.cs`** 加一个公共函数（建议名 `Absorb`，与 `ShadeHit` 并列）：

```
public static Transform Absorb(Transform parent, string name, PxRect r, int qShade, int qContentMin, PxRect? clip = null)
```

- **档位 `q` 由公共件算**：`q = qContentMin - 1`（**严格夹在** `qShade` 与 `qContentMin` 之间）——
  因为「面板矩形 / 档位」是逐窗的，让调用方各挑一档 = 迟早挑错。
- ⚠️ **若 `q <= qShade`**（该窗没有空档）⇒ **当场告警**并计数（照 `ShadeHitTierWarns` 那个形状做 `AbsorbTierWarns`，**不许静默**）
- 建出后挂一颗**标记组件**（照 `ShadeHitMark` / `WasShadeHit`），让自检能分辨「这扇窗的面板吸收了没有」

### 3·2 ⛔ 三条实现红线（每条都有实证代价）

1. **⛔ 不能沿用面板自己那一档** —— `Shell/DeckInfoPopup.cs` 实读：压暗底 `Menu Dark Background`、红底、`Info Panel`
   **全在 `QDI = 3120`**，而 `ShadeHit` 也传 `qShade = QDI` ⇒ **面板与压暗命中区同档**。
   同档时 `HitButton` 两个条件都判不开（队列相等、`ImageQuad` 的 z 恒 0）⇒ **赢家退化成枚举顺序**，
   正是本工程反复踩的「同一个队列谁盖谁不可控」那一族坑。
2. **⛔ 不能只把 `onClick` 置 null** —— `Shell/PointerLayer.cs:332` 会打「🔴 **这个命中区没有绑动作**（`onClick == null`）」，
   那是给「忘了绑」用的真告警 ⇒ 吸收层会被误报成缺陷。
3. **⛔ 不能裸挂 `WindowButton`** —— 它自带两处副作用：
   - `public bool tintOnHover = true;`（`Shell/PromptPopup.cs:329`）⇒ 指针划过整块面板会让面板**变暗**（原版面板没有 `Selectable`、**没有任何悬停变化**）
   - `Press()` 那条「连高亮图也没有 ⇒ 按下画面什么都不变」的告警（`Bind` 从不被调用 ⇒ `_hoverTex/_pressedTex` 都是 null）⇒ **每次点面板都会误报**

### 3·3 逐窗一行接线（21 处）

- 每扇窗加**一行** `MenuDraw.Absorb(...)`，传**该窗面板底图的原版矩形**
- 面板矩形的判据 = **原版 prefab 里那块面板 `Image` 的 rect**（逐窗读，⛔ 别拿我们自己的常量反推）
- **⛔ 没有面板底图的窗（如 `CardDetailPopup`）不接**，并在注释里写明「**原版这里点了也会关，我们的行为本来就对**」

### 3·4 断言（每扇接了的窗配一条）

- 必须能**真的分辨两条路**：点面板 ⇒ **不关**；点压暗区 ⇒ **关**
- 🔴 **⛔ 不许写成 `if` 没有 `else` 的自证断言** —— 那会**整段静默不跑**（教训 → A52-F10）
- 若找不到能真分辨的写法 ⇒ **如实写进报告**，⛔ 别写自证断言充数
