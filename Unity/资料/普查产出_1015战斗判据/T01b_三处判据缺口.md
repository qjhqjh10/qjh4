# T01b · 三处判据缺口（2026-10-15 · 只读普查）

## 结论

1. **① `ChatToggle` —— 能动手，但要如实声明「作用面为空」。** 原版静音 `chatMuted` 的读点**只有 3 个、全在 `VoiceLinesController` 内**，挡的是**一条链**：**对手**从 `ChatPopup` 选的那 6 句 → 你这边的「气泡 + 语音 + 对手在聊天提示」。它**不挡**单位语音条 / 无线电提示 / 自己的发言。值的存放处 = **只在本局内存**（`VoiceLinesController.chatMuted`，场景序列化 0、`Initialize` 写 0、`Open` 从同一字段回填），**不是 PlayerPrefs、不是服务器**。我们**没有「对手聊天」这条链**（`Net/*.cs` 里 `chat` 0 命中）⇒ 照原版建出来，点它**不会有可见效果**。
2. **② `Anim Anchors` —— `anchorId ↔ 名字` 全查到了；答案是「现有演出答不上 ⇒ 单独建 = 死件」。** 枚举是 **`PositionOption`**（不是 `BattleHud.UIAnchor`，本地没这个类型），表 = `BattleHud.uiAnimAnchors`（**7 行**，arena1/arena2 逐行相同）。5 个锚里 **4 个**原版代码真读（`6/11/140/145`），第 5 个 `Anchor: Cemetery` **原版也没人读**。我们全仓**没有 `PositionOption` 解析器**，落点走 `SlotPosition` / `HudAnchor01` ⇒ **单独建 5 个空 RT 是死件**，要与解析器一起做。
3. **③ `LoadingMenu` —— 两个数都读到了（现读，不是推断）**：时长 **`1.25 s`** · `DAT_1834b2bb8` = **`1.0f`**（另 `DAT_1834b3180` = `0.6f`）。🔴 **并纠正 `D1` §5 的一处方向错误**：`DOFade` 的目标值与「立刻设的那个 α」**相反** ⇒ 进战斗是**立刻全黑 → 1.25 s 淡出到透明 → 自己关掉**，⛔ 不是「补间到全黑」。

## ① `ChatToggle` 的单机语义

### 1·1 原版这个开关对什么生效 —— `chatMuted`（`VoiceLinesController` `this+0x40`）的【全部】读点

| # | 读点（`文件:行号`） | 作用 |
|---|---|---|
| 1 | `VoiceLinesController__CanChat.c:22` | `isPlayer==false` 且 `chatMuted` ⇒ 返回 0（调用方直接 return） |
| 2 | `VoiceLinesController__CheckIfEnemyChatReceivedForTip.c:6` | `return chatMuted == 0` ⇒ 静音时「对手在聊天」的提示**不弹** |
| 3 | `VoiceLinesController__DisplayWarlordChatMessage.c:87` | 同一条提示的**节流守卫**（`chatsReceivedInTurn > 4` 那个）里带 `chatMuted` |

写点（同字段）：`VoiceLinesController__Initialize.c:23`（无条件写 0）· `VoiceLinesController__ToggleMute.c`（一行 setter，见 §顺手发现 2）· `BattleSettingsWindow__OnMuteChatChanged.c:10` · `BattleSettingsWindow__Open.c`（回填，见 1·3）。
⚠️ 另有两处 `+0x40` 命中在 `PopUpShowed/PopUpHid/IsAnyVoiceLinePlaying` 里，**不是 chatMuted**（那是 `Action` 委托 / `UnitsVoiceLinesPanel` 三个子件自己的 `+0x40`），别误引。

- **`CanChat` 的唯一调用方 = `DisplayWarlordChatMessage`** —— 实据是那行日志的字面量：`"DisplayWarlordChatMessage failed because chatMuted"`（`stringliteral.json` 解出，`DAT_1842818c0`；同族还有 `…because !IsDuringBattle` / `…because !isPopUpShown`）。
- 该函数在 `DisplayWarlordChatMessage.c:49` 的用法：`param_4（ignoreUiState）== 0` 时才调 `CanChat(this, isPlayer)`。
- ⇒ **静音挡的是「对手发来的 warlord 聊天消息」这一条链**：`BattleCommsManager.PUNReceiveChatMessage.c:25`（`isPlayer=0`，`ignoreUiState=0`）→ `DisplayWarlordChatMessage` → 被 `CanChat` 拦下 ⇒ **气泡、语音、提示三样一起没有**。

### 1·2 不挡的（逐条判据，⛔ 别扩大作用面）

- **自己的发言**：`DisplayLocalChatMessage.c:8` 传的是 `CanChat(1)` ⇒ 走 `isPopUpShown(+0x78)` 那条，**与 chatMuted 无关**；`VoiceLineButtonPressed.c:5` 传 `isPlayer=1`，同理。
- **单位语音条**（原版 `UnitsVoiceLinesPanel.ShowChatBox`，即我们 `UnitChatPanel` 那一件）：门控是 `CanUseVOs`（`CanUseVOs.c` = `matchType ∈ {100,0x8c}` + 远端配置），**没有 chatMuted**。
- **无线电小提示**：`NotifyCantDoAction` → `DisplayLocalChatMessage(3, 1)` ⇒ `ignoreUiState=1`，**连 `CanChat` 都进不去**。
- **脚本 bot 发言**：`AiScripted__ExecuteAction.c:237` · `BattleManager__ResolveTransformUnit.c:2229` · `BattleManager__BattleFinished.c:49` 全是 `ignoreUiState=1` ⇒ **绕过**。
- ⚠️ **例外一处**：`BattleManager__ResolveAction.c:4538` 是 `ignoreUiState=0`（实址 `0x180977a09`）⇒ **这一处会被静音**；但它的 `isPlayer` 实参我没定死，见「没查清的 1」。

### 1·3 值存在哪

- **只在【本局内存】**：`chatMuted` = `VoiceLinesController` 的 `[SerializeField] private bool // 0x40`（`dump.cs:42854`）；**场景序列化 = `0`**（`bundle_scenes_scenes_battlearena2/MonoBehaviour/MonoBehaviour_4450.json`，即 `voiceLinesController` PPtr 4450）；`Initialize.c:23` 无条件写 0。
- `Open()` 里那句回填，读的就是**同一个字段**：`BattleSettingsWindow__Open.c` → `uVar1 = *(byte*)(voiceLinesController(+0xE0) + 0x40)` → `muteChatToggle(+0xD0).set_isOn(uVar1)` → `muteChatToggleOn(+0xD8).SetActive(uVar1)`。
- **不是 PlayerPrefs、不是服务器**：搜过 `all_strings.txt` 里 `chatmute`（只命中那条报错文案）· 全 `decomp_full` 里 `ChatMuted`（只出现在该类的 getter）· 13 个战场包里 `chatMuted`（只在各自的 `VoiceLinesController` MonoBehaviour JSON 里）。
- 监听是 `Awake` 挂的：`BattleSettingsWindow__Awake.c:74-79`（`muteChatToggle(+0xD0)+0x118` = `onValueChanged` → `AddListener(OnMuteChatChanged)`）。

### 1·4 我们该关掉哪几样 —— 建议 + 判据

- **我们现状**：`CardPresentation/Net/*.cs`（8 个文件）里 `chat` **0 命中** ⇒ **没有「对手聊天」这条链**。`_unitChat.Speak(1, …)` 只出现在 `Battle/BattleDriver.cs:4064`（单位部署/攻击/阵亡语音条）· `:4080`（认输）· `:5527`（开场白）—— **这三样原版都不受静音影响**（见 1·2）。
- **建议（按优先级）**：
  1. ✅ **建 + 如实声明**：照 `T01` §2·1 几何建；状态机三处照做（`isOn` / **只切 `Background On` 那半张** / 一个 per-battle bool —— 建议落 `BattleDriver` 的一个字段，初值 `false`，打开设置窗时按它回填，与 `Open()` 同形）。**作用面为空要在代码注释 + 报告里写明**：「原版它挡的是联机对手聊天消息，我们没有那条链（局内 bot 发言在原版也走 `ignoreUiState=1` 绕过）」。
  2. 🔴 **将来做联机对手聊天时，它必须进这个开关** —— 判据 = 1·1 那条链（`isPlayer=0` + `ignoreUiState=0`）。
  3. ⛔ **别为了「让它有用」把 `_unitChat` 的敌方半绑上去** —— 那**不是原版行为**（1·2 有判据）。
  4. ⛔ 也不要「因为没作用所以不建」。

## ③ `LoadingMenu` 的时长与 alpha 常量 —— **两个都读到了**

**试过哪几条路 · 各自结果**

1. `.c` 里读不出（实参在 xmm 寄存器）—— 确认，改走下面三条。
2. **`.rdata` 常量池现读**（本工程现成手法）：`RVA = VA − 0x180000000` → PE 节表 → 文件偏移 → 从 `D:/2/unity_run_ref/GameAssembly.dll` 读 4 字节。脚本我放在 `d:/4/_tmp_view/t01b/rd.py`。**结果**：
   - `DAT_1834b2bb8` = **`1.0f`**（不是推断，**读到的**）
   - `DAT_1834b3180` = **`0.6f`**
   - 旁证（同一批常量，验读数手法）：`DAT_1834b2df0` = `4.0f`，正对上 `VoiceLinesController.Initialize` 里 `WaitForSeconds(DAT_1834b2df0)` 与 `CHAT_INTERACTABLE_COOLDOWN = 4`。
3. **反汇编调用点**（`disasm_va.py`）：`LoadingMenu.LoadingFade` @ `VA 0x180837A80`（`script.json` 现核）。
   - `0x180837BDC: movss xmm2, [rip+0x2c7b2dc]`，`rip` 取下一条（`0x180837BE4`）⇒ 目标 `0x1834B2EC0`。

## 顺手发现（⛔ 未改，报给主对话）

1. 🔴 **`T01` §2·3 / `D1` §5 的 `LoadingFade` 方向是反的**（见 §③）。照 `D1` 那句做出来，进战斗会「淡入到全黑然后关掉」，屏幕上就是**黑屏卡住**。
2. 🔴 **`decomp_full/VoiceLinesController__ToggleMute.c` 的内容是错的** —— 该文件里装的居然是 `EntityScript__set_isPlayer`。我按 `script.json` 的 RVA（`0x663580`）现反汇编，真身 = `mov byte ptr [rcx + 0x40], dl; ret`（**一行 setter**，只写字段、不碰 UI）。⇒ **`decomp_full` 至少有个别文件【文件名与内容不符】**；引它之前按内容核一遍（`d:/2/tools/decomp_chat/` 那份对照下来是好的）。要引「方法体」时优先 `rva_of_method.py` + `disasm_va.py`。
3. ⚠️ **枚举类型名不是 `UIAnchor`**：是 **`PositionOption`**（`dump.cs:25161`）；`BattleHud` 里那个嵌套类叫 **`UIAnimAnchors`**（字段名 `uiAnimAnchors`）。`T01` §2·2 / `D1` §4 写的「枚举 `BattleHud.UIAnchor`」**这个类型本地不存在**。
4. ⚠️ **`Anchor: Cemetery` 原版也没人读** —— `T01` §2·2 把 5 个并列成「5 个锚」，实际是 **4 个被读 + 1 个死件**；而 `positionOption 7 (cemetery)` 指的是 **`CemeteryLogPanel`**，不是那个锚。
5. ⚠️ **`AbilityLogic.GetPos` 还送 6/7/8/10/11 进锚表**，其中 **8/10 不在表里** ⇒ 原版每次都会 `LogError` 并落回 `BattleHud` 中心（`D1`/`T01` 只记了 4 个 id）。
6. ✅ **`VoiceLinesController.ToggleMute(bool)` 是个纯 setter**（顺手发现 2 提到的那一行）—— 也就是说**改值只有两条路**：设置窗的 `OnMuteChatChanged`（三处一起改）与这个 setter（只改值）。⛔ 别以为 `ToggleMute` 会连带刷新 UI。
7. ⚠️ **`SettingsPanel.cs:622` 把原版 `ChatToggle` 记成 `y=−174.94`**（`D1` 顺手发现 10）—— 本轮**没核**（不在本次范围），仍挂着。
