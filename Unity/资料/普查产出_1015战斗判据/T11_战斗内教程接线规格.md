# T11 · 战斗内教程接线规格（2026-10-15 · 只读普查）

## 结论（3~5 句）

1. **战斗教程是「一条协程 + 一张白名单」**：`BattleManager._ExecuteScriptedTurn`（`d__597`）每跳执行**一条**脚本动作，执行前先问
   `AiScripted.IsNextActionScriptedPlayerAction` —— 是玩家那一拍 ⇒ **协程当场停住、把输入权交出去**；玩家做完后由
   `BattleManager.FinishResolvingAction` / `ContinuePlayerScriptedTurn` **把指针 +1 并重启同一个协程**。
2. **「这一步算做完了」有两条完全不同的判据**：① 脚本自己那几拍（`DrawCard/PlayCard/AiChat/SmallTip/…`）= 执行完即算完、指针 ++；
   ② 玩家那几拍 = 靠 `ScriptedActionData.CheckIfMatchesActionData(battleActionType, actingCard, targetCard, targetPosition)` **逐个字段比**。
3. **「玩家被拦」= 14 个调用点**，每个都先过 `IsTutorialMatch`，再问 `CheckIfPlayerActionPermittedInTutorial`；拦下之后原版**只出声**
   （`BattleTipController.NotifyCantDoAction`，督军说一句「我不能这么做」）——**例外是拖牌落场那一处会 `MoveBackToHand` 弹回手里**。
   ⚠️ 玩家的「等」还有第二个口：`Update` 里 `CheckIfWaitingToUseAbility` / `CheckIfWaitingToChangeAttack` / `StartAttackFrom` 的引导高亮。
4. **与回合的关系**：`turnScriptedData[turnCounter - 1]`（`+0x3F8` 是 `turnCounter`，`ObscuredInt`）；`AiScripted.UpdateTurn(n)`
   **只在 n 变大时**写并把 `actionCounter` 归零（`AiScripted__UpdateTurn.c` 全文 11 行）；`turnCounter` 在 `BattleFinished` 里再 ++ 一次后跑 `onVictory/onDefeat`。
5. **🔴 我们这边【不是「未接」】** —— `RuleEngine/Core/TutorialScript.cs`（1523 行）+ `BattleDriver` 的教程段 + `TutorialOverlay.cs` 已经把本报告
   第二~七节**几乎全落地了**（含 `playerAlwaysWins` / `preventPlayerResign` 两条机制）。真缺口**只有 7 条**，见 §八。

## 二、驱动循环（分步，每步带出处）

**入口只有四个**（`ExecuteScriptedTurn` 的调用点，判据 = grep 全 `decomp_full`）：

| 时点 | 调用 | 出处（resetCounter, abortOnTurnChange） |
|---|---|---|
| 开局（换牌前） | `ExecuteScriptedTurn(bm, GetPremulliganScriptedData(), 1, 0, 0)` | `_StartBattleSequence_d__331__MoveNext.c:35-37` |
| 每回合开始（**只玩家回合**） | `ExecuteScriptedTurn(bm, GetCurrentTurnScriptedData(), 1, 1, 0)` | `_NextTurn_d__395__MoveNext.c:427-431` |
| 战斗结束 | 先 `turnCounter++` → `UpdateTurn` → `ExecuteScriptedTurn(bm, onVictory/**onDefeat**, 1, 0, cb)` | `BattleFinished.c:88,91,99-111` |
| 玩家做完一拍 | `ExecuteScriptedTurn(bm, GetCurrentTurnScriptedData(), 0, 1, 0)` | `FinishResolvingAction.c:168-181` · `ContinuePlayerScriptedTurn.c:16-20` |

`ExecuteScriptedTurn` 只做一件事：把 `(bm, turnData, resetCounter[+0x30], abortOnTurnChange[+0x31], callback[+0x38])`
**包成闭包 + 返回协程**（`BattleManager__ExecuteScriptedTurn.c` 全 29 行，**它自己不是协程**，调用方必须 `StartCoroutine`）。

**协程体 `_ExecuteScriptedTurn_d__597__MoveNext.c`（状态机）**：

1. `:50` —— `scriptedManager.stoppedTutorial(+0x28)` 为真 ⇒ `WaitForSeconds` 空转（**教程被暂停 = 协程原地等**）。
2. `:62-70` —— 抓 `turnCounter` 快照存 `0x40`，`manager.coroutineCounter(+0x534)++` 存 `0x44`（**每次重启都 +1**，纯诊断）。
3. `:74-82` —— `turnData.scriptedTurn(+0x18)` 为假 ⇒ `LogWarning` 后 **协程直接结束**。
4. `:319-330` —— `BattleManager.ActionsInQueue` 为真就等（`WaitForSeconds` + 回状态 2）；清空后才往下。
5. `:114-140` —— `abortOnTurnChange` 且 `turnCounter` 已变 ⇒ 打印后 **`return 0` 收工**（回合被跳过就不重放旧回合）。
6. `:144` —— **`IsNextActionScriptedPlayerAction(scriptedManager, bm, turnData)`**（= `scriptedActions[actionCounter].playerAction`，且 `actionCounter < count`）。
7. `:227` —— **`PlayScriptedTurn(...)`**：执行 `scriptedActions[actionCounter]` 那一条，然后 **`actionCounter++`**（`AiScripted__GetCurrentScriptedAction.c` 用 `ElementAtOrDefault` ⇒ 指针 = 下一条待播）。
8. `:232` —— 第 6 步为真 ⇒ **`return 0`**（协程停住、等玩家；由 §四的表重启）。
9. `:245,260` —— 否则 `GetDelay(…, delayBefore=false)` = **`waitAfter`**（回退到上一条）⇒ `SkippableActionWait(action, delay)` 等这一拍。
10. `:273` —— 若 `scriptedManager.skipNextAction(+0x29)` 被置过 ⇒ `CloseChatBoxes(currentAction)` + 清标记（**点空白跳过聊天**，见 §四）。
11. `:335-365` —— 到底（`finished=1`）：回调、`GetDelay(…, true)` = **`waitBefore`**、`GetCurrentScriptedAction`、`SkippableActionWait` ⇒ 回第 3 步重来。
12. `:331-333` —— `resetCounter` 为真 ⇒ **`ResetActionCounter()`（`+0x10 = 0`）**。

⚠️ **两个重载**：`PlayScriptedTurn(BattleManager, TurnScriptedData)` **和** `PlayScriptedTurn(BattleManager, List<ScriptedActionCampaignData>)`
（`dump.cs:24567-24568`）。**导出到 `decomp_full` 的 `.c` 只有战役那一份**（它读 `actionCampaignCounter +0x14` / `param_3` 直接当 List）
—— 教程那一份要按调用点反推：`PlayScriptedTurn(教程) = { if (actionCounter < scriptedActions.Count) { ExecuteAction(GetCurrentScriptedAction()); actionCounter++; } return actionCounter < Count; }`
（旁证：`GetCurrentScriptedAction` 用 `+0x10` + `ElementAtOrDefault`、`FinishedScriptedActionsInTurn` = `count <= +0x10`）。

## 三、完成判定（逐 case，判据 `ScriptedActionData__CheckIfMatchesActionData.c`）

**入参**：`(this, BattleActionType battleActionType, CardScript actingCard, CardScript targetCard, int targetPosition = 0)`。

**第 ① 步：动作类型配对**（`switch(this.actionType)`，`:27-91`）：

| `this.actionType` | 允许的 `battleActionType` |
|---|---|
| `Attack 30` | `attack 1` · `attackContinuation 53` |
| `AttackFreeMode 31` | `{1, 19, 53}`（位掩码 `0x20000000080002` ⇒ bit1/bit19/bit53） |
| `ChangeToRanged 35` / `ChangeToMelee 36` | `changeAttack 19` · `attack 1` |
| `ActiveAbility 40` | `playActiveAbility 30` |
| `PlayCard 20` | `playCardFromHand 5`（**外加落点左右那一判**，见下） |
| `EndTurn 100` | `endTurn 14` |
| `TapCard 120` | `useWaystone 76`（`_ == 0x4c` 直接 `return 1`，**后面两步全跳过**） |
| 其它 | `return 0`（`+= switchD_caseD_2`） |

`PlayCard 20` 额外一条：`targetPosition != 0` 且 `actingUnitType ∈ {31,32}` 时，
`MinionManager.PositionWillBeAtLeft(targetPosition, actingCard)` ⇒ `31` 必须为左、`32` 必须非左，否则 `return 0`。

**第 ② 步：发起者配对**（`actingCard != null` 才算，`:100-150`）：
`this.actingUnitType` → `PlayerWarlord(10)` 要求 `actingCard.rawCardData.cardType == Hero(10)`；
`PlayerMinion(30)` / `PlayerCardInHand(50)` 要求 **`cardType != 10`**，且若 `this.actingUnit(+0x18)` 非 null 则
**`actingUnit.uniqueId == actingCard.rawCardData.uniqueId`**（`PlayerItem.uniqueId`，`dump.cs:18804` +0x38）逐字相等。
⚠️ 其余档（`AiWarlord 20` / `PlayerMinionLeft 31` / `EnemyMinion 40` / `EnemyCardInHand 60`）落进 `CustomDebug.LogError("Unknown actingUnitType …")` 那一支（`:135-140`）。

**第 ③ 步：目标配对**（`targetCard == null` ⇒ `return 1`（不设目标就都算过），`:152-236`）：

| `this.targetUnitType` | 判据（`isPlayer` = `EntityScript +0x40`） |
|---|---|
| `None 0` | `return 1` |
| `PlayerWarlord 10` | `cardType == Hero(10)` **且 `isPlayer == 1`** |
| `AiWarlord 20` | `cardType == Hero(10)` **且 `isPlayer == 0`** |
| `PlayerMinion 30` / `PlayerCardInHand 50` | **`isPlayer == 1`** 且非督军；命名卡时还要 `uniqueId` 相等 |
| `EnemyMinion 40` / `EnemyCardInHand 60` | **`isPlayer == 0`** 且非督军；命名卡时还要 `uniqueId` 相等 |
| 其它（<0 / >60 等） | `return 1`（宽松放行） |

**白名单 = 上述三步全过的**那一条 `scriptedActionData`。**当前这一拍的门** = §四的 `CheckIfPlayerActionPermittedInTutorial`。

## 四、玩家被拦的规则

**`BattleManager.CheckIfPlayerActionPermittedInTutorial(bm, BattleActionType t, CardScript acting, CardScript target, int targetPosition)`**
（`.c` 全 97 行）语义，逐行：

1. **`bm.turnCounter(+0x3F8) < 1` ⇒ 直接 false**（`turn 0` = 开局/换牌，**不拦**）。
2. `GetCurrentTurnScriptedData()` 非 null 且 `scriptedTurn == true`。
3. `actionCounter(+0x10) < scriptedActions.Count`，取 `scriptedActions[actionCounter]` 为**当前这一拍**。
4. 当前这一拍 **`playerAction(+0x40)` 为假** 时：若它不满足 `ScriptedAction.IsActivateHandCards()` ⇒ **false（拦）**；满足 ⇒ 继续（`ActivateHandCards 170` 那一档放行）。
5. 遍历当前这一拍的 `scriptedActionData`：`actionType == PlayerChoice(70)` 或 `ActivateHandCards(170)` ⇒ **放行**；
   否则 `CheckIfMatchesActionData(t, acting, target, targetPosition)` 为真 ⇒ **放行**。
6. 一条都不命中 ⇒ **false（拦）**。**没有别的分支 —— 它是纯布尔门，不改任何状态。**

**14 个调用点**（全部先 `IsTutorialMatch`；多数还额外要求 `actingCard.isPlayer(+0x40) != 0` 或 `IsPlayerTurn`）：

| 调用点（`:行号`） | `t` | 其余实参 |
|---|---|---|
| `CanPlayCard.c:59` · `IsValidSpellTarget.c:33` · `Update.c:369`(拖牌落场) | `5 playCardFromHand` | (card, 0, 0) / (card, target, 0) / (card, 0, **落点槽号**) |
| `CanAttackCard.c:12` · `IsValidAttackTarget.c:100` · `AllowResolveAttack.c:231` | `1 attack` | (card, 0, 0) / (card, target, 0) / (card, 0, 0) |
| `CanUseActiveAbility.c:86` · `IsValidActiveAbilityTarget.c:33` · `…Tutorial.c:26` | `0x1e playActiveAbility` | (card, 0, 0) / (card, target, 0) ×2 |
| `CanUseWaystone.c:52` · `CanShowPotentialTargets.c:11` · `UnitOnBoardAttackTypeSelector.AttackButtonClick.c:55` | `0x4c useWaystone` · `0x35 attackContinuation` · `0x13 changeAttack` | 均 (card, 0, 0) |
| `EndTurnClick.c:57` · `FinishResolvingAction.c:138` | `0xe endTurn` | (0, 0, 0)（后者只用来决定「没动作了」的 UI 提示） |

**拦了之后原版做什么**：这些站点**只 `return false/0`**（把按钮/Target 判无效、`NotifyCantDoAction` 出提示），
**唯一有副作用的是拖牌落场那一处**：`Update.c:372-395` 在拦下后 `CardScript.MoveBackToHand(card)` +
`CardsHorizontalLayout.GetClosestInHandSlot` → `PlayerHand.HandCardMovedToNewIndex`（**牌弹回手里并归位**，联网时还发 `SendCardReorder`）。

**引导（不是拦）的另一族** —— 用来**亮出「你现在该点哪儿」**：`AiScripted.CheckIfWaitingToUseAbility`（`Update.c:170`）·
`CheckIfWaitingToChangeAttack`（`StartAttackFrom.c:36` / `Update.c:1066`）· `CheckIfWaitingToChangeDesiredAttack` ·
`CheckIfPlayerActionPermittedInTutorial` 的宽松兄弟 `IsValidActiveAbilityTargetTutorial`（`Update.c:1219` 那一支**先比宽松的、再比严的**）。

**「跳过」的三条路**：① 设置窗 `SkipTutorialButtonOnClick` → `ClickExitBattle` → 见 §六；
② `BattleManager.ClickSkip`（**跳过整套教程**）= `playMode == 100` 时 `DeadHero(bm, 0, 4)`，其余档只 `LogError`；
③ **聊天那几拍可以「点空白」跳过**：`BattleTutorialManager.DetectClickToSkip`（`Update` 只在 `+0x24 == 2` 时调它）——
`canSkipAction(+0x48)` 为真、非回放、教程局、无弹窗，且鼠标**没打到任何东西**（`EventSystem.IsPointerOverGameObject` 假 +
`Physics.RaycastNonAlloc == 0`）⇒ 置 `scriptedManager.skipNextAction(+0x29) = 1` ⇒ 协程第 10 步提前收工。
`AiScripted.CanSkipAction`（只认 `scriptedActionData[0].actionType ∈ {50,55,60,65,90}`）是**另一条**判据（`SkippableActionWait` 起始用它决定等不等）。

## 五、与回合的关系

- **当前回合的脚本** = `stage.turnScriptedData[turnCounter - 1]`，且必须 `scriptedTurn == true`（`GetCurrentTurnScriptedData.c:52-58`；
  `turnCounter` 是 `ObscuredInt @ +0x3F8`）。**先手/后手按 `turnCounter` 数的是「第几个回合」而不是「谁的回合」**（数据里 `turnName` = `"Player 1"` / `"Enemy 1"`…）。
- **`IsTutorialStageAvailable`**（`:.c` 86 行）= `IsTutorialMatch` && `currentTutorialStage != null` && `turnCounter > 0` && `turnCounter - 1 < turnScriptedData.Count`。
  `IsTutorialMatch` = `matchData.matchType ∈ {Tutorial 100, TutorialReplay 140}`；`IsCampaignLike` = `{Campaign 130, Scene 190}`。
- **指针归零**：`AiScripted.UpdateTurn(turnNumber)` = **`if (currentTurn < n) { currentTurn = n; actionCounter = 0; }`**（`.c` 全 11 行）。
  调用点：`_NextTurn_d__395:278`（每回合开始，取 `bm.turnCounter`）· `BattleFinished.c:91`（结束前 ++）。
  另有 `ResetActionCounter()`（无条件 `+0x10 = 0`）由协程的 `resetCounter` 参数触发（§二第 12 步）。
- **回合结束那一拍**：`actionType == EndTurn 100` 在脚本里是**一条动作**（数据 73 条），玩家那一侧由 `EndTurnClick` 过门（§四）。
  **`dontDrawCard` / `dontDrawTalent`**（`TurnScriptedData +0x19/+0x1A`）= 回合开始抽不抽牌/天赋 —— 字段在，**读点未定位**（§九）。

## 六、教程两条特例

**`preventPlayerResign`（`TutorialStage +0xB9`）** —— 唯一读点 = `BattleManager.ClickExitBattle.c:59`
（入口链：设置窗 `ResignButtonOnClick` → `ClickExitBattle`；`matchType == 140` 或 `160` 时**提前 return**、根本不走这段）：
```
AddResignAction(bm, 1);
if (IsTutorialStageAvailable(bm) || IsCampaignStageAvailable(bm))
   if (stage.preventPlayerResign == 0)  DeadHero(bm, 1, /*BattleResult.Forfeit*/2);   // 正常判负
   else { LogWarning; AiScripted.ExecuteAction(bm, stage.actionOnPlayerResign(+0xC0)); }  // ← 投降被吃下、改演这一段脚本
else DeadHero(bm, 1, 2);
```
⇒ **精确条件**：**教程关或战役关在跑**（`IsTutorialStageAvailable || IsCampaignStageAvailable`）&& `stage.preventPlayerResign == 1`。此时**不判负**，而是把
`stage.actionOnPlayerResign`（**6 关全非空**）当一条普通脚本动作**就地 Execute**；若它是 null ⇒ 直接 return（投降被**静默吞掉**）。
⛔ **本项目现状：只做了「挡下」，没做「改演 `actionOnPlayerResign`」**（见 §八 G-1）。

**`playerAlwaysWins`（`TutorialStage +0xB8`）** —— 两个读点、判据逐字相同：
`BattleManager__GetWinnerAfterBattleEnd.c:52-68` 与 `BattleManager__DeadHero.c:270-284`：
```
if (IsCampaignLike(bm))                                   // 130 / 190
   if (GetCurrentTutorialStage(bm) != null)
      if (stage.playerAlwaysWins != 0) { LogWarning; 赢家 = 10 = BattleWinner.Player; }
```
⇒ **精确条件**：`matchType ∈ {Campaign 130, Scene 190}` && `currentCampaignStage != null` && `playerAlwaysWins == 1`；
生效点是**「谁死了谁输」算完之后覆盖结果**（默认 `Player=10 / Enemy=20 / Draw=30`，见 `BattleWinner` 枚举 `dump.cs:45419`）。
⚠️ **关掉它的是 `IsCampaignLike` 而不是 `IsTutorialMatch`**：`MatchType.Tutorial(100)` 那一支**永远不会**命中这两处。

## 七、`TutorialPointer`

**是什么**：战场侧 prefab `TutorialPointerCombat`（挂在 `BattleManager.tutorialPointerBattle @ +0x208`），一个**指点光标**组件。
**怎么摆**：`TutorialPointer.StartPointer(mode, Vector2 pos, Vector2 dragTo, float t)` = `SetActive(true)` + `counter(+0x6c)++`
+ `showFlag(+0x70)=1` ＋ 起协程；`mode 0=ClickInPosition / 1=ClickAndHold / 2=ClickAndDrag`。
**谁来摆**：`AiScripted.ShowPlayerActionAnim`（638 行）—— 当**当前这一拍是玩家的**（`playerAction`），按 `scriptedActionData[0].actionType` 选：

## 十、顺手发现（照实报，⛔ 别自己改）

1. 🔴 **`playerAlwaysWins` 的守卫是 `IsCampaignLike()`（130/190），不是 `IsTutorialMatch()`（100/140）** —— 两个读点
   （`GetWinnerAfterBattleEnd.c:63` / `DeadHero.c:280`）都是这个写法。若将来有人「照着教程局去验这条」，会发现它**在教程局上永远不触发**。
   我们的 `RuleCore.cs:8727` 用的是 `ctx.Tutorial != null`（= 只教程局），**与原版这两处的 matchType 条件不完全等价** —— 交主对话裁。
2. 🔴 **`preventPlayerResign` 的真语义是「改演 `actionOnPlayerResign`」而不是「什么都不做」** —— 原版 `ClickExitBattle.c:63-72`
   会 `AiScripted.ExecuteAction(bm, stage.actionOnPlayerResign)`；`actionOnPlayerResign` 是 null 才静默吞掉。**6 关该字段全非空**（`tutorial_stages.json` 实测 `(1..6, True)`）。
3. **`smallTipParams` 不是 SmallTip 专属**：6 关 462 条动作**全部**带它；`waitForTip=true` 有 **64** 条，其中 **3 条不是 `SmallTip`**
   （S2 `Player 5` 第 7 条 `EndTurn` · S5/S6 `Player 7` 的 `ActivateHandCards`）。我们的 `_tutTipUp` **只在 `SmallTip` 分支里置位** ⇒ 那 3 条的 `waitForTip` **被忽略**。
   （原版 `ShowTutorialTip` 也只从 SmallTip 那一支调 ⇒ 可能同效，但**我们没核过**，如实记。）
4. **`ScriptedAction.actionType` 是 String 且是派生物**（`UpdateName` = `Enum.ToString(scriptedActionData[0].actionType)`）——
   我们的 `tutorial_stages.json` 里那串 `"SmallTip (This is your Warlord…)"` **是显示名**，运行时逻辑**一律读内层 int**。⛔ 别去解析它。
5. **`BattleTutorialManager.Update` 只在 `+0x24 == 2` 时调 `DetectClickToSkip`** ⇒ 「点空白跳过」**只在某个 UI 状态档下生效**（那一档是什么，本报告没查）。
6. **`CheckIfMatchesActionData` 对 `targetCard == null` 恒返回 1** ⇒ 不带目标的玩家动作**目标那一关自动过**；同理 `actingCard == null` 直接跳过第 ② 步 ⇒ 这是「宽松」的来源，写实现时别多加严。
