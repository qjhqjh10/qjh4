## 三、shader 现状：三层解析架构

```
① 自建 shader（工程资产）      ← 最优先。可改、跨平台、属性名与原版对齐
② 工程自带（URP/Sprites）      ← 次优先。标准 shader 走这条
③ 原版 shader bundle（817KB）  ← 兜底。只给工程里没有的 Everguild 自定义 shader 用
```

优先级开关：`WarpforgeShaderMap.PreferBuiltIn`（默认 true，只影响 ① 要不要抢在前面）。

> ⚠️ **② 必须排在 ③ 前面**。`shaders_assets_all.bundle` 里连 `Universal Render Pipeline/Particles/Unlit`
> 这类标准 URP shader 都有，但那份**和工程自带的同名 shader 不是同一个对象**
> （实测 `GetInstanceID()` 不同），而且**在编辑器下渲染会出故障（整片品红）**。
> 拿它当基准会让「原版 vs 导出」的比对整个失真（原版那一侧全是品红）。
> 修好后原版那侧的品红像素 15899 → 0。**bundle 里的 shader 只适合运行时用。**

**为什么自建 shader 是最优解**：它是普通 `.shader` 工程资产（所见即所得、任意平台），而**属性名与原版一一对应**，所以原版材质的数值可以原样灌进来，零转换。

### 自定义 shader 的用量分布（决定先做哪个）

13,898 个粒子渲染器里，**30.4% 用自定义 shader**，958 个效果里 **86.8% 至少依赖一个**。

## 六、已知问题（按优先级）

### P0-a　~~sprite 类发射器导出不渲染~~ → 已修（覆盖比 0.02 → 0.65）

**结论**：上一轮记的两个方向（「SpriteRenderer 材质槽映射 bug」/「binder 解析不到
`Everguild/Sprites/Sprite Additive`、保留占位材质」）**都是错的**。真因是两个，都不在导出器里：
①**少了自建替代 shader** —— 没映射的原版 shader 会掉进默认的 URP 粒子 shader，属性名对不上，
`_MainTex`/`_Color` 全丢、粒子渲成空（→ 新建 `WarpforgeVFX/Sprites/Additive`，属性表和 pass 状态
照 bundle 的 `SerializedShaderState` 抄：`Blend One One` / `ZWrite Off` / `Cull Off`）；
②**URP 粒子的「派生属性」没补**（影响面最大的一条）—— `_SoftParticleFadeParams` / `_CameraFadeParams`
**原版材质里根本没序列化**，binder 新建 Material 拿到默认值 0，而 shader 拿它直接乘 alpha
（`col.a *= saturate(... / _SoftParticleFadeParams.y)`，y=0 → 除零 → alpha=0）→ **整个发射器全黑**
（修法：`WarpforgeEffectBinder.ApplyDerivedParticleDefaults()`）。**详见第八节坑表。**

### P0-b　Antimatter Explosion 粒子数不足（覆盖比 0.43）→ 已修

**结论**：靠上面那条「派生属性默认值」治好了大半。剩下的差额是**密度**问题（粒子数 / 寿命 / 尺寸），
跟 shader 无关 —— 方向是 `Emission` 的 burst 数量、`maxParticles`、`Rate over Distance`、`Sub Emitters`。
**详见第八节坑表。**

### P0-c　原版渲染的品红污染（基准问题，已修）

**结论**：根因是 **bundle 里那份标准 URP shader（如 `Universal Render Pipeline/Particles/Unlit`）
和工程自带的同名 shader 不是同一个 Shader 对象**（`GetInstanceID()` 不同），在编辑器下渲染出故障
（整片品红）—— 拿它当基准会让「原版 vs 导出」的比对整个失真（原版那一侧全是品红）。
修法：`WarpforgeShaderMap.TryResolve` 里让**工程自带 shader 排在前面**，bundle 只给工程里没有的
Everguild 自定义 shader 兜底（= 第三节的三层解析架构与「bundle 里的 shader 只适合运行时用」那条）。
修好后原版那侧的品红像素 15899 → 0。**详见第八节坑表。**

### P0-d　~~非粒子 shader 掉进粒子默认 shader~~ → **已修。真因不是 shader 映射，是加载器的 bundle 冲突**

**结论**：`Environmental Condition Dark Angels Void Combat` / `... Asteroid Zone` 原版是青色漩涡贴图，
导出是**一整块纯白矩形**。上一轮记的三个排查方向（`_BaseMap` 空 / 混合状态 / 顶点色）**全部不对**：
这两个效果用的 `Everguild/FX/Alpha Masks Two Layer` 虽然不在映射表里，**但在 `wf_shaders.bundle` 里、
运行时本来就能解析，材质一直是对的**。坏在编辑器侧 —— `EffectCompare` / `EffectDiag` / `EffectIso`
会先把 `BundleDir` 下 84 个源 bundle 全量加载，而 `StreamingAssets/.../wf_shaders.bundle` **是它的副本**
（同一份内容、不同路径 → `AssetBundle.LoadFromFile` 返回 **null**）→ 旧代码直接放弃 → shader 字典为空
→ binder 保留占位材质 → **纯白块**。修法：`WarpforgeShaderLoader.EnsureLoaded()` 拿到 null 时不再放弃，
用 `LoadAllAssets<Shader>()` 把进程里已加载的 bundle 扫一遍把 shader 捡回来（被顶掉时实测捡回 49 个）。

**同一次探针查出的真 bug（已修）**：

原版 `Everguild/FX/Particle Distortion Affect Transparents` 的**属性表里没有

## 八、踩过的坑（别重踩）

| 坑 | 真相 |
|---|---|
| **🆕⚠️ 重导 prefab 之后必须重建效果库，否则所有特效静默不播** | 效果库（ScriptableObject）存的是 **(guid + fileID)** 引用。重导 prefab 时 GUID 不变（.meta 还在），但**内部 GameObject 的 fileID 会重新生成** → 958 条引用**全部解析成 null**。实测对账：库里 958 条，fileID 对得上的 **0 条**。而它**不报错**，只是 `Play()` 返回 null、什么都不发生（本会话就是被这个坑掉的：卡牌落位该播特效，一声不响）。**规矩：跑过 `EffectExporter.Run` 之后一定要跑一次 `EffectLibraryBuilder.Run`。** 现在 `Play()` 遇到空 prefab 会打警告、构建器生成完也会自检空引用数 |
| **🆕 粒子系统的随机种子：不钉死，尺子就不确定** | `useAutoRandomSeed` 默认**开**，每次重播都换种子 → 粒子分布每次不同。实测**同一进程连渲三次**得 537/518/512 个亮点（亮度和却几乎不变 = 分布变了、能量没变），连跑两遍扫描有 ~60% 的采样行会变 —— **噪声和要测的改动一样大**。修法三件事缺一不可（`EffectSweepBatch.SeedAndReset`）：`useAutoRandomSeed=false` + 显式 `randomSeed` + 先 `Simulate(0, restart:true)` 复位再推进。修完 2968 行只剩 11 行不同（都是 1 个像素）。**顺带排除的两个错嫌疑**：`ps.Play()` 和 `fixedTimeStep` 都不是原因，别往那查 |
| **🆕 `SpriteRenderer`/`SpriteMask` 的 sprite 不会被导出** | 精灵是 bundle 资产，克隆成工程 prefab 时引用落不下来 —— Unity 写的是 **guid 全 0 的伪引用**，`EffectDiag` 里能看出是 `<null>`，但**光看 prefab YAML 会以为有值**。后果不止「精灵自己不显示」：`maskInteraction=VisibleInsideMask` 的粒子全靠它裁形，遮罩一空整块效果渲成空。修法见 P0-h |
| **🆕 判「材质不对」还是「prefab 不对」要用交叉材质** | 把 A 的材质贴到 B 上再渲一次：①导出 prefab + 原版材质 能渲出来 → 材质的锅 ②照样渲不出来 → prefab/渲染状态的锅。这一刀把排查面砍掉一半（P0-h 就是靠它锁定的） |
| **🆕 隔离实例别用 `SetActive(false)`** | 停用再启用会把粒子系统重置，活粒子直接变 0 —— 于是「换了材质也渲不出来」这种**假结论**就出来了（实测踩过）。正确做法：把另一个实例**挪到画面外**（x=10000） |
| **🆕 材质缓存键是「材质名\|shader 名」，会串** | `WarpforgeEffectBinder.Cache` 用这个名字做键，而「Glow Additive」「Smoke」这类名字在几百个效果里重复。实测 **5 个键（22 个效果）同名但属性不同**，先建的会顶替后面的。量它的工具：`MatKeyCheck` |
| **原版有一批 prefab 的根节点停在「场外 x≈100」** | 实测 `Atk_GrotGrenade` / `Atk_ExileGlaiveThrow Movement` 根节点在 **(99.59, 1.24, -0.37)**、`Attack_Stomp` 在 **(100, 0.725, 0)** —— Unity 里常见的「没上场的东西停在场外」。播放时**位置必须归位**，否则效果直接播在场景外面。但**旋转和缩放不能动**：它们是效果作者定的（`Antimatter Explosion` 根节点是 **X=-90°**，`Atk_GrotGrenade` 是 **scale 0.5**），归零会把一批效果整体转 90°。见 `WarpforgeEffectPlayer.Play` 里的注释 |
| **取景必须量「要渲染的那个实例」** | 白板自检里 10/24 个效果全程 0 亮点，台账却说它们「对得上 + 高置信」。真因：取景量的是**原样实例化的临时副本**（还停在 x≈100），而播放器把实例归位到了原点 → 相机看 x=100、效果在原点 → 一个像素都没有。**看着像还原失败，其实是尺子错了。** 修法：`FrameForInstance()` 只量要渲染的那一个实例 |
| **「一整块粉色/品红糊满屏」先分清是坏 shader 还是效果本身就是全屏类** | 实拍图里出现过一大团粉色，第一反应是品红（坏 shader）。实际是 `Environmental Condition Black Legion Warp Storm` 的 `Color change overlay` / `Color change smoke` —— 渲染器半径 **245.95 单位**，设计上就是盖满整个战场，铺进 4 单位的白板格子自然糊满屏。判据用半径：普通卡牌特效 3–15、大范围闪电 74–82、战场环境叠加 245+（`VFXWhiteboard.FullscreenRadius = 100`） |
| **`sweep_*.tsv` 的 `lit_srgb`/`sum_srgb` 两列是坏的** | 它们恒为 65536（全屏像素数）。原因：代码把像素转成 sRGB 之后，**拿去和线性空间的背景色**比阈值，背景自己就超阈值 → 每个像素都算「亮」。台账用的是 `lit`/`sum` 两列，**没受影响**；但那两列以后别再拿去算任何东西（文档里原来写的「会把比值压到 0.9 附近」还低估了它） |
| **推进方式会改变「有没有内容」的结论** | 排查白板渲不出来时写了 `PlayProbe` 做 A/B：绝对时刻法（`Stop`→`Simulate(t, restart:true)`→`Play`，即扫描工具那套）和增量法（逐步 `Simulate(dt, restart:false)`）结果**基本一致**，所以不是推进方式的锅 —— 真因是上面那条取景错位。**教训**：瞬时闪光只有 0.15s，增量步长 1/30 会错过，**渲染采样要用绝对时刻法**；而寿命检查根本不需要粒子动，**两件事分开跑**，别混在一个循环里 |
| **读材质属性：名字和「值」都要走序列化数据** | `Material.GetFloat/GetColor/GetTexture()` 对「shader 没声明」的属性返回 0/黑，而原版材质的 shader 来自 bundle、声明表是残缺的（`Shader.GetPropertyCount()` 也残缺）。只改名字不改成值 → 记下来 44 个属性但**值全是 0** → `_SrcBlend=0` → 渲染不出来。正确做法：`SerializedObject` 读 `m_SavedProperties.m_Floats/m_Colors/m_TexEnvs` |
| **兜底默认值不能覆盖已有值** | `ApplyDerivedParticleDefaults` 原本是**无条件** `SetFloat("_SoftParticlesEnabled", 0)`。当属性记录变完整之后，它会把原版真值（`=1`）改写成 0 → 导出集体变亮。改成「只补没记到的」才对。**兜底逻辑只该在「真缺」的时候生效** |
| **改判据字符串前先数清覆盖面** | `isParticle` 判据从 `"Particles"`（复数）改成 `"Particle"`（单数）本身是对的（原版一大堆 shader 是单数），但它同时让上面那个无条件覆盖作用于**新的一大批材质**。一处小改动的连带影响要靠实拍量出来 |
| **多时刻扫描：原版那趟必须加载全部源 bundle** | 原版 prefab 的材质同样要从包里解析 shader，而 `battleprefabs` 里的 shader **不是可加载资产**（`LoadAllAssets<Shader>()` 返回 0）。只加载它一个包时原版渲染成**品红**，品红很亮 → 原版亮度和虚高 → 比值假性掉到 0.2 |
| **多时刻扫描：导出那趟一个源包都不能加载** | `wf_shaders_extra.bundle` 是从 `battleprefabs` 抽出来的，那个包在场时 Unity 按「内容相同」判重、拒绝加载补充包 → 导出侧退回占位材质。日志里表现为「共 44 个原版 shader 可用」（少了 42 个） |
| **上面两条方向相反，所以扫描必须分两个进程跑** | 试过在一个进程里 `AssetBundle.Unload(false)` 卸包，**但连 prefab 一起销毁了**，不行。正确做法：两趟分别跑，取景由 orig 那趟缓存下来给 exp 用，结果按效果名合并（`工具/analyze_sweep.py`） |
| **比值要有置信度** | 两个小数字相除得出的比值没有意义。实测 `GatlingSweep` 原版只有 22 个亮点、导出 114 个，比值算出来 5.38，纯属噪声。台账里必须带「峰值亮点」和置信度，让低置信的判定自己暴露出来，别硬给结论 |
| **截图口径：`tex.GetPixels()` 和 `EncodeToPNG` 是一致的** | 一度怀疑是线性/sRGB 口径差（线性下 0.5 的差会变成 0.5^2.2≈0.22，正好对得上观察值），**查下来不是** —— 两者一致。再套一次 sRGB 变换反而会把所有比值压到 0.9 附近，掩盖真实差异。别在这上面绕 |
| **`AssetBundle.LoadFromFile` 对「内容已在进程里」的文件返回 null** | 编辑器工具先把 84 个源 bundle 全量加载后，`wf_shaders.bundle`（`shaders_assets_all.bundle` 的副本）就再也加载不进来 —— **同一份内容、两个路径也算重复**。旧代码遇到 null 直接放弃，后果是**所有只靠 bundle 兜底的原版 shader 全部解析失败**、binder 退回占位材质、渲染成纯色块。这是 P0-d 的真因。修法见 `WarpforgeShaderLoader.HarvestFromLoadedBundles()` |
| **遇到「整个变成纯色块」，先分清是「没映射」还是「映射了却没解析到」** | 两者的修法完全相反：前者要自建 shader / 改映射表，后者是加载器问题，改导出器和写 shader 都是白费劲。用 `EffectShaderProbe` 的 A/B 两轮区分（唯一变量 = 有没有先加载源 bundle） |
| **UnityPy 重打 bundle：必须保留 `AssetBundle` 对象并重写它的 `m_Container`** | 只留 Shader 对象、把 `AssetBundle` 对象一起删掉 → Unity 报 `could not be loaded because it is not compatible with this newer version of the Unity runtime`（**这句话极具误导性，跟版本毫无关系**）。保留它但不重写容器（容器里还指着已删的对象）→ 包能加载但一个资产都暴露不出来。两者都做对才正常。另外 `SerializedFile.container` 是只读属性，底层是 `ContainerHelper`（attrs+slots），要改 `.container` / `.container_dict` / `.path_dict` 三个 |
| **这些 bundle 的资产名是 32 位 GUID，不是路径** | 所以 `GetAllAssetNames()` 里按 `.shader` 后缀过滤一个都匹配不上。要拿 shader 就用 `LoadAllAssets<Shader>()`，一次调用，不依赖 container |
| **诊断脚本一次进程只测一个 bundle** | 把多个包放同一个进程里测，同一个文件在不同位置会报出**不同的**错误（`not compatible with this newer version` vs `same files already loaded`），那是 Unity 的内容去重机制在干扰，不是包的属性。`BundleSmokeTest -bundle <单个路径>` 就是为此加的 |

| **诊断日志用行首前缀，别用多行插值** | 批量模式下每条 `Debug.Log` 后面都跟一坨 Unity 堆栈。给行首加可 grep 的标记（`WFPROBE ` / `WFSMOKE `），筛日志用 `grep "^WFPROBE"` 才干净 |
| **URP 粒子的「派生属性」必须手动补，否则整块渲染成黑** | `_SoftParticleFadeParams` / `_CameraFadeParams` 这几个**原版材质里根本没序列化** —— 是 `ParticleSystemRenderer` 每次渲染现算、临时塞给材质的。binder 新建 Material 拿到默认值 0，而 shader 拿它直接乘 alpha（`col.a *= saturate(... / _SoftParticleFadeParams.y)`，y=0 除零 → alpha=0）。**这是导出后「整个发射器看不见」的头号原因**。见 `WarpforgeEffectBinder.ApplyDerivedParticleDefaults()` |
| **`_EMISSION` 是全局关键字，但会混在 `Material.shaderKeywords` 里** | URP 粒子 shader 的 `_EMISSION` 由 `ParticleSystemRenderer` 以**全局**作用域开关；可它又会出现在 bundle 材质的 `shaderKeywords` 里。导出时若照单全收烘进局部关键字，运行时 `Material.IsKeywordEnabled`（= 局部‖全局）就**恒为真** → 无条件开 Emission → 整体偏亮。**导出时必须剔掉**（`EffectExporter.StripGlobalKeywords`）。顺着「它是全局的所以导出丢了、要补上」这个直觉走会**反着修** |
| **bundle 里的 shader 在编辑器下渲染会出故障（品红）** | `shaders_assets_all.bundle` 里连标准 URP shader 都有，但那份**和工程自带的同名 shader 不是同一个对象**（`GetInstanceID` 不同），实测在编辑器里会渲染成整片品红。**只适合运行时用**。解析顺序里工程自带的同名 shader 必须排在 bundle 前面，否则「原版 vs 导出」的比对基准整个失真（原版那侧全是品红） |
| **测试环境自己的坑：同进程重复加载 bundle** | `AssetBundle.LoadFromFile` 对**已加载**的文件返回 null。诊断脚本若先把 84 个源 bundle 全加载了，会把 StreamingAssets 里那份 `wf_shaders.bundle` 的加载顶掉，binder 只能退回 `Shader.Find`。诊断时**只加载要用的那一个包** |
