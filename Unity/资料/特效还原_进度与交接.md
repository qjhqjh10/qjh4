## 〇·一、`_EmissionColor` 那次退步（2026-09-15 已修）—— 三条坑

🔴 **坑一：原版材质带的是内置 shader 的默认值，不是「原版数据」。**
`_EmissionColor` 在 URP / 内置粒子 shader 的属性表里就是 `[HDR] _EmissionColor("Color", Color) = (0,0,0)`（`ParticlesUnlit.shader:9`），
没开发光的材质原样留成 `{0,0,0,1}`，而原版那边**根本不采它**（`_EmissionEnabled=0` / 无 `_EMISSION`）
⇒ **新接一个原版属性之前先问三句：默认值是什么、原版在什么条件下才采它、原版是加法还是乘法**（`工具/dump_shader.py` 读属性表）。
⚠️ **修法也不是「改成加法」** —— 原版 `Everguild/FX/Extra Color` 的属性表里**根本没有 `_EmissionColor`**
（21 项逐字：`资料/普查产出_0917/shader属性表_块1.md:278`），而它默认值是白 ⇒ 加了等于**白白多加一整份贴图（≈2×）** ⇒ **最终是整项删掉**。
（当时那三行「略偏亮」`StrikeEffect` / `VulnerableEffect` / `EnvironmentalCondition…` 已定案 —— **不是资产缺陷**。）

🔴 **坑二：`_EMISSION` 不能用 sweep 验。** 2026-09-18 实测（16 个目标 × 三批次，开 `WFSWEEP_GLOBALS=1`）：
**扫描态下它对全部 16 个目标都是全局开着的**（进第 1 个目标前就已开着；全局关键字总数第 1 个 59 个、第 2 个起 132 个）
⇒ **sweep 测的不是游戏里的样子**（游戏里我们的材质没开它，见 `EffectExporter.cs:388`）。
凡与 `_EMISSION` 有关的假设要**单效果 A/B，且先按 Emission 模块重置全局关键字**。
（同一次实测的另一半结论：绝对值漂移属实但**共模**，比值 `|ln|` 差 ≤0.0005 ⇒ **`RenderAt()` 不用改**；证据见正本 §五。）

🔴 **坑三：跑小批前必看** —— `EffectSweepBatch` 里写 `ResultPath` / `FrameCachePath` 的那几处是 `File.WriteAllText`，
**小批会把全量基线 `sweep_{orig,exp}.tsv` 与取景缓存整份覆盖掉**（先 `cp` 备份并存 md5、跑完按 md5 还原）。

**全量指标与逐组计数只认 `资料/特效还原台账.tsv` 一处**（修完已重跑全量 sweep 重生；`analyze_sweep.py` 每次会打「尺子自检」表，**看计数变化前先跟它比**）。**本节不抄第二份**。
⚠️ **`资料/特效E组_逐效果根因表.md` 的锅名单要按新台账重核**（那张表是按旧台账分的组）。

**三条老经验（仍成立）**：① 「编辑器里好、进游戏坏」是这条线最难查的一类 bug —— **编辑器里的比对图不能代表运行时**；

## 三、shader 现状：三层解析架构

```
① 自建 shader（工程资产）      ← 最优先。可改、跨平台、属性名与原版对齐
② 工程自带（URP/Sprites）      ← 次优先。标准 shader 走这条
③ 原版 shader bundle（817KB）  ← 兜底。只给工程里没有的 Everguild 自定义 shader 用
```

优先级开关：`WarpforgeShaderMap.PreferBuiltIn`（默认 true，只影响 ① 要不要抢在前面）。

> ⚠️ **② 必须排在 ③ 前面**。`shaders_assets_all.bundle` 里连 `Universal Render Pipeline/Particles/Unlit`
> 这类标准 URP shader 都有，但那份**和工程自带的同名 shader 不是同一个对象**
> （实测 `GetInstanceID()` 不同），而且**在编辑器下渲染会出故障（整片品红）**。
> 拿它当基准会让「原版 vs 导出」的比对整个失真（原版那一侧全是品红）。
> 修好后原版那侧的品红像素 15899 → 0。**bundle 里的 shader 只适合运行时用。**

**为什么自建 shader 是最优解**：它是普通 `.shader` 工程资产（所见即所得、任意平台），而**属性名与原版一一对应**，所以原版材质的数值可以原样灌进来，零转换。

**同一次探针查出的真 bug（已修）**：

原版 `Everguild/FX/Particle Distortion Affect Transparents` 的**属性表里没有
`_SrcBlend/_DstBlend/_ZWrite/_Surface/_Blend/_Cull`**（14 个属性，混合相关的一个没有），
混合是**写死在 pass 状态里的**（bundle 实测 `rtBlend0`：src=5 SrcAlpha / dst=10 OneMinusSrcAlpha，
`zWrite=0` / `zTest=4` / `cull=2`，`separateBlend=False`）。

而原版材质上**带着一批内置 Standard shader 的残留值**：`_SrcBlend=1`(One) / `_DstBlend=0`(Zero) /
`_ZWrite=1` / `_Surface=0`（还有 `_Glossiness` / `_BumpScale` / `_Metallic` … 一堆）。
在原版那边这些是**死值**（shader 不声明，Unity 忽略）；但我们自建的 `WFDistortion.shader`
用 `Blend [_SrcBlend] [_DstBlend]` 间接寻址 → 残留值被灌进来 → 变成**不透明覆盖 + 写深度**。
实测：棋盘背景上导出侧糊出一整块**纯黑**，把棋盘抠掉（`contrib` 全是 `(0,0,0)`）。

**修法**（照解包资源，不猜）：
1. `WFDistortion.shader` 的混合/深度/剔除**硬编码**成上面那组 pass 状态，
   删掉原版根本没有的 `_SrcBlend/_DstBlend/_ZWrite/_Surface/_Blend/_Cull/_Cutoff/_AlphaClip`；
2. 属性表和原版对齐：`_DistortionStrength` 是 **Float 默认 1.0**（我们原来写成 `Range(0,1)` 默认 0.1）、
   `_DistortTex` 默认 `"bump"`、`_Depth_And_Fallof` 默认 `(1,0.1,0,0)`（**不是** `(0,1,1,0)`）、
   `_UVSpeed` 默认 `(1,1,0,0)`、`_QueueControl` 默认 `-1`；
3. 关键字名照原版：`_SOFTPARTICLES` / `_USEMASK` / `_ANIMUVS`（**没有 `_ON` 后缀** ——
   原来写成 `_SOFTPARTICLES_ON`，导出侧 `EnableKeyword` 全部落空，等于这三个功能永远关着）；
4. `WarpforgeEffectBinder` 补混合的判据从「**原版材质**里有没有记到 `_SrcBlend`」
   改成「**我们这边的 shader** 认不认 `_SrcBlend`」—— 原来那条判据永远为真，兜底逻辑没机会生效。

#### 二、`WFLUTBlender` —— ✅ 复核通过（它真的是 `lerp`）

原版在 **`scenes_scenes_battlearena*`** 里（**原来 `disasm_dxbc.py` 够不着** —— 见第四节）。
本机重跑（用兜底扫描捞到的 13 个 shader 对象），ps 正文：

```
dcl_constantbuffer CB0[4], immediateIndexed
sample r0.xyzw, v0.xyxx, t1.xyzw, s1
sample r1.xyzw, v0.xyxx, t0.xyzw, s0
add    r0.xyzw, r0.xyzw, -r1.xyzw
mad    o0.xyzw, cb0[3].xxxx, r0.xyzw, r1.xyzw     ; = lerp(t0, t1, cb0[3].x)
```
我们那份（`WFLUTBlender.shader:98-100`）是 `lerp(_LUT1, _LUT2, _Blend)` —— **同一个东西**（结合律下
`o = b + k(a−b)` 与 `lerp(a,b,k)` 逐位等价）。**不需要改。**

#### 三、改了什么（**都只影响「兜底路」**：bundle 不在场时才轮到我们这份）

**`WFSpritesAdditive`**（判据 `_tmp_view/dxbc/Everguild_Sprites_Sprite Additive_{ps,vs}.txt`）
- ps 基础变体（11 条，材质 `keywords: []`）：`sample t0` → `mul × v1`（顶点色）→ **`mul o0.xyz, r0.w, r0.xyz`**
  ⇒ **rgb 要预乘 alpha**。我们原来直接 `return c` ⇒ `Blend One One` 下**alpha 完全不参与衰减**（硬边高亮）。
- vs：`mul r0, v1, cb0[2]` `mul o1, r0, cb3[0]` ⇒ **两道材质色**（`_Color` **和** `_RendererColor`），
  我们只乘了 `_Color`；UV 是 **`mov o2.xy, v2.xy`（直通）**，我们做了 `TRANSFORM_TEX`。
- ETC1 那一档取 `_AlphaTex` 的 **`.x`（红通道）**，不是 `.a`。

**`WFMatcap`**（判据 `Everguild_Matcap_Matcap Full Options_ps.txt` 行 22–49 = 基础彩色变体）
- 原版：`r0 = LinearToSrgb(_Color) × _MainTex.rgb` · `r1 = _MatCap.rgb × _Intensity` · `o0 = (r0×r1, **1.0**)`。
- 我们原来三处不同：**没做 `_Color` 的 sRGB 编码** · **多乘了 `IN.color`**（原版基础变体
  **一个颜色分量都没读**：只用 `v1.xy` / `v3.w` / `v4.w`）· 输出 alpha 用了 `main.a`（原版恒 1）。
- **文件头「两个原版共用同一份属性表（25 个）」是错的**：`dump_shader.py` 实读
  **Full Options 35 个 / With Texture 25 个** ⇒ 改成**并集**（38 个），`_APPLYAMBIENTCOLOR` 默认值 0 → **1**。
- ⚠️ **关键字分支实测被用着**：FO 的 138 个材质里 119 个只有 `_NOISECHANNEL_R`（≈基础变体）·
  6 个带 `_USEEMISSION` · 11 个带 `_SURFACE_TYPE_TRANSPARENT` · 1 个带 `_ALPHATEST_ON`；
  **With Texture 的 70 个全部带 `_APPLYAMBIENTCOLOR`**。

**`WFUnlitAmbient`**（判据 `Everguild_UnlitAmbient_ps.txt`，基础彩色变体 14 条）
- 原版：`o0.rgb = lerp(主图.rgb, v2.rgb, v2.w) × cb1[5].rgb` · `o0.w = **1**` · **基础变体不 clip**。
- 只改了**两条与 cbuffer 槽位无关**的：① **去掉「永远 clip」**（`#ifdef _ALPHATEST_ON` 从来没声明过
  pragma ⇒ 恒假、恒走 `#else` 去裁）② 输出 alpha 去掉 `* IN.color.a`（原版全文件 `o0.w` 只有
  4 种写法，**顶点 alpha 一次都没进过 alpha**）。
- **其余没改** —— 见下一节，**不是不做**。

| 某个效果整个是纯色块 | `EffectDiag` 看 shader 名 → 大概率「没映射，掉进粒子默认 shader」 |

## 十、🔴 **`cb0[i]` 到底是什么：Unity `$Globals` 槽位表**（2026-10-02，六族兜底路重写时坐实）

**问题**：原版 shader 的 DXBC **没有 RDEF**（22/22 实测）⇒ 反汇编里只有 `cb0[27]` 这种**光槽位、没有名字**，
而「读不出 cbuffer 名字」一直被当成结构性卡点（`资料/已知的坑.md` 末节）。

**答案**：`cb0` 就是 **Unity 的 `$Globals`**，布局 = **URP 全局的声明顺序**
（`com.unity.render-pipelines.universal/ShaderLibrary/Input.hlsl` 在前、`UnityInput.hlsl` 在后，
**逐个 float4 累加**，一个向量不跨寄存器）。累出来之后**实测槽位一个不差地全部对上**：

| 槽 | 名字 | 佐证 |
|---|---|---|
| `cb0[3]` | `_ScaledScreenParams` | Input.hlsl:108；原版拿它当屏幕尺寸除数 `div v0.xy, cb0[3].xy` |
| `cb0[4].x` / `[4].z` | `_GlobalMipBias` / `_AlphaToMaskAvailable` | Input.hlsl:112 / :115（**相邻两条**，与实读逐位吻合）|
| `cb0[19].x` | `_TimeParameters.x` | 15=_Time·16=_SinTime·17=_CosTime·18=unity_DeltaTime·**19=_TimeParameters**；与 `资料/战场13场_逐场对账_0920.md:1524` 独立结论一致 |
| `cb0[22].x` | `_ProjectionParams.x` | UnityInput.hlsl:57；`< 0` = 投影翻转（原版用它 `movc` 翻 y）|
| `cb0[23]` / `[24]` / `[25].w` | `_ScreenParams` / `_ZBufferParams` / `unity_OrthoParams.w` | UnityInput.hlsl:63 / :75 / :81；`1/(z·d+w)` 就是 `LinearEyeDepth`，`.w==1` 就是正交 |
| `cb0[28]` | `_RTHandleScale` | UnityInput.hlsl:91；屏幕 UV 的 RTHandle 缩放 |
| `cb0[56].xyz` | `unity_AmbientSky` | 与 `ArenaEnvGlobal.cs` 那套 `_AmbientColorBlend` tint 对得上 |
| `cb0[66..69]` / `[78..81]` / `[82..85]` | `unity_MatrixV` / `unity_MatrixVP` / `unity_MatrixInvVP` | **`[78..81]` 有顶点着色器独立佐证**：`o0 = x·cb0[78] + y·cb0[79] + z·cb0[80] + cb0[81]` 正是裁剪位置 |

- ⚠️ **矩阵在 cbuffer 里按【列】放**：片元里逐字出现的 `clip.w = x·cb0[78].w + y·cb0[79].w + z·cb0[80].w + cb0[81].w`
  就是它（别按「行」去理解，会推错）。
- ⚠️ **`cb1` 的含义按阶段不同**（D3D11 的 VS/PS 常量槽分开绑）：**VS 里 = `UnityPerDraw`**
  （`cb1[0..3]`=unity_ObjectToWorld、`[4..6]`=unity_WorldToObject 的 3×3）；**PS 里 = `UnityPerMaterial`**
  （只含 ShaderGraph **真正用到**的属性 ⇒ 槽数很小，材质上那些对不上的属性是**残留死值**）。
- ⚠️ **尾槽（129/130 附近）是「每 shader 各自追加」的**（`_CameraDepthTexture_TexelSize`、游戏自己的
  `_AmbientColorBlend` 都落在这儿）⇒ **尾槽不能跨 shader 类比**，判它是什么只能看**用法**
  （`1 − 0.5·texel` 那种就是 texel size）。

**怎么用**：写自建 shader 时**不要照槽位写数字** —— 用**名字**（`unity_MatrixVP` / `_ZBufferParams` …），
Unity 自己会绑对；这张表只用来**读懂原版那一段在干什么**。

## 十二、2026-10-02 第三批：**「白名单里的弱兜底」也重写了**（判据同上批，逐条在各自 shader 文件头）

**为什么是这批**：审计表重生成后发现 —— 剩下那批最差的**在正常态其实是好的**（表里「白名单比值」≈1.0），
只在**全开强制**时才退化 ⇒ 元凶是**白名单里那些「自建兜底版还很差」的名字**，
也就是 🔴 **新克隆真会走到的那条路**。把 59 个白名单名字里「兜底版仍是通用 `Extra Color`」的 **16 个**筛出来，
先做掉在审计表里出现最多的那几个：

| 原版 shader | 新自建 shader | 一句话关键点 |
|---|---|---|
| `Everguild/FX/Alpha Mask One Layer` | `WFAlphaMaskOneLayer` | 两张图**各滚各的 UV**（第一条多加 `uv0.z`）→ 逐通道相乘 → alpha 走 `pow(·, _Alpha_Modifier)` |
| `Everguild/FX/Unlit UV scroll` | `WFUnlitUVScroll` | 两张图 **Overlay** → `lerp(S1,·,_Layers_Blend_Opacity)`（可 >1 外插）→ × sRGB(`_Color`) × 顶点色；`_SOFT` 支另加深度淡出 |
| `Everguild/FX/Particle Shine Custom Vertex Streams` | `WFParticleShineCVS` | 主图 + **旋转 UV 采样的 Shine** 经 smoothstep 叠加；K 取**顶点流** `uv0.w` |
| `Everguild/FX/Particle Premultiply Greyscale Coloring` | `WFParticlePremultiplyGreyscale` | `t·lerp(sRGB(Color2), sRGB(Color), t)`（**比普通 lerp 多乘一次 t**）+ **预乘** |
| `Everguild/UnlitAmbient`（改现有） | `WFUnlitAmbient` | **顶点色改成 lerp 的目标色**（原来是乘）· ambient 从加法改成**乘性 tint** —— 与 `WFMatcap` 同一套算式 |
| `Legacy Shaders/Particles/Additive` | `WFLegacyParticlesAdditive` | `2·顶点色·_TintColor·贴图`，alpha 取 `saturate` |
| `Legacy Shaders/Particles/Alpha Blended` | `WFLegacyParticlesAlphaBlended` | `2·顶点色·贴图`（**不读 `_TintColor`**）—— 与上一条是**两个不同算式**，别合并 |

**同批查实、结论是「不用动」的**（省得下次再查一遍）：
- `Mobile/Particles/Additive` 与 `Mobile/Particles/Alpha Blended` 的 PS **只有 2 条指令**：
  `o0 = tex × 顶点色`（**连 cbuffer 都没有**）⇒ 通用那份 `WFParticlesExtraColor` 对它们**逐位正确**，
  **不要**给它加 `×2` / `_TintColor`（那是 Legacy 那族的）。它们的偏差来自别的 shader（`URP/Particles/Unlit` 的版本差，两侧都有）。
- `Legacy` 那族的 `×2` 恰好被 `_TintColor` 的**默认值 0.5** 抵消 ⇒ 审计表上看不出来；只有改过 `_TintColor` 的材质才现形。

**🔴 同批修掉的一个真缺口（`WarpforgeShaderMap.TryResolve`）**：
白名单名字**取不到原件**时（= 新克隆没有那 8 个随包），原来因为一个 `!wantOriginal &&` 守卫会**跳过 `Replacements`**：
Everguild 那批最终 `return false`（保留占位材质，**凑巧**也是我们那份）、而 **8 个内置管线名会命中「引擎自带那一份」**
（= 在 URP 下渲染不了的那个）✗ —— **与项目记录「新克隆必然走兜底路」不符**。
改成「取不到原件就落到自建替代」⇒ 两条路都变成我们那份。**正常态不受影响**（包在 → 上面早就 return 了）。
判据 → `WarpforgeShaderMap.cs` 那段注释；自检 = `ShaderResolveProbe` 的 `59 个走原件 / 0 个没走成`。

**工具坑（派子代理时踩的，记这里）**：`工具/disasm_dxbc.py` 是「先把反汇编全打到 stdout、最后才写 `--out`」
⇒ 用 `... | head -40` 会把它 **SIGPIPE 掉**：**文件不落盘、而且不报错**。要截断请用 `| tail -n` 或 `| grep`（会读满 stdin 的那种）。

### 🔴 本轮新增的通用知识（下次别再踩）

- **`cb0` = Unity `$Globals`**，按 URP 声明顺序累加就能把槽位读成名字 → **§十**（六族共用）。
- **`[Toggle(KEY)]` 的 KEY 不要同时在 CBUFFER 里声明同名变量**（Unity 开关键字时 `#define` 它 ⇒ 重定义、编不过）
  → `资料/已知的坑.md` 末节。
- **兜底路 shader 的快速内环 = `EffectCompare` 对拍**（2 分钟，比全量 sweep 的 8 分钟快）
  —— 判读口诀：**形状不同 ⇒ 配对错；形状同只差亮暗 ⇒ 算式错；品红 ⇒ 编译错** → 同上。
- **`disasm_dxbc.py` 用 `| head` 截断会被 SIGPIPE 掉 ⇒ 文件不落盘且不报错**，要用 `| tail` / `| grep` → 同上。
- **`WFMatDef` 的并列数组按名字 ASCII 排序、且混着旧 shader 的残留名** ⇒ 「读到一个数」≠「读对了那个数」
  → 同上。
