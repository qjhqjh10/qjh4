## 〇·一、✅ **那次退步已定位并修好（2026-09-15）—— 一句话：`_EmissionColor` 被当成乘性因子**

**真因**：第三十三轮 `4e0741d`（③-3）给自建 shader `WFParticlesExtraColor.shader` 加了一行
`col = tex * _Color * _EmissionColor * IN.color`（**乘法**）。而原版那批材质里的
`_EmissionColor` **是黑的死值**——URP / 内置粒子 shader 的属性表里它就是
`[HDR] _EmissionColor("Color", Color) = (0,0,0)`（`ParticlesUnlit.shader:9`），
没开发光的材质原样留成 `{0,0,0,1}`，而原版那边**根本不采它**（`_EmissionEnabled=0` /
没有 `_EMISSION` 关键字）。⇒ 我们这边一乘，**整个材质被乘成黑**。

🔴 **「改成加法发光项」那条修法 2026-09-18 已作废**（原来这里给了代码 `col.rgb += tex.rgb * _EmissionColor.rgb * IN.color.rgb;`）。
**为什么删**：**原版 `Everguild/FX/Extra Color` 的属性表里根本没有 `_EmissionColor`**
（21 项逐字，`资料/普查产出_0917/shader属性表_块1.md:278`）⇒ 原版从不做这项加法；
而它默认值是白 ⇒ 没记到该属性的材质会**白白多加一整份贴图（≈2×）**。
**保留下来的坑（这条仍成立）**：原版那批材质里 `_EmissionColor` 的 `{0,0,0,1}` 是**死值**，
乘上去会把材质乘没。判据·实测·修法见 `资料/普查产出_0918/E组_共享资产筛_与EMISSION线索.md` §十一。

⚠️ 当时还有**三行「略偏亮」**（`StrikeEffect` / `VulnerableEffect` / `EnvironmentalCondition…`）已于 2026-09-15 定案 —— **不是资产缺陷**，见下。

⚠️ **这支探针自己踩过三个坑，别重踩**：
1. **同名兄弟按名字配对会撞车** —— `PinDownEffect` 底下**两个渲染器都叫 `Sprite Mask`**，

## 三、shader 现状：三层解析架构

```
① 自建 shader（工程资产）      ← 最优先。可改、跨平台、属性名与原版对齐
② 工程自带（URP/Sprites）      ← 次优先。标准 shader 走这条
③ 原版 shader bundle（817KB）  ← 兜底。只给工程里没有的 Everguild 自定义 shader 用
```

优先级开关：`WarpforgeShaderMap.PreferBuiltIn`（默认 true，只影响 ① 要不要抢在前面）。

> ⚠️ **② 必须排在 ③ 前面**。`shaders_assets_all.bundle` 里连 `Universal Render Pipeline/Particles/Unlit`
> 这类标准 URP shader 都有，但那份**和工程自带的同名 shader 不是同一个对象**
> （实测 `GetInstanceID()` 不同），而且**在编辑器下渲染会出故障（整片品红）**。
> 拿它当基准会让「原版 vs 导出」的比对整个失真（原版那一侧全是品红）。
> 修好后原版那侧的品红像素 15899 → 0。**bundle 里的 shader 只适合运行时用。**

**为什么自建 shader 是最优解**：它是普通 `.shader` 工程资产（所见即所得、任意平台），而**属性名与原版一一对应**，所以原版材质的数值可以原样灌进来，零转换。

### 自定义 shader 的用量分布（决定先做哪个）

958 个效果里 **86.8% 至少依赖一个**自定义 shader（分母「13,898 个粒子渲染器」见 §二 那张表，本文件不抄第二处）。

**逐条「影响到多少个效果」写在 `WarpforgeShaderMap.cs` 那张表旁边**（含 2026-09-18 那批的 `// N 条效果` 注释），**本文件不抄第二份**。

**长尾那些（`Rays For Trail` / `Unlit UV scroll` / `Multi Ray` / `Particle Dissolve Mask` / `Alpha Mask One Layer` …）不用再自建** —— 它们都在 `wf_shaders_extra.bundle` 里，运行时能解析（见 P1-a）。
🔴 **2026-09-18 更正：用户已取消版权红线**（个人学习用途）⇒ 原写「进发布版本时要换成自建替代」的约束**作废**。

## 六、已知问题（按优先级）

### P0-a　~~sprite 类发射器导出不渲染~~ → 已修（覆盖比 0.02 → 0.65）

### P0-c　原版渲染的品红污染（基准问题，已修）

**结论**：根因是 bundle 里那份标准 URP shader（如 `Universal Render Pipeline/Particles/Unlit`）**和工程自带的同名 shader 不是同一个对象**（`GetInstanceID()` 不同），编辑器下整片品红 ⇒ 拿它当基准会让「原版 vs 导出」整个失真。修法：`WarpforgeShaderMap.TryResolve` 里让**工程自带 shader 排在前面**（= §三 三层解析架构）；修好后原版那侧品红像素 15899 → 0。**详见 §八 坑表。**

## 八、踩过的坑（别重踩）

| 坑 | 真相 |
|---|---|
| **🆕🔴 原版材质里的「黑 `_EmissionColor`」是死值，不是数据** | 2026-09-15 把 `_EmissionColor` 接进自建粒子 shader 时写成了**乘法**（`col = tex * _Color * _EmissionColor * IN.color`），而原版那批材质的 `_EmissionColor` 是**内置 shader 的默认黑**（`{0,0,0,1}`，URP `ParticlesUnlit.shader:9`），原版那边要 `_EmissionEnabled`/`_EMISSION` 才采它 ⇒ 我们这边一乘，**整个材质被乘成黑**，13 个效果同时变暗 30 倍。**修法**：🔴 **2026-09-18 更正 —— 一度改成加法发光项，那条也作废了**（实测原版 `Everguild/FX/Extra Color` 属性表里**根本没有 `_EmissionColor`**，而它默认值是白 ⇒ 加了等于**白白多加一整份贴图 ≈2×**）⇒ **最终是整项删掉**（见 §〇·一）。⚠️ **这和上面 `_SrcBlend` 残留值是同一个坑的第二次**：原版材质带的是内置 shader 的默认值，**接一个新属性前先问「默认值是什么、原版什么条件才采它、是加法还是乘法」**。定位：把 `4e0741d`（③-3）那一笔回退掉**13 个效果就全部复原**；细节见 §〇·一 |
| **🆕⚠️ 重导 prefab 之后必须重建效果库，否则所有特效静默不播** | 效果库（ScriptableObject）存的是 **(guid + fileID)** 引用。重导 prefab 时 GUID 不变（.meta 还在），但**内部 GameObject 的 fileID 会重新生成** → 958 条引用**全部解析成 null**。实测对账：库里 958 条，fileID 对得上的 **0 条**。而它**不报错**，只是 `Play()` 返回 null、什么都不发生（本会话就是被这个坑掉的：卡牌落位该播特效，一声不响）。**规矩：跑过 `EffectExporter.Run` 之后一定要跑一次 `EffectLibraryBuilder.Run`。** 现在 `Play()` 遇到空 prefab 会打警告、构建器生成完也会自检空引用数 |
| **🆕 粒子系统的随机种子：不钉死，尺子就不确定** | `useAutoRandomSeed` 默认**开**，每次重播都换种子 → 粒子分布每次不同。实测**同一进程连渲三次**得 537/518/512 个亮点（亮度和却几乎不变 = 分布变了、能量没变），连跑两遍扫描有 ~60% 的采样行会变 —— **噪声和要测的改动一样大**。修法三件事缺一不可（`EffectSweepBatch.SeedAndReset`）：`useAutoRandomSeed=false` + 显式 `randomSeed` + 先 `Simulate(0, restart:true)` 复位再推进。修完 2968 行只剩 11 行不同（都是 1 个像素）。**顺带排除的两个错嫌疑**：`ps.Play()` 和 `fixedTimeStep` 都不是原因，别往那查 |
| **🆕 `SpriteRenderer`/`SpriteMask` 的 sprite 不会被导出** | 精灵是 bundle 资产，克隆成工程 prefab 时引用落不下来 —— Unity 写的是 **guid 全 0 的伪引用**，`EffectDiag` 里能看出是 `<null>`，但**光看 prefab YAML 会以为有值**。后果不止「精灵自己不显示」：`maskInteraction=VisibleInsideMask` 的粒子全靠它裁形，遮罩一空整块效果渲成空。修法见 P0-h |
| **🆕 判「材质不对」还是「prefab 不对」要用交叉材质** | 把 A 的材质贴到 B 上再渲一次：①导出 prefab + 原版材质 能渲出来 → 材质的锅 ②照样渲不出来 → prefab/渲染状态的锅。这一刀把排查面砍掉一半（P0-h 就是靠它锁定的） |
| **🆕 隔离实例别用 `SetActive(false)`** | 停用再启用会把粒子系统重置，活粒子直接变 0 —— 于是「换了材质也渲不出来」这种**假结论**就出来了（实测踩过）。正确做法：把另一个实例**挪到画面外**（x=10000） |
| **🆕 材质缓存键是「材质名\|shader 名」，会串** | `WarpforgeEffectBinder.Cache` 用这个名字做键，而「Glow Additive」「Smoke」这类名字在几百个效果里重复。实测 **5 个键（22 个效果）同名但属性不同**，先建的会顶替后面的。量它的工具：`MatKeyCheck` |
