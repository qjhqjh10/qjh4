## 一、规则（**照规则书，不是照客户端代码**）

## 三、原版的界面结构（从 prefab 节点树抄的）

出处：`d:/2/解包整理/03_界面UI/菜单/`（来自 `menus_assets_all.bundle`，
18435 个 GameObject json + 33020 个 RectTransform json）。格式：`节点 (sizeDelta.x × sizeDelta.y)`。

> ⚠️ GameObject json 里**没有 `m_PathID`**、RectTransform **没有 `m_Name`** ——
> 要靠 `m_Component` 反查 `RectTransform_<pathID>.json` 才能重建树。
> 而且**脚本类名不出现在节点名里**，所以树里看不到 `CardNameFilter` 这类名字。

├── Header: Instructions (400×50)、Wildcard Counter (400×0)、Close (150×60)
├── Sidebar (335×-85)
│   ├── Window Options (327×205)  ← Buttons、Deck Name (×50)
│   ├── Deck Details (335×-275)
│   │   ├── Deck List drawer (325×-5)
│   │   ├── Deck Counter Drawer (0×256)
│   │   └── Cosmetic Drawer (0×1024)
│   └── Footer (0×112): Done (189×50)、Counter (75×50)
├── Card Display (0×0)
│   ├── Scroll View (-163×-85)  ← Content (0×768)、Reference Card Pointer (194×45)
│   ├── Card Filters (332×-85)
│   └── Card Drag Controller (100×100)

**关键子模板尺寸（实测）**：
`Collection Card` **350×512**、`Collection Deck` **250×405**、
`Card in deck container` **570×620**、`CardUI` / `CardFrame` / `CardImage` 都是 **3×3**
（由 LayoutGroup / AspectFitter 驱动，不是固定值）、`Card Cost` 26×20、`Deck Name Filter` 335×80、
卡组列表项 `Cards in deck panel` 12×83。

**一个容易想错的点**：卡组编辑列表里**不是缩小的卡图**，而是 **54 px 高的行**
（`40k_deck_cardlist_bg` 318×54，行内子节点是 `Card Name` / `Card Cost`(26×20) / `Card counter`）。
展示完整卡面缩略图的是右侧 `Card Display > Scroll View`（LayoutGroup 自动排版）。

## 四、⚠️ 参照图**不能**用

`资料/原版参照图/Unity参照管线_0825/shots_ui/ui_prefabs/` 那 **218 张 PNG 全是坏的** ——
实测**每张都恒为 27260 字节、1920×1080、内容全黑**（`ui_004_DeckEditingMenu.png` 全黑，
`data/prefab_names.txt` 是 0 字节）。**只能当文件名单用**（能看出原版有哪些窗口 prefab）。

唯一有内容的菜单实拍是 `shots_ui/menu_full_0825.png`（1920×1080，但那只有顶栏）。

⇒ **卡组编辑器没有可用的视觉参照，要照第三节那棵树 + 第二节的素材还原。**

**为什么是坏的（2026-09-12 查明，不是「进不去游戏」）**：
生成它的是 SceneJumpShot **v2.2**（现在的 mod 是 v3.6）。那一版做了两件错事 ——
① 挑相机时取「名字含 ui 的第一个相机」→ 拿到的是战斗场景的 `UI Camera`，
  它的 `clearFlags = Nothing`，`ReadPixels` 读回全 0；
② 把所有 Canvas **强制成 `ScreenSpaceOverlay`** —— Overlay canvas 不经过任何相机，
   `cam.Render()` 进 RenderTexture 时当然什么都不画。
**证据**：同一轮的 `battle_ui_cam_BoardCamera_0825.png`（mean 95.55）是正常渲出来的，
两张只差一个 `clearFlags`；而且那 217 张**字节完全相同**（同一个 MD5、都是 27260 B）
—— 是「每次都在读同一张空 RT」，不是「每个 prefab 各自渲成黑」。
v3.6 把 Overlay 改回 `ScreenSpaceCamera` + 赋 `worldCamera` 之后图就正常了
（`资料/原版实拍/wf_run/shot_battle_hand.png` 就是那么拍的）。

**顺带一个更要紧的结论**：`资料/原版参照图/` 一共 239 张 PNG，其中
**可信的真渲图只有 11 张互不相同的**（`shots_battle/` 4 + `data/` 4 + `pitch_matrix/` 3），
`shots_ui/` 那 224 张里实际只有 1 张可用（`battle_ui_cam_BoardCamera_0825.png`）。
引用参照图之前先看文件大小/内容 —— **别把那份目录当成「原版长什么样」的标准答案**。

> 另一处容易误判的：`shots_ui/menu_roots/` 5 张**字节完全相同**（291390 B / 同一 MD5）。
> 那**不是渲染失败** —— 内容是**一张真实的主菜单整屏**（很暗，mean 7.89），
> 只是那一版抓图是「整屏抓、逐根切换」，五个场景根（含 `004_UICamera` / `005_GameUI`）
> 拍出来当然一模一样。所以它**可以当一次主菜单参考**，但别指望 5 张能看出 5 个根的区别。

## 五、卡面本身怎么组装

我们自己的 `CardView` 是**四层**（`Assets/CardPresentation/Core/CardView.cs`）：

```
info   数值/名字/关键词（我们画的，透明底）   z -0.02  ← 最前
frame  卡框（原版 PNG，UV 按 alpha 包围盒自动裁）  z  0
art    立绘（原版插画；没有对应文件退回占位图）  z +0.03
rim    状态描边（独立的一圈，不是卡面的一层）
```

**原版卡面是两层**：`40k_Cardframe_{troop,stratagem}_<阵营>_SDF[_tier1..4]`（**144 个**）
+ 立绘（`_inf_` 827 / `_veh_` 270 / `_war_` 30 / `_monster_` 4 = **1131 张**）。
数值和描述**没有独立 sprite**，原版是 TMP 文本 + `Card Text smooth background`。
**没有 warlord 专用卡框** —— 督军靠 `AA_HB_*` 整图。

## 六、跟原版**不一样**的地方（先说清楚，别当成 bug）

1. **存档在本地**。原版卡组存在服务器（`CardDeck.syncedToServer` / `deckId`），
   单机没有服务器，落到 `Application.persistentDataPath/WarpforgeDecks.json`（`RuleEngine/Data/DeckStore.cs`）。
2. **没有「拥有」概念**。原版的 `DeckUtility.ValidateDeck(validateOwnership: true)` 会检查你有没有这张卡
   （要开包/合成）。我们把卡池全部 **1126** 张当已拥有（单位 586 / 战术 445 / 督军 56 / 防御 39；
   ⚠️ 别跟上面立绘的 **1131** 张混 —— 那是插画文件数）—— 单机没有获取途径，卡池就是收藏。
   ⚠️ **2026-09-16 更正**：这里原来写 **1130** 张（战术 **449**）—— 实际 **1126 / 445**
   （生成器删掉了 5 张幽灵卡与 `SW_Aggressor` 重复行；`cards_engine.json` 的 `count` 字段 = 1126）。
3. **没有异画/卡背/战吼**（原版 `DeckCosmeticDrawer` / `WildcardDisplay`）。
   素材切出来了，但那是装饰系统，等主体做完再说。
