## 一、A176 —— `Use super sampling` 的真实现 / URP 落点 / 哪一档算 Ultra

### 1·1 结论（原版真实现 = **渲染缩放**，不是 MSAA）

- 开的是 **URP `UniversalRenderPipelineAsset.renderScale`**：常态 **1.0**，开超采样 **2.0**。
- 三层门（全在反编译里逐句读到）：`!Application.isMobilePlatform` **且** 该画质档 `allowSuperSampling` **且** 玩家开关。

| 证据 | 位置 |

| `set_renderScale(...)` 唯一两个调用点 | `decomp_full/QualitySettingsManager.QualityDefinition__ApplyResolutionScale.c:7` · `…QualityDefinition__ChangeResolution.c:54` |
| 两个常量 = **1.0 / 2.0**（4B float，`.rdata`） | `工具/read_literal.py` 读 `0x1834b2bb8`→`1` · `0x1834b2bbc`→`2`（脚本 `资料/战斗规则与数值_出处.md` §三） |
| 取值分支：`fVar4 = DAT_1834b2bb8`（1.0）；若非移动端 ∧ `+0x2d`(allowSuperSampling) ∧ `GameStaticData+0x124`(开关) ⇒ `DAT_1834b2bbc`（2.0） | `…ChangeResolution.c:38,43,45` |
| 行的**显隐** = `SetActive(toggleGO, !isMobilePlatform & allowSuperSampling)` | `decomp_full/GraphicsTab__ConfigureSuperSamplingVisibility.c:21,27,29` |

| 真正生效点 = `ChangeResolution()` ← `SceneChanged()` / `ApplyGraphicsQuality()` | `decomp_full/QualitySettingsManager__SceneChanged.c:6` · `…__ApplyGraphicsQuality.c:66` |

- **不是 MSAA**：MSAA 走的是 Unity 画质档本身（`QualitySettings.SetQualityLevel(qualityNumber)`，`…QualityDefinition__TryEnableQuality.c:23-25`）；
  另有一个**卡牌 AA 的 shader 关键字**开关 `enableCardsAntiAliasing`@0x2c（`TryEnableQuality.c` 的 `Enable/DisableKeyword`）—— 与超采样无关。
- ⚠️ `QualityDefinition.ApplyResolutionScale(float)`（公开那个）**全量反编译里零调用者**（`grep -rl ApplyResolutionScale` 只命中它自己）
  ⇒ 本 build 里是**死代码**（推断：`QualityDefinition` 不是 `UnityEngine.Object`，也挂不上 Inspector 事件；**这条是推断、未坐实**）。
- 搜过的词/范围（按本仓规矩列全）：`/d/2/tools/decomp_full/` 内容搜 `supersampl`（大小写不敏感）= **4 个文件**（上表已全覆盖）；
  文件名搜 `super` = `GraphicsTab__ConfigureSuperSamplingVisibility` / `…__SuperSamplingToggleClick` / `QualitySettingsManager.QualityDefinition__get_AllowSuperSampling` 等；
  文件名搜 `graphic|quality` = **`GraphicsTab__*` 14 个 + `QualitySettingsManager*` 25 个**（另 `MediaTab__SetupVideoSettings` 是视频设置，无关）。
  ⛔ 「`super sampling` 带空格」在反编译 C 里搜不到东西（那是 UI 文案/字段名，不是标识符），别据此说「没有」。

### 1·3 ⚖️ 待裁：**我们哪一档算 Ultra**（这一格我查不出唯一答案，见下）

- 原版门里那个「哪档允许」= `QualityDefinition.allowSuperSampling`（0x2d），**只有 Ultra(=4)** 为真（五档 0/0/0/0/1，已知值）。

  ⇒ 简报里「我们自己的 5 档」**不成立**（现读：2 档）。`Shell/SettingsWindow.cs:163-171` 早就写着「与它那 5 档**没有对应关系** ⇒ 不硬映射」。
- 两个候选（**都要调度台拍**）：
  - **(a) `PC` == Ultra**：机械对得上原版的第一层门 —— 原版的 `!isMobilePlatform` 正好是**我们这两档分开的那条轴**
    （`Mobile` 档在 `QualitySettings.asset:61-62` 写了 `excludedTargetPlatforms: Standalone`）⇒ 桌面端跑的就是 `PC`。
    落法：`QualitySettings.GetQualityLevel() == PC(1)` 时才显示那一行 / 才允许开。
  - **(b) 桌面端恒显示**（忽略档位门）：简单，但**偏离**原版「只有 Ultra 有这一行」（Ultra 之外的档原版是**没有**这行的）。
- 🔴 **没查清的一小块**：`QualitySettings.SetQualityLevel(0)`（那个 `Standalone` 被排除的 `Mobile` 档）**在 player 里到底生不生效** ——
  Unity 引擎行为，静态读不到；我们游戏内又有 `CycleQuality()`（`SettingsWindow.cs:725-733`）会去切它。
  → 若它有实效，则 (a) 的判据要按「当前档 == 1」而不是「平台不是移动端」，两者会分叉；⛔ 别用猜测顶替，**要真 Play 或一个 player 断言**。
