## 一 · A269 —— 口径判定（**先判后改**）

### 1·1 判据（本地真源码，不是推断）

`MyGame/Library/PackageCache/com.unity.ugui@27635d171b1a/Runtime/UGUI/UI/Core/ScrollRect.cs`

| 位置 | 内容 |
|---|---|
| `:1332-1352` `AdjustBounds` | **"Make sure content bounds are at least as large as view by adding padding if not."** / **"Scrolling is *only* possible when content is *larger* than view."** ⇒ 内容比视口小时，`contentSize` 被**撑到 `viewBounds.size`** |
| `:1281-1294` `UpdateBounds` | 每帧把 `AdjustBounds` 的结果**存回 `m_ContentBounds`** ⇒ 后面一切读的都是**调整过**的值 |
| `:1386-1426` `InternalCalculateOffset` | `maxOffset = viewBounds.max.y − max.y`，**且 `if (maxOffset > 0.001f)` 才取** ⇒ **恒 ≥ 0**（另一个方向同理夹负） |

⇒ **口径裁定**：空列表 / 内容矮于视口 ⇒ **可滚极值 = 0**。
⇒ A182 那条断言（`Editor/RewardsScene.cs`：空列表 ⇒ `MaxOffset == 0`）**期望值是对的**；
**错的是我们 `MenuScroll.MaxOffset` 给的是「没经过 `AdjustBounds` 的裸值」**（空列表 ⇒ `ContentX2 − ViewHi` = 211.98 − 990.77 = **−778.79**）。

### 1·2 落地（`Shell/MenuScroll.cs`）

```csharp
public float MinOffset { get { return Mathf.Min(0f, ContentX1 - ViewLo); } }   // 原：ContentX1 - ViewLo
public float MaxOffset { get { return Mathf.Max(0f, ContentX2 - ViewHi); } }   // 原：ContentX2 - ViewHi
public float ClampLo   { get { return MinOffset; } }                            // 原：Mathf.Min(0f, MinOffset)
public float ClampHi   { get { return MaxOffset; } }                            // 原：Mathf.Max(0f, MaxOffset)
// SetOffset 里那句自写的 Mathf.Min(0f,…)/Mathf.Max(0f,…) 改成读 ClampLo/ClampHi（原来是第二份夹法）
```

🔑 **行为零变化的证明**：`SetOffset` 原来夹的是 `Clamp(o, min(0,MinOffset_raw), max(0,MaxOffset_raw))`；
新的 `MinOffset/MaxOffset` 就是 `min(0,·)`/`max(0,·)` 本身 ⇒ 夹出来的区间**逐字相同**。
⇒ 全工程 **~30 处读 `MaxOffset` 的断言/调用**只在「内容 ≤ 视口」那一种情形下读数改变（原来给负值、现在给 0），
**没有一处依赖负值**（逐处 grep 过：非断言的只有 `ScrollBy(MaxOffset)` 与 `if (MaxOffset > 0f)` 两种守卫）。

### 1·3 连带订正（**旧口径作废**，铁律 5）

上一轮有一句**明文写下的旧口径**：「`MaxOffset` 本身是**负的**，⛔ 别把它当「能滚多远」，要判「能不能滚」看 `ClampHi/ClampLo`」。
A269 之后它**不再成立**（两者现在是同一个数）。逐处改掉：
