## 三、顺手发现的（⛔ 一个都没改）

1. 🔴 **`Premium Panel/Title` 我们这一侧是「折行」的，原版是「不折行」**（与 A274 同一条 TMP）。
   判据：原版那条 TMP 的 `m_TextWrappingMode = 0`（简报里也写着）；
   而我们 `Shell/CampaignTab.cs:721` 走 `Label.SetAutoFitBox` → 内部第一句就是 `SetWrapWidth(worldW)`
   → `Core/TmpFont.cs` 的 `SetWrapWidth` **无条件** `t.textWrappingMode = TextWrappingModes.Normal`
   ⇒ 我们这一颗 = `1`。**还没查清**：`autosize=1 + wrap=0` 这一组合原版实际收敛到多少 px、
   以及我们折行后是几行（批处理下要跑一次 `RewardsScene.Run` 才知道）⇒ ⛔ 不猜。
   **这不是「影响小」，是「判据齐了但要不要照做要先裁定」**（改它会让上面两条边缘断言的行为一起变）。
2. 🆕 **一个名字里带斜杠的节点**：成员行那颗 `Individual rating value` 的**真名是 `Draft Rating/Individual rating value`**
   （`Shell/AllianceMemberTab.cs` 的 `Rating()` 里 `name + "/Individual rating value"`）。
   `MenuDraw.Node` 是 `new GameObject(name)` ⇒ 斜杠是**名字的一部分**；
   本文件的 `FindChild` 是**按整名字精确比**（`GetComponentsInChildren` + `t.name == name`）⇒ 取得到；
   ⛔ **但任何用 `Transform.Find("…")` / `GetChild` 路径语义的取法都会静默取不到**（把它当路径）。
   已写进件3 那条断言的文案里（`Editor/MainMenuScene.cs:4651-4653`），供后来人看见。
3. 🆕 **`MainMenuScene.Run()` 体内已经有一个方法级局部 `chat`**（`:516`，主菜单那扇 `ChatPreview`）
   ⇒ 往这个巨型方法里再加同名局部会 `CS0136`。我把件3 用的那个改名为 `a263Chat` 并在注释里写明了原因。
   （`var search` 在 `:4391` / `:5644` 两处是**并列块**里的，各自合法。）
4. **`Editor/RewardsScene.cs` 已有现成助手 `CheckFontWindow(Transform card, string nodeName, float minPx, float maxPx, string what)`**
   （`:4752`）—— 它读的就是 `Label.FontSizeMin/Max` 并经 `Label.FontSizeToPx` 折成 px。
   件1 直接复用了它（⛔ 没有另写一份读口 = 两处写同一条规则迟早不一致）。
