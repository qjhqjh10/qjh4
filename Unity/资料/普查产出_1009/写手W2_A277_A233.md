## 一、A277 —— `ApplySoftEdges` 在 `soft = (0,0)` 时第 3 行早退（图形那半）

### 1) 判据
原版 `RectMask2D`：**硬裁四边都求交、与 `m_Softness` 无关**（uGUI `Culling/Clipping.cs:17` `FindCullAndClipWorldRect`；
`m_Softness` 只经 `UpdateClipSoftness()` 当**渐隐带宽**）⇒「两分量都 0」= **没有渐隐带**，⛔ **不是「不裁」**。

### 2) 改了什么（`Shell/MenuDraw.cs`）
| 行 | 改动 |
|---|---|
| `:445-447` | 头部 doc：`softPx 两分量都 0 ⇒ 立刻返回（硬边 = 现有行为）` **订正**成「没有渐隐带、**但仍然硬裁**」 |
| `:460-466` | **删掉第 3 行那句 `if (softPx.x <= 0f && softPx.y <= 0f) return;`**（留了更正痕：原写法 + 错因） |
| `:475` | 新增 `PxRect visRaw = vis;`（裁之前那一份） |
| `:487-509` | 🆕 **零 softness 分支**（在 `ClipVisToClip` **之后**）：`if (!SameRect(vis, visRaw)) PlaceCell(q, vis, vis, uv0);` + `ArmSoftRebuild(...)` + `return` |

🔴 **关键（最容易做错的一点）：光删那句早退是不够的。**
删掉早退后 `soft = (0,0)` 会一路走到 `SoftCuts`，而切刀位置 = `clip.x1+0 / clip.x2−0` —— `ClipVisToClip`
**已经**把 `vis` 裁到框内 ⇒ 两个候选都**不严格落在 `vis` 内部** ⇒ `nx=ny=0` ⇒ 落进「整块不切」支路，
而那一支**只在 `SoftEdgeRebuild != null` 时才 `PlaceCell`** ⇒ **首次调用时宿主仍停在原来那个越界矩形**
⇒ 越界那一段**照样画**（= 什么都没修）。所以修法必须是「裁完把 quad 摆到裁剩那块」——
`PlaceCell(q, vis, vis, uv0)`（`uv0` 已是 `ClipVisToClip` 缩过的那份 ⇒ 几何与 uv 同步，不会把图压扁）。
> 复算证据：`/tmp/w2_sim.py`（纯算术，不碰 Unity）—— 越界那颗：`PlaceCell(裁剩那块)`；框包住那颗：不动。

### 3) 断言在哪（`Editor/ShellScene.cs`，新增 ⑤·d-2 节，`:1105-1161`）
- `:1117` `Section(...)`；`:1122` 建一颗 **400..900**、框 **400..700** 的 quad（**不带 `clip` 建**，
  否则 `MenuDraw.Rect` 自己先裁一刀、本条就测不到了）；`:1130` 调 `ApplySoftEdges(..., soft=Vector2.zero, ...)`。
- 断：**渲染矩形右沿 = 700**（`:1133`，量的是 `QuadPxRect` = 世界→px 反推的**渲染真值**，⛔ 不是实参）、
  左/上/下沿不动（`:1136-1138`）、**uv 宽 = 0.6**（`:1139`，只缩矩形不缩 uv = 把图压扁）。
- **成对**（判别力，`:1144-1160`）：同一个矩形、框**包住**它 ⇒ 右沿仍 **900**、uv 仍 **1.0**
  （少了这条就分不出「按需裁」与「无条件缩到框沿」）。
- **改坏法**：把 `Shell/MenuDraw.cs:461` 那句早退加回去 ⇒ 第一条断言的 700 变回 **900** ⇒ **红**。
- ⚠️ **前提护栏**：`:1127` 先断「调 `ApplySoftEdges` **之前**它就是 900」——
  否则「裁到 700」可能只是「本来就在 700」。

### 4) 一个「我们挑的」决定（请调度台过一眼）
零 softness 分支**照相邻两支一样挂了 `ArmSoftRebuild`**（之后再改几何时裁切跟着重算）。
不挂的话，改完几何就会把越界那一条**静默**又画出来（正是 A225-① 那个病）。**这条没写断言** ——
它属于「我们挑的做法」、不是原版判据；要否决就把 `:507` 那句删掉即可（画面在今天的调用点上**无差别**）。

### 5) 行为面
**零行为变化**（今天四条路里仍带 `clipSoftness > 0` 闸的 `Rect`/`Nine`/`Tiled` 不受影响；
`ImgTex` 那道闸本批按 A233 去掉了，但**没有调用点给它传 `(0,0)`** ⇒ 实际行为一样）。
⚠️ 已在 `ShellScene.cs:1113-1115` 与 `MenuDraw.cs:498-500` 两处**就地写准**（别再照旧说「四条路都带闸」）。

## 三、顺手发现（⛔ 只报不改）

### 1) 🔴🔴 「裁过了、但没落在任何切刀之间」的件：`vis` 裁小了、**宿主几何一个字都没动** ⇒ 越界像素**照旧画**
- **现场（现读代码）**：`Shell/MenuDraw.cs:513-527`（`nx == 0 && ny == 0` 支路）里的
  `if (q.SoftEdgeRebuild != null && !SameRectNear(QuadRectPx(q), vis)) PlaceCell(q, vis, vis, uv0);`
  —— 那个 `SoftEdgeRebuild != null` 闸的**前提**是注释里写的「**首次切进来时 `vis` 就是宿主自己的矩形**」，
  而 **A225-① 已经在它前面插了 `ClipVisToClip`** ⇒ 前提**不再成立**（首次调用时 `vis` 可能就是**裁小过的**那份）。
- **实算（`/tmp/w2_sim.py`，纯算术）**：练习窗 `DeckRow_0` 第 2 列 `IsPlayerDeck`（`Purity Seal_02`）
  = 画布 **587.34..640.27**、y **358.65..463.21**；视口 **261.28,262.64..634.88,803.43**、带 **23**（上下内沿 285.64 / 780.43）
  ⇒ 右侧越界 **5.39px**；`ClipVisToClip` 把它裁到 **..634.88**，可是切刀候选 `clip.x2−23`=**780.43**、
  `clip.x1+23`=**285.64** **都不在** y 范围里、`clip.x2−0`=**634.88** 又**等于**裁完的 `vis.x2`（不满足「严格落在内部」）
  ⇒ **0 条切刀** ⇒ 走「整块不切」支路 ⇒ 首次调用 `SoftEdgeRebuild == null` ⇒ **宿主不动** ⇒ **那 5.39px 仍然画在视口外**。
- **它也是 `SoftEdgeUvDrifts` 的一个假来源**：那一支末尾的 `CheckSoftEdgeUv(q, uv0)` 里 `want` = **裁过的** `uv0`（0.898…）、
  `got` = 宿主自己的 uv（1.0）⇒ **计数会涨**。⚠️ 这个计数器**只有 `Editor/ShellScene.cs` 在断**（断的是外壳自己那几扇窗），
  `MainMenuScene.Run` **一条都没断** ⇒ 练习窗这一档**静默**。
- 🔴 **这很可能就是 A225-① 的残件**：`普查产出_1008/波A_A225_三条红.md` §① 结论写着「**附带修掉**「那 5.39px 一直画在视口外」这处真偏离」
  —— 但同报告 **证据 #9** 的那句几何核对是**算错的**（`vis.y = 358.65..463.21` **并不含** 285.64；
  而实测切线条数 **2** 恰好 = 「两格各 1 条（无 y 切刀）」= **我这条结论** ⇒ 实测数反而**支持**「y 没切」）。
  ⇒ **A225-① 修掉的是「假切口 + 那条断言的红」，不是越界像素本身**（对「裁了但没切刀」的件）。
- **建议修法（一行，留给调度台分派）**：把那个闸从
  `if (q.SoftEdgeRebuild != null && !SameRectNear(...))` 改成 `if (!SameRectNear(...))`
  —— 未裁时 `QuadRectPx(q)` 与 `vis` 在 0.05px 内（`SameRectNear` 就是为这个浮点往返准备的）⇒ 仍然一个字不动；
  裁过时才会真正 `PlaceCell`。**验收**：练习窗第 2 列那几个 `IsPlayerDeck` 的并集右沿 ≤ **634.88**
  （`UnionQuadRect`）+ `MainMenuScene.Run` 的切线条数仍为 0/0 + `ShellScene.Run` 那 5 条 `SoftEdgeUvDrifts == 0`。
