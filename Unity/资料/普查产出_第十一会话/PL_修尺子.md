## 六 · 第二个缺陷（`--rt` 跨文件）—— **只出声、行为不动**（含「为什么不能顺手修」）

### 现场（本件现读数据，逐条可复核）

```
    → 2684 'BackCanvas'  ls = 1
      → …（3498 → 2849 → 2687 → 3083 → 3568）
```

`parent_rect_of` 在 `1395` 处 `rt is None` ⇒ **原来直接 `return screen_rect, None, (1.0, 1.0)`、一个字不说**
⇒ `--rt 3568` 给 **1482.88×781.08**（比整屏还大，因为退回「整屏当父 + `sd` 裸值」）。

### 试过「续爬」，**实测更坏 → 撤掉**

把那一支改成 `continue`（当恒等帧、继续往下算）之后实跑：**整张表塌成 0**，连根 `BackCanvas` 都是 `0.00×0.00`
（`⇲ls=0,0`）。原因就是断点**下面一级** `2759 Canvas` 的序列化 `m_LocalScale` 是 **`(0,0,0)`**
（原版 prefab 里存的动画/隐藏态 —— 本工具文件头已记「本包 390 个 RT 是 `(0,0)`」、`--no-ancestor-scale` 那条 help 也点了名）
⇒ **`continue` 让整棵子树乘上这个 0**。

⇒ 结论：**「退到整屏」不是偷懒，而是这个导出形态下唯一还能读的兜底**。要真修得先定
「`(0,0)` 帧算不算数 / 画布那一级该取哪个值」的**口径** —— 那是另一笔账（⛔ 本件不自己发明口径）。

**代价（已写进那句警告，读表的人必须知道）**：凡走这一支，被丢掉的**不止断点那一级**，
而是「断点以上已算出的框 + 下面所有级」一起退化成「整屏 + 缩放 1」⇒
**位置与宽高都可能整体偏**，`--rt <目标>`（父链跨文件时）**不能当判据**，要按名 / `--rt <根>` 查。
