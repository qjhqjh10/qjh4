## 5. 实现形状与理由

**形状**：把内联那一段收成一个**具名口**（判据**只此一处**，照 `RuleCore.StunStillOnBoard` 的先例）：

```csharp
static bool TryRedirectAttackToBodyguard(BattleContext ctx, int p, int atkSlot, int tgtP,
                                         ref int tgtSlot, ref UnitState target)
```

**四道闸**（判据全是从原版读来的；**执行顺序**按「先跑最省的」排 —— 原版 `CanTriggerAbility.c:126-141`
里 `IsRightContext` 在前、criteria 在后，而**任一道假都不产出任何日志/事件**
（原版只在命中后才 `AddRedirectedAttack`）⇒ 交换顺序没有可观察差异）：

1. `target.IsWarlord`（原版：`targetCriteria` 筛被打者）
2. 扫**督军那一方**的场，逐个要 `IsAlive && !IsWarlord && !Has(jam) && Card.Bodyguard`
   （原版：扫**全场** `unitsInPlay`，由第 1 条的 criteria 收窄到这一侧；`jam` 例外见 §2.3）
3. 攻方：`attacker != null && attacker.IsAlive`
4. （第 2 条里那个 `IsWarlord` 跳过是**旁证**，见 §9）

**两条不变式（写进注释，⛔ 别顺手改回去）**：
- **不复检目标合法性**：原版 `AllowResolveAttack.c:134-136` 对 `0x4a` 直接 `return 1`
  ⇒ 带 `Stealth` 的替身照样挨打。我们的换目标**排在 `IsValidTarget` 之后**，顺序正好对上。
- **一记只改一次、改完不再进这一条**：原版整段取消判定跳过 `redirectedAttack`；
  我们这边新目标是部队 ⇒ 第 1 条判据当场假，结构上不会递归。

**为什么「就地换目标」是等价的**（原版是「取消 + 重排」）：原版排出去的那条 `redirectedAttack`
由**同一个** `_ResolveAttack` 协程结算（同一套伤害/反击/死亡/触发），而我们这边：
- 打法 = `ranged` 入参原样不动（= 原版 `actingCard.currentAttackType`）；
- 反击取自**换完之后**的 `target.Attack`（`RuleCore.cs` 那句 `int counterAtk = target.Attack;`
  在重定向**之后**）⇒ 反击来自替身 ✓；
- `Emit(EvtKind.Attack, …)` 与 `BroadcastWhen(…Attack…)` 都在**换目标之后** ⇒
  事件里的目标就是替身（原版那一记被 `:541-587` 取消在 `:988` 广播之前 ⇒ 只有重定向那一条广播）✓；
- `Sentry`/`Shuriken`/`Camouflage` 那些读的都是换完之后的 `target` ✓。

**没有新增「会改引擎状态的动作路径」** ⇒ 两个记账口（`LocalAct` / `SimpleAI.ExecuteAction`）、
本地录像、联机两边都不受影响：重定向是 `DeclareAttack` 内部的**确定性函数**（只依赖棋盘状态 +
同一个 `ranged` 入参），回放/对端会算出同一结果。
