（本次的实例：`BoosterInfoPopup` / `DailyRewardPopup` / `ShopWindow` / `ItemDrawer` 四颗**都挂着** `TextMeshProUGUI + EverguildButtonMaterialModifier + ContentSizeFitter + EverguildTextController`。）

### 3. 🆕 **「原版的框高」⛔ 不能照抄**（一条会让人改错的陷阱，建议记进 `A1226`/`A1262`）
只看 §二那张表会得出「我们的框**高**也比原版大」（Booster `71.0` vs `43.56` = **1.63×**）⇒ 想把它改成 43.56。
**⛔ 别改**：两边的行盒系数不一样，**那个 1.63× 刚好把行盒差抵消掉** ——
- 原版 `Pragati` 行盒 = `(70−(−20))/95 =` **`0.9474 em`**；
- 我们 `NotoSerifCJK-Regular SDF` 行盒 = `lineHeight 71.85 / pointSize 50 =` **`1.437 em`**；
- 比值 = **`1.517`** —— **正是 `A1262` 量出来的那个数**（`55.905/36.851 = 1.517`）；
- 而我们的框高 / 原版的框高 = `71.0/43.56 =` **`1.63`** ⇒ **`46.8 vs 46.0` 的「竖界字号」几乎相等** ⇒ **两边收敛到同一个字号**。
⇒ **框高照原版改，会把我们的字按 `0.9474/1.437 = 66%` 压小** —— 那是**制造偏离**，不是消除偏离。**这条要记成坑。**

### 6. 🆕 一条可复用的只读手法（下一个会话会用到）
「一颗 **`Dynamic` 模式的 TMP 字体资产**，某串在某字号下有多宽」**静态可算**：
从 `bundle_fonts_assets_all/MonoBehaviour/<字体>.json` 读 `m_FaceInfo`（`m_PointSize` / `m_UnitsPerEM` / `m_Scale` / `m_AscentLine` / `m_DescentLine`）+ `m_CharacterTable`（`m_Unicode → m_GlyphIndex`）+ `m_GlyphTable`（`m_Metrics.m_HorizontalAdvance`），
则 `宽 = Σ advance × (fontSize / pointSize × scale)`、`行盒 = (ascentLine − descentLine)/pointSize × fontSize`。
⚠️ **原版那份字体资产是真静态的**（`m_GlyphTable` 非空）；**我们工程那份是 `Dynamic` ⇒ 表是空的、算不了**（同 `Core/TmpFont.cs` 那句「按字体标定」）。
