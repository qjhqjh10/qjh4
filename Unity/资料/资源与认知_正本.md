## 二、五个关键认知

1. **原版的卡牌动效不是 AnimationClip，是 DOTween 代码。**
   证据：反编译的 `DrawCard` 里直接写着 `DOScale` + `SetEase`；`CardScript` 有 423 个方法。
   全项目只有 **98 个唯一 clip**，用在 DOTween 补不出来的地方（着色器参数、粒子开关、后处理）。
   → **好消息**：代码驱动路线被验证可行，而且**74 个 `UnitTweenSO` 的 ease/duration/loops 数值可以整套搬**。

2. **没有 Spine。** 盘点说的「Spine 卡牌动画 2334 文件」是**误标** —— 那 2334 个全是 `CardAnim` 的 `AnimInfo` JSON。
   三层穷举 0 命中。

3. **原版战场就是 URP，特效不会变粉红。** 之前担心的管线兼容问题在原版素材上不存在。

4. **原版特效不需要服务器。** 实测：本地加载战场 bundle 进战斗，火焰/烟/碎片都是活的；
   catalog 里 84 个 bundle 全部解析为本地路径，一个不缺。服务器只影响卡牌数据和对局逻辑。
   **详见 `特效还原_进度与交接.md` 第二节。**

5. **🆕 解包资源里没有卡牌数值 —— 只有图和 ID。**（2026-09-12 全库验证）
   立绘/卡框/卡背/语音/动画 ✅ 在；卡牌 **ID**（哪个卡包有哪些卡）✅ 在；
   但**费用/攻/血/护甲** ❌ **不在**（原版是联网游戏，数值在服务端）。
   全库 grep `"(attack|health|cost|damage)"\s*:\s*\d` **0 命中**；客户端只有
   `RawCardScript.cs` / `CardData.cs` 这样的**类定义**，没有数据资产。
   - **数值的唯一来源** = `D:\2\Warpforge部队卡片` 的**卡面照片 OCR**
     （`d:/warpforge/tools/ocr_cards.py` → `card_stats_raw.json` → `merge_card_stats.py` → `card_stats.json`）
     ⚠️ **是 OCR，会有错**：87 张没读到值、47 处靠编辑距离模糊匹配、个别 `desc` 有重复词
     （总张数**一律写成指针** → `资料/阵营推进_清单与交接.md` §一）。**拿不准的回查 `ocrSrc` 指向的原图**。
   - 🔴 **2026-09-23 更正**：原文写「效果文字更权威的来源 = `d:/warpforge/data/i18n/zh_CN.csv`，
     第一列英文、第三列中文，98% 的卡能对上」—— **两处都不成立**：
     ① 原版**客户端根本没有中文表**（246,807 个文件扫中文串零命中 · 84 个 bundle 无本地化包 · I2 词条表在**远端 CCD**）；
     ② 那份中文**是我们自己译的**，源头 `数据/卡牌翻译/zh_cards.json`（`工具/gen_cards_engine.py` 读进来）。
     ⇒ **游戏里卡面走的就是它**（`BattleDriver.FaceTextFull`：`DescZh` 有就用中文）—— **看中文 = 看玩家实际看到的东西**。
