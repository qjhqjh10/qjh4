## 二、几个关键设计决策（别轻易推翻）

### 1. 布局用**归一化坐标 + 自适应正交相机**，不用 uGUI

用户要求「1080p / 2K 这些能自由切换」。做法：

- 可见**高度恒定 10 世界单位**，宽度 = 高度 × 宽高比；归一化坐标 (0,0)=左下、(1,1)=右上
- 窄屏（4:3）可见宽度小于设计宽度时整体乘 `Scale` 缩下来，**不裁切**
- 超宽屏多出来的宽度就是留白

**为什么不用 uGUI 的 CanvasScaler**：卡牌要跟特效（世界空间粒子）严丝合缝对齐，
走 UI 的话每次都要在 RectTransform 和世界坐标之间换算，粒子还会被 UI 排序规则缠住。
世界空间只要一处换算，而且超宽屏的行为比 CanvasScaler 的 match 模式更可控。

### 2. 占位美术**刻意不依赖任何资源**

连费用/攻/血的数字都是画进贴图的（5×7 点阵）。**真卡面走 `Core/CardArt.cs` 取图**；
`CardView.FaceTexture()` 只是**没有美术时的占位** —— 布局/状态/动效都不用动。

> TMP Essentials 已由 `TmpSetup.ImportEssentials` 命令行导入（37 个文件落在 `Assets/TextMesh Pro/`，
> 可重跑）；中文卡面走 TMP + Dynamic CJK 字体。**别手点菜单** —— 那条路在批处理下不落地（详见 §四）。

### 3. 状态色用**描边**而不是整卡着色

`material.color` 是**乘法** —— 红卡染「置灰」出来还是暗红，状态根本读不出来（试过）。
改成卡后面加一圈状态描边（`CardView` 的 rim），不受卡面配色影响，也是真实卡牌游戏的通行做法。

### 4. 卡牌和特效**解耦**

`CardEffects.Play` 是个 `Action<string, Vector3, Transform>` 钩子，游戏启动时接到
`WarpforgeEffectPlayer.Play` 上。好处：`CardPresentation` 不依赖 `WarpforgeVFX`
（特效库不在时卡牌照样跑），批处理自检里还能挂个假钩子只记录「谁在什么时候播了什么」。

> 卡牌动作 → 特效名走 `VfxMap.Resolve(事件, 阵营, 卡)`（名单经 `VfxPicker` 试片台实拍挑过，含技能 / 触发）；
> `CardEffects.EffectDeploy/Attack/Damage` 三个老接口只是转发到 `VfxMap`。

## 四、踩过的坑

| 坑 | 真相 |
|---|---|
| **`cam.aspect` 一旦显式赋值就固定住** | 不再跟着 RenderTexture 走。**必须在 `Render()` 之前设**，否则会拿上一个分辨率的宽高比去渲（自检图全部横向压扁）。本会话在自检工具上踩过 |
| **`material.color` 是乘法** | 红卡染灰还是暗红，状态读不出来。用描边（见设计决策 3） |
| **TMP 缺 Essentials 就一个字都不显示** | 本工程已由 `TmpSetup.ImportEssentials` 导好（37 个文件，命令行可重跑）；换别的工程时要注意先导，别手点菜单（批处理下不落地） |
| **旧输入 API 会直接抛异常** | 本工程 `activeInputHandler: 1`（只开新输入系统），读指针要用 `Mouse.current` / `Touchscreen.current` |
| **拖拽平滑系数要按 dt 算** | 写死 `Lerp(x, y, 0.45f)` 的话帧率一变手感就变，而且批处理里手动喂 dt 时推不到位 |
| **格位底片别共用一份材质** | `MarkOccupied(i)` 会把 9 格一起变色。每格一份 |
| **🆕 `TryResolveSlot` 只比 x、不看 y** | 拖到战场**正上方空白处**，只要 x 恰好落在某格附近就算合法落点。实测：非法落点用例丢在归一化 (0.12, 0.88)，槽 0 的 nx 是 0.148，`\|0.12-0.148\|=0.028 < 0.055` → 判合法，牌直接落到战场上（本该回弹）。**7 格时槽 0 在 0.236 恰好躲过，改成 9 格才暴露。** 横纵容差**不是同一个物理尺度**（可见宽 17.78 / 高 10），是两个独立参数 |
| **🆕 格位底片要跟分辨率缩放走** | `localScale` 直接写 `CardView.Width` 的话，4:3 下间距只剩 1.17 而底片宽 1.45，**相邻格会叠上**。落上去的卡走的是 `placedScale * Scale`，底片要同口径 |
| **🆕 棋盘格数两边各写一份** | `RuleEngine.BoardSpec` 和 `BoardLayout` 各有一份常量，靠 `RuleEngineTest.TestBoardMatchesPresentation()` **断言相等**。表现层曾自己拍成 7 格 —— 那是 `rule_core.gd:42` 点名推翻过的误读（`索引与盘点/解包资源使用地图.md:800` 也记着用户已裁决过）。**改格数必须两个一起改再跑自检** |
| **`Vector3.Lerp` 之外还要注意层序** | 相机在 -Z 看 +Z，**z 越小越靠前**。命中测试要从最前面往后测，不然会选中被压住的那张 |
| **🆕 相机的宽高比必须在建东西之前定死** | HUD 文字 / 格位底片 / 槽带的世界坐标都是**建的时候算一次**，而 `LayoutSpace.VisibleWidth` 跟着 `cam.aspect` 走。批处理下相机默认 **4:3** —— 建完再拍 16:9，HUD 整片偏左（实测：ENERGY 那行跑到手牌底下）。`BuildScene` 里 `LayoutSpace.Apply` 之后立刻 `cam.aspect = DesignAspect`；运行时改分辨率则由 `BattleDriver.ReanchorHud()` 兜 |
| **🆕 牌挨得近以后，「点在 X 上」会命中压着的邻牌** | 原版手牌间距是 **0.95 卡宽**（牌几乎挨着，左右各压一点），所以点在 X 的中心可能选到 X−1 —— 这本身对（原版 `useZOrder` 就是「左卡压右卡」，露出来的是每张牌的**右半边**，所以费用/生命都在右边）。但自检里「悬停第 6 张」那种写法得改成点**露出来的那半边** |
| **🆕 批处理能跑 ≠ GUI 编辑器能开** | 工程的 `Packages/manifest.json` 是瘦的、**没装 `com.unity.modules.physics2d`**，而 DOTween 的模块是「默认全开」——`DOTweenModulePhysics2D.cs` 引用 `Rigidbody2D` 会编译不过。`DOTweenSetup` 只给 Standalone/Android/iOS 设了 `DOTWEEN_NOPHYSICS2D`，**编辑器那套编译用不上**，于是「批处理全绿、GUI 一打开满屏报错」。修法是 `Assets/csc.rsp` 里写一行 `-define:DOTWEEN_NOPHYSICS2D`（**rsp 里不能写中文注释** —— 会被当成源文件参数报 `CS2001`，踩过） |
| **🆕 拖拽的放大/回弹缩放不能写绝对值** | `dragScale` 要**乘在手牌缩放上**、回弹要回到 `hand.cardScale * LayoutSpace.Scale`。原来写死 `1.16` / `LayoutSpace.Scale`，在 4:3（Scale 0.70）下会炸开 |

## 四·五、卡面并排验收（2026-09-15，我们的卡面 vs PnP 成品卡）

**做法**：`CardFaceProbe.Run` 渲出的卡面，逐张与 `D:/2/Warpforge部队卡片/<阵营>/<类别>/*.png` 并排看 —— **这一步是必须的，断言查不出「像不像」**。
**验收结果**：卡名 / 费用 / 卡底四个数值 / 底部稀有度宝石 **21/21 全对**，插图是同一幅立绘的 **20/21**（差的多数只是我们裁得更紧）；**两条真缺陷都已修**（类型行「该印没印」· 效果文字与类型行叠字），同批还修了阵营行印成 `BLACKLEGION` 那种无空格全大写（中英两张表都补，⚠️ 修的时候**别只修一半**：`Faction()` 有 `Zh` 两条分支）。

**① 类型行「印不印」的判据**（派子代理**逐张开图读了 70 张 PnP**、13 阵营全跨推出来的，落在 `CardView.SubtypeLine`）：
`印 ⟺ type∈{unit, hero, defence} ∨ (type==tactic ∧ subtype ∈ 9 个白名单)`
· `unit` → 印 `subtype` 原值 · `hero` → **恒印 `Warlord`** · `defence` → **恒印 `Defence`**（⚠️ 有 3 张防御卡的 subtype 数据写的是 Stratagem/Spell/Structure，卡面**照样印 `Defence`**）
· `tactic` → 白名单才印：`Dark Pact` · `Overlord Power` · `Combat Elixir` · `Codicil` · `Psychic Power` · `Rune` · `Invocation` · `Genomic Enhancement` · `Sabotage`
⚠️ **不能只看 subtype 空不空** —— 非空的约 370 张，卡面上都没有这一行。**排除过的假设**（别再试）：①「只单位/督军/防御印」被 9 类计策推翻；②「词不泛用就印」被 Structure/Order/Trick/Talent/Mission/Relic 推翻；③「按卡框模板」被同阵营同框反例推翻。

**② 效果文字的下沿：三个常量是一组** —— 印类型行时用 `CardView.RaceDescBottom01 = 0.834`，否则走 `UnitDescBottom01` / `TacticDescBottom01`（原来战术/防御卡用 `TacticDescBottom01 = 0.9061`，比类型行**更低**，一印就撞：`Lychguard` / `Alien Idol` / `Dark Pact of Excess`）。
⚠️ **纯按公式算会得出「本来就不该叠」的错结论**：`PlaceBottomAt` 对齐的是 `textBounds`（含基线以下那段），与肉眼看到的字形下沿差约 **0.039 卡高** ⇒ **必须量渲染图**。
⚠️ 顺带更正一条**我量错的**：**阵营行并不偏大**（3.86% vs PnP 3.50%，位置也对得上）—— 第一次量成「1.3 倍」是**认错了橙色带**（把两段橙字混成一段）⇒ **量的时候要把每一段按位置列出来，别只取一个总数**。

**🔴 坑（这次又踩了一次）**：**新生成的 PNG 必须再跑一次 `ArtBaker.ApplyImportSettings`** —— python 导入脚本会**新建** `.meta`，而它是在 `ApplyImportSettings` **之后**跑的 ⇒ 新文件拿到默认设置（`isReadable: 0`），`CardFaceProbe` 会**当场抛** `ArgumentException: Texture 'art_xxx' is not readable`。顺序要写成：**导入 → `ArtBaker.ApplyImportSettings` → 再渲卡面**。
