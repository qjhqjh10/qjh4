## 二、落盘设计

| 项 | 取值 | 出处 / 理由 |
|---|---|---|
| **目录** | `Application.persistentDataPath/WarpforgeDaily/` | 用户裁定「跟回放一条路子」；**照 `ReplayStore`**（`Battle/ReplayStore.cs:82` `DirName = "WarpforgeReplays"` + `:112-121` 的 `Dir` 属性） |
| **文件名** | `daily.json`（`StoreFileName`） | 一族一个文件（不是一局一个）；**文件名里不带路径分隔符**（`ReplayStore` 那条纪律） |
| **注入口** | `public static string OverrideDir` | **照 `ReplayStore.OverrideDir`**（`:96-97`）—— 同族的 `DeckStore.OverridePath`（`RuleEngine/Data/DeckStore.cs:31`）是**整条路径**版，回放是**目录**版；本件按简报点名的 `ReplayStore` 取**目录**版 |
| **读口** | `public static string StorePath` | 日志里打完整路径（`ReplayStore` 的规矩：编辑器里它在 `AppData` 深处、不好找） |
| **格式** | `JsonUtility`（**紧凑**）+ `[System.Serializable]` 的 `StoreDto` | 与 `ReplayStore.Save` / `DeckStore.SaveAll` 同一套 |
| **写盘手法** | 先写 `daily.json.tmp` → 删旧 → `File.Move` | **照 `DeckStore.SaveAll`**（`RuleEngine/Data/DeckStore.cs:110-115`）——「写一半崩了不至于把旧档毁掉」。⛔ 不是 `PlayerPrefs` |
| **失败策略** | 读失败/写失败**一律出声**（`Debug.LogError`，含完整路径），且**绝不静默回退成「看起来正常」** | 红线「不许静默失败」；尤其「以为进度还在、其实没了」 |
| **版本** | `StoreDto.version`（现 = 1）；读到不认识的版本 ⇒ **出声 + 不读它**（按出厂值走），下一拍落盘会盖掉 | 照 `ReplayStore.Load:198-205`（**拿 `new StoreDto().version` 比，⛔ 不写死数** —— 那正是 `ReplayStore` 踩过并已修的那条） |

### 落盘哪些量（**= 重置清哪些量 + 「下一次刷新时刻」本身**，⛔ 没扩大范围）

| 落盘 | 不落盘（各自的理由写在代码里） |
|---|---|
| `_daily[]` 的 `Progress` / `St` · `_skullsCount` / `_skullsState` · `_loginState` · `_nextReset` / `_nextResetSet` | `_loginDay`（7 天周期的第几天，本来就不在重置范围内）· 周常 / 连登 / 每日奖励抽屉 / 商店（各有各的周期）· `DailyResetCount` / `DailyResetChecks` / `LastResetMessage` / `RerollCount` / `_rerollRound`（进程内诊断量/游标——自检拿它们做**差分**基线）· `Wallet`（记账，不是「当日进度」） |

**⚠️ 一个刻意多做的地方（说明理由，不是范围蔓延）**：`RerollDaily` 那一行**连【内容】一起存**
（`Desc`/`Target`/`RewardArt`/`RewardText` + 一个 `rerolled` 掩码）。理由：`RerollDaily` 是**就地换掉那一行**的
（原版这一步是服务端换一条新的），**只存进度的话重启后那一行会「文案退回出厂、进度却是重摇后的」**（自相矛盾）。
掩码是**现算**的（跟已有的 `_dailyFactory` 出厂快照逐格比，`MakeDto` 里那 4 个比较）⇒
**没摇过的行永远跟代码里的出厂内容走**（改了 `_daily` 的文案不会被旧档静默盖住）。

### 怎么注入临时档做自检（三个自检口，全在 `DailyData` 上）

| 口 | 干什么 | 关键纪律 |
|---|---|---|
| `OverrideDir = "d:/4/_tmp_view/daily_selftest"` | 注入临时目录（**要先设它**，否则后面两个口全都不动盘） | 与 `Editor/BattleScene.cs:196`（`ReplayStore.OverrideDir = @"d:/4/_tmp_view/replays_selftest"`）同一写法 |
| `DeleteStoreForTest()` | 删掉存档文件（从「第一次跑」那一态起手） | 🔴 **没设 `OverrideDir` 时它【拒绝执行】并报错** —— 那种情况下删的就是玩家真档（**硬挡，不靠自觉**） |
| `ReloadForTest()` | **模拟一次进程重启**：把落盘那一族打回出厂值 + 重新读盘 | ⚠️ 它**不动**进程内诊断量（`DailyResetCount` 等）—— 那些自检拿来做差分 |
| `SaveNowForTest()` | 把当前内存状态**立刻落盘**（模拟「上一个进程写下去的」） | `Force*ForTest` 那一族**自己不落盘**（自检口不该在真档上留痕） |
| `StoredSkullsCountForTest()` / `StoredDailyProgressForTest(i)` | **从盘上**读回那两格（`int.MinValue` = 盘上没有/读不出） | 🔴 **门关着时连读都不读**（「绝不碰真档」是对**读写两边**说的）。**存在理由**：光断内存验不出「`Persist` 那一句被删掉」（内存照样对）—— 它专门堵那个洞 |

## 四、`DailyData.cs` 那句注释改成了什么（旧 `:1212` ⇒ 现 `:1236-1248`）
