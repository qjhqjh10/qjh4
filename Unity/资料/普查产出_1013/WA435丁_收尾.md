## 二、A743（B1）改动

### 2·1 改了哪两处（`Shell/WindowsManager.cs` 的 `GameWindow.Text`）

改编前：
```csharp
if (!MenuDraw.Visible(r, RenderClip)) return null;
…
if (RenderClip.HasValue) MenuDraw.ClipText(lb, RenderClip, ClipSoftness);
```
改成（**两处都吃同一份 `_st`**）：
```csharp
var _st = ViewportClip.Resolve(parent, RenderClip, ClipSoftness, default(Vector4));
if (!MenuDraw.Visible(r, _st.RenderClip)) return null;
…
if (_st.RenderClip.HasValue) MenuDraw.ClipText(lb, RenderClip, ClipSoftness);
```
并在方法的 doc 里加了一段 `<para>🔴 2026-10-13（A435 阶段 2 · 丁 / B1）…</para>`（说明「本窗那两份只是**形参**」+ 这一处不接的后果）。

### 2·2 「同一份 `_st`」是怎么落的（逐条对位）

| 要素 | 值 | 为什么 |
|---|---|---|
| 解析起点 | **`parent`**（本方法建的标签挂它下面） | 与 `MenuDraw.Text` / `ClipText` 内部那一份**同一口径**（节点在父链上同样命中）。⚠️ `ClipText` 从 `lb.transform` 往上走 —— `lb` 是 `parent` 的直接子 ⇒ **同一条链** |
| 形参 ①（`clip`） | `RenderClip`（不是裸 `Clip`） | 与 `MenuWindowBase.Text` **逐字同形**：`RenderClip` = `PaddedClip(Clip, ClipPad)`，喂进去后 `Resolve` 第 1 支里的 `PaddedClip(·, Vector4.zero)` 首句早退 ⇒ `_st.RenderClip` **逐位等于**原来的 `RenderClip` |
| 形参 ②（`softPx`） | `ClipSoftness` | 形参非空时原样带出；形参为 `null` 时由**节点**给 |
| 形参 ③（`pad`） | `default(Vector4)`（= 零） | 与 `MenuWindowBase.Text` 同 —— 这一处本来就**不转发 pad**（pad 只走 `AddHit` / `Hit`，A742 已核「不用改」） |
| 两处用同一份 | ① `Visible(r, _st.RenderClip)`；② `if (_st.RenderClip.HasValue) ClipText(…)` | 🔴 不同一份就会出现「**按节点判了可见、却按本窗字段（= 不裁）建出来**」= 半拉子、**静默** |
| 交给 `ClipText` 的形参 | **调用方原样那一份**（`RenderClip` / `ClipSoftness`），**不是** `_st` 里那两份 | 与 A484 / A435① 同一条：`ClippedTextGuard` 要在**每次重裁时重新解析**（快照会在节点挪动后拿旧框裁、还会把 `NodeShadowedByParam` 误报成「旧设站点没删」） |

### 2·3 与 `MenuWindowBase` 那一份的对照（逐字段）

| | `MenuWindowBase.Text`（A435① 已改） | `GameWindow.Text`（本件） |
|---|---|---|
| 形参表 | `(parent, string text, x1,x2,y1,y2, scale, color, name, fontPx=0)` | `(parent, PxRect r, s, color, name, fontPx, q, wrapPx=0, autoMinPx=0, align=0, autoMaxPx=0, autoBasePx=0)` |
| 解析那一句 | `var _st = ViewportClip.Resolve(parent, RenderClip, ClipSoftness, default(Vector4));` | **逐字相同** |
| 守卫 ① | `if (!MenuDraw.Visible(<矩形>, _st.RenderClip)) return null;` | 同（`<矩形>` = 本方法的 `r`） |
| 守卫 ② | `if (_st.RenderClip.HasValue) MenuDraw.ClipText(lb, RenderClip, ClipSoftness);` | **逐字相同** |
| 差异（如实记） | 它的矩形是**四个 float** 现拼 `new PxRect(x1,y1,x2,y2)` | 本方法的矩形是**现成的 `PxRect r`** ⇒ 不需要拼 |
| 差异（如实记） | 它有一条「建完之后才 `AlignLeft/Right`」的次序要求 | 本方法**也有**同一条（`align == 1/2` 在 `ClipText` **之前**）——本件**没有改动那个次序** |

> ⛔ 两处**必须是两份实现**（不是重复代码）：参数表不同（重载），而且各自有各自的对齐/自适应差异
> （`MenuWindowBase.Text` 的 `fontPx` 走 `SetGlyphHeight`、本方法走 `MenuDraw.Text` 的 `wrapPx/autoMin/autoMax/autoBase` 那一套）。
> 判据 = `Shell/WindowsManager.cs` 的 `Text` doc 里那段 A241/A446 的注释（原来在三扇窗里各有一份、已经收口到本处）。
