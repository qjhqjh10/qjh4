## 二、A773 —— `Shell/ItemDrawer.cs` `TextCentered`（甲块漏的那一处）

### 2.1 改法（一行）

```csharp
// 改前（生产上恒假）
if (st.Clip.HasValue) MenuDraw.ClipText(lb, st.Clip.Value, st.ClipSoftness);
// 改后（照同文件 `ClippedText` 那一句逐字）
MenuDraw.ClipText(lb, st.Clip, st.ClipSoftness);
```

**为什么「恒假」**：`ItemDrawerStyle.Clip` 生产上**没有任何写入点**——
缺省在 `ItemDrawer.cs` 的 `Default`（只写 `ClipSoftness`）· 甲块 B8/B9/B10 把三处派生写入（`CampaignRewardWindow` /
`RewardWindow` / `CampaignTab`）**全删了** · 唯一的非空写入是 `Editor/RewardsScene.cs` 的 A302 探针（γ 档）。
⇒ 这两段字（`SetEphemeral` 的 `24 hours` 那串 · `SetConverted` 的数量数字）**一个顶点都不裁**，
压在视口边上**整段画出去**（静默）。
⚠️ 同一个函数里另两处**甲块已改**：`:996` 的粗筛（`Visible`→`VisibleAbove`）、`SetConverted` 里 `Already Owned`
那条（走 `ClippedText`）⇒ **只剩 `:1012` 这一处**，所以改完这两条路**行为应当一致**（我把这句话也做成了断言，见 §五）。

### 2.2 「一个顶点都不裁」怎么用**行为**断言钉住（落在 `Editor/CollectionScene.cs`）

探针形状**照 `Editor/RewardsScene.cs:5898` 的 A302 探针**（无父 `GameObject` + 直调 `ItemDrawer.SetConverted`），
但把「裁切来源」从**显式形参**换成**视口节点**（= 生产那一档）：

```
① 对照组：探针（**不挂节点**）→ 量两段字的 TMP 顶点（画布 px）
② 拿**实测**的落点当框沿：`edge = (数字那段字的 minX + maxX) / 2`
③ 主态：同一个 box / 同一份 style（`Clip` 保持缺省 null），探针上挂一颗 `ViewportClip.Hang(…,(0,300,edge,1080),…)`
④ 断：两段字的 **maxX 都恰好被夹在 `edge` 上**（≤ edge+0.5 且 ≥ edge−0.5）
```

🔴 **为什么这样定期望值**：期望值**不写死**成我们自己的常量，而是**先量对照组**（未被裁的那一态）再拿它当边界 ——
这样「压边」这件事与 `Label.WorldW` 量出来是多少**无关**（那个量在本工程有前科：TMP 在未激活时会给天文数字）。
「真被夹住（≥ edge−0.5）」那一条是我特意加的牙口：只断「≤ edge」的话，一段**本来就落在框内**的短文字也能过（假绿）。

**影响面（如实标：没算）**：**哪一格会露出视口、露多少，本件没跑 Unity ⇒ 没量**。
能确定的只有「这两段字现在一个顶点都不裁」（判据 = §2.1 那条恒假链）。

## 三、A774 —— `Core/CardView.cs` 的 clip 口不进 `Resolve`

### 3.1 新口长什么样（`Core/CardView.cs`）

```csharp
bool _clipFromTree;                                   // 🆕「每次重裁都沿父链重新解析」
bool Clipping { get { return _clipFromTree || _clip.HasValue; } }

public void SetClip(PxRect? clip) { _clipFromTree = false; _clip = clip; ApplyClip(); }   // 显式覆盖（关掉跟随）
public bool SetClipFromTree()    { _clipFromTree = true;  ApplyClip(); return _clipOn; }   // 🆕 跟随节点

void ApplyClip()
{
    RestoreClip();
    if (_clipFromTree)                                // 🆕：**每次重裁都重新解析**（节点后挂/搬走/改 pad 都跟得上）
    {
        var st = ViewportClip.Resolve(transform, null, Vector2.zero, default(Vector4));
        _clip = st.RenderClip;                        // = 框 − padding（与 `MenuDraw.Rect/Text` 吃的同一份）
        if (_clip.HasValue && (st.Softness.x > 0f || st.Softness.y > 0f) && _softnessWarned++ < 3)
            Debug.LogWarning(…“本类只会硬边切几何，软隐带还没做”…);   // ⛔ 不静默当硬边
    }
    _clipOn = _clip.HasValue;
    …
}
```

**三处重裁尾巴**（`SetFace` / `SetData` / `SetPose`）的判据从 `_clip.HasValue` 换成 **`Clipping`** ——
理由：跟随档下「这一刻没有节点」时 `_clip` 是 `null`，用旧判据会**漏掉后面挂上来的节点**（静默）。
**顺序没变**：`SetPose` 仍是「先写位姿、再 `if (Clipping) ApplyClip()`」（位姿是画布矩形→局部系那个换算的输入）。

**解析起点 = 卡自己的 `transform`**：`ViewportClip.FindAbove` 从 `t` 自己开始逐级找 ⇒ 卡就挂在 `Viewport` 节点下面一级。

**⛔ 我没有动 `Create(..., clip)` 那个闸**（`if (clip.HasValue) v.SetClip(clip);`）：全仓**没有一个调用点**给它传 `clip`，
而把它改成「`null` 也解析」会**改掉 20+ 个调用点**（战斗/手牌/卡组/详情窗那一族）的语义 —— 简报要的是「两个调用点」，
所以只补了形参文档（写明它现在是**显式覆盖**的口子，要跟节点走请用 `SetClipFromTree`）。

### 3.2 两处调用点怎么改（`Shell/CollectionWindow.cs`）

```csharp
v.SetPose(Local(parent, r.x1, r.y1, r.x2, r.y2), 0f, scale);   // 卡池：原来第 4 个实参 = CardsViewport
v.SetClipFromTree();                                            // 🆕 A774
```
异画页同一形状（原来第 4 个实参 = `StyleView`）。**顺序有意**：`SetPose` 先定完位姿，再让卡解析边界。

### 3.3 为什么**不能**「直接传 `null`」

`SetPose(pos, rot, scale, clip = null)` 的语义是「**不改**当前状态」（见它那个形参的注释）；
而这张卡出生时 `_clip` 本来就是 `null` ⇒ 传 `null` 的净效果 = **整卡一张都不裁**（静默，正是 A181 当初那个缺陷）。
⇒ 必须有一个**正面表达「跟节点走」**的口，那就是 `SetClipFromTree()`。

### 3.4 断言怎么做（两态 + 真卡池，落在 `Editor/CollectionScene.cs`）

量的是**真卡池那张卡**（`RebuildCardsCells` 建的那批），三态：

| 态 | 做什么 | 断什么 |
|---|---|---|
| ① | 按生产那两行的形状重摆第 1 张卡（`padding = 0`） | 渲染最高顶点 `b1 ≈ 155.9`（= 节点框上沿；⛔ 没裁的话影子会顶到 ≈94.2） |
| ② | **只改节点**：`vc.padding = (0,0,0,60)`（原版 `m_Padding.w` = Top）→ 同一次摆位 | `b2 ≥ 155.9+59.5` ⇒ 边界**跟着节点走到 215.9**；`|b2−b1| > 50` ⇒ 这条真能分出两态 |
| ③ | 还原 `padding` → 再摆一次 | 边界**回到** 155.9 ⇒ 读数随状态动，不是恒值 |

**改坏法**（写在断言正上方）：① 调用点退回 `v.SetPose(…, CardsViewport)`（显式矩形赢）⇒ 态② 停在 155.9 ⇒ 红；
② 删掉调用点那句 `v.SetClipFromTree()` ⇒ 整卡不裁 ⇒ 态① 红；③ 删掉 `ApplyClip` 里 `_clipFromTree` 那一支 ⇒ 态② 红。

### 3.5 配套：软边（如实出声）

`CardView` 的裁法是「按框切几何」，**原版 `m_Softness` 那个渐隐带我们还没做**。
⇒ 节点 `softness` 非零时**出声一次**（限流 3 条，`_softnessWarned`），⛔ 不静默当硬边。
收藏窗那四处视口实读都是 `(0,0)`（`A435_迁移表.md` §二·A 注），所以今天**不会响**。

### 4.2 我裁：**照 `Intersects` 补齐形状**（不是「标死代码」）

理由三条：
1. **同一个类里两个「把内容矩形夹到视口」的口**：`Intersects`（A465 已迁）与 `Place`（未迁）。
   留着一个直读 `Viewport` = 「两处写同一条规则」（`CLAUDE.md` §三）⇒ 将来谁用了就**静默**吃旧框。
2. 补齐 = **今天逐位不可观测**（零调用点）+ 一行来源替换，风险为 0；反过来说**删掉**它是更大的动作
   （公开 API 消失，且本件拿不到「原版有没有这个口」的判据）。
3. 铁律 11：查出偏离 ⇒ 记录**并且**做，只有「原版没有 / 用户拍板不做」两种才不做 —— 这一条不属于那两种。

**改法**（与 `Intersects` 逐字同一条来源）：

```csharp
var node = ClipNode;
var vp = node != null ? node.State.RenderClip : (PxRect?)Viewport;
```
外加**一条新的分支**：节点在、但**给不出框**（`padding` 比框还大那一支）⇒ 按原版那一支处置
（`validRect = false` ⇒ `DisableRectClipping()`）**整块不裁** —— 与 `MenuDraw.PaddedClip` 的退化处置一致，
⛔ 不是「裁到没有」。⚠️ 这一支生产上够不着（唯一非零 pad 是锻造轨道 `(10,0,0,0)`，视口宽 1588.7）。

### 4.3 断言（直调，两态）

`Editor/CollectionScene.cs` 里现造两个 `MenuScroll`（`Viewport = (0,0,1000,500)`，内容 2000 宽）+ 一颗节点 `(0,0,600,500)`：

| 态 | 断 |
|---|---|
| ① `ClipNode = null` | `onScreen.x2 = 1000`（= 迁移前行为，逐位不变） |
