## 一、`ClickedThisFrame()` 是什么（定义 + 为什么是「按下沿」）

**定义**（现读 `Battle/BattleDriver.cs:9056-9078`）：

```
bool _clickLatch;                                       // :9056
bool ClickedThisFrame()                                 // :9058
{
    bool down = PointerHeld();                          // :9061
    if (!down) { _clickLatch = false; return false; }   // :9062  ← 松手那一帧复位
    if (_clickLatch) return false;                      // :9063  ← 同一次按住只算一次
    _clickLatch = true;                                 // :9064
    …ClickLog…                                          // :9068-9076
    return true;                                        // :9077
}
```

- `PointerHeld()`（`:9081-9085`）= 新输入系统的 `Mouse.current.leftButton.isPressed` / `Touchscreen…primaryTouch.press.isPressed` —— **「现在还按着」**，不是「这一帧刚按下」（没有 `wasPressedThisFrame`）。
- ⇒ 真实语义 = **「按住状态的上升沿」**：pressed 由 false→true 那一帧为真，之后恒假，直到松开那一帧复位。
- 注释自写「轮询按下…用 latch 防止按住触发多次」（`:9060`）—— 本意就是**在没有 EventSystem 的批处理/自检里轮询出一个边沿**。

⚠️ **命名坑（不是 bug，但会误导下一个会话）**：`static bool PointerDown()`（`:5233-5237`）与 `PointerHeld()`（`:9081-9085`）**函数体逐字相同**（都是 `isPressed`）。`PointerDown()` 读起来像「按下沿」，实际是「按住」。它在 `:5164`（`BoardPress(world, PointerDown())`）与 `:5172`（技能卡面板 `SetPointer`）被用 —— 那两处要的正好是「按住」，**行为没错**，但别拿它当边沿用。

## 二、原版那一侧：事件模型 + `TouchInputManager.TouchPressed` 的语义

### 2.1 `TouchPressed` 是「按住」，**不是**「按下沿」

`TouchInputManager__Update.c`（亲读）：
- `:128` `GetMouseButton(0,0)` → `:133` 写进 `TouchPressed`（静态字段偏移 **`+0x8`**）
- `:134` `GetMouseButton(1)` → `:139` 写进 `TouchPressedSecondary`（`+0x9`）
- `:189` 内部判据 `TouchPressed==0 && TouchPressedSecondary==0` 才走 `UpdateDrag`
- `:151-152` `GetMouseButtonDown` **只出现这一处**，而且只用在「没有触摸时把鼠标位置当触点」的兜底分支 —— **与 `TouchPressed` 无关**

字段偏移对照（`d:/2/tools/il2cpp_out/dump.cs:89641-89665`）：
`TouchPosition +0x0` · **`TouchPressed +0x8`** · `TouchPressedSecondary +0x9` · `TouchDragDelta +0xC` · `IsDragging +0x14` · `TouchDragDeltaViewport +0x18` · `ScrollDelta +0x20` · `TwoFingerMidPoint +0x24`。

⇒ **`TouchPressed` = `Input.GetMouseButton(0)` = 「左键按住中」**，`Update` 每帧刷一次，**没有边沿语义**。`IsDragging` 也只是「这一帧位移 ≠ 0」（`TouchInputManager__UpdateDrag.c:50`）。

## 四、改法分档

### 4.1 必须改成「抬起」（**12 行**：`#1 #2 #4 #5 #6 #7 #8 #9 #12 #13 #14 #15`，**外加 `#10` 的一半**）

> 计数口径：#4 那一行只有 ③④ 两支要改（⑤ 支已经是松手才做）；`#10` 那一行只有「命中某条台词」那半要改，**条外关闭那半保持按下沿**（见 §4.2）。

**改法一行级**：`BattleDriver` 里加一个**真的松手沿**（现在的 `PointerHeld()` 只给「按住」）：

```
bool _holdLatch;                       // 复用/照抄 _clickLatch 的形状
bool ReleasedThisFrame()               // 名字先占位，写手可自定
{
    bool held = PointerHeld();
    if (!held && _holdLatch) { _holdLatch = false; return true; }   // 松手那一帧
    if (held) _holdLatch = true;
    return false;
}
```
然后把上表这 12 处（+ #10 的「选台词」半）的 `ClickedThisFrame()` 换成它。
⚠️ **`_clickLatch` 不能删**：`ClickedThisFrame()` 还要给 #4③′（`ShowMyDeck`，我们自己的入口）· #4⑤（`_pressSlot`）· #10 的关闭半 · #11 用，而且它同时承担 `ClickLog` 那一跳（`:9068-9076`）—— 见 §4.4。

### 4.2 该保持「按下沿」（本来就对，**别一起改掉**）

- **#11** `HandleBattleLog:2917` —— 原版 `shade` 就是 `EventTrigger` `PointerDown`。**改坏法**：把它也换成「抬起」⇒ 与原版不符（点一下日志面板背板、要等松手才收）。
- **#10 的「条外关闭」半** `HandleChatPopup:2612` —— 原版 `CloseChatPopup` 就是 `EventTrigger` `PointerDown`。
- ⚠️ 这两处与其余 12 处**共用同一个 `ClickedThisFrame()`** ⇒ 不能全局替换，只能**逐处改**。这是本件工量的主要来源。

### 4.3 判据不足 / 原版无对应（**不许猜**）

- **#3** 的攻击选择器：**改成「悬停即选中 + 0.1 s 安全窗」**（判据齐：§三 #3 那一格）。⚠️ 但「**压在条外 ⇒ 取消**」这一支我**没找到原版对应**（`AttackSelector.ContainsBar:561-567` 是一段纯几何，**方法上没有出处注释**，我也没在反编译里找到等价物）⇒ 那一半**保持现状**，别顺手删。

### 4.4 三条落地纪律（写手简报里要写死）

1. **`_clickLatch` 与新的松手 latch 是两套状态**，各自独立复位。`ClickedThisFrame()` 里那段 `ClickLog.Begin/Hit`（`:9068-9076`）是**点击记录**的落点（用户 2026-09-24 要的），**改沿的时候别把它漏掉** —— 松手沿那一支也要记一次（否则「真实点击记录」会缺一半）。
2. **`PointerDown()`（`:5233`）不要动** —— 它是「按住」，`BoardPress` 与技能卡面板要的就是它。想加松手沿就**新写一个**，别改它的语义。
3. **#4 的 ⑤ 支（`_pressSlot`）必须留在按下那一帧**：`BoardPress:5218-5224` 靠「`held==false` 那一帧」判轻点。若把 `_pressSlot = pick` 也挪到松手帧，`BoardPress` 会在**同一帧**看到 `_pressSlot` 刚被赋值又 `!held` ⇒ 立刻 `ToggleUnitCard`（「轻点开卡窗」与「拖拽弹选择器」的分流会静默坏掉）。

### 4.5 依赖 A463 吗？

**这 15 处的「改法」没有一个依赖 A463。** 松手沿用新输入系统本机就能取（`Mouse.current.leftButton.wasReleasedThisFrame` 或上面的 latch）。

⇒ **A462 可以先做、A463 后做，互不阻塞。**
