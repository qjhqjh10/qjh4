# 常用操作速查（从 `项目任务.md` 拆出来 · 2026-09-21）

> 所有命令的原文。⚠️ 跑 Unity 批处理前 `unset ELECTRON_RUN_AS_NODE`；**同工程同时只能一个实例**。

| **不清旧产物会累积副本** | `GenerateUniqueAssetPath` 不断产出 `X 1.mat`；清理时别把 `WarpforgeVFX/Runtime` 和 `Shaders` 一起删掉 |
| **`Warpforge_code` 是签名桩** | 方法体**直接留空**（不是抛异常），0 个文件含桩标记。字段名/类型/`[SerializeField]` 完整可用 |
| 🔴 **🆕 往自建 shader 里接原版属性之前，先问三句**（2026-09-15 踩到，13 个效果同时变暗） | 三句 = **默认值是什么 · 原版在什么条件下才采它 · 原版是加法还是乘法** —— **它多半不是乘法**。实测：给 `WFParticlesExtraColor.shader` 接 `_EmissionColor` 时写成 `col = tex * _Color * _EmissionColor * IN.color`，而原版那批材质里它是**黑的默认值**（URP/内置粒子 shader 属性表就是 `(0,0,0)`，还要 `_EmissionEnabled`/`_EMISSION` 才采它）⇒ **整个材质被乘成黑**（`Cut Wulfen SW` 亮度比 0.033）。改回**加法发光项**后 13 个效果全复原。**这跟「原版材质带内置 Standard 的残留值」是同一条规矩的两个方向** |
| 🔴 **🆕 「尺子漏了」：`BlendProbe` 的 shader 解析那段覆盖不全**（2026-09-15 亲手验过） | 它是**从 `导出报告.tsv` 的 `原 shader:` 行抓名字**来试的（`BlendProbe.cs:128-150`），所以**报告里没出现过的 shader 它一条都不验** —— 把三张 ShaderGraph（`Fx_ParticleDissolve_apb` / `Fx_RockDissolve` / `Eclipse Tau`）从映射表里 stash 掉，它**照样报 70/70 / 0 失败**。那三条因此能烂到 C 组。⇒ 新增**点名验**的探针 `-executeMethod ShaderResolveProbe.Run`（`WarpforgeArena1/Editor/ShaderResolveProbe.cs`，带对照组、**不依赖任何报告**）。⇒ **断言绿不等于覆盖面够**，跟「白板 20/20 不是 958 个」是同一类坑 |
| **🆕 W 组的「两边全程空」是噪声门假阳性** | 判据是「亮点数 < 60」，**不是「都为 0」** ⇒ 这批得重判。⚠️ 手头有两份**不同口径**的台账别混：`d:/2/Warpforge_tools/data/vfx_wiring_j1..5.tsv` 是 2026-08-24 的**独立「效果→触发事件」台账**（可用它重判 W 组，别逐条找触发条件）；`资料/特效还原_进度与交接.md` §〇·一 记的是**验收指标**那一路 |
