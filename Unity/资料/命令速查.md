## 🆕 **秒级类型检查**（2026-09-28 造，**改完代码先跑它、再跑 Unity**）

Unity 一次批处理要 1–9 分钟，而其中**大半是编译**。改 C# 时想先知道「编不编得过」，
直接调 **Roslyn `csc`**，用 Unity 自己生成的 `.csproj` 当**源清单 + 引用清单**：

```bash
bash d:/4/Unity/工具/typecheck.sh     # 幂等，随时可跑；几秒出结果
```
它做两件事：① 编**运行时程序集**（`Assembly-CSharp`）· ② 编**编辑器程序集**
（`Assembly-CSharp-Editor`，拿①的输出当引用）。**各报错误条数**，`0 = 过`。

🔴 **2026-09-29：那两个脚本已经从临时目录搬进仓库**（原来只在 `%TEMP%` 里，**重启就没了**）：
`工具/typecheck.sh`（外层）+ `工具/gen_csc_rsp.py`（生成两份 rsp）。
同一次改动还修了一个**会误导人**的老毛病：原来「新加的 `.cs`」是一串**手写名单**，
每加一个文件都得改它，漏了就报 `CS0246 找不到类型`（看着像代码错，其实是源清单没跟上）
—— 现在 `gen_csc_rsp.py` **自动扫 `Assets/`**，排除 `Editor/`（另一个程序集）与 `Plugins/`。
🔴 **2026-09-30 晚补**：**编辑器程序集那一份原来不扫新文件**（只认 `Assembly-CSharp-Editor.csproj`，
而那是**上次 Unity 生成**的）⇒ 新加的 `Editor/*.cs` 编不到、报 `CS0246`（踩的实例 = `MeshVertexColors.cs`，
类型检查红、Unity 里却是好的）。现在**两份都扫**（编辑器那份的规则 = 路径含 `/Editor/`）。

**它是怎么来的**：
1. `python` 读 `Unity/MyGame/Assembly-CSharp.csproj`，把所有 `<Compile Include>` 与
   `<HintPath>` 抽出来写成 `-r:` 与源文件列表；
2. **新加的文件不在 csproj 里**（那是上次 Unity 生成的）⇒ **自动扫**补上（见上）；
3. `dotnet msbuild` **走不通**（DOTween 是针对 .NET **4.7.2** 编的，本机只有 **4.7.1** 的引用程序集
   ⇒ `MSB3274`），而 **`csc` 不做框架版本检查** ⇒ 直接
   `dotnet "<dotnet sdk>/Roslyn/bincore/csc.dll" @rsp`。

⚠️ 三个前提，缺一个就报一堆假的 `CS0006 找不到元数据文件`：
· **cwd 必须是 `Unity/MyGame`**（csproj 里的 HintPath 有相对路径；`typecheck.sh` 已经帮你 `cd`）；
· 引用里要**手动补** `Assets/Plugins/Demigiant/DOTween/DOTween.dll` 与
  `Library/ScriptAssemblies/Assembly-CSharp-firstpass.dll`（原 csproj 用的是 `ProjectReference`，会去**重编** firstpass 而失败）；
· 第 2 份 rsp 要**把 `Assembly-CSharp.dll` 换成第 1 份的输出**（否则编辑器程序集是按**上次 Unity 编的旧 DLL** 在查，
  新加的类型会「找不到」）。
⚠️ 它**只管编不编得过**，不跑断言 —— 断言仍要走 Unity 那 11 条。
⚠️ **批处理跑着的时候别改 `.cs`**（CLAUDE.md 铁律 12）。
