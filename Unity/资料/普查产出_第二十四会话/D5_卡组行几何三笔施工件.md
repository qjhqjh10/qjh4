## ① `A1722` —— 结论 = 「**框 vs 墨迹**」（`A1528` 同族），**不是真偏离**。⇒ **要改常量**

### 原版 prefab 现读（`bundle_menus_assets_all`）
卡行 `Deck Selector Card Info button` 的 `Cost Image`，RT `1553532234772573988`：
`m_AnchorMin/Max = (0.03, 0)/(0.03, 1)` · `m_SizeDelta = (0, 6)` · `m_AnchoredPosition = (-0.1800079, 0)` · `m_Pivot = (0.5, 0.5)`；
父 = 卡行 `Background` RT `-2197820584482115804`（**25.655..317.400，291.745 宽**）；
同 GameObject 上 ARF = `AspectMode 2`（**高控宽**）· `m_AspectRatio 1.0` · Image `m_Type = 0` · **`m_PreserveAspect = 0`**。
⇒ 中心 x = 25.655 + 0.03×291.745 − 0.18 = **34.227** · 高 = 55.7 + 6 = **61.7** · 宽 = 61.7×1.0
⇒ **绝对 3.377..65.077（61.7 见方）= 行内 −5.02..56.68**。
✅ **转述属实**：`menu_dump.py "Deck Editing Menu" --depth 12` 对**卡行**与 `Deck Selector Defensive Card Slot`
**都**印 `3.4 … 65.1`（**同档**）。

### k 独立核过（保留 k = 1.21442）
- ① `1581 × 1.21442 = 1920.0`（**宽逐位对上**；纵向只到 1077.2 ⇒ 图底部少 2.8px，**是裁切不是 k 错**）；
- ② 用**行距**反算：10 颗六边形顶缘 ref 352→779，均 **47.44 px/行 × k = 57.6 ≈ 画布 57.7**（0.2%）。
- 两法一致。

### 参考图墨迹（两种掩膜，算法写全）
- ① **只取蓝体**（`b−r>40 & b>60`）⇒ ref x **10..48** ⇒ 画布 **12.1..58.3**
  —— **账上那个数就是这么来的，逐位复现**；
- ② **含外圈亮边**（逐行扫 `max|px−rowbg|>45`，`y∈[348,398]`）⇒ ref x **7..50** ⇒
  画布 **8.50..60.72（宽 52.22）**；纵向 ref 352..392 ⇒ 画布 y 427.5..476.1。

### 换算
sprite 被**拉伸**进 61.7 方框（`m_PreserveAspect = 0`）⇒ x 每 sprite px = 61.7/248 = **0.24879** · y = 61.7/244 = 0.25287。
`Resources/Art/ui_deck/Card_Frame_Cost_Icon.png` = **248×244**，与 Sprite json 的 `m_Rect`/`textureRect`（0,0,248,244）
**等大** ⇒ **PNG 就是整张 sprite**。它的 `alpha≥128` 列 = 12..229 ⇒ 画进框后重墨迹落 **x 6.36..60.60**；
`alpha≥8` 列 = 3..238 ⇒ 4.12..62.84。

### 结论与要改的
**是「框 vs 墨迹」**：61.7 的框里装的是 **sprite 自带的透明发光边**（左 12 / 右 18 个 sprite px）。
按「拉伸进 61.7」算，重墨迹 = **6.36..60.60**，参考图实测 **8.50..60.72**
（**右缘差 0.12px**、左缘差 2.1px = 非整数降采样 1581/1920 的 ±1.2px 带内）。
⇒ **要改的就是我们那两个常量**：`RowCostX/RowCostS` **12.1/46.2（墨迹）→ 3.377/61.7（框）**
（落点：`Deck/DeckRuntime.cs` 定义 · 建 · 搬 · `SetAutoFitBox` 的框一并按 61.7）。

⚠️ **连带影响 `A1720` 的可视性**：框左缘若是 3.377（重墨迹 6.36），督军行多出的那段 17.255（8.4→25.655）
**几乎全被费用圆盖住** ⇒ `A1720` 说的「真露 ≈ 3.7px」应缩到「**只在行顶/行底两角各露一个小三角**」。

## ② `A1720` —— **成立**（只在 `firstRow ≥ 1` 时）

- 槽号取几何：`Deck/DeckRuntime.cs` 的 `RowBgRect(i)` / `RowGradRect(i)` 按**槽号**；调用点**只有两处**（建 · 搬）。
- 装进去的那一项是 `shown[firstRow + i]`；`row_*`/`row_b*`/`row_g*` 的 active 由 `RefreshDeckList` 统一开关。
- `DeckEntries()` 恒把**督军放 `shown[0]`**、**防御卡放 `[1]`** ⇒ **唯一错态 = `firstRow ≥ 1` 时槽 0 装卡行却用督军档**
  （8.400 / 宽 309 / 色条 197.364）；`firstRow == 0` **逐位正确**。

### 建议改法（**比 `D1` 的建议更省**）
把 `RowBgRect/RowGradRect` 的参数从「**槽号**」改成「**这一项是不是督军**」（两个调用点各传 `isHero`）。
⚠️ **九宫格搬得动、改不了尺寸**（`MenuDraw.Nine` / `ImageQuad.CreateNineSlice` **没有 resize 口**，`Move()` 只写 `localPosition`）
⇒ **不能原地重摆**。可行做法 = **槽 0 建两套**：
1. 现有 `row_0/row_g0/row_b0` **保留为督军档**（这样 `Editor/DeckScene.cs:2159/2164/2167/2169/2175/3068/3086`
   那批**全部不动**）；
2. 另建 `row_0c/row_g0c/row_b0c` 卡行档，在 `RefreshDeckList` 里
   `SetOn(督军套, on && firstRow == 0)` / `SetOn(卡行套, on && firstRow >= 1)`；
3. `MoveRow(0, y)` **两套都搬**。
**可行性：可以**，代价 = 多 3 件 + 3 条搬/开关；**比 `D1` 版更省**的是它**不动 `row_0` 这一族的名字语义**。

### 连动断言（逐条 `Editor/DeckScene.cs:行`）
`:2159`（`UiTextureName("row_0")`）· `:2164`（`UiQuadCount("row_0")>=3`）· `:2167`（`row_b0>=9`）·

## ③ `A1721` —— **成立**。`RowPitch = 56` 是「我们挑的」，原版 = **57.7**

- `const float RowPitch = 56f;`（`Deck/DeckRuntime.cs:168`，**注释自陈「我们挑的」**）；`RowH = 55.7`。
- 原版真值（`menu_dump.py` 现读 `Deck Editing Menu` 的 `Content`）：`VerticalLayoutGroup m_Spacing = 2.0` ·
  `pad (8,8,0,0)` · `CSF v:MinSize`，三行打在 y 366 / 423.7 / 481.4 ⇒ **步长 57.7 = 55.7 + 2.0**；
  `Content` 高 171.1 = 3×55.7 + 2×2.0，**逐位自洽**。

### 连动面（逐条 `Deck/DeckRuntime.cs:行`）
**一屏几行** `RowVisible = 11`（`:300`，依据 `644.1/55.7 = 11.56`）· **滚动上限**
`maxScroll = max(0, Count*RowPitch − ListH)`（`:3562`）与自检口 `MaxDeckScrollPx`（`:5193`）·
**firstRow/off** `:3564-3565` · **其它读 `RowPitch` 的点** `:1675`（建列表 y）· `:3614`（刷新的 y）·
`:3740`（`RowRectAt` 命中）· `:3787`（`RowFirstRowAt`）· `:4301` · `:5285`（`UiDeckRowAt`）· `:5893`/`:5907`。
**断言**：`Editor/DeckScene.cs:5043`（`MaxDeckScrollPx>0`）· `:5045`（`UiScrollDeck(56f)`）· `:5047`（回顶夹 0）·
`:3377`（`for i<11` **硬写 11**）。

### 建议改法
`RowPitch` 拆成 `RowH + RowSpacing`，`RowSpacing = 2f`（照原版 VLG `m_Spacing`），**`RowPitch = 57.7f`**；
🔴 **上限要同时改**成 `max(0, Count*RowPitch − RowSpacing − ListH)`
（原版 = `Content 高 − 视口高`，而 `Content 高 = n×57.7 − 2.0`），否则会**多给 2px**。
⚠️ **单改 `RowPitch` 而不改上限 ⇒ 少给约 `1.7×n` px 的滚动量**。

## 🔴 四、`A1727`（新账 · **用户可见的真缺陷**）—— `RowVisible = 11` ⇒ **最后一行永远看不到**

1. **槽位永远填不满视口**：`644.1 / 57.7 = 11.16` ⇒ 原版**卷到 0 时会露出第 12 行的 9.4px 残行**
   （参考图实测：蓝六边形带最后一颗在 ref y 827、**高只 6px** ⇒ 画布 1004.3..1010.4；
   而 **行 11 顶 = 366 + 11×57.7 = 1000.7**，**逐位对上**）—— **我们 11 槽不画**；
2. **更严重**：**`max scroll` 时最后一行永远看不到** —— `firstRow_max = Count − ceil(644.1/57.7) = Count − 12`，
   槽 0..10 只覆盖 `Count−12 .. Count−2` ⇒ **`Count−1` 那颗一个槽都没有**
   （它算出来的屏上 y **落在视口内**，只是**没槽**）。

⇒ **要做**。修法 = **`RowVisible = 12` + 给行加视口裁切**（`ViewportClip` / `MenuScroll.ClipNode`；
现在 `NineSlice(...)` 传的是 `clip: null`）⇒ **建议并进 `A1721` 那批一起做**。
